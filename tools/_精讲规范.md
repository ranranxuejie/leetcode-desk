这份文件是给改写教材的人（或 AI）看的唯一标准。动笔前从头读到尾，尤其读最后的**样板**。

---

## 一、读者是谁（这决定了你写什么）

- **多年前学过 Python，现在基本忘光。** 他知道"列表"这两个字，但想不起 `pop()` 是拿走还是只看一眼；见过 `dict`，但不确定 `d.get(k, 0)` 和 `d[k]` 有什么区别。
- **算法零基础。** 没听过滑动窗口、单调栈、回溯、DP 状态转移。这些词第一次出现在他眼前时，如果没人解释，他读不下去。
- **理解力不差，缺的是"补课"。** 不需要哄，不需要鼓励。需要的是：**这个名词是什么 → 一个生活类比 → 三行能跑的例子 → 它在这题里干什么**。
- **他原话**：「一些概念没学过就直接出现还是不好让我理解」。

所以你的任务不是"把解法再讲一遍"，而是**在解法和他之间铺一层台阶**：把每个会绊倒他的名词先拆开、垫平，再让他走过去。

## 三、四段结构（顺序不能变）

### ① 这题要用到的东西

把这道题的代码和思路里出现的、**读者可能不认识**的东西，逐个拆开讲。分三类，都要覆盖：

- **容器 / 数据结构**：list、dict、set、栈、队列（`deque`）、堆（`heapq`）、链表、树、图
- **Python 语法**：`enumerate`、切片 `s[i:j]`、推导式、`d.get()`、`float('inf')`、`nonlocal`、类型标注 `-> int`、`//` 和 `%`、`zip`、`sorted(key=...)`
- **算法名词**：哈希表、双指针、滑动窗口、递归、回溯、DFS/BFS、二分、前缀和、单调栈、动态规划、贪心、并查集、拓扑排序

每个名词固定四件套：

1. **一句人话**（不用术语解释术语）
2. **一个生活类比**（盘子、排队、字典查字、翻书……）
3. **一段 3–6 行、能直接跑的最小代码**，带 `# -> 输出` 注释
4. **它在这题里扮演什么角色**（一句话）

**关键规则：同一个概念在一册里只精讲一次。** 第二次出现时写一行：

> **栈**（前面 B1 讲过）：只能从末尾增删的列表。这题用它存"还没结算的柱子"。

这样读者不会连着读十遍"栈是什么"，但每节都还能想起来。

### ② 大白话：这题到底在干什么

像师兄坐你旁边说话。要求：

- **不许出现没解释过的名词。** 非要用，就在后面紧跟一句括号解释。
- 先讲**最笨的办法**怎么做（要具体，说清它每一步在干嘛），再讲**笨在哪**（浪费了什么），最后讲**聪明办法**。
- 3–8 句，短句。可以用"你"、"想象一下"、"注意这里"。
- 不要在这里出现代码。

### ③ 拿一个具体输入走一遍

- 用题面示例，或者一个更小的自造例子（≤ 6 个元素）。
- **必须做成表格**：列 ≤ 5，行 ≤ 10。表头形如 `步骤 | 变量状态 | 发生了什么`。
- 数字必须**真的算过**——自己跑一遍代码抄下来，不许脑补。
- 表格后面补一句"所以答案是 X"。

### ④ 代码逐行对译

- **表格**：`代码` | `大白话`。挑 8–15 行关键行，不要每行都译。
- 左边照抄原文代码（可以省略缩进细节），右边说人话。
- 重点译这三类行：初始化为什么这么设、判断条件在问什么、答案在哪一步被写下去。

### 精讲（零基础版）

#### ① 这题要用到的东西

**栈（stack）**

一句话：栈就是一个**只能从末尾增删的列表**。Python 里不用 import 任何东西，`list` 本身就是栈。

- `stack.append(x)`：往末尾放一个 —— 叫"进栈"
- `stack.pop()`：把末尾那个**拿走**，并且把它返回给你 —— 叫"出栈""弹栈"
- `stack[-1]`：只看一眼末尾，**不拿走** —— 叫"看栈顶"

生活类比：**一摞盘子**。你只能往最上面放，也只能从最上面拿；想拿最底下那只，得先把上面的端走。这个性质叫"后进先出"（LIFO）—— 最后放进去的最先出来。

```python
stack = []
stack.append("第1天")     # 栈: ['第1天']
stack.append("第2天")     # 栈: ['第1天', '第2天']
print(stack[-1])          # -> 第2天   （只看，不拿走）
print(stack.pop())        # -> 第2天   （拿走，并且返回给你）
print(stack)              # -> ['第1天']
```

这题里，栈扮演"**待办便签摞**"：把"还没等到更热天气的日子"攒在栈里，等热天来了再一张张撕。

**单调栈**

一句话：一种**始终保持从栈底到栈顶递减**（或递增）的栈。做法是：新元素进栈之前，先把"破坏这个顺序"的栈顶一个个弹掉。

这题里栈内温度从上到下越来越低（栈顶最冷）。新来的一天只要比栈顶热，栈顶那天就"等到了"，可以弹掉。

**下标（index）**

一句话：元素在列表里的位置编号，**从 0 开始**。`temperatures[2]` 是第 3 天的温度。

这题为什么存下标、不存温度？因为答案要的是"隔了几天"，只有两个下标相减才是天数；存温度你算不出距离。

**`enumerate`**

一句话：一边遍历，一边把下标也给你。

```python
for i, t in enumerate(["a", "b"]):
    print(i, t)      # -> 0 a / 1 b
```

等价于 `for i in range(len(x)): t = x[i]`，但少写一行。

#### ② 大白话：这题到底在干什么

最笨的办法：站在第 i 天，往后一天一天看，看到第一个比今天热的日子就停下，把中间隔了几天记下来。这样每一天都可能要看到末尾，最坏情况下总共要看 n² 次，n 到十万就跑不完了。

笨在哪？**重复劳动**。比如温度是 75、71、69，你算 71 那天的时候扫过了 69，算 69 那天还得再扫一遍。

聪明的办法：把"还没等到热天"的日子先攒着。你会发现这些日子有个规律——**越靠后攒着的，温度一定越低**。因为只要来了一个更热的天，前面那些更冷的早就被结算掉了。

于是桌上永远是一摞"从下往上越来越冷"的便签。新来一天，就盯着最上面那张看：比它热，就撕掉它、写上"等了几天"；撕完再看新的一张，直到最上面那张比今天还热，或者桌子空了。最后把自己这张放上去，接着等。

每张便签只会被贴上、撕掉各一次，所以总共就 n 次操作。

#### ③ 拿 `[73,74,75,71,69,72,76,73]` 走一遍

| 天数 i | 温度 | 发生了什么 | 桌上便签（存下标） | 已填答案 |
|---|---|---|---|---|
| 0 | 73 | 桌子空，放上 | `[0]` | 全 0 |
| 1 | 74 | 73<74，撕掉 0，`answer[0]=1` | `[1]` | `[1,0,…]` |
| 2 | 75 | 74<75，撕掉 1，`answer[1]=1` | `[2]` | `[1,1,0,…]` |
| 3 | 71 | 75>71，不撕，放上 | `[2,3]` | 不变 |
| 4 | 69 | 71>69，不撕，放上 | `[2,3,4]` | 不变 |
| 5 | 72 | 69<72 撕 4 → `answer[4]=1`；71<72 撕 3 → `answer[3]=2`；75>72 停 | `[2,5]` | `…,2,1,…` |
| 6 | 76 | 72<76 撕 5 → `answer[5]=1`；75<76 撕 2 → `answer[2]=4`；桌子空 | `[6]` | `[1,1,4,2,1,1,0,0]` |
| 7 | 73 | 76>73，放上 | `[6,7]` | 不变 |

所以答案是 `[1,1,4,2,1,1,0,0]`。注意第 5 步：**一次循环里撕了两张**，这就是"一口气结算一批"。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `answer = [0] * n` | 先准备 n 个 0。等不到热天的日子，答案本来就该是 0，所以不用收尾 |
| `stack = []` | 空桌子 |
| `for i, t in enumerate(temperatures)` | 第 i 天，温度 t |
| `while stack and temperatures[stack[-1]] < t` | 桌子没空，**并且**最上面那张比今天冷。先判 `stack` 是因为空列表取 `stack[-1]` 会报错 |
| `j = stack.pop()` | 撕掉最上面那张，`j` 就是那天的编号 |
| `answer[j] = i - j` | 它等了 `i - j` 天 —— 写的是 `j` 的位置，不是今天的 |
| `stack.append(i)` | 把自己这张放上去，继续等 |
