# 专题 6：树与二叉树（下）· BST 与高级

**本册覆盖**：专题6-1 验证二叉搜索树（98）、6-2 二叉树中的最大路径和（124）、6-3 实现 Trie（208）、6-4 添加与搜索单词（211）、6-5 二叉搜索树的最近公共祖先（235）、6-6 二叉树的最近公共祖先（236）、6-7 二叉树的序列化与反序列化（297）。

**本册地图**

第一册的 C5、C6、C7、C8 解决的是"怎么把一棵树走一遍"：中序、层序、求深度、按遍历序列建树。这一册问的是另一个问题——**走的时候顺手算什么**。

七道题分三组。第一组是 BST（98、235）：二叉搜索树多了一条"左小右大"的规矩，这条规矩能让你查找时每步扔掉一半的树，也能让你判断合法性时不必真的去比较每一对祖先和后代。第二组是"没有规矩时怎么办"（236、124）：普通二叉树没有大小关系，只能靠后序遍历把左右子树的结果汇总上来；124 在这之上还多一层——递归的返回值和最终答案不是同一个东西，这是本册最容易踩的坑。第三组是"把结构编码成线性序列"（208、211、297）：Trie 把字符串按字符拆成路径，序列化把树按遍历顺序拆成记号。

建议顺序：98 → 235（先把 BST 性质用熟）→ 236（对比：没有性质要多花多少力气）→ 124（后序 + 全局答案，返回值和答案要分开）→ 208 → 211（Trie 两连）→ 297（综合，也是 Hard）。

三个要带走的思维模型：

1. **返回值是给父亲的，答案是自己留的**。递归函数返回什么，取决于上一层需要什么，不取决于你想知道什么。
2. **有序性等于可以砍掉一半**。看到 BST，先问自己能不能只走一条路。
3. **线性化必须无歧义**。任何"树 ↔ 序列"的转换，都要保证序列能唯一还原结构。

## 专题6-1. 验证二叉搜索树（Medium）

> 力扣 98 · 二叉搜索树 · 上下界递归 / 中序遍历
> 前置：[第一册 C5 二叉树的中序遍历](12-分册C-链表树图.md)、[C7 二叉树的最大深度](12-分册C-链表树图.md)

**一句话**：判断一棵树是不是满足"左边全小、右边全大"的二叉搜索树。

### 精讲（零基础版）

#### ① 这题要用到的东西

**二叉搜索树（BST）**

一句话：一棵二叉树，并且对**每个**节点都成立——它左子树里所有值都比它小，右子树里所有值都比它大。

生活类比：图书馆的书架。左边一整排的索书号都比中间这本小，右边一整排都比它大；而且这个规矩在每一层书架上都得成立。

这题要判断的，就是"这棵树守不守这条规矩"。

**开区间 `(low, high)`**

一句话：一个范围，两头的数不算在内。

生活类比：电梯限载"13 到 60 岁"，13 岁和 60 岁本身都不让进。

```python
low, high = float('-inf'), float('inf')
print(low < 5 < high)     # -> True
low, high = 5, 6
print(low < 3 < high)     # -> False
```

`low < x < high` 是 Python 的连写，等价于 `low < x and x < high`。

**`float('-inf')`**

一句话：负无穷，比任何数都小。

为什么不用 `-2**31`？因为节点值本身可能就是 `-2**31`，拿它当下界会把合法节点判死。负无穷没有这个问题；同理 `float('inf')` 是正无穷。

**`nonlocal`**

一句话：让里层函数能**改**外层的变量。

```python
def outer():
    prev = None
    def inner(v):
        nonlocal prev        # 声明：我要改外面那个 prev
        prev = v
    inner(7)
    return prev

print(outer())      # -> 7
```

不加 `nonlocal` 的话，`prev = v` 会在 `inner` 里造一个**新的**局部变量，外面的 `prev` 一直是 `None`。

**递归**（上一册讲过）：函数自己调用自己，小到不能再小就停。这题里每一层负责"检查自己这棵子树"。

**中序遍历**（上一册讲过，这里复习一句）：左 → 根 → 右。对 BST 做中序，得到的一定是**从小到大**排好的序列。

#### ② 大白话：这题到底在干什么

最笨的办法：对每个节点，把它左子树里所有节点都取出来比一遍，右子树也一样。能对，但每个节点都要扫一遍自己的子树，总共 O(n²)。

笨在哪：同一个节点被反复检查。3 是不是比 5 小，你在 5 那里查一次，在 6 那里又查一次。

再聪明一点、也是最常见的错解：只比"我和我的直接孩子"。看这棵树：

```
      5
     / \
    4   6
       / \
      3   7
```

每一对父子都合法：4<5、6>5、3<6、7>6。可它不是 BST，因为 3 在 5 的右子树里，却比 5 小。

错在哪：规矩是"**整棵子树**"都小、都大，不是"直接孩子"。这个约束沿着祖先链一路累积，你得把它带在身上往下走。

聪明办法有两个。一是给每个节点带一个开区间：往左走，上界收紧成当前值；往右走，下界收紧成当前值。走到 3 时，它继承的区间是 `(5,6)`，3 不在里面，立刻判死。

二是换个角度：BST 的中序一定严格递增。那就不比区间了，走一遍中序，只检查"当前值是不是大于上一个值"。

#### ③ 拿 `[5,4,6,null,null,3,7]` 走一遍

| 步骤 | 节点 | 拿到的区间 | 在区间内？ | 接下来 |
|---|---|---|---|---|
| 1 | 5 | `(-inf, inf)` | 是 | 往左，上界收成 5 |
| 2 | 4 | `(-inf, 5)` | 是 | 4 没有孩子，返回 True |
| 3 | 6 | `(5, inf)` | 是 | 往左，上界收成 6 |
| 4 | 3 | `(5, 6)` | **否** | 立刻返回 False |

所以答案是 False。而"只比父子"的写法在这一棵树上会返回 True——这就是它的招牌反例。

同一棵树的中序是 `4, 5, 3, 6, 7`：读到 3 时上一个值是 5，`3 <= 5`，递增断了，同样返回 False。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `def check(node, low, high):` | 每个节点带着自己的合法区间进来 |
| `if not node: return True` | 空树算合法，这是出口 |
| `if not (low < node.val < high): return False` | 值不在区间里，立刻判死。必须严格不等号，重复值不合法 |
| `check(node.left, low, node.val)` | 往左：上界收紧成自己 |
| `check(node.right, node.val, high)` | 往右：下界收紧成自己。每次只动一边 |
| `return check(...) and check(...)` | 两边都合法才算合法 |
| `check(root, float('-inf'), float('inf'))` | 根没有约束，区间开到两头无穷 |
| `prev = None` | 中序解法的"上一个值"。用 `None` 起手，因为节点值可以是负数 |
| `nonlocal prev` | 声明要改外层的 `prev` |
| `if not inorder(node.left): return False` | 左边已经非法，直接往上冒，不用再往下走 |
| `if prev is not None and node.val <= prev: return False` | 没有严格递增就失败 |
| `prev = node.val` | 记下自己，给下一个节点比。放在比较之后、进右子树之前 |

### 考什么

- 表面考点：BST 的定义。
- 真正考点：**"子树里所有节点"和"直接孩子"是两回事**。这题唯一的坑就在这里；越过这个坑，剩下的只是遍历。
- 面试官想听到的关键句：① 只比较父子不够，要给每个节点带一个开区间；② BST 的中序遍历严格递增，反过来也成立。

### 思路是怎么想出来的

先看一个看起来对、其实错的写法：

```python
def dfs(node):
    if not node:
        return True
    if node.left and node.left.val >= node.val:
        return False
    if node.right and node.right.val <= node.val:
        return False
    return dfs(node.left) and dfs(node.right)
```

它只检查"每个节点和它的直接孩子"。拿这棵树试：

```
          5
         / \
        4   6
           / \
          3   7
```

每一对父子都合法：4 < 5、6 > 5、3 < 6、7 > 6。这个写法返回 True，而正确答案是 False——3 在 5 的右子树里，却比 5 小。BST 要求的是"右子树里的每一个节点都大于根"，不是"右孩子大于根"。

约束是**沿着祖先链累积**的，这是全题的出发点。

#### 解法一：带着区间往下走

换个说法：每个节点都活在一个开区间 `(low, high)` 里，它的值必须落在区间内。

- 根节点：`(-∞, +∞)`。
- 往左走：上界收紧成当前节点的值，因为左子树里所有数都得比它小。
- 往右走：下界收紧成当前节点的值。

```
          5            (-∞, +∞)
         / \
        4   6          4: (-∞, 5)      6: (5, +∞)
           / \
          3   7        3: (5, 6)       7: (6, +∞)
```

节点 3 的区间是 `(5, 6)`，3 不在里面，立刻判死。这样一次遍历就把祖先链上的所有约束都带上了，不用回头比较。

#### 解法二：中序遍历

BST 有一个等价刻画：**中序遍历的结果严格递增**。中序是"左 - 根 - 右"，而 BST 保证左 < 根 < 右，所以整条序列必然从小到大。

上面那棵树的中序输出是 `4, 5, 3, 6, 7`。读到 3 的时候，上一个输出是 5，`3 <= 5`，递增断了，返回 False。一次相邻比较就够了，不需要区间。

两种解法都讲，是因为它们代表两种不同的思路：解法一是"把约束往下传"，解法二是"把树压成一个序列再看"。面试时先说你想到哪个，再补另一个。

### 代码（Python）

```python
from typing import Optional


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:
        # 解法一：每个节点带一个开区间 (low, high)
        def check(node, low, high):
            if not node:
                return True
            if not (low < node.val < high):
                return False
            return (check(node.left, low, node.val)
                    and check(node.right, node.val, high))

        return check(root, float('-inf'), float('inf'))


class SolutionInorder:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:
        # 解法二：中序遍历，检查是否严格递增
        prev = None

        def inorder(node):
            nonlocal prev
            if not node:
                return True
            if not inorder(node.left):        # 左边已经非法，直接往上冒
                return False
            if prev is not None and node.val <= prev:
                return False                  # 没有严格递增
            prev = node.val
            return inorder(node.right)

        return inorder(root)
```

**逐段讲解**：

- `check(root, -inf, +inf)`：根没有约束，区间开到无穷。用 `float('-inf')` 而不是 `-2**31`，因为节点值本身就可能等于 `-2^31`，拿它当下界会把合法节点判死。
- `low < node.val < high` 必须用严格不等号。BST 的定义是严格小于、严格大于，重复值不合法，`[1,1]` 应该返回 False。
- 往左传 `(low, node.val)`，往右传 `(node.val, high)`。每次只动一边：左边改上界，右边改下界。两边都改是另一个常见错误。
- 解法二的 `prev` 用 `None` 起手，而不是 `0` 或 `-1`。节点值可以是负数，拿 0 当"上一个值"会让 `[-1]` 这种单节点树被误判。
- `prev = node.val` 要放在"比较完、进右子树之前"。放早了等于拿自己跟自己比。

### 复杂度

- 时间 O(n)：每个节点进一次，常数次比较。
- 空间 O(h)：递归栈深度等于树高。链状树 O(n)，平衡树 O(log n)。

### 常见误区（★ 最容易丢分的地方）

1. **只比较父子**：`[5,4,6,null,null,3,7]` 返回 True，正确答案 False。这是本题的招牌反例。
2. **上下界只传一边**：`check(node.left, low, node.val)` 写成 `check(node.left, node.val, node.val)`，左子树所有节点都过不了。
3. **中序用 0 初始化 `prev`**：节点值域是 `[-2^31, 2^31-1]`，负数用例直接误判。
4. **用 `<=` 放行重复值**：`[1,1]` 返回 True，但 BST 要求严格。
5. **把 `prev` 写成类属性**：力扣复用同一个 `Solution` 实例，第二次调用会带着上一次的 `prev`。写在方法内部，用 `nonlocal`。

### 面试追问 / 变体

- 中序的迭代版（显式栈）：避免递归深度问题，模板在第一册 C5。
- 力扣 230「BST 中第 k 小的元素」：中序走到第 k 个就停，不用走完。
- 力扣 99「恢复二叉搜索树」：中序里找到两处逆序，交换那两个节点的值。
- 如果允许重复值，且规定"左 ≤ 根 < 右"：把判断改成 `low < node.val <= high`，往右走时 `low = node.val`，往左走时 `high = node.val`。这样左子树允许等于根，右子树仍然严格大于。

### 自测

- 必测用例：`[2,1,3] → True`；`[5,1,4,null,null,3,6] → False`；`[5,4,6,null,null,3,7] → False`（父子全合法但整体非法）；`[] → True`；`[1,1] → False`；`[5,4,null,3] → True`（只有左链）；`[5,null,6,null,7] → True`（只有右链）。
- 30 秒自检：能不能说出"为什么只比父子会错"，以及两种解法各自靠什么传递约束。

## 专题6-2. 二叉树中的最大路径和（Hard）

> 力扣 124 · 二叉树 · 后序遍历 + 全局最值
> 前置：[第一册 C7 二叉树的最大深度](12-分册C-链表树图.md)、本册 6-1

**一句话**：在树里找一条不重复经过节点的路径，让路径上所有节点值的和最大。

### 精讲（零基础版）

#### ① 这题要用到的东西

**路径（path）**

一句话：从某个节点出发、沿着边走、到另一个节点结束的一串节点，同一个节点不能走两次。

生活类比：在一张只往下分叉的地图上画一条线，笔不能抬起来，也不能走回头路。

在树里，这样的线只有一个形状：从某处往上爬一段，到某个最高点拐个弯，再往下走一段。它不可能拐两次——树没有环，拐两次必然重复踩到节点。那个拐弯的点叫**拐点**，它是这条路径上最高的节点。

**后序遍历**（上一册讲过，这里复习一句）：先拿到左右子树的结果，再算自己。这题必须用后序，因为"某个节点往下能拿到多少"要先知道它的孩子能拿到多少。

**返回值 ≠ 答案**

一句话：递归函数返回给父亲的东西，和题目要的最终答案，可以是两个不同的量。

生活类比：你向上司汇报"我这个组今年能贡献多少利润"，和你自己在心里记"我见过的最大一笔单子是多少"，是两回事。前者要能并进别的组里，后者只是你自己的记录。

这题里，返回值是"从这个节点往下、**只走一边**的最大和"（父亲只能接一条路）；答案是"以这个节点为拐点、**两边都接**的最大和"。两者混成一个变量，题就废了。

**`float('-inf')`**（前面 6-1 讲过）：负无穷，比任何数都小。这里用它当全局答案的初始值——整棵树全负时答案可以是负数，初始值不能是 0。

**`nonlocal`**（前面 6-1 讲过）：让里层函数改外层的 `best`。

#### ② 大白话：这题到底在干什么

最笨的办法：把所有可能的路径都列出来，一条条求和，取最大。可树里的路径有多少条？任意两个节点之间都有一条，数量是 n² 级别，还没算"同一条路径被算两次"，根本列不完。

笨在哪：绝大多数路径都在绕远路，而绕远路只会让和变小。真正的最优路径一定在某处拐个弯，不会为了多走几个节点而故意往下绕。

聪明办法：既然每条路径都有唯一一个拐点，那就**枚举拐点**。对每个节点 x，算"从 x 往左下方走能拿到多少" + x 自己的值 + "从 x 往右下方走能拿到多少"，在所有 x 里取最大。

那"往左下方走能拿到多少"怎么算？从 x 到 x.left，之后只能继续往它的左或右**一边**走，不能两边都要。这正好是个递归：某节点往下单边能拿到的最大值 = 它自己的值 + 左右两边里更大的那个。如果某一边算出来是负数，那还不如不要它，直接取 0。

于是每个节点做两件事：用"左右都接"算一个候选答案，去更新全局最大；用"只接一边"算一个返回值，交给父亲。

#### ③ 拿 `[1,2,3]` 走一遍

1 是根，左 2 右 3。

| 步骤 | 节点 | 左贡献 | 右贡献 | 候选答案（自己+左+右） | best | 返回给父亲（自己+较大的一边） |
|---|---|---|---|---|---|---|
| 1 | 2 | 0 | 0 | 2 | 2 | 2 |
| 2 | 3 | 0 | 0 | 3 | 3 | 3 |
| 3 | 1 | 2 | 3 | 6 | 6 | 4 |

所以答案是 6。注意第 3 行：`gain(1)` 返回的是 **4**，不是 6——6 是"在 1 这里拐弯"的答案，它没有资格往上传；假如 1 上面还有父亲，父亲也只能接 1 的一条边。

再看 `[-10,9,20,null,null,15,7]`：

| 步骤 | 节点 | 左贡献 | 右贡献 | 候选答案 | best | 返回值 |
|---|---|---|---|---|---|---|
| 1 | 9 | 0 | 0 | 9 | 9 | 9 |
| 2 | 15 | 0 | 0 | 15 | 15 | 15 |
| 3 | 7 | 0 | 0 | 7 | 15 | 7 |
| 4 | 20 | 15 | 7 | 42 | 42 | 35 |
| 5 | -10 | 9 | 35 | 34 | 42 | 25 |

答案是 42，出现在 20 这里，跟根没关系——这就是题面强调"不一定经过根节点"的原因。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `best = float('-inf')` | 全局答案。不能写 0：`[-3]` 的正确答案是 -3 |
| `def gain(node):` | 返回"从 node 往下单边走能拿到的最大和"，给父亲用 |
| `nonlocal best` | 声明要改外层的 `best` |
| `if not node: return 0` | 空树贡献 0，等于"不走这边" |
| `left = max(gain(node.left), 0)` | 先递归算左边，负数就扔掉 |
| `right = max(gain(node.right), 0)` | 右边同理 |
| `best = max(best, node.val + left + right)` | 算**答案**：路径在 node 拐弯，两边都接 |
| `return node.val + max(left, right)` | 算**返回值**：只能接一边，否则路径在 node 分叉，就不再是一条路径 |
| `gain(root)` | 跑一遍，返回值不用管，答案已经在 `best` 里 |
| `return best` | 收尾，把全局最大交出去 |

两行的先后不能换：先更新 `best`（此时 `left`、`right` 还在手上），再 `return`。反过来写，`best` 那一行永远执行不到。

### 考什么

- 表面考点：树的遍历加求最值。
- 真正考点：**递归的返回值和最终答案是两个不同的量**。返回值是"从这个节点往下、只走一边"的最大贡献；答案是"以这个节点为拐点、两边都走"的最大和。把两者混成一个变量，题就废了。
- 面试官想听到的关键句：① 路径在树里最多拐一次弯，拐点是这条路径上最高的那个节点；② 枚举每个节点当拐点，取 `左贡献 + 自己 + 右贡献` 的最大值。

### 思路是怎么想出来的

先把"路径"钉死。题面说路径是节点序列，相邻节点之间有边，同一个节点至多出现一次。在树里，这样的路径只有一种形状：从某处往上走一段，到最高点拐弯，再往下走一段。它不可能拐两次，因为树没有环，拐两次必然重复经过节点。

所以每条路径都有一个最高点，在最高点这里，路径分成左右两支：

```
            最高点 x
           /          \
      往左下走        往右下走
      （至多一条）    （至多一条）
```

于是问题变成：对每个节点 x，求"从 x 往左下方走能拿到的最大和" + x 的值 + "从 x 往右下方走能拿到的最大和"，再在所有 x 里取最大。

那"从 x 往左下方走"是什么？它是 x.left 往下的一条单边路径，到了 x.left 之后只能继续往它的左或右一边走，不能两边都要。这正好是一个递归定义：

```
单边最大贡献(node) = node.val + max(0, 单边最大贡献(node.left), 单边最大贡献(node.right))
```

`max(0, ...)` 的意思是：某一边的贡献如果是负的，不如不要它，直接断开。

关键的一步在这里。这个递归函数返回的是"单边贡献"，因为它的父亲只能从它这里接一条路继续往上走。但答案允许在 node 这里拐弯，两边都接：

```
以 node 为拐点的候选答案 = node.val + 左贡献 + 右贡献
```

在 `[1,2,3]` 上验证：2 的贡献是 2，3 的贡献是 3，1 的贡献是 `1 + max(2,3) = 4`；而在 1 这里拐弯的候选答案是 `2 + 1 + 3 = 6`。最终答案 6，但它从来不是任何一次递归的返回值。

用题面第二个例子看得更清楚：

```
        -10
        /  \
       9    20
           /  \
          15   7
```

- 20 的单边贡献 = `20 + max(15, 7) = 35`（只能带 15 或 7 中的一条上去）。
- 20 处的候选答案 = `15 + 20 + 7 = 42`（在这里拐弯，两条都算）。
- 根 -10 处的候选答案 = `-10 + 9 + 35 = 34`，比 42 小。任何经过根的路径都得把 -10 加进去，所以都赢不了 42。

答案 42 出现在 20 这里，跟根没有关系，这就是题面强调"不一定经过根节点"的原因。

### 代码（Python）

```python
from typing import Optional


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def maxPathSum(self, root: Optional[TreeNode]) -> int:
        best = float('-inf')          # 全局答案，先设成负无穷

        def gain(node: Optional[TreeNode]) -> int:
            """返回：从 node 往下走、只走一边能得到的最大和（给父亲用）"""
            nonlocal best
            if not node:
                return 0              # 空树贡献 0，等于"不走这边"

            left = max(gain(node.left), 0)     # 负数分支直接扔掉
            right = max(gain(node.right), 0)

            # 以 node 为拐点：两边都接，这条路径到此为止
            best = max(best, node.val + left + right)

            # 返回给父亲：只能接一边
            return node.val + max(left, right)

        gain(root)
        return best
```

**逐段讲解**：

- `best = float('-inf')` 不能写成 `0`。整棵树全是负数时（比如 `[-3]`），正确答案是 -3，初始 0 会让答案变成 0，而 0 根本不是一条路径的和。
- `left = max(gain(node.left), 0)`：先把子树的贡献算出来，再和 0 取大。负贡献意味着这条路越走越小，父亲不如在 node 这里停住。
- `best = max(best, node.val + left + right)`：这一行算的是**答案**，路径在 node 拐弯。左右都是已经剪掉负数的贡献，不会把亏本的分支算进来。
- `return node.val + max(left, right)`：这一行是**返回值**，只能选一边。父亲要通过 node 继续往上；如果两边都带上，路径就在 node 分叉，不再是路径。
- 两行的顺序不能换：先更新答案（此时 left、right 还在），再返回。

**为什么返回值不能是答案**：假设 node 上面还有一个父亲 P，P 要算 `P.val + node 的返回值`。如果返回值里已经包含了两边，P 就会以为"从 P 经过 node 能同时走到 node 的左右子树"，可那条路在 node 就分叉了，节点被重复经过，不合法。

这题还有个麻烦之处：把返回值写成 `node.val + left + right` 的错解，**官方两个例子都能过**。`[1,2,3]` 得 6，`[-10,9,20,null,null,15,7]` 得 42，看起来完全正确。要等一棵"某个节点有两个很赚的孩子、上面还挂着一个父亲"的树才暴露：`[10,20,null,100,100]`，正确 220（100-20-100），错解得 230（它让 10 接上了一条已经在 20 分叉的假路径）。所以自测时必须自己构造反例，不能只跑题面。

### 复杂度

- 时间 O(n)：每个节点访问一次，常数次比较。
- 空间 O(h)：递归栈深度。链状树 O(n)，平衡树 O(log n)。

### 常见误区（★ 最容易丢分的地方）

1. **`best` 初始化成 0**：`[-3]` 输出 0，`[-2,-1]` 输出 0。题目保证至少一个节点，答案可以是负数。
2. **`return node.val + left + right`**：把答案当返回值交给父亲，父亲会算出一条分叉的假路径。`[10,20,null,100,100]` 会输出 230 而不是 220。
3. **忘了 `max(..., 0)`**：`[2,-1]` 会算成 `2 + (-1) = 1`，正确答案是 2（只取根）。
4. **把 `best` 写成类属性 `self.best`**：力扣复用实例，第二次调用会带着上一次的最大值。要么用 `nonlocal`（本解），要么在方法开头重置。
5. **先 `return` 再更新 `best`**：递归先返回了，`best` 那一行根本执行不到，结果永远是负无穷。
6. **递归深度**：节点上限 3×10^4，链状树高 3×10^4，本地会抛 `RecursionError`（默认上限约 1000）。力扣的 Python 环境放宽了上限，所以递归解能提交；面试时要能说出"改成显式栈的迭代后序"这条路子。

### 面试追问 / 变体

- 力扣 543「二叉树的直径」：完全同构。返回值是"单边最大深度"，答案是 `left + right`，只是把和换成了边数。
- 力扣 337「打家劫舍 III」：返回值变成两个数（抢当前节点 / 不抢），树形 DP 的入门。
- 要求输出路径本身：在 `best` 更新时记下当前节点和左右分支的走向，最后从拐点往两边收集。
- 如果规定路径必须经过根：不需要全局变量，直接 `root.val + max(0, left) + max(0, right)`。

### 自测

- 必测用例：`[1,2,3] → 6`；`[-10,9,20,null,null,15,7] → 42`；`[-3] → -3`；`[-2,-1] → -1`；`[2,-1] → 2`；`[1,-2,-3] → 1`；`[10,20,null,100,100] → 220`（把返回值当答案会得 230）。
- 30 秒自检：能不能用一句话说清"gain 返回什么、best 记什么"，以及 gain 为什么只能选一边。

## 专题6-3. 实现 Trie（Medium）

> 力扣 208 · 前缀树 · 设计题
> 前置：Python 的 `dict`、本册 6-4 会接着用它

**一句话**：设计一个数据结构，支持插入单词、查单词是否存在、查某个前缀是否存在。

### 精讲（零基础版）

#### ① 这题要用到的东西

**类（class）和 `self`**

一句话：类是一张图纸，`self` 是"正在被操作的那个具体对象"。

生活类比：`Trie` 节点是"节点"这张图纸，每个节点都是照图纸造出来的一个实物。图纸上写着"每个节点都有一张 children 表"，那每个实物就各有一张，互不相干。

```python
class Cat:
    def __init__(self, name):
        self.name = name        # 每个对象自己的一份

    def say(self):
        return "我是" + self.name

c = Cat("咪")
print(c.name)      # -> 咪
print(c.say())     # -> 我是咪
```

`__init__` 是"造对象时自动跑一次"的函数，用来初始化。方法的第一个参数永远是 `self`，指的就是你正在操作的那个对象。

**字典（dict）**

一句话：键 → 值的对照表，给键直接拿值。

```python
d = {"a": 1}
d["b"] = 2          # 加一条
print(d)            # -> {'a': 1, 'b': 2}
print(d["a"])       # -> 1
print("b" in d)     # -> True
print(len(d))       # -> 2
```

这题里，每个节点用一个字典存"下一个字符 → 子节点"。

**前缀树（Trie）**

一句话：把一堆单词的**公共前缀**合并成一棵树。从根往下走一条路，路上经过的字符拼起来就是一个前缀。

生活类比：一本翻开的词典，所有以 `app` 开头的词都挤在同一段里；你顺着 a → p → p 走过去，就站在那一段的入口。

这题里，它把"查前缀"从"翻遍整个词典"变成"顺着字符走 L 步"。

**`ord()`**

一句话：把字符换成它的编号。

```python
print(ord('a'))              # -> 97
print(ord('c') - ord('a'))   # -> 2
```

数组版 Trie 用它算下标：`ord(ch) - ord('a')` 把 `a`~`z` 映射到 0~25。

**单词结尾标记**

一句话：光有路径不够，还得在"这里是一个完整单词"的节点上盖个章。

为什么？`app` 和 `apple` 走的是同一条路的前三段。没有这个章，你分不清 `app` 到底是不是一个词。

#### ② 大白话：这题到底在干什么

最笨的办法：拿一个 `set` 装所有单词。查"这个词在不在"很快，一次哈希就够。但查"有没有以 `app` 开头的词"，set 帮不了你——它只认整串，你只能把 set 里每个词都取出来看开头，单词一多就慢死。

笨在哪：`apple`、`app`、`application` 前三个字母一模一样，set 把它们当成三个毫不相干的整体，这份"共享"被白白扔掉了。

聪明办法：把这份共享显式地建出来。每个节点只干一件事——记下"下一个字符是谁、它对应的子节点在哪"。插入 `apple` 时，从根开始一个字符一个字符走，路上没有的节点就新建、有的就复用；走完在最后一个节点上盖章。

插入 `bad` 时，第一个字符 `b` 在根下面没有，新建一条；于是根下面就有了两条岔路。

查询就简单了：顺着字符走。走得到，节点就存在；`search` 还额外要求那个节点盖过章，`startsWith` 不要求。

#### ③ 依次插入 `apple`、`bad` 走一遍

树长这样（★ 是单词结尾）：

```
root
 ├── a ── p ── p ── l ── e   ★
 └── b ── a ── d            ★
```

| 操作 | 走的路径 | 结果 |
|---|---|---|
| `insert("apple")` | a→p→p→l→e，五个节点全是新建 | 末端 `e` 盖 ★ |
| `insert("bad")` | b 是新的，a、d 也是新的 | 末端 `d` 盖 ★ |
| `search("apple")` | 走得到 `e`，且 `e` 有 ★ | True |
| `search("app")` | 走得到第二个 `p`，但它**没有** ★ | False |
| `startsWith("app")` | 走得到第二个 `p`，不检查 ★ | True |
| `search("ba")` | 走得到 `a`，没有 ★ | False |
| `startsWith("")` | 一个字符都不走，站在根上 | True |

所以 `search("app")` 是 False、`startsWith("app")` 是 True——这一对就是题面示例要考的区别。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `self.children = {}` | 每个节点一张"字符 → 子节点"的表。写在 `__init__` 里才是每人一份 |
| `self.is_end = False` | 默认"这里不是单词结尾" |
| `node = self` | 从根开始走 |
| `for ch in word:` | 一个字符一个字符往下 |
| `if ch not in node.children:` | 这条路还没有，就造一个新节点接上 |
| `node.children[ch] = Trie()` | 新节点和根是同一种结构，所以能一层层接下去 |
| `node = node.children[ch]` | 走到子节点，准备处理下一个字符 |
| `node.is_end = True` | 整个单词走完了才盖章。盖在循环里会让每个前缀都变成单词 |
| `def _walk(self, s):` | 把"顺着走"抽出来，两个查询方法共用 |
| `if ch not in node.children: return None` | 走不通，直接说没有 |
| `return node is not None and node.is_end` | `search` 要两个条件都满足：走得通 **且** 盖过章 |
| `return self._walk(prefix) is not None` | `startsWith` 只要走得通就行 |

### 考什么

- 表面考点：设计一个类，实现三个方法。
- 真正考点：**把字符串的公共前缀共享成一棵树**。每个节点不代表一个字符，而代表"从根走到这里的这条前缀"。
- 面试官想听到的关键句：① 查前缀不用遍历整个词典，顺着字符走 L 步就够；② 单词结尾必须单独标记，否则 `app` 和 `apple` 分不开。

### 思路是怎么想出来的

先想最笨的：用一个 `set` 存所有单词。`search` 是 O(L)（哈希整个字符串）；`startsWith` 呢？只能把 set 里每个词都拿出来看开头，O(单词数 × L)。词典一大就废了。

问题出在：`apple`、`app`、`application` 共享前三个字符，set 把它们当成三个互不相干的整体，前缀信息被浪费了。

Trie 的做法是把这层共享显式建出来：每个节点存"下一个字符 → 子节点"的映射，从根往下走一条路径，路径上的字符拼起来就是一个前缀。

```
root
 ├── a ── p ── p ── l ── e   ★
 └── b ── a ── d            ★
```

★ 表示"这里是一个单词的结尾"。插入 `apple` 和 `bad` 之后长这样。注意 `app` 不是单词，但 `a → p → p` 这条路径存在，因为它是 `apple` 的前缀。

于是三个操作都变成"顺着字符走"：

- `insert(word)`：从根开始，每个字符没有对应孩子就新建一个，走完把最后一个节点标成 ★。
- `search(word)`：走完，节点存在并且是 ★，才是单词。
- `startsWith(prefix)`：走完，节点存在就行，不用管 ★。

`search("app")` 走得到节点，但它不是 ★，所以 False；`startsWith("app")` 同样走得到，所以 True。示例里那一对 True/False 考的就是这个区别。

节点长什么样？两种写法：

| 写法 | 优点 | 缺点 |
|---|---|---|
| `children = {}`（字典） | 只存实际出现的字符，省内存；不关心字符集 | 每次查找多一次哈希 |
| `children = [None] * 26`（数组） | 下标直接算，快；面试官常默认这种 | 每个节点固定 26 个槽，稀疏时浪费 |

题面限定小写字母，所以 26 数组可行；字符集不确定时字典更稳。下面主代码用字典，后面给一版数组。

### 代码（Python）

```python
class Trie:
    def __init__(self):
        self.children = {}      # 字符 -> 子节点
        self.is_end = False     # 从根到这里是不是一个完整单词

    def insert(self, word: str) -> None:
        node = self
        for ch in word:
            if ch not in node.children:
                node.children[ch] = Trie()
            node = node.children[ch]
        node.is_end = True

    def _walk(self, s: str):
        """顺着 s 走，走得到就返回末端节点，走不到返回 None"""
        node = self
        for ch in s:
            if ch not in node.children:
                return None
            node = node.children[ch]
        return node

    def search(self, word: str) -> bool:
        node = self._walk(word)
        return node is not None and node.is_end

    def startsWith(self, prefix: str) -> bool:
        return self._walk(prefix) is not None
```

**逐段讲解**：

- `self.children = {}` 写在 `__init__` 里，每个节点一份。写成类属性 `children = {}` 会让所有节点共享同一个字典，插一个词全树都变。
- `Trie()` 造出来的子节点和根是同一种结构，所以"子树"就是另一个 Trie，插入时可以一层层往下走。
- `insert` 里"没有就新建，有就复用"，复用这一步就是前缀共享。
- `is_end` 只在走完整个单词之后置 True。在循环里置 True 的话，`apple` 会让 `a`、`ap`、`app` 全都变成单词。
- `_walk` 抽出来给 `search` 和 `startsWith` 共用，两个方法的差别只有最后那一下。
- `search` 必须 `node is not None and node.is_end`，两个条件缺一不可。

数组版（同样的逻辑，换个存法）：

```python
class TrieArray:
    def __init__(self):
        self.children = [None] * 26
        self.is_end = False

    def insert(self, word: str) -> None:
        node = self
        for ch in word:
            i = ord(ch) - ord('a')
            if node.children[i] is None:
                node.children[i] = TrieArray()
            node = node.children[i]
        node.is_end = True

    def _walk(self, s: str):
        node = self
        for ch in s:
            node = node.children[ord(ch) - ord('a')]
            if node is None:
                return None
        return node

    def search(self, word: str) -> bool:
        node = self._walk(word)
        return node is not None and node.is_end

    def startsWith(self, prefix: str) -> bool:
        return self._walk(prefix) is not None
```

### 复杂度

- 时间：三个操作都是 O(L)，L 是传入字符串的长度。跟词典里有多少词无关，这是 Trie 的价值。
- 空间 O(总字符数)：所有单词的字符总数；数组版还要乘上每个节点 26 个槽的固定开销。

### 常见误区（★ 最容易丢分的地方）

1. **`search` 只看节点存在**：插入 `apple` 后 `search("app")` 返回 True，示例直接挂。
2. **`is_end` 在循环里置 True**：`apple` 会让 `a`、`ap`、`app` 都变成单词。
3. **`children` 写成类属性**：所有实例共享一个字典，第二个 Trie 对象会看到第一个的词。
4. **`startsWith` 也检查 `is_end`**：`startsWith("app")` 返回 False，示例挂。
5. **数组版忘了 `- ord('a')`**：`IndexError`，或者所有字符挤到同一个槽。
6. **以为 Trie 的 `search` 是 O(1)**：哈希整个字符串是 O(L)，Trie 也是 O(L)。Trie 赢在前缀查询和共享内存，不赢在单次查找。

### 面试追问 / 变体

- 力扣 211：前缀里带 `.` 通配符，见下一题。
- 统计"以 prefix 开头的单词有多少个"：每个节点加一个 `count`，插入时沿途 +1。
- 删除单词：走到底把 `is_end` 置 False，再自底向上把没有孩子、也不是单词结尾的节点剪掉。
- 力扣 212「单词搜索 II」：把词典建成 Trie，在网格上 DFS 时顺着 Trie 走，走不动就剪枝。
- 内存优化：把单字符节点压成"一段字符串 + 子节点"（压缩前缀树），代价是插入时要拆分节点。

### 自测

- 必测用例：题面 7 步操作 → `[null,null,true,false,true,null,true]`；空 Trie `search("a") → False`、`startsWith("") → True`；只插了 `apple` 时 `startsWith("apples") → False`；重复插入同一个词不报错。
- 30 秒自检：能不能画出插入 `apple`、`bad` 之后的树，并指出 `search("app")` 和 `startsWith("app")` 分别停在哪个节点、看哪个字段。

## 专题6-4. 添加与搜索单词（Medium）

> 力扣 211 · 前缀树 + DFS · 设计题
> 前置：本册 6-3（先把 Trie 的节点结构吃透）

**一句话**：在 Trie 上支持带 `.` 的查询，`.` 可以代表任意一个字母。

### 精讲（零基础版）

#### ① 这题要用到的东西

**通配符 `.`**

一句话：查询串里的 `.` 表示"这里可以是任意一个字母"。

生活类比：填空题里的横线，填什么都行，但只能填一个字。

**DFS（深度优先搜索）**

一句话：一条路走到黑，走不通了退回上一个岔口，换一条路再走。

生活类比：走迷宫，手一直扶着左墙往前；走进死胡同就退回来，退到上一个路口换方向。

**回溯**

一句话：DFS 里"试完一种可能，把状态退回原样，再试下一种"的那个动作。

这题里不需要手动撤销什么——因为"走到第几个字符"是靠参数 `i` 往下传的，函数返回时 `i` 自然就回到上一层了，没有改过的全局变量要恢复。

**`dict.get()`**

一句话：查键，查不到返回 `None`，而不是报错。

```python
d = {"a": 1}
print(d.get("a"))      # -> 1
print(d.get("z"))      # -> None
print(d.get("z", 0))   # -> 0     第二个参数是"查不到时给什么"
```

对比一下 `d["z"]`：那会直接抛 `KeyError`。这题里用 `get` 就是为了"查不到就当走不通"，不用额外写判断。

**`any()`**

一句话：只要有一个是 True，结果就是 True；全是 False 才是 False。

```python
print(any([False, True, False]))   # -> True
print(any([False, False]))         # -> False
print(all([True, True]))           # -> True
```

`any` 还是**短路**的：找到第一个 True 就立刻返回，后面的根本不跑。这题里它负责"所有孩子里只要有一个能走通，就算成功"。

**Trie**（前面 6-3 讲过）：把公共前缀合并成树，每个节点存"字符 → 子节点"。

#### ② 大白话：这题到底在干什么

最笨的办法：把所有单词都存进一个 list，查询时挨个比对，`.` 的位置上不管是什么都算匹配。能对，但每次查询都要扫一遍全部单词。

笨在哪：明明知道第一个字符是 `b`，那些以 `d`、`m` 开头的词根本不用看，可 list 不会帮你跳过。

聪明办法：还是用 6-3 的 Trie，只是查询方式要改。普通字符仍然只有一条路，顺着走就行；碰到 `.`，当前节点下面可能挂着好几个孩子，每一个都值得试一试——只要有一个孩子能把剩下的部分走通，整个查询就成功。

"试所有可能，有一个成功就行"，翻译成代码就是"递归 + `any`"。这也是 211 比 208 多出来的全部难度：208 的查询是一条链，211 的查询是一棵搜索树。

有个细节必须盯住：递归要同时传两个东西——**站在哪个节点**和**匹配到第几个字符**。因为 `.` 会让"一个节点对应一个字符"这件事失效，你不能只靠一个循环变量往前推。

#### ③ 插入 `bad`、`dad`、`mad` 之后，走一遍查询

```
root
 ├── b ── a ── d ★
 ├── d ── a ── d ★
 └── m ── a ── d ★
```

| 查询 | 第 0 位 | 第 1 位 | 第 2 位 | 第 3 位 | 结果 |
|---|---|---|---|---|---|
| `.ad` | `.`，试 b/d/m 三棵 | 三棵都有 `a` | 三棵都有 `d` | 走到头，`is_end` 为 True | True |
| `b..` | `b`，唯一一条路 | `.`，只有孩子 `a` | `.`，只有孩子 `d` | 走到头，`is_end` 为 True | True |
| `b...` | `b` | `.` → `a` | `.` → `d` | `.`，但 `d` 没有孩子，试 0 个 | False |
| `b` | `b` | — | — | 走到头，`is_end` 为 False | False |

所以 `.ad` 是 True、`b...` 是 False。注意最后一行 `b`：路径存在，但它不是一个完整单词，所以 False。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `addWord` 和 6-3 的 `insert` 一样 | 通配符只影响查询，不影响插入 |
| `def dfs(node, i):` | `node` 是站在哪个前缀节点，`i` 是已经匹配到第几个字符 |
| `if node is None: return False` | 上一步就走空了（`get` 查不到会返回 None） |
| `if i == len(word): return node.is_end` | 单词用完了，看这里是不是结尾。不能直接 `return True` |
| `ch = word[i]` | 取当前要匹配的字符。**必须放在长度判断之后**，否则越界 |
| `if ch == '.':` | 通配符分支 |
| `return any(dfs(child, i + 1) for child in node.children.values())` | 所有孩子各试一次，有一个通就行；`.values()` 只遍历真实存在的孩子，天然跳过空槽 |
| `return dfs(node.children.get(ch), i + 1)` | 普通字符只有一条路；查不到就是 None，交给下一层的 `if node is None` 判掉 |

### 考什么

- 表面考点：在 208 的基础上加通配符。
- 真正考点：**`.` 把确定性查找变成了分支搜索**。原来是"顺着唯一的路走"，现在遇到 `.` 要把所有孩子都试一遍，本质是一次受 Trie 结构约束的 DFS。
- 面试官想听到的关键句：① 普通字符仍然只有一条路，只有 `.` 需要枚举孩子；② 枚举孩子加递归下一位，天然就是回溯，不需要额外记录路径。

### 思路是怎么想出来的

先看没有 `.` 的情况，那就是 208 的 `search`。现在多了 `.`，分两种：

- 当前字符是普通字母：和以前一样，`children.get(ch)`，没有就失败。
- 当前字符是 `.`：当前节点可能有好几个孩子，每一个都值得试。只要有一个孩子能走通剩下的部分，整体就成功。

"试所有可能，有一个成功就行"——这句话翻译成代码就是递归加 `any`。这也是 211 比 208 多出来的全部难度：208 的查询是一条链，211 的查询是一棵搜索树，最坏情况要展开很多分支。

```
root
 ├── b ── a ── d ★
 ├── d ── a ── d ★
 └── m ── a ── d ★

search(".ad")：第 0 位是 '.'，分别试 b、d、m 三棵子树，后两位固定是 "ad"
               三条都通，返回 True
search("b..")：b 之后第一位 '.' 只有一个孩子 a；再一位 '.' 只有 d
               返回 True
search("b...")：走到 d 之后单词还没完，但 d 没有孩子，返回 False
```

递归函数需要两个参数：**当前节点**和**当前匹配到第几个字符**。因为 `.` 会让"节点"和"下标"不再一一对应，不能只靠一个循环变量推进。

终止条件：`i == len(word)` 时，看当前节点是不是 ★。这里不能提前返回 True，单词必须刚好用完。

### 代码（Python）

```python
class WordDictionary:
    def __init__(self):
        self.children = {}
        self.is_end = False

    def addWord(self, word: str) -> None:
        node = self
        for ch in word:
            if ch not in node.children:
                node.children[ch] = WordDictionary()
            node = node.children[ch]
        node.is_end = True

    def search(self, word: str) -> bool:
        def dfs(node, i: int) -> bool:
            if node is None:                 # 上一步就走空了
                return False
            if i == len(word):               # 单词用完，看是不是结尾
                return node.is_end

            ch = word[i]
            if ch == '.':
                # 所有孩子都试一遍，有一个通就行
                return any(dfs(child, i + 1) for child in node.children.values())
            # 普通字符：只有一条路
            return dfs(node.children.get(ch), i + 1)

        return dfs(self, 0)
```

**逐段讲解**：

- `addWord` 和 208 的 `insert` 一模一样，一个字都没变。通配符只影响查询。
- `dfs(node, i)` 的两个参数：`node` 是"现在站在哪个前缀节点"，`i` 是"已经匹配到第几个字符"。分开传是因为 `.` 之后可能同时站在多个节点上，不能靠循环推进。
- `if node is None: return False`：`children.get(ch)` 查不到会返回 None，下一层直接判失败，普通字符那条路不用额外写判断。
- `i == len(word)` 时返回 `node.is_end`：长度必须刚好相等。只存了 `bad` 的时候，`search("b")` 走到 b 就停了，b 不是 ★，返回 False。
- `any(...)` 是短路求值：第一个孩子走通就停，不会白跑后面的分支。
- `.` 分支遍历 `node.children.values()`，不是遍历 26 个字母。字典里只存了实际存在的字符，天然跳过空槽。

### 复杂度

- `addWord`：O(L)。
- `search`：没有 `.` 时 O(L)；有 k 个 `.` 时最坏 O(26^k)，实际只走存在的分支，上界是 Trie 的节点数。题目限定 L ≤ 25、调用总次数 ≤ 10^4，能过。
- 空间：递归深度 O(L)，Trie 本身 O(总字符数)。

### 常见误区（★ 最容易丢分的地方）

1. **`.` 只试第一个孩子**：`.ad` 可能碰巧对（如果 b 分支恰好也是 ad），但 `b..` 这类一定会错。必须遍历全部孩子。
2. **`i == len(word)` 时直接 `return True`**：只存了 `bad` 时 `search("b")` 返回 True，因为路径存在，但 b 不是单词结尾。
3. **`.` 当成普通字符存进 `children`**：`addWord` 不会存 `.`，查询时 `children.get('.')` 永远是 None，所有带 `.` 的查询全 False。
4. **`any` 写成 `all`**：要求所有孩子都匹配上，几乎必然返回 False。
5. **先取 `word[i]` 再判断长度**：`i` 已经越界时抛 `IndexError`。终止条件的判断必须放在取字符之前。

### 面试追问 / 变体

- 支持 `*`（匹配任意长度，含空串）：光靠 `.` 式的分支不够，还要加"原地不动"或"跳过"的选择，变成正则匹配的回溯。
- 返回所有匹配的单词而不只是 True：DFS 到 ★ 时把沿途字符收集起来。
- 大小写不敏感：插入和查询前统一 `lower()`。
- 力扣 212「单词搜索 II」：把这里"在 Trie 上 DFS"的思路搬到二维网格上。

### 自测

- 必测用例：题面 8 步 → `[null,null,null,null,false,true,true,true]`；`addWord("a")` 后 `search(".") → True`、`search("b") → False`；`addWord("ab")` 后 `search("a.") → True`、`search(".b") → True`、`search("..") → True`、`search(".") → False`；空词典 `search("a") → False`。
- 30 秒自检：能不能说出"为什么 dfs 要同时传节点和下标"，以及 `.` 分支为什么用 `any` 而不是循环累加。

## 专题6-5. 二叉搜索树的最近公共祖先（Medium）

> 力扣 235 · 二叉搜索树 · 单向下行
> 前置：本册 6-1（BST 的大小关系）

**一句话**：在 BST 里找 p 和 q 的分叉点，也就是离它们最近的共同祖先。

### 精讲（零基础版）

#### ① 这题要用到的东西

**祖先 / 最近公共祖先（LCA）**

一句话：一个节点的祖先，是从根走到它路上经过的所有节点（包括它自己）。两个节点的最近公共祖先，是它们**共同的**祖先里最深的那个。

生活类比：两个同事分别从自己的工位往总经理办公室走，第一次汇合的那个路口，就是他们的 LCA。

注意"自己也算自己的祖先"，所以 p 是 q 的祖先时，答案就是 p。

**BST**（前面 6-1 讲过）：左边全小、右边全大。这题全靠这条性质。

**`min` / `max` 合并两种情况**

一句话：`min(p.val, q.val)` 拿到较小的那个，`max` 拿较大的。这样不用管 p、q 谁大谁小，后面的判断只写一遍。

**单向下行 vs 后序遍历**

一句话：能"每步判断一次、只往一个方向走、不回头"的走法，叫单向下行。

对比 236（下一题）：普通二叉树没有大小关系，只能左右都搜、搜完再汇总，那就是后序遍历。

#### ② 大白话：这题到底在干什么

最笨的办法：把 p 到根的所有祖先收集成一个 list，q 的也收集一个，然后从后往前找第一个相同的。能对，但要额外的 list 存祖先，还得先能往上走——而树只有向下的指针。

笨在哪：为了"往上走"，你得先把整棵树遍历一遍、记下每个节点的父亲，白费一趟。

聪明办法：BST 有个白送的性质——站在任意节点 x 上，比一下值就知道 p、q 在哪边。

- p、q 都比 x 小：两个都在左子树，LCA 一定也在左边，往左走一步。
- p、q 都比 x 大：同理，往右走。
- 一个比 x 小、一个比 x 大：它们从这里分开，x 就是分叉点，也就是 LCA。

第三种为什么就是答案？因为比 x 更深的节点只能覆盖一边，不可能同时是两者的祖先；而 x 本身是两者的祖先。所以 x 是最近的。

还有个容易漏的情况：p 或 q 就是 x 自己。这时也该归到第三种，直接返回 x——不能再往下走了。

#### ③ 拿题面的树走两遍

p = 2、q = 8：

| 步骤 | 站在 | 比一下 | 判断 | 下一步 |
|---|---|---|---|---|
| 1 | 6 | 2 < 6 < 8 | 一个在左一个在右，分叉了 | 返回 6 |

只有一步。再走 p = 2、q = 4：

| 步骤 | 站在 | 比一下 | 判断 | 下一步 |
|---|---|---|---|---|
| 1 | 6 | 2 < 6，4 < 6 | 两个都在左边 | 往左到 2 |
| 2 | 2 | p 就是自己，q=4 在自己右子树 | 既不是"都小"也不是"都大" | 返回 2 |

所以答案分别是 6 和 2。第二例说明了"其中一个就是当前节点"必须归到第三种，不能继续往下走。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `low, high = min(p.val, q.val), max(p.val, q.val)` | 先把两个值排好，后面只写一套判断 |
| `node = root` | 从根开始 |
| `while node:` | 一路往下，不停 |
| `if node.val < low:` | 当前节点比两个都小 → 两个都在右边 |
| `node = node.right` | 往右走一步 |
| `elif node.val > high:` | 当前节点比两个都大 → 两个都在左边 |
| `node = node.left` | 往左走一步 |
| `else: return node` | 剩下的情况：`low <= node.val <= high`，夹在中间（含等于），就是分叉点 |
| `return None` | 防御性出口。题面保证 p、q 都在树里，一定撞得到 |

### 考什么

- 表面考点：最近公共祖先的定义。
- 真正考点：**BST 的大小关系能告诉你 p、q 在哪边**，所以不用搜整棵树，一条路走下去就行。
- 面试官想听到的关键句：p、q 一个比当前节点小、一个比当前节点大，当前节点就是分叉点；否则两个都在同一边，往那边走。

### 思路是怎么想出来的

先把"最近公共祖先"说清楚：它是 p、q 共同的祖先里，离 p、q 最近（最深）的那个。一个节点可以是自己的祖先，所以 p 是 q 的祖先时，答案是 p。

普通二叉树里你不知道 p、q 在哪，只能两边都搜（下一题）。但 BST 有一条额外规矩：左边的都小，右边的都大。站在任意节点 x 上，p、q 的位置只有三种可能：

```
        x
      /   \
   左边    右边

1) p、q 都小于 x  → 两个都在左子树，LCA 一定在左边，往左走
2) p、q 都大于 x  → 两个都在右子树，往右走
3) 一个小于 x、一个大于 x（或其中一个就是 x）→ 它们在这里分开，x 就是 LCA
```

第三种为什么就是答案：如果 p 在左、q 在右，那么任何比 x 更深的节点都只覆盖一边，不可能同时是两者的祖先；而 x 本身是两者的祖先（BST 里 p 在左子树、q 在右子树，都挂在 x 下面）。所以 x 是最近的。

用题面的树走一遍，p = 2、q = 8：

```
          6
         / \
        2   8
       / \ / \
      0  4 7  9
        / \
       3   5

站在 6：2 < 6 < 8，一个左一个右，6 就是 LCA，停。
```

再走 p = 2、q = 4：

```
站在 6：2 < 6，4 < 6，都在左边，往左到 2
站在 2：q = 4 就在自己的右子树里，p 就是自己
        不属于"都小于"也不属于"都大于"，2 就是 LCA
```

第二例正好说明"其中一个就是当前节点"也要归到第三种情况，不能继续往下走。

和 236 对照着看，两题的差别只有一句话：BST 里"值的大小"能告诉你 p、q 在哪边，普通二叉树不能。这一点差别决定了整份代码的形状：

| 对比项 | 235 二叉搜索树 | 236 普通二叉树 |
|---|---|---|
| 判断 p、q 在哪边 | 比较值，立刻知道 | 不知道，只能搜 |
| 走法 | 单向下行，不回退 | 后序遍历，左右都要 |
| 时间 | O(h) | O(n) |
| 写法 | 迭代最自然，O(1) 空间 | 递归最自然，O(h) 空间 |

下一题就来看"没有这条性质"要付出什么代价。

### 代码（Python）

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def lowestCommonAncestor(self, root: TreeNode,
                             p: TreeNode, q: TreeNode) -> TreeNode:
        low, high = min(p.val, q.val), max(p.val, q.val)
        node = root
        while node:
            if node.val < low:          # 当前节点比两个都小，两个都在右边
                node = node.right
            elif node.val > high:       # 当前节点比两个都大，两个都在左边
                node = node.left
            else:                       # 分叉了，或者撞上其中一个
                return node
        return None
```

递归版更短，面试也常写：

```python
class SolutionRec:
    def lowestCommonAncestor(self, root: TreeNode,
                             p: TreeNode, q: TreeNode) -> TreeNode:
        if root.val < p.val and root.val < q.val:
            return self.lowestCommonAncestor(root.right, p, q)
        if root.val > p.val and root.val > q.val:
            return self.lowestCommonAncestor(root.left, p, q)
        return root
```

**逐段讲解**：

- 先算 `low`、`high`，把"p 小 q 大"和"q 小 p 大"合并。不合并也行，但三个 `if` 会变成一堆 `and`/`or`。
- `node.val < low` 表示当前节点比两个都小，两个都在右边，往右走。
- `node.val > high` 表示当前节点比两个都大，两个都在左边，往左走。
- 剩下的情况是 `low <= node.val <= high`，当前节点夹在两者之间（含等于），返回它。
- `while node` 配末尾的 `return None` 是防御性写法。题面保证 p、q 都在树里，一定能撞到，但保留出口不会错。

### 复杂度

- 时间 O(h)：每步只往一个方向走，h 是树高。平衡 BST 是 O(log n)，最坏链状 O(n)。
- 空间：迭代 O(1)，递归 O(h)。

### 常见误区（★ 最容易丢分的地方）

1. **照搬 236 的通用解法**：能过，但是 O(n)。面试官问"能用 BST 性质做到 O(h) 吗"就答不上来。
2. **判断方向反了**：`root.val > p.val and root.val > q.val` 时往右走，会一路走到空。
3. **把"等于"写成 `<=` / `>=`**：p 就是当前节点时还会继续往下走，走到 None 报错。
4. **返回节点却返回了值**：力扣要求返回 `TreeNode`，不是 `int`。本地自测时要先按值找到节点对象。
5. **以为 p、q 一定分居两侧**：p 可以是 q 的祖先，这时答案是 p 本身，靠"等于"分支兜住。

### 面试追问 / 变体

- 力扣 236：普通二叉树，没有大小关系，只能后序搜索，O(n)。见下一题。
- 如果 p、q 可能不在树里：先各搜一遍确认存在，再找 LCA（力扣 1644 就是这个设定）。
- 如果 BST 允许重复值：比较要改成严格的边界处理，或者先约定重复值放哪边。
- 如果要多次查询同一棵树：预处理每个节点的父节点，或者用欧拉序加 RMQ，单次查询更快，但那属于另一类题。

### 自测

- 必测用例：`[6,2,8,0,4,7,9,null,null,3,5], p=2, q=8 → 6`；同树 `p=2, q=4 → 2`；`p=3, q=5 → 4`；`p=0, q=9 → 6`；`[2,1], p=2, q=1 → 2`；把 p、q 顺序对调结果不变。
- 30 秒自检：能不能说出三种位置关系，以及"等于"为什么归到第三种。

## 专题6-6. 二叉树的最近公共祖先（Medium）

> 力扣 236 · 二叉树 · 后序遍历
> 前置：本册 6-5（先看 BST 版，再对比这题）

**一句话**：普通二叉树里找 p、q 的最近公共祖先，没有大小关系可用。

### 精讲（零基础版）

#### ① 这题要用到的东西

**后序遍历的"汇报"机制**（前面 6-2 讲过后序）：先让左右子树各自跑完，拿到两个结果，再决定自己返回什么。这题就靠它——父亲必须知道左右两边各自找到了谁。

**`is` 和 `==`**

一句话：`==` 比"值一样不一样"，`is` 比"是不是同一个对象"。

```python
a = [1, 2]
b = [1, 2]
c = a
print(a == b)     # -> True    内容一样
print(a is b)     # -> False   两个不同的 list
print(a is c)     # -> True    同一个对象
```

这题里 `root is p` 比 `root.val == p.val` 更稳：它不依赖"值唯一"这个条件。

**`or` 返回的是值，不是 True/False**

一句话：`A or B` 的意思是"如果 A 是真的，就要 A；否则要 B"，它把 A 本身返回给你。

```python
print(None or 5)     # -> 5
print(3 or 5)        # -> 3
print(None or None)  # -> None
```

所以 `return left or right` 的效果是：左边有就返回左边，左边是 None 就返回右边。

#### ② 大白话：这题到底在干什么

最笨的办法：先想办法知道 p、q 各自的全部祖先，再找最深的那个公共的。麻烦在于"往上走"——树只有向下的指针，你得先遍历一遍记下每个节点的父亲。

笨在哪：多存了一张父亲表，多走了一趟。

聪明办法：既然不知道 p、q 在哪边，那就**两边都搜**，搜完再汇总。这就是后序。

给每个节点定一个规矩：我这棵子树里，如果 p、q 都在，我返回它们的 LCA；如果只找到其中一个，我返回找到的那个；都没找到，返回 None。

父亲拿到左右两个返回值就好办了：两边都非空，说明 p、q 一个在左一个在右，父亲自己就是分叉点；只有一边非空，就把那个结果原样往上传。

有个地方特别容易绕晕：搜到 p 就立刻返回、不再往下找 q 了，凭什么对？因为如果 q 真在 p 的子树里，那 p 本来就是 LCA；如果 q 不在，上层会在另一边找到 q，那时上层就成了分叉点。两种情况都对。

#### ③ 拿题面的树走两遍

p = 5、q = 1：

| 步骤 | 调用 | 左边拿到 | 右边拿到 | 返回 |
|---|---|---|---|---|
| 1 | `dfs(5)` | — | — | 5（自己就是 p，直接返回） |
| 2 | `dfs(1)` | — | — | 1（自己就是 q） |
| 3 | `dfs(3)` | 5 | 1 | 两边都非空 → 3 |

答案是 3。再看 p = 5、q = 4：

| 步骤 | 调用 | 左边拿到 | 右边拿到 | 返回 |
|---|---|---|---|---|
| 1 | `dfs(5)` | — | — | 5（自己就是 p，右子树根本没进去） |
| 2 | `dfs(1)`（连同它的孩子 0、8） | None | None | None |
| 3 | `dfs(3)` | 5 | None | 只有左边有 → 5 |

答案是 5。第 1 步明明没去看 q 在哪，为什么返回 5 是对的？因为 5 本身就是 p，而 q = 4 在 5 的子树里，5 一定是 LCA。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `if not root or root is p or root is q: return root` | 一行管三件事：空树返回 None；撞上 p 返回 p；撞上 q 返回 q |
| `left = self.lowestCommonAncestor(root.left, p, q)` | 先问左边，把结果存下来 |
| `right = self.lowestCommonAncestor(root.right, p, q)` | 再问右边。**不能**找到左边就提前返回 |
| `if left and right: return root` | 两边都非空 → p、q 分居两侧，自己就是分叉点 |
| `return left or right` | 只有一边有结果，原样往上传；两边都空就传 None |

### 考什么

- 表面考点：LCA。
- 真正考点：**后序遍历的"汇报"机制**。每个节点向父亲汇报"我这棵子树里找到了谁"，父亲根据左右两边的汇报决定自己是不是分叉点。
- 面试官想听到的关键句：左子树和右子树都汇报"找到了"，当前节点就是 LCA；只有一边汇报，就把那个结果原样往上传。

### 思路是怎么想出来的

没有 BST 的大小关系，站在节点 x 上你无法判断 p、q 在哪边。唯一能做的就是**两边都搜**，搜完再汇总。这就是后序：先要左右子树的结果，再决定自己返回什么。

定义 `dfs(node)` 的返回值：在以 node 为根的子树里，

- 如果 p、q 都在，返回它们的 LCA；
- 如果只找到其中一个，返回找到的那个节点；
- 都没找到，返回 None。

这个定义看着绕，但它是自洽的：父亲拿到左右两个返回值，就能判断。

```
          3
        /   \
       5     1
      / \   / \
     6   2 0   8
        / \
       7   4

p = 5, q = 1：
  dfs(5) 返回 5（自己是 p）
  dfs(1) 返回 1（自己是 q）
  在 3 这里，左右都非空，3 是 LCA
```

```
p = 5, q = 4：
  dfs(5)：自己是 p，直接返回 5，它的右子树根本没进去
  dfs(1)：这棵子树里既没有 p 也没有 q，返回 None
  在 3 这里，左边是 5、右边是 None，返回 5
```

第二个例子是这题最容易绕晕的地方：dfs(5) 明明没去看 q 在哪，为什么返回 5 是对的？因为 5 本身就是 p，而 q = 4 在 5 的子树里，所以 5 一定是 LCA。递归不需要证明这一点，它只需要保证"如果 p、q 都在我的子树里，我返回的一定是 LCA"。

三种情况归纳一下：

| 左右返回值 | 含义 | 返回 |
|---|---|---|
| 都非空 | p、q 分居两侧 | 当前节点 |
| 只有左边非空 | 两个都在左边，或只找到左边那个 | 左边的结果 |
| 只有右边非空 | 同理 | 右边的结果 |
| 都为空 | 这棵子树里既没有 p 也没有 q | None |

### 代码（Python）

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def lowestCommonAncestor(self, root: TreeNode,
                             p: TreeNode, q: TreeNode) -> TreeNode:
        # 空树，或者撞上 p / q 本身，直接返回
        if not root or root is p or root is q:
            return root

        left = self.lowestCommonAncestor(root.left, p, q)
        right = self.lowestCommonAncestor(root.right, p, q)

        if left and right:      # 两边都找到了，当前节点是分叉点
            return root
        return left or right    # 只有一边有结果，原样上传
```

**逐段讲解**：

- `if not root or root is p or root is q: return root`：一行处理三件事——空树返回 None、撞上 p 返回 p、撞上 q 返回 q。撞上就返回，是因为"我这里是 p，那 p 就在我这棵子树里"。
- `left`、`right` 必须都算出来，不能找到左边就提前返回。这是后序和"找到就停"的区别：你必须知道另一边有没有。
- `if left and right: return root`：左右都非空，说明 p、q 一个在左一个在右，当前节点是它们能共同到达的最深节点。
- `return left or right`：Python 的 `or` 返回第一个真值。左边有就返回左边，否则返回右边（可能都是 None）。
- 用 `root is p` 而不是 `root.val == p.val`：题面保证值唯一，两种都对；用对象身份不依赖"值唯一"这个条件，更稳。

### 复杂度

- 时间 O(n)：最坏要把每个节点看一遍。
- 空间 O(h)：递归栈。

### 常见误区（★ 最容易丢分的地方）

1. **找到 p 就立刻返回，不再搜另一侧**：如果 q 在 p 的兄弟子树里，上层拿到的只有 p，会把 p 当成 LCA。必须两边都搜完再判断。
2. **`if left and right` 写成 `if left or right`**：永远返回第一个找到的节点，示例 1 会返回 5 而不是 3。
3. **把返回值理解成"找到了几个"**：返回的是节点，不是计数。用计数也能做（返回 0/1/2），但那是另一套写法，别混着写。
4. **递归深度**：节点上限 10^5，链状树高 10^5，本地会抛 `RecursionError`（默认上限约 1000）。力扣的 Python 环境放宽了上限，递归解能提交；面试时要能说出迭代方案。
5. **拿 235 的写法套过来**：普通二叉树没有 `node.val < p.val` 这种判断依据，写了就是错的。

### 面试追问 / 变体

- 迭代版：从根开始 DFS，用 `parent` 字典记每个节点的父亲，再从 p 往上染色，最后让 q 往上走，第一个染过色的就是 LCA。O(n) 时间、O(n) 空间，不用递归。
- 力扣 235：BST 版本，利用大小关系做到 O(h)。两题的差距就是"有没有序"。
- 力扣 1644：p、q 可能不存在，要先确认两个都找到。
- 要查很多次：预处理每个节点的深度和父节点（或欧拉序加 RMQ），单次查询更快。

### 自测

- 必测用例：`[3,5,1,6,2,0,8,null,null,7,4], p=5, q=1 → 3`；同树 `p=5, q=4 → 5`；`p=7, q=4 → 2`；`p=6, q=4 → 5`；`[1,2], p=1, q=2 → 1`；p、q 顺序对调结果不变。
- 30 秒自检：能不能说出 `dfs` 返回值的三种含义，以及"为什么找到 p 之后还要搜另一侧"。

## 专题6-7. 二叉树的序列化与反序列化（Hard）

> 力扣 297 · 二叉树 · 设计题 · 前序遍历 + 迭代器
> 前置：[第一册 C8 从前序与中序遍历序列构造二叉树](12-分册C-链表树图.md)

**一句话**：把一棵树变成字符串，再从这个字符串把一模一样的树造回来。

### 精讲（零基础版）

#### ① 这题要用到的东西

**序列化 / 反序列化**

一句话：序列化是把内存里的结构变成一串字符，反序列化是拿这串字符把结构原样造回来，两个方向必须互逆。

生活类比：把一堆积木拍照存档（序列化），再照着照片重新搭一遍（反序列化）。照片得拍得够清楚，清楚到只有一种搭法。

**编码必须无歧义**

一句话：同一串字符，只能读出一棵树。

`1,2` 这串记号就有歧义：2 可能是 1 的左孩子，也可能是右孩子。要消掉歧义，就得把"空位"也写进串里。

**迭代器 `iter()` / `next()`**

一句话：把一串东西包装成一个"只能往前取"的取物口，每 `next` 一次往前走一格。

```python
tokens = iter(["1", "#", "2"])
print(next(tokens))     # -> 1
print(next(tokens))     # -> #
print(next(tokens))     # -> 2
```

好处是"取到哪了"这个状态存在迭代器自己身上，递归的每一层共享同一个进度，不用你手动传下标。

**`','.join()` 和 `split(',')`**

一句话：`join` 把一堆字符串用分隔符粘成一个，`split` 反过来切开。

```python
parts = ["1", "#", "2"]
s = ",".join(parts)
print(s)              # -> 1,#,2
print(s.split(","))   # -> ['1', '#', '2']
print("#".split(",")) # -> ['#']
```

注意最后一行：`split` 永远返回 list，哪怕只有一个元素。

**队列（deque）**

一句话：一头进、另一头出，先进先出。BFS 版序列化用它逐层输出。

```python
from collections import deque

q = deque([1])
q.append(2)          # 队尾进
q.append(3)
print(q.popleft())   # -> 1    队头出
print(list(q))       # -> [2, 3]
```

#### ② 大白话：这题到底在干什么

最笨的办法：把前序遍历的结果拼成一个串。`[1,2]` 这棵树前序是 `1,2`，看着挺像那么回事。

笨在哪：还原不了。`1,2` 里的 2 到底是 1 的左孩子还是右孩子？两种树的前序都是 `1,2`，一模一样。信息丢了，再聪明也补不回来。

丢在哪：前序只记了"根什么时候出现"，没记"一棵子树什么时候结束"。

聪明办法：把空位置也写进串里，规定空节点记作 `#`。左孩子那棵树变成 `1,2,#,#,#`，右孩子那棵变成 `1,#,2,#,#`，一眼就分开。

为什么这样就唯一了？因为前序的访问顺序是"根、整个左子树、整个右子树"，而 `#` 给每棵子树画上了明确的句号：读到 `#`，就说明"这棵子树是空的，到此为止"。递归天然是"读完一棵子树正好停在它的边界上"，所以同一串记号只有一种读法。

反序列化就是把这串记号按同样的顺序读一遍：读一个建一个节点，然后递归建它的左、再建它的右。

为什么不用中序或后序？中序的根夹在中间，读到第一个记号时你不知道它是谁；后序的根在最后，得从后往前消费，写起来别扭。前序的根永远在最前面，最适合"读一个、建一个"。

#### ③ 拿 `[1,2,3,null,null,4,5]` 走一遍

```
      1
     / \
    2   3
       / \
      4   5
```

| 步骤 | 访问 | 记下的记号 | parts 现在长这样 |
|---|---|---|---|
| 1 | 1 | `1` | `1` |
| 2 | 1 的左 → 2 | `2` | `1,2` |
| 3 | 2 的左 → 空 | `#` | `1,2,#` |
| 4 | 2 的右 → 空 | `#` | `1,2,#,#` |
| 5 | 1 的右 → 3 | `3` | `1,2,#,#,3` |
| 6 | 3 的左 → 4 | `4` | `1,2,#,#,3,4` |
| 7 | 4 的左 → 空 | `#` | `1,2,#,#,3,4,#` |
| 8 | 4 的右 → 空 | `#` | `1,2,#,#,3,4,#,#` |
| 9 | 3 的右 → 5 | `5` | `1,2,#,#,3,4,#,#,5` |
| 10 | 5 的左、右都是空 | `#,#` | `1,2,#,#,3,4,#,#,5,#,#` |

所以序列化结果是 `1,2,#,#,3,4,#,#,5,#,#`，一共 11 个记号 = 2×5+1（5 个节点值 + 6 个 `#`）。

反序列化拿这串从头读：`1` 建根 → 递归建左，读到 `2` → 2 的左读到 `#`、右读到 `#`，2 建完 → 回到 1 建右，读到 `3` → 3 的左读到 `4`，4 的左右都是 `#` → 3 的右读到 `5`，5 的左右都是 `#`。还原出来的层序是 `[1,2,3,null,null,4,5]`，和原来一样。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `parts = []` | 先把记号收进 list，最后一次性 `join`，比反复拼字符串快 |
| `if not node: parts.append('#'); return` | 整道题的灵魂：空位不是"省略"，是"必须记下来" |
| `parts.append(str(node.val))` | 记下当前节点的值，要转成字符串才能 `join` |
| `dfs(node.left)` 和 `dfs(node.right)` | 按前序走：先左后右 |
| `','.join(parts)` | 用逗号粘成一个串。分隔符必须有，否则 `1,2` 和 `12` 分不清 |
| `tokens = iter(data.split(','))` | 先切成 list，再包成迭代器，进度存在它自己身上 |
| `token = next(tokens)` | 按前序顺序，一次取一个 |
| `if token == '#': return None` | 读到 `#` 就是空子树，返回 None，不再往下读 |
| `node = TreeNode(int(token))` | 字符串转成数字，建节点 |
| `node.left = build()` | 紧接着的记号属于左子树 |
| `node.right = build()` | 左子树读完了，剩下的才轮到右子树 |
| `return build()` | 从整串的第一个记号开始 |

最后补一句：如果改用下标 `i`，递归里的 `i += 1` 必须被父层看见，要么 `nonlocal`、要么让 `build` 返回新下标，两种都比迭代器啰嗦。迭代器把"消费到哪了"藏在对象里，天然共享。

### 考什么

- 表面考点：设计两个互逆的方法。
- 真正考点：**编码必须无歧义**。字符串里要包含足够的信息，让"还原"只有一种可能；空位置也要显式记下来。
- 面试官想听到的关键句：① 只存前序不够，`[1,2]` 分不清 2 是左孩子还是右孩子；② 前序加 `#` 标记空位就唯一了，反序列化按同样的顺序递归消费。

### 思路是怎么想出来的

先想最直接的：把前序遍历的结果拼起来。`[1,2,3]` 的前序是 `1,2,3`。但这样还原不了：

```
    1            1
   /              \
  2                2

两棵树的前序都是 1, 2
```

问题在于前序只记录了"根什么时候出现"，没记录"子树什么时候结束"。一棵树的前序是 `1,2`，2 可能是 1 的左孩子，也可能是右孩子。

修法：**把空位置也写进序列**。规定空节点写成 `#`，上面两棵树分别变成：

```
左孩子：1, 2, #, #, #        右孩子：1, #, 2, #, #
```

一眼就能分开。为什么这样就唯一了？因为前序的访问顺序是"根、整个左子树、整个右子树"，而 `#` 给每棵子树画上了明确的句号：

- 读到 `1`，知道根是 1，接下来要读它的左子树；
- 读到 `2`，知道左子树的根是 2，接下来读 2 的左子树；
- 读到 `#`，2 的左子树是空；再读 `#`，2 的右子树是空，2 这棵子树读完了；
- 再读 `#`，1 的右子树是空，整棵树结束。

递归结构天然就是"读完一棵子树正好停在它的边界上"，所以同一串记号只有一种读法。

那为什么不用中序或后序？中序的根夹在左右子树中间，读到第一个记号时你不知道它是谁，得先知道左子树有多长；后序的根在最后，要从后往前消费，写起来别扭。前序的根永远在最前面，天然适合"读一个、建一个"。

用题面示例走一遍：

```
        1
       / \
      2   3
         / \
        4   5

前序加空位：1, 2, #, #, 3, 4, #, #, 5, #, #
```

反序列化就是拿着这串记号，按"根、左、右"的顺序递归建节点。用一个迭代器逐个 `next`，天然保证"每个记号只被消费一次"，也不用维护下标。

再检查两个边界。空树的序列化结果是单个 `#`，反序列化读到一个 `#` 就返回 None；只有一个节点的树是 `1,#,#`，读 1 建根，再读两个 `#` 把左右都填成空。两种极端都被同一套规则处理，说明这套编码没有特例。

### 代码（Python）

```python
from typing import Optional


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Codec:
    def serialize(self, root: Optional[TreeNode]) -> str:
        parts = []

        def dfs(node):
            if not node:
                parts.append('#')       # 空位也要记下来
                return
            parts.append(str(node.val))
            dfs(node.left)
            dfs(node.right)

        dfs(root)
        return ','.join(parts)

    def deserialize(self, data: str) -> Optional[TreeNode]:
        tokens = iter(data.split(','))

        def build():
            token = next(tokens)        # 按前序顺序，一次消费一个
            if token == '#':
                return None
            node = TreeNode(int(token))
            node.left = build()
            node.right = build()
            return node

        return build()
```

**逐段讲解**：

- `parts` 先收集成 list，最后 `','.join`，比在循环里反复拼字符串干净。
- 分隔符必须存在。`[1, 2]` 和 `[12]` 如果直接拼成 `12`，就分不清了。
- `dfs` 里的 `if not node: parts.append('#')` 是整道题的灵魂：空位不是"省略"，而是"必须记录"。
- `iter(data.split(','))` 把 list 变成一次性迭代器，`next` 每调一次前进一格。递归的调用顺序和前序完全一致，所以消费顺序也一致。
- `build()` 里先读根，再 `build()` 左，再 `build()` 右，三行的顺序就是前序的定义。
- 空树序列化成 `"#"`，反序列化时第一个 token 就是 `#`，直接返回 None，不会走进 `int()`。
- 一棵 n 个节点的树，序列化后恰好有 `2n+1` 个记号：n 个节点值，加 n+1 个 `#`（每个空孩子一个，空树自己也算一个）。反序列化消费的记号数正好对上，不多读也不少读。

**为什么用迭代器而不是下标**：如果用 `i` 做下标，递归里 `i += 1` 必须能被父层看见，要么 `nonlocal`，要么让 `build` 返回"新的下标"，两种都比迭代器啰嗦。迭代器把"消费到哪了"这个状态藏在对象里，天然共享。

### 复杂度

- 时间 O(n)：每个节点访问一次，空位也是 n+1 个，反序列化每个 token 消费一次。
- 空间 O(n)：字符串本身 O(n)，递归栈 O(h)，反序列化时 `split` 出的 list O(n)。

### 常见误区（★ 最容易丢分的地方）

1. **不记空位，只存前序**：`[1,2]` 的两种树编码成同一个字符串，反序列化只能猜。
2. **用下标递归但不共享**：`build(i)` 里 `i += 1` 只改当前层，父层的 `i` 不变，左右子树会重复读同一段 token。用迭代器或 `nonlocal`。
3. **不加分隔符**：`12` 到底是 `[1,2]` 还是 `[12]`，无法区分。
4. **用 `token.isdigit()` 判断是不是数字**：`'-1'.isdigit()` 是 False，负数值会被当成空位。要么直接比 `token == '#'`，要么 `try/except`。
5. **空树序列化成空字符串**：`''.split(',')` 得到 `['']`，`int('')` 直接抛异常。空树要返回 `'#'`。
6. **递归深度**：节点上限 10^4，链状树高 10^4，本地会抛 `RecursionError`（默认上限约 1000）。力扣环境放宽了上限，能过；要更稳就换 BFS 版或显式栈。

### 面试追问 / 变体

- 如果节点值里可能出现逗号和 `#`：换分隔符或先转义，本质还是"编码要可逆"。
- 力扣 449「序列化与反序列化 BST」：利用有序性省掉 `#`，只存前序，反序列化时靠上下界划分左右子树。
- 如果要求序列化结果尽量短：可以省掉最后一层末尾的 `#`（力扣控制台显示的就是这种），代价是反序列化要处理"token 已经用完"的情况。
- 树很大、要流式处理：前序加迭代器天然支持边读边建。
- 用 BFS 序列化：队列逐层输出，空位同样写 `#`，反序列化时也用队列，父亲出队、依次认领两个孩子。两种格式都能唯一还原；前序版代码短，BFS 版读起来更接近题面里层序数组的样子。

BFS 版完整代码：

```python
from collections import deque


class CodecBFS:
    def serialize(self, root: Optional[TreeNode]) -> str:
        if not root:
            return '#'
        out, q = [], deque([root])
        while q:
            node = q.popleft()
            if node is None:
                out.append('#')
            else:
                out.append(str(node.val))
                q.append(node.left)
                q.append(node.right)
        return ','.join(out)

    def deserialize(self, data: str) -> Optional[TreeNode]:
        tokens = data.split(',')
        if tokens[0] == '#':
            return None
        root = TreeNode(int(tokens[0]))
        q, i = deque([root]), 1
        while q:
            node = q.popleft()
            if i < len(tokens) and tokens[i] != '#':
                node.left = TreeNode(int(tokens[i]))
                q.append(node.left)
            i += 1
            if i < len(tokens) and tokens[i] != '#':
                node.right = TreeNode(int(tokens[i]))
                q.append(node.right)
            i += 1
        return root
```
