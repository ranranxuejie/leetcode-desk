## 本册要建立的 5 个思维模型

**模型 1：栈 = 只能从尾巴进出的 list。**
不需要 import 任何东西，`append` / `pop()` 都是 O(1)。它是"记住最近发生的事"最省事的容器。B2 和 B6 是它最裸的两次使用。

**模型 2：看到信号词就想栈。**
"最近一次""上一个更大""配对""嵌套""撤销"——这些词都在说同一件事：当前元素要和"最近处理过、还没了结的"东西打交道。把没了结的东西攒在栈里，需要的时候从栈顶取最近的。

**模型 3：单调栈 = 进栈前先把破坏单调性的栈顶弹掉。**
它看起来有嵌套 while，但因为每个元素最多进出各一次，总操作数是 2n，所以是 O(n)。**这是本册最容易被误判成 O(n²) 的地方**，见 0.3 的推导。B1、B5 是它的两个用法。

**模型 4：栈里存下标比存值信息量大。**
下标既能取值（`a[stack[-1]]`），又能算距离（`i - stack[-1]`）。B1 的答案就完全依赖这一点。

**模型 5：栈可以存"任意一组要一起保存的状态"。**
存下标（B1）、存带符号的数（B3）、存 `(字符串, 倍数)`（B4）、存"还没爆炸的小行星"（B6）——容器一直是 list，变的是存什么。动手前先问自己：**谁和谁是一起被记住、一起被取出来的？**

## 零、先把"栈"说清楚（第一次接触栈，这段必读）

### 0.1 栈是什么

Python 里栈不需要 import 任何东西，**它就是一个 `list`**。规矩只有一条：只从尾巴进、只从尾巴出。

```python
stack = []
stack.append(3)   # 进栈，放最上面
stack.append(7)   # 再进一个
stack[-1]         # 看栈顶 -> 7
stack.pop()       # 出栈 -> 7，栈里只剩 [3]
```

`append` 和 `pop()` 都是 O(1)：list 在尾部增删不用搬动别的元素。（头部 `insert(0, x)` 才是 O(n)，所以队列要用 `deque`。）

生活里的类比是**叠盘子**：只能往最上面放、也只能从最上面拿，想拿最底下那只得先把上面的端走。Ctrl+Z 撤销也是栈——最后做的动作最先被撤销。这个性质叫**后进先出**（LIFO）。

### 0.2 什么时候该想到栈

盯住这几类信号词：

| 信号 | 例子 |
| --- | --- |
| "最近一次""上一个""下一个更大/更小" | B1 每日温度、B5 去除重复字母 |
| "配对""合法""嵌套" | B2 括号、B4 字符串解码 |
| "回到上一层""撤销" | B4 |
| 后面的元素可能"推翻"前面刚做的决定 | B5、B6 |

一句话概括：**当前元素需要和"最近处理过的、还没了结的"元素打交道时，就用栈把这些没了结的东西攒起来。**

### 0.3 单调栈是什么，为什么是 O(n)

单调栈就是：**栈里的元素始终保持单调**（从栈底到栈顶递增或递减）。做法是，新元素进栈之前，先把"破坏单调性"的栈顶一个个弹掉。

你看到 `for` 套 `while`，第一反应肯定是"嵌套循环 = O(n²)"。**这个直觉在这里是错的**，要这样数：

- 每个元素在 for 循环里被 `append` 恰好一次 → 进栈总共 n 次。
- 每个元素一旦被 `pop` 就永远离开栈，不可能被弹第二次 → 出栈总共不超过 n 次。
- 所以 while 的循环体，**在整次运行中**加起来执行不超过 n 次。它不是"每个 i 都跑 n 次"，而是"所有 i 分摊这 n 次"。

总操作数 = n 次进栈 + ≤n 次出栈 = O(n)。这种"单次可能很贵、总账很便宜"的分析叫**均摊分析**，这里每个元素均摊 O(1)。

判断这类嵌套循环，别看嵌套了几层，要看**最内层那句代码总共执行了多少次**。这是本册最重要的一句话。

## B1. 每日温度（Medium）

> 力扣 739 · 单调栈 · CodeTop 华为频度 23（第 2 名）
> 前置：本册「0.3 单调栈为什么是 O(n)」

**一句话**：给你一串每天的温度，对每一天问"还要等几天才会比今天更热"，等不到就填 0。

### 精讲（零基础版）

#### ① 这题要用到的东西

**栈**（前面「零、0.1 栈是什么」讲过）：只能从末尾增删的 list，`append` 放、`pop()` 拿走、`[-1]` 只看一眼。这题里它是一摞"待办便签"，攒着还没等到更热天气的日子。

**单调栈**（前面「零、0.3」讲过）：进栈之前先把"破坏顺序"的栈顶弹掉，所以栈内温度从底到顶一路递减。这题里"今天比栈顶热"就是弹栈信号。

**下标（index）**：元素在列表里的位置编号，**从 0 开始**。`temps[2]` 是第 3 天的温度。

```python
temps = [73, 74, 75]
print(temps[0])   # -> 73
print(temps[2])   # -> 75
```

这题为什么存下标、不存温度？因为答案要的是"隔了几天"，只有两个下标相减才是天数；存温度你算不出距离。

**`enumerate`**：一边遍历，一边把下标也递给你。

```python
for i, t in enumerate([73, 74, 75]):
    print(i, t)
# -> 0 73
# -> 1 74
# -> 2 75
```

等价于 `for i in range(len(x)): t = x[i]`，但少写一行。

**`[0] * n`**：把 0 复制 n 份，得到长度 n 的列表。这题用它一次干两件事：开数组 + 把"等不到更高温度"的答案预置成 0。

```python
print([0] * 4)   # -> [0, 0, 0, 0]
```

**`and` 的短路**：`A and B` 从左往右算，A 为假就**不再算 B**。所以 `while stack and temperatures[stack[-1]] < t` 里，栈空时右边那句根本不会执行——否则空栈取 `stack[-1]` 会报 IndexError。

```python
print(False and 1 / 0)   # -> False  右边没算，所以没报除零错
```

#### ② 大白话：这题到底在干什么

最笨的办法：站在第 i 天，往后一天一天看，看到第一个比今天热的日子就停下，把中间隔了几天记下来。每天都要往后扫，最坏总共 n² 次，n 到十万就跑不完。

笨在哪？重复劳动。温度是 73、71、69 时，你算 71 那天扫过了 69，算 69 那天还得再扫一遍。

聪明的办法：把"还没等到热天"的日子攒成一摞便签。你会发现这摞便签有个规律——**越往上、温度越低**。因为一旦来了更热的天，上面那些更冷的早就被结算掉了。

于是新来一天，只盯最上面那张：比它热就撕掉、写上"等了几天"，撕完再看新的一张；直到最上面那张比今天热，或者桌子空了。最后把自己这张放上去接着等。每张便签只贴一次、撕一次，总共 n 次操作。

#### ③ 拿 `[73,74,75,71,69,72]` 走一遍

| 天数 i | 温度 t | 发生了什么 | 栈 stack（存下标） | answer |
|---|---|---|---|---|
| 0 | 73 | 桌子空，放上 | `[0]` | `[0,0,0,0,0,0]` |
| 1 | 74 | 73<74，撕掉 0，`answer[0]=1` | `[1]` | `[1,0,0,0,0,0]` |
| 2 | 75 | 74<75，撕掉 1，`answer[1]=1` | `[2]` | `[1,1,0,0,0,0]` |
| 3 | 71 | 75>71，不撕，放上 | `[2,3]` | 不变 |
| 4 | 69 | 71>69，不撕，放上 | `[2,3,4]` | 不变 |
| 5 | 72 | 69<72 撕 4 → `answer[4]=1`；71<72 撕 3 → `answer[3]=2`；75>72 停 | `[2,5]` | `[1,1,0,2,1,0]` |

所以答案是 `[1,1,0,2,1,0]`。注意第 5 步：**一次循环里撕了两张**，这就是"一口气结算一批"。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `answer = [0] * n` | 先摆 n 个 0。等不到热天的日子，答案本来就该是 0，所以不用收尾 |
| `stack = []` | 空桌子 |
| `for i, t in enumerate(temperatures)` | 第 i 天，温度 t |
| `while stack and temperatures[stack[-1]] < t` | 桌子没空，**并且**最上面那张比今天冷。先判 `stack` 是为了空栈时不报错 |
| `j = stack.pop()` | 撕掉最上面那张，`j` 就是那天的编号 |
| `answer[j] = i - j` | 它等了 `i - j` 天。写的是 `j` 的位置，不是今天的 |
| `stack.append(i)` | 把自己这张放上去，继续等 |

### 考什么

- 表面考点：对每个元素，找右边第一个比它大的元素，输出两者的位置差。
- 真正考点：**单调栈模板**——用一个栈维护"还没等到更高温度的那些天"。这是"下一个更大元素"这一大家族的母题，后面的下一个更大元素 II（503）、柱状图中最大矩形（84）、接雨水（42）都是它的变体。
- 面试官想听到的关键句：
  - "栈里存的是**下标**不是温度值，因为答案要的是天数差，只有下标相减才是距离。"
  - "栈内温度从栈底到栈顶**严格递减**，所以新来的温度只要比栈顶高，就能一次性结算掉一批。"

### 思路是怎么想出来的

- **暴力**：对每天 i，往后扫 `j = i+1, i+2, ...`，找到第一个 `temperatures[j] > temperatures[i]`，答案就是 `j - i`。最坏 O(n²)：温度一路走低时，每天都得扫到底。n 最大 10^5，10^10 次比较必然超时。
- **关键观察**：暴力里有大量重复劳动。看 `[73,74,75,71,69,72,76,73]`：算 71 那天时扫过了 69、72，算 69 那天又要再扫一遍 72。这些"还没被结算"的天，完全可以一起攒着，等某个更热的日子来了一次性处理。
- 攒的时候有个结构可以利用：如果 i 比 j 早、而且 `temperatures[i] <= temperatures[j]`，那 i 的答案不可能晚于 j 的答案。换句话说，**"还在等"的这些天，温度一定是从早到晚递减的**——越靠后、越靠栈顶，温度越低。
- **于是有**：从左往右扫，每天 i 进栈之前，把栈顶那些"温度比今天低"的天弹出来，它们的答案就是 `i - 那天`；弹完了自己进栈，继续等。

### 代码（Python）

```python
from typing import List   # 力扣已预导入这行，本地跑时要加上

class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        n = len(temperatures)
        answer = [0] * n        # 默认 0，正好就是"等不到更高温度"的答案
        stack = []              # 存下标；栈内对应温度单调递减
        for i, t in enumerate(temperatures):
            while stack and temperatures[stack[-1]] < t:
                j = stack.pop()          # j 这天终于等到了
                answer[j] = i - j        # 距离 = 今天 - 那天
            stack.append(i)
        return answer
```

**逐段讲解**

- **初始化**：`answer = [0] * n` 一箭双雕——既分配了数组，又让"永远等不到更高温度"的天默认填 0，不用额外处理收尾。
- **循环不变量**：每轮 for 结束、i 入栈之后，栈里存的是**下标递增、对应温度严格递减**的一串天。越靠栈顶，天越近、温度越低。
- **灵魂是那三行 while**：`temperatures[stack[-1]] < t` 成立，说明栈顶那天等到了更高的温度，而且**今天就是它等的第一个**更高的温度。为什么能直接写死 `answer[j] = i - j`？因为栈里比 j 更早的天温度都比 j 高，不会先被结算；而 i 是从左往右第一次出现比 j 高的。所以不用比较、不用再判断，直接填。
- 注意是 `<` 不是 `<=`：题目要"更高"，温度相等不算。相等的天会一起留在栈里继续等。

### 复杂度

- 时间 O(n)：每个下标进栈一次、出栈至多一次，while 总体执行次数 ≤ n（见 0.3 的均摊分析）。
- 空间 O(n)：栈最坏装下所有天（温度一路递减时），`answer` 本身也是 O(n)。

### 常见误区（★ 最容易丢分的地方）

1. **栈里存温度值而不是下标**。存值能判断大小，但算不出"几天后"。要么再塞一个下标进元组，要么根本填不了答案。**从第一版就存下标**，温度用 `temperatures[stack[-1]]` 现取。
2. **`<` 写成 `<=`**。`[50,50,50]` 会输出 `[1,1,0]`，正确答案是 `[0,0,0]`——相等的温度不是"更高"。
3. **while 里写 `answer[i] = i - j`**。被结算的是栈顶那天 j，不是今天 i。写成 i 的话，示例 1 的输出第 0 位会是 0 而不是 1，一眼就能看出来。
4. **忘了 `stack.append(i)`，或者把它写进 while 里**。今天也必须进栈，它自己也在等更高的温度。

### 面试追问 / 变体

- 改成"下一个更低温度"：while 条件翻成 `>`，其余不动。
- 改成"左边第一个更高"：从右往左扫；或者扫的时候先弹栈、再取值。
- 改成"下一个更大元素的值"：`answer[j] = t`，就是力扣 496 / 503。
- 环形数组（503）：数组接一遍，用 `i % n` 取下标。

### 自测

- 必测用例：
  - `[73,74,75,71,69,72,76,73]` → `[1,1,4,2,1,1,0,0]`（题面示例）
  - `[30,40,50,60]` → `[1,1,1,0]`（一路升高）
  - `[90,80,70,60]` → `[0,0,0,0]`（一路降低，栈最深）
  - `[50]` → `[0]`（单元素）
  - `[50,50,50]` → `[0,0,0]`（相等不结算）
- 30 秒自检：能不能说出"栈存下标、栈内温度递减、新温度一次性结算栈顶"这三步？

## B2. 有效的括号（Easy）

> 力扣 20 · 栈 · 括号匹配 · CodeTop 华为频度 16（第 3 名）
> 前置：本册「0.1 栈是什么」

**一句话**：给一串只有三种括号的字符串，判断每个右括号是不是都和"最近那个还没闭合的左括号"配上了对。

### 精讲（零基础版）

#### ① 这题要用到的东西

**栈**（前面「零、0.1」讲过）：只能从末尾增删的 list。这题里它是一摞"还没闭合的左括号"，最新那个永远在栈顶。

**字典（dict）**：一堆"键 → 值"的配对，像查字典——给一个字（键），翻到它的解释（值）。

```python
pairs = {')': '(', ']': '[', '}': '{'}
print(pairs[')'])     # -> (
print(')' in pairs)   # -> True    ')' 是键
print('(' in pairs)   # -> False   '(' 只是值，不是键
```

`pairs[ch]` 是"取值"，键不存在会报 KeyError；`ch in pairs` 是"问有没有这个键"，返回 True / False，不会报错。这题用 `in` 一次判断"这是不是右括号"。

**`not stack`**：列表的真假就看空不空——空列表算假，非空算真。所以 `not stack` 就是"栈是不是空的"。

```python
stack = []
print(not stack)     # -> True
stack.append('(')
print(not stack)     # -> False
```

**`or` 的短路**：`A or B` 里 A 为真就不再算 B。`if not stack or stack[-1] != pairs[ch]` 先问"栈空吗"，空了直接判失败，右边取 `stack[-1]` 不会执行；顺序反过来就会在空栈上报错。

#### ② 大白话：这题到底在干什么

最笨的办法：数一数三种括号各几个，一样多就算合法。可惜 `"([)]"` 三种各两个，数量全对，它却不合法——顺序也得对，数量法直接出局。

笨在哪？它只看"有几个"，完全不管"谁挨着谁"。

聪明的办法：从左往右读，一个右括号出现时，它要闭合的一定是"前面最后一个还没闭合的左括号"。而"最后一个还没闭合的"，正好在栈顶。

于是：遇到左括号就压栈；遇到右括号，先看栈空不空（空了说明右括号多了），再看栈顶类型对不对（不对说明类型或顺序错了），两个都过关就弹出栈顶。扫完之后栈必须空，否则还有左括号没闭合。

#### ③ 拿 `"([])"` 走一遍

| 读到 | 栈 stack | 发生了什么 |
|---|---|---|
| `(` | `['(']` | 左括号，压栈 |
| `[` | `['(', '[']` | 左括号，压栈 |
| `]` | `['(']` | 右括号，栈顶 `[` 正好等于 `pairs[']']`，弹出 |
| `)` | `[]` | 右括号，栈顶 `(` 正好等于 `pairs[')']`，弹出 |
| 扫完 | `[]` | 栈空 → 返回 True |

换成 `"([)]"`：前三个字符同上，读到第 4 个字符 `)` 时栈顶是 `[`，而 `pairs[')']` 是 `(`，两者不等 → 返回 False。所以 `"([])"` 得 True，`"([)]"` 得 False。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `pairs = {')': '(', ']': '[', '}': '{'}` | 造一张对照表：右括号 → 它需要的左括号 |
| `for ch in s` | 一个字符一个字符地读 |
| `if ch in pairs` | 它在表里 → 是右括号 |
| `if not stack or stack[-1] != pairs[ch]` | 栈空（右括号多了）或栈顶对不上（类型 / 顺序错），都直接 False |
| `stack.pop()` | 配对成功，把这个左括号消耗掉 |
| `else: stack.append(ch)` | 是左括号，压栈等它自己的右括号 |
| `return not stack` | 扫完栈空才算合法；`"("` 这种剩东西的必须 False |

### 考什么

- 表面考点：括号是否合法。
- 真正考点：**栈处理配对/嵌套的标准动作**——左半边入栈，右半边来的时候跟栈顶对账。
- 面试官想听到的关键句："右括号只能和**最近一个还没闭合**的左括号配对，'最近'两个字就是栈。"

### 思路是怎么想出来的

- **暴力**：先数三种括号的数量相等吗？不行。`"([)]"` 三种括号各两个，数量全对，但它是非法的——顺序也要对。所以数量法直接出局。
- **关键观察**：从左往右读，一个右括号出现时，它要闭合的一定是"前面最后一个还没闭合的左括号"。而"最后一个还没闭合的"正好在栈顶。
- **于是有**：遇左括号入栈；遇右括号，若栈空（没有可闭合的）或栈顶不等于它需要的类型，直接 false；否则弹出栈顶。扫完后栈必须为空，否则有左括号没闭合。

### 代码（Python）

```python
class Solution:
    def isValid(self, s: str) -> bool:
        pairs = {')': '(', ']': '[', '}': '{'}   # 右括号 -> 它需要的左括号
        stack = []
        for ch in s:
            if ch in pairs:                       # 是右括号
                if not stack or stack[-1] != pairs[ch]:
                    return False                  # 没得配，或配错类型
                stack.pop()                       # 配对成功，消耗掉
            else:                                 # 是左括号
                stack.append(ch)
        return not stack                          # 还有剩的 = 有没闭合的
```

**逐段讲解**

- 字典把"右括号 → 左括号"做成映射，好处是判断方向只需一次 `ch in pairs`，不用先写 `if ch in "([{"`、再在 else 里反查。
- `not stack or stack[-1] != pairs[ch]` 是这题的灵魂：两个失败条件合成一行。栈空 = 右括号多了；栈顶不匹配 = 类型错或顺序错（比如 `"([)]"` 里 `)` 遇到栈顶 `[`）。
- 最后 `return not stack` 而不是 `return True`：`"("` 这种扫完没报错、但栈里还剩东西的，必须 false。

### 复杂度

- 时间 O(n)：每个字符进栈或出栈至多一次。
- 空间 O(n)：最坏情况全是左括号，栈装 n 个。

### 常见误区

1. **只比较栈顶、不判空**。输入 `")"` 会让 `stack[-1]` 抛 IndexError。必须写成 `not stack or ...`，短路顺序不能反。
2. **最后忘了判空**。`"("`、`"([]"` 会错误返回 true。
3. **遇到右括号先 `pop` 再比较**。pop 完栈顶就没了，比较对象变成上一个元素。先比、后 pop。
4. **想用"左括号计数"代替栈**。计数只知道数量，不知道类型和顺序，`"([)]"` 会被误判成 true。

### 面试追问 / 变体

- 只有一种括号：可以用计数器代替栈。
- 要求"最少加几个括号才合法"（力扣 921 / 1541）：把 `return False` 改成累加不匹配次数。
- 字符串里混了字母：字母直接跳过。
- 最长有效括号（32）：栈里要存"最后一个没配上的位置"，难度跳一档。

### 自测

- 必测：`"()"` → true、`"()[]{}"` → true、`"(]"` → false、`"([])"` → true、`"([)]"` → false
- 边界：`"("` → false、`")"` → false、`"{[()]}"` → true
- 30 秒自检：左括号入栈、右括号对栈顶、扫完栈空。

## B3. 基本计算器 II（Medium）

> 力扣 227 · 栈 + 符号 · 表达式求值 · CodeTop 华为频度 12（第 7 名）
> 前置：B2（先建立 push/pop 的手感）

**一句话**：给一个只有 `+ - * /` 和空格、没有括号的表达式字符串，按先乘除后加减算出结果。

### 精讲（零基础版）

#### ① 这题要用到的东西

**栈**（前面 B2 讲过）：只能从末尾增删的 list。这题里它存"已经确定下来的加项"。

**`str.isdigit()` 与 `int(ch)`**：`isdigit()` 问"这个字符是数字吗"，`int(ch)` 把单个数字字符变成整数。

```python
print('7'.isdigit())   # -> True
print('+'.isdigit())   # -> False
print(int('7'))        # -> 7
```

**攒多位数 `num = num * 10 + int(ch)`**：字符是一位一位来的，`"12"` 先来 `'1'` 再来 `'2'`。每来一位，把手里已有的数乘 10 往左挪一格，再加上新的一位。

```python
num = 0
for ch in "12":
    num = num * 10 + int(ch)
    print(ch, num)
# -> 1 1
# -> 2 12
```

**`int(a / b)` 和 `//` 不是一回事**：`//` 是**向下取整**（往更小的方向走），`int(a / b)` 是**向零截断**（小数部分直接扔掉）。正数上两者一样，负数上差 1。

```python
print(-3 // 2)       # -> -2   向下取整
print(int(-3 / 2))   # -> -1   向零截断
```

题目要的是向零截断（`-3/2` 得 -1），所以必须写 `int(a / b)`，不能图省事写 `//`。

**`sum(list)`**：把列表里的数全加起来。

```python
print(sum([3, -1, 4]))   # -> 6
```

**哨兵**：在数据末尾塞一个"一定会触发结算"的假字符。`s + '+'` 就是把 `+` 接在末尾，让最后一个数字后面也有运算符。

```python
print("3+2" + "+")   # -> 3+2+
```

**`continue`**：这一轮剩下的代码不跑了，直接进下一轮。空格就靠它跳过。

#### ② 大白话：这题到底在干什么

最笨的办法：先扫一遍找出所有乘除、算完把那段子串替换掉，再从左到右做加减。要反复扫字符串、还要处理下标位移，代码又脏又容易错。

笨在哪？它把"优先级"当成两趟活干，来回搬运字符串。

聪明的办法：换个角度——一个数字的最终命运，由**它后面那个运算符**决定。后面是 `+` / `-`，它就是一个独立的加项，符号已经确定，可以立刻压进栈；后面是 `*` / `/`，它得和左边刚算出来的结果合并。

所以真正要等的不是"优先级算完"，而是"下一个运算符出现"。于是：一个栈存已确定的加项，`sign` 记住**上一个**运算符，`num` 攒当前数字。碰到运算符就按 `sign` 结算 `num`，然后把 `sign` 换成当前这个。扫完把栈里全加起来。

#### ③ 拿 `"3+2*2"` 走一遍

| 读到 | sign | num | 栈 stack（处理完之后） | 发生了什么 |
|---|---|---|---|---|
| `3` | `+` | 3 | `[]` | 攒数字 |
| `+` | `+` | 0 | `[3]` | 用上一个 sign（`+`）结算：压 3；sign 记成 `+`，num 清零 |
| `2` | `+` | 2 | `[3]` | 攒数字 |
| `*` | `*` | 0 | `[3, 2]` | sign 还是 `+`，压 2；sign 记成 `*` |
| `2` | `*` | 2 | `[3, 2]` | 攒数字 |
| `+`（末尾哨兵） | `+` | 0 | `[3, 4]` | sign 是 `*`：弹出 2、乘 2 得 4 压回 |

最后 `sum([3, 4])` = 7，所以答案是 7。注意第 4 步压进去的 2，到第 6 步才被乘掉——**先压、后改**，这就是延迟结算。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `stack = []` | 空栈，用来装已确定的加项 |
| `num = 0` | 正在攒的数字，从 0 开始攒 |
| `sign = '+'` | 记住上一个运算符；开头没有上一个，就当加号 |
| `for ch in s + '+'` | 末尾补一个 `+`，保证最后一个数也被结算 |
| `if ch == ' ': continue` | 空格直接跳过 |
| `if ch.isdigit(): num = num * 10 + int(ch)` | 是数字就攒进 num，多位数靠这句 |
| `if sign == '+': stack.append(num)` | 上一个运算符是加号，这个数原样进栈 |
| `elif sign == '-': stack.append(-num)` | 是减号，存成负数，减法就变成了加法 |
| `elif sign == '*': stack.append(stack.pop() * num)` | 是乘号，弹出栈顶乘上 num 再压回 |
| `else: stack.append(int(stack.pop() / num))` | 是除号，向零截断后压回 |
| `sign = ch` / `num = 0` | 结算完了才更新 sign，然后清零 num 准备下一个数 |
| `return sum(stack)` | 所有加项求和就是答案 |

### 考什么

- 表面考点：字符串解析 + 四则运算优先级。
- 真正考点：**延迟结算**。读到数字时先别急着加，因为它后面可能跟一个 `*` 或 `/` 把它改掉。把"还不确定最终值"的数存进栈，确定一个结算一个。
- 面试官想听到的关键句："**遇到运算符，才结算上一个数字。**乘法直接改栈顶，加减法往栈里压带符号的数，最后全部求和。"

### 思路是怎么想出来的

- **暴力**：先扫一遍找所有乘除、算完把子串替换掉、再从左到右加减。要反复扫描字符串，还得处理下标位移，代码脏且容易错。
- **关键观察**：优先级只有两级。一个数字的最终命运由**它后面那个运算符**决定：后面是 `+` / `-`，它就是一个独立加项，符号确定、可以立刻压栈；后面是 `*` / `/`，它要和栈顶合并，而合并结果还可能被再后面的乘除继续合并。
- **于是有**：一个栈存"已经确定的加项"（带正负号），一个 `sign` 记住**上一个**运算符，一个 `num` 攒当前数字。碰到运算符就把 `num` 按 `sign` 处理：加减 → 压 `±num`；乘除 → 弹出栈顶和 `num` 运算再压回。扫完 `sum(stack)`。

### 代码（Python）

```python
class Solution:
    def calculate(self, s: str) -> int:
        stack = []          # 已经确定的加项（带符号）
        num = 0             # 正在攒的数字，可能是多位数
        sign = '+'          # 上一个运算符，开头当作加号
        for ch in s + '+':  # 末尾补一个运算符，保证最后一个数也被结算
            if ch == ' ':
                continue
            if ch.isdigit():
                num = num * 10 + int(ch)      # 多位数：逐位累加
            else:                             # ch 是 + - * /
                if sign == '+':
                    stack.append(num)
                elif sign == '-':
                    stack.append(-num)
                elif sign == '*':
                    stack.append(stack.pop() * num)
                else:                         # '/'
                    stack.append(int(stack.pop() / num))   # 向零取整
                sign = ch                     # 记住这个运算符，等下一个数
                num = 0
        return sum(stack)
```

**逐段讲解**

- `s + '+'` 这个尾巴是整段代码最省事的地方。如果不补，最后一个数字后面没有运算符，永远触发不了结算分支，只能在循环外再抄一遍结算逻辑。补一个 `+`，最后那个数就被正常当加项压栈了（`sign` 是 `'+'` 时就是 `append(num)`，不改变结果）。
- `num = num * 10 + int(ch)` 就是"处理多位数"的全部秘密。读到 `1`、`2`、`3`，num 依次是 1、12、123。不能靠 `split`，因为数字和符号可能贴着，空格也可能没有。
- `sign` 是**上一轮看到的**运算符，不是当前字符。结算用的是 `sign`，处理完才 `sign = ch`。这个先后顺序错了，整题全错。
- 加法压 `num`、减法压 `-num`：把减法统一成加法，最后只要 `sum` 一次，不用管括号也不用管优先级。
- 除法那行 `int(a / b)` 是向零取整，这是 Python 的一个坑，见下面误区 1。

### 复杂度

- 时间 O(n)：每个字符扫一次，每个数进出栈常数次。
- 空间 O(n)：栈最多存下所有加减项。

### 常见误区（★ 最容易丢分的地方）

1. **用 `//` 做除法**。`"1-3/2"` 里栈顶是 -3，`-3 // 2 == -2`，最后得到 -1；而"整数除法仅保留整数部分"是**向零截断**，`-3/2` 应为 -1，正确答案是 0。凡是可能出负数的表达式，`//` 都会偏小 1。
2. **先 `sign = ch` 再结算**。这样结算用的是**当前**运算符而不是上一个：`"3+2*2"` 里读到 `*` 时 sign 已经变成 `*`，于是把栈顶的 3 和 2 先乘成 6，再加 2 得 8（正确答案 7）。正确顺序是**先结算、后更新 sign**。
3. **只在 `ch in '+-*/'` 时进分支，不处理结尾**。`"3+2"` 扫完循环就结束了，最后的 2 没被结算，返回 3。
4. **`num` 结算后忘了清零**。下一段数字会拼在上一个数后面（`2` 变成 `23` 之类）。
5. **想用 `eval`**。题面明确禁止，面试官也会直接判不合格。

### 面试追问 / 变体

- 加上括号（力扣 224 基本计算器）：括号相当于"把里面的值算完再当操作数"，需要再开一个栈存"括号外算到哪了"，或者写递归下降。
- 支持一元负号、负数：在 `sign` 为 `'-'` 且 `num` 为 0 时特殊处理。
- 加幂运算 `^`：优先级从两级变三级，代码里要按优先级比较。
- 表达式里有变量：变量名映射成数值，再走同一套逻辑。

### 自测

- 必测：`"3+2*2"` → 7、`" 3/2 "` → 1、`" 3+5 / 2 "` → 5
- 边界：`"1-3/2"` → 0（负数截断）、`"14-3/2"` → 13、`"0"` → 0、`" 3/2  "` → 1（多个尾空格）
- 30 秒自检：遇到运算符才结算、乘法改栈顶、最后 sum。

## B4. 字符串解码（Medium）

> 力扣 394 · 栈 + 字符串 · 嵌套结构 · CodeTop 华为频度 7（第 16 名）
> 前置：B2（栈的配对直觉）

**一句话**：把 `k[内容]` 这种"内容重复 k 次"的编码解开，编码可以嵌套。

### 精讲（零基础版）

#### ① 这题要用到的东西

**栈**（前面 B2 讲过）：只能从末尾增删的 list。这题里它存"进入这层括号之前，外面长什么样"。

**元组 `(a, b)` 与解包**：元组是把几个值打包成一个整体，打包后不能改，只能整体存、整体取。`prev, k = stack.pop()` 叫解包——把包里两个值分别倒进两个变量。

```python
pair = ('a', 2)
prev, k = pair
print(prev)   # -> a
print(k)      # -> 2
```

这题为什么存元组、不开两个栈？因为"外面的字符串"和"这层的倍数"必须一起存、一起取，缺一个就还原不了。

**`'x' * n` 字符串重复**：把字符串重复 n 遍，n 为 0 时得到空串。

```python
print('c' * 3)          # -> ccc
print('ab' + 'ccc')     # -> abccc
print(repr('' * 5))     # -> ''
```

**`cur += ch`**：等价于 `cur = cur + ch`，把新字符接在末尾。

```python
cur = ''
cur += 'a'
cur += 'c'
print(cur)   # -> ac
```

**嵌套**：编码里面还能套编码，`3[a2[c]]` 是两层。处理嵌套的通用套路是"进一层存一次现场、出一层恢复一次现场"——存档和读档必须成对，正好是栈的后进先出。题目保证括号合法，所以 `[` 和 `]` 一样多，压栈和弹栈次数相等，扫完栈一定是空的。

#### ② 大白话：这题到底在干什么

最笨的办法：反复找最内层的一对 `[]`，把它展开，字符串变短，再找下一对，直到没有括号。每轮都要重新扫描定位，嵌套一深就容易写乱。

笨在哪？**它每次都从头找**，前面已经确认过的位置全白扫了。

聪明的办法：从左往右只读一遍。读到 `[` 就是"我要进下一层了"，进之前先把外面的现场存起来——外面已经拼好的字符串、这一层的重复倍数，两个都得存；然后清空，从零开始拼里层。读到 `]` 就是"这层解完了，回上一层"：把存的那份取出来，让这层的结果重复 k 次，接在外面前缀后面。普通字符和数字就老老实实往当前层里加。

#### ③ 拿 `"2[ab]"` 走一遍

| 读到 | cur | num | 栈 stack（存 `(prev, k)`） | 发生了什么 |
|---|---|---|---|---|
| `2` | `''` | 2 | `[]` | 攒倍数 |
| `[` | `''` | 0 | `[('', 2)]` | 存档 `('', 2)`，清空 cur 和 num，开新层 |
| `a` | `'a'` | 0 | `[('', 2)]` | 普通字符，拼进当前层 |
| `b` | `'ab'` | 0 | `[('', 2)]` | 普通字符，拼进当前层 |
| `]` | `'abab'` | 0 | `[]` | 取档：`cur = '' + 'ab' * 2` |

所以答案是 `"abab"`。再看嵌套的 `"2[2[b]]"`：第二个 `[` 处栈里会有两层，第一个 `]` 先拼出 `"bb"`，外层再乘 2 得 `"bbbb"`。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `stack = []` | 空栈，用来存每一层的现场 |
| `cur = ''` | 当前这一层已经拼好的字符串，从空串开始 |
| `num = 0` | 正在攒的倍数 |
| `if ch.isdigit(): num = num * 10 + int(ch)` | 数字就攒倍数，多位数靠这句 |
| `elif ch == '[':` | 要进下一层了 |
| `stack.append((cur, num))` | 存档：外面拼到哪了、这层要重复几次 |
| `cur = ''` / `num = 0` | 开新的一层，一切从零开始 |
| `elif ch == ']':` | 这层解完了，回上一层 |
| `prev, k = stack.pop()` | 读档，把存的两个值取出来 |
| `cur = prev + cur * k` | 这层结果重复 k 次，接在外面前缀后面。顺序不能反 |
| `else: cur += ch` | 普通字符，直接拼进当前层 |
| `return cur` | 扫完没有未闭合的层，cur 就是答案 |

### 考什么

- 表面考点：字符串解析 + 展开。
- 真正考点：**嵌套结构用栈**。`[` 是"进入下一层"，`]` 是"回到上一层"，栈保存的就是"进这一层之前，外面算到哪了"。
- 面试官想听到的关键句："`[` 的时候把**外面的字符串和倍数**压栈，`]` 的时候弹出来接上。"

### 思路是怎么想出来的

- **暴力**：反复找最内层的一对 `[]`，展开、字符串变短、再找下一对。每轮都要重新扫描定位，逻辑容易写错，而且嵌套层数一多就慢。
- **关键观察**：嵌套意味着"上下文"必须保存。读到 `3[a2[c]]` 的第二个 `[` 时，外层状态是：已拼好的 `"a"`、倍数 3。这两个东西必须先存起来，等里面解完再接着用。**"先存起来、解完再取"——这就是栈。**
- **于是有**：一个栈存 `(进入括号前的字符串, 倍数)` 二元组；`cur` 是"当前这层已拼好的字符串"；`num` 攒倍数。遇 `[` 压栈并清空 cur / num，遇 `]` 弹出并 `cur = prev + cur * k`。

拿 `"3[a2[c]]"` 手动走一遍，看清楚栈到底在存什么：

| 读到 | 动作 | cur | num | stack（元组是 `(prev, k)`） |
| --- | --- | --- | --- | --- |
| `3` | 攒倍数 | `''` | 3 | `[]` |
| `[` | 压栈、开新层 | `''` | 0 | `[('', 3)]` |
| `a` | 拼进当前层 | `'a'` | 0 | `[('', 3)]` |
| `2` | 攒倍数 | `'a'` | 2 | `[('', 3)]` |
| `[` | 压栈、开新层 | `''` | 0 | `[('', 3), ('a', 2)]` |
| `c` | 拼进当前层 | `'c'` | 0 | 同上 |
| `]` | 出栈、拼回外层 | `'a' + 'c' * 2 = 'acc'` | 0 | `[('', 3)]` |
| `]` | 出栈、拼回外层 | `'' + 'acc' * 3` | 0 | `[]` |

最后 `cur = "accaccacc"`。这张表建议你在纸上自己画一遍——只要 `]` 那一步的 `prev + cur * k` 填对，这题就通了。

### 代码（Python）

```python
class Solution:
    def decodeString(self, s: str) -> str:
        stack = []      # 存 (进入这层括号前的字符串, 这层的倍数)
        cur = ''        # 当前层已经解出来的字符串
        num = 0         # 正在攒的倍数，可能是多位数
        for ch in s:
            if ch.isdigit():
                num = num * 10 + int(ch)
            elif ch == '[':
                stack.append((cur, num))   # 存档：外面拼到哪了、要重复几次
                cur = ''                   # 开新的一层
                num = 0
            elif ch == ']':
                prev, k = stack.pop()      # 回到上一层
                cur = prev + cur * k       # 这一层的结果重复 k 次，接在外面前缀后面
            else:
                cur += ch
        return cur
```

**逐段讲解**

- 栈里存的**不是**字符串、也**不是**数字，而是**一对** `(外面的 cur, 这层的 k)`。因为 `]` 的时候两个都要用。这是这题最容易漏的地方——只存字符串，出栈时不知道重复几次。
- `cur` 的含义在 `[` 处发生切换：从"外层已拼好的"变成"内层从空开始"。压栈保存的正是它的旧含义。
- `cur = prev + cur * k`：先重复、再接前缀。顺序不能反，`prev` 是外层已经确定的部分，必须排在前面。
- `num` 用 `* 10 + int(ch)` 攒多位数，`"10[a]"` 才不会只重复 1 次。
- 没有 `[` 的普通字符直接 `cur += ch`，所以 `"abc3[cd]xyz"` 里的 `abc`、`xyz` 自然被留在最外层。

### 复杂度

- 时间：每个字符的进出栈都是 O(1)，共 n 次；但字符串拼接 / 重复 `cur * k` 本身要复制字符，成本与输出长度和嵌套层数相关。对题面规模（输出 ≤ 10^5）完全够用。
- 空间 O(输出长度 + 嵌套深度)：栈的深度就是括号嵌套层数，每层存一个字符串。

### 常见误区

1. **栈里只存倍数或只存字符串**。出栈时缺一半信息，`]` 处无法还原。
2. **`[` 时忘了把 `num` 清零**。`"3[a]2[bc]"` 里第二个倍数会变成 `3*10+2 = 32`，结果完全错。
3. **`]` 时写成 `cur = cur * k + prev`**。前后缀接反，示例 1 会输出 `"bcbcaaa"`。
4. **用递归写但没处理多位倍数**。递归思路没错，但 `num` 同样要 `* 10 + int(ch)` 累积。
5. **`ch.isdigit()` 对全角数字也返回 True**。本题只有 ASCII，但写成 `'0' <= ch <= '9'` 更保险。
6. **想用 `split('[')` 或正则一把梭**。`"3[a2[c]]"` 切出来是 `['3', 'a2', 'c]]']`，括号的配对关系在切分那一刻就丢了。嵌套结构必须靠栈一层层还原。

### 面试追问 / 变体

- 倍数出现在字符后面（`"a[b]"`）：题面排除了，真实面试可能加，要区分"数字倍数"和"普通字符"。
- 支持 `k = 0`：`cur * 0` 天然返回空串，代码不用改。
- 反方向（力扣 443 字符串压缩）：那是"编码"，用两个下标一读一写。
- 输出可能超长：需要边解边判断长度，或者改成返回生成器。
- 不真展开，只问"解压后第 k 个字符是什么"：先算出每一层的长度再按区间定位，思路从"拼接"变成"分段计数"。

### 自测

- 必测：`"3[a]2[bc]"` → `"aaabcbc"`、`"3[a2[c]]"` → `"accaccacc"`、`"2[abc]3[cd]ef"` → `"abcabccdcdcdef"`、`"abc3[cd]xyz"` → `"abccdcdcdxyz"`
- 边界：`"10[a]"` → 10 个 a、`"2[2[b]]"` → `"bbbb"`
- 30 秒自检：`[` 存 (cur, num)、`]` 取出来拼、普通字符直接加。

## B5. 去除重复字母（Medium，本册最难）

> 力扣 316 · 单调栈 + 贪心 + 计数（与 1081 相同） · CodeTop 华为频度 9（第 10 名）
> 前置：B1（单调栈的不变量）

**一句话**：把字符串里重复的字母各留一个，保持原来的相对顺序，并让结果的字典序尽可能小。

### 精讲（零基础版）

#### ① 这题要用到的东西

**栈**（前面 B1 讲过）：只能从末尾增删的 list。这题里栈内字符从底到顶**递增**。

**集合（set）**：只记"有哪些东西"，不管顺序、不许重复。查"在不在"是 O(1)，比在列表里逐个找快。

```python
seen = set()
for ch in "aba":
    if ch in seen:
        print(ch, 'already')   # -> a already
    seen.add(ch)
```

**字典推导式 `{ch: i for i, ch in enumerate(s)}`**：一边遍历一边建字典。同一个字符出现两次时，后一次会**覆盖**前一次，所以留下的正好是"最后一次出现的下标"。

```python
print({ch: i for i, ch in enumerate("aba")})   # -> {'a': 2, 'b': 1}
```

**`''.join(list)`**：把字符列表粘成一个字符串，`''` 是分隔符（空串表示直接拼）。

```python
print(''.join(['a', 'c', 'd']))   # -> acd
```

**字典序**：就是查字典的顺序，逐位比字符大小，`'a' < 'c'` 为真。

```python
print('a' < 'c')                    # -> True
print(''.join(sorted("cba")))       # -> abc   排序会打乱原顺序
```

注意第二行：排序确实能得到更小的字典序，但原顺序被打乱了，这题不允许。所以只能"边扫边调整"，不能事后重排。

**贪心**：每一步都做"当下看起来最好"的选择。这题的贪心带一点"后悔权"：栈顶那个字符如果后面还会出现，现在让位给更小的字符，不算亏。

#### ② 大白话：这题到底在干什么

先把三个要求拆开：每个字母只留一个（去重）、相对顺序不能变（保序）、结果字典序尽量小。

最笨的办法：把所有"去重子序列"列出来，挑最小的那个。数量是指数级的，写不出来也跑不动。

笨在哪？它把"选哪个"当成一次性决定，没注意到有些决定**以后可以反悔**。

聪明的办法：从左往右扫，一边扫一边维护结果。扫到 `ch` 时回头看栈顶：如果栈顶比 `ch` 大（说明 `ch` 放前面字典序更小），而且栈顶这个字符**后面还会再出现**（说明现在扔掉它不会永久丢字符），那就把栈顶弹掉，让 `ch` 往前挤。弹到不能再弹，再把 `ch` 压进去。

"后面还会不会出现"要靠预计算：先扫一遍记下每个字符最后一次出现的下标 `last`，扫第二遍时用 `last[栈顶] > i` 判断。

#### ③ 拿 `"bcabc"` 走一遍

`last` 是 `{'b': 3, 'c': 4, 'a': 2}`。

| i | 扫到 ch | 发生了什么 | 栈 stack |
|---|---|---|---|
| 0 | `b` | 栈空，直接放上 | `['b']` |
| 1 | `c` | 栈顶 `b` 比 `c` 小，不弹，放上 | `['b', 'c']` |
| 2 | `a` | 栈顶 `c` > `a` 且 `last['c']=4 > 2`，弹；栈顶 `b` > `a` 且 `last['b']=3 > 2`，再弹；栈空，放上 `a` | `['a']` |
| 3 | `b` | 栈顶 `a` 比 `b` 小，不弹，放上 | `['a', 'b']` |
| 4 | `c` | 栈顶 `b` 比 `c` 小，不弹，放上 | `['a', 'b', 'c']` |

所以答案是 `"abc"`。第 2 步是关键：一次弹了两个，因为它们后面都还会出现，现在让位不亏。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `last = {ch: i for i, ch in enumerate(s)}` | 预计算：每个字符最后一次出现在哪 |
| `stack = []` | 结果，同时也是栈 |
| `in_stack = set()` | 已经在结果里的字符，用来防重复 |
| `if ch in in_stack: continue` | 这个字符已经在结果里了，这个位置直接跳过 |
| `while stack and stack[-1] > ch and last[stack[-1]] > i` | 三个条件：栈非空、栈顶更大、栈顶后面还会出现。缺一个都不能弹 |
| `in_stack.remove(stack.pop())` | 弹掉栈顶，同时从集合里删掉它 |
| `stack.append(ch)` / `in_stack.add(ch)` | 压入当前字符，两处状态同步更新 |
| `return ''.join(stack)` | 栈里就是答案，粘成字符串 |

### 考什么

- 表面考点：三个约束同时满足——去重、保序、字典序最小。
- 真正考点：**带"后悔"的单调栈**。栈顶字符如果比当前字符大、而且它后面还会出现，就把它弹掉，让更小的字符上位。这是贪心 + 单调栈的组合。
- 面试官想听到的关键句："能弹的条件有两个：**栈顶比当前大**（字典序能更小），**且栈顶后面还会出现**（弹了不丢字符）。缺一个都不能弹。"

### 思路是怎么想出来的

先把三个条件拆开，别混在一起想：

- **去重**：每个字母只留一个 → 需要一个集合记录"哪些字符已经在结果里"。
- **保序**：不能打乱相对顺序 → 从左往右扫，结果只能是原串的子序列。
- **字典序最小**：越靠前的字符越小越好 → 遇到更小的字符，就想让它往前挤。

- **暴力**：枚举所有"去重子序列"取最小。指数级，不可行。
- **关键观察**：一个字符能不能被扔掉，取决于**它后面还会不会出现**。后面还有，现在这个位置就可以让给更小的字符，反正它以后还能再进来；后面没有了，它必须留着，否则这个字母就永久丢了。
- **于是有**：扫到 `ch` 时，只要"栈顶字符 > ch"且"栈顶字符后面还会出现"，就弹掉栈顶（它以后还能再进栈）。弹到不能弹为止，再压入 `ch`。判断"后面还会不会出现"，靠一个 `last` 数组记下每个字符**最后一次出现的下标**。

### 代码（Python）

```python
class Solution:
    def removeDuplicateLetters(self, s: str) -> str:
        last = {ch: i for i, ch in enumerate(s)}   # last 数组：每个字符最后出现的位置
        stack = []        # 结果，同时也是单调递增的栈
        in_stack = set()  # 已经在栈里的字符，用来防重复
        for i, ch in enumerate(s):
            if ch in in_stack:      # 已经在结果里了，这个位置直接跳过
                continue
            # 栈顶更大、且它后面还会再出现 -> 弹掉，让 ch 上位
            while stack and stack[-1] > ch and last[stack[-1]] > i:
                in_stack.remove(stack.pop())
            stack.append(ch)
            in_stack.add(ch)
        return ''.join(stack)
```

**逐段讲解**

- **`last` 是整题的"许可证"**：`last[stack[-1]] > i` 的意思是"栈顶字符在 i 之后还会再出现一次"，所以现在弹掉它不会丢字符。如果 `last[stack[-1]] == i`，说明今天就是它最后一次露面的位置，弹了就永远没了，不能弹。字符集只有 26 个小写字母，所以这里用 dict 实现；换成 ASCII 全集就用长度 128 的数组，`last[ord(ch)]`。
- **为什么还要 `in_stack`**：栈最多 26 个元素，每次线性扫栈也能查重，但集合是 O(1)、意图更清楚。关键是它必须**和栈同步维护**——弹栈时要一起 `remove`，入栈时要一起 `add`。
- **`if ch in in_stack: continue` 必须放在 while 之前**。已经在结果里的字符不需要再处理，否则要么重复、要么把栈顺序搅乱。
- **循环不变量**：每轮结束后，栈里存的是"已扫描前缀的一个子序列，无重复，且在当前前缀下字典序最小"的结果。
- **灵魂是 while 里的两个条件同时成立**。`stack[-1] > ch` 负责"字典序能更小"，`last[stack[-1]] > i` 负责"弹了不丢字符"。这是全题唯一需要理解透的一行。

### 复杂度

- 时间 O(n)：每个字符进栈一次、出栈至多一次，while 总执行次数 ≤ n（同 0.3 的均摊分析）。
- 空间 O(1)（相对字符集）：栈、集合、`last` 都最多 26 个元素。严格写是 O(Σ)，Σ 为字符集大小。

### 常见误区（★ 最容易丢分的地方）

1. **只判"栈顶比当前大"就弹**。`"cba"` 会一路弹光，最后只剩 `"a"`；正确答案是 `"cba"`——三个字符各出现一次，弹掉就永久丢失。必须加 `last[...] > i`。
2. **弹栈后忘了 `in_stack.remove`**。`"cbacdcbc"` 会输出 `"ad"`（c、b 被误判为"已在结果里"而跳过），正确答案是 `"acdb"`。
3. **先 `append` 再 `while`**。当前字符已经进栈，while 会把它自己当栈顶参与比较，`"bcabc"` 直接输出 `"bca"`。顺序必须是**先弹、后压**。
4. **在 while 里现查"后面还有没有"**，比如 `s.find(stack[-1], i + 1) != -1`。每次 O(n)，最坏 O(n²)，n = 10^4 会明显变慢，面试官会追问。必须**预计算** `last`。
5. **以为答案是"所有字符排序去重"**。`"cbacdcbc"` 排完是 `"abcd"`，正确答案是 `"acdb"`——保序约束下不能重排。

### 面试追问 / 变体

- 力扣 1081：完全同题，换了层壳。
- 要求"字典序最大"：while 条件里的 `>` 改成 `<`。
- 字符集扩到 ASCII 全集：`last` 用长度 128 的数组，`in_stack` 用 bool 数组。
- "移掉 K 位数字使字典序最小"（力扣 402）：同一套单调栈，但弹的次数受 k 限制。

### 自测

- 必测：`"bcabc"` → `"abc"`、`"cbacdcbc"` → `"acdb"`
- 边界：`"a"` → `"a"`、`"aaaa"` → `"a"`、`"abacb"` → `"abc"`、`"cba"` → `"cba"`（保序，不能排成 `"abc"`）
- 30 秒自检：三个条件、两个弹栈条件、一个 `last` 数组。

## B6. 小行星碰撞（Medium）

> 力扣 735 · 栈模拟（不在华为 Top20，但栈模拟类是手撕常客）
> 前置：B2（push/pop 手感）

**一句话**：一排小行星，正数往右飞、负数往左飞，撞上了小的碎、一样大一起碎，问最后剩谁。

### 精讲（零基础版）

#### ① 这题要用到的东西

**栈**（前面 B2 讲过）：只能从末尾增删的 list。这题里它存"还活着的小行星"。

**布尔标志 `alive`**：一个只装 True / False 的变量，用来记"当前这颗还在不在"。把它放进 while 条件里，一旦变成 False，循环立刻停。

```python
alive = True
alive = False
print(alive)   # -> False
```

**取相反数 `-a`**：`a` 是负数时，`-a` 就是它的**大小**。

```python
a = -5
print(-a)   # -> 5
```

所以 `stack[-1] < -a` 读作"栈顶那颗比当前这颗小"。

**多条件 `and`**：从左往右算，任一条件为假就整体为假，后面的不再算。`while alive and a < 0 and stack and stack[-1] > 0` 四个条件依次是：还活着、往左飞、栈里有东西、栈顶往右飞。`alive` 放最前面是有意的：当前这颗一旦碎了，后面三个条件根本不用再算，循环立刻停。

#### ② 大白话：这题到底在干什么

最笨的办法：每一轮扫一遍数组，找出所有"正数在前、负数在后"的相邻对，让它们对撞，撞完再来一轮，直到一轮下来没人撞为止。一轮 O(n)，最多 n 轮，O(n²)，实现还啰嗦。

笨在哪？**撞一次就要重扫全数组**，而其实只有被撞掉的那个位置附近会变。

聪明的办法：先想清楚谁会撞。同向的两颗永远追不上；`[-1, 2]` 这种"左负右正"在互相远离，也永远撞不上。所以唯一会撞的组合是"**左边是正数、右边是负数**"。

从左往右扫的时候，左边的都已经进了栈，所以当前这颗如果往左飞，它只可能和栈里那些往右飞的撞。而且撞碎一个不代表结束——它可能还要继续撞更靠前的。所以用 while 一直打，直到出现三种情况之一：当前这颗碎了、栈空了、栈顶不是往右飞的。打完还活着，才把它放进栈。

#### ③ 拿 `[3,5,-6,2,-1,4]` 走一遍

| 来了 a | alive | 栈 stack（处理完之后） | 发生了什么 |
|---|---|---|---|
| 3 | True | `[3]` | 往右飞，直接入栈 |
| 5 | True | `[3, 5]` | 往右飞，直接入栈 |
| -6 | True | `[-6]` | 往左飞：栈顶 5 比 6 小，弹掉；栈顶 3 比 6 小，再弹；栈空，停。活着入栈 |
| 2 | True | `[-6, 2]` | 往右飞，不撞，入栈 |
| -1 | False | `[-6, 2]` | 往左飞，栈顶 2 比 1 大 → 当前这颗碎，不入栈 |
| 4 | True | `[-6, 2, 4]` | 往右飞，不撞，入栈 |

所以答案是 `[-6, 2, 4]`。注意第 3 步：一次 while 里连撞两颗，这就是"撞完还要继续撞"。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `stack = []` | 空栈，装还活着的小行星 |
| `for a in asteroids` | 一颗一颗处理 |
| `alive = True` | 先假设当前这颗能活下来 |
| `while alive and a < 0 and stack and stack[-1] > 0` | 还活着、往左飞、栈非空、栈顶往右飞——四个条件全成立才打 |
| `if stack[-1] < -a: stack.pop()` | 栈顶比当前这颗小，栈顶碎；当前这颗继续往左撞 |
| `elif stack[-1] == -a:` | 一样大，同归于尽 |
| `stack.pop()` / `alive = False` | 栈顶没了，当前这颗也没了，循环停 |
| `else: alive = False` | 栈顶更大，当前这颗碎 |
| `if alive: stack.append(a)` | 打完了还活着才入栈，这句必须在 while 外面 |
| `return stack` | 栈里剩下的就是答案 |

### 考什么

- 表面考点：按规则模拟碰撞。
- 真正考点：**只有一种碰撞会发生**——栈顶往右（正）、当前往左（负）。把这个条件想清楚，剩下就是把"撞完还可能继续撞"写成 while。
- 面试官想听到的关键句："往右的压在栈里等着，遇到往左的才开打；打输了当前这颗没了，打赢了还要继续和下一个栈顶打。"

### 思路是怎么想出来的

- **暴力**：每一轮扫描数组，找出相邻的"正、负"对撞掉，重复到没有可撞的为止。O(n²)，实现还啰嗦。
- **关键观察**：方向相同永远不会撞。而"负在正左边"（左移的已经在右边、右移的在左边）它们在互相远离，也不会撞。所以唯一会撞的组合是：**左边的正数 + 右边的负数**。从左往右扫时，左边的都进了栈，当前这颗如果往左，就只可能和栈里那些往右的撞。
- 而且**撞一次不一定结束**：当前这颗撞碎栈顶后，可能还要撞更靠前的正数。所以用 while 一直打，直到出现三种情况之一：当前碎了 / 栈空了 / 栈顶不是正数。
- **于是有**：栈存"还活着的小行星"。来一颗新的，先假设它活着；如果它往左且栈顶往右，就循环打；打完还活着才入栈。

### 代码（Python）

```python
from typing import List   # 力扣已预导入这行，本地跑时要加上

class Solution:
    def asteroidCollision(self, asteroids: List[int]) -> List[int]:
        stack = []                      # 还活着的小行星
        for a in asteroids:
            alive = True
            # 只有"当前往左 a < 0" 且 "栈顶往右 stack[-1] > 0" 才会撞
            while alive and a < 0 and stack and stack[-1] > 0:
                if stack[-1] < -a:      # 栈顶小，栈顶碎
                    stack.pop()         # 当前这颗继续往左撞
                elif stack[-1] == -a:   # 一样大，同归于尽
                    stack.pop()
                    alive = False
                else:                   # 栈顶大，当前这颗碎
                    alive = False
            if alive:
                stack.append(a)
        return stack
```

**逐段讲解**

- `alive` 是这题的"状态位"。它在 while 条件里，一旦当前这颗碎了，while 立刻停，后面的逻辑自然跳过。没有它就得用 `break` 加标志位，更绕。
- while 的四个条件对应四种"不该继续打"：当前已经碎了（`not alive`）、当前往右（`a < 0` 不成立）、栈空（`stack` 为假）、栈顶往左（`stack[-1] > 0` 不成立，同向不撞）。
- `-a` 是当前这颗的**大小**（a 是负数）。比较的是大小，不是数值大小关系。
- 三种结果里，**只有第一种 `stack.pop()` 之后不退出循环**——因为当前这颗还在，要继续和新的栈顶打。另外两种都让 `alive = False`，循环自然结束。
- `if alive: stack.append(a)` 必须在 while **外面**：打完了才决定入不入栈。

### 复杂度

- 时间 O(n)：每颗小行星入栈一次、出栈至多一次，while 总执行次数 ≤ n。
- 空间 O(n)：栈最多存下所有小行星。

### 常见误区

1. **碰撞条件写成"方向不同就撞"**。`[-2,-1]` 都往左、`[1,2]` 都往右，同向不撞；`[-1, 2]` 是左移的在左、右移的在右，两者在互相远离，也永远撞不上。只有**正数在左、负数在右**才撞。
2. **只用 `if` 不用 `while`**。`[10,2,-5]` 里 -5 撞碎 2 之后还要继续撞 10，只写 if 会得到 `[10,-5]`，正确答案是 `[10]`。
3. **同归于尽时忘了 `alive = False`**。`[8,-8]` 会输出 `[-8]`，正确答案是 `[]`。
4. **先 `stack.append(a)` 再打**。当前这颗变成栈顶，while 里 `stack[-1] > 0` 判断的是它自己，逻辑失效。
5. **`stack[-1] < -a` 写成 `stack[-1] < a`**。a 是负数，`3 < -5` 不成立，会误判成"栈顶大"让当前碎掉：`[3,-5]` 输出 `[3]`，正确答案是 `[-5]`。

### 面试追问 / 变体

- 大小相同时要求"保留左边那颗"：改 `==` 分支的行为。
- 不同速度、多方向：要算相遇时间，用堆（优先队列）。
- 要求返回碰撞过程（每次谁碎）：栈里再存原始下标，记日志。
- 输入保证不会撞（所有负数都在正数左边）：直接返回原数组，可作快速路径。

### 自测

- 必测：`[5,10,-5]` → `[5,10]`、`[8,-8]` → `[]`、`[10,2,-5]` → `[10]`、`[3,5,-6,2,-1,4]` → `[-6,2,4]`
- 边界：`[-2,-1,1,2]` → 原样（不会撞）、`[-1,-1]` → `[-1,-1]`、`[1,-2,-3]` → `[-2,-3]`（1 碎后 -2 继续，-3 与它同向不撞）
- 30 秒自检：只有"正左负右"才撞、用 while 连续撞、打完才入栈。
