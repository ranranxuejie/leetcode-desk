# 02 · 复杂度的直觉：什么叫"快"

这一章只解决一个问题：**看到一个 n 的范围，你能立刻知道自己最多能用几层循环。**

---

## 1. 为什么算法题在乎"快慢"

力扣和华为机考都有时间限制（一般 1-2 秒）。Python 每秒大约能做 **10⁷ 次简单操作**（10 的 7 次方，一千万次）。

所以：

```
n = 100         → 随便怎么写都行，O(n³) 也来得及
n = 10,000      → O(n²) 是 10⁸ 次，Python 已经超时了
n = 100,000     → 必须 O(n) 或 O(n log n)
n = 1,000,000   → 只有 O(n) 甚至 O(n) 还得写得很省
```

**这不是理论，是硬门槛。** 你写完一个 O(n²) 的解法，发现测试用例有 10⁵ 个元素，那这解法就是错的——不是逻辑错，是过不了。

---

## 2. 大 O 是什么（一句话版）

**大 O 描述的是"输入翻倍时，耗时大概怎么变"，不是具体几秒。**

| 复杂度 | 输入翻倍时 | 名字 | 感觉 |
|---|---|---|---|
| O(1) | 不变 | 常数 | 查字典 |
| O(log n) | 只多一步 | 对数 | 猜数字（每次砍一半） |
| O(n) | 翻倍 | 线性 | 把一摞纸数一遍 |
| O(n log n) | 翻倍多一点 | 线性对数 | 排序 |
| O(n²) | 变 4 倍 | 平方 | 每张纸都要和其他所有纸比一次 |
| O(2ⁿ) | 平方级爆炸 | 指数 | 每个元素"选/不选"全枚举 |
| O(n!) | 灾难 | 阶乘 | 全排列 |

记住这个顺序就够了：**O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)**

---

## 3. ★ 反查表：看到 n 的范围，就知道能用什么

**这张表是本章唯一必须背下来的东西。**

| 题目给的 n 范围 | 你能用的复杂度 | 典型解法 |
|---|---|---|
| n ≤ 10 | O(n!) / O(2ⁿ) | 全排列、暴力枚举 |
| n ≤ 20 | O(2ⁿ) | 状态压缩、子集枚举 |
| n ≤ 100 | O(n³) | 三重循环、Floyd |
| n ≤ 1,000 | O(n²) | 双层循环、DP 二维 |
| n ≤ 10⁵ | **O(n log n)** | 排序、堆、二分 |
| n ≤ 10⁶ | **O(n)** | 一次遍历、哈希、双指针、滑窗 |
| n ≤ 10⁹ | **O(log n)** 或 O(1) | 二分、数学公式 |

**实战用法**：读完题先看数据范围，直接反推算法。

- 看到 `1 <= nums.length <= 10^5` → 别想 O(n²)，往 O(n) / O(n log n) 想
- 看到 `1 <= n <= 20` → 大概率是回溯 / 状态压缩
- 看到 `1 <= n <= 1000` → O(n²) 的 DP 可以放心写

这个习惯能让你在**读完题的 10 秒内**就知道方向对不对。

## 4. 怎么数循环

### 单层循环 → O(n)

```python
for x in nums:          # 跑 n 次
    total += x          # 每次 O(1)
# 总共 O(n)
```

### 双层循环 → O(n²)

```python
for i in range(n):          # n 次
    for j in range(n):      # 每次里面 n 次
        ...                 # 总共 n × n = O(n²)
```

### 但注意：不是看到两层循环就是 O(n²)

```python
for i in range(n):          # n 次
    for j in range(i):      # 第 i 次跑 i 次
        ...
# 总共 0+1+2+...+(n-1) = n(n-1)/2，还是 O(n²)
```

```python
left = 0
for right in range(n):      # 外层 n 次
    while left < right and 条件:
        left += 1           # 但 left 总共只增加 n 次！
# 总共 O(n) —— 这是滑动窗口为什么是线性的关键
```

**判断技巧：看内层循环的变量总共增加了多少次，而不是看它嵌套了几层。** 如果 `left` 从 0 走到 n 就停了，那内层的 while 加起来只有 n 次。

### 循环里带 log → O(n log n)

```python
for x in nums:              # n 次
    heapq.heappush(h, x)    # 每次 O(log n)
# O(n log n)
```

### 每次砍一半 → O(log n)

```python
while left <= right:
    mid = (left + right) // 2
    if ...: left = mid + 1
    else:   right = mid - 1
# n → n/2 → n/4 → ... → 1，约 log₂n 步
```

**n = 10⁹ 时 log₂n ≈ 30。** 这就是二分查找的威力。

### 排序 → O(n log n)

Python 的 `sorted()` / `list.sort()` 是 Timsort，O(n log n)。**所以"先排序再处理"通常是可接受的。**

## 5. 递归的复杂度怎么估

**方法：数"每个节点被访问几次" × "每次访问做多少事"。**

以二叉树遍历为例：

```python
def dfs(node):
    if not node: return
    dfs(node.left)
    dfs(node.right)
```

每个节点访问一次，每次 O(1) → **O(n)**（n 是节点数）。

如果每次访问还要做 O(n) 的事（比如复制整个列表），那就是 O(n²)。

**回溯/全排列是 O(n!)**，因为决策树有 n! 个叶子。看到回溯题，先问自己"搜索空间有多大"。

---

## 6. 空间复杂度：别忘了数

空间复杂度看两样东西：

1. **你新开了多少数据结构**（list / dict / set / 递归栈）
2. **递归的深度**（每层递归占一个栈帧）

```python
def f(nums):
    res = []                # O(n) 空间
    for x in nums:
        res.append(x * 2)
    return res              # 空间 O(n)
```

```python
def dfs(node):              # 递归深度 = 树高 h
    ...
# 空间 O(h)，最坏 O(n)（退化成链）
```

**面试时经常被问"能不能 O(1) 空间"**，意思是"别开新数组，原地改"。比如反转链表、原地删除数组元素。

## 7. 摊还分析：为什么单调栈是 O(n)

这是初学者最容易困惑的一点。看这段：

```python
for i, x in enumerate(nums):
    while stack and nums[stack[-1]] < x:   # 看起来嵌套了！
        stack.pop()
    stack.append(i)
```

看到 `while` 嵌在 `for` 里，第一反应是 O(n²)。**但它其实是 O(n)。**

**为什么？** 因为每个下标**最多进栈一次、出栈一次**。整个循环过程中，`pop()` 的总次数不超过 n。所以：

```
总操作数 = n 次 push + 最多 n 次 pop = 2n = O(n)
```

**这就是"摊还"的思想：不看最坏的那一次，看总账。** 后面分册 B 讲单调栈时还会强调这一点。

## 8. 五个常见误判

| 误判 | 真相 |
|---|---|
| "两层循环就是 O(n²)" | 看内层变量总共走了多少步（滑窗、单调栈是 O(n)） |
| "用了 `in` 就是 O(1)" | `x in list` 是 O(n)，`x in set/dict` 才是 O(1) |
| "递归就是 O(n)" | 看递归树的分支数，回溯是 O(n!)，朴素递归斐波那契是 O(2ⁿ) |
| "排序太慢不能排" | 排序只有 O(n log n)，n=10⁵ 完全没问题，而且能换来 O(n) 的后续处理 |
| "复杂度只看时间" | 空间也要看，尤其递归深度 |

## 9. 一个完整的判断流程

拿到一道题，按这个顺序走：

```
1. 看 n 的范围  →  反查表，确定目标复杂度
2. 想暴力解法    →  它的复杂度是多少？
3. 暴力够用吗？  →  够用就直接写（面试时先写暴力再优化是加分项）
4. 不够用        →  问：慢在哪一步？那一步能不能用哈希/排序/二分/滑窗加速？
5. 写完验证      →  数一遍循环，确认复杂度和你想的一致
```

**第 4 步是算法题的核心**。所有优化本质上就这几招：

- 把"查找"从 O(n) 变成 O(1) → **哈希表**
- 把"枚举所有"变成"砍一半" → **二分 / 分治**
- 把"重复计算"变成"存起来" → **动态规划 / 记忆化**
- 把"两层循环"变成"一次扫描" → **双指针 / 滑动窗口 / 单调栈**
- 把"无序"变成"有序" → **排序**

记住这五招，你已经能解释 80% 的算法优化了。

## 10. 每道题的「最优复杂度」标签在哪看

网页题库里，**每一道题的标题右边都有一个灰色小标签**，写着这道题最优解法的时间复杂度，比如 `O(n)`、`O(n log n)`、`O(n²)`。鼠标悬上去会显示三样东西：

| 显示 | 含义 |
|---|---|
| `O(n)` | 这道题**最优解法**的时间复杂度（不是某份代码的，是这道题能做到的最好） |
| `空间 O(1)` | 最优解额外用的空间（不数输出本身） |
| `一层循环，每个元素只走一次` | **人话版**：这段解法到底是几层循环、什么结构 |

题目详情页的标题下面也会重复一行，比如：

> 最优 O(n²) · 空间 O(1) · 排序后两层循环，双指针收拢

**怎么用它**：

1. **写之前先看一眼**。看到 `O(n log n)` 就知道八成要排序；看到 `O(n)` 就知道不能两层循环。
2. **写完对一下**。你的代码是两层循环，标签说最优是 O(n)，那大概率还能优化——这就是你该想"能不能用哈希/双指针"的信号。
3. **别把它当答案抄**。标签告诉你"目标在哪"，不告诉你"怎么走"；怎么走看那道题的精讲。

> 注：少数题的最优解比教材里的代码更高级（比如「接雨水」最优是双指针 O(n)/O(1)，教材里给的是三趟扫描）。这种情况标签写的是**最优的**，代码可能略慢一点，`why` 里会点明差别。
