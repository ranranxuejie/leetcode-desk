# 写作规范（分册作者必读）

这套教材只有一个读者，先把他/她刻在脑子里，再动笔。

## 一、读者画像（非常重要，决定了你写什么、不写什么）

- **会 Python，而且写得不少**：list/dict/set/推导式/切片/类，日常做数据分析和深度学习，PyTorch 写过，所以**不怕代码，怕的是"算法"这门手艺**。
- **没学过 C/C++**：不要用"数组指针""结构体""内存地址"类比。不要出现 `int*`、`struct`、`vector`、`malloc` 这类词。
- **算法基础≈零**：只看过两数之和这类简单题。**不知道**时间复杂度怎么算、**不知道**什么是滑动窗口/单调栈/回溯/DP 状态转移。这些概念**第一次出现必须解释**。
- **理解力强、思维清晰**：不需要哄，不需要"相信自己你可以的"这种话。要的是**把道理讲透**：为什么这样做、为什么不能那样做。
- **能顺着代码看懂意图**：所以代码要写得像"可读的伪代码"，变量名要有意义，关键行要有注释。不需要逐字符解释 `for` 循环怎么写。

**由此推出三条铁律**：
1. 任何算法名词第一次出现，用一句人话解释 + 一个生活类比，再上代码。
2. 不要为了显得专业而堆术语；每个术语都要能落地到"代码里是哪一行"。
3. 不要写"显然""易得""显然成立"——读者没有这个直觉，你要把"为什么显然"拆开。

## 二、每道题的固定结构（必须严格按这个顺序，标题层级也要一致）

```markdown
## A3. 无重复字符的最长子串（Medium）

> 力扣 3 · 滑动窗口 · 华为 CodeTop 频次 49（第 1 名）
> 前置：第 03 章「滑动窗口模板」

**一句话**：用一句人话说清这题要你干什么（不要抄题面）。

### 考什么
- 表面考点：……
- 真正考点：……（这是重点，说清它其实在考哪个模板/哪种思维）
- 面试官想听到的关键句：……（1-2 条，就是能证明"你真懂"的那句话）

### 思路是怎么想出来的
从最笨的办法讲起，一步步推到最优解。每一步都要说"为什么上一步不够好"。
- 暴力：…… 复杂度 …… 为什么不行
- 关键观察：……（这是全题最重要的一步，要讲透）
- 于是有：……（引出模板）

### 代码（Python）

```python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        ...
```

**逐段讲解**：不要逐行翻译代码，而是讲"这一段在干什么、为什么这么写"。重点讲：
- 初始化为什么这么设
- 循环不变量（走到第 i 步时，什么是始终成立的）
- 哪一行是这题的灵魂

### 复杂度
- 时间 O(?)：为什么（数了什么）
- 空间 O(?)：为什么

### 常见误区（★ 最容易丢分的地方）
每条都要写清"错在哪一行 / 错了会得到什么错误结果 / 怎么发现"。
1. ……
2. ……

### 面试追问 / 变体
- 如果面试官改成……，怎么改？（给 1-3 条，点到为止，不要展开成新题）

### 自测
- 必测用例：……（列出 3-5 个，含边界）
- 30 秒自检：不看代码，能不能说出这题的三步？
```

## 三、代码要求（硬性）

1. **必须是能直接跑的完整 `class Solution`**，方法签名与力扣一致（用 `s: str -> int` 这种类型标注）。
2. **必须自己跑过**：把代码写进临时文件，用下面的 Python 跑至少 3 个用例（含题面示例和边界），确认输出正确。跑不过不许交。
   `C:\Users\Administrator\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`
3. **只用标准库**：`collections`（deque/Counter/defaultdict）、`heapq`、`bisect`、`math`、`itertools`、`functools`。不要用 numpy/pandas（面试不让用）。
4. **Pythonic 但不炫技**：可以用推导式、`enumerate`、`zip`，但不要用 `functools.reduce` 写复杂逻辑，不要为了短而牺牲可读性。
5. 需要自定义结构（链表/树）时，把 `class ListNode` / `class TreeNode` 的定义也写出来，并说明"力扣后台已经帮你定义好了，你只要写方法"。

## 四、写作风格

- **中文，第二人称"你"**，像一个耐心的师兄在旁边讲。
- 允许用比喻（窗口=传送带、栈=叠盘子、DP=填表格），但比喻之后必须回到代码。
- 段落短，多用小标题、列表、表格。**不要写大段连续文字**。
- 关键结论加粗，但**每节最多加粗 2-3 处**，否则等于没加粗。
- 不要写"这道题很简单/很难"，写"这题的坑在哪"。
- 不要写鸡汤、不要写"加油"、不要写"相信你"。

## 五、篇幅

- 简单题（Easy）：600-900 字 + 代码
- 中等题（Medium）：900-1400 字 + 代码
- 困难题（Hard）：1400-2000 字 + 代码
- 宁少勿水：如果某节没内容可写，宁可写短，不要凑字数。

## 七、第二册（专题册）的补充规则

第二册按用户提供的 11 个专题组织，覆盖 104 道题。题目分两类，写法不同：

### A 类：全新题（第一册没讲过）→ 用完整的七段结构
和第一册完全一样：考什么 / 思路是怎么想出来的 / 代码 / 复杂度 / 常见误区 / 面试追问 / 自测。

### B 类：第一册已精讲的题 → 只写「回顾 + 换个角度」，不重复精讲

```markdown
## 专题1-6. 两数之和（回顾）
> 第一册已精讲：[分册 A · A6](../10-分册A-数组字符串滑窗哈希.md)
> 力扣 1 · 哈希表 · Easy

**30 秒回顾**：哈希表存"值→下标"，遍历时查 `target - x` 在不在表里。O(n) 时间，O(n) 空间。

**核心代码（背这一段就够）**：
```python
seen = {}
for i, x in enumerate(nums):
    if target - x in seen:
        return [seen[target - x], i]
    seen[x] = i
```

**换个角度**：
- 如果数组**已经有序**，这题用双指针可以做到 O(1) 空间（这是 167 两数之和 II 的解法），
  面试官常追问"能不能不用哈希表"，答案就是这个。
- 哈希表解法的隐含代价：需要额外 O(n) 空间，且哈希在最坏情况下退化。
```

篇幅 300-500 字，不要超过 600 字。**B 类的价值在于"换个角度"那一节**，要写出第一册没讲的补充信息（变体、权衡、追问），不要只是复述。

### 用户笔记里的核心思路
`data/用户题单.json` 的 `hints` 字段里有用户自己整理的每道题的"核心解题思路"。**动笔前先读一遍**：
- 如果它和你的解法一致 → 可以引用它作为"一句话记忆"
- 如果它和你的解法不同（比如 42 接雨水用户记的是双指针，你想讲单调栈）→ **两种都讲**，并说明各自适用场景
- 如果它明显有误 → 在「常见误区」里指出来，并说明为什么

### 每册开头
写 200-400 字的「本册地图」：这册有哪几道题、它们共同考什么、建议按什么顺序读、和第一册哪一册呼应。

## 八、禁止事项

- ❌ 编造题目编号、题面、示例（题面以 `data/题面-第一册.md` 为准，也可看力扣原题）
- ❌ 只给代码不解释思路
- ❌ 用 C/C++ 概念类比
- ❌ 写"这里显然""读者可以自行验证"
- ❌ 空泛的误区（"注意边界"不行，要写"注意 `left` 只能前进不能后退，否则 abba 会输出 4"）

## 九、精讲（零基础版）—— 全部习题必写

读者的真实反馈是「一些概念没学过就直接出现，不好理解」。所以**每一道习题**的章节里，都必须有一节 `### 精讲（零基础版）`，位置在章节 `>` 引言块之后、第一个 `###` 之前（也就是该章节的第一个小节）。

四段结构（顺序固定）：

1. **① 这题要用到的东西**：把容器、Python 语法、算法名词逐个拆开——一句人话 + 一个生活类比 + 3–6 行能跑的最小例子 + 它在这题里的角色。同一个概念一册只精讲一次，后面出现写「（前面 X 讲过）：……」。
2. **② 大白话：这题到底在干什么**：先讲最笨的办法，再讲笨在哪，最后讲聪明办法。不出现未解释的名词，不出现代码。
3. **③ 拿一个具体输入走一遍**：表格，列 ≤ 5、行 ≤ 10，数字必须是真跑出来的。
4. **④ 代码逐行对译**：表格「代码 | 大白话」，挑 8–15 行关键行。

完整标准与样板见 `tools/_精讲规范.md`。术语急救包见 `教程/04-术语急救包.md`。
