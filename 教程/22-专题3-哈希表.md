## 本册地图

你日常写 Python 就一直在用 dict、set、Counter，所以这一册不教"哈希表是什么"，而是回答三个更难的问题：

1. **什么时候该用哈希？** 判断标准只有一条：你需要"按值直接找到某个东西"——存在性、次数、下标、分组，都属于这一类；"按顺序找""找最值""找范围"不属于。本册精讲的三题都是"值 → 结果"的映射。
2. **哈希表的代价是什么？** 空间 O(n)、丢掉顺序、最坏情况退化。动手前先问一句：我能不能不存？专题3-4、3-5 专门讲这条边界。
3. **key 怎么设计？** 这是 49 题的核心：把"看起来不像同一个东西"的对象映射到一个可比较的 key 上。设计 key 的能力，才是哈希表真正的能力。

建议顺序：242（最小例子，频率表）→ 49（key 的设计）→ 128（用集合做存在性查询）→ 3-4、3-5（边界与权衡）。前三题从易到难，后两题是"什么时候不该用哈希"。

与第一册的呼应：第一册 A6（两数之和）、A8（前缀和 + 哈希）已经建过"值 → 下标 / 次数"的模型。本册把它们当成已掌握，只补边界和代价。

## 专题3-1. 字母异位词分组（Medium）

> 力扣 49 · 哈希表 + key 设计 · 前置：专题3-3（频率表）
> 用户笔记："将每个字符串排序后作为 key（或计数数组作 key），哈希表按 key 分组收集" —— 完全正确，本册补上"为什么排序能当 key"和三种 key 的取舍。

**一句话**：把一堆字符串按"字母组成相同"分组——`"eat"`、`"tea"`、`"ate"` 是一组，`"bat"` 自己一组。

### 精讲（零基础版）

#### ① 这题要用到的东西

**字典 `dict`（也就是哈希表）**

一句话：一张"键 → 值"的对照表。你报一个键，它直接告诉你值，不用从头一个个找。

- `d[k] = v`：存一对
- `d[k]`：按键取值，**键不在会报错**
- `k in d`：问在不在
- `d.get(k, 默认值)`：键不在时给你个默认值，不报错

生活类比：查字典。你报一个字，直接翻到那一页，不用从第一页读起。

```python
d = {}
d["aet"] = d.get("aet", []) + ["eat"]
print(d)          # -> {'aet': ['eat']}
```

它在这题里：key 是"排序后的串"，value 是"这一组的原始字符串列表"。

**`defaultdict(list)`**

一句话：普通字典查一个没存过的键会报错；`defaultdict(list)` 会自动先建一个空列表给你，省掉"键不在就先建列表"那三行。

生活类比：一排空抽屉，每个抽屉上都贴着标签。你拉开任何一个没贴过的标签，里面已经放好一个空盒子，直接往里扔东西就行。

```python
from collections import defaultdict
groups = defaultdict(list)
groups["aet"].append("eat")
groups["aet"].append("tea")
print(dict(groups))            # -> {'aet': ['eat', 'tea']}
print(list(groups.values()))   # -> [['eat', 'tea']]
```

它在这题里：`groups[key].append(s)` 一行就是"把 s 扔进它那一组"。分组题几乎都用它。

**`sorted()` 和 `"".join()`**

一句话：`sorted(s)` 把字符串的字符排好序，返回一个**列表**；`"".join(列表)` 把列表里的字符用空串粘起来，变回字符串。

生活类比：`sorted` 是把一袋字母倒出来按顺序摆好（散在桌上），`join` 是把它们串成一根项链。

```python
s = "eat"
print(sorted(s))                 # -> ['a', 'e', 't']
print("".join(sorted(s)))        # -> aet
print("".join(sorted("tea")))    # -> aet    和上面一模一样，这就是同一个 key
```

它在这题里：`key = "".join(sorted(s))` 就是每个词的"身份证号"——异位词排序后必然相同。

**可哈希（hashable）**

一句话：只有"内容永远不会变"的东西才能当字典的 key。数字、字符串、元组可以；列表不行，因为列表能改。

生活类比：储物柜的钥匙牌上必须刻死一个号码。号码还能随手改，柜子就再也找不回来了。

```python
d = {}
d[(1, 2)] = "元组可以当 key"
print(d[(1, 2)])     # -> 元组可以当 key
print(d)             # -> {(1, 2): '元组可以当 key'}
```

它在这题里：`key = sorted(s)` 会报 `TypeError: unhashable type: 'list'`，所以必须 `"".join(...)` 或 `tuple(...)` 变回不可变的东西。

#### ② 大白话：这题到底在干什么

最笨的办法：从第一个词开始，把它和后面每个词都比一遍——比法是把两个词都拆成字母数一数，数一样就归到一组。n 个词要比大约 n×n÷2 次，n 到一万时是几千万次，勉强但很浪费。

笨在哪？**每来一个新词，都要回头和已有的每一组重新比一遍**。可"它属于哪一组"这件事，其实看它自己就够了，不需要和谁比。

聪明的办法：给每个词算一个"身份证号"（key），字母组成相同，身份证号就相同。然后拿一本字典按身份证号归堆：报出号码，直接找到那一堆，把词扔进去。

这样一来，每个词只需要算一次号、查一次表，全程 O(n) 次"算号 + 查表"。这道题真正考的不是哈希表本身，而是**你能不能想出这个身份证号**。

#### ③ 拿 `["eat","tea","tan","ate","nat","bat"]` 走一遍

| 步 | 进来的 s | 算出的 key | 这一组现在的成员 | 一共几组 |
|---|---|---|---|---|
| 1 | `"eat"` | `aet` | `['eat']` | 1 |
| 2 | `"tea"` | `aet` | `['eat', 'tea']` | 1 |
| 3 | `"tan"` | `ant` | `['tan']` | 2 |
| 4 | `"ate"` | `aet` | `['eat', 'tea', 'ate']` | 2 |
| 5 | `"nat"` | `ant` | `['tan', 'nat']` | 2 |
| 6 | `"bat"` | `abt` | `['bat']` | 3 |

所以答案是三组：`[['eat','tea','ate'], ['tan','nat'], ['bat']]`。注意第 4 步：`"ate"` 排完序是 `aet`，和第 1 步的 `"eat"` 撞在同一个 key 上，于是自动并进第一组——**这就是整道题的全部机制**。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `groups = defaultdict(list)` | 准备好那排"自带空盒子"的抽屉 |
| `for s in strs:` | 一个一个词处理 |
| `key = "".join(sorted(s))` | 算身份证号：字符排好序，再粘回字符串 |
| `groups[key].append(s)` | 按号找到抽屉，把原词扔进去。注意存的是**原词**，不是排好序的版本 |
| `return list(groups.values())` | 把所有抽屉里的东西倒出来。题目不要求组间、组内顺序，所以直接取 values 就行；`list(...)` 不能省，`values()` 只是个视图 |

### 考什么

- 表面考点：分组。
- 真正考点：**怎么给"字母异位词"设计一个 key**。两个词是异位词，等价于"字母的多重集合相同"。可比较的"多重集合"有三种表示：排序后的字符串、26 个字母的计数、质数乘积。选哪个，决定代码长短和复杂度。
- 第二个考点：**哈希表的 value 可以是列表**。分组类题目的标准动作就是 `groups[key].append(x)`。
- 面试官想听到的关键句："异位词排序后是同一个字符串，所以拿排序结果当 key，一次遍历就能分好组。"

### 思路是怎么想出来的

- 暴力：两两判断是不是异位词（比较计数，O(k)），O(n²k)。n = 10⁴ 时 10⁸ 起步，不行。
- 关键观察：**"是不是同一组"这件事，只需要一个能代表整组的标签。** 标签相同就同组——这正是哈希表的工作方式：把"复杂对象"压成"可比较的 key"。
- 三种 key：

| key | 怎么构造 | 单次代价 | 说明 |
|---|---|---|---|
| 排序后的串 | `"".join(sorted(s))` | O(k log k) | 最短、最好写，面试首选 |
| 26 字母计数 | `tuple(count)` | O(k) | 更快，代码长一点 |
| 质数乘积 | 每个字母乘一个质数 | O(k) | 乘积会非常大（Python 能扛，别的语言会溢出），不推荐 |

- 于是有：`groups = defaultdict(list)`，遍历每个词算 key，`groups[key].append(s)`，最后 `list(groups.values())`。

### 代码（Python）

```python
from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        groups = defaultdict(list)          # key（排序后的串）-> 这一组的原始字符串
        for s in strs:
            key = "".join(sorted(s))        # 异位词排序后一定是同一个串
            groups[key].append(s)
        return list(groups.values())
```

**逐段讲解**

- `defaultdict(list)`：第一次遇到某个 key 时自动给一个空列表，省掉"key 不存在就先建列表"的三行。分组题几乎都用它。
- `"".join(sorted(s))`：`sorted` 返回的是字符列表，要拼回字符串才能当 key。**直接用 `sorted(s)` 不行**——列表不能做字典的 key（不可哈希）。这是这题最常见的报错。
- 空字符串 `""` 排序后还是 `""`，自然成为一组；`[""]` 输出 `[[""]]`，不用特判。
- 返回 `list(groups.values())`：题目不要求组间顺序、也不要求组内顺序，直接取 values 就行。
- 循环不变量：**每轮结束时，`groups` 里每个 key 对应的列表，恰好是所有已处理过的、该 key 的字符串。**

### 复杂度

- 时间 O(n·k log k)：n 个词，每个排序 O(k log k)，k 是词长（≤100）。
- 空间 O(n·k)：所有字符串都要存进结果（不计输出的话，额外空间主要是 key 的总长）。

### 常见误区（★ 最容易丢分的地方）

1. **`key = sorted(s)`。** 列表不可哈希，直接 `TypeError: unhashable type: 'list'`。必须 `"".join(...)` 或 `tuple(...)`。
2. **用 `len(s)` 当 key。** `"eat"` 和 `"tan"` 长度都是 3，会被分到一组。key 必须能区分"字母组成"，长度不行。
3. **用 `set(s)` 当 key。** `"aab"` 和 `"ab"` 的集合都是 `{"a","b"}`，会被误合并。**异位词比的是"每个字母出现几次"，不是"出现过哪些字母"。**
4. **直接 return `groups.values()`。** 返回的是视图对象，力扣判题要 list，必须 `list(...)`。

### 面试追问 / 变体

- **要求组内按字典序、组间按首元素排序**：最后对每个组 `sort()`，再对整体排序，O(n log n) 级别，不影响主逻辑。
- **词里含 Unicode**：计数法的"26 个字母"假设不成立，数组要换成字典；排序法不受影响——**这就是排序 key 的隐性优势**。
- **不用排序的 O(nk) 解法**：`key = tuple(count)`，`count` 是长度 26 的计数数组。面试官追问"能不能更快"时给这个。
- **同族题目**：242 有效的字母异位词是这题的单对版本；438 找到所有字母异位词是"定长滑窗 + 计数"。

### 自测

- 必测：`["eat","tea","tan","ate","nat","bat"]`→3 组、`[""]`→`[[""]]`、`["a"]`→`[["a"]]`、`["",""]`→一组两个空串、`["abc","bca","cab","xyz"]`→2 组、`["ab","ba","abc","cba","bca"]`→2 组。
- 30 秒自检：能不能说出为什么 `set(s)` 不能当 key？举出 `"aab"` / `"ab"` 就算过。

## 专题3-2. 最长连续序列（Medium）

> 力扣 128 · 哈希集合 · 前置：专题3-1（"用哈希换 O(1) 查询"）
> 用户笔记："HashSet 存所有数；遍历每个数，若 num-1 不在集合中则作为起点，不断 num+1 数长度" —— 完全正确。本册补上"为什么这道闸决定了 O(n) 还是 O(n²)"。

**一句话**：数组里数字连续（值连续，不是位置连续）的最长一段有多长，要求 O(n)。比如 `[100,4,200,1,3,2]` 里 `1,2,3,4` 连成一段，答案是 4。

### 精讲（零基础版）

#### ① 这题要用到的东西

**集合 `set`**

一句话：只存"有哪些"，不存"第几个"，而且**自动去重**。

生活类比：一袋弹珠。你只关心"袋里有没有红色的"，不关心红色的是第几颗；同一颗红的扔两次，袋里还是一颗。

```python
s = set([3, 1, 3])
print(s)          # -> {1, 3}    重复的 3 只留一个
print(1 in s)     # -> True
print(2 in s)     # -> False
```

它在这题里：`num_set = set(nums)` 一物两用——去重，以及让"这个数在不在"变成一步查询。

**`in` 的速度：列表慢、集合快**

一句话：`x in 列表` 要从头一个一个比，最坏 O(n)；`x in 集合 / 字典` 是算出位置直接跳过去，平均 O(1)。

生活类比：找一个人在不在名单上——列表是逐行往下读，集合是直接翻到按姓氏排好的那一格。

```python
nums = [1, 2, 3]
print(2 in nums)          # -> True    列表：比到第 2 个才找到
print(2 in set(nums))     # -> True    集合：一步
```

它在这题里：这题的全部速度就压在这一行上。要是拿 `nums` 去问"`x+1` 在不在"，每次都是 O(n)，整体立刻退化回 O(n²)。

**集合和字典的关系**（前面 专题3-1 讲过字典）：集合就是"只有键、没有值"的字典，查起来一样快。

**集合不保证顺序**

一句话：`for x in num_set` 出来的次序，和 `nums` 里原来的次序没关系，也不保证从小到大。

生活类比：从袋子里往外掏弹珠，掏出来的顺序取决于它们躺在哪儿。

```python
num_set = set([100, 4, 200, 1, 3, 2])
print(list(num_set))     # -> [1, 2, 3, 100, 4, 200]    和原数组顺序不同
```

它在这题里：这题答案和遍历顺序无关，所以可以放心地遍历集合。

#### ② 大白话：这题到底在干什么

最笨的办法：先把数组排个序，然后从头扫一遍，看相邻两个数是不是差 1，一路数下去。O(n log n)，答案是对的，但题面要求 O(n)，这条路直接被堵。

另一个笨办法：对每个数 `x`，都从 `x` 开始往上数 `x+1`、`x+2`…看能数多长。这样每个数都要数一遍，遇到 `[1,2,3,…,n]` 这种输入，数到后面越来越长，总共 n+(n−1)+…+1 次，O(n²)。

笨在哪？**同一段连续序列被从头数了好多遍**。`1,2,3,4` 这一段，从 1 数过、从 2 又数一遍、从 3 再数一遍。

聪明的办法：加一道闸。对每个数先问一句："`x-1` 在不在集合里？"在，说明 `x` 不是开头，直接跳过——这一段等它的开头来数就行。不在，`x` 就是某一段的开头，从它往上数到底，记下长度。

加了这道闸之后，每个数字只会被"它所在那一段的开头"数到一次，总次数不超过 n。**答案不变，速度从 O(n²) 变成 O(n)，差别全在这一行判断上。**

#### ③ 拿 `[100,4,200,1,3,2]` 走一遍

集合遍历出来的顺序是 `1, 2, 3, 100, 4, 200`（和原数组顺序不同）：

| 步 | x | `x-1` 在集合里？ | 动作 | best |
|---|---|---|---|---|
| 1 | 1 | 否（0 不在） | 是起点，往上数 2、3、4 都在，长度 4 | 4 |
| 2 | 2 | 是（1 在） | 不是起点，跳过 | 4 |
| 3 | 3 | 是（2 在） | 不是起点，跳过 | 4 |
| 4 | 100 | 否（99 不在） | 是起点，往上 101 不在，长度 1 | 4 |
| 5 | 4 | 是（3 在） | 不是起点，跳过 | 4 |
| 6 | 200 | 否（199 不在） | 是起点，往上 201 不在，长度 1 | 4 |

所以答案是 4（序列 `1,2,3,4`）。注意第 2、3、5 步一次都没往上数——这就是那道闸省下来的工作量。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `num_set = set(nums)` | 把数组倒进集合：去重 + 换来 O(1) 的"在不在" |
| `best = 0` | 还没数过，先记 0（空数组正好返回 0） |
| `for x in num_set:` | 遍历集合里的每个数（重复的已经被去掉了） |
| `if x - 1 in num_set: continue` | **整段代码的灵魂**：左边还有邻居，说明 `x` 不是开头，交给它的开头去数 |
| `length = 1` | 起点自己算一个 |
| `cur = x` | `cur` 是"现在数到哪了"，从起点开始 |
| `while cur + 1 in num_set:` | 右边还有邻居就继续 |
| `cur += 1` / `length += 1` | 往右挪一格，长度加一 |
| `best = max(best, length)` | 这一整段数完了，和记录比一比 |
| `return best` | 所有起点都数过了，最大的那段就是答案 |

### 考什么

- 表面考点：最长连续序列。
- 真正考点：**用集合把"这个数在不在"变成 O(1)，然后只从"序列起点"开始数。** 这是"哈希表做存在性查询"的教科书例子。
- 第二个考点：**为什么必须只从起点开始数**——这是 O(n) 和 O(n²) 的分水岭。
- 面试官想听到的关键句："把所有数放进集合；对每个数先判断 `x-1` 在不在集合里，不在才说明 `x` 是一段的开头，从它往后数。每个数只会被数一次，所以是 O(n)。"

### 思路是怎么想出来的

- 暴力：排序后扫一遍，O(n log n)。题目要求 O(n)，排序这条路直接被排除。
- 关键观察：一段连续序列 `x, x+1, x+2, ...` 有一个天然起点：`x-1` 不在数组里。只要找到所有起点，从起点往后数就行。
- 但"往后数"会不会退化成 O(n²)？比如 `[1,2,3,...,n]`，如果对每个数都往后数，总次数是 n+(n−1)+…+1 = O(n²)。所以必须加那道闸：`x-1` 在集合里就跳过。加了之后，每个数只会被"它所在那一段的起点"数到一次，总次数 O(n)。
- 于是有：`num_set = set(nums)`；遍历 `num_set` 里的每个 `x`，`x-1` 存在就跳过，否则从 `x` 一路 `+1` 数到底。

### 代码（Python）

```python
class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        num_set = set(nums)          # 顺便去重
        best = 0
        for x in num_set:
            if x - 1 in num_set:     # 不是起点，跳过（这一行决定了 O(n) 还是 O(n²)）
                continue
            length = 1
            cur = x
            while cur + 1 in num_set:   # 从起点往后数
                cur += 1
                length += 1
            best = max(best, length)
        return best
```

**逐段讲解**

- `set(nums)` 一物两用：去重（重复的 `1` 不该让长度变长），以及 O(1) 判断存在性。`[1,0,1,2]` 的答案是 3 不是 4，靠的就是去重。
- **`if x - 1 in num_set: continue` 是整段代码的灵魂。** 没有它，`[1..n]` 会退化成 O(n²)（答案倒是对的）；有了它，每个数字最多被访问两次：一次作为 `x`，一次作为某段的成员。
- 遍历 `num_set` 而不是 `nums`：遍历原数组会让重复元素被重复处理，虽然不影响答案，但白白多跑。
- `length` 从 1 开始：起点自己算一个。
- 循环不变量：**进入内层 while 时，`x` 一定是某段连续序列的起点；while 结束时 `length` 就是这一段的长度。**

### 复杂度

- 时间 O(n)：外层遍历 n 个元素；内层 while 总共只执行"所有序列长度之和"次，而每段只在它的起点被数一次，所以总次数 ≤ n。**外层内层加起来是 O(n)，不是 O(n²)**——这个论证面试官一定会问。
- 空间 O(n)：集合存所有不同的数。

### 常见误区（★ 最容易丢分的地方）

1. **忘了 `x - 1 in num_set` 这道闸。** 答案仍然正确，但复杂度退化到 O(n²)，`[1..10⁵]` 这种输入直接超时。这是"答案对但过不了"的典型。
2. **先排序再扫。** O(n log n)，不满足题面"O(n)"的要求，面试官问复杂度时当场露馅。
3. **用 `nums.count(x+1) > 0` 判断存在。** `count` 是 O(n) 的，整体 O(n²)。
4. **把闸写反：`if x + 1 in num_set: continue`。** 这样只剩每段的**最后一个**数能当起点，而它后面没有连续数，`length` 永远是 1。`[1,0,1,2]` 输出 1（正确 3）。判断方向的口诀：**要找的是"我是不是开头"，所以看左边有没有 `x-1`。**
5. **内层用 `for cur in range(x, x+n)` 之类。** 边界靠猜、容易越界；用 while + 集合判断最稳。

### 面试追问 / 变体

- 要返回序列本身：在 while 里记 `start = x`，最后 `list(range(start, start + best))`。
- 数据流场景（不断插入数字、随时问最长连续段）：集合不够用，要换成并查集，或"维护区间两端"的哈希表（`left_len`、`right_len`），插入时合并左右两段。
- 只要求"是否存在长度 ≥ k 的连续序列"：提前剪枝，`best >= k` 就返回。
- 容易混淆的题：674 最长连续递增序列比的是"位置连续"，128 比的是"值连续"。

### 自测

- 必测：`[100,4,200,1,3,2]`→4、`[0,3,7,2,5,8,4,6,0,1]`→9、`[1,0,1,2]`→3、`[]`→0、`[5]`→1、`[-3,-2,-1,0,1]`→5、`[10,5,12,3,55,30,4,11,2]`→4。
- 30 秒自检：删掉 `x - 1 in num_set` 那行，答案还对吗？复杂度变成多少？

## 专题3-3. 有效的字母异位词（Easy）

> 力扣 242 · 频率表 · 前置：无。这是本册最小的一道题，但它把"用数组代替哈希"讲清楚了。

**一句话**：判断两个字符串是不是"字母一样、只是顺序不同"。

### 精讲（零基础版）

#### ① 这题要用到的东西

**频率表（计数数组）**

一句话：开一个数组，下标代表"是哪个字符"，格子里存"它出现了几次"。

生活类比：26 个格子的小收纳盒，每个格子贴一个字母标签，'a' 的格子里放 a 的个数，'b' 的放 b 的。两个串是不是异位词，就看两本账对不对得上。

```python
s = "aab"
count = [0] * 26
for ch in s:
    count[ord(ch) - 97] += 1
print(count[0])     # -> 2    'a' 出现 2 次
print(count[1])     # -> 1    'b' 出现 1 次
```

它在这题里：一个数组当账本，s 里遇到字符就 +1、t 里遇到就 −1，最后看账是不是平的。

**`[0] * 26`**

一句话：列表乘一个整数，就是把元素复制几遍。这里造出 26 个 0，一个格子一个字母。

```python
count = [0] * 26
print(len(count))    # -> 26
print(count[:5])     # -> [0, 0, 0, 0, 0]    前 5 格，切片取一段
```

它在这题里：账本一开始全是 0，因为还没有字母出现过。

**`ord()`**

一句话：给你一个字符在编码表里的编号。`ord('a')` 是 97，减掉 97 就映射到 0~25 的下标。

生活类比：每个字母在抽屉柜里有一个固定编号，`ord` 就是查编号的窗口。

```python
print(ord("a"))        # -> 97
print(ord("a") - 97)   # -> 0
print(ord("z") - 97)   # -> 25
```

它在这题里：`count[ord(ch) - 97]` 就是"字母 ch 对应的那个格子"。

**为什么用数组而不是字典**（前面 专题3-1 讲过字典）

字符集只有 26 个、而且是连续的，所以能拿编号当下标，用数组当查找表。它比字典快，还不用管哈希冲突，空间也是常数。**字符集小且固定 → 用数组；否则 → 用字典。** 这就是本册反复出现的那条取舍线。

#### ② 大白话：这题到底在干什么

最笨的办法：把两个串都排好序，再看两个结果是不是一模一样。能过，O(n log n)，但没必要——排序干的事情，比这题要的多得多。

笨在哪？**这题只关心"每个字母出现几次"，根本不在乎顺序**。既然不在乎，就不该花力气去排出一个顺序。

聪明的办法：数次数。开一个 26 格的账本，扫 s 的时候遇到哪个字母就把那格加一，扫 t 的时候遇到哪个字母就把那格减一。

扫 t 的过程中只要某一格变成负数，就说明 t 里这个字母比 s 里多——那肯定不是异位词，可以立刻返回 False，后面的字都不用看了。

最后一格没变成负数，账就是平的，两个串字母组成一样。

#### ③ 拿 `s = "aacc"`、`t = "ccac"` 走一遍

| 步 | 在处理谁 | 哪个格子变了 | 账本（a 格 / c 格） | 判定 |
|---|---|---|---|---|
| 1 | s 扫完 | a 加 2 次、c 加 2 次 | 2 / 2 | 继续 |
| 2 | t 第 1 个 `c` | c 减一 | 2 / 1 | 没负，继续 |
| 3 | t 第 2 个 `c` | c 减一 | 2 / 0 | 没负，继续 |
| 4 | t 第 3 个 `a` | a 减一 | 1 / 0 | 没负，继续 |
| 5 | t 第 4 个 `c` | c 减一 | 1 / −1 | **负数！立刻返回 False** |

所以答案是 False。注意第 5 步：两个串长度一样、字母种类也一样（都只有 a 和 c），错在**个数**——这就是为什么 `set(s) == set(t)` 判不出来。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `if len(s) != len(t): return False` | 长度都不一样，字母个数总和就不可能一样，直接判掉 |
| `count = [0] * 26` | 26 格的空账本 |
| `for ch in s: count[ord(ch) - 97] += 1` | 扫 s，每个字母把自己的格子加一 |
| `for ch in t: count[ord(ch) - 97] -= 1` | 扫 t，每个字母把自己的格子减一 |
| `if count[ord(ch) - 97] < 0: return False` | 减出负数，说明 t 里这个字母多了，当场判掉 |
| `return True` | 账全平，是异位词 |

### 考什么

- 表面考点：判断异位词。
- 真正考点：**频率表**。异位词等价于"每个字符出现次数完全相同"。这是 49 题的单对版本，也是"用数组代替哈希"的第一个例子。
- 面试官想听到的关键句："长度不同直接 False；否则用一个 26 长度的计数数组，s 里加、t 里减，出现负数就说明 t 多了某个字符。"

### 思路是怎么想出来的

- 暴力：把两个串都排序再比较，O(n log n)。能过，但没必要。
- 关键观察：顺序无关的相等 = 每个字符出现次数相等。那就数次数。
- 字符集只有 26 个小写字母，可以用数组当查找表：下标 = `ord(ch) - 97`。这比字典快，也没有哈希冲突。
- 于是有：长度不等直接 False；一个数组，s 加、t 减，中途出现负数就提前返回 False。

### 代码（Python）

```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):        # 长度不同一定不是异位词
            return False
        count = [0] * 26            # 26 个小写字母的频率表
        for ch in s:
            count[ord(ch) - 97] += 1
        for ch in t:
            count[ord(ch) - 97] -= 1
            if count[ord(ch) - 97] < 0:   # t 里某个字符比 s 多
                return False
        return True
```

**逐段讲解**

- `len(s) != len(t)` 这个早退不是必须的（后面也能判出来），但便宜、意图清楚。`"ab"` 和 `"a"` 会在计数阶段被判出来吗？会——但 t 遍历完后 count 里还剩 1，如果只检查负数就漏了。所以要么保留长度检查，要么最后再检查一遍数组是否全 0。
- `ord(ch) - 97`：`'a'` 的编码是 97，减完映射到 0~25。
- 中途判负数：一旦 `t` 里某个字符比 `s` 多，后面怎么减都救不回来，可以立刻返回。这是个小优化，也让逻辑更早收敛。
- 只加不减、最后比较两个数组也行（`Counter(s) == Counter(t)` 一行），但那样要分配两个对象；"一加一减"只用一个数组。
- 循环不变量：**处理完 t 的前 k 个字符时，`count` 表示"`s` 的字符数 − `t` 已处理部分的字符数"，且所有分量都 ≥ 0（否则已经返回 False）。**

### 复杂度

- 时间 O(n)：两趟遍历，每趟 O(1) 的数组操作。
- 空间 O(1)：26 个整数的数组，和输入规模无关。这就是"用数组代替哈希"的好处：空间是常数，还快。

### 常见误区（★ 最容易丢分的地方）

1. **只比较 `set(s) == set(t)`。** `"aab"` 和 `"abb"` 的集合都是 `{"a","b"}`，会误判 True。
2. **忘了长度检查、最后也不检查数组全 0。** `"ab"` vs `"a"` 会返回 True（t 遍历完后 `'b'` 的计数还是 1）。
3. **用 `count[ord(ch)]`（不减 97）。** 数组得开到 123 才不越界，`[0]*26` 直接 IndexError。
4. **把"加 s、减 t"写反。** 本题结果对称、不受影响，但换成"t 是否是 s 的异位词"这类单向判断时就会出错。

### 面试追问 / 变体

- 含 Unicode 字符：`[0]*26` 的假设不成立，换成 `Counter(s) == Counter(t)` 或普通字典。这就是"数组 vs 哈希"的取舍点：字符集小且固定用数组，否则用哈希。
- 要求 O(1) 额外空间且字符集很大：排序比较，O(n log n) 时间、O(1) 额外空间（原地排序）。
- 找出所有字母异位词（438）：定长滑窗 + 计数比较，是 567 的姊妹题。
- 分组：49 题就是把这题"一对一的相等判断"扩展成"多对多的分组"。

### 自测

- 必测：`("anagram","nagaram")`→True、`("rat","car")`→False、`("a","a")`→True、`("ab","a")`→False、`("aacc","ccac")`→False、`("aabb","abab")`→True。
- 30 秒自检：为什么 `set(s) == set(t)` 不够？举出 `"aab"` / `"abb"` 就算过。

## 专题3-4. 两数之和（回顾 · 换个角度：哈希的边界）

> 第一册已精讲：[分册 A · A6 两数之和](10-分册A-数组字符串滑窗哈希.md)
> 力扣 1 · 哈希表 · Easy

### 精讲（零基础版）

#### ① 这题要用到的东西

**均摊 O(1)**

一句话：单次操作偶尔可能慢，但平均下来每次只要一步。字典查一次平均是 O(1)，极端情况下所有 key 挤在同一个位置才会退化成 O(n)。

生活类比：地铁安检偶尔排长队，但平均每个人几秒钟就过去了。说"均摊几秒"比说"永远几秒"准确。

**有序数组 + 双指针**

一句话：数组排好序之后，两个下标从两端往中间夹：和偏小就把左指针往右挪（数变大），偏大就把右指针往左挪（数变小）。

生活类比：两个人从一排台阶的两头往中间走，看谁先碰上——每走一步都能根据"现在高不高"决定该动哪一头。

```python
nums = [1, 2, 4, 7]
target = 9
left, right = 0, len(nums) - 1
while left < right:
    s = nums[left] + nums[right]
    print(nums[left], nums[right], s)          # -> 1 7 8 / 2 7 9
    if s == target:
        print("找到:", nums[left], nums[right])  # -> 找到: 2 7
        break
    if s < target:
        left += 1
    else:
        right -= 1
```

它在这题里：如果数组本来就排好了序，双指针 O(n) 时间、O(1) 空间，比哈希的 O(n) 空间更省。

#### ② 大白话：哈希表这笔买卖什么时候划算

哈希买到的东西很明确：把"回头找 `target - x`"从 O(n) 变成 O(1)，总时间从 O(n²) 降到 O(n)。代价也很明确：多花 O(n) 的内存，还丢掉了顺序。

所以判断标准就两条：**"查一个值"是不是瓶颈**，以及**内存松不松**。两条都满足才该上哈希。

什么时候不该用：数组已经有序（双指针更省）；值域又小又连续（开数组当查找表，常数更小）；内存是硬约束（O(n) 的字典可能就是最后一根稻草）；需要"比 x 大的最小数"这类范围查询（哈希不保留顺序，做不了）。

一句话收尾：哈希是"用空间买常数时间"的工具，不是万能钥匙。

**30 秒回顾**：字典存"值 → 下标"，扫到 `x` 时查 `target - x` 在不在表里；**先查后存**，否则 `[3,3]` 会返回 `[0,0]`。O(n) 时间，O(n) 空间。

**核心代码**：

```python
seen = {}
for i, x in enumerate(nums):
    if target - x in seen:
        return [seen[target - x], i]
    seen[x] = i
```

**换个角度：这笔空间换时间，划不划算？**

- 哈希买到的是什么？把"回头找 `target - x`"的 O(n) 变成 O(1)。总时间从 O(n²) 降到 O(n)，代价是 O(n) 空间。
- 什么时候不该用哈希？
  - 数据已经有序：双指针 O(n) 时间、O(1) 空间，全面优于哈希（力扣 167）。
  - 值域很小且连续（比如全是 `0..1000`）：开数组当查找表，常数比哈希小得多。
  - 内存是硬约束（嵌入式、超大流式数据）：O(n) 的字典可能就是压垮骆驼的那根稻草，这时排序 + 双指针、或者分块处理更现实。
  - 需要顺序 / 最值 / 范围查询：哈希表不保留顺序，也做不了"比 x 大的最小数"，这类需求要用排序数组或平衡树。
- 隐性风险：理论上最坏一次查找是 O(n)（所有 key 冲突）。Python 的 dict 用开放寻址 + 随机化哈希，实际几乎不可能被构造出退化；但聊复杂度时说"均摊 O(1)"比说"O(1)"严谨。
- 一句话总结：哈希表是"用空间买常数时间"的工具，**只有当"查一个值"是瓶颈、且内存不紧张时才划算**。这题正好两条都满足。

## 专题3-5. 和为 K 的子数组（回顾 · 换个角度：前缀和哈希的边界）

> 第一册已精讲：[分册 A · A8](10-分册A-数组字符串滑窗哈希.md)
> 力扣 560 · 前缀和 + 哈希 · Medium

### 精讲（零基础版）

#### ① 这题要用到的东西

**前缀和**

一句话：`pre` 是"从第一个数一直加到我这里"的累计和。任意一段的和不用重新加，两个前缀和相减就是。

生活类比：里程表。想知道"从 A 站到 B 站开了多远"，拿 B 的读数减 A 的读数就行，不用重新跑一遍。

```python
nums = [1, 2, 3]
pre = 0
for x in nums:
    pre += x
    print(pre)      # -> 1 / 3 / 6
```

它在这题里：`sum(i..j) = pre[j] - pre[i-1]`，于是"区间和等于 k"变成"`pre[i-1] = pre[j] - k`"。

**`defaultdict(int)`**（前面 专题3-1 讲过 `defaultdict(list)`）

同一个东西，只是默认值从"空列表"换成了 0。

```python
from collections import defaultdict
count = defaultdict(int)
count[0] = 1
print(count[9])      # -> 0    没存过的键，自动给 0
```

它在这题里：`res += count[prefix - k]` 直接查，不用先判断键在不在，代码短一行、意图也更清楚。

**`count[0] = 1` 为什么不能漏**

一句话：0 代表"空前缀"——那段"从数组第一个数就开始"的子数组，它起点之前什么都没有，前缀和是 0。不先把这一次记上，所有从下标 0 开始的答案都会漏掉。

#### ② 大白话：哈希表什么时候是多余的

哈希在这题干的活是：把"某个前缀和出现过几次"从"再扫一遍数组"变成"查一下表"。O(n²) 变 O(n)，代价是 O(n) 空间。

但它不是必须的。**如果数组全是正数**，窗口和会随着左指针右移单调变小，滑动窗口就能做，O(1) 空间——哈希白买了。负数一出现，滑窗的单调性立刻崩掉，这才轮得到前缀和 + 哈希。

另外要看问题问什么：只要"存不存在"，字典可以退化成集合；要"最长"而不是"几个"，value 从"次数"换成"最早下标"。**哈希只擅长精确命中，不擅长范围统计**——问"和 ≤ k 的区间有多少个"，它就答不上来了，得换排序 + 树状数组。

**30 秒回顾**：`sum(i..j) = pre[j] - pre[i-1]`，于是"区间和为 k"等价于"`pre[i-1] = pre[j] - k`"。字典记"前缀和 → 出现次数"，**`count[0] = 1`** 代表空前缀。O(n) 时间，O(n) 空间。

**核心代码**：

```python
count = defaultdict(int)
count[0] = 1
prefix = res = 0
for x in nums:
    prefix += x
    res += count[prefix - k]
    count[prefix] += 1
return res
```

**换个角度：什么时候这张哈希表是多余的？**

- 数组全是正数：窗口和随 `left` 右移单调减小，滑动窗口就能做，O(1) 空间。负数一出现，滑窗立刻失效——这是判断"该不该用前缀和哈希"的第一道闸。
- 只要"是否存在"而不是"有多少个"：字典可以退化成集合（只存前缀和），省掉计数。
- 要最长而不是计数（力扣 325）：字典的 value 从"次数"换成"最早下标"，其余不变。同一个前缀和结构，value 存什么取决于问题问什么——这是本册最值得记住的一句话。
- 哈希买不到的东西：它回答不了"和 ≤ k 的区间有多少个"（那要排序 + 树状数组 / 归并）。**哈希只擅长"精确命中"，不擅长"范围统计"。**
- 空间账：字典最多存 n+1 个前缀和。n = 2×10⁴ 时毫无压力；但如果是 10⁸ 级别的流式数据，就得考虑分块 + 外部排序，哈希表放不下。
