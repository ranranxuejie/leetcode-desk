## 专题4-1. 最长有效括号（Hard）

> 力扣 32 · 栈存下标 · 基准 -1
> 前置：第一册 [分册 B · B2 有效的括号](11-分册B-栈与单调栈.md)

**一句话**：给一串只有 `(` 和 `)` 的字符串，找出其中"括号完全配好、而且连续"的那一段，最长能有多长。

### 精讲（零基础版）

#### ① 这题要用到的东西

**栈（用 `list` 当栈）**

一句话：栈就是一个**只能从末尾放、也只能从末尾拿**的列表。Python 里不用 import 任何东西，`list` 本身就是栈。

- `stack.append(x)`：往末尾放一个，叫"进栈"
- `stack.pop()`：把末尾那个**拿走**，并且把它还给你，叫"出栈"
- `stack[-1]`：只看一眼末尾，**不拿走**，叫"看栈顶"

生活类比：**一摞盘子**。只能往最上面放，也只能从最上面拿；想拿最底下那只，得先把上面的端走。这叫"后进先出"。

```python
stack = []
stack.append("第1个")
stack.append("第2个")
print(stack[-1])     # -> 第2个   （只看，不拿走）
print(stack.pop())   # -> 第2个   （拿走，并且还给你）
print(stack)         # -> ['第1个']
```

这题里栈存的是"**还没配上对的左括号的位置**"。栈底那个特殊值代表"最后一个配不上的位置"，也就是断点。

**`enumerate`**

一句话：一边遍历，一边把**下标**也递给你。

```python
for i, ch in enumerate("()"):
    print(i, ch)      # -> 0 (  /  1 )
```

等价于 `for i in range(len(s)): ch = s[i]`，但少写一行。这题里下标就是"位置"，答案靠两个下标相减算出来。

**`not stack`（空列表算"假"）**

一句话：Python 里 `[]`、`""`、`0`、`None` 都算"假"，非空的列表算"真"。所以 `if not stack:` 就是"如果栈空了"。

```python
s = []
print(not s)     # -> True
s.append(1)
print(not s)     # -> False
```

这题里它在 `pop()` 之后判一件事：刚才弹掉的到底是"一个配对的左括号"，还是"那个基准"。

#### ② 大白话：这题到底在干什么

最笨的办法：把所有子串都试一遍（大约 n²/2 个），每个都跑一遍括号匹配，总共 n³。n 最大 3 万，这条路直接堵死。

稍好一点的：从每个起点往右扫，记一个"余额"——遇到 `(` 加 1，遇到 `)` 减 1，余额归零时更新长度，余额变负就停。这样是 n²，3 万的平方还是过不去。

笨在哪？**每个起点都要把后面重扫一遍**，同样的字符被数了几十次。

聪明的办法是一趟扫完，关键是想通一件事：**一段有效括号什么时候断？** 就是出现了一个配不上的右括号的时候。这种位置一旦出现，它左边的所有内容就再也不可能和右边连成一段了。

所以只要记住"最后一个配不上的位置"，长度就是 `当前位置 - 那个位置`。

做法：栈里先放一个 `-1` 当作"位置 0 左边一格"这个虚拟断点。之后遇到 `(` 就把它的下标压进去；遇到 `)` 先弹一个出来（弹掉的可能是配对的左括号，也可能就是那个基准），弹完栈空了说明这个右括号自己就是新断点，把它压进去；弹完还有东西，栈顶就是断点，量一下长度。

#### ③ 拿 `")()())"` 走一遍

| i | 字符 | 做了什么 | 栈（底→顶） | 目前最长 |
|---|---|---|---|---|
| 开始 | — | 放基准 -1 | `[-1]` | 0 |
| 0 | `)` | 弹出 -1，栈空 → 压 0（新断点） | `[0]` | 0 |
| 1 | `(` | 压 1 | `[0, 1]` | 0 |
| 2 | `)` | 弹出 1，栈非空 → 2 - 0 = 2 | `[0]` | 2 |
| 3 | `(` | 压 3 | `[0, 3]` | 2 |
| 4 | `)` | 弹出 3，栈非空 → 4 - 0 = 4 | `[0]` | 4 |
| 5 | `)` | 弹出 0，栈空 → 压 5（新断点） | `[5]` | 4 |

所以答案是 4。注意第 5 步：这个 `)` 弹掉的是**断点本身**，说明它自己配不上，于是断点从 0 挪到了 5——这就是"断点会移动"。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `stack = [-1]` | 先放一个虚拟断点，代表"位置 0 左边一格" |
| `best = 0` | 目前找到的最长长度 |
| `for i, ch in enumerate(s)` | 第 i 个字符，字符是 ch |
| `if ch == '(': stack.append(i)` | 左括号：记下它的位置，等一个右括号来配 |
| `else: stack.pop()` | 右括号：无条件先弹一个（不知道弹掉的是谁，先消了再看） |
| `if not stack: stack.append(i)` | 弹完空了 → 弹掉的是基准 → 这个右括号自己就是新断点 |
| `else: best = max(best, i - stack[-1])` | 弹完还有 → 栈顶是断点，从断点后一格到 i 就是一段 |
| `return best` | 扫完就得到答案 |

两个细节：`i - stack[-1]` 后面**不加 1**，因为 `stack[-1]` 是"左边界再往左一格"，`i` 是右边界本身，两头都偏了一格正好抵消；`pop()` 必须无条件执行，不能先判断再弹，因为你并不知道栈里那个是不是配对对象。

### 考什么

- 表面考点：括号匹配，再加上"最长连续子串"。
- 真正考点：**栈不只能判断"配没配上"，还能记录"位置"**。当栈里存的是下标时，两个下标相减就是一段长度；而栈底那个下标，定义了一段有效括号的"左边界再往左一格"。
- 面试官想听到的关键句：
  - "栈里存下标不存括号，因为答案要的是长度，只有下标能相减。"
  - "栈底那个数代表'最后一个没被匹配上的位置'，所以长度是 `i - stack[-1]`，不是 `i - stack[-1] + 1`。"

### 思路是怎么想出来的

- **暴力**：枚举所有子串（O(n²) 个），每个用一遍括号匹配校验（O(n)），总共 O(n³)。n 最大 3×10⁴，这条路直接封死。
- **稍好一点的暴力**：对每个起点往右扫一遍，维护"左括号比右括号多几个"（下面就叫**余额**），余额归零时更新长度，余额变负就停。这是 O(n²)，3×10⁴ 的平方是 9×10⁸，还是过不去。
- **关键观察**：上面那个暴力里，每个起点都要把后面的字符重扫一遍，重复劳动太多。而"余额"这个东西，其实可以用一个栈统一维护——**遇到左括号就记下它的位置，遇到右括号就消掉最近记下的那个**。消掉之后如果还能对上更早的位置，就说明这一段是连着的。
- 但这里有个绕不过去的坎：**消掉之后，这段有效串的起点在哪？** 栈顶只告诉你"还有哪个左括号没配"，不告诉你"从哪儿开始算长度"。
- **破局点**：换个角度想——一段有效括号什么时候"断"？就是出现了一个**配不上的右括号**。比如 `)()` 里第 0 个字符，它前面没有任何左括号可以配。这种位置一旦出现，它左边的所有内容就再也不可能和右边连成一段了。所以只要记住"最后一个配不上的位置"，答案就是 `当前位置 - 那个位置`。
- **于是有**：栈里存下标。初始化 `stack = [-1]`，把 -1 当作"位置 0 左边一格"，也就是虚拟的"最后一个没匹配上的位置"。之后：

  - 遇 `(`：把它的下标压栈（它在等一个右括号）。
  - 遇 `)`：先弹一次栈（弹出的是"和它配对的那个左括号"；如果栈里只剩基准，弹出的就是基准本身）。
    - 弹完栈空了 → 说明这个 `)` 没有配对对象，它就是新的断点，把它的下标压进去。
    - 弹完栈非空 → 栈顶就是这段有效串的左边界再往左一格，长度 = `i - stack[-1]`。

### 为什么"栈底留一个 -1"这件事成立

这是全题最需要想通的地方，我们慢一点，把三种情况都走一遍。

**先看 `s = "()"`。**

| i | 字符 | 做了什么 | 栈（底→顶） | 本次长度 |
|---|---|---|---|---|
| 初始 | | 压入基准 -1 | `[-1]` | — |
| 0 | `(` | 压 0 | `[-1, 0]` | — |
| 1 | `)` | 弹出 0，栈非空 | `[-1]` | 1 - (-1) = 2 |

答案 2。注意这里如果没压 -1：弹出 0 之后栈就空了，`stack[-1]` 直接抛 `IndexError`；就算你特判成"栈空时长度为 0"，也会得到 0 而不是 2。**-1 的作用就是把"空栈"翻译成一个合法的坐标**。

**再看 `s = ")()"`。** 这个例子演示"断点会移动"。

| i | 字符 | 做了什么 | 栈 | 本次长度 |
|---|---|---|---|---|
| 初始 | | | `[-1]` | — |
| 0 | `)` | 弹出 -1，栈空 → 压 0（新断点） | `[0]` | — |
| 1 | `(` | 压 1 | `[0, 1]` | — |
| 2 | `)` | 弹出 1，栈非空 | `[0]` | 2 - 0 = 2 |

答案 2。这里第 0 个字符配不上，于是断点从 -1 变成了 0。后面那段 `()` 的长度是 `2 - 0 = 2`，而不是 `2 - (-1) = 3`——因为下标 0 那个右括号不属于任何有效段。

**再看 `s = "()(()"`。** 这是"连续性"的坑。

| i | 字符 | 做了什么 | 栈 | 本次长度 |
|---|---|---|---|---|
| 初始 | | | `[-1]` | — |
| 0 | `(` | 压 0 | `[-1, 0]` | — |
| 1 | `)` | 弹出 0 | `[-1]` | 1 - (-1) = 2 |
| 2 | `(` | 压 2 | `[-1, 2]` | — |
| 3 | `(` | 压 3 | `[-1, 2, 3]` | — |
| 4 | `)` | 弹出 3 | `[-1, 2]` | 4 - 2 = 2 |

答案 2。第 2 个字符那个左括号始终没配上，它留在栈里当"墙"，所以前后两段 `()` 不会被拼成 4。**这正是"连续"两个字的实现方式：没配上的左括号会挡住左右两边。**

### 代码（Python）

```python
class Solution:
    def longestValidParentheses(self, s: str) -> int:
        stack = [-1]        # 栈底永远放着"最后一个没匹配上的位置"
        best = 0
        for i, ch in enumerate(s):
            if ch == '(':
                stack.append(i)          # 左括号：记下位置，等一个右括号
            else:
                stack.pop()              # 右括号：先消掉一个（可能消掉的是基准）
                if not stack:            # 消完空了 -> 这个右括号配不上，它成为新断点
                    stack.append(i)
                else:                    # 还有基准在 -> 从断点后一格到 i 是有效段
                    best = max(best, i - stack[-1])
        return best
```

**逐段讲解**

- `stack = [-1]` 是地基，不是可选项。它让"栈空"这个状态在坐标轴上有一个位置，后面的 `i - stack[-1]` 才永远算得出来。
- **循环不变量**：每一轮结束后，栈里是一串**递增的下标**。除栈底外，每个下标都是一个"还在等右括号的左括号"；栈底那个下标，是"到目前为止最后一个没被匹配掉的位置"。
- **灵魂是 `pop()` 后面那三行**。`pop()` 必须无条件执行——遇右括号时你并不知道栈里那个是不是配对对象，只能先消一个再看。消完判空，空了说明刚才消掉的是基准，也就是"这个右括号自己就是断点"。
- 为什么是 `i - stack[-1]` 而不是 `i - stack[-1] + 1`：因为 `stack[-1]` 是"左边界再往左一格"，`i` 是右边界本身。两头都偏了一格，正好抵消。

### 复杂度

- 时间 O(n)：每个字符进栈至多一次、出栈至多一次，循环体里没有嵌套扫描。
- 空间 O(n)：最坏情况（`"(((("`）栈里装下全部下标，再加上那个基准。

### 常见误区（★ 最容易丢分的地方）

1. **初始栈写成空 `[]`，不压 -1**。`"()"` 会在 `pop()` 之后 `stack[-1]` 崩掉；就算你加了 `if stack` 保护，长度也算不出来（返回 0）。这题的第一步就决定了后面全部。
2. **`pop()` 之后不判空，直接算长度**。`")"` 会让 `stack[-1]` 抛 `IndexError`。正确动作是"空了就把当前下标压进去"，让它成为新断点。
3. **长度写成 `i - stack[-1] + 1`**。示例 1 `"(()"` 会输出 3（正确答案 2），因为把断点那一格也算进去了。
4. **栈里存字符 `'('` 而不是下标**。能判合法性，但算不出长度。用户笔记里写的"遇 `)` 且栈顶非 `(` 时弹出并计算长度"是**存字符版本**的描述——那个版本只能回答"合不合法"，回答不了"多长"。本题必须存下标，对应到代码里就是"弹完之后栈非空"这个条件。
5. **以为要额外处理"连续"**。连续性不是靠额外判断实现的，是靠"没配上的左括号留在栈里挡路"天然实现的。见上面 `"()(()"` 的走法。

### 面试追问 / 变体

- **要求 O(1) 空间**：有双计数器法——从左往右扫一遍（左计数、右计数，相等时更新长度，右计数超过左计数就双双清零），再从右往左扫一遍。方向反过来扫是为了处理 `"(()"` 这种左括号多出来的情况。面试官问空间时答这个。
- **要求返回具体子串**：把 `best` 换成 `(best_start, best_len)`，更新时一起记下来。
- **改成"最少加几个括号才合法"**（力扣 921、1541）：不需要栈的深度信息，两个计数器就够。
- **DP 解法**：`dp[i]` 表示"以 i 结尾的最长有效长度"，`s[i] == ')'` 时往前找配对位置。写起来比栈绕，但面试官有时会指定这个思路。

### 自测

- 必测用例：
  - `"(()"` → 2（题面示例）
  - `")()())"` → 4（题面示例）
  - `""` → 0（题面示例，空串）
  - `"()(()"` → 2（连续性的坑）
  - `"()(())"` → 6（嵌套）
  - `")("` → 0（两个都配不上）
  - `"()()"` → 4（两段拼起来）
- 30 秒自检：能不能说出"栈存下标、栈底是断点、弹完非空就算 `i - stack[-1]`"这三步？

## 专题4-2. 柱状图中最大的矩形（Hard）

> 力扣 84 · 单调栈 · 两头加哨兵
> 前置：第一册 [分册 B · B1 每日温度](11-分册B-栈与单调栈.md)（单调栈模板）

**一句话**：一排紧挨着的柱子，每根宽都是 1、高不一样，问你能在里面框出的矩形最大面积是多少。

### 精讲（零基础版）

#### ① 这题要用到的东西

**单调栈**

一句话：一个**始终保持"从栈底到栈顶递增"（或递减）**的栈。做法是：新元素进栈之前，先把"破坏这个顺序"的栈顶一个个弹掉。

生活类比：一排人按身高从矮到高站在台阶上。新来一个人比台阶上最高的那位还矮，那就把比他高的都请下来，然后自己站上去。

```python
arr = [2, 1, 3]
st = [0]                       # 栈里放的是下标
for i in range(1, len(arr)):
    while st and arr[st[-1]] > arr[i]:
        print("弹出", st.pop(), "右边来了更矮的", arr[i])
    st.append(i)
print(st)                      # -> [1, 2]
```

输出是 `弹出 0 右边来了更矮的 1`，最后栈里剩 `[1, 2]`，对应高度 `1, 3`，确实是递增的。

这题里栈里存下标，对应的**高度严格递增**。新柱子比栈顶矮，栈顶那根柱子的右边界就确定了，立刻结算它。

**哨兵**

一句话：在数组两头各塞一个"比所有元素都矮"的 0，用来**省掉两个特判**。

生活类比：给一条走廊两头各放一堵墙。你永远走不出边界，也永远会被墙拦住，不用每走一步都问"我是不是到头了"。

```python
h = [0] + [2, 1, 5] + [0]
print(h)        # -> [0, 2, 1, 5, 0]
print(len(h))   # -> 5
```

`[0] + 列表 + [0]` 是 Python 的列表拼接，生成一个新列表。这题里头部那个 0 保证栈永远不空（结算时 `stack[-1]` 一定存在），尾部那个 0 比所有柱子都矮，会把栈里剩下的柱子全部弹出来结算。

#### ② 大白话：这题到底在干什么

先解决"矩形高度从哪来"。假设最大矩形的高度是 h，你把这个矩形往上拉，直到它的上边碰到某根柱子的顶端——这时 h 就等于那根柱子的高度。所以**最优矩形的高度必然是某根柱子的高度**，只需要枚举 n 种可能。

高度定了，宽度就定了：以第 i 根柱子为最矮的那根，矩形能往左伸到"左边第一个比它矮的柱子"的右边一格，往右伸到"右边第一个比它矮的柱子"的左边一格。

于是问题变成：**对每根柱子，求左右两边第一个比它矮的位置**。这就是单调栈的活。

最笨的办法是枚举左右边界，每对再求区间最小值，n 最大 10 万，n² 都嫌多，更别说 n³。

聪明的办法：从左往右扫一遍，维护一个"高度递增"的下标栈。新来的柱子比栈顶矮，说明栈顶那根柱子的右边界找到了（就是现在这根），可以立刻结算它；结算完再跟新的栈顶比，一直比到栈顶不比自己高，再把自己压进去。

每根柱子进栈一次、出栈一次，总共 O(n)。虽然外面有 `for`、里面有 `while`，但内层加起来不会超过 n 次。

#### ③ 拿 `[2, 1, 2]` 走一遍

加哨兵后 `h = [0, 2, 1, 2, 0]`，下标 0…4。

| i | h[i] | 弹出了谁、算了多少 | 栈（底→顶） | 目前最大 |
|---|---|---|---|---|
| 1 | 2 | — | `[0, 1]` | 0 |
| 2 | 1 | 弹 1：高 2，宽 2-0-1=1 → 2 | `[0, 2]` | 2 |
| 3 | 2 | — | `[0, 2, 3]` | 2 |
| 4 | 0 | 弹 3：高 2，宽 4-2-1=1 → 2 | `[0, 2]` | 2 |
| 4 | 0 | 弹 2：高 1，宽 4-0-1=3 → 3 | `[0]` | **3** |
| 4 | 0 | 比完了，压 4 | `[0, 4]` | 3 |

所以答案是 3——整排三根柱子取最矮的那根（高 1）横着铺满，面积 1 × 3 = 3。

注意 i = 4 那一行连着弹了两次：**一次循环里可以结算好几根柱子**，这就是"一口气结算一批"。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `h = [0] + heights + [0]` | 头尾各加一个哨兵 0（原数组下标整体右移一位，不影响答案） |
| `stack = [0]` | 先放头部哨兵的下标；它比谁都矮，永远不会被弹出去 |
| `best = 0` | 目前最大面积 |
| `while h[stack[-1]] > h[i]:` | 栈顶比当前高 → 栈顶那根柱子的右边界确定了 |
| `height = h[stack.pop()]` | 先弹出，拿到"以它为高" |
| `width = i - stack[-1] - 1` | 左边界 = 弹出之后的新栈顶，宽度两头各让一格 |
| `best = max(best, height * width)` | 结算，更新最大值 |
| `stack.append(i)` | 结算干净了，把自己压进去，继续等右边界 |

两个细节：`pop()` 必须在读 `stack[-1]` **之前**，否则读到的是被弹的那根自己，宽度会算错；`while` 用严格大于 `>`，等高时不互相弹，这样后面那根窄的先结算、前面那根宽的后结算，跨过等高柱子的矩形才不会漏。

### 考什么

- 表面考点：在一堆高度里找最大矩形面积。
- 真正考点：**单调栈求"每个位置左右两边第一个比它矮的位置"**。这是"下一个更小元素"的左右合体版。
- 面试官想听到的关键句：
  - "任何最大矩形，它的高度一定等于某根柱子的高度——因为可以一直往上顶，顶到某根柱子为止。所以只要对每根柱子问一次'以我为高，最宽能多宽'。"
  - "栈顶被弹出的那一刻，就是它的右边界被确定的那一刻；而它的左边界，是弹出它之后的新栈顶。"

### 思路是怎么想出来的

- **暴力**：枚举左右边界（O(n²) 对），每对求区间最小高度。朴素做法是 O(n³)，边扫边维护最小值能压到 O(n²)。n 最大 10⁵，10¹⁰ 次运算，没戏。
- **关键观察**：先解决"矩形高度从哪来"。假设最大矩形的高度是 h，把矩形往上拉，直到它的上边碰到某根柱子的顶端——这时 h 就等于那根柱子的高度。所以**最优矩形的高度必然是某个 `heights[i]`**，只需要枚举 n 种高度。
- 高度定了，宽度就定了：以第 i 根柱子为最矮的那根，矩形能往左延伸到"左边第一个比它矮的柱子"的右边一格，往右延伸到"右边第一个比它矮的柱子"的左边一格。所以问题变成：**对每个 i，求左右两边第一个更矮的位置**。
- **于是有**：从左往右扫，维护一个下标栈，**栈内对应的高度严格递增**。新来的柱子 i 比栈顶矮时，栈顶那根柱子的右边界就确定了（就是 i），可以立刻结算它；结算完继续比新的栈顶。等栈顶不再比 i 高，把 i 压进去。
- **哨兵**：在数组头尾各加一个 0，得到 `h = [0] + heights + [0]`。
  - 头部 0：保证栈永远不为空，结算时 `stack[-1]` 一定存在，不用写 `if not stack` 分支。
  - 尾部 0：它比所有柱子都矮，会把栈里剩下的柱子全部弹出来结算。没有它，遇到 `[1,2,3,4,5]` 这种一路递增的输入，循环结束时栈还是满的，那些柱子一次都结算不到，答案会是 0。

### 宽度公式为什么是 `i - stack[-1] - 1`

被弹出的是下标 `j`，它的高度是 `h[j]`。

- 右边界：i 是右边第一个比 `h[j]` 矮的柱子，所以矩形最右只能到 `i - 1`。
- 左边界：弹出 j 之后的新栈顶 `stack[-1]`，是左边第一个比 `h[j]` 矮的柱子，所以矩形最左只能到 `stack[-1] + 1`。
- 宽度 = `(i - 1) - (stack[-1] + 1) + 1 = i - stack[-1] - 1`。

**注意顺序**：必须先 `pop()` 拿到高度，此时 `stack[-1]` 才是左边界。如果先读 `stack[-1]` 再 pop，读到的是 j 自己，宽度会变成 `i - j - 1`，全错。

### 走一遍示例

`heights = [2,1,5,6,2,3]`，加哨兵后 `h = [0, 2, 1, 5, 6, 2, 3, 0]`，下标 0…7。

| i | h[i] | 弹出了谁、算了多少 | 栈（底→顶） | 当前最大 |
|---|---|---|---|---|
| 1 | 2 | — | `[0, 1]` | 0 |
| 2 | 1 | 弹 1：高 2，宽 2-0-1=1 → 2 | `[0, 2]` | 2 |
| 3 | 5 | — | `[0, 2, 3]` | 2 |
| 4 | 6 | — | `[0, 2, 3, 4]` | 2 |
| 5 | 2 | 弹 4：高 6，宽 5-3-1=1 → 6 | `[0, 2, 3]` | 6 |
| 5 | 2 | 弹 3：高 5，宽 5-2-1=2 → 10 | `[0, 2, 5]` | **10** |
| 6 | 3 | — | `[0, 2, 5, 6]` | 10 |
| 7 | 0 | 弹 6：高 3，宽 7-5-1=1 → 3 | `[0, 2, 5]` | 10 |
| 7 | 0 | 弹 5：高 2，宽 7-2-1=4 → 8 | `[0, 2]` | 10 |
| 7 | 0 | 弹 2：高 1，宽 7-0-1=6 → 6 | `[0, 7]` | 10 |

答案 10。表里 `i = 5` 弹出下标 3 的那一步（高 5、宽 2）就是题面图里那块红色矩形：高度 5 来自 `heights[3]`，宽度 2 覆盖下标 3、4 两根柱子。

### 代码（Python）

```python
from typing import List   # 力扣已预导入这行，本地跑时要加上

class Solution:
    def largestRectangleArea(self, heights: List[int]) -> int:
        h = [0] + heights + [0]     # 头尾各加一个哨兵 0
        stack = [0]                 # 存下标；栈内对应高度严格递增
        best = 0
        for i in range(1, len(h)):
            while h[stack[-1]] > h[i]:          # 栈顶比当前高 -> 栈顶的右边界确定了
                height = h[stack.pop()]         # 先弹出，拿到"以它为高"
                width = i - stack[-1] - 1       # 左边界 = 弹出后的新栈顶
                best = max(best, height * width)
            stack.append(i)
        return best
```

**逐段讲解**

- `h = [0] + heights + [0]` 之后，原数组的下标整体右移了一位。这个偏移对答案没有影响，因为我们只关心"下标差"，不关心绝对下标。
- `stack = [0]` 一开始就放头部哨兵的下标。`h[0] = 0` 不大于任何一根柱子（题目高度非负），而弹栈的条件是**严格大于**，所以它永远不会被弹出去，栈也就不可能空——`while` 里的 `stack[-1]` 绝对安全。
- **循环不变量**：每一轮结束后，栈里存的是**递增的下标**，对应的 `h` 值**严格递增**。也就是说，栈里每一根柱子，都还在等"右边第一个比它矮的"。
- **灵魂是那三行**：`height = h[stack.pop()]` 取高度，`width = i - stack[-1] - 1` 取宽度。这两句的顺序不能换，理由见上一节。
- `while` 用严格大于 `>`：高度相等的柱子不会互相弹，后一根留在栈里。等到它们共同的右边界出现时，先弹后一根（宽度窄），再弹前一根（宽度宽，能把后一根一起覆盖）。这样"跨过等高柱子"的那种矩形也不会漏。

### 复杂度

- 时间 O(n)：每个下标进栈一次、出栈至多一次。虽然有 `for` 套 `while`，但内层总执行次数不超过 n，这就是第一册分册 B 的 0.3 节讲的**均摊分析**。
- 空间 O(n)：栈最坏装下所有下标（数组严格递增时），哨兵数组本身也是 O(n)。

### 常见误区（★ 最容易丢分的地方）

1. **宽度少减 1**：写成 `i - stack[-1]`。示例 1 会输出 15 而不是 10——因为把右边界那根更矮的柱子也算进宽度了。
2. **先读 `stack[-1]` 再 `pop()`**。读到的 `stack[-1]` 就是 j 自己，宽度变成 `i - j - 1`，`[2,1,5,6,2,3]` 的最大值会掉到 5。记住：**先弹出、后看栈顶**。
3. **不加尾部哨兵**。`[1,2,3,4,5]` 这种递增数组，循环结束时栈里还压着 5 个下标，一个都没结算，返回 0。这是最隐蔽的一类错——示例 1 能过，换个用例就崩。
4. **栈里存高度而不是下标**。高度能比大小，但算不出宽度。
5. **把 `best` 的更新写进 `if` 分支**。`best = max(best, ...)` 必须每次结算都执行，漏一次就可能漏掉最优解。
6. **以为"最大矩形一定贴着某根柱子的顶端"需要证明才能用**。它就是这题的题眼，但面试时一句话就够："矩形往上拉，直到碰到某根柱子为止，面积只会变大不会变小。"

### 面试追问 / 变体

- **最大矩形（力扣 85）**：二维版本。逐行把"这一列往上连续有多少个 1"当成柱高，每一行套一次本题，取最大。这是 84 最经典的延伸。
- **接雨水（力扣 42）**：同一套单调栈，但结算的不是面积而是"凹槽里的水量"，宽度乘的是"左右两边较矮者与槽底的高度差"。
- **只要"每个柱子左边第一个更矮"**：正着扫一遍；只要右边：反着扫一遍。本题是一次遍历同时拿到两边。
- **要求返回矩形的位置**：结算时把 `(左, 右, 高)` 一起记下来。

### 自测

- 必测用例：
  - `[2,1,5,6,2,3]` → 10（题面示例）
  - `[2,4]` → 4（题面示例）
  - `[1]` → 1（单根）
  - `[0]` → 0（高度为 0）
  - `[2,2]` → 4（等高，验证 `>` 不互相弹）
  - `[6,5,4,3,2,1]` → 12（严格递减，每次只弹一根）
  - `[1,2,3,4,5]` → 9（严格递增，全靠尾部哨兵收尾）
  - `[0,0,0]` → 0（全 0）

## 专题4-3. 最小栈（Medium）

> 力扣 155 · 设计题 · 辅助栈
> 前置：第一册 [分册 B · 0.1 栈是什么](11-分册B-栈与单调栈.md)

**一句话**：让你实现一个栈，除了正常的 `push` / `pop` / `top`，还要能在 O(1) 时间里报出"现在栈里最小的那个数"。

### 精讲（零基础版）

#### ① 这题要用到的东西

**类和 `self`**

一句话：`class` 是一张**模板**，`self` 是用这张模板造出来的那个**具体东西**；`self.xxx` 就是"我这个东西自己的 xxx"。

生活类比：`class` 是户型图，`self` 是具体那一套房。`self.stack` 是"我家那个柜子"——每套房各有一个，互不相干。

```python
class Box:
    def __init__(self):
        self.items = []          # 每造一个 Box，就新开一个空列表

    def push(self, x):
        self.items.append(x)

    def top(self):
        return self.items[-1]

b = Box()
b.push(7)
print(b.top())    # -> 7
```

`__init__` 是"对象造出来时自动跑一次"的函数，用来做初始化。这题里它建两个列表：主栈和辅助栈。注意方法里的第一个参数永远写 `self`，调用时**不用传**——`b.push(7)` 会自动把 `b` 塞进 `self`。

**辅助栈**

一句话：为了能随时回答"当前最小值是多少"，**再开一个栈，专门记录每一步的历史最小值**，两个栈同进同出。

生活类比：记账。你不仅记"现在花了多少"，还每一步都抄一份"到目前为止最少花过多少"。回头翻账本，任何一个时刻的"最少"都在那一页上。

```python
main, aux = [], []
for v in [4, 2, 3]:
    main.append(v)
    aux.append(v if not aux else min(v, aux[-1]))
print(main)   # -> [4, 2, 3]
print(aux)    # -> [4, 2, 2]
```

`min(a, b)` 取两个里小的那个。这题里 `aux[-1]` 就是 `getMin()` 要返回的答案，一次索引，O(1)。

**类型标注 `-> None`**（一句话）：表示这个函数不返回值，只改自己内部的状态。`val: int` 表示"参数应该是整数"。它们只是给人看的提示，不写也能跑。

#### ② 大白话：这题到底在干什么

最笨的办法：`getMin` 的时候现算一遍 `min(self.stack)`。功能对，但每次 O(n)，题面说 `getMin` 最多调 3 万次，会超时。

那用一个变量存最小值呢？看起来很聪明，其实有个致命问题。你走一遍：

`push(3)` 时最小值是 3；`push(1)` 之后最小值变成 1；再 `pop()` 一次把 1 弹掉——可变量里还是 1，而栈里只剩 3 了。**变量被覆盖之后，原来那个 3 就再也找不回来了**。

问题出在"覆盖"上。`pop` 是后进先出，它撤销的永远是"最近一次 push"，所以"上一个最小值"天然是可以用一个栈存起来的——**栈的后进先出，正好对上 push/pop 的撤销顺序**。

于是：每次 `push` 时，除了往主栈压值，再往辅助栈压一个"**压完之后的最小值**"（新值更小就是新值，否则沿用辅助栈栈顶）。`pop` 时两个栈一起弹。

这样辅助栈的栈顶永远等于当前主栈的最小值，而且两个栈**长度永远相等**，弹的时候不需要任何判断。

#### ③ 拿 `push(4), push(2), push(3)` 走一遍

| 操作 | 主栈 | 辅助栈（历史最小值） | 返回 |
|---|---|---|---|
| `push(4)` | `[4]` | `[4]` | — |
| `push(2)` | `[4, 2]` | `[4, 2]` | — |
| `push(3)` | `[4, 2, 3]` | `[4, 2, 2]` | — |
| `getMin()` | | | 2 |
| `pop()` | `[4, 2]` | `[4, 2]` | — |
| `pop()` | `[4]` | `[4]` | — |
| `getMin()` | | | 4 |

注意 `push(3)` 那一行：3 不比 2 小，所以辅助栈压的是**上一个最小值 2**，不是 3。

再看最后两行：连着弹掉 3 和 2 之后，辅助栈栈顶自动变回 4。**恢复上一个最小值不需要计算，只需要弹一下**——这就是"可回退"。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `self.stack = []` | 主栈：正常存值 |
| `self.min_stack = []` | 辅助栈：和主栈同长，存"压到这里时的最小值" |
| `self.stack.append(val)` | 值照常进主栈 |
| `if not self.min_stack or val <= self.min_stack[-1]:` | 辅助栈还是空的（第一次），或者新值更小 → 最小值要更新 |
| `self.min_stack.append(val)` | 历史最小值换成新值 |
| `else: self.min_stack.append(self.min_stack[-1])` | 否则沿用上一个最小值，**也要压**，保证两个栈同长 |
| `self.stack.pop()` 与 `self.min_stack.pop()` | 两个栈无条件一起弹，不用判断 |
| `return self.stack[-1]` | `top` 就是看主栈栈顶 |
| `return self.min_stack[-1]` | `getMin` 就是看辅助栈栈顶 |

### 考什么

- 表面考点：设计一个类，五个方法全部 O(1)。
- 真正考点：**用空间换"可回退的历史"**。最小值不是一个固定的数，它随 push 变小、随 pop 变大，所以必须把"每一步的最小值"都存下来。
- 面试官想听到的关键句："最小值是一条随时间变化的序列，不是一个数。辅助栈存的就是这条序列，所以它和主栈永远同长、同步进出。"

### 思路是怎么想出来的

- **最笨**：`getMin` 的时候现算 `min(self.stack)`，O(n)。题面说 `getMin` 最多被调用 3×10⁴ 次，最坏 9×10⁸ 次比较，超时。
- **一个变量**：`self.min_val`，每次 `push` 时更新 `self.min_val = min(self.min_val, val)`。看起来 O(1) 就解决了。**但这儿有个致命问题**，我们走一遍：

  ```
  push(3)   stack=[3]        min_val=3
  push(1)   stack=[3,1]      min_val=1
  push(2)   stack=[3,1,2]    min_val=1
  pop()     stack=[3,1]      min_val=1    ← 弹掉的是 2，没影响
  pop()     stack=[3]        min_val=1    ← 弹掉的是 1，可是 min_val 还是 1！
  getMin()  → 1             ← 错，栈里只剩 3，答案应该是 3
  ```

  问题出在**覆盖**：`min_val` 被 1 覆盖之后，原来那个 3 就再也找不回来了。而 `pop` 是不可逆的——你没法"反算"出上一个最小值。

- **关键观察**：既然 `pop` 需要"退回上一个状态"，而 `pop` 本身是后进先出，那么"上一个状态"天然可以用一个栈来存。每次 `push` 时，除了把值压进主栈，再往辅助栈压一个"**压完之后的最小值**"；`pop` 时两个栈一起弹。
- **于是有**：辅助栈的栈顶，永远等于当前主栈的最小值。两个栈长度永远相等，所以弹的时候不需要任何判断。

### 走一遍题面示例

| 操作 | 主栈 | 辅助栈（同步的历史最小值） | 返回 |
|---|---|---|---|
| `push(-2)` | `[-2]` | `[-2]` | — |
| `push(0)` | `[-2, 0]` | `[-2, -2]` | — |
| `push(-3)` | `[-2, 0, -3]` | `[-2, -2, -3]` | — |
| `getMin()` | | | -3 |
| `pop()` | `[-2, 0]` | `[-2, -2]` | — |
| `top()` | | | 0 |
| `getMin()` | | | -2 |

注意 `pop()` 那一行：弹掉 -3 之后，辅助栈的栈顶自动变回 -2。这就是"可回退"——**恢复上一个最小值不需要计算，只需要弹一下**。

### 代码（Python）

```python
class MinStack:

    def __init__(self):
        self.stack = []          # 主栈：正常存值
        self.min_stack = []      # 辅助栈：与主栈同长，存"压到这里时的最小值"

    def push(self, val: int) -> None:
        self.stack.append(val)
        if not self.min_stack or val <= self.min_stack[-1]:
            self.min_stack.append(val)          # 新值更小，历史最小值更新
        else:
            self.min_stack.append(self.min_stack[-1])   # 否则沿用上一个

    def pop(self) -> None:
        self.stack.pop()
        self.min_stack.pop()     # 同长，无条件一起弹

    def top(self) -> int:
        return self.stack[-1]

    def getMin(self) -> int:
        return self.min_stack[-1]
```

**逐段讲解**

- 两个栈**长度永远相等**，这是这套写法最大的好处：`pop` 里不用任何 `if`，不会出现"该不该弹辅助栈"的判断错误。
- `push` 里那句 `if / else` 的本质是 `min_stack.append(min(val, min_stack[-1]))`，只是把"第一次"单独拎出来了（第一次没有 `min_stack[-1]`）。
- 用 `<=` 还是 `<` 在这里**无所谓**：因为每个 `push` 都会往辅助栈压一个值（压的是 `val` 或上一个最小值），两个栈长度永远一致，重复的最小值不会造成错位。真正需要小心的是另一种"只在更小时才压"的写法，见误区 3、4。
- `getMin` 就是取辅助栈栈顶，一次索引，O(1)。

### 复杂度

- 时间：五个方法全部 O(1)，没有任何循环。
- 空间：O(n)。最坏情况（一路递减）辅助栈装 n 个不同的最小值；一路递增时辅助栈里全是重复的同一个数，但长度仍是 n。

### 常见误区（★ 最容易丢分的地方）

1. **只用一个变量存 min**。这就是上面走过的那条路，`pop` 掉当前最小值后无法恢复。**"pop 会撤销一次 push"是这题唯一的关键，凡是不可撤销的状态都不能只存一份。**
2. **`getMin` 里现算 `min(self.stack)`**。功能对，但 O(n)，3×10⁴ 次调用会超时。题面明确要求"常数时间"。
3. **辅助栈"只在更小时才压"，但 `pop` 里无条件弹**。两个栈长度不同步：`push(5), push(3), push(4)` 之后主栈长 3、辅助栈长 2，第一次 `pop` 正常，第二次 `pop` 辅助栈就空了，`getMin` 崩。
4. **辅助栈"只在更小时才压"，`pop` 里用 `==` 判断，但 `push` 用的是 `<`**。这是最阴的一个：`push(5), push(5)` 时辅助栈只有 `[5]`（因为 5 不比 5 小），`pop` 一次弹掉主栈的 5，`5 == min_stack[-1]` 成立，辅助栈也被弹空，`getMin` 崩。要么 `push` 用 `<=`，要么改成上面那种"每次必压"的写法。
5. **`__init__` 里忘了初始化辅助栈**。力扣会先调 `__init__` 再调方法，AttributeError 一眼能看出来，但紧张时真的会漏。

### 面试追问 / 变体

- **要求 O(1) 空间**：辅助栈不存值，存**差值**。压 `val - min_val`，`pop` 时如果差值是负的，说明弹掉的是最小值，用 `min_val - 差值` 反推出上一个最小值。这就是用户笔记里写的"一个变量 + 栈存差值"。代价是可读性差、还要处理整数溢出（Python 无所谓，别的语言要小心）。
- **改成最大栈**：所有比较方向反过来。
- **改成"队列 + 求最小值"**：辅助栈不够用（队列是先进先出，最小值的历史不是栈式的），要用单调队列。
- **要求 `getMin` 同时返回"最小值第一次出现的下标"**：辅助栈改存 `(值, 下标)`。

### 自测

- 必测用例（题面调用序列）：`push(-2), push(0), push(-3), getMin()= -3, pop(), top()= 0, getMin()= -2`
- 边界：
  - 最小值重复出现：`push(5), push(5), push(3), getMin()=3, pop(), getMin()=5, pop(), getMin()=5, top()=5`
  - 单元素：`push(0), getMin()=0, top()=0, pop()`
  - 整数边界：`push(-2147483648), push(2147483647), getMin()=-2147483648, pop(), getMin()=-2147483648`
- 30 秒自检：能不能说出"辅助栈与主栈同长、每次压入当前最小值、弹的时候一起弹"这三步？

## 专题4-4. 基本计算器（Hard）

> 力扣 224 · 栈存"括号外的现场" · 只有加减和括号
> 前置：第一册 [分册 B · B3 基本计算器 II](11-分册B-栈与单调栈.md)

**一句话**：给一个只含非负整数、`+`、`-`、括号和空格的表达式字符串，算出结果，不许用 `eval`。

### 精讲（零基础版）

#### ① 这题要用到的东西

**用栈存"现场"**

一句话：进括号时，把"外面算到哪了"和"括号前面是什么符号"**压进栈里存着**；出括号时再弹出来，接着算。

生活类比：你正在算账，突然要接个电话。你把"算到第几笔了"和"这账是收入还是支出"写在便签上，压到一摞便签里；接完电话抽出来，接着算。**电话里聊的事和账本互不干扰**，因为账本已经被收起来了。

```python
stack = []
result = 10
stack.append(result)      # 存现场
result = 0                # 换一本新账本
result += 3
result += stack.pop()     # 取回现场
print(result)             # -> 13
```

这题里压的是两样东西：`result`（括号外算到多少）和 `sign`（括号前是加还是减）。

**`isdigit()` 和 `int(ch)`**

一句话：`ch.isdigit()` 问"这个字符是不是 0 到 9"，`int(ch)` 把字符变成数字。

```python
print("7".isdigit())    # -> True
print("-".isdigit())    # -> False
print(" ".isdigit())    # -> False
print(int("0") + 5)     # -> 5
```

为什么需要它：`int('-')` 会直接报错，`int(' ')` 也一样。所以必须先判断"是不是数字"，把符号和空格挡在外面。

**多位数累加**

一句话：读到一位数字就 `num = num * 10 + 这一位`，数字就一位一位接起来了。

```python
num = 0
for ch in "123":
    num = num * 10 + int(ch)
    print(num)      # -> 1 / 12 / 123
```

这题里 `num` 是"正在攒的那个数"。不能靠 `split` 拆，因为数字和符号可能紧贴着，比如 `"1+1"` 拆出来会是 `['1', '+', '1']`，但 `"12+3"` 就未必了，还是逐字符扫最稳。

**`sign` 存 `+1` / `-1` 而不是 `'+'` / `'-'`**

一句话：存成数字就能直接乘，`result += sign * num` 一行同时处理加和减，不用写两个分支。

#### ② 大白话：这题到底在干什么

先想没有括号的情况。只有加减时，一个 `result` 从左往右累加就够了，连栈都不用：`1 - 2 + 3` 就是 `((1-2)+3)`，加法天然从左往右结合。

那括号带来了什么？看 `1 - (2 + 3)`。如果硬按从左往右算，你会先算 `1 - 2 = -1`，再 `-1 + 3 = 2`——错了，正确是 -4。

括号的作用是：**把里面的部分整体算完，再带着括号前的符号参与外面的计算**。

关键观察：`1 - (2 + 3)` 其实等价于 `1 + (-1) × (2 + 3)`。也就是说，括号里那段的算法**跟外面一模一样**，只是整体要乘一个符号，而这个符号就是紧挨着 `(` 的那个运算符。

所以要做的只有两件事。进括号时，把外面的 `result` 和括号前的 `sign` 压进栈，然后把 `result` 清零、`sign` 置正，安心算括号里面。出括号时，括号里的 `result` 已经算完了，乘上存下来的 `sign`、加上存下来的外层 `result`。

注意压栈顺序：**先压 `result`、再压 `sign`**，因为弹的时候要先拿符号去乘、再拿外层结果去加，后进先出正好对上。

#### ③ 拿 `"2-(1+2)"` 走一遍

| i | 字符 | 做了什么 | 栈（底→顶） | result / sign / num |
|---|---|---|---|---|
| 0 | `2` | 攒数字 | `[]` | 0 / +1 / 2 |
| 1 | `-` | 结算 2，记住减号 | `[]` | 2 / -1 / 0 |
| 2 | `(` | 压 result=2、压 sign=-1，现场清零 | `[2, -1]` | 0 / +1 / 0 |
| 3 | `1` | 攒数字 | `[2, -1]` | 0 / +1 / 1 |
| 4 | `+` | 结算 1 | `[2, -1]` | 1 / +1 / 0 |
| 5 | `2` | 攒数字 | `[2, -1]` | 1 / +1 / 2 |
| 6 | `)` | 先结算 2 → 3；乘 -1 → -3；加外层 2 → -1 | `[]` | -1 / +1 / 0 |

循环结束后还要补一句 `result + sign * num`（此时 num 是 0，等于加 0），答案 -1。

看第 6 步那三下：**先结算括号里最后一个数、再乘符号、最后加外层**，三步的顺序就是"把整个括号当成一个数"。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `stack = []` | 存"括号外的现场"，先压 result 再压 sign |
| `result = 0` | 当前这一层的累加结果 |
| `num = 0` | 正在攒的数字（可能是多位数） |
| `sign = 1` | 上一个运算符，用 +1 / -1 表示 |
| `num = num * 10 + int(ch)` | 数字一位一位接起来 |
| `result += sign * num` 与 `num = 0` | 结算上一个数，然后把 num 清空准备攒下一个 |
| `sign = 1 if ch == '+' else -1` | 记住这个符号，等下一个数 |
| `stack.append(result)` 与 `stack.append(sign)` | 进括号：把现场存起来 |
| `result = 0` 与 `sign = 1` | 开新账本：括号里从 0 开始，第一个数默认是正的 |
| `result *= stack.pop()` | 出括号：先乘上括号前的符号 |
| `result += stack.pop()` | 再加上括号外算到哪了 |
| `return result + sign * num` | 收尾：最后一个数还没有运算符来触发结算 |

### 考什么

- 表面考点：字符串解析 + 表达式求值。
- 真正考点：**括号是一个"暂停当前计算、把现场存起来"的信号**。栈里存的不是数字，是"进括号之前算到哪了"加上"紧挨着这个括号的符号"。
- 面试官想听到的关键句：
  - "括号前的那个符号，是括号里每一个数的符号。所以进括号时把它压栈，出括号时再乘回去。"
  - "括号里的算法和括号外**完全一样**，只是初始值从 0 开始、初始符号是正号。"

### 思路是怎么想出来的

- **先想没有括号的情况**：只有加减、没有括号，一个 `result` 从左往右累加就够了，连栈都不需要。`1 - 2 + 3` 就是 `((1-2)+3)`，加法天然满足从左往右结合。
- **再看括号带来了什么**：`1 - (2 + 3)`。如果硬按从左往右算，你会先把 `1 - 2` 算成 -1，然后 `-1 + 3 = 2`，错了（正确是 -4）。括号的作用是**把里面的部分整体算完，再带着括号前的符号参与外面的计算**。
- **关键观察**：`1 - (2 + 3)` 等价于 `1 + (-1) × (2 + 3)`。也就是说，括号里面那段的算法，跟外面一模一样，只是**整体要乘一个符号**。而"这个符号"就是紧挨着 `(` 的那个运算符。
- 所以要做的只有两件事：进括号时，把"外面的 result"和"括号前的符号"存起来，然后把 result 清零、符号置正，安心算括号里面；出括号时，括号里的 result 已经算完了，乘上存下来的符号、加上存下来的外层 result。
- **于是有**：一个栈存"现场"（result 和 sign），一个 `num` 攒当前数字，一个 `sign` 记上一个运算符（只取 +1 / -1）。
- **为什么不用递归**：递归写法（遇到 `(` 就递归求值、遇到 `)` 就返回）和这个栈写法是同一件事——递归用的是函数调用栈，我们用的是显式的 list。面试时两种都能讲，显式栈更好控制。

### 走一遍 `"1-(2+3)"`

| i | 字符 | 做了什么 | 栈（底→顶） | result | sign | num |
|---|---|---|---|---|---|---|
| 0 | `1` | 攒数字 | `[]` | 0 | +1 | 1 |
| 1 | `-` | 结算 1，更新 sign | `[]` | 1 | -1 | 0 |
| 2 | `(` | 压 result=1，压 sign=-1，现场清空 | `[1, -1]` | 0 | +1 | 0 |
| 3 | `2` | 攒数字 | `[1, -1]` | 0 | +1 | 2 |
| 4 | `+` | 结算 2 | `[1, -1]` | 2 | +1 | 0 |
| 5 | `3` | 攒数字 | `[1, -1]` | 2 | +1 | 3 |
| 6 | `)` | 先结算 3 → result=5；再弹出符号 -1 乘上去 → -5；再弹出外层 1 加上去 → -4 | `[]` | -4 | +1 | 0 |

循环结束还要补一句 `result + sign * num`（此时 num=0，加了个 0），结果 -4。

**注意栈的压入顺序**：先压 `result`、再压 `sign`。因为弹的时候要"先拿符号乘、再拿外层 result 加"，后进先出正好对上。**压入顺序永远是弹出顺序的倒序**——这是所有"用栈保存现场"的通用规律。

### 代码（Python）

```python
class Solution:
    def calculate(self, s: str) -> int:
        stack = []          # 存"括号外的现场"：先压 result，再压 sign
        result = 0          # 当前这一层的累加结果
        num = 0             # 正在攒的数字，可能是多位数
        sign = 1            # 上一个运算符：+1 或 -1

        for ch in s:
            if ch.isdigit():
                num = num * 10 + int(ch)        # 多位数：逐位累加
            elif ch == '+' or ch == '-':
                result += sign * num            # 结算上一个数
                num = 0
                sign = 1 if ch == '+' else -1   # 记住这个符号，等下一个数
            elif ch == '(':
                stack.append(result)            # 存：括号外算到哪了
                stack.append(sign)              # 存：括号前是什么符号
                result = 0                      # 括号里从 0 开始算
                sign = 1                        # 括号里第一个数默认是正的
            elif ch == ')':
                result += sign * num            # 先把括号里最后一个数结算掉
                num = 0
                result *= stack.pop()           # 乘上括号前的符号
                result += stack.pop()           # 加上括号外的 result
            # ch 是空格时什么都不做

        return result + sign * num              # 收尾：最后一个数还没被结算
```

**逐段讲解**

- `num = num * 10 + int(ch)` 是"处理多位数"的全部秘密：读到 `1`、`2`、`3`，num 依次是 1、12、123。不能靠 `split`，因为数字和符号可能贴着。
- `sign` 存 1 / -1 而不是 `'+'` / `'-'`，是为了能直接乘——`result += sign * num` 一行搞定加减。
- **遇 `+` / `-` 那一段，顺序不能反**：先结算**上一个**数（用旧的 sign），再更新 sign。反过来会用到当前符号，`1-2` 会变成 `-1-2`。
- **遇 `(` 时不用结算 `num`**，因为题面保证 `(` 前面要么是运算符、要么是开头（不会出现 `2(` 这种写法），此时 `num` 一定是 0。
- **遇 `)` 那三行是灵魂**：第一行把括号里最后一个数结算掉（不然 `(2+3)` 里的 3 会丢），第二行乘符号，第三行加外层。三步的顺序就是"把括号整体当成一个数"。
- **循环外那句 `result + sign * num`** 不能省。`"1 + 1"` 扫完循环时最后一个 1 还躺在 `num` 里，没有运算符来触发结算。这是 227 里"末尾补一个 `+`"的等价写法。

### 复杂度

- 时间 O(n)：每个字符扫一次，进出栈都是常数次。
- 空间 O(n)：栈的深度等于括号嵌套层数，最坏 n/2 层。

### 常见误区（★ 最容易丢分的地方）

1. **遇 `(` 忘了把 `result` 清零**。`"2+(3+4)"` 会算成 11（正确答案 9）：括号里的 3、4 加到了外面那个 2 身上，然后整个 9 又被加了一次。进括号 = 开一个新账本，旧账本要收进栈里。
2. **压栈顺序写反（先 sign 后 result），弹的时候也跟着反**。看起来"对称"，但 `result *= stack.pop()` 会拿外层 result 去乘，`1-(2+3)` 会算出 4。**先压 result、后压 sign；弹的时候先 sign、后 result。**
3. **遇 `)` 时忘了先结算 `num`**。`"1-(2+3)"` 会得到 2（正确答案 -4）——那个 3 一直留在 `num` 里，最后按**外面**的符号被加了出去。
4. **循环外漏了 `+ sign * num`**。`"1 + 1"` 返回 1，`"0"` 返回 0（这个碰巧对），示例 1 直接错。
5. **把"结算"和"更新 sign"塞进 `if num != 0`**。看 `"-(2+3)"`：`-` 前面是开头，`num` 是 0，如果这时跳过整个分支，`sign` 就不会变成 -1，结果算成 +5。正确做法是无条件 `result += sign * num`（加 0 无害），再更新 sign。
6. **忘了跳过空格**。`int(' ')` 会抛异常。`ch.isdigit()` 已经把它挡在第一个分支外，但如果你写成 `if ch in '+-()'` 之外全当数字处理，就会炸。
7. **想用 `eval`**。题面明确禁止，面试官也会直接判不合格。

### 面试追问 / 变体

- **加上乘除（力扣 227）**：优先级从一级变两级，本题的"一个 result 累加"就不够了，需要像 227 那样用栈存加项，或者上"双栈 + 优先级表"。
- **同时支持 `+ - * /` 和括号**：标准做法是数字栈 + 符号栈，遇运算符时比较优先级决定"先算还是先压"；也可以写递归下降。
- **支持一元正号 `+1`、`+(2+3)`**：题面说不出现，但上面的代码其实能正确处理（`+` 时 `num` 为 0，加 0 不改变 result）。
- **要求处理非法表达式**：加一个"括号计数"和"运算符位置检查"，遇到问题抛异常。

### 自测

- 必测用例：
  - `"1 + 1"` → 2（题面示例）
  - `" 2-1 + 2 "` → 3（题面示例，含空格）
  - `"(1+(4+5+2)-3)+(6+8)"` → 23（题面示例，嵌套 + 并列）
  - `"0"` → 0（单个数）
  - `"1-(-2)"` → 3（括号里带一元负号）
  - `"-(2+3)"` → -5（开头就是负号 + 括号）
  - `"2-(5-6)"` → 3（括号里算出负数）
  - `"(1)"` → 1（括号里只有一个数）
  - `"2147483647"` → 2147483647（32 位边界）
- 30 秒自检：能不能说出"遇 `(` 压 result 和 sign、遇 `)` 弹出来乘和加、循环外补最后一个数"这三步？

## 专题4-5. 有效的括号（回顾）

> 第一册已精讲：[分册 B · B2](11-分册B-栈与单调栈.md)
> 力扣 20 · 栈 · Easy

**30 秒回顾**：左括号入栈，右括号来的时候只认栈顶——栈空或者类型不对就直接 false，对上了就弹掉。扫完栈必须为空。

### 精讲（零基础版）

#### ① 这题要用到的东西

**栈**（前面 4-1 讲过）：只能从末尾增删的列表。这题里它存"还没配对的左括号"——右括号只可能跟**最近一个**没配上的配对。

**字典做配对表**

一句话：`{')': '(', ']': '[', '}': '{'}` 把右括号映射到它该配的左括号，查一次表就知道对不对。

生活类比：墙上贴一张对照表，来了个 `)` 抬头看一眼，知道要找 `(`。

```python
pairs = {')': '(', ']': '['}
print(pairs[')'])        # -> (
print(']' in pairs)      # -> True
print('(' in pairs)      # -> False
```

`in` 查的是**键**在不在。左括号不在表里，正好用来区分"这是左括号还是右括号"。

#### ② 大白话：这题到底在干什么

最笨的办法：反复把相邻的 `()`、`[]`、`{}` 删掉，删到不能再删，看最后是不是空。能过，但每删一次都要从头扫。

笨在哪？括号配对有天然的顺序：**最后出现的左括号最先被配掉**，这正是后进先出。

所以左括号进栈；遇右括号只看栈顶——栈空说明没得配，类型不对说明配错了，都直接判非法；对上了就弹。扫完栈必须为空。

**核心代码（背这一段就够）**：

```python
pairs = {')': '(', ']': '[', '}': '{'}
stack = []
for ch in s:
    if ch in pairs:
        if not stack or stack[-1] != pairs[ch]:
            return False
        stack.pop()
    else:
        stack.append(ch)
return not stack
```

**换个角度**：

- **它和 32 是一对**：20 关心"最后栈空不空"，是一个**布尔问题**；32 关心"两次断点之间隔多远"，是一个**距离问题**。所以 20 存字符就够，32 必须存下标。你把这两题的代码摆在一起看，会发现骨架几乎一样，差别只在"栈里存什么、什么时候读长度"。
- **只有一种括号时，栈可以退化成两个计数器**：左括号 +1、右括号 -1，中途为负或结尾非零就非法，O(1) 空间。三种括号就不行——计数器记不住类型，`"([)]"` 会被误判成合法。**"要不要栈"取决于"要不要记住顺序和类型"**。
- **追问"最少加几个括号才合法"**（力扣 921、1541）：把 `return False` 换成计数——栈空时遇到右括号，说明必须补一个左括号；扫完栈里剩几个，就还得补几个右括号。同一个骨架，改的是"失败时做什么"。

## 专题4-6. 基本计算器 II（回顾）

> 第一册已精讲：[分册 B · B3](11-分册B-栈与单调栈.md)
> 力扣 227 · 栈 + 符号 · Medium

**30 秒回顾**：一个栈存"已经确定的加项"，一个 `num` 攒数字，一个 `sign` 记上一个运算符。遇到运算符才结算上一个数：加减就压 `±num`，乘除就弹出栈顶和 `num` 运算再压回。末尾补一个 `'+'` 保证最后一个数被结算。最后 `sum(stack)`。

### 精讲（零基础版）

#### ① 这题要用到的东西

**运算符优先级**

一句话：乘除先算、加减后算，所以"边读边加"不够——乘号要跟**紧挨着的前一个数**结合，而那个数可能还没被加进去。

生活类比：算 `2 + 3 * 4`，你不能先把 2 和 3 加起来，因为 3 还得先跟 4 乘。

这题里栈存的是"已经算完、但还没相加的加项"，乘除就地解决掉。

**`int(a / b)` 和 `a // b`**

一句话：`int()` 是**向零截断**，`//` 是**向下取整**；正数时一样，负数时不同。

```python
print(int(-3 / 2))   # -> -1   向零截断
print(-3 // 2)       # -> -2   向下取整
```

这题（227）要求向零截断，所以必须写 `int(a / b)`。

#### ② 大白话：这题到底在干什么

`2 + 3 * 4` 里，遇到第一个 `+` 时 2 已经是完整加项，可以先定下来；但 3 后面跟着 `*`，它得先跟 4 乘。

所以规则是：**看到运算符才结算上一个数**。上一个是加减，这个数直接压栈（`±num`）；上一个是乘除，就把栈顶弹出来算完再压回——乘除只影响紧挨着它的那一个数。

扫完栈里全是加项，`sum(stack)` 就是答案；末尾补一个 `'+'` 是让最后一个数也被结算。

注意 227 和 224 的栈存的不是一种东西：227 存"算出来的加项"（结果），224 存"括号外的现场"（状态）。

**核心代码（骨架）**：

```python
for ch in s + '+':
    if ch.isdigit():
        num = num * 10 + int(ch)
    elif ch != ' ':
        if sign == '+':   stack.append(num)
        elif sign == '-': stack.append(-num)
        elif sign == '*': stack.append(stack.pop() * num)
        else:             stack.append(int(stack.pop() / num))   # 向零取整
        sign, num = ch, 0
return sum(stack)
```

**换个角度**：

- **它和 224 的栈存的完全不是一种东西**，这点最值得记。227 的栈存"**已经算出来的加项**"，是计算结果；224 的栈存"**括号外的现场**"，是待恢复的状态。同样是 `stack.append`，一个存数据、一个存上下文——判断标准是：**这个值将来是拿来相加的，还是拿来"接着算"的？**
- **为什么 227 不需要第二个栈**：它的优先级只有两级，而且乘除只影响"紧挨着它的那一个数"，用"弹出栈顶、合并、压回"就能就地解决。一旦加上括号（224），优先级关系变成嵌套的，就地合并就不够了。
- **除法的坑是 227 独有的**：`int(a / b)` 是向零截断，`a // b` 是向下取整。`"1-3/2"` 里栈顶是 -3，`-3 // 2 == -2`，最后得 -1；正确答案是 0。224 只有加减，不涉及这个坑——但这也是为什么很多人把 224 的代码直接改一改去做 227 会挂。

## 专题4-7. 每日温度（回顾）

> 第一册已精讲：[分册 B · B1](11-分册B-栈与单调栈.md)
> 力扣 739 · 单调栈 · Medium

**30 秒回顾**：栈存下标，栈内对应温度从栈底到栈顶**严格递减**。新温度比栈顶高，就一次性把栈顶那些"等到了"的天弹出来，答案填 `i - 那天`。默认值 0 正好就是"等不到更高温度"的答案。

### 精讲（零基础版）

#### ① 这题要用到的东西

**单调栈**（前面 4-2 讲过）：栈内保持递增或递减，新元素进栈前先弹掉破坏顺序的栈顶。这题里栈存下标，对应温度从栈底到栈顶**严格递减**——越靠栈顶越冷，越急着等热天。

**`[0] * n`（造 n 个 0）**

一句话：`[0] * 4` 得到 `[0, 0, 0, 0]`，一次造出填满 0 的列表。

```python
answer = [0] * 4
print(answer)      # -> [0, 0, 0, 0]
```

这题里它既是答案初值，也是收尾手段：等不到更高温度的天，答案本来就该是 0。

#### ② 大白话：这题到底在干什么

最笨：站在每一天往后找第一个更热的，最坏看到末尾，总共 n² 次。笨在重复——算 71 那天扫过 69，算 69 那天还得再扫。

聪明的办法：把"还没等到热天"的日子攒进栈。它们有个规律——**越晚攒的温度越低**（更热的来了，前面早被结算掉），所以栈里从下往上越来越冷。

新来一天就盯栈顶：比它热就弹出来、写上等了几天，弹完再看新的一张；直到栈顶比今天热或栈空，就把自己压进去。

每张便签只压一次、弹一次，总共 O(n)。739 和 84 是同一模板，区别只在弹出后算什么：739 算距离，84 算面积。

**核心代码（背这一段就够）**：

```python
answer = [0] * n
stack = []
for i, t in enumerate(temperatures):
    while stack and temperatures[stack[-1]] < t:
        j = stack.pop()
        answer[j] = i - j
    stack.append(i)
```

**换个角度**：

- **它和 84 是同一个模板的两个难度档**。弹出时机完全一样——都是"右边第一个更大 / 更小出现了"。区别只在**弹出之后算什么**：739 算 `i - j`（距离），84 算 `h[j] * (i - 新栈顶 - 1)`（面积）。你可以把 84 看成"739 的结算部分被换掉了"，模板一行没动。
- **两题的收尾方式正好相反，这个对比值得记**。739 靠"答案数组默认 0"收尾，栈里剩下的不用管；84 必须靠尾部哨兵 0 把栈清空，因为 84 要取 max，漏算一根就可能漏掉最优解。**什么时候能"不管剩下的"，取决于你要的是"每个位置的答案"还是"全局最大值"。**
- **739 用不上哨兵，84 用不上默认值**，这不是巧合：739 的输出是 n 个独立答案，天然有"没答案"这个取值；84 的输出是一个数，没有"没答案"的余地，只能保证每根柱子都被结算一次。
