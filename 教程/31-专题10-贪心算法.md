| 题 | 每步在选什么 | 为什么这样选不吃亏 |

## 零、贪心什么时候能用

贪心的定义很朴素：**每一步都在当前信息下选一个"看起来最好"的，选完就不再改，也不保存其他可能。**

它能用的前提只有一条：**局部最优能推出全局最优**。用行话说叫"贪心选择性质"——你把最优解里的某一步换成贪心选的那个，解不会变差。这句话必须能证出来，否则你的代码只是"一种可能的做法"，不是"正确答案"。

反例最能说明问题。零钱面额 `[1, 3, 4]`，凑 6 元：贪心先拿最大的 4，剩 2 只能用两个 1，一共 3 张；而最优是 3 + 3，2 张。局部最优（先拿最大的）推不出全局最优，这题只能上动态规划。

所以贪心和 DP 的分界线在这里：

- **DP 会把"所有可能的选择"都算一遍并保存下来**，所以它一定对，但慢，常常 O(n²)。
- **贪心只保留一个分支，把其余可能全扔掉**，所以它快，O(n) 或 O(n log n)，但扔掉的那些必须真的没用。

换句话说，贪心是"剪枝剪到只剩一条路"的 DP。这也解释了一个现象：**贪心题代码短得像没写，证明却要写一页。** 面试时"为什么这样贪心是对的"比代码重要得多，常用的两把刀是：

- **交换论证**：假设最优解里某一步没选贪心选的那个，把它换过去，证明解不变差。435 用的就是这把。
- **反证 + 单调性**：假设贪心不是最优，推出与"区间只能变大/变小"矛盾。502 用的接近这把。

还有一条实践建议：**拿不准能不能贪，就先写暴力，再用随机小数据对拍。** 本册每道题的代码我都这么干过（见文末自测记录），这比盯着屏幕想证明快得多。

## 专题10-1. 分发糖果（Hard）

> 力扣 135 · 贪心 · 两次扫描
> 前置：本册「零、贪心什么时候能用」

**一句话**：一排孩子各有评分，相邻两人里评分高的必须拿得比低的多，每人至少 1 颗，问最少要准备多少颗糖。

### 精讲（零基础版）

#### ① 这题要用到的东西

**列表（list）和 `[1] * n`**

一句话：列表就是方括号里装一串东西的容器；`[1] * 4` 是"把 1 复制 4 份"，得到一个长度为 4 的新列表。

生活类比：复印机。你放一张写着 1 的纸进去，按 4 下，出来 4 张独立的纸 —— 改第 3 张不会影响第 1 张。

```python
candies = [1] * 4          # 造一个 4 个 1 的列表
print(candies)             # -> [1, 1, 1, 1]
candies[2] = candies[1] + 1
print(candies)             # -> [1, 1, 2, 1]
print(sum(candies))        # -> 5
```

这题里，`candies = [1] * n` 就是"先给每个孩子发 1 颗"，后面所有调整都在这个列表上改。

**`range` 的三个参数**

一句话：`range(起点, 终点, 步长)`，终点取不到，步长可以写负数表示倒着走。

生活类比：电梯楼层。`range(1, 5)` 是"1、2、3、4 楼"，不含 5 楼；`range(4, -1, -1)` 是"4、3、2、1、0 楼"，一层层往下。

```python
for i in range(4, -1, -1):
    print(i, end=" ")      # -> 4 3 2 1 0
print()
```

这题里左→右扫用 `range(1, n)`（从 1 开始，因为要跟 `i-1` 比），右→左扫用 `range(n-2, -1, -1)`（从倒数第二个开始，因为要跟 `i+1` 比）。两个起点各少一格，就是为了不越界。

**`max(a, b)`**

一句话：返回括号里最大的那个，可以给两个数，也可以给一个列表。

```python
print(max(3, 5))           # -> 5
print(max([3, 5, 2]))      # -> 5
```

这题里第二遍扫描要写 `max(candies[i], candies[i + 1] + 1)`：既保住左→右那一遍的结论，又满足右→左的要求。

**两次扫描（从左一遍、从右一遍）**

一句话：同一条"相邻"约束，其实包含"我比左边高"和"我比右边高"两句，一次扫描只能管其中一句。

生活类比：给一排人按身高发凳子。从左往右走，你只看得见左边那个人；从右往左走，你只看得见右边那个人。走两趟，两边的信息才齐。

这题里，第一遍保证"右边评分高的人比左边拿得多"，第二遍保证"左边评分高的人比右边拿得多"。

**贪心**（前面「零、贪心什么时候能用」讲过）：每一步都在当前信息下选"看起来最好"的，选完不回头。这题里"当前最好"= 在满足已扫过的那一侧约束的前提下，拿最少的糖，也就是比邻居多 1 颗。

#### ② 大白话：这题到底在干什么

最笨的办法：先每人发 1 颗，然后从头到尾反复检查 —— 发现谁比邻居评分高却糖不多，就给他加一颗；加完可能又破坏了别处，于是再从头扫一遍，直到某一整轮没人被加。

这个办法是对的，但最坏要扫 n 轮、每轮 n 次，n 是 5 万时就是 25 亿次操作，超时。

笨在哪？**它在重复检查同一段**。左边加了一颗，右边那一整串可能都要跟着加，而你每次只加一颗、再从头找。

聪明的办法：注意到"相邻两人里评分高的拿得多"这句话管两个方向。先把"我比左边高"这条单独满足掉 —— 从左往右走一遍，谁比左邻居评分高，就比左邻居多 1 颗。这一遍结束时所有"左邻关系"都合法了，但"右邻关系"可能还不合法。于是再从右往左走一遍，专门修"我比右边高"。

两遍走完，每个人手里都有两个"至少该拿几颗"的数字，取大的那个 —— 因为两个条件必须同时满足。注意这里不能相加（会多发糖），也不能取小的（会违反另一条约束）。

还有一个容易忽略的点：评分相等的两个人之间没有任何约束，谁都不必比对方多。`[1,2,2]` 里第三个孩子只拿 1 颗就是对的。

#### ③ 拿 `[1,0,2]` 走一遍

| 步骤 | i | ratings[i] | candies | 发生了什么 |
|---|---|---|---|---|
| 初始化 | — | — | `[1,1,1]` | 每人先发 1 颗 |
| 左→右 | 1 | 0 | `[1,1,1]` | `0 > 1` 不成立，不动 |
| 左→右 | 2 | 2 | `[1,1,2]` | `2 > 0` 成立，`candies[2] = 1+1 = 2` |
| 右→左 | 1 | 0 | `[1,1,2]` | `0 > 2` 不成立，不动 |
| 右→左 | 0 | 1 | `[2,1,2]` | `1 > 0` 成立，`candies[0] = max(1, 1+1) = 2` |

两遍都走完，`candies` 是 `[2,1,2]`，合计 `2+1+2 = 5`，所以答案是 5。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `candies = [1] * n` | 先每人发 1 颗 —— 题面规定至少 1 颗，这就是下界 |
| `for i in range(1, n)` | 从左往右，从第 2 个人开始（要跟左边比） |
| `if ratings[i] > ratings[i - 1]` | 我比左邻居评分高吗？ |
| `candies[i] = candies[i - 1] + 1` | 高就比他多 1 颗。此刻 `candies[i]` 还是 1，所以不用取 `max` |
| `for i in range(n - 2, -1, -1)` | 从右往左，从倒数第二个开始（要跟右边比） |
| `if ratings[i] > ratings[i + 1]` | 我比右邻居评分高吗？ |
| `candies[i] = max(candies[i], candies[i + 1] + 1)` | 高就至少得 `candies[i+1]+1`；但左边那一遍的结论也得留着，所以取大的 |
| `return sum(candies)` | 题目只要总数，把列表加起来 |

### 考什么

- 表面考点：最少糖果总数。
- 真正考点：**"相邻"这一条约束其实包含两个方向**，一次扫描只能满足一个方向。你要做的是把约束拆成两条，各扫一遍，再合并。
- 面试官想听到的关键句：
  - "约束是双向的：`ratings[i] > ratings[i-1]` 要求右边多，`ratings[i] > ratings[i+1]` 要求左边多。左→右扫一遍只管前者，右→左扫一遍只管后者。"
  - "两遍的结果要取 `max`，不能相加也不能取 `min`——每个人必须同时满足两条约束，所以他的糖果数必须同时不小于两个下界。"

### 思路是怎么想出来的

**暴力一**：枚举每个人拿几颗。n 最多 5×10⁴，每个人至少 1 颗，组合数是天文数字，直接排除。

**暴力二**：每人先发 1 颗，然后反复从头扫，发现谁违反约束就给他加一颗，直到没有违反为止。这个写法是对的，但最坏情况每轮只修好一处，n 轮 × n 次扫描 = O(n²)，5×10⁴ 的平方是 2.5×10⁹，超时。

**关键观察一：把一条约束拆成两条。** 原题要求"相邻两人评分高的拿得多"，这句话同时管两个方向：

- 约束 L：若 `ratings[i] > ratings[i-1]`，则 `candies[i] > candies[i-1]`（只看左邻居）
- 约束 R：若 `ratings[i] > ratings[i+1]`，则 `candies[i] > candies[i+1]`（只看右邻居）

原题 = 同时满足 L 和 R。

**关键观察二：约束 L 只依赖左边，所以从左往右扫一遍就能一次性满足。** 处理到 `i` 时，`i-1` 已经定好了，而 `i` 的取值只跟 `i-1` 有关，跟右边无关——这就是"无后效性"，也是贪心能成立的地方。做法是：默认给 1 颗，若 `ratings[i] > ratings[i-1]` 就取 `candies[i-1] + 1`。这一遍得到的数组（记作 `left`）是"只满足 L 时，每个人最少要几颗"。

同理，从右往左扫一遍得到 `right`，它是"只满足 R 时的最小值"。

**关键观察三：最终答案取 `max(left[i], right[i])`。** 因为第 `i` 个人必须同时满足两条约束，他的糖果数必须 ≥ `left[i]` 且 ≥ `right[i]`，两个下界取大的那个就是最小可行值。

到这里还差一步：**取 `max` 之后，约束会不会又被破坏？** 这是这题最该讲清的地方。看递增的那条边（`ratings[i-1] < ratings[i]`）：

- 右→左那一遍在 `i-1` 处看到的是 `ratings[i-1] < ratings[i]`，条件不成立，所以 `right[i-1]` 保持 1。
- 于是 `final[i-1] = max(left[i-1], 1) = left[i-1]`。
- 而 `final[i] >= left[i] = left[i-1] + 1 > final[i-1]`。

递减的边同理。**所以 `max` 不但不破坏约束，还恰好让"低的那一侧"退回 1，给高的那一侧腾出了空间。** 这就是为什么必须取 `max` 而不是别的运算。

### 走一遍

`ratings = [1, 0, 2]`：

| 阶段 | 数组 | 说明 |
|---|---|---|
| 初始化 | `[1, 1, 1]` | 每人 1 颗 |
| 左→右，i=1 | `[1, 1, 1]` | `0 > 1` 不成立，不动 |
| 左→右，i=2 | `[1, 1, 2]` | `2 > 0` 成立，`candies[2] = 1+1` |
| 右→左，i=1 | `[1, 1, 2]` | `0 > 2` 不成立，不动 |
| 右→左，i=0 | `[2, 1, 2]` | `1 > 0` 成立，`max(1, 1+1) = 2` |

合计 5 颗，和题面示例一致。

`ratings = [1, 2, 2]`（这题的关键用例）：

| 阶段 | 数组 |
|---|---|
| 左→右 | `[1, 2, 1]`（`2 > 1` 成立；`2 > 2` 不成立） |
| 右→左 | `[1, 2, 1]`（三个位置都不满足"左边比右边高"） |

合计 4 颗。注意第 2、3 个孩子评分相同，他们之间**没有任何约束**，所以第三个人只拿 1 颗是合法的。

### 代码（Python）

```python
from typing import List   # 力扣已预导入这行，本地跑时要加上

class Solution:
    def candy(self, ratings: List[int]) -> int:
        n = len(ratings)
        candies = [1] * n                    # 每人先发 1 颗，保证下界

        # 左 -> 右：只保证"右边评分更高的，比左边多"
        for i in range(1, n):
            if ratings[i] > ratings[i - 1]:
                candies[i] = candies[i - 1] + 1

        # 右 -> 左：只保证"左边评分更高的，比右边多"
        for i in range(n - 2, -1, -1):
            if ratings[i] > ratings[i + 1]:
                candies[i] = max(candies[i], candies[i + 1] + 1)

        return sum(candies)
```

**逐段讲解**

- `candies = [1] * n`：下界先坐实。后面所有赋值都是"在 1 的基础上往上加"，不会出现 0 颗。
- 第一遍 `for i in range(1, n)`：从 1 开始，因为 `i-1` 得先存在。这一遍**不需要** `max`，因为 `candies[i]` 此刻还是 1，`candies[i-1] + 1` 一定更大。
- 第二遍 `for i in range(n - 2, -1, -1)`：从 `n-2` 开始往 0 走，因为要用 `i+1`。
- `candies[i] = max(candies[i], candies[i + 1] + 1)`：**这一行是全题的灵魂**。`candies[i]` 里已经存着左→右那一遍的结论，现在要和右→左的结论取大。如果写成 `candies[i] = candies[i + 1] + 1`，就会把左→右的成果覆盖掉。
- `sum(candies)`：题目只要总数。

### 复杂度

- 时间 O(n)：两次线性扫描，每次每个元素看一次。
- 空间 O(n)：`candies` 数组。这个数组不能省，因为第一遍的结果要传给第二遍。想做到 O(1) 额外空间得按"上坡段/下坡段"分段求和，属于炫技，面试不要求。

### 常见误区（★ 最容易丢分的地方）

1. **只扫一遍（左→右）**。`[1, 0, 2]` 会得到 `[1, 1, 2]`，返回 4，正确答案 5。漏掉的是"左边比右边高"这种情况：第 0 个孩子评分 1 比第 1 个的 0 高，必须多拿。
2. **只扫一遍（右→左）**。同一个用例得到 `[2, 1, 1]`，也返回 4。两个方向漏哪个都一样错。
3. **第二遍直接覆盖，不取 `max`**。`[1, 2, 3, 1]` 会返回 6（`[1, 2, 2, 1]`），但这个分配是**非法**的：第 2 个孩子评分 2、第 3 个评分 3，糖却都是 2 颗。正确答案是 7。
4. **比较用 `>=` 而不是 `>`**。评分相等时不该有约束。`[1, 2, 2]` 会返回 8（正确 4）：代码把"相等"也当成了"更高"，一路加下去。
5. **两遍结果相加**。会得到大约两倍的糖果数。要记住是"取大"不是"叠加"——同一个人只拿一份糖。
6. **以为评分相同的孩子必须拿一样多**。题面没这个要求，`[1, 2, 2]` 里第三个孩子拿 1 颗就是标准答案。

### 面试追问 / 变体

- **如果孩子围成一圈（首尾也相邻）**：多了一条"第 0 个和第 n-1 个"的约束，两遍扫描不够了。常见做法是枚举断开点，或者先找到评分最低的那个孩子当断点，再按线性做。
- **如果要求"评分相同必须糖果相同"**：取 `max` 就不对了，得把连续相等的评分当成一个"块"整体处理。
- **如果只问总数、不问方案**：仍然需要数组，因为第一遍的中间结果要传给第二遍。
- **如果要求输出具体的分配方案**：直接返回 `candies` 即可，这题的数组本身就是方案。

### 自测

- 必测用例：
  - `[1,0,2]` → 5（题面示例）
  - `[1,2,2]` → 4（题面示例，相等不约束）
  - `[1]` → 1（单元素）
  - `[1,2,3,4,5]` → 15（严格递增，答案是 1+2+3+4+5）
  - `[5,4,3,2,1]` → 15（严格递减，对称）
  - `[1,1,1,1]` → 4（全相同，每人 1 颗）
  - `[1,3,2,2,1]` → 7（中间高、两边低，考验 `max`）
  - `[1,2,87,87,87,2,1]` → 13（平顶山，两个方向都得让路）
- 30 秒自检：能不能说出"两条约束、两次扫描、最后取 `max`"这三步，以及"为什么取 `max` 之后约束还成立"？

## 专题10-2. 无重叠区间（Medium）

> 力扣 435 · 贪心 · 区间调度
> 前置：本册「零、贪心什么时候能用」

**一句话**：给一堆区间，问最少删掉几个，才能让剩下的区间两两不重叠。题面特别说明：只在端点接触（`[1,2]` 和 `[2,3]`）不算重叠。

### 精讲（零基础版）

#### ① 这题要用到的东西

**区间，以及"端点接触不算重叠"**

一句话：区间就是一段范围，写成 `[开始, 结束]` 两个数。两个区间"端点接触"指前一个的结束正好等于后一个的开始。

生活类比：两节课 8:00–9:00 和 9:00–10:00，接着上，不算冲突。题面说这种不算重叠，所以代码里判断用 `>=` 而不是 `>` —— `[1,2]` 和 `[2,3]` 能同时留下。

**`sort(key=...)` 和 `lambda`**

一句话：`sort()` 默认按元素本身排；`key=` 后面给一个"从元素里取出排序依据"的小函数。

生活类比：给一摞简历排序，你可以按姓名排，也可以按年龄排 —— `key` 就是"你看哪一栏"。

```python
intervals = [[1, 3], [1, 2], [3, 4]]
intervals.sort(key=lambda seg: seg[1])   # 用每个区间的第 2 个元素（结束时间）当排序键
print(intervals)                         # -> [[1, 2], [1, 3], [3, 4]]
```

`lambda seg: seg[1]` 读作"给我一个 `seg`，我返回 `seg[1]`"，等价于临时写一个只返回 `seg[1]` 的小函数。这题里 `seg[1]` 是结束时间，所以排完是按结束时间升序。

**切片 `[1:]`**

一句话：`列表[1:]` 是"从下标 1 取到末尾"的一个新列表，原列表不动。

生活类比：一叠牌，`[1:]` 是把最上面那张拿开，剩下的整叠递给你。

```python
pairs = [[1, 2], [2, 3]]
for start, end in pairs[1:]:   # [1:] = 从第 2 个取到末尾
    print(start, end)          # -> 2 3
```

这题里 `intervals[1:]` 是"跳过第一个区间"，因为第一个已经被默认留下了。

**元组解包 `for start, end in ...`**

一句话：列表里装的是 `[开始, 结束]` 这种两元素的小列表，`for start, end in` 会一次把它们分给两个变量。

上面那段代码里，`start` 拿到 2、`end` 拿到 3。这样写就不用满屏 `seg[0]`、`seg[1]`。

**`if not intervals`**

一句话：空列表当条件用就是假，前面加 `not` 就变成真 —— 用来判"啥都没给"。

```python
print(not [])          # -> True
print(not [[1, 2]])    # -> False
```

**贪心**（前面 10-1 讲过）：每步选当前最好的，选完不回头。这题里"当前最好"= 结束最早的那个区间。

#### ② 大白话：这题到底在干什么

最笨的办法：把所有区间子集都试一遍，看哪个子集里两两不重叠、而且个数最多。n 是 10 万，子集有 2 的 n 次方个，完全不可能。

稍微聪明一点但是错的：按"开始时间"排序，能接就接。看 `[[1,100],[11,22],[1,11],[2,12]]`：`[1,100]` 开始最早，先选它，结果它把后面三个全盖住了，只留下 1 个。

笨在哪？**"开始得早"不等于"占得少"**。`[1,100]` 开始最早，可它一占就是 100 格。

真正决定"后面还能塞几个"的，不是从哪开始，而是什么时候结束。结束得越早，右边剩下的地方越大，能接上的就越多。所以按结束时间升序排，每次选"和上一个不冲突的、结束最早的那个"。

还有一步翻译：题目问"最少删几个"，等价于"最多留几个"，答案是 `n - 最多留`。

#### ③ 拿 `[[1,2],[2,3],[3,4],[1,3]]` 走一遍

按结束时间排序后是 `[[1,2],[2,3],[1,3],[3,4]]`：

| 步骤 | 看的区间 | `start >= last_end` | 动作 | `last_end` / `kept` |
|---|---|---|---|---|
| 1 | `[1,2]` | 第一个，直接留 | 留下 | 2 / 1 |
| 2 | `[2,3]` | `2 >= 2` 成立 | 留下 | 3 / 2 |
| 3 | `[1,3]` | `1 >= 3` 不成立 | 丢掉 | 3 / 2 |
| 4 | `[3,4]` | `3 >= 3` 成立 | 留下 | 4 / 3 |

留下 3 个，总共 4 个，所以答案是 `4 - 3 = 1`（删掉 `[1,3]` 这一个）。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `if not intervals: return 0` | 空列表直接返回 0，不然下面取 `intervals[0]` 会报错 |
| `intervals.sort(key=lambda seg: seg[1])` | 按结束时间升序。写 `seg[0]` 就是那道经典错题 |
| `kept = 1` | 排完第一个区间结束最早，选它一定不亏，先坐实 |
| `last_end = intervals[0][1]` | 记下"上一个留下的区间"的右边界 |
| `for start, end in intervals[1:]` | 从第二个区间开始，逐个看 |
| `if start >= last_end` | 它的开始 ≥ 上一个的结束吗？`>=` 是因为端点接触不算重叠 |
| `kept += 1` | 不冲突就留下，留几个数几个 |
| `last_end = end` | **只有真留下了才更新右边界**，放外面会让被丢的区间也推边界 |
| `return len(intervals) - kept` | 题目要的是删掉几个，不是留下几个 |

### 考什么

- 表面考点：最少移除数量。
- 真正考点：**区间调度**。把"最少删几个"翻译成"最多能留几个"，答案就是 `n - 最多能留`。而"最多能留几个不重叠区间"有唯一正确的贪心：**按结束时间排序**。
- 面试官想听到的关键句：
  - "要让后面还能塞下尽量多的区间，就得让已经占用的右边界尽量小，所以每次选结束最早的那个。"
  - "按开始时间排序会掉进坑里：一个 `[1, 100]` 就能把后面所有小区间全堵死。"

### 思路是怎么想出来的

**暴力**：枚举所有子集，判断是否两两不重叠，取最大的合法子集。n 最多 10⁵，2ⁿ 不可能。

**换个问法**：最少移除 = `n - 最多能留下`。所以只要求出"最多能选几个互不重叠的区间"。

**最直觉的贪心（错的）**：按开始时间排序，能选就选。看 `[[1,100],[11,22],[1,11],[2,12]]`：排序后先选 `[1,100]`，它把后面三个全盖住了，只留 1 个，返回移除 3。而正确答案是留下 `[1,11]` 和 `[11,22]` 两个，移除 2。**错在"早开始"不等于"占得少"**——`[1,100]` 开始得最早，却占得最久。

**关键观察**：真正决定"后面还能塞几个"的，不是区间从哪开始，而是它**什么时候结束**。结束得越早，右边剩下的空间越大，能接上的区间就越多。所以按结束时间升序排，每次选"和上一个不冲突的、结束最早的那个"。

**为什么这样贪心是对的（交换论证）**：设某个最优解的第一个区间是 `O1`，贪心选的第一个是 `G1`（结束时间全局最早）。因为 `G1.end <= O1.end`，而最优解第二个区间的 `start >= O1.end >= G1.end`，所以把 `O1` 换成 `G1` 之后，它和第二个区间仍然不冲突，区间个数一个没少。于是**一定存在一个以 `G1` 开头的最优解**。对剩下的部分重复同样的论证，贪心解不劣于最优解。

这段论证的价值在于：它解释了"为什么是结束时间"——交换的时候用的正是 `G1.end <= O1.end` 这个不等式。换成按开始时间排，这个不等式就没了，论证立刻崩掉。

### 走一遍

`intervals = [[1,2],[2,3],[3,4],[1,3]]`，按结束时间排序后是 `[[1,2],[2,3],[1,3],[3,4]]`：

| 区间 | 判断 | 动作 | 已留下 | 当前右边界 |
|---|---|---|---|---|
| `[1,2]` | 第一个，必留 | 留下 | 1 | 2 |
| `[2,3]` | `2 >= 2` 成立 | 留下 | 2 | 3 |
| `[1,3]` | `1 >= 3` 不成立 | 丢掉 | 2 | 3 |
| `[3,4]` | `3 >= 3` 成立 | 留下 | 3 | 4 |

留下 3 个，总共 4 个，移除 1 个。被丢掉的是 `[1,3]`，和题面示例一致。

再看 `[[1,2],[1,2],[1,2]]`：排序后三个一样，第一个留下，后两个都是 `1 >= 2` 不成立，全丢，移除 2。

### 代码（Python）

```python
from typing import List

class Solution:
    def eraseOverlapIntervals(self, intervals: List[List[int]]) -> int:
        if not intervals:
            return 0

        intervals.sort(key=lambda seg: seg[1])   # 按"结束时间"升序
        kept = 1                                 # 第一个区间一定留下
        last_end = intervals[0][1]

        for start, end in intervals[1:]:
            if start >= last_end:                # 和上一个留下的不重叠
                kept += 1
                last_end = end                   # 只有真留下了才更新结尾

        return len(intervals) - kept
```

**逐段讲解**

- `sort(key=lambda seg: seg[1])`：`seg[1]` 是结束时间。**这里写 `seg[0]` 就是那道经典错题**，后面误区里会看到它的具体后果。
- `kept = 1` 和 `last_end = intervals[0][1]`：排序后第一个区间结束最早，选它一定不亏（交换论证的第一句），所以直接坐实。
- `if start >= last_end`：`>=` 而不是 `>`，因为题面说端点接触不算重叠。这个符号错了，`[[1,2],[2,3]]` 会算成重叠。
- `last_end = end` 放在 `if` 里面：**只有真的留下了这个区间，右边界才更新**。放到外面的话，被丢掉的区间也会推右边界，后面本来能接上的区间会被误判。
- `return len(intervals) - kept`：题目要的是移除数，不是保留数。

### 复杂度

- 时间 O(n log n)：排序是瓶颈，后面一次线性扫描。
- 空间 O(1) 额外（不算 Python `sort` 自带的辅助空间）。

### 常见误区（★ 最容易丢分的地方）

1. **按开始时间排序**。`[[1,100],[11,22],[1,11],[2,12]]` 会返回 3，正确答案 2。这是这题最典型的错，也是面试官最爱问"为什么不是按开始时间"的原因。
2. **`start > last_end` 而不是 `>=`**。题面明确说端点接触不重叠，`[[1,2],[2,3]]` 会返回 1（正确 0）。用 `>` 的话，这类"刚好接上"的区间会被当成冲突白白丢掉一个。
3. **返回 `kept` 而不是 `n - kept`**。示例 1 会返回 3（正确 1）——题目问的是删掉几个，不是留下几个。
4. **不管留没留下都更新 `last_end`**。`[[1,2],[1,3],[2,4]]` 会返回 2（正确 1）：`[1,3]` 被丢掉却把右边界推到了 3，于是 `[2,4]` 也被误判为冲突。
5. **排序键写成 `lambda x: x[1] - x[0]`（按区间长度）**。短区间不一定好接，`[1,2]` 很短但它在最左边，和 `[5,6]` 一点关系都没有。

### 面试追问 / 变体

- **合并区间（力扣 56）**：同样排序，但键是开始时间，然后把重叠的合并成一个大区间。**排序键跟着问题变**，这是区间题的第一判断。
- **用最少数量的箭引爆气球（力扣 452）**：几乎一模一样的贪心（按结束排序、能覆盖就覆盖），只是答案从"移除数"变成"箭数"，而且那题里端点接触**算**重叠，判断要用 `>`。
- **会议室 II（力扣 253）**：问"最多同时有几个区间重叠"，那是另一类问题，用堆或差分数组，不是这题的贪心。
- **如果区间是开区间 `(start, end)`**：端点不共享，判断仍然是 `start >= last_end`，代码不用改。
- **如果要输出具体删掉哪些**：把 `if` 的 `else` 分支补上，把被丢的区间收集起来即可。

### 自测

- 必测用例：
  - `[[1,2],[2,3],[3,4],[1,3]]` → 1（题面示例）
  - `[[1,2],[1,2],[1,2]]` → 2（题面示例，全相同）
  - `[[1,2],[2,3]]` → 0（题面示例，端点接触）
  - `[[1,2]]` → 0（单区间）
  - `[[1,100],[11,22],[1,11],[2,12]]` → 2（专治"按开始时间排序"）
  - `[[0,2],[1,3],[2,4],[3,5]]` → 2（阶梯状，两两相邻）
- 30 秒自检：能不能说出"为什么按结束时间排、为什么 `last_end` 只在留下时更新、为什么返回 `n - kept`"？

## 专题10-3. IPO（Hard）

> 力扣 502 · 贪心 + 排序 + 堆
> 前置：本册 10-2；堆的用法见 [专题 5 · 队列与堆](24-专题5-队列与堆.md)

**一句话**：你手里有 `w` 块钱，最多能做 `k` 个项目；每个项目要 `capital[i]` 块本钱、做完赚 `profits[i]` 块，赚的钱立刻能投进下一个项目。问最后最多有多少钱。

### 精讲（零基础版）

#### ① 这题要用到的东西

**`zip`**

一句话：把两个列表"拉链式"配对，第 i 个配第 i 个，配成一个个二元组。

生活类比：两列队伍，一列报门槛、一列报利润，`zip` 把它们一对一牵起手来。

```python
capital = [1, 0, 1]
profits = [2, 1, 3]
print(list(zip(capital, profits)))      # -> [(1, 2), (0, 1), (1, 3)]
print(sorted(zip(capital, profits)))    # -> [(0, 1), (1, 2), (1, 3)]
```

`sorted` 对二元组默认先比第一个数（门槛），门槛相同再比第二个。这题里就是"按门槛从低到高排"。

**堆（`heapq`）**

一句话：堆是一个"随时能取出最小值"的容器。Python 的 `heapq` 是小顶堆 —— `heappush` 放进去，`heappop` 拿走最小的那个。

生活类比：一个会自动把最小的球顶到最上面的箱子。你往里扔球，它自己整理；你伸手，永远先摸到最小的那个。

```python
import heapq

h = []
heapq.heappush(h, 3)      # 放进去一个
heapq.heappush(h, 1)
heapq.heappush(h, 5)
print(h)                  # -> [1, 3, 5]
print(heapq.heappop(h))   # -> 1   （拿走最小的）
print(h)                  # -> [3, 5]
```

注意打印出来的 `[1, 3, 5]` 只是"堆在内存里的排列"，规律只有一条：`h[0]` 永远是最小的。这题里堆里放"当前买得起、但还没做"的项目，堆顶就是这一轮最该做的那个。

**大顶堆 = 存负数**

一句话：Python 只有小顶堆。想要"取最大"，就把数取负存进去，取出来再取负还原。

生活类比：所有东西反过来写，最大的就变成最小的了。

```python
import heapq

h = []
for p in [1, 3, 2]:
    heapq.heappush(h, -p)     # 存的是负利润
print(h)                      # -> [-3, -1, -2]
print(-heapq.heappop(h))      # -> 3   （弹出 -3，还原成利润 3）
```

**两个数据结构的分工**

一句话：排序表负责"谁进来了"，堆负责"谁最赚"。

生活类比：医院分诊台。门口按先来后到发号（排序表），诊室里医生只看"当前等着的病人里谁最急"（堆）。

这题里，一张静态排序表回答不了"此刻买得起的人里谁利润最大"，所以必须再加一个堆。

**`for _ in range(k)`**

一句话：`_` 就是个"我不打算用"的变量名，`range(k)` 是"重复 k 次"。这题里表示"最多做 k 个项目，每轮一次"。

**贪心**（前面 10-1 讲过）：每步选当前最好的。这题里"当前最好"= 现在买得起的项目里利润最大的那个。

#### ② 大白话：这题到底在干什么

最笨的办法：每一轮把 n 个项目从头扫一遍，在"门槛 ≤ 我现在有多少钱"且"还没做过"的项目里挑利润最大的，做掉，钱变多，再来下一轮。

这个策略本身没错，但每轮扫 n 个、一共 k 轮。n 和 k 都能到 10 万，10 万 × 10 万 = 100 亿次，超时。

笨在哪？**钱只增不减，所以"买得起"的名单只会变长，永远不会缩短**。既然如此，每轮从头重扫完全是浪费。

聪明的办法：先把项目按门槛从小到大排好，拿一个指针 `i` 记住"前 i 个项目已经进过候选池"。每轮开始，把门槛 ≤ 当前钱的继续放进候选池，指针只往前走、不回头。然后从候选池里挑利润最大的做掉。

候选池要支持"随时取出最大值"，这正是堆的活。排序表负责"谁进来了"，堆负责"谁最赚"，两件事分开管。

还要注意题面写的是"最多 k 个"：某一轮如果候选池空了（钱不够开任何项目），后面也不会有新项目进来，直接停。

#### ③ 拿 `k=2, w=0, profits=[1,2,3], capital=[0,1,1]` 走一遍

按门槛排完是 `[(0,1), (1,2), (1,3)]`：

| 轮 | 进来时的 `w` | 新入堆的项目 | 堆里的利润 | 做哪个 | 做完的 `w` |
|---|---|---|---|---|---|
| 1 | 0 | `(0,1)`：门槛 0 ≤ 0 | `[1]` | 1 | 1 |
| 2 | 1 | `(1,2)`、`(1,3)`：门槛 1 ≤ 1 | `[2,3]` | 3 | 4 |

第 2 轮堆里同时有 2 和 3，取大的 3。两轮做完，所以答案是 `w = 4`。

对照一下反例：如果一上来就"按利润从大到小"选，会去开利润 3 的项目，可它门槛是 1，而你现在只有 0 块，根本开不了。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `projects = sorted(zip(capital, profits))` | 把门槛和利润配成对，按门槛从低到高排 |
| `affordable = []` | 候选池（堆）先空着 |
| `i = 0` | 指针：前 `i` 个项目已经进过池子 |
| `for _ in range(k)` | 最多做 k 轮 |
| `while i < n and projects[i][0] <= w` | 用 `while` 不用 `if`：一轮里可能有好几个同时变得买得起 |
| `heapq.heappush(affordable, -projects[i][1])` | 存负利润，小顶堆就变成"利润大顶堆" |
| `i += 1` | 指针只前进。写在循环里、不重置，这是 O(n log n) 的来源 |
| `if not affordable: break` | 池子空 = 一个都开不起，后面也不会变好，收工 |
| `w += -heapq.heappop(affordable)` | 弹出最小的负数 = 最大的利润，取负加回钱里 |

### 考什么

- 表面考点：最大化最终资本。
- 真正考点：**把"选哪个"拆成两个动作**——先用排序 + 指针把"现在买得起的"筛出来，再用大顶堆从里面挑利润最大的。这是一道"两个数据结构各管一件事"的典型题。
- 面试官想听到的关键句：
  - "资本只增不减，所以'买得起'的集合只会变大，指针 `i` 只需要往前走，不用回头。"
  - "每轮只把**新变得买得起**的项目入堆，堆里始终是'当前买得起但还没做'的全部项目，堆顶就是利润最大的那个。"

### 思路是怎么想出来的

**暴力**：每轮把所有项目扫一遍，在"`capital[i] <= w` 且没做过"的项目里挑利润最大的，做掉，`w` 增加。贪心策略本身是对的，但每轮重扫一遍是 O(n)，`k` 轮就是 O(nk)。n 和 k 都能到 10⁵，乘积 10¹⁰，超时。

**关键观察一：资本单调不减，所以"买得起"是一个只增不减的集合。** 把项目按 `capital` 升序排好，用一个指针 `i` 表示"前 `i` 个项目已经进过堆"。每轮开始时，把 `capital <= w` 的项目继续入堆，`i` 只前进不后退。整个过程中每个项目最多入堆一次，总代价 O(n log n)。

**关键观察二：每轮要的是"买得起的里面利润最大的"，这正是堆的活。** Python 只有小顶堆，存 `-profit` 就变成大顶堆。堆里放的是"当前买得起、但还没做"的项目，所以堆顶就是这一轮该做的。

**为什么每轮选利润最大是对的**：任取一个最优方案，如果它某一步没做"当前买得起里利润最大"的那个项目 `p`，而是做了 `q`。把这一步换成 `p`：这一步结束时资本是 `w + p.profit >= w + q.profit`，比原来只多不少；资本更多意味着后面能做的项目只多不少。所以换完不劣，贪心不吃亏。

**那为什么不能干脆按利润排个序、从头取 `k` 个？** 因为每一轮的"买得起"集合都不一样，而且只会变大。静态排序给的是一张固定的顺序表，回答不了"**此刻**能做的里面谁最赚"。所以顺序表（按门槛排）+ 堆（随时取最大值）必须配合：一个负责"谁进来了"，一个负责"谁最赚"。

**注意"最多 k 个"**：题目说的是"最多"，所以买不起的时候要能停下来，不能硬凑够 k 个。

### 走一遍

`k = 2, w = 0, profits = [1,2,3], capital = [0,1,1]`，按 `capital` 排序后是 `[(0,1), (1,2), (1,3)]`：

| 轮次 | 新入堆的项目 | 入堆后的堆（利润） | 做哪个（堆顶） | 做完的 `w` |
|---|---|---|---|---|
| 1 | `(0,1)`：门槛 0 ≤ 0 | `[1]` | 1 | 1 |
| 2 | `(1,2)`、`(1,3)`：门槛 1 ≤ 1 | `[2, 3]` | 3 | 4 |

第 2 轮里，堆里同时有利润 2 和 3，选 3。最终 `w = 4`，和题面一致。

反例对照：如果第一轮就"按利润从大到小"选，会去开利润 3 的项目，但它的门槛是 1，而你现在只有 0 块，根本开不了。

### 代码（Python）

```python
from typing import List
import heapq

class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int],
                            capital: List[int]) -> int:
        n = len(profits)
        projects = sorted(zip(capital, profits))   # 按门槛从低到高
        affordable = []                            # 大顶堆（存负数）
        i = 0

        for _ in range(k):
            while i < n and projects[i][0] <= w:   # 只把"现在买得起"的加进堆
                heapq.heappush(affordable, -projects[i][1])
                i += 1
            if not affordable:                     # 一个都买不起，提前结束
                break
            w += -heapq.heappop(affordable)        # 做利润最大的那个

        return w
```

**逐段讲解**

- `sorted(zip(capital, profits))`：`zip` 把两个数组配成 `(门槛, 利润)`，`sorted` 默认按第一项（门槛）排。**这里不能只按利润排**，否则指针 `i` 的语义就废了。
- `while i < n and projects[i][0] <= w`：这个 `while` 而不是 `if` 是关键——一轮里可能有好几个项目同时变得买得起，必须一次全放进去。
- `i` 写在 `while` 里自增，**不重置**：这就是"每个项目只入堆一次"的保证，也是 O(n log n) 的来源。
- `if not affordable: break`：堆空说明当前资本下没有任何项目可做，后面 `k` 轮也不会有（资本不再增长），直接结束。
- `w += -heapq.heappop(affordable)`：弹出的是最小的负数，也就是最大的利润。取负还原。

### 复杂度

- 时间 O((n + k) log n)：排序 O(n log n)；每个项目入堆、出堆各最多一次，每次 O(log n)；外层 `k` 轮，每轮至少一次 `heappop`。
- 空间 O(n)：`projects` 列表 + 堆。

### 常见误区（★ 最容易丢分的地方）

1. **不看 `capital`，直接按利润从大到小做 `k` 个**。`k=2, w=0, profits=[1,2,3], capital=[0,1,1]` 会返回 5（先做利润 3、再做利润 2），正确答案 4。门槛不是摆设。
2. **一次把所有项目都压进堆**（等于忽略门槛）。同一个用例也返回 5。正确做法是"每轮只把新买得起的加进去"。
3. **用小顶堆**。同一个用例返回 3：每轮都在做利润最小的项目，钱涨得最慢。
4. **忘了"堆空就停"**。`k=1, w=0, profits=[1], capital=[1]` 会直接抛 `IndexError: index out of range`——对着空堆 `heappop`。
5. **每轮都从头扫一遍找买得起的**。逻辑对但 O(nk)，10⁵ × 10⁵ 必然超时。这题的分数就在"指针不回头"上。
6. **`while` 写成 `if`**。一轮里只放进一个项目，剩下的明明买得起却进不了堆，结果偏小。

### 面试追问 / 变体

- **如果利润可以是负数**（有些项目会亏）：那就不能"买得起就做"，每轮只做正利润的；堆顶 ≤ 0 就停。题目说"最多 k 个"，所以不做是允许的。
- **如果项目之间有依赖**（做完 A 才能做 B）：贪心立刻失效，变成带约束的调度问题，要 DP 或搜索。
- **如果 `k >= n` 且钱一直够**：答案就是 `w + sum(profits)`，每个项目都做一遍。
- **和"课程表/任务调度"的区别**：那些题有依赖关系或时间窗，这题只有"钱够不够"这一个门槛，所以能贪。
- **如果要求输出做项目的顺序**：堆里存 `(-profit, 下标)`，弹出时记下下标即可。

### 自测

- 必测用例：
  - `k=2, w=0, [1,2,3], [0,1,1]` → 4（题面示例）
  - `k=3, w=0, [1,2,3], [0,1,2]` → 6（题面示例）
  - `k=1, w=0, [1,2,3], [1,1,1]` → 0（一个都买不起）
  - `k=1, w=2, [1,2,3], [1,1,1]` → 5（`k` 只够做一个，选利润最大的）
  - `k=3, w=0, [1], [0]` → 1（单项目）
  - `k=2, w=0, [0,0], [0,0]` → 0（利润全 0，做与不做一样）
  - `k=10, w=0, [1,2,3], [0,1,2]` → 6（`k` 比项目数多，做完就停）
- 30 秒自检：能不能说出"按门槛排序、指针只前进、堆里放买得起的、堆顶即本轮该做的"这四步？

## 专题10-4. 跳跃游戏 II（回顾）

> 第一册已精讲：[分册 D · D6 跳跃游戏 II](13-分册D-动态规划贪心二分回溯.md)
> 力扣 45 · 贪心（BFS 分层）· Medium

### 精讲（零基础版）

#### ① 这题要用到的东西

**"层"（BFS 分层）**

一句话：跳 1 次能到的位置叫第一层，跳 2 次能到的叫第二层，答案是"终点在第几层"。

生活类比：往湖里扔石头，第一圈涟漪、第二圈涟漪 —— 圈数就是扔了几次。

**`end` 和 `farthest`**

一句话：`end` 是"这一层最远铺到哪"，`farthest` 是"扫这一层时，下一层最远能铺到哪"。

生活类比：铺地毯，`end` 是这一卷铺到的位置，`farthest` 是下一卷最多能铺到哪。

```python
nums = [2, 3, 1, 1, 4]
jumps = end = farthest = 0
for i in range(len(nums) - 1):
    farthest = max(farthest, i + nums[i])
    if i == end:                 # 这一层扫完了
        jumps += 1
        end = farthest
print(jumps)                     # -> 2
```

#### ② 大白话：这题到底在干什么

最笨的办法：算出"到每一格最少跳几步"，第 i 格 = 能一步跳到 i 的所有格子里最小的那个 + 1。对，但每格都要回头看前面所有格子，n 是 1 万时就是 1 亿次。

笨在哪？**它记下了"从哪跳过来"这种没用的信息**，而题目只问跳几次。

聪明的办法：同一层那么多落点，只有最远的那个有用 —— 能跳到近处，就一定能跳过它去更远。于是只留两个数：这一层铺到哪、下一层最远能铺到哪。扫到 `end` 说明这一层用完，步数 +1，`end` 换成 `farthest`。

**30 秒回顾**：维护两个量——`end` 是"当前这一跳能覆盖的最右边界"，`farthest` 是"扫描过程中见过的最远落点"。`i` 走到 `end` 就说明这一层用完了，`jumps += 1`，`end` 更新为 `farthest`。循环只扫到 `n-2`。时间 O(n)，空间 O(1)。

**核心代码（背这一段就够）**：

```python
from typing import List

class Solution:
    def jump(self, nums: List[int]) -> int:
        jumps = 0
        end = 0          # 当前这一跳最远能落到的位置
        farthest = 0     # 扫描过程中能跳到的最远位置
        for i in range(len(nums) - 1):
            farthest = max(farthest, i + nums[i])
            if i == end:
                jumps += 1
                end = farthest
        return jumps
```

**换个角度**：

- 这题本质是 **BFS 的层数**：跳 1 次能到的位置是第一层，跳 2 次能到的是第二层，层数就是答案。区别只在于 BFS 用队列存"每一层有哪些点"，这里用一个整数 `farthest` 存"这一层最远到哪"——因为同一层里的点，只有最远的那个有用。
- 和 DP 的对比值得说一句：`dp[i] = 1 + min(dp[j])` 是 O(n²)，因为它保留了"从哪跳过来"的信息；贪心 O(n)，因为它只保留"最远能到哪"。**信息丢得越多越快，但丢掉的那些必须真的没用**——这就是贪心的代价结构。
- 面试追问常问"**要输出具体跳法**"：在每次 `i == end` 时把当时的落点记下来，或者从后往前反推（从终点找最左边能一步到它的位置）。
- 如果规则改成"**必须恰好跳 `nums[i]` 步**"：分层就失效了（能到的位置不再是一段连续区间），贪心不成立，只能 BFS 或 DP。
- 边界：`n == 1` 时答案是 0，代码靠 `range(0)` 空转自动处理，不需要特判——但你要能说清"为什么不需要"。

## 专题10-5. 跳跃游戏（回顾）

> 第一册已精讲：[分册 D · D7 跳跃游戏](13-分册D-动态规划贪心二分回溯.md)
> 力扣 55 · 贪心 · Medium

### 精讲（零基础版）

#### ① 这题要用到的东西

**`enumerate`**

一句话：一边遍历元素，一边把下标也递给你。

```python
for i, x in enumerate(["a", "b", "c"]):
    print(i, x)        # -> 0 a / 1 b / 2 c
```

等价于 `for i in range(len(x))` 再取 `x[i]`，但少写一行。这题里就是"第 i 格，上面写着能跳 step 步"。

**`farthest`（最远可达位置）**（前面 10-4 讲过）：一个整数代表"目前能摸到的最右位置"。这题只维护它一个，连"层"都不数。

#### ② 大白话：这题到底在干什么

最笨的办法：从第 0 格出发做一次搜索，把能到的格子全标记上，最后看终点有没有被标记。对，但要拿队列存"待处理的格子"，n 大时又慢又费地方。

笨在哪？**它把"能到的格子"当成一堆散点存着**，而这些点其实有结构。

聪明的办法：能到的位置一定连成一段，从 0 开始，中间没有洞 —— 只要能跳到 p，p 左边每一格就都踩得到。既然是一段连续区间，一个整数 `farthest` 就够表示它。每走到第 i 格，先问 `i > farthest`：成立说明这格根本到不了，返回假；不成立就用 `i + step` 更新 `farthest`。整趟只扫一遍。

**30 秒回顾**：只维护一个 `farthest`。遍历时先判断 `i > farthest`——超出了就永远到不了，返回 `False`；否则用 `i + nums[i]` 更新 `farthest`。时间 O(n)，空间 O(1)。

**核心代码（背这一段就够）**：

```python
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        farthest = 0
        for i, step in enumerate(nums):
            if i > farthest:
                return False
            farthest = max(farthest, i + step)
        return True
```

**换个角度**：

- 这题能 O(n) 的**根本原因**是：可达位置一定是一段**从 0 开始的连续区间** `[0, farthest]`。证明只有两句——若 `farthest` 由位置 `p` 产生（`p + nums[p] = farthest`），那么 `0..farthest` 里任意 `q` 都可达：先走到 `p`（`p` 本身可达），再从 `p` 一步跳到 `q`（因为 `q <= p + nums[p]`）。**区间内部没有洞**，所以一个整数就能代表整个集合。
- 一旦规则让区间出现洞（比如"只能跳到指定的几个位置"），这个整数就不够用了，必须上 BFS。这也是判断"这题能不能贪"的通用方法：**看你要维护的集合能不能被一个数概括**。
- 还有一条**反向**的写法，很多人没想过：从右往左扫，维护 `last_good`（最左边那个能到达终点的位置），若 `i + nums[i] >= last_good` 就令 `last_good = i`，最后看 `last_good == 0`。同样是 O(n) O(1)，但思路是"从终点往回找靠山"，和正向的"从起点往前推"正好对称。
- 和 45 的关系：45 数"滚了几层"，55 只看"滚到哪"。两者共用 `farthest`，所以 55 的代码是 45 删掉 `end` 和 `jumps` 之后的残骸。
- 边界：`[0]` 返回 `True`（已经站在终点），`[0,1]` 返回 `False`（第一步就动不了）。

## 专题10-6. 加油站（回顾）

> 第一册已精讲：[分册 D · D8 加油站](13-分册D-动态规划贪心二分回溯.md)
> 力扣 134 · 贪心（前缀和）· Medium

### 精讲（零基础版）

#### ① 这题要用到的东西

**前缀和**

一句话：从开头一路加过来，每加一个就记一笔，那串累计值叫前缀和。

生活类比：跑步看计步器，`1、3、6、10` 是每段跑完的累计距离，不是这一段跑了多少。

```python
diff = [1, -2, 3]      # 每站净赚（gas - cost）
total = 0
for d in diff:
    total += d         # 前缀和：从第 0 站加到当前站
    print(total)       # -> 1 / -1 / 2
```

这题里的 `tank` 就是"从当前起点开到这里还剩多少油"，本质是一段前缀和；它一旦变负，这段路就开不过去。

**差值 `gas[i] - cost[i]`**：这一站净赚多少油。加 5 升、开到下一站烧 3 升，净赚 2 升。

#### ② 大白话：这题到底在干什么

最笨的办法：每站都当起点试一遍，模拟开一整圈。n 站、每站走 n 步，O(n²)，n 是 10 万时就是 100 亿次。

笨在哪？**试第 2 站时，第 1 站走过的路又走了一遍**。

聪明的办法：先看总量，总油比总消耗少就直接返回 -1。然后从第 0 站累加净赚，一旦变负，说明"从当前起点开到这里"这段一定过不去 —— 而且这段里任何一站当起点都不行，因为从更靠后的站出发只会少赚前面那几站的油。所以起点直接挪到下一站，累加清零。每站只看一眼，O(n)。

**30 秒回顾**：令 `diff[i] = gas[i] - cost[i]`。先判总量：`sum(gas) < sum(cost)` 直接返回 -1。然后从 0 开始累加 `tank`，一旦 `tank < 0`，说明 `start` 到 `i` 之间任何一站都不能当起点，把 `start` 跳到 `i+1` 并把 `tank` 清零。时间 O(n)，空间 O(1)。

**核心代码（背这一段就够）**：

```python
from typing import List

class Solution:
    def canCompleteCircuit(self, gas: List[int], cost: List[int]) -> int:
        if sum(gas) < sum(cost):
            return -1
        start = 0
        tank = 0
        for i in range(len(gas)):
            tank += gas[i] - cost[i]
            if tank < 0:
                start = i + 1
                tank = 0
        return start
```

**换个角度**：

- 这题和"最大子数组和"是同一类东西：都在找"哪一段前缀和能一直保持非负"。区别是最大子数组和要的是最大的那段和，这里要的是"绕一整圈都不为负"的起点。**前缀和变负就整段作废**，这个动作两题共用。
- 为什么"`tank` 变负就能一次排除一整段"值得再想一遍：设从 `start` 累加到 `i` 首次变负。对 `start` 和 `i` 之间的任意 `k`，从 `k` 开到 `i` 的净油量 = `(start→i 的净油量) - (start→k-1 的净油量)`。前一项是负的，后一项非负（因为 `i` 是首次变负），负减非负只会更负。所以这一整段全部出局，起点至少是 `i+1`。
- 一个容易忽略的细节：`tank = 0` 必须写在 `if` 里面。换起点后如果还带着上一段的亏损，后面所有判断都会偏。
- 变体：如果题目**不保证答案唯一**，那要返回所有可行起点。这时的等价刻画是"`start` 必须是前缀和取到全局最小值的那个位置的下一个"，所以要把所有取到最小值的位置都算一遍——`start` 一路推到 `n` 的写法只给最后一个，不够用。
- 变体：如果油箱有容量上限，贪心结论不再成立（"先亏后赚"的段可能因为装不下而爆掉），要上更复杂的模型。
