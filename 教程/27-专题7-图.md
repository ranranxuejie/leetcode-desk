# 专题 7：图

**本册覆盖**：7-1 单词接龙（127）、7-2 克隆图（133）、7-3 课程表 II（210）、7-4 无向图中连通分量的数目（323）、7-5 冗余连接（684）、7-6 腐烂的橘子（994）；回顾 7-7 岛屿数量（200）、7-8 课程表（207）。

## 本册地图

这八道题看起来分了四拨——最短路、深拷贝、拓扑排序、连通块——其实是同一件事的四种问法：**先把题目翻译成"点和边"，再看你要的是"最少的步数"还是"连不连通"**。

- **BFS 求最短**（7-1、7-6，回顾 7-7）：边不带权时，BFS 第一次到达就是最短。7-1 难在建模，7-6 难在"多个起点"。
- **拓扑排序**（7-3，回顾 7-8）：有向图、有先后约束时用它，顺便判环。
- **并查集**（7-4、7-5）：只关心"连不连通"、不关心"怎么连"时用它，比 DFS 短。
- **遍历本身**（7-2）：图的遍历加一张"原→新"的哈希表，防止重复和死循环。

建议顺序：第 0 章（世界观）→ 7-2 → 7-6 → 7-3 → 7-4 → 7-5 → 7-1（建模那一步最容易卡住，放最后）。7-7、7-8 只读"换个角度"。

和 [分册 C](12-分册C-链表树图.md) 的关系：那边 0.5 节第一次介绍图，讲"邻接表长什么样"；本册讲"拿到一道题，怎么看出它是图"。

**本册要建立的思维模型**

1. **图 = 点 + 边，题目不会告诉你谁是点**。单词、课程、格子、橘子都可能是点，能不能"一步到"决定有没有边。
2. **网格图不用建邻接表**：每个格子是一个点，上下左右四个邻居就是它的边，越界就是没有边。
3. **DFS 管"有没有/有几块"，BFS 管"最少几步"**。要求最短步数时用 DFS 一定错，除非你把所有路径都枚举一遍。
4. **BFS 的队列是按距离排队的**，所以第一次到达某个点时，走的就是最少的边数。
5. **并查集只回答一个问题：你和我是不是一伙的**。它不记录路径，所以比 DFS 快，但也问不出路径。

## 第 0 章 先把"图"这个世界观建起来

### 0.1 图就是"点"和"点之间的线"

一张图只有两样东西：**节点**和**边**。地铁线路图就是标准的图：站点是节点，相邻两站之间的轨道是边。

边可以带方向，也可以不带：

- **无向边**：`1 — 2` 和 `2 — 1` 是同一件事。好友、地铁、岛屿的相邻格子都是无向的。
- **有向边**：`1 → 2` 表示只能从 1 走到 2。先修课就是有向的：上了 A 才能上 B，反过来不成立。

本册里 127、133、323、684、994、200 是无向的，207、210 是有向的。**分不清有向无向，代码就会写反**。

### 0.2 两种表示法，只学两种就够

**第一种：邻接表**。给每个点开一个 list，装它能一步走到的所有点。

```python
graph = [[] for _ in range(n)]     # n 个点，每个点一个空 list
for a, b in edges:                 # 一条无向边
    graph[a].append(b)
    graph[b].append(a)             # 有向图就只写上面那一行
```

`graph[3] = [1, 5]` 读作"3 号点能一步走到 1 和 5"。遍历整张图，就是"从某个点出发，看它的 list，再对 list 里每个点重复"。注意 `[[] for _ in range(n)]` 不能写成 `[[]] * n`：后者是同一个 list 被引用 n 次，往任意一行加边，所有行都会变。

**第二种：网格图，不建表**。给你一个 `m × n` 的二维数组，每个格子是一个点，上下左右相邻就是有边：

```python
for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
    nx, ny = x + dx, y + dy
    if 0 <= nx < m and 0 <= ny < n and grid[nx][ny] == "1":
        ...
```

这四行就是网格图的邻接表，`0 <= nx < m` 是在说"这条边不存在"。200、994 都用这个骨架，一个字不用改。

### 0.3 DFS 和 BFS，各自负责什么

两种遍历都是"从一个点出发，把所有能走到的点走一遍"，区别只在**先走哪条**：

- **DFS**：一条路走到黑，走不动了退回上一个路口换一条。用递归写，递归会帮你记住每个路口。
- **BFS**：先把一步能到的全走完，再走两步能到的，像水波一圈圈扩散。用队列写。

分工很清楚：

| 你要的东西 | 用哪个 | 为什么 |
|---|---|---|
| 有几个连通块 / 某块多大 | DFS 或 BFS 都行 | 只要走遍，顺序无所谓 |
| A 能不能走到 B | DFS 或 BFS 都行 | 同上 |
| 从 A 到 B 最少几步 | **只能 BFS** | DFS 走到的第一条路不一定最短 |
| 所有路径 / 所有方案 | DFS + 回溯 | BFS 不记录"怎么来的" |
| 只问连不连通、边还在动态增加 | 并查集 | 每次加边不用重跑整张图 |

### 0.4 为什么 BFS 第一次到达就是最短

这是本册最需要想透的一句话，127、994 全靠它。

队列先进先出，而 BFS 又是"把当前点的所有邻居塞到队尾"。两条合起来产生一个性质：**队列里的点，是按"离起点的边数"从小到大排的**。

于是可以分层看：

```
第 0 层: 起点
第 1 层: 起点一步能到的所有点
第 2 层: 第 1 层一步能到、且前面没出现过的点
...
```

第 k 层里的每个点，离起点**恰好** k 步——不可能更少，更少的话它早就在更早的层被发现了；也不可能更多，它是由第 k-1 层的点一步走到的。

所以第一次把 `endWord` 放进队列时，它所在的层号就是最短距离。**这个"第一次"是唯一的，之后不会出现更短的路径**：BFS 从不回头修正已经确定的距离。994 里"层数 = 分钟数"是同一个道理。

## 7-1. 单词接龙（Hard）

> 力扣 127 · 图 · BFS · 隐式图建模
> 前置：第 0 章 0.3、0.4

**一句话**：每次只改一个字母，把 `beginWord` 变成 `endWord`，问最短的那条变换序列一共有几个词。

### 精讲（零基础版）

#### ① 这题要用到的东西

**图（graph）：点 + 边**

一句话：图就是一堆"点"和"点之间的连线"。地铁线路图就是图：站是点，相邻两站之间的轨道是边。

这题里，**每个单词是一个点**，两个单词只差一个字母就连一条边。题面说"每次只改一个字母"，就是在描述边。这种"题目不给你图、让你自己把对象和关系翻译成点和边"的题，叫**隐式图**——图不在输入里，在你脑子里。

**BFS（广度优先搜索）**

一句话：从起点出发，先把一步能到的全走完，再走两步能到的，像水波一圈圈往外扩。用**队列**实现。

生活类比：往池塘里扔块石头，波纹先到 1 米、再到 2 米。所以"某个点第一次被波纹碰到"时，波纹走过的距离就是最短距离。

这题里每条边都代表"改一次字母"，代价一样，所以第一次碰到 `endWord` 时的层数就是最短答案。反过来，DFS（一条路走到黑）找到的第一条路不一定最短——这是本册最容易踩的坑。

**队列 `deque`**

一句话：从队尾进、从队头出，先进先出。

```python
from collections import deque
q = deque([("hit", 1)])
print(q.popleft())     # -> ('hit', 1)
```

`popleft()` 把队头**拿走**并返回。这题队列里存的是 `(单词, 到它用了几个词)` 这样的元组。

**`set`：查得快**

一句话：`set` 是"只存键、不存值"的集合，判断"某个东西在不在里面"是 O(1)，比 list 的 O(n) 快得多。

```python
words = {"hot", "dot"}
print("hot" in words)    # -> True
print("hut" in words)    # -> False
```

这题里 `set(wordList)` 是性能分水岭：每个单词要试 260 个候选，用 list 查就是上百万次比较。

**字符串切片拼接 `word[:i] + c + word[i+1:]`**

一句话：`word[:i]` 是"前 i 个字符"，`word[i+1:]` 是"第 i 位之后的全部"，中间夹上 `c`，就得到"只改第 i 位"的新词。

```python
w = "hot"
print(w[:1] + "a" + w[2:])   # -> hat   改下标 1 那一位
print(w[:0] + "a" + w[1:])   # -> aot   改下标 0 那一位
```

#### ② 大白话：这题到底在干什么

最笨的办法：从起点出发，枚举所有"改一个字母"能得到的新词，留下在字典里的，再对每个新词重复。这个描述其实已经很接近答案，但它有两个说不清的地方：什么时候停？怎么知道哪条路最短？

笨在哪？如果你按"一条路走到黑"的方式去试，第一条走通的路可能绕了远路。词表里加几个干扰词，那种走法就会给你一条 10 个词的路径，而正确答案是 5。

聪明的办法：**按层推进**。第 1 层是起点自己，第 2 层是所有"改一个字母就能变成、且在字典里"的词，第 3 层是第 2 层再改一个字母能到的……因为是一层一层推的，**某个词第一次出现在第几层，它就是几步能到**。第一次看到 `endWord`，直接返回它的层数，不用再往下找。

两个细节。第一，不用真的把图建出来：5000 个词两两比较是 1250 万对，扩展的时候现场造邻居便宜得多。第二，一个词进了队列就立刻打上"来过"的标记，否则图里有环（`hit → hot → hit`），会在原地来回走。

#### ③ 示例 1 走一遍

`beginWord = "hit"`，`endWord = "cog"`，`wordList = ["hot","dot","dog","lot","log","cog"]`

| 层 | 这一层弹出的词 | 队列里剩下什么 |
|---|---|---|
| 1 | `hit` | `[(hot, 2)]` |
| 2 | `hot` | `[(dot, 3), (lot, 3)]` |
| 3 | `dot`、`lot` | `[(dog, 4), (log, 4)]` |
| 4 | `dog`、`log` | `[(cog, 5)]` |
| 5 | `cog` | `[]` |

弹出 `cog` 时它带的步数是 5，所以答案是 5。注意 `dog` 和 `log` 都在第 4 层：它们是两条不同的最短路，长度一样，走哪条都行。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `word_set = set(wordList)` | 字典换成 set，查一个词在不在是 O(1) |
| `if endWord not in word_set: return 0` | 终点根本不在字典里，怎么变都变不到 |
| `q = deque([(beginWord, 1)])` | 队列里存 (单词, 到它用了几个词)，起点自己算 1 个 |
| `visited = {beginWord}` | 起点先打标记，不然第一步就会走回自己 |
| `word, steps = q.popleft()` | 从队头拿一个词，它离起点 steps 步 |
| `if word == endWord: return steps` | 第一次碰到终点，这个步数就是最短 |
| `for i in range(len(word)):` | 枚举改哪一位 |
| `nxt = word[:i] + c + word[i + 1:]` | 拼出"只改第 i 位"的新词 |
| `if nxt in word_set and nxt not in visited:` | 两个条件：新词合法 + 没来过 |
| `visited.add(nxt)` | **入队之前就标记**，不是出队才标记 |
| `q.append((nxt, steps + 1))` | 新词进队，步数加 1 |
| `return 0` | 队列空了还没碰到终点，说明走不通 |

### 考什么

- 表面考点：字符串逐位替换。
- 真正考点：**题目没有给你图，图要自己建**。建完之后它就是一道标准的无权图最短路，BFS 十行写完。这题的坑集中在"看出这是图"这一步。
- 为什么标 Hard：建模这一步没有套路可套，而且很容易一头扎进"两两比较建图"这条死路——方向错了，后面写多快都没用。
- 面试官想听到的关键句：① 每个单词是一个点，只差一个字母的两个单词之间连一条边；② 边权都是 1，所以 BFS 第一次碰到 `endWord` 时的层数就是最短。

### 思路是怎么想出来的

- **最笨的想法**：从 `beginWord` 出发，枚举所有"改一个字母"能得到的新词，留下在字典里的，再对每个新词重复。这个描述其实已经很接近答案了，但它有两个说不清的地方：什么时候停？怎么知道哪条路最短？
- **关键观察一（建模）**：把每个单词看成一个点，两个单词只差一个字母就在它们之间连一条边。那么"转换序列"就是图上的一条路径，"最短转换序列"就是最短路径，路径上有几个点就是答案。这一步做完，题面里"转换序列"那些绕口的措辞可以全忘掉。

  怎么想到这一步：题面里"每一对相邻的单词只差一个字母"这句话，本身就是在描述边。凡是题目用"只差一个 / 相邻 / 一步能到 / 必须先于"这类说法去描述两个对象的关系，基本都可以翻译成图——对象是点，关系是边。这句话值得单独记下来，本册八道题全靠它。

- **关键观察二（别真的建图）**：直觉上应该先把图建出来，但 5000 个单词两两比较是 1250 万对，每对还要比 10 个字符。换个方向：**不建图，在 BFS 扩展的时候现场造邻居**——把当前单词的第 i 位换成 `a`~`z` 的每个字母，看新词在不在字典的 set 里。每个词最多产生 26×L 个候选，L ≤ 10，比两两比较便宜得多。
- **为什么必须是 BFS**：每条边都代表"一次变换"，代价相同，正是 0.4 节说的那种情况。DFS 也能找到一条路，但那条路可能绕了远路——我实测过，加几个干扰词之后 DFS 给出 10，正确答案是 5。
- **双向 BFS（知道就行）**：从 `beginWord` 和 `endWord` 两头同时扩展，每次挑当前层更小的那一侧扩一层；某个新词如果出现在另一侧的已访问集合里，说明两边接上了，答案是两侧层数之和。搜索量从 b^d 降到大约 2·b^(d/2)。面试说清这个思路就够，不必手写。

示例 1 的图长这样（一条边 = 两个词只差一个字母）：

```
        hit
         │
        hot
       ╱   ╲
     dot   lot
      │     │
     dog   log
       ╲   ╱
        cog
```

两条最短路都是 5 个词：`hit → hot → dot → dog → cog`，`hit → hot → lot → log → cog`。BFS 分层走一遍：

```
第 1 层: hit                      起点，1 个词
第 2 层: hot                      hit 换一个字母，只有 hot 在字典里
第 3 层: dot, lot
第 4 层: dog, log
第 5 层: cog                      ← 第一次出现，返回 5
```

### 代码（Python）

```python
from collections import deque
from typing import List

class Solution:
    def ladderLength(self, beginWord: str, endWord: str, wordList: List[str]) -> int:
        word_set = set(wordList)              # 查一个词在不在，O(1)
        if endWord not in word_set:           # 终点不在字典里，永远变不过去
            return 0

        q = deque([(beginWord, 1)])           # (当前单词, 到这里用了几个词)
        visited = {beginWord}                 # 入队即标记，起点先标记

        while q:
            word, steps = q.popleft()
            if word == endWord:
                return steps

            for i in range(len(word)):        # 枚举改哪一位
                for c in "abcdefghijklmnopqrstuvwxyz":   # 这一位换成什么
                    nxt = word[:i] + c + word[i + 1:]
                    if nxt in word_set and nxt not in visited:
                        visited.add(nxt)      # 关键：入队的同时就标记
                        q.append((nxt, steps + 1))
        return 0                              # 队列空了还没到，说明走不通
```

**逐段讲解**：

- `word_set = set(wordList)`：`in` 在 list 上是 O(N)，5000 个词、每个词 260 个候选，用 list 会多出上百万次比较。set 是 O(1)，这行是性能的分水岭。
- `if endWord not in word_set: return 0`：终点不在字典里，怎么变都变不到。这是剪枝，不是必需（BFS 跑完也会返回 0），但能省掉一整轮搜索。
- `q = deque([(beginWord, 1)])`：队列里存"单词 + 到它为止用了几个词"。起点自己算 1 个词，所以初值是 1 而不是 0。
- `visited = {beginWord}`：**起点在入队前就标记**。图里有环（`hit → hot → hit`），不标记就会来回走。
- 三层循环：外层弹队列，中层枚举位置 `i`，内层枚举 26 个字母。`nxt = word[:i] + c + word[i+1:]` 用切片拼接，比"转成 list、改一位、再 join"短。
- `if nxt in word_set and nxt not in visited`：两个条件缺一不可。前者保证新词合法，后者保证同一个词不会被反复入队。
- `visited.add(nxt)` 写在 `append` 之前，也就是**入队即标记**。这一点在 127 里格外要紧：我拿 26 个两两相邻的词试过，出队才标记的队列峰值是 721，入队就标记是 25，答案都是 2。词表一大，前者就是超时。
- `if word == endWord: return steps` 放在弹出时判断。也可以放在入队时判断，两种写法都对，前者少一个分支。

### 复杂度

- 时间 O(N · 26 · L²)：N 个词各出队一次，每个词试 26·L 个候选，每次拼字符串要 O(L)。N = 5000、L = 10 时大约 1300 万次字符操作，Python 能过。
- 空间 O(N · L)：`visited` 和队列最多各存 N 个词，每个词 L 个字符。
- 想要更紧的界：把"枚举 26 个字母"换成预处理通配符索引（`h*t` → 所有匹配的词），建索引 O(N·L²)，每次查邻居 O(L)。这是空间换时间。

### 常见误区（★ 最容易丢分的地方）

1. **先两两比较建图**：5000 个词是 1250 万对，每对还要逐字符比较，Python 里必超时。正确做法是现场造邻居。
2. **出队才标记 `visited`**：就是上面那组 721 vs 25 的实测数据。图越密，队列膨胀得越夸张。
3. **用 DFS 找路径**：DFS 找到的第一条路不保证最短。我在示例 1 的图上加了 `ait/bit/cit/dit` 四个干扰词，DFS 按字母序先走了一条 10 个词的弯路，而正确答案是 5。
4. **写了 `if beginWord not in word_set: return 0`**：题面明确说 `beginWord` 不需要在 `wordList` 中。加上这一句，示例 1 直接返回 0。
5. **返回值差 1**：路径长度数的是**词数**，包含 `beginWord` 和 `endWord`，`hit → cog` 是 5 不是 4。用"队列里存步数"的写法就不会在 `steps` 和 `steps + 1` 之间犹豫。

### 面试追问 / 变体

- 要输出具体路径：BFS 时记 `parent[nxt] = word`，到达后从 `endWord` 往回走，再反转。
- 要输出**所有**最短路径（力扣 126）：先用 BFS 算出每个词的距离，再用 DFS 只沿"距离 +1"的边回溯。
- 单词特别长、字典特别大：用通配符索引，把"枚举 26 个字母"换成"查这个 pattern 下的所有词"。
- 双向 BFS：多写二十行，搜索量显著下降；面试说出思路即可。

### 自测

- 必测用例：示例 1 → 5；示例 2 → 0；`"ab","cd",["ad","cd"]` → 3；`"hot","dog",["hot","dog"]` → 0（差两个字母，没有边）；`"ab","ad",["ab","ad"]` → 2（直接相邻）。
- 30 秒自检：能不能说出"点和边分别是什么"、"为什么不能先建图"、"为什么必须 BFS"。

## 7-2. 克隆图（Medium）

> 力扣 133 · 图 · 遍历 + 哈希表
> 前置：第 0 章 0.2

**一句话**：给你一个连通无向图里的某个节点，返回一份完全独立的深拷贝——新图里的每个节点都是新对象，但连法一模一样。

### 精讲（零基础版）

#### ① 这题要用到的东西

**深拷贝和浅拷贝**

一句话：浅拷贝只复制"外面那层壳"，里面的东西还是同一批；深拷贝是把里面的东西也全部新造一份，改新的不影响旧的。

```python
a = [1, 2]
b = a            # 根本不是拷贝，是同一个列表的第二个名字
c = list(a)      # 浅拷贝：新列表，但元素还是原来那些
b.append(3)
print(a)         # -> [1, 2, 3]   改 b 就是改 a
print(c)         # -> [1, 2]
```

这题要的是深拷贝：新图里每个节点都是**新对象**，只把"连法"抄过来。所以不能 `return node`，也不能 `Node(node.val, node.neighbors)`（那样新节点的邻居还指着旧图）。

**对象和"按身份认人"**

一句话：`Node(1)` 造出来是内存里的一个东西。它的 `val` 是 1，但两个 `val` 都是 1 的 Node 是两个不同的人。

这题里，判断"这个节点我克隆过没有"必须按**对象身份**认，不能按 `val` 认。dict 的键默认按身份比，所以 `cloned[原节点] = 新节点` 天然正确。

```python
d = {"a": 1}
print(d.get("b"))    # -> None    没有就返回 None，不报错
print("b" in d)      # -> False
```

**`Optional[Node]` 和 `if not node`**

一句话：`Optional[X]` 意思是"要么是 X，要么是 None"。`if not node` 就是"如果 node 是 None"——空图直接返回 `None`。

**BFS / 队列**（前面 7-1 讲过）：用队列一层层往外扩，每弹出一个点就处理它的邻居。这题不关心"最短"，只用它"能把整张图走一遍"。

#### ② 大白话：这题到底在干什么

最直接的想法：遍历原图，给每个节点新造一个，把邻居照抄过去。这个想法有两个洞。

第一个洞：图有环（1 连着 2，2 又连回 1）。照着抄会顺着边一直往下走，永远走不完，就是死循环。

第二个洞：同一个节点会从好几条路被走到，你会给它抄出好几份，克隆图里出现重复节点，谁连谁全乱。

聪明的办法：准备一张"身份证登记表" `cloned`，记"原节点 → 新节点"。第一次见到某个原节点，就造一个新的、登记上去；之后再见到它，直接从表里取，不再造。

这张表顺便把死循环也解决了：它同时是"来过没有"的标记。走到一个已经登记过的节点，就知道不用再往下钻。

还有一个顺序要求：**必须先登记自己，再去处理邻居**。反过来"先把邻居都处理完、再登记自己"，1 还没登记就进了 2，2 又进 1，还是死循环。

#### ③ 示例 1 走一遍

四个点围成一个环：`adjList = [[2,4],[1,3],[2,4],[1,3]]`，起点是节点 1。

| 弹出 | 它的邻居 | 新建了谁 | 队列 |
|---|---|---|---|
| 1 | 2、4 | `2'`、`4'` | `[2, 4]` |
| 2 | 1、3 | `3'`（1 已在表里） | `[4, 3]` |
| 4 | 1、3 | 无（都在表里） | `[3]` |
| 3 | 2、4 | 无 | `[]` |

所以最后登记表里有 4 个新节点，每个原节点对应一个。注意弹出 4 的时候，它的邻居 3 已经在表里了（3 是在处理 2 的时候被造的），所以不新建、不入队，但**边还是要连**。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `if not node: return None` | 空图直接返回 None |
| `cloned = {node: Node(node.val)}` | 登记表：起点先造好、先登记 |
| `q = deque([node])` | 待处理的队列，装的是**原图**的节点 |
| `cur = q.popleft()` | 拿出一个原节点 |
| `for nb in cur.neighbors:` | 看它的每个邻居 |
| `if nb not in cloned:` | 第一次见这个邻居 |
| `cloned[nb] = Node(nb.val)` | 造一个新的、登记上 |
| `q.append(nb)` | 新造的也要继续处理它的邻居 |
| `cloned[cur].neighbors.append(cloned[nb])` | 连边。**这行在 if 外面**：邻居是新的要连，是旧的也要连 |
| `return cloned[node]` | 返回起点对应的那个新节点 |

### 考什么

- 表面考点：图的遍历。
- 真正考点：**遍历图的时候，每个节点只能被创建一次**。图有环，同一个节点会从多条路被走到；你需要一张"原节点 → 新节点"的哈希表，它同时兼任 `visited`。
- 面试官想听到的关键句：① 哈希表存"原节点 → 新节点"，既防重复创建又防死循环；② 创建新节点必须在访问它的邻居之前完成（先登记，再处理边）。

### 思路是怎么想出来的

- **最直接的想法**：遍历原图，给每个节点 `new` 一个，把邻居照抄。但这个想法有两个洞。第一，图有环（`1 → 2 → 1`），照着抄会无限递归。第二，同一个节点会被抄出好几份，克隆图里出现重复节点，谁连谁全乱。
- **关键观察**：需要一个"身份证"。第一次见到某个原节点时，创建它的克隆并登记到 `cloned[原] = 新`；之后再见到它，直接从表里取，不再创建。**这张表就是 `visited`**——不需要再开一个 set。
- **为什么必须先登记再处理邻居**：假设处理 1 的时候发现邻居 2，于是创建 2 并登记。等处理 2 的时候，它的邻居里有 1，此时 1 已经在表里了，直接取用——环就被切断了。如果反过来"先递归处理邻居再创建自己"，1 还没登记就进 2，2 又进 1，直接死循环。
- **用 BFS 还是 DFS**：都行，逻辑完全对称。这里用 BFS，因为不用考虑递归深度。

示例 1 的图：

```
   1 ─── 2
   │     │
   4 ─── 3
```

`adjList = [[2,4],[1,3],[2,4],[1,3]]`，四个节点首尾相连成一个环。走一遍 BFS：

```
cloned = {1: 1'}            q = [1]

弹出 1：邻居 2 不在表 → 建 2'，入队；1'.neighbors = [2']
        邻居 4 不在表 → 建 4'，入队；1'.neighbors = [2', 4']
弹出 2：邻居 1 在表 → 2'.neighbors = [1']
        邻居 3 不在表 → 建 3'，入队；2'.neighbors = [1', 3']
弹出 4：邻居 1 在表 → 4'.neighbors = [1']
        邻居 3 在表 → 4'.neighbors = [1', 3']
弹出 3：邻居 2 在表 → 3'.neighbors = [2']
        邻居 4 在表 → 3'.neighbors = [2', 4']
```

注意 `4` 处理时，`3` 已经在表里了（它是在处理 `2` 的时候被创建的），所以不用入队，但**边还是要连**。

### 代码（Python）

```python
from collections import deque
from typing import Optional

class Node:
    def __init__(self, val: int = 0, neighbors: list = None):
        self.val = val
        self.neighbors = neighbors if neighbors is not None else []

class Solution:
    def cloneGraph(self, node: Optional["Node"]) -> Optional["Node"]:
        if not node:
            return None                        # 空图（示例 3）

        cloned = {node: Node(node.val)}        # 原节点 -> 新节点，起点先登记
        q = deque([node])

        while q:
            cur = q.popleft()
            for nb in cur.neighbors:
                if nb not in cloned:           # 第一次见到这个原节点
                    cloned[nb] = Node(nb.val)
                    q.append(nb)               # 新节点也要继续处理它的邻居
                # 不管 nb 是新是旧，边都要连
                cloned[cur].neighbors.append(cloned[nb])

        return cloned[node]
```

**逐段讲解**：

- 力扣后台已经把 `Node` 定义好了，你只写 `class Solution`；本地跑要自己补这个类，所以上面写出来了。
- `if not node: return None`：示例 3 给的是空图，输入 `None`，直接返回 `None`。
- `cloned = {node: Node(node.val)}`：**起点在进入循环之前就登记好**。这一步是防死循环的关键：等环绕回起点时，`node in cloned` 为真，不会再建第二个起点。
- `if nb not in cloned`：只有第一次见到才创建并入队。`cloned` 同时充当 `visited`，不需要第二个集合。
- `cloned[cur].neighbors.append(cloned[nb])` 这一行在 `if` **外面**，是这题的灵魂。它对两种情况都要执行：邻居是新建的，要连；邻居早就存在（比如环上的回边），也要连。写进 `if` 里面，克隆图就会缺掉所有"指向老节点"的边——我实测过，示例 1 会变成 `[[2,4],[3],[],[]]`，节点 3 和 4 的边全丢了。
- 为什么用 dict 而不是 list：dict 的 key 是节点对象，默认按对象身份比较，不需要 `val` 唯一。如果题目保证 `val` 是 `1..100` 且不重复，用 `list` 按 `val` 索引也行，但 dict 更通用，换成"val 可能重复"的题也不用改。

### 复杂度

- 时间 O(V + E)：每个节点入队一次，每条边在两端各被检查一次。
- 空间 O(V)：`cloned` 存 V 个映射，队列最多 V 个节点。返回的克隆图本身占 O(V + E)，那不算额外空间。

### 常见误区（★ 最容易丢分的地方）

1. **`append` 写进 `if` 里面**：只在新建邻居时连边，回边全丢。示例 1 实测输出 `[[2,4],[3],[],[]]`。
2. **忘记先把起点放进 `cloned`**：BFS 版会在第一轮的 `cloned[cur]` 处直接 `KeyError`；如果写成"先递归处理邻居、回来再登记自己"的 DFS，就是无限递归。两种写法都在提醒同一件事：起点必须先登记。
3. **直接 `return node`**：返回的是同一个对象，等于没克隆。题目要的是"新对象 + 同样的连法"，面试官随手改一下克隆图就能看出来。
4. **只复制 `val`，`neighbors` 直接引用原列表**：`Node(node.val, node.neighbors)` 看起来像克隆，实际新节点指着原图的邻居，改一个影响另一个。我实测这种写法下新旧图共享全部 4 个节点。
5. **用 `val` 当 key 却没确认唯一**：本题 `val` 唯一所以能过，但换成"值可以重复"的图就错。用对象本身当 key 永远安全。

### 面试追问 / 变体

- 图不连通、一次给你一组节点：外层再套一层循环，对每个没登记过的节点启动一次 BFS。
- 带权图 / 有向图：结构完全一样，只是 `neighbors` 换成 `(邻居, 权重)` 或只存出边。
- 复制带随机指向的链表（力扣 138）：一模一样的套路——哈希表存"原节点 → 新节点"，先把所有新节点建出来，再补 `next` 和 `random` 两条引用。
- 为什么不能用 `id(node)` 当 key：`id` 是解释器给对象编的号，对象被回收之后这个号可能被别的对象复用；直接用对象本身当 key 更稳。

### 自测

- 必测用例：示例 1（4 节点环）→ 结构相同且新旧无共享节点；示例 2（单节点无邻居）→ `[[]]`；示例 3（空图）→ `None`；三角形 `[[2,3],[1,3],[1,2]]`；5 节点链 `[[2],[1,3],[2,4],[3,5],[4]]`。
- 30 秒自检：能不能说出"哈希表的 key 和 value 分别是什么"、"为什么必须先登记再处理邻居"、"哪一行最容易缩进错"。

## 7-3. 课程表 II（Medium）

> 力扣 210 · 图 · 拓扑排序（BFS / Kahn）
> 前置：第 0 章 0.1（有向边）

**一句话**：给一堆"上 A 之前必须先上 B"的约束，给出一个能上完所有课的顺序；上不完就返回空数组。

### 精讲（零基础版）

#### ① 这题要用到的东西

**有向边和"入度"**

一句话：有向边是带箭头的，`b → a` 表示"先 b 后 a"。一个点的**入度**就是"有几条箭头指向它"——在这题里读作"它还有几门先修课没上"。

```python
graph = [[] for _ in range(3)]     # 3 个点，每个点一个空 list
indegree = [0] * 3
for a, b in [[1, 0], [2, 1]]:      # 先 0 再 1，先 1 再 2
    graph[b].append(a)             # 边 b -> a：上完 b 才能上 a
    indegree[a] += 1               # a 多了一条指向它的箭头
print(graph)      # -> [[1], [2], []]   0 解锁 1，1 解锁 2
print(indegree)   # -> [0, 1, 1]        0 不用等，1 和 2 各等一门
```

**邻接表**

一句话：给每个点开一格，记它能一步走到谁。`graph[b]` 就是"b 上完之后能解锁的课"。

建表有个必须记住的坑：

```python
bad = [[]] * 3
bad[0].append(9)
print(bad)        # -> [[9], [9], [9]]   三行是同一个 list！
good = [[] for _ in range(3)]
good[0].append(9)
print(good)       # -> [[9], [], []]
```

`[[]] * 3` 是"同一个空 list 被引用了三次"，不是"三个空 list"。建图必须用 `[[] for _ in range(n)]`。

**拓扑排序**

一句话：把有先后关系的任务排成一个顺序，保证"先修永远排在后面那门的前面"。做法是每次挑一个"没人等它"（入度为 0）的任务做掉，做完把它解锁的任务的"等待数"减 1，减到 0 的就可以做了。

生活类比：穿衣服。先穿袜子再穿鞋。你不会一上来就排出"全部顺序"，你只会问"现在哪件能穿"——内衣能穿，穿完外套就能穿了。

这题里，课是点、先修关系是有向边，答案就是那个顺序。如果排不完（有环，互相等），返回空数组。

**生成器表达式 `deque(i for i in range(n) if ...)`**

一句话：和列表推导一样，只是不建中间列表，直接喂给 `deque`。等价于写个 for 循环往里 `append`。

#### ② 大白话：这题到底在干什么

最笨的办法：每一轮扫一遍所有课，找出"先修全都上过了"的课，上一门，再扫一遍。这样每上一门课都要重扫全图，O(n²)。

笨在哪？一门课现在能不能上，只取决于一个数字：**它的先修还剩几门没上**。上一门课只会影响它直接解锁的那几门，其他课的状态一点没变，重扫是白干。

聪明的办法：先把所有"一门先修都不用等"（入度 0）的课一次性放进队列。每次从队头取一门，记进答案，然后把它解锁的每门课的"等待数"减 1；谁减到 0 了，谁就可以进队。直到队列空。

为什么这样能判环：环上的课互相等对方先上，等待数永远减不到 0，一辈子进不了队列。所以最后数一数"上了几门"，比总数少就说明剩下的都在环里。

#### ③ 示例 2 走一遍

`numCourses = 4`，`prerequisites = [[1,0],[2,0],[3,1],[3,2]]`。

先建图：0 解锁 1 和 2；1 解锁 3；2 解锁 3。所以 `graph = [[1,2],[3],[3],[]]`，`indegree = [0,1,1,2]`。

| 弹出 | order | 入度数组 | 新入队 |
|---|---|---|---|
| 0 | `[0]` | `[0,0,0,2]` | 1、2 |
| 1 | `[0,1]` | `[0,0,0,1]` | 无 |
| 2 | `[0,1,2]` | `[0,0,0,0]` | 3 |
| 3 | `[0,1,2,3]` | `[0,0,0,0]` | 无 |

所以答案是 `[0,1,2,3]`。注意 3 的入度是 2——它要等 1 和 2 **都**上完，所以第 2 行减到 1 时还不入队，第 3 行才减到 0。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `graph = [[] for _ in range(numCourses)]` | 每门课一格，装它解锁的课 |
| `indegree = [0] * numCourses` | 每门课"还差几门先修" |
| `for a, b in prerequisites:` | b 是 a 的先修 |
| `graph[b].append(a)` | 边从 b 指向 a：上完 b 才能上 a |
| `indegree[a] += 1` | a 多了一个约束 |
| `q = deque(i for i in range(numCourses) if indegree[i] == 0)` | **所有**不用等的课都入队，不是只放 0 号 |
| `cur = q.popleft()` | 取一门现在能上的课 |
| `order.append(cur)` | 出队才代表"真的上了" |
| `indegree[nxt] -= 1` | 它的先修少了一门 |
| `if indegree[nxt] == 0: q.append(nxt)` | 减到 0 才入队；减一次就入队会重复 |
| `return order if len(order) == numCourses else []` | 少上了课，说明有环，返回空 |

### 考什么

- 表面考点：排课。
- 真正考点：**拓扑排序**。把课看成点、先修关系看成有向边，能排出一个"先修永远在前面"的顺序，就说明图里没有环。
- 面试官想听到的关键句：① 入度 = 还有几门先修没上；② 入度为 0 的课可以立刻上，上完把它指向的课入度减 1；③ 最后"上过的课数 == 总课数"才说明无环。

### 思路是怎么想出来的

- **暴力**：每一轮扫一遍所有课，找出"先修全都上过了"的课，上一门，再扫一遍。这是 O(n²)，而且每轮都要重新检查所有先修关系，重复劳动。
- **关键观察**：一门课现在能不能上，只取决于"它的先修还剩几门没上"这一个数字。这个数字就是**入度**（指向它的边数）。上完一门课，只会影响它指向的那些课——让它们的入度减 1。所以根本不用每轮重扫全图。
- **于是有队列**：把所有入度为 0 的课一次性放进队列（它们之间没有先后关系，谁先上都行）。每弹出一门，就把它指向的课入度减 1；减到 0 的课入队。这就是 **Kahn 算法**，也叫 BFS 拓扑排序。
- **为什么能判环**：环上的课互相等着对方先上，入度永远减不到 0，永远进不了队列。所以最后数一数"上过几门"，少于总数就说明剩下的都在环里。
- **为什么用队列而不是栈**：两种都能得到合法的拓扑序。队列（FIFO）得到的是"按层"的顺序，栈（LIFO）得到的是"一条链走到底"的顺序。本题任意顺序都算对。

示例 2 的图（边 `b → a` 表示先上 b 才能上 a）：

```
      0
     ╱ ╲
    1   2
     ╲ ╱
      3
```

```
indegree = [0, 1, 1, 2]        # 0 没人管；1、2 各等 0；3 等 1 和 2
q = [0]

弹出 0 → order=[0]，1 的入度 1→0 入队，2 的入度 1→0 入队     q=[1,2]
弹出 1 → order=[0,1]，3 的入度 2→1                          q=[2]
弹出 2 → order=[0,1,2]，3 的入度 1→0 入队                    q=[3]
弹出 3 → order=[0,1,2,3]                                    q=[]

len(order)=4 == numCourses → 返回 [0,1,2,3]
```

### 代码（Python）

```python
from collections import deque
from typing import List

class Solution:
    def findOrder(self, numCourses: int, prerequisites: List[List[int]]) -> List[int]:
        graph = [[] for _ in range(numCourses)]    # 邻接表：graph[b] 存 b 解锁的课
        indegree = [0] * numCourses                # 每门课还差几门先修

        for a, b in prerequisites:                 # b 是 a 的先修
            graph[b].append(a)                     # 边：b -> a
            indegree[a] += 1                       # a 多了一个约束

        q = deque(i for i in range(numCourses) if indegree[i] == 0)
        order = []

        while q:
            cur = q.popleft()
            order.append(cur)                      # 这门课现在可以上了
            for nxt in graph[cur]:                 # 它解锁的课
                indegree[nxt] -= 1
                if indegree[nxt] == 0:             # 先修全部满足，才能入队
                    q.append(nxt)

        return order if len(order) == numCourses else []
```

**逐段讲解**：

- `graph = [[] for _ in range(numCourses)]`：邻接表。不能写 `[[]] * numCourses`，那是同一个 list 被引用 n 次，加边会互相污染。
- `for a, b in prerequisites`：解包成 `a`（想上的课）和 `b`（先修课）。**方向别搞反**：边从 `b` 指向 `a`，因为"上完 b 才能上 a"，信息是从 b 流向 a 的。
- `q = deque(i for i in range(numCourses) if indegree[i] == 0)`：**所有**入度为 0 的课都要入队，不是只放 0 号。课程之间可能完全不连通，比如 `numCourses=3, prerequisites=[]`，三门课都该能上。
- `order.append(cur)` 在**出队时**做，不在入队时做。入队只代表"它已经解锁"，出队才代表"它真的被上了"。这个顺序在 210 里无所谓（入队即出队都合法），但在需要"边处理边输出"的题里必须分清楚。
- 邻居入度减 1，**只有减到 0 才入队**。减一次就入队会让同一门课重复入队，`order` 变长，最后的长度检查直接失效。
- `return order if len(order) == numCourses else []`：这行是判环。少上了一些课，说明那些课在环上互相等着，返回空数组。

### 复杂度

- 时间 O(V + E)：每门课入队出队各一次，每条边被检查一次。
- 空间 O(V + E)：邻接表存所有边，队列和入度数组各 O(V)，`order` 也是 O(V)。

### 常见误区（★ 最容易丢分的地方）

1. **忘了最后判环**：`numCourses=3, prerequisites=[[1,0],[0,1]]`（0 和 1 成环，2 是孤立的），不判环会返回 `[2]`，正确答案是 `[]`。这是本册最隐蔽的一个错——`[2]` 看起来"像个答案"。
2. **边建反**：写成 `graph[a].append(b)`。示例 2 实测输出 `[3,1,2,0]`，3 排在它自己的先修课前面，完全非法。
3. **只从 0 号课开始 BFS**：`numCourses=3, prerequisites=[[2,1]]` 时 0 号课和 1、2 都不连通，只从 0 开始会漏掉 1 和 2。必须把所有入度 0 的点都放进队列。
4. **`graph = [[]] * n`**：所有行是同一个 list，`graph[b].append(a)` 会把同一条边加到每一行上。
5. **入度减 1 后不管是不是 0 都入队**：同一门课被重复入队，`len(order)` 可能超过 `numCourses`，判环失效。
6. **拿并查集判有向环**：不行。并查集只能回答"无向意义上连不连通"，有向图里 `a → b` 和 `b → a` 含义完全不同，并查集看不见方向。

### 面试追问 / 变体

- 只要判断能不能上完（力扣 207）：把 `order` 换成计数器，最后比较 `taken == numCourses`，见 7-8。
- 要求**字典序最小**的上课顺序：把 `deque` 换成 `heapq`，其余一行不改。
- 用 DFS 写拓扑排序：后序遍历，节点在"子树全处理完"时加入结果，最后把结果反转。
- 课程表 III（力扣 630）不是这题：那题是"在截止时间内最多上几门"，用贪心 + 堆，和图无关。

### 自测

- 必测用例：`2, [[1,0]]` → `[0,1]`；`4, [[1,0],[2,0],[3,1],[3,2]]` → 合法拓扑序（我实测得到 `[0,1,2,3]`）；`1, []` → `[0]`；`2, [[1,0],[0,1]]` → `[]`；`3, [[0,1],[1,2],[2,0]]` → `[]`；`4, []` → 任意合法顺序；`1, [[0,0]]` → `[]`（自环）。
- 30 秒自检：能不能说出"入度的物理含义"、"为什么环上的点进不了队列"、"最后那行 `if` 在判什么"。

## 7-4. 无向图中连通分量的数目（Medium）

> 力扣 323 · 图 · 并查集（Union-Find）
> 前置：第 0 章 0.3

**一句话**：`n` 个点（编号 `0`~`n-1`）、若干条无向边，问整张图被分成了几块互不相连的部分。

### 精讲（零基础版）

#### ① 这题要用到的东西

**并查集（Union-Find）**

一句话：并查集只回答一个问题——"你和我是不是一伙的"。它不记路径，只记"谁归谁管"。

生活类比：每个人填一张表，写"我的上级是谁"。一路往上问，问到某个"上级就是他自己"的人，那个人就是**总经理**（术语叫**根**）。两个人的总经理是同一个人，他俩就是同一家公司。

两个动作：

- `find(x)`：一路往上问到根，返回根是谁。
- `union(a, b)`：a 和 b 各找到自己的根，如果根不同，就让其中一个根认另一个根当上级。

```python
parent = list(range(5))     # 一开始每人自己是自己的上级
print(parent)               # -> [0, 1, 2, 3, 4]
parent[0] = 1               # 让 0 认 1 当上级
print(parent)               # -> [1, 1, 2, 3, 4]
```

`list(range(5))` 就是 `[0,1,2,3,4]`——`range(5)` 是"0 到 4 这个序列"，`list()` 把它变成真的列表。

**路径压缩**

一句话：`find` 往上走的时候，顺手把沿途每个人的上级改成"爷爷的上级"，树就越来越扁，以后查得越来越快。

这题里，并查集负责把一条条边并成一块块；最后数"有几个人的上级是自己"，就是几块。

**嵌套函数（闭包）**

一句话：在函数里面再定义一个函数，里面的函数能直接用外面的变量。

```python
def outer():
    data = [1, 2]
    def inner():
        return len(data)      # 直接用外面的 data，不用传参
    return inner()
print(outer())                # -> 2
```

这题里 `find` 定义在 `countComponents` 里面，所以它能直接用 `parent`，不用到处传参。

#### ② 大白话：这题到底在干什么

最笨的办法：从每个没访问过的点出发，做一次遍历（DFS 或 BFS），把能走到的全标记；出发了几次，就是几块。

这个办法能过，面试先答它不吃亏。但它有个隐含前提：**图不变**。如果边是一条一条加进来的，每来一条就问你"现在几块"，你就得从头再跑一遍。

并查集的思路完全不同：一开始当 n 个人互不相识（n 块）。每来一条边，就等于宣布"这两个人是一伙的"，把两伙合成一伙，块数少一。前面算好的结果全部保留，只处理新来的这条边。

合并时有个细节必须注意：改的是**根**的上级，不是某个点自己的上级。因为点底下可能还挂着别人，改了它自己，底下那串就和它断了。

#### ③ `n = 5, edges = [[0,1],[1,2],[3,4]]` 走一遍

| 加边 | find 结果 | 动作 | parent |
|---|---|---|---|
| 初始 | | 5 个人各自一伙 | `[0,1,2,3,4]` |
| `0-1` | 0, 1 | 不同根，合并：`parent[0]=1` | `[1,1,2,3,4]` |
| `1-2` | 1, 2 | 不同根，合并：`parent[1]=2` | `[1,2,2,3,4]` |
| `3-4` | 3, 4 | 不同根，合并：`parent[3]=4` | `[1,2,2,4,4]` |

最后数"自己是自己的上级"的点：只有 2 和 4（0 的根是 2，1 的根是 2，3 的根是 4）。所以答案是 2。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `parent = list(range(n))` | 一开始每个点自成一派，上级是自己 |
| `while parent[x] != x:` | 还没到根，继续往上问 |
| `parent[x] = parent[parent[x]]` | 顺手把上级改成爷爷（路径压缩） |
| `x = parent[x]` | 往上走一层，**这行必须在上一行之后** |
| `ra, rb = find(a), find(b)` | 两个点各自的根 |
| `if ra != rb:` | 不是一伙的才需要合并 |
| `parent[ra] = rb` | 改的是根 ra，不是 a |
| `return sum(1 for i in range(n) if find(i) == i)` | 数有几个点自己是根 |

> 这题是力扣会员题。`data/题面-第二册.md` 里它的正文是空的，只留了两组官方输入输出：`5, [[0,1],[1,2],[3,4]] → 2`，`5, [[0,1],[1,2],[2,3],[3,4]] → 1`。本地测试的 `n` 和 `edges` 都得自己造，方法签名是 `countComponents(self, n: int, edges: List[List[int]]) -> int`。

### 考什么

- 表面考点：数连通块。
- 真正考点：**并查集**。它专门回答"你和我是不是一伙的"，而且支持边一条条加进来。
- 面试官想听到的关键句：① `find(x)` 一路往上找到根，根相同就是同一块；② `union(a,b)` 把两个根接起来；③ 最后数一数"自己是自己的根"的点有几个。

### 思路是怎么想出来的

- **DFS 也能做**：从每个没访问过的点出发，DFS 把能走到的全标记，出发次数就是块数。O(n+e)，能过。面试先答这个不吃亏。
- **那为什么还要并查集**：DFS 的隐含前提是"图不变"。如果边是**一条一条来的**，每来一条就问你"现在几块"，DFS 每次都要从头跑一遍。并查集只处理新来的那条边，前面算好的结果全部保留。这就是"动态连通性"。
- **并查集是什么**：每个点记一个"我的上级是谁"。一路往上问，直到问到一个"上级就是自己"的点，那个点叫**根**。两个点的根相同，就在同一块。人话类比：每个人填一张"我的上级"，一路问到总经理；同一个总经理，就是同一家公司。
- **怎么合并**：`a` 和 `b` 各找到自己的根 `ra`、`rb`，如果不同，就让 `ra` 认 `rb` 当上级（`parent[ra] = rb`）。注意改的是**根**的上级，不是 `a` 的上级——改 `a` 的话，原来挂在 `a` 下面的那些点就和 `a` 断开了。
- **路径压缩**：每次 `find` 都顺手把沿途节点的上级改成爷爷（`parent[x] = parent[parent[x]]`），树越来越扁，后面查得越来越快。这一步不影响正确性，只影响速度。

示例 1：`n = 5, edges = [[0,1],[1,2],[3,4]]`

```
图：  0 ─ 1 ─ 2      3 ─ 4

parent 初始: [0, 1, 2, 3, 4]        （每个点自成一派）

union(0,1): find(0)=0, find(1)=1 → parent[0]=1     [1,1,2,3,4]
union(1,2): find(1)=1, find(2)=2 → parent[1]=2     [1,2,2,3,4]
union(3,4): find(3)=3, find(4)=4 → parent[3]=4     [1,2,2,4,4]

数根：0 的根是 2（0→1→2），1 的根是 2，2 是根，3 的根是 4，4 是根
→ 根只有 2 和 4 两个 → 返回 2
```

### 代码（Python）

```python
from typing import List

class Solution:
    def countComponents(self, n: int, edges: List[List[int]]) -> int:
        parent = list(range(n))            # 一开始每个点自成一派，上级是自己

        def find(x: int) -> int:
            while parent[x] != x:          # 还没到根，继续往上问
                parent[x] = parent[parent[x]]   # 路径压缩：让爷爷直接当上级
                x = parent[x]
            return x

        for a, b in edges:
            ra, rb = find(a), find(b)
            if ra != rb:                   # 只有两个不同的集合才需要合并
                parent[ra] = rb            # 让 a 的根认 b 的根当上级

        # 数一数有几个点是"自己的上级"
        return sum(1 for i in range(n) if find(i) == i)
```

**逐段讲解**：

- `parent = list(range(n))`：`parent[i] = i` 表示"我是自己的上级"，也就是自成一个集合。这个初始状态很重要：没有边的时候，n 个点就是 n 块。
- `find` 的循环：`parent[x] != x` 说明 x 还有上级，往上走。走到 `parent[x] == x` 就是根。
- `parent[x] = parent[parent[x]]`：这一行是路径压缩的"隔代压缩"版。它把 x 的上级直接改成它爷爷，比"找到根之后再把整条链全部改一遍"少写几行，效果接近。**注意这行必须在 `x = parent[x]` 之前执行**，否则改的是已经上移过的节点。
- `if ra != rb`：两个点已经同根就跳过。这一步在 323 里不影响答案（重复合并根还是那个根），但它是 684 的全部逻辑，养成习惯。
- `parent[ra] = rb`：改的是根 `ra`，不是 `a`。
- 最后一行 `sum(1 for i in range(n) if find(i) == i)`：**判断"我是不是根"必须调用 `find(i)`**。直接写 `parent[i] == i` 在本题也能得到同样结果（非根节点的 `parent` 永远不等于自己），但 `find(i)` 表达的意图更清楚，而且以后加上按秩合并、路径压缩的变体也不会错。
- 另一个常见写法是维护一个计数器：`count = n`，每次成功合并 `count -= 1`，最后直接返回 `count`。少一次 O(n) 的扫描，但只在"边很多"时才值得。

### 复杂度

- 时间 O((n + e) · α(n))，α 是反阿克曼函数，实际取值不超过 4，所以约等于 O(n + e)。每个点、每条边都只被 `find` 常数次。
- 空间 O(n)：`parent` 数组。递归版 `find` 还有栈开销，这里用 while 写成迭代，没有这个问题。

### 常见误区（★ 最容易丢分的地方）

1. **每条边都 `count -= 1`**：不管两个点是否已经连通。`n=3, edges=[[0,1],[1,2],[2,0]]` 是三角形，正确答案 1，这种写法实测返回 0。
2. **合并时写 `parent[a] = b`**：改的是 `a` 本身而不是 `a` 的根。如果 `a` 底下还挂着别的点，那些点就和 `a` 断开，连通块数会算多。必须 `parent[find(a)] = find(b)`。
3. **`find` 写成 `if` 而不是 `while`**：只往上跳一层就返回，链一长就找错根。三节点链 `0→1→2` 时，`find(0)` 会返回 1 而不是 2。
4. **路径压缩写错顺序**：先 `x = parent[x]` 再压缩，压的是上一层，白压。
5. **用 DFS 数块却复用了上一题的 `visited`**：这题的点是 `0..n-1`，没有网格，别把 200 的代码直接搬过来。
6. **忘了孤立点**：`edges` 里没出现过的点也各算一块。`n=4, edges=[]` 的答案是 4，不是 0。

### 面试追问 / 变体

- 边是动态加进来的（力扣 305 岛屿数量 II）：并查集的主场，每加一块陆地就和上下左右的陆地合并，块数实时维护。
- 要支持删边：并查集做不到，得换成 DFS 重算，或者用更复杂的数据结构（线段树分治）。面试说出"并查集不支持删边"就够了。
- 按秩合并：合并时把矮树挂到高树下，树高控制在 O(log n)。配合路径压缩，均摊 O(α(n))。
- 用并查集做 684 冗余连接：见下一题，代码只差三行。

### 自测

- 必测用例：`5, [[0,1],[1,2],[3,4]]` → 2；`5, [[0,1],[1,2],[2,3],[3,4]]` → 1；`1, []` → 1；`4, []` → 4；`3, [[0,1],[1,2],[2,0]]` → 1（三角形）；`2, [[0,1],[0,1]]` → 1（重复边）；`6, [[0,1],[2,3],[4,5]]` → 3。
- 30 秒自检：能不能说出"根是什么"、"为什么合并要改根而不是改自己"、"最后为什么数 `find(i) == i`"。

## 7-5. 冗余连接（Medium）

> 力扣 684 · 图 · 并查集判环
> 前置：7-4

**一句话**：`n` 个点的树被多加了一条边，找出这条边——删掉它，剩下的又是一棵树。

### 精讲（零基础版）

#### ① 这题要用到的东西

**树的性质：n 个点、n-1 条边**

一句话：一棵树是"全都连在一起、但一个圈也没有"的图。这样的图，n 个点恰好有 n-1 条边。题目说"多了一条边"，所以边数正好是 n。

这题里，"多余的边"就是"加上去会形成圈的那条边"。

**并查集**（前面 7-4 讲过）：`find(x)` 往上找到根，根相同就是同一块；`union` 就是让一个根认另一个根当上级。这题用它，只多了一句"如果两端已经同根，这条边就是多余的"。

**下标从 1 开始：`range(n + 1)`**

一句话：这题的节点编号是 `1..n`，而 Python 列表下标从 0 开始。所以开 `n+1` 个位置，把下标 0 空着不用。

```python
parent = list(range(4))    # 下标 0、1、2、3 —— 装得下编号 1..3
print(parent)              # -> [0, 1, 2, 3]
```

开成 `n` 个的话，访问编号 n 的那个点就会 `IndexError`。多开一格，换掉每次都要写的 `-1`，很划算。

**"同根意味着什么"**

一句话：`find(a) == find(b)` 说明 a 和 b 之间**已经有一条不经过这条边的路**。再补上这条边，就绕出一个圈。

#### ② 大白话：这题到底在干什么

最笨的办法：对每条边，试着删掉它，再看剩下的图还连不连通、有没有环。每条边检查一次要 O(n)，总共 O(n²)。n ≤ 1000 能过，但没必要。

聪明的办法：根本不用删。按输入顺序把边一条条加进来，用并查集盯着连通性。加某条边 `(a, b)` 的时候，先看 a 和 b 是不是已经一伙的：

- 不是一伙的：正常，把两伙合并。
- 已经一伙的：说明 a 到 b 本来就有路，再加上这条就绕出一个圈了。这条边就是多余的。

为什么"第一条撞上的"就是题目要的"最后出现的"：题目保证只多一条边。圈上的边，除了最后加进来的那条，其余每条加进来时两端都还没连通（否则早就成圈了，而只允许一个圈）。所以按顺序扫，第一次撞上"已经同根"，撞到的必然是圈上最后出现的那条。

和 7-4 比，这题只多了三行：读入两端、比根、同根就返回。并查集的模板一个字没变，写一次能吃四道题。

#### ③ `edges = [[1,2],[1,3],[2,3]]` 走一遍

| 加边 | find 结果 | 动作 | parent |
|---|---|---|---|
| 初始 | | 3 个点各自一伙 | `[0,1,2,3]` |
| `1-2` | 1, 2 | 不同根，合并 | `[0,2,2,3]` |
| `1-3` | 2, 3 | 不同根，合并 | `[0,2,3,3]` |
| `2-3` | 3, 3 | **同根**，成环 | 返回 `[2,3]` |

所以答案是 `[2,3]`。注意第 3 行 `find(1)` 返回的是 2 而不是 1——1 已经认了 2 当上级，根是 2。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `n = len(edges)` | 题目保证点数 = 边数（树 n-1 条，多 1 条） |
| `parent = list(range(n + 1))` | 编号 1..n，多开一格，下标 0 空着 |
| `while parent[x] != x:` | 一路往上找根 |
| `parent[x] = parent[parent[x]]` | 路径压缩，树变扁 |
| `ra, rb = find(a), find(b)` | 这条边两端的根 |
| `if ra == rb: return [a, b]` | 已经一伙 → 这条边成环 → 就是答案 |
| `parent[ra] = rb` | 不同根才合并 |
| `return []` | 兜底，题目保证有答案 |

### 考什么

- 表面考点：找环上的一条边。
- 真正考点：**并查集判环**。边一条条加进去，如果某条边的两端早就连通了，这条边就是多余的。
- 面试官想听到的关键句：① 树 = 连通 + 无环，n 个点恰好 n-1 条边；② 加边时两端已经同根，说明这条边闭合了一个环；③ 按输入顺序扫，第一条"两端同根"的边就是答案。

### 思路是怎么想出来的

- **暴力**：对每条边，试着删掉它，再检查剩下的图是不是树（连通且无环）。每条边检查一次要 O(n)，总共 O(n²)。能过（n ≤ 1000），但没必要。
- **关键观察**：不用删。按顺序把边一条条加进来，同时用并查集维护连通性。加某条边 `(a, b)` 时，如果 `find(a) == find(b)`，说明 a 和 b 之间**已经有一条路了**，再加上这条就直接成环——这条边就是多余的。
- **为什么"第一条"就是题目要的"最后出现的那个"**：题目说如果有多个答案，返回 `edges` 里最后出现的。环上的边，除了最后加进来的那条，其余每条在加入时两端都还没连通（否则早就成环了，而题目保证只多一条边）。所以扫描时第一次撞上"两端已同根"，撞到的必然是环上最后出现的那条。这两个说法是同一件事。
- **为什么不用 DFS 判环**：每加一条边就 DFS 一遍是 O(n²)；并查集均摊下来接近 O(1)。

示例 1：`edges = [[1,2],[1,3],[2,3]]`

```
图：   1
      ╱ ╲
     2 ─ 3

加 1-2: find(1)=1, find(2)=2 不同根 → 合并 {1,2}       parent[1]=2
加 1-3: find(1)=2, find(3)=3 不同根 → 合并 {1,2,3}     parent[2]=3
加 2-3: find(2)=3, find(3)=3 同根！  → 返回 [2,3]
```

### 代码（Python）

```python
from typing import List

class Solution:
    def findRedundantConnection(self, edges: List[List[int]]) -> List[int]:
        n = len(edges)
        parent = list(range(n + 1))        # 节点编号 1..n，多开一格省得减 1

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]     # 路径压缩
                x = parent[x]
            return x

        for a, b in edges:
            ra, rb = find(a), find(b)
            if ra == rb:                   # 两端早就连通，再加这条就成环
                return [a, b]
            parent[ra] = rb

        return []                          # 题目保证有答案，这行只是兜底
```

**逐段讲解**：

- `parent = list(range(n + 1))`：节点编号是 `1..n`，不是 `0..n-1`。开 `n+1` 个位置，下标 0 空着不用，这样 `parent[a]` 可以直接用，不用写 `a-1`。开成 `n` 个的话，访问节点 n 会 `IndexError`。
- `n = len(edges)`：题目保证 `n == edges.length`，所以边数就是点数。树有 n-1 条边，多一条正好是 n 条。
- `if ra == rb: return [a, b]`：**这题的全部逻辑就在这三行**。同根意味着"a 和 b 之间已经有一条不经过这条边的路"，加上这条边就形成了环。
- `return [a, b]` 而不是 `[b, a]`，也不排序：题目要的是 `edges` 里那条边的原样，顺序按输入给。排序会改变边的表示。
- `parent[ra] = rb` 只在"不同根"时执行，也就是正常把两个集合接起来。

### 复杂度

- 时间 O(n · α(n))，约等于 O(n)。每条边两次 `find`，路径压缩之后接近常数。
- 空间 O(n)：`parent` 数组。

### 常见误区（★ 最容易丢分的地方）

1. **不查同根直接合并**：`parent[find(a)] = find(b)` 一路合到底，永远不返回，实测输出 `[]`。力扣判错。
2. **`parent` 开 `n` 个**：节点编号到 `n`，访问 `parent[n]` 直接越界。开 `n+1`。
3. **返回下标或排序后的边**：题目要边本身 `[a, b]`，而且顺序按输入。返回 `[2, 3]` 写成 `[3, 2]` 也判错（力扣按数组逐位比较）。
4. **真的去删边再验证**：能过但 O(n²)，面试官会追问"能不能一遍扫完"。
5. **拿并查集判有向环**：这题是无向图才能这么干。207/210 是有向的，必须拓扑排序——有向图里 `a → b` 和 `b → a` 不是一回事，并查集会把它俩当成同一条边。

### 面试追问 / 变体

- 冗余连接 II（力扣 685）：有向图，多一条边。要先看有没有节点入度为 2，再分情况用并查集，比这题麻烦一档。
- 要返回**所有**可以删的边：先用 DFS 找出那个环，环上每条边都是候选。
- 判断"加一条边之后还是不是树"：并查集合并时返回 False 就说明成环。
- 这题和 323 的代码差多少：只差 `if ra == rb: return` 这一句和最后的计数。并查集的模板是通用的，写一次能吃四道题（323、684、305、547）。

### 自测

- 必测用例：`[[1,2],[1,3],[2,3]]` → `[2,3]`；`[[1,2],[2,3],[3,4],[1,4],[1,5]]` → `[1,4]`；`[[1,2],[2,3],[1,3]]` → `[1,3]`（三角形，闭合边在最后）；`[[1,2],[2,3],[3,4],[1,4]]` → `[1,4]`；`[[1,3],[1,2],[2,3]]` → `[2,3]`（冗余边不在末尾）。
- 30 秒自检：能不能说出"同根意味着什么"、"为什么第一条撞上的就是最后出现的那条"、"parent 为什么开 n+1"。

## 7-6. 腐烂的橘子（Medium）

> 力扣 994 · 图 · 多源 BFS
> 前置：第 0 章 0.2（网格图）、0.4

**一句话**：每分钟，每个烂橘子把它上下左右的新鲜橘子变烂；问多久全烂完，烂不完返回 `-1`。

### 精讲（零基础版）

#### ① 这题要用到的东西

**网格图：不用建邻接表**

一句话：给一个 m 行 n 列的二维数组，每个格子是一个点，上下左右相邻就是有边。不用建表，用四个方向现场算邻居。

```python
grid = [[2, 1], [1, 1]]
m, n = len(grid), len(grid[0])
print(m, n)          # -> 2 2
print(grid[0][1])    # -> 1     第 0 行第 1 列
```

`grid[i][j]` 是"第 i 行第 j 列"。`len(grid)` 是行数，`len(grid[0])` 是列数。

**多源 BFS**

一句话：普通 BFS 从一个起点出发；多源 BFS 是**把所有起点一次性放进队列**，让它们同时往外扩。因为队列先进先出，第 0 层全处理完才轮到第 1 层——这正好就是"所有起点同时发作"。

生活类比：好几个地方同时点着了火，火苗同时往四周烧。你问"什么时候烧完"，答案是最晚被烧到的那一格的时间。

这题里每个烂橘子都是起点，全部入队。**层号就是分钟数。**

**BFS 和分层**（前面 7-1 讲过 BFS 用队列一层层扩）：这题的关键动作是 `for _ in range(len(q))`——`len(q)` 在循环开始时只算一次，所以这一轮只处理"当前层"的节点；这一轮里新入队的属于下一层，留到下一轮。`_` 是"这个变量我不用"的惯例写法。

#### ② 大白话：这题到底在干什么

最笨的办法：每分钟扫一遍整个网格，把"自己是新鲜的、上下左右有烂的"格子变烂，直到某一分钟没有任何变化。

笨在哪？每一分钟都在重扫所有格子，包括早就烂掉的、还有永远烂不了的空格。最坏 O(m²n²)。

聪明的办法：把这题看成"好几个人从不同起点同时出发，问最晚什么时候覆盖完"。第 0 分钟就烂的是第 0 层，第 1 分钟被传染的是第 1 层……所以只要把所有烂橘子一次性放进队列，一层一层往外扩，扩了几层就是几分钟。

最后还要检查一件事：如果还有新鲜橘子没被传染到，说明它被空格围死了，永远烂不了，返回 -1。所以不能只看分钟数。

#### ③ 示例 1 走一遍

`grid = [[2,1,1],[1,1,0],[0,1,1]]`，一开始 `(0,0)` 是烂的，新鲜橘子有 6 个。

| 分钟 | 这一分钟变烂的格子 | 队列 | 剩余新鲜 |
|---|---|---|---|
| 0 | 起点 `(0,0)` | `[(0,0)]` | 6 |
| 1 | `(1,0)`、`(0,1)` | `[(1,0),(0,1)]` | 4 |
| 2 | `(1,1)`、`(0,2)` | `[(1,1),(0,2)]` | 2 |
| 3 | `(2,1)` | `[(2,1)]` | 1 |
| 4 | `(2,2)` | `[(2,2)]` | 0 |

第 4 分钟结束后新鲜橘子归零，循环退出，答案是 4。注意 `(1,1)` 到第 2 分钟才烂——它离起点有两条路，都是 2 步。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `m, n = len(grid), len(grid[0])` | 行数、列数 |
| `q.append((i, j))` | **所有**烂橘子都是起点，这就是"多源" |
| `elif grid[i][j] == 1: fresh += 1` | 顺便数清楚有多少个新鲜橘子 |
| `while q and fresh > 0:` | 队列空了、或者已经全烂了，就收工 |
| `for _ in range(len(q)):` | 只处理当前这一层 = 这一分钟 |
| `x, y = q.popleft()` | 拿出一个刚烂的橘子 |
| `for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):` | 上下左右四个邻居 |
| `if 0 <= nx < m and 0 <= ny < n and grid[nx][ny] == 1:` | 没越界、而且是新鲜橘子 |
| `grid[nx][ny] = 2` | 感染的同时就标记，防止重复入队 |
| `fresh -= 1` | 新鲜橘子少一个 |
| `minutes += 1` | 这一层处理完，分钟数加 1（在层循环**外面**） |
| `return minutes if fresh == 0 else -1` | 还有没烂的，说明被空格隔开了 |

### 考什么

- 表面考点：二维网格模拟。
- 真正考点：**多源 BFS**。起点不止一个，所有烂橘子同时出发，答案是最晚被覆盖的那一格所用的时间。
- 面试官想听到的关键句：① 一开始把所有烂橘子全部入队；② 队列里一层 = 一分钟；③ 最后还有新鲜橘子，说明它被空格隔开了，返回 `-1`。

### 思路是怎么想出来的

- **暴力模拟**：每分钟扫一遍整个网格，把"自己是新鲜的、上下左右有烂的"格子变烂，直到某一分钟没有任何变化。这能过（网格最大 10×10），但最坏要扫 O(mn) 轮，每轮 O(mn)，总共 O(m²n²)。
- **关键观察**：这是"多个人从不同起点同时出发，问最晚什么时候覆盖完"。第 0 分钟被感染的（也就是一开始就烂的）是第 0 层，第 1 分钟被感染的是第 1 层……**层号就是时间**。
- **为什么多源入队等价于同时扩散**：把所有烂橘子一次性放进队列，它们都在第 0 层。处理第 0 层时，每个烂橘子各自把邻居变烂，这些新烂的都在第 1 层。因为队列是先进先出的，第 0 层的全部处理完才会轮到第 1 层——这正好就是"同一分钟里所有烂橘子同时发作"。
- **层数怎么数**：`for _ in range(len(q))` 把当前这一层一次性处理完，然后 `minutes += 1`。`len(q)` 在进入循环时求值一次，循环里 `q` 变长不影响次数。
- **最后为什么还要检查**：被空格围住的橘子永远进不了队列，`fresh` 减不到 0。所以不能只看 `minutes`。

示例 1：

```
2 1 1
1 1 0
0 1 1

第 0 分钟  q = [(0,0)]
第 1 分钟  (0,1), (1,0) 变烂        q = 这两个
第 2 分钟  (0,2), (1,1) 变烂
第 3 分钟  (2,1) 变烂
第 4 分钟  (2,2) 变烂，fresh 归零
→ 返回 4
```

### 代码（Python）

```python
from collections import deque
from typing import List

class Solution:
    def orangesRotting(self, grid: List[List[int]]) -> int:
        m, n = len(grid), len(grid[0])
        q = deque()
        fresh = 0

        for i in range(m):                 # 一次扫描：收烂橘子 + 数新鲜橘子
            for j in range(n):
                if grid[i][j] == 2:
                    q.append((i, j))       # 所有烂橘子都是起点
                elif grid[i][j] == 1:
                    fresh += 1

        minutes = 0
        while q and fresh > 0:             # 没有新鲜橘子就提前收工
            for _ in range(len(q)):        # 这一层 = 这一分钟
                x, y = q.popleft()
                for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                    nx, ny = x + dx, y + dy
                    if 0 <= nx < m and 0 <= ny < n and grid[nx][ny] == 1:
                        grid[nx][ny] = 2   # 感染的同时就标记
                        fresh -= 1
                        q.append((nx, ny))
            minutes += 1

        return minutes if fresh == 0 else -1
```

**逐段讲解**：

- 第一次双重循环只做两件事：把所有 `2` 的位置入队（**这是"多源"的全部含义**），数清楚有多少个 `1`。注意这里没有"选一个起点"的逻辑，起点是全部。
- `while q and fresh > 0`：`fresh > 0` 是提前收工的条件。示例 3 是 `[[0,2]]`，一开始就没有新鲜橘子，`fresh == 0`，循环一次都不进，直接返回 0。如果不写这个条件，会白跑一轮，返回 1。
- `for _ in range(len(q))`：这一行是"分层"的关键。`len(q)` 在循环开始时算一次，所以这一轮只处理当前层的节点，新入队的下一层节点留到下一轮。
- 四个方向 + 边界判断：`0 <= nx < m` 放在 `grid[nx][ny]` 之前，Python 的 `and` 短路保证不会越界。
- `grid[nx][ny] = 2` 写在 `q.append` **之前**，也就是入队即标记。如果等出队再标记，同一个格子会被上下左右四个邻居各入队一次，队列膨胀，`fresh` 也会被减多次。
- `minutes += 1` 在层循环**外面**。写在里面就变成"每处理一个格子算一分钟"，示例 1 会输出 7。
- `return minutes if fresh == 0 else -1`：还有新鲜的没烂，说明它被空格隔开了。

### 复杂度

- 时间 O(mn)：每个格子最多入队一次，出队时检查四个邻居，常数次操作。
- 空间 O(mn)：队列最坏装下所有格子（全是烂橘子时，第一层就是 mn 个）。

### 常见误区（★ 最容易丢分的地方）

1. **不检查 `fresh`**：示例 2 实测返回 5，正确答案是 `-1`。这个错最要命，因为返回值"看起来像个正常答案"。
2. **不分层，每弹一个就 `minutes += 1`**：示例 1 实测返回 7，正确答案 4。BFS 的"层"必须靠 `for _ in range(len(q))` 划出来。
3. **只把第一个烂橘子入队**：多源退化成单源。`[[2,2],[1,1]]` 正确答案 1（两颗烂橘子同时往下传），只入第一个源实测返回 2——下面那颗橘子要多等一分钟。
4. **用 DFS**：DFS 走到的第一条路不一定是最短的那条。要让它正确，就得把所有路径都枚举一遍取最小，指数级。网格里绕路很常见，所以这类"最少时间"的题一律 BFS。
5. **`while q and fresh > 0` 写了，最后却 `return minutes`**：两个地方都要检查。循环条件负责"早点停"，返回值负责"报告失败"。
6. **感染时不立刻改 `grid`**：同一格被多个邻居重复入队，`fresh` 被减多次，可能提前归零，答案偏小。

### 面试追问 / 变体

- 腐烂可以斜着传（8 方向）：方向数组加四条，其余不动。
- 只要判断"能不能全烂"：不需要分钟数，返回 `fresh == 0`。
- 01 矩阵（力扣 542，每个格子到最近 0 的距离）：同一个多源 BFS 模板，把"距离"存进结果数组而不是计数器。

## 7-7. 岛屿数量（回顾）

> 第一册已精讲：[分册 C · C9 岛屿数量](12-分册C-链表树图.md)
> 力扣 200 · 图 · DFS/BFS 连通块 · Medium

### 精讲（零基础版）

#### ① 这题要用到的东西

全是老朋友，一句一个：

> **BFS / DFS**（前面 7-1、7-6 讲过）：从一个点出发把能走到的点走一遍。BFS 用队列一层层扩，DFS 用递归一条路走到黑。

> **网格图**（前面 7-6 讲过）：每个格子是点，上下左右是边，越界就是没边。

> **连通块**：互相能走到的格子算一块，数块数 = 数"从几个地方出发过"。

> **"淹掉"**：把走过的 `'1'` 改成 `'0'`，同时完成"标记来过"和"这座岛已经数过"。

#### ② 大白话：这题到底在干什么

最笨的办法：对每个 `'1'` 都去问"它和之前数过的岛是不是同一座"，为了回答这个问题，每次都得把整张图走一遍。

聪明的办法：扫格子，遇到没被淹过的 `'1'` 就说明发现了一座新岛——答案加 1，然后从它出发把整座岛淹掉。以后扫到这座岛的格子都是 `'0'`，不会再数第二次。

所以每个格子最多被访问两次，O(mn)。"淹掉"比另开一个 visited 数组省事：标记和去重一步到位。

**30 秒回顾**：外层双循环扫每个格子，遇到 `'1'` 就 `count += 1`，然后从它出发把整块连通的 `'1'` 全改成 `'0'`（"淹掉"）。淹掉是为了以后不再重复数同一座岛。时间 O(mn)，空间 O(mn)（BFS 队列）。分册 C 里实测过：300×300 全 `'1'` 的网格，递归 DFS 会 `RecursionError`，BFS 正常。

**核心代码（背这一段就够）**：

```python
count = 0
for i in range(m):
    for j in range(n):
        if grid[i][j] == "1":
            count += 1
            q = deque([(i, j)])
            grid[i][j] = "0"          # 入队即标记
            while q:
                x, y = q.popleft()
                for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                    nx, ny = x + dx, y + dy
                    if 0 <= nx < m and 0 <= ny < n and grid[nx][ny] == "1":
                        grid[nx][ny] = "0"
                        q.append((nx, ny))
```

**换个角度**：

- **200 和 323 是同一道题**。323 给你"点 + 边"，200 给你一张网格。把每个 `'1'` 看成一个点、相邻看成边，200 就是 323。区别只在"边怎么来"：323 要读 `edges` 建邻接表，200 的边是**隐式**的——上下左右四个方向就是邻接表，越界就是没边。所以 200 用并查集写也行：把每个 `'1'` 和它右边、下边的 `'1'` 合并，最后数根。写起来比 DFS 长，但"边是动态加进来的"时（力扣 305 岛屿数量 II）就只有并查集能扛。
- **为什么 200 的 DFS 不需要"撤销"**。对比 79 单词搜索：那题走错要退回来，因为同一个格子不能在同一条路径里用两次；200 是"走到的都归我"，淹掉就淹掉了，不用恢复。**判断标准是"走过的格子还能不能再用"**——能复用就得撤销，不能复用就不用。
- 同类骨架：733 图像渲染（flood fill）、695 岛屿的最大面积（DFS 返回淹掉的格子数）、1254 统计封闭岛屿（先把边缘的岛淹掉再数）、463 岛屿的周长（数"陆地-水"的边界条数）。这五道题共用同一个 `for dx, dy in ...` 骨架。

## 7-8. 课程表（回顾）

> 第一册已精讲：[分册 C · C10 课程表](12-分册C-链表树图.md)
> 力扣 207 · 图 · 拓扑排序判环 · Medium

### 精讲（零基础版）

#### ① 这题要用到的东西

这题和 7-3 是同一份代码，没有新名词：

> **拓扑排序**（前面 7-3 讲过）：入度 0 的任务先入队，每弹出一个就记进结果，把它解锁的任务入度减 1，减到 0 的入队。

> **入度**（前面 7-3 讲过）：有几条箭头指向这个点，这题里读作"还有几门先修没上"。

> **邻接表**（前面 7-3 讲过）：`graph[b]` 装"b 上完之后能解锁的课"。

> **判环**：环上的点互相等对方，入度永远减不到 0，进不了队列。所以"上过的课数 < 总课数"就是有环。

#### ② 大白话：这题到底在干什么

最笨的办法：反复扫所有课，每轮挑出一门"先修全上完"的课，上一门，再扫一遍。

笨在哪？一门课能不能上只取决于"还剩几门先修"这一个数字，上一门课只影响它直接解锁的那几门。

聪明的办法：维护每个点的入度，只把入度 0 的课放进队列；每弹出一门就把它解锁的课入度减 1，谁减到 0 谁进队。每个点、每条边各处理一次，O(V+E)。

这题比 7-3 少一样东西：不用输出顺序，把 `order` 换成计数器，最后比 `taken == numCourses` 就行。

**30 秒回顾**：建图（边 `b → a`）+ 入度数组。所有入度为 0 的课入队，每弹出一门就把它指向的课入度减 1，减到 0 的入队。最后 `taken == numCourses` 就是无环（能上完），否则有环。时间 O(V + E)。

**核心代码（背这一段就够）**：

```python
graph = [[] for _ in range(numCourses)]
indegree = [0] * numCourses
for a, b in prerequisites:
    graph[b].append(a)
    indegree[a] += 1

q = deque(i for i in range(numCourses) if indegree[i] == 0)
taken = 0
while q:
    cur = q.popleft()
    taken += 1
    for nxt in graph[cur]:
        indegree[nxt] -= 1
        if indegree[nxt] == 0:
            q.append(nxt)
return taken == numCourses
```

**换个角度**：

- **207 和 210 是同一份代码**。210 把 `taken` 换成 `order` 列表，返回 `order if len(order) == numCourses else []`；207 只要 `len(order) == numCourses` 这个布尔值。**先写 210，207 就是它的一行返回值**。反过来先写 207 再改 210，容易只想着"加个 `order` 列表"，忘了环旁边还可能挂着没参与环的点（`3, [[1,0],[0,1]]` 里 2 是自由的），于是返回 `[2]` 而不是 `[]`。
- **判环的第二种写法：DFS 三色标记**。白色 = 没访问过，灰色 = 正在当前这条递归链上，黑色 = 整棵子树处理完了。走到灰色节点就说明回到了自己，有环。代码比 Kahn 短，但"灰色"这个概念第一次见容易懵：它其实就是"递归栈里还有它"。Kahn 不需要这个概念，所以面试优先写 Kahn。
- **为什么并查集不能判有向环**。并查集只记"谁和谁一伙"，不记方向。`a → b` 和 `b → a` 在它眼里都是"a 和 b 一伙"，而前者是合法的先修关系、后者才是环。207 的示例 2 正是 `[[1,0],[0,1]]`，并查集会把两条边合并成同一个集合，然后告诉你"没问题"。
