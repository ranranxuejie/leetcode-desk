## 1. 容器四件套

Python 里装东西的就这四个。**选错容器，复杂度直接差一个量级**，这是最容易丢分的地方。

| 容器 | 有序 | 可变 | 查一个元素在不在 | 典型用途 |
|---|---|---|---|---|
| `list` | ✅ | ✅ | O(n) 慢 | 按下标访问、当栈 |
| `tuple` | ✅ | ❌ | O(n) 慢 | 不想被改的小组合 |
| `dict` | ✅（插入序） | ✅ | **O(1) 快** | 值→下标、计数 |
| `set` | ❌ | ✅ | **O(1) 快** | 去重、判重 |

### `list` ★

**一句话**：一排有编号的格子，格子能改、能加、能删，编号从 0 开始；力扣里凡是要"按下标随机访问"或"只在末尾加删"，都用它。

**类比**：一排储物柜，柜门上贴着 0、1、2……你要拿第 3 个柜子的东西，直接开 2 号门，不用从 1 号一个个开过去，这就是"随机访问"。而且柜子是紧挨着排的：想数"从第 2 个到第 4 个一共几件"，你顺着走一遍就够（切片）；但要在最前面塞一个新柜子，就得把后面所有柜子整体往右挪一格——这就是 `insert(0, x)` 慢的原因。

```python
nums = [3, 1, 4]
nums.append(1)      # 末尾加一个，O(1)
nums.pop()          # 末尾删一个，O(1)
nums[0] = 9         # 按下标改，O(1)
print(nums)         # -> [9, 1, 4]
print(nums[1])      # -> 1
print(len(nums))    # -> 3
```

**坑**：`nums.pop(0)` 和 `nums.insert(0, x)` 要把后面所有元素整体挪一格，是 O(n)；在循环里用就变成 O(n²)，队列请换 `deque`。

另外提醒一句：`x in nums` 是**线性扫描**（O(n)），而 `x in set` 才是 O(1)。很多人以为 `in` 都很快，在循环里对着 list 写 `in` 就是超时的常见来源。

速记：尾部 `append` / `pop()` 和 `nums[i]` 都是 O(1)；`x in nums`、`remove`、`pop(0)`、`insert(0, x)` 全是 O(n)。`len(nums)` 也是 O(1)，它不会真的去数一遍。

### `tuple`

**一句话**：和 `list` 长得一样，但建好就不能改，适合装"一组固定的值"，也常用来当字典的键。

**类比**：塑封好的套餐卡——米饭、菜、汤三样钉死在一起，你可以整张递出去，但不能把汤换成可乐。正因为"钉死了不会变"，它才敢被放进 `set` 或当 `dict` 的键（能变的东西哈希值会变，表就找不到它了）。

```python
point = (3, 5)
x, y = point            # 解包：一次拆成两个变量
print(x + y)            # -> 8
print(point[0])         # -> 3
print(type((1,)).__name__)   # -> tuple
print(type((1)).__name__)    # -> int
```

**坑**：只有一个元素的元组必须写逗号 `(1,)`，写 `(1)` 那就只是个带括号的整数，`for` 里遍历它会直接报错。

### `dict` ★

**一句话**：一本字典，你拿"键"去查"值"，一步到位，不用从头翻；它同时是 Python 的哈希表实现。

**类比**：查字典找"猫"这个字，你不会从第一页读到最后一页，你直接翻到 M 部，这个"直接翻到"就是 O(1)。在算法题里它还有第二个身份——**记忆本**：`{值: 下标}`、`{字符: 出现次数}`、`{前缀和: 出现次数}`，凡是"待会儿还要回头查"的东西，都先记进去。

```python
age = {"amy": 20, "bob": 22}
age["carl"] = 25            # 没有就新增，有就覆盖，O(1)
print(age["amy"])           # -> 20
print("bob" in age)         # -> True
print(len(age))             # -> 3
print(list(age.keys()))     # -> ['amy', 'bob', 'carl']
print(age.get("dave", -1))  # -> -1  查不到给默认值
```

**坑**：`age["dave"]` 查不到会直接抛 `KeyError` 让程序崩掉；不确定键在不在时，一律用 `.get(k, 默认值)`。

遍历用 `for k, v in d.items()`，只要键用 `d.keys()`，只要值用 `d.values()`。字典还**记住插入顺序**，所以 `list(d)` 得到的是"第一次出现的顺序"——"找第一个只出现一次的字符"就靠这个性质。

它还有一个常被忽略的一行写法：`dict(zip(keys, values))`，把两个列表压成映射，比写循环快也短。

速记：`{}` 建字典、`[]` 建列表、`()` 建元组，三种括号别搞混。

`d.items()` 返回的是"键值对视图"，遍历时直接解包成 `k, v`；想按值排序就 `sorted(d.items(), key=lambda kv: kv[1])`。

### `set` ★

**一句话**：一堆"只有键、没有值"的东西，自动去重，问"在不在"是 O(1)，代价是不保证顺序。

**类比**：演唱会门口的已入场名单。你只关心"这个人进没进过"，不关心他是第几个进的，也不会让他进第二次。所以 `set` 天生适合干两件事：**去重**（把重复的挤掉）和**判重**（走过的地方插旗子，防止绕圈，图/树的 DFS 全靠它）。

```python
seen = {1, 2, 3}
seen.add(4)          # 加，重复加不会报错也不会变多
print(4 in seen)     # -> True
print(2 in seen)     # -> True
print(len(seen))     # -> 4
seen.discard(1)      # 删，删不存在的元素也不报错
print(seen)          # -> {2, 3, 4}
```

**坑**：空集合必须写 `set()`，写 `{}` 得到的是空字典；另外 `set` 里的元素必须可哈希，`list` 塞不进去，要存就转成 `tuple`。

集合还支持一行做完交并差：`a & b` 交集、`a | b` 并集、`a - b` 差集，比自己写循环快得多，也短得多。

去重也不用自己写：`list(set(nums))` 一行搞定，但它会打乱顺序；要保序就用 `list(dict.fromkeys(nums))`。

## 2. 栈与队列

这两个不是新数据类型，是**两种"只能从特定位置进出"的用法**。Python 用现成的 `list` 和 `deque` 就能实现。

| | 从哪进 | 从哪出 | 顺序 | Python 写法 |
|---|---|---|---|---|
| 栈 stack | 顶部 | 顶部 | 后进先出 LIFO | `list` 的 `append` / `pop()` |
| 队列 queue | 尾部 | 头部 | 先进先出 FIFO | `deque` 的 `append` / `popleft()` |

### 栈（`list` 就是栈）★

**一句话**：只在一头加、同一头取，最后放进去的最先被拿出来，这个顺序叫 LIFO（后进先出）。

**类比**：洗好的一摞盘子。你只能往最上面放，也只能从最上面拿。想拿最底下那个，得先把上面全搬走——所以"栈"天然适合处理"最近的事先处理"：括号匹配看最近的左括号、单调栈找最近的更大值、撤销操作回退到上一步，都是同一个形状。**在 Python 里你不需要 `Stack` 类，一个 `list` 就是栈。**

```python
stack = []
stack.append(1)        # 压栈 push
stack.append(2)
top = stack.pop()      # 弹栈 pop，拿走最后进来的
print(top)             # -> 2
print(stack)           # -> [1]
print(stack[-1])       # -> 1   只看栈顶，不弹
print(len(stack))      # -> 1
```

**坑**：对空栈 `pop()` 会抛 `IndexError`；循环里弹栈前先写 `if stack:` 判断，`while stack and ...` 这个写法要背下来。

栈的经典题有一串：括号匹配（最近的左括号要先闭合）、逆波兰表达式求值、单调栈、DFS 的非递归写法，全是"压栈—弹栈"两个动作。

空栈时 `stack[-1]` 也会抛 `IndexError`，所以"看栈顶"之前同样要判空，`while stack and ...` 要养成条件反射。

记法：栈就是"后进先出"四个字，凡是"最近的先处理"，先想它。

### `collections.deque` ★

**一句话**：两头都能 O(1) 进出的队列，专门替代"用 list 当队列"的错误做法；BFS 的标准容器。

**类比**：一根两端都开口的管子。从右端塞球，从左端接球，两端都不用挪动其他球。而 `list` 是一端封死的管子，你非要从封死那头取，就得把所有球往前推一格——一次是 O(n)，循环 n 次就是 O(n²)，BFS 直接超时。

```python
from collections import deque

q = deque([1, 2, 3])
q.append(4)             # 右端进
print(q.popleft())      # -> 1   左端出，O(1)
q.appendleft(0)         # 左端进
print(list(q))          # -> [0, 2, 3, 4]
print(q[0], q[-1])      # -> 0 4   两端都能直接看
print(len(q))           # -> 4
```

**坑**：`deque` 不支持切片，`q[1:3]` 直接抛 `TypeError`；要切片先 `list(q)`，但那样又变成 O(n) 复制了。

它也能当栈用（`append` / `pop`），还支持 `deque(maxlen=3)`：超过 3 个就自动从另一头丢弃最老的元素，滑动窗口求最大值时正好用得上。

建的时候直接传可迭代对象就行：`deque([1, 2, 3])`、`deque(range(n))`、`deque("abc")`；要变回 list 就 `list(q)`。

记法：队列是"先进先出"，`popleft()` 就是"排在最前面那个人办完事走了"。

## 3. 堆与优先队列

堆解决的是"边来边取最值"的场景：数据一个个来，你随时要拿走当前最小的那个。**它不是新类型，是 list 的一种用法约定**，由 `heapq` 模块维护。

### `heapq` ★

**一句话**：一个"永远把最小值顶在最上面"的容器，压入和弹出都是 O(log n)；它的另一个名字叫**优先队列**。

**类比**：医院急诊分诊台。病人随时来，但医生每次只叫"当前最紧急"的那个——不需要把所有人排成一队，只要保证"最紧急的永远在队首"。为什么不干脆每次都 `sort()`？因为数据是边来边处理的：排序是"全来完再排"（O(n log n)），堆是"来一个插一个，随时能取最小"（每次 O(log n)），后者才符合"流式"的场景。

`heapq` 是模块，不是类，它操作的是**普通 list**。三个函数够用：

| 函数 | 作用 | 复杂度 |
|---|---|---|
| `heappush(h, x)` | 压入一个元素 | O(log n) |
| `heappop(h)` | 弹出最小值 | O(log n) |
| `heapify(lst)` | 把一个乱序 list 原地变成堆 | O(n) |
| `h[0]` | 看最小值（不弹） | O(1) |

```python
import heapq

h = []
heapq.heappush(h, 5)
heapq.heappush(h, 1)
heapq.heappush(h, 3)
print(h[0])              # -> 1   堆顶永远最小
print(heapq.heappop(h))  # -> 1
print(h)                 # -> [3, 5]

nums = [5, 1, 3]
heapq.heapify(nums)      # 原地建堆，比 push 三次快
print(nums[0])           # -> 1
print(heapq.nsmallest(2, nums))   # -> [1, 3]
```

**想要大根堆怎么办**：Python 只有小根堆，标准做法是**存负数**，取出来再取反。

```python
import heapq

h = []
for x in [5, 1, 3]:
    heapq.heappush(h, -x)      # 存 -x
print(-heapq.heappop(h))       # -> 5   最大的先出来
print(-heapq.heappop(h))       # -> 3
```

**坑**：Python **没有**大根堆，只能存负数绕过去；`heapq` 也只保证 `h[0]` 最小，`h` 整体**不是有序的**，别拿它当排序结果用；想删堆里任意一个元素它也帮不上忙，只能"弹到它为止"或加个 `deleted` 标记跳过。

## 4. 下标、切片与遍历

下标、切片、遍历是写算法时的"呼吸"——几乎每一行代码都在干这三件事。这一节全是肌肉记忆，不涉及思维，但**写错一个下标，整题就废**。

### 下标 ★

**一句话**：元素在容器里的位置编号，**从 0 开始数**，负数表示从末尾倒着数。

**类比**：电影院的座位号。第一排是 0 号排，最后一排也可以叫 -1 号排，不用知道总共几排就能找到最后一排。**所以"最后一个元素"永远是 `nums[-1]`，"倒数第二个"是 `nums[-2]`**，这个写法在算法题里到处都是，比 `nums[len(nums)-1]` 干净得多。

```python
s = "abcde"
print(s[0])       # -> a
print(s[2])       # -> c
print(s[-1])      # -> e   最后一个
print(s[-2])      # -> d   倒数第二个
print(len(s))     # -> 5
```

**坑**：长度是 5 的字符串，最大下标是 **4**；写 `s[len(s)]` 一定抛 `IndexError`，循环写 `for i in range(len(s))` 时别越界。

负下标只有"有序容器"支持——`list`、`str`、`tuple` 都行，`set` 和 `dict` 没有下标，`d[-1]` 会被当成"键为 -1"去查，查不到就 `KeyError`。

还有一个高频组合：`i` 和 `i + 1` 一起用（比较相邻元素），这时循环要写到 `len(nums) - 1`，否则最后一次 `nums[i + 1]` 越界。

速记：`nums[-1]` 最后一个、`nums[-2]` 倒数第二个、`nums[len(nums) - 1]` 和 `nums[-1]` 等价但更啰嗦。

还有：下标必须是整数，`nums[1.0]` 会抛 `TypeError`；用除法算出来的下标记得 `//` 或 `int()` 一下。

最后记一句话：**数组的合法下标范围是 `0 ~ n-1`**，所有越界错误都从忘了这一点开始。

### 切片 `s[i:j]` ★

**一句话**：一次取出一段连续元素，**含 i 不含 j**（左闭右开），第三个参数是步长。

**类比**：切面包。你说"从第 1 片切到第 3 片"，刀落在第 1 片前面和第 3 片前面，拿到的其实是第 1、2 片。左闭右开还有个隐藏好处：`s[i:j]` 的长度正好是 `j - i`，算窗口长度时不用 `+1`，少一个 off-by-one 的坑。

```python
nums = [0, 1, 2, 3, 4, 5]
print(nums[1:4])      # -> [1, 2, 3]   不含下标 4
print(nums[:3])       # -> [0, 1, 2]
print(nums[3:])       # -> [3, 4, 5]
print(nums[1:4:2])    # -> [1, 3]      第三个数是步长
print(nums[::-1])     # -> [5, 4, 3, 2, 1, 0]   反转
print(nums[:2] + nums[4:])   # -> [0, 1, 4, 5]
```

**坑**：切片是**复制**，`b = a[:]` 改 `b` 不影响 `a`，但 `b = a` 只是起了个别名，改 `b` 就是改 `a`；另外 `s[i:j]` 的 `j` 超出长度不会报错，会自动截到末尾，这一点和 `s[j]` 完全不同。

切片还能**赋值**：`nums[1:3] = [9]` 会把两个元素换成一个，长度随之变化，"原地删掉一段"用它最简洁。

字符串题里两个顺手的写法：判断回文 `s == s[::-1]`；判断"b 是不是 a 的旋转" `b in a + a`。

速记：`s[:k]` 前 k 个、`s[k:]` 从 k 到末尾、`s[-k:]` 最后 k 个、`s[::-1]` 反转。

再补一个：切片越界**不报错**，`nums[10:]` 直接返回 `[]`，所以"取不到"和"取到空"它分不开，需要区分时要先判长度。

### `enumerate` ★

**一句话**：遍历时同时拿到"下标"和"元素"，不用自己维护计数器。

**类比**：点名册。老师念的时候既报学号也报名字，你不用自己在心里数到第几个。它最常见的搭档是哈希表：`for i, x in enumerate(nums): seen[x] = i`，一行就把"值和它的位置"一起收进字典。

```python
print(list(enumerate(["a", "b"])))          # -> [(0, 'a'), (1, 'b')]
print(list(enumerate(["a", "b"], start=1))) # -> [(1, 'a'), (2, 'b')]

for i, ch in enumerate("hey"):
    if ch == "e":
        print(i)        # -> 1
```

**坑**：写 `for i in range(len(nums)): x = nums[i]` 不会错但啰嗦，而且容易把 `nums[i]` 写成 `nums[j]`；能用 `enumerate` 就别用 `range(len())`。

`start` 参数只影响编号，不影响取到的元素；要输出"第 1 个人、第 2 个人"，就写 `enumerate(xs, start=1)`，别在 `print` 里手动 `+1`。

还有个小细节：遍历时如果**要改原列表的元素**，只能写 `for i in range(len(nums))` 再 `nums[i] = ...`；`for x in nums` 拿到的 `x` 是元素的副本，改了不影响列表。

速记：`for i, x in enumerate(nums):` 是力扣题解里最常见的开头，看到它就知道下面要"用下标做事"。

调试时可以直接 `list(enumerate(xs))` 看全貌，它返回的就是一串 `(下标, 元素)` 元组。

它还能和 `zip` 叠着用：`for i, (a, b) in enumerate(zip(xs, ys))`，两个数组带下标一起遍历。

这两个搭档合起来，就是力扣题解里最省事的遍历写法。

### `zip`

**一句话**：把两个等长的列表"拉链式"配对，一次遍历同时拿两边的元素。

**类比**：拉链的两排齿，一个对一个咬合；左边第 3 个齿只跟右边第 3 个齿配。它最实用的两个用法是**同时遍历两个数组**（`for a, b in zip(xs, ys)`）和**一行建字典**（`dict(zip(keys, values))`）。

```python
names = ["amy", "bob"]
scores = [90, 85]
print(list(zip(names, scores)))    # -> [('amy', 90), ('bob', 85)]
print(dict(zip(names, scores)))    # -> {'amy': 90, 'bob': 85}
print(list(zip([1, 2, 3], "ab")))  # -> [(1, 'a'), (2, 'b')]
```

**坑**：两边长度不等时，`zip` **按短的截断**，多出来的元素被静默丢掉，不报错——这会导致答案莫名其妙少一块。

### 列表推导式 ★

**一句话**：用一行写出"对每个元素做点什么，顺便筛掉一些"，结果是新列表。

**类比**：流水线。原料从传送带过来，每件都过一道加工，不合格的从旁边缺口掉出去，最后箱子里就是成品。它的可读性来自顺序和英文一致：**"先说要什么，再说从哪来，最后说筛什么"**——`[x * x for x in nums if x % 2 == 0]` 读作"要 x 的平方，从 nums 里拿，只要偶数"。

```python
nums = [1, 2, 3, 4]
print([x * x for x in nums])                  # -> [1, 4, 9, 16]
print([x for x in nums if x % 2 == 0])        # -> [2, 4]
print([[0] * 2 for _ in range(3)])            # -> [[0, 0], [0, 0], [0, 0]]
print(sum(x for x in nums if x > 2))          # -> 7   生成器写法，省内存
```

**坑**：二维数组不能用 `[[0] * 2] * 3`，那样三行是**同一个列表**，改一行三行全变；必须用推导式让每行独立创建。

两层推导式 `[x for row in grid for x in row]` 是"先外层后内层"，顺序和写两个 `for` 一样；超过两层就换回普通循环，可读性比短更重要。

速记：`[f(x) for x in xs if cond]`——**加工在最前、来源在中间、筛在最后**，这个顺序写反就是语法错。

## 5. 十个最常忘的小语法

这一节的十个写法，几乎每道题都会用到。**忘了它们，你会写出又长又错的代码。**

### `d.get(k, 0)` ★

**一句话**：查字典时给一个"查不到就用它"的默认值，永远不会 `KeyError`。

**类比**：问前台"305 房间有人住吗"，前台不会因为没这房间就骂你，而是回答"没有"。`get` 的第二个参数就是那句"没有"——你要计数就给 `0`，要收集列表就给 `[]`，要标记"没找到"就给 `-1`。

```python
d = {"a": 1}
print(d.get("a", 0))      # -> 1
print(d.get("z", 0))      # -> 0
print(d.get("z"))         # -> None
print(d.get("z", []))     # -> []
```

**坑**：`d.get(k, [])` 每次调用都会新建一个空列表，往里 `append` 不会存回字典；要累积请用 `defaultdict(list)` 或先判断再赋值。

另一种写法是先 `if k in d:` 再取，两步、两次哈希；`get` 一步搞定，还顺手给了默认值。**计数、查表、给默认值，全用它。**

它还有个亲戚 `d.setdefault(k, 默认值)`：键不存在就设上并返回默认值，存在就直接返回旧值——"建图"时用它比 `get` 更顺手。

速记：`d.get(k, 0)` 计数、`d.get(k, -1)` 标记"没找到"、`d.get(k, [])` 给空列表。

注意默认值只在**键不存在**时生效：键存在但值是 `None`，`get` 返回的仍是 `None`，不是你的默认值。

把它练成肌肉记忆，`KeyError` 基本就跟你无关了。

### 计数：`d[k] = d.get(k, 0) + 1`

**一句话**：字典计数的标准写法——取旧值、加一、放回去，键不存在时旧值算 0。

**类比**：投票箱旁边贴一张计数表，每来一张票就在对应名字后面划一笔，第一次出现的名字从 0 开始划。这个写法值得当成一个"成语"背下来：`d[k] = d.get(k, 0) + 1`，看到"统计出现次数"就反射出这一行。

```python
d = {}
for c in "hello":
    d[c] = d.get(c, 0) + 1
print(d)               # -> {'h': 1, 'e': 1, 'l': 2, 'o': 1}
print(d["l"])          # -> 2
print(max(d.values())) # -> 2
```

**坑**：写成 `d[k] += 1` 会在键不存在时抛 `KeyError`；第一次出现必须走 `get` 或者 `defaultdict`。

### `defaultdict`

**一句话**：查不存在的键时自动建一个默认值（`0` 或空列表）的字典，省掉 `get` 和判断。

**类比**：一个自动开新账户的银行。你报一个没开户的名字，柜员不报错，直接给他开一个余额为 0 的户。它最常出现在**建图**里：`g = defaultdict(list)`，然后 `g[a].append(b)` 一行搞定"节点 a 的第一个邻居"和"第 n 个邻居"两种情况。

```python
from collections import defaultdict

g = defaultdict(list)
for a, b in [(0, 1), (0, 2), (1, 2)]:
    g[a].append(b)          # 0 号键第一次出现时自动变成 []
print(dict(g))              # -> {0: [1, 2], 1: [2]}

cnt = defaultdict(int)
cnt["x"] += 1
print(dict(cnt))            # -> {'x': 1}
```

**坑**：`if g[x]:` 这种写法会**顺手创建**一个空值键，把字典污染掉；判断存在要用 `if x in g:`。

### `Counter`

**一句话**：一次统计出"每个元素出现了几次"，还自带"出现最多的前 k 个"。

**类比**：超市盘点。把所有商品倒进一台机器，它直接给你一张表：苹果 3 个、香蕉 1 个。判断"两个字符串是不是字母异位词"时，`Counter(a) == Counter(b)` 一行就完事，比手写两个字典干净得多。

```python
from collections import Counter

c = Counter("hello")
print(c)                    # -> Counter({'l': 2, 'h': 1, 'e': 1, 'o': 1})
print(c["z"])               # -> 0   不存在的键返回 0，不报错
print(c.most_common(1))     # -> [('l', 2)]
print(Counter([1, 1, 2]) == Counter([1, 2, 1]))   # -> True  只比内容不比顺序
```

**坑**：`Counter` 是 `dict` 的子类，`c["z"]` 返回 0 但**不会**把 `"z"` 加进键里；反过来 `c["z"] += 1` 会加进去，和 `defaultdict` 行为不一样。

两个 `Counter` 还能相减：`Counter(a) - Counter(b)` 得到"a 比 b 多出来的那部分"，判断字母异位词、找多余字符都靠它。

### `float('inf')` ★

**一句话**：正无穷大，任何真实数字都比它小，用来初始化"求最小值"的答案。

**类比**：找全班最矮的人。你先假设"有个矮到无法超越的基准线"，然后每个真人一来就替换它，走完最后留下的就是最矮的。同理，求最大值就初始化成 `-inf`——`float('-inf')` 和 `float('inf')` 是一对。

```python
INF = float("inf")
print(INF > 10 ** 18)     # -> True
print(-INF < -10 ** 9)    # -> True
print(min(3, INF))        # -> 3
print(INF + 1)            # -> inf
print(INF == INF)         # -> True
```

**坑**：`best = 0` 初始化最小值，遇到"答案本身可能小于 0"的题（比如最大子数组和为负）就永远输出 0；该用 `float('inf')` 或 `nums[0]` 初始化。

注意 `inf` 是浮点数：`int(inf)` 会抛 `OverflowError`，返回值要求整数时用 `10 ** 18` 当哨兵更稳妥。

配对用法记牢：**求最小值初始化 `float('inf')`，求最大值初始化 `-float('inf')`**；如果答案一定是数组里的某个元素，直接 `best = nums[0]` 更省事。

速记：先 `INF = float('inf')`，循环里 `best = min(best, x)`，最后判 `best == INF` 就知道"根本没找到"。

它比任何数都大、比任何数都小（取负时），所以拿它当哨兵很安全：`inf > 10 ** 100` 仍然是 `True`。

这对哨兵用熟了，能省掉一堆"先判断再更新"的 `if`。

### `//` 与 `%` ★

**一句话**：`//` 是整除（向下取整），`%` 是取余数，两者满足 `a == (a // b) * b + a % b`。

**类比**：分糖果。7 颗糖分给 2 个人，每人 3 颗（`7 // 2 = 3`），剩 1 颗（`7 % 2 = 1`）。这两个符号在算法里有两个固定用途：**算中点**（`mid = (lo + hi) // 2`）和**取数位**（`x % 10` 拿个位，`x // 10` 去掉个位）。

```python
print(7 // 2)          # -> 3
print(7 % 2)           # -> 1
print(-7 // 2)         # -> -4   向下取整，不是向零取整
print(-7 % 2)          # -> 1
print(divmod(7, 2))    # -> (3, 1)
print(2 ** 10)         # -> 1024
```

**坑**：Python 的 `//` 是**向下取整**（`-7 // 2 == -4`），而 C/Java 是向零取整（得 -3）；负数下标算中点时 `(lo + hi) // 2` 在 `lo` 为负时会偏，二分里下标非负就没事。

负数取模在 Python 里结果**总是非负**，所以 `(i - 1) % n` 能安全绕回数组末尾，写"循环数组""约瑟夫环"时特别顺手。

二分里写 `mid = (lo + hi) // 2` 不用担心溢出（Python 整数没有上限）；换成 C/Java 就得写 `lo + (hi - lo) / 2`，这个差别面试官偶尔会问。

速记：`mid = (lo + hi) // 2` 算中点、`x % 10` 取个位、`x // 10` 去掉个位、`n % 2 == 0` 判偶数。

商和余数都要的时候用 `divmod(a, b)`，一次拿到两个值，比分别算两次清楚，也少算一次。

最后一个坑：`/` 是浮点除法，`7 / 2` 得 `3.5`；下标计算里用错就会抛 `TypeError`，认准 `//`。

记住这条分界线：**要整数用 `//`，要小数才用 `/`。**

### 类型标注 `-> int`

**一句话**：写在参数和返回值后面的"类型备注"，Python 不检查它，但它帮你想清楚输入输出。

**类比**：快递单上写的"易碎品"。没人在运输时真的去测，但它提醒你和别人该怎么对待这个包裹。力扣的方法签名 `def twoSum(self, nums: List[int], target: int) -> List[int]:` 就是在告诉你：进来的是"整数列表 + 整数"，出去的是"整数列表"——**先看签名，再想解法**，能省掉一半读题时间。

```python
def add(a: int, b: int) -> int:
    return a + b

print(add(1, 2))            # -> 3
print(add("a", "b"))        # -> ab   不检查类型，照样跑
print(add.__annotations__)  # -> {'a': <class 'int'>, 'b': <class 'int'>, 'return': <class 'int'>}
```

**坑**：力扣的 `List[int]` 要 `from typing import List` 才有，本地跑忘了 import 会 `NameError`；标注写错了不会报错，别指望它帮你查 bug。

### `nonlocal`

**一句话**：在嵌套函数里，声明"我要改的是外面那层函数的变量"，不是新建一个同名局部变量。

**类比**：你和室友合租，冰箱是共用的（外层变量）。你在自己房间贴张纸条写"冰箱里的牛奶归我"（`nonlocal`），不然你买的那盒只会放在你房间，冰箱里那盒永远不变。写回溯/DFS 时，如果用一个外层变量记答案（`res = []`），`append` 不需要 `nonlocal`，但 `res = []` 重新赋值就需要。

```python
def counter():
    n = 0
    def step():
        nonlocal n        # 没有这行，n += 1 会报 UnboundLocalError
        n += 1
        return n
    return step

c = counter()
print(c(), c(), c())      # -> 1 2 3
```

**坑**：只读外层变量不需要 `nonlocal`，只有"赋值/`+=`"才需要；忘了写就会抛 `UnboundLocalError`，而且报错行看起来完全正常，特别难查。

### `sorted(key=...)`

**一句话**：排序时用 `key` 指定"按什么排"——给每个元素算一个排序用的分数。

**类比**：排队按身高排。你不需要比较两个人本身，只需要比他们头顶到地面的高度。`key` 就是那把尺子。所以"按第二个元素排"是 `key=lambda x: x[1]`，"按绝对值排"是 `key=abs`，"按频率排"是 `key=lambda x: cnt[x]`——**变的只是尺子，排序算法本身不变**。

```python
words = ["bb", "a", "ccc"]
print(sorted(words, key=len))                 # -> ['a', 'bb', 'ccc']
print(sorted(words, key=len, reverse=True))   # -> ['ccc', 'bb', 'a']

people = [("amy", 90), ("bob", 85)]
print(sorted(people, key=lambda p: -p[1]))    # -> [('amy', 90), ('bob', 85)]
print(sorted(people, key=lambda p: p[0]))     # -> [('amy', 90), ('bob', 85)]
```

**坑**：`key` 只能有一个参数，`key=lambda a, b:` 直接语法错；要按多个字段排就返回元组 `key=lambda x: (x[0], -x[1])`，元组会按位依次比较。

### `a, b = b, a`

**一句话**：一行交换两个变量，右边先算成一个整体，再一起赋给左边。

**类比**：两只手各拿一个球互换。你先用"第三只手"（右边的临时元组）把两个球同时接住，再分别递回去，所以不会丢。这个"先算右边整体"的规则不只用于交换：`a, b = b, a + b`（斐波那契滚动）、`prev, cur = cur, cur.next`（链表前进）都是同一个套路。

```python
a, b = 1, 2
a, b = b, a
print(a, b)          # -> 2 1

nums = [1, 2, 3]
nums[0], nums[2] = nums[2], nums[0]
print(nums)          # -> [3, 2, 1]

x, y, z = 1, 2, 3
x, y, z = z, x, y
print(x, y, z)       # -> 3 1 2
```

**坑**：`nums[i], nums[j] = nums[j], nums[i]` 是安全的，但写成两行（先 `nums[i] = nums[j]` 再 `nums[j] = nums[i]`）就会把两个位置都变成同一个值，这是手写快排时最常见的 bug。

## 6. 复杂度：怎么一眼看出快慢

复杂度不是数学，是**"数据量翻倍时，耗时会涨多少"**的估算。面试官问"你这解法多快"，就是问这个。

### 时间复杂度与 O 记号 ★

**一句话**：把代码的执行次数写成"输入规模 n 的函数"，只留增长最快的那一项，就是 O(...)。

**类比**：估算从北京开车到上海要多久。你只关心"全程 1200 公里、平均时速 100"，不会去算轮胎转了几圈，也不会因为多了个收费站就把结论改成"要 3 天"。O 记号就是那个"只看公里数"的粗算：**常数因子和低阶项全扔掉，因为 n 一大它们就不重要了**。

```python
# O(1)：执行次数和 n 无关
def first(nums):
    return nums[0]

# O(n)：循环 n 次
def total(nums):
    s = 0
    for x in nums:
        s += x
    return s

# O(log n)：每次砍一半，n 变 2 倍只多 1 次
n, steps = 64, 0
while n > 1:
    n //= 2
    steps += 1
print(steps)          # -> 6
print(total([1, 2, 3]), first([9, 8]))   # -> 6 9
```

**坑**：O 记号只看**最高阶项**，`3n² + 100n + 7` 就是 O(n²)，那个 100n 在 n 很大时微不足道；所以别为了省一次循环把 O(n²) 优化成 O(n²/2)，量级没变。

数的方法很简单：**只看最内层那条语句执行了几次**。一层 `for` 是 n，两层嵌套是 n×n，`while n > 1: n //= 2` 是 log n，`for` 里套一个"只前进不后退"的 `while` 还是 n。

速记：看到一层 `for` 想 O(n)，两层想 O(n²)，`sort()` 想 O(n log n)，`//2` 折半想 O(log n)。

严格说 O 是"上界"，但面试语境里它就是"这算法大约要跑多少步"，不必纠结数学定义。

### 五个量级速查 ★

**一句话**：面试里 99% 的复杂度就是这五档，记住它们对应的"数据量上限"比记公式有用。

**类比**：五档车速。O(1) 是伸手拿桌上的杯子，O(log n) 是查字典，O(n) 是把一摞纸数一遍，O(n log n) 是把纸排序，O(n²) 是每张纸都和其余每张比一遍。**做题顺序反过来用这张表**：先看题目给的 n 有多大，就能反推出"出题人允许你用哪一档"，再去找对应的模板。

| 量级 | 典型代码 | n = 10⁵ 时的操作数 | 力扣能不能过 |
|---|---|---|---|
| O(1) | 哈希查表、`nums[i]` | 1 | ✅ |
| O(log n) | 二分、`//2` 折半 | 17 | ✅ |
| O(n) | 一次遍历 | 10⁵ | ✅ |
| O(n log n) | `sort()`、堆 | 1.7×10⁶ | ✅ |
| O(n²) | 双重循环 | 10¹⁰ | ❌ 超时 |

```python
import math

n = 1000
print(n)                       # -> 1000
print(int(n * math.log2(n)))   # -> 9965
print(n * n)                   # -> 1000000

# n 从 1000 涨到 2000，各量级涨了几倍
print(2 ** 10)                 # -> 1024   O(log n) 几乎不变
print(2000 // 1000)            # -> 2      O(n) 涨 2 倍
print(4 * 10 ** 6 // 10 ** 6)  # -> 4      O(n²) 涨 4 倍
```

**坑**：n = 10⁵ 时 O(n²) 是 10¹⁰ 次操作，Python 一秒只能跑约 10⁷ 次，**必然超时**；看到题目 n ≤ 10⁵ 就该条件反射地排除双重循环。

O(n log n) 几乎都来自同一个结构：**每层做 O(n) 的活，一共 log n 层**——归并排序、快排平均、堆排序都是这么来的。

速记这张对照表：n ≤ 20 可以用 2ⁿ，n ≤ 10³ 可以用 n²，n ≤ 10⁵ 必须 n log n 或 n，n ≤ 10⁷ 只能 O(n)。

### 空间复杂度

**一句话**：你额外开了多少"随 n 增长的"存储，不算输入本身占的地方。

**类比**：搬家。房子（输入）已经在那儿了，空间复杂度算的是你**额外租了几个仓库**来中转。所以"用哈希表换时间"是有代价的：时间从 O(n²) 降到 O(n)，空间从 O(1) 涨到 O(n)，面试官问"能不能不用额外空间"，就是在问你能不能把这 O(n) 省掉。

```python
nums = [1, 2, 3]

doubled = [x * 2 for x in nums]   # 新开了 n 个格子 → O(n) 空间
print(doubled)                    # -> [2, 4, 6]

total = 0                         # 只用了常数个变量 → O(1) 空间
for x in nums:
    total += x
print(total)                      # -> 6

seen = set()
for x in nums:
    seen.add(x)                   # 集合最多装 n 个 → O(n) 空间
print(len(seen))                  # -> 3
```

**坑**：递归的调用栈也算空间，递归深度 n 就是 O(n) 空间；写递归时说自己"只用了几个变量"是错的，深度 10⁵ 的递归会直接爆栈。

### 均摊分析（为什么 for 套 while 也可能是 O(n)）

**一句话**：单次操作偶尔很贵，但**总代价摊到每次操作上**很便宜，就按平均值算。

**类比**：你每月往公交卡充一次 100 块，单看"充值那天"花得很多，但摊到 30 天，每天就 3 块多。`list.append` 就是这样：偶尔要扩容搬家（O(n)），但绝大多数时候只是往尾巴上放（O(1)），摊下来仍是 O(1)。

```python
stack = []
pops = 0
for x in [1, 2, 3, 4, 5]:
    stack.append(x)                    # 每个元素进栈一次
    while stack and stack[-1] % 2 == 0:
        stack.pop()                    # 每个元素最多出栈一次
        pops += 1
print(pops, stack)                     # -> 2 [1, 3, 5]
```

上面这段 `for` 里套了 `while`，看着像 O(n²)，其实是 O(n)：**每个元素一生只进栈一次、出栈一次**，`while` 的总执行次数上限就是 n。

**坑**：判断"for 套 while"的复杂度，别看循环嵌套层数，要看**内层循环的变量总共能走多少步**；如果内层指针只前进不后退（比如双指针、单调栈），总步数就是 O(n)。

## 7. 指针与双指针

这里的"指针"和 C 语言里那个存地址的指针**没有关系**。在 Python 算法题里，它就是一个整数下标；两个整数下标配合起来，就是双指针。

### 指针 / 下标

**一句话**：在 Python 里"指针"就是**一个记录位置的整数下标**，不是 C 里那个存地址的东西。

**类比**：书签。书本身没变，书签只是标记"我读到第 37 页"。移动书签就是移动指针。所以看到题解里写 `i`、`j`、`left`、`right`、`slow`、`fast`，全都当"书签"理解——它们本身没有数据，只是**指向某个位置**。

```python
nums = [10, 20, 30]
i = 0
print(nums[i])       # -> 10
i += 1               # 指针右移一格
print(nums[i])       # -> 20
print(nums[i:])      # -> [20, 30]   从指针位置到末尾
```

**坑**：Python 没有指针算术，`i + 1` 只是数字加一，`nums + 1` 会抛 `TypeError`（list 只能和 list 相加）；想移动指针只能改 `i` 本身。

### 双指针（对撞、快慢）★

**一句话**：用两个下标从不同方向/不同速度扫同一个数组，把 O(n²) 的暴力比较压成 O(n)。

**类比**：两个人从书架两头往中间找同一本书，一个从 A 往 Z 翻，一个从 Z 往 A 翻，碰到就停——比一个人把整排翻两遍快得多。

**对撞型**（有序数组两数之和）：

```python
nums = [1, 2, 4, 7, 11]
target = 9
l, r = 0, len(nums) - 1
while l < r:
    s = nums[l] + nums[r]
    if s == target:
        break
    elif s < target:
        l += 1          # 和太小，左指针右移让和变大
    else:
        r -= 1          # 和太大，右指针左移让和变小
print(l, r)             # -> 1 3
```

**快慢型**（原地把 0 挪到末尾，保持非零元素相对顺序）：

```python
nums = [0, 1, 0, 3, 12]
slow = 0
for fast in range(len(nums)):
    if nums[fast] != 0:
        nums[slow], nums[fast] = nums[fast], nums[slow]
        slow += 1
print(nums)             # -> [1, 3, 12, 0, 0]
print(slow)             # -> 3   非零元素个数
```

**坑**：对撞型必须建立在"数组有序"上，无序数组用双指针会漏解；快慢型里 `slow` 只能前进不能后退，写成 `slow -= 1` 就会把已经排好的元素又打乱。

双指针能省掉一层循环，靠的是一个**单调性**：和太小就只能靠左指针右移来变大，和太大就只能靠右指针左移来变小。面试时把这句话说出来，就是"我真懂"的信号。

## 8. 滑动窗口 ★

滑动窗口是双指针的一个特例，也是字符串/数组题里出场率最高的模板。**核心只有一句：右边界负责扩张，左边界负责收缩，窗口里的东西始终合法。**

### 滑动窗口 ★

**一句话**：在数组/字符串上维护一个"左右边界都能动的区间"，右边界负责扩张、左边界负责收缩，全程只走一遍。

**类比**：你在一条传送带上装了一个可伸缩的取景框。框先慢慢变大，直到装不下为止；装不下时把左边的东西放掉一点，再继续往右移。框里的东西始终是"当前考虑的那一段"。它的价值在于：**暴力是"每个起点都重新数一遍"（O(n²)），滑窗是"框只往右走，从不回头"（O(n)）**。

**一句话模板**（变长窗口，背这个形状）：

```python
# 通用骨架：ok(窗口) 为 False 就收缩，直到窗口重新合法
def longest_window(s, ok):
    left, best = 0, 0
    for right in range(len(s)):
        while not ok(s[left:right + 1]):    # ① 不合法，收缩左边界
            left += 1
        best = max(best, right - left + 1)  # ② 合法了，更新答案
    return best

print(longest_window("abcabcbb", lambda w: len(w) == len(set(w))))   # -> 3
```

上面这个骨架为了好懂，每次都用切片重新判断，实际写题时要把 `ok` 换成"维护一个计数器/集合"，才能做到真正的 O(n)。

**真实例子**（无重复字符的最长子串，O(n) 版本）：

```python
s = "abcabcbb"
seen = set()
left = 0
best = 0
for right, c in enumerate(s):
    while c in seen:            # 窗口里有重复，收缩左边界
        seen.remove(s[left])
        left += 1
    seen.add(c)                 # 扩张右边界
    best = max(best, right - left + 1)
print(best)                     # -> 3
```

**坑**：收缩时**必须真的把左边元素从统计量里删掉**（`seen.remove`），只写 `left += 1` 不删，窗口内的集合会越来越大，答案偏大。

### 定长窗口 vs 变长窗口

**一句话**：题目说"长度为 k 的区间"就是定长，窗口大小固定、每次整体右移一格；题目说"最长/最短"就是变长。

**类比**：定长窗口像火车的一节车厢，长度固定，整节往前开；变长窗口像手风琴，可以拉开也可以合上。

| | 定长窗口 | 变长窗口 |
|---|---|---|
| 题目特征 | "长度为 k 的子数组" | "最长/最短的满足…的子数组" |
| 右边界 | 每次 `+1` | 每次 `+1` |
| 左边界 | 跟着 `+1`，窗口大小不变 | 用 `while` 收缩到合法 |
| 答案 | 每次移动后比较 | 窗口合法时比较 |

```python
# 定长：长度 k 的子数组最大和
nums = [1, 3, 2, 6, 1, 4]
k = 3
window = sum(nums[:k])
best = window
for i in range(k, len(nums)):
    window += nums[i] - nums[i - k]   # 进一个、出一个
    best = max(best, window)
print(best)                            # -> 11
```

**坑**：定长窗口的"进一个出一个"顺序不能反，也不能写成两个独立的 `sum()`——那样每次都是 O(k)，整体退化成 O(nk)。

## 9. 哈希表 ★

哈希表不是一种"算法"，是一种"用空间换时间"的结构选择。这一节讲清它为什么快、以及**看到什么样的题就该想到它**。

### 哈希表 ★

**一句话**：用"键"直接算出它该存在哪个格子，所以查一个元素是 O(1)，不用从头找。

**类比**：图书馆按书名的拼音首字母分书架。你要《三体》，直接走到 S 架，不用从 A 架开始一本本看。哈希函数就是"算出该去哪个架子"的那条规则。**注意这个类比的边界**：书架上的书多了会挤（哈希冲突），挤到一定程度就要加书架（扩容），所以 O(1) 是"平均情况"的说法。

```python
nums = [2, 7, 11, 15]
target = 9
seen = {}                       # 值 -> 下标
for i, x in enumerate(nums):
    need = target - x
    if need in seen:            # O(1) 查：之前见过 need 吗
        print(seen[need], i)    # -> 0 1
        break
    seen[x] = i
```

**为什么是 O(1)**：`dict`/`set` 内部是一大片格子，存的时候用哈希函数把键算成一个格子编号，取的时候用同一个函数再算一次，直接跳到那个格子。跟"表里有多少元素"无关，所以是常数时间。

**坑**：O(1) 是**平均**情况，哈希冲突严重时会退化；而且 `dict` 的键必须可哈希，`list` 不能当键，要当键先转成 `tuple`。

它也有干不了的事：哈希表**不维护顺序**，所以"第 k 大""按大小输出"它帮不上忙，那些要用堆或排序。

### 什么时候该想到哈希

**一句话**：只要你在循环里反复问"这个东西我之前见过吗 / 它出现过几次"，就该上哈希。

**类比**：进考场前老师在名单上打勾。每来一个人查一次名单（O(1)），而不是把已经进场的人从头扫一遍（O(n)）。

```python
# 场景 1：判重
print(len(set([1, 2, 2, 3])))          # -> 3

# 场景 2：两数之和（用空间换时间）
print(1 in {1: "a"})                   # -> True

# 场景 3：统计频率，找第一个只出现一次的字符
from collections import Counter
c = Counter("aabbc")
print([ch for ch in c if c[ch] == 1])  # -> ['c']
```

**四个信号**，看到就该想哈希：

1. 题目要"O(1) 判断存在"——判重、查过没见过
2. 题目要"配对"——两数之和、字母异位词
3. 题目要"计数"——出现次数、频率前 k 高
4. 你写了一层内循环只是为了"回头找某个值"——把它换成哈希就少一层

**坑**：哈希表是拿**空间换时间**，用了就是 O(n) 空间；如果题目要求 O(1) 额外空间（比如"原地"），就不能用哈希，得换双指针或原地标记。

## 10. 递归与调用栈

递归是第一个真正反直觉的东西：你在函数里调用它自己，而它居然能正确结束。这一节把"为什么能结束""为什么每层都记得住"讲清楚。

### 递归 ★

**一句话**：函数在内部调用自己，每次把问题缩小一点，缩到"不用再缩"时直接给答案。

**类比**：剥洋葱。你剥一层，剩下的还是一个洋葱（同样的东西，只是小了一圈），剥到没有皮了（终止条件）就停。**剥的动作只写一次，但要重复很多次**——这就是递归省事的地方：你只描述"一层怎么剥"，剩下的交给函数自己。写树、写回溯、写分治，全是这个形状。

递归三要素，缺一个就写不对：

| 要素 | 是什么 | 漏了会怎样 |
|---|---|---|
| ① 终止条件 | 什么情况下直接返回，不再往下调 | 无限递归，`RecursionError` |
| ② 缩小规模 | 每次调用，问题必须更小 | 同上 |
| ③ 组合答案 | 用小规模的结果拼出当前结果 | 返回值不对或返回 None |

```python
def fact(n):
    if n <= 1:              # ① 终止条件
        return 1
    return n * fact(n - 1)  # ② 缩小规模 + ③ 组合答案

print(fact(5))              # -> 120
print(fact(1))              # -> 1
```

**坑**：`return` 后面忘了写 `fact(...)` 只写 `fact(...)`，函数会返回 `None`，最后答案莫名其妙变成 `None`，而且不报错。

递归的优势在"结构本身就是递归的"：链表、二叉树、回溯、分治，用递归写出来几乎和定义一模一样；反过来，纯线性的循环硬写成递归只会更难读。

### 调用栈

**一句话**：每次函数调用都会在内存里压一张"记录卡"，函数返回时弹掉；递归就是连续压很多张。

**类比**：一摞便签。你进一个函数就在最上面贴一张"我做到哪了"，返回时把最上面那张撕掉，回到上一张继续。所以**最后进去的最先出来**，这就是栈。这也解释了为什么递归能"记住"每一层的局部变量：它们各自躺在自己那张便签上。

```python
trace = []

def down(n):
    if n == 0:
        return
    trace.append(("进", n))
    down(n - 1)
    trace.append(("出", n))

down(3)
print(trace)
# -> [('进', 3), ('进', 2), ('进', 1), ('出', 1), ('出', 2), ('出', 3)]
```

注意输出顺序：进去是 3→2→1，出来是 1→2→3，完全对称。这就是"调用栈"的形状。

**坑**：递归里的 `print` 放在递归调用**前**还是**后**，输出顺序是相反的；想"从底往上"处理（比如反转链表），代码要写在递归调用**之后**。

### 递归为什么会栈溢出

**一句话**：调用栈的层数有上限（Python 默认 1000 层），递归太深就装不下，直接报 `RecursionError`。

**类比**：便签摞到天花板就贴不上去了。不是你的逻辑错，是物理空间不够。所以看到"链表的长度最多 5000"这种数据范围，就该条件反射地想：**这题能不能用递归？深度 5000 会不会爆？**

```python
import sys

print(sys.getrecursionlimit())   # -> 1000

def depth(n):
    return 0 if n == 0 else 1 + depth(n - 1)

print(depth(500))                # -> 500
```

数据量 10⁵ 时，递归深度可能就是 10⁵，一定爆。**两个办法**：

1. 改成循环（用 `while` + 自己维护的栈）
2. 把递归深度压到 O(log n)（比如归并排序、二分）

**坑**：`sys.setrecursionlimit(100000)` 能调高上限，但栈内存也会跟着吃满，可能直接段错误崩掉进程；面试里正确做法是改写成迭代，别调这个参数。

### 记忆化

**一句话**：把算过的结果存进字典，下次遇到同样的参数直接取，不重复算。

**类比**：做数学题时在草稿纸边上记下"f(10)=55"。下次又要 f(10)，看一眼笔记就行，不用从头再推一遍。它和 DP 是同一件事的两种写法：**记忆化是"从上往下 + 查笔记"，DP 是"从下往上填表"**，能写成记忆化的题基本都能改写成 DP。

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(30))                    # -> 832040
print(fib.cache_info().hits > 0)  # -> True
```

手写版本（面试更常考，因为要你自己说清"存什么"）：

```python
memo = {}

def fib(n):
    if n < 2:
        return n
    if n in memo:          # 算过就直接取
        return memo[n]
    memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]

print(fib(30))             # -> 832040
```

**坑**：不加记忆化的 `fib(40)` 要算约 10 亿次（指数级），加了之后是 O(n)；但记忆化的 key 必须能唯一确定子问题，参数里有"可变对象"时不能直接当 key。

## 11. 链表与二叉树

这两种结构都是"用引用串起来"的，写法几乎全靠指针和递归。它们的题有个共同点：**先在纸上画出来，比盯着代码看快得多**。

### 链表节点

**一句话**：一个存着"值"和"下一个节点在哪"的小盒子，节点之间靠 `next` 串起来。

**类比**：寻宝游戏。每张纸条上写着一个线索和"下一张纸条藏在哪"，你只能顺着线索一张张找，不能跳到第 5 张。所以链表的代价很明确：**按下标访问是 O(n)**（得从头走），但"在已知位置插入/删除"是 O(1)（改两根线就行），这正是数组的短板。

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

head = ListNode(1, ListNode(2, ListNode(3)))
cur = head
vals = []
while cur:                 # cur 变成 None 就到底了
    vals.append(cur.val)
    cur = cur.next
print(vals)                # -> [1, 2, 3]
print(head.next.val)       # -> 2
```

**坑**：链表不能用 `head[2]` 取第 3 个，只能顺着 `next` 走；`while cur:` 和 `while cur.next:` 差一个节点，删除/反转时用错就会漏掉最后一个或空指针。

### dummy 哨兵 ★

**一句话**：在链表最前面加一个假的头节点，让"删除头节点"和"删除中间节点"变成同一种操作。

**类比**：排队时在最前面放一个"占位牌"。不管你是要删第一个人还是第三个人，你永远站在"要删的人的前一个"位置动手，规则统一了。没有哨兵的话，删头节点要单独写一段 `if head.val == target: head = head.next`，而这段代码在"连续删两个头节点"时最容易写错——哨兵就是来消灭这个特殊情况的。

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def remove_all(head, target):
    dummy = ListNode(0, head)     # 哨兵指向真正的头
    prev = dummy
    while prev.next:
        if prev.next.val == target:
            prev.next = prev.next.next   # 跨过被删节点
        else:
            prev = prev.next
    return dummy.next             # 返回真正的头

head = ListNode(1, ListNode(2, ListNode(2, ListNode(3))))
node = remove_all(head, 2)
out = []
while node:
    out.append(node.val)
    node = node.next
print(out)                        # -> [1, 3]
```

**坑**：忘了 `return dummy.next` 而是 `return head`，头节点被删时返回的还是一个已被摘掉的旧节点，答案直接错；哨兵本身**永远不要返回**。

哨兵不只用于删除：合并两个有序链表、按值分区、反转前 k 个节点，都是先建 `dummy`，再用一个 `tail` 往后接。

速记：`dummy = ListNode(0, head)` 开头，`return dummy.next` 结尾，这两行是固定搭配，中间的循环只管操作 `prev`。

记法：哨兵就是一个"不存真实数据、只负责站岗"的头节点。

### 二叉树

**一句话**：每个节点最多两个子节点（左、右）的树，天然适合递归处理。

**类比**：家谱。每个人最多记两个孩子，问"这一家一共几口人"，就是 1 + 左边那家的人数 + 右边那家的人数。**这个"1 + 左 + 右"就是二叉树几乎所有题的骨架**：求深度、求节点数、判断对称、翻转，都只是把那个 `1` 换成别的东西。

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

#        1
#       / \
#      2   3
#     /
#    4
root = TreeNode(1, TreeNode(2, TreeNode(4)), TreeNode(3))

def count(node):
    if not node:              # 空节点返回 0，这是递归的终止条件
        return 0
    return 1 + count(node.left) + count(node.right)

print(count(root))            # -> 4
```

**坑**：判断空节点要写 `if not node:`，别写 `if node.val is None`；叶子节点的 `left`/`right` 是 `None` 而不是"没有这个属性"，访问 `node.left.val` 前必须先判空。

### 前序 / 中序 / 后序 ★

**一句话**：三种遍历顺序的区别，只是"根节点"在什么时候被处理——前序先根、中序中间、后序最后。

**类比**：读一本书的目录。先看章标题再看内容（前序）；先看左半部分内容再看章标题（中序）；先看完所有内容最后才写章标题（后序）。**BST 的中序遍历一定是升序**，这条性质是"验证 BST""找第 k 小"这类题的钥匙。

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

root = TreeNode(1, TreeNode(2, TreeNode(4)), TreeNode(3))

def preorder(node, out):
    if not node:
        return
    out.append(node.val)          # 根
    preorder(node.left, out)      # 左
    preorder(node.right, out)     # 右

def inorder(node, out):
    if not node:
        return
    inorder(node.left, out)
    out.append(node.val)          # 根在中间
    inorder(node.right, out)

def postorder(node, out):
    if not node:
        return
    postorder(node.left, out)
    postorder(node.right, out)
    out.append(node.val)          # 根在最后

a, b, c = [], [], []
preorder(root, a)
inorder(root, b)
postorder(root, c)
print(a)     # -> [1, 2, 4, 3]
print(b)     # -> [4, 2, 1, 3]
print(c)     # -> [4, 2, 3, 1]
```

**坑**：三段代码**只有 `append` 那一行的位置不同**，别去背三套逻辑；写的时候先把 `if not node: return` 写好，再决定 `append` 放前、中、后。

记法就是看"根"在哪：根在第一个是前序，夹在中间是中序，最后一个就是后序。

面试还可能要求"不用递归"：前序用栈（先压右孩子再压左孩子），中序用栈一路向左压到底再弹。会写递归是及格，会写迭代是加分。

### BST（二叉搜索树）

**一句话**：对每个节点，左子树全部比它小、右子树全部比它大，所以查找能像二分一样砍半。

**类比**：一本按字母排好的字典。要找 M，先翻到中间，比 M 小就往左半本，比 M 大就往右半本。所以 BST 的查找、插入、删除都是 O(树高)，树平衡时是 O(log n)，退化成一条链时是 O(n)——这也是为什么会有"平衡二叉树"这种东西。

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

#        5
#       / \
#      3   7
root = TreeNode(5, TreeNode(3), TreeNode(7))

def search(node, target):
    while node:
        if node.val == target:
            return True
        node = node.left if target < node.val else node.right
    return False

print(search(root, 7))     # -> True
print(search(root, 4))     # -> False
```

**坑**：BST 的"有序"是**整棵子树**都满足，不只是父子关系；判断一棵树是不是 BST，不能只比较 `node.left.val < node.val`，要用上下界（或中序遍历是否递增）。

### 层序遍历

**一句话**：一层一层从左到右访问，用队列实现，是 BFS 在树上的版本。

**类比**：公司发通知，先通知所有部门经理（第 1 层），再由经理通知各自下属（第 2 层），一层传一层。它和 DFS 的分工很明确：**问"最短/最少几步"用层序，问"所有路径/是否存在"用 DFS**。

```python
from collections import deque

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

root = TreeNode(1, TreeNode(2, TreeNode(4)), TreeNode(3))

q = deque([root])
order = []
while q:
    node = q.popleft()
    order.append(node.val)
    if node.left:
        q.append(node.left)
    if node.right:
        q.append(node.right)
print(order)      # -> [1, 2, 3, 4]
```

**坑**：入队前要判空（`if node.left:`），直接 `q.append(node.left)` 会把 `None` 塞进队列，下一轮 `node.val` 就崩；另外要"按层输出"时，必须在 `while` 里再套一个"当前层长度"的 `for`。

## 12. 图

图就是"一堆点 + 一堆连线"。点叫**节点**，线叫**边**。难点不在概念，在"怎么存"和"怎么走"。

### 邻接表 ★

**一句话**：给每个节点配一个列表，记着"它直接连着谁"，这是最常用的存图方式。

**类比**：每个小区门口挂一块牌子，写着"从这儿能直接到哪几个小区"。想去更远的地方，就得一个牌子一个牌子看过去。它的空间是 O(节点数 + 边数)，比"开一个 n×n 的矩阵记谁和谁相连"省得多——矩阵在稀疏图上会浪费一大片 0。

```python
edges = [(0, 1), (0, 2), (1, 3)]
graph = {}
for a, b in edges:
    graph.setdefault(a, []).append(b)
    graph.setdefault(b, []).append(a)   # 无向图：两个方向都记
print(graph)        # -> {0: [1, 2], 1: [0, 3], 2: [0], 3: [1]}
print(graph[0])     # -> [1, 2]
print(len(graph))   # -> 4
```

**坑**：无向图只加了一个方向 `graph[a].append(b)`，反向就搜不到；另外节点编号不连续时用 `graph = [[] for _ in range(n)]` 会漏掉编号外的点，要么用字典，要么先确认编号范围。

带权图就把邻居存成 `(节点, 权重)` 元组，遍历写 `for nxt, w in graph[u]`；反过来，边特别多的稠密图用邻接矩阵查"两点是否相连"更快。

节点数到 10⁵、边也是 10⁵ 时，邻接表是唯一可行的存法——矩阵要 10¹⁰ 个格子，根本开不出来。

速记：`g = [[] for _ in range(n)]` 建表，`g[a].append(b)` 加边，无向图记得反向再加一次。

### DFS（深度优先搜索）

**一句话**：一条路走到黑，走不通再退回来换下一条，用递归或栈实现。

**类比**：走迷宫。你总是先挑一个岔口往里钻，钻到死胡同就退回上一个岔口，换另一个口继续。它擅长回答"能不能到""一共有几条路""连通块有几个"，但**不保证最短路**——因为它是"钻到底"而不是"一圈圈铺开"。

```python
graph = {0: [1, 2], 1: [0, 3], 2: [0], 3: [1]}

def dfs(node, seen):
    seen.add(node)                 # 标记：来过了
    for nxt in graph[node]:
        if nxt not in seen:        # 没来过才往下走
            dfs(nxt, seen)

seen = set()
dfs(0, seen)
print(sorted(seen))    # -> [0, 1, 2, 3]
print(len(seen))       # -> 4
```

**坑**：`seen.add(node)` 必须写在**进入函数的第一行**，写在 `for` 循环里会让环上的节点被反复访问，直接无限递归。

### BFS（广度优先搜索）★

**一句话**：一层一层往外扩，先看所有距离为 1 的，再看距离为 2 的，用队列实现。

**类比**：往水里扔石子，波纹一圈一圈荡开。第一圈是邻居，第二圈是邻居的邻居，所以**第一次到达某个点时，走的一定是最短路**。这就是"无权图最短路"全用 BFS 的原因：它天然按距离分层，谁先到谁就最短。

```python
from collections import deque

graph = {0: [1, 2], 1: [0, 3], 2: [0], 3: [1]}

q = deque([0])
seen = {0}                 # 入队时就标记，不是出队时
order = []
while q:
    node = q.popleft()
    order.append(node)
    for nxt in graph[node]:
        if nxt not in seen:
            seen.add(nxt)
            q.append(nxt)
print(order)               # -> [0, 1, 2, 3]
```

**坑**：`seen` 必须在**入队时**标记，如果在**出队时**才标记，同一个点会被多个邻居重复塞进队列，队列爆炸；这是 BFS 最常见的写法错误。

BFS 还能顺便求最短路：给每个节点记一个 `dist`，或者每弹完一层就 `step += 1`；把所有起点一次性入队就是**多源 BFS**（"腐烂的橘子"那类题）。

要"按层处理"就写 `for _ in range(len(q)):`，把当前层一次性弹完，层数自然就累加出来了。

速记：`q = deque([start])`、`seen = {start}`、`while q:` 三步开头，缺一个都会出错。

记法：BFS = 队列 + 已访问集合，两个都不能少。

### 拓扑排序

**一句话**：给一堆"必须先做 A 才能做 B"的任务排出顺序，每次挑一个"没有前置依赖"的任务做掉。

**类比**：大学选课。想修"编译原理"必须先修"数据结构"，你把所有课按依赖关系排个序，保证每门课的前置课都排在它前面。实现上就是 BFS 加一个"入度"计数器：**入度 = 还有几门前置课没修**，修完一门就给它后面的课减一。

```python
from collections import deque

n = 4
edges = [(0, 1), (0, 2), (1, 3), (2, 3)]   # 0 → 1 表示 0 必须先做
indeg = [0] * n
g = [[] for _ in range(n)]
for a, b in edges:
    g[a].append(b)
    indeg[b] += 1                          # b 多了一个前置

q = deque(i for i in range(n) if indeg[i] == 0)
order = []
while q:
    u = q.popleft()
    order.append(u)
    for v in g[u]:
        indeg[v] -= 1                      # 前置被做掉一个
        if indeg[v] == 0:
            q.append(v)
print(order)               # -> [0, 1, 2, 3]
print(len(order) == n)     # -> True    False 说明有环
```

**坑**：结果长度小于 n 就说明图里有环（互相依赖），这时候要返回空而不是硬排；`indeg` 数组忘了初始化或忘了 `+= 1`，排出来的顺序会漏节点。

### 并查集

**一句话**：快速回答"这两个东西是不是同一伙的"，以及"把这两伙合并成一伙"。

**类比**：社团。每个人记住"我的团长是谁"，问两个人是不是一个团，就看他们的团长是不是同一个人；合并两个团，就是让一个团长认另一个当团长。两个优化值得记住：**路径压缩**（查的时候顺手把链压平）和**按秩合并**（小树挂到大树上），都做了之后单次操作接近 O(1)。

```python
parent = list(range(5))        # 一开始每人自己当团长

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]   # 路径压缩：顺手把链缩短
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra != rb:
        parent[ra] = rb

union(0, 1)
union(1, 2)
print(find(2) == find(0))      # -> True    0、1、2 是一伙的
print(find(3) == find(0))      # -> False   3 还没加入
print(parent)                  # -> [2, 2, 2, 3, 4]
```

**坑**：`parent[x] = x` 的初始化写成 `parent = [0] * n`，所有点都指向 0，`find` 会把所有人判成同一伙；另外 `union` 里必须先 `find` 再改 `parent`，直接 `parent[a] = b` 会破坏树结构。

## 13. 四个必背套路

这四个模板覆盖了华为手撕里出现频率最高的一批题。**背下来，改两个变量就能用。**

### 二分查找 ★（含"左闭右开"坑）

**一句话**：在**有序**数组里每次砍掉一半，O(log n) 找到目标或插入位置。

**类比**：猜数字游戏。你说 50，对方说"小了"，那 1~50 全部作废，下一次直接猜 75。每次砍一半，100 万个数 20 次就猜完。所以二分的适用条件只有两条：**数组有序**（或者"能判断答案在哪一半"的单调性），**能 O(1) 访问中点**（数组可以，链表不行）。

```python
nums = [1, 3, 5, 7, 9]
target = 7
lo, hi = 0, len(nums)          # 左闭右开：[lo, hi)
while lo < hi:
    mid = (lo + hi) // 2
    if nums[mid] == target:
        break
    if nums[mid] < target:
        lo = mid + 1           # mid 已排除，从 mid+1 开始
    else:
        hi = mid               # 注意：不是 mid - 1
print(lo, mid)                 # -> 3 3
```

找"第一个 ≥ target 的位置"（`bisect_left` 的手写版，最常用）：

```python
import bisect

nums = [1, 3, 3, 5]
print(bisect.bisect_left(nums, 3))    # -> 1   第一个 3 的下标
print(bisect.bisect_right(nums, 3))   # -> 3   最后一个 3 的右边
print(bisect.bisect_left(nums, 4))    # -> 3   4 该插在下标 3
print(bisect.bisect_left(nums, 6))    # -> 4   比所有都大，插在末尾
```

**坑**：区间定义必须**从头到尾一致**。写了 `hi = len(nums)`（左闭右开），循环条件就是 `lo < hi`、更新就是 `hi = mid`；如果改成 `hi = len(nums) - 1`（闭区间），循环条件要变 `lo <= hi`、更新要变 `hi = mid - 1`。两套混着写，必死循环或漏答案。

二分不只用来"找某个数"，还能**对答案二分**：答案范围是 `[lo, hi]` 且"越大越容易满足"，就写个 `check(mid)` 判断该收哪边——"最少需要多少天""最大能装多少"全是这一类。

速记：`lo, hi = 0, len(nums)`、`while lo < hi:`、`mid = (lo + hi) // 2`，这三行是左闭右开版本的固定开头。

### 前缀和 ★

**一句话**：预先算好"前 i 个元素的和"，之后任何一段区间的和都能用两次减法 O(1) 拿到。

**类比**：体重记录表。你想知道"3 月到 5 月胖了多少"，不用把这三个月每天的都加一遍，只要"5 月底体重 − 2 月底体重"。它是"用 O(n) 的预处理换 O(1) 的查询"，所以**查询次数多的时候才划算**；只查一次就别建表了。进阶玩法是配哈希表：`{前缀和: 出现次数}` 能把"和为 k 的子数组个数"做到 O(n)。

```python
nums = [2, 4, 1, 5]
pre = [0] * (len(nums) + 1)      # pre[i] = 前 i 个元素之和
for i, x in enumerate(nums):
    pre[i + 1] = pre[i] + x
print(pre)                       # -> [0, 2, 6, 7, 12]
print(pre[3] - pre[1])           # -> 5   nums[1] + nums[2] = 4 + 1
print(pre[4] - pre[0])           # -> 12  整个数组
```

**坑**：`pre` 的长度必须是 `n + 1`，`pre[0] = 0` 是哨兵；如果开成长度 n，`pre[0]` 就既是"前 0 个"又是"第 0 个"，所有下标都会错一位。

它的逆操作叫**差分**：要给区间 `[l, r]` 整体加 `v`，就在差分数组的 `l` 处 `+v`、`r+1` 处 `-v`，最后前缀和还原，一次区间修改只要 O(1)。

不想手写循环也行：`list(itertools.accumulate(nums, initial=0))` 一行得到同样的 `pre`。速记 `pre[i + 1] = pre[i] + nums[i]`、查询写 `pre[r] - pre[l]`；注意 `pre[i]` 是"**前** i 个"，不含第 i 个，这个差一位是最高频的错误。

### 单调栈 ★

**一句话**：栈里只放"还没找到答案的下标"，并且它们的值保持单调，新元素来了就把该淘汰的一次性弹掉。

**类比**：排队看演出。后面来了个更高的人，前面比他矮的人就再也看不到舞台了——一次性把他们请出队伍，队伍始终保持"从矮到高"。它解决的是同一类问题：**"左边/右边第一个比我大（小）的元素"**，比如接雨水、柱状图最大矩形、每日温度。

```python
nums = [2, 1, 2, 4, 3]
n = len(nums)
nxt_greater = [0] * n            # 0 表示右边没有更大的
stack = []                       # 存下标，对应值从栈底到栈顶递减
for i, x in enumerate(nums):
    while stack and nums[stack[-1]] < x:
        nxt_greater[stack.pop()] = x   # 它的"下一个更大值"就是 x
    stack.append(i)
print(nxt_greater)               # -> [4, 2, 4, 0, 0]
```

**坑**：栈里存**下标**而不是值，因为要写回 `nxt_greater[下标]`；存了值就没法知道答案该填在哪个位置。

它和**单调队列**分工不同：单调栈回答"最近的更大值"（只在一头进出），单调队列回答"滑动窗口内的最大值"（两头都要动，所以用 `deque`）。

速记：整个模板的魂就是那句 `while stack and nums[stack[-1]] < x: pop`，方向换成 `>` 就是"下一个更小值"；栈里站的就是"挡住我视线的那排人"。

### 动态规划（状态 / 转移 / 初始化 / 遍历顺序）★

**一句话**：把大问题拆成一串小问题，**每个小问题只算一次并存表**，大问题查表拼出来。

**类比**：爬楼梯。到第 5 层的方法数 = 到第 4 层的方法数 + 到第 3 层的方法数，因为最后一步要么跨 1 层要么跨 2 层。你只要把每一层的结果记在纸上，一路往上填。**"拆 + 存 + 填"这三步就是 DP 的全部**，剩下的都是细节。

写 DP 就回答四个问题：

| 四步 | 要回答的问题 | 爬楼梯的答案 |
|---|---|---|
| ① 状态 | `dp[i]` 表示什么 | 到第 i 层的方法数 |
| ② 转移 | `dp[i]` 由谁推出来 | `dp[i-1] + dp[i-2]` |
| ③ 初始化 | 最小的几个值是多少 | `dp[0] = dp[1] = 1` |
| ④ 遍历顺序 | 先算谁后算谁 | i 从小到大，因为依赖前两项 |

```python
n = 5
dp = [0] * (n + 1)
dp[0], dp[1] = 1, 1                    # ③ 初始化
for i in range(2, n + 1):              # ④ 从小到大
    dp[i] = dp[i - 1] + dp[i - 2]      # ② 转移
print(dp)                              # -> [1, 1, 2, 3, 5, 8]
print(dp[n])                           # -> 8
```

**坑**：遍历顺序必须保证"用到的值已经算好"。爬楼梯是从小到大，但背包问题里 0-1 背包要**倒序**遍历容量，完全背包才**正序**——顺序写反，答案会变成"物品可以重复拿"。

## 14. 回溯与贪心

这两个是"搜索策略"层面的东西：回溯是"穷举所有可能，但聪明地穷举"，贪心是"每步都选眼前最好，赌它全局也最好"。**一个不敢赌（要撤销），一个敢赌（不回头）。**

### 回溯 ★

**一句话**：在决策树上一个个试，试完就撤销，回到上一步换下一个选项——本质是"带撤销的 DFS"。

**类比**：走迷宫时手里拿一支粉笔。每进一个岔口就在地上画个记号，走不通就退回岔口、擦掉记号、换另一条路。**"撤销"这个动作是回溯的灵魂**：不撤销，你会把上一条路的选择带进下一条路，答案全乱。

```python
res = []

def backtrack(path, choices):
    if not choices:                 # 没有可选项了，说明排完了一个
        res.append(path[:])         # 存副本，不能存 path 本身
        return
    for i, c in enumerate(choices):
        path.append(c)                            # 做选择
        backtrack(path, choices[:i] + choices[i + 1:])   # 递归
        path.pop()                                # 撤销选择

backtrack([], [1, 2, 3])
print(len(res))     # -> 6
print(res[:2])      # -> [[1, 2, 3], [1, 3, 2]]
```

**坑**：`res.append(path)` 存的是**引用**，最后所有结果都会变成同一个空列表；必须写 `path[:]` 或 `list(path)` 复制一份。

回溯的复杂度是"解的个数 × 构造每个解的代价"，所以指数级很常见；面试里要能说出"为什么这题只能枚举"，以及剪枝砍掉了哪些分支。

模板里 `choices[:i] + choices[i+1:]` 是"剩下的选项"；如果题目允许**重复选同一个元素**（组合总和），就传 `choices[i:]` 而不是 `choices[i+1:]`。

速记：`path.append(x)` → 递归 → `path.pop()`，这三行的顺序永远不变，变的只是"终止条件"和"下一步的选项"。

### 剪枝

**一句话**：在回溯的搜索树上，提前判断"这条路走下去不可能有答案"，直接砍掉整棵子树。

**类比**：摘苹果时看到这根树枝上全是青的，就不用一个个摘下来看，整枝剪掉。剪枝不改变答案，只砍掉注定失败的搜索，所以**判断条件必须"宁可放过，不可错杀"**——错杀就会漏解。

```python
res = []

def dfs(path, rest, target):
    if target == 0:                 # 凑够了
        res.append(path[:])
        return
    for i, x in enumerate(rest):
        if x > target:              # 剪枝：单个就超了，后面的更大，全跳过
            break
        dfs(path + [x], rest[i + 1:], target - x)

dfs([], [1, 2, 3, 5], 5)
print(res)      # -> [[2, 3], [5]]
```

**坑**：`if x > target: break` 能成立的前提是 `rest` **有序**；数组没排序时只能 `continue` 不能 `break`，否则会漏掉后面的小元素。

### 贪心

**一句话**：每一步都选"当前看起来最好"的那个，选了就不回头，赌全局最优。

**类比**：找零钱。要凑 173 块，你肯定先拿最大面额 100，再 50，再 10……每一步都拿能拿的最大张，最后张数最少。它和 DP 的区别就在"回不回头"：**贪心不回头、不存表、通常是 O(n)；DP 要存所有子问题的答案，因为要比较**。

```python
coins = [100, 50, 10, 5, 1]
amount = 173
used = []
for c in coins:
    while amount >= c:
        amount -= c
        used.append(c)
print(used)          # -> [100, 50, 10, 10, 1, 1, 1]
print(len(used))     # -> 7
```

**坑**：贪心只在"面额体系合适"时才对。把面额换成 `[1, 3, 4]` 凑 6，贪心拿 4+1+1 共 3 张，而最优是 3+3 共 2 张——**面试里要能说出"为什么这里贪心是对的"**，说不出来就该上 DP。
