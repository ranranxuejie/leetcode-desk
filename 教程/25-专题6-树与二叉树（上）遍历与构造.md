**本册覆盖**：6-1 二叉树的前序遍历（144）、6-2 二叉树的后序遍历（145）、6-3 二叉树的锯齿形层序遍历（103）、6-4 从中序与后序遍历序列构造二叉树（106）、6-5 翻转二叉树（226）；回顾 6-6 中序遍历（94）、6-7 层序遍历（102）、6-8 最大深度（104）、6-9 前序 + 中序构造（105）。

## 本册地图

这九道题其实是同一件事的九个侧面：**树的每个操作都是"对每个节点做同一件小事"，剩下的交给递归或队列**。

按用途分三组：

- **遍历**（6-1、6-2、6-3，回顾 6-6、6-7）：把树摊平成一维。前序、中序、后序的代码一模一样，只有一行 `append` 的位置不同；层序换了一把工具——队列。
- **构造**（6-4，回顾 6-9）：反过来，用两个摊平后的序列把树拼回去。核心是"谁当根"和"区间怎么切"。
- **改造**（6-5）：在遍历的骨架上改每个节点，是最短的递归题。

建议顺序：第 0 章（把"树 = 节点 + 两棵更小的树"钉死）→ 6-1 → 6-2（同一模板的两个位置）→ 6-3（换队列）→ 6-9 → 6-4（构造两连，对照着看）→ 6-5。6-6～6-8 已讲过，读过 [分册 C](12-分册C-链表树图.md) 的 C5～C8 就只看"换个角度"——那边讲"递归是什么"，这边讲"三种记录时刻分别能干什么"。

**本册要建立的思维模型**

1. **树是递归定义的**：一个节点 + 左子树 + 右子树，而左子树也是一棵树。所以树的代码天然是递归。
2. **遍历 = 选一个时刻记录**：进入节点时记（前序）、左子树回来时记（中序）、右子树也回来时记（后序）。
3. **递归展开就是栈**：所有递归都能手写成栈，栈里存的是"还没轮到我记录"的节点。
4. **BFS 用队列，分层靠 `len(q)`**：队列里同时躺着两层节点，先数清楚这一层有几个。
5. **构造题只做三件事**：找根、在中序里定位根、按长度切区间。

### 0.2 三种遍历只差 `append` 的位置

```python
def dfs(node):
    if not node:
        return
    # ← 位置 A
    dfs(node.left)
    # ← 位置 B
    dfs(node.right)
    # ← 位置 C
```

| 记录位置 | 名字 | 顺序 | 上面那棵树的输出 |
|---|---|---|---|
| A（进节点就记） | 前序 | 根 → 左 → 右 | `[1,2,4,5,6,7,3,8,9]` |
| B（左子树回来记） | 中序 | 左 → 根 → 右 | `[4,2,6,5,7,1,3,9,8]` |
| C（右子树也回来记） | 后序 | 左 → 右 → 根 | `[4,6,7,5,2,9,8,3,1]` |

为什么位置决定顺序：`dfs(node.left)` 这一行不返回，就说明整棵左子树还没走完。所以 A 处的代码一定发生在"任何子孙之前"——根最先；C 处的代码一定发生在"左右子树都走完"之后——根最后。

三个位置也可以混着用（A 和 C 都记一次），那就得到别的序列。**遍历不是三种魔法，是在每个节点上挑一个时刻按下快门。**

### 0.3 力扣的层序数组怎么读

## 6-1. 二叉树的前序遍历（Easy）

> 力扣 144 · 二叉树 · 递归 / 栈
> 前置：第 0 章 0.2

**一句话**：按"根 → 左 → 右"的顺序，把每个节点的值收进一个 list。

### 精讲（零基础版）

#### ① 这题要用到的东西

**二叉树节点（TreeNode）**

一句话：一个存值的小盒子，外加两个指针，分别指向它的左孩子和右孩子。

生活类比：家谱里的一个人。他有名字，还有"左孩子""右孩子"两个格子；格子里填的是另一个人，没人就填空。

力扣后台已经把这个盒子写好了，取值用点号：`node.val`、`node.left`、`node.right`。为了不写类，下面用字典演示同一个结构，你把它当成同一个东西：

```python
node = {"val": 1, "left": None, "right": None}
print(node["val"])      # -> 1
print(node["left"])     # -> None
```

这题里，`node.val` 是要抄进答案的那个数，`node.left` / `node.right` 是往下走的两条路。

**递归（recursion）**

一句话：函数在自己内部再调用自己一次，但每次的范围小一圈；小到不能再小就停。

生活类比：查家谱里"这个人的所有祖先"。查你爸爸的祖先，和查你的祖先，是同一件事，只是起点换了一个人。查到没有爸爸的人就停。

那个"停"叫**出口**。没有出口，函数会一直叫自己，直到 Python 抛 `RecursionError`。

```python
def countdown(n):
    if n == 0:          # 出口：n 到 0 就停
        return
    print(n)
    countdown(n - 1)    # 自己叫自己，但 n 小了一号

countdown(3)
# -> 3
# -> 2
# -> 1
```

这题里，`dfs(node.left)` 就是"同一套规矩，换个更小的起点再来一遍"。

**栈（stack）**

一句话：只能从末尾增删的 list。

- `stack.append(x)`：往末尾放一个（进栈）
- `stack.pop()`：把末尾那个**拿走**并返回（出栈）
- `stack[-1]`：只看一眼末尾，不拿走（看栈顶）

生活类比：一摞盘子，只能从最上面放、最上面拿。这个性质叫"后进先出"。

```python
stack = []
stack.append("第1天")
stack.append("第2天")
print(stack[-1])      # -> 第2天  只看不拿
print(stack.pop())    # -> 第2天  拿走
print(stack)          # -> ['第1天']
```

这题里，栈是递归的替身：系统替你记回程路，你要自己写就得用栈记。

**前序遍历**

一句话：每个节点都"先记自己，再走左边，最后走右边"（根 → 左 → 右）。

生活类比：进一栋房子，先在门口拍张照（根），再进左屋（连同左屋里所有房间），最后进右屋。左屋没走完，不会去右屋。

这题要的就是按这个顺序排出来的 list。

**`Optional[TreeNode]` 和 `-> List[int]`**

一句话：冒号后面写"这个参数应该是什么类型"，箭头后面写"这个函数返回什么类型"。

它是给人看的说明书，Python 不会因为它报错。`Optional[X]` 读作"X 或者 None"——树可能是空的；`List[int]` 是"装整数的 list"。

#### ② 大白话：这题到底在干什么

最笨的办法：拿张纸，从根往下走。每到一个节点抄下值，往左走；左边走到头了，再想办法回到上一个岔口，往右走。麻烦就在"回去"这一步——树只有向下的指针，没有向上的，你得自己记"我从哪来、哪边还没走"。

笨在哪：这套记路的活儿每棵树都一样，手写又长又容易漏，而且越往下记的东西越多。

聪明办法：每一层只管自己那一小块。到了节点 x，只做三件事——记下 x，对左子树说"你按同样的规矩走一遍"，对右子树说同样的话。左子树内部怎么走你不操心，它用的规矩和你一模一样。

这就是递归：你只写一遍规矩，树有几层它就自己跑几层；"回去"这件事 Python 帮你记着。

#### ③ 拿 `[1,null,2,3]` 走一遍

1 没有左孩子，右孩子是 2；2 的左孩子是 3。

| 步骤 | 调用 | 记完后的 res | 说明 |
|---|---|---|---|
| 1 | `dfs(1)` | `[1]` | 进节点就记，这就是"根" |
| 2 | `dfs(1 的左)` | `[1]` | 空的，进去就返回 |
| 3 | `dfs(1 的右)` = `dfs(2)` | `[1,2]` | 2 是右子树的根，进节点就记 |
| 4 | `dfs(2 的左)` = `dfs(3)` | `[1,2,3]` | 3 是 2 的左孩子 |
| 5 | `dfs(3 的左)` | `[1,2,3]` | 空 |
| 6 | `dfs(3 的右)` | `[1,2,3]` | 3 是叶子，两边都空 |
| 7 | `dfs(2 的右)` | `[1,2,3]` | 2 的右孩子为空 |

所以答案是 `[1,2,3]`。注意第 2 步：**1 没有左孩子，可递归还是被调用了一次**，只是进去就返回——这就是 `if not node: return` 存在的意义。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `res = []` | 准备一个空 list 装答案。写在方法里、不写在 `dfs` 里，因为所有层要往**同一个** list 里塞 |
| `def dfs(node):` | 定下"走一棵子树"的规矩 |
| `if not node: return` | 走到空位置（叶子的外面），停。`None` 在 if 里算假 |
| `res.append(node.val)` | 位置 A：进门先记自己。这一行放在哪，决定了它叫"前序" |
| `dfs(node.left)` | 把这套规矩原样交给左子树 |
| `dfs(node.right)` | 左子树整个走完了，才轮到右子树 |
| `dfs(root)` | 从整棵树的根开始跑 |
| `return res` | 收尾的返回留在外层；`dfs` 自己只负责往 `res` 里塞 |

### 考什么

- 表面考点：前序遍历。
- 真正考点：**递归三行的顺序就是遍历的定义**，以及"栈能模拟递归"——这是所有迭代写法的源头。
- 面试官想听到的关键句：① 前序、中序、后序的代码完全一样，只有 `res.append` 的位置不同；② 迭代版先压右孩子再压左孩子，因为栈是后进先出。

### 思路是怎么想出来的

- **递归**：照定义写。前序 = 记录根 + 前序遍历左子树 + 前序遍历右子树。相信两个子调用会把各自子树按前序输出完，那么三行的顺序自然就是答案。
- **为什么三行能变出三种遍历**：`dfs(node.left)` 不返回，就说明左子树还没走完，所以 `append` 放在它前面就是"根最先"，放在它后面就是"根在左之后"。
- **迭代**：递归的本质是系统帮你维护一个栈。要手写，就自己拿一个 list 当栈：弹出栈顶、记录它、把它的孩子压进去。这里有个反直觉的点——**想让左孩子先出，就得后压左孩子**。栈是后进先出，压入顺序要和输出顺序反过来。
- **Morris 遍历**：借用叶子节点空着的 `right` 位置当回程路，做到 O(1) 空间。面试说清"用空位置省掉栈"即可，不要求手写。

用 `[1,null,2,3]` 走一遍迭代版（这棵树是 1 只有右孩子 2，2 只有左孩子 3）：

```
stack=[1]  弹出 1，记录 → res=[1]；压右 2（左为空）      stack=[2]
stack=[2]  弹出 2，记录 → res=[1,2]；压左 3（右为空）    stack=[3]
stack=[3]  弹出 3，记录 → res=[1,2,3]；没有孩子          stack=[]
```

### 代码（Python）

```python
from typing import Optional, List


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def preorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        res = []

        def dfs(node: Optional[TreeNode]) -> None:
            if not node:
                return
            res.append(node.val)   # 位置 A：进节点就记录 → 根
            dfs(node.left)         # 左
            dfs(node.right)        # 右

        dfs(root)
        return res
```

迭代版（题目进阶要求，面试也爱问）：

```python
class Solution:
    def preorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        if not root:
            return []
        res, stack = [], [root]
        while stack:
            node = stack.pop()
            res.append(node.val)          # 弹出即记录，此时它就是"当前的根"
            if node.right:
                stack.append(node.right)  # 先压右
            if node.left:
                stack.append(node.left)   # 后压左，下一轮先弹出
        return res
```

**逐段讲解**：

- `res` 定义在方法内部，别挂到 `self` 上（原因见误区 4）。
- `if not node: return`：空树或走到叶子外面了，停。所有树递归的第一行都是它。
- 递归版三行里，`append` 在最前面。把它挪到 `dfs(node.left)` 后面就是中序，挪到最后就是后序——这是本册最值钱的一句话。
- 迭代版 `res.append` 紧跟 `pop()`：被弹出的节点，父节点早就记过了，它自己就是当前子树的根。
- 两个 `if` 的顺序是灵魂：**先右后左**。写反了，弹出的顺序就变成"根右左"（实测见下面误区 1）。

### 复杂度

- 时间 O(n)：每个节点记录一次；迭代版进出栈各一次。
- 空间：递归 O(h)，迭代 O(h)，`h` 是树高。链状树最坏 O(n)，完全二叉树 O(log n)。

### 常见误区（★ 最容易丢分的地方）

1. **迭代版先压左再压右**：输出变成"根右左"。用示例 2 实测，得到 `[1,3,8,9,2,5,7,6,4]`，而正确答案是 `[1,2,4,5,6,7,3,8,9]`。发现方法：只要你的输出里"右子树的节点跑到了左子树前面"，就是压栈顺序反了。
2. **迭代版空树不特判**：`stack = [root]` 里放的是 `None`，下一行 `node.val` 直接 `AttributeError`。递归版不用特判，因为 `dfs(None)` 会自己返回。
3. **把 `return res` 写进 `dfs` 里**：`dfs` 返回 `None`，`return dfs(root)` 就得到 `None`。它只负责往 `res` 里塞，收尾的 `return res` 留在外层。
4. **拿 `res` 当类属性**：`self.res = []` 写在方法外，力扣连测多个用例时越跑越长。

### 面试追问 / 变体

- "不用递归怎么写"：就是上面的栈版本；再追问就是 Morris。
- "只要第 k 个节点"：迭代版弹出时计数，到 k 直接 `return`，递归版做不到这么干脆的提前退出。
- 中序、后序的迭代版：中序见 6-6，后序见 6-2（后序的迭代比前序绕，因为根要最后出）。
- N 叉树的前序遍历（589）：把"压右、压左"换成"孩子列表倒着压"。

### 自测

- 必测用例：`[1,null,2,3] → [1,2,3]`；`[1,2,3,4,5,null,8,null,null,6,7,9] → [1,2,4,5,6,7,3,8,9]`；`[] → []`；`[1] → [1]`。
- 30 秒自检：能不能说出"为什么先压右"，以及"`append` 挪到最后会变成什么遍历"。

## 6-2. 二叉树的后序遍历（Easy）

> 力扣 145 · 二叉树 · 递归 / 栈
> 前置：6-1

**一句话**：按"左 → 右 → 根"的顺序记录，根是最后才被记下的那个。

### 精讲（零基础版）

#### ① 这题要用到的东西

**后序遍历**

一句话：每个节点都"先走左边，再走右边，最后才记自己"（左 → 右 → 根）。

生活类比：收拾房间——先把左抽屉清空，再清右抽屉，最后才把柜门关上。根是最后一个被记下的。

和 6-1 的前序比，代码只差 `res.append` 放在哪一行：放最前面是前序，放最后面就是后序。

**递归**（前面 6-1 讲过）：函数自己调用自己，靠"出口"停下来。这题里它负责"走完左、走完右，回来再记自己"。

**栈**（前面 6-1 讲过）：只能从末尾增删的 list。这题的迭代版用它当递归的替身。

**切片反转 `res[::-1]`**

一句话：从后往前把整个 list 复制一份新的。

生活类比：把一叠牌整摞翻过来，牌本身没动，你手上多了一摞倒序的。

```python
res = [1, 3, 8]
print(res[::-1])      # -> [8, 3, 1]   另抄一份倒序的
print(res)            # -> [1, 3, 8]   原来那份没变
print(res.reverse())  # -> None        原地翻转，不返回东西
print(res)            # -> [8, 3, 1]
```

`res[::-1]` 是"另抄一份倒序的"，`res.reverse()` 是"把手上这摞当场翻过来"。两者只差一份内存。

这题里它扮演最后一步：先拼出"根右左"，再整个翻过来变成"左右根"。

**为什么"根右左"翻过来就是"左右根"**

把 `根 右 左` 倒着念：`左 右 根`。就这么简单，没有更深的道理。

#### ② 大白话：这题到底在干什么

递归版没什么好想的：把 6-1 的 `append` 从第一行挪到最后一行，别的字都不改。这不是巧合——后序的定义就是"左右都回来了才记自己"。

麻烦在迭代版。迭代版靠栈，而栈的天性就是"后进先出"：你压进去的是根，第一个弹出来的还是根。可后序偏偏要求根最后出现。硬顶着写，就得额外拿一个变量记住"刚处理完的是谁"，代码立刻长一倍。

聪明办法是绕一下：先按"根右左"的顺序收集（这就是 6-1 的代码，把两个 `if` 的顺序对调），收完把整个结果倒过来读。因为 `根右左` 倒着念正好是 `左右根`。

一句话记住：**能顺着做出来的先做出来，最后翻个面**。

#### ③ 拿 `[1,null,2,3]` 走一遍

这棵树：1 只有右孩子 2，2 只有左孩子 3。正确答案是后序 `[3,2,1]`。

迭代版（先压左、后压右）：

| 步骤 | 弹出 | 记完后的 res | 栈里剩 | 说明 |
|---|---|---|---|---|
| 1 | 1 | `[1]` | `[2]` | 弹出即记；左为空跳过，压右孩子 2 |
| 2 | 2 | `[1,2]` | `[3]` | 压左孩子 3；右为空跳过 |
| 3 | 3 | `[1,2,3]` | `[]` | 3 是叶子，没有孩子可压 |

收完的 `[1,2,3]` 是"根右左"，倒过来 `[3,2,1]`，正是后序。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `res = []` | 装答案的空 list，所有层共用这一个 |
| `dfs(node.left)` | 先把左子树整棵走完 |
| `dfs(node.right)` | 再把右子树整棵走完 |
| `res.append(node.val)` | 位置 C：左右都回来了才记自己。挪到最前面就变成前序 |
| `if not root: return []` | 空树直接给空 list，别让 `None` 进栈 |
| `res, stack = [], [root]` | 一行建两个：答案 list 和只装着根的栈 |
| `node = stack.pop()` | 弹出栈顶，它就是当前子树的根 |
| `if node.left: stack.append(node.left)` | 先压左。栈后进先出，所以左会**后**弹出 |
| `if node.right: stack.append(node.right)` | 后压右，右就先弹出——于是顺序成了"根右左" |
| `return res[::-1]` | 整个翻过来，`根右左` 变 `左右根` |

### 考什么

- 表面考点：后序遍历。
- 真正考点：递归版只是把 `append` 挪到最后一行；**迭代版必须绕一下**——栈弹出的第一个元素永远是根，可后序要求根最后出。这个矛盾怎么绕过去，是本题的全部难点。
- 面试官想听到的关键句：先按"根右左"遍历（就是 6-1 的代码把两个 `if` 对调），最后把结果整个反转，就得到"左右根"。

### 思路是怎么想出来的

- **递归**：把 6-1 的 `append` 从第一行挪到最后一行，别的什么都不改。这不是巧合，是定义。
- **为什么迭代不能照抄前序**：前序能"弹出即记录"，是因为弹出的顺序恰好是"根最先"。后序要"根最后"，而栈的天性就是先弹出根。硬顶着写，就得靠一个 `prev` 变量记住刚处理完的节点，代码立刻变长。
- **绕路方案**：既然"根左右"好写，"根右左"也一样好写（把压栈顺序对调），而"根右左"反过来读正好是"左右根"。于是：**照 6-1 的代码把两个 `if` 对调，跑完把 `res` 反转**。
- 实测对照：示例 2 的"根右左"是 `[1,3,8,9,2,5,7,6,4]`，反转后 `[4,6,7,5,2,9,8,3,1]`，正是后序答案。

### 代码（Python）

```python
from typing import Optional, List


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def postorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        res = []

        def dfs(node: Optional[TreeNode]) -> None:
            if not node:
                return
            dfs(node.left)          # 左
            dfs(node.right)         # 右
            res.append(node.val)    # 位置 C：左右都回来了才记录 → 根

        dfs(root)
        return res
```

迭代版：

```python
class Solution:
    def postorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        if not root:
            return []
        res, stack = [], [root]
        while stack:
            node = stack.pop()
            res.append(node.val)           # 弹出即记录 → 先得到"根"
            if node.left:
                stack.append(node.left)    # 先压左
            if node.right:
                stack.append(node.right)   # 后压右，下一轮先弹出 → 得到"右"
        return res[::-1]                   # 根右左 反转 = 左右根
```

**逐段讲解**：

- 递归版和 6-1 逐字相同，只有 `res.append` 的位置换了。**如果只能记一件事，就记这个。**
- 迭代版的两个 `if` 和 6-1 正好相反：先压左、后压右，于是右孩子先弹出，整体顺序变成"根右左"。
- `return res[::-1]`：切片反转，O(n) 时间、O(n) 空间（生成新 list）。也可以原地 `res.reverse()` 再 `return res`，少一份拷贝。
- 为什么反转一下就对了：把后序 `左右根` 整个倒过来读，正好是 `根右左`；反过来也成立——拿到 `根右左` 再倒一次，就回到 `左右根`。

### 复杂度

- 时间 O(n)：遍历一次 + 反转一次，都是线性。
- 空间 O(h)：栈深等于树高；反转那一步额外 O(n)（用 `reverse()` 可以省掉）。

### 常见误区（★ 最容易丢分的地方）

1. **忘了最后反转**：输出是 `[1,3,8,9,2,5,7,6,4]`，看着"挺有规律"，其实是前序的镜像，不是后序。这个错误特别隐蔽，因为序列长度对、元素对，只是顺序错。
2. **压栈顺序照抄 6-1（先右后左）却又反转一次**：得到的是"前序的反转"，不是后序。示例 2 输出 `[9,8,3,7,6,5,4,2,1]`，正确答案是 `[4,6,7,5,2,9,8,3,1]`。阴险之处：`[1,null,2,3]` 这种单链树上前序 `[1,2,3]` 反转恰好等于后序，用单链自测发现不了。
3. **递归版把 `append` 放在 `dfs(node.left)` 之前**：那是前序，示例 1 输出 `[1,2,3]`。
4. **`res[::-1]` 写成 `res.reverse()` 后又 `return res[::-1]`**：反转了两次，等于没反。用 `reverse()` 就 `return res`。

### 面试追问 / 变体

- "不许反转，一次遍历出结果"：用单栈 + 一个 `prev` 变量，弹出前先看右孩子是不是刚处理完。代码长一倍，除非面试官点名要，写反转版即可。
- 后序为什么重要：释放树、算子树大小、算表达式树的值，都必须"孩子先于父亲"，这是后序的天然场景。6-4 的构造也靠"后序最后一个才是根"。
- N 叉树的后序遍历（590）：同样的反转套路。
- 前序 + 后序能不能唯一确定一棵树：不能（见 6-9）。

### 自测

- 必测用例：`[1,null,2,3] → [3,2,1]`；`[1,2,3,4,5,null,8,null,null,6,7,9] → [4,6,7,5,2,9,8,3,1]`；`[] → []`；`[1] → [1]`。
- 30 秒自检：能不能说出"为什么后序迭代要反转"，以及"根右左"是怎么从压栈顺序来的。

## 6-3. 二叉树的锯齿形层序遍历（Medium）

> 力扣 103 · 二叉树 · BFS / 队列
> 前置：6-7（层序遍历）

**一句话**：还是按层输出，但第 1 层从左往右、第 2 层从右往左、第 3 层又从左往右……一层换一个方向。

### 精讲（零基础版）

#### ① 这题要用到的东西

**队列（queue）**

一句话：一头进、另一头出的容器，先进的先出。

生活类比：排队买奶茶。后来的人站队尾，前面的人先拿到。

Python 里别拿 list 当队列（`pop(0)` 要把后面所有人往前挪一格），用 `collections` 里的 `deque`：

```python
from collections import deque

q = deque()
q.append("甲")        # 队尾进
q.append("乙")
print(q.popleft())   # -> 甲   队头出
print(q.popleft())   # -> 乙
```

`popleft` 里的 "left" 指的就是队头那一端。

**BFS（广度优先搜索）**

一句话：从起点开始，先把"距离 1 步的"全看完，再看"距离 2 步的"，一圈一圈往外扩。

生活类比：往水里扔块石头，波纹一圈圈荡开；先荡到近处，再到远处。

在树上，"一圈"就是"一层"，所以树的 BFS 又叫**层序遍历**。这题里 BFS 是骨架，锯齿只是给每层多加一个"要不要倒过来"的开关。

**`len(q)` 为什么能分层**

一句话：每轮循环开始时，队列里**只装着当前这一层**的节点。

想象一下：一开始队列里只有根（第 0 层）。你数一下 `len(q) == 1`，然后只弹 1 个；弹的时候把它的孩子塞到队尾，那些孩子属于第 1 层。这一轮弹完，队列里剩下的正好是第 1 层的全部。

所以每轮先 `size = len(q)`，再 `for _ in range(size)`。`range` 在进入循环那一刻就把数字定死了，循环中间队列变长也不影响它——这就是"只处理本层"的全部秘密。

`for _ in range(...)` 里的下划线是个约定：这个变量我不用，只是要循环这么多次。

**`level.reverse()`**（前面 6-2 讲过它和 `res[::-1]` 的区别）：前者把 list 当场翻过来、不产生新的，后者另抄一份。

#### ② 大白话：这题到底在干什么

最笨的办法：先不管锯齿，就想"怎么按层打印"。从根开始记下根；再把根的孩子按顺序记下；再把孩子的孩子按顺序记下……问题是，记到第三层时你怎么知道哪些属于第三层？光靠一个 list 从头扫到尾，所有层会挤成一坨。

笨在哪：树是往下分叉的，可你手上只有一个一维的 list，它没有"层"这个概念。

聪明办法：请一个队列来当传送带。根放上传送带；每轮从带上取下**当前这一批**，把它们的孩子放到带子末尾排队。因为先进先出，同一层的一定挨在一起，下一层的一定排在它们后面。

至于锯齿：既然每轮你手上拿到的正好是完整的一层，方向就是这一层自己的事。记住"已经完成了几层"，奇数层倒一下，偶数层不倒。

#### ③ 拿 `[3,9,20,null,null,15,7]` 走一遍

| 轮次 | 开始时队列 | size | 弹出的值 | level（倒之前） | 倒吗 | 存进 res |
|---|---|---|---|---|---|---|
| 0 | `[3]` | 1 | 3 | `[3]` | 否（0 是偶数） | `[[3]]` |
| 1 | `[9,20]` | 2 | 9、20 | `[9,20]` | 是（1 是奇数） | `[[3],[20,9]]` |
| 2 | `[15,7]` | 2 | 15、7 | `[15,7]` | 否（2 是偶数） | `[[3],[20,9],[15,7]]` |

所以答案是 `[[3],[20,9],[15,7]]`。注意第 1 轮：`9` 和 `20` 是按从左到右弹出来的，倒的是**记完之后**的 level，不是弹出的顺序。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `if not root: return []` | 空树返回 `[]`。少了这行，`deque([None])` 会进循环然后炸 |
| `res, q = [], deque([root])` | `res` 装每层，`q` 是传送带，根先上去 |
| `while q:` | 传送带上还有节点就继续 |
| `for _ in range(len(q)):` | 关键一行：**先数清这一层有几个**，然后只弹这么多个 |
| `node = q.popleft()` | 从队头取一个，先进先出 |
| `level.append(node.val)` | 记进本层的 list |
| `if node.left: q.append(node.left)` | 孩子排到队尾，属于下一轮 |
| `if len(res) % 2 == 1:` | `res` 里已有几层，当前就是第几层（从 0 数）。奇数层要倒 |
| `level.reverse()` | 原地倒过来 |
| `res.append(level)` | 这一层收工，整层塞进答案 |

### 考什么

- 表面考点：层序遍历加个方向交替。
- 真正考点：**你知不知道"分层"这件事在 BFS 里是靠什么实现的**。锯齿只是给每层多加一个"要不要倒过来"的开关，BFS 骨架一行没变。
- 面试官想听到的关键句：每轮循环开始时 `len(q)` 就是这一层的节点数，因为队列里此刻只装着这一层；取的过程中新加的孩子全在队尾，属于下一轮。

### 思路是怎么想出来的

- **先回到 102**：队列先进先出，根入队；每次弹出一个，把它的孩子放到队尾。这样同一层会连续被弹出。麻烦在于——你怎么知道一层什么时候结束？直接 `while q` 一个个弹，所有层会挤在同一个 list 里（实测得到 `[[3,9,20,15,7]]`）。
- **关键技巧**：每轮开始时先 `size = len(q)`，然后**只弹 `size` 个**。这 `size` 个正好是当前层的全部节点，它们新加的孩子排在队尾，这一轮碰不到。一轮 = 一层。
- **锯齿怎么加**：既然每轮拿到的是一个完整的 `level` 列表，方向就是它自己的事。用一个变量记"这一层该不该倒"：已经完成 `len(res)` 层，那么当前层的编号就是 `len(res)`（0 起），编号为奇数的层倒过来。
- **第二种写法**：不用 `reverse`，改用双端队列，往左走时 `append`、往右走时 `appendleft`。插入是 O(1)，比整层反转少一次线性操作。但代码多一个布尔变量，面试写第一种就够。

用示例 1 走一遍（`[3,9,20,null,null,15,7]`）：

```
第 0 轮：q=[3]        size=1  弹出 3，加 9、20        level=[3]        层号 0 偶数，不倒
第 1 轮：q=[9,20]     size=2  弹出 9、20，加 15、7    level=[9,20]     层号 1 奇数，倒 → [20,9]
第 2 轮：q=[15,7]     size=2  弹出 15、7             level=[15,7]     层号 2 偶数，不倒
结果：[[3],[20,9],[15,7]]
```

### 代码（Python）

```python
from collections import deque
from typing import Optional, List


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def zigzagLevelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        if not root:
            return []
        res, q = [], deque([root])
        while q:
            level = []
            for _ in range(len(q)):        # 先数清这一层有几个节点
                node = q.popleft()
                level.append(node.val)
                if node.left:
                    q.append(node.left)
                if node.right:
                    q.append(node.right)
            if len(res) % 2 == 1:          # 已经完成奇数层 → 当前层是第 2、4、6… 层
                level.reverse()
            res.append(level)
        return res
```

双端队列版（不反转，交替头尾插入）：

```python
class Solution:
    def zigzagLevelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        if not root:
            return []
        res, q = [], deque([root])
        left_to_right = True
        while q:
            level = deque()
            for _ in range(len(q)):
                node = q.popleft()
                if left_to_right:
                    level.append(node.val)      # 正序：往右接
                else:
                    level.appendleft(node.val)  # 逆序：往左接
                if node.left:
                    q.append(node.left)
                if node.right:
                    q.append(node.right)
            res.append(list(level))
            left_to_right = not left_to_right
        return res
```

**逐段讲解**：

- `if not root: return []`：空树返回 `[]` 而不是 `[[]]`。少了这行，`deque([None])` 进循环会炸。
- `for _ in range(len(q))`：`len(q)` 在进入循环时就算好了，循环中 `q` 变长不影响 `range`。**这就是"只处理本层"的全部秘密**，写 `while q` 或 `for node in q` 都会丢掉分层。
- `len(res) % 2 == 1`：`res` 里已经有几层，就说明当前正在处理第几层（从 0 数）。0、2、4 层正序，1、3、5 层倒序。用 `res` 的长度当层号，省掉一个额外计数器。
- `level.reverse()` 是原地反转，不产生新列表；`level[::-1]` 会复制一份，效果一样但多一次内存。
- 双端队列版里 `list(level)` 不能省：力扣要的是普通 list，返回 `deque` 虽然能打印，但和预期类型不一致。

### 复杂度

- 时间 O(n)：每个节点进出队各一次，每层最多反转一次，加起来仍是 O(n)。
- 空间 O(w)：`w` 是最大层宽，队列里同时最多两层的节点。最坏（满二叉树最后一层）约 n/2，所以最坏 O(n)。

### 常见误区（★ 最容易丢分的地方）

1. **奇偶判断写反**（`len(res) % 2 == 0` 才反转）：示例 1 输出 `[[3],[9,20],[7,15]]`，第 2 层没倒、第 3 层倒了。发现方法：第一层永远不该倒，如果你的第 1 层是倒的，就是这里反了。
2. **不先记 `len(q)`**：所有节点挤进一层，输出 `[[3,9,20,15,7]]`。
3. **用 `list` 当队列**：`q.pop(0)` 每次都要把后面所有元素往前挪，2000 个节点会明显变慢。用 `deque.popleft()`。
4. **边遍历边 `append` 到正在迭代的容器**：Python 的 `deque` 会直接抛 `RuntimeError`。
5. **空树返回 `[[]]`**：示例 3 会挂。

### 面试追问 / 变体

- 二叉树的右视图（199）：每层只取最后一个元素，`res.append(level[-1])`，连反转都省了。
- 每层平均值（637）、最大层宽：同一套骨架，只换"每层怎么处理"。
- 用 DFS 带 `depth` 参数也能按层收集：`res[depth].append(node.val)`，但要注意 `res` 得先按层数初始化。
- 要求"层内按值排序"：BFS 后对每层 `sort()`，代价 O(n log n)。

### 自测

- 必测用例：`[3,9,20,null,null,15,7] → [[3],[20,9],[15,7]]`；`[1] → [[1]]`；`[] → []`；`[1,2,3,4,5,6,7] → [[1],[3,2],[4,5,6,7]]`（四层，验证奇偶交替没有断）。
- 30 秒自检：能不能说出"`len(q)` 为什么能分层"，以及"第 0 层该不该反转"。

## 6-4. 从中序与后序遍历序列构造二叉树（Medium）

> 力扣 106 · 二叉树 · 递归 + 哈希表
> 前置：6-9（前序 + 中序构造）、6-2（后序是什么）

**一句话**：给你中序和后序两个数组，把原来那棵树还原出来，返回根节点。

### 精讲（零基础版）

#### ① 这题要用到的东西

**哈希表 / 字典（dict）**

一句话：一张"键 → 值"的对照表，给键就能直接拿到值，不用一个个翻。

生活类比：查字典。你知道拼音，直接翻到那一页，不用从第一页读起。

```python
index = {}
for i, v in enumerate([9, 3, 15]):
    index[v] = i
print(index)        # -> {9: 0, 3: 1, 15: 2}
print(index[15])    # -> 2        给键，直接拿值
print(3 in index)   # -> True     问"这个键在不在"
```

上面那三行可以用一行**推导式**写完，`{键: 值 for ...}`，读作"对每个元素，造一条 `键: 值` 的记录"：

```python
index = {v: i for i, v in enumerate([9, 3, 15])}
print(index)        # -> {9: 0, 3: 1, 15: 2}
```

这题里它存"节点的值 → 它在中序数组里的下标"，把每次找根的 O(n) 变成 O(1)。

**下标区间 `[l, r]`（两头都算）**

一句话：`[l, r]` 表示"从第 l 个到第 r 个，r 也算在内"。

注意 Python 的切片是"左闭右开"：`a[l:r]` 不含 `a[r]`。想让 `r` 也算进来，得写 `a[l:r+1]`。

```python
a = [9, 3, 15, 20, 7]
l, r = 2, 4
print(a[l:r + 1])   # -> [15, 20, 7]
print(r - l + 1)    # -> 3      区间里有几个元素
```

这题里四个下标（`in_l`、`in_r`、`post_l`、`post_r`）全是这种"两头都算"的区间，长度一律是 `右 - 左 + 1`。

**递归**（前面 6-1 讲过）：函数自己调用自己。这题里每一层递归负责"把一段区间拼成一棵子树"。

**后序遍历**（前面 6-2 讲过）：左 → 右 → 根。这题靠它"根排在最后"来定根。

#### ② 大白话：这题到底在干什么

最笨的办法：后序数组的最后一个一定是根，这点没问题。但接下来呢？你不知道根的左子树有几个节点，也就不知道后序数组里前几个属于左子树。于是只能猜：试 1 个、试 2 个……每种猜法拼出一棵树，再验证它对不对。

笨在哪：猜的组合是指数级涨的，树一大就完全跑不动。

聪明办法：答案其实白送——**中序数组里根左边那几个，就是左子树的全部节点**。所以拿根的值去中序里找一下位置，数一数它左边有几个数，这个数就是左子树的节点数。

有了这个数，两个数组同时切一刀：中序切成"左段 | 根 | 右段"，后序切成"左段 | 右段 | 根"。然后对左段、右段各递归一次。每次规模都变小，切到空就返回。

再补一步：找根的位置如果每次从头扫一遍中序，就白费了。先用一个字典把"值 → 下标"存下来，之后查表就够。

#### ③ 拿 `inorder = [9,3,15,20,7]`、`postorder = [9,15,7,20,3]` 走一遍

| 步骤 | 区间（中序 / 后序） | 根 | 中序里根的位置 k | 左子树大小 | 切出来的左 / 右 |
|---|---|---|---|---|---|
| 1 | `in[0..4]` / `post[0..4]` | `post[4]=3` | 1 | `1-0=1` | 左 `in[0..0]`/`post[0..0]`；右 `in[2..4]`/`post[1..3]` |
| 2 | `in[0..0]` / `post[0..0]` | `post[0]=9` | 0 | 0 | 两边都空，返回叶子 9 |
| 3 | `in[2..4]` / `post[1..3]` | `post[3]=20` | 3 | `3-2=1` | 左 `in[2..2]`/`post[1..1]`；右 `in[4..4]`/`post[2..2]` |
| 4 | `in[2..2]` / `post[1..1]` | `post[1]=15` | 2 | 0 | 叶子 15 |
| 5 | `in[4..4]` / `post[2..2]` | `post[2]=7` | 4 | 0 | 叶子 7 |

拼起来：`3` 是根，左 `9`、右 `20`；`20` 的左右是 `15` 和 `7`。层序写出来是 `[3,9,20,null,null,15,7]`。

注意第 1 步右子树的后序区间是 `post[1..3]`，右端点是 `post_r - 1 = 3` 而不是 4——因为 4 已经被根用掉了。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `index = {v: i for i, v in enumerate(inorder)}` | 一次扫完，记下"值 → 中序下标"。只建一次，别放进递归里 |
| `if in_l > in_r: return None` | 区间空了就返回空树。是 `>` 不是 `>=`：`in_l == in_r` 时还剩一个节点要建 |
| `root_val = postorder[post_r]` | 后序的最后一个，一定是当前子树的根 |
| `k = index[root_val]` | 查表拿到根在中序里的位置 |
| `left_size = k - in_l` | 左子树有几个节点。不是 `k`——只有整棵树时两者才相等 |
| `build(in_l, k - 1, post_l, post_l + left_size - 1)` | 左子树：中序取根的左边，后序从头开始取 `left_size` 个 |
| `build(k + 1, in_r, post_l + left_size, post_r - 1)` | 右子树：中序取根的右边，后序紧贴根的前面，所以终点是 `post_r - 1` |
| `return root` | 把自己这棵拼好的子树交回给上一层 |

### 考什么

- 表面考点：根据遍历序列建树。
- 真正考点：**用"长度"记账，而不是硬凑下标**。后序的最后一个元素是根，在中序里定位它，就能把两个数组同时切成"左子树段"和"右子树段"；每一段在两个数组里长度必须相等，这是唯一的下标依据。
- 面试官想听到的关键句：左子树有 `left_size = k - in_l` 个节点，所以后序里左子树占 `[post_l, post_l + left_size - 1]`，右子树占 `[post_l + left_size, post_r - 1]`——根在 `post_r`，已经被用掉了。

### 思路是怎么想出来的

先立住两个事实：中序是"左根右"，后序是"左右根"。

- **找根**：后序最后访问根，所以 `postorder[post_r]` 一定是当前子树的根。
- **切中序**：在中序里找到这个根的位置 `k`，`k` 左边 `[in_l, k-1]` 是左子树全部节点，右边 `[k+1, in_r]` 是右子树全部节点。`left_size = k - in_l`。
- **切后序**：后序的末尾是根，根前面依次是"左子树那一段"和"右子树那一段"。左子树有 `left_size` 个节点，所以它占 `[post_l, post_l + left_size - 1]`；右子树占 `[post_l + left_size, post_r - 1]`。
- **为什么右端点一定是 `post_r - 1`**：根占了 `post_r`，右子树紧挨在根前面，所以它的最后一个元素就是 `post_r - 1`。这一条比"长度 = 右子树长度"更好记——**根用掉最后一个，右子树就贴着根**。
- **优化**：每次用 `inorder.index(root_val)` 找根是 O(n)，递归 n 层就是 O(n²)。先用一个 dict 存"值 → 中序下标"，每次 O(1)。

用示例 1 手动走一遍（`inorder = [9,3,15,20,7]`，`postorder = [9,15,7,20,3]`）：

```
第 1 层：整段 in[0..4]，post[0..4]
  post[4] = 3 是根。3 在 inorder 里下标 k = 1。
  left_size = 1 - 0 = 1
  左子树：in[0..0] = [9]              post[0..0] = [9]
  右子树：in[2..4] = [15,20,7]        post[1..3] = [15,7,20]   ← 注意右端点是 post_r-1 = 3

第 2 层（右子树）：in[2..4]，post[1..3]
  post[3] = 20 是根。20 在 inorder 里下标 k = 3。
  left_size = 3 - 2 = 1
  左子树：in[2..2] = [15]             post[1..1] = [15]
  右子树：in[4..4] = [7]              post[2..2] = [7]

第 3 层：15、7 都是叶子，两个区间长度都是 1，各自返回一个节点。

拼起来：
        3
       / \
      9   20
         /  \
        15   7
```

对照一下 105（前序 + 中序）：那边根在 `pre_l`，左子树占 `[pre_l+1, pre_l+left_size]`，右子树从 `pre_l+left_size+1` 开始。**两题只差"根在哪一头"**，长度记账的方式完全一样。

### 代码（Python）

```python
from typing import Optional, List


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def buildTree(self, inorder: List[int], postorder: List[int]) -> Optional[TreeNode]:
        index = {v: i for i, v in enumerate(inorder)}   # 值 → 中序下标

        def build(in_l: int, in_r: int, post_l: int, post_r: int) -> Optional[TreeNode]:
            if in_l > in_r:                             # 区间为空 → 空树
                return None
            root_val = postorder[post_r]                # 后序最后一个 = 根
            root = TreeNode(root_val)
            k = index[root_val]                         # 根在中序里的位置
            left_size = k - in_l                        # 左子树节点数

            root.left = build(in_l, k - 1, post_l, post_l + left_size - 1)
            root.right = build(k + 1, in_r, post_l + left_size, post_r - 1)
            return root

        return build(0, len(inorder) - 1, 0, len(postorder) - 1)
```

**逐段讲解**：

- `index` 只建一次，之后每次找根 O(1)。这是从"能过"到"漂亮"的一步。
- 四个下标而不是切片：`postorder[post_l:post_r]` 每层都会复制一份 list，总空间 O(n²)，3000 个节点会很慢。下标全程只读原数组。
- `if in_l > in_r`：区间空了返回 `None`。是 `>` 不是 `>=`——`in_l == in_r` 时区间里还有一个节点，要建。
- `left_size = k - in_l`：不是 `k`。只有整棵树（`in_l = 0`）时两者才相等，递归进右子树就会错。
- 两个递归调用的区间是"左对左、右对右"：中序的左段配后序的左段。**中序区间和后序区间必须描述同一批节点**，这是检查写对没写对的唯一标准。
- 左子树的 `post_r` 是 `post_l + left_size - 1`，不是 `post_l + left_size`。差一就会把根或者右子树的第一个节点卷进来。

### 复杂度

- 时间 O(n)：每个节点建一次，哈希查找 O(1)。
- 空间 O(n)：哈希表 O(n) + 递归栈 O(h)。链状树最坏 O(n)。

### 常见误区（★ 最容易丢分的地方）

1. **`left_size` 写成 `k`**：示例 1 会直接 `RecursionError`（递归停不下来），因为左子树区间被撑大，根又被当成自己的左孩子。阴险的地方在于 **`in=[2,1,3], post=[2,3,1]` 这种小例子能跑对**：那两个非根节点都没有左子树，错误的 `left_size` 压根没被用到。别拿小平衡树自测。
2. **右子树后序区间抄了 105 的写法**（写成 `post_l + left_size + 1`）：跳过了一个节点，示例 1 同样 `RecursionError`，小例子同样能过——右子树为空时，错误的起点也不会被用到。后序的根在末尾，右子树**紧贴根**，没有那个 `+1`。
3. **忘了 `if in_l > in_r`**：叶子节点的孩子会继续递归，`postorder[post_r]` 取到别的元素，建出多余的节点。
4. **用切片递归**：`build(inorder[:k], postorder[:k])` 写法短，但每层复制数组，O(n²) 空间。
5. **把 `index` 建在 `build` 里面**：每层重建一次哈希表，白扔掉优化。

### 面试追问 / 变体

- "和前序 + 中序那题（105）有什么区别"：只差根在哪一头。前序根在 `pre_l`，右子树的起点要 `+1` 跳过根；后序根在 `post_r`，右子树的终点要 `-1` 让开根。其余全是长度记账。
- "前序 + 后序能不能构造"：不能唯一确定。某个节点只有一个孩子时，前序和后序都分不清它是左还是右。
- "不用哈希表行不行"：行，每次 `inorder.index()`，O(n²)，3000 个节点能过但面试官会追问。
- "能不能不递归"：可以，用显式栈从后往前扫，逻辑绕，面试写递归版足够。
- 序列化 / 反序列化（297）：本质也是"用遍历 + 空位标记"唯一表示一棵树。

### 自测

- 必测用例：题面示例 `in=[9,3,15,20,7], post=[9,15,7,20,3] → [3,9,20,null,null,15,7]`；`[-1]/[-1] → [-1]`；左斜 `in=[3,2,1], post=[3,2,1] → [1,2,null,3]`；右斜 `in=[1,2,3], post=[3,2,1] → [1,null,2,null,3]`；只有左孩子 `in=[2,1], post=[2,1] → [1,2]`。
- 30 秒自检：能不能不看代码，说出四个区间的端点分别是怎么来的。

## 6-5. 翻转二叉树（Easy）

> 力扣 226 · 二叉树 · 递归
> 前置：6-1

**一句话**：把每个节点的左右孩子互换，整棵树就左右镜像了。

### 精讲（零基础版）

#### ① 这题要用到的东西

**元组交换 `a, b = b, a`**

一句话：Python 允许一行同时给两个变量赋值，而且右边会**先整体算好**，再一起赋过去。

生活类比：两个人换座位。正确做法是两人同时起身、再各自坐下；错误做法是"你先坐他的位子"，那他一站起来就没地方坐了。

```python
a, b = 1, 2
a, b = b, a
print(a, b)          # -> 2 1

x = {"l": 1, "r": 2}
x["l"], x["r"] = x["r"], x["l"]
print(x)             # -> {'l': 2, 'r': 1}
```

拆成两句写会怎样：

```python
x = {"l": 1, "r": 2}
x["l"] = x["r"]      # 现在 x["l"] 已经是 2 了
x["r"] = x["l"]      # 拿到的还是 2
print(x)             # -> {'l': 2, 'r': 2}   两个变成同一个
```

这题里，交换左右孩子就靠这一行。

**原地修改（in-place）**

一句话：直接在原来那棵树上动刀，不新建一棵。

这题允许原地改，所以最后返回的还是同一个 `root`——根节点本身没换，换的是它下面的连接。

**递归**（前面 6-1 讲过）：函数自己调用自己。这题里"翻转一棵树" = 换自己的两个孩子 + 翻转左子树 + 翻转右子树。

**BFS / 队列**（前面 6-3 讲过）：一圈一圈往外扩，靠队列实现。这题可以用它代替递归，一层层换过去。

#### ② 大白话：这题到底在干什么

最笨的办法：新建一棵树，把原树的节点一个个搬过去，搬的时候故意反着挂。能对，但要多占一份内存，还得处理一堆空指针。

笨在哪：题目根本没要求你保留原树，多建一棵纯属浪费。

聪明办法：先看最小的例子。`[2,1,3]` 翻完是 `[2,3,1]`——根没动，两个孩子换了。再看 `[4,2,7,1,3,6,9]`：根 4 没动，7 和 2 换了，7 下面的 6、9 换了，2 下面的 1、3 也换了。

看出来了吗？**每个节点都在干同一件事：把自己的左右孩子对调**。既然如此，就写一句"交换我的两个孩子"，然后让左子树、右子树各自去干同一件事。

顺序无所谓：先换再递归、先递归再换，结果一样。因为"换"只动当前节点，"递归"只管下面，互不干扰。

#### ③ 拿 `[4,2,7,1,3,6,9]` 走一遍

| 步骤 | 进入的节点 | 换之前（左 / 右） | 换之后（左 / 右） |
|---|---|---|---|
| 1 | 4 | 2 / 7 | 7 / 2 |
| 2 | 7（原右孩子） | 6 / 9 | 9 / 6 |
| 3 | 9 | 空 / 空 | 空 / 空 |
| 4 | 6 | 空 / 空 | 空 / 空 |
| 5 | 2（原左孩子） | 1 / 3 | 3 / 1 |
| 6 | 3 | 空 / 空 | 空 / 空 |
| 7 | 1 | 空 / 空 | 空 / 空 |

层序写出来是 `[4,7,2,9,6,3,1]`。注意第 2 步进的是 **7**——因为第 1 步换完之后，`root.left` 已经是原来的右孩子了。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `if not root: return None` | 空树翻过来还是空。这是递归的出口 |
| `root.left, root.right = root.right, root.left` | 全题的核心一行：同时交换。右边先算成一个元组，再一起赋过去 |
| `self.invertTree(root.left)` | 处理换过来的那棵（原来是右子树） |
| `self.invertTree(root.right)` | 另一棵 |
| `return root` | 返回根。根节点自己没变，变的是它下面的连接 |
| `q = deque([root])` | BFS 版：根先上队列 |
| `node = q.popleft()` | 从队头取一个 |
| `node.left, node.right = node.right, node.left` | 取出来就换它的两个孩子 |
| `q.append(node.left)` 和 `q.append(node.right)` | 换完再入队。两个都要入，先后无所谓 |

### 考什么

- 表面考点：递归交换左右子树。
- 真正考点：**递归的粒度**——"交换当前节点的两个孩子"和"交换整棵树"是两件事，前者要发生在每个节点上。以及 Python 元组赋值的求值顺序。
- 面试官想听到的关键句：对每个节点做同一件事（换孩子），所以先换根的孩子、再对两个孩子递归，顺序反过来（先递归后换）也对。

### 思路是怎么想出来的

- **先看小例子**：`[2,1,3]` 翻完是 `[2,3,1]`——根没动，两个孩子换了。再看 `[4,2,7,1,3,6,9]`：根 4 没动，7 和 2 换了，7 的孩子 6、9 也换了，2 的孩子 1、3 也换了。**每个节点都干同一件事：交换自己的左右孩子。**
- **所以是递归**：`invert(root)` = 交换 root 的左右孩子 + `invert(root.left)` + `invert(root.right)`。交换和递归谁先谁后都行，因为交换只动当前节点，递归只管子节点。
- **交换怎么写**：Python 里 `a, b = b, a` 是安全的，因为**右边先整体算成一个元组 `(b, a)`，再解包赋值**。写成两句就会丢数据：
  ```python
  root.left = root.right     # 此时 root.left 已经变成原来的右孩子
  root.right = root.left     # 拿到的还是右孩子 → 两个孩子变成同一个
  ```
  实测这种写法在示例 1 上输出 `[4,7,7,9,9,9,9]`：值重复出现，因为同一个子树被挂到了两边。
- 同样的坑在递归里更隐蔽：
  ```python
  root.left = self.invertTree(root.right)    # root.left 被覆盖，原来的左子树丢了
  root.right = self.invertTree(root.left)    # 翻转的是刚挂上去的右子树
  ```
  要么先递归拿到两个结果再赋值，要么先交换再递归。

### 代码（Python）

```python
from typing import Optional


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def invertTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        if not root:                     # 空树：翻过来还是空
            return None
        root.left, root.right = root.right, root.left   # 右边先算成元组，再赋值
        self.invertTree(root.left)       # 处理换过来的左子树（原右子树）
        self.invertTree(root.right)
        return root
```

BFS 版（层序骨架，换完孩子再入队）：

```python
from collections import deque


class Solution:
    def invertTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        if not root:
            return None
        q = deque([root])
        while q:
            node = q.popleft()
            node.left, node.right = node.right, node.left
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
        return root
```

**逐段讲解**：

- `if not root: return None`：空树返回 `None`。写成 `return root` 也对（此时 `root` 就是 `None`），但 `return None` 更直白。
- `root.left, root.right = root.right, root.left`：这一行就是全题。元组赋值的安全性来自"先求值、后赋值"，和 `a, b = b, a` 是同一个机制。
- 递归的两个参数写 `root.left` / `root.right`：交换之后它们已经互换了身份。这题两边都要翻，写哪个结果都一样，但别养成"以为没换"的习惯。
- 返回值是 `root` 而不是递归的返回值：力扣要的是整棵树的根，根节点本身没变。
- BFS 版里交换之后 `node.left` 已是原来的右孩子，但**两个都要入队**，先后无所谓，别只入队一个。

### 复杂度

- 时间 O(n)：每个节点访问一次、交换一次。
- 空间：递归 O(h)，BFS O(w)。最坏都是 O(n)（链状树 / 最后一层）。

### 常见误区（★ 最容易丢分的地方）

1. **两句赋值代替元组交换**：`root.left = root.right` 之后再 `root.right = root.left`，两个孩子指向同一棵子树。示例 1 输出 `[4,7,7,9,9,9,9]`，值重复是最好认的特征。
2. **只交换根，忘了递归**：输出 `[4,7,2,6,9,1,3]`——第二层的 2、7 换了，第三层没换。看起来"差不多对"，其实只翻了一层。
3. **递归里先覆盖再递归**：`root.left = self.invertTree(root.right)` 这行一执行，原来的左子树就没人引用了（Python 会回收它），后面再想翻也找不回来。
4. **忘了 `return root`**：力扣拿不到树，判 `null`。
5. **以为要返回新树**：题目允许原地改，返回同一个 `root` 即可；面试官若要求"不许改原树"，才需要新建节点。

### 面试追问 / 变体

- "递归能不能换成后序"：能，先翻两个孩子再交换，结果一样。
- 对称二叉树（101）：判断一棵树是否左右镜像，`check(left, right)` 里比较 `left.val == right.val` 且交叉递归。
- 判断两棵树是否互为翻转（951 的弱化版）：同时遍历，一边按原顺序、一边按交换后的顺序比。
- "翻转两次会怎样"：回到原树，可以用来自测。

### 自测

- 必测用例：`[4,2,7,1,3,6,9] → [4,7,2,9,6,3,1]`；`[2,1,3] → [2,3,1]`；`[] → []`；`[1] → [1]`；翻两次应还原（自测里验证过）。
- 30 秒自检：能不能说出元组交换为什么安全，以及"先递归后交换"为什么也行。

## 6-6. 二叉树的中序遍历（回顾）

> 第一册已精讲：[分册 C · C5](12-分册C-链表树图.md)
> 力扣 94 · 二叉树 · 栈 · Easy

### 精讲（零基础版）

#### ① 这题要用到的东西

**中序遍历**（前面 6-1、6-2 讲过前序和后序，这里补第三个）：每个节点"先走左边，再记自己，最后走右边"（左 → 根 → 右）。代码和前序、后序逐字相同，只有 `res.append` 挪到了中间。

**用栈模拟"一路向左"**：递归版的中序，进了节点第一件事就是钻左孩子，钻到底才回头。手写迭代版时，就得先把这条左链上的节点全压进栈——它们都是"左子树还没处理完、自己还没被记下"的节点。

这题里，栈扮演"还没轮到我记录的祖先名单"。

#### ② 大白话：这题到底在干什么

递归版不用想：`dfs(左)` → 记自己 → `dfs(右)`，三行。

迭代版的难点只有一个：**什么时候该记自己**。想一下你的处境——站在节点 x 上，你要先确认"x 的左子树是不是已经全走完了"。没走完，就往左下走；走完了，x 就该被记下来，然后转向 x 的右子树。

于是循环长这样：先一路向左，把沿途每个节点压进栈（它们都还没被记）；走到空，说明最左边那个的左子树空了，弹出栈顶记下它；再把它当成新的起点，去它的右子树重复同一套动作。

`while cur or stack` 两个条件缺一不可：`cur` 管"还在往下钻"，`stack` 管"还有祖先没记"。两个都空了，整棵树才算走完。

**30 秒回顾**：`dfs(left)` → 记录 → `dfs(right)`。迭代版是"一路向左压栈，弹出来记录，再转向右子树"，O(n) 时间、O(h) 空间。

**核心代码（背这一段就够）**：

```python
res, stack, cur = [], [], root
while cur or stack:
    while cur:                 # 一路向左，把祖先压栈
        stack.append(cur)
        cur = cur.left
    cur = stack.pop()          # 左边处理完了，轮到自己
    res.append(cur.val)
    cur = cur.right            # 转向右子树
```

**换个角度**：

- 中序真正的用处不在"输出顺序"，而在**二叉搜索树**：对 BST 做中序，得到的一定是升序。98（验证 BST）、230（第 k 小）、501（众数）全靠这一条。看到 BST 就该条件反射想到中序。
- 迭代版的循环不变量值得记牢：栈里装的是"左子树已处理完、自己还没被记录"的节点，而且**从栈底到栈顶的值是递减的**（都是还没访问的祖先）。理解了这一点，就能解释为什么 `while cur or stack` 两个条件缺一不可。
- 空间上中序是三种遍历里最"深"的：它必须攒够一整条左链才能开始输出，链状树要 O(n) 的栈。
- 迭代版还有"先无条件压左链"的变体写法。别被不同版本绕晕，判断标准只有一条：**栈顶那个节点的左子树，是不是已经处理完了**。是，就弹出记录；不是，就继续往左下走。

## 6-7. 二叉树的层序遍历（回顾）

> 第一册已精讲：[分册 C · C6](12-分册C-链表树图.md)
> 力扣 102 · 二叉树 · BFS / 队列 · Medium

### 精讲（零基础版）

#### ① 这题要用到的东西

**队列**（前面 6-3 讲过）：一头进、另一头出，先进先出。这题用它当"传送带"，同一层的节点在带上一定挨在一起。

**`len(q)` 分层**（前面 6-3 讲过）：每轮循环开始时队列里只有当前这一层，所以 `size = len(q)` 数出来的就是本层的节点数，只弹这么多个，一轮正好一层。

**`deque`**：`collections` 里的双端队列，`popleft()` 从队头取是 O(1)；拿 list 写 `pop(0)` 会把后面所有元素往前挪一格，慢得多。

#### ② 大白话：这题到底在干什么

递归版没法直接写这题——递归是"一条路走到黑"，它天然会把一棵子树钻透再回头，不会"横着"一层层走。

所以换工具：用队列。根先进队；然后反复做一件事——从队头取一个节点，记下它，把它的两个孩子排到队尾。因为先进先出，第一层的节点一定排在第二层节点的前面，取出来的顺序天然就是"一层一层、从左到右"。

唯一要补的是"哪几个属于同一层"。答案就在队头：每轮开始时数一下队列里有几个，就弹几个，弹出来的正好是一整层；这一轮新加的孩子排在队尾，这一轮碰不到。

**30 秒回顾**：队列存节点，每轮先 `size = len(q)`，只弹 `size` 个，弹的时候把孩子放到队尾。一轮一层。O(n) 时间，O(w) 空间。

**核心代码（背这一段就够）**：

```python
if not root:
    return []
res, q = [], deque([root])
while q:
    level = []
    for _ in range(len(q)):    # 循环开始时 len(q) 就是本层节点数
        node = q.popleft()
        level.append(node.val)
        if node.left:
            q.append(node.left)
        if node.right:
            q.append(node.right)
    res.append(level)
```

**换个角度**：

- `len(q)` 的本质是"层边界"，不是"节点计数"。任何需要知道"我在第几层"的题，都可以在这个位置插一脚：103 的锯齿、199 的右视图、637 的平均值、116 的 `next` 填充，全是同一行代码的变体。
- 队列里同时最多躺两层节点，这是 O(w) 空间而不是 O(n) 的原因。写复杂度时能说出这句话，比背结论强。
- 反过来，DFS 带 `depth` 也能按层收集：`res[depth].append(node.val)`。代价是要处理"`res` 还没有第 depth 项"的情况，收益是空间降到 O(h)。面试官问"不用队列行不行"，答案就是它。
- 还有一条岔路：把 `(节点, 层号)` 元组塞进队列，靠层号判断换层。能跑，但每层都要多做一次比较，还得处理层号跳变；`len(q)` 是现成的 O(1) 边界，没必要绕。
- 队列的长度最多是"当前层 + 下一层"的节点数。满二叉树最后一层能占 n/2，所以最坏 O(n)；而链状树每层只有一个节点，队列里永远只有一个元素，空间反而降到 O(1)。同一种写法，空间差一个 n，取决于树的形状。

## 6-8. 二叉树的最大深度（回顾）

> 第一册已精讲：[分册 C · C7](12-分册C-链表树图.md)
> 力扣 104 · 二叉树 · 递归 · Easy

### 精讲（零基础版）

#### ① 这题要用到的东西

**递归的"后序位置"**（前面 6-2 讲过后序遍历）：`dfs(左)`、`dfs(右)` 都返回之后，紧接着的那一行代码叫后序位置。放在这里的代码能同时拿到左右两边的结果——这正是"先问孩子、再算自己"的写法。

**出口与递推式是配套的**：这题的出口是"空树返回 0"，递推式是"`1 + max(左, 右)`"。出口定的是"深度按节点数算"；哪天改成按边数算，出口就得变成 -1，其余不动。

#### ② 大白话：这题到底在干什么

先想人是怎么量的：站在根上问"我这棵树多高"，你没法直接答，但你敢说"比我高的那棵子树再高一层"。于是你把问题丢给两个孩子：左边多高？右边多高？拿回两个数，取大的那个，加 1（加的是自己这一层）。

孩子怎么回答？它也用同一句话去问它的孩子。问到空位置，空位置答 0——那里没有节点，高度就是 0。

一层层问下去、一层层答上来，最后根拿到答案。整个过程只有一句递推式，没有任何循环。

**30 秒回顾**：空树返回 0，否则 `1 + max(左深, 右深)`。O(n) 时间、O(h) 空间。

**核心代码（背这一段就够）**：

```python
def maxDepth(self, root: Optional[TreeNode]) -> int:
    if not root:
        return 0
    return 1 + max(self.maxDepth(root.left), self.maxDepth(root.right))
```

**换个角度**：

- 这行代码其实是**后序位置**的典型用法：先拿到左右子树的答案，再合并成自己的答案。6-2 的后序遍历和它是同一个骨架——`append` 换成 `return`，就从"收集"变成了"汇总"。
- `max` 不能换成 `+`：换成 `+` 数的是节点总数（示例 1 会得 5）。但**如果题目问"节点总数"，就该用 `+`**——两个递推式只差一个函数名，考的是你有没有读懂"深度是一条路径"。
- 递归深度是真实风险：节点数上限 10⁴，链状树递归 10⁴ 层，超过 Python 默认的约 1000 会 `RecursionError`。面试可以主动提 BFS 版（层数计数），或者提"这题也能用显式栈做后序"。
- 这题的返回值是 543（二叉树的直径）、110（平衡二叉树）、124（最大路径和）的地基：那些题都是"递归返回深度，同时用左右深度顺手更新一个全局答案"。
- 顺带记一个约定：空树返回 0，说明深度按**节点数**算。哪天题目改成按边数算，base case 要变成 -1，其余不动——base case 和递推式是配套的，改一个另一个就得跟着改。

## 6-9. 从前序与中序遍历序列构造二叉树（回顾）

> 第一册已精讲：[分册 C · C8](12-分册C-链表树图.md)
> 力扣 105 · 二叉树 · 递归 + 哈希表 · Medium

### 精讲（零基础版）

#### ① 这题要用到的东西

**哈希表**（前面 6-4 讲过）：键 → 值的对照表，给出节点值就直接拿到它在中序里的下标，O(1)。

**"长度记账"**（前面 6-4 讲过）：`left_size = k - in_l` 是左子树的节点数。同一批节点在中序里长 `left_size`，在前序里也长 `left_size`，只是起点不同。这题和 6-4 的唯一差别是"根在哪一头"：前序的根在**第一个**，后序的根在**最后一个**。

#### ② 大白话：这题到底在干什么

它和 6-4 是同一道题的镜像。前序的第一个是根，中序里根的左边是左子树；数出左子树有几个节点（`left_size`），前序里紧跟着根的那 `left_size` 个就是左子树，剩下的才是右子树。

所以代码只差两处：根从 `pre_l` 取，右子树的起点要 `+1` 跳过根。其余全是长度记账。

为什么必须给中序？因为前序只能告诉你"谁是根"，告诉不了你"左右的分界线在哪"。中序的"左根右"把分界线暴露出来了——根左边全是左子树。这也顺带解释了"前序 + 后序不能唯一建树"：没有中序，只有一个孩子的树分不清那孩子是左还是右。

**30 秒回顾**：前序第一个是根，在中序里定位它，左边是左子树、右边是右子树；`left_size = k - in_l`，前序左段是 `[pre_l+1, pre_l+left_size]`，右段从 `pre_l+left_size+1` 开始。哈希表存"值 → 中序下标"，总 O(n)。

**核心代码（背这一段就够）**：

```python
k = index[preorder[pre_l]]
left_size = k - in_l
root.left = build(pre_l + 1, pre_l + left_size, in_l, k - 1)
root.right = build(pre_l + left_size + 1, pre_r, k + 1, in_r)
```

**换个角度**：

- **为什么必须给中序**：前序只能告诉你"谁是根"，不能告诉你"左右子树的分界线在哪"。中序的"左根右"恰好把分界线暴露出来——根左边全是左子树。这就是"前序 + 后序不能唯一建树"的根源：没有中序，单孩子的树分不清左右。
- 把 `left_size` 理解成"**两个数组共用的长度**"，比记四个端点稳。左子树在中序里长 `left_size`，在前序里也长 `left_size`，只是起点不同。106 是同一句话，把起点换到末尾。
- 105 和 106 可以互推：105 建出来的树，取它的中序和后序，喂给 106 必须还原出同一棵。本册自测里就跑了这个交叉验证——**写构造题时，这种"自己验证自己"的手法比肉眼检查可靠**。
