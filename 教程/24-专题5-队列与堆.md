## 本册地图

第一册讲栈时说过一句话：**栈只暴露一端**。这一册的两个容器也是"只暴露特定位置"，只是暴露的位置不一样：

- **队列**（`deque`）暴露**两端**：一头进、另一头出，先进先出。
- **堆**（`heapq`）暴露**最小值**：不管谁先进来，`h[0]` 永远是当前最小的那个。

这 6 道题可以分成三组：

| 组 | 题 | 在练什么 |
|---|---|---|
| 互相模拟 | 225、232 | 用 A 容器的标准操作拼出 B 容器的语义 |
| Top-K 三连 | 215、347、973 | 同一个模板（大小为 k 的堆），换三次"比较什么" |
| 双堆 | 295 | 一个堆不够，用两个堆从两头夹住中位数 |

**互相模拟那两题（225、232）看着像脑筋急转弯，其实是最能练"容器语义"的题**：你必须清楚每个容器"哪一端是活的"，才写得出来。Top-K 三连是面试高频，模板只有一个，但"该用小顶堆还是大顶堆"这个判断每年都有人错。295 是这一册唯一需要"两个堆配合"的题，也是唯一 Hard。

建议顺序：**232 → 225 → 215 → 347 → 973 → 295**。232 和 225 互为镜像，先做 232（"两个栈倒一次"更直观）；215 建立 Top-K 模板；347 和 973 是同一个模板的两次应用；295 放最后。

## 零、先把"队列"和"堆"说清楚

这一节是这一册的地基。第一册只在 [01-Python 写算法题的基本功](01-Python写算法题的基本功.md) 的 3.6 节和 [03-题型模板总览](03-题型模板总览.md) 的「⑩ 堆」里过了一遍 `heapq` 的用法，还没在真题里用过。所以哪怕你急着做题，也先花十分钟把 0.2 和 0.5 读完。

### 0.1 队列：一头进、另一头出

队列就是排队买饭：从队尾进，从队头出，先进先出（FIFO）。

Python 里**不要用 `list` 模拟队列**。`list.append(x)` 是 O(1)，但 `list.pop(0)` 是 O(n)——它要把后面所有元素往前挪一格。n 次出队就是 O(n²)。

用 `collections.deque`（双端队列）：

```python
from collections import deque
q = deque()
q.append(3)      # 从右边进，O(1)
q.append(7)
q.popleft()      # 从左边出 -> 3，O(1)
q[0]             # 看队头 -> 7，O(1)
```

`deque` 的两端增删都是 O(1)，这就是它存在的理由。

### 0.2 堆：一个"随时能拿到最小值"的容器

堆（也叫**优先队列**）是这样一个容器：你不断往里扔数，它随时能用 O(1) 告诉你"现在里面最小的是哪个"，并且用 O(log n) 把这个最小值取走。

它不是"排好序的 list"。堆只保证一件事：**`h[0]` 是当前所有元素里最小的**。别的元素之间没有顺序保证，所以不要对堆做切片、不要假设 `h[1]` 是第二小。

```python
import heapq
h = []
heapq.heappush(h, 5)     # O(log n)
heapq.heappush(h, 1)
heapq.heappush(h, 3)
h[0]                     # 1，堆顶，O(1)
heapq.heappop(h)         # 1，弹出最小值，O(log n)
```

小顶堆长这样（只保证"父 ≤ 子"，兄弟之间不管）：

```
            h[0] = 1          <- 堆顶，永远最小
           /        \
      h[1] = 3    h[2] = 2    <- 3 和 2 谁大谁小，堆不关心
       /
  h[3] = 7
```

还有两个常用函数：

- `heapq.heapify(lst)`：把一个现成的 list 就地整理成堆，O(n)。比逐个 `heappush` 的 O(n log n) 快。
- `heapq.nlargest(k, lst)` / `heapq.nsmallest(k, lst)`：直接取前 k 大 / 前 k 小，内部就是大小为 k 的堆。

### 0.3 Python 只有小顶堆，要大顶堆就存负数

这是本册出现频率最高的一句话。`heapq` 没有 `maxheap`。想维护"最大的那些"，就**存相反数**：

```python
h = []
heapq.heappush(h, -5)    # 想维护最大值，压 -5
heapq.heappush(h, -1)    # 压 -1
-h[0]                    # 1，取反还原成最大值
```

原理：`-5 < -1`，所以 -5 在堆顶；取反之后 5 > 1，正好是最大值在"堆顶"。**负数把"最大"翻译成了"最小"，而小顶堆只认最小。**

### 0.4 什么时候用哪个容器

| 你要的效果 | 用什么 | 关键操作 |
|---|---|---|
| 后进先出 | `list`（栈） | `append` / `pop()` |
| 先进先出 | `deque` | `append` / `popleft()` |
| 每次拿最小值 | `heapq` 小顶堆 | `heappush` / `heappop` / `h[0]` |
| 每次拿最大值 | `heapq` + 存负数 | 同上，进出都取反 |
| 滑动窗口里的最值 | 单调队列 | 见 [03-题型模板总览](03-题型模板总览.md) 的「⑨ 单调队列」 |

### 0.5 Top-K 的三种解法（215、347、973 共用）

| 解法 | 时间 | 空间 | 什么时候选它 |
|---|---|---|---|
| 排序后取 | O(n log n) | O(n) | n 不大，代码最短，最不容易写错 |
| 大小为 k 的堆 | O(n log k) | O(k) | k 远小于 n；数据是流式的、不能全存 |
| 快速选择 | 平均 O(n)，最坏 O(n²) | O(1) | 要求 O(n)、数组在内存里、允许改数组 |

三条路都要会说，但**面试主要考堆**，因为它能处理流式数据，而且代码短到能背。

选堆的时候只有一个判断要做：

> **求"最大的 k 个"→ 小顶堆；求"最小的 k 个"→ 大顶堆（存负数）。**
>
> 因为堆顶必须是"这 k 个里最该被淘汰的那一个"——它得在堆顶，你才能 O(1) 看到它、O(log k) 扔掉它。求最大的 k 个时，该淘汰的是"这 k 个里最小的"，所以用小顶堆。反过来同理。

这句话看着绕，但它是本册所有 Top-K 题的唯一分岔口。215 和 973 正好是它的两个方向。

## 专题5-1. 数组中的第 K 个最大元素（Medium）

> 力扣 215 · 大小为 k 的小顶堆 / 快速选择
> 前置：本册「0.5 Top-K 的三种解法」

**一句话**：不用把数组排好，只要知道"从大到小排，第 k 个是谁"。

### 精讲（零基础版）

#### ① 这题要用到的东西

**堆（heap）和 `heapq`**

一句话：堆是一个"随时能告诉你谁最小"的容器。你往里面扔数，它不排序，但永远让最小的那个待在最前面。

生活类比：一队人按"谁矮谁站前面"排队，但只保证队首是最矮的，后面谁挨着谁它不管。你要找最矮的，往队首看一眼就行；你要把最矮的领走，剩下的人会自动补位。

Python 里没有"堆"这个类型，用 `heapq` 模块操作一个普通 `list`：

- `heapq.heappush(h, x)`：把 x 扔进堆，O(log n)
- `heapq.heappop(h)`：把最小值**拿走**并返回，O(log n)
- `h[0]`：只看最小值，**不拿走**，O(1)

```python
import heapq
h = []
heapq.heappush(h, 5)
heapq.heappush(h, 1)
heapq.heappush(h, 3)
print(h)                 # -> [1, 5, 3]
print(h[0])              # -> 1      （堆顶，最小值）
print(heapq.heappop(h))  # -> 1      （拿走）
print(h)                 # -> [3, 5]
```

注意第一行输出是 `[1, 5, 3]`，不是 `[1, 3, 5]`：**堆不是排好序的 list**，它只保证 `h[0]` 最小。

这题里，堆扮演"前 k 名的候补席"：只留 k 个人，多一个就淘汰最差的那个。

**`len()` 当门禁**

一句话：`len(heap)` 是"现在堆里有几个"。这题用它做门禁——超过 k 个就赶人。

**类型标注 `nums: List[int]` 和 `-> int`**

一句话：给参数和返回值贴的标签，**对运行没有任何影响**，纯粹写给人看。`List[int]` 读作"装整数的列表"，`-> int` 读作"这个函数返回一个整数"。忘了语法也没关系，照抄就行。

#### ② 大白话：这题到底在干什么

最笨的办法：把整个数组从大到小排一遍，取第 k 个。一行代码，n = 10⁵ 其实也跑得动。

笨在哪？你为了知道"第 2 名是谁"，把第 3 名到第 10 万名全部认真排了一遍。可题目根本没问你它们。

聪明的办法：想象你在看选秀，只需要记住"目前最强的 k 个人"。来一个新人，先让他进榜；榜上超过 k 个人了，就把榜上**最弱**的那个踢掉。扫完一遍，榜上就是最强的 k 个，而榜上最弱的那位，正好是第 k 名。

关键就在"榜上最弱"这四个字：你需要随时能 O(1) 看到最弱的是谁。**小顶堆的堆顶就是最弱的那个**——所以这里用小顶堆。用大顶堆的话，堆顶是最强的，你总不能把最强的踢掉。

#### ③ 拿 `nums = [3,2,1,5,6,4], k = 2` 走一遍

| 读入 | 堆里有什么 | 发生了什么 |
|---|---|---|
| 3 | `[3]` | 直接进榜 |
| 2 | `[2, 3]` | 进榜，正好 2 个 |
| 1 | `[2, 3]` | 进榜变 3 个，超了，踢掉最弱的 1 |
| 5 | `[3, 5]` | 进榜变 3 个，踢掉最弱的 2 |
| 6 | `[5, 6]` | 进榜变 3 个，踢掉最弱的 3 |
| 4 | `[5, 6]` | 进榜变 3 个，踢掉最弱的 4 |

所以答案是 `heap[0] = 5`。注意第 5 行：6 进来踢掉了 3，说明"第 1 名换人了"，榜上始终是当前最强的两个。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `heap = []` | 空榜 |
| `for x in nums:` | 一个个新人上场 |
| `heapq.heappush(heap, x)` | 先进榜再说，不提前判断他该不该进 |
| `if len(heap) > k:` | 榜上人数超过 k 了 |
| `heapq.heappop(heap)` | 踢掉最弱的（堆顶），保持 k 个 |
| `return heap[0]` | 榜上最弱的那位，就是第 k 名 |

为什么"先 push 再判长度"而不是"先判断该不该 push"：只有一条路径，不会漏人，也不会写出 `>= k` 这种差一位的错。

### 考什么

- 表面考点：找第 k 大。
- 真正考点：**Top-K 的三种解法与取舍**。这题是面试官用来分辨"会背模板"和"懂代价"的题。
- 面试官想听到的关键句：
  - "求第 k 大用**小顶堆**，堆里存的是'目前见过的最大的 k 个'，堆顶是这 k 个里最小的，正好就是第 k 大。"
  - "堆是 O(n log k)，快速选择平均 O(n) 但最坏 O(n²)。题面要求 O(n)，严格说只有快速选择满足。"

### 思路是怎么想出来的

- **排序**：`sorted(nums)[-k]`，一行。O(n log n)，n = 10⁵ 完全跑得动，但题面明确写了"必须 O(n)"，所以这只是兜底答案。
- **全部建堆再弹 k 次**：`heapq.heapify` 建大顶堆（存负数）O(n)，然后弹 k 次 O(k log n)。k 接近 n 时退化回 O(n log n)。
- **关键观察**：我们根本不需要知道"第 k 名之后是谁、什么顺序"，只需要知道"前 k 名是哪些"。既然如此，就没必要把所有元素都留在容器里——**只留 k 个**。
- 具体做法：维护一个容量为 k 的堆。新元素进来先扔进去，如果堆超过 k 个，就弹掉堆顶。扫完一遍，堆里就是"最大的 k 个"，堆顶是其中最小的，也就是第 k 大。
- **为什么是小顶堆而不是大顶堆**：要淘汰的是"这 k 个里最小的那个"。它必须在堆顶，你才能 O(1) 看见、O(log k) 扔掉。大顶堆的堆顶是这 k 个里**最大**的——你总不能把最大的扔掉。
- **快速选择**：随便挑一个数当基准（pivot），把数组分成"比它大的"和"比它小的"两堆。如果大的那堆正好有 k-1 个，基准就是答案；否则只递归有答案的那一边。每轮平均砍一半，总工作量 n + n/2 + n/4 + … = 2n，所以平均 O(n)。

### 走一遍 `nums = [3,2,1,5,6,4], k = 2`

| 读入 | 动作 | 堆（小顶堆） | 堆顶 |
|---|---|---|---|
| 3 | 压入 | `[3]` | 3 |
| 2 | 压入（正好 k 个） | `[2, 3]` | 2 |
| 1 | 压入后超了，弹掉 1 | `[2, 3]` | 2 |
| 5 | 压入后超了，弹掉 2 | `[3, 5]` | 3 |
| 6 | 压入后超了，弹掉 3 | `[5, 6]` | 5 |
| 4 | 压入后超了，弹掉 4 | `[5, 6]` | **5** |

答案 5。注意每一轮堆里都恰好是"到目前为止最大的 2 个"，堆顶就是"这 2 个里较小的那个"——第 2 大。

### 代码（Python）

```python
from typing import List   # 力扣已预导入这行，本地跑时要加上
import heapq

class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        heap = []                       # 小顶堆，只装 k 个
        for x in nums:
            heapq.heappush(heap, x)
            if len(heap) > k:           # 超过 k 个，弹掉最小的
                heapq.heappop(heap)
        return heap[0]                  # 堆顶就是这 k 个里最小的 = 第 k 大
```

**逐段讲解**

- 先 `heappush` 再判长度，而不是"先判断该不该压"。这样只有一条路径，不用写 `if len(heap) < k` 的分支，也不会漏压。
- **循环不变量**：每轮结束后，堆里恰好是"已扫描过的元素中最大的 min(i, k) 个"，且堆顶是其中最小的。
- `len(heap) > k` 不能写成 `>= k`：写成 `>=` 的话，压入第 k 个元素后立刻弹出，堆里永远只有 k-1 个，最后 `heap[0]` 是第 k+1 大。
- 最后直接 `heap[0]`，不需要 `heappop`——题目只要值，不要"取走"。

### 复杂度

- 时间 O(n log k)：n 次 `heappush`（每次 O(log k)），最多 n 次 `heappop`（每次 O(log k)）。k 是常数时退化成 O(n)。
- 空间 O(k)：堆里最多 k 个元素。

### 常见误区（★ 最容易丢分的地方）

1. **用大顶堆装 k 个**（存负数）。超长时 `heappop` 弹掉的是"这 k 个里最大的"，于是堆里留下的是**最小的 k 个**，最后 `-heap[0]` 拿到的是第 k 小。示例 1 会返回 2 而不是 5。
2. **`> k` 写成 `>= k`**。压入第 k 个之后立刻弹出，堆里只剩 k-1 个（k=2 时只剩 1 个），示例 1 返回 6（最大值）。
3. **先判长度再压，却把判断写反**：`if len(heap) < k: heappush(...)` 之后就再也不压了，堆里永远只有前 k 个元素，后面的 6 根本进不来。
4. **`heapq.nlargest(k, nums)[-1]` 写成 `[0]`**。`nlargest` 返回的是**降序**列表，第 k 大是最后一个 `[-1]`，`[0]` 是最大。
5. **以为 `heapq` 能直接建大顶堆**。Python 没有 `maxheap`，只能存负数。这题恰好不需要大顶堆，但 973 需要。
6. **快速选择里对两边都递归**。那就退化成快速排序 O(n log n) 了。只递归"包含答案的那一边"，才有 O(n)。

### 面试追问 / 变体

- **数据流里求第 k 大（力扣 703）**：就是这题，只是 `add` 一次调一次。堆天然适合，因为不用重扫历史数据。
- **要求 O(1) 空间**：快速选择。原地划分，不额外开数组。
- **k 很小、n 很大（比如 n = 10⁹ 的日志）**：堆，而且是唯一可行的（内存装不下全部数据时也能用）。
- **要求返回"前 k 大的所有元素"**：堆里那 k 个就是，直接返回（顺序不定）。
- **数组已部分有序**：快速选择的 pivot 选不好会退化到 O(n²)，可以随机选 pivot 或者用"三数取中"。

### 自测

- 必测用例：
  - `[3,2,1,5,6,4], k=2` → 5（题面示例）
  - `[3,2,3,1,2,4,5,5,6], k=4` → 4（题面示例，有重复）
  - `[1], k=1` → 1（单元素）
  - `[2,1], k=1` → 2（k=1 就是最大值）
  - `[2,1], k=2` → 1（k=n 就是最小值）
  - `[-1,-2], k=2` → -2（负数）
  - `[7,7,7], k=2` → 7（全相同）
  - `[5,4,3,2,1], k=5` → 1（严格递减，k=n）
- 30 秒自检：能不能说出"小顶堆装 k 个、超了就弹堆顶、最后堆顶即答案"这三步？

## 专题5-2. 用队列实现栈（Easy）

> 力扣 225 · 两个队列 · 设计题
> 前置：本册「0.1 队列」+ 第一册 [分册 B · 0.1 栈是什么](11-分册B-栈与单调栈.md)

**一句话**：只准用"先进先出"的队列，做出一个"后进先出"的栈。

### 精讲（零基础版）

#### ① 这题要用到的东西

**队列（queue）和 `deque`**

一句话：队列就是排队买饭，**从队尾进、从队头出**，先来的先走（先进先出，FIFO）。

生活类比：食堂窗口。你只能站到队尾，阿姨只从队头叫号，中间的人谁也动不了。

Python 用 `collections.deque`（读作"deck"，双端队列）：

- `q.append(x)`：站到队尾，O(1)
- `q.popleft()`：队头那个人**走掉**，并把他返回给你，O(1)
- `q[0]`：只看队头是谁，**不叫走**，O(1)

```python
from collections import deque
q = deque()
q.append("A")
q.append("B")
print(q[0])          # -> A    （只看）
print(q.popleft())   # -> A    （叫走）
print(q)             # -> deque(['B'])
```

为什么不用 `list`：`list.pop(0)` 要把后面所有人往前挪一格，是 O(n)；`deque.popleft()` 是 O(1)。

这题里，队列扮演"仓库"：东西只能从一头进、另一头出，而我们要的偏偏是反过来的顺序。

**栈**（第一册讲过，这题只用它的两个动作）：`append(x)` 放末尾，`pop()` 拿末尾，后进先出。

**`class` / `self` / `__init__`**

一句话：设计题要你造一个"对象"。`class` 是图纸，`__init__` 是出厂设置，`self.xxx` 是这个对象自己身上的抽屉。

```python
class Box:
    def __init__(self):
        self.items = []      # 每个 Box 出厂时自带一个空抽屉
    def put(self, x):
        self.items.append(x)
b = Box()
b.put(1)
b.put(2)
print(b.items)               # -> [1, 2]
```

这题里 `MyStack` 就是图纸，`self.q1` / `self.q2` 是两个抽屉。题面调 `push` / `pop` 时会把对象自己自动传进来，所以第一个参数永远写 `self`。

**`not x`**：`not self.q1` 读作"q1 是空的"。空的 deque 在 `if` 里算"假"。

#### ② 大白话：这题到底在干什么

最笨的办法：`pop` 的时候，把队列里除了最后一个之外的元素全搬到另一个队列，取出最后一个，再搬回来。能对，但每次 `pop` 都是 O(n)。

笨在哪？明明"最后一个进来的"才是最该先出去的，可它偏偏躺在队尾，从队头出不来。

聪明的办法：把这份搬运的活从 `pop` 挪到 `push`。新元素来了，先让它进中转队列 q2，再把 q1 里的老元素一个个接到它**后面**——于是新元素跑到了队头。最后把 q1 和 q2 的名字交换一下，q1 永远是"当前有效"的那个。之后 `pop` 直接从队头拿，O(1)。

代价没有消失，只是换了个地方付：`push` 变 O(n)，`pop` 变 O(1)。

#### ③ 走一遍 `push(1), push(2), top(), pop(), empty()`

| 调用 | q2（中转） | 搬完之后 | 交换后 q1 | 返回 |
|---|---|---|---|---|
| `push(1)` | `[1]` | q1 是空的，不用搬 | `[1]` | — |
| `push(2)` | `[2]` | 搬 1 → `[2, 1]` | `[2, 1]` | — |
| `top()` | | | `[2, 1]` | 2 |
| `pop()` | | | `[1]` | 2 |
| `empty()` | | | `[1]` | False |

所以 `push(1), push(2)` 之后栈顶是 2——后进的 2 跑到了队头，正好是栈该有的样子。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `self.q1 = deque()` | 主仓库，它的队头就是栈顶 |
| `self.q2 = deque()` | 中转仓库，每次 push 完自动变空 |
| `self.q2.append(x)` | 新人先进中转站 |
| `while self.q1:` | 老仓库还有人，就一个个往外搬 |
| `self.q2.append(self.q1.popleft())` | 老元素排到新人**后面** |
| `self.q1, self.q2 = self.q2, self.q1` | 交换名字：中转站转正，老仓库清空待用 |
| `return self.q1.popleft()` | 队头就是栈顶，直接叫走 |
| `return self.q1[0]` | 只看队头，不叫走 |
| `return not self.q1` | q1 空就返回 True |

### 考什么

- 表面考点：两个队列模拟一个栈。
- 真正考点：**用两个容器倒一次手，把顺序反过来**。它和 232 是镜像题，两题一起看才看得清。
- 面试官想听到的关键句："栈的栈顶 = 队列的队尾。所以我在 `push` 的时候就把新元素挪到队头，之后 `pop` 直接从队头取。"

### 思路是怎么想出来的

- **矛盾在哪**：队列只能从队尾进、从队头出；栈要的是"最后进的先出"。而"最后进的那个"恰好躺在队尾，队头出不来。
- **最笨的想法**：`pop` 的时候把队列里除最后一个之外的元素都搬走，取出最后一个，再搬回来。这需要第二个队列当中转，而且 `pop` 变成 O(n)。
- **关键观察**：既然"新元素必须跑到队头"，那不如**在 `push` 的时候就把这件事做掉**。做法是：新元素进 q2，然后把 q1 里的所有元素依次搬到 q2 的后面——搬完之后，q2 的队头就是新元素。最后交换 q1 和 q2 的名字，让 q1 永远是"当前有效"的那个队列。
- **于是有**：`push` O(n)，`pop` / `top` / `empty` 全 O(1)。代价从 `pop` 挪到了 `push`，功能完全一样。

### 走一遍

```
push(1):  q2=[1]          把 q1（空）搬过去 -> q2=[1]        交换 -> q1=[1]
push(2):  q2=[2]          把 q1 的 1 搬过去 -> q2=[2,1]      交换 -> q1=[2,1]
          q1 的队头是 2，正好是栈顶
top():    q1[0] = 2
pop():    从 q1 队头取 -> 2，q1=[1]
empty():  q1 非空 -> False
```

关键在第 2 步：旧元素 1 被搬到了 2 的**后面**，所以 2 跑到了队头。**"搬运"这个动作，就是把新元素插队的唯一办法。**

### 代码（Python）

```python
from collections import deque

class MyStack:

    def __init__(self):
        self.q1 = deque()        # 当前有效的队列，队头就是栈顶
        self.q2 = deque()        # 中转用的空队列

    def push(self, x: int) -> None:
        self.q2.append(x)                    # 新元素先进中转队列
        while self.q1:
            self.q2.append(self.q1.popleft())  # 旧元素依次排到它后面
        self.q1, self.q2 = self.q2, self.q1  # 交换名字，q2 重新变空

    def pop(self) -> int:
        return self.q1.popleft()             # 队头就是栈顶

    def top(self) -> int:
        return self.q1[0]

    def empty(self) -> bool:
        return not self.q1
```

**逐段讲解**

- 交换 `q1` 和 `q2` 而不是"把 q2 的内容拷回 q1"：Python 里交换两个变量只是换引用，O(1)；拷贝是 O(n)。而且交换之后 q2 自动变成空队列，下一轮 `push` 可以直接用。
- `popleft()` 而不是 `pop()`：`pop()` 是从右边弹，那是栈的动作；队列必须从左边出。
- `while self.q1` 而不是 `for x in self.q1`：循环体里在 `popleft()`，边遍历边改容器，deque 会直接抛 `RuntimeError: deque mutated during iteration`。
- `top()` 用 `q1[0]` 而不是 `q1.popleft()`：看一眼不能把元素取走。`deque` 支持 O(1) 下标访问首尾。

### 复杂度

- `push`：O(n)，要把 q1 里的 n 个元素全部搬一遍。
- `pop` / `top` / `empty`：O(1)。
- 空间 O(n)：两个队列加起来最多 n 个元素。

### 常见误区（★ 最容易丢分的地方）

1. **搬运时用 `q1.pop()`**。那是从右边弹，等于把队列当栈用。`push(1), push(2), push(3)` 之后连续三次 `pop` 会得到 3、1、2（正确答案 3、2、1）——第一次碰巧对，因为搬运时只有一个元素，之后全乱。队列出队只能 `popleft()`。
2. **忘了交换 `q1` / `q2`**。新元素全堆在 q2 里，q1 永远是空的，`top()` 会直接 `IndexError: deque index out of range`。
3. **想用 `list.insert(0, x)` 一把梭**。那是 O(n) 的 list 操作，也不属于题面允许的"队列标准操作"。
4. **以为 `pop` 也得 O(n)**。代价全在 `push` 上了，这正是设计的一部分——面试时主动说出来："我把 O(n) 放在 push，所以 pop 是 O(1)。"
5. **`empty()` 写成 `return not self.q2`**。q2 在两次 `push` 之间总是空的，永远返回 True。

### 面试追问 / 变体

- **进阶：只用一个队列**。`push(x)` 时先把 x 压进队尾，然后把"前面 size-1 个"依次从队头取出、再压回队尾。转完一圈，x 就跑到了队头。
- **反过来（力扣 232）**：用栈实现队列。注意 232 能做到**均摊 O(1)**，而本题的 `push` 是实打实的 O(n)——两题的代价结构不对称，这是面试常问的对比点。
- **要求 `push` 也 O(1)**：那就得让 `pop` 变 O(n)，两头都 O(1) 做不到。

### 自测

- 必测用例（题面调用序列）：`push(1), push(2), top()=2, pop()=2, empty()=False`
- 边界：空栈 `empty()=True`；`push(1),push(2),push(3)` 后连续三次 `pop` 得 3、2、1
- 30 秒自检：新元素进 q2 → 旧元素搬到它后面 → 交换 q1/q2，这三步说得出来吗？

## 专题5-3. 用栈实现队列（Easy）

> 力扣 232 · 两个栈 · 均摊 O(1) · 设计题
> 前置：本册 5-2（先看镜像题，再看这题）

**一句话**：只准用"后进先出"的栈，做出一个"先进先出"的队列。

### 精讲（零基础版）

#### ① 这题要用到的东西

**栈**（前面 5-2 讲过）：`append` 放末尾、`pop()` 拿末尾，后进先出。这题的两个栈一个只管收（`in_stack`），一个只管发（`out_stack`）。

**"倒一次"会发生什么**

一句话：把一摞东西从 A 栈逐个弹出、压进 B 栈，顺序就反过来。

```python
a = [1, 2, 3]
b = []
for x in a:            # 顺序遍历：b 还是 [1, 2, 3]
    b.append(x)
c = []
while a:               # 从末尾拿：c 变成 [3, 2, 1]
    c.append(a.pop())
print(b)   # -> [1, 2, 3]
print(c)   # -> [3, 2, 1]
print(a)   # -> []
```

这题里，`while a: c.append(a.pop())` 就是"倒栈"的标准写法；用 `for` 写不出反转效果。

**均摊复杂度（amortized）**

一句话：单次操作可能很贵，但**总账摊到每次上很便宜**。

生活类比：你一年洗两次窗帘，每次两小时。单看某一天是"两小时的大工程"，摊到 365 天，平均每天几秒钟。面试问复杂度时答"单次最坏 O(n)，均摊 O(1)"，既诚实又准确。

这题里，每个元素一辈子只会被"从 in 搬到 out"一次，所以 n 次操作的总搬运次数不超过 n，摊到每次就是 O(1)。

**辅助方法 `_move`**

一句话：把一段反复用的代码抽出来起个名字。前面的下划线 `_` 是"内部使用"的约定，不影响运行。

#### ② 大白话：这题到底在干什么

最笨的办法：每次 `pop` 都把 `in_stack` 全部倒进 `out_stack` 再弹。

笨在哪？倒一次顺序就反过来了，**再倒一次又反回去**。所以"什么时候允许倒"必须有个条件，不然顺序全乱。

聪明的办法：`in_stack` 只负责收，`out_stack` 只负责发。要出队时看一眼 `out_stack`：空了才把 `in_stack` 整个倒过来；不空就直接从 `out_stack` 弹。

那个"空才倒"的判断是这题的灵魂：`out_stack` 里还有货，说明上一批还没发完，这时候再倒一次，新倒进来的会压在旧的上面，等于让后到的插了队。

为什么总共还是快的：每个元素一生只被搬一次，搬完就一直在 out 里等着被弹。n 次 push 最多带来 n 次搬运，摊到每次操作上就是 O(1)。

#### ③ 走一遍 `push(1), push(2), peek(), pop(), push(3), pop(), pop()`

| 调用 | in_stack | out_stack | 发生了什么 |
|---|---|---|---|
| `push(1)` | `[1]` | `[]` | 收 |
| `push(2)` | `[1, 2]` | `[]` | 收 |
| `peek()` | `[]` | `[2, 1]` | out 空 → 倒 → 返回栈顶 1 |
| `pop()` | `[]` | `[2]` | out 非空，不倒，弹 1 |
| `push(3)` | `[3]` | `[2]` | 收，注意 3 没有插队 |
| `pop()` | `[3]` | `[]` | out 非空，不倒 → 弹 2 |
| `pop()` | `[]` | `[3]` | out 空了 → 倒 → 弹 3 |

所以出队顺序是 1、2、3。第 6 行是核心：out 里还有 2，所以**不倒**，3 老老实实待在 in 里排队。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `self.in_stack = []` | 收件箱 |
| `self.out_stack = []` | 发件箱 |
| `self.in_stack.append(x)` | push 就是往收件箱里扔，O(1) |
| `if not self.out_stack:` | **只有发件箱空了**才允许倒 |
| `while self.in_stack:` | 收件箱还有人 |
| `self.out_stack.append(self.in_stack.pop())` | 从收件箱末尾拿，压进发件箱——顺序就反了 |
| `self._move()` | pop 和 peek 都先调它，保证发件箱有货 |
| `return self.out_stack.pop()` | 从发件箱末尾弹，那是最早进来的 |
| `return not self.in_stack and not self.out_stack` | 两个都空才算空 |

### 考什么

- 表面考点：两个栈模拟一个队列。
- 真正考点：**两个栈 = 一次反转**，以及"什么时候才允许反转"这个条件。这题是"均摊复杂度"最好的入门例子。
- 面试官想听到的关键句："输入栈负责收，输出栈负责发；**只有输出栈空了才把输入栈整个倒过来**。每个元素最多被倒一次，所以 n 次操作总共 O(n)，均摊 O(1)。"

### 思路是怎么想出来的

- **一个栈为什么不行**：栈顶是最后进来的，而队列要发的是最早进来的。方向正好相反。
- **关键观察**：把一栈元素**倒进另一个栈**，顺序会反转一次。`[1,2,3]`（栈顶 3）倒过去变成 `[3,2,1]`（栈顶 1）——最早进来的 1 现在在栈顶了，正好可以弹出去。
- 所以需要两个栈：`in_stack` 只管收，`out_stack` 只管发。要出队时，如果 `out_stack` 是空的，就把 `in_stack` 全部倒过来；然后从 `out_stack` 弹。
- **关键条件**：**只在 `out_stack` 空的时候才倒**。如果 `out_stack` 里还有元素（说明之前倒过来、还没发完），你再倒一次就会把顺序又打乱一遍——新倒进来的会压在旧的上面，插队到前面去了。

### 走一遍

```
push(1) push(2):   in=[1,2]（栈顶 2）   out=[]
peek():  out 空 -> 倒：弹 2 压 out，弹 1 压 out -> out=[2,1]（栈顶 1）
         返回 out[-1] = 1
pop():   out 非空 -> 直接弹 -> 1，out=[2]
push(3): in=[3]    out=[2]
pop():   out 非空 -> 直接弹 -> 2     <- 注意：3 还在 in 里，没有插队
pop():   out 空 -> 倒 in -> out=[3] -> 弹 -> 3
```

`push(3)` 后面那个 `pop()` 是核心：此时 `out` 里还有 2，所以**不倒**，3 老老实实待在 `in` 里排队。

### 代码（Python）

```python
class MyQueue:

    def __init__(self):
        self.in_stack = []       # 只负责收（push）
        self.out_stack = []      # 只负责发（pop / peek）

    def push(self, x: int) -> None:
        self.in_stack.append(x)  # 收，O(1)

    def _move(self) -> None:
        # 只有 out 空的时候才倒，否则会把顺序打乱
        if not self.out_stack:
            while self.in_stack:
                self.out_stack.append(self.in_stack.pop())

    def pop(self) -> int:
        self._move()
        return self.out_stack.pop()

    def peek(self) -> int:
        self._move()
        return self.out_stack[-1]

    def empty(self) -> bool:
        return not self.in_stack and not self.out_stack
```

**逐段讲解**

- `_move()` 单独抽出来，是因为 `pop` 和 `peek` 都需要"确保 out 里有货"。抽出来之后两处逻辑不会写岔。
- `if not self.out_stack` 这个判断是灵魂，不是优化。去掉它，`push(3)` 之后的 `pop` 会返回 3 而不是 2。
- `while self.in_stack: self.out_stack.append(self.in_stack.pop())` 一次倒完。**不要写 `for x in self.in_stack`**：`for` 是从头到尾遍历，倒过去顺序不变，等于没倒。
- `empty()` 必须**两个栈都看**。只看 `in_stack` 会漏掉"in 空了但 out 里还有货"的状态；只看 `out_stack` 会漏掉"刚 push 完还没倒"的状态。

### 复杂度

- `push`：O(1)。
- `pop` / `peek`：**均摊 O(1)**，单次最坏 O(n)。
- 空间 O(n)。

为什么是均摊 O(1)：每个元素一生只会被"从 in 搬到 out"一次，搬完就一直在 out 里等着被弹。n 次 `push` 最多带来 n 次搬运，所以 n 次操作的总搬运次数 ≤ n。摊到每次操作上就是 O(1)。这正是第一册分册 B 的 0.3 节讲单调栈时用的同一种数法——**别看单次，看总账**。

### 常见误区（★ 最容易丢分的地方）

1. **每次 `pop` 都倒一遍**（`_move` 里去掉 `if`）。`push(1), push(2), pop()` 得到 1；再 `push(3)`，此时 `out` 里还有 2，但没判空又倒了一次，3 压到了 2 上面，第二次 `pop` 返回 3 而不是 2。
2. **用 `for x in self.in_stack` 搬运**。顺序没反转，`push(1), push(2)` 之后两次 `pop` 得到 2、1（正确答案 1、2）。必须用 `pop()` 从栈顶取。
3. **`empty()` 只看一个栈**。`push(1), push(2), pop()` 之后 in=[2]、out=[]，只写 `not self.out_stack` 会返回 True（错）。
4. **以为单次 O(n) 就不满足"均摊 O(1)"**。题面的进阶要求就是均摊，不是最坏。面试时要主动说"最坏 O(n)、均摊 O(1)"，别只说一个。
5. **`peek` 里写成 `self.out_stack.pop()`**。看一眼就把元素弹走了，后面的 `pop` 会少一个。

### 面试追问 / 变体

- **反过来（力扣 225）**：用队列实现栈。那题的 `push` 是实打实 O(n)，没有均摊的说法。
- **要求 `pop` 严格 O(1)**：做不到。要么 `push` 变 O(n)（225 那种思路），要么接受均摊。
- **用栈实现双端队列**：需要更复杂的中转结构，属于扩展题。
- **多线程场景**：这题的"倒"过程不是原子的，并发下要加锁——工程岗面试有时会追问这一句。

### 自测

- 必测用例（题面调用序列）：`push(1), push(2), peek()=1, pop()=1, empty()=False`
- 边界：`push(1),push(2),pop()` 之后再 `push(3)`，下一次 `pop` 必须是 2 而不是 3
- 30 秒自检：in 收、out 发、out 空才倒，这三步说得出来吗？

## 专题5-4. 数据流的中位数（Hard）

> 力扣 295 · 对顶堆 · 两个堆夹住中位数
> 前置：本册「0.2 堆」「0.3 存负数」

**一句话**：数字一个一个来，每来一个之后，随时能报出"目前所有数的中位数"。

### 精讲（零基础版）

#### ① 这题要用到的东西

**中位数**

一句话：把一堆数从小到大排好，站正中间那个；个数是偶数时，取中间两个的平均。

生活类比：全班按身高站成一排，中位数就是"正中间那位同学的身高"。它比平均数抗极端值——班里转来一个 2 米 2 的，平均数被拉高，中位数基本不动。

这题里，中位数只跟"中间那一两个数"有关，两边的数具体是多少完全不影响——这是全部优化的起点。

**最大堆：Python 没有，就存负数**

一句话：`heapq` 只有小顶堆。想要"随时拿到最大值"，就把每个数**取负**再扔进去，堆顶是最小的负数，也就是原数里最大的。

```python
import heapq
h = []
for x in (3, 1, 5):
    heapq.heappush(h, -x)
print(h)        # -> [-5, -1, -3]
print(-h[0])    # -> 5
```

注意 `h[0]` 是 `-5`，取负还原成 5。**负数把"最大"翻译成了"最小"，而小顶堆只认最小。**

这题里，左半边（较小的一半）用最大堆，右半边（较大的一半）用小顶堆，两个堆顶正好夹住中位数。

**`/` 和 `//`**

```python
print((1 + 2) / 2)    # -> 1.5    真除法，得小数
print((1 + 2) // 2)   # -> 1      整除，砍掉小数部分
```

题面要 1.5，所以必须用 `/`。`float(x)` 是把整数转成小数（`5` → `5.0`），题面要求返回浮点，奇数分支包一层更稳。

**堆的"弹一个、压一个"**（前面 5-1 讲过 `heappush` / `heappop`）：`heapq.heappush(self.large, -heapq.heappop(self.small))` 这种一行套两层，读法是从里往外——先 `heappop` 拿出左堆的最小值，取负还原，再 `heappush` 进右堆。

#### ② 大白话：这题到底在干什么

最笨的办法：每次问中位数，就把目前所有数排一遍取中间。单次 O(n log n)，而 `addNum` 和 `findMedian` 加起来最多 5 万次调用，最坏到 10¹⁰ 量级，必超时。

稍好一点：维持一个有序数组，插入时用二分找位置。查找 O(1)，但插入要挪元素，还是 O(n)。

笨在哪？每次都在为"中间那一两个数"付出"把全部数据排好"的代价。可最大值多少、最小值多少，你根本不需要知道。

聪明的办法：把数据**劈成两半**——左半全部 ≤ 右半。这样中位数只跟"左半最大的那个"和"右半最小的那个"有关，两半内部怎么乱都无所谓。而"随时拿到一组数的最大/最小"，正是堆的活。

于是：左半用最大堆（存负数），右半用小顶堆。每来一个新数，先无脑扔进左堆，然后把左堆最大的挪到右堆；如果右堆因此比左堆多了，再把右堆最小的挪回左堆。转完这一圈，两个堆的大小最多差 1。

取的时候：左堆比右堆多 1 个（总共奇数个），答案就是左堆顶；两边一样多（偶数个），答案是两个堆顶的平均。

#### ③ 走一遍 `addNum(1), addNum(2), findMedian(), addNum(3), findMedian()`

| 操作 | 左堆 small（存负数） | 右堆 large | 返回 |
|---|---|---|---|
| `addNum(1)` | `[-1]` = {1} | `[]` | — |
| `addNum(2)` | `[-1]` = {1} | `[2]` | — |
| `findMedian()` | 1 个 | 1 个 | (1+2)/2 = **1.5** |
| `addNum(3)` | `[-2, -1]` = {2, 1} | `[3]` | — |
| `findMedian()` | 2 个（比右多 1） | 1 个 | 左堆顶 = **2.0** |

`addNum(2)` 那一行要看清：2 先被压进左堆变成 `[-2, -1]`，然后左堆最小的 `-2`（也就是原数 2）被挪到右堆——**新来的大数自己跑去了右半**，不用你判断它该去哪边。

`addNum(3)` 则是"挪过去之后右堆反超了，再还一个回来"：3 进了左堆，左堆最大被挪到右边，右堆变 2 个，于是把右堆最小的 2 还回左边，最后左堆是 `[-2, -1]`。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `self.small = []` | 左半，最大堆（所以里面存的是负数） |
| `self.large = []` | 右半，最小堆（正常存） |
| `heapq.heappush(self.small, -num)` | 第 1 步：先无脑进左堆，不判断该去哪边 |
| `heapq.heappush(self.large, -heapq.heappop(self.small))` | 第 2 步：把左堆最大的挪到右堆（弹出的是最小负数，取负还原） |
| `if len(self.large) > len(self.small):` | 第 3 步：右堆反超了 |
| `heapq.heappush(self.small, -heapq.heappop(self.large))` | 把右堆最小的还回左堆 |
| `if len(self.small) > len(self.large):` | 奇数个：左堆多一个 |
| `return float(-self.small[0])` | 中位数就是左堆顶（记得取负还原） |
| `return (-self.small[0] + self.large[0]) / 2.0` | 偶数个：两个堆顶取平均，必须用 `/` |

为什么第 1 步敢"无脑进左堆"：第 2 步马上会把左堆最大值挪到右边。如果新数最大，被挪走的就是它；如果不是，被挪走的是原来的最大值。**这一步同时完成了"分流"和"保证右堆非空"两件事。**

### 考什么

- 表面考点：动态维护中位数。
- 真正考点：**对顶堆**——把数据分成"较小的一半"和"较大的一半"，两个堆顶正好夹住中位数。
- 面试官想听到的关键句：
  - "最大堆放较小的一半，最小堆放较大的一半，两个堆的大小差不超过 1。中位数只跟这两个堆顶有关。"
  - "Python 只有小顶堆，所以左半边存负数来模拟最大堆。"

### 思路是怎么想出来的

- **最笨**：每次 `findMedian` 都 `sorted(arr)` 取中间。单次 O(n log n)，而 `addNum` + `findMedian` 最多 5×10⁴ 次调用，最坏会到 10¹⁰ 量级，必超时。
- **稍好**：插入时用 `bisect.insort` 维护有序数组。查找 O(1)，但插入要搬元素，O(n)。5×10⁴ 次插入 × 每次最多 10⁵ 的搬动 ≈ 5×10⁹，还是慢。
- **关键观察**：中位数只取决于"中间那一两个数"。如果把数据分成两半——左半全部 ≤ 右半——那么中位数只跟**左半的最大值**和**右半的最小值**有关。左半内部怎么排、右半内部怎么排，一点都不重要。
- 而"随时能拿到一组数的最大值 / 最小值"，正是堆的活。
- **于是有**：
  - 左半（较小的一半）用**最大堆**，堆顶 = 左半最大；
  - 右半（较大的一半）用**最小堆**，堆顶 = 右半最小；
  - 维持 `len(左) == len(右)` 或 `len(左) == len(右) + 1`。
- 取中位数：
  - 奇数个（左比右多 1）：中位数 = 左堆顶。
  - 偶数个（两边相等）：中位数 = (左堆顶 + 右堆顶) / 2。

### 为什么"大小差 ≤ 1"就够了

假设左半有 3 个、右半有 3 个，一共 6 个（偶数）。因为左半全部 ≤ 右半，排序后第 3、4 个位置正好是"左半最大"和"右半最小"。中位数就是这两个数的平均值。**中间那些数具体是多少，不影响中位数。**

假设左半 4 个、右半 3 个，一共 7 个（奇数）。排序后第 4 个（正中间）就是"左半最大"，也就是左堆顶。

所以两个堆的大小关系只有两种合法状态，其他状态都说明"分界线歪了"，中位数会算错。

### 走一遍 `addNum(1), addNum(2), findMedian(), addNum(3), findMedian()`

| 操作 | 左堆 small（最大堆，存负数） | 右堆 large（最小堆） | 返回 |
|---|---|---|---|
| `addNum(1)` | `[-1]` → 实际是 {1} | `[]` | — |
| `addNum(2)` | 先压 -2，再把左堆最大（-2，即 2）挪到右堆 → `[-1]` = {1} | `[2]` | — |
| `findMedian()` | | | (1+2)/2 = **1.5** |
| `addNum(3)` | 压 -3 → `[-3,-1]`；挪最大（3）到右 → `[-1]` = {1}；此时右堆 `[2,3]` 比左堆多，还一个 2 回去 → `[-2,-1]` = {2,1} | `[3]` | — |
| `findMedian()` | 左堆 2 个、右堆 1 个，左多 1 | | 左堆顶 = **2.0** |

注意 `addNum(3)` 那一行：它触发了**两次调整**——先把新元素挪到右边，再把右边多的挪回左边。这个"一进一出"的再平衡是本算法的固定动作。

### 代码（Python）

```python
import heapq

class MedianFinder:

    def __init__(self):
        self.small = []      # 最大堆（存负数），装较小的一半
        self.large = []      # 最小堆，装较大的一半

    def addNum(self, num: int) -> None:
        heapq.heappush(self.small, -num)                       # 1. 先无脑进左堆
        heapq.heappush(self.large, -heapq.heappop(self.small)) # 2. 左堆最大挪到右堆
        if len(self.large) > len(self.small):                  # 3. 右堆多了就还一个
            heapq.heappush(self.small, -heapq.heappop(self.large))

    def findMedian(self) -> float:
        if len(self.small) > len(self.large):
            return float(-self.small[0])                       # 奇数个：左堆顶
        return (-self.small[0] + self.large[0]) / 2.0          # 偶数个：两个堆顶平均
```

**逐段讲解**

- **第 1 步"先无脑进左堆"**：不判断"这个数该去左边还是右边"。反正第 2 步马上会把左堆最大值挪到右边——如果新数最大，它会被挪过去；如果不是，被挪过去的就是原来的最大值。**这一步同时完成了"分流"和"保证右堆非空"两件事。**
- **第 2 步**：`-heapq.heappop(self.small)` 弹出左堆的**最小值**（因为存的是负数，负数最小 = 原数最大），取反还原，压进右堆。
- **第 3 步**：第 2 步之后，右堆可能比左堆多 1 个（比如左 1 右 2）。这时把右堆最小（`large[0]`）挪回左堆，恢复"左 ≥ 右"的约定。
- **循环不变量**：每次 `addNum` 结束后，`len(small) == len(large)` 或 `len(small) == len(large) + 1`，并且 `small` 里所有数 ≤ `large` 里所有数。
- **对称的另一种写法**：很多题解是"先压右堆、再把右堆最小挪回左堆、最后若左堆比右堆多 2 个就还一个"。两种写法效果完全一样，只是"默认进哪边"不同。**看别人的代码时先确认他用的是哪种约定，再去看 `findMedian` 的分支**——这是这题最容易看晕的地方。
- `findMedian` 里 `float(-self.small[0])`：题面要求返回浮点。Python 3 里 `/` 本来就是浮点除，但奇数分支返回的是 int，包一层 `float` 更稳。

### 复杂度

- `addNum`：O(log n)。三次堆操作，每次 O(log n)。
- `findMedian`：O(1)。只读两个堆顶。
- 空间 O(n)：两个堆加起来装下所有数。

### 常见误区（★ 最容易丢分的地方）

1. **两个堆都建成小顶堆**。左堆拿不到最大值，`small[0]` 是最小值，中位数全错。左堆必须存负数。
2. **存了负数但 `findMedian` 忘了取反**。`addNum(1), addNum(2)` 之后会返回 0.5（正确答案 1.5）——因为 `small[0]` 存的是 -1。
3. **只往一边压，不做再平衡**。所有数都堆进 `small`，`findMedian` 取 `-small[0]` 拿到的永远是**当前最大值**：`addNum(1), addNum(2), addNum(3)` 之后返回 3.0（正确答案 2.0）。
4. **只做第 2 步、不做第 3 步**。第 2 步会把 `small` 抽空，`addNum(1)` 之后 `small` 就空了，`findMedian` 在 `small[0]` 上直接 `IndexError`。
5. **把不变量写成"右堆 ≥ 左堆"**，但 `findMedian` 还按"左 ≥ 右"写。两边约定不一致，奇数个时取错堆顶。**要么全按左多，要么全按右多，别混。**
6. **`findMedian` 用 `//`**。`(1+2)//2` 得 1，题面要 1.5。
7. **每次 `findMedian` 现 `sorted`**。功能对但超时，理由见开头。

### 面试追问 / 变体

- **支持删除元素**：堆不支持任意删除。标准做法是"延迟删除"——再开一个哈希表记"待删元素"，`findMedian` 前先把堆顶那些待删的弹掉。
- **求第 25 百分位 / 任意分位数**：还是对顶堆，但两边的大小比例不再是 1:1，而是按分位数定（比如 1:3）。
- **数据范围很小（比如 0–100）**：不用堆，开一个计数数组，再用两个下标从两头往中间走，`findMedian` 也是 O(1)，`addNum` 也是 O(1)。
- **数据是浮点数**：堆的比较不挑类型，代码一行不用改。
- **要求 O(1) 空间**：做不到。中位数需要"记住分布"，至少 O(n)。

### 自测

- 必测用例（题面调用序列）：`addNum(1), addNum(2), findMedian()=1.5, addNum(3), findMedian()=2.0`
- 边界：
  - 单元素：`addNum(5), findMedian()=5.0`
  - 严格递减：`addNum(5..1)`，`findMedian()=3.0`
  - 全部相同：`addNum(2)×4`，`findMedian()=2.0`
  - 负数：`addNum(-1), addNum(-2), findMedian()=-1.5, addNum(-3), findMedian()=-2.0`
- 30 秒自检：能不能说出"左堆存负数当最大堆、先压左再挪右、右多了还回来、奇数取左顶偶数取平均"这四步？

## 专题5-5. 前 K 个高频元素（Medium）

> 力扣 347 · 哈希表 + 大小为 k 的小顶堆（或桶排序）
> 前置：本册「0.5 Top-K 的三种解法」

**一句话**：先数清楚每个数出现了几次，再把出现次数最多的 k 个数挑出来。

### 精讲（零基础版）

#### ① 这题要用到的东西

**字典（dict）和 `Counter`**

一句话：字典是"键 → 值"的查号台，给它一个键，它立刻告诉你对应的值。

生活类比：查字典。你不会从第一页翻到最后一页找"猫"，你直接按拼音翻到 M。dict 就是这个意思——用键直接定位，不用遍历。

```python
d = {"a": 1}
print(d["a"])       # -> 1
print(d.get("b"))   # -> None   键不存在，给个默认值，不报错
print("b" in d)     # -> False
```

`d["b"]` 会直接 `KeyError` 崩掉；`d.get("b", 0)` 则是"没有就当 0"。数频次时常用后者。

`Counter` 是专门数数的字典，一行完成统计：

```python
from collections import Counter
c = Counter([1, 1, 2])
print(c)                # -> Counter({1: 2, 2: 1})
print(c[1])             # -> 2
print(c[9])             # -> 0     （不存在的键，Counter 给 0，不报错）
print(list(c.items()))  # -> [(1, 2), (2, 1)]
```

`.items()` 把字典变成一串 `(键, 值)` 对，方便 `for x, c in freq.items()` 一次拿两个。

这题里，`Counter` 负责把"n 个元素的数组"压成"m 个 (元素, 频次)"。

**元组（tuple），以及元组怎么比大小**

一句话：元组是用圆括号包起来的一串值，`(3, 1)` 就是"3 和 1 捆一起"。它和 list 差不多，但不能改。

关键：两个元组比大小，**从左往右逐位比，某一位分出胜负就停**。

```python
print((3, 1) < (2, 9))   # -> False   先比第一位：3 < 2 不成立，直接结束
print((2, 9) < (2, 1))   # -> False   第一位都是 2，才比第二位：9 < 1 不成立
```

这题里堆里存 `(频次, 元素)`，靠的就是这个规则：先按频次排，频次一样才比元素。写反成 `(元素, 频次)`，就变成按元素值排了。

**列表推导 `[x for _, x in heap]`**

一句话：把"遍历 + 挑选 + 装进新列表"压成一行。`_` 是"这个位置我不要，占个位"的惯例写法。

```python
pairs = [(3, 1), (2, 2)]
print([x for _, x in pairs])   # -> [1, 2]
```

**小顶堆**（前面 5-1 讲过）：`heappush` 进、`heappop` 弹堆顶、`h[0]` 看堆顶。这题还是"只留 k 个、超了弹堆顶"那个模板。

#### ② 大白话：这题到底在干什么

最笨的办法：先数一遍每个数出现几次，再把所有 (数, 次数) 按次数从大到小排序，取前 k 个。

笨在哪？你只需要前 k 名，却把 m 个全部排了一遍。k 远小于 m 的时候，大部分排序工作白做。

聪明的办法：还是那个"只留 k 个的候补席"。这次进榜的资格不是数值大小，而是**出现次数**。来一个 (数, 次数)，进榜；榜上超过 k 个，踢掉次数最少的。扫完，榜上就是出现最多的 k 个。

注意比较的东西换了：215 比的是数本身，这题比的是"次数"。所以堆里必须把次数放第一位，否则堆按元素值排，踢掉的就是"元素最小的"，全错。

还有一条更快的路（进阶要求）：次数不可能超过 n，那就开 n+1 个桶，第 c 个桶装"出现次数恰好为 c 的所有数"，然后从 c = n 往下扫，凑够 k 个就停。不用比较，O(n)。**能用桶排序的题，一定有"值域小且已知"这个隐藏条件。**

#### ③ `nums = [1,1,1,2,2,3], k = 2`

统计得到 `{1: 3, 2: 2, 3: 1}`，遍历顺序是 1、2、3。

| 读入 | 堆（按频次的小顶堆） | 发生了什么 |
|---|---|---|
| `(3, 1)` | `[(3, 1)]` | 1 出现 3 次，进榜 |
| `(2, 2)` | `[(2, 2), (3, 1)]` | 2 出现 2 次，进榜，正好 2 个 |
| `(1, 3)` | `[(2, 2), (3, 1)]` | 3 只出现 1 次，进榜后超了，踢掉次数最少的 `(1, 3)` |

堆里剩 `(2, 2)` 和 `(3, 1)`，对应元素 2 和 1，所以答案是 `[2, 1]`（顺序无所谓）。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `freq = Counter(nums)` | 一行数完：`{元素: 次数}` |
| `heap = []` | 空榜，只留 k 个 |
| `for x, c in freq.items():` | 一次拿一个 (元素, 次数) |
| `heapq.heappush(heap, (c, x))` | **次数在前**，堆才会按次数比 |
| `if len(heap) > k:` | 超过 k 个了 |
| `heapq.heappop(heap)` | 踢掉次数最少的（堆顶） |
| `return [x for _, x in heap]` | 把次数丢掉只留元素；返回顺序不限 |

### 考什么

- 表面考点：频率统计 + Top-K。
- 真正考点：**先降维，再做 Top-K**。原数组有 n 个元素，但不同的元素最多只有 m 个（m ≤ n）。统计完之后，问题就从"n 个元素的 Top-K"变成了"m 个 (元素, 频次) 的 Top-K"。
- 面试官想听到的关键句：
  - "先用哈希表把 n 个元素压成 m 个 (元素, 频次)，再在 m 个频次上做大小为 k 的小顶堆，总时间 O(n + m log k)。"
  - "进阶要求优于 O(n log n)，桶排序能做到 O(n)——因为频次的取值范围是 [1, n]，很小而且已知。"

### 思路是怎么想出来的

- **排序**：`sorted(count.items(), key=lambda kv: kv[1], reverse=True)[:k]`。O(m log m)，代码最短。n = 10⁵ 跑得动，但不满足"优于 O(n log n)"的进阶要求。
- **堆**：在 m 个频次里挑前 k 大，就是 215 那道题，只是"比较的东西"从数值变成了频次。小顶堆，O(m log k)。
- **桶排序**：频次最大不会超过 n，所以可以开 n+1 个桶，`bucket[c]` 装"所有频次恰好为 c 的元素"。然后从 c = n 往 1 扫，边扫边收集，凑够 k 个就停。O(n) 时间、O(n) 空间。
- **关键观察**：桶排序能成立，靠的是一个额外条件——**频次的取值范围已知且很小**（1 到 n）。如果题目问的是"前 k 大的数"（215），数值范围是 -10⁴ 到 10⁴，桶也能开，但一旦范围变成 10⁹ 就不行了。**能用桶排序的题，一定有"值域小"这个隐藏条件。**
- **快速选择**：也能用——在 m 个频次上做划分，平均 O(m)。但它会改数组，而且返回的 k 个是无序的（本题本来就允许任意顺序）。

### 走一遍 `nums = [1,1,1,2,2,3], k = 2`

统计得到 `{1: 3, 2: 2, 3: 1}`。

| 读入 | 动作 | 堆（按频次的小顶堆） |
|---|---|---|
| `(3, 1)` | 压入 | `[(3,1)]` |
| `(2, 2)` | 压入（正好 k 个） | `[(2,2), (3,1)]` |
| `(1, 3)` | 压入后超了，弹掉频次最小的 `(1,3)` | `[(2,2), (3,1)]` |

堆里是元素 2 和 1，答案 `[2, 1]`（顺序无所谓）。

注意堆里存的是 `(频次, 元素)`，**频次在前**——因为堆是按元组的第一个元素比较的。写反了就变成按元素大小排序，全错。

### 代码（Python）

```python
from typing import List
from collections import Counter
import heapq

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        freq = Counter(nums)          # 元素 -> 出现次数
        heap = []                     # 小顶堆，装 (频次, 元素)，只留 k 个
        for x, c in freq.items():
            heapq.heappush(heap, (c, x))
            if len(heap) > k:         # 频次最小的被淘汰
                heapq.heappop(heap)
        return [x for _, x in heap]
```

**逐段讲解**

- `Counter(nums)` 一行完成统计，等价于手写 `for x in nums: freq[x] = freq.get(x, 0) + 1`。
- 元组 `(c, x)` 的顺序是硬要求：堆按元组**从左到右**比较，先比频次，频次相同才比元素。反写成 `(x, c)` 就变成"按元素值排序"了。
- `len(heap) > k` 而不是 `>= k`，理由同 215。
- 最后用列表推导 `[x for _, x in heap]` 把元素取出来，丢掉频次。**返回顺序不限**，所以不用再排。
- 时间复杂度里那个 m 是"不同元素的个数"。最坏 m = n，所以写作 O(n log k)；但实际统计那一步是 O(n)，堆那一步是 O(m log k)。

### 复杂度

- 时间 O(n + m log k)：统计 O(n)，建堆 O(m log k)，其中 m 是不同元素个数，m ≤ n。
- 空间 O(m)：哈希表 O(m)，堆 O(k)。

### 常见误区（★ 最容易丢分的地方）

1. **堆里存 `(元素, 频次)`**。堆按元素值排序，弹掉的是"元素最小的"，不是"频次最低的"。示例 1 会返回 `[2, 3]`（正确答案 `{1, 2}`）。
2. **用大顶堆装全部 m 个再弹 k 次**。O(m log m)，比小顶堆差，而且没必要——你只需要 k 个。
3. **`len(heap) > k` 写成 `>= k`**。堆里只剩 k-1 个，示例 1（k=2）只返回 1 个元素 `[1]`。
4. **`heapq.nlargest(k, freq, key=freq.get)` 的返回值搞错**。它返回的是**元素**（key 只用来排序），不是频次。这个写法其实最简洁，可以当备选答案背。
5. **桶排序时桶的下标算错**。频次从 1 开始（不会出现频次 0 的元素），所以 `bucket = [[] for _ in range(n + 1)]`，用 `bucket[c]` 直接索引，不要写成 `bucket[c-1]`。
6. **`Counter.most_common(k)` 直接用**。功能对（内部就是 `nlargest`，O(m log k)），但面试时手写堆才能证明你懂原理。可以提一句"标准库有现成的"，然后照写。

### 面试追问 / 变体

- **要求 O(n)（进阶要求）**：桶排序，代码大约十行。完整写法如下，可以整段替换上面那个 `class Solution`：

```python
from typing import List
from collections import Counter

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        bucket = [[] for _ in range(len(nums) + 1)]   # bucket[c] 装"频次恰好为 c"的元素
        for x, c in Counter(nums).items():
            bucket[c].append(x)
        res = []
        for c in range(len(nums), 0, -1):             # 频次从高到低扫
            res.extend(bucket[c])
            if len(res) >= k:
                return res[:k]
        return res
```

- **频次相同的要求按元素值排序**：堆里存 `(频次, -元素)` 或最后对结果排一次。
- **数据流里实时求 Top-K 频率**：堆不够用（频次会变，堆里旧频次就失效了），要用"桶 + 双向链表"（LFU 那套结构）。
- **k = 1**：直接 `max(freq, key=freq.get)`，O(m)。

- 必测用例：
  - `[1,1,1,2,2,3], k=2` → `{1,2}`（题面示例）
  - `[1], k=1` → `{1}`（题面示例，单元素）
  - `[1,2,1,2,1,2,3,1,3,2], k=2` → `{1,2}`（题面示例，两个并列最高）

## 专题5-6. 最接近原点的 K 个点（Medium）

> 力扣 973 · 大小为 k 的大顶堆（存负距离）
> 前置：本册「0.5」+ 5-1（先看"求最大 k 个用小顶堆"，这题正好相反）

**一句话**：给一堆平面上的点，挑出离原点最近的 k 个。

### 精讲（零基础版）

#### ① 这题要用到的东西

**"列表套列表"和 `for x, y in points`**

一句话：`points = [[1,3], [-2,2]]` 是一个列表，里面每个元素又是一个小列表，代表一个点的 (x, y)。

```python
for x, y in [[1, 3], [-2, 2]]:
    print(x, y, x * x + y * y)
# -> 1 3 10
# -> -2 2 8
```

`for x, y in points` 叫**解包**：每个小列表有两个值，一次分给 x 和 y。这题里它就是"逐个点处理"。

`List[List[int]]` 读作"装列表的列表，里层装整数"——就是二维的意思。

**大顶堆**（前面 5-4 讲过）：`heapq` 只有小顶堆，要拿最大值就存负数。这题存的是 `-距离`，于是"最远的点"变成"最小的数"，跑到堆顶。

**为什么不开根号**

一句话：距离是 `√(x²+y²)`，但"谁更近"和"谁的 `x²+y²` 更小"是同一件事——开根是单调的，不改变大小关系。所以直接用平方和，省一次开方，也避开浮点误差。

这题里 `d = x * x + y * y` 就是那个"不用开根的距离"。

**堆元素是三元组**

一句话：`(-d, x, y)` 是把三个值捆在一起。堆按元组从左往右比，所以第一位放 `-d`，它才按距离排；后两位是坐标，只用来最后拼答案。距离相同时堆会接着比 x、再比 y，不会报错——本题保证答案唯一，所以不影响结果。

#### ② 大白话：这题到底在干什么

最笨的办法：算出每个点到原点的距离，按距离从小到大排序，取前 k 个。

笨在哪？和 215 一模一样：只要前 k 个，却把所有点排了一遍。

聪明的办法：还是"只留 k 个的候补席"。这次求的是**最近**的 k 个，所以该被淘汰的是"这 k 个里**最远**的那个"。要让最远的待在堆顶，就得用大顶堆（存负距离）。

把 0.5 节那句话再念一遍：**堆顶必须是"这 k 个里最该被淘汰的那一个"**。求最大 k 个 → 淘汰最小的 → 小顶堆；求最小 k 个 → 淘汰最大的 → 大顶堆。这题是后一半。

具体动作：每个点算距离平方，把 `(-距离, x, y)` 压进堆；堆超过 k 个就弹堆顶，弹掉的是最远的那个。扫完，堆里就是最近的 k 个。因为堆里始终只留 k 个，最后不用再排一次——题目说顺序不限，直接返回就行。

#### ③ `points = [[3,3],[5,-1],[-2,4]], k = 2`

距离平方：`(3,3)` 是 9+9=18，`(5,-1)` 是 25+1=26，`(-2,4)` 是 4+16=20。

| 读入 | 堆（存负距离） | 发生了什么 |
|---|---|---|
| `(3,3)` | `[(-18, 3, 3)]` | 距离 18，进榜 |
| `(5,-1)` | `[(-26, 5, -1), (-18, 3, 3)]` | 距离 26，进榜，正好 2 个 |
| `(-2,4)` | `[(-20, -2, 4), (-18, 3, 3)]` | 距离 20，进榜后超了，弹掉堆顶 `-26`（最远的） |

所以答案是 `[[-2, 4], [3, 3]]`（顺序不限）。堆顶是 `-20`，对应距离 20 的 `(-2,4)`——它是这 2 个里最远的，随时准备被下一个更近的点踢掉。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `for x, y in points:` | 一次拿出一个点的横纵坐标 |
| `d = x * x + y * y` | 距离平方，不开根 |
| `heapq.heappush(heap, (-d, x, y))` | **第一位必须是 `-d`**，否则堆不按距离排 |
| `if len(heap) > k:` | 超过 k 个了 |
| `heapq.heappop(heap)` | 踢掉最远的（堆顶是最小负数 = 最大距离） |
| `return [[x, y] for _, x, y in heap]` | 拼回列表；必须是 list 不能是 tuple，力扣按值逐位比 |

### 考什么

- 表面考点：按距离排序取前 k。
- 真正考点：**Top-K 的"最近"版本**——求最小的 k 个，要用**大顶堆**。它和 215 正好是 0.5 节那句话的两个方向。
- 面试官想听到的关键句：
  - "求最近的 k 个，堆顶要放'这 k 个里最远的那个'，它才该被淘汰。所以是大顶堆，Python 里存负距离。"
  - "不用开根号——比较 `x² + y²` 和比较 `√(x²+y²)` 等价，省掉浮点误差。"

### 思路是怎么想出来的

- **排序**：`sorted(points, key=lambda p: p[0]**2 + p[1]**2)[:k]`。O(n log n)，n = 10⁴ 跑得动，代码最短。
- **堆**：维护一个容量为 k 的**大顶堆**，堆顶是"当前这 k 个里最远的"。新点如果比堆顶近，就把堆顶弹掉、把新点压进去。O(n log k)。
- **快速选择**：按距离划分数组，只递归有答案的那一半，平均 O(n)。缺点是要改数组，而且返回的 k 个无序（本题允许）。
- **为什么这题是大顶堆，215 是小顶堆**：把 0.5 节那句话再念一遍——**堆顶必须是"这 k 个里最该被淘汰的那一个"**。
  - 215 求"最大的 k 个"，该淘汰的是"这 k 个里最小的" → 小顶堆。
  - 973 求"最小的 k 个"，该淘汰的是"这 k 个里最大的" → 大顶堆。
- **一个省事的细节**：距离用平方和，不开根。`√` 是单调递增的，所以"谁更近"和"谁的平方和更小"完全等价。开根只会引入浮点误差，还慢。

### 走一遍 `points = [[1,3],[-2,2]], k = 1`

距离平方：`(1,3)` 是 1+9=10；`(-2,2)` 是 4+4=8。

| 读入 | 动作 | 大顶堆（存 `-距离`） | 堆顶（最远） |
|---|---|---|---|
| `(1,3)` | 压入 `(-10, 1, 3)` | `[(-10,1,3)]` | (1,3)，距离 10 |
| `(-2,2)` | 压入 `(-8,-2,2)`，长度 2 > 1，弹堆顶 | `[(-8,-2,2)]` | (-2,2)，距离 8 |

答案 `[[-2,2]]`。

读入 `(-2,2)` 那一行值得看仔细：小顶堆里 `-10 < -8`，所以 `-10` 在堆顶——它对应的是**距离最大**的那个点。弹掉它，正好淘汰了最远的。

### 代码（Python）

```python
from typing import List
import heapq

class Solution:
    def kClosest(self, points: List[List[int]], k: int) -> List[List[int]]:
        heap = []                                   # 大顶堆（存负距离），只留 k 个
        for x, y in points:
            d = x * x + y * y                       # 距离平方，不用开根
            heapq.heappush(heap, (-d, x, y))
            if len(heap) > k:                       # 堆顶是这 k 个里最远的
                heapq.heappop(heap)
        return [[x, y] for _, x, y in heap]
```

**逐段讲解**

- 堆元素是三元组 `(-d, x, y)`。**第一个位置必须是 `-d`**，否则堆不按距离排。后两位是坐标，用来最后拼答案。
- 为什么要 `-d` 而不是 `d`：小顶堆的堆顶是最小值。存 `-d` 之后，"距离最大"变成了"数值最小"，就跑到堆顶了——正好是要淘汰的那个。
- `d = x*x + y*y` 不用 `math.sqrt`：省一次开方，也避开浮点比较。
- 返回 `[[x, y] for ...]` 而不是 `[(x, y) for ...]`：力扣的判题是拿你的返回值和期望值逐项比较，`(1, 2) != [1, 2]`，返回元组列表会判错。
- 元组的后两位参与比较：距离相同时，堆会继续比 x、再比 y。本题保证"答案唯一（除顺序外）"，所以不影响正确性。

### 复杂度

- 时间 O(n log k)：n 次 `heappush`，最多 n 次 `heappop`，每次 O(log k)。
- 空间 O(k)：堆里最多 k 个三元组。

### 常见误区（★ 最容易丢分的地方）

1. **用小顶堆存距离**。堆顶是最近的，超长时 `heappop` 弹掉的正是最近的点，最后堆里剩下的是**最远的** k 个。示例 1 会返回 `[[1,3]]` 而不是 `[[-2,2]]`。**方向反了，这题必错。**
2. **忘了存负数**。同上。
3. **堆里只存距离不存坐标**。最后拼不出答案。必须 `(-d, x, y)` 把坐标带上。
4. **用 `math.sqrt` 比较距离**。功能上没错（单调），但浮点数在"距离相等"时可能判出 `1e-16` 的差，把本该并列的点排出先后。平方和是整数，比较绝对精确。
5. **返回 `[(x, y), ...]`**。元组和 list 不相等，力扣判错。
6. **`len(heap) > k` 写成 `>= k`**。示例 1（k=1）会返回空列表 `[]`——压入第一个点后立刻被弹出。
7. **以为"距离相同"会让程序崩**。不会——元组会继续比 x、y。但如果题目不保证答案唯一，你就要自己定一个稳定的 tie-break 规则。

### 面试追问 / 变体

- **求最远的 k 个点**：换成小顶堆（堆顶是最近的，正好该淘汰），其余不动。这就是 215 的形态。
- **点带权重（加权距离）**：把 `x*x + y*y` 换成 `w * (x*x + y*y)`，其余不动。
- **要求按距离升序返回**：最后对结果再排一次，O(k log k)，不影响总复杂度。
- **n 大到内存放不下**：分块读 + 每块维护 k 个，最后归并；或者外部排序。
- **三维空间**：`d = x*x + y*y + z*z`，其余不动。

### 自测

- 必测用例：
  - `[[1,3],[-2,2]], k=1` → `[[-2,2]]`（题面示例）
  - `[[3,3],[5,-1],[-2,4]], k=2` → `[[3,3],[-2,4]]` 或 `[[-2,4],[3,3]]`（题面示例，顺序不限）
  - `[[0,1]], k=1` → `[[0,1]]`（单点）
  - `[[1,1],[1,1]], k=2` → 两个点（重复点）
  - `[[-9999,-9999],[10000,10000]], k=1` → `[[-9999,-9999]]`（大坐标，平方和到 2×10⁸ 量级）
  - `[[1,0],[0,1],[-1,0]], k=2` → 任意两个距离为 1 的点（距离并列）
