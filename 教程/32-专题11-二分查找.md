## 零、把二分收成一个框架

先把最常用的模板钉死。**左闭右闭**：

```python
def binary_search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:                 # 区间里还有元素就继续
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1               # 答案在右半边，mid 已排除
        else:
            right = mid - 1              # 答案在左半边，mid 已排除
    return -1
```

三个分支各管一件事：命中就交卷；`nums[mid] < target` 说明 `mid` 和它左边全部小于 `target`，整段砍掉；`else` 对称。

**为什么它是 O(log n)**：每轮区间长度大约减半，从 n 减到 1 只要 log₂n 轮。n = 10⁵ 时约 17 轮，n = 10⁹ 时约 30 轮。所以看到题目把 n 给到 10⁵ 甚至 10⁹、又要求 O(log n)，基本就是在提示你二分。

四个细节必须能解释，不能背：

- **`right = len(nums) - 1`**：闭区间的标志，`right` 是"最后一个可能的下标"。
- **`while left <= right`**：也是闭区间的标志。`left == right` 时区间里还有一个元素，必须检查；写成 `<` 就会漏掉它。
- **`mid = (left + right) // 2`**：整除必须**向下**取整，这样 `left < right` 时必有 `mid < right`，`mid + 1` 不会越界。
- **`left = mid + 1` 而不是 `mid`**：`nums[mid]` 刚刚比过了，确定不是答案。若写 `left = mid`，区间长度为 2 时 `mid == left`，`left` 原地不动，**死循环**。

然后是**找边界**的变体。它回答的是"第一个 `>= target` 的位置在哪"：

```python
def lower_bound(nums, target):
    left, right = 0, len(nums)      # 左闭右开：right 是"越界位"
    while left < right:             # 区间空了才停
        mid = (left + right) // 2
        if nums[mid] < target:
            left = mid + 1          # mid 太小，确定不要
        else:
            right = mid             # mid 可能就是答案，留着
    return left                     # 第一个 >= target 的下标（可能 == len）
```

和上面那份逐条对照，差别只有三处：`right` 取 `len` 而不是 `len-1`；循环用 `<` 而不是 `<=`；收缩时写 `right = mid` 而不是 `mid-1`。**根源是一句话：能确定"不是答案"的那一侧才 ±1，可能是答案的那一侧留在区间里。** 返回值可能等于 `len(nums)`（`target` 比所有元素都大），用之前要判越界。

最后一句总纲：**闭区间配 `<=`，开区间配 `<`；`+1/-1` 表示"这个位置排除了"，不写 `+1/-1` 表示"这个位置还可能是答案"。** 选一套，从头用到尾，绝不混。

写之前先回答两个问题，答完这两句，代码基本就出来了：**① 我的区间是闭的还是开的？② `mid` 这个位置，是"候选答案"还是"已经排除"？** 二分写错的人，九成是在这两个问题上前后不一致。

## 专题11-1. 搜索旋转排序数组（Medium）

> 力扣 33 · 二分 · 判据换成"哪一半有序"
> 前置：本册「零、把二分收成一个框架」

**一句话**：一个升序数组被"整体左移"过一段（比如 `[0,1,2,4,5,6,7]` 变成 `[4,5,6,7,0,1,2]`），值互不相同，要在 O(log n) 内找到 `target` 的下标。

### 精讲（零基础版）

#### ① 这题要用到的东西

**二分查找（binary search）**

一句话：每问一次就砍掉一半的查找方法。前提是你得能一眼判断"答案在左半边还是右半边"。

生活类比：猜数字 1–100。你先猜 50，对方说"大了"，51–100 就全扔了；再猜 25 …… 7 次之内必中。

```python
nums = [1, 3, 5, 7, 9, 11, 13]
target = 9
left, right = 0, len(nums) - 1
while left <= right:
    mid = (left + right) // 2
    print("看", mid, nums[mid])
    if nums[mid] == target:
        print("找到，下标", mid)
        break
    elif nums[mid] < target:
        left = mid + 1
    else:
        right = mid - 1
# 输出：
# 看 3 7
# 看 5 11
# 看 4 9
# 找到，下标 4
```

7 个数只看了 3 次。这题里，二分砍的不是"数字大小"，而是"哪一半还是升序的"。

**`//` 整除**

一句话：`//` 是"除完向下取整"，不是四舍五入。`7 // 2` 是 3，不是 3.5。

```python
print(7 // 2)      # -> 3
print(6 // 2)      # -> 3
```

二分里必须用它：下标得是整数，而且必须向下取整，否则 `mid` 可能等于右端点，`mid + 1` 就出去了。

**`while left <= right` 和"区间"**

一句话：`left`、`right` 是"还有可能的答案"这段区间的两个端点，`[left, right]` 叫闭区间 —— 两端都还没被排除。

生活类比：在书里找一页，`left` 是你翻到的左边那页、`right` 是右边那页，两页都还没看。

这题里区间从 `[0, n-1]` 开始，每轮砍掉一半；`left > right` 说明全找完还没命中，返回 -1。

**循环不变量**

一句话：每轮开始时"一定成立的那句话"。这题的不变量是"如果 `target` 在数组里，它的下标一定落在 `[left, right]` 内"。

为什么重要：写二分时只盯这一句 —— 每一步收缩都不能把它弄假。这句话定了，`mid ± 1` 该不该写就跟着定了，不用背。

**旋转数组**

一句话：把一个升序数组从某处掰断，把前半段搬到后面。`[0,1,2,4,5,6,7]` 从 4 那里掰，变成 `[4,5,6,7,0,1,2]`。

生活类比：一摞按大小排好的扑克，从中间切一刀，把上面那叠放到最下面。

关键性质：掰断只制造**一个**"往下掉"的地方，所以随便切一半，两半里必有一半还是升序的。

#### ② 大白话：这题到底在干什么

最笨的办法：从头到尾扫一遍，看 `target` 在不在。O(n)，n 是 5000 时也能过，但题目明说要 O(log n)。

为什么普通二分直接套会错：普通二分靠"`nums[mid] < target` 就往右找"，这句话默认整个数组是升序的。旋转之后它不成立了。`[4,5,6,7,0,1,2]` 找 0，`mid` 落在 7 上，7 > 0，普通二分会把右半边扔掉 —— 可 0 恰恰在右半边。

笨在哪？**它用了一个这题不成立的假设**。

聪明的办法：换一个"每轮都能一眼判断"的问题。`mid` 把数组切成两半，因为只有一个下降点，两半里必有一半是升序的。先认出哪一半是升序的（比较 `nums[mid]` 和 `nums[left]`），再看 `target` 在不在这一半的数值范围里：在，就往这半走；不在，就一定在另一半。

#### ③ 拿 `[4,5,6,7,0,1,2]` 找 0 走一遍

| 轮 | left | right | mid | nums[mid] | 判断 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 7 | `7 >= 4` 左半有序；`4 <= 0 < 7` 不成立 | `left = 4` |
| 2 | 4 | 6 | 5 | 1 | `1 >= 0` 左半有序；`0 <= 0 < 1` 成立 | `right = 4` |
| 3 | 4 | 4 | 4 | 0 | `nums[4] == 0`，命中 | 返回 4 |

所以答案是 4。注意第 2 轮：`target` 恰好等于左端点 `nums[4] = 0`，值域判断用 `<=` 才能把它留在区间里。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `left, right = 0, len(nums) - 1` | 一开始整个数组都是候选 |
| `while left <= right` | 区间里还有元素就继续；空了就说明找完了 |
| `mid = (left + right) // 2` | 取中点，向下取整 |
| `if nums[mid] == target: return mid` | 命中就交卷 |
| `if nums[mid] >= nums[left]` | 左半 `[left, mid]` 是升序吗？用 `>=` 是因为 `mid` 可能等于 `left` |
| `if nums[left] <= target < nums[mid]` | `target` 落在左半的值域里吗？左端点算，`mid` 不算（它刚比过） |
| `right = mid - 1` | 在左半 → 砍掉右半 |
| `else: left = mid + 1` | 不在左半 → 一定在右半，砍掉左半 |
| `if nums[mid] < target <= nums[right]` | 右半有序时，`target` 落在右半的值域里吗？ |
| `return -1` | 区间空了还没命中 = 不存在 |

### 考什么

- 表面考点：旋转数组里查找。
- 真正考点：**二分的判据不必是"大小比较"**。只要能用 O(1) 判断"答案在哪一半"，二分就成立。这题的判据是"从 `mid` 切开后，哪一半还是升序的"。
- 面试官想听到的关键句：
  - "旋转只制造了一个下降点，所以 `mid` 左右两半里**必有一半是升序的**。"
  - "先定位有序的那半，再看 `target` 在不在它的值域里：在就进去，不在就去另一半。"

### 思路是怎么想出来的

**暴力**：线性扫一遍，O(n)。n ≤ 5000，能过，但题目明确要 O(log n)，而且这题就是考二分。

**为什么普通二分直接套会错**：普通二分靠"`nums[mid] < target` ⟹ 答案在右边"。这在旋转数组里不成立。看 `[4,5,6,7,0,1,2]` 找 0：`mid = 3`，`nums[3] = 7 > 0`，普通二分会把右半边整段砍掉——而 0 恰恰在右边。

**关键观察**：无论 `mid` 落在哪，`[left, mid]` 和 `[mid, right]` 里**至少有一半是严格升序的**。原因是旋转只产生一个"下降点"，`mid` 不可能同时站在下降点的两侧。

判断哪一半有序，看 `nums[mid]` 和 `nums[left]` 的关系：

- `nums[mid] >= nums[left]` ⟹ `[left, mid]` 升序（左半有序）。
- 否则 ⟹ `[mid, right]` 升序（右半有序）。

为什么用 `>=` 而不是 `>`：`mid` 可能等于 `left`（区间长度为 1 或 2 时），此时 `nums[mid] == nums[left]`，左半只有一个元素，当然"有序"。写成 `>` 会把这种情况误判成右半有序，区间直接走反。

**找到有序半之后怎么用**：有序半的值域是已知的（从 `nums[left]` 到 `nums[mid]`，或从 `nums[mid]` 到 `nums[right]`），所以可以直接判断 `target` 在不在里面：

- 左半有序时，若 `nums[left] <= target < nums[mid]`，答案在左半，`right = mid - 1`；否则在右半，`left = mid + 1`。
- 右半有序时，若 `nums[mid] < target <= nums[right]`，答案在右半，`left = mid + 1`；否则在左半，`right = mid - 1`。

值域判断用**开区间**（不含 `nums[mid]`）是因为 `nums[mid] == target` 已经被第一个分支拦掉了，不必再管。

### 走一遍

`nums = [4,5,6,7,0,1,2]`，`target = 0`：

| 轮 | left | right | mid | nums[mid] | 判断 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 7 | `7 >= 4` 左半有序；`4 <= 0` 不成立 | `left = 4` |
| 2 | 4 | 6 | 5 | 1 | `1 >= 0` 左半有序；`0 <= 0 < 1` 成立 | `right = 4` |
| 3 | 4 | 4 | 4 | 0 | 命中 | 返回 4 |

`target = 3` 时，第 2 轮 `0 <= 3 < 1` 不成立，`left = 6`；第 3 轮 `nums[6] = 2`，左半只剩它自己，`2 <= 3 < 2` 不成立，`left = 7`，循环结束返回 -1。

### 代码（Python）

```python
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1
        while left <= right:
            mid = (left + right) // 2
            if nums[mid] == target:
                return mid
            if nums[mid] >= nums[left]:          # 左半边 [left, mid] 有序
                if nums[left] <= target < nums[mid]:
                    right = mid - 1
                else:
                    left = mid + 1
            else:                                # 右半边 [mid, right] 有序
                if nums[mid] < target <= nums[right]:
                    left = mid + 1
                else:
                    right = mid - 1
        return -1
```

**逐段讲解**

- 外层还是那个左闭右闭模板，`<=` 和 `mid ± 1` 一个都没改。**这题的改动全在"往哪边收"的判断上**，模板本身没动——这是二分题的通例。
- `nums[mid] >= nums[left]`：`mid` 可能是 `left`，所以用 `>=`。
- `nums[left] <= target < nums[mid]`：左闭右开。`target == nums[left]` 要算"在里面"（左端点是候选），`target == nums[mid]` 不用管（前面已返回）。
- `else` 分支里 `nums[mid] < target <= nums[right]`：同样，右端点包含、`mid` 不包含。
- 两个内层 `else` 是**互补**的：不在有序半，就一定在另一半。漏写一个就会走错方向。

### 复杂度

- 时间 O(log n)：每轮区间减半，和普通二分一样。
- 空间 O(1)：只用了三个下标。

### 常见误区（★ 最容易丢分的地方）

1. **直接套普通二分**。`[4,5,6,7,0,1,2]` 找 0 返回 -1，正确 4。原因见上面"为什么普通二分会错"。
2. **判断有序用 `nums[left] < nums[mid]`（严格小于）**。区间长度为 2 时 `mid == left`，`<` 不成立，代码误判成"右半有序"。`[3,1]` 找 1 返回 -1，正确 1。
3. **只写一个分支**。只处理"左半有序"，右半有序的情况漏掉，`[5,1,3]` 找 5 这类用例会错。
4. **值域判断写成 `nums[left] <= target <= nums[mid]`**。这不会算错（`== nums[mid]` 的情况前面已返回），但会让"命中"的那一轮多收缩一次，属于可读性问题，不是错误——面试时别把它说成 bug。
5. **`while left < right` 配 `right = len(nums) - 1`**。单元素数组 `[1]` 找 1，循环不进入，返回 -1，正确 0。

### 面试追问 / 变体

- **允许重复元素（力扣 81）**：判据会失效，要加一段"三端相同就缩一格"，最坏退化到 O(n)。
- **数组根本没旋转**：这题代码天然支持（`nums[mid] >= nums[left]` 永远成立，退化成普通二分）。
- **不找 target，找最小值（力扣 153）**：不用 `target` 了，改成和右端点比。
- **找"旋转了多少次"**：就是最小值的下标，153 返回下标即可。
- **如果要求返回所有匹配下标**：先按 33 找到一个，再向两边扩，但重复元素多时最坏 O(n)。

### 自测

- 必测用例：
  - `[4,5,6,7,0,1,2], 0` → 4（题面示例）
  - `[4,5,6,7,0,1,2], 3` → -1（题面示例）
  - `[1], 0` → -1（题面示例，单元素）
  - `[1], 1` → 0（单元素命中）
  - `[3,1], 1` → 1（两元素旋转，专治 `>` 写成 `<`）
  - `[5,1,3], 5` → 0（命中左端点）
- 30 秒自检：能不能说出"必有一半有序、怎么判断哪一半、判断完怎么用值域走"？

## 专题11-2. 在排序数组中查找元素的第一个和最后一个位置（Medium）

> 力扣 34 · 二分 · 两次找边界
> 前置：本册「零、找边界的变体模板」

**一句话**：非递减数组里可能有重复值，找出 `target` 第一次和最后一次出现的下标；没有就返回 `[-1, -1]`。

### 精讲（零基础版）

#### ① 这题要用到的东西

**"命中之后不停"的二分（找边界）**

一句话：普通二分一找到就交卷；找边界要"找到了也继续往同一个方向收"，收到区间空了，落点就是边界。

生活类比：在一排同名同姓的人里找"第一个张三"。随便抓到一个张三不算完，得一直往左问"你前面还有张三吗"，问到没有为止。

```python
nums = [5, 7, 7, 8, 8, 10]
target = 8
left, right = 0, len(nums) - 1
while left <= right:
    mid = (left + right) // 2
    if nums[mid] >= target:      # 注意是 >= ，不是 ==
        right = mid - 1
    else:
        left = mid + 1
print(left)                      # -> 3
```

`nums[3]` 正是第一个 8。这题里，`>= target` 一路把 `right` 往左压，压到底时 `left` 就停在"第一个 `>= target`"的位置 —— 那就是左边界。

**函数里再定义函数**

一句话：Python 允许在函数体里再写 `def`，内层函数能直接读外层的变量（`nums`、`target`、`n`），不用当参数传进去。

生活类比：一个工具箱里放两个小工具，它们都看得见工具箱主人的桌子。

```python
def outer(nums, target):
    def find_first():          # 内层函数，可以直接读外层的 nums 和 target
        return nums[0] + target
    return find_first()

print(outer([5, 7], 1))        # -> 6
```

这题里 `find_first` 和 `find_last` 都直接用了外层的 `nums` 和 `target`，所以调用时不用传参。

**`-> int` 这种类型标注**

一句话：写在函数名后面，只是"声明返回值是整数"，Python 不会检查，纯给人看的。

这题里 `def find_first() -> int:` 就是提醒你"它返回一个下标"。

**为什么要校验 `first > last`**

一句话：两个边界函数在 `target` 不存在时也会各返回一个下标，所以必须再验一次。

生活类比：两个人在一本书里分别找"第一个 ≥ 某页"和"最后一个 ≤ 某页"，如果第一个人指到了第二个人后面，说明这一页根本不存在。

#### ② 大白话：这题到底在干什么

最笨的办法：从头扫到尾，记下第一次和最后一次看到 `target` 的位置。O(n)，题目要 O(log n)。

看起来聪明一点但不够好的：先用普通二分随便找到一个 `target`，再往左右两边扩。这个最坏还是 O(n) —— 数组里全是 `target` 时，从中间扩到两头要走 n/2 步。

笨在哪？**"先找到再扩"这个动作本身就在线性地走**。

聪明的办法：从一开始就不打算停在命中处。把判断条件从"等于 target"换成"大于等于 target"，这样即使 `nums[mid]` 就是 `target` 也不返回，而是继续把 `right` 往左压。压到区间空了，`left` 停下的地方就是"第一个 ≥ target"的位置，也就是左边界。

右边界把不等号反过来：`<= target` 就往右推，最后 `right` 停在"最后一个 ≤ target"。

最后别忘了校验：`target` 根本不在数组里时，这两个函数也会各返回一个位置，而此时必然 `first > last`。一个判断同时挡住空数组、太小、太大三种情况。

#### ③ 拿 `[5,7,7,8,8,10]` 找 8 的左边界走一遍

| 轮 | left | right | mid | nums[mid] | `>= 8` ? | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 2 | 7 | 否 | `left = 3` |
| 2 | 3 | 5 | 4 | 8 | 是 | `right = 3` |
| 3 | 3 | 3 | 3 | 8 | 是 | `right = 2` |

第 3 轮之后 `left = 3 > right = 2`，循环结束，所以左边界是 3。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `n = len(nums)` | 先把长度存下来，两个内层函数都要用 |
| `def find_first() -> int:` | 定义"找左边界"的小工具，返回一个下标 |
| `left, right = 0, n - 1` | 每个小工具都从整个数组开始 |
| `if nums[mid] >= target` | 只要 ≥ 目标就把右端往左压 —— 命中也不停 |
| `right = mid - 1` | `mid` 可能是答案，但先记着，继续往左找 |
| `return left` | 循环结束时 `left` = 第一个 ≥ target 的位置 |
| `if nums[mid] <= target` | 找右边界时反过来：只要 ≤ 目标就往右推 |
| `return right` | 循环结束时 `right` = 最后一个 ≤ target 的位置 |
| `if first > last` | 两个边界交叉 = 目标不存在（或数组为空） |
| `return [first, last]` | 都在界内，就是答案 |

### 考什么

- 表面考点：找左右边界。
- 真正考点：**二分可以"命中之后不停"**。普通二分命中就交卷；找边界要命中后继续朝一个方向收，用循环结束时 `left`/`right` 的落点当答案。
- 面试官想听到的关键句：
  - "找左边界 = 找第一个 `>= target` 的位置；找右边界 = 找最后一个 `<= target` 的位置。"
  - "两次二分各 O(log n)，最后校验一次 `first > last` 就同时覆盖了空数组、太小、太大三种情况。"

### 思路是怎么想出来的

**暴力一**：线性扫一遍记下首尾，O(n)。题目要 O(log n)。

**暴力二**：先用普通二分找到任意一个 `target`，再往两边扩。这个写法**最坏是 O(n)**：数组全是 `target` 时，从中间扩到两头要走 n/2 步。

**关键观察**：与其"找到再扩"，不如**从一开始就不打算停在命中处**。把判断条件从 `== target` 换成 `>= target`：

```python
if nums[mid] >= target:
    right = mid - 1     # mid 可能就是答案，但先记着，继续往左找
else:
    left = mid + 1      # mid 太小，确定不是
```

循环结束时 `left` 落在"第一个 `>= target`"的位置——这就是左边界。为什么：所有 `< target` 的位置都被 `left` 跨过去了，而 `>= target` 的位置只会让 `right` 往左压，最终 `left` 停在第一个满足条件的地方。

右边界把条件反过来：`nums[mid] <= target` 时 `left = mid + 1`，结束时 `right` 是"最后一个 `<= target`"的位置。

**为什么最后要校验**：这两个函数都会返回一个下标，即使 `target` 不存在。`[5,7,7,8,8,10]` 找 6，`first` 会得到 1（第一个 ≥ 6 的是 7），`last` 会得到 0（最后一个 ≤ 6 的是 5），于是 `first > last`。**一个判断同时挡住三种情况**：空数组（`first=0, last=-1`）、`target` 太小、`target` 太大。

### 走一遍

`nums = [5,7,7,8,8,10]`，`target = 8`，找左边界：

| 轮 | left | right | mid | nums[mid] | 判断 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 2 | 7 | `7 < 8` | `left = 3` |
| 2 | 3 | 5 | 4 | 8 | `8 >= 8` | `right = 3` |
| 3 | 3 | 3 | 3 | 8 | `8 >= 8` | `right = 2` |

`left = 3 > right = 2`，退出，`first = 3`。

同一个数组找 6：`mid=2`（7 ≥ 6）→ `right=1`；`mid=0`（5 < 6）→ `left=1`；`mid=1`（7 ≥ 6）→ `right=0`；退出得 `first = 1`。而 `last` 那边会得 0，`1 > 0`，返回 `[-1,-1]`。

### 代码（Python）

```python
from typing import List

class Solution:
    def searchRange(self, nums: List[int], target: int) -> List[int]:
        n = len(nums)

        def find_first() -> int:             # 第一个 >= target 的下标
            left, right = 0, n - 1
            while left <= right:
                mid = (left + right) // 2
                if nums[mid] >= target:
                    right = mid - 1
                else:
                    left = mid + 1
            return left

        def find_last() -> int:              # 最后一个 <= target 的下标
            left, right = 0, n - 1
            while left <= right:
                mid = (left + right) // 2
                if nums[mid] <= target:
                    left = mid + 1
                else:
                    right = mid - 1
            return right

        first = find_first()
        last = find_last()
        if first > last:                     # 数组为空，或 target 不存在
            return [-1, -1]
        return [first, last]
```

**逐段讲解**

- 两个内层函数都是标准的左闭右闭模板，只是把"三分支"压成了"两分支"：**不需要 `== target` 的分支**，因为命中之后还要继续收，不能返回。
- `find_first` 返回 `left`，`find_last` 返回 `right`：这不是随便写的。循环退出时一定满足 `left == right + 1`，而 `left` 是"第一个不满足 `< target`"的位置，`right` 是"最后一个满足 `<= target`"的位置。两个返回值各自对应一句不变量。
- `if first > last`：这一行同时处理空数组和"不存在"。`nums = []` 时 `find_first` 返回 0、`find_last` 返回 -1，`0 > -1` 成立，直接返回 `[-1,-1]`，不用特判。
- 返回 `[first, last]` 而不是 `[first, first + count - 1]`：不用数个数，省一次扫描。

### 复杂度

- 时间 O(log n)：两次二分，各 O(log n)。
- 空间 O(1)：两个内层函数只用了四个整数。

### 常见误区（★ 最容易丢分的地方）

1. **不校验直接返回**。`[5,7,7,8,8,10]` 找 6 返回 `[1,0]`；空数组返回 `[0,-1]`。两个都是非法下标，力扣判错。
2. **右边界用 `first - 1` 凑**。`[5,7,7,8,8,10]` 找 8 返回 `[3,2]`，正确 `[3,4]`。`first-1` 只在"目标出现一次"时碰巧对。
3. **找到后线性扩**。全相同数组下退化成 O(n)，题目要的 O(log n) 没了。
4. **两个函数里判断条件写反**。`find_first` 里用 `<=` 就变成了找右边界，返回 `[4,4]`，看起来"有结果"但完全错。
5. **`return right` 和 `return left` 互换**。`find_first` 返回 `right` 会得到"最后一个 `< target`"的位置，差一位，`target` 存在时返回 `[first-1, last]`。

### 面试追问 / 变体

- **一行版**：`from bisect import bisect_left, bisect_right`，然后 `lo = bisect_left(nums, target); hi = bisect_right(nums, target) - 1`，再判 `lo > hi`。标准库就是这两个函数的 C 实现，面试写出来是加分项。
- **找"第一个 `>= target`"**：就是 35 的插入位置，`find_first` 直接返回。
- **找"最后一个 `<= target`"**：`find_last` 直接返回。
- **数 `target` 出现几次**：`bisect_right - bisect_left`。
- **数组是旋转的**：边界查找会复杂很多（33/81 的判据 + 边界收缩），面试一般不考这个组合。

### 自测

- 必测用例：
  - `[5,7,7,8,8,10], 8` → `[3,4]`（题面示例）
  - `[5,7,7,8,8,10], 6` → `[-1,-1]`（题面示例，夹在两个值中间）
  - `[], 0` → `[-1,-1]`（题面示例，空数组）
  - `[1], 1` → `[0,0]`（单元素命中）
  - `[2,2], 2` → `[0,1]`（全相同，最坏情况）
  - `[1,2,3], 3` → `[2,2]`（命中右端）
  - `[1,2,3], 0` → `[-1,-1]`（比所有元素小）
  - `[1,2,3], 4` → `[-1,-1]`（比所有元素大）
- 30 秒自检：能不能说出"两次二分各找什么、为什么命中不返回、为什么一个 `first > last` 就够校验"？

## 专题11-3. 搜索插入位置（Easy）

> 力扣 35 · 二分 · lower_bound
> 前置：本册「零、找边界的变体模板」

**一句话**：升序无重复数组里找 `target`，找到返回下标，找不到返回它按顺序该插的位置。

### 精讲（零基础版）

#### ① 这题要用到的东西

**lower_bound（下界）**

一句话：在有序数组里找"第一个 ≥ target 的位置"。找到了它就是 `target` 自己的下标，找不到它就是 `target` 该插进去的位置。

生活类比：一排人按身高站好了，来了个新同学，你要找出"他该插在哪个人前面"。比他矮的都在他前面，第一个不比他矮的就是他的位置。

```python
def where(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return left          # 没找到：left 就是插入点

print(where([1, 3, 5, 6], 2))    # -> 1
print(where([1, 3, 5, 6], 7))    # -> 4
print(where([1, 3, 5, 6], 5))    # -> 2
```

这题要的正是这个数：命中给下标，没命中给插入点。

**`return left` 而不是 `return -1`**

一句话：循环结束时 `left` 和 `right` 会交叉（`left == right + 1`），`left` 恰好指向"第一个比 target 大的位置"。

```python
nums = [1, 3, 5, 6]
target = 2
left, right = 0, len(nums) - 1
while left <= right:
    mid = (left + right) // 2
    if nums[mid] < target:
        left = mid + 1
    else:
        right = mid - 1
print(left, right)      # -> 1 0
```

所以答案是 1，而不是"没找到"。这题里 `left` 本身就是答案。

**`if / elif / else`**

一句话：从上往下试，第一个成立的分支执行，后面的全跳过。这题三个分支：命中、太小、太大。

#### ② 大白话：这题到底在干什么

最笨的办法：从头扫，找到第一个不小于 `target` 的数就返回它的下标。O(n)，题目要 O(log n)。

笨在哪？数组本来是有序的，扫一遍等于把"有序"这个信息白白扔了。

聪明的办法：直接套二分模板，只改最后一行。命中就返回下标；没命中时，循环结束时 `left` 已经跨过了所有比 `target` 小的位置，而所有比它大的位置都被 `right` 压到了左边 —— 于是 `left` 正好停在"第一个比 target 大的位置"，也就是它该插的地方。

"插到末尾"不用特判：找比所有数都大的值时，`left` 会一路推到 `len(nums)`，正好是末尾。

#### ③ 拿 `[1,3,5,6]` 走三个用例

| 找谁 | 每轮的 mid | 结束时 | 答案 |
|---|---|---|---|
| 2 | mid=1（3>2）→`right=0`；mid=0（1<2）→`left=1` | `left=1, right=0` | 1 |
| 5 | mid=1（3<5）→`left=2`；mid=2 命中 | 命中返回 | 2 |
| 7 | mid=1→`left=2`；mid=2（5<7）→`left=3`；mid=3（6<7）→`left=4` | `left=4, right=3` | 4 |

所以答案是 1、2、4。注意找 7 时 `left` 变成了 4，正好等于数组长度 —— 这就是"插到末尾"，天然正确。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `left, right = 0, len(nums) - 1` | 整个数组都是候选 |
| `while left <= right` | 区间里还有元素就继续 |
| `mid = (left + right) // 2` | 取中点 |
| `if nums[mid] == target: return mid` | 命中就直接交卷，这是唯一"提前返回"的分支 |
| `elif nums[mid] < target: left = mid + 1` | 中点太小，连同它左边一起砍掉 |
| `else: right = mid - 1` | 中点太大，连同它右边一起砍掉 |
| `return left` | 循环结束时 `left` 就是插入点，不用特判 |

### 考什么

- 表面考点：插入位置。
- 真正考点：**这是 lower_bound 的最简形态**，也是"返回 `left` 而不是 -1"这件事最好的入门例子。
- 面试官想听到的关键句："循环结束时 `left` 是第一个 `>= target` 的位置，而插入点按定义就是它。"

### 思路是怎么想出来的

**暴力**：从头扫，找到第一个 `>= target` 的位置就返回，O(n)。题目要 O(log n)。

**关键观察**：普通二分模板里，命中就 `return mid`；如果没命中，循环结束时 `left > right`。此时 `left` 是什么？所有 `< target` 的位置都被 `left = mid + 1` 跨过去了，所有 `> target` 的位置都被 `right = mid - 1` 压到左边。所以 `left` 恰好停在"第一个比 `target` 大的位置"上——也就是 `target` 该插的地方。

拿 `[1,3,5,6]` 找 2 走一遍：`mid=1`（3 > 2）→ `right=0`；`mid=0`（1 < 2）→ `left=1`；`left=1 > right=0` 退出，返回 1。下标 1 上是 3，把 2 插在它前面，正确。

**为什么不用单独处理"插到末尾"**：找 7 时 `left` 会一路推到 4，正好等于 `len(nums)`，插在末尾，天然正确。这也是为什么这题不需要任何特判。

### 代码（Python）

```python
from typing import List

class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1
        while left <= right:
            mid = (left + right) // 2
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1
        return left                          # 循环结束时 left 就是插入点
```

**逐段讲解**

- 前三行就是标准模板，一个字没改。这题的全部"新东西"在最后一行。
- `return left` 而不是 `return -1`：因为题目要的答案在"没找到"时依然存在，而 `left` 恰好指向它。
- 也可以写成 `while left < right` + `right = mid` 的边界版（就是本册「零」里那份 `lower_bound`），两者结果一样。**选一种写熟，别在考场临时换。**

### 复杂度

- 时间 O(log n)：每轮减半。
- 空间 O(1)。

### 常见误区（★ 最容易丢分的地方）

1. **`return right`**。`[1,3,5,6]` 找 2 返回 0（正确 1）；找 7 返回 3（正确 4）。差一位，而且"看起来很像对的"。
2. **找"第一个 `> target`"而不是"第一个 `>= target`"**。`[1,3,5,6]` 找 5 会返回 3（正确 2）——`target` 存在时，插入点应该是它自己的位置。
3. **`while left <= right` 里写 `right = mid`**。区间不缩小，直接死循环。
4. **单独加 `if target > nums[-1]: return len(nums)`**。逻辑上没错，但和二分里的 `left` 重复了，多一个分支多一个出错点。这题不需要任何特判。

### 面试追问 / 变体

- **一行版**：`import bisect; return bisect.bisect_left(nums, target)`。
- **最后一个 `<= target` 的位置**：`bisect_right(nums, target) - 1`。
- **数组有重复元素**：插入位置仍有定义（第一个 `>= target`），这份代码不用改；但"返回的下标"不再是 `target` 第一次出现的位置。
- **如果数组是降序的**：把三个分支的比较方向全反过来，或者先反转数组（O(n)，不划算）。

### 自测

- 必测用例：
  - `[1,3,5,6], 5` → 2（题面示例，命中）
  - `[1,3,5,6], 2` → 1（题面示例，插中间）
  - `[1,3,5,6], 7` → 4（题面示例，插末尾）
  - `[1,3,5,6], 0` → 0（插开头）
  - `[1], 1` → 0（单元素命中）
  - `[1], 2` → 1（单元素，插到它后面）
- 30 秒自检：能不能说出"为什么 `left` 就是插入点、为什么不需要特判末尾"？

## 专题11-4. 搜索旋转排序数组 II（Medium）

> 力扣 81 · 二分 · 重复元素让判据失效
> 前置：本册 11-1（先看无重复版本）

**一句话**：还是旋转过的数组，但这次允许重复值，问 `target` 在不在（返回 `True`/`False`）。

### 精讲（零基础版）

#### ① 这题要用到的东西

**链式比较 `a == b == c`**

一句话：Python 允许把比较连着写，`nums[left] == nums[mid] == nums[right]` 就是"左边等于中间，并且中间等于右边"。

```python
print(1 == 1 == 1)     # -> True
print(1 == 1 == 2)     # -> False
```

这题里用它判"三端同值"，这种情况下列据失效，得走特殊分支。

**"判据失效"是什么意思**

一句话：二分每一轮都要回答"答案在哪一半"。如果这个问题答不出来，二分就没法砍。

生活类比：猜数字时对方回答"我不告诉你"，那你就没法砍半，只能一个一个试。

这题里，三端同值时无法判断哪一半有序，只能把两端各扔掉一个。

**为什么可以扔掉两端**

一句话：第一个分支已经确认 `nums[mid] != target`，而 `nums[left]` 和 `nums[right]` 都等于 `nums[mid]`，所以它们也不是答案，扔掉不亏。

```python
nums = [1, 0, 1, 1, 1]
left, right = 0, 4
print(nums[left], nums[right])   # -> 1 1
left += 1
right -= 1
print(left, right)               # -> 1 3
```

这题里就是 `left += 1; right -= 1` 这两行，扔完重新判断。

**最坏 O(n)**

一句话：如果数组全是同一个值，每一轮都只能缩掉 2 个元素，总共 n/2 轮 —— 这就退化成了线性扫描。

**二分**（前面 11-1 讲过）：每轮砍掉一半的查找。这题还是那个模板，只是多了一个"判据失效时手动缩格"的补丁。

#### ② 大白话：这题到底在干什么

先看重复为什么坏。11-1 用"`nums[mid] >= nums[left]` 就认为左半有序"，靠的是左半的首尾能定序。有重复时这个依据就没了。

看 `[1,0,1,1,1]`：`mid` 指到中间那个 1，`nums[mid] >= nums[left]` 成立，代码认定"左半 `[1,0,1]` 有序" —— 可它中间明明掉到了 0。于是 `target = 0` 被当成"不在左半"，直接往右走，返回假。

笨在哪？**它相信了一个已经不成立的判断**。

聪明的办法：先检查"是不是三端同值"。如果是，说明这一轮什么信息都拿不到，但可以确认左右两端都不是答案（中间那个不是答案，而它们和中间同值），于是两端各扔掉一个，重新来。只要不是三端同值，就照 11-1 的办法走。

代价要说清：数组全是同一个值时，每轮只缩 2 个元素，最坏 O(n)。这不是代码写得笨，而是数据里根本没有"该往哪边砍"的信息。

#### ③ 拿 `[1,0,1,1,1]` 找 0 走一遍

| 轮 | left | right | mid | nums[mid] | 判断 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 4 | 2 | 1 | 三端都是 1，判据失效 | `left=1, right=3` |
| 2 | 1 | 3 | 2 | 1 | `1 != 0`；`nums[1]=0 <= 1` 左半有序；`0 <= 0 < 1` 成立 | `right = 1` |
| 3 | 1 | 1 | 1 | 0 | `nums[1] == 0`，命中 | 返回 `True` |

所以答案是 `True`。注意第 1 轮如果不缩格、直接按"左半有序"走，就会把下标 1 上的 0 排除掉，返回 `False`。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `if nums[mid] == target: return True` | **必须放在三端判断前面**，否则 `[1,1]` 找 1 会先被缩空 |
| `if nums[left] == nums[mid] == nums[right]` | 三端同值吗？这时候判断不出哪边有序 |
| `left += 1` | 左端扔掉一格，它和中间同值，不是答案 |
| `right -= 1` | 右端也扔掉一格 |
| `elif nums[left] <= nums[mid]` | 不是三端同值，那就能判断：左半有序吗？ |
| `if nums[left] <= target < nums[mid]` | 目标在左半的值域里 → 砍右半 |
| `else: left = mid + 1` | 不在左半 → 去右半 |
| `if nums[mid] < target <= nums[right]` | 右半有序时同理，看目标在不在右半的值域里 |
| `return False` | 区间空了还没命中 = 不存在 |

### 考什么

- 表面考点：33 的重复版本。
- 真正考点：**重复元素会破坏"必有一半有序"这个判据**，需要在判据失效时手动缩一格，代价是最坏 O(n)。
- 面试官想听到的关键句：
  - "`nums[left] == nums[mid] == nums[right]` 时，无法判断哪边有序，只能把两端各缩一格。"
  - "所以最坏是 O(n)（全相同数组），平均仍是 O(log n)。题面的进阶问题问的就是这一点。"

### 思路是怎么想出来的

**先看重复为什么坏**。33 用 `nums[mid] >= nums[left]` 判断左半有序，靠的是"左半的首尾能定序"。有重复时这个依据没了。看 `[1,0,1,1,1]`：`left=0, mid=2, right=4`，三个位置都是 1，`nums[mid] >= nums[left]` 成立，代码认定"左半 `[1,0,1]` 有序"——可它明明在中间掉到了 0。于是 `target = 0` 被当成"不在左半"，直接走右边，返回 `False`。

**关键观察**：判据失效只发生在**三端相等**这一种情况。而这时候可以安全地扔掉两端：

- `nums[mid] != target`（第一个分支已经检查过），所以 `nums[left] == nums[mid] != target`，左边那个 1 不是答案，扔掉不亏。
- `nums[right] == nums[mid] != target`，右边那个也不是，同样扔掉。

所以做法是 `left += 1; right -= 1`，然后重新判断。每缩一格区间少 2，最坏情况（全 1 的数组）退化成 O(n)。

**为什么这个代价躲不掉**：数组全是同一个值时，"下降点"在数据上完全不可见——任何基于比较的算法都拿不到"该往哪边砍"的信息。所以 O(n) 不是实现不够聪明，是这题的下界。

### 走一遍

`nums = [1,0,1,1,1]`，`target = 0`：

| 轮 | left | right | mid | nums[mid] | 判断 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 4 | 2 | 1 | 三端都是 1，判据失效 | `left=1, right=3` |
| 2 | 1 | 3 | 2 | 1 | `1 != 0`；`nums[1]=0 <= 1` 左半有序；`0 <= 0 < 1` 成立 | `right = 1` |
| 3 | 1 | 1 | 1 | 0 | 命中 | 返回 `True` |

第 1 轮如果不缩格，直接按"左半有序"走，就会把下标 1 上的 0 排除掉，返回 `False`。

### 代码（Python）

```python
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> bool:
        left, right = 0, len(nums) - 1
        while left <= right:
            mid = (left + right) // 2
            if nums[mid] == target:
                return True
            if nums[left] == nums[mid] == nums[right]:
                left += 1                    # 三端相同，分不清哪边有序
                right -= 1
            elif nums[left] <= nums[mid]:    # 左半边有序
                if nums[left] <= target < nums[mid]:
                    right = mid - 1
                else:
                    left = mid + 1
            else:                            # 右半边有序
                if nums[mid] < target <= nums[right]:
                    left = mid + 1
                else:
                    right = mid - 1
        return False
```

**逐段讲解**

- `if nums[mid] == target: return True` **必须放在三端判断之前**。放后面的话，`[1,1]` 找 1 会先走"三端相等"分支，把区间缩空，返回 `False`。这是这题最容易写反的一行。
- `nums[left] == nums[mid] == nums[right]`：Python 支持连等，等价于三个值两两相等。
- 后面两个分支和 33 完全一样，只是 `elif` 挂在三端判断后面。
- 三端相等时 `left` 和 `right` 同时动：只动一边也行，但慢一倍。

### 复杂度

- 时间：平均 O(log n)，**最坏 O(n)**（全相同数组每轮只缩 2 个元素）。
- 空间 O(1)。

### 常见误区（★ 最容易丢分的地方）

1. **直接套 33 的代码**。`[1,0,1,1,1]` 找 0 返回 `False`，正确 `True`。注意 `[2,5,6,0,0,1,2]` 找 0 却能返回 `True`——**示例能过不代表对**，这题必须自己造"三端相等"的用例。
2. **三端相等时直接 `return False`**。还是 `[1,0,1,1,1]` 找 0，返回 `False`。缩格不是放弃，是换一段继续找。
3. **把三端判断放在 `nums[mid] == target` 之前**。`[1,1]` 找 1 返回 `False`。
4. **宣称时间复杂度是 O(log n)**。题面进阶问题问的就是这个，答"是"会被追问到崩。正确说法是"平均 O(log n)，最坏 O(n)，因为重复值让判据失效"。
5. **判断有序用 `nums[left] < nums[mid]`**。和 33 一样，`[3,1]` 这类两元素用例会走反方向。

### 面试追问 / 变体

- **进阶问题怎么答**：允许重复会影响复杂度，最坏从 O(log n) 退化到 O(n)。原因是三端相等时无法判断哪一半有序，只能缩一格，而最坏情况下每轮都这样。
- **能不能保持 O(log n)**：不能。全相同数组里没有任何信息能定位"唯一的下降点"，这是信息论层面的下界。
- **如果重复元素很少**：实际运行接近 O(log n)，可以提一句"最坏和平均要分开说"。
- **和 33 的代码差异只有三行**：`return True/False`、三端判断、`if/elif` 的结构。面试时先说"这题是 33 加一个退化处理"，比从头讲更清楚。

### 自测

- 必测用例：
  - `[2,5,6,0,0,1,2], 0` → `True`（题面示例）
  - `[2,5,6,0,0,1,2], 3` → `False`（题面示例）
  - `[1,0,1,1,1], 0` → `True`（三端相等，专治"直接套 33"）
  - `[1,1,1,1], 2` → `False`（全相同，最坏情况）
  - `[3,1], 1` → `True`（两元素）
  - 20 个 1 中间夹一个 2（共 21 个元素），找 2 → `True`（力扣的经典刁难用例）
- 30 秒自检：能不能说出"什么时候判据失效、失效时为什么可以扔两端、为什么最坏是 O(n)"？

## 专题11-5. 寻找旋转排序数组中的最小值（Medium）

> 力扣 153 · 二分 · 和右端点比
> 前置：本册 11-1

**一句话**：升序数组旋转若干次（值互不相同），找出最小值，要求 O(log n)。

### 精讲（零基础版）

#### ① 这题要用到的东西

**"和端点比"的二分**

一句话：二分的比较对象不一定是 `target`，也可以是区间的一端。这题根本没有 `target`，改和右端点 `nums[right]` 比。

生活类比：蒙着眼找山谷最低点。你不用知道"最低点有多深"，只要摸出脚下这段是往下走还是往上走，就能判断该往哪边走。

```python
nums = [4, 5, 6, 7, 0, 1, 2]
left, right = 0, len(nums) - 1
while left < right:
    mid = (left + right) // 2
    if nums[mid] > nums[right]:     # 最小值在 mid 右边
        left = mid + 1
    else:                           # 最小值在 mid 或它左边
        right = mid
print(left, nums[left])             # -> 4 0
```

这题里 `nums[mid] > nums[right]` 说明 `mid` 还在"第一段"（数值大的那段），最小值一定在它右边。

**`right = mid` 和 `right = mid - 1` 的区别**

一句话：写 `mid - 1` 是"这个位置已经排除"；写 `mid` 是"这个位置还可能是答案"。

这题里 `mid` 自己可能就是最小值（比如 `[3,1,2]` 的 `mid` 正好指到 1），所以只能写 `right = mid`。

**为什么挑右端点当"代表"**

一句话：`nums[right]` 一定落在第二段上（除非整个区间只剩一段），而 `nums[left]` 可能在第一段、也可能在第二段 —— 它分不清自己在哪。

这题里选代表要选"位置固定"的那个，不是选"离得近"的那个。`[11,13,15,17]` 这种"转了一圈等于没转"的输入，就是和左端点比会翻车的地方。

**`while left < right`**

一句话：区间缩到只剩一个元素就停 —— 那个元素就是答案，不用再检查。

这题里如果写成 `<=` 又配 `right = mid`，`left == right` 时 `mid == left`，`right` 原地不动，就死循环了。

**二分**（前面 11-1 讲过）：每轮砍掉一半。这题砍的依据从"和 target 比"换成了"和右端点比"。

#### ② 大白话：这题到底在干什么

最笨的办法：`min(nums)` 直接扫一遍。O(n)，题目要 O(log n)。

笨在哪？**扫一遍完全没用上"数组是两段升序拼起来的"这个结构**。

聪明的办法：旋转后的数组是"两段升序"，第二段的第一个元素就是最小值。所以问题变成"找那个往下掉的地方"。

怎么找？盯着右端点。`nums[right]` 是当前区间最后一个元素，它一定落在第二段上（除非整个区间就一段）。如果 `nums[mid] > nums[right]`，说明从 `mid` 到 `right` 是往下掉的，`mid` 还在第一段，最小值在右边；否则说明 `mid` 已经在第二段，最小值只可能在 `mid` 或它左边。

注意不能和左端点比：左端点既可能在第一段也可能在第二段，它分不清自己在哪。`[11,13,15,17]`（转了一圈等于没转）就是反例，和左端点比会一路往右推，最后返回 15。

#### ③ 拿 `[4,5,6,7,0,1,2]` 走一遍

| 轮 | left | right | mid | nums[mid] | nums[right] | 判断 | 动作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 7 | 2 | `7 > 2` | `left = 4` |
| 2 | 4 | 6 | 5 | 1 | 2 | `1 <= 2` | `right = 5` |
| 3 | 4 | 5 | 4 | 0 | 1 | `0 <= 1` | `right = 4` |

`left == right == 4`，循环结束，所以答案是 `nums[4] = 0`。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `while left < right` | 缩到只剩一个元素就停，那个就是最小值 |
| `mid = (left + right) // 2` | 取中点，此时一定有 `mid < right` |
| `if nums[mid] > nums[right]` | 从 mid 到右端是往下掉的 → mid 还在第一段 |
| `left = mid + 1` | mid 右边还有更小的，mid 自己可以排除 |
| `else:` | 从 mid 到右端是升序的 → mid 已经在第二段 |
| `right = mid` | mid 可能就是最小值，**必须留着**，不能减 1 |
| `return nums[left]` | 结束时 `left == right`，返回那个位置的值 |

### 考什么

- 表面考点：找旋转点。
- 真正考点：**二分的比较对象可以不是 `target`，而是区间端点**。这题把"和 `target` 比"换成"和右端点比"。
- 面试官想听到的关键句：
  - "`nums[mid] > nums[right]` 说明最小值在 `mid` 右边；否则最小值在 `mid` 或它左边。"
  - "右边那一支要写 `right = mid` 而不是 `mid - 1`，因为 `mid` 自己可能就是最小值。"

### 思路是怎么想出来的

**暴力**：`min(nums)`，O(n)。题目要 O(log n)。

**关键观察**：旋转后的数组是"两段升序"，第二段的开头就是最小值。所以问题等价于**找那个下降点**。

**为什么和右端点比**：`nums[right]` 是当前区间的最后一个元素，它一定属于"第二段"（或者整个区间就是一段）。于是：

- `nums[mid] > nums[right]`：从 `mid` 到 `right` 是往下掉的，说明 `mid` 还在第一段，下降点在 `mid` 右边 → `left = mid + 1`。
- `nums[mid] < nums[right]`：从 `mid` 到 `right` 是升序的，说明 `mid` 已经在第二段，最小值只可能在 `mid` 或它左边 → `right = mid`。

**为什么不能和左端点比**：`nums[left]` 既可能是第一段的元素，也可能是第二段的元素，它**无法区分"我在哪一段"**。看 `[11,13,15,17]`（旋转了 n 次，等于没旋转）：`nums[mid]` 永远大于 `nums[left]`，代码会一路把 `left` 往右推，最后返回 15——而正确答案是 11。这就是"和左端点比"的经典翻车现场。

再补一层直觉：`nums[right]` 是当前区间最靠右的元素，它一定落在第二段上（除非区间里只剩一段），所以它天然是"第二段的代表"；而 `nums[left]` 没有这个保证——下降点可能就在它右边一个位置，也可能在很远的后面。**选代表要选"位置固定"的那个，不是选"离得近"的那个。**

**为什么 `right = mid` 而不是 `mid - 1`**：`nums[mid] < nums[right]` 时，`mid` 自己可能就是最小值（比如 `[3,1,2]` 的 `mid=1`）。用 `mid - 1` 会把它跳过。

**为什么循环用 `left < right`**：区间收敛到只剩一个元素就是答案，不需要再检查它。若用 `<=` 配 `right = mid`，`left == right` 时 `mid == left`，`right` 原地不动，死循环。

### 走一遍

`nums = [4,5,6,7,0,1,2]`：

| 轮 | left | right | mid | nums[mid] | nums[right] | 判断 | 动作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 7 | 2 | `7 > 2` | `left = 4` |
| 2 | 4 | 6 | 5 | 1 | 2 | `1 <= 2` | `right = 5` |
| 3 | 4 | 5 | 4 | 0 | 1 | `0 <= 1` | `right = 4` |

`left == right == 4`，返回 `nums[4] = 0`。

再看 `[2,1]`：`mid=0`，`nums[0]=2 > nums[1]=1`，`left=1`，返回 `nums[1]=1`。两元素的情况一步到位。

### 代码（Python）

```python
from typing import List

class Solution:
    def findMin(self, nums: List[int]) -> int:
        left, right = 0, len(nums) - 1
        while left < right:
            mid = (left + right) // 2
            if nums[mid] > nums[right]:      # 最小值在 mid 右边
                left = mid + 1
            else:                            # 最小值在 mid 或 mid 左边
                right = mid
        return nums[left]
```

**逐段讲解**

- `while left < right`：收敛到一个元素就停。**这题的区间是"答案一定在里面"的闭区间，所以不需要检查空区间。**
- `nums[mid] > nums[right]`：注意是严格大于。`nums[mid] == nums[right]` 在"值互不相同"的前提下不会发生（除非 `mid == right`，而 `mid < right` 恒成立）。
- `left = mid + 1`：`mid` 在第一段，不可能是最小值（它右边还有更小的），可以排除。
- `right = mid`：`mid` 可能是最小值，必须留着。
- `return nums[left]`：结束时 `left == right`，写 `nums[right]` 也对。

### 复杂度

- 时间 O(log n)：每轮区间减半。
- 空间 O(1)。

### 常见误区（★ 最容易丢分的地方）

1. **和左端点比**。`[11,13,15,17]` 返回 15（正确 11）；`[2,1]` 返回 2（正确 1）。这是这题最典型的错。
2. **`right = mid - 1`**。`mid` 可能就是最小值，减一会把它跳过。
3. **`while left <= right` 配 `right = mid`**。`left == right` 时 `mid == left`，`right` 原地不动，实测 2 秒都跑不完——死循环。
4. **`left = mid` 而不是 `mid + 1`**。区间长度 2 且 `nums[mid] > nums[right]` 时 `left` 不动，同样死循环。
5. **以为"旋转 0 次"不存在**。题面说旋转 1 到 n 次，n 次等于没旋转，所以 `[11,13,15,17]` 是合法输入，必须能处理。

### 面试追问 / 变体

- **允许重复（力扣 154）**：相等时无法判断，只能缩一格，最坏 O(n)。
- **返回最小值的下标**：就是"旋转了多少次"，代码只需把 `return nums[left]` 改成 `return left`。
- **找最大值**：和最小值对称，改成和 `nums[left]` 比（`nums[mid] > nums[left]` 时最大值在右）。
- **数组完全有序**：这题代码天然支持，会一路 `right = mid` 收到下标 0。
- **要求 O(1) 空间且不修改数组**：已经满足。

### 自测

- 必测用例：
  - `[3,4,5,1,2]` → 1（题面示例）
  - `[4,5,6,7,0,1,2]` → 0（题面示例）
  - `[11,13,15,17]` → 11（题面示例，没旋转，专治"和左端点比"）
  - `[1]` → 1（单元素）
  - `[2,1]` → 1（两元素）
  - `[3,1,2]` → 1（最小值在中间）
- 30 秒自检：能不能说出"为什么和右端点比、为什么 `right = mid`、为什么用 `<` 而不是 `<=`"？

## 专题11-6. 寻找旋转排序数组中的最小值 II（Hard）

> 力扣 154 · 二分 · 相等时只能缩一格
> 前置：本册 11-5（先看无重复版本）

**一句话**：153 的重复版本——旋转数组里可能有重复值，找最小值。

### 精讲（零基础版）

#### ① 这题要用到的东西

**相等时的退化处理**

一句话：`nums[mid] == nums[right]` 时，这两个位置是同一个值，而 `mid` 还留在区间里，所以把 `right` 扔掉不会丢掉最小值 —— 因为 `mid` 处还留着一份。

生活类比：两张一模一样的票，撕掉一张，你手里还有一张。

```python
nums = [10, 1, 10, 10, 10]
left, right = 0, len(nums) - 1
while left < right:
    mid = (left + right) // 2
    if nums[mid] > nums[right]:
        left = mid + 1
    elif nums[mid] < nums[right]:
        right = mid
    else:
        right -= 1          # 相等：只扔右端一格
print(nums[left])           # -> 1
```

这题里就是最后那个 `else: right -= 1`。注意它不能写成 `right = mid - 1`，那会一次跳过多格，把最小值直接排除掉。

**为什么只能一格一格扔**

一句话：相等时"哪边都可能是答案"，多扔就可能把答案扔出去。

```python
nums = [2, 2, 1, 2]

# 错法：相等时写 right = mid（看起来"把候选留着更保险"）
left, right = 0, len(nums) - 1
while left < right:
    mid = (left + right) // 2
    if nums[mid] > nums[right]:
        left = mid + 1
    else:
        right = mid
print(nums[left])      # -> 2   （错，正确答案是 1）
```

`mid` 和 `right` 都是 2，可最小值 1 偏偏在 `mid` 右边，把区间收到 `[0,1]` 就把它关在门外了。

**"平均"和"最坏"要分开说**

一句话：平均复杂度是"随机数据下的典型情况"，最坏复杂度是"专门造数据整你时的上限"。面试被问复杂度，两个都要报。

这题里：平均 O(log n)，最坏 O(n)（全相同数组每轮只缩一格）。

**为什么平均还是 O(log n)**

一句话：只有 `nums[mid] == nums[right]` 才缩一格，而这个条件要求两个位置恰好同值。随机数据里它很少连续成立，均摊下来仍接近 log n。

这题里把"平均"和"最坏"分开说，是最容易被加分的细节。

**为什么不像 11-4 那样判"三端相等"**

一句话：11-4 要判断"哪一半有序"，所以得看三个端点；这题只判断"最小值在哪边"，看 `mid` 和 `right` 两端就够了。

所以这题的失效条件比 11-4 窄：只有 `nums[mid] == nums[right]` 时才失效，不必三端都相等。

**二分**（前面 11-1 讲过）：每轮砍掉一半。这题砍不动的时候只能缩一格。

**判据失效导致退化**（前面 11-4 讲过）：重复值让"必有一半有序"这个判断失去依据。区别在于 154 的失效条件更窄 —— 只要 `mid` 和 `right` 同值就失效，不必三端都相等。

#### ② 大白话：这题到底在干什么

为什么不能照抄 11-5：11-5 的 `else` 分支（`right = mid`）建立在"`nums[mid] < nums[right]`"这个前提上。相等时前提没了，`right = mid` 就变成瞎猜。

看 `[3,3,1,3]`：`mid` 指到下标 1 的 3，`nums[right]` 也是 3，走 `else` 把区间收成 `[0,1]`，最小值 1 直接被关在门外。

笨在哪？**它在"两个数一样大"的时候硬做了一个方向选择**。

聪明的办法：相等时承认"这一轮判不出来"，但注意 `mid` 和 `right` 是同一个值，而且 `mid` 还在区间里 —— 所以把 `right` 扔掉是安全的，最小值如果就在右边，`mid` 那儿还留着一份同样的值。于是 `right -= 1`，缩一格，重来。

为什么缩右边而不是缩左边：实测 `[10,1,10,10,10]` 缩左边会把下标 1 上的 1 扔掉，最后返回 10；缩右边才正确。

还要记住相等时不能直接 `return nums[mid]`：相等只说明这个值出现了至少两次，不说明它是全局最小。`[3,3,1,3]` 里两个 3 相等，可最小值是 1。

代价：全相同数组里每轮只缩一格，最坏 O(n)。这是数据层面的信息缺失，换写法绕不过去 —— 先去重本身就要 O(n)。

再补一句：也不能一次缩两格、三格。缩格的前提是"被扔掉的一定不是答案"，而相等时你只能保证"扔一个不亏"，多扔就可能丢答案。

#### ③ 拿 `[10,1,10,10,10]` 走一遍

| 轮 | left | right | mid | nums[mid] | nums[right] | 判断 | 动作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 4 | 2 | 10 | 10 | 相等 | `right = 3` |
| 2 | 0 | 3 | 1 | 1 | 10 | `1 < 10` | `right = 1` |
| 3 | 0 | 1 | 0 | 10 | 1 | `10 > 1` | `left = 1` |

`left == right == 1`，循环结束，所以答案是 `nums[1] = 1`。

注意第 1 轮只缩了一格，第 2 轮就砍掉了一半 —— 退化只发生在"相等"的那些轮里，不是整趟都慢。

顺带看一个反例 `[2,2,2,0,1]`：`mid` 和右端点一路都不同值，一次"缩一格"都没走 —— 重复值多不等于一定慢，只有 `mid` 和 `right` 同值时才退化。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `while left < right` | 缩到一个元素就停，那个就是最小值 |
| `if nums[mid] > nums[right]` | 和 153 一字不差：mid 在第一段，最小值在右边 |
| `left = mid + 1` | mid 右边还有更小的，mid 排除 |
| `elif nums[mid] < nums[right]` | mid 已经在第二段，最小值在 mid 或它左边 |
| `right = mid` | mid 可能是最小值，留着 |
| `else:` | 剩下的情况就是相等（前两支已经把 `>` 和 `<` 拿走了） |
| `right -= 1` | 相等：只扔右端一格。**不能写成什么都不做**，否则死循环 |
| `return nums[left]` | 结束时 `left == right`，返回那个位置的值 |

### 考什么

- 表面考点：带重复的旋转数组求最小。
- 真正考点：**相等时判据失效，只能缩一格；这会把 O(log n) 变成最坏 O(n)**。它和 81 是同一个道理的两次出现。
- 面试官想听到的关键句：
  - "`nums[mid] > nums[right]` 往右，`<` 往左（`right = mid`），`==` 时 `right -= 1`。"
  - "相等时扔 `nums[right]` 是安全的：`nums[mid]` 和它同值，且 `mid` 还在区间里。"

### 思路是怎么想出来的

**为什么不能照抄 153**：153 的 `else` 分支（`right = mid`）建立在"`nums[mid] < nums[right]`"上。相等时这个前提没了。看 `[3,3,1,3]`：`mid=1`，`nums[1] = 3`，`nums[3] = 3`，走 `else` 得 `right = 1`，区间缩成 `[0,1]`，最小值 1 被排除，最后返回 3。

**关键观察**：`nums[mid] == nums[right]` 时，这两个位置是同一个值。而 `nums[mid]` 还在区间里，所以**把 `right` 扔掉不会丢掉最小值**——如果最小值恰好是这个值，`mid` 处还留着一份。

**为什么缩右边而不是缩左边**：两者都能保证不丢答案，但缩左边在某些用例上会把最小值排除。实测 `[10,1,10,10,10]`：用 `left += 1` 会一路把下标 1 上的 1 扔掉，最后返回 10；用 `right -= 1` 则正确返回 1。**缩右边更稳，因为 `nums[right]` 是"已经被 `mid` 备份过"的那个值。**

**为什么最坏是 O(n)**：全相同的数组里，每一轮都走"缩一格"分支，区间一次只少 1 个元素，总共 n 轮。这不是实现问题——数组在数据上看起来完全有序，任何比较都无法定位下降点。

**那能不能先去重、再套 153**：不能改善复杂度。去重本身就要扫一遍数组（O(n)），除非数组已经有序——而它恰好不有序。这条路还额外花了 O(n) 空间，最后仍然是 O(n)。**重复元素的代价是信息层面的，不是实现层面的**，换写法绕不过去。

**为什么不用像 81 那样判"三端相等"**：因为 154 不需要判断"哪一半有序"，只需要判断"最小值在哪边"，看 `mid` 和 `right` 两端就够了。所以这题的失效条件比 81 窄：只有 `nums[mid] == nums[right]` 时才失效，不必三端都相等。

**顺带说一句难度**：153 和 154 的代码只差一个分支，难度却差一档。差的不在代码量，在"意识到判据会失效"和"能说清退化的代价"。面试里这题常被用来区分"背过模板"和"真的理解二分"——后者会主动补一句"最坏 O(n)"。

### 走一遍

`nums = [10,1,10,10,10]`：

| 轮 | left | right | mid | nums[mid] | nums[right] | 判断 | 动作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 4 | 2 | 10 | 10 | 相等 | `right = 3` |
| 2 | 0 | 3 | 1 | 1 | 10 | `1 < 10` | `right = 1` |
| 3 | 0 | 1 | 0 | 10 | 1 | `10 > 1` | `left = 1` |

`left == right == 1`，返回 `nums[1] = 1`。

再看 `[3,3,1,3]`：第 1 轮 `mid=1`，`nums[1]=3 == nums[3]=3`，`right=2`；第 2 轮 `mid=1`，`nums[1]=3 > nums[2]=1`，`left=2`；收敛到下标 2，返回 1。

再看 `[2,2,2,0,1]`：`mid=2`，`nums[2]=2 > nums[4]=1`，`left=3`；`mid=3`，`nums[3]=0 < nums[4]=1`，`right=3`；收敛到下标 3，返回 0。这一路一次都没走"缩一格"分支——**只有 `mid` 和 `right` 同值时才退化**，重复值多不等于一定慢。

### 代码（Python）

```python
from typing import List

class Solution:
    def findMin(self, nums: List[int]) -> int:
        left, right = 0, len(nums) - 1
        while left < right:
            mid = (left + right) // 2
            if nums[mid] > nums[right]:
                left = mid + 1
            elif nums[mid] < nums[right]:
                right = mid
            else:
                right -= 1                   # 相等：缩一格，丢掉的一定不是唯一最小
        return nums[left]
```

**逐段讲解**

- 前两个分支和 153 一字不差。
- `else: right -= 1`：注意 `else` 在这里等价于 `nums[mid] == nums[right]`（因为前两个分支已经把 `>` 和 `<` 拿走了）。**这个 `else` 不能写成"什么都不做"**，否则区间不缩小，死循环。
- `right -= 1` 而不是 `left += 1`：见上面的实测对比。
- `while left < right`：和 153 一样，收敛到一个元素即答案。
- 循环结束时 `nums[left]` 就是最小值。注意这里不能像 153 那样断言"`nums[mid] == nums[right]` 不会发生"——这正是这题存在的理由。

### 复杂度

- 时间：平均 O(log n)，**最坏 O(n)**（全相同数组）。
- 空间 O(1)。

**为什么平均还是 O(log n)**：只有 `nums[mid] == nums[right]` 才会缩一格，而这个条件要求两个位置恰好同值。随机数据里它很少连续成立，所以均摊下来仍接近 log n。面试时把"平均"和"最坏"分开说，是这题最容易被加分的细节。

### 常见误区（★ 最容易丢分的地方）

1. **直接套 153 的代码**。`[3,3,1,3]` 返回 3（正确 1）。
2. **相等时 `left += 1`**。`[10,1,10,10,10]` 返回 10（正确 1）。看起来对称，实际会把最小值扔掉。
3. **相等时 `return nums[mid]`**。`[3,3,1,3]` 返回 3。相等只说明"这个值出现了至少两次"，不说明它是全局最小。
4. **宣称 O(log n)**。题面进阶问题问的就是这个。正确说法：平均 O(log n)，最坏 O(n)，因为重复值让"砍一半"失去依据。
5. **相等时 `right -= 1` 写成 `right = mid - 1`**。会一次跳过多格，`[3,3,1,3]` 第 1 轮就从 `right=3` 跳到 `right=0`，把下标 2 上的 1 排除。
6. **相等时 `right = mid`**（看起来"把候选留着更保险"）。`[2,2,1,2]` 会返回 2，正确 1：`mid=1` 和 `right=3` 都是 2，可最小值 1 偏偏在 `mid` **右边**，把区间收到 `[0,1]` 就把它关在门外了。**相等时"哪边都可能是答案"，所以只能一格一格地扔。**

### 面试追问 / 变体

- **进阶问题怎么答**：允许重复会影响复杂度，最坏 O(n)。全相同数组里每轮只缩一格，任何基于比较的算法都做不到更好。
- **和 81 的关系**：81 处理的是"三端相等"，154 处理的是"`mid` 与 `right` 相等"。两者本质相同：**判据失效时手动缩小范围，代价是复杂度退化。**
- **如果重复元素很少**：实际运行接近 O(log n)。
- **如果要求"返回第一个出现的位置"**：这题做不到 O(log n)——缩格时你无法知道被扔掉的那一侧有没有更靠前的最小值，只能退化成 O(n) 扫。
- **能不能一次缩两格、三格**：不能。缩格的前提是"被扔掉的一定不是答案"，而相等时你只能保证"扔一个不亏"，多扔就可能丢答案。**一次一格，是这里唯一安全的速度。**
- **如果要返回下标（旋转次数）**：`return left`。注意 154 里 `left` 停在的位置就是最小值的某个出现位置，重复时可能不是第一个。

### 自测

- 必测用例：
  - `[1,3,5]` → 1（题面示例）
  - `[2,2,2,0,1]` → 0（题面示例）
  - `[3,3,1,3]` → 1（重复值把最小值夹住，专治"直接套 153"）
  - `[10,1,10,10,10]` → 1（专治"相等时缩左边"）
  - `[2,2,1,2]` → 1（最小值在 `mid` 右边，专治"相等时 `right = mid`"）
  - `[1,1]` → 1（全相同，最坏情况）
  - `[1]` → 1（单元素）
- 30 秒自检：能不能说出"相等时为什么可以扔 `right`、为什么缩右边不缩左边、为什么最坏是 O(n)"？

## 专题11-7. 寻找峰值（Medium）

> 力扣 162 · 二分 · 判据是"斜率"
> 前置：本册 11-5（同样是"和邻居比"）

**一句话**：数组相邻元素不相等，找一个"比左右都大"的元素的下标（边界外当作 -∞），多个峰任选一个。

### 精讲（零基础版）

#### ① 这题要用到的东西

**"斜率"判据**

一句话：不看具体数值，只看"往上走还是往下走"。`nums[mid] < nums[mid + 1]` 就是上坡。

生活类比：蒙着眼爬山，你只要摸出脚下是上坡还是下坡，一直往上走总能走到一个山顶。

关键是"上坡/下坡"这个判断随位置是单调的，二分才成立。

```python
nums = [1, 2, 1, 3, 5, 6, 4]
left, right = 0, len(nums) - 1
while left < right:
    mid = (left + right) // 2
    if nums[mid] < nums[mid + 1]:    # 在爬坡，峰在右边
        left = mid + 1
    else:                            # 在下坡，峰在 mid 或左边
        right = mid
print(left)                          # -> 5
```

`nums[5] = 6` 确实是峰。这题里上坡就往右走，下坡就往左走（并且保留 `mid`）。

**`nums[mid + 1]` 为什么不会越界**

一句话：循环条件是 `left < right`，所以 `mid` 一定小于 `right`，`mid + 1` 最多等于 `right`，还在数组里。

这题里如果写成 `left <= right`，`mid` 可能等于 `right`，`nums[mid + 1]` 就出去了，直接报 `IndexError`。

**循环不变量（这题版）**

一句话：每一轮开始时"当前区间里一定至少有一个峰"。

为什么够用：初始时整个数组满足（边界外是负无穷，所以从最左往上爬一定能爬到峰）；每次收缩都保留"有峰"的那一半；区间缩到一个点时，那个点必然是峰。所以只比较右边邻居就够了，不用看左边。

**二分**（前面 11-1 讲过）：每轮砍掉一半。这题连"数组有序"都不需要，只需要判据单调。

#### ② 大白话：这题到底在干什么

最笨的办法：从头扫，找第一个"比左右都大"的位置。O(n)，题目要 O(log n)。

笨在哪？**扫一遍没有利用"坡的方向"这个信息**。

聪明的办法：把数组想成一条折线，两端各接一个负无穷。站在 `mid` 上摸一下右边：如果右边比它高，说明在爬坡 —— 而坡爬到头必然是一个峰（要么某处开始下坡，那就是峰；要么一直爬到最右端，右端外是负无穷，那也是峰）。所以峰一定在右边，左半边整段可以扔掉。

如果右边不比它高，说明 `mid` 已经在往下走或者到了顶，那么峰一定在 `mid` 或它左边。注意这里必须保留 `mid`，因为 `mid` 自己可能就是峰。

一路缩到只剩一个点，那个点就是峰。题目说返回任意一个峰即可，所以不用找最高的。

题面保证相邻元素不相等，这一条很关键：如果有平坡，"往哪走"就没有依据，二分可能来回横跳。

#### ③ 拿 `[1,2,1,3,5,6,4]` 走一遍

| 轮 | left | right | mid | nums[mid] | nums[mid+1] | 判断 | 动作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 3 | 5 | 上坡 | `left = 4` |
| 2 | 4 | 6 | 5 | 6 | 4 | 下坡 | `right = 5` |
| 3 | 4 | 5 | 4 | 5 | 6 | 上坡 | `left = 5` |

`left == right == 5`，循环结束，所以答案是下标 5（`nums[5] = 6`）。注意下标 1 上的 2 也是峰，题目说返回任意一个即可。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `while left < right` | 缩到一个点就停，那个点就是峰 |
| `mid = (left + right) // 2` | 取中点；此时 `mid < right`，所以 `mid + 1` 安全 |
| `if nums[mid] < nums[mid + 1]` | 右边比它高 = 在爬坡 |
| `left = mid + 1` | 坡爬到头才是峰，所以 `mid` 自己不是，可以排除 |
| `else: right = mid` | 右边比它低 = 在下坡，`mid` 可能就是峰，必须留着 |
| `return left` | 题目要的是下标，不是值 |

### 考什么

- 表面考点：找峰值。
- 真正考点：**二分不要求数组有序，只要求"判据单调"**。这题既没有 `target` 也没有序，只有"往上走还是往下走"。
- 面试官想听到的关键句：
  - "`nums[mid] < nums[mid+1]` 说明在爬坡，右边一定有峰；否则 `mid` 或左边一定有峰。"
  - "边界外是 -∞，所以上坡走到头必然是峰——这个'头'要么是数组末尾，要么是个真正的峰。"

### 思路是怎么想出来的

**暴力**：扫一遍找第一个满足 `nums[i] > nums[i-1]` 且 `nums[i] > nums[i+1]` 的位置，O(n)。题目要 O(log n)。

**关键观察（这题的核心）**：把数组看成一条折线，两端各接一个 -∞。如果从 `mid` 往右是上坡（`nums[mid] < nums[mid+1]`），那么"沿着上坡一直走"最终一定会停在一个峰上：要么在某个位置开始下坡（那就是峰），要么一直走到最右端（而右端外是 -∞，所以最右端就是峰）。**上坡的尽头一定是峰**，所以右边一定有峰，左边整段可以扔掉。

反过来，`nums[mid] >= nums[mid+1]`（下坡或平）时，`mid` 自己可能就是峰，左边（含 `mid`）一定有一个峰 → `right = mid`。

**为什么不用检查 `nums[mid-1]`**：因为我们在维护一个不变量——"**当前区间 `[left, right]` 里一定存在至少一个峰**"。初始时整个数组满足（边界是 -∞）；每次收缩都保留"有峰"的那一半；区间缩到一个点时，那个点必然是峰。这就是为什么代码里只比较右边邻居就够。

**为什么需要"相邻不相等"**：题面保证 `nums[i] != nums[i+1]`。如果没有这个条件，平坡上"往哪走"就没有依据，二分可能来回横跳。

### 走一遍

`nums = [1,2,1,3,5,6,4]`：

| 轮 | left | right | mid | nums[mid] | nums[mid+1] | 判断 | 动作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 3 | 5 | 上坡 | `left = 4` |
| 2 | 4 | 6 | 5 | 6 | 4 | 下坡 | `right = 5` |
| 3 | 4 | 5 | 4 | 5 | 6 | 上坡 | `left = 5` |

`left == right == 5`，返回 5，`nums[5] = 6` 确实是峰。注意下标 1 上的 2 也是峰，题目说返回任意一个即可。

### 代码（Python）

```python
from typing import List

class Solution:
    def findPeakElement(self, nums: List[int]) -> int:
        left, right = 0, len(nums) - 1
        while left < right:
            mid = (left + right) // 2
            if nums[mid] < nums[mid + 1]:    # 在爬坡，峰值在右边
                left = mid + 1
            else:                            # 在下坡，峰值在 mid 或左边
                right = mid
        return left
```

**逐段讲解**

- `while left < right`：区间缩到一个点就停，那个点就是峰。
- `nums[mid + 1]`：因为 `mid < right`，`mid + 1` 一定不越界。**这就是为什么循环条件必须是 `<` 而不是 `<=`**——用 `<=` 时 `mid` 可能等于 `right`，`nums[mid+1]` 直接越界。
- `left = mid + 1`：`mid` 在上坡，不可能是峰（右边比它大），排除。
- `right = mid`：`mid` 可能是峰（它比右边大），必须留着。
- `return left`：题目要下标，不是值。

### 复杂度

- 时间 O(log n)：每轮减半。
- 空间 O(1)。

### 常见误区（★ 最容易丢分的地方）

1. **`right = mid - 1`**。`mid` 可能是峰，减一会跳过它。`[1,2,1]` 会返回 0，而 `nums[0]=1` 不是峰（右边 2 比它大）。
2. **方向写反**（`nums[mid] > nums[mid+1]` 时 `left = mid + 1`）。`[1,2,3,1]` 返回 0，`nums[0]=1` 不是峰；正确是 2。
3. **`while left <= right` 配 `right = mid`**。死循环。
4. **`while left <= right` 配 `nums[mid+1]`**。`mid` 可能等于 `right`，越界 `IndexError`。
5. **返回 `nums[left]` 而不是 `left`**。题目要下标。
6. **试图找"最高的峰"**。二分只保证"某一个峰"，找最高的要 O(n)。这题的题面写得很清楚：返回任何一个。

### 面试追问 / 变体

- **二维峰值（力扣 1901）**：先二分列，取该列最大值，再和左右邻居比，决定往哪半走。判据从"斜率"变成"列最大值的方向"。
- **找出所有峰**：O(n) 扫一遍，`nums[i] > nums[i-1] and nums[i] > nums[i+1]`。
- **找最高的峰**：O(n)，二分给不出这个信息。
- **允许相等（`nums[i] == nums[i+1]`）**：判据失效，平坡上可能来回横跳，通常退化成 O(n)。
- **如果数组首尾相连成环**：峰值定义变了（每个点都有左右邻居），二分的边界假设（-∞）不成立。

### 自测

- 必测用例：
  - `[1,2,3,1]` → 2（题面示例）
  - `[1,2,1,3,5,6,4]` → 1 或 5（题面示例，多峰）
  - `[1]` → 0（单元素，边界外是 -∞，它自己就是峰）
  - `[2,1]` → 0（严格递减，第一个就是峰）
  - `[1,2]` → 1（严格递增，最后一个是峰）
  - `[3,2,1]` → 0（严格递减）
- 30 秒自检：能不能说出"为什么上坡尽头一定有峰、为什么只比右边邻居就够、为什么用 `<` 而不是 `<=`"？

## 专题11-8. 分割数组的最大值（Hard）

> 力扣 410 · 二分答案 · 最小化最大值
> 前置：本册「零」+ 11-3（lower_bound 的"找第一个满足条件"）

**一句话**：把非负数组切成 `k` 段连续子数组，让"各段和的最大值"尽可能小，返回这个最小值。

### 精讲（零基础版）

#### ① 这题要用到的东西

**二分答案**

一句话：二分的对象不是数组下标，而是"答案本身"。你先猜一个答案，写个函数验证它行不行，再根据行/不行砍掉一半。

生活类比：猜一个箱子的重量。你不用直接算出它多重，只要有一台秤能告诉你"比 50 公斤重还是轻"，你就能一路二分逼近。

```python
nums = [7, 2, 5, 10, 8]
k = 2

def can_split(limit):        # 每段和都不超过 limit 时，能否切成 <= k 段
    pieces = 1
    current = 0
    for x in nums:
        if current + x > limit:
            pieces += 1
            current = x
            if pieces > k:
                return False
        else:
            current += x
    return True

print(can_split(15))    # -> False
print(can_split(18))    # -> True
print(can_split(21))    # -> True
```

这题里"答案"是"各段和的最大值"，验证函数是"每段和不超过 `limit` 时，能否切成 ≤ k 段"。

**单调性**

一句话：`limit` 越大越容易切成功。所以"行不行"的答案排出来一定是"不行不行…行行行"，中间只有一个翻转点。

生活类比：考试分数线。分数越高越容易过，所以"过没过"随分数是单调的。

这题要的就是那个"从不行翻到行"的最小 `limit`，形状和 11-3 的 lower_bound 一模一样。

**判定问题 vs 优化问题**

一句话："求最优"叫优化问题，"给个候选、问行不行"叫判定问题，判定通常好写得多。

生活类比：让你"说出这堆石头里最重的那块"很难，让你"看这块石头是不是最重的"就容易多了。

这题里正是把"怎么切最优"换成了"这个 `limit` 行不行"，而验证只要从左往右扫一遍数组。

**函数里再定义函数**（前面 11-2 讲过）：内层函数直接读外层的 `nums` 和 `k`，不用当参数传。

**贪心**（前面 10-1 讲过）：每步选当前最好的。这里"当前最好"= 能装多少装多少，装不下才切一刀。

#### ② 大白话：这题到底在干什么

最笨的办法：枚举所有切法，取"最大段和"最小的那个。切法数量是指数级的，n = 1000 时完全不可能。

用动态规划能降到 O(n²k)：`dp[i][j]` 表示"前 i 个数分成 j 段的最小最大和"，但写起来长、容易错。

笨在哪？**它一直在"直接构造最优解"这条路上硬走**。

聪明的办法：换个问法 —— 不问"怎么切最好"，改问"如果要求每段和都不超过 `limit`，最少要切几段？"这个问题特别好答：从左往右装，装不下就切一刀，一段一段数下来就行。

而且这个"段数"随 `limit` 变大只会变小：`limit` 大，每段能装更多，段数更少。于是"能否切成 ≤ k 段"的答案一定是"先一串不行，再一串行"。这正是二分要找的形状 —— 找第一个"行"的 `limit`。

范围也现成：下界是 `max(nums)`（某个元素单独成段时，这段和就是它，`limit` 不能比它小），上界是 `sum(nums)`（一整段不切，一定可行）。

顺便说清一个常见的错误直觉：这题不是"凑数"题，不能均匀切。`[7,2,5,10,8]` 总和 32、`k=2`，均匀切是每段 16，可 10 和 8 是相邻的，必须待在同一段，`10+8=18 > 16`，切不出来。"连续"这个约束让"平均值"失去意义 —— 你只能顺着数组往下走，不能任意分配元素。

这正是"判定比优化简单"的好处：想不出怎么直接构造最优解时，先问自己"给我一个候选答案，我能快速验证吗"。

#### ③ 拿 `[7,2,5,10,8], k=2` 走一遍

初始 `left = max(nums) = 10`，`right = sum(nums) = 32`：

| 轮 | left | right | mid | check(mid) | 说明 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 10 | 32 | 21 | `True` | 切成 `[7,2,5]` 和 `[10,8]`，2 段 | `right = 21` |
| 2 | 10 | 21 | 15 | `False` | `7+2+5=14`，再加 10 就超；`10+8=18` 也超，要 3 段 | `left = 16` |
| 3 | 16 | 21 | 18 | `True` | `[7,2,5]` 和 `[10,8]`，2 段 | `right = 18` |
| 4 | 16 | 18 | 17 | `False` | `10+8=18 > 17`，要 3 段 | `left = 18` |

`left == right == 18`，所以答案是 18。

两个边界可以用来自检：`k = 1` 时答案是 `sum(nums)`，`k = n` 时答案是 `max(nums)`。

#### ④ 代码逐行对译

| 代码 | 大白话 |
|---|---|
| `pieces = 1` | 初值 1 不是 0：至少有一段，第一段从第一个元素开始 |
| `current = 0` | 当前这一段已经装了多少 |
| `if current + x > limit` | 装不下了才另起一段。**严格大于**，正好等于 `limit` 是装得下的 |
| `pieces += 1` | 多切一刀，段数 +1 |
| `current = x` | 新的一段从当前元素开始 |
| `if pieces > k: return False` | 超过 k 段就失败。**`> k` 不是 `>= k`**，正好 k 段是合法的 |
| `left, right = max(nums), sum(nums)` | 答案的搜索范围：下界最大单元素，上界整段不切 |
| `if can_split(mid): right = mid` | 可行 → 答案 ≤ mid，`mid` 自己也要留着 |
| `else: left = mid + 1` | 不可行 → 答案严格更大，`mid` 排除 |
| `return left` | 收敛后就是最小的可行 `limit` |

### 考什么

- 表面考点：分割数组。
- 真正考点：**二分答案**——二分的对象不是数组下标，而是"答案本身"。这是二分里最难的题型，因为你要自己证明"答案可以二分"。
- 面试官想听到的关键句：
  - "猜一个上限 `limit`，写 `check(limit)` 判断'每段和不超过 `limit` 时，能否切成 ≤ k 段'。"
  - "`check` 关于 `limit` 单调：`limit` 越大越容易成立。所以答案是那个'从 false 翻到 true'的分界点。"
  - "搜索范围是 `[max(nums), sum(nums)]`：下界是最大单个元素，上界是一整段。"

### 思路是怎么想出来的

**暴力/DP**：`dp[i][j]` = 前 `i` 个数分 `j` 段的最小最大和，转移要枚举最后一段的起点，O(n²k)。n=1000、k=50 时约 5×10⁷，勉强能过，但写起来长、容易错。

**关键观察一：换个问法。** 不问"怎么切最优"，改问"**如果要求每段和都不超过 `limit`，最少要切几段？**"这个问题非常好答：从左往右装，装不下就切一刀。这个贪心就是最优的——因为任何提前切分只会让段数变多（每次提前切，后面就多出一段来）。

**关键观察二：段数关于 `limit` 单调不增。** `limit` 越大，每段能装越多，需要的段数越少。于是"能否切成 ≤ k 段"也是单调的：`limit` 小 → 段数多 → 可能 > k → `False`；`limit` 大 → 段数少 → `True`。形状是 `False...False, True...True`，**这正是 lower_bound 的形状**：找第一个 `True`。

**关键观察三：答案的范围。** 下界 `max(nums)`：某个元素单独成段时，这段的和就是它，所以 `limit` 不能比它小。上界 `sum(nums)`：整段不切。答案一定在这个闭区间里。

**为什么 `check` 里的贪心是对的**：要让段数最少，每段就应该"能装多少装多少"。设某个切法在第 `i` 个元素处提前切了，而贪心会把它并进当前段——贪心的当前段和更大，但不超过 `limit`（否则它也会切），所以贪心的段数不会更多。逐段替换即可。

**为什么不能"均匀切"**：`[7,2,5,10,8]` 总和 32、`k=2`，均匀切是每段 16，可 `10` 和 `8` 是相邻的，它们必须待在同一段，`10+8=18 > 16`，切不出来。**"连续"这个约束让"平均值"失去意义**——你只能顺着数组往下走，不能任意分配元素。这也解释了为什么这题不是"凑数"题，而是"切点"题。

**二分写法**：`while left < right` + `right = mid`（`mid` 可能就是答案，不能 `mid - 1`）+ `left = mid + 1`（`mid` 不可行，答案严格更大）。这就是本册「零」里那份 `lower_bound` 的骨架。

### 走一遍

`nums = [7,2,5,10,8]`，`k = 2`，初始 `left = 10`（最大值），`right = 32`（总和）：

| 轮 | left | right | mid | check(mid) | 说明 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 10 | 32 | 21 | `True` | 切成 `[7,2,5]`+`[10,8]`，2 段 | `right = 21` |
| 2 | 10 | 21 | 15 | `False` | `7+2+5=14`，`+10` 超了；`10+8=18` 也超，要 3 段 | `left = 16` |
| 3 | 16 | 21 | 18 | `True` | `[7,2,5]`+`[10,8]`，2 段 | `right = 18` |
| 4 | 16 | 18 | 17 | `False` | `10+8=18 > 17`，要 3 段 | `left = 18` |

`left == right == 18`，返回 18，和题面一致。

### 代码（Python）

```python
from typing import List

class Solution:
    def splitArray(self, nums: List[int], k: int) -> int:
        def can_split(limit: int) -> bool:
            """每段和都不超过 limit 时，能否切成 <= k 段。"""
            pieces = 1
            current = 0
            for x in nums:
                if current + x > limit:      # 装不下了，另起一段
                    pieces += 1
                    current = x
                    if pieces > k:
                        return False
                else:
                    current += x
            return True

        left, right = max(nums), sum(nums)   # 答案的搜索范围
        while left < right:
            mid = (left + right) // 2
            if can_split(mid):
                right = mid                  # mid 可行，答案 <= mid
            else:
                left = mid + 1               # mid 不可行，答案 > mid
        return left
```

**逐段讲解**

- `pieces = 1` 不是 0：至少有一段，第一段从第一个元素开始。
- `if current + x > limit`：**严格大于**。等于 `limit` 时是装得下的，不该切。这个符号错了，答案会偏大。
- `if pieces > k: return False`：**`> k` 不是 `>= k`**。`pieces == k` 时还没超，可以继续；写成 `>= k` 会在恰好 k 段时提前判死。
- `current = x`：新的一段从当前元素开始。
- `left, right = max(nums), sum(nums)`：下界必须是 `max(nums)`，否则 `check` 在"单个元素就超限"时无解；上界是总和，一定可行。
- `right = mid` / `left = mid + 1`：标准的"找第一个 True"。注意这里是 `right = mid`，因为 `mid` 可能是答案。

### 复杂度

- 时间 O(n log(sum))：`check` 是 O(n)，二分轮数是 O(log(sum))，`sum` 最大 10⁹ 量级，约 30 轮。
- 空间 O(1)：只用了几个整数（不算输入）。
- 和 DP 的 O(n²k) 对比：二分答案把"枚举所有切点"换成了"验证一个猜测"，验证只要 O(n)，所以整体降到了 O(n log(sum))。**这是"判定问题比优化问题简单得多"的典型例子**——想不出怎么直接构造最优解时，先问自己"给我一个候选答案，我能快速验证吗"。

### 常见误区（★ 最容易丢分的地方）

1. **`check` 里用 `>=` 而不是 `>`**。`[7,2,5,10,8], k=2` 返回 19（正确 18）——等于 `limit` 的情况被误判成"装不下"。
2. **`pieces >= k` 就 `return False`**。示例 1 返回 32，示例 2 返回 15。恰好 k 段是合法的，只有超过 k 才不行。
3. **上界写成 `max(nums)`**。二分区间退化成一个点，直接返回 10（正确 18）。
4. **`while left <= right` 配 `right = mid`**。死循环。
5. **以为要"恰好切 k 段"所以 `check` 里判 `== k`**。`[1,2,3], k=3` 返回 6（正确 3），`[1,4,4], k=3` 返回 9（正确 4）。少切几刀一定可以再补刀（只要段数 < n），所以"≤ k 段"和"恰好 k 段"的最优值相同，但**判据必须写成 `<= k`**：判 `== k` 会把"切得更少也可行"的 `limit` 一律否掉，答案被抬高。
6. **以为 `nums` 可以有负数**。有负数时"装不下就切"的贪心不成立（先装一个负数会让后面的判断失真），整个二分答案的框架失效。
7. **`pieces` 初值写成 0**。`[1,2,3], k=1` 返回 3（正确 6），`[7,2,5,10,8], k=2` 返回 14（正确 18）——少算了最后一段，于是每一轮都低估需要的段数，答案整体偏小。

### 面试追问 / 变体

- **同一模板的三道题**：1011 在 D 天内送达包裹、875 爱吃香蕉的珂珂、410 分割数组的最大值。都是"最小化最大值 / 最大化最小值 → 二分答案"，只是 `check` 不同。
- **怎么识别二分答案**：题目问"最小的最大值""最大的最小值""至少需要多少天/多少艘船"，而且"给定一个候选值，验证它行不行"比"直接求最优"容易得多——这就是信号。

## 专题11-9. 二分查找（回顾）

> 第一册已精讲：[分册 D · D12 二分查找](13-分册D-动态规划贪心二分回溯.md)
> 力扣 704 · 二分 · Easy

### 精讲（零基础版）

#### ① 这题要用到的东西

**二分查找**（前面 11-1 讲过）：每轮砍掉一半的查找。这题是最朴素的版本 —— 数组整体升序，直接和 `target` 比，没有旋转、没有重复、没有别的判据。

**闭区间模板的三个记号**：`right = len(nums) - 1`（右端是最后一个下标）、`while left <= right`（两端都还没排除）、`mid ± 1`（`mid` 刚比过，已排除）。三个必须配套，混一个就会漏元素或死循环。

**`bisect` 标准库**：Python 自带的二分。`bisect_left` 返回第一个 ≥ target 的位置，`bisect_right` 返回第一个 > target 的位置。

```python
import bisect

nums = [1, 3, 3, 5]
print(bisect.bisect_left(nums, 3))     # -> 1   （第一个 >= 3 的位置）
print(bisect.bisect_right(nums, 3))    # -> 3   （第一个 > 3 的位置）
```

它是 C 实现的，比手写快一个数量级；手写版的价值在于你能改它 —— 34、35、410 都是从这模板改出来的。

#### ② 大白话：这题到底在干什么

最笨的办法：从头扫到尾，等于目标就返回下标。O(n)，题目要 O(log n)。

笨在哪？**有序数组里比较一次能排除一半，而扫一遍只排除一个**。

聪明的办法：每次看中间那个。等于目标就交卷；比目标小，中间和它左边全小，整段扔掉；比目标大，右边整段扔掉。区间空了还没命中，就是不存在。这题几乎不单独考，它的价值是模板。

**30 秒回顾**：左闭右闭 `[left, right]`，`right = len - 1`，`while left <= right`，三分支：命中返回；`nums[mid] < target` 则 `left = mid + 1`；否则 `right = mid - 1`。循环结束返回 -1。时间 O(log n)，空间 O(1)。

**核心代码（背这一段就够）**：

```python
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1
        while left <= right:
            mid = (left + right) // 2
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1
        return -1
```

**换个角度**：

- 这题本身在面试里几乎不会单独考，它的价值是**模板**：本册其余 8 道题都是它的变体，变的只有"往哪边收"这一件事。所以背它不是为了做 704，是为了让手指记住 `<=`、`mid ± 1` 这一套。
- 标准库里有现成的：`bisect.bisect_left(nums, target)` 返回第一个 `>= target` 的位置，找不到时返回 `len(nums)`；`bisect_right` 返回第一个 `> target` 的位置。两个都是 C 实现，比手写快一个数量级。手写版的价值在于**你能改它**——34、35、410 都是改出来的。
- 三种流派都能写对：左闭右闭（`<=`，`mid ± 1`）、左闭右开（`<`，`right = mid`）、全开区间（`<`，`left = mid + 1, right = mid`）。**但必须自洽**，混用必错：初始值用闭、循环用开，是最常见的崩法。
- 死循环只有两个来源：`left = mid` 和 `right = mid`。它们本身不错，错在配错了循环条件——用 `mid` 就意味着"这个位置还可能是答案"，那循环条件必须是 `<`（区间里至少留一个元素时停），而不是 `<=`。记住这条，二分就不会转圈。
