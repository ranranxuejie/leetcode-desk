## 一句话思路
前缀和 + 哈希表计数：`pre[j] - pre[i] == goal` 等价于查 `pre[i] == pre[j] - goal` 出现过几次。

## 怎么做
1. 维护 `pre`（当前前缀和）和字典 `cnt`，`cnt[0] = 1` 表示空前缀。
2. 遍历 `nums`，先 `pre += x`，再累加 `ans += cnt.get(pre - goal, 0)`。
3. 最后 `cnt[pre] = cnt.get(pre, 0) + 1`，把当前前缀和登记进去。

用示例 1 `nums = [1,0,1,0,1], goal = 2`：走到第 3 个元素时 `pre = 2`，`pre - goal = 0`，`cnt[0] = 1`，`ans` 加 1；走到末尾 `pre = 3`，`pre - goal = 1`，此时 `cnt[1] = 2`（下标 0 和下标 2 处的前缀和都是 1），`ans` 再加 2，累计 4。

```python
cnt = {0: 1}
pre = ans = 0
for x in nums:
    pre += x
    ans += cnt.get(pre - goal, 0)
    cnt[pre] = cnt.get(pre, 0) + 1
return ans
```

顺序不能反：必须先查 `pre - goal` 再登记 `pre`，否则 `goal = 0` 时会把「自己减自己」的空子数组算进去。

## 复杂度
时间 O(n)：一次遍历，每次字典操作 O(1)。
空间 O(n)：`cnt` 最多存 n+1 个不同前缀和。

## 易错点
- `nums = [0,0,0,0,0], goal = 0` → 若先 `cnt[pre] += 1` 再查 `pre - goal`，每个位置都会把自己算进去，答案变成 20 而不是 15 → 必须先查后登记。
- `goal = 0` 且数组含 1，如 `nums = [0,1,0], goal = 0` → 若漏掉 `cnt[0] = 1` 的初始化，前缀和恰为 0 的那段（`[0]`、`[0,1,0]` 里的首尾 0 段）会漏计 → 初始化必须写 `{0: 1}`。

## 如果面试官追问
问：数组不是二元、元素可为负，还能用滑动窗口吗？
答：不能，窗口右移时和不再单调，只能退回前缀和 + 哈希表，复杂度仍是 O(n)。
