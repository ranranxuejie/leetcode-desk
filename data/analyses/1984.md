## 一句话思路
排序后，最优的 k 个分数必是连续的一段，故只需在 `nums[i+k-1] - nums[i]` 上滑窗取最小。

## 怎么做
1. 对 `nums` 升序排序，把「任选 k 个」变成「选连续 k 个」。
2. 枚举窗口左端点 `i`，从 `0` 到 `n-k`，右端点是 `i+k-1`。
3. 用 `nums[i+k-1] - nums[i]` 更新答案，初值取 `2**31 - 1`。

以 `nums = [9,4,1,7], k = 2` 为例：排序得 `[1,4,7,9]`，`n-k = 2`，窗口只有 `i=0,1,2` 三个。`i=0` 时 `nums[1]-nums[0] = 4-1 = 3`；`i=1` 时 `7-4 = 3`；`i=2` 时 `9-7 = 2`，答案收敛到 `2`。注意原始数组里 `9-7=2` 这一对排序后正好相邻，这就是「连续段」的含义。

```python
nums.sort()
n = len(nums)
ans = 2**31 - 1
for i in range(n - k + 1):
    diff = nums[i + k - 1] - nums[i]
    if diff < ans:
        ans = diff
return ans
```

`range` 的上界是 `n-k+1`，因为最后一个窗口左端点是 `n-k`，右端点 `n-k+k-1 = n-1` 刚好不越界。

## 复杂度
时间：排序 `O(n log n)` 主导，滑窗 `O(n)`，n 是 `len(nums)`。
空间：排序原地进行，额外只开 `ans`、`i` 等常数变量，`O(1)`。

## 易错点
- `k = 1` 时（如 `nums = [90]`）→ 若把循环写成 `range(n-k)` 会一次都不进，`ans` 停在 `2**31 - 1` → 上界必须是 `n-k+1`，此时 `nums[i]-nums[i] = 0` 正确返回 `0`。
- 忘记排序直接按原下标取 `nums[i+k-1] - nums[i]`（如 `[9,4,1,7]` 取 `4-9 = -5`）→ 得到负数或错误最小值 → 必须先 `nums.sort()`，让窗口内元素天然有序、差值非负。

## 如果面试官追问
问：要求返回具体是哪 k 个分数怎么办？
答：滑窗时记录取到最小差值的 `i`，返回 `nums[i:i+k]` 即可，复杂度不变。
