## 一句话思路
枚举操作次数 k（0..n-1），对每个 k 把每个位置替换成「k 步内能转到它的最小成本」，取总成本最小值。

## 怎么做
1. 关键观察：若总共只做 k 次操作，位置 i 的巧克力在某个时刻会变成类型 (i+t) mod n（t=0..k），所以买类型 i 的最低成本是 `min(nums[(i-t) mod n] for t in 0..k)`。
2. 对每个 k 维护数组 `best[i]`，k 增大时只需 `best[i] = min(best[i], nums[(i-k) mod n])`，即每轮 O(n) 更新。
3. 总成本 = `k * x + sum(best)`，对所有 k 取最小；k 只需枚举到 n-1，因为 n 次操作后类型回到原位，多做的操作纯亏。

以 `nums=[20,1,15], x=5` 为例：k=0 时 `best=[20,1,15]`，总成本 36；k=1 时 `best[0]=min(20,nums[2]=15)=15`，`best=[15,1,15]`，总成本 5+31=36；k=2 时 `best[0]=min(15,nums[1]=1)=1`，`best=[1,1,1]`，总成本 10+3=13，取到答案。

```python
n = len(nums)
best = nums[:]
ans = sum(best)          # k = 0
for k in range(1, n):
    for i in range(n):
        best[i] = min(best[i], nums[(i - k) % n])
    ans = min(ans, k * x + sum(best))
return ans
```

注意 `best` 是滚动更新的，第 k 轮里 `best[i]` 已经含了 t=0..k 全部候选，不需要重算。

## 复杂度
时间：O(n²)，外层 k 共 n-1 轮，内层更新 n 个位置。
空间：O(n)，只开了 `best` 数组，无额外结构。

## 易错点
- 只枚举到 n-1 就够，但若写成 `range(n+1)` 不会错、只是白算一轮；真正会错的是把 k 上限设成 `n//2` 之类，`nums=[20,1,15]` 会漏掉 k=2 的 13，输出 36。
- 忘记 k=0 这一项：`nums=[1,2,3], x=4` 若从 k=1 起算，得到 4+6=10，而正确答案是 6；初始化 `ans = sum(nums)` 必须在循环前。
- `k * x` 与 `sum(best)` 都是大数（n=1000、x=1e9 时 k*x 达 1e12），Python 无溢出，但若按 32 位截断的题面要求输出，需注意返回值类型是 long。

## 如果面试官追问
若 n 放大到 1e5 怎么办？答：O(n²) 不可行，需换思路——注意到 `best[i]` 单调不增，可用单调栈/分段结构把每轮更新摊还到 O(1)，或直接对每个 i 找「向左最近的更小值」确定其最优 k 区间，再对 k 做差分统计。
