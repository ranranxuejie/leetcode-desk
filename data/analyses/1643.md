## 一句话思路
逐位贪心：每位先试放 `'H'`，用组合数算出以 `'H'` 开头的方案数，与 `k` 比较决定放 `'H'` 还是 `'V'`。

## 怎么做
1. 设剩余 `h` 个 H、`v` 个 V，总方案数 `C(h+v, h)`；字典序中 `'H' < 'V'`，所以所有以 `'H'` 开头的指令排在前面。
2. 以 `'H'` 开头的方案数 = 固定这一位后剩余位置的排列数 `C(h+v-1, h-1)`；若 `k <= 该值`，这一位就是 `'H'`，否则是 `'V'` 且 `k -= 该值`。
3. 每确定一位就减少对应计数，重复 `h+v` 次。

以 `destination=[2,3], k=3` 为例：初始 `h=3, v=2`，`C(4,2)=6` 个以 H 开头，`3 <= 6` → 首位 `'H'`，`h=2`。第二位 `C(3,1)=3`，`3 <= 3` → 又是 `'H'`，`h=1`。第三位 `C(2,0)=1`，`3 > 1` → 放 `'V'`，`k=3-1=2`，`v=1`。继续得 `"HHVVH"`。

```python
from math import comb
h, v = destination[1], destination[0]
res = []
while h + v:
    if h == 0:
        res.append('V'); v -= 1
    elif v == 0:
        res.append('H'); h -= 1
    else:
        cnt = comb(h + v - 1, h - 1)   # 以 H 开头的方案数
        if k <= cnt:
            res.append('H'); h -= 1
        else:
            res.append('V'); k -= cnt; v -= 1
```

## 复杂度
时间：O((h+v) · 组合数计算)，共 h+v 位，每位一次 `comb`。
空间：O(h+v) 存结果字符串，无额外 DP 表。

## 易错点
- `k` 是 1-based，比较时用 `k <= cnt` 而不是 `k < cnt`；写成 `<` 会让 `k=1` 时误判成 `'V'`，示例 1 直接错成 `"VHHHV"`。
- `h` 或 `v` 减到 0 后 `comb(h+v-1, h-1)` 的 `h-1 = -1`，Python 的 `comb` 会抛 `ValueError`；必须先判 `h==0`/`v==0` 直接补剩余字符。

## 如果面试官追问
若 `destination` 规模到 10^5 且 `k` 极大，还能这样逐位算吗？能，但需用对数或大整数维护组合数，避免 `comb` 反复重算；单次 `comb` 是 O(min(h,v))，总代价 O((h+v)·min)。
