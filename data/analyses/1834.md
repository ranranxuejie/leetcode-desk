## 一句话思路
按入队时间排序任务，用最小堆按 (processingTime, index) 取任务，模拟 CPU 时间推进。

## 怎么做
1. 把 `tasks` 转成 `(enqueueTime, processingTime, index)` 三元组并按入队时间升序排序，指针 `i` 指向下一个未入堆任务。
2. 维护 `time` 和最小堆 `heap`（元素 `(processingTime, index)`）；每轮先把所有 `enqueueTime <= time` 的任务压堆。
3. 堆空时说明 CPU 空闲，直接把 `time` 跳到 `tasks[i][0]`，再压堆。
4. 弹出堆顶执行，`time += processingTime`，把 `index` 追加到答案。

以示例 1 的 `tasks = [[1,2],[2,4],[3,2],[4,1]]` 为例：`time=1` 压入任务 0，弹出执行，`time` 变 3；此时任务 1、2 都已入堆，堆顶是 `(2, 2)`（任务 2 与任务 1 同为 2 时长，但下标 2 < 1 不成立，实际任务 1 时长 4，故取任务 2），答案前两位是 `[0, 2]`。

```python
order = sorted((e, p, i) for i, (e, p) in enumerate(tasks))
heap, res, time, i = [], [], 0, 0
while i < len(order) or heap:
    while i < len(order) and order[i][0] <= time:
        e, p, idx = order[i]
        heapq.heappush(heap, (p, idx))
        i += 1
    if not heap:
        time = order[i][0]
        continue
    p, idx = heapq.heappop(heap)
    time += p
    res.append(idx)
```

## 复杂度
时间：排序 O(n log n)，每个任务进出堆各一次 O(n log n)，合计 O(n log n)。
空间：堆与排序数组各 O(n)，即额外 O(n)。

## 易错点
- 堆里只放 `(processingTime, index)` 而不放入队时间，是对的；但若把 `index` 放前面当第一关键字，示例 2 的 `[[7,10],[7,12],[7,5],[7,4],[7,2]]` 会输出 `[0,1,2,3,4]`，正确是 `[4,3,2,0,1]`——必须让 `processingTime` 当第一关键字。
- 堆空但还有任务未入队时，若直接 `time += 1` 逐秒推进，遇到 `enqueueTime = 10**9` 会超时；正确做法是 `time = order[i][0]` 直接跳到下一个入队时刻。

## 如果面试官追问
问：若允许多核（k 个 CPU）并行，怎么改？
答：把单个 `time` 换成大小为 k 的最小堆记录各核空闲时刻，每次取最早空闲的核，逻辑不变。
