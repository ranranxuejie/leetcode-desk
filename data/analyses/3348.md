## 一句话思路
从右往左枚举「第一个变大的位置」，用剩余后缀贪心填最小数位，取第一个可行解。

## 怎么做
1. 把 t 分解成只含 2、3、5、7 的因子；若剩下 >1，直接返回 `"-1"`（数位乘积只含这四个质因子）。
2. 从右往左扫 num，维护前缀乘积对 t 的剩余需求 `need`，在位置 i 尝试把 `num[i]` 换成更大的无零数字 d，再判断后缀能否补足 `need // gcd(need, d)`。
3. 后缀补足用贪心：把剩余需求拆成尽量少的 9/8/…/2，位数不够就补 1，最后升序排列。
4. 若整个 num 本身已满足（`need == 1` 且无 0），直接返回 num。

以 `num="1234", t=256=2^8` 为例：扫到 i=2（字符 `'3'`），换成 `'4'` 后 need 变为 `2^8 / gcd(2^8,4)=2^6`，后缀只剩 1 位，需 6 个 2 因子，1 位最多贡献 3 个（8），不够；继续试 i=1，`'2'`→`'4'`，need 变 `2^6`，后缀 2 位可拆成 `8,8`，可行，得 `"1488"`。

```python
def factor_need(t):
    need = {}
    for p in (2, 3, 5, 7):
        while t % p == 0:
            need[p] = need.get(p, 0) + 1
            t //= p
    return need if t == 1 else None

def min_suffix(need, length):
    # 把 need 拆成最少位数，不足补 1，返回升序字符串
    digits = []
    for d in (9, 8, 7, 6, 5, 4, 3, 2):
        while need % d == 0:
            digits.append(str(d)); need //= d
    if need != 1 or len(digits) > length:
        return None
    return ''.join(sorted(digits + ['1'] * (length - len(digits))))
```

## 复杂度
时间 O(n · 10 · log t)：n 为 num 长度，每位置试 10 个数字，每次算 gcd 与拆因子 O(log t)。
空间 O(log t)：存 need 字典与后缀数字列表，不复制整个 num。

## 易错点
- `num="12355", t=50`：若先尝试「变大」再判断，会漏掉原串本身已满足的情况，错答成 `"12356"` 之类；正确做法是先检查 `need==1` 且无 0 就直接返回 num。
- `num="11111", t=26`：26 含质因子 13，若不在分解阶段提前返回 `"-1"`，会在后缀贪心里死循环或返回错误串；正确做法是分解后 `t != 1` 立即判无解。

## 如果面试官追问
问：t 上限提到 10^18 还成立吗？答：成立，只需把因子分解循环改成对 2、3、5、7 反复除，复杂度仍是 O(log t)，其余逻辑不变。
