## 一句话思路
把查询从小到大排序，用并查集按格子值递增「解锁」格子，维护与左上角连通的格子数，答案单调递增。

## 怎么做
1. 把所有格子按 `grid` 值升序排序，查询按值升序排序并记下原下标。
2. 用并查集，`size` 记录每个连通块大小；另用 `active` 标记格子是否已解锁。
3. 对每个查询 `q`，把所有 `grid` 值 `< q` 的格子解锁，与已解锁的四邻合并，`size` 累加。
4. 若左上角 `(0,0)` 已解锁，当前分数就是它所在连通块大小，否则为 0；按原下标写回 `answer`。

以示例 1 的 `queries=[5,6,2]` 排序后为 `[2,5,6]`：处理 `q=2` 时只解锁 `(0,0)` 值 1，分数 1；处理 `q=5` 时解锁值 2、3 的格子，`(0,0)` 连通块扩到 5；处理 `q=6` 时解锁值 5 的格子，扩到 8。写回原序得 `[5,8,1]`。

```python
order = sorted(range(m*n), key=lambda i: grid[i//n][i%n])
qs = sorted(range(len(queries)), key=lambda i: queries[i])
parent = list(range(m*n)); size = [1]*(m*n); active = [False]*(m*n)
p = 0
for qi in qs:
    q = queries[qi]
    while p < m*n and grid[order[p]//n][order[p]%n] < q:
        v = order[p]; active[v] = True
        for u in (v-n if v>=n else -1, v+n if v<m*n-n else -1,
                  v-1 if v%n else -1, v+1 if v%n!=n-1 else -1):
            if u >= 0 and active[u]:
                union(v, u)
        p += 1
    answer[qi] = size[find(0)] if active[0] else 0
```

## 复杂度
时间 O(mn log(mn) + k log k)，排序主导，并查集近 O(mn α)。
空间 O(mn)，`parent`/`size`/`active` 各开 mn，另有排序下标数组。

## 易错点
- 查询条件严格小于：`grid` 值等于 `q` 的格子不能解锁。示例 2 中 `q=3`、`(0,0)` 值 5，若写成 `<=` 会误判为可进入，答案错成非 0。
- 左上角未解锁时不能直接读 `size[find(0)]`：`(0,0)` 的 `size` 初值 1 会给出假分数 1。示例 2 正确输出 0，必须先判 `active[0]`。

## 如果面试官追问
问：若要求输出每个查询实际访问的格子集合而非数量？
答：并查集只给大小，需额外维护连通块成员链表或改用 BFS 逐查询扩展，代价升到 O(k·mn)。
