## 一句话思路
固定切点 j，用左右两个「不同字符数」数组做前缀和，把 O(n³) 枚举压成 O(n²)。

## 怎么做
1. 预处理 `L[j][c]`：`s[0..j]` 中字符 c 是否出现；`R[j][c]`：`s[j..n-1]` 中 c 是否出现。
2. 枚举切点 j，对每个 i 累加 `s[i..j]` 的不同字符数 `dl`，对每个 k 累加 `s[j+1..k]` 的 `dr`。
3. 用计数数组 `cnt[dl]` 记录当前 j 下各 `dl` 出现次数，再对每个 k 把 `cnt[dr]` 加进答案。

以 `s = "abcac"`、j=1 为例：i=0 时 `s[0..1]="ab"`，`dl=2`；i=1 时 `"b"`，`dl=1`。k=3 时 `s[2..3]="ca"`，`dr=2`，命中 `cnt[2]=1`，贡献 1 个（即 (0,1,3)）。

```python
n = len(s)
ans = 0
for j in range(n - 1):
    cnt = [0] * 27
    seen = set()
    for i in range(j, -1, -1):
        seen.add(s[i])
        cnt[len(seen)] += 1
    seen = set()
    for k in range(j + 1, n):
        seen.add(s[k])
        ans += cnt[len(seen)]
```

## 复杂度
时间 O(n²)：外层 j 共 n 次，内层 i、k 各扫 O(n)。
空间 O(1)：`cnt` 固定 27 格，`seen` 最多 26 个字符。

## 易错点
- `s = "kkk"` → 若把 `s1`、`s2` 当成「字符集合相等」而非「不同字符数相等」，会漏掉 (0,0,2) 这类 `"k"` 对 `"kk"` 的配对 → 只比较 `len(seen)`，不比集合内容。
- `s = "aba"` → 若内层 i 从 0 正向扫到 j，`seen` 无法增量维护（删字符难）→ i 必须从 j 倒着扫到 0，只做 add。

## 如果面试官追问
若 n 放大到 10⁵ 怎么办？答：不同字符数 ≤26，可对每个 j 用双指针+26 个前缀出现位置二分，把内层降到 O(26 log n)。
