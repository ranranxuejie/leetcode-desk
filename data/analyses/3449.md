## 一句话思路
二分答案 `x`，贪心判定能否在 `m` 步内让每个 `gameScore[i] >= x`，因为可行性对 `x` 单调。

## 怎么做
1. 二分下界 `lo=0`，上界 `hi=sum(points)//n+1`（答案不可能超过平均值），判定 `can(x)`。
2. 从左往右扫，维护当前位置 `pos` 和已用步数 `used`；对每个 `i`，若 `points[i]` 已够则跳过，否则要来回补。
3. 关键贪心：补第 `i` 个时，尽量用「右邻居」来回（`i` 与 `i+1` 往返一次得 `points[i]+points[i+1]`），不够再用左邻居 `i-1` 补，因为左邻居已经满足，浪费它不亏。
4. 用官方示例 `points=[2,4], m=3` 验证：`can(4)` 时 `i=0` 需补 4，`points[0]=2` 不够，用 `i+1` 往返一次得 `2+4=6`，`used=2`（走到 1 再回 0），`i=1` 已由那次往返拿到 4，`used=2<=3`，返回真，故答案 4。

```python
def can(x):
    used = 0
    for i in range(n):
        if points[i] >= x:
            continue
        need = x - points[i]
        if i + 1 < n:
            pair = points[i] + points[i + 1]
            k = (need + pair - 1) // pair
            used += 2 * k
        else:
            used += 2 * ((need + points[i] - 1) // points[i]) - 1
        if used > m:
            return False
    return True
```

注意 `i` 为最后一个元素时没有右邻居，只能靠自身往返，步数是 `2*k-1`（最后一次停在原地不用返回）。

## 复杂度
时间：二分 `log(sum/n)` 层，每层 `O(n)` 扫描，共 `O(n log(sum/n))`。
空间：只用了 `used`、`need` 等常数变量，`O(1)` 额外空间。

## 易错点
- 输入 `points=[1,2,3], m=5`：若对每个 `i` 都只用自身往返，`i=0` 补到 2 要 3 步、`i=1` 已够、`i=2` 补到 2 要 1 步，共 4 步看似可行，但实际走位冲突；正确做法是优先用 `i` 与 `i+1` 的往返共享收益，`i=0` 往返一次得 `1+2=3`，`used=2`，再走到 `i=2` 得 3，`used=4`，最小值 2 成立。
- 输入 `points=[2,4], m=3`：若把 `hi` 设成 `sum(points)=6` 而不除 `n`，二分范围偏大不影响正确性但多跑几轮；若 `hi` 设成 `max(points)=4` 恰好对，但一般 `max` 不是上界（`n` 大时平均值更小），正确上界用 `sum(points)//n+1` 保证 `can(hi)` 为假。

## 如果面试官追问
问：`m` 增大到 `10^18` 会怎样？答：二分上界仍是 `sum(points)//n+1`，与 `m` 无关，`used` 用 Python 大整数不会溢出，逻辑不变。
