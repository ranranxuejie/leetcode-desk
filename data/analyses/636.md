## 一句话思路
用栈保存当前正在执行的函数 id，每条日志只结算「栈顶函数」从上一时间戳到当前时间戳的独占时间。

## 怎么做
1. 解析每条日志为 `fid, typ, ts`，维护 `stack` 和 `res = [0]*n`，以及 `prev` 表示上一条日志的时间戳。
2. 遇到 `start`：若栈非空，栈顶函数刚执行了 `ts - prev` 个单位，累加进 `res[stack[-1]]`；然后把 `fid` 压栈。
3. 遇到 `end`：栈顶就是 `fid`，它执行了 `ts - prev + 1` 个单位（结束时间戳本身也算 1 个单位），累加后弹栈。
4. 每条日志处理完令 `prev = ts`。

以示例 1 为例，处理到 `"1:end:5"` 时 `stack = [0, 1]`、`prev = 2`，函数 1 独占 `5 - 2 + 1 = 4`，`res[1] = 4`，弹栈后 `prev = 5`；下一条 `"0:end:6"` 结算 `6 - 5 + 1 = 2`，加上之前 start 时结算的 `2 - 0 = 2`，`res[0] = 3`。

```python
res = [0] * n
stack = []
prev = 0
for log in logs:
    fid, typ, ts = log.split(":")
    fid, ts = int(fid), int(ts)
    if typ == "start":
        if stack:
            res[stack[-1]] += ts - prev
        stack.append(fid)
    else:
        res[fid] += ts - prev + 1
        stack.pop()
    prev = ts
return res
```

关键差异只在 `+1`：`start` 结算的是「上一段」`ts - prev`，`end` 结算的是「本段含端点」`ts - prev + 1`。

## 复杂度
时间 O(m)，m 为 `logs` 长度，每条日志一次 split 和常数次栈操作。
空间 O(n + m)，`res` 长 n，栈最深为递归层数，不超过 m。

## 易错点
- 输入 `["0:start:0","0:end:0"]` → 若 `end` 也写成 `ts - prev` 会得 0 → 正确是 `ts - prev + 1 = 1`，结束时间戳本身占一个单位。
- 输入示例 2 的递归 `["0:start:0","0:start:2",...]` → 若在 `start` 时忘了先给栈顶结算 `ts - prev`，函数 0 外层那 2 个单位会丢 → 正确是压栈前先 `res[stack[-1]] += ts - prev`，再 `append`。

## 如果面试官追问
若日志不保证成对、可能缺 `end` 怎么办？答：在遍历结束后对栈中剩余函数按「最后时间戳 + 1」补结算，或直接判定输入非法。
