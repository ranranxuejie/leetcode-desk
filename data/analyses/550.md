## 一句话思路
先按 `player_id` 取 `MIN(event_date)` 当首次登录日，再自连接判断是否存在 `首次日 + 1 天` 的记录，最后用 `COUNT(DISTINCT)` 相除。

## 怎么做
1. 子查询按 `player_id` 分组求 `MIN(event_date)`，得到每个玩家的首登日。
2. 把原表 `a` 与首登表 `f` 按 `player_id` 连接，条件加 `a.event_date = f.first_day + INTERVAL 1 DAY`。
3. 满足条件的 `player_id` 去重计数，除以首登表的总人数。
4. 用 `ROUND(..., 2)` 保留两位。

以官方示例为例：首登表是 `{1: 2016-03-01, 2: 2017-06-25, 3: 2016-03-02}`。玩家 1 存在 `2016-03-02` 的记录，命中；玩家 2 只有 `2017-06-25`，玩家 3 只有 `2016-03-02` 和 `2018-07-03`，都不命中。分子 `1`，分母 `3`，得 `0.33`。

```python
# 伪 SQL 逻辑，落到 pandas 上同理
first = df.groupby("player_id")["event_date"].min().rename("first_day")
merged = df.merge(first, on="player_id")
hit = merged[merged["event_date"] == merged["first_day"] + pd.Timedelta(days=1)]
fraction = round(hit["player_id"].nunique() / first.shape[0], 2)
```

关键在 `+ INTERVAL 1 DAY` 而不是 `> first_day`：题目要的是「第二天」，不是「之后任意一天」。

## 复杂度
时间：`O(n log n)`，n 是 Activity 行数，排序/分组贡献 log n。
空间：`O(p)`，p 是不同玩家数，额外存首登表和去重集合。

## 易错点
- 用 `a.event_date > f.first_day` 代替 `= first_day + 1`：玩家 3 的 `2018-07-03` 会被误判为次日登录，分子变 2、结果变 `0.67`；必须严格等于首登日加一天。
- 分母用 `COUNT(*)` 而不是 `COUNT(DISTINCT player_id)`：示例里 5 行会被当成 5 个玩家，`1/5 = 0.2`；分母必须是首登表行数即玩家总数。

## 如果面试官追问
问：如果要求「首次登录后连续登录 3 天」的比率怎么改？
答：把单次自连接改成对首登日 `+1`、`+2` 各连接一次，或用窗口函数按玩家排序后检查连续日期差。
