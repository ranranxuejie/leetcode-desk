## 一句话思路
维护「当前以加号结尾」和「以减号结尾」的最大交替和，逐元素更新，等价于贪心取每个上升段的峰和下降段的谷。

## 怎么做
1. 设 `plus` 为子序列长度为奇数（最后一项是加号）时的最大交替和，`minus` 为长度为偶数（最后一项是减号）时的最大交替和，初始 `plus = nums[0]`、`minus = 0`。
2. 遍历 `nums[1:]`，对每个 `x` 同时更新：`new_plus = max(plus, minus + x)`，`new_minus = max(minus, plus - x)`，注意两个式子必须用**旧值**，所以先算完再赋值。
3. 答案就是 `plus`（长度至少为 1，`minus` 对应空子序列或偶数长度，不会更大）。

以 `nums = [4,2,5,3]` 为例：初始 `plus=4, minus=0`。处理 `x=2`：`new_plus=max(4,0+2)=4`，`new_minus=max(0,4-2)=2`。处理 `x=5`：`new_plus=max(4,2+5)=7`，`new_minus=max(2,4-5)=2`。处理 `x=3`：`new_plus=max(7,2+3)=7`，`new_minus=max(2,7-3)=4`。最终 `plus=7`，与示例一致。

```python
plus, minus = nums[0], 0
for x in nums[1:]:
    new_plus = max(plus, minus + x)
    new_minus = max(minus, plus - x)
    plus, minus = new_plus, new_minus
return plus
```

关键点：`minus + x` 表示把 `x` 接在某个偶数长度子序列后面当新的加号项；`plus - x` 表示接在奇数长度后面当减号项。两个 `max` 里的第一项代表「不选 `x`」，保留原状态。

## 复杂度
时间 O(n)：一次遍历 `nums`，每个元素做两次 `max`。
空间 O(1)：只开了 `plus`、`minus`、`new_plus`、`new_minus` 四个变量。

## 易错点
- 输入 `[5,6,7,8]` → 若初始化 `plus=0` 或允许空子序列，会错成把 `8` 之前的递减都算进去得到 0 甚至负数；正确做法是 `plus=nums[0]`，保证至少选一个元素，答案 8。
- 输入 `[6,2,1,2,4,5]` → 若在循环里先更新 `plus` 再用新 `plus` 算 `minus`，`x=1` 时会得到 `minus=max(0,6-1)=5` 后又被污染，最终错成 9 而非 10；正确做法是用临时变量 `new_plus`/`new_minus` 同时算完再一起赋值。

## 如果面试官追问
要求输出具体子序列而非只求和，怎么改？答：在 `plus`/`minus` 更新时额外记录「上一个被选元素的下标」和「当前长度奇偶」，回溯即可，时间空间仍 O(n)。
