## 一句话思路
维护一个大小为 k 的小顶堆，堆顶就是第 k 大元素，因为堆里恰好装着当前最大的 k 个数。

## 怎么做
1. 初始化时把 `nums` 逐个 `heappush` 进堆，堆大小超过 k 就 `heappop` 弹出最小值。
2. 每次 `add(val)` 先 `heappush` 再判断大小是否超过 k，超过就弹出堆顶。
3. 此时堆顶 `heap[0]` 就是第 k 大，直接返回。

以示例 1 为例，`k=3`，初始 `nums=[4,5,8,2]` 建堆后堆内是 `[4,5,8]`（2 被弹出），堆顶 4 即第 3 大。`add(3)` 后堆变 `[4,5,8,3]`，弹出 3，堆顶仍是 4；`add(10)` 后堆变 `[4,5,8,10]`，弹出 4，堆顶变 5——正好对应输出里的 5。

```python
import heapq

class KthLargest:
    def __init__(self, k, nums):
        self.k = k
        self.heap = []
        for x in nums:
            heapq.heappush(self.heap, x)
            if len(self.heap) > k:
                heapq.heappop(self.heap)

    def add(self, val):
        heapq.heappush(self.heap, val)
        if len(self.heap) > self.k:
            heapq.heappop(self.heap)
        return self.heap[0]
```

关键点：堆里始终只保留最大的 k 个元素，堆顶是这 k 个里最小的，也就是整体第 k 大。重复元素不用去重，`[7,7,7,7]` 会原样留在堆里，这正符合「第 k 大不是第 k 个不同元素」的要求。

## 复杂度
时间：初始化 O(n log k)，每次 add O(log k)，n 为 nums 长度。
空间：O(k)，堆里最多存 k 个元素。

## 易错点
- `nums` 长度小于 k 时（如 `k=3, nums=[4,5]`），初始化后堆只有 2 个元素，此时 `heap[0]` 不是第 3 大。正确做法是允许堆暂时不足 k 个，等 add 补足后再返回堆顶，不要提前返回或报错。
- 用大顶堆存全部元素再取第 k 个，每次 add 是 O(n log n) 且空间 O(n)，在 10^4 次调用下会超时。必须用小顶堆只留 k 个，弹出的是最小值而非最大值，方向搞反会得到第 k 小。

## 如果面试官追问
问：如果 k 很大接近 n，还能用小顶堆吗？
答：可以，但可换双堆或有序容器平衡，或直接维护全量排序结构，按 k 与 n 的关系选更省空间的一方。
