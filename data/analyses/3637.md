## 一句话思路
从左扫到第一个下降点定 p，再扫到第一个上升点定 q，最后验证尾段严格递增。

## 怎么做
1. 从 `i = 1` 开始向右走，只要 `nums[i] > nums[i-1]` 就继续，停下时 `p = i-1`；若 `p == 0` 直接返回 `False`（第一段没长度）。
2. 从 `p` 继续向右走，只要 `nums[i] < nums[i-1]` 就继续，停下时 `q = i-1`；若 `q == p` 返回 `False`（第二段没长度）。
3. 从 `q` 继续向右走，只要 `nums[i] > nums[i-1]` 就继续；若走到 `n-1` 返回 `True`，否则 `False`。

以 `nums = [1,3,5,4,2,6]` 为例：第一段停在 `i=3`（`5 > 4` 不成立），得 `p=2`；第二段停在 `i=5`（`2 < 6` 不成立），得 `q=4`；第三段从 `q=4` 走到 `n-1=5`，返回 `True`。

```python
n = len(nums)
p = 1
while p < n and nums[p] > nums[p-1]:
    p += 1
p -= 1
if p == 0:
    return False
q = p + 1
while q < n and nums[q] < nums[q-1]:
    q += 1
q -= 1
if q == p:
    return False
i = q + 1
while i < n and nums[i] > nums[i-1]:
    i += 1
return i == n
```

关键点：`p`、`q` 是「停下后回退一格」得到的峰/谷下标，不是循环变量本身；三段都必须非空，所以 `p == 0` 和 `q == p` 要单独拦。

## 复杂度
时间：O(n)，三段扫描各走一遍，总步数不超过 n。
空间：O(1)，只用了 `p`、`q`、`i` 三个下标。

## 易错点
- `nums = [1,2,3]` 全程递增 → 第一段扫到末尾，`p = n-1`，此时 `q = p+1 = n` 越界或第二段为空 → 正确做法是先判 `p == 0`，再判 `q == p`，两段都必须有真实下降。
- `nums = [3,2,1]` 全程递减 → `p = 0` 被拦下返回 `False`，但若写成「先找峰再找谷」而没检查 `p > 0`，会误判成第一段长度为 0 也算合法 → 必须显式要求 `0 < p`。
- `nums = [1,3,5,4,2,6,7,8]` 尾段一直涨到末尾没问题，但 `nums = [1,3,5,4,2,6,5]` 尾段中途下降 → 第三段循环停在 `i=6`，`i != n` 返回 `False`，别只检查「尾段起点小于终点」。

## 如果面试官追问
问：要求返回具体的 `p, q` 而不是布尔值？
答：把三处 `return False` 改成返回 `None`，成功时返回 `(p, q)`，扫描逻辑完全不变。
