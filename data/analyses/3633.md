## 一句话思路
只需保留每类中「最早结束」的那一个设施，两种顺序各算一次取最小。

## 怎么做
1. 对陆地，求 `min(landStartTime[i] + landDuration[i])`，记为 `landEnd`；水同理得 `waterEnd`。
2. 顺序「陆→水」：水最早只能在 `max(landEnd, waterStartTime[j])` 开始，故对每个 j 算 `max(landEnd, waterStartTime[j]) + waterDuration[j]` 取最小。
3. 顺序「水→陆」对称：对每个 i 算 `max(waterEnd, landStartTime[i]) + landDuration[i]` 取最小。
4. 两次结果取 min 即为答案。

关键中间值（示例 1）：`landEnd = min(2+4, 8+1) = 6`，`waterEnd = 6+3 = 9`。陆→水：`max(6,6)+3 = 9`；水→陆：`max(9,2)+4 = 13`、`max(9,8)+1 = 10`，取 9。

```python
land_end = min(s + d for s, d in zip(landStartTime, landDuration))
water_end = min(s + d for s, d in zip(waterStartTime, waterDuration))
ans = min(max(land_end, ws) + wd for ws, wd in zip(waterStartTime, waterDuration))
ans = min(ans, min(max(water_end, ls) + ld for ls, ld in zip(landStartTime, landDuration)))
```

为什么只留最早结束的那个：先做的那一项结束越早，后一项能开始的时间只会更早或不变，`max(landEnd, ...)` 单调不减，所以其余陆地设施永远不可能更优。

## 复杂度
时间 O(n + m)：两次求 min 加两轮扫描，无排序无二分。
空间 O(1)：只存 `land_end`、`water_end`、`ans` 三个标量。

## 易错点
- 误以为要枚举所有 (i, j) 对：n=m=100 时 10⁴ 对也能过，但若把「先做的那项」也逐个枚举，逻辑上仍对却多写了循环；正确做法是先压缩成 `land_end`/`water_end` 两个标量再扫另一侧。
- 忘记后一项可能要等：示例 2 中 `water_end = 11`，陆地 5 就开放，若写成 `landStartTime[i] + landDuration[i]` 会得 8，漏掉 `max(water_end, 5) = 11`，答案错成 8 而非 14。

## 如果面试官追问
若 n、m 放大到 10⁵ 并要求输出具体设施下标？答：仍先求两类各自最早结束的下标，再扫另一侧记录 argmin，O(n+m) 不变。
