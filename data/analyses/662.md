## 一句话思路
按满二叉树编号（左子 `2i`、右子 `2i+1`），BFS 每层用「最右编号 − 最左编号 + 1」得宽度。

## 怎么做
1. 队列存 `(node, idx)`，根入队时 `idx = 1`。
2. 每层先记下队首的 `idx` 作为 `left`，循环处理完本层所有节点。
3. 出队时把子节点按 `2*idx`、`2*idx+1` 入队，最后一个出队的 `idx` 就是 `right`。
4. 每层结束用 `right - left + 1` 更新答案。

以示例 2 的 `[1,3,2,5,null,null,9,6,null,7]` 为例：第 4 层入队的是 `6`（idx=8）和 `7`（idx=14），`left=8`、`right=14`，宽度 `14-8+1=7`，正是答案。中间那些 null 位置被编号自然「占」掉了，不用真的建节点。

```python
from collections import deque

q = deque([(root, 1)])
ans = 0
while q:
    left = q[0][1]
    right = left
    for _ in range(len(q)):
        node, idx = q.popleft()
        right = idx
        if node.left:
            q.append((node.left, 2 * idx))
        if node.right:
            q.append((node.right, 2 * idx + 1))
    ans = max(ans, right - left + 1)
```

注意 `right` 每层要重置成 `left`，否则单节点层会沿用上一层的值。

## 复杂度
时间 O(n)：每个节点入队出队各一次，n 为节点数。
空间 O(n)：队列最多存一层节点，最坏约 n/2；编号本身不额外占空间。

## 易错点
- 输入是链状树（如每层只有一个右孩子）→ 编号会指数增长到 `2**3000` 量级，若用 C++/Java 的 `int` 会溢出成负数、宽度算错；Python 大整数天然安全，但别自己加 `% (2**31)` 之类的截断，题目只说答案在 32 位内，编号不在。
- 每层只更新 `right` 不重置 `left`，或把 `right` 初值写成 0 → 单节点层（如示例 3 第 1 层）会算出 `1-0+1=2` 或沿用上层右端，宽度虚高；正确做法是每层开头 `left = q[0][1]`、`right = left`。

## 如果面试官追问
若节点数涨到 10^6 且树极深，编号会到 2^1000000 位，怎么办？
答：改用 DFS 传 `(depth, idx)` 只维护每层最左编号，或对编号取模前先确认答案范围；本质仍需大整数或换「按层压缩」的思路。
