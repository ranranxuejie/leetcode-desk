## 一句话思路
按攻击降序、防御升序排序后单次扫描，维护已见最大防御，防御小于它的角色即为弱角色。

## 怎么做
1. 排序：`properties.sort(key=lambda p: (-p[0], p[1]))`，攻击降序、同攻击时防御升序。
2. 同攻击组内防御升序，保证组内先出现的防御更小，不会被同攻击的后者误判为弱。
3. 扫描时维护 `max_def`（此前所有攻击严格更大的角色中的最大防御），当前 `defense < max_def` 则计数加一。
4. 每组处理完再更新 `max_def`，避免同攻击组内互相污染。

以示例 3 `[[1,5],[10,4],[4,3]]` 为例：排序后为 `[[10,4],[4,3],[1,5]]`。扫描到 `[4,3]` 时 `max_def=4`，`3<4` 计数 1；扫描到 `[1,5]` 时 `5<4` 不成立，最终返回 1。

```python
properties.sort(key=lambda p: (-p[0], p[1]))
ans = 0
max_def = 0
i = 0
while i < len(properties):
    j = i
    while j < len(properties) and properties[j][0] == properties[i][0]:
        if properties[j][1] < max_def:
            ans += 1
        j += 1
    max_def = max(max_def, properties[i][1])  # 组内防御升序，末位最大
    i = j
return ans
```

关键点：`max_def` 只在整组扫描完后更新，且取组内最大防御（因组内升序，即 `properties[j-1][1]`）。

## 复杂度
时间 O(n log n)：排序贡献 n log n，扫描 O(n)。
空间 O(log n)：排序栈开销，`max_def`、`ans` 为常数。

## 易错点
- 同攻击不同防御的输入如 `[[1,5],[1,3]]` → 若按防御降序排，`[1,3]` 会看到 `max_def=5` 被误判为弱 → 必须同攻击时防御升序，且组内不更新 `max_def`。
- 攻击相同但防御也相同的输入如 `[[2,2],[2,2]]` → 若边扫边更新 `max_def`，第二个会被判弱 → 严格大于要求攻击必须不同，整组扫完再更新。

## 如果面试官追问
问：若要求输出所有弱角色的下标而非数量？
答：排序时保留原下标 `(attack, defense, idx)`，计数改为收集 `idx`，其余逻辑不变。
