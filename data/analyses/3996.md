## 一句话思路
骑士每步都改变格子颜色，所以偶数步等价于起点终点同色，直接比较 `(x+y)` 奇偶性。

## 怎么做
1. 把棋盘按 `(x + y) % 2` 染色，骑士每走一步横纵坐标之和的奇偶性必然翻转。
2. 因此偶数步可达 ⟺ 起点与终点同色，即 `(start[0]+start[1]) % 2 == (target[0]+target[1]) % 2`。
3. 起点等于终点时 0 步也算偶数步，同色判断天然覆盖，无需特判。

以示例 1 为例：`start=[1,1]` 得 `1+1=2`，`2%2=0`；`target=[2,2]` 得 `2+2=4`，`4%2=0`，两者相等返回 `True`。示例 2 中 `start=[4,5]` 得 `9%2=1`，`target=[6,6]` 得 `12%2=0`，不等返回 `False`。

```python
def canReach(start, target):
    return (start[0] + start[1]) % 2 == (target[0] + target[1]) % 2
```

注意这里只判奇偶，不判「是否真的能走到」——8×8 棋盘上同色格子之间一定存在偶数步路径（最少 2 步，除起点等于终点为 0 步），所以奇偶性就是充要条件。

## 复杂度
时间 O(1)，只做两次加法和两次取模。
空间 O(1)，没有开任何额外数组。

## 易错点
- 输入 `start=[1,1], target=[1,1]` → 若误以为「必须移动至少一次」会返回 `False` → 正确做法是 0 步算偶数步，同色判断直接返回 `True`。
- 输入 `start=[0,0], target=[0,1]` → 若只比较 `x` 或只比较 `y` 的奇偶会误判 → 必须用 `x+y` 之和的奇偶，因为骑士一步同时改变两个坐标，单看一个坐标不守恒。

## 如果面试官追问
问：如果要求返回具体移动序列怎么办？
答：同色时用 BFS 在 8×8 棋盘上搜偶数步路径，记录 `parent` 回溯即可，状态数只有 64。
