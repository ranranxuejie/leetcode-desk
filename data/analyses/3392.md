## 一句话思路
枚举每个长度为 3 的窗口，用 `nums[i] + nums[i+2] == nums[i+1] / 2` 判断，避免浮点用乘法改写。

## 怎么做
1. 循环 `i` 从 0 到 `len(nums) - 3`，每个 `i` 对应唯一一个窗口 `[i, i+1, i+2]`。
2. 判断条件写成 `2 * (nums[i] + nums[i+2]) == nums[i+1]`，把「和是中间数的一半」变成整数比较。
3. 成立则计数加一，最后返回计数。

以 `nums = [1,2,1,4,1]` 为例：`i=0` 时窗口 `[1,2,1]`，`2*(1+1)=4 ≠ 2`，不计数；`i=1` 时窗口 `[2,1,4]`，`2*(2+4)=12 ≠ 1`；`i=2` 时窗口 `[1,4,1]`，`2*(1+1)=4 == 4`，计数变 1。这正是示例里唯一命中的窗口。

```python
count = 0
for i in range(len(nums) - 2):
    if 2 * (nums[i] + nums[i + 2]) == nums[i + 1]:
        count += 1
return count
```

注意 `range` 上界是 `len(nums) - 2`，保证 `i+2` 不越界；写成 `len(nums) - 3` 会漏掉最后一个窗口。

## 复杂度
时间：O(n)，n 为 `len(nums)`，每个窗口常数次比较。
空间：O(1)，只开了 `count` 和循环变量 `i`。

## 易错点
- 输入 `nums = [1,1,1]` → 若写成 `nums[i] + nums[i+2] == nums[i+1] / 2`，`2 == 0.5` 为假没错，但换成 `[0,0,0]` 时 `0 == 0.0` 为真、结果对；真正的坑是 `[1,2,1]` 这类 `2*(1+1)==2` 不成立却因浮点误差误判，正确做法是全程用 `2 * (nums[i] + nums[i+2]) == nums[i+1]` 的整数比较。
- 输入 `nums = [1,2,1,4,1]` → 若循环写成 `range(len(nums) - 3)`，`i` 最大到 1，漏掉 `i=2` 的 `[1,4,1]`，输出 0 而非 1；正确上界是 `len(nums) - 2`。

## 如果面试官追问
问：若要求返回所有满足条件的子数组下标而非计数？答：把 `count += 1` 换成 `res.append(i)`，其余不变，仍是 O(n)。
