## 一句话思路
以每个位置结尾的交替子数组长度只取决于前一位是否与它不同，累加这个长度即得总数。

## 怎么做
1. 维护 `cur`：以 `nums[i]` 结尾的最长交替子数组长度，初值 1。
2. 若 `i > 0` 且 `nums[i] != nums[i-1]`，则 `cur += 1`，否则重置 `cur = 1`。
3. 把 `cur` 累加进 `ans`，因为以 `i` 结尾的交替子数组恰好有 `cur` 个（长度 1 到 cur 各一个）。
4. 返回 `ans`。

以 `nums = [0,1,1,1]` 为例：`i=0` 时 `cur=1`，`ans=1`；`i=1` 时 `nums[1]=1 != nums[0]=0`，`cur=2`，`ans=3`；`i=2` 时 `nums[2]=1 == nums[1]=1`，`cur` 重置为 1，`ans=4`；`i=3` 同理 `cur=1`，`ans=5`。关键中间值是 `i=2` 处的重置：`cur` 从 2 掉回 1，这一步决定了 `[1,1]` 不被计入。

```python
ans = 0
cur = 1
for i, x in enumerate(nums):
    if i > 0 and x != nums[i - 1]:
        cur += 1
    else:
        cur = 1
    ans += cur
return ans
```

注意 `i=0` 时走 `else` 分支把 `cur` 设为 1，与初值一致，不会重复计数。

## 复杂度
时间 O(n)：一次遍历，每个 `nums[i]` 只比较一次。
空间 O(1)：只开了 `ans`、`cur`、`i`、`x` 几个标量。

## 易错点
- 输入 `[1,1]` → 若只在 `x != nums[i-1]` 时 `cur += 1` 而不重置，`cur` 会停在 1 但漏掉「相等时必须归 1」的语义，后续若接 `0` 会错算成 `cur=2` 而实际最长交替段只有 `[1,0]` 长度 2 但起点错位 → 正确做法是 `else` 分支显式 `cur = 1`。
- 输入 `[1,0,1,0]` → 若把 `ans += cur` 写在循环外只加一次，得到 4 而非 10 → 正确做法是每轮循环内累加，因为以每个下标结尾的计数互不相同。
