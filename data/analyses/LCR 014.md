## 一句话思路
用长度固定为 `len(s1)` 的滑动窗口在 `s2` 上滑动，窗口内字符计数与 `s1` 计数完全相等即命中。

## 怎么做
1. 若 `len(s1) > len(s2)` 直接返回 `False`，否则窗口长度 `k = len(s1)` 永远合法。
2. 用长度 26 的数组 `need` 记 `s1` 各字母频次，`win` 记 `s2` 前 `k` 个字符频次。
3. 每步比较 `need == win`，相等返回 `True`；否则右移一格：加入 `s2[i]`、移除 `s2[i-k]`。
4. 扫完 `s2` 仍无相等则返回 `False`。

以 `s1="ab", s2="eidbaooo"` 为例，`k=2`，`need` 中 `a:1,b:1`。初始窗口 `"ei"` 的 `win` 是 `e:1,i:1`，不等；滑到 `i=3` 时窗口为 `"db"`，`win` 是 `d:1,b:1`，仍不等；`i=4` 时窗口 `"ba"`，`win` 变成 `b:1,a:1`，与 `need` 相等，返回 `True`。

```python
need = [0] * 26
win = [0] * 26
for ch in s1:
    need[ord(ch) - 97] += 1
for ch in s2[:k]:
    win[ord(ch) - 97] += 1
if need == win:
    return True
for i in range(k, len(s2)):
    win[ord(s2[i]) - 97] += 1
    win[ord(s2[i - k]) - 97] -= 1
    if need == win:
        return True
return False
```

## 复杂度
时间：O(len(s2) + 26·len(s2))，每次比较两个 26 长数组，`len(s1)` 只贡献建表。
空间：O(1)，只开两个长度 26 的定长数组，与输入规模无关。

## 易错点
- `s1="a", s2="a"` 这类 `len(s1) == len(s2)` 的输入 → 若循环写成 `range(k, len(s2))` 却不先比较初始窗口，会漏判直接返回 `False` → 必须在进入循环前先比一次 `need == win`。
- `s1="ab", s2="a"` 这种 `len(s1) > len(s2)` 的输入 → 切片 `s2[:k]` 只取到 `"a"`，`win` 长度不足却仍继续滑窗，`i-k` 变负数索引到 `s2` 尾部，计数错乱 → 开头先判 `len(s1) > len(s2)` 返回 `False`。

## 如果面试官追问
若字符集从 26 个小写字母扩到全部 Unicode，怎么做？答：把定长数组换成 `collections.Counter` 或字典，比较改为逐键比对，复杂度不变但常数变大。
