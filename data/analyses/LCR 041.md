## 一句话思路
用 `collections.deque` 维护窗口内元素并同步维护 `total`，每次 `next` 只做一次入队、至多一次出队，O(1) 得到平均值。

## 怎么做
1. 初始化：`self.size = size`、`self.q = deque()`、`self.total = 0`。
2. `next(val)` 先把 `val` 入队并累加到 `total`。
3. 若 `len(self.q) > self.size`，弹出队头 `old` 并从 `total` 减去它。
4. 返回 `self.total / len(self.q)`，注意分母是**当前队列长度**而非 `size`。

拿官方示例走一遍：`size=3`，依次 `next(1)`、`next(10)`、`next(3)` 后 `q=[1,10,3]`、`total=14`，返回 `14/3=4.66667`；再 `next(5)` 时先入队得 `q=[1,10,3,5]`、`total=19`，长度 4>3 弹出 `old=1`，`total=18`、`q=[10,3,5]`，返回 `18/3=6.0`。关键中间值是出队后的 `total=18`——若忘记减 `old`，这里会错成 `19/3≈6.333`。

```python
from collections import deque

class MovingAverage:
    def __init__(self, size: int):
        self.size = size
        self.q = deque()
        self.total = 0

    def next(self, val: int) -> float:
        self.q.append(val)
        self.total += val
        if len(self.q) > self.size:
            self.total -= self.q.popleft()
        return self.total / len(self.q)
```

## 复杂度
时间：每次 `next` 均摊 O(1)，入队出队各至多一次，共 10^4 次调用。
空间：O(size)，`deque` 最多存 `size` 个元素，`total` 是单个整数。

## 易错点
- 窗口未满时用 `size` 做分母 → 示例中 `next(1)` 会返回 `1/3≈0.333` 而非 `1.0` → 分母必须取 `len(self.q)`，只有满窗后才恒等于 `size`。
- 先判断再入队（`if len(q)==size: popleft()` 写在 `append` 之前）→ 满窗时窗口变成 `[10,3]` 少一个元素，`next(5)` 返回 `13/2=6.5` → 正确顺序是先 `append` 再判 `len > size` 出队。

## 如果面试官追问
追问：`size` 很大且要求 O(1) 内存怎么办？答：用环形数组固定 `size` 个槽位加下标取模覆盖，省掉 `deque` 的节点开销。
