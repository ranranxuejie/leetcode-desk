## 一句话思路
维护已覆盖区间 `[1, reach]`，排序后能接上就扩区间，接不上就补 `reach+1`，这是唯一能最小化补币数的贪心。

## 怎么做
1. 对 `coins` 升序排序，初始化 `reach = 0`、`ans = 0`、`i = 0`。
2. 当 `reach < target` 时，若 `i < len(coins)` 且 `coins[i] <= reach + 1`，则 `reach += coins[i]`、`i += 1`。
3. 否则补一枚面值 `reach + 1`，`ans += 1`、`reach += reach + 1`。
4. 循环结束返回 `ans`。

以 `coins = [1,4,10], target = 19` 为例：先吃 1 得 `reach = 1`；4 > 2，补 2 后 `reach = 3`、`ans = 1`；此时 4 ≤ 4，吃 4 得 `reach = 7`；10 > 8，补 8 后 `reach = 15`、`ans = 2`；10 ≤ 16，吃 10 得 `reach = 25 ≥ 19`，返回 2。关键中间值是补 2 后 `reach` 从 1 跳到 3，正好让 4 变得可接。

```python
coins.sort()
reach = ans = i = 0
while reach < target:
    if i < len(coins) and coins[i] <= reach + 1:
        reach += coins[i]
        i += 1
    else:
        reach += reach + 1
        ans += 1
return ans
```

## 复杂度
时间：排序 O(n log n)，扫描 O(n + log target)，n 为 `coins` 长度。
空间：排序栈开销 O(log n)，其余只有 `reach`、`ans`、`i` 三个变量。

## 易错点
- `coins = [1,1,1], target = 20` → 若把补币写成 `reach += 1`，会补 17 枚而不是 3 枚 → 正确是补 `reach + 1` 后 `reach` 翻倍为 `2*reach + 1`，即 1→3→7→15→31。
- `coins = [1,4,10], target = 19` → 若判断条件写成 `coins[i] <= reach`，4 > 1 会被跳过，先补 2 再补 8 变成 3 枚 → 正确条件是 `coins[i] <= reach + 1`，因为 `reach+1` 这枚币本身就能由「已有 1..reach 加一枚 reach+1」凑出。

## 如果面试官追问
问：要输出具体补了哪些面值？
答：在 `else` 分支里把 `reach + 1` 追加到结果列表，其余逻辑不变。
