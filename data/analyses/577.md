## 一句话思路
用 `Employee LEFT JOIN Bonus` 保留全部员工，再筛 `bonus < 1000 OR bonus IS NULL`。

## 怎么做
1. 以 `Employee` 为左表 `LEFT JOIN Bonus ON e.empId = b.empId`，保证没奖金的员工不被丢掉。
2. 连接后 Brad(3)、John(1) 的 `b.bonus` 为 `None`，Dan(2) 为 500，Thomas(4) 为 2000。
3. 过滤条件写成 `b.bonus < 1000 OR b.bonus IS NULL`，`None < 1000` 在 SQL 里是 UNKNOWN，必须显式补 `IS NULL`。
4. 只 `SELECT e.name, b.bonus`，输出 Brad/None、John/None、Dan/500，Thomas 被 2000 挡掉。

```python
# 关键三行（伪 SQL 表达，落到 pandas 即 merge + 布尔掩码）
# SELECT e.name, b.bonus
# FROM Employee e LEFT JOIN Bonus b ON e.empId = b.empId
# WHERE b.bonus < 1000 OR b.bonus IS NULL
merged = employee.merge(bonus, on="empId", how="left")
mask = (merged["bonus"] < 1000) | merged["bonus"].isna()
result = merged.loc[mask, ["name", "bonus"]]
```

中间值核对：`how="left"` 后行数仍是 4（不是 2），Brad 那行 `bonus` 是 `NaN`；`NaN < 1000` 得 `False`，所以 `| isna()` 这一半不能省，否则 Brad、John 直接消失，只剩 Dan。

## 复杂度
时间 O(n+m)：n 为 Employee 行数，m 为 Bonus 行数，连接各扫一遍。
空间 O(n)：左连接结果最多 n 行，另存一个长度 n 的布尔掩码。

## 易错点
- 用 `INNER JOIN`：输入示例里 Brad、John 在 Bonus 无匹配行 → 结果只剩 Dan 一行，漏掉两个 `null` 员工 → 必须 `LEFT JOIN`，让 Employee 全保留。
- 只写 `bonus < 1000`：Brad 的 `bonus` 是 `NULL`，`NULL < 1000` 求值为 UNKNOWN 被过滤掉 → 输出缺 Brad、John → 条件补 `OR bonus IS NULL`（pandas 里补 `| isna()`）。

## 如果面试官追问
问：Bonus 表若一个员工有多条记录怎么办？答：先按 `empId` 聚合（如 `MIN(bonus)`）再左连接，否则左连接会放大 Employee 行数、同一员工重复出现。
