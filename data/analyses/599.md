## 一句话思路
把 list1 的值→下标建成哈希表，扫 list2 时直接查表算 `i + j`，边扫边维护最小和与答案列表。

## 怎么做
1. 遍历 list1，建 `pos = {s: i}`，因为 list1 元素唯一，映射无歧义。
2. 初始化 `best = 2**31 - 1`、`ans = []`，扫 list2 的 `j, s`。
3. 若 `s in pos`，算 `total = pos[s] + j`，与 `best` 比较：更小就重置 `ans = [s]` 并更新 `best`，相等就 `ans.append(s)`。
4. 返回 `ans`。

以示例 3 为例：`pos = {"happy":0, "sad":1, "good":2}`。扫 list2 到 `j=0, s="sad"` 时 `total = 1+0 = 1`，`best` 从 `2**31-1` 降到 1，`ans = ["sad"]`；到 `j=1, s="happy"` 时 `total = 0+1 = 1` 等于 `best`，`ans` 变成 `["sad","happy"]`；到 `j=2, s="good"` 时 `total = 4 > 1`，丢弃。最终两个都留。

```python
pos = {s: i for i, s in enumerate(list1)}
best, ans = 2**31 - 1, []
for j, s in enumerate(list2):
    if s in pos:
        total = pos[s] + j
        if total < best:
            best, ans = total, [s]
        elif total == best:
            ans.append(s)
return ans
```

关键在 `elif`：相等必须追加而不是覆盖，否则示例 3 只剩 `["happy"]`。

## 复杂度
时间 O(n + m)，n = len(list1) 建表，m = len(list2) 扫一遍，每次查表 O(1)。
空间 O(n)，`pos` 存 list1 全部 n 个字符串；`ans` 最坏 O(min(n, m))。

## 易错点
1. 用 `if total <= best` 覆盖写 `ans = [s]` → 示例 3 输出 `["happy"]`，漏掉 `"sad"`。正确做法是严格小于才重置，等于走 `elif` 追加。
2. `best` 初值设成 0 或 `len(list1)+len(list2)` 之外的怪值 → 前者导致第一个公共串的 `total` 永远不小于 `best`，`ans` 空；后者在极端输入下可能被真实 `total` 顶掉。用 `2**31 - 1` 或 `float('inf')` 最稳。

## 如果面试官追问
问：list1/list2 各到 10^5 且允许重复怎么办？
答：重复时同串取最小下标建表（`setdefault` 保留首次），其余逻辑不变，仍是 O(n+m)。
