## 一句话思路
只有零元素两侧的「左段和」与「右段和」相等时，该零位置的两个方向才可能有效，逐零检查即可。

## 怎么做
1. 先求 `total = sum(nums)`，它是所有非零元素要被打掉的次数总和。
2. 从左往右扫描，维护 `left` = 当前下标左侧元素之和；遇到 `nums[i] == 0` 时，`right = total - left`。
3. 若 `left == right`，则 `curr = i` 向左、向右两个方案都有效，答案加 2；否则加 0。
4. 扫描时把 `nums[i]` 累加进 `left`（零加不加都一样）。

以 `nums = [1,0,2,0,3]`，`total = 6` 为例：扫到 `i = 1` 时 `left = 1`、`right = 5`，不等；扫到 `i = 3` 时 `left = 1 + 0 + 2 = 3`、`right = 6 - 3 = 3`，相等，答案 +2，最终得 2。

```python
total = sum(nums)
left = ans = 0
for x in nums:
    if x == 0 and left == total - left:
        ans += 2
    left += x
return ans
```

关键点：`left` 必须在判断之后再加 `x`，否则零位置会把自身（0）算进去——虽然加 0 不影响数值，但若把判断写在累加后、且 `x` 非零，就会错位。

## 复杂度
时间 O(n)：一次求和加一次扫描，n 为 `nums` 长度。
空间 O(1)：只用了 `total`、`left`、`ans` 三个变量。

## 易错点
- 输入 `[0]` → 若误以为「必须移动过才算有效」会返回 0 → 正确做法是 `left = right = 0` 成立，返回 2（向左、向右各一种，虽然一步就出界，但数组已全零）。
- 输入 `[2,3,4,0,4,1,0]` → 若只比较零两侧的「元素个数」而非「元素和」会误判 → 必须比较 `left` 与 `total - left` 的数值和，这里 `total = 14`，两个零处都不等，返回 0。

## 如果面试官追问
问：若要求输出所有有效方案的具体 (curr, 方向) 列表？
答：把 `ans += 2` 换成向结果追加 `(i, -1)` 和 `(i, 1)`，其余不变。
