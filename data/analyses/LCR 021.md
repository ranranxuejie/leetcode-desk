## 一句话思路
快慢双指针保持 n 个间距，快指针到尾时慢指针正好停在待删结点的前驱。

## 怎么做
1. 建哑结点 `dummy` 指向 `head`，让 `slow = fast = dummy`，这样删头结点时也有前驱可改。
2. `fast` 先走 `n + 1` 步，把间距拉开到「慢指针落后 n+1 个位置」。
3. `fast` 和 `slow` 同步前进，直到 `fast is None`。
4. 此时 `slow.next` 就是倒数第 n 个结点，执行 `slow.next = slow.next.next`，返回 `dummy.next`。

以 `head = [1,2,3,4,5], n = 2` 为例：`fast` 先走 3 步到结点 `3`，`slow` 仍在 `dummy`；同步走 2 轮后 `fast` 到 `5`、`slow` 到 `2`；再走一轮 `fast` 变 `None`，`slow` 停在 `3`，`slow.next` 是 `4`，删掉后得 `[1,2,3,5]`。

```python
dummy = ListNode(0, head)
slow = fast = dummy
for _ in range(n + 1):
    fast = fast.next
while fast:
    slow = slow.next
    fast = fast.next
slow.next = slow.next.next
return dummy.next
```

关键在 `n + 1` 而不是 `n`：走 `n` 步时 `slow` 会落在待删结点本身，拿不到前驱，只能靠 `slow.next = slow.next.next` 之外的写法绕，容易写错。

## 复杂度
时间 O(sz)：`fast` 走 `sz + 1` 步，一趟扫描。
空间 O(1)：只开了 `dummy`、`slow`、`fast` 三个指针。

## 易错点
- `head = [1], n = 1` → 若不加 `dummy`，`slow` 无处可停，删头结点时直接返回 `None` 或改不动 `head` → 必须用 `dummy` 并返回 `dummy.next`。
- `head = [1,2], n = 1` → 若 `fast` 只先走 `n` 步，`slow` 会停在结点 `2`（待删结点本身），`slow.next = slow.next.next` 删的是 `None` 的后继，链表不变 → 先走 `n + 1` 步，让 `slow` 落在 `1`。

## 如果面试官追问
问：能不能不用 `dummy`？答：可以，先让 `fast` 走 `n` 步，若 `fast` 已为 `None` 说明删的是头结点，直接返回 `head.next`，否则再同步走到 `fast.next is None`，此时 `slow` 是前驱。
