## 一句话思路
按 nums2 升序排序后做 DP：dp[j] 表示重置 j 个元素时能省下的最大和，答案取最小可行 j。

## 怎么做
1. 把 (nums2[i], nums1[i]) 按 nums2 升序排序，因为越晚重置的元素被乘的时间越大，应配越大的 nums2。
2. 设 sum1=sum(nums1)、sum2=sum(nums2)。若重置 j 个元素，第 k 个被重置的元素（按重置顺序第 k 次，k 从 1 计）贡献的减少量是 nums1[i] + k*nums2[i]。
3. 用 dp[j] 记录「已选 j 个元素重置」时的最大减少量，对每个元素倒序更新 dp[j] = max(dp[j], dp[j-1] + nums1[i] + j*nums2[i])。
4. 从 j=0 到 n 找第一个满足 sum1 + j*sum2 - dp[j] <= x 的 j，返回 j；都不满足返回 -1。

以示例 1 为例，排序后仍是 [(1,1),(2,2),(3,3)]，sum1=6，sum2=6。处理到第三个元素时 dp[3] = dp[2] + 3 + 3*3 = 3 + 12 = 15，此时 6 + 3*6 - 15 = 9 > 4；而 dp[3] 实际最优是选全部三个：1+1*1 + 2+2*2 + 3+3*3 = 2+6+12 = 20，6+18-20 = 4 <= 4，返回 3。

```python
a = sorted(zip(nums2, nums1))
s1, s2 = sum(nums1), sum(nums2)
dp = [-1] * (n + 1)
dp[0] = 0
for i, (b, v) in enumerate(a, 1):
    for j in range(i, 0, -1):
        if dp[j-1] >= 0:
            dp[j] = max(dp[j], dp[j-1] + v + j * b)
for j in range(n + 1):
    if s1 + j * s2 - dp[j] <= x:
        return j
return -1
```

## 复杂度
时间：O(n²)，排序 O(n log n) 被 n² 的 DP 双循环盖过。
空间：O(n)，dp 数组长度 n+1，排序额外 O(n)。

## 易错点
- 忘记按 nums2 升序排序 → 示例 1 恰好有序看不出错，但 nums2=[3,1,2] 这类输入会把大 nums2 配到早重置的位置，dp 值偏小、答案偏大；必须先 `sorted(zip(nums2, nums1))`。
- 内层 j 写成正序 → 同一元素被重复计入 dp[j]，示例 1 会算出 dp[3] 虚高、错误返回更小的 j；必须 `range(i, 0, -1)` 倒序，保证 dp[j-1] 还是上一轮的值。

## 如果面试官追问
问：n 放大到 10^5 怎么办？
答：dp 的 O(n²) 撑不住，但答案 j 有上界（j*sum2 增长快），可只维护前 O(sqrt(x)) 层或改用贪心+二分验证。
