## 一句话思路
用 BFS 维护「已拥有但未开」和「有钥匙但未到手」两个集合，任一条件满足即入队开箱。

## 怎么做
1. 把 `initialBoxes` 全部标记为「已拥有」，其中 `status[i]==1` 的直接入队。
2. 开箱时累加 `candies[i]`，把 `keys[i]` 标记为「有钥匙」，把 `containedBoxes[i]` 标记为「已拥有」。
3. 每次新获得钥匙或新获得盒子，都检查对方集合是否已具备，具备则入队。
4. 队列空即结束，返回累加值。

以示例 1 为例：初始拥有 `{0}`，`status[0]=1` 入队。开 0 得 7 糖果，钥匙无，盒子 `{1,2}` 入拥有集；`status[2]=1` 入队。开 2 得 4 糖果，钥匙 `{1}` 入钥匙集，此时盒子 1 同时在拥有集和钥匙集，入队。开 1 得 5 糖果，盒子 `{3}` 入拥有集但无钥匙，停。总计 7+4+5=16。

```python
from collections import deque
have = [False] * n          # 已拥有盒子
key = [False] * n           # 已有钥匙
q = deque()
for b in initialBoxes:
    have[b] = True
    if status[b] == 1:
        q.append(b)
ans = 0
while q:
    b = q.popleft()
    ans += candies[b]
    for k in keys[b]:
        key[k] = True
        if have[k]:
            q.append(k)
    for c in containedBoxes[b]:
        have[c] = True
        if key[c] or status[c] == 1:
            q.append(c)
```

## 复杂度
时间 O(n + 总钥匙数 + 总内含盒数)，每个盒子至多入队一次。
空间 O(n)，`have`、`key` 两个布尔数组加队列。

## 易错点
- 初始 `initialBoxes` 里 `status=0` 的盒子：若只按 `status` 判断入队会直接丢掉它，之后拿到钥匙也找不回来 → 必须先全部记入 `have`，等钥匙到达时再入队。
- 同一盒子可能被「钥匙到达」和「盒子到达」两条路径各触发一次入队 → 示例 1 的盒子 1 先随盒子 2 的钥匙变可用，若不加 `visited` 或出队后不再重复处理，糖果会被加两次，答案变 21 而非 16。

## 如果面试官追问
若要求输出开箱顺序而非糖果数？答：BFS 队列的出队序列就是合法顺序，但需保证「钥匙先于盒子」的依赖，改用拓扑排序按依赖边建图。
