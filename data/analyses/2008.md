## 一句话思路
按终点排序后做 DP：`dp[i]` 表示前 i 个地点最大盈利，接单时用二分找上一个不冲突的订单。

## 怎么做
1. 把每个订单的盈利 `end - start + tip` 预先算好，按 `end` 升序排序。
2. 定义 `dp[i]` 为「只考虑前 i 个订单」的最大盈利，`dp[0] = 0`。
3. 对第 i 个订单（1-indexed），二分找最后一个 `end <= start_i` 的订单下标 `j`，转移 `dp[i] = max(dp[i-1], dp[j] + profit_i)`。
4. 答案即 `dp[len(rides)]`。

以示例 2 为例，排序后第 3 个订单是 `[10,12,3]`，profit = 5；二分找 `end <= 10` 的最后一个订单，命中 `[3,10,2]`（下标 2），于是 `dp[3] = max(dp[2]=9, dp[2]+5=14) = 14`。注意 `dp[2]` 本身已是 9，说明「不接」分支不能丢。

```python
rides.sort(key=lambda r: r[1])
ends = [r[1] for r in rides]
dp = [0] * (len(rides) + 1)
for i, (s, e, t) in enumerate(rides, 1):
    j = bisect_right(ends, s, 0, i - 1)  # 前 i-1 个里找 end<=s
    dp[i] = max(dp[i - 1], dp[j] + e - s + t)
return dp[-1]
```

关键在 `bisect_right(ends, s, 0, i - 1)` 的 `hi` 参数：只在已处理的前 `i-1` 个订单里搜，避免搜到自己。

## 复杂度
时间：排序 O(m log m) + 每个订单二分 O(m log m)，m = len(rides)。
空间：`dp` 与 `ends` 各 O(m)，与 n 无关。

## 易错点
- 二分范围写成整个 `ends` 数组 → 可能命中 `end > start` 的后续订单，转移出非法状态；必须把 `hi` 限制为 `i - 1`，只在已决策的订单里找。
- 忘记 `dp[i] = max(dp[i-1], ...)` 的「不接」分支 → 遇到 `[1,5,1]` 这类低盈利长订单时，`dp` 会倒退；正确写法是每步都取 `dp[i-1]` 与接单值中的较大者。

## 如果面试官追问
若 n 缩小到 1000 但 rides 不变，能否 O(n + m)？答：可以，用 `dp[x]` 按地点递推，`dp[e] = max(dp[e], dp[s] + profit)`，遍历 1..n 即可。
