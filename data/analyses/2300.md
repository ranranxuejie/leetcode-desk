## 一句话思路
把 potions 排序后，对每个 spells[i] 二分找第一个满足 `spells[i]*potions[j] >= success` 的下标，其后数量即答案。

## 怎么做
1. 先 `potions.sort()`，让「乘积 ≥ success」变成后缀性质。
2. 对每个 `s in spells`，用 `bisect_left` 找最小药水强度 `need = (success + s - 1) // s`。
3. 该下标到末尾的元素个数 `m - idx` 就是 `pairs[i]`。

以示例 1 为例：`potions` 排序后仍是 `[1,2,3,4,5]`。对 `s=5`，`need = (7+4)//5 = 2`，`bisect_left(potions, 2)` 返回 1，答案 `5-1=4`；对 `s=1`，`need=7`，返回 5，答案 0；对 `s=3`，`need=(7+2)//3=3`，返回 2，答案 3。

```python
from bisect import bisect_left

potions.sort()
m = len(potions)
pairs = []
for s in spells:
    need = (success + s - 1) // s
    idx = bisect_left(potions, need)
    pairs.append(m - idx)
```

关键在 `need` 用向上取整，避免浮点除法；`bisect_left` 找到第一个 `>= need` 的位置，后面全部满足。

## 复杂度
时间：排序 `O(m log m)`，每个咒语二分 `O(n log m)`，合计 `O((n+m) log m)`。
空间：`O(1)` 额外空间（不计排序栈和输出数组）。

## 易错点
1. 用 `success // s` 向下取整 → 示例 1 中 `s=5` 得 `need=1`，`bisect_left` 返回 0，答案错成 5 而非 4。正确写法是 `(success + s - 1) // s`。
2. 对每个咒语线性扫描 potions → `n,m` 都到 `10^5` 时是 `10^10` 次比较，超时。必须先排序再二分，把内层降到 `log m`。

## 如果面试官追问
若 spells 也有序，能否双指针做到 `O(n+m)`？可以：potions 升序时，spells 升序会让所需药水阈值单调下降，指针从右往左移动即可。
