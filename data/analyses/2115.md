## 一句话思路
把菜当节点、原料依赖当入边做拓扑排序，入度归零即“所有原料已具备”，可做。

## 怎么做
1. 用 `have = set(supplies)` 记录已拥有物，`indeg` 只统计原料里属于 `recipes` 的那些（外部原料靠 `have` 判断）。
2. 建反图 `graph[原料] -> [用到它的菜]`，只对 `ingredients[i]` 中出现在 `recipes` 里的字符串建边。
3. 初始队列放所有 `indeg[r] == 0` 的菜，逐个出队加入 `have` 和答案，并把反图邻居入度减一。
4. 入度减到 0 的菜入队，循环到队列空。

以示例 3 为例：`indeg = {"bread":0, "sandwich":1, "burger":2}`，队列初始只有 `bread`；弹出 `bread` 后 `sandwich` 入度变 0 入队，再弹 `sandwich` 使 `burger` 入度从 2 变 1，最后弹 `sandwich` 的邻居才让 `burger` 归零——注意 `burger` 的原料含 `bread` 和 `sandwich` 两个菜，两条边都要减。

```python
from collections import deque, defaultdict
have = set(supplies)
indeg = {r: 0 for r in recipes}
graph = defaultdict(list)
for r, ings in zip(recipes, ingredients):
    for x in ings:
        if x in indeg:
            indeg[r] += 1
            graph[x].append(r)
q = deque(r for r in recipes if indeg[r] == 0)
ans = []
while q:
    r = q.popleft()
    ans.append(r)
    for nxt in graph[r]:
        indeg[nxt] -= 1
        if indeg[nxt] == 0:
            q.append(nxt)
```

## 复杂度
时间 O(n + m)，n 是菜数、m 是原料条目总数，每条边进出各一次。
空间 O(n + m)，存 `indeg`、反图 `graph` 和队列。

## 易错点
- 示例 4：`ingredients = [["yeast","flour"]]` 但 `supplies = ["yeast"]`，若只按“原料在 recipes 里才计入度”就漏判 `flour` 缺失，`bread` 入度为 0 被误判可做。正确做法是入度只数菜类原料，但出队前还要校验非菜原料是否都在 `have` 里（或建图时把缺失外部原料的菜直接标记不可做）。
- 示例 3 的 `burger` 原料含 `bread` 和 `sandwich` 两道菜，若只对 `ingredients[i]` 去重或只建一条边，`indeg["burger"]` 会是 1 而非 2，`bread` 一出队就误判 `burger` 可做。正确做法是每个菜类原料各建一条边、各计一次入度。

## 如果面试官追问
问：若要求输出做菜顺序而非集合？答：拓扑序本身就是合法顺序，直接返回 `ans` 即可，无需额外处理。
