## 一句话思路
排序后从小到大贪心配对：每个未用的 `x` 必须配 `2x`，用哈希表计数即可。

## 怎么做
1. 若 `len(changed)` 为奇数，直接返回 `[]`。
2. 对 `changed` 排序，用 `Counter` 记录每个值的剩余次数。
3. 从小到大遍历 `x`：若 `cnt[x] == 0` 跳过；否则消耗一个 `x` 和一个 `2x`，把 `x` 加入答案。
4. 若某步 `cnt[2*x] == 0`，说明配不上，返回 `[]`。

以 `changed = [1,3,4,2,6,8]` 排序后为 `[1,2,3,4,6,8]`。处理 `x=1` 时 `cnt[2]=1`，消耗后 `cnt[1]=0, cnt[2]=0`，答案加入 `1`；接着 `x=2` 已为 0 跳过；`x=3` 配 `6`，`x=4` 配 `8`，得 `[1,3,4]`。

```python
from collections import Counter

def findOriginalArray(changed):
    if len(changed) % 2:
        return []
    cnt = Counter(changed)
    ans = []
    for x in sorted(cnt):
        if cnt[x] == 0:
            continue
        if cnt[2 * x] < cnt[x]:
            return []
        cnt[2 * x] -= cnt[x]
        ans.extend([x] * cnt[x])
        cnt[x] = 0
    return ans
```

关键点：`x=0` 时 `2*x` 还是 `0`，`cnt[0]` 必须成对消耗，`cnt[0]` 为奇数就失败。

## 复杂度
时间 O(n log n)：排序贡献 log n，遍历 n 个不同值。
空间 O(n)：`Counter` 存至多 n 个键，答案数组 n/2。

## 易错点
- `changed = [0,0,0]` → 长度奇数直接返回 `[]` 是对的，但 `[0,0]` 要返回 `[0]`；若把 `x=0` 当普通元素配 `2x=0` 会重复消耗同一个 0，必须让 `cnt[0]` 一次性减半。
- `changed = [4,2,1]` → 排序后 `x=1` 配 `2`，剩 `4` 无 `8`，返回 `[]`；若从大到小贪心会先配 `4` 找不到 `8` 误判，必须从小到大。

## 如果面试官追问
问：若 `changed` 长度到 10^7 且值域已知，怎么优化？
答：用值域数组代替 `Counter` 和排序，按值从小到大扫一遍，O(n + V)。
