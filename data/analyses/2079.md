## 一句话思路
按顺序模拟浇水，水不够就回河边，步数 = n 次前进 + 每次回程的 2×位置。

## 怎么做
1. 维护 `water = capacity` 和 `steps = 0`，从 `i = 0` 开始遍历。
2. 每株植物先判断：若 `water < plants[i]`，说明必须回河边，`steps += 2 * i`，`water = capacity`。
3. 然后前进一格 `steps += 1`，浇水 `water -= plants[i]`。

用示例 1 `plants = [2,2,3,3], capacity = 5`：浇完植物 1 后 `water = 1`，到 `i = 2` 时 `1 < 3`，触发回程 `steps += 2 * 2 = 4`，`water` 重置为 5，再 `steps += 1` 前进浇水。注意回程距离是 `2 * i`（从位置 i 走回 -1 再走回 i），不是 `2 * (i + 1)`。

```python
water = capacity
steps = 0
for i, need in enumerate(plants):
    if water < need:
        steps += 2 * i
        water = capacity
    steps += 1
    water -= need
return steps
```

关键点：回程发生在**到达植物 i 之前**，此时人还在位置 `i - 1`，但回河边再回来要走到 `i`，所以往返是 `2 * i`。示例 1 中 `i = 2` 时 `steps` 从 2 跳到 6（+4），再 +1 到 7，与官方解释的 `1+1+2+3` 一致。

## 复杂度
时间：O(n)，一次遍历，n 为 plants 长度。
空间：O(1)，只用了 water 和 steps 两个变量。

## 易错点
- 输入 `plants = [7,7,7,7,7,7,7], capacity = 8`：若把回程写成 `2 * (i + 1)`，每株都多算 2 步，答案从 49 变成 63。正确做法是回程距离用当前位置 `i`，因为从 `i-1` 出发回河边再走到 `i` 恰好是 `i + i`。
- 输入 `plants = [1,1,1,4,2,3], capacity = 4`：若在浇完当前植物后才判断下一株（即先 `water -= need` 再检查），`i = 3` 时 `water` 已为 0，会漏掉回程或错位。正确做法是先判断 `water < plants[i]` 再浇水，保证回程发生在到达该植物之前。

## 如果面试官追问
问：如果要求输出每次回河边的位置列表怎么办？
答：在 `water < need` 分支里把 `i` 追加到结果数组，其余逻辑不变，时间空间仍是 O(n)。
