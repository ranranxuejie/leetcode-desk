## 一句话思路
维护前缀和 `pos`，每步后判断 `pos == 0` 就计数，因为蚂蚁位置就是 nums 的前缀和。

## 怎么做
1. 初始化 `pos = 0`、`ans = 0`，`pos` 表示蚂蚁相对边界的位移。
2. 遍历 `nums`，每步执行 `pos += x`，把「向左 `-nums[i]`」和「向右 `nums[i]`」统一成加法。
3. 累加后立刻判断 `pos == 0`，成立则 `ans += 1`。
4. 返回 `ans`。

拿示例 1 `nums = [2,3,-5]` 走一遍：`pos` 依次为 `2`、`5`、`0`，只有第三步后 `pos == 0`，所以 `ans = 1`。关键中间值是第二步后的 `pos = 5`，第三步 `5 + (-5) = 0` 才命中。

```python
pos = 0
ans = 0
for x in nums:
    pos += x
    if pos == 0:
        ans += 1
return ans
```

注意判断写在 `pos += x` 之后，不能写在之前——写在之前会把「起点在边界」误算一次，而题面只统计移动后回到边界。

## 复杂度
时间：O(n)，n 为 `nums` 长度，每个元素一次加法一次比较。
空间：O(1)，只开了 `pos` 和 `ans` 两个整数。

## 易错点
- 输入 `nums = [1,-1]` → 若在循环开头判断 `pos == 0`，会在第一步前多算一次（初始 `pos` 就是 0）→ 正确做法是判断放在 `pos += x` 之后，只统计移动结束时的位置。
- 输入 `nums = [2,3,-5]` → 若把「移动过程中穿过边界」也算进去（比如认为从 5 走到 0 途中经过边界）→ 会多算；题面明确只在移动 `|nums[i]|` 单位后检查，所以只看每步结束的 `pos`，中途不判。

## 如果面试官追问
问：如果要求返回每次回到边界时的步数下标列表？
答：把 `ans += 1` 换成 `ans.append(i)`，`i` 是当前遍历下标，其余不变。
