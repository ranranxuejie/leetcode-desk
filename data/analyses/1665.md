## 一句话思路
按 `minimum - actual` 降序排，再倒推所需初始能量，因为差值大的任务越该早做。

## 怎么做
1. 排序键取 `minimum_i - actual_i`，降序。
2. 从后往前扫，维护「完成当前后缀所需的最小初始能量」`need`。
3. 对任务 `[a, m]`：进入它时能量至少 `max(m, need + a)`，更新 `need`。

以示例 2 为例，排序后差值降序为 `[1,3]`(2)、`[2,4]`(2)、`[8,9]`(1)、`[10,11]`(1)、`[10,12]`(2)——注意 `[10,12]` 差值为 2 应排前面，实际排序结果按差值降序是 `[1,3],[2,4],[10,12],[8,9],[10,11]`。倒推：`need` 从 0 起，处理 `[10,11]` 得 `max(11, 0+10)=11`；处理 `[8,9]` 得 `max(9, 11+8)=19`；处理 `[10,12]` 得 `max(12, 19+10)=29`；处理 `[2,4]` 得 `max(4, 29+2)=31`；处理 `[1,3]` 得 `max(3, 31+1)=32`。答案 32。

```python
tasks.sort(key=lambda t: t[1] - t[0], reverse=True)
need = 0
for a, m in reversed(tasks):
    need = max(m, need + a)
return need
```

关键中间值：处理到 `[10,12]` 时 `need` 已是 19，`19+10=29 > 12`，所以 `need` 被抬到 29，而不是停在 12。

## 复杂度
时间 O(n log n)：排序贡献 log n，倒扫 O(n)。
空间 O(1)：只开 `need` 一个变量（排序原地，不计入）。

## 易错点
- 按 `minimum` 升序或 `actual` 排序 → 示例 3 会得 33 而非 27 → 必须按 `minimum - actual` 降序，差值大的先做才能把「高门槛」任务放在能量充足时。
- 正着扫、用 `need = max(need, m) + a` 累加 → 示例 2 会得 34 → 正确是倒推 `need = max(m, need + a)`，因为门槛 `m` 只需在进入该任务时满足，不必叠加到后缀总和上。

## 如果面试官追问
要求输出具体任务顺序怎么办？答：排序后的正序即为一个可行顺序，倒推得到的 `need` 就是该顺序的初始能量，直接返回排序结果即可。
