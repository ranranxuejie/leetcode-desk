## 一句话思路
用哈希集合记录已出现过的值，遍历时把重复节点从链表里摘掉，保留首次出现的那个。

## 怎么做
1. 空链表或单节点直接返回 `head`，省掉建集合的开销。
2. 用 `seen = {head.val}` 存首节点值，`prev = head` 指向当前保留链的尾。
3. `cur = head.next` 开始遍历，值不在 `seen` 就加入集合并让 `prev = cur`，否则 `prev.next = cur.next` 跳过它。
4. 每轮末尾 `cur = cur.next`，最后返回 `head`。

以 `[1, 2, 3, 3, 2, 1]` 为例：走到第 4 个节点（第二个 `3`）时，`seen = {1, 2, 3}`，`3 in seen` 为真，执行 `prev.next = cur.next`，此时 `prev` 是第 3 个节点，它的 `next` 从第二个 `3` 改成第二个 `2`，链表变成 `1→2→3→2→1`，`prev` 不动；接着 `cur` 移到第二个 `2`，同样被摘掉。

```python
seen = {head.val}
prev, cur = head, head.next
while cur:
    if cur.val in seen:
        prev.next = cur.next
    else:
        seen.add(cur.val)
        prev = cur
    cur = cur.next
return head
```

关键点：删除时 `prev` 不前进，只有保留节点才更新 `prev`，这样连续重复（如 `[1,1,1,1,2]`）也能一路摘干净。

## 复杂度
时间 O(n)：`cur` 走一遍链表，每次集合查询 O(1)。
空间 O(n)：`seen` 最多存 n 个不同值，n 为链表长度。

## 易错点
- 输入 `[1, 1, 1, 1, 2]` → 若删除后也执行 `prev = cur`，`prev` 会指向已被摘掉的节点，后续 `prev.next` 改错位置导致链表断裂或残留重复 → 删除分支里 `prev` 必须原地不动。
- 输入 `[1, 2, 3, 3, 2, 1]` → 若用 `cur.val != prev.val` 判断相邻去重，只能去掉连续的 `3`，末尾的 `2`、`1` 会残留 → 未排序链表必须靠集合记录全部历史值，不能只比前驱。

## 如果面试官追问
追问：不用额外缓冲区怎么做？
答：双重循环，外层 `cur` 固定，内层 `runner` 从 `cur` 往后扫，遇到 `runner.next.val == cur.val` 就删，时间 O(n²)、空间 O(1)，n=20000 时约 4×10⁸ 次比较，能过但慢。
