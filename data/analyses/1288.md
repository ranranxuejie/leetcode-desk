## 一句话思路
按左端点升序、左端点相同时右端点降序排序，再单次扫描统计不被覆盖的区间数。

## 怎么做
1. 排序：`intervals.sort(key=lambda x: (x[0], -x[1]))`，左端点升序、右端点降序。
2. 维护当前能覆盖后续区间的最大右端点 `max_right`，初始为 `intervals[0][1]`。
3. 从第二个区间开始扫描：若 `intervals[i][1] <= max_right`，说明它被覆盖，跳过；否则计数加一，并更新 `max_right = intervals[i][1]`。
4. 返回计数（初始为 1，代表第一个区间）。

以官方示例 `[[1,4],[3,6],[2,8]]` 为例：排序后为 `[[1,4],[2,8],[3,6]]`。`max_right` 初始为 4；扫描 `[2,8]` 时 `8 > 4`，计数变 2，`max_right` 更新为 8；扫描 `[3,6]` 时 `6 <= 8`，被覆盖跳过。最终返回 2。

```python
intervals.sort(key=lambda x: (x[0], -x[1]))
count = 1
max_right = intervals[0][1]
for i in range(1, len(intervals)):
    if intervals[i][1] > max_right:
        count += 1
        max_right = intervals[i][1]
return count
```

关键点：左端点相同时右端点降序，保证大区间排在小区间前面，这样小区间会被 `max_right` 直接判定为覆盖，不会误计数。

## 复杂度
时间：排序 O(n log n)，扫描 O(n)，n 为区间个数。
空间：排序额外 O(log n) 栈空间，其余 O(1)。

## 易错点
- 输入 `[[1,4],[2,8],[3,6]]` 若只按左端点升序排序，`[3,6]` 排在 `[2,8]` 后仍能被 `max_right=8` 覆盖，但若输入 `[[1,10],[2,3],[4,5]]` 且排序不稳定，可能把 `[2,3]` 误判为独立区间；正确做法是左端点相同时右端点降序，确保大区间先出现。
- 输入 `[[1,2],[3,4]]` 两个区间互不覆盖，若把 `max_right` 初始化为 0 或忘记在 `intervals[i][1] > max_right` 时更新，会漏计第二个区间；正确做法是计数从 1 开始，每次遇到更大右端点时计数加一并更新 `max_right`。

## 如果面试官追问
若要求输出剩余区间的具体列表而非数目，怎么改？答：把 `count += 1` 改为将 `intervals[i]` 加入结果列表，最后返回列表即可。
