## 一句话思路
把交易分成「亏钱」和「不亏钱」两类，亏钱的按 cashback 降序先做，答案 = 亏钱组最大前缀缺口 + 全组净亏损。

## 怎么做
1. 设 `total = sum(cost - cashback)`，即全部做完后的净支出；设 `need = 0` 记录过程中最缺钱的时刻。
2. 只遍历 `cost > cashback` 的交易，按 `cashback` 从大到小排序，逐个累加 `cost - cashback` 得到前缀亏损 `s`，取 `need = max(need, s - cashback)`。
3. 返回 `need + total`。

用示例 1 `[[2,1],[5,0],[4,2]]`：亏钱组是 `[2,1]`（亏 1）和 `[5,0]`（亏 5），按 cashback 降序为 `[2,1]`、`[5,0]`。第一笔后 `s=1`，`s - cashback = 1-1 = 0`；第二笔后 `s=6`，`s - 0 = 6`，故 `need=6`。`total = 1+5-2 = 4`，答案 `6+4=10`。

```python
total = sum(c - b for c, b in transactions)
lose = sorted((b, c - b) for c, b in transactions if c > b)
need = s = 0
for b, d in reversed(lose):
    s += d
    need = max(need, s - b)
return need + total
```

关键在 `s - b`：做完这笔亏钱交易后，钱要先垫付 `cost`，而此前已累计亏 `s`，所以此刻最低要求是 `s - cashback`（因为这笔的 cashback 会立刻回血）。

## 复杂度
时间：排序亏钱组 O(k log k)，k ≤ n，其余 O(n)。
空间：排序额外 O(k)，即亏钱交易条数。

## 易错点
- 把不亏钱的交易也塞进排序 → 对 `[[3,0],[0,3]]` 会算出 `need` 偏大。正确做法是只对 `cost > cashback` 的排序，`[0,3]` 直接进 `total` 不参与 `need`。
- 排序方向写反成 cashback 升序 → 示例 1 会先做 `[5,0]` 得 `need=5`，再加 `[2,1]` 的 `s=6` 时 `s-b=5`，最终 `need=5`，答案 9 偏小。正确是按 cashback 降序，让回血多的先做。

## 如果面试官追问
问：要求输出具体交易顺序怎么办？
答：亏钱组按 cashback 降序排在前，不亏钱组任意顺序接在后，这个顺序就达到 `need + total`。
