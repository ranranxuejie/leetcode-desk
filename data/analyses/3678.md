## 一句话思路
用哈希集合存 nums，从 `floor(avg)+1` 起逐个试，第一个不在集合里的正整数就是答案。

## 怎么做
1. 求和 `s = sum(nums)`，长度 `n = len(nums)`，平均值 `avg = s / n`（浮点，别整除）。
2. 把 nums 全部塞进 `set(nums)`，O(1) 判断某个数是否出现过。
3. 起点取 `x = int(avg) + 1`；若 `avg` 恰为整数，`int(avg)+1` 正好是「严格大于」的下一个整数，若为小数，`int(avg)+1` 是向上取整，同样满足严格大于。
4. 从 `x` 开始 `while x in seen: x += 1`，返回 `x`。

以 `nums = [3,5]` 为例：`s = 8`，`n = 2`，`avg = 4.0`，`x = int(4.0)+1 = 5`；`5 in {3,5}` 为真，`x` 变 6；`6 in {3,5}` 为假，返回 6。再看 `nums = [-1,1,2]`：`avg = 2/3 ≈ 0.667`，`x = 0+1 = 1`；1 在集合里，2 也在，3 不在，返回 3。

```python
s, n = sum(nums), len(nums)
avg = s / n
seen = set(nums)
x = int(avg) + 1
while x in seen:
    x += 1
return x
```

关键点：`int(avg)` 对正数是向下取整，对负数是向零取整，但本题起点只关心「大于 avg 的最小整数」，`int(avg)+1` 在 avg 为负小数时（如 -0.5 → 0+1=1）也正确，因为正整数从 1 开始，而 1 > -0.5 恒成立。

## 复杂度
时间 O(n + k)，n 是建集合，k 是从起点到答案的试探步数，k ≤ n+1。
空间 O(n)，额外开了一个 `seen` 集合，最多 n 个元素。

## 易错点
- 用 `s // n` 求平均 → 对 `nums = [-1,1,2]` 得 `2//3 = 0`，起点变 1，但 1 在数组里、2 也在，仍能返回 3；可对 `nums = [3,5]` 得 `8//2 = 4`，起点 5，5 在集合里跳到 6，也对。真正翻车的是负数场景如 `nums = [-3,-3]`：`s//n = -3`，起点 -2，返回 -2 这个非正整数。必须用 `/` 浮点除。
- 从 1 开始暴力找而不从 `int(avg)+1` 起 → 对 `nums = [1,2,3,...,100]` 要白跑 100 步才到 101，虽然本题 n≤100 不会超时，但逻辑上起点应直接跳过平均值以下的所有数，否则等于没利用「大于平均值」这个条件。

## 如果面试官追问
问：若 nums 长度扩到 10^6 且值域到 10^9，还能这么做吗？
答：能，集合仍 O(n) 空间，试探步数上界是 n+1（答案不超过 n+1），总时间仍是 O(n)。
