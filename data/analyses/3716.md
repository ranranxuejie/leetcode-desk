## 一句话思路
按 user_id 分组，用窗口函数取每个用户的首末事件与当前状态，再聚合出降级次数和最高费用，最后用 WHERE 一次性筛四个条件。

## 怎么做
1. 用 `ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY event_date DESC)` 取 `rn=1` 的那行作为当前事件，拿到 `current_plan`、`current_monthly_amount`，并判断 `event_type != 'cancel'`。
2. 用 `MIN(event_date)`、`MAX(event_date)` 算 `days_as_subscriber`，注意是首末事件之差，不是到今天的差。
3. 用 `SUM(CASE WHEN event_type='downgrade' THEN 1 ELSE 0 END)` 数降级次数，`MAX(monthly_amount)` 取历史最高。
4. 外层 WHERE 同时卡四个条件，最后 `ORDER BY days_as_subscriber DESC, user_id ASC`。

以用户 501 为例：`rn=1` 是 2024-03-20 的 downgrade，`current_monthly_amount=9.99`；`MAX(monthly_amount)=29.99`；`9.99 < 29.99*0.5=14.995` 成立；`days=79`。用户 506 同样满足前三条，但 `days=50 < 60` 被刷掉——这正是最容易漏筛的一条。

```python
# 分组聚合 + 窗口取当前行
cur = df[df["rn"] == 1][["user_id", "event_type", "plan_name", "monthly_amount"]]
agg = df.groupby("user_id").agg(
    max_amt=("monthly_amount", "max"),
    downs=("event_type", lambda s: (s == "downgrade").sum()),
    first_d=("event_date", "min"),
    last_d=("event_date", "max"),
)
m = agg.join(cur.set_index("user_id"))
m["days"] = (m["last_d"] - m["first_d"]).dt.days
res = m[(m["event_type"] != "cancel")
        & (m["downs"] >= 1)
        & (m["monthly_amount"] < m["max_amt"] * 0.5)
        & (m["days"] >= 60)]
```

## 复杂度
时间 O(n log n)：n 为事件行数，排序/窗口按 user_id 分区排序贡献 log n。
空间 O(u)：u 为用户数，额外开分组聚合结果和当前行表。

## 易错点
- 用 `MAX(monthly_amount)` 时把 cancel 行的 0 也算进去没问题（0 不会成为最大值），但若用 `AVG` 或 `MIN` 就会被 0 污染 → 正确做法是只对 `monthly_amount` 取 `MAX`，且比较用严格小于 `<`，501 的 9.99 与 14.995 不能写成 `<=`。
- 判断「当前有效」若用 `MAX(event_date)` 再 join 回原表，遇到同一天多条事件会重复出行 → 正确做法是用 `ROW_NUMBER` 按 `event_date DESC, event_id DESC` 定唯一当前行，避免 501 这类同日多事件被放大。

## 如果面试官追问
问：若「订阅天数」改成到今天的活跃天数怎么改？
答：把 `last_d` 换成 `CURRENT_DATE`，但已 cancel 的用户要截到 cancel 日期，需在窗口里先取 cancel 的 `event_date`。
