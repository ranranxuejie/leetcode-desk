## 一句话思路
把上下边界固定成一条"压缩行"，二维子矩阵求和就退化成 1074 的一维版本：前缀和 + 哈希表数配对。

## 怎么做
1. 枚举上边界 `top` 和下边界 `bottom`，把 `matrix[top..bottom]` 按列压成数组 `col[j]`。
2. 对 `col` 做一维前缀和，用哈希表 `cnt` 记录每个前缀和出现次数，`cnt[0] = 1`。
3. 扫到位置 `j` 时，累加 `cnt[pre - target]`，再把 `pre` 计入 `cnt`。

以示例 2 `matrix = [[1,-1],[-1,1]]`、`target = 0` 为例，取 `top=0, bottom=1`，压缩后 `col = [0, 0]`。前缀和序列是 `pre=0, 0`：扫第一个 0 时 `cnt[0-0]=cnt[0]=1` 计入，`cnt[0]` 变 2；扫第二个 0 时 `cnt[0]=2` 计入，累计 3。这 3 个正是两个 2x1 子矩阵加一个 2x2 子矩阵，剩下 2 个来自 `top=bottom=0` 和 `top=bottom=1` 的 1x2 子矩阵。

```python
rows, cols = len(matrix), len(matrix[0])
ans = 0
for top in range(rows):
    col = [0] * cols
    for bottom in range(top, rows):
        for j in range(cols):
            col[j] += matrix[bottom][j]
        pre, cnt = 0, {0: 1}
        for v in col:
            pre += v
            ans += cnt.get(pre - target, 0)
            cnt[pre] = cnt.get(pre, 0) + 1
```

关键点：`col` 在 `bottom` 内层循环里**增量累加**，不是每次重算，这样压缩一行的代价是 O(cols) 而不是 O(rows*cols)。

## 复杂度
时间 O(rows² · cols)：枚举上下边界 O(rows²)，每对边界扫一遍列 O(cols)。
空间 O(cols)：`col` 数组和哈希表 `cnt` 都只开列数大小。

## 易错点
- `target = 0` 且矩阵含 0（示例 1）→ 若忘了 `cnt = {0: 1}` 这个初始项，单个 0 单元格自己构成的子矩阵就数不到，输出 0 而非 4 → 前缀和为 0 的"空前缀"必须预先放进表里。
- 矩阵含负数（示例 2 的 `-1`）→ 若想用双指针或"前缀和单调"来滑动窗口，`pre` 不单调，窗口收缩条件失效，会漏解 → 只能用哈希表数配对，不能滑窗。

## 如果面试官追问
问：如果要求返回所有子矩阵坐标而不只是数量呢？
答：哈希表里存前缀和到下标列表的映射，命中时枚举列表里每个下标，复杂度升到 O(答案规模)。
