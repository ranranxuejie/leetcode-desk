## 一句话思路
统计频次后从大到小贪心：每个频次最多保留 `min(freq, 上一个保留值 - 1)`，差额即删除数。

## 怎么做
1. 用 `Counter(s)` 得到每个字符的频次，只取 `values()`，排序后**从大到小**遍历。
2. 维护 `prev` 表示上一个字符最终保留的频次，初始为无穷大；对当前频次 `f`，实际保留 `keep = min(f, prev - 1)`。
3. 若 `keep < 0` 说明这个字符只能全删，贡献 `f`；否则贡献 `f - keep`，并令 `prev = keep`。
4. 累加所有贡献即为答案。

以 `s = "aaabbbcc"` 为例：频次为 `[3, 3, 2]`，降序后仍是 `[3, 3, 2]`。第一个 `3` 保留 3，`prev = 3`；第二个 `3` 只能保留 `min(3, 2) = 2`，删 1，`prev = 2`；`2` 保留 `min(2, 1) = 1`，删 1，`prev = 1`。总计 `1 + 1 = 2`，与示例一致。

```python
from collections import Counter

freqs = sorted(Counter(s).values(), reverse=True)
ans = 0
prev = float('inf')
for f in freqs:
    keep = min(f, prev - 1)
    if keep < 0:
        ans += f
        keep = 0
    else:
        ans += f - keep
    prev = keep
return ans
```

关键点：降序保证大频次优先占位，小频次只能往下让，这样总删除量最小。若升序处理，`[2, 3, 3]` 会先让 2 占住 2，两个 3 分别降到 1 和 0，删除 5，明显更差。

## 复杂度
时间：`O(n + k log k)`，`n = len(s)` 用于计数，`k ≤ 26` 是不同字符数，排序贡献 `log k`。
空间：`O(k)`，`Counter` 和排序后的频次列表各占一份，与 `n` 无关。

## 易错点
- 输入 `s = "abcdefghijklmnopqrstuvwxyz"`（26 个字符频次全为 1）→ 若忘记降序或直接用 `set` 去重频次，会误判为 0 删除；正确做法是排序后逐个让位，实际删除 25。
- 输入 `s = "aaabbbcc"` → 若对每个频次只做 `f - 1` 而不更新 `prev`，第二个 3 会降到 2，但此时 `prev` 仍是 3，第三个 2 又保留 2，产生重复；正确做法是每轮把 `prev` 更新为 `keep`，让后续频次继续往下压。

## 如果面试官追问
追问：若要求输出删除后每个字符的最终频次方案？
答：在循环里记录 `(字符, keep)`，`Counter` 的键与频次一一对应，排序时带上字符即可还原。
