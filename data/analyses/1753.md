## 一句话思路
排序后设最大堆为 c，答案就是 `min(a+b, (a+b+c)//2)`：每回合消耗 2 颗石子，且小堆总和不够时大堆必然剩。

## 怎么做
1. 先排序，令 `a <= b <= c`，把最大堆固定成 `c`，后面所有判断都只针对它。
2. 若 `a + b <= c`，小堆全被大堆"吃掉"，每回合消耗一颗小堆加一颗 c，得分 `a + b`。
3. 否则三堆能互相消耗到接近空，总石子 `a+b+c` 每回合减 2，得分 `(a+b+c)//2`。
4. 两式合并即 `min(a+b, (a+b+c)//2)`，一行返回。

拿示例 2 的 `(4, 4, 6)` 走一遍：排序后 `a=4, b=4, c=6`，`a+b=8 > c=6`，走第 3 步，`(4+4+6)//2 = 7`，与官方输出一致。再看示例 3 的 `(1, 8, 8)`：排序后 `a=1, b=8, c=8`，`a+b=9 > 8`，`(1+8+8)//2 = 8`，也对。真正触发第 2 步的是 `(1, 2, 9)` 这类：`a+b=3 <= 9`，返回 3，因为 c 剩 6 颗却再没有第二个非空堆可配。

```python
def maximumScore(a, b, c):
    a, b, c = sorted((a, b, c))
    return min(a + b, (a + b + c) // 2)
```

关键就一行：`min` 的两个候选分别对应"大堆吃不完"和"三堆能配平"两种局面，排序保证 `c` 是那个可能吃不完的堆。

## 复杂度
时间：排序 3 个数是常数，整体 O(1)。
空间：只存三个变量，O(1)。

## 易错点
- 输入 `(1, 2, 9)` → 若直接返回 `(a+b+c)//2 = 6` 就错了，因为 c 剩 6 颗时另两堆已空、游戏停止 → 必须先判 `a+b <= c`，返回 `a+b = 3`。
- 输入 `(2, 4, 6)` → 若忘记排序、拿原始 `a=2` 当最大堆去比 `b+c=10 > 2`，会误走配平分支 → 先 `sorted` 把最大堆锁到 `c`，再比较。

## 如果面试官追问
问：若允许从同一堆取两颗呢？
答：约束变了，`min(a+b, (a+b+c)//2)` 不再成立，得改用大顶堆每回合取最大两堆各减一。
