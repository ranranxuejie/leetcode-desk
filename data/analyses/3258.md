## 一句话思路
固定右端点 r，用滑动窗口维护最左合法左端点 left，则 r 结尾的合法子串数恰为 r-left+1。

## 怎么做
1. 用 `cnt0`、`cnt1` 记录窗口 `s[left..r]` 内 0 和 1 的个数，`ans` 累加答案。
2. 右端点 r 逐个右移，把 `s[r]` 计入对应计数。
3. 当 `cnt0 > k and cnt1 > k` 时，说明窗口两端都超标，必须收缩：把 `s[left]` 移出窗口并 `left += 1`，直到至少一个计数 ≤ k。
4. 收缩后 `s[left..r]` 合法，且它的所有后缀（以 r 结尾、起点 ≥ left）都合法，累加 `ans += r - left + 1`。

以 `s = "10101", k = 1` 为例：r=3 时窗口为 `"1010"`，`cnt0=2, cnt1=2`，两者都 > 1，触发收缩；移出 `s[0]='1'` 后 `cnt1=1`，left=1，此时 `r-left+1 = 3`，即以 r=3 结尾的合法子串是 `"010"`、`"10"`、`"0"` 三个，`"1010"` 被排除。

```python
left = ans = cnt0 = cnt1 = 0
for r, ch in enumerate(s):
    if ch == '0':
        cnt0 += 1
    else:
        cnt1 += 1
    while cnt0 > k and cnt1 > k:
        if s[left] == '0':
            cnt0 -= 1
        else:
            cnt1 -= 1
        left += 1
    ans += r - left + 1
return ans
```

关键点：收缩条件是 `and` 不是 `or`。只要有一个计数 ≤ k 就满足「任一条件」，窗口立刻合法，不需要继续缩。

## 复杂度
时间 O(n)：r 和 left 各单调右移一次，每个字符进出窗口各一次。
空间 O(1)：只开了 left、ans、cnt0、cnt1 四个变量。

## 易错点
- 把收缩条件写成 `cnt0 > k or cnt1 > k`：对 `s="11111", k=1`，r=1 时 cnt1=2 就触发收缩，窗口被压到长度 1，答案变成 5 而非 15。正确是 `and`，两个都超标才不合法。
- 收缩后忘记 `ans += r - left + 1` 而写成 `ans += 1`：对 `s="10101", k=1`，r=3 收缩后只加 1，漏掉 `"010"`、`"10"` 两个后缀，最终得 9 而非 12。正确是以 r 结尾的合法起点有 `r-left+1` 个。

## 如果面试官追问
问：n 放大到 10^5、k 也很大，这题还这么做吗？
答：一样，滑动窗口仍是 O(n)，只是答案可能超 32 位，Python 整数天然安全，别的语言要开 64 位。
