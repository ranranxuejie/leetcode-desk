## 一句话思路
按「片段 a 排在片段 b 前更优」的相邻交换比较器排序，再从左到右拼接求值。

## 怎么做
1. 比较器：a 在 b 前更优当且仅当 `a1*2**b0 + b1 > b1*2**a0 + a1`，即 `a1*(2**b0-1) > b1*(2**a0-1)`，用 `cmp_to_key` 传入。
2. 排序后按顺序累加：每段先 `res = res * 2**c1 + (2**c1 - 1)`，再 `res = res * 2**c0`。
3. 全程对 `10**9+7` 取模，`pow(2, k, MOD)` 直接算幂。

以示例 1 为例：片段 `(1,1)` 与 `(2,0)`，比较 `1*(2**0-1)=0` 对 `2*(2**1-1)=2`，故 `(2,0)` 排前。拼接 `"11"` 后 `"10"` 得 `1110`=14。

```python
from functools import cmp_to_key
MOD = 10**9 + 7
def cmp(a, b):
    l = a[1] * (pow(2, b[0], MOD) - 1)
    r = b[1] * (pow(2, a[0], MOD) - 1)
    return -1 if l > r else (1 if l < r else 0)
segs = sorted(zip(nums1, nums0), key=cmp_to_key(cmp))
res = 0
for c1, c0 in segs:
    res = (res * pow(2, c1, MOD) + pow(2, c1, MOD) - 1) % MOD
    res = res * pow(2, c0, MOD) % MOD
```

## 复杂度
时间：排序 O(n log n) 次比较，每次比较两次 `pow` 各 O(log C)，C 为单个片段长度。
空间：`segs` 与排序栈 O(n)，无额外大数组。

## 易错点
- 比较器写成 `a1/a0 > b1/b0` 或直接比 `nums1[i]` 大小 → 示例 1 中 `(1,1)` 的 `1/1` 大于 `(2,0)` 的 `2/0`（除零或误判），会把 `"10"` 排前得 `1011`=11 而非 14；正确是比较 `a1*(2**b0-1)` 与 `b1*(2**a0-1)`。
- 拼接时把 `c1` 个 1 当成 `res*2**c1 + c1` → 示例 2 中 `"111"` 段会算成 `7+3` 而非 `7`；正确是 `res*2**c1 + (2**c1-1)`，即补满 `c1` 个 1。

## 如果面试官追问
若片段数增到 10^6 且长度总和不变，排序还够快吗？答：比较次数 O(n log n) 不变，但每次比较的 `pow` 可预存 `2**k mod MOD` 降到 O(1)。
