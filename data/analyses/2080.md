## 一句话思路
对每个值建一个下标升序列表，查询时二分出 `[left, right]` 内的下标个数。

## 怎么做
1. 构造时遍历 `arr`，把下标 `i` 追加到 `pos[arr[i]]` 里，天然升序。
2. 查询时取 `p = pos.get(value, [])`，空则直接返回 0。
3. 用 `bisect_left(p, left)` 得第一个 ≥ left 的位置 `lo`，用 `bisect_right(p, right)` 得第一个 > right 的位置 `hi`。
4. 返回 `hi - lo`。

以官方示例 `arr = [12,33,4,56,22,2,34,33,22,12,34,56]` 为例，`pos[33] = [1, 7]`。查询 `query(0, 11, 33)`：`lo = bisect_left([1,7], 0) = 0`，`hi = bisect_right([1,7], 11) = 2`，返回 `2 - 0 = 2`。查询 `query(1, 2, 4)`：`pos[4] = [2]`，`lo = bisect_left([2],1) = 0`，`hi = bisect_right([2],2) = 1`，返回 1。

```python
from bisect import bisect_left, bisect_right
from collections import defaultdict

class RangeFreqQuery:
    def __init__(self, arr):
        self.pos = defaultdict(list)
        for i, x in enumerate(arr):
            self.pos[x].append(i)

    def query(self, left, right, value):
        p = self.pos.get(value)
        if not p:
            return 0
        return bisect_right(p, right) - bisect_left(p, left)
```

关键点：`bisect_right(p, right)` 而不是 `bisect_left(p, right)`，因为 right 本身可能就在 `p` 里，用 left 会漏掉它。

## 复杂度
时间：构造 O(n)，每次查询 O(log k)，k 是该值出现次数，n 为数组长度。
空间：O(n)，`pos` 存了全部 n 个下标。

## 易错点
- 查询 `value` 不在 `arr` 中（如 `query(0, 11, 99)`）→ 若直接 `self.pos[value]` 用 defaultdict 会静默建空列表并返回 0，看似对但污染结构；用 `.get(value)` 判空更稳，返回 0。
- 把 `bisect_right(p, right)` 写成 `bisect_left(p, right)` → 当 `right` 恰好等于某个下标（如 `query(0, 7, 33)`，`p=[1,7]`）时返回 `1-0=1`，漏掉下标 7，正确答案是 2；右端必须用 `bisect_right`。

## 如果面试官追问
若 `arr` 长度升到 10^7 且值域也很大，怎么省空间？答：改用「值 → 下标列表」的哈希分桶，或对每个值只存差分游程，查询仍二分。
