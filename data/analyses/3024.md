## 一句话思路
先排序，只需验证 `a + b > c` 一条不等式，再按相等边数分类。

## 怎么做
1. 对 `nums` 排序，得到 `a <= b <= c`。
2. 只判断 `a + b > c`：排序后这是唯一可能失败的不等式，其余两条必然成立。
3. 若失败返回 `"none"`；否则数相等边对数，返回对应类型。

以 `nums = [3,4,5]` 为例：排序后 `a=3, b=4, c=5`，`a + b = 7 > 5` 成立，三条边互不相等，返回 `"scalene"`。若输入 `[1,2,3]`，`a + b = 3`，`3 > 3` 为假，返回 `"none"`——注意是严格大于，等于也不行。

```python
a, b, c = sorted(nums)
if a + b <= c:
    return "none"
if a == c:
    return "equilateral"
if a == b or b == c:
    return "isosceles"
return "scalene"
```

分类顺序有讲究：先判 `a == c` 覆盖三边全等（排序后 `a == c` 等价于 `a == b == c`），再判 `a == b or b == c` 覆盖恰好两边相等，剩下就是 `scalene`。因为 `a <= b <= c`，`a == c` 一旦成立，`b` 必然也等于它们，所以不需要写三个 `==` 的与。

## 复杂度
时间：O(1)，只有 3 个元素，排序常数次比较。
空间：O(1)，`sorted` 返回长度 3 的新列表，不随输入增长。

## 易错点
- 输入 `[1,2,3]` → 若写成 `a + b >= c` 会误判为可构成三角形，返回 `"scalene"` → 正确做法是严格用 `a + b <= c` 判 `"none"`，因为退化三角形（两边之和等于第三边）不算三角形。
- 输入 `[3,3,3]` → 若先判 `a == b or b == c` 再判全等，会错返回 `"isosceles"` → 正确做法是把 `a == c` 的全等判断放在前面，利用排序后 `a == c` 蕴含三边相等。

## 如果面试官追问
问：如果 `nums` 长度变成 n，要判断能否选出三条边构成三角形？
答：排序后只需检查是否存在相邻三元组 `nums[i] + nums[i+1] > nums[i+2]`，因为最优候选必是相邻的。
