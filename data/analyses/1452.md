## 一句话思路
把每个清单转成集合，对每个 i 检查是否存在 j≠i 使集合 i 是集合 j 的子集，没有则保留 i。

## 怎么做
1. 先把 `favoriteCompanies` 每项转成 `set`，存进 `sets`，避免后面反复做列表转集合。
2. 外层枚举 `i`，内层枚举 `j`，用 `sets[i] <= sets[j]` 判断子集（`<=` 对 set 就是包含关系）。
3. 一旦找到某个 `j` 满足条件，`i` 就淘汰，`break` 跳出内层；内层跑完没被淘汰才把 `i` 加入答案。
4. 因为 `i` 从小到大枚举，答案天然升序，不用再 `sort`。

用示例 1：`sets[3] = {"google"}`，内层 `j=0` 时 `{"google"} <= {"leetcode","google","facebook"}` 为 `True`，`i=3` 直接淘汰；而 `sets[0]` 对 `j=1,2,3,4` 全部为 `False`，所以 `0` 进答案。

```python
sets = [set(x) for x in favoriteCompanies]
ans = []
for i in range(len(sets)):
    if not any(i != j and sets[i] <= sets[j] for j in range(len(sets))):
        ans.append(i)
```

关键点：`i != j` 不能省。虽然题目保证清单互不相同，但 `sets[i] <= sets[i]` 恒为 `True`，漏掉这个条件会把所有下标都淘汰，示例 3 会输出 `[]` 而不是 `[0,1,2,3]`。

## 复杂度
时间：O(n² · m)，n 为清单数（≤100），m 为单清单长度（≤500），每个 `<=` 最坏扫 m 个元素。
空间：O(n · m)，`sets` 存了全部字符串的集合副本，答案列表 O(n)。

## 易错点
- 忘写 `i != j` → 每个 `sets[i] <= sets[i]` 都为 `True`，示例 3 输出 `[]` → 内层条件必须写成 `i != j and sets[i] <= sets[j]`。
- 用 `sets[i] in sets[j]` 或 `all(c in favoriteCompanies[j] for c in ...)` 判断 → 前者是元素判断不是子集判断，后者对列表是 O(m) 查找，总复杂度退化到 O(n²m²)，500 长度下会明显变慢 → 统一先转 `set` 再用 `<=`。

## 如果面试官追问
问：如果 n 放大到 10⁴ 怎么办？答：给每个集合算哈希签名或按大小排序后只和更大的集合比，配合倒排索引剪枝，避免全量两两比较。
