## 一句话思路
一次遍历维护「已见过的最小值」，用当前值减它更新答案，保证 i<j 且 nums[i]<nums[j]。

## 怎么做
1. 初始化 `min_seen = nums[0]`、`ans = -1`。
2. 从下标 1 开始遍历 `x = nums[j]`，先判断 `x > min_seen` 则 `ans = max(ans, x - min_seen)`。
3. 再用 `min_seen = min(min_seen, x)` 更新最小值，顺序不能反。
4. 遍历结束返回 `ans`，全程没更新过就是 -1。

拿 `nums = [7, 1, 5, 4]` 走一遍关键步：`min_seen=7`；`j=1` 时 `x=1` 不满足 `1>7`，更新后 `min_seen=1`；`j=2` 时 `x=5>1`，`ans=5-1=4`；`j=3` 时 `x=4>1`，`4-1=3` 不敌 4，最终返回 4。注意 `7-1=6` 之所以不算，是因为 7 在下标 0、1 在下标 1，`i<j` 反了——先更新 min 再算差值就会把 7 当成候选最小值，从而漏掉正确答案。

```python
min_seen = nums[0]
ans = -1
for x in nums[1:]:
    if x > min_seen:
        ans = max(ans, x - min_seen)
    min_seen = min(min_seen, x)
return ans
```

## 复杂度
时间 O(n)：一次遍历，每个元素只做常数次比较。
空间 O(1)：只开 `min_seen`、`ans` 两个变量，不复制数组。

## 易错点
- `nums = [9,4,3,2]` 严格递减 → 若把 `ans` 初值写成 0，会返回 0 而非 -1；正确做法是初值设 -1，且只在 `x > min_seen` 时更新。
- `nums = [7,1,5,4]` → 若先 `min_seen = min(min_seen, x)` 再算差值，`j=1` 时 `min_seen` 已变成 1，`7-1=6` 这类非法组合反而可能混入；正确做法是先比较后更新，保证 `min_seen` 来自 `j` 之前的下标。

## 如果面试官追问
要求返回具体的 `(i, j)` 而不只是差值怎么办？
答：额外记 `min_idx`，更新 `ans` 时同步存下 `(min_idx, j)`，更新 `min_seen` 时同步改 `min_idx`。
