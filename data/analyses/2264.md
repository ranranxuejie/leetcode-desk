## 一句话思路
从左到右扫一遍，用 `num[i:i+3]` 判断三字符是否全等，维护见过的最大者，因为字典序对等长数字串就是数值序。

## 怎么做
1. 初始化 `best = ""`，它天然小于任何三位串，省掉特判。
2. 对 `i` 从 0 到 `len(num)-3` 遍历，取窗口 `w = num[i:i+3]`。
3. 若 `w[0] == w[1] == w[2]` 且 `w > best`，则 `best = w`。
4. 循环结束返回 `best`。

以 `num = "6777133339"` 为例，`i=1` 时窗口 `"777"`，三字符相等，`best` 从 `""` 变成 `"777"`；`i=5` 时窗口 `"333"`，虽然三字符相等，但 `"333" > "777"` 为 `False`，`best` 保持 `"777"`。注意 `i=4` 的窗口是 `"133"`，`w[0] != w[1]`，直接跳过。

```python
best = ""
for i in range(len(num) - 2):
    w = num[i:i + 3]
    if w[0] == w[1] == w[2] and w > best:
        best = w
return best
```

关键点：`w > best` 用的是字符串比较，三位等长时逐位比 ASCII，`"777" > "333"` 成立，所以不需要 `int(w)`。若改成 `int(w)` 再比，`"000"` 会变成 `0`，返回时还得补回 `"000"`，多此一举。

## 复杂度
时间：O(n)，n 为 `num` 长度，每个位置做一次常数次字符比较。
空间：O(1)，只存 `best` 和长度 3 的切片 `w`。

## 易错点
1. 输入 `num = "2300019"` → 若用 `int(w)` 比较并把结果转回字符串，`"000"` 会变成 `0`，返回 `"0"` 而非 `"000"` → 正确做法是全程用字符串比较和返回，不碰 `int`。
2. 输入 `num = "000111"` → 若循环写成 `range(len(num) - 3)`，会漏掉最后一个窗口 `"111"`，只找到 `"000"` → 正确上界是 `len(num) - 2`，因为切片右端不含，`i = len(num)-3` 时 `num[i:i+3]` 恰好取到末尾三位。

## 如果面试官追问
问：若要求返回所有优质整数去重后的降序列表？
答：把 `best` 换成 `set`，命中就 `add(w)`，最后 `sorted(s, reverse=True)`，时间仍是 O(n)。
