## 一句话思路
排序后对每个 `nums[i]` 用双指针或二分找 `nums[j] <= target - nums[i]` 的个数，累加取模。

## 怎么做
1. 先对 `nums` 排序，使「和不超过 target」的配对具有单调性。
2. 用左右指针 `l=0, r=n-1`，当 `nums[l] + nums[r] <= target` 时，说明 `l` 能和 `l+1..r` 全部配对，累加 `r-l` 后 `l+=1`；否则 `r-=1`。
3. 每次累加后对 `1000000007` 取模。

以 `nums=[2,5,3,5], target=6` 为例：排序得 `[2,3,5,5]`。`l=0,r=3`：`2+5=7>6`，`r=2`；`2+5=7>6`，`r=1`；`2+3=5<=6`，累加 `r-l=1`，`l=1`；此时 `l>=r` 结束，结果 `1`。

```python
nums.sort()
l, r = 0, len(nums) - 1
ans = 0
MOD = 1000000007
while l < r:
    if nums[l] + nums[r] <= target:
        ans = (ans + r - l) % MOD
        l += 1
    else:
        r -= 1
return ans
```

关键中间值：`l=0, r=1` 时 `nums[0]+nums[1]=5<=6`，一次性计入 `r-l=1` 个方案，避免逐个枚举。

## 复杂度
时间：排序 `O(n log n)`，双指针扫描 `O(n)`，n 为 `len(nums)`。
空间：排序额外 `O(log n)` 栈空间（Python Timsort），无其他数组。

## 易错点
- 输入 `nums=[2,2,1,9], target=10`：若用 `l<r` 但漏掉 `r-l` 批量累加、改成每次只 `ans+=1`，会漏计 `(0,1)` 与 `(0,2)` 等组合，正确做法是 `ans += r - l` 一次计入 `l` 与右侧所有合法元素。
- 输入含大量相等元素如 `nums=[1,1,1,1], target=2`：若在 `nums[l]+nums[r]<=target` 时只 `l+=1` 不累加 `r-l`，会少算；正确做法是每次命中都加 `r-l` 再移动 `l`，保证每对只计一次。

## 如果面试官追问
问：若要求输出所有具体方案而非计数？答：双指针命中时枚举 `l+1..r` 逐个输出，复杂度升为 `O(n^2)`，需按方案数评估。
