## 一句话思路
只需把「峰」压低、绝不碰「谷」，两种奇偶目标各算一遍取较小值。

## 怎么做
1. 目标分两种：偶数位为峰（`nums[0]>nums[1]<nums[2]...`）和奇数位为峰，分别求代价。
2. 对每个峰位 `i`，它只需比左右邻居都小 1 以上，故目标值 `t = min(左邻, 右邻) - 1`；若 `nums[i] > t`，代价 `nums[i] - t`，否则 0。
3. 谷位不动：把谷压低只会让相邻峰更难满足，纯亏。
4. 两种目标取 `min`。

以 `nums = [9,6,1,6,2]` 为例，算「奇数位为峰」：`i=1` 邻居是 9 和 1，`t = min(9,1)-1 = 0`，`6>0` 代价 6；`i=3` 邻居是 1 和 2，`t = min(1,2)-1 = 0`，`6>0` 代价 6，合计 12。算「偶数位为峰」：`i=0` 只有右邻 6，`t=5`，`9>5` 代价 4；`i=2` 邻居 6 和 6，`t=5`，`1` 不超，代价 0；`i=4` 只有左邻 6，`t=5`，`2` 不超，代价 0，合计 4。取 `min(12,4)=4`，与示例一致。

```python
def cost(peak_parity):
    total = 0
    for i in range(peak_parity, len(nums), 2):
        t = 2**31 - 1
        if i > 0:
            t = min(t, nums[i-1])
        if i + 1 < len(nums):
            t = min(t, nums[i+1])
        t -= 1
        if nums[i] > t:
            total += nums[i] - t
    return total

return min(cost(0), cost(1))
```

边界：`len(nums)==1` 时两种代价都是 0，直接返回 0；端点峰只有一个邻居，`t` 只由那一侧决定。

## 复杂度
时间 O(n)：两种奇偶目标各扫一遍，共 2n 次比较。
空间 O(1)：只用了 `total`、`t` 几个标量，没开额外数组。

## 易错点
- `nums = [1,2,3]` 若把谷位 `nums[1]=2` 也往下压，会算成更大代价；正确做法是只动峰位，偶数位为峰时只压 `nums[2]` 到 1（代价 2），奇数位为峰时只压 `nums[1]` 到 0（代价 2），答案 2。
- 端点峰 `i=0` 或 `i=n-1` 若漏判单邻居，`t` 会取到不存在的邻居导致越界或算错；正确做法是 `i>0` 和 `i+1<n` 分别判断，`[9,6,1,6,2]` 中 `i=0` 的 `t` 只由 `nums[1]=6` 得 5，代价 4。

## 如果面试官追问
问：若允许同时增大元素，答案会变吗？
答：会，峰可抬高而非只压谷，代价变成两侧差额绝对值之和，贪心仍按峰独立算。
