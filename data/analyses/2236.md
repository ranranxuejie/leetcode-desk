## 一句话思路
树恰好三个结点，直接取 `root.val`、`root.left.val`、`root.right.val` 做一次加法比较即可。

## 怎么做
1. 读根值 `r = root.val`。
2. 读左子值 `l = root.left.val`，右子值 `rr = root.right.val`。
3. 返回 `r == l + rr`。

以官方示例 1 的 `root = [10,4,6]` 为例：`r = 10`，`l = 4`，`rr = 6`，中间值 `l + rr = 10`，与 `r` 相等，返回 `True`。示例 2 的 `[5,3,1]` 算出 `l + rr = 4 ≠ 5`，返回 `False`。

```python
r = root.val
l = root.left.val
rr = root.right.val
return r == l + rr
```

不需要递归，也不需要遍历：题目保证树只有三层结点，任何递归写法都只是把这三行包了一层，反而多出空指针判断的成本。若想写成一行，`return root.val == root.left.val + root.right.val` 等价，但拆成三个变量后，调试时能直接看到 `l + rr` 的值，出错时一眼定位是左子还是右子读错。

## 复杂度
时间：O(1)，只访问三个结点，与 n 无关。
空间：O(1)，没有递归栈、没有额外容器。

## 易错点
- 把 `root.left.val + root.right.val` 写成 `root.left + root.right` → 拿到的是两个 Node 对象相加，Python 直接抛 `TypeError` → 必须显式取 `.val`，两个子结点都要取。
- 看到「二叉树」就条件反射写递归 `checkTree(root.left) and checkTree(root.right)` → 递归到叶子时 `root.left` 是 `None`，访问 `.val` 抛 `AttributeError` → 本题树固定三层，不递归，只在根这一层做一次比较。

## 如果面试官追问
问：如果树不保证三个结点，而是任意二叉树，要求每个结点都满足「父值 = 子值之和」呢？
答：改成后序遍历，叶子返回自身值，内部结点先递归两子再比较，空子按 0 处理。
