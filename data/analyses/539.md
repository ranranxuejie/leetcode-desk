## 一句话思路
把每个 "HH:MM" 转成一天内的分钟数排序，最小差只可能出现在相邻两项或首尾跨零点之间。

## 怎么做
1. 用 `int(s[:2]) * 60 + int(s[3:])` 把每个时间点转成 0~1439 的分钟数，存进 `mins`。
2. 对 `mins` 升序排序，相邻差 `mins[i] - mins[i-1]` 逐个比较取最小。
3. 别忘了首尾：`mins[0] + 1440 - mins[-1]` 是跨零点的那段差，也要参与取最小。

以 `["23:59","00:00"]` 为例：转换后 `mins = [1439, 0]`，排序得 `[0, 1439]`。相邻差是 `1439`，首尾差是 `0 + 1440 - 1439 = 1`，取最小得 `1`——这正是示例 1 的答案，也说明首尾那一项不能漏。

```python
mins = sorted(int(t[:2]) * 60 + int(t[3:]) for t in timePoints)
ans = mins[0] + 1440 - mins[-1]
for i in range(1, len(mins)):
    ans = min(ans, mins[i] - mins[i - 1])
return ans
```

排序后相邻差覆盖了所有「同一天内」的配对，而首尾差覆盖了唯一一段「跨零点」的配对，两者合起来就是全部候选，所以取最小即答案。

## 复杂度
时间：O(n log n)，n 为时间点个数，瓶颈在排序。
空间：O(n)，`mins` 列表存 n 个整数（排序本身另有 O(n) 或 O(log n)）。

## 易错点
- 输入 `["23:59","00:00"]` → 只算相邻差会得到 `1439`，漏掉跨零点 → 必须把 `mins[0] + 1440 - mins[-1]` 作为初始 `ans` 参与比较。
- 输入 `["00:00","23:59","00:00"]` → 若先去重再排序，两个 `00:00` 被合并，答案错成 `1` → 保留重复项，排序后相邻差自然为 `0`，直接返回 `0`。

## 如果面试官追问
问：时间点数量涨到 10^7 还排序吗？
答：改用长度 1440 的布尔桶标记出现过的分钟，扫一遍桶取相邻最小间隔，时间 O(n + 1440)、空间 O(1440)。
