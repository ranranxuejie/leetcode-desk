## 一句话思路
首尾配对，每对差值的一半就是该对需要的操作数，累加即可。

## 怎么做
1. 数组是等差数列 `arr[i] = 2*i + 1`，首项 1、末项 `2*n - 1`，总和固定，所以最终相等的值只能是平均值 `n`。
2. 第 `i` 个元素与第 `n-1-i` 个元素关于中心对称，二者之和恒为 `2*n`，平均值正好是 `n`，所以只需把小的补到 `n`、大的减到 `n`。
3. 一对 `(arr[i], arr[n-1-i])` 的差距是 `n - arr[i] = n - (2*i + 1)`，一次操作同时让两端各靠近 1，故该对需要 `n - 2*i - 1` 次。
4. 只遍历前一半 `i < n // 2`，把这些差值累加。

以 `n = 6` 为例：`arr = [1,3,5,7,9,11]`，平均值 `n = 6`。配对差值依次是 `6-1=5`、`6-3=3`、`6-5=1`，累加 `5+3+1 = 9`，与示例输出一致。注意 `n = 3` 时只算 `i = 0` 一对，差值 `3-1 = 2`，中间元素 3 本来就是 `n`，不用动。

```python
total = 0
for i in range(n // 2):
    total += n - (2 * i + 1)
return total
```

也可以直接套公式：前 `n//2` 项是 `n-1, n-3, ...`，和为 `(n // 2) * (n - n // 2)`，一行返回。

## 复杂度
时间：O(n)，循环 `n // 2` 次，每次 O(1)。
空间：O(1)，只用了累加变量 `total`，没有开数组。

## 易错点
- `n` 为奇数时误把中间元素也算进去：`n = 3` 若遍历 `i < n` 会多算 `i = 1` 的 `3 - 3 = 0`，虽然结果碰巧不变，但 `n = 5` 时若写成 `n - 2*i` 就会把中间项算成 1，答案从 6 错成 7；正确做法是循环上界取 `n // 2`，中间元素天然等于 `n`。
- 用 `n // 2 * (n - n // 2)` 时把整除优先级搞错：写成 `n // 2 * n - n // 2` 在 `n = 6` 会得到 `3*6-3 = 15` 而非 9；正确做法是加括号 `(n // 2) * (n - n // 2)`，或干脆用循环累加避免歧义。

## 如果面试官追问
问：如果每次操作只能选相邻两个下标呢？
答：那就变成把数组「削平」的经典题，答案是所有前缀和与平均值之差的绝对值之和，仍是 O(n)。
