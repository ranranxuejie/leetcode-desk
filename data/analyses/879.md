## 一句话思路
把「利润 ≥ minProfit」压成「利润 = minProfit」这一格，用二维 0/1 背包按人数和利润做 DP。

## 怎么做
1. 定义 `dp[j][k]` = 用恰好 j 名员工、利润**至少**为 k 的方案数，初始化 `dp[0][0] = 1`。
2. 对每个工作 `(g, p)` 倒序枚举 j 从 n 到 g、k 从 minProfit 到 0，做 0/1 背包转移。
3. 关键：利润维度用 `max(0, k - p)` 截断，因为超过 minProfit 的部分都归到 minProfit 这一格。
4. 答案是 `dp` 中所有 j 的 `dp[j][minProfit]` 之和。

以示例 1 为例：`n=5, minProfit=3, group=[2,2], profit=[2,3]`。处理工作 0 后 `dp[2][0]=1`（利润 2 不足 3，归到 0 格）；处理工作 1 时，从 `dp[2][0]` 转移到 `dp[4][3] += 1`，同时单独选工作 1 得 `dp[2][3] += 1`，最终 `dp[2][3]=1`、`dp[4][3]=1`，和为 2。

```python
MOD = 10**9 + 7
dp = [[0] * (minProfit + 1) for _ in range(n + 1)]
dp[0][0] = 1
for g, p in zip(group, profit):
    for j in range(n, g - 1, -1):
        for k in range(minProfit, -1, -1):
            nk = max(0, k - p)
            dp[j][k] = (dp[j][k] + dp[j - g][nk]) % MOD
return sum(dp[j][minProfit] for j in range(n + 1)) % MOD
```

## 复杂度
时间：O(len(group) · n · minProfit)，三重循环各贡献一维。
空间：O(n · minProfit)，只开一张二维表，无额外数组。

## 易错点
- 利润维度写成 `k - p` 而不截断到 0 → 当 `p > minProfit` 时下标为负，Python 会静默取到列表尾部元素，答案偏大。正确做法是 `nk = max(0, k - p)`，把超额利润全部归到 0 格。
- 人数维度正序枚举 j → 同一个工作被重复选取，示例 1 会算出超过 2 的结果。正确做法是 j 从 n 倒序到 g，保证每个工作只用一次。

## 如果面试官追问
问：若要求输出具体方案而非计数？答：DP 存方案列表会爆内存，改用回溯 + 剪枝，按剩余人数和剩余利润提前终止。
