## 一句话思路
从每个警卫向四个方向走，遇墙或警卫就停，把走到的格子标记为已保卫，最后数未标记的空格。

## 怎么做
1. 建 `m x n` 的 `state` 数组：警卫记 1、墙记 2、其余 0。
2. 对每个警卫，四个方向逐格前进，遇 `state != 0` 立即停，否则置 3（已保卫）。
3. 遍历全图，统计 `state == 0` 的格子数。

以示例 1 为例：`m=4, n=6`，警卫 `(0,0)` 向东走到 `(0,1)` 是墙就停，只保卫 `(0,0)` 本身；警卫 `(1,1)` 向西走到 `(1,0)` 停，向东走到 `(1,3)` 停（`(1,4)` 是墙），向南走到 `(3,1)` 停，向北走到 `(0,1)` 是墙停。关键中间值：`(1,1)` 这一轮结束后 `state[1][0]=state[1][2]=state[1][3]=3`，而 `(2,1)` 被 `(2,3)` 警卫的向西扫描覆盖。

```python
state = [[0] * n for _ in range(m)]
for r, c in guards: state[r][c] = 1
for r, c in walls:  state[r][c] = 2
for r, c in guards:
    for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)):
        x, y = r + dr, c + dc
        while 0 <= x < m and 0 <= y < n and state[x][y] == 0:
            state[x][y] = 3
            x, y = x + dr, y + dc
return sum(row.count(0) for row in state)
```

注意 `while` 条件里 `state[x][y] == 0` 同时挡住了墙(2)、警卫(1)和已保卫格(3)——已保卫格不必重复走，因为从它继续往前的那段一定已被同一警卫扫过。

## 复杂度
时间：O(m·n + G·(m+n))，每个警卫四方向最多走满一行一列，总扫描量受网格规模约束。
空间：O(m·n)，`state` 二维数组存三种标记。

## 易错点
- 警卫自身格子 `state` 是 1 不是 0，若最后用 `state == 0` 统计没问题，但若误把警卫格也当空格计数，示例 1 会从 7 变成 10（3 个警卫格被多算）。
- 扫描时若只判墙不判警卫，示例 2 中 `(1,1)` 警卫向东会穿过 `(1,2)` 墙前先被自己挡住——实际坑在于两个警卫相邻时（如 `guards=[[0,0],[0,1]]`），`(0,0)` 向东会越过 `(0,1)` 继续保卫 `(0,2)`，正确做法是 `state[x][y] == 0` 作为循环条件，让警卫格 1 直接终止。

## 如果面试官追问
若 m、n 放大到 10^9 而警卫墙数量不变，怎么办？答：不建网格，按行分组警卫和墙，对每行排序后只算相邻障碍之间的区间长度，列同理去重。
