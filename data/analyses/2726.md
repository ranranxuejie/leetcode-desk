## 一句话思路
按 actions 顺序逐条派发到 Calculator 的对应方法，链式调用靠每个方法返回 self 实现。

## 怎么做
1. 构造函数把 `values[0]` 存进 `self.result`，因为第一个 action 恒为 `"Calculator"`。
2. 从下标 1 开始遍历 `actions`，用 `values[i]` 作为该步的操作数，`getResult` 不消耗操作数。
3. 每个运算方法改完 `self.result` 后 `return self`，链式调用才成立。
4. `divide` 先判 `value == 0` 抛 `ValueError("Division by zero is not allowed")`，再算。

以示例 2 为例：`actions = ["Calculator","multiply","power","getResult"]`，`values = [2,5,2]`。i=1 时 `self.result = 2*5 = 10`；i=2 时 `self.result = 10**2 = 100`；i=3 是 `getResult`，直接返回 100。关键中间值是 power 之前的 10，不是 2。

```python
class Calculator:
    def __init__(self, value):
        self.result = value

    def add(self, value):
        self.result += value
        return self

    def divide(self, value):
        if value == 0:
            raise ValueError("Division by zero is not allowed")
        self.result /= value
        return self

    def getResult(self):
        return self.result
```

派发循环里 `getResult` 要单独处理，不能拿 `values[i]` 当参数。

## 复杂度
时间：O(n)，n 为 actions 长度，每步一次算术。
空间：O(1)，只存一个 `self.result`，无额外数组。

## 易错点
- 输入 `actions` 含 `getResult` 时仍按 `values[i]` 取操作数 → 下标错位或越界 → `getResult` 分支不读 values，其余分支才读。
- 输入 `divide` 的 value 为 0（示例 3 的 `values=[20,0]`）→ 直接算 `20/0` 抛 `ZeroDivisionError`，消息不对 → 先显式判 0 抛指定文案的 `ValueError`。

## 如果面试官追问
问：若 actions 里出现连续两个 `getResult` 怎么办？答：仍返回同一个 `self.result`，不消耗 values，派发逻辑天然支持。
