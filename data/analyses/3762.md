## 一句话思路
把每个数按 `nums[i] % k` 分组，同余才可行；组内取中位数，用前缀和加二分算绝对差之和。

## 怎么做
1. 预处理：若 `nums[i] % k != nums[0] % k`，该位置标记为不可行，用前缀计数 `bad` 快速判断区间是否全同余。
2. 对每个查询，先查 `bad[r+1]-bad[l] > 0` 则返回 `-1`。
3. 可行时把区间内元素除以 k 后排序（离线按 k 分组，用树状数组/有序结构维护），取中位数 `mid`。
4. 答案 = `(mid * cnt_left - sum_left) + (sum_right - mid * cnt_right)`，即两侧到中位数的距离和。

以 `nums=[1,4,7], k=3, query=[0,2]` 为例：三数同余 1，除以 k 得 `[0,1,2]`，中位数 1，左差 `1-0=1`，右差 `2-1=1`，合计 2，与示例一致。

```python
# 核心：区间绝对差和（已按 k 归一化并排序）
def cost(arr, l, r):
    m = (l + r) // 2
    mid = arr[m]
    left = mid * (m - l) - (pref[m] - pref[l])
    right = (pref[r + 1] - pref[m + 1]) - mid * (r - m)
    return left + right
```

## 复杂度
时间：预处理 `O(n log n)`，每查询二分 `O(log n)`，总 `O((n+q) log n)`。
空间：前缀和与树状数组各 `O(n)`，答案数组 `O(q)`。

## 易错点
- 区间内 `nums[i] % k` 不一致（如示例 2 的 `[1,2,4]`，k=2，余数 1/0/0）→ 误算成有限值 → 必须先判同余，返回 `-1`。
- 中位数取下标 `(l+r)//2` 而非 `(l+r+1)//2`，偶数长度时两者结果相同但前缀和边界 `pref[m+1]` 易写错 → 统一用左中位数并核对 `right` 的起点是 `m+1`。

## 如果面试官追问
若 k 随查询变化怎么办？答：无法预处理同余分组，需对每个查询单独判断并排序，复杂度退化为 `O(q·len log len)`。
