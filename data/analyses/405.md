## 一句话思路
把 `num` 按 32 位补码理解成无符号数，每 4 位取一个十六进制字符，从低位往高位拼。

## 怎么做
1. 若 `num == 0` 直接返回 `"0"`，否则把负数 `num & 0xFFFFFFFF` 转成无符号值。
2. 循环 `while num:`，每次取 `num & 0xF` 查表得字符，追加到结果。
3. 每轮 `num >>= 4`，直到为 0。
4. 结果逆序拼接（或每轮前插）。

以 `num = 26` 为例：`26 & 0xF = 10` → 字符 `'a'`，`26 >> 4 = 1`；下一轮 `1 & 0xF = 1` → `'1'`，`1 >> 4 = 0` 结束，逆序得 `"1a"`。以 `num = -1` 为例：`-1 & 0xFFFFFFFF = 4294967295`，共 8 轮每轮都取到 `15` → `'f'`，得 `"ffffffff"`。

```python
def toHex(num: int) -> str:
    if num == 0:
        return "0"
    digits = "0123456789abcdef"
    num &= 0xFFFFFFFF
    res = []
    while num:
        res.append(digits[num & 0xF])
        num >>= 4
    return "".join(reversed(res))
```

关键点：`& 0xFFFFFFFF` 这一步把 `-1` 变成 `4294967295`，之后 `>> 4` 是逻辑右移语义（Python 中正数右移即逻辑右移），不会因符号位补 1 而死循环。

## 复杂度
时间：O(log n)，即最多 8 轮（32 位 / 4 位），每轮 O(1)。
空间：O(log n) 存结果字符，最多 8 个，常数级。

## 易错点
- 输入 `num = 0` → 若不加特判，`while num:` 一次都不进，返回空串 `""` 而非 `"0"`；正确做法是开头单独返回 `"0"`。
- 输入 `num = -1` → 若直接对负数做 `num & 0xF` 再 `num >>= 4`，Python 的负数右移是算术右移、高位补 1，`-1 >> 4` 仍是 `-1`，循环永不终止；正确做法是先 `num &= 0xFFFFFFFF` 转成无符号正数再移位。

## 如果面试官追问
问：如果要求支持 64 位整数怎么办？答：把掩码换成 `0xFFFFFFFFFFFFFFFF`，循环上限从 8 轮变 16 轮，其余逻辑不变。
