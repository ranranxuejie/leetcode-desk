## 一句话思路
用一个 0 下标数组 `bal` 存余额，所有操作先查账户号是否落在 `1..n`，再改 `bal`，O(1) 完成。

## 怎么做
1. 构造时把 `balance` 直接存成 `self.bal`，账户 `k` 对应 `self.bal[k-1]`。
2. 每个方法第一步统一做边界检查：`if not (1 <= account <= len(self.bal)): return False`。
3. 取款/转账在边界检查后，再判 `self.bal[i-1] < money` 则返回 `False`，否则先扣后加。
4. 存款只需边界检查，直接 `+= money`。

用官方示例走一遍最关键那步：`transfer(5, 1, 20)`，此时 `bal = [10, 100, 10, 50, 30]`（账户 3 已被取走 10）。`account1=5` 合法，`bal[4]=30 >= 20`，于是 `bal[4] = 30-20 = 10`，`bal[0] = 10+20 = 30`，返回 `True`。注意扣款判断用的是**转账前**的 `bal[4]`，不是扣完再判。

```python
def transfer(self, a1, a2, money):
    n = len(self.bal)
    if not (1 <= a1 <= n and 1 <= a2 <= n):
        return False
    if self.bal[a1-1] < money:
        return False
    self.bal[a1-1] -= money
    self.bal[a2-1] += money
    return True

def withdraw(self, a, money):
    if not (1 <= a <= len(self.bal)) or self.bal[a-1] < money:
        return False
    self.bal[a-1] -= money
    return True
```

`deposit` 只有边界检查一行，`money` 可以为 0，照样返回 `True`。

## 复杂度
时间：每次操作 O(1)，与 n 无关；构造 O(n)。
空间：O(n) 存 `self.bal`，无额外哈希表。

## 易错点
- `transfer(3, 4, 15)` 在示例中账户 3 余额已是 10 → 若先加后判或漏判余额，会错误返回 `True` 并把账户 3 扣成负数 → 必须先判 `bal[a1-1] < money` 再扣。
- `withdraw(10, 50)` 账户号 10 超出 n=5 → 若只判余额不判下标，`bal[9]` 直接 IndexError 或误判 → 边界检查必须放在取 `bal` 之前，且用 `1 <= account <= len(self.bal)` 而非 `0 <=`。

## 如果面试官追问
若要求返回每笔交易后的全部余额快照？答：单次操作仍是 O(1) 改数组，快照需 O(n) 拷贝，可改为记录增量日志按需回放。
