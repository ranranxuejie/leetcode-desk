## 一句话思路
先筛出 `time_stamp` 落在 2020 年的行，再按 `user_id` 分组取 `max(time_stamp)`，分组天然排除了 2020 年没登录的用户。

## 怎么做
1. 用 `WHERE time_stamp >= '2020-01-01' AND time_stamp < '2021-01-01'` 过滤，注意用左闭右开而不是 `LIKE '2020%'`。
2. 对过滤后的行 `GROUP BY user_id`，每组只剩该用户 2020 年的登录记录。
3. 取 `MAX(time_stamp)` 并起别名 `last_stamp`，即该用户 2020 年最后一次登录。

以官方示例的 user_id=8 为例：过滤后剩 `2020-02-01 05:10:53` 和 `2020-12-30 00:46:50` 两行，分组后 `MAX` 比较出后者更大，输出 `2020-12-30 00:46:50`。user_id=6 过滤后只剩 `2020-06-30 15:06:07` 一行，`MAX` 就是它本身；user_id=14 的两行分别是 2019 和 2021，全被 `WHERE` 滤掉，分组里根本没有它，自然不出现在结果中——这正是「不包含 2020 年没登录过的用户」的实现方式，不需要额外写 `HAVING`。

```python
# 关键三行（SQL 思路，pandas 等价写法）
df = df[(df.time_stamp >= '2020-01-01') & (df.time_stamp < '2021-01-01')]
res = df.groupby('user_id')['time_stamp'].max().reset_index()
res.columns = ['user_id', 'last_stamp']
```

`reset_index()` 把 `user_id` 从索引还原成列，否则输出少一列。

## 复杂度
时间：O(n)，n 是 Logins 总行数，过滤扫一遍、分组聚合再扫一遍。
空间：O(k)，k 是 2020 年出现过的不同 user_id 数，即分组哈希表大小。

## 易错点
- 用 `LIKE '2020%'` 或 `YEAR(time_stamp) = 2020` 过滤 → 前者对 datetime 隐式转字符串，后者让 `time_stamp` 上的索引失效，大数据量下全表扫；正确做法是写死 `>= '2020-01-01' AND < '2021-01-01'` 的范围条件。
- 忘记过滤直接 `GROUP BY user_id` 取 `MAX` → user_id=6 会输出 `2021-04-21 14:06:06`，user_id=14 会输出 `2021-01-06 11:59:59`，两个都错；必须先 `WHERE` 再聚合，顺序不能反。

## 如果面试官追问
问：如果要求同时输出 2019 和 2020 两年的各自最后一次登录？
答：把年份抽成列 `GROUP BY user_id, YEAR(time_stamp)`，再在 `WHERE` 里限定 `IN (2019, 2020)`。
