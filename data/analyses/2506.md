## 一句话思路
把每个字符串压成 26 位掩码，相同掩码即相似，用哈希表边计数边累加已出现的同掩码个数。

## 怎么做
1. 对 `words` 中每个 `w`，遍历其字符，用 `mask |= 1 << (ord(c) - 97)` 得到字符集合掩码。
2. 用字典 `cnt` 记录每个掩码已出现的次数。
3. 处理当前掩码 `m` 时，先 `ans += cnt.get(m, 0)`，再 `cnt[m] = cnt.get(m, 0) + 1`，这样每对只算一次。
4. 返回 `ans`。

以示例 1 的 `words = ["aba","aabb","abcd","bac","aabc"]` 为例：`"aba"` 的掩码是 `1<<0 | 1<<1 = 3`，`"aabb"` 也是 `3`，处理到 `"aabb"` 时 `cnt[3]` 已是 1，`ans` 变 1；`"abcd"` 掩码 `1|2|4|8 = 15`，`"bac"` 也是 `15`，`ans` 变 2；`"aabc"` 掩码 `1|2|4 = 7`，此前没出现过，`ans` 保持 2。

```python
cnt = {}
ans = 0
for w in words:
    m = 0
    for c in w:
        m |= 1 << (ord(c) - 97)
    ans += cnt.get(m, 0)
    cnt[m] = cnt.get(m, 0) + 1
return ans
```

关键中间值：`"aba"` 与 `"aabb"` 的掩码都等于 `3`，这是它们被判为相似的全部依据，与长度、顺序无关。

## 复杂度
时间：O(总字符数)，每个字符做一次移位或；`words.length` 只贡献外层循环次数。
空间：O(不同掩码数)，最多 `min(n, 2**26)` 个键，实际远小于 n。

## 易错点
- 输入 `["ab","ab"]` → 若先 `cnt[m] += 1` 再累加 `ans`，会把自身这一对算进去，得到 3 而非 1 → 必须先查 `cnt.get(m, 0)` 加到 `ans`，再自增。
- 输入 `["a","aa","aaa"]` → 若用 `set(w)` 转成字符串或元组当键，逻辑也对但慢；若误用 `len(set(w))` 当键，三个长度都是 1 会全判相似，实际它们确实相似（都只含 `'a'`），但换成 `["ab","cd"]` 长度都是 2 就会错判成相似 → 键必须是完整字符集合，不能是集合大小。

## 如果面试官追问
若字符集扩到全部 ASCII，26 位移位不够怎么办？
答：改用 `frozenset(w)` 或对排序去重后的字符串做键，思路不变，只是常数变大。
