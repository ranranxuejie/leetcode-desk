## 一句话思路
把 `(nums[i], i)` 排序成候选队列，用指针顺序取最小未标记元素，配合 `marked` 数组和滚动总和。

## 怎么做
1. 预处理：`order = sorted(range(n), key=lambda i: (nums[i], i))`，`total = sum(nums)`，`marked = [False]*n`，指针 `p = 0`。
2. 每次操作先处理 `index`：若 `not marked[index]`，标记它并 `total -= nums[index]`。
3. 再处理 `k`：`while k > 0 and p < n`，跳过已标记的 `order[p]`，否则标记并扣减，`k -= 1`。
4. 每轮结束把 `total` 追加进答案。

以示例 1 的 `nums = [1,2,2,1,2,3,1]`、`queries = [[1,2],...]` 为例：`total = 12`，第一轮标记下标 1（值 2），`total = 10`；指针从 `order[0]`（下标 0，值 1）开始，标记下标 0 和 3（值都是 1），`total = 8`，与输出首项一致。

```python
order = sorted(range(n), key=lambda i: (nums[i], i))
marked = [False] * n
total, p, ans = sum(nums), 0, []
for idx, k in queries:
    if not marked[idx]:
        marked[idx] = True
        total -= nums[idx]
    while k > 0 and p < n:
        j = order[p]
        if not marked[j]:
            marked[j] = True
            total -= nums[j]
            k -= 1
        p += 1
    ans.append(total)
```

关键点：`p` 只增不减，因为被跳过的元素要么已标记、要么刚被标记，永远不会再成为候选。

## 复杂度
时间：排序 `O(n log n)`，指针 `p` 全程最多走 `n` 步，总 `O(n log n + m + n)`。
空间：`order`、`marked`、`ans` 各 `O(n)`，无堆。

## 易错点
- `queries` 里 `index` 可能已被前面的 `k` 标记过（示例 1 第二轮 `index=3` 就是），此时不能重复扣 `total`，否则答案偏小；必须先查 `marked[index]`。
- `k` 很大时（如 `k = n-1`）指针会一路扫到 `n`，若 `while` 条件只写 `k > 0` 不写 `p < n`，会 `IndexError`；正确做法是双条件并允许提前耗尽。

## 如果面试官追问
若 `nums` 动态修改（单点更新）怎么办？答：改用堆存 `(值, 下标)`，更新时惰性删除旧条目，复杂度 `O((n+m) log n)`。
