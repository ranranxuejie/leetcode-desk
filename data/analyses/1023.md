## 一句话思路
双指针扫 query：小写字母只能被跳过，大写字母必须与 pattern 当前位严格对上，最后 pattern 必须耗尽。

## 怎么做
1. 对每个 `q` 设 `j = 0` 指向 pattern 待匹配位。
2. 遍历 `q` 的每个字符 `c`：若 `c` 是小写，直接跳过（插入的只能是它）。
3. 若 `c` 是大写，则要求 `j < len(pattern)` 且 `pattern[j] == c`，否则该 query 判 `False`；匹配成功则 `j += 1`。
4. 扫完 `q` 后检查 `j == len(pattern)`，相等才为 `True`。

以示例 1 的 `q = "FooBar"`、`pattern = "FB"` 为例：`F` 大写对上 `pattern[0]`，`j` 变 1；`oo` 小写跳过；`B` 对上 `pattern[1]`，`j` 变 2；`ar` 跳过；末尾 `j == 2 == len("FB")`，返回 `True`。而 `"FooBarTest"` 扫到 `T` 时 `j` 已是 2，`j < len(pattern)` 不成立，直接判 `False`。

```python
def match(q, p):
    j = 0
    for c in q:
        if c.islower():
            continue
        if j < len(p) and p[j] == c:
            j += 1
        else:
            return False
    return j == len(p)
```

关键点：小写字母永远不消耗 `j`，所以 `pattern` 里若出现小写（如 `"FoBa"`），它必须靠 query 中对应位置的小写来消耗——`"FooBar"` 里第二个 `o` 之后紧跟 `B`，`pattern[1] = 'o'` 由 `"FooBar"` 的第二个 `o` 匹配，`j` 才推进到 2。

## 复杂度
时间：O(Σ|queries[i]| + |pattern|)，每个 query 字符只看一次。
空间：O(1) 额外（不计输出数组），只用了 `j` 一个指针。

## 易错点
- `pattern` 含小写时（如 `"FoBa"`）若把小写也当「可跳过」，`"FrameBuffer"` 会被误判 `True`：它的大写序列是 `FB`，缺 `o`、`a`。正确做法是小写字符也要和 `pattern[j]` 比对，对上才 `j += 1`，不能无条件 `continue`。
- 只检查大写、忘了末尾 `j == len(pattern)`：`queries = ["FooBar"]`、`pattern = "FBX"` 会错判 `True`，因为 `X` 从未被消耗。正确做法是循环结束后必须校验 `j` 已走完整个 pattern。

## 如果面试官追问
问：若 query 长度到 10^5、query 数到 10^5 怎么办？
答：仍是 O(总字符数) 线性扫描，无需建字典树；瓶颈在输入规模而非算法。
