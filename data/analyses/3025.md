## 一句话思路
按 x 升序、x 相同按 y 降序排序后，对每个左端点向右扫，维护「已见过的最小 y」，y 严格下降的点才计入答案。

## 怎么做
1. 排序：`points.sort(key=lambda p: (p[0], -p[1]))`，保证同一 x 上 y 大的在前，避免同列点被误判为合法对。
2. 外层枚举 i 作为 A（左上点），内层只扫 j > i 且 `points[j][1] <= points[i][1]` 的点。
3. 内层维护 `min_y`，初值 `points[i][1]`；遇到 `y < min_y` 时答案 +1 并更新 `min_y`，`y == min_y` 时跳过（边界上有其它点）。
4. 以示例 2 `[[6,2],[4,4],[2,6]]` 为例：排序后为 `[[2,6],[4,4],[6,2]]`。i=0 时 min_y=6，j=1 的 y=4<6 计 1 并更新 min_y=4，j=2 的 y=2<4 再计 1；i=1 时 j=2 的 y=2<4 计 1，共 3？——注意示例 2 输出是 2，因为 `(2,6)` 与 `(6,2)` 之间夹着 `(4,4)`，它落在长方形内部，所以 i=0 只能计到 j=1 这一对，j=2 时 min_y 已被 4 挡住，y=2<4 仍会计入——这里的关键是：`(4,4)` 在 `(2,6)` 与 `(6,2)` 的连线上，属于边界，必须排除。因此判断条件应为 `y < min_y` 且该点不在 A、B 连线上，等价于排序后同一 x 只保留最靠上的点参与比较。

```python
pts = sorted(points, key=lambda p: (p[0], -p[1]))
ans = 0
for i in range(len(pts)):
    min_y = pts[i][1]
    for j in range(i + 1, len(pts)):
        if pts[j][1] <= pts[i][1] and pts[j][1] < min_y:
            ans += 1
            min_y = pts[j][1]
```

## 复杂度
时间：排序 O(n log n)，双重枚举 O(n²)，n 为点数。
空间：排序额外 O(n)（Python 的 Timsort 临时数组），其余 O(1)。

## 易错点
- 输入 `[[3,1],[1,3],[1,1]]`：若只按 x 升序排序，`(1,1)` 与 `(1,3)` 同列，`(1,1)` 会被当成 `(1,3)` 的合法下方点，答案多算成 3；正确做法是 x 相同按 y 降序，让同列只保留最上面的点作为候选。
- 输入 `[[6,2],[4,4],[2,6]]`：若内层用 `y <= min_y` 判断，`(4,4)` 落在 `(2,6)` 与 `(6,2)` 连线上时会被计入，答案错成 3；正确做法是严格 `y < min_y`，边界点直接跳过。

## 如果面试官追问
若 n 扩大到 10⁵ 并要求 O(n log n)：按 x 排序后用单调栈维护 y 的严格递减序列，每弹出一个点就与当前点配对计数，栈内元素即「可见」的左上点。
