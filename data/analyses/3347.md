## 一句话思路
排序后对每个候选目标值 x，用二分/双指针统计 `[x-k, x+k]` 内的元素数，答案取 `min(窗口内总数, 已有 x 的个数 + numOperations)` 的最大值。

## 怎么做
1. 排序 `nums`，用 `Counter` 记每个值的原始频次 `cnt`。
2. 枚举候选目标 x：只需枚举 `nums` 中出现过的值（最优目标必可平移到某个原值上，因为窗口右移不增元素数）。
3. 对每个 x，用 `bisect_left/right` 求 `[x-k, x+k]` 的下标区间 `[lo, hi)`，窗口内总数 `total = hi - lo`。
4. 该 x 能达到的频次是 `min(total, cnt[x] + numOperations)`，取全局最大。

以 `nums=[1,4,5], k=1, numOperations=2` 为例：排序后枚举 x=4，窗口 `[3,5]` 命中下标 1、2，`total=2`，`cnt[4]=1`，得 `min(2, 1+2)=2`；枚举 x=1 时窗口 `[0,2]` 只命中 1，`total=1`，得 1。最大值 2。

```python
from bisect import bisect_left, bisect_right
from collections import Counter

nums.sort()
cnt = Counter(nums)
ans = 0
for x in cnt:
    lo = bisect_left(nums, x - k)
    hi = bisect_right(nums, x + k)
    total = hi - lo
    ans = max(ans, min(total, cnt[x] + numOperations))
return ans
```

关键点：`cnt[x] + numOperations` 是上界——窗口内非 x 的元素每个最多被改一次，而 x 本身不用改，所以能凑到的 x 个数不超过「原有 x 数 + 操作数」。

## 复杂度
时间：排序 O(n log n)，枚举去重值 O(m log n)，m ≤ n，合计 O(n log n)。
空间：`Counter` 与排序栈 O(n) 额外空间。

## 易错点
- `numOperations` 很大（如 `nums=[1,4,5], k=1, numOperations=3`）时，若直接返回 `total` 会得 3，但窗口 `[3,5]` 只有 2 个元素，正确是 `min(2, 1+3)=2` → 必须对 `total` 取 min。
- `k=0` 且 `numOperations=0`（如 `nums=[5,11,20,20]`）时，若漏掉「x 自身不改也算频次」，会把 `cnt[x]+0` 与 `total` 混淆；此时窗口只含 x 本身，`total=cnt[x]`，答案应是 2（两个 20），取 `min` 后仍正确，但若把 `cnt[x]` 写成 1 就错成 1。

## 如果面试官追问
要求输出具体方案（哪些下标改成什么值）怎么办？
答：对取到最优的 x，把窗口内非 x 的前 `numOperations` 个元素各改成 x，记录原值与新值即可。
