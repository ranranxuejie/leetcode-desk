## 一句话思路
边扫边维护 `seen` 集合与长度 `i+1`，逐个前缀比较 `len(seen)` 与 `(i+1) % 3`，相等就计数。

## 怎么做
1. 初始化 `seen = set()`、`ans = 0`，按下标 `i` 遍历 `s`。
2. 每步把 `s[i]` 加入 `seen`，此时 `seen` 恰好是前缀 `s[:i+1]` 的去重字符集。
3. 令 `r = (i + 1) % 3`，若 `len(seen) == r` 则 `ans += 1`。
4. 遍历结束返回 `ans`。

以 `s = "abc"` 为例：`i=0` 时 `seen={'a'}`，`len=1`，`r=1%3=1`，相等，`ans=1`；`i=1` 时 `seen={'a','b'}`，`len=2`，`r=2`，相等，`ans=2`；`i=2` 时 `seen` 大小 3，`r=0`，不等。返回 2。

```python
seen = set()
ans = 0
for i, ch in enumerate(s):
    seen.add(ch)
    if len(seen) == (i + 1) % 3:
        ans += 1
return ans
```

关键点：`len(seen)` 是「不同字符数」，不是前缀长度；`(i+1) % 3` 才是长度模 3。两者量纲不同，别拿 `i+1` 去比。

## 复杂度
时间 O(n)：每个字符入集合一次，集合操作均摊 O(1)。
空间 O(1)：`seen` 最多 26 个小写字母，与 n 无关。

## 易错点
- 输入 `s = "dd"`：若用 `i % 3` 而不是 `(i+1) % 3`，第一个前缀会算成 `0 % 3 = 0`，与 `len(seen)=1` 不等，漏掉这个残差前缀，答案错成 0。正确做法是长度取 `i+1` 再模 3。
- 输入 `s = "bob"`：若把「不同字符数」误写成前缀长度 `i+1`，第三个前缀会判成 `3 == 3 % 3 = 0` 不成立、第二个前缀 `2 == 2` 成立，看似答案对，但换成 `"aaa"` 就会把 `len=1` 与 `r=1` 之外的前缀全判错。必须用 `len(seen)`。

## 如果面试官追问
若 n 放大到 10^7 且字符集扩到全部 Unicode，怎么做？答：仍是一遍扫描，把 `seen` 换成哈希集合即可，空间上界变成字符集大小而非 26。
