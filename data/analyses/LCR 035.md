## 一句话思路
把每个 "HH:MM" 转成一天内的分钟数排序，最小差只可能出现在相邻两项或首尾跨午夜处。

## 怎么做
1. 用 `int(t[:2]) * 60 + int(t[3:])` 把每个时间点转成 0..1439 的分钟数，存进 `mins`。
2. 对 `mins` 排序，相邻差 `mins[i] - mins[i-1]` 逐个比较取最小。
3. 别忘了首尾跨午夜：补一个 `mins[0] + 1440 - mins[-1]` 参与比较。
4. 因为一天只有 1440 分钟，`len(timePoints) > 1440` 时必有重复，直接返回 0。

以示例 1 `["23:59","00:00"]` 为例：转换后 `mins = [1439, 0]`，排序得 `[0, 1439]`；相邻差是 1439，跨午夜差是 `0 + 1440 - 1439 = 1`，取最小得 1。

```python
mins = sorted(int(t[:2]) * 60 + int(t[3:]) for t in timePoints)
if len(mins) > 1440:
    return 0
best = mins[0] + 1440 - mins[-1]
for i in range(1, len(mins)):
    best = min(best, mins[i] - mins[i - 1])
return best
```

注意 `best` 的初值必须先放跨午夜那一项，否则 `["23:59","00:00"]` 这种只有两项、相邻差很大的输入会漏掉答案 1。

## 复杂度
时间：O(n log n)，n 是 `timePoints` 长度，排序贡献 log n，转换是 O(n)。
空间：O(n)，`mins` 列表存 n 个整数，排序本身 O(log n) 栈。

## 易错点
- 只算相邻差、忘了首尾跨午夜 → `["23:59","00:00"]` 会错成 1439 → 必须把 `mins[0] + 1440 - mins[-1]` 也纳入比较。
- 没做 `len > 1440` 的提前返回 → 2*10^4 个时间点里必然有重复，答案应为 0，但排序后相邻差最小也是 0，逻辑上仍对；真正的坑是**先排序再判重**浪费了 O(n log n)，正确做法是长度超 1440 直接返回 0。

## 如果面试官追问
问：如果时间点带秒 "HH:MM:SS" 怎么办？
答：把一天换成 86400 秒，转换式改成 `h*3600 + m*60 + s`，跨午夜补 `86400`，其余逻辑不变。
