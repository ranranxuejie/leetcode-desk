## 一句话思路
枚举加倍次数 k，总时间 = k + ceil(n / 2^k)，取最小值；k 只需枚举到 17 左右。

## 怎么做
1. 设加倍 k 次，带宽变成 `2**k`，之后每轮下载 `2**k` 个，剩余下载轮数 `ceil(n / 2**k)`。
2. 总时间 `k + (n + 2**k - 1) // 2**k`，对 k 从 0 开始枚举取最小。
3. k 的上界：`2**k >= n` 后继续加倍只会让 k 增大而轮数恒为 1，故枚举到 `n.bit_length()` 即可。

以 `n = 4` 为例：k=0 时 `0 + 4 = 4`；k=1 时 `1 + (4+1)//2 = 1 + 2 = 3`；k=2 时 `2 + (4+3)//4 = 2 + 1 = 3`；k=3 时 `3 + 1 = 4`。最小值 3，与示例一致。

```python
def leastMinutes(n):
    best = n
    k = 0
    while (1 << k) < n:
        k += 1
        cur = k + (n + (1 << k) - 1) // (1 << k)
        if cur < best:
            best = cur
    return best
```

注意循环条件 `(1 << k) < n` 保证 k 覆盖到 `2**k >= n` 那一档，此时轮数为 1，`k + 1` 通常已不优，但保留比较不会错。

## 复杂度
时间：O(log n)，k 从 0 枚举到 `n.bit_length()`，每轮 O(1)。
空间：O(1)，只用了 `best`、`k`、`cur` 三个整数。

## 易错点
- `n = 1` 时若从 k=1 开始枚举，会算出 `1 + 1 = 2`，而正确答案是 1（直接下载）。必须让 k=0 参与比较，初始 `best = n` 就是兜住这一档。
- 用 `n // 2**k` 代替向上取整：`n = 5, k = 1` 时得 `1 + 2 = 3`，实际需要 `1 + 3 = 4` 分钟（带宽 2 下 5 个要 3 轮）。必须写 `(n + 2**k - 1) // 2**k`。

## 如果面试官追问
问：如果每分钟可以「下载」或「加倍」二选一，但加倍有冷却（不能连续加倍）？
答：状态里多记一个「上一分钟是否加倍」，DP 或枚举时把 k 拆成若干段，复杂度仍是 O(log n)。
