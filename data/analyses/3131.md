## 一句话思路
排序后取 `nums2[0] - nums1[0]`，因为同一 x 加到每个元素上不改变两数组的大小顺序。

## 怎么做
1. 对 `nums1` 和 `nums2` 分别排序，让「第 i 小」对「第 i 小」。
2. 取排序后第一个元素相减：`x = nums2[0] - nums1[0]`。
3. 直接返回这个差值，不需要验证其余位置。

以示例 1 为例：`nums1 = [2,6,4]` 排序得 `[2,4,6]`，`nums2 = [9,7,5]` 排序得 `[5,7,9]`。此时 `nums2[0] - nums1[0] = 5 - 2 = 3`，正好是答案；再看中间位 `7 - 4 = 3`、末位 `9 - 6 = 3`，全部一致，说明 x 是全局常量而非局部巧合。

```python
a = sorted(nums1)
b = sorted(nums2)
return b[0] - a[0]
```

为什么排序后相减一定对：设原数组里 `nums1` 的最小值是 `a[0]`，它加 x 后变成 `a[0] + x`，这个值必然落在 `nums2` 里；而 `nums2` 的最小值 `b[0]` 是全体元素加 x 后的最小值，所以 `b[0] = a[0] + x`。这一步只用到「加同一个数保持序关系」，不需要频次信息。

示例 2 验证边界：`nums1 = [10]`、`nums2 = [5]`，排序后仍是单元素，`5 - 10 = -5`，负数结果正常返回，不需要特判。示例 3 全相等：`[1,1,1,1]` 与自身，`1 - 1 = 0`。

## 复杂度
时间：排序两个长度 n 的数组，O(n log n)，n 为数组长度。
空间：排序产生的副本 O(n)，不额外开哈希表或计数数组。

## 易错点
- 输入 `nums1 = [2,6,4]`、`nums2 = [9,7,5]` 时直接取 `nums2[0] - nums1[0] = 9 - 2 = 7` → 错成 7，因为原数组下标不对应 → 必须先排序再取首元素，或改用 `min(nums2) - min(nums1)`。
- 输入 `nums1 = [1,1,1,1]`、`nums2 = [1,1,1,1]` 时若用「找第一个不相等的下标再相减」→ 找不到差异会返回 `None` 或越界 → 本题 x 可以为 0，直接首元素相减即可，不要依赖「存在差异」这个前提。

## 如果面试官追问
追问：如果 nums1 和 nums2 长度不等，还能这样解吗？答：不能，长度不等时「加同一 x 后相等」本身不成立，需先确认题意是否改为子集匹配。
