## 一句话思路
从右往左扫，维护右侧奇数和偶数的个数，当前元素是奇数就取右侧偶数个数，反之取奇数个数。

## 怎么做
1. 初始化 `right_odd = 0`、`right_even = 0`，`answer = [0] * n`。
2. 从 `i = n-1` 倒序循环到 0，先按 `nums[i]` 的奇偶性把对应计数写进 `answer[i]`。
3. 再把 `nums[i]` 自己计入右侧计数，供左边的下标使用。
4. 返回 `answer`。

以 `nums = [1,2,3,4]` 为例：`i=3` 时 `nums[3]=4` 是偶数，`answer[3] = right_odd = 0`，然后 `right_even` 变 1；`i=2` 时 `nums[2]=3` 是奇数，`answer[2] = right_even = 1`，`right_odd` 变 1；`i=1` 时 `nums[1]=2` 是偶数，`answer[1] = right_odd = 1`；`i=0` 时 `nums[0]=1` 是奇数，`answer[0] = right_even = 2`。

```python
right_odd = right_even = 0
answer = [0] * len(nums)
for i in range(len(nums) - 1, -1, -1):
    if nums[i] % 2 == 1:
        answer[i] = right_even
        right_odd += 1
    else:
        answer[i] = right_odd
        right_even += 1
return answer
```

关键点：`answer[i]` 必须在把 `nums[i]` 计入计数**之前**写，否则 `i` 会把自己算进 `j`，违反 `i < j`。

## 复杂度
时间：O(n)，倒序扫一遍，每个下标只做常数次判断和赋值。
空间：O(n)，除返回数组 `answer` 外只开了 `right_odd`、`right_even` 两个计数器。

## 易错点
- 写成先 `right_odd += 1` 再取 `answer[i]`：对 `nums = [1,2,3,4]` 的 `i=0`，会把自己算进去得到 3 而不是 2。正确顺序是先取值、后自增。
- 用双重循环对每个 `i` 再扫一遍 `j > i`：n=100 时是 4950 次比较，虽然能过但白丢分；且容易把 `j` 的起点写成 `i` 而不是 `i+1`，导致 `nums[i]` 与自身比较（同奇偶性不会误判，但逻辑已错）。

## 如果面试官追问
问：如果要求在线回答，每插入一个元素就返回当前所有下标的新分数？
答：维护全局奇偶总数，插入时对已有下标按奇偶性批量加 1，用两个累加偏移量 O(1) 完成。
