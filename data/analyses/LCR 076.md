## 一句话思路
用快速选择在 `nums` 上原地划分，把「第 k 大」转成「升序下标 n-k」，每轮只递归一侧。

## 怎么做
1. 目标下标 `target = len(nums) - k`，找升序排好后落在 `target` 的元素。
2. 取 `nums[lo]` 为 pivot，用双指针把小于 pivot 的换到左边，返回 pivot 最终落点 `p`。
3. `p == target` 直接返回 `nums[p]`；`p < target` 只搜右半，否则只搜左半。
4. 用循环而非递归，避免 10^4 规模下的递归栈开销。

以 `nums = [3,2,1,5,6,4], k = 2` 为例，`target = 4`。第一轮 pivot=3，划分后数组变 `[1,2,3,5,6,4]`，`p = 2`；因 `2 < 4`，`lo` 改为 3，只在 `[5,6,4]` 里继续找下标 4 的元素，最终返回 5。

```python
def findKthLargest(nums, k):
    target, lo, hi = len(nums) - k, 0, len(nums) - 1
    while True:
        pivot, p = nums[lo], lo
        for i in range(lo + 1, hi + 1):
            if nums[i] < pivot:
                p += 1
                nums[p], nums[i] = nums[i], nums[p]
        nums[lo], nums[p] = nums[p], nums[lo]
        if p == target:
            return nums[p]
        if p < target:
            lo = p + 1
        else:
            hi = p - 1
```

## 复杂度
时间：平均 O(n)，每轮划分扫当前区间，区间期望减半；最坏 O(n^2)（已排序输入 + 固定取首元素）。
空间：O(1)，只用了 `lo/hi/p/pivot` 几个变量，原地交换。

## 易错点
- 输入 `nums = [3,2,1,5,6,4], k = 2` 时若把 `target` 写成 `k - 1 = 1`，会返回升序第 2 小即 2，正确答案是 5；必须用 `len(nums) - k`。
- 输入 `nums = [1,2,3,4,5], k = 1` 这类已升序数组，固定取 `nums[lo]` 当 pivot 每轮只缩小一格，退化成 O(n^2)；面试中应说明随机化 pivot（`random.randint(lo, hi)` 后与 `nums[lo]` 交换）来保证期望复杂度。

## 如果面试官追问
问：数据量涨到 10^8、内存放不下怎么办？
答：改用大小为 k 的小顶堆流式扫描，时间 O(n log k)、空间 O(k)，只保留当前最大的 k 个。
