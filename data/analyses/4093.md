## 一句话思路
每个数重排后最大就是数字降序排列，所以只需把「最大增量」前 k 大的数各重排一次。

## 怎么做
1. 对每个 `nums[i]`，把它的十进制数字降序拼起来得到 `best`，增量 `gain = best - nums[i]`。
2. 把所有 `gain` 收集起来降序排序，取前 `min(k, n)` 个相加。
3. 答案 = `sum(nums) + 这些 gain 之和`（`gain` 为 0 的数重排也无所谓，不影响结果）。

以 `nums = [102, 90, 14], k = 2` 为例：`102` 的数字降序是 `210`，`gain = 108`；`90` 已是降序，`gain = 0`；`14` 降序是 `41`，`gain = 27`。排序后取前 2 个 `108 + 27`，答案 `206 + 135 = 341`。

```python
total = sum(nums)
gains = []
for x in nums:
    best = int(''.join(sorted(str(x), reverse=True)))
    gains.append(best - x)
gains.sort(reverse=True)
total += sum(gains[:k])
return total
```

注意 `sorted(str(x), reverse=True)` 是字符排序，对单个数字字符等价于数值降序；`90` 排完仍是 `"90"`，`gain` 为 0，符合预期。

## 复杂度
时间：O(n log n)，每个数转字符串排序是 O(log nums[i])，整体被 `gains.sort` 的 n log n 主导。
空间：O(n)，`gains` 列表存 n 个增量，字符串临时空间 O(log nums[i])。

## 易错点
- 输入含前导零可能的数如 `102`：若升序排会得到 `012` 即 `12`，增量算成负数 → 必须 `reverse=True` 降序，得到 `210`。
- `k` 可能大于实际有正增量的个数，如 `nums = [90, 99], k = 2`：两个 `gain` 都是 0，直接取 `gains[:2]` 仍正确；但若误以为「必须重排 k 次」而去重排已最优的数，结果不变，别写成跳过导致漏加。

## 如果面试官追问
问：若要求输出重排后的数组而非和？
答：排序 `gains` 时保留原下标，对前 k 个下标把 `nums[i]` 替换成降序拼接的 `best` 即可。
