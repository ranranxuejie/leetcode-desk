## 一句话思路
用哈希表把「文件内容」映射到「路径列表」，遍历完取长度 ≥2 的组。

## 怎么做
1. 对 `paths` 中每个字符串按空格切分，第 0 段是目录，其余每段是一个文件。
2. 对每个文件段，用 `rfind('(')` 定位内容起点，`[:-1]` 去掉右括号，得到 `name` 和 `content`。
3. 把 `dir + '/' + name` 追加进 `table[content]`。
4. 最后筛出 `len(v) >= 2` 的 `v` 作为答案。

以示例 1 为例，处理 `"root/a 1.txt(abcd) 2.txt(efgh)"` 时，`table` 变成 `{"abcd": ["root/a/1.txt"], "efgh": ["root/a/2.txt"]}`；再处理 `"root 4.txt(efgh)"` 后，`table["efgh"]` 变为 `["root/a/2.txt", "root/c/d/4.txt", "root/4.txt"]`，长度 3，进入答案。

```python
table = {}
for info in paths:
    parts = info.split(' ')
    d = parts[0]
    for f in parts[1:]:
        i = f.rfind('(')
        name, content = f[:i], f[i + 1:-1]
        table.setdefault(content, []).append(d + '/' + name)
return [v for v in table.values() if len(v) > 1]
```

关键点：`rfind` 而不是 `find`，因为文件名里可能含 `(`；`f[i+1:-1]` 一次剥掉左右括号。

## 复杂度
时间 O(S)：S 为所有 `paths[i]` 长度之和，每个字符只被扫常数次。
空间 O(S)：`table` 存全部路径字符串，最坏无重复时也是 O(S)。

## 易错点
- 输入 `"root/a 1.txt(ab(cd))"` 这类内容含括号 → 用 `find('(')` 会把内容截成 `ab`，路径分组错乱 → 必须用 `rfind('(')` 取最后一个左括号。
- 输入里只有一个目录、文件内容全不同（如 `["root/a 1.txt(x)"]`）→ 若直接 `return list(table.values())` 会把单文件组也输出 → 必须加 `len(v) > 1` 过滤，否则答案多出一组。

## 如果面试官追问
问：内容 GB 级、每次只能读 1KB 怎么办？
答：先按文件大小分组，只对同大小的文件流式读 1KB 块算哈希，哈希相同再逐块比对确认，避免全量载入内存。
