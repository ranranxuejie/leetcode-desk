## 一句话思路
按 `(actor_id, director_id)` 分组计数，筛出计数 ≥3 的组，因为每行就是一次合作。

## 怎么做
1. 用 `GROUP BY actor_id, director_id` 把同一对演员导演的行聚成一组。
2. 用 `COUNT(*)` 数每组的行数，即合作次数。
3. 用 `HAVING COUNT(*) >= 3` 过滤，注意不能用 `WHERE`，因为过滤的是聚合结果。
4. 选出两列 id 即可。

拿官方示例走一遍：7 行按对分组后，`(1,1)` 组有 timestamp 0、1、2 共 3 行，`(1,2)` 组有 3、4 共 2 行，`(2,1)` 组有 5、6 共 2 行。`HAVING COUNT(*) >= 3` 只留下 `(1,1)`，计数正好等于 3，边界值 3 必须用 `>=` 而不是 `>`。

```python
# 关键 SQL
SELECT actor_id, director_id
FROM ActorDirector
GROUP BY actor_id, director_id
HAVING COUNT(*) >= 3;
```

如果按 Python 写（pandas 风格），等价逻辑是：

```python
df.groupby(["actor_id", "director_id"]).size().reset_index(name="cnt")
df = df[df["cnt"] >= 3][["actor_id", "director_id"]]
```

`size()` 数的是组内行数，`timestamp` 是主键保证每行唯一，所以行数就是合作次数，不需要 `COUNT(DISTINCT timestamp)`。

## 复杂度
时间 O(n)，n 为表行数，分组哈希扫一遍。
空间 O(k)，k 为不同 id 对数量，即分组哈希表大小。

## 易错点
- 用 `WHERE COUNT(*) >= 3` → 报聚合函数不能出现在 WHERE 中 → 必须写 `HAVING`，因为过滤发生在分组之后。
- 写成 `HAVING COUNT(*) > 3` → 示例中 `(1,1)` 恰好 3 次会被漏掉，输出空集 → 题目是「至少三次」，用 `>= 3`。
- 只 `GROUP BY actor_id` → `(1,1)` 和 `(1,2)` 会被合并成 actor 1 的 5 行，错误输出 `(1, ?)` → 必须两列一起分组。

## 如果面试官追问
问：如果要求输出合作次数并降序取前 3 对？
答：在 SELECT 里加 `COUNT(*) AS cnt`，`ORDER BY cnt DESC LIMIT 3`，分组和 HAVING 逻辑不变。
