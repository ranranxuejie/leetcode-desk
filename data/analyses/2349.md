## 一句话思路
用 `idx2num` 记录每个下标当前数字，用 `num2heap` 给每个数字维护一个小顶堆，`find` 时惰性弹出已失效下标。

## 怎么做
1. `change(index, number)` 先把 `idx2num[index]` 更新为 `number`，并把 `index` 压入 `num2heap[number]`。
2. 旧数字的堆里会残留 `index`，不主动删除，留给 `find` 惰性清理。
3. `find(number)` 循环检查堆顶：若 `idx2num[堆顶] != number` 就 `heappop`，直到堆空返回 `-1`，否则返回堆顶。

以官方示例为例，`change(1, 20)` 后 `idx2num[1] = 20`，但 `num2heap[10]` 里仍有 `1`；随后 `find(10)` 看到堆顶 `1` 与 `idx2num[1] = 20` 不符，弹出后堆顶变 `2`，返回 `2`。

```python
import heapq

def change(self, index, number):
    self.idx2num[index] = number
    heapq.heappush(self.num2heap[number], index)

def find(self, number):
    h = self.num2heap.get(number, [])
    while h and self.idx2num[h[0]] != number:
        heapq.heappop(h)
    return h[0] if h else -1
```

## 复杂度
时间：每次 `change` 是 O(log n) 入堆；`find` 的弹出总量摊还 O(n log n)，n 为总调用次数。
空间：`idx2num` 存 O(n) 个下标，`num2heap` 累计 O(n) 个残留下标。

## 易错点
- `change(1, 20)` 后 `num2heap[10]` 仍含 `1`，若 `find(10)` 直接返回堆顶会错答 `1`；必须用 `idx2num[h[0]] != number` 校验后再弹。
- 同一数字被反复 `change` 到同一下标（如 `change(2,10)` 两次）会让堆里出现重复 `2`；惰性删除只按值校验，重复项不影响正确性，但别在 `change` 里额外去重导致漏压。

## 如果面试官追问
问：若要求 `find` 严格 O(1)？答：改用 `num2set` + 有序结构（如平衡树/`SortedList`），`change` 时从旧集合删、新集合加，`find` 取集合最小值。
