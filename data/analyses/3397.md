## 一句话思路
排序后贪心：每个数尽量取「比上一个已用值大 1」的最小可行值，可行区间是 `[x-k, x+k]`。

## 怎么做
1. 对 `nums` 升序排序，让每个数的可选区间 `[x-k, x+k]` 左端点单调不减。
2. 维护 `last` = 上一个被占用的值，初始为极小值（如 `-2**31`）。
3. 对每个 `x`，取 `v = max(x - k, last + 1)`；若 `v <= x + k` 则占用它、`last = v`、答案 +1，否则跳过。
4. 用示例 1 走一遍：`nums=[1,2,2,3,3,4], k=2`。第一个 `1` 取 `max(-1, -2**31+1) = -1`，`last=-1`；`2` 取 `max(0, 0)=0`；第二个 `2` 取 `max(0, 1)=1`；`3` 取 `max(1, 2)=2`；第二个 `3` 取 `max(1, 3)=3`；`4` 取 `max(2, 4)=4`，六个数全部落位，答案 6。

```python
nums.sort()
last = -2**31
ans = 0
for x in nums:
    v = max(x - k, last + 1)
    if v <= x + k:
        last = v
        ans += 1
return ans
```

关键点：`last + 1` 而不是 `last`，保证严格递增；`v <= x + k` 是唯一判可行的条件，不满足就说明这个 `x` 的区间已被前面占满，直接丢弃。

## 复杂度
时间：排序 `O(n log n)` 主导，扫描 `O(n)`，n 为 `nums` 长度。
空间：排序额外 `O(log n)`（或 `O(n)`，视实现），其余只用了 `last`、`ans` 两个变量。

## 易错点
- 输入 `nums=[4,4,4,4], k=1`：若把 `last` 初值设成 0 或 `nums[0]-k`，第一个 `4` 会取到 `3`，之后 `4`、`5` 依次落位仍得 3，看似没事；但输入 `nums=[1,1], k=0` 时若 `last` 初值取 0，第一个 `1` 的 `max(1, 1)=1` 正常，第二个 `1` 得 `max(1, 2)=2 > 1` 被丢弃，答案 1 正确——真正的坑是 `last` 初值必须小于任何可能的 `x-k`，用 `-2**31` 而非 `0`，否则 `nums=[1], k=0` 之外的负数场景会误判。
- 输入 `nums=[1,2,2,3,3,4], k=2`：若写成 `v = max(x-k, last)` 而非 `last+1`，第二个 `2` 会取到 `0` 与第一个 `2` 的 `0` 重复，答案错成 5；必须 `last + 1` 强制严格递增。

## 如果面试官追问
问：若要求输出具体方案（每个元素加多少）？答：扫描时把 `v - x` 记进结果数组，丢弃的元素记 `None` 即可，逻辑不变。
