## 一句话思路
按难度排序工作并维护前缀最大收益，工人能力排序后双指针扫描，每个工人取当前能做的最高收益。

## 怎么做
1. 把 `(difficulty[i], profit[i])` 配对后按难度升序排序。
2. 遍历排序后的工作，把 `profit` 原地改成「到当前为止的最大收益」，即 `profit[i] = max(profit[i], profit[i-1])`。
3. 把 `worker` 升序排序，用指针 `j` 从 0 开始，对每个工人能力 `w` 推进 `j` 直到 `difficulty[j] > w`，累加 `profit[j-1]`（`j>0` 时）。

以示例 1 为例：排序后 `difficulty=[2,4,6,8,10]`，前缀最大 `profit=[10,20,30,40,50]`。工人 `w=4` 时 `j` 推进到 2（`difficulty[2]=6>4`），累加 `profit[1]=20`；`w=5` 时 `j` 停在 2，仍累加 `profit[1]=20`；`w=6` 时 `j` 推进到 3，累加 `profit[2]=30`。合计 `20+20+30+30=100`。

```python
jobs = sorted(zip(difficulty, profit))
d = [x[0] for x in jobs]
p = [x[1] for x in jobs]
for i in range(1, len(p)):
    p[i] = max(p[i], p[i - 1])
worker.sort()
ans = j = 0
for w in worker:
    while j < len(d) and d[j] <= w:
        j += 1
    if j > 0:
        ans += p[j - 1]
return ans
```

关键点：`p` 的前缀最大值让 `p[j-1]` 直接就是「能力 `w` 能做的所有工作里的最高收益」，不用回退找。

## 复杂度
时间：排序 `difficulty` 和 `worker` 各 O(n log n)、O(m log m)，双指针扫描 O(n+m)。
空间：`jobs`/`d`/`p` 额外 O(n)，排序本身 O(log n) 栈。

## 易错点
- 不做前缀最大：`difficulty=[2,4,6]`、`profit=[30,10,20]` 时，工人能力 6 会取到 `profit[2]=20`，但正确答案是难度 2 的 30。必须先跑一遍 `p[i]=max(p[i],p[i-1])`。
- 工人能力低于所有工作难度：示例 2 中 `worker=[40,25,25]` 全部小于最小难度 47，`j` 始终为 0，若直接写 `ans += p[j-1]` 会取到 `p[-1]=99` 变成 297。必须加 `if j > 0` 判断。

## 如果面试官追问
问：如果要求输出每个工人分配的具体工作编号怎么办？
答：前缀最大时同步记录取到最大值的那个工作下标 `best_idx[i]`，累加时输出 `best_idx[j-1]` 即可。
