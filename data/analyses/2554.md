## 一句话思路
从小到大贪心取未被 ban 的数，因为任意 k 个数里最小的 k 个和最小，取小不取大不会更差。

## 怎么做
1. 把 `banned` 转成 `set`，O(1) 判断；遍历 `x = 1..n`，跳过在集合里的。
2. 对每个可取的 `x`，若 `maxSum - x >= 0` 就取它，`maxSum -= x`，`count += 1`；否则 `break`。
3. 因为 `x` 递增，一旦某个 `x` 放不下，后面更大的更放不下，直接停。

用示例 1：`banned = [1,6,5], n = 5, maxSum = 6`。`x=1` 被 ban 跳过；`x=2` 取，`maxSum` 变 4，`count=1`；`x=3` 取，`maxSum` 变 1，`count=2`；`x=4` 时 `1-4 < 0`，break，返回 2。注意 `x=4` 其实放不下，但 `x=2,4` 的和 6 恰好等于 `maxSum`——这里贪心取的是 2 和 3，和 5，count 同样是 2，答案数不变。

```python
ban = set(banned)
cnt = 0
for x in range(1, n + 1):
    if x in ban:
        continue
    if x > maxSum:
        break
    maxSum -= x
    cnt += 1
return cnt
```

关键点：`x > maxSum` 用 `>` 而不是 `>=`，因为 `x == maxSum` 时还能取这一个（和正好用满）。

## 复杂度
时间 O(n + |banned|)：建集合 O(|banned|)，循环最多 n 次。
空间 O(|banned|)：额外开一个 set，其余是常数。

## 易错点
- `banned` 里有大于 n 的元素（如示例 3 的 `11`，n=7）→ 若先对 banned 排序再双指针推进，容易把 `11` 当成范围内的数去跳过，导致漏取 → 正确做法是直接 `set(banned)`，循环里只查 `x in ban`，范围外的自然查不到。
- `maxSum` 很大而 n 很小（示例 3：maxSum=50, n=7）→ 若写成「取到和接近 maxSum 为止」的循环条件，可能越界访问 `x > n` → 正确做法是循环上界固定为 `n`，靠 `x > maxSum` 提前 break，两个终止条件都要有。

## 如果面试官追问
问：若要求返回具体选了哪些数？答：把 `cnt += 1` 处改成 `res.append(x)`，贪心顺序不变，返回 `res` 即可。
