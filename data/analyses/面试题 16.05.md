## 一句话思路
尾随零来自因子 10 = 2×5，阶乘中 2 的个数远多于 5，所以只数 5 的个数，用 n//5 + n//25 + … 累加。

## 怎么做
1. 初始化 `count = 0`，`power = 5`。
2. 循环条件 `power <= n`，每轮 `count += n // power`。
3. 每轮结束 `power *= 5`，直到 `power > n` 退出。
4. 返回 `count`。

以 n = 5 为例：`power = 5`，`5 <= 5` 成立，`count += 5 // 5 = 1`，`power` 变成 25，`25 <= 5` 不成立，退出返回 1。这里 5! = 120 只有一个 5（来自 5 本身），没有 25 的倍数，所以只加一次。

再看 n = 25：`power = 5` 时加 `25 // 5 = 5`（5,10,15,20,25 各贡献一个 5），`power = 25` 时加 `25 // 25 = 1`（25 额外再贡献一个 5），合计 6。25! 的尾零正是 6 个，说明 25 这个数被数了两次，这正是 `power *= 5` 的意义。

```python
count = 0
power = 5
while power <= n:
    count += n // power
    power *= 5
return count
```

关键点：不要写成 `while n:` 里 `n //= 5` 再累加——那样也对，但本题用 `power` 变量更直观地体现「5、25、125…」的层级，且避免改动入参 `n`，便于调试时打印原始 n。

## 复杂度
时间：O(log₅ n)，循环次数由 `power` 从 5 倍增到超过 n 决定。
空间：O(1)，只开了 `count` 和 `power` 两个整数。

## 易错点
- 输入 n = 25 → 只算 `25 // 5 = 5` 就返回 5，漏掉 25 这个数贡献的第二个 5 → 正确做法是继续用 `power = 25` 再加 `25 // 25 = 1`，答案 6。
- 输入 n = 0 或 n = 4 → 若把循环写成 `while power < n` 或先加后判断，可能返回 0 之外的错误值或死循环 → 正确做法是条件严格用 `power <= n`，n < 5 时循环体一次不执行，直接返回 0。

## 如果面试官追问
问：如果要求返回尾零的个数而不是只数 5，怎么改？
答：仍只数 5，因为 2 的个数恒 ≥ 5 的个数，数 2 会得到偏大的错误结果。
