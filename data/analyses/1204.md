## 一句话思路
按 `turn` 升序累加 `weight` 做窗口求和，取累计和 ≤1000 的最后一行。

## 怎么做
1. 用窗口函数 `SUM(weight) OVER (ORDER BY turn)` 得到每人上车时的累计重量。
2. 过滤 `running_total <= 1000`，这些人都是能上车的。
3. 在剩下的行里按 `turn` 降序取第一行，就是最后一个上车的。

以官方示例为例：按 turn 排序后累计重量依次是 250、600、1000、1200、1375、1875。过滤 ≤1000 剩前三行，其中 turn 最大的是 turn=3 的 John Cena，累计正好 1000。

```python
# 关键逻辑（SQL 思路，Python 里等价于排序后累加）
q = sorted(queue, key=lambda r: r["turn"])
total = 0
last = None
for r in q:
    total += r["weight"]
    if total <= 1000:
        last = r["person_name"]
    else:
        break
# last == "John Cena"
```

注意 `break` 的位置：一旦 `total > 1000` 就停，因为后面的人累计只会更大，不可能再上车。

## 复杂度
时间 O(n log n)：排序贡献 log n，累加扫描 O(n)。
空间 O(n)：排序后新列表（SQL 里是窗口函数的中间结果）。

## 易错点
- 用 `total < 1000` 而非 `<= 1000`：示例里 John Cena 累计正好 1000，会被漏掉，输出变成 Alex。题目是「不超过」，必须取等号。
- 先按 `weight` 或 `person_id` 排序再累加：`turn` 才是上车顺序，示例里 person_id=5 的 Alice 是第一个上车，按 id 排会得到完全错误的累计序列。

## 如果面试官追问
若要求输出所有能上车的人而非最后一个？答：去掉取最后一行的步骤，直接返回过滤后的整张表按 turn 排序即可。
