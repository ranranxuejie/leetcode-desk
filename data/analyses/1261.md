## 一句话思路
先 DFS 把每个节点按 `2*x+1` / `2*x+2` 还原并塞进哈希集合，`find` 就退化成一次 O(1) 查表。

## 怎么做
1. 构造函数里从 `root` 出发做 DFS，参数带上父节点算好的值。
2. 进入节点先 `self.s.add(val)`，再递归左 `2*val+1`、右 `2*val+2`。
3. `find(target)` 直接返回 `target in self.s`。

以示例 1 的 `[-1,null,-1]` 为例：根先记 0；左孩子是 `None` 跳过；右孩子算 `2*0+2 = 2` 记入集合。于是 `find(1)` 查不到返回 `False`，`find(2)` 命中返回 `True`。

```python
def dfs(node, val):
    if not node:
        return
    self.s.add(val)
    dfs(node.left, 2 * val + 1)
    dfs(node.right, 2 * val + 2)

dfs(root, 0)

def find(self, target):
    return target in self.s
```

注意还原时**不要**去改 `node.val`，值只走递归参数，污染字段留着也无所谓。

## 复杂度
时间：构造 O(n)，n 为节点数；每次 `find` O(1)，共 q 次即 O(q)。
空间：集合存 n 个值 O(n)，DFS 栈深不超过树高 20。

## 易错点
- 输入 `[-1,null,-1]` 时若写成「先判断 `node.val == -1` 才赋值」，会把根漏掉或把 `None` 当节点算 → 正确做法是值完全由递归参数 `val` 决定，根固定传 0，不读 `node.val`。
- 输入 `[-1,-1,-1,-1,-1]`（示例 2）时若只还原到第二层就停，会漏掉 `2*1+1=3` 这类深层值，`find(3)` 错成 `False` → 必须递归到叶子，`None` 才返回。

## 如果面试官追问
问：不建集合、每次 `find` 现场搜行不行？
答：可以，按 `target` 反推父节点 `(target-1)//2` 一路回溯到 0，沿树走 O(高度)=O(20)，但节点缺失时要能判断路径存在，实现更绕。
