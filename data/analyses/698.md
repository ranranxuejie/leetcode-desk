## 一句话思路
用位掩码 `mask` 记录已选元素，记忆化搜索「当前子集已凑 `cur`、还剩哪些元素」，按子集顺序填满 k 个桶。

## 怎么做
1. 先判 `total % k != 0` 或 `max(nums) > target` 直接返回 `False`，其中 `target = total // k`。
2. 状态定义为 `(mask, cur)`，`cur` 是当前正在凑的子集已有和；`cur == target` 时归零进入下一个桶。
3. 每次从未选元素里挑一个 `nums[i]`，要求 `cur + nums[i] <= target`，递归后记忆化。
4. 用 `lru_cache` 缓存 `mask`（`cur` 可由 `mask` 推出，但直接带上更省事）。

以示例 1 为例：`total = 20`，`target = 5`。从 `mask = 0, cur = 0` 出发，先选 `5` 使 `cur = 5`，归零；再选 `4` 后 `cur = 4`，接着选 `1` 使 `cur = 5`，归零；剩下 `[3,2,3,2]` 恰好分成两组 `(2,3)`，返回 `True`。

```python
from functools import lru_cache

@lru_cache(None)
def dfs(mask, cur):
    if mask == (1 << n) - 1:
        return True
    for i in range(n):
        if mask >> i & 1 or cur + nums[i] > target:
            continue
        nxt = (cur + nums[i]) % target
        if dfs(mask | 1 << i, nxt):
            return True
    return False

return dfs(0, 0)
```

关键剪枝：排序后从大到小尝试，大元素先放能更早触发 `cur + nums[i] > target` 的失败分支。

## 复杂度
时间：`O(2^n * n)`，`mask` 共 `2^n` 种，每种枚举 `n` 个元素。
空间：`O(2^n)` 个缓存状态，每个存一个布尔值。

## 易错点
- `nums = [1,2,3,4], k = 3`：`total = 10` 不能被 3 整除，若不先判 `total % k` 会进入搜索白跑，正确做法是入口直接返回 `False`。
- `nums = [2,2,2,2,3,3], k = 4`：`target = 3`，若允许 `cur + nums[i] > target` 继续递归，会把 `2` 塞进已满的桶导致误判，正确做法是循环里 `continue` 掉超限分支。

## 如果面试官追问
问：要求输出具体分组方案怎么办？
答：把 `dfs` 改成返回选中的下标列表，或在递归时记录每个元素落入的桶编号，回溯时收集即可。
