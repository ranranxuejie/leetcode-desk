## 一句话思路
用数位 DP 按位枚举，状态带上「已匹配 evil 的前缀长度」，配合 KMP 的 fail 转移保证不出现 evil。

## 怎么做
1. 对 evil 建 KMP 的 `fail` 数组，`go[j][c]` 表示当前匹配长度 j 接字符 c 后的新匹配长度，若等于 `len(evil)` 则该分支非法。
2. 把「≤ s2」减去「≤ s1 的前一位」转成 `count(s2) - count(s1) + isGood(s1)`，即前缀计数差。
3. `count(s)` 用记忆化 DFS：`dfs(i, j, tight)`，i 是位置、j 是已匹配 evil 长度、tight 表示是否贴着 s 的前缀。
4. 转移时枚举 26 个字母，`tight` 时上界取 `ord(s[i])-97`，否则 25；新状态 `nj = go[j][c]`，`nj == len(evil)` 跳过。

以示例 1 的 `count("da")` 为例：i=0 时 tight=True，c 取 0..3；c=1 即 'b' 时 `go[0][1]=1==len(evil)` 被剪掉，所以首字母 'b' 整支为 0，最终 `count("da")=26+26-1=51` 中的 51 来自 a、c、d 三支。

```python
def count(s):
    @lru_cache(None)
    def dfs(i, j, tight):
        if i == n: return 1
        up = ord(s[i]) - 97 if tight else 25
        res = 0
        for c in range(up + 1):
            nj = go[j][c]
            if nj == m: continue
            res += dfs(i + 1, nj, tight and c == up)
        return res % MOD
    return dfs(0, 0, True)
```

## 复杂度
时间：O(n · m · 26)，n 为位数、m 为 evil 长度，26 是字母表。
空间：O(n · m) 的记忆化表，外加 O(m · 26) 的 go 表。

## 易错点
- `s1` 本身可能含 evil，如 `s1="leetx"`、`evil="leet"`：直接 `count(s2)-count(s1)` 会把 s1 多算进去，正确做法是减 `count(s1)` 后再单独判 `s1` 是否合法并加回。
- `evil` 长度 1 时 `go[0][c]` 直接等于 m，所有含该字母的分支全灭；若忘了在转移里 `continue`，会返回 26^n 量级的错误值，正确做法是建表时就把 `nj == m` 的分支标死。

## 如果面试官追问
若 n 放大到 10^5 且 evil 很短，怎么办？答：把 DP 转移写成 26×m 的矩阵，用矩阵快速幂，复杂度降到 O(m^3 log n)。
