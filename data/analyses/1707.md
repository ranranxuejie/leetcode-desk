## 一句话思路
把 nums 排序后按 m 升序离线插入二进制字典树，每个查询在「已插入的 ≤m 元素」中贪心取异或最大。

## 怎么做
1. 把 queries 变成 `(m, x, 原下标)` 并按 m 升序排序，nums 升序排序，指针 `p` 指向下一个待插入元素。
2. 对每个查询，先 `while p < len(nums) and nums[p] <= m` 把 nums[p] 插入字典树（31 位，从高位到低位），再在树上贪心。
3. 贪心规则：对 x 的第 b 位，优先走 `1 - bit` 的分支（异或得 1），走不通才走同侧；把选中的位累加进答案。
4. 若插入后树为空（`p == 0`），该查询答案记 -1。

以示例 1 的 `queries = [[3,1],[1,3],[5,6]]` 为例：排序后先处理 m=1，插入 nums[0]=0、nums[1]=1，此时 `p=2`；对 x=3（二进制 11）在树上先取 0 分支得高位 1，最终得 3。处理 m=6 时 `p=5`，树含 0..4，x=5 走 2 的分支得 7。

```python
# 插入
node = root
for b in range(30, -1, -1):
    bit = (v >> b) & 1
    if node[bit] is None:
        node[bit] = [None, None]
    node = node[bit]

# 查询
node, cur = root, 0
for b in range(30, -1, -1):
    bit = (x >> b) & 1
    want = 1 - bit
    if node[want] is not None:
        cur |= 1 << b
        node = node[want]
    else:
        node = node[bit]
```

## 复杂度
时间：排序 O(n log n + q log q)，每次插入/查询 O(31)，共 O((n+q)·31)。
空间：字典树最多 31n 个节点，加排序与答案数组 O(n + q)。

## 易错点
- 忘记按 m 升序离线：若按 queries 原顺序直接建全量树，示例 2 的 `[8,1]` 会拿 5、6 参与异或得 13 而非 -1；必须先排序再插入。
- 位宽取错：`nums[j], x ≤ 10^9 < 2**30`，从 30 位起即可；若从 31 位起多一位不影响正确性但多一层，若只到 29 位则示例 1 的 x=5 会丢掉最高位得 3 而非 7。

## 如果面试官追问
若要求在线回答（不能离线排序）怎么办？答：改用可持久化字典树，按 nums 排序后第 i 个版本只含前 i 个元素，查询时在 `upper_bound(m)` 对应版本上贪心。
