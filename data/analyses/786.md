## 一句话思路
用二分查找猜一个分数值 x，统计 ≤x 的分数个数与 x 比较，收敛到第 k 小。

## 怎么做
1. 二分区间取 `lo=0.0, hi=1.0`，每轮 `mid=(lo+hi)/2`。
2. 对每个 `j` 从 1 到 n-1，用双指针找最大的 `i` 使 `arr[i]/arr[j] <= mid`，累加个数 `cnt += i+1`。
3. 同时记录这轮里最接近 mid 的分数 `best = arr[i]/arr[j]`（取最大者）。
4. `cnt < k` 则 `lo=mid`，否则 `hi=mid`；循环约 60 次后 `best` 即答案。

以 `arr=[1,2,3,5], k=3` 为例：`mid=0.5` 时，`j=3`（值 5）指针停在 `i=1`（2/5=0.4≤0.5，3/5=0.6>0.5），`cnt` 累计到 4 ≥ 3，`hi` 收缩；最终 `best` 收敛到 `2/5`。

```python
lo, hi = 0.0, 1.0
for _ in range(60):
    mid = (lo + hi) / 2
    cnt, i, best = 0, -1, (0, 0)
    for j in range(1, n):
        while i + 1 < j and arr[i + 1] / arr[j] <= mid:
            i += 1
        cnt += i + 1
        if i >= 0 and arr[i] / arr[j] > best[0] / best[1] if best[1] else True:
            best = (arr[i], arr[j])
    if cnt < k:
        lo = mid
    else:
        hi = mid
return list(best)
```

## 复杂度
时间：二分 60 轮 × 双指针 O(n)，共 O(n log(1/eps))，n 是 arr 长度。
空间：只存 `lo/hi/cnt/best` 几个变量，O(1) 额外空间。

## 易错点
- `arr=[1,7], k=1` → 若内层 `while` 写成 `i+1 <= j` 会越界取到 `arr[j]/arr[j]=1`，把 1 算进 cnt；正确是 `i+1 < j`，保证分子下标严格小于分母。
- `arr=[1,2,3,5], k=3` → 若只在 `cnt==k` 时更新 best，浮点几乎不会精确相等，best 永远是初始值；正确是每轮无条件用当前最大 ≤mid 的分数刷新 best，靠二分收敛逼近。

## 如果面试官追问
问：能否不用浮点？答：改成比较 `arr[i]*den <= num*arr[j]` 的整数交叉相乘，二分在分数空间上做，避免精度问题。
