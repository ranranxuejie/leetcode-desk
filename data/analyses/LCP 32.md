## 一句话思路
按 `end` 升序扫描时间轴，用大根堆维护「已开机时刻」的分布，每个任务只补足缺口且尽量往 `end` 靠。

## 怎么做
1. 把 `tasks` 按 `end` 升序排序，保证处理到某任务时，之前所有任务都已满足。
2. 用大根堆 `heap` 存已开机时刻（取负），`total` 记开机总时长；对每个 `[s,e,p]`，弹出 `> e` 的时刻并累加 `cnt`，得到落在 `[s,e]` 内的已开机数。
3. 若 `cnt < p`，从 `e` 往下逐个补 `p - cnt` 个时刻，压入堆并 `total += 1`。
4. 返回 `total`。

以示例 1 为例：排序后仍是 `[[1,3,2],[2,5,3],[5,6,2]]`。处理 `[2,5,3]` 时堆里已有 `3,2`（来自任务 0），`cnt = 2`，缺口 1，从 `e=5` 往下补时刻 `5`，`total` 变 3；处理 `[5,6,2]` 时堆内 `[1,3]` 区间已有 `5`，`cnt = 1`，补 `6`，`total = 4`。

```python
import heapq
tasks.sort(key=lambda t: t[1])
heap, total = [], 0
for s, e, p in tasks:
    cnt = 0
    while heap and -heap[0] > e:
        heapq.heappop(heap)
    for x in heap:
        if -x >= s:
            cnt += 1
    need = p - cnt
    t = e
    while need > 0:
        heapq.heappush(heap, -t)
        total += 1
        need -= 1
        t -= 1
return total
```

## 复杂度
时间：排序 `O(n log n)`，每个任务最多补 `p` 个时刻，总补数不超过答案规模，堆操作 `O(log n)`。
空间：堆最多存 `total` 个时刻，`O(total)`，`total` 可到 `10^9` 量级需注意。

## 易错点
- 输入 `[[1,3,2],[2,5,3]]`：若按 `start` 排序，处理 `[1,3,2]` 时先补 `3,2`，再处理 `[2,5,3]` 时 `cnt=1` 补 `5,4`，`total=4`；正确按 `end` 排序后 `[2,5,3]` 先补 `5`，`[1,3,2]` 补 `3,2`，`total=3`。必须按 `end` 升序。
- 输入 `[[1,5,5],[2,3,2]]`：若补时刻时从 `s` 往上填，任务 0 占 `1..5`，任务 1 的 `[2,3]` 已被覆盖但 `cnt` 统计需正确弹出 `> e` 的时刻；若忘记弹出 `> e` 的堆元素，`cnt` 会虚高导致少补，答案偏小。正确做法是每次先 `while heap and -heap[0] > e: pop`。

## 如果面试官追问
若 `period` 可达 `10^9` 且要求输出具体开机时刻集合，怎么做？答：堆里改存区间而非单点，补缺口时整段压入 `[e-need+1, e]`，输出时展开区间。
