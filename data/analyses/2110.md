## 一句话思路
以每个位置结尾的平滑下降段数 = 前一位的段数 + 1（若 `prices[i-1] - prices[i] == 1`），累加即答案。

## 怎么做
1. 令 `cur` 表示「以当前天结尾的平滑下降阶段数」，初始 `cur = 1`（单天本身算一个），`ans = 1`。
2. 从 `i = 1` 开始遍历：若 `prices[i-1] - prices[i] == 1`，则 `cur += 1`；否则 `cur = 1`。
3. 每步把 `cur` 累加进 `ans`，遍历结束返回 `ans`。

以 `prices = [3,2,1,4]` 为例：`i=1` 时 `3-2==1`，`cur` 从 1 变 2，`ans=1+2=3`；`i=2` 时 `2-1==1`，`cur=3`，`ans=6`；`i=3` 时 `1-4=-3≠1`，`cur` 重置为 1，`ans=7`。关键中间值就是 `cur` 的 1→2→3→1。

```python
cur = ans = 1
for i in range(1, len(prices)):
    if prices[i - 1] - prices[i] == 1:
        cur += 1
    else:
        cur = 1
    ans += cur
return ans
```

注意 `cur` 重置为 1 而不是 0：`prices[i]` 自己单独构成一个阶段，这一步漏了就会在示例 2 的 `[8,6,7,7]` 上少算。

## 复杂度
时间 O(n)：一次遍历，n 为 `prices` 长度。
空间 O(1)：只开 `cur`、`ans` 两个变量。

## 易错点
- 输入 `[8,6,7,7]` → 若在 `8-6≠1` 处把 `cur` 置 0，则 `[6]` 这个单天阶段被漏掉，输出 3 而非 4 → 断链时 `cur` 必须重置为 1，因为任何单天都是合法阶段。
- 输入 `[3,2,1,4]` → 若只统计最长下降段长度 3 或只数相邻对数 2，会得到 3 或 2 而非 7 → 必须把每个位置结尾的 `cur` 全部累加，`[3,2,1]` 内部就贡献 3+2+1=6 个阶段。

## 如果面试官追问
若要求返回所有阶段而非计数？答：对每个 `cur` 的起点区间展开，总输出规模本身是 O(n²)，只能按需流式生成，无法优于平方。
