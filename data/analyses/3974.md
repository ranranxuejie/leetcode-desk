## 一句话思路
排序后取最大的 k 个，按从大到小依次配递减的 mul，乘比加更优就乘。

## 怎么做
1. 对 `nums` 排序，取末尾 `k` 个（最大的 k 个）作为被选元素。
2. 把这 k 个按**从大到小**处理，让最大的数吃到最大的 `mul`。
3. 每个元素比较 `x * mul` 与 `x`，取大者累加，然后 `mul -= 1`。
4. 用 `long` 累加（Python 天然大整数，无需处理）。

以示例 1 为例：`nums = [6,1,2,9], k = 3, mul = 2`，排序后取 `[2,6,9]`，倒序处理：
- `9`：`9*2=18 > 9`，取 18，`mul` 变 1
- `6`：`6*1=6`，取 6，`mul` 变 0
- `2`：`2*0=0 < 2`，取 2
总和 `18+6+2=26`。

关键中间值：处理 `2` 时 `mul` 已降到 0，乘法贡献 0，必须回退到加法。

```python
nums.sort()
total = 0
for x in reversed(nums[-k:]):
    total += max(x, x * mul)
    mul -= 1
return total
```

注意 `mul` 可能变负：此时 `x * mul < 0 < x`，`max` 自动选加法，无需特判。

## 复杂度
时间：排序 `O(n log n)`，遍历 k 个元素 `O(k)`，总计 `O(n log n)`。
空间：排序原地 `O(log n)` 栈空间，无额外数组。

## 易错点
- 选错元素：若取最小的 k 个（如示例 1 取 `[1,2,6]`），最大只能得 `6*2+2*1+1=15`，远小于 26。必须取最大的 k 个，因为乘数 `mul` 递减，大数配大乘数收益最高。
- `mul` 降到 0 或负数后仍盲目乘：如示例 1 处理 `2` 时 `mul=0`，若直接算 `2*0=0` 会少加 2。正确做法是每步用 `max(x, x*mul)`，负数时自动退回加法。

## 如果面试官追问
问：如果要求输出具体选了哪些元素及每个元素的操作？
答：排序后记录下标，遍历时判断 `x*mul > x` 则标记乘法，否则标记加法，一并返回。
