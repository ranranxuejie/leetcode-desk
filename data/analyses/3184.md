## 一句话思路
用哈希表记录已扫过的 `hours[i] % 24` 频次，对每个新元素查互补余数 `(24 - r) % 24` 累加即可。

## 怎么做
1. 遍历 `hours`，对每个值先取 `r = h % 24`，把「余数」当作唯一需要关心的信息。
2. 在哈希表 `cnt` 里查 `(24 - r) % 24` 的已有次数，累加到答案——这些下标都小于当前 `i`，天然满足 `i < j`。
3. 再把当前 `r` 计入 `cnt`，继续下一个。

以 `hours = [12,12,30,24,24]` 为例：处理到下标 1 时 `r = 12`，查 `(24-12)%24 = 12`，`cnt[12]` 已是 1，答案变 1；处理下标 3 时 `r = 0`，查 `(24-0)%24 = 0`，`cnt[0]` 为 0，答案不变；处理下标 4 时 `r = 0`，`cnt[0]` 已是 1，答案变 2。

```python
cnt = {}
ans = 0
for h in hours:
    r = h % 24
    ans += cnt.get((24 - r) % 24, 0)
    cnt[r] = cnt.get(r, 0) + 1
return ans
```

关键在 `(24 - r) % 24` 这个写法：`r = 0` 时互补余数仍是 0（24 的倍数配 24 的倍数），若写成 `24 - r` 会得到 24，永远查不到，示例 1 的 `(3,4)` 就漏了。

## 复杂度
时间 O(n)：n 为 `hours` 长度，每个元素做一次取模和两次哈希查询。
空间 O(1)：哈希表最多 24 个键，与 n 无关。

## 易错点
- `hours = [24,24]` → 若互补余数写成 `24 - r`，`r = 0` 时查到键 24，答案错成 0 → 必须写 `(24 - r) % 24`，让 0 的搭档还是 0。
- `hours = [12,12,12]` → 若先计数再统一配对、或对每对重复统计，会错成 6 或 2 → 必须边扫边查，每个 `j` 只和它之前的 `i` 配对，正确答案是 3。

## 如果面试官追问
问：`hours` 长度放大到 10^5 甚至 10^9 怎么办？
答：哈希法本来就是 O(n) 单遍，规模变大只影响遍历耗时，24 个桶的空间不变，无需改算法。
