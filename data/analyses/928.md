## 一句话思路
对每个非感染节点统计它能被几个 initial 节点感染：恰好 1 个时，删掉那个源头能救它，按源头累加可救节点数取最大。

## 怎么做
1. 把 initial 转成集合 `bad`，对每个非感染节点 `v` 做一次 BFS/DFS，只走非感染节点，记录能到达它的感染源集合 `src`。
2. 若 `len(src) == 1`，说明删掉 `src` 里那个唯一源头就能让 `v` 不被感染，给该源头计数 `save[src] += 1`。
3. 遍历 initial，取 `save` 最大者；并列取索引最小。

以示例 2 `graph=[[1,1,0],[1,1,1],[0,1,1]]`, `initial=[0,1]` 为例：节点 2 只连节点 1，从 0 出发走不到 2（0 的邻居只有 1，1 是感染源不能走），从 1 出发能到 2，故 `src(2)={1}`，`save[1]=1`；`save[0]=0`，返回 1。

```python
bad = set(initial)
save = {x: 0 for x in initial}
for v in range(n):
    if v in bad: continue
    src, seen, stack = set(), {v}, [v]
    while stack:
        u = stack.pop()
        for w in range(n):
            if graph[u][w] and w not in seen:
                if w in bad: src.add(w)
                else: seen.add(w); stack.append(w)
    if len(src) == 1:
        save[next(iter(src))] += 1
return min(initial, key=lambda x: (-save[x], x))
```

## 复杂度
时间 O(n² · |initial|)：每个非感染节点 BFS 扫 n 个邻居，最多 n 次。
空间 O(n)：`seen`、`stack`、`src` 各至多 n 个元素。

## 易错点
- 若把感染源也放进 BFS 队列继续扩散，示例 2 中从 0 会经 1 走到 2，`src(2)={0,1}`，`save` 全为 0，错误返回 0；正确做法是遇到 `w in bad` 只记入 `src` 不入栈。
- 若只统计「删掉后能救多少」却漏了初始感染源本身，示例 1 中 `save[0]=save[1]=0` 并列，靠 `min` 返回 0 恰好对；但若某源头 `save` 为 0 而另一源头为负（不存在）会误判，正确做法是 `save` 初值全 0、并列取最小索引。

## 如果面试官追问
若 initial 很大（接近 n），还能用这方法吗？答：不能，O(n²·|initial|) 会退化到 O(n³)，应改用并查集按连通块统计每块的感染源数，只对源数为 1 的块累加。
