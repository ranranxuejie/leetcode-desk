## 一句话思路
定长窗口维护长度 k 的和，用 `sum >= k * threshold` 判平均，避免浮点除法。

## 怎么做
1. 先算 `arr[:k]` 的和 `s`，作为第一个窗口。
2. 用 `s >= k * threshold` 判断，成立则计数加一。
3. 窗口右移：`s += arr[i] - arr[i-k]`，每移一次判一次。
4. 遍历 `i` 从 `k` 到 `n-1`，循环结束返回计数。

以示例 1 为例，`arr = [2,2,2,2,5,5,5,8]`，`k = 3`，`threshold = 4`，门槛是 `k * threshold = 12`。初始窗口 `[2,2,2]` 的 `s = 6`，不达标；移到 `i = 3` 时 `s = 6 + 2 - 2 = 6`；到 `i = 4` 时 `s = 6 + 5 - 2 = 9`；到 `i = 5` 时 `s = 9 + 5 - 2 = 12`，首次达标，对应子数组 `[2,5,5]`，平均值正好 4。

```python
n = len(arr)
s = sum(arr[:k])
cnt = 1 if s >= k * threshold else 0
for i in range(k, n):
    s += arr[i] - arr[i - k]
    if s >= k * threshold:
        cnt += 1
return cnt
```

关键点：比较用乘法 `k * threshold` 而不是 `s / k >= threshold`，示例 1 中 `s = 12`、`k * threshold = 12` 时等号必须算达标，浮点除法在边界上容易出偏差。

## 复杂度
时间 O(n)：每个元素最多进出窗口一次，`sum(arr[:k])` 也是 O(k) ≤ O(n)。
空间 O(1)：只开了 `s`、`cnt`、`i` 三个标量，没有额外数组。

## 易错点
- `arr = [2,2,2,2,5,5,5,8]`、`k = 3`、`threshold = 4`：若写成 `s / k > threshold` 用严格大于，`s = 12` 的 `[2,5,5]` 会被漏掉，答案错成 2；题面是「大于等于」，必须用 `>=`。
- `k = 1` 或 `k = len(arr)`：若循环写成 `for i in range(k, n)` 却把初始窗口的判断漏在循环外，`k = len(arr)` 时循环体一次不执行，答案恒为 0；正确做法是初始窗口先判一次再进循环，如上面代码的 `cnt` 初始化。

## 如果面试官追问
问：要求输出所有达标的子数组起始下标怎么办？
答：把 `cnt += 1` 换成 `res.append(i - k + 1)`，初始窗口对应下标 0，空间从 O(1) 变 O(答案个数)。
