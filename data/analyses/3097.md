## 一句话思路
用滑动窗口维护窗口内 OR 值，因为 OR 只增不减，右指针扩张到满足条件后左指针收缩即可求最短。

## 怎么做
1. 用 `left`、`right` 双指针，`cur` 记录 `nums[left..right]` 的 OR 值，`ans` 初始为 `n+1`。
2. 右指针逐个纳入 `nums[right]`，`cur |= nums[right]`，窗口 OR 单调不减。
3. 当 `cur >= k` 时，用 `right-left+1` 更新 `ans`，然后尝试右移 `left` 缩小窗口。
4. 收缩时不能简单 `cur ^= nums[left]`，因为 OR 不可逆，需重新计算窗口 OR（或用按位计数）。

以 `nums=[2,1,8], k=10` 为例：`right=2` 时 `cur = 2|1|8 = 11 >= 10`，`ans=3`；尝试移走 `2` 后 `cur=1|8=9 < 10`，停止收缩，最终返回 3。

```python
n = len(nums)
ans = n + 1
left = 0
for right in range(n):
    # 重新计算窗口 OR（简化写法，实际可用按位计数优化）
    cur = 0
    for i in range(left, right + 1):
        cur |= nums[i]
    while cur >= k:
        ans = min(ans, right - left + 1)
        left += 1
        cur = 0
        for i in range(left, right + 1):
            cur |= nums[i]
return ans if ans <= n else -1
```

上面是 O(n²) 的直观写法；标准 O(n log C) 做法是用 `cnt[32]` 记录窗口内每一位出现次数，移出元素时对应位减一，`cur` 由 `cnt` 中非零位重组。

## 复杂度
时间：O(n log C)，n 为数组长度，log C 为 32 位按位计数开销。
空间：O(log C)，仅开 32 长度的计数数组。

## 易错点
- 输入 `nums=[1,2], k=0` → 若先判断 `cur >= k` 再纳入元素，会漏掉单元素窗口 → 正确做法是纳入后立即判断，`k=0` 时任意单元素都满足，返回 1。
- 输入 `nums=[5,1,2], k=8` → 若收缩时用 `cur ^= nums[left]` 移除，会把其他元素贡献的同一位也清掉，得到错误 OR → 正确做法是用按位计数数组逐位减，或每次重算窗口 OR。

## 如果面试官追问
若要求输出最短子数组的具体下标而非长度？答：在 `ans` 更新时同步记录 `(left, right)`，收缩循环里每次满足条件都覆盖记录，最后返回该区间。
