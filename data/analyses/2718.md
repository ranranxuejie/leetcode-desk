## 一句话思路
倒序扫描 queries，用两个集合记录已被后续覆盖的行和列，只对首次出现的行/列计入贡献。

## 怎么做
1. 倒序遍历 queries，维护 `seen_rows`、`seen_cols` 两个集合，表示后面已有更新的行/列。
2. 遇到 `type==0` 且 `index` 不在 `seen_rows`：该行最终值就是 `val`，但列方向已被覆盖的格子不算，贡献 `val * (n - len(seen_cols))`。
3. 遇到 `type==1` 且 `index` 不在 `seen_cols`：贡献 `val * (n - len(seen_rows))`。
4. 把该 index 加入对应集合，继续往前扫。

以示例 1 `n=3, queries=[[0,0,1],[1,2,2],[0,2,3],[1,0,4]]` 为例，倒序：
- `[1,0,4]`：列 0 首次，`seen_rows` 空，贡献 `4*3=12`，`seen_cols={0}`。
- `[0,2,3]`：行 2 首次，`len(seen_cols)=1`，贡献 `3*(3-1)=6`，`seen_rows={2}`。
- `[1,2,2]`：列 2 首次，`len(seen_rows)=1`，贡献 `2*(3-1)=4`，`seen_cols={0,2}`。
- `[0,0,1]`：行 0 首次，`len(seen_cols)=2`，贡献 `1*(3-2)=1`。
合计 `12+6+4+1=23`，与输出一致。

```python
seen_rows, seen_cols = set(), set()
total = 0
for t, idx, val in reversed(queries):
    if t == 0 and idx not in seen_rows:
        total += val * (n - len(seen_cols))
        seen_rows.add(idx)
    elif t == 1 and idx not in seen_cols:
        total += val * (n - len(seen_rows))
        seen_cols.add(idx)
return total
```

## 复杂度
时间：O(q)，q 为 queries 长度，每个查询均摊 O(1)。
空间：O(n)，两个集合最多存 n 个行号和 n 个列号。

## 易错点
1. 正序扫描 → 后写的行会覆盖先写的列交叉格，正序无法知道哪些格子已被覆盖，会重复计数；必须倒序，让「最后生效」的赋值先被处理。
2. 用 `len(seen_cols)` 而非 `n` 乘 → 若写成 `val * n`，示例 1 中行 2 会算成 `3*3=9` 而非 6，因为列 0 已被更晚的查询覆盖，交叉格应归列 0 的 4；正确是减去已覆盖列数。

## 如果面试官追问
若要求返回最终矩阵而非和？答：倒序记录每行/列最终值，再正序填充，未被覆盖的格子为 0，时间 O(n² + q)。
