## 一句话思路
用两个哈希表 `count` 和 `tail` 贪心：能接就接，接不上就新开，新开不了就失败。

## 怎么做
1. 先统计每个值出现次数 `count`，再从左到右扫描 `nums`。
2. 对当前 `x`，若 `count[x] == 0` 跳过；若 `tail[x-1] > 0`，优先接到已有序列后，`tail[x-1] -= 1`、`tail[x] += 1`。
3. 否则尝试以 `x` 开头新序列，需 `count[x+1] > 0 and count[x+2] > 0`，成立则三者各减 1、`tail[x+2] += 1`。
4. 两者都不行返回 `False`，扫描完返回 `True`。

以 `nums = [1,2,3,3,4,5]` 为例：处理到第一个 `3` 时 `tail[2] = 1`，接上后 `tail[3] = 1`；处理第二个 `3` 时 `tail[2] = 0`，新开 `3,4,5`，`tail[5] = 1`，最终成功。

```python
from collections import Counter
count = Counter(nums)
tail = Counter()
for x in nums:
    if count[x] == 0:
        continue
    if tail[x - 1] > 0:
        tail[x - 1] -= 1
        tail[x] += 1
        count[x] -= 1
    elif count[x + 1] > 0 and count[x + 2] > 0:
        count[x] -= 1
        count[x + 1] -= 1
        count[x + 2] -= 1
        tail[x + 2] += 1
    else:
        return False
return True
```

## 复杂度
时间 O(n)：每个元素只被常数次哈希操作处理。
空间 O(n)：`count` 和 `tail` 各存至多 n 个不同值。

## 易错点
- 输入 `[1,2,3,4,4,5]` → 若先给 `4` 新开序列（`4,5` 不够长）会误判 → 正确做法是优先接 `tail[3]`，让 `1,2,3,4` 延长，剩下 `4,5` 才暴露失败。
- 输入 `[1,2,3,3,4,5]` → 若只检查 `count[x+1]` 不检查 `count[x+2]`，会在 `3` 处新开 `3,4` 导致后续 `5` 无处安放 → 必须同时确认 `x+1`、`x+2` 都存在。

## 如果面试官追问
要求输出具体分割方案怎么办？答：把 `tail` 改成记录每条序列末尾值到序列列表的映射，接续时把 `x` 追加到对应列表，最后返回所有长度 ≥3 的列表即可。
