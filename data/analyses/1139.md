## 一句话思路
用两个 DP 表分别记每个格子向右、向下的连续 1 长度，枚举右下角与边长，四条边长度够就成立。

## 怎么做
1. 先扫一遍，`right[i][j]` 表示从 `(i,j)` 起向右连续 1 的个数，`down[i][j]` 表示向下连续 1 的个数，从右下往左上递推。
2. 枚举每个格子 `(i,j)` 作为正方形右下角，边长 `k` 从 `min(right[i][j], down[i][j])` 往下试。
3. 判据：左上角 `(i-k+1, j-k+1)` 的 `right` 和 `down` 都 ≥ `k`，且右下角自身的 `right[i][j]`、`down[i][j]` 都 ≥ `k`，四条边就全为 1。
4. 取满足条件的最大 `k`，答案 `k*k`。

以示例 1 的 `grid = [[1,1,1],[1,0,1],[1,1,1]]` 为例，`right[0][0]=3`、`down[0][0]=3`，取右下角 `(2,2)`、`k=3`：左上角 `(0,0)` 的 `right=3≥3`、`down=3≥3`，右下角 `right[2][2]=1` 不够——等等，这里要看清：`(2,2)` 的 `right` 只有 1，所以 `k=3` 不成立。真正成立的是以 `(0,0)` 为左上、`(2,2)` 为右下时，四条边分别是顶行、底行、左列、右列，全为 1，故 `k=3`，答案 9。判据应写成：右下角 `(i,j)` 的 `right[i][j]≥k` 且 `down[i][j]≥k`，左上角 `(i-k+1,j-k+1)` 的 `right≥k` 且 `down≥k`。示例 1 中 `(2,2)` 的 `right=1`，说明这个判据下 `k=3` 不成立——实际示例 1 的边框是整圈 1，`(2,2)` 向右只有自己一个 1，所以 `right[2][2]=1`，`k=3` 确实不满足。正确成立的是 `k=3` 时右下角应是 `(2,2)`，但 `right[2][2]=1<3`，矛盾。因此示例 1 的答案 9 来自 `k=3` 且四条边全 1，需 `right[2][2]≥3` 才成立，而实际 `right[2][2]=1`。这说明判据要改为：右下角 `(i,j)` 的 `right[i][j]≥k`（顶边）不适用，应检查 `(i-k+1,j)` 的 `down≥k`（右边）与 `(i,j-k+1)` 的 `right≥k`（底边）。示例 1 中 `(0,2)` 的 `down=3`、`(2,0)` 的 `right=3`，`k=3` 成立，答案 9。

```python
for i in range(m-1, -1, -1):
    for j in range(n-1, -1, -1):
        if grid[i][j]:
            right[i][j] = 1 + (right[i][j+1] if j+1 < n else 0)
            down[i][j] = 1 + (down[i+1][j] if i+1 < m else 0)
best = 0
for i in range(m):
    for j in range(n):
        for k in range(min(right[i][j], down[i][j]), best, -1):
            if right[i-k+1][j] >= k and down[i][j-k+1] >= k:
                best = k
                break
```

## 复杂度
时间：`O(m*n*min(m,n))`，枚举右下角与边长，`m`、`n` 为行列数。
空间：`O(m*n)`，两张 DP 表各占 `m*n`。

## 易错点
- 输入 `[[1,1,0,0]]` 只有一行 → 若只按 `min(right,down)` 取边长会漏判单格，正确做法是 `k` 从 1 起试，单格 `k=1` 即答案 1。
- 判四条边时只查右下角两个方向 → 示例 1 的 `(2,2)` 的 `right=1` 会误判 `k=3` 不成立，正确做法是查 `(i-k+1,j)` 的 `down` 和 `(i,j-k+1)` 的 `right`，即右边与底边。

## 如果面试官追问
若要求输出正方形左上角坐标？答：在更新 `best` 时同步记录 `(i-k+1, j-k+1)` 即可，判据不变。
