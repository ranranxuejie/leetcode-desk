## 一句话思路
设最大值 m 与其余元素之和 rest，答案就是 min(sum, 2*rest+1)：最大值是唯一可能“排不下”的项目。

## 怎么做
1. 求 `total = sum(milestones)` 和 `m = max(milestones)`，令 `rest = total - m`。
2. 若 `m <= rest + 1`，最大值项目能被其他项目充分隔开，全部任务都能做完，返回 `total`。
3. 否则最大值项目是瓶颈：其余 `rest` 个任务最多“夹住” `rest + 1` 个最大值任务，返回 `2 * rest + 1`。
4. 两式合并即 `min(total, 2 * rest + 1)`。

以 `milestones = [5,2,1]` 为例：`total = 8`，`m = 5`，`rest = 3`。此时 `m = 5 > rest + 1 = 4`，走瓶颈分支，答案 `2*3+1 = 7`，与官方输出一致——第 8 周那个项目 0 的剩余任务确实排不进去。

```python
total = sum(milestones)
m = max(milestones)
rest = total - m
if m <= rest + 1:
    ans = total
else:
    ans = 2 * rest + 1
return ans
```

关键中间值就是 `rest = 3` 和阈值 `rest + 1 = 4`：`m = 5` 比它大 1，所以恰好浪费掉 1 个任务。

## 复杂度
时间 O(n)：一次 `sum` 加一次 `max` 各扫一遍数组。
空间 O(1)：只开 `total`、`m`、`rest` 三个标量。

## 易错点
- `milestones = [1]` 这种单元素输入 → 若直接套 `2*rest+1` 会得 1 但漏判 `m <= rest+1` 的边界（此处 `1 <= 0+1` 成立，返回 `total=1` 才对）→ 正确做法是先判 `m <= rest + 1` 再分支，别把两个公式写反。
- `milestones = [1,1,1,1]` 全相等 → 若误以为“最大值唯一才受瓶颈限制”而只对 `m` 做特判，会漏掉 `m = 1, rest = 3` 时 `1 <= 4` 应返回 4 的情况 → 正确做法是统一用 `min(total, 2*rest+1)`，不区分最大值是否并列。

## 如果面试官追问
要求输出具体工作序列怎么办？答：先按瓶颈分支确定能做完的任务数，再把最大值项目与其他项目交替放置，剩余任务按原顺序补在末尾即可。
