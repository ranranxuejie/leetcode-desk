## 一句话思路
按 `user_id` 分组数 `follower_id` 的行数，因为主键保证同一 (user_id, follower_id) 不重复，行数即关注者数。

## 怎么做
1. 对 `Followers` 按 `user_id` 做 `GROUP BY`，把同一用户的所有关注记录聚到一组。
2. 每组用 `COUNT(follower_id)` 得到该用户的关注者数量，别名 `followers_count`。
3. 最后 `ORDER BY user_id` 保证按用户编号升序输出。

拿官方示例走一遍：`user_id=2` 这一组有 `(2,0)`、`(2,1)` 两行，`COUNT(follower_id)` 得 2；`user_id=0` 只有 `(0,1)` 一行，得 1；`user_id=1` 只有 `(1,0)`，得 1。三组结果拼起来正是 `0→1, 1→1, 2→2`。

```python
# 伪代码：SQL 解法
# SELECT user_id, COUNT(follower_id) AS followers_count
# FROM Followers
# GROUP BY user_id
# ORDER BY user_id;

# 若用 pandas 表达同一逻辑
def count_followers(followers):
    return (followers.groupby("user_id")["follower_id"]
            .count()
            .reset_index(name="followers_count")
            .sort_values("user_id"))
```

关键点：`COUNT(follower_id)` 与 `COUNT(*)` 在这题等价，因为主键保证 `follower_id` 非空且组合唯一；但写 `COUNT(follower_id)` 语义更贴「数关注者」。

## 复杂度
时间：`GROUP BY` 需扫全表 n 行，排序至多 k 个不同用户贡献 O(k log k)。
空间：分组哈希表存 k 个用户计数，额外 O(k)。

## 易错点
- 输入里某用户只有关注别人、没人关注他（如示例中 `user_id=1` 只出现在 `follower_id` 列）→ 若误按 `follower_id` 分组会把他算成「被关注者」而漏掉 `user_id=1` 这一行 → 必须按 `user_id` 分组，关注者数来自 `follower_id` 列。
- 输入存在重复 (user_id, follower_id) 的脏数据（题面主键保证不重复，但若约束被放宽）→ 直接 `COUNT(*)` 会把重复行重复计数，得到偏大的 `followers_count` → 改用 `COUNT(DISTINCT follower_id)` 去重。

## 如果面试官追问
问：若表里有上亿行、只要关注者数 ≥ 100 的用户怎么办？
答：加 `HAVING COUNT(follower_id) >= 100`，让过滤在分组后完成，避免全量输出。
