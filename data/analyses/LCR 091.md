## 一句话思路
用动态规划按房子逐层递推，`dp[i][j]` 表示第 i 个房子刷颜色 j 时的最小总花费，转移时取另外两种颜色的较小值。

## 怎么做
1. 初始化 `dp = costs[0][:]`，表示第一个房子刷三种颜色的花费。
2. 从第 1 个房子开始遍历，对每个颜色 j，新花费 = `costs[i][j] + min(dp[其他两种颜色])`。
3. 用临时变量保存旧 dp，避免原地更新污染。
4. 最终答案是 `min(dp)`。

以示例 1 为例：`costs = [[17,2,17],[16,16,5],[14,3,19]]`。初始 `dp = [17,2,17]`。处理第 1 个房子：红色取 `min(2,17)=2`，得 `16+2=18`；蓝色取 `min(17,17)=17`，得 `16+17=33`；绿色取 `min(17,2)=2`，得 `5+2=7`。此时 `dp = [18,33,7]`。处理第 2 个房子：红色取 `min(33,7)=7`，得 `14+7=21`；蓝色取 `min(18,7)=7`，得 `3+7=10`；绿色取 `min(18,33)=18`，得 `19+18=37`。最终 `min([21,10,37]) = 10`。

```python
dp = costs[0][:]
for i in range(1, len(costs)):
    r, b, g = dp
    dp[0] = costs[i][0] + min(b, g)
    dp[1] = costs[i][1] + min(r, g)
    dp[2] = costs[i][2] + min(r, b)
return min(dp)
```

## 复杂度
时间：O(n)，每个房子固定处理 3 种颜色。
空间：O(1)，只开了长度为 3 的 dp 数组。

## 易错点
- 输入 `costs = [[7,6,2]]` 只有 1 个房子 → 若循环从 `range(len(costs))` 开始会重复计算 → 循环应从 `range(1, len(costs))` 开始，直接返回 `min(costs[0])`。
- 原地更新 dp 时先改了 `dp[0]` 再算 `dp[1]` → 会用到已被覆盖的旧值，导致结果偏小 → 必须先用 `r, b, g = dp` 保存旧值再更新。

## 如果面试官追问
若要求输出具体粉刷方案（每个房子刷什么颜色）？答：额外开一个 `n x 3` 的 `choice` 数组记录每个状态选的是哪种颜色，最后从 `min(dp)` 对应颜色回溯即可。
