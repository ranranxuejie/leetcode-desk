## 一句话思路
把「摘到的水果」看成一个连续下标区间，用前缀和加二分枚举区间端点，判断该区间能否在 k 步内走完。

## 怎么做
1. 对 `fruits` 求前缀和 `pre`，`pre[i]` 表示前 i 个位置的水果总数。
2. 枚举区间左端点 `l`，用 `bisect_right` 在位置数组里找右端点 `r`，使区间 `[l, r)` 内最远位置不超过可达范围。
3. 对每个候选区间，判断「先左后右」或「先右后左」哪种走法步数更少，取最小值与 k 比较。
4. 用 `pre[r] - pre[l]` 更新答案。

以示例 2 为例：`fruits = [[0,9],[4,1],[5,7],[6,2],[7,4],[10,9]]`，`startPos=5`，`k=4`。位置数组 `pos=[0,4,5,6,7,10]`。当 `l=1`（位置 4）时，区间最右能到位置 7，即 `r=5`，`pre[5]-pre[1]=14`。走法「先左到 4 再右到 7」需 `(5-4)+(7-4)=4` 步，恰好等于 k，答案 14。

```python
from bisect import bisect_right
pos = [p for p, _ in fruits]
pre = [0]
for _, a in fruits:
    pre.append(pre[-1] + a)
ans = 0
for l in range(len(fruits)):
    # 最远右端点：先左后右 或 先右后左 的步数上限
    limit = max(startPos - pos[l], 0) * 2 + k
    r = bisect_right(pos, startPos + k - 2 * max(startPos - pos[l], 0))
    r2 = bisect_right(pos, pos[l] + k - max(startPos - pos[l], 0))
    r = max(r, r2)
    ans = max(ans, pre[r] - pre[l])
```

## 复杂度
时间：O(n log n)，n 为水果位置数，每个左端点做一次二分。
空间：O(n)，前缀和数组与位置数组各占一份。

## 易错点
- `startPos` 不在任何水果位置（如示例 3 的 `startPos=3`）→ 若直接用 `bisect` 找起点下标会错位 → 应始终以位置数组 `pos` 为二分对象，不假设起点存在。
- 区间只在一侧时（如示例 1 全向右）→ 若统一套「往返」公式会多算步数 → 需分别计算「只左」「只右」「先左后右」「先右后左」四种情况取最小。

## 如果面试官追问
若 k 很大、能走遍所有水果，怎么优化？答：直接返回 `pre[-1]`，因为此时所有水果都能摘到。
