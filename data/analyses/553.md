## 一句话思路
除第一个数外，把所有数用括号包成连除，让 `nums[1]` 之后每个数都翻到分子上，值最大。

## 怎么做
1. 长度 1 直接返回 `str(nums[0])`，长度 2 返回 `"a/b"`，这两种情况加括号反而多余。
2. 长度 ≥3 时，表达式固定为 `nums[0] + "/(" + "/".join(nums[1:]) + ")"`。
3. 以 `[1000,100,10,2]` 为例：`nums[1:]` 拼成 `"100/10/2"`，外层括号后整体是 `1000/(100/10/2)`，内部按左结合算 `(100/10)/2 = 5`，结果 `1000/5 = 200`，正是最大值。
4. 不加内层括号的原因：`100/10/2` 左结合已经等于 `(100/10)/2`，再加一层就是题面禁止的冗余括号。

```python
def optimalDivision(nums):
    n = len(nums)
    if n == 1:
        return str(nums[0])
    if n == 2:
        return f"{nums[0]}/{nums[1]}"
    return f"{nums[0]}/({'/'.join(map(str, nums[1:]))})"
```

关键点：`nums[0]` 永远在分子，`nums[1]` 永远在分母，从 `nums[2]` 起每个数只要落在分母的分子位置就乘进结果。括号把 `nums[1:]` 整体变成分母，于是 `nums[2..]` 全部翻上去，`1000 * 10 * 2 / 100 = 200`。

## 复杂度
时间 O(n)：`join` 遍历 `nums[1:]` 一次，字符串拼接总量 O(n)。
空间 O(n)：结果字符串长度，额外只开了 `nums[1:]` 的映射列表。

## 易错点
- 输入 `[2,3]` → 若套用 `"2/(3)"` 会多出冗余括号，判题按字符串比对直接错 → 长度 2 必须走 `"2/3"` 分支。
- 输入 `[2,3,4]` → 若写成 `"2/3/4"` 得 0.166，若写成 `"2/(3)/4"` 括号冗余 → 正确是 `"2/(3/4)"`，只有 `nums[1:]` 整体一层括号，`nums[1]` 自己不再单独加括号。

## 如果面试官追问
问：如果要求返回所有能达到最大值的表达式怎么办？
答：本题保证最优解唯一，多解时需枚举括号方案比较浮点值，n≤10 可区间 DP 存最大最小值和对应串。
