## 一句话思路
按质量从小到大排序后依次碰撞，因为先吃小的能最快把 mass 抬到能吃掉下一颗，任何顺序只要可行，升序一定可行。

## 怎么做
1. 对 `asteroids` 升序排序，让行星从最弱的目标开始吃。
2. 遍历排序后的数组，每步判断 `mass >= a`；成立就 `mass += a`，不成立立刻返回 `False`。
3. 全部吃完返回 `True`。

拿示例 2 走一遍：`mass = 5`，排序后 `[4,4,9,23]`。吃 4 后 `mass = 9`，再吃 4 后 `mass = 13`，吃 9 后 `mass = 22`，此时面对 23，`22 >= 23` 不成立，返回 `False`。注意 22 正好是 `5+4+4+9`，说明失败不是顺序问题，而是总和上限不够。

```python
def asteroidsDestroyed(mass, asteroids):
    for a in sorted(asteroids):
        if mass < a:
            return False
        mass += a
    return True
```

关键点：排序后一旦卡住，就说明当前 mass 已经吃下了所有比 `a` 小的行星，再换顺序也只会更早卡住，所以直接返回 `False` 是安全的。

## 复杂度
时间：排序贡献 O(n log n)，遍历 O(n)，n 为 `asteroids` 长度。
空间：排序额外 O(n)（Python `sorted` 返回新列表），若原地排序则 O(log n) 栈空间。

## 易错点
- 输入 `mass = 5, asteroids = [4,9,23,4]` → 若按原顺序先撞 9，`5 < 9` 直接返回 `False`，但正确顺序是先吃两个 4 再吃 9 → 必须先排序再判断。
- 输入 `mass = 1, asteroids = [1,1,1]` → 若把判断写成 `mass > a`（严格大于）而非 `mass >= a`，第一颗 1 就判失败 → 题面要求「大于等于」才摧毁，边界必须用 `>=`。

## 如果面试官追问
问：如果要求输出一种可行的碰撞顺序怎么办？
答：排序后的顺序本身就是答案，直接返回 `sorted(asteroids)` 即可，无需回溯。
