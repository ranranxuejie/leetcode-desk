## 一句话思路
用闭包保存 `timer` 句柄，每次调用先 `clearTimeout` 再重设，只有最后一次调用能活到 `t` 毫秒后执行。

## 怎么做
1. 在 `debounce` 内定义 `timer = None`，它跨调用存活，是唯一需要保存的状态。
2. 每次被调用时，若 `timer is not None` 就 `clearTimeout(timer)`，取消上一次的待执行任务。
3. 用 `setTimeout` 重新挂一个 `t` 毫秒后执行 `fn(*args)` 的任务，把句柄写回 `timer`。
4. 参数必须用 `*args` 透传，否则示例 3 的 `inputs: [1, 2]` 会丢成 `[1]`。

拿示例 1 走一遍：`t = 50`，50ms 调用 `dlog(1)`，`timer` 从 `None` 变成句柄 A，计划 100ms 执行；75ms 调用 `dlog(2)`，先 `clearTimeout(A)` 杀掉 100ms 那次，再挂句柄 B 计划 125ms 执行。最终只有 `{"t": 125, inputs: [2]}` 输出，`inputs` 是第二次的 `[2]` 而不是 `[1]`。

```python
def debounce(t, fn):
    timer = None
    def wrapper(*args):
        nonlocal timer
        if timer is not None:
            clearTimeout(timer)
        timer = setTimeout(lambda: fn(*args), t)
    return wrapper
```

关键在 `nonlocal timer`：不加这行，`wrapper` 内的 `timer = ...` 会新建局部变量，`clearTimeout` 永远拿到 `None`，防抖退化成「每次都执行」。

## 复杂度
时间：每次调用 O(1)，共 `calls.length` 次，与 `t` 无关。
空间：O(1)，只存一个 `timer` 句柄，`args` 随闭包短暂持有。

## 易错点
- 漏写 `nonlocal timer` → 示例 1 会输出 `[{"t": 100, inputs: [1]}, {"t": 125, inputs: [2]}]` 两条，因为第一次的定时器没被取消 → 正确做法是在 `wrapper` 首行声明 `nonlocal timer`。
- 用 `fn(args)` 而非 `fn(*args)` → 示例 3 第三次调用输出 `inputs: [[5, 6]]` 而非 `[5, 6]`，嵌套了一层列表 → 正确做法是 `lambda: fn(*args)`，让 `args` 元组解包。

## 如果面试官追问
问：要「立即执行版」防抖（首次立刻跑，窗口内后续忽略）怎么改？
答：加 `immediate` 标志，`timer is None` 时直接 `fn(*args)`，否则只重置 `timer`。
