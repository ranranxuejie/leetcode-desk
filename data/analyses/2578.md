## 一句话思路
把数位升序排序后按奇偶下标轮流分给两个数，高位放小数字，贪心即最优。

## 怎么做
1. 把 `num` 转成字符串，逐位取 `int`，得到数位列表 `digits`。
2. 对 `digits` 升序排序，让小的数字占据高位。
3. 按下标奇偶交替累加：偶数下标进 `num1`，奇数下标进 `num2`，每次 `num1 = num1 * 10 + d`。
4. 返回 `num1 + num2`。

以 `num = 4325` 为例：`digits = [4,3,2,5]`，排序后 `[2,3,4,5]`。偶数下标取 `2`、`4` 组成 `num1 = 24`，奇数下标取 `3`、`5` 组成 `num2 = 35`，和为 `59`，与示例一致。

```python
digits = sorted(int(c) for c in str(num))
num1 = num2 = 0
for i, d in enumerate(digits):
    if i % 2 == 0:
        num1 = num1 * 10 + d
    else:
        num2 = num2 * 10 + d
return num1 + num2
```

为什么交替分而不是把小的全给一个数：和的每一位权重由该数位所在位置决定，两个数长度最多差 1，把排序后的数字按位权从高到低依次分配给当前「更缺高位」的那个数，等价于交替取。`687` 排序后 `[6,7,8]`，`num1 = 68`、`num2 = 7`，和 `75`，验证了长度不等时短数只有一位、长数吃两个高位仍然最优。

## 复杂度
时间：O(d log d)，d 是数位个数（≤10），排序贡献 log d。
空间：O(d)，存 `digits` 列表，无其他额外结构。

## 易错点
- 输入 `num = 10` → 若直接把数位两两配对成 `1` 和 `0` 却把 `0` 当无效位丢掉，会错成 `1`；正确是保留前导 0 语义，`num1 = 1`、`num2 = 0`，和 `1`，代码里 `num2 = num2 * 10 + 0` 自然得 0，不要特判跳过 0。
- 输入 `num = 4325` → 若先转成整数再取模（`num % 10` 逐位）会得到逆序 `[5,2,3,4]`，排序后虽仍是 `[2,3,4,5]` 不影响本题，但若中途用 `num //= 10` 且忘记收集全部位，会漏掉最高位 `4`，结果偏小；正确做法是先 `str(num)` 一次性取全所有位再排序。

## 如果面试官追问
要求输出具体的 `num1`、`num2` 而不只是和？答：上面的循环已经同时构造出两个数，直接返回 `(num1, num2)` 即可，无需改动贪心顺序。
