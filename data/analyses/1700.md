## 一句话思路
只数学生里 0 和 1 的个数，按 sandwiches 从栈顶往下逐个消耗，遇到没人要的立刻停。

## 怎么做
1. 统计 `students` 中 0 和 1 的数量，记作 `cnt[0]`、`cnt[1]`。
2. 从 `sandwiches[0]` 开始遍历，若 `cnt[s] > 0` 就 `cnt[s] -= 1`，否则跳出。
3. 跳出时剩下的学生数就是 `cnt[0] + cnt[1]`。

以示例 2 为例：`students = [1,1,1,0,0,1]` 得 `cnt = {0:2, 1:4}`。依次消耗 `sandwiches` 的 1,0,0,0,1,1：前五个都能匹配，`cnt` 变成 `{0:0, 1:2}`；第六个栈顶是 1，`cnt[1]=2>0` 仍可消耗，最终 `cnt` 全为 0，返回 0——注意示例 2 实际输出是 3，说明我上面数错了，正确统计是 `students` 中 0 有 2 个、1 有 4 个，而 `sandwiches` 前三个是 1,0,0，消耗后 `cnt={0:0,1:3}`，第四个栈顶 0 时 `cnt[0]=0`，跳出，返回 3。关键中间值就是跳出那一刻的 `cnt[0]=0`。

```python
cnt = [0, 0]
for s in students:
    cnt[s] += 1
for s in sandwiches:
    if cnt[s] == 0:
        break
    cnt[s] -= 1
return cnt[0] + cnt[1]
```

顺序无关性成立的原因：队列可以任意旋转，只要还有学生喜欢栈顶类型，总能把他转到队首。

## 复杂度
时间 O(n)：遍历 `students` 一次、`sandwiches` 至多一次，n 为数组长度。
空间 O(1)：只开了长度 2 的 `cnt`。

## 易错点
- 用 `students = [1,1]`、`sandwiches = [0,0]` 时，若真去模拟队列会死循环（学生反复回到队尾），必须靠 `cnt[0]==0` 立刻 break；正确做法是先统计再按栈顶消耗，不实际移动元素。
- 示例 2 中若把 `sandwiches` 当成从尾部取（误以为栈底是顶部），会得到错误答案；`sandwiches[0]` 才是栈顶，遍历必须从头开始。

## 如果面试官追问
问：若三明治类型不止 0/1 而是 k 种？
答：`cnt` 改成大小 k 的数组，逻辑不变，时间仍 O(n)，空间 O(k)。
