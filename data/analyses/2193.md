## 一句话思路
从两端向中间贪心配对：左端字符去右侧找最近的同字符换到右端，找不到就说明它是唯一落单的中心字符，往中间挪。

## 怎么做
1. 双指针 `i=0, j=n-1`，每轮固定 `s[i]`，从 `k=j` 向左找第一个 `s[k]==s[i]`。
2. 若 `k>i`，把 `s[k]` 一路冒泡到 `j`，累加 `j-k` 次交换，然后 `i+=1, j-=1`。
3. 若 `k==i`（右侧没有配对），说明 `s[i]` 是那个奇数次的中心字符，把它与 `s[i+1]` 交换一次、`ans+=1`，`i` 不动，下一轮继续为它找配对。
4. 以 `s="letelt"` 为例：`i=0` 固定 `'l'`，从 `j=5` 左扫到 `k=3` 才遇到 `'l'`，冒泡 2 次得 `"letetl"`，`ans=2`；之后 `i=1,j=4` 的 `'e'` 与 `'e'` 已对称，`'t'` 居中，结束。

```python
def minMovesToMakePalindrome(s):
    s = list(s)
    i, j, ans = 0, len(s) - 1, 0
    while i < j:
        k = j
        while k > i and s[k] != s[i]:
            k -= 1
        if k == i:                      # 落单的中心字符
            s[i], s[i + 1] = s[i + 1], s[i]
            ans += 1
        else:
            while k < j:                # 冒泡到右端
                s[k], s[k + 1] = s[k + 1], s[k]
                k += 1
                ans += 1
            i += 1
            j -= 1
    return ans
```

## 复杂度
时间：外层 `i/j` 收缩 n/2 轮，内层扫描加冒泡最坏 O(n)，共 O(n²)，n=2000 约 4×10⁶ 次交换。
空间：只把 `s` 转成 list 原地改，O(n)，无额外数组。

## 易错点
- 输入 `"mamad"`：若在 `k==i` 时直接 `i+=1` 跳过，`'m'` 就永远配不上对，答案偏小。正确做法是交换到 `s[i+1]` 后 `i` 保持不动，下一轮重新为它找右侧的 `'m'`。
- 输入 `"aabb"`：若固定右端 `s[j]` 去左边找配对，`'b'` 会先被搬到左端，虽然也能得 2，但遇到 `"letelt"` 这类会多算。统一固定左端 `s[i]`、把配对字符搬到右端 `j`，方向不能混。

## 如果面试官追问
问：n 放大到 10⁵ 怎么办？
答：贪心结论不变，但冒泡要换成树状数组统计逆序对，把每步的移动次数 O(1) 累加，总复杂度降到 O(n log n)。
