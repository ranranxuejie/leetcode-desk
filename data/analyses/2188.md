## 一句话思路
先对每种轮胎预处理「连续跑 k 圈」的最优代价，再对圈数做完全背包式 DP。

## 怎么做
1. 对每个 `(f, r)` 累乘求前缀和，得到该轮胎连续跑 k 圈的耗时 `cost[k]`，只算到 `cost[k] <= changeTime + f` 为止（再长不如换新胎）。
2. 对所有轮胎取逐 k 的最小值，得到 `best[k]`：一条新胎连跑 k 圈的最少耗时。
3. `dp[i]` = 跑完前 i 圈的最少时间，转移 `dp[i] = min(dp[i-k] + best[k] + changeTime)`，最后减去多算的一次换胎时间。
4. 用示例 1 验证：`best[1]=2, best[2]=8`；`dp[2]=8`，`dp[4]=dp[2]+5+8=21`，减 5 得 21。

```python
best = [0] * (numLaps + 1)
for k in range(1, numLaps + 1):
    best[k] = 2**31 - 1
for f, r in tires:
    s, cur = 0, f
    for k in range(1, numLaps + 1):
        s += cur
        if s >= best[k] and cur > changeTime:
            break
        best[k] = min(best[k], s)
        cur *= r
        if cur > changeTime + f:
            break
dp = [2**31 - 1] * (numLaps + 1)
dp[0] = -changeTime
for i in range(1, numLaps + 1):
    for k in range(1, i + 1):
        dp[i] = min(dp[i], dp[i - k] + best[k] + changeTime)
return dp[numLaps]
```

## 复杂度
时间：O(len(tires) · log(changeTime) + numLaps²)，前者是每种轮胎的截断长度。
空间：O(numLaps)，只开 `best` 和 `dp` 两个数组。

## 易错点
- `r=1` 时 `cur` 不增长，若只靠 `cur > changeTime + f` 截断会死循环 → 必须同时用 `s >= best[k]` 提前 break，否则 `tires=[[1,1]]` 会跑到 `numLaps` 之外。
- 忘记 `dp[0] = -changeTime` 或最后不减去一次换胎 → 示例 1 会输出 26 而非 21，因为第一段轮胎不需要换胎时间。

## 如果面试官追问
若 `numLaps` 放大到 10⁹ 怎么办？答：`best[k]` 在 k 超过约 log 量级后不再改善，可证明最优段长有上界，用矩阵快速幂或分段周期处理。
