## 一句话思路
按起点排序后一次扫描，用结果数组末尾区间与当前区间比较，重叠就原地扩右端。

## 怎么做
1. 对 `intervals` 按 `start` 升序排序，保证可能重叠的区间相邻。
2. 初始化 `res = []`，遍历每个 `[s, e]`。
3. 若 `res` 为空或 `res[-1][1] < s`，说明不重叠，直接 `res.append([s, e])`。
4. 否则重叠，执行 `res[-1][1] = max(res[-1][1], e)`。

以示例 1 的 `[[1,3],[2,6],[8,10],[15,18]]` 为例：排序后不变。处理 `[2,6]` 时，`res[-1]` 是 `[1,3]`，`3 < 2` 为假，于是 `res[-1][1] = max(3, 6) = 6`，`res` 变成 `[[1,6]]`；处理 `[8,10]` 时 `6 < 8` 成立，新开一段。

```python
intervals.sort(key=lambda x: x[0])
res = []
for s, e in intervals:
    if not res or res[-1][1] < s:
        res.append([s, e])
    else:
        res[-1][1] = max(res[-1][1], e)
return res
```

关键在 `res[-1][1] < s` 这个判断：用严格小于，是因为 `[1,4]` 与 `[4,5]` 端点相接也算重叠，示例 2 要求合并成 `[1,5]`。若写成 `<=`，示例 2 会输出 `[[1,4],[4,5]]`，错。

## 复杂度
时间：排序 O(n log n) 主导，扫描 O(n)，n 为区间个数。
空间：排序栈开销 O(log n)，结果数组最坏 O(n)。

## 易错点
- 输入 `[[1,4],[4,5]]` → 判断写成 `res[-1][1] <= s` 会把相接区间当不重叠，输出两段 → 必须用严格 `<` 判不重叠。
- 输入 `[[1,10],[2,3]]` → 若直接 `res[-1][1] = e` 会把右端从 10 缩到 3，输出 `[[1,3]]` → 必须取 `max(res[-1][1], e)`，被包含的区间不能缩短已有右端。

## 如果面试官追问
问：区间数量涨到 10^6 且已按起点有序，还能更快吗？
答：跳过排序，直接 O(n) 单次扫描，逻辑不变。
