## 一句话思路
排序后双指针从两端夹逼，和等于 k 就配对计数，因为排序后小值只可能配大值，不会漏解。

## 怎么做
1. 对 `nums` 排序，`i = 0`，`j = len(nums) - 1`，`ans = 0`。
2. 循环 `while i < j`：算 `s = nums[i] + nums[j]`。
3. `s == k` 时 `ans += 1`、`i += 1`、`j -= 1`；`s < k` 时 `i += 1`；`s > k` 时 `j -= 1`。
4. 返回 `ans`。

以 `nums = [1,2,3,4], k = 5` 为例：排序后不变。首轮 `i=0, j=3`，`s = 1 + 4 = 5`，配对成功，`ans = 1`，指针收缩到 `i=1, j=2`；第二轮 `s = 2 + 3 = 5`，`ans = 2`，`i=2, j=1` 退出循环。返回 2。

关键中间值：`s < k` 时 `nums[i]` 与当前最大的 `nums[j]` 相加都不够，说明 `nums[i]` 和任何剩余元素都配不成 k，直接丢弃 `i`；`s > k` 同理丢弃 `j`。这一步保证每轮至少移动一个指针，不会死循环。

```python
nums.sort()
i, j, ans = 0, len(nums) - 1, 0
while i < j:
    s = nums[i] + nums[j]
    if s == k:
        ans += 1
        i += 1
        j -= 1
    elif s < k:
        i += 1
    else:
        j -= 1
return ans
```

哈希表写法也可：遍历时若 `k - x` 在计数表中就配对并减计数，否则 `x` 计数加一。但双指针不用额外字典，且排序后逻辑更短。

## 复杂度
时间 O(n log n)：排序贡献 log n，双指针单趟 O(n)。
空间 O(1)：只开了 `i`、`j`、`ans`、`s` 几个变量（排序栈空间不计）。

## 易错点
- `nums = [3,1,3,4,3], k = 6`：若用哈希表但配对后忘记把 `k - x` 的计数减一，会把三个 3 两两配成 3 对，错成 3；正确是每用一个就减一，答案 1。
- `nums = [2,2,2,2], k = 4`：双指针若写成 `s == k` 时只动 `i` 不动 `j`，`i` 会追上 `j` 前多算或死循环；正确是 `i += 1` 和 `j -= 1` 同时执行，答案 2。

## 如果面试官追问
问：要求输出具体配对了哪些下标怎么办？
答：排序会打乱下标，需先存 `(值, 原下标)` 再排序，配对时记录两个原下标即可。
