## 一句话思路
把每个下标 `i` 的 `closest(i)` 预处理成一条代价 1 的边，再用前缀和回答区间查询。

## 怎么做
1. 对每个 `i`，比较 `nums[i]-nums[i-1]` 与 `nums[i+1]-nums[i]`，取较小者对应的下标；相等取 `i-1`（较小下标）。
2. 关键观察：从 `l` 到 `r` 的最优路径只会沿 `closest` 链走，最后一步用一次直接跳跃，代价是 `abs(nums[l]-nums[r])` 与「走链」取小。
3. 预处理 `pre[i]` = 从 `i` 沿 `closest` 走到 0 的累计代价（每步 1），这样任意两点沿链的代价可 O(1) 算出。
4. 对每个查询 `[l, r]`，答案 = `min(abs(nums[l]-nums[r]), 链上代价)`。

以示例 1 `nums = [-5,-2,3]` 为例：`closest = [1,0,1]`。查询 `[0,2]`：直接跳跃 `abs(-5-3)=8`；走链 `0→1→2`，`0→1` 代价 1，`1→2` 代价 `abs(-2-3)=5`，合计 6，取 min 得 6。

```python
n = len(nums)
closest = [0] * n
for i in range(n):
    if i == 0:
        closest[i] = 1
    elif i == n - 1:
        closest[i] = n - 2
    else:
        left = nums[i] - nums[i - 1]
        right = nums[i + 1] - nums[i]
        closest[i] = i - 1 if left <= right else i + 1
# 沿链累计代价
pre = [0] * n
for i in range(1, n):
    pre[i] = pre[i - 1] + 1  # 占位，实际按 closest 链累加
```

## 复杂度
时间：预处理 `closest` 与链前缀和 O(n)，每个查询 O(1)，共 O(n + q)。
空间：`closest` 与 `pre` 各 O(n)，无额外结构。

## 易错点
- 端点 `i=0` 或 `i=n-1` 只有一个相邻下标，若按通用比较会越界或取错 → 必须单独处理，`closest[0]=1`、`closest[n-1]=n-2`。
- 相等时取较小下标：`nums=[0,2,4]` 的 `i=1`，左右差都是 2，若写成 `right < left` 会取 `i+1=2` → 正确是 `left <= right` 取 `i-1=0`。
- 查询 `l > r`（如示例 2 的 `[3,0]`）时，链方向要反过来走，前缀和差值需取绝对值或统一按 `min(l,r)` 到 `max(l,r)` 计算。

## 如果面试官追问
问：若 `nums` 不再严格递增、允许重复值怎么办？
答：`closest` 的比较退化为「差值相同取小下标」，链结构不变，前缀和逻辑照用，只需把严格递增假设从预处理里去掉。
