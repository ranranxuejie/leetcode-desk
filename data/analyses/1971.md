## 一句话思路
用并查集把每条边两端合并，最后判断 `source` 和 `destination` 是否在同一集合，连通即存在路径。

## 怎么做
1. 初始化 `parent = list(range(n))`，每个顶点自成一个集合。
2. 遍历 `edges`，对每条边 `[u, v]` 执行 `union(u, v)`。
3. 查找时用路径压缩，`find` 递归把沿途节点直接挂到根上。
4. 返回 `find(source) == find(destination)`。

以示例 2 为例：`edges` 前两条把 0、1、2 并成一棵，后三条把 3、4、5 并成另一棵。处理完后 `find(0)` 的根是 0，`find(5)` 的根是 3（或 5，取决于合并方向），两者不等，返回 `False`。

```python
def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

for u, v in edges:
    ru, rv = find(u), find(v)
    if ru != rv:
        parent[ru] = rv
return find(source) == find(destination)
```

关键中间值：示例 1 中 `edges = [[0,1],[1,2],[2,0]]`，合并后 `parent` 全部指向同一根，`find(0) == find(2)` 为 `True`。

## 复杂度
时间：O(n + m·α(n))，m 为边数，α 近似常数，主要开销在初始化 `parent` 和遍历边。
空间：O(n)，`parent` 数组占 n 个元素，无额外邻接表。

## 易错点
- `source == destination` 时（如 `n=1, edges=[], source=0, destination=0`）→ 若先判 `edges` 为空就返回 `False` 会错 → 应直接返回 `True`，因为单点自身连通。
- 只做 `parent[ru] = rv` 而不在 `find` 里路径压缩 → 链式合并（如 `[[0,1],[1,2],[2,3],...]`）会退化成 O(n) 查找，n=2*10^5 时超时 → 必须带路径压缩或按秩合并。

## 如果面试官追问
问：要求输出具体路径而非布尔值怎么办？
答：改用 BFS/DFS 并记录 `prev` 数组，从 `destination` 回溯到 `source` 即可，复杂度不变。
