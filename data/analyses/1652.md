## 一句话思路
把 `code` 复制成两倍长，用前缀和加滑动窗口，`k>0` 取右侧窗口、`k<0` 取左侧窗口，避免逐元素求和。

## 怎么做
1. 若 `k == 0`，直接返回 `[0]*n`。
2. 构造 `a = code * 2`，并算前缀和 `pre`，其中 `pre[i]` 表示 `a[:i]` 的和。
3. 对每个 `i`，根据 `k` 的正负确定窗口区间，用前缀和差值一次算出结果。
4. 把结果写回 `res[i]`，返回 `res`。

以 `code = [5,7,1,4], k = 3` 为例，`a = [5,7,1,4,5,7,1,4]`。对 `i=0`，右侧 3 个是 `a[1:4]`，前缀和差为 `pre[4]-pre[1] = 17-5 = 12`，与输出 `[12,10,16,13]` 首项一致。

```python
n = len(code)
if k == 0:
    return [0] * n
a = code * 2
pre = [0] * (2 * n + 1)
for i in range(2 * n):
    pre[i + 1] = pre[i] + a[i]
res = [0] * n
for i in range(n):
    if k > 0:
        res[i] = pre[i + k + 1] - pre[i + 1]
    else:
        res[i] = pre[i + n] - pre[i + n + k]
return res
```

## 复杂度
时间：O(n)，前缀和与单层循环各扫一遍，`k` 的绝对值不影响复杂度。
空间：O(n)，`a` 和 `pre` 各开 2n+1 长度，`res` 开 n。

## 易错点
- `k < 0` 时窗口下标容易写反：若用 `pre[i+n]-pre[i+n+k]`，当 `k=-2, i=0, n=4` 得 `pre[4]-pre[2]=17-12=5`，但正确答案是 `code[2]+code[3]=9+3=12`。正确做法是左侧窗口取 `a[i+n+k : i+n]`，即 `pre[i+n] - pre[i+n+k]` 中 `k` 为负时区间起点是 `i+n+k`，需确认 `i+n+k` 不小于 `i`，否则会取到空区间。
- `k` 的绝对值等于 `n-1` 时，窗口覆盖除自身外所有元素，若用 `code[i+1:i+k+1]` 直接切片会越界；必须用 `a = code*2` 或取模，不能只对 `code` 切片。

## 如果面试官追问
若 `n` 很大且 `k` 固定，能否 O(1) 空间？答：可以，先算首个窗口和，之后每步减去滑出元素、加上滑入元素，用取模处理循环。
