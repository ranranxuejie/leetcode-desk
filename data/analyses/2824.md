## 一句话思路
排序后双指针从两端收缩，因为有序性让「和太小」能一次性确定一整批配对。

## 怎么做
1. 先 `nums.sort()`，把下标约束 `i < j` 变成「排序后位置不同即可」，因为任意两个不同位置都对应原数组的一对下标。
2. `l, r = 0, len(nums) - 1`，`ans = 0`，循环条件 `l < r`。
3. 若 `nums[l] + nums[r] < target`，则 `nums[l]` 与 `nums[l+1..r]` 全部满足，`ans += r - l`，再 `l += 1`；否则 `r -= 1`。
4. 返回 `ans`。

拿示例 1 `nums = [-1,1,2,3,1], target = 2`：排序得 `[-1,1,1,2,3]`。首轮 `l=0, r=4`，`-1 + 3 = 2`，不严格小于 2，`r` 减到 3；此时 `-1 + 2 = 1 < 2`，`ans += 3 - 0 = 3`，`l` 变 1。之后 `1+2=3`、`1+1=2` 都不满足，`r` 一路降到 1，循环结束，`ans = 3`。关键中间值就是第一次成功时的 `r - l = 3`，它一次性吃掉了 `(-1,1)`、`(-1,1)`、`(-1,2)` 三对。

```python
nums.sort()
l, r, ans = 0, len(nums) - 1, 0
while l < r:
    if nums[l] + nums[r] < target:
        ans += r - l
        l += 1
    else:
        r -= 1
return ans
```

## 复杂度
时间：排序 `O(n log n)`，双指针扫描 `O(n)`，总计 `O(n log n)`。
空间：排序栈开销 `O(log n)`，其余只有 `l/r/ans` 三个变量。

## 易错点
- 写成 `nums[l] + nums[r] <= target`：示例 1 首轮 `-1 + 3 = 2` 会被算进去，`ans` 变成 4 而非 3。题目是严格小于，判断必须用 `<`。
- 成功分支里写成 `ans += 1` 再 `l += 1`：示例 1 只会得到 1，漏掉 `r - l` 这一批。正确做法是 `ans += r - l`，因为 `nums[l]` 与区间内每个右端元素的和都不超过 `nums[l] + nums[r]`。

## 如果面试官追问
若 n 放大到 10^5 且要求输出所有下标对而非计数，怎么办？
答：计数仍用双指针，输出方案则需枚举，最坏 `O(n^2)` 个答案，无法低于输出规模。
