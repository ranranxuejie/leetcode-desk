## 一句话思路
固定右端点，用「以 i 结尾的所有子数组 LCM 去重后只有 O(log k) 个」做滚动集合，逐个比对 k。

## 怎么做
1. 维护 `cur` 字典：键是「以 `nums[i]` 结尾的某个子数组的 LCM」，值是这种 LCM 出现的子数组个数。
2. 每步把 `nums[i]` 自身作为长度 1 的子数组加入，再把上一轮每个 LCM 与 `nums[i]` 求新 LCM 合并计数。
3. 任何 LCM 一旦大于 k 就丢弃——LCM 只增不减，超过 k 后永远回不到 k。
4. 累加 `cur.get(k, 0)` 到答案。

以 `nums = [3,6,2,7,1], k = 6` 为例，走到 `i=1`（元素 6）时，上一轮 `cur = {3:1}`，合并后 `cur = {6:2}`（子数组 `[6]` 和 `[3,6]`），此时 `cur[6]=2` 直接计入答案；`i=2` 时 `{6:2}` 与 2 求 LCM 得 6，`cur = {6:3}`，再计入 3；`i=3` 的 7 使 LCM 变 42 > 6 被丢弃，`cur` 只剩 `{7:1}`，不再贡献。总计 4。

```python
from math import gcd
cur = {}
ans = 0
for x in nums:
    nxt = {x: 1}
    for l, c in cur.items():
        nl = l // gcd(l, x) * x
        if nl <= k:
            nxt[nl] = nxt.get(nl, 0) + c
    cur = nxt
    ans += cur.get(k, 0)
```

## 复杂度
时间 O(n · log k)：每个右端点最多保留 log k 个不同 LCM，每次求 gcd 是 O(log k)。
空间 O(log k)：`cur` 字典最多存 log k 个键。

## 易错点
- `nums = [4, 8], k = 4`：若只判断 `x > k` 就跳过，会漏掉 `[4]` 本身；正确做法是先把 `x` 放进 `nxt`，再对合并结果做 `nl <= k` 过滤，因为 8 单独就超了但 4 合法。
- `nums = [2, 3, 5], k = 6`：若用「LCM 等于 k 就 break 内层循环」的暴力双指针，会在 `[2,3]` 后误以为后续都无效；正确做法是保留所有 ≤ k 的 LCM 并计数，因为 `[2,3,5]` 的 LCM 是 30 但 `[2,3]` 仍是 6，必须靠字典计数而非提前终止。

## 如果面试官追问
若 k 放大到 10^9 且 nums 长度 10^5，还能这么做吗？答：能，去重后 LCM 个数仍是 O(log k)，只是 gcd 常数变大，总复杂度 O(n log k)。
