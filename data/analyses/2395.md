## 一句话思路
把每个长度为 2 的子数组的和丢进哈希集合，一旦某个和重复出现就返回 `True`。

## 怎么做
1. 用 `seen = set()` 记录已经出现过的相邻两元素之和。
2. 从 `i = 0` 遍历到 `len(nums) - 2`，每次算 `s = nums[i] + nums[i+1]`。
3. 若 `s` 已在 `seen` 中，直接返回 `True`；否则 `seen.add(s)`。
4. 循环走完没撞上重复，返回 `False`。

以 `nums = [4,2,4]` 为例：`i=0` 时 `s = 4+2 = 6`，`seen = {6}`；`i=1` 时 `s = 2+4 = 6`，`6 in seen` 成立，返回 `True`。两个子数组起点分别是 0 和 1，满足「下标不同」的要求。

```python
seen = set()
for i in range(len(nums) - 1):
    s = nums[i] + nums[i + 1]
    if s in seen:
        return True
    seen.add(s)
return False
```

关键点在于：长度为 2 的子数组由起点唯一确定，起点不同即子数组不同，所以「和相同」直接等价于「集合里已有这个和」，不需要额外记录下标。

## 复杂度
时间：O(n)，一次遍历，每个相邻对只算一次加法。
空间：O(n)，最坏情况下 `seen` 存下 n-1 个不同的和。

## 易错点
- `nums = [1,1,1,1]`：若把「和相同」误判成「元素相同才算重复」，会漏掉 `[1,1]` 与 `[1,1]` 起点 0、1 这一对，错返回 `False`；正确做法是只比较和，不看元素。
- `nums = [0,0,0]`：若循环写成 `range(len(nums))` 并在 `i` 处访问 `nums[i+1]`，`i=2` 时越界抛 `IndexError`；正确做法是上界取 `len(nums) - 1`，保证 `i+1` 合法。

## 如果面试官追问
问：如果要求返回这两个子数组的起始下标而不是布尔值？
答：把 `seen` 从 `set` 换成 `dict`，键为和、值为首次出现的起点 `i`，命中时返回 `(seen[s], i)`。
