## 一句话思路
在 [0,1000] 上做 BFS，因为越界值只能作为终点，所以只需把 goal 单独判断，不必入队。

## 怎么做
1. 若 `start == goal` 返回 0；把 `start` 入队，`dist[start] = 0`。
2. 每次出队 `x`，对每个 `v in nums` 生成 `x+v`、`x-v`、`x^v` 三个候选值。
3. 候选值等于 `goal` 就返回 `dist[x] + 1`；落在 `[0,1000]` 且未访问过才入队。
4. 队列空仍未命中，返回 -1。

以示例 1 为例：`nums=[2,4,12], start=2`。第一层从 2 出发得到 `2+12=14`，14 在范围内入队，`dist[14]=1`；第二层从 14 出发，`14-2=12 == goal`，返回 `1+1=2`。注意 14 本身不是 goal，必须真的入队才能走到 12。

```python
from collections import deque

q = deque([start])
dist = {start: 0}
while q:
    x = q.popleft()
    for v in nums:
        for y in (x + v, x - v, x ^ v):
            if y == goal:
                return dist[x] + 1
            if 0 <= y <= 1000 and y not in dist:
                dist[y] = dist[x] + 1
                q.append(y)
return -1
```

关键点：`y == goal` 的判断必须放在范围检查**之前**，否则示例 2 的 `-4` 会被 `0 <= y` 挡掉。

## 复杂度
时间 O(1001 × n)，每个状态最多出队一次，每次枚举 n 个 nums。
空间 O(1001)，dist 字典和队列最多存 1001 个状态。

## 易错点
- 输入 `nums=[3,5,7], start=0, goal=-4` → 若先判 `0 <= y <= 1000` 再判 `y == goal`，`-4` 被丢弃，错答 -1 → 正确做法是先比 goal 再判范围。
- 输入 `nums=[2,4,12], start=2, goal=12` → 若把 `x+v` 等结果直接当答案而不入队，会漏掉 14 这个中间态，错答 1 或 -1 → 正确做法是范围内未访问值一律入队，靠 BFS 层数累加。

## 如果面试官追问
问：若 nums 很大、goal 也很大怎么办？答：本题靠 1001 个状态封顶，换大范围就得改用双向 BFS 或数学剪枝，不能直接套这个队列。
