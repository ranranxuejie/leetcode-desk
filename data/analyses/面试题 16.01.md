## 一句话思路
用异或 `a ^= b; b ^= a; a ^= b` 三步交换，因为 `x ^ x = 0`、`x ^ 0 = x`，两数信息在异或中可逆还原。

## 怎么做
1. 令 `a, b = numbers[0], numbers[1]`，先执行 `a = a ^ b`，此时 `a` 存的是两数的异或值。
2. 执行 `b = a ^ b`，用新 `a` 异或原 `b`，得到原 `a`，写回 `b`。
3. 执行 `a = a ^ b`，用新 `a` 异或新 `b`（即原 `a`），得到原 `b`，写回 `a`。
4. 返回 `[a, b]`。

以官方示例 `numbers = [1, 2]` 为例：第一步 `a = 1 ^ 2 = 3`；第二步 `b = 3 ^ 2 = 1`；第三步 `a = 3 ^ 1 = 2`，最终 `[2, 1]`。关键中间值是 `a = 3`，它同时编码了 1 和 2。

```python
a, b = numbers[0], numbers[1]
a = a ^ b      # a = 1 ^ 2 = 3
b = a ^ b      # b = 3 ^ 2 = 1
a = a ^ b      # a = 3 ^ 1 = 2
return [a, b]
```

若改用加减法：`a = a + b; b = a - b; a = a - b`，同样三步，但 `a + b` 在 32 位下可能越界，异或没有这个问题。

## 复杂度
时间 O(1)：固定 3 次异或，与 `numbers` 长度无关。
空间 O(1)：只用了 `a`、`b` 两个标量，未开数组。

## 易错点
- 输入 `numbers = [0, 5]` → 若误写成 `a = a ^ b` 后直接用 `b = a ^ b` 却把 `a` 覆盖前先算错顺序，会得到 `[0, 5]` 未交换 → 严格按「先改 a、再改 b、最后改 a」的顺序，且每步都用最新值。
- 输入 `numbers = [7, 7]` → 若用加减法 `a = a + b` 后 `b = a - b` 得 7、`a = a - b` 得 7，看似正确，但若题目要求按 32 位截断且 `a + b` 超过 `2**31 - 1`，中间值会被截断导致结果错 → 用异或，`7 ^ 7 = 0` 再还原仍得 7，不产生越界中间值。

## 如果面试官追问
问：若要求交换后数组元素类型为 64 位且禁止位运算怎么办？
答：用 `a, b = b, a` 元组解包，Python 底层用临时栈实现，语义上仍无显式临时变量。
