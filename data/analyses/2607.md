## 一句话思路
把下标按 `i % gcd(n,k)` 分成若干组，组内元素必须相等，各组取中位数即为最小代价。

## 怎么做
1. 令 `g = gcd(n, k)`，则下标 `i` 与 `i+k` 同组，组号就是 `i % g`，共 `g` 组。
2. 对每组收集 `arr[i], arr[i+g], arr[i+2g], ...` 的值。
3. 组内排序后取中位数 `mid`，累加 `abs(v - mid)`。
4. 返回总和。

以 `arr = [1,4,1,3], k = 2` 为例：`n=4, g=gcd(4,2)=2`。组 0 取下标 0、2 得 `[1,1]`，代价 0；组 1 取下标 1、3 得 `[4,3]`，排序后中位数取 3（或 4），代价 `abs(4-3)+abs(3-3)=1`。合计 1，与示例一致。

```python
from math import gcd

n = len(arr)
g = gcd(n, k)
ans = 0
for r in range(g):
    vals = sorted(arr[r::g])
    mid = vals[len(vals) // 2]
    ans += sum(abs(v - mid) for v in vals)
return ans
```

关键点：`arr[r::g]` 正好取出同组全部元素，因为同组下标差是 `g` 的倍数。

## 复杂度
时间：每组排序，总代价 `O(n log(n/g))`，最坏 `O(n log n)`。
空间：`arr[r::g]` 与 `sorted` 各开一份，额外 `O(n)`。

## 易错点
- `k` 与 `n` 不互素时（如 `n=4, k=2`），若只按 `i` 和 `i+k` 两两配对而不取 `gcd`，会把本应同组的 0、2 拆开，得到错误答案；正确做法是先算 `g = gcd(n, k)` 再按 `i % g` 分组。
- 组大小为偶数时，中位数取 `vals[len//2]` 即可，取任意中间值代价相同；若误取平均值再取整，遇到 `[1, 100]` 这类会算出 99 而非 99（此处相同），但遇到 `[1, 2, 100]` 取平均 34 得 133，取中位数 2 得 100，会偏大；正确做法是排序后取下标 `len//2` 的元素。

## 如果面试官追问
问：若要求输出最终数组而非最小次数？
答：每组把全部元素改成该组中位数，按下标 `r, r+g, ...` 回填即可，代价不变。
