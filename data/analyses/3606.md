## 一句话思路
逐项校验三个条件，把合法项按 (类别序号, code) 排序后取 code。

## 怎么做
1. 用字典把四个类别映射成序号 0~3，排序时直接当第一关键字。
2. 遍历下标 i，三个条件同时成立才收进结果。
3. 收集时存 `(order[businessLine[i]], code[i])` 元组，Python 元组比较天然先比序号再比字符串。
4. 排序后取每个元组的第二个元素。

以示例 1 为例：`code[1]=""` 长度 0 直接淘汰；`code[3]="SAVE@20"` 含 `@` 淘汰；剩下 `("pharmacy", "PHARMA5")` 和 `("restaurant", "SAVE20")`，序号 2 < 3，输出 `["PHARMA5","SAVE20"]`。

```python
order = {"electronics": 0, "grocery": 1, "pharmacy": 2, "restaurant": 3}
valid = set("abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789_")
res = []
for c, b, a in zip(code, businessLine, isActive):
    if not c or any(ch not in valid for ch in c):
        continue
    if b not in order or not a:
        continue
    res.append((order[b], c))
res.sort()
return [c for _, c in res]
```

## 复杂度
时间 O(n·L + n log n)，L 是 code 长度，排序贡献 log n。
空间 O(n)，res 存了至多 n 个元组。

## 易错点
- 空字符串 `""` → `all(ch in valid for ch in "")` 返回 True，会被误判为合法 → 必须先单独判 `not c`，再判字符集。
- 类别大小写或拼写偏差，如 `"Electronics"`、`"electronic"` → 用 `b not in order` 判会正确淘汰，但若写成 `b.lower() in order` 就会把非法类别放进来 → 严格按四个字面量匹配，不做归一化。

## 如果面试官追问
若 n 放大到 10^6 且要求流式输出？答：仍要全量排序，改用桶按类别分四组、组内各自排序，避免全局比较。
