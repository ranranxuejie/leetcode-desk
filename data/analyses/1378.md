## 一句话思路
以 Employees 为左表左连接 EmployeeUNI，因为要保留全部员工，没有 unique_id 的补 None。

## 怎么做
1. 把 Employees 当主表，`LEFT JOIN EmployeeUNI ON Employees.id = EmployeeUNI.id`。
2. 只选 `unique_id` 和 `name` 两列，顺序按输出要求。
3. 用 pandas 时把 `merge(how="left")` 的键对齐到 `id`，缺失自动成 `NaN`。

以官方示例走一遍：Employees 的 id 序列是 `[1, 7, 11, 90, 3]`，EmployeeUNI 只有 `{3:1, 11:2, 90:3}`。左连接后 id=1 和 id=7 在右表找不到匹配，`unique_id` 取 `NaN`；id=11 匹配到 2，id=90 匹配到 3，id=3 匹配到 1。最终 `unique_id` 列是 `[NaN, NaN, 2, 3, 1]`，与 `name` 列 `[Alice, Bob, Meir, Winston, Jonathan]` 一一对应。

```python
emp = employees[["id", "name"]]
uni = employee_uni[["id", "unique_id"]]
res = emp.merge(uni, on="id", how="left")
res = res[["unique_id", "name"]]
# NaN 在输出时即表现为 null
```

关键点：`how="left"` 保证 5 行员工一行不少；若误写 `how="inner"`，Alice 和 Bob 会被丢掉，只剩 3 行。

## 复杂度
时间：O(n + m)，n 为 Employees 行数、m 为 EmployeeUNI 行数，哈希连接各扫一遍。
空间：O(n + m)，连接结果表额外存放合并后的行。

## 易错点
1. 用 `how="inner"` 连接 → 输入官方示例时 Alice、Bob 两行消失，输出只剩 3 行 → 必须用 `how="left"`，以 Employees 为主表。
2. 连接键写成 `unique_id` 或 `name` → id=11 的 Meir 匹配不上，`unique_id` 全变 `NaN` → 两表共同键是 `id`，`on="id"` 不能改。

## 如果面试官追问
问：若 EmployeeUNI 同一 id 有多行怎么办？答：题设 `(id, unique_id)` 为主键，但 id 可重复，此时左连接会放大行数，需先按 id 聚合取 `min(unique_id)` 再连接。
