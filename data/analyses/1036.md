## 一句话思路
从 source 和 target 各做一次有界 BFS，步数上限取 `len(blocked)**2//2`，任一方被围死即 false。

## 怎么做
1. 把 `blocked` 转成 `set`，BFS 时用 `(x,y) in blocked_set` 判墙，避免每次线性扫描。
2. 关键观察：n 个障碍最多围出 `n*(n-1)/2` 个格子，所以 BFS 访问数超过这个上限就说明没被围住，直接返回 True。
3. 对 source 和 target 各跑一次 `bfs`，两次都返回 True 才整体 True；任一次返回 False 立即短路。

以示例 1 为例：`blocked={(0,1),(1,0)}`，`limit=2*1//2=1`。从 `(0,0)` 出发，邻居 `(1,0)`、`(0,1)` 都在墙里，队列空，`visited` 只有 1 个点，返回 False，直接得答案 false。

```python
def bfs(start):
    q, seen = [start], {tuple(start)}
    while q:
        x, y = q.pop()
        if len(seen) > limit:
            return True
        for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
            nx, ny = x+dx, y+dy
            if 0 <= nx < 10**6 and 0 <= ny < 10**6 \
               and (nx,ny) not in blocked_set and (nx,ny) not in seen:
                seen.add((nx,ny)); q.append((nx,ny))
    return tuple(target) in seen
```

`limit = len(blocked) * (len(blocked) - 1) // 2`，两次 `bfs` 用 `and` 连接。

## 复杂度
时间：O(n²)，n 为 `len(blocked)`，每次 BFS 最多访问 limit 个格子。
空间：O(n²)，`seen` 集合与队列最多存 limit 个坐标。

## 易错点
- `blocked=[]` 时 `limit=0`，若把判断写成 `len(seen) >= limit`，起点一入队就返回 True，看似对但逻辑错；应写 `>`，空障碍时靠 `target in seen` 兜底。
- source 与 target 被同一堵墙隔开但各自都没被围死（如示例 1 的变体：墙横在中间、两端通到边界外）→ 只跑一次 BFS 会误判 True；必须两次都跑，任一方 `False` 就返回 `False`。

## 如果面试官追问
问：若 blocked 规模涨到 10^5，还能这么做吗？
答：不能，limit 是 O(n²) 会爆；改用坐标压缩或按行扫描障碍的连通性判定。
