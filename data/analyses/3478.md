## 一句话思路
按 `nums1` 升序处理，用最小堆维护「已处理过的 `nums2` 中最大的 k 个」，堆和就是答案；同值时先算答案再入堆，保证严格小于。

## 怎么做
1. 把 `(nums1[i], nums2[i], i)` 按 `nums1` 升序排序，得到处理顺序。
2. 遍历排序后的三元组，先把当前堆和写入 `answer[i]`（此时堆里全是 `nums1` 更小的元素）。
3. 再把 `nums2[i]` 压入最小堆，堆超过 k 个就弹出堆顶，同时维护 `total`。
4. 关键：`nums1` 相等的元素必须「先全部算答案、再入堆」，否则同值会互相污染。

以示例 1 为例，排序后顺序是 `(1,30,2) (2,20,1) (3,50,4) (4,10,0) (5,40,3)`。处理到 `i=3`（`nums1=4`）时，堆里已有 `{30,20,50}`，`total=100`，超过 k=2 弹出 20，`total=80`，写入 `answer[3]=80`。

```python
order = sorted(range(n), key=lambda i: nums1[i])
heap, total, ans = [], 0, [0] * n
p = 0
while p < n:
    q = p
    while q < n and nums1[order[q]] == nums1[order[p]]:
        ans[order[q]] = total
        q += 1
    for t in range(p, q):
        v = nums2[order[t]]
        heappush(heap, v); total += v
        if len(heap) > k:
            total -= heappop(heap)
    p = q
```

## 复杂度
时间：排序 O(n log n)，每个元素进出堆各一次 O(n log k)，合计 O(n log n)。
空间：堆最多 k 个元素 O(k)，排序下标数组 O(n)。

## 易错点
- `nums1 = [2,2,2,2]` 时若边遍历边入堆，第二个 2 会看到第一个 2 的 `nums2` 值，输出非 0；正确做法是按值分组，同组先统一写 `ans` 再入堆。
- `k` 大于当前堆大小时（如 `i=1` 只有 1 个候选而 k=2），不要补 0 也不要报错，直接取 `total`；示例 1 的 `answer[1]=30` 就是「至多 k 个」而非「恰好 k 个」。

## 如果面试官追问
若要求输出具体选了哪些下标而不只是和？答：堆里存 `(nums2[j], j)` 二元组，弹出时按值比较，最后堆中下标即方案。
