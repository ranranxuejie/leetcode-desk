## 一句话思路
从两端贪心取最短的相等前后缀，每取到一对就计数加二，中间剩余部分自成一段。

## 怎么做
1. 用双指针 `i=0, j=n-1` 框住未处理区间，`ans=0` 记录已配对的段数。
2. 从长度 `L=1` 开始枚举前缀 `text[i:i+L]`，找到最小的 `L` 使它与后缀 `text[j-L+1:j+1]` 相等。
3. 找到就 `ans += 2`，`i += L`，`j -= L`，回到步骤 2；找不到（`L` 超过剩余长度一半）就跳出。
4. 若 `i <= j`，中间剩余部分单独成一段，`ans += 1`。

以 `text = "ghiabcdefhelloadamhelloabcdefghi"` 为例：`L=1` 时 `text[0]='g'` 与 `text[j]='i'` 不等，`L=2` 时 `"gh"` 与 `"hi"` 不等，`L=3` 时 `"ghi"` 与 `"ghi"` 相等，于是 `ans=2, i=3, j=len-4`。继续配对得到 `(abcdef)(hello)`，中间剩 `"adam"`，最终 `ans=7`。

```python
n = len(text)
i, j, ans = 0, n - 1, 0
while i <= j:
    L = 1
    while i + L - 1 < j - L + 1 and text[i:i+L] != text[j-L+1:j+1]:
        L += 1
    if i + L - 1 >= j - L + 1:
        break
    ans += 2
    i += L
    j -= L
if i <= j:
    ans += 1
return ans
```

贪心为什么成立：取最短的相等前后缀，剩下的中间部分仍可继续拆分，且不会比取更长前缀得到更少的段数。

## 复杂度
时间：最坏 O(n²)，每轮枚举 `L` 并做 O(L) 的切片比较，n 为 `len(text)`。
空间：O(n)，切片 `text[i:i+L]` 每次新建字符串。

## 易错点
- 输入 `"aaaa"` → 若贪心取 `L=2` 得 `(aa)(aa)` 只有 2 段 → 正确应取 `L=1` 得 `(a)(a)(a)(a)` 共 4 段，所以必须从 `L=1` 起枚举最短前缀。
- 输入 `"merchant"` → 若循环条件写成 `i < j` 且不处理剩余，会漏掉中间段 → 跳出后必须补 `if i <= j: ans += 1`，否则返回 0 而非 1。

## 如果面试官追问
若 n 扩大到 10⁵ 怎么优化？答：用滚动哈希把每次前后缀比较降到 O(1)，总时间 O(n log n) 或 O(n)。
