## 一句话思路
对答案秒数 `k` 二分，判定时用大根堆贪心决定哪些下标值得「重置为 0」而非逐次减 1。

## 怎么做
1. 二分 `k ∈ [1, m]`，判定 `check(k)` 是否能在前 `k` 秒标记全部 `n` 个下标。
2. 在 `[1, k]` 内对每个下标只保留**最后一次**出现的秒数 `last[i]`，其余出现秒数都是「可自由支配」的秒。
3. 从 `k` 倒序扫描：遇到 `last[i] == s` 时，把 `nums[i]` 压入大根堆（前提 `nums[i] > 0`，且堆非空时先弹出最大值比较，用重置更划算就替换）；否则 `free += 1`。
4. 扫描完后，堆里每个元素代表一次「重置为 0」操作，消耗 1 秒；剩余 `free` 秒要覆盖所有 `nums[i]` 的逐次减 1 总量加 `n` 次标记。

以示例 1 `nums=[3,2,3], changeIndices=[1,3,2,2,2,2,3]`、`k=6` 为例：`last = {1:1, 3:2, 2:6}`（下标 2 的最后出现是第 6 秒）。倒序扫到 s=6 时 `nums[2]=3` 入堆；s=2 时 `nums[3]=3` 入堆；s=1 时 `nums[1]=3` 入堆。`free=3`（第 3、4、5 秒），堆大小 3，重置消耗 3 秒，`free` 剩 0，而 `sum(nums)=8` 无法覆盖 → 但注意示例中实际是把三个都重置为 0，重置后无需再减，故判定条件应为：重置的下标不再计入 `sum`。

```python
import heapq
def check(k):
    last = {}
    for s in range(k):
        last[changeIndices[s]] = s
    heap, free = [], 0
    for s in range(k - 1, -1, -1):
        i = changeIndices[s]
        if last[i] == s and nums[i - 1] > 0:
            heapq.heappush(heap, -nums[i - 1])
            if len(heap) > free + 1:
                heapq.heappop(heap)
        else:
            free += 1
    need = sum(nums) - sum(-x for x in heap) + n
    return need <= free
```

## 复杂度
时间：二分 `log m` 次，每次 `O(k log k)`，堆操作贡献 `log n`。
空间：`last` 字典与堆各 `O(n)`。

## 易错点
- `nums[i] == 0` 的下标：若误入堆会白占一次重置秒数，正确做法是 `nums[i-1] > 0` 才压堆，0 直接靠「标记」那一秒解决。
- 堆容量控制：`len(heap) > free + 1` 时弹出，若写成 `>= free` 会漏掉最优重置，示例 1 的 `k=6` 会误判为不可行。

## 如果面试官追问
问：`nums[i]` 很大（如 1e9）时二分上界怎么定？答：上界仍是 `m`，因为每秒最多一次操作，`sum(nums)` 超过 `m` 时直接返回 -1，无需按数值二分。
