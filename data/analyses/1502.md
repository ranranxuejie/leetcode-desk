## 一句话思路
排序后相邻差必须全相等，因为等差数列重排后唯一形态就是单调序列（或反向），排序把候选顺序钉死。

## 怎么做
1. 对 `arr` 排序，得到唯一可能的相邻顺序。
2. 用前两项之差 `d = arr[1] - arr[0]` 作为基准公差。
3. 从下标 2 起逐个比较 `arr[i] - arr[i-1]` 是否等于 `d`，一旦不等立即返回 `False`。
4. 全部通过返回 `True`。

以 `arr = [3,5,1]` 为例：排序得 `[1,3,5]`，`d = 3 - 1 = 2`；检查 `i=2` 时 `5 - 3 = 2` 等于 `d`，返回 `True`。若换成 `[1,2,4]`，排序后 `d = 1`，而 `4 - 2 = 2 ≠ 1`，返回 `False`。

```python
arr.sort()
d = arr[1] - arr[0]
for i in range(2, len(arr)):
    if arr[i] - arr[i - 1] != d:
        return False
return True
```

关键点：`d` 只算一次，不要在每个循环里重算 `arr[i] - arr[i-1]` 再和「上一轮的差」比，那样多一个变量且容易在 `i=2` 时把 `d` 覆盖掉。长度 2 的数组循环体不执行，直接 `True`，符合「两项必成等差」。

## 复杂度
时间：排序 `O(n log n)` 主导，扫描 `O(n)`，合计 `O(n log n)`。
空间：排序额外 `O(log n)` 栈空间（TimSort），其余只用了 `d` 和循环变量。

## 易错点
- 输入含重复元素如 `[1,1,1]` 或 `[0,0,0,0]`：若先做 `set(arr)` 去重再判断，长度变成 1，会错判或数组越界访问 `arr[1]`；正确做法是不去重，`d = 0` 时逐项比较差是否为 0 即可。
- 输入 `[1,3,5,7,9]` 这类已经有序但公差为负的镜像如 `[9,7,5,3,1]`：若只判断「后一项减前一项恒为正」会错成 `False`；正确做法是排序后统一用升序差，或允许 `d` 为负但不额外加符号约束。

## 如果面试官追问
问：不排序能否 `O(n)` 做？答：可以，先求 `min` 和 `max`，公差 `d = (max - min) // (n - 1)`，要求整除且用集合验证每个 `min + k*d` 都出现，重复元素需额外计数。
