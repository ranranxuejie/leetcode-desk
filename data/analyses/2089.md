## 一句话思路
排序后 target 的所有下标必然是一段连续区间，用 `bisect_left/right` 直接定位区间端点。

## 怎么做
1. 对 `nums` 排序，得到非递减序列。
2. 用 `bisect_left(nums, target)` 求第一个等于 target 的下标 `lo`。
3. 用 `bisect_right(nums, target)` 求第一个大于 target 的下标 `hi`。
4. 返回 `list(range(lo, hi))`；若 `lo == hi` 自然得到空列表。

以 `nums = [1,2,5,2,3], target = 2` 为例：排序后 `nums = [1,2,2,3,5]`，`lo = 1`，`hi = 3`，返回 `[1,2]`。

```python
from bisect import bisect_left, bisect_right

nums.sort()
lo = bisect_left(nums, target)
hi = bisect_right(nums, target)
return list(range(lo, hi))
```

关键点：`bisect_right` 返回的是「第一个 > target 的位置」，不是「最后一个等于 target 的位置」，所以区间是左闭右开 `[lo, hi)`，直接 `range(lo, hi)` 即可，不需要 `hi - 1`。

## 复杂度
时间：排序 O(n log n) 主导，两次二分各 O(log n)。
空间：`list(range(lo, hi))` 存结果，最坏 O(n)；排序本身 O(log n) 栈。

## 易错点
- `nums` 全等于 target，如 `[2,2,2], target=2` → 若把 `hi` 当成「最后一个等于 target 的下标」再 `range(lo, hi)`，会漏掉末尾元素，返回 `[0,1]` 而非 `[0,1,2]`；正确做法是 `hi = bisect_right(...)` 后直接 `range(lo, hi)`。
- target 不存在，如 `nums=[1,2,5,2,3], target=4` → 若用 `nums.index(target)` 会抛 `ValueError`；正确做法是 `lo == hi` 时 `range` 为空，返回 `[]`，无需特判。

## 如果面试官追问
追问：不排序能否 O(n) 完成？答：可以，先数出小于 target 的个数 `c`，再扫一遍把等于 target 的原下标按出现顺序填到 `c, c+1, ...`，结果天然递增。
