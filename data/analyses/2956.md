## 一句话思路
把两个数组各转成 set，再各扫一遍原数组数「元素在对方 set 里」的下标个数。

## 怎么做
1. 先建 `s1 = set(nums1)`、`s2 = set(nums2)`，去重是为了让成员判断 O(1)。
2. 遍历 `nums1`，累加 `x in s2` 为真的次数，得 `answer1`。
3. 遍历 `nums2`，累加 `x in s1` 为真的次数，得 `answer2`。
4. 返回 `[answer1, answer2]`。

拿示例 1 走一遍：`nums1 = [2,3,2]`、`nums2 = [1,2]`，则 `s1 = {2,3}`、`s2 = {1,2}`。扫 `nums1` 时三个元素依次判 `2 in s2`（真）、`3 in s2`（假）、`2 in s2`（真），`answer1 = 2`；扫 `nums2` 时 `1 in s1` 假、`2 in s1` 真，`answer2 = 1`，输出 `[2,1]`。注意重复的 `2` 被数了两次，这正是题目要的「下标个数」而非「不同值个数」。

```python
s1, s2 = set(nums1), set(nums2)
answer1 = sum(1 for x in nums1 if x in s2)
answer2 = sum(1 for x in nums2 if x in s1)
return [answer1, answer2]
```

`sum(1 for ... if ...)` 等价于手写计数器，但少一个变量；若面试官偏好显式循环，写成 `cnt = 0` 再 `cnt += 1` 也一样。

## 复杂度
时间 O(n + m)：建两个 set 各 O(n)、O(m)，两次扫描各 O(n)、O(m)。
空间 O(n + m)：额外开了 `s1` 和 `s2` 两个 set。

## 易错点
- 把 `nums1 = [2,3,2]` 的 `answer1` 算成 1（以为数不同值）→ 漏掉重复下标 → 必须遍历原数组而不是遍历 set，`2` 出现两次就要计 2。
- 只建一个 set 就双向复用，例如拿 `s1` 去判 `nums2` 的元素却忘了 `nums2` 自身也要建 set → 示例 2 中 `nums2` 的 `2` 出现三次，若用 `nums2.count` 之类会退化到 O(nm) 且逻辑绕 → 老老实实两个 set 各管一边。

## 如果面试官追问
问：值域若放大到 10^9、数组长到 10^5 还这么做吗？
答：照样两个 set，哈希期望 O(1)，总时间仍是 O(n + m)，只是常数和内存变大。
