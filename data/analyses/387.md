## 一句话思路
先扫一遍用哈希表统计每个字符出现次数，再按原顺序找第一个计数为 1 的下标。

## 怎么做
1. 遍历 `s`，用 `Counter(s)` 或字典累加每个字符的出现次数。
2. 再遍历 `s` 的索引 `i` 和字符 `ch`，检查 `cnt[ch] == 1`。
3. 第一个满足条件的 `i` 直接返回，循环结束返回 `-1`。

以 `s = "loveleetcode"` 为例：统计后 `cnt` 中 `'l'` 出现 2 次、`'o'` 2 次、`'v'` 1 次、`'e'` 4 次……第二遍扫到 `i=0` 时 `cnt['l']=2` 跳过，`i=1` 时 `cnt['o']=2` 跳过，`i=2` 时 `cnt['v']=1`，返回 `2`。

```python
from collections import Counter

cnt = Counter(s)
for i, ch in enumerate(s):
    if cnt[ch] == 1:
        return i
return -1
```

关键点：第二遍必须按**原字符串顺序**扫，不能遍历 `cnt` 的键。字典/计数器的键顺序是首次出现顺序，对 `"leetcode"` 恰好也是 `l,e,t,c,o,d`，看起来对；但一旦有字符重复出现位置靠前，按键顺序就会给出错误下标。

## 复杂度
时间：O(n)，两遍扫描各 O(n)，n 为 `len(s)`。
空间：O(1)，字符集只有 26 个小写字母，计数器最多 26 个键。

## 易错点
- 输入 `s = "aabb"` → 若只统计不检查，或误把「出现次数最少」当答案，会返回某个下标而非 `-1`；正确做法是严格判断 `cnt[ch] == 1`，全不满足才返回 `-1`。
- 输入 `s = "leetcode"` → 若第二遍遍历 `cnt` 的键而非 `s` 的索引，返回的是字符而非索引，或顺序错乱；正确做法是 `for i, ch in enumerate(s)`，用原串位置定位。

## 如果面试官追问
问：若字符集扩大到全部 Unicode，空间复杂度怎么变？
答：计数器键数上界变成不同字符数 k，空间 O(k)，最坏 O(n)，时间仍是 O(n)。
