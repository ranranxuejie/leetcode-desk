## 一句话思路
先把 targetIntervals 合并成互不相交的连续段，再对每段用「当前覆盖右端点内、右端最远」的贪心跳跃。

## 怎么做
1. 把 targetIntervals 按左端点排序后合并，得到若干互不相交的段 `segs`，例如示例 1 合并成 `[1,5]、[7,8]、[10,15]`。
2. 把 availableIntervals 按左端点排序，指针 `i` 只前进不回退。
3. 对每个段 `[L,R]`，令 `cur=L`：在 `a[i][0] <= cur` 的区间里取最大右端 `best`；若 `best < cur` 说明断了，返回 -1；否则 `cur=best+1`、计数加一，直到 `cur > R`。
4. 关键中间值：示例 1 处理 `[1,5]` 时，`cur=1` 取到 `[1,7]` 的 `best=7`，一步覆盖整段；处理 `[10,15]` 时 `cur=10` 取到 `[10,15]` 的 `best=15`，共 3 个。

```python
segs = []
for l, r in sorted(targetIntervals):
    if segs and l <= segs[-1][1] + 1:
        segs[-1][1] = max(segs[-1][1], r)
    else:
        segs.append([l, r])
av = sorted(availableIntervals)
i = ans = 0
for L, R in segs:
    cur = L
    while cur <= R:
        best = cur - 1
        while i < len(av) and av[i][0] <= cur:
            best = max(best, av[i][1]); i += 1
        if best < cur:
            return -1
        cur = best + 1; ans += 1
```

## 复杂度
时间 O(n log n + m log m)，n、m 分别是两个数组长度，log 来自两次排序，扫描是线性的。
空间 O(m)，存合并后的 `segs`；排序本身另有 O(n) 栈开销。

## 易错点
- 合并条件写成 `l <= segs[-1][1]` 而非 `l <= segs[-1][1] + 1`：示例 3 的 `[1,2]`、`[3,4]` 会被当成两段，各自可覆盖，错误返回 2；实际 `[1,4]` 中间 2.5 无覆盖，应返回 -1。
- 内层 `while` 的 `i` 不跨段复用：若每段重置 `i=0`，示例 1 处理 `[10,15]` 时仍能扫到 `[1,7]`，`best` 被旧区间污染；正确做法是 `i` 全局单调前进，且只收 `av[i][0] <= cur` 的区间。

## 如果面试官追问
要求输出具体选了哪些区间？答：在 `best` 更新时记下对应下标，每段结束时把该下标加入结果列表即可。
