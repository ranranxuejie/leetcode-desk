## 一句话思路
用自增计数器当短码，配两张哈希表双向映射，encode 存、decode 查，O(1) 且天然无冲突。

## 怎么做
1. 维护 `self.id` 自增整数，`self.long2short`、`self.short2long` 两张字典。
2. `encode` 里先查 `long2short`，命中直接返回，保证同一 URL 多次加密得到同一短码。
3. 未命中则 `self.id += 1`，拼出 `short = "http://tinyurl.com/" + str(self.id)`，两张表各写一条。
4. `decode` 直接 `return self.short2long[shortUrl]`，题目保证短码来自本对象。

以官方示例为例：`longUrl = "https://leetcode.com/problems/design-tinyurl"`，首次 encode 后 `self.id` 从 0 变 1，`short` 为 `"http://tinyurl.com/1"`，`short2long["http://tinyurl.com/1"]` 存的是原长链；decode 拿这个短码查表即得原串。

```python
def encode(self, longUrl):
    if longUrl in self.long2short:
        return self.long2short[longUrl]
    self.id += 1
    short = "http://tinyurl.com/" + str(self.id)
    self.long2short[longUrl] = short
    self.short2long[short] = longUrl
    return short

def decode(self, shortUrl):
    return self.short2long[shortUrl]
```

关键点：短码只由 `self.id` 决定，与 URL 内容无关，所以不需要哈希函数也不会碰撞；`long2short` 的存在是为了幂等，不是解密必需。

## 复杂度
时间：encode 平均 O(1)（字典查找 + 一次整数转字符串），decode O(1)。
空间：O(k)，k 为不同长链个数，两张表各存 k 条，长链本身占 O(url 长度)。

## 易错点
- 同一 `longUrl` 连续 encode 两次 → 若不加 `long2short` 查表，会生成 `.../1` 和 `.../2` 两个短码，虽然 decode 都能还原，但违背「一个 URL 对应一个 TinyURL」的语义，且浪费 id；正确做法是先查 `long2short` 再自增。
- 短码前缀与长链前缀混淆 → 若把 `short = str(self.id)` 直接当短码返回，decode 时传入的 `"http://tinyurl.com/1"` 在 `short2long` 里查不到，抛 KeyError；正确做法是 encode 和 decode 用完全相同的拼接规则生成 key。

## 如果面试官追问
问：若要求短码长度固定为 6 位且不可预测，怎么改？
答：把 `self.id` 换成 `secrets.token_urlsafe(6)` 或对 id 做 base62 加盐，仍用两张表映射，冲突时重抽。
