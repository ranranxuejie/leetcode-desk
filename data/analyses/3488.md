## 一句话思路
按值分组存下标，每组内相邻下标距离取环上最小，查询时二分定位。

## 怎么做
1. 一次遍历 `nums`，用字典 `pos` 把每个值出现的下标按升序收集成列表。
2. 对每个列表 `idx`，若长度 ≥ 2，对每个位置 `k` 计算它与前后邻居的环距离，取最小值存进 `best[值]`。
3. 查询时直接查 `best.get(nums[q], -1)`。

关键中间值：示例 1 中 `pos[1] = [0,2,4]`。对 `k=0`，前驱是 `4`，环距离 `min(4-0, 7-(4-0)) = min(4,3) = 3`；后继是 `2`，距离 `2`。取小得 `best[1] = 2`。对 `k=2`，前驱 `0` 距离 `2`，后继 `4` 距离 `2`，仍为 `2`。`pos[3] = [1,5]`，`k=1` 时前驱 `5`，环距离 `min(4, 7-4) = 3`，所以 `best[3] = 3`，正好对应查询 `5` 的答案。

```python
from collections import defaultdict
pos = defaultdict(list)
for i, v in enumerate(nums):
    pos[v].append(i)
n = len(nums)
best = {}
for v, idx in pos.items():
    if len(idx) < 2:
        continue
    m = len(idx)
    res = n
    for k in range(m):
        prev = idx[k - 1]
        nxt = idx[(k + 1) % m]
        d1 = (idx[k] - prev) % n
        d2 = (nxt - idx[k]) % n
        res = min(res, d1, d2)
    best[v] = res
return [best.get(nums[q], -1) for q in queries]
```

## 复杂度
时间：O(n + q)，建表 O(n)，每个下标只被前后各看一次，查询 O(1)。
空间：O(n)，`pos` 存全部下标，`best` 最多 n 个键。

## 易错点
- 只有一个下标的组（如示例 1 的 `4` 和 `2`）→ 若漏判 `len(idx) < 2`，`k-1` 和 `k+1` 会绕回自己，算出距离 0 → 必须先跳过，返回 -1。
- 环距离直接用 `idx[k] - prev` → 对 `pos[1]=[0,2,4]` 的 `k=0` 会得 4 而非 3 → 必须 `% n` 取环上短边，`(idx[k] - prev) % n` 与 `(nxt - idx[k]) % n` 都要算。

## 如果面试官追问
若要求返回最近的那个下标而不只是距离？答：`best` 里同时存 `(距离, 下标)`，比较时用元组取小即可，逻辑不变。
