## 一句话思路
用一个 `cached` 变量提前存下 `next()` 取出的值，`peek()` 只读缓存不推进底层迭代器。

## 怎么做
1. 构造时把底层迭代器存为 `self.it`，缓存 `self.cached = None`。
2. `peek()` 时若 `cached is None`，就调 `self.it.next()` 存入 `cached`，再返回它。
3. `next()` 时若 `cached` 有值，取出并清空缓存；否则直接调 `self.it.next()`。
4. `hasNext()` 判断 `cached is not None or self.it.hasNext()`。

以 `[1,2,3]` 为例：`next()` 时缓存为空，直接取底层得 1；`peek()` 时缓存为空，调底层 `next()` 得 2 存入 `cached`，底层指针已到 3 前；再 `next()` 命中缓存返回 2 并清空，底层指针不动。

```python
def peek(self):
    if self.cached is None:
        self.cached = self.it.next()
    return self.cached

def next(self):
    if self.cached is not None:
        val, self.cached = self.cached, None
        return val
    return self.it.next()

def hasNext(self):
    return self.cached is not None or self.it.hasNext()
```

关键点：`peek()` 的「不移动指针」是靠把底层已经前进的那一步记在 `cached` 里抵消掉的，所以 `next()` 必须先查缓存。

## 复杂度
时间：每次操作 O(1)，每个元素最多被底层 `next()` 取一次。
空间：O(1)，只多开一个 `cached` 变量。

## 易错点
- 输入 `[1,2,3]` 连续调 `peek()` 两次 → 若每次都调 `self.it.next()` 覆盖缓存，第二次会返回 3 而不是 2 → 正确做法是 `if self.cached is None` 才取，已有缓存直接返回。
- 输入 `[1,2,3]` 先 `peek()` 再 `next()` → 若 `next()` 不查缓存直接调底层，会跳过 2 返回 3 → 正确做法是 `next()` 优先消费 `cached` 并置回 `None`。
- 输入只剩最后一个元素时 `hasNext()` → 若只看 `self.it.hasNext()`，缓存里还压着元素会误报 `False` → 正确做法是 `cached is not None or self.it.hasNext()`。

## 如果面试官追问
问：怎么让它支持任意类型而非 int？
答：缓存变量不设类型注解、不参与运算，逻辑与类型无关，Python 里天然通用；强类型语言用泛型 `T` 即可。
