## 一句话思路
按 limit 升序逐个激活，用最小堆维护当前活跃元素的 value，活跃数超过 `limit[i]` 时弹出最小值——因为被挤掉的元素之后必然失效，留大的。

## 怎么做
1. 把 `(limit[i], value[i])` 按 limit 升序排序，保证激活时活跃上限单调不减。
2. 遍历排序后的对，把 `v` 压入最小堆，堆大小即当前活跃数。
3. 若堆大小 > 当前 `lim`，弹出堆顶最小值——它已无法再贡献，且被挤掉不影响后续。
4. 累加每次压入的 `v`，最后减去所有弹出值，或直接维护总和。

以示例 1 为例：排序后为 `(1,5),(2,3),(3,8)`。压 5，堆 `[5]`，大小 1 ≤ 1；压 3，堆 `[3,5]`，大小 2 ≤ 2；压 8，堆 `[3,5,8]`，大小 3 ≤ 3。总和 16，无弹出。

```python
pairs = sorted(zip(limit, value))
heap, total = [], 0
for lim, v in pairs:
    heapq.heappush(heap, v)
    total += v
    if len(heap) > lim:
        total -= heapq.heappop(heap)
return total
```

关键中间值：示例 3 排序后 `(2,5),(3,4),(3,1),(3,2)`。压 5 堆 `[5]`；压 4 堆 `[4,5]` 大小 2 ≤ 3；压 1 堆 `[1,4,5]`；压 2 堆 `[1,2,4,5]` 大小 4 > 3，弹出 1，总和 12。

## 复杂度
时间：排序 O(n log n)，堆操作共 O(n log n)，n 为数组长度。
空间：堆最多 n 个元素，O(n) 额外空间。

## 易错点
- 输入 `limit = [1,1,1], value = [4,2,6]`：若按原顺序激活，先激活 4 后活跃数变 1，触发 `limit[j] <= 1` 全部失效，总和只有 4。正确做法是先激活 value 最大的 6，得 6。
- 输入 `value = [3,5,8], limit = [2,1,3]`：若按 limit 降序处理，先激活 limit=3 的 8，活跃数 1，再激活 limit=2 的 3 时活跃数 2 不满足严格小于 2，会漏掉 3。必须升序，让上限逐步放宽。

## 如果面试官追问
要求输出具体激活顺序怎么办？答：堆中保留 `(value, index)`，弹出时记录被淘汰的 index，最终堆内元素按 limit 升序即为激活序列。
