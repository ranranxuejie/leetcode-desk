## 一句话思路
用正则 `REGEXP` 一次性匹配四段结构，比拆 `SUBSTRING_INDEX` 再逐段校验更短且不易漏条件。

## 怎么做
1. 把邮箱拆成 `^本地@域名\.com$` 四段，用 `REGEXP` 整体匹配，避免多次 `LIKE` 拼接。
2. 本地段写 `[A-Za-z0-9_]+`，域名段写 `[A-Za-z]+`，`@` 和 `.com` 用字面量转义。
3. 用 `BINARY` 或默认大小写不敏感需确认：MySQL 默认 `REGEXP` 不区分大小写，`[A-Za-z]` 已覆盖两种。
4. 最后 `ORDER BY user_id`。

以 `alice@example.com` 为例：`^[A-Za-z0-9_]+@[A-Za-z]+\.com$` 匹配成功；`bob_at_example.com` 因无 `@` 失败；`charlie@example.net` 因结尾非 `.com` 失败。

```python
# 伪 SQL，实际提交为 MySQL
SELECT user_id, email
FROM Users
WHERE email REGEXP '^[A-Za-z0-9_]+@[A-Za-z]+\\.com$'
ORDER BY user_id;
```

若用 Python 模拟校验：
```python
import re
pat = re.compile(r'^[A-Za-z0-9_]+@[A-Za-z]+\.com$')
valid = [row for row in rows if pat.match(row.email)]
valid.sort(key=lambda r: r.user_id)
```

关键中间值：对 `david@domain.com`，`pat.match` 返回匹配对象，`group(0)` 为整串；对 `eve@invalid` 返回 `None`。

## 复杂度
时间：O(n·m)，n 为行数，m 为邮箱平均长度，正则逐字符扫描。
空间：O(1) 额外空间（SQL 侧），Python 模拟需 O(k) 存结果，k 为合法行数。

## 易错点
- `bob_at_example.com` 含下划线但无 `@` → 若只写 `LIKE '%@%.com'` 会漏掉本地段字符集校验，误判为合法 → 必须显式限定 `@` 前为 `[A-Za-z0-9_]+`。
- `alice@exa_mple.com` 域名含下划线 → 若域名段写成 `[A-Za-z0-9_]+` 会误收 → 域名段只能是 `[A-Za-z]+`，且 `.com` 前至少一个字母。

## 如果面试官追问
问：若要求域名支持多级如 `mail.example.com` 怎么改？
答：域名段改为 `[A-Za-z]+(\.[A-Za-z]+)*\.com`，仍保证 `.com` 结尾且各级仅字母。
