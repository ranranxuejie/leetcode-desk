## 一句话思路
从左到右贪心：只要 `flowerbed[i]==0` 且左右邻居都不是 1，就种下并计数，因为越早种越不会挤占后面的空位。

## 怎么做
1. 遍历 `i` 从 0 到 `len(flowerbed)-1`，跳过已经是 1 的地块。
2. 用 `(i == 0 or flowerbed[i-1] == 0) and (i == len-1 or flowerbed[i+1] == 0)` 判断能否种，边界外视为空。
3. 能种就把 `flowerbed[i]` 置 1、`n -= 1`，`n <= 0` 时提前返回 `True`。
4. 遍历结束返回 `n <= 0`。

以 `flowerbed = [1,0,0,0,1], n = 2` 为例：`i=1` 时左邻是 1，跳过；`i=2` 时左右都是 0，种下，`flowerbed` 变成 `[1,0,1,0,1]`，`n` 变 1；`i=3` 时左邻已是 1，跳过。最终 `n=1 > 0`，返回 `False`。

```python
i = 0
while i < len(flowerbed):
    if flowerbed[i] == 0 \
       and (i == 0 or flowerbed[i-1] == 0) \
       and (i == len(flowerbed)-1 or flowerbed[i+1] == 0):
        flowerbed[i] = 1
        n -= 1
        if n <= 0:
            return True
        i += 2          # 种下后下一格必不能种，直接跳
    else:
        i += 1
return n <= 0
```

## 复杂度
时间：O(len(flowerbed))，每个下标最多访问一次，`n` 只影响提前返回。
空间：O(1)，只改了原数组的若干位，没有额外容器。

## 易错点
- 输入 `flowerbed = [0], n = 1` → 若判断邻居时直接写 `flowerbed[i-1]` 和 `flowerbed[i+1]`，会越界或误用 Python 负索引把 `flowerbed[-1]` 当成 0 而错判 → 必须先判 `i == 0` / `i == len-1` 再取邻居。
- 输入 `flowerbed = [1,0,0,0,1], n = 2` → 若种下后仍 `i += 1`，会在刚种的位置右边再判一次，虽然邻居是 1 不会真种，但若写成先置 1 再回看容易把计数逻辑绕乱 → 种下后直接 `i += 2`，跳过必然冲突的下一格。

## 如果面试官追问
问：要求返回具体种植方案而不是布尔值？答：把每次置 1 的下标 `i` 追加进列表返回即可，贪心顺序不变，仍是 O(len(flowerbed))。
