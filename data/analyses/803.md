## 一句话思路
正着删砖块会连锁掉落，难维护；倒着来，用并查集把砖块一块块加回去，每次加回时统计与顶部连通块合并了多少块。

## 怎么做
1. 先把所有 `hits` 位置上的砖块从 `grid` 里抹成 0，得到「删完所有 hits 之后」的网格。
2. 建一个虚拟顶部节点 `TOP = m*n`，把所有 `grid[0][j] == 1` 的砖块与 `TOP` 合并，再对剩余砖块做四邻合并。
3. 倒序遍历 `hits`：若该位置原本是 0（`grid[r][c] == 0`），答案记 0；否则先记下 `TOP` 所在连通块大小 `before`，把 `(r,c)` 恢复为 1 并与四邻及 `TOP` 合并，`after - before - 1` 就是这次掉落的砖块数。
4. 把结果数组反转输出。

以示例 1 为例：`grid = [[1,0,0,0],[1,1,1,0]]`，`hits = [[1,0]]`。抹掉后 `grid[1][0] = 0`，此时与 `TOP` 连通的只有 `(0,0)`，`before = 1`。恢复 `(1,0)` 后它连上 `(0,0)`，同时把 `(1,1)`、`(1,2)` 也拉进来，`after = 4`，`4 - 1 - 1 = 2`，正是答案。

```python
parent = list(range(m * n + 1))
size = [1] * (m * n + 1)
TOP = m * n

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return
    if size[ra] < size[rb]:
        ra, rb = rb, ra
    parent[rb] = ra
    size[ra] += size[rb]
```

## 复杂度
时间：O(m·n·α + len(hits)·α)，并查集近似常数，网格初始化占主导。
空间：O(m·n)，`parent`、`size` 各开 m·n+1 个槽位。

## 易错点
- `hits` 里可能指向空白格，如 `grid[1][1] = 0` 时被 hit。若倒序时不判断 `grid[r][c] == 0` 就直接恢复成 1，会凭空多出一块砖，答案偏大。正确做法是先判 0 则答案记 0 并跳过。
- 统计掉落数时容易写成 `after - before`，把被恢复的那块砖本身也算进掉落。示例 1 中 `after = 4`、`before = 1`，直接相减得 3，正确是 `4 - 1 - 1 = 2`，必须减掉恢复的这块。

## 如果面试官追问
问：若 hits 长度达到 4*10^4 且 m·n 也很大，并查集还够用吗？
答：够，路径压缩加按大小合并后单次操作近似 O(1)，总代价由 m·n 决定，与 hits 长度线性相关。
