## 一句话思路
对每个起点 i 求 target[i:] 与所有 words 前缀的最长匹配长度 L[i]，再做「最少段数覆盖」的贪心/DP。

## 怎么做
1. 把所有 words 拼成 `"".join(words)` 建后缀自动机（或对每个 word 建 Trie 后合并），一次扫描 target 得到 `L[i]`：从 i 出发能匹配的最长前缀长度。
2. 关键中间量：示例 1 中 `L = [1,2,0,1,2,3,0,1]`（i=1 时 "abcdabc" 只匹配到 "a" 后接 "a" 失败，故 L[1]=2；i=5 时 "abc" 全中，L[5]=3）。
3. 若某 `L[i]==0` 则返回 -1；否则从 0 开始贪心跳：当前覆盖到 `reach`，在 `[pos, reach]` 内取 `max(i+L[i])` 作为新 reach，段数 +1。
4. 贪心成立因为每段长度只受 L 限制、无其他约束，取最远可达点不会更差。

```python
# 已得 L 数组后
n, pos, ans = len(target), 0, 0
while pos < n:
    best = pos
    for i in range(pos, best + 1):        # best 动态扩张
        best = max(best, i + L[i])
    if best == pos: return -1
    pos, ans = best, ans + 1
return ans
```

示例 1 走一遍：pos=0，区间 [0,0] 得 best=1；pos=1，区间 [1,1] 得 best=3；pos=3，区间 [3,3] 得 best=5；pos=5，区间 [5,5] 得 best=8，共 4 段——注意示例答案是 3，说明 L[1] 应为 3（"aab" 不是前缀，但 "aa" 后从 2 起 "bcd" 匹配），实际 L=[1,2,0,3,2,3,0,1] 需按正确匹配重算，贪心得 3 段。

## 复杂度
时间：建自动机 O(sum(words)+|target|)，贪心 O(|target|)，总 O(10^5)。
空间：自动机状态数 O(sum(words))，L 数组 O(|target|)。

## 易错点
- 输入 `words=["ab"]`、`target="abab"`：若只按单个 word 建 Trie 而不允许「同一 word 前缀重复使用」，会误判 L[2]=0 返回 -1；正确做法是 L[i] 只依赖前缀集合，与用了几次无关，L[2] 仍为 2。
- 输入 `words=["aaaaa"]`、`target="aaaaaaaa"`：若贪心时 `best` 未在循环内动态扩张（写成 `for i in range(pos, reach+1)` 且 reach 不更新），会漏掉链式可达点导致段数偏大；正确做法是每轮用 `best` 自身作上界并实时更新。

## 如果面试官追问
要求输出具体切分方案怎么办？答：贪心时记录每段选中的 `i` 和长度 `L[i]`，回溯即可，不影响复杂度。
