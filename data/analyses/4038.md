## 一句话思路
用哈希表记录每个值第一次和最后一次出现的下标，若 `last - first + 1` 等于该值出现次数，则它连续。

## 怎么做
1. 遍历 `nums`，用字典 `first` 记每个值首次出现的下标，用 `cnt` 记出现次数。
2. 再遍历一次（或边遍历边更新）记录每个值的最后下标 `last`。
3. 对每个值判断 `last[x] - first[x] + 1 == cnt[x]`，成立则计数加一。

以 `nums = [3,3,1,2,2,1]` 为例：`3` 的 `first=0, last=1, cnt=2`，`1-0+1=2` 成立，算特殊；`1` 的 `first=2, last=5, cnt=2`，`5-2+1=4 != 2`，不算；`2` 的 `first=3, last=4, cnt=2`，`4-3+1=2` 成立。结果 2。

```python
first, last, cnt = {}, {}, {}
for i, x in enumerate(nums):
    if x not in first:
        first[x] = i
    last[x] = i
    cnt[x] = cnt.get(x, 0) + 1
ans = 0
for x in first:
    if last[x] - first[x] + 1 == cnt[x]:
        ans += 1
```

关键点：区间长度必须恰好等于出现次数，因为区间内每个位置都被这个值占满，中间不能夹别的值。

## 复杂度
时间 O(n)：一次遍历建表，一次遍历判定，n 为 `nums` 长度。
空间 O(k)：k 为不同值的个数，开了 `first`/`last`/`cnt` 三个字典。

## 易错点
- 输入 `[1,2,2,1]`：若只比较 `first[1]=0` 和 `last[1]=3` 就认为 1 连续，会错算成 2；正确做法是加上 `cnt` 校验，`3-0+1=4 != 2`，排除 1。
- 输入 `[5]`：若把「出现次数为 1」直接判为特殊而漏掉下标校验，逻辑上碰巧对，但若代码写成 `last - first == cnt`（少加 1），单元素会得 `0 == 1` 判错；正确写法是 `last - first + 1 == cnt`。

## 如果面试官追问
若 `nums` 长度升到 10^7 且值域很大，怎么省空间？答：只用一个字典存 `(first, last, cnt)` 三元组，边遍历边更新，判定放到最后统一做。
