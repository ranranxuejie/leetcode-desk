## 一句话思路
排序后最大乘积只可能是「最大三个数之积」或「最小两个负数乘最大数」，取二者较大值。

## 怎么做
1. 对 `nums` 升序排序，负数全挤到左边、正数在右边。
2. 算候选一 `nums[-1] * nums[-2] * nums[-3]`（最大的三个数）。
3. 算候选二 `nums[0] * nums[1] * nums[-1]`（两个最小数配最大数）。
4. 返回两者较大值。

拿 `nums = [1,2,3,4]` 走一遍：排序后仍是 `[1,2,3,4]`，候选一 `4*3*2 = 24`，候选二 `1*2*4 = 8`，`max(24, 8) = 24`，与示例一致。再拿 `[-1,-2,-3]`：候选一 `(-3)*(-2)*(-1) = -6`，候选二 `(-1)*(-2)*(-3) = -6`，两者相等，返回 `-6`，也符合。

```python
def maximumProduct(nums):
    nums.sort()
    a = nums[-1] * nums[-2] * nums[-3]
    b = nums[0] * nums[1] * nums[-1]
    return max(a, b)
```

关键点在于候选二：当数组里有两个以上负数时，两个最小负数相乘得正，再乘最大正数，可能反超「三个最大数」。例如 `[-100,-98,1,2,3]`，候选一 `3*2*1 = 6`，候选二 `(-100)*(-98)*3 = 29400`，答案取 29400。若数组全负，如 `[-5,-4,-3,-2]`，候选一 `(-2)*(-3)*(-4) = -24`，候选二 `(-5)*(-4)*(-2) = -40`，取 `-24`，即「最接近零的三个负数」，排序后正好是最大的三个。

## 复杂度
时间：排序 `O(n log n)`，n 是 `nums` 长度，比较是常数次。
空间：`O(1)` 额外（不计排序内部栈），未开新数组。

## 易错点
- 输入 `[-100,-98,1,2,3]` → 只算最大三个数得 `6`，漏掉 `29400` → 必须同时算 `nums[0]*nums[1]*nums[-1]` 再取 max。
- 输入全负如 `[-5,-4,-3,-2]` → 误以为「两个最小负数配最大数」一定更大，得 `-40` → 实际 `-24` 更大，靠 `max` 兜住，别手写 if 只判一种情况。

## 如果面试官追问
问：不排序、要求 `O(n)` 怎么做？
答：一趟扫描同时维护最大的三个数和最小的两个数，最后同样取 `max(max1*max2*max3, min1*min2*max1)`。
