## 一句话思路
先花最小能量拿 1 分，再把除最小值外的敌人全部「卖」成能量，最后用总能量除以最小值。

## 怎么做
1. 若 `currentEnergy < min(enemyEnergies)`，一分都拿不到，直接返回 0。
2. 先对最小值那个敌人做一次操作一，`currentEnergy -= mn`，`points = 1`。
3. 把其余所有敌人（含最小值本身，因为它已被标记、不能再卖，但它的能量已在第 2 步花掉）的能量全部通过操作二收进来：`currentEnergy += sum(enemyEnergies) - mn`。
4. 之后反复对最小值做操作一，得分 `points += currentEnergy // mn`。

以 `enemyEnergies = [3,2,2], currentEnergy = 2` 为例：`mn = 2`，第 2 步后 `currentEnergy = 0, points = 1`；第 3 步收进 `3+2 = 5`，`currentEnergy = 5`；第 4 步 `5 // 2 = 2`，总分 `1 + 2 = 3`。

```python
mn = min(enemyEnergies)
if currentEnergy < mn:
    return 0
cur = currentEnergy - mn + (sum(enemyEnergies) - mn)
return 1 + cur // mn
```

关键点：卖敌人时不能卖最小值那个（它已被标记），所以收进的是 `sum - mn`；而最小值本身的能量在第 2 步已经花掉，两边不重不漏。

## 复杂度
时间 O(n)：一次 `min` 加一次 `sum` 扫两遍数组。
空间 O(1)：只存 `mn`、`cur` 两个标量。

## 易错点
- `currentEnergy < mn` 时（如 `enemyEnergies=[5], currentEnergy=3`）→ 若仍走第 2 步会得到负能量、算出错误正分 → 必须先判 `currentEnergy < mn` 返回 0。
- 第 3 步写成 `sum(enemyEnergies)` 而非 `sum - mn` → 如 `[3,2,2]` 会多算 2 点能量，答案变 4 → 最小值已被标记，只能收 `sum - mn`。

## 如果面试官追问
要求输出具体操作序列怎么办？答：先记录对最小值的一次操作一，再依次对每个非最小值下标做操作二，最后循环对最小值做操作一，按此顺序打印即可。
