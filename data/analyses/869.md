## 一句话思路
把 n 的数字排序成签名串，与 2^0…2^30 各自的签名串比对，相等即成立。

## 怎么做
1. 把 n 转成字符串后排序，得到签名 `sig`，例如 n=10 得 `"01"`。
2. 枚举 2 的幂 `p = 1, 2, 4, ...`，直到 `p > 10**9`（即 p 最多 30 位二进制，共 30 个候选）。
3. 每个 p 同样转字符串排序，与 `sig` 比较，命中就返回 `True`。
4. 全部枚举完没命中返回 `False`。

关键中间值：n=10 时 `sig = "01"`；枚举到 p=1 得 `"1"`、p=2 得 `"2"`……p=1024 得 `"0124"`，长度和内容都对不上 `"01"`，故返回 `False`。而 n=1 时 `sig = "1"`，p=1 的签名也是 `"1"`，直接命中。

```python
sig = ''.join(sorted(str(n)))
p = 1
while p <= 10**9:
    if ''.join(sorted(str(p))) == sig:
        return True
    p *= 2
return False
```

注意 `p <= 10**9` 这个上界：n 最大 10^9（10 位），而 2^30 = 1073741824 已超过 10^9，所以循环到 2^29 就够，不会漏掉位数相同的候选。

## 复杂度
时间：O(log n × d log d)，d ≤ 10 为位数，枚举约 30 个 2 的幂，每个排序常数级。
空间：O(d)，只存两个长度 ≤10 的签名串，无额外哈希表。

## 易错点
- 输入 n=10 → 若只比较数字多重集合而忽略前导零，会误判 `"01"` 能排成 `"10"`？实际 10 不是 2 的幂，正确做法是排序签名严格相等比较，`"01"` 与任何 2 的幂签名都不等，返回 `False`。
- 输入 n=1000000000（10 位）→ 若枚举上界写成 `p < 10**9` 会漏掉 2^29=536870912 之后的候选，虽然本题该值签名不匹配，但上界必须覆盖到 `p <= 10**9` 才能保证不漏；正确做法是循环条件写 `p <= 10**9`。

## 如果面试官追问
若 n 上限放大到 10^18，签名长度变 19 位，枚举 2 的幂到 2^59，仍只需约 60 次排序比较，方法不变。
