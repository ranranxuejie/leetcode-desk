## 一句话思路
用哈希表记每个任务类型上次完成的天数，逐任务推进当前天数，撞冷却就跳到解冻日。

## 怎么做
1. 维护 `day`（当前已用天数）和 `last`（类型 → 上次完成的天数）。
2. 遍历 `tasks`，每个任务先 `day += 1`，表示今天干活。
3. 若该类型在 `last` 里且 `day - last[t] <= space`，说明冷却没走完，把 `day` 直接推到 `last[t] + space + 1`。
4. 更新 `last[t] = day`，遍历结束返回 `day`。

拿示例 1 `tasks = [1,2,1,2,3,1], space = 3` 走一遍关键处：处理到下标 2 的 `1` 时，`day` 从 2 加到 3，而 `last[1] = 1`，`3 - 1 = 2 <= 3`，冷却不足，`day` 被推到 `1 + 3 + 1 = 5`；同理下标 5 的 `1` 会从 6 推到 9，最终答案 9。

```python
last = {}
day = 0
for t in tasks:
    day += 1
    if t in last and day - last[t] <= space:
        day = last[t] + space + 1
    last[t] = day
return day
```

注意 `day` 是「第几天完成」，从 1 开始计；`last[t] + space + 1` 里的 `+1` 是因为间隔 `space` 天意味着两次完成日之差至少 `space + 1`。

## 复杂度
时间 O(n)：`tasks` 长度 n，每个元素 O(1) 哈希操作。
空间 O(m)：`last` 存不同任务类型数 m，最坏 m = n。

## 易错点
- 把间隔条件写成 `day - last[t] < space`：示例 1 中下标 2 的 `1` 在 `day = 3` 时 `3 - 1 = 2 < 3` 成立会被推，但若 `space = 2`、`day - last[t] = 2` 时不该推却推了，答案偏大。正确是 `<= space` 才推。
- 推完 `day` 后忘记用新 `day` 更新 `last[t]`：示例 1 下标 2 若仍记 `last[1] = 3` 而非 5，后面下标 5 的 `1` 会算错解冻日，答案偏小。必须先推 `day` 再写 `last[t] = day`。

## 如果面试官追问
要求输出具体每天干什么（任务或休息）？答：在推 `day` 时把 `last[t]+1` 到 `day-1` 记为空闲日，其余记任务下标即可。
