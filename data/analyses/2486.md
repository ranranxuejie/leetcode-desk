## 一句话思路
双指针在 s 上贪心匹配 t 的前缀，匹配到哪停，剩下的 t 后缀长度就是答案。

## 怎么做
1. 指针 `j` 指向 t 的开头，遍历 s 的每个字符 `c`。
2. 若 `c == t[j]`，则 `j += 1`，表示 t 的这一位已在 s 里找到。
3. 遍历结束（或 `j == len(t)`）后，返回 `len(t) - j`。

以 `s = "coaching", t = "coding"` 为例：s 的 `c` 匹配 t[0]='c'，`o` 匹配 t[1]='o'，`a` 不匹配 t[2]='d' 跳过，`c` 不匹配 'd' 跳过，`h`、`i` 跳过，`n` 匹配 t[2]='d'？不匹配——实际 s 中 `n` 对应 t[2]='d' 失败，`g` 也失败，最终 `j = 2`，返回 `6 - 2 = 4`。剩下的 `"ding"` 正是要追加的部分。

```python
j = 0
for c in s:
    if j < len(t) and c == t[j]:
        j += 1
return len(t) - j
```

关键点：追加的字符只能放在 s 末尾，所以 s 中能匹配的必须是 t 的一个**前缀**，不能跳着匹配后面的字符。贪心匹配前缀是最优的——多匹配一个就少追加一个。

## 复杂度
时间 O(len(s) + len(t))，遍历 s 一次，`j` 最多走到 len(t)。
空间 O(1)，只用了 `j` 一个变量。

## 易错点
- 输入 `s = "abcde", t = "a"` → 若写成「统计 t 中不在 s 里的字符数」会得 0 但逻辑错，比如 `s = "ba", t = "ab"` 会误判 0；正确做法是按顺序匹配前缀，`s="ba"` 时 `b` 匹配 t[0]='a' 失败，`a` 匹配成功，`j=1`，返回 1。
- 输入 `s = "z", t = "abcde"` → 若在循环里不检查 `j < len(t)`，当 `j` 走到 len(t) 后继续访问 `t[j]` 会 IndexError；正确做法是加 `j < len(t)` 短路，或匹配完直接 break。

## 如果面试官追问
问：如果允许在 s 的任意位置插入字符（不只在末尾）呢？
答：那就变成求 t 与 s 的最长公共子序列长度 L，答案是 `len(t) - L`，需 O(len(s)·len(t)) 的 DP。
