## 一句话思路
区间 DP：把 cuts 排序后加哨兵 0 和 n，枚举区间内「最后切的那一刀」求最小。

## 怎么做
1. 排序 cuts，前后补 0 和 n，得到 `pos = [0,1,3,4,5,7]`（示例 1），共 m=6 个点。
2. 定义 `dp[i][j]` 为只切 pos[i..j] 之间内部点时的最小成本，区间长度从 2 开始递推。
3. 转移：`dp[i][j] = min(dp[i][k] + dp[k][j]) + pos[j] - pos[i]`，k 取 i+1..j-1，含义是「k 这一刀最后切」。
4. 答案即 `dp[0][m-1]`。

关键中间值：示例 1 中 `dp[0][5]`（整根 0..7）枚举 k=1,2,3,4。取 k=3（位置 4）时，`dp[0][3]` 对应 0..4 段、`dp[3][5]` 对应 4..7 段，两者之和加 7。最终 `dp[0][5]=16`，与输出一致。

```python
pos = [0] + sorted(cuts) + [n]
m = len(pos)
dp = [[0] * m for _ in range(m)]
for length in range(2, m):
    for i in range(m - length):
        j = i + length
        best = 2**31 - 1
        for k in range(i + 1, j):
            best = min(best, dp[i][k] + dp[k][j])
        dp[i][j] = best + pos[j] - pos[i]
return dp[0][m - 1]
```

注意 `best` 初值用 `2**31 - 1` 只是占位，本题答案远小于它；Python 整数不溢出，无需担心累加。

## 复杂度
时间 O(m³)，m = len(cuts)+2，三层循环分别贡献区间长度、起点、断点。
空间 O(m²)，dp 表开 m×m，无其他额外结构。

## 易错点
- 忘记加哨兵 0 和 n → 用 `cuts=[1,3,4,5]` 直接建表，区间边界算成相邻 cut 之差，`dp[0][3]` 会漏掉 0..1 和 5..7 两段长度，答案偏小。正确做法是先 `pos = [0] + sorted(cuts) + [n]`。
- 转移写成 `dp[i][k] + dp[k][j] + pos[k] - pos[i]` → 成本只算了左半段长度。示例 1 中 k=3 时会得 4 而非 7，总答案错成 13。正确是加整段 `pos[j] - pos[i]`，因为切这一刀时整根当前棍子都要付费。

## 如果面试官追问
问：cuts 长度到 100 怎么办？
答：O(m³) 在 m=102 时约 10⁶ 次，Python 直接跑没问题；再大就得换思路，本题无更优通用解。
