## 一句话思路
把 `ruleKey` 映射成列下标 0/1/2，逐行比较该列与 `ruleValue`，相等就计数。

## 怎么做
1. 用字典 `{"type": 0, "color": 1, "name": 2}` 把 `ruleKey` 转成下标 `idx`，避免三路 if 分支。
2. 遍历 `items`，每行取 `item[idx]` 与 `ruleValue` 比较。
3. 相等则 `ans += 1`，最后返回 `ans`。

拿示例 1 走一遍：`ruleKey = "color"` → `idx = 1`。第 0 行 `["phone","blue","pixel"]` 的 `item[1]` 是 `"blue"`，不等于 `"silver"`，跳过；第 1 行 `item[1]` 是 `"silver"`，相等，`ans` 从 0 变 1；第 2 行 `item[1]` 是 `"gold"`，跳过。返回 1。

```python
idx = {"type": 0, "color": 1, "name": 2}[ruleKey]
ans = 0
for item in items:
    if item[idx] == ruleValue:
        ans += 1
return ans
```

关键点在于 `idx` 只算一次，循环体里不再碰字符串比较 `ruleKey == "type"` 这类判断——示例 2 里 `ruleKey = "type"`，`idx = 0`，三行第 0 列分别是 `"phone"`、`"computer"`、`"phone"`，命中第 0、2 行，`ans = 2`，与官方输出一致。

## 复杂度
时间 O(n)：n 是 `items` 的行数，每行只做一次 `item[idx] == ruleValue` 的字符串比较。
空间 O(1)：只开了固定 3 项的字典 `idx` 和计数器 `ans`。

## 易错点
- 把 `ruleKey` 当列值去比：例如示例 1 里写成 `item[1] == ruleKey`（即 `"blue" == "color"`），三行全不匹配，返回 0 而非 1。正确做法是先查字典得 `idx`，再比 `item[idx] == ruleValue`。
- 列顺序记错：`items[i]` 是 `[type, color, name]`，若把 `"name"` 映射成 1、`"color"` 映射成 2，示例 2 用 `ruleKey = "type"` 不受影响，但换成 `ruleKey = "color", ruleValue = "silver"` 就会去比 `item[2]`（`"lenovo"`），返回 0 而非 1。映射表必须严格是 `type→0, color→1, name→2`。

## 如果面试官追问
若 `items` 有 10^6 行、要多次查询不同 `ruleKey/ruleValue`，怎么办？
答：预处理时按三列各建一个 `col → 行数` 的计数字典，每次查询 O(1) 查表，代价是 O(n) 额外空间。
