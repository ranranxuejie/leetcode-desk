## 一句话思路
奇偶下标各自独立可任意重排，故只需比较 s1、s2 在偶数位和奇数位上的字符多重集是否分别相同。

## 怎么做
1. 把下标按奇偶分成两组，因为交换距离为偶数，i 和 j 同奇偶，字符永远困在原来的奇偶组里。
2. 分别统计 s1 偶数位、s2 偶数位的字符计数，逐字母比较；奇数位同理。
3. 两组都一致返回 `True`，否则 `False`。

以 `s1 = "abcdba"`、`s2 = "cabdab"` 为例：偶数位 s1 取下标 0,2,4 得 `a,c,b`，s2 得 `c,b,a`，排序后都是 `abc`；奇数位 s1 取 1,3,5 得 `b,d,a`，s2 得 `a,d,b`，排序后都是 `abd`，两组都相等，返回 `True`。

```python
def checkStrings(s1, s2):
    for start in (0, 1):
        a = sorted(s1[start::2])
        b = sorted(s2[start::2])
        if a != b:
            return False
    return True
```

`start=0` 处理偶数位，`start=1` 处理奇数位，切片 `s1[start::2]` 一步取出该组全部字符。排序后直接比列表，省去手写 26 长度计数数组。n 到 1e5 时排序是 O(n log n)，完全够用；若想 O(n)，把 `sorted` 换成 `collections.Counter` 再比字典即可。

## 复杂度
时间：O(n log n)，两组切片各占 n/2，排序贡献 log n。
空间：O(n)，`a`、`b` 两个列表各存 n/2 个字符。

## 易错点
- 误以为整个字符串可任意重排，对 `s1="abe"`、`s2="bea"` 直接比全串计数会返回 `True`，但偶数位 s1 是 `a,e`、s2 是 `b,a`，不等，正确结果是 `False`；必须按奇偶分组比。
- 只比一组就返回，比如只查偶数位通过就 `return True`，会漏掉奇数位不匹配的输入；两组都要过，任一组不等立刻 `False`。

## 如果面试官追问
问：要求输出具体交换方案怎么办？
答：在每组内把 s1 的字符按 s2 对应位置做置换，沿环逐个交换，距离必为偶数，O(n) 步即可。
