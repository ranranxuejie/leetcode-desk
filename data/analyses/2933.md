## 一句话思路
按员工分组、把时间转成分钟数排序，再看是否存在连续三条跨度 ≤59 分钟。

## 怎么做
1. 用字典 `d` 把 `access_times` 按姓名聚成时间列表，时间用 `int(t[:2])*60 + int(t[2:])` 转成分钟。
2. 对每个员工的时间列表排序。
3. 滑动检查 `times[i+2] - times[i] <= 59`，成立就把该姓名加入答案。

以示例 2 的 `"c"` 为例：`"0808"→488`、`"0829"→509`、`"0809"→489`，排序后为 `[488, 489, 509]`，`509 - 488 = 21 <= 59`，命中。而 `"d"` 的 `[850, 884, 908]` 中 `908 - 850 = 58`，也命中；`"e"` 只有一条，长度不足 3 直接跳过。

```python
d = {}
for name, t in access_times:
    d.setdefault(name, []).append(int(t[:2]) * 60 + int(t[2:]))

ans = []
for name, ts in d.items():
    ts.sort()
    for i in range(len(ts) - 2):
        if ts[i + 2] - ts[i] <= 59:
            ans.append(name)
            break
```

关键点：判据是「最早和最晚相差 ≤59 分钟」，不是「小时数相同」。示例 1 的 `"a"` 是 `[332, 349, 381]`，`381 - 332 = 49`，跨了 05 点和 06 点仍算同一小时窗口。

## 复杂度
时间：O(n log n)，n 为记录数，排序主导，字典分组是 O(n)。
空间：O(n)，字典存全部时间，答案列表最多 O(n)。

## 易错点
- 输入 `[["a","0815"],["a","0915"],["a","0916"]]` → 若按「小时数相同」分组会漏判或误判 → 正确做法是转分钟数后看 `ts[i+2]-ts[i] <= 59`，`555-495=60` 不成立，这组不算高访问。
- 输入 `[["a","0005"],["a","0030"],["a","2350"]]` → 若把「一天首尾」当成同一小时会误判 → 转分钟数后 `2350→1430`，`1430-5` 远超 59，正确不命中；跨零点不特殊处理，因为题面明确不算同一小时。

## 如果面试官追问
问：如果要求返回每个高访问员工的具体三次访问时间怎么办？
答：命中时记录 `(ts[i], ts[i+1], ts[i+2])` 即可，判据不变，只是把 `break` 换成收集。
