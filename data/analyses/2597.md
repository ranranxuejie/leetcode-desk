## 一句话思路
按 `nums[i] % k` 分组，每组内相邻值差恰为 k 的才冲突，组间互不影响，逐组算合法方案数再相乘。

## 怎么做
1. 用 `Counter` 统计每个值出现次数，再按 `v % k` 把值分到不同组。
2. 同一组内排序后，只有相差恰好 `k` 的两个值会冲突，因为同余类里差为 k 的倍数，而组内相邻差才可能等于 k。
3. 对每组做线性 DP：`dp0` 表示当前值不选的方案数，`dp1` 表示当前值选的方案数；若当前值与上一个值差为 k，则 `new1 = dp0 * (2**c - 1)`，否则 `new1 = (dp0 + dp1) * (2**c - 1)`。
4. 每组总方案数为 `dp0 + dp1`，各组相乘，最后减 1 去掉空集。

以 `nums = [2,4,6], k = 2` 为例：三个值同属 `%2 == 0` 组，排序后为 `[2,4,6]`。处理 2 时 `dp0=1, dp1=1`；处理 4 时差为 2，`new1 = dp0 * 1 = 1`，`new0 = 2`；处理 6 时差为 2，`new1 = dp0 * 1 = 2`，`new0 = 3`。该组共 `3+2=5` 种，减空集得 4。

```python
from collections import Counter
cnt = Counter(nums)
groups = {}
for v in cnt:
    groups.setdefault(v % k, []).append(v)
ans = 1
for g in groups.values():
    g.sort()
    dp0, dp1, prev = 1, 0, None
    for v in g:
        ways = (1 << cnt[v]) - 1
        new1 = (dp0 if prev is not None and v - prev == k else dp0 + dp1) * ways
        dp0, dp1, prev = dp0 + dp1, new1, v
    ans *= dp0 + dp1
return ans - 1
```

## 复杂度
时间：O(n log n)，排序各组贡献 log n，分组与 DP 线性扫描贡献 n。
空间：O(n)，`Counter` 与 `groups` 各存一份不同值。

## 易错点
- 输入 `nums = [1,1,3], k = 2`：若把重复的 1 当成两个独立元素分别决策，会漏算「选一个 1」的 2 种选法。正确做法是对每个值用 `2**cnt[v] - 1` 一次性算出该值选非空子集的方案数。
- 输入 `nums = [2,4,6], k = 2`：若只判断「当前值与上一个值差为 k」而不排序，`[6,2,4]` 的顺序会让 6 和 4 的冲突被漏掉。正确做法是每组先 `sort()` 再 DP，保证冲突只发生在相邻位置。

## 如果面试官追问
问：若 k 很大、nums 值域到 10^9 怎么办？答：分组仍按 `v % k`，组内排序后只比较相邻差是否为 k，与值域无关，复杂度不变。
