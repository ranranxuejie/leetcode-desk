## 一句话思路
先翻转所有首列为 0 的行，再逐列比较 0 和 1 的个数，少的一侧翻成多的一侧，因为高位权重最大。

## 怎么做
1. 遍历每一行，若 `grid[i][0] == 0` 则整行异或 1，保证首列全为 1。
2. 对第 `j` 列（`j` 从 1 到 n-1），统计该列 1 的个数 `ones`。
3. 若 `ones < m - ones`，说明 0 更多，翻转该列，贡献变为 `(m - ones) * (1 << (n-1-j))`；否则贡献 `ones * (1 << (n-1-j))`。
4. 累加所有列贡献，加上首列的 `m * (1 << (n-1))`。

以示例 1 的 `grid = [[0,0,1,1],[1,0,1,0],[1,1,0,0]]` 为例：第 0 行首列为 0，翻转为 `[1,1,0,0]`，矩阵变为 `[[1,1,0,0],[1,0,1,0],[1,1,0,0]]`。第 1 列（`j=1`）的值为 `[1,0,1]`，`ones=2`，`m-ones=1`，取 2，贡献 `2 * (1 << 2) = 8`。

```python
m, n = len(grid), len(grid[0])
for i in range(m):
    if grid[i][0] == 0:
        for j in range(n):
            grid[i][j] ^= 1
score = m * (1 << (n - 1))
for j in range(1, n):
    ones = sum(grid[i][j] for i in range(m))
    score += max(ones, m - ones) * (1 << (n - 1 - j))
return score
```

## 复杂度
时间：O(m·n)，每行翻转 O(n)，每列统计 O(m)，共 n 列。
空间：O(1)，原地修改 grid，未开额外数组。

## 易错点
- 输入 `[[0]]`（m=n=1）→ 若忘记处理首列翻转，直接算列贡献会得 0 → 正确做法是先翻首列得 `[[1]]`，`score = 1 * (1 << 0) = 1`。
- 输入 `[[1,0],[0,1]]` → 若只翻首列为 0 的行而不逐列比较，第 1 列 `[0,1]` 的 `ones=1`，`m-ones=1`，翻不翻一样，但若误判为必须翻会得错 → 正确做法是用 `max(ones, m-ones)` 取较大值，相等时任取。

## 如果面试官追问
问：若 m、n 扩大到 1000 且要求输出翻转方案而非得分？
答：记录每行是否翻转、每列是否翻转的布尔数组，按同样贪心决策，最后输出这些标记即可。
