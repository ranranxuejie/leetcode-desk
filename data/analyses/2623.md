## 一句话思路
用字典按参数元组缓存结果，命中就返回缓存、未命中才真正调用并累加计数器。

## 怎么做
1. 按 `fnName` 选实现：`sum` 取 `values[i]` 两个数相加，`fib`/`factorial` 用递归，但递归内部也要走同一份缓存，否则 `fib(5)` 会重复展开。
2. 缓存键用 `tuple(values[i])`，这样 `(3,2)` 和 `(2,3)` 天然是两个键，满足 sum 的顺序敏感要求。
3. `call` 时先查 `cache`，命中直接 append 结果；未命中则 `cnt += 1`、算值、写回 `cache`。
4. `getCallCount` 只 append `cnt`，不碰缓存。

以示例 1 为例：第 3 次 `call` 参数 `(1,2)`，`cache` 里此时只有 `(2,2): 4`，查不到，于是 `cnt` 从 1 变 2，算得 3 后写入 `cache[(1,2)] = 3`；紧接着的 `getCallCount` 输出 2。

```python
cache, cnt = {}, 0
def memo(*args):
    global cnt
    if args not in cache:
        cnt += 1
        cache[args] = raw(*args)   # raw 是 sum/fib/factorial
    return cache[args]

def fib(n):
    if n <= 1: return 1
    return memo(n - 1) + memo(n - 2)
```

注意 `fib` 里递归调的是 `memo` 而不是 `fib`，这样 `fib(5)` 展开时 `fib(3)`、`fib(2)` 都只算一次，示例 3 的 `cnt` 才是 1。

## 复杂度
时间：O(actions.length)，每次 call 均摊 O(1) 查字典，fib 递归因缓存每值只算一次。
空间：O(不同参数个数)，即 cache 条目数，fib 递归栈 O(n)。

## 易错点
- `sum` 用 `frozenset` 或排序后的元组做键 → `(3,2)` 和 `(2,3)` 被合并成一个缓存项，示例 1 里 `(1,2)` 若与已缓存的 `(2,1)` 撞键会少算一次调用，`getCallCount` 输出偏小；正确做法是键直接用 `tuple(values[i])` 保序。
- `fib`/`factorial` 递归体里调原始函数而非记忆化版本 → `fib(5)` 内部仍指数展开，虽然顶层 `cnt` 只加 1，但一旦 `actions` 里连续 call 多个 n，重复子问题会反复计算，且 `cnt` 语义与「真正调用次数」不符；正确做法是递归内部统一走 `memo`。

## 如果面试官追问
若 `actions` 涨到 10^6 且 `sum` 参数范围到 10^9，字典键还够用吗？答：够，哈希键与值域无关，只与不同参数对数量有关，空间仍是 O(去重后调用数)。
