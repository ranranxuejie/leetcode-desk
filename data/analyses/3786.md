## 一句话思路
按边拆贡献：每条边被同组点对经过的次数 = 两侧该组点数之积，DFS 一次算子树内各组计数即可。

## 怎么做
1. 以 0 为根建邻接表，迭代 DFS 求后序，避免递归深度 10^5 爆栈。
2. 对每个节点维护 `cnt[v][g]`：v 的子树中组 g 的节点数，初始 `cnt[v][group[v]] = 1`。
3. 处理边 (v, parent) 时，设 v 侧组 g 有 `a = cnt[v][g]`，整棵树组 g 共 `total[g]`，则这条边贡献 `a * (total[g] - a)`。
4. 把 `cnt[v]` 逐组加到父节点上，回溯完成。

以示例 2 为例：`group = [3,2,3]`，根 0，`total[3] = 2`。边 (2,1) 处 `cnt[2][3] = 1`，贡献 `1 * (2-1) = 1`；边 (1,0) 处 `cnt[1][3] = 1`（来自子节点 2），贡献同样为 1，合计 2。

```python
total = [0] * 21
for g in group:
    total[g] += 1
cnt = [[0] * 21 for _ in range(n)]
for v in range(n):
    cnt[v][group[v]] = 1
ans = 0
for v in reversed(order[1:]):          # order 为 DFS 先序，跳过根
    p = parent[v]
    for g in range(1, 21):
        a = cnt[v][g]
        if a:
            ans += a * (total[g] - a)
            cnt[p][g] += a
```

关键点：`cnt[v][g]` 在加给父节点前先算贡献，保证 `a` 是「v 子树侧」的计数，不会重复计入。

## 复杂度
时间 O(20n)：每条边对 20 个组各算一次。
空间 O(20n)：`cnt` 是 n×21 的表，另加邻接表 O(n)。

## 易错点
- 组标签最大到 20 但可能不连续（如示例 2 只有 2、3）→ 若用 `max(group)+1` 开表再按值索引，遇到标签跳跃会漏算 → 直接固定开 21 列，按 `group[v]` 原值索引。
- 链状树 n = 10^5（如 `edges = [[i, i+1] ...]`）→ 递归 DFS 触发 RecursionError 或栈溢出 → 用显式栈求 `order` 和 `parent`，再 `reversed(order[1:])` 后序处理。
- 答案量级：全同组链上点对距离和约 n^3/6 ≈ 1.7×10^14 → 题目若规定按 32 位截断需自行取模，Python 本身不会溢出，别照搬 C++ 的 `long long` 思维去截断。

## 如果面试官追问
问：group 值域放大到 10^5 怎么办？
答：把 `cnt[v]` 换成 dict 或「小到大合并」的 map，总复杂度降到 O(n log n)，思路不变。
