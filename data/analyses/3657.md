## 一句话思路
按 `customer_id` 分组聚合出购买数、退款数、活跃天数，再用三个条件一次过滤。

## 怎么做
1. 用 `groupby("customer_id")` 聚合，`purchase` 数用 `(transaction_type == "purchase").sum()`，退款数同理。
2. 活跃天数取 `transaction_date.max() - transaction_date.min()` 的 `.dt.days`，注意是**全部交易**（含退款）的日期跨度。
3. 退款率用 `refund / (purchase + refund) < 0.2`，分母是总交易数，不是购买数。
4. 三个条件用 `&` 连接后筛出 `customer_id` 并 `sort_values`。

以客户 104 为例：`purchase=5`、`refund=1`，分母 `5+1=6`，退款率 `1/6≈0.1667 < 0.2` 通过；日期跨度 `2024-03-15 - 2024-01-01 = 73` 天通过；购买数 5 ≥ 3 通过。而客户 102 的 `refund=2`、总数 `3+2=5`，`2/5=0.4` 直接被卡掉。

```python
g = df.groupby("customer_id")
stat = pd.DataFrame({
    "purchase": g["transaction_type"].apply(lambda s: (s == "purchase").sum()),
    "refund":   g["transaction_type"].apply(lambda s: (s == "refund").sum()),
    "days":     (g["transaction_date"].max() - g["transaction_date"].min()).dt.days,
})
stat["rate"] = stat["refund"] / (stat["purchase"] + stat["refund"])
ans = stat[(stat["purchase"] >= 3) & (stat["days"] >= 30) & (stat["rate"] < 0.2)]
ans.index.sort_values()
```

## 复杂度
时间 O(n)：n 为交易行数，一次分组扫描；排序 O(k log k)，k 为通过筛选的客户数。
空间 O(k)：额外存每个客户的一行聚合结果。

## 易错点
- 客户 104 这种有退款的：若把退款率分母写成 `purchase`，得 `1/5=0.2`，`< 0.2` 为假，104 被误删；正确分母是 `purchase + refund = 6`。
- 客户 103 只有 3 天跨度：若活跃天数只算购买交易或误用 `count()` 当天数，会把它判成活跃；正确做法是 `max(date) - min(date)` 取 `.dt.days`，得 2 天，被过滤。

## 如果面试官追问
问：如果要求退款率严格按「退款金额 / 总金额」算怎么办？
答：把 `refund` 计数换成 `amount` 按类型求和，条件改成 `refund_amt / (purchase_amt + refund_amt) < 0.2`，其余不变。
