## 一句话思路
对每个查询，用随机化采样：区间内出现次数 ≥ threshold 的元素，随机取一个位置命中它的概率 ≥ threshold/len，取 30 次即可高概率命中。

## 怎么做
1. 预处理每个值的位置列表 `pos[v]`，用二分 `bisect_right(pos[v], r) - bisect_left(pos[v], l)` 得区间内频次。
2. 对查询 `[l, r, t]`，若 `t` 大于区间长度则直接 -1（题面保证不会），否则随机采样 `k = 30` 次。
3. 每次在 `[l, r]` 随机取下标 `i`，算 `nums[i]` 的频次 `c`；若 `c >= t`，用它更新答案（频次更高，或频次相同但值更小）。
4. 采样结束若没找到任何 `c >= t` 的元素，返回 -1。

以示例 1 的 `[0,5,4]` 为例：区间长 6，threshold 4，随机命中 1 的概率是 4/6，30 次几乎必中；命中后 `c = 4 >= 4`，答案记为 1。而 `[0,3,3]` 中 1 和 2 各出现 2 次，都 `< 3`，30 次采样全部失败，返回 -1。

```python
import random
from bisect import bisect_left, bisect_right

def solve(nums, queries):
    pos = {}
    for i, v in enumerate(nums):
        pos.setdefault(v, []).append(i)
    ans = []
    for l, r, t in queries:
        best, bestc = -1, 0
        for _ in range(30):
            v = nums[random.randint(l, r)]
            p = pos[v]
            c = bisect_right(p, r) - bisect_left(p, l)
            if c >= t and (c > bestc or (c == bestc and v < best)):
                best, bestc = v, c
        ans.append(best)
    return ans
```

## 复杂度
时间：每个查询 30 次二分，O(q · 30 · log n)，预处理 O(n)。
空间：`pos` 存 n 个下标，O(n)。

## 易错点
- 采样次数取太少（如 5 次）：threshold 接近区间长度时命中率虽高，但 threshold 很小时反而容易漏掉真正的高频元素，导致答案偏大或返回 -1；固定 30 次并配合「频次相同取更小值」的比较逻辑才稳。
- 只记录第一个满足 `c >= t` 的元素就 break：示例 2 的 `[1,5,2]` 中 2 出现 3 次、3 出现 2 次，若先采到 3 就停会错答 3；必须遍历全部 30 次采样并按 `(c, -v)` 取最优。

## 如果面试官追问
问：要求确定性正确怎么办？
答：改用「候选值 = 区间内出现次数 ≥ t 的值」，可对每个值二分位置列表枚举，或按出现次数分块预处理，代价是 O(不同值数 · log n)。
