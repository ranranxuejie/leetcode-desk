## 一句话思路
把圆心到矩形的最近点夹取出来，比较它到圆心的距离平方与 `radius**2`。

## 怎么做
1. 用 `min(max(xCenter, x1), x2)` 把圆心横坐标夹到 `[x1, x2]`，得到最近点横坐标 `cx`。
2. 同理夹出 `cy = min(max(yCenter, y1), y2)`，`(cx, cy)` 就是矩形上离圆心最近的点。
3. 判断 `(xCenter-cx)**2 + (yCenter-cy)**2 <= radius**2`，成立即有重叠。

拿示例 2 走一遍：`xCenter=1, yCenter=1, x1=1, y1=-3, x2=2, y2=-1`。夹取得 `cx = min(max(1,1),2) = 1`，`cy = min(max(1,-3),-1) = -1`。距离平方 `(1-1)**2 + (1-(-1))**2 = 4`，而 `radius**2 = 1`，`4 > 1` 返回 `False`，与预期一致。注意这里 `cy` 被夹到了矩形上边界 `y2=-1`，说明圆心在矩形正上方，最近点确实落在边上而不是角上。

```python
cx = min(max(xCenter, x1), x2)
cy = min(max(yCenter, y1), y2)
dx = xCenter - cx
dy = yCenter - cy
return dx * dx + dy * dy <= radius * radius
```

圆心在矩形内部时 `cx == xCenter`、`cy == yCenter`，距离为 0，必然 `<= radius**2`（`radius >= 1`），自动返回 `True`，无需单独判分支。

## 复杂度
时间：O(1)，只有四次比较和两次乘法，与坐标范围无关。
空间：O(1)，只开了 `cx/cy/dx/dy` 四个整型变量。

## 易错点
- 用「圆心到矩形中心」的距离代替最近点距离：示例 2 中矩形中心是 `(1.5, -2)`，距离平方 `0.25 + 9 = 9.25 > 1` 恰好也是 `False`，但换成 `radius=2` 就会误判成 `True`，而真实最近距离平方是 4，`4 <= 4` 其实为 `True`——两种算法在边界上结论相反，必须夹取最近点。
- 用 `math.sqrt` 开方后比较浮点数：`radius=2000`、距离平方恰为 `4000000` 时，`sqrt` 可能返回 `2000.0000000000002`，把本该 `True` 判成 `False`；应全程用整数平方比较。

## 如果面试官追问
问：若矩形改成任意旋转的平行四边形怎么办？
答：把圆心变换到矩形局部坐标系，仍夹取最近点，只是多一次旋转矩阵乘法。
