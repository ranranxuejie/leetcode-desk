## 一句话思路
从左往右扫，遇到 `nums[i] <= nums[i-1]` 就把它抬到 `nums[i-1]+1`，累加抬升量；因为只增不减，抬到刚好够是最优的。

## 怎么做
1. 维护 `ans = 0`，从 `i = 1` 开始遍历。
2. 若 `nums[i] <= nums[i-1]`，需要抬到 `nums[i-1] + 1`，把差值 `nums[i-1] + 1 - nums[i]` 累加进 `ans`，并原地改写 `nums[i]`。
3. 否则不动，继续下一个。

用示例 2 `nums = [1,5,2,4,1]` 走一遍关键几步：
- `i=1`：`5 > 1`，跳过。
- `i=2`：`2 <= 5`，抬到 `6`，`ans += 4`，`nums` 变 `[1,5,6,4,1]`。
- `i=3`：`4 <= 6`，抬到 `7`，`ans += 3`（累计 7），`nums` 变 `[1,5,6,7,1]`。
- `i=4`：`1 <= 7`，抬到 `8`，`ans += 7`，累计 **14**，与官方输出一致。

```python
ans = 0
for i in range(1, len(nums)):
    if nums[i] <= nums[i - 1]:
        need = nums[i - 1] + 1
        ans += need - nums[i]
        nums[i] = need
return ans
```

注意 `nums[i] = need` 这行不能省：后面 `i+1` 比较的是改写后的值，不是原值。示例 2 里若只累加不回写，`i=3` 会拿原 `4` 和 `5` 比，少算 2 次操作。

## 复杂度
时间 O(n)：一次遍历，`n = len(nums)`，每步 O(1)。
空间 O(1)：只用了 `ans`、`need` 两个变量（原地改写 `nums` 不算额外空间）。

## 易错点
- 输入 `[1,5,2,4,1]` → 只累加 `ans` 却不回写 `nums[i]`，`i=3` 时拿原值 `4` 和 `5` 比较，得到 12 而非 14 → 必须把 `nums[i]` 改成 `nums[i-1]+1` 再往后走。
- 输入 `[1,1,1]` → 用 `nums[i] < nums[i-1]` 判断，漏掉相等的情况，`i=1` 时 `1 < 1` 为假直接跳过，输出 0 而非 3 → 条件必须是 `<=`，相等也要抬。

## 如果面试官追问
问：如果允许把元素减小，答案会变吗？
答：会，此时贪心不再成立，需要先确定一个不降的基准序列（如排序后取中位数思路），代价模型从「只补差」变成双向距离。
