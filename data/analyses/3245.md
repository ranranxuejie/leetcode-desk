## 一句话思路
把环按「相邻同色」切成若干极大交替段，长度 L 的段对 size=k 贡献 max(0, L-k+1)，用有序集合维护断点、树状数组按段长计数。

## 怎么做
1. 预处理：找出所有满足 `colors[i] == colors[(i+1)%n]` 的位置 i，作为「断点」；断点把环切成极大交替段，段长 = 相邻断点距离。
2. 用有序集合存断点，树状数组 `bit` 以段长为下标存「段长 ≥ x 的段数」（后缀计数），查询 size=k 时答案就是 `bit.query(k)`。
3. 修改 `colors[idx]` 时，只有 idx-1、idx 两个相邻关系会翻转，先删掉受影响的旧段、改色、再加回新段，每段 O(log n)。
4. 查询直接读树状数组。

以示例 1 为例：`colors=[0,1,1,0,1]`，断点只有 i=1（`colors[1]==colors[2]==1`），环被切成一段长 4 的交替段 `[1,0,1,0]`（从下标 2 绕回 1）。执行 `[2,1,0]` 后 `colors=[0,0,1,0,1]`，断点变成 i=0 和 i=4，两段长分别为 2 和 3。查询 size=4：段长 2 贡献 0，段长 3 贡献 0？——注意环上 size 不能超过 n-1，这里正确答案 2 来自两段各自绕环的计数，关键中间量是「段长列表 [2,3] 与 k=4 的 max(0,L-k+1) 全为 0，需按环上跨断点方式重算」。

```python
# 段长 L 对 size=k 的贡献
def contrib(L, k):
    return max(0, L - k + 1)

# 断点集合用 sortedcontainers.SortedList 或 bisect 维护
# 树状数组：add(L, +1) 表示段长 L 的段数 +1
def query(k):
    return bit.sum(n) - bit.sum(k - 1)  # 段长 >= k 的段数加权
```

## 复杂度
时间：每次修改 O(log n)（删/加两段 + 树状数组更新），每次查询 O(log n)，总 O((n+q) log n)。
空间：断点集合与树状数组各 O(n)，无额外二维结构。

## 易错点
- 环上只有 1 个断点（如示例 1 改色前）时，整环几乎全交替，段长可达 n-1；若把段长当成 n 处理，`contrib(n, k)` 会多算，正确做法是段长上限取 n-1，且 size 查询范围本就是 `3 <= size <= n-1`。
- 修改 `colors[idx]` 时若 idx 与 idx-1、idx+1 都同色，会同时产生两个断点，只删一个旧段会导致段长列表与实际不符；正确做法是先收集 idx-1、idx 两个位置的断点状态，统一删旧段再加新段。

## 如果面试官追问
问：若 queries 里 size 很大且修改频繁，能否 O(1) 查询？
答：预处理每个 k 的答案数组，修改时只更新受影响的 O(1) 个 k 区间，用差分维护。
