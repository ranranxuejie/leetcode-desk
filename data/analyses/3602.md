## 一句话思路
对 n² 和 n³ 分别做「除基取余、逆序拼接」，因为十六进制与三十六进制只差进制数和字母表长度。

## 怎么做
1. 先算 `sq = n * n`、`cube = n * n * n`，别用浮点 `n ** 2` 之外的写法混淆类型。
2. 写一个 `to_base(x, b)`：循环 `x, b` 取余 `x % b`，余数查表 `DIGITS`，再 `x //= b`，最后反转。
3. 十六进制传 `b=16`，三十六进制传 `b=36`，两段直接 `+` 拼接。
4. 用 n=13 走一遍：`sq=169`，`169 % 16 = 9`、`169 // 16 = 10`，`10 % 16 = 10` 查表得 `'A'`，反转得 `"A9"`；`cube=2197`，`2197 % 36 = 1`、`61 % 36 = 25` 查表 `'P'`、`1 % 36 = 1`，反转得 `"1P1"`，拼接 `"A91P1"`。

```python
DIGITS = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ"

def to_base(x, b):
    if x == 0:
        return "0"
    out = []
    while x:
        out.append(DIGITS[x % b])
        x //= b
    return "".join(reversed(out))

sq = n * n
cube = n * n * n
return to_base(sq, 16) + to_base(cube, 36)
```

关键中间值：`to_base(169, 16)` 的余数序列是 `[9, 10]`，反转后 `"A9"`；`to_base(2197, 36)` 的余数序列是 `[1, 25, 1]`，反转后 `"1P1"`。

## 复杂度
时间：O(log₁₆ n² + log₃₆ n³)，即 O(log n)，循环次数由位数决定。
空间：O(log n)，`out` 列表存每位字符，无其他额外结构。

## 易错点
1. 输入 n=1 → 若 `to_base` 里没处理 `x == 0` 的提前返回，`while x` 一次都不进，返回空串 `""`，答案变成 `"1"` 而不是 `"11"`（1²=1 的十六进制是 `"1"`，1³=1 的三十六进制是 `"1"`）。正确做法是循环前判 `x == 0` 直接返回 `"0"`，本题 n≥1 时 sq、cube 都 ≥1，但保留这个分支更稳。
2. 输入 n=36 → 若把三十六进制也传 `b=16`，或查表只写到 `'F'`，`25` 会越界或错成 `'F'` 之后的乱码；正确做法是 `DIGITS` 至少 36 个字符，且 `to_base(cube, 36)` 里 `25` 必须映射到 `'P'`，得到 `"1000"` 而非 `"510"`。

## 如果面试官追问
问：n 放大到 10^9 呢？答：`n * n * n` 到 10^27，Python 大整数照样算，位数只增到约 18 位，`to_base` 循环次数仍是 O(log n)，不用改。
