## 一句话思路
一次遍历，用 `best` 记录当前满足 `capacity[i] >= itemSize` 的最小容量，只在严格更小时更新下标。

## 怎么做
1. 初始化 `best = 2**31 - 1`、`ans = -1`，`best` 表示已见过的最小可行容量。
2. 从左到右遍历 `i, c in enumerate(capacity)`，顺序遍历天然保证「同容量取小下标」。
3. 若 `c >= itemSize and c < best`，则更新 `best = c`、`ans = i`；注意是严格小于，等于时不覆盖。
4. 遍历结束返回 `ans`，没更新过就是 `-1`。

以示例 2 的 `capacity = [3,5,4,3], itemSize = 2` 为例：i=0 时 `3 >= 2` 且 `3 < 2**31-1`，`best` 变 3、`ans` 变 0；i=3 时 `c = 3` 不满足 `3 < best(3)`，所以 `ans` 保持 0——这正是「同容量取小下标」的关键中间值。

```python
best = 2**31 - 1
ans = -1
for i, c in enumerate(capacity):
    if c >= itemSize and c < best:
        best = c
        ans = i
return ans
```

## 复杂度
时间：O(n)，n 为 `capacity` 长度，每个箱子只看一次。
空间：O(1)，只开了 `best`、`ans` 两个变量。

## 易错点
- 写成 `c <= best` 更新：示例 2 中 i=3 的 `c = 3` 会覆盖 `ans` 成 3，输出 3 而非 0。正确做法是严格 `c < best`，让先出现的小下标守住位置。
- 把 `best` 初始化成 `capacity[0]`：若 `capacity[0] < itemSize`（如 `[1,5,3,7], itemSize = 3`），`best = 1` 后所有 `c < 1` 都不成立，永远不更新，返回 -1。正确做法是初始化成大于任何 `capacity[i]` 的值，如 `2**31 - 1`。

## 如果面试官追问
问：若 `capacity` 长度涨到 10^7 且要求多次不同 `itemSize` 查询怎么办？
答：先对 `(capacity[i], i)` 排序并预处理后缀最小下标，每次查询二分找第一个 `>= itemSize` 的位置，O(log n)。
