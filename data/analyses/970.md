## 一句话思路
枚举所有不超过 bound 的 x^i 与 y^j 幂值，两两求和去重，因为幂增长极快所以枚举量很小。

## 怎么做
1. 先分别生成 x 的幂列表 `px` 和 y 的幂列表 `py`，每项都 ≤ bound。
2. 生成时用 `while p <= bound` 循环，每轮 `p *= x`，一旦 `p == 1` 就 break 防止死循环。
3. 双重循环把 `px[i] + py[j]` 塞进 set，只保留 ≤ bound 的和。
4. 返回 set 转 list。

以 `x=2, y=3, bound=10` 为例：`px = [1,2,4,8]`（16>10 停），`py = [1,3,9]`（27>10 停）。两两相加得到 2,4,10,3,5,11,9,11,17 等，过滤 ≤10 后 set 为 {2,3,4,5,7,9,10}，正好是答案。

```python
px, p = [], 1
while p <= bound:
    px.append(p)
    if x == 1: break
    p *= x
py, p = [], 1
while p <= bound:
    py.append(p)
    if y == 1: break
    p *= y
res = set()
for a in px:
    for b in py:
        if a + b <= bound:
            res.add(a + b)
return list(res)
```

## 复杂度
时间：O(log_x bound · log_y bound)，两个幂列表长度之积，x、y ≥ 2 时各不超过 20。
空间：O(log_x bound + log_y bound + 答案个数)，即两个幂列表加一个去重 set。

## 易错点
- `x == 1` 或 `y == 1` → `p *= 1` 永远等于 1，`while p <= bound` 死循环 → 生成幂时判断 `if x == 1: break`，让 `px` 只含 `[1]`。
- `bound == 0` → 若循环条件写成 `p < bound` 会漏掉 `1+1=2` 之外的情况，且 `1 <= bound` 不成立时 `px` 为空 → 用 `p <= bound` 保证 `bound=0` 时 `px=[1]` 但 `1+1=2>0` 被过滤，返回空列表，符合题意。

## 如果面试官追问
问：若 bound 放大到 10^18 怎么办？
答：幂列表长度只增到约 60，双重循环仍是 3600 次，直接枚举照样过，无需换算法。
