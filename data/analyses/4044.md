## 一句话思路
把数组复制一份接在后面，用长度 n/2 的滑动窗口枚举每个循环移位的前半段和，与总和比较。

## 怎么做
1. 令 `half = n // 2`、`total = sum(nums)`，窗口和 `s = sum(nums[:half])`。
2. 枚举起点 `i` 从 0 到 n-1，判断 `2 * s > total`（等价于前半和 > 后半和），成立则计数加一。
3. 每次右移窗口：`s += nums[(i + half) % n] - nums[i]`，用取模代替拼接数组。
4. 返回计数。

以 `nums = [1,2,3,4,5,6]` 为例，`half = 3`、`total = 21`、初始 `s = 6`。`i = 0` 时 `2*6 = 12 < 21` 不算；滑到 `i = 2` 时 `s = 3+4+5 = 12`，`2*12 = 24 > 21` 计数；`i = 3` 时 `s = 15`，`30 > 21` 计数；`i = 4` 时 `s = 12` 计数，共 3 个。

```python
half = len(nums) // 2
total = sum(nums)
s = sum(nums[:half])
ans = 0
for i in range(len(nums)):
    if 2 * s > total:
        ans += 1
    s += nums[(i + half) % len(nums)] - nums[i]
return ans
```

注意循环里先判断再滑动，第 `i` 次判断对应的是以 `i` 为起点的移位；`i` 走满 n 次正好覆盖全部 n 种移位（包括空前缀那次）。

## 复杂度
时间：O(n)，一次求和加 n 次 O(1) 窗口滑动。
空间：O(1)，只用了 `s`、`total`、`ans` 几个标量，没开新数组。

## 易错点
- 用 `2 * s > total` 判等时，若写成 `s > total - s` 在 Python 里没问题，但若误写成 `s >= total // 2`，遇到 `total` 为奇数（如 `[1,2,3,4,5,6]` 的 21）会因整除截断把 `s = 10` 误判为不满足，正确做法是保留乘法比较避免除法。
- 滑动时写成 `s += nums[i + half] - nums[i]` 而不取模，当 `i >= half` 时下标越界（如 n=6、i=4 时 `4+3=7` 越界），正确做法是 `nums[(i + half) % n]`。

## 如果面试官追问
若 n 可达 10^7 且内存吃紧，怎么省？答：仍用取模滑动，不复制数组，空间保持 O(1)，时间线性扫描一遍即可。
