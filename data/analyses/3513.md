## 一句话思路
答案只由 n 决定：n≤2 时是 n，n≥3 时是大于 n 的最小 2 的幂，因为排列能凑出 0..2^k-1 全部值。

## 怎么做
1. 注意 `nums` 是 1..n 的排列，元素集合固定，下标顺序不影响可达的 XOR 值集合，所以答案与 `nums` 的具体顺序无关。
2. 令 k 为满足 `2**k > n` 的最小整数，则所有可达 XOR 值恰好是 `[0, 2**k - 1]`，共 `2**k` 个。
3. 特判 n≤2：n=1 只有 `1^1^1=1`，n=2 只有 {1,2}，都等于 n，不满足上面的公式（此时 2**k = 2 或 4 会多算）。
4. 代码只需算 k：

```python
n = len(nums)
if n <= 2:
    ans = n
else:
    k = n.bit_length()      # 2**(k-1) <= n < 2**k
    ans = 1 << k
```

以 `nums = [3,1,2]` 为例，n=3，`n.bit_length()` 得 2，`1 << 2 = 4`，与示例输出 4 一致；此时可达集合是 {0,1,2,3}，正好由 `3^3^3=3`、`3^3^1=1`、`3^3^2=2`、`3^1^2=0` 取到。

为什么上界是 `2**k - 1`：所有元素都小于 `2**k`，异或不会产生第 k 位，所以值域被卡在 `[0, 2**k-1]`。为什么下界能填满：1..n 里含有 `2**(k-1)` 这一位为 1 的数，配合 `i<=j<=k` 允许重复取同一元素（`x^x^x = x`），可以逐个构造出每个目标值，因此 0 到 `2**k-1` 全部可达。

## 复杂度
时间 O(1)：只做一次 `bit_length`，与 n 无关（读入数组本身 O(n)）。
空间 O(1)：除输入外不额外开数组。

## 易错点
- 输入 `nums = [1]` 或 `[1,2]` → 直接套 `1 << n.bit_length()` 会得到 1 和 4，示例 1 正确答案是 2 → 必须先判 `n <= 2` 返回 n。
- 输入 n 恰为 2 的幂，如 n=4 → 误以为 k 要取 `n.bit_length()+1` 或答案 2n → 正确是 `2**k` 中 k 满足 `2**k > n`，n=4 时 k=3、答案 8，`bit_length()` 已自动给出 3，不要再加一。

## 如果面试官追问
问：若允许四元组（i<=j<=k<=l）呢？
答：值域仍是 `[0, 2**k-1]`，但 n=1、2 时需重新枚举小规模，公式不再直接复用。
