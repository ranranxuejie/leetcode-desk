## 一句话思路
每个商品维护一个 `(金额, userId)` 的大顶堆，堆顶即最高出价者；出价变更时惰性删除，查询时弹出与当前出价不符的旧堆项。

## 怎么做
1. 用 `bids[(userId, itemId)] = amount` 存权威出价，用 `heaps[itemId]` 存 `(-amount, -userId)` 的堆（取负让金额大、userId 大者优先）。
2. `addBid`/`updateBid` 只改字典并往堆里 push 新项，不删旧项。
3. `removeBid` 只删字典项，堆里残留项靠查询时校验。
4. `getHighestBidder` 循环弹堆顶，直到堆顶与 `bids` 一致或堆空。

以官方示例为例：`addBid(1,7,5)`、`addBid(2,7,6)` 后 `heaps[7] = [(-6,-2), (-5,-1)]`，堆顶 `(-6,-2)` 对应 `bids[(2,7)]==6`，返回 `2`。接着 `updateBid(1,7,8)` push `(-8,-1)`，堆顶变 `(-8,-1)`，返回 `1`。`removeBid(2,7)` 后堆顶仍是 `(-8,-1)`，返回 `1`；查商品 3 时 `heaps` 无键，返回 `-1`。

```python
import heapq

def getHighestBidder(self, itemId):
    h = self.heaps.get(itemId)
    if not h:
        return -1
    while h:
        neg_amt, neg_uid = h[0]
        uid = -neg_uid
        if self.bids.get((uid, itemId)) == -neg_amt:
            return uid
        heapq.heappop(h)
    return -1
```

关键点：`(-amount, -userId)` 的元组比较天然实现「金额相同取 userId 大」，无需额外比较器。

## 复杂度
时间：每次操作均摊 O(log n)，n 为该商品历史 push 次数，惰性弹出总计不超过 push 总数。
空间：O(n)，`bids` 存当前有效出价，`heaps` 额外存历史残留项。

## 易错点
- 同一用户对同一商品重复 `addBid`：若直接 push 新项而不覆盖字典，旧金额会残留在堆里被误判为有效 → 必须先写 `bids[(userId, itemId)] = bidAmount` 再 push，查询时用字典值校验堆顶。
- 金额相同比 userId：若堆只存 `-amount`，`addBid(1,7,5)` 与 `addBid(2,7,5)` 堆顶顺序不确定 → 必须存 `(-amount, -userId)` 二元组，让 Python 元组比较自动取 userId 大者。

## 如果面试官追问
问：若要求 `getHighestBidder` 严格 O(1)？答：改用 `SortedList` 或平衡树按 `(amount, userId)` 维护每商品出价集合，变更时精确删除，堆顶即答案。
