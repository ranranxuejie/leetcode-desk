## 一句话思路
用 `NOT IN` 子查询筛出 manager_id 不在员工表中的行，再叠加 salary 条件。

## 怎么做
1. 先锁定薪水门槛：`salary < 30000`，示例中只剩 1 号 Kalel（21241）和 11 号 Joziah（28485）。
2. 再判断经理是否在职：把每行的 `manager_id` 拿去和全表 `employee_id` 集合比对。
3. 关键中间值：Joziah 的 `manager_id = 6`，而 `employee_id` 集合是 `{3,12,13,1,9,11}`，6 不在其中 → 离职，保留；Kalel 的 `manager_id = 11` 在集合里 → 在职，剔除。
4. 最后 `ORDER BY employee_id` 升序输出。

```python
# 等价 SQL 逻辑，用 pandas 表达关键两行
ids = set(emp["employee_id"])
mask = (emp["salary"] < 30000) & (~emp["manager_id"].isin(ids))
# manager_id 为 None 时 isin 返回 False，~ 后变 True，必须额外排除
mask &= emp["manager_id"].notna()
res = sorted(emp.loc[mask, "employee_id"].tolist())
```

## 复杂度
时间：O(n) 建 `employee_id` 集合，每行 O(1) 查表，排序 O(k log k)，k 为命中行数。
空间：O(n) 存 id 集合，结果列表 O(k)。

## 易错点
- `manager_id` 为 `None` 的行（示例中 12、13、9 号）→ `NOT IN` 遇到 NULL 会让整个条件返回 unknown，一行都查不出 → 正确做法是加 `manager_id IS NOT NULL`，或改用 `NOT EXISTS` 相关子查询，它对 NULL 安全。
- 只写 `manager_id NOT IN (SELECT employee_id ...)` 却漏了薪水条件 → 会把 3 号 Mila（经理 9 在职）之外所有经理离职的人都捞出来，比如若存在高薪但经理离职者会误入 → 两个条件必须同时 AND，且薪水用严格小于 `< 30000`，不是 `<=`。

## 如果面试官追问
问：表很大、`employee_id` 有索引，怎么优化？
答：改用 `NOT EXISTS (SELECT 1 FROM Employees m WHERE m.employee_id = e.manager_id)`，可走索引且天然规避 NULL。
