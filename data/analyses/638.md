## 一句话思路
把 needs 当状态做记忆化 DFS，每层只尝试「还能装下的礼包」，剩余部分按单价补齐，取最小值。

## 怎么做
1. 先剪枝 special：若某礼包按单价算不比原价便宜，或某件物品数量超过 needs，直接丢弃。
2. 用 `tuple(needs)` 作 memo 的 key，递归函数返回满足该需求的最小花费。
3. 每层先算全按单价买的基线 `sum(price[i]*cur[i])`，再枚举每个礼包，若 `cur[i] >= sp[i]` 全部成立就递归剩余需求。
4. 取 `min(基线, 礼包价 + dfs(剩余))` 存 memo 返回。

以示例 1 为例，`price=[2,5], needs=[3,2]`，礼包 2 是 `[1,2,10]`。进入 `dfs((3,2))` 时基线 `2*3+5*2=16`；礼包 2 可装下，剩余 `(2,0)`，递归得 `2*2=4`，合计 `10+4=14`，比 16 小，最终返回 14。

```python
from functools import lru_cache

@lru_cache(None)
def dfs(cur):
    best = sum(p * c for p, c in zip(price, cur))
    for sp in special:
        if all(c >= s for c, s in zip(cur, sp[:-1])):
            rest = tuple(c - s for c, s in zip(cur, sp[:-1]))
            best = min(best, sp[-1] + dfs(rest))
    return best

return dfs(tuple(needs))
```

## 复杂度
时间：状态数 `∏(needs[i]+1)`，每个状态枚举至多 100 个礼包，n 只影响元组长度。
空间：memo 存全部状态，每个 key 是长度 n 的元组，递归深度不超过 `sum(needs)`。

## 易错点
- 礼包数量超过 needs 时（如示例 2 的 `[2,2,1,9]` 对 `needs=[1,2,1]`）→ 若只判「总价更便宜」就选它，会买超 → 必须逐件判 `cur[i] >= sp[i]`，超了直接跳过。
- 礼包本身不划算时（如 `special=[[1,0,3]]` 而 `price[0]=2`）→ 递归仍会尝试它，多算但不错；真正会错的是漏算「全按单价买」的基线，导致某状态无解返回 0 → 每层必须先算 `sum(price[i]*cur[i])` 兜底。

## 如果面试官追问
问：needs 上限从 10 提到 100 怎么办？
答：状态数爆炸，改用完全背包按物品维度 DP 或整数规划，记忆化只适合小 needs。
