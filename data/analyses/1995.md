## 一句话思路
枚举 c 作为分界点，用哈希表存 `nums[a]+nums[b]` 的出现次数，边扫边查 `nums[d]-nums[c]`。

## 怎么做
1. 固定 c 从 2 到 n-2，把 d 从 c+1 到 n-1 的所有 `nums[d]-nums[c]` 累加进答案。
2. 关键：在进入 c 之前，先把所有 `a<b<c` 的 `nums[a]+nums[b]` 计数存进哈希表。
3. 用具体输入 `[1,1,1,3,5]` 走一遍：c=3 时表里存的是 `{2:3}`（(0,1)(0,2)(1,2) 三对和都是 2），d=4 时 `nums[4]-nums[3]=2`，命中 3 次；c=4 时表里加入含 3 的对，`{2:3, 4:3}`，d 已无，答案 3+1=4。
4. 顺序不能反：先查后加，否则会把 c 自己算进 a/b。

```python
from collections import Counter
cnt = Counter()
ans = 0
for c in range(2, len(nums) - 1):
    for a in range(c - 1):
        cnt[nums[a] + nums[c - 1]] += 1
    for d in range(c + 1, len(nums)):
        ans += cnt[nums[d] - nums[c]]
```

注意内层 `nums[c-1]`：c 每前进一步，只新增 b=c-1 这一批对，避免重复计数。

## 复杂度
时间 O(n²)：外层 c 与内层 a/d 各扫一遍，共约 n²/2 次哈希操作。
空间 O(n²)：哈希表最多存 n²/2 个不同的和，值域 2~200 实际更小。

## 易错点
- 输入 `[1,1,1,3,5]` → 若把「先加后查」写成「先查后加」，c=3 时表里已含 `nums[2]+nums[3]=4`，会多算；正确做法是每轮 c 只加 `nums[a]+nums[c-1]`，查完再进下一轮。
- 输入 `[3,3,6,4,5]` → 若用 `nums[d]-nums[c]` 却忘了 d 必须严格大于 c，会把 d=c 的 0 也算进去；正确做法是 d 从 c+1 起，且 c 上界取 `len(nums)-2`。

## 如果面试官追问
问：n 放大到 10⁵ 怎么办？答：值域只有 1~100，和的范围 2~200，用长度 201 的数组代替 Counter，仍是 O(n²) 但常数极小；再大就得换思路。
