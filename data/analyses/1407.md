## 一句话思路
以 Users 为主表 LEFT JOIN Rides，按用户聚合 `SUM(distance)`，无行程补 0，再按距离降序、姓名升序排。

## 怎么做
1. 从 Users 出发 LEFT JOIN Rides，保证 Donald 这种零行程用户不丢。
2. 用 `COALESCE(SUM(distance), 0)` 把 NULL 折成 0。
3. 按 `user_id` 分组后取 `name`，再 `ORDER BY travelled_distance DESC, name ASC`。

拿官方示例看关键中间值：Lee（id=7）在 Rides 里有 100、120、230 三行，聚合后 `SUM=450`；Elvis（id=19）有 50、400，也是 450。两人距离相同，`name` 比较 `'Elvis' < 'Lee'`，所以 Elvis 排前。Donald（id=4）在 Rides 中无匹配行，LEFT JOIN 后 distance 为 NULL，`COALESCE` 得 0，排在最后。

```python
# 思路等价写法（pandas）
m = users.merge(rides, left_on="id", right_on="user_id", how="left")
g = m.groupby(["id", "name"], as_index=False)["distance"].sum()
g["distance"] = g["distance"].fillna(0)
g = g.rename(columns={"distance": "travelled_distance"})
g = g.sort_values(["travelled_distance", "name"], ascending=[False, True])
```

SQL 版核心就一行聚合：

```python
# SELECT u.name, COALESCE(SUM(r.distance), 0) AS travelled_distance
# FROM Users u LEFT JOIN Rides r ON u.id = r.user_id
# GROUP BY u.id, u.name
# ORDER BY travelled_distance DESC, u.name ASC
```

注意 `GROUP BY` 要带上 `u.id`，否则同名用户会被合并。

## 复杂度
时间：O(R + U log U)，R 为 Rides 行数做一次扫描，U 为用户数参与排序。
空间：O(U)，分组结果和排序额外占用。

## 易错点
- 用 INNER JOIN → Donald 直接消失，输出少一行 → 必须 LEFT JOIN 且 `COALESCE(..., 0)`。
- 只 `GROUP BY name` → 两个同名用户距离被错误相加 → 分组键用 `u.id, u.name`，排序才用 name。

## 如果面试官追问
问：若 Rides 有百万行、Users 只有几千，怎么优化？
答：先在 Rides 上按 `user_id` 预聚合再 JOIN Users，避免大表参与分组排序。
