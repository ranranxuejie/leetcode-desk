## 一句话思路
按 user_id 分组算出 count 和 avg，再用 `HAVING` 同时卡「≥3 条」和「存在 tokens > avg」，一次聚合搞定。

## 怎么做
1. 用 `GROUP BY user_id` 聚合出 `COUNT(*)` 和 `ROUND(AVG(tokens), 2)`。
2. 在 `HAVING` 里写 `COUNT(*) >= 3`，过滤掉用户 2（只有 2 条）。
3. 第二个条件用 `MAX(tokens) > AVG(tokens)` 判断「至少一条超过自己均值」——因为只要最大值超过均值，就说明存在这样的行。
4. 最后 `ORDER BY avg_tokens DESC, user_id ASC`。

关键中间值：用户 1 的 `AVG(tokens) = (120+80+200)/3 = 133.33`，`MAX(tokens) = 200 > 133.33`，保留；用户 3 的 `AVG = 237.5`，`MAX = 300 > 237.5`，保留。用户 2 被 `COUNT(*) >= 3` 直接挡掉。

```python
# 核心聚合逻辑（SQL 思路，Python 里用 dict 模拟）
from collections import defaultdict

stat = defaultdict(list)
for uid, tok in rows:            # rows = [(user_id, tokens), ...]
    stat[uid].append(tok)

res = []
for uid, toks in stat.items():
    cnt = len(toks)
    avg = round(sum(toks) / cnt, 2)
    if cnt >= 3 and max(toks) > sum(toks) / cnt:
        res.append((uid, cnt, avg))
res.sort(key=lambda x: (-x[2], x[0]))
```

注意 `max(toks) > sum(toks)/cnt` 用的是未舍入的均值，和 `avg` 字段的舍入值无关——用户 1 若用 133.33 比较，200 仍大于它，本例不暴露差异，但边界数据（如均值 133.335）会翻车。

## 复杂度
时间：O(n) 扫一遍建分组，排序 O(k log k)，k 为用户数。
空间：O(n) 存每个用户的 tokens 列表，额外 O(k) 存结果。

## 易错点
- 用舍入后的 `avg_tokens`（如 133.33）去和 `tokens` 比较 → 均值恰为 x.xx5 时判定翻转 → 必须用 `SUM/COUNT` 原始值比较，只在输出列做 `ROUND`。
- 把「至少一条超过均值」写成 `AVG(tokens) > AVG(tokens)` 或漏掉 `MAX` → 条件恒假/恒真 → 正确写法是 `MAX(tokens) > AVG(tokens)`，等价于 `EXISTS (SELECT 1 ... WHERE tokens > avg)`。

## 如果面试官追问
问：如果要求输出「超过均值的那条 prompt 原文」怎么办？
答：聚合改成窗口函数 `AVG(tokens) OVER (PARTITION BY user_id)`，再在外层筛 `tokens > avg` 并保留 `prompt` 列。
