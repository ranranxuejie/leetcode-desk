## 一句话思路
每行先降序排序，再按列取 `max` 累加；因为每轮删的是各行当前最大值，排序后第 j 轮删的正是第 j 列。

## 怎么做
1. 对 `grid` 的每一行执行 `row.sort(reverse=True)`，让每行最大值落到下标 0。
2. 用 `zip(*grid)` 按列遍历，第 j 列就是第 j 轮从各行删掉的元素。
3. 每轮取 `max(col)` 累加到 `ans`。

以 `grid = [[1,2,4],[3,3,1]]` 为例：排序后变成 `[[4,2,1],[3,3,1]]`。第 0 列是 `(4,3)`，`max` 得 4；第 1 列是 `(2,3)`，得 3；第 2 列是 `(1,1)`，得 1。`ans = 4+3+1 = 8`。注意第二行有两个 3，排序后它们占据下标 0 和 1，正好对应前两轮各删一个，不会重复也不会漏。

```python
ans = 0
for row in grid:
    row.sort(reverse=True)
for col in zip(*grid):
    ans += max(col)
return ans
```

`zip(*grid)` 在 `m` 行长度都为 `n` 时产生 `n` 个元组，每个元组长度 `m`，所以内层 `max` 扫的是「这一轮各行删掉的数」。

## 复杂度
时间：每行排序 `m * n log n`，列扫描 `m * n`，总计 `O(m n log n)`。
空间：排序原地进行，`zip` 逐列产出元组，额外 `O(m)`（不计输入）。

## 易错点
- 输入 `[[1,2,4],[3,3,1]]` 若只对第一行排序、第二行保持原序，第 1 列会变成 `(2,3)` 之外的错位组合，答案可能算成 7 或 9。必须对**每一行**都排序，`for row in grid` 不能漏。
- 输入 `[[10]]`（`m=n=1`）时若用 `zip(*grid)` 却忘了 `grid` 是列表的列表、误写成 `zip(grid)`，会把整行当一列，`max` 拿到的是列表本身而报错。正确写法是 `zip(*grid)`，星号不能省。

## 如果面试官追问
问：如果 `m` 很大、`n` 很小，怎么优化？
答：改成对每行建大顶堆，每轮 `heappop` 一次取 `m` 个值求 `max`，时间降到 `O(m n + m n log n)` 的堆版本，但本题 `m,n ≤ 50` 排序已足够。
