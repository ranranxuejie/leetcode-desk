## 一句话思路
按顺序遍历 events，用 score 和 counter 两个变量累加，counter 到 10 立刻 break。

## 怎么做
1. 初始化 `score = 0`、`counter = 0`，用 `for e in events` 顺序扫描。
2. 先判 `e == "W"`：`counter += 1`，然后立刻检查 `if counter == 10: break`，因为停止条件是「计数器变为 10」而非「超过 10」。
3. 再判 `e in ("WD", "NB")`：两者都只让 `score += 1`，counter 不动。
4. 剩下的必然是数字串 `"0"/"1"/"2"/"3"/"4"/"6"`，直接 `score += int(e)`。

以示例 1 `["1","4","W","6","WD"]` 为例，走到第 3 个元素 `"W"` 时 counter 从 0 变 1，此时 `counter == 10` 不成立，继续；第 5 个 `"WD"` 让 score 从 11 变 12，最终 `[12, 1]`。

```python
score = counter = 0
for e in events:
    if e == "W":
        counter += 1
        if counter == 10:
            break
    elif e in ("WD", "NB"):
        score += 1
    else:
        score += int(e)
return [score, counter]
```

关键点：`break` 必须写在 `counter += 1` 之后、同一分支内，不能放到循环末尾统一判断——否则 counter 到 10 的那一轮里，后面的 `"WD"` 之类还会被误加。

## 复杂度
时间 O(n)：n 是 events 长度，最坏扫完全部；提前 break 只会更少。
空间 O(1)：只开 score、counter 两个整数，无额外容器。

## 易错点
- 输入 `["W"]*10 + ["4"]` → 若把 break 判断放在循环体末尾或漏写，会把末尾的 `"4"` 也加进 score，错成 `[4,10]`；正确做法是 counter 一到 10 立即 break，输出 `[0,10]`。
- 输入 `["WD","NB"]` → 若把 `"WD"` 当成 `"W"` 处理（比如用 `e.startswith("W")` 判断），counter 会错成 1、score 只加 1；正确做法是 `"W"` 用精确相等判断，`"WD"` 和 `"NB"` 单独归到加 1 分的分支。

## 如果面试官追问
问：如果 events 长度到 10^7 且要求流式处理怎么办？
答：逻辑不变，仍是单次遍历 O(1) 空间，只需把 events 换成迭代器逐个 `next`，counter 到 10 就停止拉取。
