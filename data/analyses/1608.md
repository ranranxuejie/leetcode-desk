## 一句话思路
排序后从大到小枚举 x，用 `bisect_left` 数出 ≥x 的个数，第一个相等即答案。

## 怎么做
1. 对 `nums` 升序排序，特征值 x 只可能落在 `[0, n]` 内。
2. 从 `x = n` 往下枚举到 0，用 `bisect_left(nums, x)` 得到下标 `i`，则 `n - i` 就是 ≥x 的元素个数。
3. 一旦 `n - i == x` 立即返回 x；枚举完返回 -1。

拿示例 3 `nums = [0,4,3,0,4]` 说：排序后 `[0,0,3,4,4]`，n=5。x=5 时 `bisect_left` 返回 5，个数 0≠5；x=4 返回 3，个数 2≠4；x=3 返回 2，个数 3==3，返回 3。

```python
from bisect import bisect_left

def specialArray(nums):
    nums.sort()
    n = len(nums)
    for x in range(n, -1, -1):
        i = bisect_left(nums, x)
        if n - i == x:
            return x
    return -1
```

关键点：`bisect_left` 返回第一个 ≥x 的位置，所以 `n - i` 恰好是 ≥x 的个数，不用手写计数。x 从 n 开始而不是从 `max(nums)` 开始，因为 x 可以大于所有元素（如 `[3,5]` 的答案 2 虽在数组内，但 `[0,0]` 的候选 x=1、2 都超出元素值域，必须覆盖到 n）。

## 复杂度
时间：排序 O(n log n) 主导，枚举 n+1 个 x 各做一次 O(log n) 二分，合计 O(n log n)。
空间：排序原地 O(1) 额外空间（不计排序栈），无额外数组。

## 易错点
- 输入 `[0,0]` → 若只枚举到 `max(nums)=0`，x=0 时个数 2≠0 就返回 -1，看似对；但换成 `[1,1]` 会漏掉 x=2 这个候选（个数 2==2 应返回 2），错成 -1。正确做法是枚举上界取 `n` 而非 `max(nums)`。
- 输入 `[3,6,7,7,0]` → 若用 `bisect_right` 或手写 `>=` 计数时把等于 x 的元素漏掉，x=4 会算成 2 个（实际 3 个：6、7、7），误判返回 4。正确做法是用 `bisect_left` 保证「≥」语义，`n - i` 含所有等于 x 的元素。

## 如果面试官追问
问：n 放大到 10^7 还排序吗？
答：改用计数数组（值域 ≤1000 或先压缩），从大到小累加后缀个数，O(n + V) 时间，避免 O(n log n)。
