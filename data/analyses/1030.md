## 一句话思路
把所有单元格坐标连同曼哈顿距离一起生成，按距离排序即可，因为题目只要求距离非降、同距离任意序。

## 怎么做
1. 双重循环枚举 `r in range(rows)`、`c in range(cols)`，把 `(abs(r-rCenter)+abs(c-cCenter), r, c)` 塞进列表。
2. 对列表按元组第一项排序，Python 元组比较天然只按距离排，同距离时按 `r`、`c` 兜底，仍合法。
3. 取排序结果的后两位还原成 `[r, c]`。

以示例 3（`rows=2, cols=3, rCenter=1, cCenter=2`）为例，生成的元组是 `(1,0,2)`、`(0,0,1)`、`(0,1,2)`、`(1,1,1)`、`(2,1,0)`、`(3,0,0)`；排序后前两项是 `(0,0,1)` 和 `(1,0,2)`，即距离 0 的 `[1,2]` 排在距离 1 的 `[0,2]` 之前。

```python
cells = []
for r in range(rows):
    for c in range(cols):
        cells.append((abs(r - rCenter) + abs(c - cCenter), r, c))
cells.sort()
return [[r, c] for _, r, c in cells]
```

关键点：距离在生成时就算好，排序阶段不再重复计算 `abs`，避免 `sort(key=...)` 里对每个元素再跑一次 lambda。

## 复杂度
时间：O(rows·cols·log(rows·cols))，排序主导，n = rows·cols。
空间：O(rows·cols)，存了每个单元格的三元组，返回值另算。

## 易错点
- 用 `sort(key=lambda x: x[0])` 只按距离排，同距离元素顺序取决于生成顺序，虽然本题合法，但若面试官要求「同距离按行优先」就错了 → 直接 `cells.sort()` 让元组整体比较，天然满足行优先。
- 把距离写成欧氏距离 `(r-rCenter)**2 + (c-cCenter)**2` 再开方 → 示例 2 中 `(0,0)` 与 `(1,1)` 到 `(0,1)` 的曼哈顿距离都是 1，但平方距离分别是 1 和 2，排序结果会变成 `[[0,1],[0,0],[1,0],[1,1]]`，与题目定义的曼哈顿距离不符 → 严格用 `abs` 相加。

## 如果面试官追问
问：若 rows、cols 放大到 10^5 但只需返回前 k 个最近单元格怎么办？
答：按距离 d 从 0 递增，枚举该层曼哈顿菱形上的点，凑够 k 个即停，避免全量排序。
