## 一句话思路
坐标只有 0..6，共 7³=343 个格点，直接按代 BFS 模拟并哈希去重，代数超过 343 仍无解即 -1。

## 怎么做
1. 把 points 转成元组集合 `cur`，若 target 在其中返回 0。
2. 每轮用 `cur` 中所有点两两配对（`i < j`），对每个坐标算 `(a[i]+b[i])//2`，收集进 `nxt`。
3. 把 `nxt` 并入 `cur`；若 target 在 `nxt` 中返回当前代数，否则代数 +1。
4. 若某轮 `nxt` 为空（`len(cur) < 2`）或代数超过 343，返回 -1。

以示例 2 为例：`cur={(0,0,0),(5,5,5)}`，第 1 轮唯一配对得 `nxt={(2,2,2)}`，不含 `(1,1,1)`；第 2 轮 `cur` 有 3 点，配对 `(0,0,0)+(2,2,2)` 得 `(1,1,1)`，返回 2。

```python
cur = {tuple(p) for p in points}
t = tuple(target)
if t in cur:
    return 0
gen = 0
while len(cur) >= 2 and gen <= 343:
    gen += 1
    lst = list(cur)
    nxt = set()
    for i in range(len(lst)):
        for j in range(i + 1, len(lst)):
            a, b = lst[i], lst[j]
            nxt.add(((a[0]+b[0])//2, (a[1]+b[1])//2, (a[2]+b[2])//2))
    if t in nxt:
        return gen
    cur |= nxt
return -1
```

## 复杂度
时间：每轮 O(|cur|²)，|cur| ≤ 343，总轮数 ≤ 343，最坏约 343³ 次配对，实际远小于此。
空间：`cur` 与 `nxt` 各存至多 343 个三元组，O(343)。

## 易错点
- 输入 `points=[[1,2,3]]`、`target=[5,5,5]` → 若循环里不判 `len(cur) >= 2`，会空转或对单点自配对 → 正确做法是配对用 `i < j` 且循环条件带 `len(cur) >= 2`，直接返回 -1。
- 输入 `points=[[0,0,0],[5,5,5]]`、`target=[1,1,1]` → 若每轮只用上一代 `nxt` 配对，第 2 轮拿不到 `(0,0,0)`，会错答 -1 → 正确做法是 `cur |= nxt`，配对范围是第 0 到第 k-1 代全部点。

## 如果面试官追问
问：坐标范围放大到 10⁹ 怎么办？
答：格点爆炸不能模拟，需按每维二进制位从低位往高位数「可生成」，逐维独立判断。
