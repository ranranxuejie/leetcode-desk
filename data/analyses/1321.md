## 一句话思路
先按 `visited_on` 聚合每日总额，再用窗口函数取当前行及前 6 行的滚动和，行号 ≥7 才输出。

## 怎么做
1. 先 `GROUP BY visited_on` 把同一天多笔交易（如 2019-01-10 的 130+150）合并成一行 `daily_amount`，否则窗口会按交易行数而非天数滑动。
2. 用 `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW` 求 7 行滚动和，因为日期已去重且连续，7 行即 7 天。
3. 用 `ROW_NUMBER()` 过滤掉前 6 行，保证窗口内恰好 7 天。
4. 平均值用 `ROUND(sum/7, 2)`，注意 MySQL 的 `ROUND` 与 Python 的 `round` 在 .5 处行为不同，示例中 860/7=122.857… 得 122.86 无歧义。

关键中间值：以 2019-01-10 为例，窗口覆盖 01-04 至 01-10，`daily_amount` 依次为 130、110、140、150、80、110、280（01-10 已合并），和为 1000，`1000/7 = 142.857…` → 142.86。

```python
# 思路伪代码（SQL 逻辑用 Python 表达）
daily = {}  # visited_on -> sum(amount)
for d, a in rows:
    daily[d] = daily.get(d, 0) + a
days = sorted(daily)
for i in range(6, len(days)):
    window = days[i-6:i+1]
    total = sum(daily[d] for d in window)
    print(days[i], total, round(total / 7, 2))
```

## 复杂度
时间：O(n log n)，n 为交易行数，排序去重后的日期占主导。
空间：O(d)，d 为不同日期数，用于存每日聚合结果。

## 易错点
- 输入 2019-01-10 有两笔交易（130、150）→ 若直接对原表开窗，会把两行算成两天，窗口错位 → 必须先 `GROUP BY visited_on` 聚合再开窗。
- 日期不连续时（如缺 01-05）→ 用 `ROWS` 按行数滑动会跨过空缺日期，把 8 个自然日算成 7 行 → 本题数据连续可接受，但严格应改用 `RANGE BETWEEN INTERVAL 6 DAY PRECEDING`，或先补全日期。

## 如果面试官追问
问：若日期有缺失怎么办？答：改用 `RANGE ... INTERVAL 6 DAY PRECEDING`，并只输出窗口内实际天数恰为 7 的行。
