## 一句话思路
用辗转相除代替逐次减法：每轮把大数一次性减到小于小数，商就是这一轮省下的操作数。

## 怎么做
1. 先处理边界：`num1 == 0 or num2 == 0` 时直接返回 0，否则 `num1 == num2` 会进入循环，商为 1、余数为 0，答案自然为 1。
2. 每轮保证 `num1 >= num2`，用 `num1 // num2` 得到这一轮能连续减的次数，累加进 `ans`。
3. 把 `num1` 更新为 `num1 % num2`，交换两数，让下一轮的大数仍在 `num1`。
4. 循环到 `num2 == 0` 为止，返回 `ans`。

以 `num1 = 2, num2 = 3` 为例：先交换成 `num1 = 3, num2 = 2`。第一轮 `3 // 2 = 1`，`ans = 1`，`num1 = 3 % 2 = 1`，交换后 `num1 = 2, num2 = 1`。第二轮 `2 // 1 = 2`，`ans = 3`，`num1 = 0`，结束，返回 3。注意第二轮商是 2 而不是 1：`2 - 1 = 1` 后还要再减一次才归零，逐次减法会走两步，这里一步算清。

```python
def countOperations(num1, num2):
    ans = 0
    while num1 and num2:
        if num1 < num2:
            num1, num2 = num2, num1
        ans += num1 // num2
        num1 %= num2
    return ans
```

关键点：`ans += num1 // num2` 必须在取模之前算，因为取模后 `num1` 已经变小，商的信息就丢了。

## 复杂度
时间：O(log(min(num1, num2)))，每轮取模至少让较小数减半，等价于辗转相除的轮数。
空间：O(1)，只用了 `ans` 和两个入参变量，没有额外容器。

## 易错点
- 输入 `num1 = 0, num2 = 5` → 若循环条件写成 `while num1 or num2`，会拿 0 做除数触发 `ZeroDivisionError` → 正确做法是循环条件用 `while num1 and num2`，任一为 0 立即停。
- 输入 `num1 = 10, num2 = 10` → 若先写 `num1 %= num2` 再累加商，`ans` 会漏掉这 1 次操作，输出 0 → 正确做法是先 `ans += num1 // num2` 再取模，商为 1、余数为 0，答案正好 1。

## 如果面试官追问
问：如果要求返回每一步的具体操作序列而不是次数呢？
答：把 `ans += num1 // num2` 展开成循环，每步记录 `(大数, 小数)` 并做一次减法，序列长度就是原答案，规模仍是 O(ans)。
