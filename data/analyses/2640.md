## 一句话思路
边扫边维护前缀最大值 `mx` 和分数累加值 `s`，第 i 项贡献 `nums[i] + mx`，直接追加到答案。

## 怎么做
1. 初始化 `mx = 0`、`s = 0`、`ans = []`，三者随扫描同步更新。
2. 对每个 `x` 先更新 `mx = max(mx, x)`，因为 `conver[i]` 用的是含 `nums[i]` 自身的前缀最大值。
3. 令 `s += x + mx`，此时 `s` 就是前缀 `nums[0..i]` 的分数。
4. 把 `s` 追加进 `ans`，扫完返回。

以 `nums = [2,3,7,5,10]` 为例：处理 `x = 7` 时 `mx` 从 3 变成 7，`s` 从 10 变成 `10 + 7 + 7 = 24`，对应输出第三项 24；接着 `x = 5` 时 `mx` 仍是 7，`s = 24 + 5 + 7 = 36`，注意这里 `mx` 没有回退。

```python
mx = 0
s = 0
ans = []
for x in nums:
    if x > mx:
        mx = x
    s += x + mx
    ans.append(s)
return ans
```

关键点：`mx` 只增不减，所以 `nums[i] + mx` 里 `mx` 可能远大于 `nums[i]`（如 `x = 5` 时加的是 7），这正是题目要的「前缀最大值」而非「当前值」。

## 复杂度
时间 O(n)：一次遍历，每步 O(1)。
空间 O(n)：除返回数组 `ans` 外只用了 `mx`、`s` 两个变量。

## 易错点
- 输入 `nums = [2,3,7,5,10]` → 若把 `mx` 写成「当前元素与前一元素取大」或每步重置，处理 `x = 5` 时会得到 `5 + 5 = 10` 而非 `5 + 7 = 12`，`s` 错成 34 → 正确做法是 `mx` 全程单调不减，只与历史最大值比较。
- 输入 `nums = [1,1,2,4,8,16]` → 若先算 `s += x` 再更新 `mx`，处理 `x = 2` 时 `mx` 还是 1，贡献算成 `2 + 1 = 3`，`s` 错成 7 而非 8 → 正确顺序是先 `mx = max(mx, x)` 再累加 `x + mx`。

## 如果面试官追问
问：若 `nums[i]` 可达 `10^18`、n 达 `10^7`，答案会溢出 64 位吗？
答：最坏 `s ≈ n * 2 * 10^18`，超 64 位，Python 大整数无碍，其他语言需按题意取模或换大数。
