## 一句话思路
用栈在线消除：栈顶连续同类型同色元素凑满 `groupSize[t]` 就弹出，因为任何可删组在消除时刻必然紧邻。

## 怎么做
1. 维护栈 `st`，每个元素存 `(type, color, cnt)`，`cnt` 是栈顶这段连续同色同类型元素的个数。
2. 遍历 `types[i], colors[i]`：若栈非空且栈顶 `type`、`color` 都相同，则 `cnt += 1`；否则压入新段 `(t, c, 1)`。
3. 压入或累加后检查栈顶 `cnt == groupSize[t]`，成立就 `pop()`，让左右两段重新相邻。
4. 遍历结束栈空则 `True`。

以示例 1 为例：`i=0` 压 `(0,5,1)`；`i=1` 压 `(1,3,1)`；`i=2` 栈顶同型同色，变 `(1,3,2)`，`groupSize[1]=2` 命中，弹出；`i=3` 压 `(0,5,1)`，此时栈顶下方是 `(0,5,1)`，合并成 `(0,5,2)`，`groupSize[0]=2` 命中，弹出，栈空返回 `True`。

```python
st = []
for t, c in zip(types, colors):
    if st and st[-1][0] == t and st[-1][1] == c:
        st[-1][2] += 1
    else:
        st.append([t, c, 1])
    if st[-1][2] == groupSize[t]:
        st.pop()
return not st
```

关键点：弹出后不需要主动合并新栈顶与更下一层，因为下一轮循环压入时自然会和当前栈顶比较；但若弹出后栈顶两段本就同型同色，说明它们之前被中间段隔开，中间段已消失，此时它们其实应合并——所以更稳的写法是弹出后立即再检查一次合并，或把合并逻辑放在循环开头统一处理。示例 1 中 `i=3` 的合并正是靠「压入时与栈顶比较」完成的，因为弹出后栈顶已是 `(0,5,1)`。

## 复杂度
时间 O(n)：每个元素最多入栈出栈各一次，`zip` 遍历 n 个。
空间 O(n)：栈最坏存 n 段，每段 3 个整数。

## 易错点
- 输入 `types=[0,1,0], colors=[9,9,9], groupSize=[3,2]`：若只看类型连续而不看颜色，会误判 `[0,1,0]` 中类型 0 不连续；正确做法是栈顶必须 `type` 和 `color` 同时相等才累加 `cnt`。
- 输入 `types=[2,0,1,2], colors=[7,5,4,7], groupSize=[3,1,2]`：删掉下标 2 的 `(1,4)` 后，剩下 `[2,0,2]` 类型 2 被 0 隔开，若弹出后不重新比较栈顶两段，会漏掉「0 无法消除导致整体失败」；正确做法是弹出后让新栈顶与更下层在下一轮压入时正确合并，最终栈非空返回 `False`。

## 如果面试官追问
要求输出删除顺序的方案怎么办？答：栈里每段额外存原始下标列表，弹出时把这段下标按序追加到答案，最后栈空即得合法序列。
