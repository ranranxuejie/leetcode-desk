## 一句话思路
用单调栈维护一段「尚未结算的高度」：每遇到比栈顶矮的柱子就弹出并结算差值，答案就是所有上升沿的增量之和。

## 怎么做
1. 把问题看成直方图：`target[i]` 是第 i 根柱子的高度，一次操作 = 给一段连续区间整体加 1，等价于「用最少的水平刷子涂满直方图」。
2. 关键结论：答案 = 从左到右扫描时，所有 `target[i] - target[i-1]` 中正数部分之和（`target[-1]` 视为 0）。因为每段新抬升的高度都必须由新的操作层数补齐，而下降部分可以复用之前的层。
3. 用单调栈实现更直观：栈里存递增的高度，遇到 `target[i] < 栈顶` 就弹出，弹出时把 `栈顶 - max(target[i], 新栈顶)` 累加进答案。

以 `target = [3,1,5,4,2]` 为例，扫描到 `5` 时栈为 `[1,5]`，答案已累计 `3 + 4 = 7`；后面 `4`、`2` 依次弹出，每次弹出的差值都被 `1` 挡住，不再新增，最终答案 `7`。

```python
ans = 0
stack = []
for h in target:
    while stack and stack[-1] > h:
        top = stack.pop()
        ans += top - max(h, stack[-1] if stack else 0)
    if not stack or stack[-1] < h:
        stack.append(h)
```

上面这段是核心逻辑，`stack` 始终保持严格递增，`max(h, stack[-1])` 保证只结算真正「露出来」的那部分高度。

## 复杂度
时间：O(n)，每个元素最多入栈出栈各一次，n 为 `target` 长度。
空间：O(n)，最坏情况（严格递增如 `[1,2,3,...]`）栈存满 n 个元素。

## 易错点
- 输入 `target = [3,1,1,2]` → 若只写 `ans += top - h` 而漏掉 `max(h, stack[-1])`，弹出 `3` 时会把 `3-1=2` 全算进去，但实际 `1` 那层已被前面的 `1` 覆盖，正确增量是 `3-1=2` 这里恰好对，换成 `[5,3,4]` 就会多算 → 必须用 `max(h, 栈顶)` 挡住被下层遮住的部分。
- 输入 `target = [1,1,1,1]` → 若用 `stack[-1] <= h` 才入栈，会把相等的 `1` 重复压栈，弹出时算出 `1-1=0` 虽不致命，但若写成 `ans += top - h` 且栈里堆了多个相等值，逻辑会乱 → 相等高度直接跳过，只在 `stack[-1] < h` 时入栈。

## 如果面试官追问
问：要求输出具体操作方案（每步的区间）怎么办？
答：在弹出结算时记录区间 `[该高度的起始下标, i-1]`，按高度从低到高输出即可。
