## 一句话思路
用 `target and target + mechanicalAccumulator(target - 1)` 短路求值代替 if，递归到 0 返回 0。

## 怎么做
1. 递归函数只做一件事：`target == 0` 时返回 0，否则返回 `target + f(target - 1)`。
2. 用 `and` 的短路特性替代条件判断：`target` 为 0 时整个表达式直接得 0，不再递归。
3. 以 `target = 5` 为例，展开为 `5 and 5 + f(4)`，`5` 为真继续算，一路到 `f(0)` 得 0，回传 `1+0=1`、`2+1=3`、`3+3=6`、`4+6=10`、`5+10=15`。
4. 关键中间值：`f(1)` 返回 `1 and 1 + f(0)` = `1 + 0` = 1，这是递归的基准回传点。

```python
def f(n):
    return n and n + f(n - 1)

# target = 5 时：
# f(0) = 0
# f(1) = 1 and 1 + 0 = 1
# f(2) = 2 and 2 + 1 = 3
# f(5) = 5 and 5 + 10 = 15
```

`and` 返回的是操作数本身而非布尔值：`0 and x` 得 `0`，`n and x`（n 非 0）得 `x`，正好当条件分支用。

## 复杂度
时间：O(target)，递归深度 target，每层一次加法。
空间：O(target)，递归调用栈占 target 层，无额外数组。

## 易错点
- 写成 `return n and n + f(n - 1) or 0`：`target = 5` 时结果仍是 15 看不出问题，但 `n = 0` 时 `0 and ...` 已得 0，`or 0` 多余；更危险的是若误写成 `n + f(n - 1) and n`，`target = 5` 会返回 5 而非 15，因为 `and` 返回最后一个真值操作数。
- 用 `target * (target + 1) // 2` 直接套公式：违反「不具备乘除」约束，`target = 10000` 时虽答案 50005000 正确，但面试判违规；必须走纯加法递归。

## 如果面试官追问
问：target 放大到 10**6 递归会栈溢出怎么办？
答：改写成尾递归形式或手动展开为循环累加，Python 默认递归上限约 1000 层。
