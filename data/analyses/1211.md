## 一句话思路
按 `query_name` 分组，用 `AVG(rating/position)` 算质量、`AVG(rating<3)*100` 算劣质占比，再 `ROUND(...,2)`。

## 怎么做
1. 先 `GROUP BY query_name`，把同一查询名的行聚到一起。
2. 质量用 `AVG(rating / position)`，注意除法要先转浮点，否则整数除法会把 `5/2` 算成 2。
3. 劣质占比用 `AVG(rating < 3) * 100`，布尔值在聚合里当 0/1 用，比 `SUM(CASE WHEN...)` 短。
4. 两个结果都套 `ROUND(x, 2)`。

以 Dog 为例：三行 `rating/position` 分别是 `5/1=5.0`、`5/2=2.5`、`1/200=0.005`，`AVG` 得 `(5.0+2.5+0.005)/3 = 2.5016...`，`ROUND` 后 `2.50`；`rating<3` 只有 Mule 一行成立，`AVG` 得 `1/3`，乘 100 得 `33.33`。

```python
# 假设用 pandas 模拟 SQL 聚合
df["ratio"] = df["rating"] / df["position"]          # 必须浮点除
df["poor"] = (df["rating"] < 3).astype(float)
g = df.groupby("query_name")
out = g.agg(quality=("ratio", "mean"), poor=("poor", "mean"))
out["quality"] = out["quality"].round(2)
out["poor_query_percentage"] = (out["poor"] * 100).round(2)
```

关键点：`rating / position` 在 Python 里 `/` 本身就是浮点除，不会踩整数除法的坑；但若写成 SQL 且两列都是 int，某些方言会截断，需 `rating * 1.0 / position`。

## 复杂度
时间：O(n)，n 为 Queries 行数，分组与两次聚合各扫一遍。
空间：O(k)，k 为不同 query_name 数，存分组结果。

## 易错点
- 输入里 `position=200, rating=1` 这种行 → 若用整数除法 `1//200` 得 0，Dog 的质量会算成 `(5+2+0)/3=2.33` 而非 `2.50` → 除法前转浮点。
- 劣质占比的分母是**该 query_name 的行数**而非全表行数 → 若误用全表 6 行做分母，Dog 会得 `1/6*100=16.67` 而非 `33.33` → 分母必须跟着 `GROUP BY` 走。

## 如果面试官追问
问：如果要求质量按 `position` 加权平均而非简单平均？答：把 `AVG(rating/position)` 改成 `SUM(rating)/SUM(position)`，其余不变。
