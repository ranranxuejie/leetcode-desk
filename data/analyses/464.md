## 一句话思路
用位掩码记录已选数字，记忆化搜索当前局面是否必赢；因为剩余可选集合完全由掩码决定，与选数顺序无关。

## 怎么做
1. 先判两个直接胜负：`desiredTotal == 0` 返回 `True`；`maxChoosableInteger*(maxChoosableInteger+1)//2 < desiredTotal` 返回 `False`。
2. 状态用 `mask`（第 i 位表示数字 i+1 已用）和 `cur`（当前累计和）表示，`cur` 可由 `mask` 推出，但直接传更省事。
3. 对每个未用数字 i，若 `cur+i+1 >= desiredTotal` 立即返回 `True`；否则递归对手，若对手返回 `False` 则当前必赢。
4. 用 `lru_cache` 缓存 `(mask, cur)`，避免重复搜索。

以 `maxChoosableInteger=10, desiredTotal=11` 为例：先手选 1 后 `mask=1, cur=1`，对手可选 10，`cur+10=11 >= 11` 直接赢，所以先手选 1 返回 `False`；遍历所有选择都返回 `False`，最终答案 `False`。

```python
from functools import lru_cache

@lru_cache(None)
def dfs(mask, cur):
    for i in range(maxChoosableInteger):
        if not (mask >> i) & 1:
            if cur + i + 1 >= desiredTotal:
                return True
            if not dfs(mask | (1 << i), cur + i + 1):
                return True
    return False

return dfs(0, 0)
```

## 复杂度
时间：`O(2^n * n)`，n = `maxChoosableInteger`，每个状态枚举 n 个数字。
空间：`O(2^n)` 个缓存状态，每个存一个布尔值。

## 易错点
1. `desiredTotal=0` 时 → 若直接进入 `dfs(0,0)`，循环里 `cur+i+1 >= 0` 恒真，返回 `True` 看似对，但若先判总和不足会误返回 `False` → 正确做法是先单独判 `desiredTotal == 0` 返回 `True`。
2. `maxChoosableInteger=20` 时 → 若用 `mask` 但忘记 `cur` 可由 `mask` 推出而重复传参导致缓存键冗余 → 正确做法是只缓存 `mask`，`cur` 用预计算数组 `sum_of_mask` 或直接传但保证一致性。

## 如果面试官追问
问：若 `maxChoosableInteger` 扩大到 30 怎么办？
答：`2^30` 状态爆炸，需改用数学结论：总和不足则先手必输，否则先手通常赢，仅少数边界需特判。
