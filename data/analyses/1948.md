## 一句话思路
自底向上给每个文件夹算一个「子结构签名」，同签名出现两次以上就整棵剪掉，最后 DFS 收集幸存路径。

## 怎么做
1. 把 paths 建成字典树，节点用 `dict` 存子节点，根为空串。
2. 后序 DFS 返回签名：子节点按名字排序后拼成 `name(子签名)` 串；叶子返回 `""`。
3. 用哈希表记签名出现次数，第二次出现时把该节点标记 `dead`。
4. 再 DFS 一次，遇到 `dead` 就整枝跳过，否则把当前路径加入答案。

以示例 4 为例：`/a/x` 和 `/b/x` 都只有子节点 `y`，签名都是 `"y()"`，第二次算到 `/b/x` 时计数变 2，`/b/x` 被标 `dead`。随后 `/a` 的签名是 `"x(y())z()"`，`/b` 也是 `"x(y())z()"`——注意这里用的是**子节点名字 + 子签名**，`x` 的签名虽然相同但节点已死，签名本身不变，所以 `/a`、`/b` 仍被判重，全部删除，输出 `[]`。

```python
def dfs(node):
    parts = []
    for name in sorted(node):
        parts.append(name + "(" + dfs(node[name]) + ")")
    sig = "".join(parts)
    if sig:
        cnt[sig] = cnt.get(sig, 0) + 1
        if cnt[sig] >= 2:
            node["#dead"] = True
    return sig
```

关键点：`if sig:` 保证空文件夹不参与判重（示例 5 的 `/a/z`、`/b/z` 都是空，不能删）；`node["#dead"]` 挂在节点上，第二次 DFS 直接查。

## 复杂度
时间 O(S log S)：S 为所有文件夹名字总长，排序子节点贡献 log。
空间 O(S)：字典树 + 签名串 + 计数哈希表，签名串总长与树同阶。

## 易错点
- 空文件夹参与判重 → 示例 5 会把 `/a/z`、`/b/z` 误删 → 签名返回 `""` 时不写计数表，只有非空签名才 `cnt[sig] += 1`。
- 只比较直接子文件夹名、不递归比较结构 → 示例 4 中 `/a` 与 `/b` 子名都是 `x,z`，会漏判 → 签名必须拼接子节点的完整签名 `name(子签名)`，让结构差异体现在串里。
- 边 DFS 边删 → 父节点签名会因已删子节点而变化，导致示例 4 的 `/a`、`/b` 不再相同 → 先完整算完所有签名并标记，再单独跑一次收集 DFS。

## 如果面试官追问
问：paths 规模到 10^6 怎么办？答：签名串会爆内存，改用「子签名哈希值」做签名（双哈希防冲突），把字符串比较换成整数比较。
