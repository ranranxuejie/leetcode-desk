## 一句话思路
对 k 二分：nonPositive 随 k 增大单调不增、k² 单调增，故条件单调，二分找最小可行 k。

## 怎么做
1. 确定二分下界 `lo = 1`、上界 `hi = max(nums)`（k 取 max 时每个元素一次归零，nonPositive = n ≤ k² 必成立）。
2. 对每个 `mid` 计算 `ops = sum((x + mid - 1) // mid for x in nums)`，即每个元素需要的向上取整次数。
3. 若 `ops <= mid * mid` 则 `hi = mid`，否则 `lo = mid + 1`，循环到 `lo == hi`。
4. 返回 `lo`。

以 `nums = [3,7,5]` 为例，`lo=1, hi=7`。第一次 `mid=4`：`ops = 1+2+2 = 5`，而 `4*4=16`，5 ≤ 16 成立，`hi=4`。接着 `mid=2`：`ops = 2+4+3 = 9`，`2*2=4`，9 > 4 不成立，`lo=3`。再 `mid=3`：`ops = 1+3+2 = 6`，`3*3=9`，6 ≤ 9 成立，`hi=3`，收敛到 3。

```python
lo, hi = 1, max(nums)
while lo < hi:
    mid = (lo + hi) // 2
    ops = 0
    for x in nums:
        ops += (x + mid - 1) // mid
    if ops <= mid * mid:
        hi = mid
    else:
        lo = mid + 1
return lo
```

关键点：`(x + mid - 1) // mid` 就是 `ceil(x / mid)`，别写成 `x // mid`，否则 `x=7, mid=3` 会得 2 而非 3。

## 复杂度
时间：O(n log(max(nums)))，n 来自每次二分遍历数组，log 来自二分次数。
空间：O(1)，只开了 lo、hi、mid、ops 几个标量。

## 易错点
- 上界取成 `10**5` 或 `sum(nums)` 也能过，但取 `max(nums)` 更紧；若误取 `min(nums)`，如 `nums=[1,100000]` 时 `hi=1`，`ops=100001 > 1`，二分区间直接不含答案，返回错误值。
- 用 `x // mid` 代替向上取整：`nums=[3,7,5], mid=3` 时 `ops` 算成 `1+2+1=4 ≤ 9` 仍成立，但 `mid=2` 时算成 `1+3+2=6 > 4`，边界判断被扭曲，可能返回 2 而非 3；必须用 `(x + mid - 1) // mid`。

## 如果面试官追问
问：若 nums 长度升到 10^7 且要求 O(n) 一次扫描？
答：条件 `sum(ceil(x/k)) ≤ k²` 对 k 单调，可先估 k ≈ sqrt(sum) 附近再局部调整，但严格最坏仍需二分，实际用并行求和降常数。
