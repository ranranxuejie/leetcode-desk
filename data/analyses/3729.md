## 一句话思路
前缀和取模后，同余的两两配对即和为 k 倍数的子数组，用哈希表边扫边计数。

## 怎么做
1. 维护 `pre` = 当前前缀和模 k，哈希表 `cnt` 记录每个余数出现次数，初始 `cnt = {0: 1}`（空前缀）。
2. 遍历 `nums`，每步 `pre = (pre + x) % k`，答案累加 `cnt.get(pre, 0)`，再把 `pre` 计数加一。
3. 用示例 2 走一遍：`nums = [2,2,2,2,2,2], k = 6`。前三个 2 后 `pre = 6 % 6 = 0`，此时 `cnt[0] = 1`（初始那个），累加 1，`cnt[0]` 变 2；第六个 2 后 `pre` 又回到 0，累加 2，总共 3？——注意这里 `pre` 序列是 2,4,0,2,4,0，只有两个 0，第一个 0 配对初始 0 得 1，第二个 0 配对第一个 0 得 1，合计 2，与输出一致。
4. 关键点：`pre` 必须每步取模，不能攒大前缀和，`nums[i]` 到 1e9、n 到 1e5，累加会到 1e14，虽 Python 不溢出但哈希键会爆炸。

```python
cnt = {0: 1}
pre = 0
ans = 0
for x in nums:
    pre = (pre + x) % k
    ans += cnt.get(pre, 0)
    cnt[pre] = cnt.get(pre, 0) + 1
return ans
```

## 复杂度
时间 O(n)：一次遍历，每步哈希操作均摊 O(1)。
空间 O(min(n, k))：哈希表最多存 n 个不同余数。

## 易错点
- `nums = [3], k = 3`：若忘记初始 `cnt = {0: 1}`，`pre = 0` 时查不到配对，答案错成 0；正确做法是先把空前缀余数 0 计入。
- `nums = [2,2,2,2,2,2], k = 6`：若把「不同子数组」理解成按数值去重（题面示例 2 的「只计数一次」容易误读），会错成 1；实际是按位置区分的连续段，两个长度 3 的段各算一次，答案 2。

## 如果面试官追问
若 k 很大（如 1e9）而 n 只有 1e5，哈希表会不会退化？答：不会，键数受 n 限制，空间 O(n)，与 k 无关。
