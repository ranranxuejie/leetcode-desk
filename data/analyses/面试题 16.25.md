## 一句话思路
哈希表存 key→节点，双向链表按访问顺序排列，get/put 都把节点移到头部，尾部即最久未用。

## 怎么做
1. 建 `self.map = {}` 和带 `prev/next` 的哨兵头尾节点，`head` 侧是最近使用，`tail.prev` 是最久未用。
2. `get(key)`：不在 `map` 返回 -1；在则把该节点摘出、插到 `head` 后，返回 `node.val`。
3. `put(key, value)`：key 已存在则改值并移到头部；否则新建节点插头部、写入 `map`，若 `len(map) > capacity` 就删 `tail.prev` 并从 `map` 中移除其 key。
4. 摘除与插入各写成一个 4 行的小函数，避免在 get/put 里重复改指针。

以官方示例容量 2 走关键一步：`put(1,1)`、`put(2,2)` 后链表头→尾为 `2,1`；`get(1)` 命中，把 1 移到头部，链表变为 `1,2`，此时 `tail.prev` 是 2；接着 `put(3,3)` 触发淘汰，删掉的正是 2，所以后面 `get(2)` 返回 -1。

```python
def _remove(self, node):
    node.prev.next, node.next.prev = node.next, node.prev

def _add_front(self, node):
    node.next, node.prev = self.head.next, self.head
    self.head.next.prev = node
    self.head.next = node

def get(self, key):
    if key not in self.map:
        return -1
    node = self.map[key]
    self._remove(node); self._add_front(node)
    return node.val
```

## 复杂度
时间：get 和 put 均为 O(1)，哈希查找与链表摘插都是常数次指针操作。
空间：O(capacity)，`map` 存 capacity 个键，链表含同样多节点加两个哨兵。

## 易错点
1. `put` 一个已存在的 key（如容量 2 时再 `put(1, 9)`）→ 若只改 `node.val` 不移动节点，1 仍停在尾部，下次淘汰会误删刚更新的它 → 必须改值后同样执行 `_remove` + `_add_front`。
2. 容量为 1 时 `put` 新 key → 若先插新节点再判断超容，`tail.prev` 可能指向刚插入的节点，把新数据删掉 → 必须先插头部、再检查 `len(map) > capacity` 并删 `tail.prev`，顺序不能反。

## 如果面试官追问
问：要求淘汰时返回被淘汰的 (key, value)？
答：节点里多存一个 `key` 字段，删 `tail.prev` 前先读它的 `key` 和 `val` 返回即可，复杂度不变。
