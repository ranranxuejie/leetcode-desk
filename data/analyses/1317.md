## 一句话思路
从 a=1 开始枚举，检查 a 和 n-a 的十进制是否都不含 0，第一个命中即答案。

## 怎么做
1. 令 `a` 从 1 递增到 `n-1`，`b = n - a`。
2. 写一个判定函数 `no_zero(x)`：循环 `x % 10`，遇到 0 返回 `False`，否则 `x //= 10`，直到 `x == 0`。
3. 当 `no_zero(a) and no_zero(b)` 同时为真，立即返回 `[a, b]`。

以 `n = 1010` 为例：`a = 1` 时 `b = 1009`，`no_zero(1009)` 在取到十位 0 时返回 `False`；继续枚举到 `a = 11`，`b = 999`，两者都不含 0，返回 `[11, 999]`。关键中间值就是 `a = 11, b = 999` 这一对。

```python
def no_zero(x):
    while x:
        if x % 10 == 0:
            return False
        x //= 10
    return True

a = 1
while True:
    b = n - a
    if no_zero(a) and no_zero(b):
        return [a, b]
    a += 1
```

枚举上界不必担心：`n <= 10^4`，且 `a = 1` 时 `b = n-1`，只要 `n-1` 不含 0 就一步命中；最坏情况也只是几百次尝试。

## 复杂度
时间：O(n · log n)，枚举 a 最多 n 次，每次判定两位数的位数。
空间：O(1)，只用了 `a`、`b` 和循环里的余数。

## 易错点
- 输入 `n = 2` → 若从 `a = 0` 开始枚举，`no_zero(0)` 里 `while 0` 直接跳过返回 `True`，会错答 `[0, 2]`，但 0 不是正整数 → `a` 必须从 1 起。
- 输入 `n = 10000` → 若只检查 `a` 不检查 `b`，`a = 1` 时 `b = 9999` 恰好合法看不出问题；但 `n = 1010` 时 `a = 1` 会返回 `[1, 1009]`，`b` 含 0 → 两个数都要过 `no_zero`。

## 如果面试官追问
问：n 放大到 10^9 还枚举吗？
答：仍可枚举，但改成从 `a = 1` 起按位构造无零数，或直接取 `a = 1`、`b = n-1` 再逐位修补 0，避免线性扫描。
