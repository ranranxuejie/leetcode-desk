## 一句话思路
用 `dp[i]` 记录跳到第 i 块石子时所有可能的上一跳距离集合，逐个石子向后转移。

## 怎么做
1. 建 `pos = {v: i for i, v in enumerate(stones)}`，把石子值映射到下标，后面查「跳 k 步落点是否存在」是 O(1)。
2. `dp = [set() for _ in stones]`，`dp[0] = {0}`，把起点的「上一跳距离」记成 0，这样第一步 `k-1/k/k+1` 里只有 1 合法。
3. 遍历 `i`，对 `dp[i]` 里每个 `k`，枚举 `nk in (k-1, k, k+1)`，`nk > 0` 且 `stones[i]+nk in pos` 时把 `nk` 加进 `dp[pos[stones[i]+nk]]`。
4. 最后返回 `bool(dp[-1])`。

以示例 1 为例，处理到 `i=3`（`stones[3]=5`）时 `dp[3]={2}`（从 3 跳 2 过来）；由 `k=2` 得 `nk∈{1,2,3}`，`5+3=8` 在 `pos` 中，于是 `dp[5]` 收下 3。这一步正是通往 `12→17` 的关键分支。

```python
pos = {v: i for i, v in enumerate(stones)}
dp = [set() for _ in stones]
dp[0] = {0}
for i in range(len(stones)):
    for k in dp[i]:
        for nk in (k - 1, k, k + 1):
            if nk > 0 and stones[i] + nk in pos:
                dp[pos[stones[i] + nk]].add(nk)
return bool(dp[-1])
```

## 复杂度
时间 O(n²)：每个石子最多收 O(n) 种距离，每种试 3 个 `nk`。
空间 O(n²)：`dp` 里最多存 n 个集合、每个至多 n 个距离。

## 易错点
- `stones=[0,1,2,3,4,8,9,11]` → 若把 `dp[0]` 初始化成 `{1}` 再直接按 `k-1/k/k+1` 转移，起点会凭空多出 0 和 2 两条非法首跳，可能误判可达 → 正确做法是 `dp[0]={0}`，靠 `nk > 0` 过滤掉 0 和负数。
- `stones=[0,2]` → 若只判断 `stones[i]+nk in pos` 而不检查 `nk > 0`，`k=0` 时 `nk=-1` 会被 `in pos` 挡掉但 `nk=0` 会自环，浪费且逻辑混乱 → 显式写 `nk > 0`，同时保证首跳只能是 1。

## 如果面试官追问
问：n 放大到 2×10⁴ 怎么办？
答：`dp` 集合改成按 `(i, k)` 记忆化 DFS，只展开真实可达状态，实际远小于 n²。
