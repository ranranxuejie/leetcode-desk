## 一句话思路
把 `(heights[i], names[i])` 打包成对，按身高降序排序后取名字，用身高做排序键避免下标错位。

## 怎么做
1. 用 `zip(heights, names)` 把身高和名字绑成元组，身高在前当排序键。
2. 对元组列表按第一个元素降序排序，`reverse=True` 或 `key=lambda p: -p[0]`。
3. 遍历排序结果，取每个元组的第二个元素 `p[1]` 收集成结果列表。

以示例 1 为例：`zip` 后得到 `[(180,"Mary"),(165,"John"),(170,"Emma")]`，降序排序后为 `[(180,"Mary"),(170,"Emma"),(165,"John")]`，取 `p[1]` 得 `["Mary","Emma","John"]`。

```python
pairs = sorted(zip(heights, names), reverse=True)
return [name for _, name in pairs]
```

注意 `zip(heights, names)` 的顺序：身高在前，`reverse=True` 才会按身高降序；若写成 `zip(names, heights)`，排序键变成字符串，结果全错。

## 复杂度
时间 O(n log n)：排序贡献 log n，n 来自人数。
空间 O(n)：`pairs` 存 n 个元组，结果列表再存 n 个名字。

## 易错点
1. 输入 `names=["Alice","Bob","Bob"], heights=[155,185,150]` → 若用 `names.sort(key=heights.index)` 之类按下标反查，两个 `"Bob"` 会因 `index` 只返回第一个匹配位置而错位 → 正确做法是先把身高和名字 zip 成元组再排序，让每个名字带着自己的身高走。
2. 输入 `heights=[180,165,170]` → 若写成 `zip(names, heights)` 再 `reverse=True`，排序键是名字字符串，输出会变成按字母倒序而非身高 → 正确做法是确保元组第一个元素是 `heights[i]`。

## 如果面试官追问
问：若身高允许重复，要求同身高保持原数组顺序怎么办？
答：`sorted` 是稳定排序，用 `key=lambda p: -p[0]` 即可，同身高自动保留原序。
