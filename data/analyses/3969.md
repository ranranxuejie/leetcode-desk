## 一句话思路
枚举左端点 l，向右累加 sum，边加边判首位和末位是否都等于 x，n≤1500 允许 O(n²)。

## 怎么做
1. 外层 `for l in range(n)` 固定左端点，内层 `for r in range(l, n)` 向右扩展。
2. 内层维护累加变量 `s += nums[r]`，避免每次重算区间和。
3. 对每个 `s` 判末位 `s % 10 == x`，再判首位：反复 `// 10` 直到 `< 10`。
4. 两个条件都成立就 `ans += 1`。

以 `nums = [1,100,1], x = 1` 为例，l=0 时：r=0 得 s=1，末位 1、首位 1，计数；r=1 得 s=101，末位 1、首位 1，计数；r=2 得 s=102，末位 2 淘汰。l=1 时 r=1 得 s=100（末位 0 淘汰），r=2 得 s=101 计数；l=2 时 s=1 计数，共 4。

```python
n = len(nums)
ans = 0
for l in range(n):
    s = 0
    for r in range(l, n):
        s += nums[r]
        if s % 10 != x:
            continue
        t = s
        while t >= 10:
            t //= 10
        if t == x:
            ans += 1
return ans
```

关键点：`s % 10` 先做廉价剪枝，只有末位命中才进 `while` 求首位，省掉大量除法。

## 复杂度
时间 O(n² · log S)：n² 个子数组，每个求首位最多除 log₁₀S 次，S 为总和。
空间 O(1)：只开 `s`、`t`、`ans` 三个标量。

## 易错点
- 输入 `nums = [10], x = 1` → 若只判 `s % 10 == x` 就计数，会把 10 算成有效 → 必须再求首位，10 的首位是 1 但末位是 0，应淘汰。
- 输入 `nums = [1], x = 1` → 若首位循环写成 `while t > 10`，t=1 时循环不执行、t 仍是 1 恰好对；但换成 `nums=[9], x=9` 时若写成 `while t >= 10: t //= 10` 后忘记比较，或把单 digit 的 s 直接跳过 → 会漏掉所有一位数子数组 → 循环条件用 `t >= 10`，循环后无条件比较 `t == x`。

## 如果面试官追问
若 n 放大到 10⁵ 怎么办？答：末位条件等价于前缀和模 10 相等，首位条件需按数量级分桶统计前缀和，配合哈希把 O(n²) 降到 O(n log S)。
