## 一句话思路
每个时间单位独立：先求单时刻最少开几盏灯达到 brightness，再乘区间并集总长度。

## 怎么做
1. 单时刻问题：n 个位置，一盏灯照亮自身及左右各一格，求覆盖 ≥ brightness 个位置的最少灯数 k。
2. 贪心：从左往右，第一个未覆盖位置 i 必须在 i+1 放灯（放 i 或 i-1 会浪费右侧覆盖），每放一盏覆盖 3 格，直到覆盖数 ≥ brightness。
3. 由 k 反推：k 盏灯最多覆盖 min(n, 3k) 格，故 k = ceil(brightness / 3)，但 k 盏灯要放得下且覆盖不越界——n 个位置最多容纳 ceil(n/3) 盏互不重叠的灯，所以 k = min(ceil(brightness/3), ceil(n/3))，再验证 3k ≥ brightness 是否仍成立（k 被 n 限制时可能不足，此时无解，但题面保证 brightness ≤ n 且灯可相邻放置，实际总能达到，故 k = ceil(brightness/3) 且需 3k 覆盖不超 n，即 k ≤ ceil(n/3) 自动满足）。
4. 区间并集：把 intervals 按 start 排序，合并重叠/相邻区间，累加每段长度 L，答案 += k * L。

以示例 1 为例：n=5, brightness=5，k = ceil(5/3) = 2；区间 [6,12] 长度 7；答案 2*7 = 14。示例 3：brightness=2，k = ceil(2/3) = 1；[1,3] 与 [2,4] 合并为 [1,4] 长度 4；答案 1*4 = 4。

```python
k = (brightness + 2) // 3
intervals.sort()
total = 0
cur_s, cur_e = intervals[0]
for s, e in intervals[1:]:
    if s <= cur_e + 1:
        cur_e = max(cur_e, e)
    else:
        total += (cur_e - cur_s + 1) * k
        cur_s, cur_e = s, e
total += (cur_e - cur_s + 1) * k
```

注意 `s <= cur_e + 1` 用 `+1` 是因为闭区间相邻（如 [0,0] 和 [1,1]）也应合并，否则示例 2 会算成两段各乘 k，虽然结果碰巧对，但逻辑上应合并。

## 复杂度
时间：排序 O(m log m)，m = intervals.length；扫描 O(m)。
空间：排序额外 O(log m) 栈空间，其余 O(1)。

## 易错点
- intervals 的端点可达 10^9 而 n ≤ 10^6：区间长度可能远超 n，但灯只在 0..n-1 内，长度 L 直接乘 k 仍正确（每个时间单位独立，灯位可重复使用），不要误以为要截断到 n。
- 相邻区间 [0,0] 和 [1,1]：若用 `s <= cur_e` 判断会分成两段，各乘 k 得 2k；正确用 `s <= cur_e + 1` 合并成一段长度 2，结果 2k 相同但语义错——若 k 计算依赖段数就会翻车，务必合并。

## 如果面试官追问
若要求输出具体灯位方案？答：对每个合并后的时间单位，从位置 1 开始每隔 3 格放一盏，共 k 盏，覆盖 3k 格 ≥ brightness。
