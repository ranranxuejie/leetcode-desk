## 一句话思路
排序后从左往右贪心：每个位置取 `min(arr[i], 前一个值+1)`，第一个位置强制为 1，这样每个元素都尽量大且不破坏相邻差 ≤1。

## 怎么做
1. 对 `arr` 升序排序，让小的数先占住低位，大的数才有机会往后顶。
2. 把 `arr[0]` 置为 1（第一个元素必须为 1，且只能减小）。
3. 从 `i=1` 起，令 `arr[i] = min(arr[i], arr[i-1] + 1)`，即当前值最多比前一个大 1。
4. 返回 `arr[-1]`。

以 `arr = [100,1,1000]` 为例：排序得 `[1,100,1000]`；`arr[0]=1`；`i=1` 时 `min(100, 1+1)=2`；`i=2` 时 `min(1000, 2+1)=3`，返回 3。关键中间值是 `arr[1]` 从 100 被压到 2——它决定了后面只能到 3。

```python
arr.sort()
arr[0] = 1
for i in range(1, len(arr)):
    if arr[i] > arr[i - 1] + 1:
        arr[i] = arr[i - 1] + 1
return arr[-1]
```

为什么贪心成立：排序后第 `i` 个位置的上界是 `arr[i]` 和 `arr[i-1]+1` 的较小者，取满这个上界不会让后面的位置变差（后面的上界只依赖当前值，当前值越大上界越大），所以每步取最大是安全的。

## 复杂度
时间：排序 `O(n log n)` 主导，扫描 `O(n)`，n 为 `arr` 长度。
空间：排序额外 `O(log n)`（Python 的 Timsort 栈），其余 `O(1)`。

## 易错点
- 输入 `arr = [2,2,1,2,1]`：若忘记先把 `arr[0]` 置 1，排序后首元素是 1 恰好没事，但换成 `[5,5,5]` 就会从 5 开始算，错得 5；正确做法是显式 `arr[0] = 1`，再往后推得 `[1,2,3]` 返回 3。
- 输入 `arr = [1,2,3,4,5]`：若写成 `arr[i] = arr[i-1] + 1` 无条件覆盖，会把本来合法的 5 也改，虽然本例结果仍是 5，但遇到 `[1,1,1]` 会错误地变成 `[1,2,3]` 返回 3；正确做法是只在 `arr[i] > arr[i-1]+1` 时才压，即取 `min`。

## 如果面试官追问
问：如果要求输出具体方案而不只是最大值？答：上面的原地修改已经得到一组可行数组，直接返回 `arr` 即可，无需额外构造。
