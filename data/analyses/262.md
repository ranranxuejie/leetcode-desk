## 一句话思路
先把 Trips 按「乘客和司机都未被禁」过滤，再按 request_at 分组算取消数除以总数。

## 怎么做
1. 用两次 join 把 Trips 分别连到 Users 的 client_id 和 driver_id，各取 banned。
2. WHERE 同时要求两个 banned 都是 `'No'`，并限定 request_at 在 `'2013-10-01'` 到 `'2013-10-03'`。
3. 用 `status != 'completed'` 作为取消标记，SUM 出取消数、COUNT 出总数。
4. 相除后 `round(..., 2)`，按 request_at 分组输出。

以官方示例 10-01 为例：id=2 的 client_id=2 在 Users 里 banned='Yes'，被 WHERE 过滤掉；剩下 id=1、3、4 三条，其中 id=4 是 cancelled_by_client，所以取消数 1、总数 3，得 0.33。

```python
# 关键过滤与聚合（伪 SQL 转 Python 思路）
valid = trips[
    (trips.client_id.map(banned) == 'No') &
    (trips.driver_id.map(banned) == 'No') &
    (trips.request_at.between('2013-10-01', '2013-10-03'))
]
valid['cancel'] = valid.status != 'completed'
rate = valid.groupby('request_at').cancel.mean().round(2)
```

## 复杂度
时间 O(n)：n 为 Trips 行数，两次 join 各扫一遍，分组再扫一遍。
空间 O(k)：k 为日期数，只存每天的两个计数。

## 易错点
1. 只过滤乘客或只过滤司机 → 示例里 id=2 的乘客被禁、id=6 的乘客被禁，若漏掉司机侧判断，10-01 会算成 2/4=0.50 而非 0.33。必须两个 banned 都判 `'No'`。
2. 用 `status = 'cancelled_by_client'` 当取消条件 → 会漏掉 cancelled_by_driver，10-03 的 id=10 就漏了，结果变 0.00 而非 0.50。正确做法是 `status != 'completed'`。

## 如果面试官追问
问：日期范围改成参数化、数据量到亿级怎么办？
答：把日期条件下推到 Trips 扫描阶段先裁剪分区，再 join Users，避免全表 join。
