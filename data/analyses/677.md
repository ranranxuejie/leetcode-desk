## 一句话思路
用哈希表存 key→val，sum 时遍历所有 key 做 `startswith` 前缀匹配并累加，规模只有 50 次调用，够用。

## 怎么做
1. 初始化 `self.d = {}`，insert 直接 `self.d[key] = val`，天然完成「已存在则覆盖」。
2. sum 遍历 `self.d.items()`，用 `k.startswith(prefix)` 过滤，累加 `v`。
3. 用官方示例走一遍：insert("apple",3) 后 `d={"apple":3}`；sum("ap") 遍历到 "apple" 匹配，返回 3。
4. insert("app",2) 后 `d={"apple":3,"app":2}`；sum("ap") 两个 key 都 `startswith("ap")`，返回 3+2=5。

```python
class MapSum:
    def __init__(self):
        self.d = {}

    def insert(self, key, val):
        self.d[key] = val

    def sum(self, prefix):
        total = 0
        for k, v in self.d.items():
            if k.startswith(prefix):
                total += v
        return total
```

关键中间值：第二次 sum("ap") 时循环体依次命中 `("apple",3)` 和 `("app",2)`，`total` 从 0→3→5。

## 复杂度
时间：insert O(1)；sum O(m·L)，m 为已插入 key 数、L 为 key 长度（startswith 比较）。
空间：O(m·L)，哈希表存下所有 key 字符串本身。

## 易错点
1. 重复 insert 同一 key 时若写成 `self.d[key] += val` → 示例中再 insert("apple",5) 会得 8 而非 5 → 必须直接赋值覆盖，因为题面要求「替代」。
2. sum 用 `prefix in k` 而非 `k.startswith(prefix)` → 对 key="xap"、prefix="ap" 会误判命中 → 前缀必须从首字符对齐，只能用 startswith。

## 如果面试官追问
若 key 长度到 10^5、调用到 10^5 次，O(m·L) 的 sum 会超时怎么办？答：改字典树，每个节点维护子树 val 和，insert 时沿路径把差值加到各节点。
