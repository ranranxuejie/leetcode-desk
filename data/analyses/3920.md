## 一句话思路
删除元素只会让后面的元素下标变小，所以对每个 `nums[i]` 只需判断它能否被"挤"到下标 `nums[i]`，用计数数组统计每个目标下标能凑到几个。

## 怎么做
1. 关键观察：`nums[i]` 最终落在下标 `nums[i]` 处，当且仅当它前面恰好删掉 `i - nums[i]` 个元素，且 `nums[i] <= i`。
2. 对每个满足 `nums[i] <= i` 的 `i`，把 `nums[i]` 计入 `cnt[nums[i]]`，表示"想占下标 `nums[i]` 的候选有几个"。
3. 答案取 `max(cnt)`，因为同一个下标只能有一个元素占住，多个候选也只能贡献 1。

以 `nums = [1,0,1,2]` 为例：`i=0` 时 `1>0` 跳过；`i=1` 时 `0<=1`，`cnt[0]=1`；`i=2` 时 `1<=2`，`cnt[1]=1`；`i=3` 时 `2<=3`，`cnt[2]=1`。三个下标各凑到 1 个，答案 3。

```python
n = len(nums)
cnt = [0] * (n + 1)
for i, v in enumerate(nums):
    if v <= i:
        cnt[v] += 1
return max(cnt)
```

注意 `cnt` 开 `n+1` 是因为 `nums[i]` 最大可能等于 `n-1`，而 `nums[i]` 可能超过 `n`，但那些被 `v <= i` 过滤掉了。

## 复杂度
时间 O(n)：一次遍历 `nums`，`max(cnt)` 再扫一遍长度 `n+1` 的数组。
空间 O(n)：额外开了 `cnt` 数组，大小 `n+1`。

## 易错点
- 输入 `nums = [3,1,2]`：若不加 `v <= i` 判断，`i=0, v=3` 会把 `cnt[3]` 加 1，但下标 3 根本不存在，答案可能虚高。正确做法是先过滤 `v <= i` 再计数。
- 输入 `nums = [0,0,0]`：三个元素都想占下标 0，`cnt[0]=3`，但答案只能是 1（一个下标只能一个固定点）。若直接返回 `sum(cnt)` 会错成 3，必须取 `max`。

## 如果面试官追问
问：如果要求输出具体删除方案怎么办？
答：对每个 `cnt[v] > 0` 的 `v`，保留第一个满足 `nums[i] == v` 且 `i >= v` 的元素，其余全删，删完重排即可。
