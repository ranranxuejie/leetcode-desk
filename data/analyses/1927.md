## 一句话思路
把两边已知和的差与问号数折算成「Bob 需要补的差值」，看 Bob 能否用 9 的倍数精确凑出，能则 Bob 赢。

## 怎么做
1. 设 `diff = sum(左半已知) - sum(右半已知)`，`qL`、`qR` 为左右问号数。
2. 每个问号取值 0~9，Bob 想让最终两边相等，即需要把 `diff` 用左半问号减、右半问号加来抵消。
3. 关键结论：Bob 能赢当且仅当 `diff` 落在 `[-9*qL, 9*qR]` 内且 `diff % 9 == 0`（因为每个问号贡献 0~9，可视为 9 的倍数加余数，余数部分由 0~9 的取值自由度吸收）。
4. 以 `num = "?3295???"` 为例：左半 `"?329"`，右半 `"5???"`。`sum(左已知)=3+2+9=14`，`sum(右已知)=5`，`diff=9`；`qL=1`，`qR=3`。`diff=9` 在 `[-9, 27]` 内且 `9%9==0`，Bob 赢，返回 `False`。

```python
n = len(num)
half = n // 2
diff = 0
qL = qR = 0
for i, ch in enumerate(num):
    if ch == '?':
        if i < half: qL += 1
        else: qR += 1
    else:
        diff += int(ch) if i < half else -int(ch)
# Bob 赢的条件
bob_wins = (-9 * qL <= diff <= 9 * qR) and diff % 9 == 0
return not bob_wins
```

## 复杂度
时间：O(n)，遍历字符串一次，n 为 `num` 长度。
空间：O(1)，只用了 `diff`、`qL`、`qR` 三个变量。

## 易错点
- 输入 `num = "25??"`：若只判断 `diff` 是否在区间内而漏掉 `% 9`，会误判。`sum(左)=2+5=7`，`sum(右)=0`，`diff=7`，`qL=0`，`qR=2`，区间 `[0,18]` 包含 7，但 `7%9!=0`，Bob 实际赢不了，应返回 `True`。正确做法是同时检查 `diff % 9 == 0`。
- 输入 `num = "5023"`：无问号时 `qL=qR=0`，区间退化为 `[0,0]`，只有 `diff==0` 才 Bob 赢。此处 `diff=5+0-2-3=0`，返回 `False`。若把区间判断写成 `diff <= 9*qR` 而忽略下界 `-9*qL`，当 `diff` 为负且 `qL=0` 时会漏判。

## 如果面试官追问
问：如果问号取值改成 1~9 而非 0~9 呢？
答：每个问号贡献整体加 1，`diff` 需减去 `qR - qL` 后再判断区间与 `%9`，边界相应平移。
