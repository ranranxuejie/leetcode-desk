## 一句话思路
用 26 个桶记录每个字符当前最左未合并位置，从左到右扫描时若与桶内位置距离 ≤ k 就删掉当前字符，否则更新桶。

## 怎么做
1. 建 `last = {}` 存每个字符在结果串中的下标，`res = []` 存结果。
2. 遍历 `s` 的每个字符 `c`：若 `c` 在 `last` 且 `len(res) - last[c] <= k`，跳过 `c`（合并到左侧）。
3. 否则把 `c` 追加进 `res`，并令 `last[c] = len(res) - 1`。
4. 返回 `''.join(res)`。

以 `s = "yybyzybz", k = 2` 为例：扫到下标 1 的 `y` 时 `last['y'] = 0`，`1 - 0 = 1 <= 2`，跳过；扫到下标 2 的 `y` 时 `last['y']` 仍是 0，`2 - 0 = 2 <= 2`，跳过，此时 `res = ['y']`。注意 `last['y']` 始终是 0，因为被合并的字符不更新桶。

```python
def mergeCharacters(s, k):
    last = {}
    res = []
    for c in s:
        if c in last and len(res) - last[c] <= k:
            continue
        last[c] = len(res)
        res.append(c)
    return ''.join(res)
```

关键点：`last[c]` 存的是**结果串**中的下标，不是原串下标。合并后原串下标会失效，用结果串长度算距离才正确。

## 复杂度
时间 O(n)：每个字符扫一次，哈希表操作 O(1)。
空间 O(n)：`res` 最多存 n 个字符，`last` 最多 26 项。

## 易错点
- 输入 `s = "aabca", k = 2`：若用原串下标算距离，第二个 `a`（原下标 1）与第一个 `a`（原下标 0）距离 1 ≤ 2 会合并，但合并后第三个 `a` 原下标 4 与第一个距离 4 > 2 不合并，结果看似对；但若先合并了中间字符，原下标差会失真。正确做法是始终用 `len(res) - last[c]` 算结果串中的距离。
- 输入 `s = "abca", k = 3`：若合并后忘记更新 `last['a']`，或错误地把被合并字符也写进 `last`，会导致后续 `a` 与错误位置比较。正确做法是只在追加字符时更新 `last[c] = len(res)`，被跳过的字符不动桶。

## 如果面试官追问
若 k 很大（如 k = n），能否 O(1) 空间？答：不能，仍需记录每个字符最左位置，但可用长度 26 的数组替代字典，空间 O(1)。
