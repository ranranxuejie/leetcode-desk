## 一句话思路
按 1、0、-1 的优先级贪心取，因为每件物品价值固定且互不影响，先拿高价值的一定不劣。

## 怎么做
1. 先尽量取 1：`take1 = min(numOnes, k)`，贡献 `take1`。
2. 剩余需求 `k -= take1`，再取 0：`take0 = min(numZeros, k)`，贡献 0。
3. 剩余需求只能取 -1：`takeNeg = k - take0`，贡献 `-takeNeg`。
4. 返回 `take1 - takeNeg`。

以示例 2 为例：`numOnes=3, numZeros=2, numNegOnes=0, k=4`。第一步 `take1 = min(3,4) = 3`，`k` 剩 1；第二步 `take0 = min(2,1) = 1`，`k` 剩 0；`takeNeg = 0`。结果 `3 - 0 = 3`。

```python
take1 = min(numOnes, k)
k -= take1
take0 = min(numZeros, k)
k -= take0
takeNeg = k
return take1 - takeNeg
```

关键点：`k` 在每步后递减，第三步的 `k` 就是被迫取 -1 的件数，不需要再 `min(numNegOnes, k)`，因为题目保证 `k <= numOnes + numZeros + numNegOnes`。

## 复杂度
时间：O(1)，只做三次 `min` 和减法，与输入规模无关。
空间：O(1)，只开 `take1`、`take0`、`takeNeg` 三个整型变量。

## 易错点
- `k` 大于 `numOnes + numZeros` 时（如 `numOnes=1, numZeros=1, numNegOnes=5, k=4`）→ 若忘记第三步直接用 `k` 当 `takeNeg`，会漏算被迫取的 -1 件数，错成 `1` 而非正确 `1 - 2 = -1` → 正确做法是第三步 `takeNeg = k`（此时 `k` 已减过前两步）。
- `numOnes` 远大于 `k` 时（如 `numOnes=50, numZeros=0, numNegOnes=0, k=3`）→ 若先算 `k -= numOnes` 再取 `min`，`k` 变负数导致后续逻辑错乱 → 正确做法是先 `take1 = min(numOnes, k)` 再减，保证 `k` 始终非负。

## 如果面试官追问
问：若要求输出具体选了哪些物品而非只求和？答：按同样优先级记录 `take1`、`take0`、`takeNeg` 三个计数即可还原方案，仍是 O(1)。
