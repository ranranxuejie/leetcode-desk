## 一句话思路
用 `setTimeout` 拿到定时器 id，取消函数里 `clearTimeout(id)`，因为清除后回调永不触发。

## 怎么做
1. 调用 `setTimeout(fn, t, *args)`，把返回的定时器 id 存进局部变量 `timer`。
2. 返回一个闭包 `cancelFn`，函数体只有 `clearTimeout(timer)`。
3. 关键中间值：以示例 2 为例，`t=100`、`cancelTimeMs=50`，`timer` 在 0ms 时被创建，50ms 时 `cancelFn` 执行 `clearTimeout(timer)`，此时 `fn(2)` 尚未到 100ms，定时器被移除，输出 `[]`。
4. 示例 1 中 `t=20 < cancelTimeMs=50`，20ms 时 `fn(2)` 已跑出 `10`，50ms 的 `clearTimeout` 作用在已触发的 id 上，无副作用，输出仍是 `[{"time":20,"returned":10}]`。

```python
import threading

def cancellable(fn, args, t):
    timer = threading.Timer(t / 1000, fn, args=args)
    timer.start()

    def cancelFn():
        timer.cancel()

    return cancelFn
```

Python 里没有 `setTimeout`，用 `threading.Timer` 等价：`start()` 相当于注册定时器，`cancel()` 相当于 `clearTimeout`。`args` 通过 `args=` 关键字传入，不要写成 `args` 位置参数，否则会被当成 `interval`。

## 复杂度
时间：O(1) 注册与取消，`fn` 本身耗时不计入。
空间：O(1) 额外开一个 `timer` 对象和闭包，`args` 长度 ≤10 可视为常数。

## 易错点
- `t=20`、`cancelTimeMs=50`（示例 1）→ 若在 `cancelFn` 里加 `if not fired` 之类的判断反而多此一举，`clearTimeout` 对已触发的 id 本就安全 → 直接 `clearTimeout(timer)`，不要自己维护 `fired` 标志。
- `args=[2,4]`、`fn=(x1,x2)=>x1*x2`（示例 3）→ 若写成 `setTimeout(fn, t, args)` 把整个数组当一个参数传，`fn` 收到的是 `[2,4]` 而非 `2,4`，会报参数个数错误 → 必须展开成 `setTimeout(fn, t, ...args)`（Python 用 `args=args`）。

## 如果面试官追问
追问：如果要求 `cancelFn` 可重复调用且第二次调用要报错？
答：加一个 `cancelled` 布尔量，首次 `clearTimeout` 后置 `True`，再调用时 `raise`。
