## 一句话思路
累加 1..k 直到 sum ≥ |target| 且 (sum - |target|) 为偶数，此时把某个 +i 翻成 -i 恰好补上差值。

## 怎么做
1. 取 `t = abs(target)`，正负对称，只算正数。
2. 从 k=1 起累加 `s += k`，直到 `s >= t`。
3. 若 `(s - t) % 2 == 0`，返回 k；否则 k 再加一次（多走一步），再判一次。
4. 为什么加一步必成：k→k+1 时 s 增加 k+1，奇偶性翻转，所以最多多试一次。

以 target=2 为例：k=1 时 s=1 < 2；k=2 时 s=3 ≥ 2，但 `(3-2)%2 = 1` 是奇数，不成立；k=3 时 s=6，`(6-2)%2 = 0`，返回 3。对应翻符号的是 +1 变 -1：-1+2+3=4？不对，正确翻的是 +2 变 -2：1-2+3=2，与示例路径一致（1, -1, 2 的位移序列等价）。

```python
t = abs(target)
k = 0
s = 0
while s < t or (s - t) % 2 != 0:
    k += 1
    s += k
return k
```

循环条件写成 `s < t or (s - t) % 2 != 0` 比「先加到够再补一步」更省心：s 不够时继续加，够了但奇偶不对也继续加，一次循环覆盖两种情况。注意 `(s - t) % 2` 在 Python 里对负数也返回非负余数，但这里 s ≥ t 恒成立，不必担心。

## 复杂度
时间：O(√target)，k 约等于 √(2·target)，循环次数由 target 的平方根决定。
空间：O(1)，只开 t、k、s 三个整数。

## 易错点
- target 为负数（如 -3）→ 直接拿负数累加比较，`s < t` 一开始就假，返回 0 → 先取 `abs(target)`，正负路径完全对称。
- target=2 这类「够但奇偶不对」的输入 → 只判 `s >= t` 就返回 2，实际答案是 3 → 必须同时判 `(s - t) % 2 == 0`，因为差值必须由翻转某个 i 贡献，而翻转改变总和 2i，只能消掉偶数差。

## 如果面试官追问
要求输出具体移动方案怎么办？答：从 k 往下找第一个满足 `i <= (s-t)//2` 的 i 翻成负号，其余保持正号，剩下的差继续贪心翻。
