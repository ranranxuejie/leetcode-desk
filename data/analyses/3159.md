## 一句话思路
先扫一遍 `nums` 把每个 `x` 的下标按出现顺序存进列表，查询时按下标直接取，越界返回 -1。

## 怎么做
1. 遍历 `nums`，`if nums[i] == x` 就把 `i` 追加到 `pos`，得到 `pos` 是升序的下标列表。
2. 对每个 `q in queries`，判断 `q <= len(pos)` 是否成立，成立取 `pos[q-1]`，否则填 -1。
3. 用列表推导一次生成 `answer`，长度与 `queries` 对齐。

拿示例 1 走一遍：`nums = [1,3,1,7], x = 1`，扫描后 `pos = [0, 2]`，`len(pos) = 2`。`queries = [1,3,2,4]` 依次得 `pos[0]=0`、`3>2` 填 -1、`pos[1]=2`、`4>2` 填 -1，输出 `[0,-1,2,-1]`。

```python
pos = []
for i, v in enumerate(nums):
    if v == x:
        pos.append(i)

m = len(pos)
answer = [pos[q - 1] if q <= m else -1 for q in queries]
```

关键点：`pos` 天然升序，因为 `enumerate` 从左到右扫；所以「第 q 个 x」就是 `pos[q-1]`，不需要额外排序或二分。`q` 从 1 开始，减 1 别漏。

## 复杂度
时间：O(n + m)，n 是 `nums` 长度扫一遍，m 是 `queries` 长度查一遍。
空间：O(k)，k 是 `x` 在 `nums` 中的出现次数，即 `pos` 的长度，答案数组 O(m) 不计入额外。

## 易错点
- `queries` 里出现 `q = 0` 或负数 → 若只写 `q <= m` 判断会通过，`pos[q-1]` 变成 `pos[-1]` 取到最后一个下标而不报错 → 本题约束 `queries[i] >= 1` 所以安全，但若换约束要写成 `1 <= q <= m`。
- `x` 在 `nums` 中一次都没出现 → `pos = []`、`m = 0`，此时任何 `q >= 1` 都走 -1 分支，别写成 `if pos` 之外还去访问 `pos[0]`；示例 2 就是这种情形，输出 `[-1]`。

## 如果面试官追问
追问：如果 `queries` 有 10^5 个且要求在线逐条回答（不能预存全部下标）？
答：仍要预存 `pos`，单次查询 O(1)；若连 `pos` 都不许存，则只能每次 O(n) 扫描，退化为 O(n·m)。
