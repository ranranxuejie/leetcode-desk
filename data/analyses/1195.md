## 一句话思路
用一个共享的 `self.i` 加 `threading.Condition`，四个线程各自循环等待「轮到我」再打印并 `i += 1`。

## 怎么做
1. 构造函数里存 `self.n = n`、`self.i = 1`、`self.cv = threading.Condition()`。
2. 每个线程方法都写成 `while True`：进 `with self.cv`，先 `while self.i <= self.n and not 该我打印: self.cv.wait()`，再判断 `self.i > self.n` 就 `return`。
3. 打印后 `self.i += 1` 并 `self.cv.notify_all()`，让其他三个线程重新竞争。
4. 判断条件用 `self.i % 15 == 0` 给 fizzbuzz、`% 3 == 0` 给 fizz、`% 5 == 0` 给 buzz、否则 number，顺序不能反。

以 `n = 15`、`self.i = 15` 为例：`15 % 15 == 0`，只有 fizzbuzz 线程的等待条件为真，它打印 `"fizzbuzz"` 后 `self.i` 变成 16，`notify_all` 唤醒其余三个，它们发现 `self.i > self.n` 直接返回。

```python
def fizz(self, printFizz):
    while True:
        with self.cv:
            while self.i <= self.n and self.i % 3 != 0 or self.i % 15 == 0 and self.i <= self.n:
                self.cv.wait()
            if self.i > self.n:
                return
            printFizz()
            self.i += 1
            self.cv.notify_all()
```

（其余三个方法同构，只换判断式和打印函数；`number` 的条件是 `self.i % 3 and self.i % 5`。）

## 复杂度
时间：每个线程最多被唤醒 O(n) 次，总打印 n 次，O(n)。
空间：只开一个 Condition 和常数个变量，O(1) 额外空间。

## 易错点
- `n = 1` 时四个线程都会进循环，若先判断打印再判断越界，fizz/buzz/fizzbuzz 线程会因 `1 % 3 != 0` 卡在 `wait()` 永不退出 → 必须把 `self.i > self.n` 的 return 放在 wait 循环之后、打印之前。
- `n = 15` 时若 fizz 的条件只写 `self.i % 3 == 0`，第 15 步 fizz 和 fizzbuzz 同时满足，会多打一个 `"fizz"` → fizz 必须排除 15 的倍数，即 `% 3 == 0 and % 5 != 0`。

## 如果面试官追问
问：不用 Condition，能只靠一个 `threading.Semaphore` 数组吗？
答：可以，开 n 个信号量，第 i 个只放行该打印的线程，打印完 release 第 i+1 个，空间 O(n)。
