## 一句话思路
排序后回溯，每层从 `start` 起枚举，允许重复选当前数，靠 `target` 递减到 0 收集。

## 怎么做
1. 先 `candidates.sort()`，让后续 `candidates[i] > target` 时能直接 `break`。
2. 回溯参数 `(start, target, path)`，`target == 0` 时把 `path[:]` 收进结果。
3. 循环 `for i in range(start, len(candidates))`，选 `candidates[i]` 后递归传 `i`（不是 `i+1`），保证可重复选。
4. 剪枝：`candidates[i] > target` 就 `break`，因为数组已升序。

以 `candidates=[2,3,6,7], target=7` 为例：第一层选 2，`target` 变 5，递归仍从下标 0 开始；再选 2 得 `target=1`，此时 `candidates[0]=2 > 1` 直接 `break`，这条分支被剪掉。回到第一层选 7，`target=0`，收集 `[7]`。

```python
candidates.sort()
res, path = [], []

def dfs(start, target):
    if target == 0:
        res.append(path[:])
        return
    for i in range(start, len(candidates)):
        if candidates[i] > target:
            break
        path.append(candidates[i])
        dfs(i, target - candidates[i])
        path.pop()

dfs(0, target)
```

关键在 `dfs(i, ...)`：传 `i` 允许重复选同一个数，传 `i+1` 就变成每个数只能用一次（那是 40 题）。

## 复杂度
时间：O(S)，S 为所有解的长度之和，每个节点只做一次 append/pop。
空间：O(target/min(candidates)) 递归深度，加结果集本身。

## 易错点
- 传 `dfs(i+1, ...)` → `[2,2,3]` 这类重复选数的解全丢，只剩 `[7]`。正确做法是传 `i`，让当前数可被再次选中。
- 不排序就写 `if candidates[i] > target: break` → 遇到 `[7,2,3,6]` 时 7 在首位，`break` 会漏掉 `[2,2,3]`。必须先 `sort()`，或把 `break` 换成 `continue`。

## 如果面试官追问
问：若每个数只能用一次（40 题）怎么改？
答：递归传 `i+1`，并在循环里跳过 `i > start and candidates[i] == candidates[i-1]` 去重。
