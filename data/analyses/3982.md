## 一句话思路
对每个数拆位求 max-min 得数字范围，先扫一遍取最大值，再扫一遍把范围等于最大值的数累加。

## 怎么做
1. 写一个 `digit_range(x)`：循环 `while x:` 取 `x % 10` 更新 `mx`/`mn`，再 `x //= 10`，返回 `mx - mn`。
2. 第一遍遍历 `nums`，用 `best = max(best, digit_range(v))` 求出最大数字范围。
3. 第二遍遍历，`if digit_range(v) == best: ans += v`。
4. 返回 `ans`。

以 `nums = [5724,111,350]` 为例：`5724` 拆位得 `mx=7, mn=2`，范围 `5`；`111` 得 `1-1=0`；`350` 得 `5-0=5`。第一遍后 `best = 5`，第二遍命中 `5724` 和 `350`，`ans = 6074`。

```python
def digit_range(x):
    mx, mn = 0, 9
    while x:
        d = x % 10
        mx = max(mx, d)
        mn = min(mn, d)
        x //= 10
    return mx - mn

best = max(digit_range(v) for v in nums)
ans = sum(v for v in nums if digit_range(v) == best)
```

注意 `mn` 初值必须是 `9` 而不是 `0`：若初值取 `0`，`111` 会算成 `1-0=1`，把 `best` 抬错。

## 复杂度
时间 O(n·log M)，n 是数组长度，log M 是每个数的位数（M ≤ 10^5 即最多 6 位）。
空间 O(1)，只用了 `mx`、`mn`、`best`、`ans` 几个标量。

## 易错点
- `nums = [111]` 这类全同数字 → 若 `mn` 初值写 `0`，范围算成 `1` 而非 `0`，`best` 偏大导致漏加 → `mn` 初值取 `9`，或先令 `mn = mx = x % 10` 再进循环。
- `nums = [90,900]` → 若把 `90` 当两位、`900` 当三位分别处理却漏掉末尾的 `0`（比如用 `str` 转但只取非零位）→ 两者范围都会算错，答案不是 `990` → 必须逐位 `% 10` 把 `0` 也算进 `mn`，`90` 得 `9-0=9`、`900` 得 `9-0=9`。

## 如果面试官追问
问：若 `nums` 长度涨到 10^6、值到 10^18 呢？
答：仍 O(n·位数)，位数最多 19，瓶颈在遍历而非拆位，无需改结构。
