## 一句话思路
排序后去重建「值 → 序号」哈希表，再按原数组顺序查表映射回去。

## 怎么做
1. 对 `arr` 排序得到 `sorted_arr`，用 `sorted(set(arr))` 一步去重，去重后的下标 `i` 对应序号 `i + 1`。
2. 建字典 `rank = {v: i + 1 for i, v in enumerate(sorted(set(arr)))}`，重复值只占一个序号。
3. 遍历原 `arr`，输出 `[rank[x] for x in arr]`。

以示例 3 的 `arr = [37,12,28,9,100,56,80,5,12]` 为例：`set` 后是 `{37,12,28,9,100,56,80,5}`，排序得 `[5,9,12,28,37,56,80,100]`，于是 `rank = {5:1, 9:2, 12:3, 28:4, 37:5, 56:6, 80:7, 100:8}`。注意两个 `12` 在字典里只留一个键 `12:3`，映射时两个位置都取 3，正好对上输出里的第 2 位和第 9 位都是 3。

```python
def array_rank_transform(arr):
    rank = {v: i + 1 for i, v in enumerate(sorted(set(arr)))}
    return [rank[x] for x in arr]
```

关键点：序号由「去重后的排序位置」决定，不是原数组排序位置。若用 `sorted(arr)` 直接枚举下标，示例 3 里第二个 `12` 会拿到 4，整体错位。

## 复杂度
时间 O(n log n)：`set` 和排序各 O(n log n)，两次遍历 O(n)。
空间 O(n)：`set`、排序副本、`rank` 字典、结果数组各占 O(n)。

## 易错点
- 输入 `[100,100,100]` → 若用 `sorted(arr)` 枚举下标建表，三个 100 会得到 1、2、3 三个不同序号，输出 `[1,2,3]` → 必须先 `set` 去重再排序，让重复值共用一个键。
- 输入 `arr = []` → 若代码里写了 `rank[arr[0]]` 或先取 `min(arr)` 之类的前置判断，会抛 `IndexError` → 空数组直接返回 `[]`，上面的列表推导天然安全。

## 如果面试官追问
追问：`arr` 长度到 10^7、值域仍是 ±10^9，怎么优化？
答：排序仍是 O(n log n) 瓶颈，可改用值域桶或基数排序把排序降到 O(n)，但哈希表 O(n) 空间不变。
