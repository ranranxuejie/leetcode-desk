## 一句话思路
在普通旋转二分上加一条「`nums[lo] == nums[mid] == nums[hi]` 就缩边界」的规则，其余照旧判断哪半边有序。

## 怎么做
1. 用 `lo, hi = 0, len(nums)-1` 做闭区间二分，循环条件 `lo <= hi`。
2. 每轮先算 `mid = (lo + hi) // 2`，命中 `nums[mid] == target` 直接返回 `True`。
3. 若 `nums[lo] == nums[mid] == nums[hi]`，说明三端同值、无法判断哪边有序，就 `lo += 1; hi -= 1` 各缩一格。
4. 否则判断左半有序（`nums[lo] <= nums[mid]`）：有序且 `nums[lo] <= target < nums[mid]` 就 `hi = mid - 1`，否则 `lo = mid + 1`；右半对称处理。

拿示例 1 `nums = [2,5,6,0,0,1,2], target = 0`：首轮 `lo=0, hi=6, mid=3`，`nums[3]=0` 直接命中返回 `True`。若 target 换成 `1`，则 `mid=3` 不中，`nums[0]=2 > nums[3]=0` 说明左半无序、右半 `[0,0,1,2]` 有序，`nums[3]=0 <= 1 <= nums[6]=2` 成立，于是 `lo = 4`，下一轮 `mid=5` 命中。

```python
lo, hi = 0, len(nums) - 1
while lo <= hi:
    mid = (lo + hi) // 2
    if nums[mid] == target:
        return True
    if nums[lo] == nums[mid] == nums[hi]:
        lo += 1
        hi -= 1
    elif nums[lo] <= nums[mid]:
        if nums[lo] <= target < nums[mid]:
            hi = mid - 1
        else:
            lo = mid + 1
    else:
        if nums[mid] < target <= nums[hi]:
            lo = mid + 1
        else:
            hi = mid - 1
return False
```

## 复杂度
时间：平均 O(log n)，最坏 O(n)——全数组同值（如 `[1,1,1,1]`）时每轮只缩一格。
空间：O(1)，只用了 `lo/hi/mid` 三个下标。

## 易错点
- 输入 `[1,0,1,1,1], target=0` → 若只写 `nums[lo] <= nums[mid]` 判有序，`nums[0]=1 <= nums[2]=1` 成立会误判左半有序，把 `target=0` 排除掉 → 必须先处理三端同值再判有序。
- 输入 `[1,3,1,1,1], target=3` → 若三端同值时直接 `return False` 或只缩 `lo` 不缩 `hi`，会漏掉 `mid=1` 之外的解或死循环 → 必须 `lo += 1` 和 `hi -= 1` 同时执行。

## 如果面试官追问
问：重复元素让最坏退化到 O(n)，能避免吗？
答：不能，`[1,1,1,0,1]` 这类输入信息量本身不足，只能线性缩边界；要 O(log n) 得先预处理去重或保证元素互异。
