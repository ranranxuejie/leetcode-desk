## 一句话思路
累加价值随 num 单调不减，二分答案 num，用数位 DP 在 O(log num) 内算出 1..num 的总价值。

## 怎么做
1. 把「1..num 的总价值」拆成按位统计：第 j 位（j 从 0 起）若 `j % x == 0`，统计 1..num 中该位为 1 的个数。
2. 对第 j 位，周期 `p = 1 << (j+1)`，完整周期贡献 `(num+1) // p * (1 << j)`，余数部分贡献 `max(0, (num+1) % p - (1 << j))`。
3. 二分 `lo=1, hi=10**16`，`count(mid) <= k` 则 `lo = mid+1`，答案取 `lo-1`。
4. 以 k=9, x=1 验证：mid=6 时，j=0 贡献 3，j=1 贡献 2，j=2 贡献 2，合计 7 ≤ 9；mid=7 时合计 12 > 9，故答案 6。

```python
def count(num):
    total = 0
    j = 0
    while (1 << j) <= num:
        if j % x == 0:
            p = 1 << (j + 1)
            total += (num + 1) // p * (1 << j)
            total += max(0, (num + 1) % p - (1 << j))
        j += 1
    return total

lo, hi = 1, 10**16
while lo <= hi:
    mid = (lo + hi) // 2
    if count(mid) <= k:
        lo = mid + 1
    else:
        hi = mid - 1
return lo - 1
```

## 复杂度
时间：二分 O(log 10^16) 次，每次按位 O(log num)，合计 O(log²k)。
空间：只用了 `total`、`p` 等几个整数，O(1)。

## 易错点
- x=8 且 num 很小时，`j % x == 0` 只在 j=0 成立，若循环条件写成 `j <= 60` 固定上界，会多算高位贡献导致 count 偏大、二分答案偏小；正确做法是 `while (1 << j) <= num` 动态截断。
- k=10^15 时答案接近 10^16，若 hi 取 `10**15` 会漏掉合法解，返回偏小的值；正确做法是 hi 取 `10**16`（或 `2*k+1` 量级），保证 count(hi) > k。

## 如果面试官追问
若 k 增大到 10^18 呢？答：hi 改到 `10**19`，二分次数只多约 10 次，count 逻辑不变。
