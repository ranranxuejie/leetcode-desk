## 一句话思路
分别累加个位数之和与两位数之和，任一严格大于总和的一半即赢。

## 怎么做
1. 一次遍历，把 `nums[i] < 10` 的累进 `single`，否则累进 `double`。
2. 同时累出总和 `total`。
3. 判断 `single * 2 > total or double * 2 > total`，用乘法避免写 `/2` 的浮点。
4. 返回该布尔值。

以示例 2 `nums = [1,2,3,4,5,14]` 为例：遍历完 `single = 15`、`double = 14`、`total = 29`；`15 * 2 = 30 > 29` 成立，返回 `True`。注意 Bob 拿的是「剩下的」，所以 Alice 赢的条件等价于她的和 > 总和减她的和，即 `2 * 她的和 > total`，不必真的去算 Bob 的和。

```python
single = double = total = 0
for x in nums:
    total += x
    if x < 10:
        single += x
    else:
        double += x
return single * 2 > total or double * 2 > total
```

关键点：`x < 10` 就是「个位数」的判定，题面保证 `1 <= nums[i] <= 99`，不会出现 0 或三位数，所以不需要 `x // 10 == 0` 这种写法，也不需要处理负数。

## 复杂度
时间 O(n)：一次遍历，n 为 `nums` 长度。
空间 O(1)：只开 `single`、`double`、`total` 三个累加器。

## 易错点
- 写成 `single > total - single` 时若先算 `total - single` 再比较，逻辑没错，但有人误写成 `single > total // 2`，遇到 `total` 为奇数如 29 时 `29 // 2 = 14`，`single = 15 > 14` 侥幸对，而 `single = 14`、`double = 15` 时 `14 > 14` 为假却应判 `double` 赢——用 `2 * 和 > total` 一次覆盖两种情况。
- 把「严格大于」写成 `>=`：示例 1 `nums = [1,2,3,4,10]` 中 `single = 10`、`double = 10`、`total = 20`，`10 * 2 = 20` 不满足 `> 20`，正确返回 `False`；若用 `>=` 会误判为 `True`。

## 如果面试官追问
问：若 Alice 可以任选一个子集而非「全部个位或全部两位」呢？
答：那就变成子集和/背包判定，需 O(n·sum) 的 DP，本题的两次求和技巧失效。
