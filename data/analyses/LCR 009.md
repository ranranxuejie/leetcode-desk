## 一句话思路
用滑动窗口维护乘积小于 k 的区间，右端点每扩一格就累加以它为结尾的合法子数组数。

## 怎么做
1. 初始化 `left = 0`、`prod = 1`、`ans = 0`，`prod` 表示窗口 `nums[left..right]` 的乘积。
2. 右指针 `right` 从左到右遍历，每步先 `prod *= nums[right]`。
3. `while left <= right and prod >= k` 时收缩：`prod //= nums[left]`，`left += 1`。
4. 收缩后窗口内所有以 `right` 结尾的子数组都合法，数量恰为 `right - left + 1`，累加进 `ans`。

以 `nums = [10,5,2,6], k = 100` 为例，走到 `right = 2`（值 2）时 `prod = 10*5*2 = 100`，不满足 `< 100`，于是移出 `10` 得 `prod = 10`、`left = 1`；此时 `right - left + 1 = 2`，对应 `[5,2]` 和 `[2]`。

```python
left, prod, ans = 0, 1, 0
for right, x in enumerate(nums):
    prod *= x
    while left <= right and prod >= k:
        prod //= nums[left]
        left += 1
    ans += right - left + 1
return ans
```

关键点：`ans += right - left + 1` 必须在收缩之后执行，且 `left` 可能越过 `right`（当 `nums[right] >= k` 时窗口为空，贡献 0）。

## 复杂度
时间 O(n)：`right` 走 n 步，`left` 总共最多走 n 步，均摊线性。
空间 O(1)：只开了 `left`、`prod`、`ans` 三个变量，没有额外数组。

## 易错点
- `k <= 1` 时（如示例 2 的 `k = 0`）任何子数组乘积都 ≥ 1 > k，答案必为 0。若直接进循环，`prod >= k` 恒成立、`left` 一路推到 `right + 1`，`right - left + 1` 变成 0 或负数，累加出错。正确做法是开头 `if k <= 1: return 0`，或保证 `left <= right` 的循环条件并把贡献写成 `max(0, right - left + 1)`。
- 收缩用 `while` 而非 `if`：`nums = [1,1,1,100], k = 100` 走到 100 时，`prod = 100`，只移出一个 1 仍是 100，必须连续移出全部三个 1 才降到 1。写成 `if` 会残留 `prod >= k` 的窗口，把非法子数组计入 `ans`。

## 如果面试官追问
问：`nums[i]` 允许为 0 怎么办？答：乘积会归零，窗口内出现 0 后 `prod` 恒为 0，需在收缩时单独处理 0 的位置，或按 0 把数组切段分别统计。
