## 一句话思路
从左往右贪心扫描，遇 0 走一步、遇 1 走两步，看最后一步是否恰好落在末尾的 0 上。

## 怎么做
1. 令 `i = 0`，循环条件写成 `i < len(bits) - 1`，即只处理最后一个 0 之前的部分。
2. 若 `bits[i] == 1`，说明这里必须吃掉两位，`i += 2`。
3. 否则 `bits[i] == 0`，是单比特字符，`i += 1`。
4. 循环结束后判断 `i == len(bits) - 1`：等于则末尾 0 被单独解析，返回 `True`；否则它被前一个 1 吞掉，返回 `False`。

以 `bits = [1, 1, 1, 0]` 为例：`i=0` 时 `bits[0]=1`，跳到 `i=2`；`bits[2]=1`，跳到 `i=4`，循环退出时 `i=4`，而 `len(bits)-1=3`，两者不等，返回 `False`。对比 `[1, 0, 0]`：`i=0` 跳 2 到 `i=2`，`bits[2]=0` 但 `2 < 2` 不成立，退出时 `i=2 == len-1`，返回 `True`。

```python
i, n = 0, len(bits)
while i < n - 1:
    i += 2 if bits[i] == 1 else 1
return i == n - 1
```

关键点：循环上界是 `n - 1` 而不是 `n`，这样末尾的 0 永远不会被当作起点消费掉，只由最后的 `i` 落点来判定归属。

## 复杂度
时间 O(n)：`i` 每轮至少加 1，最多扫到 `n-1`。
空间 O(1)：只用了 `i`、`n` 两个整数，没有额外数组。

## 易错点
- 输入 `[1, 0]` → 若把循环写成 `i < n`，`i=0` 时 `bits[0]=1` 跳到 `i=2`，退出后 `i != n-1` 返回 `False`，但正确答案是 `True`（`10` 是一个两比特字符，末尾 0 不属于它）。正确做法是循环条件严格用 `i < n - 1`。
- 输入 `[0]` → 若先判断 `bits[i] == 1` 再考虑边界，容易在 `n=1` 时越界访问 `bits[1]`；正确做法是 `n - 1 = 0`，循环体一次都不进，直接返回 `i == 0` 即 `True`。

## 如果面试官追问
问：如果允许字符集里再加一个三比特字符 `110`，怎么改？
答：贪心失效，需改成从右往左的 DP，`dp[i]` 表示 `bits[i:]` 能否合法解码，末尾 0 单独成字符当且仅当 `dp[n-1]` 为真且 `dp[n-2]` 不成立。
