## 一句话思路
贪心：从 1 开始按序取数，遇到 `k - x` 已在集合里就跳过 x，取满 n 个即最小。

## 怎么做
1. 维护已选集合 `chosen`，从 `x = 1` 开始逐个尝试，直到取满 n 个。
2. 对每个 x，检查 `k - x` 是否已在 `chosen` 中；若在则跳过 x（否则 x 与 k-x 求和为 k，违反条件）。
3. 否则把 x 加入并累加进 `total`，`x += 1` 继续。

以 `n = 5, k = 4` 为例：x=1 时 `k-x=3` 不在集合，取 1；x=2 时 `k-x=2`，2 不在集合（此时集合只有 {1}），取 2；x=3 时 `k-x=1` 在集合，跳过；x=4 时 `k-x=0` 不在集合，取 4；x=5 时 `k-x=-1`，取 5；x=6 时 `k-x=-2`，取 6。集合 {1,2,4,5,6}，总和 18。

关键中间值：x=3 被跳过，因为 `k - 3 = 1` 已在 `chosen` 里。

```python
chosen = set()
total = 0
x = 1
while len(chosen) < n:
    if k - x not in chosen:
        chosen.add(x)
        total += x
    x += 1
return total
```

注意 `k - x` 可能为 0 或负数，此时必然不在集合中（集合只存正整数），自然取用，无需特判。

## 复杂度
时间：O(n + k)，循环最多推进到约 `k + n` 个数，每个 O(1) 集合查询。
空间：O(n)，`chosen` 集合最多存 n 个元素。

## 易错点
- 输入 `n = 2, k = 6`：若误以为「所有小于 k/2 的数都要取」而直接取 1,2 后停止判断，会漏掉后续 x 的检查逻辑；正确做法是逐个 x 检查 `k - x` 是否已选，本例取 1、2 后 x=3 时 `k-3=3` 不在集合，仍可取 3，但只需 2 个故答案为 3。
- 输入 `n = 5, k = 4`：若只取 `1..k//2` 即 {1,2} 就补连续整数 3,4,5，会得到含 1 和 3 的数组（1+3=4=k），总和偏小但非法；正确做法是跳过 3，取 4,5,6，答案 18。

## 如果面试官追问
若 n、k 放大到 10^9 要求 O(1) 公式？答：前半段取 `1..(k-1)//2`，若不够 n 则继续从 k 开始取连续整数，用等差数列求和直接算。
