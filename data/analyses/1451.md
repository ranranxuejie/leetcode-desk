## 一句话思路
按 `(len(word), 原下标)` 排序后拼接，Python 的 `sort` 稳定，所以只按长度排也能保住同长单词的原序。

## 怎么做
1. 用 `text.split()` 切词，得到 `words`；`split()` 不带参数会自动吃掉单个空格，不用手写 `split(' ')`。
2. 直接 `words.sort(key=len)`——`list.sort` 是稳定排序，长度相同的词保持原相对顺序，不需要额外存下标。
3. 把首词首字母大写、其余词全小写，再 `' '.join`。

以 `"Keep calm and code on"` 为例，`words = ["Keep","calm","and","code","on"]`，`key=len` 得到 `[4,4,3,4,2]`，排序后 `["on","and","Keep","calm","code"]`——`Keep/calm/code` 三个长度 4 的词仍按原出现顺序排列，这就是稳定性的直接体现。

```python
words = text.split()
words.sort(key=len)
words[0] = words[0].capitalize()
for i in range(1, len(words)):
    words[i] = words[i].lower()
return ' '.join(words)
```

注意 `capitalize()` 会把首词剩余字母转小写，正好满足「首字母大写、其余小写」；但若首词是 `"Leetcode"` 这种本来就规范的，`capitalize()` 结果不变，安全。

## 复杂度
时间：`split` 与 `join` 各 O(n)，排序 O(m log m)，m 为单词数。
空间：`words` 列表 O(n)，排序原地进行，无额外 O(n) 结构。

## 易错点
- 输入 `"To be or not to be"` → 若用 `sorted(words, key=len)` 再手动拼，容易忘了首词大写，输出 `"to be or to be not"` → 正确做法是排序后对 `words[0]` 调 `capitalize()`，其余 `lower()`。
- 输入 `"Keep calm and code on"` → 若用 `key=lambda w: len(w)` 配合非稳定排序（如手写快排）→ `Keep/calm/code` 顺序可能被打乱成 `code/Keep/calm` → 正确做法是用 Python 内置 `sort`（Timsort 稳定），或显式存 `(len(w), i)` 元组排序。

## 如果面试官追问
追问：若要求长度降序、同长保持原序怎么办？
答：`words.sort(key=len, reverse=True)` 仍稳定，同长词原序不变；不要用 `sorted(..., key=lambda w: -len(w))` 之外的取反技巧去破坏稳定性。
