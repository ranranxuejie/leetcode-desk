## 一句话思路
把 `order` 扫一遍，凡是出现在 `friends` 里的就按扫描顺序收集，天然得到完成顺序。

## 怎么做
1. 把 `friends` 转成集合 `fs`，让判断从 O(len(friends)) 降到 O(1)。
2. 顺序遍历 `order`，遇到 `x in fs` 就 append 进结果。
3. 遍历结束直接返回结果，长度必然等于 `len(friends)`。

以示例 1 为例：`order = [3,1,2,5,4]`，`fs = {1,3,4}`。扫到 3 命中、1 命中、2 不命中、5 不命中、4 命中，结果 `[3,1,4]`。关键中间值就是 `fs` 这个集合，它让每次判断只看当前元素本身，不看它在 `friends` 里的下标。

```python
fs = set(friends)
res = []
for x in order:
    if x in fs:
        res.append(x)
return res
```

也可以反过来做：先建 `pos = {v: i for i, v in enumerate(order)}`，再按 `pos` 给 `friends` 排序。但 `friends` 本身严格递增，排序键是 `pos`，写法更长，收益为零，不推荐。

注意 `friends` 递增这个条件在这里是干扰项——它只保证输入合法，不参与求解。真正决定输出顺序的是 `order` 的下标。

## 复杂度
时间 O(n)：`order` 扫一遍，集合查询 O(1)，n = len(order)。
空间 O(k)：`fs` 存 len(friends) 个元素，结果数组同阶，k ≤ 8。

## 易错点
- 误按 `friends` 原顺序输出 → 示例 1 会得到 `[1,3,4]` 而非 `[3,1,4]` → 必须以 `order` 为主循环，`friends` 只当查询集。
- 用 `order.index(f)` 对每个朋友求位置再排序 → 示例 2 中 `order.index(2)=4`、`order.index(5)=2`，虽然结果对，但复杂度退化成 O(n·k)，且 `index` 在重复值上会取首个位置；本题 `order` 是 1..n 的排列不会重复，但换成有重复的输入就错，正确做法是单次扫描。

## 如果面试官追问
追问：如果 `order` 长度到 10^6、`friends` 到 10^5 呢？
答：仍是 O(n) 单次扫描，`set(friends)` 建一次即可，不要对每个朋友去 `order` 里找位置。
