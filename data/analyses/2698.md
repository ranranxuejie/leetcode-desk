## 一句话思路
对每个 i 把 i*i 的字符串做回溯切分，看能否凑出 i；n≤1000 直接枚举，剪枝靠「部分和已超 i 就停」。

## 怎么做
1. 外层 `for i in range(1, n+1)`，取 `s = str(i*i)`，对 s 做 DFS 切分。
2. DFS 参数 `(pos, cur)`：`pos` 是 s 中当前切点，`cur` 是已累加的和；`pos == len(s)` 时返回 `cur == i`。
3. 每层枚举终点 `j` 从 `pos+1` 到 `len(s)`，取 `int(s[pos:j])` 递归；若 `cur + val > i` 直接 `break`（后面更长只会更大）。
4. 命中就把 `i*i` 累加进答案。

以 `i = 36` 为例：`s = "1296"`，先切 `"1"` 得 `cur=1`；再切 `"29"` 得 `cur=30`；剩 `"6"` 得 `cur=36 == i`，命中，答案加 `1296`。注意 `"12"+"9"+"6"=27`、`"129"+"6"=135` 都不等，只有这一条路径成立。

```python
def dfs(pos, cur):
    if pos == len(s):
        return cur == i
    for j in range(pos + 1, len(s) + 1):
        val = int(s[pos:j])
        if cur + val > i:
            break
        if dfs(j, cur + val):
            return True
    return False

ans = 0
for i in range(1, n + 1):
    s = str(i * i)
    if dfs(0, 0):
        ans += i * i
```

## 复杂度
时间：外层 n 次，每次对长度 ≤7 的串枚举切点，约 O(n·2^log n)，实际远小于此。
空间：递归深度 ≤7，O(log n)，无额外数组。

## 易错点
- `i = 10` 时 `s = "100"`，若只允许「每段非空且不以前导零开头」会漏掉 `"10"+"0"` 这条（`"0"` 单独成段是合法的）→ 正确做法是允许任意非空子串，`int("0") == 0` 照常参与求和。
- `i = 1` 时 `s = "1"`，若 DFS 写成「至少切两段」会返回 False → 正确做法是 `pos == len(s)` 时直接比较 `cur == i`，单段整串也算一种切分。

## 如果面试官追问
问：n 放大到 10^5 怎么办？答：预处理 1..1000 的合法 i 前缀和打表，查询 O(1)；因为合法 i 极少（1,9,10,36,45,55,82,91,99,100,…），枚举成本可忽略。
