## 一句话思路
从不超过 k 的最大斐波那契数开始贪心递减，因为最大数必被选中且不选它无法用更小数凑出更优解。

## 怎么做
1. 先递推生成所有 ≤ k 的斐波那契数，存进列表 `fib`（从 1, 1 开始，`fib[-1] + fib[-2]` 直到超过 k）。
2. 从 `fib` 末尾（最大数）往前扫，维护剩余量 `rem = k` 和计数 `cnt = 0`。
3. 对每个 `f`，若 `f <= rem` 就反复减：`cnt += rem // f`，`rem %= f`。
4. `rem` 归零时返回 `cnt`。

以 k = 19 为例：`fib = [1, 1, 2, 3, 5, 8, 13]`。从 13 开始，`rem = 19 - 13 = 6`，`cnt = 1`；8 跳过（8 > 6）；5 取一次，`rem = 1`，`cnt = 2`；3、2 跳过；1 取一次，`rem = 0`，`cnt = 3`。中间关键值是 `rem` 从 19 变 6 再变 1，最后归零。

```python
fib = [1, 1]
while fib[-1] + fib[-2] <= k:
    fib.append(fib[-1] + fib[-2])

rem, cnt = k, 0
for f in reversed(fib):
    if f <= rem:
        cnt += rem // f
        rem %= f
return cnt
```

注意 `fib` 里有两个 1，贪心时先遇到较大的那个 1 不影响结果，因为 `rem // 1` 会把剩余全吃掉。

## 复杂度
时间：生成斐波那契数 O(log k) 项，倒序扫描 O(log k)，总计 O(log k)。
空间：`fib` 列表存 O(log k) 个数，无其他额外结构。

## 易错点
- 生成循环条件写成 `fib[-1] + fib[-2] < k` 而非 `<= k`：k = 8 时漏掉 8 本身，`fib` 最大只到 5，结果从 1 变成 3（5+2+1）。正确做法是 `<= k`，让等于 k 的斐波那契数进入列表，一步取完。
- 用 `rem -= f` 只减一次而非 `rem %= f`：k = 10 时若对 1 只减一次，`rem` 停在 1 不归零，循环结束返回错误计数。正确做法是 `cnt += rem // f; rem %= f`，一次把同一个斐波那契数用尽。

## 如果面试官追问
问：如果要求输出具体用了哪些斐波那契数而非只返回个数？
答：在 `rem // f` 处记录 `(f, rem // f)` 的倍数对，最后按倍数展开成列表即可，贪心选择不变。
