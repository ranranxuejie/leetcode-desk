## 一句话思路
自顶向下记忆化：`f(n) = 1 + min(f(n-1), f(n//2)+1, f(n//3)+1)`，只对整除分支递归，减一用取模一步补齐。

## 怎么做
1. 定义 `f(x)` 为吃完 `x` 个橘子的最少天数，边界 `f(0)=0`、`f(1)=1`。
2. 关键剪枝：不要真的逐次减一。要让 `x` 变成 2 的倍数，只需先吃 `x % 2` 个（花 `x%2` 天），再走 `x//2` 分支；3 同理吃 `x % 3` 个。
3. 于是 `f(x) = min(x%2 + 1 + f(x//2), x%3 + 1 + f(x//3))`，用字典缓存。
4. 拿 `n=10` 走一遍：`f(10)` 走 2 分支得 `0+1+f(5)`；`f(5)` 走 3 分支得 `2+1+f(1)=3`，故 `f(5)=4`？不对——`f(5)` 走 2 分支是 `1+1+f(2)=1+1+1=3`，取小得 3，回代 `f(10)=1+3=4`，与示例一致。

```python
from functools import lru_cache

@lru_cache(None)
def f(x):
    if x <= 1:
        return x
    return min(x % 2 + 1 + f(x // 2),
               x % 3 + 1 + f(x // 3))
```
（`x=2` 时 `x%3=2`，`2+1+f(0)=3`，而 2 分支给 `0+1+f(1)=2`，取 2，正确。）

## 复杂度
时间：每层状态数 O(log n) 量级，每个状态 O(1)，总 O(log² n)。
空间：缓存 O(log² n) 个键，递归栈 O(log n)。

## 易错点
- 写成 `f(x-1)+1` 逐次递归 → `n=2*10^9` 时栈深两亿直接爆栈/超时 → 必须用 `x%2`、`x%3` 把减一压缩成常数步。
- 漏掉 `x%3` 那一步的代价 → 例如 `n=4`，只走 2 分支得 `0+1+f(2)=2`，但走 3 分支 `1+1+f(1)=3`，取小仍是 2；若误把 `x%3` 写成 0，`n=5` 会算成 `1+1+f(1)=3` 而非正确的 3——差别在 `n=7` 这类数上会少算天数，务必保留取模项。

## 如果面试官追问
问：要输出具体吃法方案怎么办？
答：缓存里同时存「选了哪个分支」，回溯时按 `x%k` 先补减一、再跳 `x//k`，逆序打印即可。
