## 一句话思路
从左到右、从右到左各扫一遍，取两次距离的较小值，因为每个位置最近的那个 `c` 必在它左边或右边。

## 怎么做
1. 初始化 `ans = [n] * n`，`last = -n`（用一个足够远的哨兵，保证第一次更新不会误判）。
2. 从左往右扫，遇到 `s[i] == c` 就更新 `last = i`，然后 `ans[i] = i - last`。
3. 把 `last` 重置为 `2 * n`，从右往左再扫一遍，`ans[i] = min(ans[i], last - i)`。
4. 返回 `ans`。

以 `s = "loveleetcode", c = "e"` 为例，左扫到 `i = 4` 时 `last = 3`，`ans[4] = 1`；右扫时 `i = 4` 的 `last = 5`，`min(1, 1) = 1`，与示例一致。而 `i = 0` 左扫得 `0 - (-12) = 12`，右扫 `last = 3` 得 `3`，取 `3`。

```python
n = len(s)
ans = [n] * n
last = -n
for i in range(n):
    if s[i] == c:
        last = i
    ans[i] = i - last
last = 2 * n
for i in range(n - 1, -1, -1):
    if s[i] == c:
        last = i
    ans[i] = min(ans[i], last - i)
return ans
```

关键点：哨兵 `-n` 和 `2 * n` 让「左侧还没有 `c`」的位置得到一个大于任何真实距离的值，从而被另一侧的结果覆盖掉。

## 复杂度
时间：O(n)，两趟线性扫描，每趟每个下标常数次操作。
空间：O(n)，除返回数组 `ans` 外只用了 `last` 一个变量。

## 易错点
- `s = "aaab", c = "b"`：若 `last` 初值取 `0` 而非 `-n`，左扫时 `ans[0] = 0 - 0 = 0`，错成 `[0,0,0,0]`；正确做法是初值取 `-n`，让 `ans[0]` 先得 `3`。
- `s = "eabcde", c = "e"`：若只做左扫不做右扫，`ans[5]` 会是 `5 - 0 = 5`，而正确答案是 `0`；必须补上右扫并用 `min` 合并，不能直接覆盖。

## 如果面试官追问
若 `c` 在 `s` 中出现多次且要求返回每个位置最近的 `c` 的下标而非距离？答：把 `ans[i]` 存成 `last` 本身，右扫时比较 `abs(i - last)` 决定是否替换。
