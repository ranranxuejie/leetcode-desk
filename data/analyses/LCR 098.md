## 一句话思路
到 (i,j) 的路径数等于上方与左方之和，因为最后一步只能从这两个格子迈进来。

## 怎么做
1. 把 `dp` 初始化成 `[1]*n`，表示第一行每个格子只有一路向右这一种走法。
2. 外层按行 `i` 从 1 到 m-1 遍历，内层按列 `j` 从 1 到 n-1 遍历。
3. 原地更新 `dp[j] = dp[j] + dp[j-1]`：等号右边的 `dp[j]` 还是上一行的值（上方），`dp[j-1]` 是本行刚算好的值（左方）。
4. 返回 `dp[n-1]`。

以 `m=3, n=7` 为例，初始 `dp = [1,1,1,1,1,1,1]`。处理完第 2 行后 `dp = [1,2,3,4,5,6,7]`，处理完第 3 行后 `dp = [1,3,6,10,15,21,28]`，`dp[6] = 28` 就是答案。关键中间值是第 2 行末尾的 7：它等于上一行末尾的 1 加上本行前一格的 6。

```python
dp = [1] * n
for i in range(1, m):
    for j in range(1, n):
        dp[j] += dp[j - 1]
return dp[n - 1]
```

`dp[j-1]` 必须在本轮已被覆盖，所以内层循环只能从小到大；反过来写就退化成只用上一行数据。

## 复杂度
时间 O(m·n)：两层循环各走 m-1、n-1 次，每次 O(1) 加法。
空间 O(n)：只开一个长度 n 的 `dp` 数组，行维度被滚动掉了。

## 易错点
- `m=1` 或 `n=1` → 若把循环写成 `range(m)` 且不特判，`dp` 初值虽是全 1 但内层 `range(1,1)` 不执行，结果碰巧对；真正翻车的是把 `dp` 初始化成 `[0]*n` 再只填 `dp[0]=1`，此时单行输入返回 0，正确做法是初值全 1。
- 内层写成 `for j in range(n-1, 0, -1)` → `dp[j-1]` 还是上一行的旧值，`m=3, n=7` 会算出 7 而不是 28，正确做法是从小到大遍历让 `dp[j-1]` 先被本行更新。

## 如果面试官追问
问：要求输出所有具体路径而非计数？
答：回溯 DFS，每步在「下」和「右」里选，走到 `(m-1,n-1)` 时把当前路径拷进结果，复杂度变成 O(路径数 × m+n)。
