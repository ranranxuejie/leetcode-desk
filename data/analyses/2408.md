## 一句话思路
每张表用 `dict` 存 `rowId -> row`，另存一个自增计数器 `next_id`，删除只删键、不动计数器。

## 怎么做
1. 构造时把 `names[i]` 映射到 `{"cols": columns[i], "rows": {}, "next_id": 1}`，`names` 互不相同所以直接建字典。
2. `ins`：先查 `name` 是否存在、`len(row) == cols`，任一不满足返回 `False`；否则 `rows[next_id] = row`，`next_id += 1`，返回 `True`。
3. `rmv`：`rows.pop(rowId, None)`，不存在就自然什么都不做，`next_id` 保持不变。
4. `sel`：`rows.get(rowId)` 为 `None` 或 `columnId` 越界（`< 1` 或 `> cols`）返回 `"<null>"`，否则取 `row[columnId - 1]`。
5. `exp`：按 `rowId` 升序拼 `str(rid) + "," + ",".join(row)`。

以示例 1 为例：`ins("two", ["first","second","third"])` 时 `next_id` 从 1 变 2，`rows = {1: [...]}`；随后 `rmv("two", 1)` 后 `rows = {}` 但 `next_id` 仍是 2，所以第二次 `ins` 拿到的 id 是 2 而不是 1——这正是示例输出里 `"2,fourth,fifth,sixth"` 的来源。

```python
def ins(self, name, row):
    t = self.tables.get(name)
    if t is None or len(row) != t["cols"]:
        return False
    t["rows"][t["next_id"]] = row
    t["next_id"] += 1
    return True

def sel(self, name, rowId, columnId):
    t = self.tables.get(name)
    if t is None or rowId not in t["rows"] or not (1 <= columnId <= t["cols"]):
        return "<null>"
    return t["rows"][rowId][columnId - 1]

def exp(self, name):
    t = self.tables.get(name)
    if t is None:
        return []
    return [str(rid) + "," + ",".join(t["rows"][rid]) for rid in sorted(t["rows"])]
```

## 复杂度
时间：`ins`/`rmv`/`sel` 均摊 O(1)，`exp` 为 O(k log k)，k 是该表当前行数（排序）。
空间：O(总插入行数 × 列数)，只存未删除的行，`next_id` 是单个整数。

## 易错点
- 删光某表所有行后再 `ins`，若把 `next_id` 重置为 1 → 新行 id 变成 1，与示例 1 期望的 2 冲突；正确做法是 `rmv` 只 `pop` 键，`next_id` 永不回退。
- `sel` 传 `columnId = 0` 或 `cols + 1`，若只判 `rowId in rows` 就直接 `row[columnId-1]` → 会取到 `row[-1]`（最后一列）或抛 `IndexError`；必须先判 `1 <= columnId <= cols` 再索引。

## 如果面试官追问
问：表被大量删除后变稀疏，怎么选结构？
答：仍用 `dict` 按 `rowId` 存，删除即释放内存，`exp` 时排序输出；只有 `exp` 频繁且要求顺序时才换有序结构。
