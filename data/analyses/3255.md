## 一句话思路
维护「以 i 结尾的连续上升段长度」`run`，`run >= k` 时答案就是 `nums[i]`，否则 -1。

## 怎么做
1. 遍历 `nums`，用 `run` 记录以当前下标结尾、满足 `nums[j] == nums[j-1] + 1` 的连续长度；`i == 0` 或断链时重置为 1。
2. 当 `i >= k - 1` 时，若 `run >= k`，说明窗口 `nums[i-k+1..i]` 整段连续上升，能量值就是窗口最大值 `nums[i]`；否则填 -1。
3. 结果按 `i` 递增顺序 append，天然对应 `results[i-k+1]`。

以 `nums = [1,2,3,4,3,2,5], k = 3` 为例：`i=2` 时 `run=3`，`run >= 3` 成立，答案取 `nums[2]=3`；`i=3` 时 `run=4`，答案取 `nums[3]=4`；`i=4` 时 `nums[4]=3 != nums[3]+1`，`run` 重置为 1，`1 < 3` 填 -1。关键中间值就是 `run` 在 `i=4` 从 4 掉回 1。

```python
res = []
run = 0
for i, x in enumerate(nums):
    if i > 0 and x == nums[i - 1] + 1:
        run += 1
    else:
        run = 1
    if i >= k - 1:
        res.append(x if run >= k else -1)
```

注意 `run` 初值写 0、循环内先判断再赋值，避免 `i=0` 时访问 `nums[-1]`。

## 复杂度
时间 O(n)：每个下标只做一次比较和一次 append。
空间 O(1) 额外（不计长度 n-k+1 的输出数组）。

## 易错点
- `nums = [2,2,2,2,2], k = 4` → 若只判 `run >= k` 却把 `run` 在相等元素上也累加，会错判成连续上升 → 必须严格用 `x == nums[i-1] + 1`，相等不算。
- `k = 1` → 若把 `i >= k - 1` 写成 `i > k - 1`，会漏掉第一个窗口，输出长度变成 n-1 → 边界条件写成 `i >= k - 1`，此时 `run` 恒为 1 满足 `run >= 1`，答案就是每个元素本身。

## 如果面试官追问
若要求返回每个窗口的具体子数组而非能量值？答：仍需 O(n) 判断连续性，但输出总量 O(nk)，无法低于这个量级。
