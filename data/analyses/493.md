## 一句话思路
归并排序分治：左右两半各自有序后，用双指针线性统计跨半区的翻转对，再合并。

## 怎么做
1. 递归把 `nums` 拆到单元素，返回该段内部的翻转对数。
2. 合并前先统计跨半区对数：左半 `L`、右半 `R` 都已升序，对每个 `L[i]` 找最小的 `j` 使 `L[i] <= 2*R[j]`，则 `R[0..j-1]` 全部满足，累加 `j`；`j` 只增不减。
3. 用临时数组做标准归并，写回 `nums` 对应区间，返回「左内部 + 右内部 + 跨区」。

以 `[1,3,2,3,1]` 为例，拆到 `[3]` 与 `[2,3,1]` 合并时，左 `L=[3]`、右 `R=[1,2,3]`：`3 > 2*1=2` 成立，`3 > 2*2=4` 不成立，`j` 停在 1，跨区贡献 1 对 `(3,1)`。最终总计 2。

```python
def merge_count(lo, hi):
    if hi - lo <= 1:
        return 0
    mid = (lo + hi) // 2
    cnt = merge_count(lo, mid) + merge_count(mid, hi)
    j = mid
    for i in range(lo, mid):
        while j < hi and nums[i] > 2 * nums[j]:
            j += 1
        cnt += j - mid
    nums[lo:hi] = sorted(nums[lo:hi])
    return cnt
```

（`sorted` 只为压缩篇幅，等价于双指针归并；面试写标准归并更稳。）

## 复杂度
时间：每层归并 O(n)，共 log n 层，O(n log n)。
空间：递归栈 O(log n) 加归并临时数组 O(n)。

## 易错点
- 输入含 `-2**31` 这类极小值 → 若先算 `2*nums[j]` 再比较，在 C++/Java 里会溢出成错误的正数；Python 大整数不溢出，但若你按 32 位模拟（如 `(2*nums[j]) & 0xFFFFFFFF`）就会错，正确做法是直接比较 `nums[i] > 2 * nums[j]`，不做截断。
- 输入 `[2,4,3,5,1]` → 若在归并**之后**才统计跨区，左右已混序，双指针单调性被破坏，会漏掉 `(4,1)`、`(3,1)` 这类对；正确做法是统计必须在 `nums[lo:hi]` 被覆盖之前完成。

## 如果面试官追问
问：n 到 10^6、内存吃紧怎么办？
答：改用树状数组，把 `nums` 与 `2*nums` 离散化后按值域计数，空间 O(n) 但常数更小。
