## 一句话思路
按位置从大到小排序，算每辆车到达 target 的时间，时间不严格递增就并入前一个车队。

## 怎么做
1. 把 `position` 和 `speed` 配对，按 `position` 降序排，得到从最靠近 target 到最远的顺序。
2. 对每辆车算 `(target - p) / s`，得到它单独到达终点的时间。
3. 从前往后扫，维护当前车队的最慢到达时间 `cur`；若新车时间 `t <= cur`，它会在终点前追上，并入车队，`cur` 不变。
4. 若 `t > cur`，说明它追不上前面，自己开一个新队，`cur = t`，答案加一。

以示例 1 为例，排序后是 `(10,2),(8,4),(5,1),(3,3),(0,1)`，时间依次为 `1.0, 1.0, 7.0, 3.0, 12.0`。第一辆 `cur=1.0` 计数 1；第二辆 `1.0 <= 1.0` 并入；第三辆 `7.0 > 1.0` 新队 `cur=7.0` 计数 2；第四辆 `3.0 <= 7.0` 并入；第五辆 `12.0 > 7.0` 新队计数 3。

```python
cars = sorted(zip(position, speed), reverse=True)
cur = 0.0
ans = 0
for p, s in cars:
    t = (target - p) / s
    if t > cur:
        ans += 1
        cur = t
return ans
```

关键点：排序必须按位置降序，因为只有后面的车才可能追上前面的车；比较的是「到达终点的时间」，不是「相遇位置」。

## 复杂度
时间：排序 O(n log n)，扫描 O(n)，n 为车数。
空间：排序后新列表 O(n)，其余 O(1)。

## 易错点
- 用 `position` 升序排 → 示例 1 会先处理 `(0,1)` 再处理 `(10,2)`，把「后车追前车」判成「前车等后车」，输出错成 2 或 4。必须 `reverse=True` 按位置降序。
- 用浮点 `t` 直接比较 → 像 `(12-10)/2` 和 `(12-8)/4` 都等于 `1.0` 没问题，但某些数据下 `a/b` 与 `c/d` 数学相等而浮点不等，会多算车队。稳妥做法是交叉相乘比较 `(target-p1)*s2 <= (target-p2)*s1`，全程整数。

## 如果面试官追问
若要求输出每个车队的车辆编号？答：在扫描时用并查集或列表把 `t <= cur` 的车挂到当前队首，`t > cur` 时开新组，最后按组输出即可。
