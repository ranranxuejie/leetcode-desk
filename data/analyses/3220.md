## 一句话思路
按 `transaction_date` 分组，用 `CASE WHEN amount % 2 = 1` 分别累加奇偶金额，`SUM` 天然把缺失分支当 0。

## 怎么做
1. 用 `GROUP BY transaction_date` 把同一天的交易聚到一起。
2. 在 `SUM` 里套 `CASE WHEN amount % 2 = 1 THEN amount ELSE 0 END` 得到 `odd_sum`，偶数分支同理。
3. 用 `ORDER BY transaction_date` 升序输出。

拿官方示例 2024-07-01 这天看：三行 `amount` 是 150、200、75。`150 % 2 = 0` 进偶数分支，`200 % 2 = 0` 进偶数分支，`75 % 2 = 1` 进奇数分支，所以 `odd_sum = 0 + 0 + 75 = 75`，`even_sum = 150 + 200 + 0 = 350`，和输出表第一行对上。2024-07-02 的 300、50 全是偶数，奇数分支三行都取 `ELSE 0`，`odd_sum = 0`，这正是「没有奇数交易显示 0」的来由，不需要额外补 `COALESCE`。

```python
# 伪 SQL 表达分组逻辑，Python 侧等价写法：
from collections import defaultdict

agg = defaultdict(lambda: [0, 0])  # [odd_sum, even_sum]
for tid, amount, d in rows:
    if amount % 2 == 1:
        agg[d][0] += amount
    else:
        agg[d][1] += amount

result = [(d, agg[d][0], agg[d][1]) for d in sorted(agg)]
```

关键点：`defaultdict` 的初值 `[0, 0]` 承担了 SQL 里 `ELSE 0` 的角色，某天只有偶数交易时 `agg[d][0]` 保持 0，不会缺列。

## 复杂度
时间 O(n + d log d)：n 是交易行数，d 是不同日期数，排序贡献 log。
空间 O(d)：只开每个日期一个 `[odd_sum, even_sum]` 二元组。

## 易错点
- 用 `amount % 2 == 1` 判奇数，若 `amount` 可能为负（题面未说明非负），Python 里 `-3 % 2 == 1` 仍成立，但 SQL 某些方言 `MOD(-3,2) = -1`，`= 1` 会漏掉负数奇数 → 统一写成 `amount % 2 != 0` 更稳。
- 只对出现过的日期分组，若某天整表无任何交易，该天不会出现在结果里；题面「某天没有奇数或偶数交易」指的是该天有交易但缺奇/偶分支，不是整天缺失，别自作主张补日历。

## 如果面试官追问
问：如果要求同时输出交易笔数而非金额总和？
答：把 `SUM(CASE...)` 换成 `SUM(CASE WHEN amount % 2 = 1 THEN 1 ELSE 0 END)`，分组和排序不变。
