## 一句话思路
用 `NOT IN` 先查出买过 RED 的 `sales_id` 黑名单，再从 SalesPerson 里排除它们。

## 怎么做
1. 在 Company 里筛 `name = 'RED'`，拿到 `com_id = 1`。
2. 用这个 `com_id` 去 Orders 里取 `sales_id`，得到黑名单 `{1, 4}`（John、Pam）。
3. 对 SalesPerson 做 `sales_id NOT IN (黑名单)`，输出 `name`。

关键中间值：示例中 Orders 里 `com_id = 1` 的行是 order_id 3 和 4，对应 `sales_id` 为 1 和 4；剩下 2、3、5 即 Amy、Mark、Alex。

```python
red_ids = {c.com_id for c in Company if c.name == "RED"}
bad = {o.sales_id for o in Orders if o.com_id in red_ids}
ans = [s.name for s in SalesPerson if s.sales_id not in bad]
```

如果写成 SQL，就是：

```python
# SELECT name FROM SalesPerson
# WHERE sales_id NOT IN (
#   SELECT o.sales_id FROM Orders o
#   JOIN Company c ON o.com_id = c.com_id
#   WHERE c.name = 'RED')
```

注意 `NOT IN` 的子查询结果里若有 `NULL`，整个条件会变成未知、一行都返回不了；本题 `sales_id` 是外键非空，安全。

## 复杂度
时间 O(S + O + C)，三张表各扫一遍，集合查找 O(1)。
空间 O(R)，R 为黑名单大小，最多等于 Orders 行数。

## 易错点
- 把 `NOT IN` 写成 `NOT EXISTS` 却漏了关联条件 `o.sales_id = s.sales_id` → 子查询恒为真，返回空集；正确做法是关联到外层销售员。
- 只按 `Company.name = 'RED'` 过滤却忘了 Orders 里可能有多家 RED 订单、同一销售员重复出现 → 用 `DISTINCT` 或集合去重，否则黑名单有重复但不影响 `NOT IN` 结果，真正会错的是用 `JOIN` 后直接 `GROUP BY` 计数时把重复订单算成多个销售员。

## 如果面试官追问
问：如果 RED 公司改名或有多条同名记录怎么办？
答：先按 `name = 'RED'` 收集全部 `com_id` 再进 Orders，不要假设只有一条。
