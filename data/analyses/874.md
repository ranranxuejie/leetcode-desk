## 一句话思路
用哈希集合存障碍物，按方向数组逐步模拟，每走一格查一次集合，撞到就停。

## 怎么做
1. 把 `obstacles` 转成 `set` 存 `(x, y)` 元组，查询 O(1)。
2. 方向用 `dirs = [(0,1),(1,0),(0,-1),(-1,0)]` 表示北东南西，`d` 初始为 0（北）。
3. 遍历 `commands`：`-2` 时 `d = (d+3) % 4`，`-1` 时 `d = (d+1) % 4`，正数则逐格移动。
4. 每走一格先算 `nx, ny`，若 `(nx, ny) in obs` 就 `break`，否则更新 `x, y` 并刷新 `ans = max(ans, x*x + y*y)`。

以示例 2 为例：`commands = [4,-1,4,-2,4]`，`obstacles = [[2,4]]`。执行到第 3 条命令 `4` 时，`d=1`（东），从 `(0,4)` 出发，第一格到 `(1,4)` 合法，第二格 `(2,4)` 命中障碍物，`break`，停在 `(1,4)`，`ans` 此时为 17。后续向北到 `(1,8)`，`ans` 更新为 65。

```python
obs = set(map(tuple, obstacles))
dirs = [(0,1),(1,0),(0,-1),(-1,0)]
x = y = d = ans = 0
for c in commands:
    if c == -2:
        d = (d + 3) % 4
    elif c == -1:
        d = (d + 1) % 4
    else:
        dx, dy = dirs[d]
        for _ in range(c):
            nx, ny = x + dx, y + dy
            if (nx, ny) in obs:
                break
            x, y = nx, ny
            ans = max(ans, x*x + y*y)
```

## 复杂度
时间：O(len(commands) × 9 + len(obstacles))，每步最多走 9 格，建集合扫一遍障碍物。
空间：O(len(obstacles))，额外开一个哈希集合存障碍物坐标。

## 易错点
- `obstacles` 是列表的列表，直接 `set(obstacles)` 会报 `TypeError: unhashable type: 'list'`，必须先 `map(tuple, ...)` 转成元组再入集合。
- 障碍物在 `(0,0)` 或起点方向第一格时，若先移动再判断，会错误地走到障碍物上并更新 `ans`；正确做法是每格先算 `nx, ny` 查集合，命中就 `break`，不更新坐标。

## 如果面试官追问
如果 `commands` 里的移动步数上限从 9 放大到 10^9，怎么优化？答：把逐格走改成沿当前方向二分查找该行/列上最近的障碍物，一次跳跃到障碍物前一格。
