## 一句话思路
从右往左维护后缀和与后缀个数，用 `nums[i] * cnt > suffix_sum` 做整数比较，避免浮点误差。

## 怎么做
1. 初始化 `suffix_sum = 0`、`cnt = 0`、`ans = 0`，从 `i = n-1` 开始倒序遍历。
2. 每轮先用当前 `suffix_sum / cnt` 判断 `nums[i]` 是否主导（`cnt > 0` 时），再把它并入后缀。
3. 判断写成乘法 `nums[i] * cnt > suffix_sum`，等价于 `nums[i] > suffix_sum / cnt` 且无精度问题。
4. 遍历结束后返回 `ans`。

以 `nums = [5,4,3]` 为例：`i=2` 时 `cnt=0` 跳过，并入后 `suffix_sum=3, cnt=1`；`i=1` 时 `4*1 > 3` 成立，`ans=1`，并入后 `suffix_sum=7, cnt=2`；`i=0` 时 `5*2=10 > 7` 成立，`ans=2`。

```python
n = len(nums)
suffix_sum = 0
cnt = 0
ans = 0
for i in range(n - 1, -1, -1):
    if cnt > 0 and nums[i] * cnt > suffix_sum:
        ans += 1
    suffix_sum += nums[i]
    cnt += 1
return ans
```

## 复杂度
时间：O(n)，倒序遍历一次，每个下标做一次乘法和一次加法。
空间：O(1)，只开了 `suffix_sum`、`cnt`、`ans` 三个标量。

## 易错点
- `nums = [1]` 或 `[5,4,3]` 的 `i = n-1`：若先判断再并入，`cnt=0` 会触发除零或把最右元素误判成主导；正确做法是先判 `cnt > 0`，最右元素永远不计入 `ans`。
- `nums = [4,1,2]` 的 `i=1`：用 `1 > 1.5` 浮点比较虽结果对，但 `nums = [3,1,1,1]` 这类 `suffix_sum/cnt` 出现循环小数时浮点可能翻转；正确做法统一用 `nums[i] * cnt > suffix_sum` 整数比较。

## 如果面试官追问
若 n 扩大到 10^5 并要求输出所有主导下标而非计数？答：同一套倒序遍历，把 `ans += 1` 换成 `ans.append(i)`，最后反转列表即可，仍是 O(n)。
