## 一句话思路
只反转后一半数字，与前一半比较，避免整体反转可能带来的溢出问题。

## 怎么做
1. 负数直接返回 `False`；末位为 0 且 x 不为 0（如 10）也返回 `False`。
2. 循环把 x 的末位弹出压入 `rev`，直到 `rev >= x` 停止。
3. 偶数位比较 `x == rev`，奇数位比较 `x == rev // 10`。

以 `x = 121` 为例：第一轮 `rev = 1, x = 12`；第二轮 `rev = 12, x = 1`，此时 `rev >= x` 停止，奇数位判断 `x == rev // 10` 即 `1 == 1`，返回 `True`。

```python
if x < 0 or (x % 10 == 0 and x != 0):
    return False
rev = 0
while x > rev:
    rev = rev * 10 + x % 10
    x //= 10
return x == rev or x == rev // 10
```

注意 `x = 0` 时循环不执行，`0 == 0` 返回 `True`，符合预期。

## 复杂度
时间：O(log₁₀x)，循环次数是 x 的位数，即数字长度。
空间：O(1)，只开了 `rev` 一个整型变量。

## 易错点
- 输入 `x = 10` → 若不特判末位 0，循环后 `rev = 1, x = 0`，`0 == 1` 和 `0 == 0` 中后者成立，会错返回 `True` → 必须加 `x % 10 == 0 and x != 0` 提前返回 `False`。
- 输入 `x = 12321`（奇数位）→ 若只写 `x == rev`，循环结束时 `x = 12, rev = 123`，比较失败错返回 `False` → 奇数位要额外判断 `x == rev // 10`，用整除丢掉中间那位。

## 如果面试官追问
问：如果要求判断任意进制（比如二进制）下的回文数怎么办？
答：把 `% 10` 和 `// 10` 换成 `% base` 和 `// base`，其余逻辑不变。
