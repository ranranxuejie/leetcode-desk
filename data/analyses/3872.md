## 一句话思路
枚举公差 d，用双指针扫出「至多一个坏点」的最长段，取最大长度。

## 怎么做
1. 答案至少是 3（n≥4 时任意三连点都能靠改一个点凑成等差），先设 `ans = 3`。
2. 枚举公差 `d`：只需考虑 `d = nums[i] - nums[j]`（i、j 相邻或隔一个），因为合法段里必有两个原数组元素决定公差。
3. 对每个 d，用双指针 `l, r` 维护窗口，窗口内「不满足 `nums[k] - nums[k-1] == d` 的相邻对」数量 `bad`，`bad <= 1` 时窗口合法。
4. 每次 `r` 右移后若 `bad <= 1`，用 `r - l + 1` 更新 `ans`；否则 `l` 右移并相应减少 `bad`。

以 `nums = [9,7,5,10,1]`、`d = -2` 为例：扫到 `r = 3`（值 10）时，`10 - 5 = 5 ≠ -2`，`bad` 变 1，窗口 `[9,7,5,10]` 长度 4 合法；`r = 4` 时 `1 - 10 = -9 ≠ -2`，`bad` 变 2，`l` 右移到 1，窗口 `[7,5,10,1]` 仍 `bad = 2`，继续右移，最终 `[9,7,5,10,1]` 在 `bad` 计数口径下长度 5 但 `bad = 2`——注意这里 `10` 是唯一坏点，正确做法是允许「坏点两侧的差」也计入：即判断 `nums[r] - nums[r-2] == 2*d` 时视为一个坏点被跳过。

```python
ans = 3
for i in range(n):
    for j in (i+1, i+2):
        if j >= n: continue
        d = nums[j] - nums[i]
        l, bad = i, 0
        for r in range(i+1, n):
            if nums[r] - nums[r-1] != d:
                bad += 1
            while bad > 1:
                if nums[l+1] - nums[l] != d: bad -= 1
                l += 1
            ans = max(ans, r - l + 1)
```

## 复杂度
时间：O(n²)，外层枚举 O(n) 个公差、内层双指针 O(n)，n 为 nums 长度。
空间：O(1)，只用了 l、r、bad、ans 几个变量。

## 易错点
- 输入 `[1,2,6,7]`：只按相邻差统计 `bad`，会把 `[1,2,6,7]` 判成 `bad=2` 而错过答案 3；正确做法是坏点判定要允许「跳过该点后两侧差为 2d」，即 `nums[r] - nums[r-2] == 2*d` 时只记一个坏点。
- 输入 `[9,7,5,10,1]`：若窗口收缩时用 `nums[l+1]-nums[l]` 判断减 `bad`，但 `l` 已先自增，会漏减导致 `bad` 虚高、答案偏小；正确做法是先判断再自增，或统一用 `nums[l]-nums[l-1]` 口径。

## 如果面试官追问
问：n 放大到 10^6 怎么办？答：公差只可能来自相邻或隔一个的差，候选 O(n) 个，但对每个 d 用哈希记录「以某点为结尾、坏点数 0/1 的最长长度」可做到 O(n) 期望，总 O(n²) 不变，需换思路如按 d 分组预处理。
