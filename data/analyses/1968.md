## 一句话思路
排序后把前半段和后半段交错拼接，让每个元素都夹在比自己大和比自己小的数之间，平均值不可能等于它。

## 怎么做
1. 先对 `nums` 排序，得到升序序列。
2. 取中点 `mid = (n + 1) // 2`，前半段 `nums[:mid]`、后半段 `nums[mid:]`。
3. 交错拼接：依次取前半段一个、后半段一个，即 `nums[0], nums[mid], nums[1], nums[mid+1], ...`。

以 `nums = [1,2,3,4,5]` 为例，排序后 `mid = 3`，前半段 `[1,2,3]`，后半段 `[4,5]`，交错得 `[1,4,2,5,3]`。验证 `i=1`：`(1+2)/2 = 1.5 ≠ 4`；`i=2`：`(4+5)/2 = 4.5 ≠ 2`；`i=3`：`(2+3)/2 = 2.5 ≠ 5`，全部成立。

为什么成立：交错后每个位置要么是「小-大-小」要么是「大-小-大」的局部形态。对任意 `i`，`nums[i-1]` 和 `nums[i+1]` 来自不同的半段，一个严格小于 `nums[i]`、一个严格大于 `nums[i]`（或反之），所以 `nums[i]` 严格落在两邻居之间，而两邻居的平均值必然严格偏离它——除非两邻居相等，但数组元素互不相同，不会发生。

```python
nums.sort()
n = len(nums)
mid = (n + 1) // 2
res = []
for i in range(mid):
    res.append(nums[i])
    if mid + i < n:
        res.append(nums[mid + i])
return res
```

注意 `mid` 用 `(n+1)//2` 而不是 `n//2`：奇数长度时前半段多一个，保证交错后首尾都是前半段的元素，不会出现末尾两个后半段元素相邻。

## 复杂度
时间：排序 `O(n log n)`，交错拼接 `O(n)`，总 `O(n log n)`。
空间：结果数组 `O(n)`，排序若用 Timsort 最坏 `O(n)` 额外空间。

## 易错点
- 输入 `nums = [1,2,3]`（长度 3 的奇数）：若 `mid = n // 2 = 1`，交错得 `[1,2,3]`，`i=1` 时 `(1+3)/2 = 2` 恰好等于 `nums[1]`，直接翻车。正确做法是 `mid = (n+1)//2 = 2`，得 `[1,3,2]`，`(1+2)/2 = 1.5 ≠ 3`。
- 输入 `nums = [0,1,2,3]`（偶数长度）：若把后半段整体放在前面再拼前半段（`[2,3,0,1]`），`i=1` 时 `(2+0)/2 = 1` 等于 `nums[1]`。必须严格一个前半段、一个后半段交替，不能分块拼接。

## 如果面试官追问
问：如果要求返回字典序最小的合法排列怎么办？
答：交错法不保证字典序最小，需要按位置贪心枚举候选值并验证，复杂度会升到 `O(n^2)` 级别，得用有序结构优化。
