## 一句话思路
一次遍历 `logs`，用相邻 `leaveTime` 之差算每个任务用时，边算边维护「最大用时 + 对应最小 id」。

## 怎么做
1. 初始化 `best = logs[0][1]`（任务 0 从时刻 0 开始，用时就是它的 `leaveTime`），`ans = logs[0][0]`。
2. 从 `i = 1` 开始遍历，用时 `cost = logs[i][1] - logs[i-1][1]`。
3. 若 `cost > best`，更新 `best = cost`、`ans = logs[i][0]`。
4. 若 `cost == best` 且 `logs[i][0] < ans`，只更新 `ans`（保留更小 id）。

拿示例 1 走一遍：`logs = [[0,3],[2,5],[0,9],[1,15]]`，初始 `best=3, ans=0`。`i=1` 时 `cost=5-3=2 < 3` 跳过；`i=2` 时 `cost=9-5=4 > 3`，`best=4, ans=0`；`i=3` 时 `cost=15-9=6 > 4`，`best=6, ans=1`。返回 1。

```python
best, ans = logs[0][1], logs[0][0]
for i in range(1, len(logs)):
    cost = logs[i][1] - logs[i-1][1]
    if cost > best:
        best, ans = cost, logs[i][0]
    elif cost == best and logs[i][0] < ans:
        ans = logs[i][0]
return ans
```

关键点：`cost` 只依赖前一条的 `leaveTime`，不需要额外存开始时间；`leaveTime` 严格递增，差值必为正，不用取绝对值。

## 复杂度
时间：O(m)，m 为 `logs` 长度，一次遍历，`n` 完全没用到。
空间：O(1)，只开了 `best`、`ans`、`cost` 三个变量。

## 易错点
- 把 `best` 初始化成 0 或 `-1`：示例 3 `logs=[[0,10],[1,20]]` 里任务 0 用时 10 会被漏掉比较逻辑之外的边界，若初始值设错（比如设成 `logs[0][1]` 之外的数）会算错首个任务；正确做法是直接用 `logs[0][1]` 当初始最大用时。
- 平局时只更新 `best` 不比较 id：示例 3 两个任务都是 10，若写成 `if cost >= best: ans = logs[i][0]`，`i=1` 会把 `ans` 覆盖成 1，输出 1 而非 0；正确做法是严格大于才换 `ans`，等于时再比 id 大小。

## 如果面试官追问
问：如果 `logs` 不按 `leaveTime` 排序怎么办？
答：先按 `leaveTime` 排序再扫，或改用「记录每个 id 的总用时」的哈希表，最后取最大用时里最小 id。
