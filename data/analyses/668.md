## 一句话思路
对答案值二分，用 `count(x) = Σ min(n, x//i)` 数出 ≤x 的个数，找最小的 x 使 count ≥ k。

## 怎么做
1. 二分区间取 `lo, hi = 1, m*n`，答案必在其中。
2. 每轮取 `mid = (lo + hi) // 2`，遍历 `i = 1..m` 累加 `min(n, mid // i)`。
3. 若 `cnt >= k` 则 `hi = mid`，否则 `lo = mid + 1`。
4. 循环结束返回 `lo`。

以 `m = 3, n = 3, k = 5` 为例：`lo=1, hi=9`，`mid=5` 时 `i=1` 贡献 `min(3,5)=3`，`i=2` 贡献 `min(3,2)=2`，`i=3` 贡献 `min(3,1)=1`，`cnt=6 ≥ 5`，故 `hi=5`；继续收缩到 `lo=hi=3`，返回 3。

```python
lo, hi = 1, m * n
while lo < hi:
    mid = (lo + hi) // 2
    cnt = 0
    for i in range(1, m + 1):
        cnt += min(n, mid // i)
    if cnt >= k:
        hi = mid
    else:
        lo = mid + 1
return lo
```

关键点：`min(n, mid // i)` 的 `n` 截断不能省。第 `i` 行是 `i, 2i, ..., ni`，`mid // i` 可能超过 `n`，比如 `m=2, n=3, mid=6` 时 `i=1` 得 `6//1=6`，但该行只有 3 个数，必须截到 3，否则 `cnt` 虚高、二分被推向错误的小值。

## 复杂度
时间：`O(m log(mn))`，`m` 来自每轮扫行，`log(mn)` 来自二分。
空间：`O(1)`，只开 `lo/hi/mid/cnt` 四个标量。

## 易错点
- `m=2, n=3, k=6` 时若漏掉 `min(n, ...)`，`mid=6` 的 `cnt` 会算成 `6+3=9`，把 `hi` 压到 6 以下，最终返回 4 而非 6；正确做法是每行贡献一律取 `min(n, mid // i)`。
- 循环条件写成 `lo <= hi` 并在 `cnt >= k` 时 `hi = mid - 1`，会跳过真正的答案值（如示例 1 中 `mid=3` 时 `cnt=5` 恰好等于 k，却被排除）；正确做法是 `while lo < hi` 配 `hi = mid`，让 `lo` 收敛到最小可行值。

## 如果面试官追问
若 `m, n` 都放大到 `10^9`、`k` 仍为 `m*n` 量级怎么办？
答：把每轮 `O(m)` 的扫描换成对 `mid // i` 分块求和，或枚举较小的那一维，复杂度降到 `O(min(m,n) log(mn))`。
