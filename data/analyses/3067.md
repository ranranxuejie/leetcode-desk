## 一句话思路
对每个节点 c 分别 DFS 各邻居分支，统计距离能被 signalSpeed 整除的节点数，再两两相乘累加。

## 怎么做
1. 用 edges 建邻接表 `g[u].append((v, w))`，n = len(edges) + 1。
2. 对每个候选中心 c，遍历它的每个邻居，从该邻居出发 DFS，只往远离 c 的方向走，累计距离 dist。
3. DFS 中若 `dist % signalSpeed == 0` 就计数 +1，并继续往下传 `dist + w`。
4. 设各分支计数为 `cnts`，答案 = 依次累加 `cnts[i] * 已累加和`（等价于所有无序对之积之和）。

以示例 2 的 c = 0 为例：邻居 6 的分支距离 3 命中（节点 6），再走 3+3=6 命中（节点 5），计数 2；邻居 3 的分支距离 1 不命中，1+2=3 命中（节点 4），计数 1。`cnts = [2, 1]`，答案 = 2*1 = 2，与输出 `count[0] = 2` 一致。

```python
def dfs(u, p, dist):
    res = 1 if dist % signalSpeed == 0 else 0
    for v, w in g[u]:
        if v != p:
            res += dfs(v, u, dist + w)
    return res

ans = []
for c in range(n):
    total = cur = 0
    for v, w in g[c]:
        cnt = dfs(v, c, w)
        total += cur * cnt
        cur += cnt
    ans.append(total)
```

## 复杂度
时间：每个中心做一次全树 DFS，O(n²)，n 为节点数。
空间：邻接表 O(n)，DFS 递归栈最深 O(n)。

## 易错点
- 从 c 出发 DFS 时忘记传父节点 `p`，会沿原边折返，把 c 自己或重复节点算进分支计数，导致 `cnts` 偏大、答案虚高；必须用 `v != p` 剪掉回头路。
- 距离判定写成 `dist == signalSpeed` 而非 `dist % signalSpeed == 0`：示例 2 中 c=0 到节点 5 的距离是 6，等于 2 倍 signalSpeed，用等号会漏掉它，count[0] 从 2 变成 0。

## 如果面试官追问
若 n 放大到 1e5 怎么办？答：用换根 DP，先算以 0 为根的各子树按距离模 signalSpeed 分类的计数，再二次 DFS 把父方向贡献下推，做到 O(n·signalSpeed) 或 O(n)。
