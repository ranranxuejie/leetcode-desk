## 一句话思路
按时间顺序扫描 events，用 `offline_until[i]` 记录每个用户恢复在线的时刻，MESSAGE 时按当前时刻判断在线状态并累加。

## 怎么做
1. 维护 `mentions = [0]*numberOfUsers` 和 `offline_until = [0]*numberOfUsers`，后者初值 0 表示一直在线。
2. 遍历 events，先取 `t = int(events[i][1])`；OFFLINE 事件直接写 `offline_until[int(events[i][2])] = t + 60`。
3. MESSAGE 事件分三种：`ALL` 给所有人 +1；`HERE` 只给 `offline_until[j] <= t` 的用户 +1；`id<number>` 形式按空格切分，逐个解析出 id 后无条件 +1（离线用户也算）。
4. 关键判断是 `<=` 而不是 `<`：示例 1 中 id0 在 t=11 离线，`offline_until[0] = 71`，t=71 的 HERE 事件里 `71 <= 71` 成立，id0 已重新上线，所以输出 `[2,2]`。

```python
mentions = [0] * numberOfUsers
offline_until = [0] * numberOfUsers
for typ, ts, arg in events:
    t = int(ts)
    if typ == "OFFLINE":
        offline_until[int(arg)] = t + 60
    elif arg == "ALL":
        for j in range(numberOfUsers):
            mentions[j] += 1
    elif arg == "HERE":
        for j in range(numberOfUsers):
            if offline_until[j] <= t:
                mentions[j] += 1
    else:
        for tok in arg.split():
            mentions[int(tok[2:])] += 1
```

## 复杂度
时间：O(n·numberOfUsers)，每个 ALL/HERE 扫一遍全体用户，id 形式只按提及数计。
空间：O(numberOfUsers)，只开了 mentions 和 offline_until 两个数组。

## 易错点
- 输入 `["OFFLINE","11","0"], ["MESSAGE","71","HERE"]` → 若把恢复条件写成 `offline_until[j] < t`，t=71 时 id0 被误判为离线，输出 `[1,2]` 而非 `[2,2]` → 必须用 `<= t`，因为 60 单位后恰好在 `t+60` 时刻上线。
- 输入 `["MESSAGE","12","ALL"]` 且 id0 在 t=11 离线 → 若对 ALL 也套在线过滤，id0 少算一次 → ALL 不查 `offline_until`，无条件给全部用户 +1；只有 HERE 才过滤。

## 如果面试官追问
问：若 events 不按时间排序怎么办？答：先按 `int(events[i][1])` 稳定排序再扫描，同一时刻 OFFLINE 排在 MESSAGE 前即可。
