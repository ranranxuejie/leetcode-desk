## 一句话思路
用前缀异或把 a==b 化成 `pre[i]==pre[k+1]`，再枚举 i<k 统计中间 j 的个数。

## 怎么做
1. 定义 `pre[0]=0`，`pre[t]=arr[0]^...^arr[t-1]`，长度 n+1。
2. 由 a==b 推出 `pre[i]^pre[j] == pre[j]^pre[k+1]`，两边消去 `pre[j]` 得 `pre[i]==pre[k+1]`。
3. 所以固定 i、k 后，j 可取 i+1..k 共 k-i 个，全部合法，无需再判断。
4. 双重循环枚举 i<k，相等就累加 `k-i`。

以 arr=[2,3,1,6,7] 为例，pre=[0,2,1,0,6,1]。i=0,k=2 时 pre[0]=pre[3]=0，贡献 2-0=2，对应 (0,1,2)、(0,2,2)；i=2,k=4 时 pre[2]=pre[5]=1，贡献 2，对应 (2,3,4)、(2,4,4)，合计 4。

```python
n = len(arr)
pre = [0] * (n + 1)
for t in range(n):
    pre[t + 1] = pre[t] ^ arr[t]
ans = 0
for i in range(n):
    for k in range(i + 1, n):
        if pre[i] == pre[k + 1]:
            ans += k - i
return ans
```

## 复杂度
时间：O(n²)，双重循环枚举 i、k，n≤300 足够。
空间：O(n)，额外开 pre 数组 n+1 个元素。

## 易错点
- 把 k 的上界写成 n-1 却用 `pre[k]` 比较：k 最大取 n-1，此时要取 `pre[k+1]=pre[n]`，写成 `pre[k]` 会漏掉所有以末元素结尾的三元组，示例 1 会从 4 错成 2。
- 误以为 j 还要额外判断：a==b 已等价于 `pre[i]==pre[k+1]`，与 j 无关；若在循环里再算一遍 a、b 的异或，示例 2 的 10 仍对但复杂度退化成 O(n³)，n=300 时约 2.7e7 次异或，容易超时。

## 如果面试官追问
若 n 放大到 1e5 怎么办？答：按 `pre` 值分组，组内对下标做「前面有几个更小的 i」的累加，用哈希表存 (计数, 下标和)，O(n)。
