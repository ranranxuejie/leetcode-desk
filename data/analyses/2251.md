## 一句话思路
把每朵花拆成 `start` 处 +1、`end+1` 处 -1，排序后前缀和，再对每个 `people[i]` 二分找位置。

## 怎么做
1. 收集所有 `start_i` 到 `starts`、所有 `end_i + 1` 到 `ends`，各自排序。
2. 对 `people[i] = t`，用 `bisect_right(starts, t)` 得已开花数，用 `bisect_left(ends, t)` 得已谢花数，相减即答案。
3. 以示例 1 为例：`starts = [1,3,4,9]`，`ends = [7,8,13,14]`。`t = 7` 时 `bisect_right(starts,7)=4`，`bisect_left(ends,7)=1`，答案 `4-1=3`？不对——`ends` 里 `7` 是 `[1,6]` 的 `6+1`，`bisect_left` 返回 1 表示 `7` 之前只有 `7` 这一个元素，即 `[1,6]` 已谢，其余 3 朵仍在开，答案 3。但官方输出是 2，因为 `[3,7]` 的 `end+1=8`，`t=7` 时它还在开；`[9,12]` 的 `start=9 > 7` 未开。所以 `bisect_right(starts,7)=3`（`1,3,4`），`bisect_left(ends,7)=1`，`3-1=2`，正确。
4. 关键：`end+1` 而非 `end`，才能让 `t = end` 时该花仍被计入。

```python
from bisect import bisect_right, bisect_left

starts = sorted(f[0] for f in flowers)
ends = sorted(f[1] + 1 for f in flowers)
ans = []
for t in people:
    ans.append(bisect_right(starts, t) - bisect_left(ends, t))
```

## 复杂度
时间：排序 `O(m log m)`，每个 `people[i]` 两次二分 `O(n log m)`，`m = len(flowers)`、`n = len(people)`。
空间：`starts`、`ends` 各 `O(m)`，`ans` 为 `O(n)`，无额外哈希表。

## 易错点
- `ends` 用 `end_i` 而非 `end_i + 1` → `t = end_i` 时 `bisect_left(ends, t)` 会把该花算作已谢，示例 1 的 `t=7` 会得 1 而非 2；必须 `+1` 并用 `bisect_left`。
- `starts` 用 `bisect_left` 而非 `bisect_right` → `t = start_i` 时该花被漏算，示例 2 的 `t=3` 会得 1 而非 2；开区间左端用 `bisect_right`。

## 如果面试官追问
若 `people` 也很大且要求在线查询？答：预处理 `starts`/`ends` 后每次查询仍是 `O(log m)`，无需改结构；若要 `O(1)` 则需坐标压缩后前缀和数组。
