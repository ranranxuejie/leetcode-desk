## 一句话思路
对 tasks 做前缀和，每个班次用二分定位「累计工作量」落在哪个任务里，一次 O(log n) 算出剩余任务数。

## 怎么做
1. 令 `pre[i] = tasks[0]+...+tasks[i-1]`，`pre[0]=0`，长度 `n+1`，`pre[n]` 是总工作量。
2. 维护 `done`：已经彻底完成的工作量（跨班次累加，但每班次结束若 `done >= pre[n]` 就归零，因为下一班次从任务 0 重来）。
3. 每班次先算 `done += shifts[j]`，若 `done >= pre[n]`，答案 0 且 `done = 0`；否则用 `bisect_right(pre, done) - 1` 得到当前正在做的任务下标 `k`，未完成数 = `n - k`。
4. 关键点：`done` 落在任务内部时，`bisect_right` 返回的是「第一个 > done 的前缀下标」，减 1 正好是正在做的那个任务，它算未完成。

以示例 3 `tasks=[4,2], shifts=[3,6,1]` 为例：`pre=[0,4,6]`。班次 0：`done=3`，`3 < 6`，`bisect_right([0,4,6],3)=1`，`k=0`，答案 `2-0=2`。班次 1：`done=3+6=9 >= 6`，答案 0，`done` 归零。班次 2：`done=1`，`k=0`，答案 2。输出 `[2,0,2]`。

```python
from bisect import bisect_right

pre = [0] * (n + 1)
for i, t in enumerate(tasks):
    pre[i + 1] = pre[i] + t

ans, done = [], 0
for s in shifts:
    done += s
    if done >= pre[n]:
        ans.append(0)
        done = 0
    else:
        k = bisect_right(pre, done) - 1
        ans.append(n - k)
```

## 复杂度
时间 O((n + m) log n)：建前缀和 O(n)，每个班次二分 O(log n)，m 为 shifts 长度。
空间 O(n)：只多开了一个长度 n+1 的 `pre` 数组。

## 易错点
- `done` 恰好等于某个 `pre[k]`（任务刚好做完）时，若用 `bisect_left` 会得到 `k-1`，把已完成的任务算成未完成。示例 1 班次 1：`done=1=pre[1]`，必须用 `bisect_right` 得 `k=1`，答案 `3-1=2`。
- 班次内完成全部任务后忘记把 `done` 归零：示例 2 班次 0 `done=20 >= 9`，若不归零，班次 1 的 `done=24` 仍 ≥ 9，会错答 0 而非 2。剩余时间必须丢弃。

## 如果面试官追问
若 shifts 长度升到 10^9 但值域很小，怎么优化？答：把 shifts 按值排序后对相同值缓存二分结果，或直接对 `done` 做前缀和再整体二分。
