## 一句话思路
对每个 targetIndices 下标，用前后缀匹配判断删除它后 pattern 是否仍是子序列，能删就删。

## 怎么做
1. 预处理 `pre[i]`：source 前 i 个字符最多匹配 pattern 的前 `pre[i]` 个字符。
2. 预处理 `suf[i]`：source 从 i 开始的后缀最多匹配 pattern 从 `suf[i]` 开始的后缀。
3. 对 targetIndices 中每个 idx，检查 `pre[idx] + suf[idx+1] >= len(pattern)`，成立则删除。
4. 删除后更新 pre/suf 数组（或重新计算受影响部分）。

以示例 1 `source="abbaa", pattern="aba", targetIndices=[0,1,2]` 为例：
- `pre = [0,1,1,2,2,3]`，`suf = [3,2,2,1,1,0]`
- idx=0: `pre[0]+suf[1]=0+2=2 < 3`，不能删
- idx=1: `pre[1]+suf[2]=1+2=3 >= 3`，可删，答案+1

```python
n, m = len(source), len(pattern)
pre = [0] * (n + 1)
for i in range(n):
    pre[i+1] = pre[i] + (pre[i] < m and source[i] == pattern[pre[i]])
suf = [0] * (n + 1)
for i in range(n - 1, -1, -1):
    suf[i] = suf[i+1] + (suf[i+1] < m and source[i] == pattern[m-1-suf[i+1]])
ans = 0
for idx in targetIndices:
    if pre[idx] + suf[idx+1] >= m:
        ans += 1
```

## 复杂度
时间：O(n + |targetIndices|)，n 为 source 长度，预处理前后缀各扫一遍。
空间：O(n)，开了 pre 和 suf 两个长度 n+1 的数组。

## 易错点
- 删除后 source 下标不变但字符消失，后续判断必须基于「已删除集合」而非原始 source。示例 1 中删了 idx=1 后，idx=2 的判断要用更新后的 pre/suf，不能直接用原始数组。
- `pre[idx] + suf[idx+1] >= m` 用的是严格大于等于，不是大于。示例 2 `source="bcda", pattern="d"`，idx=0 时 `pre[0]+suf[1]=0+1=1 >= 1` 成立可删，写成 `> m` 会漏掉。

## 如果面试官追问
问：如果 targetIndices 不是升序怎么办？
答：先排序再按同样逻辑处理，因为删除顺序不影响最终可删集合。
