## 一句话思路
把位置拆成行列 `(r, c)` 做四方向加减，最后用 `r * n + c` 还原成一维下标。

## 怎么做
1. 由 `pos = 0` 反解出 `r, c = 0, 0`，因为 `grid[0][0] = 0`。
2. 遍历 `commands`，按方向只改一个坐标：`"UP"` 减 `r`，`"DOWN"` 加 `r`，`"LEFT"` 减 `c`，`"RIGHT"` 加 `c`。
3. 遍历结束后返回 `r * n + c`。

以示例 2 为例，`n = 3, commands = ["DOWN","RIGHT","UP"]`：起点 `(0,0)`；`"DOWN"` 后 `(1,0)`；`"RIGHT"` 后 `(1,1)`；`"UP"` 后 `(0,1)`，返回 `0 * 3 + 1 = 1`，与输出一致。关键中间值是 `"RIGHT"` 那步把 `c` 从 0 变成 1，而不是把 `pos` 从 3 变成 4——两者在这一步恰好都成立，但 `"UP"` 之后 `pos` 会算成 `4 - 3 = 1` 才对，直接对 `pos` 加减 `n` 在换行处容易错位。

```python
r = c = 0
for cmd in commands:
    if cmd == "UP":
        r -= 1
    elif cmd == "DOWN":
        r += 1
    elif cmd == "LEFT":
        c -= 1
    else:  # "RIGHT"
        c += 1
return r * n + c
```

注意 `"UP"` 是 `r -= 1` 而不是 `r += 1`：行号向下增大，`grid[i][j] = i * n + j` 里 `i` 是行。

## 复杂度
时间：O(len(commands))，每条命令常数次比较与加减，与 `n` 无关。
空间：O(1)，只开了 `r`、`c` 两个整数。

## 易错点
- 把 `"UP"` 写成 `r += 1`：示例 2 中 `"UP"` 后 `r` 会变成 2，返回 `2 * 3 + 1 = 7` 而非 1。正确做法是记住行号向下增大，`"UP"` 对应 `r -= 1`。
- 直接对一维 `pos` 加减：`"RIGHT"` 加 1、`"LEFT"` 减 1 没问题，但 `"UP"` 减 `n`、`"DOWN"` 加 `n` 在跨行时依赖当前位置的列，示例 2 里 `pos` 从 3 加 1 到 4 再减 3 到 1 恰好对，但若命令是 `["RIGHT","UP"]` 从 `(0,0)` 出发，`pos` 会算成 `1 - 3 = -2`，而正确是 `(0,1)` 即 1。正确做法是始终维护 `(r, c)` 两个坐标。

## 如果面试官追问
若 `n` 扩大到 10^5 且 `commands` 长达 10^6，还这么写吗？答：仍然 O(len(commands)) 一遍扫描，只是 `r * n + c` 要用 Python 大整数，无需改结构。
