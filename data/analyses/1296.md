## 一句话思路
用哈希表统计频次，从小到大枚举每个数作为集合起点，贪心消耗 k 个连续数，任一数不够即失败。

## 怎么做
1. 若 `len(nums) % k != 0` 直接返回 `False`，否则用 `Counter(nums)` 建频次表。
2. 对 `sorted(cnt)` 从小到大遍历，遇到频次为 0 的键跳过。
3. 以当前数 `x` 为起点，检查 `x, x+1, ..., x+k-1` 是否都在表中且频次 ≥ `cnt[x]`，不足则返回 `False`。
4. 全部通过则返回 `True`。

以示例 1 为例：`nums = [1,2,3,3,4,4,5,6]`，`k = 4`，频次为 `{1:1,2:1,3:2,4:2,5:1,6:1}`。从 `x=1` 起，`cnt[1]=1`，检查 `1..4` 频次均 ≥1，各减 1 后 `3`、`4` 剩 1；接着 `x=3`，`cnt[3]=1`，检查 `3..6` 均 ≥1，减完全为 0，返回 `True`。

```python
from collections import Counter

def isPossibleDivide(nums, k):
    if len(nums) % k:
        return False
    cnt = Counter(nums)
    for x in sorted(cnt):
        c = cnt[x]
        if c == 0:
            continue
        for y in range(x, x + k):
            if cnt[y] < c:
                return False
            cnt[y] -= c
    return True
```

关键在 `c = cnt[x]`：它表示必须同时开 `c` 个以 `x` 开头的集合，所以后续每个数都要一次扣掉 `c`，而不是扣 1。

## 复杂度
时间 O(n log n)：排序 `sorted(cnt)` 贡献 log n，内层 k 次扣减总计 O(n)。
空间 O(n)：`Counter` 存至多 n 个不同键。

## 易错点
- 输入 `nums = [1,2,3,4]`、`k = 3`：只判频次会误判为可划分，实际 `4 % 3 != 0`，必须先做 `len(nums) % k` 检查。
- 输入 `nums = [1,2,3,3,4,5]`、`k = 3`：若内层只扣 1 而非扣 `cnt[x]`，`3` 的频次 2 会被拆错，导致 `[1,2,3]` 和 `[3,4,5]` 判成失败；正确做法是每个 `y` 都减 `c`。

## 如果面试官追问
问：要求输出具体划分方案怎么办？
答：在扣减循环里把 `[x, x+1, ..., x+k-1]` 追加到结果列表，重复 `c` 次即可，复杂度不变。
