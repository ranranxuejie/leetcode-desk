## 一句话思路
按 efficiency 降序枚举「团队最低效率」，用最小堆维护已扫过工程师中最大的 k 个 speed 之和。

## 怎么做
1. 把 `(efficiency[i], speed[i])` 打包成对，按 efficiency 降序排序。
2. 顺序扫描，每扫到一个工程师就把它当作当前团队的最低效率，此时团队只能从前缀里选。
3. 用最小堆维护前缀中最大的至多 k 个 speed，堆和 `sum_speed` 同步增减。
4. 每步用 `sum_speed * 当前 efficiency` 更新答案，堆满 k 时弹出最小 speed。

以示例 2（k=3）为例：排序后 efficiency 降序为 9,7,5,4,3,2，对应 speed 1,5,2,10,3,8。扫到 efficiency=4（speed=10）时，堆里是 {1,5,2}，`sum_speed=8`，但堆未满 3 个？实际此时堆已有 3 个，先算 `8*4=32`，再 push 10 得 `sum_speed=18`，弹出最小 1 得 17，`17*4=68`——这正是答案。

```python
pairs = sorted(zip(efficiency, speed), reverse=True)
heap, total, ans = [], 0, 0
for e, s in pairs:
    heapq.heappush(heap, s)
    total += s
    if len(heap) > k:
        total -= heapq.heappop(heap)
    ans = max(ans, total * e)
return ans % (10**9 + 7)
```

注意：先 push 再判断是否超 k，这样 `total` 始终是当前前缀中最大的至多 k 个 speed 之和。

## 复杂度
时间：排序 O(n log n)，每个元素进出堆各一次 O(n log k)，合计 O(n log n)。
空间：堆最多 k 个元素，加上排序后的 pairs 列表 O(n)。

## 易错点
- 堆未满 k 个时不能提前算答案吗？可以算，但要注意此时 `total` 是前缀全部 speed 之和，乘当前 efficiency 是合法的（团队人数 ≤ k）。若写成「堆满 k 才开始算」，会漏掉 n < k 或前缀不足 k 的情况，示例 1 中 k=2 扫到第一个元素时堆只有 1 个，漏算会少一个候选。
- 取余时机：`ans` 在循环中不能提前取模，因为后续 `total * e` 可能比当前 `ans` 大，提前取模会让比较失真。正确做法是全程用 Python 大整数比较，最后 `return ans % (10**9+7)`。若在循环里写 `ans = max(ans, total*e) % MOD`，示例 3 的 72 可能被错误截断。

## 如果面试官追问
要求输出具体选了哪些工程师怎么办？答：堆里存 `(speed, index)`，最后把堆中剩余元素的 index 收集起来即为团队，注意排序后需保留原始下标映射。
