## 一句话思路
先用哈希表统计频率，再用大小为 k 的小顶堆按频率筛出前 k 个元素，避免全排序。

## 怎么做
1. 用 `Counter(nums)` 统计每个元素的出现次数，得到 `freq`。
2. 遍历 `freq.items()`，用小顶堆维护当前频率最高的 k 个元素，堆顶是这 k 个里频率最低的。
3. 新元素频率大于堆顶频率时弹出堆顶、压入新元素；否则跳过。
4. 最后把堆中元素取出即为答案（顺序任意）。

以 `nums = [1,1,1,2,2,3], k = 2` 为例：`freq = {1:3, 2:2, 3:1}`。遍历到 `(1,3)` 入堆 `[(3,1)]`；`(2,2)` 入堆 `[(2,2),(3,1)]`；`(3,1)` 频率 1 不大于堆顶 2，跳过。最终堆里是 `1` 和 `2`。

```python
from collections import Counter
import heapq

freq = Counter(nums)
heap = []
for num, cnt in freq.items():
    if len(heap) < k:
        heapq.heappush(heap, (cnt, num))
    elif cnt > heap[0][0]:
        heapq.heapreplace(heap, (cnt, num))
return [num for cnt, num in heap]
```

关键点：堆里存 `(cnt, num)` 元组，Python 会先比 `cnt` 再比 `num`，不会因元素值相同报错；`heapreplace` 一步完成弹出加压入，比先 `heappop` 再 `heappush` 少一次调整。

## 复杂度
时间 O(n + m log k)，n 是数组长度用于计数，m 是不同元素个数，每次堆操作 log k。
空间 O(m + k)，`freq` 存 m 个键值对，堆最多 k 个元素。

## 易错点
- 输入 `nums = [1,1,1,2,2,3], k = 2` 时若用大顶堆存全部 m 个元素再取前 k，复杂度退化成 O(m log m)，不满足进阶要求；正确做法是堆容量固定为 k，只在 `cnt > heap[0][0]` 时替换。
- 输入 `nums = [1,2], k = 2`（所有元素频率都是 1）时，若堆里只存频率 `cnt` 不存 `num`，两个频率相同的元素无法区分，取出的值会错；正确做法是存 `(cnt, num)` 元组，靠第二维区分。

## 如果面试官追问
追问：要求 O(n) 时间怎么办？
答：用桶排序，桶下标是频率（最大为 n），从高到低扫桶收集 k 个元素，时间 O(n)。
