## 一句话思路
在升序数组上二分答案 h：对下标 mid，若 `citations[mid] >= n - mid` 则 h 至少是 `n - mid`，向右收缩找更大值。

## 怎么做
1. 令 `n = len(citations)`，`lo, hi = 0, n`，在 `[0, n]` 上二分 h 的可能取值。
2. 取 `mid = (lo + hi) // 2`，此时「引用数 ≥ citations[mid] 的论文数」恰为 `n - mid`。
3. 若 `citations[mid] >= n - mid`，说明 h 可以取到 `n - mid`，令 `lo = mid + 1` 继续往右找；否则 `hi = mid`。
4. 循环结束时 `lo` 就是最大可行 h（等价于 `n - hi`）。

以 `citations = [0,1,3,5,6]`，`n = 5` 为例：`mid = 2` 时 `citations[2] = 3`，`n - mid = 3`，`3 >= 3` 成立，`lo` 抬到 3；再 `mid = 4`，`citations[4] = 6 >= 1` 成立，`lo = 5`；最后 `hi = 5`，返回 `n - hi = 0`？不对——这里要盯住边界：`hi` 停在 5 时答案应是 `n - lo` 的对称写法，正确返回是 `n - hi` 需 `hi` 为第一个不满足的下标。用 `[0,1,3,5,6]` 走完，`lo = 5, hi = 5`，答案 `n - lo = 0` 显然错，说明模板要改成返回 `lo` 的另一种形式：让 `lo` 表示「已知可行的最大 h」，初值 0，命中时 `ans = n - mid; lo = mid + 1`，最后返回 `ans`。

```python
n = len(citations)
lo, hi, ans = 0, n - 1, 0
while lo <= hi:
    mid = (lo + hi) // 2
    if citations[mid] >= n - mid:
        ans = n - mid
        lo = mid + 1
    else:
        hi = mid - 1
return ans
```

## 复杂度
时间 O(log n)：二分每次砍半，n 是数组长度。
空间 O(1)：只开了 `lo/hi/mid/ans` 四个整数。

## 易错点
- `citations = [0]` → 若把 `hi` 初始化成 `n` 并返回 `n - lo`，会得到 1，实际 h 应为 0；正确做法是 `hi = n - 1` 且用 `ans` 记录命中值，未命中时保持 0。
- `citations = [100,100,100]` → 若判断写成 `citations[mid] > n - mid`（漏等号），`mid = 0` 时 `100 > 3` 仍成立但边界语义偏移，`[1,2,100]` 上会漏掉 h=2；必须用 `>=`，因为「至少被引用 h 次」含等号。

## 如果面试官追问
问：若数组未排序怎么办？
答：先排序 O(n log n) 再套同一二分，或直接计数排序后从后往前扫，O(n)。
