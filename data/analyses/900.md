## 一句话思路
用指针 `i` 指向当前编码对 `(encoding[i], encoding[i+1])`，`next(n)` 时不断从当前剩余次数里扣 `n`，扣到不够就跳过这一对。

## 怎么做
1. 初始化 `self.i = 0`，`self.enc = encoded`，指针始终停在偶数下标上。
2. `next(n)` 循环：若 `i >= len(enc)` 返回 `-1`；若 `enc[i] < n`，则 `n -= enc[i]`、`i += 2` 继续。
3. 否则 `enc[i] -= n`，返回 `enc[i+1]`（这一对还有剩余，指针不动）。
4. 关键中间值：以 `[3,8,0,9,2,5]` 为例，第一次 `next(2)` 时 `enc[0]=3 >= 2`，扣成 `enc[0]=1`，返回 `enc[1]=8`；第二次 `next(1)` 时 `enc[0]=1 >= 1`，扣成 `0`，仍返回 `8`；第三次 `next(1)` 时 `enc[0]=0 < 1`，`n` 变 `0`、`i` 跳到 `2`，`enc[2]=0 < 0` 不成立，于是 `enc[2] -= 0` 后返回 `enc[3]=9`——注意这里 `0` 次的那一对必须被跳过，不能返回 `9`。

```python
def next(self, n):
    while self.i < len(self.enc):
        if self.enc[self.i] < n:
            n -= self.enc[self.i]
            self.i += 2
        else:
            self.enc[self.i] -= n
            return self.enc[self.i + 1]
    return -1
```

注意 `enc[i] == n` 时走 `else` 分支，扣成 `0` 并返回该值，下一次调用才会跳过它——这正好对应「最后一个耗尽的元素」的语义。

## 复杂度
时间：每次 `next` 均摊 O(1)，指针 `i` 只增不减，总跳过次数不超过 `len(encoding)/2`。
空间：O(1)，原地修改 `encoding`，没有额外数组。

## 易错点
- 输入 `[3,8,0,9,2,5]` 且 `next(1)` 连续调用：若把 `enc[i] == 0` 当成「还有 0 个可耗尽」直接返回 `enc[i+1]=9`，会错成 `9`；正确做法是 `0 < n` 成立，先 `n -= 0`、`i += 2` 跳过这一对。
- 输入 `[1,5]` 且 `next(2)`：若在 `enc[0]=1 < 2` 时先扣减再判断剩余，容易把 `n` 扣成 `1` 后误返回 `5`；正确做法是扣完 `n=1`、`i=2` 越界，返回 `-1`，因为第二个元素不存在。

## 如果面试官追问
问：如果 `next` 调用次数涨到 10^5 而 `encoding` 长度不变，会退化吗？
答：不会，指针单调前进，总代价仍是 O(len(encoding)/2 + 调用次数)。
