## 一句话思路
以 Signups 为左表 LEFT JOIN Confirmations，用 `AVG(action = 'confirmed')` 一次算出比率，天然处理零请求用户。

## 怎么做
1. 从 `Signups` 出发 LEFT JOIN `Confirmations`，保证 user_id=6 这种没有确认记录的用户不被丢掉。
2. 在连接结果上按 `user_id` 分组，用 `AVG(action = 'confirmed')` 求比率：`action='confirmed'` 得 1，`'timeout'` 得 0，平均即比率。
3. 用 `ROUND(..., 2)` 保留两位小数，`IFNULL` 兜底 NULL。

以官方示例中 user_id=2 为例：连接后两行 action 分别是 `'confirmed'` 和 `'timeout'`，`action='confirmed'` 得到 `[1, 0]`，`AVG` = 0.5，`ROUND` 后为 0.50。user_id=6 连接后 action 为 NULL，`NULL = 'confirmed'` 得 NULL，`AVG` 忽略 NULL 返回 NULL，`IFNULL` 转成 0。

```python
# 关键 SQL 片段
SELECT s.user_id,
       IFNULL(ROUND(AVG(c.action = 'confirmed'), 2), 0) AS confirmation_rate
FROM Signups s
LEFT JOIN Confirmations c ON s.user_id = c.user_id
GROUP BY s.user_id;
```

若用 pandas 实现，等价写法是先把 `action` 映射成 0/1，再 `groupby('user_id').mean()`，最后 `round(2)` 并用 `fillna(0)` 补零。

## 复杂度
时间：O(n + m)，n 为 Signups 行数、m 为 Confirmations 行数，JOIN 与分组各扫一遍。
空间：O(k)，k 为去重后的 user_id 数，用于分组聚合的哈希表。

## 易错点
- 用 INNER JOIN 代替 LEFT JOIN：user_id=6 在 Confirmations 中无记录，会被直接丢掉，输出少一行；正确做法是以 Signups 为左表 LEFT JOIN。
- 用 `SUM(action='confirmed')/COUNT(*)` 而非 `AVG`：对 user_id=6，COUNT(*) 为 0 会触发除零或返回 NULL，且 COUNT(*) 把 NULL 行也计入；正确做法是用 `AVG` 或 `COUNT(c.action)` 作分母。

## 如果面试官追问
问：如果 Confirmations 里有 Signups 中不存在的 user_id 怎么办？答：以 Signups 为左表 JOIN 会自动过滤掉这些孤儿记录，无需额外 WHERE。
