## 一句话思路
用 `locked` 数组存每个节点的锁主，`children` 邻接表存树；upgrade 时沿 parent 链查祖先、DFS 查子孙，规模小直接暴力。

## 怎么做
1. 初始化：`locked = [0]*n`（0 表示未锁），由 `parent` 建 `children` 邻接表。
2. `lock(num, user)`：`locked[num] == 0` 时置为 `user` 返回 `True`，否则 `False`。
3. `unlock(num, user)`：`locked[num] == user` 时清 0 返回 `True`，否则 `False`。
4. `upgrade(num, user)`：先沿 `parent` 链上溯，任一祖先 `locked != 0` 即失败；再 DFS 子树收集被锁子孙，一个都没有即失败；否则把这些子孙清 0、`locked[num] = user`。

以官方示例 `parent = [-1,0,0,1,1,2,2]` 为例，执行到 `upgrade(0, 1)`：`locked` 此时为 `[0,0,0,0,5,0,0]`（节点 4 被用户 5 锁）。上溯 0 无父节点，祖先检查通过；DFS 从 0 出发遍历到 4，`locked[4]=5 != 0`，收集到 `[4]`，非空；于是 `locked[4]=0`、`locked[0]=1`，返回 `True`。

```python
def upgrade(self, num, user):
    p = self.parent[num]
    while p != -1:
        if self.locked[p]: return False
        p = self.parent[p]
    found, st = [], [num]
    while st:
        x = st.pop()
        for c in self.children[x]:
            if self.locked[c]: found.append(c)
            st.append(c)
    if not found: return False
    for c in found: self.locked[c] = 0
    self.locked[num] = user
    return True
```

## 复杂度
时间：lock/unlock 为 O(1)；upgrade 为 O(n)，上溯祖先 O(树高) + DFS 子树 O(子树大小)，最坏 O(n)。
空间：`locked` 与 `children` 各 O(n)，DFS 栈最坏 O(n)。

## 易错点
- `upgrade` 只查了祖先没查自己：若 `num` 本身已被锁（如示例最后 `upgrade(0,1)` 前若 0 已被锁），会错误地覆盖锁主。正确做法是进入 upgrade 先判 `locked[num] != 0` 直接返回 `False`。
- 子孙检查用「至少一个」而非「全部」：若把条件写成「所有子孙都被锁」或「子树里没有未锁节点」，示例中节点 0 的子树含未锁的 1、2、3、5、6，会误判失败。正确做法是 DFS 中只收集 `locked[c] != 0` 的节点，判断 `found` 非空即可。

## 如果面试官追问
若 n 和调用次数都放大到 10^5，怎么做？答：维护每个节点子树内被锁节点计数，upgrade 时用计数判非空、用「最近被锁祖先」标记判祖先，把 O(n) 降到 O(树高)。
