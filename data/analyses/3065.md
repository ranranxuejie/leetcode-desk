## 一句话思路
统计 `nums` 中小于 `k` 的元素个数即可，因为每次删除最小值恰好能消掉一个不达标元素。

## 怎么做
1. 遍历 `nums`，对每个元素判断是否 `< k`。
2. 计数变量 `cnt` 每命中一次加一。
3. 返回 `cnt`。

以示例 1 的 `nums = [2,11,10,1,3], k = 10` 为例：扫描到 `2` 时 `2 < 10` 成立，`cnt` 从 0 变 1；接着 `11`、`10` 不计数；`1` 使 `cnt` 变 2；`3` 使 `cnt` 变 3，最终返回 3。

关键中间值：`cnt` 的终值 3 正好等于示例输出，说明「小于 k 的个数」就是答案，无需真的模拟删除。

```python
cnt = 0
for x in nums:
    if x < k:
        cnt += 1
return cnt
```

等价写法一行：`return sum(x < k for x in nums)`，`x < k` 是 `bool`，`sum` 会把 `True` 当 1 累加。

为什么不用排序或模拟？因为题目保证至少有一个 `nums[i] >= k`，删除过程不会把数组删空；而每次操作只能删当前最小值，最小值若 `< k` 就必然要被删，若 `>= k` 则所有元素都达标、应立即停止。所以操作次数与「有多少个元素 `< k`」严格相等，顺序无关。

## 复杂度
时间：O(n)，n 为 `nums` 长度，一次遍历。
空间：O(1)，只开 `cnt` 一个计数器。

## 易错点
1. 把条件写成 `x <= k` → 对 `nums = [1,1,2,4,9], k = 9` 会把 `9` 也计入，返回 5 而非 4；正确做法是严格用 `x < k`，因为题目要求「大于或等于 k」。
2. 误以为要排序后从头部删、或模拟 `pop(0)` → 对 `nums = [2,11,10,1,3], k = 10` 会写出 O(n²) 的删除循环，且容易在「删到只剩达标元素」的终止条件上写错；正确做法是直接计数，不改变数组。

## 如果面试官追问
问：若允许一次操作删除任意一个元素，答案变吗？
答：不变，仍是小于 `k` 的元素个数，因为达标元素一个都不能删。
