## 一句话思路
把 `ranges` 按起点排序后依次合并，看合并出的连续段能否完整盖住 `[left, right]`。

## 怎么做
1. 按 `start` 升序排序 `ranges`，保证区间从左往右扫。
2. 维护当前合并段的右端点 `cur`，初始为 `left - 1`，表示「已确认覆盖到哪」。
3. 遍历每个 `[s, e]`：若 `s > cur + 1` 说明中间断了，直接返回 `False`；否则 `cur = max(cur, e)`。
4. 遍历中一旦 `cur >= right` 就返回 `True`，循环结束仍未达到则返回 `False`。

用示例 1：`ranges = [[1,2],[3,4],[5,6]]`，`left = 2`，`right = 5`。排序后不变，`cur` 初始为 1。处理 `[1,2]`：`s=1 <= cur+1=2`，`cur = max(1,2) = 2`；处理 `[3,4]`：`s=3 <= 3`，`cur = 4`；处理 `[5,6]`：`s=5 <= 5`，`cur = 6 >= 5`，返回 `True`。关键中间值是 `cur` 从 1 一路推到 6，中间没有出现 `s > cur + 1`。

```python
ranges.sort(key=lambda x: x[0])
cur = left - 1
for s, e in ranges:
    if s > cur + 1:
        return False
    cur = max(cur, e)
    if cur >= right:
        return True
return False
```

注意 `cur` 初值取 `left - 1` 而不是 0：若 `left = 5`，第一个区间 `[1,2]` 的 `s=1 <= cur+1=5` 成立，`cur` 被推到 2，仍小于 `right`，继续扫；这样不会因为「区间在 left 左边」而误判断裂。

## 复杂度
时间：排序 O(m log m)，m 为 `ranges` 长度，扫描 O(m)。
空间：排序额外 O(log m) 栈空间，其余 O(1)。

## 易错点
- 输入 `ranges = [[1,10],[10,20]]`、`left = 21`、`right = 21`：若只判断「有区间包含 left」就返回 `True`，会错成 `True`；实际 `cur` 最大到 20，`20 >= 21` 不成立，正确返回 `False`。
- 输入 `ranges = [[1,2],[4,5]]`、`left = 1`、`right = 5`：若用 `s > cur` 判断裂，`s=4 > cur=2` 成立会提前返回 `False`，但 3 确实没被覆盖，结论碰巧对；换成 `[[1,2],[3,5]]` 时 `s=3 > cur=2` 也成立却应返回 `True`，正确判据是 `s > cur + 1`。

## 如果面试官追问
若 `ranges` 规模到 10^5 且 `left/right` 到 10^9，能否不排序？答：用差分哈希表记录端点增减，按坐标排序后前缀和扫一遍，O(m log m) 不变但省去区间合并的边界判断。
