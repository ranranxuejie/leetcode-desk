## 一句话思路
把数组对半劈开，用双指针判断后半段能否逐个「吃掉」前半段，能配对的最大数量决定答案。

## 怎么做
1. 设 `n = len(nums)`，`half = n // 2`，答案最多是 `n - 2 * half`（即 `n` 为奇数时留 1 个）。
2. 左指针 `i` 从 0 起，右指针 `j` 从 `half` 起，只在 `nums[i] < nums[j]` 时配对成功、`i` 前进；无论成败 `j` 都前进。
3. 配对数 `pairs = i`，返回 `n - 2 * pairs`。

以 `nums = [2,3,4,4,4]` 为例：`n=5`，`half=2`，`j` 从下标 2 开始。`i=0,j=2`：`2<4` 配对，`i=1`；`i=1,j=3`：`3<4` 配对，`i=2`；`i=2,j=4`：`4<4` 失败。最终 `pairs=2`，返回 `5-4=1`，与示例 4 一致。

```python
n = len(nums)
half = n // 2
i, j = 0, half
while i < half and j < n:
    if nums[i] < nums[j]:
        i += 1
    j += 1
return n - 2 * i
```

关键点：为什么 `i` 只从 `[0, half)` 取？因为每次删除消耗两个元素，最多删 `half` 对；把前半段当「被吃的一方」、后半段当「吃的一方」，是让每个 `nums[i]` 都有机会找到严格更大的搭档。由于数组非递减，`j` 单调右移时 `nums[j]` 不减，一旦某个 `i` 配不上，后面的 `j` 只会更大或相等，所以 `j` 不需要回退——这就是双指针成立的原因。

## 复杂度
时间：O(n)，`i` 和 `j` 各单调走一遍，总步数不超过 n。
空间：O(1)，只开了 `i`、`j`、`half` 三个整数。

## 易错点
- 输入 `[1,1,2,2,3,3]` → 若把 `j` 从 0 开始或允许 `i` 与 `j` 交叉，会把相等的 `1` 和 `1` 误判为可删 → 正确做法是 `j` 严格从 `half=3` 起，且条件写 `nums[i] < nums[j]` 而非 `<=`。
- 输入 `[1000000000,1000000000]` → 若用「统计每个值出现次数、取最大频次与其余比较」的贪心，容易得出能删 1 对 → 正确做法是双指针直接判 `nums[0] < nums[1]` 为假，返回 2；本题不能靠频次，必须靠位置顺序。

## 如果面试官追问
问：如果要求输出具体删除了哪些下标对怎么办？
答：在 `nums[i] < nums[j]` 成立时记录 `(i, j)`，配对顺序即删除顺序，删完后重编号不影响后续配对判断。
