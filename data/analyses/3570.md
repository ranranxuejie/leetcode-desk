## 一句话思路
先按 `book_id` 统计 `return_date IS NULL` 的借阅条数，再与 `total_copies` 比较，相等即无可用副本。

## 怎么做
1. 对 `borrowing_records` 过滤 `return_date IS NULL`，按 `book_id` 分组计数，得到每本书的当前借阅数。
2. 用该结果与 `library_books` 按 `book_id` 内连接，只保留计数等于 `total_copies` 的行。
3. 输出 `book_id, title, author, genre, publication_year` 加计数列 `current_borrowers`。
4. 按 `current_borrowers` 降序、`title` 升序排序。

以官方示例的 book_id=1 为例：未归还记录是 record_id 1、2、7，计数为 3，`total_copies=3`，`3 == 3` 成立，入选；book_id=2 未归还记录是 9、10，计数 2，而 `total_copies=3`，`2 != 3`，被排除。

```python
from collections import Counter

active = Counter(r["book_id"] for r in borrowing_records if r["return_date"] is None)
rows = []
for b in library_books:
    c = active.get(b["book_id"], 0)
    if c == b["total_copies"]:
        rows.append((b["book_id"], b["title"], b["author"], b["genre"],
                     b["publication_year"], c))
rows.sort(key=lambda x: (-x[5], x[1]))
```

关键点：`active.get(book_id, 0)` 的默认值 0 让「从未被借」的书也参与比较，book_id=5 计数 0、`total_copies=1`，`0 != 1` 自然排除，无需额外分支。

## 复杂度
时间：O(n + m + k log k)，n 为借阅记录数、m 为书籍数、k 为结果行数，排序贡献 k log k。
空间：O(n) 存 Counter，结果列表 O(k)。

## 易错点
- 把 `return_date` 非 NULL 的记录也算进借阅数 → book_id=2 会得 3（含已归还的 record_id 3），误判为无可用副本；必须先过滤 `return_date IS NULL` 再计数。
- 用 `>=` 而非 `==` 判断 → 若某书借阅数超过 `total_copies`（脏数据或重复记录），会被错误纳入；题目要求「无可用副本」即 `available = total - current = 0`，严格用 `==`。

## 如果面试官追问
问：若借阅数可能超过 `total_copies`，怎么处理？答：仍用 `current >= total_copies` 更稳健，语义是「已无可用副本」，并单独统计超借异常。
