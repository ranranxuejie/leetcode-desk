## 一句话思路
从 `R` 出发沿上下左右四个方向逐格扫描，遇到第一个非 `.` 的格子就停，是 `p` 就计数。

## 怎么做
1. 双重循环找到 `board[i][j] == 'R'` 的位置 `(r, c)`。
2. 对四个方向 `(1,0),(-1,0),(0,1),(0,-1)` 各走一遍，每步 `r += dr, c += dc`。
3. 每步先判越界，再看 `board[r][c]`：是 `.` 就继续走；是 `p` 就 `count += 1` 然后 `break`；是 `B` 就直接 `break`。
4. 四个方向走完返回 `count`。

以示例 2 为例，`R` 在 `(3,3)`。向上走：`(2,3)` 是 `'B'`，立即 `break`，不计数；向下走：`(4,3)` 是 `'B'`，同样 `break`；向左 `(3,2)` 是 `'B'`、向右 `(3,4)` 是 `'B'`，四个方向全被象挡住，`count` 保持 0。关键中间值就是第一次探测到的格子 `board[2][3] == 'B'`，它决定了这个方向贡献 0 而不是继续往后找 `p`。

```python
for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)):
    x, y = r + dr, c + dc
    while 0 <= x < 8 and 0 <= y < 8:
        if board[x][y] == 'p':
            count += 1
            break
        if board[x][y] == 'B':
            break
        x += dr
        y += dc
```

注意 `while` 里 `x += dr` 必须放在两个 `break` 之后，否则遇到 `p` 时坐标已被推进，`break` 前读到的就不是卒的位置。

## 复杂度
时间：O(1)，棋盘固定 8×8，每个方向最多走 7 步，总步数 ≤ 28。
空间：O(1)，只用了 `r, c, count, x, y` 几个标量。

## 易错点
1. 示例 3 中 `R` 在 `(3,3)`，向左 `(3,2)` 是 `.`、`(3,1)` 是 `p`，能吃到；但若把 `B` 的判断写成「跳过继续走」，示例 2 的 `(2,3)='B'` 会被越过，错误地数到更远的 `p`，输出变成非 0。正确做法是遇到 `B` 立即 `break`，象和卒一样终止该方向。
2. 示例 1 中 `R` 在 `(2,3)`，向上 `(1,3)='p'` 计数后必须 `break`，否则继续走到 `(0,3)='.'` 再越界，虽然本例结果不变，但若 `(0,3)` 也是 `p` 就会重复计数。正确做法是吃到 `p` 后立刻 `break`，一个方向最多贡献 1。

## 如果面试官追问
问：如果棋盘不是 8×8 而是 n×n，且要求返回所有能被吃掉的卒的坐标列表？
答：逻辑不变，四个方向扫描时把 `count += 1` 换成 `res.append((x, y))`，复杂度 O(n)，最坏情况车在中心且四向无阻挡。
