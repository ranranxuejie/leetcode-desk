## 一句话思路
对每个质数 p，从 0 到 p-1 枚举 ans[i]，取第一个满足 `a | (a+1) == p` 的值，找不到就是 -1。

## 怎么做
1. 外层遍历 `nums` 的每个质数 `p`。
2. 内层 `a` 从 0 枚举到 `p-1`，因为 `a | (a+1) >= a+1`，所以 `a < p` 是必要条件。
3. 第一个命中的 `a` 就是最小解，直接 `break`；循环走完没命中就填 -1。

拿 `p = 11` 走一遍：`a=0` 得 `0|1=1`，`a=1` 得 `1|2=3`，`a=2` 得 `2|3=3`，`a=3` 得 `3|4=7`，`a=4` 得 `4|5=5`，`a=5` 得 `5|6=7`，`a=6` 得 `6|7=7`，`a=7` 得 `7|8=15`，`a=8` 得 `8|9=9`，`a=9` 得 `9|10=11` 命中，答案 9。注意 `a=7` 时结果 15 已经超过 11，说明中间值不是单调的，不能靠二分，只能顺序扫。

```python
def minBitwiseArray(nums):
    res = []
    for p in nums:
        found = -1
        for a in range(p):
            if (a | (a + 1)) == p:
                found = a
                break
        res.append(found)
    return res
```

`p = 2` 时 `a` 只能取 0 和 1：`0|1=1`、`1|2=3`，都不等于 2，所以填 -1，和示例一致。

## 复杂度
时间：O(n · max(nums))，每个质数最多扫 p 次，n 来自数组长度。
空间：O(1) 额外空间（不计返回的 res 数组）。

## 易错点
- `nums = [2]` → 若把枚举上界写成 `p//2` 或从 1 开始，会漏掉或错判，返回 -1 的判断就不可靠 → 上界必须是 `range(p)`，从 0 开始，2 才能正确落到 -1。
- `nums = [7]` → 若以为 `a | (a+1)` 随 a 单调递增而提前剪枝（比如 a 超过某值就停），会错过 3（`3|4=7`）之后还有 `7|8=15` 这种回跳 → 必须完整扫完 0 到 p-1，命中即 break 才是最小。

## 如果面试官追问
问：nums[i] 放大到 10^9 怎么办？
答：枚举不可行，改看 p 的二进制：p 为 2 时无解，否则把 p 最低位的 0 改成 1、其右边全置 0 再减 1 的思路可 O(log p) 构造。
