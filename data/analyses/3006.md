## 一句话思路
先分别收集 a、b 在 s 中所有匹配的起始下标，再用双指针判断每个 a 匹配点附近 k 内是否存在 b 匹配点。

## 怎么做
1. 用 `str.find` 循环（或切片比较）扫出 `a` 的所有起始下标存进 `posA`，`b` 的存进 `posB`。
2. 因为 `str.find` 从左往右扫，`posA`、`posB` 天然升序，无需再排序。
3. 对 `posA` 中每个 `i`，用指针 `p` 在 `posB` 上滑动，找到第一个 `>= i - k` 的位置，判断它是否 `<= i + k`。
4. 满足就收进答案，指针 `p` 只增不减，整体线性。

以示例 1 为例：`posA = [16, 33]`，`posB = [4, 18]`。处理 `i=16` 时，`p` 停在 `posB[0]=4`，`4 >= 16-15=1` 且 `4 <= 31`，成立；处理 `i=33` 时，`p` 前进到 `posB[1]=18`，`18 >= 18` 且 `18 <= 48`，成立，输出 `[16, 33]`。

```python
posA = [i for i in range(len(s) - len(a) + 1) if s[i:i+len(a)] == a]
posB = [j for j in range(len(s) - len(b) + 1) if s[j:j+len(b)] == b]
ans, p = [], 0
for i in posA:
    while p < len(posB) and posB[p] < i - k:
        p += 1
    if p < len(posB) and posB[p] <= i + k:
        ans.append(i)
return ans
```

## 复杂度
时间：O(n·(|a|+|b|)) 切片比较，双指针部分 O(n)；若用 KMP/滚动哈希则 O(n)。
空间：O(n)，`posA`、`posB` 最坏各存 n 个下标。

## 易错点
- `a` 或 `b` 比 `s` 长时，`range(len(s) - len(a) + 1)` 为负，列表推导直接为空，不会报错；但若手写 `for i in range(...)` 再访问 `s[i:i+len(a)]`，负上界同样安全。真正会错的是把上界写成 `len(s) - len(a)` 漏掉 `+1`，导致最后一个合法起点被丢，如 `s="aa", a="a"` 只得到 `[0]`。
- `posB` 为空时，`while p < len(posB)` 直接跳过，`if p < len(posB)` 为假，答案为空——正确。但若把判断写成 `posB[p] <= i + k` 而不先检查 `p < len(posB)`，会抛 `IndexError`；示例 1 中若 `b="zzz"` 就会触发。

## 如果面试官追问
若 s 长度升到 10^7、a/b 长度也变大，切片比较退化成 O(n·m) 怎么办？答：改用 KMP 或滚动哈希求匹配位置，双指针部分不变。
