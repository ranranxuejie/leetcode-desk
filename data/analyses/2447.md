## 一句话思路
以每个位置结尾维护「所有后缀 GCD 的去重集合」，因为后缀 GCD 随长度增加只会变小且种类数 O(log max) 级。

## 怎么做
1. 遍历 `nums`，维护 `cur` 为「以 `i` 结尾的所有后缀 GCD 值 → 出现次数」的字典。
2. 新 `cur = {nums[i]: 1}`，再把上一轮每个 `g` 更新为 `gcd(g, nums[i])` 并累加计数。
3. 每轮统计 `cur.get(k, 0)` 累加到答案。

以 `nums = [9,3,1,2,6,3], k = 3` 为例：`i=0` 时 `cur={9:1}`；`i=1` 时 `cur={3:2}`（`gcd(9,3)=3` 与 `3` 合并），答案 +2；`i=2` 时 `cur={1:3}`，答案不变；`i=3` 时 `cur={1:4}`；`i=4` 时 `cur={1:4, 2:1}`；`i=5` 时 `cur={1:4, 3:2}`，答案 +2，共 4。

```python
from math import gcd
from collections import defaultdict

ans = 0
cur = {}
for x in nums:
    nxt = defaultdict(int)
    nxt[x] += 1
    for g, c in cur.items():
        nxt[gcd(g, x)] += c
    cur = nxt
    ans += cur.get(k, 0)
```

关键点：`nxt[gcd(g, x)] += c` 是把「上一轮同 GCD 值的多个后缀」合并计数，不能只存集合，否则会漏掉计数。

## 复杂度
时间 O(n · log max(nums))：每个位置的后缀 GCD 种类数不超过 O(log max)。
空间 O(log max)：`cur` 字典最多存 O(log max) 个键。

## 易错点
- 输入 `nums = [4], k = 7` → 若直接判断 `nums[i] % k == 0` 就计数，会错成 1 → 正确做法是必须走 GCD 合并，`gcd(4,4)=4 ≠ 7`，答案 0。
- 输入 `nums = [9,3,1,2,6,3], k = 3` → 若用 `set` 存后缀 GCD 而不带计数，`i=1` 时 `{3}` 只算 1 次，漏掉 `[9,3]` 和 `[3]` 两个 → 必须用 `dict` 累加出现次数。

## 如果面试官追问
若 `n` 放大到 10^5 且 `nums[i]` 到 10^9，这方法还成立吗？答：成立，后缀 GCD 种类数仍是 O(log max)，总时间 O(n log max)，无需改结构。
