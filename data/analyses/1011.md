## 一句话思路
答案在 `[max(weights), sum(weights)]` 上单调，二分这个载重，用贪心模拟天数验证。

## 怎么做
1. 下界取 `max(weights)`（单个最重包裹必须装得下），上界取 `sum(weights)`（一天全装完）。
2. 写 `need(cap)`：顺序累加，超过 `cap` 就换天、天数 +1，返回总天数。
3. 二分找最小的 `cap` 使 `need(cap) <= days`。

以示例 1 为例，`lo=10, hi=55`，第一次 `mid=32`，`need(32)=1 <= 5`，`hi=32`；继续收缩到 `mid=15` 时 `need(15)=5`，可行，`hi=15`；`mid=12` 时 `need(12)=6 > 5`，不可行，`lo=13`；最终 `lo=hi=15`。

```python
def need(cap):
    d, cur = 1, 0
    for w in weights:
        if cur + w > cap:
            d += 1
            cur = 0
        cur += w
    return d

lo, hi = max(weights), sum(weights)
while lo < hi:
    mid = (lo + hi) // 2
    if need(mid) <= days:
        hi = mid
    else:
        lo = mid + 1
return lo
```

关键在 `need` 里 `cur + w > cap` 才换天：`cur` 重置为 0 后必须把 `w` 加进去，不能漏。

## 复杂度
时间：二分 `log(sum - max)` 次，每次 `need` 扫 n 个包裹，共 O(n log S)。
空间：只用了 `lo/hi/mid/d/cur` 几个变量，O(1)。

## 易错点
- 下界写成 0 或 1 → `need(cap)` 遇到 `weights[i] > cap` 时 `cur` 永远装不下，会死循环式换天或返回错误天数 → 下界必须是 `max(weights)`，保证每个包裹单独一天能装。
- `need` 里写成 `cur + w >= cap` 才换天 → 示例 1 中 `cap=15` 时 `1+2+3+4+5=15` 会被误判为超载，`need(15)` 变成 6 天，答案错成 16 → 判断条件只能是严格大于 `cap`。

## 如果面试官追问
要求输出每天装哪些包裹怎么办？答：二分定下 `cap` 后，用同一个 `need` 的贪心逻辑再扫一遍，把每次换天前的下标区间记下来即可，天数仍是最优的。
