## 一句话思路
把 words 建成哈希集合，对每个词做「能否切成至少两段、每段都在集合里」的 DP 判定。

## 怎么做
1. 先按长度升序排序，保证判定长词时短词已全部入集合。
2. 用 `set(words)` 做 O(1) 查词，逐词跑 `can_split`。
3. DP 定义 `dp[i]` = 前缀 `w[:i]` 能否由集合中单词拼成，`dp[0]=True`。
4. 转移时枚举切点 `j`，要求 `dp[j] and w[j:i] in st`，且总段数 ≥2。

以 `"catdog"` 为例，`st={"cat","dog"}`：`dp[0]=True`；`i=3` 时 `j=0`，`"cat" in st` → `dp[3]=True`；`i=6` 时 `j=3`，`"dog" in st` → `dp[6]=True`，段数 2，收入答案。

```python
def can_split(w, st):
    n = len(w)
    dp = [False] * (n + 1)
    dp[0] = True
    for i in range(1, n + 1):
        for j in range(i):
            if dp[j] and w[j:i] in st:
                dp[i] = True
                break
    return dp[n]
```

段数 ≥2 的约束不能靠 DP 本身保证：`"cat"` 自身在集合里，`dp[3]` 也会是 True。做法是转移时禁止 `j==0 and i==n` 这一整段直接命中，即要求至少切一刀。

## 复杂度
时间：O(m·L²)，m 为词数、L≤30 为词长，切片比较再乘 L，总长 10⁵ 时约 10⁷ 量级。
空间：集合存全部字符 O(sum L)，单次 DP 数组 O(L)。

## 易错点
- 输入 `["cat","dog","catdog"]` 若只判 `dp[n]`，`"cat"`、`"dog"` 自身也会被误判为连接词 → 必须加「至少切一刀」的条件，只输出 `"catdog"`。
- 输入 `["a"]` 或 `["cat","cats"]` 这类无连接词的数组，若先排序后忘记跳过自身匹配，会把单词自己算成由自己组成 → 判定时排除 `j==0 and i==n` 的整段命中。

## 如果面试官追问
问：词长上限从 30 提到 10³ 怎么办？
答：哈希切片退化为 O(L³)，改用字典树边走边匹配，把每个起点的枚举压到 O(L²)。
