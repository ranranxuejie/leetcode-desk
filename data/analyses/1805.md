## 一句话思路
用正则或双指针切出每段连续数字，去掉前导零后丢进 set，集合大小即答案。

## 怎么做
1. 用 `re.findall(r'\d+', word)` 一次性取出所有连续数字子串，得到列表 `nums`。
2. 对每个子串 `s` 做 `s.lstrip('0')`，全零会变成空串，统一替换成 `'0'`。
3. 把处理后的串加入 `set`，最后返回 `len(set)`。

以示例 3 `word = "a 1 b 01 c 001 "` 为例：`findall` 得到 `['1','01','001']`；`lstrip('0')` 后分别是 `'1'`、`'1'`、`'1'`（`'001'` 去掉两个零剩 `'1'`），集合只剩一个元素，返回 1。

```python
import re

def numDifferentIntegers(word):
    seen = set()
    for s in re.findall(r'\d+', word):
        t = s.lstrip('0') or '0'
        seen.add(t)
    return len(seen)
```

关键点：`lstrip('0')` 对 `'000'` 返回 `''`，必须用 `or '0'` 兜底，否则 `'000'` 和 `'0'` 会被当成两个不同值。

## 复杂度
时间 O(n)：n 为 `word` 长度，扫描一遍加集合插入，字符串比较总长不超过 n。
空间 O(n)：`seen` 最多存 n/2 个数字串，加上 `findall` 的临时列表。

## 易错点
- 输入 `"0"` 或 `"a0b00c"` → 若只写 `s.lstrip('0')` 不加 `or '0'`，`'0'` 和 `'00'` 都变成空串 `''`，虽然恰好还能去重，但若同时出现 `'0'` 与 `'000'` 之外的组合（如 `'10'` 与 `'010'`）逻辑仍对；真正翻车是 `'0'` 单独出现时集合里存的是 `''`，与题意「整数 0」不符，调试时打印集合会看到空串。正确做法：`t = s.lstrip('0') or '0'`。
- 输入 `"a123456789012345678901234567890b"` → 若用 `int(s)` 转成整数再存集合，Python 虽不溢出但大整数哈希和比较代价高；更隐蔽的坑是若按 32 位截断（题目未要求，但有人误加 `% (2**31)`）会把两个不同大数判成同一个。正确做法：全程按字符串去前导零比较，不做数值转换。

## 如果面试官追问
问：若 `word` 长度到 10^7，`re.findall` 一次性建列表内存吃紧怎么办？
答：改用单指针原地扫描，边扫边把当前数字段 `lstrip('0')` 后插入 set，空间只留 set 本身。
