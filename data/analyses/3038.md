## 一句话思路
固定第一刀的和 `nums[0]+nums[1]` 为基准分，从下标 2 起每两个一组往后扫，组和不等就停。

## 怎么做
1. 记 `target = nums[0] + nums[1]`，这是唯一可能的分值——第一刀必须切前两个元素，没有别的选择。
2. 令 `i = 2`，`ans = 1`，从下标 2 开始按步长 2 往后走。
3. 每轮检查 `nums[i] + nums[i+1] == target`，成立则 `ans += 1`、`i += 2`，否则立刻 `break`。
4. 循环条件写成 `i + 1 < len(nums)`，保证不会越界取到单个尾巴。

用示例 1 `nums = [3,2,1,4,5]` 走一遍：`target = 5`，`i = 2` 时 `nums[2]+nums[3] = 1+4 = 5` 命中，`ans` 变 2、`i` 变 4；此时 `i+1 = 5` 不满足 `< 5`，退出，返回 2。示例 2 里 `target = 5`，`i = 2` 时 `nums[2]+nums[3] = 6+1 = 7 ≠ 5`，第一轮就 break，返回 1。

```python
target = nums[0] + nums[1]
ans, i = 1, 2
while i + 1 < len(nums):
    if nums[i] + nums[i + 1] != target:
        break
    ans += 1
    i += 2
return ans
```

关键点在于「前两个元素」是硬约束：删除后数组左移，但剩下的元素相对顺序不变，所以第 k 次操作切的就是原数组下标 `2k` 和 `2k+1`。不需要真的 `pop(0)` 两次去模拟，那会把复杂度推到 O(n²)。

## 复杂度
时间 O(n)：最坏扫完整个数组，每轮只做一次加法比较。
空间 O(1)：只开了 `target`、`ans`、`i` 三个变量，没有复制数组。

## 易错点
- 输入 `nums = [1,1,1,1]` → 若把 `ans` 初值写成 0 再在循环里累加，会漏掉第一刀，错成 3 → 正确做法是初值直接给 1，因为长度 ≥ 2 时第一刀必然能切。
- 输入 `nums = [2,2,2,3]` → 若循环条件写成 `i < len(nums)`，`i = 2` 时访问 `nums[3]` 得 5 ≠ 4 恰好 break 侥幸正确，但换成 `nums = [2,2,2,2,7]` 就会在 `i = 4` 时访问 `nums[5]` 越界 → 正确做法是条件写 `i + 1 < len(nums)`，奇数长度时自动留下最后一个元素不处理。

## 如果面试官追问
问：如果允许从任意位置开始删（不限于前两个），答案怎么变？
答：那就变成统计数组里出现次数最多的「相邻对和」，返回该次数，用哈希表 O(n) 扫一遍即可。
