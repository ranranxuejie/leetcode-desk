## 一句话思路
统计每个值出现在多少个长度为 k 的窗口里，计数恰为 1 的最大值就是答案。

## 怎么做
1. 用 `Counter` 记下每个值在 nums 中出现的次数，记为 `cnt`。
2. 关键观察：值 x 被多少个窗口覆盖，只取决于它出现的位置离数组两端有多远——出现在下标 `i` 的 x，被覆盖的窗口数等于 `min(i, n-k) - max(0, i-k+1) + 1`，但更简单的做法是直接枚举所有窗口。
3. 枚举 `n-k+1` 个窗口，用集合去重后累加每个值的窗口计数 `win[v] += 1`。
4. 从大到小扫 `win`，第一个计数为 1 的值即为答案，否则返回 -1。

以示例 1 `nums = [3,9,2,1,7], k = 3` 为例，窗口是 `[3,9,2]`、`[9,2,1]`、`[2,1,7]`，累加后 `win = {3:1, 9:2, 2:3, 1:2, 7:1}`，计数为 1 的有 3 和 7，取最大得 7。

```python
from collections import Counter
n = len(nums)
win = Counter()
for i in range(n - k + 1):
    for v in set(nums[i:i + k]):
        win[v] += 1
ans = -1
for v, c in win.items():
    if c == 1 and v > ans:
        ans = v
return ans
```

注意 `set(nums[i:i+k])` 这一层去重不能省：示例 2 中窗口 `[7,2,1,7]` 里 7 出现两次，若不去重会把 7 的窗口计数多加一次，从 3 变成 4，答案就会错判成 7 而不是 3。

## 复杂度
时间 O((n-k+1)·k)，每个窗口切片加去重贡献 k。
空间 O(n)，`win` 最多存 n 个不同值。

## 易错点
- 输入 `nums = [0,0], k = 1` → 若不去重直接 `win[v] += 1`，0 的计数会变成 2，误判为不存在；正确做法是每个窗口先 `set()` 再累加，0 的计数为 1 但值本身是 0，仍要参与比较。
- 输入 `nums = [3,9,7,2,1,7], k = 4` → 若只统计元素总出现次数（7 出现 2 次）而不按窗口统计，会漏掉 3 这种「全局只出现一次但只在 1 个窗口里」的值；正确做法是统计窗口覆盖数而非元素频次。

## 如果面试官追问
若 n 放大到 10^5、k 也很大，怎么优化？
答：用差分数组按每个值出现的位置区间累加覆盖窗口数，避免逐窗口切片，时间降到 O(n)。
