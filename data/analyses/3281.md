## 一句话思路
二分答案 `g`，用贪心检查能否在排序后的区间里依次放下间距 ≥ g 的数。

## 怎么做
1. 把 `start` 排序，区间顺序不影响可行性，但排序后才能从左往右贪心。
2. 二分 `g`，范围 `[0, (max(start)+d - min(start)) // (n-1)]`，上界是平均间距。
3. 检查函数：维护上一个选的数 `prev`，对每个区间取 `cur = max(start[i], prev + g)`，若 `cur > start[i] + d` 则失败，否则 `prev = cur`。
4. 以 `start = [6,0,3], d = 2` 为例，排序后 `[0,3,6]`。试 `g = 4`：第一个区间取 `0`；第二个 `max(3, 0+4)=4 ≤ 5`，取 `4`；第三个 `max(6, 4+4)=8 ≤ 8`，取 `8`，成功，答案 4。

```python
def ok(g):
    prev = -10**18
    for s in start:
        cur = max(s, prev + g)
        if cur > s + d:
            return False
        prev = cur
    return True
```

二分时 `lo, hi = 0, (max(start) + d - min(start)) // (n - 1)`，`while lo < hi` 取 `mid = (lo + hi + 1) // 2`，`ok(mid)` 为真则 `lo = mid`，否则 `hi = mid - 1`，返回 `lo`。

## 复杂度
时间：排序 `O(n log n)`，二分 `O(log(max(start)+d))` 轮、每轮 `O(n)`，合计 `O(n log n + n log V)`。
空间：排序额外 `O(log n)` 栈空间，检查函数只用 `prev` 一个变量。

## 易错点
- `start` 有重复值如 `[2,6,13,13]`：不排序直接按原顺序贪心，`13` 和 `13` 两个区间会互相挤压导致误判失败；必须先 `sort()`，排序后 `13` 取 `13`、`18` 取 `18` 才可行。
- 检查时写成 `cur = prev + g` 而不与 `start[i]` 取 `max`：当 `prev + g < start[i]` 时（如 `g=0`、`prev=0`、`start[i]=6`），会取到区间外的数；正确是 `max(start[i], prev + g)`，保证落在 `[start[i], start[i]+d]` 内。

## 如果面试官追问
要求输出具体方案而非得分？答：二分出 `g` 后，用同一贪心再跑一遍，把每步的 `cur` 收集起来即为可行解。
