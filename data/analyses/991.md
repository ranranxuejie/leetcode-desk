## 一句话思路
从 target 反向推回 startValue：偶数就除 2，奇数就加 1，比正向贪心好判断。

## 怎么做
1. 反向思考：正向的「乘 2」在反向是「除 2」，「减 1」在反向是「加 1」，操作数不变。
2. 循环条件 `target > startValue`：只要还没退到起点就继续。
3. 若 `target` 是偶数，直接 `target //= 2`；若是奇数，先 `target += 1` 再除（等价于加 1 后下一步除 2，但这里分两步各计一次操作）。
4. 循环结束后 `target <= startValue`，剩下的差值只能靠反向的「加 1」补，即 `startValue - target` 次。

以示例 3 `startValue = 3, target = 10` 走一遍：10 偶 → 5（1 次）；5 奇 → 6（1 次）→ 3（1 次）；此时 `target = 3 == startValue`，循环停，差值 0，总计 3 次，与官方答案一致。

```python
def brokenCalc(startValue, target):
    ops = 0
    while target > startValue:
        if target % 2 == 0:
            target //= 2
        else:
            target += 1
        ops += 1
    return ops + (startValue - target)
```

关键点：奇数时「加 1」不是浪费——`target = 5` 加 1 变 6 才能被 2 整除，若改成减 1 变 4，反向就对应正向的「加 1 再乘 2」，路径更长。

## 复杂度
时间：O(log target)，每轮 target 至少减半，循环次数由 target 的二进制位数决定。
空间：O(1)，只用了 `ops` 和 `target` 两个变量。

## 易错点
- 输入 `startValue = 5, target = 8` → 若正向贪心「先乘 2 再减」会得 5→10→9→8 共 3 次，错成 3；正确反向是 8 偶→4（1 次），4 < 5，差值 1，共 2 次，对应正向 5→4→8。
- 输入 `startValue = 1, target = 10**9` → 若用 `while target != startValue` 且奇数时盲目 `target -= 1`，会把 10**9 一路减到 1，超时；正确做法是奇数加 1、偶数除 2，循环 O(log target) 次就收敛。

## 如果面试官追问
问：要求输出具体操作序列而非次数怎么办？
答：反向记录每步是「除 2」还是「加 1」，最后反转序列并映射回正向的 Double/Decrement 即可。
