## 一句话思路
自底向上 DFS，每个节点返回「到本子树各叶子的距离列表」，在节点处跨左右子树配对计数。

## 怎么做
1. 叶子节点返回 `[0]`；空节点返回 `[]`。
2. 递归拿到 `left`、`right` 两个距离列表后，先做配对：对每个 `l in left`、`r in right`，若 `l + r + 2 <= distance` 则答案加一。
3. 把 `left`、`right` 里每个距离加一（跨过当前节点这条边）后合并返回，同时丢弃 `> distance` 的项——它们再往上只会更长，永远配不上。
4. 以示例 2（`[1,2,3,4,5,6,7]`, `distance=3`）为例：节点 2 收到 `left=[0]`（叶子 4）、`right=[0]`（叶子 5），配对 `0+0+2=2<=3`，答案 +1，返回 `[1,1]`；节点 3 同理 +1 返回 `[1,1]`；根处 `left=[1,1]`、`right=[1,1]`，最小配对 `1+1+2=4>3`，不再增加，最终答案 2。

```python
def dfs(node):
    if not node: return []
    if not node.left and not node.right: return [0]
    left, right = dfs(node.left), dfs(node.right)
    for l in left:
        for r in right:
            if l + r + 2 <= distance:
                ans[0] += 1
    return [d + 1 for d in left + right if d + 1 <= distance]
```

`ans` 用单元素列表或 `nonlocal` 承接，避免在递归里传返回值。

## 复杂度
时间：每个节点合并两个长度 ≤ distance 的列表，O(n · distance²) 最坏，配对是主项。
空间：递归栈 O(h)，每层列表长度 ≤ distance，额外 O(h · distance)。

## 易错点
- 单节点树 `root=[100]`、`distance=1`：若把根当叶子返回 `[0]` 并参与配对，会误判出 1 对；正确做法是只有 `not node.left and not node.right` 才算叶子，根无子节点时返回 `[0]` 但没有任何配对机会，答案 0。
- 忘记在返回前过滤 `d + 1 > distance`：示例 2 中若把节点 2 返回的 `[1,1]` 继续加一传到根变成 `[2,2]`，配对 `2+2+2=6` 虽仍不满足，但深层树里这些超距项会白白撑大列表、拖慢合并；正确做法是 `if d + 1 <= distance` 才保留。

## 如果面试官追问
若 `distance` 放大到 10^5 且节点数 10^5，怎么做？答：距离列表会退化，改用「每个节点维护有序距离数组 + 双指针/二分统计跨子树配对数」，或直接对每对叶子求 LCA 距离，按数据规模取舍。
