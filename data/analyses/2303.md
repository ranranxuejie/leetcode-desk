## 一句话思路
按税级逐段切分 income，每段宽度取 `min(income, upper) - 上一档上限`，乘税率累加。

## 怎么做
1. 维护 `prev = 0` 表示上一税级的上限，`tax = 0.0` 累加税款。
2. 遍历 `brackets`，每档实际计税收入为 `min(income, upper) - prev`。
3. 若该值 `<= 0` 说明 income 已在本档之前耗尽，直接 `break`。
4. 否则 `tax += 该值 * percent / 100`，再更新 `prev = upper`。

以示例 1 `brackets = [[3,50],[7,10],[12,25]], income = 10` 为例：第一档 `min(10,3)-0 = 3`，税 `3*50/100 = 1.5`；第二档 `min(10,7)-3 = 4`，税 `0.4`；第三档 `min(10,12)-7 = 3`，税 `0.75`；合计 `2.65`。

```python
prev = 0
tax = 0.0
for upper, percent in brackets:
    taxable = min(income, upper) - prev
    if taxable <= 0:
        break
    tax += taxable * percent / 100
    prev = upper
return tax
```

关键点：`min(income, upper)` 保证 income 落在中间档时只算到 income，不会把整档宽度算进去。

## 复杂度
时间 O(n)：n 为 `brackets.length`，最多遍历全部税级。
空间 O(1)：只开了 `prev`、`tax`、`taxable` 三个变量。

## 易错点
- `income = 0`（示例 3）→ 若先算 `upper - prev` 再判断，会把第一档整段 `2` 计入税款 → 必须先取 `min(income, upper)`，此时 `taxable = 0` 直接 break，返回 `0.0`。
- `income` 恰好等于某档上限，如 `income = 7` 配示例 1 → 若循环不 break 继续算第三档，`min(7,12)-7 = 0` 虽不加税但逻辑侥幸对；若写成 `upper - prev` 则第三档会多算 `5*25/100` → 统一用 `min(income, upper) - prev` 并配 `<= 0` 判断才稳。

## 如果面试官追问
问：若 brackets 未按上限排序怎么办？答：先按 `upper` 升序排序再跑同一套逐段累加，复杂度变 O(n log n)。
