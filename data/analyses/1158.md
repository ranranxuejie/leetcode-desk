## 一句话思路
以 Users 为主表左连 Orders，把 2019 年条件放进 ON 而不是 WHERE，这样零单用户不会被过滤掉。

## 怎么做
1. 从 Users 出发 LEFT JOIN Orders，连接键是 `Users.user_id = Orders.buyer_id`。
2. 年份过滤写成 `ON ... AND YEAR(order_date) = 2019`，让不匹配的行保留为 NULL。
3. 按 `user_id, join_date` 分组，用 `COUNT(order_id)` 计数（COUNT 列名而非 COUNT(*)）。
4. 输出列别名 `buyer_id, join_date, orders_in_2019`。

用官方示例看关键中间值：user_id=3 在 Orders 里只有 2018-08-04 那单（order_id=5），ON 条件把它判为不匹配，左连后该行 `order_id` 为 NULL；分组后 `COUNT(order_id)` 得 0，而不是 1。若把 `YEAR(order_date)=2019` 挪到 WHERE，user_id=3 和 4 整行被删，输出只剩 1、2 两行。

```python
# 关键三行（SQL 语义，用 pandas 表达同一逻辑）
o19 = orders[orders["order_date"].dt.year == 2019]
cnt = o19.groupby("buyer_id").size().rename("orders_in_2019")
res = users.merge(cnt, left_on="user_id", right_index=True, how="left")
res["orders_in_2019"] = res["orders_in_2019"].fillna(0).astype(int)
```

`how="left"` 对应 LEFT JOIN，`fillna(0)` 对应 COUNT 对 NULL 记 0 的行为；user_id=3 在 `cnt` 里不存在，merge 后为 NaN，填 0 得正确结果。

## 复杂度
时间：O(U + O)，U 为 Users 行数、O 为 Orders 行数，各扫一遍，分组是哈希。
空间：O(U)，额外存每个用户的计数结果。

## 易错点
- 把 `YEAR(order_date) = 2019` 写进 WHERE：user_id=3、4 在 2019 年无单，会被整行过滤，输出少两行；正确做法是放进 LEFT JOIN 的 ON 子句。
- 用 `COUNT(*)` 代替 `COUNT(order_id)`：左连产生的 NULL 行也被计入，user_id=3 会错成 1；正确做法是 COUNT 具体列 `order_id`，NULL 不计。

## 如果面试官追问
问：Orders 涨到十亿行怎么办？答：先在 Orders 上按 `YEAR(order_date)=2019` 过滤再聚合，把参与 join 的行数压到 2019 年那部分。
