## 一句话思路
维护「最小首元素」和「最小二元组尾元素」两个变量，扫描时一旦出现比后者大的数就成立。

## 怎么做
1. 令 `first = 2**31 - 1`、`second = 2**31 - 1`，分别表示已见过的最小 `nums[i]` 和最小可行 `nums[j]`。
2. 遍历 `x in nums`：若 `x > second` 直接返回 `True`；否则若 `x > first` 就更新 `second = min(second, x)`；否则更新 `first = x`。
3. 用示例 3 `[2,1,5,0,4,6]` 走一遍：`x=2` 更新 `first=2`；`x=1` 更新 `first=1`；`x=5` 因 `5>first` 令 `second=5`；`x=0` 更新 `first=0`；`x=4` 因 `4<second` 令 `second=4`；`x=6>4` 返回 `True`。
4. 关键中间值：走到 `x=4` 时 `first=0, second=4`，说明存在下标 `i<j` 使 `nums[i]=0<nums[j]=4`，`6` 正好补上第三元。

```python
first = second = 2**31 - 1
for x in nums:
    if x > second:
        return True
    if x > first:
        second = min(second, x)
    else:
        first = x
return False
```

注意 `second` 用 `min` 而不是直接赋值：`[1,5,2,3]` 中 `x=2` 时 `second` 从 5 降到 2，`3` 才能触发。

## 复杂度
时间 O(n)：一次遍历 `nums`，每个元素常数次比较。
空间 O(1)：只开 `first`、`second` 两个变量。

## 易错点
- 输入 `[1,5,2,3]` → 若写成 `second = x` 无条件覆盖，`x=2` 时 `second` 变 2 没问题，但若顺序写成先判 `x > first` 再判 `x > second`，`x=3` 会先被 `second` 分支吞掉返回 `False`；正确做法是 `x > second` 的判断必须放在最前面。
- 输入 `[2,1,5,0,4,6]` → 若把 `first` 更新成 `0` 后认为「前面的 1 丢了」，误判为不存在；正确做法是 `first` 变小只会让后续更容易满足 `x > first`，`second=4` 仍代表 `1<4` 这个旧二元组，贪心替换是安全的。

## 如果面试官追问
要求返回具体三元组下标怎么办？答：额外存 `first_idx`、`second_idx`，命中 `x > second` 时返回 `(first_idx, second_idx, 当前下标)`，`second` 更新时同步记下当时的 `first_idx`。
