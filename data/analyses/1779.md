## 一句话思路
一次遍历所有点，筛出 `a == x or b == y` 的有效点，用严格小于更新最小曼哈顿距离，天然保留最小下标。

## 怎么做
1. 初始化 `best = -1`（答案下标）、`best_dist = 2**31 - 1`（当前最小距离）。
2. 按下标 `i` 从 0 到 `len(points)-1` 顺序遍历，保证「距离相同取小下标」自动成立。
3. 对每个 `[a, b]`，先判有效：`a == x or b == y`；无效直接跳过。
4. 有效则算 `d = abs(a - x) + abs(b - y)`，只有 `d < best_dist` 才更新 `best_dist = d; best = i`——用严格小于，等距时保留先遇到的（即更小下标）。

以示例 1 为例，`x=3, y=4`，遍历到 `i=2` 时点是 `[2,4]`：`b == y` 有效，`d = abs(2-3) + abs(4-4) = 1`，更新 `best_dist=1, best=2`。接着 `i=3` 的 `[2,3]` 无效跳过；`i=4` 的 `[4,4]` 有效但 `d = 1`，不满足 `1 < 1`，`best` 保持 2，正是答案。

```python
best, best_dist = -1, 2**31 - 1
for i, (a, b) in enumerate(points):
    if a == x or b == y:
        d = abs(a - x) + abs(b - y)
        if d < best_dist:
            best_dist, best = d, i
return best
```

关键点：`best_dist` 初值取 `2**31 - 1` 而非 `0`，否则任何 `d >= 0` 都不会更新；坐标上限 10^4，最大距离 2*10^4，这个初值足够大。

## 复杂度
时间 O(n)：n 为 `points` 长度，每个点常数次比较与一次绝对值求和。
空间 O(1)：只开 `best`、`best_dist` 两个标量，无额外数组。

## 易错点
- 输入 `points = [[3,4]]`（示例 2）→ 若把有效条件写成 `a == x and b == y`，会漏掉「同 x 或同 y」的点，返回 -1；正确是 `or`，此点 `d=0` 返回 0。
- 输入示例 1 中 `[2,4]` 与 `[4,4]` 距离都是 1 → 若用 `d <= best_dist` 更新，`i=4` 会覆盖 `i=2`，返回 4；正确用严格 `<`，等距保留小下标。

## 如果面试官追问
若要求返回所有最近有效点的下标列表？答：把更新逻辑改成「`d < best_dist` 时清空列表并重置，`d == best_dist` 时追加 `i`」，仍是一趟 O(n)。
