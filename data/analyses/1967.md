## 一句话思路
对 `patterns` 里每个串直接调 `in` 判断是否为 `word` 的子串，命中就计数，重复元素各算一次。

## 怎么做
1. 初始化 `cnt = 0`，遍历 `patterns` 的每个 `p`。
2. 用 `p in word` 判断子串关系，成立则 `cnt += 1`。
3. 不建集合去重，因为示例 3 的 `["a","a","a"]` 要求输出 3。
4. 返回 `cnt`。

以示例 1 为例：`patterns = ["a","abc","bc","d"]`，`word = "abc"`。逐个判断得 `"a" in "abc"` 为 `True`、`"abc" in "abc"` 为 `True`、`"bc" in "abc"` 为 `True`、`"d" in "abc"` 为 `False`，`cnt` 依次累加到 3。

```python
cnt = 0
for p in patterns:
    if p in word:
        cnt += 1
return cnt
```

关键点：`p in word` 是 Python 的连续子串判断，语义与题面「连续字符序列」完全一致，不需要自己写双指针或切片比较。若手写，等价于对每个起点 `i` 检查 `word[i:i+len(p)] == p`，但内置实现更快且不会写错边界。

## 复杂度
时间：O(len(patterns) × len(word) × L)，`in` 最坏按 `word` 每个起点比 L 个字符，L 为 `p` 长度。
空间：O(1)，只开 `cnt` 一个计数器，不复制子串。

## 易错点
- 输入 `patterns = ["a","a","a"], word = "ab"` → 若先 `set(patterns)` 去重再计数，会错成 1 → 正确做法是直接遍历原列表，重复项各计一次，输出 3。
- 输入 `patterns = ["ab"], word = "ba"` → 若误用「字符集合包含」或 `sorted` 比较，会错判为子串 → 正确做法是坚持连续子串语义，`"ab" in "ba"` 为 `False`，不计入。

## 如果面试官追问
追问：若 `word` 长达 10^5、`patterns` 有 10^4 个，还逐个 `in` 吗？
答：改用 Aho-Corasick 或对 `word` 建后缀自动机，把所有 `patterns` 一次匹配，避免重复扫描。
