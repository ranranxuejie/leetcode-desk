## 一句话思路
按位统计奇偶：子数组每位 1 的个数全为偶数才美丽，用前缀异或值相等来计数。

## 怎么做
1. 关键观察：操作只在同一二进制位上成对消去两个 1，所以子数组美丽 ⟺ 每一位上 1 的个数都是偶数。
2. 把每个 `nums[i]` 看成一个「奇偶向量」，子数组美丽 ⟺ 向量异或和为 0，于是转成前缀异或相等计数。
3. 用哈希表 `cnt` 记录每个前缀异或值出现次数，`cnt[0] = 1`，遍历时累加 `cnt[cur]` 再自增。
4. 以 `nums = [4,3,1,2,4]` 为例：前缀异或依次为 `4, 7, 6, 4, 0`；到下标 3 时 `cur = 4`，`cnt[4]` 已是 1，答案 +1；到下标 4 时 `cur = 0`，`cnt[0]` 为 1，答案 +1，共 2。

```python
cnt = {0: 1}
cur = 0
ans = 0
for x in nums:
    cur ^= x
    ans += cnt.get(cur, 0)
    cnt[cur] = cnt.get(cur, 0) + 1
```

## 复杂度
时间 O(n)：每个元素做一次异或和一次哈希查改。
空间 O(n)：`cnt` 最多存 n+1 个不同前缀异或值。

## 易错点
- 漏掉 `cnt[0] = 1`：`nums = [4,3,1,2,4]` 会漏掉从下标 0 开始的 `[4,3,1,2,4]`，答案错成 1 而不是 2；必须先把空前缀的异或值 0 计入。
- 用「子数组和」代替异或：`nums = [1,10,4]` 中 `1+10+4=15` 非 0 看似无解，但真正判据是逐位奇偶，若误用和为零会漏判或误判；应始终维护 `cur ^= x` 而非 `cur += x`。

## 如果面试官追问
问：若要求返回所有美丽子数组的起止下标？
答：哈希表存 `cur -> 下标列表`，命中时把当前下标与列表中每个下标配对输出，时间仍是 O(n + 答案数)。
