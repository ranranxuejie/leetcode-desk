## 一句话思路
用最小堆每次弹出两个最小值合并后压回，因为合并结果只会变大，贪心取最小两个不会让后续变差。

## 怎么做
1. 把 `nums` 全部 `heapify` 成小顶堆，操作计数 `ans = 0`。
2. 循环条件：堆顶 `heap[0] < k`（堆顶是当前最小值，它达标则全体达标）。
3. 每轮 `heappop` 两次得 `x`、`y`，压回 `x * 2 + y`，`ans += 1`。
4. 返回 `ans`。

以示例 1 `nums = [2,11,10,1,3], k = 10` 为例：堆化后弹出 `1` 和 `2`，压回 `1*2+2 = 4`，堆变 `[3,4,10,11]`；再弹出 `3` 和 `4`，压回 `3*2+4 = 10`，堆变 `[10,10,11]`，堆顶 `10 >= 10` 停止，`ans = 2`。

```python
import heapq

def minOperations(nums, k):
    heapq.heapify(nums)
    ans = 0
    while nums[0] < k:
        x = heapq.heappop(nums)
        y = heapq.heappop(nums)
        heapq.heappush(nums, x * 2 + y)
        ans += 1
    return ans
```

注意 `x * 2 + y` 里 `x` 是第一次弹出的（更小），`y` 是第二次弹出的，顺序不能反——反了会算成 `y*2+x`，示例 1 第一轮就变成 `2*2+1 = 5` 而非 `4`，后续步数全错。

## 复杂度
时间：O(n + m log n)，`n` 来自建堆，`m` 次操作每次两次 pop 一次 push 各 O(log n)。
空间：O(1) 额外，原地复用 `nums` 作堆。

## 易错点
- 输入 `nums = [1,1,2,4,9], k = 20`：若循环写成 `while min(nums) < k` 且每轮重新 `min()`，会退化成 O(n·m) 超时；正确做法是维护堆，只看 `nums[0]`。
- 输入 `nums = [1000000000, 1000000000], k = 1000000000`：堆顶已达标，若漏掉循环条件直接进循环体，会 `heappop` 两次后堆空再 `heappush`，逻辑上多做一次无意义操作；正确做法是先判 `nums[0] < k` 再进循环。另外合并值可能超过 `2**31 - 1`，Python 整数无溢出问题，但若移植到 32 位语言需用 64 位。

## 如果面试官追问
问：如果要求输出每次操作的具体元素和结果序列？
答：在循环里把 `(x, y, x*2+y)` 追加到列表，最后一起返回即可，堆逻辑不变。
