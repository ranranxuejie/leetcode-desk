## 一句话思路
按排独立：每排只有 A/B、C/D 两对相邻关系，用 4 位掩码记该排状态，总时间累加、最小时间按对查表。

## 怎么做
1. 用 `rows = [0] * (n + 1)` 存每排 4 位掩码，位序 A=1,B=2,C=4,D=8；`total` 维护当前总时间。
2. `toggle` 解析出列字母和排号，算出 `bit`；若 `rows[r] & bit` 已置位则释放，否则预订。
3. 预订时算该座位耗时：中间座位恒为 1；靠窗座位看相邻中间位是否已置位，是则 3 否则 1，加到 `total`；释放时从 `total` 减去当初记下的耗时（需另存每座位耗时，或按同样规则重算——释放时相邻中间位状态未变，重算结果一致）。
4. `getMinTime` 逐排对 `rows[r]` 查预置表：对 (A,B) 和 (C,D) 两对，若两个都订则贡献 2（先订窗后订中），否则贡献该对已订座位数。

以示例 1 为例：订 B3 后 `rows[3]=2`，`total=1`；再订 A3，`rows[3]&1==0` 但 `rows[3]&2!=0`，耗时 3，`total=4`；`getMinTime` 查表 `rows[3]=3` 得 2。

```python
COST = {}  # 每对 (窗位, 中位) 的 4 种组合 -> 最小耗时
for w in (0, 1):
    for m in (0, 1):
        COST[(w, m)] = 2 if (w and m) else (w + m)

def min_time(mask):
    return (COST[((mask >> 0) & 1, (mask >> 1) & 1)]
            + COST[((mask >> 3) & 1, (mask >> 2) & 1)])
```

## 复杂度
时间：每次 toggle 与 getTotalTime 均 O(1)；getMinTime 需扫 n 排，O(n)。
空间：`rows` 数组 O(n)，无其他额外结构。

## 易错点
- 释放座位时若用「当前相邻状态重算耗时」而非「当初记录的耗时」，在 A3、B3 都订后先释放 B3 再释放 A3 的场景下，A3 重算得 1 而非当初的 3，`total` 会算错；正确做法是预订时把耗时存进 `cost[r][col]`，释放时直接减。
- `getMinTime` 若按「所有已订座位数 × 1」算，示例 1 的 `rows[3]=3`（A、B 同订）会得 3 而非 2；必须按对分别查表，同对两座都订才省下那 2 秒。

## 如果面试官追问
若 n 扩大到 10^9 但 toggle 次数仍 10^5，怎么办？
答：`rows` 改用字典只存被操作过的排，`getMinTime` 遍历字典而非 1..n，复杂度降为 O(操作次数)。
