## 一句话思路
先按 income 分桶计数，再与三行固定类别表左连接补 0，保证空类别也出现。

## 怎么做
1. 用 `CASE WHEN` 把每行 income 映射成三个类别名之一，`GROUP BY` 得到有账户的类别计数。
2. 单独构造三行类别常量表（Low/Average/High），作为左表。
3. 左连接计数结果，`COALESCE(cnt, 0)` 补零。
4. 以官方示例验证：income 12747 → Low；108939、87709、91796 均 > 50000 → High；无 20000~50000 的值，故 Average 计数为 0，最终 `(Low,1),(Average,0),(High,3)`。

```python
# 伪 SQL 逻辑，落到 Python 即：
cats = ["Low Salary", "Average Salary", "High Salary"]
cnt = {c: 0 for c in cats}
for inc in incomes:                      # incomes = [108939,12747,87709,91796]
    if inc < 20000: cnt["Low Salary"] += 1
    elif inc <= 50000: cnt["Average Salary"] += 1
    else: cnt["High Salary"] += 1
return [(c, cnt[c]) for c in cats]
```
关键中间值：遍历完 4 行后 `cnt = {"Low Salary":1, "Average Salary":0, "High Salary":3}`，Average 的 0 来自初始化而非数据。

## 复杂度
时间 O(n)，n 为 Accounts 行数，每行一次比较。
空间 O(1)，只开三个类别的计数字典。

## 易错点
- 边界值 20000 和 50000 → 若写成 `inc < 20000` 判 Low 后又用 `inc < 50000` 判 Average，则 50000 会漏进 High；正确是 Average 用 `20000 <= inc <= 50000`（闭区间），High 用 `inc > 50000`。
- 表里没有 Average 区间的账户（如示例）→ 只 `GROUP BY` 会少一行，输出只剩 2 行；正确做法是先固定三行类别再左连接补 0，不能靠数据里出现的类别。

## 如果面试官追问
问：若类别边界改成可配置（如动态阈值列表）？答：把三行常量换成阈值表，用 `JOIN ... ON income BETWEEN lo AND hi` 或按阈值排序后二分定位类别，再左连接补零。
