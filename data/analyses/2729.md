## 一句话思路
把 n、2n、3n 拼成字符串，用长度 9 加集合去重判断是否恰好是 1 到 9。

## 怎么做
1. 用 `s = str(n) + str(2*n) + str(3*n)` 一次拼出三段，避免逐位取模。
2. 先判 `len(s) == 9`，长度不对直接 `False`，省掉后续集合操作。
3. 再判 `set(s) == set("123456789")`，等价于「无 0、无重复、1 到 9 齐全」。
4. 两个条件同时成立才返回 `True`。

以 n = 192 为例：`2*n = 384`、`3*n = 576`，拼出 `s = "192384576"`，长度 9；`set(s)` 是 `{'1','2','3','4','5','6','7','8','9'}`，与 `set("123456789")` 相等，返回 `True`。

```python
s = str(n) + str(2 * n) + str(3 * n)
if len(s) != 9:
    return False
return set(s) == set("123456789")
```

关键点：长度 9 这个前置判断不是可选的优化，而是正确性的一部分。n = 100 时拼出 `"100200300"` 长度也是 9，但 `set(s)` 只有 `{'1','0','2','3'}`，集合比较把它挡掉；而像 n = 999 拼出 `"99919982997"` 长度 11，长度判断先挡掉，不必再算集合。

## 复杂度
时间：O(1)，拼接固定 3 个数、最多 9 位，与 n 大小无关。
空间：O(1)，只开一个长度 ≤9 的字符串和一个 ≤9 元素的集合。

## 易错点
- n = 100 → 拼出 `"100200300"` 长度正好 9，若只判长度就误判 `True` → 必须用集合比较或显式排除 `'0'`，不能只靠 `len(s) == 9`。
- n = 999 → `3*n = 2997` 使拼接长度变成 11，若先做 `set(s) == set("123456789")` 再判长度，逻辑上仍对但多算一次；若把长度判断写成 `len(s) <= 9` 就会漏掉超长情况 → 用 `!= 9` 而不是 `<= 9`。

## 如果面试官追问
问：若 n 范围放宽到 1 到 10**4，方法还成立吗？
答：不成立，拼接长度不再固定为 9，需改成「拼接后长度恰为 9 且集合等于 1 到 9」，或按位数枚举候选 n。
