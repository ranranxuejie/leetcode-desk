## 一句话思路
把代价拆成「前缀和 × 段 cost 和」加「k·i × 段 cost 和」，用 DP + 斜率优化（凸包）降到 O(n log n)。

## 怎么做
1. 记 `P[i]=sum(nums[:i])`、`C[i]=sum(cost[:i])`。第 i 段 `[l..r]` 的代价 = `(P[r+1]+k*i)*(C[r+1]-C[l])`。
2. 设 `dp[r]` 为前 r 个元素的最小代价，则 `dp[r] = min_{l<r} dp[l] + (P[r]+k*i)*(C[r]-C[l])`，其中 i 是段号，但 i 依赖 l 的段数——这是关键：把 `k*i` 展开成对每个切点累加，等价于每多切一刀就多付 `k*C[n]` 的固定增量（因为 `k*i` 乘的是该段 cost 和，总和恰为 `k*C[n]` 每刀）。
3. 于是 `dp[r] = min_{l<r} dp[l] + P[r]*(C[r]-C[l]) + k*C[n]`（每切一刀加一次），整理成 `dp[r] = P[r]*C[r] + k*C[n] + min_l (dp[l] - P[r]*C[l])`，对 l 是直线 `y = -C[l]*x + dp[l]` 在 `x=P[r]` 处取值，斜率 `-C[l]` 单调递减、查询 `P[r]` 单调递增，用单调队列维护下凸包。
4. 以示例 1 为例：`P=[0,3,4,8]`、`C=[0,4,10,16]`、`k*C[3]=16`。算 `dp[2]`（前两元素）：候选 l=0 给 `0+4*10+16=56`，l=1 给 `dp[1]+P[2]*(C[2]-C[1])+16`，`dp[1]=3*4+16=28`，得 `28+4*6+16=68`，取 56；最终 `dp[3]=110`。

```python
P = [0]; C = [0]
for a, b in zip(nums, cost):
    P.append(P[-1] + a); C.append(C[-1] + b)
add = k * C[n]
dp = [0] * (n + 1)
# 凸包存下标，斜率 -C[l] 递减，查询 x=P[r] 递增
hull = [0]
for r in range(1, n + 1):
    x = P[r]
    while len(hull) > 1 and \
        (dp[hull[1]] - P[r]*C[hull[1]]) <= (dp[hull[0]] - P[r]*C[hull[0]]):
        hull.pop(0)
    l = hull[0]
    dp[r] = dp[l] + P[r]*(C[r]-C[l]) + add
    while len(hull) > 1 and bad(hull[-2], hull[-1], r):
        hull.pop()
    hull.append(r)
```

## 复杂度
时间 O(n)：每个下标入队出队各一次，凸包查询均摊 O(1)。
空间 O(n)：`P`、`C`、`dp` 各 n+1，凸包队列最多 n。

## 易错点
- 把 `k*i` 当成每段独立乘 `k*段号` 直接写进 DP，会漏掉「段号随切点变化」的耦合；正确做法是把它摊成每切一刀加 `k*C[n]`，`dp` 里只加一次 `add`。
- 凸包弹出条件写成严格 `<` 而非 `<=`：当 `P[r]` 与某条线斜率相等（如示例 1 中 `P[2]=4` 恰好等于某 `C[l]`）时会保留冗余点，后续 `bad` 判断退化，最坏 O(n²)；用 `<=` 保证斜率相等时也弹出。

## 如果面试官追问
问：n 涨到 1e5 还这么写？答：凸包查询 `P[r]` 单调，仍 O(n)；若 `nums` 有负数导致 `P` 不单调，改用二分查凸包，O(n log n)。
