## 一句话思路
答案 = 总和 − 每个元素能降到的最大值之和，而每个 nums[i] 只能降到「能整除它的最小数组元素」，用倍数枚举筛出这个值。

## 怎么做
1. 统计每个值是否出现（`present`），并取 `m = min(nums)`，因为任何替换链的终点必然是最小值。
2. 对每个出现过的值 `d`，用倍数枚举把 `d, 2d, 3d, ...` 中「在数组里出现过」的值的 `best` 更新为 `d`；从小到大枚举，第一次写入的就是最小可行除数。
3. 对每个 `nums[i]`，若 `best[nums[i]]` 存在则累加它，否则累加 `nums[i]` 本身。
4. 返回总和。

以 `nums = [4,2,8,3]` 为例：`m = 2`，枚举 `d = 2` 时把 `best[4]`、`best[8]` 都写成 2；`d = 3` 时 `best[3]` 保持 3（3 的倍数 6、9 不在数组里）。最终 `2 + 2 + 2 + 3 = 9`。

```python
m = min(nums)
present = set(nums)
best = {}
for d in sorted(present):
    for v in range(d, max(nums) + 1, d):
        if v in present and v not in best:
            best[v] = d
total = 0
for x in nums:
    total += best.get(x, x)
return total
```

注意 `best` 只对「数组里真实出现过的值」有意义，`nums` 有重复元素时直接查表复用即可，不必逐个重算。

## 复杂度
时间：O(M log M)，M = max(nums) ≤ 10^5，倍数枚举总量是 M/1 + M/2 + … = M log M。
空间：O(M)，`present` 与 `best` 各存至多 M 个键。

## 易错点
- 输入 `[6, 10, 15]` → 误以为 6 能降到 10 或 15（6 % 10 ≠ 0）→ 正确做法是只允许「大数 % 小数 == 0」，`best` 只由更小的 `d` 写入，`best[6]` 应为空，答案 31。
- 输入 `[2, 4, 8]` → 只把 4 降到 2、忘了 8 也能一步降到 2 → 正确做法是倍数枚举覆盖所有倍数，`best[8] = 2`，答案 6 而非 10。

## 如果面试官追问
问：若 nums[i] 上限升到 10^9 怎么办？答：倍数枚举退化，改用对每个值枚举其约数（试除到 √x），复杂度 O(n√M)。
