## 一句话思路
每次 `shortestPath` 现跑一遍 Dijkstra（堆优化），因为 `addEdge` 只加边不改结构，重算最省事。

## 怎么做
1. 构造函数把 `edges` 存进邻接表 `g = [[] for _ in range(n)]`，`addEdge` 直接 `g[f].append((t, c))`。
2. `shortestPath` 里开 `dist = [inf]*n`，`dist[node1] = 0`，堆初始放 `(0, node1)`。
3. 弹出 `(d, u)` 时若 `d > dist[u]` 就跳过（惰性删除），否则遍历 `g[u]` 松弛。
4. 弹出 `u == node2` 即可提前返回 `d`；堆空仍未到则返回 `-1`。

用官方示例第一次 `shortestPath(3, 2)`：初始 `dist[3]=0`，弹出 3 松弛出 `dist[0]=3`；弹出 0 松弛出 `dist[1]=5`、`dist[2]=8`；弹出 1 松弛出 `dist[2]=min(8,5+1)=6`；弹出 2 返回 6。注意 `dist[2]` 先被写成 8 后被改成 6，堆里两条 `(8,2)`、`(6,2)` 都还在，靠 `d > dist[u]` 丢掉旧的。

```python
import heapq
def shortestPath(self, s, t):
    dist = [float('inf')] * self.n
    dist[s] = 0
    pq = [(0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        if u == t:
            return d
        for v, w in self.g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return -1
```

## 复杂度
时间：每次查询 O((n + E) log n)，E 含新增边，log 来自堆。
空间：O(n + E)，`dist` 数组加邻接表和堆。

## 易错点
- `addEdge` 后忘了新边要参与后续查询 → 若把 `edges` 只存成列表、查询时才建图，容易漏掉后加的边 → 正确做法是构造时就建好 `g`，`addEdge` 直接往 `g[f]` 追加。
- 提前返回写成弹出即返回但没判 `d > dist[u]` → 示例中 `(8,2)` 先于 `(6,2)` 出堆时会返回 8 → 必须先 `if d > dist[u]: continue` 再判 `u == t`。

## 如果面试官追问
若 `addEdge` 和查询都放大到 10^4 次，还每次重跑 Dijkstra 吗？答：可缓存各源点的 `dist`，加边时只失效受影响的源点，或改用 Floyd 增量更新。
