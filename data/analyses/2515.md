## 一句话思路
枚举每个等于 target 的下标 i，取 `min(|i-startIndex|, n-|i-startIndex|)` 的最小值，因为环形上只有左右两条路。

## 怎么做
1. 令 `n = len(words)`，初始化 `ans = n`（环形上最大距离不超过 n-1，用 n 当哨兵）。
2. 遍历 `i, w in enumerate(words)`，只处理 `w == target` 的下标。
3. 对每个命中下标算 `d = abs(i - startIndex)`，再取 `min(d, n - d)` 更新 `ans`。
4. 循环结束若 `ans == n` 说明没命中过，返回 -1，否则返回 `ans`。

以示例 1 为例：`words = ["hello","i","am","leetcode","hello"]`，`n = 5`，`startIndex = 1`。命中下标是 0 和 4。i=0 时 `d = abs(0-1) = 1`，`min(1, 5-1) = 1`；i=4 时 `d = abs(4-1) = 3`，`min(3, 5-3) = 2`。`ans` 最终为 1，与输出一致——注意 i=4 向左走只要 2 步，但 i=0 向左 1 步更近，两个候选都要算。

```python
n = len(words)
ans = n
for i, w in enumerate(words):
    if w == target:
        d = abs(i - startIndex)
        ans = min(ans, d, n - d)
return -1 if ans == n else ans
```

关键点：`n - d` 就是「反方向绕过去」的步数，不需要真的模拟走 `(i-1+n) % n`。

## 复杂度
时间：O(n)，遍历 words 一次，每次比较字符串（长度 ≤100，视作常数）。
空间：O(1)，只开了 `n`、`ans`、`i`、`w`、`d` 几个标量。

## 易错点
- 输入 `words = ["a","b","leetcode"], target = "leetcode", startIndex = 0`：只算 `abs(2-0) = 2` 会错成 2，正确答案是 1。必须同时取 `n - d = 3 - 2 = 1`，两个方向都算再取 min。
- 输入 `words = ["i","eat","leetcode"], target = "ate", startIndex = 0`：若把 `ans` 初始化成 0 或 `2**31 - 1` 后忘记判空，会返回哨兵值而不是 -1。正确做法是用 `ans = n` 当哨兵，最后 `ans == n` 就返回 -1——因为真实距离最大只到 n-1，不可能等于 n。

## 如果面试官追问
问：如果 words 长度到 10^6、且要多次查询不同 target 怎么办？
答：预处理一个 `dict[字符串] -> 有序下标列表`，每次查询在列表里二分找 startIndex 的左右邻居，O(log k) 出答案。
