## 一句话思路
排序后从左往右扫，把每个数抬到「前一个数 + 1」以上，抬多少就累加多少，因为小的数先占位不会比大的数先占位更差。

## 怎么做
1. 对 `nums` 排序，让可能冲突的值相邻。
2. 维护 `prev = nums[0]` 和 `ans = 0`，从下标 1 开始遍历。
3. 若 `nums[i] <= prev`，需要抬到 `prev + 1`，代价 `prev + 1 - nums[i]` 累加进 `ans`，并把 `prev` 更新为 `prev + 1`；否则 `prev = nums[i]`。
4. 返回 `ans`。

以 `nums = [3,2,1,2,1,7]` 为例，排序后是 `[1,1,2,2,3,7]`。`prev` 从 1 开始：第二个 1 抬到 2，`ans = 1`，`prev = 2`；接着的 2 抬到 3，`ans = 2`，`prev = 3`；下一个 2 抬到 4，`ans = 4`，`prev = 4`；3 抬到 5，`ans = 6`，`prev = 5`；7 大于 5，直接 `prev = 7`。最终 `ans = 6`，与示例一致。

```python
nums.sort()
prev, ans = nums[0], 0
for x in nums[1:]:
    if x <= prev:
        ans += prev + 1 - x
        prev += 1
    else:
        prev = x
return ans
```

关键点：`prev` 记录的是「上一个位置最终落成的值」，不是原数组里的值，所以连续冲突时 `prev` 会一路加 1，代价自然累加。

## 复杂度
时间：排序 `O(n log n)` 主导，扫描 `O(n)`，n 为 `len(nums)`。
空间：排序额外 `O(log n)` 栈空间，其余只用了 `prev`、`ans` 两个变量。

## 易错点
- 输入 `[1,1,1]` → 若只写 `ans += prev + 1 - x` 却忘了 `prev += 1`，三个 1 都按抬到 2 算，得 3，正确是 `1+2=3` 看似对但 `[2,2,2]` 会错成 3 而正确是 `1+2+3=6` → 必须每轮把 `prev` 自增 1。
- 输入 `[0,2,2]` → 若把 `prev` 初始化为 0 而不是 `nums[0]`，第一个 0 会被误判为冲突 → `prev` 必须取排序后的首元素。

## 如果面试官追问
问：`nums[i]` 上限放大到 `10^9` 还能排序吗？答：能，`O(n log n)` 与值域无关；若值域小（如 ≤ `10^5`）可改用计数数组做到 `O(n + V)`。
