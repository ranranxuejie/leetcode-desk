## 一句话思路
排序后从最大端每隔两个取一个累加，即取下标 `n-2, n-4, ...` 共 `n/3` 个元素。

## 怎么做
1. 把 `nums` 升序排序，让大数集中在右端。
2. 每组三个数里，中位数最多只能是组内第二大，所以每次让一个「炮灰」当最大值、一个当最小值，中位数取剩下的那个。
3. 从右往左，跳过最大的那个当炮灰，取 `nums[n-2]` 作中位数，再跳两个，取 `nums[n-4]`，共取 `n//3` 次。
4. 用最小的 `n//3` 个元素当每组的最小值，它们不贡献答案。

以 `nums = [1,1,10,10,10,10]` 为例：排序后不变，`n=6`，取下标 `4` 和 `2`，即 `10 + 10 = 20`。第一个中位数 `nums[4]=10`，此时最大值 `nums[5]=10` 当炮灰，最小值 `nums[0]=1` 当垫底。

```python
nums.sort()
n = len(nums)
total = 0
i = n - 2
for _ in range(n // 3):
    total += nums[i]
    i -= 2
return total
```

关键就一行：`i` 从 `n-2` 起步，每次减 2，循环 `n//3` 次。

## 复杂度
时间：排序 `O(n log n)`，遍历 `O(n)`，总 `O(n log n)`。
空间：排序额外 `O(log n)` 栈空间，无其他数组。

## 易错点
- 输入 `[2,1,3,2,1,3]` 若从下标 `n-1` 开始取会得到 `3+2=5` 看似对，但换成 `[1,1,10,10,10,10]` 会取到 `nums[5]=10` 和 `nums[3]=10` 得 20 也碰巧对；真正翻车在 `[1,2,3,4,5,6]`，从 `n-1` 取会得 `6+4=10`，正确应是 `nums[4]+nums[2]=5+3=8`。必须从 `n-2` 起。
- 循环次数写成 `n//2` 或 `n//3+1` 会越界或漏取；`n=3` 时只取一次 `nums[1]`，写成 `range(n//3+1)` 会多取 `nums[-1]` 导致答案偏大。

## 如果面试官追问
问：如果要求输出每组的具体三元组怎么办？
答：排序后把最小端 `n//3` 个元素依次配给每个中位数，剩余最大端元素当炮灰即可。
