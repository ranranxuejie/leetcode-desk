## 一句话思路
把 nums 丢进 set，再用哑节点统一处理删头节点的情况，一趟遍历跳过命中集合的节点。

## 怎么做
1. 用 `set(nums)` 建哈希集合，查询 O(1)。
2. 建哑节点 `dummy.next = head`，`prev = dummy`，避免单独判断头节点被删。
3. 遍历 `cur = head`：若 `cur.val in s` 则 `prev.next = cur.next`，否则 `prev = cur`；每步 `cur = cur.next`。
4. 返回 `dummy.next`。

以示例 2 为例：`nums=[1]`，`s={1}`，链表 `1→2→1→2→1→2`。`cur` 指向第一个 1 时命中，`prev` 仍是 dummy，执行 `dummy.next = cur.next`，头节点被摘掉；随后 `prev` 停在第一个 2 上，后面两个 1 依次被 `prev.next = cur.next` 跳过，最终 `dummy.next` 指向 `2→2→2`。

```python
s = set(nums)
dummy = ListNode(0, head)
prev, cur = dummy, head
while cur:
    if cur.val in s:
        prev.next = cur.next
    else:
        prev = cur
    cur = cur.next
return dummy.next
```

关键点：`prev` 只在「保留」时前移，命中时不动，这样连续多个待删节点（如示例 2 的 `1,2,1` 中两个 1 之间夹的 2 被保留后，再遇 1）也能正确接上。

## 复杂度
时间 O(n + m)：n 为链表长度（每个节点访问一次），m 为 nums 长度（建集合）。
空间 O(m)：额外开了一个大小为 m 的 set，哑节点是 O(1)。

## 易错点
- 头节点本身在 nums 中（如示例 2 的 `head.val=1`）→ 若直接 `while head.val in s: head = head.next` 再遍历，容易漏掉「删完后新头又被删」的连锁，或忘记更新返回值 → 用 dummy 统一处理，返回 `dummy.next`。
- 连续待删节点（如 `nums=[1,2]`、链表 `1→2→3`）→ 若命中后写成 `prev = cur` 再 `cur = cur.next`，`prev` 会指向已删节点，导致 `prev.next` 挂错 → 命中分支里 `prev` 必须保持不动。

## 如果面试官追问
问：若 nums 很大而链表很短，怎么优化？
答：先遍历链表把值收进一个 set，再与 nums 求交集，只对交集建集合，查询规模取两者较小者。
