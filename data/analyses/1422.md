## 一句话思路
枚举分割点 i，用「左边 0 的个数 + 右边 1 的个数」直接算分，前缀统计让每次 O(1)。

## 怎么做
1. 先数出全串 1 的总数 `total_ones`，它等于 i=0 时右半部分的 1 数。
2. 从左往右扫 i 从 0 到 n-2（保证右半非空），维护 `left_zeros`（s[0..i] 中 0 的个数）和 `right_ones`（s[i+1..] 中 1 的个数）。
3. 每步得分 `left_zeros + right_ones`，取最大值。
4. 关键转移：i 右移一位时，若 s[i] 是 '0' 则 `left_zeros += 1`，若 s[i] 是 '1' 则 `right_ones -= 1`（这个 1 从右半挪进了左半）。

以 s = "011101" 为例，`total_ones = 4`。i=0 时 s[0]='0'，`left_zeros=1`、`right_ones=4`，得分 5；i=1 时 s[1]='1'，`right_ones` 降到 3，`left_zeros` 仍 1，得分 4。最大值 5 在 i=0 取到。

```python
total_ones = s.count('1')
left_zeros = 0
right_ones = total_ones
best = 0
for i in range(len(s) - 1):
    if s[i] == '0':
        left_zeros += 1
    else:
        right_ones -= 1
    best = max(best, left_zeros + right_ones)
return best
```

注意循环里先更新再算分：i 位置字符归左半，所以 s[i] 的贡献要在算分前结算。

## 复杂度
时间 O(n)：一次 `count` 加一次单层扫描，每个字符只处理一次。
空间 O(1)：只开了 `total_ones`、`left_zeros`、`right_ones`、`best` 四个整数。

## 易错点
- 输入 "1111" → 若循环写成 `range(len(s))` 让 i 走到 n-1，右半为空串，`right_ones` 减到 0，得分 0，答案错成 0 或 1；正确做法是 `range(len(s) - 1)`，保证右半至少一个字符，此例 i=0 得 0+3=3。
- 输入 "00" → 若把更新顺序写成「先算分再更新」，i=0 时 `left_zeros` 还是 0，得分 0+0=0，漏掉正确答案 1；正确做法是先按 s[i] 更新 `left_zeros`/`right_ones`，再取 max，此例 i=0 得 1+0=1。

## 如果面试官追问
问：若要求返回取得最大得分的分割点（左半长度），怎么改？
答：把 `best = max(...)` 换成显式比较，命中时记录 `i + 1` 即可，仍是 O(n)。
