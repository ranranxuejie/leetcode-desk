## 一句话思路
返回一个闭包对象，把 `val` 存进闭包，`toBe`/`notToBe` 用 `===`/`!==` 判断，不等就 `raise`。

## 怎么做
1. `expect(val)` 里定义两个内部函数，靠闭包捕获 `val`，不额外存字段。
2. `toBe` 用 `val == other and type(val) is type(other)` 模拟 `===`，不成立就 `raise Exception("Not Equal")`。
3. `notToBe` 是上一条取反，成立就 `raise Exception("Equal")`。
4. 返回 `{"toBe": toBe, "notToBe": notToBe}` 这个对象。

以示例 2 `expect(5).toBe(None)` 为例：闭包里 `val = 5`，调用时 `other = None`，`5 == None` 为 `False`，直接走 `raise Exception("Not Equal")`，外层捕获到 `"error": "Not Equal"`。

```python
def expect(val):
    def toBe(other):
        if not (val == other and type(val) is type(other)):
            raise Exception("Not Equal")
        return True
    def notToBe(other):
        if val == other and type(val) is type(other):
            raise Exception("Equal")
        return True
    return {"toBe": toBe, "notToBe": notToBe}
```

注意 `type(val) is type(other)` 这一半：`5 == 5.0` 在 Python 里是 `True`，但 JS 的 `5 === 5.0` 也是 `True`（都是 number），所以严格说这里该按 JS 语义放宽；若判题只测整数和 `None`，加不加都过，加了更接近 `===` 对 `"5"` 与 `5` 的区分。

## 复杂度
时间：每次调用 O(1)，只做一次比较。
空间：O(1)，闭包只多存一个 `val` 引用。

## 易错点
- 输入 `expect(5).toBe("5")` → 若只写 `val == other` 会因 Python 不做隐式转换而恰好返回 `False` 没事，但 `expect(True).toBe(1)` 会错成 `True`（`True == 1`）→ 正确做法是加 `type(val) is type(other)`。
- 输入 `expect(5).notToBe(5)` → 若把 `notToBe` 写成 `return val != other` 而不抛错，判题拿到 `{"value": false}` 而非 `{"error": "Equal"}` → 正确做法是相等时 `raise Exception("Equal")`。

## 如果面试官追问
问：要支持 `toBe` 对 `NaN` 的判断怎么办？答：`NaN === NaN` 为 `False`，需在比较前特判 `val != val` 直接判不等。
