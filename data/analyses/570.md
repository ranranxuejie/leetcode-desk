## 一句话思路
按 `managerId` 分组计数，筛出计数 ≥5 的 id，再回表取 `name`。

## 怎么做
1. 对 `Employee` 按 `managerId` 做 `GROUP BY`，`COUNT(*)` 得到每个经理的直接下属数。
2. 用 `HAVING COUNT(*) >= 5` 过滤，得到合格经理的 id 集合。
3. 把结果与原表按 `e.id = t.managerId` 连接，取出 `name`。

以官方示例走一遍：`managerId` 分组后只有 `101 -> 6` 这一组非空（102、103、104、105、106 共 5 行在 A 部门，加上 Ron 共 6 行），`6 >= 5` 成立，所以中间结果 `t.managerId = 101`；回表 `id=101` 得 `name='John'`。注意 `101` 自己那行 `managerId` 是 `None`，不参与任何分组，所以不会被误算成下属。

```python
# df: Employee
cnt = df.groupby("managerId").size().reset_index(name="c")
cnt = cnt[cnt["c"] >= 5]
ans = df.merge(cnt, left_on="id", right_on="managerId")[["name"]]
```

SQL 等价写法：

```python
# SELECT e.name FROM Employee e
# JOIN (SELECT managerId FROM Employee
#       GROUP BY managerId HAVING COUNT(*) >= 5) t
#   ON e.id = t.managerId
```

关键点：分组键是 `managerId` 而不是 `id`；过滤发生在聚合之后，所以必须用 `HAVING` 而不是 `WHERE`——`WHERE` 在分组前执行，看不到 `COUNT(*)`。

## 复杂度
时间 O(n)：一次分组扫描 n 行，一次连接再扫 n 行。
空间 O(k)：额外存 k 个合格经理 id，k ≤ n。

## 易错点
- 把过滤写成 `WHERE COUNT(*) >= 5`：聚合函数不能出现在 `WHERE` 里，SQL 直接报错；正确做法是用 `HAVING`，或先聚合出子表再在外层 `WHERE c >= 5`。
- 用 `COUNT(managerId)` 而不是 `COUNT(*)`：本题 `managerId` 为 `None` 的行是顶层员工，`COUNT(managerId)` 会跳过它们，但分组后每组内 `managerId` 都非空，两者结果相同——真正的坑是漏掉 `GROUP BY` 直接 `COUNT(*)`，会得到全表 6 行而误判 John 合格，正确做法是先按 `managerId` 分组再计数。

## 如果面试官追问
问：如果要求返回经理的 `id` 和下属数，且按下属数降序？
答：把 `HAVING` 子查询的 `managerId, COUNT(*) AS c` 一起选出，外层 `ORDER BY c DESC` 即可。
