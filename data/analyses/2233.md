## 一句话思路
每次把当前最小值加 1，用最小堆维护，因为乘积对短板最敏感。

## 怎么做
1. 把 `nums` 全部 `heapify` 成最小堆。
2. 循环 `k` 次：`heappop` 出最小值 `x`，`heappush` 回 `x + 1`。
3. 循环结束后把堆里所有元素相乘，每步对 `10**9 + 7` 取余。

以 `nums = [0,4], k = 5` 为例：堆顶先是 0，弹出压回 1；再弹出 1 压回 2……5 次后堆内是 `[4,5]`，乘积 20。关键中间值：第 1 次操作后堆为 `[1,4]`，第 5 次后为 `[4,5]`。

```python
import heapq

def maximumProduct(nums, k):
    heapq.heapify(nums)
    for _ in range(k):
        x = heapq.heappop(nums)
        heapq.heappush(nums, x + 1)
    ans = 1
    for v in nums:
        ans = ans * v % (10**9 + 7)
    return ans
```

注意 `k` 最大 1e5，逐次操作是 `O(k log n)`，可接受；不要试图一次算出每个元素加多少再统一乘，那样反而容易在「多个相等最小值」上分错。

## 复杂度
时间：`O(n + k log n)`，`n` 来自建堆和最后遍历，`log n` 来自每次堆操作。
空间：`O(1)` 额外（原地 heapify），堆复用 `nums` 本身。

## 易错点
- 输入 `nums = [0,4], k = 5` 若先乘再取余、或对每个元素单独取余后相乘，结果虽对但若中途用 `ans *= v` 不取余，Python 大整数会变慢；正确做法是每乘一个就 `% (10**9+7)`。
- 输入 `nums = [6,3,3,2], k = 2` 若误以为「加最大的数」更优，会把 6 加成 8 得 `8*3*3*2=144`；正确做法是加最小值，得 `6*4*3*3=216`。

## 如果面试官追问
问：`k` 扩大到 1e9 怎么办？
答：先排序，用「水位线」批量抬平最小值，剩余 `k` 均分到各元素，再算乘积。
