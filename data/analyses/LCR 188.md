## 一句话思路
一次遍历维护「历史最低价」`min_price`，每天用 `prices[i] - min_price` 更新最大利润，因为卖出日固定时最优买入价就是它之前的最低价。

## 怎么做
1. 初始化 `min_price = prices[0]`、`best = 0`，`best` 取 0 直接覆盖了「不能获利返回 0」。
2. 从 `i = 1` 开始遍历，每步先用当前价减 `min_price` 更新 `best`，再更新 `min_price`。
3. 顺序不能反：先算利润再更新最低价，否则当天买当天卖会算出 0 甚至负数干扰判断。

拿示例 1 `[3, 6, 2, 9, 8, 5]` 走一遍关键中间值：`i=1` 时 `best = 6-3 = 3`，`min_price` 仍为 3；`i=2` 时 `2-3 = -1` 不更新 `best`，但 `min_price` 降到 2；`i=3` 时 `9-2 = 7`，`best` 变成 7，之后 `8-2=6`、`5-2=3` 都超不过它，最终返回 7。

```python
min_price = prices[0]
best = 0
for i in range(1, len(prices)):
    best = max(best, prices[i] - min_price)
    min_price = min(min_price, prices[i])
return best
```

注意 `prices` 长度为 0 时 `prices[0]` 会越界，提示里 `0 <= prices.length`，所以入口要先判空返回 0。

## 复杂度
时间：O(n)，`for` 循环扫一遍 `prices`，每次 O(1)。
空间：O(1)，只开了 `min_price` 和 `best` 两个标量。

## 易错点
- 输入 `[7, 6, 4, 3, 1]` 全程递减 → 若把 `best` 初始化成 `-inf` 或 `prices[1]-prices[0]`，会返回负数 → 正确做法是 `best = 0`，让「不能获利」自然落到 0。
- 输入 `[2, 4, 1]` → 若先更新 `min_price` 再算利润，`i=1` 时 `min_price` 还是 2 没问题，但若写成先 `min_price = min(...)` 再算，遇到 `[3, 1, 4]` 在 `i=1` 会把 `min_price` 压到 1，`i=2` 算 `4-1=3` 看似对，可一旦当天就是最低价（如 `[5, 1]`）会算出 `1-1=0` 掩盖真实情况 → 正确做法是固定「先算 `prices[i] - min_price`，后更新 `min_price`」。

## 如果面试官追问
问：要求返回买入和卖出的具体下标怎么办？
答：多存 `buy_day`，在 `best` 被刷新时同步记下 `buy_day` 和当前 `i`，其余逻辑不变。
