## 一句话思路
边遍历 `gain` 边累加当前海拔，用 `max` 记录累加过程中的峰值，起点 0 也要参与比较。

## 怎么做
1. 初始化 `alt = 0`（点 0 的海拔）和 `best = 0`（答案至少是起点）。
2. 遍历 `gain`，每读一个 `g` 就执行 `alt += g`，得到下一个点的海拔。
3. 每次更新后执行 `best = max(best, alt)`，把当前点纳入比较。
4. 遍历结束返回 `best`。

以 `gain = [-5,1,5,0,-7]` 为例，关键中间值：`alt` 依次为 `-5, -4, 1, 1, -6`，`best` 依次为 `0, 0, 1, 1, 1`，最终返回 1。

```python
alt = 0
best = 0
for g in gain:
    alt += g
    if alt > best:
        best = alt
return best
```

`best` 初值必须是 0 而不是 `gain[0]`：示例 2 的 `gain = [-4,-3,-2,-1,4,3,2]` 全程海拔为负，最高点就是起点 0，若用 `gain[0] = -4` 初始化会返回 -1。

## 复杂度
时间：O(n)，`gain` 每个元素只被加一次。
空间：O(1)，只开了 `alt`、`best` 两个变量，没有存海拔数组。

## 易错点
- `gain` 全为负数（如 `[-4,-3,-2,-1,4,3,2]`）→ 若把 `best` 初始化为 `gain[0]` 或 `-2**31`，会返回 -1 或负值 → 正确做法是 `best = 0`，因为点 0 海拔为 0 本身就是候选最高点。
- 把 `best` 更新写在循环外或只在末尾取 `alt` → 对 `[-5,1,5,0,-7]` 会返回 -6（终点海拔）而非 1 → 正确做法是每步累加后立刻比较，峰值可能出现在中途。

## 如果面试官追问
问：如果要求返回最高海拔对应的点下标（多个取最小）？
答：多存一个 `best_idx`，`alt > best` 严格大于时才更新，天然保留最早出现的下标。
