## 一句话思路
用双指针从两端向中间收缩，每步移动较矮的一侧，因为该侧的水位已被对侧更高的柱子封顶。

## 怎么做
1. 初始化 `left=0, right=len(height)-1, left_max=0, right_max=0, ans=0`。
2. 当 `left < right` 时，比较 `height[left]` 与 `height[right]`，移动较矮的那一端。
3. 若移动左端：`left_max = max(left_max, height[left])`，累加 `left_max - height[left]`；右端对称处理。
4. 返回 `ans`。

以官方示例 `[0,1,0,2,1,0,1,3,2,1,2,1]` 为例，走到 `left=3`（`height[3]=2`）时，`left_max` 从 1 更新为 2，`ans` 累加 `2-2=0`；继续到 `left=4`（`height[4]=1`），`left_max` 仍为 2，`ans += 2-1=1`，此时 `ans` 累计到 1。

```python
left, right = 0, len(height) - 1
left_max = right_max = ans = 0
while left < right:
    if height[left] < height[right]:
        left_max = max(left_max, height[left])
        ans += left_max - height[left]
        left += 1
    else:
        right_max = max(right_max, height[right])
        ans += right_max - height[right]
        right -= 1
return ans
```

## 复杂度
时间：O(n)，双指针各走一遍，每个下标只被访问一次。
空间：O(1)，只开了 `left/right/left_max/right_max/ans` 五个变量。

## 易错点
- 输入 `[2,0,2]` → 若先更新 `left_max` 再累加，`left=1` 时 `left_max=2`，`ans += 2-0=2`，正确；但若写成 `ans += left_max - height[left]` 之前忘了 `max`，`left_max` 停在 0，会错成 0。必须先 `max` 再累加。
- 输入 `[5,4,1,2]` → 若固定先动左指针，`left=1` 时 `height[1]=4 < height[3]=2` 不成立，会误判；正确做法是每步比较 `height[left]` 与 `height[right]` 决定动哪边，不能写死方向。

## 如果面试官追问
问：若要求输出每个位置的水量数组而非总和？答：把 `ans += ...` 改成 `water[i] = left_max - height[i]`，双指针照样 O(n)。
