## 一句话思路
排序后双指针：小令牌朝上换分，分不够时用最大令牌朝下换能量，全程记录分数峰值。

## 怎么做
1. 先 `tokens.sort()`，让 `tokens[l]` 是最小值、`tokens[r]` 是最大值。
2. 若 `power >= tokens[l]`，就朝上：`power -= tokens[l]`，`score += 1`，`l += 1`，并更新 `ans = max(ans, score)`。
3. 否则若 `score >= 1`，就朝下：`power += tokens[r]`，`score -= 1`，`r -= 1`。
4. 两者都不满足（`power < tokens[l]` 且 `score == 0`）时退出，返回 `ans`。

以示例 3 的 `tokens = [100,200,300,400], power = 200` 为例：先朝上 100，`power=100, score=1`；此时 `100 < 200`，朝下 400 得 `power=500, score=0`；再朝上 200、300，最终 `power=0, score=2`，`ans=2`。

```python
tokens.sort()
l, r, score, ans = 0, len(tokens) - 1, 0, 0
while l <= r:
    if power >= tokens[l]:
        power -= tokens[l]
        score += 1
        l += 1
        ans = max(ans, score)
    elif score >= 1:
        power += tokens[r]
        score -= 1
        r -= 1
    else:
        break
return ans
```

关键点：`ans` 只在朝上后更新，因为朝下必然让分数变小，峰值只可能出现在朝上之后。

## 复杂度
时间 O(n log n)：排序贡献 log n，双指针每步消耗一个令牌，共 O(n)。
空间 O(1)：除排序自身开销外只用了 `l, r, score, ans` 四个变量。

## 易错点
- `tokens = [100], power = 50`：若先判断「分不够就朝下」，`score=0` 无法朝下，会漏掉直接返回 0 的分支；正确做法是 `elif score >= 1` 才朝下，否则 `break`。
- `tokens = [100,200,300,400], power = 200`：若在朝下后也更新 `ans`，会把 `score=0` 记成答案；正确做法是只在朝上分支更新 `ans`，朝下只改 `power/score/r`。

## 如果面试官追问
问：要求输出具体操作序列怎么办？
答：在朝上/朝下分支各追加 `(i, "up")` 或 `(i, "down")` 到列表，最后返回 `ans` 和该列表即可。
