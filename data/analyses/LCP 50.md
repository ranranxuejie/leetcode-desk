## 一句话思路
按 operations 顺序原地模拟每次转移，最后对 gem 取 max 减 min。

## 怎么做
1. 遍历 `operations`，每次取出 `x, y = op`。
2. 算出转移量 `give = gem[x] // 2`，先减后加，顺序不能反。
3. 执行 `gem[x] -= give; gem[y] += give`。
4. 全部操作结束后返回 `max(gem) - min(gem)`。

拿示例 1 走一遍最关键的一步：初始 `gem = [3,1,2]`，第一次操作 `[0,2]`，`give = gem[0] // 2 = 3 // 2 = 1`，于是 `gem[0]` 变 `2`、`gem[2]` 变 `3`，得到 `[2,1,3]`。注意这里 `3 // 2` 是 `1` 不是 `1.5`，向下取整就靠 `//`。

```python
for x, y in operations:
    give = gem[x] // 2
    gem[x] -= give
    gem[y] += give
return max(gem) - min(gem)
```

关键点是 `give` 必须在修改 `gem[x]` **之前**算好。如果写成 `gem[x] -= gem[x] // 2` 再 `gem[y] += gem[x] // 2`，第二次读到的 `gem[x]` 已经是减半后的值，转移量就错了。示例 1 第一次操作若这么写，`gem[0]` 先变 `2`，再给 `gem[2]` 加 `2 // 2 = 1`，得到 `[2,1,3]` 碰巧一样；但换成 `gem = [5,0]`、操作 `[0,1]`，正确是 `give=2` 得 `[3,2]`，错误写法会得 `[3,1]`。所以先存 `give` 是必须的。

另外 `x == y` 的情况（题面没禁止）也要能自洽：`give = gem[x]//2`，减完再加回同一个位置，净效果是 `gem[x]` 变成 `gem[x] - give`，即向下取整后的一半，逻辑上仍是「自己给自己一半」，不会崩。

## 复杂度
时间 O(m + n)：m 为 `operations` 长度，每次 O(1)；n 为 `gem` 长度，最后扫一遍求极值。
空间 O(1)：只用了 `give`、`x`、`y` 几个标量，原地改 `gem`。

## 易错点
- `gem[x]` 为奇数时（如示例 1 的 `3`）→ 若用 `/` 得 `1.5` 再转 int 或直接浮点累加，`gem` 里混进浮点数，`max - min` 输出 `2.0` 而非 `2` → 一律用 `//`，全程保持 int。
- 先改 `gem[x]` 再算转移量 → 如 `gem=[5,0]`、`[0,1]` 会得 `[3,1]` 而不是 `[3,2]`，差 1 → 先把 `give = gem[x] // 2` 存下来，再分别做减和加。

## 如果面试官追问
若 `operations` 长度涨到 10^7 且要求输出最终数组而非差值，怎么办？答：仍是 O(m) 原地模拟，瓶颈在输入解析，可流式逐条读 `operations` 边读边改，不存整个列表。
