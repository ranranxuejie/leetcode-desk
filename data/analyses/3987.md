## 一句话思路
从左到右维护剩余资源 `res`，不够就一次性补足到够用，补的次数用等差数列求和算成本。

## 怎么做
1. 初始化 `res = k`、`used = 0`（已执行的操作次数）、`ans = 0`。
2. 遍历 `x in nums`：若 `res < x`，算出还差多少、需要补几次 `t = (x - res + k - 1) // k`。
3. 这 `t` 次操作的成本是 `used+1` 到 `used+t` 的等差和，累加进 `ans`，再更新 `res += t * k`、`used += t`。
4. 最后 `res -= x`，返回 `ans % (10**9 + 7)`。

以 `nums = [1,1,7,14], k = 4` 为例：处理到 `7` 时 `res = 2`，差 5，`t = (5+3)//4 = 2`，成本 `1+2 = 3`，`res` 变成 `2+8 = 10`，减 7 后剩 3；处理 `14` 时差 11，`t = (11+3)//4 = 3`，成本 `3+4+5 = 12`，合计 15。

```python
MOD = 10**9 + 7
res, used, ans = k, 0, 0
for x in nums:
    if res < x:
        t = (x - res + k - 1) // k
        ans += (used + 1 + used + t) * t // 2
        used += t
        res += t * k
    res -= x
return ans % MOD
```

关键点：`t` 必须一次算够，不能循环加 k，否则 `nums[i] = 10**9`、`k = 1` 时会退化成 10^9 次循环。

## 复杂度
时间 O(n)：每个元素只做常数次算术，`t` 用整除直接算出。
空间 O(1)：只开了 `res`、`used`、`ans` 三个标量。

## 易错点
- `nums = [10**9], k = 1` → 若写成 `while res < x: res += k` 逐次补，单元素就要循环 10^9 次直接超时 → 必须用 `(x - res + k - 1) // k` 一次算出次数。
- `nums = [1,1,7,14], k = 4` → 若把每次操作成本都记成 1，会得到 5 而不是 15 → 成本是第 `used+1` 到第 `used+t` 次，必须用 `used` 做偏移再等差求和。

## 如果面试官追问
问：如果要求输出每次操作发生在哪个下标、补了几次？
答：在 `t > 0` 的分支里把 `(i, t)` 追加到列表，其余逻辑不变，成本仍用等差和算。
