## 一句话思路
把「第 k 个剩余偶数」转成对候选值 x 的二分：x 以内被删的偶数个数 = 子数组里偶数的个数，用前缀和 O(1) 算。

## 怎么做
1. 预处理 `pre[i]` = `nums[0..i-1]` 中偶数的个数，于是 `nums[l..r]` 的偶数个数是 `pre[r+1] - pre[l]`。
2. 对每个查询，二分答案 x（x 是偶数），判定 `x//2 - removed >= k`，其中 `removed` 是区间内 ≤ x 的偶数个数。
3. 因为 `nums` 严格递增，区间内 ≤ x 的偶数就是 `nums[l..r]` 中 ≤ x 的偶数，用 `bisect_right(nums, x, l, r+1) - l` 定位后再数偶数——但更省事的是直接二分下标。

以示例 2 的 `[0,2,4]` 为例：`nums=[2,5,8]`，区间偶数 `[2,8]` 共 2 个。x=10 时 `10//2=5`，被删 2 个，剩 3 个 < 4；x=12 时 `12//2=6`，剩 4 个 ≥ 4，答案 12。

```python
from bisect import bisect_right
pre = [0] * (len(nums) + 1)
for i, v in enumerate(nums):
    pre[i + 1] = pre[i] + (v % 2 == 0)

for l, r, k in queries:
    lo, hi = 2, 2 * (k + (r - l + 1))  # 上界足够
    while lo < hi:
        mid = (lo + hi) // 2
        mid -= mid % 2  # 只考虑偶数
        j = bisect_right(nums, mid, l, r + 1)
        removed = pre[j] - pre[l]
        if mid // 2 - removed >= k:
            hi = mid
        else:
            lo = mid + 2
    ans.append(lo)
```

## 复杂度
时间：每个查询 O(log(值域) · log n)，二分答案 × 二分下标，共 O(q log V log n)。
空间：`pre` 数组 O(n)，其余 O(1)。

## 易错点
- 上界取小了：`k` 可达 1e9，若只取 `2*k` 而区间删了很多偶数，可能不够；应取 `2*(k + 区间长度)`，因为最多删 `r-l+1` 个偶数。
- 二分时 `mid` 是奇数：必须 `mid -= mid % 2` 归到偶数，否则 `mid//2` 与实际偶数个数错位，示例 1 的 `[1,1,2]` 会算成 5 而非 6。

## 如果面试官追问
若 `nums` 不再严格递增（有重复）？答：先去重排序，`pre` 与 `bisect` 逻辑不变，重复偶数只删一次。
