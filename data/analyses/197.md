## 一句话思路
用 `DATEDIFF` 自连接同一张表，把「昨天」变成 `w1.recordDate = w2.recordDate + 1 天` 的等值条件，再比温度。

## 怎么做
1. 把 Weather 起两个别名 `w1`（今天）、`w2`（昨天），自连接。
2. 连接条件用日期差 1 天，而不是 `id - 1`，因为 id 不保证连续。
3. 过滤 `w1.temperature > w2.temperature`，输出 `w1.id`。

以官方示例为例：`w1` 取 `(2, 2015-01-02, 25)` 时，只有 `w2 = (1, 2015-01-01, 10)` 满足 `DATEDIFF(w1.recordDate, w2.recordDate) = 1`，且 `25 > 10` 成立，所以 id=2 入选；`w1` 取 `(3, 2015-01-03, 20)` 时配到 `w2` 温度 25，`20 > 25` 为假，被过滤掉。

```python
# 关键几行（pandas 写法）
w2 = weather.rename(columns={"id": "id2", "recordDate": "d2", "temperature": "t2"})
m = w2.merge(weather, left_on="d2", right_on="recordDate")
m = m[(m["recordDate"] - m["d2"]).dt.days == 1]
res = m[m["temperature"] > m["t2"]][["id"]]
```

SQL 版核心就一句：`FROM Weather w1 JOIN Weather w2 ON DATEDIFF(w1.recordDate, w2.recordDate) = 1 AND w1.temperature > w2.temperature`，`SELECT w1.id`。

## 复杂度
时间：O(n²) 最坏，自连接两两配对；若按日期建索引可降到 O(n log n)。
空间：O(n) 存连接结果，n 为 Weather 行数。

## 易错点
- 用 `w1.id = w2.id + 1` 当「昨天」→ 示例里 id 恰好连续看不出问题，但一旦删掉 2015-01-02 这行，id=3 的昨天是 id=1 而非 id=2，会漏判或错判；必须用 `DATEDIFF(...) = 1` 或 `recordDate = d2 + INTERVAL 1 DAY`。
- 只写 `w1.temperature > w2.temperature` 而漏掉日期差条件 → 2015-01-04（30）会和 2015-01-01（10）配对成功，把 id=4 之外的错误组合也带出来，输出多出不该有的 id；两个条件必须同时出现在 ON 里。

## 如果面试官追问
问：如果要求「比前一个**有记录**的日期温度高」（允许跳空）？
答：把等值连接换成 `w2.recordDate = (SELECT MAX(recordDate) FROM Weather WHERE recordDate < w1.recordDate)`，用相关子查询取最近一天。
