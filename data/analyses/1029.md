## 一句话思路
按 `aCost - bCost` 升序排序，前 n 人去 a、后 n 人去 b，因为差值最小的那批人「去 a 相对最划算」。

## 怎么做
1. 对每个人算 `diff = aCost - bCost`，按 `diff` 升序排序。
2. 排序后前 `n = len(costs)//2` 人派去 a，累加 `aCost`。
3. 后 `n` 人派去 b，累加 `bCost`。
4. 返回总和。

拿示例 1 走一遍：`costs = [[10,20],[30,200],[400,50],[30,20]]`，差值分别是 `-10, -170, 350, 10`。升序后顺序为 `[30,200](-170)`、`[10,20](-10)`、`[30,20](10)`、`[400,50](350)`。前 2 人（`n=2`）去 a：`30 + 10 = 40`；后 2 人去 b：`20 + 50 = 70`；合计 `110`。注意第 4 人 `[30,20]` 差值只有 `10`，被排到后半段去 b，正是它 b 便宜。

```python
costs.sort(key=lambda c: c[0] - c[1])
n = len(costs) // 2
total = 0
for i, (a, b) in enumerate(costs):
    total += a if i < n else b
return total
```

关键那行是 `key=lambda c: c[0] - c[1]`：它把「去 a 比去 b 多花多少」量化成一个可排序的标量，排序后切一刀就满足人数约束。

## 复杂度
时间 O(n log n)：`sort` 对 2n 个元素排序贡献 log n，遍历贡献 n。
空间 O(1) 额外（不计排序内部开销），只用了 `n`、`total` 两个标量。

## 易错点
- 把 `diff` 降序排 → 示例 1 会得到前 2 人 `[400,50]`、`[30,20]` 去 a，总和 `400+30+200+10 = 640`，错成 640 而非 110。正确做法是升序：`diff` 越小（越负）说明去 a 越省，必须排前面。
- 用 `min(aCost, bCost)` 逐人贪心 → 示例 1 中第 1 人 `min(10,20)=10` 去 a、第 4 人 `min(30,20)=20` 去 b 看着对，但第 3 人 `min(400,50)=50` 去 b 后 a 只剩 1 人，人数约束被破坏。必须先排序再按位置切分，不能独立取小。

## 如果面试官追问
要求输出具体派谁去哪个城市怎么办？
排序后返回前 n 人的原始下标集合给 a、其余给 b，切分逻辑不变，只是累加时顺带记录 `i`。
