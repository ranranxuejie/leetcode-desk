## 一句话思路
自底向上 DFS 合并子树的 26 位标签计数，回溯时顺手读出 `cnt[labels[u]]` 就是答案。

## 怎么做
1. 把 `edges` 建成邻接表 `g`，因为是无向图，DFS 时要传 `parent` 防止走回父节点。
2. 对节点 `u` 开一个长度 26 的计数数组，先记上自己：`cnt[ord(labels[u]) - 97] = 1`。
3. 递归处理每个子节点 `v`，把 `v` 返回的计数数组逐位加到 `cnt` 上，26 次加法。
4. 加完后 `ans[u] = cnt[ord(labels[u]) - 97]`，再把 `cnt` 返回给父节点。

以示例 1 的节点 1（标签 `'b'`）为例：子节点 4、5 的标签是 `'e'`、`'d'`，合并后 `cnt` 里 `b` 位仍是 1，所以 `ans[1] = 1`；而节点 0 合并完子树 1 和子树 2 后，`cnt['a'] = 2`（自己 + 节点 2），得 `ans[0] = 2`。

```python
def dfs(u, p):
    cnt = [0] * 26
    cnt[ord(labels[u]) - 97] = 1
    for v in g[u]:
        if v != p:
            sub = dfs(v, u)
            for i in range(26):
                cnt[i] += sub[i]
    ans[u] = cnt[ord(labels[u]) - 97]
    return cnt
```

`n = 10^5` 时递归深度可能到 10^5，超过 Python 默认递归上限，入口处要 `sys.setrecursionlimit(200000)`，或者改写成显式栈的后序 DFS。

## 复杂度
时间 O(26n)：每条边触发一次 26 位合并，DFS 遍历 n 个节点。
空间 O(26n + n)：每层递归各持一个 26 长数组，加上邻接表 `g` 的 2(n-1) 条边。

## 易错点
- 无向边不判 `parent`：输入 `edges = [[0,1],[1,2],[0,3]]` 时，从 0 走到 1 后 1 又会走回 0，无限递归爆栈。正确做法是 DFS 传 `p`，`if v != p` 才下探。
- 用全局单个 `cnt` 数组不回溯：处理完节点 1 的子树后 `cnt` 里还留着节点 4、5 的 `'e'`、`'d'`，再算节点 2 时就被污染。正确做法是每个节点返回独立数组，或全局数组在回溯时把子树的贡献减掉。

## 如果面试官追问
若 `n` 放大到 10^6 且内存吃紧，26 长数组每层都开一份太浪费，怎么办？
答：改成全局 `cnt` 数组 + 后序 DFS，进入节点时 `+1`、离开时 `-1`，答案在离开前读，空间降到 O(26 + n)。
