## 一句话思路
对每个数算出二进制反转值当排序键，用 `(反转值, 原值)` 二元组排序，一次 `sorted` 搞定。

## 怎么做
1. 写一个 `rev(x)`：循环 `x & 1` 取最低位，累加进 `r`，再 `x >>= 1`，直到 `x == 0`。
2. 对 `nums` 里每个元素调用 `rev`，得到键 `(rev(v), v)`。
3. 用 `sorted(nums, key=...)` 排序，Python 的 `sorted` 稳定且键是元组，天然满足「反射值相同则原值升序」。

以示例 2 `nums = [3,6,5,8]` 为例，关键中间值：`rev(6)` 中 `6=110`，依次取位得 `0,1,1`，累加 `r = 0*2+0=0 → 0*2+1=1 → 1*2+1=3`，所以 `rev(6)=3`，与 `rev(3)=3` 相同；键分别是 `(3,3)`、`(3,6)`、`(5,5)`、`(1,8)`，排序后 `[8,3,6,5]`。

```python
def rev(x):
    r = 0
    while x:
        r = (r << 1) | (x & 1)
        x >>= 1
    return r

def sortByReflection(nums):
    return sorted(nums, key=lambda v: (rev(v), v))
```

注意 `r = (r << 1) | (x & 1)` 等价于「把已积累的反转值左移一位再拼上当前最低位」，比先转字符串再 `[::-1]` 少一次分配，且对 `10^9`（约 30 位）只循环 30 次。

## 复杂度
时间：每个数 `rev` 走 `O(log nums[i])` 位，排序 `O(n log n)`，总计 `O(n log n + n log max)`。
空间：`sorted` 额外开 `O(n)` 的结果列表，`rev` 只用常数个整数。

## 易错点
- 输入含 `4`（`100`）时，若用字符串 `bin(x)[2:][::-1]` 再 `int(..., 2)`，`'001'` 会被正确解析成 `1`，但若手写循环时忘了「忽略前导零」——其实循环法天然忽略，因为 `x` 末尾的 0 在反转后变成高位 0，`r` 左移时不会保留它们；真正会错的是把 `rev` 写成「先补到固定 32 位再反转」，那样 `4` 会得到 `2**29` 级别的巨大值，排序全乱。
- 输入 `[3,6]` 时，两者 `rev` 都是 `3`，若只写 `key=rev` 而不带原值，`sorted` 虽稳定但依赖输入顺序，`[6,3]` 会输出 `[6,3]` 而非 `[3,6]`；必须用 `(rev(v), v)` 元组键显式保证原值升序。

## 如果面试官追问
问：`nums[i]` 放大到 `10^18` 还成立吗？答：成立，`rev` 循环次数变成约 60 次，总时间仍是 `O(n log n + n log max)`，Python 整数无溢出问题。
