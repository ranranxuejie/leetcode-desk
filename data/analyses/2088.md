## 一句话思路
对每个格子算「以它为顶、向下最多能扩几层」的 dp，再按高度累加，正反各扫一遍。

## 怎么做
1. 定义 `down[i][j]`：以 `(i,j)` 为顶点的金字塔最大高度（只要求每行连续肥沃，不要求整体合法）。转移是 `down[i][j] = 1 + min(down[i+1][j-1], down[i+1][j], down[i+1][j+1])`，边界外取 0，`grid[i][j]==0` 时取 0。
2. 关键观察：若 `down[i][j] = k`，则以 `(i,j)` 为顶的合法金字塔高度恰为 `2..k` 各一个，贡献 `k-1`。因为高度 h 合法等价于 h-1 合法且第 h 层三格都够深，`down` 的 min 正好卡住这个条件。
3. 倒金字塔把 `grid` 上下翻转后重跑步骤 1、2，答案相加。
4. 用示例 2 `[[1,1,1],[1,1,1]]` 验证：底行 `down[1]=[1,1,1]`，顶行 `down[0][1]=1+min(1,1,1)=2`，贡献 1；翻转后同理再得 1，合计 2。

```python
def count(grid):
    m, n = len(grid), len(grid[0])
    down = [[0] * n for _ in range(m)]
    total = 0
    for i in range(m - 1, -1, -1):
        for j in range(n):
            if grid[i][j]:
                a = down[i + 1][j - 1] if i + 1 < m and j > 0 else 0
                b = down[i + 1][j] if i + 1 < m else 0
                c = down[i + 1][j + 1] if i + 1 < m and j + 1 < n else 0
                down[i][j] = 1 + min(a, b, c)
                total += down[i][j] - 1
    return total

return count(grid) + count(grid[::-1])
```

## 复杂度
时间：O(m·n)，正反各扫一遍，每格常数次比较。
空间：O(m·n) 存 `down`，可压成两行降到 O(n)。

## 易错点
- 把 `down[i][j]` 直接当贡献累加：示例 2 会得 3 而不是 2，因为高度 1 的「金字塔」只有 1 格，题目要求格子数大于 1，必须累加 `down[i][j] - 1`。
- 倒金字塔用 `grid[::-1]` 翻转后忘记 `down` 也要重建：若复用上一轮的 `down` 数组，`down[i+1]` 读到的是旧方向的值，示例 4 会少算 6 个倒金字塔。

## 如果面试官追问
问：m·n 到 10^6 且内存吃紧怎么办？
答：`down` 只依赖下一行，滚动成两个长度 n 的数组，空间 O(n)，时间不变。
