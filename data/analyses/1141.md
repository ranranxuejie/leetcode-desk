## 一句话思路
按 `activity_date` 分组，用 `COUNT(DISTINCT user_id)` 去重计数，再用 `BETWEEN '2019-06-28' AND '2019-07-27'` 卡住 30 天窗口。

## 怎么做
1. 窗口是 `[2019-07-27 - 29天, 2019-07-27]`，即 `2019-06-28` 到 `2019-07-27`，闭区间共 30 天。
2. 用 `WHERE activity_date BETWEEN '2019-06-28' AND '2019-07-27'` 先过滤，把示例里 `2019-06-25` 的 user 4 直接排除。
3. 按 `activity_date` 分组，`COUNT(DISTINCT user_id)` 得到当天活跃人数。
4. 列别名 `day`、`active_users` 对齐输出。

关键中间值：示例中 `2019-07-20` 有 user 1 的三条记录（open/scroll/end）和 user 2 的一条，`COUNT(DISTINCT user_id)` 得 2，而不是 4；`2019-07-21` 同理得 2。

```python
# 伪 SQL 思路，落到 pandas 等价写法
df = activity[(activity["activity_date"] >= "2019-06-28") &
              (activity["activity_date"] <= "2019-07-27")]
res = (df.groupby("activity_date")["user_id"]
         .nunique()
         .reset_index()
         .rename(columns={"activity_date": "day", "user_id": "active_users"}))
```

## 复杂度
时间：O(n)，n 为 Activity 行数，过滤 + 分组各扫一遍。
空间：O(k)，k 为窗口内不同日期数，即分组结果大小。

## 易错点
- 窗口边界写成 `2019-06-27` 到 `2019-07-27`（31 天）或漏掉 `2019-07-27` 当天 → 多算/少算一天 → 正确是 `2019-06-28` 起、`2019-07-27` 止的闭区间。
- 用 `COUNT(user_id)` 而非 `COUNT(DISTINCT user_id)` → 示例中 `2019-07-20` 的 user 1 有三条记录会被算成 4 而非 2 → 必须去重。

## 如果面试官追问
问：若窗口改为「截至某参数日期的近 N 天」怎么改？
答：把 `2019-07-27` 换成参数 `d`，起点用 `d - INTERVAL (N-1) DAY`，其余逻辑不变。
