## 一句话思路
逐位取模 10 拆出数字，边拆边累加和、累乘积，最后返回积减和。

## 怎么做
1. 初始化 `prod = 1`、`total = 0`，注意积的初值必须是 1 而不是 0。
2. 循环 `while n > 0`，每轮取 `d = n % 10` 拿到最低位。
3. 同一轮里 `prod *= d`、`total += d`，再 `n //= 10` 丢掉这一位。
4. 循环结束时 `n` 已归零，返回 `prod - total`。

以 `n = 234` 为例，第一轮 `d = 4`，`prod` 从 1 变 4、`total` 变 4、`n` 变 23；第二轮 `d = 3`，`prod = 12`、`total = 7`、`n = 2`；第三轮 `d = 2`，`prod = 24`、`total = 9`、`n = 0`，返回 15。拆位顺序是从低位到高位，但乘法和加法都满足交换律，顺序不影响结果。

```python
prod, total = 1, 0
while n > 0:
    d = n % 10
    prod *= d
    total += d
    n //= 10
return prod - total
```

如果不想改 `n`，也可以先 `s = str(n)`，再 `prod = 1` 遍历 `for ch in s: prod *= int(ch)`，同时累加 `total`。两种写法复杂度一样，取模版不额外开字符串，更省空间。

## 复杂度
时间：O(log n)，循环次数等于 `n` 的十进制位数，`n = 10^5` 时最多 6 轮。
空间：O(1)，只用了 `prod`、`total`、`d` 三个整型变量，没有额外数组或字符串。

## 易错点
1. `n = 10` → 若把 `prod` 初始化成 0，`prod` 永远是 0，返回 `0 - 1 = -1`，正确答案是 `0 - 1 = -1` 恰好对，但 `n = 234` 会错成 `-9` → 正确做法是 `prod = 1`，让第一个数字 `d` 乘上去才生效。
2. `n = 100` → 若用 `while n:` 之外还额外判断 `n != 0` 才乘，或误以为中间的 0 要跳过，会漏乘两个 0 导致 `prod = 1`、返回 `1 - 1 = 0`，而正确是 `prod = 0`、返回 `0 - 1 = -1` → 正确做法是每一位都无条件参与乘和加，0 也要乘进去。

## 如果面试官追问
问：如果 `n` 的范围放大到 `10^18` 甚至以字符串形式给出怎么办？
答：字符串版直接遍历字符累乘累加，位数即长度，逻辑不变，只是不再依赖取模拆位。
