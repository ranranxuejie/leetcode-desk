## 一句话思路
奇偶交替只有两种目标模式，各自独立算最小代价，取代价小的那种，再在该模式下最小化极差。

## 怎么做
1. 枚举两种模式：下标偶数为偶、下标奇数为奇（记模式 A），或反过来（模式 B）。
2. 对每个位置，把 `nums[i]` 调成目标奇偶的最小代价是 0（已符合）或 1（差 1 即可翻转奇偶），累加得总代价。
3. 取总代价较小的模式；若两模式代价相同，两种都要算极差取小。
4. 在选定模式下，每个元素可取值是 `nums[i]` 或 `nums[i]±1`（保持目标奇偶），用「最小化 max-min」的经典做法：对每个候选值排序后滑动窗口，或直接枚举候选区间端点。

以 `nums = [-2,-3,1,4]` 为例：模式 A 要求下标 0,2 偶、1,3 奇。`nums[2]=1` 是奇需 +1 变 2，代价 1；`nums[3]=4` 是偶需 -1 变 3，代价 1；总代价 2。模式 B 代价更高，故选 A，极差为 `3-(-3)=6`。

```python
def solve(nums):
    n = len(nums)
    best = None
    for start in (0, 1):  # start=0: 偶数位为偶
        cost = 0
        cand = []
        for i, x in enumerate(nums):
            want_even = (i % 2 == start)
            if (x % 2 == 0) == want_even:
                cand.append(x)
            else:
                cost += 1
                cand.append(x - 1 if x % 2 == 0 else x + 1)
        if best is None or cost < best[0]:
            best = (cost, cand)
    return best
```

极差最小化：对 `cand` 排序后，用双指针找最短区间覆盖所有下标对应的候选集（每个下标有 1~2 个候选值），或直接枚举 `cand` 中每个值作为最小值，检查能否让所有元素落入 `[v, v+d]`。

## 复杂度
时间：O(n log n)，排序贡献 log n，n 为数组长度。
空间：O(n)，存候选值列表。

## 易错点
- 输入 `[0,2,-2]`：模式 A 代价 1（`nums[1]=2` 需变 1），模式 B 代价 2，若只算模式 A 会漏掉模式 B 可能更优的极差，必须两模式都算极差再取小。
- 输入 `[7]`：长度为 1 时两模式代价都是 0，极差都是 0，若代码假设 n≥2 会越界或返回错误。

## 如果面试官追问
问：若要求输出具体操作方案而非仅次数？答：记录每个位置选 `x` 还是 `x±1`，按选定模式回填即可。
