## 一句话思路
把 `_` 全押向同一侧：答案就是 `abs(L - R) + 下划线个数`，因为下划线可任意选向，全给多数方向收益最大。

## 怎么做
1. 遍历 `moves`，用 `count('L')`、`count('R')`、`count('_')` 三个计数一次拿到。
2. 令 `diff = L - R`，它表示固定字符把终点钉在 `diff` 处（正为右）。
3. 每个 `_` 都往 `diff` 的符号方向走，绝对值每次加 1，故最远距离为 `abs(diff) + underscore`。
4. 直接返回该值，无需模拟路径。

以 `moves = "L_RL__R"` 为例：`L=3`、`R=2`、`_=2`，`diff = 3 - 2 = 1`，`abs(1) + 2 = 3`，与示例输出 3 一致。中间值 `diff=1` 说明固定部分偏右 1 格，两个下划线都向右，最终到 +3。

```python
def furthestDistanceFromOrigin(moves):
    L = moves.count('L')
    R = moves.count('R')
    blank = moves.count('_')
    diff = L - R
    return abs(diff) + blank
```

关键点：`abs(diff)` 而不是 `diff`，因为 `L` 多时终点在负半轴，距离取绝对值；`blank` 无条件相加，因为每个下划线都能贡献 1 格。

## 复杂度
时间 O(n)：三次 `count` 各扫一遍 `moves`，n 为字符串长度。
空间 O(1)：只开 `L`、`R`、`blank`、`diff` 四个整数。

## 易错点
- 输入 `"L_RL__R"` 时若写成 `diff + blank` 得 `1 + 2 = 3` 碰巧对，但输入 `"LL_R"` 会得 `(2-1)+1 = 2`，正确是 `abs(1)+1 = 2` 也对；真正翻车在 `"LLL_R"`：`diff = 2`，`diff + blank = 3`，而 `abs(2)+1 = 3` 仍对——错的是 `"R_LL"` 这类 `diff` 为负时若漏 `abs`，`-1 + 1 = 0`，正确为 `1 + 1 = 2`。必须取 `abs(diff)`。
- 输入 `"_______"` 时 `L=R=0`，若把 `diff` 初始化为 `None` 或漏算 `blank`，会返回 0；正确是 `abs(0) + 7 = 7`，全押一侧。

## 如果面试官追问
问：若要求输出具体移动序列而非距离？答：先算 `diff` 符号，把所有 `_` 替换成该方向的字符，再原样保留 `L`/`R` 即可，O(n) 一次构造。
