## 一句话思路
行列代价互不干扰，只需沿最短方向逐格累加经过的行/列代价，绕路只会多付。

## 怎么做
1. 行方向：从 `startPos[0]` 走到 `homePos[0]`，把途经的每一行 `rowCosts[r]` 累加，起点行不算。
2. 列方向同理，累加 `colCosts[c]`，起点列不算。
3. 两者相加即答案，无需模拟路径。

以示例 1 为例：`startPos=[1,0]`、`homePos=[2,3]`。行方向从 1 到 2，只经过第 2 行，累加 `rowCosts[2]=3`；列方向从 0 到 3，经过第 1、2、3 列，累加 `colCosts[1]+colCosts[2]+colCosts[3]=2+6+7=15`。合计 `3+15=18`，与输出一致。

```python
def minCost(startPos, homePos, rowCosts, colCosts):
    sr, sc = startPos
    hr, hc = homePos
    ans = 0
    step = 1 if hr >= sr else -1
    for r in range(sr + step, hr + step, step):
        ans += rowCosts[r]
    step = 1 if hc >= sc else -1
    for c in range(sc + step, hc + step, step):
        ans += colCosts[c]
    return ans
```

关键点：`range` 的起点是 `sr + step`，终点是 `hr + step`，这样起点行/列天然被排除，且 `hr == sr` 时循环为空。

## 复杂度
时间：O(|hr-sr| + |hc-sc|)，最多遍历 m+n 格。
空间：O(1)，只用了 `ans` 和两个 `step`。

## 易错点
- 把起点行/列也算进去 → 示例 1 会多算 `rowCosts[1]=4` 得 22 → 循环起点必须是 `sr + step`，不是 `sr`。
- 只写 `range(sr, hr)` 处理降序 → 当 `homePos[0] < startPos[0]` 时循环为空、答案偏小 → 必须用带 `step` 的三参数 `range`，正负方向都覆盖。

## 如果面试官追问
问：若要求输出具体路径怎么办？
答：行方向先走完再走列方向即可，任意单调路径代价相同，按 `step` 逐格记录坐标。
