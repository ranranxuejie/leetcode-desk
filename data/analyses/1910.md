## 一句话思路
用栈逐字符压入，每次压完检查栈顶是否等于 part，是就弹出，因为删除后新拼接处可能再成 part。

## 怎么做
1. 建空列表 `st`，遍历 `s` 的每个字符 `c`，`st.append(c)`。
2. 每次 append 后，若 `len(st) >= len(part)` 且 `''.join(st[-len(part):]) == part`，就 `del st[-len(part):]`。
3. 遍历结束返回 `''.join(st)`。

以 `s = "daabcbaabcbc"`、`part = "abc"` 为例：压到 `st = ['d','a','a','b','c']` 时栈顶 3 个是 `"abc"`，删掉得 `['d','a']`；继续压 `b','a','a','b','c'` 又凑出 `"abc"` 删掉，最终 `st = ['d','a','b']`，返回 `"dab"`。

```python
st = []
m = len(part)
for c in s:
    st.append(c)
    if len(st) >= m and ''.join(st[-m:]) == part:
        del st[-m:]
return ''.join(st)
```

关键点：删除后栈顶可能立刻又和 part 匹配（如 `s="aabab"`、`part="ab"`），所以判断必须放在每次 append 之后，而不是只在原串上找一次。

## 复杂度
时间 O(n·m)：n 为 s 长度，每次栈顶比较最多 m 个字符。
空间 O(n)：栈最多存 n 个字符，无其他额外结构。

## 易错点
- `s = "aabab"`、`part = "ab"`：只在原串上从左删一次会得到 `"aab"`，漏掉删除后新拼接的 `"ab"`；正确做法是每次 append 后都检查栈顶，删完继续让后续字符触发新匹配。
- `part` 长度大于当前栈时直接切片 `st[-m:]` 会取到整个栈并误判；必须先判 `len(st) >= m`，否则 `s="a"`、`part="abc"` 会拿 `"a"` 去和 `"abc"` 比较，逻辑上虽不等但边界不清，长 part 下容易写错下标。

## 如果面试官追问
问：s 长度到 10^5 怎么优化？答：把栈顶比较换成 KMP 的失配指针维护每个位置的最长匹配长度，比较降到 O(1)，总时间 O(n+m)。
