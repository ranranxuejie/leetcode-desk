## 一句话思路
两个 FIFO 队列分别存司机和乘客，取消时用哈希表标记作废，出队时跳过作废项。

## 怎么做
1. 维护 `drivers`、`riders` 两个 `deque`，以及 `cancelled` 集合记录被取消的 riderId。
2. `addRider` / `addDriver` 直接 `append` 到对应队列尾部，保证先进先出。
3. `cancelRider` 只把 id 丢进 `cancelled`，不真从队列里删（deque 中间删除是 O(n)）。
4. `matchDriverWithRider` 先弹出队首司机，再循环弹出队首乘客直到遇到不在 `cancelled` 里的；若乘客队列先空，把司机塞回队首返回 `[-1, -1]`。

以示例 1 为例：`addRider(3)`、`addDriver(2)`、`addRider(1)` 后，`riders = [3, 1]`，`drivers = [2]`。第一次匹配弹出司机 2、乘客 3，返回 `[2, 3]`，此时 `riders = [1]`。之后 `cancelRider(3)` 把 3 加入 `cancelled`，但 3 早已出队，集合里这条是死数据，不影响后续。第二次匹配弹出司机 5、乘客 1，返回 `[5, 1]`。

```python
from collections import deque

def matchDriverWithRider(self):
    if not self.drivers or not self.riders:
        return [-1, -1]
    d = self.drivers.popleft()
    while self.riders and self.riders[0] in self.cancelled:
        self.cancelled.discard(self.riders.popleft())
    if not self.riders:
        self.drivers.appendleft(d)
        return [-1, -1]
    return [d, self.riders.popleft()]
```

关键点：司机先弹出再判断乘客是否为空，为空必须 `appendleft` 塞回去，否则司机被白白吃掉。

## 复杂度
时间：每次操作均摊 O(1)，每个 rider 最多被弹出一次，n 为总操作数。
空间：O(n)，两个 deque 加一个 `cancelled` 集合，最多存下所有 id。

## 易错点
- 输入 `addRider(2)` 后 `cancelRider(2)` 再 `matchDriverWithRider`（示例 2 场景）→ 若取消时直接 `riders.remove(2)`，deque 中间删除是 O(n)，1000 次操作虽能过但写法不地道；正确做法是懒删除，出队时用 `cancelled` 过滤。
- 司机队列非空但乘客全被取消 → 若先 `popleft` 司机再发现乘客空却不塞回，这个司机就永久丢失，后续 `addRider` 后匹配会返回 `[-1, -1]`；正确做法是 `appendleft(d)` 还原。
- 对已匹配的 rider 调 `cancelRider`（示例 1 的 `cancelRider(3)`）→ 若误以为要报错或影响队列，会打乱顺序；正确做法是直接加入 `cancelled`，反正它已不在队列里，天然无害。

## 如果面试官追问
问：如果要求取消操作立即从队列中移除且保持 O(1) 均摊，怎么改？
答：用双向链表节点 + 哈希表存 riderId 到节点的映射，取消时 O(1) 摘链，匹配时取链表头。
