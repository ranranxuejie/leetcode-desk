## 一句话思路
排序后，问题变成找最长的区间 `[nums[l], nums[r]]` 满足 `nums[r] - nums[l] <= 2k`，用滑动窗口一次扫描。

## 怎么做
1. 先对 `nums` 排序，因为子序列可重排成任意顺序，只需关心数值集合。
2. 排序后，若窗口两端差 `<= 2k`，则窗口内所有元素都能被改成同一个值（取两端的中点附近）。
3. 用双指针 `l`、`r` 维护窗口，`r` 右移扩张，不满足条件时 `l` 右移收缩，记录最大窗口长度。

以 `nums = [4,6,1,2], k = 2` 为例：排序得 `[1,2,4,6]`，`2k = 4`。窗口 `[1,2,4]` 时 `4-1=3 <= 4`，长度 3；扩到 `6` 时 `6-1=5 > 4`，`l` 右移到 `2`，`6-2=4 <= 4`，长度仍为 3。

```python
nums.sort()
left = 0
ans = 0
for right in range(len(nums)):
    while nums[right] - nums[left] > 2 * k:
        left += 1
    ans = max(ans, right - left + 1)
return ans
```

关键中间值：`right=3`（值 6）时，`nums[3]-nums[0]=5 > 4`，`left` 从 0 移到 1，此时 `6-2=4` 满足条件，窗口长度 `3-1+1=3`。

## 复杂度
时间：排序 `O(n log n)` 主导，双指针扫描 `O(n)`。
空间：排序栈空间 `O(log n)`，无额外数组。

## 易错点
- `k=0` 且 `nums=[4,6,1,2]` → 若误用 `nums[right]-nums[left] <= k` 而非 `2*k`，会得到 1 而非正确答案 1（此时确实为 1，但 `k=2` 时误用 `k` 会得 2 而非 3）→ 正确做法是条件写 `> 2 * k` 才收缩。
- 窗口收缩用 `if` 而非 `while` → 当 `nums=[1,1,1,100], k=0` 时，`right=3` 处 `100-1=99 > 0`，`if` 只移一次 `left` 到 1，窗口仍含 `100` 与 `1`，长度算成 3 → 必须用 `while` 持续收缩直到 `nums[right]-nums[left] <= 2*k`。

## 如果面试官追问
若要求输出具体方案（哪些下标、改成什么值）？答：窗口确定后取 `target = nums[left] + k`，窗口内每个 `nums[i]` 都能改到 `target`（因 `nums[i] <= nums[left]+2k` 且 `nums[i] >= nums[left]`），直接返回这些下标即可。
