## 一句话思路
按 groups 顺序贪心：在 nums 里从上次匹配结束处起找第一个匹配位置，找到就跳到其末尾，找不到即失败。

## 怎么做
1. 维护指针 `start`，表示 nums 中下一个可用的起始下标，初值 0。
2. 对 groups 中每个 `g`，从 `start` 开始逐个位置尝试匹配，取**第一个**成功的位置 `p`。
3. 匹配成功则令 `start = p + len(g)`，继续下一个 group；若扫到 `len(nums) - len(g)` 仍无匹配，返回 `False`。
4. 全部 group 匹配完返回 `True`。

以示例 1 为例：`groups[0] = [1,-1,-1]`，从 `start=0` 扫，`nums[0..2]=[1,-1,0]` 不匹配，`nums[3..5]=[1,-1,-1]` 匹配，`start` 变为 6；`groups[1]=[3,-2,0]` 从 6 起正好匹配 `nums[6..8]`，返回 `True`。

```python
start = 0
for g in groups:
    m = len(g)
    p = start
    while p + m <= len(nums) and nums[p:p + m] != g:
        p += 1
    if p + m > len(nums):
        return False
    start = p + m
return True
```

关键点：`p + m <= len(nums)` 是循环条件，保证切片不越界；`nums[p:p+m] != g` 用列表比较代替手写内层循环。

## 复杂度
时间 O(len(nums) * 总匹配长度)，最坏每个 group 都从 `start` 扫到末尾。
空间 O(1)，只用了 `start`、`p` 两个下标，切片比较是临时对象。

## 易错点
- 示例 3 的 `groups=[[1,2,3],[3,4]]`、`nums=[7,7,1,2,3,4,7,7]`：若匹配完 `[1,2,3]` 后把 `start` 设成 `p`（而非 `p+m`），`[3,4]` 会复用 `nums[4]=3`，错判为 `True`。正确做法是 `start = p + m`，强制不相交。
- 示例 2 的 `groups=[[10,-2],[1,2,3,4]]`、`nums=[1,2,3,4,10,-2]`：若对每个 group 都从下标 0 重新搜，会先找到 `[1,2,3,4]` 再找到 `[10,-2]`，错判为 `True`。正确做法是 `start` 只增不减，保证顺序。

## 如果面试官追问
问：要求输出具体选出的下标区间怎么办？
答：把 `start = p + m` 改成记录 `(p, p+m-1)` 到结果列表，其余逻辑不变。
