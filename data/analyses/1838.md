## 一句话思路
排序后，最优方案必是把一段连续区间全抬到区间最大值，用滑动窗口维护这段区间的「补齐代价」≤ k。

## 怎么做
1. 先 `nums.sort()`，因为把小的抬到大的才省操作，最优目标值一定是区间右端元素。
2. 窗口 `[l, r]` 的代价是 `nums[r]*(r-l+1) - sum(nums[l..r+1])`，即全抬到 `nums[r]` 需要的增量。
3. `r` 右移加入新元素，代价超 `k` 就 `l` 右移收缩，每步更新最大窗口长度。
4. 用前缀和 `pre` 让区间和 O(1)，避免每步重算。

以 `nums=[1,2,4], k=5` 为例：排序后不变。`r=2` 时窗口 `[0,2]`，代价 `4*3-(1+2+4)=12-7=5 ≤ 5`，窗口长度 3，答案 3。

```python
nums.sort()
pre = [0]
for x in nums:
    pre.append(pre[-1] + x)
l = ans = 0
for r in range(len(nums)):
    # 代价 = 右端值*窗口长度 - 窗口和
    while nums[r] * (r - l + 1) - (pre[r + 1] - pre[l]) > k:
        l += 1
    ans = max(ans, r - l + 1)
return ans
```

关键中间值：`r=2, l=0` 时 `pre[3]-pre[0]=7`，`4*3-7=5`，恰好等于 `k`，不触发收缩。

## 复杂度
时间：排序 O(n log n) 主导，窗口双指针各走一遍 O(n)。
空间：`pre` 前缀和数组 O(n)，排序栈开销 O(log n)。

## 易错点
- 输入 `nums=[1,1,1], k=0` → 若把代价写成 `nums[r]*(r-l) - ...`（漏算窗口内元素个数）会得 0 或负数，误判窗口可扩 → 正确是 `r-l+1` 个元素全要抬，代价为 0，答案 3。
- 输入 `nums=[1,4,8,13], k=5` → 若只把 `l` 移一格就退出 while，窗口 `[1,2]` 代价 `8*2-(4+8)=4` 看似合法但漏了更优的 `[0,1]` 代价 3 → 必须 `while` 循环收缩到代价 ≤ k 再更新 `ans`，且 `ans` 在收缩后取。

## 如果面试官追问
问：若要求返回具体的目标值和被修改的下标方案？
答：在窗口达到最大长度时记录 `target=nums[r]`，区间内每个下标需加 `target-nums[i]` 次，累加即方案。
