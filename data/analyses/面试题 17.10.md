## 一句话思路
Boyer-Moore 投票：不同元素两两抵消，超过一半的元素抵消不完，剩下的候选再验一遍。

## 怎么做
1. 维护 `cand` 和 `count`，遍历 `nums`，`count == 0` 时把当前元素设为 `cand`。
2. 当前元素等于 `cand` 就 `count += 1`，否则 `count -= 1`。
3. 遍历结束后 `cand` 只是候选，必须再扫一遍统计它出现次数，`> len(nums) // 2` 才返回，否则 `-1`。

拿示例 1 `[1,2,5,9,5,9,5,5,5]` 走一遍关键段：前 8 个元素两两抵消后 `cand=5, count=1`，最后一个 `5` 让 `count=2`；复验时 `5` 出现 6 次，`6 > 9 // 2 = 4`，返回 `5`。

```python
cand, count = None, 0
for x in nums:
    if count == 0:
        cand, count = x, 1
    elif x == cand:
        count += 1
    else:
        count -= 1
if nums.count(cand) > len(nums) // 2:
    return cand
return -1
```

第 3 步不能省：示例 2 `[3,2]` 抵消后 `count=0`，候选是 `2`，但 `2` 只出现 1 次，`1 > 1` 为假，正确返回 `-1`。

## 复杂度
时间 O(n)：第一遍投票 n 次，第二遍 `count` 再扫 n 次，共 2n。
空间 O(1)：只开 `cand`、`count` 两个变量，没有额外数组或哈希表。

## 易错点
- 输入 `[3,2]` 或 `[1,2,3]` → 只做投票直接返回 `cand`，会错成 `2` 或 `3` → 必须补第二遍计数，用 `nums.count(cand) > len(nums) // 2` 判定，不满足返回 `-1`。
- 输入 `[2,2,1,1,1,2,2]` → 若在 `count == 0` 时写成先 `count -= 1` 再赋值，或把 `x == cand` 和 `count == 0` 的判断顺序颠倒，候选会漂成 `1` → 严格按「先判 `count == 0` 重置，再判相等加减」的顺序写，此例最终 `cand=2, count=1`，复验 4 次 `> 3` 成立。

## 如果面试官追问
问：要求返回所有出现次数超过 n/3 的元素怎么办？
答：候选最多两个，用两个 `cand` 加两个 `count` 同时投票，最后各自复验次数是否 `> n // 3`。
