## 一句话思路
把每个大于 threshold 的因数 z 当作「枢纽」，用并查集把 z 的所有倍数（≤n）并成一团，再回答查询。

## 怎么做
1. 枚举 z 从 threshold+1 到 n；z 若已在某个已合并的团里可跳过，但直接枚举也不慢。
2. 对每个 z，把 2z, 3z, … ≤ n 全部 union 到 z 上——它们共享因数 z，必然连通。
3. 查询时只比较 find(a) == find(b)。

以示例 1（n=6, threshold=2）为例：z=3 时把 3 与 6 合并；z=4、5、6 的倍数只有自己，无操作。于是只有 {3,6} 成团，`[3,6]` 返回 True，其余 False。

关键剪枝：z 从 threshold+1 起，且只需枚举到 n//2（更大的 z 没有倍数伙伴）。另外若 threshold==0，因数 1 让全图连通，可直接全 True。

```python
parent = list(range(n + 1))
def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x
for z in range(threshold + 1, n // 2 + 1):
    for m in range(2 * z, n + 1, z):
        ra, rb = find(z), find(m)
        if ra != rb:
            parent[ra] = rb
return [find(a) == find(b) for a, b in queries]
```

## 复杂度
时间：调和级数 ∑ n/z ≈ n·ln n，即 O(n log n + q·α(n))。
空间：parent 数组 O(n)，答案数组 O(q)。

## 易错点
- threshold ≥ n//2 时（如 n=6, threshold=3），循环体一次不进，所有查询都 False——别误以为「没合并就是全连通」；正确做法是照常 find 比较，天然得 False。
- threshold=0 时若仍从 z=1 枚举，会把 1 与所有数合并，结果虽对但白跑 O(n log n)；更隐蔽的坑是漏掉 z=1 这一层导致 `[4,5]` 错判 False，正确做法是显式处理 threshold==0 直接全 True。

## 如果面试官追问
问：n 放大到 10^7 怎么办？答：仍用筛法式并查集，但只对 z ≤ n//2 枚举，且用数组版 find 避免递归，内存约 40MB 可控。
