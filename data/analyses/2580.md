## 一句话思路
按左端点排序后扫描合并出连通块个数 k，答案就是 2^k（每个块独立选组）。

## 怎么做
1. 把 `ranges` 按 `start` 升序排序，这样有交集的区间在排序后必然相邻成段。
2. 维护当前连通块的右边界 `cur_end`，初始为第一个区间的 `end`；块数 `k = 1`。
3. 遍历后续区间：若 `start <= cur_end` 就并入当前块并 `cur_end = max(cur_end, end)`；否则新开一块，`k += 1`，`cur_end = end`。
4. 返回 `pow(2, k, 10**9 + 7)`。

以示例 2 `[[1,3],[10,20],[2,5],[4,8]]` 为例，排序后是 `[[1,3],[2,5],[4,8],[10,20]]`。扫到 `[2,5]` 时 `2 <= 3`，并入，`cur_end` 从 3 变成 5；扫到 `[4,8]` 时 `4 <= 5`，并入，`cur_end` 变成 8；扫到 `[10,20]` 时 `10 > 8`，新开一块，`k = 2`，答案 `2**2 = 4`。

```python
ranges.sort(key=lambda r: r[0])
k, cur_end = 1, ranges[0][1]
for s, e in ranges[1:]:
    if s <= cur_end:
        cur_end = max(cur_end, e)
    else:
        k += 1
        cur_end = e
return pow(2, k, 10**9 + 7)
```

注意 `k` 的初值是 1 而不是 0：第一个区间自己就构成一个块，`ranges` 长度至少为 1，所以不会越界。

## 复杂度
时间 O(n log n)：排序贡献 log n，扫描 O(n)。
空间 O(1) 额外（不计排序开销），只存 `k` 和 `cur_end`。

## 易错点
- 输入 `[[1,2],[3,4]]` → 若把判断写成 `s < cur_end`，会把 `3 <= 2` 误判成不相交之外的另一种错，实际这里本就该分成 2 块；真正翻车的是 `[[1,3],[3,5]]` 这种端点相接的输入，用 `<` 会错分成 2 块得 4，正确是 `<=` 判为相交、`k = 1`、答案 2。
- 输入 `[[1,10],[2,3],[4,5]]` → 若并入时只写 `cur_end = e` 而不取 `max`，`cur_end` 会从 10 被改写成 3，导致 `[4,5]` 被误判为新块，`k` 从 1 错成 2，答案从 2 错成 4；必须 `cur_end = max(cur_end, e)`。

## 如果面试官追问
问：如果要求输出具体分组方案而不只是方案数？
答：合并时给每个块记一个块编号，最后枚举 2^k 种块到组的映射，把块内区间展开即可。
