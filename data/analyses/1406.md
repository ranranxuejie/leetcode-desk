## 一句话思路
从后往前算 `dp[i]` = 从第 i 堆起先手能拿到的最大净胜分，用后缀和 `suf[i]` 把「拿走的分数减对手净胜分」一步算完。

## 怎么做
1. 预处理后缀和 `suf[i] = sum(stoneValue[i:])`，`dp[n] = 0`。
2. 倒序枚举 i，取 `k = 1,2,3` 中 `suf[i] - suf[i+k] - dp[i+k]` 的最大值，即「本轮拿到的分减去对手在剩余局面的净胜分」。
3. 以 `[1,2,3,7]` 为例：`suf = [13,12,10,7,0]`；`dp[3] = 7`，`dp[2] = 10 - 7 = 3`，`dp[1] = max(12-3, 12-7) = 9`，`dp[0] = max(13-9, 13-3, 13-7) = 10`。
4. 最后比较 `dp[0]` 与 0：大于返回 `"Alice"`，小于返回 `"Bob"`，等于返回 `"Tie"`。

```python
n = len(stoneValue)
suf = [0] * (n + 1)
for i in range(n - 1, -1, -1):
    suf[i] = suf[i + 1] + stoneValue[i]
dp = [0] * (n + 4)
for i in range(n - 1, -1, -1):
    best = -2**31
    for k in range(1, 4):
        if i + k <= n:
            best = max(best, suf[i] - suf[i + k] - dp[i + k])
    dp[i] = best
return "Alice" if dp[0] > 0 else ("Bob" if dp[0] < 0 else "Tie")
```

## 复杂度
时间：O(n)，每个 i 只枚举 k=1..3，后缀和预处理也是 O(n)。
空间：O(n)，`suf` 和 `dp` 各开 n+4 长度，可滚动到 O(1) 但没必要。

## 易错点
1. 输入 `[1,2,3,-9]` → 若把 `dp[i]` 定义成「先手能拿到的最大分数」而不是净胜分，`-9` 这种负堆会让转移式写错，得到 Alice 输的错误结论 → 必须用 `suf[i]-suf[i+k]-dp[i+k]` 的净胜分形式，`dp[0]=6-(-3)=9>0` 才是 Alice。
2. 输入 `[1,2,3,6]` → 若在 `i+k>n` 时仍取 `dp[i+k]`（越界读到 0）或漏掉 k 的边界判断，`dp[0]` 会算成 7 判 Alice 赢 → 正确是 `dp[0]=0` 返回 `"Tie"`，循环里必须加 `if i+k <= n`。

## 如果面试官追问
问：n 扩大到 10^6 且只能拿前 1..m 堆怎么办？
答：转移变成对 `dp[i+1..i+m]` 取 `suf[i]-suf[j]-dp[j]` 的最大值，用单调队列维护 `suf[j]+dp[j]` 的最小值，O(n)。
