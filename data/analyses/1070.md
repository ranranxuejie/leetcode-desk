## 一句话思路
先用 `groupby` 求每个 `product_id` 的 `min(year)`，再按 `(product_id, year)` 内连接回原表，取回该年全部销售条目。

## 怎么做
1. 对 `Sales` 按 `product_id` 分组，取 `year` 的最小值，得到 `first_year` 表。
2. 把这张表与原表按 `product_id` 和 `year == first_year` 做内连接。
3. 连接后重命名列，只保留 `product_id, first_year, quantity, price`。

用官方示例：`product_id=100` 的两行 `year` 是 2008、2009，分组取 min 得 `first_year=2008`；连接时 2009 那行因 `year != 2008` 被丢弃，只剩 `sale_id=1` 的 `quantity=10, price=5000`。`product_id=200` 只有 2011 一行，min 也是 2011，原样保留。

```python
first = sales.groupby("product_id", as_index=False)["year"].min()
first = first.rename(columns={"year": "first_year"})
ans = sales.merge(first, on="product_id")
ans = ans[ans["year"] == ans["first_year"]]
ans = ans[["product_id", "first_year", "quantity", "price"]]
```

关键在 `merge` 后必须再过滤 `year == first_year`：`merge` 只按 `product_id` 匹配，会把该产品所有年份的行都带出来，不筛就多出 2009 那行。

## 复杂度
时间 O(n)：`groupby` 扫一遍 n 行，`merge` 再扫一遍，过滤一遍。
空间 O(k)：额外存 k 个产品的 `first_year` 表，k ≤ n。

## 易错点
- 同一产品同一年有多条销售（题面明说可能）→ 若用 `drop_duplicates("product_id")` 取首年，会随机只留一条，丢掉该年其他条目 → 必须用 `min(year)` 定位年份，再按年份取**全部**行。
- 只按 `product_id` 连接后忘记过滤 `year == first_year` → 示例中 `product_id=100` 会输出 2008 和 2009 两行，结果翻倍 → 连接后加 `ans["year"] == ans["first_year"]` 这一条件。

## 如果面试官追问
问：若要求每个产品首年只返回销量最大的那一条？
答：在 `year == first_year` 的子集上再按 `product_id` 分组取 `quantity` 的 `idxmax`，用 `loc` 取回整行。
