## 一句话思路
对每个下标独立做可行性 DP（子集和），再二分最小的 k，因为「前 k 个查询可行」对 k 单调。

## 怎么做
1. 二分 k（0..len(queries)），判定函数 `ok(k)` 检查前 k 个查询能否把 nums 清零。
2. 对每个下标 i，收集所有覆盖 i 的查询的 val，做 0/1 子集和 DP，看能否凑出 nums[i]。
3. 所有下标都能凑出才算 `ok(k)` 为真。

以示例 1 `nums=[2,0,2]`、`queries=[[0,2,1],[0,2,1],[1,1,3]]` 为例，k=2 时下标 0 覆盖查询是 val=[1,1]，子集和能凑 2；下标 1 覆盖 val=[1,1,3]，能凑 0（空集）；下标 2 同理凑 2，全部可行，返回 2。

```python
def ok(k):
    for i, need in enumerate(nums):
        if need == 0:
            continue
        reach = 1  # 位掩码，第 b 位表示能凑出 b
        for l, r, v in queries[:k]:
            if l <= i <= r:
                reach |= reach << v
        if not (reach >> need) & 1:
            return False
    return True
```

用位掩码 `reach` 代替布尔数组，`reach |= reach << v` 一次完成「选或不选 val=v」。注意 `need` 最大 1000，掩码位数够用。

## 复杂度
时间：二分 O(log Q) 次判定，每次 O(n·k·need/word)，need≤1000 用 Python 大整数近似 O(n·k)。
空间：每个下标一个整数掩码，O(need) 位，无额外数组。

## 易错点
- `nums[i]=0` 的下标若也跑 DP，空集本就能凑 0，但若误判「必须选至少一个查询」会返回 False → 示例 1 下标 1 的 need=0 直接跳过，正确。
- 二分边界写成 `lo=1` 会漏掉 k=0 的情况（nums 全 0 时答案就是 0）→ 应从 `lo=0` 开始，且先判 `ok(0)`。

## 如果面试官追问
问：若 queries 长度到 10^5 怎么办？
答：二分仍成立，但每次判定要预处理差分或按 val 分组，避免 O(n·k) 扫描。
