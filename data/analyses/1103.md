## 一句话思路
按轮次模拟发糖，每轮每人应得 `k` 递增，用 `min(k, candies)` 处理最后一次不足的情况。

## 怎么做
1. 初始化 `ans = [0] * num_people`，`k = 1`（当前应发颗数），`i = 0`（当前小朋友下标）。
2. 循环直到 `candies == 0`：本轮实发 `give = min(k, candies)`，累加到 `ans[i]`，`candies -= give`。
3. 更新 `k += 1`，`i = (i + 1) % num_people`，回到步骤 2。

以 `candies = 7, num_people = 4` 为例：第 4 次循环时 `k = 4`，但 `candies = 1`，所以 `give = min(4, 1) = 1`，`ans[3]` 从 0 变 1，`candies` 归零退出，得到 `[1,2,3,1]`。

```python
ans = [0] * num_people
k, i = 1, 0
while candies > 0:
    give = min(k, candies)
    ans[i] += give
    candies -= give
    k += 1
    i = (i + 1) % num_people
```

关键点：`min(k, candies)` 一行同时覆盖「正常发」和「最后一次不够也全发」两种情形，不需要额外分支。

## 复杂度
时间：O(√candies)，因为前 m 轮共发 m(m+1)/2 颗，轮数约 √(2·candies)。
空间：O(num_people)，仅答案数组本身，无额外结构。

## 易错点
- `candies = 10**9, num_people = 1` → 若用 `while candies > 0` 但忘记 `min`，会在最后一轮把 `k` 全加进去导致 `ans[0]` 超过 `candies` → 必须写 `give = min(k, candies)`。
- `candies = 7, num_people = 4` → 若循环条件写成 `while candies >= k`，第 4 轮 `candies = 1 < k = 4` 会直接退出，漏发最后 1 颗，输出 `[1,2,3,0]` → 条件必须是 `candies > 0`。

## 如果面试官追问
若 `candies` 放大到 `10**18` 且要求 O(num_people) 而非 O(√candies)，怎么办？
答：先解二次方程 `m(m+1)/2 ≤ candies` 求出完整轮数 m，再用等差数列公式一次性算出每人基础份额，最后单独处理剩余不足一轮的部分。
