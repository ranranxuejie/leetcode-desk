## 一句话思路
用 UNION ALL 把 store1/store2/store3 三列各自「竖过来」，每段带常量店名并过滤 NULL。

## 怎么做
1. 对 store1 取 `product_id, 'store1' AS store, store1 AS price`，加 `WHERE store1 IS NOT NULL`。
2. 对 store2、store3 重复同一模式，只改列名和常量。
3. 三段用 `UNION ALL` 拼接（不能用 `UNION`，否则会去重丢掉同价行）。
4. 以官方示例产品 1 为例：第一段产出 `(1,'store1',70)`，第二段因 `store2 IS NULL` 被过滤掉，第三段产出 `(1,'store3',80)`，最终该产品只剩两行。

```python
q1 = "SELECT product_id, 'store1' AS store, store1 AS price FROM Products WHERE store1 IS NOT NULL"
q2 = "SELECT product_id, 'store2' AS store, store2 AS price FROM Products WHERE store2 IS NOT NULL"
q3 = "SELECT product_id, 'store3' AS store, store3 AS price FROM Products WHERE store3 IS NOT NULL"
sql = f"{q1} UNION ALL {q2} UNION ALL {q3}"
```

## 复杂度
时间：O(n)，n 为 Products 行数，三段各扫一遍共 3n。
空间：O(n)，结果集最多 3n 行，无额外辅助结构。

## 易错点
- 漏写 `WHERE storeX IS NOT NULL` → 产品 1 的 store2 会输出 `(1,'store2',None)` 这种不该存在的行 → 每段都必须带该列的非空过滤。
- 用 `UNION` 代替 `UNION ALL` → 若两个产品在同店同价（如都为 95），会被合并成一行丢数据 → 必须用 `UNION ALL` 保留全部行。

## 如果面试官追问
问：若商店列不固定、存在 store4…storeN 怎么办？
答：列转行需动态生成 SQL 或改用 `UNPIVOT`/`LATERAL`，静态三列写法失效。
