## 一句话思路
先把 nums 相邻元素的升降关系压成等长的 sign 数组，问题就变成在 sign 里数 pattern 出现次数。

## 怎么做
1. 构造 `sign[i] = (nums[i+1] > nums[i]) - (nums[i+1] < nums[i])`，长度 `n-1`。
2. 枚举起点 `i` 从 `0` 到 `n-1-m`，逐个比较 `sign[i+k]` 与 `pattern[k]`。
3. 全部相等则计数加一，任一不等立即跳出。

以示例 2 为例：`nums = [1,4,4,1,3,5,5,3]`，sign 为 `[1,0,-1,1,1,0,-1]`。pattern 是 `[1,0,-1]`，在 sign 中从下标 0 和 4 各匹配一次，答案 2。

```python
sign = [(nums[i+1] > nums[i]) - (nums[i+1] < nums[i]) for i in range(len(nums)-1)]
ans = 0
for i in range(len(sign) - len(pattern) + 1):
    if sign[i:i+len(pattern)] == pattern:
        ans += 1
```

## 复杂度
时间：O((n-m)·m)，外层 n-m 个起点，每个起点最多比 m 次。
空间：O(n)，sign 数组占 n-1 个整数，无其他额外结构。

## 易错点
- 起点上界写成 `n - m` 而非 `n - 1 - m`：`nums` 长 n 时 sign 只有 n-1 个，多枚举一个起点会越界或错配，正确上界是 `len(sign) - m`。
- 用 `nums[i+k+1] - nums[i+k]` 直接和 pattern 比：差值可能是 2 或 -5，永远不等于 1/-1，必须先用比较运算压成 -1/0/1 再比。

## 如果面试官追问
若 n 放大到 10^5 并要求 O(n+m)？答：把 sign 和 pattern 拼起来跑 KMP，或用滚动哈希把每次比较降到 O(1)。
