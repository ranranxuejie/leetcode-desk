## 一句话思路
对 s 建 26 个字母的位置表，每个 word 用二分逐字符贪心跳位置，跳不动就淘汰。

## 怎么做
1. 扫一遍 s，把每个字符出现的下标按顺序塞进 `pos[c]`，共 26 个升序列表。
2. 对每个 word 维护游标 `cur = -1`，表示上一个匹配字符在 s 中的位置。
3. 对 word 的每个字符 c，在 `pos[c]` 里二分找第一个 `> cur` 的下标，找到就更新 `cur`，找不到就判该 word 失败。
4. 全部字符都跳成功，计数加一。

以示例 1 的 `s = "abcde"` 为例：`pos['a']=[0]`、`pos['c']=[2]`、`pos['e']=[4]`。处理 `"ace"`：`cur=-1` 时在 `pos['a']` 找到 0，`cur=0`；在 `pos['c']` 找 `>0` 得 2，`cur=2`；在 `pos['e']` 找 `>2` 得 4，`cur=4`，成功。而 `"bb"`：`pos['b']=[1]`，第一个 b 取到 1，第二个 b 要找 `>1`，二分返回越界，失败。

```python
from bisect import bisect_right
pos = [[] for _ in range(26)]
for i, ch in enumerate(s):
    pos[ord(ch) - 97].append(i)
ans = 0
for w in words:
    cur = -1
    for ch in w:
        p = pos[ord(ch) - 97]
        j = bisect_right(p, cur)
        if j == len(p):
            break
        cur = p[j]
    else:
        ans += 1
```

关键点：`bisect_right(p, cur)` 返回的是「第一个大于 cur 的位置」，正好是贪心要的下标；用 `bisect_left` 会取到等于 cur 的位置，导致同一字符被重复使用。

## 复杂度
时间 O(|s| + Σ|words[i]| · log|s|)，每个字符一次二分。
空间 O(|s|)，26 个位置表合计存下 s 的每个下标。

## 易错点
- 输入 `s = "abcde"`、`words = ["bb"]`：若用 `bisect_left` 或线性扫描时没把 `cur` 前移，第二个 b 会复用下标 1，错判为子序列；正确做法是每次取严格大于 `cur` 的位置，取不到立即 break。
- 输入 `s = "aaaa"`、`words = ["aaaaa"]`：若只判断字符存在而不检查数量，会错判成功；`pos['a']` 只有 4 个下标，第 5 次二分必然越界，靠 `j == len(p)` 拦住。

## 如果面试官追问
问：words 长度涨到 10^6 怎么办？答：把 words 按首字母分桶，边扫 s 边推进各桶游标，省掉每个 word 的重复二分。
