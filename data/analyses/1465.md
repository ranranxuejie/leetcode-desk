## 一句话思路
最大面积必来自「最大水平间距 × 最大竖直间距」，因为任意一块蛋糕都由相邻两条切口（含边界）围成，行列独立。

## 怎么做
1. 把 `horizontalCuts` 排序，并在首尾补上 `0` 和 `h`，相邻差的最大值就是 `maxH`。
2. 对 `verticalCuts` 同样处理，得到 `maxW`。
3. 返回 `maxH * maxW % (10**9 + 7)`，先乘后取模。

以示例 1 为例：`horizontalCuts` 排序后 `[1,2,4]`，补边界成 `[0,1,2,4,5]`，相邻差 `1,1,2,1`，`maxH = 2`；`verticalCuts` 补成 `[0,1,3,4]`，差 `1,2,1`，`maxW = 2`；面积 `2*2 = 4`。

```python
MOD = 10**9 + 7

def max_gap(cuts, limit):
    cuts = sorted(cuts)
    prev, best = 0, 0
    for c in cuts:
        best = max(best, c - prev)
        prev = c
    return max(best, limit - prev)

maxH = max_gap(horizontalCuts, h)
maxW = max_gap(verticalCuts, w)
return maxH * maxW % MOD
```

关键点：`max_gap` 里 `limit - prev` 不能漏，最后一段到边界的间距往往最大（示例 1 的 `5-4=1` 虽小，但示例 3 中 `h=5`、切口 `[3]` 时 `5-3=2` 才是 `maxH`）。

## 复杂度
时间：排序 `horizontalCuts` 和 `verticalCuts` 各 O(n log n)、O(m log m)，扫描 O(n+m)。
空间：排序额外 O(n+m)（Python `sorted` 返回新列表），无其他结构。

## 易错点
- 忘记补边界 `0` 和 `h`/`w` → 示例 3 中 `horizontalCuts=[3]` 只算出间距 `3`，漏掉 `5-3=2` 与首段 `3`，若切口集中在中间会低估 `maxH`，正确做法是首尾都补。
- 先取模再比较大小 → 若在求 `maxH`、`maxW` 时提前 `% MOD`，`maxH*maxW` 的比较基准被破坏；正确做法是全程用原始整数求最大间距，只在最后 `maxH * maxW % MOD` 一次。

## 如果面试官追问
问：若要求返回最大那块蛋糕的四条边界坐标而非面积？
答：在求 `maxH` 时同步记录产生它的 `(prev, c)` 区间，`maxW` 同理，组合即得矩形四边。
