## 一句话思路
用哈希表按 creator 聚合总播放量和最佳视频，再扫一遍取最大流行度。

## 怎么做
1. 建 `total = {}` 存每个 creator 的播放量总和，`best = {}` 存 `(views, id)` 的最优视频。
2. 遍历一次，累加 `total[c] += v`；对 `best[c]` 用「播放量更大，或播放量相等且 id 字典序更小」更新。
3. 求 `max(total.values())`，把所有 `total[c] == mx` 的 creator 收集成 `[c, best[c][1]]`。

以示例 1 为例，遍历完 `total = {"alice":10, "bob":10, "chris":4}`，`best = {"alice":(5,"one"), "bob":(10,"two"), "chris":(4,"four")}`。alice 的 `"three"` 播放量也是 5，但 `"one" < "three"`，所以 `best["alice"]` 停在 `(5,"one")`。`mx = 10`，命中 alice 和 bob。

```python
total, best = {}, {}
for c, i, v in zip(creators, ids, views):
    total[c] = total.get(c, 0) + v
    if c not in best or v > best[c][0] or (v == best[c][0] and i < best[c][1]):
        best[c] = (v, i)
mx = max(total.values())
return [[c, best[c][1]] for c in total if total[c] == mx]
```

关键在 `best` 的比较条件：先比 `v`，相等才比 `i`，顺序反了会把低播放量的 id 选进来。

## 复杂度
时间 O(n)：一次遍历聚合，`max` 和列表推导各扫一遍 creator 数（≤ n）。
空间 O(k)：`total` 和 `best` 各存 k 个 creator，k 为不同创作者数。

## 易错点
- 输入 `creators=["alice","alice"]`、`views=[0,0]`、`ids=["b","a"]` → 若只写 `v > best[c][0]` 就更新，会保留先到的 `"b"` → 必须加上 `v == best[c][0] and i < best[c][1]` 这一支。
- 输入 `views=[0,0,0]` 且 creator 各不同 → 若把 `mx` 初始化成 0 再判 `total[c] > mx`，会漏掉全部（因为都不严格大于）→ 用 `max(total.values())` 直接取，或初始化 `mx = -1`。

## 如果面试官追问
问：如果要求按流行度降序、同流行度按 creator 字典序升序输出？
答：把最后一步换成 `sorted(total, key=lambda c: (-total[c], c))`，再逐个取 `best[c][1]`。
