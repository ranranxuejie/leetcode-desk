## 一句话思路
对每个起点 i 求 target[i:] 能匹配的最长有效前缀长度，再做「最少段数覆盖」的贪心/DP。

## 怎么做
1. 把 words 全部插入字典树，节点只存子节点，不存词尾标记（前缀即有效）。
2. 对 target 的每个起点 i，从 trie 根沿 target[i]、target[i+1]… 走，走到走不动为止，得到 `reach[i] = i + 匹配长度`。
3. 从 0 开始贪心跳：维护当前段能覆盖的最远位置 `far`，每跳一次答案 +1，若某次 `far` 不再前进则返回 -1。

以示例 1 为例：target = "aabcdabc"，i=0 时沿 'a','a' 走两步后 trie 无 'b' 子节点，`reach[0]=2`；i=2 时 "bcd" 走三步，`reach[2]=5`；i=5 时 "abc" 走三步，`reach[5]=8`。贪心从 0 起：第一跳覆盖到 2，第二跳在 [0,2) 内最远到 5，第三跳在 [2,5) 内最远到 8，共 3 段。

```python
# trie 建好后
reach = [0] * n
for i in range(n):
    node, j = root, i
    while j < n and target[j] in node:
        node = node[target[j]]
        j += 1
    reach[i] = j

ans, far, nxt, i = 0, 0, 0, 0
while far < n:
    while i < n and i <= far:
        nxt = max(nxt, reach[i])
        i += 1
    if nxt == far:
        return -1
    far, ans = nxt, ans + 1
return ans
```

## 复杂度
时间：建 trie O(sum(len(words)))，匹配 O(n·L)（L 为最长匹配长度，最坏 n），贪心 O(n)。
空间：trie 节点数 O(sum(len(words)))，另开 reach 数组 O(n)。

## 易错点
- words 里有 "ab" 和 "abababab" 时，若在 trie 节点上打词尾标记并只允许整词匹配，示例 2 的 "ababa" 就取不到 → 会错成 -1 或 3；正确做法是不设词尾限制，任意深度停下都算有效前缀。
- target 某位置在 trie 根就没有对应字符（如示例 3 的 'x'）→ 若贪心循环里不检查 `nxt == far` 就继续加段，会死循环或返回错误段数；正确做法是 reach[i]==i 时立刻判 -1。

## 如果面试官追问
若 target 长度升到 10^5 怎么办？答：把逐起点暴力匹配换成 Z 函数/滚动哈希预处理每个位置的最长匹配，或对 reach 用线段树做区间最远覆盖，总复杂度降到 O((n+sum)log n)。
