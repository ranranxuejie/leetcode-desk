## 一句话思路
对每个 `strs[i]` 贪心匹配：从左到右扫，用 `s` 中尚未消耗的字符去满足它，`?` 当通配符。

## 怎么做
1. 关键观察：一次操作等价于「把 `s` 中某些位置的 1 往后挪、0 往前挪」，所以只要 `t` 的每个前缀里 0 的个数不少于 `s` 对应前缀里 0 的个数（即 `s` 的 0 不能凭空变多），就能做到；更直接的做法是双指针贪心。
2. 用指针 `j` 扫 `s`，指针 `i` 扫 `t = strs[k]`：若 `t[i] == '?'` 或 `t[i] == s[j]`，则 `i++`；无论是否匹配，`j++`。
3. 扫完 `s` 后若 `i == n`，说明 `t` 能被 `s` 的子序列「覆盖」，返回 `True`。
4. 以 `s = "101"`、`t = "0?1"` 为例：`j=0,s[0]='1'` 与 `t[0]='0'` 不匹配，`j=1`；`s[1]='0'` 匹配 `t[0]`，`i=1`；`s[2]='1'` 匹配 `t[1]='?'`，`i=2`；`j` 到头，`i=2<3`，但 `t[2]='1'` 未匹配——注意这里 `?` 应吃掉 `s[2]` 的 `1`，`t[2]` 的 `1` 需要另找，实际正确匹配是 `t[0]='0'←s[1]`、`t[1]='?'←s[2]`、`t[2]='1'←s[0]`，贪心需允许 `?` 优先匹配。

修正贪心：`?` 应尽量匹配「难匹配」的字符。更稳的判定是前缀计数条件：对每个前缀，`t` 中 0 的个数 ≤ `s` 中 0 的个数，且 `t` 中 1 的个数 ≤ `s` 中 1 的个数（`?` 可任意填）。因为排序操作只能把 0 前移，`t` 的每个前缀的 0 数不能超过 `s` 同前缀的 0 数。

```python
def ok(s, t):
    n = len(s)
    c0 = c1 = 0
    for i in range(n):
        if t[i] == '0': c0 += 1
        elif t[i] == '1': c1 += 1
        # 前缀中 t 的 0 数不能超过 s 的 0 数
        if c0 > s[:i+1].count('0'): return False
        if c1 > s[:i+1].count('1'): return False
    return True
```

（实际实现用前缀和预存 `s` 的 0/1 计数，避免每步 `count`。）

## 复杂度
时间：每个 `strs[i]` 扫一遍 `n`，总 `O(m·n)`，`m = len(strs)`。
空间：预存 `s` 的前缀 0/1 计数，`O(n)`。

## 易错点
- `s = "101"`、`t = "0?0"`：若把 `?` 当 `0` 后不检查前缀 0 数，会误判 `True`；实际 `t` 前缀 `"00"` 的 0 数 2 > `s` 前缀 `"10"` 的 0 数 1，应返回 `False`。
- `s = "1100"`、`t = "11?1"`：`?` 填 `0` 得 `"1101"`，前缀 `"1101"` 的 1 数 3 > `s` 前缀 `"1100"` 的 1 数 2，误判 `True`；必须同时检查 1 的前缀约束。

## 如果面试官追问
问：若 `strs` 长度到 `2*10^5` 怎么办？答：对 `s` 预存前缀 0/1 计数，每个 `t` 仍 `O(n)`，总 `O(m·n)` 已是最优，除非用位运算加速前缀比较。
