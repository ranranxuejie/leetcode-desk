## 一句话思路
对每个子串区间枚举切点 k，判断「不交换」或「交换」两种拼法能否同时匹配，用记忆化避免重复枚举。

## 怎么做
1. 先剪枝：区间内 s1 与 s2 的字符计数必须相同，否则直接 `False`（用 `Counter` 或长度 26 的数组）。
2. 定义 `f(i, j, L)`：s1 从 i 起、s2 从 j 起、长度 L 的两段是否互为扰乱串。
3. 枚举切点 k（1 ≤ k < L），两种拼法任一成立即可：不交换 `f(i,j,k) and f(i+k,j+k,L-k)`；交换 `f(i,j+L-k,k) and f(i+k,j,L-k)`。
4. 用 `lru_cache` 记忆化，边界 L==1 时直接比较 `s1[i] == s2[j]`。

以 `s1="great", s2="rgeat"` 为例：L=5 时取 k=2，不交换分支要求 `f(0,0,2)`（"gr" vs "rg"）与 `f(2,2,3)`（"eat" vs "eat"）同时成立；前者再取 k=1 走交换分支 `f(0,1,1) and f(1,0,1)`，即 `s1[0]=='g'==s2[1]` 且 `s1[1]=='r'==s2[0]`，返回 `True`。

```python
from functools import lru_cache
from collections import Counter

@lru_cache(None)
def f(i, j, L):
    if L == 1:
        return s1[i] == s2[j]
    if Counter(s1[i:i+L]) != Counter(s2[j:j+L]):
        return False
    for k in range(1, L):
        if f(i, j, k) and f(i+k, j+k, L-k):
            return True
        if f(i, j+L-k, k) and f(i+k, j, L-k):
            return True
    return False
return f(0, 0, len(s1))
```

## 复杂度
时间：状态数 O(n³)（i、j、L 三维），每状态枚举 k 为 O(n)，共 O(n⁴)。
空间：`lru_cache` 存 O(n³) 个布尔值，加每层 Counter 的 O(n) 临时开销。

## 易错点
- 输入 `s1="abcde", s2="caebd"` → 只写不交换分支会漏判、只写交换分支会误判；必须两个分支用 `or` 并列，且交换分支的偏移是 `j+L-k` 与 `j`，写反成 `j+k` 就永远匹配不上。
- 输入 `s1="aab", s2="aba"` 这类有重复字符的串 → 不做字符计数剪枝会枚举大量无效切点，甚至误以为 `f(i,j,k)` 成立；正确做法是进入循环前先比 `Counter`，不等直接 `False`。

## 如果面试官追问
问：n 到 30 以上怎么优化？
答：把 Counter 换成前缀计数数组 O(1) 判等，或改用区间 DP 自底向上按长度递推，省掉递归栈。
