## 一句话思路
用正则 `SN\d{4}-\d{4}` 在 description 上做匹配，关键是加边界防止第 3 行那种「多一位数字」被误判。

## 怎么做
1. 先明确匹配串：`SN` + 恰好 4 位数字 + `-` + 恰好 4 位数字，用 `\d{4}` 而不是 `\d+`。
2. 加边界：前后各用 `(?<![0-9A-Za-z])` 和 `(?![0-9])`，否则 `SN1234-56789` 会被截出 `SN1234-5678` 而误判为有效。
3. 对每行 description 跑 `re.search`，命中则保留该行。
4. 结果按 `product_id` 升序返回。

拿官方示例第 3 行 `Product SN1234-56789 is available now` 走一遍：`\d{4}` 匹配到 `5678` 后，后向断言 `(?![0-9])` 看到下一个字符是 `9`，断言失败，整条不命中——这正是它该被排除的原因。第 1 行 `SN1234-5678` 后面是空格，断言通过，命中。

```python
import re

PAT = re.compile(r'(?<![0-9A-Za-z])SN\d{4}-\d{4}(?![0-9])')

def find_valid_serial_products(products):
    res = [p for p in products if PAT.search(p['description'])]
    return sorted(res, key=lambda p: p['product_id'])
```

注意 `re.search` 而非 `match`：序列号可能不在描述开头（第 2 行 `A product with serial SN9876-1234 in the description` 前面还有文字）。

## 复杂度
时间 O(n·m)，n 为行数、m 为 description 平均长度，正则扫描每行一次。
空间 O(k)，k 为命中行数，排序另占 O(k log k)。

## 易错点
- 输入第 3 行 `SN1234-56789` → 若只写 `SN\d{4}-\d{4}` 会截出 `SN1234-5678` 误判为有效 → 必须加 `(?![0-9])` 后向断言。
- 输入 `XSN1234-5678` 这类前缀粘连 → 若不加 `(?<![0-9A-Za-z])` 会把 `SN` 从单词中间起匹配 → 前向断言要同时排除字母和数字，只排除数字不够。

## 如果面试官追问
问：如果要求返回序列号本身而不只是整行怎么办？
答：把 `PAT.search` 换成 `PAT.findall`，取 `[0]` 放进新列，注意 findall 无捕获组时返回整串。
