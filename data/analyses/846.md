## 一句话思路
按值排序后，用哈希表计数，每次取当前最小值 x，把 x…x+groupSize-1 的计数各减一，缺一个就失败。

## 怎么做
1. 若 `len(hand) % groupSize != 0`，直接返回 `False`。
2. 用 `Counter(hand)` 统计每个值出现次数，并对 `hand` 排序去重得到起点候选。
3. 按升序遍历每个值 x：只要 `cnt[x] > 0`，就以 x 为组首连续消耗 `groupSize` 张牌，中途某值计数不足即返回 `False`。

以示例 1 为例，`hand=[1,2,3,6,2,3,4,7,8]`、`groupSize=3`，计数为 `{1:1,2:2,3:2,4:1,6:1,7:1,8:1}`。从 x=1 起消耗 1、2、3，计数变成 `{2:1,3:1,4:1,6:1,7:1,8:1}`；接着 x=2 消耗 2、3、4；最后 x=6 消耗 6、7、8，全部归零，返回 `True`。

```python
from collections import Counter

cnt = Counter(hand)
if len(hand) % groupSize:
    return False
for x in sorted(cnt):
    c = cnt[x]
    if c == 0:
        continue
    for y in range(x, x + groupSize):
        if cnt[y] < c:
            return False
        cnt[y] -= c
return True
```

关键点：内层一次减 `c`（当前 x 的剩余张数）而不是减 1，因为 x 是当前最小值，所有以 x 开头的组都必须在这里被消耗掉，一次批量处理等价于循环 c 次。

## 复杂度
时间：排序去重 O(u log u)，u 为不同值个数；内层总消耗 O(n·groupSize) 次计数访问，最坏 O(n·groupSize)。
空间：`Counter` 存 u 个键值对，排序后的键列表 O(u)，均为额外开销。

## 易错点
- `hand=[1,2,3,4,5]`、`groupSize=4`：长度 5 不是 4 的倍数，若跳过整除检查直接进循环，会在消耗 1、2、3、4 后剩一个 5 无法成组，逻辑上绕一圈才返回 `False`；正确做法是开头就用 `len(hand) % groupSize` 拦掉。
- `hand=[1,2,3,3,4,5]`、`groupSize=3`：从 1 消耗 1、2、3 后剩 `{3:1,4:1,5:1}`，若遍历时只按原数组顺序而不按值升序，可能先处理 3 再回头发现 1 已无牌可配；正确做法是 `sorted(cnt)` 保证每次取的 x 是当前最小值，且 `cnt[x]` 为 0 时 `continue` 跳过。

## 如果面试官追问
要求输出具体分组方案怎么办？答：把内层减计数改成同时向结果列表 append `[x, x+1, …, x+groupSize-1]`，每组重复 c 次即可，复杂度不变。
