## 一句话思路
用内置 `pow(base, exp, mod)` 做两次快速幂，第一次取模 10 把底数压到个位，第二次取模 `m_i` 与 target 比较。

## 怎么做
1. 遍历 `variables`，解包 `a, b, c, m = variables[i]`。
2. 先算 `base = pow(a, b, 10)`，即 `a^b % 10`，结果必在 0..9。
3. 再算 `val = pow(base, c, m)`，即 `(a^b%10)^c % m`。
4. `val == target` 就把 `i` 加入结果。

以示例 1 下标 0 为例：`a=2,b=3,c=3,m=10`，`pow(2,3,10)=8`，`pow(8,3,10)=512%10=2`，等于 target 2，收下标 0。下标 1 的 `m=1`，`pow(3,3,1)=0`，不等于 2，跳过。

```python
res = []
for i, (a, b, c, m) in enumerate(variables):
    base = pow(a, b, 10)
    if pow(base, c, m) == target:
        res.append(i)
return res
```

关键点：`pow` 的三参数形式内部就是快速幂，`b`、`c` 最大 10^3 也不会真去算 `39^3` 再 `^1000` 这种天文数字。

## 复杂度
时间：O(n · (log b + log c))，n 是 `variables.length`，两次快速幂各贡献 log。
空间：O(1) 额外空间（不计返回的 `res` 列表）。

## 易错点
- 写成 `(a**b % 10)**c % m`：`a=39,b=3` 时 `39**3=59319` 还行，但 `c=1000` 时 `base**1000` 是上千位大数，慢且没必要；正确做法是第二次也用 `pow(base, c, m)` 边乘边取模。
- 忘记 `m_i` 可能为 1：如示例 1 下标 1，`pow(3,3,1)=0`，若误以为模 1 无意义而跳过或报错就错了；`pow` 对 `mod=1` 正常返回 0，直接比较即可。

## 如果面试官追问
问：若 `b_i`、`c_i` 放大到 10^18 呢？
答：`pow` 的复杂度是 O(log exp)，10^18 也只是约 60 次乘法，代码一行不用改。
