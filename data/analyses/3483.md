## 一句话思路
枚举所有下标三元组，用集合去重三位数，靠 `d[0] != 0` 和 `d[2] % 2 == 0` 过滤。

## 怎么做
1. 用 `itertools.permutations(range(len(digits)), 3)` 枚举下标，保证同一位置不重复取数。
2. 对每个下标元组拼出 `a, b, c = digits[i], digits[j], digits[k]`，先判 `a != 0` 再判 `c % 2 == 0`。
3. 通过则把 `a*100 + b*10 + c` 塞进 `set`，重复数字自动合并。
4. 返回 `len(set)`。

以 `digits = [0,2,2]` 为例：下标 `(0,1,2)` 得 `022`，`a == 0` 直接丢弃；`(1,0,2)` 得 `202`，`a=2`、`c=2` 通过；`(1,2,0)` 得 `220` 通过；`(2,0,1)` 得 `202` 与前面重复，集合里仍是 2 个元素，答案 2。

```python
from itertools import permutations

def total_numbers(digits):
    seen = set()
    for i, j, k in permutations(range(len(digits)), 3):
        a, b, c = digits[i], digits[j], digits[k]
        if a == 0 or c % 2:
            continue
        seen.add(a * 100 + b * 10 + c)
    return len(seen)
```

关键是按**下标**枚举而不是按值枚举：`[0,2,2]` 里两个 2 值相同但下标不同，按值枚举会漏掉 `220`，按下标枚举才能让两个 2 分别占百位和个位。

## 复杂度
时间：`O(n^3)`，`n = len(digits) ≤ 10`，最多 720 个排列，每个排列 O(1) 判断。
空间：`O(n^3)` 最坏，`seen` 集合最多存 720 个整数，其余是常数。

## 易错点
- `digits = [0,2,2]` → 若只判 `c % 2 == 0` 不判 `a != 0`，会把 `022` 当成 22 计入，答案错成 3；必须先 `a == 0` 就 `continue`，再判末位奇偶。
- `digits = [6,6,6]` → 若用 `set(digits)` 去重后再枚举，只剩一个 6，凑不出三位数，答案错成 0；正确做法是对**下标**做 `permutations`，让三个 6 各占一位，得到唯一的 `666`。

## 如果面试官追问
问：`digits` 长度放大到 100 怎么办？
答：`O(n^3)` 不可行，改成统计每个数字出现次数，按百位、十位、个位三层计数乘起来，`O(10^3)`。
