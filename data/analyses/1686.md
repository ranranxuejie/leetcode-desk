## 一句话思路
按 `aliceValues[i] + bobValues[i]` 降序轮流取，因为拿走一个石子等于自己得分同时剥夺对方得分，总收益就是这两项之和。

## 怎么做
1. 把下标按 `aliceValues[i] + bobValues[i]` 从大到小排序。
2. 依次遍历排序后的下标，偶数位（第 0、2、4…个）归 Alice，累加 `aliceValues[i]`。
3. 奇数位归 Bob，累加 `bobValues[i]`。
4. 比较两个累加和，返回 `1` / `-1` / `0`。

用示例 3 验证：`aliceValues = [2,4,3]`，`bobValues = [1,6,7]`，和数组是 `[3,10,10]`。排序后下标为 `[1,2,0]`（和 10、10、3）。Alice 取下标 1 得 4，Bob 取下标 2 得 7，Alice 再取下标 0 得 2，最终 Alice = 6、Bob = 7，返回 `-1`，与官方一致。

```python
order = sorted(range(n), key=lambda i: aliceValues[i] + bobValues[i], reverse=True)
a = b = 0
for k, i in enumerate(order):
    if k % 2 == 0:
        a += aliceValues[i]
    else:
        b += bobValues[i]
return 1 if a > b else (-1 if a < b else 0)
```

关键点：排序键必须是**和**而不是单看 `aliceValues[i]`。示例 3 中 Alice 最看重下标 1（值 4），但下标 2 的和也是 10，先抢下标 2 才能压住 Bob 的 7 分。

## 复杂度
时间：排序 O(n log n)，遍历 O(n)，n 是石子个数。
空间：`order` 列表 O(n)，排序本身 O(log n) 栈空间。

## 易错点
- 只按 `aliceValues` 降序排 → 示例 3 会先取下标 1（Alice 得 4），Bob 立刻拿走下标 2 得 7，Alice 最终 6:7 输；正确做法是按 `aliceValues[i] + bobValues[i]` 排序，让 Alice 先拿走「自己拿收益大且对方拿也收益大」的石子。
- 用 `a - b` 的差值贪心或只比较单个数组 → 示例 2 中 `aliceValues = [1,2]`、`bobValues = [3,1]`，和数组 `[4,3]`，Alice 取下标 0 得 1，Bob 取下标 1 得 1，平局返回 0；若按 Alice 值降序会先取下标 1，Bob 拿下标 0 得 3，错判为 -1。

## 如果面试官追问
问：如果要求输出 Alice 和 Bob 各自的具体取子顺序怎么办？
答：排序后按奇偶位直接切分 `order`，前一半位置给 Alice、后一半给 Bob，顺序即最优策略下的取子序列。
