## 一句话思路
排序后，最小值必是某个 lower，枚举它与后面每个数的差作 2k，用哈希表配对验证。

## 怎么做
1. 把 `nums` 升序排序，`nums[0]` 一定属于 lower（最小元素不可能是 arr[i]+k）。
2. 枚举 `nums[j]`（j 从 1 到 n）作为与 `nums[0]` 配对的 higher，则 `k = (nums[j]-nums[0])//2`，差为奇数直接跳过。
3. 用 `Counter` 计数，从前往后扫：对每个未消耗的 `x`，必须消耗一个 `x+2k`，配对成功则 `arr.append(x+k)`，失败则换下一个 j。
4. 第一个完整配对成功的 j 即为答案。

以 `nums = [2,4,6,8,10,12]`（示例 1 排序后）为例：j=1 时 `k=(4-2)//2=1`，扫描时 2 配 4、6 配 8、10 配 12，全部成功，得 `arr=[3,7,11]`。

```python
from collections import Counter
nums.sort()
n = len(nums) // 2
for j in range(1, len(nums)):
    d = nums[j] - nums[0]
    if d % 2: continue
    k, cnt, arr, ok = d // 2, Counter(nums), [], True
    for x in nums:
        if cnt[x] == 0: continue
        if cnt[x + 2 * k] == 0:
            ok = False; break
        cnt[x] -= 1; cnt[x + 2 * k] -= 1
        arr.append(x + k)
    if ok: return arr
```

## 复杂度
时间：排序 O(n log n)，每个候选 k 扫一遍 O(n)，最坏 O(n²)。
空间：`Counter` 存 2n 个计数，O(n)。

## 易错点
- `nums = [1,1,3,3]`：若允许 `k=0`，会配出 `arr=[1,3]`，但题面要求 k 为正整数。差为 0 的候选必须跳过（`d % 2` 挡不住 0，需额外判 `d == 0` 或依赖 `x+2k` 自配失败）。
- `nums = [5,435]`：`d=430`，`k=215`，若写成 `k = d` 而非 `d//2`，会去找 `x+860` 而配不上，返回空。配对时消耗的是 `x+2k`，加回 arr 的是 `x+k`，两个偏移别混。

## 如果面试官追问
问：n 扩大到 10⁵ 还能这么做吗？
答：不能，O(n²) 会超时；需先确定唯一的 k（如用最小值与某个 higher 的差配合频次校验），再线性配对。
