## 一句话思路
答案对初始强度单调，二分答案 + 差分数组 O(n+m) 模拟判定，找最小可行值。

## 怎么做
1. 用差分数组 `diff` 把每条 `boosts[i] = [l, r, v]` 记成 `diff[l] += v`、`diff[r+1] -= v`，前缀和即得每个下标的 bonus。
2. 二分初始强度 `x`，范围 `[0, sum(monsters)]`（全无加成时最多需要总和）。
3. 判定函数：从左到右扫，维护 `cur = x` 和滚动 bonus；若 `cur + bonus < monsters[i]` 返回 `False`，否则 `cur = max(0, cur - monsters[i])`。

以示例 1 为例：`monsters=[5,10,15]`，`boosts=[[1,1,10]]`，差分后 bonus 序列为 `[0,10,0]`。二分到 `x=25` 时：i=0 通过，`cur=20`；i=1 时 `20+10>=10` 通过，`cur=10`；i=2 时 `10+0<15` 失败，故 25 不可行，答案 30。

```python
def check(x):
    cur, bonus = x, 0
    for i, m in enumerate(monsters):
        bonus += diff[i]
        if cur + bonus < m:
            return False
        cur = max(0, cur - m)
    return True

lo, hi = 0, sum(monsters)
while lo < hi:
    mid = (lo + hi) // 2
    if check(mid):
        hi = mid
    else:
        lo = mid + 1
return lo
```

## 复杂度
时间 O((n+m) log S)，S = sum(monsters)，二分 log S 次、每次 O(n+m)。
空间 O(n)，差分数组长度 n+1，其余为常数。

## 易错点
- 判定里 `cur` 必须 `max(0, ...)` 截到 0：若写成 `cur -= monsters[i]` 允许负值，示例 2 中 i=1 后 `cur` 会变成负数，后续 `cur + bonus` 被低估，答案偏大。
- 二分上界不能取 `max(monsters)`：示例 1 中 `max=15`，但 i=2 时 `cur` 已被前两只怪消耗到 0 且无加成，15 不够，必须用 `sum(monsters)=30`。

## 如果面试官追问
问：若要求返回具体每步的初始强度分配方案（即每步剩余强度）？
答：二分出最小 `x` 后，用同一 `check` 逻辑再跑一遍记录每步 `cur` 即可，O(n+m) 额外时间。
