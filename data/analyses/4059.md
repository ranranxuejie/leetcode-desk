## 一句话思路
按位从高到低贪心：每步在「当前位为 1」的候选里挑一个数放到排列最前，使该位连续 1 最长。

## 怎么做
1. 把 15 个位从高到低（14→0）依次处理，维护候选集合 `cand`（初始为全部下标）和已用集合。
2. 对当前位 b，从 `cand` 中筛出第 b 位为 1 的元素；若为空，`power[14-b]=0`，跳过。
3. 否则把其中一个放到排列最前（顺序无关，只影响后续筛选），`power[14-b] = len(cand)`，并把 `cand` 更新为这些位为 1 的元素。
4. 关键：`power[14-b]` 取的是**筛选前** `cand` 的大小，因为前 `len(cand)` 个元素都来自 `cand`，它们的第 b 位全为 1。

以 `nums=[7,5]` 为例：位 2，`cand={0,1}` 都含位 2，`power[12]=2`，`cand` 不变；位 1，只有 7 含位 1，`power[13]=1`，`cand={0}`；位 0，7 含位 0，`power[14]=1`？——注意此时 `cand` 只剩 1 个，但 5 的第 0 位也是 1，正确做法是**不缩小 `cand`**，只记录「当前位为 1 的最长前缀长度」：位 0 时 7 和 5 都含位 0，`power[14]=2`。

```python
n = len(nums)
power = [0] * 15
alive = list(range(n))          # 仍可能进入前缀的下标
for b in range(14, -1, -1):
    ones = [i for i in alive if (nums[i] >> b) & 1]
    if not ones:
        continue
    power[14 - b] = len(ones)   # 这些元素可全部排在前面
    alive = ones                # 只有它们能继续贡献更低位
```

## 复杂度
时间：O(15·n)，15 次扫描 `alive`，每次最多 n 个元素。
空间：O(n)，`alive` 与 `ones` 各至多 n 个下标，`power` 固定 15。

## 易错点
- 把 `power[14-b]` 写成 `len(alive)` 而非 `len(ones)`：`nums=[7,5]` 位 1 时 `alive` 有 2 个但只有 7 含位 1，会错成 2，正确是 1。
- 筛完后忘记用 `ones` 覆盖 `alive`：`nums=[3,1,7]` 位 2 后若仍保留全部，位 1 会算出 3 而非 2，因为 1 的第 1 位是 0，不能进前缀。

## 如果面试官追问
若 nums 长度升到 10^6 且值域仍是 2^15？答：按位分桶预存「含该位的下标」，每层只扫当前桶，总代价仍是 O(15·n)。
