## 一句话思路
枚举 `x` 从 0 到 num，检查 `x + reverse(x) == num`，因为 num ≤ 10^5 时 x 必然不超过 num。

## 怎么做
1. 对每个候选 `x` 从 0 遍历到 `num`，因为 `x + rev(x) ≥ x`，所以 `x > num` 时不可能成立。
2. 写一个 `rev(n)`：循环 `r = r * 10 + n % 10; n //= 10`，前导零自然被丢掉（041 变成 41）。
3. 命中 `x + rev(x) == num` 立即返回 `True`，遍历完返回 `False`。

以 `num = 181` 为例：枚举到 `x = 140` 时，`rev(140)` 循环三次得 `r = 0 → 4 → 41`，`140 + 41 = 181` 命中，返回 `True`。注意 `x = 41` 时 `41 + 14 = 55` 不命中，说明「x 和 rev(x) 谁大谁小」不能假设，必须双向都试。

```python
def rev(n):
    r = 0
    while n:
        r = r * 10 + n % 10
        n //= 10
    return r

for x in range(num + 1):
    if x + rev(x) == num:
        return True
return False
```

关键点：`rev(0)` 返回 0，所以 `num = 0` 时 `x = 0` 命中，返回 `True`，符合「0 + 0 = 0」。

## 复杂度
时间：O(num · log num)，外层 num+1 次，每次 rev 走位数位。
空间：O(1)，只开了 `r`、`x` 两个整型变量。

## 易错点
- 输入 `num = 181` 时若只枚举 `x ≤ num // 2`，会漏掉 `x = 140`（140 > 90）→ 错答 `False` → 正确做法是上界取 `num`，因为 `rev(x)` 可能远小于 `x`，`x` 可以超过一半。
- 输入 `num = 0` 时若循环写成 `range(1, num + 1)` 或特判漏掉 → 错答 `False` → 正确做法是 `range(num + 1)` 从 0 开始，且 `rev(0) = 0` 使 `0 + 0 = 0` 命中。

## 如果面试官追问
问：num 放大到 10^9 怎么办？
答：枚举上界仍是 num，但可只枚举位数不超过 len(num) 的 x，并剪枝 `x + rev(x)` 的位数，实际仍 O(num·log num)，需换数学构造或按位 DP。
