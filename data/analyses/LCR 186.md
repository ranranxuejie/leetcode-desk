## 一句话思路
排序后看相邻非零朝代的差值，用 0 的个数去填缺口，缺口总和不超过 0 的个数即可。

## 怎么做
1. 过滤出非零朝代 `nums`，记 `zeros = 5 - len(nums)`。
2. 对 `nums` 排序，相邻差值 `d = nums[i] - nums[i-1]` 若 `d == 0` 直接返回 `False`（重复朝代不可能连续）。
3. 缺口 `d - 1` 累加到 `gap`，最后判断 `gap <= zeros`。
4. 拿示例 1 `[0, 6, 9, 0, 7]` 走一遍：`nums = [6, 7, 9]`，`zeros = 2`；差值 `1` 和 `2`，缺口 `0 + 1 = 1`，`1 <= 2` 返回 `True`（两个 0 分别补 8 和 5 或 10）。

```python
nums = sorted(x for x in places if x != 0)
zeros = 5 - len(nums)
gap = 0
for i in range(1, len(nums)):
    d = nums[i] - nums[i - 1]
    if d == 0:
        return False
    gap += d - 1
return gap <= zeros
```

关键点：`gap` 只统计「必须填」的空位，`zeros` 是「可自由支配」的未知朝代，多出来的 0 可以往两端延伸，不影响连续性。

## 复杂度
时间：排序 `nums` 贡献 O(k log k)，k ≤ 5，实际 O(1)。
空间：`nums` 最多 5 个元素，O(1)。

## 易错点
- 输入 `[1, 1, 0, 0, 0]` → 若只算 `gap` 不查重复，`gap = 0 <= 3` 会错判 `True` → 必须显式判断 `d == 0` 返回 `False`。
- 输入 `[0, 0, 0, 0, 13]` → 若把 `gap` 和 `zeros` 写成相等判断会错判 `False` → 正确是 `gap <= zeros`，多出的 0 可向两端延伸成 `[9,10,11,12,13]`。

## 如果面试官追问
问：如果 places 长度变成 n、朝代编号范围也变大，怎么做？
答：思路不变，排序 O(n log n) 后扫一遍累加缺口，与 0 的个数比较即可。
