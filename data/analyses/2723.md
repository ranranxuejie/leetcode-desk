## 一句话思路
用 `Promise.all([promise1, promise2])` 等两个 Promise 都解析后，把结果数组的两个元素相加返回。

## 怎么做
1. 把 `promise1`、`promise2` 放进数组交给 `Promise.all`，它返回一个新 Promise，解析值是长度为 2 的数组。
2. 在 `.then` 里解构出 `[a, b]`，直接 `return a + b`，`.then` 的返回值会自动被外层 Promise 采纳。
3. 不需要 `await` 也不需要手动 `new Promise`，`Promise.all` 已经处理了「谁先谁后」的时序问题。

以示例 1 为例：`promise1` 20ms 后解析为 2，`promise2` 60ms 后解析为 5。`Promise.all` 在 60ms 时拿到 `[2, 5]`，`.then` 里 `a=2`、`b=5`，返回 `7`。注意 20ms 时 `promise1` 已就绪但 `Promise.all` 不会提前返回，它等的是最慢的那个。

```python
# 伪代码示意（本题是 JS Promise，Python 用 asyncio 对应）
async def add_two_promises(promise1, promise2):
    a, b = await asyncio.gather(promise1, promise2)
    return a + b
```

JS 版本核心就一行：`return Promise.all([promise1, promise2]).then(([a, b]) => a + b);`

## 复杂度
时间：O(max(t1, t2))，由较慢的那个 Promise 的解析延迟决定，与数值大小无关。
空间：O(1)，只多存一个长度为 2 的结果数组。

## 易错点
- 写成 `promise1.then(a => promise2.then(b => a + b))`：串行等待，示例 1 会拖到 20+60=80ms 才出结果，虽然答案仍是 7，但违背了并行语义；正确做法是 `Promise.all` 让两个计时器同时起跑。
- 忘记 `.then` 里要 `return`：`([a, b]) => { a + b }` 用花括号却没 `return`，外层 Promise 解析成 `undefined` 而非 7；正确写法是箭头函数直接返回表达式，或显式写 `return a + b`。

## 如果面试官追问
问：如果其中一个 Promise 被 reject 怎么办？答：`Promise.all` 会立即以该错误 reject，若想等全部结束再处理，改用 `Promise.allSettled` 后过滤 `status`。
