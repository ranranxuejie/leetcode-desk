## 一句话思路
先求 `max(candies)` 作为基准，再逐个判断 `candies[i] + extraCandies >= 最大值`，因为给某个孩子加糖不会改变其他孩子的糖数。

## 怎么做
1. 用 `m = max(candies)` 记录当前最多糖果数。
2. 遍历 `candies`，对每个 `candies[i]` 计算 `candies[i] + extraCandies`。
3. 若该值 `>= m` 则追加 `True`，否则追加 `False`。
4. 返回结果列表。

以示例 1 为例：`candies = [2,3,5,1,3]`，`extraCandies = 3`，先得 `m = 5`。孩子 4 的 `candies[3] = 1`，`1 + 3 = 4 < 5`，所以 `result[3] = False`；其余孩子加完后分别为 5、6、8、6，都 `>= 5`，结果为 `True`。

```python
m = max(candies)
result = []
for c in candies:
    result.append(c + extraCandies >= m)
return result
```

关键点：基准 `m` 是原始最大值，不是加糖后的最大值。因为只有第 i 个孩子加糖，其他人不变，所以只要 `candies[i] + extraCandies` 达到原始最大值，就能并列最多。

## 复杂度
时间：O(n)，一次求最大值加一次遍历，n 为 `candies` 长度。
空间：O(n)，结果列表占 n 个布尔值，无其他额外空间。

## 易错点
- 输入 `candies = [12,1,12]`、`extraCandies = 10` → 若误用 `>` 而非 `>=`，会把 `12 + 10 = 22` 与 `m = 12` 比较没问题，但若把基准误设为加糖后的最大值会出错；正确做法是基准固定为原始 `max(candies)`，判断用 `>=` 以允许并列最多。
- 输入 `candies = [4,2,1,1,2]`、`extraCandies = 1` → 若在遍历中动态更新最大值，孩子 1 加糖后 `4 + 1 = 5` 会抬高基准，导致后续孩子判断错误；正确做法是先算完 `m` 再遍历，基准不变。

## 如果面试官追问
问：如果要求返回具体分配方案而非布尔数组？答：只需记录每个 `True` 对应的下标 i，表示把 `extraCandies` 全给第 i 个孩子即可。
