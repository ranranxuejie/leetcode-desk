## 一句话思路
逐位累加余数 `rem = (rem * 2 + bit) % 5`，每步判断 `rem == 0`，因为整除性只由余数决定。

## 怎么做
1. 维护余数 `rem`，初值 0，遍历 `nums` 的每个 `bit`。
2. 每步更新 `rem = (rem * 2 + bit) % 5`，把「左移一位再加新位」的十进制值对 5 取模。
3. 把 `rem == 0` 追加进结果列表。

以 `nums = [0,1,1]` 为例：`bit=0` 时 `rem = (0*2+0)%5 = 0` → `True`；`bit=1` 时 `rem = (0*2+1)%5 = 1` → `False`；`bit=1` 时 `rem = (1*2+1)%5 = 3` → `False`。得到 `[True, False, False]`。

```python
rem = 0
ans = []
for bit in nums:
    rem = (rem * 2 + bit) % 5
    ans.append(rem == 0)
return ans
```

关键点：`rem` 始终在 `0..4` 之间，不会随前缀变长而膨胀，所以 `nums.length` 到 `10^5` 也不会出现大整数运算。

## 复杂度
时间 O(n)：遍历 `nums` 一次，每步常数次运算。
空间 O(1)：除输出列表 `ans` 外只开 `rem` 一个变量。

## 易错点
- 输入 `nums = [1,0,1]`（前缀 1,2,5）→ 若先拼出完整整数再 `% 5`，前缀长度到 `10^5` 时整数巨大，Python 虽不溢出但运算变慢 → 正确做法是每步只保留 `rem`，用 `(rem*2+bit)%5`。
- 输入 `nums = [0]` → 若把 `rem` 初值设成非 0 或漏掉首元素判断，会错成 `[False]` → 正确做法是 `rem` 初值 0，且对每个 `bit`（含第一个）都先更新再判断，`0 % 5 == 0` 得 `True`。

## 如果面试官追问
问：若除数不是 5 而是任意 `k`，还能 O(1) 空间吗？
答：能，把 `% 5` 换成 `% k`，`rem` 落在 `0..k-1`，空间仍是 O(1)。
