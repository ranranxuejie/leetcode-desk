## 一句话思路
排序后每三个一组，组内最大差就是 `nums[i+2]-nums[i]`，只要每组都 ≤ k 就成立。

## 怎么做
1. 对 `nums` 升序排序，让相近的数挨在一起。
2. 从下标 0 开始，每次取连续三个 `nums[i], nums[i+1], nums[i+2]` 作为一组。
3. 检查 `nums[i+2] - nums[i] <= k`，不满足立刻返回 `[]`。
4. 全部通过就返回收集到的二维数组。

以示例 2 为例：排序后 `nums = [2,2,2,2,4,5]`。第一组 `[2,2,2]` 差为 0 通过；第二组取 `nums[3..5] = [2,4,5]`，`5 - 2 = 3 > k = 2`，直接返回 `[]`。这正是题面说的「四个 2 必然有一个和 5 同组」。

为什么连续三连是最优：排序后若存在合法划分，把每组的最小元当锚点，任何跨组的交换都只会让组内极差变大，所以按顺序切分不劣于任何方案。

```python
nums.sort()
res = []
for i in range(0, len(nums), 3):
    if nums[i + 2] - nums[i] > k:
        return []
    res.append(nums[i:i + 3])
return res
```

关键点：只比较组内首尾，因为排序后中间元素必然落在 `[nums[i], nums[i+2]]` 之间，差不会超过端点差。

## 复杂度
时间：排序 `O(n log n)` 主导，扫描 `O(n)`。
空间：结果数组 `O(n)`，排序栈开销 `O(log n)`。

## 易错点
- 输入 `nums = [2,4,2,2,5,2], k = 2` → 若按原顺序切 `[2,4,2]` 判 `4-2=2` 通过，但剩下 `[2,5,2]` 里 `5-2=3` 失败，仍返回 `[]` 看似对；换成 `[1,1,3,3,4,5,7,8,9]` 这类数据，不排序就可能把 `1` 和 `9` 分到一组误判失败 → 必须先 `sort()` 再切。
- 输入 `nums = [1,3,4,8,7,9,3,5,1], k = 2` → 若只检查相邻两元素差（`nums[i+1]-nums[i]`）会漏掉首尾差，例如某组 `[1,1,3]` 相邻差都 ≤2 但首尾 `3-1=2` 恰好通过，构造 `[1,2,4]` 时相邻差 1、2 都 ≤2 而 `4-1=3>2` 会误判通过 → 必须用 `nums[i+2]-nums[i]` 判整组。

## 如果面试官追问
若要求返回字典序最小的方案？答：排序后顺序切分本身已使每组元素尽量小且组间递增，即为字典序最小，无需额外处理。
