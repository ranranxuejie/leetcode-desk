## 一句话思路
每批独立向上取整算次数，乘该类型单次耗时累加；批次间清空背包，所以批次之间没有可复用的余量。

## 怎么做
1. 遍历 `fruits`，取出 `t, num = fruits[j]`。
2. 次数用 `(num + limit - 1) // limit` 向上取整。
3. 累加 `time[t] * 次数` 到 `ans`。

以示例 1 的 `[1,4]` 为例：`num=4, limit=3`，次数 `(4+2)//3 = 2`，`time[1]=3`，贡献 `6`；若误用 `4//3=1` 就少算一次。

```python
ans = 0
for t, num in fruits:
    times = (num + limit - 1) // limit
    ans += time[t] * times
return ans
```

关键点：`num` 与 `limit` 都是正数，向上取整公式安全；`fruits[j][0]` 直接当下标用，因为提示保证 `0 <= fruits[i][0] < time.length`。

## 复杂度
时间：O(len(fruits))，每批一次整除一次乘法，与 `time` 长度无关。
空间：O(1)，只开 `ans` 和循环变量。

## 易错点
- `num` 恰为 `limit` 的倍数（如 `num=6, limit=3`）→ 用 `num//limit + 1` 会多算一次 → 必须用 `(num+limit-1)//limit`，得 2 而非 3。
- 把不同批次同类型的果实合并再算（示例 2 的 `[0,3]` 和 `[0,5]` 合并成 8 颗 → 3 次 → 3）→ 错成 3，正确是 `2+3=5`，因为每批结束清空背包，余量不能带到下一批。

## 如果面试官追问
若允许跨批次保留余量怎么改？答：按类型维护剩余果实数，每批先扣余量再向上取整，累加剩余。
