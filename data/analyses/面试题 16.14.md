## 一句话思路
枚举每个点作基准，用最简分数斜率哈希统计共线点数，取最大且编号字典序最小的点对。

## 怎么做
1. 外层 `i` 枚举基准点，内层 `j > i` 枚举其余点，只统计编号大于 `i` 的点，保证每对点只被算一次。
2. 斜率用 `(dy//g, dx//g)` 约分后作键，`g = gcd(abs(dy), abs(dx))`；同时统一符号，让 `dx > 0` 或 `dx == 0 and dy > 0`。
3. 哈希表 `cnt` 记录每个斜率方向上的点数（含基准点自己，初值 1），取最大值 `best`；若 `best > global_best`，更新答案为 `[i, j]`。
4. 因为 `i` 从小到大、`j` 从小到大枚举，第一次达到某个 `best` 时的 `[i, j]` 天然是字典序最小的。

以官方示例 `[[0,0],[1,1],[1,0],[2,0]]` 为例：`i=0` 时，`j=2` 得斜率 `(0,1)`，`j=3` 得斜率 `(0,1)`，`cnt[(0,1)]` 累加到 3，`best=3`，答案锁定 `[0,2]`。

```python
from math import gcd
best_len, ans = 1, [0, 1]
for i in range(n):
    cnt = {}
    for j in range(i + 1, n):
        dy = points[j][1] - points[i][1]
        dx = points[j][0] - points[i][0]
        g = gcd(abs(dy), abs(dx))
        dy //= g; dx //= g
        if dx < 0 or (dx == 0 and dy < 0):
            dy, dx = -dy, -dx
        cnt[(dy, dx)] = cnt.get((dy, dx), 1) + 1
        if cnt[(dy, dx)] > best_len:
            best_len, ans = cnt[(dy, dx)], [i, j]
```

## 复杂度
时间：O(n² log C)，`n²` 对点枚举，`log C` 来自每次 gcd。
空间：O(n)，每个基准点最多开 `n` 个斜率键的哈希表。

## 易错点
- 输入含重复点（如 `[[0,0],[0,0],[1,1]]`）→ `dx=dy=0` 时 `gcd(0,0)=0` 会除零崩溃 → 正确做法是特判 `dx==0 and dy==0` 时直接 `cnt` 记一个哨兵键或跳过约分。
- 斜率不约分直接存 `(dy, dx)` → `(1,2)` 和 `(2,4)` 被当成两条线，`[[0,0],[1,2],[2,4]]` 会错算成 2 而非 3 → 必须先除 `g` 再入表。

## 如果面试官追问
问：点数是 10⁵ 怎么办？答：这题本质是 O(n²) 枚举，规模上去只能靠随机采样或对偶变换，面试中说明复杂度瓶颈即可。
