## 一句话思路
区间 DP：`dp[i][j]` 表示子数组 `stoneValue[i..j]` 上 Alice 能拿到的最大分，按区间长度从小到大递推。

## 怎么做
1. 前缀和 `pre` 使区间和 O(1)：`sum(i,j) = pre[j+1] - pre[i]`。
2. 枚举切点 `k`（`i <= k < j`），左段和 `L = sum(i,k)`，右段和 `R = sum(k+1,j)`。
3. 若 `L < R`，Bob 丢右段，Alice 得 `L` 并继续玩左段：`dp[i][j] = max(dp[i][j], L + dp[i][k])`；若 `L > R` 对称取 `R + dp[k+1][j]`；若 `L == R` 两式都试。
4. 长度 1 的区间 `dp[i][i] = 0`（只剩一块石头，游戏结束）。

以 `stoneValue = [6,2,3,4,5,5]` 为例，`pre = [0,6,8,11,15,20,25]`。算 `dp[0][5]` 时切点 `k=2`：`L = pre[3]-pre[0] = 11`，`R = pre[6]-pre[3] = 14`，`L < R`，候选 `11 + dp[0][2]`；`dp[0][2]` 在 `k=0` 时 `L=6, R=5`，取 `5 + dp[1][2] = 5+2 = 7`，故候选 `11+7 = 18`，正是答案。

```python
n = len(stoneValue)
pre = [0] * (n + 1)
for i, v in enumerate(stoneValue):
    pre[i + 1] = pre[i] + v
dp = [[0] * n for _ in range(n)]
for length in range(2, n + 1):
    for i in range(n - length + 1):
        j = i + length - 1
        for k in range(i, j):
            L = pre[k + 1] - pre[i]
            R = pre[j + 1] - pre[k + 1]
            if L <= R:
                dp[i][j] = max(dp[i][j], L + dp[i][k])
            if R <= L:
                dp[i][j] = max(dp[i][j], R + dp[k + 1][j])
return dp[0][n - 1]
```

## 复杂度
时间：O(n^3)，三层循环分别是区间长度、起点、切点，n ≤ 500 约 1.25e8 次内层操作。
空间：O(n^2) 存 `dp` 表，前缀和额外 O(n)。

## 易错点
- `L == R` 时只写一个分支 → 例如 `[7,7]`，`L=R=7`，若只走 `L <= R` 分支得 `7 + dp[0][0] = 7`，漏掉对称的 `7 + dp[1][1]`；虽然本题两者相等，但 `[7,7,7]` 这类等值区间必须两个分支都试，否则会漏掉更优的后续划分。
- 递推顺序写成 `i` 从 0 到 n、`j` 从 `i` 到 n → 算 `dp[i][j]` 时 `dp[k+1][j]`（`k+1 > i`）还没算出来，读到 0；必须按区间长度 `length` 外层递增，保证子区间先算完。

## 如果面试官追问
问：n 放大到 5000 怎么办？答：O(n^3) 不可行，需利用「切点使两侧和尽量接近」的单调性做 O(n^2) 或记忆化剪枝，但最坏仍退化。
