## 一句话思路
用两个 `threading.Event` 做闸门：`first` 放行 `second`，`second` 放行 `third`，谁先被调度都得等前一道门开。

## 怎么做
1. 在 `Foo.__init__` 里建 `self.e2 = Event()`、`self.e3 = Event()`，初始都是未置位。
2. `first()` 里 `print("first")` 后立刻 `self.e2.set()`，把第二道闸门打开。
3. `second()` 先 `self.e2.wait()` 再打印，打印完 `self.e3.set()`。
4. `third()` 先 `self.e3.wait()` 再打印。

拿示例 2 的 `nums = [1,3,2]` 走一遍：线程 C 先跑 `third()`，此时 `e3` 未置位，C 阻塞在 `wait()`；线程 B 跑 `second()`，`e2` 也未置位，同样阻塞；线程 A 跑 `first()` 打印 `"first"` 并 `e2.set()`，B 被唤醒打印 `"second"` 并 `e3.set()`，C 才被唤醒打印 `"third"`。关键中间值就是 `e2` 从 `False` 变 `True` 那一刻——它决定了 B 能否越过 `wait()`。

```python
import threading

class Foo:
    def __init__(self):
        self.e2 = threading.Event()
        self.e3 = threading.Event()

    def first(self):
        print("first")
        self.e2.set()

    def second(self):
        self.e2.wait()
        print("second")
        self.e3.set()

    def third(self):
        self.e3.wait()
        print("third")
```

注意 `wait()` 必须写在 `print` 之前，`set()` 必须写在 `print` 之后——顺序反了闸门就形同虚设。

## 复杂度
时间：O(1)，三次打印加两次 `set`，与 `nums` 长度无关。
空间：O(1)，只多开两个 `Event` 对象。

## 易错点
1. 把 `self.e2.set()` 写在 `first()` 的 `print` 之前 → 输入 `[1,3,2]` 时 B 可能在 `"first"` 输出前就打印 `"second"`，输出变成 `"secondfirstthird"` → 正确做法是 `print` 在前、`set` 在后，保证前驱动作已完成。
2. 用 `time.sleep` 或固定延时代替 `Event` → 输入 `[1,2,3]` 在慢机器上仍可能乱序，且 `nums` 换成任意排列都无法保证 → 必须用 `Event.wait()` 这种真正的同步原语，让后驱线程阻塞而非空转。

## 如果面试官追问
问：不用 `Event` 还能怎么做？答：用 `threading.Condition` 配一个 `self.stage` 整数，三个方法各自 `while self.stage != k: cond.wait()`，打印后 `stage += 1` 再 `notify_all()`。
