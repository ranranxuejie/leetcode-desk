## 一句话思路
反复把 `s` 按 `k` 切块、每块求数字和再拼回字符串，直到 `len(s) <= k`，因为每轮长度严格变小所以必然终止。

## 怎么做
1. 外层 `while len(s) > k` 控制轮次，内层用 `range(0, len(s), k)` 枚举每块起点。
2. 每块取 `s[i:i+k]`，用 `sum(int(c) for c in ...)` 求数字和，转成 `str` 追加到 `parts`。
3. 拼回 `s = "".join(parts)`，回到步骤 1 判断。

以 `s = "11111222223", k = 3` 为例：第一轮切出 `"111"`、`"112"`、`"222"`、`"23"`，和分别是 3、4、6、5，拼成 `"3465"`；此时 `len("3465") = 4 > 3` 继续，第二轮切出 `"346"`、`"5"`，和为 13、5，拼成 `"135"`，长度 3 不大于 k，返回。

```python
while len(s) > k:
    parts = []
    for i in range(0, len(s), k):
        block = s[i:i + k]
        parts.append(str(sum(int(c) for c in block)))
    s = "".join(parts)
return s
```

关键点：`s[i:i+k]` 在末尾自动截短，不需要单独处理最后一块；`sum` 的结果可能是两位数（如 13），必须 `str()` 而不是 `chr()`。

## 复杂度
时间：每轮 O(len(s))，长度按 k 倍收缩，总 O(n·log_k n)，n 为初始长度。
空间：`parts` 与新旧 `s` 共 O(n)，无递归栈。

## 易错点
- 输入 `s = "00000000", k = 3` → 若把 `sum` 为 0 的块跳过或误判为空串，会少拼出 `"0"`，错成 `"00"` 或 `""`；正确做法是每块无条件 `append(str(sum(...)))`，0 也要拼成 `"0"`。
- 输入 `s = "11111222223", k = 3` → 若循环条件写成 `while len(s) >= k`，第二轮 `"135"` 长度正好 3 还会再切一次，得到 `"9"`，错成 `"9"`；正确做法是严格 `> k`，长度等于 k 时直接返回。

## 如果面试官追问
问：若 s 长度到 10^5 且 k 很小，怎么优化？答：每轮长度至少缩为约 1/3（每 k 个字符最多产生 9k 的两位和），轮数是 O(log n)，总代价仍是 O(n log n)，可预先把字符转 int 数组避免重复 `int(c)`。
