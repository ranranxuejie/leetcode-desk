## 一句话思路
只关心前缀和的奇偶性，用 `odd`/`even` 计数：当前前缀和为奇时，配之前偶数前缀即得奇数子数组。

## 怎么做
1. 初始化 `odd = 0, even = 1, pre = 0, ans = 0`，`even = 1` 代表空前缀和为偶。
2. 遍历 `arr`，`pre ^= x & 1` 只保留前缀和的奇偶位。
3. 若 `pre == 1`，则 `ans += even`，`odd += 1`；否则 `ans += odd`，`even += 1`。
4. 每步 `ans %= 10**9 + 7`。

以 `arr = [1,3,5]` 为例：初始 `even=1`。读 1 后 `pre=1`，`ans += even = 1`，`odd=1`；读 3 后 `pre=0`，`ans += odd = 2`，`even=2`；读 5 后 `pre=1`，`ans += even = 4`，`odd=2`。最终 `ans = 4`，与示例一致。

```python
odd, even, pre, ans = 0, 1, 0, 0
MOD = 10**9 + 7
for x in arr:
    pre ^= x & 1
    if pre:
        ans += even
        odd += 1
    else:
        ans += odd
        even += 1
    ans %= MOD
return ans
```

关键点：`pre` 只存 0/1，`x & 1` 取最低位，异或即翻转奇偶，不需要真的累加 `arr[i]`。

## 复杂度
时间：O(n)，一次遍历 `arr`，每个元素做常数次位运算与加法。
空间：O(1)，只开 `odd`、`even`、`pre`、`ans` 四个标量。

## 易错点
1. `arr = [2,4,6]` → 若把 `even` 初始成 0，第一个元素就配不上空前缀，答案错成 0 之外的数；正确做法是 `even = 1`，因为空前缀和 0 是偶数。
2. `arr = [100,100,99,99]` → 若用 `pre += x` 累加真实和，数值到 10^5 级别虽不溢出但没必要，且容易在取模时把奇偶性搞乱；正确做法是 `pre ^= x & 1`，只保留奇偶位，取模只作用于 `ans`。

## 如果面试官追问
问：若要求返回所有和为奇数的子数组下标对？答：仍需前缀奇偶分组，把 `odd`/`even` 从计数改成存下标列表，遍历时批量配对输出。
