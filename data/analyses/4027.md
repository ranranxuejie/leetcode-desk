## 一句话思路
对请求集合做状压 DP：`dp[mask][i]` 表示已处理 `mask`、最后停在请求 `i` 楼层的最早时刻，因为 n 高达 1e9 只能按请求数 16 枚举。

## 怎么做
1. 把 `start` 当作虚拟起点，`dp[0][i]` 表示从 `start` 直达请求 `i` 的时刻：`max(arrival_i, |start - floor_i|)`。
2. 转移时从 `mask` 里的 `i` 走到 `mask` 外的 `j`：到达时刻 `t = dp[mask][i] + |floor_i - floor_j|`，再取 `max(t, arrival_j)`。
3. 答案取所有 `dp[(1<<m)-1][i]` 的最小值。

用示例 1：`start=0`，请求 0 是 `(0,8)`、请求 1 是 `(6,5)`。`dp[0][1] = max(6, |0-5|) = 6`；从 1 到 0：`6 + |5-8| = 9`，`max(9, 0) = 9`，即 `dp[0b10][0] = 9`，与输出 9 吻合。

```python
m = len(requests)
INF = 10**18
dp = [[INF] * m for _ in range(1 << m)]
for i, (a, f) in enumerate(requests):
    dp[1 << i][i] = max(a, abs(start - f))
for mask in range(1 << m):
    for i in range(m):
        cur = dp[mask][i]
        if cur == INF:
            continue
        fi = requests[i][1]
        for j in range(m):
            if mask >> j & 1:
                continue
            aj, fj = requests[j]
            t = max(cur + abs(fi - fj), aj)
            nm = mask | (1 << j)
            if t < dp[nm][j]:
                dp[nm][j] = t
full = (1 << m) - 1
return min(dp[full])
```

## 复杂度
时间：`O(2^m * m^2)`，`m = len(requests) ≤ 16`，约 1600 万次转移。
空间：`O(2^m * m)` 的 dp 表，约 100 万个 long，与 n 无关。

## 易错点
- 请求到达时间早于电梯到达 → 若写成 `cur + abs(...)` 直接当结果，会漏掉等待。示例 2 中从楼层 7 到 3 是 `2+4=6`，但 `arrival=7`，必须 `max(6,7)=7`，否则输出 6。
- 多个请求同一楼层或 `start` 恰好在某请求楼层 → 若初始化只写 `abs(start-f)` 而忘了 `max(arrival, ...)`，示例 3 的 `(6,3)` 会被算成 0 秒处理，实际要等 6 秒后才可能被处理。

## 如果面试官追问
问：若 `requests.length` 涨到 20 以上怎么办？答：状压 `2^m` 会爆，需换思路（如按到达时间排序后贪心/区间 DP），本题 16 是状压的边界信号。
