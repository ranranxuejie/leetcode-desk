## 一句话思路
分别数 A、B 各自「能删的次数」，Alice 先手，A 的次数严格多于 B 就赢。

## 怎么做
1. 扫描 `colors`，对每段连续相同字符，长度 `L` 贡献 `max(0, L - 2)` 次可删机会。
2. 把贡献按字符累加到 `cntA`、`cntB`。
3. 返回 `cntA > cntB`。

关键中间值：`colors = "ABBBBBBBAAA"`，B 段长 7 贡献 5，A 段长 3 贡献 1，得 `cntA = 1, cntB = 5`，`1 > 5` 为 `False`，与示例 3 一致。

```python
cntA = cntB = 0
i, n = 0, len(colors)
while i < n:
    j = i
    while j < n and colors[j] == colors[i]:
        j += 1
    extra = max(0, j - i - 2)
    if colors[i] == 'A':
        cntA += extra
    else:
        cntB += extra
    i = j
return cntA > cntB
```

为什么成立：删掉一个字符只会让同段长度减 1，不会把两段合并（中间隔着另一种颜色），所以 A 的可删次数恒为 `cntA`，与操作顺序无关；双方各删各的，互不干扰，等价于比谁的总步数多，先手 Alice 只要 `cntA > cntB` 就赢。

## 复杂度
时间 O(n)：一次扫描，`i`、`j` 各只前进不回头。
空间 O(1)：只开了 `cntA`、`cntB`、`i`、`j` 几个整数。

## 易错点
- `colors = "AA"` 或 `"AAA"`：误以为长度 3 能删 1 次就够，但 `"AA"` 的 `L - 2 = 0` 必须用 `max(0, ...)` 兜住，否则 `cntA` 变负数，`"AA"` 会错判成 Alice 赢；正确做法是每段都取 `max(0, j - i - 2)`。
- `colors = "AAAAB"`：只数 A 不数 B，或反过来只判断 `cntA > 0`，会漏掉 Bob 也有步数的情况；必须两个计数都算，比较 `cntA > cntB` 而不是 `cntA > 0`。

## 如果面试官追问
问：如果要求输出 Alice 的具体删除序列怎么办？
答：按段从左到右贪心删中间字符即可，段内顺序不影响胜负，任取一个合法下标输出。
