## 一句话思路
用哈希表统计每个数的出现次数，把计数恰好为 1 的键加起来。

## 怎么做
1. 用 `Counter(nums)` 一次遍历得到每个值的频次，键是数值本身。
2. 遍历 `Counter` 的 `items()`，只累加 `cnt == 1` 的 `val`。
3. 以 `nums = [1,2,3,2]` 为例，`Counter` 得到 `{1:1, 2:2, 3:1}`，筛选后累加 `1 + 3 = 4`。
4. 返回累加结果；若没有频次为 1 的键，自然返回 0（如示例 2 的 `{1:5}`）。

```python
from collections import Counter

cnt = Counter(nums)
ans = 0
for val, c in cnt.items():
    if c == 1:
        ans += val
return ans
```

关键中间值：`nums = [1,2,3,2]` 时 `cnt = {1:1, 2:2, 3:1}`，`2` 的计数是 2 被跳过，`ans` 从 0 加到 1 再到 4。

## 复杂度
时间：O(n)，`Counter` 遍历一遍 `nums`，再遍历至多 n 个不同键。
空间：O(n)，哈希表最多存 n 个不同值（本题值域 ≤100，实际至多 100 个键）。

## 易错点
- 输入 `nums = [1,1,1,1,1]` → 若写成「第一次出现就加、第二次出现再减」的边扫边算，容易在第三次出现时重复减 → 正确做法是先完整统计频次，再统一筛选 `c == 1`。
- 输入 `nums = [2,2,3]` → 若用 `set(nums)` 求和会得到 `2 + 3 = 5`，把重复的 2 也算进去 → 必须用计数而非去重集合，答案应为 3。

## 如果面试官追问
问：如果 `nums` 长度到 10^7 且值域很大，怎么省空间？
答：仍用哈希计数，O(n) 空间不可避免；若值域已知且小，可换数组计数把常数降下来。
