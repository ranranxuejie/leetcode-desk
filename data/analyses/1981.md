## 一句话思路
逐行做 0/1 可达和 DP，用布尔集合记录前 i 行能凑出的所有和，最后在 target 附近找最近的可达和。

## 怎么做
1. 用集合 `reach` 存「处理完前 i 行后所有可能的行和」，初始 `reach = {0}`。
2. 对每一行，把 `reach` 里每个和与这一行每个元素相加，生成新集合 `nxt`，再令 `reach = nxt`。
3. 全部行处理完后，遍历 `reach`，取 `abs(s - target)` 的最小值返回。

以示例 1 `mat = [[1,2,3],[4,5,6],[7,8,9]]`、`target = 13` 为例：第 1 行后 `reach = {1,2,3}`；第 2 行后 `reach = {5,6,7,6,7,8,7,8,9} = {5,6,7,8,9}`；第 3 行后 `reach` 含 `1+5+7 = 13`，故答案为 0。

```python
reach = {0}
for row in mat:
    nxt = set()
    for s in reach:
        for x in row:
            nxt.add(s + x)
    reach = nxt
ans = min(abs(s - target) for s in reach)
return ans
```

关键点：每行**必须且只能**选一个数，所以是「行与行之间做加法」，不是行内组合。集合去重能压掉大量重复和，`m=70, n=70` 时最大和 `70*70=4900`，集合规模被这个上界卡住。

## 复杂度
时间：O(m · n · S)，S 为可达和个数，上界 4900，即每行对每个和枚举 n 个元素。
空间：O(S)，只开一个集合存可达和，S ≤ 4900。

## 易错点
- 输入 `mat = [[1],[2],[3]]`、`target = 100` → 若把「每行选一个」误写成「每行选或不选」或行内求和，会得到 6 之外的和 → 正确做法是每行恰好取一个元素累加，唯一方案和为 6，答案 94。
- 输入 `mat = [[1,2,9,8,7]]`、`target = 6` → 若只保留 `s <= target` 的和（剪枝过头），会漏掉 7 而错答 5（选 1 得 |1-6|=5 其实更小，但若 target 更小如 2，剪掉大于 target 的和会漏掉最优）→ 正确做法是保留全部可达和，最后统一算绝对差，不做单侧剪枝。

## 如果面试官追问
问：若要求输出具体选法而非只返回差值？
答：把集合换成 `dict`，`key` 为和、`value` 为到达该和的上一行选择和，回溯即可还原每行选的列。
