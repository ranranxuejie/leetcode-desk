## 一句话思路
一次遍历，用 `cur` 记录当前递增段的元素和，遇到 `nums[i] <= nums[i-1]` 就重置为 `nums[i]`，全程用 `best` 取最大。

## 怎么做
1. 初始化 `cur = best = nums[0]`，把首元素当作第一个递增段。
2. 从 `i = 1` 开始遍历，若 `nums[i] > nums[i-1]` 则 `cur += nums[i]`，否则 `cur = nums[i]` 另起一段。
3. 每步用 `best = max(best, cur)` 更新答案。
4. 返回 `best`。

以示例 1 `nums = [10,20,30,5,10,50]` 为例：走到 `30` 时 `cur = 60`、`best = 60`；`5 <= 30` 触发重置，`cur` 从 60 掉回 5；随后 `10`、`50` 依次累加，`cur` 变成 65，`best` 更新为 65。

```python
cur = best = nums[0]
for i in range(1, len(nums)):
    if nums[i] > nums[i - 1]:
        cur += nums[i]
    else:
        cur = nums[i]
    best = max(best, cur)
return best
```

关键在重置那一步：`cur = nums[i]` 而不是 `cur = 0` 再补加，否则会漏掉新段的首元素。

## 复杂度
时间：O(n)，`i` 从 1 扫到 `len(nums)-1`，每个元素只被加一次。
空间：O(1)，只开了 `cur`、`best`、`i` 三个标量。

## 易错点
- 输入 `[10,20,30,5,10,50]` → 若在 `5 <= 30` 处写成 `cur = 0` 后忘记加 `nums[i]`，`cur` 会从 0 开始累加 `10,50` 得 60，漏掉 5，答案错成 60 → 正确做法是重置时直接 `cur = nums[i]`。
- 输入 `[12,17,15,13,10,11,12]` → 若把条件写成 `nums[i] >= nums[i-1]`，`15` 之后会被误判为递增，`cur` 一路累加成 90 而非 33 → 题目要求严格递增，必须用 `>`。

## 如果面试官追问
问：如果要求返回这个子数组本身而不只是和？
答：额外记 `start`，重置时更新 `start = i`，`best` 刷新时同步记下 `(start, i)`，最后切片返回。
