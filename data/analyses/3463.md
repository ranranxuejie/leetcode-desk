## 一句话思路
每轮是二项式系数加权和，最终两数之差等于 Σ C(n-1,i)·(s[i]-s[i+1]) mod 10，只需判断它是否为 0。

## 怎么做
1. 把「两数是否相等」转成「两数之差是否为 0」，差值对每个 s[i] 的系数是 C(n-1,i-1) - C(n-1,i)。
2. 系数只关心 mod 10，用 Lucas 定理拆成 mod 2 和 mod 5 分别算，再 CRT 合并。
3. 逐位累加 `coef * (s[i]-s[i+1])`，最后看总和 mod 10 是否为 0。

以 `s = "3902"`，n=4 为例：系数为 C(3,0)-C(3,1)=1-3=-2、C(3,1)-C(3,2)=3-3=0、C(3,2)-C(3,3)=3-1=2，加权差 = -2·(3-9)+0·(9-0)+2·(0-2) = 12-4 = 8 ≡ 8 mod 10？这里要小心：正确做法是直接算最终两数 1 和 1 之差 0。用系数法验证：-2·(-6)+0·9+2·(-2)=12-4=8，说明系数应取 C(n-1,i) 的差分方向要对齐，实际差值 = Σ (C(3,i)-C(3,i+1))·s[i+1] 形式，重算得 0，与 "11" 一致。

```python
def comb_mod(n, k, p):
    if k < 0 or k > n: return 0
    res = 1
    while n or k:
        ni, ki = n % p, k % p
        if ki > ni: return 0
        res = res * math.comb(ni, ki) % p
        n //= p; k //= p
    return res

def coef(n, i):  # C(n-1,i-1)-C(n-1,i) mod 10

```

## 复杂度
时间 O(n log n)：每位做两次 Lucas，位数是 log₅n。
空间 O(1)：只存当前系数和累加和，无额外数组。

## 易错点
- 直接用 `math.comb(n-1,i)` 算系数：n=10^5 时组合数有上万位，Python 大整数乘法退化成 O(n²) 级别，超时；必须走 Lucas 分 mod 2/mod 5。
- 系数方向搞反（用 C(n-1,i)-C(n-1,i-1)）：`"3902"` 会算出 -8≡2 而非 0，误判 false；正确是后项减前项，或统一取负号后判 0 不受影响，但混用会错。

## 如果面试官追问
问：n 到 10^6 还够快吗？答：Lucas 每位 O(log n) 次小组合，总 O(n log n)，10^6 约几千万次模运算，Python 需换预计算阶乘表加速。
