## 一句话思路
排序后从最大边往前扫，用前缀和判断「当前边 < 其余边之和」，第一个成立的集合就是最大周长。

## 怎么做
1. 对 `nums` 升序排序，并求总和 `total`。
2. 从最大的边开始，令 `total` 表示「当前候选集合所有边之和」，检查 `nums[i] < total - nums[i]`。
3. 一旦成立，`total` 就是答案（因为从大往小删边，周长单调递减，第一个成立即最大）。
4. 若扫到 `i == 2` 仍不成立，返回 `-1`。

以示例 2 为例：排序后 `[1,1,2,3,5,12,50]`，`total = 74`。`i=6`：`50 < 24` 假，`total` 减为 24；`i=5`：`12 < 12` 假（严格小于，相等也不行），`total` 减为 12；`i=4`：`5 < 7` 真，返回 12。

```python
nums.sort()
total = sum(nums)
for i in range(len(nums) - 1, 1, -1):
    if nums[i] < total - nums[i]:
        return total
    total -= nums[i]
return -1
```

关键点：`total` 在循环里同步减去被淘汰的边，所以 `total - nums[i]` 始终是「除最长边外其余边之和」，不需要额外前缀和数组。

## 复杂度
时间：排序 `O(n log n)` 主导，扫描 `O(n)`。
空间：排序栈开销 `O(log n)`，无额外数组。

## 易错点
- 输入 `[5,5,50]` → 若把判断写成 `nums[i] <= total - nums[i]`，`50 <= 10` 仍为假没问题，但换成 `[2,2,4]` 会误判 `4 <= 4` 成立返回 8，实际退化不成多边形 → 必须严格 `<`。
- 输入 `[1,1,2,3,5,12,50]` → 若从最小边开始累加、遇到第一个不满足就停，会在 `1+1+2=4 > 3` 处提前返回 4，漏掉更大的 12 → 必须从最大边往前扫，靠「删边」而非「加边」。

## 如果面试官追问
要求输出具体选了哪些边怎么办？
答：返回时把 `i` 之后被减掉的边剔除，剩下的 `nums[0..i]` 就是方案，因为删边顺序已确定。
