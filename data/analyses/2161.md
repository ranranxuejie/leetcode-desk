## 一句话思路
三路稳定划分：按 `<pivot`、`==pivot`、`>pivot` 顺序各扫一遍收集，天然保序。

## 怎么做
1. 建三个空列表 `less`、`equal`、`greater`，一次遍历 `nums` 按与 `pivot` 的大小关系分别 `append`。
2. 因为是从左到右顺序 append，三个列表内部各自保留了原数组的相对顺序，直接满足第 3、4 条要求。
3. 返回 `less + equal + greater`。

以示例 1 的 `nums = [9,12,5,10,14,3,10]`、`pivot = 10` 为例，遍历结束后三个列表分别是 `less = [9,5,3]`、`equal = [10,10]`、`greater = [12,14]`，拼接即得 `[9,5,3,10,10,12,14]`。注意 `12` 在 `14` 之前、`9` 在 `5` 在 `3` 之前，这个顺序完全来自原数组下标，不是排序。

```python
less, equal, greater = [], [], []
for x in nums:
    if x < pivot:
        less.append(x)
    elif x == pivot:
        equal.append(x)
    else:
        greater.append(x)
res = less + equal + greater
```

（`res` 即返回值；`nums` 长度 1e5，三次 append 总计 O(n)。）

## 复杂度
时间 O(n)：一次遍历，每个元素只做一次比较和一次 append。
空间 O(n)：`less`/`equal`/`greater` 合计装下全部 n 个元素，另加结果数组。

## 易错点
- 用 `nums.sort(key=lambda x: (x > pivot) - (x < pivot))` 之类排序写法 → 对 `[9,12,5,10,14,3,10]` 会把 `less` 内部排成 `[3,5,9]`，破坏相对顺序 → 必须用稳定收集而非排序。
- 把 `equal` 合并进 `less` 或 `greater`（如只写 `if x <= pivot`）→ 示例 1 中两个 `10` 会跑到 `less` 尾部，输出 `[9,5,3,10,10,...]` 看似对，但示例 2 的 `pivot=2` 时 `2` 会混进 `less` 段 → 三路必须严格分开。

## 如果面试官追问
追问：要求原地 O(1) 额外空间怎么办？
答：三指针原地分区会打乱相对顺序，需用「先计数再回填」或稳定分区算法，代价是常数变大。
