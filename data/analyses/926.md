## 一句话思路
枚举分界点，用前缀 1 的个数加后缀 0 的个数算翻转代价，取最小。

## 怎么做
1. 设分界点 `i` 表示前 `i` 个字符全变 0、后 `n-i` 个字符全变 1，`i` 从 0 到 `n`。
2. 代价 = 前缀里 `'1'` 的个数（要翻成 0）+ 后缀里 `'0'` 的个数（要翻成 1）。
3. 先统计全串 `'0'` 总数 `zeros`，从左往右扫，维护已见 `'1'` 数 `ones`，扫到位置 `i` 时后缀 0 数 = `zeros - 已见 0 数`。
4. 每步更新 `ans = min(ans, ones + zeros - seen0)`。

以 `s = "00110"` 为例：`zeros = 3`。扫到 `i=4`（前 4 个字符 `"0011"`）时 `ones = 2`、`seen0 = 2`，代价 `2 + 3 - 2 = 3`；扫完整个串 `i=5` 时 `ones = 2`、`seen0 = 3`，代价 `2 + 0 = 2`；而 `i=3` 时 `ones=1`、`seen0=2`，代价 `1+1=2`。真正最优在 `i=4` 之后把最后一位 `'0'` 翻成 `'1'`，代价 1，对应 `i=5` 前一步的 `ones=2, seen0=2` 不是最优——注意 `i=4` 处 `s[4]='0'` 属于后缀，代价应是 `ones + (zeros - seen0) = 2 + (3-2) = 3`，而 `i=5` 时 `ones=2, seen0=3` 得 `2+0=2`。正确答案 1 来自 `i=4` 时把 `s[4]` 翻成 1：`ones=2`（前 4 位两个 1 翻 0）+ 后缀 0 数 1（`s[4]` 翻 1）= 3，仍不是 1。实际最优是 `i=4` 前 `"0011"` 已单调，只需翻 `s[4]='0'→'1'`，代价 1，对应 `i=4` 时 `ones=2` 不对——因为前 4 位 `"0011"` 里两个 1 不用翻。修正：前缀 1 数应只数需要翻的，即 `i` 之前 `'1'` 全翻 0，`"0011"` 的 `ones=2` 确实要翻，代价 2+1=3。真正 1 次翻转是 `i=4` 时把 `s[4]` 翻 1，但前 4 位 `"0011"` 的 1 保留，说明分界点应取 `i=4` 且前缀 1 不翻——矛盾。正确枚举：`i=4` 分界，前 4 位 `"0011"` 视为已单调（0 后跟 1），不需翻，只翻 `s[4]`，代价 1。所以代价公式应为「前缀中 1 的个数」仅在把前缀全变 0 时成立，而最优解允许前缀本身含 1。改用标准 DP：`dp0` = 当前位变 0 的最小代价，`dp1` = 当前位变 1 的最小代价。

```python
dp0 = dp1 = 0
for ch in s:
    if ch == '0':
        dp1 += 1          # 变 1 要翻
    else:
        dp1 = min(dp0, dp1)  # 保持 1，取前态较小
        dp0 += 1          # 变 0 要翻
return min(dp0, dp1)
```

对 `"00110"`：扫完 `dp0=2, dp1=1`，返回 1。

## 复杂度
时间 O(n)，一次遍历每个字符更新两个状态。
空间 O(1)，只开 `dp0`、`dp1` 两个变量。

## 易错点
- 输入 `"010110"` → 若只按「前缀 1 数 + 后缀 0 数」硬套会得 2 但推导易把前缀 1 误算成必翻 → 正确用 `dp1 = min(dp0, dp1)` 允许前缀保留 1。
- 输入全 `"1"` 或全 `"0"` → 若初始化 `dp1` 为 0 且不处理 `'1'` 分支会漏翻 → 全 `"1"` 时 `dp0` 累加到 n、`dp1` 保持 0，返回 0 正确；全 `"0"` 时 `dp1` 累加到 n，返回 0。

## 如果面试官追问
要求输出具体翻转方案？答：在 DP 时记录每步选 `dp0` 还是 `dp1` 的来源，回溯得到每个位置的目标字符，与 `s` 不同处即翻转点。
