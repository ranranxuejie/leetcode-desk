## 一句话思路
树上背包：对每个节点做「父买/父不买」两套预算 DP，再按预算合并子节点。

## 怎么做
1. 把 hierarchy 建成邻接表，从员工 1 开始 DFS，返回两个长度 budget+1 的数组 `dp0`（父未买）和 `dp1`（父已买）。
2. 每个节点先初始化：`dp0` 只放「不买自己」的 0，`dp1` 同理；再分别尝试买自己——`dp0` 用 `present[u]`，`dp1` 用 `present[u]//2`，利润都是 `future[u]-cost`。
3. 对每个子节点 v 递归拿到 `(c0, c1)`，用 `c0` 与当前 `dp0` 做背包合并、`c1` 与当前 `dp1` 合并（子节点是否打折只取决于 u 买没买）。
4. 返回根节点 `dp0` 的最大值。

以示例 4 为例：`present=[5,2,3]`，`future=[8,5,6]`，链 1→2→3，budget=7。员工 2 在父买时成本 `2//2=1`、利润 4；员工 3 在父买时成本 `3//2=1`、利润 5。合并后 `dp1[7]=3+4+5=12`，正是答案。

```python
def dfs(u):
    dp0 = [0] + [-1] * budget      # 父未买
    dp1 = [0] + [-1] * budget      # 父已买
    for cost, gain in ((present[u], future[u]-present[u]),
                       (present[u]//2, future[u]-present[u]//2)):
        pass
    # 买自己：dp0 用原价，dp1 用半价
    for b in range(budget, present[u]-1, -1):
        dp0[b] = max(dp0[b], future[u]-present[u])
    for b in range(budget, present[u]//2-1, -1):
        dp1[b] = max(dp1[b], future[u]-present[u]//2)
    for v in children[u]:
        c0, c1 = dfs(v)
        dp0 = merge(dp0, c0)
        dp1 = merge(dp1, c1)
    return dp0, dp1
```

`merge(a, b)` 是标准分组背包：`res[i+j] = max(res[i+j], a[i]+b[j])`，只枚举 `a[i]!=-1 and b[j]!=-1`。

## 复杂度
时间：O(n·budget²)，每个节点与子节点合并一次背包。
空间：O(n·budget) 递归栈上的 DP 数组，n≤160、budget≤160 可接受。

## 易错点
- 把「父买」状态传给孙子时用错数组：员工 2 买了、员工 3 才打折，但员工 3 的折扣取决于员工 2 是否买，不是员工 1。若在 DFS 里统一用 `dp1` 往下传，示例 4 会算出员工 3 也按半价但员工 2 未买，利润虚高。正确做法是子节点用 `c1` 只在 u 的 `dp1` 分支合并。
- 买自己的循环写成正序：`for b in range(present[u], budget+1)` 会让同一员工被重复买。必须倒序 `range(budget, cost-1, -1)`，和 0/1 背包一致。

## 如果面试官追问
问：budget 放大到 1e5 怎么办？
答：本题利润上界小（future≤50），可把 DP 维度换成「利润→最小成本」，复杂度转为 O(n·总利润²)。
