## 一句话思路
把 requests 排序后，最优路线必是「先扫一侧再折返扫另一侧」，用区间 DP 枚举最后处理的是左端还是右端。

## 怎么做
1. 把 start 并入 requests 一起排序去重，记 start 的下标为 `p`，其余是必须访问的点。
2. 关键观察：已处理的请求在排序后一定构成包含 `p` 的连续区间 `[l, r]`，因为电梯不会跳过中间楼层不处理。
3. 设 `dp[l][r][0/1]` 为处理完 `[l, r]` 且电梯停在左端/右端时的最小惩罚，转移时加上「移动时间 × 剩余未处理请求数」。
4. 用示例 3 验证：排序后 `[0,2,5,9]`，`p=2`。先到 2 用 3 秒，此时剩余 2 个请求，惩罚累加 `3*2=6`；再到 0 用 2 秒，剩余 1 个，累加 `2*1=2`；最后到 9 用 9 秒，累加 `9*1=9`，总计 `6+2+9=17`？注意这里要按「每个请求的完成时刻」算，实际是 `3+5+14=22`，说明转移里乘的是「本段移动影响的请求数」，即从当前时刻起所有未完成请求都多等这段路程。

```python
# 排序后 a，p 为 start 下标，m = len(a)
# dp[l][r][0/1]，初值 inf，dp[p][p][0]=dp[p][p][1]=0
for length in range(1, m):
    for l in range(0, p + 1):
        r = l + length - 1
        if r < p or r >= m: continue
        # 从 [l+1,r] 扩到 l，或从 [l,r-1] 扩到 r
        # 代价 = 移动距离 * (m - (r - l))  剩余未处理数
```

## 复杂度
时间：O(m²)，m 为去重后请求数（≤1501），两层区间枚举。
空间：O(m²) 的 dp 表，可滚动成一维降到 O(m)。

## 易错点
- 忘记把 start 放进排序数组：示例 2 中 start=3 已在 requests 里，若重复插入会多一个点导致区间长度错；正确做法是先去重再定位 `p`。
- 转移时乘的系数写成「已处理数」而非「剩余未处理数」：示例 3 中从 5 到 2 的 3 秒应让剩余 3 个请求各等 3 秒共 9，若乘已处理数会得 0，答案偏小。

## 如果面试官追问
若 n 很大但 requests 稀疏，能否只对请求点建图？答：可以，相邻请求点间距离预计算，DP 状态不变，仍是 O(m²)。
