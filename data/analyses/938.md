## 一句话思路
用 BST 有序性做剪枝 DFS：节点值小于 low 只往右走，大于 high 只往左走，否则累加并两边都走。

## 怎么做
1. 递归函数接收 `node`，返回该子树中落在 `[low, high]` 的和，空节点返回 0。
2. 若 `node.val < low`，左子树全部更小，直接返回对右子树的递归结果。
3. 若 `node.val > high`，右子树全部更大，直接返回对左子树的递归结果。
4. 否则 `node.val` 在范围内，返回 `node.val + 左递归 + 右递归`。

以示例 1 为例，`root = [10,5,15,3,7,null,18]`，`low=7, high=15`：根 10 在范围内，累加 10；左子 5 < 7，剪掉 5 的左子树（3），只递归 7，7 在范围内累加 7；右子 15 在范围内累加 15，15 的右子 18 > 15 被剪掉。最终 `10 + 7 + 15 = 32`。

```python
def dfs(node):
    if not node:
        return 0
    if node.val < low:
        return dfs(node.right)
    if node.val > high:
        return dfs(node.left)
    return node.val + dfs(node.left) + dfs(node.right)
```

关键中间值：访问到 5 时因 `5 < 7` 直接返回 `dfs(7)`，跳过了节点 3，这就是剪枝省下的那次递归。

## 复杂度
时间：最坏 O(n) 遍历全部节点，剪枝后实际访问远少于 n。
空间：递归栈 O(h)，h 为树高，平衡时 O(log n)，退化成链时 O(n)。

## 易错点
- 输入 `root=[10,5,15,3,7,null,18], low=7, high=15` 时若写成无条件遍历全树，会把 3 也访问一遍，虽然结果仍是 32 但丢掉了 BST 剪枝的意义；正确做法是在 `node.val < low` 时只走右子树，`node.val > high` 时只走左子树。
- 输入 `root=[10,5,15,3,7,13,18,1,null,6], low=6, high=10` 时，若把边界判断写成 `node.val <= low` 或 `node.val >= high`，会把 6 或 10 漏掉，答案错成 17 或 13；正确做法是严格用 `< low` 和 `> high` 才剪枝，等于边界时照常累加。

## 如果面试官追问
问：若树不是 BST 而是普通二叉树怎么办？
答：剪枝失效，只能全树 DFS 累加，时间固定 O(n)，无法靠有序性跳过子树。
