## 一句话思路
遍历下标 `i`，用 `i.bit_count()` 数置位，等于 `k` 就把 `nums[i]` 累加进答案。

## 怎么做
1. 初始化 `ans = 0`，用 `enumerate(nums)` 同时拿到下标 `i` 和值 `v`。
2. 对每个 `i` 调 `i.bit_count()` 得到置位数，与 `k` 比较。
3. 相等则 `ans += v`，不等直接跳过。
4. 遍历结束返回 `ans`。

以示例 1 `nums = [5,10,1,5,2], k = 1` 为例，关键中间值：`i=1` 时 `1.bit_count()==1` 命中，`ans` 从 0 变 10；`i=2` 时 `2.bit_count()==1` 命中，`ans` 变 11；`i=3` 时 `3.bit_count()==2` 不命中，`ans` 保持 11；`i=4` 时 `4.bit_count()==1` 命中，`ans` 变 13。`i=0` 的 `bit_count()` 是 0，不命中。

```python
ans = 0
for i, v in enumerate(nums):
    if i.bit_count() == k:
        ans += v
return ans
```

`bit_count()` 是 Python 3.10+ 的内置方法，等价于 `bin(i).count('1')`，但更快且不产生字符串。若环境版本低，可写 `bin(i).count("1")`，本题 `nums.length <= 1000`，两种写法都过。

## 复杂度
时间：O(n log n)，n 是 `nums` 长度，每个下标 `bit_count()` 最多扫 log n 位。
空间：O(1)，只用了 `ans` 一个累加变量，无额外数组。

## 易错点
- 把 `nums[i]` 的值当置位数去数：如示例 1 中 `nums[0]=5` 的 `bit_count()` 是 2，若误用值判断会漏掉或错加元素；正确做法是只对下标 `i` 调 `bit_count()`。
- `k=0` 时忘记下标 0：`0.bit_count()==0` 成立，示例若为 `nums=[7], k=0` 应返回 7；若循环从 1 开始或误判 0 无置位就跳过，会错成 0。

## 如果面试官追问
问：`nums` 长度放大到 10^7 怎么优化？
答：置位数只依赖下标，可预计算 `0..n-1` 的 `bit_count` 或用 `i & (i-1)` 递推 `cnt[i]=cnt[i>>1]+(i&1)`，避免每次重算。
