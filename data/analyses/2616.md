## 一句话思路
排序后二分答案 d，用贪心从左往右扫，能配对就配对，判断能否凑出 p 对。

## 怎么做
1. 先对 `nums` 排序，相邻元素差值最小，最优配对一定在排序后的相邻或近邻位置。
2. 二分答案 `d`，范围 `[0, nums[-1]-nums[0]]`。
3. `check(d)`：从左往右扫，若 `nums[i+1]-nums[i] <= d` 就配对并 `i += 2`，否则 `i += 1`，统计配对数是否 `>= p`。
4. 二分找最小可行 `d`。

以示例 1 为例：`nums = [10,1,2,7,1,3]` 排序后 `[1,1,2,3,7,10]`，`p=2`。检查 `d=1`：`1,1` 差 0 配对，`2,3` 差 1 配对，凑够 2 对，可行；`d=0` 只能配 1 对，不可行，答案 1。

```python
def check(d):
    cnt = i = 0
    while i + 1 < len(nums):
        if nums[i+1] - nums[i] <= d:
            cnt += 1
            i += 2
        else:
            i += 1
    return cnt >= p

nums.sort()
lo, hi = 0, nums[-1] - nums[0]
while lo < hi:
    mid = (lo + hi) // 2
    if check(mid):
        hi = mid
    else:
        lo = mid + 1
return lo
```

## 复杂度
时间：排序 O(n log n)，二分 O(log V) 次，每次 O(n)，共 O(n log n + n log V)。
空间：排序 O(log n) 栈空间，其余 O(1)。

## 易错点
- `p = 0` 时直接返回 0：若仍走二分，`check` 恒真会收敛到 0，但边界 `hi = nums[-1]-nums[0]` 在 `n=1` 时是 0，`lo<hi` 不成立也返回 0，逻辑上没问题；真正坑是 `n=1, p=0` 时 `nums[-1]` 合法但循环不进入，需确认返回 0 而非报错。
- 贪心配对时 `i += 2` 而非 `i += 1`：若写成 `i += 1`，`[1,1,2]` 检查 `d=0` 会重复用下标 1，导致 `cnt` 虚高，把不可行判成可行。

## 如果面试官追问
要求输出具体配对方案怎么办？答：`check` 里记录每对下标，二分收敛后重跑一次 `check(lo)` 收集结果即可。
