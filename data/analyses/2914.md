## 一句话思路
按相邻两字符分组，每组内两字符不同就改一次，因为美丽串的每个偶数长度块必然由成对的相同字符组成。

## 怎么做
1. 把 s 按 `(s[0],s[1])`、`(s[2],s[3])`… 切成 n/2 个长度为 2 的相邻对。
2. 每对内部若两字符不同，必须改其中一个（改哪个都行，代价都是 1），累加进答案。
3. 对与对之间不做任何约束：`"11"` 后面接 `"00"` 或 `"11"` 都合法，所以不需要跨对比较。

以 `s = "1001"` 为例：对 `(1,0)` 不同 → +1；对 `(0,1)` 不同 → +1，答案 2。中间值就是这两次 `s[i] != s[i+1]` 的判定，i 取 0 和 2。

```python
ans = 0
for i in range(0, len(s), 2):
    if s[i] != s[i + 1]:
        ans += 1
return ans
```

关键点：为什么按 2 切就够？美丽串的每个子串长度是偶数且字符全同，那么任意一个长度偶数的全同块，从下标 0 开始每两位必然相同。反过来，只要每个 `(s[2k], s[2k+1])` 相同，整串就能按这些对切成 `"11"|"00"|...` 形式，每块长度 2 且字符单一，满足定义。所以「每对相同」既是必要条件也是充分条件，逐对独立计数即最优——不存在改一个字符同时修好两对的情况，因为对与对之间没有共享下标。

## 复杂度
时间 O(n)：一次遍历，n 为 `len(s)`，每步只做一次字符比较。
空间 O(1)：只用 `ans` 和循环变量 `i`，没有额外数组。

## 易错点
- 输入 `"10"`：若误以为要整串统一成一种字符，会算成 1 次但理由错（以为要全变 0 或全变 1）；正确做法是只看这一对 `(1,0)` 不同，改 1 位得 `"11"` 或 `"00"`，答案 1，与整串统一恰好同值但逻辑不同，别把逻辑写死成「统计 0 和 1 谁少」。
- 输入 `"0000"`：若循环写成 `range(0, len(s)-1)` 步长 1 去比较所有相邻位，会把 `s[1]!=s[2]` 这类跨对边界也算进去，得到错误答案；正确做法是 `range(0, len(s), 2)`，只比较对内的 `s[i]` 与 `s[i+1]`。

## 如果面试官追问
若要求输出修改后的字符串而非次数？答：对每个不同的对，把 `s[i+1]` 改成 `s[i]` 即可，逐对就地改，仍 O(n) 且不改动对边界。
