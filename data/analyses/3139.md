## 一句话思路
枚举最终目标值 `t`，每个 `t` 下用「配对优先」算最小开销，取最小；`t` 只需枚举到 `max(nums) + 2`。

## 怎么做
1. 先判 `cost2 >= 2*cost1`：此时配对不比两次单加便宜，答案直接是 `sum(max(nums)-x) * cost1`。
2. 否则对每个候选 `t` 计算总增量 `total = sum(t - x)` 和最大单元素增量 `mx = t - min(nums)`。
3. 配对次数上限是 `total // 2`，但受 `total - mx` 限制（最大缺口不能自己和自己配），实际配对 `p = min(total // 2, total - mx)`，剩下 `total - 2p` 次单加。
4. 开销 `p*cost2 + (total-2p)*cost1`，对所有 `t` 取最小。

以示例 2 `nums=[2,3,3,3,5], cost1=2, cost2=1` 为例，`t=5` 时 `total=3+2+2+2+0=9`，`mx=5-2=3`，`p=min(4, 9-3)=4`，剩 1 次单加，开销 `4*1+1*2=6`，正是答案。

```python
MOD = 10**9 + 7
n = len(nums)
lo, hi = min(nums), max(nums)
if cost2 >= 2 * cost1:
    return (sum(hi - x for x in nums) * cost1) % MOD
best = float('inf')
for t in range(hi, hi + 3):
    total = sum(t - x for x in nums)
    mx = t - lo
    p = min(total // 2, total - mx)
    best = min(best, p * cost2 + (total - 2 * p) * cost1)
return best % MOD
```

## 复杂度
时间：O(n) 求 min/max/sum，枚举 3 个 `t` 各 O(n)，共 O(n)。
空间：O(1)，只存 `total`、`mx`、`p` 等标量。

## 易错点
- 只枚举到 `max(nums)`：示例 2 里 `t=5` 恰好是最优，但若 `cost2` 很便宜，抬到 `max+1` 能让最大元素也参与配对，开销更低；正确做法是枚举 `hi` 到 `hi+2`。
- 忘记 `p = min(total//2, total-mx)` 的上界：`nums=[1,1,1,100]` 时 `total` 很大但 `mx` 接近 `total`，若直接取 `total//2` 会多算配对，实际只能配 `total-mx` 次，剩下全靠单加。

## 如果面试官追问
问：为什么枚举到 `max+2` 就够？答：目标值再往上，每加 1 所有元素增量同增 n，配对结构不变，开销线性增长，不会更优。
