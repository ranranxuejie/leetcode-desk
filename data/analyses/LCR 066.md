## 一句话思路
用哈希表存 key→val，`sum` 时遍历所有 key 做 `startswith` 前缀匹配并累加，规模只有 50 次调用，够用。

## 怎么做
1. `insert` 直接 `self.d[key] = val`，天然覆盖旧值。
2. `sum` 遍历 `self.d.items()`，用 `k.startswith(prefix)` 过滤。
3. 命中的累加 `v` 返回；无命中返回 0。

以官方示例走一遍：`insert("apple",3)` 后 `d={"apple":3}`；`sum("ap")` 遍历到 `"apple".startswith("ap")` 为 `True`，累加得 3。再 `insert("app",2)`，`d={"apple":3,"app":2}`；`sum("ap")` 两个 key 都命中，`3+2=5`。

```python
class MapSum:
    def __init__(self):
        self.d = {}

    def insert(self, key, val):
        self.d[key] = val

    def sum(self, prefix):
        return sum(v for k, v in self.d.items() if k.startswith(prefix))
```

关键中间值：第二次 `sum("ap")` 时，`"apple"` 贡献 3、`"app"` 贡献 2，生成器产出 `[3, 2]`，`sum` 得 5。

## 复杂度
时间：`insert` O(1)；`sum` O(m·L)，m 为已插入 key 数、L 为前缀长度，`startswith` 逐字符比较。
空间：O(m·L)，哈希表存下所有 key 字符串本身。

## 易错点
- 重复插入同一 key：`insert("apple",3)` 后再 `insert("apple",5)`，若用 `d.setdefault` 或列表追加会保留旧值 3，`sum("ap")` 错成 8；正确做法是直接赋值覆盖，结果应为 5。
- 前缀恰好等于某个 key：`insert("app",2)` 后 `sum("app")`，若误用 `k.startswith(prefix) and k != prefix` 会漏掉 `"app"` 自身，错成 0；`startswith` 本身包含相等情形，不要额外排除。

## 如果面试官追问
若 key 数量涨到 10^5、`sum` 调用也到 10^5，哈希表遍历会超时，怎么办？
答：改用字典树，每个节点维护 `sub_sum`，`insert` 沿路径更新差值，`sum` 走到前缀末尾直接返回该节点 `sub_sum`，均摊 O(L)。
