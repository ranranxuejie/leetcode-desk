## 一句话思路
按值从小到大处理，用树状数组维护「还没删的元素」的位置，累计每次从当前指针走到下一个最小值要跨过多少活元素。

## 怎么做
1. 把 `nums` 按值排序得到下标序列 `order`，`pos[v]` 记录值 v 在原数组的下标。
2. 树状数组 `bit` 初始全 1，表示每个位置都还在；`cur` 是当前队首在原数组中的下标，初始 0。
3. 对 `order` 里每个下标 `p`：若 `p >= cur`，跨过的是 `[cur, p]` 的活元素数；否则绕一圈，是 `[cur, n-1]` 加 `[0, p]`。
4. 把这段计数累加进答案，再在 `bit` 里把 `p` 置 0，令 `cur = p`。

以 `nums = [3,4,-1]` 为例：`order = [2,0,1]`。第一步 `p=2, cur=0`，区间 `[0,2]` 活元素 3 个，答案 3，删掉下标 2，`cur=2`。第二步 `p=0 < cur=2`，绕圈计数 `[2,2]`+`[0,0]` = 1+1 = 2，答案 5，删掉下标 0。第三步 `p=1`，`[1,1]` 剩 1 个，答案 6？——注意最后一步删最小值本身也算一次操作，但此时 `p=1` 已被前一步的绕圈覆盖，实际答案是 5，因为删 `-1` 那一步的「移动」和「删除」合并计 1。关键修正：每次累加的是「移动到 p 的操作数」，删除操作单独 +1，即总答案 = 移动总数 + n。

```python
order = sorted(range(n), key=lambda i: nums[i])
bit = [0] * (n + 1)
for i in range(1, n + 1):
    bit[i] += 1
    j = i + (i & -i)
    if j <= n:
        bit[j] += bit[i]
ans, cur = n, 0
for p in order:
    if p >= cur:
        moved = query(p) - query(cur - 1)
    else:
        moved = query(n - 1) - query(cur - 1) + query(p)
    ans += moved - 1
    update(p, -1)
    cur = p
```

## 复杂度
时间：排序 O(n log n)，每个元素两次树状数组操作 O(log n)，共 O(n log n)。
空间：`order`、`bit` 各 O(n)，无递归栈。

## 易错点
- `nums = [1,2,3]` 已升序：若把「删除」也当成一次移动累加，会得 6 而非 3；正确做法是每次只加 `moved - 1`（移动步数），删除的 n 次在初始化 `ans = n` 里一次给足。
- `nums = [3,4,-1]` 中 `p=0 < cur=2` 的绕圈：若只写 `query(p) - query(cur-1)` 会得负数；必须拆成 `[cur, n-1]` 与 `[0, p]` 两段相加。

## 如果面试官追问
若要求输出每一步的数组状态而非操作数？答：同样按值序模拟，用有序集合定位 `cur` 到 `p` 之间活元素个数，逐个弹出并记录即可，复杂度不变。
