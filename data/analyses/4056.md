## 一句话思路
按起点排序后，用「已结束区间数」做差：相交对数 = 总对数 − 完全在左侧（end < 当前 start）的区间数。

## 怎么做
1. 把 `intervals` 按 `start` 升序排序，得到 `iv`。
2. 维护一个最小堆 `heap`，存已处理区间的 `end`。
3. 对每个 `[s, e]`，弹出所有 `heap[0] < s` 的 `end`，堆大小就是与当前区间相交的左侧区间数，累加。
4. 把 `e` 压入堆。

以示例 1 `[[1,2],[2,3],[3,4]]` 为例：处理 `[2,3]` 时堆里是 `[2]`，`2 < 2` 为假不弹出，堆大小 1，累加 1；处理 `[3,4]` 时堆是 `[2,3]`，弹出 `2`（`2 < 3`），剩 `[3]`，累加 1，合计 2。

```python
iv = sorted(intervals)
heap, ans = [], 0
for s, e in iv:
    while heap and heap[0] < s:
        heapq.heappop(heap)
    ans += len(heap)
    heapq.heappush(heap, e)
return ans
```

关键点：`heap[0] < s` 用严格小于，因为 `end == start` 时共享端点仍算相交，不能弹出。

## 复杂度
时间：排序 O(n log n) + 每个区间入堆出堆各一次 O(n log n)，共 O(n log n)。
空间：堆最多存 n 个 `end`，O(n)。

## 易错点
- 输入 `[[1,2],[2,3]]` → 若写成 `heap[0] <= s` 会把 `end=2` 弹出，漏算共享端点这一对，输出 0；正确用 `heap[0] < s`，输出 1。
- 输入 `[[1,5],[2,4],[3,6]]` → 若只按 `end` 排序或只比较相邻区间，会漏掉 `[1,5]` 与 `[3,6]`；必须先按 `start` 排序，再用堆统计所有 `end >= s` 的左侧区间。

## 如果面试官追问
问：n 扩大到 10^5 且要求输出所有相交对？
答：相交对可能 O(n²)，只能按需枚举；用堆弹出时记录被弹出的区间下标即可，输出规模决定复杂度。
