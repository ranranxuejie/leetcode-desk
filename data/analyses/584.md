## 一句话思路
用 `referee_id IS NULL OR referee_id != 2` 过滤，因为 `NULL != 2` 在 SQL 里结果是 `NULL` 而非 `True`，必须显式补上 `IS NULL`。

## 怎么做
1. 在 `WHERE` 里写 `referee_id IS NULL OR referee_id != 2`，两个条件用 `OR` 连接。
2. 只 `SELECT name`，因为题目只要姓名，`id` 和 `referee_id` 不进结果。
3. 顺序任意，不加 `ORDER BY`。

拿官方示例走一遍：`referee_id` 依次是 `None, None, 2, None, 1, 2`。逐行判断——Will 的 `None` 命中 `IS NULL`，保留；Alex 的 `2` 两个条件都不成立，丢弃；Zack 的 `1` 命中 `!= 2`，保留。最终留下 Will、Jane、Bill、Zack 四行，与输出一致。

```python
# 伪 SQL 逻辑，用 Python 表达过滤条件
rows = [(1, "Will", None), (2, "Jane", None), (3, "Alex", 2),
        (4, "Bill", None), (5, "Zack", 1), (6, "Mark", 2)]
ans = [name for _, name, r in rows if r is None or r != 2]
# ans == ["Will", "Jane", "Bill", "Zack"]
```

关键点：`r is None or r != 2` 的短路顺序不能反。若写成 `r != 2 or r is None`，在 Python 里 `None != 2` 是 `True`，结果碰巧对；但在 SQL 里 `NULL != 2` 是 `NULL`，`NULL OR TRUE` 才是 `TRUE`，`NULL OR FALSE` 仍是 `NULL`，所以 SQL 必须把 `IS NULL` 单独列出来。

## 复杂度
时间：O(n)，n 为 Customer 行数，每行只做一次常数次比较。
空间：O(1) 额外空间，结果集不计入。

## 易错点
- 只写 `referee_id != 2` → 所有 `referee_id` 为 `NULL` 的行（Will、Jane、Bill）被 `NULL` 比较结果吞掉，输出只剩 Zack → 必须加 `referee_id IS NULL OR`。
- 写成 `referee_id <> 2 AND referee_id IS NOT NULL` → 把「没被推荐」的客户全排除，输出只剩 Zack → 两个条件应是 `OR` 不是 `AND`，`IS NULL` 是「要保留」不是「要排除」。

## 如果面试官追问
问：如果要求按 `id` 升序输出并去重姓名？答：加 `ORDER BY id`，姓名重复时用 `DISTINCT name` 或 `GROUP BY name` 取最小 `id`。
