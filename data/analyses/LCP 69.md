## 一句话思路
对每个单词预处理「取某字母子集的最小代价」，再按 13 个目标字母的计数做多重背包状压 DP。

## 怎么做
1. 统计 `helloleetcode` 的字母需求：`e` 4 个、`l` 3 个、`o` 2 个，`h/c/t/d` 各 1 个，其余为 0。
2. 对每个单词，枚举要取哪些位置（`m ≤ 8`，至多 256 种），按「从右往左删」的顺序算代价：删掉位置 `i` 时，左右剩余字母数之积就是代价。
3. 把每个单词的每种取法折算成一个 13 维计数向量，超出需求的直接丢弃，作为一次「物品」。
4. 用字典做 DP，键是已收集的计数向量（编码成整数），值是当前最小代价，逐个单词合并。

以 `words = ["hold","engineer","cost","level"]` 为例，`engineer` 取第 1 个 `e` 和最后一个 `e`：先删末尾 `e`，此时左边 7 个字母、右边 0 个，代价 `7*0=0`；再删第 1 个 `e`，左边 0 个、右边 5 个，代价 `0*5=0`。而示例里说最后那个 `e` 代价 `5*1=5`，是因为它先删了别的字母——顺序不同代价不同，所以枚举子集时必须固定一种删除顺序（从右往左）才能保证算的是该子集的真实最小代价。

```python
need = [0]*26
for ch in "helloleetcode": need[ord(ch)-97] += 1
# 对单词 w 枚举 mask，从右往左删，累加代价
for mask in range(1 << len(w)):
    s, cost = list(w), 0
    for i in range(len(w)-1, -1, -1):
        if mask >> i & 1:
            cost += (i) * (len(s)-1-i)   # 左边 i 个，右边剩余
            s.pop(i)
    # 统计 s 中字母，若不超过 need 则作为物品
```

## 复杂度
时间：`O(n * 2^m * m + 状态数 * 物品数)`，`n` 是单词数、`m ≤ 8` 是单词长度。
空间：`O(状态数)`，状态数是各字母需求数乘积（约 `5*4*3*2^4` 量级），额外只存一个字典。

## 易错点
- 对 `"engineer"` 若按从左往右删算代价，会得到与示例不符的值（示例是 `0` 和 `5`），因为删除顺序改变左右字母数；正确做法是固定从右往左删，保证每个子集代价唯一且最小。
- 需求是 `e` 4 个、`l` 3 个，若把 `helloleetcode` 当成字母去重集合（`e` 只算 1 个），DP 状态维度会少算，导致 `["hello","leetcode"]` 这种刚好凑齐的输入被判成 `-1`；正确做法是按 `need` 数组逐字母计数。

## 如果面试官追问
问：单词数 `n` 增大到几百怎么办？
答：单词语义独立，可先对每个单词只保留「帕累托最优」的取法（同向量取代价最小），再合并，状态数不随 `n` 线性膨胀。
