## 一句话思路
把「删 k 个路标」看成把 n-1 段路划分成 n-1-k 个连续块，块内 time 求和、块长取 position 差，用区间 DP 求最小总时间。

## 怎么做
1. 关键观察：合并 i 与 i+1 后新 time 是两段之和，所以连续合并一段区间 `[i, j)` 的路标后，这段路每公里时间恰为 `sum(time[i:j])`，长度恰为 `position[j] - position[i]`。
2. 于是问题等价于：把下标 0..n-1 切成 `m = n - k` 个连续段（每段至少 2 个端点），最小化 `Σ (position[j]-position[i]) * sum(time[i:j])`。
3. 定义 `dp[t][j]` = 前 j 个路标切成 t 段的最小代价，枚举上一段起点 i：`dp[t][j] = min(dp[t-1][i] + (position[j]-position[i]) * (pre[j]-pre[i]))`。
4. 以示例 1 为例，`pre = [0,5,13,16,22]`，k=1 即 m=3 段。取 `dp[2][2]` 时 i=0 得 `0 + (8-0)*(13-0)=104`；最终最优切法 0|2|4 得 `8*5 + 2*11 + 2*6 = 62`，对应删掉下标 1。

```python
pre = [0] * (n + 1)
for i in range(n):
    pre[i + 1] = pre[i] + time[i]
m = n - k
INF = float('inf')
dp = [[INF] * (n + 1) for _ in range(m + 1)]
dp[0][0] = 0
for t in range(1, m + 1):
    for j in range(2 * t, n + 1):
        for i in range(2 * (t - 1), j - 1):
            cost = (position[j - 1] - position[i]) * (pre[j - 1] - pre[i])
            dp[t][j] = min(dp[t][j], dp[t - 1][i] + cost)
return dp[m][n]
```

## 复杂度
时间 O(m·n²)，m = n-k ≤ 50，n ≤ 50，约 1.25e5 次转移。
空间 O(m·n) 的 dp 表，前缀和 pre 额外 O(n)。

## 易错点
- 段数算错：k 次合并后剩 `n-k` 个路标、`n-k-1` 段路，若把 m 写成 `n-k-1` 会少算一段，示例 1 会得到 40 而非 62。正确做法是令 `m = n - k` 表示「切成的段数」，j 从 `2*t` 起枚举保证每段至少两个端点。
- 下标错位：`position` 与 `time` 长度都是 n，但 time[i] 描述的是 position[i] 到 position[i+1] 的段，用 `position[j-1]-position[i]` 配 `pre[j-1]-pre[i]`；若写成 `position[j]-position[i]` 会越界或把最后一段长度算成 0。

## 如果面试官追问
问：n 放大到 10^5 怎么办？
答：这个 O(n²k) 转移不成立，需要换思路（如凸包/决策单调性优化），但本题 n≤50 无需。
