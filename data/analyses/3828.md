## 一句话思路
答案只由 n 的奇偶和数组最值决定：n 为奇数时 Alice 只能保下最小值，n 为偶数时保下最大值。

## 怎么做
1. 先看 n = len(nums)：n == 1 时无人可动，直接返回 nums[0]。
2. 关键观察是每轮至少删 1 个、至多删 m-1 个，所以玩家无法一次性清空数组，只能决定「留下哪一段」。
3. 用示例 1 走一遍：nums = [1,5,2]，n = 3 为奇数，Alice 先手删 [1] 得 [5,2]，Bob 删 [5] 得 [2]，最终 2 = min(nums)。
4. 用示例 2 走一遍：nums = [3,7]，n = 2 为偶数，Alice 删 [3] 直接剩 [7]，7 = max(nums)。

```python
def finalElement(nums):
    n = len(nums)
    if n == 1:
        return nums[0]
    if n % 2 == 0:
        return max(nums)
    return min(nums)
```

为什么奇偶决定一切：n 为偶数时，Alice 第一步就能把数组削到只剩 1 个元素（删掉除目标外的 n-1 个，n-1 < n 合法），她直接挑最大值，Bob 没有回合。n 为奇数时，Alice 第一步后剩偶数个，Bob 同样能一步削到 1 个，于是 Bob 挑最小值。所以中间过程不用模拟。

## 复杂度
时间：O(n)，一次 max 和一次 min 各扫一遍数组，n 来自 nums 长度。
空间：O(1)，只存 n 和返回值，没有额外数组。

## 易错点
- 输入 nums = [5]（n = 1）→ 若直接套奇偶规则会返回 min(nums) = 5 看似对，但逻辑上此时没有回合，必须单独 return nums[0]，否则遇到 n = 1 且后续扩展规则时会误判。
- 输入 nums = [1,5,2]（n 为奇数）→ 若误以为先手 Alice 总能拿最大值会返回 5，实际 Bob 后手一步削到 1 个，正确返回 min = 2；判断依据是 n % 2，不是谁先手。

## 如果面试官追问
问：如果要求输出最终元素的下标而非值？答：偶数 n 取 argmax，奇数 n 取 argmin，同样 O(n) 一遍扫描记录下标即可。
