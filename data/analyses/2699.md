## 一句话思路
把 -1 先全设成 1 跑 Dijkstra，若最短路已超 target 则无解，否则按需逐条放大 -1 边。

## 怎么做
1. 所有 `w == -1` 的边先赋 1，跑一次 Dijkstra 得 `dist`；若 `dist[destination] > target` 直接返回 `[]`。
2. 若 `dist[destination] == target`，当前赋值即答案，直接返回。
3. 否则按 `edges` 顺序遍历每条 -1 边 `(a,b)`，用 `d = target - dist[destination]` 算需要补的量，把这条边改成 `1 + d`，再重跑 Dijkstra。
4. 每改一条后若 `dist[destination] == target` 就停；遍历完仍不等则返回 `[]`。

以示例 1 为例：四条边全 -1，先全设 1，`dist[1] = 2`（0-2-1 或 0-3-4-1 都是 2），小于 target=5。第一条 `(4,1)` 需补 `5-2=3`，改成 `1+3=4`，重跑后 `dist[1]` 变成 0-3-4-1 的 `1+1+4=6`？此时 0-2-1 仍是 2，故 `dist[1]=2` 没变——继续下一条 `(2,0)` 补 3 改成 4，`dist[1]` 变 5，命中。

```python
import heapq
def dijkstra(n, adj, s):
    dist = [float('inf')] * n
    dist[s] = 0
    pq = [(0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]: continue
        for v, w in adj[u]:
            if d + w < dist[v]:
                dist[v] = d + w
                heapq.heappush(pq, (dist[v], v))
    return dist
```

关键循环：`for i,(a,b,w) in enumerate(edges): if w==-1: edges[i][2] = 1 + target - dist[destination]; 重建 adj; dist = dijkstra(...)`。

## 复杂度
时间：每条 -1 边重跑一次 Dijkstra，O(k·(E log V))，k 为 -1 边数，log 来自堆。
空间：邻接表 O(E)，dist 与堆 O(V+E)。

## 易错点
- 示例 2 中 `(0,1,-1)` 设 1 后 `dist[2]=5 < 6`，但 0-1 这条边无论怎么放大都只影响经过 1 的路径，而 0-2 直连 5 已是最短，放大 -1 边只会让 `dist[2]` 变大到 6 吗？不会——0-1 放大后 0-2 仍走直连 5，永远到不了 6，正确做法是遍历完所有 -1 边后 `dist[destination] != target` 就返回 `[]`，别在循环里提前 return 当前 edges。
- 补量算成 `target - dist[destination]` 而非 `target - dist[a] - dist[b]`：示例 1 第一条边若用后者会得到 `5-0-1=4` 改成 5，重跑后 `dist[1]` 反而可能因 0-3-4-1 路径变长而失真；必须用全局最短路差值，且每次改完立刻重跑 Dijkstra 刷新 `dist`。

## 如果面试官追问
问：-1 边很多（如 n=100 全 -1）会不会超时？答：k 最多约 4950，每次 Dijkstra O(E log V)，总量约 2.5e7 次堆操作，Python 需注意用 `float('inf')` 而非大整数比较，实测可过。
