## 一句话思路
所有数对 x 取模必须相同，否则返回 -1；否则排序后取中位数，各数到中位数的步数之和最小。

## 怎么做
1. 把 grid 展平成一维列表 `a`，用 `a[0] % x` 作为基准，检查每个 `v % x` 是否相等，不等直接返回 -1。
2. 对 `a` 排序，取中位数 `mid = a[len(a) // 2]`。
3. 累加 `abs(v - mid) // x`，返回总和。

以示例 1 为例：`a = [2,4,6,8]`，`x = 2`，全部 `% 2 == 0` 通过检查；排序后 `mid = a[2] = 6`，但注意——中位数取 `a[2]=6` 时总步数 = `4//2 + 2//2 + 0 + 2//2 = 2+1+0+1 = 4`，与取 4 相同（偶数个元素时中间两个任取一个都最优）。这里取 `a[len(a)//2] = 6`，结果仍是 4。

```python
a = [v for row in grid for v in row]
r = a[0] % x
if any(v % x != r for v in a):
    return -1
a.sort()
mid = a[len(a) // 2]
return sum(abs(v - mid) // x for v in a)
```

关键中间值：`r = 2 % 2 = 0`，`mid = 6`，`sum = 2+1+0+1 = 4`。

## 复杂度
时间：O(mn log(mn))，排序贡献 log 因子，展平和取模是 O(mn)。
空间：O(mn)，额外开了一维列表 `a` 存全部元素。

## 易错点
- 输入 `[[1,2],[3,4]], x = 2` → 若跳过取模检查直接排序取中位数，会算出 `abs(1-3)//2 + abs(2-3)//2 + 0 + abs(4-3)//2 = 1+0+0+0 = 1` 这种无意义结果 → 正确做法是先验证所有 `v % x` 相等，不等立即返回 -1。
- 输入 `[[2,4],[6,8]], x = 2` → 若误用平均值 `(2+4+6+8)/4 = 5` 作为目标，`5` 不是 `2` 的倍数，步数算出来是 `3//2+1//2+1//2+3//2 = 1+0+0+1 = 2`，看似更小但目标 5 根本不可达 → 正确做法是目标必须与所有元素同余，只能取中位数 `a[len(a)//2]`。

## 如果面试官追问
问：如果要求输出具体的目标值和每个元素的操作次数怎么办？
答：目标值就是 `a[len(a)//2]`，对每个 `v` 输出 `(mid - v) // x`（正为加、负为减）即可。
