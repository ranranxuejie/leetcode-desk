## 一句话思路
按「已播放的不同歌曲数」做 DP，第 i 位要么放新歌、要么放旧歌，旧歌可选数由 k 决定。

## 怎么做
1. 定义 `dp[i][j]`：前 i 首歌里恰好出现了 j 首不同歌曲的方案数，答案取 `dp[goal][n]`。
2. 第 i 位放新歌：从 j-1 首转移，有 `n-(j-1)` 首没唱过可选，即 `dp[i-1][j-1] * (n-j+1)`。
3. 第 i 位放旧歌：从 j 首转移，最近 k 首被禁用，可选 `j-k` 首，即 `dp[i-1][j] * (j-k)`，且仅当 `j > k` 时非零。
4. 以 `n=2, goal=3, k=1` 为例：`dp[1][1]=2`；`dp[2][2]=dp[1][1]*(2-2+1)=2`；`dp[3][2]=dp[2][2]*(2-1)=2`，与输出 2 一致。

```python
MOD = 10**9 + 7
dp = [[0] * (n + 1) for _ in range(goal + 1)]
dp[0][0] = 1
for i in range(1, goal + 1):
    for j in range(1, min(i, n) + 1):
        dp[i][j] = dp[i-1][j-1] * (n - j + 1) % MOD
        if j > k:
            dp[i][j] = (dp[i][j] + dp[i-1][j] * (j - k)) % MOD
return dp[goal][n]
```

注意 `j` 的上界是 `min(i, n)`：前 i 位不可能出现超过 i 首不同歌，超过 n 首也无意义，这一剪枝同时避免了 `n-j+1` 取到负数。

## 复杂度
时间：O(goal × n)，两层循环各贡献一维，内层常数操作。
空间：O(goal × n) 的二维表；可滚动成一维 O(n)，因为只依赖 i-1 行。

## 易错点
- `k=0` 时旧歌可选数是 `j-k=j`，若写成 `j-k-1` 或漏掉 `j>k` 判断，示例 2 会算成 2 而非 6；正确是 `j > k` 才累加 `dp[i-1][j]*(j-k)`。
- `goal > n` 且 `k >= n-1` 时无解（如 `n=2, goal=3, k=1` 恰好有解，但 `k=2` 不满足 `k<n`），若把 `j>k` 写成 `j>=k`，`j=k` 时旧歌可选 0 首却仍乘出非零项，会多算；正确是严格大于。

## 如果面试官追问
问：goal 放大到 10^9 怎么办？答：n ≤ 100 时转移是常系数线性递推，可用矩阵快速幂把 O(goal·n) 降到 O(n³ log goal)。
