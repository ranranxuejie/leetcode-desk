## 一句话思路
按 book_id 聚合 reading_sessions，用条件聚合一次算出总次数、极端次数和最高/最低评分，再在 HAVING 里筛。

## 怎么做
1. 先 `GROUP BY book_id` 聚合，用 `COUNT(*)` 得总事件数 `total`，用 `SUM(CASE WHEN session_rating >= 4 OR session_rating <= 2 THEN 1 ELSE 0 END)` 得极端次数 `extreme`。
2. 同一层聚合里取 `MAX(session_rating)` 和 `MIN(session_rating)`，`rating_spread` 直接相减，不用再扫一遍表。
3. 用 `HAVING` 卡三个条件：`COUNT(*) >= 5`、同时存在 `>= 4` 和 `<= 2` 的评分、`extreme / total >= 0.6`。
4. 最后 join books 取 title/author/genre/pages，`ROUND(..., 2)` 后按 `polarization_score DESC, title DESC` 排序。

以 book_id=1 为例，5 条评分 `5,1,4,2,5`：`total=5`，`extreme=5`（1、2 是低分，4、5、5 是高分），`MAX=5`、`MIN=1`，spread=4，score=5/5=1.00。book_id=2 的 `extreme=0`，score=0，被 0.6 卡掉。

```python
# 聚合层核心（SQL 思路，Python 里用字典模拟同一逻辑）
agg[b] = {
    "total": agg[b]["total"] + 1,
    "extreme": agg[b]["extreme"] + (1 if r >= 4 or r <= 2 else 0),
    "hi": max(agg[b]["hi"], r),
    "lo": min(agg[b]["lo"], r),
}
# 过滤
ok = (a["total"] >= 5 and a["hi"] >= 4 and a["lo"] <= 2
      and a["extreme"] / a["total"] >= 0.6)
score = round(a["extreme"] / a["total"], 2)
```

## 复杂度
时间 O(n)，n 为 reading_sessions 行数，聚合一次 + 排序 O(k log k)，k 为候选书数。
空间 O(k)，只存每本书的 total/extreme/hi/lo 四个计数器。

## 易错点
- 只写 `HAVING MAX>=4 AND MIN<=2` 却漏了 `total >= 5`：book_id=4 只有 2 条评分 `3,3`，spread 算出来是 0 但若评分是 `5,1` 就会被误收；必须先卡次数再算分。
- 把 `extreme` 写成 `>= 4` 单独一类：book_id=3 的 `2,1,2,1,4,5` 里低分有 4 条，只数高分得 2/6≈0.33 会被 0.6 误杀；正确是 `>= 4 OR <= 2` 合并计数得 6/6。

## 如果面试官追问
问：若要求输出每本书的高分人数和低分人数两列？
答：在聚合里拆成两个 `SUM(CASE ...)` 分别计数，其余过滤逻辑不变。
