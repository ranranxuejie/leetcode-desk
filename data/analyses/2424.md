## 一句话思路
维护指针 `cur` 表示当前最长前缀，`upload` 时标记已上传，若 `video == cur+1` 就顺着连续已上传往后推。

## 怎么做
1. 初始化 `seen = [False] * (n + 2)`（多开一格防越界）和 `cur = 0`。
2. `upload(video)`：置 `seen[video] = True`。
3. 若 `video == cur + 1`，就 `while seen[cur + 1]: cur += 1`，把前缀一路推到底。
4. `longest()` 直接返回 `cur`。

以官方示例为例：`upload(3)` 后 `seen[3]=True`，但 `3 != 0+1`，`cur` 仍是 0，`longest()` 返回 0；`upload(1)` 时 `1 == cur+1`，循环把 `cur` 推到 1（`seen[2]` 为 False 停下），返回 1；再 `upload(2)`，`2 == cur+1`，`cur` 推到 3。

```python
def __init__(self, n):
    self.seen = [False] * (n + 2)
    self.cur = 0

def upload(self, video):
    self.seen[video] = True
    if video == self.cur + 1:
        while self.seen[self.cur + 1]:
            self.cur += 1

def longest(self):
    return self.cur
```

关键点：`cur` 只增不减，每个下标最多被 `while` 访问一次，所以总推进量是 O(n)，不是每次 `upload` 都 O(n)。

## 复杂度
时间：`upload` 均摊 O(1)（`cur` 总共推进 ≤ n 次），`longest` O(1)，总 O(n + 调用次数)。
空间：`seen` 数组 O(n)，无其他额外结构。

## 易错点
1. 只在 `video == cur + 1` 时才推进 → 若写成每次 `upload` 都无条件 `while seen[cur+1]`，逻辑也对但会多扫；反过来若漏掉这个判断，`upload(3)` 后 `cur` 仍为 0 是对的，但 `upload(1)` 时若不进循环就永远推不动，示例会输出 0 而非 1。
2. `seen` 只开 `n+1` 格 → `while seen[cur+1]` 在 `cur == n` 时访问 `seen[n+1]` 越界；开 `n+2` 并让 `seen[n+1]` 保持 `False` 才能自然停住。

## 如果面试官追问
问：若 `video` 可达 10^9 而调用次数只有 10^5，数组开不下怎么办？
答：改用哈希集合存已上传编号，`while (cur+1) in seen` 推进，复杂度不变。
