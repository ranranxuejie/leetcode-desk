## 一句话思路
模拟每轮移除数 10、9、8…直到某玩家拿不出，用剩余石头数 `n` 直接减，看谁先卡住。

## 怎么做
1. 设 `take = 10`，表示当前玩家要移除的石头数，初始为 Alice 的 10。
2. 循环：若 `n < take`，当前玩家输，返回 `take == 10` 的相反判断（即 Alice 是否赢）。
3. 否则 `n -= take`，`take -= 1`，轮到下一位玩家。
4. 用布尔 `alice_turn` 翻转记录当前是谁，卡住时返回 `not alice_turn`。

以官方示例 `n = 12` 走一遍：`take = 10`，`12 >= 10`，`n` 变 `2`，`take` 变 `9`，轮到 Bob；此时 `2 < 9`，Bob 卡住，Alice 赢，返回 `True`。关键中间值就是 `n = 2` 与 `take = 9` 的比较。

```python
n = 12
take = 10
alice_turn = True
while n >= take:
    n -= take
    take -= 1
    alice_turn = not alice_turn
# 循环退出时，当前 alice_turn 的玩家无法操作
return not alice_turn
```

注意 `n = 1` 时循环一次都不进，`alice_turn` 仍为 `True`，返回 `not True = False`，与示例 2 一致。

## 复杂度
时间：O(√n)，因为移除数从 10 递减，总消耗约 10+9+…，轮数受 n 约束。
空间：O(1)，只开了 `take`、`alice_turn` 两个变量。

## 易错点
- 输入 `n = 10` → 若写成 `while n > take` 会直接跳过循环判 Alice 输，实际 Alice 正好拿走 10 赢；正确用 `n >= take` 让等号成立时也能操作。
- 输入 `n = 1` → 若在循环外默认返回 `True`（以为 Alice 先手总有机会），会错成赢；正确做法是让 `alice_turn` 初值 `True`，循环不进入时返回 `not alice_turn` 得 `False`。

## 如果面试官追问
问：若 n 放大到 10^9 还能模拟吗？
答：不能逐轮减，但轮数只到移除数降到 0 为止（最多约 10 轮后 take 变负），实际循环次数是 O(1) 量级，n 再大也只比 10 次多常数，直接模拟仍可行。
