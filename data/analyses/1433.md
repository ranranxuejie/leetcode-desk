## 一句话思路
两个字符串各自排序后逐位比较，若存在一方每位都 ≥ 另一方，则可行；排序把「选哪个排列」的搜索变成固定配对。

## 怎么做
1. 对 `s1`、`s2` 分别 `sorted()`，得到升序列表 `a`、`b`。
2. 用两个布尔量 `a_ge_b`、`b_ge_a` 同时记录「a 每位都 ≥ b」和「b 每位都 ≥ a」是否仍成立。
3. 遍历 `zip(a, b)`，一旦某位 `x < y` 就把 `a_ge_b` 置 `False`，某位 `x > y` 就把 `b_ge_a` 置 `False`。
4. 返回 `a_ge_b or b_ge_a`。

以示例 2 `s1="abe"`、`s2="acd"` 为例：排序后 `a=['a','b','e']`、`b=['a','c','d']`。第 0 位 `'a'=='a'` 两边都不破坏；第 1 位 `'b'<'c'`，`a_ge_b` 变 `False`；第 2 位 `'e'>'d'`，`b_ge_a` 变 `False`。两个标志都假，返回 `False`，与答案一致。

```python
a, b = sorted(s1), sorted(s2)
a_ge_b = b_ge_a = True
for x, y in zip(a, b):
    if x < y:
        a_ge_b = False
    if x > y:
        b_ge_a = False
return a_ge_b or b_ge_a
```

关键点：排序后的逐位配对是最优配对。若存在某个排列让 `x[i] >= y[i]` 全成立，则把两串都升序后这个性质仍成立（交换论证：任何逆序对交换后不会破坏不等式），所以只需检验这一种配对，不必枚举 `n!` 种排列。

## 复杂度
时间：排序 `O(n log n)`，`n` 为字符串长度，逐位比较 `O(n)`。
空间：`sorted` 各生成一个长度 `n` 的列表，额外 `O(n)`。

## 易错点
- 只检查一个方向就返回：如 `s1="abc"`、`s2="xya"`，若只算 `a_ge_b` 会得 `False` 而误判，实际 `b_ge_a` 为 `True`，答案应为 `True`；必须两个方向都算再取 `or`。
- 用 `s1[i] >= s2[i]` 直接比原串：如 `s1="abe"`、`s2="acd"` 原序第 1 位 `'b'<'c'`、第 2 位 `'e'>'d'`，方向混杂会误判；必须先排序让同向比较成立。

## 如果面试官追问
问：若要求输出具体的两个排列而非布尔值？答：排序后若 `a_ge_b` 成立就返回 `(a, b)`，否则返回 `(b, a)`，排序结果本身就是一组可行解。
