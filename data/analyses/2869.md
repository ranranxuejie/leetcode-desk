## 一句话思路
从右往左扫，用布尔数组标记 1..k 是否已出现，集齐即停，扫过的元素个数就是答案。

## 怎么做
1. 开一个长度 `k+1` 的 `seen` 数组，`seen[0]` 不用，`need = k` 记录还差几个数。
2. 从 `i = len(nums)-1` 往左遍历，只关心 `1 <= nums[i] <= k` 的值。
3. 若 `nums[i]` 首次出现（`not seen[nums[i]]`），置 `True` 并 `need -= 1`；`need == 0` 时立刻返回 `len(nums) - i`。
4. 循环结束返回 `len(nums)`（保证能收集齐，实际不会走到）。

以示例 1 `nums = [3,1,5,4,2], k = 2` 为例：`i=4` 取到 `2`，`seen[2]=True`，`need` 从 2 变 1；`i=3` 取到 `4`，超出 `k` 跳过；`i=2` 取到 `5` 跳过；`i=1` 取到 `1`，`need` 变 0，返回 `5-1=4`。中间值 `need` 的变化是 2→1→0，正是答案 4 的来源。

```python
def minOperations(nums, k):
    seen = [False] * (k + 1)
    need = k
    n = len(nums)
    for i in range(n - 1, -1, -1):
        x = nums[i]
        if 1 <= x <= k and not seen[x]:
            seen[x] = True
            need -= 1
            if need == 0:
                return n - i
    return n
```

关键就三行：越界过滤 `1 <= x <= k`、去重 `not seen[x]`、计数 `need -= 1`。`nums[i] > k` 的元素（如示例里的 4、5）必须跳过，否则会把 `seen` 下标写越界或误减 `need`。

## 复杂度
时间 O(n)：从右往左最多扫 n 个元素，每个 O(1)。
空间 O(k)：额外开 `seen` 数组，长度 k+1，与 n 无关。

## 易错点
- 输入 `nums = [3,2,5,3,1], k = 3` → 若不去重，`3` 在 `i=3` 和 `i=0` 各减一次 `need`，会提前返回 2 → 必须用 `seen[x]` 判首次出现再减。
- 输入 `nums = [3,1,5,4,2], k = 2` → 若对 `nums[i] > k` 也执行 `seen[nums[i]] = True`，`seen` 长度只有 3，`seen[5]` 直接 IndexError → 先判 `1 <= x <= k` 再访问 `seen`。

## 如果面试官追问
问：若要求返回具体收集了哪些元素及顺序？
答：把 `seen[x] = True` 那行改成 `res.append(x)`，返回 `res` 即可，顺序天然是从右往左的收集顺序。
