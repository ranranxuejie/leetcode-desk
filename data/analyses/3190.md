## 一句话思路
每个元素独立，只需看 `nums[i] % 3`：余 0 花 0 次，余 1 减 1、余 2 加 1，各花 1 次，累加即可。

## 怎么做
1. 遍历 `nums`，对每个元素取 `r = x % 3`。
2. 余 0 贡献 0；余 1 和余 2 都贡献 1（余 1 往下减到 3 的倍数，余 2 往上加到 3 的倍数，距离都是 1）。
3. 把贡献累加进 `ans` 返回。

拿示例 1 `nums = [1,2,3,4]` 走一遍：`1 % 3 = 1` 贡献 1，`2 % 3 = 2` 贡献 1，`3 % 3 = 0` 贡献 0，`4 % 3 = 1` 贡献 1，`ans = 1+1+0+1 = 3`，与输出一致。

```python
ans = 0
for x in nums:
    r = x % 3
    if r != 0:
        ans += 1
return ans
```

等价写法是 `ans += min(r, 3 - r)`：`r = 1` 时 `min(1, 2) = 1`，`r = 2` 时 `min(2, 1) = 1`，`r = 0` 时 `min(0, 3) = 0`。两种写法在本题结果相同，因为模 3 的余数只有 0/1/2，距离永远不会超过 1。选第一种更直白，少一次 `min` 调用。

关键点在于「元素之间互不影响」：把 `1` 改成 `0` 不会改变 `2` 需要加 1 这件事，所以不需要考虑操作顺序，也不存在「先改谁更省」的贪心选择问题，直接逐项求和就是最优。这也是为什么这题通过率 87.6%——难点只在意识到「余 1 和余 2 都只要 1 步」，而不是去算 `x` 到最近的 3 的倍数差多少。

## 复杂度
时间 O(n)：遍历 `nums` 一次，n 为数组长度。
空间 O(1)：只用了 `ans` 和 `r` 两个变量，没有额外数组。

## 易错点
- 输入 `nums = [2]` → 若写成「余 2 就减 2 到 0」会得 2，实际 `2` 加 1 到 `3` 只要 1 步 → 正确做法是对余数取 `min(r, 3 - r)`，或直接判断 `r != 0` 就加 1。
- 输入 `nums = [3,6,9]` → 若漏掉 `r == 0` 的分支、无条件 `ans += 1`，会错成 3 → 必须先判断余数是否为 0，余 0 的元素贡献 0 次操作。

## 如果面试官追问
问：如果每次操作可以把一个元素加减任意值、代价是加减量的绝对值，答案变吗？
答：不变，每个元素仍独立取到最近 3 的倍数，代价还是 0 或 1。
