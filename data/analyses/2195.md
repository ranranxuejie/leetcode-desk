## 一句话思路
排序后从小到大扫，遇到 `nums[i]` 就跳过它，否则按等差数列一次补齐缺口，缺口不够 k 个就截断。

## 怎么做
1. 对 `nums` 排序，用 `cur = 1` 表示下一个待考察的正整数，`ans = 0` 累计追加和。
2. 遍历每个 `x`：若 `cur < x`，说明 `[cur, x-1]` 全是空缺，可补 `cnt = min(k, x - cur)` 个，用等差数列求和 `cnt * (2*cur + cnt - 1) // 2` 累加，然后 `cur += cnt`、`k -= cnt`；若 `k == 0` 立即返回。
3. 若 `cur >= x`（重复元素或已越过），直接 `cur = max(cur, x + 1)` 跳过这个数。
4. 扫完后若 `k > 0`，从 `cur` 起继续补 k 个连续整数，同样用等差公式。

以 `nums = [5,6], k = 6` 为例：排序后 `cur = 1`，遇到 `x = 5`，缺口 `[1,4]` 共 4 个，`cnt = min(6,4) = 4`，`ans = 4*(2*1+3)//2 = 10`，`cur = 5`、`k = 2`；`x = 5` 使 `cur = 6`，`x = 6` 使 `cur = 7`；扫完 `k = 2`，补 `[7,8]` 得 `2*(2*7+1)//2 = 15`，`ans = 25`。

```python
nums.sort()
cur, ans = 1, 0
for x in nums:
    if k == 0:
        break
    if cur < x:
        cnt = min(k, x - cur)
        ans += cnt * (2 * cur + cnt - 1) // 2
        cur += cnt
        k -= cnt
    cur = max(cur, x + 1)
if k > 0:
    ans += k * (2 * cur + k - 1) // 2
return ans
```

## 复杂度
时间 O(n log n)：排序贡献 log n，单次线性扫描贡献 n。
空间 O(1)：除排序自身开销外只用了 `cur/ans/k` 几个变量。

## 易错点
- `nums = [1,1,1], k = 2` → 若对每个 `x` 都做 `cur = x + 1` 而不取 `max`，`cur` 会被重复的 1 反复压回 2，导致漏补或重复计数 → 必须写 `cur = max(cur, x + 1)`，重复元素只跳过不推进缺口。
- `nums = [1,2,3], k = 10**9` → 若逐个 `cur += 1` 累加会超时，且答案量级到 `10^18` → 必须整段用等差公式 `cnt*(2*cur+cnt-1)//2` 一次算完，Python 大整数天然安全，不要按 32 位截断。

## 如果面试官追问
要求返回追加的具体 k 个数而非和？答：把每段缺口展开成 `range(cur, cur+cnt)` 收集，最后不足 k 个时补 `range(cur, cur+k)`，复杂度不变。
