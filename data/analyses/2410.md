## 一句话思路
两边都排序后双指针贪心：用当前最小的训练师去接当前最小的运动员，接不住就换更强的训练师。

## 怎么做
1. 对 `players` 和 `trainers` 分别升序排序。
2. 指针 `i` 指向运动员、`j` 指向训练师，都从 0 开始，`ans = 0`。
3. 若 `players[i] <= trainers[j]`，匹配成功，`i += 1`、`j += 1`、`ans += 1`；否则只 `j += 1`，放弃这个训练师。
4. 当 `i == len(players)` 或 `j == len(trainers)` 时结束，返回 `ans`。

拿示例 1 走一遍：排序后 `players = [4,7,9]`，`trainers = [2,5,8,8]`。`j=0` 时 `4 > 2`，跳过 2；`j=1` 时 `4 <= 5`，匹配，`ans=1`；接着 `7 <= 8` 匹配，`ans=2`；最后 `9 > 8`，`j` 走到头，返回 2。注意 2 被跳过而不是硬塞给 4，这正是贪心的关键：2 连最小的 4 都接不住，对任何运动员都无用。

```python
players.sort()
trainers.sort()
i = j = ans = 0
while i < len(players) and j < len(trainers):
    if players[i] <= trainers[j]:
        ans += 1
        i += 1
    j += 1
return ans
```

为什么成立：排序后若最小运动员都接不住某训练师，该训练师对全体运动员都无效，直接丢弃不损失最优解；能接住时立刻配对，把更强的训练师留给后面更强的运动员，不会更差。

## 复杂度
时间：排序 `O(n log n + m log m)`，双指针扫描 `O(n + m)`，n、m 分别是两数组长度。
空间：排序的栈开销 `O(log n + log m)`，双指针只用了 `i`、`j`、`ans` 三个变量。

## 易错点
- 输入 `players = [1,1,1], trainers = [10]`：若写成对每个运动员都遍历训练师、或忘记 `j` 只能前进不能回退，会重复使用同一个训练师得到 3；正确做法是匹配后 `j += 1`，且 `j` 单调递增，答案封顶为 `min(len(players), len(trainers))`，这里是 1。
- 输入 `players = [4,7,9], trainers = [8,2,5,8]`：若先不排序直接按下标配对，`players[0]=4` 对 `trainers[0]=8` 成功、`players[1]=7` 对 `trainers[1]=2` 失败，容易只得到 1 或 2 的错误组合；必须先 `sort()` 两边，让 `2` 排到最前被正确跳过。

## 如果面试官追问
问：要求输出具体匹配方案怎么办？
答：双指针里匹配成功时把 `(i, j)` 存进列表，返回 `ans` 和该列表即可，逻辑不变。
