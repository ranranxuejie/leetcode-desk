## 一句话思路
用两个集合收集所有菜品名和桌号，排序后建表，再用哈希表按 (桌号, 菜品) 累加数量填格。

## 怎么做
1. 遍历 `orders`，把 `foodItem` 塞进 `foods` 集合、`tableNumber` 塞进 `tables` 集合。
2. `foods` 按字母序排、`tables` 按数值升序排，表头就是 `["Table"] + sorted(foods)`。
3. 用 `count[(table, food)]` 累加每桌每菜的点单次数，客户名完全丢弃。
4. 按 `tables` 顺序逐行生成，每格取 `count.get((t, f), 0)` 再 `str()`。

拿示例 1 走一遍：`foods` 排序后是 `["Beef Burrito","Ceviche","Fried Chicken","Water"]`，`tables` 是 `["3","5","10"]`。累加后 `count[("3","Ceviche")] = 2`（David 和 Rous 各一次），`count[("3","Fried Chicken")] = 1`，所以桌 3 那行是 `["3","0","2","1","0"]`。

```python
foods, tables, cnt = set(), set(), {}
for _, t, f in orders:
    foods.add(f)
    tables.add(t)
    cnt[(t, f)] = cnt.get((t, f), 0) + 1
foods = sorted(foods)
tables = sorted(tables, key=int)
res = [["Table"] + foods]
for t in tables:
    res.append([t] + [str(cnt.get((t, f), 0)) for f in foods])
```

注意 `tables` 里存的是字符串 `"3"`、`"10"`，直接 `sorted` 会得到 `"10" < "3"` 的字典序，必须 `key=int`。

## 复杂度
时间：O(n + T·F)，n 为订单数，T·F 为桌数乘菜品数，排序的 O(T log T + F log F) 被其覆盖。
空间：O(n + T·F)，`cnt` 最多存 n 个键，结果表占 T·F 个格子。

## 易错点
- 桌号是字符串，示例 1 里 `sorted(["3","5","10"])` 得到 `["10","3","5"]`，输出行序就错了；必须 `key=int`，且输出时保留原字符串 `"3"` 而非 `3`。
- 某桌没点某菜时不能漏格：示例 2 桌 12 没点 `Canadian Waffles`，若只遍历 `cnt` 的键来填行，桌 12 那行会少一格；必须对 `foods` 全量遍历并 `get(..., 0)`。

## 如果面试官追问
若桌号范围固定为 1~500，能否省掉排序？答：可以开长度 501 的数组按桌号下标直接扫，时间降到 O(n + 500·F)，但菜品名仍要排序。
