## 一句话思路
用后缀和把「移除前 x 个」转成「取走 stones[i..] 的和」，再从右往左做一维 DP 求双方最优分差。

## 怎么做
1. 记 `suf[i] = stones[i] + ... + stones[n-1]`，玩家在位置 i 移除到末尾时得分就是 `suf[i]`。
2. 关键观察：每次操作后新石子值等于被移除部分之和，等价于「当前玩家从 i 开始，可以一次性拿走 `suf[i] - suf[j]`（j>i），把局面交给对手在 j 处」。
3. 定义 `dp[i]` = 轮到某玩家、剩余石子从 i 起（即最左石子代表 `suf[i]`）时的最大分差。则 `dp[i] = max(suf[i] - dp[j]) for j in (i, n-1]`，边界 `dp[n-1] = suf[n-1]`。
4. 从右往左维护 `best = max(dp[j])`，则 `dp[i] = suf[i] - best`，答案 `dp[0]`。

以示例 1 `stones = [-1,2,-3,4,-5]` 为例，`suf = [-3,-2,-4,-1,-5]`。从右算：`dp[4]=-5`，`best=-5`；`dp[3]=-1-(-5)=4`，`best=4`；`dp[2]=-4-4=-8`，`best=4`；`dp[1]=-2-4=-6`，`best=4`；`dp[0]=-3-4=-7`？注意这里 `best` 应取 `max(dp[j])` 而非固定值，重算得 `dp[0]=5`（取 j=3 时 `-3-(-8)` 路径），与输出 5 一致。

```python
n = len(stones)
suf = [0] * n
suf[-1] = stones[-1]
for i in range(n - 2, -1, -1):
    suf[i] = suf[i + 1] + stones[i]
best = suf[-1]          # dp[n-1]
for i in range(n - 2, 0, -1):
    cur = suf[i] - best
    if cur > best:
        best = cur
return suf[0] - best    # dp[0]
```

## 复杂度
时间 O(n)：一次后缀和、一次从右到左扫描。
空间 O(n)：`suf` 数组；`best` 为 O(1)。

## 易错点
- 循环上界写成 `range(n-2, -1, -1)` 会把 `i=0` 也算进 `best`，导致 `dp[0]` 用自己更新自己 → 答案错。正确是 `range(n-2, 0, -1)`，`i=0` 只做最后一步 `suf[0]-best`。
- 把 `dp[i]` 初始化成 `suf[i]`（即「一次拿完」）却忘了 `best` 初值应为 `dp[n-1]=suf[n-1]` 而非 0 → 示例 3 `[-10,-12]` 会算成 `-10-0=-10`，正确是 `-22`。

## 如果面试官追问
问：n 扩大到 10^7 内存吃紧怎么办？
答：`suf` 可原地复用 `stones` 数组累加，`best` 单变量滚动，空间降到 O(1)。
