## 一句话思路
以每个右端点维护「以 r 结尾的所有子数组 OR 值」的去重集合（至多 30 个），逐个与 k 比差值。

## 怎么做
1. 关键性质：固定右端点 r，随着左端点 l 从 r 往 0 移动，OR 值只增不减，且每次变化至少多一个二进制位，所以不同取值至多 30 个（nums[i] ≤ 10^9 < 2^30）。
2. 用 `pre` 存「以 r-1 结尾」的去重 OR 集合，则「以 r 结尾」的集合 = `{x | nums[r] for x in pre} ∪ {nums[r]}`，再去重。
3. 每轮遍历这个集合，用 `abs(v - k)` 更新答案；若中途出现 0 可直接返回。
4. 以示例 1 `nums = [1,2,4,5], k = 3` 为例：r=0 时集合 `{1}`；r=1 时 `{1|2, 2} = {3, 2}`，命中 `abs(3-3)=0`，返回 0。

```python
ans = 2**31 - 1
pre = set()
for x in nums:
    cur = {x}
    for v in pre:
        cur.add(v | x)
    for v in cur:
        d = abs(v - k)
        if d < ans:
            ans = d
    if ans == 0:
        return 0
    pre = cur
return ans
```

注意 `cur` 必须新建，不能原地改 `pre`，否则同一轮里会把刚加入的值再 OR 一次（虽然结果不变，但集合语义混乱）。

## 复杂度
时间：O(n · 30)，n 为数组长度，30 是 OR 值去重后的上界。
空间：O(30)，只存当前右端点的去重 OR 集合，与 n 无关。

## 易错点
- 输入 `nums = [1,3,1,3], k = 2`：若只比较单元素子数组，会漏掉 `nums[0..1]` 的 OR=3 与 `nums[1..3]` 的 OR=3，答案仍是 1 但逻辑错；必须枚举所有以 r 结尾的 OR 值，不能只看 `nums[r]`。
- 输入 `nums = [1], k = 10`：若把 `ans` 初始化为 0 或忘记更新，会返回 0；正确做法是初始化为 `2**31 - 1`（或 `abs(nums[0]-k)`），保证单元素时也能被 `abs(1-10)=9` 覆盖。

## 如果面试官追问
问：若要求返回具体子数组下标而非差值？答：在集合里存 `(or值, 最左下标)`，OR 值相同时保留更靠左的 l，命中时反查即可。
