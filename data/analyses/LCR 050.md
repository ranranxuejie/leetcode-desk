## 一句话思路
用前缀和 + 回溯 DFS：把「从根到当前节点的路径和」记进哈希表，查 `cur - targetSum` 出现过几次，就是当前节点结尾的合法路径数。

## 怎么做
1. 维护 `prefix` 字典，`prefix[s]` 表示当前根到节点路径上，前缀和等于 `s` 的节点个数，初始 `{0: 1}`（空前缀，让「从根开始」的路径也能被算到）。
2. DFS 进入节点时 `cur += node.val`，答案累加 `prefix.get(cur - targetSum, 0)`。
3. 把 `cur` 计入 `prefix`，递归左右子树。
4. 回溯时 `prefix[cur] -= 1`，撤销本节点的贡献，避免污染兄弟子树。

以示例 1 为例，沿 `10 → 5 → 3 → 3` 走：`cur` 依次为 `10, 15, 18, 21`。到最后一个 `3` 时查 `21 - 8 = 13`，`prefix` 里没有，贡献 0；而走到 `10 → 5 → 3` 时 `cur = 18`，查 `18 - 8 = 10`，`prefix[10] = 1`，命中一条（`5+3`）。整棵树累计得 3。

```python
def dfs(node, cur):
    if not node:
        return 0
    cur += node.val
    res = prefix.get(cur - targetSum, 0)
    prefix[cur] = prefix.get(cur, 0) + 1
    res += dfs(node.left, cur) + dfs(node.right, cur)
    prefix[cur] -= 1
    return res

return dfs(root, 0)
```

## 复杂度
时间 O(n)：每个节点进出各一次，哈希查询 O(1)。
空间 O(n)：`prefix` 最多存树高条前缀和，递归栈同阶，最坏链状为 n。

## 易错点
- 忘记初始化 `prefix = {0: 1}` → 示例 1 中从根出发的路径（如 `10 + (-3) + ...` 凑 8 的那条）全部漏算，输出偏小；正确做法是先把空前缀计数置 1。
- 回溯时漏写 `prefix[cur] -= 1` → 左子树的前缀和被右子树看到，示例 1 中右子树 `11` 分支会误用左子树留下的 `cur` 值，答案偏大；正确做法是递归返回后立刻撤销。

## 如果面试官追问
问：节点值全为正、要求输出所有路径怎么办？
答：前缀和仍可用，但要把 `prefix` 的值改成存「前缀和 → 节点列表」，命中时沿父指针回溯拼出路径。
