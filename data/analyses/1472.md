## 一句话思路
用数组存历史、一个下标 `cur` 指向当前页，`visit` 时截断 `cur` 之后的部分。

## 怎么做
1. 构造时 `hist = [homepage]`，`cur = 0`。
2. `visit(url)`：先 `del hist[cur+1:]` 删掉前进记录，再 `hist.append(url)`，`cur += 1`。
3. `back(steps)`：`cur = max(0, cur - steps)`，返回 `hist[cur]`。
4. `forward(steps)`：`cur = min(len(hist) - 1, cur + steps)`，返回 `hist[cur]`。

拿官方示例走关键一步：三次 visit 后 `hist = ["leetcode.com","google.com","facebook.com","youtube.com"]`，`cur = 3`。接着 `back(1)` 得 `cur = 2`，返回 `"facebook.com"`；再 `back(1)` 得 `cur = 1`，返回 `"google.com"`；`forward(1)` 得 `cur = 2`，返回 `"facebook.com"`。此时 `visit("linkedin.com")` 执行 `del hist[3:]`，把 `"youtube.com"` 删掉，`hist` 变成 `["leetcode.com","google.com","facebook.com","linkedin.com"]`，`cur = 3`——这就是「前进记录被清空」的具体体现，之后 `forward(2)` 因 `cur` 已在末尾返回 `"linkedin.com"`。

```python
def visit(self, url):
    del self.hist[self.cur + 1:]
    self.hist.append(url)
    self.cur += 1

def back(self, steps):
    self.cur = max(0, self.cur - steps)
    return self.hist[self.cur]

def forward(self, steps):
    self.cur = min(len(self.hist) - 1, self.cur + steps)
    return self.hist[self.cur]
```

`max`/`min` 两个夹取就是「至多 x 步」的全部实现，不需要循环。

## 复杂度
时间：`visit` 的 `del` 最坏 O(n)，n 为历史长度；`back`/`forward` O(1)。
空间：O(n) 存 `hist`，n 为累计访问过的 url 数。

## 易错点
- `visit` 忘了先截断：在示例 `cur = 2`（facebook）时直接 `append("linkedin.com")`，`hist` 变成 5 个元素且 `"youtube.com"` 还在，之后 `forward(2)` 会错误返回 `"youtube.com"` 而非 `"linkedin.com"`。正确做法是先 `del hist[cur+1:]` 再 append。
- `back`/`forward` 用 `cur -= steps` 不夹取：示例最后 `back(7)` 时 `cur = 1`，直接减得 `-6`，`hist[-6]` 在 Python 里不报错但会绕回取到错误元素（长度不足时抛 IndexError）。必须 `max(0, ...)` / `min(len(hist)-1, ...)`。

## 如果面试官追问
问：若 `visit` 频繁且历史很长，`del` 的 O(n) 能优化吗？
答：换双向链表加当前节点指针，`visit` 断开后继即 O(1)，代价是 `back`/`forward` 要逐步走 O(steps)。
