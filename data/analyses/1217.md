## 一句话思路
按位置奇偶分两组，同组内移动代价为 0，只需把少的那组逐个挪到另一组，代价即少数组的个数。

## 怎么做
1. 遍历 `position`，统计偶数位置个数 `even`，奇数个数 `odd = len(position) - even`。
2. 因为 ±2 免费，所有同奇偶的位置可零代价聚到一点，问题退化为「两组之间搬」。
3. 把少的那组搬到多的那组，每个筹码花 1，答案就是 `min(even, odd)`。

以 `position = [1,2,3]` 为例：`1`、`3` 是奇数，`2` 是偶数，得 `odd = 2`、`even = 1`；`min(2,1) = 1`，与示例一致——把 `2` 挪到 `1` 花 1，`3` 免费滑到 `1`。

```python
even = 0
for p in position:
    if p % 2 == 0:
        even += 1
odd = len(position) - even
return min(even, odd)
```

注意 `position[i]` 最大到 `10**9`，但只取 `% 2`，不涉及任何大数运算或溢出。

## 复杂度
时间：O(n)，n 为 `position` 长度，一次遍历计数。
空间：O(1)，只开 `even`、`odd` 两个整数。

## 易错点
- 输入 `[1,1000000000]` → 若真去模拟「往中间位置靠拢」会算成巨大代价或死循环 → 正确做法是只看奇偶：`1` 奇、`1000000000` 偶，`min(1,1)=1`。
- 输入 `[2,2,2,3,3]` → 若误以为要选「中位数位置」当目标，会纠结目标点在哪 → 正确做法是目标点可任选同奇偶的任一点，答案只由两组数量决定，`min(3,2)=2`。

## 如果面试官追问
问：若把 ±2 的代价改成 1、±1 改成 2 呢？
答：同奇偶内不再免费，需按距离加权，退化为带权中位数问题，不能只数奇偶。
