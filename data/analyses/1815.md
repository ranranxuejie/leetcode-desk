## 一句话思路
按 `groups[i] % batchSize` 分组，整除的必开心，余数用位掩码记忆化搜索排最优顺序。

## 怎么做
1. 把每组对 `batchSize` 取余，余数 0 的组直接计入答案（它们总在批次边界开始）。
2. 余数相同的组合并计数，只对「余数种类」做状态，避免对每组单独枚举。
3. 用 `(mask, rem)` 记忆化：`mask` 标记哪些余数种类已用完，`rem` 是当前批次已消耗的甜甜圈数。
4. 若 `rem == 0`，下一组必开心；否则看 `rem + r` 是否跨批次。

以示例 1 为例：`batchSize=3`，余数为 `[1,2,0,1,2,0]`，余数 0 的 2 组直接开心。剩余余数计数 `{1:2, 2:2}`，搜索时先放余数 2（`rem=2`），再放余数 1 时 `rem+1=3` 跨批次，该组开心，`rem` 归 0。

```python
from functools import lru_cache
from collections import Counter

cnt = Counter(g % batchSize for g in groups)
ans = cnt.pop(0, 0)
items = list(cnt.items())  # (余数, 个数)

@lru_cache(None)
def dfs(mask, rem):
    if mask == (1 << len(items)) - 1:
        return 0
    best = 0
    for i, (r, c) in enumerate(items):
        if mask >> i & 1 or c == 0:
            continue
        happy = 1 if rem == 0 else 0
        nrem = (rem + r) % batchSize
        best = max(best, happy + dfs(mask | (1 << i), nrem))
    return best

return ans + dfs(0, 0)
```

## 复杂度
时间：`O(2^k * k * batchSize)`，`k` 为不同余数种类数（≤ batchSize-1）。
空间：`O(2^k * batchSize)` 记忆化表，`k` 由余数种类决定。

## 易错点
- 输入 `groups=[3,3,3], batchSize=3` → 若把余数 0 也放进搜索会重复计数 → 余数 0 的组应直接累加，不进 `mask`。
- 输入 `groups=[1,1,1,1], batchSize=4` → 若按每组而非余数种类建状态，`2^n` 爆炸 → 必须用 `Counter` 合并同余数，状态只跟种类数有关。

## 如果面试官追问
问：若要求输出具体排列顺序？答：在 `dfs` 里额外记录每步选的余数种类下标，回溯时还原成组编号即可。
