## 一句话思路
边取模边累加数位和 `s`，再用 `x % s == 0` 判断，因为数位和与整除判定互不干扰。

## 怎么做
1. 令 `s = 0`，`t = x`，用 `t` 做循环变量以免破坏 `x`。
2. 循环 `while t:`，每轮 `s += t % 10`，再 `t //= 10`。
3. 循环结束时 `s` 就是各位数字之和。
4. 返回 `s if x % s == 0 else -1`。

以 `x = 18` 为例：第一轮 `t % 10 = 8`，`s` 变 8，`t` 变 1；第二轮 `t % 10 = 1`，`s` 变 9，`t` 变 0，循环结束。此时 `18 % 9 == 0`，返回 9。若换成 `x = 23`，两轮后 `s = 5`，`23 % 5 == 3`，返回 -1。

```python
s = 0
t = x
while t:
    s += t % 10
    t //= 10
return s if x % s == 0 else -1
```

关键点是 `t //= 10` 而不是 `t /= 10`：后者在 Python 里得到浮点数，`while t:` 会因 `0.0` 才停，但中途 `t` 变成 `1.8`、`0.18` 时 `t % 10` 已不是数位，结果全错。用整除才能保证每轮剥掉最低位。

## 复杂度
时间 O(log x)：循环次数等于 `x` 的十进制位数，`x ≤ 100` 时最多 3 轮。
空间 O(1)：只开了 `s` 和 `t` 两个整型变量。

## 易错点
- 输入 `x = 100` → 若直接对 `x` 做 `x //= 10`，循环结束后 `x` 变 0，再算 `x % s` 得 `0 % 1 == 0`，误判为哈沙德数并返回 1 → 必须用副本 `t` 拆位，保留原 `x` 做整除判断。
- 输入 `x = 1` → 若把循环写成 `while t > 1:`，`t = 1` 时直接跳过，`s` 停在 0，随后 `x % s` 抛 `ZeroDivisionError` → 循环条件必须是 `while t:`，保证个位数也被累加，`s` 至少为 1。

## 如果面试官追问
问：若 `x` 上限改成 `2**31 - 1` 呢？
答：思路不变，循环最多 10 轮，仍是 O(log x)，Python 整数不会溢出，无需额外处理。
