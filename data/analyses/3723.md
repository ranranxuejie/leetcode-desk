## 一句话思路
把数字尽量堆成 9 放在高位，剩余零头放次高位，其余补 0，因为平方函数在 0~9 上凸，集中比分散得分高。

## 怎么做
1. 先判无解：`sum > 9 * num` 或 `sum < 1`（首位不能为 0，但 num≥1 且 sum≥1 时总能凑出）→ 返回 `""`。
2. 用 `q, r = divmod(sum, 9)`，把 `q` 个 9 放在最前面。
3. 若 `r > 0`，在 9 之后放一个 `r`；剩余位数全补 0。
4. 拼接成字符串返回。

以 `num=2, sum=17` 为例：`divmod(17, 9) = (1, 8)`，先放 1 个 9，再放 8，位数已满 → `"98"`。若 `num=3, sum=17`：`q=1, r=8`，得到 `"98" + "0"` = `"980"`。

```python
def solve(num, sum):
    if sum > 9 * num:
        return ""
    q, r = divmod(sum, 9)
    parts = ["9"] * q
    if r:
        parts.append(str(r))
    parts.extend(["0"] * (num - len(parts)))
    return "".join(parts)
```

关键点：`r` 必须放在 9 之后、0 之前，这样既保证分数最大（凸性），又保证同分时数值最大（高位尽量大）。

## 复杂度
时间 O(num)，构造长度为 num 的字符串。
空间 O(num)，结果字符串本身。

## 易错点
- `sum > 9 * num` 时若不提前返回，`divmod` 会得到 `q > num`，拼出的字符串长度超过 num，例如 `num=1, sum=10` 会输出 `"91"` 而非 `""`。
- `r == 0` 时若仍 `append(str(0))`，会多出一个 0 占位，导致后续补 0 数量算错，例如 `num=2, sum=9` 会得到 `"90"` 而非 `"90"`（此处恰好对），但 `num=3, sum=9` 会得到 `"900"` 而非 `"900"`——真正翻车在 `num=2, sum=18`：`q=2, r=0`，若补 0 逻辑用 `num - len(parts)` 且 parts 已含多余 0，长度变 3，输出 `"990"` 超位数。正确做法是 `r` 为 0 时不 append。

## 如果面试官追问
若 sum 可达 2e6 而 num 只有 1e5，无解判断 `sum > 9*num` 会先触发返回空串，无需构造，O(1) 完成。
