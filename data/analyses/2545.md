## 一句话思路
按 `score[i][k]` 降序对行排序即可，因为题目保证分数互不相同，不存在并列需要额外处理。

## 怎么做
1. 用 `sorted` 对 `score` 排序，`key` 取 `lambda row: row[k]`，`reverse=True` 实现降序。
2. 排序对象是整行，所以第 k 列一动，整行跟着走，不需要手动搬数据。
3. 以示例 1 为例：`score = [[10,6,9,1],[7,5,11,2],[4,8,3,15]]`，`k = 2`，取出的 key 依次是 `9, 11, 3`；降序后顺序为 `11, 9, 3`，对应行下标 `1, 0, 2`，输出 `[[7,5,11,2],[10,6,9,1],[4,8,3,15]]`。
4. 返回排序结果，`m` 行 `n` 列结构不变。

```python
def sortTheStudents(score, k):
    return sorted(score, key=lambda row: row[k], reverse=True)
```

关键中间值：`[row[k] for row in score]` 在示例 1 中是 `[9, 11, 3]`，排序后行顺序变成 `[1, 0, 2]`。

## 复杂度
时间：排序比较 `m` 行，每次取 `row[k]` 是 O(1)，共 O(m log m)。
空间：`sorted` 额外开一个长度 m 的行引用列表，O(m)；行本身不复制。

## 易错点
- 写成 `key=lambda row: row[k]` 但漏了 `reverse=True` → 示例 1 会输出 `[[4,8,3,15],[10,6,9,1],[7,5,11,2]]`，变成升序，与「从高到低」相反；正确做法是显式加 `reverse=True`，不要靠取负号 `-row[k]`（虽然本题分数为正也能对，但语义不直观）。
- 误以为要原地排序并返回 `score` → 若写成 `score.sort(...)` 后 `return score`，虽然本题判题通常接受，但 `sorted` 返回新列表更安全；更危险的是把 `k` 当成行下标去取 `score[k]`，示例 2 中 `k = 0` 会取到第一行 `[3,4]` 而不是第一列，排序 key 全错。

## 如果面试官追问
问：如果分数允许重复、要求相同分数保持原行序怎么办？
答：`sorted` 是稳定排序，直接去掉「互不相同」的假设，`reverse=True` 下同分仍保持原相对顺序，无需改代码。
