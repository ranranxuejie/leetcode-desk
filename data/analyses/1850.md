## 一句话思路
先用 k 次「下一个排列」求出目标串，再用双指针贪心匹配原串与目标串，累加每个字符的移动距离。

## 怎么做
1. 对 `num` 的字符列表执行 k 次下一个排列，得到目标串 `target`。以 `num="5489355142", k=4` 为例，第 4 次后 `target="5489355421"`。
2. 用双指针 `i` 扫原串、`j` 扫目标串，把 `num` 的字符逐个搬到 `target` 对应位置。
3. 每次在 `num` 中从 `i` 往后找第一个等于 `target[i]` 的位置 `j`，把 `num[j]` 一路左移到 `i`，答案加上 `j - i`。

```python
def next_perm(a):
    i = len(a) - 2
    while i >= 0 and a[i] >= a[i+1]: i -= 1
    j = len(a) - 1
    while a[j] <= a[i]: j -= 1
    a[i], a[j] = a[j], a[i]
    a[i+1:] = a[i+1:][::-1]

ans = 0
for i in range(n):
    j = i
    while num[j] != target[i]: j += 1
    ans += j - i
    num[i:j+1] = [num[j]] + num[i:j]
```

关键中间值：`num="11112", k=4` 时 `target="21111"`，第一个 `i=0` 在 `num` 里找到 `'2'` 在 `j=4`，`ans += 4`，随后 `num` 变成 `"21111"`，后续 `j-i` 全为 0，最终答案 4。

## 复杂度
时间：O(k·n + n²)，k 次下一个排列各 O(n)，匹配阶段最坏 O(n²)。
空间：O(n)，只开了 `target` 和字符列表副本。

## 易错点
- `num="00123", k=1` 时若把前导零当无效位跳过，会算成 0 或错位；正确做法是把字符串当定长数组，`target="00132"`，只在 `i=3` 处 `j=4`，答案 1。
- `num="11112", k=4` 时若用「统计逆序对」代替逐位左移，会把相同数字的交换漏算；正确做法是每次找**第一个**等于 `target[i]` 的下标，`j-i` 就是真实相邻交换次数。

## 如果面试官追问
问：k 放大到 10^9 怎么办？答：k 次下一个排列不可行，需按字典序直接定位第 k 个排列（阶乘进制），再算距离。
