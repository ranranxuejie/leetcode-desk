## 一句话思路
只枚举黑格影响到的块：每个黑格最多属于 4 个块，用哈希表累计每个块的黑格数，剩下的块黑格数必为 0。

## 怎么做
1. 总块数 `total = (m-1)*(n-1)`，先全部记成 0 个黑格。
2. 对每个黑格 `(x, y)`，枚举左上角 `(x-1,y-1)` 到 `(x,y)` 这 4 个候选块，只保留满足 `0 <= i < m-1 and 0 <= j < n-1` 的。
3. 用字典 `cnt` 以 `(i, j)` 为键累加，最后按值把 `total - len(cnt)` 记到 `arr[0]`，其余 `arr[v] += 1`。

以示例 2 为例，`m=n=3`，`total=4`。黑格 `(1,1)` 贡献的候选块是 `(0,0),(0,1),(1,0),(1,1)`，四个都合法；黑格 `(0,0)` 只贡献 `(0,0)`；黑格 `(0,2)` 只贡献 `(0,1)`。累加后 `cnt = {(0,0):2, (0,1):2, (1,0):1, (1,1):1}`，`len(cnt)=4`，所以 `arr[0]=0`，`arr[1]=2`，`arr[2]=2`。

```python
total = (m - 1) * (n - 1)
cnt = {}
for x, y in coordinates:
    for i in (x - 1, x):
        for j in (y - 1, y):
            if 0 <= i < m - 1 and 0 <= j < n - 1:
                cnt[(i, j)] = cnt.get((i, j), 0) + 1
arr = [0] * 5
arr[0] = total - len(cnt)
for v in cnt.values():
    arr[v] += 1
```

## 复杂度
时间：`O(len(coordinates))`，每个黑格固定查 4 次哈希，与 `m*n` 无关。
空间：`O(len(coordinates))`，`cnt` 最多存 `4 * len(coordinates)` 个键。

## 易错点
- 黑格贴着边界时，比如 `(0,0)` 在 `m=n=3` 下，候选左上角 `(-1,-1)`、`(-1,0)`、`(0,-1)` 都越界，只有 `(0,0)` 合法。若漏掉 `0 <= i < m-1` 的过滤，会把不存在的块算进 `cnt`，`arr[0]` 偏小。
- `total - len(cnt)` 必须用「块数」而不是「黑格数」来减。示例 1 中 `total=4`、`len(cnt)=1`，得 `arr[0]=3`；若误写成 `total - len(coordinates)` 会得到 3 但示例 2 就崩成 `4-3=1`，正确是 0。

## 如果面试官追问
若 `coordinates` 规模涨到 `10^9` 且要求输出每个块的黑格数，怎么办？
答：仍只枚举黑格影响的块，无法枚举全部块，只能输出非零块，其余按 0 处理。
