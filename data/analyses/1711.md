## 一句话思路
边遍历边用哈希表记录已见美味值的出现次数，对每个 x 枚举 2 的幂 s 查 s-x 的计数累加。

## 怎么做
1. 先求上界：`max_val = max(deliciousness)`，两数之和最大为 `2 * max_val`，枚举的幂只需到 `1 << (2*max_val).bit_length()`。
2. 遍历 `x`，对每个幂 `s` 查 `cnt.get(s - x, 0)` 累加到答案，再 `cnt[x] += 1`。
3. 顺序必须是「先查后加」，这样每对只被数一次，且天然排除自己和自己配对。

以示例 1 `[1,3,5,7,9]` 为例，`max_val = 9`，幂枚举到 16。处理到 `x = 3` 时，`cnt = {1: 1}`；`s = 4` 查 `cnt[1] = 1`，答案变 1；`s = 8` 查 `cnt[5] = 0`。处理到 `x = 7` 时 `cnt = {1:1, 3:1, 5:1}`，`s = 8` 查 `cnt[1] = 1`，`s = 16` 查 `cnt[9] = 0`，答案累加到 3；最后 `x = 9` 时 `s = 16` 查 `cnt[7] = 1`，答案 4。

```python
MOD = 10**9 + 7
cnt = {}
ans = 0
limit = 1 << (2 * max(deliciousness)).bit_length()
for x in deliciousness:
    s = 1
    while s <= limit:
        ans += cnt.get(s - x, 0)
        s <<= 1
    cnt[x] = cnt.get(x, 0) + 1
return ans % MOD
```

## 复杂度
时间：O(n log M)，n 为数组长度，M 为最大美味值，每个元素枚举约 log(2M) 个幂。
空间：O(n)，哈希表最多存 n 个不同美味值。

## 易错点
- 输入 `[1,1,1]` → 若先 `cnt[x] += 1` 再查表，会把自身算进去，得到 6 而非 3 → 必须先查后加，且查的是 `s - x` 而不是 `s`。
- 输入 `[0,0]` 或含 0 的数组 → 若幂枚举从 `s = 1` 起且上界用 `max_val` 而非 `2*max_val`，会漏掉 `0+0=0` 之外的组合或越界 → 上界取 `2*max_val` 的 bit_length，`s = 1` 起步即可覆盖 0 的情况（0 不是 2 的幂，`0+0` 不合法，无需特殊处理）。

## 如果面试官追问
问：若要求输出所有配对方案而非计数？答：把 `cnt` 的值改成下标列表，查表时两两拼接，复杂度升到 O(答案规模)。
