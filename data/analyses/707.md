## 一句话思路
用带哑结点 `dummy` 的单链表，`size` 记录长度，所有插入删除都先走到 `index-1` 的前驱再改指针。

## 怎么做
1. 初始化 `dummy = Node(0)`、`size = 0`，`dummy.next = None`。
2. `get(index)`：先判 `index < 0 or index >= size` 返回 `-1`，否则从 `dummy.next` 走 `index` 步。
3. `addAtIndex(index, val)`：`index > size` 直接返回；否则从 `dummy` 走 `index` 步到前驱 `prev`，插入 `Node(val)` 到 `prev` 之后，`size += 1`。
4. `deleteAtIndex(index)`：判 `index < 0 or index >= size` 返回；走到 `index-1` 前驱，`prev.next = prev.next.next`，`size -= 1`。

以官方示例为例：`addAtHead(1)` 后 `dummy.next.val = 1`，`size = 1`；`addAtTail(3)` 走到尾部插入，链表 `1->3`，`size = 2`；`addAtIndex(1, 2)` 从 `dummy` 走 1 步到值为 1 的节点，插入后 `1->2->3`，`size = 3`；此时 `get(1)` 从 `dummy.next` 走 1 步得 `2`。

```python
def addAtIndex(self, index, val):
    if index > self.size:
        return
    prev = self.dummy
    for _ in range(index):
        prev = prev.next
    node = Node(val)
    node.next = prev.next
    prev.next = node
    self.size += 1

def deleteAtIndex(self, index):
    if index < 0 or index >= self.size:
        return
    prev = self.dummy
    for _ in range(index):
        prev = prev.next
    prev.next = prev.next.next
    self.size -= 1
```

关键点：`addAtIndex` 的循环走 `index` 步（从 `dummy` 出发），`deleteAtIndex` 也走 `index` 步，两者都停在 `index-1` 位置的前驱上，因为 `dummy` 本身占了一位。

## 复杂度
时间：`get`/`add`/`delete` 均为 O(index)，最坏 O(n)，n 为 `size`。
空间：O(1) 额外指针，链表本身 O(n)。

## 易错点
- `addAtIndex(index, val)` 中 `index == size` 时是合法追加，若写成 `index >= size` 直接返回，示例里 `addAtTail` 之后的追加会丢失，正确判断是 `index > size` 才返回。
- `deleteAtIndex(0)` 时若从 `dummy.next` 出发走 `index-1 = -1` 步会越界或删错节点，正确做法是从 `dummy` 出发走 `index` 步，`prev` 停在 `dummy` 上，`prev.next = prev.next.next` 正好删掉头节点。

## 如果面试官追问
问：改成双链表有什么收益？
答：`get` 可按 `index < size//2` 从 `head` 或 `tail` 双向逼近，最坏步数减半，但仍是 O(n)，只是常数优化。
