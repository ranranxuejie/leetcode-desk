## 一句话思路
按 `session_id` 分组聚合出时长、滚动数、点击数、购买数，再用四个条件一次过滤。

## 怎么做
1. 用 `GROUP BY session_id` 一次算出 `MAX(event_timestamp) - MIN(event_timestamp)` 的分钟数、`SUM(event_type='scroll')`、`SUM(event_type='click')`、`SUM(event_type='purchase')`。
2. 把聚合结果套进 `HAVING`，四个条件同时成立才留下。
3. 比率写成 `click_count / scroll_count < 0.20`，因为 `scroll_count >= 5` 已保证分母非零，不会除零。
4. 最后 `ORDER BY scroll_count DESC, session_id ASC`。

以 S003 为关键中间值：`scroll_count=5`、`click_count=1`，比率 `1/5 = 0.20`，`0.20 < 0.20` 为 `False`，被正确排除；S001 是 `0/6 = 0.0`，通过。

```python
# 聚合后逐会话判断
for sid, g in df.groupby("session_id"):
    dur = (g.event_timestamp.max() - g.event_timestamp.min()).total_seconds() / 60
    scroll = (g.event_type == "scroll").sum()
    click = (g.event_type == "click").sum()
    buy = (g.event_type == "purchase").sum()
    if dur > 30 and scroll >= 5 and click / scroll < 0.20 and buy == 0:
        rows.append((sid, g.user_id.iloc[0], int(dur), int(scroll)))
```

SQL 等价写法：

```python
# HAVING 里四个条件用 AND 串起来
# HAVING duration > 30 AND scroll_count >= 5
#    AND click_count / scroll_count < 0.20 AND purchase_count = 0
```

## 复杂度
时间 O(n)：扫一遍 `app_events` 的 n 行做分组聚合，排序 O(k log k)，k 为会话数。
空间 O(k)：每个会话存 4 个计数值，外加结果集。

## 易错点
- S003 的 `click_count/scroll_count = 1/5 = 0.20` → 若写成 `<= 0.20` 会把它误判为僵尸会话 → 必须用严格 `< 0.20`，题面明确「等于 0.20 不算」。
- 时长用 `app_open` 到 `app_close` 相减 → 若某会话缺 `app_close` 会算成 0 或报错 → 正确做法是对该会话所有事件取 `MAX - MIN`，不依赖首尾事件类型。

## 如果面试官追问
问：若同一 `session_id` 可能跨用户出现怎么办？
答：分组键改成 `(user_id, session_id)`，输出时 `user_id` 直接取分组键，不再用 `iloc[0]`。
