## 一句话思路
用字典存 `key -> (value, expire_at)`，时间取 `timeDelays` 的累计值，惰性删除：访问时才判断是否过期。

## 怎么做
1. 维护 `now` 累加 `timeDelays[i]`，`set` 时写入 `expire_at = now + duration`。
2. `set` 先查旧键：存在且 `expire_at > now` 才返回 `True`，否则 `False`，两种情况都覆盖。
3. `get` 和 `count` 都先按 `expire_at <= now` 清掉过期项再统计。
4. 以示例 2 为例：`t=40` 时 `set(1,50,100)`，旧键 `expire_at=50 > 40` 未过期，返回 `True`，新 `expire_at=140`；`t=120` 时 `120 <= 140`，`get(1)` 返回 `50`。

```python
cache = {}  # key -> (value, expire_at)
now = 0
for i, act in enumerate(actions):
    now += timeDelays[i]
    if act == "set":
        k, v, d = values[i]
        alive = k in cache and cache[k][1] > now
        cache[k] = (v, now + d)
        res.append(alive)
    elif act == "get":
        k = values[i][0]
        res.append(cache[k][0] if k in cache and cache[k][1] > now else -1)
    elif act == "count":
        res.append(sum(1 for _, e in cache.values() if e > now))
```

## 复杂度
时间：每个操作 O(1)，`count` 是 O(k)，k 为字典中键数，总 O(n·k) 最坏。
空间：O(k)，字典存每个未清理键的 `(value, expire_at)`。

## 易错点
- `set` 时旧键已过期（如示例 2 若在 `t=60` 再 `set(1,...)`，旧 `expire_at=50 <= 60`）→ 误返回 `True` → 必须先判 `expire_at > now` 再覆盖。
- `count` 直接 `len(cache)` → 示例 1 在 `t=150` 时字典里还留着 `key=1`，会错答 1 → 必须按 `expire_at > now` 过滤。

## 如果面试官追问
若 `duration` 上限从 1000 放大到 10^9、操作数到 10^5，惰性删除还够吗？
够，单次操作仍是 O(1)，只是 `count` 需改成维护存活计数或加最小堆。
