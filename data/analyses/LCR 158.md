## 一句话思路
摩尔投票：把不同商品两两抵消，剩下的候选必然是数量过半的那个。

## 怎么做
1. 维护 `cand` 和 `votes`，初始 `cand = None`、`votes = 0`。
2. 遍历 `stock`：`votes == 0` 时把当前元素设为 `cand`，然后 `votes += 1`；否则相同则 `votes += 1`，不同则 `votes -= 1`。
3. 遍历结束后 `cand` 就是答案（题面保证结果存在，无需第二遍验证）。

以 `stock = [6, 1, 3, 1, 1, 1]` 为例，关键中间值：处理到 `3` 时 `votes` 归零，`cand` 被重置为 `3`；接着 `1` 把 `cand` 顶成 `1`，之后两个 `1` 让 `votes` 涨到 3，最终 `cand = 1`。

```python
cand, votes = None, 0
for x in stock:
    if votes == 0:
        cand = x
    if x == cand:
        votes += 1
    else:
        votes -= 1
return cand
```

注意 `votes == 0` 的判断必须在比较 `x == cand` 之前，否则重置后 `cand` 还是旧值，会把 `votes` 减成 -1。

## 复杂度
时间：O(n)，一次遍历 `stock`，每个元素只做常数次比较。
空间：O(1)，只开 `cand` 和 `votes` 两个变量，没有额外数组或哈希表。

## 易错点
- 输入 `stock = [1]` → 若把 `votes == 0` 的重置写在 `x == cand` 之后，`cand` 仍是 `None`，`votes` 变 -1，返回 `None` → 正确做法是先判零再赋值，保证单元素数组直接返回 `1`。
- 输入 `stock = [2, 2, 1, 1, 2]` → 若误以为「最后 `cand` 一定过半」而不理解抵消逻辑，会在 `[1, 1, 2, 2, 3]` 这类无多数数组上返回错误值 → 本题题面保证存在结果，但若换到 169 题的变体（不保证存在），必须补一遍计数验证 `stock.count(cand) > len(stock) // 2`。

## 如果面试官追问
问：如果数组大到无法一次读入内存怎么办？
答：分块读，每块内跑摩尔投票得到局部 `cand`，再对所有局部候选做一次计数合并，仍只需 O(1) 额外空间。
