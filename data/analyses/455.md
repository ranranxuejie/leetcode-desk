## 一句话思路
两个数组都升序排序，用最小能满足当前胃口的饼干去配最小胃口的孩子，双指针一次扫完。

## 怎么做
1. 把 `g` 和 `s` 都 `sort()`，让「最小胃口」和「最小饼干」都排在前面。
2. 指针 `i` 扫孩子、`j` 扫饼干，都从 0 开始。
3. 若 `s[j] >= g[i]`，这块饼干就喂给这个孩子，`i += 1`；无论是否喂成，`j += 1`（这块饼干要么用掉了，要么太小永远没用）。
4. `i` 走到 `len(g)` 或 `j` 走到 `len(s)` 时停，返回 `i`。

拿示例 1 走一遍：`g = [1,2,3]`、`s = [1,1]` 排完序不变。`j=0` 时 `s[0]=1 >= g[0]=1`，喂成，`i=1, j=1`；`j=1` 时 `s[1]=1 < g[1]=2`，饼干太小，只 `j=2`；`j` 越界，返回 `i=1`。关键中间值是第二次比较的 `1 < 2`——这块 1 的饼干对胃口 2 和 3 都没用，直接丢弃，不用回头。

```python
g.sort()
s.sort()
i = j = 0
while i < len(g) and j < len(s):
    if s[j] >= g[i]:
        i += 1
    j += 1
return i
```

为什么贪心成立：排序后若某块饼干能喂饱当前最小胃口的孩子，喂给他不会比留给更大胃口的孩子更差；若喂不饱他，那更喂不饱后面任何孩子，这块饼干必然作废。所以每步都无回头。

## 复杂度
时间 O(m log m + n log n)，m = len(g)、n = len(s)，排序贡献两个 log，双指针扫描是 O(m+n)。
空间 O(1) 额外（不计排序自身开销），只开了 `i`、`j` 两个整数。

## 易错点
- `s = []`（提示允许 `s.length = 0`）→ 若先写 `s.sort()` 再进循环没问题，但若写成 `while i < len(g) and s[j] >= g[i]` 会 `IndexError` → 正确做法是把 `j < len(s)` 放在 `and` 左边，短路求值挡住越界。
- `g = [10,10]`、`s = [1,2,3]` → 若写成「每块饼干找能喂的最大胃口孩子」或对 `s` 从大到小配，容易把 3 浪费在别处、或误判能喂 1 个 → 正确做法是固定「最小胃口优先」，`s[j] < g[i]` 时只推进 `j`，绝不推进 `i`，本例返回 0。

## 如果面试官追问
要求输出具体分配方案（哪些饼干给了哪些孩子）怎么办？
答：在 `s[j] >= g[i]` 分支里记下 `(i, j)` 配对再 `i += 1`，其余逻辑不变，返回配对列表长度即答案。
