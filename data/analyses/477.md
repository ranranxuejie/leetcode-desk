## 一句话思路
按位统计：第 k 位上 1 的个数 c，该位贡献 c×(n−c)，因为每个 1 与每个 0 组成一对。

## 怎么做
1. 对每个位 k（0 到 30，因为 `nums[i] ≤ 10^9 < 2^30`），统计 `nums` 中该位为 1 的元素个数 `c`。
2. 该位贡献 `c * (n - c)`，累加到 `total`。
3. 返回 `total`。

以 `nums = [4,14,2]` 为例，n=3。二进制：4=`0100`，14=`1110`，2=`0010`。
- 第 2 位（值 4）：4 和 14 为 1，c=2，贡献 2×1=2。
- 第 3 位（值 8）：仅 14 为 1，c=1，贡献 1×2=2。
- 第 1 位（值 2）：14 和 2 为 1，c=2，贡献 2×1=2。
- 其余位 c=0，贡献 0。合计 6。

```python
total = 0
n = len(nums)
for k in range(31):
    c = sum((x >> k) & 1 for x in nums)
    total += c * (n - c)
return total
```

关键中间值：第 2 位 c=2，`c*(n-c)=2*1=2`；第 3 位 c=1，`1*2=2`。三位累加得 6，与示例一致。

## 复杂度
时间：O(31n)，31 是固定位数，实际 O(n)。
空间：O(1)，只用了 `total`、`c` 两个标量。

## 易错点
1. 位范围取 30 而非 31：`nums[i] ≤ 10^9 < 2^30`，最高位是第 29 位。若写成 `range(30)` 覆盖 0~29 位刚好够；若误写成 `range(20)` 会漏掉第 20~29 位，对 `nums=[10**9]` 这类输入少算贡献。稳妥用 `range(31)`。
2. 用 `c*(n-c)` 而非 `c*(c-1)//2`：后者只统计 1 与 1 的对，漏掉 1 与 0 的对。对 `nums=[4,14,2]` 第 2 位 c=2，`c*(c-1)//2=1` 会得 1 而非 2，最终输出 3 而非 6。

## 如果面试官追问
若 `nums` 长度扩到 10^6 且要求 O(n) 单遍？答：仍按位累加，每读一个数就更新 31 个位的计数，最后统一算 `c*(n-c)`，时间不变。
