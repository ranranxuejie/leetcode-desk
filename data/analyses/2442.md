## 一句话思路
把原数组和每个数的反转数都塞进一个 set，最后取 set 的长度；因为「不同」天然对应集合去重。

## 怎么做
1. 建一个空集合 `seen`，遍历 `nums` 时把原数 `x` 直接加入。
2. 对每个 `x` 用取模循环求反转值 `rev`：`rev = rev * 10 + x % 10`，`x //= 10`。
3. 把 `rev` 也加入 `seen`，遍历结束后返回 `len(seen)`。

以 `nums = [1,13,10,12,31]` 为例，处理 `10` 时循环得到 `rev = 1`（先取 0 再取 1，前导零自然被丢掉），于是 `seen` 里 `10` 和 `1` 同时存在；处理 `13` 得到 `31`，而 `31` 本身也在原数组里，重复加入不改变集合大小。最终 `seen = {1,10,12,13,21,31}`，长度 6。

```python
seen = set()
for x in nums:
    seen.add(x)
    rev = 0
    while x > 0:
        rev = rev * 10 + x % 10
        x //= 10
    seen.add(rev)
return len(seen)
```

关键点：`x` 在 while 里被消耗掉，所以要先 `seen.add(x)` 再进循环，否则原数丢失。

## 复杂度
时间 O(n · log M)，n 是 `nums` 长度，log M 来自每个数最多 7 位（M ≤ 10^6）的逐位反转。
空间 O(n)，`seen` 最多存 2n 个整数。

## 易错点
- 输入含 `10`、`100` 这类尾零数 → 若用字符串 `str(x)[::-1]` 再 `int()` 其实没问题，但若手写反转时把 `rev` 初始化成 `x % 10` 之类会漏掉前导零处理，得到错误值；正确做法是 `rev` 从 0 开始，靠 `rev * 10 + x % 10` 自然丢弃前导零，`10` 必须得到 `1`。
- 输入 `[2,2,2]` → 若把反转数追加到一个 list 再 `len(set(list))` 也正确，但若误以为「原数组已去重就不用管反转」而只对 `set(nums)` 做反转，会漏掉不同原数反转后相同的情况（如 `[12,21]` 反转后互相重合）；正确做法是对每个原始元素都算反转并全部并入同一个 `seen`。

## 如果面试官追问
问：如果 `nums[i]` 上限提到 10^18 怎么办？
答：算法不变，只是每个数位数升到 19，时间变 O(n · 19)，仍可接受；注意 Python 无溢出问题。
