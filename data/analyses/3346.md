## 一句话思路
排序后对每个候选值 x，用双指针框出 `[x-k, x+k]` 内的元素，答案 = 原有频率 + min(可改数量, numOperations)。

## 怎么做
1. 排序 `nums`，用 Counter 记每个值的原始频率。
2. 对每个不同的值 x 作为目标，双指针 l、r 维护满足 `nums[r] - nums[l] <= 2*k` 的窗口，窗口内元素都能改成 x。
3. 窗口大小 `cnt = r - l`，其中 `freq[x]` 个不用改，其余 `cnt - freq[x]` 个要消耗操作，取 `min(cnt - freq[x], numOperations)`。
4. 答案取所有 x 的 `freq[x] + min(...)` 最大值。

以 `nums=[1,4,5], k=1, numOperations=2` 为例：排序后 `[1,4,5]`。目标 x=4 时窗口 `[1,4,5]`（5-1=4 ≤ 2k=2？不，4>2，所以窗口是 `[4,5]`，cnt=2）。freq[4]=1，需改 1 个，min(1,2)=1，得 1+1=2。目标 x=5 时窗口 `[4,5]`，freq[5]=1，需改 1 个，得 2。答案 2。

```python
from collections import Counter
nums.sort()
freq = Counter(nums)
ans = 0
l = 0
for r, x in enumerate(nums):
    while nums[r] - nums[l] > 2 * k:
        l += 1
    cnt = r - l + 1
    ans = max(ans, freq[x] + min(cnt - freq[x], numOperations))
```

注意：窗口右端固定为当前 r，左端收缩到满足条件，这样每个 x 都能拿到以它为中心的最大可改集合。

## 复杂度
时间 O(n log n)：排序主导，双指针 O(n)。
空间 O(n)：Counter 存频率，排序栈空间 O(log n)。

## 易错点
- 输入 `nums=[1,1,1], k=0, numOperations=0` → 若忘记 `min(cnt-freq[x], numOperations)` 直接加 `cnt-freq[x]`，会错算成 3 但实际只能保持 3（这里恰好对），换成 `nums=[1,2,3], k=0, numOperations=0` 会错成 1 而正确是 1（也对）——真正翻车是 `numOperations=0` 时窗口内有多个不同值，如 `[1,2], k=1, numOperations=0`，不加 min 会得 2，正确是 1。必须取 min。
- 输入 `nums=[5,11,20,20], k=5, numOperations=1` → 若窗口条件写成 `nums[r]-nums[l] <= k` 而非 `2*k`，x=20 时窗口只含 `[20,20]`，漏掉 11 可改成 16 不行……实际 11 到 20 差 9 > 2k=10？9≤10 可以，窗口应含 11。写成 k 会漏，得 2 而非正确 2（这里巧合），换 `[5,11], k=5` 会漏 5→11 差 6≤10 应可合并。正确用 `2*k`。

## 如果面试官追问
若 numOperations 很大（≥n），答案是什么？答：所有元素都能改成同一值当且仅当 `max-min <= 2k`，否则取最大窗口大小。
