## 一句话思路
按值从小到大排序后，每个元素最终都要降到最小值，它跨过的不同值个数就是它的操作次数。

## 怎么做
1. 排序 `nums`，最小值 `nums[0]` 是最终统一目标。
2. 从左往右扫，维护「当前元素前面出现过多少个严格更小的不同值」`distinct`，它就是这个元素要付的操作数。
3. 若 `nums[i] != nums[i-1]`，说明进入新的一层，`distinct += 1`；把 `distinct` 累加进答案。

以 `nums = [5,1,3]` 为例：排序后 `[1,3,5]`。`i=0` 时 `distinct=0`；`i=1`，`3 != 1`，`distinct` 变 1，答案加 1；`i=2`，`5 != 3`，`distinct` 变 2，答案加 2，合计 3。中间值 `distinct` 从 0→1→2，正好是 5 要跨 3、1 两层，3 要跨 1 一层。

```python
nums.sort()
ans = 0
distinct = 0
for i in range(1, len(nums)):
    if nums[i] != nums[i - 1]:
        distinct += 1
    ans += distinct
return ans
```

再验 `[1,1,2,2,3]`：排序不变，`i=1` 相等不加；`i=2` 的 `2 != 1`，`distinct=1`，加 1；`i=3` 相等，加 1；`i=4` 的 `3 != 2`，`distinct=2`，加 2，合计 4，与示例一致。注意 `i` 从 1 开始，`nums[0]` 本身不产生操作。

## 复杂度
时间：排序 O(n log n) 主导，扫描 O(n)。
空间：排序额外 O(log n) 栈空间，其余只有 `ans`、`distinct` 两个变量。

## 易错点
- 输入 `[1,1,1]` → 若把 `distinct += 1` 写在循环体最外层而不判 `nums[i] != nums[i-1]`，会错成 2 → 必须只在值变化时递增，相等元素共享同一层。
- 输入 `[5,1,3]` → 若从 `i=0` 开始累加，会把最小值 `1` 也算一次操作，错成 4 → 循环从 `i=1` 起，`nums[0]` 是终点不是起点。

## 如果面试官追问
问：不排序能做吗？答：可以，用哈希集合记不同值，对每个 `nums[i]` 数「比它小的不同值个数」再求和，时间 O(n·d)，d 为不同值个数，n 大时不如排序。
