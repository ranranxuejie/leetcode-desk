## 一句话思路
先判总和能被 4 整除，再用回溯把每根火柴放进四条边之一，边和超过 target 就剪枝。

## 怎么做
1. 算 `total = sum(matchsticks)`，若 `total % 4 != 0` 或 `max(matchsticks) > total // 4` 直接返回 `False`。
2. 令 `target = total // 4`，把 `matchsticks` 降序排序，让长火柴先试，剪枝更早生效。
3. 开长度 4 的数组 `sides` 记录四条边当前和，回溯时对每根火柴依次尝试放进 `sides[i]`，放完递归下一根。
4. 剪枝：`sides[i] + stick > target` 跳过；`sides[i] == 0` 时若这条边失败，直接 `break`（空边等价，试一条就够）。

以 `[1,1,2,2,2]` 为例，`total=8`、`target=2`，排序后 `[2,2,2,1,1]`。第一根 2 放进 `sides[0]` 得 `[2,0,0,0]`，第二根 2 因 `sides[0]+2>2` 跳过，放进 `sides[1]` 得 `[2,2,0,0]`，继续填满后四边均为 2，返回 `True`。

```python
def dfs(i):
    if i == len(sticks):
        return True
    for j in range(4):
        if sides[j] + sticks[i] > target:
            continue
        sides[j] += sticks[i]
        if dfs(i + 1):
            return True
        sides[j] -= sticks[i]
        if sides[j] == 0:
            break
    return False
```

## 复杂度
时间：最坏 O(4^n)，n 为火柴根数，降序排序与剪枝大幅降低实际搜索量。
空间：O(n) 递归栈，外加长度 4 的 `sides` 数组。

## 易错点
- 输入 `[3,3,3,3,4]` → 只判 `total % 4` 会误判：`total=16` 能整除，但 `max=4` 恰好等于 `target=4`，其余 3 无法凑成 4，仍返回 `False`。正确做法是回溯真正尝试分配，不能只靠整除判断。
- 输入 `[5,5,5,5,4,4,4,4,3,3,3,3]` → 不排序时短火柴先放，长火柴最后无处可放，回溯树爆炸甚至超时。正确做法是先 `sort(reverse=True)`，让 5 先占边，剪枝在浅层就生效。

## 如果面试官追问
问：若火柴数增到 20 根怎么办？答：改用状压 DP，`dp[mask]` 记录当前已填边和模 `target`，O(2^n) 状态，n=20 约百万级可接受。
