## 一句话思路
枚举每个可能的公约数 g，看 nums 中所有 g 的倍数能否凑出 GCD 恰为 g，能则计数。

## 怎么做
1. 取 `m = max(nums)`，用布尔数组 `has` 标记哪些值在 nums 中出现过。
2. 对 g 从 1 到 m 枚举，用 `cur = 0` 累积：遍历 g 的倍数 `v = g, 2g, ...`，若 `has[v]` 为真则 `cur = gcd(cur, v)`。
3. 一旦 `cur == g` 就说明存在子序列 GCD 恰为 g，答案加一并 `break`（继续扫只会让 cur 更小或不变，不可能再等于 g）。
4. 关键中间值：以 `nums = [6,10,3]` 为例，g=2 时扫到 6 得 `cur=6`，扫到 10 得 `cur=gcd(6,10)=2`，命中，答案 +1；g=1 时扫 3 后 `cur=gcd(2,3)=1` 命中。

```python
from math import gcd
m = max(nums)
has = [False] * (m + 1)
for x in nums:
    has[x] = True
ans = 0
for g in range(1, m + 1):
    cur = 0
    for v in range(g, m + 1, g):
        if has[v]:
            cur = gcd(cur, v)
            if cur == g:
                ans += 1
                break
```

## 复杂度
时间：O(m log m)，调和级数 Σ m/g 次 gcd 调用，m = max(nums)。
空间：O(m)，`has` 布尔数组，与 n 无关。

## 易错点
- 只对 nums 里出现过的值枚举 g（如只试 6、10、3）→ 会漏掉 2 和 1 这类不在数组中的 GCD → 必须枚举 1..max(nums) 全部候选。
- 内层扫到 `cur == g` 后不 `break` 继续扫 → 后续倍数可能把 cur 拉得更小，逻辑上仍正确但白跑；更危险的是写成「扫完所有倍数再判断 cur 是否整除 g」→ 会把 g=1 之外的合数误判，正确做法是命中即停。

## 如果面试官追问
若 nums 长度到 10^5 但值域到 10^9 怎么办？答：值域大时改用「对每个 nums 元素枚举其约数并聚合 gcd」的约数分解法，复杂度随元素约数个数走。
