## 一句话思路
每个字符最多用 `cnt[c] // k` 次，答案长度 ≤ n/k，故按长度从大到小枚举字符多重集并回溯验证。

## 怎么做
1. 先统计 `cnt`，只保留 `cnt[c] >= k` 的字符，每个字符可用次数为 `cnt[c] // k`。
2. 答案长度上界 `maxLen = sum(cnt[c] // k)`，从 `maxLen` 往下枚举长度 `L`。
3. 对每个 `L`，按字典序**从大到小**回溯生成候选串（先试 `'z'` 到 `'a'`），第一个通过验证的就是答案。
4. 验证用双指针：把候选串重复 k 次去匹配 s，能匹配完即合法。

以 `s = "letsleetcode", k = 2` 为例：`cnt` 中 `l,e,t,c,o,d,s` 各 2 次，`maxLen = 7`。长度 7 到 4 全部失败；长度 3 时按 `z→a` 顺序试，`"let"` 在 `"letsleetcode"` 上重复两次可匹配（`l,e,t` 后接 `l,e,t`），直接返回。

```python
def ok(seq):
    it = iter(s)
    return all(ch in it for ch in seq * k)

def dfs(cur):
    if len(cur) == L:
        return cur if ok(cur) else None
    for c in sorted(avail, reverse=True):
        if avail[c]:
            avail[c] -= 1
            r = dfs(cur + c)
            avail[c] += 1
            if r: return r
    return None
```

## 复杂度
时间：O(Σ_L 26^L · n)，L ≤ n/k ≤ 7（由 `n < k*8` 保证），实际远小于此。
空间：O(n/k) 递归栈 + O(26) 计数表。

## 易错点
- 用 `cnt[c]` 而非 `cnt[c] // k` 作为可用次数 → 如 `s="bb", k=2` 会生成 `"bb"`，但 `"bbbb"` 不是 s 的子序列，正确上限是 1 次，答案 `"b"`。
- 回溯时按 `'a'→'z'` 顺序试 → 示例 1 会先返回 `"ete"` 而非字典序更大的 `"let"`；必须 `sorted(..., reverse=True)`，且长度优先于字典序。

## 如果面试官追问
问：若 n 放大到 10^5 且 k=2 怎么办？
答：n/k 上界仍是 5·10^4，枚举不可行；需改用「对每个字符二分答案长度 + 贪心验证」或按字符频率构造，复杂度降到 O(26·n·log n)。
