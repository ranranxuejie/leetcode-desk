## 一句话思路
把 usageLimits 升序排序后逐个累加，用「已用配额 - 已填格子」判断能否再撑起下一组，能撑就组数 +1。

## 怎么做
1. 排序 usageLimits，令 `groups = 0`、`used = 0`（已消耗的总配额）。
2. 遍历每个 `limit`：`used += limit`，若 `used >= (groups+1)*(groups+2)//2` 则 `groups += 1`。
3. 返回 `groups`。

以 `[1,2,5]` 为例：排序后仍是 `[1,2,5]`。处理 1 时 `used=1`，需要 `1*2//2=1`，成立，`groups=1`；处理 2 时 `used=3`，需要 `2*3//2=3`，成立，`groups=2`；处理 5 时 `used=8`，需要 `3*4//2=6`，成立，`groups=3`。关键中间值就是 `used=8` 对阈值 `6`，多出的 2 是后续可复用的余量。

```python
limits = sorted(usageLimits)
groups = used = 0
for limit in limits:
    used += limit
    need = (groups + 1) * (groups + 2) // 2
    if used >= need:
        groups += 1
return groups
```

为什么成立：k 组的最短长度是 1,2,…,k，总格子数 `k(k+1)/2`；每个数字在每组最多出现一次，所以一个数字的配额只能填进不同组，配额总量够且单个数字不超过 k 时总能排满（贪心按列填即可）。

## 复杂度
时间 O(n log n)，排序贡献 log n，遍历贡献 n。
空间 O(n)，`sorted` 复制了一份数组。

## 易错点
- 输入 `[1,1]`：若只看总配额 `2 >= 1` 就判 2 组，会错成 2；正确做法是阈值用 `(groups+1)*(groups+2)//2`，第 2 组需要 3 个格子，`used=2 < 3`，只能 1 组。
- 输入 `[1000000000]` 或大配额数组：`used` 会累加到 1e14 量级，若用 32 位思路截断会算错；Python 整数不溢出，直接累加即可，不要手动取模。

## 如果面试官追问
要求输出具体分组方案怎么办？答：按组号从大到小填，每个数字尽量放进编号最大的空组，用堆维护各组剩余空位即可。
