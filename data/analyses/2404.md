## 一句话思路
用哈希表统计每个偶数出现次数，按「次数降序、数值升序」取第一个。

## 怎么做
1. 遍历 `nums`，跳过奇数（`x & 1`），只把偶数累加进 `cnt[x]`。
2. 遍历 `cnt` 的键值对，维护 `best`（当前最优偶数）和 `best_cnt`。
3. 更新条件：`c > best_cnt` 或 `c == best_cnt and x < best`，这样平票时自动留小的。
4. 若 `best` 从未被赋值，返回 `-1`。

以示例 1 `nums = [0,1,2,2,4,4,1]` 为例，统计完 `cnt = {0:1, 2:2, 4:2}`；遍历到 `2` 时 `best=2, best_cnt=2`，再遍历到 `4` 时 `c == best_cnt` 但 `4 < 2` 为假，故 `best` 保持 `2`。

```python
cnt = {}
for x in nums:
    if x % 2 == 0:
        cnt[x] = cnt.get(x, 0) + 1

best, best_cnt = -1, 0
for x, c in cnt.items():
    if c > best_cnt or (c == best_cnt and x < best):
        best, best_cnt = x, c
return best
```

注意 `best` 初值取 `-1` 是安全的：`nums[i] >= 0`，任何真实偶数都大于它，且 `best_cnt` 初值 `0` 保证第一次一定进分支。

## 复杂度
时间 O(n)：一次遍历 `nums` 建表，一次遍历 `cnt`（≤ n 个键）。
空间 O(n)：`cnt` 最多存 n/2 个偶数键，无其他额外数组。

## 易错点
- 输入 `[0,0,1]` → 若把 `best` 初值写成 `0` 并用 `best == -1` 判空，会误判「没找到」而返回 `-1` → 正确做法是用 `best_cnt = 0` 做哨兵，`0` 的计数 `2 > 0` 能正常更新。
- 输入 `[4,4,2,2]` → 若只写 `c > best_cnt` 而不加 `x < best`，遍历顺序决定返回 `4` 还是 `2`，字典序不保证 → 必须显式写平票取小，才能稳定得到 `2`。

## 如果面试官追问
若 `nums` 长度涨到 10^7 且值域仍是 [0, 10^5]，怎么做？
答：改用长度 10^5+1 的计数数组，O(值域) 空间换掉哈希常数，仍是一遍扫描。
