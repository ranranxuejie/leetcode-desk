## 一句话思路
先统计每行每列的一的个数，再用 `onesRow[i] + onesCol[j] - (n - onesRow[i]) - (m - onesCol[j])` 直接填 diff，避免重复数零。

## 怎么做
1. 遍历 grid，累加 `onesRow[i]` 和 `onesCol[j]`，零的个数由 `n - onesRow[i]`、`m - onesCol[j]` 推出。
2. 对每个 `(i, j)` 套公式，把四个量合并成 `2*onesRow[i] + 2*onesCol[j] - n - m`。
3. 用示例 1 验证：`onesRow = [2,2,1]`，`onesCol = [1,1,3]`；取 `i=2, j=0`，得 `2*1 + 2*1 - 3 - 3 = -2`，与输出 `diff[2][0] = -2` 一致。
4. 按行构造结果矩阵返回。

```python
m, n = len(grid), len(grid[0])
onesRow = [0] * m
onesCol = [0] * n
for i in range(m):
    for j in range(n):
        if grid[i][j] == 1:
            onesRow[i] += 1
            onesCol[j] += 1
diff = [[0] * n for _ in range(m)]
for i in range(m):
    for j in range(n):
        diff[i][j] = 2 * onesRow[i] + 2 * onesCol[j] - n - m
```

关键中间值：示例 1 中 `onesRow[0]=2`、`onesCol[2]=3`，代入得 `diff[0][2] = 2*2 + 2*3 - 3 - 3 = 4`，与官方输出一致。

## 复杂度
时间：O(m*n)，两遍扫描矩阵，每格 O(1)。
空间：O(m+n) 存 onesRow/onesCol，另加 O(m*n) 的 diff 输出。

## 易错点
- 把 `zerosRow[i]` 写成 `m - onesRow[i]`：行有 n 个元素，零的个数应是 `n - onesRow[i]`；示例 1 第 0 行若误用 m=3 会得 `3-2=1`，正确是 `3-2=1` 恰好巧合，但第 2 行 `onesRow=1` 时 `m-1=2` 与 `n-1=2` 也巧合，换 m≠n 的输入（如 2×3 全 1）立刻错成负数。
- 直接对每格重新数行、列的一和零：复杂度退化成 O(m*n*(m+n))，m*n=10^5 且 m、n 都接近 316 时约 6*10^7 次操作，虽可能过但没必要；正确做法是先预处理 onesRow/onesCol 再 O(1) 查表。

## 如果面试官追问
问：若 grid 是稀疏的、只有 k 个 1，能否更快？
答：只遍历 k 个 1 的位置累加 onesRow/onesCol，其余行列计数为 0，时间降到 O(k + m*n) 填表仍不可省。
