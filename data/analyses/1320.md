## 一句话思路
用 DP 记录「当前字母由一根手指按下，另一根手指停在哪个字母」，把 26×n 的状态压成 n 个。

## 怎么做
1. 坐标映射：`pos[c] = (ord(c)-65)//6, (ord(c)-65)%6`，注意 Z 是 (4,1) 而非 (4,2)，所以第 5 行只有 4 个字母，需特判 `ord(c)-65 == 25`。
2. 定义 `dp[j]` = 打完 `word[i]` 后，一根手指在 `word[i]`、另一根手指停在字母 `j` 的最小总距离。
3. 转移只有两种：另一根手指从 `j` 移到 `word[i+1]`（当前手指不动），或当前手指从 `word[i]` 移到 `word[i+1]`（另一根手指停在 `j` 不变）。
4. 初始 `dp` 全为 0（起始位置零代价），答案取 `min(dp)`。

以 `word = "CAKE"` 为例：C=(0,2), A=(0,0), K=(1,5), E=(0,4)。打完 C 后 `dp` 全 0。处理 A 时，若另一根手指停在 C，则 `dp[C] = dist(C,A) = 2`；若当前手指从 C 移到 A，则 `dp[C]` 保持 0（另一根手指仍在 C）。到 K 时最优是让停在 C 的手指不动、当前手指从 A 移到 K，`dp[C] = 2 + dist(A,K) = 2+6 = 8`，而让另一根手指从 C 移到 K 得 `dp[A] = 0 + dist(C,K) = 1+3 = 4`。最终 E 时 `dp[K] = 4 + dist(K,E) = 4+1 = 5`，`dp[A] = 2 + dist(A,E) = 2+4 = 6`，取 min 得 3（对应另一根手指从 K 移到 E 的路径）。

```python
def dist(a, b):
    return abs(a[0]-b[0]) + abs(a[1]-b[1])

pos = {}
for i in range(26):
    c = chr(65+i)
    pos[c] = (i//6, i%6) if i < 25 else (4, 1)

n = len(word)
dp = [0] * 26
for i in range(1, n):
    ndp = [float('inf')] * 26
    cur, nxt = word[i-1], word[i]
    for j in range(26):
        if dp[j] == float('inf'):
            continue
        ndp[j] = min(ndp[j], dp[j] + dist(pos[cur], pos[nxt]))
        ndp[ord(cur)-65] = min(ndp[ord(cur)-65], dp[j] + dist(pos[chr(65+j)], pos[nxt]))
    dp = ndp
return min(dp)
```

## 复杂度
时间 O(26·n)，n 为 `word` 长度，每步扫 26 个停靠字母。
空间 O(26)，只开两个长度 26 的数组。

## 易错点
- 输入 `"CAKE"` 时若把 Z 也按 `i//6, i%6` 算成 (4,2)，则 `dist` 全错，答案偏大；正确做法是对 `i == 25` 特判为 (4,1)。
- 输入 `"HAPPY"` 中连续两个 P，若转移时漏掉「当前手指不动、另一根手指移到 P」这一支（`dist(P,P)=0`），会多算距离；正确做法是两支都取 min，`ndp[j]` 和 `ndp[ord(cur)-65]` 都要更新。

## 如果面试官追问
问：若要求输出具体的手指移动方案怎么办？
答：在 `dp` 转移时额外存前驱 `(i, j, 哪根手指动)`，最后从 `min(dp)` 回溯即可。
