## 一句话思路
区间 DP：`dp[i][j]` 表示猜中 `[i,j]` 内任意数所需的最小保证金额，枚举第一个猜的 `k` 取最坏分支的最小值。

## 怎么做
1. 定义 `dp[i][j]`，`i == j` 时为 0（只剩一个数，直接猜中不花钱）。
2. 枚举区间长度 `length` 从 2 到 n，再枚举左端点 `i`，右端点 `j = i + length - 1`。
3. 对每个 `k in [i, j]`，猜错后最坏花费是 `k + max(dp[i][k-1], dp[k+1][j])`，取所有 `k` 的最小值。
4. 返回 `dp[1][n]`。

以 `n = 10` 为例，算 `dp[1][2]`：`k=1` 时 `1 + max(dp[1][0], dp[2][2]) = 1 + 0 = 1`；`k=2` 时 `2 + max(dp[1][1], dp[3][2]) = 2`。取最小得 `dp[1][2] = 1`。这正是示例 3 的答案，也是往上递推到 `dp[1][10] = 16` 的起点。

```python
n = 10
dp = [[0] * (n + 2) for _ in range(n + 2)]
for length in range(2, n + 1):
    for i in range(1, n - length + 2):
        j = i + length - 1
        dp[i][j] = 2**31 - 1
        for k in range(i, j + 1):
            cost = k + max(dp[i][k - 1], dp[k + 1][j])
            dp[i][j] = min(dp[i][j], cost)
print(dp[1][n])  # 16
```

注意 `dp` 开 `n+2` 是为了让 `dp[i][i-1]`（空区间）和 `dp[j+1][j]` 合法访问，空区间天然是 0，不用特判。

## 复杂度
时间：`O(n^3)`，三层循环分别贡献区间长度、左端点、猜测点 `k`。
空间：`O(n^2)`，即 `dp` 表本身，无其他辅助结构。

## 易错点
- `n = 1` → 若循环从 `length = 1` 起且没初始化 `dp[1][1]`，会返回 `2**31 - 1` → 正确做法是 `i == j` 保持初始 0，循环从 `length = 2` 开始。
- 边界 `k = i` 或 `k = j` → 若 `dp` 只开 `n+1` 且不处理空区间，`dp[i][i-1]` 会越界或取到脏值 → 正确做法是开 `n+2` 并让空区间保持 0，使 `max(dp[i][k-1], dp[k+1][j])` 在端点处自动退化为单侧值。

## 如果面试官追问
问：n 放大到 10^4 还能这么做吗？
答：不能，`O(n^3)` 会超时；这题有数学结论，最优首猜接近 `n` 的某个比例，可用 `O(n^2)` 或直接查表，但面试一般只要求到 200 的 DP。
