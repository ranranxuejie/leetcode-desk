## 一句话思路
从 `isqrt(num+2)` 往下枚举，第一个能整除 `num+1` 或 `num+2` 的 `d` 就给出最接近的一对。

## 怎么做
1. 两个因数越接近，较小的那个越接近 `sqrt(n)`，所以从 `isqrt(num+2)` 开始向下试。
2. 对每个 `d`，先看 `num+2` 能否被 `d` 整除，能就返回 `[d, (num+2)//d]`。
3. 否则看 `num+1`，能整除就返回 `[d, (num+1)//d]`。
4. 因为 `d` 从大到小，第一个命中的必然是差最小的一对，无需比较。

以 `num = 999` 为例：`num+2 = 1001`，`isqrt(1001) = 31`。`d` 从 31 往下试，31、30…都不整除 1001 或 1000；到 `d = 25` 时 `1000 % 25 == 0`，返回 `[25, 40]`，与示例 3 一致（顺序任意）。注意 `d = 40` 不会出现，因为起点是 31。

```python
from math import isqrt

d = isqrt(num + 2)
while True:
    if (num + 2) % d == 0:
        return [d, (num + 2) // d]
    if (num + 1) % d == 0:
        return [d, (num + 1) // d]
    d -= 1
```

关键点：`num+2` 优先于 `num+1` 判断，是因为同一个 `d` 下 `num+2` 的配对因数更大、差更小；但两者起点相同，先命中谁就返回谁，不会漏掉更优解——更优解只可能来自更大的 `d`，而更大的 `d` 已经试过了。

## 复杂度
时间：O(sqrt(num))，`d` 从 `isqrt(num+2)` 递减到 1，最坏约 3.2 万次取模。
空间：O(1)，只用了 `d` 一个整型变量。

## 易错点
- `num = 1` → 若从 `isqrt(num+1)` 起手会漏掉 `num+2 = 3` 的因子对，错成 `[1,2]`；正确起点是 `isqrt(num+2)`，得 `[1,3]`（3 的因数只有 1 和 3）。
- `num = 8` → 若只检查 `num+1 = 9` 就返回，得 `[3,3]` 恰好对；但 `num = 123` 时 `num+1 = 124` 的最优是 `[4,31]`（差 27），而 `num+2 = 125` 是 `[5,25]`（差 20），只查 `num+1` 会错成 `[4,31]`；正确做法是两个数都查，靠 `d` 递减保证全局最优。

## 如果面试官追问
问：`num` 上限提到 `10^18` 怎么办？
答：`isqrt` 仍是 O(1) 位运算级，枚举量涨到 `10^9` 就不可接受，需改用 Pollard-Rho 分解 `num+1`、`num+2` 再枚举因数对。
