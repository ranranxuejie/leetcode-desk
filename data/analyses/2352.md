## 一句话思路
把每行转成元组存进哈希表计数，再逐列取出元组去表里查，命中就累加。

## 怎么做
1. 遍历 `grid` 的每一行，用 `tuple(row)` 作键，`Counter` 里计数加一。
2. 对每个列下标 `j`，用 `tuple(grid[i][j] for i in range(n))` 拼出列元组。
3. 用这个列元组去 `Counter` 里取 `cnt.get(col, 0)`，累加到答案。

以示例 1 的 `grid = [[3,2,1],[1,7,6],[2,7,7]]` 为例：行计数表是 `{(3,2,1):1, (1,7,6):1, (2,7,7):1}`。取第 1 列得到 `(2,7,7)`，在表里命中，答案 +1；其余两列 `(1,6,7)`、`(1,6,7)` 都不在表里，最终返回 1。

```python
from collections import Counter

n = len(grid)
row_cnt = Counter(tuple(row) for row in grid)
ans = 0
for j in range(n):
    col = tuple(grid[i][j] for i in range(n))
    ans += row_cnt.get(col, 0)
```

关键点：行和列都统一成 `tuple` 才能当字典键，`list` 不可哈希。示例 2 里第 2、3 行都是 `(2,4,2,2)`，`row_cnt[(2,4,2,2)] = 2`，第 2 列也是 `(2,4,2,2)`，一次就贡献 2 对，加上第 0 行第 0 列的 1 对，正好 3。

## 复杂度
时间：O(n²)，构造 n 个行元组和 n 个列元组各扫 n 个元素。
空间：O(n²)，`Counter` 最多存 n 个长度 n 的元组。

## 易错点
- 用 `list` 当字典键 → 直接抛 `TypeError: unhashable type: 'list'` → 行和列都必须先 `tuple(...)` 再入表或查表。
- 只统计「行在列中出现过」而不计重数 → 示例 2 会返回 2 而不是 3 → 必须用 `Counter` 存行出现次数，列命中时加的是次数而非 1。

## 如果面试官追问
问：n 放大到 10⁴、矩阵稀疏怎么办？
答：只对非零位置建「行签名/列签名」，用 `(下标, 值)` 稀疏元组做键，避免 O(n²) 全量构造。
