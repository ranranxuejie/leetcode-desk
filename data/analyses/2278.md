## 一句话思路
遍历 `s` 统计 `letter` 出现次数 `cnt`，答案就是 `cnt * 100 // len(s)`，整除天然向下取整。

## 怎么做
1. 用 `s.count(letter)` 一次拿到出现次数，记为 `cnt`。
2. 用 `len(s)` 拿到总长度，记为 `n`。
3. 返回 `cnt * 100 // n`，先乘后除保证整除结果就是向下取整。

以官方示例 `s = "foobar", letter = "o"` 为例：`cnt = s.count("o") = 2`，`n = 6`，中间值 `cnt * 100 = 200`，`200 // 6 = 33`，返回 33。若先算 `2 / 6` 得 0.333…，再乘 100 取整，浮点误差可能让结果变成 32，所以顺序必须是先乘 100。

```python
cnt = s.count(letter)
n = len(s)
return cnt * 100 // n
```

关键点只有两个：`count` 直接给出分子，`//` 直接给出向下取整，不需要 `math.floor`，也不需要 `int()` 转换浮点。示例 2 中 `s = "jjjj", letter = "k"`，`cnt = 0`，`0 * 100 // 4 = 0`，自然返回 0，无需特判。

## 复杂度
时间：O(n)，`s.count` 扫一遍 `s`，n 为 `len(s)`。
空间：O(1)，只存 `cnt` 和 `n` 两个整数。

## 易错点
- 写成 `cnt / n * 100` 再取整 → 对 `"foobar"` 得 `0.333... * 100 = 33.33...`，`int()` 截断虽得 33，但某些长度下浮点表示偏差会让 `33.0` 变成 `32.999...`，截断成 32 → 正确做法是整数运算 `cnt * 100 // n`，全程不碰浮点。
- 用 `round(cnt * 100 / n)` 或 `math.ceil` → 对 `"foobar"` 的 33.33 会四舍五入成 33 看不出错，但对 `cnt * 100 / n = 33.6` 这类值会返回 34，与题目要求的向下取整不符 → 只用 `//`，不用 `round`、`ceil`。

## 如果面试官追问
追问：如果 `s` 长度到 10^7 且要多次查询不同 `letter`，怎么优化？
答：先一次遍历建 26 长度的计数数组，之后每次查询 O(1) 取 `freq[ord(letter) - 97] * 100 // n`。
