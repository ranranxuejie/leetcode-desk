## 一句话思路
逐元素拆出 `width = nums[i] % 10` 和 `d = nums[i] // 10`，按位数切出 x、y 后算 `pow(x, y, MOD)` 累加。

## 怎么做
1. 对每个 `v` 取 `width = v % 10`、`d = v // 10`。
2. 用 `len(str(d))` 得总位数 `L`，则 `y = d % 10**(L - width)`、`x = d // 10**(L - width)`。
3. 累加 `pow(x, y, 10**9 + 7)`，最后再取一次模。

以 `v = 2522` 为例：`width = 2`，`d = 252`，`L = 3`，`10**(3-2) = 10`，于是 `y = 252 % 10 = 2`、`x = 252 // 10 = 25`，解码值 `pow(25, 2, MOD) = 625`。

```python
MOD = 10**9 + 7
total = 0
for v in nums:
    width = v % 10
    d = v // 10
    p = 10 ** (len(str(d)) - width)
    x, y = d // p, d % p
    total = (total + pow(x, y, MOD)) % MOD
return total
```

关键点：`p` 是「y 的位数」对应的 10 的幂，`d // p` 与 `d % p` 天然把 `d` 切成前后两段，不需要转字符串再拼接。

## 复杂度
时间：O(n · log nums[i])，每个元素做一次 `str(d)` 和一次 `pow`，指数为 y 的位数级别。
空间：O(1)，只开了 `width`、`d`、`p`、`x`、`y` 几个标量。

## 易错点
- `nums = [2301]` 时若先算 `x**y` 再取模，中间值 1073741824 虽在 Python 里没问题，但换成 `pow(x, y)` 无模版本在 y 接近 10^9 时会直接卡死；必须用三参数 `pow(x, y, MOD)`，它内部快速幂，且 `y` 最大约 10^9 位数字对应的值。
- `width` 取的是 `nums[i] % 10` 而不是 `d % 10`：对 `2522`，若误用 `d = 252` 的末位 2 恰好相同看不出错，但对 `231` 用 `d % 10 = 3` 会得 `width = 3`，而 `d = 23` 只有 2 位，`10**(2-3)` 变成小数、切片全错；正确是 `v % 10 = 1`。

## 如果面试官追问
问：若 `nums[i]` 允许到 10^100 怎么办？
答：`v % 10` 和 `v // 10` 换成按字符串取末位与去尾，`len(str(d))` 直接可用，其余逻辑不变。
