## 一句话思路
按下时间就是相邻两次事件的时间差，一次遍历累加每个 index 的时长，边算边比最大值即可。

## 怎么做
1. 用 `prev_time = 0` 记录上一次按下的时间，`best_idx` 和 `best_dur` 记录当前最优。
2. 遍历 `events`，对每个 `[idx, t]` 算 `dur = t - prev_time`，这就是这次按下持续的时间。
3. 把 `dur` 累加到该按钮的总时长上（用字典 `total`），再和 `best_dur` 比较。
4. 比较时用严格大于：`dur > best_dur` 才更新，这样时长相等时保留先出现的更小 index。

以示例 1 的 `events = [[1,2],[2,5],[3,9],[1,15]]` 为例，走到最后一条 `[1,15]` 时 `prev_time = 9`，`dur = 15 - 9 = 6`，`total[1]` 从 2 变成 8，`6 > 4`（此前 `best_dur` 是 4）所以 `best_idx` 更新为 1。

```python
prev_time = 0
best_idx, best_dur = -1, -1
total = {}
for idx, t in events:
    dur = t - prev_time
    prev_time = t
    total[idx] = total.get(idx, 0) + dur
    if dur > best_dur:
        best_dur, best_idx = dur, idx
```

注意 `best_dur` 初值取 `-1` 而不是 0，因为 `time_i >= 1`，第一次 `dur` 至少为 1，用 `-1` 保证第一条一定被选中。

## 复杂度
时间：O(n)，n 为 `events` 长度，每条事件只做常数次运算。
空间：O(k)，k 为不同 index 的个数，字典 `total` 存每个按钮的累计时长。

## 易错点
- 输入 `events = [[10,5],[1,7]]` → 若把 `prev_time` 初值写成 `events[0][1]` 再从头遍历，第一条 `dur` 会算成 0，漏掉 5 这个最长时长 → 正确做法是 `prev_time = 0`，第一条的 `dur` 就是它自己的时间戳。
- 输入 `[[1,2],[2,5],[3,9],[1,15]]` → 若用 `>=` 更新 `best_dur`，当两个按钮时长相等时会保留后出现的较大 index → 正确做法是用严格 `>`，让相等时先出现的更小 index 胜出。

## 如果面试官追问
追问：如果 events 不按时间排序怎么办？
答：先按 `time` 排序再跑同一套逻辑，时间 O(n log n)，其余不变。
