## 一句话思路
摩尔投票扩展成两候选：超过 ⌊n/3⌋ 的元素最多两个，先选出候选，再回扫验票。

## 怎么做
1. 维护 `c1, c2` 两个候选和 `v1, v2` 两个计数，遍历 `nums` 时先匹配已有候选，否则填空位，否则两个计数同时减一。
2. 遍历结束后 `c1, c2` 只是「可能」的答案，必须再扫一遍 `nums` 数真实票数。
3. 只有 `count > n // 3` 的候选才放进结果。

以 `nums = [3,2,3]` 为例：读到第一个 `3` 时 `c1=3, v1=1`；读到 `2` 时 `c2=2, v2=1`；读到第二个 `3` 时命中 `c1`，`v1` 变 2。回扫得 `3` 出现 2 次，`2 // 3 = 0`，`2 > 0`，所以 `3` 入选；`2` 只出现 1 次也大于 0，同样入选——注意 `n=3` 时阈值是 0，任何出现过的元素都满足，这正是示例 3 里 `[1,2]` 全输出的原因。

```python
c1 = c2 = None
v1 = v2 = 0
for x in nums:
    if x == c1:
        v1 += 1
    elif x == c2:
        v2 += 1
    elif v1 == 0:
        c1, v1 = x, 1
    elif v2 == 0:
        c2, v2 = x, 1
    else:
        v1 -= 1
        v2 -= 1
n = len(nums)
return [c for c in (c1, c2) if c is not None and nums.count(c) > n // 3]
```

## 复杂度
时间 O(n)：投票一遍、验票一遍，`nums.count` 各扫一次，常数次线性。
空间 O(1)：只开了 `c1, c2, v1, v2` 四个变量，结果列表最多两个元素。

## 易错点
- `nums = [1,1,1,3,3,2,2,2]` 这类两强并存的输入 → 若只维护一个候选（普通摩尔投票）会漏掉一个 → 必须开 `c1, c2` 两组计数，且 `v1 == 0` 的判断要排在 `v2 == 0` 之前，保证填位顺序稳定。
- `nums = [1]` 或 `nums = [1,2]` → 若把阈值写成 `n / 3` 浮点或写成 `n // 3 + 1` 之外的变体 → 会漏判 → 严格用整数 `n // 3`，`n=1` 时阈值 0，`n=2` 时阈值 0，两个元素都要输出。
- 候选 `c1` 或 `c2` 可能是 `None`（数组只有一种元素时 `c2` 从未被赋值）→ 直接 `nums.count(None)` 得 0 不报错但语义混乱 → 用 `c is not None` 先过滤。

## 如果面试官追问
问：如果要求 O(1) 空间但元素出现次数阈值改成 ⌊n/k⌋ 怎么办？
答：候选扩到 k-1 组，投票阶段仍是 O(nk)，验票阶段 O(nk)，k 是常数时整体 O(n)。
