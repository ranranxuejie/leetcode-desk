## 一句话思路
先二分出峰顶，再在左升序段和右降序段各二分一次，取较小下标。

## 怎么做
1. 用 `get(mid) < get(mid+1)` 判断峰顶在右侧，二分出 `peak`。
2. 在 `[0, peak]` 升序段二分找 `target`，找到即返回（左段下标必更小）。
3. 左段没找到，再在 `[peak+1, n-1]` 降序段二分，注意比较方向反过来。

以 `[1,2,3,4,5,3,1]`、`target=3` 为例：峰顶二分时 `mid=3`，`get(3)=4 < get(4)=5`，`lo` 右移到 4，最终 `peak=4`。左段 `[0,4]` 二分命中下标 2，直接返回 2，右段根本不用查。

```python
lo, hi = 0, n - 1
while lo < hi:
    mid = (lo + hi) // 2
    if arr.get(mid) < arr.get(mid + 1):
        lo = mid + 1
    else:
        hi = mid
peak = lo
# 左段升序
lo, hi = 0, peak
while lo <= hi:
    mid = (lo + hi) // 2
    v = arr.get(mid)
    if v == target: return mid
    if v < target: lo = mid + 1
    else: hi = mid - 1
# 右段降序：v > target 才往右走
```

## 复杂度
时间 O(log n)：峰顶一次二分 + 两段各一次二分，共约 3·log₂(10⁴) ≈ 40 次 `get`，远低于 100。
空间 O(1)：只开了 `lo/hi/mid/peak` 几个整数。

## 易错点
- 峰顶二分写成 `lo <= hi` 且 `hi = mid - 1`：`[1,2,3,4,5,3,1]` 会漏掉 `peak=4` 或死循环。正确写法是 `while lo < hi` 配 `hi = mid`，收敛到单点即峰顶。
- 右段降序仍按 `v < target: lo = mid + 1` 走：在 `[5,3,1]` 找 1 时会往错误方向收缩，返回 -1。降序段必须反过来——`v > target` 才右移，`v < target` 则 `hi = mid - 1`。

## 如果面试官追问
问：如果数组不是严格山脉、有平台段怎么办？
答：`get(mid) < get(mid+1)` 的严格比较会把平台判到左侧，峰顶定位仍可用，但需在平台内线性或再二分找边界。
