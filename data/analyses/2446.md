## 一句话思路
把 `HH:MM` 转成分钟数，两个闭区间相交当且仅当 `max(start1,start2) <= min(end1,end2)`。

## 怎么做
1. 写一个 `to_min(t)`：`int(t[:2])*60 + int(t[3:])`，把 `"01:15"` 变成 75。
2. 对 `event1`、`event2` 各转一次，得到 `s1,e1,s2,e2` 四个整数。
3. 取 `lo = max(s1,s2)`、`hi = min(e1,e2)`，返回 `lo <= hi`。

拿示例 1 走一遍：`event1 = ["01:15","02:00"]` → `s1=75, e1=120`；`event2 = ["02:00","03:00"]` → `s2=120, e2=180`。于是 `lo = max(75,120) = 120`，`hi = min(120,180) = 120`，`120 <= 120` 成立，返回 `True`——这正是「两个事件在 2:00 出现交集」的那一分钟。

```python
def to_min(t):
    return int(t[:2]) * 60 + int(t[3:])

s1, e1 = to_min(event1[0]), to_min(event1[1])
s2, e2 = to_min(event2[0]), to_min(event2[1])
return max(s1, s2) <= min(e1, e2)
```

关键在 `<=` 而不是 `<`：区间是闭的，端点重合算冲突。示例 3 里 `s1=600,e1=660`、`s2=840,e2=900`，`lo=840 > hi=660`，返回 `False`。

## 复杂度
时间：O(1)，只解析 4 个长度固定为 5 的字符串，与输入规模无关。
空间：O(1)，只开了 `s1,e1,s2,e2,lo,hi` 几个整数。

## 易错点
- 用字符串直接比大小 → 对 `"01:15"` 和 `"1:15"` 这类长度不齐的写法会错，且 `"9:00" > "10:00"` 字典序为真。本题保证长度都是 5，但仍应统一转分钟再比，别依赖 `event1[0] < event2[1]` 这种字符串比较。
- 把相交判成 `<` 而非 `<=` → 示例 1 的 `["01:15","02:00"]` 与 `["02:00","03:00"]` 会返回 `False`，而正确答案是 `True`。闭区间端点相接就是非空交集（那一分钟），必须用 `max(s1,s2) <= min(e1,e2)`。

## 如果面试官追问
问：如果事件不是同一天、时间带日期怎么办？
答：把日期也折算进分钟（如 `天序号*1440 + 分钟`），判据 `max(s1,s2) <= min(e1,e2)` 一字不改。
