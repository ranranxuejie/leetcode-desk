## 一句话思路
从左往右扫，维护 `left_max` 和「右侧最小值后缀」，第一个满足 `left_max <= suffix_min[i+1]` 的切点就是答案。

## 怎么做
1. 先倒序预处理 `suffix_min[i] = min(nums[i:])`，这样任意切点右侧最小值 O(1) 可得。
2. 正序扫 `i`，同步更新 `left_max = max(left_max, nums[i])`。
3. 一旦 `left_max <= suffix_min[i+1]`，立即返回 `i+1`（left 长度），因为再往右扩只会让 left 更长。

以 `nums = [5,0,3,8,6]` 为例：`suffix_min = [0,0,3,6,6]`。扫到 `i=2` 时 `left_max = max(5,0,3) = 5`，而 `suffix_min[3] = 6`，`5 <= 6` 成立，返回 `3`。注意 `i=1` 时 `left_max=5` 但 `suffix_min[2]=3`，`5 <= 3` 不成立，所以不能提前切。

```python
n = len(nums)
suffix_min = [0] * n
suffix_min[-1] = nums[-1]
for i in range(n - 2, -1, -1):
    suffix_min[i] = min(nums[i], suffix_min[i + 1])

left_max = nums[0]
for i in range(n - 1):
    left_max = max(left_max, nums[i])
    if left_max <= suffix_min[i + 1]:
        return i + 1
```

关键点：`left_max` 是前缀最大值而非 `nums[i]`，切点判定必须用前缀整体最大值，因为 left 里任何一个元素都不能超过 right 的最小值。

## 复杂度
时间 O(n)：一次倒序建后缀、一次正序扫描，各 n。
空间 O(n)：额外开了长度 n 的 `suffix_min` 数组。

## 易错点
- 输入 `[1,1,1,0,6,12]` → 若用 `nums[i] <= nums[i+1]` 判断切点，会在 `i=2`（1<=1）就切，错成 3；正确做法是比 `left_max` 与右侧最小值，`i=3` 时 `left_max=1 <= suffix_min[4]=6` 才返回 4。
- 输入 `[5,0,3,8,6]` → 若只维护 `left_max` 而不看后缀，扫到 `i=1` 时 `left_max=5` 看似能切，但右侧含 3，`5 <= 3` 假；必须用 `suffix_min[i+1]` 而非 `nums[i+1]` 做比较。

## 如果面试官追问
要求输出 left 和 right 两个数组本身怎么办？
答：返回切点 `i+1` 后切片 `nums[:i+1]`、`nums[i+1:]` 即可，判定逻辑不变。
