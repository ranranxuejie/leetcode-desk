## 一句话思路
固定 j 向前看 i ≤ j - indexDifference，只需维护这段前缀里 nums 的最小值和最大值，就能 O(n) 判定。

## 怎么做
1. 令 j 从 indexDifference 遍历到 n-1，此时可用的 i 集合是 [0, j - indexDifference]。
2. 用一个变量在 j 递增时把 nums[j - indexDifference] 并入，维护前缀最小值的下标 minIdx 和最大值的下标 maxIdx。
3. 对每个 j，只需比较 nums[j] 与这两个极值：`nums[j] - nums[minIdx] >= valueDifference` 或 `nums[maxIdx] - nums[j] >= valueDifference`，命中即返回 `[minIdx, j]` 或 `[maxIdx, j]`。
4. 全部 j 走完没命中，返回 `[-1, -1]`。

以示例 1 `nums = [5,1,4,1], indexDifference = 2, valueDifference = 4` 为例：j=2 时前缀只有 i=0，minIdx=maxIdx=0，`nums[2]-nums[0] = 4-5 = -1`、`nums[0]-nums[2] = 1`，都不够 4；j=3 时把 nums[1]=1 并入，minIdx 变成 1（值 1），maxIdx 仍是 0（值 5），此时 `nums[maxIdx] - nums[3] = 5 - 1 = 4 >= 4`，返回 `[0, 3]`。

```python
min_idx = max_idx = 0
for j in range(indexDifference, n):
    k = j - indexDifference
    if nums[k] < nums[min_idx]:
        min_idx = k
    if nums[k] > nums[max_idx]:
        max_idx = k
    if nums[j] - nums[min_idx] >= valueDifference:
        return [min_idx, j]
    if nums[max_idx] - nums[j] >= valueDifference:
        return [max_idx, j]
return [-1, -1]
```

注意 min_idx / max_idx 的初值要指向第一个被并入的下标（即 0），因为 j 从 indexDifference 起跳时 k 恰好是 0。

## 复杂度
时间 O(n)：j 单趟扫描，每个下标只并入一次。
空间 O(1)：只开了 min_idx、max_idx 两个下标变量。

## 易错点
- `indexDifference = 0` 且 `valueDifference = 0`（示例 2）→ 若把循环写成从 `indexDifference + 1` 起跳或要求 i < j，会漏掉 `[0,0]` 直接返回 `[-1,-1]` → 循环起点必须是 `indexDifference`，允许 i == j。
- 只维护最小值不维护最大值 → 输入 `nums = [1,100,2], indexDifference = 1, valueDifference = 50`，j=2 时若只看 minIdx=0（值 1），`2-1=1` 不够，会误判无解，实际 `nums[1]-nums[2] = 98 >= 50` → 必须同时维护 maxIdx，两个方向都判。

## 如果面试官追问
问：如果要求返回差值最大的那一对怎么办？
答：仍用前缀极值，但每个 j 都算一次 `max(nums[j]-nums[minIdx], nums[maxIdx]-nums[j])` 并记录全局最优，不提前返回。
