## 一句话思路
逐列自上而下贪心：若 `grid[i][j] <= grid[i-1][j]`，就把它抬到 `grid[i-1][j]+1`，抬升量累加；因为只增不减，抬到刚好大于上一行是最省的。

## 怎么做
1. 外层枚举列 `j`，内层从 `i = 1` 到 `m-1` 自上而下扫。
2. 维护 `prev = grid[i-1][j]`（已修正后的值），若 `grid[i][j] <= prev`，则 `need = prev + 1 - grid[i][j]`，累加进 `ans`，并把 `grid[i][j]` 改成 `prev + 1`。
3. 用示例 1 第 0 列 `[3,1,3,0]` 走一遍：`i=1` 时 `1 <= 3`，抬到 4，`ans += 3`；`i=2` 时 `3 <= 4`，抬到 5，`ans += 2`；`i=3` 时 `0 <= 5`，抬到 6，`ans += 6`。该列共 11，第 1 列 `[2,3,4,1]` 只在 `i=3` 抬到 5，`ans += 4`，合计 15。
4. 关键点：抬升后的值必须写回 `grid[i][j]`，否则下一行比较的是原始值，会少算。

```python
ans = 0
m, n = len(grid), len(grid[0])
for j in range(n):
    for i in range(1, m):
        if grid[i][j] <= grid[i - 1][j]:
            need = grid[i - 1][j] + 1 - grid[i][j]
            ans += need
            grid[i][j] = grid[i - 1][j] + 1
return ans
```

## 复杂度
时间：O(m·n)，每个格子访问一次，m 行 n 列各贡献一重循环。
空间：O(1) 额外空间，只用了 `ans`、`need` 和循环变量（原地改 `grid`）。

## 易错点
- 输入 `[[3,2],[1,3],[3,4],[0,1]]` 第 0 列：若只比较原始 `grid[i][j]` 与 `grid[i-1][j]` 而不写回，`i=2` 时 `3 > 1` 就跳过，漏掉 `i=1` 抬到 4 后 `3 <= 4` 的 2 次操作，答案会算成 13 而非 15。正确做法是每步把 `grid[i][j]` 更新为 `grid[i-1][j]+1`。
- 输入 `[[1],[1],[1]]`：若用 `grid[i][j] < grid[i-1][j]` 判断（漏等号），三行相等时一次都不抬，返回 0；但严格递增要求 1,2,3，正确是 `ans = 0+1+2 = 3`。等号必须算进需要抬升的情况。

## 如果面试官追问
问：若允许对元素做加减两种操作，最少操作数怎么变？
答：每列变成「使序列严格递增的最小 L1 调整」，需先减去下标转成非降，再用中位数/保序回归，贪心不再成立。
