## 一句话思路
用窗口函数 `LAG` 按用户取上一门课，拼成课程对后 `GROUP BY` 计数，再排序。

## 怎么做
1. 先筛顶尖学生：按 `user_id` 分组，`HAVING COUNT(*) >= 5 AND AVG(course_rating) >= 4`，得到合格用户集合。
2. 只保留合格用户的行，按 `user_id, completion_date` 排序，用 `LAG(course_name) OVER (PARTITION BY user_id ORDER BY completion_date)` 取前一门课。
3. 丢掉 `prev_course IS NULL` 的行（每个用户第一门课没有前驱），剩下的 `(prev_course, course_name)` 就是连续课程对。
4. 按课程对 `GROUP BY` 计数，`ORDER BY transition_count DESC, first_course ASC, second_course ASC`。

以示例用户 1 为例：排序后 `LAG` 依次产出 `None, Python Basics, SQL Fundamentals, JavaScript, React Basics, Node.js`，丢弃首行后得到 5 个课程对，其中 `Node.js → Docker` 和 `React Basics → Node.js` 各被用户 1、2 贡献一次，计数为 2。

```python
# 假设已用 pandas 读入 df
top = df.groupby('user_id').filter(
    lambda g: len(g) >= 5 and g['course_rating'].mean() >= 4)
top = top.sort_values(['user_id', 'completion_date'])
top['prev'] = top.groupby('user_id')['course_name'].shift(1)
pairs = top.dropna(subset=['prev'])
res = (pairs.groupby(['prev', 'course_name']).size()
       .reset_index(name='transition_count')
       .rename(columns={'prev': 'first_course', 'course_name': 'second_course'})
       .sort_values(['transition_count', 'first_course', 'second_course'],
                    ascending=[False, True, True]))
```

SQL 版把第 2 步换成 `LAG(course_name) OVER (PARTITION BY user_id ORDER BY completion_date) AS prev_course`，第 3 步用 `WHERE prev_course IS NOT NULL`，其余聚合排序一致。

## 复杂度
时间 O(n log n)：n 为表行数，排序与窗口分区各贡献一次排序。
空间 O(n)：窗口函数物化每个用户的上一门课，结果集最多 n 个课程对。

## 易错点
- 用 `AVG(course_rating) >= 4` 时若先 `WHERE` 过滤掉低分课再算平均，用户 3 的 2.8 会被算成 3.0 仍不达标，但用户 1 的 4.5 会变成 4.5 不变——真正翻车的是「先过滤再计数」，用户 4 的 3 门课被过滤后连 5 门都凑不齐，正确做法是先按全量行算 `COUNT` 和 `AVG` 再筛人。
- 同一用户同一天完成两门课时 `ORDER BY completion_date` 不唯一，`LAG` 结果不稳定，课程对可能颠倒；需补 `course_id` 作第二排序键。

## 如果面试官追问
问：若要求输出每个用户各自的路径而非全局频率？答：去掉 `GROUP BY` 课程对，直接保留 `user_id, prev, course_name` 三列按用户输出即可。
