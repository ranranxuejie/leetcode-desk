## 一句话思路
按难度分组计数，每组数量 c 必须 ≥2；c 用尽量多的 3 来凑，轮数为 `c//3` 向上取整，即 `(c+2)//3`。

## 怎么做
1. 用 `Counter(tasks)` 得到每个难度级别的任务数 `c`。
2. 若某个 `c == 1`，直接返回 `-1`（1 个任务凑不出 2 或 3）。
3. 对每个 `c` 累加 `(c + 2) // 3`。
4. 返回累加和。

以示例 1 的 `tasks = [2,2,3,3,2,4,4,4,4,4]` 为例，计数得到 `{2:3, 3:2, 4:5}`。三组分别贡献 `(3+2)//3=1`、`(2+2)//3=1`、`(5+2)//3=2`，合计 `1+1+2=4`。其中 `c=5` 拆成 `3+2` 两轮，不能拆成 `2+2+1`（剩 1 个无法成轮）。

```python
from collections import Counter

cnt = Counter(tasks)
ans = 0
for c in cnt.values():
    if c == 1:
        return -1
    ans += (c + 2) // 3
return ans
```

关键点：`(c+2)//3` 对 `c=2` 得 1、`c=3` 得 1、`c=4` 得 2（拆 2+2）、`c=5` 得 2（拆 3+2）、`c=6` 得 2（拆 3+3）。除 `c=1` 外所有 `c≥2` 都能被 2 和 3 组合表示，所以只需拦 `c==1`。

## 复杂度
时间：O(n)，`Counter` 遍历一次 `tasks`，n 为 `tasks.length`。
空间：O(k)，k 为不同难度级别数，最坏 O(n)。

## 易错点
- 输入 `tasks = [2,3,3]` → 若只判 `c==1` 之外不处理，会漏掉难度 2 的 `c=1` 返回 0 或 1；正确做法是遍历所有 `cnt.values()`，任一为 1 立即返回 `-1`。
- 输入 `tasks = [2,2,2,2]`（`c=4`）→ 若用 `c//3 + (c%3>0)` 会得 `1+1=2` 看似对，但 `c=2` 时 `2//3=0` 加 1 得 1 也对；真正翻车在 `c=1` 时该式给 1 而非 -1，必须前置拦截 `c==1`，不能靠公式兜底。

## 如果面试官追问
问：若每轮可完成 2、3 或 5 个，怎么改？
答：`c==1` 仍返回 -1，其余用贪心优先减 5，但需对 `c=2,3,4` 特判，不能直接套 `(c+4)//5`。
