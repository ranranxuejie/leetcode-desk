## 一句话思路
用布尔数组 `seen` 记录谁接过球，从 1 号出发按 `i*k` 累加取模推进，直到踩到已标记的人。

## 怎么做
1. 开 `seen = [False]*(n+1)`，下标 1..n 对应朋友编号，`seen[1] = True`，`cur = 1`，`step = 1`。
2. 循环：`cur = (cur + step*k - 1) % n + 1`，然后 `step += 1`。
3. 若 `seen[cur]` 已为 `True`，说明第 2 次接到球，立即 `break`（不能先标记再判断，否则永远不结束）。
4. 收集所有 `seen[i] == False` 的 `i`，天然升序。

以 `n=5, k=2` 为例：`cur=1` 出发，`step=1` 时 `cur=(1+2-1)%5+1=3`；`step=2` 时 `cur=(3+4-1)%5+1=2`；`step=3` 时 `cur=(2+6-1)%5+1=3`，此时 `seen[3]` 已为 `True`，结束。剩下 `4,5` 未标记。

```python
seen = [False] * (n + 1)
seen[1] = True
cur, step = 1, 1
while True:
    cur = (cur + step * k - 1) % n + 1
    if seen[cur]:
        break
    seen[cur] = True
    step += 1
return [i for i in range(1, n + 1) if not seen[i]]
```

关键点：`(cur + step*k - 1) % n + 1` 这个写法把 1-based 编号映射到 0-based 再映射回来，避免 `cur + step*k` 恰好等于 `n` 时取模得 0 的错误。

## 复杂度
时间：O(n)，最多 n 个不同朋友被标记，循环次数不超过 n+1。
空间：O(n)，`seen` 数组长度 n+1。

## 易错点
- `n=4, k=4`：若先标记再判断，`cur` 第一次算出 `(1+4-1)%4+1=1`，会立刻把 1 号标记两次而漏判结束条件，导致死循环。正确做法是先判断 `seen[cur]` 再标记。
- `k=n` 时 `step*k` 对 n 取模恒为 0，球永远停在 1 号，第二轮就结束。若用 `cur = (cur + step*k) % n`（不加 `-1/+1` 偏移），`n=4` 时算出 `cur=0`，越界访问 `seen[0]` 且漏掉 1 号。必须用 1-based 取模公式。

## 如果面试官追问
问：若 n 放大到 10^9 但 k 很小，怎么优化？
答：`seen` 换成哈希集合只存实际接到球的人，循环次数仍是 O(接到球的人数)，空间从 O(n) 降到 O(人数)。
