## 一句话思路
用 `taskId -> (userId, priority)` 哈希表存权威状态，再用大顶堆按 `(priority, taskId)` 惰性删除，堆顶即答案。

## 怎么做
1. 哈希表 `info` 存 `taskId -> (userId, priority)`，堆 `heap` 存 `(-priority, -taskId, userId)`，初始化时逐个 `add`。
2. `add` 直接写 `info` 并 push 堆；`edit` 只改 `info[taskId]` 的 priority，不删旧堆项。
3. `rmv` 从 `info` 里 `pop` 掉 taskId，堆里旧项留着。
4. `execTop` 循环弹堆顶，若 `info` 中该 taskId 不存在或 priority 对不上就丢弃，否则从 `info` 删除并返回 userId。

以官方示例为例：`edit(102, 8)` 后 `info[102] = (2, 8)`，堆里仍留着 `(-20, -102, 2)`。`execTop` 弹出它时发现 `info[102]` 的 priority 是 8 而非 20，判定为过期项丢弃；继续弹出 `(-15, -103, 3)`，与 `info[103] = (3, 15)` 一致，返回 3。

```python
import heapq

def add(self, userId, taskId, priority):
    self.info[taskId] = (userId, priority)
    heapq.heappush(self.heap, (-priority, -taskId, userId))

def execTop(self):
    while self.heap:
        neg_p, neg_t, uid = heapq.heappop(self.heap)
        taskId = -neg_t
        if self.info.get(taskId) == (uid, -neg_p):
            del self.info[taskId]
            return uid
    return -1
```

`edit` 只需 `uid, _ = self.info[taskId]; self.info[taskId] = (uid, newPriority)`，不用碰堆。

## 复杂度
时间：每次操作 O(log n)，n 为堆中元素总数（含过期项，最多 初始化 + add + edit 次）。
空间：`info` 存活跃任务 O(m)，堆含过期项 O(n)，n 可达 3×10^5 量级。

## 易错点
- `edit` 后堆里同时存在同一 taskId 的新旧两项 → 若只判 `taskId in info` 就返回，会把旧 priority 的任务当成最高优先级执行 → 必须比对 `info[taskId]` 的 `(userId, priority)` 与堆项完全一致。
- 优先级相同要比 taskId 最大 → 若堆只存 `(-priority, userId)` 或忘了把 taskId 取负，同优先级时会弹出 taskId 最小的 → 堆元组必须是 `(-priority, -taskId, userId)`，让 taskId 大的排前面。

## 如果面试官追问
若要求 `execTop` 严格 O(log n) 最坏而非摊还，怎么办？
答：改用有序集合（如按 `(priority, taskId)` 排序的平衡树）配合 `taskId -> 节点` 映射，`edit`/`rmv` 直接定位删除，无需惰性清理。
