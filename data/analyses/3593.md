## 一句话思路
自底向上 DFS，每个节点把各子树路径补齐到最大子树高度，补的子树个数就是该节点要加成本的次数。

## 怎么做
1. 把 edges 建成邻接表，从 0 出发 DFS，跳过父节点。
2. 叶子返回 `cost[u]`；内部节点收集所有子节点返回的路径和。
3. 取 `mx = max(子路径和)`，对每个 `s < mx` 的子树，在子节点上补 `mx - s`，答案加 1。
4. 返回 `cost[u] + mx` 给父节点。

以示例 3 为例：节点 2、3 是叶子，各返回 `cost=1`；节点 1 收到 `[1, 1]`，`mx=1`，无缺口，返回 `4+1=5`。节点 4 返回 `7`。根 0 收到 `[5, 7]`，`mx=7`，`5<7` 补一次，答案 `1`，返回 `3+7=10`。

```python
def dfs(u, p):
    child = [dfs(v, u) for v, _ in adj[u] if v != p]
    if not child:
        return cost[u]
    mx = max(child)
    nonlocal ans
    ans += sum(1 for s in child if s < mx)
    return cost[u] + mx
```

关键点：补的是**子节点**的成本，不是当前节点——补当前节点会同时抬高所有子树，无法只补短的那条。

## 复杂度
时间 O(n)：每条边在 DFS 中访问两次，每个子路径和只被比较一次。
空间 O(n)：邻接表 2(n-1) 条记录，递归栈最坏 n 层（链状树）。

## 易错点
- 链状树如示例 2（`0-1-2`）：若把「只有一个子节点」也当成需要补齐的分支，会在节点 1 处误加 1；正确做法是 `len(child) == 1` 时缺口恒为 0，`sum(1 for s in child if s < mx)` 自然得 0，不要额外特判。
- 星形树 `edges=[[0,1],[0,2],...]` 且 `cost[0]` 很大：若把增量加在根 0 上，所有路径同时变长，永远补不齐；必须加在返回较小值的那个子节点上，答案按「有几个子路径小于 mx」计数，而不是按差值大小计数。

## 如果面试官追问
要求输出具体在哪些节点加多少？答：DFS 时把 `(子节点, mx - s)` 记进列表，回溯结束统一输出，计数逻辑不变。
