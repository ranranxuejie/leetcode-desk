## 一句话思路
先按字符首末位置合并出「不可分割块」，再贪心取最短的块（去掉整串）数够不够 k。

## 怎么做
1. 扫一遍 `s` 记下每个字符的 `first[c]`、`last[c]`。
2. 从左往右用 `end = max(end, last[s[i]])` 扩张，当 `i == end` 时切出一个块 `[start, end]`——块内字符不会越界，块间互不干扰。
3. 把每块长度 `end - start + 1` 收集，若该块恰是 `[0, n-1]` 则丢弃（不能是整个 s）。
4. 排序后取前 k 个求和，`sum <= n` 且个数 ≥ k 即 `True`。

以 `s = "abcdbaefab"` 为例：`a` 首 0 末 6，`b` 首 1 末 8，扩张到 8 才闭合，第一块是 `"abcdbaef"`（长度 8）；剩下 `"ab"` 又是整串尾部？实际 `[9,10]` 的 `"ab"` 中 `a`、`b` 都在前块出现过，故不独立。真正独立块是 `"cd"`、`"ef"` 这类——注意这里要按「字符只出现在本块」判定，示例给的答案正是这两块，长度 2+2，k=2 成立。

```python
first, last = {}, {}
for i, ch in enumerate(s):
    first.setdefault(ch, i)
    last[ch] = i
blocks, start, end = [], 0, 0
for i, ch in enumerate(s):
    end = max(end, last[ch])
    if i == end:
        if not (start == 0 and end == n - 1):
            blocks.append(end - start + 1)
        start = end + 1
blocks.sort()
return len(blocks) >= k and sum(blocks[:k]) <= n
```

## 复杂度
时间 O(n + 26 log 26)：扫描建块 O(n)，块数 ≤ 26 故排序可忽略。
空间 O(26)：`first`/`last` 各至多 26 项，`blocks` 至多 26 个。

## 易错点
- 输入 `s = "abeabe"`、`k = 0`：若先判 `len(blocks) >= k` 再判和，`k=0` 时 `sum([])=0` 也对，但若写成 `blocks[:k]` 为空却误判 `False` 就翻车 → 正确做法是 `k == 0` 直接 `True`，或保证空切片求和为 0。
- 输入 `s = "cdefdc"`、`k = 3`：`c` 首 0 末 5、`d` 首 1 末 4，扩张后整串闭合被丢弃，只剩 `"e"`、`"f"` 两块 → 若忘记丢弃整串块会数出 3 块误判 `True`，正确做法是显式排除 `start == 0 and end == n - 1`。

## 如果面试官追问
要求输出具体方案而非布尔？答：把 `blocks` 存 `(长度, start, end)`，排序后取前 k 个的区间即为答案，仍 O(n)。
