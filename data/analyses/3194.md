## 一句话思路
排序后首尾配对求和，取所有配对和的最小值再除以 2，因为排序后第 i 小必与第 i 大配对。

## 怎么做
1. 对 `nums` 排序，得到 `[1,3,4,4,7,8,13,15]`（示例 1）。
2. 用双指针 `i=0`、`j=n-1` 向中间夹，每轮取 `nums[i] + nums[j]`。
3. 维护 `best` 为这些和的最小值，最后返回 `best / 2`。

关键中间值：示例 1 排序后配对为 `1+15=16`、`3+13=16`、`4+8=12`、`4+7=11`，`best` 收敛到 11，返回 `11/2 = 5.5`。注意比较的是**和**而不是平均值，避免浮点比较。

```python
nums.sort()
i, j = 0, len(nums) - 1
best = float('inf')
while i < j:
    best = min(best, nums[i] + nums[j])
    i += 1
    j -= 1
return best / 2
```

为什么排序后首尾配对就是最优：若存在更优的配对方式，交换论证可证最小的元素必须与最大的元素配对，否则两者各自与别的元素配对会产生更大的和。

## 复杂度
时间：排序 `O(n log n)` 主导，双指针扫描 `O(n)`。
空间：排序额外 `O(log n)` 栈空间（Python Timsort），无其他数组。

## 易错点
- 输入 `[1,2,3,7,8,9]` → 若误以为要返回所有平均值里的最小值但用浮点累加比较，可能因精度把 `5.0` 判成 `4.999...`；正确做法是全程用整数比较 `nums[i] + nums[j]`，只在最后除 2。
- 输入 `[1,9,8,3,10,5]` → 若用 `best = 0` 初始化，`min` 永远得 0，返回 `0.0`；正确做法是初始化为 `float('inf')` 或第一个配对和。

## 如果面试官追问
问：若 n 可达 10^5 且要求输出所有平均值中的最小值对应的配对方案？
答：排序后仍首尾配对，记录使 `nums[i]+nums[j]` 最小的 `(i, j)` 下标即可，时间不变。
