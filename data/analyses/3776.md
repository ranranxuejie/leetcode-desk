## 一句话思路
负余额只有一个，把它左右两侧的正余额按「到它的环上距离」排序，从近到远搬，每单位代价就是距离。

## 怎么做
1. 先判 `sum(balance) < 0` 直接返回 -1，因为总量不够填坑。
2. 找到唯一负值下标 `k`（若没有负值返回 0），缺口 `need = -balance[k]`。
3. 把除 `k` 外每个正余额 `balance[i]` 折算成环上到 `k` 的距离 `d = min(|i-k|, n-|i-k|)`，按 `d` 升序排。
4. 贪心从最近的正余额取，每取 `x` 单位累加 `x * d`，直到凑满 `need`。

以 `balance = [5,1,-4]` 为例：`k = 2`，`need = 4`。`i=1` 距离 1、余额 1；`i=0` 距离 1（环上 `min(2,1)=1`）、余额 5。排序后先取 1 单位付 1，再取 3 单位付 3，合计 4。

```python
n = len(balance)
if sum(balance) < 0:
    return -1
if all(b >= 0 for b in balance):
    return 0
k = next(i for i, b in enumerate(balance) if b < 0)
need = -balance[k]
items = []
for i, b in enumerate(balance):
    if i != k and b > 0:
        d = min(abs(i - k), n - abs(i - k))
        items.append((d, b))
items.sort()
ans = 0
for d, b in items:
    take = min(b, need)
    ans += take * d
    need -= take
    if need == 0:
        break
return ans
```

## 复杂度
时间：排序 O(n log n)，扫描 O(n)，n 为数组长度。
空间：`items` 最多 n 项，O(n)。

## 易错点
- 用线性距离 `abs(i-k)` 而非环距离：`[5,1,-4]` 中 `i=0` 会算成 2，答案变 5；必须用 `min(abs(i-k), n-abs(i-k))`。
- 忘记先判 `sum < 0`：`[-3,2]` 会进入贪心，`need=3` 但只有 2 单位可取，`need` 停在 1 却返回 2；正确做法是开头就返回 -1。

## 如果面试官追问
问：若允许多个负余额呢？
答：贪心失效，需转成环上最小费用流或前缀和 + 中位数模型，复杂度升到 O(n log n) 以上。
