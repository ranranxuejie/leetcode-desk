## 一句话思路
用 `id - row_number()` 把连续 id 压成同一组号，再按组计数筛出 ≥3 的组。

## 怎么做
1. 先过滤 `people >= 100`，只留下候选行。
2. 对候选行按 `id` 排序后取 `row_number()`，用 `id - rn` 作分组键：连续 id 的差值恒定。
3. 按分组键 `count(*)`，保留计数 ≥3 的组，回连原表取全部列。
4. 按 `visit_date` 升序输出。

以官方示例为例，过滤后剩 id = 2,3,5,6,7,8。排序取行号后：

| id | rn | id - rn |
|----|----|---------|
| 2  | 1  | 1       |
| 3  | 2  | 1       |
| 5  | 3  | 2       |
| 6  | 4  | 2       |
| 7  | 5  | 2       |
| 8  | 6  | 2       |

组 1 计数 2 被丢弃，组 2 计数 4 保留，正好输出 5,6,7,8。注意 id=4（people=99）被过滤掉后，5 和 3 的 id 差是 2，但行号差也是 2，差值仍相等——所以「先过滤再编号」是正确顺序，反过来会断组。

```python
cand = df[df["people"] >= 100].sort_values("id").copy()
cand["rn"] = range(1, len(cand) + 1)
cand["grp"] = cand["id"] - cand["rn"]
cnt = cand.groupby("grp")["id"].transform("size")
res = cand[cnt >= 3][["id", "visit_date", "people"]]
res = res.sort_values("visit_date")
```

关键就三行：`rn`、`grp`、`transform("size")`。用 `transform` 而不是 `agg`，是为了把组大小广播回每一行，避免再 merge 一次。

## 复杂度
时间 O(n log n)：n 为 Stadium 行数，排序贡献 log n。
空间 O(n)：cand 副本加 rn/grp 两列。

## 易错点
- 先编号后过滤：id=4（people=99）会留在序列里，把 5,6,7,8 拆成 5 单独一组、6,7,8 一组，输出漏掉 id=5。正确做法是先 `people >= 100` 再 `row_number()`。
- 用 `visit_date` 判断连续：示例里 id=7 是 01-07、id=8 是 01-09，日期差 2 天但 id 连续，按日期分组会把 8 踢出去。题目只认 id 连续，日期只用于最终排序。

## 如果面试官追问
问：如果要求输出「最长的那一段」而不是所有 ≥3 的段？
答：在 `grp` 上取 `size().idxmax()`，只保留该组，再按 visit_date 排序即可。
