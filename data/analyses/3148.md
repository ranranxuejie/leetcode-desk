## 一句话思路
把「多步得分」拆成相邻两格之差的和，路径上中间格全部抵消，所以只需在每格维护「左上方最小起点值」，用 `grid[i][j] - min_val` 更新答案。

## 怎么做
1. 关键观察：从 `(r1,c1)` 走到 `(rk,ck)` 的总得分等于 `grid[rk][ck] - grid[r1][c1]`，中间格的值全部抵消，所以只需关心起点值。
2. 按行优先遍历，维护 `min_val` = 当前格左上方（含同行左侧、同列上方）所有格中的最小值。
3. 每格先算 `ans = max(ans, grid[i][j] - min_val)`，再把 `grid[i][j]` 并入 `min_val`（顺序不能反，否则自己减自己得 0）。
4. 用官方示例验证：走到 `(2,2)=14` 时，`min_val` 已含 `(0,1)=5`，得 `14-5=9`；走到 `(0,1)=5` 时 `min_val=9`，得 `-4`，`ans` 保持 9。

```python
ans = -10**18
min_val = 10**18
for i in range(m):
    for j in range(n):
        if min_val < 10**18:
            ans = max(ans, grid[i][j] - min_val)
        min_val = min(min_val, grid[i][j])
```

上面是单行扫描的骨架；实际要保证 `min_val` 只含「左上方」的格，所以按行遍历时，每行开始前 `min_val` 应重置为 `10**18`，行内从左到右累积，同时把上一行同列的值提前并入。更稳的写法是维护 `best[i][j]` = 左上区域最小值，递推 `best[i][j] = min(grid[i][j], best[i-1][j], best[i][j-1])`，答案取 `grid[i][j] - min(best[i-1][j], best[i][j-1])`。

## 复杂度
时间：O(m·n)，每个格常数次比较，m、n 来自矩阵维度。
空间：O(n) 滚动数组存上一行/当前行的左上最小值，不额外开 m×n。

## 易错点
- 全负增长矩阵如 `[[4,3,2],[3,2,1]]`：若把 `ans` 初始化为 0，会错成 0；正确做法是初始化为 `-10**18`，因为必须至少移动一次，答案可以是 `-1`。
- 更新顺序反了：先 `min_val = min(min_val, grid[i][j])` 再算差值，当前格自己减自己得 0，会把 `[[4,3,2],[3,2,1]]` 错算成 0；正确做法是先算 `grid[i][j] - min_val` 再并入 `min_val`。

## 如果面试官追问
问：要求输出具体路径怎么办？答：额外存每个格的最优前驱坐标，从取到 `ans` 的终点沿前驱回溯到起点，再反转即可。
