## 一句话思路
枚举分割点 j，用「左端 i 的计数数组」和「右端 k 的计数数组」按不同字符数配对求和，靠前缀/后缀增量维护做到 O(26n)。

## 怎么做
1. 固定 j，把 s1=s[i..j] 的 i 从 j 往左扫，记录每个不同字符数 d 对应的 i 的个数 `L[d]`；同理 k 从 j+1 往右扫得 `R[d]`。
2. 答案贡献是 `sum_d L[d]*R[d]`，但每个 j 都重扫是 O(n²)，要利用 j→j+1 时 L、R 的增量。
3. 关键观察：i 往左扩时不同字符数只增不减，且最多 26 种；用 `last[c]` 记录字符 c 在 j 左侧最近出现位置，就能 O(26) 算出 L 的分布。
4. 对每个 j，L 的分布由「j 左侧各字符最近位置排序后的区间长度」决定，R 对称。用双指针/差分把每个 j 的配对和 O(26) 累加。

以 s="aba" 为例，j=0：L={1:1}（i=0），R 从 k=1 扫：k=1 得 "b" d=1，k=2 得 "ba" d=2，故 R={1:1,2:1}，贡献 L[1]*R[1]=1。j=1：L 中 i=1 得 "b" d=1、i=0 得 "ab" d=2；R 中 k=2 得 "a" d=1，贡献 1*1=1。合计 2。

```python
# 对固定 j，L[d] 由左侧字符最近位置分段得到
# pos[c] = 字符 c 在 [0..j] 中最后出现的位置
# 按 pos 降序排，第 t 个不同字符数对应区间长度
order = sorted(range(26), key=lambda c: -pos[c])
L = {}
prev = j + 1
d = 0
for c in order:
    if pos[c] < 0: break
    d += 1
    L[d] = L.get(d, 0) + (prev - pos[c])
    prev = pos[c]
# R 对称：用 nxt[c] 从右往左同理
```

## 复杂度
时间 O(26n)：每个 j 排序 26 个字符、累加 26 项。
空间 O(26)：pos/nxt 两个长度 26 的数组加常数级字典。

## 易错点
- 输入 s="kkk"：若把「不同字符数」当成子串长度，会算出 0 个而非 4 个；正确做法是对每个 j 只统计 `len(set(s[i..j]))`，全 k 时恒为 1，故 L[1]、R[1] 都非空。
- 输入 s="aba" 的 j=1：若忘记 i 可以等于 j（s1 非空），会漏掉 (1,1,2) 这一组；正确做法是 i 从 j 开始往左扫，包含 i=j 的单字符情况。

## 如果面试官追问
若 n 扩大到 10^6 且字符集仍是 26，怎么做？答：仍是 O(26n)，把排序换成对 26 个位置做计数排序即可，常数更小。
