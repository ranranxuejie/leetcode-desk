## 一句话思路
按 `timer == 0`、`timer == 30`、`30 < timer <= 90` 的顺序做三次判断，命中即返回，全不命中返回 `"Invalid"`。

## 怎么做
1. 先判 `timer == 0`，返回 `"Green"`。
2. 再判 `timer == 30`，返回 `"Orange"`。
3. 再判 `30 < timer <= 90`，返回 `"Red"`。
4. 以上都不成立，返回 `"Invalid"`。

以官方示例 `timer = 60` 为例：第 1 步 `60 == 0` 为 `False`，第 2 步 `60 == 30` 为 `False`，第 3 步 `30 < 60 <= 90` 为 `True`，直接返回 `"Red"`，不再往下走。再看 `timer = 5`：三步依次为 `False`、`False`、`30 < 5` 为 `False`，落到第 4 步返回 `"Invalid"`。

```python
if timer == 0:
    return "Green"
if timer == 30:
    return "Orange"
if 30 < timer <= 90:
    return "Red"
return "Invalid"
```

顺序不能换：`30` 同时满足 `30 < timer <= 90` 吗？不满足（左端是严格小于），所以 `30` 和 `Red` 区间其实不冲突；但 `0` 与任何区间都不冲突。真正要注意的是别把 `30 < timer <= 90` 写成 `30 <= timer <= 90`，那样 `timer = 30` 会先被第 2 步截住，逻辑上仍对，但一旦你调换判断顺序就会把 `30` 判成 `"Red"`。所以稳妥做法是保持「等值判断在前、区间判断在后」。

## 复杂度
时间：O(1)，最多三次整数比较，与 `timer` 大小无关。
空间：O(1)，只用了几个字符串字面量，没有额外容器。

## 易错点
- 输入 `timer = 30` → 若把区间写成 `30 <= timer <= 90` 且把区间判断放在等值判断之前，会错成 `"Red"` → 正确做法是 `timer == 30` 先判，或区间左端保持严格 `30 < timer`。
- 输入 `timer = 91` 或 `timer = 1000` → 若把上界写成 `timer < 90` 或漏掉上界，会错成 `"Red"` → 正确做法是右端用 `<= 90`，且 `91`、`1000` 必须落到 `"Invalid"`。

## 如果面试官追问
问：若 timer 是浮点秒数，规则怎么改？
答：把等值判断改成容差比较（如 `abs(timer - 30) < 1e-9`），区间判断不变。
