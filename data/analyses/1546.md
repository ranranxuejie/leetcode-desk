## 一句话思路
从左往右贪心：一旦凑出和为 target 的区间就立刻切下并清空前缀和表，这样给后面留的余量最大。

## 怎么做
1. 维护 `prefix`（当前段内前缀和）和集合 `seen`（本段出现过的前缀和），初始 `seen = {0}`。
2. 遍历 `x in nums`，`prefix += x`；若 `prefix - target in seen`，说明本段内存在和为 target 的后缀，答案 +1，并把 `prefix` 归零、`seen` 重置为 `{0}`。
3. 否则把 `prefix` 加入 `seen` 继续。
4. 用示例 2 走一遍：`nums = [-1,3,5,1,4,2,-9], target = 6`。到 `5` 时 `prefix = 7`，`7-6 = 1` 在 `seen` 里（`-1+3 = 2`？不，`seen` 是 `{0,-1,2}`，`1` 不在），继续；到 `1` 时 `prefix = 8`，`8-6 = 2` 在 `seen` 中，切出 `[5,1]`，计数 1，重置。之后 `4,2` 得 `prefix = 6`，`6-6 = 0` 在 `seen` 中，切出 `[4,2]`，计数 2。最后 `-9` 单独无法成段，返回 2。

```python
seen = {0}
prefix = count = 0
for x in nums:
    prefix += x
    if prefix - target in seen:
        count += 1
        prefix = 0
        seen = {0}
    else:
        seen.add(prefix)
return count
```

关键点：命中后必须把 `seen` 清成 `{0}` 而不是只清 `prefix`，否则跨段的旧前缀和会让下一段误判。

## 复杂度
时间：O(n)，每个元素最多进 `seen` 一次，哈希查询均摊 O(1)。
空间：O(n)，最坏情况 `seen` 存下整段所有前缀和。

## 易错点
- 输入 `nums = [0,0,0], target = 0` → 若命中后只把 `prefix` 归零却保留旧 `seen`，第二、三个 0 会因 `0-0 = 0` 反复命中同一逻辑段，或反之漏计 → 正确做法是每次命中后 `seen = {0}`，这样三个 0 各自独立成段，返回 3。
- 输入含负数如示例 2 → 若用双指针滑动窗口（依赖前缀和单调）会漏掉 `[5,1]` 之后 `[4,2]` 这种跨负数的段 → 必须用哈希表存前缀和，不能假设窗口右移时和单调增。

## 如果面试官追问
问：要求输出具体是哪些子数组怎么办？
答：命中时记录当前下标 `i` 和段起点，段为 `[start, i]`，重置时把 `start = i + 1`。
