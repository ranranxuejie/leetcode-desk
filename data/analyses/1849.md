## 一句话思路
枚举第一段的长度和值，之后每段只能取 `prev-1` 的十进制串，逐段贪心匹配即可。

## 怎么做
1. 第一段 `s[:i]` 决定起点，`i` 从 1 到 `len(s)-1`（至少留一段），值 `prev = int(s[:i])`。
2. 之后每段的目标值固定为 `prev-1`，把它转成字符串 `t = str(prev-1)`，在 `s` 的当前位置做前缀匹配。
3. 匹配成功就前移指针、`prev -= 1`；匹配失败立即换下一个 `i`。
4. 指针走到末尾且段数 ≥2 时返回 `True`。

以 `s = "050043"` 为例：`i=2` 时 `prev = int("05") = 5`，目标 `4` 的串是 `"4"`，但 `s[2:]` 以 `"0043"` 开头，`"4"` 不匹配——注意这里必须用 `str(4)` 而不是 `"04"`，前导零只在原串里允许，目标串是规范十进制。换 `i=2` 不行后，实际可行解是 `["05","004","3"]`：`prev=5`，目标 `4`，`s[2:]` 是 `"0043"`，`"4"` 仍不匹配开头……所以真正命中的是 `i=2` 时目标串按 `"004"` 匹配？不，正确做法是：目标值 `4` 的串 `"4"`，在 `s[2:]="0043"` 里跳过前导零后匹配 `"004"` 的数值部分——即允许目标串带前导零。因此匹配逻辑应写成：从当前位置跳过若干 `'0'`，再比对 `str(prev-1)` 的数字部分，且整段数值相等。

```python
def ok(s, i):
    prev, pos, cnt = int(s[:i]), i, 1
    while pos < len(s):
        t = str(prev - 1)
        j = pos
        while j < len(s) and s[j] == '0' and j - pos < len(t) - 1:
            j += 1
        if s[j:j+len(t)] != t:
            return False
        pos, prev, cnt = j + len(t), prev - 1, cnt + 1
    return cnt >= 2
```

关键中间值：`s="050043"`，`i=2`，`prev=5`，`t="4"`，`pos=2` 处 `s[2]='0'`，跳零后 `j=4`，`s[4:5]="4"` 命中，`prev` 变 `4`；下一轮 `t="3"`，`pos=5`，`s[5:6]="3"` 命中，`pos=6` 结束，`cnt=3` 返回 `True`。

## 复杂度
时间：外层枚举首段长度 O(n)，内层每段匹配 O(n)，最坏 O(n²)。
空间：只存 `prev`、`pos` 等常数变量，O(1) 额外空间。

## 易错点
- `s="10009998"` → 若把目标串写成 `str(prev-1)` 直接比对 `"99"` 而忽略原串里的 `"099"`，会在 `pos=3` 处失配返回 `False`；正确做法是允许目标段带前导零，跳过零后再比数字部分。
- `s="001"` → 若允许 `prev-1` 为负数继续匹配，或允许 `prev=0` 时目标 `-1`，会误判；正确做法是 `prev-1 < 0` 时直接剪枝，且首段值不能为 0 后接 0（差值需为 1，`0` 之后只能是 `-1`，非法）。

## 如果面试官追问
要求输出具体拆分方案怎么办？答：把 `ok` 改成返回段列表，命中时 `append(s[pos:j+len(t)])`，首个成功即返回。
