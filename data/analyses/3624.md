## 一句话思路
深度只与 popcount 有关且 k≤5，用 6 棵 Fenwick 按深度分桶，更新时把旧桶 -1、新桶 +1。

## 怎么做
1. 预处理深度表：`depth[x]` 对 x≤64 直接递推 `depth[x]=depth[popcount(x)]+1`，`depth[1]=0`；对任意 v≤10^15，先算 `c=popcount(v)`（≤50），答案就是 `depth[c]+1`（v=1 特判 0）。
2. 建 6 棵 Fenwick（下标 0..5），初始把 `nums[j]` 的深度桶里 `add(j,1)`。
3. 类型 1：`sum(k, r+1) - sum(k, l)` 即答案；类型 2：先 `add(old_depth, idx, -1)`，改 `nums[idx]=val`，再 `add(new_depth, idx, +1)`。
4. 用示例 1 验证：`nums=[2,4]`，popcount 都是 1，`depth[1]=0`，故深度均为 1，桶 1 里是 `{0,1}`。查询 `[1,0,1,1]` 得 2；更新 `nums[1]=1` 后桶 1 删 1、桶 0 加 1，查询 `[1,0,1,0]` 得 1。

```python
def depth_of(v):
    if v == 1: return 0
    c = bin(v).count('1')
    return DEPTH[c] + 1          # DEPTH 预计算到 64

def add(bit, i, d):
    i += 1
    while i < len(bit):
        bit[i] += d; i += i & -i

def pref(bit, i):                # [0, i)
    s = 0
    while i > 0:
        s += bit[i]; i -= i & -i
    return s
```

## 复杂度
时间：每次操作 O(log n)，共 O((n+q) log n)，popcount 为 O(1)。
空间：6 棵 Fenwick 共 O(6n)，加深度表 O(64)。

## 易错点
- `nums[i]=1` 时若照搬 `depth[popcount(1)]+1` 会得 1，实际深度是 0（p0=1 已收敛）→ 必须特判 v==1 返回 0，否则示例 3 的 `[1,0,0,1]` 会错答 1 而非 0。
- 更新时先算新深度再覆盖 `nums[idx]`，若先赋值再取旧深度，旧桶删的是新值 → 桶计数永久偏移，后续所有区间查询都错。

## 如果面试官追问
若 k 上限放大到 10^5 怎么办？答：深度实际最大约 6（10^15 的 popcount≤50，再收敛极快），桶数按真实最大深度开即可，不必按 k 开。
