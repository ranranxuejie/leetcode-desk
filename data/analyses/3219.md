## 一句话思路
按切割代价从大到小贪心切，代价高的线先切，让它少乘几次另一方向的段数。

## 怎么做
1. 把 `horizontalCut` 和 `verticalCut` 各自降序排序，用双指针 `i`、`j` 从大到小比较。
2. 维护 `hSeg = 1`（当前水平段数，即竖切已把蛋糕分成几行）和 `vSeg = 1`（当前竖直段数）。
3. 每次取两数组当前最大值中较大的那条切：切水平线时累加 `cost * vSeg`，然后 `hSeg += 1`；切竖直线时累加 `cost * hSeg`，然后 `vSeg += 1`。
4. 一侧切完后，把另一侧剩余全部按同样规则累加。

以示例 1 为例：`horizontalCut=[3,1]`、`verticalCut=[5]`。先比 3 和 5，取 5 切竖线，累加 `5 * hSeg = 5 * 1 = 5`，此时 `vSeg = 2`；再切 3，累加 `3 * vSeg = 3 * 2 = 6`，`hSeg = 2`；最后切 1，累加 `1 * 2 = 2`，总计 `5 + 6 + 2 = 13`。

```python
h = sorted(horizontalCut, reverse=True)
v = sorted(verticalCut, reverse=True)
i = j = 0
hSeg = vSeg = 1
ans = 0
while i < len(h) or j < len(v):
    if j == len(v) or (i < len(h) and h[i] >= v[j]):
        ans += h[i] * vSeg
        hSeg += 1
        i += 1
    else:
        ans += v[j] * hSeg
        vSeg += 1
        j += 1
```

## 复杂度
时间：排序 `O(m log m + n log n)`，双指针合并 `O(m + n)`。
空间：排序额外 `O(m + n)`（Python `sorted` 返回新列表）。

## 易错点
- 把 `h[i] >= v[j]` 写成 `>` 本身不影响结果，但若误写成升序排序（`reverse=False`）→ 示例 1 会先切代价 1 的水平线，累加 `1 * 1`，最终得到 11 而非 13 → 必须降序，让大代价先乘小段数。
- 混淆乘数：切水平线时乘的是 `vSeg`（竖直段数），切竖直线时乘的是 `hSeg` → 示例 1 若把切竖线的 5 乘成 `vSeg` 得 5，看似对，但后续切 3 时若乘 `hSeg=1` 会得 3，总计 9，漏掉了「竖切后水平线要切两段」这一事实 → 记住切完某方向后，是**另一方向**的段数加一。

## 如果面试官追问
问：若要求输出具体切割顺序而非总开销？答：双指针每次选中的那条线就是下一步要切的线，按选择顺序记录 `('H', i)` 或 `('V', j)` 即可，复杂度不变。
