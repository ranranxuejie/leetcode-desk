## 一句话思路
用有序字典维护互不重叠的区间，add 时合并所有相交区间并同步维护总长度 total。

## 怎么做
1. 用 `SortedDict` 存 `left -> right`，保证按左端点有序，且任意两区间不相交。
2. add 时先找可能相交的区间：左端点 ≤ right 的那些，取最后一个作为起点。
3. 逐个合并：相交就吸收进 `[left, right]`，从 total 里扣掉旧区间长度、从字典里删掉。
4. 合并完插入新区间，total 加上新长度。

以示例 `add(5, 8)` 为例：此时字典是 `{2:3, 7:10}`，total=6。左端点 ≤ 8 的有 2 和 7，从 7 开始合并：`[7,10]` 与 `[5,8]` 相交，left 变 5、right 变 10，total 减 4 得 2，删掉 7。再往前看 2，`[2,3]` 与 `[5,10]` 不相交，停。插入 `5:10`，total=2+6=8。

```python
from sortedcontainers import SortedDict

def add(self, left, right):
    keys = list(self.d.keys())
    i = bisect_right(keys, right) - 1
    while i >= 0 and self.d[keys[i]] >= left:
        l, r = keys[i], self.d.pop(keys[i])
        self.total -= r - l + 1
        left, right = min(left, l), max(right, r)
        i -= 1
    self.d[left] = right
    self.total += right - left + 1
```

## 复杂度
时间：每次 add 均摊 O(log n + k)，k 是被删区间数，每个区间一生只被删一次，总计 O(n log n)。
空间：O(n)，字典存至多 n 个不相交区间。

## 易错点
- 相邻区间 `[2,3]` 和 `[4,5]`：若用 `self.d[keys[i]] >= left` 判断会漏合并，导致 total 正确但区间碎片化，后续 add 变慢；本题允许不合并相邻，但若改成 `> left` 判断相交则 `[4,5]` 会被误并，务必用 `>=` 判「有重叠」而非「相邻」。
- 只删了 `keys[i]` 却忘了 `total -= r - l + 1`：示例中 add(5,8) 会得到 total=6+4=10 而非 8；正确做法是删区间和扣长度必须成对出现。

## 如果面试官追问
若 left/right 上限改成 10^18 且要求返回具体区间列表？答：字典方案不变，只是不能开数组，合并逻辑与本题完全一致。
