## 一句话思路
按最大值 n 插入位置枚举逆序对增量，用前缀和把 O(k) 的转移压成 O(1)，得 dp[n][k]。

## 怎么做
1. 定义 `dp[i][j]` = 用 1..i 排列出恰好 j 个逆序对的方案数，插入 i 时它前面有 t 个更大元素，贡献 t 个逆序对，t 取 0..min(i-1, j)。
2. 转移 `dp[i][j] = sum(dp[i-1][j-t] for t in 0..i-1)`，即对上一行取长度 i 的滑动窗口和。
3. 用前缀和 `pre` 把窗口和变成 `pre[j+1] - pre[max(0, j-i+1)]`，每行 O(k)。
4. 以 n=3, k=1 走一遍：i=1 时 dp=[1]；i=2 时 dp[2][0]=1, dp[2][1]=1；i=3 求 j=1，窗口是 dp[2][0..1] 之和 = 1+1 = 2，与示例输出 2 一致。

```python
MOD = 10**9 + 7
dp = [0] * (k + 1)
dp[0] = 1
for i in range(2, n + 1):
    pre = [0] * (k + 2)
    for j in range(k + 1):
        pre[j + 1] = (pre[j] + dp[j]) % MOD
    ndp = [0] * (k + 1)
    for j in range(k + 1):
        lo = max(0, j - i + 1)
        ndp[j] = (pre[j + 1] - pre[lo]) % MOD
    dp = ndp
return dp[k]
```

## 复杂度
时间：O(n·k)，外层 n 次、内层 k 次前缀和与窗口查询。
空间：O(k)，只保留上一行 dp 和长度 k+2 的 pre 数组。

## 易错点
- n=1, k=0 → 若循环从 `range(1, n+1)` 起且没初始化 `dp[0]=1`，会返回 0；正确做法是先把 `dp[0]=1` 当 i=1 的答案，循环从 i=2 开始。
- k 很大而 n 很小时（如 n=3, k=1000）→ 不设 `j <= min(k, i*(i-1)//2)` 的上界也能过，但若把 `lo = max(0, j-i+1)` 写成 `j-i`，窗口会多算一项，n=3,k=1 会得 3 而非 2；正确做法是 `lo = max(0, j - i + 1)`，因为 t 最大取 i-1。

## 如果面试官追问
若 k 扩大到 1e5 而 n 仍 1000，怎么办？答：k 超过 n(n-1)/2 直接返回 0，实际有效 k 上界约 5e5，仍用滚动前缀和，只是内层循环截到 `min(k, i*(i-1)//2)`。
