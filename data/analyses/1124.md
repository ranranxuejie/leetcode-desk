## 一句话思路
把 >8 记 +1、否则记 -1，求前缀和 `pre` 上满足 `pre[j] > pre[i]` 的最大 `j-i`，用哈希表存每个前缀和首次出现的下标。

## 怎么做
1. 遍历 `hours`，累加 `pre += 1 if h > 8 else -1`，把 `(pre, i)` 里 `pre` 第一次出现的位置记进 `first`。
2. 关键：`first` 初始化成 `{0: -1}`，代表空前缀和为 0、下标 -1，这样从 0 开始的区间也能被算到。
3. 再扫一遍，若 `pre - 1` 在 `first` 里，就用 `i - first[pre-1]` 更新答案；用 `pre-1` 而不是 `pre`，是因为要严格大于。

以 `hours = [9,9,6,0,6,6,9]` 为例，前缀和依次是 `1,2,1,0,-1,-2,-1`。`first` 记录 `{0:-1, 1:0, 2:1, -1:4, -2:5}`。扫到 `i=6` 时 `pre=-1`，查 `first[-2]=5`，得长度 `6-5=1`；扫到 `i=2` 时 `pre=1`，查 `first[0]=-1`，得长度 `2-(-1)=3`，这就是答案。

```python
first = {0: -1}
pre = 0
for i, h in enumerate(hours):
    pre += 1 if h > 8 else -1
    if pre not in first:
        first[pre] = i

ans = 0
pre = 0
for i, h in enumerate(hours):
    pre += 1 if h > 8 else -1
    if pre - 1 in first:
        ans = max(ans, i - first[pre - 1])
```

## 复杂度
时间：O(n)，两趟线性扫描，`hours` 长度 n。
空间：O(n)，`first` 最多存 n+1 个不同前缀和。

## 易错点
- `hours = [6,6,6]` 时前缀和一路降到 -3，若 `first` 不预置 `{0:-1}`，从下标 0 起的区间永远查不到 `pre-1`，答案会错成 0 之外的负数或漏解；正确做法是初始化就带上 `0:-1`。
- 查表时写成 `pre in first` 而不是 `pre-1 in first`，会把「劳累天数 ≥ 不劳累天数」当成严格大于；对 `[9,9,6,0,6,6,9]` 会算出 4 而非 3，必须用 `pre-1`。

## 如果面试官追问
问：要求输出具体区间下标而不只是长度？
答：在 `first` 里同时存下标，更新答案时记下 `(first[pre-1]+1, i)` 即可，仍是 O(n)。
