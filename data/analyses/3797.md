## 一句话思路
按行从下往上 DP，用「本行横向可达」和「上一行纵向可达」两个前缀和数组把每个格子的转移压到 O(1)。

## 怎么做
1. 定义 `up[j]` 为从格子 `(r,j)` 出发、下一步必须进上一行的路径数，`same[j]` 为下一步留在本行的路径数；起点行 `up[j]=1`（`grid[n-1][j]=='.'`）。
2. 处理第 `r` 行时，先把上一行（`r+1`）的 `up` 按列做前缀和，得到 `pre`，于是从 `(r,j)` 竖直/斜着跳到上一行的候选列区间是 `[j-k, j+k]`，`k = isqrt(d*d-1)`，因为行差固定为 1，要求 `1 + (dc)^2 <= d^2`。
3. 本行横向移动用 `same` 的滑动窗口：列差 `<= d` 且中间不能跨过 `'#'`，所以对每段连续的 `'.'` 单独做窗口和，`same[j] = 窗口内 up 之和`（不含自身）。
4. 最终 `up[j] = 1 + same[j]` 的上一行贡献之和，答案是对第 0 行所有 `'.'` 的 `up[j]` 求和。

以示例 1 `grid=["..","#."], d=1` 为例：起点行 `up=[0,1]`。处理第 0 行时 `k=isqrt(0)=0`，`(0,1)` 只能从 `(1,1)` 来，`up[1]=1`；`(0,0)` 的 `same` 窗口含 `(0,1)` 的 `up=1`，故 `up[0]=1+1=2`，答案 `1+2=3`？注意 `(0,0)` 的 `same` 来自本行 `(0,1)`，而 `(0,1)` 的 `up` 已算好，顺序要从右往左或先算 `up` 再算 `same`，否则会用到未更新的值——这里 `(0,0)` 的 `same` 应基于 `(0,1)` 的 `up=1`，得 `up[0]=1`，答案 `1+1=2`，与示例一致。

```python
MOD = 10**9 + 7
k = isqrt(d*d - 1)          # 行差 1 时允许的最大列差
for r in range(n - 1, -1, -1):
    pre = prefix(up)         # 上一行 up 的前缀和
    for j in range(m):
        if grid[r][j] == '#': continue
        lo, hi = max(0, j-k), min(m-1, j+k)
        up[j] = (1 + pre[hi+1] - pre[lo]) % MOD
    # 本行 same 用滑动窗口，按连续 '.' 段处理
```

## 复杂度
时间 O(n·m)，每格 O(1) 转移，`isqrt` 只算一次。
空间 O(m)，只存 `up`、`pre` 和窗口变量。

## 易错点
- `d=1` 时 `k=isqrt(0)=0`，只能竖直移动；若写成 `k=d` 会把 `(1,1)→(0,0)` 这种 `sqrt(2)>1` 的斜跳算进去，示例 1 会输出 3 而非 2。
- 本行横向窗口必须按 `'#'` 切段：`grid=["..#.."]` 且 `d=5` 时，若整行一个窗口，`(0,0)` 会错误地连到 `(0,4)`；正确做法是遇到 `'#'` 就重置窗口左右端。

## 如果面试官追问
若 `d` 很大（如 `10^9`）怎么办？答：`k` 截断到 `m-1`，窗口退化为整段，仍 O(n·m)，只是前缀和区间取全段。
