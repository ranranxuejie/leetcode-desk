## 一句话思路
用计数器 `done` 记录已解析的 promise 数，每个 `.then` 里把结果按下标写进 `results`，凑满 `len(functions)` 才 resolve。

## 怎么做
1. 先 `results = [None] * len(functions)`，`done = 0`，再 `return new Promise(...)` 包住整个逻辑。
2. 遍历 `functions`，对每个 `fn` 立刻调用 `fn()` 拿到 promise，**不要**在循环里 `await`，否则就串行了。
3. 每个 promise 挂 `.then(val => ...)`：写 `results[i] = val`，`done += 1`，若 `done == len(functions)` 则 `resolve(results)`。
4. 每个 promise 挂 `.catch(reject)`，直接透传第一个拒绝原因。

以示例 3 为例：三个函数分别在 50/150/100 ms 解析。50 ms 时 `results[0]=4, done=1`；100 ms 时 `results[2]=16, done=2`；150 ms 时 `results[1]=10, done=3`，此时才 `resolve([4,10,16])`。注意 `results` 是按**下标**填的，所以最终顺序天然是 `[4,10,16]` 而非完成顺序 `[4,16,10]`。

```python
def promiseAll(functions):
    results = [None] * len(functions)
    done = 0
    def executor(resolve, reject):
        nonlocal done
        for i, fn in enumerate(functions):
            fn().then(
                lambda val, i=i: (
                    results.__setitem__(i, val),
                    globals().__setitem__('done', done + 1),
                    done == len(functions) and resolve(results)
                ),
                reject
            )
    return Promise(executor)
```

（Python 里没有原生 Promise，上面是伪实现；真实提交用 JS 的 `new Promise`，逻辑一致。关键就三行：`results[i] = val`、`done += 1`、`done === n && resolve(results)`。）

## 复杂度
时间 O(n)，n 为 `functions.length`，并行等待取最慢那个的耗时。
空间 O(n)，`results` 数组存 n 个解析值，计数器 O(1)。

## 易错点
- 在 `for` 循环里写 `await fn()` → 变成串行，示例 3 总耗时从 150 ms 变 300 ms → 正确做法是循环里只调用 `fn()` 收集 promise，`.then` 里再处理结果。
- 用 `results.append(val)` 而非按下标赋值 → 示例 3 得到 `[4,16,10]`（完成顺序）→ 必须 `results[i] = val`，用 `enumerate` 的 `i`。
- 空数组 `functions = []` → 若只在 `.then` 里判断 `done == n`，永远不触发，promise 挂死 → 循环前先判 `if not functions: resolve([])`。

## 如果面试官追问
问：要求「第一个拒绝就立刻 reject，但其余 promise 继续跑」怎么保证？
答：`.catch(reject)` 挂在每个 promise 上，谁先 reject 谁触发外层 reject，其余 promise 不受影响照常执行完，只是结果被丢弃。
