## 一句话思路
先对 original/changed 建图跑 Floyd 求任意两串的最短替换成本，再用字典树在 source 上做区间 DP。

## 怎么做
1. 把所有 original[i]、changed[i] 收进一个字符串集合，编号后建邻接矩阵，`cost[i]` 取 min（重复边保留最小），跑 Floyd 得到 `d[a][b]`。
2. 用字典树存所有 original 串，节点记录「以该节点结尾的 original 编号」，供 DP 时枚举从 i 出发能匹配哪些 original。
3. `dp[i]` = 把 source[i:] 变成 target[i:] 的最小成本，从后往前推；先判 `dp[i] = dp[i+1]` 当 `source[i]==target[i]`。
4. 从 i 沿字典树走 source 的字符，走到某个 original 串 x（长度 L）时，若 `source[i:i+L]` 与 `target[i:i+L]` 能通过 `d` 连通，则 `dp[i] = min(dp[i], d[x][y] + dp[i+L])`，其中 y 是 target 对应子串。

以示例 1 为例：Floyd 后 `d["c"]["b"] = 3`（c→e→b，1+2），故 `dp[2]` 处 source[2]='c'、target[2]='b' 走这条链成本 3，而不是直接边 5。

```python
# 建图 + Floyd（节点为字符串编号）
d = [[INF]*m for _ in range(m)]
for i in range(m): d[i][i] = 0
for a, b, c in edges:
    d[id[a]][id[b]] = min(d[id[a]][id[b]], c)
for k in range(m):
    for i in range(m):
        for j in range(m):
            if d[i][k] + d[k][j] < d[i][j]:
                d[i][j] = d[i][k] + d[k][j]

# DP
dp = [INF]*(n+1); dp[n] = 0
for i in range(n-1, -1, -1):
    if source[i] == target[i]: dp[i] = dp[i+1]
    node = root
    for j in range(i, n):
        node = trie[node].get(source[j])
        if node is None: break
        for x in end[node]:          # 以 node 结尾的 original 编号
            L = len(orig[x])
            y = target[i:i+L]
            if y in id and d[x][id[y]] < INF:
                dp[i] = min(dp[i], d[x][id[y]] + dp[i+L])
```

## 复杂度
时间：Floyd `O(m^3)`（m≤200 个不同串）+ DP 每位置沿字典树走 `O(n·Lmax)`，n=1000。
空间：`O(m^2)` 距离矩阵 + 字典树 `O(总串长)` + `dp` 数组 `O(n)`。

## 易错点
- 只对 `original[i]→changed[i]` 建单向边、忘记 Floyd 传递闭包：示例 1 中 c→b 需经 c→e→b 才得 3，直接取边 5 会输出 30 而非 28。
- 字典树匹配时把 `source[i:i+L]` 与 `target[i:i+L]` 直接比较而不查 `d`：示例 2 中 "fgh"→"thh"→"ghh" 两跳成本 8，只认单跳会漏掉这条路径。

## 如果面试官追问
若 original/changed 长度可达 1000 且 n 不变，怎么优化？答：Floyd 换成对每个起点跑 Dijkstra，`O(m·E log m)`，DP 部分不变。
