## 一句话思路
利用 BST 有序性：从根往下走，p、q 分居当前节点两侧（或之一等于当前节点）时，当前节点即 LCA。

## 怎么做
1. 令 `cur = root`，循环直到找到答案。
2. 若 `p.val` 和 `q.val` 都小于 `cur.val`，说明两者都在左子树，`cur = cur.left`。
3. 若两者都大于 `cur.val`，`cur = cur.right`。
4. 否则（一大一小，或某个等于 `cur.val`），`cur` 就是分叉点，直接返回。

以示例 1 为例：`cur=6`，`p.val=2 < 6`、`q.val=8 > 6`，一左一右，第一次判断就返回 `6`。示例 2：`cur=6` 时 2、4 都小于 6，走左到 `cur=2`；此时 `p.val=2` 等于 `cur.val`，不再满足「都小于」或「都大于」，返回 `2`——这正是「节点可以是自己的祖先」。

```python
cur = root
while cur:
    if p.val < cur.val and q.val < cur.val:
        cur = cur.left
    elif p.val > cur.val and q.val > cur.val:
        cur = cur.right
    else:
        return cur
```

关键在 `else` 分支：它同时覆盖「分居两侧」和「命中 p 或 q」两种终止条件，不需要单独判断 `cur == p`。

## 复杂度
时间：O(h)，h 为树高，只沿一条路径下降，最坏 O(n)（退化成链）。
空间：O(1)，迭代无递归栈；递归写法才是 O(h)。

## 易错点
- 输入 `p=2, q=4`（示例 2）→ 若写成「找到第一个值介于 p、q 之间的节点就返回」但漏了等号判断，会继续往左走到 `0` 返回错误节点 → 正确做法是用严格 `<` / `>` 判断「都小于」「都大于」，相等时落入 `else` 返回 `cur`。
- 输入是普通二叉树而非 BST（面试官改条件）→ 仍按大小比较会走错分支，返回错误祖先 → 此时必须改成后序遍历：左右子树分别找 p、q，都非空则当前节点为 LCA，否则返回非空的那侧。

## 如果面试官追问
问：若 p、q 不一定存在于树中怎么办？
答：先各做一次查找确认存在，再走上面的下降逻辑；或后序递归时统计命中数，凑满 2 才认 LCA。
