## 一句话思路
从高位到低位贪心：逐位尝试把答案该位清零，用「合并成若干段、每段 AND 该位为 0」判断可行性，段数够少就保留清零。

## 怎么做
1. 答案初值 `ans = 0`，从第 29 位扫到第 0 位，令 `target = ans | (1 << b)`，表示「假设这一位必须为 1」的候选上界。
2. 顺序扫 `nums`，维护当前段 AND 值 `cur`；若 `cur & target == 0`，说明这一段可以整体压成一个元素且不贡献 target 的位，段数 `cnt += 1`，`cur` 重置为全 1（用 `(1<<30)-1`）。
3. 扫完后若 `cnt > k`，说明压不出足够少的段，这一位只能保留：`ans |= (1 << b)`；否则这一位可以清零，`ans` 不动。
4. 返回 `ans`。

以 `nums = [3,5,3,2,7], k = 2` 为例，看第 1 位（值 2）：`target = 2`。扫到 `3&5=1`，`1&2=0` → 段数 1；接着 `3&2=2`，`2&2=2` 不为 0，继续 `2&7=2`，仍不为 0，段数停在 1。`cnt=1 ≤ k=2`，第 1 位可清零。而第 0 位 `target=1` 时，`3&5&3=1`，`1&1=1` 卡住，最终 `cnt=2` 仍 ≤ 2，也清零——但第 1 位与第 0 位组合后 `ans=3`，正是输出。

```python
ans = 0
for b in range(29, -1, -1):
    target = ans | (1 << b)
    cnt, cur = 0, (1 << 30) - 1
    for x in nums:
        cur &= x
        if cur & target == 0:
            cnt += 1
            cur = (1 << 30) - 1
    if cnt > k:
        ans |= (1 << b)
return ans
```

## 复杂度
时间：O(30n)，30 是位宽常数，n 来自每位的整数组扫描。
空间：O(1)，只用了 `ans`、`target`、`cnt`、`cur` 四个标量。

## 易错点
- `nums = [3,5,3,2,7], k = 2` 若把 `cnt > k` 写成 `cnt >= k`，第 0 位会被误判为不可清零，答案错成 3 之外的更大值；正确是「段数 ≤ k 才可清零」，因为 n 个元素压成 cnt 段需要 n-cnt 次操作。
- `cur` 重置必须用 `(1<<30)-1` 而非 `0`：若重置成 0，`cur & target` 恒为 0，每遇到一个元素就 `cnt += 1`，`cnt` 直接等于 n，所有位都被判为不可清零，答案退化成全数组 OR。

## 如果面试官追问
问：若要求输出具体操作方案怎么办？
答：在每位判定时记录每段的起止下标，段内相邻元素依次 AND 合并，按段从左到右执行即可。
