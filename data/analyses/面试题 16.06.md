## 一句话思路
两边排序后双指针同向推进，每次移动较小值那一侧，因为差值只可能被这一侧的下一元素缩小。

## 怎么做
1. 对 `a`、`b` 分别排序，示例得 `a=[1,2,3,11,15]`、`b=[8,19,23,127,235]`。
2. 指针 `i=j=0`，`best=2**31-1`，循环到任一边越界。
3. 每轮算 `d=abs(a[i]-b[j])` 更新 `best`，然后移动较小值那侧的指针。
4. 返回 `best`。

关键中间值：初始 `a[0]=1, b[0]=8`，`d=7`，`best=7`，`1<8` 故 `i=1`；接着 `a[1]=2` 对 `8` 得 `d=6`，`i=2`；`a[2]=3` 对 `8` 得 `d=5`，`i=3`；`a[3]=11` 对 `8` 得 `d=3`，`best=3`，此时 `11>8` 故 `j=1`；之后 `11` 对 `19` 得 `8`、`15` 对 `19` 得 `4`，都不再小于 3，最终返回 3。

```python
a.sort()
b.sort()
i = j = 0
best = 2**31 - 1
while i < len(a) and j < len(b):
    best = min(best, abs(a[i] - b[j]))
    if a[i] < b[j]:
        i += 1
    else:
        j += 1
return best
```

## 复杂度
时间：排序 `O(m log m + n log n)`，双指针扫描 `O(m+n)`，`m`、`n` 为两数组长度。
空间：排序额外 `O(log m + log n)` 栈空间，指针与 `best` 为 `O(1)`。

## 易错点
- 输入含负数（如 `a=[-5]`、`b=[3]`）→ 若用「排序后只比较相邻下标」或误以为差值可直接相减取正，会漏掉跨数组配对 → 必须对每个 `(i,j)` 取 `abs(a[i]-b[j])`，不能假设 `a[i]>=b[j]`。
- 一边先耗尽（如 `a=[1]`、`b=[100,200]`）→ 若循环条件写成 `or` 继续访问 `a[i]` 会 `IndexError` → 条件必须是 `i < len(a) and j < len(b)`，耗尽即停，剩余元素不可能产生更小差。

## 如果面试官追问
问：若 `a`、`b` 长度差极大（`m=10`、`n=10**6`）怎么优化？
答：只排序短数组 `a`，对 `b` 每个元素在 `a` 上二分找插入位置，比较左右邻居，`O(n log m)`。
