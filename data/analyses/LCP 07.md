## 一句话思路
按轮数做 DP，`dp[t][v]` 表示第 t 轮信息到 v 的方案数，逐轮按 relation 累加。

## 怎么做
1. 建邻接表 `g[u]` 存 u 能传给谁，遍历 relation 一次填好。
2. 初始化 `dp = [0]*n`，`dp[0] = 1`（第 0 轮只有 0 号有 1 种）。
3. 循环 k 次，每轮用 `ndp = [0]*n`，对每条边 `(u,v)` 做 `ndp[v] += dp[u]`，然后 `dp = ndp`。
4. 返回 `dp[n-1]`。

用示例 1（n=5, k=3）走一遍：第 1 轮后 `dp = [0,0,1,0,1]`（0→2、0→4 各 1 种）；第 2 轮 2 号能到 1、3、0，得 `dp = [1,1,0,1,0]`；第 3 轮 0→4、1→4、3→4 各贡献 1，`dp[4] = 3`，与答案一致。

```python
g = [[] for _ in range(n)]
for u, v in relation:
    g[u].append(v)
dp = [0] * n
dp[0] = 1
for _ in range(k):
    ndp = [0] * n
    for u in range(n):
        for v in g[u]:
            ndp[v] += dp[u]
    dp = ndp
return dp[n - 1]
```

关键点：每轮必须用新的 `ndp`，不能在 `dp` 上原地累加，否则同一轮内刚更新的值会被当成本轮起点再传一次，轮数就乱了。

## 复杂度
时间 O(k·(n + m))，m = relation 长度，每轮扫全部边。
空间 O(n + m)，邻接表存 m 条边，两个长度 n 的 dp 数组。

## 易错点
- k 轮后到达 n-1 才算数，但 `dp[n-1]` 在第 0 轮是 0（n≥2，起点是 0 号），若把循环写成 `range(k+1)` 会多传一轮，示例 1 会得 0 而不是 3。
- relation 里可能有重复边（题面未禁止），如 `[[0,4],[0,4]]`，邻接表会存两条，`ndp[4] += dp[0]` 加两次，这恰好是两种不同方案，不能去重；反过来若用 set 存邻接表就会把方案数算少。

## 如果面试官追问
要求输出所有具体方案路径怎么办？把 dp 换成 `paths[t][v]` 存路径列表，转移时对每条边做列表拼接，代价是方案数级别的空间。
