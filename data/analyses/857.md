## 一句话思路
按 `wage[i]/quality[i]` 升序枚举「组内最高工资率」的工人，用大顶堆维护质量最小的 k 人。

## 怎么做
1. 把工人按 `wage[i]/quality[i]` 升序排序，枚举当前工人作为组内工资率最高者。
2. 维护一个存 `quality` 的大顶堆，堆内始终保留当前前缀中质量最小的 k 个工人。
3. 堆满 k 人时，总成本 = 当前工资率 × 堆内质量之和，取全局最小。

以示例 1 为例：三人工资率为 7、2.5、6，排序后顺序是工人 1(2.5)、工人 2(6)、工人 0(7)。扫到工人 2 时堆里是 `[5, 20]`，和 `sum_q = 25`，成本 `6 × 25 = 150`；扫到工人 0 时先弹掉质量 20，堆变 `[5, 10]`、`sum_q = 15`，成本 `7 × 15 = 105`，即答案。

```python
import heapq
workers = sorted((w / q, q) for q, w in zip(quality, wage))
heap, sum_q, ans = [], 0, float('inf')
for rate, q in workers:
    heapq.heappush(heap, -q)
    sum_q += q
    if len(heap) > k:
        sum_q += heapq.heappop(heap)   # 弹出的是负数，等于减去最大质量
    if len(heap) == k:
        ans = min(ans, rate * sum_q)
return ans
```

关键点：`heappop` 返回 `-q_max`，所以 `sum_q += heappop(...)` 就是在减掉最大质量，别写成 `-=`。

## 复杂度
时间：排序 O(n log n) 加每个工人一次堆操作 O(n log k)，共 O(n log n)。
空间：堆最多 k 个元素 O(k)，排序后的 `workers` 列表 O(n)。

## 易错点
- 堆里存质量还是存工资率搞混 → 若把 `rate` 压进堆，弹掉的是工资率最大的而非质量最大的，示例 1 扫到工人 0 时会弹错人、`sum_q` 变成 25，答案错成 175。堆里必须只放 `quality`，用 `-q` 实现大顶堆。
- 堆未满 k 就计算成本 → 示例 2 中 k=3，扫到第二个工人时堆只有 2 人，若此时算 `rate * sum_q` 会得到一个偏小的假答案。必须先判 `len(heap) == k` 再更新 `ans`。

## 如果面试官追问
要求输出具体雇佣哪 k 个人而不只是金额？答：堆里改存 `(quality, index)`，记录取到最优 `ans` 那一刻堆内的下标集合即可。
