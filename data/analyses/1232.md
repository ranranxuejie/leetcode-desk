## 一句话思路
用前两点定基准向量，其余点与基准点做叉积，叉积全为 0 即共线。

## 怎么做
1. 取 `p0 = coordinates[0]`、`p1 = coordinates[1]`，算出基准向量 `dx = p1[0]-p0[0]`、`dy = p1[1]-p0[1]`。
2. 遍历 `coordinates[2:]`，对每个点 `p` 算 `(p[0]-p0[0])*dy - (p[1]-p0[1])*dx`。
3. 任一结果不为 0 立即返回 `False`，全部为 0 返回 `True`。

以示例 2 的 `[[1,1],[2,2],[3,4],...]` 为例：`p0=(1,1)`、`p1=(2,2)`，得 `dx=1, dy=1`。检查 `(3,4)`：`(3-1)*1 - (4-1)*1 = 2-3 = -1 ≠ 0`，直接判 `False`，后面的点不用看。

```python
p0, p1 = coordinates[0], coordinates[1]
dx, dy = p1[0] - p0[0], p1[1] - p0[1]
for x, y in coordinates[2:]:
    if (x - p0[0]) * dy - (y - p0[1]) * dx != 0:
        return False
return True
```

叉积而非斜率，是因为斜率要处理 `dx == 0` 的竖直线，叉积把「竖直」和「水平」统一成同一个式子，不用分支。

## 复杂度
时间：O(n)，n 为点数，每个点做一次常数次乘减。
空间：O(1)，只存 `p0, p1, dx, dy` 四个变量，不额外开数组。

## 易错点
- 用斜率 `(y-p0[1])/(x-p0[0])` 比较时，遇到 `[[0,0],[0,1],[0,2]]` 这种竖直线会 `ZeroDivisionError`，或浮点除法把 `1/3` 和 `2/6` 比出误差；正确做法是全程用叉积整数比较，不出现除法。
- 只拿相邻两点比较（`p[i]` 与 `p[i-1]`）时，`[[0,0],[1,1],[2,2],[3,4]]` 前几对都共线，最后才崩，逻辑上没错但容易写成「相邻斜率相等」而漏掉基准点；正确做法是固定 `p0` 作原点，所有点都对 `p0` 算叉积。

## 如果面试官追问
问：坐标范围放大到 10^9 怎么办？
答：Python 整数无溢出，叉积最大约 `2*10^9 * 2*10^9 = 4*10^18` 仍精确；换 C++ 需用 `long long` 存叉积。
