## 一句话思路
把一次操作看成下标映射 `i -> 2i (i<n/2)` 或 `i -> 2i-n+1`，答案就是下标 1 回到 1 的循环长度。

## 怎么做
1. 只跟踪下标 1：初始 `perm[1]=1`，一步后它被搬到位置 `2`，即 `pos = 2`。
2. 反复对 `pos` 施加同一映射，直到 `pos == 1`，计步数即为答案。
3. 映射写成 `pos = pos * 2 if pos < n // 2 else (pos - n // 2) * 2 + 1`，两分支分别对应题面偶数位/奇数位公式。
4. 用 `n = 6` 走一遍：`pos` 序列为 `1 → 2 → 4 → 3 → 1`，4 步回到 1，与示例 3 输出 4 一致。

```python
pos, steps = 1, 0
while True:
    if pos < n // 2:
        pos *= 2
    else:
        pos = (pos - n // 2) * 2 + 1
    steps += 1
    if pos == 1:
        break
return steps
```

关键中间值：`n = 6` 时 `n // 2 = 3`，`pos = 4` 走 else 分支得 `(4-3)*2+1 = 3`，再走 else 得 `(3-3)*2+1 = 1`，循环结束。

## 复杂度
时间：O(答案)，每步只更新一个整数 `pos`，与 n 无直接关系。
空间：O(1)，只开 `pos`、`steps` 两个变量，没有建数组。

## 易错点
- 用 `n = 2` 时若写成 `pos < n // 2` 判断，`n // 2 = 1`，`pos = 1` 走 else 分支得 `(1-1)*2+1 = 1`，一步即回，正确；但若把条件写成 `pos <= n // 2`，`pos = 1` 会走 `pos *= 2` 得 2，再走 else 得 1，答案变成 2，错成示例 1 的 1 之外的值。边界必须严格用 `<`。
- 直接模拟整个 `perm` 数组时，若把 `arr` 写成原地修改 `perm`，`n = 4` 第一步会读到已被覆盖的 `perm[1]`，得到 `[0,2,2,3]` 而非 `[0,2,1,3]`，步数永远回不到初始。必须新建数组或只跟踪单个下标。

## 如果面试官追问
问：n 很大（比如 10**9）还能算吗？
答：能，答案是最长循环长度，量级 O(n)，但只跟踪下标 1 的循环，实际迭代次数就是答案本身，不需要开 n 大小的数组。
