## 一句话思路
找到 1 和 n 的下标，把 1 左移到 0、n 右移到 n-1，两步距离相加，若路径交叉再减 1。

## 怎么做
1. 用 `nums.index(1)` 和 `nums.index(n)` 拿到两个下标 `i1`、`in_`。
2. 把 1 移到最左需要 `i1` 次相邻交换，把 n 移到最右需要 `n-1-in_` 次。
3. 若 `i1 > in_`，说明 1 在 n 右边，两者相向移动时会互相「借道」一次，总次数减 1。
4. 返回 `i1 + (n-1-in_) - (1 if i1 > in_ else 0)`。

以 `nums = [2,4,1,3]` 为例：`i1 = 2`，`in_ = 1`（n=4 在下标 1）。`i1 > in_` 成立，答案 `2 + (3-1) - 1 = 3`，与示例一致。中间值：1 左移 2 次、4 右移 2 次，交叉一次抵消 1 次。

```python
n = len(nums)
i1 = nums.index(1)
in_ = nums.index(n)
ans = i1 + (n - 1 - in_)
if i1 > in_:
    ans -= 1
return ans
```

关键点：`i1 > in_` 这个判断只在 1 和 n 的相对位置颠倒时触发，此时两者交换路径重叠一格，少算一次。

## 复杂度
时间：O(n)，`index` 各扫一遍数组，n 为排列长度。
空间：O(1)，只存两个下标和答案，无额外数组。

## 易错点
- 输入 `nums = [1,3,4,2,5]`（已半有序）→ 若忘记 `i1 > in_` 判断会多减 1 得 -1 或错值 → 正确做法是只在 `i1 > in_` 时减 1，此处 `i1=0 < in_=4`，不减，返回 0。
- 输入 `nums = [2,1,4,3]` → 若把 n 的下标当成 `nums.index(n)` 却用 `n-1` 当目标位置混淆 → 会算成 `1 + 3 - 1 = 3` 而非 2 → 正确做法是目标位置固定为 `n-1`，距离为 `n-1-in_`，此处 `in_=3`，距离 0。

## 如果面试官追问
问：若要求输出具体交换序列而非次数？答：按 1 左移、n 右移的顺序逐次记录相邻交换的下标对即可，交叉时先移 1 再移 n。
