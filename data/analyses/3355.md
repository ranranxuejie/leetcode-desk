## 一句话思路
用差分数组统计每个下标被多少个查询区间覆盖，逐位比较覆盖次数与 `nums[i]`。

## 怎么做
1. 建长度 `n+1` 的差分数组 `diff`，对每个 `[l, r]` 做 `diff[l] += 1`、`diff[r+1] -= 1`。
2. 从左到右累加 `diff` 得到 `cover`，即下标 `i` 最多能被减的次数。
3. 只要某个 `i` 满足 `cover < nums[i]`，立刻返回 `False`；全部满足返回 `True`。

以示例 2 的 `nums = [4,3,2,1]`、`queries = [[1,3],[0,2]]` 为例：差分后 `diff = [1,1,0,-1,-1]`，前缀和 `cover = [1,2,2,1]`。下标 0 处 `cover=1 < nums[0]=4`，直接判 `False`——这正是示例里最终剩下 `[3,1,0,0]` 的根因。

```python
n = len(nums)
diff = [0] * (n + 1)
for l, r in queries:
    diff[l] += 1
    diff[r + 1] -= 1

cover = 0
for i in range(n):
    cover += diff[i]
    if cover < nums[i]:
        return False
return True
```

关键点：查询是「选子集减 1」，所以一个下标被覆盖 `c` 次时，最多减 `c`，且可以少减，因此条件恰好是 `cover >= nums[i]`，不是相等。

## 复杂度
时间 O(n + q)，n 为 `nums` 长度、q 为 `queries` 长度，各扫一遍。
空间 O(n)，额外开 `diff` 数组（n+1 个元素）。

## 易错点
- 把 `diff[r+1] -= 1` 写成 `diff[r] -= 1`：区间变成 `[l, r-1]`，示例 1 中 `[0,2]` 会让下标 2 的 `cover` 变成 0，`nums[2]=1` 判 `False`，正确答案却是 `True`。右端点必须落在 `r+1`，且数组要开到 `n+1`。
- 把条件写成 `cover == nums[i]`：`nums = [1,0,1]`、`queries = [[0,2]]` 时下标 1 的 `cover=1` 但 `nums[1]=0`，会误判 `False`。覆盖次数是上限，允许浪费，用 `cover < nums[i]` 判失败。

## 如果面试官追问
问：如果要求输出每个查询实际选的下标集合怎么办？
答：先算出 `cover`，再从右往左贪心分配——每个下标最多被减 `nums[i]` 次，优先用靠右的查询覆盖它，倒序扫描查询即可构造。
