## 一句话思路
用长度 26 的数组记下每个字符在 s 中的下标，再扫 t 累加下标差的绝对值。

## 怎么做
1. 建 `pos = [0] * 26`，遍历 `s` 把 `pos[ord(ch) - 97] = i`。
2. 遍历 `t`，对每个 `ch` 取 `j = ord(ch) - 97`，累加 `abs(pos[j] - i)`。
3. 返回累加值。

以 `s = "abc", t = "bac"` 为例：填表后 `pos[0]=0, pos[1]=1, pos[2]=2`；扫 t 时 `i=0` 遇 `'b'` 得 `abs(1-0)=1`，`i=1` 遇 `'a'` 得 `abs(0-1)=1`，`i=2` 遇 `'c'` 得 `abs(2-2)=0`，合计 2。

```python
pos = [0] * 26
for i, ch in enumerate(s):
    pos[ord(ch) - 97] = i
ans = 0
for i, ch in enumerate(t):
    ans += abs(pos[ord(ch) - 97] - i)
return ans
```

关键点：`pos` 存的是「字符 → s 中下标」，扫 t 时下标 `i` 就是该字符在 t 中的位置，两边一减即得。因为 t 是 s 的排列，每个字符在 t 中必出现且只出现一次，`pos` 里不会有未被覆盖的脏值。

## 复杂度
时间：O(n)，两趟线性扫描，n 为字符串长度（≤26）。
空间：O(1)，固定 26 个槽位的 `pos` 数组，与 n 无关。

## 易错点
- 输入 `s = "abc", t = "bac"` 若把 `pos` 建成「字符 → 出现次数」而非下标，`abs` 两边就变成计数相减，全得 0，输出 0 而非 2；正确做法是存下标 `i`，不是存 1。
- 输入含 `'z'` 时若用 `ord(ch) - ord('a')` 之外的偏移（如直接 `ord(ch)`）建 26 长数组会越界；正确做法统一减 97，保证下标落在 0..25。

## 如果面试官追问
若字符集扩到全部 Unicode、n 到 10^5，怎么做？答：改用字典 `pos` 存下标，时间仍 O(n)，空间 O(字符种类数)。
