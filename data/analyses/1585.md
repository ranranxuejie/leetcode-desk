## 一句话思路
对 t 逐位贪心，用 10 个队列存 s 中每个数字的下标，每次取最小的可用下标，并保证它前面没有更小的数字被卡住。

## 怎么做
1. 先比较 s 和 t 的字符计数，不等直接返回 `False`。
2. 建 `pos = [deque() for _ in range(10)]`，把 s 中每个字符的下标压进对应队列。
3. 遍历 t 的每个字符 c，从 `pos[int(c)]` 弹出队首下标 i；若队列空则 `False`。
4. 检查所有比 c 小的数字 d，若 `pos[d]` 非空且 `pos[d][0] < i`，说明 d 被压在 i 后面无法前移，返回 `False`。

以 `s = "84532", t = "34852"` 为例：处理 t[0]='3' 时，`pos[3]` 弹出下标 3；此时 `pos[2][0] = 4 > 3`、`pos[1]` 空，通过。处理 t[1]='4' 时弹出下标 0，`pos[2][0]=4 > 0`，通过。到 t[2]='8' 弹出下标 1，`pos[2][0]=4 > 1` 仍通过，最终返回 `True`。

```python
from collections import deque
pos = [deque() for _ in range(10)]
for i, ch in enumerate(s):
    pos[int(ch)].append(i)
for ch in t:
    c = int(ch)
    if not pos[c]:
        return False
    i = pos[c].popleft()
    for d in range(c):
        if pos[d] and pos[d][0] < i:
            return False
return True
```

## 复杂度
时间 O(10n)：n 为串长，每个字符只弹出一次，内层固定扫 10 个数字。
空间 O(n)：10 个队列合计存 n 个下标。

## 易错点
- 输入 `s="12345", t="12435"`：只查计数会误判 `True`，因为 3 在 s 中下标 2、4 在下标 3，t 要求 4 先于 3，而升序排序只能把小的往前挪。必须做「更小数字是否卡在前面」的下标检查。
- 输入 `s="34521", t="23415"`：若用 `pos[d][0] <= i` 判断会误判 `False`，因为弹出 i 后同一下标已不在队列。正确写法是严格 `<`，且必须在 `popleft()` 之后比较。

## 如果面试官追问
若字符集从 '0'-'9' 扩到任意 ASCII，怎么做？
答：把 10 个队列换成 128 或 256 个桶，内层扫描范围随之变大，时间变 O(σn)，逻辑不变。
