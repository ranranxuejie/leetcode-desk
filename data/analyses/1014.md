## 一句话思路
把 `values[i] + i` 和 `values[j] - j` 拆开，扫到 j 时只需维护前面最大的 `values[i] + i`。

## 怎么做
1. 令 `best = values[0] + 0`，`ans = 0`，从 `j = 1` 开始向右扫。
2. 每个 j 先用 `ans = max(ans, best + values[j] - j)` 结算以 j 为右端点的最优组合。
3. 再用 `best = max(best, values[j] + j)` 把 j 变成未来候选的左端点。
4. 顺序不能反：先结算再更新，否则 j 会和自己配对。

以 `values = [8,1,5,2,6]` 为例：j=1 时 `best=8`，`ans = 8 + 1 - 1 = 8`，随后 `best = max(8, 1+1) = 8`；j=2 时 `ans = 8 + 5 - 2 = 11`，`best = max(8, 5+2) = 8`；j=4 时 `ans = max(11, 8 + 6 - 4) = 11`，最终返回 11。

```python
best = values[0]          # values[i] + i
ans = 0
for j in range(1, len(values)):
    ans = max(ans, best + values[j] - j)
    best = max(best, values[j] + j)
return ans
```

关键点：`best` 里存的是「历史最优左端点」而不是当前 j，所以 `best + values[j] - j` 天然满足 i < j。

## 复杂度
时间 O(n)：一次遍历，每个 j 做两次 max。
空间 O(1)：只开 `best`、`ans` 两个变量。

## 易错点
- 输入 `[1,2]` → 若把更新 `best` 写在结算之前，j=1 时 `best` 已变成 `2+1=3`，算出 `3+2-1=4`，把同一个点用了两次 → 正确做法是先 `ans` 后 `best`。
- 输入 `[2,2,2]` → 若 `ans` 初始化为 0 且误以为答案可能为负，其实本题 values 为正、i<j 时得分至少 `1+1+0-1=1`，但若把 `ans` 初始化成 `values[0]+values[1]-1` 之外的错误值（如 `-2**31`）不会错，真正的坑是漏掉 j=1 这一轮导致 `[1,2]` 返回 0 → 循环必须从 j=1 起且每轮都结算。

## 如果面试官追问
要求输出 i、j 而不是分数？答：结算时若 `best + values[j] - j > ans`，同时记录 `best_idx` 和 `j`，更新 `best` 时同步换 `best_idx`。
