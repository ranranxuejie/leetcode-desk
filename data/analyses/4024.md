## 一句话思路
一次遍历，对每架无人机算曼哈顿距离并判断是否 ≤ range，用严格小于更新最优，从而天然保留最小下标。

## 怎么做
1. 初始化 `best = -1`、`best_dist = 2**31 - 1`，`best_dist` 只用来比较，不参与输出。
2. 用 `enumerate(drones)` 拿到下标 `i` 和 `[x, y, r]`，按下标从小到大扫描。
3. 算 `d = abs(x - tx) + abs(y - ty)`，先判 `d <= r`，不满足直接跳过。
4. 只有 `d < best_dist` 时才更新 `best = i` 和 `best_dist = d`；用严格小于，等距时保留先遇到的小下标。

拿示例 2 走一遍：`target = [5,5]`。`i=0` 时 `d = |2-5| + |1-5| = 7 > 5`，跳过；`i=1` 时 `d = 1 + 1 = 2 <= 5`，更新 `best = 1, best_dist = 2`；`i=2` 时 `d = |6-5| + |6-5| = 2 <= 8`，但 `2 < 2` 为假，不更新，最终返回 `1`。

```python
best, best_dist = -1, 2**31 - 1
tx, ty = target
for i, (x, y, r) in enumerate(drones):
    d = abs(x - tx) + abs(y - ty)
    if d <= r and d < best_dist:
        best, best_dist = i, d
return best
```

注意 `d <= r` 和 `d < best_dist` 是两个独立条件，不能合并成 `d < best_dist` 就更新——那样会把够不着的无人机也选进来。

## 复杂度
时间 O(n)，n 为 `drones.length`，每架只算一次距离。
空间 O(1)，只开了 `best`、`best_dist`、`d` 几个标量。

## 易错点
- 示例 2 这种等距情形：若写成 `d <= best_dist` 更新，`i=2` 会覆盖 `i=1`，返回 2 而非 1。正确做法是严格小于，让先出现的小下标胜出。
- 全都不够时：若把 `best` 初值设成 0 或忘了判 `d <= r`，示例 3（`d=6 > r=5`）会返回 0。正确做法是 `best` 初值 `-1`，且先判可达再比距离。

## 如果面试官追问
若要求返回所有最近可达无人机的下标列表？答：把更新逻辑改成「更近则清空列表并加入 i，等距则 append i」，仍是一趟 O(n)。
