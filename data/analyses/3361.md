## 一句话思路
每个位置独立，用前缀和把「从 x 走到 y 的 26 步代价」压成 O(1) 查询，逐位取 min 累加。

## 怎么做
1. 对 nextCost 和 previousCost 各做一次长度 52 的循环前缀和，`preN[k]` 表示字母 0 走到字母 k 的累计代价（k 从 0 到 26，超过 26 就绕回）。
2. 对每一位，设 `a = ord(s[i]) - 97`、`b = ord(t[i]) - 97`，向后走需要 `(b - a) % 26` 步，向前走需要 `(a - b) % 26` 步。
3. 向后代价 = `preN[a + d] - preN[a]`，向前代价 = `preP[a + 26] - preP[a + 26 - e]`（向前是倒着走，前缀和要反过来减）。
4. 累加 `min(向后, 向前)`。

以示例 1 的 `s[0]='a'`、`t[0]='b'` 为例：`a=0, b=1`，向后 1 步代价 `nextCost[0]=100`；向前 25 步，`previousCost[0]=1` 走一步到 'z'，再走 24 步全是 0，合计 1，取 min 得 1。四位累加正好 2。

```python
preN = [0] * 53
preP = [0] * 53
for k in range(52):
    preN[k + 1] = preN[k] + nextCost[k % 26]
    preP[k + 1] = preP[k] + previousCost[k % 26]

ans = 0
for cs, ct in zip(s, t):
    a, b = ord(cs) - 97, ord(ct) - 97
    d = (b - a) % 26
    e = (a - b) % 26
    fwd = preN[a + d] - preN[a]
    bwd = preP[a + 26] - preP[a + 26 - e]
    ans += min(fwd, bwd)
```

## 复杂度
时间 O(n + 26)，n 是字符串长度，26 是建前缀和的固定开销。
空间 O(26)，只开了两个长度 53 的数组，与 n 无关。

## 易错点
- `s[i] == t[i]` 时 `d = e = 0`，若把向前写成 `preP[a+26] - preP[a]` 就会白算一整圈 26 步的代价；正确做法是减 `preP[a + 26 - e]`，e=0 时差为 0。
- 向前走的区间是 `[a+26-e, a+26)`，写成 `[a-e, a]` 会因 a-e 为负而索引到数组尾部（Python 负索引不报错，静默取错值）；必须整体加 26 偏移。

## 如果面试官追问
问：如果允许一次操作同时改多个下标，代价怎么算？
答：那就退化成每位的 min 代价求和后再乘操作次数约束，需要重新建模成最短路或 DP，不能直接套前缀和。
