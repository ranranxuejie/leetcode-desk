## 一句话思路
用滑动窗口 `[left, right]` 在 s 上扩张找可行解、收缩找最短解，因为「包含 t 全部字符」对窗口是单调的（窗口变大只会更满足）。

## 怎么做
1. 用 `need = Counter(t)` 记需求，`missing = len(t)` 记还差多少个字符（含重复计数）。
2. `right` 右移，把 `s[right]` 计入窗口；若该字符在 `need` 里且计数仍为正，`missing -= 1`。
3. `missing == 0` 时窗口可行，记录长度并尝试 `left` 右移收缩，直到窗口不再可行。
4. 收缩时若移出的字符使某计数变负，说明它是多余副本，`missing` 不变。

以 `s = "ADOBECODEBANC", t = "ABC"` 为例：`right` 走到 5（字符 `C`）时窗口 `"ADOBEC"` 首次 `missing == 0`，长度 6；继续右移到 12（`C`）时窗口收缩到 `"BANC"`，长度 4，即答案。

```python
from collections import Counter
need = Counter(t)
missing, left, best = len(t), 0, (0, len(s) + 1)
for right, ch in enumerate(s):
    if need[ch] > 0:
        missing -= 1
    need[ch] -= 1
    while missing == 0:
        if right - left + 1 < best[1] - best[0]:
            best = (left, right + 1)
        need[s[left]] += 1
        if need[s[left]] > 0:
            missing += 1
        left += 1
return s[best[0]:best[1]] if best[1] <= len(s) else ""
```

## 复杂度
时间 O(n + m)：`right` 和 `left` 各只前进 n 次，m = len(t) 用于建 Counter。
空间 O(k)：k 为 t 中不同字符数，最多 52（英文字母），与 n 无关。

## 易错点
- 输入 `s = "a", t = "aa"` → 若用 `set(t)` 判覆盖，会误判 `"a"` 可行返回 `"a"`；必须用 `Counter` 按重数比较，`missing` 初值取 `len(t)` 而非 `len(set(t))`。
- 收缩时把 `need[s[left]] += 1` 写在判断 `missing` 之前 → 对 `"ADOBEC"` 移出 `A` 时若先加后判，`need['A']` 从 0 变 1 才触发 `missing += 1`，顺序反了会把可行窗口提前判死；正确是先回加计数、再判 `> 0` 才 `missing += 1`。

## 如果面试官追问
问：s 长达 10^7、t 只有小写字母，怎么省内存？
答：把 `Counter` 换成 26 长度的 `list`，`need[ord(ch) - 97]` 直接索引，常数更小且无哈希开销。
