## 一句话思路
给每个字母建一个长度为 26 的票数数组，按「票数向量降序、字母升序」排序即可。

## 怎么做
1. 用 `votes[0]` 收集参赛字母集合，避免把没出现的字母算进去。
2. 建 `cnt = {ch: [0]*m for ch in votes[0]}`，`m = len(votes[0])`，遍历每张票的每个位置 `i` 累加 `cnt[ch][i] += 1`。
3. 排序键取 `(-cnt[ch][0], -cnt[ch][1], ..., ch)`，即票数取负做升序、字母本身做最后一级。
4. 把排好序的字母拼成字符串返回。

以示例 1 的 `votes = ["ABC","ACB","ABC","ACB","ACB"]` 为例，累加后 `cnt["A"] = [5,0,0]`、`cnt["B"] = [0,2,3]`、`cnt["C"] = [0,3,2]`。比较 B 和 C：第 0 位都是 0，第 1 位 2 < 3，所以 C 排在 B 前，结果 `"ACB"`。

```python
m = len(votes[0])
cnt = {ch: [0] * m for ch in votes[0]}
for v in votes:
    for i, ch in enumerate(v):
        cnt[ch][i] += 1

def key(ch):
    return tuple(-x for x in cnt[ch]) + (ch,)

return "".join(sorted(cnt, key=key))
```

关键点：`tuple(-x for x in cnt[ch])` 把「票数多者优先」翻译成 Python 的升序排序；末尾拼上 `ch` 让完全并列时按字母升序，正好对上题目最后一条规则。

## 复杂度
时间 O(n·m + k·m·log k)，n 是票数、m 是队伍数、k 是参赛队伍数，排序比较每次看 m 个计数。
空间 O(k·m)，就是 `cnt` 这张表，没有别的额外结构。

## 易错点
- 用 `votes[0]` 之外的字母建表 → 若某字母只在 `votes[0]` 出现（题面保证不会，但改约束后可能），会漏队或多数出空队 → 始终以 `votes[0]` 的字符集为准。
- 排序键只写票数不拼字母 → 示例 2 中若 W 和 X 所有位票数都相同，`sorted` 会保留字典插入顺序而非字母序 → 键末尾必须加 `(ch,)`，让 `"W"` 和 `"X"` 由字母决定。

## 如果面试官追问
若票数规模涨到 10^6、队伍数仍是 26，怎么优化？答：计数阶段不变仍是 O(n·m)，排序只有 26 个元素可忽略，瓶颈在遍历票，无法再降。
