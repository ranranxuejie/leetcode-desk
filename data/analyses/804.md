## 一句话思路
把每个单词映射成摩尔斯串后丢进 `set`，集合大小即答案，因为「不同翻译」就是去重。

## 怎么做
1. 建 26 字母到摩尔斯串的映射表 `MORSE`，下标用 `ord(ch) - ord('a')`。
2. 对 `words` 中每个单词，逐字符查表并拼接成完整串。
3. 把拼接结果加入 `set`，重复的自动被吞掉。
4. 返回 `len(set)`。

以 `words = ["gin", "zen", "gig", "msg"]` 为例，关键中间值是 `"gin"` 和 `"zen"` 都拼出 `"--...-."`，`"gig"` 和 `"msg"` 都拼出 `"--...--."`，所以集合只剩 2 个元素。

```python
MORSE = [".-","-...","-.-.","-..",".","..-.","--.","....","..",".---",
         "-.-",".-..","--","-.","---",".--.","--.-",".-.","...","-",
         "..-","...-",".--","-..-","-.--","--.."]

seen = set()
for w in words:
    code = "".join(MORSE[ord(ch) - ord('a')] for ch in w)
    seen.add(code)
return len(seen)
```

拼接用 `"".join(...)` 而不是循环 `+=`，单词长度最多 12，差别不大但写法更干净。

## 复杂度
时间 O(n·L)，n 是 `words` 长度，L 是单词平均长度，每个字符查表一次。
空间 O(n·L)，`set` 最多存 n 个长度约 4L 的串。

## 易错点
1. 映射表下标写错：若用 `ord(ch) - 96` 得到 1..26，再取 `MORSE[...]` 会整体偏移一位，`"a"` 会取到 `"-..."` 而不是 `".-"`，示例 2 仍返回 1 但示例 1 的 `"gin"` 就拼错了。正确做法是 `ord(ch) - ord('a')` 得到 0..25。
2. 用 `list` 存结果再 `len(set(...))` 或手动 `if code not in list` 判断：`words` 有 100 个元素时 `in list` 是 O(n) 线性扫描，整体退化成 O(n²·L)。正确做法是直接 `seen.add(code)`，哈希 O(1)。

## 如果面试官追问
问：如果 `words` 规模到 10^6、单词长度到 10^3，怎么优化？
答：瓶颈在拼接出的长串占内存，可对每个单词的摩尔斯串做哈希（如 `hash(code)` 或滚动哈希）只存指纹，代价是理论上有碰撞风险。
