## 一句话思路
排序后只改中位数下标及其右侧偏小、左侧偏大的元素，逐位累加差值即为最少操作数。

## 怎么做
1. 先对 `nums` 排序，偶数长度取较大中间值，所以中位数下标固定为 `mid = len(nums) // 2`。
2. 若 `nums[mid] < k`，从 `mid` 向右扫，遇到小于 `k` 的元素就补到 `k`，累加 `k - nums[i]`。
3. 若 `nums[mid] > k`，从 `mid` 向左扫，遇到大于 `k` 的元素就压到 `k`，累加 `nums[i] - k`。
4. 相等直接返回 0。

以示例 2 为例：`nums = [2,5,6,8,5]` 排序得 `[2,5,5,6,8]`，`mid = 2`，`nums[2] = 5 < 7`。向右扫：`i=2` 补 `7-5=2`，`i=3` 的 6 补 `7-6=1`，`i=4` 的 8 已 ≥7 停止，合计 3。

```python
nums.sort()
mid = len(nums) // 2
ans = 0
if nums[mid] < k:
    for i in range(mid, len(nums)):
        if nums[i] < k:
            ans += k - nums[i]
else:
    for i in range(mid, -1, -1):
        if nums[i] > k:
            ans += nums[i] - k
return ans
```

关键点：右侧元素一旦 ≥ k 就停，因为排序后它们不会再影响中位数；左侧同理，一旦 ≤ k 就停。

## 复杂度
时间：排序 O(n log n)，扫描 O(n)，n 为数组长度。
空间：排序额外 O(log n) 栈空间，其余 O(1)。

## 易错点
- 偶数长度取中间两个的**较大值**：`nums = [1,2,3,4]` 若误取 `mid = (n-1)//2 = 1`，会把中位数当 2，实际应为下标 2 的 3，答案全错。正确用 `mid = n // 2`。
- 扫描时忘记提前终止：`nums = [1,2,3,100,100]`、`k = 2`，若从 `mid` 向左无脑累加所有大于 k 的元素，会把 100 也算进去。正确做法是遇到 `nums[i] <= k` 立即停，因为排序后更左侧只会更小。

## 如果面试官追问
问：如果要求输出操作后的数组而非次数？
答：把累加改成赋值 `nums[i] = k`，返回修改后的 `nums` 即可，扫描逻辑不变。
