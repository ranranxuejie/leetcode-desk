## 一句话思路
排序后按绝对值从小到大贪心配对：每个数只能和它的 2 倍或一半配，先处理绝对值小的，用哈希表记剩余个数。

## 怎么做
1. 用 `Counter(arr)` 统计每个值的剩余次数，键是 `arr` 里的具体值。
2. 按 `abs(x)` 升序排序所有键，保证处理 `x` 时它的配对对象还没被消耗。
3. 对每个键 `x`，若 `cnt[x] > 0`，则必须消耗 `cnt[x]` 个 `2*x`；`cnt[2*x]` 不足就返回 `False`，否则两边同时扣减。
4. 全部键处理完返回 `True`。

以 `arr = [4,-2,2,-4]` 为例：`cnt = {4:1,-2:1,2:1,-4:1}`，按绝对值排序得 `[-2,2,-4,4]`。处理 `-2` 时 `cnt[-2]=1`，需要 `cnt[-4]>=1`，扣减后 `cnt[-2]=0, cnt[-4]=0`；处理 `2` 时同理消耗 `4`，最终全为 0，返回 `True`。

```python
from collections import Counter

def canReorderDoubled(arr):
    cnt = Counter(arr)
    for x in sorted(cnt, key=abs):
        if cnt[x] == 0:
            continue
        if cnt[2 * x] < cnt[x]:
            return False
        cnt[2 * x] -= cnt[x]
        cnt[x] = 0
    return True
```

关键点：`cnt[x] = 0` 而非删除键，避免后续 `cnt[2*x]` 访问时 KeyError；`cnt[2*x]` 不存在时 `Counter` 返回 0，正好触发 `False`。

## 复杂度
时间：排序 `O(k log k)`，k 为不同值个数，遍历 `O(k)`，总计 `O(n + k log k)`。
空间：`Counter` 存 k 个键值对，`O(k)`，排序额外 `O(k)`。

## 易错点
- 输入 `[2,1,2,6]` → 若只按数值升序处理，`1` 会先找 `2` 配对成功，剩下 `2` 和 `6` 无法配对，误判为 `True` 或漏判。正确做法是按 `abs` 排序，负数先处理 `-2` 再处理 `-4`，保证配对方向一致。
- 输入 `[0,0]` → `2*0 = 0`，若写成 `cnt[2*x] -= cnt[x]` 后没把 `cnt[x]` 置 0，会重复消耗同一个 0 导致误判。正确做法是扣减后立即 `cnt[x] = 0`，且 `0` 的配对对象就是自己，`cnt[0]` 为偶数即可。

## 如果面试官追问
问：如果要求输出具体分组方案而非布尔值？
答：在扣减时把 `x` 和 `2*x` 成对 append 到结果列表，每对消耗 `cnt[x]` 次，最后返回列表即可。
