## 一句话思路
用一个 `val` 变量从 `init` 出发，按下标顺序把 `nums[i]` 逐个喂给 `fn` 覆盖更新，循环结束即答案。

## 怎么做
1. 令 `val = init`，这是累加器的唯一载体。
2. 用 `for i in range(len(nums))` 按下标遍历，不用 `Array.reduce`。
3. 每轮执行 `val = fn(val, nums[i])`，把上一轮结果和当前元素一起交给 `fn`。
4. 循环结束后直接返回 `val`；`nums` 为空时循环体一次不执行，自然返回 `init`。

以示例 2 的 `nums = [1,2,3,4]`、`init = 100` 为例，关键中间值是第 3 轮：进入时 `val = 105`，`nums[2] = 3`，`fn(105, 3) = 105 + 9 = 114`，下一轮再拿 `114` 去配 `nums[3] = 4` 得 `130`。注意 `fn` 的第二个参数是元素本身，平方是在 `fn` 内部做的，循环里不要自己先平方。

```python
val = init
for i in range(len(nums)):
    val = fn(val, nums[i])
return val
```

空数组的路径不需要额外 `if`：`range(0)` 直接跳过，`val` 保持 `init`，与示例 3 的 `25` 一致。

## 复杂度
时间：O(n)，n 为 `nums` 长度，每轮一次 `fn` 调用，`fn` 本身视为 O(1)。
空间：O(1)，只开 `val` 和循环下标 `i`，没有额外数组。

## 易错点
- `nums = []` 且 `init = 25` → 若写成先取 `nums[0]` 再循环，会抛索引越界 → 正确做法是让 `val` 从 `init` 起步、循环从下标 0 开始，空数组自然返回 `init`。
- `fn = function sum(accum, curr) { return accum + curr * curr; }`、`init = 100` → 若把 `fn` 的参数顺序写成 `fn(nums[i], val)`，示例 2 会算成 `1 + 100*100` 之类的错值 → 正确做法是严格 `fn(累加值, 当前元素)`，即 `fn(val, nums[i])`。

## 如果面试官追问
问：若 `fn` 不是纯函数、会修改外部状态，结果还稳定吗？
答：稳定，因为调用顺序被 `for i in range(len(nums))` 固定为下标递增，与题面规定的执行次序一致。
