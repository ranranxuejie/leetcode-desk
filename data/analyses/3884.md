## 一句话思路
从 i=0 起用双指针向中间扫，首次命中 `s[i] == s[n-1-i]` 就返回 i，因为下标递增保证最小。

## 怎么做
1. 令 `n = len(s)`，`i` 从 0 开始，`j = n - 1 - i` 同步收缩。
2. 每轮比较 `s[i]` 与 `s[j]`，相等立即 `return i`。
3. 循环条件写 `i <= j`，让 i 与 j 相遇（奇数长度中点）时仍能比较一次。
4. 循环走完没命中，`return -1`。

以 `s = "abcacbd"`（n=7）为例：i=0 时 j=6，`s[0]='a'` 与 `s[6]='d'` 不等；i=1 时 j=5，`s[1]='b'` 与 `s[5]='b'` 相等，返回 1。再看 `s = "abc"`（n=3）：i=0 比 `'a'` 与 `'c'` 不等；i=1 时 j=1，`s[1]` 与自身比较必相等，返回 1——这就是「中点自比」的情形。

```python
n = len(s)
i, j = 0, n - 1
while i <= j:
    if s[i] == s[j]:
        return i
    i += 1
    j -= 1
return -1
```

关键在 `i <= j` 而非 `i < j`：若写成 `i < j`，`"abc"` 会在 i=1、j=1 时退出循环，错误返回 -1。

## 复杂度
时间 O(n)：最坏扫到中点，比较次数约 n/2，由字符串长度贡献。
空间 O(1)：只开 i、j 两个整型变量，未复制字符串。

## 易错点
- 输入 `"abc"` 这类奇数长度串 → 循环条件写成 `i < j` 会跳过中点自比，错返回 -1 → 必须用 `i <= j`，让 i==j 时也进一次比较。
- 输入 `"abcdab"` → 若把 `j` 写成 `n - i`（漏减 1）会越界或错位比较，把 `s[0]` 和 `s[6]` 比（越界）→ 镜像下标固定为 `n - 1 - i`，i=0 时 j=5，`'a'` 与 `'b'` 不等，正确返回 -1。

## 如果面试官追问
若要求返回所有满足条件的下标而非最小一个？答：去掉提前 return，命中时 append 到结果列表，继续收缩到 `i > j`，时间仍是 O(n)。
