## 一句话思路
后缀排序结果只由「值降序、同值按下标升序」决定，故可把每个 i 的排序结果哈希成定长指纹，再对 target 做滑窗匹配。

## 怎么做
1. 对 nums 建后缀数组：按 (值降序, 下标升序) 排序所有后缀起点，得到 rank 数组。
2. 每个 i 的排序结果 = 后缀内元素按 rank 升序排列，用双哈希前缀和算出长度 n 的指纹。
3. 对 target 每个长度 n 的窗口算同样的指纹，与 i 的指纹比对计数。

以示例 1 为例：nums=[2,2,3]，后缀起点 0/1/2 排序后分别是 [3,2,2]、[2,3,2]、[2,2,3]。i=2 的指纹与 target[0..2]=[2,2,3] 相同，故 ans[0]=1；i=1 匹配 target[1..3]=[2,3,2]，ans[1]=1；i=0 匹配 target[5..7]=[3,2,2]，ans[5]=1。

```python
# 伪代码：双哈希指纹
def fp(seq):  # seq 为已排序的值序列
    h1 = h2 = 0
    for x in seq:
        h1 = (h1 * B1 + x) % M1
        h2 = (h2 * B2 + x) % M2
    return (h1, h2)

# 对每个 i，取 nums[i:] 按 (值降序, 下标升序) 排序后的前 n 个值
# 实际用后缀数组 + 树状数组/线段树维护 rank 前缀和，O(n log n)
```

关键中间值：i=2 时排序序列 [2,2,3]，指纹 (h1,h2)；target 窗口 k=0 的 [2,2,3] 指纹相同，计数 +1。

## 复杂度
时间：O((n+m) log n)，后缀数组与滑窗各贡献一次排序/哈希。
空间：O(n+m)，存 rank、前缀哈希与答案数组。

## 易错点
- nums 有重复值（如 [2,2,3]）时，若只按值排序会丢失下标信息，导致 i=1 与 i=2 的排序结果混淆；必须用 (值降序, 下标升序) 作为比较键。
- target 窗口跨过 n 边界时（如示例 1 的 k=5），若直接截取 target[k..k+n-1] 会越界；需先判断 k+n<=m 再计算指纹，否则 ans[k] 应为 0。

## 如果面试官追问
若 n 接近 m 且要求输出所有匹配的 i 列表而非计数，怎么办？
答：把指纹换成「排序后序列的滚动哈希 + 起点映射」，用字典存每个指纹对应的 i 集合，查询时直接取集合大小。
