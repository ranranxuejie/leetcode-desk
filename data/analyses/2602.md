## 一句话思路
排序 nums 后前缀和 + 二分定位 queries[i] 的插入点，把数组拆成「小于目标」和「大于目标」两段分别算距离和。

## 怎么做
1. 对 nums 排序，求前缀和 `pre`，`pre[k]` 表示前 k 个元素之和。
2. 对每个 q，用 `bisect_left(nums, q)` 得到下标 `i`：`nums[0..i-1] < q`，`nums[i..n-1] >= q`。
3. 左侧代价 `q*i - pre[i]`，右侧代价 `(pre[n]-pre[i]) - q*(n-i)`，两者相加即答案。
4. 以 `nums=[3,1,6,8]` 排序成 `[1,3,6,8]`、`pre=[0,1,4,10,18]` 为例：q=5 时 `i=2`，左侧 `5*2-4=6`，右侧 `(18-4)-5*2=4`，合计 10，与示例一致。

```python
from bisect import bisect_left

nums.sort()
n = len(nums)
pre = [0] * (n + 1)
for k, v in enumerate(nums):
    pre[k + 1] = pre[k] + v

ans = []
for q in queries:
    i = bisect_left(nums, q)
    left = q * i - pre[i]
    right = (pre[n] - pre[i]) - q * (n - i)
    ans.append(left + right)
```

## 复杂度
时间：排序 O(n log n)，每个查询二分 O(log n)，共 O((n+m) log n)。
空间：前缀和数组 O(n)，答案数组 O(m)。

## 易错点
- `nums` 含重复值且等于 q 时，`bisect_left` 会把它们划到右侧，此时 `q*(n-i)` 与 `pre[n]-pre[i]` 中这些元素贡献恰好抵消为 0；若误用 `bisect_right`，左侧多算一段 `q*i-pre[i]` 仍为 0，但下标偏移会让后续 `pre[i]` 取错，务必统一用 `bisect_left`。
- q 大于 `nums` 全部元素时 `i=n`，右侧项 `(pre[n]-pre[n]) - q*0 = 0`，左侧 `q*n-pre[n]` 正常；若把右侧写成 `pre[n]-pre[i]-q*(n-i)` 而漏括号，会得到 `pre[n]-pre[i]-q*n+q*i` 的错误符号，示例 2 中 q=10 会算出负数。

## 如果面试官追问
若 queries 也达到 1e5 且要求在线回答、nums 动态修改怎么办？答：改用有序容器（如平衡树/树状数组维护计数与和），单次查询仍是 O(log n)。
