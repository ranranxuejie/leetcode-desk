## 一句话思路
每种 cuisine 挂一个堆，堆元素是 `(-rating, food)`，changeRating 时懒删除旧条目，取堆顶前校验评分是否过期。

## 怎么做
1. 建三个字典：`food_cuisine[food]`、`food_rating[food]`、`heaps[cuisine]` 存 `(-rating, food)` 元组。
2. 初始化时把每个食物按 `(-ratings[i], foods[i])` 压进对应 cuisine 的堆。
3. `changeRating` 只更新 `food_rating[food]`，并把新元组压入堆，旧条目留在堆里不删。
4. `highestRated` 循环弹堆顶，直到 `-neg == food_rating[food]` 且 cuisine 匹配，返回该 food。

以官方示例为例：`changeRating("sushi", 16)` 后，japanese 堆里同时存在 `(-8,"sushi")` 和 `(-16,"sushi")`。再 `changeRating("ramen", 16)`，堆顶是 `(-16,"ramen")`，校验 `food_rating["ramen"]==16` 通过，返回 `"ramen"`；若堆顶是 `(-16,"sushi")`，因 `"ramen" < "sushi"`，元组比较自动让 ramen 排前。

```python
import heapq

def change_rating(food, new_rating):
    food_rating[food] = new_rating
    heapq.heappush(heaps[food_cuisine[food]], (-new_rating, food))

def highest_rated(cuisine):
    h = heaps[cuisine]
    while -h[0][0] != food_rating[h[0][1]]:
        heapq.heappop(h)
    return h[0][1]
```

关键点：元组 `(-rating, food)` 的字典序比较天然满足「评分高优先、同分名字小优先」，不需要自定义比较器。

## 复杂度
时间：初始化 O(n log n)，每次 changeRating O(log n)，highestRated 均摊 O(log n)（每个旧条目最多被弹一次）。
空间：O(n + m)，n 个食物条目 + m 次 changeRating 产生的过期条目。

## 易错点
1. 只更新 `food_rating` 却不压新堆条目 → `changeRating("sushi",16)` 后 highestRated(“japanese”) 仍返回 `"ramen"`（旧堆顶 `(-14,"ramen")` 未失效）。正确做法是每次 changeRating 必须 push 新元组。
2. 校验条件写成 `-h[0][0] == food_rating[h[0][1]]` 但漏了 cuisine 归属检查 → 若某食物被误判，可能返回别的菜系食物。本题 food 的 cuisine 不变，但校验时仍应确认 `food_cuisine[h[0][1]] == cuisine`，否则跨菜系同名评分巧合会误返回。

## 如果面试官追问
问：若 changeRating 调用达 10^6 次，堆会膨胀怎么办？
答：改用 `sortedcontainers.SortedList` 或平衡树，changeRating 时先删旧条目再插新条目，空间稳定 O(n)。
