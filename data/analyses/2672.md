## 一句话思路
维护当前相同相邻对总数 `ans`，每次改色只重算 `index` 与左右邻居的两条边，增量更新。

## 怎么做
1. 开 `colors = [0]*n` 和 `res = []`，`ans = 0`。
2. 每次查询先减去 `index` 与左右邻居原有的贡献，再改色，再加回新贡献。
3. 把 `ans` 追加进 `res`。

以示例 1 第 4 次查询 `[1,1]` 为例：改色前 `colors = [2,2,0,1]`，`index=1` 左邻居 `colors[0]=2` 相等贡献 1，右邻居 `colors[2]=0` 不等贡献 0，先 `ans -= 1` 得 0；改色后 `colors = [2,1,0,1]`，左 2≠1、右 0≠1，都不贡献，`ans` 仍为 0，与输出第 4 项一致。

```python
colors = [0] * n
ans = 0
res = []
for idx, c in queries:
    if idx > 0 and colors[idx] == colors[idx - 1]:
        ans -= 1
    if idx + 1 < n and colors[idx] == colors[idx + 1]:
        ans -= 1
    colors[idx] = c
    if idx > 0 and colors[idx] == colors[idx - 1]:
        ans += 1
    if idx + 1 < n and colors[idx] == colors[idx + 1]:
        ans += 1
    res.append(ans)
```

## 复杂度
时间：O(n + q)，初始化 `colors` 花 O(n)，每个查询只碰 2 条边。
空间：O(n)，只额外开了 `colors` 数组和长度 q 的 `res`。

## 易错点
- 边界下标 `idx=0` 或 `idx=n-1` → 若直接访问 `colors[idx-1]` 会取到 `colors[-1]`（Python 负索引绕到末尾）或越界 → 必须先判 `idx > 0` 和 `idx + 1 < n` 再比较。
- 同一位置被重复染色（示例 1 的 `index=1` 被染两次）→ 若只加新贡献不减旧贡献，`ans` 会虚高 → 必须「先减旧边、再改色、再加新边」，顺序不能颠倒。

## 如果面试官追问
若要求返回每次查询后所有相同相邻对的**具体下标**？答：增量维护一个集合，减边时 `discard`、加边时 `add`，输出时转列表即可。
