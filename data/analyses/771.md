## 一句话思路
把 `jewels` 的字符塞进 `set`，再遍历 `stones` 逐个查表计数，查表 O(1) 所以整体线性。

## 怎么做
1. 用 `set(jewels)` 建宝石集合，`jewels` 字符唯一，集合大小就是宝石类型数。
2. 初始化 `count = 0`，遍历 `stones` 的每个字符 `c`。
3. `c in jewel_set` 成立就 `count += 1`，不成立跳过。
4. 返回 `count`。

拿示例 1 走一遍：`jewels = "aA"`，`jewel_set = {'a', 'A'}`。遍历 `stones = "aAAbbbb"`，前三个字符 `'a'`、`'A'`、`'A'` 都在集合里，`count` 依次变成 1、2、3；后四个 `'b'` 都不在，`count` 停在 3。

```python
jewel_set = set(jewels)
count = 0
for c in stones:
    if c in jewel_set:
        count += 1
return count
```

也可以写成一行生成器：`sum(c in jewel_set for c in stones)`，`True` 当 1 累加，结果一样。但显式循环在面试里更好讲，也方便加提前退出之类的改动。

为什么不用 `stones.count(j)` 对每个 `j` 求和？那样是 O(len(jewels) × len(stones))，本题 50×50 也能过，但思路是「对每个宝石类型扫一遍石头」，跟哈希表的意图相反，面试官会追问为什么不用集合。

## 复杂度
时间 O(len(jewels) + len(stones))，建集合扫一遍 jewels，再扫一遍 stones。
空间 O(len(jewels))，额外开的是宝石集合，最多 52 个字符。

## 易错点
1. `jewels = "aA", stones = "aAAbbbb"` 如果写成 `jewels.lower()` 或统一大小写再比较，`'A'` 会被当成 `'a'`，示例 1 仍得 3 看不出错；但 `jewels = "a", stones = "A"` 会错答 1，正确是 0。字母区分大小写，集合里原样存，不做任何转换。
2. `jewels = "z", stones = "ZZ"` 若用 `stones.count(jewels)` 或 `jewels in stones` 这类子串判断，会把「整串包含」当成「字符包含」，示例 2 得 0 碰巧对，但 `jewels = "ab", stones = "aXb"` 会错答 0（子串 `"ab"` 不在），正确是 2。必须按单字符 `in` 集合判断。

## 如果面试官追问
问：如果 `stones` 长到 10**7 且流式输入、不能全存？
答：仍用 `set(jewels)`，边读边 `count += (c in jewel_set)`，空间只跟宝石类型数走，与 `stones` 长度无关。
