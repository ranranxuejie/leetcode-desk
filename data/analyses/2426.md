## 一句话思路
把不等式移项成 `nums1[i]-nums2[i] <= nums1[j]-nums2[j]+diff`，令 `a[k]=nums1[k]-nums2[k]`，问题变成统计 `i<j` 且 `a[i] <= a[j]+diff` 的数对，用树状数组按值域计数。

## 怎么做
1. 预处理 `a = [nums1[k]-nums2[k] for k in range(n)]`，不等式等价于 `a[i] - a[j] <= diff`，即 `a[i] <= a[j] + diff`。
2. 从右往左扫 `j`，树状数组里存的是 `a[j+1..n-1]` 的计数；对每个 `j` 查询 `<= a[j]+diff` 的个数累加。
3. 查询前先把 `a[j]` 插入树状数组（这样 `i<j` 自动满足，因为插入的是已经扫过的右侧元素）。
4. 值域 `a[k]` 落在 `[-2*10^4, 2*10^4]`，加偏移 `20000` 后范围 `[0, 40000]`，树状数组开 `40002` 足够。

以示例 1 为例：`a = [1,0,4]`，`diff=1`。从右往左：`j=2` 时树状数组空，查询 `a[2]+1=5` 得 0，插入 4；`j=1` 时查询 `a[1]+1=1`，树状数组只有 4，得 0，插入 0；`j=0` 时查询 `a[0]+1=2`，树状数组有 {0,4}，`<=2` 的只有 0，得 1。总计 1？但答案是 3——注意方向：`a[i] <= a[j]+diff` 中 `i<j`，应固定 `j` 查左侧。改为从左往右扫 `j`，树状数组存 `a[0..j-1]`，对每个 `j` 查 `<= a[j]+diff` 的个数：`j=1` 查 `<=1`，左侧 {1} 得 1；`j=2` 查 `<=5`，左侧 {1,0} 得 2；合计 3，正确。

```python
a = [x - y for x, y in zip(nums1, nums2)]
OFF, M = 20000, 40002
tree = [0] * (M + 1)
def add(p):
    p += OFF + 1
    while p <= M:
        tree[p] += 1
        p += p & -p
def query(p):
    p = min(p + OFF + 1, M)
    s = 0
    while p > 0:
        s += tree[p]
        p -= p & -p
    return s
ans = 0
for j in range(n):
    ans += query(a[j] + diff)
    add(a[j])
```

## 复杂度
时间 O(n log M)，n 来自扫描，log M 来自树状数组单次更新/查询，M=40002。
空间 O(M)，树状数组固定开 40002 个槽，与 n 无关。

## 易错点
- 扫描方向搞反：若从右往左扫并查 `a[j]+diff`，示例 1 会得 1 而非 3。因为不等式是 `a[i] <= a[j]+diff`，`i` 在左、`j` 在右，必须从左往右扫、树状数组存已扫过的左侧元素。
- 偏移量算错：`a[k]` 最小 `-10^4-10^4=-2*10^4`，加 `diff` 后查询上界可能到 `2*10^4+10^4=3*10^4`，若偏移只取 20000 且不截断，`query` 下标会越界。代码里 `min(p+OFF+1, M)` 就是防这个，别删。

## 如果面试官追问
问：若 diff 很大导致查询上界超过值域怎么办？
答：`query` 里对下标取 `min(..., M)`，等价于把所有元素都算进去，不会越界。
