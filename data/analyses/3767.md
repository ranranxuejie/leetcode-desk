## 一句话思路
先全部按技巧 2 拿分，再按 `technique1[i] - technique2[i]` 从大到小挑 k 个换成技巧 1，之后只换增益为正的。

## 怎么做
1. 令 `base = sum(technique2)`，即所有任务都用技巧 2 的总分。
2. 计算每个任务的换法增益 `d[i] = technique1[i] - technique2[i]`，按 `d` 降序排序。
3. 前 `k` 个必须换成技巧 1（哪怕 `d` 为负），累加 `d`；第 `k` 个之后只累加正的 `d`。
4. 返回 `base + 累加的 d`。

以示例 1 为例：`technique1 = [5,2,10]`，`technique2 = [10,3,8]`，`k = 2`。`base = 10+3+8 = 21`，`d = [-5,-1,2]`，降序为 `[2,-1,-5]`。前 2 个强制换：`2 + (-1) = 1`，第三个 `-5` 不换。结果 `21 + 1 = 22`，与官方一致。

```python
base = sum(technique2)
d = sorted((a - b for a, b in zip(technique1, technique2)), reverse=True)
ans = base
for i, x in enumerate(d):
    if i < k or x > 0:
        ans += x
return ans
```

关键点：排序后前 `k` 个是「最值得换」的，但 `k` 是下限不是上限，所以第 `k` 位之后只要 `x > 0` 就继续换，这样不会漏掉「技巧 1 反而更高」的任务。

## 复杂度
时间：排序 `O(n log n)`，`n` 为任务数，遍历 `O(n)`。
空间：`d` 数组 `O(n)`，排序额外栈空间 `O(log n)`。

## 易错点
- `k = n` 且所有 `d` 都为负（如 `technique1=[1,1]`、`technique2=[9,9]`、`k=2`）→ 若写成「只换正的」会少换，答案偏大 → 必须无条件换满前 `k` 个，即使增益为负。
- `k = 0` 且存在 `d > 0`（如示例 3 的 `d = [-3,-3,-3]` 全负没事，但若 `technique1=[9,9]`、`technique2=[1,1]`、`k=0`）→ 若只按「前 k 个」处理会漏掉正增益，答案偏小 → 第 0 位起就要判断 `x > 0`。

## 如果面试官追问
问：如果要求输出具体哪些任务用技巧 1 怎么办？
答：排序时保留原下标，前 `k` 个和后续 `x > 0` 的下标即为答案，逻辑不变。
