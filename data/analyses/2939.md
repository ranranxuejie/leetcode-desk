## 一句话思路
按位从高到低贪心：某一位 a、b 相同则 x 取反使两数都得 1，不同则把 1 补给当前较小的那个。

## 怎么做
1. 从第 n-1 位往下扫，维护 `A = a ^ x`、`B = b ^ x` 的当前值（初始为 a、b）。
2. 若 a、b 该位相同：x 该位取 1，A、B 该位都变 1，两数同时变大，必选。
3. 若该位不同：x 该位取 0 则 A、B 该位保持原样，取 1 则互换；两种选法两数之和不变，把 1 给较小的那个，乘积更大。
4. 用示例 1（a=12=1100, b=5=0101, n=4）走一遍：第 3 位 1/0 不同，A=12>B=5，x 该位取 1 让 B 得 1，此时 A=4、B=13；第 2 位 1/1 相同，x 取 1，A=6、B=15；第 1 位 0/0 相同，x 取 1，A=6、B=15 不变（该位本就 0→1 后 A=6、B=15）；第 0 位 0/1 不同，A<B，x 取 1 让 A 得 1，A=7、B=14，乘积 98。

```python
MOD = 10**9 + 7
A, B = a, b
for i in range(n - 1, -1, -1):
    bit = 1 << i
    if (a >> i) & 1 == (b >> i) & 1:
        A |= bit
        B |= bit
    elif A < B:
        A |= bit
    else:
        B |= bit
return (A % MOD) * (B % MOD) % MOD
```

注意 `A |= bit` 只在原该位为 0 时有效；若原该位已是 1，说明 x 该位取 0，等价。

## 复杂度
时间 O(n)，n ≤ 50，逐位扫描一次。
空间 O(1)，只存 A、B 两个大整数。

## 易错点
- 第 3 位不同时若直接按「a 大就给 b」判断，会错：示例 1 中 a=12>b=5，但第 0 位时 A=6<B=15，必须比较**当前** A、B 而非原始 a、b，否则得 84 而非 98。
- 取模时机：A、B 可达 2^50 量级，先乘再取模在 Python 里没问题，但若中途对 A、B 单独取模再比较大小会破坏贪心判断，必须全程用未取模的 A、B 比较，只在最后 `(A % MOD) * (B % MOD) % MOD`。

## 如果面试官追问
若 n 扩大到 10^5 且 a、b 也超大，怎么做？答：贪心逻辑不变，仍逐位扫，只是大整数位运算成本上升，总代价 O(n^2/word) 级别。
