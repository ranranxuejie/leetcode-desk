## 一句话思路
答案的可行性随能力值单调，二分能力值，用贪心从左往右数最多能偷几间来判定。

## 怎么做
1. 二分的下界取 `min(nums)`，上界取 `max(nums)`，因为能力值必是某个 `nums[i]`。
2. 判定函数 `can(cap)`：从左往右扫，遇到 `nums[i] <= cap` 就偷下并跳过下一间，计数加一。
3. 计数 `>= k` 就说明 `cap` 可行，收缩右边界；否则放大左边界。
4. 返回收敛后的左边界。

以 `nums = [2,3,5,9], k = 2` 为例，二分到 `cap = 5`：扫到 `nums[0]=2<=5` 偷下，跳过 `nums[1]`；`nums[2]=5<=5` 偷下，计数 `cnt=2 >= k`，可行。而 `cap = 3` 时只能偷到 `nums[0]`，`cnt=1 < 2`，不可行，所以答案是 5。

```python
lo, hi = min(nums), max(nums)
while lo < hi:
    mid = (lo + hi) // 2
    cnt, i = 0, 0
    while i < len(nums):
        if nums[i] <= mid:
            cnt += 1
            i += 2
        else:
            i += 1
    if cnt >= k:
        hi = mid
    else:
        lo = mid + 1
return lo
```

贪心为什么对：在「不能相邻」的约束下，从左往右能偷就偷，得到的计数是 `cap` 限制下的最大值，所以 `cnt >= k` 与「存在合法方案」等价。

## 复杂度
时间 `O(n log(max-min))`：`n` 来自每次判定扫描 `nums`，`log` 来自二分值域。
空间 `O(1)`：只用了 `lo/hi/mid/cnt/i` 几个变量。

## 易错点
- 判定里写成 `i += 1` 而不是 `i += 2`：`nums = [2,3,5,9], cap = 5` 时会数出 `2,3,5` 三间，把相邻的 `2` 和 `3` 同时算进去，`cnt` 虚高导致答案偏小。偷下 `nums[i]` 后必须 `i += 2` 跳过相邻那间。
- 二分写成 `lo = mid` 且 `hi = mid - 1` 的混搭，或返回 `hi` 前没处理 `lo == hi`：`nums = [2,7,9,3,1], k = 2` 时区间可能卡在 `lo=1, hi=2` 死循环。统一用 `lo < hi` 配 `hi = mid` / `lo = mid + 1`，最后返回 `lo`。

## 如果面试官追问
问：要求输出具体偷哪几间怎么办？
答：二分定下 `cap` 后，再跑一遍同样的贪心，把 `nums[i] <= cap` 的下标收集起来即可，仍是 `O(n)`。
