## 一句话思路
逐个数拆位取模判断，范围只有 10^4，直接暴力枚举每个数即可。

## 怎么做
1. 外层遍历 `x` 从 `left` 到 `right`，对每个 `x` 单独判定。
2. 内层用 `t = x` 反复取 `t % 10` 得到当前最低位 `d`，再 `t //= 10` 右移。
3. 遇到 `d == 0` 立即判 `x` 不合格（自除数不含 0，且 0 不能做除数）；遇到 `x % d != 0` 也立即不合格。
4. 全部位都通过才把 `x` 追加进结果列表。

以 `x = 128` 为例：第一轮 `d = 8`，`128 % 8 == 0`，`t` 变 `12`；第二轮 `d = 2`，`128 % 2 == 0`，`t` 变 `1`；第三轮 `d = 1`，`128 % 1 == 0`，`t` 变 `0`，循环结束，128 合格。注意取模用的是原数 `x`，不是被不断缩小的 `t`——这是最容易写错的一处。

```python
def selfDividingNumbers(left, right):
    res = []
    for x in range(left, right + 1):
        t, ok = x, True
        while t:
            d = t % 10
            if d == 0 or x % d != 0:
                ok = False
                break
            t //= 10
        if ok:
            res.append(x)
    return res
```

对示例 2 的 `x = 48`：`d = 8`，`48 % 8 == 0`；`t = 4`，`d = 4`，`48 % 4 == 0`，通过。而 `x = 50` 第一轮 `d = 0` 直接淘汰，所以 50 不在答案里。

## 复杂度
时间：O((right-left+1) · log right)，每个数拆位约 log10 位。
空间：O(1) 额外（不计返回列表），只用了 `t`、`d`、`ok` 几个标量。

## 易错点
- 输入含 0 的数（如 `left=1, right=22` 中的 10、20）→ 若只判 `x % d != 0` 而不先判 `d == 0`，会抛 `ZeroDivisionError` 直接崩 → 必须先 `if d == 0` 短路。
- 取模对象写成 `t % d` 而非 `x % d`（如 `x = 128` 第二轮 `t = 12`，`12 % 2 == 0` 碰巧对，但 `x = 15` 时 `t = 1`，`1 % 5 != 0` 会误判 15 不合格）→ 必须始终用原数 `x` 取模。

## 如果面试官追问
问：若 `right` 放大到 10^9 怎么办？答：单个数判定不变，但枚举量爆炸，需按位 DP 或预处理合法数字集合，不能裸暴力。
