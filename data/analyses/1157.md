## 一句话思路
随机采样 + 前缀位置表：多数元素在区间内占比超 1/2，随机抽 20 次几乎必中，再用二分确认次数。

## 怎么做
1. 预处理 `pos[x]` 存每个值出现的下标列表，查询时用 `bisect` 数区间内次数。
2. 每次 query 在 `[left, right]` 内随机取 20 个下标，对每个候选值 `v = arr[i]` 用 `bisect_right(pos[v], right) - bisect_left(pos[v], left)` 算出现次数。
3. 次数 ≥ `threshold` 立即返回该值，20 次都不中返回 -1。
4. 以示例 `arr=[1,1,2,2,1,1]`, `query(0,3,3)` 为例：区间长度 4，`threshold=3`，随机抽到 1 或 2 都只有 2 次，全部失败返回 -1。

```python
import random, bisect
def query(self, left, right, threshold):
    for _ in range(20):
        v = self.arr[random.randint(left, right)]
        p = self.pos[v]
        cnt = bisect.bisect_right(p, right) - bisect.bisect_left(p, left)
        if cnt >= threshold:
            return v
    return -1
```

## 复杂度
时间：建表 O(n)，每次 query 期望 O(20·log n)，20 次采样 × 二分。
空间：`pos` 存全部 n 个下标，O(n)。

## 易错点
- 采样次数太少（如 5 次）→ 当 `threshold` 恰好等于 `(right-left+1)//2+1` 时命中率约 1/2，5 次失败率约 3%，1e4 次查询会错几十次 → 用 20 次，失败率约 1e-6。
- 只采样不验证 → 抽到候选值直接返回，但该值可能不足 `threshold` 次（如 `query(0,3,3)` 抽到 1 只有 2 次）→ 必须用 `bisect` 数出真实次数再比较。

## 如果面试官追问
问：要求确定性而非随机怎么办？
答：改用线段树存区间 Boyer-Moore 候选值，再二分验证次数，O(log n) 查询且无随机性。
