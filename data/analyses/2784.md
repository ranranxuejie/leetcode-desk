## 一句话思路
长度必须等于 `max(nums)+1`，且排序后逐位等于 `[1,2,...,n-1,n,n]`，两个条件一起卡死。

## 怎么做
1. 取 `n = max(nums)`，先判 `len(nums) == n + 1`，不等直接 `False`。
2. 排序后逐位比对：下标 `i` 处期望值是 `i+1`，但最后一位（`i == n`）期望仍是 `n`。
3. 任一位不等就返回 `False`，全过返回 `True`。

拿示例 4 `nums = [3,4,4,1,2,1]` 走一遍：`n = 4`，`len(nums) = 6`，而 `n+1 = 5`，第一步就返回 `False`，根本进不到排序。再看示例 2 `nums = [1,3,3,2]`：`n = 3`，`len = 4 = n+1` 通过；排序得 `[1,2,3,3]`，`i=0` 期望 1 ✓，`i=1` 期望 2 ✓，`i=2` 期望 3 ✓，`i=3` 期望 `n=3` ✓，返回 `True`。

```python
n = max(nums)
if len(nums) != n + 1:
    return False
nums.sort()
for i, v in enumerate(nums):
    expect = n if i == n else i + 1
    if v != expect:
        return False
return True
```

也可以不排序，用计数数组 `cnt` 统计后检查 `cnt[1..n-1]` 全为 1、`cnt[n] == 2`，但排序版更短且 `n ≤ 100` 完全够用。

## 复杂度
时间：排序 `O(m log m)`，`m = len(nums)`，逐位比对 `O(m)`。
空间：排序原地 `O(log m)` 栈开销，无额外数组。

## 易错点
- 输入 `[1,1,1]`：只查最大值和长度会误判——`n=1`、`len=3 ≠ 2` 其实第一步就拦住了；但 `[1,2,2,2]` 长度 4 等于 `n+1=3`？不，`n=2`、`n+1=3≠4` 也拦住。真正危险的是 `[1,1,2,2]`：`n=2`、`len=4≠3` 仍被拦。所以长度检查必须用 `max+1` 而不是「元素种类数」，否则 `[1,2,2]` 这种 `n=2`、长度 3 正确但缺 `1` 的会被放过——排序比对才能抓到。
- 输入 `[1,2,3,3,3]`：`n=3`、`len=5≠4` 被长度拦；但 `[1,2,2,3]` 长度 4 正确、最大值 3 正确，排序后 `i=1` 期望 2 实得 2 ✓、`i=2` 期望 3 实得 2 ✗，必须靠逐位比对，不能只统计「每个值出现次数 ≤ 2」。

## 如果面试官追问
问：如果 `nums` 长度到 `10**5`、值域也到 `10**5`，还排序吗？
答：改用计数数组 `cnt`，`O(m + n)` 时间，检查 `cnt[1..n-1]==1` 且 `cnt[n]==2`。
