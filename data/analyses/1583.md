## 一句话思路
用 rank[i][j] 记录 j 在 i 心中的名次，再对每对 (x,y) 枚举 x 比 y 更亲近的人 u，检查 u 是否也更喜欢 x。

## 怎么做
1. 预处理 `rank`：`rank[i][preferences[i][k]] = k`，名次越小越亲近。
2. 建 `partner[x] = y`，把 pairs 双向展开。
3. 对每对 (x,y)，遍历 `preferences[x]` 中排在 y 前面的人 u；若 `rank[u][x] < rank[u][partner[u]]`，则 x 不开心，跳出。
4. 对 y 同样做一遍，累加不开心人数。

以示例 1 为例：`rank[1] = {3:0, 2:1, 0:2}`，`partner[1]=0`。遍历 `preferences[1]` 时先遇到 3，`rank[3][1]=0 < rank[3][partner[3]]=rank[3][2]=1`，两个条件同时成立，朋友 1 判为不开心。

```python
rank = [[0]*n for _ in range(n)]
for i in range(n):
    for k, j in enumerate(preferences[i]):
        rank[i][j] = k
partner = [0]*n
for x, y in pairs:
    partner[x], partner[y] = y, x
ans = 0
for x, y in pairs:
    for u in preferences[x]:
        if u == y:
            break
        if rank[u][x] < rank[u][partner[u]]:
            ans += 1
            break
    for v in preferences[y]:
        if v == x:
            break
        if rank[v][y] < rank[v][partner[v]]:
            ans += 1
            break
```

## 复杂度
时间 O(n²)：建 rank 表 O(n²)，每对最多扫 n 个候选。
空间 O(n²)：rank 二维表占 n²，partner 数组占 n。

## 易错点
- 遍历 `preferences[x]` 时忘了在遇到 y 时 `break`：会把排在 y 后面、亲近度更低的人也当成候选，示例 1 中朋友 0 会被误判不开心，答案从 2 变成 3。正确做法是只检查严格排在 y 前面的人。
- 只检查单向条件 `rank[x][u] < rank[x][y]`：示例 1 中 0 比 1 更喜欢 2，但 2 的伴侣是 3 且 2 更亲近 3，0 其实开心；漏掉 `rank[u][x] < rank[u][partner[u]]` 会把 0 误算进去。

## 如果面试官追问
若 n 放大到 10⁵ 且每人只给前 k 个偏好，怎么办？答：只对前 k 个建 rank，枚举候选时截断到 k，复杂度 O(nk)。
