## 一句话思路
把「不生气时的满意数」当底数，再用长度 `minutes` 的滑动窗口找「被抑制后额外挽回的最大顾客数」。

## 怎么做
1. 先累加所有 `grumpy[i] == 0` 的 `customers[i]`，记为 `base`。
2. 窗口只统计 `grumpy[i] == 1` 的 `customers[i]`，因为只有这些顾客能被挽回。
3. 窗口右移时加 `customers[r] * grumpy[r]`，左端出窗时减 `customers[l] * grumpy[l]`，全程记录窗口最大值 `best`。
4. 返回 `base + best`。

以示例 1 为例：`base = 1+1+1+7 = 10`（下标 0,2,4,6）。窗口长度 3 扫到 `[5,6,7]` 时，窗口内 `grumpy` 为 `[1,0,1]`，挽回 `1+5 = 6`，`best = 6`，答案 `10+6 = 16`。

```python
base = sum(c for c, g in zip(customers, grumpy) if g == 0)
cur = best = 0
for r in range(len(customers)):
    if grumpy[r]:
        cur += customers[r]
    if r >= minutes and grumpy[r - minutes]:
        cur -= customers[r - minutes]
    best = max(best, cur)
return base + best
```

## 复杂度
时间：O(n)，一次遍历，`n = len(customers)`。
空间：O(1)，只开了 `base/cur/best` 三个标量。

## 易错点
1. 窗口里把 `grumpy[i] == 0` 的顾客也算进去 → 示例 1 窗口 `[5,6,7]` 会算成 `1+7+5 = 13`，答案变 23。正确做法是乘 `grumpy[i]` 过滤，只累加生气分钟的顾客。
2. 左端出窗时忘记判断 `grumpy[r - minutes]` → 示例 1 在 `r=3` 时会把 `customers[0]=1` 减掉，而它本来就没进过窗口，`cur` 被错误压低。正确做法是出窗和入窗用同一个 `grumpy` 条件。

## 如果面试官追问
问：如果技巧可以用 k 次（每次连续 `minutes` 分钟）怎么办？
答：变成在「生气分钟收益数组」上做 k 段不重叠定长区间最大和，用 DP 或贪心加堆，不再是单窗口。
