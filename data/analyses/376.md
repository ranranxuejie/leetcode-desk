## 一句话思路
贪心：只统计相邻差值的符号翻转次数，因为每个单调段最多贡献一个摆动点。

## 怎么做
1. 维护 `prev` 表示上一个非零差值的符号，`count` 初始为 1（首元素必计入）。
2. 遍历 `i` 从 1 到 `len(nums)-1`，算 `diff = nums[i] - nums[i-1]`。
3. `diff == 0` 直接跳过（相等不产生摆动点）；`diff` 符号与 `prev` 不同则 `count += 1` 并更新 `prev`。
4. 返回 `count`。

以示例 2 `[1,17,5,10,13,15,10,5,16,8]` 为例：`diff` 序列是 `16,-12,5,3,2,-5,-5,11,-8`。前两个 `16`（正）、`-12`（负）翻转，`count=3`；接着 `5,3,2` 都是正，`prev` 已是负，只有第一个 `5` 翻转 `count=4`；`-5` 翻转 `count=5`；第二个 `-5` 与 `prev` 同号跳过；`11` 翻转 `count=6`；`-8` 翻转 `count=7`。结果 7，与官方一致。

```python
count, prev = 1, 0
for i in range(1, len(nums)):
    diff = nums[i] - nums[i-1]
    if diff == 0:
        continue
    sign = 1 if diff > 0 else -1
    if sign != prev:
        count += 1
        prev = sign
return count
```

关键点：`prev` 初始为 0，所以第一个非零差值一定翻转，天然处理了「第一个差可正可负」。

## 复杂度
时间：O(n)，一次遍历，每个元素只算一次 `diff`。
空间：O(1)，只开了 `count`、`prev`、`diff`、`sign` 四个标量。

## 易错点
- 输入 `[1,7,4,5,5]` → 若把 `diff == 0` 当成翻转（或更新 `prev` 为 0）→ 会错算成 5；正确做法是 `diff == 0` 直接 `continue`，`prev` 保持上一个非零符号不变，答案 4。
- 输入 `[1,2,3,4,5]` → 若用「相邻差值符号交替」逐对判断而不合并单调段 → 会漏掉「整段单调只算一个点」；正确做法是只在符号翻转时 `count += 1`，答案 2 而非 5。

## 如果面试官追问
问：要求输出具体的最长摆动子序列而非长度？答：在 `count += 1` 处把 `nums[i]` 追加到结果列表，最后补上末尾元素即可，仍是 O(n)。
