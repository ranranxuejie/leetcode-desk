## 一句话思路
用 `dp[i][d]` 记录以 `nums[i]` 结尾、公差为 `d` 的最长长度，枚举前驱 `j` 转移。

## 怎么做
1. 建 `n` 个字典，`dp[i]` 存「以 `i` 结尾的各公差对应长度」，初值全空。
2. 外层 `i` 从 1 到 `n-1`，内层 `j` 从 0 到 `i-1`，算 `d = nums[i] - nums[j]`。
3. 转移：`dp[i][d] = dp[j].get(d, 1) + 1`，同时更新全局 `best`。
4. 返回 `best`，`n >= 2` 时至少为 2。

以示例 2 `nums = [9, 4, 7, 2, 10]` 为例，走到 `i=4`（值 10）、`j=2`（值 7）时 `d = 3`，而 `dp[2][3]` 在 `j=1` 那步已被置成 2（序列 `[4,7]`），于是 `dp[4][3] = 2 + 1 = 3`，`best` 从 2 升到 3。

```python
n = len(nums)
dp = [{} for _ in range(n)]
best = 2
for i in range(1, n):
    for j in range(i):
        d = nums[i] - nums[j]
        cur = dp[j].get(d, 1) + 1
        dp[i][d] = cur
        if cur > best:
            best = cur
return best
```

关键在 `dp[j].get(d, 1)`：`1` 表示 `j` 前面没有同公差元素，`j` 自己单独成首项，接上 `i` 得长度 2。

## 复杂度
时间：`O(n^2)`，双重循环枚举 `(j, i)` 对，字典查询是 `O(1)`。
空间：`O(n^2)`，最坏每个 `dp[i]` 存 `i` 个不同公差。

## 易错点
- 输入 `[3, 6, 9, 12]` 若把 `best` 初值写成 1 或 0，全等数组或 `n=2` 时会少算；正确做法是 `best = 2`，因为任意两个元素都构成等差子序列。
- 输入 `[0, 0, 0]` 时若用「先判 `d` 是否已存在再赋值」的写法，容易把 `d = 0` 当成无效公差跳过，错成 2；正确做法是 `d = 0` 照常走 `dp[j].get(0, 1) + 1`，得 3。

## 如果面试官追问
问：`nums[i]` 上限只有 500，能更快吗？
答：公差范围被限制在 `[-500, 500]`，可把字典换成定长数组 `dp[i][d+500]`，省掉哈希开销，仍是 `O(n^2)` 但常数更小。
