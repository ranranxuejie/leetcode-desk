## 一句话思路
用并查集把「共享邮箱的账户」连成同一集合，再按根节点聚合邮箱并排序。

## 怎么做
1. 遍历所有账户，用 `email_to_id` 记录每个邮箱首次出现的账户下标；若邮箱已存在，就 `union(i, email_to_id[email])`，把当前账户并入老账户。
2. 再遍历一次，对每个账户取 `find(i)` 作为根，把该账户所有邮箱塞进 `groups[root]` 集合（用 set 去重）。
3. 最后对每个根，取 `accounts[root][0]` 作名字，`sorted(groups[root])` 作邮箱列表。

以示例 1 为例：`accounts[2]` 的 `johnsmith@mail.com` 已在 `email_to_id` 中对应 0，于是 `union(2, 0)`，根统一为 0；`groups[0]` 最终是 `{johnsmith@mail.com, john00@mail.com, john_newyork@mail.com}`，排序后正好是输出第一个账户的三个邮箱。

```python
parent = list(range(n))
def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x
def union(a, b):
    ra, rb = find(a), find(b)
    if ra != rb:
        parent[rb] = ra

email_to_id = {}
for i, acc in enumerate(accounts):
    for email in acc[1:]:
        if email in email_to_id:
            union(i, email_to_id[email])
        else:
            email_to_id[email] = i
```

聚合时注意：`groups` 的 key 必须是 `find(i)` 而不是 `i`，否则 `accounts[2]` 会单独成组。

## 复杂度
时间 O(N·K·α(N) + N·K·log(N·K))，N 是账户数、K 是每账户邮箱数，排序贡献 log。
空间 O(N·K)，`email_to_id` 和 `groups` 各存一份邮箱。

## 易错点
- 输入 `[["John","a@m.com"],["John","b@m.com"],["John","a@m.com","b@m.com"]]` → 若只把邮箱映射到「首次出现的账户」而不做 union，第三个账户会独立成组 → 必须对重复邮箱执行 `union(i, email_to_id[email])`，让传递关系合并。
- 输入 `[["John","a@m.com","a@m.com"]]`（同账户内重复邮箱）→ 若用 list 收集邮箱，输出会出现两个 `a@m.com` → 用 set 收集再 `sorted`，天然去重。

## 如果面试官追问
问：账户数涨到 10^5、邮箱总数 10^6 还这么做吗？
答：可以，并查集近似线性；瓶颈在排序，可改用桶或直接对邮箱全局排序后按根切分。
