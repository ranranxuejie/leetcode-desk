## 一句话思路
用长度 `2k+1` 的滑动窗口维护区间和，窗口整体右移一格就 `+nums[r] - nums[l-1]`，避免每个中心重算。

## 怎么做
1. 先算首个合法窗口（中心 `i=k`）的和 `s = sum(nums[0:2*k+1])`，写进 `avgs[k] = s // (2*k+1)`。
2. 之后中心从 `k+1` 走到 `n-k-1`，每步 `s += nums[i+k] - nums[i-k-1]`，再整除写入。
3. 其余位置（`i < k` 或 `i > n-k-1`）保持初值 `-1`。
4. 边界：`n < 2*k+1` 时整个数组都是 `-1`，循环一次都不进。

以示例 1 `nums = [7,4,3,9,1,8,5,2,6], k = 3` 为例：首窗口 `nums[0:7]` 和 `s = 37`，`avgs[3] = 37 // 7 = 5`；移到中心 4 时 `s = 37 + nums[7] - nums[0] = 37 + 2 - 7 = 32`，`avgs[4] = 32 // 7 = 4`。

```python
n = len(nums)
avgs = [-1] * n
w = 2 * k + 1
if n >= w:
    s = sum(nums[:w])
    avgs[k] = s // w
    for i in range(k + 1, n - k):
        s += nums[i + k] - nums[i - k - 1]
        avgs[i] = s // w
return avgs
```

## 复杂度
时间：O(n)，首窗口求和 O(k) 加 n-2k 次 O(1) 滑动，整体线性。
空间：O(n)，只额外开了输出数组 `avgs`，窗口和 `s` 是 O(1)。

## 易错点
- `k = 0` 时窗口长度 `w = 1`，若把循环写成 `range(k+1, n-k)` 之外的边界判断搞错，会漏掉 `avgs[0]`。示例 2 `nums = [100000], k = 0` 必须输出 `[100000]`，正确做法是首窗口 `sum(nums[:1])` 直接覆盖全部下标。
- `n < 2*k+1` 时（示例 3 `nums = [8], k = 100000`），若不先判 `n >= w` 就执行 `sum(nums[:w])`，`avgs[k]` 会越界写。正确做法是整段跳过，返回全 `-1`。

## 如果面试官追问
问：如果要求返回浮点平均值而不是截断整数？
答：把 `s // w` 换成 `s / w`，滑动逻辑不变，只是输出类型改成 `float`。
