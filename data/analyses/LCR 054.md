## 一句话思路
反序中序遍历（右→根→左），用全局累加和 `total` 边遍历边累加，节点值直接改成累加后的 `total`。

## 怎么做
1. 维护一个非局部变量 `total = 0`，表示「已访问过的所有更大节点值之和」。
2. 先递归右子树，因为右子树的值全部大于当前节点。
3. 访问根：`total += root.val`，再 `root.val = total`。
4. 最后递归左子树。

以示例 1 的根 `4` 为例：先走右子树 `6`，再走 `6` 的右子树 `7`，再走 `7` 的右子树 `8`。到 `8` 时 `total = 0 + 8 = 8`，`8` 改成 `8`；回溯到 `7` 时 `total = 8 + 7 = 15`，`7` 改成 `15`；回到 `6` 时 `total = 15 + 6 = 21`，`6` 改成 `21`。此时 `total = 21` 正是「≥4 的所有值之和」中已经累计的部分，接着 `total = 21 + 4 = 25`，根 `4` 改成 `25`？——注意，正确输出根是 `30`，因为还要加上左子树里比 4 大的 `5`。反序中序的顺序是 `8,7,6,5,4,...`，`5` 在 `6` 的左子树里，会在 `4` 之前被访问，所以到根时 `total` 已经是 `8+7+6+5=26`，`26+4=30`，与输出一致。

```python
total = 0

def dfs(node):
    nonlocal total
    if not node:
        return
    dfs(node.right)
    total += node.val
    node.val = total
    dfs(node.left)

dfs(root)
return root
```

关键点：`total` 必须在「访问根」这一步才加上 `node.val`，顺序不能颠倒成先改值再累加。

## 复杂度
时间 O(n)：每个节点恰好被访问一次，n 为节点数。
空间 O(h)：递归栈深度等于树高 h，最坏链状树 O(n)，平衡树 O(log n)，无额外数组。

## 易错点
- 写成普通中序（左→根→右）→ 示例 1 中 `0` 会先被访问，`total` 从 `0` 开始累加，根 `4` 得到的是「≤4 的和」而非「≥4 的和」，输出全错。必须右→根→左。
- 在递归右子树之前就把 `total += node.val` → 示例 1 中根 `4` 会先加自己得 `4`，再进右子树，最终根变成 `4+8+7+6+5=30` 看似对，但叶子 `8` 会变成 `4+8=12` 而非 `8`。累加必须严格在「右子树处理完、当前节点处理时」发生。

## 如果面试官追问
问：若树不是 BST，还能这么做吗？
答：不能，反序中序的有序性依赖 BST；非 BST 需先收集所有值排序，再对每个节点二分求后缀和，时间 O(n log n)。
