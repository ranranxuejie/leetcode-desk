## 一句话思路
从左到右扫，若 `s[i]` 的值小于 `s[i+1]` 就减它，否则加它，一次遍历得答案。

## 怎么做
1. 建字典 `val` 把七个字符映射到 1/5/10/50/100/500/1000。
2. 遍历 `i` 从 0 到 `len(s)-1`，取 `cur = val[s[i]]`。
3. 若 `i+1 < len(s)` 且 `cur < val[s[i+1]]`，说明这是 `IV`/`IX`/`XL` 这类减法组合，`total -= cur`；否则 `total += cur`。
4. 返回 `total`。

以 `s = "MCMXCIV"` 为例，走到 `i=1` 时 `cur = val['C'] = 100`，下一个是 `'M' = 1000`，`100 < 1000` 成立，于是 `total` 从 1000 减 100 变成 900；而 `i=0` 的 `'M'` 因为 `1000 > 100` 走加法。整串累加结果 1000-100+1000-10+100-1+5 = 1994。

```python
val = {'I':1,'V':5,'X':10,'L':50,'C':100,'D':500,'M':1000}
total = 0
for i, ch in enumerate(s):
    cur = val[ch]
    if i + 1 < len(s) and cur < val[s[i + 1]]:
        total -= cur
    else:
        total += cur
return total
```

关键点：判断的是「当前位与右邻位」的大小关系，而不是去匹配 `IV`、`IX` 这些两字符子串。这样 `XLIX` 这种连续两个减法组合（`XL` 和 `IX`）也能自然处理，不需要额外分支。

## 复杂度
时间 O(n)：`n = len(s)`，每个字符访问一次，字典查询 O(1)。
空间 O(1)：字典固定 7 个键，只多了 `total`、`cur` 两个变量。

## 易错点
- 输入 `"IV"` → 若只做无脑求和 `1+5=6` → 正确做法是在 `i=0` 时发现 `1 < 5` 就减 1，得 4。减法组合必须靠「当前位小于右邻位」触发，不能靠字符串包含判断。
- 输入 `"MCM"` → 若把 `CM` 当成整体先替换再求和，容易在 `"CMXCIX"` 这类连续组合上替换顺序出错 → 正确做法是单字符遍历 + 相邻比较，`i=1` 的 `C` 减、`i=2` 的 `M` 加，天然不依赖替换。

## 如果面试官追问
问：如果要求反向，把整数转成罗马数字呢？
答：从 1000 到 1 建有序表（含 900、400、90、40、9、4 这些减法项），贪心从大到小减并拼接即可。
