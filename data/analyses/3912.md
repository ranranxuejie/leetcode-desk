## 一句话思路
正反两遍扫描，分别记录前缀最大值和后缀最大值，逐位判断是否严格大于其中一侧。

## 怎么做
1. 从左往右扫，维护 `left_max`，把每个位置左侧的最大值存进 `pre[i]`（`pre[0] = -inf`）。
2. 从右往左扫，维护 `right_max`，把每个位置右侧的最大值存进 `suf[i]`（`suf[n-1] = -inf`）。
3. 逐位判断 `nums[i] > pre[i] or nums[i] > suf[i]`，成立就加入答案。

以 `nums = [1,2,4,2,3,2]` 为例，`pre = [-inf,1,2,4,4,4]`，`suf = [4,4,3,3,2,-inf]`。看 `i=4`（值 3）：`3 > pre[4]=4` 不成立，但 `3 > suf[4]=2` 成立，所以 3 入选；而 `i=3`（值 2）：`2 > 4` 假、`2 > 3` 假，被排除。

```python
n = len(nums)
pre = [float('-inf')] * n
suf = [float('-inf')] * n
for i in range(1, n):
    pre[i] = max(pre[i-1], nums[i-1])
for i in range(n-2, -1, -1):
    suf[i] = max(suf[i+1], nums[i+1])
ans = [nums[i] for i in range(n) if nums[i] > pre[i] or nums[i] > suf[i]]
```

首尾元素天然满足（`-inf` 比较），无需特判。

## 复杂度
时间 O(n)：两遍扫描加一遍判断，各 O(n)。
空间 O(n)：`pre`、`suf` 两个长度 n 的数组。

## 易错点
- 输入 `[5,5,5,5]` → 若把条件写成 `>=`，中间两个 5 会被误判为有效，输出 `[5,5,5,5]` → 必须严格 `>`，`pre`/`suf` 存的是「左侧/右侧最大值」，相等时不算严格大于。
- 输入 `[1]` → 若循环写成 `range(1, n)` 且没处理 `n=1`，`pre`/`suf` 全为 `-inf` 时判断仍成立，但若用 `max(nums[:i])` 在 `i=0` 时取空列表会抛异常 → 用 `-inf` 初始化哨兵，避免对空切片求 `max`。

## 如果面试官追问
问：能否把空间降到 O(1)？
答：可以先正扫标记左侧有效的位置，再反扫时直接决定是否输出，但输出顺序需额外处理；n≤100 时没必要。
