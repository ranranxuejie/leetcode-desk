## 一句话思路
把所有数丢进 `set`，只从「没有前驱 `x-1`」的数 `x` 起向上数，每个数只被访问一次，故 O(n)。

## 怎么做
1. 用 `s = set(nums)` 去重，重复值（示例 2 的两个 `0`）不会让长度虚增。
2. 遍历 `s` 中的 `x`，若 `x - 1 in s` 就跳过——它不是任何序列的起点。
3. 否则从 `x` 开始，`while x + 1 in s` 一路加，记下长度更新 `best`。
4. 返回 `best`。

以 `nums = [100,4,200,1,3,2]` 为例：`s = {1,2,3,4,100,200}`。遍历到 `1` 时 `0 not in s`，于是 `1→2→3→4`，`cur` 从 1 涨到 4，`best = 4`；之后 `2`、`3`、`4` 因 `x-1 in s` 全被跳过，`100`、`200` 各只数到自身，`best` 保持 4。

```python
s = set(nums)
best = 0
for x in s:
    if x - 1 in s:
        continue
    cur = x
    while cur + 1 in s:
        cur += 1
    best = max(best, cur - x + 1)
return best
```

关键在 `if x - 1 in s: continue`：没有它，从 `2` 起会重数 `2,3,4`，退化成 O(n²)。

## 复杂度
时间 O(n)：`set` 建表 O(n)，每个数最多作为某条序列的成员被 `while` 访问一次。
空间 O(n)：`s` 存去重后的至多 n 个数，无其他额外结构。

## 易错点
- 输入 `[1,2,0,1]` → 若用 `list` 判 `x-1 in nums` 且不去重，重复的 `1` 会让同一条序列被数两遍、且查找是 O(n) → 正确做法是先 `set(nums)`，判存在和去重一步到位。
- 输入 `[0,3,7,2,5,8,4,6,0,1]` → 若漏掉 `x-1 in s` 的跳过判断，从 `3` 起会重数 `3..8`，复杂度退化但答案仍对，容易误以为没问题 → 必须显式 `continue`，保证每个数只被 `while` 走一次。

## 如果面试官追问
要求输出这条序列本身而不只是长度？答：在 `while` 里记下起点 `x` 和终点 `cur`，最后按 `range(x, cur+1)` 还原，长度相同、复杂度不变。
