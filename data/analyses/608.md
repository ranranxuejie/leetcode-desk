## 一句话思路
用 `CASE WHEN` 按「p_id 为空 → Root、id 出现在别人 p_id 里 → Inner、否则 Leaf」三档判定，一次扫描即可。

## 怎么做
1. 先想清楚判定顺序：`p_id IS NULL` 一定是 Root，这条必须放最前面，否则单节点树会被误判。
2. 判断「有没有孩子」不能靠本行，要看本行的 `id` 是否出现在**其他行**的 `p_id` 中，用 `id IN (SELECT p_id FROM Tree)` 做子查询。
3. 用 `CASE` 把三种情况串起来，`ELSE 'Leaf'` 兜底。
4. 以示例 1 为例：对 `id=2` 这一行，`p_id=1` 非空，且 `2` 出现在 `p_id` 列（第 4、5 行），所以落到 `Inner`；对 `id=3`，`3` 不在 `p_id` 列中，落到 `Leaf`。

```python
# 关键判定逻辑（伪 SQL 表达，落到 Python 里就是拼这段 CASE）
case_sql = """
CASE
  WHEN p_id IS NULL THEN 'Root'
  WHEN id IN (SELECT p_id FROM Tree WHERE p_id IS NOT NULL) THEN 'Inner'
  ELSE 'Leaf'
END AS type
"""
# 若用 pandas：
# has_child = set(df["p_id"].dropna())
# df["type"] = df.apply(
#     lambda r: "Root" if r.p_id is None
#     else ("Inner" if r.id in has_child else "Leaf"), axis=1)
```

子查询里加 `p_id IS NOT NULL` 是防御性的：`NULL` 参与 `IN` 比较不会命中任何 `id`，但显式过滤让语义更干净，也避免某些引擎对 `NULL` 集合的处理差异。

## 复杂度
时间：O(n)，外层扫 n 行，子查询对每行做一次 `p_id` 集合查找（建索引后 O(1)）。
空间：O(n)，子查询/集合缓存了所有非空 `p_id`，即最多 n-1 个值。

## 易错点
- 单节点树 `(1, NULL)` → 若先判「id 不在 p_id 里」就归为 Leaf，错成 `Leaf`；正确做法是把 `p_id IS NULL` 放 `CASE` 第一支，先命中 Root。
- 把「有孩子」写成 `p_id IS NOT NULL` → 示例 1 中 `id=3` 的 `p_id=1` 非空，会被错判成 Inner；正确做法是查 `id IN (SELECT p_id FROM Tree)`，看的是别人指向自己，不是自己指向别人。

## 如果面试官追问
问：如果树退化成一条链（每个节点最多一个孩子），结论会变吗？
答：不变，链中间节点仍有孩子所以是 Inner，只有链尾是 Leaf，判定逻辑与树的形状无关。
