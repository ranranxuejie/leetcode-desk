## 一句话思路
按空格切分，只取纯数字 token 转 int，用 `prev` 记录上一个数字，逐个比较是否严格大于。

## 怎么做
1. 用 `s.split()` 切出 token 列表，空格是单个的，切完不会有空串。
2. 遍历 token，用 `token.isdigit()` 判断是不是数字 token（单词全小写字母，不会误判）。
3. 是数字就转 `int`，和 `prev` 比：`<= prev` 立刻返回 `False`，否则更新 `prev`。
4. 全部走完返回 `True`；`prev` 初值设 `-1` 或 `0` 都行，因为数字是正整数。

以示例 3 `"sunset is at 7 51 pm overnight lows will be in the low 50 and 60 s"` 为例：token 依次是 `sunset/is/at/7/51/pm/...`，读到 `7` 时 `prev=7`，读到 `51` 时 `51>7` 通过、`prev=51`，读到 `50` 时 `50<=51` 直接返回 `False`——注意这里不是"最后才失败"，是中途就短路。

```python
prev = 0
for token in s.split():
    if token.isdigit():
        cur = int(token)
        if cur <= prev:
            return False
        prev = cur
return True
```

关键点：`isdigit()` 对本题足够，因为 token 要么纯数字要么纯字母，不存在 `"12a"` 这种混合。别用 `token[0].isdigit()`，虽然本题也能过，但语义上不如整体判断干净。

## 复杂度
时间 O(n)：n 是字符串长度，split 扫一遍、遍历 token 再扫一遍，每个字符常数次。
空间 O(n)：split 产生的 token 列表，最坏约 n/2 个 token。

## 易错点
- 输入 `"hello world 5 x 5"` → 若用 `>=` 之外的宽松判断（比如只比"是否不同"）会错判成 `True`；必须严格 `cur <= prev` 就返回 `False`，两个 5 相等要判失败。
- 输入 `"4 5 11 26"` → 若把 token 当字符串比较，`"11" < "26"` 碰巧对，但 `"11" < "5"` 会因字典序判成 `True` 而漏掉 `5 < 11` 的真实关系；必须先 `int(token)` 再比。

## 如果面试官追问
问：如果数字 token 可能带前导零或超过 100，代码要改吗？
答：不用改，`int()` 天然处理前导零和任意位数，Python 整数无溢出，比较逻辑不变。
