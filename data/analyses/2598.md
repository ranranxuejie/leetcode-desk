## 一句话思路
按 `nums[i] % value` 分桶，从 0 开始逐个消费桶内元素，第一个凑不出的数就是最大 MEX。

## 怎么做
1. 对每个 `nums[i]` 取 `nums[i] % value`（Python 负数取模结果非负，正好是它所在桶），把桶计数存进长度 `value` 的数组 `cnt`。
2. 从 `mex = 0` 开始循环：桶 `mex % value` 里还有剩余就消耗一个、`mex += 1`，否则立刻返回 `mex`。
3. 循环上限是 `len(nums)`，因为最多只能填出 `n` 个不同的非负整数。

拿示例 1 走一遍：`nums = [1,-10,7,13,6,8], value = 5`，取模得 `[1,0,2,3,1,3]`，所以 `cnt = [1,2,1,2,0]`。`mex=0` 用掉桶 0 的 1 个；`mex=1` 用掉桶 1 的 1 个（剩 1）；`mex=2`、`mex=3` 各用掉桶 2、桶 3 的 1 个；`mex=4` 时桶 `4 % 5 = 4` 的计数是 0，返回 4。

```python
cnt = [0] * value
for x in nums:
    cnt[x % value] += 1

mex = 0
while mex < len(nums) and cnt[mex % value] > 0:
    cnt[mex % value] -= 1
    mex += 1
return mex
```

关键点：同一个桶里的数模 `value` 相同，加减 `value` 只能在桶内移动，所以桶 `r` 里的数能变成 `r, r+value, r+2*value, ...` 中任意一个，且每个数只服务一个目标值。

## 复杂度
时间 O(n + value)：一次遍历建桶，`mex` 最多推进 n 步。
空间 O(value)：只开了长度 `value` 的计数数组 `cnt`。

## 易错点
- `nums` 含负数如 `-10`、`value = 5`：若用 C 风格取模会得到 `-0` 或负下标直接越界；Python 的 `-10 % 5 == 0` 天然正确，别手动写 `x - x // value * value` 之外的修正逻辑，也别加 `abs`。
- 循环条件漏掉 `mex < len(nums)`：如 `nums = [0,0,0], value = 1`，桶 0 有 3 个，`mex` 会一路涨到 3 才停，若不设上界虽也能靠桶耗尽停下，但 `nums = [0], value = 1` 这类边界要确认返回 1 而不是死循环；正确做法是显式写上界。

## 如果面试官追问
要求输出具体操作方案怎么办？答：在消耗桶时记录「哪个下标贡献了当前 mex」，最后对每个目标值反推 `(目标值 - nums[i]) // value` 次加减即可。
