## 一句话思路
先按相邻字符差 >2 的位置把 word 切成若干段，段内再枚举字符种类数 m，用定长窗口 2mk 滑窗统计。

## 怎么做
1. 预处理 `bad[i] = abs(ord(word[i])-ord(word[i-1])) > 2`，在 bad 处断开，得到若干连续段；完全子串不可能跨段。
2. 段内若含 m 种字符，长度必为 `m*k`（每种恰好 k 次），故 m 只需枚举到 `len(seg)//k`。
3. 对每个 m，用长度 `m*k` 的定长窗口滑动，维护 26 长计数数组和「计数等于 k 的字符个数 cnt」，`cnt == m` 时答案 +1。

以 `word="igigee", k=2` 为例：i-g 差 2、g-i 差 2、i-g 差 2、g-e 差 2、e-e 差 0，无断点，整串一段。m=1 时窗口长 2，`"ee"` 处 cnt=1 计 1；m=2 时窗口长 4，`"igig"` 计数 i:2,g:2，cnt=2 计 1；m=3 时窗口长 6，`"igigee"` 中 i:2,g:2,e:2，cnt=3 计 1，合计 3。

```python
for seg in segments:
    n = len(seg)
    for m in range(1, n // k + 1):
        w = m * k
        cnt = [0] * 26
        ok = 0
        for i, ch in enumerate(seg):
            c = ord(ch) - 97
            cnt[c] += 1
            if cnt[c] == k: ok += 1
            if i >= w:
                d = ord(seg[i - w]) - 97
                if cnt[d] == k: ok -= 1
                cnt[d] -= 1
            if i >= w - 1 and ok == m:
                ans += 1
```

## 复杂度
时间：每段枚举 m 共 O(n/k) 轮，每轮 O(n)，总 O(n²/k)，n 为段长。
空间：计数数组固定 26 个，额外 O(1)（不计分段存储）。

## 易错点
- 输入 `"aaabbbccc", k=3`：若忘记「每种恰好 k 次」要求种类数 m 与窗口长 2mk 绑定，会把 `"aaabbb"` 这种长度 6 但只含 2 种、每种 3 次的窗口误判——它其实合法，真正的坑是把长度不是 `m*k` 的窗口也纳入统计，导致多算。正确做法是窗口长严格取 `m*k`。
- 输入 `"igigee", k=2`：若只在 bad 处切段却忘了段内还要按 m 枚举，只用一个窗口长 `2k` 滑，会漏掉 `"igigee"` 这个 m=3 的解，输出 2 而非 3。正确做法是 m 从 1 枚举到 `len(seg)//k`。

## 如果面试官追问
问：若 k 很大、word 很长，O(n²/k) 还能优化吗？
答：段内字符种类上限 26，m 最多 26，实际是 O(26n)，已接近线性。
