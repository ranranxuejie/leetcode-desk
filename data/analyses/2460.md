## 一句话思路
从左到右单趟扫描，相等就翻倍并把后一个清零，最后把 0 挤到末尾。

## 怎么做
1. 用 `i` 从 0 遍历到 `n-2`，只比较 `nums[i]` 和 `nums[i+1]`。
2. 相等时执行 `nums[i] *= 2; nums[i+1] = 0`，注意 `i` 不跳步，因为清零后的 `nums[i+1]` 在下一步会作为左元素参与比较。
3. 扫描结束后用双指针 `k` 收集非零值写回 `nums` 前段，剩余位置补 0。

以 `nums = [1,2,2,1,1,0]` 为例，`i=1` 时 `nums[1]==nums[2]==2`，变成 `[1,4,0,1,1,0]`；接着 `i=2` 比较 `nums[2]=0` 与 `nums[3]=1` 不等，跳过——这一步是关键，清零位不能直接跳过不比较。

```python
n = len(nums)
for i in range(n - 1):
    if nums[i] == nums[i + 1]:
        nums[i] *= 2
        nums[i + 1] = 0

k = 0
for x in nums:
    if x != 0:
        nums[k] = x
        k += 1
while k < n:
    nums[k] = 0
    k += 1
```

## 复杂度
时间：O(n)，扫描和搬移各一趟，n 为数组长度。
空间：O(1)，原地修改，只用了 `i`、`k`、`x` 三个变量。

## 易错点
- 输入 `[0,0,1]` → 若先做「移零」再合并，会错成 `[0,1,0]` 之类；正确顺序是先按原下标合并（`nums[0]==nums[1]==0` 得 `[0,0,1]` 不变），最后统一移零得 `[1,0,0]`。
- 输入 `[2,2,2]` → 若合并后把 `i` 直接加 2 跳过，会漏掉 `nums[1]=4` 与 `nums[2]=2` 的比较；正确做法是 `i` 每次只加 1，让清零位继续参与下一轮比较。

## 如果面试官追问
问：若要求返回合并后的非零序列长度并原地压缩？
答：合并阶段后接 `k` 指针写回，返回 `k` 即可，仍是 O(n) 时间 O(1) 空间。
