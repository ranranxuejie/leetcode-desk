## 一句话思路
答案只由 `max(nums)` 和 `min(nums)` 决定：两端各能向内收 `k`，收拢后取 `max(0, max-min-2k)`。

## 怎么做
1. 扫一遍数组求 `lo = min(nums)`、`hi = max(nums)`，中间元素不影响结果。
2. 把最小值抬到 `lo + k`、最大值压到 `hi - k`，这是两端能达到的最接近位置。
3. 若 `hi - lo <= 2*k`，两段区间重叠，可把全部元素调到同一点，返回 0。
4. 否则返回 `hi - lo - 2*k`。

以示例 2 `nums = [0,10], k = 2` 为例：`lo = 0`、`hi = 10`，`hi - lo = 10 > 2*k = 4`，所以答案 `10 - 4 = 6`，对应把 0 调到 2、10 调到 8。

```python
lo, hi = min(nums), max(nums)
gap = hi - lo
if gap <= 2 * k:
    return 0
return gap - 2 * k
```

关键点：中间元素 `nums[i]` 只要满足 `lo + k <= nums[i] <= hi - k` 就能被调到公共点，而 `lo + k <= hi - k` 正是 `gap <= 2*k`，所以重叠时一定全体可调平。

## 复杂度
时间：O(n)，`min` 和 `max` 各扫一遍数组，n 是 `len(nums)`。
空间：O(1)，只存 `lo`、`hi`、`gap` 三个整数。

## 易错点
- `nums = [1], k = 0` → 若先算 `gap - 2*k` 再判断，会得到 0 没问题，但若写成 `abs(gap - 2*k)` 或漏掉 `max(0, ...)`，遇到 `nums = [5,5], k = 3`（gap=0）会返回负数 -6 → 必须先判 `gap <= 2*k` 返回 0。
- `nums = [0,10], k = 100` → 若直接返回 `gap - 2*k = -190`，答案错成负数 → 正确做法是取 `max(0, gap - 2*k)`，因为 k 可以大于 gap/2，两端区间完全重叠。

## 如果面试官追问
问：如果要求输出调整后的数组而不只是分数？
答：先算 `target = lo + k`（或 `hi - k`），对每个元素取 `min(max(x, lo+k), hi-k)`，再统一平移到 `target` 即可。
