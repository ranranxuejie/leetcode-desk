## 一句话思路
逐位取 max 只会让分量变大，所以先剔除任一分量超过 target 的三元组，剩下的按位取 max 看能否凑齐 target。

## 怎么做
1. 维护 `best = [0, 0, 0]`，记录可用三元组在各分量上的最大值。
2. 遍历 `triplets`，若某个 `t[k] > target[k]` 就跳过——它一旦参与合并，该分量就永远回不到 target。
3. 否则对三个分量做 `best[k] = max(best[k], t[k])`。
4. 最后判断 `best == target`。

以示例 1 的 `[[2,5,3],[1,8,4],[1,7,5]]`、`target = [2,7,5]` 为例：`[1,8,4]` 因 `8 > 7` 被跳过；`[2,5,3]` 使 `best = [2,5,3]`；`[1,7,5]` 使 `best = [2,7,5]`，与 target 相等，返回 `True`。

```python
best = [0, 0, 0]
for t in triplets:
    if t[0] > target[0] or t[1] > target[1] or t[2] > target[2]:
        continue
    for k in range(3):
        best[k] = max(best[k], t[k])
return best == target
```

关键点：max 操作单调不减，所以「超过 target 的三元组」是唯一需要排除的；剩下的三元组全部合并也不会越界，只要每个分量都有人能顶到 target 即可。

## 复杂度
时间 O(n)：n 为 triplets 长度，每个三元组只看 3 个分量。
空间 O(1)：只开了长度 3 的 `best`。

## 易错点
- 输入 `triplets = [[3,4,5],[4,5,6]]`、`target = [3,2,5]` → 若不过滤直接取 max，会得到 `[4,5,6]` 并误判 → 正确做法是先跳过任一分量超 target 的三元组，本题中两个都被跳过，`best` 停在 `[0,0,0]`，返回 `False`。
- 输入 `triplets = [[2,5,3],[1,7,5]]`、`target = [2,7,5]` → 若只检查「是否存在单个三元组等于 target」会漏判 → 正确做法是允许跨三元组拼凑：`[2,5,3]` 贡献 x=2，`[1,7,5]` 贡献 y=7、z=5，合并后正好是 target。

## 如果面试官追问
问：要求输出具体合并了哪些三元组怎么办？
答：在更新 `best[k]` 时顺带记录首次把该分量顶到 target 的下标，三个下标去重后即为答案集合。
