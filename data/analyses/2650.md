## 一句话思路
用 `gen.next(v)` / `gen.throw(e)` 手动驱动生成器，把每个 yield 出的 promise 接上 then/catch 再递归推进。

## 怎么做
1. 定义 `step(method, arg)`：调用 `gen[method](arg)` 拿到 `{value, done}`，`done` 为真就 `resolve(value)`。
2. 未完成时对 `value` 挂 `.then(v => step("next", v), e => step("throw", e))`，把结果或错误送回生成器。
3. `cancel` 只做一件事：`step("throw", "Cancelled")`，让错误从当前挂起点注入。
4. 用 `finished` 标志防止 cancel 在生成器已结束后重复注入。

以示例 5 为例：t=100ms 第一个 promise 解析，`step("next", undefined)` 推进到第二个 yield；t=150ms 调 `cancel`，此时生成器正挂在第二个 `setTimeout` 上，`step("throw", "Cancelled")` 让 `catch(e)` 命中，`return result` 返回 1，`done=True` 后 `resolve(1)`。

```python
def cancellable(gen):
    finished = False
    def step(method, arg):
        nonlocal finished
        try:
            r = getattr(gen, method)(arg)
        except StopIteration as e:
            finished = True
            resolve(e.value)
            return
        if r.done:
            finished = True
            resolve(r.value)
        else:
            r.value.then(lambda v: step("next", v),
                         lambda e: step("throw", e))
    def cancel():
        if not finished:
            step("throw", "Cancelled")
    return [cancel, promise]
```

## 复杂度
时间：O(k)，k 为生成器 yield 次数，每次只做一次 next/throw 和一次 then 挂载。
空间：O(1) 额外状态，只有 `finished` 标志和 promise 链本身。

## 易错点
- 示例 1 中 `cancelledAt=100` 但生成器 t=0 就 `return 42` 完成 → 若 cancel 不检查 `finished` 就 `gen.throw`，会对已关闭的生成器抛 `StopIteration` 之外的异常 → 正确做法是 `finished` 为真时 cancel 直接返回。
- 示例 6 中第一个 promise 被 reject 为 `"Promise Rejected"` → 若用 `.then(v => step("next", v))` 而不给第二参数，错误会逃逸成未捕获拒绝，生成器的 `catch` 收不到 → 必须写成 `.then(onFulfilled, onRejected)` 两个回调，让 `step("throw", e)` 把错误送回。

## 如果面试官追问
问：如果 cancel 要在 promise 已 reject 但生成器还没处理时生效怎么办？
答：把 cancel 也走 `step("throw", "Cancelled")`，由生成器自身的 try/catch 决定优先级，不需要额外状态。
