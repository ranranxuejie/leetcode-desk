## 一句话思路
用哈希表把「数位和 → 已见过的最大数」存起来，边遍历边配对，一次扫描出答案。

## 怎么做
1. 遍历 `nums`，对每个 `x` 用循环 `while x: s += x % 10; x //= 10` 求数位和 `s`。
2. 若 `s` 已在字典 `best` 中，用 `best[s] + nums[i]` 更新答案 `ans`。
3. 再把 `best[s]` 更新为 `max(best[s], nums[i])`，保证同组只留最大数。
4. 遍历结束若 `ans` 仍为 `-1`，说明没有配对成功。

以 `nums = [18,43,36,13,7]` 为例：处理 `18` 得 `s=9`，`best={9:18}`；处理 `36` 时 `s=9` 命中，`ans = 18+36 = 54`，随后 `best[9]` 更新为 `36`；处理 `43` 得 `s=7`，`best={9:36,7:43}`；处理 `7` 时 `s=7` 命中，`ans = max(54, 43+7=50) = 54`。

```python
best = {}
ans = -1
for v in nums:
    x, s = v, 0
    while x:
        s += x % 10
        x //= 10
    if s in best:
        ans = max(ans, best[s] + v)
        best[s] = max(best[s], v)
    else:
        best[s] = v
return ans
```

关键点：`best[s]` 只存该数位和下的最大值，因为配对时另一个数固定，取最大者必然最优，无需保留全部。

## 复杂度
时间 O(n·log₁₀M)：n 个元素，每个最多 10 位（`nums[i] ≤ 10^9`）。
空间 O(n)：字典 `best` 最多存 n 个不同数位和（实际最多 82 个键）。

## 易错点
- 输入 `[18, 18]` → 若先更新 `best[s]` 再判断命中，会把同一个下标和自己配对，错得 36 但逻辑上应得 36 却掩盖了「必须 i≠j」的隐患；正确做法是先查 `best` 再更新，且用 `max` 保留旧值。
- 输入 `[10, 12, 19, 14]` → 数位和分别为 1、3、10、5，全不相同，若忘记初始化 `ans = -1` 而用 `0`，会错返回 0；正确做法是初值设 `-1`，无配对时原样返回。

## 如果面试官追问
问：若要求返回具体下标对而非和？答：字典改存 `(最大值, 其下标)`，命中时记录 `(best[s][1], i)`，更新时同步替换下标即可。
