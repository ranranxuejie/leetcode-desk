## 一句话思路
用单调递减栈存下标，遇到比栈顶高的温度就弹栈结算天数，每个下标只进出一次。

## 怎么做
1. 建 `res = [0] * n` 和空栈 `stack`（存下标，对应温度从栈底到栈顶递减）。
2. 从左到右遍历 `i`，只要 `stack` 非空且 `temperatures[i] > temperatures[stack[-1]]`，就弹栈并写 `res[j] = i - j`。
3. 把 `i` 压栈，继续下一个。
4. 遍历结束仍在栈里的下标保持 0。

以示例 1 的 `[73,74,75,71,69,72,76,73]` 为例，走到 `i=5`（温度 72）时，栈里是 `[2,3,4]`（75,71,69）：72 > 69 弹 4 得 `res[4]=1`，72 > 71 弹 3 得 `res[3]=2`，72 < 75 停，压入 5。关键中间值就是这一步连弹两次。

```python
n = len(temperatures)
res = [0] * n
stack = []
for i, t in enumerate(temperatures):
    while stack and t > temperatures[stack[-1]]:
        j = stack.pop()
        res[j] = i - j
    stack.append(i)
return res
```

注意 `res[j] = i - j` 用的是下标差，不是温度差；栈里存下标而不是温度，就是为了能算这个差。

## 复杂度
时间 O(n)：每个下标最多压栈一次、弹栈一次，while 总次数不超过 n。
空间 O(n)：`res` 占 n，`stack` 最坏（温度严格递减）也占 n。

## 易错点
- 输入 `[30,40,50,60]` 这种严格递增序列 → 若写成 `if` 而不是 `while`，`i=1` 只弹一个就停，后面 `res` 全错；正确做法是 `while`，让 60 一次把 30、40、50 全结算成 1。
- 输入 `[73,74,75,71,69,72,76,73]` 末尾的 73 → 若遍历完不检查栈，容易误以为栈里元素也该有值；正确做法是 `res` 初始化为 0，栈中残留下标（如 6、7）自然保持 0，不要额外赋值。

## 如果面试官追问
问：温度范围只有 30~100，能更快吗？
答：可以倒着扫，对每个温度维护「最近出现位置」，从 `t+1` 到 100 取最小下标差，O(100n) 但常数小。
