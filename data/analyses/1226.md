## 一句话思路
给每根叉子配一把 `Lock`，但让 4 号哲学家先拿右叉再拿左叉，打破环形等待，从而不会死锁。

## 怎么做
1. 建 5 把锁 `forks = [Lock() for _ in range(5)]`，哲学家 `p` 的左叉是 `forks[p]`、右叉是 `forks[(p+1) % 5]`。
2. 对 `p < 4` 固定「先左后右」，对 `p == 4` 反转成「先右后左」，这样 0 号和 4 号争 `forks[0]` 时顺序相反，环被切断。
3. 拿到两把锁后依次调用 `pickLeftFork()`、`pickRightFork()`、`eat()`，再 `putLeftFork()`、`putRightFork()`，最后 `release()` 两把锁。
4. 用 `with` 或 `try/finally` 保证 `eat()` 抛异常也能放锁。

以官方示例 `n = 1` 看 3 号哲学家：`p=3 < 4`，先 `forks[3].acquire()` 再 `forks[4].acquire()`，输出 `[3,1,1]`、`[3,2,1]`、`[3,0,3]`；而 4 号先 `forks[0].acquire()` 再 `forks[4].acquire()`，输出 `[4,2,1]`、`[4,1,1]`、`[4,0,3]`——两者对 `forks[4]` 的争抢顺序相反，不会互相卡住。

```python
from threading import Lock

forks = [Lock() for _ in range(5)]

def wantsToEat(p, pickL, pickR, eat, putL, putR):
    left, right = forks[p], forks[(p + 1) % 5]
    first, second = (right, left) if p == 4 else (left, right)
    with first:
        with second:
            pickL(); pickR(); eat(); putL(); putR()
```

## 复杂度
时间：每个哲学家吃 `n` 次，每次 O(1) 次加锁/解锁，总计 O(n)。
空间：额外开 5 个 `Lock` 对象，O(1)。

## 易错点
- 若 5 个哲学家都「先左后右」→ 5 人各持左叉等右叉，形成环形等待死锁，`n=1` 时输出会卡在 5 个 `[p,1,1]` 之后不再前进；正确做法是让 4 号反转顺序，或改用 `try_acquire` 失败即释放。
- 若把 `forks[(p+1) % 5]` 写成 `forks[p+1]` → `p=4` 时索引 5 越界抛 `IndexError`，输出缺 4 号的记录；正确做法是取模，且注意 4 号「右叉」是 `forks[0]` 不是 `forks[4]`。

## 如果面试官追问
问：改成 100 个哲学家还这么写吗？
答：反转顺序仍成立，但更通用的是给每根叉子编号后按编号升序加锁，或引入一个服务生信号量限制最多 4 人同时抢叉。
