## 一句话思路
递增数组右移后必是「一个下降点 + 循环有序」，故数下降点个数即可判定。

## 怎么做
1. 遍历 `i` 从 0 到 n-1，比较 `nums[i] > nums[(i+1) % n]`，统计下降点个数 `drops`。
2. 若 `drops == 0`，数组本身递增，返回 0。
3. 若 `drops > 1`，说明有两处逆序，任何右移都消不掉，返回 -1。
4. 若 `drops == 1`，唯一下降点在下标 `k`（即 `nums[k] > nums[k+1]`），答案就是 `n - 1 - k`。

以 `nums = [3,4,5,1,2]` 为例：比较得 `3<4`、`4<5`、`5>1`（下降点 k=2）、`1<2`、`2<3`（末位与首位比），`drops = 1`，答案 `5 - 1 - 2 = 2`，与示例一致。

```python
n = len(nums)
drops = [i for i in range(n) if nums[i] > nums[(i + 1) % n]]
if not drops:
    return 0
if len(drops) > 1:
    return -1
return n - 1 - drops[0]
```

关键点：右移 `r` 次后，原下标 `i` 的元素落到 `(i + r) % n`，要让最小值 `nums[k+1]` 落到下标 0，需 `r = n - 1 - k`。

## 复杂度
时间：O(n)，一次遍历比较相邻（含首尾）元素。
空间：O(n) 存 `drops` 列表，可优化为 O(1) 只记计数与下标。

## 易错点
- 漏比末位与首位：`nums = [1,3,5]` 若只比 `i` 到 `n-2`，得 `drops = 0` 返回 0 正确；但 `nums = [5,1,3]` 漏比 `3 > 5` 会得 `drops = 1` 却算错 k，正确做法是循环比较 `nums[(i+1) % n]`，此处 `3 < 5` 不构成下降点，`drops = 1` 在 k=0，答案 `3-1-0 = 2`。
- 把 `drops == 1` 的答案写成 `k` 或 `k+1`：`[3,4,5,1,2]` 中 k=2，正确答案是 `n-1-k = 2`；写成 `k` 得 2 碰巧对，但 `[2,1,4]` 中 k=0，`k` 给 0 错、`n-1-k = 2` 也错（此题 `drops` 实为 2：`2>1` 与 `4>2`），必须先判 `drops > 1` 返回 -1。

## 如果面试官追问
若允许元素重复，怎么改？答：`drops` 判定失效，需找最小值首次出现位置并验证旋转后非降，O(n) 扫描即可。
