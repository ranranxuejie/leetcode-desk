## 一句话思路
每步总数减一，胜负只由 x+y 的奇偶决定：奇数先手 Alice 赢，答案即 [1,n]×[1,m] 中 x+y 为奇数的对数。

## 怎么做
1. 把游戏看成「共 x+y 朵花，每步摘一朵，摘完者胜」，所以总步数固定为 x+y，Alice 走第 1、3、5… 步。
2. 因此 Alice 赢 ⟺ x+y 为奇数，即 x、y 一奇一偶。
3. 统计：x 取奇数有 `(n+1)//2` 个、偶数有 `n//2` 个；y 同理。答案 = 奇x·偶y + 偶x·奇y。
4. 以 n=3, m=2 为例：x 奇数 2 个（1,3）、偶数 1 个（2）；y 奇数 1 个（1）、偶数 1 个（2）。答案 = 2·1 + 1·1 = 3，与示例一致。

```python
odd_n, even_n = (n + 1) // 2, n // 2
odd_m, even_m = (m + 1) // 2, m // 2
return odd_n * even_m + even_n * odd_m
```

也可以写成 `n * m // 2`：n·m 个格子按 x+y 奇偶交替，奇数格恰占一半（n·m 为奇数时少一个，整除正好向下取整）。两种写法结果相同，前者更能说明「为什么是一半」。

## 复杂度
时间 O(1)：只做四次整除和两次乘法，与 n、m 大小无关。
空间 O(1)：只开 odd_n、even_n、odd_m、even_m 四个整数。

## 易错点
- 误判终局条件：以为「摘完最后一朵的人输」或「无法行动者输」，会把 (1,1) 判成 Alice 赢；实际 (1,1) 共 2 步，Bob 摘完获胜，答案 0，与示例 2 一致。
- 用 `n * m // 2` 时把 n·m 先算成浮点或按 32 位截断：n=m=10^5 时 n·m=10^10 超出 2**31-1，若题目规定答案按 32 位截断就会出错；Python 整数不溢出，直接 `n * m // 2` 即可，不要额外取模。

## 如果面试官追问
追问：若要求输出所有满足条件的 (x, y) 方案而非计数？
答：双重循环枚举 x∈[1,n]、y∈[1,m]，只保留 (x+y) 为奇数的对，时间升到 O(nm)，计数仍用奇偶公式 O(1) 校验。
