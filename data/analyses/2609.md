## 一句话思路
按「0 段 + 紧邻的 1 段」切块，每块取 `2*min(零数, 一数)` 的最大值。

## 怎么做
1. 用 `i` 扫字符串，遇到 `'0'` 就数出这一段连续 0 的个数 `zeros`。
2. 紧接着从 `i` 数出连续 1 的个数 `ones`，这一段 0 和这一段 1 拼起来才可能平衡。
3. 更新 `ans = max(ans, 2 * min(zeros, ones))`，因为平衡子串必须 0 全在 1 前，只能从这段 0 的尾部取、这段 1 的头部取。
4. 以 `s = "01000111"` 为例：第一块 `zeros=1, ones=1` 得 2；第二块 `zeros=3, ones=3` 得 6，`ans` 停在 6，正是 `"000111"`。

```python
i, n, ans = 0, len(s), 0
while i < n:
    zeros = 0
    while i < n and s[i] == '0':
        zeros += 1; i += 1
    ones = 0
    while i < n and s[i] == '1':
        ones += 1; i += 1
    ans = max(ans, 2 * min(zeros, ones))
return ans
```

关键点：`i` 在两个内层循环后已经停在下一段 0 的起点，外层不再 `i += 1`，否则会跳过一个字符。

## 复杂度
时间 O(n)：`i` 只前进不后退，每个字符被两个内层循环之一消费一次。
空间 O(1)：只开了 `i, zeros, ones, ans` 四个整数。

## 易错点
- 输入 `"00111"`：若把整串的 0 总数 2 和 1 总数 3 直接取 `min` 得 4 看似对，但换成 `"0110"` 就会错算成 2，实际平衡子串只有 `"01"` 长 2——必须按段配对，不能全局计数。
- 输入 `"111"`：外层若在 `zeros=0` 时仍进入 1 段统计，`min(0,3)=0` 结果没错，但若写成先数 1 再数 0 的顺序，`"10"` 会被误判成平衡——顺序必须是先 0 段后 1 段。

## 如果面试官追问
若 n 放大到 10^7 且要求返回子串本身而非长度？答：同样一趟扫描，记录取得最大值的 `i - zeros - ones` 起点和长度即可，仍是 O(n)、O(1)。
