## 一句话思路
按整周和零头拆开：前 `n // 7` 周用等差数列求和，剩下 `n % 7` 天逐天累加。

## 怎么做
1. 令 `weeks = n // 7`、`days = n % 7`，把天数拆成完整周加零头。
2. 第 `w` 周（从 0 数）的 7 天是 `w+1` 到 `w+7`，和为 `7*(w+1) + 21`，对 `w = 0..weeks-1` 求和得 `weeks*(weeks+1)//2*7 + 21*weeks`。
3. 零头落在第 `weeks` 周，从 `weeks+1` 开始连续 `days` 天，和为 `days*(weeks+1) + days*(days-1)//2`。
4. 两段相加返回。

以 `n = 20` 为例：`weeks = 2`、`days = 6`。整周部分 `2*3//2*7 + 21*2 = 21 + 42 = 63`；零头是第 2 周（从 0 数）的前 6 天 `3+4+5+6+7+8 = 33`，公式给 `6*3 + 6*5//2 = 18 + 15 = 33`。合计 `63 + 33 = 96`，与示例一致。

```python
weeks, days = n // 7, n % 7
full = weeks * (weeks + 1) // 2 * 7 + 21 * weeks
rest = days * (weeks + 1) + days * (days - 1) // 2
return full + rest
```

关键点：`days == 0` 时 `rest` 自动为 0，不用特判；`weeks` 从 0 起算，所以零头的首项是 `weeks + 1` 而不是 `weeks`。

## 复杂度
时间：O(1)，只做常数次乘除，与 `n` 无关。
空间：O(1)，只开了 `weeks`、`days`、`full`、`rest` 四个整数。

## 易错点
- `n = 7` → 若把零头首项写成 `weeks` 而非 `weeks + 1`，`days = 0` 时看不出错，但 `n = 8` 会算成 `1 + 1 = 2` 而非正确的 `1`，总额少 1。正确做法是零头首项恒为 `weeks + 1`。
- `n = 1` → 若用 `(n + 6) // 7` 当周数，会得到 `weeks = 1`，把第 1 天误算进整周，结果变成 `28` 而非 `1`。正确做法是整周数用向下取整 `n // 7`，零头单独处理。

## 如果面试官追问
问：若 `n` 放大到 `10**18`，公式还成立吗？
答：成立，仍是 O(1)；只需注意中间量 `weeks*(weeks+1)//2*7` 量级约 `n²/14`，Python 大整数无溢出，若换语言需用 64 位或取模。
