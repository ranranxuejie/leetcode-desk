## 一句话思路
操作保持总和不变，故先比总和；总和相等时，除「source 全等 target」外恒可行。

## 怎么做
1. 先算 `sum(source)` 与 `sum(target)`，不等直接返回 `False`。
2. 若两数组完全相同，返回 `True`（零次操作）。
3. 总和相等但数组不同时，返回 `True`——此时 `n >= 2`，总能借一个「中转」下标把任意一位改成目标值。
4. 只有一种例外要单独想：`n == 2` 且总和相等但两元素不同，仍可行（示例 2 就是），所以无需特判。

以示例 1 为例：`source = [1,2,3]`，`target = [0,2,4]`，两边和都是 6。取 `i=0, j=2, delta=4`，则 `source[0] = 1 + 3 - 4 = 0`，`source[2] = 4`，一步到位。关键中间值就是 `1 + 3 - 4 = 0`：新 `source[i]` 等于「旧 `source[i]` + 旧 `source[j]` − delta」，而 `source[j]` 被直接赋成 delta，两者之和 `source[i]+source[j]` 前后不变。

```python
def canTransform(source, target):
    if sum(source) != sum(target):
        return False
    if source == target:
        return True
    return True
```

上面第 3 步的「恒可行」值得验一下：总和相等且数组不同，说明存在某位 `source[k] != target[k]`。选 `j = k`，令 `delta = target[k]`，则 `source[j]` 直接变成 `target[k]`；再选一个 `i != k`，令 `source[i] = source[i] + source[k] - delta`，由于总和守恒，这一步自动把差额补到 `i` 上。反复做即可逐位对齐。

## 复杂度
时间 O(n)：`sum` 和 `==` 各扫一遍，n 为数组长度。
空间 O(1)：只做求和与比较，未开额外数组。

## 易错点
- 只比总和忘了「全等」分支：`source = [1,2,3]`、`target = [1,2,3]` 时总和相等，直接返回 `True` 也对，但若写成「总和相等且数组不同才 True」，全等输入会误判 `False`，正确做法是先判 `source == target` 返回 `True`。
- 误以为 `n == 2` 需要特判：示例 2 的 `[-5,-5] → [-15,5]` 总和都是 −10，一步可达，若加「n==2 且元素不同则 False」会错，正确做法是 `n >= 2` 一律按总和判。

## 如果面试官追问
问：若要求输出具体操作序列怎么办？
答：按上面第 3 步逐位对齐，每次固定一个 `j` 把 `target[j]` 写进去，最多 n 步，输出 `(i, j, delta)` 三元组即可。
