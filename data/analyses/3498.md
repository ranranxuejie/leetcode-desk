## 一句话思路
一次遍历，用 `ord(ch) - ord('a')` 算出正序位再取 `26 - 正序位` 得反转位，乘以下标 `i+1` 累加。

## 怎么做
1. 初始化 `total = 0`，遍历 `enumerate(s)` 拿到 `i` 和 `ch`。
2. 反转位 = `26 - (ord(ch) - ord('a'))`，即 `'a'` 得 26、`'z'` 得 1。
3. 字符串位置用 `i + 1`（下标从 1 起），把 `反转位 * (i + 1)` 累加进 `total`。
4. 返回 `total`。

以 `s = "abc"` 为例，关键中间值：`i=0, ch='a'` 时反转位 `26 - 0 = 26`，乘 `1` 得 26；`i=1, ch='b'` 时反转位 `26 - 1 = 25`，乘 `2` 得 50；`i=2, ch='c'` 时反转位 `26 - 2 = 24`，乘 `3` 得 72，`total = 26 + 50 + 72 = 148`。

```python
total = 0
for i, ch in enumerate(s):
    rev = 26 - (ord(ch) - ord('a'))
    total += rev * (i + 1)
return total
```

注意 `'a'` 的 `ord(ch) - ord('a')` 是 0，反转位 26；`'z'` 是 25，反转位 1，正好对上题面表格。用 `enumerate` 而不是 `range(len(s))` 索引，少一次 `s[i]` 取值，也避免把 `i` 和 `i+1` 搞混。

## 复杂度
时间 O(n)：n 为 `s` 长度，每个字符做一次减法一次乘法。
空间 O(1)：只开了 `total`、`rev` 两个整数，无额外数组。

## 易错点
- 用 `i` 而不是 `i + 1` 当字符串位置 → `"abc"` 会算成 `26*0 + 25*1 + 24*2 = 73`，错成 73 而非 148 → 位置必须从 1 开始，写 `rev * (i + 1)`。
- 反转位写成 `ord(ch) - ord('a') + 1`（正序位）→ `"abc"` 得 `1*1 + 2*2 + 3*3 = 14`，方向反了 → 正确是 `26 - (ord(ch) - ord('a'))`，`'a'` 对应 26 而非 1。

## 如果面试官追问
若 `s` 长度放大到 10^7 且要求边读边算（流式输入）？答：仍是 O(1) 空间，维护当前下标计数器，每读一个字符即时累加，无需存整个串。
