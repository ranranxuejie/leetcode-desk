## 一句话思路
把所有 0 尽量挤到左边变成 1，最终形态是「一串 1 + 一个 0 + 剩下的 1」，用贪心定位这个 0 的位置。

## 怎么做
1. 记下第一个 `'1'` 的位置 `first`，它左边的 0 无法被操作 1 变成 1（因为没有前导 1 来配对）。
2. 统计 `first` 之后（含）所有 `'0'` 的个数 `zeros`，这些 0 都能被「搬运」并合并。
3. 最终结果：`first` 个 `'1'`，接着 `zeros-1` 个 `'1'`，再一个 `'0'`，最后补齐剩余长度的 `'1'`；若 `zeros==0` 原样返回。

以 `binary = "000110"` 为例：`first = 3`（下标 3 是第一个 1），其后 0 的个数 `zeros = 2`（下标 4、5 之外，实际是下标 4 的 0 和…需按代码数）。按代码：`first=3`，`zeros=2`，输出前 3 个 1，再 `zeros-1=1` 个 1，一个 0，剩余补 1，得 `"111011"`，与示例一致。

```python
first = binary.find('1')
if first == -1:
    return binary
zeros = binary.count('0', first)
if zeros == 0:
    return binary
n = len(binary)
return '1' * (n - zeros) + '0' + '1' * (zeros - 1)
```

关键中间值：`n - zeros` 是最终 1 的总数减一，`zeros - 1` 是那个 0 右边剩余的 1 的个数。

## 复杂度
时间：O(n)，`find` 和 `count` 各扫一遍，字符串拼接也 O(n)。
空间：O(n)，返回的新字符串本身占 n，无额外结构。

## 易错点
- 输入 `"0"` 或 `"000"`（全 0）→ `find('1')` 返回 -1，若直接算 `zeros` 会得到错误结果 → 必须先判 `first == -1` 直接返回原串。
- 输入 `"10"`（`zeros=1`）→ 若写成 `'1'*(n-zeros) + '0' + '1'*zeros` 会多出一个 1，长度变 3 → 右边必须是 `zeros-1` 个 1，因为那个 0 本身占一位。

## 如果面试官追问
问：如果允许把 `"11"` 变成 `"00"` 呢？答：贪心不再成立，需重新分析可达状态，可能要 BFS 或找不变量。
