## 一句话思路
枚举 26 个字母当两端，用首末位置夹出中间字符集合，集合大小即该字母贡献的回文数。

## 怎么做
1. 对每个字符 c，用 `s.find(c)` 和 `s.rfind(c)` 取首末下标，若 `l >= r` 则跳过（凑不出两端）。
2. 取 `s[l+1:r]` 这段中间串，转成 `set`，集合大小就是能夹在 c 中间的不同字符数。
3. 把 26 个字母的结果累加。

以 `s = "aabca"` 为例：c='a' 时 `l=0, r=4`，中间 `s[1:4] = "abc"`，集合 `{'a','b','c'}` 大小 3，贡献 "aaa"、"aba"、"aca"；c='b' 时 `l=2, r=2`，`l >= r` 跳过；c='c' 时 `l=3, r=3` 跳过。总计 3，与示例一致。

```python
total = 0
for c in set(s):
    l, r = s.find(c), s.rfind(c)
    if l >= r:
        continue
    total += len(set(s[l + 1:r]))
return total
```

关键点：外层只遍历 `set(s)` 里出现过的字母，没出现的字母 `find` 返回 -1，`l >= r` 也会被跳过，两种写法等价。

## 复杂度
时间 O(26·n)：每个字母扫一遍中间段，n 为 `len(s)`。
空间 O(26)：`set(s[l+1:r])` 最多 26 个字符，切片本身 O(n) 但可忽略。

## 易错点
- 输入 `"adc"`：若只判断 `l != r` 而不判 `l >= r`，'a' 的 `l=0, r=0` 会误算中间空串，虽然 `set("")` 大小为 0 不出错，但换成 `"aba"` 里 'b' 的 `l=r=1` 时若写成 `l > r` 判断就会漏掉合法情况——正确做法统一用 `l >= r` 跳过，因为长度 3 回文要求两端之间至少有一个字符。
- 输入 `"bbcbaba"`：若用 `s.count(c)` 或统计字符频次来判断，'b' 出现 4 次会误以为能凑出 C(4,2)=6 种，实际只有 "bbb"、"bcb"、"bab" 三种——正确做法是看首末位置之间的**不同字符集合**，而不是频次，因为中间字符只按种类计一次。

## 如果面试官追问
问：如果要求返回所有不同的回文子序列本身而不是个数？
答：把 `len(set(...))` 换成对集合里每个字符拼 `c + mid + c` 加入结果集，复杂度不变，输出规模最多 26×26。
