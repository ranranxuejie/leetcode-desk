## 一句话思路
中序遍历 BST 得到升序序列，边遍历边把节点串成只走 right 的链，前驱的 right 指向当前节点。

## 怎么做
1. 用迭代中序（显式栈）遍历，避免 100000 节点时递归爆栈。
2. 维护 `prev` 和 `head`：`prev` 是上一个访问的节点，`head` 是第一个访问的节点。
3. 每访问到 `cur`，把 `prev.right = cur`、`cur.left = None`，再 `prev = cur`。

以 `[4,2,5,1,3,null,6,0]` 为例，中序访问顺序是 0,1,2,3,4,5,6。访问到 1 时 `prev` 是 0，执行 `0.right = 1`、`1.left = None`；访问到 2 时 `prev` 是 1，执行 `1.right = 2`、`2.left = None`。最终 `head` 停在 0。

```python
stack, cur = [], root
prev = head = None
while cur or stack:
    while cur:
        stack.append(cur)
        cur = cur.left
    cur = stack.pop()
    if prev:
        prev.right = cur
    else:
        head = cur
    cur.left = None
    prev = cur
    cur = cur.right
return head
```

关键点：`cur.left = None` 必须在 `cur = cur.right` 之前做，否则改完 left 再取 right 没问题，但若先取 right 再改 left 也不影响——真正要小心的是 `prev.right = cur` 会覆盖 `prev` 原来的 right 指针，而那个 right 子树此时已经访问完了（中序保证），所以安全。

## 复杂度
时间 O(n)：每个节点入栈出栈各一次，指针改写 O(1)。
空间 O(h)：栈深度等于树高，最坏链状树 O(n)，平衡树 O(log n)。

## 易错点
- 输入 `[4,2,5,1,3,null,6,0]` 若用递归中序，链状退化树（100000 个节点全在左）会触发 Python 默认递归深度约 1000 的限制 → `RecursionError` → 必须用显式栈迭代。
- 忘记把 `cur.left = None`：输出里 2 的 left 仍指向 1，判题按 `[0,null,1,null,2,...]` 逐位比对时，2 的 left 非空直接判错 → 每个节点出栈后立刻置空 left，且 `head` 的 left 也要为 None（第一个节点 `prev` 为 None，同样执行了 `cur.left = None`）。

## 如果面试官追问
问：节点数涨到 10^7 怎么办？
答：迭代中序空间仍是 O(h)，但 10^7 次 Python 循环偏慢，可改 Morris 中序做到 O(1) 额外空间，代价是临时改指针再复原。
