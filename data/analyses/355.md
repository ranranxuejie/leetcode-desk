## 一句话思路
每个用户一条推文链表（头插），getNewsFeed 用大顶堆按时间戳归并所有关注者（含自己）的链表头，取前 10 条。

## 怎么做
1. 全局自增 `time`，`postTweet` 时把 `(time, tweetId)` 头插进 `tweets[userId]`，保证每条链表内时间戳递减。
2. `follow` 往 `follows[followerId]` 集合里加 `followeeId`；`unfollow` 用 `discard` 而不是 `remove`，避免取消未关注的人时抛 KeyError。
3. `getNewsFeed` 先取 `follows[userId] | {userId}`，把每个用户链表头 `(time, tweetId, userId, node)` 压入堆，堆按 `time` 取负或直接存负时间戳。
4. 弹堆顶取 `tweetId`，若该用户链表还有下一个节点就继续压入，凑满 10 条或堆空即停。

以官方示例为例：`postTweet(1,5)` 后 `tweets[1]` 头节点是 `(time=1, 5)`；`follow(1,2)` 后 `follows[1]={2}`；`postTweet(2,6)` 后 `tweets[2]` 头是 `(time=2, 6)`。此时 `getNewsFeed(1)` 的候选集合是 `{1,2}`，堆里两个头节点时间戳分别为 2 和 1，先弹出 6 再弹出 5，得到 `[6,5]`。

```python
import heapq

def getNewsFeed(self, userId):
    users = self.follows[userId] | {userId}
    heap = []
    for u in users:
        if self.tweets[u]:
            node = self.tweets[u]
            heapq.heappush(heap, (-node.time, node.tweetId, u, node))
    res = []
    while heap and len(res) < 10:
        _, tid, u, node = heapq.heappop(heap)
        res.append(tid)
        if node.next:
            heapq.heappush(heap, (-node.next.time, node.next.tweetId, u, node.next))
    return res
```

## 复杂度
时间：`getNewsFeed` 为 O(F + 10·log F)，F 是关注数；`postTweet`/`follow` 均摊 O(1)。
空间：O(T + F)，T 为总推文数（链表节点），F 为关注关系集合大小。

## 易错点
- `unfollow(1, 2)` 时若 1 从未关注 2，用 `set.remove` 会抛 KeyError → 应改用 `discard`，示例中 `unfollow` 前已 `follow` 过所以不暴露，但测试用例会踩。
- `getNewsFeed` 忘记把 `userId` 自己并入候选集合 → 示例第一次 `getNewsFeed(1)` 会返回 `[]` 而不是 `[5]`，因为此时 `follows[1]` 还是空集。

## 如果面试官追问
问：若关注数 F 很大（如 10^4）且频繁 getNewsFeed 怎么办？
答：改为全局时间戳 + 按时间倒序扫描所有关注者链表，或用分段合并缓存，避免每次重建 F 大小的堆。
