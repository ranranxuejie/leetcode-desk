## 一句话思路
用哈希表把商品 id 映射到单价，再用一个计数器 `count` 记录当前是第几位顾客，每满 `n` 位就打折并清零。

## 怎么做
1. 构造时把 `products[i]` 和 `prices[i]` 配对存进字典 `self.price`，并初始化 `self.count = 0`。
2. 每次 `getBill` 先把 `self.count += 1`，再判断 `self.count == self.n`。
3. 遍历 `product` 与 `amount`，累加 `self.price[p] * a` 得到原价 `total`。
4. 若命中折扣，返回 `total - total * self.discount / 100`，并把 `self.count` 归零。

以官方示例第 3 次调用为例：`count` 从 2 变成 3，等于 `n = 3`，此时 `total = 100+200+300+400+300+200+100 = 1600`，折扣后 `1600 - 1600*50/100 = 800.0`，与输出一致；随后 `count` 重置为 0，所以第 4、5 次调用都不打折。

```python
def getBill(self, product, amount):
    self.count += 1
    total = 0
    for p, a in zip(product, amount):
        total += self.price[p] * a
    if self.count == self.n:
        total -= total * self.discount / 100
        self.count = 0
    return total
```

注意折扣判断放在累加之后、返回之前，且 `count` 归零必须发生在打折分支内部，否则第 4 位顾客会被误判。

## 复杂度
时间：每次 `getBill` 为 O(len(product))，最多 200，1000 次调用共 O(1000 × 200)。
空间：字典存至多 200 个商品价格，O(products.length)，其余为常数。

## 易错点
- 折扣判断写成 `self.count % self.n == 0` 且初始 `count = 0` → 第一位顾客就被打折（示例 1 会返回 250 而非 500）→ 应先自增再比较 `== self.n`，或初始化为 1 后用取模。
- 用 `total * (100 - discount) / 100` 之外的写法如 `total * discount / 100` 直接当结果 → 示例 1 第 3 次返回 800 却算成 800 的折扣额 800（碰巧相等），换 `discount = 20` 就错成 320 而非 1280 → 必须用 `total - total * discount / 100`。

## 如果面试官追问
若 `n` 很大而调用次数少，能否避免每次比较？答：计数器只在 `count == n` 时归零，比较是 O(1)，无需优化；真正可优化的是把 `product` 中重复 id 合并后再乘，但题目保证单次购买不重复。
