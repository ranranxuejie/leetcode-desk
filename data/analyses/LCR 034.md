## 一句话思路
把 `order` 转成「字母→排名」的哈希表，再逐对比较相邻单词，第一个不同字母的排名决定大小。

## 怎么做
1. 建 `rank = {c: i for i, c in enumerate(order)}`，之后任意字母比较都是 O(1)。
2. 遍历 `i` 从 0 到 `len(words)-2`，只比较 `words[i]` 和 `words[i+1]` 这一对。
3. 逐位比到第一个不同字母就返回 `rank[a] < rank[b]`；若前缀全相同，则要求 `len(words[i]) <= len(words[i+1])`。
4. 任一对不满足即返回 `False`，全部通过返回 `True`。

拿示例 2 走一遍：`words = ["word","world","row"]`，`order = "worldabcefghijkmnpqstuvxyz"`。比较 `"word"` 与 `"world"`，前三位 `w,o,r` 相同，第 4 位 `d` vs `l`，此时 `rank['d'] = 4`、`rank['l'] = 3`，`4 < 3` 为假，直接返回 `False`，不用再看 `"row"`。

```python
rank = {c: i for i, c in enumerate(order)}
for i in range(len(words) - 1):
    a, b = words[i], words[i + 1]
    for j in range(min(len(a), len(b))):
        if a[j] != b[j]:
            if rank[a[j]] > rank[b[j]]:
                return False
            break
    else:
        if len(a) > len(b):
            return False
return True
```

关键在 `for...else`：内层循环没被 `break` 打断，说明短的那个是长的前缀，此时才需要检查长度。

## 复杂度
时间 O(N·L)，N 是单词数、L 是最长单词长度（≤20），每对单词最多扫 L 个字符。
空间 O(1)，`rank` 固定 26 项，与输入规模无关。

## 易错点
1. 输入 `words = ["apple","app"]`、`order` 为正常字母表 → 若只比公共前缀就返回 `True`，会错成 `True`；正确做法是前缀相同时比较长度，`len("apple") > len("app")` 判 `False`。
2. 输入 `words = ["hello","leetcode"]`、`order = "hlabcdefgijkmnopqrstuvwxyz"` → 若拿 `order.index()` 每次现查，虽结果对但慢；更隐蔽的错是拿字符 ASCII 直接比，`'h' < 'l'` 恰好成立但示例 2 的 `'d' > 'l'` 会判反，必须走 `rank` 表。

## 如果面试官追问
问：如果 `words` 有 10^5 个、每个长 10^4，怎么优化？
答：瓶颈是逐字符比较，可先按首字母分桶，桶内再比；或用 Trie 存所有单词，一次 DFS 判断序列是否单调。
