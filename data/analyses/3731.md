## 一句话思路
把 `nums` 转成集合，从 `min(nums)` 遍历到 `max(nums)`，不在集合里的就是缺失值。

## 怎么做
1. 取 `lo = min(nums)`、`hi = max(nums)`，题目保证两端都在数组里，所以范围就是 `[lo, hi]`。
2. 用 `set(nums)` 做 O(1) 成员判断，避免每步都 `in nums` 变成 O(n²)。
3. 从 `lo` 到 `hi` 逐个检查，不在集合中就追加到结果列表，天然有序。

以 `nums = [1,4,2,5]` 为例：`lo = 1`、`hi = 5`、`s = {1,2,4,5}`。循环到 `x = 3` 时 `3 not in s` 成立，追加 `3`；其余 1、2、4、5 都在集合里被跳过，最终返回 `[3]`。

```python
s = set(nums)
lo, hi = min(nums), max(nums)
res = []
for x in range(lo, hi + 1):
    if x not in s:
        res.append(x)
return res
```

范围长度是 `hi - lo + 1`，最多 100（因为 `nums[i] <= 100`），所以这个朴素循环完全够用。若数据规模放大到 10^9 级别，就得换成「排序后看相邻差」的写法，但本题不需要。

## 复杂度
时间：O(n + (hi - lo))，n 来自建集合与求最值，范围长度来自遍历。
空间：O(n)，集合存了全部 n 个元素，结果列表最多 O(hi - lo)。

## 易错点
- 输入 `nums = [5,1]` → 若只写 `range(min(nums), max(nums))` 漏掉 `+1`，会漏掉最大值 5 这一端，虽然 5 本身存在不影响结果，但换成 `[1,2,5]` 就会漏判边界；正确写法是 `range(lo, hi + 1)`。
- 输入 `nums = [7,8,6,9]` → 若用 `for x in range(lo, hi)` 且没做集合判断、直接按索引差推断，容易把「连续无缺失」误判成有缺失；正确做法是逐个 `x not in s` 判断，本例全部命中，返回 `[]`。

## 如果面试官追问
问：如果 `nums[i]` 上限放大到 10^9 怎么办？
答：改用排序后扫描相邻元素差，差大于 1 就把中间整数补进结果，时间 O(n log n)，不依赖值域大小。
