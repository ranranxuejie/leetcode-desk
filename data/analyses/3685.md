## 一句话思路
对每个 x 单独做 0/1 背包太慢，改为按 x 递增维护可达和集合，用「排序 + 双指针」把每个 x 的判定压到 O(k)。

## 怎么做
1. 把 `nums` 排序，记 `cnt[v]` 为值 v 的出现次数，值域 1..n。
2. 对固定 x，capped 后值只有 1..x，且值 v 的个数为 `cnt[v]`（v<x）或「所有 ≥x 的个数」（v=x）。
3. 关键观察：x 增大时，原来被截成 x 的元素变成 x+1，可达和集合只会「变大」，用增量 DP 维护 `reach[s]` 表示和 s 是否可达。
4. 对每个 x，只需把「值恰好为 x 的那批元素」加入背包（多重背包，二进制拆分或按个数循环），再读 `reach[k]`。

以 `nums=[4,3,2,4], k=5` 为例：排序后 `[2,3,4,4]`，`cnt[2]=1,cnt[3]=1,cnt[4]=2`。x=1 时全部截成 1，共 4 个 1，`reach` 只到 4，`reach[5]=False`；x=3 时加入值 2 和 3，`reach[2]=True`、`reach[3]=True`，于是 `reach[5]=reach[2] or reach[3]` 中 `reach[2] and 3 可达` 成立，输出 True。

```python
reach = [False] * (k + 1)
reach[0] = True
ans = [False] * n
for x in range(1, n + 1):
    c = cnt[x] if x < n else 0
    # 值 x 的元素：cnt[x] 个，加上所有 > x 的（它们被截成 x）
    c += sum(cnt[x + 1:]) if x < n else 0
    for _ in range(c):
        for s in range(k, x - 1, -1):
            if reach[s - x]:
                reach[s] = True
    ans[x - 1] = reach[k]
```

## 复杂度
时间：O(n·k) 最坏（每个 x 加 c 个元素，总元素数 O(n)，每个元素 O(k) 更新）。
空间：O(k) 的 `reach` 数组，外加 O(n) 的 `cnt`。

## 易错点
- 输入 `nums=[1,2,3,4,5], k=3`：若只把「值恰好为 x」的元素入背包，x=1 时只有 1 个 1，`reach[3]` 为 False，错判；正确做法是把所有 ≥x 的元素都截成 x 一起加入，x=1 时有 5 个 1，`reach[3]=True`。
- 输入 `nums=[4,3,2,4], k=5`，x=1：若忘记子序列非空，`reach[0]=True` 会让 `reach[5]` 误判为 True；正确做法是只在 `s>=x` 时更新，且最终读 `reach[k]` 时 k≥1 天然非空。

## 如果面试官追问
问：k 增大到 10^5 怎么办？答：改用 bitset 维护 `reach`，每个元素一次移位或运算，复杂度降到 O(n·k/64)。
