## 一句话思路
对每个任务算 `s + t` 取最小值，因为任务互不影响、可并行，最早完成者就是单任务完成时间的最小值。

## 怎么做
1. 遍历 `tasks`，每个元素解包成 `s, t`。
2. 对每个任务算完成时刻 `s + t`。
3. 用 `min` 维护当前最小完成时刻，初始为无穷大。
4. 返回该最小值。

以示例 1 `tasks = [[1,6],[2,3]]` 为例：第一个任务 `s + t = 1 + 6 = 7`，第二个 `2 + 3 = 5`；`min(7, 5)` 得 5，即答案。关键中间值是第二个任务的 5，它比 7 小，所以覆盖了初始值。

```python
def earliestTime(tasks):
    best = float('inf')
    for s, t in tasks:
        finish = s + t
        if finish < best:
            best = finish
    return best
```

也可以一行：`return min(s + t for s, t in tasks)`。注意 `min` 的生成器里解包的是 `tasks` 的每个 `[s, t]`，不是下标。

## 复杂度
时间 O(n)：n 为 `tasks.length`，每个任务只算一次加法。
空间 O(1)：只存 `best` 一个变量，生成器版本也不额外开列表。

## 易错点
- 输入 `[[100,100],[100,100],[100,100]]` → 若误以为任务要串行排队、把三个 100 累加成 300 → 正确做法是每个任务独立算 `s + t`，三个都是 200，返回 200。
- 输入 `[[5,1],[1,100]]` → 若按 `s` 排序后取第一个任务的完成时间，会得到 `5 + 1 = 6`，但真正最早的是 `1 + 100 = 101`？不对，6 更小，排序反而没错；真正的坑是只比较 `t` 而不加 `s`：`t` 最小的是 1，但完成时刻是 6，若直接返回 `min(t)` 得 1，错。正确做法是必须比较 `s + t` 而非单独的 `t` 或 `s`。

## 如果面试官追问
若任务改为必须串行、同一时刻只能做一个，怎么求全部完成的最早时间？答：按 `s` 排序后维护当前时刻 `cur = max(cur, s) + t`，取最后一个的 `cur`。
