## 一句话思路
按 `class` 分组计数，用 `HAVING COUNT(*) >= 5` 过滤，因为「至少 5 名学生」就是分组后行数阈值。

## 怎么做
1. 对 `Courses` 按 `class` 做 `GROUP BY`，把同一门课的行聚成一组。
2. 每组用 `COUNT(*)` 数行数；主键是 `(student, class)`，所以行数等于选课人数，不会重复计数。
3. 用 `HAVING COUNT(*) >= 5` 只留人数达标的组，`WHERE` 不能筛聚合值。
4. 只 `SELECT class`，顺序任意。

拿官方示例走一遍：`Math` 组有 A、C、E、G、H、I 共 6 行，`6 >= 5` 保留；`English` 组只有 B 一行，`1 >= 5` 为假被丢弃；`Biology`、`Computer` 同理各 1 行被丢。最终只剩 `Math`。

```python
# 思路等价写法（pandas），核心是 size() 而非 count()
df = courses.groupby("class").size().reset_index(name="cnt")
res = df[df["cnt"] >= 5][["class"]]
```

SQL 版本关键三行：

```sql
SELECT class
FROM Courses
GROUP BY class
HAVING COUNT(*) >= 5;
```

注意 `COUNT(student)` 和 `COUNT(*)` 在这题结果相同（`student` 无 NULL 且是主键一部分），但 `COUNT(*)` 语义更贴「行数=人数」。

## 复杂度
时间：O(n)，n 为 `Courses` 行数，分组哈希扫一遍。
空间：O(k)，k 为不同 `class` 数，存分组计数。

## 易错点
- 用 `WHERE COUNT(*) >= 5` → 聚合函数不能出现在 `WHERE`，会直接报错 → 必须放 `HAVING`。
- 用 `COUNT(DISTINCT student)` 却忘了主键已保证唯一 → 结果虽对但多一次去重开销；若表允许同学生重复选同一课，则 `COUNT(*)` 会虚高，此时才需要 `DISTINCT`。

## 如果面试官追问
问：若要求「至少 5 名**不同**学生且排除退课记录」怎么办？
答：先 `WHERE status = 'enrolled'` 过滤，再 `COUNT(DISTINCT student) >= 5`，两步不能合并到 `HAVING` 里做过滤。
