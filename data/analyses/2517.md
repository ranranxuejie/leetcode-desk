## 一句话思路
把 price 排序后二分答案 d，用贪心从左往右数能塞进多少个间隔 ≥ d 的糖果，够 k 个就说明 d 可行。

## 怎么做
1. 排序 `price`，答案范围是 `[0, max(price) - min(price)]`，二分这个区间。
2. 对候选 `d` 做贪心判定：取第一个元素，之后每个元素只要与上一个被选元素差 ≥ `d` 就选它，计数。
3. 计数 ≥ `k` 则 `d` 可行，收缩左界；否则收缩右界。
4. 二分结束返回左界。

以 `price = [13,5,1,8,21,2], k = 3` 为例：排序得 `[1,2,5,8,13,21]`。判 `d = 8` 时，选 1 → 下一个 ≥ 9 的是 13 → 下一个 ≥ 21 的是 21，计数 3 ≥ 3，可行；判 `d = 9` 时选 1 → 13 → 21 后无元素，仍为 3？注意 13 到 21 差 8 < 9，所以 21 不能被选，计数只有 2，不可行。故答案 8。

```python
price.sort()
lo, hi = 0, price[-1] - price[0]
while lo < hi:
    mid = (lo + hi + 1) // 2
    cnt, last = 1, price[0]
    for p in price[1:]:
        if p - last >= mid:
            cnt += 1
            last = p
    if cnt >= k:
        lo = mid
    else:
        hi = mid - 1
return lo
```

关键点：`mid = (lo + hi + 1) // 2` 必须上取整，否则 `lo = mid` 会死循环；`cnt` 初值为 1 因为第一个元素必选。

## 复杂度
时间：排序 O(n log n)，二分 O(log(max-min)) 轮、每轮 O(n)，合计 O(n log n + n log V)。
空间：排序额外 O(log n) 栈空间，其余 O(1)。

## 易错点
- `price = [7,7,7,7], k = 2` → 若二分下界写成 1 或贪心判定用 `>` 而非 `>=`，会错成返回 1 或死循环；正确做法是 `lo` 从 0 起、判定用 `p - last >= mid`，让重复价格自然被跳过，答案落到 0。
- `price = [1,3,1], k = 2` → 若不排序直接按原顺序贪心，选 1 后下一个差 ≥ 2 的元素是 3，看似没问题，但换成 `[3,1,2]` 这类乱序就会漏选；必须先 `price.sort()` 再从左扫，保证贪心选到的是最紧凑的可行集合。

## 如果面试官追问
要求输出具体选了哪些糖果怎么办？答：判定函数里把选中的 `p` 追加进临时列表，二分收敛后重跑一次 `d = lo` 的判定即可拿到方案。
