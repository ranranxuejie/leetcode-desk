## 一句话思路
对每个查询直接切片 `nums[i][-trim:]` 后排序，键取 `(裁剪串, 下标)`，因为 n、q 都只有 100，暴力足够。

## 怎么做
1. 遍历 `queries`，对每个 `[k, trim]` 生成 `(nums[i][-trim:], i)` 的列表。
2. 用 `list.sort()` 排序，元组比较天然先比裁剪串、再比下标，正好满足「同值下标小者更小」。
3. 取排序后第 `k-1` 个元组的第二个元素作为答案。

以示例 1 的 `[4,2]` 为例：裁剪后得到 `[("02",0),("73",1),("51",2),("14",3)]`，排序为 `("02",0),("14",3),("51",2),("73",1)`，第 4 个是 `("73",1)`，答案 `1`。

```python
ans = []
for k, trim in queries:
    pairs = [(nums[i][-trim:], i) for i in range(len(nums))]
    pairs.sort()
    ans.append(pairs[k - 1][1])
```

注意 `nums[i][-trim:]` 在 `trim == len(nums[i])` 时返回整串，不会越界；前导 0 保留在字符串里，但字符串比较 `"02" < "14"` 与数值比较一致，因为长度都等于 `trim`。

## 复杂度
时间：每个查询排序 O(n log n)，共 O(q · n log n)，n 来自 nums 长度，log n 来自排序。
空间：每次查询开一个长度 n 的 pairs 列表，O(n)。

## 易错点
- 输入 `nums = ["24","37","96","04"], queries = [[2,1]]`：若只按裁剪串排序而丢掉下标，两个 `"4"` 无法区分，可能返回下标 0；正确做法是排序键用 `(裁剪串, 下标)` 元组，让下标 3 的 `"4"` 排在后面，第 2 小才是下标 3。
- 输入 `nums = ["102","473","251","814"], queries = [[1,1]]`：若把裁剪串转成 `int` 再比较，`"02"` 和 `"2"` 会混淆，且前导 0 信息丢失；正确做法是保持字符串比较，长度统一为 `trim` 时字典序等价于数值序。

## 如果面试官追问
问：n 放大到 10^5、q 也 10^5 怎么办？
答：按 trim 分组离线处理，对每个 trim 用基数排序从右往左逐位稳定排序，复用上一轮顺序，总代价 O((n+q)·L)。
