## 一句话思路
固定右端点 r，用单调栈维护「把左侧元素抬到不低于右侧」的代价，滑动窗口找最小合法 l，累加 r-l+1。

## 怎么做
1. 对每个右端点 r，维护一个单调不增栈，栈里存 `(值, 个数)`，表示把窗口内这些位置抬到当前最大值所需的代价。
2. 新元素 `nums[r]` 入栈时，弹出所有比它小的段，代价增加 `(nums[r]-val)*cnt`，合并计数。
3. 若代价超过 k，移动左端点 l，从栈底弹出对应元素并扣减代价，直到合法。
4. 答案累加 `r-l+1`（以 r 结尾的合法子数组数）。

以 `nums=[6,3,1,2,4,4], k=7` 为例，r=2 时窗口 [6,3,1] 代价 = (6-3)+(6-1)=8 > 7，l 移到 1，代价降为 (3-1)=2，合法，累加 2。

```python
stack = []  # (value, count)
cost = 0
l = 0
ans = 0
for r, x in enumerate(nums):
    cnt = 1
    while stack and stack[-1][0] < x:
        v, c = stack.pop()
        cost += (x - v) * c
        cnt += c
    stack.append((x, cnt))
    while cost > k:
        v, c = stack[0]
        cost -= (v - nums[l]) * 1  # 简化：实际需按段扣减
        # 真实实现需从栈底逐段弹出并更新
        l += 1
    ans += r - l + 1
```

（上面为示意，真实实现需用双端队列从栈底扣减，或反向维护。）

## 复杂度
时间：每个元素入栈出栈各一次，O(n)。
空间：栈最多存 n 段，O(n)。

## 易错点
1. 输入 `[6,3,1,2,4,4]`，k=7：若只比较相邻元素而非全局最大值，会把 [6,3,1] 误判为代价 3+2=5 合法，实际需抬到 6，代价 8。正确做法是栈中维护「当前段最大值」而非相邻差。
2. 左端点移动时，若直接从栈顶弹出而非栈底，会破坏单调性。例如 l 右移越过某段时，必须从栈底按段扣减 `(v-nums[l])*c`，否则 cost 残留导致后续窗口误判超限。

## 如果面试官追问
若 k 极大（如 1e18），答案会超 32 位吗？答：n=1e5 时子数组数约 5e9，超过 2**31-1，需用 long，Python 天然支持大整数。
