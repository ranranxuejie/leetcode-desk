## 一句话思路
用前缀和 + 回溯：根到当前节点的路径和减去目标和，若这个差值在祖先路径上出现过 k 次，就有 k 条路径以当前节点结尾。

## 怎么做
1. 维护 `prefix` 字典，记录从根到当前节点路径上各前缀和出现的次数，初始 `{0: 1}`（空路径，让「从根开始」的路径也能被统计）。
2. DFS 进入节点时，更新 `cur = cur + node.val`，答案累加 `prefix.get(cur - sum, 0)`。
3. 把 `cur` 计入 `prefix`，递归左右子树，返回前把 `cur` 的计数减回去（回溯）。
4. 以官方示例 `sum = 22` 走一遍：到节点 `2`（路径 5→4→11→2）时 `cur = 22`，查 `prefix[22-22] = prefix[0] = 1`，命中 `[5,4,11,2]`；到节点 `5`（路径 5→8→4→5）时 `cur = 22`，同样命中；到节点 `7`（路径 5→4→11→7）时 `cur = 27`，查 `prefix[27-22] = prefix[5] = 1`，命中 `[4,11,7]`。

```python
def dfs(node, cur):
    if not node:
        return 0
    cur += node.val
    cnt = prefix.get(cur - sum, 0)
    prefix[cur] = prefix.get(cur, 0) + 1
    cnt += dfs(node.left, cur) + dfs(node.right, cur)
    prefix[cur] -= 1
    return cnt
```

## 复杂度
时间 O(n)：每个节点只进出一次，字典查询均摊 O(1)。
空间 O(n)：递归栈最坏 O(n)（链状树），`prefix` 最多存 O(n) 个不同前缀和。

## 易错点
- 忘记 `prefix = {0: 1}` 初始化 → 所有从根节点开始的路径（如 `[5,4,11,2]`）全部漏掉 → 必须把空前缀和 0 预置一次。
- 回溯时写成 `del prefix[cur]` 而不是 `prefix[cur] -= 1` → 当两条不同分支产生相同前缀和时（示例中 5 和 5→8→4→5 都经过和 22），会误删别的分支的计数 → 只减计数，减到 0 也保留键。

## 如果面试官追问
要求输出所有路径本身而非数量？答：把 `prefix` 的值从计数改成「前缀和 → 节点列表」，命中时沿列表回溯拼出路径，空间升到 O(n·路径长)。
