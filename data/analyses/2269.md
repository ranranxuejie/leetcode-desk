## 一句话思路
把 num 转成字符串后枚举所有长度 k 的连续窗口，转成整数判断能否整除 num，0 直接跳过。

## 怎么做
1. 令 `s = str(num)`，`n = len(s)`，答案 `ans = 0`。
2. 枚举起点 `i` 从 0 到 `n - k`，取切片 `s[i:i+k]`。
3. 用 `int(s[i:i+k])` 转成整数 `v`，若 `v != 0 and num % v == 0` 则 `ans += 1`。
4. 返回 `ans`。

以 `num = 430043, k = 2` 为例，`s = "430043"`，共 5 个窗口：`"43"→43`、`"30"→30`、`"00"→0`、`"04"→4`、`"43"→43`。其中 `430043 % 43 == 0` 成立两次，`430043 % 30 == 23`、`430043 % 4 == 3` 均不整除，`"00"` 转成 0 被跳过，所以 `ans = 2`。

```python
s = str(num)
n = len(s)
ans = 0
for i in range(n - k + 1):
    v = int(s[i:i + k])
    if v != 0 and num % v == 0:
        ans += 1
return ans
```

关键点：`int("04")` 得到 4 而不是报错，前缀 0 天然被 `int` 吃掉，不需要额外处理；`int("00")` 得到 0，必须靠 `v != 0` 挡掉，否则 `num % 0` 会抛 `ZeroDivisionError`。

## 复杂度
时间：O(n·k)，n 为 num 的位数，每个窗口切片加转整数花 O(k)。
空间：O(n)，`str(num)` 存了一份字符串，其余是常数。

## 易错点
- 输入 `num = 1000, k = 3` → 窗口 `"000"` 转成 0，若漏写 `v != 0` 会直接 `ZeroDivisionError` 崩掉 → 必须先判 `v != 0` 再取模。
- 输入 `num = 240, k = 2` → 若用 `num % int(...)` 前不转字符串、直接对数字做位运算取窗口，容易把 `"40"` 错算成 4 或 40 之外的数 → 统一走 `str(num)` 切片再 `int`，保证 `"40"→40`、`"04"→4` 的语义正确。

## 如果面试官追问
问：num 上限提到 10^18、k 也很大怎么办？
答：位数最多 19，窗口数仍是 O(n)，切片转整数的 O(k) 可忽略，原做法不变。
