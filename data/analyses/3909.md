## 一句话思路
先线性扫出峰值下标 `p`，再用前缀和一次遍历同时累加两段，避免重复求和。

## 怎么做
1. 从 `i=1` 开始向右扫，第一个满足 `nums[i] < nums[i-1]` 的位置，峰值就是 `i-1`。
2. 用 `sum(nums[:p+1])` 得递增部分和 `left`，`sum(nums[p:])` 得递减部分和 `right`。
3. 比较 `left` 与 `right`，按题意返回 `0` / `1` / `-1`。

以 `nums = [1,3,2,1]` 为例：`i=2` 时 `nums[2]=2 < nums[1]=3`，故 `p=1`；`left = 1+3 = 4`，`right = 3+2+1 = 6`，`left < right` 返回 `1`。

```python
p = 1
while p < len(nums) and nums[p] > nums[p - 1]:
    p += 1
p -= 1                      # 峰值下标
left = sum(nums[:p + 1])
right = sum(nums[p:])
if left > right:
    return 0
return 1 if right > left else -1
```

注意 `p` 初值取 1 而非 0：若从 0 起，`nums[0] > nums[-1]` 会拿首尾比较，双调数组首元素通常小于末元素，循环会立刻误停。峰值同时计入两段，所以切片是 `[:p+1]` 和 `[p:]`，不是 `[:p]` 和 `[p+1:]`。

## 复杂度
时间 O(n)：找峰值一次扫描 + 两段求和各扫一遍，共 3n 次访问。
空间 O(1)：只用 `p`、`left`、`right` 三个变量（切片会临时开 O(n)，可改成循环累加）。

## 易错点
- 输入 `[1,2,4,3]`（峰值在倒数第二个）→ 若循环条件写成 `nums[p] >= nums[p-1]`，遇到相等会继续走，但双调数组严格递增不会相等，真正的问题是循环结束后忘记 `p -= 1`，峰值下标偏一位，`left` 少加峰值、`right` 多加一个元素 → 正确做法是循环退出时 `p` 指向第一个下降位置，必须回退一位。
- 输入 `[2,4,5,2]` → 若把峰值只算进递减部分（`left = sum(nums[:p])`），得 `left=6`、`right=7`，误返回 `1`，而正确答案是 `0` → 峰值必须两边都算，切片用 `[:p+1]` 与 `[p:]`。

## 如果面试官追问
若要求 O(log n)：双调数组上二分找峰值——比较 `nums[mid]` 与 `nums[mid+1]`，上升则峰值在右侧，下降则在左侧，但两段求和仍需 O(n)，除非再维护前缀和数组。
