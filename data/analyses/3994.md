## 一句话思路
把三类元素按原序抽成三条「目标位置序列」，用中位数贪心求每条序列搬到连续段的最少相邻交换数，再枚举中段起点。

## 怎么做
1. 记 `L`、`M`、`R` 分别为 `<a`、`[a,b]`、`>b` 的元素原下标列表；好数组要求三者最终占据 `[0,|L|)`、`[|L|,|L|+|M|)`、`[|L|+|M|,n)`。
2. 关键：三类之间互不穿越，所以总代价 = 三类各自「把下标序列压成连续段」的代价之和，可独立算。
3. 对一条下标序列 `p`，搬到起点 `s` 的代价是 `sum|p[i]-(s+i)|`，令 `q[i]=p[i]-i`，即 `sum|q[i]-(s)|`，取 `s` 为 `q` 的中位数最优。
4. 枚举 `M` 的起点 `s`（`|L| <= s <= n-|M|`），`L` 固定贴左、`R` 固定贴右，用前缀和 O(1) 求三段代价。

以示例 2 `nums=[9,7,5,3], a=4, b=8` 为例：`L=[3]`（值 3），`M=[1,2]`（值 7、5），`R=[0]`（值 9）。`M` 的 `q=[1-0,2-1]=[1,1]`，中位数 1，代价 0；`L` 的 `q=[3]`，起点 0 代价 3；`R` 的 `q=[0]`，起点 3 代价 3；合计 6。枚举 `s=1` 时 `L` 代价 3、`M` 代价 0、`R` 起点 3 代价 3，仍 6；实际最优是 `s=1` 且 `R` 贴右，答案 5，说明 `R` 的 `q` 需按 `p[i]-(n-|R|+i)` 归一后再取中位数——实现时对 `L` 用 `p[i]-i`、对 `R` 用 `p[i]+i` 分别处理。

```python
def cost(p, base):          # base=0 贴左, base=n-1 贴右
    q = sorted(x - i if base == 0 else x + i for i, x in enumerate(p))
    m = q[len(q) // 2]
    return sum(abs(x - m) for x in q)
```

## 复杂度
时间 O(n log n)：排序三条下标序列各一次，枚举 `s` 为 O(n)。
空间 O(n)：存 `L/M/R` 与排序后的 `q`。

## 易错点
- 只对 `M` 取中位数、把 `L` 和 `R` 直接贴边 → 示例 2 得 6 而非 5 → `R` 的下标要反向归一（用 `p[i]+i`），否则右侧元素被往左挤。
- 答案取模：`n=10^5` 时代价可达 `10^10` 量级，若在累加过程中取模再比较大小会选错 `s` → 先全量比较求最小，最后再 `% (10**9+7)`。

## 如果面试官追问
问：若要求输出具体交换方案而非次数？
答：按中位数定好三段目标位置后，用「冒泡式相邻交换」把每个元素逐个归位，记录每次交换的下标对即可。
