## 一句话思路
贪心：只从「右侧最大值」的位置起跳，把每一段距离都乘上该段能拿到的最大 nums[i]。

## 怎么做
1. 从右往左扫，维护后缀最大值 `mx`，记录每个位置右侧（含自身）的最大值。
2. 得分等价于 `sum(nums[i] * 1)` 对每个「严格大于右侧所有值」的位置 i 累加，其余位置跳过。
3. 用 `[1,3,1,5]` 走一遍：从右扫，i=3 时 `mx=5`；i=2 时 `nums[2]=1<5` 跳过；i=1 时 `nums[1]=3<5` 跳过；i=0 时 `nums[0]=1<5` 跳过——这样只累加 5，得 5，错。正确做法是**从左往右**：维护当前能跳到的最大 `nums` 值，遇到更大的就切换起跳点。

正确贪心：从左往右，`cur = nums[0]`，对每个 i，若 `nums[i] > cur` 则 `cur = nums[i]`；每步累加 `cur`。`[1,3,1,5]`：i=0 加 1，i=1 时 3>1 切换 cur=3 加 3，i=2 加 3，i=3 时 5>3 切换 cur=5 加 5，总 12？不对——最后一步不该加。

关键：得分是 `(j-i)*nums[i]`，等价于「每跨一格，乘当前所在位置的 nums」。所以从左往右，每走一格累加当前 `cur`，但**最后一格不累加**（到达即止）。`[1,3,1,5]`：i=0→1 加 1（cur=1），i=1 切换 cur=3，i=1→2 加 3，i=2→3 加 3，共 7。✓

```python
cur = nums[0]
score = 0
for i in range(1, len(nums)):
    score += cur
    if nums[i] > cur:
        cur = nums[i]
return score
```

## 复杂度
时间：O(n)，一次左到右扫描，每个元素常数次比较。
空间：O(1)，只开 `cur` 和 `score` 两个变量。

## 易错点
- `nums = [4,3,1,3,2]`：若在 i=1 就因 3<4 不切换、却仍用 cur=4 累加到底，得 4*4=16 正确；但若误在 i=3 因 3<4 提前切换成 3，会得 4+4+4+3=15。正确是全程 cur=4，只在严格更大时切换。
- 循环里先 `score += cur` 再判断切换：`[1,3,1,5]` 若顺序反了，i=1 会先切换 cur=3 再加，i=0→1 那段被算成 3 而非 1，得 9。必须先加旧 cur 再更新。

## 如果面试官追问
要求输出具体跳法？答：记录每次 `cur` 切换的下标，切换点即起跳点，末尾补 n-1。
