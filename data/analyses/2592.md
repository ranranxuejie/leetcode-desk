## 一句话思路
排序后双指针：用大数去“压”小数，能压过就计数并双移，压不过就只移大数指针。

## 怎么做
1. 把 `nums` 升序排序，得到 `s`；伟大值只与元素多重集有关，与下标位置无关。
2. 设 `i = 0`（待被压的小数指针）、`j = 0`（候选大数指针）、`ans = 0`。
3. 遍历 `j` 从 0 到 n-1：若 `s[j] > s[i]`，则 `ans += 1`、`i += 1`；无论是否成功，`j` 都前进。
4. 返回 `ans`。

以 `nums = [1,3,5,2,1,3,1]` 为例，排序后 `s = [1,1,1,2,3,3,5]`。`j=0` 时 `s[0]=1 > s[0]=1` 不成立，`i` 不动；`j=3` 时 `s[3]=2 > s[0]=1` 成立，`ans=1`、`i=1`；继续推进，最终 `ans=4`，对应 `i` 停在 4、`j` 走完 7 个元素。

```python
s = sorted(nums)
i = ans = 0
for j in range(len(s)):
    if s[j] > s[i]:
        ans += 1
        i += 1
return ans
```

关键点：`i` 只在配对成功时前进，保证每个小数最多被一个大数压一次；`j` 无条件前进，因为当前大数若压不过 `s[i]`，它对更靠后（更大）的 `s[i]` 更压不过，直接弃用不亏。

## 复杂度
时间：排序贡献 O(n log n)，双指针扫描 O(n)，合计 O(n log n)。
空间：排序额外 O(n)（Python `sorted` 复制一份），指针与计数器 O(1)。

## 易错点
- 输入 `[1,1,1,1]` → 若写成 `s[j] >= s[i]` 会错成 3 或 4 → 必须严格 `>`，相等不算“伟大”。
- 输入 `[1,2,3,4]` → 若让 `i` 和 `j` 同步前进（`i=j` 起步且同时加）会错成 0 或 1 → `i` 必须独立于 `j`，只在成功配对时 `i += 1`，否则 `s[i]` 会被跳过而少算。

## 如果面试官追问
要求输出具体排列方案怎么办？答：把成功配对的 `(s[i], s[j])` 记下来，未配对元素随意填到剩余位置即可，答案不变。
