## 一句话思路
区间 DP：`dp[i][j]` 记把 `stones[i..j]` 合并到「不能再少」的最低成本，最后一步合并时补上整段和。

## 怎么做
1. 先判可行性：每次合并让堆数减少 `k-1`，所以 `(n-1) % (k-1) != 0` 直接返回 `-1`。
2. 前缀和 `pre`，`sum(i,j) = pre[j+1]-pre[i]`，用于最后一步合并的代价。
3. 按区间长度从 `k` 到 `n` 递推，枚举分割点 `m` 从 `i` 跳到 `j-1`、步长 `k-1`：`dp[i][j] = min(dp[i][m] + dp[m+1][j])`。
4. 若 `(j-i) % (k-1) == 0`，说明这段能压成一堆，再加 `sum(i,j)`。

以 `stones=[3,2,4,1], k=2` 为例：`dp[0][1]=5`（合并 3,2），`dp[2][3]=5`（合并 4,1），`dp[0][3]` 取 `m=1` 得 `dp[0][1]+dp[2][3]=10`，因 `(3-0)%1==0` 再加 `sum(0,3)=10`，得 **20**。

```python
n = len(stones)
if (n - 1) % (k - 1): return -1
pre = [0] * (n + 1)
for i, v in enumerate(stones): pre[i+1] = pre[i] + v
INF = 2**31 - 1
dp = [[0] * n for _ in range(n)]
for length in range(k, n + 1):
    for i in range(n - length + 1):
        j = i + length - 1
        dp[i][j] = INF
        for m in range(i, j, k - 1):
            dp[i][j] = min(dp[i][j], dp[i][m] + dp[m+1][j])
        if (j - i) % (k - 1) == 0:
            dp[i][j] += pre[j+1] - pre[i]
return dp[0][n-1]
```

## 复杂度
时间：`O(n^3 / k)`，三层循环由区间长度、起点、分割点贡献。
空间：`O(n^2)`，`dp` 表；`pre` 只占 `O(n)`。

## 易错点
- `stones=[3,2,4,1], k=3`：不判 `(n-1)%(k-1)` 会算出 `dp[0][3]` 的伪值而非 `-1`；正确做法是入口先返回 `-1`。
- 分割点 `m` 若按步长 1 枚举，`dp[i][m]` 可能对应「压不成整数堆」的非法状态；必须 `range(i, j, k-1)`，保证左右两段各自合法。

## 如果面试官追问
问：`n` 放大到 100 还能这么做吗？答：`O(n^3)` 会超时，需用四边形不等式把分割点枚举压到 `O(n^2)` 总量。
