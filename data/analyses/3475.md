## 一句话思路
用 SQL 的 `LIKE` 和 `REGEXP` 在 `dna_sequence` 上逐条判定四个模式，输出 0/1 标志列。

## 怎么做
1. 用 `LIKE 'ATG%'` 判起始密码子，`LIKE '%TAA' OR ... '%TAG' OR ... '%TGA'` 判终止密码子。
2. 用 `LIKE '%ATAT%'` 判基序，`LIKE '%GGG%'` 判连续三个 G（`%GGG%` 已覆盖 GGGG）。
3. 每个条件用 `CASE WHEN ... THEN 1 ELSE 0 END` 转成整数列。
4. `ORDER BY sample_id` 升序。

以 sample_id=4 的 `ATGGGGTCATCATAA` 为例：`LIKE 'ATG%'` 为真 → has_start=1；结尾 `TAA` 命中 → has_stop=1；串中无 `ATAT` → has_atat=0；含 `GGGG`，`%GGG%` 命中 → has_ggg=1。

```python
# 伪代码：SQL 逻辑映射到 Python 判定
def flags(s):
    return (
        int(s.startswith("ATG")),
        int(s.endswith(("TAA", "TAG", "TGA"))),
        int("ATAT" in s),
        int("GGG" in s),
    )
# sample 4: flags("ATGGGGTCATCATAA") -> (1, 1, 0, 1)
```

## 复杂度
时间：O(n·m)，n 为行数，m 为序列平均长度，四次子串扫描各 O(m)。
空间：O(1) 额外空间，仅输出结果集。

## 易错点
- 终止密码子写成 `LIKE '%TAA%'`（中间匹配）→ sample 1 的 `ATGCTAGCTAGCTAA` 中段含 `TAG` 会被误判，但结尾确实是 `TAA` 仍为 1；真正翻车的是 sample 5 `TCAGTCAGTCAG`，中段无终止子但若用 `%TGA%` 之类会误命中，正确做法是 `LIKE '%TAA'` 只锚定结尾。
- 判 `GGG` 时写成 `LIKE '%GGG'`（只匹配结尾）→ sample 2 `GGGTCAATCATC` 的 GGG 在开头，会错成 has_ggg=0；正确用 `LIKE '%GGG%'`，它同时覆盖 `GGGG`。

## 如果面试官追问
问：若序列很长、要统计每种模式出现次数而非是否存在？答：把 `LIKE` 换成 `REGEXP` 计数或应用层 `str.count`，注意 `ATAT` 重叠匹配需用前瞻正则。
