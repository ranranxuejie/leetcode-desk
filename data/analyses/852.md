## 一句话思路
用二分查找比较 `arr[mid]` 与 `arr[mid+1]`，上升则峰在右侧，下降则峰在左侧或就是 mid。

## 怎么做
1. 令 `lo = 0`、`hi = len(arr) - 1`，在 `[lo, hi]` 上二分，循环条件 `lo < hi`。
2. 取 `mid = (lo + hi) // 2`，只比较 `arr[mid]` 和 `arr[mid+1]` 这一对相邻值。
3. 若 `arr[mid] < arr[mid+1]`，说明 mid 还在上坡，峰必在 `mid+1` 右侧，令 `lo = mid + 1`。
4. 否则 `arr[mid] > arr[mid+1]`，mid 已在下坡，峰在 `mid` 或更左，令 `hi = mid`；循环结束时 `lo == hi` 即峰顶下标。

以 `arr = [0,2,1,0]` 为例：初始 `lo=0, hi=3`，`mid=1`，`arr[1]=2 > arr[2]=1`，走第 4 步令 `hi=1`；下一轮 `lo=0, hi=1`，`mid=0`，`arr[0]=0 < arr[1]=2`，令 `lo=1`；此时 `lo==hi==1`，返回 1。

```python
lo, hi = 0, len(arr) - 1
while lo < hi:
    mid = (lo + hi) // 2
    if arr[mid] < arr[mid + 1]:
        lo = mid + 1
    else:
        hi = mid
return lo
```

关键点：`hi = mid` 而不是 `mid - 1`，因为 mid 本身可能就是峰；`lo = mid + 1` 则安全，因为 mid 处于上坡时绝不可能是峰。

## 复杂度
时间 O(log n)：每次把 `[lo, hi]` 区间折半，n 是数组长度。
空间 O(1)：只开了 `lo`、`hi`、`mid` 三个整数。

## 易错点
- 输入 `arr = [0,1,0]` 时若把 `hi` 初始化为 `len(arr)` 并访问 `arr[mid+1]`，`mid` 可能取到 `n-1` 导致越界；正确做法是 `hi = len(arr) - 1`，保证 `mid < hi ≤ n-1`，`arr[mid+1]` 恒合法。
- 输入 `arr = [0,10,5,2]` 时若写成 `hi = mid - 1`，`mid=1` 那轮 `arr[1]=10 > arr[2]=5` 会把峰排除到区间外，最终返回 0；正确做法是 `hi = mid`，把 mid 留在候选区间内。

## 如果面试官追问
问：若数组允许有平台（相邻相等）怎么办？
答：相邻相等时二分方向不再唯一，需先线性收缩平台或改用三分/找第一个下降点，O(log n) 不再保证。
