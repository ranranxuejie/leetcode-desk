## 一句话思路
用哈希表把每个值映射到节点，边建节点边连边，同时记录谁当过孩子，最后没当过孩子的就是根。

## 怎么做
1. 建 `nodes = {}` 存值到 `TreeNode` 的映射，建 `has_parent = set()` 记录所有出现过的 `child`。
2. 遍历每条 `[p, c, isLeft]`，用 `nodes.setdefault(x, TreeNode(x))` 保证父子节点都存在。
3. 按 `isLeft` 把 `nodes[c]` 挂到 `nodes[p].left` 或 `.right`，并把 `c` 加入 `has_parent`。
4. 遍历 `nodes` 的键，第一个不在 `has_parent` 里的值就是根。

以示例 1 为例，处理完 `[20,15,1]` 后 `nodes` 有键 `20,15`，`has_parent={15}`；全部处理完 `has_parent={15,17,20,80,19}`，`nodes` 键为 `20,15,17,50,80,19`，只有 `50` 不在集合里，返回 `nodes[50]`。

```python
nodes, has_parent = {}, set()
for p, c, isLeft in descriptions:
    nodes.setdefault(p, TreeNode(p))
    nodes.setdefault(c, TreeNode(c))
    if isLeft:
        nodes[p].left = nodes[c]
    else:
        nodes[p].right = nodes[c]
    has_parent.add(c)
for v in nodes:
    if v not in has_parent:
        return nodes[v]
```

## 复杂度
时间 O(n)：n 为 `descriptions` 长度，建表、连边、找根各扫一遍。
空间 O(n)：`nodes` 与 `has_parent` 各存至多 2n 个值。

## 易错点
- 只给 `parent` 建节点、忘了 `child` 也可能是别人的父节点：示例 1 里 `20` 先作为 `child` 出现，若不在处理 `[20,15,1]` 时 `setdefault(20, ...)`，后面 `[50,20,1]` 拿到的 `nodes[20]` 会 KeyError。正确做法是父子都 `setdefault`。
- 用「入度为 0」以外的判据找根，比如取 `descriptions[0][0]`：示例 2 的 `descriptions[0][0]=1` 恰好是根，但示例 1 的 `descriptions[0][0]=20` 不是根（根是 50）。正确做法是维护 `has_parent` 集合，取唯一不在其中的值。

## 如果面试官追问
若 `descriptions` 长度涨到 10^6、值域也变大，哈希表还够用吗？答：够，仍是 O(n) 时间空间，只是常数和内存上升，可改用数组按值域下标存节点换常数。
