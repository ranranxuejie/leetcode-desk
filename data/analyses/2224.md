## 一句话思路
把两个时间都换算成分钟数求差 `diff`，再按 60、15、5、1 从大到小贪心取整，因为每种面额都整除比它小的面额。

## 怎么做
1. 用 `int(s[:2]) * 60 + int(s[3:])` 把 `"HH:MM"` 转成分钟，得到 `cur` 和 `cor`，令 `diff = cor - cur`。
2. 对 `[60, 15, 5, 1]` 依次做 `ans += diff // step; diff %= step`。
3. 返回 `ans`。

以示例 1 为例：`cur = 2*60+30 = 150`，`cor = 4*60+35 = 275`，`diff = 125`。第一步 `125 // 60 = 2`，`diff` 变 `5`；第二步 `5 // 15 = 0`；第三步 `5 // 5 = 1`，`diff` 变 `0`；第四步加 0。`ans = 3`，与官方输出一致。

```python
def convertTime(current, correct):
    def to_min(t):
        return int(t[:2]) * 60 + int(t[3:])
    diff = to_min(correct) - to_min(current)
    ans = 0
    for step in (60, 15, 5, 1):
        ans += diff // step
        diff %= step
    return ans
```

关键点：`diff` 在循环里被不断取余缩小，所以 `ans` 累加的是每种步长「用满」的次数，而不是重新从原 `diff` 算。

## 复杂度
时间：O(1)，固定 4 种步长，与输入无关。
空间：O(1)，只开了 `diff`、`ans` 两个整数。

## 易错点
- 输入 `current = "00:00", correct = "23:59"` → 若忘记 `current <= correct` 保证，误以为要处理跨天回绕、写成 `(cor - cur) % 1440` → 本题已保证 `current <= correct`，直接相减即可，取模反而在 `diff = 0` 时也正确但没必要。
- 输入 `current = "11:00", correct = "11:01"`，`diff = 1` → 若把步长顺序写成 `[1, 5, 15, 60]` 从小到大，`1 // 1 = 1` 后 `diff = 0`，答案碰巧对；但换成 `diff = 125` 会先被 1 拆成 125 步 → 必须从大到小，靠「大面额整除小面额」保证贪心最优。

## 如果面试官追问
问：若步长改成 `[7, 15, 60]` 这种不互相整除的集合呢？
答：贪心失效，要按 `diff` 做完全背包/DP 求最少硬币数。
