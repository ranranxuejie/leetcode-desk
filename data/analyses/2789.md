## 一句话思路
从右往左贪心累加：只要当前前缀和 `s` 不小于 `nums[i]`，就能把 `nums[i]` 并进来，否则 `s` 重置为 `nums[i]`。

## 怎么做
1. 令 `s = nums[-1]`，从 `i = n-2` 开始向左扫描。
2. 若 `nums[i] <= s`，执行 `s += nums[i]`；否则 `s = nums[i]`（这一段接不上，重新起头）。
3. 全程用 `ans` 记录 `s` 出现过的最大值，返回 `ans`。

以 `nums = [2,3,7,9,3]` 为例：`s=3`；`i=3` 时 `9>3`，重置 `s=9`；`i=2` 时 `7<=9`，`s=16`；`i=1` 时 `3<=16`，`s=19`；`i=0` 时 `2<=19`，`s=21`。关键中间值是 `s=16` 那一步——`7` 被并进 `9` 之后，左边的 `3`、`2` 才有资格继续并。

```python
s = nums[-1]
ans = s
for i in range(len(nums) - 2, -1, -1):
    if nums[i] <= s:
        s += nums[i]
    else:
        s = nums[i]
    if s > ans:
        ans = s
return ans
```

为什么从右往左：合并只能把左边的数并到右边，所以一个元素能吸收的只有它左边、且从左往右看「不递减到它」的那一段。反向扫描时 `s` 恰好就是「右边已合并成的那个数」，比较 `nums[i] <= s` 就是判断能否继续左扩。

## 复杂度
时间：O(n)，每个 `nums[i]` 只被比较一次，循环一趟。
空间：O(1)，只开了 `s` 和 `ans` 两个变量。

## 易错点
- `nums = [5,3,3]`：若从左往右贪心，先看到 `5>3` 就卡住，误以为只能得 `5` 或 `6`；正确做法是从右往左，`3+3=6` 后再 `5<=6` 得 `11`。
- `nums = [1,2,3]`：若写成 `nums[i] < s` 的严格比较，`1<=3` 这一步会被跳过，答案错成 `6` 而非 `6`（此处相等必须并入）；正确条件是 `nums[i] <= s`，等号不能丢。

## 如果面试官追问
问：要求输出合并后的最终数组怎么办？
答：反向扫描时把并入的下标记进列表，最后按原顺序输出未被并入的元素加合并结果。
