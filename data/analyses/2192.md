## 一句话思路
对每个节点反向 BFS 收集祖先，用集合去重后排序；DAG 保证反向搜索不会绕回自己。

## 怎么做
1. 建反向邻接表 `rev`：对每条 `[u, v]`，把 `u` 追加到 `rev[v]`，这样从 v 出发只能往祖先方向走。
2. 对每个起点 `i` 做一次 BFS/DFS，用 `seen` 集合记录访问过的节点，遍历 `rev[cur]` 里的每个前驱。
3. 把 `seen` 转成 `list` 并 `sorted()`，作为 `answer[i]`。

以示例 1 的节点 6 为例：`rev[6] = [3, 4]`，先访问 3、4；从 3 扩展到 `rev[3] = [0, 1]`，从 4 扩展到 `rev[4] = [0, 2]`；`seen` 最终为 `{0,1,2,3,4}`，排序后正好是 `[0,1,2,3,4]`。注意 0 被 3 和 4 两条路径都指向，集合去重后只算一次。

```python
from collections import deque

rev = [[] for _ in range(n)]
for u, v in edges:
    rev[v].append(u)

answer = []
for i in range(n):
    seen = set()
    q = deque(rev[i])
    while q:
        cur = q.popleft()
        if cur in seen:
            continue
        seen.add(cur)
        q.extend(rev[cur])
    answer.append(sorted(seen))
```

关键点：入队时就该判重，否则节点 6 的 0 会被 3、4 各推一次，队列里出现重复元素，虽然结果不错但白跑。

## 复杂度
时间：每个节点各做一次反向遍历，最坏 O(n·(n+m))，n=1000、m=2000 可接受。
空间：`rev` 占 O(n+m)，每次 BFS 的 `seen` 和队列占 O(n)，answer 总计 O(n²)。

## 易错点
- 用正向图从 i 出发搜索 → 搜到的是 i 的后代而不是祖先，示例 1 节点 0 会错成 `[3,4]` 之类，正确做法是建 `rev` 反向边。
- 忘记去重直接 append → 示例 1 节点 6 的 0 会因 3→0 和 4→0 两条路径出现两次，输出 `[0,0,1,2,3,4]`，必须用 `seen` 集合或布尔数组。

## 如果面试官追问
问：n 放大到 10^5 怎么办？答：改用拓扑序 + 位图/集合合并，每个节点继承所有前驱的祖先集合，避免逐点重搜。
