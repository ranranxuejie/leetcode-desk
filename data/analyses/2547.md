## 一句话思路
用 dp[i] 表示前 i 个元素的最小代价，枚举最后一段起点 j，靠「从右往左扫时维护出现次数」把每段 trimmed 长度增量算成 O(1)。

## 怎么做
1. 定义 `dp[0] = 0`，`dp[i]` 为 `nums[:i]` 的最小代价，答案是 `dp[n]`。
2. 外层枚举右端点 `i` 从 1 到 n，内层 `j` 从 `i-1` 递减到 0，表示最后一段是 `nums[j:i]`。
3. 内层用 `cnt` 字典边扫边更新：`nums[j]` 出现次数从 0→1 时该数还不贡献长度，从 1→2 时它开始贡献 1，从 2→3 时贡献从 1 变 2（即每次 `cnt[x] >= 2` 就让 `trim_len += 1`）。
4. 转移 `dp[i] = min(dp[i], dp[j] + k + trim_len)`。

以示例 1 `nums = [1,2,1,2,1,3,3], k = 2` 算 `i = 7`（整段）时，从 `j = 6` 往左扫：`nums[6]=3` 首次出现 `trim_len=0`；`nums[5]=3` 第二次出现 `trim_len=1`；`nums[4]=1` 第三次出现（此前已出现两次）`trim_len=2`；继续到 `j=0` 时 `trim_len=4`，对应 `dp[0]+2+4=6`。而最优切法是 `dp[2]=2` 加上 `nums[2:7]=[1,2,1,3,3]` 的 `k+4=6`，得 8。

```python
n = len(nums)
dp = [0] + [2**63 - 1] * n
for i in range(1, n + 1):
    cnt = {}
    trim_len = 0
    for j in range(i - 1, -1, -1):
        x = nums[j]
        c = cnt.get(x, 0)
        if c >= 2:
            trim_len += 1
        cnt[x] = c + 1
        cand = dp[j] + k + trim_len
        if cand < dp[i]:
            dp[i] = cand
```

## 复杂度
时间：O(n²)，外层 i 与内层 j 各贡献 n，字典操作 O(1)。
空间：O(n) 存 dp，内层 cnt 最多 n 个键。

## 易错点
- 把 `trim_len` 增量写成「出现次数 ≥1 就 +1」→ 对 `[1,2]` 这种全不重复段会算出 `trim_len=2`，而正确是 0；必须只在 `cnt[x] >= 2` 时加。
- 内层 `j` 从 `i-1` 递减而不是递增 → 递增时 `cnt` 统计的是 `nums[j:i]` 的补集方向，`trim_len` 与当前段不符，`dp[j]` 也对不上；必须固定右端点、左端点向左扩。

## 如果面试官追问
问：n 放大到 10^5 怎么办？答：这题 O(n²) 是标程上限，放大后需换思路（如按 k 与重复代价的分段性质做贪心/凸优化），面试中先说明 O(n²) 已满足 n≤1000 的约束。
