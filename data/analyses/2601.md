## 一句话思路
从左往右贪心，每个 `nums[i]` 减到「比前一个值大」的最小可行值，因为留得越小对后面越宽松。

## 怎么做
1. 预处理 1000 以内的质数表，用二分查「小于 x 的最大质数」。
2. 维护 `prev` 表示前一个元素最终确定的值，初始为 0。
3. 对每个 `nums[i]`，若 `nums[i] <= prev` 直接返回 `False`；否则取 `p` 为小于 `nums[i] - prev` 的最大质数，令 `nums[i] -= p`（无此质数则不减）。
4. 更新 `prev = nums[i]`，全部通过返回 `True`。

以 `nums = [4,9,6,10]` 为例：`i=0` 时 `prev=0`，`nums[0]-prev=4`，小于 4 的最大质数是 3，`nums[0]` 变 1；`i=1` 时 `prev=1`，`9-1=8`，小于 8 的最大质数是 7，`nums[1]` 变 2。关键中间值就是 `prev` 从 0→1→2。

```python
def primeSubOperation(nums):
    primes = [p for p in range(2, 1001) if all(p % d for d in range(2, int(p**0.5) + 1))]
    prev = 0
    for x in nums:
        if x <= prev:
            return False
        k = bisect_left(primes, x - prev) - 1
        if k >= 0:
            x -= primes[k]
        prev = x
    return True
```

## 复杂度
时间：O(n log P)，n 为数组长度，P 为质数表大小，每个元素一次二分。
空间：O(P)，质数表额外占用，与 n 无关。

## 易错点
- 输入 `[5,8,3]` → 若只判断 `nums[i] > nums[i-1]` 而不看 `prev`，会以为 8>5 通过、3<8 失败就结束；正确做法是 `i=2` 时 `3 <= prev=8` 立即返回 `False`，因为减质数只会让 3 更小。
- 输入 `[2,3]` → 若把「小于 `nums[i]-prev` 的最大质数」写成「小于等于」，`i=0` 时 `2-0=2` 会选到 2，`nums[0]` 变 0，虽仍递增但语义错；正确做法是严格小于，`k = bisect_left(...) - 1`。

## 如果面试官追问
问：若 nums 长度到 10^5、值到 10^9 怎么办？答：质数表按最大值筛到 10^9 不现实，改用「小于 x 的最大质数」在线判定，或只对差值做 Miller-Rabin 降级搜索。
