## 一句话思路
用二分查找收缩区间，靠 `nums[mid]` 与 `nums[hi]` 比较判断最小值在哪侧，相等时只能 `hi -= 1` 逐个排除。

## 怎么做
1. 初始化 `lo, hi = 0, len(nums) - 1`，循环条件 `lo < hi`。
2. 若 `nums[mid] < nums[hi]`，最小值在左半（含 mid），令 `hi = mid`。
3. 若 `nums[mid] > nums[hi]`，最小值在右半，令 `lo = mid + 1`。
4. 若相等，无法判断，令 `hi -= 1` 缩小范围。

以 `nums = [2,2,2,0,1]` 为例：`lo=0, hi=4, mid=2`，`nums[2]=2 > nums[4]=1`，所以 `lo=3`；下一轮 `lo=3, hi=4, mid=3`，`nums[3]=0 < nums[4]=1`，`hi=3`，循环结束返回 `nums[3]=0`。

```python
lo, hi = 0, len(nums) - 1
while lo < hi:
    mid = (lo + hi) // 2
    if nums[mid] < nums[hi]:
        hi = mid
    elif nums[mid] > nums[hi]:
        lo = mid + 1
    else:
        hi -= 1
return nums[lo]
```

关键中间值：示例 2 第一轮 `mid=2` 时 `nums[mid]=2`、`nums[hi]=1`，走 `lo = mid + 1 = 3`，把最小值锁进 `[3,4]`。

## 复杂度
时间：平均 O(log n)，最坏 O(n)，因为相等时 `hi -= 1` 每次只缩一格。
空间：O(1)，只用了 `lo`、`hi`、`mid` 三个变量。

## 易错点
- 输入 `[1,1,1,1]` → 若写成 `nums[mid] <= nums[hi]` 就 `hi = mid`，会漏掉相等分支导致死循环或错判 → 必须把 `==` 单独拆成 `hi -= 1`。
- 输入 `[3,3,1,3]` → 若相等时直接 `hi = mid`，`mid=1` 处 `nums[1]=3 == nums[3]=3`，会把 `hi` 压到 1，丢掉 `nums[2]=1` → 正确做法是相等只 `hi -= 1`，保证不跳过最小值。

## 如果面试官追问
问：允许重复后最坏为什么退化到 O(n)？
答：全相等数组 `[2,2,2,2]` 每轮只能 `hi -= 1`，二分退化成线性扫描。
