## 一句话思路
用两把 `threading.Semaphore` 互相放行：foo 先拿 `s_bar` 的许可、打印后放 `s_foo`，bar 反之，靠信号量计数保证严格交替。

## 怎么做
1. 初始化 `s_foo = Semaphore(0)`、`s_bar = Semaphore(1)`，让 foo 第一轮能直接进、bar 必须等。
2. `foo()` 每轮先 `s_bar.acquire()`，打印 `"foo"`，再 `s_foo.release()`。
3. `bar()` 每轮先 `s_foo.acquire()`，打印 `"bar"`，再 `s_bar.release()`。
4. 两个循环都跑 `n` 次，第 n 轮 bar 释放的 `s_bar` 无人再取，无害。

以 `n = 2` 为例：初始 `s_bar` 计数 1、`s_foo` 计数 0。foo 第 1 轮 `acquire` 后 `s_bar` 变 0，打印 foo，`s_foo` 变 1；bar 随即 `acquire` 使 `s_foo` 回 0，打印 bar，`s_bar` 回 1——计数在 0/1 间来回，交替成立。

```python
import threading

class FooBar:
    def __init__(self, n):
        self.n = n
        self.s_foo = threading.Semaphore(0)
        self.s_bar = threading.Semaphore(1)

    def foo(self):
        for _ in range(self.n):
            self.s_bar.acquire()
            print("foo", end="")
            self.s_foo.release()

    def bar(self):
        for _ in range(self.n):
            self.s_foo.acquire()
            print("bar", end="")
            self.s_bar.release()
```

## 复杂度
时间：O(n)，两个线程各循环 n 次，每次信号量操作 O(1)。
空间：O(1)，只多开两个 Semaphore 对象，与 n 无关。

## 易错点
- 把 `s_bar` 初值写成 0 → `n = 1` 时 foo 和 bar 都卡在 `acquire` 上死锁，输出空串；正确是 `s_bar = Semaphore(1)`、`s_foo = Semaphore(0)`，让 foo 先跑。
- 用一把 `Lock` 加共享布尔标志却忘了在 `print` 前后成对加解锁 → `n = 2` 时可能输出 `foofoobarbar`；要么全程用两把信号量，要么标志读写都在锁内。

## 如果面试官追问
问：n 很大（如 10**6）时这套还合适吗？
答：合适，信号量是 O(1) 阻塞唤醒，瓶颈在 print 的 I/O，可改为写缓冲区再一次性输出。
