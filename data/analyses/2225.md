## 一句话思路
只统计每个玩家输的场次，赢过但没输过的记 0 场，再按输场数 0 和 1 分桶排序。

## 怎么做
1. 用 `lose = {}` 记录每个玩家输的场次，遍历 `matches` 时对 `loser` 累加。
2. 同时把 `winner` 也写进 `lose`（用 `setdefault` 置 0），否则只赢不输的玩家会漏掉。
3. 遍历 `lose`，按 `cnt == 0` 和 `cnt == 1` 分别放进 `answer[0]`、`answer[1]`。
4. 两个列表各自 `sort()` 后返回。

以示例 1 为例，遍历完 `matches` 后 `lose` 的关键值是 `{3:2, 6:2, 7:1, 5:1, 8:1, 9:2, 4:1, 1:0, 2:0, 10:0}`——注意 1、2、10 只作为 winner 出现，靠第 2 步才被补进字典，它们的值停在 0。

```python
lose = {}
for w, l in matches:
    lose.setdefault(w, 0)
    lose[l] = lose.get(l, 0) + 1

ans = [[], []]
for p, c in lose.items():
    if c == 0:
        ans[0].append(p)
    elif c == 1:
        ans[1].append(p)
ans[0].sort()
ans[1].sort()
```

## 复杂度
时间：O(n + k log k)，n 是 `matches` 长度，k 是参与玩家数，排序贡献 log。
空间：O(k)，`lose` 字典和两个结果列表各存一份玩家。

## 易错点
- 只遍历 `matches` 累加 `loser` 而不登记 `winner` → 示例 1 里 1、2、10 从不出现在 loser 位置，会整个从 `answer[0]` 消失 → 必须用 `setdefault(w, 0)` 先把 winner 补进字典。
- 用 `lose.get(l, 0) + 1` 之外还去判断 `c == 0` 时把没输过的人也算进去，但漏了「只考虑参与至少一场」的约束 → 若把 1..10^5 全量初始化，会把从未参赛的编号塞进 `answer[0]` → 只从 `matches` 里出现过的玩家建键。

## 如果面试官追问
问：若要求同时返回输 0、1、2 场的三个列表怎么办？
答：把 `elif c == 1` 换成 `if c <= 2: ans[c].append(p)`，桶数随阈值线性扩展，复杂度不变。
