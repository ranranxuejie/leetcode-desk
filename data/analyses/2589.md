## 一句话思路
按 end 升序贪心，每个任务缺的时长尽量塞进区间内最靠右的空闲时间点，因为越靠右越可能被后续任务复用。

## 怎么做
1. 把 tasks 按 `end` 升序排序，保证处理到某任务时，它区间内已占用的时间点都是「更早结束」的任务留下的。
2. 维护布尔数组 `used[1..2000]`，表示该整数时间点电脑是否开机。
3. 对每个 `[s, e, d]`，先数 `[s, e]` 内已 `used` 的点数 `cnt`；若 `cnt >= d` 直接跳过，否则从 `e` 往 `s` 倒着扫，遇到 `used[t] == False` 就置 `True` 并 `cnt += 1`，直到 `cnt == d`。
4. 每置一个 `True` 就 `ans += 1`，最后返回 `ans`。

以示例 2 `[[1,3,2],[2,5,3],[5,6,2]]` 排序后仍是这个顺序。处理 `[2,5,3]` 时，`[2,3]` 已被第一个任务占用 2 个点，`cnt = 2`，还差 1，从 `e = 5` 倒扫，`used[5]` 为 `False`，置 `True`，`ans` 从 2 变 3。处理 `[5,6,2]` 时 `used[5]` 已为 `True`，`cnt = 1`，只补 `6`，`ans = 4`。

```python
tasks.sort(key=lambda x: x[1])
used = [False] * 2001
ans = 0
for s, e, d in tasks:
    cnt = sum(used[s:e + 1])
    t = e
    while cnt < d:
        if not used[t]:
            used[t] = True
            cnt += 1
            ans += 1
        t -= 1
return ans
```

关键点：倒扫从 `e` 开始而不是从 `s`，因为靠右的点更可能落在后续任务的区间里。

## 复杂度
时间：排序 `O(n log n)`，每个任务最多倒扫区间长度，总 `O(n * maxEnd)`，`maxEnd ≤ 2000`。
空间：`used` 数组固定 2001 个布尔，`O(maxEnd)`，与 `n` 无关。

## 易错点
- 输入 `[[1,3,2],[2,5,3],[5,6,2]]` 若不按 `end` 排序而按输入顺序处理，处理 `[5,6,2]` 时 `5` 可能还没被占用，会多开一个点，答案错成 5；必须先 `sort(key=lambda x: x[1])`。
- 输入 `[[2,3,1],[4,5,1],[1,5,2]]` 若从 `s` 往 `e` 正扫填点，第三个任务会填 `1,2` 而非 `2,5`，`ans` 错成 3；必须从 `e` 倒扫，让点尽量靠右。

## 如果面试官追问
若 `end` 上限放大到 `10^9` 怎么办？答：布尔数组换成有序集合存已占用点，用二分统计区间内占用数并倒序取空位，复杂度降到 `O(n log n)`。
