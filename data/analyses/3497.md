## 一句话思路
按 `user_id` 分组，用 `HAVING` 筛出同时有 `free_trial` 和 `paid` 的用户，再用条件聚合分别算两种活动的均值。

## 怎么做
1. 先按 `user_id` 分组，用 `SUM(activity_type = 'paid') > 0` 判断该用户是否转为付费，过滤掉用户 2。
2. 在同一分组内用 `AVG(CASE WHEN activity_type = 'free_trial' THEN activity_duration END)` 算试用均值，`paid` 同理。
3. 两个均值都 `ROUND(..., 2)`，最后 `ORDER BY user_id`。

以用户 1 为例：分组后 `free_trial` 三行 45、30、60，`AVG` 得 45.00；`paid` 三行 75、90、65，`AVG` 得 76.666…，`ROUND` 后 76.67。用户 4 的 `paid` 只有 45 一行，均值直接是 45.00，`cancelled` 那行 `duration=0` 不参与任何 `CASE`，不影响结果。

```python
# 伪 SQL 逻辑，落到 pandas 就是下面几行
df["is_paid"] = df.activity_type == "paid"
df["is_trial"] = df.activity_type == "free_trial"
g = df.groupby("user_id")
res = g.agg(
    paid_cnt=("is_paid", "sum"),
    trial_avg=("activity_duration", lambda s: s[df.loc[s.index, "is_trial"]].mean()),
    paid_avg=("activity_duration", lambda s: s[df.loc[s.index, "is_paid"]].mean()),
)
res = res[res.paid_cnt > 0].round(2).reset_index()
```

关键点：`paid_cnt > 0` 必须在聚合之后过滤，不能先 `WHERE activity_type='paid'`，否则试用行被删掉，`trial_avg` 算不出来。

## 复杂度
时间 O(n)：n 为 `UserActivity` 行数，一次分组扫描。
空间 O(k)：k 为不同 `user_id` 数，存分组聚合结果。

## 易错点
- 用户 2 只有 `free_trial` 和 `cancelled` → 若只按 `activity_type IN ('free_trial','paid')` 过滤而不加 `HAVING paid 存在`，会把用户 2 以 `paid_avg = NULL` 带进结果 → 正确做法是分组后要求 `SUM(activity_type='paid') > 0`。
- 用户 4 的 `cancelled` 行 `activity_duration = 0` → 若用 `AVG(activity_duration)` 不分类型，会把 0 混进均值把 45.00 拉成 22.50 → 正确做法是 `CASE WHEN activity_type='paid'` 限定范围，`cancelled` 行不进入任何聚合。

## 如果面试官追问
问：如果同一用户有多次试用（多段 `free_trial`）怎么办？
答：当前按 `user_id` 聚合会把所有试用行合并算均值；若要按「每段试用」分别统计，需先按日期切段再分组，`GROUP BY user_id, trial_seq`。
