## 一句话思路
比较起点到 target 的曼哈顿距离：只要没有阻碍者比你先到（距离 ≤ 你的距离），就能逃脱。

## 怎么做
1. 算出你从 `[0,0]` 到 `target` 的曼哈顿距离 `d = abs(target[0]) + abs(target[1])`。
2. 对每个 `ghosts[i]` 算它到 target 的曼哈顿距离 `g`。
3. 只要存在 `g <= d`，返回 `False`；全部 `g > d` 才返回 `True`。

关键中间值：示例 2 中 `target=[2,0]`，你的 `d = 2+0 = 2`；阻碍者 `[1,0]` 的 `g = abs(1-2)+abs(0-0) = 1`，`1 <= 2` 成立，直接返回 `False`——它在 (1,0) 卡在你和终点之间，你走 2 步它只需 1 步。

为什么成立：曼哈顿距离是网格上最短步数下界，阻碍者能任意走，所以它最早到达 target 的时间就是 `g`。你最早是 `d`。若 `g <= d`，它可以先到或同时到 target 守株待兔（同时到也不算你赢）；若所有 `g > d`，你按最短路直奔 target，任何阻碍者都来不及在终点前截住你。

```python
d = abs(target[0]) + abs(target[1])
for gx, gy in ghosts:
    g = abs(gx - target[0]) + abs(gy - target[1])
    if g <= d:
        return False
return True
```

注意 `<=` 不是 `<`：示例 3 中 `target=[1,0]`，你的 `d=1`，阻碍者 `[2,0]` 的 `g=1`，同时到达判负，输出 `False`。

## 复杂度
时间 O(n)，n 为 `ghosts.length`，每个阻碍者算一次曼哈顿距离。
空间 O(1)，只用了 `d`、`g` 两个标量。

## 易错点
- 把条件写成 `g < d`：示例 3 的 `ghosts=[[2,0]], target=[1,0]` 会错判成 `True`，但双方同时到达 target 不算逃脱。正确做法是 `g <= d` 即返回 `False`。
- 误以为要模拟 BFS 或考虑阻碍者中途拦截：`ghosts=[[1,0]], target=[2,0]` 会去搜路径、判 (1,0) 是否被占，其实只需比较 `g=1` 与 `d=2`。正确做法是纯距离比较，不建图不搜索。

## 如果面试官追问
若要求输出一条具体逃脱路径怎么办？答：沿曼哈顿最短路任选方向走即可，因为所有 `g > d` 保证终点前无人能截，路径本身不影响判定。
