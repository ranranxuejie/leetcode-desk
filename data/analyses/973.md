## 一句话思路
用最大堆维护当前最近的 k 个点，堆顶是这 k 个里最远的，新点比堆顶近就替换。

## 怎么做
1. 距离比较用平方 `x*x + y*y`，省掉开方且不丢精度。
2. 遍历 `points`，把 `(-dist, x, y)` 压入堆，负号让最大堆变最小堆的语义。
3. 堆大小超过 k 就 `heappop` 弹出堆顶，即当前 k 个里最远的。
4. 最后把堆里元素的 `(x, y)` 取出返回。

以 `points = [[1,3],[-2,2]], k = 1` 为例：第一个点 `dist = 1+9 = 10`，堆为 `[(-10,1,3)]`；第二个点 `dist = 4+4 = 8`，压入后堆顶是 `(-10,1,3)`，弹出，堆剩 `[(-8,-2,2)]`，返回 `[[-2,2]]`。

```python
import heapq

def kClosest(points, k):
    heap = []
    for x, y in points:
        d = x * x + y * y
        heapq.heappush(heap, (-d, x, y))
        if len(heap) > k:
            heapq.heappop(heap)
    return [[x, y] for _, x, y in heap]
```

注意堆里存 `(-d, x, y)` 而非只存 `-d`，否则取不回坐标；元组比较时 `d` 相同会继续比 `x`、`y`，不影响正确性。

## 复杂度
时间：O(n log k)，n 为点数，每个点一次 push/pop 各 O(log k)。
空间：O(k)，堆里最多存 k 个三元组。

## 易错点
- 用 `sqrt` 或浮点距离比较 → 大坐标下 `x*x+y*y` 最大约 `2*10^8`，浮点仍安全但多一次开方；直接比平方更稳，且避免 `sqrt` 引入的相等判断误差。
- 堆里只存 `-d` 不存坐标 → 最后无法还原 `[x, y]`；必须存 `(-d, x, y)` 三元组，或另存索引映射。
- `k == len(points)` 时 → 堆不会触发弹出，逻辑仍正确，无需特判；但若写成「先建 k 个再逐个比较」的变体，要确认初始 k 个已入堆。

## 如果面试官追问
问：n 很大（如 10^6）且 k 接近 n 时堆解法还合适吗？
答：此时 O(n log k) 退化接近 O(n log n)，可改用快速选择平均 O(n)，但最坏 O(n²)，需随机化 pivot。
