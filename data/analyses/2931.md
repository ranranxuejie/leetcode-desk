## 一句话思路
把所有元素降序排序，第 k 大（从 1 计）乘 k 累加，因为大值必须配大天数。

## 怎么做
1. 把所有 `values[i][j]` 摊平成一个列表 `a`，共 `m*n` 个。
2. 对 `a` 降序排序，得到 `a[0] >= a[1] >= ...`。
3. 第 `d` 天（`d` 从 1 到 `m*n`）取 `a[d-1]`，累加 `a[d-1] * d`。

为什么合法：同一商店内下标大的先买，而 `values[i]` 非递增，所以同店先买的元素值不小于后买的，降序序列天然满足「同店按从右到左」的约束，任意降序排列都可行。

以示例 1 为例，摊平后降序为 `[9,8,7,6,5,4,3,2,1]`，第 1 天乘 1 得 9，第 9 天乘 9 得 9，中间 `5*5=25`、`6*4=24`，总和 285，与官方一致。

```python
a = sorted((v for row in values for v in row), reverse=True)
ans = 0
for d, x in enumerate(a, 1):
    ans += x * d
# ans 即答案
```

注意 `ans` 用 Python 原生 int 即可，最大约 `10^6 * 10^5 * 10^5 / 2`，远超 32 位，但 Python 不会溢出。

## 复杂度
时间：排序 `m*n` 个元素，`O(mn log(mn))`，`log` 来自排序。
空间：`O(mn)` 存摊平后的列表 `a`。

## 易错点
- 误以为要按商店逐列合并（像多路归并那样每次取各店最右的最大值）→ 会写出 `O(mn log m)` 的堆，虽然也对但没必要；正确做法是直接全局降序，因为同店非递增保证了可行性。
- 天数从 0 开始枚举 → 第一天乘 0，示例 1 会得 276 而不是 285；正确做法是 `enumerate(a, 1)` 让第一天乘 1。

## 如果面试官追问
问：如果 `values[i]` 不再有序，还能全局排序吗？
答：不能，需用堆维护每店最右可用元素，每次取最大者，`O(mn log m)`。
