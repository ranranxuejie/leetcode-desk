## 一句话思路
DFS 逐位填 0/1，用 `prev` 记上一位、`cost` 记当前成本，超 k 或连续 1 就剪枝。

## 怎么做
1. 从 `i = 0`、`prev = 0`、`cost = 0` 开始递归，每层决定第 `i` 位填什么。
2. 填 `'0'` 永远合法，直接进入 `i+1`，`cost` 不变。
3. 填 `'1'` 需同时满足 `prev == 0` 且 `cost + i <= k`，否则这条分支立刻剪掉。
4. `i == n` 时把路径拼成字符串收进答案。

以 `n = 3, k = 1` 为例，走到 `i = 2` 时若路径是 `"10"`，此时 `prev = 0`、`cost = 0`，填 `'1'` 得 `cost + 2 = 2 > 1`，剪枝，所以 `"101"` 不出现；而 `"01"` 在 `i = 2` 时 `cost = 1`，填 `'1'` 得 `1 + 2 = 3 > 1` 同样剪掉，最终只剩 `"000"`、`"010"`、`"100"`。

```python
def dfs(i, prev, cost, path):
    if i == n:
        res.append(''.join(path))
        return
    path.append('0')
    dfs(i + 1, 0, cost, path)
    path.pop()
    if prev == 0 and cost + i <= k:
        path.append('1')
        dfs(i + 1, 1, cost + i, path)
        path.pop()
```

关键点：`cost + i` 里的 `i` 是下标本身，不是位数计数，别写成 `cost + 1`。

## 复杂度
时间：O(2^n) 量级，剪枝后实际远小于此，n ≤ 12 完全够。
空间：O(n) 递归栈加路径，答案列表本身占 O(答案数 × n)。

## 易错点
- `n = 1, k = 0` → 若把 `cost + i <= k` 写成 `cost + i < k`，会漏掉 `"1"`（`0 + 0 = 0` 恰好等于 k）→ 必须用 `<=`。
- `n = 3, k = 1` 的 `"001"` → 若只判 `prev == 0` 不判成本，会把 `cost = 2` 的 `"001"` 和 `"101"` 都收进答案 → 填 `'1'` 前两个条件必须同时检查。

## 如果面试官追问
若 n 放大到 30、k 也很大，还能这样枚举吗？
不能，答案数本身指数级；应改成按「已用成本 + 剩余位最多能贡献多少」做可行性剪枝，或直接 DP 计数再回溯构造。
