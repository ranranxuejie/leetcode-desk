## 一句话思路
数 `nums[i] > nums[i+1]` 的下降次数（含首尾环绕），次数 ≤1 即合法。

## 怎么做
1. 遍历 `i` 从 0 到 n-1，比较 `nums[i]` 与 `nums[(i+1) % n]`，统计严格下降的次数 `drops`。
2. 用取模把 `nums[-1]` 与 `nums[0]` 的比较也纳入，这样轮转点落在末尾时也能被数到。
3. 返回 `drops <= 1`。

以 `nums = [3,4,5,1,2]` 为例：比较对依次是 (3,4)(4,5)(5,1)(1,2)(2,3)，只有 `5 > 1` 一处下降，`drops = 1`，返回 `True`。而 `[2,1,3,4]` 有 `2 > 1` 和 `4 > 2` 两处，`drops = 2`，返回 `False`。

```python
n = len(nums)
drops = 0
for i in range(n):
    if nums[i] > nums[(i + 1) % n]:
        drops += 1
        if drops > 1:
            return False
return True
```

关键点：非递减序列轮转后，最多只有一个位置「掉下去」，即从大值跳回小值；重复元素处 `nums[i] == nums[i+1]` 不算下降，所以 `[1,1,1]` 的 `drops = 0` 也返回 `True`。

## 复杂度
时间 O(n)：一次遍历，每个下标比较一次。
空间 O(1)：只开了 `drops` 和循环变量 `i`。

## 易错点
- 只比较 `nums[i] > nums[i+1]` 而漏掉 `nums[-1]` 与 `nums[0]`：输入 `[1,2,3]` 会得 `drops = 0` 碰巧对，但 `[3,1,2]` 会漏掉 `3 > 1` 之外还漏掉 `2 > 3`？实际是漏掉环绕对 `2 > 3` 不成立、真正下降在 `3 > 1`，若只扫到 n-2 则 `[2,3,1]` 的 `3 > 1` 在末尾被漏掉，`drops` 算成 0 误判 `True`。正确做法是循环到 n-1 并用 `(i+1) % n`。
- 把 `>=` 当下降：输入 `[1,1,2]` 会在 `1 >= 1` 处多记一次，`drops` 变 1 仍返回 `True` 侥幸通过，但 `[1,1,2,2]` 会记 2 次误判 `False`。必须用严格 `>`。

## 如果面试官追问
问：要求返回轮转的偏移量 x 而不是布尔值？
答：记下唯一下降位置 `p`（`nums[p] > nums[p+1]`），则 `x = p + 1`；无下降时 `x = 0`。
