## 一句话思路
用 `Prices` 左连 `UnitsSold`（按 product_id 且 purchase_date 落在区间内），先算每行 `price*units` 再按产品聚合，就能同时覆盖有销量和无销量两种情况。

## 怎么做
1. 以 `Prices` 为左表 `LEFT JOIN UnitsSold`，连接条件写 `p.product_id = u.product_id AND u.purchase_date BETWEEN p.start_date AND p.end_date`。
2. 对每行算 `p.price * u.units`，无匹配时 `u.units` 为 `None`，用 `COALESCE(u.units, 0)` 兜底。
3. 按 `product_id` 分组，`SUM(price*units) / SUM(units)`，分母为 0 时用 `IFNULL` 返回 0。
4. 用 `ROUND(..., 2)` 保留两位。

以产品 1 为例：`2019-02-25` 落在 `02-17~02-28`，得 `5*100=500`；`2019-03-01` 落在 `03-01~03-22`，得 `20*15=300`。分子 `800`，分母 `115`，`800/115=6.9565...`，`ROUND` 后 `6.96`。

## 复杂度
时间：连接需对每个 `Prices` 行扫描 `UnitsSold`，朴素实现 O(P·U)，建索引后接近 O(P log U + U)。
空间：分组聚合额外开 O(P) 的哈希表存每个 product_id 的分子分母。

## 易错点
- 用 `INNER JOIN` 时，产品 3 这类无销量的产品会整行消失 → 结果缺产品 → 必须 `Prices LEFT JOIN UnitsSold`，并对 `units` 用 `COALESCE(u.units, 0)`，让分子分母都为 0，再 `IFNULL` 输出 0。
- 分母写成 `COUNT(*)` 或 `SUM(price)` → 产品 1 会算成 `800/2=400` 或 `800/25=32` → 正确分母是 `SUM(u.units)`，即销量总和 115，不是行数也不是价格和。

## 如果面试官追问
问：若同一产品时间段允许重叠怎么办？
答：连接会一对多放大销量，需先去重或改用区间归属唯一化再聚合。
