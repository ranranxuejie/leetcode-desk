## 一句话思路
以 `strs[0]` 为基准，逐字符与其余字符串同位置比较，第一个不匹配处截断即为答案。

## 怎么做
1. 取 `base = strs[0]` 作为候选前缀，外层循环 `i` 遍历 `base` 的下标。
2. 内层对每个 `s in strs[1:]` 检查 `i >= len(s) or s[i] != base[i]`，命中就立刻返回 `base[:i]`。
3. 全部字符都通过则返回整个 `base`。

以 `["flower","flow","flight"]` 为例：`base = "flower"`。`i=0` 时三个串都是 `'f'`；`i=1` 时都是 `'l'`；`i=2` 时 `"flight"[2] == 'i'` 而 `base[2] == 'o'`，不匹配，返回 `base[:2] == "fl"`。关键中间值是 `i=2` 这个断点，它同时说明「前缀长度由最短的那个不匹配位置决定」。

```python
base = strs[0]
for i, ch in enumerate(base):
    for s in strs[1:]:
        if i >= len(s) or s[i] != ch:
            return base[:i]
return base
```

注意 `i >= len(s)` 必须写在 `s[i]` 之前，Python 的 `or` 短路保证不会越界——这正是 `["ab","a"]` 这类「短串先耗尽」的输入能安全返回 `"a"` 的原因。

## 复杂度
时间 O(S)，S 为所有字符串长度之和，最坏要扫完每个串的每个字符。
空间 O(1)，只用了 `base`、`i`、`ch` 三个引用，切片 `base[:i]` 是返回值的必要开销。

## 易错点
- 输入 `["ab","a"]` → 若先写 `s[i] != ch` 再判长度，`s[1]` 直接抛 `IndexError` → 正确做法是把 `i >= len(s)` 放在 `or` 左边，靠短路挡住越界。
- 输入 `[""]` 或 `["","b"]` → 若拿 `min(strs, key=len)` 当基准再逐位比，空串会让循环一次都不进、误返回 `""` 看似对，但 `["a",""]` 用 `strs[0]` 当基准时 `i=0` 就因 `0 >= len("")` 返回 `""`，逻辑才一致 → 统一用 `strs[0]` 当基准，别额外挑最短串，避免基准与比较集错位。

## 如果面试官追问
问：如果 `strs` 是流式输入、长度未知怎么办？
答：维护当前前缀 `pre`，每来一个新串就把它和 `pre` 逐位比、就地截短，空间仍是 O(len(pre))。
