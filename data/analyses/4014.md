## 一句话思路
把最大的折扣给最贵的商品：排序后按位配对，因为交换论证表明大折扣配大价格省得最多。

## 怎么做
1. 把 `prices` 和 `discounts` 都降序排序。
2. 取 `k = min(len(prices), len(discounts))`，只对前 k 件商品用折扣。
3. 前 k 件按 `p * (100 - d) / 100` 累加，其余商品原价累加。
4. 全程用浮点累加，最后返回总和。

以示例 1 为例：`prices` 降序为 `[30,21,10]`，`discounts` 降序为 `[60,50]`。配对后 `30*(100-60)/100 = 12.0`，`21*(100-50)/100 = 10.5`，剩下 `10` 原价，总和 `32.5`。若反过来把 60 给 21、50 给 30，得到 `8.4 + 15 + 10 = 33.4`，明显更差。

```python
prices.sort(reverse=True)
discounts.sort(reverse=True)
total = 0.0
k = min(len(prices), len(discounts))
for i in range(k):
    total += prices[i] * (100 - discounts[i]) / 100.0
for i in range(k, len(prices)):
    total += prices[i]
return total
```

关键点：`(100 - d) / 100.0` 必须用浮点除法，`/ 100` 在 Python 3 里也是浮点，但写成 `100.0` 更明确；不要用 `//`。

## 复杂度
时间：排序 `prices` 和 `discounts` 各 O(n log n)、O(m log m)，配对扫描 O(min(n,m))。
空间：排序原地进行，额外只开了 `total`、`k`、循环变量，O(1)。

## 易错点
- `discounts` 比 `prices` 长时（如示例 2 的 `[10,40,50]` 对 2 件商品），若直接 `zip(prices, discounts)` 会漏掉多余折扣没关系，但若写成按下标 `discounts[i]` 遍历 `prices` 会越界；正确做法是先取 `k = min(...)` 再循环。
- 用整数除法 `p * (100 - d) // 100` 会截断，示例 1 的 `21*50//100` 得 `10` 而非 `10.5`，总和错成 `32`；必须用 `/ 100.0` 保留小数。

## 如果面试官追问
问：如果要求返回具体分配方案而不只是总价？
答：排序后记录每件商品配到的折扣下标，未配到的标记为 `-1`，随总价一起返回即可。
