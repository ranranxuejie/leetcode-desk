## 一句话思路
用 visited 布尔数组记录已执行下标，循环模拟 add/jump 直到越界或撞到已访问下标。

## 怎么做
1. 开 `visited = [False] * n`，`i = 0`，`score = 0`。
2. 循环条件写成 `while 0 <= i < n and not visited[i]`，先置 `visited[i] = True` 再分派。
3. `"add"` 时 `score += values[i]` 且 `i += 1`；`"jump"` 时只做 `i += values[i]`，不碰 score。
4. 循环退出即返回 `score`，越界和重复访问共用同一个出口。

拿示例 1 走关键一步：`i=5` 时 `instructions[5]="jump"`、`values[5]=-3`，执行 `i = 5 + (-3) = 2`；下一轮 `visited[2]` 已是 `True`（第 2 步 add 时置的），循环条件直接为假，返回此刻的 `score = 3 + (-2) = 1`。

```python
n = len(instructions)
visited = [False] * n
i = score = 0
while 0 <= i < n and not visited[i]:
    visited[i] = True
    if instructions[i] == "add":
        score += values[i]
        i += 1
    else:
        i += values[i]
return score
```

注意 `visited[i] = True` 必须在分派之前，否则 jump 回自身（示例 3 的 `values[0]=0`）会死循环。

## 复杂度
时间 O(n)：每个下标最多被置 True 一次，循环最多 n 轮。
空间 O(n)：visited 布尔数组，n 为 instructions 长度。

## 易错点
- `values[i]` 为负且 `i + values[i] < 0`（如 `i=1, values[1]=-5`）→ 若只判 `i >= n` 会拿负下标去索引 `instructions[-5]`，Python 会静默取到倒数第 5 个元素继续跑 → 条件必须写全 `0 <= i < n`。
- 把 `visited[i] = True` 写在 add/jump 分支之后 → 示例 3 的 `jump` 到自身 `i=0` 时永远进不了已访问判断，死循环 → 标记放在分派前，且循环条件里就检查 visited。

## 如果面试官追问
问：n 放大到 10^7、values 范围不变，还能这么写吗？
答：能，时间仍是 O(n)，但 visited 用 bytearray(n) 替代 list 省 8 倍内存。
