## 一句话思路
用哈希表把 pieces 按首元素建索引，再顺着 arr 逐段匹配，因为 arr 元素互不相同，每段起点唯一。

## 怎么做
1. 建 `head = {p[0]: p for p in pieces}`，键是每段首元素，值是整段。
2. 从 `i = 0` 扫 arr，取 `p = head.get(arr[i])`，取不到直接返回 `False`。
3. 用 `arr[i:i+len(p)] != p` 校验整段，不等返回 `False`，相等则 `i += len(p)`。
4. 扫完 `i == len(arr)` 返回 `True`。

以示例 3 为例：`arr = [91,4,64,78]`，`head = {78:[78], 4:[4,64], 91:[91]}`。`i=0` 取到 `[91]`，`arr[0:1] == [91]`，`i` 变 1；`i=1` 取到 `[4,64]`，`arr[1:3] == [4,64]`，`i` 变 3；`i=3` 取到 `[78]`，匹配后 `i=4`，返回 `True`。

```python
head = {p[0]: p for p in pieces}
i = 0
while i < len(arr):
    p = head.get(arr[i])
    if p is None or arr[i:i + len(p)] != p:
        return False
    i += len(p)
return True
```

关键在 `arr[i:i+len(p)] != p` 这一句：它同时挡住了「首元素对但后续错位」和「段长超出 arr 尾部」两种情况，切片越界在 Python 里只会变短，不会抛异常，所以长度不等自然判 False。

## 复杂度
时间 O(n)：n 为 arr 长度，建表 O(pieces 长度)，扫描每段只走一次。
空间 O(n)：head 存了 pieces 全部元素，切片 `arr[i:i+len(p)]` 额外开一段。

## 易错点
- 输入 `arr = [49,18,16], pieces = [[16,18,49]]`：只比对首元素 `16` 就放行，会错判成 True；必须整段切片比对，`arr[0:3] = [49,18,16] != [16,18,49]` 才返回 False。
- 输入 `arr = [1,2], pieces = [[1,2],[2]]`：这种数据违反「pieces 扁平化后互不相同」的约束，但若真出现，`head` 字典后写的 `[2]` 会覆盖 `[1,2]` 的键 `1`？不会——键是首元素，`[1,2]` 键为 1、`[2]` 键为 2，不冲突；真正的坑是 `pieces = [[1],[1,2]]` 这类重复首元素，字典静默覆盖导致漏段，正确做法是建表时若键已存在直接返回 False。

## 如果面试官追问
问：若允许 pieces 内部重排，怎么做？
答：退化成多重集合划分，需回溯或按元素计数贪心，复杂度升到指数级，不再是 O(n)。
