## 一句话思路
用倍增预处理 `up[j][i]` 表示 i 的第 2^j 个祖先，把 k 按二进制拆位逐位跳。

## 怎么做
1. 建表：`LOG = n.bit_length()`，`up[0] = parent`，`up[j][i] = up[j-1][up[j-1][i]]`，根的父亲记为 -1。
2. 查询时从低位到高位扫 k 的二进制位，第 j 位为 1 就跳 `up[j][node]`。
3. 任何一次跳完变成 -1 就提前返回 -1。

以示例 `parent = [-1,0,0,1,1,2,2]` 为例，`up[0] = [-1,0,0,1,1,2,2]`，`up[1][3] = up[0][up[0][3]] = up[0][1] = 0`，即 3 的祖父是 0。查 `getKthAncestor(5, 2)`：k=2 二进制 `10`，只有第 1 位为 1，直接取 `up[1][5] = up[0][up[0][5]] = up[0][2] = 0`，返回 0。查 `(6,3)`：k=3 是 `11`，先跳第 0 位得 `up[0][6]=2`，再跳第 1 位得 `up[1][2]=up[0][0]=-1`，返回 -1。

```python
LOG = n.bit_length()
up = [parent[:]]
for j in range(1, LOG):
    prev = up[j - 1]
    up.append([prev[p] if p != -1 else -1 for p in prev])

def getKthAncestor(node, k):
    j = 0
    while k and node != -1:
        if k & 1:
            node = up[j][node]
        k >>= 1
        j += 1
    return node
```

## 复杂度
时间：预处理 O(n log n)，每次查询 O(log k) ≤ O(log n)，log 来自 k 的二进制位数。
空间：`up` 表 O(n log n)，额外只存这张二维表。

## 易错点
- `parent[0] = -1` 直接当数组下标用 → 会取到 `up[j-1][-1]`，Python 里这是最后一个元素，静默返回错误祖先而不是报错 → 建表时必须写 `prev[p] if p != -1 else -1` 显式拦截。
- k 的二进制位数可能超过 `LOG`：n=1 时 `bit_length()` 为 1，但 k 最大也是 1，尚可；若把 `LOG` 写成 `n.bit_length()-1` 或固定 16，查 `(6,3)` 这类 k 较大的查询会在 `up[j]` 处越界 → 用 `n.bit_length()` 且循环条件带 `node != -1` 提前退出。

## 如果面试官追问
若要求支持「动态加边 + 查询」，倍增表怎么维护？答：新节点只依赖父节点，追加一列 O(log n) 即可，无需重建整表。
