## 一句话思路
从右往左维护后缀乘积 `right_prod`，同时用前缀和 `left_sum` 从左累加，第一个满足 `left_sum == right_prod` 的下标即答案。

## 怎么做
1. 先算 `nums` 总和 `total`，令 `left_sum = 0`，`right_prod = 1`（右侧为空时乘积为 1）。
2. 从 `i = n-1` 往左遍历，每步先把 `nums[i]` 从 `total` 中减去，得到 `i` 左侧总和 `left_sum`。
3. 比较 `left_sum == right_prod`，相等就记录 `ans = i`（继续往左找更小的）。
4. 每步结束把 `nums[i]` 乘进 `right_prod`，供下一个下标使用。

以 `nums = [2,8,2,2,5]` 为例：`total = 19`。`i=4` 时 `left_sum = 14`，`right_prod = 1`，不等；`i=3` 时 `left_sum = 12`，`right_prod = 5`，不等；`i=2` 时 `left_sum = 10`，`right_prod = 10`，命中，答案 2。

```python
n = len(nums)
total = sum(nums)
left_sum, right_prod = 0, 1
ans = -1
for i in range(n - 1, -1, -1):
    left_sum = total - nums[i]
    total = left_sum
    if left_sum == right_prod:
        ans = i
    right_prod *= nums[i]
return ans
```

## 复杂度
时间：O(n)，一次求和加一次倒序遍历，每个元素常数次操作。
空间：O(1)，只开了 `total`、`left_sum`、`right_prod`、`ans` 四个变量。

## 易错点
- `nums = [1]` 这类单元素输入 → 若把 `right_prod` 初始化为 0 或漏掉「右侧为空乘积为 1」的约定，会误判 `i=0` 平衡 → 正确做法是 `right_prod` 初值取 1，且 `i=0` 时 `left_sum` 必须为 0 才可能命中，本题返回 -1。
- `nums` 全为 1 或含大量 1 → 乘积增长慢、前缀和增长快，容易在 `i` 较大处就误以为找到答案而提前 `return` → 必须倒序遍历并持续更新 `ans`，不能一命中就返回，否则拿到的是最大下标而非最小。

## 如果面试官追问
若要求返回所有平衡下标而非最小一个？答：把 `ans = i` 改成 `ans.append(i)`，倒序遍历后反转列表即可，复杂度不变。
