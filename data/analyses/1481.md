## 一句话思路
统计每个数的出现次数，按次数从小到大贪心删，先删次数少的整数，删满 k 个为止。

## 怎么做
1. 用 `Counter(arr)` 得到每个整数的频次，得到频次列表 `freqs`。
2. 对 `freqs` 升序排序，因为删掉一个整数需要付出它的全部频次，频次越小越"便宜"。
3. 从小到大遍历 `freqs`，若 `k >= f` 就整类删掉（`k -= f`，答案减一），否则跳出。
4. 返回剩余不同整数个数。

以示例 2 `arr = [4,3,1,1,3,3,2], k = 3` 为例：`freqs = [1,1,2,3]`（4 和 2 各 1 次，1 是 2 次，3 是 3 次）。排序后仍是 `[1,1,2,3]`。遍历：`k=3 >= 1` 删 4，`k=2`；`k=2 >= 1` 删 2，`k=1`；`k=1 < 2` 跳出。剩下 1 和 3 两类，答案 2。

```python
from collections import Counter

freqs = sorted(Counter(arr).values())
ans = len(freqs)
for f in freqs:
    if k >= f:
        k -= f
        ans -= 1
    else:
        break
return ans
```

关键点：`k` 必须整类整类地扣，不能把某一类删一半就算它消失——只有频次被扣到 0，这一类才真正从"不同整数"里消失。

## 复杂度
时间：O(n + m log m)，n 是 arr 长度用于计数，m 是不同整数个数用于排序。
空间：O(m)，Counter 存 m 个频次，排序额外 O(m)。

## 易错点
- `k = 0` 时（如 `arr = [1,1,2], k = 0`）→ 若循环里先 `k -= f` 再判断，会把 `k` 扣成负数误删整数 → 必须先判断 `k >= f` 再扣减，`k=0` 直接返回原不同数个数。
- 频次相同的整数（如示例 2 中 4 和 2 都是 1 次）→ 若按 `arr` 原顺序删而不排序，可能先删频次大的 3（3 次）导致 `k` 不够 → 必须先 `sorted(freqs)`，让 `[1,1,2,3]` 里两个 1 优先被消耗。

## 如果面试官追问
若要求输出删除后剩下的整数集合而非个数？答：遍历时记录被整类删掉的键，最后用 `set(arr) - removed` 输出即可，复杂度不变。
