## 一句话思路
直接对 `arr` 调用 `sort`，比较键用 `fn`，因为 `fn` 的输出唯一，升序即唯一确定顺序。

## 怎么做
1. 把 `arr` 复制一份，避免原地改输入（力扣判题会复用入参）。
2. 用 `sorted(arr, key=fn)` 一次完成取键和排序，`key` 对每个元素只调用一次 `fn`。
3. 返回结果列表。

以示例 3 为例：`arr = [[3,4],[5,2],[10,1]]`，`fn = lambda x: x[1]`。`key` 阶段算出键序列 `[4, 2, 1]`，排序后元素顺序变为 `[[10,1],[5,2],[3,4]]`，对应键 `[1,2,4]` 严格递增。

```python
def sortBy(arr, fn):
    return sorted(arr, key=fn)
```

如果不用 `key` 而手写比较器，等价写法是 `sorted(arr, key=fn)` 内部按 `fn(a) < fn(b)` 判定，不要写成 `sorted(arr, key=lambda x: fn(x))` 之外的二次调用，否则 `fn` 被调用 O(n log n) 次，示例 3 里 `x[1]` 虽便宜，但题面允许 `fn` 是任意函数，重复调用是纯浪费。

关键中间值再确认一遍：示例 2 的 `arr = [{"x":1},{"x":0},{"x":-1}]`，`key` 得到 `[1, 0, -1]`，排序后字典顺序是 `x=-1, 0, 1`，与输出一致。注意这里排的是字典对象本身，不是键值，别把 `fn` 的结果当返回值。

## 复杂度
时间 O(n log n)：`key` 阶段 O(n) 次 `fn` 调用，排序比较 O(n log n)。
空间 O(n)：`sorted` 新建结果列表，`key` 缓存 n 个键值。

## 易错点
- 输入 `arr = [5,4,1,2,3]` 且直接写 `arr.sort(key=fn)` → 会原地改掉入参，判题若复用同一数组，后续用例读到已排序的 `arr` 导致结果错乱 → 用 `sorted(arr, key=fn)` 返回新列表。
- 输入示例 3 的 `[[3,4],[5,2],[10,1]]`，若写成 `sorted(arr, key=lambda x: fn(x))` 之外的 `sorted(arr, key=fn())`（漏传参或提前调用）→ 会对整个列表调用一次 `fn` 而不是逐元素，直接抛 `TypeError` → `key` 必须传函数对象 `fn` 本身，不能带括号。

## 如果面试官追问
追问：若 `fn` 可能返回重复值，要求稳定排序怎么办？
答：`sorted` 本身稳定，重复键保持原相对顺序，无需改动。
