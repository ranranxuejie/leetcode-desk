## 一句话思路
从 0 出发做一次 DFS，边权相乘得到 0 到每个单位的换算倍数，因为保证路径唯一所以无需处理多路径。

## 怎么做
1. 把 `conversions` 建成邻接表 `g`，每条边存 `(对方单位, 倍数)`，正反两个方向都存。
2. 从 0 开始 DFS，用 `res[u]` 记录「1 个 0 单位 = 多少个 u 单位」，初始 `res[0] = 1`。
3. 遍历 `g[u]` 中未访问的 `(v, f)`，令 `res[v] = res[u] * f % MOD`，再递归 `v`。
4. 返回 `res`。

以示例 2 为例，走到 `u=1` 时 `res[1]=2`，边 `(3,4)` 使 `res[3]=2*4=8`；边 `(4,5)` 使 `res[4]=2*5=10`，与输出一致。

```python
MOD = 10**9 + 7
g = [[] for _ in range(n)]
for a, b, f in conversions:
    g[a].append((b, f))
    g[b].append((a, f))
res = [0] * n
res[0] = 1
stack = [0]
while stack:
    u = stack.pop()
    for v, f in g[u]:
        if res[v] == 0:
            res[v] = res[u] * f % MOD
            stack.append(v)
```

用显式栈而非递归，避免 n=10^5 时递归深度超限。

## 复杂度
时间 O(n)：每条边在邻接表里出现两次，各访问一次。
空间 O(n)：邻接表存 2(n-1) 条边，`res` 与栈各 O(n)。

## 易错点
- 反向边倍数写错：`conversions[i]=[a,b,f]` 表示 1 个 a = f 个 b，反向是 1 个 b = 1/f 个 a。若反向也存 `f`，示例 1 中从 1 出发会把 `res[0]` 算成 `2*2=4` 而非 1。正确做法是反向边存 `f` 但只在「从 0 向外」方向使用，即只从已确定 `res[u]` 的节点推 `v`，不反向回推。
- 取模时机：`res[u]*f` 最大约 `(10^9)^2`，Python 不会溢出，但若先累乘整条路径再取模，中间值可达 `(10^9)^(10^5)`，运算极慢。正确做法是每步 `res[v] = res[u] * f % MOD` 立即取模。

## 如果面试官追问
若允许反向转换且路径不唯一，怎么办？答：把每条边存成 `(v, f)` 与 `(u, 1/f)` 的有理数形式，用分数或模逆元 `pow(f, MOD-2, MOD)` 处理，BFS 仍成立。
