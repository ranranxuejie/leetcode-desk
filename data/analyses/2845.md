## 一句话思路
把「满足 `nums[i] % modulo == k`」压成 0/1 序列求前缀和，再用哈希表数 `(pre[r] - pre[l]) % modulo == k` 的配对。

## 怎么做
1. 遍历 `nums`，令 `a[i] = 1 if nums[i] % modulo == k else 0`，累加得前缀 `pre`。
2. 条件 `cnt % modulo == k` 等价于 `(pre[r] - pre[l]) % modulo == k`，即 `pre[l] % modulo == (pre[r] - k) % modulo`。
3. 边扫边把 `pre` 的余数塞进哈希表，对每个 `r` 查 `(pre[r] - k) % modulo` 出现几次，累加到答案。
4. 表初始放 `{0: 1}`，对应空前缀 `l = -1`。

以示例 1 `nums = [3,2,4], modulo = 2, k = 1` 为例：`a = [1,0,0]`，`pre = [1,1,1]`。扫到 `r=0` 时 `pre[0] % 2 = 1`，查 `(1-1)%2 = 0`，表里 `0` 有 1 个，答案 +1；随后把余数 1 计数加一。三个 `r` 各贡献 1，答案 3。

```python
from collections import defaultdict

cnt = defaultdict(int)
cnt[0] = 1
pre = 0
ans = 0
for x in nums:
    if x % modulo == k:
        pre += 1
    ans += cnt[(pre - k) % modulo]
    cnt[pre % modulo] += 1
return ans
```

注意 `pre` 本身不必取模，只对入表的键取模；`(pre - k) % modulo` 在 Python 里对负数也返回非负，正好是需要的余数。

## 复杂度
时间 O(n)：一次遍历，哈希表均摊 O(1)。
空间 O(min(n, modulo))：哈希表最多存 `modulo` 个不同余数。

## 易错点
- `k = 0` 时（示例 2），若把条件写成 `pre[r] % modulo == k` 而漏掉 `pre[l]` 的配对，会把「cnt 是 modulo 倍数」误判成「cnt 为 0」；必须走 `(pre[r] - k) % modulo` 查表，示例 2 中 `pre = [1,1,2,3]`，`r=3` 时查 `3 % 3 = 0`，表里 0 有 1 个（空前缀），答案才得 2。
- 忘记初始化 `cnt[0] = 1`，则所有 `l = -1` 开头的子数组（示例 1 的 `[3]`、`[3,2]`、`[3,2,4]`）全部丢失，答案变 0；正确做法是先把空前缀余数 0 计入。

## 如果面试官追问
问：`modulo` 很大（如 1e9）时哈希表会不会爆？
答：不会，表里键最多 `n+1` 个不同余数，空间实际是 O(n)，与 `modulo` 无关。
