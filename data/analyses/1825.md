## 一句话思路
用三个有序容器把窗口内元素分成「小 k 个 / 中间段 / 大 k 个」，只维护中间段的和，滑动时按值迁移。

## 怎么做
1. 用 `deque` 存最近 m 个元素，`SortedList` 存全部窗口元素，另用两个 `SortedList` 分别存最小的 k 个（`low`）和最大的 k 个（`high`），中间段的和记在 `mid_sum`。
2. 每次 `addElement` 先入队入 `all`，窗口满 m 后弹出队头并从 `all` 删除。
3. 关键：每次增删后调用一次 `rebalance`，把 `all` 的前 k 个塞进 `low`、后 k 个塞进 `high`，其余进中间段，重算 `mid_sum`。
4. `calculateMKAverage` 在元素不足 m 时返回 -1，否则返回 `mid_sum // (m - 2*k)`。

以示例 `m=3,k=1`，加入 `3,1,10` 后：`all=[1,3,10]`，`low=[1]`，`high=[10]`，中间段 `[3]`，`mid_sum=3`，返回 `3 // 1 = 3`。

```python
from sortedcontainers import SortedList
from collections import deque

def rebalance(self):
    self.low = SortedList(self.all[:self.k])
    self.high = SortedList(self.all[len(self.all)-self.k:])
    self.mid = SortedList(self.all[self.k:len(self.all)-self.k])
    self.mid_sum = sum(self.mid)

def addElement(self, num):
    self.q.append(num); self.all.add(num)
    if len(self.q) > self.m:
        self.all.remove(self.q.popleft())
    self.rebalance()
```

## 复杂度
时间：每次 add 的 `rebalance` 重建三个有序表为 O(m)，总操作 10^5 时偏慢，可改为增量迁移到 O(log m)。
空间：`all/low/high/mid` 各存 O(m) 个元素，队列 O(m)。

## 易错点
- 窗口未满 m 就调 `calculateMKAverage`：示例中只有 `[3,1]` 时若直接算会拿 `m-2k=1` 做除数得 3，正确应返回 -1，必须先判 `len(q) < m`。
- 重复值 `5,5,5` 时用 `set` 或按值去重会丢元素，`low/high` 必须按多重集处理，`SortedList` 的 `remove` 只删一个副本才对。

## 如果面试官追问
问：能否把每次 add 降到 O(log m)？答：不重建，只把新元素按值插入对应段，再在段间搬移边界元素维持各段大小 k、k、m-2k。
