## 一句话思路
双指针同步扫 name 和 typed，typed 多出的字符必须等于 name 当前字符（长按），否则失败。

## 怎么做
1. 指针 `i` 扫 `name`、`j` 扫 `typed`，都从 0 开始。
2. 若 `name[i] == typed[j]`，两指针同时前进。
3. 否则若 `j > 0 and typed[j] == typed[j-1]`，说明是长按重复，只前进 `j`。
4. 否则直接返回 `False`；循环结束后要求 `i == len(name)`。

以 `name = "alex"`、`typed = "aaleex"` 为例：`i=0,j=0` 时 `'a'=='a'`，双双进到 `i=1,j=1`；此时 `name[1]='l'` 而 `typed[1]='a'`，但 `typed[1]==typed[0]`，只把 `j` 推到 2，`typed[2]='l'` 与 `name[1]` 匹配，继续。关键中间值就是 `i=1, j=1` 那一步——`j` 单独前进而 `i` 不动。

```python
i = j = 0
while j < len(typed):
    if i < len(name) and name[i] == typed[j]:
        i += 1
        j += 1
    elif j > 0 and typed[j] == typed[j - 1]:
        j += 1
    else:
        return False
return i == len(name)
```

注意 `i < len(name)` 这个守卫不能省：`name` 扫完后 `typed` 尾部若还有合法长按字符，`name[i]` 会越界。

## 复杂度
时间 O(len(name) + len(typed))，两指针各自单调前进，总步数是两者长度之和。
空间 O(1)，只开了 `i`、`j` 两个整数。

## 易错点
- `name = "alex"`、`typed = "alexx"` 这类尾部多字符：若循环条件写成 `i < len(name)` 而不是 `j < len(typed)`，会提前退出并返回 `True`，漏判尾部。正确做法是以 `j` 为循环主控，最后再校验 `i == len(name)`。
- `name = "saeed"`、`typed = "ssaaedd"`：`name` 里 `'e'` 出现两次，`typed` 里只有 `'e'` 一次。若把「长按」理解成「typed 里字符数 ≥ name 里字符数」而不逐字符对齐，会误判 `True`。正确做法是严格按位置匹配，`name` 的第二个 `'e'` 找不到对应 `typed` 字符时返回 `False`。

## 如果面试官追问
问：若要求返回具体哪些位置发生了长按，怎么改？
答：在 `j` 单独前进的分支里记录 `(j, typed[j])`，即每次跳过的重复字符下标。
