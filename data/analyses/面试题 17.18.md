## 一句话思路
用滑动窗口在 big 上维护「窗口内已覆盖 small 全部元素」，右指针扩、左指针缩，记录最短且左端点最小的窗口。

## 怎么做
1. 用 `need = Counter(small)` 记录每个目标元素还差几个，`missing = len(small)` 表示还没凑齐的元素个数。
2. 右指针 `r` 遍历 big：若 `big[r] in need`，把 `need[big[r]]` 减 1，减到仍 `>= 0` 时说明这个元素的有效需求被满足，`missing -= 1`。
3. 当 `missing == 0` 时，窗口已覆盖全部 small，尝试收缩左指针 `l`：若 `big[l]` 在 need 中，把它加回 need，加回后 `> 0` 说明该元素不再被覆盖，`missing += 1`，停止收缩。
4. 每次收缩前用 `(r - l, l)` 与当前最优比较，长度更短或长度相同但 `l` 更小则更新答案。

以示例 1 为例，`small = [1,5,9]`，`need = {1:1, 5:1, 9:1}`，`missing = 3`。右指针走到 `r=10`（值 1）时，窗口 `[7,10]` 内 1、5、9 各出现至少一次，`missing` 首次归 0；此时左指针从 7 开始收缩，`big[7]=5` 移出后 need[5] 变 1、`missing` 回到 1，收缩停止，记录 `[7,10]`。之后右指针继续走，窗口只会更长，答案不再更新。

```python
from collections import Counter
need = Counter(small)
missing = len(small)
l = 0
best = None
for r, x in enumerate(big):
    if x in need:
        need[x] -= 1
        if need[x] >= 0:
            missing -= 1
    while missing == 0:
        if best is None or (r - l, l) < (best[1] - best[0], best[0]):
            best = (l, r)
        y = big[l]
        if y in need:
            need[y] += 1
            if need[y] > 0:
                missing += 1
        l += 1
return list(best) if best else []
```

## 复杂度
时间 O(n + m)：n 为 big 长度，每个元素进出窗口各一次；m 为 small 长度用于建 Counter。
空间 O(m)：need 哈希表最多存 small 中不同元素，best 只存两个下标。

## 易错点
- 收缩条件写成 `need[y] >= 0` 就 `missing += 1`：当 big 中某元素出现次数多于 small 需求（如示例 1 的 1 出现多次），移出一个多余的 1 时 need[1] 从 -1 变 0，此时窗口仍覆盖，却误判 missing 增加，导致窗口提前断开、答案偏长。正确做法是只在 `need[y] > 0` 时才 `missing += 1`。
- 更新答案放在收缩循环外：若只在 `missing == 0` 的瞬间记一次，会漏掉收缩后更短的窗口；示例 1 中 `[7,10]` 正是收缩到极限才得到的，必须每轮 while 内先比较再收缩。

## 如果面试官追问
问：若 small 中元素可重复（不再互不相同）怎么办？
答：Counter 天然支持重复计数，`missing = len(small)` 与 `need[x] >= 0` 的判断逻辑不变，代码无需改。
