## 一句话思路
把 nums 对半拆成两段各枚举全部子集和，排序后用双指针在两侧逼近 goal。

## 怎么做
1. 拆成 `left = nums[:n//2]`、`right = nums[n//2:]`，各 ≤20 个元素，子集数 ≤2^20。
2. 对每段用位掩码枚举所有子集和，得到 `A`、`B` 两个列表（含空集和 0）。
3. 把 `B` 排序去重，对 `A` 中每个 `a`，在 `B` 里二分找最接近 `goal - a` 的值，更新答案。
4. 用示例 1：`nums=[5,-7,3,5]`，`left=[5,-7]` 得 `A=[0,5,-7,-2]`，`right=[3,5]` 得 `B=[0,3,5,8]`；取 `a=-2` 时目标 `goal-a=8`，`B` 中正好有 8，差为 0。

```python
from bisect import bisect_left
A = [0]
for x in nums[:n//2]:
    A += [s + x for s in A]
B = sorted({0} | {sum(...)})  # 实际用同样方式枚举 right 后 set 去重
ans = 10**18
for a in A:
    t = goal - a
    i = bisect_left(B, t)
    for j in (i-1, i):
        if 0 <= j < len(B):
            ans = min(ans, abs(a + B[j] - goal))
```

## 复杂度
时间：O(2^(n/2) · n/2) 枚举 + O(2^(n/2) log 2^(n/2)) 排序二分。
空间：O(2^(n/2))，存两半子集和列表。

## 易错点
- `nums` 含负数（如 `[-7,3]`）时，若误以为子集和单调而用普通双指针从两端收缩，会漏掉 `-7+3=-4` 这类组合；必须对 `B` 排序后对每个 `a` 二分，而不是两个未排序列表对撞。
- `goal` 可达 `-10^9`、单个 `nums[i]` 达 `10^7`，若用 `10**9` 当初始 `ans` 上界，遇到全正数组 `[10^7]*40` 时真实答案可能超过它；初始值要取足够大（如 `10**18`）或直接用第一个候选初始化。

## 如果面试官追问
问：n 放宽到 60 怎么办？答：折半枚举变 2^30 不可行，需改用 meet-in-the-middle 加剪枝或承认这是 NP 难、按实际数据规模取舍。
