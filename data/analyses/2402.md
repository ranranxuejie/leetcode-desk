## 一句话思路
按开始时间排序后，用「空闲会议室小顶堆 + 占用中堆（结束时间, 房间号）」模拟，每次先释放再分配。

## 怎么做
1. 把 `meetings` 按 `start` 升序排序，`free` 初始化为 `[0..n-1]` 的小顶堆，`busy` 存 `(end, room)`。
2. 对每场会议，先把 `busy` 中 `end <= start` 的全部弹出并 push 回 `free`（半闭区间，等于也算空闲）。
3. 若 `free` 非空，弹出最小房间号 `r`，会议在 `[start, start+dur)` 举办；否则弹出 `busy` 中最早结束的 `(e, r)`，会议改在 `[e, e+dur)` 举办。
4. 把 `(新结束时间, r)` 压入 `busy`，`cnt[r] += 1`；最后取 `cnt` 最大且下标最小的房间。

以示例 1 的 `n=2, meetings=[[0,10],[1,5],[2,7],[3,4]]` 为例：处理 `[2,7]` 时 `busy` 是 `(5,1),(10,0)`，`free` 为空，弹出 `(5,1)`，该会议实际区间变成 `[5,10)`，`cnt[1]` 变 2——这一步就是「延期」的关键中间值。

```python
import heapq
meetings.sort()
free = list(range(n)); heapq.heapify(free)
busy = []; cnt = [0] * n
for s, e in meetings:
    while busy and busy[0][0] <= s:
        _, r = heapq.heappop(busy)
        heapq.heappush(free, r)
    if free:
        r = heapq.heappop(free); end = e
    else:
        t, r = heapq.heappop(busy); end = t + (e - s)
    heapq.heappush(busy, (end, r))
    cnt[r] += 1
return cnt.index(max(cnt))
```

## 复杂度
时间：排序 `O(m log m)`，每次会议堆操作 `O(log n)`，共 `O(m log m + m log n)`，m 为会议数。
空间：`free`/`busy`/`cnt` 共 `O(n)`，排序额外 `O(log m)` 栈。

## 易错点
- 释放条件写成 `busy[0][0] < s` → 示例 1 中 `[5,10)` 与 `[10,11)` 首尾相接时会议室 0 不会被及时释放，导致 `[3,4]` 被错误延期到 `[10,11)` 之外；正确写法是 `<= s`，因为区间半开。
- 延期时用 `start + dur` 而不是「当前最早结束时间 + dur」→ 示例 1 的 `[2,7]` 会算成 `[2,7)` 而非 `[5,10)`，`cnt` 全错；必须取 `busy` 弹出的 `t` 作为新起点。

## 如果面试官追问
若 `n` 扩大到 `10^5` 而会议数不变，做法要改吗？不用，`busy` 堆大小受会议数限制，瓶颈仍是排序的 `O(m log m)`。
