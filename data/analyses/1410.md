## 一句话思路
把 6 个实体放进字典，从左到右扫 `text`，遇到 `&` 就查表替换，查不到就原样输出。

## 怎么做
1. 建字典 `mp`，键是 `"&amp;"` 这类完整实体串，值是单字符。
2. 用 `i` 遍历 `text`，`i` 指向 `&` 时尝试匹配。
3. 匹配成功就把对应字符追加到结果并跳过整个实体长度，否则只追加 `&` 并 `i += 1`。
4. 非 `&` 字符直接追加。

以示例 1 的 `"&amp; is an HTML entity but &ambassador; is not."` 为例：`i=0` 读到 `&`，从 `mp` 里试 `text[0:5] == "&amp;"` 命中，结果追加 `&`、`i` 跳到 5；后面 `&ambassador;` 的 `text[31:41]` 不在 `mp` 中，只追加 `&`、`i` 前进 1，其余字符原样保留。

```python
mp = {"&quot;": '"', "&apos;": "'", "&amp;": "&",
      "&gt;": ">", "&lt;": "<", "&frasl;": "/"}
res, i, n = [], 0, len(text)
while i < n:
    if text[i] == "&":
        for k, v in mp.items():
            if text.startswith(k, i):
                res.append(v); i += len(k); break
        else:
            res.append("&"); i += 1
    else:
        res.append(text[i]); i += 1
return "".join(res)
```

关键点：`startswith(k, i)` 只比对当前位置，不会误吃后面的字符；`for...else` 保证未命中时只前进 1。

## 复杂度
时间 O(n·6)，n 为 `text` 长度，每个位置最多比对 6 个实体，实体长度是常数。
空间 O(n)，`res` 列表存最终结果，最坏与输入同长。

## 易错点
- 输入 `"&ambassador;"` → 若用 `text.find(";", i)` 截取整段再查表，会得到 `"&ambassador;"` 查不到而丢掉 `&` 后面的字符；正确做法是只按 6 个固定实体长度做前缀匹配，未命中就输出单个 `&`。
- 输入 `"&amp;amp;"` → 若替换后对结果再扫一遍，会把 `&amp;` 变成 `&` 后再把 `&amp;` 二次解析成 `&`，得到 `&`；正确做法是单趟从左到右、替换后不回头，输出 `"&amp;"`。

## 如果面试官追问
若实体表扩大到上千个、长度不一，怎么优化？答：把实体按首字符分组，或建 Trie，从 `&` 起沿 Trie 走，走到终止节点即命中，单次匹配 O(最长实体长度)。
