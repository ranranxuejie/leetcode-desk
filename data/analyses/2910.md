## 一句话思路
枚举组大小下界 k，用「每个频次能否拆成若干个 k 或 k+1」判定可行性，取最小总组数。

## 怎么做
1. 先统计每个编号的出现次数，得到频次列表 `cnt`（示例 2 得 `[3,1,2]`）。
2. 组大小只能是 k 或 k+1，所以 k 的上界是 `min(cnt)`，从大到小枚举 k，第一个可行的 k 对应最少组数。
3. 对某个频次 c，判定能否拆成若干个 k 和 k+1：设用 x 个 k+1 组，则 `c - x*(k+1)` 必须是非负的 k 的倍数，即 `c % k <= c // k`（这是把 c 尽量按 k 分后，余数能用 k+1 吸收的条件）。
4. 可行时该频次的最少组数是 `ceil(c / (k+1))`，累加即答案。

以示例 2 的 `cnt = [3,1,2]` 为例：k 从 1 开始试。k=1 时，c=3 满足 `3 % 1 = 0 <= 3`，c=1 满足 `1 % 1 = 0 <= 1`，c=2 满足 `2 % 1 = 0 <= 2`，全部可行，组数 `ceil(3/2)+ceil(1/2)+ceil(2/2) = 2+1+1 = 4`，与输出一致。

```python
from collections import Counter
cnt = list(Counter(balls).values())
m = min(cnt)
for k in range(m, 0, -1):
    total = 0
    ok = True
    for c in cnt:
        if c % k > c // k:
            ok = False
            break
        total += (c + k) // (k + 1)
    if ok:
        return total
```

注意 `(c + k) // (k + 1)` 就是 `ceil(c / (k+1))`，避免浮点。

## 复杂度
时间：O(d · min(cnt))，d 是不同编号数，最坏 O(n·n) 但频次和受 n 约束，实际远小于此。
空间：O(d)，Counter 存每个编号的频次。

## 易错点
- 枚举方向搞反：从 1 往上枚举 k 会先命中「组大小更小、组数更多」的方案，示例 2 会返回 6 而非 4；必须从 `min(cnt)` 往下枚举，第一个可行即最优。
- 判定条件写成 `c % k == 0`：漏掉用 k+1 吸收余数的情况，示例 2 中 c=3、k=2 时 `3 % 2 = 1`，但 `3 // 2 = 1 >= 1`，实际可拆成 1+2 两组，写成 `== 0` 会误判不可行。

## 如果面试官追问
要求输出具体分组方案怎么办？答：在可行 k 上对每个频次先尽量用 k+1 组，剩余用 k 组，记录每组的球数即可还原。
