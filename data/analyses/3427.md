## 一句话思路
用前缀和 `pre[i+1]` 存前 i+1 项之和，每个下标 i 的区间和就是 `pre[i+1] - pre[max(0, i-nums[i])]`，一次遍历累加。

## 怎么做
1. 先建长度 `n+1` 的前缀和数组 `pre`，`pre[0]=0`，`pre[k]=sum(nums[:k])`。
2. 对每个 `i`，起点 `start = max(0, i - nums[i])`，区间和 `pre[i+1] - pre[start]`。
3. 把每个区间和累加到 `total`，返回 `total`。

以 `nums = [3,1,1,2]` 为例，`pre = [0,3,4,5,7]`。`i=3` 时 `start = max(0, 3-2) = 1`，区间和 `pre[4] - pre[1] = 7 - 3 = 4`，正是 `nums[1..3] = [1,1,2]` 的和。

```python
n = len(nums)
pre = [0] * (n + 1)
for k in range(n):
    pre[k + 1] = pre[k] + nums[k]
total = 0
for i in range(n):
    start = max(0, i - nums[i])
    total += pre[i + 1] - pre[start]
return total
```

关键点：`start` 用 `max(0, ...)` 截断，因为 `nums[i]` 可能大于 `i`，此时子数组从 0 开始。`pre` 的下标偏移是 `i+1` 对应到 `nums[i]`，别写成 `pre[i]`。

## 复杂度
时间：O(n)，建前缀和一遍、累加一遍，各扫 n 个元素。
空间：O(n)，额外开了长度 n+1 的 `pre` 数组。

## 易错点
1. `nums[i] > i` 的输入（如 `nums=[1000]`，`i=0`）→ 若直接写 `start = i - nums[i]` 会得到负数下标，`pre[-1000]` 在 Python 里会静默取到数组尾部元素，结果错得毫无报错 → 必须 `max(0, i - nums[i])` 截断。
2. 前缀和下标错位 → 写成 `pre[i] - pre[start]` 会漏掉 `nums[i]` 本身，示例 1 的 `i=0` 会算成 `pre[0]-pre[0]=0` 而非 2 → 区间和固定用 `pre[i+1] - pre[start]`。

## 如果面试官追问
问：n 放大到 10^5、`nums[i]` 到 10^9 还成立吗？答：成立，前缀和仍是 O(n)，Python 整数不溢出，只需注意答案规模。
