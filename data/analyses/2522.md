## 一句话思路
从左到右贪心，每段尽量多吞字符，因为把字符留给下一段只会让段数不减反增。

## 怎么做
1. 逐字符扫描 `s`，维护当前段的值 `cur` 和段数 `ans`。
2. 若 `cur * 10 + int(ch) <= k`，就把 `ch` 并入当前段；否则以 `ch` 开新段，`ans += 1`。
3. 若单个字符 `int(ch) > k`，直接返回 `-1`（无解）。
4. 扫描结束返回 `ans`。

以 `s = "165462", k = 60` 为例：读到 `'6'` 时 `cur = 16`，`16*10+5 = 165 > 60`，于是 `"16"` 封段，`cur` 重置为 `5`；继续 `5→54`，读到 `'6'` 时 `54*10+6 = 546 > 60`，封 `"54"`。最终切成 `"16"|"54"|"6"|"2"`，共 4 段。

```python
ans, cur = 1, 0
for ch in s:
    d = int(ch)
    if d > k:
        return -1
    if cur * 10 + d <= k:
        cur = cur * 10 + d
    else:
        ans += 1
        cur = d
return ans
```

关键点：`cur` 只增不减，一旦 `cur*10+d > k`，后面任何字符都不可能再并进来，所以此刻封段是唯一不劣的选择。

## 复杂度
时间 O(n)：每个字符恰好被读一次，`n = len(s)`。
空间 O(1)：只开了 `ans`、`cur`、`d` 三个整数。

## 易错点
- 输入 `s = "238182", k = 5`：若只判断 `cur*10+d <= k` 而不先检查 `d > k`，`'8'` 会被当成新段起点，最后返回一个假的段数；正确做法是遇到 `d > k` 立刻返回 `-1`。
- 输入 `s = "9", k = 9`：若把 `ans` 初始化为 0 再在循环里加，会漏掉最后一段；正确做法是 `ans` 初值 1（至少一段），或循环结束后补加。

## 如果面试官追问
问：若要求输出具体分割方案而非段数？
答：把每次封段的位置 `i` 记进列表，最后按位置切片 `s` 即可，时间空间仍是 O(n)。
