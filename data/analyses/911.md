## 一句话思路
预处理每个投票时刻的领先者存进 `leaders`，查询时用 `bisect_right(times, t) - 1` 定位最后一个 ≤t 的时刻，直接取答案。

## 怎么做
1. 遍历 `persons`，用 `cnt` 累计票数，维护 `best`（当前领先者）和 `best_cnt`；平票时因当前投票者刚得票，直接令 `best = p`。
2. 每处理完第 i 票，把 `best` 追加到 `leaders[i]`，使 `leaders` 与 `times` 一一对应。
3. 查询 `q(t)`：`i = bisect_right(times, t) - 1`，返回 `leaders[i]`；题面保证 `t >= times[0]`，故 `i >= 0`。

以官方示例为例，处理到 `times[5]=25`（第 6 票投给 1）时，`cnt = {0:2, 1:3}`，`best` 从 0 翻转为 1，故 `leaders[5]=1`；查询 `t=24` 时 `bisect_right` 返回 5，`i=4`，取 `leaders[4]=0`，与输出一致。

```python
from bisect import bisect_right

def build(persons, times):
    cnt, best, best_cnt = {}, -1, 0
    leaders = []
    for p in persons:
        cnt[p] = cnt.get(p, 0) + 1
        if cnt[p] >= best_cnt:
            best, best_cnt = p, cnt[p]
        leaders.append(best)
    return leaders

def q(t):
    return leaders[bisect_right(times, t) - 1]
```

## 复杂度
时间：预处理 O(n)，每次查询 O(log n)，n 为投票数。
空间：`leaders` 与 `cnt` 共 O(n)，`cnt` 最多存 n 个候选人。

## 易错点
1. 平票判定写成 `cnt[p] > best_cnt` → 示例中 `times[5]=25` 时 1 的票数 3 超过 0 的 2 没问题，但 `times[2]=10` 时 1 得 2 票追平 0 的 2 票，会错留 `best=0`，正确输出应为 1；必须用 `>=`，因为「最近获得投票者获胜」等价于当前投票者 `p` 在平票时胜出。
2. 查询用 `bisect_left(times, t)` → 当 `t` 恰好等于某个 `times[i]`（如 `t=15`）时返回下标 i 而非 i+1，`-1` 后落到 `i-1`，取到上一时刻的领先者 1，而正确答案是 0；必须用 `bisect_right` 保证「t 时刻投出的票也计入」。

## 如果面试官追问
若 `times` 不再严格递增（同一时刻多票）怎么办？答：先按时刻聚合，同一时刻内按 `persons` 顺序逐票更新 `best`，只在该时刻结束时记录一次 `leaders`，查询逻辑不变。
