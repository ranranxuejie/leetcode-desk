## 一句话思路
对 words2 逐字符取最大频次得到需求向量 need，再逐个检查 words1 中单词是否覆盖 need。

## 怎么做
1. 遍历 words2，用 `Counter` 统计每个单词，对 26 个字母取逐位最大值，得到 `need`。
2. 遍历 words1，对每个单词 `w` 统计 `Counter(w)`。
3. 检查 `need` 中每个字母 `c` 是否满足 `cnt[c] >= need[c]`，全满足则加入答案。
4. 用 `all()` 一行完成第 3 步的判定。

以示例 2 为例：`words2 = ["lc","eo"]`，`need` 为 `{'l':1,'c':1,'e':1,'o':1}`。检查 `"leetcode"` 时 `cnt` 中 l、c、e、o 均 ≥1，通过；而 `"google"` 的 `c` 为 0，被淘汰。

```python
from collections import Counter

need = Counter()
for w in words2:
    cw = Counter(w)
    for ch, v in cw.items():
        if v > need[ch]:
            need[ch] = v

ans = []
for w in words1:
    cw = Counter(w)
    if all(cw[ch] >= v for ch, v in need.items()):
        ans.append(w)
```

关键点：`need` 是**逐字母取 max**，不是把 words2 所有字符拼起来统计。示例 3 中 `words2 = ["c","cc","b"]`，`need` 为 `{'c':2,'b':1}`；若误用总和会得到 `c:3`，导致 `"cccbb"` 被错误排除（它只有 3 个 c，实际要求 2 个）。

## 复杂度
时间：O(L1 + L2)，L1、L2 分别为 words1、words2 所有字符总数，每个字符常数次哈希操作。
空间：O(1)，need 与临时 Counter 最多 26 个键。

## 易错点
- 把 words2 所有字符合并统计 → 示例 3 得到 `c:3`，`"cccbb"` 被误判淘汰 → 必须对每个单词单独统计后逐字母取 max。
- 用 `set(w) >= set(need)` 判子集 → 示例 3 中 `"acaac"` 的字符集含 c、a，看似覆盖，但 c 只有 2 个、b 为 0 → 必须比较频次而非集合。

## 如果面试官追问
若 words1 规模涨到 10^6 且需多次查询，怎么优化？答：预处理 words1 每个单词的 26 维频次向量并缓存，查询时只做向量比较，避免重复统计。
