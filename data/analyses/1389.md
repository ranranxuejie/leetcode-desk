## 一句话思路
用 Python 列表的 `insert` 按下标逐个插入，因为 `index[i] <= i` 保证插入位置永远合法。

## 怎么做
1. 建空列表 `target`，用 `zip(nums, index)` 同时遍历两个数组。
2. 每轮执行 `target.insert(j, v)`，`insert` 会把 `j` 及之后的元素整体右移一位。
3. 遍历结束直接返回 `target`。

以示例 1 为例，处理到第 4 轮 `v=3, j=2` 时，`target` 从 `[0,1,2]` 变成 `[0,1,3,2]`——原来的 `2` 被挤到下标 3；最后一轮 `v=4, j=1`，`[0,1,3,2]` 变成 `[0,4,1,3,2]`，`1/3/2` 全部右移。

```python
target = []
for v, j in zip(nums, index):
    target.insert(j, v)
return target
```

关键点：`insert(j, v)` 的语义就是「插到下标 j，原 j 位置元素后移」，和题面完全一致，不需要自己写搬移循环。

## 复杂度
时间：O(n²)，每轮 `insert` 最坏搬移 O(n) 个元素，n 为 `nums` 长度。
空间：O(n)，只开了结果数组 `target`，无其他辅助结构。

## 易错点
- 误用 `target[j] = v` 赋值 → 示例 1 第 4 轮会把 `[0,1,2]` 的 `2` 覆盖成 `3` 得 `[0,1,3]`，长度永远停在 3 → 必须用 `insert` 让长度增长并后移元素。
- 以为 `index[i]` 可能越界而加 `min(j, len(target))` 保护 → 提示保证 `index[i] <= i`，第 i 轮时 `len(target) == i`，`j == i` 就是合法的尾部追加，加保护反而掩盖逻辑错误。

## 如果面试官追问
追问：n 放大到 10^5 怎么优化？
答：从后往前倒推每个元素的最终位置，用树状数组/线段树求第 k 个空位，O(n log n)。
