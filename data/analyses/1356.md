## 一句话思路
用 `(x.bit_count(), x)` 作为排序键，元组比较天然实现「1 的个数升序，同数按值升序」。

## 怎么做
1. 对 `arr` 中每个元素 `x` 构造键 `(x.bit_count(), x)`。
2. 用 `sorted(arr, key=...)` 一次排序，Python 的 `sorted` 是稳定排序，但这里键已含 `x`，稳定性无关。
3. 直接返回结果。

以示例 1 `arr = [0,1,2,3,4,5,6,7,8]` 为例，关键中间值：`3.bit_count() == 2`、`5.bit_count() == 2`、`6.bit_count() == 2`，三者键分别为 `(2,3)`、`(2,5)`、`(2,6)`，元组第二项让它们排成 `3,5,6`；而 `1,2,4,8` 的键是 `(1,1)`、`(1,2)`、`(1,4)`、`(1,8)`，自然按数值升序。

```python
def sortByBits(arr):
    return sorted(arr, key=lambda x: (x.bit_count(), x))
```

若环境 Python < 3.8 无 `bit_count`，可写 `bin(x).count('1')`，本题 `arr[i] <= 10^4`，字符串开销可忽略。

## 复杂度
时间：排序 `O(n log n)`，每次键计算 `O(1)`（`bit_count` 对 ≤10^4 的数最多 14 位）。
空间：`O(n)` 存键元组与结果列表，排序本身额外 `O(n)`。

## 易错点
- 只写 `key=lambda x: bin(x).count('1')`：示例 1 中 `1,2,4,8` 的 1 个数都是 1，稳定排序会保留原顺序 `1,2,4,8` 看似对，但示例 4 `[2,3,5,7,11,13,17,19]` 里 `2,3,5,17` 的 1 个数都是 1，原序恰好也是升序才没暴露；换成 `[17,2]` 就会错成 `[17,2]`。必须把 `x` 放进键里。
- 用 `arr.sort(key=...)` 原地改并返回 `None`：力扣判题比较返回值，返回 `None` 直接判错。要么 `return sorted(...)`，要么 `arr.sort(...); return arr`。

## 如果面试官追问
问：若 `arr[i]` 上限提到 `10^9`，`bit_count` 还够快吗？
答：够，`bit_count` 是硬件指令，`O(1)`，键计算不变，整体仍是 `O(n log n)`。
