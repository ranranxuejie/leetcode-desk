## 一句话思路
对每个 nums[i] 预处理「变成值 v 的最少操作数」，再做分组背包 DP 求凑出 sum 的最小代价。

## 怎么做
1. 关键观察：从 x 出发，先除到某个祖先再乘 2 的幂，比反复乘除更省；所以 x 能变成的值只有「x 不断 //2 得到的链上每个值，再乘 2 的幂」，代价 = 除的次数 + 乘的次数。
2. 对每个 nums[i] 枚举链上每个祖先 a（含 x 本身），再枚举 a * 2^k ≤ sum，记录 cost[i][a*2^k]。
3. 分组背包：dp[s] = 用前 i 个元素凑出 s 的最小操作数，每个元素只能选一个值或不选。
4. 以 nums=[10,2], sum=13 为例：10 的链是 10→5→2→1，代价 0/1/2/3；2 的链是 2→1，代价 0/1。2 取 8 需 2 次（2→4→8），10 取 5 需 1 次，dp[13]=1+2=3。

```python
# 预处理单个元素的可达值
def options(x, limit):
    res, d = {}, 0
    while x:
        a, m = x, 0
        while a <= limit:
            res[a] = min(res.get(a, 10**9), d + m)
            a *= 2; m += 1
        x //= 2; d += 1
    return res

dp = [10**9] * (sum + 1); dp[0] = 0
for x in nums:
    ndp = dp[:]
    for v, c in options(x, sum).items():
        for s in range(sum, v - 1, -1):
            if dp[s - v] + c < ndp[s]:
                ndp[s] = dp[s - v] + c
    dp = ndp
ans = dp[sum] if dp[sum] < 10**9 else -1
```

## 复杂度
时间：O(n · log(max(nums)) · log(sum) · sum)，n 来自元素个数，两个 log 来自链长与倍增。
空间：O(sum)，dp 数组加每个元素的 options 字典。

## 易错点
- nums=[6,3], sum=8：若只允许「先乘后除」或只枚举 x*2^k，会漏掉 3→1→2 这条路径，错答 -1；正确做法是链上每个祖先 a 都再乘 2 的幂，3 的祖先 1 乘 2 得 2，代价 2。
- 分组背包若用正序更新 s，同一个元素会被重复选取，nums=[2,2], sum=4 会错答 1；必须倒序 `range(sum, v-1, -1)`，且用 `dp` 而非 `ndp` 做转移源。

## 如果面试官追问
问：sum 放大到 10^9 怎么办？
答：dp 数组开不下，改为对每个元素只保留 ≤ sum 的可达值做哈希表 DP，或按 sum 的二进制位贪心剪枝。
