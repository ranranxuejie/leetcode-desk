## 一句话思路
把 nums 复制一份接在后面，用前缀和 + 哈希表找「和等于 target 或 target 减掉若干个整段和」的最短窗口。

## 怎么做
1. 设 `s = sum(nums)`，`k = target // s`，`r = target % s`；答案长度 = `k * n` 加上在 `nums + nums` 里凑出 `r` 的最短窗口长度（`r == 0` 时窗口长度为 0）。
2. 在 `nums + nums` 上跑滑动窗口，维护窗口和 `cur`，左指针 `l` 只在 `cur > r` 时右移。
3. 当 `cur == r` 时更新 `ans = min(ans, k * n + (right - l + 1))`。
4. 遍历完仍无解返回 -1。

以 `nums = [1,2,3], target = 5` 为例：`s = 6`，`k = 0`，`r = 5`。窗口在 `[1,2,3,1,2]` 上滑动，当 `l = 1, right = 2` 时 `cur = 2 + 3 = 5`，长度 `2`，即答案。

```python
n = len(nums)
s = sum(nums)
k, r = divmod(target, s)
ans = float('inf')
cur = 0
l = 0
for right, x in enumerate(nums + nums):
    cur += x
    while cur > r and l <= right:
        cur -= nums[l % n]
        l += 1
    if cur == r:
        ans = min(ans, k * n + (right - l + 1))
return -1 if ans == float('inf') else ans
```

## 复杂度
时间：O(n)，`nums + nums` 长度 2n，每个元素进出窗口各一次。
空间：O(n)，复制出的 `nums + nums` 占 2n。

## 易错点
- `r == 0` 时（如 `nums = [2,4], target = 4`），窗口长度应为 0，若强行找非空窗口会返回错误长度；正确做法是 `k * n` 直接作为候选，窗口部分贡献 0。
- `target` 小于 `s` 但 `nums` 里凑不出 `r`（如 `nums = [2,4,6,8], target = 3`），`cur` 永远不等于 3，必须返回 -1，不能因为 `k = 0` 就默认有解。

## 如果面试官追问
问：若 `nums` 含负数怎么办？答：滑动窗口失效，需改用前缀和 + 哈希表存最早出现的下标，且无限数组的和不再单调。
