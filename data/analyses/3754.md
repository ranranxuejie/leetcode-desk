## 一句话思路
从低位往高位扫 `n`，用 `place` 记录当前拼接位权，跳过 0 直接拼出 `x`，同时累加 `sum`。

## 怎么做
1. 初始化 `x = 0`、`sum = 0`、`place = 1`。
2. 循环 `while n > 0`，取 `d = n % 10`，然后 `n //= 10`。
3. 若 `d != 0`，执行 `x += d * place`、`place *= 10`、`sum += d`；`d == 0` 时三者都不动。
4. 返回 `x * sum`。

以 `n = 10203004` 为例，从低位读出的数字序列是 `4,0,0,3,0,2,0,1`。前四轮里 `4` 落在 `place=1`、`3` 落在 `place=10`、`2` 落在 `place=100`、`1` 落在 `place=1000`，最终 `x = 1234`、`sum = 10`，返回 `12340`。关键点是 `place` 只在遇到非零数字时才乘 10，所以中间的 0 不会在 `x` 里留下空位——这正是「连接」而非「保留原位置」的含义。

```python
x = 0
s = 0
place = 1
while n > 0:
    d = n % 10
    n //= 10
    if d != 0:
        x += d * place
        place *= 10
        s += d
return x * s
```

注意 `n = 0` 时循环不进入，`x = 0`、`s = 0`，返回 `0`，与「不存在非零数字则 x = 0」一致，无需特判。

## 复杂度
时间：O(log n)，循环次数等于 `n` 的十进制位数，最多 10 次。
空间：O(1)，只开了 `x`、`s`、`place`、`d` 四个整数。

## 易错点
- 输入 `n = 1000` → 若把 `place *= 10` 写在 `if` 外面，`x` 会算成 `1000` 而不是 `1`，答案变成 `1000` 而非 `1` → 正确做法是 `place` 的更新必须和 `x += d * place` 一起放在 `d != 0` 分支内。
- 输入 `n = 0` → 若先写 `while n:` 再在循环后无条件 `return x * s`，结果虽是 `0` 但若误加「至少一位」的特判（比如强行令 `x = 0` 后 `s = 0` 再乘）容易写成返回 `n` 本身 → 正确做法是让循环自然不执行，直接返回 `x * s = 0`。

## 如果面试官追问
问：若 `n` 是字符串形式且长度到 `10^5`，怎么改？
答：仍用同一套 `place` 累加会超时且 `x` 巨大，改为直接收集非零字符拼成字符串，`sum` 边扫边加，最后用大整数乘法。
