## 一句话思路
逐位取模拆出每个数字，边拆边累加 `digitSum` 与 `squareSum`，最后比较差值是否 ≥ 50。

## 怎么做
1. 初始化 `digitSum = 0`、`squareSum = 0`。
2. 循环 `while n > 0`，用 `d = n % 10` 取末位，`n //= 10` 去掉末位。
3. 每轮累加 `digitSum += d`、`squareSum += d * d`。
4. 循环结束后返回 `squareSum - digitSum >= 50`。

以 `n = 19` 为例：第一轮 `d = 9`，`digitSum = 9`、`squareSum = 81`，`n` 变成 1；第二轮 `d = 1`，`digitSum = 10`、`squareSum = 82`，`n` 变成 0，退出循环，`82 - 10 = 72 >= 50`，返回 `True`。

```python
digitSum = 0
squareSum = 0
while n > 0:
    d = n % 10
    digitSum += d
    squareSum += d * d
    n //= 10
return squareSum - digitSum >= 50
```

注意循环条件用 `n > 0` 而不是 `n != 0`，因为题面保证 `n >= 1`，但写成 `> 0` 语义更贴合「正整数」；`n //= 10` 必须是整除，用 `/` 会得到浮点数导致死循环。

## 复杂度
时间：O(log n)，循环次数等于 n 的十进制位数，最多 10 次（n ≤ 10^9）。
空间：O(1)，只开了 `digitSum`、`squareSum`、`d` 三个整型变量。

## 易错点
- `n = 1000` → 若把 `squareSum - digitSum` 写成 `squareSum >= 50` 直接判断，会得到 `1 >= 50` 为 `False` 侥幸正确，但 `n = 19` 时 `squareSum = 82 >= 50` 也返回 `True`，看似对；真正翻车在 `n = 1000000` 这类数：`squareSum = 1`、`digitSum = 1`、差为 0，若误判成 `squareSum` 单独比较就会错。正确做法是严格算差值再和 50 比。
- `n = 10^9` → 若循环条件写成 `while n:` 且中途用 `/` 而非 `//`，`n` 变成浮点 `1e8` 后 `% 10` 结果失真，`digitSum` 累加出小数。正确做法是全程整数运算，`n //= 10`。

## 如果面试官追问
问：若 n 上限提到 10^18 甚至以字符串给出，怎么改？
答：逻辑不变，把输入当字符串逐字符 `int(ch)` 累加即可，仍是 O(位数) 时间、O(1) 额外空间。
