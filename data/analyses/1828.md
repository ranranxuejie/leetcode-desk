## 一句话思路
对每个查询暴力枚举全部点，用平方距离与 `r*r` 比较，避开开方误差。

## 怎么做
1. 外层遍历 `queries`，取 `xj, yj, rj`，内层遍历 `points` 取 `xi, yi`。
2. 用 `dx = xi - xj`、`dy = yi - yj`，判断 `dx*dx + dy*dy <= rj*rj`，成立则计数加一。
3. 每个查询的计数追加进 `answer`，最后返回。

以示例 1 的 `queries[0] = [2,3,1]` 为例：点 `[1,3]` 得 `dx=-1, dy=0`，平方和 `1 <= 1` 计入；点 `[5,3]` 得 `dx=3`，平方和 `9 > 1` 排除；点 `[2,2]` 得 `dx=0, dy=-1`，平方和 `1 <= 1` 计入。三个点命中，答案 3，与输出 `[3,2,2]` 首位一致。

```python
answer = []
for xj, yj, rj in queries:
    r2 = rj * rj
    cnt = 0
    for xi, yi in points:
        dx = xi - xj
        dy = yi - yj
        if dx * dx + dy * dy <= r2:
            cnt += 1
    answer.append(cnt)
```

注意 `r2` 提到内层循环外，避免 500 次重复乘法；`dx*dx` 最大 `500*500=250000`，两点相加 `500000`，远小于 `2**31 - 1`，Python 里更无溢出顾虑。

## 复杂度
时间：`O(len(queries) * len(points))`，最坏 500×500 = 25 万次距离判断。
空间：`O(1)` 额外空间，除返回的 `answer` 列表外不新开结构。

## 易错点
- 用 `math.sqrt(dx*dx+dy*dy) <= rj` 判断 → 浮点开方在边界点（如示例 1 的 `[1,3]` 距圆心恰好 1）可能因精度判成 `1.0000000002 > 1` 而漏计 → 必须全程用整数平方比较 `dx*dx + dy*dy <= rj*rj`。
- 把 `<=` 写成 `<` → 边界上的点被排除，示例 1 的 `queries[0]` 会从 3 错成 1（只剩 `[3,3]` 圆心本身）→ 题面明确边界算圆内，必须用 `<=`。

## 如果面试官追问
若 `points` 和 `queries` 都放大到 10^5，怎么做？答：对点建 KD 树或按 x 排序后对每个圆做区间剪枝，把单次查询从 O(n) 降到接近 O(log n + k)。
