## 一句话思路
锁定点把数组切成若干连续可交换段，段内排序代价是「元素数 − 环数」，解锁点选在段边界最省。

## 怎么做
1. 把 `locked[i]=1` 的位置视为墙，相邻解锁位置连成段；每段内 `nums` 的值集合必须恰好等于该段的目标下标集合，否则返回 -1。
2. 对每段算最小交换次数：段内建图 `i -> nums[i]-1`，代价 = 段长 − 环数。
3. 解锁一个墙点 `i` 会合并左右两段，合并后代价可能下降；用「合并收益」排序，贪心取收益最大的至多 k 个。
4. 总操作数 = 解锁次数 + 各段交换次数之和。

以示例 2 `nums=[3,1,2], locked=[1,0,1], k=2`：初始段只有 `[1]`（值 1 已在位，代价 0），墙点 0 和 2 各解锁一次后整段变 `[0,1,2]`，图是 `0->2, 1->0, 2->1` 一个 3-环，代价 `3-1=2`，总计 `2+2=4`。

```python
def seg_cost(seg):  # seg: 段内下标列表
    seen, cycles = set(), 0
    for i in seg:
        if i in seen: continue
        cycles += 1
        j = i
        while j not in seen:
            seen.add(j)
            j = nums[j] - 1
    return len(seg) - cycles
```
合并收益 = 左代价 + 右代价 + 1（解锁）− 合并后代价，按收益降序取前 k 个；收益 ≤0 的不取。

## 复杂度
时间：O(n log n)，排序收益贡献 log n，段内环检测 O(n)。
空间：O(n)，存段下标、visited 集合和收益列表。

## 易错点
- `nums=[2,3,1], locked=[1,0,0], k=0`：只看「段内值集合是否匹配」会漏掉墙点 0 的值 2 永远动不了，必须先把每个锁定位置 `i` 检查 `nums[i]==i+1`，否则直接 -1。
- `nums=[2,1,3,4], locked=[0,1,0,1], k=1`：把解锁成本漏算或把收益算成「交换次数差」而忘了 +1，会得 1 而非 2；收益公式必须是 `cost(L)+cost(R)+1-cost(merged)`。

## 如果面试官追问
若 k 很大（k=n）还要贪心吗？答：不用，全解锁后答案就是 `n − 环数`，直接一次算完。
