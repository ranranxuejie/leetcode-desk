## 一句话思路
按价格从低到高买，用计数排序把 costs 桶化后顺序扣 coins，买到买不起为止。

## 怎么做
1. 建长度 `max(costs)+1` 的桶 `cnt`，遍历 costs 让 `cnt[c] += 1`。
2. 从价格 `p = 1` 往上扫，每档最多买 `min(cnt[p], coins // p)` 支。
3. 每买一支就 `coins -= p`、`ans += 1`，买不起就跳出。

以示例 1 `costs = [1,3,2,4,1], coins = 7` 为例：桶为 `cnt[1]=2, cnt[2]=1, cnt[3]=1, cnt[4]=1`。p=1 时 `coins//1=7`，买 2 支后 coins=5、ans=2；p=2 买 1 支后 coins=3、ans=3；p=3 买 1 支后 coins=0、ans=4；p=4 时 `coins//4=0`，跳出，返回 4。

```python
m = max(costs)
cnt = [0] * (m + 1)
for c in costs:
    cnt[c] += 1
ans = 0
for p in range(1, m + 1):
    if coins < p:
        break
    take = min(cnt[p], coins // p)
    ans += take
    coins -= take * p
```

关键在 `take = min(cnt[p], coins // p)`：一次算清这一档能买几支，避免逐支循环在 `cnt[p]` 很大时退化。

## 复杂度
时间：O(n + max(costs))，n 来自建桶，max(costs) 来自扫桶。
空间：O(max(costs))，即计数数组 cnt，无其他额外结构。

## 易错点
- `costs = [10,6,8,7,7,8], coins = 5` → 若从 p=1 扫到 p=5 都 `cnt[p]=0`，容易漏写 `if coins < p: break` 而继续空转，虽结果仍是 0 但白扫；正确做法是保留该 break，或直接判断最小价格 `min(costs) > coins` 返回 0。
- `costs = [1,1,1,...]`（n=10^5 全为 1）、coins 很大 → 若写成逐支 `while cnt[p] and coins >= p` 内层循环，单档就转 10^5 次，总复杂度仍是 O(n) 但常数大；正确做法是用 `coins // p` 一次取整，把内层压成 O(1)。

## 如果面试官追问
问：coins 大到 10^18 呢？答：`coins // p` 与 `take * p` 在 Python 里都是大整数，逻辑不变，只是别用 C 系定长类型。
