## 一句话思路
按字母统计每天各字符出现次数，取每个字符在所有天中的最大值，再求和。

## 怎么做
1. 用长度 26 的数组 `need` 记录每个字母的历史最大需求。
2. 逐天统计当天各字母出现次数 `cnt`。
3. 对每个字母取 `need[c] = max(need[c], cnt[c])`。
4. 返回 `sum(need)`。

以 `demand = ["acd","bed","accd"]` 为例：
- 第 0 天 `cnt = {a:1,c:1,d:1}`，`need` 更新为 a=1,c=1,d=1。
- 第 1 天 `cnt = {b:1,e:1,d:1}`，`need` 变为 a=1,b=1,c=1,d=1,e=1。
- 第 2 天 `cnt = {a:1,c:2,d:1}`，`need[c]` 从 1 升到 2，其余不变。
- 最终 `need` 中 a=1,b=1,c=2,d=1,e=1，`sum = 6`。

```python
need = [0] * 26
for day in demand:
    cnt = [0] * 26
    for ch in day:
        cnt[ord(ch) - ord('a')] += 1
    for i in range(26):
        if cnt[i] > need[i]:
            need[i] = cnt[i]
return sum(need)
```

关键点：`need[c]` 取的是**跨天最大值**而不是累加，因为同一展台在不同天可重复使用。

## 复杂度
时间：O(L)，L 为所有 `demand[i]` 字符总数，每天额外扫 26 个字母。
空间：O(1)，只开两个长度 26 的数组。

## 易错点
- 把 `need[c] += cnt[c]` 写成累加 → 示例 1 中 `c` 会变成 1+0+2=3，答案错成 7 → 正确做法是 `max` 取历史峰值。
- 只统计全局字符总频次而不按天分组 → 示例 2 中 `a` 全局出现 2 次但分属不同天，会误判需要 2 个 `a` → 必须逐天统计再取 max。

## 如果面试官追问
追问：若要求输出具体展台方案（每种字母准备几个）？
答：`need` 数组本身就是方案，把下标映射回 `chr(i + ord('a'))` 即可。
