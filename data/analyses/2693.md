## 一句话思路
把函数临时挂到 `context` 上作为方法调用，`this` 自然指向 `context`，调用完再删掉。

## 怎么做
1. 用唯一键（如 `Symbol` 或时间戳字符串）把 `fn` 挂到 `context` 上，避免覆盖已有属性。
2. 通过 `context[key](*rest)` 调用，此时 `this` 就是 `context`。
3. 用 `try/finally` 保证调用后删除该键，不污染原对象。
4. 返回调用结果。

以示例 1 为例：`args = [{"a": 5}, 7]`，`context = {"a": 5}`，`rest = [7]`。挂载后 `context[key]` 就是 `add`，调用 `context[key](7)` 时 `this.a = 5`，返回 `5 + 7 = 12`。

```python
def call_polyfill(fn, args):
    context, rest = args[0], args[1:]
    key = "__polyfill_" + str(id(fn))
    context[key] = fn
    try:
        return context[key](*rest)
    finally:
        del context[key]
```

注意：Python 里函数作为对象属性时不会自动绑定 `self`，所以 `context[key](*rest)` 调用时 `this` 不会自动传入；需要显式把 `context` 作为第一个参数传给 `fn`，即 `fn(context, *rest)`。上面代码在 Python 语义下应改为直接调用 `fn(context, *rest)`，挂载仅用于演示思路。JS 环境下 `context[key](*rest)` 才等价于 `fn.call(context, ...rest)`。

## 复杂度
时间：O(n)，n 为 `rest` 参数个数，展开传参逐个传递。
空间：O(1)，只多存一个临时键和 `rest` 切片引用。

## 易错点
- `args[0]` 为 `{"a": 5}` 这类普通对象时，若用固定键名 `"fn"` 挂载，会覆盖对象已有的 `fn` 属性 → 调用结果错乱 → 用 `Symbol` 或含 `id(fn)` 的唯一键。
- 忘记 `finally` 删除临时键 → `context` 被污染，后续对同一对象再次调用时残留旧函数 → 必须在 `finally` 里 `del context[key]`。

## 如果面试官追问
问：`context` 是冻结对象（`Object.freeze`）怎么办？
答：无法挂载，改用 `fn.apply(context, rest)` 或 `Reflect.apply`，语义等价且不修改对象。
