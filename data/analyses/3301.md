## 一句话思路
从大到小排序后贪心取 `min(maximumHeight[i], 上一个高度-1)`，因为大上限的塔让出空间给谁都不亏。

## 怎么做
1. 把 `maximumHeight` 降序排序，让上限大的塔先占高位。
2. 维护 `prev = 10**18`（比任何上限都大），逐座塔计算 `h = min(maximumHeight[i], prev - 1)`。
3. 若 `h <= 0` 说明已经挤到 1 以下，直接返回 `-1`；否则累加 `h` 并令 `prev = h`。

以 `[2,3,4,3]` 为例：排序得 `[4,3,3,2]`。第一座 `h = min(4, 10**18-1) = 4`，`prev=4`；第二座 `h = min(3,3) = 3`，`prev=3`；第三座 `h = min(3,2) = 2`，`prev=2`；第四座 `h = min(2,1) = 1`。总和 `4+3+2+1 = 10`，与示例一致。

```python
maximumHeight.sort(reverse=True)
prev = 10**18
total = 0
for cap in maximumHeight:
    h = min(cap, prev - 1)
    if h <= 0:
        return -1
    total += h
    prev = h
return total
```

关键点：`prev - 1` 保证严格递减，`min(cap, ...)` 保证不超上限；降序保证每个 `cap` 都尽量被用满。

## 复杂度
时间：排序 `O(n log n)`，遍历 `O(n)`，n 为塔数。
空间：排序原地 `O(1)` 额外（Python 的 Timsort 最坏 `O(n)` 辅助）。

## 易错点
- 输入 `[2,2,1]` → 若升序贪心，先给 1 号塔取 1，剩下两座上限 2 只能取 2 和 1，冲突返回 -1 看似对；但升序在 `[3,3,1]` 会先占 1 再取 3、2 得 6，而降序得 3、2、1 也是 6——真正翻车的是 `[1,100]` 升序先取 1 再取 100 得 101 没问题，但 `[2,2,2]` 升序取 2、1、0 提前判 -1，降序取 2、1、0 同样 -1，正确。核心坑是**必须降序**：`[5,5,5]` 降序得 5、4、3 和 12，若乱序可能得 5、3、4 仍 12，但 `[10,2,2]` 降序 10、2、1 和 13，升序 2、1、0 直接 -1 误判。正确做法：先 `sort(reverse=True)`。
- 输入 `[1]` → `prev - 1 = 10**18 - 1`，`h = min(1, ...) = 1`，返回 1 正确；但若把 `prev` 初始化为 `0`，`h = min(1, -1) = -1` 会误返 -1。正确做法：`prev` 初值取大于 `10**9` 的数，如 `10**18`。

## 如果面试官追问
要求输出具体高度方案怎么办？答：把每步的 `h` 存进与排序后下标对应的数组，最后按原下标映射回去即可，时间不变。
