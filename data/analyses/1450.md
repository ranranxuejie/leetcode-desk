## 一句话思路
逐对比较 `startTime[i] <= queryTime <= endTime[i]`，因为每个学生独立、区间含端点，计数即可。

## 怎么做
1. 用 `zip(startTime, endTime)` 同时取出每个学生的 `s` 和 `e`，避免下标错位。
2. 对每对判断 `s <= queryTime <= e`，Python 支持链式比较，等价于 `s <= queryTime and queryTime <= e`。
3. 条件成立就 `count += 1`，遍历完返回 `count`。

拿示例 1 走一遍：`startTime = [1,2,3]`、`endTime = [3,2,7]`、`queryTime = 4`。
- 第 1 对 `(1,3)`：`1 <= 4 <= 3` 为 `False`，`count = 0`。
- 第 2 对 `(2,2)`：`2 <= 4 <= 2` 为 `False`，`count = 0`。
- 第 3 对 `(3,7)`：`3 <= 4 <= 7` 为 `True`，`count = 1`。
返回 `1`，与官方输出一致。关键中间值是第 3 对的 `s=3, e=7`，只有它把 `queryTime=4` 包住。

```python
count = 0
for s, e in zip(startTime, endTime):
    if s <= queryTime <= e:
        count += 1
return count
```

也可以写成一行生成器：`return sum(s <= queryTime <= e for s, e in zip(startTime, endTime))`，布尔值在 Python 里可直接当 0/1 相加。

## 复杂度
时间：O(n)，n 是 `startTime.length`，每个学生只比较一次。
空间：O(1)，只开了 `count` 一个累加变量，`zip` 是惰性迭代不建新列表。

## 易错点
1. 把区间当成左闭右开 `[s, e)` 写 `s <= queryTime < e` → 示例 2 的 `startTime=[4], endTime=[4], queryTime=4` 会错成 `0` → 题目明确是闭区间 `[startTime[i], endTime[i]]`，必须用 `<=` 两端。
2. 用 `startTime.index(queryTime)` 或只比较 `startTime` 而漏掉 `endTime` → 示例 5 中 `queryTime=5` 时，`startTime` 里小于等于 5 的有 5 个，但若只看开始时间不看结束时间，遇到 `endTime[i] < queryTime` 的学生会多算 → 必须成对取 `(s, e)` 同时判断两端，`zip` 保证下标对齐。

## 如果面试官追问
追问：如果 `queryTime` 有很多个查询怎么办？
答：把每个学生拆成 `(startTime[i], +1)` 和 `(endTime[i]+1, -1)` 两个事件，按时间排序做前缀和，单次查询 O(log n)。
