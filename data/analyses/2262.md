## 一句话思路
按右端点增量累加：以 `s[i]` 结尾的所有子串引力之和 = 上一轮总和 + (i - 上次出现位置)，因为新字符只对起点在 `last[c]` 之后的子串贡献 +1。

## 怎么做
1. 维护 `last` 字典记录每个字符上次出现的下标，初始为空；`cur` 表示以当前字符结尾的所有子串引力之和，`ans` 累加 `cur`。
2. 遍历 `i, ch`：若 `ch` 未出现过，`cur += i + 1`；否则 `cur += i - last[ch]`。
3. 更新 `last[ch] = i`，`ans += cur`。

以 `s = "abbca"` 为例，走到 `i=2`（第二个 `'b'`）时 `last['b']=1`，`cur` 从 3 变成 `3 + (2-1) = 4`；走到 `i=4`（第二个 `'a'`）时 `last['a']=0`，`cur` 从 9 变成 `9 + (4-0) = 13`，`ans` 最终为 28。

```python
last = {}
cur = ans = 0
for i, ch in enumerate(s):
    if ch in last:
        cur += i - last[ch]
    else:
        cur += i + 1
    last[ch] = i
    ans += cur
return ans
```

关键点：`cur` 不是「当前子串的引力」，而是「以 `i` 结尾的全部 `i+1` 个子串的引力之和」，`ans` 再对 `cur` 求和。

## 复杂度
时间 O(n)：每个字符只做一次字典查询和常数次加法，n 为 `len(s)`。
空间 O(1)：`last` 最多 26 个键，与 n 无关。

## 易错点
- 把 `cur` 当成单个子串的引力去 `ans += cur` 之外再算别的 → 对 `"abbca"` 会得到 5 而非 28；正确做法是 `cur` 始终是「以 i 结尾的所有子串引力之和」，`ans` 只做累加。
- 首次出现的字符写成 `cur += i` 而非 `i + 1` → 对 `"code"` 的 `i=0` 会漏掉 1，结果变成 16 而非 20；正确做法是未出现时贡献 `i + 1`（起点可取 0..i 共 `i+1` 个）。

## 如果面试官追问
若要求返回引力最大的那个子串而非总和？答：仍需 O(n) 扫描，但要在 `cur` 更新时同步记录取到最大值的右端点，再回溯左端点，空间升到 O(n)。
