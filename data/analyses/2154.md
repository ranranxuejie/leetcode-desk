## 一句话思路
把 nums 丢进 set，然后 while original in s 就 original *= 2，集合 O(1) 查找让链式判断不退化。

## 怎么做
1. 用 `s = set(nums)` 建哈希集合，去重同时把查找降到 O(1)。
2. 写 `while original in s:` 循环，命中就 `original *= 2`。
3. 一旦 `original` 不在 `s` 中，循环退出，直接返回 `original`。

拿示例 1 走一遍：`nums = [5,3,6,1,12]`，`original = 3`，`s = {1,3,5,6,12}`。第一轮 `3 in s` 为真，`original` 变成 6；第二轮 `6 in s` 为真，变成 12；第三轮 `12 in s` 为真，变成 24；第四轮 `24 in s` 为假，退出返回 24。关键中间值是第三轮结束时的 `original = 24`，它恰好是 12 的两倍且不在集合里。

```python
s = set(nums)
while original in s:
    original *= 2
return original
```

注意循环条件写在 `in s` 上，而不是先取出来再判断，这样少一次赋值。`original` 每轮翻倍，最多翻到超过 `max(nums)` 就停，因为 `nums[i] <= 1000`，所以循环次数不超过约 11 次（从 1 翻到 1024）。示例 2 里 `original = 4`，`s = {2,7,9}`，第一轮 `4 in s` 就是假，循环体一次没进，直接返回 4。

## 复杂度
时间 O(n + log(max/original))：建集合扫一遍 n，翻倍循环最多 log 次。
空间 O(n)：额外开了一个 set 存 nums 的去重元素。

## 易错点
- 输入 `nums = [2,4,8], original = 2` 且数组里有重复值如 `[2,2,4]`：若用 list 的 `in` 判断，每次查找 O(n)，链长时退化成 O(n log)；正确做法是先 `set(nums)`，重复值对结果无影响，因为只关心「在不在」。
- 输入 `nums = [1], original = 1`：若把循环写成 `while original in nums: original *= 2` 后忘了在 `original` 超出范围时停，逻辑上没问题但会多算；真正的坑是 `original` 翻倍后可能超过 `1000`，此时必然不在集合里，不要额外加 `original <= 1000` 的边界判断，否则 `nums` 含 1000 时 `original = 1000` 翻成 2000 会被错误截断——直接靠 `in s` 判断即可。

## 如果面试官追问
问：如果 nums 长度到 10^5、值域到 10^9 呢？答：set 方案不变，时间仍是 O(n + log)，只是哈希表内存变大，无需排序。
