## 一句话思路
按起点贪心：每一轮在所有 `start <= 当前已覆盖右端` 的片段里挑 `end` 最大的，跳数最少。

## 怎么做
1. 预处理：把 `clips` 按 `start` 升序排序，用指针 `i` 扫描。
2. 维护 `cur`（当前已覆盖到哪）和 `far`（本轮能延伸到的最远点），每轮把 `start <= cur` 的片段全部吃进来更新 `far`。
3. 若某轮 `far == cur`，说明没有片段能接上，返回 `-1`；否则 `cur = far`、`ans += 1`，直到 `cur >= time`。

以示例 1 为例：排序后第一轮吃进 `[0,2]`，`far = 2`，`cur` 从 0 变 2、`ans = 1`；第二轮吃进 `[1,9]`、`[1,5]`，`far = 9`，`cur = 9`、`ans = 2`；第三轮吃进 `[8,10]`，`far = 10 >= time`，`ans = 3`。

```python
clips.sort()
cur = far = ans = i = 0
while cur < time:
    while i < len(clips) and clips[i][0] <= cur:
        far = max(far, clips[i][1])
        i += 1
    if far == cur:
        return -1
    cur, ans = far, ans + 1
return ans
```

关键点：`i` 只前进不回退，被吃进来的片段不会重复计入，所以每轮 `far` 是「从 `cur` 出发一步能到的最远处」。

## 复杂度
时间：排序 O(n log n)，扫描 O(n)，n 为 `clips` 长度。
空间：排序额外 O(log n)（或 O(n)），其余只有几个整型变量。

## 易错点
- 输入 `clips = [[0,1],[1,2]]`、`time = 5`：若只判断「有没有片段 `start == cur`」就继续，会在 `cur = 2` 后找不到起点为 2 的片段却仍返回计数。正确做法是每轮先看 `far` 是否还等于 `cur`，相等立刻返回 `-1`。
- 输入 `clips = [[0,2],[0,3],[1,4]]`、`time = 4`：若按排序顺序逐个累加而不是取 `max`，会先选 `[0,2]` 再选 `[1,4]` 得 2，实际 `[0,3]` 加 `[1,4]` 也是 2，但若写成「遇到第一个 `start <= cur` 就停」会漏掉 `[0,3]` 导致多跳。正确做法是本轮把所有 `start <= cur` 的片段都扫完，取最大 `end`。

## 如果面试官追问
问：要求输出具体选了哪些片段怎么办？
答：在更新 `far` 时记录取到最大 `end` 的那个片段下标，每轮结束时把它压入结果列表即可。
