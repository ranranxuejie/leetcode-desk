## 一句话思路
对每个 i 只比较 nums[i] 与 nums[i-k]、nums[i+k]（存在才比），全满足就累加，因为好元素定义就是逐点局部比较。

## 怎么做
1. 遍历 `i` 从 0 到 `len(nums)-1`，先假设 `ok = True`。
2. 若 `i-k >= 0` 且 `nums[i] <= nums[i-k]`，置 `ok = False`。
3. 若 `i+k < len(nums)` 且 `nums[i] <= nums[i+k]`，置 `ok = False`。
4. `ok` 为真时把 `nums[i]` 加进 `total`。

以示例 1 `nums = [1,3,2,1,5,4], k = 2` 为例：`i=1` 时左邻 `nums[-1]` 不存在（`1-2=-1`），右邻 `nums[3]=1`，`3 > 1` 成立，`ok` 保持 `True`，累加 3；`i=0` 时右邻 `nums[2]=2`，`1 > 2` 不成立，`ok` 变 `False`，跳过。最终 `total = 3+5+4 = 12`。

```python
total = 0
n = len(nums)
for i in range(n):
    ok = True
    if i - k >= 0 and nums[i] <= nums[i - k]:
        ok = False
    if i + k < n and nums[i] <= nums[i + k]:
        ok = False
    if ok:
        total += nums[i]
return total
```

关键点：两个边界判断必须分开写，不能写成 `nums[i] > nums[i-k] and nums[i] > nums[i+k]` 后直接索引，否则 `i-k < 0` 会取到倒数元素（Python 负索引不报错，静默算错）。

## 复杂度
时间：O(n)，每个 i 最多做两次比较，n 为 `len(nums)`。
空间：O(1)，只开了 `total`、`ok`、`n` 三个标量。

## 易错点
1. 输入 `nums = [2,1], k = 1` 且用负索引直接写 `nums[i-k]` → `i=0` 时 `nums[-1]` 取到 1，`2 > 1` 恰好成立，看似对；但换成 `nums = [1,2], k = 1` 时 `i=0` 的 `nums[-1]=2`，`1 > 2` 判为不好，实际左邻不存在应为好 → 必须先判 `i-k >= 0` 再比较。
2. 输入 `nums = [1,3,2,1,5,4], k = 2` 中 `i=5` → 右邻 `5+2=7 >= 6` 不存在，若漏判 `i+k < n` 会索引越界或（用取模/负索引时）误比 `nums[1]=3`，把 `4 > 3` 当成唯一条件，虽本例结果不变但逻辑已错 → 两个方向各自独立判边界。

## 如果面试官追问
若 k 随查询变化、要求多次询问好元素之和？答：预处理前缀和无法直接用，因为好元素依赖 k；可对每个 k 重扫 O(n)，或按 k 分组离线处理，n≤100 时直接每次 O(n) 即可。
