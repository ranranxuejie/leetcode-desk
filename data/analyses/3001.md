## 一句话思路
答案只可能是 1 或 2：先判车/象能否一步吃，否则车两步必到。

## 怎么做
1. 先判车：若 `a == e`（同列）或 `b == f`（同行），再看象是否卡在中间。
2. 再判象：若 `abs(c - e) == abs(d - f)`（同对角线），再看车是否卡在中间。
3. 两者都不成立，返回 2——车总能先走到皇后所在行/列再吃。

以示例 1 为例：`a=1,b=1,c=8,d=8,e=2,f=3`。车不同行不同列；象的 `abs(8-2)=6`、`abs(8-3)=5`，不等，所以不是 1，返回 2。

关键在「卡住」的判定，必须用**严格介于**，不能写成 `<=`：

```python
def blocked_by_car(c, d, e, f):
    # 象在车的攻击线上，且位于车与皇后之间
    if c == e and min(b, f) < d < max(b, f):
        return True
    if d == f and min(a, e) < c < max(a, e):
        return True
    return False
```

象挡车时，象必须与车同列（`c == e`）且 `d` 严格夹在 `b` 与 `f` 之间；同行同理。反过来车挡象，要判车是否落在象到皇后的对角线段上：`abs(a - c) == abs(b - d)` 且 `abs(a - e) == abs(b - f)`，并且车在两者之间（用 `min/max` 夹一次即可）。

示例 2 验证：`a=5,b=3,c=3,d=4,e=5,f=2`。车 `a == e == 5` 同列，象在 `(3,4)`，`d=4` 不在 `min(3,2)=2` 与 `max(3,2)=3` 之间，没挡住，直接返回 1。

## 复杂度
时间 O(1)：只做常数次比较与 `abs`。
空间 O(1)：没有开任何数组或集合。

## 易错点
- 输入 `a=1,b=1,c=1,d=3,e=1,f=5`：车和象同列且象夹在中间，若把「卡住」写成 `min(b,f) <= d <= max(b,f)`，会把象自身位置也算进去，误判成被挡而返回 2；正确做法是严格不等号 `min(b,f) < d < max(b,f)`。
- 输入 `a=1,b=1,c=2,d=2,e=3,f=3`：车不在象的对角线上，象一步可吃，但若判「车挡象」时只写 `abs(a-c)==abs(b-d)` 而漏掉「车也在象到皇后的线段上」，会误判成被挡返回 2；正确做法是同时要求 `abs(a-e)==abs(b-f)` 且车坐标夹在象与皇后之间。

## 如果面试官追问
问：若棋盘扩到 n×n、棋子数变多怎么办？答：仍只需检查每个攻击者到皇后的线段上是否有棋子，用行/列/对角线集合预处理，O(1) 查询。
