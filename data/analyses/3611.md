## 一句话思路
按 `(employee_id, 周一日期)` 分组求和，筛出周和 > 20 的周再计数，最后 join 员工表过滤 ≥ 2。

## 怎么做
1. 用 `meeting_date - weekday` 把每条会议折算到所在周的周一，作为分组键。
2. 按 `(employee_id, week_start)` 聚合 `sum(duration_hours)`，只保留 `> 20` 的行。
3. 对剩下的行按 `employee_id` 计数，得到 `meeting_heavy_weeks`，再 `HAVING >= 2`。
4. join `employees` 拿姓名部门，按周数降序、姓名升序排。

关键中间值：Alice 的 2023-06-05（周一）→ week_start 仍是 06-05，三条 8+6+7=21 > 20；06-12 那周 12+9=21 > 20，计数 2。Bob 的 06-05 周 15+8=23 过线，06-12 周只有 10，计数 1 被 `HAVING` 刷掉。

```python
# meetings 已读成 DataFrame df，含 employee_id / meeting_date / duration_hours
df["meeting_date"] = pd.to_datetime(df["meeting_date"])
df["week_start"] = df["meeting_date"] - pd.to_timedelta(df["meeting_date"].dt.weekday, unit="D")
weekly = df.groupby(["employee_id", "week_start"], as_index=False)["duration_hours"].sum()
heavy = weekly[weekly["duration_hours"] > 20]
cnt = heavy.groupby("employee_id").size().reset_index(name="meeting_heavy_weeks")
cnt = cnt[cnt["meeting_heavy_weeks"] >= 2]
res = cnt.merge(emp, on="employee_id")
res = res.sort_values(["meeting_heavy_weeks", "employee_name"], ascending=[False, True])
```

## 复杂度
时间 O(n log n)：n 为 meetings 行数，排序与分组主导。
空间 O(n)：weekly 中间表按 (员工, 周) 去重后最多 n 行。

## 易错点
- 用 `WEEK()` 或 `YEARWEEK()` 分组 → 周起始可能落在周日或跨年错位，2023-06-05 会被算进上一周，Alice 的 21 小时被拆散。正确做法是显式减 `weekday` 得到周一。
- 阈值写成 `>= 20` → Bob 的 06-12 周恰好 10 不受影响，但若有员工某周正好 20.0 会被误判为密集周。题目要求「超过 50%」，必须是严格 `> 20`。

## 如果面试官追问
问：如果要求输出每个密集周的具体日期区间而不只是计数？
答：保留 `week_start` 和 `week_start + 6 days` 两列，在 `HAVING` 前不聚合掉，直接按员工列出区间即可。
