## 一句话思路
以「箱子位置 + 玩家相对箱子的方位」为状态做 BFS，每层推动一次，首次到 T 即最小推动数。

## 怎么做
1. 先定位 `S`、`B`、`T`，状态用 `(bx, by, px, py)` 表示箱子坐标和玩家坐标。
2. 对每个状态枚举四个推箱方向 `(dx, dy)`：箱子目标格 `(bx+dx, by+dy)` 必须是地板，且玩家要能走到箱子反方向的格子 `(bx-dx, by-dy)`。
3. 「玩家能否走到」用一次 BFS/DFS 在**把箱子当墙**的地图上判断，起点是当前玩家位置。
4. 推动后新状态是 `(bx+dx, by+dy, bx, by)`（玩家站到箱子原位置），推动数 +1，入队。

以示例 1 为例：初始 `B=(2,3)`、`S=(4,4)`。第一次推动方向 `(0,-1)`，箱子目标 `(2,2)` 是 `.`，玩家需到 `(2,4)`——从 `(4,4)` 沿第 4 行、第 4 列绕行可达，于是状态变为 `(2,2,2,3)`，`dist=1`。三次推动后箱子到 `(1,1)=T`，返回 3。

```python
from collections import deque
def can_reach(grid, sx, sy, tx, ty, box):
    if (sx, sy) == (tx, ty): return True
    q, seen = deque([(sx, sy)]), {(sx, sy)}
    while q:
        x, y = q.popleft()
        for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
            nx, ny = x+dx, y+dy
            if 0<=nx<m and 0<=ny<n and grid[nx][ny]!='#' \
               and (nx,ny)!=box and (nx,ny) not in seen:
                if (nx,ny)==(tx,ty): return True
                seen.add((nx,ny)); q.append((nx,ny))
    return False
```

主循环里对每个出队状态，若 `can_reach(grid, px, py, bx-dx, by-dy, (bx,by))` 为真才推。

## 复杂度
时间 O(m²n²·(m+n))：状态数 m²n²，每个状态一次内层 BFS 最多 O(mn)，实际远小于此。
空间 O(m²n²)：`seen` 集合存四元组状态，外加内层 BFS 的 visited。

## 易错点
- 示例 2 中箱子在 `(2,3)`、玩家在 `(4,4)`，第 3 行 `(3,3)` 是 `.` 但 `(3,2)` 是 `#`：若只判断「箱子目标格可走」而不检查玩家能否绕到 `(2,4)`，会误判为可推、输出有限值；正确做法是每次推动前都跑 `can_reach`，此处玩家到不了 `(2,4)`，返回 -1。
- 把玩家坐标也放进状态去重时，若只按 `(bx,by)` 去重会漏掉「同一箱子位置、玩家在不同侧」的差异：示例 3 箱子在 `(2,3)`，玩家从下方 `(4,4)` 与从左侧 `(2,2)` 到达时后续可推方向不同，必须用四元组 `(bx,by,px,py)` 做 key，否则会提前剪掉通往 5 步的路径。

## 如果面试官追问
若要求输出具体推动序列而非次数？答：BFS 队列里存 `(状态, 路径)` 或记录 `parent` 指针，出队到 T 时回溯即可，代价是空间从 O(状态数) 升到 O(状态数×路径长)。
