## 一句话思路
枚举位数 len（最多约 60），对每个 len 二分找底数 k，使 1+k+…+k^(len-1) = n；len 从大到小找，首个命中即最小 k。

## 怎么做
1. 把 n 转成 int，len 从 `n.bit_length()` 递减到 2，因为 k≥2 时位数最多是 log2(n)+1。
2. 对固定 len，底数 k 的可行区间是 `[2, n-1]`，且 `f(k)=sum(k^i)` 关于 k 单调递增，可二分。
3. 二分中用 `while` 累乘并提前截断，超过 n 就判大，避免大整数膨胀。
4. 命中即返回 `str(k)`；len=2 时 k=n-1 必然成立（n = 1 + (n-1)），作为兜底。

以 n=4681 为例：len 从 13 递减，len=5 时二分区间 [2,4680]，mid=2340 时 f 远超 4681 判大，逐步收缩到 k=8，验证 1+8+64+512+4096=4681，返回 "8"。

```python
def check(n, k, length):
    total, cur = 1, 1
    for _ in range(length - 1):
        cur *= k
        total += cur
        if total > n:
            return 1
    return 0 if total == n else -1

for length in range(n.bit_length(), 1, -1):
    lo, hi = 2, n - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        r = check(n, mid, length)
        if r == 0:
            return str(mid)
        if r > 0:
            hi = mid - 1
        else:
            lo = mid + 1
return str(n - 1)
```

## 复杂度
时间：外层 O(log n) 个 len，每个 len 二分 O(log n) 次、每次累乘 O(log n)，共 O(log³ n)。
空间：O(1)，只用了 total、cur、lo、hi 几个整数。

## 易错点
- n="1000000000000000000" 时若只枚举 len≥3 就返回，会漏掉 len=2 的答案 999999999999999999；必须保留 len=2 兜底，且它对应 k=n-1 而非 k=n。
- 二分上界写成 `n` 而非 `n-1`：len=2 时 k=n 得 1+n≠n，会多一次无效判定；同时 check 里不提前截断，cur 会涨到 n^len 量级，Python 虽不溢出但乘法和比较代价剧增，必须 `total > n` 立即返回。

## 如果面试官追问
问：若 n 上限提到 10^100 怎么办？
答：len 上界变成约 333，仍可枚举，但二分区间 [2,n-1] 需改用大整数比较，复杂度 O(log³n) 不变。
