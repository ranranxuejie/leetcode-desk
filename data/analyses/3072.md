## 一句话思路
把 nums 离散化后用两棵 Fenwick 树维护 arr1/arr2 的值域计数，每次 O(log n) 查「严格大于」的个数再决定归属。

## 怎么做
1. 对 `sorted(set(nums))` 建映射 `rank`，值域大小 `m`；两棵 BIT 各开 `m+1`。
2. 前两个元素直接落位：`nums[0]` 进 arr1、`nums[1]` 进 arr2，同时 `add` 到对应 BIT。
3. 从 `i = 2` 起，令 `r = rank[nums[i]]`，`c1 = len(arr1) - query(bit1, r)`（前缀和含等于，减掉才是严格大于），`c2` 同理。
4. 按 `c1 > c2` → arr1；`c1 < c2` → arr2；相等比长度，长度也相等进 arr1；最后 `add` 到选中那棵 BIT。

以 `nums = [2,1,3,3]` 为例，`rank = {1:1, 2:2, 3:3}`。`i = 2` 时 `r = 3`，`query(bit1, 3) = 1`、`len(arr1) = 1`，得 `c1 = 0`；`c2` 同样为 0；长度 1 == 1，落 arr1。`i = 3` 时 `c1 = c2 = 0`，但 `len(arr1) = 2 > len(arr2) = 1`，落 arr2。

```python
def add(bit, i, m):
    while i <= m:
        bit[i] += 1
        i += i & -i

def query(bit, i):
    s = 0
    while i > 0:
        s += bit[i]
        i -= i & -i
    return s

# 主循环内：
r = rank[nums[i]]
c1 = len(arr1) - query(bit1, r)
c2 = len(arr2) - query(bit2, r)
if c1 > c2 or (c1 == c2 and len(arr1) <= len(arr2)):
    arr1.append(nums[i]); add(bit1, r, m)
else:
    arr2.append(nums[i]); add(bit2, r, m)
```

## 复杂度
时间：离散化排序 O(n log n)，n 次操作每次两次 BIT 查询加一次更新，共 O(n log n)。
空间：两棵 BIT 各 O(m)，m ≤ n，加上 rank 字典与两个结果数组，O(n)。

## 易错点
- `nums = [3,3,3,3]` → 若用 `query(bit, r)` 当「大于」的个数，会把相等的 3 也算进去，`c1`、`c2` 恒为 0 但长度判断被带偏；正确写法是 `len(arr) - query(bit, r)`，前缀和只统计 ≤ r 的部分。
- `nums = [5,14,3,1,2]` → 若直接拿 `nums[i]` 当下标建 BIT，值域到 10^9 直接爆内存；必须先 `rank` 压缩到 1..m，且 `add` 的边界是 `m` 不是 `n`。

## 如果面试官追问
问：n 放大到 10^7 还这么写？答：BIT 常数小仍可用，但离散化排序成瓶颈，可换基数排序或改用平衡树在线插入。
