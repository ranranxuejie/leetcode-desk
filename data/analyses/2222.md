## 一句话思路
合法三元组必是 `010` 或 `101`，枚举中间位置 i，用左右两侧异类计数相乘再累加。

## 怎么做
1. 合法子序列只有 `010` 和 `101` 两种形态，所以中间那栋建筑的类型决定两端类型。
2. 对每个位置 i 作为中间点，统计它左边与 `s[i]` 不同的个数 `left`、右边与 `s[i]` 不同的个数 `right`，贡献 `left * right`。
3. 用两个前缀计数数组（或一次遍历维护）避免 O(n²) 枚举。

以 `s = "001101"` 为例，取 i=4（`s[4]='0'`）：左边 `s[0..3]="0011"` 中 `'1'` 有 2 个，右边 `s[5]='1'` 中 `'1'` 有 1 个，贡献 `2*1=2`，对应 `[0,4,5]` 和 `[1,4,5]` 之外的 `[2,4,5]`、`[3,4,5]`。全部 i 累加得 6。

```python
n = len(s)
pre = [0, 0]          # pre[c] = 前 i 个字符里 c 的个数
suf = [s.count('0'), s.count('1')]
ans = 0
for i, ch in enumerate(s):
    suf[int(ch)] -= 1
    ans += pre[1 - int(ch)] * suf[1 - int(ch)]
    pre[int(ch)] += 1
return ans
```

关键中间值：i=2（`s[2]='1'`）时 `pre=[2,0]`、`suf=[1,2]`，贡献 `pre[0]*suf[0]=2*1=2`。

## 复杂度
时间 O(n)：一次遍历，每步 O(1) 查表。
空间 O(1)：只开 `pre`、`suf` 两个长度 2 的数组。

## 易错点
- 输入 `"11100"`：若只判断「存在 0 和 1」就返回非零，会错成 6 之类；正确做法是必须中间点两侧都有异类，此例 i=2 时 `suf[0]=2` 但 `pre[0]=0`，贡献 0，最终 0。
- 输入 `"001101"`：若把 `left`、`right` 统计成「同类个数」而非「异类个数」，i=4 会算成 `pre[0]*suf[0]=2*1=2` 但方向反了导致 i=2 处漏算；正确做法是固定取 `1 - int(ch)` 这一侧。

## 如果面试官追问
问：若要求输出所有合法下标三元组而非计数？
答：同样枚举中间点 i，对每个 i 用左右异类下标列表做笛卡尔积，总输出量即答案规模，复杂度 O(答案数)。
