## 一句话思路
按下标奇偶分别累加数字，最后比较两个和是否相等。

## 怎么做
1. 初始化 `even_sum = 0`、`odd_sum = 0`。
2. 用 `enumerate(num)` 同时拿到下标 `i` 和字符 `ch`，`i % 2 == 0` 就加到 `even_sum`，否则加到 `odd_sum`。
3. 遍历结束后返回 `even_sum == odd_sum`。

以 `num = "24123"` 为例，走到 `i = 4` 时 `even_sum = 2 + 1 + 3 = 6`、`odd_sum = 4 + 2 = 6`，两者相等返回 `True`。注意 `i = 4` 是偶数下标，`ch = '3'` 加进 `even_sum`，这一步最容易漏。

```python
even_sum = odd_sum = 0
for i, ch in enumerate(num):
    if i % 2 == 0:
        even_sum += int(ch)
    else:
        odd_sum += int(ch)
return even_sum == odd_sum
```

关键点：`ch` 是字符，必须 `int(ch)` 转成数字再累加，直接加字符会报 `TypeError`；下标从 0 开始，所以「偶数下标」对应 `i % 2 == 0`，不是从 1 数。

## 复杂度
时间 O(n)：`enumerate` 扫一遍 `num`，n 为字符串长度。
空间 O(1)：只开了 `even_sum`、`odd_sum` 两个整数。

## 易错点
- 输入 `num = "1234"` → 若把下标从 1 开始数，会把 `1 + 3` 算成奇数下标、`2 + 4` 算成偶数下标，虽然本例仍得 4 和 6 判 `False`，但换成 `"24123"` 就会把 `2 + 1 + 3` 错算成奇数侧，得 `6 != 6` 之外的错误结果 → 正确做法是严格用 `i % 2 == 0` 判偶数下标。
- 输入 `num = "10"` → 若用 `sum(int(num[::2]))` 和 `sum(int(num[1::2]))` 切片，`num[::2]` 得 `"1"`、`num[1::2]` 得 `"0"`，看似对；但若写成 `num[1::2]` 漏了起始 1 的偏移，或对空切片 `sum` 得 0 时误判 → 正确做法是显式 `enumerate` 累加，不依赖切片边界。

## 如果面试官追问
问：如果要求返回使字符串平衡需要修改的最少字符数？
答：算 `abs(even_sum - odd_sum)` 后按差值能否由单个数字调整覆盖来推，本质是差值除以 9 向上取整的变体，需重新建模。
