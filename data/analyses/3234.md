## 一句话思路
枚举左端点，用「零的个数平方」封顶窗口长度，滑动右端点统计合法子串。

## 怎么做
1. 固定左端点 `i`，右端点 `j` 从 `i` 开始向右扩，维护窗口内 `ones` 和 `zeros`。
2. 关键剪枝：一旦 `zeros * zeros > ones` 且继续扩只会让 `zeros` 增、`ones` 增得慢，但 `zeros²` 增长更快，所以当 `zeros > sqrt(n)` 时直接 `break`——因为 `ones ≤ n`，`zeros² > n` 后不可能再满足。
3. 对每个 `i`，只要 `ones >= zeros * zeros` 就 `ans += 1`，然后 `j += 1` 继续。

以 `s = "00011"` 为例：`i=2` 时，`j=2` 得 `zeros=1, ones=0`，`0 >= 1` 不成立；`j=3` 得 `zeros=1, ones=1`，`1 >= 1` 成立，`ans += 1`；`j=4` 得 `zeros=1, ones=2`，`2 >= 1` 成立，`ans += 1`。这一轮贡献 2 个。

```python
n = len(s)
ans = 0
for i in range(n):
    zeros = ones = 0
    for j in range(i, n):
        if s[j] == '1':
            ones += 1
        else:
            zeros += 1
        if zeros * zeros > ones:
            if zeros * zeros > n:   # 再扩也不可能满足
                break
        else:
            ans += 1
```

注意 `break` 条件要放在 `zeros*zeros > ones` 分支里，否则会误伤。

## 复杂度
时间：外层 n 次，内层受 `zeros ≤ sqrt(n)` 约束，O(n·sqrt(n))。
空间：只用了 `zeros`、`ones`、`ans` 几个变量，O(1)。

## 易错点
- 输入 `s = "1111"`：若把 `break` 写成「`zeros*zeros > ones` 就 break」，`zeros=0` 时 `0 > ones` 永不成立，看似没事；但换成 `s = "0000"`，`i=0` 时 `j=0` 就 `1 > 0` 触发 break，会漏掉后面所有 `i` 的合法窗口——正确做法是只在 `zeros*zeros > n` 时才 break，因为 `ones ≤ n` 是硬上界。
- 输入 `s = "101101"`：若在 `zeros*zeros > ones` 时直接 `continue` 而不判断 `zeros*zeros > n`，内层会一直跑到 `j = n-1`，退化成 O(n²)，4×10⁴ 规模下超时——正确做法是加上 `zeros*zeros > n` 的 break 剪枝。

## 如果面试官追问
问：如果 n 放大到 10⁶ 怎么办？
答：改用「枚举 1 的个数 k」，对每个 k 用前缀和定位第 k 个 1 的位置，窗口长度受 `zeros ≤ sqrt(k)` 约束，复杂度 O(n·sqrt(n)) 但常数更小，或直接按 1 的位置分段统计。
