## 一句话思路
对每个 i 用 `(i + nums[i]) % n` 一步算出落脚下标，取模天然处理左右越界。

## 怎么做
1. 记 `n = len(nums)`，新建 `result = [0] * n`。
2. 遍历每个下标 i，直接算 `j = (i + nums[i]) % n`，正负都交给 Python 取模。
3. 令 `result[i] = nums[j]`，返回 `result`。

以 `nums = [3,-2,1,1]`、`n = 4` 为例：i=1 时 `nums[1] = -2`，`j = (1 + (-2)) % 4 = -1 % 4 = 3`，`nums[3] = 1`，所以 `result[1] = 1`；i=3 时 `j = (3+1) % 4 = 0`，`nums[0] = 3`，`result[3] = 3`。负下标靠 Python 的 `%` 自动回到 `[0, n)`，不用手写 `if j < 0: j += n`。

```python
n = len(nums)
result = [0] * n
for i, v in enumerate(nums):
    j = (i + v) % n
    result[i] = nums[j]
return result
```

`nums[i] == 0` 时 `j = i`，`result[i] = nums[i] = 0`，与题面第三条规则一致，无需单独分支。

## 复杂度
时间 O(n)：每个下标一次取模一次取值。
空间 O(n)：只额外开了长度 n 的 `result`，没有别的辅助结构。

## 易错点
- `nums = [-1,4,-1]` 中 i=0 得 `j = -1 % 3 = 2`：若用 C 风格取模或写成 `(i + v + n) % n` 之外的 `abs` 处理，会得到 -1 或越界下标 → 正确做法是直接用 Python 的 `%`，它对负数返回非负余数。
- `nums = [3,-2,1,1]` 中 i=0 的 `nums[0] = 3` 恰好等于 `n-1` 步：若误写成 `(i + v) % (n-1)` 或先 `v %= n` 再判断正负，会把 `nums[0]=3` 落到下标 0 而非 3 → 正确做法是模数固定为 `n`，且不对 `v` 做任何预处理。

## 如果面试官追问
问：若 nums 长度到 10^7 且要求原地修改怎么办？
答：仍 O(n) 时间，但需先备份被覆盖位置或用额外数组，原地需按环置换处理。
