## 一句话思路
每步都取当前最大值，用大顶堆维护，因为取最大值后它变成 ceil(x/3) 仍可能最大，贪心可证。

## 怎么做
1. 把 `nums` 全部取负压入 `heapq`，Python 只有小顶堆，负号即大顶堆。
2. 循环 `k` 次：弹出堆顶 `x`（已取负），`ans += -x`。
3. 把 `-x` 替换成 `-((-x + 2) // 3)` 再压回，`(v + 2) // 3` 就是 `ceil(v/3)`。
4. 返回 `ans`。

以示例 2 `nums = [1,10,3,3,3], k = 3` 为例：堆顶是 10，`ans = 10`，压回 `ceil(10/3) = 4`；第二次堆顶变 4，`ans = 14`，压回 `ceil(4/3) = 2`；第三次堆顶是 3，`ans = 17`。注意第二次取的是 4 而不是 3，这正是贪心的关键。

```python
import heapq

def maxKelements(nums, k):
    h = [-v for v in nums]
    heapq.heapify(h)
    ans = 0
    for _ in range(k):
        v = -heapq.heappop(h)
        ans += v
        heapq.heappush(h, -((v + 2) // 3))
    return ans
```

## 复杂度
时间：`O(n + k log n)`，`n` 来自建堆，`k` 次各一次 `log n` 的弹出与压入。
空间：`O(n)`，堆里始终存 `n` 个元素，无其他额外结构。

## 易错点
- 用 `v // 3` 代替 `ceil`：输入 `nums = [10], k = 1` 时 `10 // 3 = 3`，正确是 `4`，第二次取到的值就偏小。必须写 `(v + 2) // 3`。
- 忘记 Python 是小顶堆：直接 `heapq.heappop` 弹出的是最小值 1，示例 2 会算成 `1 + 3 + 3 = 7` 而非 17。压入时统一取负，弹出后再取负还原。

## 如果面试官追问
问：若 `k` 达到 `10^9` 怎么优化？答：值降到 1 后不再变化，可先模拟到全为 1，剩余次数直接加 `k_rest`，避免逐次循环。
