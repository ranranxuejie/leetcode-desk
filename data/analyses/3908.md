## 一句话思路
把 n 转成字符串，用 `str(n)[0]` 判首位、`str(x) in str(n)` 判是否含 x，两个条件同时成立才返回 `True`。

## 怎么做
1. 先把 `n` 和 `x` 都转成字符串：`s = str(n)`，`t = str(x)`。
2. 判断首位：`s[0] == t` 为真说明以 x 开头，直接返回 `False`。
3. 判断包含：`t in s` 为真说明至少出现一次 x。
4. 两个条件合并返回 `s[0] != t and t in s`。

以示例 1 的 `n = 101, x = 0` 为例：`s = "101"`，`t = "0"`，`s[0]` 是 `"1"` 不等于 `"0"`，`"0" in "101"` 为 `True`，所以返回 `True`。示例 2 的 `n = 232, x = 2`：`s[0]` 是 `"2"` 等于 `"2"`，第一个条件就挂了，返回 `False`。

```python
def validDigit(n, x):
    s, t = str(n), str(x)
    if s[0] == t:
        return False
    return t in s
```

注意 `x` 是单个数字，`str(x)` 长度恒为 1，所以 `t in s` 等价于「s 中某个字符等于 t」，不会出现子串误判。`n = 0` 时 `s = "0"`，`s[0]` 合法，不会越界。

## 复杂度
时间：O(log n)，`str(n)` 生成和两次扫描都按 n 的位数走。
空间：O(log n)，`s` 和 `t` 两个字符串，t 恒为 1 个字符。

## 易错点
- `n = 0, x = 0` → 若先判「包含」再判「开头」容易漏掉首位检查，返回 `True`；正确做法是先比 `s[0] == t` 直接 `False`，因为 0 以 0 开头。
- `n = 5, x = 1` → 若只写 `t in s` 就返回 `True`，漏了「至少包含」这个反向条件；正确做法是 `t in s` 为假时返回 `False`，两个条件缺一不可。

## 如果面试官追问
问：如果 n 的范围放大到 10^18 甚至以字符串形式给出，怎么办？
答：逻辑不变，直接对字符串做 `s[0]` 和 `in` 判断，O(len) 时间，无需转整数。
