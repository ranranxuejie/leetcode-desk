## 一句话思路
排序后取 `nums[1]`，因为长度 ≥3 时它必然既非最小也非最大。

## 怎么做
1. 先判长度：`len(nums) < 3` 时直接返回 `-1`，此时数组最多只有最小和最大两个值。
2. 对 `nums` 排序，使最小值落在 `nums[0]`、最大值落在 `nums[-1]`。
3. 返回 `nums[1]`，它严格大于 `nums[0]`、严格小于 `nums[-1]`。

以 `nums = [3,2,1,4]` 为例：排序后得到 `[1,2,3,4]`，`nums[0]=1`、`nums[-1]=4`，取 `nums[1]=2`，2 既不是 1 也不是 4，直接命中示例答案。

```python
def findNonMinOrMax(nums):
    if len(nums) < 3:
        return -1
    nums.sort()
    return nums[1]
```

关键点在于「所有数字互不相同」这条约束：它保证了排序后 `nums[0] < nums[1] < nums[-1]` 严格成立，所以 `nums[1]` 不会等于边界值。若存在重复元素，`nums[1]` 可能等于 `nums[0]`，这个写法就失效了。

另外，题目只要求返回「任一」符合条件的数，因此不需要找中位数、不需要比较 `nums[1]` 与 `nums[-2]`，取排序后第二个元素是最省事的做法。也可以不排序，用 `min(nums)` 和 `max(nums)` 各扫一遍，再遍历找第一个落在两者之间的元素，但排序写法更短，且 `n ≤ 100` 时开销可忽略。

## 复杂度
时间：`O(n log n)`，由 `nums.sort()` 的排序贡献，`n = len(nums)`。
空间：`O(log n)`，排序的递归栈开销，未额外开数组。

## 易错点
- 输入 `nums = [1,2]` 或 `nums = [5]` → 若直接返回 `nums[1]` 会越界或返回最大值本身 → 必须先判 `len(nums) < 3` 返回 `-1`。
- 输入 `nums = [2,1,3]` → 若误以为要返回中位数以外的值、或先取 `min`/`max` 再遍历却漏掉边界比较 → 应直接排序取 `nums[1]`，它天然满足 `nums[0] < nums[1] < nums[-1]`。

## 如果面试官追问
问：如果数组允许重复元素，还能取 `nums[1]` 吗？
答：不能，需排序后找第一个满足 `nums[0] < x < nums[-1]` 的 `x`，找不到返回 `-1`。
