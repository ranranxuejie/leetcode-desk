## 一句话思路
把 ages 排序后，对每个 x 用二分找满足条件的 y 区间，区间长度就是 x 发出的请求数。

## 怎么做
1. 排序 ages，使「ages[y] 落在 [0.5*ages[x]+7, ages[x]]」变成一个连续下标区间。
2. 对每个 x，用 `bisect_right` 求上界 `hi = bisect_right(ages, ages[x])`，用 `bisect_right(ages, ages[x]//2 + 7)` 求下界 `lo`。
3. 该 x 的请求数 = `hi - lo`，再减去自己（若自己落在区间内，即 `ages[x] > ages[x]//2 + 7`）。
4. 累加所有 x。

以 `ages = [16,17,18]` 排序后不变。x=17：`ages[x]//2+7 = 15`，`lo = bisect_right(ages,15) = 0`，`hi = bisect_right(ages,17) = 2`，区间 [0,2) 含 16、17，减自己得 1（17→16）。x=18：`18//2+7=16`，`lo=1`，`hi=3`，区间含 17、18，减自己得 1（18→17）。x=16：`16//2+7=15`，`lo=0`，`hi=1`，区间只含自己，减自己得 0。合计 2。

```python
from bisect import bisect_right
ages.sort()
ans = 0
for x in ages:
    lo = bisect_right(ages, x // 2 + 7)
    hi = bisect_right(ages, x)
    ans += hi - lo
    if x > x // 2 + 7:   # 自己落在区间内
        ans -= 1
return ans
```

注意 `ages[y] <= 0.5*ages[x]+7` 是「不发送」，所以下界用 `bisect_right(ages, x//2+7)` 跳过所有 ≤ 该值的元素；`x//2` 对整数等价于 `0.5*x` 向下取整，因为 `0.5*x+7` 的比较对象是整数，`x//2+7` 恰好是满足 `ages[y] > 0.5*ages[x]+7` 的最小整数下界。

## 复杂度
时间：排序 O(n log n)，n 次二分各 O(log n)，共 O(n log n)。
空间：排序原地 O(log n) 栈空间，无额外数组。

## 易错点
- 输入 `[16,16]` → 若忘记减自己，每个 16 的区间 `[0,2)` 长度 2，答案错成 4 → 必须判断 `x > x//2+7` 时减 1，得 2。
- 输入 `[20,30,100,110,120]` → 若用 `0.5*x+7` 浮点比较，100 与 110 的边界可能因浮点误差错判 → 统一用整数 `x//2+7`，110 的 `lo=bisect_right(ages,62)=2`，正确排除 20、30。

## 如果面试官追问
若要求输出所有请求对而非总数？答：二分定位区间后遍历 `ages[lo:hi]` 逐个输出，复杂度升到 O(答案规模)。
