## 一句话思路
用哈希表 `used` 记录已占用的文件名，并缓存每个基名下一个可用的 `k`，避免每次从 1 重试。

## 怎么做
1. 维护 `used` 集合存所有已分配名字，`nxt` 字典存基名 → 下一个待试的 k。
2. 对每个 `name`，若 `name not in used`，直接占用，并把 `nxt[name]` 初始化为 1。
3. 否则从 `nxt[name]` 起递增 k，拼出 `name(k)`，直到不在 `used` 中；占用后把 `nxt[name]` 更新为 k+1。

以示例 5 `["kaido","kaido(1)","kaido","kaido(1)"]` 为例：处理到第 3 个 `"kaido"` 时，`used` 已有 `kaido`、`kaido(1)`，`nxt["kaido"]` 从 1 起试，`kaido(1)` 被占，k 增到 2，得 `kaido(2)`，`nxt["kaido"]=3`。第 4 个 `"kaido(1)"` 是独立基名，`used` 里已有它，从 `nxt["kaido(1)"]=1` 起试得 `kaido(1)(1)`。

```python
used = set()
nxt = {}
ans = []
for name in names:
    if name not in used:
        used.add(name)
        nxt.setdefault(name, 1)
        ans.append(name)
    else:
        k = nxt.get(name, 1)
        while f"{name}({k})" in used:
            k += 1
        cand = f"{name}({k})"
        used.add(cand)
        nxt[name] = k + 1
        ans.append(cand)
```

关键点：`nxt[name]` 只增不减，因为更小的 k 对应的名字一旦被占用就永远被占用。

## 复杂度
时间：每个名字最多被 while 推进一次，总 O(总字符数)，n 为 names 长度。
空间：`used` 存 n 个字符串，O(总字符数)。

## 易错点
- 输入 `["kaido","kaido(1)","kaido","kaido(1)"]` → 若把 `"kaido(1)"` 当成 `"kaido"` 的后缀去重，会错成 `kaido(2)`、`kaido(2)` → 正确做法是把 `"kaido(1)"` 当独立基名，它被占后加后缀得 `kaido(1)(1)`。
- 输入 `["wano","wano","wano","wano"]` → 若每次从 k=1 重试，虽结果对但退化成 O(n²) → 正确做法是用 `nxt["wano"]` 缓存上次的 k，直接跳到 3。

## 如果面试官追问
若 names 长度升到 10^6 且要求返回时按字典序？答：仍用同一哈希表，最后对 `ans` 排序，时间多一个 O(n log n)。
