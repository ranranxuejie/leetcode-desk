## 一句话思路
排序后取最小的两个价格 `prices[0] + prices[1]`，与 `money` 比较，够就返回差值，不够返回 `money`。

## 怎么做
1. 对 `prices` 升序排序，最小的两块必然在 `prices[0]` 和 `prices[1]`。
2. 计算 `cost = prices[0] + prices[1]`。
3. 若 `cost > money`，两块都买不起，返回 `money`；否则返回 `money - cost`。

以示例 1 `prices = [1,2,2], money = 3` 为例：排序后仍是 `[1,2,2]`，`cost = 1 + 2 = 3`，`3 > 3` 不成立，返回 `3 - 3 = 0`。关键中间值是 `cost = 3`，恰好等于 `money`，所以走的是「够买」分支而不是返回 `money`。

示例 2 `prices = [3,2,3], money = 3`：排序后 `[2,3,3]`，`cost = 2 + 3 = 5`，`5 > 3` 成立，返回 `money = 3`。

```python
prices.sort()
cost = prices[0] + prices[1]
if cost > money:
    return money
return money - cost
```

注意比较用的是严格大于：`cost == money` 时剩余为 0，是合法的非负数，必须返回 0 而不是 `money`。

## 复杂度
时间：O(n log n)，排序贡献 log n，n 为 `prices` 长度。
空间：O(1)，原地排序，只开了 `cost` 一个变量。

## 易错点
- 输入 `prices = [1,2,2], money = 3` → 若把判断写成 `cost >= money` 就返回 `money = 3`，错成 3 → 正确是 `cost > money` 才返回 `money`，相等时返回 0。
- 输入 `prices = [3,2,3], money = 3` → 若直接返回 `money - cost = -2`，违反「剩余钱数必须非负」→ 必须先判 `cost > money` 提前返回 `money`，不能无条件相减。

## 如果面试官追问
问：如果要求返回买的是哪两块（下标）？
答：排序会丢下标，改成对 `(price, index)` 排序或一次遍历维护最小两个值和它们的下标，返回这两个下标即可。
