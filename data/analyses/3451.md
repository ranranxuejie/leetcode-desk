## 一句话思路
用 SQL 的 `REGEXP` 逐条判定 ip 是否合法，再 `GROUP BY ip` 计数，最后按 `invalid_count`、`ip` 双降序输出。

## 怎么做
1. 先按 `ip` 分组，`COUNT(*)` 得到每个 IP 出现次数，记为 `invalid_count`。
2. 用正则把「合法 IPv4」整体匹配出来，取反即为无效：`^(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)(\.(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)){3}$`。
3. 该正则同时卡住三件事：每段 0–255、无前导零（`[1-9]?\d` 不允许 `01`）、恰好 4 段（`{3}` 表示再跟 3 段）。
4. 外层 `WHERE ip NOT REGEXP ...` 过滤，`ORDER BY invalid_count DESC, ip DESC`。

以示例 `192.168.001.1` 为例：第三段 `001` 无法匹配 `[1-9]?\d`（`[1-9]?` 至多一位非零，后面只能再跟一位数字），整串匹配失败，被 `NOT REGEXP` 留下，计数为 2。而 `192.168.1.1` 四段全过，被排除。

```python
# 伪代码：核心判定逻辑
pattern = r'^(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)(\.(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)){3}$'
def is_valid(ip: str) -> bool:
    import re
    return re.fullmatch(pattern, ip) is not None

# 等价 SQL 骨架
# SELECT ip, COUNT(*) AS invalid_count
# FROM logs
# WHERE ip NOT REGEXP '<pattern>'
# GROUP BY ip
# ORDER BY invalid_count DESC, ip DESC;
```

若用 Python 实现，`re.fullmatch` 已隐含首尾锚定，`^...$` 可省；`is not None` 比 `bool(...)` 更直白。

## 复杂度
时间：O(n·L)，n 为行数、L 为 IP 串长（≤15），正则单次匹配常数级。
空间：O(k)，k 为不同 ip 数，用于分组聚合，无额外大结构。

## 易错点
- 输入 `1.1.1.01` → 若正则写成 `\d{1,3}` 会误判为合法 → 必须用 `[1-9]?\d` 或 `0|[1-9]\d{0,2}` 显式排除前导零。
- 输入 `1.1.1.1.1`（5 段）→ 若只校验每段范围、不锚定段数，会漏判 → 正则末尾必须 `{3}$` 且整串 `fullmatch`，不能只 `search`。

## 如果面试官追问
问：若 ip 列含 `NULL` 或空串怎么办？
答：`NULL NOT REGEXP` 结果为 `NULL` 被过滤，需显式 `OR ip IS NULL` 或先 `COALESCE(ip,'')` 纳入无效统计。
