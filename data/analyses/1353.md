## 一句话思路
按天扫描，每天在已开始且未结束的会议里选 endDay 最小的那个参加，用最小堆维护。

## 怎么做
1. 把 events 按 startDay 升序排序，指针 i 指向下一个待加入堆的会议。
2. 从第 1 天扫到最大 endDay，每天先把 `startDay <= d` 的会议 `(endDay)` 压入堆。
3. 弹出堆顶（endDay 最小者）作为当天参加的会议，`ans += 1`；若堆顶 `endDay < d` 说明已过期，直接丢弃继续弹。
4. 堆空则跳过该天。

以示例 2 `[[1,2],[2,3],[3,4],[1,2]]` 为例：排序后为 `[[1,2],[1,2],[2,3],[3,4]]`。第 1 天压入两个 `endDay=2`，弹出 2，`ans=1`；第 2 天压入 `endDay=3`，堆为 `[2,3]`，弹出 2，`ans=2`；第 3 天压入 `endDay=4`，堆为 `[3,4]`，弹出 3，`ans=3`；第 4 天堆为 `[4]`，弹出 4，`ans=4`。

```python
events.sort()
heap, i, ans = [], 0, 0
for d in range(1, max(e for _, e in events) + 1):
    while i < len(events) and events[i][0] <= d:
        heapq.heappush(heap, events[i][1])
        i += 1
    while heap and heap[0] < d:
        heapq.heappop(heap)
    if heap:
        heapq.heappop(heap)
        ans += 1
return ans
```

关键点：第 2 天堆顶是 2 而非 3，因为两个 `[1,2]` 的 endDay 都是 2，先消耗截止更早的。

## 复杂度
时间：排序 O(n log n)，扫描天数 O(D log n)，D 为最大 endDay。
空间：堆最多存 n 个 endDay，O(n)。

## 易错点
- 输入 `[[1,2],[1,2],[1,2]]` → 若按 startDay 排序后直接顺序取，会误判为 3 场 → 正确做法是每天只取 endDay 最小的，第 3 天堆已空，答案应为 2。
- 输入 `[[1,1],[1,2],[2,2]]` → 若扫描时先弹堆顶再判过期，会把第 1 天的 `endDay=1` 误留到第 2 天 → 正确做法是每天先 `while heap[0] < d` 清过期，再取堆顶。

## 如果面试官追问
问：要求输出具体参加了哪些会议怎么办？
答：堆里存 `(endDay, 会议下标)`，每天弹出时记录 `(d, idx)` 即可，复杂度不变。
