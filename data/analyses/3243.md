## 一句话思路
每次加边后从 0 跑一次 BFS，因为 n≤500、queries≤500，500 次 BFS 完全够用。

## 怎么做
1. 建邻接表 `g`，初始对每个 `i` 加边 `i -> i+1`。
2. 对每条查询 `[u, v]`，把 `v` 追加进 `g[u]`。
3. 从 0 做 BFS，`dist[0]=0`，其余 `-1`，返回 `dist[n-1]`。
4. 把结果追加进 `answer`。

以示例 1 的 `n=5, queries=[[2,4],[0,2],[0,4]]` 为例：处理完第一条边后 `g[2]=[3,4]`，BFS 队列依次弹出 0、1、2、3、4，`dist[4]=3`；加入 `0->2` 后 `g[0]=[1,2]`，0 先到 2 再到 4，`dist[4]=2`。

```python
from collections import deque

g = [[] for _ in range(n)]
for i in range(n - 1):
    g[i].append(i + 1)

answer = []
for u, v in queries:
    g[u].append(v)
    dist = [-1] * n
    dist[0] = 0
    q = deque([0])
    while q:
        x = q.popleft()
        for y in g[x]:
            if dist[y] == -1:
                dist[y] = dist[x] + 1
                q.append(y)
    answer.append(dist[n - 1])
```

## 复杂度
时间：每次 BFS 遍历 O(n + 边数)，边数最多 n-1+queries 条，总 O(q·(n+q))。
空间：邻接表 O(n+q)，`dist` 与队列各 O(n)。

## 易错点
- 忘记初始的 `i -> i+1` 链，只把 queries 的边加进 `g`：示例 1 第一条查询后 `g[0]` 为空，BFS 到不了 4，`dist[4]` 停在 -1，输出 `[-1,...]`；正确做法是先建好链再加查询边。
- 把新边当成无向边或反向加 `v -> u`：示例 2 加 `0->3` 后若同时加 `3->0`，BFS 可能绕路，`dist[3]` 仍为 1 但后续 `0->2` 时路径计数会乱；本题边严格单向，只 `g[u].append(v)`。

## 如果面试官追问
若 n 和 queries 都放大到 1e5，怎么做？答：用有序集合维护未访问点，BFS 时只跳未访问的，配合每条新边增量更新，或改用 0-1 BFS 思路。
