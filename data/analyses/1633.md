## 一句话思路
按 contest_id 分组数注册人数，除以 Users 总行数再乘 100，用 ROUND 保留两位。

## 怎么做
1. 先取分母：`SELECT COUNT(*) FROM Users`，示例里是 3。
2. 对 Register 按 contest_id 分组，`COUNT(user_id)` 得该赛事注册人数，示例里 215 组是 2、207 组是 1。
3. 用 `ROUND(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM Users), 2)` 算百分比，乘 `100.0` 而不是 `100` 是为了触发小数除法。
4. `ORDER BY percentage DESC, contest_id ASC`，示例中 208/209/210 都是 100.0，靠第二键升序排成 208、209、210。

```python
# 思路等价于下面这段 SQL
# SELECT contest_id,
#        ROUND(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM Users), 2) AS percentage
# FROM Register
# GROUP BY contest_id
# ORDER BY percentage DESC, contest_id ASC
```

关键中间值：215 组 `COUNT(*)=2`，分母 3，`2 * 100.0 / 3 = 66.666...`，ROUND 后 `66.67`；207 组 `1 * 100.0 / 3 = 33.33`。若写成 `COUNT(*) * 100 / 3`，整数除法得 66 和 33，两位小数全丢。

## 复杂度
时间：O(m + n)，m 为 Register 行数做分组，n 为 Users 行数算分母。
空间：O(k)，k 为不同 contest_id 数，用于分组哈希。

## 易错点
- 写成 `COUNT(*) * 100 / COUNT(*)` 或漏了 `100.0` → 整数除法把 66.67 截成 66、33.33 截成 33 → 分子乘 `100.0` 强制浮点，再 ROUND 两位。
- 分母误用 `COUNT(DISTINCT user_id) FROM Register` → 示例里 Register 去重后仍是 3 个用户，看似对，但若某用户从未注册任何赛事，分母会偏小、百分比虚高 → 分母必须取 Users 全表行数。

## 如果面试官追问
问：如果 Users 表里有用户从未出现在 Register 中，结果会变吗？
答：不会，分母始终是 Users 总人数，这类用户只压低所有赛事的百分比，不会产生新行。
