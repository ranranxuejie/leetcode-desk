## 一句话思路
先算不排序的逐位绝对差总和，再算排序后逐位差总和加 k，取较小值。

## 怎么做
1. 计算 `sum(abs(arr[i] - brr[i]))`，这是完全不重排的代价。
2. 计算 `sorted(arr)` 与 `sorted(brr)` 逐位绝对差之和，再加一次 `k`。
3. 返回两者较小值。

以示例 1 为例：`arr = [-7,9,5]`，`brr = [7,-2,-5]`。不排序代价为 `|-7-7| + |9-(-2)| + |5-(-5)| = 14+11+10 = 35`。排序后 `arr' = [-7,5,9]`，`brr' = [-5,-2,7]`，差值和为 `2+7+2 = 11`，加 `k=2` 得 `13`，取 `min(35,13)=13`。

```python
a = sorted(arr)
b = sorted(brr)
no_sort = sum(abs(x - y) for x, y in zip(arr, brr))
with_sort = k + sum(abs(x - y) for x, y in zip(a, b))
return min(no_sort, with_sort)
```

关键点：重排操作只需做一次。因为一次操作就能把 `arr` 切成任意多个连续子数组再任意重排，等价于把 `arr` 变成任意排列，所以排序后的配对是最优的（同序配对使绝对差之和最小）。

## 复杂度
时间：排序贡献 `O(n log n)`，两次线性扫描贡献 `O(n)`。
空间：`sorted` 各开一个长度 n 的列表，`O(n)`。

## 易错点
- `k` 很大（可达 `2*10^10`）时，若只算排序方案会得到巨大值；必须与不排序方案取 `min`，示例 1 中 `k=2` 才使排序方案胜出。
- 只做一次重排就够：若误以为每次重排都要付 `k` 而累加多次，会把 `with_sort` 算成 `2k + ...`；正确做法是 `k` 只加一次，因为一次操作即可实现任意排列。

## 如果面试官追问
问：若限制只能切成至多两段重排？答：枚举切点，对每种切法算重排后差值和加 k，取全局最小，复杂度升到 `O(n^2)`。
