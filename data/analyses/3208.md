## 一句话思路
把环复制成两倍长度，用滑动窗口维护「相邻两两不同」的连续段长度，长度 ≥ k 就计数。

## 怎么做
1. 把 `colors` 拼成 `colors * 2`，这样环上任意起点都能在数组里连续取到 k 个。
2. 维护 `run`：以当前位置结尾的、相邻元素两两不同的最长后缀长度；若 `colors[i] != colors[i-1]` 则 `run += 1`，否则 `run = 1`。
3. 只在 `i >= k-1` 时判断 `run >= k`，成立则答案 +1，且只统计 `i` 落在 `[k-1, n+k-2]` 的窗口，避免重复计数。

以示例 1 `colors = [0,1,0,1,0], k = 3` 为例，双倍后为 `[0,1,0,1,0,0,1,0,1,0]`。走到 `i=2` 时 `run=3`，计数 1；`i=3` 时 `run=4`，计数 2；`i=4` 时 `run=5`，计数 3；`i=5` 时 `colors[5]=0 == colors[4]=0`，`run` 重置为 1，之后不再满足，最终答案 3。

```python
n = len(colors)
arr = colors * 2
ans = run = 0
for i in range(n + k - 1):
    if i > 0 and arr[i] != arr[i - 1]:
        run += 1
    else:
        run = 1
    if i >= k - 1 and run >= k:
        ans += 1
```

循环上界取 `n + k - 1`：起点最多是 `n-1`，终点最多是 `n-1 + k-1 = n+k-2`，所以 `range` 到 `n+k-1` 为止正好覆盖所有合法窗口。

## 复杂度
时间 O(n + k)，遍历长度 `n + k - 1` 的双倍数组一次。
空间 O(n)，额外开了 `colors * 2` 的数组；若改成取模访问可降到 O(1)。

## 易错点
- 只遍历原数组 `range(n)` → 会漏掉跨越首尾的交替组，如示例 1 中起点 `i=3`、`i=4` 的组 → 必须遍历到 `n + k - 2`，用双倍数组或 `arr[i % n]` 取模。
- 判断条件写成 `run == k` → 当 `run` 已经大于 k（如示例 1 的 `i=4` 时 `run=5`）会漏计 → 应写 `run >= k`，因为长度超过 k 的交替段里每个长度为 k 的窗口都合法。

## 如果面试官追问
若要求空间 O(1) 怎么做？答：不复制数组，用 `colors[i % n]` 和 `colors[(i-1) % n]` 比较，循环上界仍是 `n + k - 1`。
