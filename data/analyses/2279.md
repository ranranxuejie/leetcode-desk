## 一句话思路
把每个背包的缺口 `capacity[i] - rocks[i]` 排序，从小到大用 `additionalRocks` 依次填满，能填几个就是答案。

## 怎么做
1. 用列表推导算出每个背包还差多少块石头：`need = [c - r for c, r in zip(capacity, rocks)]`。
2. 对 `need` 升序排序，缺口小的背包优先填，因为填满它消耗的石头最少。
3. 遍历 `need`，若 `additionalRocks >= need[i]` 就扣掉并计数，否则直接 `break`——后面缺口只会更大，不可能再填满。

以示例 1 为例：`capacity = [2,3,4,5]`，`rocks = [1,2,4,4]`，得到 `need = [1,1,0,1]`，排序后 `[0,1,1,1]`。`additionalRocks = 2`：先填缺口 0（剩 2，计数 1），再填缺口 1（剩 1，计数 2），再填缺口 1（剩 0，计数 3），下一个缺口 1 时 `0 < 1` 退出，返回 3。

```python
need = sorted(c - r for c, r in zip(capacity, rocks))
ans = 0
for d in need:
    if additionalRocks < d:
        break
    additionalRocks -= d
    ans += 1
return ans
```

关键点：缺口为 0 的背包（示例 1 中下标 2）排序后排在首位，不消耗任何石头就计入答案，这正是排序而非直接按原顺序遍历的价值。

## 复杂度
时间：O(n log n)，排序贡献 log n，遍历贡献 n。
空间：O(n)，`need` 列表额外开 n 个元素（生成器进 sorted 后落地）。

## 易错点
- 缺口为 0 的背包 → 若写成 `if additionalRocks >= d and d > 0` 才计数，会漏掉本来就装满的背包，示例 1 会错答 2 而非 3 → 正确做法是缺口 0 也照常计数，`additionalRocks -= 0` 无副作用。
- `additionalRocks` 很大（如示例 2 的 100）→ 若循环里不 `break` 而继续累加，可能把已填满的背包重复计数，或误以为必须用完所有石头 → 正确做法是缺口不够就 `break`，剩余石头直接丢弃，题目允许不用完。

## 如果面试官追问
问：若要求返回具体往哪些背包放多少石头，怎么改？
答：遍历时记录被填满的下标 i 和消耗量 `need[i]`，输出 `(i, need[i])` 列表即可，逻辑不变。
