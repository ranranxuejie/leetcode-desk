## 一句话思路
维护一个容量为 k 的小顶堆，堆顶就是第 k 大元素，因为堆里始终装着当前最大的 k 个数。

## 怎么做
1. 初始化时把 `nums` 全部 `heappush` 进堆，再 `while len(heap) > k: heappop`，只留最大的 k 个。
2. `add(val)` 先无条件 `heappush(heap, val)`，此时堆大小可能变成 k+1。
3. 若 `len(heap) > k` 就 `heappop` 弹出堆顶，把最小的那个踢出去。
4. 返回 `heap[0]`，即这 k 个数里最小的，也就是全局第 k 大。

用官方示例：`k=3, nums=[4,5,8,2]`，建堆后弹出最小的 2，堆内 `[4,5,8]`，堆顶 4。第一次 `add(3)`：push 后堆为 `[3,4,5,8]`，长度 4 > 3，pop 掉 3，堆回到 `[4,5,8]`，返回 4。第三次 `add(10)`：push 后 `[4,5,8,10]`，pop 掉 4，堆变 `[5,8,10]`，返回 5——注意 10 进来了但堆顶仍是 5，这正是"第 3 大"而非"最大值"的关键。

```python
import heapq

def build(k, nums):
    heap = list(nums)
    heapq.heapify(heap)
    while len(heap) > k:
        heapq.heappop(heap)
    return heap

def add(heap, k, val):
    heapq.heappush(heap, val)
    if len(heap) > k:
        heapq.heappop(heap)
    return heap[0]
```

## 复杂度
时间：建堆 O(n)，每次 add 是 O(log k)，n 为初始 `nums` 长度。
空间：堆固定存 k 个元素，额外 O(k)。

## 易错点
- `nums` 长度小于 k 时（如 `k=3, nums=[]`），若初始化阶段就写 `while len(heap) > k` 不会出错，但若误写成"取前 k 个"或断言 `len(nums) >= k` 会直接崩；正确做法是初始化只做裁剪、不做补齐，靠后续 `add` 把堆填到 k。
- 用大顶堆存全部元素再取第 k 个 → 每次 add 是 O(n log n) 且内存随数据流无限增长；正确做法是小顶堆只留 k 个，`add` 里先 push 再按 `len(heap) > k` 弹堆顶，顺序不能反（先弹再 push 会在堆未满时误删）。

## 如果面试官追问
问：数据流极大、k 也很大（如 k=10^6）怎么办？
答：小顶堆内存 O(k) 仍可接受，但可换平衡 BST 或有序容器，把"第 k 大"变成按秩查询，代价是常数更大。
