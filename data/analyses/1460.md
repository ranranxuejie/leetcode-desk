## 一句话思路
翻转任意子数组能生成任意排列，所以只需比较 target 和 arr 的元素多重集是否相同，用 Counter 计数即可。

## 怎么做
1. 长度已由题面保证相等，直接比较两个数组的计数。
2. 用 `Counter(target)` 与 `Counter(arr)` 做相等判断，相等返回 `True`，否则 `False`。
3. 以示例 1 为例：`Counter(target)` 得到 `{1:1, 2:1, 3:1, 4:1}`，`Counter(arr)` 得到 `{2:1, 4:1, 1:1, 3:1}`，两个字典键值完全一致，返回 `True`。
4. 示例 3 中 `Counter(arr)` 是 `{3:1, 7:1, 11:1}`，与 target 的 `{3:1, 7:1, 9:1}` 在键 `9` 和 `11` 上不同，返回 `False`。

```python
from collections import Counter

def canBeEqual(target, arr):
    return Counter(target) == Counter(arr)

# 不用 Counter 的等价写法
def canBeEqual2(target, arr):
    cnt = {}
    for x in target:
        cnt[x] = cnt.get(x, 0) + 1
    for x in arr:
        if cnt.get(x, 0) == 0:
            return False
        cnt[x] -= 1
    return True
```

关键中间值：示例 1 里 `Counter(target) == Counter(arr)` 比较的是两个长度 4 的字典，逐键比对 `1/2/3/4` 的计数都为 1，故为 `True`。

## 复杂度
时间 O(n)：n 为数组长度，两次遍历建计数表。
空间 O(k)：k 为不同元素个数，最坏 k=n，额外开一个字典。

## 易错点
- 输入 `target=[1,1,2], arr=[1,2,2]` → 若只比较 `set(target) == set(arr)` 会错成 `True`（两个集合都是 `{1,2}`）→ 必须比较计数而非去重后的集合。
- 输入 `target=[1,2,3], arr=[1,2,3]` 但用排序后逐位比较时忘了长度相等的前提 → 本题长度由题面保证，若自行扩展到不等长场景需先判 `len(target) != len(arr)` 返回 `False`，否则 `zip` 会静默截断。

## 如果面试官追问
问：如果要求输出具体的翻转步骤序列怎么办？
答：先按计数判定可行性，再用选择排序式构造：对每个位置 i，在 arr[i:] 中找到 target[i] 后翻转 arr[i:j+1] 把它换到 i，最多 n 次翻转。
