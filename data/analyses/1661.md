## 一句话思路
按 `(machine_id, process_id)` 分组把 start/end 时间戳配对相减，再按 `machine_id` 求平均。

## 怎么做
1. 用条件聚合把每对进程的耗时压成一行：`SUM(CASE WHEN activity_type='start' THEN -timestamp ELSE timestamp END)`，按 `(machine_id, process_id)` 分组。
2. 机器 0 进程 0 得到 `-0.712 + 1.520 = 0.808`，进程 1 得到 `-3.140 + 4.120 = 0.980`。
3. 外层再按 `machine_id` 分组，对上面两行取 `AVG`：`(0.808 + 0.980) / 2 = 0.894`。
4. 用 `ROUND(..., 3)` 保留三位小数，别名 `processing_time`。

```python
# 内层：每台机器每个进程一行耗时
inner = """
SELECT machine_id, process_id,
       SUM(CASE WHEN activity_type = 'start' THEN -timestamp
                ELSE timestamp END) AS duration
FROM Activity
GROUP BY machine_id, process_id
"""
# 外层：按机器求平均
sql = f"""
SELECT machine_id,
       ROUND(AVG(duration), 3) AS processing_time
FROM ({inner}) t
GROUP BY machine_id
"""
```

关键点：`start` 取负、`end` 取正，一次 `SUM` 就完成减法，不用自连接。

## 复杂度
时间 O(n)：扫描 Activity 表 n 行，分组聚合各一次。
空间 O(m)：中间结果每台机器每个进程一行，m 为进程总数。

## 易错点
1. 用 `AVG(end) - AVG(start)` 代替逐进程相减 → 机器 0 会算成 `(1.520+4.120)/2 - (0.712+3.140)/2 = 2.820 - 1.926 = 0.894`，本例恰好相等，但进程数不等或时间分布不均时结果就错，必须按 `(machine_id, process_id)` 先配对。
2. 只按 `machine_id` 分组、漏掉 `process_id` → 机器 0 的四个时间戳混在一起，`SUM` 得到 `-0.712+1.520-3.140+4.120 = 1.788`，再除以进程数 2 得 0.894 看似对，但机器 2 会因 `-4.100+4.512-2.500+5.000 = 2.912` 除以 2 得 1.456 也碰巧对——这是示例的巧合，实际数据里 start/end 交错就会错，必须两级分组。

## 如果面试官追问
问：如果同一进程有多次 start/end 循环怎么办？
答：把内层分组键加上循环序号，或改用窗口函数按时间排序配对相邻 start/end。
