## 一句话思路
对每个 `words[i]` 用 `x in words[i]` 判断包含关系，命中就把下标 `i` 收进结果。

## 怎么做
1. 建空列表 `res`，准备按下标顺序收集。
2. 用 `enumerate(words)` 同时拿到下标 `i` 和单词 `w`。
3. 判断 `x in w`，为 `True` 就 `res.append(i)`。
4. 遍历结束直接返回 `res`，无需排序。

拿示例 2 走一遍：`words = ["abc","bcd","aaaa","cbc"]`，`x = "a"`。`i=0` 时 `"a" in "abc"` 为 `True`，`res` 变 `[0]`；`i=1` 时 `"a" in "bcd"` 为 `False`，跳过；`i=2` 时 `"a" in "aaaa"` 为 `True`，`res` 变 `[0,2]`；`i=3` 时 `"a" in "cbc"` 为 `False`。返回 `[0,2]`。

```python
res = []
for i, w in enumerate(words):
    if x in w:
        res.append(i)
return res
```

`x in w` 在 Python 里对字符串就是子串查找，单字符时等价于逐字符扫描，语义正好是「包含字符 x」。不用 `w.find(x) != -1`，也不用 `any(c == x for c in w)`——前者多一层比较，后者是纯 Python 循环，慢且啰嗦。

## 复杂度
时间：O(Σ|words[i]|)，每个单词被 `in` 扫一遍，最坏全不命中。
空间：O(1) 额外（不计返回的 `res`），`res` 最坏装 50 个下标。

## 易错点
1. 输入 `words = ["abc","bcd","aaaa","cbc"], x = "z"` → 若把判断写成 `if x in words`（漏了下标）会去整个列表里找字符串 `"z"`，永远 `False`，返回 `[]` 看似「对」但示例 1 就崩了 → 必须写成 `x in w`，`w` 是当前单词。
2. 输入 `words = ["aaaa"], x = "a"` → 若用 `w.count(x) == 1` 判断会漏掉重复字符的单词，返回 `[]` → 用 `in` 只问「是否存在」，不关心出现几次。

## 如果面试官追问
问：若 `words` 规模到 10^5、总长 10^7，还这么写吗？
答：仍是一遍扫描，`in` 是 C 层实现，瓶颈在总字符数，不额外优化也够；要更快只能换多模式匹配，这题不值。
