## 一句话思路
排序后从大到小贪心累加：每加一道菜，前面所有菜的系数都 +1，增量就是当前前缀和。

## 怎么做
1. 把 `satisfaction` 升序排序，从末尾往前遍历（等价于降序）。
2. 维护 `prefix` = 已选菜满意度之和，`ans` = 当前总系数；每加入一道菜 `x`，`ans += prefix + x`，`prefix += x`。
3. 若某一步 `ans` 变小（即 `prefix + x < 0`），立即停止——再加更小的菜只会更亏。

以 `[-1,-8,0,5,-9]` 排序后 `[-9,-8,-1,0,5]` 为例，倒序处理：
- 加 5：`prefix=0`，`ans=5`，`prefix=5`
- 加 0：`ans=5+(5+0)=10`，`prefix=5`
- 加 -1：`ans=10+(5-1)=14`，`prefix=4`
- 加 -8：`ans=14+(4-8)=10 < 14`，停止，返回 14。

关键中间值：加入 -1 时 `prefix` 还是 5，所以增量是 4 而不是 -1，这正是「前面菜系数集体 +1」的体现。

```python
def maxSatisfaction(satisfaction):
    satisfaction.sort()
    prefix = ans = 0
    for x in reversed(satisfaction):
        if prefix + x <= 0:
            break
        ans += prefix + x
        prefix += x
    return ans
```

注意 `<= 0` 而非 `< 0`：增量恰为 0 时加不加结果一样，提前 break 更省事，但若要求输出方案则要改成 `< 0`。

## 复杂度
时间：排序 O(n log n) 主导，倒序扫描 O(n)。
空间：排序原地 O(1)（Python 的 `sort` 额外 O(n) 栈/临时空间，不计入算法本身）。

## 易错点
- 输入 `[-1,-4,-5]` → 若不加 `prefix + x <= 0` 的 break，会把 -1 也加进去得 `-1`，再被后续负数拉更低；正确做法是首轮 `prefix=0`、`x=-5` 时 `0+(-5)<0` 直接返回 0。
- 输入 `[4,3,2]` → 若按原顺序正着算 `4*1+3*2+2*3=16`，错成 16；正确做法是升序排序后倒序，让最大的 4 拿最大时间 3，得 `2*1+3*2+4*3=20`。

## 如果面试官追问
问：要求输出具体做了哪些菜、按什么顺序？
答：记录 break 前加入的所有 `x`，按加入顺序（即降序）排列就是烹饪顺序，时间从 1 开始编号。
