## 一句话思路
先把购买表按用户去重成「用户-类别」对，再自连接同一用户的两个类别，按类别对聚合计数。

## 怎么做
1. 用 `ProductPurchases` join `ProductInfo` 得到每行的类别，`SELECT DISTINCT user_id, category` 去重——同一用户买两个 Books 商品只算一次。
2. 把这张去重表自连接，条件 `a.user_id = b.user_id AND a.category < b.category`，这样每个用户对每个类别对只产生一行，且天然满足 category1 < category2。
3. 按 `(a.category, b.category)` 分组 `COUNT(*)`，即同时购买两类别的不同用户数。
4. `HAVING COUNT(*) >= 3`，再按 `customer_count DESC, category1, category2` 排序。

关键中间值：以官方示例为例，去重后用户 2 的类别集合是 `{Electronics, Books, Clothing}`（101→Electronics，102/103→Books，201→Clothing）。自连接后用户 2 贡献三行：`(Books, Clothing)`、`(Books, Electronics)`、`(Clothing, Electronics)`。用户 5 的集合是 `{Books, Clothing}`，只贡献 `(Books, Clothing)` 一行。最终 `(Books, Clothing)` 由用户 1、2、5 三行聚成 `customer_count = 3`。

```python
# 去重后的用户-类别表 u
pairs = {}
for uid, cats in u.items():
    for c1, c2 in combinations(sorted(cats), 2):
        pairs[(c1, c2)] = pairs.get((c1, c2), 0) + 1

res = [(c1, c2, n) for (c1, c2), n in pairs.items() if n >= 3]
res.sort(key=lambda x: (-x[2], x[0], x[1]))
```

SQL 版核心就一句：`FROM user_cat a JOIN user_cat b ON a.user_id=b.user_id AND a.category<b.category GROUP BY a.category,b.category HAVING COUNT(*)>=3`。

## 复杂度
时间：O(U·C²)，U 为用户数、C 为单用户类别数，自连接是主要开销。
空间：O(U·C) 存去重表，外加 O(P) 存类别对计数，P 为不同类别对数。

## 易错点
- 不去重直接自连接 → 用户 2 买了 102、103 两个 Books，会和 Clothing 产生 2 行，`(Books, Clothing)` 被算成 4 而不是 3 → 必须先 `DISTINCT user_id, category`。
- 用 `a.category != b.category` 而非 `<` → 每个类别对出现两次（正反各一），计数翻倍且 category1/category2 顺序混乱 → 用严格小于保证唯一有序。
- 忘记 `HAVING >= 3` 只靠外层过滤 → 结果里混入 Clothing-Sports（2 人）、Books-Kitchen（1 人）→ 在聚合层就过滤掉。

## 如果面试官追问
问：如果阈值从 3 改成动态参数 k，且要求返回所有 k≥2 的对？答：把 `HAVING COUNT(*)>=3` 换成 `>= k`，排序键不变，自连接逻辑完全复用。
