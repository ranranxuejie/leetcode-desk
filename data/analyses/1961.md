## 一句话思路
按顺序把 `words` 拼到 `s` 上比对，用双指针同步推进，一旦 `s` 走完就返回 `True`。

## 怎么做
1. 维护 `i` 指向 `s` 中待匹配位置，初值 0。
2. 遍历 `words`，对每个 `w` 逐字符与 `s[i]` 比较，匹配一个就 `i += 1`。
3. 若某次比较失配，或 `i` 越界前 `w` 还没走完，返回 `False`。
4. 每拼完一个 `w` 后检查 `i == len(s)`，成立就立刻返回 `True`（`k` 可以小于 `len(words)`）。

以示例 1 为例：`s = "iloveleetcode"`，`words = ["i","love","leetcode","apples"]`。拼完 `"i"` 后 `i = 1`；拼完 `"love"` 后 `i = 5`；拼 `"leetcode"` 时逐字符推进到 `i = 13 == len(s)`，此时 `w` 恰好也走完，返回 `True`，`"apples"` 根本没被访问。

```python
i = 0
for w in words:
    for ch in w:
        if i == len(s) or s[i] != ch:
            return False
        i += 1
    if i == len(s):
        return True
return False
```

关键在 `i == len(s)` 这个判断放在内层循环开头：它保证 `s` 用尽后不再越界访问，同时把「`s` 是某个 `w` 的真前缀」这种情况判成 `False`。

## 复杂度
时间 O(len(s))：每个字符最多被比较一次，`words` 中 `s` 之后的元素不访问。
空间 O(1)：只开了 `i` 一个整数，没有拼接字符串。

## 易错点
- `s = "ilove"`、`words = ["i","love","leetcode"]` → 若只在循环末尾判 `i == len(s)`，会在拼完 `"love"` 时正确返回，但若写成先拼完所有 `words` 再比较，就会把 `"leetcode"` 也拼进去导致长度不等而错判 `False`；正确做法是每拼完一个 `w` 立即检查并返回。
- `s = "iloveleetcode"`、`words = ["i","love","leetcode","apples"]` → 若内层循环不先判 `i == len(s)`，拼到 `"leetcode"` 末尾时 `i` 已等于 13，下一次访问 `s[13]` 直接 `IndexError`；正确做法是把越界判断放在取 `s[i]` 之前，用 `or` 短路。

## 如果面试官追问
问：如果 `words` 很长而 `s` 很短，怎么提前剪枝？
答：先累加 `words` 前缀长度，一旦超过 `len(s)` 就停，因为 `s` 不可能再被拼出。
