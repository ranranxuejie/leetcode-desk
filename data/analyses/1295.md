## 一句话思路
用 `len(str(x))` 取位数判奇偶，或按 10/100/1000/10000 分档比较，一次遍历计数。

## 怎么做
1. 遍历 `nums`，对每个元素 `x` 求位数。
2. 位数用 `len(str(x))` 直接得到，或写成 `x < 10 → 1 位`、`x < 100 → 2 位` 的分档判断。
3. 位数 `% 2 == 0` 时计数器 `ans += 1`。
4. 遍历结束返回 `ans`。

以示例 1 `nums = [12,345,2,6,7896]` 为例：`x = 12` 时 `len(str(12)) == 2`，`2 % 2 == 0`，`ans` 从 0 变 1；`x = 345` 得 3 位，跳过；`x = 7896` 得 4 位，`ans` 变 2。最终返回 2。

```python
ans = 0
for x in nums:
    d = len(str(x))
    if d % 2 == 0:
        ans += 1
return ans
```

分档写法（避免字符串转换）：

```python
ans = 0
for x in nums:
    if (10 <= x <= 99) or (1000 <= x <= 9999):
        ans += 1
return ans
```

注意 `nums[i] <= 10**5`，所以 `100000` 是 6 位（偶数位），分档写法必须把 `100000` 也算进去——上面的区间漏了它，正确写法是 `x == 100000` 单独加一条，或直接用 `len(str(x))`。

## 复杂度
时间：O(n·log M)，n 是 `nums` 长度，log M 是每个数转字符串/分档的位数代价（M ≤ 10^5，最多 6 位）。
空间：O(1)，只开了 `ans` 和循环变量 `x`，`str(x)` 的临时字符串长度 ≤ 6。

## 易错点
- 输入含 `100000`（如 `nums = [100000]`）→ 分档写法若只写到 `1000 <= x <= 9999` 会漏判，输出 0 而非 1 → 必须补 `x == 100000` 或改用 `len(str(x))`。
- 输入全是 1 位数（如 `nums = [2,6]`）→ 误把「1 位」当偶数位（以为 1 是奇数就对，但若写成 `d % 2 == 1` 取反就全错）→ 判定条件固定为 `d % 2 == 0`，别用 `d & 1` 后取反。

## 如果面试官追问
若 `nums[i]` 上限改成 10^18 怎么办？答：分档写法要写 9 个区间太啰嗦，直接用 `len(str(x))`，位数最多 19，代价仍是常数级。
