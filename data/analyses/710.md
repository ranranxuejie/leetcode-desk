## 一句话思路
把黑名单里落在后半段 `[n-m, n-1]` 的数换成前半段里的白名单数，用哈希表映射后只需一次随机。

## 怎么做
1. 设 `m = len(blacklist)`，把 `pick` 的随机范围缩到 `[0, n-m-1]`，因为白名单恰好有 `n-m` 个。
2. 收集黑名单中 `< n-m` 的数，它们是前半段里被占掉的坑。
3. 收集黑名单中 `>= n-m` 的数，它们在后半段，本来就不会被随机到，无需处理。
4. 把前半段的黑名单数依次映射到后半段的白名单数，`pick` 时随机 `x`，命中映射就返回映射值。

以 `n=7, blacklist=[2,3,5]` 为例，`m=3`，随机范围 `[0,3]`。前半段黑名单是 `{2,3}`，后半段 `[4,6]` 里黑名单是 `{5}`，白名单是 `{4,6}`。于是 `2→4`、`3→6`。随机到 0、1 直接返回，随机到 2 返回 4，随机到 3 返回 6，四个白名单数概率各 1/4。

```python
m = len(blacklist)
front = {b for b in blacklist if b < n - m}
back_white = [x for x in range(n - m, n) if x not in set(blacklist)]
mp = {}
for b, w in zip(front, back_white):
    mp[b] = w

def pick():
    x = random.randrange(n - m)
    return mp.get(x, x)
```

## 复杂度
时间：初始化 O(m)，`pick` 为 O(1)，只调用一次随机函数。
空间：哈希表与列表各存 O(m) 个元素，与 n 无关。

## 易错点
- `blacklist` 为空时 `m=0`，随机范围是 `[0, n-1]`，若误写成 `n-m-1` 会漏掉最后一个数 `n-1`，正确做法是 `randrange(n-m)`。
- 黑名单全落在后半段（如 `n=5, blacklist=[3,4]`）时，`front` 为空、`back_white` 也需按 `n-m=3` 起算，若把 `back_white` 写成从 0 开始收集，会把 0、1、2 这些前半段白名单数错配进映射，导致 `pick` 返回黑名单值。

## 如果面试官追问
若 `pick` 调用次数极大、要求零哈希开销？答：可把映射压成数组 `mp[x]`，初始化时对前半段黑名单位置填映射值，其余填自身，`pick` 直接下标访问。
