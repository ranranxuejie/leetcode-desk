## 一句话思路
把数字转成字符串，按 `a+b < b+a` 排序后拼接，因为该比较满足传递性，可得到全局最小拼接。

## 怎么做
1. 把 `password` 中每个整数转成字符串，得到列表 `s`。
2. 用自定义比较器排序：`a` 排在 `b` 前当且仅当 `a+b < b+a`。
3. 把排好序的 `s` 直接 `"".join` 返回，保留前导 0。

以示例 2 的 `[0, 3, 30, 34, 5, 9]` 为例，转成 `["0","3","30","34","5","9"]`。比较 `"3"` 和 `"30"`：`"330" > "303"`，所以 `"30"` 排在 `"3"` 前；比较 `"3"` 和 `"34"`：`"334" < "343"`，所以 `"3"` 排在 `"34"` 前。最终顺序为 `["0","30","3","34","5","9"]`，拼接得 `"03033459"`。

```python
from functools import cmp_to_key

def cmp(a, b):
    if a + b < b + a:
        return -1
    if a + b > b + a:
        return 1
    return 0

s = [str(x) for x in password]
s.sort(key=cmp_to_key(cmp))
return "".join(s)
```

关键中间值：排序后 `s = ["0","30","3","34","5","9"]`，`"".join(s)` 即 `"03033459"`。

## 复杂度
时间：排序做 `O(n log n)` 次比较，每次比较拼接两个字符串，总代价与数字位数有关。
空间：`O(n)` 存字符串列表和排序临时空间。

## 易错点
- 输入 `[0, 0, 0]` → 若先去掉前导 0 或把结果转 int 再转回字符串，会错成 `"0"` 或空串 → 题目明确要求保留前导 0，直接 `"".join` 返回 `"000"`。
- 输入 `[3, 30, 34]` → 若按普通字典序排序得 `["3","30","34"]`，拼成 `"33034"`，比正确结果 `"30334"` 大 → 必须用 `a+b` 与 `b+a` 比较，不能直接 `sort()`。

## 如果面试官追问
问：如果数组长度增到 10^5，还能这样做吗？
答：可以，仍是 `O(n log n)` 次比较；但每次比较要拼字符串，可先缓存每个数的字符串形式减少重复转换。
