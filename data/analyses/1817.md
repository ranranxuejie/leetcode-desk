## 一句话思路
用哈希表把每个 ID 映射到它去重后的分钟集合，集合大小就是该用户的 UAM，再按大小计数。

## 怎么做
1. 建 `d = defaultdict(set)`，遍历 `logs`，执行 `d[uid].add(t)`。
2. 对示例 1，`d` 最终为 `{0: {5, 2}, 1: {2, 3}}`，注意 `[0,5]` 出现两次但集合里只有一个 `5`。
3. 建长度 `k+1` 的 `ans`（下标 1 开始），对每个 `len(s)` 执行 `ans[len(s)] += 1`。
4. 返回 `ans[1:]`。

```python
from collections import defaultdict

d = defaultdict(set)
for uid, t in logs:
    d[uid].add(t)

ans = [0] * (k + 1)
for s in d.values():
    ans[len(s)] += 1
return ans[1:]
```

关键中间值：示例 1 里 `d[0]` 是 `{5, 2}` 而非 `[5, 2, 5]`，`len` 得 2；`d[1]` 得 2；于是 `ans[2] = 2`，其余为 0。

## 复杂度
时间 O(n)：n 为 `logs` 长度，每条日志一次 `add`，集合去重是均摊 O(1)。
空间 O(n)：`d` 里最多存 n 个 (ID, 分钟) 对，`ans` 额外 O(k)。

## 易错点
- 同一用户同一分钟多次操作，如示例 1 的 `[0,5]` 出现两次 → 若用 `list` 或直接 `len` 计数会得 3 而非 2 → 必须用 `set` 存分钟再去重。
- 返回时忘记去掉下标 0：`ans` 长度是 `k+1`，直接返回会多一个前导 0，示例 1 会错成 `[0,0,2,0,0,0]` → 返回 `ans[1:]`。

## 如果面试官追问
问：若 `k` 远大于最大 UAM（如 10^9）怎么办？
答：只统计实际出现的 UAM 到字典，最后按需展开或返回稀疏表示，避免开 10^9 数组。
