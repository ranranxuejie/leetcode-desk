## 一句话思路
用哈希表统计每个数字出现在多少个数组里，计数等于 `len(nums)` 的就是交集元素，最后排序。

## 怎么做
1. 建一个 `dict` 记 `cnt[x]`，遍历 `nums` 中每个子数组。
2. 对每个子数组 `arr`，遍历其中每个 `x`，执行 `cnt[x] = cnt.get(x, 0) + 1`。
3. 收集所有满足 `cnt[x] == len(nums)` 的 `x`，`sorted()` 后返回。

以示例 1 为例，`nums` 有 3 个子数组。遍历完后 `cnt[3]=3`、`cnt[4]=3`，而 `cnt[1]=2`（只在 nums[0]、nums[1] 出现）、`cnt[5]=2`。所以只有 3 和 4 的计数等于 3，排序后得 `[3,4]`。

```python
cnt = {}
for arr in nums:
    for x in arr:
        cnt[x] = cnt.get(x, 0) + 1
m = len(nums)
return sorted(x for x, c in cnt.items() if c == m)
```

关键点：题目保证每个 `nums[i]` 内部元素互不相同，所以同一个 `x` 在一个子数组里最多被加一次，`cnt[x]` 恰好等于「包含 x 的子数组个数」，不会因为重复而虚高。这个前提是计数法成立的基础，缺了它就得先对每个子数组去重。

## 复杂度
时间：`O(S + K log K)`，`S = sum(nums[i].length)` 是遍历总次数，`K` 是交集大小，排序贡献 `log K`。
空间：`O(D)`，`D` 是不同数字个数，即哈希表大小，返回值另算。

## 易错点
- 输入 `nums = [[1,2,3],[4,5,6]]` → 若误用「取 nums[0] 与其他数组求交」的写法，会得到 `[]` 看似对，但换成 `[[1],[1,2],[1,2,3]]` 时若只和 nums[1] 比就漏判 → 正确做法是计数必须等于 `len(nums)`，不能只和某一个数组比。
- 输入 `[[3,1,2,4,5],[1,2,3,4],[3,4,5,6]]` → 若忘记排序直接返回 `cnt` 的键顺序（Python 3.7+ 是插入序，这里是 `3,1,2,4,5,6`）→ 会输出 `[3,4,5,6]` 之外的乱序结果，必须 `sorted()`。

## 如果面试官追问
问：如果某个子数组内部有重复元素怎么办？
答：先对每个 `arr` 做 `set(arr)` 再计数，否则 `cnt[x]` 会超过 `len(nums)` 而漏掉真正的交集元素。
