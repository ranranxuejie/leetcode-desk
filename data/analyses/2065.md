## 一句话思路
用 DFS 回溯枚举从 0 出发、时间不超 maxTime 的路径，只在第一次进入节点时加价值，回到 0 时更新答案。

## 怎么做
1. 把 edges 建成邻接表 `g[u].append((v, t))`，无向边两个方向都存。
2. 从 `dfs(0, maxTime, values[0])` 开始，参数是当前节点、剩余时间、当前价值。
3. 每到一个节点先更新答案（因为路径可以在此刻回 0，也可以继续走），再枚举邻居：剩余时间够就走，进入未访问节点时加 `values[v]`。
4. 回溯时把 `visited[v]` 复位，保证别的分支能重新访问。

以示例 1 为例：`values=[0,32,10,43]`，从 0 出发，走 0→1 花 10 秒、价值 32；回 0 再走 0→3 花 10 秒、价值 75；此时剩余时间 49-40=9，不够再走任何边，答案停在 75。关键中间值是 `dfs(3, 9, 75)` 这一层直接更新 `ans=75`。

```python
def dfs(u, rest, cur):
    nonlocal ans
    ans = max(ans, cur)
    for v, t in g[u]:
        if t > rest:
            continue
        if not visited[v]:
            visited[v] = True
            dfs(v, rest - t, cur + values[v])
            visited[v] = False
        else:
            dfs(v, rest - t, cur)
```

剪枝：若 `cur + 剩余可达价值 <= ans` 可提前返回，但本题 maxTime≤100、每点度数≤4，不剪也能过。

## 复杂度
时间：O(4^(maxTime/10))，度数≤4、每条边至少 10 秒，路径长度受 maxTime 限制。
空间：O(n) 存邻接表和 visited，递归栈深度不超过 maxTime/10。

## 易错点
- 节点价值重复累加：路径 0→1→0→1 时若每次进 1 都加 `values[1]`，示例 1 会算成 32+32+43=107。正确做法是用 `visited` 标记，只在 `not visited[v]` 时加价值。
- 忘记在起点更新答案：示例 4 中 `edges=[[1,2,10]]`，节点 0 孤立，若只在回到 0 时更新 ans 会漏掉初始值。正确做法是 dfs 入口就 `ans = max(ans, cur)`，初始调用传 `values[0]`。

## 如果面试官追问
问：maxTime 放大到 10^9 怎么办？答：回溯会爆炸，需改成状态压缩 DP 或按时间分层的记忆化，本题规模下不必要。
