## 一句话思路
每个推文名挂一个有序时间列表，查询时用 `bisect` 在 `[startTime, endTime]` 内按 `freq` 切块逐块数，块数 ≤ 10^4/60+1 所以直接扫块即可。

## 怎么做
1. 用 `dict[str, list[int]]` 存每个 `tweetName` 的时间，`recordTweet` 直接 `append`。
2. 查询时先按 `freq` 取步长 `step`（minute→60，hour→3600，day→86400），块数 `k = (endTime - startTime) // step + 1`。
3. 对第 `i` 块，区间是 `[startTime + i*step, min(startTime + (i+1)*step - 1, endTime)]`，用两次 `bisect_left/right` 求差。
4. 把每块结果 append 进列表返回。

以官方示例 `getTweetCountsPerFrequency("minute","tweet3",0,60)` 为例：`tweet3` 的时间列表排序后是 `[0,10,60]`，`step=60`，`k = 60//60 + 1 = 2`。第 0 块 `[0,59]`：`bisect_right(...,59)=2`、`bisect_left(...,0)=0`，得 2；第 1 块 `[60,60]`：`bisect_right(...,60)=3`、`bisect_left(...,60)=2`，得 1，输出 `[2,1]`。

```python
from bisect import bisect_left, bisect_right

step = {"minute": 60, "hour": 3600, "day": 86400}[freq]
ts = sorted(self.data.get(tweetName, []))
k = (endTime - startTime) // step + 1
res = []
for i in range(k):
    lo = startTime + i * step
    hi = min(lo + step - 1, endTime)
    res.append(bisect_right(ts, hi) - bisect_left(ts, lo))
return res
```

注意 `recordTweet` 只 append 不排序，查询时才 `sorted`，因为操作数 ≤ 10^4，排序成本可接受；若想省，可改用 `SortedList` 或插入时 `insort`。

## 复杂度
时间：每次查询 O(m log m + k log m)，m 为该推文时间数，k 为块数，排序占 m log m。
空间：O(N) 存所有推文时间，查询额外 O(k) 结果列表。

## 易错点
- 块右端点写成 `startTime + (i+1)*step` 而非 `-1`：示例 `[0,60]` 会把 60 算进第 0 块得 `[3]`，正确是 `[2,1]`，因为块是左闭右开 `[0,60)`。
- 最后一块没截断到 `endTime`：`getTweetCountsPerFrequency("hour","tweet3",0,210)` 若用 `hi = lo + step - 1 = 3599` 会多算，正确 `hi = min(3599, 210) = 210`，得 `[4]`。

## 如果面试官追问
问：若 `recordTweet` 达 10^6 次、查询也 10^6 次怎么办？答：改用 `SortedList` 或 Fenwick 按时间离散化，把每次查询降到 O(k log N)，避免每次重排。
