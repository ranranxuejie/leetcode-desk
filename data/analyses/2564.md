## 一句话思路
把 `s` 所有长度 ≤30 的子串值预先存进哈希表（只留最左端点），查询时算 `val = first ^ second` 直接查表。

## 怎么做
1. 从每个起点 `i` 向右扩展，值 `v = v * 2 + int(s[j])`，长度超过 30 就停（因为 `first, second ≤ 10^9 < 2^30`）。
2. 用 `dict` 记录 `v -> (i, j)`，只在 `v` 首次出现时写入，保证 left 最小。
3. 对每个查询算 `target = first ^ second`，查表命中就返回端点，否则 `[-1, -1]`。

以 `s = "101101"`、查询 `[1,2]` 为例：`target = 1 ^ 2 = 3`。枚举时 `i=2` 得 `"1"`→1、`"11"`→3，此时 `v=3` 首次出现，记 `3 -> (2,3)`，查询命中返回 `[2,3]`。

```python
n = len(s)
pos = {}
for i in range(n):
    v = 0
    for j in range(i, min(n, i + 30)):
        v = v * 2 + (s[j] == '1')
        if v not in pos:
            pos[v] = (i, j)
ans = []
for f, sec in queries:
    ans.append(list(pos.get(f ^ sec, (-1, -1))))
```

注意 `s[j] == '1'` 在 Python 里是 `bool`，参与 `v * 2 + ...` 时自动当 0/1 用，不必写 `int()`。

## 复杂度
时间：预处理 O(n·30)，每个查询 O(1)，共 O(30n + q)。
空间：哈希表最多存 30n 个键值对，O(30n)。

## 易错点
- 子串长度不设上限 → `s` 长 10^4 时 `v` 会膨胀到 2^10000，既慢又无意义；正确做法是内层循环截到 `i + 30`，因为 `target = first ^ second ≤ 2^30 - 1`，更长的子串值必然超出。
- 用 `pos[v] = (i, j)` 无条件覆盖 → 同一 `v` 后出现的起点更大，会丢掉最小 left；正确做法是 `if v not in pos` 才写入，靠外层 `i` 递增天然保证首次即最左。

## 如果面试官追问
若 `s` 长度涨到 10^6 怎么办？答：仍只需枚举每个位置起 ≤30 位，复杂度 O(30n)，瓶颈在哈希表内存，可改用字典只存查询涉及的 `target` 集合。
