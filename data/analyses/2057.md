## 一句话思路
从左到右扫一遍，第一个满足 `i % 10 == nums[i]` 的 `i` 就是答案，因为下标天然递增。

## 怎么做
1. 用 `for i, v in enumerate(nums)` 顺序遍历，`i` 就是待比较的下标。
2. 每步只判断 `i % 10 == v`，成立立刻 `return i`。
3. 循环走完没命中就 `return -1`。

拿示例 2 `nums = [4,3,2,1]` 走一遍：`i=0` 时 `0 % 10 = 0`，`nums[0]=4`，不等；`i=1` 时 `1 % 10 = 1`，`nums[1]=3`，不等；`i=2` 时 `2 % 10 = 2`，`nums[2]=2`，相等，直接返回 `2`，后面的 `i=3` 根本不用看。这就是「最小」的来源——顺序扫描保证第一次命中即最小。

```python
for i, v in enumerate(nums):
    if i % 10 == v:
        return i
return -1
```

关键点：`nums[i]` 范围是 `0..9`，而 `i % 10` 也落在 `0..9`，所以比较是同一量纲，不需要额外处理。当 `i >= 10` 时 `i % 10` 会回绕，比如 `i=10` 时 `10 % 10 = 0`，此时要跟 `nums[10]` 比 0 而不是比 10——这是本题唯一需要「想一下」的地方，但 `%` 已经替你做了。

## 复杂度
时间：O(n)，n 为 `nums` 长度，最坏扫完整个数组。
空间：O(1)，只用了 `i`、`v` 两个循环变量，没开额外容器。

## 易错点
1. 输入 `nums = [1,2,3,4,5,6,7,8,9,0]`（示例 3）→ 若误写成比较 `i == nums[i]`，`i=0` 时 `0 != 1`、`i=9` 时 `9 != 0`，会得出 -1 但理由错；正确做法是始终用 `i % 10`，本题恰好也返回 -1，容易掩盖错误，换 `nums = [0,1,...]` 才暴露。
2. 输入 `nums = [0,1,2]`（示例 1）→ 若先收集所有满足条件的下标再取 `min`，多开一个列表且多一次遍历；正确做法是顺序扫描中第一个命中就 `return`，天然最小，无需比较。

## 如果面试官追问
问：若 `nums` 长度扩到 10^7 且要求返回所有满足条件的下标？
答：仍 O(n) 一次扫描，命中就 append 到结果列表，不再提前 return，空间变为 O(k)，k 为命中个数。
