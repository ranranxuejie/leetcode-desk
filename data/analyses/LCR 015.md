## 一句话思路
用长度固定为 `len(p)` 的滑动窗口维护字符计数，窗口计数与 `p` 的计数相等时记录左端点。

## 怎么做
1. 先统计 `p` 的字符频次 `need`（26 个字母），窗口长度固定为 `m = len(p)`。
2. 用 `cnt` 记录 `s[left:left+m]` 的频次，右端每加一个字符、左端每减一个字符，同步更新 `cnt`。
3. 每步比较 `cnt == need`，相等就把 `left` 加入答案。
4. 窗口右移时先加 `s[right]`，当窗口长度超过 `m` 再减 `s[right-m]`。

以 `s = "cbaebabacd"`, `p = "abc"` 为例：`m = 3`，`need = {a:1,b:1,c:1}`。窗口滑到 `left = 0` 时 `cnt` 恰好是 `{c:1,b:1,a:1}`，与 `need` 相等，记录 `0`；继续滑到 `left = 6`，窗口是 `"bac"`，`cnt` 又是 `{b:1,a:1,c:1}`，记录 `6`。

```python
from collections import Counter

need = Counter(p)
m = len(p)
cnt = Counter()
res = []
for right, ch in enumerate(s):
    cnt[ch] += 1
    left = right - m + 1
    if left < 0:
        continue
    if cnt == need:
        res.append(left)
    cnt[s[left]] -= 1
    if cnt[s[left]] == 0:
        del cnt[s[left]]
```

注意 `del` 那行：`Counter` 相等比较会把计数为 0 的键也算进去，不删就会漏判。

## 复杂度
时间 O(n + m)：`n = len(s)` 每个字符进出窗口各一次，`m = len(p)` 建 `need`。
空间 O(1)：`need`、`cnt` 最多 26 个键，答案数组 O(n) 不计入。

## 易错点
- `s = "abab"`, `p = "ab"`：若用 `cnt == need` 但不清理 0 值键，滑到 `left = 1` 时 `cnt` 里残留 `a:0` 之类，比较恒不等，输出 `[]` 而非 `[0,1,2]`。正确做法是计数减到 0 时 `del`。
- `len(p) > len(s)`（如 `s = "a"`, `p = "ab"`）：若先无条件 `cnt[s[left]] -= 1` 再判 `left < 0`，会访问 `s[-1]` 把末尾字符减成负数，或直接越界。正确做法是先判 `left < 0` 就 `continue`，不进减法分支。

## 如果面试官追问
问：若 `s` 含 Unicode 字符而非小写字母？答：把 26 位数组换成 `Counter` 或 `dict`，逻辑不变，空间随字符集大小走。
