## 一句话思路
用哈希表统计每个数的出现次数，次数能被 k 整除就把「该数 × 次数」累加进答案。

## 怎么做
1. 遍历 `nums`，用 `Counter` 得到 `cnt[x]`。
2. 遍历 `cnt` 的每个键值对 `(x, c)`，判断 `c % k == 0`。
3. 成立时累加 `x * c`，不成立跳过。

以示例 1 的 `nums = [1,2,2,3,3,3,3,4], k = 2` 为例，统计后 `cnt = {1:1, 2:2, 3:4, 4:1}`；对 `x=3, c=4`，`4 % 2 == 0` 成立，累加 `3 * 4 = 12`；对 `x=2, c=2` 累加 `2 * 2 = 4`；`1` 和 `4` 的次数为 1，跳过，最终 `12 + 4 = 16`。

```python
from collections import Counter

cnt = Counter(nums)
ans = 0
for x, c in cnt.items():
    if c % k == 0:
        ans += x * c
return ans
```

关键点：题目要求「计算恰好与其出现次数相同的次数」，所以是 `x * c` 而不是 `x`。示例 3 中 `4` 出现 3 次、`k=3`，贡献 `4 * 3 = 12`，若写成 `ans += x` 会得到 4。

## 复杂度
时间：O(n)，n 为 `nums` 长度，统计与遍历哈希表各一遍。
空间：O(d)，d 为不同元素个数，即哈希表大小。

## 易错点
- 输入 `nums = [4,4,4,1,2,3], k = 3` → 若累加 `ans += x` 得 4，错；正确是 `ans += x * c` 得 12，因为元素按出现次数重复计入。
- 输入 `nums = [1,2,3,4,5], k = 2` → 若把「次数能被 k 整除」误读成「元素值能被 k 整除」，会把 2、4 加进去得 6；正确做法是判断 `c % k == 0`，此处所有 `c` 均为 1，返回 0。

## 如果面试官追问
若 `nums` 规模升到 10^7 且值域很大，怎么做？答：仍用哈希表一遍统计，O(n) 时间；若值域有界（如 ≤100）可换数组计数，省掉哈希开销。
