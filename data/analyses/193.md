## 一句话思路
用一条 `grep -E` 正则同时匹配两种格式，锚定整行，因为每行就是一个候选号码。

## 怎么做
1. 把两种格式写成一条正则：`\([0-9]{3}\) [0-9]{3}-[0-9]{4}` 或 `[0-9]{3}-[0-9]{3}-[0-9]{4}`，用 `|` 连接。
2. 用 `^...$` 锚定整行，避免 `123 456 7890` 这种中间带空格的串被部分匹配。
3. 用 `grep -E` 逐行过滤，`-E` 让 `|` 和 `{3}` 不必转义。
4. 括号在正则里是元字符，`(123)` 必须写成 `\(123\)`，否则会被当成分组。

拿官方示例第 2 行 `123 456 7890` 走一遍：`^[0-9]{3}-` 要求前 3 位后紧跟 `-`，实际第 4 位是空格，匹配失败，整行被丢弃；第 3 行 `(123) 456-7890` 命中左分支，`\(` 吃掉字面左括号，`[0-9]{3}` 吃掉 `123`，`\) ` 吃掉 `) `，继续匹配 `456-7890`，成功输出。

```python
import re

# 等价 Python 版：逐行整行匹配
pat = re.compile(r'^(\([0-9]{3}\) [0-9]{3}-[0-9]{4}|[0-9]{3}-[0-9]{3}-[0-9]{4})$')
for line in open('file.txt').read().splitlines():
    if pat.match(line):
        print(line)
```

bash 单行版：`grep -E '^(\([0-9]{3}\) [0-9]{3}-[0-9]{4}|[0-9]{3}-[0-9]{3}-[0-9]{4})$' file.txt`

## 复杂度
时间：O(n)，n 为文件总字符数，每行正则匹配是常数级。
空间：O(1)，逐行流式处理，只存当前行。

## 易错点
- 漏写 `^...$` → `123 456 7890` 里 `456-7890` 不构成完整号码，但若某行是 `xx123-456-7890xx`，无锚点会误判为有效；正确做法是两端都加锚点，强制整行匹配。
- 括号未转义 → 写成 `([0-9]{3})` 时 `(` `)` 被当成分组，`(123) 456-7890` 反而匹配不上（因为分组不消耗字面括号）；正确写法是 `\([0-9]{3}\)`，反斜杠转义成字面字符。

## 如果面试官追问
问：如果允许号码前后有空格怎么办？
答：把锚点改成 `^[[:space:]]*...` 并在末尾加 `[[:space:]]*$`，或先 `strip()` 再匹配。
