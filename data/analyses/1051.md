## 一句话思路
把 `heights` 排序得到 `expected`，逐位比对计数；因值域只有 1~100，用长度 101 的计数数组代替排序。

## 怎么做
1. 开 `cnt = [0] * 101`，遍历 `heights` 做 `cnt[h] += 1`。
2. 按高度 1→100 展开 `cnt`，得到非递减的 `expected`（也可不显式建表，边展开边比对）。
3. 逐位比较 `heights[i] != expected[i]`，累加不匹配数。

以 `heights = [1,1,4,2,1,3]` 为例：计数后 `cnt[1]=3, cnt[2]=1, cnt[3]=1, cnt[4]=1`，展开得 `expected = [1,1,1,2,3,4]`；比对时 `i=2` 处 `4 != 1`、`i=4` 处 `1 != 3`、`i=5` 处 `3 != 4`，计数为 3。

```python
cnt = [0] * 101
for h in heights:
    cnt[h] += 1
expected = []
for h in range(1, 101):
    expected.extend([h] * cnt[h])
return sum(1 for i in range(len(heights)) if heights[i] != expected[i])
```

不建 `expected` 的写法：用指针 `h` 从 1 扫到 100，`cnt[h]` 个位置依次对应 `expected` 的下标区间，边推进边比对，空间降到 O(1)（不计返回）。

## 复杂度
时间 O(n + 100)：n 来自计数与比对，100 是值域上界，与 n 无关。
空间 O(100)：`cnt` 固定 101 个槽；若建 `expected` 则额外 O(n)。

## 易错点
- 输入 `heights = [5,1,2,3,4]` → 若误以为「只要元素集合相同就算匹配」会返回 0 → 必须按下标逐位比，正确答案是 5。
- 输入含大量重复如 `[1,1,1]` → 若用 `set` 去重后比较长度会错判 → 重复元素占多个位置，计数数组的 `cnt[h]` 必须原样展开，不能去重。

## 如果面试官追问
追问：高度值域放大到 10^9 怎么办？
答：计数排序失效，直接 `sorted(heights)` 得 `expected`，时间 O(n log n)，空间 O(n)。
