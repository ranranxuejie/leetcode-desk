## 一句话思路
把 s 切成 0/1 交替的段，答案 = 段数 + 一次操作能净增的最大值，用前缀和 + 二分定位查询边界。

## 怎么做
1. 预处理：把 s 压缩成段列表 `segs`，每段记 `(char, start, end)`，同时记 `pref[i]` = 前 i 段里 '1' 段的个数。
2. 对查询 `[l, r]`，二分找到 l、r 落在哪段，得到区间内完整段数 `cnt`（即活跃区段数基线）。
3. 操作本质：选一个被 1 包围的 0 段，把它变 1，同时它两侧的 1 段被"吞掉"——净变化 = 该 0 段长度贡献的合并效果。实际净增 = 该 0 段两侧 1 段合并后，活跃段数从 3 变 1 再变回 1 段，净增 = 0 段两侧 1 段的数量减 1（即 +1 当且仅当该 0 段两侧都有 1 段）。
4. 所以答案 = 基线活跃段数 + 1（若区间内存在一个完整被 1 包围的 0 段），否则不变。

以 `s = "0100"`, query `[0,3]` 为例：segs = `[('0',0,0),('1',1,1),('0',2,3)]`，区间内活跃段数 = 1，存在 0 段 `(2,3)` 左侧是 1 段、右侧是添加的 '1'（视为 1），故 +1，但示例答案是 4——说明操作是把整个 0 段变 1 后与两侧 1 合并，净增 = 0 段长度 - 1 段数变化。正确净增公式：把 0 段变 1 后，原本 `1 0 1` 三段变一段，活跃段数减少 2，但 0 段本身变成活跃，净增 = 0 段长度对应新增活跃字符数 - 合并损失。简化结论：净增 = 该 0 段两侧 1 段的总长度（因为合并后这些 1 连成一片，活跃区段数 = 1，而原来这些 1 是 2 段，净增 = 0）。

```python
# 关键：净增 = 被吞并的 0 段两侧 1 段长度之和 - 1（合并损失）
# 对每个 0 段 i（非首尾），gain[i] = len(segs[i-1]) + len(segs[i+1]) - 1
# 查询内取 max gain，答案 = 基线 + max(0, maxgain)
```

## 复杂度
时间：预处理 O(n)，每个查询 O(log n) 二分 + O(1) 查表，共 O(n + q log n)。
空间：段列表、前缀和、gain 数组各 O(n)，额外 O(n)。

## 易错点
- 查询 `[1,3]` 在 `s="0100"` 上 → 子串 `"100"` 无被 1 包围的 0 段 → 若误判边界 0 段可操作会多算 1，正确做法是只统计两侧都有 1 段的 0 段。
- 查询 `[2,3]` 子串 `"00"` → 全是 0，基线活跃段数 = 0，但示例输出 1，因为两端补的 '1' 不算贡献却使 `"00"` 被包围——正确做法是基线按子串内实际 '1' 段数算，补的 '1' 只用于判断 0 段是否被包围。

## 如果面试官追问
若 queries 达 10^6 且要求在线？答：预处理 gain 的稀疏表做区间 max，O(1) 查询，空间 O(n log n)。
