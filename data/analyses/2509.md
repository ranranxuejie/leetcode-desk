## 一句话思路
两个节点沿父指针 `val //= 2` 同时上跳，相遇点即 LCA，环长 = 两条路径边数之和 + 新加的 1 条边。

## 怎么做
1. 对每个查询取 `a, b`，各自维护一个「到当前节点的边数」计数器 `da, db`，初值 0。
2. 循环：若 `a == b` 跳出；否则把编号大的那个上跳一层（`a //= 2` 或 `b //= 2`），对应计数器 +1。
3. 跳出时 `da + db + 1` 就是答案——`da + db` 是 a、b 到 LCA 的树上路径边数，加 1 是新增的那条边。

以 `n = 3, queries = [[5,3]]` 为例：`a=5, b=3`，5 > 3 故 `a=2, da=1`；此时 2 < 3，`b=1, db=1`；2 > 1，`a=1, da=2`；`a == b == 1` 跳出，答案 `2 + 1 + 1 = 4`，与示例一致。第二个查询 `[4,7]`：4 < 7 → `b=3, db=1`；4 > 3 → `a=2, da=1`；2 < 3 → `b=1, db=2`；2 > 1 → `a=1, da=2`；相遇，`2+2+1=5`。

```python
def cycleLengthQueries(n, queries):
    ans = []
    for a, b in queries:
        da = db = 0
        while a != b:
            if a > b:
                a //= 2
                da += 1
            else:
                b //= 2
                db += 1
        ans.append(da + db + 1)
    return ans
```

关键点：编号大的节点深度不一定大，但「编号大就上跳」在完全二叉树里恰好等价于「深度大的先上跳」，因为同一层内编号越大越靠右，而父节点编号 `val // 2` 严格小于子节点，所以按数值比较上跳不会跳过 LCA。

## 复杂度
时间：每个查询 O(log(2^n)) = O(n)，总 O(m·n)，m 为查询数。
空间：O(1) 额外空间（不计长度为 m 的答案数组）。

## 易错点
- 忘记加新增的那条边 → 对 `[1,2]` 会输出 1，正确是 2。环必须包含新加的边，答案恒为 `da + db + 1`，不是 `da + db`。
- 用「深度」而不是「编号大小」判断谁先上跳，需要额外算 `bit_length`；直接比较 `a > b` 更省事且正确，因为父编号恒小于子编号。若误写成 `a < b` 时上跳 `a`，会在 `[5,3]` 上把 5 和 3 交替上跳，多算步数得到 5 而非 4。

## 如果面试官追问
问：若查询数 m 涨到 10^7 且 n 到 60，怎么优化？
答：单次已是最优 O(n)，只能靠批量预处理深度数组或按层分桶，但常数收益有限，瓶颈在 m 本身。
