## 一句话思路
枚举类型 3 物品的数量 k（只需枚举到 min(need1, need2) 附近的两个候选），其余需求用类型 1/2 补齐，取最小花费。

## 怎么做
1. 先把 costBoth 压到 min(costBoth, cost1 + cost2)，因为一个类型 3 物品最多替代一个类型 1 加一个类型 2。
2. 关键观察：最优解中类型 3 的数量 k 只会取 0 或 min(need1, need2) 这两个端点之一（中间值不会更优，因为超出部分用更便宜的单品补）。
3. 对 k = 0 和 k = min(need1, need2) 分别计算：剩余 need1-k 个用 cost1，剩余 need2-k 个用 cost2，取较小值。
4. 用示例 1 验证：cost1=3, cost2=2, costBoth=1, need1=3, need2=2。k=0 时花费 3*3+2*2=13；k=min(3,2)=2 时花费 2*1 + (3-2)*3 + 0 = 5；但实际最优是 k=3（超过 need2），花费 3*1=3。所以 k 还要考虑 max(need1, need2) 端点。

修正：k 的候选是 0、min(need1,need2)、max(need1,need2) 三个值，因为类型 3 可能"超买"一侧来省另一侧的钱。

```python
def minimumCost(cost1, cost2, costBoth, need1, need2):
    costBoth = min(costBoth, cost1 + cost2)
    ans = cost1 * need1 + cost2 * need2
    for k in (min(need1, need2), max(need1, need2)):
        r1 = max(0, need1 - k)
        r2 = max(0, need2 - k)
        ans = min(ans, k * costBoth + r1 * cost1 + r2 * cost2)
    return ans
```

## 复杂度
时间：O(1)，只枚举 3 个候选 k 值，与 need1/need2 大小无关。
空间：O(1)，仅用常数个变量。

## 易错点
- 只枚举 k=min(need1,need2) → 示例 1 会得 5 而非 3 → 必须加上 k=max(need1,need2) 这个"超买"候选。
- 忘记把 costBoth 压到 min(costBoth, cost1+cost2) → 当 costBoth 很贵时（如示例 2 的 15 > 5+4=9），k 取大值反而多花钱，压一下保证枚举安全。

## 如果面试官追问
问：如果 need1/need2 达到 10^18 还能这样做吗？答：能，候选 k 仍是那三个端点，O(1) 不受规模影响。
