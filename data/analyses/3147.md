## 一句话思路
按 `i % k` 把下标分成 k 条链，每条链从尾往头累加后缀和，取全局最大。

## 怎么做
1. 关键观察：从 `i` 出发只能走 `i, i+k, i+2k, ...`，所以所有下标按 `i % k` 分成 k 条互不相交的链，答案必是某条链的某个后缀和。
2. 倒序遍历 `i` 从 `n-1` 到 `0`，用 `suf[i] = energy[i] + (suf[i+k] if i+k < n else 0)` 一次算出每个位置出发能拿到的总能量。
3. 边算边更新 `best`，初值取 `-2**31`（答案可能全负，不能初始化成 0）。

以 `energy = [5,2,-10,-5,1], k = 3` 为例：`i=4` 时 `suf[4]=1`（`4+3=7` 越界），`i=1` 时 `suf[1]=2+suf[4]=3`，`best` 更新为 3；`i=0` 得 `5+suf[3]=0`，`i=2` 得 `-10+suf[5]` 越界即 `-10`，最终 `best=3`。

```python
n = len(energy)
suf = [0] * n
best = -2**31
for i in range(n - 1, -1, -1):
    nxt = suf[i + k] if i + k < n else 0
    suf[i] = energy[i] + nxt
    if suf[i] > best:
        best = suf[i]
return best
```

注意 `i + k < n` 这个边界：`i` 在最后 k 个位置时链就断了，`nxt` 必须是 0 而不是 `suf` 里的残留值。

## 复杂度
时间 O(n)：倒序扫一遍，每个下标只算一次 `suf[i]`。
空间 O(n)：额外开 `suf` 数组存 n 个后缀和；若只保留 `i+k` 位置的值可压到 O(k)。

## 易错点
- 全负输入如 `energy = [-2,-3,-1], k = 2` → 把 `best` 初始化成 0 会返回 0，但正确答案是 `-1` → 初值必须用 `-2**31` 或 `energy[0]`。
- `i + k >= n` 时 → 误写成 `suf[i] = energy[i] + suf[i+k]` 会数组越界或读到 0 以外的脏值 → 必须先判断 `i + k < n` 再取 `suf[i+k]`，否则加 0。

## 如果面试官追问
问：能不能 O(k) 空间？
答：可以，只维护长度为 k 的滚动数组，`suf[i % k]` 存当前链的累加值，倒序时 `suf[i % k] += energy[i]` 即可。
