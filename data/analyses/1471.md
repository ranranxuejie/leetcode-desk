## 一句话思路
排序后取中位数 m，用左右双指针从两端向中间扫，每步挑离 m 更远（距离相等取更大）的一端，取满 k 个。

## 怎么做
1. 先 `arr.sort()`，取 `m = arr[(n - 1) // 2]`。
2. 设 `l = 0, r = n - 1`，循环 k 次，每次比较 `abs(arr[l] - m)` 与 `abs(arr[r] - m)`。
3. 若右端距离更大，或距离相等且 `arr[r] > arr[l]`，取 `arr[r]` 并 `r -= 1`；否则取 `arr[l]` 并 `l += 1`。
4. 收集到的 k 个值直接返回，顺序任意。

以示例 1 `arr = [1,2,3,4,5], k = 2` 为例：排序后 `m = arr[2] = 3`，`l = 0, r = 4`。第一轮 `abs(1-3) = 2`、`abs(5-3) = 2`，距离相等但 `5 > 1`，取 5、`r` 变 3；第二轮 `abs(1-3) = 2`、`abs(4-3) = 1`，左端更远，取 1。结果 `[5, 1]`。

```python
arr.sort()
n = len(arr)
m = arr[(n - 1) // 2]
l, r, res = 0, n - 1, []
while len(res) < k:
    dl, dr = abs(arr[l] - m), abs(arr[r] - m)
    if dr > dl or (dr == dl and arr[r] > arr[l]):
        res.append(arr[r]); r -= 1
    else:
        res.append(arr[l]); l += 1
return res
```

关键点：`l` 和 `r` 永远不会交叉到取重复元素，因为每轮只动一端，且 `k <= n`。

## 复杂度
时间：排序 O(n log n)，双指针扫 k 步 O(k)，总计 O(n log n)。
空间：排序栈开销 O(log n)，结果数组 O(k)，无额外哈希。

## 易错点
- 输入 `arr = [1,1,3,5,5], k = 2`：若只按距离比较、漏掉「距离相等取更大」的规则，可能先取到左边的 1 而不是右边的 5，输出 `[1,5]` 而非 `[5,5]`。正确做法是判断条件写成 `dr > dl or (dr == dl and arr[r] > arr[l])`，相等时优先右端。
- 输入 `arr = [6,7,11,7,6,8], k = 5`：中位数下标若写成 `n // 2` 会得到 `arr[3] = 7`（本题恰好对），但换成偶数长度如 `[-7,22,17,3]` 排序后 `[-7,3,17,22]`，`n // 2 = 2` 取到 17，而题目规定 `(n-1)//2 = 1` 取到 3，中位数错则所有距离全错。必须用 `(n - 1) // 2`。

## 如果面试官追问
追问：如果 arr 长度到 10^7、内存吃紧，还能这么做吗？
答：排序仍是 O(n log n) 瓶颈，可改用快速选择找中位数 O(n)，但双指针仍需有序数组，省不掉排序。
