## 一句话思路
倒着从第 k 个字符回溯：每步看它在操作后字符串的前半还是后半，后半就按操作类型回退，前半不动。

## 怎么做
1. 先正序算出每次操作后 word 的长度 `len[i]`，用 `len[i] = len[i-1] * 2`，一旦超过 `k` 就截断成 `k`（因为只关心第 k 位，再长也没用）。
2. 从最后一次操作倒着走，维护当前目标位置 `k`；若 `k > len[i-1]`，说明它落在追加的那半，`k -= len[i-1]`，且若 `operations[i] == 1` 记一次「加一」。
3. 走完所有操作后 `k` 必为 1，答案就是 `'a'` 加上累计的加一次数，对 26 取模。

以示例 2 为例：`k=10, operations=[0,1,0,1]`，长度依次为 2,4,8,16（都 ≤10 不截断）。倒推：`k=10 > 8` → `k=2`，`op=1` 记加一；`k=2 ≤ 4` 不动；`k=2 ≤ 2` 不动；`k=2 > 1` → `k=1`，`op=0` 不加。累计加一 1 次，`'a'+1 = 'b'`，与输出一致。

```python
lengths = []
cur = 1
for op in operations:
    cur = min(cur * 2, k)
    lengths.append(cur)

shift = 0
for i in range(len(operations) - 1, -1, -1):
    half = lengths[i - 1] if i > 0 else 1
    if k > half:
        k -= half
        if operations[i] == 1:
            shift += 1
return chr((ord('a') - ord('a') + shift) % 26 + ord('a'))
```

## 复杂度
时间 O(n)，n 为 `operations.length`，每步 O(1)。
空间 O(n) 存 `lengths`，无其他额外结构。

## 易错点
- `k` 可达 `10^14`，若老老实实算 `cur * 2` 不截断，长度会膨胀到天文数字（虽 Python 不溢出但白算）；正确做法是 `cur = min(cur * 2, k)`，因为超过 k 的部分永远回溯不到。
- 倒推时判断条件写成 `k > half` 而非 `k >= half`：`k == half` 时它在前半的最后一位，属于原串，不该减也不该加一；写成 `>=` 会把示例 2 的 `k=2` 误判进后半，答案错成 `'c'`。

## 如果面试官追问
若 operations 长度涨到 `10^5` 且要求输出完整字符串？答：不可行，长度指数增长，只能保留「第 k 位」这类单点查询思路。
