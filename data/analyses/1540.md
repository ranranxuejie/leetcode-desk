## 一句话思路
把每个位置需要的切换次数 d 按 d 分组计数，第 c 个需要 d 的字符实际占用操作 d + 26·(c−1)，取最大值与 k 比较。

## 怎么做
1. 逐位算 `d = (ord(t[i]) - ord(s[i])) % 26`，`d == 0` 的位置直接跳过（不需要操作）。
2. 用长度 26 的数组 `cnt` 记录每个 d 出现的次数，`cnt[d]` 就是「需要切换 d 次」的字符有几个。
3. 对每个 d，第 c 个（c 从 1 开始）字符只能等到第 `d + 26*(c-1)` 次操作，因为操作序号必须 ≡ d (mod 26)。
4. 所有字符所需的最大操作序号 ≤ k 就返回 `True`。

以示例 2 `s="abc", t="bcd", k=10` 为例：三个位置 d 都是 1，`cnt[1] = 3`。第 1 个占第 1 次，第 2 个占第 27 次，第 3 个占第 53 次，最大 53 > 10，返回 `False`。示例 3 `s="aab", t="bbb", k=27`：`cnt[1] = 2`，最大是 `1 + 26*1 = 27 ≤ 27`，返回 `True`。

```python
cnt = [0] * 26
for a, b in zip(s, t):
    d = (ord(b) - ord(a)) % 26
    if d:
        cnt[d] += 1
need = 0
for d in range(1, 26):
    if cnt[d]:
        need = max(need, d + 26 * (cnt[d] - 1))
return need <= k
```

## 复杂度
时间 O(n + 26)，n 是字符串长度，26 是固定字母表开销。
空间 O(26)，只开了 `cnt` 这个定长数组。

## 易错点
- `s="aab", t="bbb", k=27`：若只判断 `d <= k` 就返回 True，会漏掉第二个 'a' 必须等到第 27 次；正确做法是按 `cnt[d]` 算出 `d + 26*(cnt[d]-1)` 再比。
- `s="abc", t="bcd", k=10`：若把三个 d=1 都当成第 1 次操作，会误判 True；实际同一 d 的字符必须错开到 1、27、53，最大 53 > 10 才是 False。

## 如果面试官追问
问：若要求输出具体操作方案（每次操作选哪个下标）？
答：对每个 d 维护一个待处理下标队列，按 `d, d+26, d+52…` 依次弹出队首下标即可。
