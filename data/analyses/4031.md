## 一句话思路
排序去重后，用 `prev = lower - 1` 扫描每个落在 `[lower, upper]` 内的值，缺口就是 `[prev+1, x-1]`。

## 怎么做
1. 对 `nums` 排序并去重，只保留 `lower <= x <= upper` 的值。
2. 维护 `prev = lower - 1`，表示上一个「已覆盖」的整数。
3. 遍历每个有效 `x`：若 `x > prev + 1`，说明 `[prev+1, x-1]` 整段缺失，收进答案；然后 `prev = x`。
4. 收尾：若 `prev < upper`，补上 `[prev+1, upper]`。

以 `nums = [3,9,7], lower = 1, upper = 12` 为例：排序去重得 `[3,7,9]`。初始 `prev = 0`；遇 `x=3`，`3 > 1` 收 `[1,2]`，`prev=3`；遇 `x=7`，`7 > 4` 收 `[4,6]`，`prev=7`；遇 `x=9`，`9 > 8` 收 `[8,8]`，`prev=9`；循环结束 `9 < 12`，补 `[10,12]`。

```python
nums = sorted(set(nums))
prev, res = lower - 1, []
for x in nums:
    if x < lower or x > upper:
        continue
    if x > prev + 1:
        res.append([prev + 1, x - 1])
    prev = x
if prev < upper:
    res.append([prev + 1, upper])
```

关键在 `prev` 的语义：它永远是「最后一个被覆盖的整数」，所以缺口起点恒为 `prev + 1`，不需要额外判断边界。

## 复杂度
时间：排序 `O(n log n)`，扫描 `O(n)`，n 为 `nums` 长度。
空间：`set` 去重额外 `O(n)`，答案数组不计入。

## 易错点
- `nums = [1,1], lower = 5, upper = 7`：若不去重或不过滤，`x=1` 会让 `prev` 停在 1，收尾补出 `[2,7]` 而非 `[5,7]`。正确做法是先 `set` 去重，且 `x < lower` 时直接 `continue`，`prev` 保持 `lower-1`。
- `nums = [2,3,5], lower = 2, upper = 3`：若漏掉 `x > upper` 的过滤，`x=5` 会触发 `5 > 4` 收 `[4,4]`，多出区间。正确做法是 `x > upper` 也 `continue`，让收尾逻辑统一处理右端。

## 如果面试官追问
问：`nums` 长度到 10^7 且值域也是 10^7，排序还合适吗？
答：改用长度 `upper-lower+1` 的布尔标记数组，`O(n + upper-lower)` 时间，省掉 `log n`。
