## 一句话思路
把 `order` 转成字符→排名映射，再逐对比较相邻单词，首个不同字符的排名决定大小。

## 怎么做
1. 建映射 `rank = {c: i for i, c in enumerate(order)}`，之后所有比较都查它。
2. 相邻两词 `a, b` 逐位比到 `min(len(a), len(b))`，遇到第一个 `rank[a[i]] != rank[b[i]]` 就返回 `rank[a[i]] < rank[b[i]]`。
3. 前缀全等时，只有 `len(a) <= len(b)` 才合法，否则 `a` 更长即违规。
4. 所有相邻对都通过才返回 `True`。

用示例 3：`a="apple"`、`b="app"`，前 3 位 `a,p,p` 排名全等，循环走完 `min(5,3)=3` 位没分出胜负；此时 `len(a)=5 > len(b)=3`，直接判 `False`——这正是 `'l' > '∅'` 的规则。

```python
rank = {c: i for i, c in enumerate(order)}
for a, b in zip(words, words[1:]):
    for x, y in zip(a, b):
        if x != y:
            if rank[x] > rank[y]:
                return False
            break
    else:
        if len(a) > len(b):
            return False
return True
```

注意 `for...else`：`break` 表示已由首异字符定胜负，跳过长度检查；只有前缀全等才落到 `else` 里比长度。

## 复杂度
时间 O(N·L)：N 为单词数、L 为单词平均长度，每对最多扫 L 个字符。
空间 O(1)：`rank` 固定 26 项，其余只有循环变量。

## 易错点
- `words = ["apple","app"]`、`order` 为正常字母表 → 若只写「首异字符比较」而漏掉循环结束后的长度判断，会错返回 `True`；正确做法是前缀全等时判 `len(a) > len(b)` 即 `False`。
- `words = ["hello","leetcode"]`、`order = "hlabcdefg..."` → 若直接拿 Python 原生 `<` 比字符串，`'h' > 'l'` 会错判 `False`；必须全程走 `rank[x]` 查表，不能混用原生比较。

## 如果面试官追问
问：`words` 有 10^5 个、总字符数 10^6，还能这么写吗？
答：能，仍是 O(总字符数)，瓶颈只在逐字符扫描，映射查表 O(1)。
