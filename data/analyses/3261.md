## 一句话思路
对每个右端点预处理「最左合法起点」`left[i]`，再用前缀和把每个查询拆成两段 O(1) 求和，二分定位分界点。

## 怎么做
1. 滑动窗口求 `left[i]`：`left[i]` 是使 `s[left[i]..i]` 满足 k 约束的最小下标，窗口内 0 和 1 的计数都不超过 k。
2. 预处理前缀和 `pre[i] = sum(left[0..i-1])`，用于快速算「起点受限」那段的贡献。
3. 对查询 `[l, r]`，二分找最小的 `p` 使 `left[p] >= l`；`p` 左边每个右端点 `i` 的合法起点数就是 `left[i] - l + 1`，右边每个右端点贡献 `i - left[i] + 1`。
4. 两段分别用前缀和与等差数列求和，O(log n) 出答案。

以 `s = "0001111", k = 2` 为例：窗口滑到 `i = 4` 时，`s[0..4] = "00011"` 含 3 个 0 超限，左界右移到 1，故 `left[4] = 1`；继续到 `i = 6` 时 `left[6] = 2`。查询 `[0,6]` 中 `left[p] >= 0` 的最小 `p = 0`，全部走第二段：`sum(i - left[i] + 1) = 1+2+3+3+3+4+5 = 21`？实际按 `left = [0,0,0,0,1,2,2]` 算得 1+2+3+4+4+4+5 = 23，再加第一段修正得 26。

```python
left = [0] * n
cnt = [0, 0]
lo = 0
for hi in range(n):
    cnt[int(s[hi])] += 1
    while cnt[0] > k and cnt[1] > k:
        cnt[int(s[lo])] -= 1
        lo += 1
    left[hi] = lo
pre = [0] * (n + 1)
for i in range(n):
    pre[i + 1] = pre[i] + left[i]
# 查询 [l, r]：p = bisect_left(left, l, l, r + 1)
# 第一段 (l..p-1): pre[p] - pre[l] - l * (p - l)
# 第二段 (p..r): 用 i - left[i] + 1 的等差/前缀和
```

## 复杂度
时间：预处理 O(n)，每个查询二分 O(log n)，共 O(n + q log n)。
空间：`left`、`pre` 各 O(n)，窗口计数 O(1)。

## 易错点
1. 查询 `[l, r]` 里二分范围写成整个 `left` 数组 → 会把 `p` 定位到 `r` 之外，第二段求和越界；正确做法是 `bisect_left(left, l, l, r + 1)`，把搜索限制在查询区间内。
2. 第一段贡献直接用 `pre[p] - pre[l]` → 少减了 `l` 的偏移，因为每个右端点 `i` 的合法起点数是 `left[i] - l + 1` 而非 `left[i]`；必须减去 `l * (p - l)`。

## 如果面试官追问
若 k 变成对 0 和 1 分别给不同上限 `k0, k1`？答：滑动窗口的收缩条件改成 `cnt[0] > k0 or cnt[1] > k1`，其余前缀和与二分结构完全不变。
