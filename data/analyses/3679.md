## 一句话思路
按天贪心保留，用哈希表记录每种类型最近 w 天内被保留的天数，超限就丢弃当天物品。

## 怎么做
1. 维护 `kept[type]` 为双端队列，存该类型被保留的天数下标，队首是最早的保留记录。
2. 遍历 `arrivals`，第 `i` 天（0 基）先弹出 `kept[arrivals[i]]` 中 `< i - w + 1` 的下标，保证队列只覆盖窗口 `[i-w+1, i]`。
3. 若队列长度 `< m`，保留该物品并把 `i` 入队；否则丢弃，`ans += 1`，不入队。
4. 返回 `ans`。

以示例 2 `arrivals = [1,2,3,3,3,4], w = 3, m = 2` 为例：处理到 `i = 4`（第 5 天，值 3）时，`kept[3]` 中已有下标 2、3，弹出 `< 4-3+1 = 2` 的下标后剩 `[2,3]`，长度 2 已达 `m`，故丢弃，`ans = 1`。

```python
from collections import defaultdict, deque

kept = defaultdict(deque)
ans = 0
for i, x in enumerate(arrivals):
    q = kept[x]
    while q and q[0] < i - w + 1:
        q.popleft()
    if len(q) < m:
        q.append(i)
    else:
        ans += 1
return ans
```

关键点：丢弃的物品**不入队**，所以队列长度天然就是「窗口内该类型被保留的次数」，无需额外计数变量。

## 复杂度
时间 O(n)：每个下标最多入队、出队各一次，`n = len(arrivals)`。
空间 O(n)：`kept` 中所有队列元素总数不超过 n。

## 易错点
- 窗口边界写成 `i - w` 而非 `i - w + 1`：示例 2 中 `i = 4` 时会把下标 2 误弹出，`kept[3]` 只剩 `[3]`，长度 1 `< 2` 于是错误保留，答案变成 0。正确是弹出 `< i - w + 1` 的下标。
- 丢弃时仍把下标入队：示例 2 中第 5 天丢弃后若入队，`kept[3]` 变 `[2,3,4]`，第 6 天窗口 `[3,4,5]` 弹出 2 后长度仍为 2，看似无碍，但后续同类型到达会连锁误判为超限，多丢物品。正确做法是丢弃分支只 `ans += 1`，不碰队列。

## 如果面试官追问
若要求输出具体丢弃的天数列表而非仅计数？答：丢弃分支里追加 `i + 1` 到结果数组即可，贪心策略不变，仍是最优。
