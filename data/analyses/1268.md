## 一句话思路
先对 products 排序，每个前缀用二分找左边界，从该位置连续取最多 3 个即字典序最小的候选。

## 怎么做
1. 对 products 排序，得到 `["mobile","moneypot","monitor","mouse","mousepad"]`。
2. 逐字母累积前缀 `prefix`，用 `bisect_left(products, prefix)` 求第一个 ≥ prefix 的下标 `lo`。
3. 从 `lo` 起向后取，只要 `products[j].startswith(prefix)` 且不足 3 个就收下，遇到不匹配立即停。
4. 每步结果 append 进答案。

关键中间值：`prefix="mou"` 时 `bisect_left` 返回 3（`"mouse"` 的位置），从 3 起 `"mouse"`、`"mousepad"` 都匹配，得 `["mouse","mousepad"]`；而 `prefix="mo"` 返回 0，取前 3 个 `["mobile","moneypot","monitor"]`。

```python
import bisect
products.sort()
res, prefix = [], ""
for ch in searchWord:
    prefix += ch
    lo = bisect.bisect_left(products, prefix)
    cur = []
    for j in range(lo, min(lo + 3, len(products))):
        if not products[j].startswith(prefix):
            break
        cur.append(products[j])
    res.append(cur)
```

注意 `range` 上界用 `lo+3` 只是剪枝，真正的终止靠 `startswith` 失败——因为 `lo` 之后可能连续多个都不匹配（如 `prefix="tat"` 时 `lo=len(products)`，循环直接空转）。

## 复杂度
时间：排序 O(m·L·log m)，每个前缀二分 O(log m) 加最多 3 次 `startswith` 比较 O(L)，共 O(L·(m log m + n))。
空间：答案列表最多 n×3 个字符串引用，排序原地，额外 O(1) 辅助。

## 易错点
- `products=["bags","baggage","banner","box","cloths"]`、`prefix="bags"`：`bisect_left` 返回 1（`"bags"` 位置），但 `"baggage"` 排在 `"bags"` 前且也以 `"bags"` 开头，若只从 `lo` 往后取会漏掉它 → 正确做法是排序后 `"baggage"` 在 `"bags"` 之前，`lo` 指向 `"bags"`，从 `lo` 起取恰好是 `["bags"]`，但示例 3 期望 `["bags"]` 而非含 `"baggage"`，说明 `"baggage"` 不以 `"bags"` 开头（是 `"bagg"`），所以 `lo` 定位正确；真正的坑是误以为 `"baggage"` 匹配 `"bags"`。
- `searchWord="tatiana"`、`products=["havana"]`：`bisect_left` 返回 1（越界），若写成 `products[lo]` 直接索引会 IndexError → 正确做法是先判 `lo < len(products)` 或用 `range(lo, min(lo+3, len(products)))` 保证空循环。

## 如果面试官追问
问：products 到 10^5、searchWord 到 10^5 怎么办？
答：换字典树，每个节点存至多 3 个字典序最小的产品，插入时沿路径更新，查询 O(L)。
