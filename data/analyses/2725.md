## 一句话思路
用 `setInterval` 立即调用一次 `fn`，再靠 `clearInterval` 在取消时停掉，避免递归 `setTimeout` 累积。

## 怎么做
1. 先同步调用 `fn(*args)`，保证 time=0 那次不依赖定时器。
2. 用 `setInterval` 存下 `timerId`，间隔 `t` 毫秒重复调用 `fn(*args)`。
3. 返回的 `cancelFn` 里只做 `clearInterval(timerId)`。
4. 取消时机由外部 `setTimeout(cancelFn, cancelTimeMs)` 控制，函数内部不判断时间。

以示例 1 为例：`fn(4)` 在 0ms 立即返回 8，`timerId` 每 35ms 触发一次；到 190ms 外部调用 `cancelFn`，`clearInterval` 后 175ms 那次是最后一次，190ms 不再产生新调用。

```python
import threading

def cancellable(fn, args, t):
    fn(*args)
    stopped = threading.Event()

    def loop():
        while not stopped.wait(t / 1000):
            fn(*args)

    th = threading.Thread(target=loop, daemon=True)
    th.start()

    def cancel_fn():
        stopped.set()

    return cancel_fn
```

关键中间值：`stopped.wait(0.035)` 返回 `False` 时执行 `fn(4)`，返回 `True` 时退出循环，对应 190ms 的取消点。

## 复杂度
时间：每次触发 O(1)，共约 `cancelTimeMs // t` 次调用，即 O(cancelTimeMs / t)。
空间：只存一个 `timerId`（或一个 `Event`），O(1) 额外空间。

## 易错点
- 若用递归 `setTimeout` 且每次新建定时器，`cancelFn` 只清掉最后一个 `timerId`，前面的仍会触发 → 示例 1 在 190ms 后还会冒出 210ms 的调用 → 正确做法是只保留一个 `setInterval` 的 id，或用一个 `stopped` 标志让循环整体退出。
- 若把首次调用也放进 `setInterval`，第一次触发会推迟到 `t` 毫秒（示例 1 变成 35ms 才有第一个 8，缺了 time=0 那条）→ 正确做法是启动定时器前先手动 `fn(*args)` 一次。

## 如果面试官追问
问：如果 `t` 不是固定值而是每次动态变化怎么办？
答：改用递归 `setTimeout`，每次回调里重新排下一次，并把最新的 `timerId` 存到闭包变量里供 `cancelFn` 清除。
