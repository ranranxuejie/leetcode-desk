## 一句话思路
每次对当前最大值减半，用大顶堆维护，因为减半的收益与该数当前大小成正比，贪心取最大必然最优。

## 怎么做
1. 求 `total = sum(nums)`，目标是把总和降到 `total / 2` 以下，即累计减少量 `reduced >= total / 2`。
2. 把 `nums` 全部取负压入堆（Python 的 `heapq` 是小顶堆），堆顶 `-heap[0]` 就是当前最大值。
3. 循环：弹出堆顶 `x`，减半得 `half = x / 2`，`reduced += half`，把 `-half` 压回堆，`ops += 1`，直到 `reduced >= total / 2`。
4. 返回 `ops`。

以 `nums = [5,19,8,1]` 为例，`total = 33`，目标 `reduced >= 16.5`。第一次弹 `19`，`half = 9.5`，`reduced = 9.5`；第二次弹 `9.5`，`half = 4.75`，`reduced = 14.25`；第三次弹 `8`，`half = 4.0`，`reduced = 18.25 >= 16.5`，返回 3。注意第二次弹的是减半后的 `9.5` 而不是 `8`，这正是堆动态更新的关键。

```python
import heapq

def halveArray(nums):
    total = sum(nums)
    heap = [-x for x in nums]
    heapq.heapify(heap)
    reduced = 0.0
    ops = 0
    while reduced < total / 2:
        x = -heapq.heappop(heap)
        half = x / 2
        reduced += half
        heapq.heappush(heap, -half)
        ops += 1
    return ops
```

## 复杂度
时间：`O(n log n)`，`n` 来自建堆，每次操作 `log n`，操作次数上界 `O(n log(max))` 但实际远小。
空间：`O(n)`，堆里存了 `n` 个元素。

## 易错点
- 输入 `nums = [1]`：若用 `reduced > total / 2` 严格大于，`1` 减半后 `reduced = 0.5`，`0.5 > 0.5` 为假会死循环或漏判；题目要求「至少减少一半」，必须用 `>=`。
- 输入 `nums = [3,8,20]`：若只对原始数组排序后从大到小减半、不把减半结果放回堆，会先减 `20→10`、再减 `8→4`，漏掉 `10→5` 这次更优操作，得到错误次数；正确做法是每次把 `half` 压回堆，让 `10` 继续参与比较。

## 如果面试官追问
问：如果要求输出具体操作序列（每次选哪个下标）？答：堆里存 `(-value, index)` 元组，每次弹出记录 `index`，减半后带同一 `index` 压回即可。
