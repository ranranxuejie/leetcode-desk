## 一句话思路
把每个数按 mapping 逐位转成映射串，用 (映射串, 原下标) 排序，稳定性和前导零问题一并解决。

## 怎么做
1. 对 `nums` 中每个数，逐位取 `mapping[d]` 拼成字符串 `s`，同时记下原下标 `i`。
2. 排序键用 `(s, i)`：`s` 是字符串，长度不同时短的自然小，长度相同时逐字符比较，正好等价于去前导零后的数值比较。
3. 按下标顺序取回原数，输出。

以示例 1 为例：`991` 逐位得 `mapping[9]=6, mapping[9]=6, mapping[1]=9`，拼成 `"669"`；`338` 得 `"007"`，`38` 得 `"07"`。排序键分别是 `("669",0)`、`("007",1)`、`("07",2)`。`"007"` 与 `"07"` 长度不同，`"007" < "07"`（第 2 位 `0` < `7`），所以 `338` 排在 `38` 前，与题意一致。

```python
def key(x, i):
    s = ''.join(str(mapping[int(c)]) for c in str(x))
    return (s, i)

order = sorted(range(len(nums)), key=lambda i: key(nums[i], i))
return [nums[i] for i in order]
```

关键点：**不要**把映射串转成 `int` 再比较。`"007"` 和 `"07"` 转成 int 都是 `7`，此时只能靠下标 `i` 兜底；而字符串比较本身已经区分了它们，`i` 只用于真正完全相同的映射串（如两个 `38`）。

## 复杂度
时间：O(n·L·log n)，n 是 `nums` 长度，L ≤ 10 是位数，log n 来自排序比较。
空间：O(n·L)，存 n 个映射串和下标数组。

## 易错点
- 输入 `nums = [338, 38]` → 若把映射串转 `int` 后只按数值排序，两者都是 `7`，可能被排成 `[38, 338]` → 正确做法是保留原下标作第二关键字，或直接用字符串比较。
- 输入 `nums = [0]`、`mapping[0]=0` → 若用 `while x: x //= 10` 逐位处理，`0` 一位都不产生，映射串为空串 → 正确做法是对 `str(x)` 逐字符映射，`"0"` 天然得到一位。

## 如果面试官追问
问：`nums` 涨到 10^6 还能这么排吗？
答：能，但把映射串预先算好存进数组，避免排序时重复构造，比较仍是 O(L)。
