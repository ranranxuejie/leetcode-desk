## 一句话思路
维护当前楼层 `cur`，逐个请求累加 `abs(req - cur)` 并更新 `cur`，因为每段移动时间就是楼层差的绝对值。

## 怎么做
1. 初始化 `cur = 0`、`total = 0`，`cur` 表示电梯当前所在楼层。
2. 遍历 `requests`，对每个 `req` 累加 `abs(req - cur)`，这一步就是电梯从 `cur` 走到 `req` 的秒数。
3. 累加后立刻把 `cur` 更新为 `req`，因为处理完请求电梯就停在该楼层。
4. 遍历结束返回 `total`。

以示例 1 `n = 5, requests = [2,1,4,3]` 为例，走完前两个请求后 `cur = 1`、`total = 2 + 1 = 3`；处理 `req = 4` 时 `abs(4 - 1) = 3`，`total` 变成 6，`cur` 变成 4；最后 `abs(3 - 4) = 1`，`total = 7`。关键中间值就是每步的 `cur`，它决定了下一段距离。

```python
cur = 0
total = 0
for req in requests:
    total += abs(req - cur)
    cur = req
return total
```

注意 `n` 在这道题里完全没参与计算：楼层编号范围只保证 `requests[i]` 合法，不影响距离。别为了「用上 n」去写 `min(req, n - 1)` 之类的多余逻辑。

## 复杂度
时间：O(m)，m 为 `requests.length`，每个请求做一次减法取绝对值。
空间：O(1)，只开了 `cur` 和 `total` 两个变量。

## 易错点
- 输入 `requests = [0, 0, 0]` → 若把初始 `cur` 写成 `requests[0]` 再跳过第一个元素，会漏算或错算首段 → 正确做法是 `cur` 固定从 0 起，第一个请求也照常算 `abs(0 - 0) = 0`。
- 输入 `requests = [2,0,0]` → 若在 `req == cur` 时 `continue` 而不更新 `cur`，本例恰好没事，但若写成「相等就跳过整轮循环」并顺手改了别的状态就会出错 → 正确做法是不做特判，`abs` 自然给出 0，`cur = req` 照常执行。

## 如果面试官追问
问：如果电梯一次能载多个请求、要求按最优顺序服务，怎么改？
答：那就不是顺序模拟了，变成在楼层序列上求最短路径，需要排序或 DP，不再是 O(m) 累加。
