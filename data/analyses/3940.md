## 一句话思路
用读写双指针原地压缩：写指针 `w` 只在「当前元素出现次数 < k」时前进，读指针 `i` 扫一遍。

## 怎么做
1. 设 `w = 0` 表示下一个可写位置，`i` 从 0 扫到 `len(nums)-1`。
2. 判断 `nums[i]` 能否保留：若 `w < k`，说明前面不足 k 个元素，直接保留；否则比较 `nums[i] != nums[w-k]`。
3. 能保留就写 `nums[w] = nums[i]`，然后 `w += 1`。
4. 扫完后返回 `nums[:w]`。

关键中间值：以 `nums = [1,1,1,2,2,3], k = 2` 为例，扫到 `i = 2`（第三个 1）时 `w = 2`，此时 `nums[w-k] = nums[0] = 1`，与 `nums[2] = 1` 相等，说明 1 已出现满 2 次，跳过不写；扫到 `i = 3` 时 `w` 仍为 2，`nums[0] = 1 != 2`，写入 `nums[2] = 2`，`w` 变 3。

```python
w = 0
for i in range(len(nums)):
    if w < k or nums[i] != nums[w - k]:
        nums[w] = nums[i]
        w += 1
return nums[:w]
```

`nums[w-k]` 这个下标是本解的核心：因为数组有序，若当前元素与「往前数第 k 个已保留元素」相同，说明它已经是第 k+1 次出现，必须丢弃；不同则说明它是新元素或还没满 k 次。`w < k` 的短路判断防止 `w-k` 为负。

## 复杂度
时间 O(n)：`i` 单趟扫描，`w` 只增不减，总写入次数 ≤ n。
空间 O(1)：只在 `nums` 上原地覆写，`nums[:w]` 是返回结果，不计入额外空间。

## 易错点
- 输入 `nums = [1,1,1], k = 1`：若写成 `nums[i] != nums[w-1]`（用 `w-1` 而非 `w-k`），第三个 1 会与 `nums[1]` 比较，而 `nums[1]` 已被覆写成 1，判断失效导致输出 `[1,1]`。正确做法是固定回看 `w-k`，它指向「上一个不同元素」或「本元素第 k 次出现的位置」。
- 输入 `nums = [1,1,2], k = 3`：若省略 `w < k` 的短路，`i = 0` 时 `w - k = -3`，Python 负索引会取到 `nums[-3] = 1`，恰好与 `nums[0]` 相等，第一个元素就被误删，输出 `[1,2]`。正确做法是先判 `w < k` 直接保留。

## 如果面试官追问
问：若数组未排序，还能 O(1) 空间吗？
答：不能，需哈希表计数，空间 O(不同元素个数)，且要保持相对顺序只能顺序扫描。
