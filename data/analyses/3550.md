## 一句话思路
从左到右扫一遍，对每个 `nums[i]` 求数位和，第一个等于 `i` 的直接返回，因为下标递增天然保证最小。

## 怎么做
1. 用 `enumerate(nums)` 同时拿到下标 `i` 和值 `v`，顺序即从小到大。
2. 对 `v` 反复 `v // 10` 累加 `v % 10`，得到数位和 `s`。
3. 若 `s == i` 立即 `return i`，不再看后面的元素。
4. 循环结束仍无匹配，`return -1`。

以 `nums = [1,10,11]` 为例：`i=0` 时 `v=1`，数位和 `s=1`，`1 != 0` 跳过；`i=1` 时 `v=10`，第一轮 `s += 0`、`v` 变 `1`，第二轮 `s += 1`、`v` 变 `0`，得 `s=1`，`1 == 1` 命中，返回 `1`。注意 `i=2` 的 `11` 数位和也是 `2` 也满足，但已经被 `i=1` 抢先返回，这正是「最小」的来源。

```python
def smallestIndex(nums):
    for i, v in enumerate(nums):
        s = 0
        while v:
            s += v % 10
            v //= 10
        if s == i:
            return i
    return -1
```

关键细节：`while v` 在 `v == 0` 时不进循环，`s` 保持 `0`。这对 `nums[i] = 0` 且 `i = 0` 是必需的——`0` 的数位和是 `0`，应命中下标 `0`。若写成 `while v > 0` 效果相同，但若误写成先 `v % 10` 再判断就会漏。

## 复杂度
时间：O(n log M)，`n = len(nums)`，`log M` 是 `nums[i] ≤ 1000` 的位数（最多 4 位）。
空间：O(1)，只用了 `i`、`v`、`s` 三个标量，没有额外数组。

## 易错点
- 输入 `nums = [0]` → 若把数位和循环写成 `while v > 0` 之外还额外假设「至少一位」，或直接 `return -1` 跳过 `v=0`，会错成 `-1`；正确做法是让 `s` 初值 `0`、`while v` 不进循环，得 `s=0 == i=0`，返回 `0`。
- 输入 `nums = [1,10,11]` → 若先收集所有满足的下标再取 `min`，逻辑对但多此一举；若反向遍历取最后一个匹配，会错成 `2`；正确做法是从 `i=0` 正向扫，第一次 `s == i` 就 `return`，保证最小。

## 如果面试官追问
问：若 `nums` 长度到 `10**5`、`nums[i]` 到 `10**9`，还能更快吗？
答：不能渐进更快，仍要 O(n log M) 全扫，只是位数上限变大；可预计算数位和数组复用。
