## 一句话思路
把所有 (值, 下标) 排序后按顺序扫描，用 `marked` 数组跳过已标记位置，选中即标记左右邻居。

## 怎么做
1. 构造 `order = sorted((v, i) for i, v in enumerate(nums))`，值升序、值相同下标升序，正好匹配「最小且下标最小」。
2. 开 `marked = [False] * n`，遍历 `order`，`if marked[i]: continue`。
3. 命中则 `score += v`，并把 `i-1, i, i+1`（在界内）置 `True`。
4. 返回 `score`。

以 `nums = [2,1,3,4,5,2]` 为例：`order` 前两项是 `(1,1)`、`(2,0)`。处理 `(1,1)` 时标记下标 0、1、2，`score = 1`；接着 `(2,0)` 已被标记跳过；`(2,5)` 未标记，标记 4、5，`score = 3`；最后 `(4,3)` 未标记，标记 2、3、4，`score = 7`。注意 `(2,0)` 被跳过这一步——排序保证它先于 `(2,5)` 被检查，但标记状态让它出局。

```python
order = sorted((v, i) for i, v in enumerate(nums))
marked = [False] * len(nums)
score = 0
for v, i in order:
    if marked[i]:
        continue
    score += v
    for j in (i - 1, i, i + 1):
        if 0 <= j < len(nums):
            marked[j] = True
return score
```

关键点：排序一次定序，之后只做「查标记 + 打标记」，不需要堆的删除操作，也不需要真的从数组里删元素。

## 复杂度
时间 O(n log n)：排序主导，扫描是 O(n)，每个位置最多被标记一次。
空间 O(n)：`order` 存 n 个二元组，`marked` 存 n 个布尔。

## 易错点
1. 相等元素的下标顺序：`nums = [2,3,5,1,3,2]` 里两个 2 在下标 0 和 5。若只按值排序（如 `sorted(nums)` 再 `index` 找位置），可能先取到下标 5 的 2，标记 4、5 后下标 0 的 2 仍存活，最终得分变成 1+2+2 的顺序错乱。必须把下标一起放进元组，Python 元组比较天然按 (值, 下标) 升序。
2. 边界标记：`i = 0` 时 `i - 1 = -1`，若直接写 `marked[i-1] = True` 会污染数组末尾元素，导致本该计分的 `nums[n-1]` 被跳过。必须用 `0 <= j < len(nums)` 过滤，不能依赖 Python 负索引「不报错」这一点。

## 如果面试官追问
问：如果要求返回被选中元素的下标序列而非分数？答：同样排序扫描，命中时把 `i` 追加到结果列表，标记逻辑不变，复杂度不变。
