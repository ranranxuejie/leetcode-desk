## 一句话思路
左右双指针从两端向中间收缩，因为数组升序，和偏小只能右移左指针、偏大只能左移右指针。

## 怎么做
1. 令 `left = 0`、`right = len(numbers) - 1`，分别指向最小和最大元素。
2. 每轮算 `s = numbers[left] + numbers[right]`，与 `target` 比较。
3. `s == target` 直接返回 `[left, right]`；`s < target` 则 `left += 1`；`s > target` 则 `right -= 1`。
4. 循环直到 `left >= right`（题设保证有解，实际不会走到）。

以 `numbers = [1,2,4,6,10], target = 8` 为例：初始 `left=0, right=4`，`s = 1 + 10 = 11 > 8`，右指针左移；`right=3` 时 `s = 1 + 6 = 7 < 8`，左指针右移；`left=1` 时 `s = 2 + 6 = 8`，返回 `[1,3]`。关键中间值是第一次比较的 `11`——它直接排除了 `10` 与任何元素的组合。

```python
left, right = 0, len(numbers) - 1
while left < right:
    s = numbers[left] + numbers[right]
    if s == target:
        return [left, right]
    if s < target:
        left += 1
    else:
        right -= 1
```

正确性依据：当 `numbers[left] + numbers[right] < target` 时，`numbers[left]` 与区间内任何更小元素相加只会更小，故 `left` 可安全丢弃；右侧对称。

## 复杂度
时间 O(n)：`left` 与 `right` 合计最多移动 n 次，每次比较 O(1)。
空间 O(1)：只开了 `left`、`right`、`s` 三个变量，没有额外数组。

## 易错点
- 输入 `numbers = [2,3,4], target = 6` → 若写成 `while left <= right`，当 `left == right == 2` 时会拿 `4` 和自己相加得 `8`，或误判同一元素用两次 → 循环条件必须是 `left < right`，保证两个下标不同。
- 输入 `numbers = [-1,0], target = -1` → 若照搬主站 167 题返回 `[left+1, right+1]`，会输出 `[1,2]` 越界 → 本题下标从 0 开始，直接返回 `[left, right]`，不要加一。

## 如果面试官追问
问：若数组无序且要求 O(n) 时间怎么办？
答：改用哈希表存 `target - numbers[i]` 到已访问下标，边扫边查，代价是 O(n) 额外空间。
