## 一句话思路
按顺序贪心：20 元优先用 10+5 找零，因为 5 元更通用，留着它应对后续的 10 元顾客。

## 怎么做
1. 维护 `five` 和 `ten` 两个计数器，分别记录手头 5 元和 10 元的张数。
2. 收到 5 元：`five += 1`，无需找零。
3. 收到 10 元：若 `five == 0` 直接返回 `False`，否则 `five -= 1; ten += 1`。
4. 收到 20 元：优先 `ten > 0 and five > 0` 时 `ten -= 1; five -= 1`；否则 `five >= 3` 时 `five -= 3`；都不满足返回 `False`。

以 `bills = [5,5,10,10,20]` 为例，处理到最后一个 20 时，`five == 0`、`ten == 2`：10+5 路线因 `five == 0` 失败，3×5 路线因 `five < 3` 失败，返回 `False`——这正是示例 2 的答案。

```python
five = ten = 0
for b in bills:
    if b == 5:
        five += 1
    elif b == 10:
        if five == 0:
            return False
        five -= 1
        ten += 1
    else:
        if ten > 0 and five > 0:
            ten -= 1
            five -= 1
        elif five >= 3:
            five -= 3
        else:
            return False
return True
```

关键在 20 元那一步的顺序：先试 10+5，再试 5+5+5。反过来先花 3 张 5 元，会让后面 10 元顾客无零可找。

## 复杂度
时间：O(n)，n 为 `bills` 长度，每个元素常数次判断。
空间：O(1)，只开 `five`、`ten` 两个计数器。

## 易错点
- 输入 `[5,5,10,10,20]` → 若 20 元先走 3×5 分支（此处 `five` 已为 0 走不通，但换成 `[5,5,5,10,20]` 后若先花 3 张 5 元）会误判 → 正确做法是 20 元永远先试 `ten > 0 and five > 0`。
- 输入 `[10]` 或 `[10,10]` → 若只检查 `five` 总量而不在 10 元分支提前 `return False`，会漏掉首位顾客就找不开的情况 → 收到 10 元时 `five == 0` 必须立刻返回 `False`。

## 如果面试官追问
问：如果面额改成 5/10/20/50，贪心还成立吗？
答：不成立，50 元找零有 20+20+10、20+10+10+5 等多种组合，需按面额从大到小贪心并验证，或退化为回溯/DP。
