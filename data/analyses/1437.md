## 一句话思路
一次遍历，用 `prev` 记录上一个 1 的下标，遇到新 1 就检查 `i - prev - 1 >= k`。

## 怎么做
1. 初始化 `prev = -1`，表示还没见过 1。
2. 从左到右扫 `nums`，遇到 `nums[i] == 1` 时判断：若 `prev != -1` 且 `i - prev - 1 < k`，立即返回 `False`。
3. 检查通过后把 `prev = i`，继续扫。
4. 扫完没触发返回，说明全部满足，返回 `True`。

以示例 2 `nums = [1,0,0,1,0,1], k = 2` 为例：`i=0` 时 `prev=-1`，跳过检查，`prev` 变 0；`i=3` 时 `i - prev - 1 = 3 - 0 - 1 = 2 >= 2` 通过，`prev` 变 3；`i=5` 时 `5 - 3 - 1 = 1 < 2`，返回 `False`。关键中间值就是 `i - prev - 1`，它算的是两个 1 之间夹的 0 的个数，不是下标差。

```python
prev = -1
for i, x in enumerate(nums):
    if x == 1:
        if prev != -1 and i - prev - 1 < k:
            return False
        prev = i
return True
```

注意 `prev != -1` 这个守卫不能省：第一个 1 前面没有参照物，若直接算 `i - (-1) - 1 = i`，当 `k` 较大且第一个 1 靠左时会误判失败。比如 `nums = [1,0,1], k = 1`，`i=0` 时若不加守卫会得到 `0 < 1` 直接返回 `False`，而正确答案是 `True`。

## 复杂度
时间 O(n)：`n = len(nums)`，每个元素访问一次。
空间 O(1)：只开了 `prev` 和循环变量 `i`、`x`。

## 易错点
- `nums = [1,0,0,1], k = 2` → 若用 `i - prev < k` 判断会错成 `False`（`3 - 0 = 3` 不满足 `< 2` 其实通过，但换成 `k = 3` 就翻车：`3 < 3` 为假，误判失败）→ 正确做法是减 1，比较的是中间 0 的个数 `i - prev - 1`。
- `nums = [0,0,1], k = 5` 或 `nums = [1], k = 0` → 若把 `prev` 初始化为 0 而不是 -1，第一个 1 在 `i=2` 时会被算成 `2 - 0 - 1 = 1 < 5` 误判 `False` → 正确做法是 `prev = -1` 并加 `prev != -1` 守卫。

## 如果面试官追问
问：如果要求返回所有违规的 1 的下标对怎么办？
答：把 `return False` 换成收集 `(prev, i)` 到列表，扫完统一返回，时间仍是 O(n)。
