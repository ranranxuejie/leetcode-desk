## 一句话思路
用最小堆维护每个列表当前指针指向的值，堆顶是最小值、堆中最大值构成候选区间，弹出堆顶后推进该列表指针，扫描全部元素取最优。

## 怎么做
1. 把每个列表的首元素 `(nums[i][0], i, 0)` 压入堆，同时记录 `cur_max = max(nums[i][0])`。
2. 循环：弹出堆顶 `(v, i, j)`，用 `[v, cur_max]` 更新答案（宽度更小，或等宽且左端点更小才替换）。
3. 若 `j + 1 == len(nums[i])` 则结束（该列表已耗尽，区间不可能再覆盖全部 k 个列表）；否则压入 `(nums[i][j+1], i, j+1)` 并更新 `cur_max = max(cur_max, nums[i][j+1])`。

以示例 1 为例：初始堆顶 `v=0`（列表 2），`cur_max=5`（三个首元素 4、0、5 的最大值），候选 `[0,5]` 宽 5；弹出 0 后压入 9，`cur_max` 变 9，候选 `[4,9]` 宽 5；继续弹出 4 压入 10，`cur_max=10`，候选 `[5,10]` 宽 5……直到弹出 20 压入 26 时 `cur_max=26`，候选 `[22,26]` 宽 4 更优；再弹出 22 压入 30，`cur_max=30`，候选 `[24,30]` 宽 6 不替换；弹出 24 压入 26，`cur_max=30`，候选 `[26,30]` 宽 4 但左端点更大不替换；弹出 26 时列表 1 耗尽，结束，答案 `[20,24]`。

```python
import heapq
heap = [(nums[i][0], i, 0) for i in range(len(nums))]
heapq.heapify(heap)
cur_max = max(x[0] for x in heap)
best = [heap[0][0], cur_max]
while True:
    v, i, j = heapq.heappop(heap)
    if cur_max - v < best[1] - best[0] or (cur_max - v == best[1] - best[0] and v < best[0]):
        best = [v, cur_max]
    if j + 1 == len(nums[i]):
        break
    nxt = nums[i][j + 1]
    cur_max = max(cur_max, nxt)
    heapq.heappush(heap, (nxt, i, j + 1))
```

## 复杂度
时间：O(N log k)，N 为所有元素总数（≤175000），每次堆操作 log k，k ≤ 3500。
空间：O(k)，堆中最多 k 个元素，另存答案两个整数。

## 易错点
- 忘记在弹出后判断 `j + 1 == len(nums[i])` 就继续压入 → 某个列表耗尽后堆里只剩 k-1 个列表，区间不再覆盖全部列表却仍被当作候选 → 必须在压入前检查并 break，示例 1 中列表 1 弹出 26 时正是这个终止点。
- 更新 `cur_max` 时写成 `cur_max = nxt` → 当新压入的值小于当前最大值时（如示例 1 弹出 0 压入 9，`cur_max` 应为 9 而非 0 的旧值），区间右端点被低估，答案偏窄甚至错误 → 必须用 `max(cur_max, nxt)`。

## 如果面试官追问
问：若 k 很大而每个列表很短，堆方案还合适吗？答：仍合适，堆大小是 k，log k 增长慢；若 k 到 10^6 级别，可改用分治合并或直接对全部元素排序后滑动窗口。
