## 一句话思路
把 dig 的格子塞进哈希集合，再对每个工件枚举它最多 4 个格子，全在集合里就计数。

## 怎么做
1. 用 `dug = set(map(tuple, dig))` 把挖掘坐标转成元组集合，`tuple` 是因为列表不可哈希。
2. 遍历 `artifacts` 的每个 `[r1, c1, r2, c2]`，双重循环枚举矩形内每个格子。
3. 用 `all((r, c) in dug ...)` 判断是否全部裸露，是则 `ans += 1`。
4. 关键中间值：示例 1 中 `dug = {(0,0), (0,1)}`；工件 `[0,1,1,1]` 枚举出 `(0,1)`、`(1,1)`，`(1,1) not in dug` 使 `all` 为 `False`，不计数；工件 `[0,0,0,0]` 只有 `(0,0)` 在集合里，计数得 1。

```python
dug = set(map(tuple, dig))
ans = 0
for r1, c1, r2, c2 in artifacts:
    ok = True
    for r in range(r1, r2 + 1):
        for c in range(c1, c2 + 1):
            if (r, c) not in dug:
                ok = False
                break
        if not ok:
            break
    if ok:
        ans += 1
```

## 复杂度
时间：O(len(dig) + 4 * len(artifacts))，每个工件最多 4 格。
空间：O(len(dig))，只开了 dug 这个哈希集合。

## 易错点
- 直接把 `dig` 的列表元素丢进 `set` 会报 `TypeError: unhashable type: 'list'` → 必须 `map(tuple, dig)` 或逐个 `tuple(p)` 转换。
- 用 `r1 <= r <= r2 and c1 <= c <= c2` 去反查每个 dug 格子属于哪个工件，在 `n=1000`、`dig` 达 1e5 时会退化成 O(n²·|dig|) 超时 → 正确做法是反过来枚举工件自身的 ≤4 个格子，规模由「每工件最多 4 格」这条约束兜住。

## 如果面试官追问
若去掉「每个工件最多覆盖 4 个单元格」，只保留不重叠，怎么做？
答：仍可枚举工件格子，但总格数上界变成 n²；改用「每个工件记剩余未挖格数，遍历 dig 时对覆盖它的工件减一」需要格子→工件的映射，空间 O(n²)。
