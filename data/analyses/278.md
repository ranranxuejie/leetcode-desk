## 一句话思路
答案具有单调性（`false...false true...true`），对版本号区间二分，每次用 `isBadVersion(mid)` 收缩到第一个 `true`。

## 怎么做
1. 令 `lo = 1`、`hi = n`，搜索区间始终是「可能包含第一个错误版本」的闭区间。
2. 循环条件写 `lo < hi`，取 `mid = lo + (hi - lo) // 2`，避免 `lo + hi` 在 `n = 2**31 - 1` 时越界（Python 不会溢出，但这是通用写法）。
3. `isBadVersion(mid)` 为 `True` 时 `hi = mid`（mid 本身可能是答案，不能减 1）；为 `False` 时 `lo = mid + 1`。
4. 循环结束时 `lo == hi`，返回 `lo`。

以 `n = 5, bad = 4` 为例：初始 `lo=1, hi=5`，`mid=3`，`isBadVersion(3)=False` → `lo=4`；此时 `lo=4, hi=5`，`mid=4`，`isBadVersion(4)=True` → `hi=4`；`lo==hi==4`，返回 4。关键中间值是第二次的 `mid=4`，它把 `hi` 从 5 压到 4，而不是压到 3。

```python
lo, hi = 1, n
while lo < hi:
    mid = lo + (hi - lo) // 2
    if isBadVersion(mid):
        hi = mid
    else:
        lo = mid + 1
return lo
```

## 复杂度
时间：`O(log n)`，每次迭代把区间长度减半，最多约 31 次调用。
空间：`O(1)`，只开 `lo`、`hi`、`mid` 三个整数。

## 易错点
1. 写成 `hi = mid - 1` → 当 `mid` 恰好是第一个错误版本时，答案被排除出区间，`n=5, bad=4` 会返回 5 或死循环。正确做法是 `True` 分支只写 `hi = mid`，因为 `mid` 本身仍可能是答案。
2. 循环条件写成 `lo <= hi` 且返回 `lo` → 区间收缩到 `lo == hi` 后还会再进一次，`mid` 重复计算，若分支写错会死循环；本题只需 `lo < hi`，退出时 `lo` 就是答案，不需要额外判断。

## 如果面试官追问
问：如果 `isBadVersion` 调用很贵，能否再减少次数？
答：二分已是 `O(log n)` 下界，只能靠减少常数，比如先判 `isBadVersion(1)` 和 `isBadVersion(n)` 处理全错/全对边界，主体仍是二分。
