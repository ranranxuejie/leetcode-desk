## 一句话思路
按行、按列各做一次下标映射即可，因为行移位只改列号、列移位只改行号，两次操作互不干扰。

## 怎么做
1. 先建 `tmp`，把 `grid[i][j]` 放到 `tmp[i][(j - rowShift[i]) % n]`，完成所有行移位。
2. 再建 `res`，把 `tmp[i][j]` 放到 `res[(i - colShift[j]) % n][j]`，完成所有列移位。
3. 用示例 2 验证：`rowShift[1]=2`，`grid[1]=[4,5,6]` 左移 2 位后 `tmp[1]=[6,4,5]`；接着 `colShift[0]=2`，`tmp[0][0]=3` 上移 2 行落到 `res[1][0]`，与输出 `[[7,8,5],[2,3,9],[6,4,1]]` 一致。

```python
n = len(grid)
tmp = [[0] * n for _ in range(n)]
for i in range(n):
    for j in range(n):
        tmp[i][(j - rowShift[i]) % n] = grid[i][j]

res = [[0] * n for _ in range(n)]
for i in range(n):
    for j in range(n):
        res[(i - colShift[j]) % n][j] = tmp[i][j]
```

关键点：`(j - rowShift[i]) % n` 是「原位置 j 的元素去往新列」，不是「新列 j 取哪个旧元素」；后者要写成 `(j + rowShift[i]) % n`，方向反了结果就错。

## 复杂度
时间：O(n²)，两轮各遍历 n×n 个格子，与移位量无关。
空间：O(n²)，额外开了 `tmp` 和 `res` 两个 n×n 矩阵。

## 易错点
- 把行移位写成 `grid[i][(j + rowShift[i]) % n] = ...`：示例 1 中 `rowShift[0]=1`，`grid[0]=[1,2]` 会变成 `[2,1]` 而不是正确的 `[2,1]` 方向对但语义错，遇到 `rowShift[0]=0` 的行才暴露；正确做法是固定「原位置 j 的元素搬到 `(j - k) % n`」。
- 先做列移位再做行移位：示例 2 中先上移会让 `tmp[0][0]` 变成 7，再左移第 0 行得 `[8,5,7]`，与答案 `[7,8,5]` 不符；必须严格按题面顺序，行在前列在后。

## 如果面试官追问
若 n 放大到 10⁵ 且只给稀疏移位，怎么办？答：只处理 `rowShift[i] != 0` 或 `colShift[j] != 0` 的行列，其余整行整列直接拷贝，复杂度降到 O(n²) 但常数更小。
