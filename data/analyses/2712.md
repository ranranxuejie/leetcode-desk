## 一句话思路
逐位扫描相邻字符，不同就累加 `min(i, n-i)`，因为每个「断点」只能由覆盖它的前缀/后缀翻转单独消除。

## 怎么做
1. 从左到右遍历 `i = 1..n-1`，只看 `s[i] != s[i-1]` 的位置。
2. 对每个断点，取 `min(i, n-i)` 累加进 `ans`：`i` 是翻转前缀 `[0, i-1]` 的成本，`n-i` 是翻转后缀 `[i, n-1]` 的成本。
3. 返回 `ans`。

以 `s = "0011"`、`n = 4` 为例：`i=1` 时 `s[1]='0'==s[0]` 跳过；`i=2` 时 `s[2]='1' != s[1]='0'`，累加 `min(2, 4-2)=2`；`i=3` 时 `s[3]='1'==s[2]` 跳过。`ans=2`，与示例一致。

再验 `s = "010101"`、`n = 6`：断点在 `i=1,2,3,4,5`，各自 `min` 为 `1,2,3,2,1`，和 `=9`，与示例一致。

```python
ans = 0
n = len(s)
for i in range(1, n):
    if s[i] != s[i - 1]:
        ans += min(i, n - i)
return ans
```

关键点：翻转前缀 `[0, i-1]` 只改变 `s[i-1]` 与 `s[i]` 之间的相邻关系，不影响其他断点，所以每个断点独立计价、成本可加。

## 复杂度
时间：O(n)，一次线性扫描，每个下标只比较一次。
空间：O(1)，只用了 `ans`、`n`、`i` 三个标量。

## 易错点
- 把断点成本写成 `min(i+1, n-i)` 或 `min(i, n-i+1)` → `"0011"` 会得 3 而非 2 → 前缀翻转 `[0,i-1]` 长度是 `i`、后缀 `[i,n-1]` 长度是 `n-i`，下标从 0 起时就是 `min(i, n-i)`。
- 误以为要模拟翻转、或对每个断点贪心选同一侧 → `"010101"` 会算成 15（全用前缀）→ 每个断点独立取 `min`，两侧混用才是 9。

## 如果面试官追问
问：若要求输出具体操作序列怎么办？
答：按断点从左到右处理，选 `i <= n-i` 就翻前缀 `[0,i-1]`，否则翻后缀 `[i,n-1]`，记录 `(类型, i)` 即可，总成本不变。
