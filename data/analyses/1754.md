## 一句话思路
每步比较两个剩余串的字典序，取较大者的首字符，用后缀比较代替逐字符模拟。

## 怎么做
1. 用两个指针 `i`、`j` 指向 `word1`、`word2` 当前首字符，结果存 `res`。
2. 每步比较 `word1[i:]` 与 `word2[j:]` 的字典序，谁大就取谁的首字符。
3. 相等时取任意一边都行（后缀相同，后续结果一致），代码里取 `word1` 侧。
4. 一边耗尽后把另一边剩余部分整体拼上。

以 `word1="cabaa"`、`word2="bcaaa"` 为例：`i=0,j=0` 时 `"cabaa" > "bcaaa"`，取 `'c'`；接着 `"abaa" < "bcaaa"`，取 `'b'`；再 `"abaa" < "caaa"`，取 `'c'`；此时 `"abaa" > "aaa"`，取 `'a'`、`'b'`，最后剩 `"aa"` 与 `"aaa"` 全为 `a`，拼出 `"cbcabaaaaa"`。

```python
i = j = 0
res = []
while i < len(word1) and j < len(word2):
    if word1[i:] > word2[j:]:
        res.append(word1[i]); i += 1
    else:
        res.append(word2[j]); j += 1
res.append(word1[i:])
res.append(word2[j:])
return "".join(res)
```

关键点：比较的是**整个剩余后缀**而非单个字符。示例 2 中 `word1="abcabc"`、`word2="abdcaba"`，前两位 `a`、`b` 相同，第三位 `c < d`，所以取 `word2` 的 `'d'` 而非 `word1` 的 `'c'`，这正是逐字符贪心会翻车的地方。

## 复杂度
时间：每步切片比较最坏 O(n+m)，共 O((n+m)^2)，n、m 为两串长度。
空间：`res` 与切片临时串共 O(n+m)，无额外结构。

## 易错点
- 输入 `word1="abcabc"`、`word2="abdcaba"` → 若只比首字符 `'a'=='a'` 就随便取 `word1`，会错成 `"abcabcabdcaba"` 这类较小结果 → 必须比较完整后缀 `"abcabc"` 与 `"abdcaba"`，第三位 `c<d` 才取 `word2`。
- 输入 `word1="a"`、`word2="aa"` → 若相等时固定取 `word2` 首字符，得到 `"aaa"` 看似没问题，但换成 `word1="ab"`、`word2="a"` 时相等判断若写成 `>=` 取 `word1` 会先耗光 `word1` 再拼 `word2`，结果 `"aba"` 正确；真正坑是相等时误判为「必须取较长串」，应直接取任一侧，后缀相同不影响结果。

## 如果面试官追问
问：能否做到 O(n+m)？答：把两串拼成 `word1+'{'+word2` 求后缀数组，按 rank 比较后缀，整体线性对数级。
