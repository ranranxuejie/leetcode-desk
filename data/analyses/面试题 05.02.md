## 一句话思路
反复乘 2 取整数位，取满 32 位（含 "0."）仍不为 0 就输出 ERROR。

## 怎么做
1. 结果串先放 `"0."`，循环上限设为 30 次小数位（加上 `"0."` 正好 32 位）。
2. 每轮 `num *= 2`，若 `num >= 1` 就追加 `'1'` 并 `num -= 1`，否则追加 `'0'`。
3. 每轮结束若 `num == 0` 立即返回当前串，说明已精确表示。
4. 循环跑完仍未归零，返回 `"ERROR"`。

以 `0.625` 为例：第 1 轮 `0.625*2 = 1.25`，取 `'1'` 后 `num = 0.25`；第 2 轮 `0.5` 取 `'0'`；第 3 轮 `1.0` 取 `'1'` 后 `num = 0.0`，返回 `"0.101"`。关键中间值是第 1 轮减完 1 后的 `0.25`，它决定了后面两位。

```python
res = "0."
for _ in range(30):
    num *= 2
    if num >= 1:
        res += '1'
        num -= 1
    else:
        res += '0'
    if num == 0:
        return res
return "ERROR"
```

注意判断顺序：先乘 2 再比较，不能先比较再乘。`0.1` 走 30 轮永远不归零，因为它在二进制里是无限循环小数，直接落到 `"ERROR"`。

## 复杂度
时间 O(1)：固定最多 30 轮，与输入值无关。
空间 O(1)：只开了一个长度 ≤ 32 的结果串。

## 易错点
- 循环写成 32 次 → `0.625` 这类能精确表示的数也会在归零后继续追加 `'0'`，输出变成 `"0.101000..."`；正确做法是每轮末尾判 `num == 0` 就提前返回，上限只用来兜底。
- 用 `num > 0` 当循环条件 → `0.1` 永远为真，死循环；必须用固定次数 `range(30)` 封顶，因为浮点残差不会自己变成 0。

## 如果面试官追问
问：输入保证最多 6 位小数，能不能提前判 ERROR？
答：不能，6 位十进制小数里 `0.5`、`0.625` 可精确表示，`0.1` 不行，仍得靠乘 2 归零判断。
