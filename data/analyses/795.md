## 一句话思路
用「最大元素 ≤ right 的子数组数」减去「最大元素 ≤ left-1 的子数组数」，两次单指针扫描即可。

## 怎么做
1. 定义 `count(bound)`：统计所有元素都 ≤ `bound` 的连续子数组个数，用单指针 `i` 扫一遍，维护当前连续合法段的长度 `cur`。
2. 每遇到 `nums[i] <= bound`，`cur += 1`，否则 `cur = 0`；把 `cur` 累加进答案，因为以 `i` 结尾的合法子数组恰好有 `cur` 个。
3. 答案 = `count(right) - count(left - 1)`，差值正好是「最大值落在 [left, right]」的那些子数组。

以 `nums = [2,1,4,3], left = 2, right = 3` 为例：`count(3)` 扫到 4 时 `cur` 归零，累计得 1+2+0+1 = 4；`count(1)` 只有 1 合法，累计得 0+1+0+0 = 1；相减 4-1 = 3，与示例一致。

```python
def count(bound):
    cur = total = 0
    for x in nums:
        cur = cur + 1 if x <= bound else 0
        total += cur
    return total

return count(right) - count(left - 1)
```

关键点：`left - 1` 而不是 `left`，因为要排除最大值严格小于 `left` 的子数组；当 `left = 0` 时 `count(-1)` 自然返回 0，无需特判。

## 复杂度
时间：O(n)，两次线性扫描，n 为 `nums` 长度。
空间：O(1)，只开了 `cur`、`total` 两个计数器。

## 易错点
- `nums = [2,1,4,3], left = 2`：若写成 `count(right) - count(left)`，会把最大值恰为 1 的子数组 `[1]` 漏减，答案错成 4；正确是减 `count(left - 1)`。
- `nums = [5,5,5], left = 0, right = 4`：若在 `count` 里对 `bound < 0` 不做处理而直接比较，逻辑上仍返回 0，但若改成「先过滤再计数」的写法容易越界或漏判；统一用 `x <= bound` 比较即可，`bound = -1` 时自然全不合法。

## 如果面试官追问
问：要求输出所有满足条件的子数组而非计数？
答：仍用同一分段思路，对每个 `i` 枚举起点 `i-cur+1..i` 输出，复杂度升到 O(答案规模)。
