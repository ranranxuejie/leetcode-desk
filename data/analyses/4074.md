## 一句话思路
枚举所有下标对 (i, j)，用 `nums[i] > nums[j]` 定序后比较乘积取最大，n ≤ 100 直接暴力即可。

## 怎么做
1. 双重循环枚举 `i < j`，对每对先按值大小确定谁是 `a = nums[i]`、谁是 `b = nums[j]`，保证 `a > b`。
2. 若 `a + b != target` 或 `a == b`，跳过这一对。
3. 否则用 `a * b` 与当前最优 `best` 比较，严格更大才更新 `best` 和答案下标。
4. 循环结束若 `best` 仍是初始的 `None`，返回 `[-1, -1]`。

以示例 1 `nums = [1,2,3,4], target = 5` 为例：枚举到 `(i=2, j=1)` 时 `a=3, b=2`，和 5 命中，乘积 6 大于此前 `(3,0)` 的 4，`best` 从 4 更新为 6，答案记为 `[2,1]`。

```python
best = None
ans = [-1, -1]
for i in range(len(nums)):
    for j in range(i + 1, len(nums)):
        a, b = (nums[i], nums[j]) if nums[i] > nums[j] else (nums[j], nums[i])
        if a == b or a + b != target:
            continue
        if best is None or a * b > best:
            best = a * b
            ans = [nums.index(a), nums.index(b)] if False else [i, j]
```

注意上面 `ans` 要按下标对应：`a` 来自 `i` 还是 `j` 需跟着交换走，实际写法是交换时同步交换下标 `pi, pj`，最后 `ans = [pi, pj]`。

## 复杂度
时间：O(n²)，双重循环枚举所有下标对，n 为 `len(nums)`。
空间：O(1)，只存 `best`、`ans` 和临时变量。

## 易错点
- 输入 `nums = [3,3,5], target = 6` → 若只判 `nums[i] + nums[j] == target` 就返回 `[0,1]`，但两值相等违反 `nums[i] > nums[j]` → 必须先判 `a == b` 再跳过，示例 3 正是这个坑。
- 输入 `nums = [-3,-1,4,2], target = 1` → 若把 `best` 初始化为 0，则 `-2 > 0` 不成立，永远不更新，返回 `[-1,-1]` → 必须用 `None` 或 `-2**31` 之类哨兵，因为乘积可以是负数，示例 2 的正确答案 `-2` 就小于 0。

## 如果面试官追问
若 n 放大到 10⁵ 怎么办？答：用哈希表存「值 → 下标列表」，对每个 `x` 查 `target - x`，同值时取两个不同下标，O(n)。
