## 一句话思路
把每个 4 位数字串当图节点、一次拨动当边，从 `"0000"` 做 BFS，第一次弹出 `target` 时的层数就是最小步数。

## 怎么做
1. 先把 `deadends` 转成 `set`，BFS 起点 `"0000"` 若在集合里直接返回 -1。
2. 队列存 `(状态, 步数)`，`visited` 初始含 `"0000"`，出队时判断是否等于 `target`。
3. 对每个状态枚举 4 个位置 × 上下两个方向，共 8 个邻居；用 `(int(ch) ± 1) % 10` 生成新位，拼回字符串。
4. 邻居不在 `visited` 也不在 `dead` 里才入队并标记。

以示例 1 为例，第 0 层是 `"0000"`；第 1 层出 `"1000"`、`"9000"`、`"0100"`…；到第 3 层会出 `"1200"`，它的邻居里有 `"1201"`、`"1202"`，`"1202"` 再拨第一位得 `"0202"`，累计 6 步。注意 `"0102"` 在 `dead` 里，所以那条 4 步路径被剪掉。

```python
from collections import deque

dead = set(deadends)
if "0000" in dead:
    return -1
q = deque([("0000", 0)])
seen = {"0000"}
while q:
    cur, d = q.popleft()
    if cur == target:
        return d
    for i in range(4):
        for delta in (1, -1):
            nxt = cur[:i] + str((int(cur[i]) + delta) % 10) + cur[i+1:]
            if nxt not in seen and nxt not in dead:
                seen.add(nxt)
                q.append((nxt, d + 1))
return -1
```

## 复杂度
时间 O(10^4 × 8)，最多 10000 个状态、每个状态 8 条边，与 `deadends` 长度无关。
空间 O(10^4)，`seen` 和队列各最多存一万个 4 字符串。

## 易错点
- `deadends` 含 `"0000"`（如 `["0000"]`）→ 若先入队再判死，会返回 0 或继续搜 → 必须在建队前判 `"0000" in dead` 返回 -1。
- 示例 3 的 `"8888"` 被 8 个死锁数字围死 → 若把 `dead` 判断放在出队时而非入队时，会把死状态塞进队列、白跑一层甚至误判可达 → 入队前就过滤 `nxt not in dead`。

## 如果面试官追问
要求输出具体旋转序列怎么办？在队列里存 `(状态, 路径列表)` 或记录 `parent` 字典，弹出 `target` 时回溯即可，代价是空间从 O(状态数) 涨到 O(状态数 × 路径长)。
