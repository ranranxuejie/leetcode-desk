## 一句话思路
对每个查询做一次从 u 出发的 DFS，看能否沿先修边走到 v；numCourses≤100、queries≤10^4，单次 O(V+E) 足够。

## 怎么做
1. 把 `prerequisites` 建成邻接表 `g[a].append(b)`，方向是 a→b，表示 a 是 b 的先修。
2. 对每个查询 `[u, v]`，从 u 出发 DFS，只沿 `g` 的边往下走。
3. DFS 里一旦碰到 `v` 就返回 `True`，走完所有可达点还没碰到就返回 `False`。
4. 用 `visited` 数组防止重复访问（图无环，但同一层可能多条边指向同一点）。

以示例 3 为例：`prerequisites = [[1,2],[1,0],[2,0]]`，建出 `g[1]=[2,0]`、`g[2]=[0]`。查询 `[1,0]` 时从 1 出发，先访问 2，再从 2 访问到 0，命中，返回 `True`；查询 `[1,2]` 时第一步就走到 2，返回 `True`。

```python
def dfs(u, v, seen):
    if u == v:
        return True
    seen[u] = True
    for w in g[u]:
        if not seen[w] and dfs(w, v, seen):
            return True
    return False

ans = []
for u, v in queries:
    ans.append(dfs(u, v, [False] * numCourses))
```

注意 `u == v` 的判断放在最前面，但题面保证 `u != v`，所以实际不会触发；真正起作用的是 `seen` 剪枝。

## 复杂度
时间：每个查询 O(V+E)，共 O(Q·(V+E))，V=numCourses、E=len(prerequisites)、Q=len(queries)。
空间：`g` 占 O(V+E)，每次查询的 `seen` 占 O(V)，递归栈最深 O(V)。

## 易错点
1. 边方向写反：把 `[a,b]` 建成 `g[b].append(a)`，示例 1 查询 `[1,0]` 会从 1 出发找不到 0，输出 `[false,false]` 而非 `[false,true]`。正确做法是 `g[a].append(b)`，因为 a 是 b 的先修，边从先修指向后继。
2. 忘记 `seen` 或把 `seen` 在查询间复用：示例 3 中 1→2→0 和 1→0 两条路径都到 0，没有 `seen` 会重复展开；若把同一个 `seen` 数组跨查询复用，第二个查询 `[1,2]` 会因为 1 已被标记而直接返回 `False`。正确做法是每个查询新建 `[False]*numCourses`。

## 如果面试官追问
问：queries 涨到 10^6 怎么办？答：先对全图做一次传递闭包（Floyd 或对每个点 BFS 预计算 `reach[u][v]`），之后每个查询 O(1)，总代价 O(V·(V+E)+Q)。
