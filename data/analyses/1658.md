## 一句话思路
把「两端删到剩 x」翻成「中间留一段连续子数组，和为 total−x」，求最长的那段，答案就是 n 减它。

## 怎么做
1. 先算 `total = sum(nums)`，`target = total - x`；若 `target < 0` 直接返回 -1（全删光也不够）。
2. 问题变成：在 nums 里找**和恰好为 target 的最长连续子数组**，长度记 `best`。
3. 用滑动窗口：`left` 不动、`right` 右移累加 `cur`，`cur > target` 时收缩 `left`；`cur == target` 时更新 `best = max(best, right - left + 1)`。
4. 返回 `n - best`（`best` 初值 0，即 target 为 0 时一个都不留，答案 n）。

拿示例 3 走一遍：`nums = [3,2,20,1,1,3]`，`total = 30`，`target = 20`。窗口滑到 `nums[2] = 20` 时 `cur == 20`、长度 1，`best = 1`，答案 `6 - 1 = 5`，与官方一致。

```python
n = len(nums)
target = sum(nums) - x
if target < 0:
    return -1
left = cur = best = 0
for right, v in enumerate(nums):
    cur += v
    while cur > target:
        cur -= nums[left]
        left += 1
    if cur == target:
        best = max(best, right - left + 1)
return n - best
```

关键点：`while cur > target` 而不是 `if`，因为 `nums` 里可能有 0 或正数收缩一次不够；本题元素均为正，窗口单调，`left` 只增不减。

## 复杂度
时间 O(n)：`right` 走 n 步，`left` 总共最多走 n 步。
空间 O(1)：只开了 `left`、`cur`、`best` 几个标量。

## 易错点
- `nums = [5,6,7,8,9], x = 4` → 若不加 `target < 0` 判断，`target = 31`，窗口永远凑不出，返回 `5 - 0 = 5`，错成「删 5 次」；正确是先判 `target < 0` 返回 -1。
- `nums = [1,1,1], x = 3` → `target = 0`，若把 `best` 初始化成 -1 或漏掉 `cur == target` 的 0 长度情形，会返回 4 或 -1；正确是 `best = 0`，答案 `3 - 0 = 3`（全删）。

## 如果面试官追问
问：若 nums 含负数怎么办？
答：滑动窗口失效，改用前缀和 + 哈希表存「前缀和 → 最早下标」，对每个右端点查 `pre - target`，O(n) 时间 O(n) 空间。
