## 一句话思路
把每条线段拆成 `(start, +color)` 和 `(end, -color)` 两个事件，按坐标排序后扫描，相邻坐标之间颜色和不变，和变化处切段。

## 怎么做
1. 对每个 `[s, e, c]` 生成两个事件 `(s, c)` 和 `(e, -c)`，放进同一个列表。
2. 按坐标排序；同一坐标的事件必须一起处理完再切段，否则会把 `[1,4)` 和 `[4,7)` 错误合并。
3. 扫描时维护 `cur`（当前颜色和）和 `prev`（上一个坐标），每处理完一个坐标 `x`，若 `cur != 0` 就输出 `[prev, x, cur]`。
4. 更新 `prev = x`，继续。

以示例 1 `[[1,4,5],[4,7,7],[1,7,9]]` 为例：事件排序后为 `(1,+5),(1,+9),(4,-5),(4,+7),(7,-7),(7,-9)`。处理完坐标 1 后 `cur=14`，处理完坐标 4 后 `cur=16`，于是切出 `[1,4,14]` 和 `[4,7,16]`。

```python
events = []
for s, e, c in segments:
    events.append((s, c))
    events.append((e, -c))
events.sort()
res, cur, prev, i = [], 0, 0, 0
while i < len(events):
    x = events[i][0]
    if cur != 0 and prev != x:
        res.append([prev, x, cur])
    while i < len(events) and events[i][0] == x:
        cur += events[i][1]
        i += 1
    prev = x
```

## 复杂度
时间：O(n log n)，n 是事件数 2×len(segments)，排序贡献 log n，扫描 O(n)。
空间：O(n)，events 列表存 2n 个元组，结果数组最坏 O(n)。

## 易错点
- 同一坐标有多个事件时逐个切段 → 示例 1 在坐标 4 会先看到 `cur=14` 就输出 `[1,4,14]`，再看到 `cur=16` 又输出 `[4,4,16]`，产生零长度段。正确做法是内层 while 把同坐标事件全部累加完，再统一判断 `cur != 0`。
- 忘记跳过 `cur == 0` 的区间 → 示例 2 中 `[7,8)` 之后若某段无颜色覆盖，会输出 `mix=0` 的伪线段。正确做法是切段前判断 `cur != 0`，因为题目要求未被涂色的部分不出现。

## 如果面试官追问
若坐标范围扩大到 10^9 且 segments 只有 2×10^4，排序事件仍可行吗？答：可行，复杂度只依赖事件数 2n，与坐标绝对值无关，无需开数组做差分。
