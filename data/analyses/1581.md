## 一句话思路
用 `Visits` 左连接 `Transactions`，筛出 `transaction_id` 为 `None` 的行，再按 `customer_id` 分组计数。

## 怎么做
1. 以 `Visits` 为主表 `LEFT JOIN Transactions`，连接键是 `visit_id`，保证没交易的访问也留下。
2. 用 `WHERE t.transaction_id IS NULL` 只保留没产生交易的访问记录。
3. 按 `customer_id` 分组，`COUNT(*)` 得到该顾客无交易次数，别名 `count_no_trans`。

拿官方示例走一遍：`Visits` 里 `visit_id=5`（顾客 54）在 `Transactions` 中有 3 条记录，连接后 `transaction_id` 非空，被过滤掉；而 `visit_id=7`、`8`（同为顾客 54）在 `Transactions` 中查不到，连接后 `transaction_id` 为 `None`，保留下来。所以顾客 54 的计数是 2，不是 3——**数的是无交易的 visit_id 个数，不是顾客访问总次数**。顾客 30（`visit_id=4`）、96（`visit_id=6`）各保留 1 行，计数为 1。

```python
# 关键逻辑（伪 SQL 转 pandas 思路）
merged = visits.merge(transactions, on="visit_id", how="left")
no_trans = merged[merged["transaction_id"].isna()]
result = (no_trans.groupby("customer_id")
          .size()
          .reset_index(name="count_no_trans"))
```

若用 SQL 写：

```sql
SELECT v.customer_id, COUNT(*) AS count_no_trans
FROM Visits v
LEFT JOIN Transactions t ON v.visit_id = t.visit_id
WHERE t.transaction_id IS NULL
GROUP BY v.customer_id;
```

## 复杂度
时间：O(V + T)，V 为 `Visits` 行数、T 为 `Transactions` 行数，连接与分组各扫一遍。
空间：O(V)，左连接后中间结果最多 V 行，分组哈希表最多存不同 `customer_id` 个数。

## 易错点
1. 用 `INNER JOIN` 代替 `LEFT JOIN` → 顾客 30、96 这类从未交易的访问会被直接丢掉，输出只剩 54，漏掉两个计数为 1 的顾客。正确做法是以 `Visits` 为左表，保证无交易访问保留。
2. 用 `COUNT(t.transaction_id)` 或对 `Transactions` 先 `GROUP BY` 再连接 → 顾客 54 的 `visit_id=5` 有 3 条交易，会被算成 3 次访问而非 1 次，或计数变成 0。正确做法是 `COUNT(*)` 数保留下的 `Visits` 行，且过滤条件必须在连接之后。

## 如果面试官追问
问：如果要求同时输出有交易的顾客及其交易次数怎么办？
答：把 `LEFT JOIN` 改成 `FULL OUTER JOIN`，用 `CASE WHEN t.transaction_id IS NULL` 区分两类计数，一次分组出两列。
