## 一句话思路
按身高升序、同身高体重降序排序后，对体重求最长严格递增子序列，避免同身高被叠。

## 怎么做
1. 把 `(height[i], weight[i])` 配对成列表，按身高升序排；身高相同时按体重**降序**排。
2. 排序后问题变成在体重序列上求最长严格递增子序列（LIS）。
3. 用 `tails` 数组维护每个长度递增子序列的最小结尾体重，二分查找插入位置。

以官方示例为例，排序后体重序列为 `[90,95,100,110,150,190]`（身高各不相同，无需降序处理）。逐个处理：`tails` 依次变为 `[90]`、`[90,95]`、`[90,95,100]`……最终长度 6。

同身高降序的关键：若 `height=[1,1]`、`weight=[2,3]`，升序排体重为 `[2,3]`，LIS 会错误得到 2；降序排成 `[3,2]`，LIS 只能取 1，正确。

```python
pairs = sorted(zip(height, weight), key=lambda p: (p[0], -p[1]))
tails = []
for _, w in pairs:
    i = bisect_left(tails, w)
    if i == len(tails):
        tails.append(w)
    else:
        tails[i] = w
return len(tails)
```

`bisect_left` 保证严格递增：遇到相等体重时替换原位置而非追加，同体重不会被叠。

## 复杂度
时间：排序 O(n log n) + 每个元素二分 O(log n)，共 O(n log n)。
空间：`pairs` 和 `tails` 各 O(n) 额外空间。

## 易错点
- 同身高体重升序排 → `height=[1,1], weight=[2,3]` 会错得 2，实际只能叠 1 人。正确做法是排序键用 `(p[0], -p[1])`，让同身高的人体重递减，LIS 自然只取一个。
- 用 `bisect_right` 代替 `bisect_left` → 体重有重复时（如 `weight=[90,90]`）会把相等体重也算进递增序列，得到错误长度。正确做法是用 `bisect_left`，相等时替换而非追加，保证严格递增。

## 如果面试官追问
要求输出具体叠塔方案而非长度？答：`tails` 只存值不存下标，需额外维护 `prev` 数组记录每个元素的前驱下标，LIS 结束后从末尾回溯重建序列。
