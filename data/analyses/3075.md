## 一句话思路
降序排序后取前 k 个，第 i 个（从 0 计）实际贡献 `happiness[i] - i`，负数截为 0，累加即最优。

## 怎么做
1. 把 `happiness` 降序排序，让大的先被选，因为每轮所有未选者都减 1，先选大的损失最小。
2. 第 i 轮（i 从 0 开始）选中排序后第 i 个孩子时，它已被前面 i 轮各减 1，实际值是 `happiness[i] - i`。
3. 该值若 ≤ 0 就贡献 0（题面规定幸福值不减到负数），否则累加；一旦出现 ≤ 0 可直接 break，因为后面只会更小。

以 `happiness = [1,2,3], k = 2` 为例：降序得 `[3,2,1]`。i=0 取 `3-0=3`，i=1 取 `2-1=1`，和 `4`。注意第二个孩子原始值是 2，不是示例里说的 1——示例描述的是"选完 3 之后剩余变 [0,1]"的视角，等价结果一致。

```python
h = sorted(happiness, reverse=True)
ans = 0
for i in range(k):
    v = h[i] - i
    if v <= 0:
        break
    ans += v
return ans
```

关键点：`break` 不是优化而是正确性保障——`h[i] - i` 随 i 单调不增，后面全非正。

## 复杂度
时间：排序 `O(n log n)`，遍历 `O(k)`，n 来自数组长度。
空间：排序额外 `O(n)`（Python `sorted` 复制一份），其余 `O(1)`。

## 易错点
- 输入 `happiness = [1,1,1,1], k = 2` → 若写成 `h[i] - i` 不判负，会得 `1 + 0 = 1` 正确，但若输入 `[1,1], k = 2` 且不 break，第二个算出 `1-1=0` 仍对；真正翻车是 `[1], k=1` 之外的 `[2,2,2], k=3`：i=2 得 `2-2=0`，若误写成 `max(0, ...)` 之外的减法后仍加负值（如 `[1,1,1], k=3` 得 `1+0-1=0`）→ 正确做法是 `v <= 0` 时 break 或跳过。
- 输入 `happiness = [2,3,4,5], k = 1` → 若升序排序取末尾虽也对，但若误取 `h[0]` 得 2 → 必须 `reverse=True` 降序，保证先选最大值 5。

## 如果面试官追问
要求输出具体选了哪些孩子（下标）怎么办？
答：排序时保留 `(值, 原下标)` 对，按同样规则累加并记录被选下标即可，复杂度不变。
