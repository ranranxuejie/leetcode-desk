## 一句话思路
按开始时间排序后合并重叠区间，用总天数减去被会议覆盖的天数。

## 怎么做
1. 把 `meetings` 按 `start` 升序排序，保证重叠区间相邻。
2. 维护当前合并区间 `[cur_start, cur_end]`，初始为排序后第一个会议。
3. 遍历后续会议：若 `start <= cur_end + 1` 则合并（`cur_end = max(cur_end, end)`），否则结算当前区间长度并开启新区间。
4. 遍历结束后结算最后一个区间，用 `days` 减去总覆盖天数。

以示例 1 为例：排序后为 `[[1,3],[5,7],[9,10]]`。处理 `[5,7]` 时 `5 > 3+1`，结算 `[1,3]` 长度 3，`cur` 变为 `[5,7]`；处理 `[9,10]` 时 `9 > 7+1`，结算长度 3；最后结算 `[9,10]` 长度 2。总覆盖 8，`10-8=2`。

```python
meetings.sort()
covered = 0
cur_start, cur_end = meetings[0]
for start, end in meetings[1:]:
    if start <= cur_end + 1:
        cur_end = max(cur_end, end)
    else:
        covered += cur_end - cur_start + 1
        cur_start, cur_end = start, end
covered += cur_end - cur_start + 1
return days - covered
```

注意 `cur_end + 1` 这个判断：`[1,3]` 和 `[4,5]` 相邻但不重叠，合并后长度仍是 5，结果不变，所以用 `+1` 或不用都对；但用 `+1` 能减少区间数量，逻辑更统一。

## 复杂度
时间：排序 O(n log n)，遍历 O(n)，n 为会议数。
空间：排序额外 O(log n) 栈空间，其余 O(1)。

## 易错点
- 输入 `meetings = [[2,4],[1,3]]` → 不排序直接遍历会把 `[2,4]` 和 `[1,3]` 当成两个独立区间，覆盖算成 6 天 → 必须先按 `start` 排序，合并后才是 `[1,4]` 共 4 天。
- 输入 `meetings = [[1,3],[2,5]]` → 合并时只写 `cur_end = end` 而不取 `max`，遇到 `[2,3]` 这种被包含的区间会把 `cur_end` 从 5 缩回 3 → 必须用 `cur_end = max(cur_end, end)`。

## 如果面试官追问
若 `days` 缩小到 10^5 且要求输出具体哪些天可工作，怎么办？
答：用差分数组 `diff[start] += 1, diff[end+1] -= 1`，前缀和为 0 的天即可工作，O(days + n)。
