## 一句话思路
用哈希表存「父 → 有序子女列表」和死亡集合，getInheritanceOrder 时对国王做前序 DFS，跳过死亡者。

## 怎么做
1. `children` 用 `defaultdict(list)`，`birth(parent, child)` 直接 `children[parent].append(child)`，append 顺序天然就是出生顺序即长幼顺序。
2. `death(name)` 只往 `dead` 集合里加名字，不动树结构——题面明确死亡不影响 Successor。
3. `getInheritanceOrder()` 从国王开始前序 DFS：先判自己是否在 `dead` 里决定加不加，再按 `children[x]` 顺序递归。
4. 用官方示例验证：`children["king"] = ["andy","bob","catherine"]`，`children["bob"] = ["alex","asha"]`；`death("bob")` 后 `dead = {"bob"}`，DFS 走到 bob 时跳过它本身，但仍继续递归 alex、asha，所以输出里 bob 消失而 alex、asha 保留。

```python
def dfs(x):
    if x not in dead:
        order.append(x)
    for c in children[x]:
        dfs(c)

order = []
dfs(king)
return order
```

关键中间值：DFS 进入 `bob` 时 `x not in dead` 为 `False`，不 append，但 `for c in children["bob"]` 仍产出 `alex`、`asha`，这正是「死亡不影响继承顺序」的落点。

## 复杂度
时间：birth/death 均摊 O(1)；getInheritanceOrder 为 O(n)，n 是总人数。
空间：children 存 n-1 条边加 dead 集合，共 O(n)。

## 易错点
- 把 `death` 写成从 `children[parent]` 里删掉该人 → 他的子孙会整棵子树丢失，示例中删 bob 会连 alex、asha 一起消失；正确做法是只标记 `dead`，DFS 时跳过输出但照常递归其子女。
- 误以为 `birth` 需要按名字排序子女 → 会打乱长幼顺序，示例中若把 catherine 排到 andy 前，输出首段就变成 king、catherine…；正确做法是依赖 append 的调用先后，绝不排序。

## 如果面试官追问
问：若 birth 允许插到已有子女中间（指定排行）怎么办？
答：子女列表改用按排行插入的链表或 `SortedList`，DFS 遍历顺序随之改变，其余逻辑不变。
