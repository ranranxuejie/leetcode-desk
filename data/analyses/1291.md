## 一句话思路
从 1 到 9 每个数字起头，逐位加 1 拼出所有顺次数，再筛出落在 `[low, high]` 内的。

## 怎么做
1. 顺次数总共只有 36 个（长度 2~9，起点 1~8），直接枚举比按区间遍历快得多。
2. 外层 `start` 取 1..8，内层 `num` 从 `start` 开始，每次 `num = num * 10 + (num % 10 + 1)` 追加下一位。
3. 每拼出一个 `num` 就判断 `low <= num <= high`，满足就 `append`。
4. 因为外层按起点、内层按长度递增，但长度优先于起点，所以最后要 `sort()`。

以 `low=100, high=300` 为例：`start=1` 时 `num` 依次变成 12、123、1234…，其中 123 落在区间内被收集；`start=2` 时得到 23、234，234 被收集；`start=3` 起 `num=34` 已小于 100 但继续拼到 345 就超过 300，后续起点同理全部落空。最终 `res=[123, 234]`，排序后不变。

```python
res = []
for start in range(1, 9):
    num = start
    while num <= high:
        if num >= low:
            res.append(num)
        last = num % 10
        if last == 9:
            break
        num = num * 10 + last + 1
res.sort()
return res
```

关键在 `last == 9` 时 `break`：`num=6789` 的下一位是 10，不是一位数字，必须停，否则会拼出 678910 这种非法值。

## 复杂度
时间 O(1)：固定枚举 36 个数，与 `low`、`high` 无关，排序也只排 ≤36 个。
空间 O(1)：`res` 最多 36 个元素，无其他额外结构。

## 易错点
- `low=10, high=10**9` → 若用 `while num <= high` 却不判 `last == 9`，`num=123456789` 会继续拼成 12345678910，超出 10 位且不是顺次数 → 正确做法是 `last == 9` 立即 `break`，因为 9 之后没有合法下一位。
- `low=1000, high=13000` → 若只按长度从 `len(str(low))` 到 `len(str(high))` 枚举而漏掉跨长度，会漏掉 12345（5 位，`high` 是 5 位但 `low` 是 4 位）→ 正确做法是外层起点 1..8、内层一直拼到 `num > high`，长度自然覆盖，不预设长度区间。

## 如果面试官追问
问：若 `high` 放大到 `10**18` 呢？答：枚举个数仍是 36 个（最长 9 位），代码不变，只是 `num` 用 Python 大整数即可，无需改逻辑。
