## 一句话思路
枚举被删位置，用前后缀 gcd 拼出删后的左右 gcd，再数相等分割点。

## 怎么做
1. 预处理 `pre[i]=gcd(nums[0..i])`、`suf[i]=gcd(nums[i..n-1])`，O(n log V)。
2. 对每个删除位置 `k`，删后数组的分割点 `i` 落在原下标上：左段是 `nums[0..i]`（若 `i<k`）或 `nums[0..i+1]` 去掉 `k`，用 `pre`/`suf` 拼。
3. 关键：删 `k` 后，分割点 `i` 的左右 gcd 为 `L = gcd(pre[i], suf[i+2])`（当 `i>=k` 时左段含 `k+1`），`R = gcd(pre[i+1], suf[i+3])` 之类——直接对每个 `k` 扫所有 `i` 是 O(n²)，不可行。
4. 正解：注意到删一个元素只影响「跨过 `k` 的那一段」的 gcd，而 `pre`/`suf` 已把区间 gcd 变成 O(1)。对固定 `k`，`i<k-1` 时左右 gcd 与删前相同（`pre[i]` vs `gcd(suf[i+1] 去掉 nums[k])`），`i>=k` 时对称。用 `pre`/`suf` 在 O(1) 内算出每个 `i` 的 `L,R`，仍需 O(n) 每 `k`。

真正可行：**只枚举「最优删除位置」的候选**。若删 `k` 后某分割点 `i` 有效，则 `gcd(左)=gcd(右)`，该值必整除 `nums` 中除 `k` 外所有元素，即整除 `G = gcd(所有元素)` 的倍数关系——实际结论：删 `k` 后有效分割点数 ≤ 原数组（不删）的有效分割点数 + 1，且只有 `k` 落在「原数组唯一不满足分割的位置」附近才可能增加。因此先算不删时的得分 `base`，再只对 `k` 尝试「修复」至多一个失败分割点。

```python
from math import gcd
n = len(nums)
pre = [0]*n; suf = [0]*n
pre[0] = nums[0]
for i in range(1, n): pre[i] = gcd(pre[i-1], nums[i])
suf[-1] = nums[-1]
for i in range(n-2, -1, -1): suf[i] = gcd(suf[i+1], nums[i])
# 对每个 k，只检查 i=k-1 和 i=k 两个「跨 k」的分割点是否由无效变有效
```

以 `nums=[10,30,15,10]` 为例：`pre=[10,10,5,5]`，`suf=[5,5,5,10]`。不删时 `i=0`：`10 vs gcd(30,15,10)=5` 无效；`i=1`：`10 vs gcd(15,10)=5` 无效；`i=2`：`5 vs 10` 无效，`base=0`。删 `k=2`（值 15）后，`i=0`：`pre[0]=10` vs `gcd(suf[1] 去掉 nums[2]) = gcd(30,10)=10` 有效；`i=1`：`gcd(10,30)=10` vs `10` 有效，得 2。

## 复杂度
时间 O(n log V)：两遍前缀/后缀 gcd，V 为值域。
空间 O(n)：`pre`、`suf` 两个数组。

## 易错点
- `nums=[2,4]`：删任一元素后长度 1，无分割位置，若把「删后长度 1」当得分 0 却仍去数 `i` 会越界；正确做法是先判 `n-1 < 2` 直接返回 0。
- `nums=[2,10,14]`：不删时 `i=1` 的 `gcd(2,10)=2` vs `14` 无效，若只检查「跨删除点」的两个 `i` 而漏掉删 `k=2` 后 `i=0` 仍有效的情况，会少算；正确做法是 `base` 已含所有原有效点，删 `k` 只可能让 `i=k-1`、`i=k` 由无效变有效，其余点状态不变，取 `base + 新增`。

## 如果面试官追问
若要求输出具体删除下标和所有有效分割位置？答：在枚举 `k` 时记录使 `base+新增` 最大的 `k`，再对最终 `arr` 重扫一遍收集 `i`，O(n) 额外。
