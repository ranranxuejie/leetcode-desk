## 一句话思路
用并查集维护连通块，合并前检查两个块之间是否存在 restriction 边，有则拒绝。

## 怎么做
1. 把 restrictions 建成邻接表 `ban[x]`，记录每个点被禁止连通的点。
2. 对每个请求 `(u, v)`，先 `find` 各自根；同根直接成功（已是间接朋友）。
3. 不同根时，遍历较小块的所有成员，检查其 `ban` 中是否有节点落在另一块里，有则失败。
4. 通过则合并，并把小块成员逐个并入大块（按大小合并保证复杂度）。

以示例 3 为例，`n=5, restrictions=[[0,1],[1,2],[2,3]]`，请求 `[3,4]` 时：块 `{0,4}` 与块 `{1,3}` 要合并，遍历小块 `{0,4}`，发现 `0` 的 `ban` 含 `1`，而 `1` 在另一块中，故返回 `False`。

```python
parent = list(range(n))
size = [1] * n
ban = [[] for _ in range(n)]
for x, y in restrictions:
    ban[x].append(y)
    ban[y].append(x)

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

# 合并前检查
ru, rv = find(u), find(v)
if ru == rv:
    res.append(True)
    continue
if size[ru] > size[rv]:
    ru, rv = rv, ru
# 遍历 ru 块成员，看 ban 是否命中 rv 块
```

## 复杂度
时间：每次请求 O(小块大小)，总 O(n + m·α(n))，m 为请求数。
空间：O(n + restrictions 长度)，额外开 parent、size、ban。

## 易错点
1. 输入 `restrictions=[[0,1]]`、请求 `[0,1]` 直接相连 → 若只检查「同根」会误判成功 → 必须先查 `ban` 再合并，直接相连也受限制约束。
2. 合并时遍历大块而非小块 → 示例 3 中块 `{0,4}` 与 `{1,3}` 合并，遍历大块会漏检 `0` 的 `ban` 命中 `1` → 必须按 size 选小块遍历，否则复杂度退化且可能漏判。

## 如果面试官追问
若 n 扩大到 10^5 且 restrictions 稀疏，怎么做？答：仍用并查集，但合并检查改为遍历小块成员查 ban，靠按大小合并把总代价压到 O(n log n)。
