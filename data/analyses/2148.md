## 一句话思路
答案只取决于最小值和最大值：值严格落在 `min(nums)` 和 `max(nums)` 之间的元素才计数，用一次遍历统计。

## 怎么做
1. 先求 `lo = min(nums)`、`hi = max(nums)`，这是判断「存在严格较小/较大元素」的唯一门槛。
2. 再遍历一遍，对每个 `x` 判断 `lo < x < hi`，成立就 `ans += 1`。
3. 返回 `ans`。

以 `nums = [-3,3,3,90]` 为例：`lo = -3`、`hi = 90`。两个 `3` 都满足 `-3 < 3 < 90`，各计一次，`ans` 从 0 加到 2；`-3` 和 `90` 分别卡在两端，不满足严格不等式，跳过。结果 2，与示例一致。

关键点：判断条件是**严格**不等式，`x == lo` 或 `x == hi` 一律不计。重复值不需要去重——每个 `3` 都独立计数，所以不能先 `set(nums)` 再数。

```python
lo, hi = min(nums), max(nums)
ans = 0
for x in nums:
    if lo < x < hi:
        ans += 1
return ans
```

也可以写成一行生成器：`sum(lo < x < hi for x in nums)`，Python 的链式比较天然是严格小于，不会把端点算进去。

## 复杂度
时间：O(n)，`min`、`max` 各扫一遍，计数再扫一遍，共 3n 次比较。
空间：O(1)，只存 `lo`、`hi`、`ans` 三个变量，没有额外数组或集合。

## 易错点
- 输入 `nums = [1,1,1]` 或 `[5]` → 若用 `<=`/`>=` 判断，会把所有元素都算进去，错答 3 或 1 → 必须用 `lo < x < hi`，端点值一律排除，正确答案是 0。
- 输入 `nums = [-3,3,3,90]` → 若先 `set(nums)` 去重再计数，两个 `3` 只算一次，错答 1 → 题目统计的是元素个数不是不同值个数，重复的 `3` 要各计一次，正确答案是 2。

## 如果面试官追问
问：如果要求返回所有满足条件的元素下标列表，怎么做？
答：同样先取 `lo`、`hi`，遍历时用 `enumerate` 收集满足 `lo < x < hi` 的 `i`，时间仍是 O(n)。
