## 一句话思路
行回文和列回文互不影响，分别数出各自需要的翻转数，取较小值即可。

## 怎么做
1. 对每一行 `row`，用双指针 `l, r` 从两端向中间扫，`row[l] != row[r]` 时计数加一。
2. 对每一列同理，固定列下标 `j`，让行下标 `i` 与 `m-1-i` 配对比较。
3. 两个计数取 `min` 返回。

以示例 1 的 `grid = [[1,0,0],[0,0,0],[0,0,1]]` 为例：行方向第 0 行 `(1,0)` 不等、第 2 行 `(0,1)` 不等，`row_flips = 2`；列方向第 0 列 `(1,0)` 不等、第 2 列 `(0,1)` 不等，`col_flips = 2`，答案 2。

```python
def minFlips(self, grid):
    m, n = len(grid), len(grid[0])
    row_flips = 0
    for i in range(m):
        for l in range(n // 2):
            if grid[i][l] != grid[i][n - 1 - l]:
                row_flips += 1
    col_flips = 0
    for j in range(n):
        for i in range(m // 2):
            if grid[i][j] != grid[m - 1 - i][j]:
                col_flips += 1
    return min(row_flips, col_flips)
```

注意 `n // 2` 和 `m // 2` 的整除：奇数长度时中间那个格子自己和自己对称，永远不需要翻，所以循环上界取半长而不是 `(n+1)//2`。

## 复杂度
时间：O(m·n)，每个格子被行扫描和列扫描各访问一次。
空间：O(1)，只用了 `row_flips`、`col_flips` 两个计数器。

## 易错点
- 奇数长度行列 → 若把循环写成 `range((n + 1) // 2)`，中间格子会和自己比较，`grid[i][l] != grid[i][n-1-l]` 恒为 `False` 不会错，但多跑一次；真正会错的是误把中间格子和邻居配对，正确做法是上界严格取 `n // 2`。
- 只算了一种方向 → 比如只统计行翻转就返回，遇到示例 2 的 `[[0,1],[0,1],[0,0]]` 会输出 0（行都回文），但正确答案是 1（列方向第 0 列 `(0,0,0)` 已回文、第 1 列 `(1,1,0)` 需翻 1 次）；必须两个方向都算再取 `min`。

## 如果面试官追问
问：如果要求同时让行和列都回文呢？
答：那就不是取 min 了，得对每个四元对称组 `(i,j),(i,n-1-j),(m-1-i,j),(m-1-i,n-1-j)` 统一取值，代价是组内 0/1 少数派的数量，复杂度仍是 O(m·n)。
