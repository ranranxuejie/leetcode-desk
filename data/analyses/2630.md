## 一句话思路
用 `Map` 做缓存，键由各参数按 `===` 语义拼成，对象参数靠引用身份区分。

## 怎么做
1. 在 `memoize` 里建一个 `Map`，键是参数序列化后的字符串，值是 `fn` 的返回值。
2. 序列化时对每个参数分类：原始值用 `typeof + String(v)`，对象/函数用引用身份（`Map` 的嵌套或自增 id）。
3. 调用时先拼键查 `Map`，命中直接返回，未命中才调 `fn` 并写回。
4. 用示例 3 验证：`o` 是同一个对象，三次调用拼出的键相同，`calls` 停在 1。

关键中间值：示例 2 中 `[{},{}]` 每次都是新对象，若用 `JSON.stringify` 拼键会得到相同的 `"[{},{}]"`，导致错误命中；必须让两个不同的 `{}` 产生不同键。

```python
# 用 id() 模拟 JS 的引用身份，原始值按值比较
def memoize(getInputs, fn):
    cache = {}
    def key_of(args):
        parts = []
        for a in args:
            if isinstance(a, (int, float, str, bool)) or a is None:
                parts.append(("v", type(a).__name__, a))
            else:
                parts.append(("r", id(a)))
        return tuple(parts)
    def memoized(*args):
        k = key_of(args)
        if k not in cache:
            cache[k] = fn(*args)
        return cache[k]
    return memoized
```

## 复杂度
时间：每次调用 O(k)，k 为参数个数，拼键与哈希各一遍；总 O(n·k)。
空间：O(m·k)，m 为不同参数组合数，缓存存键和返回值。

## 易错点
- 用 `JSON.stringify(args)` 当键 → 示例 2 的三个 `[{},{}]` 全被当成同一输入，`calls` 错成 1；正确做法是对象参数取引用身份（`id` 或 `Map` 嵌套），只有原始值才按值拼。
- 把 `NaN` 或 `-0`/`0` 混为一谈 → 题面保证 `inputs[i][j] != NaN`，但 `0` 与 `-0` 在 `===` 下相等，若用 `String(v)` 拼键会得到 `"0"` 与 `"0"` 恰好一致，反而正确；真正的坑是把 `1` 和 `"1"` 拼成同一个键，需带上 `typeof` 区分。

## 如果面试官追问
问：参数是嵌套对象，怎么保证 `===` 语义？
答：只比较最外层引用，嵌套内容不展开，因为 `===` 对对象本就只看引用。
