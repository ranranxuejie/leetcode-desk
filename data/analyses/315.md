## 一句话思路
从右往左扫，用树状数组维护已见元素的排名计数，`query(rank-1)` 就是右侧更小元素个数。

## 怎么做
1. 先对 `nums` 去重排序得到 `sorted_uniq`，用 `bisect_left` 把每个值映射成 1 起始的排名 `rank`，这样值域从 `[-10^4,10^4]` 压到 `n`。
2. 从右往左遍历 `nums`，对每个 `rank` 先查前缀和 `sum(rank-1)`，写进 `counts[i]`。
3. 再把 `rank` 位置 `+1`，表示这个值已出现在右侧。
4. 以 `nums = [5,2,6,1]` 为例：`sorted_uniq = [1,2,5,6]`，排名为 `[3,2,4,1]`。处理到 `5`（rank=3）时，树状数组里已有 `1`(rank=1) 和 `6`(rank=4)，`query(2)` 返回 1（只有 1），加上此前 `2` 也已在右侧……注意顺序：从右往左依次是 `1`、`6`、`2`、`5`，处理 `5` 时树状数组含 `{1,6,2}`，`query(2)=2`，正是 `2` 和 `1`。

```python
from bisect import bisect_left
n = len(nums)
uniq = sorted(set(nums))
tree = [0] * (len(uniq) + 1)
counts = [0] * n
def query(i):
    s = 0
    while i > 0:
        s += tree[i]; i -= i & -i
    return s
for i in range(n - 1, -1, -1):
    r = bisect_left(uniq, nums[i]) + 1
    counts[i] = query(r - 1)
    j = r
    while j <= len(uniq):
        tree[j] += 1; j += j & -j
```

## 复杂度
时间：O(n log n)，排序 O(n log n) 加 n 次树状数组查询/更新各 O(log n)。
空间：O(n)，`uniq`、`tree`、`counts` 各开 n 级别。

## 易错点
- 输入 `[-1,-1]` → 若用 `bisect_right` 或不去重映射，两个 `-1` 会算成互相更小，输出 `[1,0]`；正确做法是 `sorted(set(nums))` 加 `bisect_left`，相同值映射同一 rank，`query(r-1)` 严格小于才计数。
- 输入 `[5,2,6,1]` → 若从左往右扫并查后缀，`query` 语义会反，得到 `[0,1,1,2]`；必须从右往左，先查后更新，保证树里只有 `i` 右侧的元素。

## 如果面试官追问
追问：要求 O(n log n) 但禁用树状数组？
答：改用归并排序，合并时右半元素出队即累加左半剩余个数到对应原下标。
