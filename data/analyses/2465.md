## 一句话思路
排序后双指针从两端取对，用集合存 `nums[i] + nums[j]` 的和（不除 2），集合大小即答案。

## 怎么做
1. 对 `nums` 排序，令 `i = 0`、`j = len(nums) - 1`。
2. 循环 `while i < j`，把 `nums[i] + nums[j]` 加入集合 `seen`，然后 `i += 1`、`j -= 1`。
3. 返回 `len(seen)`。

关键中间值：以 `nums = [4,1,4,0,3,5]` 为例，排序得 `[0,1,3,4,4,5]`。第一轮 `i=0,j=5` 取 `0+5=5`；第二轮 `i=1,j=4` 取 `1+4=5`，与上一轮相同，集合不增；第三轮 `i=2,j=3` 取 `3+4=7`。`seen = {5, 7}`，返回 2。

```python
nums.sort()
seen = set()
i, j = 0, len(nums) - 1
while i < j:
    seen.add(nums[i] + nums[j])
    i += 1
    j -= 1
return len(seen)
```

为什么排序后这样取对就是题目要的过程：每轮删掉当前最小和最大，等价于排序后从两端各取一个；重复元素删哪个都一样，不影响和。存和而不存 `(a+b)/2`，是因为 `a+b` 是整数，避免浮点相等判断（如 `2.5` 与 `2.5` 的浮点比较虽在本例安全，但用整数更稳）。

## 复杂度
时间：排序 `O(n log n)`，双指针扫一遍 `O(n)`，总体 `O(n log n)`。
空间：集合最多 `n/2` 个和，`O(n)`；排序若算原地则不计。

## 易错点
- 输入 `nums = [1,1,1,1]` → 若用 `(a+b)/2` 存浮点并依赖精确相等，虽然本例 `1.0` 没问题，但换成 `[0,1,2,3]` 得 `1.5` 与 `1.5`，浮点仍相等；真正的坑是 `[0,2,4,6]` 得 `3.0` 与 `3.0` 也相等——所以浮点不是必错，但存 `a+b` 整数彻底规避，且 `0+5=5` 与 `1+4=5` 判同更直观。
- 输入 `nums = [4,1,4,0,3,5]` → 若误以为「重复的 4 要分别配对」而手动模拟删除，容易把第二轮 `1+4` 和第三轮 `3+4` 的 4 搞混；正确做法是排序后固定 `i` 递增、`j` 递减，每个位置只取一次，重复值自然被两端各消耗一个。

## 如果面试官追问
问：若要求输出所有不同的平均值本身（而非个数）？答：把 `seen` 里的和 `s` 映射为 `s / 2`，返回 `sorted({s / 2 for s in seen})` 即可，复杂度不变。
