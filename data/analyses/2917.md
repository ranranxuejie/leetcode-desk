## 一句话思路
逐位统计 nums 中第 i 位为 1 的元素个数，达到 k 就把该位写进答案。

## 怎么做
1. 外层枚举位 `i`，范围 `0..30`（因为 `nums[i] < 2**31`，最高位是第 30 位）。
2. 内层遍历 `nums`，用 `(x >> i) & 1` 累加这一位的 1 的个数到 `cnt`。
3. `cnt >= k` 时执行 `ans |= 1 << i`。
4. 返回 `ans`。

以示例 1 的 `nums = [7,12,9,8,9,15], k = 4` 为例：`i = 0` 时，`7,9,9,15` 的末位是 1，`cnt = 4 >= 4`，`ans` 置上第 0 位；`i = 3` 时 `12,9,8,9,15` 的第 3 位是 1，`cnt = 5 >= 4`，`ans` 置上第 3 位；`i = 1` 时只有 `7,15` 两位为 1，`cnt = 2 < 4` 跳过。最终 `ans = 1001` 即 9。

```python
ans = 0
for i in range(31):
    cnt = 0
    for x in nums:
        cnt += (x >> i) & 1
    if cnt >= k:
        ans |= 1 << i
return ans
```

注意 `k == 1` 时这段代码自然退化为全体按位或，示例 3 会得到 15，不需要特判。

## 复杂度
时间：O(31 * n)，31 是固定的位数上界，n 是 nums 长度。
空间：O(1)，只开了 `ans`、`cnt`、`i` 三个标量。

## 易错点
- 位枚举上界写成 `range(32)` 或 `range(31)` 之外的数：`nums[i] < 2**31` 意味着第 31 位恒为 0，多枚举一位不会错但白跑；若误写成 `range(30)` 会漏掉第 30 位，输入 `nums = [2**30], k = 1` 会错成 0，正确做法是枚举到第 30 位。
- 把 `cnt >= k` 写成 `cnt == k`：示例 1 第 3 位有 5 个 1，`k = 4`，用 `==` 会漏掉这一位，答案错成 1 而不是 9；条件是「至少 k 个」，必须用 `>=`。

## 如果面试官追问
问：如果 nums 长度涨到 10^6，还能这么做吗？
答：能，仍是 31 遍扫描，O(31n) 与 O(n) 同阶，只是常数 31；若内存吃紧可改成单遍扫描、对每个数逐位累加到长度 31 的计数数组。
