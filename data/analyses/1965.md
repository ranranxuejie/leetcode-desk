## 一句话思路
把两张表的 `employee_id` 各取出来做对称差集，差集里的 id 就是缺姓名或缺薪水的雇员。

## 怎么做
1. 从 `Employees` 取 `employee_id` 集合，示例得 `{2, 4, 5}`。
2. 从 `Salaries` 取 `employee_id` 集合，示例得 `{5, 1, 4}`。
3. 两个集合做对称差 `^`，得 `{1, 2}`——1 只在薪水表（缺姓名），2 只在雇员表（缺薪水）。
4. 排序后输出。

关键中间值：`{2,4,5} ^ {5,1,4} = {1,2}`，交集 `{4,5}` 被消掉，正是信息完整的两人。

```python
emp = {e["employee_id"] for e in Employees}
sal = {s["employee_id"] for s in Salaries}
lost = sorted(emp ^ sal)
return [{"employee_id": i} for i in lost]
```

SQL 写法同理，用 `UNION` 拼两段 `NOT IN`：

```python
# SELECT employee_id FROM Employees WHERE employee_id NOT IN (SELECT employee_id FROM Salaries)
# UNION
# SELECT employee_id FROM Salaries WHERE employee_id NOT IN (SELECT employee_id FROM Employees)
# ORDER BY employee_id
```

注意 `UNION` 而非 `UNION ALL`：一个 id 不可能同时缺姓名又缺薪水（两表 id 各自唯一），但用 `UNION` 去重更稳。

## 复杂度
时间：O(n + m)，n、m 分别是两表行数，各扫一遍建集合，排序 O(k log k)，k 为丢失人数。
空间：O(n + m)，两个集合各存一份 id，输出列表另算。

## 易错点
- 用 `INNER JOIN` 或 `LEFT JOIN ... WHERE salary IS NULL` 单边查 → 只抓到缺薪水的人（示例只出 2），漏掉只在 `Salaries` 里的 1 → 必须双向查再合并，或直接对称差。
- 用 `UNION ALL` 拼两段子查询 → 若某 id 在两表都缺（本题约束下不会，但换数据可能）会重复输出 → 用 `UNION` 去重，或外层再 `DISTINCT`。

## 如果面试官追问
问：如果要求同时输出缺失字段名（name / salary）？
答：分别标记来源表，`Employees` 独有标 `'salary'`，`Salaries` 独有标 `'name'`，再 `UNION ALL` 带标签输出。
