## 1. 一句话本质

对句子里的每个单词，找出所有「是它前缀」的词根中**最短的那个**，用该词根替换；找不到就保留原词。

## 2. 读完题的第一反应

**朴素解法**：对每个单词 w，遍历整个 dictionary，检查每个词根 r 是否满足 `w.startswith(r)`，在所有命中的 r 里取最短的。

卡在哪？设句子单词数为 m（≤1000），每个单词长度 ≤1000，词典大小 d（≤1000），词根长度 ≤100。每个单词要跟 d 个词根做一次 `startswith`，每次比较最坏 O(100)。总代价 O(m · d · 100) ≈ 10⁸ 次字符比较——在 Python 里这个量级会明显超时，而且它做了大量无用功：一个单词 `"the"` 根本不可能以 `"cat"` 开头，我们却每次都从头比一遍。

**关键观察**：题目要的是「前缀匹配」，而且只要**最短**的命中。前缀匹配天然是一棵树的结构——把所有词根插进字典树后，从根往下走这个单词的字符，**第一次**踩到某个词根结尾标记时，那个词根就是最短命中，立刻停。这样每个单词只走它自己的字符数，跟词典大小 d 无关。

这个观察直接指向两个实现：字典树（Trie），或者更省事的——**按长度排序后逐个 `startswith`**。后者在本题数据规模下完全够用，但面试官问「词典很大怎么办」时，Trie 才是标准答案。下面两条路都讲。

## 3. 从暴力到最优

**第一步：暴力。** 对 `"cattle"`，遍历 `["cat","bat","rat"]`：`"cattle".startswith("cat")` 为真，`"bat"`、`"rat"` 为假，命中 `"cat"`，替换。能对，但每个词都扫全表。

**第二步：消掉「扫全表」。** 把词根按长度升序排，对单词逐个试，**第一个** `startswith` 成功的就返回。因为短的排在前面，第一个命中必然是最短的。对 `"cattle"`：先试 `"cat"`（长度 3）命中，直接返回，`"bat"`、`"rat"` 根本不用看。这一步把「找最短」从「扫完再比」变成「扫到即停」，但最坏情况（单词不以任何词根开头）仍要扫全表。

**第三步：消掉「逐字符重复比较」。** 建 Trie。以 `dictionary = ["cat","bat","rat"]` 为例，插入后结构是：

```
root
├─ c → a → t(词根结尾)
├─ b → a → t(词根结尾)
└─ r → a → t(词根结尾)
```

处理 `"cattle"` 时，从 root 出发：读 `c`，有子节点，走；读 `a`，走；读 `t`，走——此时节点带结尾标记，**立即返回 `"cat"`**，后面的 `t`、`l`、`e` 不再读。处理 `"the"` 时：读 `t`，root 下没有 `t` 子节点，立刻判定「无命中」，返回原词 `"the"`。处理 `"battery"`：`b→a→t` 命中，返回 `"bat"`。

对比一下中间状态：暴力法处理 `"the"` 要跟 3 个词根各比一次；Trie 只读了 1 个字符就失败退出。单词越长、词典越大，差距越大。

**为什么「第一次命中就停」是对的？** 因为 Trie 里从根到某节点的路径就是该前缀本身，走的步数等于前缀长度。我们先踩到的结尾标记，对应的前缀一定更短——这就是「最短」的来源，不需要额外比较。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在处理单词 w 的第 i 个字符时，Trie 当前节点恰好对应 w 的前 i 个字符组成的前缀；若该节点有结尾标记，则这个前缀是一个词根。

**不会漏**：假设存在词根 r 是 w 的前缀且 r 比我们返回的短。那么 r 的字符会沿 Trie 一路走下去，在走到第 |r| 个字符时必然踩到 r 的结尾标记，而我们在那之前就返回了——矛盾。所以不存在更短的命中被跳过。

**不会重**：我们在**第一次**踩到结尾标记时立即返回，之后不再继续走，因此每个单词最多产生一个替换结果，不会出现「多个词根都替换」的叠加。

**「最短」的保证**：Trie 中从根出发的路径长度严格递增，先遇到的结尾标记对应的前缀长度 ≤ 后遇到的，故首次命中即最短。若同一长度有多个词根（如 `"ab"` 和 `"ac"` 都是词根），它们路径不同，对给定单词至多一个能匹配上，不冲突。

**无命中时保留原词**：走完单词所有字符都没踩到结尾标记，或中途无子节点退出，返回原词，符合题意。

## 5. 完整代码（Python）

```python
class Solution:
    def replaceWords(self, dictionary: list[str], sentence: str) -> str:
        # ---------- 建 Trie ----------
        # 用 dict 嵌套表示：每个节点是 {字符: 子节点}，特殊键 '#' 标记词根结尾
        trie = {}
        for root in dictionary:
            node = trie
            for ch in root:
                node = node.setdefault(ch, {})
            node['#'] = True          # 标记：从根到这里的路径是一个词根

        # ---------- 查一个单词的最短词根 ----------
        def shortest_root(word: str) -> str:
            node = trie
            for i, ch in enumerate(word):
                if '#' in node:       # 上一轮已踩到结尾标记，当前前缀就是最短词根
                    return word[:i]
                if ch not in node:    # 走不下去，说明没有任何词根是它的前缀
                    return word
                node = node[ch]
            # 循环结束还没返回：检查最后一个字符处是否是词根结尾
            # 例如 word 本身就是词根，或词根恰好等于整个 word
            return word[:len(word)] if '#' in node else word

        # ---------- 逐词替换并拼回 ----------
        return ' '.join(shortest_root(w) for w in sentence.split(' '))
```

注意 `shortest_root` 里 `'#' in node` 的检查放在**读当前字符之前**：这样当我们在第 i 步发现「当前节点（对应前 i 个字符）是词根」时，直接返回 `word[:i]`，逻辑最干净。循环结束后再补一次检查，覆盖「整个单词恰好是词根」的情况。

## 6. 复杂度

设词典大小 d，词根最大长度 L（≤100），句子单词数 m（≤1000），单词最大长度 W（≤1000），句子总长 S（≤10⁶）。

- **建 Trie**：每个词根插入走 L 步，共 **O(d · L)**。空间最坏 **O(d · L)**（所有词根无公共前缀时节点数最多）。
- **查询**：每个单词最多走 W 步，每步 O(1) 字典查找，共 **O(m · W)**。注意不是 O(m · d · L)——词典大小 d 完全不进入查询复杂度，这正是 Trie 相对暴力的优势。
- **拼接**：`split` 和 `join` 各扫一遍句子，**O(S)**。
- **总时间 O(d·L + m·W + S)**，总空间 **O(d·L + S)**（S 来自 split 出的单词列表和结果字符串）。

对比暴力法的 O(m·d·L)：当 d=1000、m=1000、L=100 时，暴力约 10⁸，Trie 约 10⁵，差三个数量级。

## 7. 边界与反例（至少 4 条）

1. **词根比单词长** → `dictionary=["cat"]`, `sentence="ca"` → 输出 `"ca"`。容易错在：误以为「前缀」可以反向匹配，或 `startswith` 写反方向。
2. **单词本身就是词根** → `dictionary=["cat"]`, `sentence="cat"` → 输出 `"cat"`。容易错在：循环里只在「读下一个字符前」检查结尾标记，漏掉「走完整个单词」后的最后一次检查，导致返回原词（结果碰巧一样，但换成 `dictionary=["a"]`, `sentence="a"` 时若逻辑写错会返回空串）。
3. **多个词根都是前缀，取最短** → `dictionary=["a","ab","abc"]`, `sentence="abcd"` → 输出 `"a"`。容易错在：按输入顺序试，先命中 `"ab"` 就返回；必须保证「先踩到的结尾标记最短」这一性质，Trie 天然满足，排序法需显式按长度升序。
4. **无任何命中** → `dictionary=["cat"]`, `sentence="dog"` → 输出 `"dog"`。容易错在：Trie 中途无子节点时忘记 return 原词，或返回了已走的部分前缀。
5. **词根是单字符且大量命中** → `dictionary=["a","b","c"]`, `sentence="aadsfasf absbs bbab cadsfafs"` → 输出 `"a a b c"`。容易错在：`"bbab"` 应以 `"b"` 替换（最短），若按长度降序排会错成 `"bb"` 之类。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求「最长」词根替换呢？** 思路：Trie 里不能首次命中就停，要走完整个单词、记录**最后一次**踩到的结尾标记位置；或把词根按长度降序排后逐个 `startswith`。
2. **追问：词典动态增删，句子实时查询？** 思路：Trie 支持 O(L) 插入和删除（删除时清理空节点），查询不变；哈希表方案做不到前缀查询，排序数组方案增删要 O(d log d)。
3. **追问：句子有 10⁶ 个单词、内存受限怎么办？** 思路：流式处理，逐词读入、查 Trie、写入输出缓冲，避免一次性 `split` 出整个列表；Trie 本身 O(d·L) 是瓶颈，可考虑用双数组 Trie 压缩。
