## 1. 一句话本质

在「必须包含 s 中每个出现过的字母各一次」的所有子序列里，找字典序最小的那个。

注意这句话里藏了两个约束：**每个出现过的字母恰好一次**（不是「去重后随便挑」），以及**子序列**（相对顺序不能变）。题目说的「字典序最小」，就是在满足这两条的所有字符串里比大小。

## 2. 读完题的第一反应

**朴素解法**：s 里出现的不同字母有 k 个，那就枚举所有「从 s 中按顺序挑出这 k 个字母各一次」的方案，取字典序最小的。方案数是指数级的（每个字母在多个位置出现时都要试），s 长度到 10^4 直接爆炸。就算不枚举，退一步想「先找出每个字母的所有位置，再组合」，组合数依然是指数级。

**卡在哪**：字典序比较是「从左往右、第一个不同的字符决定胜负」。这意味着**结果串的第一个字符**极其重要——它越小越好，只要选了它之后，剩下的字母还都能凑齐。这个「只要……还都能凑齐」就是突破口。

**关键观察**：假设当前要决定结果串的下一个字符。我们希望在**还能保证所有剩余字母都出现**的前提下，尽量选小的字符。而「还能保证」这件事，只取决于**每个字母最后一次出现的位置**：如果某个字母的最后一次出现位置在当前扫描点之前，那它现在不选就永远没机会了，必须立刻选。

于是问题变成：从左往右扫 s，维护一个「已选字符」的栈，遇到新字符时，如果栈顶字符比它大、且栈顶字符后面还会再出现，就把栈顶弹掉——因为把更小的字符放前面，字典序更优，而被弹掉的字符以后还能补回来。这正是**单调栈 + 贪心**的经典形态。

## 3. 从暴力到最优

**第一步：暴力枚举**。以 `s = "bcabc"` 为例，不同字母是 a、b、c，所有合法子序列有 `abc`、`bac`、`bca`、`cab`……取最小得 `abc`。瓶颈：方案数指数级。

**第二步：想清楚「什么时候必须选」**。还是 `"bcabc"`，各字母最后出现位置：a→3，b→4，c→2（0-indexed）。扫描到下标 0 的 `b` 时，b 后面还有（最后位置 4），所以不急着定；但扫描到下标 2 的 `c` 时，c 的最后位置就是 2，**再不定 c 就没了**。这个「最后位置」信息把「未来还能不能补」变成了 O(1) 查询。

**第三步：单调栈 + 贪心**。完整走一遍 `s = "cbacdcbc"`：

- 预处理 last：a→2, b→6, c→7, d→4。
- 用 `in_stack` 记录栈内已有字符，避免重复入栈。

| 步骤 | 当前字符 | 栈（底→顶） | 动作 |
|---|---|---|---|
| 1 | c | [c] | 空栈，入栈 |
| 2 | b | [b] | b<c 且 c 后面还有（last[c]=7>1），弹 c，入 b |
| 3 | a | [a] | a<b 且 b 后面还有（6>2），弹 b，入 a |
| 4 | c | [a,c] | c>a，不弹，入 c |
| 5 | d | [a,c,d] | d>c，入 d |
| 6 | c | [a,c,d] | c 已在栈中，跳过 |
| 7 | b | [a,b] | b<d 且 d 后面没有了（last[d]=4<6），不能弹 d；b<c 且 c 后面还有（7>6），弹 c；b<d 但 d 不能弹，停；入 b |
| 8 | c | [a,b,c] | c 已在栈中，跳过 |

结果 `"acdb"`，与示例一致。

每一步的瓶颈消解：暴力枚举的「试所有组合」被换成「每个字符最多入栈一次、出栈一次」，总操作数 O(n)。

## 4. 正确性：为什么不会漏、不会重

**不会重**：用 `in_stack` 标记，字符已在栈中就直接跳过，保证每个字母最多入栈一次；而每个出现过的字母最终都会入栈（见下），所以恰好一次。

**不会漏**：反证。假设某字母 x 最终不在栈里。它要么从没入栈，要么入栈后被弹掉。从没入栈不可能——扫到它最后一次出现时，若不在栈中必然入栈。被弹掉时，弹它的条件是「栈顶 x 后面还会再出现」，即存在更靠后的 x，那扫到那个位置时 x 会再次入栈。所以最终每个字母都在。

**字典序最小（交换论证）**：设算法输出为 A，最优解为 O，且 A ≠ O。找第一个不同的位置 i，设 A[i]=x，O[i]=y。由于算法在位置 i 选择 x 时，是在「保证剩余字母都能凑齐」的前提下选了当前能选的最小字符，而 O 在同样前缀下选了 y，必有 x<y（否则算法会选 y）。那么把 O 中位置 i 的 y 换成 x、并把 O 中后面那个 x 删掉，得到的串仍是合法子序列（x 在 O 中 i 之后确实存在，因为 O 要包含所有字母），且新串在位置 i 更小，字典序严格更优，与 O 最优矛盾。故 A=O。

**不变量**：扫描过程中，栈内字符始终是「当前已处理前缀的一个合法去重子序列，且是字典序最小的那个」，且栈内字符的相对顺序与原串一致（因为只做入栈和弹栈顶，从不插入中间）。

## 5. 完整代码（Python）

```python
class Solution:
    def removeDuplicateLetters(self, s: str) -> str:
        # 记录每个字符最后一次出现的下标
        last = {ch: i for i, ch in enumerate(s)}

        stack = []          # 单调栈，存结果字符
        in_stack = set()    # 栈内已有字符，防止重复入栈

        for i, ch in enumerate(s):
            # 已在栈中，跳过（保证每个字母只出现一次）
            if ch in in_stack:
                continue
            # 栈顶字符更大，且后面还会再出现，就弹掉它
            # 弹掉后更小的 ch 放前面，字典序更优，被弹的字符以后能补回
            while stack and stack[-1] > ch and last[stack[-1]] > i:
                in_stack.remove(stack.pop())
            # 入栈并标记
            stack.append(ch)
            in_stack.add(ch)

        return "".join(stack)
```

关键逻辑三处：`last` 提供「未来还能不能补」的 O(1) 判断；`while` 是贪心弹栈的核心，两个条件缺一不可（栈顶更大才值得弹，后面还有才敢弹）；`in_stack` 保证不重复。

## 6. 复杂度

**时间 O(n)**：n = len(s)。预处理 `last` 扫一遍 O(n)；主循环每个字符处理一次，`while` 里每个字符最多被弹一次，所以 `while` 总执行次数 ≤ n，整体 O(n)。没有 log 项——因为字符集固定为 26 个小写字母，`last` 用字典/数组都是 O(1) 查询，不涉及排序或二分。

**空间 O(1)（严格说是 O(Σ)，Σ=26）**：`last` 最多 26 项，`stack` 和 `in_stack` 最多 26 个字符。虽然写作 O(n) 也对（n 是上界），但本质受字符集大小限制，是常数级。

## 7. 边界与反例（至少 4 条）

1. `s = "a"` → `"a"`。单字符，容易在 `while` 条件或空栈判断上写错。
2. `s = "aaaa"` → `"a"`。全相同字符，`in_stack` 必须拦住后三次入栈，否则输出 `"aaaa"`。
3. `s = "abacb"` → `"abc"`。容易错在：看到第二个 `a` 时以为要处理，其实 `a` 已在栈中应跳过；以及 `c` 后面还有 `b`，`b` 比 `c` 小且 `c` 后面还有，要弹 `c`。
4. `s = "bcabc"` → `"abc"`。经典反例：若忘记「栈顶后面还会出现」这个条件，会在扫到 `a` 时把 `b`、`c` 都弹光，但 `c` 后面确实还有（下标 2 的 c 在 a 之后？注意此处 c 的最后位置是 2，扫到 a 时 i=3，`last[c]=2 < 3`，所以 c 不能被弹——这正是条件 `last[stack[-1]] > i` 的作用，写反或漏写就错）。
5. `s = "cbacdcbc"` → `"acdb"`。长例，检验弹栈链式反应（第 7 步连弹 c、d 停住）。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求字典序最大呢？** 思路：把 `stack[-1] > ch` 改成 `stack[-1] < ch`，其余不变，即维护单调递减栈。
2. **追问：如果字符集不是小写字母而是任意 Unicode？** 思路：`last` 改用哈希表即可，复杂度不变；`in_stack` 也用集合，空间变为 O(Σ) 其中 Σ 是不同字符数。
3. **追问：如果要求「去重后字典序最小，但允许打乱相对顺序」？** 思路：那就退化成「排序去重」，直接 `"".join(sorted(set(s)))`，与本题的子序列约束完全不同——用来检验面试者是否真理解了「相对顺序」这个约束的作用。
