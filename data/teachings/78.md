## 1. 一句话本质

对长度为 n 的数组，枚举出「每个元素选或不选」的 2^n 种组合，并把每种组合物化成一个列表。

## 2. 读完题的第一反应

**朴素解法**：先想「子集 = 从 n 个里挑 k 个，k 从 0 到 n」，于是对每个 k 做组合枚举。这能对，但你要写两层嵌套的枚举框架，而且组合数求和本身是 2^n，复杂度没救——瓶颈不在「枚举方式」，而在「答案规模」。

**关键观察**：答案总数就是 2^n。题面给了 `1 <= nums.length <= 10`，2^10 = 1024，说明出题人默认你至少要输出 1024 个列表。既然输出本身就有 2^n 个元素级拷贝，任何算法的时间下界就是 Ω(n·2^n)（每个子集平均长度 n/2）。所以「优化」的空间不在渐近复杂度，而在**如何让枚举过程不重不漏、代码不写错**。

这个观察直接给出两条路：
- 每个元素做一次「选/不选」的二叉决策 → 回溯；
- 把 0 到 2^n−1 的每个整数当成一个 bitmask，第 i 位为 1 就取 nums[i] → 位运算。

两条路的枚举顺序不同，但都恰好覆盖 2^n 种状态，这就是本题的全部。

## 3. 从暴力到最优

**暴力（组合枚举）**：对 k = 0..n，用 `itertools.combinations(nums, k)`。以 `[1,2,3]` 为例，k=0 得 `[]`；k=1 得 `[1],[2],[3]`；k=2 得 `[1,2],[1,3],[2,3]`；k=3 得 `[1,2,3]`。共 8 个，正确。瓶颈：需要额外维护「当前选到第几个、还剩几个要选」两个下标，递归参数多，容易写错；而且组合函数内部还要做剪枝判断。

**回溯（决策树）**：把问题改写成「对 nums[i]，我选它还是不选它」。用一个 `path` 记录当前已选元素，走到叶子（i == n）时把 `path` 的拷贝放进结果。

以 `[1,2,3]` 走一遍，`path` 的变化：

```
i=0 不选1 → path=[]
  i=1 不选2 → path=[]
    i=2 不选3 → path=[]         → 收集 []
    i=2 选3   → path=[3]        → 收集 [3]
  i=1 选2   → path=[2]
    i=2 不选3 → path=[2]        → 收集 [2]
    i=2 选3   → path=[2,3]      → 收集 [2,3]
i=0 选1   → path=[1]
  i=1 不选2 → path=[1]
    i=2 不选3 → path=[1]        → 收集 [1]
    i=2 选3   → path=[1,3]      → 收集 [1,3]
  i=1 选2   → path=[1,2]
    i=2 不选3 → path=[1,2]      → 收集 [1,2]
    i=2 选3   → path=[1,2,3]    → 收集 [1,2,3]
```

8 个叶子，8 个子集，一一对应。瓶颈消掉了：不再需要「挑几个」这个维度，决策树天然是满二叉树，每个内部节点只做一次 append/pop。

**位运算（等价改写）**：把上面「选/不选」直接编码成二进制位。n=3 时 mask 从 0 到 7：

```
mask=000 → []          mask=100 → [1]
mask=001 → [3]         mask=101 → [1,3]
mask=010 → [2]         mask=110 → [1,2]
mask=011 → [2,3]       mask=111 → [1,2,3]
```

`mask >> i & 1` 为 1 就取 `nums[i]`。两种写法复杂度完全一样，位运算版没有递归、常数更小，回溯版更通用（后面变体里「有重复元素要去重」时回溯更好改）。面试里建议先写回溯，再提位运算作为等价方案。

## 4. 正确性：为什么不会漏、不会重

**不变量（回溯版）**：在递归进入 `dfs(i)` 时，`path` 恰好是「对 nums[0..i-1] 每个元素做出选/不选决策后，被选中的那些元素，且保持原数组顺序」。初始 `i=0` 时 `path=[]`，空决策成立。转移时 `dfs(i)` 分两支：不选 nums[i] 则 `path` 不变进入 `dfs(i+1)`；选则 append 后进入 `dfs(i+1)`，再 pop 恢复。两支都保持不变量。当 `i==n` 时，不变量说明 `path` 是 nums 的一个子集，且这个子集由唯一一条「n 位决策序列」产生。

**不漏**：任取一个子集 S，按「nums[i] ∈ S 就选、否则不选」构造一条长度为 n 的决策路径，沿这条路径走必然在叶子处得到 S，所以 S 被收集。

**不重**：若两条不同路径都得到 S，则它们在某个位置 i 的决策不同，但 S 对 nums[i] 的归属是确定的，矛盾。所以每个子集只对应一条路径。

**位运算版**：mask 与「n 位决策序列」是双射（0..2^n−1 恰好 2^n 个），第 i 位为 1 当且仅当选 nums[i]，所以同样不漏不重。注意题面保证「元素互不相同」，因此不同 mask 一定得到不同列表；若元素有重复，这个双射在「值」层面会失效，需要额外去重（见第 8 节）。

## 5. 完整代码（Python）

```python
from typing import List


class Solution:
    def subsets(self, nums: List[int]) -> List[List[int]]:
        res = []
        path = []
        n = len(nums)

        def dfs(i: int) -> None:
            # 走到叶子：nums[0..n-1] 的选/不选都决策完了，path 就是一个子集
            if i == n:
                res.append(path[:])   # 必须拷贝，path 后面还会被修改
                return

            # 分支一：不选 nums[i]
            dfs(i + 1)

            # 分支二：选 nums[i]
            path.append(nums[i])
            dfs(i + 1)
            path.pop()                # 回溯，恢复现场

        dfs(0)
        return res


class SolutionBit:
    def subsets(self, nums: List[int]) -> List[List[int]]:
        n = len(nums)
        res = []
        # 0 .. 2^n - 1 每个整数对应一种「选/不选」方案
        for mask in range(1 << n):
            cur = []
            for i in range(n):
                if mask >> i & 1:     # 第 i 位为 1 表示选 nums[i]
                    cur.append(nums[i])
            res.append(cur)
        return res
```

两段都能直接跑。`path[:]` 那行是本题最经典的坑：不拷贝的话，res 里 8 个引用会指向同一个列表，最后全变成 `[]`。

## 6. 复杂度

**时间**：O(n · 2^n)。拆开看：决策树有 2^n 个叶子，每个叶子做一次长度 ≤ n 的 `path[:]` 拷贝，贡献 n·2^n；内部节点共 2^n − 1 个，每个只做 O(1) 的 append/pop，贡献 2^n。两者相加仍是 O(n·2^n)。这里的 n 来自「每个子集平均长度 n/2、最坏 n」，2^n 来自「子集个数」。位运算版同理：外层 2^n 次，内层 n 次位判断，也是 O(n·2^n)。

**空间**：O(n) 的递归栈 + O(n) 的 `path`，即 O(n) 辅助空间（不计输出）。输出本身占 O(n·2^n)，因为要存 2^n 个列表、总元素数约 n·2^n/2。面试被问「空间复杂度」时要区分「辅助空间」和「含输出的空间」，答 O(n) 辅助 / O(n·2^n) 含输出最稳。

注意这里没有 log n 项：本题不涉及排序或二分，n 只出现在「子集长度」和「递归深度」上。

## 7. 边界与反例（至少 4 条）

1. `nums = [0]` → `[[], [0]]`。容易错在把「元素值为 0」误当成「没选」，用 `if nums[i]:` 判断选不选会漏掉 `[0]`；必须用下标/位判断。
2. `nums = [-1]` → `[[], [-1]]`。负数同样不能拿真假值判断，和第 1 条是同一类坑。
3. `nums = [1,2,3]` 且忘记 `path[:]` 拷贝 → 输出 8 个 `[]`。这是本题最高频的运行时错误，原因是列表是可变对象、res 存的是引用。
4. `nums` 长度 10、元素全不同 → 输出 1024 个子集。容易错在递归里用 `res.append(path)` 后又在别处复用 path，或把 `res` 定义成类变量导致多次调用同一实例时结果累积。
5. `nums = [1,2]` → `[[], [2], [1], [1,2]]`（回溯顺序）或 `[[], [1], [2], [1,2]]`（位运算顺序）。题面说「任意顺序」，所以两种都对；容易错在误以为必须和示例顺序一致而去排序，白增 O(2^n · n log n)。

## 8. 面试追问与变体（3 条）

1. **追问：如果 nums 里有重复元素（对应 90 题「子集 II」）怎么办？** 思路：先排序，回溯时同一层相邻且相等的元素跳过（`if i > start and nums[i] == nums[i-1]: continue`），把「按位选/不选」改成「按起始下标枚举下一个选的元素」，这样重复值只会在同一层被剪掉一次。
2. **追问：不用递归，用迭代怎么写？** 思路：从 `[[]]` 开始，每读一个 x，就把当前 res 里每个子集都加上 x 生成新子集再拼回去，本质是「按元素逐个扩张」，和位运算同复杂度。
3. **追问：只求第 k 个子集（按某种字典序）？** 思路：把 k 看成 n 位二进制数，第 i 位为 1 就取 nums[i]，O(n) 直接构造，不需要枚举全部 2^n 个。

## 9. 举一反三（2-3 道同类题）

- **90. 子集 II**：和本题共同点是「枚举全部子集」，区别是输入含重复元素，需要在决策树上加「同层去重」剪枝。
- **77. 组合**：共同点是「从 n 个里选若干」的决策树框架，区别是限定了子集大小必须为 k，递归时用「已选个数」提前剪枝。
- **46. 全排列**：共同点是回溯 + `path` 的 append/pop 模板，区别是每个位置要尝试所有未使用元素，需要 `used` 数组而不是「选/不选」二叉分支。
