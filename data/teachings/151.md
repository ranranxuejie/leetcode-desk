## 1. 一句话本质

把字符串里所有被空格分隔的「非空片段」按出现顺序收集起来，再逆序用单个空格拼回去。

## 2. 读完题的第一反应

最朴素的解法：`s.split()` 按空白切分，`[::-1]` 反转列表，`" ".join()` 拼回去。三行搞定。

它卡在哪？`split()` 会扫描整个字符串并**新建**一个列表，列表里每个单词又是一段新字符串，`join` 再新建一个结果字符串。空间是 O(n)，而且 Python 的字符串不可变，题面进阶要求的「O(1) 额外空间原地解法」在 Python 里根本做不到——这是语言层面的限制，不是算法问题。

关键的观察是：**这道题真正的难点不在「反转」，而在「清洗空格」**。反转本身是 O(单词数) 的简单操作；而输入里前导空格、尾随空格、单词间多空格这三种「脏数据」，才是示例 2、3 专门拿出来考的东西。所以思路应该拆成两件事：先决定「单词怎么被识别出来」，再决定「怎么按逆序输出」。

进一步观察：如果从**右往左**扫描，遇到的第一个单词就是结果里的第一个单词——这天然匹配「逆序输出」的需求，不需要先收集再反转。这个方向直接指向双指针。

## 3. 从暴力到最优

**第一步：暴力。** `" ".join(s.split()[::-1])`。`split()` 不带参数时按任意空白切分并自动丢弃空串，正好解决三种脏空格。复杂度 O(n) 时间、O(n) 空间。这是绝大多数人面试时写的第一版，**能过，但不是这题想考的东西**。

**第二步：想清楚瓶颈在哪。** 瓶颈是空间。要省空间，就得避免「先切出一个列表」。而 Python 字符串不可变，任何「原地」操作都得先转成 `list(s)`——这本身已经是 O(n) 空间了。所以严格意义上的 O(1) 在 Python 里不存在，我们退而求其次：**只用一个结果列表，且不产生中间的子串列表**，把「识别单词」和「拼装结果」合并成一次从右往左的扫描。

**第三步：双指针从右往左扫。** 用两个指针 `i`、`j` 圈出一个单词：`i` 从右往左走，跳过空格；停下时 `i` 指向某个单词的最后一个字符。然后 `j = i`，`j` 继续往左走到该单词前一个空格为止，此时 `s[j+1:i+1]` 就是一个完整单词。把它塞进结果列表，`i` 移到 `j` 继续。

拿示例 2 走一遍，`s = " hello world "`（长度 13，下标 0..12）：

| 步骤 | i 位置 | 动作 | 结果列表 |
|---|---|---|---|
| 初始 | 12 | `s[12]=' '`，跳过空格 | `[]` |
| 1 | 12→11 | `s[11]='d'`，停下，`i=11` | |
| 2 | j 从 11 左走到 5 | `s[5]=' '`，单词为 `s[6:12]="world"` | `["world"]` |
| 3 | i=5 | 跳过空格到 `i=4`（`s[4]='o'`） | |
| 4 | j 从 4 左走到 0 | `s[0]=' '`，单词为 `s[1:5]="hello"` | `["world","hello"]` |
| 5 | i=0 | 跳过空格，`i` 越界，结束 | |
| 输出 | | `" ".join(...)` | `"world hello"` |

注意第 4 步：`j` 走到 0 时 `s[0]` 是空格，循环条件 `j >= 0 and s[j] != ' '` 让 `j` 停在 0，单词取 `s[j+1:i+1] = s[1:5]`，正确。如果 `j` 一路走到 -1（单词顶到字符串开头且前面没有空格），`s[j+1:i+1] = s[0:i+1]` 同样正确——这个边界靠 `j+1` 的写法自动兜住了，不需要特判。

**第四步：还能不能更省？** 在 C++ 里可以真的原地做：先整体反转，再逐个单词反转，最后用双指针压缩空格，全程 O(1)。Python 里做不到，因为 `str` 不可变。面试时如果被追问，就明确说「Python 受语言限制，我给出 O(n) 空间的版本，并说明 C++ 的原地思路」——这比硬凹一个假的 O(1) 更得分。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。设 `i` 是当前扫描位置，维护不变量：

> 在任意时刻，`s[i+1:]` 中所有单词都已经被完整地、按从右到左的顺序放进了结果列表，且 `s[i]` 及其左侧尚未被处理。

**初始化**：`i = len(s)-1`，`s[i+1:]` 是空串，不含单词，不变量成立。

**保持**：每一轮，`i` 先跳过一段连续空格（这些空格不构成单词，跳过不丢信息）；若 `i < 0` 则 `s[i+1:]` 已无单词，循环结束。否则 `s[i]` 是非空格，`j` 从 `i` 向左走到第一个空格或越界，`s[j+1:i+1]` 恰好是包含 `s[i]` 的那个单词——因为 `s[i]` 非空、`s[j]` 是空格（或不存在），左右边界都被卡死，**既不会多取也不会少取**。把它加入列表后，`s[j+1:]` 的单词全部处理完毕，新不变量以 `i = j` 成立。

**终止**：`i < 0` 时，`s[0:]` 全部处理完，列表恰好包含所有单词各一次，顺序是从右到左。`join` 用单空格连接，天然满足「单词间仅一个空格、无前后导空格」。

「不会重」由 `i` 每轮严格左移（`j < i` 恒成立，因为 `s[i]` 非空而 `s[j]` 是空格或越界）保证；「不会漏」由 `i` 只跳过空格、不跳过非空格字符保证。

## 5. 完整代码（Python）

```python
class Solution:
    def reverseWords(self, s: str) -> str:
        words = []
        i = len(s) - 1          # 从最右端开始扫描
        n = len(s)

        while i >= 0:
            # 跳过单词之间的空格（含尾随空格）
            while i >= 0 and s[i] == ' ':
                i -= 1
            if i < 0:           # 全是空格或已扫完，退出
                break

            # 此时 s[i] 是某个单词的最后一个字符
            j = i
            # 向左找到该单词的第一个字符的前一位
            while j >= 0 and s[j] != ' ':
                j -= 1

            # s[j+1 : i+1] 就是当前单词，j+1 自动处理「顶到开头」的情况
            words.append(s[j + 1:i + 1])

            # i 移到 j，下一轮继续跳过空格
            i = j

        # 单词已按从右到左收集，用单空格连接即为答案
        return ' '.join(words)
```

## 6. 复杂度

**时间 O(n)**：外层 `while` 的每一轮，`i` 要么在「跳空格」里左移，要么在「找单词头」里通过 `j` 左移，两条路径覆盖的字符区间互不重叠（一个字符要么是空格被跳过，要么属于某个单词被 `j` 扫过一次），所以总移动次数不超过 `n`。`join` 再扫一遍所有单词字符，也是 O(n)。没有 log 项——这里不存在分治或排序。

**空间 O(n)**：`words` 列表里存的是 `s[j+1:i+1]` 切片，每个切片都是新字符串，所有单词字符总数 ≤ n；`join` 的结果字符串长度 ≤ n。所以额外空间是 O(n)，**不是 O(1)**。原因在语言层面：Python 的 `str` 不可变，无法原地改写；即便转成 `list(s)` 再原地操作，那个 list 本身也是 O(n)。题面进阶要求的 O(1) 只在 C++/Java 的 `char[]` 或可变字符串上成立。

## 7. 边界与反例（至少 4 条）

1. `s = "a"` → `"a"`。只有一个单词、无空格。容易错在：`j` 走到 -1，若代码写成 `s[j:i+1]` 会取到 `s[-1:1]` 这种诡异切片，必须用 `j+1`。
2. `s = "  hello  "` → `"hello"`。前后都是多空格。容易错在：只 `strip()` 一次不够，或跳空格循环漏了 `i >= 0` 判断导致负索引回绕。
3. `s = "a  b"`（中间两个空格）→ `"b a"`。容易错在：用 `s.split(' ')` 会切出空串 `['a','','b']`，反转后变成 `"b  a"`，多一个空格。必须用不带参数的 `split()` 或手写跳空格。
4. `s = "  a  b  c  "` → `"c b a"`。首尾和中间全是多空格，是三种脏数据同时出现的最强组合，用来验证「跳空格 + 取词」两个循环是否都写对。
5. `s = "a b"` → `"b a"`。最普通的两个单词，用来验证 `i = j` 之后下一轮能正确跳过中间那一个空格。

## 8. 面试追问与变体（3 条）

1. **追问：如果语言支持可变字符串，怎么做到 O(1) 空间？** 思路：整体反转 → 逐单词反转 → 双指针压缩多余空格（读指针扫、写指针写，遇连续空格只写一个），三步都原地。
2. **追问：不改变单词内部字符，但要求保留单词间的原始空格数量，只反转单词顺序，怎么做？** 思路：先记录每个单词的起止下标和它前面的空格串，再逆序拼装，空格串跟着单词走。
3. **追问：如果要求「反转每个单词内部的字符，但单词顺序不变」呢？** 思路：这是另一道题（题号 557），双指针定位每个单词后原地反转该区间即可，不需要从右往左扫。
