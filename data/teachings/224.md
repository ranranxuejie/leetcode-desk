## 1. 一句话本质

把一串带括号和正负号的加减表达式，按「括号内先算、结果回填到外层」的顺序，边扫描边维护一个当前累加值，遇到括号就把外层状态压栈、算完再弹回来。

## 2. 读完题的第一反应

朴素解法：先找最内层括号，把括号里的子表达式算出来，替换回原串，重复直到没有括号，最后算纯加减。这思路是对的，但卡在**字符串反复拼接和重复扫描**上：每消一层括号就要重新遍历一遍整串，最坏情况（嵌套 n 层）是 O(n²)，而 n 可达 3×10⁵，直接超时。

关键观察是：**括号只影响「当前累加值从哪开始、符号是什么」，不影响加减法本身的结合顺序**。也就是说，我完全可以只从左到右扫一遍，用一个变量 `res` 记当前层已经算出的和，用 `sign` 记下一个数字该加还是该减。碰到 `(`，说明要开一层新账本，那就把「外层此刻的 res 和 sign」存起来，进去重新开账；碰到 `)`，说明这层账算完了，把结果按存下来的 sign 并回外层。

这个观察之所以能落地，是因为题面保证了「表达式有效」「没有连续操作符」「`+` 不能做一元」，所以扫描时符号和数字的配对关系是确定的，不需要回溯。

## 3. 从暴力到最优

**暴力**：递归找最内层括号 → 算 → 字符串替换 → 重复。瓶颈是每层都要 O(n) 重扫，嵌套深时 O(n²)。

**优化**：注意到「替换回填」这个动作，本质就是把子结果当成一个数参与外层运算。既然外层只需要知道「这个子结果前面是加还是减」，那就不必真的替换字符串，只要在扫描到 `)` 时，把子结果乘上外层符号加回外层 `res` 即可。栈用来保存「外层此刻的 res 和 sign」。

用示例 3 走一遍 `"(1+(4+5+2)-3)+(6+8)"`：

| 读到 | 动作 | res（当前层） | sign | 栈 |
|---|---|---|---|---|
| `(` | 压栈 (0, +1)，重置 res=0, sign=+1 | 0 | +1 | [(0,+1)] |
| `1` | res += 1×1 = 1 | 1 | +1 | [(0,+1)] |
| `+` | sign=+1 | 1 | +1 | [(0,+1)] |
| `(` | 压栈 (1, +1)，重置 | 0 | +1 | [(0,+1),(1,+1)] |
| `4` | res=4 | 4 | +1 | 同上 |
| `+5+2` | res=4+5+2=11 | 11 | +1 | 同上 |
| `)` | 弹 (1,+1)，res = 1 + 1×11 = 12 | 12 | +1 | [(0,+1)] |
| `-3` | sign=-1，res = 12-3 = 9 | 9 | -1 | [(0,+1)] |
| `)` | 弹 (0,+1)，res = 0 + 1×9 = 9 | 9 | +1 | [] |
| `+` | sign=+1 | 9 | +1 | [] |
| `(6+8)` | 压栈 (9,+1)，算得 14，弹回 res=9+14=23 | 23 | +1 | [] |

最终 23，和答案一致。可以看到每个字符只被读一次，瓶颈从 O(n²) 降到 O(n)。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**说清楚。定义：扫描到位置 i 时，`res` 等于「当前所在括号层内、从该层开头到 i 之前所有已完整读入的项之和」，`sign` 等于「下一个数字前面的符号」，栈里依次保存着每一层外层的 `(进入该层时的 res, 进入该层时的 sign)`。

- **初始化**：i=0，res=0、sign=+1、栈空，符合「最外层开头、还没读入任何项」。
- **保持**：读到数字，按 sign 累加进 res，不变量成立；读到 `+/-`，只更新 sign，res 不变，成立；读到 `(`，把当前 (res, sign) 压栈并重置，新层从 0 开始，成立；读到 `)`，弹出 (outer_res, outer_sign)，令 res = outer_res + outer_sign × res，这正好是「外层已算部分 + 本层结果按外层符号并入」，成立。
- **终止**：扫完时栈必为空（题面保证括号配对），res 就是整个表达式的值。

「不漏」是因为每个数字恰好被读一次并累加一次；「不重」是因为 `)` 回填时用的是子层结果整体，子层内部各项不会在外层再被加一遍。一元负号的处理见第 5 节代码：`sign` 初值设为 +1，遇到 `-` 就翻转，天然支持 `-(2+3)` 和 `-1`。

## 5. 完整代码（Python）

```python
class Solution:
    def calculate(self, s: str) -> int:
        stack = []          # 保存每层外层的 (进入时的 res, 进入时的 sign)
        res = 0             # 当前层已算出的和
        sign = 1            # 下一个数字的符号：+1 或 -1
        i = 0
        n = len(s)

        while i < n:
            ch = s[i]

            if ch == ' ':
                i += 1
                continue

            if ch.isdigit():
                # 连续数字要整体读成一个数，不能逐位当独立项
                num = 0
                while i < n and s[i].isdigit():
                    num = num * 10 + int(s[i])
                    i += 1
                res += sign * num
                continue    # 注意：数字读完 i 已前移，不要再 i += 1

            if ch == '+':
                sign = 1
            elif ch == '-':
                sign = -1
            elif ch == '(':
                # 开新层：存下外层状态，本层从 0 开始
                stack.append((res, sign))
                res = 0
                sign = 1
            elif ch == ')':
                # 关层：本层结果按外层符号并回外层
                outer_res, outer_sign = stack.pop()
                res = outer_res + outer_sign * res
                sign = 1    # 括号整体算完，后面若跟运算符会覆盖它

            i += 1

        return res
```

## 6. 复杂度

- **时间 O(n)**：n 是字符串长度。主循环每个字符最多被访问一次；内层 `while` 读数字时，每个数字字符也只被读一次，且读完后 `i` 已跳过，不会回退。所以总访问次数是 O(n)，没有嵌套重扫。
- **空间 O(n)**：栈的深度等于括号最大嵌套层数，最坏（如 `((((...))))`）为 O(n/2)，即 O(n)。`res`、`sign`、`i` 是常数空间。这里没有 log 项，因为不存在分治或二分。

## 7. 边界与反例（至少 4 条）

1. `s = "1"` → 输出 1 → 容易错在：只处理了「数字后跟运算符」的情况，末尾单个数字没被累加。代码里数字分支独立于运算符，不会漏。
2. `s = "-1"` → 输出 -1 → 容易错在：以为 `-` 只能做二元运算，没处理开头一元负号。代码 `sign` 初值 +1，读到 `-` 翻成 -1，正确。
3. `s = "-(2+3)"` → 输出 -5 → 容易错在：`(` 前的负号没被记住。代码在 `(` 分支把 `sign=-1` 压栈，`)` 回填时乘上它，正确。
4. `s = "1-(   -2)"` → 输出 3 → 容易错在：括号内连续空格后跟一元负号，或把 `-` 当成二元减号多减一次。代码跳过空格后 `sign` 翻转为 -1，`res = 0 + (-1)×2 = -2`，回填 `1 - (-2) = 3`。
5. `s = "2147483647"` → 输出 2147483647 → 容易错在：逐位累加时用 `num = num*10 + digit` 没问题，但若用 `int(s[i])` 逐位当项加会错。题面保证结果在 32 位内，Python 无溢出问题。

## 8. 面试追问与变体（3 条）

1. **追问：如果加入乘除法（题 227）怎么办？** 思路：需要两级优先级，用「上一个操作数 + 运算符」延迟结算，遇到 `*` `/` 先和栈顶结合，遇到 `+` `-` 再把栈顶弹出累加。
2. **追问：如果允许 `+` 做一元、允许连续操作符呢？** 思路：扫描时把「连续符号」折叠成一个有效符号（如 `--` 变 `+`），再进入正常逻辑；本质是预处理符号串。
3. **追问：不用栈，能否 O(1) 空间？** 思路：括号嵌套信息必须记，除非用递归（递归栈也是 O(n)）；若只要求 O(1) 额外空间且括号深度有上界 k，可用固定数组模拟栈，空间 O(k)。
