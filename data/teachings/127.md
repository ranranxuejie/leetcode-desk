## 1. 一句话本质

把每个单词看成图上的一个节点，两个单词「只差一个字母」就连一条边，求从 `beginWord` 到 `endWord` 的**无权图最短路径**（按节点数计）。

## 2. 读完题的第一反应

**朴素解法**：把 `wordList` 里任意两个单词两两比较，判断是否只差一个字母，建出整张图，然后 BFS。判断两个等长单词是否只差一个字母要 O(L)（L 为单词长度），两两比较是 O(N²) 对，建图就要 O(N²·L)。N 最大 5000，L 最大 10，N²·L ≈ 2.5×10⁸，在 Python 里基本必超时。瓶颈就在「两两比较」这一步。

**关键观察**：我们其实不需要知道「哪两个单词相邻」，只需要在 BFS 扩展某个单词时，**快速找到它的所有邻居**。而「只差一个字母」这个关系有个很好的结构：把单词 `hot` 的某一位替换成通配符，得到 `*ot`、`h*t`、`ho*` 三种「模式」。**两个单词只差一个字母，当且仅当它们共享同一个模式**。于是可以预处理：对每个单词枚举 L 个模式，把「模式 → 单词列表」存进哈希表。这样查一个单词的邻居，只需枚举它的 L 个模式、查表即可，不用再和所有单词比较。

这个观察之所以能直接导向下一步，是因为它把「找邻居」从 O(N·L) 降到了 O(L)（枚举模式）+ 查表，而哈希表查表是 O(1) 均摊。

## 3. 从暴力到最优

**暴力建图**：对每对 (u, v) 判断是否只差一个字母。以示例 1 为例，`wordList` 有 6 个词，要比较 15 对，每对扫 3 个字符。能跑，但 N=5000 时是 1250 万对 × 10 字符，Python 里几十秒起步。

**优化建图（模式哈希）**：对每个单词生成 L 个模式。示例 1 中：

- `hot` → `*ot`, `h*t`, `ho*`
- `dot` → `*ot`, `d*t`, `do*`
- `dog` → `*og`, `d*g`, `do*`
- `lot` → `*ot`, `l*t`, `lo*`
- `log` → `*og`, `l*g`, `lo*`
- `cog` → `*og`, `c*g`, `co*`

建表后 `*ot` 对应 `[hot, dot, lot]`，`*og` 对应 `[dog, log, cog]`，`do*` 对应 `[dot, dog]`……查 `hot` 的邻居：枚举 `*ot`（得 dot、lot）、`h*t`（空）、`ho*`（空），邻居是 dot、lot。注意 `hot` 自己也在 `*ot` 列表里，需要跳过自己（或靠 visited 去重）。

**BFS 走一遍**（队列存 `(单词, 层数)`，visited 记录已入队单词）：

- 初始：队列 `[(hit, 1)]`，visited = {hit}
- 弹出 `hit`（层 1）：模式 `*it`、`h*t`、`hi*` 查表，只有 `*ot` 命中 `hot`。`hot` 未访问 → 入队 `(hot, 2)`，visited 加 hot。
- 弹出 `hot`（层 2）：`*ot` → dot、lot（跳过 hot 自己）；`h*t`、`ho*` 空。入队 `(dot, 3)`、`(lot, 3)`。
- 弹出 `dot`（层 3）：`*ot` → hot（已访问）、lot（已访问）；`d*t` 空；`do*` → dog。入队 `(dog, 4)`。
- 弹出 `lot`（层 3）：`*ot` 全访问过；`lo*` → log。入队 `(log, 4)`。
- 弹出 `dog`（层 4）：`*og` → log（已访问）、cog。`cog == endWord`，返回 4+1 = **5**。

对比暴力：暴力要比较 15 对，这里每个单词只枚举 3 个模式、查 3 次表，总操作量 O(N·L) 级别，N=5000、L=10 时约 5 万次哈希操作，轻松通过。

**还能再进一步（双向 BFS）**：从起点和终点同时 BFS，每次扩展队列较小的一侧，相遇即停。搜索空间从「半径 d 的球」变成「两个半径 d/2 的球」，分支因子 b 大时能省掉大量节点。本题 N 只有 5000，单向 BFS 已够，但面试里提双向 BFS 是加分项（见第 8 节）。

## 4. 正确性：为什么不会漏、不会重

**不漏**：设 `u`、`v` 只差一个字母，设差异位置为 i。则 `u` 和 `v` 在第 i 位替换成 `*` 后得到同一个模式串 p，所以建表时 `v` 一定被放进 `p` 对应的列表，BFS 扩展 `u` 时枚举到 p 就能查到 `v`。反过来，若 `u`、`v` 共享某个模式 p，说明它们在 p 中 `*` 的位置上字母不同、其余位置相同，即恰好差一个字母。所以「共享模式」与「相邻」等价，邻居集合既不漏也不多。

**不重**：BFS 用 `visited` 集合保证每个单词最多入队一次。这里的不变量是：**入队时记录的层数，就是该单词到起点的最短距离**。归纳证明：起点层数为 1；队列按层数非降序出队（BFS 性质），当从层 d 的节点扩展到未访问的 `v` 时，`v` 的最短距离不可能是 d 或更小（否则早被访问），也不可能是 d+2 或更大（因为经过当前节点就有 d+1 的路径），故恰为 d+1。因此第一次访问 `endWord` 时返回的层数就是最短序列长度。

**为什么返回 0 是对的**：若 BFS 队列耗尽仍未遇到 `endWord`，说明 `endWord` 与起点不在同一连通分量，不存在转换序列。

## 5. 完整代码（Python）

```python
from collections import deque, defaultdict

class Solution:
    def ladderLength(self, beginWord: str, endWord: str, wordList) -> int:
        # 提前剪枝：endWord 不在字典里，永远到不了
        word_set = set(wordList)
        if endWord not in word_set:
            return 0

        L = len(beginWord)

        # 建模式哈希表：模式 -> 拥有该模式的所有单词
        # 注意 beginWord 也要放进去，它可能是别人的邻居
        pattern_map = defaultdict(list)
        for word in word_set | {beginWord}:
            for i in range(L):
                pattern = word[:i] + '*' + word[i+1:]
                pattern_map[pattern].append(word)

        # BFS：队列存 (单词, 当前序列长度)
        queue = deque([(beginWord, 1)])
        visited = {beginWord}

        while queue:
            word, level = queue.popleft()
            if word == endWord:
                return level

            # 枚举当前单词的所有模式，查表拿邻居
            for i in range(L):
                pattern = word[:i] + '*' + word[i+1:]
                for nxt in pattern_map[pattern]:
                    if nxt not in visited:
                        visited.add(nxt)
                        queue.append((nxt, level + 1))
                # 关键优化：该模式下的单词已全部入队/访问过，
                # 清空可避免后续重复扫描同一列表
                pattern_map[pattern] = []

        return 0
```

两个细节值得讲：第一，`pattern_map[pattern] = []` 这行清空是常见优化——同一个模式列表被扫过一次后，里面所有单词都已 visited，再扫纯属浪费；不清空也正确，只是慢。第二，`beginWord` 必须加入建表，否则像 `beginWord="hit"` 这种不在 `wordList` 里的起点，它的模式 `*it` 可能对应 `wordList` 中的词（虽然示例里没有），漏掉会出错。

## 6. 复杂度

设 N = `wordList` 长度，L = 单词长度，M = 字母表大小（本题固定 26）。

- **建表**：N+1 个单词，每个生成 L 个模式，每个模式拼接字符串 O(L)，共 O(N·L²)。（若把字符串拼接视为 O(L)；很多分析直接写 O(N·L)，是把拼接当 O(1) 的简化。）
- **BFS**：每个单词最多出队一次，出队时枚举 L 个模式，每个模式查表 O(1)，并把该模式列表里的单词扫一遍。由于每个模式列表被清空，所有列表的单词总数是 O(N·L)（每个单词出现在 L 个列表里），所以总扫描量 O(N·L)。加上模式字符串构造 O(L)，BFS 总时间 O(N·L²)。
- **总时间**：O(N·L²)，N=5000、L=10 时约 5×10⁵ 量级，远优于暴力的 O(N²·L)。
- **空间**：`pattern_map` 存 N·L 个条目，每个条目是长度 L 的字符串，O(N·L²)；visited 和队列 O(N)。总空间 O(N·L²)。

对比暴力建图 O(N²·L) 时间，这里用「多存一张模式表」换掉了「两两比较」，是典型的空间换时间。

## 7. 边界与反例（至少 4 条）

1. **`beginWord = "hit", endWord = "cog", wordList = ["hot","dot","dog","lot","log"]`** → 期望 0。`endWord` 不在字典里，直接返回 0。容易错在：忘记提前判断，BFS 跑完才返回 0，虽然结果对但白跑；更糟的是有人把 `endWord` 强行加入字典，导致错误地返回路径长度。
2. **`beginWord = "a", endWord = "c", wordList = ["a","b","c"]`** → 期望 2（`a -> c` 只差一个字母）。容易错在：`beginWord` 也在 `wordList` 里，建表时若用 `set` 去重没问题，但若逻辑上把起点当成「必须经过字典词」会绕路；另外 L=1 时模式只有 `*` 一个，所有单词共享，要确保 visited 正确去重。
3. **`beginWord = "hot", endWord = "dog", wordList = ["hot","dog"]`** → 期望 0（`hot` 和 `dog` 差两个字母，且没有中间词）。容易错在：把「差一个字母」误判成「有公共字母」或「编辑距离 ≤ 1 的任意变形」，`hot` 和 `dog` 无公共字母但这不是判据；正确判据是共享模式。
4. **`beginWord = "hit", endWord = "hot", wordList = ["hot"]`** → 期望 2。容易错在：建表时只遍历 `wordList` 而漏掉 `beginWord`，导致 `hit` 的模式 `*it` 查不到任何东西（虽然本例 `hit` 和 `hot` 共享 `h*t`，`hot` 在表里所以能查到；但若换成 `beginWord="ait"`、`endWord="bit"`、`wordList=["bit"]`，`ait` 和 `bit` 共享 `*it`，`bit` 在表里也能查到——真正会漏的是 `beginWord` 作为**别人的邻居**时，比如 `wordList` 里某词的模式列表需要包含 `beginWord` 才能被反向查到，单向 BFS 从 `beginWord` 出发其实不需要，但双向 BFS 需要）。稳妥做法是始终把 `beginWord` 加入建表。
5. **`wordList` 含重复？** 题面保证互不相同，但若面试官改口说可能重复，`set(wordList)` 已兜住。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回具体路径（单词序列）而不只是长度？** 思路：BFS 时记录每个单词的 `parent`（从哪个单词扩展来的），到达 `endWord` 后沿 parent 回溯，再反转。注意同一层可能有多个 parent，任选一个即可，因为 BFS 保证层数最短。
2. **追问：如何优化到更快？** 思路：双向 BFS——从 `beginWord` 和 `endWord` 各维护一个 visited 集合和队列，每轮扩展较小的那个集合，当新扩展出的单词出现在另一侧 visited 中时，两侧层数相加即为答案。分支因子大时能显著减少访问节点数。
3. **追问：如果单词长度很大（比如 100），模式哈希还合适吗？** 思路：模式字符串构造变成 O(L)，总时间 O(N·L²) 里 L² 项会变大；可改用「对每个位置枚举 26 个字母、直接查 `word_set`」的方式，时间 O(N·L·26)，避免构造长模式串，空间也从 O(N·L²) 降到 O(N)。
