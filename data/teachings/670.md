## 1. 一句话本质

在数字的十进制字符串里，找一对位置 (i, j)（i 在左、j 在右），使得「把 j 位的数字换到 i 位」带来的高位增益最大；若不存在能让数字变大的交换，就原样返回。

## 2. 读完题的第一反应

**朴素解法**：枚举所有数对 (i, j)，交换后转成整数比较，取最大。数字最多 9 位（因为上界 10^8），数对数量是 O(L²)，L ≤ 9，其实也就 36 对——暴力在本题数据规模下**完全能过**。所以「卡在哪」不是卡在时间上，而是卡在**思维上**：如果面试官把上界改成 10^1000（字符串输入），暴力立刻退化成 O(L²) 次字符串比较，每次 O(L)，总 O(L³)，就不可接受了。我们要的是能推广到任意长度的做法。

**关键观察**：交换的收益只取决于「被换到左边的那个数字」和「它落到的位置有多靠左」。具体说，若把位置 j 的数字 d 换到位置 i（i < j），数值变化是 (d − s[i]) × 10^(L−1−i)，后面位置的相对顺序完全不受影响。于是问题被拆成两层：

1. 先决定「换到哪个位置 i」——越靠左、且 s[i] 越小，潜在增益越大；
2. 再决定「从右边哪个位置 j 拿数字」——在 i 右侧找一个比 s[i] 大的数字，且要**尽可能大**；同样大的话要取**最靠右**的那个（把最靠右的大数字提到前面，剩下的低位排列最优）。

这个观察之所以能推进，是因为它把「O(L²) 次整体比较」降成了「对每个位置做一次右侧最值查询」。

## 3. 从暴力到最优

**第一步：暴力。** 对每对 (i, j) 交换、比较。以 2736 为例，会试 (0,1)→7236、(0,2)→3726、(0,3)→6732、(1,2)→2376…… 取最大 7236。正确但笨。

**第二步：只考虑「让数字变大」的交换。** 若 s[j] ≤ s[i]，交换后不变或变小，直接排除。这样每个 i 只需在右侧找「比 s[i] 大的最大数字」。

**第三步：预计算右侧后缀最大值。** 从右往左扫，维护 `max_right[i]` = 位置 i 右侧（不含 i）的最大数字，以及它**最靠右**的出现位置 `max_pos[i]`。以 2736 走一遍：

- i=3：右侧为空，max_right=−1，max_pos=−1
- i=2（s=3）：右侧 {6}，max_right=6，max_pos=3
- i=1（s=7）：右侧 {3,6}，max_right=6，max_pos=3
- i=0（s=2）：右侧 {7,3,6}，max_right=7，max_pos=1

然后从左往右找**第一个**满足 `max_right[i] > s[i]` 的位置 i。i=0 时 7 > 2，命中，交换 (0, 1)，得 7236。

**为什么「第一个」就够？** 因为位置越靠左，权重 10^(L−1−i) 越大。只要 i 位能变大，任何在更靠右位置做的交换，其增益都被 10 的幂次压制——具体地，i 位增加 1 就值 10^(L−1−i)，而更靠右的所有位即使全变成 9，总增益也小于 10^(L−1−i)。所以最左的可改进位置一旦确定，就是最优交换点。

**第四步：为什么取「最靠右的最大数字」？** 假设 i 右侧最大数字是 7，出现在位置 j1 < j2。交换 (i, j1) 后，j1 位置上放的是原来的 s[i]（较小），而 j2 位置仍是 7；交换 (i, j2) 后，j1 位置仍是 7，j2 位置放 s[i]。两者在 i 位相同，比较 j1 位：前者是 s[i]，后者是 7，显然后者大。所以取最靠右的那个 7 更优。

**第五步：整体流程。** 一次从右往左的后缀扫描 + 一次从左往右的定位扫描，O(L) 时间、O(L) 空间。以 9973 验证：后缀最大值依次为 −1, 3, 7, 9（对应位置 3,2,1），从左扫，i=0 时 max_right=9 但 s[0]=9 不满足严格大于；i=1 时 max_right=7 < 9；i=2 时 max_right=3 < 9；i=3 无右侧。全程无命中，返回原数 9973。

## 4. 正确性：为什么不会漏、不会重

用**交换论证（exchange argument）**。

设最优解为交换 (i*, j*)（i* < j*），若不存在则答案为原数，与算法一致。分两点：

**引理 1（i* 是最左可改进位置）。** 若存在某个位置 k < i* 满足「k 右侧有比 s[k] 大的数字」，则交换 (k, 某更大数字) 得到的数严格大于交换 (i*, j*) 得到的数——因为两者在 k 之前完全相同，而 k 位上前者更大。这与 (i*, j*) 最优矛盾。故 i* 必是最左的可改进位置，算法选 i 与 i* 一致。

**引理 2（j* 是 i 右侧最大数字的最右出现）。** 固定 i 后，i 位放的数字越大越好（高位权重大于低位总和）；数字相同则取最靠右者，理由见第 3 节第四步的逐位比较。故 j* 唯一确定，算法选 j 与 j* 一致。

**不变量**：算法在从左扫描时，维护「此前所有位置都不可改进」这一事实；一旦命中第一个可改进位置，由引理 1、2 该交换即全局最优。因此不漏（最优解被覆盖）、不重（i、j 都由规则唯一确定，不存在多个候选需要比较）。

## 5. 完整代码（Python）

```python
class Solution:
    def maximumSwap(self, num: int) -> int:
        s = list(str(num))
        L = len(s)

        # max_right[i] = s[i] 右侧（不含 i）的最大数字字符
        # max_pos[i]   = 该最大数字最靠右的出现下标
        max_right = [''] * L
        max_pos = [-1] * L
        cur_max = ''      # 当前扫到的最大的数字字符
        cur_pos = -1      # 它最靠右的位置
        for i in range(L - 1, -1, -1):
            max_right[i] = cur_max
            max_pos[i] = cur_pos
            # 用 s[i] 更新，供更左边的位置使用
            if s[i] > cur_max:      # 严格大于才更新，保证同值时保留最靠右
                cur_max = s[i]
                cur_pos = i

        # 从左往右找第一个「右侧存在更大数字」的位置
        for i in range(L):
            if max_right[i] != '' and max_right[i] > s[i]:
                j = max_pos[i]
                s[i], s[j] = s[j], s[i]
                return int(''.join(s))

        # 没有任何可改进的交换，原样返回
        return num
```

关键点：更新 `cur_max` 用**严格大于**，这样遇到相同数字时 `cur_pos` 保留的是更靠右的那个，正好满足第 3 节第四步的要求。

## 6. 复杂度

- **时间 O(L)**：L 是十进制位数，L = ⌊log₁₀ num⌋ + 1。后缀扫描 O(L)，定位扫描最坏 O(L)，交换与拼接 O(L)。注意 `int(''.join(s))` 的转换在 Python 里对大整数是 O(L²) 位运算级别，但本题 L ≤ 9，可视为 O(1)；若推广到超长字符串输入，应直接返回字符串。
- **空间 O(L)**：`max_right`、`max_pos`、`s` 三个长度 L 的数组。递归栈无。
- 与暴力 O(L²)（每次比较 O(L) 则 O(L³)）相比，本题把「枚举数对」消成了「两次线性扫描」。

## 7. 边界与反例（至少 4 条）

1. **输入 0** → 输出 0。L=1，两个循环都只走一步，无命中，返回原数。容易错在把空字符串 `max_right[0]=''` 拿去和 `'0'` 比较——代码里加了 `!= ''` 保护。
2. **输入 98368** → 输出 98863。最左可改进位置是 i=1（s=8），右侧最大是 8 出现在 j=3，交换得 98863。容易错在只看「全局最大数字」而不看「最左可改进位置」，误去交换 9 和 8。
3. **输入 1993** → 输出 9913。i=0 时右侧最大是 9，出现在 j=1 和 j=2，必须取**最靠右**的 j=2，交换得 9913；若取 j=1 得 9193，更小。这是「同值取最右」的经典反例。
4. **输入 9973** → 输出 9973。全程无严格大于，返回原数。容易错在写成 `>=` 判断，导致把相等的数字交换，虽然结果数值不变但逻辑上多做了无用交换，且在某些变体（要求「恰好交换一次」）里会出错。
5. **输入 10** → 输出 10。i=0 时右侧最大是 '0'，不满足 `'0' > '1'`；i=1 无右侧。返回 10。容易错在把 0 当成「可以换到前面」的候选。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求「恰好交换一次」，不能不变怎么办？** 思路：若不存在可改进交换，则交换任意两个**相等**的数字（若存在重复数字）保持数值不变；若全不重复，则交换最后两位使损失最小。
2. **追问：输入是长度 10^5 的字符串，怎么办？** 思路：算法本身 O(L) 不变，只需把最后的 `int(...)` 改成直接返回字符串，避免大整数转换开销。
3. **追问：求「至多交换 k 次」的最大值？** 思路：贪心不再成立，需按位决策——每轮找最左可改进位置并换入右侧最大数字，重复 k 次；或用「后缀最大值 + 逐位贪心」的推广，注意 k 次后可能引入新的可改进位置。
