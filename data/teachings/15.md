## 1. 一句话本质

在数组里找出**所有**互不相同的、三个数加起来等于 0 的组合——注意是「所有」且「互不相同」，这两点决定了它比「两数之和」难一个档次。

## 2. 读完题的第一反应

最朴素的做法是三重循环枚举 `i < j < k`，检查 `nums[i]+nums[j]+nums[k]==0`。复杂度 O(n³)，n=3000 时是 2.7×10¹⁰ 次运算，必然超时。瓶颈在于：**对每个 (i,j) 我们都在重新扫描整个后缀去找第三个数**。

关键观察有两条，缺一不可：

1. **「和为 0」可以拆成「两数之和 = 某个目标值」**。固定第一个数 `a`，问题就退化成在剩余元素里找两个数之和等于 `-a`。而「有序数组里找两数之和」有经典的双指针 O(n) 解法——这就是排序的动机。
2. **「不重复」这个约束，在有序数组上变得可操作**。乱序时判断「这个三元组之前出现过吗」需要哈希集合存整个三元组；排序后，相同的值必然相邻，只要在枚举时跳过相邻重复值，重复三元组从源头上就不会产生。

所以整条路线的骨架是：**排序 → 固定一个数 → 双指针找另外两个 → 三处去重**。

## 3. 从暴力到最优

**第一步：消掉一重循环（O(n³) → O(n²)）**

固定 `i`，剩下就是「在 `nums[i+1:]` 中找两数之和 = `-nums[i]`」。如果这段是有序的，用左右指针 `l`、`r` 从两端向中间夹：和太大就 `r--`，和太小就 `l++`。每个元素最多被访问一次，单次 O(n)。外层 n 次，总计 O(n²)。

**第二步：排序的代价与收益**

排序 O(n log n)，被 O(n²) 完全吞掉，不增加量级。收益是双指针可行 + 去重变简单。

**第三步：去重（这是本题真正的坑）**

用示例 1 走一遍：`nums = [-1,0,1,2,-1,-4]`，排序后 `[-4,-1,-1,0,1,2]`。

- `i=0`，`nums[i]=-4`，目标 `4`。`l=1(-1)`，`r=5(2)`，和 `1 < 4` → `l=2`；`-1+2=1<4` → `l=3`；`0+2=2<4` → `l=4`；`1+2=3<4` → `l=5`，`l>=r` 结束。无解。
- `i=1`，`nums[i]=-1`，目标 `1`。`l=2(-1)`，`r=5(2)`，和 `1 == 1` → 记录 `[-1,-1,2]`，然后 `l=3`、`r=4`。此时 `0+1=1` → 记录 `[-1,0,1]`，`l=4`、`r=3`，结束。
- `i=2`，`nums[i]=-1`，**和 i=1 的值相同**。如果继续算，会再次得到 `[-1,-1,2]` 和 `[-1,0,1]`。所以这里必须 `continue`。
- `i=3`，`nums[i]=0`，目标 `0`。`l=4(1)`，`r=5(2)`，和 `3 > 0` → `r=4`，`l>=r` 结束。

结果 `[[-1,-1,2],[-1,0,1]]`，与期望一致。

注意 `i=1` 那一轮里，`l` 从 2 开始（`nums[2]` 也是 `-1`），这正好允许了三元组里出现两个 `-1`——**外层去重和内层去重是两套逻辑，不能混**。

## 4. 正确性：为什么不会漏、不会重

**不漏（完备性）**：任取一个合法三元组，把它的三个值排序后记为 `a ≤ b ≤ c`。由于整个数组已排序，在枚举到 `i` 指向「值为 `a` 的最后一个位置之前」的某个位置时（具体说，是 `a` 第一次出现的位置），`b` 和 `c` 都位于 `i` 右侧。双指针在 `[i+1, n-1]` 上做标准的「两数之和」搜索，而该搜索对有序数组是完备的：若当前 `l+r` 偏小，则 `l` 与任何 `≤ r` 的位置组合都偏小，只能右移 `l`；偏大同理。因此 `(b,c)` 一定会被某一对 `(l,r)` 命中。

**不重（无重复）**：分三层论证。
- 外层：若 `i>0` 且 `nums[i]==nums[i-1]`，跳过。这保证每个「作为最小值的不同数值」只被当作起点一次。
- 内层命中后：`l` 右移到第一个不等于当前值的位置，`r` 左移到第一个不等于当前值的位置。这保证在同一个 `i` 下，同一对 `(b,c)` 只被记录一次。
- 跨层：不同 `i` 对应的三元组最小值不同（因为外层已去重），故不可能重复。

**不变量**：在双指针循环的任意时刻，`[i+1, l)` 内的元素与任何右侧元素组合都已被排除，`(r, n-1]` 同理。循环结束时所有候选对被穷尽。

## 5. 完整代码（Python）

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        nums.sort()                      # 排序是双指针和去重的前提
        n = len(nums)
        res = []

        for i in range(n - 2):           # 至少留两个位置给 l、r
            # 剪枝：最小值已 > 0，后面不可能凑出 0
            if nums[i] > 0:
                break
            # 外层去重：跳过与前一个起点相同的值
            if i > 0 and nums[i] == nums[i - 1]:
                continue

            target = -nums[i]
            l, r = i + 1, n - 1
            while l < r:
                s = nums[l] + nums[r]
                if s < target:
                    l += 1               # 和偏小，左指针右移增大和
                elif s > target:
                    r -= 1               # 和偏大，右指针左移减小和
                else:
                    res.append([nums[i], nums[l], nums[r]])
                    # 内层去重：跳过相同的 l 值
                    while l < r and nums[l] == nums[l + 1]:
                        l += 1
                    # 内层去重：跳过相同的 r 值
                    while l < r and nums[r] == nums[r - 1]:
                        r -= 1
                    # 命中后两指针同时收缩，继续找下一对
                    l += 1
                    r -= 1
        return res
```

## 6. 复杂度

- **时间 O(n²)**：排序 O(n log n)；外层循环最多 n 次，每次内层双指针在 `[i+1, n-1]` 上最多走 n 步，故 O(n²)。总复杂度由 O(n²) 主导，`n log n` 被吸收。
- **空间 O(log n) 到 O(n)**：取决于排序实现（Python 的 Timsort 最坏 O(n) 辅助空间）。返回值 `res` 不计入算法空间；若计入，最坏 O(n²) 个三元组。除排序外没有额外数据结构，这是它优于哈希解法的点。

## 7. 边界与反例（至少 4 条）

1. `nums = [0,0,0]` → `[[0,0,0]]`。容易错在：内层去重时 `l` 和 `r` 都指向同一个 0 附近，若去重循环写成 `while nums[l]==nums[l+1]` 而不加 `l<r` 保护，会越界或死循环。
2. `nums = [0,0,0,0]` → `[[0,0,0]]`。容易错在：只做外层去重、不做内层去重，会输出多个 `[0,0,0]`。
3. `nums = [-2,0,1,1,2]` → `[[-2,0,2],[-2,1,1]]`。容易错在：命中 `[-2,1,1]` 后若只移动 `l` 不移动 `r`，会漏掉后续组合或重复记录。
4. `nums = [1,2,-2,-1]` → `[]`。容易错在：忘记排序就直接双指针，指针移动方向失去意义，结果错误。
5. `nums = [-1,-1,-1,2]` → `[[-1,-1,2]]`。容易错在：外层去重把 `i=1` 的 `-1` 跳过后，若误以为「所有 `-1` 都处理完了」，会漏解——实际上 `i=0` 那一轮已经覆盖了 `[-1,-1,2]`，跳过是对的，但需要理解为什么对。

## 8. 面试追问与变体（3 条）

1. **「如果要求和为任意 target 而不是 0 呢？」** 思路：把 `target = -nums[i]` 换成 `target - nums[i]`，其余不变；但剪枝 `nums[i] > 0` 要改成 `nums[i] > target` 且需考虑负数情况，不能简单 break。
2. **「不允许排序（比如输入是只读流），怎么做？」** 思路：用哈希集合做两数之和，外层枚举 `i`、内层枚举 `j`，用 `set` 存已见过的值找 `-(nums[i]+nums[j])`；去重靠把三元组排序后转 tuple 存入结果集合，时间 O(n²)、空间 O(n²)。
3. **「返回三元组的个数而不是列表，能否 O(n²) 时间 O(1) 额外空间？」** 思路：仍排序 + 双指针，但命中时用「相同值的计数」直接算出这一对能贡献多少种组合，避免逐个 append。

## 9. 举一反三（2-3 道同类题）

- **两数之和 II（输入有序数组）**：本题内层双指针的原型，共同点是「有序 → 双指针夹逼」。
- **最接近的三数之和（LeetCode 16）**：同样排序 + 固定一个数 + 双指针，只是把「等于」换成「维护最小差值」。
- **四数之和（LeetCode 18）**：在三数之和外面再套一层循环，去重逻辑逐层复制，是检验「是否真正理解去重不变量」的试金石。
