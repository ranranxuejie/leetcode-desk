## 1. 一句话本质

把「把 n 个盘子从 A 搬到 C」这个动作，拆成「先搬 n-1 个到 B、再搬最大的到 C、最后把 n-1 个从 B 搬到 C」三个同构的子动作，递归到只剩一个盘子为止。

## 2. 读完题的第一反应

**朴素解法**：把每一步移动都当成一次选择——当前有 3 根柱子，最多 3 种「从哪搬到哪」的合法动作，于是可以暴力搜索所有移动序列，找到第一条能让 C 装满的路径。它卡在两处：一是状态空间是 3^n 量级（每个盘子可能在任意柱子上），搜索会爆炸；二是即使搜到，也没法保证是最短序列。提示里 n ≤ 14，3^14 ≈ 478 万，勉强能搜，但这不是出题人想要的答案。

**关键观察**：最大的那个盘子（编号 0，在 A 的最底下）**只有一次移动机会**——它必须从 A 直接到 C，而且移动它的那一刻，C 必须是空的、A 上面必须没有别的盘子。这意味着：在搬最大盘之前，n-1 个小盘必须全部堆在 B 上；搬完之后，这 n-1 个盘又必须从 B 整体搬到 C。于是原问题被拆成了两个规模为 n-1 的**同构子问题**，只是柱子角色换了。这个「最大盘把问题切成两半」的观察，就是递归的入口。

## 3. 从暴力到最优

暴力搜索的瓶颈是「每一步都要试 3 种动作」，而递归把「试」变成了「确定」：一旦决定搬最大盘，前 n-1 个盘的去向就被唯一确定了（必须去 B），不需要搜索。

用示例 1 走一遍：`A = [2, 1, 0]`（栈顶是 0，即最小盘），`B = []`，`C = []`。目标是把 A 整体搬到 C。

记 `move(n, src, mid, dst)` 表示把 src 顶上的 n 个盘搬到 dst，mid 作中转。

- `move(3, A, B, C)`：
  - 先 `move(2, A, C, B)`：把上面两个盘从 A 搬到 B，C 当临时柱。
    - `move(1, A, B, C)`：把盘 0 从 A 搬到 C。此时 `A=[2,1], B=[], C=[0]`。
    - 把盘 1 从 A 搬到 B。此时 `A=[2], B=[1], C=[0]`。
    - `move(1, C, A, B)`：把盘 0 从 C 搬到 B。此时 `A=[2], B=[1,0], C=[]`。
  - 把盘 2 从 A 搬到 C。此时 `A=[], B=[1,0], C=[2]`。
  - `move(2, B, A, C)`：把 B 上两个盘搬到 C，A 当临时柱。
    - `move(1, B, C, A)`：盘 0 从 B 搬到 A。此时 `A=[0], B=[1], C=[2]`。
    - 盘 1 从 B 搬到 C。此时 `A=[0], B=[], C=[2,1]`。
    - `move(1, A, B, C)`：盘 0 从 A 搬到 C。此时 `A=[], B=[], C=[2,1,0]`。

最终 `C = [2, 1, 0]`，与期望一致。注意每一步中间变量的值都写出来了，你可以对照着在纸上画三根柱子验证。

瓶颈被消掉的地方在于：暴力搜索要枚举「盘 0 去哪、盘 1 去哪……」，而递归只做一次决策——「最大盘什么时候搬」，其余全被这个决策推出来。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证。定义命题 P(n)：`move(n, src, mid, dst)` 执行完后，src 顶上的 n 个盘会按原顺序整体出现在 dst 上，且 mid 恢复原状、全程不违反「大盘在下」的规则。

对 n 归纳：

- **基础** n=1：直接把唯一盘从 src 弹出、压入 dst，合法且到达目标，P(1) 成立。
- **归纳**：假设 P(n-1) 成立，看 P(n)。第一步 `move(n-1, src, dst, mid)` 由归纳假设把上面 n-1 个盘整体搬到 mid，此时 src 只剩最大盘、dst 为空。第二步把最大盘从 src 搬到 dst——因为 dst 为空，一定合法。第三步 `move(n-1, mid, src, dst)` 由归纳假设把 n-1 个盘整体搬到 dst，此时 dst 上只有最大盘，任何盘压上去都合法。三步合起来，n 个盘整体到达 dst，P(n) 成立。

**不会漏**：每个盘都被「第一步搬小盘、第二步搬最大盘、第三步搬小盘」覆盖，没有盘被跳过。**不会重**：每个盘在每一层递归里恰好被搬一次，递归树是一棵满二叉树，叶子数 = 移动次数，每个叶子对应一次真实移动，一一对应。所以既不多搬也不少搬。

## 5. 完整代码（Python）

```python
from typing import List

class Solution:
    def hanota(self, A: List[int], B: List[int], C: List[int]) -> None:
        """
        原地修改三个栈。A 的栈顶是末尾元素（最小盘），
        目标是把 A 整体搬到 C，B 作中转。
        """
        def move(n: int, src: List[int], mid: List[int], dst: List[int]) -> None:
            # 递归出口：只剩一个盘，直接搬
            if n == 1:
                dst.append(src.pop())
                return
            # 第一步：把上面 n-1 个盘从 src 搬到 mid，dst 当临时柱
            move(n - 1, src, dst, mid)
            # 第二步：把最大的盘（此时 src 栈顶）搬到 dst
            dst.append(src.pop())
            # 第三步：把 n-1 个盘从 mid 搬到 dst，src 当临时柱
            move(n - 1, mid, src, dst)

        # 空栈直接返回，避免 n=0 时进入递归出口判断出错
        if not A:
            return
        move(len(A), A, B, C)
```

关键点：`src.pop()` 弹出的是栈顶（最小盘），`dst.append(...)` 压入后仍在栈顶，符合「小盘在上」的物理规则；三步的柱子角色在递归调用里通过参数顺序交换，代码本身不需要知道「谁是 A/B/C」。

## 6. 复杂度

**时间**：设 T(n) 为搬 n 个盘的移动次数，T(n) = 2·T(n-1) + 1，T(1) = 1，解得 T(n) = 2^n - 1。每次移动是 O(1) 的 `pop` + `append`，所以总时间 O(2^n)。这里的 n 来自盘子数，指数来自「每个盘都要被搬、且递归树是满二叉树」——叶子数就是移动次数。

**空间**：递归栈深度为 n（每层递归只压一个栈帧），所以递归空间 O(n)。三个列表本身是输入，原地修改不额外分配，不计入。注意这里**没有 log n**：盘子数 n 直接决定递归深度，不存在二分。

## 7. 边界与反例（至少 4 条）

1. **输入 `A = []`** → 期望 `C = []`，三栈都不动 → 容易错在没判空，`move(0, ...)` 会走进 `n == 1` 分支之外、直接执行 `move(-1, ...)` 导致无限递归或 `pop` 空栈报错。
2. **输入 `A = [0]`**（单盘）→ 期望 `C = [0]` → 容易错在把 `n == 1` 写成 `n == 0` 的出口，或忘记 `pop` 后 `append` 的顺序，导致盘「消失」。
3. **输入 `A = [1, 0]`**（示例 2）→ 期望 `C = [1, 0]` → 容易错在第一步 `move(1, A, C, B)` 的参数顺序写反，把盘 0 搬去了 C 而不是 B，导致最大盘 1 无法移动。
4. **输入 `A = [2, 1, 0]`**（示例 1，n=3）→ 期望 `C = [2, 1, 0]` → 容易错在第三步 `move(n-1, mid, src, dst)` 里把 `src` 和 `mid` 写反，导致中转柱用错、大盘压小盘。
5. **n = 14 的极限输入** → 期望 C 完整且顺序不变 → 容易错在递归深度或移动次数（2^14 - 1 = 16383 次）上没概念，误以为会超时；实际 1.6 万次操作在 Python 里毫秒级完成，但要确认没有写成 O(n·2^n) 的额外拷贝。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求输出每一步的移动记录（从哪根柱到哪根柱），怎么改？** 思路：在 `dst.append(src.pop())` 处加一条日志，记录 `(src 名字, dst 名字)`，柱子名字需要在递归参数里额外传字符串标识。
2. **追问：如果柱子变成 4 根，最少步数是多少？** 思路：这是 Frame–Stewart 算法，不能简单套 2^n，需要枚举「先把 k 个盘搬到辅助柱、再搬剩下的」，用 DP 求 min，复杂度从 O(2^n) 降到约 O(2^{n·log_3 2})。
3. **追问：不用递归，用栈模拟递归过程怎么写？** 思路：把 `(n, src, mid, dst, 阶段)` 压入显式栈，阶段 0/1/2 分别对应「搬 n-1 到 mid」「搬最大盘」「搬 n-1 到 dst」，出栈时按阶段推进，避免系统递归栈溢出。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 21. 合并两个有序链表**：共同点是「把大问题拆成同构子问题」——合并两个链表 = 选较小的头 + 递归合并剩余部分，和汉诺塔的「最大盘切两半」是同一套递归思维。
2. **LeetCode 206. 反转链表**：共同点是递归出口 + 子问题同构，`reverse(head.next)` 返回已反转的尾部，再把 head 接到尾部，和汉诺塔「先搬 n-1、再处理最大盘」结构一致。
3. **LeetCode 50. Pow(x, n)**：共同点是递归拆分规模，`x^n = x^{n/2} · x^{n/2}`，和汉诺塔的 T(n) = 2T(n-1) + 1 一样，都是「把规模减半/减一后合并」，可以用来对比指数级与对数级递归的差别。
