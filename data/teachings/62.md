## 1. 一句话本质

在只允许「向右 / 向下」两种步子的约束下，数从网格左上角走到右下角的所有**步序方案数**——本质是数「m-1 个向下」和「n-1 个向右」的排列组合数。

## 2. 读完题的第一反应

**朴素解法**：把每条路径当成一条搜索分支，从起点 DFS，每步尝试向右或向下，走到终点就计数 +1。

它卡在哪？路径条数本身就是答案，而答案最大接近 2×10⁹（题面提示给了这个上界）。也就是说 DFS 的叶子数就是答案量级，时间复杂度直接是 O(答案)，最坏 10⁹ 级别，必然超时。**瓶颈不在「搜索得慢」，而在「你在逐条枚举答案本身」**——当答案是指数量级时，任何逐条枚举的写法都救不回来。

**关键观察**：不管怎么走，从 (0,0) 到 (m-1,n-1) 一定恰好走 (m-1) 步向下、(n-1) 步向右，总步数固定为 m+n-2。于是「一条路径」和「一个由 D/R 组成的定长序列」一一对应。这就把「枚举路径」转化成了「数序列」，而数序列可以用**递推**做：到达某个格子的路径数，只取决于它上面格子和左边格子——因为机器人只能从这两个方向进来。

这个观察之所以能引出下一步：一旦你意识到「到达 (i,j) 的方案数 = 到达 (i-1,j) 的方案数 + 到达 (i,j-1) 的方案数」，你就从「枚举」跳到了「状态转移」，复杂度从 O(答案) 降到 O(mn)。

## 3. 从暴力到最优

**第一步：DFS 暴力。** 每个格子两个分支，深度 m+n-2，叶子数就是答案。以 m=3,n=2 为例，答案是 3，DFS 会走 3 条完整路径、外加若干中途死路，能跑；但 m=n=100 时答案约 10⁵⁸ 量级（题面保证实际测试 ≤2×10⁹，但中间规模仍可能很大），枚举不可行。

**第二步：发现重叠子问题。** 在 DFS 里，从 (1,1) 出发的子问题会被从 (0,1) 和 (1,0) 两条来路各算一遍。这就是重复计算。把「从 (i,j) 到终点的路径数」记下来复用，就是记忆化。

**第三步：改成自底向上的 DP。** 定义 `dp[i][j]` = 到达格子 (i,j) 的路径数。转移：

```
dp[i][j] = dp[i-1][j] + dp[i][j-1]
```

边界：第一行只能一直向右来，`dp[0][j] = 1`；第一列只能一直向下来，`dp[i][0] = 1`。

**小例子走一遍 m=3, n=3：**

初始化第一行、第一列全为 1：

```
1 1 1
1 ? ?
1 ? ?
```

填 (1,1)：`dp[1][1] = dp[0][1] + dp[1][0] = 1 + 1 = 2`
填 (1,2)：`dp[1][2] = dp[0][2] + dp[1][1] = 1 + 2 = 3`
填 (2,1)：`dp[2][1] = dp[1][1] + dp[2][0] = 2 + 1 = 3`
填 (2,2)：`dp[2][2] = dp[1][2] + dp[2][1] = 3 + 3 = 6`

结果 6，与示例 4 一致。

**第四步：滚动数组压缩空间。** 注意到 `dp[i][j]` 只依赖「上一行同列」和「本行左一格」。所以只需要一维数组 `dp[j]`：遍历到第 i 行时，`dp[j]` 里存的还是上一行的值（即 `dp[i-1][j]`），而 `dp[j-1]` 已经被本行更新过（即 `dp[i][j-1]`）。于是原地更新：

```
dp[j] = dp[j] + dp[j-1]
```

空间从 O(mn) 降到 O(n)。以 m=3,n=3 走一遍：初始 `dp = [1,1,1]`（第一行）。i=1 时 j 从 1 到 2：`dp[1]=1+1=2`，`dp[2]=1+2=3`，得 `[1,2,3]`。i=2 时：`dp[1]=2+1=3`，`dp[2]=3+3=6`，得 `[1,3,6]`，答案 `dp[2]=6`。正确。

## 4. 正确性：为什么不会漏、不会重

用**路径分类 + 不变量**来论证。

**不变量**：对任意格子 (i,j)，`dp[i][j]` 的值恒等于「从起点到 (i,j) 的所有合法路径条数」。

**归纳证明**：

- 基础：第一行 / 第一列的格子，合法路径只有唯一一条（全向右或全向下），`dp` 置 1，不变量成立。
- 归纳步：考虑任意 (i,j)（i≥1 且 j≥1）。任何一条到达 (i,j) 的路径，其**最后一步**要么是从 (i-1,j) 向下走来的，要么是从 (i,j-1) 向右走来的，二者必居其一且不可兼得（最后一步的方向唯一）。因此所有路径被**不重不漏**地分成两类：以「向下」结尾的、以「向右」结尾的。前者的条数恰为 `dp[i-1][j]`，后者恰为 `dp[i][j-1]`（由归纳假设）。相加即得 `dp[i][j]`，不变量保持。

「不重」由「最后一步方向唯一」保证，「不漏」由「最后一步只能是这两个方向之一」保证。归纳到 (m-1,n-1) 即得答案正确。

## 5. 完整代码（Python）

```python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        # 用较短的一维做滚动数组，空间取 O(min(m, n))
        # 这里固定按「列数 n」建数组，若 n 更大可交换 m、n（答案对称）
        if n > m:
            m, n = n, m

        # dp[j] 表示「当前行第 j 列」的路径数
        # 初始化为第一行：只能一直向右，故全为 1
        dp = [1] * n

        # 从第二行开始逐行向下推
        for i in range(1, m):
            # 第 0 列只能一直向下，恒为 1，无需更新
            for j in range(1, n):
                # 原地更新：等号右边的 dp[j] 还是上一行的值（从上下来）
                # dp[j-1] 已被本行更新过（从左来）
                dp[j] = dp[j] + dp[j - 1]

        # 右下角的值即为答案
        return dp[n - 1]
```

说明：`if n > m: m, n = n, m` 利用了答案对 m、n 对称（示例 1 与示例 3 都是 28 就是佐证），把数组长度压到较小维，空间 O(min(m,n))。若不想引入这个技巧，删掉交换、直接 `dp = [1]*n` 也完全正确，只是空间是 O(n)。

## 6. 复杂度

**时间 O(m·n)**：外层循环 m-1 次、内层 n-1 次，每次 O(1) 加法。m、n 各贡献一个因子，乘积即总操作数。没有 log 项，因为没有任何分治或二分结构。

**空间 O(min(m,n))**：滚动数组只保留一行，长度取 min(m,n)（由上面的交换保证）。若不做交换则是 O(n)。原始二维 DP 是 O(mn)，压缩后消掉了一个维度。

## 7. 边界与反例（至少 4 条）

1. **m=1, n=1** → 期望 1 → 起点即终点，只有「空路径」一条。容易错在循环边界写成 `range(1, m)` 时若 m=1 直接不进循环，返回 `dp[0]=1`，恰好对；但若有人把 `dp` 初始化成 `[0]*n` 再手动填，就会漏掉这个 case 返回 0。
2. **m=1, n=5** → 期望 1 → 只有一行，只能一路向右。容易错在把第一行初始化成 0 或忘记第一行全为 1。
3. **m=5, n=1** → 期望 1 → 只有一列。容易错在滚动数组里第 0 列恒为 1 这个隐含约定被破坏（比如误在循环里更新 `dp[0]`）。
4. **m=3, n=2** → 期望 3（示例 2）→ 小规模验证转移是否正确。容易错在把 `dp[i][j] = dp[i-1][j] + dp[i][j-1]` 写成乘法或漏掉某个方向。
5. **m=100, n=100** → 期望值很大但题面保证 ≤2×10⁹ → 容易错在用 DFS 枚举导致超时，或误以为结果会溢出 Python int（Python 无溢出问题，但换 C++ 需注意用 long long 或题面保证范围内用 int）。

## 8. 面试追问与变体（3 条）

1. **追问：如果网格中有障碍物（对应力扣 63 题），怎么改？** 思路：转移不变，但遇到障碍格时 `dp[j] = 0`（该格不可达），且第一行/第一列遇到障碍后其后全部置 0。
2. **追问：如果允许向上、向左走（即可以绕路），答案还是有限吗？** 思路：不限步数时会无限多（可绕圈），必须加「每格最多访问一次」或「总步数上限」约束，问题性质变成计数简单路径，通常 NP 难，需换思路。
3. **追问：能不能不用 DP，直接用组合数公式？** 思路：答案 = C(m+n-2, m-1)，从总步数里选哪些步向下。用 Python 的 `math.comb` 一行搞定，时间 O(min(m,n)) 级别（大数乘法），但要注意这是「数学捷径」，面试官往往想看你是否理解 DP 的推导。

## 9. 举一反三（2-3 道同类题）

- **力扣 63. 不同路径 II**：在本题基础上加障碍物，转移方程不变，只是障碍格强制为 0，考的是边界处理。
- **力扣 64. 最小路径和**：同样是「只能向右/向下」的网格 DP，但目标从「计数」变成「求最小和」，转移从加法变 `min`，是同一套状态设计的换目标版本。
- **力扣 120. 三角形最小路径和**：网格形状变成三角形、方向变成「向下/向右下」，本质仍是「每格只从有限前驱转移」的路径 DP，练的是把二维网格 DP 迁移到非矩形结构。
