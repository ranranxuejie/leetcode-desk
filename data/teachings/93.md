## 1. 一句话本质

在字符串的 n-1 个空隙里挑 3 个位置插入点号，使得切出的 4 段数字串每一段都合法（0~255、无前导零），枚举所有这样的切法。

## 2. 读完题的第一反应

最朴素的想法：从 n-1 个空隙里选 3 个，组合数 C(n-1, 3)。n ≤ 20 时最多 C(19,3)=969 种，每种再花 O(n) 校验四段，总共不到 2 万次操作——其实暴力枚举空隙完全跑得动。所以这道题的"瓶颈"不是复杂度，而是**怎么写得不重不漏、不写一堆嵌套判断**。

关键观察有两条，都直接来自题面：

- 题面说"正好由四个整数"——段数是**固定**的 4，不是任意段数。这告诉我们递归深度是常数 4，天然适合"每层决定一段"的回溯框架。
- 题面说"不能含有前导 0"且"0 到 255"——每段的长度被卡死在 **1~3 个字符**。因为 4 位数最小是 1000 > 255，而前导零规则又禁止 "01" 这种两位以上的零开头串。

这两条合起来意味着：在回溯的每一层，当前段只有 3 种候选长度（1、2、3），分支因子是常数。于是"选 3 个空隙"的组合同构于"每层试 3 种长度、走 4 层"，搜索树规模 ≤ 3^4 = 81，比 C(19,3) 还小，而且**天然按顺序切分、不会重复**。这就是从"枚举空隙"转向"逐段回溯"的动机。

## 3. 从暴力到最优

**暴力版**：`itertools.combinations(range(1, n), 3)` 枚举三个切点，切成四段，逐段校验。能过，但有两个毛病：一是切点可能产生长度 >3 的段，白算；二是四段校验要写四遍或循环，代码不优雅。

**回溯版**：把"选切点"改成"从当前位置 start 开始，决定这一段取多长"。

用示例 3 `s = "101023"`（n=6）走一遍，看中间变量：

```
dfs(start=0, parts=[], path="")
  试 len=1: 段="1" 合法 → dfs(1, ["1"], "1.")
    试 len=1: 段="0" 合法 → dfs(2, ["1","0"], "1.0.")
      试 len=1: 段="1" 合法 → dfs(3, ["1","0","1"], "1.0.1.")
        试 len=1: 段="0" → dfs(4, 4段, "1.0.1.0.")  start=4≠6，且已4段 → 剪枝
        试 len=2: 段="02" 前导零 → 非法
        试 len=3: 越界（4+3>6）
      试 len=2: 段="10" 合法 → dfs(4, ["1","0","10"], "1.0.10.")
        试 len=1: 段="2" → dfs(5, 4段) start=5≠6 剪枝
        试 len=2: 段="23" → dfs(6, 4段) start=6==6 ✓ 收集 "1.0.10.23"
      ...
```

关键剪枝点：**当已经切出 4 段但 start 还没到末尾，直接返回**；**当剩余字符数不足以填满剩余段（每段至少 1 个字符）或超过剩余段能容纳的最大长度（每段至多 3 个），也返回**。后一条是"可行性剪枝"，比如 `dfs(4, 3段)` 时还剩 2 个字符却要切 1 段，可以；但若还剩 5 个字符要切 1 段，直接砍掉。

## 4. 正确性：为什么不会漏、不会重

**不漏（完备性）**：任何一个合法 IP 都对应 s 的一个唯一切分——4 段、每段长度 1~3、每段数值合法。回溯在每一层枚举了当前段所有可能的长度 1、2、3，所以这个切分的每一段长度都在枚举范围内；只要该切分合法，路径上的每次 `is_valid` 判断都会通过，最终必然被收集。归纳一下：设合法解的第 i 段长度为 L_i，则第 i 层枚举到 len=L_i 时不会被剪枝，递归继续，直到第 4 层 start 恰好等于 n。

**不重（唯一性）**：不变量是——**在任意时刻，`path` 是 s 的一个前缀的合法切分，且切点位置由 `start` 唯一确定**。因为每层只从 `start` 往后取连续字符，不同层的 len 选择产生不同的 `start` 递进序列，也就对应不同的切点集合。两个不同的搜索路径不可能到达同一个 `(start, 段数)` 状态并产生相同切分，因为切点集合不同。所以每个合法 IP 恰好被一条路径生成一次。

**剪枝不误伤**：`start == n` 且段数 == 4 才收集；段数 == 4 但 `start < n` 时，剩余字符无处安放，任何延伸都不合法，剪掉安全。剩余字符数 < 剩余段数 或 > 3×剩余段数 时，无论怎么切都填不满或塞不下，剪掉也安全。

## 5. 完整代码（Python）

```python
class Solution:
    def restoreIpAddresses(self, s: str) -> list[str]:
        n = len(s)
        res = []
        parts = []          # 当前已确定的段，元素是字符串

        def is_valid(seg: str) -> bool:
            # 长度 1~3；无前导零（长度>1 时不能以 '0' 开头）；数值 <= 255
            if len(seg) == 0 or len(seg) > 3:
                return False
            if len(seg) > 1 and seg[0] == '0':
                return False
            return int(seg) <= 255

        def dfs(start: int):
            # 剪枝：剩余段数 = 4 - len(parts)，剩余字符数必须在 [剩余段数, 3*剩余段数]
            remain_seg = 4 - len(parts)
            remain_char = n - start
            if remain_char < remain_seg or remain_char > 3 * remain_seg:
                return
            # 终止：4 段且恰好用完
            if len(parts) == 4:
                if start == n:
                    res.append(".".join(parts))
                return
            # 枚举当前段长度 1~3
            for length in range(1, 4):
                if start + length > n:
                    break
                seg = s[start:start + length]
                if not is_valid(seg):
                    # 注意：不能 break。比如 "01" 非法但 "0" 合法，
                    # 但这里 length 递增，若当前段以 '0' 开头且 length>1 才非法，
                    # 而 length=1 的 "0" 已在上轮试过，所以可以 continue 继续试更长？
                    # 更稳妥：continue，让 is_valid 自己判断。
                    continue
                parts.append(seg)
                dfs(start + length)
                parts.pop()   # 回溯，恢复现场

        dfs(0)
        return res
```

补充说明上面注释里的那个易错点：`is_valid` 对 "0" 返回 True、对 "01" 返回 False。由于 length 从 1 递增，如果 length=1 的 "0" 合法，会先走那条分支；length=2 的 "01" 被 `continue` 跳过，不影响 length=3 的判断（"012" 同样非法）。所以用 `continue` 是安全的，用 `break` 反而可能误伤——但本题中一旦某段以 '0' 开头，length≥2 全非法，`break` 其实也行。为通用性保留 `continue`。

## 6. 复杂度

**时间**：搜索树每层分支 ≤ 3，深度固定 4，节点数 ≤ 1+3+9+27+81 ≈ 121，每个节点做一次长度 ≤3 的字符串切片和 `int()` 转换，是 O(1)。所以总时间是 **O(1)**（相对于 n 是常数上界），更严谨地写成 O(3^4 · 4) = O(1)。注意：这里**没有** n 的因子进入时间复杂度，因为深度被"4 段"钉死了。如果题目改成"切成 k 段"，才会变成 O(3^k · k)。

**空间**：递归栈深度固定 4，`parts` 长度 ≤4，路径字符串总长 ≤ n+3。结果集最多 81 个字符串，每个长度 O(n)。所以**不计结果**是 O(1) 额外空间（栈+临时串），**计结果**是 O(答案个数 × n) = O(81n)。面试时建议两个都报，并说明"结果本身占的空间"。

## 7. 边界与反例（至少 4 条）

1. `s = "0000"` → `["0.0.0.0"]`。易错点：把 "00" 当成合法段（前导零），或把 "000" 当合法段；必须靠 `len>1 and seg[0]=='0'` 拦住。
2. `s = "1111"` → `["1.1.1.1"]`。易错点：长度刚好 4，每段只能 1 位；若剪枝写成 `remain_char > 3*remain_seg` 漏了等号边界，或 `start+length > n` 判断写反，会漏解。
3. `s = "25525511135"` → 两个解。易错点：`"25525511135"` 长度 11，若忘记"剩余字符数 ≤ 3×剩余段数"的剪枝，会尝试切出 `"2552"` 这种 4 位段；`is_valid` 里 `len>3` 必须拦住。
4. `s = "101023"` → 5 个解。易错点：`"1.0.102.3"` 里 `"102"` 合法但 `"023"` 非法（前导零），若 `is_valid` 只判 `int<=255` 不判前导零，会多出 `"1.0.10.23"` 之外的错误解如 `"1.0.102.3"` 是对的、但 `"1.0.10.23"` 也对——真正会错的是把 `"023"` 当合法。
5. `s = "12345678901234567890"`（长度 20）→ `[]`。易错点：长度 20 > 4×3=12，第一层剪枝就该返回空；若没写"剩余字符数上限"剪枝，会白跑很多分支（虽不超时，但暴露思路不完整）。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求切成 k 段（k 由输入给定），怎么改？** 思路：把硬编码的 4 换成参数 k，剪枝条件改成 `remain_char` 在 `[remain_seg, 3*remain_seg]` 之间，终止条件改成 `len(parts)==k and start==n`；复杂度变成 O(3^k · k)。
2. **追问：如果允许段值范围是 0~999（即每段最多 3 位但上限变了），怎么改？** 思路：只改 `is_valid` 里的上限常量，其余不动；说明"长度约束"和"数值约束"是解耦的两件事。
3. **追问：如何只返回解的个数，不返回具体字符串？** 思路：把 `res.append` 换成计数器 `self.count += 1`，空间降到 O(1)（不计栈），时间不变；进一步可用 DP 预处理"从 i 开始切 j 段的方案数"做到 O(n·k)。
