## 1. 一句话本质

统计字符串里所有「以某个位置为中心、向两边对称展开能对上」的连续片段的个数——注意中心可以是单个字符（奇数长度），也可以是两个字符之间的缝（偶数长度）。

## 2. 读完题的第一反应

最直白的做法：枚举所有子串（起点 i、终点 j，共 O(n²) 个），每个子串再花 O(n) 判断是否回文，总复杂度 O(n³)。n=1000 时是 10⁹ 量级，Python 里必超时。

瓶颈在哪？在于「判断回文」和「枚举子串」这两件事被拆开做了，每次判断都从头比一遍，前面的信息全浪费了。

关键观察：**回文串去掉首尾两个字符，剩下的仍是回文串**。反过来，如果 `s[i+1..j-1]` 是回文，且 `s[i] == s[j]`，那 `s[i..j]` 就是回文。这意味着回文性可以「由内向外」递推，不必每次重新验证。

更进一步的观察（也是本题最省事的切入点）：**任何一个回文子串，都由它的「中心」唯一确定**。中心只有 2n-1 个（n 个字符中心 + n-1 个缝隙中心）。从每个中心向两边扩展，一旦左右字符不相等就停——停之前扩展出的每一步都是一个回文子串。这样每个回文子串恰好被它的中心「认领」一次，天然不重不漏。

## 3. 从暴力到最优

**暴力 O(n³)**：三重循环，i、j 枚举端点，k 从两端往中间比。对 `s = "aaa"`，会反复判断 "a"、"aa"、"aaa" 等，大量重复。

**中心扩展 O(n²)**：外层枚举 2n-1 个中心，内层向两边扩。以 `s = "aaa"` 走一遍：

- 中心 = 下标 0（字符 'a'）：`l=r=0`，`s[0]==s[0]` 成立，计数 +1 → count=1；下一步 `l=-1` 越界，停。
- 中心 = 下标 0 和 1 之间的缝：`l=0, r=1`，`s[0]==s[1]`（'a'=='a'）成立，count=2；下一步 `l=-1` 越界，停。
- 中心 = 下标 1：`l=r=1`，成立，count=3；扩到 `l=0,r=2`，`s[0]==s[2]` 成立，count=4；再扩越界，停。
- 中心 = 缝 1|2：`l=1,r=2`，成立，count=5；再扩越界，停。
- 中心 = 下标 2：`l=r=2`，成立，count=6；扩到 `l=1,r=3` 越界，停。

结果 6，和示例一致。注意每个中心扩展时，**每成功一步就 +1**，而不是扩展完再算长度——因为从中心往外，长度 1、3、5…（或 2、4、6…）的每个前缀都是回文。

**还能不能更好？** 有 Manacher 算法可以做到 O(n)，但它常数大、实现绕，n≤1000 时中心扩展完全够用（10⁶ 次操作）。面试里先写中心扩展，被追问「能不能线性」再提 Manacher 即可。动态规划也是 O(n²)，但要多开一个 n×n 的表，空间不如中心扩展的 O(1) 划算。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。

**不漏**：任取一个回文子串 `s[i..j]`，设其长度为 L。若 L 为奇数，取中心 `c=(i+j)/2`（整数），它属于「字符中心」那一类；若 L 为偶数，取中心缝 `(i+j+1)/2` 对应的那条缝，属于「缝隙中心」那一类。从该中心向外扩展时，由于 `s[i..j]` 是回文，对任意 `0≤k≤(L-1)/2` 都有 `s[c-k]==s[c+k]`（偶数情形同理），所以扩展过程一定能走到 `l=i, r=j` 这一步，中途不会提前停。因此这个子串被计入。

**不重**：每个回文子串的中心是唯一的（奇数长度中心是中间那个字符，偶数长度中心是中间那条缝），而我们的外层循环对每个中心只跑一次扩展，所以同一个子串只会在它自己中心的那一轮被数到一次。

**计数正确**：扩展循环的写法是「每成功匹配一对就 count+=1 再继续」，等价于「以该中心为心的回文子串个数 = 扩展成功的步数」。因为从中心出发，第 1 步对应长度 1（或 2）的回文，第 2 步对应长度 3（或 4）的回文……每一步恰好对应一个以该中心为心的回文子串，且这些子串两两不同（长度不同）。所以累加即得总数。

## 5. 完整代码（Python）

```python
class Solution:
    def countSubstrings(self, s: str) -> int:
        n = len(s)
        count = 0

        def expand(l: int, r: int) -> int:
            """从中心 (l, r) 向两边扩展，返回以该中心为心的回文子串个数。
            l == r 表示奇数长度中心；l + 1 == r 表示偶数长度中心（缝隙）。"""
            cnt = 0
            # 只要不越界且两端字符相等，就说明当前 [l, r] 是回文
            while l >= 0 and r < n and s[l] == s[r]:
                cnt += 1      # 每成功一步，就多一个以该中心为心的回文子串
                l -= 1        # 左指针外扩
                r += 1        # 右指针外扩
            return cnt

        for center in range(n):
            # 奇数长度：中心是单个字符 s[center]
            count += expand(center, center)
            # 偶数长度：中心是 s[center] 与 s[center+1] 之间的缝
            count += expand(center, center + 1)

        return count
```

关键点：`expand(center, center+1)` 在 `center = n-1` 时 `r = n`，while 条件第一项就为假，直接返回 0，不会越界，所以不需要额外特判。

## 6. 复杂度

- **时间 O(n²)**：外层循环 n 次，每次调用两次 `expand`。单次 `expand` 最多扩展 `min(l+1, n-r)` 步，最坏情况（如全 'a' 串）从中心扩到边界约 n/2 步。所以总操作数上界是 `n × 2 × (n/2) = O(n²)`。这里的 n 来自「中心个数 O(n)」乘「每个中心最多扩 O(n) 步」。
- **空间 O(1)**：只用了 `count`、`l`、`r`、`cnt` 几个整型变量，没有随 n 增长的数组。递归？这里 `expand` 是普通函数调用，不是递归，栈深度恒定。没有 log n 项——本题不涉及分治或二分。

## 7. 边界与反例（至少 4 条）

1. `s = "a"` → 期望 1 → 容易错在：偶数中心 `expand(0, 1)` 中 `r=1` 越界，若 while 写成先访问 `s[r]` 再判越界就会 IndexError。正确写法是 `r < n` 放在 `and` 前面短路。
2. `s = "ab"` → 期望 2（"a"、"b"）→ 容易错在：误以为 "ab" 也算，或漏掉偶数中心那轮（`expand(0,1)` 返回 0 是对的，但奇数中心必须都数到）。
3. `s = "aaaa"` → 期望 10 → 容易错在：只数奇数长度（4 个单字符 + "aaa" 两个 = 6），漏掉偶数长度的 "aa"×3 和 "aaaa"×1。必须两个 `expand` 都调用。
4. `s = "aba"` → 期望 4（"a"、"b"、"a"、"aba"）→ 容易错在：中心扩展时在 `s[0]==s[2]` 成功后忘记继续外扩判断越界，或提前 return 导致漏数。
5. `s = "abcba"` → 期望 7 → 容易错在：动态规划写法里初始化 `dp[i][i]=True` 后忘记处理长度 2 的 `dp[i][i+1]`，导致长度 3 以上的递推全错。中心扩展法没有这个坑。

## 8. 面试追问与变体（3 条）

1. **追问：能不能做到 O(n)？** → 思路：Manacher 算法，在字符间插入分隔符（如 `#`）把奇偶统一，维护当前最右回文边界 `R` 和对应中心 `C`，利用对称性复用已算出的半径，总扩展次数均摊 O(n)。
2. **追问：返回最长回文子串而不是个数？** → 思路：中心扩展时记录 `r-l+1` 最大的那次，扩展结束后按记录的 `(l, r)` 切片返回；同样 O(n²) 时间 O(1) 空间。
3. **追问：判断 s 能否通过删除至多一个字符变成回文？** → 思路：双指针从两端向中间走，遇到不等时，分别尝试跳过左字符或右字符，看剩余子串是否回文，O(n)。

## 9. 举一反三（2-3 道同类题）

- **5. 最长回文子串**：和本题共用「中心扩展」骨架，只是把「计数」换成「记录最大长度及起止位置」。
- **516. 最长回文子序列**：同样利用「回文去掉首尾仍是回文」的递推性质，但子序列不要求连续，需用区间 DP `dp[i][j]`，是本题 DP 思路的推广。
- **131. 分割回文串**：先要能快速判断任意子串是否回文（可用本题的 DP 表预处理），再做回溯分割，是「回文判定」作为子问题的典型应用。
