## 1. 一句话本质

在数组里找「第一个缺席的正整数」——答案一定落在 `[1, n+1]` 这个区间内，所以问题等价于：**把 1..n 这些值尽可能「归位」到下标 0..n-1 上，然后看第一个没归位的下标是谁。**

## 2. 读完题的第一反应

**朴素解法**：从 `ans = 1` 开始，每轮扫一遍数组看 `ans` 在不在，不在就返回，在就 `ans += 1`。最坏情况（数组恰好是 `1..n`）要扫 n 轮，每轮 O(n)，总 O(n²)。瓶颈在于「查一个数在不在」这件事每次都要重新扫。

**第二反应**：用哈希集合把所有数装进去，然后从 1 开始逐个查，O(n) 时间。但题面明确要求「常数级别额外空间」，哈希表直接违规。

**关键观察**：题面给了两条硬约束——O(n) 时间、O(1) 空间。O(n) 时间意味着「每个元素只能被常数次访问」；O(1) 空间意味着「不能开新数组，只能在原数组上动手脚」。而原数组本身就有 n 个格子，正好能装下 1..n 这 n 个候选答案。于是自然的想法是：**把数组本身当成哈希表用**——让值 `v` 待在下标 `v-1` 的位置上。这样「值 v 是否存在」就变成了「下标 v-1 上的值是不是 v」，一次 O(1) 的比较就能回答。

这个观察是整道题的转折点：它把「额外空间」这个约束从障碍变成了提示——题目不让你开空间，就是在暗示你原地复用。

## 3. 从暴力到最优

**第一步：确定答案范围。** 数组长度是 n，最多能装 n 个不同的正整数。就算这 n 个位置恰好是 1..n，答案也是 n+1；否则答案一定 ≤ n。所以答案 ∈ [1, n+1]，我们只需要关心 1..n 这些值，**≤0 的和 >n 的数都是「垃圾」，可以直接无视**。这一步把问题规模从「值域 2³¹」压缩到「值域 n」。

**第二步：原地归位。** 遍历数组，对每个位置 i，如果 `nums[i]` 是一个「有效值」（即 `1 <= nums[i] <= n`）且它还没待在对的位置（`nums[i] != nums[nums[i]-1]`），就把它和 `nums[nums[i]-1]` 交换。交换后新到位置 i 的数可能仍然需要归位，所以用 `while` 而不是 `if` 反复处理，直到位置 i 上的数无效或已归位。

**第三步：扫描找答案。** 归位完成后，从左往右扫，第一个满足 `nums[i] != i+1` 的下标 i，答案就是 `i+1`。如果全部归位，答案是 `n+1`。

**小例子走一遍**：`nums = [3, 4, -1, 1]`，n = 4。

- i=0，`nums[0]=3`，有效且 `3 != nums[2]=-1`，交换 → `[-1, 4, 3, 1]`。现在 `nums[0]=-1` 无效，停。
- i=1，`nums[1]=4`，有效且 `4 != nums[3]=1`，交换 → `[-1, 1, 3, 4]`。现在 `nums[1]=1`，有效且 `1 != nums[0]=-1`，交换 → `[1, -1, 3, 4]`。现在 `nums[1]=-1` 无效，停。
- i=2，`nums[2]=3`，已归位（`3 == nums[2]`），停。
- i=3，`nums[3]=4`，已归位，停。

扫描：`nums[0]=1` ✓，`nums[1]=-1 != 2` ✗ → 返回 **2**。和示例一致。

注意 i=1 那一步：一次交换后新来的数 `1` 还需要继续归位，这就是 `while` 存在的理由。如果写成 `if`，这里就会漏掉，最终得到错误答案。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。

**不变量**：在 for 循环处理完下标 i 之后，位置 0..i 上所有「有效值」都已经归位，即对任意 `j <= i`，要么 `nums[j]` 是垃圾值（≤0 或 >n），要么 `nums[j] == j+1`。

**初始化**：i 从 0 开始，处理前无已处理位置，不变量平凡成立。

**保持**：处理位置 i 时，`while` 循环的终止条件正是「`nums[i]` 是垃圾 或 `nums[i] == i+1`」，所以退出时位置 i 满足不变量。而 `while` 内部的交换只把 `nums[i]` 换到它该去的位置 `nums[i]-1`（该位置 ≥ i，因为 `nums[i]-1 >= 0` 且当 `nums[i] != i+1` 时 `nums[i]-1 != i`，实际是 `> i` 或 `< i`；若 `< i` 说明那个位置早已归位，交换后 `nums[i]` 变成已归位的值，下一轮判断会因 `nums[i] == i+1` 而停），不会破坏已处理位置的不变量——因为交换的另一方位置 `nums[i]-1` 若 `< i`，它上面的值本来就是 `nums[i]`（已归位），换过去后位置 i 拿到的是正确值，位置 `nums[i]-1` 拿到的是 `nums[i]` 本身，不变。

**终止**：循环结束后，不变量覆盖整个数组。此时从左扫描，第一个 `nums[i] != i+1` 的位置 i，说明值 `i+1` 不在数组里（因为如果它在，按不变量它必须待在位置 i 上，矛盾）。而所有 `j < i` 的位置都满足 `nums[j] == j+1`，说明 1..i 全部出现过。所以 i+1 是**最小的缺失正整数**，不会漏（比它小的都出现了）也不会重（它是第一个没出现的）。

**为什么不会死循环**：每次交换都把 `nums[i]` 这个值送到它的「最终位置」，同一个值最多被送一次，总交换次数 ≤ n，所以 while 总轮数是 O(n) 级别的。

## 5. 完整代码（Python）

```python
class Solution:
    def firstMissingPositive(self, nums: list[int]) -> int:
        n = len(nums)

        for i in range(n):
            # 反复把 nums[i] 归位：值 v 应该待在下标 v-1
            # 三个条件缺一不可：
            #   1 <= nums[i] <= n  —— 只有这个范围的值才「值得」归位
            #   nums[i] != nums[nums[i] - 1] —— 目标位置已经是这个值了就不用换（也防止死循环）
            while 1 <= nums[i] <= n and nums[i] != nums[nums[i] - 1]:
                target = nums[i] - 1          # 该值应去的下标
                nums[i], nums[target] = nums[target], nums[i]

        # 归位完成后，第一个「位置 i 上不是 i+1」的地方就是答案
        for i in range(n):
            if nums[i] != i + 1:
                return i + 1

        # 1..n 全部出现，答案是 n+1
        return n + 1
```

两个容易踩的坑，代码里已经处理：

- `while` 里的第二个条件 `nums[i] != nums[nums[i]-1]` 不能省。如果目标位置已经是同一个值（比如数组里有重复的 `1`），交换会变成自己和自己换，永远不满足退出条件，死循环。
- 交换用 Python 的元组赋值，天然安全；如果写成 C 风格的三行交换，注意 `nums[i]` 在第一次赋值后已经变了，`target` 要提前存好。

## 6. 复杂度

**时间 O(n)**：外层 for 循环 n 次；内层 while 的每次交换都把某个值放到它的最终位置，而一个值一旦归位就不会再被换走（除非被别的值挤出来，但挤出来时它自己也归位了），所以总交换次数 ≤ n，while 总执行次数 O(n)。最后扫描 O(n)。合计 O(n)。

**空间 O(1)**：只用了 `n`、`i`、`target` 几个标量变量，没有开任何与 n 相关的容器。原地交换，复用输入数组。

对比一下：哈希表解法时间也是 O(n)，但空间 O(n)；排序解法空间 O(1)（原地排序）但时间 O(n log n)，log n 来自排序的比较次数。本题的解法同时压到了 O(n) 时间和 O(1) 空间，靠的就是「数组下标即哈希键」这个技巧。

## 7. 边界与反例（至少 4 条）

1. **`nums = [1]`** → 期望 `2`。容易错在：归位后 `nums[0]=1` 已归位，扫描全过，必须返回 `n+1=2`，而不是返回 1 或 0。忘记「全齐时答案是 n+1」这条分支就会错。

2. **`nums = [1, 1]`** → 期望 `2`。容易错在：`while` 条件漏掉 `nums[i] != nums[nums[i]-1]`，i=1 时 `nums[1]=1`，目标位置 `nums[0]=1` 已经是 1，交换变成自己换自己，死循环。这是本题最高频的 bug。

3. **`nums = [2, 1]`** → 期望 `3`。容易错在：i=0 时 `nums[0]=2` 和 `nums[1]=1` 交换得 `[1,2]`，两个都归位，扫描全过，返回 `n+1=3`。如果 while 写成 if，i=0 交换一次后 `nums[0]=1` 已归位没问题，但更复杂的排列（如 `[3,1,2]`）就会漏。

4. **`nums = [-1, -2, -3]`** → 期望 `1`。容易错在：所有值都是垃圾，归位阶段什么都不做，扫描时 `nums[0]=-1 != 1`，返回 1。正确。但如果代码里对负数做了 `abs` 或取模之类的「聪明」处理，反而会出错——负数就该被无视。

5. **`nums = [7, 8, 9, 11, 12]`** → 期望 `1`。所有值都 >n=5，全是垃圾，直接返回 1。容易错在：误以为要处理大数，或者把 `nums[i] <= n` 写成 `nums[i] < n`，边界差一。

## 8. 面试追问与变体（3 条）

1. **追问：如果允许 O(n) 额外空间，你会怎么做？** 思路：开一个长度为 n+1 的布尔数组，扫一遍标记出现过的值，再扫一遍找第一个 false。这是最直观的解法，面试时可以先说这个，再引出 O(1) 空间的优化，体现思考层次。

2. **追问：如果数组里有重复元素，你的算法还成立吗？** 思路：成立。重复值在归位时，第二个副本会发现目标位置已经是自己（`nums[i] == nums[nums[i]-1]`），while 直接退出，不会死循环也不会破坏正确性。可以拿 `[1,1]` 现场演示。

3. **追问：如果要求找「缺失的第一个非负整数」（包含 0）呢？** 思路：把归位规则改成「值 v 待在下标 v 上」，答案范围变成 `[0, n]`，扫描时找第一个 `nums[i] != i` 的位置 i，返回 i；全齐返回 n。本质不变，只是下标映射平移了一位。
