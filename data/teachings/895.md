## 1. 一句话本质

维护一个「按 (频率, 入栈时间) 双关键字排序」的动态集合，每次 pop 取出字典序最大的那个元素。

---

## 2. 读完题的第一反应

**朴素解法**：用一个列表当栈，push 直接 append。pop 时遍历整个列表统计每个值的频率，找出频率最高的；若并列，取下标最大的（最接近栈顶）。复杂度：push O(1)，pop O(n)（遍历统计）+ O(n)（找最大下标），总共 O(n)。n 次操作就是 O(n²)，n = 2×10⁴ 时约 4×10⁸，勉强能过但很不优雅，面试官不会满意。

**卡在哪**：pop 每次都要「重新统计频率」和「重新找最靠顶的并列者」，而这两件事在两次 pop 之间只发生了很小的变化（只少了一个元素）。重复计算是瓶颈。

**关键观察**：一个元素 `val` 被 push 第 k 次时，它的频率恰好变成 k。也就是说，**频率不是 pop 时才需要算的东西，而是 push 时就能确定的**。每次 push 我们立刻知道「这个元素当前的频率是几」。于是问题转化成：把所有 push 过的元素按「(频率, 入栈序号)」排序，pop 取最大。而频率只会随 push 单调 +1，入栈序号天然递增——这两个维度都是「只增不减」的，非常适合用**分组栈**来维护。

## 3. 从暴力到最优

### 暴力版

```python
class FreqStack:
    def __init__(self):
        self.stack = []
    def push(self, val):
        self.stack.append(val)
    def pop(self):
        freq = {}
        for v in self.stack:
            freq[v] = freq.get(v, 0) + 1
        max_f = max(freq.values())
        # 从右往左找第一个频率等于 max_f 的
        for i in range(len(self.stack) - 1, -1, -1):
            if freq[self.stack[i]] == max_f:
                return self.stack.pop(i)
```

瓶颈：每次 pop 都 O(n) 重扫。

### 优化第一步：把频率缓存下来

维护 `freq[val]`，push 时 `freq[val] += 1`，pop 时不用重算。但「找最大频率」和「在最大频率里找最靠顶的」还是要扫。先解决「找最大频率」：维护一个变量 `max_freq`，push 后更新 `max_freq = max(max_freq, freq[val])`。pop 之后 `max_freq` 可能下降，但下降多少？最多降 1——因为 pop 只移走一个元素，被移走元素的频率是 `max_freq`，移走后该频率的计数减一，若减到 0 则 `max_freq` 减 1，否则不变。这一步很关键。

### 优化第二步：按频率分组

现在还剩「在频率 = max_freq 的元素里找最靠顶的」。观察：**同一频率下的元素，谁后 push 谁就更靠顶**（因为中间没有别的操作改变它们的相对顺序）。所以对每个频率 f，维护一个栈 `group[f]`，push 时把 val 压入 `group[freq[val]]`。pop 时从 `group[max_freq]` 弹栈顶即可——栈顶天然就是「该频率下最晚入栈的」，也就是最靠顶的。

### 小例子走一遍

输入序列：push 5, push 7, push 5, push 7, push 4, push 5

| 操作 | freq | group | max_freq |
|---|---|---|---|
| push 5 | {5:1} | {1:[5]} | 1 |
| push 7 | {5:1,7:1} | {1:[5,7]} | 1 |
| push 5 | {5:2,7:1} | {1:[5,7], 2:[5]} | 2 |
| push 7 | {5:2,7:2} | {1:[5,7], 2:[5,7]} | 2 |
| push 4 | {5:2,7:2,4:1} | {1:[5,7,4], 2:[5,7]} | 2 |
| push 5 | {5:3,7:2,4:1} | {1:[5,7,4], 2:[5,7], 3:[5]} | 3 |

pop：`group[3]` 弹 5 → freq[5]=2，group[3] 空，max_freq 降为 2。返回 5 ✓
pop：`group[2]` 弹 7 → freq[7]=1，group[2] 剩 [5]，max_freq 仍 2。返回 7 ✓
pop：`group[2]` 弹 5 → freq[5]=1，group[2] 空，max_freq 降为 1。返回 5 ✓
pop：`group[1]` 弹 4（栈顶，最后入的）→ 返回 4 ✓

和示例输出完全一致。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在任意时刻，对任意频率 f，`group[f]` 中从栈底到栈顶恰好是「当前频率为 f 的所有元素，按它们达到频率 f 的先后顺序排列」。且 `max_freq` 等于当前所有元素频率的最大值。

**归纳证明**：

- 初始时所有 group 为空，max_freq = 0，不变量成立。
- push(val)：设 val 原频率为 k，新频率 k+1。它「达到频率 k+1」的时刻就是现在，所以压入 `group[k+1]` 栈顶，符合「按达到时刻排序」。其他 group 不受影响。max_freq 更新为 max(max_freq, k+1)，正确。
- pop：题面要求取「频率最高，并列时最靠顶」。频率最高 → 必在 `group[max_freq]` 中（由不变量，频率为 max_freq 的元素全在这里）。并列时最靠顶 → 即「最晚达到 max_freq 的元素」→ 由不变量就是 `group[max_freq]` 的栈顶。弹出它后，它的频率降为 max_freq - 1，从 `group[max_freq]` 移除符合不变量；若该 group 变空，则 max_freq 减 1（因为原来频率为 max_freq 的元素只剩它一个，现在最大频率必为 max_freq - 1），否则不变。不变量保持。

**为什么不会漏**：每个元素在任意时刻只属于一个 group（它的当前频率对应的那个），push 时从旧 group「逻辑上」离开（旧 group 里那条记录是历史快照，但因为我们只在栈顶操作，旧记录不会被误弹——见下）。

**为什么不会重**：pop 只从 `group[max_freq]` 弹一个，且弹完立即更新 freq 和 max_freq，不会重复弹同一元素。

**一个容易忽略的细节**：`group[f]` 里可能残留「已经不属于频率 f」的元素吗？不会。因为元素频率从 k 升到 k+1 时，我们只是往 `group[k+1]` 压入，并没有从 `group[k]` 删除——但 `group[k]` 里的那条旧记录代表的是「它曾经在频率 k 时入栈」，而 pop 只会从 `group[max_freq]` 取，max_freq ≥ 任何元素的当前频率，所以旧记录只有在 max_freq 降到 k 且该元素当前频率恰好也是 k 时才会被取到——此时它确实属于频率 k，正确。这就是为什么「不删除旧记录」是安全的：频率单调递增保证了旧记录被访问时一定「重新变得有效」。

## 5. 完整代码（Python）

```python
class FreqStack:
    def __init__(self):
        self.freq = {}        # val -> 当前频率
        self.group = {}       # 频率 -> 该频率下元素的栈（列表当栈用）
        self.max_freq = 0     # 当前最大频率

    def push(self, val: int) -> None:
        f = self.freq.get(val, 0) + 1
        self.freq[val] = f
        # 把 val 压入「频率 f」对应的栈
        if f not in self.group:
            self.group[f] = []
        self.group[f].append(val)
        # 更新最大频率
        if f > self.max_freq:
            self.max_freq = f

    def pop(self) -> int:
        # 最大频率对应的栈顶，就是「频率最高且最靠顶」的元素
        val = self.group[self.max_freq].pop()
        self.freq[val] -= 1
        # 若该频率的栈空了，最大频率降 1
        if not self.group[self.max_freq]:
            self.max_freq -= 1
        return val


class Solution:
    def solve(self, operations: list[str], args: list[list]) -> list:
        result = []
        obj = None
        for op, a in zip(operations, args):
            if op == "FreqStack":
                obj = FreqStack()
                result.append(None)
            elif op == "push":
                obj.push(a[0])
                result.append(None)
            elif op == "pop":
                result.append(obj.pop())
        return result
```

## 6. 复杂度

设总操作数为 n（push 和 pop 各若干次）。

- **push**：字典 get/set 平均 O(1)，列表 append 均摊 O(1)，比较 max_freq O(1)。合计 **O(1)**。
- **pop**：列表 pop 末尾 O(1)，字典更新 O(1)，判空 O(1)。合计 **O(1)**。
- **总时间 O(n)**。这里没有 log n——因为我们没有用堆或有序集合，而是利用了「频率只增、入栈序只增」两个单调性，用「按频率分桶 + 桶内栈」把排序问题降成了 O(1) 查表。
- **空间 O(n)**：`freq` 最多存不同值的个数（≤ n），`group` 中所有列表的元素总数 = 历史 push 次数（旧记录不删），≤ n。所以是 O(n)，不是 O(不同值个数)——这点要注意，旧记录是空间换时间的代价。

## 7. 边界与反例（至少 4 条）

1. **输入**：`push 1, pop` → **期望**：返回 1 → **易错点**：`group[1]` 弹空后 max_freq 要降为 0，若忘记降，下次 push 时 max_freq 还是 1，pop 会去访问空的 `group[1]` 报错。

2. **输入**：`push 1, push 1, push 1, pop, pop, pop` → **期望**：1, 1, 1 → **易错点**：三次 pop 分别从 group[3]、group[2]、group[1] 取，max_freq 依次 3→2→1→0。若 max_freq 只在「group 空」时降，这里每次 group 都恰好空，没问题；但若中间穿插别的值，要确认降的是 1 而不是跳到 0。

3. **输入**：`push 1, push 2, pop` → **期望**：2（频率都是 1，2 更靠顶）→ **易错点**：group[1] = [1, 2]，栈顶是 2，正确。若误用「队列」或「按值排序」就会错。

4. **输入**：`push 1, push 2, push 1, pop, pop, pop` → **期望**：1, 2, 1 → **易错点**：第一次 pop 取 group[2] 的 1（freq 变 1）；第二次 pop 时 max_freq 仍 2？不，group[2] 空了，max_freq 降为 1，group[1] = [1, 2, 1]（注意 1 的旧记录还在！），栈顶是 1——但 1 的当前频率是 1，取它正确吗？此时 1 和 2 频率都是 1，1 更靠顶（第三次 push 的），所以取 1 正确。**这里最容易错**：有人以为 group[1] 里第一个 1 是「过期记录」要跳过，其实不用——栈顶的 1 恰好是有效的那个。

5. **输入**：`push 0, pop`（val 可以为 0）→ **期望**：0 → **易错点**：用 `if val:` 判空会误判 0 为假，必须用 `is not None` 或直接不判。

## 8. 面试追问与变体（3 条）

1. **追问**：如果 pop 要求「频率最低」的元素呢？**思路**：对称地维护 `min_freq`，但 min_freq 会因 push 上升、因 pop 下降，需要额外处理「min_freq 对应的 group 空了但更高频率还有元素」的情况——不能简单 ±1，得用有序结构或重新扫描，复杂度会变。

2. **追问**：如果并列时要求「最靠栈底」而不是栈顶？**思路**：group[f] 改用双端队列，pop 时取队首而非队尾；但「最靠底」意味着最早入栈，需要额外记录入栈序号来比较，因为不同频率的元素入栈序不可比。

3. **追问**：如何支持「删除任意指定元素」？**思路**：需要从 group[freq[val]] 中间删除，列表做不到 O(1)，改用 `SortedList` 或双向链表 + 哈希定位，复杂度升到 O(log n) 或 O(1) 但实现复杂。

1. **LC 146 LRU 缓存**：共同点是「用哈希表 + 双向链表把 O(n) 查找降成 O(1)」，都是「用额外结构缓存顺序信息」的设计题。

2. **LC 460 LFU 缓存**：共同点是「按频率分桶」，但 LFU 还要在频率相同时按访问时间淘汰，需要每个频率桶内再维护有序结构，是本题的加强版。

3. **LC 155 最小栈**：共同点是「辅助栈记录历史最值」，思想同源——用额外空间换 O(1) 查询，只是本题的「最值」是双关键字。
