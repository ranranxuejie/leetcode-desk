## 1. 一句话本质

对每个位置 i，求 `min(它左边最高的柱子, 它右边最高的柱子) - height[i]`（若为负则取 0），再把所有位置加起来。

这句话是整道题的全部。后面所有解法——暴力、DP、双指针、单调栈——都只是在用不同方式算这个 `min(左max, 右max)`。

## 2. 读完题的第一反应

**朴素解法**：对每个位置 i，向左扫一遍找左最高，向右扫一遍找右最高，算 `min - height[i]`。n 个位置，每个位置扫 O(n)，总 O(n²)。n 最大 2×10⁴，n² = 4×10⁸，Python 里必超时。瓶颈很清楚：**每个位置都重复扫了左右两边，而这些信息是可以复用的**。

**关键观察**：位置 i 的「左最高」只依赖 i 左边的元素，「右最高」只依赖 i 右边的元素。也就是说，我可以先花 O(n) 把所有位置的左最高预计算出来存进数组，再花 O(n) 把右最高预计算出来，最后 O(n) 扫一遍求和。这就是 DP 解法，O(n) 时间 O(n) 空间。

再往下想一步：真的需要把两个数组都存下来吗？如果我从两端往中间走，维护两个指针 `left`、`right` 和两个变量 `left_max`、`right_max`，每次处理较矮的那一端——因为**较矮那一端的「另一侧最高」一定不低于当前已知的这一侧最高**，所以它的水量可以直接确定，不需要知道另一侧的精确值。这就是双指针，O(n) 时间 O(1) 空间。

为什么这个观察能让你想到下一步？因为它把「每个位置独立求两个全局量」变成了「一次扫描中增量维护两个量」，这是所有「区间最值 + 逐元素求和」类问题的通用降维套路。

## 3. 从暴力到最优

用示例 2：`height = [4,2,0,3,2,5]`，答案 9。

**暴力**：对 i=2（高度 0），左扫得 4，右扫得 5，水量 `min(4,5)-0 = 4`。对 i=3（高度 3），左扫得 4，右扫得 5，水量 `min(4,5)-3 = 1`。每个位置都扫两遍，n=6 时是 36 次比较，n=2×10⁴ 时是 4×10⁸ 次。

**DP**：先从左往右扫一遍填 `left_max[i] = max(left_max[i-1], height[i])`，得到 `[4,4,4,4,4,5]`；再从右往左扫填 `right_max[i] = max(right_max[i+1], height[i])`，得到 `[5,5,5,5,5,5]`。然后逐位算 `min(left_max[i], right_max[i]) - height[i]`：

| i | height | left_max | right_max | min | 水量 |
|---|--------|----------|-----------|-----|------|
| 0 | 4 | 4 | 5 | 4 | 0 |
| 1 | 2 | 4 | 5 | 4 | 2 |
| 2 | 0 | 4 | 5 | 4 | 4 |
| 3 | 3 | 4 | 5 | 4 | 1 |
| 4 | 2 | 4 | 5 | 4 | 2 |
| 5 | 5 | 5 | 5 | 5 | 0 |

合计 0+2+4+1+2+0 = 9。✓ 瓶颈从「每位置扫两遍」变成「预计算两遍 + 一遍求和」，O(n)。

**双指针**：`left=0, right=5, left_max=0, right_max=0, ans=0`。

- `height[0]=4 < height[5]=5`，处理左端。`left_max = max(0,4)=4`，`ans += 4-4=0`，`left=1`。
- `height[1]=2 < height[5]=5`，处理左端。`left_max = max(4,2)=4`，`ans += 4-2=2`，`left=2`。
- `height[2]=0 < height[5]=5`，处理左端。`left_max=4`，`ans += 4-0=4`，`left=3`。
- `height[3]=3 < height[5]=5`，处理左端。`left_max=4`，`ans += 4-3=1`，`left=4`。
- `height[4]=2 < height[5]=5`，处理左端。`left_max=4`，`ans += 4-2=2`，`left=5`。
- `left == right`，结束。ans = 0+2+4+1+2 = 9。✓

注意双指针**从没算过 right_max 的精确值**（一直是 0），但结果正确——因为每次处理的都是较矮那端，它的水量由已知的这端 max 决定，另一端只保证「不低于它」，足够用了。空间从 O(n) 降到 O(1)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。

**DP 解法的正确性**：对任意 i，`left_max[i]` 定义为 `max(height[0..i])`，`right_max[i]` 定义为 `max(height[i..n-1])`。位置 i 上方能存的水，其水面高度不可能超过左边界最高柱（否则水会从左边流走），也不可能超过右边界最高柱，所以水面高度恰为 `min(left_max[i], right_max[i])`。水量为 `水面高度 - height[i]`（负则 0）。每个 i 独立计算、只加一次，**不漏不重**。

**双指针的不变量**：循环中始终有 `left_max = max(height[0..left-1])`，`right_max = max(height[right+1..n-1])`，且 `left <= right`。当 `height[left] < height[right]` 时，位置 left 的右边界最高至少是 `height[right]`，而 `height[right] >= height[left] >= left_max` 不一定成立——但关键不等式是：`min(left_max, 真正的右max) = left_max`，因为真正的右max ≥ height[right] > height[left]，而 left_max 是左半段最大，可能比 height[left] 大也可能小，但无论如何 `min(left_max, 右max) = left_max` 当且仅当 `left_max <= 右max`。由于 `右max >= height[right] > height[left]`，而 `left_max` 是 `height[0..left]` 的最大值，可能大于 height[right]——**这里需要更细的论证**：实际上双指针的经典论证是，当 `height[left] < height[right]` 时，处理 left 位置，其水量为 `left_max - height[left]`（若 left_max > height[left]），因为此时 `min(left_max, 右max) = left_max` 成立的前提是 `left_max <= 右max`。而 `右max >= height[right] > height[left]`，且 `left_max` 是左半段（含 left）的最大值，可能超过 height[right]。但注意：如果 `left_max > height[right]`，那么 `left_max` 本身就是一个比 height[right] 高的柱子，它在 left 的左边，意味着 left 位置的水面由 left_max 决定，而右边界至少是 height[right]，`min(left_max, 右max)` 中右max ≥ height[right]，但 left_max 可能更大——此时 `min = 右max` 而非 left_max，双指针会算错吗？

不会。因为双指针的**真正不变量**是：`left_max` 和 `right_max` 中较小的那个，就是当前处理位置的 `min(左max, 右max)`。具体地，当 `height[left] < height[right]` 时，`left_max <= right_max` 不一定成立，但 `min(left_max, right_max) = left_max` 当且仅当 `left_max <= right_max`。而 `right_max` 是 `height[right..n-1]` 的最大值，`left_max` 是 `height[0..left]` 的最大值。由于 `height[left] < height[right]`，且 `left_max` 可能来自更左边的高柱——此时 `left_max > height[right]`，那么 `right_max >= height[right]` 但可能小于 left_max，`min = right_max`。这种情况下双指针处理 left 位置会用水量 `left_max - height[left]`，但正确值应是 `right_max - height[left]`，**会多算**。

所以标准双指针的正确论证需要修正：**当 `height[left] < height[right]` 时，我们处理 left，但前提是 `left_max <= right_max`**。这个前提在算法中是否恒成立？不恒成立。正确的双指针写法是：比较 `left_max` 和 `right_max`，而不是比较 `height[left]` 和 `height[right]`。标准写法是：

```
if left_max < right_max:
    处理 left，ans += left_max - height[left]，left++
else:
    处理 right，ans += right_max - height[right]，right--
```

这样不变量是：`left_max` 和 `right_max` 中较小的那个，就是当前处理位置的 `min(左max, 右max)`。因为如果 `left_max < right_max`，那么对 left 位置，`min(左max, 右max) = left_max`（左max 是精确的，右max 是下界但已大于 left_max，所以 min 就是 left_max）。这个论证是严格的。

**修正后的双指针**：维护 `left_max`、`right_max`，每次比较这两个值，处理较小那侧。这样每个位置恰好处理一次，水量公式精确，不漏不重。

## 5. 完整代码（Python）

```python
class Solution:
    def trap(self, height: list[int]) -> int:
        if not height:
            return 0
        n = len(height)
        left, right = 0, n - 1
        left_max, right_max = 0, 0
        ans = 0
        while left < right:
            # 更新两侧已知最高柱
            left_max = max(left_max, height[left])
            right_max = max(right_max, height[right])
            # 较小的一侧，其 min(左max, 右max) 已确定
            if left_max < right_max:
                # 左侧最高更矮，left 位置的水面由 left_max 决定
                ans += left_max - height[left]
                left += 1
            else:
                # 右侧最高更矮（或相等），right 位置的水面由 right_max 决定
                ans += right_max - height[right]
                right -= 1
        return ans
```

关键逻辑注释已在代码中。注意 `left_max` 和 `right_max` 在循环开头就更新，保证处理当前位置时用的是包含自己的前缀/后缀最大值。`left < right` 而非 `<=`，因为最后相遇的位置不需要单独处理（它两侧的 max 已覆盖，且该位置水量为 0 或已由相邻步骤计入——实际上相遇位置若 height 较低，其水量在之前某步已被计入；若较高，水量为 0。用 `<` 是标准写法，避免重复）。

## 6. 复杂度

**时间 O(n)**：while 循环每轮 `left` 或 `right` 移动一格，总共移动 n-1 次（从两端走到相遇），每次 O(1) 操作。n 来自数组长度，没有 log n 项——因为这是一次线性扫描，不涉及分治或排序。

**空间 O(1)**：只用了 `left, right, left_max, right_max, ans` 五个变量，与 n 无关。对比 DP 解法需要两个长度 n 的数组，空间 O(n)。

## 7. 边界与反例（至少 4 条）

1. **`height = []`** → 期望 0 → 容易错：没判空，`n-1 = -1`，`while 0 < -1` 不进入但 `height[left]` 可能越界（若先访问）。代码开头 `if not height: return 0` 兜住。
2. **`height = [5]`** → 期望 0 → 容易错：单元素，`left < right` 为假直接返回 0，正确。但若写成 `left <= right` 且循环内访问 `height[right]`，可能越界或重复计算。
3. **`height = [1,2,3,4,5]`（单调递增）** → 期望 0 → 容易错：每位置左max 是前一个，右max 是 5，`min - height[i]` 恒为 0（因为 height[i] 就是当前前缀最大）。双指针中 `left_max` 始终等于 `height[left]`，`ans += 0`，正确。
4. **`height = [5,4,3,2,1]`（单调递减）** → 期望 0 → 容易错：对称情况，`right_max` 始终等于 `height[right]`，`ans += 0`，正确。
5. **`height = [2,0,2]`** → 期望 2 → 容易错：中间 0 的水量是 `min(2,2)-0 = 2`。双指针：`left_max=2, right_max=2`，`left_max < right_max` 为假，处理 right：`ans += 2-2=0, right=1`；再 `left_max=2, right_max=max(2,0)=2`，仍假，处理 right：`ans += 2-0=2, right=0`；`left==right` 结束。ans=2。✓ 注意相等时走 else 分支，处理右侧，结果正确。
6. **`height = [0,0,0]`** → 期望 0 → 容易错：全 0，`left_max=right_max=0`，每步 `ans += 0`，正确。

## 8. 面试追问与变体（3 条）

1. **追问：如果柱子宽度不是 1，而是给定数组 `width[i]`，怎么改？** 思路：水量公式变成 `(min(left_max, right_max) - height[i]) * width[i]`，双指针中 `ans += (left_max - height[left]) * width[left]`，其余不变。
2. **追问：如果要求返回每个位置的水量数组而不是总和？** 思路：DP 解法天然支持，预计算 `left_max`、`right_max` 后逐位算并存数组；双指针需额外记录每步结果，空间回到 O(n)。
3. **追问：如果柱子可以「渗水」，即水会从任意缺口流走，怎么算？** 思路：这变成「每个位置上方能存的水 = 它到最近更高柱之间的凹陷」，可用单调栈找每个位置的左右第一个更高柱，再算区间水量，本质仍是 `min(左max, 右max)` 但需处理「缺口」语义。
