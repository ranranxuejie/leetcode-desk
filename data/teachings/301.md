## 1. 一句话本质

在所有「删掉最少括号」得到的子序列里，找出全部**合法括号串**——注意是「删最少」这个约束把问题从「求一个答案」变成了「求一层答案」，这才是它被评为困难的原因。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子序列（每个字符留或删），对每个子序列检查是否合法，记录合法解中长度最大的那些。字符串长度 n，子序列有 2^n 个，每个检查 O(n)，总复杂度 O(n·2^n)。n 最大到 50 左右（括号至多 20 个，加上字母），2^50 直接爆炸。卡点在于：**绝大多数子序列根本不值得检查**，我们却为它们付了指数代价。

**关键观察**：题目要的是「删最少」。设最少要删 k 个括号，那么任何合法答案都恰好由原串删掉 k 个字符得到。于是问题可以重新表述为：**从删 0 个开始，逐层尝试删 1 个、删 2 个……第一次出现合法串的那一层，就是答案层**。这天然是 BFS 的形状——按「删除次数」分层，层内第一次命中就停，不用再往下搜。

第二个观察：合法性检查是 O(n) 的、且**只依赖括号的相对顺序**，所以「删哪个位置的括号」会产生大量重复串（比如 `"())"` 删第 1 个 `)` 和删第 2 个 `)` 都得到 `"()"`）。这提示我们：**同一层必须去重**，否则 BFS 会指数级膨胀。

## 3. 从暴力到最优

**第一步：从「枚举子序列」到「按删除数分层」**

还是 `"()())()"`。第 0 层：`"()())()"`，检查不合法（多一个 `)`）。第 1 层：删掉任意一个字符，得到 7 个串，其中有 `"(())()"`（删第 3 个位置的 `)`）和 `"()()()"`（删第 4 个位置的 `)`）——都合法，命中，返回这两个。BFS 只走了 1+7 个状态就结束，而枚举子序列要 2^7=128 个。

**第二步：层内去重**

考虑 `"())"`。第 1 层删每个字符：删 `(` 得 `"))"`，删第一个 `)` 得 `"()"`，删第二个 `)` 也得 `"()"`。如果不去重，`"()"` 被检查两次，下一层还会被展开两次。用一个 `set` 收集本层所有新串，再统一检查，重复串只留一份。这一步把「同一层内因删除顺序不同产生的重复」压掉了。

**第三步：提前剪枝——长度下界**

BFS 一旦在某层找到合法解就返回，所以不需要额外剪枝；但如果想更稳，可以先用一次 O(n) 扫描算出「最少必须删几个」（见第 4 节的不变量），从那一层直接开始，跳过前面必然失败的所有层。对 `"()())()"`，扫描得 `need_remove = 1`，直接从删 1 个开始，省掉第 0 层的检查。

**第四步：为什么 BFS 比 DFS 回溯更省心**

回溯写法需要「先算出最少删几个、再枚举删哪些位置、最后去重」，三件事耦合在一起，容易漏解或重解。BFS 把「最少」交给层数天然保证，把「全部」交给层内枚举，把「去重」交给 set，三件事解耦。代价是空间，但括号至多 20 个，状态数可控。

## 4. 正确性：为什么不会漏、不会重

**不漏（完备性）**：设最优解需要删 k 个字符。BFS 从第 0 层开始，第 i 层恰好包含「原串删 i 个字符得到的所有串」（归纳：第 i+1 层由第 i 层每个串再删一个字符得到，覆盖了所有删 i+1 个字符的串）。所以第 k 层一定包含全部最优解，BFS 在第 k 层命中并返回，不会漏。

**不重（无重复）**：层内用 `set` 去重，保证每个不同的串只被检查一次、只被返回一次。注意去重的是**串本身**而非删除位置，所以「不同删法得到同一串」只算一个答案，符合题目「返回所有可能的结果」的语义（结果是串，不是删法）。

**不变量**：合法性检查用计数器 `balance`，遇 `(` 加 1、遇 `)` 减 1，任意前缀 `balance >= 0` 且最终 `balance == 0`。这个不变量是 O(n) 检查的核心，也是「最少删除数」扫描的依据：扫描时 `balance` 掉到 -1 就说明有一个多余的 `)` 必须删，`need_remove++` 并把 `balance` 归零；扫描完 `balance` 的剩余值就是多余的 `(` 个数，也加到 `need_remove`。对 `"()())()"`：扫描到第 4 个字符 `)` 时 balance 从 0 变 -1，need_remove=1、balance 归零，继续扫描结束 balance=0，故 need_remove=1，与 BFS 实测一致。

## 5. 完整代码（Python）

```python
class Solution:
    def removeInvalidParentheses(self, s: str) -> list[str]:
        def is_valid(t: str) -> bool:
            # 计数器法：任意前缀 balance 不能为负，最终必须归零
            balance = 0
            for ch in t:
                if ch == '(':
                    balance += 1
                elif ch == ')':
                    balance -= 1
                    if balance < 0:
                        return False
            return balance == 0

        # 第 0 层：原串
        level = {s}
        while True:
            # 本层里所有合法串就是答案（BFS 保证这是删除数最少的一层）
            valid = [t for t in level if is_valid(t)]
            if valid:
                return valid
            # 否则展开下一层：每个串删掉一个字符，用 set 去重
            next_level = set()
            for t in level:
                for i in range(len(t)):
                    # 只删括号，删字母没有意义且会浪费一层
                    if t[i] in '()':
                        next_level.add(t[:i] + t[i + 1:])
            level = next_level
```

关键逻辑说明：`level` 是「删了同样多个字符」的串集合；`valid` 非空即返回，保证最少删除；`next_level` 用 `set` 去重；只删括号是因为删字母不改变合法性却增加删除数，永远不会出现在最优解里（见第 7 节反例 4）。

## 6. 复杂度

设 n 为串长，m 为括号个数（m ≤ 20）。

- **时间**：BFS 最多展开 m 层，第 i 层状态数上界 C(m, i)（从 m 个括号里选 i 个删），每层每个状态做 O(n) 合法性检查、O(n) 展开。总上界 O(n · Σ C(m,i)) = O(n · 2^m)。m ≤ 20 时 2^20 ≈ 10^6，乘 n 可接受。这里的 n 来自每次字符串拼接和检查，2^m 来自括号子集枚举。
- **空间**：`level` 和 `next_level` 各存一层状态，每串长 O(n)，故 O(n · C(m, m/2))，最坏 O(n · 2^m / √m)。没有 log n 项——本题不涉及排序或二分。

## 7. 边界与反例（至少 4 条）

1. `s = "()"` → 期望 `["()"]` → 第 0 层就合法，直接返回；若误从第 1 层开始会返回 `[""]`，错。
2. `s = ")("` → 期望 `[""]` → 第 0 层不合法，第 1 层删一个得 `"("` 和 `")"` 都不合法，第 2 层得 `""` 合法。容易错在「以为删一个就够」。
3. `s = "((("` → 期望 `[""]` → 全是左括号，必须删 3 个；容易错在合法性检查只查 balance 归零、忘了前缀非负，导致 `"((("` 被误判。
4. `s = "a(b)c"` → 期望 `["a(b)c"]` → 字母不影响合法性，原串已合法；若代码「只删括号」写反成「只删字母」，会返回错误结果。
5. `s = "()())()"` → 期望两个解 → 容易错在层内不去重，返回重复串；或只返回一个解，漏掉 `"(())()"`。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回「删除方案」而不是「结果串」怎么办？** 思路：BFS 状态里带上「已删位置集合」，去重键改成串本身但记录所有到达它的删法，最后收集答案层所有删法。
2. **追问：能否用 DFS 回溯 + 剪枝做到同样效果？** 思路：先 O(n) 算出 need_remove，再枚举删哪些括号位置，用「当前已删数 + 剩余可删数 ≥ need_remove」剪枝，最后 set 去重。
3. **追问：如果括号种类扩展到 `()[]{}` 三种呢？** 思路：合法性检查换成栈匹配，BFS 框架不变，但状态空间和去重压力显著变大，需评估是否仍可行。

- **22. 括号生成**：同样是括号合法性 + 枚举所有解，区别是「生成」而非「删除」，用回溯 + 左右括号剩余数剪枝。
- **1249. 移除无效的括号**：本题的简化版，只要求返回一个解，可用一次扫描 + 栈直接构造，不必 BFS。
