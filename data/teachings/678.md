## 1. 一句话本质

在 `*` 可以「变左括号 / 变右括号 / 变空」的三种自由度下，判断是否存在一种 `*` 的取值方案，使得整个括号序列合法。

换句话说：**`*` 不是障碍，而是一个可调节的缓冲池**，我们要问的是「这个缓冲池够不够把括号配平」。

## 2. 读完题的第一反应

### 朴素解法：枚举所有 `*` 的取值

每个 `*` 有 3 种选择，若字符串里有 k 个 `*`，就有 3^k 种方案，逐个检查是否合法。k 最大可到 100，3^100 完全不可行。**瓶颈在于「组合爆炸」**：我们并不关心具体是哪一种取值，只关心「存不存在」。

### 关键观察

把 `*` 看成「万能牌」后，问题变成：**在扫描过程中，当前未匹配的左括号数量，能落在一个什么范围内？**

- 遇到 `(`：未匹配数必然 +1，范围整体右移。
- 遇到 `)`：未匹配数必然 -1，范围整体左移。
- 遇到 `*`：它可能当 `(`（+1）、当 `)`（-1）、当空（不变），所以范围**同时向两边扩张**。

只要在任意前缀处，这个「未匹配数」的范围**下界不为负**（否则说明右括号太多、补不回来），且**最终范围包含 0**（能配平），就存在合法方案。

这个观察之所以能想到下一步，是因为它把「3^k 种具体方案」压缩成了「一个区间 [lo, hi]」——**我们只追踪可能性的边界，不追踪具体是哪条路径**。这正是「区间 DP / 贪心」类题目的典型降维手法。

## 3. 从暴力到最优

### 第一步：暴力枚举（瓶颈：3^k）

以 `s = "(*))"` 为例，`*` 有 3 种取值：

- `*` 取 `(`：`(()))` → 多一个左括号，非法
- `*` 取 `)`：`()))` → 右括号过多，非法
- `*` 取空：`())` → 合法 ✓

枚举能出答案，但 k 一大就崩。

### 第二步：只追踪「未匹配左括号数」的区间

定义扫描到第 i 个字符时，未匹配左括号数可能取的所有值构成区间 `[lo, hi]`。

初始 `lo = hi = 0`。

对 `s = "(*))"` 走一遍：

| 字符 | 操作 | lo | hi |
|------|------|----|----|
| 初始 | — | 0 | 0 |
| `(` | lo+1, hi+1 | 1 | 1 |
| `*` | lo-1, hi+1（再截断 lo≥0） | 0 | 2 |
| `)` | lo-1, hi-1（再截断 lo≥0） | 0 | 1 |
| `)` | lo-1, hi-1（再截断 lo≥0） | 0 | 0 |

结束时 `lo = 0`，区间包含 0，返回 true。✓

注意 `*` 那一步：`lo` 从 1 变 0（`*` 当右括号），`hi` 从 1 变 2（`*` 当左括号），区间从 `[1,1]` 扩张成 `[0,2]`——**一个点变成一段**，这就是「自由度」被显式表达出来的地方。

### 第三步：瓶颈怎么被消掉

- 原来要枚举 3^k 条路径；
- 现在每一步只维护两个整数 `lo, hi`，且区间是连续的（下面第 4 节证明它为什么连续）；
- 复杂度从指数级降到 **O(n)**，空间 **O(1)**。

关键剪枝：**当 `hi < 0` 时立刻返回 false**。因为 `hi` 是「最乐观情况下未匹配左括号数」，如果连最乐观都欠右括号，那无论 `*` 怎么取都救不回来。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：扫描完前 i 个字符后，`[lo, hi]` 恰好等于「所有合法前缀方案下，未匹配左括号数能取到的值的集合」，且这个集合是一个**连续整数区间**。

证明分三点：

1. **区间连续性（不会漏中间值）**：归纳假设前 i 步是连续区间 `[lo, hi]`。遇到 `(` 或 `)` 时整体平移，仍是连续区间；遇到 `*` 时，新集合 = `[lo-1, hi-1] ∪ [lo, hi] ∪ [lo+1, hi+1]`，三个相邻区间并起来还是连续区间 `[lo-1, hi+1]`。所以连续性保持。

2. **下界截断不丢解**：当 `lo < 0` 时我们把它截成 0。被截掉的是「未匹配数为负」的状态，而负的未匹配数在括号匹配里没有意义（右括号不能反过来等左括号），这些状态本来就不可能通向合法终态，截掉不影响最终判断。

3. **终态判定充分必要**：
   - 若最终 `lo == 0`，说明存在一条方案使未匹配数为 0，即合法，返回 true 是**充分**的。
   - 若最终 `lo > 0`，说明**所有**方案结束时都还剩至少 `lo` 个左括号没配，不存在合法方案，返回 false 是**必要**的。
   - 若中途 `hi < 0`，说明最乐观方案都欠右括号，之后无论怎么补都补不回来（后面的字符只能增加或维持未匹配数，无法凭空造出左括号），提前返回 false 正确。

因此算法**不漏**（区间覆盖了所有可能值）、**不重**（区间是精确集合，不是超集），结论可靠。

## 5. 完整代码（Python）

```python
class Solution:
    def checkValidString(self, s: str) -> bool:
        # lo: 未匹配左括号数可能取到的最小值（把 * 尽量当右括号用）
        # hi: 未匹配左括号数可能取到的最大值（把 * 尽量当左括号用）
        lo, hi = 0, 0

        for ch in s:
            if ch == '(':
                # 左括号：未匹配数必然 +1，区间整体右移
                lo += 1
                hi += 1
            elif ch == ')':
                # 右括号：未匹配数必然 -1，区间整体左移
                lo -= 1
                hi -= 1
            else:  # ch == '*'
                # 星号：可当右括号(lo-1)、空(不变)、左括号(hi+1)
                # 区间向两边各扩张 1
                lo -= 1
                hi += 1

            # 下界不能为负：负的未匹配数无意义，截断到 0
            if lo < 0:
                lo = 0

            # 上界为负：最乐观情况都欠右括号，后面救不回来
            if hi < 0:
                return False

        # 最终必须存在一种方案让未匹配数恰好为 0
        return lo == 0
```

## 6. 复杂度

- **时间 O(n)**：只遍历字符串一次，每个字符做常数次加减和比较。n 是字符串长度，来自「必须至少读一遍输入」这个下界，无法再降。
- **空间 O(1)**：只用了 `lo`、`hi` 两个整型变量，与 n 无关。没有开辟栈、数组或 DP 表。

对比：若用栈解法（两个栈分别存 `(` 和 `*` 的下标），空间是 O(n)；本题的贪心区间法把空间压到了常数。

## 7. 边界与反例（至少 4 条）

1. **`s = ")"` → false**。第一个字符就让 `hi = -1 < 0`，立即返回 false。容易错在：忘记「上界为负要提前退出」，导致后面误判。
2. **`s = "("` → false**。扫描结束 `lo = 1 != 0`，说明左括号没配平。容易错在：只检查了「中途不为负」，忘了检查「终态 lo 是否为 0」。
3. **`s = "*"` → true**。`*` 当空字符串即可。容易错在：把 `*` 一律当括号处理，忘了它还能当空。
4. **`s = "(*)"` → true**。`*` 当空，`()` 配平。容易错在：误以为 `*` 必须参与匹配。
5. **`s = "((*"` → false**。`*` 最多补一个右括号，仍剩一个左括号。容易错在：以为 `*` 万能，忽略数量守恒。
6. **`s = "(*))"` → true**（官方示例 3）。`*` 当 `(`，得到 `(())`。这是「区间扩张再收缩」的典型走法，容易错在：过早把 `*` 定死成某一种取值。

## 8. 面试追问与变体（3 条）

1. **追问：如果 `*` 只能当右括号或空，不能当左括号，怎么做？**
   思路：把 `*` 的 `hi+1` 分支去掉，遇到 `*` 时 `hi` 不变、`lo` 减 1，其余逻辑不变。区间不再向「左括号方向」扩张。

2. **追问：如果要返回一种具体的合法方案（把每个 `*` 替换成什么），怎么做？**
   思路：区间贪心只能判存在性。要构造方案，需反向扫描一次：从终态 `0` 出发倒推，或用两个栈记录 `(` 和 `*` 的下标，匹配时优先用 `(` 配 `)`，剩余 `*` 补位。

3. **追问：如果允许 `*` 匹配任意长度的括号串（类似通配符），怎么改？**
   思路：区间会变成「未匹配数可以是任意非负值」，退化成只需检查「是否存在前缀使右括号数不超过左括号数 + 星号数」，用前缀和 + 后缀和两个数组 O(n) 判断。
