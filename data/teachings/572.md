## 1. 一句话本质

在 root 的**每一个节点**上，判断「以该节点为根的子树」是否与 subRoot **完全同构**；只要有一个节点命中就返回 true。

关键词是「每一个节点」和「完全同构」——前者决定外层要遍历，后者决定内层要逐节点比对。

## 2. 读完题的第一反应

朴素解法很自然：遍历 root 的每个节点 u，对每个 u 调用一个 `isSameTree(u, subRoot)`，逐节点比较结构和值。这就是「外层遍历 × 内层比对」。

它卡在哪？设 root 有 n 个节点、subRoot 有 m 个节点。外层遍历是 O(n)，内层 `isSameTree` 最坏要访问 m 个节点，所以最坏 O(n·m)。n 最大 2000、m 最大 1000，乘积 2×10⁶，其实**能过**。所以这道题「暴力」并不慢到不可接受——这一点必须诚实说清楚，不要为了讲优化而编造瓶颈。

那关键观察是什么？有两条，都值得讲：

**观察一（剪枝）**：`isSameTree(u, subRoot)` 只有在「u 的子树高度/节点数 ≥ subRoot 的」时才可能为真。更实用的是：**先比根节点的值**，值不等直接返回 false，绝大多数节点在第一步就被淘汰。这让平均复杂度远低于最坏值。

**观察二（换视角）**：把两棵树都做**先序遍历并序列化**（空节点用特殊标记占位），「root 含 subRoot 这棵子树」就等价于「subRoot 的序列是 root 序列的**子串**」。这把树问题降维成字符串匹配问题，可以上 KMP 做到 O(n+m)。这是本题标签里「字符串匹配 / 哈希函数」的由来。

为什么序列化必须带空节点标记？因为不带的话，结构信息丢了：`[1,2]` 和 `[1,null,2]` 的先序值序列都是 `1,2`，但结构不同。空标记是「结构」的唯一载体。

## 3. 从暴力到最优

**第一步：暴力。**

```
for u in all_nodes(root):
    if isSameTree(u, subRoot): return True
return False
```

`isSameTree(a, b)`：两者都空→true；一空一非空→false；值不等→false；否则递归比左右孩子。

**第二步：加剪枝。** 在 `isSameTree` 入口先判 `a.val != b.val` 直接 false。这一步不改变最坏复杂度，但把常数压得很低。

**第三步：序列化 + 子串匹配。**

以示例 2 走一遍，这是最能说明问题的小例子。

root = `[3,4,5,1,2,null,null,null,null,0]`，subRoot = `[4,1,2]`。

先序序列化（用 `#` 表示空，用 `,` 分隔，值前加 `^` 防止 `1` 和 `11` 混淆）：

- root 的先序：`^3,^4,^1,#,#,^2,#,^0,#,#,^5,#,#`
- subRoot 的先序：`^4,^1,#,#,^2,#,#`

现在检查后者是否为前者的子串。肉眼可见：root 序列里 `^4,^1,#,#,^2,#,^0,...`，而 subRoot 要求 `^4,^1,#,#,^2,#,#`——第 7 个位置 root 是 `^0`，subRoot 是 `#`，**不匹配**。返回 false，与示例一致。

再看示例 1：root = `[3,4,5,1,2]`，先序 `^3,^4,^1,#,#,^2,#,#,^5,#,#`；subRoot 仍是 `^4,^1,#,#,^2,#,#`。这次在 root 序列的第 2 位开始能完整对上 `^4,^1,#,#,^2,#,#`，返回 true。

注意 `^` 前缀和 `,` 分隔这两个细节：没有它们，`^1` 会误匹配 `^11` 的前缀，`^4,^1` 会误匹配 `^4,^12`。这是序列化法最容易翻车的地方。

**瓶颈怎么被消掉的**：暴力是「n 个起点 × 每次最多 m 次比较」；序列化后变成「一次 O(n) 生成 + 一次 O(n+m) 的 KMP 匹配」。Python 里 `sub in root_str` 底层是高效的子串查找（近似线性），所以实际写法极短。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说。

对暴力法，定义不变量：*外层循环处理到节点 u 时，已经检查过的所有节点中，没有一个的子树与 subRoot 同构*。循环体做的是「检查 u」，`isSameTree` 是标准的同构判定（结构 + 值双重递归），所以每次迭代后不变量保持。循环结束仍未返回 true，说明 root 中**所有**节点都检查过且都不匹配，由题面「子树 = 某节点及其全部后代」的定义，root 不含 subRoot 子树，返回 false 正确。**不会漏**：因为外层遍历覆盖了全部 n 个节点，每个候选起点都被试过。**不会重**：每个起点只试一次，且「同构」是等价关系，重复试同一对树不会改变结论。

对序列化法，不变量是：*先序序列（含空标记）与二叉树一一对应*。证明要点：先序的第一个元素必是根，空标记确定子树边界，递归地唯一还原左右子树，故映射是双射。既然是一一对应，「A 是 B 的子树」当且仅当「A 的序列是 B 的序列的连续子串」——因为 A 作为 B 中某节点 u 的子树，其先序序列恰好是 B 先序序列中从 u 开始的一段连续区间（先序遍历访问完 u 的整棵子树才离开）。**不会漏**：任何真实子树都对应一段连续子串。**不会重**：子串匹配找到的每一段都对应唯一一个起点节点。

## 5. 完整代码（Python）

```python
class Solution:
    def isSubtree(self, root, subRoot) -> bool:
        # 空树是任何树的子树（题面允许 tree 是自身子树，空树按惯例视为 true）
        if subRoot is None:
            return True
        if root is None:
            return False

        # 外层：枚举 root 的每个节点作为候选起点
        # 先比根值做剪枝，值不等就没必要进 isSameTree
        if root.val == subRoot.val and self._same(root, subRoot):
            return True
        # 当前节点不匹配，递归到左右子树继续找
        return self.isSubtree(root.left, subRoot) or self.isSubtree(root.right, subRoot)

    def _same(self, a, b) -> bool:
        # 标准同构判定：结构 + 值都要一致
        if a is None and b is None:
            return True
        if a is None or b is None:
            return False
        if a.val != b.val:
            return False
        return self._same(a.left, b.left) and self._same(a.right, b.right)
```

如果面试官追问「能不能 O(n+m)」，给出序列化 + KMP 版本（这里用 Python 内置 `in`，底层高效）：

```python
class Solution:
    def isSubtree(self, root, subRoot) -> bool:
        def serialize(node, out):
            if node is None:
                out.append("#")          # 空标记承载结构信息
                return
            out.append("^" + str(node.val))  # ^ 前缀防止 1 与 11 混淆
            serialize(node.left, out)
            serialize(node.right, out)

        a, b = [], []
        serialize(root, a)
        serialize(subRoot, b)
        # 用逗号连接，保证 token 边界清晰
        return ",".join(b) in ",".join(a)
```

## 6. 复杂度

**暴力版**：时间 O(n·m)。n 来自外层遍历 root 的每个节点；m 来自每次 `isSameTree` 最坏访问 subRoot 全部节点。空间 O(h)，h 是 root 的高度，来自递归栈；最坏（链状树）h = n。

**序列化版**：时间 O(n + m)。生成两个序列各 O(n)、O(m)；子串查找在 Python 中平均 O(n+m)（CPython 对短模式用 Two-Way 算法，最坏也是线性的）。空间 O(n + m)，两个序列各占一份，外加递归栈 O(h)。注意这里**没有 log n**——二叉树不保证平衡，高度最坏是 n 不是 log n，别把「树高」默认成 log n。

## 7. 边界与反例（至少 4 条）

1. **root = [1], subRoot = [1]** → true。容易错在：忘记「tree 自身也算子树」，若外层只从 root 的孩子开始找就会漏。
2. **root = [1,1], subRoot = [1]** → true。容易错在：以为要匹配整棵 root；实际只要某个单节点子树匹配即可，root 本身和它的左孩子都是候选。
3. **root = [1,2,3], subRoot = [1,2]** → false。容易错在：只比值序列不看结构。root 的节点 1 有右孩子 3，subRoot 的节点 1 没有右孩子，结构不同。序列化法里 root 是 `^1,^2,#,#,^3,#,#`，subRoot 是 `^1,^2,#,#,#`，第 5 位 `^3` vs `#` 不匹配。
4. **root = [1,2], subRoot = [1,null,2]** → false。这是序列化法的经典陷阱：若序列化**不带空标记**，两者都是 `1,2`，会误判 true。带空标记后 root 是 `^1,^2,#,#,#`，subRoot 是 `^1,#,^2,#,#`，不匹配。
5. **root = [12], subRoot = [2]** → false。若序列化不加 `^` 前缀和分隔符，字符串 `"12"` 包含 `"2"`，会误判 true。这是「值拼接」类题目的通用坑。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求 O(n+m) 且不许用内置字符串查找？** 思路：手写 KMP，对 subRoot 序列求 next 数组，在 root 序列上做线性扫描；或对两棵树做树哈希（如按「左哈希、右哈希、值」三元组取模），先算 subRoot 哈希再在 root 上滚动比对。
2. **追问：改成判断「root 是否包含 subRoot 作为**任意连通子图**（不要求是完整子树）」？** 思路：这就不是子树匹配而是子树包含问题，需要树形 DP，对每个节点算「以它为根能匹配 subRoot 的哪个前缀状态」，复杂度 O(n·m) 或借助 AC 自动机优化。
3. **追问：如果 root 极大（百万节点）而 subRoot 很小，怎么加速？** 思路：先算 subRoot 的节点数与高度，在 root 上只对「子树高度 ≥ subRoot 高度」的节点尝试匹配，用一次 DFS 预处理每个节点的高度，把候选集大幅缩小。

## 9. 举一反三（2-3 道同类题）

- **100. 相同的树**：本题的内层 `_same` 就是它，两棵固定树的同构判定，是本题的子过程。
- **101. 对称二叉树**：同样是「递归比对两棵子树」，只是比对对象变成同一棵树的左右孩子且方向镜像。
- **437. 路径总和 III**：外层遍历 + 内层从每个起点做一次搜索，和本题「枚举起点 × 内层匹配」的结构完全同构，可对照理解「双重递归」的复杂度分析方式。
