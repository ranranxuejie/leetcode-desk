## 1. 一句话本质

统计有多少对下标 `(i, j)`（`i <= j`）满足「前 j+1 项之和」与「前 i 项之和」对 k 同余——即把「子数组和整除」翻译成「两个前缀和落在同一个余数桶里」。

## 2. 读完题的第一反应

朴素解法：枚举所有子数组（`O(n²)` 个），对每个求和再判断能否被 k 整除。求和本身可以靠前缀和做到 `O(1)`，但枚举子数组仍是 `O(n²)`。n 最大 3×10⁴，`n² ≈ 9×10⁸`，Python 里必然超时。瓶颈在「枚举所有 (i, j) 对」。

关键观察：设 `P[t] = nums[0] + ... + nums[t-1]`（`P[0] = 0`），则子数组 `nums[i..j]` 的和是 `P[j+1] - P[i]`。它被 k 整除，等价于

```
P[j+1] ≡ P[i]  (mod k)
```

也就是说，**我们不需要知道前缀和的具体值，只需要知道它除以 k 的余数**。于是问题变成：把所有前缀和按余数分桶，同一个桶里任取两个（前一个下标小、后一个下标大），就对应一个合法子数组。桶内若有 c 个前缀和，就贡献 `C(c, 2)` 个答案。这样只需扫一遍数组、维护一个大小为 k 的计数表，`O(n)` 解决。

这一步之所以能想到，是因为「整除」这个条件天然只跟余数有关，而前缀和之差又天然把「区间和」转成了「两个前缀和的差」——两个性质一叠加，余数就成了唯一需要跟踪的状态。

## 3. 从暴力到最优

**暴力版**：双重循环枚举 `i, j`，内层累加求和。时间 `O(n²)`（若用前缀和数组则枚举仍是 `O(n²)`，求和降到 `O(1)`，但量级不变）。

**瓶颈在哪**：对每个右端点 j，我们要找有多少个 i 使 `P[i] ≡ P[j+1] (mod k)`。暴力是回头一个个比，`O(n)` 每次；而「某个余数出现过几次」是可以边扫边累计的——扫到 j 时，之前所有 `P[i]` 的余数分布已经记在表里了，直接查表就是 `O(1)`。

**小例子走一遍**：`nums = [4,5,0,-2,-3,1], k = 5`。

先算前缀和（含 `P[0]=0`）：`0, 4, 9, 9, 7, 4, 5`。

按 Python 的 `%` 取余（结果非负）：`0, 4, 4, 4, 2, 4, 0`。

维护 `count` 字典，初始 `{0: 1}`（代表空前缀 `P[0]`），`ans = 0`：

| 处理到 | 前缀和 | 余数 r | 查表 count[r] | ans 累加 | 更新后 count |
|---|---|---|---|---|---|
| P[1] | 4 | 4 | 0 | 0 | {0:1, 4:1} |
| P[2] | 9 | 4 | 1 | 1 | {0:1, 4:2} |
| P[3] | 9 | 4 | 2 | 3 | {0:1, 4:3} |
| P[4] | 7 | 2 | 0 | 3 | {0:1, 4:3, 2:1} |
| P[5] | 4 | 4 | 3 | 6 | {0:1, 4:4, 2:1} |
| P[6] | 5 | 0 | 1 | 7 | {0:2, 4:4, 2:1} |

最终 `ans = 7`，与示例一致。

注意第 4 行：`P[4]=7` 余 2，之前没有余 2 的前缀，所以不贡献；但它自己进了桶，供后面用。第 6 行：`P[6]=5` 余 0，之前 `P[0]=0` 也在余 0 桶里，贡献 1 个，对应整个数组 `[4,5,0,-2,-3,1]`，和为 5，确实被 5 整除。

**从暴力到最优的消瓶颈过程**：暴力对每个 j 回扫所有 i，是 `O(n)`；哈希表把「回扫」换成「查一次计数」，降到 `O(1)`，总时间 `O(n)`。空间从 `O(1)` 变成 `O(k)`（或 `O(min(n,k))`，因为余数最多 k 种）。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义扫描到下标 t（即已处理 `P[0..t]`）时的不变量：

> `count[r]` 恰好等于 `P[0..t]` 中余数为 r 的前缀和个数；`ans` 恰好等于所有满足 `0 <= i < j <= t` 且 `P[i] ≡ P[j] (mod k)` 的下标对数。

**初始化**：t=0 时只有 `P[0]=0`，`count={0:1}`，`ans=0`，不变量成立。

**归纳步**：处理 `P[t+1]`，余数 r。此前 `count[r]` 个前缀和都与它同余，每一个都对应一个以 `t+1` 为右端、以那个前缀和为左端前一位的合法子数组，且这些子数组右端点都是 `t+1`、左端点互不相同，所以**不重**；而所有右端点为 `t+1` 的合法子数组，其左端前缀和必与 `P[t+1]` 同余，必在 `count[r]` 中被数到，所以**不漏**。累加后把 `P[t+1]` 计入 `count[r]`，不变量对 t+1 成立。

**为什么不会重**：每个子数组由唯一的右端点 `j+1` 和唯一的左端前缀下标 i 确定，它只在处理 `P[j+1]` 那一步被计数一次，之后不会再被数。**为什么不会漏**：任何合法子数组 `nums[i..j]` 都满足 `P[j+1] ≡ P[i]`，处理 `P[j+1]` 时 `P[i]` 已在表中（因为 `i <= j`，`P[i]` 更早被处理），必被计入。

另外要说明**负数的取余**：Python 中 `-3 % 5 == 2`，结果非负，正好符合「余数落在 `[0, k-1]`」的桶编号需求。若用 C++/Java 的 `%`，负数会得到负余数，需要 `(x % k + k) % k` 修正——这是本题最容易踩的坑之一。

## 5. 完整代码（Python）

```python
class Solution:
    def subarraysDivByK(self, nums: list[int], k: int) -> int:
        # count[r] = 目前为止余数为 r 的前缀和出现了几次
        # 初始放入 P[0] = 0，余数为 0，出现 1 次
        count = {0: 1}
        prefix = 0      # 当前前缀和
        ans = 0         # 合法子数组个数

        for x in nums:
            prefix += x                 # 更新前缀和
            r = prefix % k              # Python 的 % 对负数也返回非负余数，直接可用
            # 之前有多少个前缀和与当前同余，就有多少个以当前位置结尾的合法子数组
            ans += count.get(r, 0)
            # 把当前前缀和计入桶，供后面的位置使用
            count[r] = count.get(r, 0) + 1

        return ans
```

若想用数组代替字典（k 最大 10⁴，完全开得起），可写成 `count = [0] * k; count[0] = 1`，循环里 `ans += count[r]; count[r] += 1`，常数更小、更快。两种写法逻辑完全一致，字典版更通用（k 很大时省空间）。

## 6. 复杂度

- **时间 `O(n)`**：外层只遍历 nums 一次，共 n 次迭代；每次迭代做常数次哈希表查/改（均摊 `O(1)`），所以是 `n × O(1) = O(n)`。这里没有 log n 项——没有排序、没有二分。
- **空间 `O(min(n, k))`**：哈希表最多存 `min(n+1, k)` 个不同余数（余数只有 k 种，前缀和只有 n+1 个）。数组写法固定 `O(k)`。题目给 `k <= 10⁴`，空间完全可控。

对比暴力 `O(n²)` 时间、`O(1)` 空间：本题是用 `O(k)` 的空间换掉了 `O(n)` 的每步回扫。

## 7. 边界与反例（至少 4 条）

1. **`nums = [5], k = 9`** → 期望 `0`。前缀和 5，余 5，表里只有余 0，贡献 0。容易错在：忘记初始化 `count[0]=1` 时，会把「整个数组自身」这类子数组漏掉；反过来若把 `P[0]` 重复计入又会多算。
2. **`nums = [-1, 2, 9], k = 2`** → 期望 `2`（子数组 `[2]`、`[-1,2,9]` 和为 10）。前缀和 `0,-1,1,10`，余数 `0,1,1,0`。若用 C 风格取余，`-1 % 2 = -1`，桶编号变负，会漏掉 `[-1,2,9]` 这一对（`P[1]` 与 `P[3]` 同余 1）。Python 无此问题，但迁移语言时必须修正。
3. **`nums = [0,0,0], k = 3`** → 期望 `6`（所有非空子数组和都是 0）。前缀和全 0，余数全 0，桶内 4 个元素（含 `P[0]`），`C(4,2)=6`。容易错在：只数「相邻」或漏掉长度为 1 的 `[0]`。
4. **`nums = [4,5,0,-2,-3,1], k = 5`** → 期望 `7`（官方示例）。容易错在：把 `[5,0,-2,-3]` 这类「中间跨过 0 和负数」的子数组漏掉，因为直觉上负数会「抵消」，但余数视角下它们恰好同余。
5. **`k` 大于所有前缀和绝对值**（如 `nums=[1,2], k=100`）→ 期望 `0`。此时余数就是前缀和本身，各不同，桶里永远只有 1 个，贡献 0。容易错在：误以为「和小于 k 就一定不整除」而提前返回，其实要扫完才知道。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求子数组和「恰好等于 k 的倍数且长度至少为 2」怎么办？** 思路：仍用余数分桶，但计数时排除「右端点 - 左端点 = 1」的那一对，即查表时减去「上一个位置的前缀和是否同余」这一项，或维护两个桶（前一位单独记）。
2. **追问：如果 k 可能为 0 或负数？** 思路：k=0 时「整除」无定义，需按题意特判（通常约定返回 0 或抛错）；k 为负时取 `abs(k)` 即可，因为整除性与符号无关，桶大小用 `|k|`。
3. **追问：不只要个数，还要返回所有满足条件的子数组？** 思路：桶里不能只存计数，要存「前缀和下标列表」，查表时把当前下标与列表中每个下标配对输出，最坏输出本身是 `O(n²)`，无法更优。

## 9. 举一反三（2-3 道同类题）

- **560. 和为 K 的子数组**：把「同余」换成「差等于 K」，同样是前缀和 + 哈希表，是本题的「加法版」母题。
- **523. 连续的子数组和**：判断是否存在长度 ≥ 2 的子数组和是 k 的倍数，余数分桶 + 记录最早下标，是本题的「存在性判定」变体。
- **525. 连续数组**：把 0 看成 -1，求和为 0 的最长子数组，本质仍是「两个前缀和相等」，只是桶里存的是下标而非计数。
