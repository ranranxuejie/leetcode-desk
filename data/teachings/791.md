## 1. 一句话本质

把 `s` 中**出现在 `order` 里的字符**按 `order` 给定的先后关系重排，**不在 `order` 里的字符**原样保留、位置随意——本质是「按一张外部给定的优先级表做稳定分组排序」。

## 2. 读完题的第一反应

**朴素解法**：把 `order` 看成一个比较器——对 `s` 中任意两个字符 `x`、`y`，若 `x` 在 `order` 中排在 `y` 前面，则 `x < y`；若某个字符不在 `order` 中，就认为它和谁都「不可比」。然后对 `s` 调用 `sorted(s, key=cmp_to_key(...))`。

它卡在哪？两个地方：

1. **比较器不是全序**。`order` 只覆盖 26 个字母中的一部分，`s` 里可能混入 `order` 之外的字符。若把「不可比」当成「相等」，Python 的 `sorted` 依赖的排序算法（Timsort）要求比较关系满足传递性，一旦比较器自相矛盾，结果就是未定义行为——不是「可能不最优」，而是**可能直接错**。这是很多人写 `cmp_to_key` 时踩的坑。
2. **复杂度不划算**。每次比较都要在 `order` 里查位置，若用 `order.index(c)` 就是 O(26)，比较次数是 O(n log n)，总代价 O(26·n log n)。虽然 26 是常数，但思路本身绕远了。

**关键观察**：题面说 `order` 中字符**互不相同**，且 `s` 只含小写字母。这意味着「优先级」可以**预先固化成一张 26 大小的表**：`rank[c] = order 中 c 的下标`，不在 `order` 里的字符给一个统一的「最低优先级」。有了这张表，排序就退化成「按一个整数键排序」，不再需要自定义比较器。

再进一步：既然只有 26 种字符，**根本不用排序**。数出 `s` 里每个字符出现几次（计数），然后按 `order` 的顺序把字符「倒出来」，最后把 `order` 之外的字符补上即可。计数排序的思想——当键的取值域很小（26）时，排序可以做到线性。

## 3. 从暴力到最优

**第一步：暴力比较器。** 对 `s` 做 `sorted`，key 是 `order.index(c)`，不在 `order` 里的给 `len(order)`。这一步已经能过题，但每次 key 计算是 O(26)，总 O(26·n log n)。

**第二步：预计算 rank 表。** 先扫一遍 `order` 建 `rank` 数组，之后每次查 key 是 O(1)。总代价降到 O(26 + n log n)。瓶颈变成 `n log n` 的排序本身。

**第三步：计数排序消掉 log n。** 注意到键只有 26 种取值，排序没必要比较。改成：

- 扫 `s` 统计 `cnt[26]`；
- 按 `order` 顺序遍历，`c` 出现几次就输出几次；
- 再扫一遍 26 个字母，把**不在 `order` 里**且 `cnt > 0` 的字符补到末尾。

**走一遍小例子**：`order = "cba"`, `s = "abcd"`。

- 建 rank：`rank['c']=0, rank['b']=1, rank['a']=2`，其余为「不在表内」。
- 统计 `cnt`：`a:1, b:1, c:1, d:1`。
- 按 `order` 输出：`c` 一次 → `"c"`；`b` 一次 → `"cb"`；`a` 一次 → `"cba"`。
- 补 `order` 外字符：扫 `a..z`，只有 `d` 满足「不在 order 且 cnt>0」→ 追加 `"cbad"`。

结果 `"cbad"`，与示例一致。注意 `d` 放末尾只是**一种**合法答案，题面明确允许任意位置。

再看一个带重复字符的：`order = "bcafg"`, `s = "aabbccd"`。

- `cnt`：`a:2, b:2, c:2, d:1`。
- 按 `order` 输出：`b`×2 → `"bb"`；`c`×2 → `"bbcc"`；`a`×2 → `"bbccaa"`；`f`、`g` 计数为 0 跳过。
- 补 `order` 外：`d`×1 → `"bbccaad"`。

`order` 内的字符严格按 `b→c→a` 排列，重复字符各自聚在一起，符合要求。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证。设最终输出串为 `res`，我们断言构造过程中始终满足：

> **不变量**：`res` 中已输出的字符，恰好是 `s` 中「属于 `order` 且已处理到 `order` 当前位置」的那些字符，且每个字符的输出次数等于它在 `s` 中的出现次数。

分三段验证：

1. **不漏**：`s` 的每个字符要么在 `order` 里，要么不在。在 `order` 里的，第二阶段按 `order` 逐个字符、按其 `cnt` 次数全部输出；不在 `order` 里的，第三阶段扫全 26 个字母时被捕获。两阶段覆盖了 `s` 的全部字符，且 `cnt` 来自对 `s` 的完整统计，所以每个字符输出次数 = 出现次数，一个不多一个不少。
2. **不重**：第二阶段只遍历 `order` 中的字符（互不相同，题面保证），第三阶段只遍历「不在 `order` 中」的字符，两个集合**不相交**，同一个字符不可能被输出两次。
3. **顺序正确**：对 `order` 中任意 `x` 排在 `y` 之前，第二阶段先处理 `x` 再处理 `y`，故 `res` 中所有 `x` 都在所有 `y` 之前——这正是题面要求的「`x` 出现在 `y` 之前」。对 `order` 外的字符，题面不施加任何约束，放哪都合法。

三段合起来：输出长度 = `len(s)`，字符多重集与 `s` 相同，且 `order` 内相对顺序被满足，故 `res` 是合法答案。**没有用到任何「显然」**——每一条都对应题面的一句约束（`order` 唯一、`s` 小写、`order` 外字符位置任意）。

## 5. 完整代码（Python）

```python
class Solution:
    def customSortString(self, order: str, s: str) -> str:
        # 1) 统计 s 中每个小写字母的出现次数
        cnt = [0] * 26
        for ch in s:
            cnt[ord(ch) - ord('a')] += 1

        # 2) 标记哪些字母出现在 order 中（用于第 4 步区分）
        in_order = [False] * 26
        for ch in order:
            in_order[ord(ch) - ord('a')] = True

        res = []

        # 3) 按 order 的顺序输出：每个字符出现几次就追加几次
        for ch in order:
            idx = ord(ch) - ord('a')
            if cnt[idx] > 0:
                res.append(ch * cnt[idx])
                cnt[idx] = 0  # 清零，防止第 4 步重复输出

        # 4) 补上不在 order 中的字符（顺序任意，这里按字母序）
        for i in range(26):
            if cnt[i] > 0 and not in_order[i]:
                res.append(chr(ord('a') + i) * cnt[i])

        return ''.join(res)
```

关键点说明：第 3 步输出后**必须把 `cnt[idx]` 清零**，否则第 4 步的 `cnt[i] > 0` 判断会把 `order` 内字符再输出一遍。`in_order` 数组是第二道保险——即使忘了清零，`not in_order[i]` 也能挡住，但两者都写更稳。

## 6. 复杂度

设 `n = len(s)`，`m = len(order)`，字母表大小 `Σ = 26`。

- **时间**：统计 `cnt` 扫 `s` 一遍 O(n)；建 `in_order` 扫 `order` 一遍 O(m)；第 3 步遍历 `order` O(m)，每次 `append` 的字符串拼接总长度不超过 n；第 4 步固定扫 26 个字母 O(Σ)。合计 **O(n + m + Σ) = O(n + m)**。注意这里**没有 log n**——因为我们没有比较排序，计数排序把 log 因子消掉了。
- **空间**：`cnt` 和 `in_order` 各 26 个槽位 O(Σ)；`res` 存最终结果 O(n)。合计 **O(n + Σ)**。若不计输出串，额外空间是 O(Σ) = O(1)。

对比一下：若用 `sorted` + rank 表，时间是 O(n log n)，空间 O(n)；计数排序版本把 log 因子换成了常数 26，这是「键值域小」带来的红利。

## 7. 边界与反例（至少 4 条）

1. **`s` 全是 `order` 外字符**：`order = "cba"`, `s = "xyz"` → 期望 `"xyz"`（或任意排列）→ 容易错在：第 3 步一个都不输出，若第 4 步的 `in_order` 判断写反（写成 `in_order[i]`），会输出空串。
2. **`s` 中某字符重复多次**：`order = "cba"`, `s = "aaabbbccc"` → 期望 `"cccbbbaaa"` → 容易错在：只输出一次而非 `cnt` 次，或忘记清零导致第 4 步重复追加。
3. **`order` 比 `s` 长、且 `s` 只覆盖部分字符**：`order = "abcdefg"`, `s = "cae"` → 期望 `"ace"`（`a` 在 `c` 前？不，`order` 中 `a` 在 `c` 前，故 `a` 先）→ 实际 `order` 顺序是 `a,b,c,d,e,f,g`，`s` 中 `c,a,e` 按 `order` 排是 `a,c,e` → 容易错在：误以为按 `s` 中首次出现顺序排。
4. **`order` 与 `s` 完全相同**：`order = "abc"`, `s = "abc"` → 期望 `"abc"` → 容易错在：第 4 步把 `order` 内字符又补一遍，得到 `"abcabc"`（长度都不对）。
5. **`s` 长度为 1**：`order = "z"`, `s = "a"` → 期望 `"a"` → 容易错在：`order` 里没有 `a`，若第 4 步漏写，返回空串。

## 8. 面试追问与变体（3 条）

1. **追问：如果 `order` 允许有重复字符怎么办？** 思路：题面保证唯一，但若放宽，`rank` 表要取**首次出现**的下标（`rank.setdefault`），第 3 步遍历 `order` 时也要去重，否则同一字符输出多次。
2. **追问：如果要求 `order` 外字符也按某种规则（比如字典序）排，且必须稳定？** 思路：第 4 步从「扫 26 个字母」改成「对 `order` 外字符做一次 `sorted`」，或直接对 `s` 用 `(rank[c], c)` 做双键排序，一次 `sorted` 搞定，代价 O(n log n)。
3. **追问：如果 `s` 很大（比如 10^7），内存吃紧，能否流式输出？** 思路：计数排序天然适合——先扫一遍 `s` 建 `cnt`（O(Σ) 内存），再按 `order` 顺序「生成」输出，不需要把 `s` 全存下来；但输入本身若不能重读，仍需 O(n) 存 `s` 或至少存 `cnt`。
