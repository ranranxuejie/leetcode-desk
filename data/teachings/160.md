## 1. 一句话本质

在两条单链表中，找到**第一个内存地址相同**的节点（不是值相同），找不到就返回 `None`。

这里有个必须先钉死的点：题面示例 1 特意强调「值为 1 的节点不是交点，因为它们在内存中指向不同位置」。所以这道题比较的是**节点对象本身**（Python 里就是 `is`），不是 `val`。这是整道题所有解法的地基。

## 2. 读完题的第一反应

**朴素解法**：拿 A 的每个节点，去 B 里从头扫一遍，看有没有同一个对象。时间 O(m·n)，空间 O(1)。卡在哪？卡在「每次都要重新扫 B」——B 被反复遍历了 m 次，这个重复劳动就是瓶颈。

**稍微聪明一点**：把 A 的所有节点塞进一个哈希集合，再遍历 B，第一个命中集合的节点就是答案。时间降到 O(m+n)，但空间 O(m)。这已经能过题，但它没回答进阶要求「O(1) 内存」。

**关键观察**：两条链表一旦相交，从交点往后的部分是**完全共享**的（同一批节点对象）。这意味着——如果两条链表等长，我们让两个指针同步往前走，第一次 `pA is pB` 的地方就是交点。问题只出在「长度不等」：短的那条会先走完，长的那条还在自己的私有前缀里。

于是下一步自然浮现：**能不能让两个指针走的总路程相等，从而同时到达交点？** 这就是双指针交换起点的思路来源——不是凭空想出来的技巧，而是「同步走」这个朴素想法被长度差卡住之后的直接修补。

## 3. 从暴力到最优

**第一步：哈希表。** 遍历 A 把节点对象存进 `set`，再遍历 B 查表。瓶颈从「重复扫 B」变成「额外 O(m) 空间」。对面试来说这已经是合格答案，但进阶要求卡在这。

**第二步：双指针交换起点。** 设 `pA` 从 headA 出发、`pB` 从 headB 出发，每次各走一步；谁走到 `None`，就跳到另一条链的头继续走。两个指针都最多走 m+n 步，且**走的总步数相同**，所以它们会在同一时刻到达交点（或同时变成 `None`）。

用示例 1 走一遍，A = [4,1,8,4,5]（m=5），B = [5,6,1,8,4,5]（n=6），交点是值为 8 的那个节点：

| 步数 | pA 所在 | pB 所在 |
|---|---|---|
| 0 | 4 | 5 |
| 1 | 1 | 6 |
| 2 | **8** | 1 |
| 3 | 4 | **8** |
| 4 | 5 | 4 |
| 5 | None → 跳到 headB=5 | 5 |
| 6 | 6 | None → 跳到 headA=4 |
| 7 | 1 | 1 |
| 8 | **8** | **8** ← 相遇 |

注意第 8 步：`pA` 走完了 A 的 5 个节点 + B 的前 3 个节点（5,6,1），`pB` 走完了 B 的 6 个节点 + A 的前 2 个节点（4,1），两边都走了 8 步，同时落在交点。**长度差被「换道」自动抹平了**：pA 多走的那段正好是 B 的私有前缀，pB 多走的那段正好是 A 的私有前缀。

**不相交的情况**（示例 3）：A = [2,6,4]，B = [1,5]。pA 走 3 步到 None 跳 headB，再走 2 步到 None；pB 走 2 步到 None 跳 headA，再走 3 步到 None。两边都在第 5 步变成 `None`，循环条件 `pA is not pB` 退出，返回 `None`。**不相交时它们也会「同时」到达 None**，所以不需要额外判断。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。定义：任一时刻，`pA` 走过的步数等于 `pB` 走过的步数（记为 k）。这个不变量在初始化时成立（都是 0），每轮循环两边各走一步、或各跳一次，仍然成立。

**相交时**：设 A 的私有前缀长 a（= skipA），B 的私有前缀长 b（= skipB），公共部分长 c。则 m = a+c，n = b+c。两个指针各走 m+n = a+b+2c 步后，pA 的路径是「A 全程 + B 全程」= a+c+b+c，pB 是「B 全程 + A 全程」= b+c+a+c，**路径完全同构**，都会在走完 a+b+c 步后落在交点。由于不变量保证同步，它们必然在同一轮同时落在交点，第一次 `pA is pB` 就命中，不会漏。

**为什么不会重（不会返回错误的节点）**：在交点之前，pA 和 pB 分别位于两条链的私有前缀上，这些节点对象互不相同（题面保证「不存在环」且相交结构是 Y 形，私有前缀不共享）。所以第一次相等一定发生在交点，不可能提前误判。

**不相交时**：两条链没有共享节点，两个指针各走 m+n 步后同时变成 `None`，`None is None` 为真，循环退出返回 `None`。不变量同样保证它们同步到达 None，不会一个先到、一个还在走导致死循环。

## 5. 完整代码（Python）

```python
class ListNode:
    def __init__(self, x):
        self.val = x
        self.next = None


class Solution:
    def getIntersectionNode(self, headA: ListNode, headB: ListNode) -> ListNode:
        # 空链表直接无交点（题面 m,n >= 1，但防御性写上）
        if headA is None or headB is None:
            return None

        pA, pB = headA, headB

        # 关键：用 is 比较对象身份，不是比较 val
        # 循环退出条件有两种：pA is pB 命中交点，或两者同时为 None（不相交）
        while pA is not pB:
            # 走到尽头就跳到另一条链的头，制造「等长」效果
            pA = pA.next if pA is not None else headB
            pB = pB.next if pB is not None else headA

        # 此时 pA 要么是交点，要么是 None
        return pA
```

注意 `pA = pA.next if pA is not None else headB` 这一行：**先判断再跳**，保证 `pA` 为 `None` 时不会去访问 `None.next`。这是本题最容易写崩的一行。

## 6. 复杂度

**时间 O(m+n)**：`pA` 最多走 m+n 步（A 全程 + B 全程），`pB` 同理，循环体每轮两边各走一步，总轮数不超过 m+n。m 来自 listA 节点数，n 来自 listB 节点数，没有 log 项——因为没有任何分治或排序操作。

**空间 O(1)**：只用了 `pA`、`pB` 两个指针变量，不随输入规模增长。哈希表解法是 O(m) 或 O(min(m,n))，双指针把它压到了常数。

## 7. 边界与反例（至少 4 条）

1. **两链在头节点就相交**：A = [1,2,3]，B = [1,2,3] 且 headA is headB → 期望返回 headA → 容易错在循环条件写成 `while pA and pB` 导致一进来就退出、或先移动再判断，跳过了头节点。
2. **一条链是另一条的后缀**：A = [1,2,3]，B = [2,3] 且 B 的头就是 A 的第二个节点 → 期望返回那个节点 → 容易错在「先算长度差再对齐」的写法里，差值为 0 时忘了处理，或对齐逻辑写反。
3. **完全不相交**：A = [2,6,4]，B = [1,5] → 期望 `None` → 容易错在循环里只判断 `pA is not pB` 却没处理两者同时为 None 的情况，或者跳转逻辑写成 `pA = pA.next or headB`（`or` 在节点对象上语义不对，且 None 判断会出错）。
4. **值相同但对象不同**：A = [1,9,1,2,4]，B = [3,2,4]，A 的第二个 1 和 B 里没有的 1 → 期望返回值为 2 的节点 → 容易错在用 `pA.val == pB.val` 判断，会在值为 1 的地方误判（示例 1 的坑）。
5. **长度差极大**：A 长 30000、B 长 1 且不相交 → 期望 `None` → 容易错在跳转后没有正确终止，或误以为会死循环（实际 m+n 步内必停）。

## 8. 面试追问与变体（3 条）

1. **追问：如果链表可能有环怎么办？** 思路：先用快慢指针分别判断各自是否有环并找环入口，再分「都无环 / 都有环 / 一有一无」讨论，有环时把环入口当作「尾部」处理。
2. **追问：不允许修改链表结构，但允许 O(m) 空间，你会怎么做？** 思路：哈希集合存 A 的节点，遍历 B 查表，第一个命中即答案——这是本题的保底解法，面试时可以先说它再优化到双指针。
3. **追问：如果要求返回交点到各自头的距离呢？** 思路：在双指针相遇后，从交点分别往回数（或提前记录两条链长度和 skip 值），距离就是 skipA 和 skipB。
