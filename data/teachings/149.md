## 1. 一句话本质

在所有点对确定的直线中，找一条被最多点「共线」穿过的线，返回这条线上的点数。

## 2. 读完题的第一反应

**朴素解法**：枚举任意两点确定一条直线，再扫一遍所有点看有多少点落在这条线上。点对数量是 O(n²)，每次验证又要 O(n)，总复杂度 O(n³)。n 最大能到 300，n³ = 2.7×10⁷ 其实勉强能过，但这不是面试官想看的——它没有利用「同一条直线上的点共享同一个斜率」这个结构。

**关键观察**：一条直线由「一个点 + 一个方向（斜率）」唯一确定。如果我们固定一个点 P 作为「锚点」，那么所有与 P 共线的点，它们相对 P 的斜率必然相同。于是问题从「枚举直线」变成「对每个锚点，统计它到其余各点的斜率，看哪个斜率出现次数最多」。

这一步转换为什么能想到？因为「共线」这个几何条件，翻译成代数就是「斜率相等」。而「统计出现次数最多的值」正是哈希表的拿手好戏。所以自然的方向是：**外层枚举锚点，内层用哈希表按斜率计数**。

## 3. 从暴力到最优

**暴力**：三重循环，i、j 定直线，k 验证。瓶颈在「每条直线都要重新扫全部点」，验证是 O(n)，总 O(n³)。

**优化第一步**：固定锚点 i，只枚举 j > i，算斜率 k_ij，用字典 `cnt[k] += 1`。这样对每个 i 只需 O(n) 时间，总 O(n²)。瓶颈从「验证」变成了「斜率怎么表示」。

**优化第二步（关键坑）**：斜率用浮点数 `(y2-y1)/(x2-x1)` 会因精度丢失把不同斜率误判为相同（比如 1/3 和 2/6 在浮点下可能不等，或大数相除丢精度）。正确做法是用**最简分数**表示方向：把 `dy = y2-y1`、`dx = x2-x1` 同时除以 `gcd(|dy|,|dx|)`，并统一符号（让 dx 恒为正，或 dx=0 时 dy 恒为正），得到互质的 `(dx, dy)` 作为字典的 key。

**小例子走一遍**：points = [[1,1],[3,2],[5,3],[4,1],[2,3],[1,4]]，锚点取 (1,1)。

| j | 点 | dy | dx | gcd | 约分后 (dx,dy) | cnt 更新后 |
|---|---|---|---|---|---|---|
| 1 | (3,2) | 1 | 2 | 1 | (2,1) | {(2,1):1} |
| 2 | (5,3) | 2 | 4 | 2 | (2,1) | {(2,1):2} |
| 3 | (4,1) | 0 | 3 | 3 | (1,0) | {(2,1):2,(1,0):1} |
| 4 | (2,3) | 2 | 1 | 1 | (1,2) | {(2,1):2,(1,0):1,(1,2):1} |
| 5 | (1,4) | 3 | 0 | 3 | (0,1) | {(2,1):2,(1,0):1,(1,2):1,(0,1):1} |

锚点 (1,1) 上最大计数是 2，加上锚点自己 = 3 个点共线（(1,1),(3,2),(5,3) 确实在 y=0.5x+0.5 上）。对所有锚点取最大值，最终得到 4。

## 4. 正确性：为什么不会漏、不会重

**不变量**：对任意一条含 m ≥ 2 个点的直线 L，设 L 上按任意顺序取一个点 P 作为锚点，则 L 上其余 m-1 个点相对 P 的斜率全部相同（都等于 L 的斜率）。因此当外层循环走到 P 时，哈希表中该斜率对应的计数恰好是 m-1，`m-1+1 = m` 会被记录到答案里。所以**任何一条直线上的点数都不会被漏掉**。

**不会重**：外层每个锚点独立统计，答案取的是所有锚点结果的最大值，不是求和，所以同一条直线被多个锚点重复统计也不影响最大值。另外内层只枚举 j > i，避免同一对点被算两次（虽然对最大值无影响，但省一半常数）。

**边界**：当所有点重合时（题面保证互不相同，所以不会发生），或 n=1 时，没有斜率可算，答案应为 1，代码里用 `max(ans, 1)` 兜底。

## 5. 完整代码（Python）

```python
from math import gcd
from collections import defaultdict

class Solution:
    def maxPoints(self, points) -> int:
        n = len(points)
        if n <= 2:
            return n  # 少于等于两个点，必然全共线

        ans = 1
        for i in range(n):
            x1, y1 = points[i]
            cnt = defaultdict(int)  # key: (dx, dy) 最简方向, value: 该方向上的点数
            for j in range(i + 1, n):
                x2, y2 = points[j]
                dx = x2 - x1
                dy = y2 - y1
                g = gcd(abs(dx), abs(dy))  # 求最大公约数用于约分
                dx //= g
                dy //= g
                # 统一符号：保证 (dx, dy) 与 (-dx, -dy) 映射到同一个 key
                if dx < 0 or (dx == 0 and dy < 0):
                    dx, dy = -dx, -dy
                cnt[(dx, dy)] += 1
            # 当前锚点上的最大共线数 = 最大方向计数 + 锚点自己
            if cnt:
                ans = max(ans, max(cnt.values()) + 1)
            else:
                ans = max(ans, 1)
        return ans
```

关键点说明：`gcd(abs(dx), abs(dy))` 在 dx=dy=0 时 gcd(0,0)=0 会除零，但题面保证点互不相同，所以 dx、dy 不会同时为 0，安全。符号统一那行是必须的，否则 (1,2) 和 (-1,-2) 会被当成两个方向，导致同一直线上的点被拆到两个桶里。

## 6. 复杂度

- **时间 O(n²)**：外层 n 个锚点，内层对每个锚点枚举 n-i-1 个点，合计约 n²/2 次。每次内层做一次 gcd，gcd 的代价是 O(log C)，C 是坐标差的最大值（≤ 2×10⁴）。所以严格说是 O(n² log C)，但 log C 是常数级，通常记作 O(n²)。
- **空间 O(n)**：每个锚点的哈希表最多存 n-1 个不同方向，字典大小 O(n)。没有存储所有点对的斜率，所以不是 O(n²)。

## 7. 边界与反例（至少 4 条）

1. **输入 [[1,1]]** → 期望 1 → 容易错：内层循环不执行，`cnt` 为空，若直接 `max(cnt.values())` 会抛异常，必须用 `if cnt` 兜底。
2. **输入 [[1,1],[2,2]]** → 期望 2 → 容易错：n=2 时若走通用逻辑也能得 2，但提前返回更清晰；若忘记处理 n≤2，某些写法会返回 1。
3. **输入 [[0,0],[1,1],[2,2],[3,3]]** → 期望 4 → 容易错：斜率全为 1，若用浮点 `dy/dx` 且坐标很大时可能精度问题；用约分后的 (1,1) 则稳定。
4. **输入 [[1,1],[2,2],[3,3],[1,2]]** → 期望 3 → 容易错：锚点 (1,1) 时 (2,2)、(3,3) 斜率 (1,1) 计数 2，(1,2) 斜率 (0,1) 计数 1，答案 3；若符号没统一，(-1,-1) 和 (1,1) 会分裂。
5. **输入 [[0,0],[1,0],[0,1]]** → 期望 2 → 容易错：三条线各只有 2 点，没有 3 点共线，答案应为 2 而不是 3；若把「锚点+计数」算错成计数本身会得 1。

## 8. 面试追问与变体（3 条）

1. **追问：如果点坐标是浮点数怎么办？** 思路：浮点无法用 gcd 约分，改用「方向向量 + 容差」或把坐标转成有理数（Fraction）表示斜率，但要注意性能。
2. **追问：如果要求返回那条直线本身（方程或两个端点）？** 思路：在哈希表里同时记录该方向对应的一个代表点，最后反解直线方程。
3. **追问：如果点会重复（题面不保证互不相同）？** 思路：先去重并记录每个位置的重数，统计斜率时把重数累加，最后答案要加上锚点自身的重数。
