## 1. 一句话本质

在一个**已经排好序**的数组里，用「每次砍掉一半候选区间」的方式定位目标值的下标，砍到最后要么命中、要么确认不存在。

## 2. 读完题的第一反应

**朴素解法**：从头到尾扫一遍，`for i in range(len(nums))`，遇到 `nums[i] == target` 就返回 `i`。这是 O(n)。

它卡在哪？题面最后一句是硬约束：「你必须编写一个具有 O(log n) 时间复杂度的算法」。线性扫描是 O(n)，n 最大 10000，虽然实际跑得动，但**不满足题目要求的复杂度**，面试里直接判错。所以瓶颈不是「能不能做出来」，而是「必须比逐个看更快」。

**关键观察**：题面第一句给了「有序的（升序）整型数组」。有序意味着元素之间的大小关系是已知的、可比较的。于是对任意一个位置 `mid`，我不用看 `nums[mid]` 之外的东西，就能做一个**三选一的判断**：

- `nums[mid] == target`：找到了，直接返回。
- `nums[mid] < target`：因为升序，`mid` 左边所有元素都 ≤ `nums[mid]` < target，**整段左半边可以一次性排除**。
- `nums[mid] > target`：同理，整段右半边可以一次性排除。

一次比较排除一半，这就是 O(log n) 的来源。这个观察之所以能让你想到下一步，是因为它把「逐个验证」变成了「用有序性做批量否定」——每次判断不是确认一个元素，而是否定一整段区间。

## 3. 从暴力到最优

**暴力**：候选集合是全部 n 个下标，每次看一个，最坏看 n 次。

**二分**：候选集合始终是一个**连续区间** `[left, right]`。每次取中点 `mid`，根据比较结果把区间缩成左半或右半，候选规模从 `len` 变成约 `len/2`。

用示例 1 走一遍：`nums = [-1,0,3,5,9,12]`，`target = 9`，下标 0~5。

| 轮次 | left | right | mid | nums[mid] | 比较 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 2 | 3 | 3 < 9 | left = 3 |
| 2 | 3 | 5 | 4 | 9 | 相等 | 返回 4 |

第 1 轮排除了下标 0、1、2 三个元素，第 2 轮直接命中。总共 2 次比较，而线性扫描要 5 次。

再看示例 2：`target = 2`。

| 轮次 | left | right | mid | nums[mid] | 比较 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 2 | 3 | 3 > 2 | right = 1 |
| 2 | 0 | 1 | 0 | -1 | -1 < 2 | left = 1 |
| 3 | 1 | 1 | 1 | 0 | 0 < 2 | left = 2 |

此时 `left = 2 > right = 1`，区间空了，说明 2 不在数组里，返回 -1。注意第 3 轮 `left` 越过 `right` 这个信号，就是「候选集合耗尽」的判据，循环条件必须写成 `left <= right`。

**瓶颈怎么被消掉的**：暴力法的成本来自「每个元素都要看一眼」；二分法把「看一眼」升级成「看一个中点、否定一半」，于是比较次数从 n 降到 log₂n。n = 10000 时，线性最多 10000 次，二分最多约 14 次。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**讲。维护这个断言：

> 每一轮循环开始时，如果 `target` 存在于 `nums` 中，那么它的下标一定落在闭区间 `[left, right]` 内。

**初始化**：`left = 0, right = n - 1`，区间覆盖全部下标，断言成立。

**保持**：设 `mid = (left + right) // 2`，必有 `left ≤ mid ≤ right`，即 `mid` 在区间内。

- 若 `nums[mid] == target`，直接返回 `mid`，正确。
- 若 `nums[mid] < target`：对任意 `i ≤ mid`，由升序有 `nums[i] ≤ nums[mid] < target`，所以 `target` 不可能在 `[left, mid]` 里。若它存在，只能在 `[mid+1, right]`，令 `left = mid + 1`，断言保持。
- 若 `nums[mid] > target`：对任意 `i ≥ mid`，有 `nums[i] ≥ nums[mid] > target`，`target` 不可能在 `[mid, right]` 里。若它存在，只能在 `[left, mid-1]`，令 `right = mid - 1`，断言保持。

**终止**：循环在 `left > right` 时退出，此时区间为空。由不变量，若 `target` 存在则其下标必在空区间内——矛盾。所以 `target` 不存在，返回 -1 正确。

**不会漏**：每次缩区间都是「整段否定」，被丢掉的那一半里每个元素都被严格证明不等于 target。
**不会重**：新区间是旧区间去掉 `mid` 及其一侧，`mid` 本身要么已返回、要么被排除，不会重复检查。

另外题面提示「所有元素是不重复的」，这保证返回值唯一，不需要考虑「找到多个下标返回哪个」。如果元素可重复，这段代码返回的是**某一个**匹配位置，不保证是最左或最右——这是后面变体要处理的事。

## 5. 完整代码（Python）

```python
class Solution:
    def search(self, nums, target):
        # 候选区间用闭区间 [left, right] 表示，初始覆盖整个数组
        left, right = 0, len(nums) - 1

        # 循环条件必须是 <=：当 left == right 时区间还剩一个元素，必须检查
        while left <= right:
            # 取中点。Python 整数不会溢出，直接 (left + right) // 2 即可
            mid = (left + right) // 2

            if nums[mid] == target:
                # 命中，mid 就是答案下标
                return mid
            elif nums[mid] < target:
                # 中点偏小，target 只可能在右半段，mid 本身已排除
                left = mid + 1
            else:
                # 中点偏大，target 只可能在左半段，mid 本身已排除
                right = mid - 1

        # 区间耗尽仍未命中，说明 target 不存在
        return -1
```

## 6. 复杂度

**时间 O(log n)**：每轮循环把候选区间长度从 `L` 缩到约 `L/2`（严格说是 `⌊(L-1)/2⌋` 或 `⌈(L-1)/2⌉`）。从 n 缩到 0 需要约 log₂n 轮，每轮只做常数次比较和赋值。所以总比较次数是 O(log n)。这里的 log 底数是 2，来自「每次砍一半」；n 来自数组长度，即初始候选规模。

**空间 O(1)**：只用了 `left`、`right`、`mid` 三个整型变量，与 n 无关。注意这是**迭代**写法；如果写成递归，栈深度是 O(log n)，空间就变成 O(log n) 了——面试里如果被问空间，要能说清这个区别。

## 7. 边界与反例（至少 4 条）

1. **`nums = [5], target = 5` → 期望 1 个元素时返回 0**。容易错在循环条件写成 `left < right`：此时 `left = right = 0`，循环根本不进，直接返回 -1。必须用 `<=`。

2. **`nums = [5], target = 3` → 期望 -1**。容易错在只处理了「找到」的分支，忘了区间耗尽后要返回 -1；或者把 `return -1` 写进了循环体内，导致第一轮没命中就提前退出。

3. **`nums = [1,3], target = 3` → 期望 1**。容易错在更新边界时写成 `left = mid` 而不是 `left = mid + 1`：`mid = 0`，`nums[0] = 1 < 3`，若 `left = mid = 0`，区间不变，死循环。`mid` 本身已被否定，必须 ±1 跳过它。

4. **`nums = [1,3], target = 1` → 期望 0**。对称地，容易错在写成 `right = mid` 而非 `right = mid - 1`，同样死循环。

5. **`nums = [-1,0,3,5,9,12], target = 13`（比最大值还大）→ 期望 -1**。容易错在只测了中间值，没测「越界」情形；逻辑上它和普通未命中一样，但手写时容易在 `right` 更新上出错。

6. **`nums = [-1,0,3,5,9,12], target = -2`（比最小值还小）→ 期望 -1**。与上一条对称，检验 `left` 一侧的边界推进。

## 8. 面试追问与变体（3 条）

1. **「如果数组里有重复元素，要求返回 target 第一次出现的下标，怎么改？」**
   思路：命中时不立即返回，而是记录答案并令 `right = mid - 1` 继续往左找；循环结束后返回最后一次记录的位置。本质是把「找到任意一个」改成「找左边界」。

2. **「不用 `mid = (left + right) // 2`，还有别的写法吗？为什么有些语言要写成 `left + (right - left) // 2`？」**
   思路：两者数学等价，后者是为了避免 `left + right` 在定长整型下溢出（如 Java/C++ 的 int）。Python 整数任意精度，不会溢出，但面试官问这个是在考你是否理解边界计算的隐患。

3. **「如果数组是降序的，代码要改哪里？」**
   思路：只需把两个比较分支的方向对调：`nums[mid] < target` 时往左走（`right = mid - 1`），`nums[mid] > target` 时往右走（`left = mid + 1`）。核心结构不变，变的是「哪一半被否定」。

## 9. 举一反三（2-3 道同类题）

1. **35. 搜索插入位置**：同样是升序数组 + O(log n)，区别是没找到时要返回「应该插入的位置」，即循环结束时 `left` 的值——正好是第一个大于 target 的下标。

2. **34. 在排序数组中查找元素的第一个和最后一个位置**：本题的「找左边界 + 找右边界」组合版，两次二分分别定位首尾，是第 8 节追问 1 的直接应用。

3. **69. x 的平方根**：把「在有序数组里找值」抽象成「在有序的答案空间里找值」，二分的对象从下标变成数值范围，是二分思想从数组迁移到数值域的典型。
