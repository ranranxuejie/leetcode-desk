## 1. 一句话本质

按 UTF-8 的「首字节声明长度、后续字节必须 10 开头」这套规则，从头到尾把字节流切分成合法字符，判断能否**恰好切完**。

## 2. 读完题的第一反应

最朴素的想法：把每个整数转成 8 位二进制字符串，然后对着题面那张表逐字符匹配——先看头几位判断这个字符该有几个字节，再检查后面几个是不是 `10` 开头。

这个思路方向是对的，但卡在两点：

- **字符串操作重**：每个数 `bin(x)` 再 `zfill(8)`，还要切片比较，写起来啰嗦，常数也大。虽然 `data.length ≤ 2*10^4`，字符串版也能过，但面试官想看的是你会不会用位运算。
- **真正的难点不在「怎么判断一个字节」，而在「怎么在数组上推进指针」**：一旦某个首字节声明「我是 3 字节字符」，你就必须**跳过**后面 2 个字节，不能让它们再被当成首字节去解析。很多人第一版错就错在这里——对每个 `data[i]` 都独立判断，结果把延续字节 `10xxxxxx` 也拿去当首字节解析了。

关键观察来自题面那张表：**所有信息都编码在「前几位」里**，而且只有 5 种可能的「前缀形态」：

| 前缀 | 含义 |
|---|---|
| `0xxxxxxx` | 1 字节字符（首字节） |
| `110xxxxx` | 2 字节字符的首字节 |
| `1110xxxx` | 3 字节字符的首字节 |
| `11110xxx` | 4 字节字符的首字节 |
| `10xxxxxx` | 延续字节 |

看到这张表就该想到：**用掩码 + 与运算，一次比较就能认出形态**，不需要转字符串。比如 `x & 0b11000000 == 0b10000000` 就是「是不是 `10` 开头」。这就是下一步的入口。

## 3. 从暴力到最优

**暴力版（字符串）**：对每个位置 `i`，把 `data[i]` 转成 8 位串，数开头有几个连续的 `1`，得到长度 `n`；然后检查 `i+1 .. i+n-1` 是否都以 `10` 开头；是则 `i += n`，否则返回 false。瓶颈是每个字节都要做一次字符串构造和切片，虽然渐进复杂度不变，但常数大、代码长。

**位运算版**：把「数开头几个 1」换成「用掩码试探」。核心是三个判断：

- `x & 0b10000000 == 0` → 首字节，长度 1
- `x & 0b11100000 == 0b11000000` → 长度 2
- `x & 0b11110000 == 0b11100000` → 长度 3
- `x & 0b11111000 == 0b11110000` → 长度 4
- `x & 0b11000000 == 0b10000000` → 延续字节

注意判断顺序：**必须先判长度 4 再判长度 3 再判长度 2**，因为 `11110xxx` 同时也满足 `x & 0b11100000 == 0b11100000`（前三位是 111）。这是本题最容易踩的坑，后面边界一节会再提。

**走一遍示例 1**：`data = [197, 130, 1]`

- `i=0`，`x=197=0b11000101`。`x & 0b11111000 = 0b11000000 ≠ 0b11110000`，不是 4 字节；`x & 0b11110000 = 0b11000000 ≠ 0b11100000`，不是 3 字节；`x & 0b11100000 = 0b11000000`，是 2 字节首字节。需要 1 个延续字节，检查 `i=1`：`130=0b10000010`，`& 0b11000000 = 0b10000000` ✓。`i += 2` 得 `i=2`。
- `i=2`，`x=1=0b00000001`，`x & 0b10000000 = 0`，1 字节字符。`i += 1` 得 `i=3`。
- `i=3 == len(data)`，循环结束，返回 true。

**走一遍示例 2**：`data = [235, 140, 4]`

- `i=0`，`235=0b11101011`。判 4 字节：`& 0b11111000 = 0b11101000 ≠ 0b11110000`，否。判 3 字节：`& 0b11110000 = 0b11100000` ✓，长度 3，需要 2 个延续字节。
- 检查 `i=1`：`140=0b10001100`，`& 0b11000000 = 0b10000000` ✓。
- 检查 `i=2`：`4=0b00000100`，`& 0b11000000 = 0b00000000 ≠ 0b10000000` ✗，返回 false。

和官方解释完全对上。

**为什么这是最优**：每个字节最多被「看一眼」（作为首字节看一次，或作为延续字节被检查一次），不可能比 O(n) 更快，因为最坏情况下你得读完整个数组才能确认合法。位运算只是把常数压到最小。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。定义不变量：

> 每次进入 while 循环体时，`data[0 .. i-1]` 已经被切分成若干个合法 UTF-8 字符，且 `i` 恰好指向下一个待解析字符的首字节。

**初始化**：`i=0`，前缀为空，不变量平凡成立。

**保持**：设当前 `data[i]` 是首字节，按掩码判出长度 `n ∈ {1,2,3,4}`。

- 若 `n=1`，`i` 前进 1，新前缀 = 旧前缀 + 一个 1 字节字符，仍合法。
- 若 `n>1`，代码检查 `data[i+1 .. i+n-1]` 全部满足 `10` 前缀。若全部满足，这 `n` 个字节恰好构成一个合法字符（首字节声明长度、后续字节格式正确），`i += n` 后不变量保持；若有任何一个不满足，直接返回 false——此时不存在任何「换一种切法」能救回来，因为首字节已经**唯一确定**了这个字符的长度，切分方式是强制的，没有选择余地。

**终止**：循环在 `i >= len(data)` 时退出。由不变量，`data[0 .. i-1]` 是合法切分；又因为 `i` 只能等于 `len(data)`（每次 `i += n` 且循环内已保证 `i+n ≤ len`，否则会提前返回 false），所以整个数组被恰好切完，返回 true。

**「不会漏、不会重」**：不漏——每个字节要么作为某个字符的首字节被消费，要么作为延续字节被检查并跳过；不重——`i` 单调递增，且每次跳过的是「这个字符占的全部字节」，延续字节不会再被当首字节解析。这正是第 2 节说的那个坑，不变量把它堵死了。

## 5. 完整代码（Python）

```python
class Solution:
    def validUtf8(self, data: list[int]) -> bool:
        n = len(data)
        i = 0
        while i < n:
            x = data[i]

            # 只看最低 8 位，题面保证 data[i] <= 255，这里再掩一次更稳
            x &= 0xFF

            # 先判 4 字节，再 3 字节，再 2 字节，最后 1 字节。
            # 顺序不能反：11110xxx 也满足 1110xxxx 的掩码条件。
            if x & 0b11111000 == 0b11110000:
                need = 3          # 4 字节字符，后面还要 3 个延续字节
            elif x & 0b11110000 == 0b11100000:
                need = 2          # 3 字节字符
            elif x & 0b11100000 == 0b11000000:
                need = 1          # 2 字节字符
            elif x & 0b10000000 == 0:
                need = 0          # 1 字节字符，0xxxxxxx
            else:
                # 走到这里说明是 10xxxxxx（延续字节）或 11111xxx 这类非法首字节
                return False

            # 检查后面 need 个字节是否都是 10 开头
            for j in range(1, need + 1):
                if i + j >= n:
                    return False                      # 越界，字符被截断
                if data[i + j] & 0b11000000 != 0b10000000:
                    return False                      # 不是延续字节

            i += need + 1     # 跳过整个字符

        return True
```

## 6. 复杂度

- **时间 O(n)**，`n = len(data)`。外层 while 每次让 `i` 至少加 1，总共推进 `n` 次；内层 for 检查的延续字节数，加起来不超过 `n`（每个字节最多被内层检查一次，且检查完就被 `i` 跳过）。所以总操作数是 `O(n)`，不是 `O(n·4)` 意义上的「乘 4」——4 是常数上界，可忽略。
- **空间 O(1)**。只用了 `i`、`x`、`need` 几个整型变量，没有随 `n` 增长的辅助结构。注意这里没有 `log n` 项：虽然每个数有 8 位，但 8 是固定常数（题面限定「最低 8 个有效位」），不随输入规模变化。

## 7. 边界与反例（至少 4 条）

1. **`data = [235, 140, 4]` → false**。容易错在：只检查了第一个延续字节就放行，忘了 3 字节字符需要**两个**延续字节。必须用循环检查 `need` 个。
2. **`data = [197, 130]` → true**。容易错在：`i + j >= n` 的越界判断写漏，导致索引越界抛异常，或者误判为 false。2 字节字符正好在数组末尾收尾是合法的。
3. **`data = [240, 162, 138, 147]` → true**（4 字节字符 `11110000 10100010 10001010 10010011`）。容易错在：判断顺序写成先判 3 字节，`240 = 0b11110000` 满足 `& 0b11110000 == 0b11100000`，被误判成 3 字节字符，后续检查错位。**必须先判 4 字节**。
4. **`data = [128]` → false**。`128 = 0b10000000`，是延续字节却出现在首字节位置。容易错在：只写了「1 字节字符」的分支 `x & 0b10000000 == 0`，没写 `else: return False`，导致延续字节被当成合法首字节放过去。
5. **`data = [255]` → false**。`255 = 0b11111111`，前 5 位是 1，不属于任何合法首字节形态。容易错在：掩码判断只覆盖了 4 种合法形态，忘了兜底 `else`。
6. **`data = [0]` → true**。`0 = 0b00000000`，合法 1 字节字符。容易错在：把 `x & 0b10000000 == 0` 写成 `x == 0` 之外的形式时手滑，或者对 0 值有特殊处理。

## 8. 面试追问与变体（3 条）

1. **追问：如果输入不是整数数组而是真正的字节串（`bytes`），怎么改？** 思路：逻辑完全一样，Python 里 `bytes` 迭代出来就是 0-255 的整数，代码一行不用改；C++ 里注意 `char` 有符号性，先转 `unsigned char`。
2. **追问：如果要求返回「第一个非法字节的下标」而不是布尔值？** 思路：把每个 `return False` 改成 `return i`（或 `i+j`，看你想报首字节还是坏字节的位置），语义上更利于调试。
3. **追问：如果允许「截断的尾部」（即最后一个字符不完整也算合法，模拟流式解码）？** 思路：把「越界即 false」改成「越界即 true」，但只允许发生在**最后一个**字符上；其余逻辑不变。这是流式 UTF-8 解码器的常见需求。
