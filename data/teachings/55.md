## 1. 一句话本质

问的是：从下标 0 出发，每一步只能在「当前能跳到的最远位置」以内选落点，是否存在一条落点序列能覆盖到最后一个下标——即**可达区间能否一路向右扩张到终点**。

## 2. 读完题的第一反应

最朴素的思路是搜索：从 0 出发，枚举每个位置能跳的每一步，看能不能走到 n-1。这等价于在「位置图」上做 DFS/BFS，每个位置 i 连向 i+1..i+nums[i]。最坏情况（比如全是 1e5 的大数）边数是 O(n²)，n=10⁴ 时就是 10⁸ 量级，虽然勉强能过，但完全没必要——而且面试官会追问「能不能 O(n)」。

卡点在哪？**我们枚举了大量「具体怎么跳」的路径，但题目只问「能不能到」。** 路径的细节是冗余信息。

关键观察：假设我现在能到达的区间是 `[0, reach]`。那么区间内任意位置 i 都是「可站上去的」，从它出发最远能到 `i + nums[i]`。所以**新的可达右边界 = max(reach, max_{i ≤ reach}(i + nums[i]))**。也就是说，我不需要知道具体站在哪、怎么跳过来的，只需要维护一个数：**当前能摸到的最右下标**。只要这个数能滚到 n-1，答案就是 true。

这个观察之所以能直接导向下一步：它把「路径搜索」降维成了「区间右端点的单调推进」，而右端点只会变大不会变小，天然适合一趟扫描。

## 3. 从暴力到最优

**暴力（DFS/BFS）**：状态是位置，转移是枚举跳跃长度。瓶颈是每个位置要展开 O(nums[i]) 个后继，总边数 O(n²)。

**第一步优化——记忆化/去重**：BFS 里同一个位置会被多次入队，加 visited 后每个位置只处理一次，但「处理一次」仍要枚举它的所有后继，边数还是 O(n²)。瓶颈没消掉。

**第二步优化——只关心最远可达**：注意到如果位置 i 可达，那么所有 j < i 也都可达（因为可以从某个能到 i 的位置少跳几步落到 j，或者更直接地：可达集合是一个前缀）。既然可达集合永远是前缀 `[0, reach]`，那「哪些位置可达」这个问题就只剩一个变量 `reach`。扫描时对每个 i ≤ reach，用 `i + nums[i]` 去更新 reach；一旦 reach ≥ n-1 立即返回 true；一旦扫描到 i > reach（说明前缀断了），返回 false。

**小例子走一遍** `nums = [2,3,1,1,4]`，n=5：

| i | nums[i] | i+nums[i] | reach（更新前→后） | 判断 |
|---|---|---|---|---|
| 0 | 2 | 2 | 0 → 2 | 2 < 4，继续 |
| 1 | 3 | 4 | 2 → 4 | 4 ≥ 4，返回 true |

再看反例 `nums = [3,2,1,0,4]`，n=5：

| i | nums[i] | i+nums[i] | reach | 判断 |
|---|---|---|---|---|
| 0 | 3 | 3 | 0 → 3 | 3 < 4，继续 |
| 1 | 2 | 3 | 3 → 3 | 继续 |
| 2 | 1 | 3 | 3 → 3 | 继续 |
| 3 | 0 | 3 | 3 → 3 | 继续 |
| 4 | — | — | — | i=4 > reach=3，前缀断了，返回 false |

注意 i=4 时循环条件 `i <= reach` 已经不成立，直接跳出返回 false。这就是「前缀断裂」的判定点。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：在扫描到下标 i 之前，`reach` 恰好等于「从 0 出发、只使用下标 < i 的位置作为起跳点，所能到达的最远下标」。

**初始化**：i=0 前，reach=0，即只能站在起点，成立。

**保持**：扫描到 i 时，若 i ≤ reach，说明 i 本身可达（由不变量，reach 是可达的最远点，且可达集合是前缀，故 i 可达）。从 i 起跳最远到 i+nums[i]，所以新的可达最远点是 max(旧 reach, i+nums[i])，更新后不变量对 i+1 成立。若 i > reach，说明 i 不可达，且由于可达集合是前缀、i 之后的所有位置更不可达，前缀到此为止，返回 false 是正确的。

**终止**：若某步 reach ≥ n-1，由不变量，n-1 可达，返回 true 正确；若循环自然结束（i 走到 n-1 且始终 i ≤ reach），说明 n-1 可达，同样正确。

**为什么「可达集合是前缀」**：若位置 k 可达，存在一条落点序列到 k。对任意 j < k，把序列中第一次越过 j 的那一跳改成落在 j（跳跃长度只会变短，仍合法），即可达 j。所以可达集合向下封闭，是前缀。这个性质是整个贪心成立的地基——没有它，「只维护一个 reach」就会漏掉可达点。

**不会重**：每个下标只被访问一次，reach 单调不减，不存在重复计算。

## 5. 完整代码（Python）

```python
class Solution:
    def canJump(self, nums: list[int]) -> bool:
        n = len(nums)
        reach = 0  # 当前能到达的最远下标，初始只能站在 0
        for i in range(n):
            # i > reach 说明前缀断裂：i 及之后都不可达，直接失败
            if i > reach:
                return False
            # 从 i 起跳能到 i + nums[i]，用它扩张可达右边界
            reach = max(reach, i + nums[i])
            # 右边界已经覆盖终点，提前成功
            if reach >= n - 1:
                return True
        # 循环走完（n=1 时 reach=0 >= 0 已在循环内返回 true）
        return True
```

> 说明：n=1 时循环第一轮 i=0，`reach = max(0, 0+nums[0]) >= 0 = n-1`，直接返回 true，符合题意（起点即终点）。末尾的 `return True` 是兜底，实际到不了这里。

## 6. 复杂度

- **时间 O(n)**：for 循环对每个下标 i 恰好访问一次，循环体内是常数次比较和 max，没有内层循环。n 来自数组长度。
- **空间 O(1)**：只用了 `reach`、`i`、`n` 三个标量，与输入规模无关。没有递归栈、没有额外数组。

对比暴力 BFS 的 O(n²) 时间 + O(n) 空间，这里把「枚举后继」换成了「一次 max 更新」，边数从 O(n²) 压到 O(n)。

## 7. 边界与反例（至少 4 条）

1. **`nums = [0]`** → 期望 `true`。容易错在：以为 nums[0]=0 跳不动就 false。但起点就是终点，不需要跳。代码里 i=0 时 reach=0 ≥ n-1=0，返回 true。
2. **`nums = [0,1]`** → 期望 `false`。容易错在：只看到 nums[1]=1 觉得能跳。但 i=0 时 reach=0，i=1 时 1 > 0 前缀断裂，返回 false。这是「起点就卡死」的典型。
3. **`nums = [2,0,0]`** → 期望 `true`。容易错在：看到中间有 0 就慌。实际 i=0 时 reach=2 已覆盖终点 n-1=2，直接 true。说明「有 0 不等于失败」，要看 0 是否落在断裂点上。
4. **`nums = [1,0,1]`** → 期望 `false`。i=0 时 reach=1；i=1 时 reach=max(1,1+0)=1；i=2 时 2 > 1 断裂，false。容易错在：以为能借 nums[0]=1 跳到 1 再借 nums[2] 往前，但 1 位置是 0，跳不过去。
5. **`nums = [5,0,0,0,0,0]`** → 期望 `true`。i=0 时 reach=5 ≥ n-1=5，直接 true。容易错在：被后面一串 0 吓到，忘了第一步就能直达终点。

## 8. 面试追问与变体（3 条）

1. **追问：如果问「最少跳几次到终点」呢？** 思路：贪心升级为「BFS 分层」——维护当前层的右边界 `curEnd` 和下一层最远 `nextEnd`，每跨过 curEnd 就跳数 +1、curEnd=nextEnd。这是 45 题「跳跃游戏 II」。
2. **追问：如果每个位置跳跃长度是「恰好」而不是「最多」呢？** 思路：可达集合不再是前缀，贪心失效，要回到 BFS/DP，状态是位置，用 visited 去重，复杂度 O(n²) 或按模数建图优化。
3. **追问：如果允许向左跳（nums[i] 可正可负）呢？** 思路：可达集合可能不连通，前缀性质破坏，需要 BFS 或并查集维护连通块，不能再用单变量 reach。

## 9. 举一反三（2-3 道同类题）

- **45. 跳跃游戏 II**：同样维护可达右边界，但要求最少步数，用「层边界」贪心，是本题的直接升级。
- **1306. 跳跃游戏 III**：从固定起点出发、跳跃目标由 nums[i] 决定（跳到 i±nums[i]），本质是图上可达性 BFS，和本题共享「可达性」骨架但失去前缀性质。
- **134. 加油站**：同样是「一趟扫描 + 维护一个累积量、断了就重置」的贪心结构，和本题的 reach 单调推进思路同源。
