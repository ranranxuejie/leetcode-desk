## 1. 一句话本质

在字符串上做一次「只交换元音、不动辅音和位置骨架」的原地对撞双指针操作。

## 2. 读完题的第一反应

朴素解法很直接：先把所有元音字母按顺序收集到一个列表里，反转这个列表，再从左到右扫描原串，遇到元音就依次用反转后的列表填回去。

这个思路是对的，但它卡在两点上：

- 需要额外一个列表存元音，最坏情况（全是元音）空间是 O(n)；
- 需要扫描两遍：一遍收集、一遍回填。

关键观察是：**元音之间的相对顺序要反转，而辅音完全不动**。这等价于「把最左边的元音和最右边的元音交换，然后向中间收缩」。也就是说，我们不需要先知道全部元音是谁，只要从两端同时找元音、找到一对就换一对。这个观察直接指向双指针：左指针只负责找元音，右指针只负责找元音，两者相遇就结束。

为什么能想到？因为「反转一个序列」的经典做法就是首尾对撞交换，而本题的序列是「原串中元音构成的子序列」——它藏在原串里，但两端的位置是天然可定位的（最左元音、最右元音）。

## 3. 从暴力到最优

**暴力（收集-反转-回填）**：以 `s = "IceCreAm"` 为例。

- 收集元音：扫描得 `['I','e','e','A']`；
- 反转：`['A','e','e','I']`；
- 回填：从左扫描，第 0 位 `I` 是元音，填 `A`；第 2 位 `e` 是元音，填 `e`；第 5 位 `e` 是元音，填 `e`；第 6 位 `A` 是元音，填 `I`。结果 `"AceCreIm"`。

瓶颈：额外 O(n) 空间 + 两趟扫描。

**双指针**：同样以 `"IceCreAm"` 走一遍，写出中间变量。

- `i=0, j=6`。`s[0]='I'` 是元音，`s[6]='A'` 是元音 → 交换，串变 `"AceCreIm"`，`i=1, j=5`。
- `i=1`：`'c'` 不是元音，`i` 右移到 2；`s[2]='e'` 是元音，停。
- `j=5`：`'e'` 是元音，停。
- 交换 `s[2]` 与 `s[5]`：两者都是 `'e'`，串不变，`i=3, j=4`。
- `i=3`：`'C'` 不是，`i=4`；`s[4]='r'` 不是，`i=5`。此时 `i=5 > j=4`，循环结束。

结果 `"AceCreIm"`，与暴力一致，但只扫了一遍、只用了两个下标。

瓶颈是怎么被消掉的：收集列表被「按需从两端找」替代，回填被「找到就换」替代，于是空间从 O(n) 降到 O(1)（不计输出串本身），扫描从两趟降到一趟。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**说清楚。维护的不变量是：

> 在每一轮循环开始时，区间 `[0, i)` 内的元音已经全部是最终结果，区间 `(j, n-1]` 内的元音也已经是最终结果；并且 `[0, i)` 与 `(j, n-1]` 中元音的总个数，恰好等于原串中「最靠左的若干个」与「最靠右的若干个」元音——即它们已经被正确配对交换过。

初始时 `i=0, j=n-1`，两个区间为空，不变量成立。

每轮：`i` 右移跳过非元音、`j` 左移跳过非元音，直到各自停在元音上（或交叉）。若 `i < j`，交换这两个元音。交换后，`s[i]` 拿到的是原串最右侧尚未处理的元音，`s[j]` 拿到的是最左侧尚未处理的元音——这正是「反转」所要求的配对关系。随后 `i++, j--`，把这两个位置并入已处理区间，不变量保持。

终止时 `i >= j`，中间没有未配对的元音（若剩一个，它自己和自己对称，无需动），所以所有元音都落在反转后的正确位置上。

**不会漏**：任何元音要么被 `i` 扫到、要么被 `j` 扫到，因为两指针从两端向中间覆盖整个串。
**不会重**：每个位置最多被交换一次，交换后立即被排除在 `[i, j]` 之外。

## 5. 完整代码（Python）

```python
class Solution:
    def reverseVowels(self, s: str) -> str:
        # 元音集合，大小写都要包含（题面明确说两种形式都可能出现）
        vowels = set("aeiouAEIOU")
        # Python 字符串不可变，先转成列表才能原地交换
        chars = list(s)
        i, j = 0, len(chars) - 1

        while i < j:
            # 左指针向右找元音；注意 i < j 防止越界/越过右指针
            while i < j and chars[i] not in vowels:
                i += 1
            # 右指针向左找元音
            while i < j and chars[j] not in vowels:
                j -= 1
            # 此时要么两指针都停在元音上，要么 i >= j 退出
            if i < j:
                chars[i], chars[j] = chars[j], chars[i]
                i += 1
                j -= 1

        return "".join(chars)
```

关键逻辑说明：

- `vowels` 用 `set` 而不是 `list`，把「是否元音」的判断从 O(5) 降到 O(1)，虽然常数小，但语义更清晰；
- 内层两个 `while` 都带 `i < j` 条件，避免在「左边全是辅音」或「右边全是辅音」时指针越界；
- 交换后 `i++, j--` 是必须的，否则两指针会卡在同一对元音上死循环；
- 返回前 `"".join(chars)` 把列表拼回字符串。

## 6. 复杂度

- **时间 O(n)**：`i` 只增、`j` 只减，两者合计最多走 `n` 步；每次交换是 O(1)。`n` 来自字符串长度，即每个字符最多被一个指针访问一次。
- **空间 O(n)**：`chars = list(s)` 复制了一份长度为 `n` 的列表，这是主要开销。若把输入视为可变字符数组（如 C++ 的 `string`），额外空间可降到 O(1)；Python 因字符串不可变，必须付这份拷贝。`vowels` 集合大小固定为 10，是 O(1)。没有 log n 项——本题不涉及排序或分治。

## 7. 边界与反例（至少 4 条）

1. `s = "a"` → `"a"`。只有一个元音，`i=0, j=0`，`while i < j` 直接不进，原样返回。容易错在写成 `while i <= j` 后仍去交换，虽然结果碰巧对，但逻辑上多了一次无意义操作。
2. `s = "bcdfg"` → `"bcdfg"`。没有元音。左指针一路右移直到 `i == j`，内层 `while` 因 `i < j` 失败而退出，外层也退出。容易错在漏掉内层的 `i < j` 判断，导致 `i` 越界抛 `IndexError`。
3. `s = "AEIOU"` → `"UOIEA"`。全是元音，每轮都交换，`i` 和 `j` 各走一半。容易错在交换后忘记 `i++, j--`，造成死循环。
4. `s = "leetcode"` → `"leotcede"`。元音是 `e,e,e,e`（位置 1,2,4,7），反转后仍是四个 `e`，但位置对应交换：`s[1]↔s[7]`、`s[2]↔s[4]`。容易错在只处理小写、或把 `'o'` 漏掉（`'o'` 是元音）。
5. `s = "Aa"` → `"aA"`。大小写混合，`'A'` 和 `'a'` 都是元音，需要交换。容易错在元音集合只写小写，导致 `'A'` 被当成辅音、不交换。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求反转的是「辅音」而不是元音，怎么做？** 思路完全一样，把 `vowels` 换成「非元音且是字母」的判定即可；注意题面若限定 ASCII 可打印字符，需明确「辅音」是否包含数字和符号。
2. **追问：不允许额外空间（输入是可变字符数组），怎么改？** 把 `list(s)` 去掉，直接在传入的字符数组上交换，返回时按语言约定返回数组或原地修改；Python 下可假设输入是 `bytearray`。
3. **追问：如果字符串含 Unicode（如带重音的元音），判定逻辑怎么变？** 不能再用固定集合，需要按 Unicode 类别或规范化后判断；同时注意 Python 字符串按码点索引，某些字符可能占多个码点，双指针的「位置」语义要重新定义。
