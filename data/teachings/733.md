## 1. 一句话本质

从起点像素出发，把「与起点原始颜色相同、且通过上下左右连通」的整个连通块，统一染成新颜色。

## 2. 读完题的第一反应

**朴素解法**：把整个矩阵扫一遍，凡是颜色等于起点原始颜色的格子都改掉。

**它卡在哪**：题目要的不是「所有同色格子」，而是「与起点连通的同色格子」。示例 1 里右下角那个 `1` 和起点 `(1,1)` 之间隔着 `0`，颜色虽然一样，但不该被改。所以全局扫描会多改，直接错。

**关键观察**：题目描述里反复出现「相邻」「继续重复此过程」「没有其它原始颜色的相邻像素时停止」——这三句话合起来就是一张图的**连通性遍历**定义。把每个格子看成一个节点，上下左右相邻且同色就连一条边，那么题目要的就是「从起点出发能走到的所有节点」这个连通分量。一旦识别出「连通分量」，DFS/BFS 就是标准工具，不需要再想别的。

还有一个容易忽略的细节：题目说「与**原始颜色**同色」。这意味着判断标准是起点的旧颜色，而不是「当前颜色和新颜色不同」。如果新颜色恰好等于旧颜色，按「当前颜色不同才走」的写法会死循环或做无用功，所以必须先把旧颜色存下来。

## 3. 从暴力到最优

**暴力**：全图扫描，改所有等于 `oldColor` 的格子。复杂度 O(mn)，但结果错——它不区分连通性。

**瓶颈**：暴力缺的是「可达性」判断。要修它，就得对每个同色格子问一句「你从起点走得到吗」。如果对每个格子单独做一次搜索，最坏 O((mn)²)，没必要。

**关键一步**：可达性是可以「传递」的——如果 A 能到 B，B 能到 C，那 A 就能到 C。所以从起点做**一次**遍历，沿途把能到的格子标记/染色，就同时回答了所有格子的可达性问题。一次遍历 O(mn)，瓶颈消掉。

**用小例子走一遍**（示例 1，DFS 递归版）：

```
image = [[1,1,1],
         [1,1,0],
         [1,0,1]]
sr=1, sc=1, color=2
oldColor = image[1][1] = 1
```

- 进入 `dfs(1,1)`：`image[1][1]=1 == oldColor`，改成 2 → `[[1,1,1],[1,2,0],[1,0,1]]`，向四个方向递归。
- `dfs(0,1)`：值 1，改 2 → `[[1,2,1],[1,2,0],[1,0,1]]`，继续扩散。
- `dfs(0,0)`：改 2 → `[[2,2,1],[1,2,0],[1,0,1]]`。
- `dfs(0,2)`：改 2 → `[[2,2,2],[1,2,0],[1,0,1]]`。
- `dfs(1,0)`：改 2 → `[[2,2,2],[2,2,0],[1,0,1]]`。
- 从 `(1,0)` 往下 `dfs(2,0)`：值 1，改 2 → `[[2,2,2],[2,2,0],[2,0,1]]`。
- 从 `(2,0)` 往右 `dfs(2,1)`：值是 0 ≠ oldColor，**直接返回**，不改。
- 其余方向越界或值不符，全部返回。

最终 `[[2,2,2],[2,2,0],[2,0,1]]`，和期望一致。注意 `(2,2)` 的 `1` 从头到尾没被访问到——因为它和起点之间被 `0` 隔断，DFS 根本走不过去。这正是「连通」和「同色」的区别。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义不变量：

> 在算法执行的任意时刻，被染成 `color` 的格子集合 S，恰好等于「从起点出发、只经过原始颜色为 `oldColor` 的格子、步数 ≤ 当前已探索深度」能到达的格子集合。

**初始**：只染了起点，S = {起点}，对应步数 0，成立。

**归纳步**：DFS 从 S 中某格子 u 出发，检查邻居 v。若 v 越界或 `image[v] != oldColor`，v 不可能在目标连通块里（目标块的定义要求颜色为 `oldColor`），跳过不破坏不变量；若 v 合法且未染色，把 v 加入 S，v 与 u 相邻、u 可达、v 同色，所以 v 确实可达，加入后不变量仍成立。

**不会漏**：假设存在目标格子 w 可达但最终没被染色。取起点到 w 的最短路径，路径上第一个没被染色的格子是 x，它的前驱 y 已被染色。y 被染色时一定检查过邻居 x，x 颜色为 `oldColor` 且未染色，会被立即染色，矛盾。所以不漏。

**不会重**：染色是「改颜色」这个动作本身。一个格子被染色后 `image[v] != oldColor`（前提 `color != oldColor`），后续任何路径再访问它都会被颜色判断挡掉，所以每个格子最多被处理一次。这也顺带解释了为什么第 2 节强调「先存 oldColor」——判断依据必须是原始颜色，否则染色后的格子会被误判。

**终止性**：每次递归要么返回，要么染色一个此前未染色的格子，格子总数有限，故必然终止。

## 5. 完整代码（Python）

```python
from typing import List

class Solution:
    def floodFill(self, image: List[List[int]], sr: int, sc: int, color: int) -> List[List[int]]:
        m, n = len(image), len(image[0])
        old_color = image[sr][sc]

        # 关键：新旧颜色相同，直接返回。
        # 否则下面的递归会把已染色的格子当成「仍是 old_color」反复访问，造成无限递归。
        if old_color == color:
            return image

        def dfs(r: int, c: int) -> None:
            # 越界检查：四个方向递归时必须先挡掉非法下标
            if r < 0 or r >= m or c < 0 or c >= n:
                return
            # 只处理「原始颜色」的格子；已染色的格子颜色已变，天然被挡掉
            if image[r][c] != old_color:
                return

            image[r][c] = color          # 染色，等价于「标记已访问」
            dfs(r - 1, c)                # 上
            dfs(r + 1, c)                # 下
            dfs(r, c - 1)                # 左
            dfs(r, c + 1)                # 右

        dfs(sr, sc)
        return image
```

如果担心递归深度（本题 m,n ≤ 50，最大连通块 2500 层，Python 默认递归上限 1000 会爆），可以换成显式栈的 BFS：

```python
from collections import deque

class Solution:
    def floodFill(self, image: List[List[int]], sr: int, sc: int, color: int) -> List[List[int]]:
        m, n = len(image), len(image[0])
        old_color = image[sr][sc]
        if old_color == color:
            return image

        q = deque([(sr, sc)])
        image[sr][sc] = color            # 入队即染色，避免同一格子被重复入队
        while q:
            r, c = q.popleft()
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < m and 0 <= nc < n and image[nr][nc] == old_color:
                    image[nr][nc] = color
                    q.append((nr, nc))
        return image
```

两版逻辑等价，BFS 版没有递归深度风险，面试里更稳。

## 6. 复杂度

**时间 O(mn)**：每个格子最多被染色一次（第 4 节已证），每次染色做常数次（4 个方向）邻居检查，所以总操作数 ≤ 4mn，即 O(mn)。这里 m 是行数、n 是列数，乘积就是格子总数——没有 log 项，因为没有任何排序或二分。

**空间 O(mn)**：递归版的空间是调用栈深度，最坏情况整个矩阵连成一片，栈深 mn，所以 O(mn)；BFS 版是队列大小，最坏同样 O(mn)。注意这还没算返回结果本身占的 O(mn)（原地修改的话不算额外空间，但栈/队列躲不掉）。

## 7. 边界与反例（至少 4 条）

1. **起点颜色 == 新颜色**：`image=[[0,0],[0,0]], sr=0, sc=0, color=0` → 期望原样返回。容易错在没写 `if old_color == color: return`，递归版会无限递归爆栈，BFS 版会把同一格子反复入队直到内存炸。

2. **单格矩阵**：`image=[[5]], sr=0, sc=0, color=9` → 期望 `[[9]]`。容易错在把 `m,n` 算成 0 或漏掉起点自身的染色——起点也要改，不能只改邻居。

3. **起点是孤岛**：`image=[[1,0,1]], sr=0, sc=0, color=2` → 期望 `[[2,0,1]]`。容易错在写成「全图同色替换」，把右边那个 `1` 也改了。这是本题最核心的坑。

4. **连通块被新颜色「包住」后仍要能走通**：`image=[[1,1],[1,1]], sr=0, sc=0, color=1` → 期望原样。和第 1 条同类但更隐蔽：如果判断条件写成 `image[r][c] != color`（而不是 `!= old_color`），当 `old_color != color` 时没问题，但当两者相等时逻辑就乱了。统一用 `old_color` 判断最安全。

5. **越界方向**：`image=[[1,1],[1,1]], sr=0, sc=0, color=2` → 期望全变 2。容易错在递归时忘了先判 `r<0 / r>=m / c<0 / c>=n`，Python 里 `image[-1]` 会静默取到最后一行，产生「幽灵连通」，把不该染的格子染了。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回「被染色格子的个数」而不是图像本身？** 思路：DFS/BFS 里每染一个格子计数器 +1，起点单独算一次，返回计数即可，复杂度不变。

2. **追问：如果允许 8 邻域（含对角线）连通呢？** 思路：把方向数组从 4 个扩成 8 个 `(dr,dc) ∈ {-1,0,1}² \ {(0,0)}`，其余逻辑完全不动——这正说明「连通性遍历」的框架和邻域定义是解耦的。

3. **追问：如果图像是流式输入、内存放不下整个矩阵？** 思路：不能原地改，需要外部存储记录「已访问」集合（如哈希集或位图），遍历时按坐标随机访问；或者用并查集按行分块处理。核心是把「染色即标记」换成显式的 visited 结构。

## 9. 举一反三（2-3 道同类题）

- **200. 岛屿数量**：同样是「数连通块」，只是把「染色」换成「计数 + 标记访问」，DFS/BFS 框架一模一样。
- **695. 岛屿的最大面积**：在 200 的基础上，每次遍历累加连通块大小取最大值，本质还是连通分量遍历。
- **130. 被围绕的区域**：从边界上的 `O` 出发做 flood fill 标记「安全区」，剩下的 `O` 才翻转——把「从指定起点扩散」用在了「从边界集合扩散」上，是本题思路的直接迁移。
