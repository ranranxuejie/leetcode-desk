## 1. 一句话本质

在**两个各自有序**的数组里，找一个"切分位置"，使得左半边元素个数恰好是总数的一半、且左半边最大值 ≤ 右半边最小值——这个切分点就决定了中位数。

## 2. 读完题的第一反应

**朴素解法**：把两个数组归并成一个有序数组，取中间一个或两个数。归并是 O(m+n)，能过，但题面明确要求 O(log(m+n))，所以归并直接出局。

**瓶颈在哪**：归并做了太多无用功——它把**所有**元素都排好了，可我们只关心"正中间那一两个"。排序全部元素是浪费。

**关键观察**：中位数只由"第 k 小"决定（k 约为总数一半）。而"在两个有序数组里找第 k 小"这件事，天然适合二分——因为数组有序，我砍掉一半候选时，能**确定**被砍掉的元素一定不是答案。

更具体地：把合并后的数组从中间劈成左右两半，设左半有 `left_size = (m+n+1)//2` 个元素。那么中位数只取决于：
- 左半的最大值 `maxLeft`
- 右半的最小值 `minRight`

总数是奇数 → 答案就是 `maxLeft`；偶数 → 答案是 `(maxLeft + minRight)/2`。

于是问题变成：**怎么把两个数组各切一刀，凑出恰好 `left_size` 个元素在左边，且左半全部 ≤ 右半？** 这个"切"的位置，就是我们要二分的对象。

## 3. 从暴力到最优

### 第一步：归并（O(m+n)）

以 `nums1=[1,3]`, `nums2=[2]` 为例，归并得 `[1,2,3]`，中位数 `2`。正确但慢。

### 第二步：只找第 k 小，用"砍一半"的二分（O(log(m+n))）

换个视角：在 `nums1` 上切一刀，位置记为 `i`（`nums1` 前 `i` 个进左半）；`nums2` 上切一刀，位置记为 `j`。为了左半恰好 `left_size` 个，必须满足：

```
i + j = left_size
```

所以 `j = left_size - i`，**只要定下 i，j 就定了**。于是只需在 `i ∈ [0, m]` 上二分。

**切分合法的条件**（这是整个算法的核心）：

```
nums1[i-1] <= nums2[j]   且   nums2[j-1] <= nums1[i]
```

（越界时把 `nums1[-1]` 视为 -∞、`nums1[m]` 视为 +∞。）

为什么是这两个不等式？因为左半由 `nums1[0..i-1]` 和 `nums2[0..j-1]` 组成，右半由 `nums1[i..]` 和 `nums2[j..]` 组成。要保证"左半全部 ≤ 右半"，只需检查**跨数组的两个边界**——数组内部本来就有序，不用查。

**走一遍示例 2**：`nums1=[1,2]`, `nums2=[3,4]`，m=n=2，`left_size=(2+2+1)//2=2`。

- 取 `i=1` → `j=1`。检查：`nums1[0]=1 <= nums2[1]=4` ✓；`nums2[0]=3 <= nums1[1]=2` ✗。说明 `i` 太小（`nums1` 左边放太少，`nums2` 被迫多放，导致 `nums2` 左边有个 3 比 `nums1` 右边的 2 还大）。→ `i` 往右移。
- 取 `i=2` → `j=0`。检查：`nums1[1]=2 <= nums2[0]=3` ✓；`nums2[-1]=-∞ <= nums1[2]=+∞` ✓。合法！
- `maxLeft = max(nums1[1], nums2[-1]) = max(2, -∞) = 2`；`minRight = min(nums1[2], nums2[0]) = min(+∞, 3) = 3`。
- 偶数个 → `(2+3)/2 = 2.5`。✓

**为什么二分方向是确定的**：若 `nums1[i-1] > nums2[j]`，说明 `i` 太大，要往左；若 `nums2[j-1] > nums1[i]`，说明 `i` 太小，要往右。两个条件不可能同时违反（否则数组本身就不有序），所以二分不会卡死。

### 第三步：小优化——在短数组上二分

`i` 的取值范围是 `[0, m]`，二分次数是 `log(min(m,n)+1)`。为了让 log 更小，**总是让 `nums1` 是较短的那个**（必要时交换）。这既省时间，又避免 `j` 越界——因为 `j = left_size - i`，若在长数组上二分，`j` 可能算出负数。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。

**不变量**：在二分过程中，始终维护一个区间 `[lo, hi]`，使得"合法的切分位置 `i` 一定落在 `[lo, hi]` 内"。

- **初始**：`lo=0, hi=m`，所有可能的 `i` 都在内，成立。
- **保持**：每次取 `i=(lo+hi)//2`。
  - 若 `nums1[i-1] > nums2[j]`：任何 `i' >= i` 都会让 `nums1[i'-1] >= nums1[i-1] > nums2[j] >= nums2[j']`（`j' = left_size - i' <= j`，`nums2` 有序所以 `nums2[j'] <= nums2[j]`），即 `i'` 也不合法。所以合法解必在 `i` 左侧，令 `hi = i-1`，不变量保持。
  - 若 `nums2[j-1] > nums1[i]`：对称地，任何 `i' <= i` 都不合法，令 `lo = i+1`，不变量保持。
  - 否则当前 `i` 合法，直接返回。
- **终止**：区间收缩到空之前必然命中合法解（因为题目保证存在中位数，且两个有序数组的"第 left_size 小"切分唯一存在）。

**为什么不会漏**：不变量保证合法解永远在搜索区间内，二分只是排除**已证明不合法**的那一半，没有误杀。

**为什么不会重**：切分位置 `i` 唯一确定 `j`，而满足两个不等式的 `i` 在有序数组上是唯一的（若有两个 `i1 < i2` 都合法，会推出 `nums1[i1] <= nums2[j2-1] <= nums1[i2-1]` 与 `nums1` 有序矛盾，除非相等——相等时取任一个结果相同）。所以答案唯一，不会重复计数。

## 5. 完整代码（Python）

```python
class Solution:
    def findMedianSortedArrays(self, nums1, nums2):
        # 保证 nums1 是较短的那个，二分范围更小，且避免 j 越界
        if len(nums1) > len(nums2):
            nums1, nums2 = nums2, nums1
        m, n = len(nums1), len(nums2)
        total = m + n
        left_size = (total + 1) // 2  # 左半元素个数（奇数时多放一个）

        lo, hi = 0, m
        while lo <= hi:
            i = (lo + hi) // 2          # nums1 切在 i：前 i 个进左半
            j = left_size - i           # nums2 切在 j：前 j 个进左半

            # 越界用 ±inf 兜底，省去大量 if 判断
            n1_left  = nums1[i-1] if i > 0 else float('-inf')
            n1_right = nums1[i]   if i < m else float('inf')
            n2_left  = nums2[j-1] if j > 0 else float('-inf')
            n2_right = nums2[j]   if j < n else float('inf')

            if n1_left > n2_right:
                # nums1 左边放多了，切分点左移
                hi = i - 1
            elif n2_left > n1_right:
                # nums1 左边放少了，切分点右移
                lo = i + 1
            else:
                # 找到合法切分
                max_left = max(n1_left, n2_left)
                if total % 2 == 1:
                    return float(max_left)          # 奇数：左半最大即中位数
                min_right = min(n1_right, n2_right)
                return (max_left + min_right) / 2.0  # 偶数：左右夹逼取平均
        # 理论上不会走到这里（题目保证有解）
        return 0.0
```

## 6. 复杂度

- **时间 O(log(min(m,n)))**：二分在较短数组上做，区间长度是 `min(m,n)+1`，每次折半，所以是 `log(min(m,n))`。**log 来自二分次数**；**min(m,n) 来自我们主动交换数组**——如果不在短数组上二分，最坏是 `log(max(m,n))`，虽然同阶但常数更大，且 `j` 可能越界。
- **空间 O(1)**：只用了 `i, j, lo, hi, n1_left` 等常数个变量，没有额外数组。**没有任何一项贡献 n**——这正是它比归并（O(m+n) 空间）强的地方。

## 7. 边界与反例（至少 4 条）

1. **`nums1=[], nums2=[1]`** → 期望 `1.0`。易错点：`m=0` 时 `i` 只能取 0，`j=left_size=1`，`n1_left=-inf, n1_right=+inf`，`max_left=nums2[0]=1`，奇数直接返回。若代码里没处理 `i=0` 的 `-inf`，会索引越界。

2. **`nums1=[1,2], nums2=[3,4]`** → 期望 `2.5`。易错点：偶数情况必须取 `(maxLeft+minRight)/2`，只返回 `maxLeft` 会得 `2.0`。

3. **`nums1=[1,3], nums2=[2]`** → 期望 `2.0`。易错点：交换后 `nums1=[2], nums2=[1,3]`，`left_size=2`，`i=1,j=1` 时 `n1_left=2, n2_left=1, n1_right=+inf, n2_right=3`，`max_left=2`，奇数返回 `2.0`。若忘记交换、在长数组上二分，`j` 可能为负导致 `nums2[j-1]` 越界。

4. **`nums1=[1,1], nums2=[1,1]`** → 期望 `1.0`。易错点：大量相等元素，`n1_left > n2_right` 和 `n2_left > n1_right` 都不成立，直接命中合法切分，返回 `1.0`。若用严格不等号写反，会死循环。

5. **`nums1=[1000000], nums2=[-1000000]`** → 期望 `0.0`。易错点：负数与 `-inf` 比较、`max/min` 取值，验证兜底逻辑正确。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求 O(1) 空间但允许 O(m+n) 时间，怎么写？** 思路：双指针归并到第 `left_size` 个就停，只记录 `maxLeft` 和 `minRight` 两个变量，不建新数组。

2. **追问：如果两个数组不是有序的，而是"各自是循环有序"（rotated sorted）？** 思路：先各自二分找旋转点还原成有序（O(log n)），再套本题；或直接在两个旋转数组上做"第 k 小"的二分，比较时处理断点。

3. **追问：如果要求找的是"第 k 小"而不是中位数？** 思路：把 `left_size` 换成 `k`，切分条件不变，`j = k - i`，其余逻辑完全一样——中位数只是 `k = (m+n+1)//2` 的特例。
