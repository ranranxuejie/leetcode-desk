## 1. 一句话本质

把两个已排好序的序列合并成一个有序序列，并且**必须原地写回 nums1 那块已经预留好尾部空位的连续内存**——难点不在"合并"，而在"往哪写"。

## 2. 读完题的第一反应

**朴素解法**：最直接的想法是开一个新数组 `res`，用两个指针分别扫 nums1 的前 m 个和 nums2，谁小先放谁，扫完再拷回 nums1。这个思路完全正确，时间复杂度也是 O(m+n)。它卡在哪？卡在**空间**：题目虽然没明说"不许用额外数组"，但 nums1 的长度恰好是 `m+n`，尾部那 n 个 0 就是明摆着告诉你"位置已经给你留好了"。开新数组等于无视了这个设计，面试官会追问"能不能 O(1) 空间"。

**那能不能直接在 nums1 上从前向后合并？** 试一下示例 1：`nums1=[1,2,3,0,0,0]`，`nums2=[2,5,6]`。两个指针都从下标 0 开始，比较 `1` 和 `2`，`1` 小，写回 `nums1[0]=1`——没问题。接着比较 `2` 和 `2`，写回 `nums1[1]=2`——也没问题。但再往下，nums1 的指针走到下标 2，那里原本是 `3`，可如果之前某一步把 nums2 的元素写进了 nums1 的前部，就会**覆盖掉 nums1 还没读的元素**。前向合并的致命伤是：写入位置和未读位置重叠。

**关键观察**：nums1 的**尾部**是空的（那 n 个 0），而两个数组都是**非递减**的，也就是说**最大值一定在某个数组的末尾**。既然最大值在末尾、空位也在末尾，那就从后往前填——每次把两个数组当前末尾的较大者，放到 nums1 的最后一个空位上。这样写入的位置永远在未读位置的右边，**永远不会覆盖还没读的数据**。这个观察直接把"空间不够"和"覆盖冲突"两个问题一起消掉了。

## 3. 从暴力到最优

**第一步：新数组暴力合并。** 两个指针 `i` 扫 nums1 前 m 个、`j` 扫 nums2，每次取小的追加到 `res`，最后 `nums1[:] = res`。时间 O(m+n)，空间 O(m+n)。瓶颈是空间。

**第二步：发现尾部空位。** 题面明确 `nums1.length == m+n`，后 n 个是占位 0。这说明出题人**故意**留了空间，期望你原地做。这一步不改变复杂度，但改变了"往哪写"的约束。

**第三步：逆向双指针。** 设三个指针：`i = m-1`（nums1 有效部分的末尾）、`j = n-1`（nums2 的末尾）、`k = m+n-1`（nums1 的最后一个位置）。每轮比较 `nums1[i]` 和 `nums2[j]`，大的那个写到 `nums1[k]`，然后对应指针左移、`k` 左移。

用示例 1 走一遍，`nums1=[1,2,3,0,0,0]`，`m=3`，`nums2=[2,5,6]`，`n=3`：

| 轮次 | i | j | k | 比较 | 写入 | nums1 状态 |
|---|---|---|---|---|---|---|
| 1 | 2 | 2 | 5 | 3 vs 6 | 6 | `[1,2,3,0,0,6]` |
| 2 | 2 | 1 | 4 | 3 vs 5 | 5 | `[1,2,3,0,5,6]` |
| 3 | 2 | 0 | 3 | 3 vs 2 | 3 | `[1,2,3,3,5,6]` |
| 4 | 1 | 0 | 2 | 2 vs 2 | 2（取 nums2 的） | `[1,2,2,3,5,6]` |
| 5 | 1 | -1 | 1 | j 已耗尽 | 停止 | `[1,2,2,3,5,6]` |

第 5 轮时 `j = -1`，nums2 已经全部放完，nums1 剩下的 `[1,2]` 本来就在正确位置，不用动。结果 `[1,2,2,3,5,6]`，正确。

注意第 4 轮 `2 vs 2` 相等时取哪个都行，这里取 nums2 的，nums1 的 `2` 留在原位，下一轮自然会被处理。

**为什么这样就消掉了瓶颈？** 因为 `k` 始终 ≥ `i`（`k` 从 `m+n-1` 开始，`i` 从 `m-1` 开始，`k - i = n + (已写入 nums2 的个数) ≥ 0`），所以写入位置永远在 nums1 未读部分的右边，不会覆盖。空间降到 O(1)。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**说清楚。在每一轮开始前，维护这个不变量：

> `nums1[k+1 .. m+n-1]` 已经包含了 nums1 前 `i+1` 个元素和 nums2 前 `j+1` 个元素中**最大的那些**，且按非递减顺序排列；并且 `nums1[0..i]` 和 `nums2[0..j]` 都还没被写过。

**初始化**：`k = m+n-1`，右侧区间为空，不变量平凡成立。

**保持**：设 `nums1[i]` 和 `nums2[j]` 中较大者为 `x`。因为两个数组非递减，`nums1[i]` 是 nums1 剩余部分的最大值，`nums2[j]` 是 nums2 剩余部分的最大值，所以 `x` 是**所有剩余元素中的最大值**。把它放到 `nums1[k]`，它就在已排好序的右侧区间的左端，且不小于右侧所有元素，不变量保持。同时 `k` 左移、对应指针左移，被写的那个位置不再属于"未读"。

**终止**：当 `j < 0` 时，nums2 全部放完，nums1 剩下的 `nums1[0..i]` 本来就有序且都在正确位置，不变量覆盖整个数组。当 `i < 0` 时，nums1 有效部分放完，把 nums2 剩下的 `nums2[0..j]` 依次拷到 `nums1[0..k]` 即可（代码里用 `while j >= 0` 统一处理）。

**不会漏**：每个元素恰好被处理一次——要么在某轮被比较后写入，要么留在 nums1 原位（当 `j` 先耗尽时）。**不会重**：写入后对应指针立即左移，该元素退出"未读"集合。

## 5. 完整代码（Python）

```python
class Solution:
    def merge(self, nums1, m, nums2, n):
        # i 指向 nums1 有效部分的末尾，j 指向 nums2 的末尾
        # k 指向 nums1 的最后一个空位（也是最终结果的末尾）
        i, j, k = m - 1, n - 1, m + n - 1

        # 只要 nums2 还有元素没放完，就继续比较
        # 注意：nums1 先耗尽也没关系，循环条件只看 j
        while j >= 0:
            # i >= 0 且 nums1[i] 更大时，把 nums1[i] 放到 k 位置
            # 否则（i < 0 或 nums2[j] >= nums1[i]）放 nums2[j]
            if i >= 0 and nums1[i] > nums2[j]:
                nums1[k] = nums1[i]
                i -= 1
            else:
                nums1[k] = nums2[j]
                j -= 1
            k -= 1
        # 循环结束时 j < 0，nums2 已全部并入
        # nums1 剩余的前缀本来就在正确位置，无需处理
```

关键点：循环条件写 `while j >= 0` 而不是 `while i >= 0 and j >= 0`。因为当 `i < 0` 时，nums1 有效部分已空，但 nums2 可能还有元素要填进 `nums1[0..k]`，必须继续。反过来，当 `j < 0` 时，nums1 剩下的元素已经在正确位置，直接停。

## 6. 复杂度

**时间 O(m+n)**：`while` 循环每轮要么 `i` 减一、要么 `j` 减一，`i` 最多减 m 次、`j` 最多减 n 次，总轮数不超过 `m+n`。每轮内部是比较和赋值，O(1)。所以总时间是 `O(m+n)`。这里没有 `log`，因为不需要排序——两个数组已经有序，合并是线性的。

**空间 O(1)**：只用了 `i, j, k` 三个整数变量，没有开新数组，所有写入都在 nums1 原地完成。

对比：新数组暴力法是 O(m+n) 时间、O(m+n) 空间；先拼接再排序是 O((m+n)log(m+n)) 时间（`log` 来自排序），空间取决于排序实现。逆向双指针在时间和空间上都最优。

## 7. 边界与反例（至少 4 条）

1. **`nums1=[1], m=1, nums2=[], n=0`** → 期望 `[1]`。`j = -1`，`while j >= 0` 直接不进循环，nums1 原样返回。容易错在：把循环条件写成 `while i >= 0 and j >= 0` 之外还加了别的判断，或者误以为 n=0 时要特殊处理。

2. **`nums1=[0], m=0, nums2=[1], n=1`** → 期望 `[1]`。`i = -1`，第一轮 `i >= 0` 为假，走 else 分支把 `nums2[0]=1` 写到 `nums1[0]`。容易错在：`if` 条件写成 `nums1[i] > nums2[j]` 而没加 `i >= 0` 保护，导致 `nums1[-1]` 越界访问（Python 里 `nums1[-1]` 不报错但语义错误，会读到占位 0 或错误值）。

3. **`nums1=[2,0], m=1, nums2=[1], n=1`** → 期望 `[1,2]`。第一轮 `i=0, j=0, k=1`，`2 > 1`，写 `nums1[1]=2`，`i=-1`；第二轮 `i=-1`，走 else 写 `nums1[0]=1`。容易错在：相等或小于时分支写反，或者 `k` 忘记自减导致覆盖。

4. **`nums1=[1,2,3,0,0,0], m=3, nums2=[4,5,6], n=3`** → 期望 `[1,2,3,4,5,6]`。nums2 全部大于 nums1，每轮都写 nums2 的元素到尾部，nums1 前三个不动。容易错在：误以为"nums1 元素一定先被处理"，其实完全可能 nums1 一个都不动。

5. **`nums1=[4,5,6,0,0,0], m=3, nums2=[1,2,3], n=3`** → 期望 `[1,2,3,4,5,6]`。nums1 全部大于 nums2，每轮都写 nums1 自己的元素到尾部（相当于把 nums1 整体右移），最后 nums2 填前三个。容易错在：担心"写 nums1 自己的元素会不会覆盖未读的"，实际上 `k` 始终在 `i` 右边，不会。

## 8. 面试追问与变体（3 条）

1. **追问：如果 nums1 没有预留尾部空间，长度就是 m，怎么办？** 思路：那就必须开新数组或从后往前借助额外空间，O(m+n) 空间不可避免（除非允许修改 nums2 或使用更复杂的原地技巧）。可以答"先扩容再逆向双指针"，本质是承认空间换时间。

2. **追问：如果要求合并后去重（保留一个）呢？** 思路：逆向双指针时，写入前判断 `nums1[k+1]` 是否等于待写值，相等就跳过不写，最后处理前缀。注意去重后数组长度变化，`k` 的推进逻辑要相应调整。

3. **追问：如果是 k 个有序数组合并呢？** 思路：用最小堆维护 k 个指针的当前元素，每次弹出最小者写入，时间 O(N log k)，N 为总元素数。两个数组时 k=2，退化成 O(N) 的双指针。

## 9. 举一反三（2-3 道同类题）

- **21. 合并两个有序链表**：同样是双指针合并两个有序序列，区别是链表没有"尾部预留空间"问题，用哑结点 + 尾指针即可，空间 O(1)。
- **977. 有序数组的平方**：数组有序但平方后可能变乱序，关键观察是"最大值在两端"，用**左右双指针从两端向中间**填结果数组，和本题"从后往前"是同一种逆向思维。
- **26. 删除有序数组中的重复项**：也是原地操作 + 双指针，但方向是"快慢指针从前向后"，用慢指针维护已处理区间，和本题的"逆向填充"形成对照，适合一起练"指针往哪走"的判断。
