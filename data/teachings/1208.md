## 1. 一句话本质

把两个等长字符串逐位相减取绝对值，得到一个非负数组 `cost[i]`，求这个数组里**和不超过 maxCost 的最长连续子数组**。

题面里所有关于"转化字符串""子字符串"的说法，剥掉外壳后就是这一句：字符串的"子串"对应数组的"连续子数组"，"总开销不超过预算"对应"子数组和 ≤ maxCost"。剩下的全是数组问题。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子串 `[i, j]`，对每个子串累加 `cost[i..j]` 判断是否 ≤ maxCost，取最大长度。子串有 O(n²) 个，每个求和 O(n)，总 O(n³)；用前缀和优化求和后降到 O(n²)。n 最大 10⁵，O(n²) 是 10¹⁰ 量级，必然超时。瓶颈在于"枚举了所有子串"——但很多子串根本不需要单独检查。

**关键观察**：`cost[i] = |ord(s[i]) - ord(t[i])|` 全部非负。这一点是整道题的命门。因为元素非负，子数组的和关于区间端点**单调**：固定左端点 `left`，右端点 `right` 往右扩，和只增不减；一旦超过 maxCost，再往右扩只会更超。这意味着对每个 `left`，合法的 `right` 有一个"最远边界"，不需要逐个试。

更进一步：当 `left` 右移一格时，这个最远边界**不会左移**。原因还是非负性——把左端点去掉一个非负元素，和只会变小或不变，原来能容纳的右端点现在只会更容易容纳。于是 `right` 可以只往右走、永不回头，两个指针各自单调前进，总移动次数 O(n)。这就是滑动窗口能成立的完整理由，不是"感觉可以滑"。

## 3. 从暴力到最优

用示例 1 走一遍：`s = "abcd"`, `t = "bcdf"`, `maxCost = 3`。

先算 cost 数组：

| i | s[i] | t[i] | \|差\| |
|---|---|---|---|
| 0 | a(97) | b(98) | 1 |
| 1 | b(98) | c(99) | 1 |
| 2 | c(99) | d(100) | 1 |
| 3 | d(100) | f(102) | 2 |

`cost = [1, 1, 1, 2]`。

**暴力**：检查 `[0,0]` 和 1 ✓，`[0,1]` 和 2 ✓，`[0,2]` 和 3 ✓，`[0,3]` 和 5 ✗；再检查 `[1,1]`、`[1,2]`、`[1,3]`……每个起点都从头累加，大量重复计算。

**滑动窗口**：维护窗口 `[left, right]` 和窗口内和 `cur`。

```
初始 left=0, right=0, cur=0, ans=0

right=0: cur += 1 → cur=1 ≤ 3 ✓  ans=max(0, 1)=1
right=1: cur += 1 → cur=2 ≤ 3 ✓  ans=2
right=2: cur += 1 → cur=3 ≤ 3 ✓  ans=3
right=3: cur += 2 → cur=5 > 3 ✗
         收缩：cur -= cost[0]=1 → cur=4，left=1，仍 > 3
         收缩：cur -= cost[1]=1 → cur=3，left=2，≤ 3 停
         ans=max(3, right-left+1=2)=3
结束，返回 3
```

注意 `right=3` 时窗口收缩到 `[2,3]`，长度 2，没有超过已有的 3。最终答案 3，对应子串 `"abc"`。

**瓶颈是怎么被消掉的**：暴力对每个 `left` 都重新从 `left` 开始累加，重复计算了 `cost[left..right]` 这段公共部分。滑动窗口让 `right` 只增不减，`cur` 用"进一个加一个、出一个减一个"的方式增量维护，每个下标最多被 `right` 扫过一次、被 `left` 扫过一次，总操作 O(n)。从 O(n²) 到 O(n)，消掉的正是"重复累加同一段区间"。

**为什么不用二分**：标签里有二分查找，那是另一种思路——预处理前缀和 `pre[i]`，对每个右端点 `r` 二分找最小的 `l` 使 `pre[r+1] - pre[l] ≤ maxCost`，O(n log n)。它正确，但比滑动窗口多一个 log，且需要额外的前缀和数组。既然 cost 非负这个条件已经给了，滑动窗口是更贴合题面的解法。二分版本在追问里提。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证。维护的不变量是：

> 每一轮 `right` 处理完之后，`[left, right]` 是**以 right 结尾**的、和 ≤ maxCost 的**最长**子数组。

分两种情况：

**情况一：加入 `cost[right]` 后 `cur ≤ maxCost`。** 此时 `left` 不动。因为 `cost` 非负，`[left, right]` 是以 `right` 结尾的所有子数组中能取到的最长者——任何更靠左的起点都会让和更大，可能超预算；而 `left` 已经是上一轮保证的最左合法起点，再左移没有依据。所以不变量成立。

**情况二：加入后 `cur > maxCost`。** 循环右移 `left` 直到 `cur ≤ maxCost`。设停下时 `left = L`。要证 `[L, right]` 是以 `right` 结尾的最长合法子数组，即 `[L-1, right]` 一定不合法。而 `[L-1, right]` 正是上一轮循环里 `cur` 还大于 maxCost 时的那个窗口（因为 `left` 是从上一轮的 `left` 一步步挪到 `L` 的，`L-1` 就是挪动前的某一步），那一步 `cur > maxCost` 是循环继续的条件，所以它确实不合法。因此 `L` 是最左合法起点，不变量成立。

**不漏**：答案取的是所有轮次中窗口长度的最大值。对任意合法子数组 `[i, j]`，当 `right` 走到 `j` 时，不变量保证 `[left, j]` 是以 `j` 结尾的最长合法子数组，故 `left ≤ i`，窗口长度 `j - left + 1 ≥ j - i + 1`，即该子数组的长度被覆盖到了。所以最优解不会漏。

**不重**：`right` 单调递增、`left` 单调不减，每个下标最多被两个指针各访问一次，不存在重复枚举同一区间。

## 5. 完整代码（Python）

```python
class Solution:
    def equalSubstring(self, s: str, t: str, maxCost: int) -> int:
        n = len(s)
        # 先算出逐位开销数组，把字符串问题转成数组问题
        cost = [abs(ord(s[i]) - ord(t[i])) for i in range(n)]

        left = 0          # 窗口左边界
        cur = 0           # 当前窗口 [left, right] 内的开销和
        ans = 0           # 记录历史最大窗口长度

        for right in range(n):
            cur += cost[right]          # 右端点进入窗口

            # 预算超了，就不断从左边踢元素，直到重新合法
            # 注意 cost 非负，所以这个 while 一定会终止
            while cur > maxCost:
                cur -= cost[left]
                left += 1

            # 此时 [left, right] 合法，更新答案
            ans = max(ans, right - left + 1)

        return ans
```

关键点说明：`while` 里先减 `cost[left]` 再 `left += 1`，顺序不能反，否则减的是新左边界而不是被踢出去的那个元素。`ans` 的更新放在 `while` 之后，保证统计的是收缩后的合法窗口。

## 6. 复杂度

**时间 O(n)**。`for` 循环执行 n 次，每次 `cur += cost[right]` 是 O(1)。内层 `while` 看起来嵌套，但 `left` 从 0 单调增加到最多 n，整个算法过程中 `while` 体总共执行不超过 n 次（摊还分析）。所以总操作次数 ≤ 2n，是 O(n)。这里的 n 就是字符串长度，来自"每个字符至少被看一眼"。

**空间 O(n)**，来自 `cost` 数组，长度 n。如果不想开数组，可以在循环里现算 `abs(ord(s[right]) - ord(t[right]))`，但 `while` 里要减 `cost[left]`，得能回取旧值，所以要么存数组，要么在 `left` 移动时重新算一次 `abs(ord(s[left]) - ord(t[left]))`——后者可行，空间降到 O(1)。面试里建议先写 O(n) 空间的清晰版，再提这个优化。

没有 log n 项，因为没用二分。

## 7. 边界与反例（至少 4 条）

1. **`s = "a", t = "a", maxCost = 0`** → 期望 1。容易错在把 `maxCost = 0` 当成"不能转化任何字符"直接返回 0。实际上开销为 0 的字符对是合法转化，长度 1 有效。代码里 `cur = 0 ≤ 0`，窗口不收缩，返回 1，正确。

2. **`s = "ab", t = "cd", maxCost = 0`** → 期望 0。每个字符开销都是 2，任何长度 1 的窗口都超预算。容易错在 `while` 条件写成 `>=` 而不是 `>`，导致开销恰好等于预算时被误判为超支。题面说"总开销应当小于等于该预算"，所以等于预算是合法的。

3. **`s = "abcd", t = "bcdf", maxCost = 100`** → 期望 4。预算远大于总开销，整个串都能转。容易错在只返回了某个局部窗口长度，或者 `ans` 初值设成 0 后忘了在每轮更新。代码每轮都 `max`，返回 4。

4. **`s = "aaaa", t = "aaaa", maxCost = 0`** → 期望 4。所有开销为 0，`cur` 恒为 0，`while` 从不进入，窗口一路扩到 4。容易错在把"开销为 0"的字符当成"不需要计入窗口"，从而错误地跳过它们、把长度算短。

5. **`s = "abcde", t = "bcdef", maxCost = 2`** → 期望 2。cost = `[1,1,1,1,1]`，任意长度 2 的窗口和 2 合法，长度 3 和 3 超支。容易错在收缩时只踢一个元素就停，但这里踢一个后 `cur = 2` 恰好合法，恰好能过；换成 `maxCost = 1` 就要踢到窗口长度 1，考验 `while` 而不是 `if`。用 `if` 代替 `while` 是这道题最常见的 bug。

## 8. 面试追问与变体（3 条）

**追问一：如果 cost 数组允许负数，滑动窗口还成立吗？**
不成立。非负性是"右端点右移和单调增、左端点右移和单调减"的前提，有负数时收缩左边界不一定让和变小，`left` 可能还需要回退，双指针的单调性被破坏。此时要换思路：前缀和 + 对每个右端点二分找最左合法左端点（前缀和不再单调，需要别的结构如单调栈或线段树），或者退化为 O(n²)。这题能滑窗，完全是因为 `|差|` 天然非负。

**追问二：用前缀和 + 二分怎么做？**
先算 `pre[i] = cost[0] + ... + cost[i-1]`，`pre[0] = 0`。对每个右端点 `r`（0-indexed），要找最小的 `l` 使 `pre[r+1] - pre[l] ≤ maxCost`，即 `pre[l] ≥ pre[r+1] - maxCost`。因为 `pre` 单调不减（cost 非负），可以二分。总 O(n log n)。思路一句话：把"区间和约束"转成"前缀和上的下界查询"，单调性让二分可用。

**追问三：如果要求返回具体的那个子串而不是长度？**
滑动窗口里记录 `ans` 更新时的 `(left, right)` 即可，最后返回 `s[left:right+1]`。注意 `ans` 相等时取哪个由题目约定（通常取最左），在 `>` 而非 `>=` 时更新即可保留最早出现的那个。

## 9. 举一反三（2-3 道同类题）

- **LeetCode 209. 长度最小的子数组**：同样是"和约束下的连续子数组"，只是求最短而非最长，且数组元素为正整数——非负性同样是滑窗成立的前提。
- **LeetCode 1004. 最大连续 1 的个数 III**：把"最多翻转 k 个 0"转成"窗口内 0 的个数 ≤ k"，本质是"窗口内某计数不超过阈值的最长窗口"，和本题"窗口内和不超过预算"是同一套滑窗骨架。
- **LeetCode 3. 无重复字符的最长子串**：窗口合法性条件从"和 ≤ maxCost"换成"窗口内无重复字符"，但"右扩、不合法则左缩、每轮更新答案"的结构完全一致，是滑窗的入门模板。
