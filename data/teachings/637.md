## 1. 一句话本质

按「层」分组，对每一层的节点值求和再除以该层节点个数，把每层的结果按从上到下的顺序收集成一个数组。

## 2. 读完题的第一反应

**朴素解法**：先想办法把每个节点标记上「它属于第几层」，然后按层号把值归堆，最后逐层求平均。标记层号最直接的做法是从根开始做一次遍历（DFS 或 BFS），把 `(节点, 层号)` 一起往下传。这本身不慢，但如果你用「先收集所有 `(层号, 值)`，再按层号排序或建字典」的思路，就会多出一层按层号聚合的开销，而且层号是连续的自然数，用排序是浪费。

**关键观察**：题目要的是「每一层」的平均值，而 BFS（广度优先搜索）天然就是一层一层往外扩的。也就是说，BFS 的队列在任意时刻，队列里的节点恰好构成「当前这一层还没处理完的部分 + 下一层已经入队的部分」。如果我们能在每一轮循环开始时，**先记下队列当前的长度 `size`**，然后只弹出 `size` 个节点，那么这一批弹出的节点就正好是完整的一层。这个「先量长度、再定量弹出」的动作，就是把 BFS 的「逐层扩展」变成「逐层切分」的开关。

为什么这个观察能直接导向解法？因为求平均值只需要两个量：这一层的**和**与这一层的**个数**。个数就是 `size`，和就是这 `size` 个节点值累加。两个量都在「定量弹出」的过程中顺手拿到，不需要额外的层号、字典或排序。

## 3. 从暴力到最优

**暴力版（DFS + 层号字典）**：递归时传 `level`，把 `node.val` 追加到 `dict[level]` 的列表里；遍历完再对每个列表求平均。瓶颈不在正确性，而在「先存后算」：每个节点值被存进列表一次、再被读出来一次，空间上是 `O(n)` 的额外列表开销，代码也绕。

**过渡版（BFS 但不分层）**：普通 BFS 只用一个队列，弹出节点、把子节点入队，一路弹到底。问题是队列里同时混着两层节点，你没法知道「现在弹的这个属于哪层」，平均值就无从谈起。

**最优版（BFS + 每轮定量弹出）**：在每轮 `while` 循环开头取 `size = len(queue)`，这一轮只处理 `size` 个。用示例 1 走一遍：

树结构：根 `3`，左 `9`，右 `20`；`20` 的左 `15`、右 `7`。

- 初始 `queue = [3]`。
- 第 0 轮：`size = 1`。弹 `3`，`sum = 3`，把 `9`、`20` 入队 → `queue = [9, 20]`。平均值 `3/1 = 3.0`，结果 `[3.0]`。
- 第 1 轮：`size = 2`。弹 `9`（`sum = 9`，无子节点），弹 `20`（`sum = 29`，入队 `15`、`7`）→ `queue = [15, 7]`。平均值 `29/2 = 14.5`，结果 `[3.0, 14.5]`。
- 第 2 轮：`size = 2`。弹 `15`（`sum = 15`），弹 `7`（`sum = 22`），都无子节点 → `queue = []`。平均值 `22/2 = 11.0`，结果 `[3.0, 14.5, 11.0]`。
- 队列空，结束。

注意第 1 轮里 `size = 2` 是在弹 `9` 之前就定死的，所以弹 `20` 时新入队的 `15`、`7` 不会被这一轮误算进去——它们属于下一轮。这个「先定 `size`」就是消掉「层与层混在一起」这个瓶颈的那一刀。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**说清楚。设 BFS 的队列为 `Q`，我们断言：

> 在每一轮 `while` 循环开始时，`Q` 中恰好存放着「当前尚未处理的那一层」的全部节点，且这些节点在 `Q` 中连续排列、位于队首。

**初始**：第 0 轮开始前 `Q = [root]`，恰好是第 0 层的全部节点，成立。

**保持**：设某轮开始时 `Q` 的前 `size` 个节点是第 `k` 层全部节点（由不变量保证）。这一轮我们只弹出这 `size` 个节点，每弹一个就把它的左右子节点（若存在）追加到队尾。由于第 `k` 层的每个节点都被弹了一次且只弹一次，第 `k+1` 层的每个节点**恰好被它的父节点入队一次**（二叉树每个非根节点有唯一父节点），所以轮末 `Q` 中剩下的正好是第 `k+1` 层的全部节点，且按入队顺序连续排列。不变量在下一轮成立。

**终止**：当 `Q` 为空时，说明上一层没有产生任何子节点，即树已遍历完，且每一层都恰好被处理过一次。

由不变量，每一层的节点被且仅被累加一次，`size` 就是该层节点数，`sum / size` 就是该层平均值，且按层号递增的顺序写入结果——不漏、不重、顺序正确。

## 5. 完整代码（Python）

```python
from collections import deque

class Solution:
    def averageOfLevels(self, root) -> list:
        # 题面保证 root 非空，但保留防御性判断，便于复用
        if root is None:
            return []

        result = []
        queue = deque([root])          # BFS 队列，存放待处理的节点

        while queue:
            size = len(queue)          # 关键：先锁定"这一层"的节点个数
            level_sum = 0              # 本层节点值之和

            for _ in range(size):      # 只弹 size 个，保证不跨层
                node = queue.popleft()
                level_sum += node.val

                # 子节点入队，它们属于下一层，本轮不会被弹出
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)

            # size 就是本层节点数，直接求平均
            result.append(level_sum / size)

        return result
```

几个容易写错的点，代码里已经规避：

- `size = len(queue)` 必须放在 `for` 之前、且每轮重新取，不能写成 `for _ in range(len(queue))`——后者在循环中 `len(queue)` 会随入队变化，导致跨层。
- 用 `deque` 而不是 `list`，`popleft()` 是 `O(1)`；`list.pop(0)` 是 `O(n)`，在 `n = 10^4` 时虽不致命但没必要。
- `level_sum / size` 在 Python 3 里是浮点除法，天然满足 `10^-5` 精度要求；`level_sum` 用 Python 整数，不会溢出（`10^4` 个 `2^31` 量级的值相加远在 Python 大整数范围内）。

## 6. 复杂度

**时间 `O(n)`**：`n` 是节点总数。每个节点恰好入队一次、出队一次，入队出队各 `O(1)`，累加 `node.val` 也是 `O(1)`。`while` 循环的轮数等于树高 `h`，但每轮内部的 `for` 总步数加起来正好是 `n`，所以总时间是 `n` 次常数操作，即 `O(n)`。这里没有 `log n` 项——层数 `h` 只影响循环轮数，不影响总操作数。

**空间 `O(w)`**：`w` 是树的最大宽度（某一层最多的节点数）。队列在任意时刻最多装「当前层剩余 + 下一层已入队」的节点，上界是 `O(w)`。结果数组存 `h` 个浮点数，是 `O(h)`，被 `O(w)` 支配（完全二叉树 `w` 可达 `n/2`，链状树 `w = 1` 而 `h = n`，此时空间是 `O(n)` 来自结果数组）。严格写：空间 `O(w + h)`，最坏 `O(n)`（链状树时 `h = n`）。递归 DFS 版本会有 `O(h)` 的调用栈，BFS 版本没有递归栈开销，这是它相对 DFS 的一个实际优势。

## 7. 边界与反例（至少 4 条）

1. **单节点树** `root = [5]` → 期望 `[5.0]` → 容易错在：以为「层平均值」需要至少两层，或 `while` 条件写成 `while queue and len(queue) > 1` 漏掉最后一层。本题保证非空，但空树若被传入，上面的代码返回 `[]`，需明确这是假设。

2. **链状树（只有左孩子）** `root = [1,2,null,3]`（即 `1→2→3` 全在左侧）→ 期望 `[1.0, 2.0, 3.0]` → 容易错在：误以为每层节点数都 ≥ 2，或 `size` 取错导致把 `2` 和 `3` 算进同一层。每层 `size` 都是 1，必须逐层单独输出。

3. **完全二叉树但最后一层不满** `root = [1,2,3,4]` → 第 0 层 `[1]` 均值 `1.0`，第 1 层 `[2,3]` 均值 `2.5`，第 2 层 `[4]` 均值 `4.0` → 期望 `[1.0, 2.5, 4.0]` → 容易错在：用「满二叉树每层 `2^k` 个」的公式硬算分母，最后一层不满时分母错，平均值偏小。

4. **节点值为负数** `root = [-1, -2, -3]` → 期望 `[-1.0, -2.5]` → 容易错在：初始化 `level_sum = 0` 没问题，但如果用「先乘后除」或把 `sum` 类型设成无符号/固定宽度整数（其他语言里），负数会溢出；Python 无此问题，但面试官可能追问其他语言的写法。

5. **值接近 `2^31 - 1` 且节点多** `10^4` 个节点全为 `2147483647` → 单层和可达 `2.1 * 10^13`，超出 32 位有符号整数 → 期望仍是 `2147483647.0` → 容易错在：用 C++/Java 的 `int` 累加会溢出，必须用 `long`；Python 自动大整数，但要能说出这个坑。

## 8. 面试追问与变体（3 条）

1. **追问：不用 BFS，用 DFS 怎么做？** 思路：递归传 `(node, depth)`，用两个列表 `sums[depth]` 和 `counts[depth]` 分别累加和计数，遍历完再逐层相除；时间仍 `O(n)`，空间 `O(h)` 递归栈加 `O(h)` 两个列表。

2. **追问：如果要求「每层的最大值/最小值/中位数」呢？** 思路：最大值/最小值只需把 `level_sum` 换成 `level_max` 并在弹出时更新，框架不变；中位数则需要在每层收集该层所有值再排序或双堆，单层代价升到 `O(k log k)`，总代价 `O(n log n)` 最坏。

3. **追问：如果树是「锯齿形」输出（第一层左到右、第二层右到左交替）？** 思路：仍是 BFS 定量弹出，但用一个布尔 `left_to_right` 控制每层结果是否 `reverse`，或者入队子节点时按方向决定先左后右；核心的「先定 `size`」不变。

## 9. 举一反三（2-3 道同类题）

1. **102. 二叉树的层序遍历**：和本题共用「BFS + 每轮先取 `size` 定量弹出」的骨架，区别只是把「求和除以个数」换成「把这一层的值原样收集成列表」。

2. **199. 二叉树的右视图**：同样逐层处理，每层只取最后一个弹出的节点值（或第一个，取决于入队顺序），是「分层 BFS」的直接变体。

3. **515. 在每个树行中找最大值**：分层 BFS 框架不变，把 `level_sum` 换成 `level_max`，是本题「换聚合函数」的最小改动版，适合用来检验是否真正掌握了分层模板。
