## 1. 一句话本质

在字典序的全排列序列里，给定一个排列，找出**恰好排在它后面一位**的那个排列——也就是"在所有比它大的排列中，最小的那一个"。

注意这句话的重心是"**最小的更大者**"，不是"随便找一个更大的"。这个限定条件决定了整个算法的形态。

## 2. 读完题的第一反应

**朴素解法**：把所有排列生成出来、排序、找到当前排列的下一个。排列数是 $n!$，即使只生成"比当前大的最小者"，也躲不开指数级。瓶颈在 $O(n!)$，完全不可行。

**第二个朴素想法**：从右往左，尝试把某一位变大一点点。比如 `[1,2,3]`，把最后一位 3 换成更大的？没有更大的了。那把倒数第二位 2 换成 3，得到 `[1,3,?]`，剩下的位置填最小的，就是 `[1,3,2]`。这个思路是对的，但"换哪一位、换成什么、剩下的怎么排"需要精确化。

**关键观察**：字典序比较是**从高位到低位**逐位比的。所以想让"下一个排列"尽可能小，就应该**尽量靠右**去动。也就是说：优先尝试只改最后一位，不行再改倒数第二位，以此类推。什么时候"改最后一位"不行？当最后一位已经是它右边（空集）能取的最大值时——也就是当**从右往左看，数组是递增的**时候，这一段已经"排满了"，没法再变大。

于是问题变成：**从右往左找到第一个"还能变大"的位置**。什么叫还能变大？就是它右边存在比它大的数。而由于右边那段已经是"排满"的状态（降序），所以只要 `nums[i] < nums[i+1]`，位置 `i` 就还能变大。这就是整个算法的入口。

## 3. 从暴力到最优

我们用一个例子把三步走完：`nums = [1, 3, 5, 4, 2]`。

**第一步：找"拐点" `i`。**
从右往左扫，找第一个满足 `nums[i] < nums[i+1]` 的位置。

- `i=3`: `nums[3]=4, nums[4]=2`，4 < 2？否。
- `i=2`: `nums[2]=5, nums[3]=4`，5 < 4？否。
- `i=1`: `nums[1]=3, nums[2]=5`，3 < 5？是。**拐点 `i=1`**。

此时 `i` 右边的 `[5, 4, 2]` 是**降序**的（从 `i+1` 开始单调不增），意味着这一段已经是它能组成的最大排列，动它只会变小。所以必须动 `i` 这一位。

**第二步：在右边找"刚好比 nums[i] 大的最小数"，交换。**
右边是降序的 `[5, 4, 2]`，从右往左找第一个 `> nums[1]=3` 的数：

- `nums[4]=2`，2 > 3？否。
- `nums[3]=4`，4 > 3？是。**交换 `nums[1]` 和 `nums[3]`**。

数组变成 `[1, 4, 5, 3, 2]`。为什么从右往左找？因为右边降序，从右往左第一个大于 3 的，就是所有大于 3 的数里**最小**的那个（这里是 4）。这一步保证了"变大"的幅度最小。

**第三步：把 `i` 右边重新排成升序（最小排列）。**
交换后右边是 `[5, 3, 2]`，仍是降序。降序反转就是升序，得到 `[2, 3, 5]`。最终 `[1, 4, 2, 3, 5]`。

验证：`[1,3,5,4,2]` 的下一个确实是 `[1,4,2,3,5]`——前缀 `1` 不变，第二位从 3 升到 4（最小幅度的提升），后面全部取最小升序。

**瓶颈怎么被消掉的**：暴力是枚举 $n!$ 个排列；这里每一步都是线性扫描，总共三次线性遍历，$O(n)$。核心是"右边那段降序"这个结构——它同时告诉我们"这段已经最大了"（所以动左边）和"从右往左找第一个更大的就是最小的更大者"（降序带来的单调性）。

**特例**：如果从右往左扫完都没找到拐点（整个数组降序，如 `[3,2,1]`），说明它已是最大排列，直接反转整个数组得到 `[1,2,3]`。

## 4. 正确性：为什么不会漏、不会重

用**不变量 + 交换论证**说清楚。

**不变量**：设拐点为 `i`，则 `nums[i+1..n-1]` 是降序的（非递增）。这是第一步扫描的直接产物——我们停在第一个 `nums[i] < nums[i+1]` 处，说明 `i` 右边每一对相邻元素都满足 `nums[j] >= nums[j+1]`。

**为什么必须动 `i` 或更左，不能只动右边**：右边降序，是它所有排列中字典序最大的。只重排右边只会让整体变小，不可能得到"更大的排列"。所以要得到更大的排列，必须让某个位置 `k <= i` 的值变大。而为了让结果**尽可能小**，`k` 应该尽量靠右，即 `k = i`（动更左边会让高位变大，结果更大，不是"下一个"）。

**为什么选"右边最小的、比 nums[i] 大的数"来交换**：设 `nums[i]=x`，右边降序序列中大于 `x` 的数构成一个后缀（因为降序）。我们要在"让第 `i` 位变大"的前提下让第 `i` 位尽可能小，所以取这个后缀里最小的，即从右往左第一个 `> x` 的数 `y`。交换后第 `i` 位是 `y`，是所有可行选择里最小的，保证了"最小幅度提升"。

**为什么交换后右边反转成升序**：交换后，右边仍然保持降序（交换 `x` 与 `y`，`y` 是后缀最小的大于 `x` 者，`x` 落到 `y` 原位置后仍满足降序关系；严格说需检查 `x` 与相邻元素的大小关系，但由 `y` 是"第一个大于 x"可推出 `x` 落在正确位置）。降序序列的字典序最小排列就是它的升序，反转即可。这样在"第 `i` 位已确定为最小可行值"的前提下，后缀取最小，整体就是**最小的更大排列**。

**不漏**：任何比当前大的排列，要么第 `i` 位更大（我们取了最小的可行值 `y`），要么第 `i` 位相同但后缀更大——但后缀已被我们排成最小升序，不存在比它更小的更大后缀。所以我们的结果就是"下一个"。

**不重**：算法是确定性的，给定输入唯一输出，不存在重复枚举。

## 5. 完整代码（Python）

```python
class Solution:
    def nextPermutation(self, nums: list[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        n = len(nums)

        # 第一步：从右往左找第一个"还能变大"的位置 i
        # 即第一个满足 nums[i] < nums[i+1] 的位置
        i = n - 2
        while i >= 0 and nums[i] >= nums[i + 1]:
            i -= 1

        if i >= 0:
            # 第二步：在 i 右边（降序段）从右往左找第一个 > nums[i] 的数
            # 从右往左保证找到的是"大于 nums[i] 的数中最小的"
            j = n - 1
            while nums[j] <= nums[i]:
                j -= 1
            # 交换，让第 i 位以最小幅度变大
            nums[i], nums[j] = nums[j], nums[i]

        # 第三步：把 i 右边反转成升序（最小排列）
        # 若 i == -1（整个数组降序），则反转整个数组，得到最小排列
        left, right = i + 1, n - 1
        while left < right:
            nums[left], nums[right] = nums[right], nums[left]
            left += 1
            right -= 1
```

注意 `i == -1` 时，`i+1 = 0`，反转区间是 `[0, n-1]`，正好覆盖整个数组，无需特判——这是代码里一个优雅的细节。

## 6. 复杂度

- **时间 $O(n)$**：第一步从右往左扫描最多 `n` 次；第二步从右往左扫描最多 `n` 次；第三步反转最多 `n/2` 次。三次都是线性，总 $O(n)$。这里没有 $\log n$ 项——因为没有任何排序或二分，全部是线性扫描。
- **空间 $O(1)$**：只用了 `i, j, left, right` 几个下标变量，原地交换，没有开辟新数组。题目要求"额外常数空间"，满足。

对比：如果第三步用 `sorted()` 会引入 $O(n \log n)$ 时间和 $O(n)$ 空间，虽然也能过，但不符合"常数空间"的严格要求，也不是最优。

## 7. 边界与反例（至少 4 条）

1. **输入 `[3,2,1]` → 期望 `[1,2,3]`**。为什么容易错：找不到拐点 `i`，若忘记处理 `i == -1` 的情况会越界或返回原数组。正确做法是反转整个数组。
2. **输入 `[1,1,5]` → 期望 `[1,5,1]`**。为什么容易错：有重复元素。找 `j` 时条件必须是 `nums[j] <= nums[i]` 才继续左移（即找严格大于的），若写成 `<` 会交换到相等的 1，破坏正确性。示例 3 专门考这个。
3. **输入 `[1]` → 期望 `[1]`**。为什么容易错：`n=1` 时 `i = -1`，第一步循环不执行，反转区间 `[0,0]` 不动，正确。但若手写边界时把 `i` 初始化为 `n-1` 会出错。
4. **输入 `[1,2,3]` → 期望 `[1,3,2]`**。为什么容易错：这是最"正常"的情况，拐点 `i=1`，`j=2`，交换后右边只有一个元素无需反转。若反转区间写成 `[i, n-1]`（多包含 `i`）会把刚换好的 `i` 位也反转，结果错成 `[1,2,3]` 或更乱。
5. **输入 `[2,3,1]` → 期望 `[3,1,2]`**（题面给的例子）。拐点 `i=0`（2<3），右边 `[3,1]` 降序，从右找第一个 >2 的是 3（`j=1`），交换得 `[3,2,1]`，反转 `[1,2]` 得 `[3,1,2]`。容易错在第二步从**左**往右找，会找到 3 没错但若右边有多个候选会选错。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回"上一个排列"（字典序更小的最大者）怎么办？**
   思路：完全对称——从右往左找第一个 `nums[i] > nums[i+1]` 的拐点，右边找第一个 `< nums[i]` 的最大者交换，再把右边反转成**降序**（最大排列）。

2. **追问：不要求原地，允许 $O(n)$ 额外空间，能否用更直观的方法？**
   思路：可以，但没必要——本题的 $O(1)$ 解法已经是理论最优（时间下界 $\Omega(n)$，因为最坏要看完整个数组）。额外空间不会带来更简单的逻辑，反而多一次拷贝。

3. **追问：如何判断一个排列是第几个（rank）？或者给定 rank 求排列？**
   思路：康托展开（Cantor expansion）——对每一位统计右边比它小的个数，乘以阶乘累加。这是本题"字典序"结构的直接推广，但复杂度涉及阶乘，需注意大数。
