## 1. 一句话本质

统计数组里「所有连续区间的和恰好等于 k」的区间个数——注意是**数个数**，不是找最长、不是判存在。

## 2. 读完题的第一反应

**朴素解法**：枚举左右端点 `i <= j`，对每个区间求和再和 k 比较。区间有 O(n²) 个，每个区间求和 O(n)，总 O(n³)；用前缀和预处理能把区间求和降到 O(1)，总 O(n²)。n 最大 2×10⁴，O(n²) 是 4×10⁸ 量级，Python 里必然超时。瓶颈在「枚举所有区间」这一步本身。

**关键观察**：设 `pre[i]` 表示 `nums[0..i-1]` 的和（`pre[0]=0`）。那么区间 `(i, j]` 的和就是 `pre[j] - pre[i]`。题目要求 `pre[j] - pre[i] == k`，等价于 `pre[i] == pre[j] - k`。

这句话是整个解法的转折点：**我们不再枚举区间，而是从左往右扫一遍，每到一个位置 j，就去问「前面已经出现过的前缀和里，有多少个恰好等于 `pre[j] - k`」**。这个「问前面出现过几次某个值」的动作，哈希表 O(1) 就能回答。于是 O(n²) 的枚举被压成了 O(n) 的一次扫描。

为什么能想到这一步？因为「区间和 = 两个前缀和之差」是前缀和技巧的标准变形，而「差等于定值 → 移项 → 查另一个值出现过几次」是「两数之差/之和为定值」这类问题的通用套路。看到「子数组和」三个字，第一反应就该是前缀和；看到「等于 k」而不是「最大/最小」，就该想到用哈希表计数而不是滑动窗口（数组含负数，窗口不单调，滑窗会错）。

## 3. 从暴力到最优

用示例 2：`nums = [1,2,3], k = 3`，答案是 2（`[3]` 和 `[1,2]`）。

**第一步：暴力枚举。** 枚举所有区间：`[1]=1`、`[1,2]=3`✓、`[1,2,3]=6`、`[2]=2`、`[2,3]=5`、`[3]=3`✓。共 6 个区间，命中 2 个。复杂度 O(n²)（前缀和优化后）。

**第二步：改成前缀和视角。** 先算前缀和数组，`pre = [0, 1, 3, 6]`（`pre[0]=0` 是哨兵，代表空前缀）。区间 `(i, j]` 的和 = `pre[j] - pre[i]`。我们要数的是满足 `pre[j] - pre[i] = 3` 的 `(i, j)` 对数，且 `i < j`。

**第三步：边扫边查表。** 维护一个哈希表 `cnt`，记录「到目前为止每个前缀和出现了几次」。初始 `cnt = {0: 1}`——这个 0 是哨兵，代表「空前缀」，它让「从下标 0 开始的区间」也能被正确统计（后面第 4 节会专门讲为什么必须有它）。

逐个位置扫：

| j | nums[j] | pre[j] | 要找 pre[j]-k | cnt 中该值次数 | 累加 | 更新后 cnt |
|---|---|---|---|---|---|---|
| 1 | 1 | 1 | -2 | 0 | 0 | {0:1, 1:1} |
| 2 | 2 | 3 | 0 | 1 | 1 | {0:1, 1:1, 3:1} |
| 3 | 3 | 6 | 3 | 1 | 2 | {0:1, 1:1, 3:1, 6:1} |

最终答案 2。注意 j=2 时命中的是 `pre[0]=0`，对应区间 `(0,2]` 即 `[1,2]`；j=3 时命中的是 `pre[2]=3`，对应区间 `(2,3]` 即 `[3]`。

**瓶颈怎么被消掉的**：原来每个 j 要回头遍历所有 i，现在「回头找 i」变成了「查哈希表里 `pre[j]-k` 的计数」。哈希表把「找」从 O(n) 降到 O(1)，总复杂度从 O(n²) 降到 O(n)。空间上多存了一个最多 n+1 个键的哈希表，O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义扫描到位置 j（处理完 `nums[j]` 之后）时的不变量：

> `cnt[x]` 恰好等于「满足 `0 <= i <= j` 且 `pre[i] == x` 的下标 i 的个数」。

**初始化**：j=0 时（还没处理任何元素），只有 `pre[0]=0` 存在，`cnt={0:1}`，不变量成立。

**归纳步**：处理 `nums[j]` 时，先算 `pre[j] = pre[j-1] + nums[j]`，然后查 `cnt[pre[j]-k]`。由不变量，这个值恰好是「满足 `i <= j-1` 且 `pre[i] = pre[j]-k` 的 i 的个数」，也就是「以 j 结尾、和为 k 的区间个数」——因为每个这样的 i 唯一确定一个区间 `(i, j]`，且 `pre[j]-pre[i]=k`。把这些数累加进答案，正好把「以 j 结尾的所有合法区间」一个不漏、一个不多地计入。最后把 `pre[j]` 写进 `cnt`，不变量对 j 继续成立。

**不会漏**：任何和为 k 的区间 `(i, j]` 在扫描到 j 时，`pre[i]` 早已在 `cnt` 里（因为 `i < j`，i 在之前就被处理过），所以它一定会被 `cnt[pre[j]-k]` 数到。

**不会重**：每个区间由右端点 j 唯一确定归属，只在扫描到 j 的那一次被统计，之后不会再被数第二次。同时 `i < j` 由「先查表、后插入」的顺序保证——查表时 `cnt` 里只有 `i <= j-1` 的前缀和，绝不会把 `i = j`（空区间）算进去。

**哨兵 0 的作用**：`cnt` 初始为 `{0:1}`，代表「空前缀 `pre[0]=0`」。它使得「从下标 0 开始的区间」在 j 处能被 `pre[j]-k = 0` 命中。如果漏掉这个初始值，所有以 0 开头的合法区间都会丢失（示例 1 里 `[1,1]` 就会漏掉）。

## 5. 完整代码（Python）

```python
class Solution:
    def subarraySum(self, nums, k):
        # cnt[x] 表示前缀和 x 到目前为止出现的次数
        # 初始放入 0:1，代表空前缀，保证从下标 0 开始的区间能被统计到
        cnt = {0: 1}
        pre = 0          # 当前前缀和 pre[j]
        ans = 0          # 合法子数组个数

        for x in nums:
            pre += x                       # 更新到 pre[j]
            # 以当前位置结尾、和为 k 的区间数 = 之前前缀和等于 pre-k 的次数
            ans += cnt.get(pre - k, 0)
            # 把当前前缀和计入表，供后面的位置查询（先查后插，保证 i < j）
            cnt[pre] = cnt.get(pre, 0) + 1

        return ans
```

关键逻辑说明：`ans += cnt.get(pre - k, 0)` 必须在 `cnt[pre] += 1` **之前**执行。顺序反了的话，当 `k == 0` 时会把「当前元素自己构成的空区间」误算进去，导致多计。

## 6. 复杂度

- **时间 O(n)**：外层 `for` 循环遍历 n 个元素，贡献 n；循环体内 `pre += x`、`cnt.get`、`cnt[pre] = ...` 都是哈希表平均 O(1) 操作，贡献常数因子。没有嵌套循环，没有排序，所以没有 log n 项。总时间 = n × O(1) = O(n)。（严格说哈希表最坏 O(n) 单次，但平均 O(1)，面试按平均算。）
- **空间 O(n)**：`cnt` 最多存 n+1 个不同的前缀和键（每个位置可能产生一个新键），贡献 O(n)；`pre`、`ans` 是常数。没有额外数组，所以总空间 = O(n)。

对比：暴力前缀和 O(n²) 时间、O(n) 空间；本解法用 O(n) 空间换来了时间上的一个数量级下降。

## 7. 边界与反例（至少 4 条）

1. **`nums = [1], k = 0`** → 期望 `0`。容易错在把 `cnt` 初始值写成 `{0:0}` 或忘记哨兵，导致逻辑混乱；也容易错在「先插入后查询」，那样 `pre=1` 时查 `pre-k=1` 会命中自己，误判为 1。
2. **`nums = [0], k = 0`** → 期望 `1`（区间 `[0]` 和为 0）。容易错在认为「和为 0 不可能」直接返回 0；也容易错在先插后查，把空区间算进去得到 2。
3. **`nums = [1,-1,0], k = 0`** → 期望 `3`（`[1,-1]`、`[0]`、`[1,-1,0]`）。容易错在试图用滑动窗口——数组含负数，窗口和不再单调，滑窗会漏解。这是「看到子数组和就上滑窗」的经典陷阱。
4. **`nums = [-1,-1,1], k = 0`** → 期望 `1`（`[-1,1]`）。容易错在只统计「正数区间」或假设前缀和递增；前缀和可以重复、可以下降，哈希表计数必须允许同键多次累加。
5. **`nums = [1,1,1], k = 2`** → 期望 `2`。这是官方示例，用来验证哨兵和「先查后插」都对：j=2 时 `pre=2`，查 `pre-k=0` 命中哨兵得 1；j=3 时 `pre=3`，查 `1` 命中得 1，合计 2。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回所有和为 k 的子数组本身（而不只是个数）？** 思路：哈希表的值从「计数」改成「前缀和出现的下标列表」，扫到 j 时把 `pre[j]-k` 对应的每个下标 i 都取出，区间 `(i, j]` 即为答案；注意输出规模可能 O(n²)，复杂度下界随之变化。
2. **追问：如果数组元素全为正数，能不能做到 O(1) 额外空间？** 思路：可以，正数保证前缀和严格递增，用双指针滑动窗口，右指针扩张、左指针收缩，O(n) 时间 O(1) 空间；这也反过来说明本题含负数时滑窗为何失效。
3. **追问：如果 k 可以随查询变化（多次询问不同的 k）？** 思路：预处理出前缀和数组并排序，对每个 k 用哈希或二分统计 `pre[j]-pre[i]=k` 的对数；单次询问 O(n)，多次询问可考虑离线或对前缀和建索引。
