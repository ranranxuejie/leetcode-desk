## 1. 一句话本质

对矩阵里每个格子，求「它所在行的最大值」和「它所在列的最大值」中的较小者，这个较小者就是该格子能长到的上限，把所有上限与原值之差累加即为答案。

## 2. 读完题的第一反应

**朴素解法**：对每个格子 `(r,c)`，先扫描第 `r` 行求最大值、扫描第 `c` 列求最大值，取较小者作为上限，累加差值。每个格子都要扫一行一列，单格 O(n)，总共 n² 个格子，复杂度 O(n³)。n ≤ 50 时 n³ = 125000，其实也能过，但这不是面试官想听的答案——瓶颈在于「同一个行最大值被反复计算了 n 次，同一个列最大值也被反复计算了 n 次」。

**关键观察**：行最大值只跟行号有关，列最大值只跟列号有关，它们和具体格子无关。也就是说，整个矩阵只有 n 个行最大值和 n 个列最大值，一共 2n 个数。先把这 2n 个数预处理出来，之后每个格子 O(1) 查表即可。这一步把「每格重新扫」变成「全表扫两遍 + 每格查表」，复杂度从 O(n³) 降到 O(n²)。

为什么这个观察能直接导向下一步？因为题面说「增加高度不能影响从任何方向看到的天际线」——从北/南看，天际线就是每列的最大值；从东/西看，天际线就是每行的最大值。天际线不变 ⟺ 每行的最大值不变 且 每列的最大值不变。所以每个格子的上限被两个数同时约束：不能超过本行最大值（否则行天际线变了），也不能超过本列最大值（否则列天际线变了）。取较小者就是同时满足两个约束的最大值。

## 3. 从暴力到最优

用示例 1 走一遍：

```
grid = [[3,0,8,4],
        [2,4,5,7],
        [9,2,6,3],
        [0,3,1,0]]
```

**第一步：预处理行最大值** `row_max[r] = max(grid[r])`

- 第 0 行 max(3,0,8,4) = 8
- 第 1 行 max(2,4,5,7) = 7
- 第 2 行 max(9,2,6,3) = 9
- 第 3 行 max(0,3,1,0) = 3

`row_max = [8, 7, 9, 3]`

**第二步：预处理列最大值** `col_max[c] = max(grid[:][c])`

- 第 0 列 max(3,2,9,0) = 9
- 第 1 列 max(0,4,2,3) = 4
- 第 2 列 max(8,5,6,1) = 8
- 第 3 列 max(4,7,3,0) = 7

`col_max = [9, 4, 8, 7]`

**第三步：逐格取上限并累加差值**

格子 `(0,0)`：原值 3，上限 min(row_max[0], col_max[0]) = min(8,9) = 8，增量 5。
格子 `(0,1)`：原值 0，上限 min(8,4) = 4，增量 4。
格子 `(0,2)`：原值 8，上限 min(8,8) = 8，增量 0。
格子 `(0,3)`：原值 4，上限 min(8,7) = 7，增量 3。
格子 `(1,0)`：原值 2，上限 min(7,9) = 7，增量 5。
……依此类推。

全部累加得到 35，与官方输出一致。对照官方给出的 `gridNew`，每个格子的值恰好就是 `min(row_max[r], col_max[c])`，验证了「上限 = 行列最大值取小」这个结论。

**瓶颈是怎么被消掉的**：暴力法里「求第 r 行最大值」这件事被做了 n 次（每个格子一次），预处理后只做 1 次；列同理。总工作量从 n² × 2n 变成 2n² + n²，即 O(n²)。

## 4. 正确性：为什么不会漏、不会重

**上界（不会超过）**：对任意格子 `(r,c)`，设它被增加到 `h`。若 `h > row_max[r]`，则第 r 行的最大值从 `row_max[r]` 变成了至少 `h`，东西方向天际线改变，违反约束。所以 `h ≤ row_max[r]`。同理 `h ≤ col_max[c]`。因此 `h ≤ min(row_max[r], col_max[c])`，任何合法方案的总增量都不超过「按此上限累加」的结果。

**可达（能取到）**：把每个格子都设成 `min(row_max[r], col_max[c])`，验证天际线不变。第 r 行的新最大值：该行里至少有一个格子 `(r, c*)` 满足 `grid[r][c*] = row_max[r]`（行最大值的定义），对这个格子，`min(row_max[r], col_max[c*]) = row_max[r]`（因为 `col_max[c*] ≥ grid[r][c*] = row_max[r]`，取 min 后等于 row_max[r]）。所以第 r 行新最大值仍为 `row_max[r]`。列同理。天际线完全不变，方案合法。

**不变量**：在整个构造过程中，「每行的最大值」和「每列的最大值」这两个向量始终等于原矩阵的 `row_max` 和 `col_max`。这是天际线不变充要条件的直接翻译，也是上面两段论证的共同依据。

上界可达 + 构造合法 ⟹ 贪心取每格上限就是最优，且每格独立决策、互不影响（因为上限只依赖预处理好的行列最大值，不依赖其他格子改成了多少），所以不会漏也不会重。

## 5. 完整代码（Python）

```python
class Solution:
    def maxIncreaseKeepingSkyline(self, grid):
        n = len(grid)
        # 预处理：每行的最大值（东西方向天际线）
        row_max = [max(grid[r]) for r in range(n)]
        # 预处理：每列的最大值（南北方向天际线）
        # 用 zip(*grid) 转置后对每列取 max
        col_max = [max(col) for col in zip(*grid)]

        total = 0
        for r in range(n):
            for c in range(n):
                # 该格子能长到的上限：行最大值与列最大值取小
                limit = min(row_max[r], col_max[c])
                # 只累加正增量；limit 一定 >= grid[r][c]，差值非负
                total += limit - grid[r][c]
        return total
```

说明：`zip(*grid)` 把 n×n 矩阵转置，`max(col)` 即第 c 列最大值。`limit - grid[r][c]` 恒非负，因为 `row_max[r] ≥ grid[r][c]` 且 `col_max[c] ≥ grid[r][c]`，两者取小仍 ≥ `grid[r][c]`。

## 6. 复杂度

**时间 O(n²)**：预处理行最大值，n 行每行扫 n 个元素，贡献 n²；预处理列最大值，`zip(*grid)` 本身 O(n²)，再对 n 列各取 max 共 n²；主循环 n² 个格子每格 O(1)。合计常数倍 n²，即 O(n²)。这里没有 log n 项——题目不涉及排序或二分，所有操作都是线性扫描。

**空间 O(n)**：`row_max` 和 `col_max` 各长 n，共 2n。`zip(*grid)` 在 Python 3 返回迭代器，但 `max(col)` 逐列消费，不额外存整个转置矩阵（若实现里物化了转置则是 O(n²)，但本写法不物化）。主循环只用常数个变量。所以额外空间 O(n)。

## 7. 边界与反例（至少 4 条）

1. **全零矩阵** `[[0,0,0],[0,0,0],[0,0,0]]` → 期望 0。容易错在：以为 0 高度建筑可以随便加，但行列最大值都是 0，上限全是 0，任何增加都会改变天际线（示例 2 就是这个）。代码里 `limit - grid[r][c] = 0`，自然得 0。

2. **单行已是该行最大、同时是该列最大** 如 `[[5,1],[1,1]]` → 期望 0。格子 `(0,0)=5` 是行最大也是列最大，上限 min(5,5)=5，增量为 0。容易错在：只考虑行约束忘了列约束，误以为 `(0,1)` 能长到 5，实际列最大值是 1，只能长到 min(5,1)=1，增量为 0。

3. **n=2 最小规模** `[[1,2],[3,4]]` → 期望 3。row_max=[2,4]，col_max=[3,4]。逐格：`(0,0)` min(2,3)-1=1，`(0,1)` min(2,4)-2=0，`(1,0)` min(4,3)-3=0，`(1,1)` min(4,4)-4=0，合计 1？重新算：`(0,0)` 上限 2，增量 1；`(0,1)` 上限 2，增量 0；`(1,0)` 上限 3，增量 0；`(1,1)` 上限 4，增量 0。合计 1。容易错在：手算时把 `(1,0)` 的上限误当成 4（用了行最大值），实际列最大值是 3。

4. **某行最大值恰好等于某列最大值** `[[3,3],[3,3]]` → 期望 0。所有格子已是行列最大值，上限等于原值。容易错在：以为「取小」会小于原值导致负增量，实际 min 恒 ≥ 原值，差值非负，不会出现负数。

5. **高度为 0 的格子** `[[0,5],[5,0]]` → 期望 10。row_max=[5,5]，col_max=[5,5]，两个 0 格子上限都是 5，各增 5。容易错在：忽略「0 也能加」这句话，或者误以为对角线 0 受另一方向约束更紧。

## 8. 面试追问与变体（3 条）

1. **追问：如果允许改变天际线，但要求改变后的天际线向量字典序最小，怎么求？** 思路：先确定哪些格子是「天际线支撑点」（行或列最大值所在），这些不能降；其余格子可以压到 0 来压低天际线，但要保证每行每列仍至少有一个支撑点，转化为覆盖问题。

2. **追问：如果只允许从北和西两个方向看，天际线约束变成什么？** 思路：北看是列最大值，西看是行最大值，约束不变，答案相同。若只允许一个方向（比如只看行），则每格上限就是行最大值，列约束消失，答案变大，直接 `sum(row_max[r] - grid[r][c])`。

3. **追问：如果增量必须是整数且每格最多加 k，怎么改？** 思路：上限变成 `min(row_max[r], col_max[c], grid[r][c] + k)`，其余逻辑不变，仍是 O(n²)。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 1582 二进制矩阵中的特殊位置**：共同点是「先预处理每行每列的统计量（这里是 1 的个数），再逐格用行列信息 O(1) 判定」，和本题「预处理行列最大值再逐格查表」是同一套模式。

2. **LeetCode 861 翻转矩阵后的得分**：共同点是「每个格子的最优决策只依赖它所在行/列的聚合信息」，先保证行首为 1 再按列多数翻转，都是先算聚合量再逐格贪心。

3. **LeetCode 135 分发糖果**：共同点是「每个位置的值受左右两个方向的约束，取两个方向约束的较大/较小者」，本题是行列两个方向取小，135 是左右两趟扫描取大，本质都是「双向约束 + 逐点合并」。
