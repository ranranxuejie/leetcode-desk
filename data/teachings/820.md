## 1. 一句话本质

把所有单词按「后缀包含」关系去重后，求剩下每个单词长度 +1（`#`）的总和——因为一个单词若恰好是另一个单词的后缀，它就能「寄生」在对方的编码里，不额外占长度。

## 2. 读完题的第一反应

**朴素解法**：把 words 里每个词都单独写成 `word#` 拼起来，长度 = Σ(len+1)。这显然不是最小，因为示例里 `"me"` 是 `"time"` 的后缀，`"time#"` 里从下标 2 开始到 `#` 正好是 `"me"`，所以 `"me"` 不用再单独占位。

**卡在哪**：要判断「词 A 是不是词 B 的后缀」。两两比较是 O(n²·L)（n 个词、每次比 L 个字符），n 和 L 都可能到 2000 量级，直接超时。瓶颈在于「后缀关系」这个判断被重复做了很多次。

**关键观察**：后缀关系天然适合**倒着看**。把每个词反转，`"me"` 是 `"time"` 的后缀 ⟺ `"em"` 是 `"emit"` 的前缀。前缀关系可以用**字典树（Trie）**一次建完、一次遍历搞定，把 O(n²) 的两两比较压成 O(总字符数)。这就是从「两两比」跳到「建树」的那一步。

## 3. 从暴力到最优

**第一步：暴力枚举后缀关系。**
对每个词 w，检查是否存在另一个词 v ≠ w 使 w 是 v 的后缀。若是，w 不计入答案；否则计入 len(w)+1。

小例子 `["time","me","bell"]`：
- `"time"`：没有更长的词以它结尾 → 计入 5
- `"me"`：`"time"` 以 `"me"` 结尾 → 跳过
- `"bell"`：没有 → 计入 5
- 答案 10 ✓

瓶颈：每个词都要扫一遍所有词，O(n²L)。

**第二步：反转 + 排序。**
把所有词反转后**按字典序降序**排序。排序后，若某词是另一词的前缀，它一定紧挨在「以它为前缀的最长词」后面（字典序性质：前缀相同的词聚在一起，长的排在短的前面）。于是只需比较相邻两个词：若后一个词是前一个词的前缀，就跳过。

小例子反转后：`["emit","em","lleb"]`，降序排序：`["lleb","emit","em"]`。
- `"lleb"` 计入 5
- `"emit"` 计入 5
- `"em"` 是 `"emit"` 的前缀 → 跳过
- 答案 10 ✓

瓶颈：排序 O(n log n · L)，比 O(n²L) 好，但比较字符串本身要 O(L)，且「相邻比较」这个论证需要小心（见第 4 节）。

**第三步：字典树（最优）。**
反转所有词，建一棵 Trie。**只有叶子节点对应的词才需要计入答案**——因为一个词若在 Trie 里还有孩子，说明存在更长的词以它为前缀（即原词以它为后缀），它能被那个更长的词覆盖。

小例子：反转 `["emit","em","lleb"]` 建树：
```
root
 ├─ e ─ m ─ i ─ t   (emit, 叶子)
 │        └ (em 在这里结束，但不是叶子，因为下面还有 i)
 └─ l ─ l ─ e ─ b   (lleb, 叶子)
```
叶子是 `"emit"` 和 `"lleb"`，各贡献 len+1 = 5+5 = 10 ✓。`"em"` 在路径中间，不是叶子，跳过。

**去重**：如果 words 里有重复词（如 `["a","a"]`），建 Trie 时它们走同一条路径、同一个终点，天然只算一次。所以先 `set(words)` 更省事，但 Trie 本身也能处理。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在反转后的 Trie 中，词 w 对应的节点是叶子 ⟺ 不存在另一个词 v 使 w 是 v 的真前缀（反转后）⟺ 不存在 v 使原词 w 是 v 的真后缀。

**为什么叶子才计入**：
- **不漏**：若 w 是叶子，说明没有更长的词以它为前缀，即没有原词以它为后缀，w 无法被任何其他词覆盖，必须单独占 len(w)+1。若 w 不是叶子，则存在更长的词 v 覆盖它，w 的编码可以完全落在 v 的编码内部（从 v 的某个下标开始到 `#`），不额外占位。
- **不重**：每个叶子节点唯一对应一个词（Trie 路径唯一），且叶子之间不存在前缀关系（否则其中一个就不是叶子），所以它们的编码互不覆盖，各自贡献 len+1 是必要的。总和 = 所有叶子贡献之和，既覆盖了所有必须占位的词，又没有重复计算。

**为什么「覆盖」是合法的**：题面要求 s 中从 indices[i] 开始到下一个 `#` 的子串等于 words[i]。若 w 是 v 的后缀，v 的编码是 `...v#`，w 从 v 的 `len(v)-len(w)` 处开始、到 v 末尾的 `#` 结束，正好是 w。所以把 w 的 index 指向 v 内部是合法的，不需要额外字符。

## 5. 完整代码（Python）

```python
class Solution:
    def minimumLengthEncoding(self, words) -> int:
        # 去重：重复词在 Trie 里会走同一路径，去重后逻辑更干净
        words = list(set(words))
        # 反转每个词：后缀关系 -> 前缀关系，方便建 Trie
        words = [w[::-1] for w in words]

        # 用嵌套 dict 表示 Trie，节点是 dict，key 是字符
        trie = {}
        # 记录每个词在 Trie 中的终点节点，以及它的长度
        nodes = []  # 元素为 (终点节点, 原词长度)

        for w in words:
            node = trie
            for ch in w:
                # 不存在则新建子节点
                node = node.setdefault(ch, {})
            # node 现在是这个词的终点
            nodes.append((node, len(w)))

        ans = 0
        for node, length in nodes:
            # 只有叶子节点（没有孩子）才需要单独编码
            if not node:
                ans += length + 1  # +1 是结尾的 '#'
        return ans
```

关键点：`node.setdefault(ch, {})` 返回该字符对应的子 dict，若不存在就新建空 dict 并返回，一行完成「走到/创建子节点」。最后判断 `not node` 即该节点无孩子 = 叶子。

## 6. 复杂度

设 n = 词数，L = 单词最大长度，S = 所有词字符总数（Σ len）。

- **时间**：建 Trie 遍历每个字符一次，O(S)；去重 `set` 平均 O(S)；反转每个词 O(S)。总计 **O(S)**。注意不是 O(n·L) 的平方级——因为 Trie 共享前缀，总节点数 ≤ S。
- **空间**：Trie 节点数 ≤ S+1，每个节点一个 dict，**O(S)**。`nodes` 列表 O(n)。
- 对比排序法：O(n log n · L) 时间（排序比较字符串），Trie 把 log 因子和字符串比较都消掉了。

## 7. 边界与反例（至少 4 条）

1. **`["a","a"]` → 2**。两个相同词，去重后只剩一个 `"a"`，答案 2。若不去重又用「相邻比较」法，容易算成 4 或漏判。
2. **`["time","me","bell"]` → 10**。经典例，`"me"` 必须被识别为 `"time"` 的后缀而跳过。若只比较「长度相等」或「完全相同」会错算成 15。
3. **`["t"]` → 2**。单字符，答案 len+1=2。容易忘记 `#` 也占 1 位而返回 1。
4. **`["me","time"]` → 10**（顺序颠倒）。后缀关系与输入顺序无关，若代码依赖「短词在前」的假设会漏判。Trie 天然与顺序无关。
5. **`["abc","bc","c"]` → 4**。`"bc"` 是 `"abc"` 后缀、`"c"` 是 `"bc"` 后缀，链式覆盖，只有 `"abc"` 计入 3+1=4。若只处理「一层」后缀关系会多算。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回具体的 s 而不只是长度？** 思路：对每个叶子词，把原词 + `#` 拼起来；非叶子词的 index 指向其「宿主」叶子词内部对应位置，记录偏移即可。
2. **追问：改成「前缀包含」而非「后缀包含」怎么办？** 思路：不反转，直接建 Trie，同样只统计叶子，逻辑完全对称。
3. **追问：词量极大、内存受限，能否不建完整 Trie？** 思路：用「反转后排序 + 相邻比较」的 O(n log n · L) 方案，空间只需存排序后的数组，牺牲时间换空间。
