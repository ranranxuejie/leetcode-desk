## 1. 一句话本质

在所有叶子节点中，找出深度最大的那一层，把这一层所有叶子节点的值加起来。

注意两个关键词：**叶子节点**（没有孩子的节点）和**最深的那一层**。题目要的不是"最深叶子节点"（可能不止一个），而是"最深那一层上所有叶子"的总和。

## 2. 读完题的第一反应

**朴素解法**：先遍历一遍求出整棵树的最大深度 `maxDepth`，再遍历一遍，把所有"深度等于 `maxDepth` 且是叶子"的节点值加起来。两遍 DFS，时间复杂度 O(n)，其实已经是最优量级了。但它的"卡点"不在复杂度，而在**你要遍历两遍、还要额外维护一个深度参数**，写起来容易在"叶子判断"和"深度传递"上出错。

**关键观察**：我们其实不需要预先知道最大深度。可以**一边遍历一边维护"当前已知的最深层"**：如果遇到的叶子比之前记录的层更深，就把累加和**清零重来**；如果一样深，就**继续累加**；如果更浅，直接忽略。

这个观察为什么能让你想到下一步？因为它把"两遍扫描"压成了"一遍扫描 + 一个状态"。状态只有两个变量：`max_depth`（目前见过的最深层）和 `total`（该层叶子值之和）。这正是"边遍历边决策"的典型信号——**当答案依赖于一个全局极值时，先假设极值已知，再看遍历时能不能顺手维护它**。

## 3. 从暴力到最优

**暴力版**（两遍 DFS）：

```
第一遍：dfs1(node, d) 求 maxDepth = max(所有叶子的 d)
第二遍：dfs2(node, d) 若 node 是叶子且 d == maxDepth，total += node.val
```

瓶颈：要写两个递归函数，且第二遍必须等第一遍完全结束才能开始，逻辑上是"先测量再收集"。

**一遍版**（带状态 DFS）：

维护 `self.max_depth = -1`、`self.total = 0`。遍历到叶子时：

- `d > max_depth`：说明发现了更深的一层，之前的累加全部作废 → `max_depth = d; total = node.val`
- `d == max_depth`：同一层，累加 → `total += node.val`
- `d < max_depth`：更浅，忽略

**用小例子走一遍**。取示例 1 的树：

```
        1
       / \
      2   3
     / \   \
    4   5   6
   /         \
  7           8
```

（按题面数组 `[1,2,3,4,5,null,6,7,null,null,null,null,8]` 还原：1 的孩子是 2、3；2 的孩子是 4、5；3 的右孩子是 6；4 的左孩子是 7；6 的右孩子是 8。）

按 DFS 先序遍历（根→左→右），深度从 0 开始：

| 访问节点 | 深度 d | 是否叶子 | 动作 | max_depth | total |
|---|---|---|---|---|---|
| 1 | 0 | 否 | — | -1 | 0 |
| 2 | 1 | 否 | — | -1 | 0 |
| 4 | 2 | 否 | — | -1 | 0 |
| 7 | 3 | 是 | d>max → 重置 | 3 | 7 |
| 5 | 2 | 是 | d<max → 忽略 | 3 | 7 |
| 3 | 1 | 否 | — | 3 | 7 |
| 6 | 2 | 否 | — | 3 | 7 |
| 8 | 3 | 是 | d==max → 累加 | 3 | 15 |

最终 `total = 15`，和示例输出一致。注意节点 5 是叶子但深度 2 < 3，被正确忽略——这就是"不会把浅层叶子混进来"的关键。

**为什么这样就消掉了瓶颈**：第二遍扫描被合并进第一遍，因为"当前最深层"这个信息在遍历过程中是**单调不减**的（只会被更深的叶子抬高），所以"发现更深就清零"不会丢失任何未来需要的数据——更深的层出现时，浅层的和本来就不该要。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义遍历过程中的不变量：

> 在处理完任意前缀个节点后，`max_depth` 等于"已访问节点中所有叶子的最大深度"，`total` 等于"已访问叶子中深度恰为 `max_depth` 的那些叶子的值之和"。

**初始**：未访问任何节点，`max_depth = -1`、`total = 0`，空集上不变量成立（约定没有叶子时和为 0）。

**归纳步**：设访问新节点 v，深度 d。

- 若 v 不是叶子：不改变叶子集合，`max_depth`、`total` 都不动，不变量保持。
- 若 v 是叶子且 `d > max_depth`：新叶子深度严格更大，新的最大深度就是 d，且"深度为 d 的已访问叶子"只有 v 一个（因为之前所有叶子深度都 < d），故 `total` 应重置为 `v.val`，代码正是这么做的。
- 若 v 是叶子且 `d == max_depth`：最大深度不变，v 加入"该层叶子"集合，`total` 加上 `v.val`，正确。
- 若 v 是叶子且 `d < max_depth`：v 不影响最大深度，也不属于该层，忽略，正确。

**终止**：所有节点访问完，`total` 就是"全体叶子中深度等于全体最大深度的那些叶子的和"，正是所求。

**不漏**：每个叶子都被访问一次，且只有 `d == max_depth` 的叶子被计入，最深层的每个叶子都满足这个条件。
**不重**：每个叶子只在被访问的那一次做一次判断，`total` 每次只加一次 `v.val`，不会重复。

## 5. 完整代码（Python）

```python
class Solution:
    def deepestLeavesSum(self, root) -> int:
        # 状态：目前见过的最深层，以及该层叶子值之和
        self.max_depth = -1
        self.total = 0

        def dfs(node, depth):
            if node is None:
                return
            # 叶子判定：左右孩子都为空
            if node.left is None and node.right is None:
                if depth > self.max_depth:
                    # 发现更深的一层，之前累加作废，从当前节点重新开始
                    self.max_depth = depth
                    self.total = node.val
                elif depth == self.max_depth:
                    # 同一层，继续累加
                    self.total += node.val
                # depth < self.max_depth 时什么都不做
                return  # 叶子没有孩子，无需继续递归
            # 非叶子：带着 depth+1 继续往下
            dfs(node.left, depth + 1)
            dfs(node.right, depth + 1)

        dfs(root, 0)
        return self.total
```

几个容易踩的点在代码里已经用注释标出：叶子要 `return`（虽然孩子是 None 递归也会立刻返回，但显式 return 更清晰）；`depth` 从 0 开始，根节点深度为 0，不影响结果（只要全树统一即可）。

## 6. 复杂度

**时间 O(n)**：n 是节点数。`dfs` 对每个节点恰好调用一次（每个节点只被其父节点递归一次，根节点被外层调用一次），每次调用内是 O(1) 的判断和加法。没有重复访问，所以是严格的 O(n)，不是 O(n log n)——树不是平衡的，DFS 不按层展开，不存在 log 因子。

**空间 O(h)**：h 是树高。空间全部来自递归调用栈，栈深度等于当前路径长度，最坏情况是链状树 h = n，此时 O(n)；最好情况是平衡树 h = log n，此时 O(log n)。**注意这里没有额外的数据结构**（没有队列、没有数组），所以空间就是栈深。如果面试官追问"能不能 O(1) 额外空间"，答案是不能用递归，但可以用 Morris 遍历做到 O(1)，不过本题没必要。

## 7. 边界与反例（至少 4 条）

1. **单节点树** `root = [5]` → 期望 `5`。容易错：把根当成"非叶子"跳过，或初始 `max_depth = 0` 导致 `depth(0) > 0` 不成立、`total` 保持 0。用 `-1` 初始化就避开了。

2. **只有左链** `[1,2,null,3,null]`（1→2→3 全在左边）→ 期望 `3`。容易错：只递归右子树，或误以为"最深叶子"在右边。必须左右都递归。

3. **最深叶子分布在两棵子树** 如 `[1,2,3,4,5,6,7]`（完全二叉树，深度 2 的叶子是 4,5,6,7）→ 期望 `4+5+6+7=22`。容易错：只累加"第一个遇到的最深层叶子"，忘记同层要累加多个。这正是 `elif depth == max_depth` 分支存在的意义。

4. **浅层叶子与深层叶子并存** 如示例 1 中的节点 5（深度 2 的叶子）与节点 7、8（深度 3 的叶子）→ 期望 `15` 而非 `15+5=20`。容易错：把所有叶子都加起来，或先累加后忘记"发现更深层要清零"。这是本题最核心的陷阱。

5. **右斜树** `[1,null,2,null,3]` → 期望 `3`。容易错：只递归左子树，或深度传递时写成 `depth` 而非 `depth+1`，导致所有节点深度相同。

## 8. 面试追问与变体（3 条）

1. **追问：改成 BFS 怎么做？** 思路：按层遍历，每层记录该层叶子值之和，最后一层的和就是答案——BFS 天然"最后处理完的层就是最深一层"，不需要维护 `max_depth`，但需要队列，空间 O(最宽层)。

2. **追问：如果要求"最深叶子节点的平均值"或"最深层的节点个数"？** 思路：状态从"和"换成"和 + 计数"，`total` 旁边加一个 `count`，重置时一起重置，最后返回 `total / count` 或 `count`。

3. **追问：如果树有 10^6 个节点、递归会爆栈怎么办？** 思路：改迭代 DFS（显式栈存 `(node, depth)`）或 BFS，把递归栈换成堆上的栈/队列，避免 Python 默认递归深度限制（约 1000）。
