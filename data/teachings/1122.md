## 1. 一句话本质

给 `arr1` 里的每个元素定一个「排序键」：在 `arr2` 里出现过的，键就是它在 `arr2` 中的下标；没出现过的，键统一排在最后、彼此按数值升序。然后按这个键排序。

## 2. 读完题的第一反应

**朴素解法**：把 `arr1` 直接排序，然后想办法把 `arr2` 里的元素按顺序「提」到前面。问题在于——Python 的 `sort` 只能按元素本身的大小排，而这里要的是一种「自定义优先级」：`2` 要排在 `1` 前面（因为 `arr2` 里 2 在 1 前面），这跟数值大小完全无关。所以直接 `sorted(arr1)` 出来的 `[1,2,2,2,3,3,4,6,7,9,19]` 是错的。

**关键观察**：题目要的顺序，本质上是给每个元素一个「排名」。`arr2 = [2,1,4,3,9,6]` 意味着 2 排第 0、1 排第 1、4 排第 2……这个「排名」就是天然的排序键。而「没在 `arr2` 里出现」的元素，题面明确说放末尾且升序，那给它们一个比所有 `arr2` 下标都大的键、键值取元素本身即可。

一旦把「排序」翻译成「按自定义键排序」，这题就没有算法难度了，只剩实现细节。这也是为什么它标「简单」——难点不在算法，在于**你能否想到把「相对顺序」抽象成「排名」**。

## 3. 从暴力到最优

**第一步：暴力模拟。**
对 `arr2` 里每个值 `v`，扫一遍 `arr1`，把所有等于 `v` 的收集起来；最后把 `arr1` 里不在 `arr2` 的元素收集起来排序接上。复杂度 O(|arr1| × |arr2| + k log k)，k 是剩余元素个数。n、m ≤ 1000 时最多 10⁶ 次比较，其实能过，但面试官会问你能不能 O(n + m)。

**第二步：用哈希表消掉「扫一遍找等于 v」的重复扫描。**
先统计 `arr1` 里每个值出现几次（计数），然后按 `arr2` 的顺序，把每个值按次数「倒出来」。这一步把 O(n×m) 降到 O(n + m)。但还剩「未出现的元素要升序」——如果对剩余元素单独排序，又引入 O(k log k)。

**第三步：注意到值域只有 0~1000。**
提示里 `0 <= arr1[i], arr2[i] <= 1000` 是明摆着的信号：值域小且固定，可以用**计数数组**代替哈希表，并且「升序」这件事天然由「从 0 到 1000 遍历计数数组」免费得到，连排序都省了。这就是计数排序的思想。

**小例子走一遍**：`arr1 = [2,3,1,3,2,4,6,7,9,2,19]`，`arr2 = [2,1,4,3,9,6]`。

计数数组 `cnt`（只列非零项）：`cnt[1]=1, cnt[2]=3, cnt[3]=2, cnt[4]=1, cnt[6]=1, cnt[7]=1, cnt[9]=1, cnt[19]=1`。

按 `arr2` 顺序输出：
- `2` → 输出 3 个 2 → `[2,2,2]`
- `1` → 输出 1 个 1 → `[2,2,2,1]`
- `4` → `[2,2,2,1,4]`
- `3` → 输出 2 个 3 → `[2,2,2,1,4,3,3]`
- `9` → `[2,2,2,1,4,3,3,9]`
- `6` → `[2,2,2,1,4,3,3,9,6]`

然后从 0 到 1000 扫 `cnt`，把剩下非零的按值升序倒出：`7`（1 个）、`19`（1 个）→ `[2,2,2,1,4,3,3,9,6,7,19]`。与示例一致。

注意一个细节：按 `arr2` 输出时，要把对应 `cnt[v]` **清零**，否则后面扫计数数组时会把它们再输出一遍，造成重复。这是本题最容易写错的地方。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。把最终结果分成两段：前段 = 在 `arr2` 中出现过的元素，后段 = 未出现的元素。

**不变量 1（前段顺序正确）**：按 `arr2` 从左到右处理，处理到 `arr2[i]` 时，把 `cnt[arr2[i]]` 个该值连续追加到结果尾部。因为 `arr2` 元素互不相同（题面保证），每个值只被处理一次，所以前段中任意两个不同值 x、y 的先后关系，恰好等于它们在 `arr2` 中的先后关系；同一个值的多个副本连续排列，也符合「相对顺序和 arr2 相同」的要求。

**不变量 2（不重不漏）**：每个元素要么属于 `arr2`（被前段消费，且消费后 `cnt` 清零），要么不属于（留给后段）。两段互斥且覆盖全部，所以总数守恒。清零这一步正是保证「不漏不重」的关键——如果不清零，属于 `arr2` 的元素会被前后两段各输出一次。

**不变量 3（后段升序）**：后段由「从 0 到 1000 顺序扫描计数数组」产生，扫描顺序即数值升序，所以后段天然升序，满足题面「未出现过的元素按升序放在末尾」。

三条合起来，输出序列既满足「相对顺序同 arr2」，又满足「剩余升序」，且元素多重集与 `arr1` 完全一致，故正确。

## 5. 完整代码（Python）

```python
class Solution:
    def relativeSortArray(self, arr1, arr2):
        # 值域上界由题面给出：0 <= arr1[i] <= 1000
        MAXV = 1000
        cnt = [0] * (MAXV + 1)

        # 第一步：统计 arr1 中每个值出现的次数
        for x in arr1:
            cnt[x] += 1

        res = []

        # 第二步：按 arr2 的顺序，把对应值按次数倒出来
        for v in arr2:
            if cnt[v] > 0:
                res.extend([v] * cnt[v])
                cnt[v] = 0   # 关键：清零，防止后面重复输出

        # 第三步：剩余元素（未在 arr2 出现）按值升序追加
        for v in range(MAXV + 1):
            if cnt[v] > 0:
                res.extend([v] * cnt[v])

        return res
```

如果不想依赖「值域 ≤ 1000」这个假设（比如面试官追问值域变大怎么办），可以换成哈希表 + 对剩余元素排序：

```python
from collections import Counter

class Solution:
    def relativeSortArray(self, arr1, arr2):
        cnt = Counter(arr1)
        res = []
        for v in arr2:
            res.extend([v] * cnt.pop(v, 0))
        # 剩余元素按键升序
        for v in sorted(cnt):
            res.extend([v] * cnt[v])
        return res
```

两版逻辑完全同构，区别只是「剩余元素升序」是靠计数数组遍历免费得到，还是靠一次显式排序。

## 6. 复杂度

设 n = len(arr1)，m = len(arr2)，V = 1001（值域大小）。

- **时间**：O(n + m + V)。统计计数 O(n)；按 arr2 输出 O(m)（`extend` 的总量不超过 n）；扫计数数组 O(V)。没有 log 项，因为升序是「遍历有序下标」免费得到的，不是排序得到的。若用哈希表版本，剩余元素排序贡献 O(k log k)，k 为剩余元素个数，最坏 O(n log n)。
- **空间**：O(V + n)。计数数组 O(V)；结果数组 O(n)。哈希表版本是 O(n)（Counter 最多 n 个不同键）。

注意 `res.extend([v] * cnt[v])` 里 `[v] * cnt[v]` 会临时分配，但总量受 n 约束，不改变量级。

## 7. 边界与反例（至少 4 条）

1. **arr1 全部在 arr2 中**：`arr1=[2,1,2]`，`arr2=[1,2]` → 期望 `[1,2,2]`。容易错在忘记清零，导致 `[1,2,2,2,2]` 之类重复输出。
2. **arr1 全部不在 arr2 中**：`arr1=[5,3,1]`，`arr2=[]`（注意题面说 arr2 长度 ≥1，但变体里可能为空）→ 期望 `[1,3,5]`。容易错在只写了「按 arr2 输出」那段，忘了后段，返回空列表。
3. **arr1 有重复且跨两段**：`arr1=[2,3,2,3,1]`，`arr2=[3,1]` → 期望 `[3,3,1,2,2]`。容易错在把 2 也当成「在 arr2 中」处理，或后段没升序。
4. **arr1 只有一个元素**：`arr1=[7]`，`arr2=[7]` → 期望 `[7]`。容易错在循环边界写成 `range(MAXV)` 漏掉 1000，或 `cnt[v] > 0` 判断写反。
5. **值恰好是 0 或 1000**：`arr1=[0,1000]`，`arr2=[1000]` → 期望 `[1000,0]`。容易错在计数数组开成 `[0]*1000`，下标 1000 越界。

## 8. 面试追问与变体（3 条）

1. **追问：如果 arr2 中元素可以重复（不再互不相同），怎么办？** 思路：此时「相对顺序」定义变模糊，需要先和面试官确认语义；若按「arr2 中首次出现的位置」定优先级，则用字典记录首次下标作为排序键即可。
2. **追问：如果值域变成 10⁹，计数数组开不下怎么办？** 思路：换哈希表 + 对剩余元素排序，时间 O(n + m + k log k)，空间 O(n)，即上面第二版代码。
3. **追问：要求原地修改 arr1，不许开新数组，能做到吗？** 思路：可以，用计数 + 双指针回填 arr1（先按 arr2 顺序写回，再按值升序写回剩余），空间降到 O(V)，但代码可读性下降，面试时要先问清是否值得。
