## 1. 一句话本质

在数组所有「三元素组合」的和里，找离 target 最近的那个和值。

## 2. 读完题的第一反应

**朴素解法**：三重循环枚举所有下标 i < j < k，算出每个和，记录与 target 差值最小的那个。n ≤ 1000 时组合数约 1.67×10⁸，Python 里跑这个量级基本要几十秒，面试直接挂。

**瓶颈在哪**：三重循环的本质是「枚举所有无序三元组」，而题目只关心和值，不关心是哪三个数。也就是说，大量组合的信息是冗余的——我们不需要逐个检查，只需要知道「有没有一个和落在 target 附近」。

**关键观察**：题目标签已经给了提示——排序 + 双指针。排序之后，数组有了单调性：固定第一个数 nums[i]，剩下两个数从 i+1 到末尾的两端往中间夹，和值随指针移动是单调变化的。单调性让我们可以用「大了就把右指针左移、小了就把左指针右移」的方式，把内层两层循环从 O(n²) 压成 O(n)。这是本题从 O(n³) 降到 O(n²) 的全部秘密。

## 3. 从暴力到最优

**第一步：暴力枚举**

```python
best = None
for i in range(n):
    for j in range(i+1, n):
        for k in range(j+1, n):
            s = nums[i] + nums[j] + nums[k]
            if best is None or abs(s - target) < abs(best - target):
                best = s
```

复杂度 O(n³)，n=1000 时约 1.67 亿次内层操作，不可接受。

**第二步：排序 + 固定一个数 + 双指针**

先排序。外层固定 i，内层用 left = i+1、right = n-1 两个指针。每次计算 s = nums[i] + nums[left] + nums[right]：

- s < target：当前和偏小，想让和变大，只能让 left 右移（因为 right 已经是最右端，左移只会更小）。
- s > target：当前和偏大，想让和变小，只能让 right 左移。
- s == target：差值 0，已经最优，直接返回。

**具体走一遍**：nums = [-1, 2, 1, -4]，target = 1。

排序后 nums = [-4, -1, 1, 2]。

i = 0（nums[0] = -4），left = 1，right = 3：
- s = -4 + (-1) + 2 = -3，|−3−1| = 4，best = -3。s < target，left → 2。
- s = -4 + 1 + 2 = -1，|−1−1| = 2 < 4，best = -1。s < target，left → 3。
- left == right，内层结束。

i = 1（nums[1] = -1），left = 2，right = 3：
- s = -1 + 1 + 2 = 2，|2−1| = 1 < 2，best = 2。s > target，right → 2。
- left == right，结束。

i = 2 时 left = 3、right = 3，不构成两个不同下标，跳过。

最终 best = 2，与示例输出一致。

注意中间 best 从 -3 变成 -1 再变成 2，每次都是因为差值更小才更新——这个「只在更优时更新」是正确性的关键，后面第 4 节会展开。

**第三步：还能不能更快？**

排序 O(n log n) 是必须的（双指针依赖单调性）。外层 O(n) 固定第一个数，内层双指针 O(n)，合计 O(n²)。n=1000 时约 10⁶ 次操作，Python 一秒内轻松跑完。再往下压到 O(n log n) 需要更复杂的技巧（比如对每个 i 二分查找最接近 target - nums[i] 的两数和），但常数更大、代码更绕，面试不划算。O(n²) 就是本题的标准答案。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在外层固定 i、内层双指针的整个过程中，我们维护的 best 始终是「已经检查过的所有三元组和中，离 target 最近的那个」。

**为什么不会漏**：任意一个三元组 (a, b, c)（排序后 a ≤ b ≤ c，对应下标 i < j < k），在外层循环到 i 时，内层双指针一定会「经过」j 和 k 这个组合。理由：双指针从 (i+1, n-1) 出发，每次只移动一个指针，且移动方向由当前和与 target 的大小关系决定。假设某一时刻 left 停在 j 之前、right 停在 k 之后，那么当前和 nums[i] + nums[left] + nums[right] 与 nums[i] + nums[j] + nums[k] 的大小关系决定了指针会朝 (j, k) 方向移动——具体说，如果当前和偏小，left 右移；偏大，right 左移。由于数组有序，这个移动过程不会「跳过」任何一对 (j, k)：left 只能从 i+1 单调增到 n-1，right 只能从 n-1 单调减到 i+1，两者相遇时停止，而 (j, k) 满足 j < k，必然在相遇之前被访问到。这就是双指针的**交换论证**：把任意一个合法三元组「交换」到指针路径上，路径一定覆盖它。

**为什么不会重**：外层 i 严格递增，内层 left 从 i+1 开始、right 从 n-1 开始且 left < right，所以每个三元组的下标满足 i < left < right，且 i 是三者中最小的下标。每个无序三元组恰好对应唯一一个「最小下标作为 i」的时刻，因此只被检查一次。

**为什么「只在更优时更新」是对的**：best 的更新条件是 `abs(s - target) < abs(best - target)`。由于题目保证「恰好一个解」，不存在两个不同的和值与 target 距离相等的情况，所以严格小于不会漏掉正确答案；即使放宽这个保证，严格小于也只是保留先遇到的那个，仍然是一个合法最优解。

## 5. 完整代码（Python）

```python
class Solution:
    def threeSumClosest(self, nums, target):
        nums.sort()                      # 排序，为双指针的单调性做准备
        n = len(nums)
        best = nums[0] + nums[1] + nums[2]  # 用前三个数初始化，保证 best 有值

        for i in range(n - 2):           # 外层固定第一个数，留两个位置给双指针
            left, right = i + 1, n - 1   # 内层双指针从 i 的右侧两端出发

            while left < right:          # 两个指针不能相遇
                s = nums[i] + nums[left] + nums[right]

                # 当前和更接近 target 时更新答案
                if abs(s - target) < abs(best - target):
                    best = s

                if s == target:          # 差值 0，已经最优，直接返回
                    return best
                elif s < target:         # 和偏小，需要更大的和 → 左指针右移
                    left += 1
                else:                    # 和偏大，需要更小的和 → 右指针左移
                    right -= 1

        return best
```

几个细节值得说：

- `best` 用 `nums[0] + nums[1] + nums[2]` 初始化，而不是 `float('inf')`。因为返回值必须是整数，用 inf 初始化后如果循环里一次都没更新（虽然不可能，但代码上不干净），返回 inf 会出错。用前三个数初始化，保证 best 一开始就是一个合法的三元组和。
- 外层 `range(n - 2)`：i 最大到 n-3，保证 i+1 和 n-1 之间至少有两个不同下标。
- `s == target` 时直接 return，不用继续找——差值 0 不可能被超越。

## 6. 复杂度

**时间 O(n²)**：
- 排序贡献 O(n log n)，其中 log n 来自排序的比较次数。
- 外层循环 n-2 次，每次内层双指针最多移动 n 步（left 和 right 各走一遍，合计不超过 n 步），所以内层总代价 O(n)。外层 × 内层 = O(n²)。
- 总时间 O(n log n + n²) = O(n²)，n 来自外层循环和内层指针移动，log n 来自排序。

**空间 O(1)**（不计排序的栈空间）：
- 只用了 best、left、right、i、s 几个变量，常数个。
- Python 的 `list.sort()` 是 Timsort，最坏 O(n) 辅助空间，但通常面试里说「排序额外空间 O(log n) 到 O(n)」即可；如果严格要求原地，可以说明「不计排序开销则为 O(1)」。

## 7. 边界与反例（至少 4 条）

1. **输入 nums = [0,0,0], target = 1 → 输出 0**
   容易错：初始化 best 时如果写成 `float('inf')` 且循环里忘记更新（比如 s == target 分支写错），可能返回 inf。另外三个 0 的和是 0，差值 1，是唯一解，代码里 s=0 < target=1，left 右移后 left==right 退出，best 保持 0，正确。

2. **输入 nums = [1,1,1,0], target = 100 → 输出 3**
   容易错：target 远大于所有和，双指针会一路 left 右移，最终 best 是 3（1+1+1）。如果外层循环写成 `range(n)` 而不是 `range(n-2)`，i 到 n-1 时 left = n、right = n-1，left < right 不成立，虽然不会崩，但逻辑上多跑了无用轮次；更危险的是如果内层没判 left < right 就访问 nums[left]，会越界。

3. **输入 nums = [-1,2,1,-4], target = 1 → 输出 2**
   这是官方示例。容易错：如果排序后忘记「只在更优时更新」，而是每次无条件覆盖 best，最后 best 会变成最后一次计算的和，不一定是最近的。比如本例最后一步 s = 2 恰好是答案，但换个数组就会错。

4. **输入 nums = [1,2,4,8,16,32,64,128], target = 82 → 输出 82（1+16+65 不存在，实际是 2+16+64=82）**
   容易错：target 恰好等于某个三元组和时，代码里 `s == target` 直接 return，但前提是双指针能走到这个组合。如果内层循环条件写成 `left <= right`，left 和 right 相等时会重复用同一个下标，产生非法三元组（比如 nums[i] + nums[left] + nums[left]），可能提前返回错误值。必须严格 `left < right`。

5. **输入 nums = [0,1,2], target = 3 → 输出 3**
   最小规模 n=3，外层只跑 i=0 一次，left=1、right=2，s=3 == target 直接返回。容易错：如果外层写成 `range(n-2)` 但 n=3 时 range(1) 只跑 i=0，正确；如果写成 `range(n-3)` 则一次都不跑，返回初始化的 best，虽然本例恰好也是 3，但逻辑错误会在别的用例暴露。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回所有「与 target 最接近」的三元组（可能有多个），怎么改？**
   思路：把「严格小于才更新」改成「小于等于都收集」，用一个列表存所有差值等于最小差值的和（或三元组），最后去重。注意题目原版保证唯一解，变体要去掉这个保证。

2. **追问：能不能做到 O(n log n)？**
   思路：对每个 i，问题变成「在 nums[i+1:] 里找两个数和最接近 target - nums[i]」。两数和最接近可以用双指针 O(n)，总 O(n²)；要 O(n log n) 需要更高级的结构（比如对每个 i 二分 + 预处理），但常数大、实现复杂，面试中通常回答「O(n²) 是本题的预期复杂度，O(n log n) 需要额外技巧，不划算」。

3. **追问：如果数组里有重复元素，双指针会不会重复计算同一个和？**
   思路：会，但不影响正确性——重复计算只是多做了几次比较，best 的更新条件保证结果不变。如果要优化，可以在外层跳过 `nums[i] == nums[i-1]`，内层在移动后跳过相同值，但本题不要求去重，加上反而增加代码复杂度，面试时提一句「可以去重优化但非必需」即可。

## 9. 举一反三（2-3 道同类题）

1. **15. 三数之和**：同样排序 + 固定一个数 + 双指针，区别是要求和恰好为 0 且要返回所有不重复三元组，需要额外去重逻辑。本题是它的「最接近」变体，双指针骨架完全一样。

2. **259. 较小的三数之和**：排序 + 双指针，统计和小于 target 的三元组个数。双指针移动时用「right - left」一次性计数，是本题双指针单调性的直接应用。

3. **167. 两数之和 II - 输入有序数组**：双指针的最基础版本，本题内层双指针就是它的直接复用——固定第一个数后，剩下两个数的和问题退化成这道题。
