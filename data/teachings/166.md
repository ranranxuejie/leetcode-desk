## 1. 一句话本质

把一次除法竖式手算的过程翻译成代码：整数部分直接除，小数部分每落一位就记下「当前余数」，一旦某个余数重复出现，说明从这里开始商必然循环。

## 2. 读完题的第一反应

**朴素解法**：直接做浮点除法 `numerator / denominator`，再想办法把结果转成字符串。它卡在两点：

- 浮点数只有 53 位有效二进制位，`4/333` 算出来是 `0.012012012...` 的一个近似值，你无法从 `0.012012012012012012` 里可靠地判断出循环节是 `012` 还是 `0120` 还是别的——精度不够，信息已经丢了。
- 就算用 `decimal` 高精度，你也得自己决定「算到第几位停」，而循环小数是无限长的，没有停的判据。

所以这条路不是「慢」，而是**根本得不到正确答案**。这提示我们：不能靠数值计算，要靠**符号推演**，也就是回到小学竖式。

**关键观察**：竖式做除法时，每一步的状态只有一个——当前的余数 `r`。第 k 位小数由 `r * 10 // d` 决定，新的余数是 `r * 10 % d`。余数的取值范围是 `0 <= r < d`，只有 `d` 种可能。于是：

- 如果某一步余数变成 `0`，后面全是 0，小数有限，结束。
- 如果余数不为 0 但**重复**了，那么从这个余数出发的后续所有位必然和上次完全一样，循环开始。

「状态空间有限 + 状态决定后续」这两点合起来，直接给出了判循环的方法：**用哈希表记录每个余数第一次出现的位置**。这就是为什么这题标签是哈希表。

## 3. 从暴力到最优

只有一层优化，但值得把中间变量写清楚。

**例子：`4 / 333`**

先处理符号和整数部分：`4 // 333 = 0`，余数 `r = 4`。答案先写 `"0."`。

然后循环，每轮做 `r *= 10`，取商、更新余数，并查表：

| 轮次 | 进入时 r | r*10 | 商 digit | 新余数 | 哈希表（余数→位置） | 已写小数位 |
|---|---|---|---|---|---|---|
| 1 | 4 | 40 | 0 | 40 | {4:0} | "0" |
| 2 | 40 | 400 | 1 | 67 | {4:0, 40:1} | "01" |
| 3 | 67 | 670 | 2 | 4 | {4:0, 40:1, 67:2} | "012" |
| 4 | 4 | — | — | — | 4 已在表中，位置 0 | 命中 |

第 4 轮进入时余数是 4，查表发现它第一次出现在小数第 0 位，于是把小数部分从下标 0 开始的部分用括号包起来：`"0.(012)"`。

注意表里存的是**余数出现时、对应商位即将写入的下标**，这样命中时 `insertPos` 直接就是左括号该插的位置，不用再算偏移。

对比一下「暴力」到底暴力在哪：如果不用哈希表，你只能靠「小数位超过某个上限就认为循环」来猜，或者两两比较历史余数（O(n²)）。哈希表把「这个余数见过没有」从线性查找降到 O(1)，整体从 O(n²) 降到 O(n)，n 是小数位数。

再补一个有限小数的例子确认分支正确：`1 / 2`。整数部分 `0`，`r = 1`。第 1 轮 `r*10 = 10`，商 `5`，新余数 `0`。余数为 0，直接返回 `"0.5"`，不进循环表。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。设当前余数为 `r`，已写出的小数位为 `s`，原始分数为 `N/D`（已取绝对值）。维护的不变量是：

> `N/D = 整数部分 + 0.s + r / (D * 10^|s|)`

也就是说，`s` 是精确的前缀，`r` 是「还没除完的那部分」放大后的余数。归纳验证：初始时 `r = N mod D`，等式成立；每轮把 `r` 乘 10 取商 `q`、余 `r'`，相当于把 `r/D` 拆成 `q/10 + r'/(10D)`，前缀多一位、余数分母多乘 10，不变量保持。所以**写出的每一位都是精确的，不存在浮点误差**——这解决了第 2 节说的「信息丢失」。

在此不变量下分三种终止情况，逐一说明不漏不重：

1. **余数为 0**：不变量变成 `N/D = 整数 + 0.s`，是精确的有限小数，且题面要求有限小数必须原样返回，此时返回不带括号的串正确。
2. **余数重复**：设余数 `r` 在位置 `i` 和位置 `j`（`i < j`）两次出现。由不变量，位置 `i` 之后要写的无限串由 `r` 唯一决定（每步是确定性函数），位置 `j` 之后同理，两者起点状态相同，故后续串完全相同。于是 `s[i:j]` 就是最小循环节的一个周期，且 `i` 之前的部分不循环。用括号包住 `s[i:]` 正确。
3. **余数永不重复**：不可能。余数只有 `D` 个取值（`0..D-1`），最多走 `D` 步必重复或归零，所以循环一定在 `D` 步内终止，算法必然停机。

「不会重」指不会把非循环部分误判成循环：因为记录的是**第一次**出现的位置，命中时取的是最早那次，左括号位置最小，不会把循环节切错。

## 5. 完整代码（Python）

```python
class Solution:
    def fractionToDecimal(self, numerator: int, denominator: int) -> str:
        # 1. 处理符号：结果的符号只由两者异或决定
        if numerator == 0:
            return "0"
        sign = "-" if (numerator < 0) ^ (denominator < 0) else ""

        # 2. 全部转正数处理，避免 Python 取模在负数上的语义干扰
        n, d = abs(numerator), abs(denominator)

        # 3. 整数部分
        integer_part = n // d
        remainder = n % d
        if remainder == 0:
            return sign + str(integer_part)   # 整除，没有小数点

        # 4. 小数部分：逐位长除，用哈希表记录余数首次出现的位置
        digits = []
        seen = {}          # 余数 -> 它对应的商位在 digits 中的下标
        while remainder != 0 and remainder not in seen:
            seen[remainder] = len(digits)     # 记录「这个余数从哪一位开始产生」
            remainder *= 10
            digits.append(str(remainder // d))
            remainder %= d

        # 5. 组装结果
        if remainder == 0:
            # 有限小数，不循环
            return sign + str(integer_part) + "." + "".join(digits)
        else:
            # 循环小数：从该余数首次出现的位置插入括号
            pos = seen[remainder]
            return (sign + str(integer_part) + "."
                    + "".join(digits[:pos]) + "(" + "".join(digits[pos:]) + ")")
```

关键点说明：`seen[remainder] = len(digits)` 写在取商**之前**，这样记录的下标正好是「这个余数将要产生的第一位商」的位置，命中时直接拿来当左括号位置。如果写成取商之后，下标会差一位，`4/333` 会错成 `0.0(12)`。

## 6. 复杂度

设小数位数为 `L`（含循环节的一个周期），`D = |denominator|`。

- **时间 O(L)**：循环每轮写一位小数，且每轮余数互不相同（一旦相同就退出），所以最多执行 `min(L, D)` 轮。每轮内部是常数次整数运算和一次哈希查找 O(1)。字符串拼接 `"".join` 是 O(L)。题面保证答案长度 < 10^4，所以 L 有上界，实际很快。
- **空间 O(L)**：`digits` 存 L 个字符，`seen` 最多存 L 个余数键值对。哈希表大小受 `D` 约束，即 O(min(L, D))。

注意这里**没有 log 因子**：虽然整数除法本身对位数是对数的，但本题把大整数运算视为 O(1)（Python 大整数实际是 O(位数)，在 32 位输入下可忽略）。如果面试官追问大数场景，再补一句「每轮大整数乘除是 O(log D) 位运算」。

## 7. 边界与反例（至少 4 条）

1. `numerator = 0, denominator = 5` → `"0"` → 容易错在没提前返回，走进小数分支拼出 `"0."` 或 `"0.0"`。
2. `numerator = -50, denominator = 8` → `"-6.25"` → 容易错在只给分子取绝对值忘了符号，或对负数用 `//` 和 `%` 导致整数部分和余数符号不一致（Python 里 `-50 // 8 = -7`，直接算会得到 `-7` 加错误余数）。
3. `numerator = 1, denominator = 6` → `"0.1(6)"` → 容易错在把整个小数部分都括起来写成 `"0.(16)"`，忽略了不循环的前缀 `1`。
4. `numerator = -1, denominator = -2147483648` → `"0.0000000004656612873077392578125"` → 容易错在 `abs(-2^31)` 溢出（C++/Java 里 `abs(INT_MIN)` 是未定义行为），Python 无此问题但要意识到这是考点；同时这是有限小数，验证长除能正确走到余数 0。
5. `numerator = 2, denominator = 3` → `"0.(6)"` → 循环节只有一位，容易错在括号位置算成 `"0.6()"` 或漏括号。

## 8. 面试追问与变体（3 条）

1. **追问：如果分母是 0 怎么办？** 思路：题面保证 `denominator != 0`，但可以主动说明会抛异常或返回约定值，展示边界意识。
2. **追问：不用哈希表，怎么判断循环节长度？** 思路：循环节长度等于 10 在模 `d'`（`d` 去掉因子 2 和 5 后的部分）下的乘法阶，可用数论直接算，但实现比哈希表复杂，哈希表是工程上的最优解。
3. **追问：如果要求返回循环节长度而不是字符串呢？** 思路：同一套长除，命中 `seen` 时返回 `len(digits) - seen[remainder]` 即可，代码改动一行。
