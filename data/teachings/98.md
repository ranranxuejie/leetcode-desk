## 1. 一句话本质

判断一棵二叉树的中序遍历序列是否**严格单调递增**——因为 BST 的定义等价于「中序遍历有序」，所以验证 BST 就是验证这个有序性。

## 2. 读完题的第一反应

**朴素解法**：对每个节点，检查它的左子树所有值都小于它、右子树所有值都大于它，然后递归检查左右子树。这个思路直接翻译题面三条定义，但每检查一个节点都要遍历它的整棵子树，总复杂度是 O(n²)（链状树最坏）。瓶颈在于：**同一个节点会被它的所有祖先反复扫描**。

**关键观察**：题面说「左子树只包含严格小于当前节点的数」——注意是「子树里所有节点」，不只是直接孩子。这意味着约束是**全局的上下界**，不是父子两两比较。一旦你意识到「每个节点其实活在一个区间 (low, high) 里」，就可以在递归时把区间往下传，每个节点只访问一次。这是从 O(n²) 到 O(n) 的转折点。

另一条等价视角：BST 的中序遍历必然严格递增。于是问题变成「边遍历边检查前一个值是否小于当前值」，同样 O(n)。

两条路都对，下面主线讲**上下界传递**（更能体现「为什么不能只比父子」），代码里给这个版本，第 8 节提中序版本。

## 3. 从暴力到最优

**暴力版**：`isValidBST(root)` 里对 root 调 `allLess(root.left, root.val)` 和 `allGreater(root.right, root.val)`，再递归左右。以示例 2 的树 `[5,1,4,null,null,3,6]` 为例：

- 检查根 5：左子树 {1} 全 < 5 ✓，右子树 {4,3,6} 全 > 5？4 不满足 ✗ → 返回 false。

这里恰好第一步就挂了，看不出瓶颈。换一棵 `[10,5,15,null,null,6,20]`：根 10 检查右子树 {15,6,20}，发现 6 < 10 挂掉——但为了发现这个 6，你把整棵右子树扫了一遍。如果树退化成链，每层都扫剩余全部，就是 O(n²)。

**优化版：带区间递归**。核心是把「祖先留下的约束」压缩成两个数 `(low, high)`，表示当前节点允许的取值范围（开区间）。

还是 `[10,5,15,null,null,6,20]`，走一遍：

| 调用 | 节点 | low | high | 判断 |
|---|---|---|---|---|
| dfs(root) | 10 | -∞ | +∞ | 10 ∈ (-∞,+∞) ✓ |
| dfs(左) | 5 | -∞ | 10 | 5 ∈ (-∞,10) ✓ |
| dfs(右) | 15 | 10 | +∞ | 15 ∈ (10,+∞) ✓ |
| dfs(15左) | 6 | 10 | 15 | 6 ∈ (10,15)? **✗** → false |

注意 6 在暴力版里要等扫到才暴露，这里一进节点立刻用祖先传下来的 `low=10` 判掉。每个节点只进一次，O(n)。

区间怎么传：进左孩子时 `high` 收紧成当前值（左子树必须小于当前节点），`low` 不变；进右孩子时 `low` 收紧成当前值，`high` 不变。这一步就是题面「子树所有节点」约束的精确编码。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。

**不变量**：调用 `dfs(node, low, high)` 时，`(low, high)` 恰好是「从根到 node 的路径上所有祖先对 node 施加的约束交集」，即 node 的值必须严格落在这个开区间内，整棵树才可能是 BST。

**归纳证明**：

- 初始 `dfs(root, -∞, +∞)`，根没有祖先，区间是全空间，不变量成立。
- 设 `dfs(node, low, high)` 时不变成立。若 `node.val` 不在区间内，说明某个祖先的约束被违反，直接返回 false 是对的（不会漏报）。
- 若在区间内，对左孩子调用 `dfs(left, low, node.val)`：左子树所有节点既要满足祖先约束（继承 low、high），又要小于 node（high 收紧为 node.val），交集正是 `(low, node.val)`。右孩子同理 `(node.val, high)`。不变量在子调用上保持。

**不会漏**：任何违反 BST 的节点，必然违反某个祖先的约束（题面定义就是「子树所有节点」），归纳保证它一定在某个 `(low, high)` 检查里被抓到。

**不会重**：每个节点恰好被 `dfs` 调用一次（树结构决定），没有重复扫描，这是 O(n) 的来源。

**严格性**：区间是开区间，用 `<=` / `>=` 判失败，正好对应题面的「严格小于 / 严格大于」。示例 2 里 4 在 `(5, +∞)` 之外，被 `low=5` 卡掉。

## 5. 完整代码（Python）

```python
class Solution:
    def isValidBST(self, root) -> bool:
        # 用上下界递归：每个节点必须落在祖先约束的交集开区间 (low, high) 内
        # 用 None 表示 ±∞，避免依赖具体数值范围
        def dfs(node, low, high) -> bool:
            if node is None:
                return True  # 空树/空子树天然合法

            # 严格性检查：等于边界也非法（题面要求严格小于/大于）
            if low is not None and node.val <= low:
                return False
            if high is not None and node.val >= high:
                return False

            # 左子树：上界收紧为当前值；右子树：下界收紧为当前值
            return dfs(node.left, low, node.val) and dfs(node.right, node.val, high)

        return dfs(root, None, None)
```

关键逻辑说明：

- `low is not None and node.val <= low`：左边界是「必须严格大于」的下界，等于也不行。
- 传参顺序 `dfs(node.left, low, node.val)`：左孩子继承下界 `low`，上界变成父节点值。
- `dfs(node.right, node.val, high)`：右孩子继承上界 `high`，下界变成父节点值。
- 用 `None` 而非 `-2**31` 当哨兵：题面提示 `Node.val` 可以取到 `-2^31`，用具体数值当哨兵会和合法值撞车，`None` 干净。

## 6. 复杂度

**时间 O(n)**：`dfs` 对每个节点恰好调用一次（树有 n 个节点，每个节点只从父节点被调一次），每次调用做常数次比较。n 来自节点数。

**空间 O(h)**，h 为树高：递归栈深度等于当前路径长度，最坏链状树 h = n，最好平衡树 h = log n。没有额外数据结构，只有调用栈。注意这里**不是** O(n) 的额外空间——除非树退化。

## 7. 边界与反例（至少 4 条）

1. **输入 `[2,2,2]`（根 2，左右孩子都是 2）→ 期望 false → 容易错**：只比父子会以为「不大于」就行，但题面要求严格小于/大于，等于非法。代码里 `<=` / `>=` 必须带等号。
2. **输入 `[5,4,6,null,null,3,7]` → 期望 false → 容易错**：3 是 6 的左孩子，父子比较 3 < 6 通过，但 3 在根的右子树里却小于 5，违反全局约束。这正是「只比父子」的经典陷阱，必须靠 `low=5` 卡掉。
3. **输入 `[1]` → 期望 true → 容易错**：单节点没有孩子，容易在边界判断上写错（比如误判空树为 false）。代码里 `node is None` 返回 True 保证空子树合法。
4. **输入 `[2147483647]` 或含 `-2^31` 的树 → 期望按实际值判断 → 容易错**：若用 `-2**31` / `2**31-1` 当哨兵，合法值会撞哨兵被误判。用 `None` 规避。
5. **输入 `[3,1,5,0,2,4,6]`（完全 BST）→ 期望 true → 容易错**：容易在区间传递时把左右孩子的 low/high 传反，导致合法树被误杀。

## 8. 面试追问与变体（3 条）

1. **追问：不用递归，用中序遍历怎么做？** 思路：迭代中序（显式栈），维护 `prev`，每弹出一个节点检查 `prev < node.val`，否则 false；时间 O(n)、空间 O(h)。
2. **追问：如果允许重复值（左 ≤ 当前 < 右）怎么改？** 思路：把左子树上界检查从 `<=` 改成 `<`（即 `node.val < low` 才失败），右子树仍严格。
3. **追问：只交换了 BST 中一对节点，如何恢复？** 思路：中序遍历找逆序对（第一个下降点和最后一个下降点），交换两值；是本题「中序有序」视角的直接延伸。
