## 1. 一句话本质

把所有人两两配对（或单人成船），在「每对体重和 ≤ limit」的约束下，让**船的总数最少**——也就是让**成功配对的人数尽可能多**。

## 2. 读完题的第一反应

**朴素解法**：枚举所有配对方案，找出合法配对最多的那种。人数 n 时配对方案是组合爆炸级别的，n 到 5×10⁴ 完全不可行。就算退一步想「对每个人，去剩下的人里找一个能同船的」，那也是 O(n²) 的匹配，5×10⁴ 平方是 2.5×10⁹，超时。

**关键观察**：题目只关心「两人之和 ≤ limit」，不关心谁和谁配。这就意味着**体重的大小关系是唯一有用的信息**。而一旦只依赖大小关系，排序就是免费的武器——排完序后，最重的人能不能带人，只取决于「最轻的还剩谁」。

进一步想：最重的那个人（记为 `people[r]`），他**必须**上某条船。这条船如果还能再塞一个人，塞谁最划算？塞**最轻的** `people[l]`。因为如果连最轻的都塞不进去（`people[l] + people[r] > limit`），那在场没有任何人能和 `people[r]` 同船，他只能独享一条船。这个「最重配最轻」的决策，就是贪心的入口。

## 3. 从暴力到最优

**暴力**：对每个人尝试与其余所有人配对，本质是求一个最大匹配，O(n²) 起步。

**第一步优化——排序**：把 people 升序排好。排序本身 O(n log n)，但它让「最重」「最轻」变成 O(1) 可取，这是后面所有操作的前提。

**第二步优化——双指针**：排完序后，维护 `l` 指向当前最轻、`r` 指向当前最重。每轮处理 `people[r]`：

- 若 `people[l] + people[r] <= limit`：两人同船，`l += 1`，`r -= 1`，船数 +1。
- 否则：`people[r]` 独船，`r -= 1`，船数 +1。

每轮 `r` 必减 1，所以循环恰好 n 轮，O(n)。总复杂度被排序的 O(n log n) 主导。

**小例子走一遍**：`people = [3,2,2,1], limit = 3`。

排序后 `[1,2,2,3]`，`l=0, r=3, boats=0`。

| 轮次 | l | r | people[l]+people[r] | 判断 | 动作 | boats |
|---|---|---|---|---|---|---|
| 1 | 0 | 3 | 1+3=4 > 3 | 最重独船 | r=2 | 1 |
| 2 | 0 | 2 | 1+2=3 ≤ 3 | 配对 | l=1, r=1 | 2 |
| 3 | 1 | 1 | l==r，剩一人 | 独船 | r=0 | 3 |

循环结束（`l > r`），返回 3，与示例一致。

再走一个 `people = [3,5,3,4], limit = 5`：排序 `[3,3,4,5]`。

| 轮次 | l | r | 和 | 判断 | 动作 | boats |
|---|---|---|---|---|---|---|
| 1 | 0 | 3 | 3+5=8 > 5 | 独船 | r=2 | 1 |
| 2 | 0 | 2 | 3+4=7 > 5 | 独船 | r=1 | 2 |
| 3 | 0 | 1 | 3+3=6 > 5 | 独船 | r=0 | 3 |
| 4 | 0 | 0 | l==r | 独船 | r=-1 | 4 |

返回 4。注意这里**没有任何一对能配对**，贪心全部判独船，正确。

## 4. 正确性：为什么不会漏、不会重

用**交换论证**说明「最重配最轻」不会让答案变差。

设当前剩余人中最重的是 `H`，最轻的是 `L`。

**情形一：`L + H > limit`。** 那么对任意剩余的人 `x`，都有 `x ≥ L`，所以 `x + H ≥ L + H > limit`。也就是说 `H` 和**任何人**都无法同船，`H` 必须独占一条船。这一步是**被迫的**，不存在「更好的选择」，贪心没有损失。

**情形二：`L + H ≤ limit`。** 贪心让 `L` 和 `H` 同船。要证明这不会比最优解差，考虑任意一个最优解：在最优解里，`H` 要么独船，要么和某人 `x` 同船。

- 若 `H` 独船：把 `L` 拉过来和 `H` 同船（因为 `L+H ≤ limit` 合法），`L` 原来所在的船少一个人，船数不增。所以存在一个最优解让 `L` 和 `H` 同船。
- 若 `H` 和 `x` 同船：若 `x = L` 已经满足；若 `x ≠ L`，则 `L` 在别的船上（或独船）。把 `x` 和 `L` 对调：`H` 与 `L` 同船合法（已知 `L+H ≤ limit`），而 `x` 去 `L` 原来的位置——因为 `x ≥ L`（`L` 是最轻的），`x` 和 `L` 原船友的重量和只会更小或不变，仍然合法。船数不变。所以同样存在一个最优解让 `L` 和 `H` 同船。

两种情形下，贪心的这一步都能被某个最优解「认领」，因此逐步贪心不劣于最优，最终船数就是最小值。

**不变量**：每轮结束时，`[0, l)` 和 `(r, n)` 中的人都已经安排好船，且 `[l, r]` 是尚未处理的人，且这个安排方式与某个最优解在这些人上的安排一致。归纳可证。

## 5. 完整代码（Python）

```python
class Solution:
    def numRescueBoats(self, people: list[int], limit: int) -> int:
        # 排序：让「最重」「最轻」都能 O(1) 取到，是双指针贪心的前提
        people.sort()
        l, r = 0, len(people) - 1
        boats = 0

        while l <= r:
            # 每轮都先给最重的 people[r] 安排一条船
            if people[l] + people[r] <= limit:
                # 最轻的能搭上最重的，两人同船，两个指针都动
                l += 1
            # 否则最重的只能独船（最轻的都搭不上，别人更搭不上）
            r -= 1
            boats += 1

        return boats
```

关键点：`boats += 1` 放在 `if` 外面，因为**无论是否配对，最重的那个人这一轮都消耗了一条船**。这是最容易写错的地方——很多人会在 `if` 和 `else` 里各写一次 `boats += 1`，逻辑上等价但容易漏。

## 6. 复杂度

- **时间 O(n log n)**：`n` 来自 `people` 的长度，`log n` 来自 `sort()` 的比较排序下界。排序之后的双指针循环每轮 `r` 减 1，最多 n 轮，是 O(n)，被 O(n log n) 吸收。
- **空间 O(log n)**：Python 的 `list.sort()` 是 Timsort，最坏额外空间 O(n)，平均/常见 O(log n) 的栈空间。如果面试官要求严格 O(1) 额外空间，可以说「排序本身不计入」或改用计数排序（因为 `people[i] ≤ limit ≤ 3×10⁴`，值域小，计数排序 O(n + limit) 时间、O(limit) 空间）。

## 7. 边界与反例（至少 4 条）

1. **`people = [1], limit = 3`** → 期望 `1`。容易错在循环条件写成 `l < r`，单人时直接不进循环返回 0。必须用 `l <= r`。
2. **`people = [3,3,3], limit = 3`** → 期望 `3`。每个人恰好等于 limit，任意两人之和 6 > 3，全部独船。容易错在没检查 `people[l] + people[r]` 就无脑配对。
3. **`people = [1,1,1,1], limit = 2`** → 期望 `2`。全部能两两配对。容易错在配对后忘记同时移动 `l` 和 `r`，导致重复计数或死循环。
4. **`people = [5,5,5,5], limit = 5`** → 期望 `4`。所有人等于 limit，全独船。和第 2 条类似但更极端，验证「和 > limit 时只动 r」的逻辑。
5. **`people = [1,2,2,3], limit = 4`** → 期望 `3`。排序后 `[1,2,2,3]`：1+3=4 配对，剩 `[2,2]`，2+2=4 配对，共 2 条船？等等——重算：轮 1 配对 (1,3)，l=1,r=2；轮 2 是 2+2=4 配对，l=2,r=1，循环结束，boats=2。但正确答案是 2 吗？(1,3) 和 (2,2) 两条船，确实 2。这条用来验证「配对后两个指针都动」不会漏人。

## 8. 面试追问与变体（3 条）

1. **追问：如果每艘船最多载 3 人，怎么做？** 思路：双指针不再够用，需要更复杂的贪心或 DP；一个常见近似是「先尽量塞最重的 + 两个最轻的」，但严格最优需要更细的分类讨论，面试中通常只要求说出「双指针失效的原因」。
2. **追问：如果要求输出具体的分组方案，而不只是船数？** 思路：在双指针过程中记录每轮的 `(l, r)` 配对或单人，用一个列表存下来即可，复杂度不变。
3. **追问：如果 `people` 已排序，能否做到 O(n) 时间？** 思路：可以，双指针本身就是 O(n)，排序是唯一瓶颈；若输入已有序，直接双指针即可，总时间 O(n)。
