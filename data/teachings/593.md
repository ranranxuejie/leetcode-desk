## 1. 一句话本质

在四个无序点构成的所有点对里，判断「距离的分布」是否恰好是正方形该有的那种分布——4 条相等的短边 + 2 条相等的长对角线。

## 2. 读完题的第一反应

**朴素解法**：四个点无序，那就枚举 4! = 24 种排列，把每种排列当成「按顺序围成四边形」，然后依次检查四条边相等、四个角是直角。检查一次是 O(1)，24 次也是 O(1)，所以复杂度上其实不卡——**卡在「怎么判直角」和「怎么判顺序」这两件事本身很脏**：判直角要算向量点积，判顺序要保证四个点真的按环绕顺序排（否则会退化成自交四边形），代码又长又容易写错。

**关键观察**：正方形有一个纯距离刻画的性质——四个点两两之间一共 C(4,2) = 6 条距离，正方形恰好是「4 条相等的小距离 + 2 条相等的大距离，且大距离 = 小距离 × √2」。这个性质**完全不依赖点的顺序**，所以「输入无序」这个最大的麻烦被直接绕开了：我们不需要知道谁挨着谁，只需要把 6 条距离全算出来看分布。

为什么这个观察能直接导向下一步？因为它把「几何形状判定」翻译成了「多重集合的相等性判定」，而后者在 Python 里就是 `sorted` 一下比较，或者用 `set` 数一数。几何的脏活（角度、顺序、共线）全部消失了。

## 3. 从暴力到最优

**第一步：暴力枚举排列。** 对 24 种排列，取相邻点算 4 条边长、算 4 个角。瓶颈不在复杂度（常数级），而在**正确性维护成本**：你得处理「排列出来的四边形是自交的」这种情况，还得用浮点或分数判直角。写对不难，写稳很难。

**第二步：换成距离分布。** 不再关心顺序，直接算 6 条距离。以示例 1 为例，p1=(0,0), p2=(1,1), p3=(1,0), p4=(0,1)：

- d(p1,p2) = 1² + 1² = 2
- d(p1,p3) = 1² + 0 = 1
- d(p1,p4) = 0 + 1² = 1
- d(p2,p3) = 0 + 1² = 1
- d(p2,p4) = 1² + 0 = 1
- d(p3,p4) = 1² + 1² = 2

排序后是 `[1, 1, 1, 1, 2, 2]`。前 4 个相等、后 2 个相等、且 2 = 1 × 2（注意这里存的是**平方距离**，所以倍数关系是 2 而不是 √2），判定通过。

**第三步：消掉「排序」这个动作。** 排序 6 个数是 O(1)，其实无所谓。但更干净的写法是用 `set`：6 条平方距离去重后**必须恰好剩 2 个不同的值**，且小值出现 4 次、大值出现 2 次、大值 = 2 × 小值。这一步把「分布」直接压成三个可验证的断言，代码只有几行。

**瓶颈在哪被消掉的**：原来的瓶颈是「顺序未知导致几何关系未知」，现在距离是**无序点对的无序集合**，天然对输入顺序免疫——这就是从暴力到最优的全部跳跃。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义不变量 I：*四个点构成的 6 条平方距离的多重集合，在点的任意重命名下不变*。因为距离只依赖点对，不依赖谁叫 p1，所以 I 对输入顺序免疫——这保证了我们的判定不会因为输入排列不同而给出不同答案（不漏判、不误判）。

然后证明两个方向：

**充分性（满足分布 ⇒ 是正方形）。** 设 6 条平方距离为 4 个 s 和 2 个 2s。取那 2 条长度为 2s 的对角线，它们必然共享某两个端点……更直接的论证：4 个点中，任取一个点 P，它到其余三点的距离里，由分布可知必是「两条 s + 一条 2s」（因为每个点参与 3 条距离，而 2s 只有 2 条、每条覆盖 2 个端点，所以 2s 的两条端点恰好是 4 个点里的 2 个，剩下 2 个点各自只连 s）。于是 P 的两条 s 边互相垂直（由 2s = s + s 的余弦定理，夹角余弦为 0），且长度相等——P 是一个直角顶点。对四个点都成立，四个直角 + 四边相等 ⇒ 正方形。**关键点：2s = 2 × s 这个等式不是装饰，它正是「直角」的代数化身**，缺了它就只能得到菱形。

**必要性（正方形 ⇒ 满足分布）。** 正方形四边平方长 s、两条对角线平方长 2s，6 条距离恰好是 4 个 s + 2 个 2s，直接成立。

**不会重**：`set` 去重后要求恰好 2 个值，排除了「6 条距离全相等」（那是正三角形加中心点之类，退化）和「只有 1 个值」（四点重合）。**不会漏**：分布条件是可逆的充要条件，上面两个方向都证了。

## 5. 完整代码（Python）

```python
class Solution:
    def validSquare(self, p1, p2, p3, p4) -> bool:
        pts = [p1, p2, p3, p4]

        # 计算两点间的平方距离（用平方避免开根号的浮点误差）
        def dist2(a, b):
            dx = a[0] - b[0]
            dy = a[1] - b[1]
            return dx * dx + dy * dy

        # 枚举全部 C(4,2)=6 个点对，收集平方距离
        ds = []
        for i in range(4):
            for j in range(i + 1, 4):
                ds.append(dist2(pts[i], pts[j]))

        # 去重后必须恰好两个不同的距离值
        uniq = set(ds)
        if len(uniq) != 2:
            return False

        # 小距离是边长平方，大距离是对角线平方
        small, large = sorted(uniq)

        # 对角线平方必须是边长平方的 2 倍（直角条件）
        if large != 2 * small:
            return False

        # 分布必须是 4 条边 + 2 条对角线
        return ds.count(small) == 4 and ds.count(large) == 2
```

注意 `small` 不可能为 0：若为 0 则四点重合，`uniq` 只剩 1 个值，早就在 `len(uniq) != 2` 处被拦下。

## 6. 复杂度

- **时间 O(1)**：固定 4 个点，点对数恒为 6，循环 6 次；`set` 和 `count` 都在长度 6 的列表上操作。没有任何随输入规模增长的项，所以是常数。这里的「n」被题目钉死为 4，不贡献任何渐进项。
- **空间 O(1)**：`ds` 长度恒为 6，`uniq` 至多 6 个元素，与坐标值大小无关（坐标范围 ±10⁴ 只影响数值大小，不影响存储个数）。

如果把它推广到「n 个点判正方形」，才会出现 O(n²) 的点对枚举——但那不是本题。

## 7. 边界与反例（至少 4 条）

1. **四点重合**：`p1=p2=p3=p4=[0,0]` → 期望 `false` → 6 条距离全是 0，`uniq` 只有 1 个值，被 `len(uniq) != 2` 拦下。容易错在只判「距离相等」就返回 true。
2. **菱形非正方形**：`[0,0],[1,0],[2,1],[1,1]` → 期望 `false` → 四边平方都是 1，但两条对角线平方是 2 和 4，`uniq` 有 3 个值。容易错在只验证「四条边相等」。
3. **矩形非正方形**：`[0,0],[2,0],[2,1],[0,1]` → 期望 `false` → 距离分布是 1,1,4,4,5,5，`uniq` 有 3 个值。容易错在只验证「对角线相等」。
4. **三点共线 / 退化**：`[0,0],[1,0],[2,0],[1,1]` → 期望 `false` → 距离里出现 1,1,4,4,2,5 之类，`uniq` 超过 2 个。容易错在用角度判直角时浮点误差放过退化情形。
5. **大坐标溢出（语言相关）**：坐标 ±10⁴ 时平方距离最大 8×10⁸，Python 无溢出；但若换成 C++ 用 `int` 也够，用 `short` 会炸——这是提醒你别在小类型上算平方。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回「哪两个点是对角线端点」怎么办？** 思路：找出那 2 条长度为 `large` 的点对，它们的公共端点就是一组对角顶点，另外两点是另一组。
2. **追问：给 n 个点，判断其中是否存在 4 个点构成正方形？** 思路：枚举所有点对作为一条边，用旋转 90° 算出另外两个候选点，哈希查表，O(n²) 时间。
3. **追问：改成判断「正三角形」或「正 k 边形」？** 思路：正三角形用 3 条距离全相等；正 k 边形距离分布更复杂，通常改用「重心 + 各顶点到重心等距且相邻夹角相等」，或直接排序后按极角检查。
