## 1. 一句话本质

把一张用「节点对象 + 邻居指针」表示的图，**按原样复制出一套全新的节点对象**，新图里任意两个节点之间的连接关系与原图完全一致，但新节点与原节点在内存上互不相干。

注意这里的关键词是「对象」而不是「值」：如果只是把每个 `val` 抄一遍、把邻居的 `val` 抄一遍，那叫复制数据；克隆要求的是复制**引用结构**，新图里节点 A 的邻居列表里放的必须是新节点 B，而不是原节点 B。

## 2. 读完题的第一反应

**朴素解法**：从给定节点出发遍历原图，每遇到一个节点就 `new Node(cur.val)` 造一个新节点，然后把它的邻居也照抄一遍。听起来很顺，但立刻会撞上两个坑：

- **坑一（重复造节点）**：图不是树，节点 1 的邻居是 2，节点 2 的邻居又是 1。你从 1 走到 2，造了「新 2」；从 2 再走回 1，如果不加判断，你会再造一个「新 1」。最后新图里出现了一堆本该是同一个节点的副本，结构就散了。
- **坑二（无限递归）**：更糟的是，1→2→1→2→… 会无限循环下去，直接栈溢出。

所以朴素解法卡在「**如何知道某个原节点已经被克隆过了**」这个问题上。复杂度上，如果每造一个节点都要在已有克隆里线性查找一遍「这个原节点克隆过没有」，那就是 O(n²)。

**关键观察**：节点值 `val` 在图中唯一（提示里明确写了「每个节点值 Node.val 都是唯一的」），而且节点数 ≤ 100。这提示我们：可以用一个**哈希表**，键是原节点（或它的 val），值是它对应的克隆节点。这样「查有没有克隆过」就是 O(1)，重复造节点和无限递归两个坑一起被填掉。

一旦有了这张表，整道题就退化成一次普通的图遍历（DFS 或 BFS 都行），遍历时顺手填表、顺手连边。

## 3. 从暴力到最优

用一个具体小例子走一遍。取示例 1 的图：1 的邻居是 [2,4]，2 的邻居是 [1,3]，3 的邻居是 [2,4]，4 的邻居是 [1,3]。

**暴力版（无记忆）**，从 1 出发 DFS：

```
clone(1):
  造 new1(val=1)
  对邻居 2: clone(2)
     造 new2(val=2)
     对邻居 1: clone(1)   ← 又造了一个 new1'，且继续往下会无限递归
```

走到这里就崩了：new1 和 new1' 是两个不同对象，原图里 1 只有一个，新图里却有两个，结构错了；而且递归停不下来。

**加哈希表版**，维护 `visited = {}`（原节点 → 克隆节点）：

```
clone(1):
  visited 里没有 1 → 造 new1，visited[1] = new1
  遍历 1 的邻居 2:
    visited 里没有 2 → 造 new2，visited[2] = new2
    遍历 2 的邻居 1:
      visited 里有 1 → 直接拿到 new1，把 new1 塞进 new2.neighbors
    遍历 2 的邻居 3:
      visited 里没有 3 → 造 new3，visited[3] = new3
      ...（3 的邻居 2 已在表里，直接连；4 未在表里，造 new4）
    回到 2，new2.neighbors = [new1, new3]
  遍历 1 的邻居 4:
    visited 里没有 4 → 造 new4，visited[4] = new4
    4 的邻居 1、3 都已在表里，直接连
  回到 1，new1.neighbors = [new2, new4]
```

最终 `visited` 里有 4 个条目，每个原节点恰好对应一个克隆节点，且邻居列表里连的都是克隆节点。**瓶颈从「线性查找 + 可能无限递归」变成「哈希 O(1) 查表 + 每个节点只展开一次」**，整体从 O(n²) 降到 O(n + m)，m 是边数。

这里有个容易忽略的细节：**「造节点」和「登记到哈希表」必须发生在「遍历它的邻居之前」**。如果先遍历邻居再登记，那么当邻居指回自己时（比如 2 的邻居是 1），表里还查不到 1，就会重复造节点。所以顺序是：查表 → 没有就造并登记 → 再展开邻居。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。在整个遍历过程中，始终维持：

> **不变量 I**：对任意原节点 u，若 u 已被访问过，则 `visited[u]` 存在且唯一，且 `visited[u].val == u.val`；并且对任意已访问节点 u 的任意邻居 v，若 v 也已访问，则 `visited[u].neighbors` 中恰好包含 `visited[v]` 一次。

**不会重（唯一性）**：节点只有在「查表发现不存在」时才会被创建并立即写入 `visited`。由于哈希表的写入是原子的、且此后查表必命中，任何原节点最多被创建一次。所以每个原节点对应恰好一个克隆节点。

**不会漏（覆盖性）**：题目保证图连通，从给定节点出发做 DFS/BFS 能到达所有节点。每到达一个未访问节点就创建它，所以所有节点都会被克隆。

**边关系正确**：对每条原边 (u, v)，当遍历到 u 时，v 要么已在表里（直接连 `visited[v]`），要么会被递归访问并创建后连上。两种情况都保证 `visited[u].neighbors` 里出现 `visited[v]`。反向边 (v, u) 同理。因此新图的边集与原图一一对应。

**不污染原图**：全程只读原节点的 `val` 和 `neighbors`，只写新节点的 `neighbors`，原图对象不被修改。

三条合起来：新图与原图同构，且是深拷贝。

## 5. 完整代码（Python）

```python
# 题目给的 Node 定义（力扣环境里已提供，这里写出便于本地运行）
class Node:
    def __init__(self, val=0, neighbors=None):
        self.val = val
        self.neighbors = neighbors if neighbors is not None else []


class Solution:
    def cloneGraph(self, node: 'Node') -> 'Node':
        # 空图直接返回 None（对应示例 3）
        if node is None:
            return None

        # visited: 原节点 -> 克隆节点。这张表同时承担两个职责：
        # 1) 判断某原节点是否已克隆（防重复造节点、防无限递归）
        # 2) 提供「原节点对应的克隆节点」以便连边
        visited = {}

        def dfs(cur: 'Node') -> 'Node':
            # 已克隆过，直接返回对应的克隆节点（这就是防环的关键）
            if cur in visited:
                return visited[cur]

            # 先造节点并登记，再展开邻居。
            # 顺序不能反：否则邻居指回自己时会重复造节点。
            clone = Node(cur.val)
            visited[cur] = clone

            # 逐个克隆邻居，并挂到克隆节点的邻居列表上
            for nb in cur.neighbors:
                clone.neighbors.append(dfs(nb))

            return clone

        return dfs(node)
```

如果面试官要求非递归，把 `dfs` 换成 BFS 即可，思路完全一样：队列里放原节点，出队时确保它的克隆已存在，然后遍历邻居、给邻居建克隆（若没有）、把克隆邻居挂上、把未访问的邻居入队。

```python
from collections import deque

class Solution:
    def cloneGraph(self, node: 'Node') -> 'Node':
        if node is None:
            return None
        visited = {node: Node(node.val)}
        q = deque([node])
        while q:
            cur = q.popleft()
            for nb in cur.neighbors:
                if nb not in visited:
                    visited[nb] = Node(nb.val)
                    q.append(nb)
                visited[cur].neighbors.append(visited[nb])
        return visited[node]
```

## 6. 复杂度

设节点数 n、边数 m（无向图里 m 是邻接表条目总数，约为边数的两倍）。

- **时间 O(n + m)**：每个节点最多被创建一次、入队/递归一次，贡献 O(n)；每条邻接关系被检查一次（DFS 里是 `for nb in cur.neighbors`，BFS 里同理），贡献 O(m)。哈希表的插入和查询均摊 O(1)，不引入额外因子。这里没有 log n，因为没排序、没二分。
- **空间 O(n)**：`visited` 哈希表存 n 个条目，贡献 O(n)；DFS 的递归栈最坏深度为 n（图退化成链时），贡献 O(n)；BFS 的队列最坏也装 n 个节点。三者都是 O(n)，合计 O(n)。注意**不**是 O(n + m)，因为邻居列表是挂在克隆节点上的，属于输出本身，不额外计入辅助空间。

## 7. 边界与反例（至少 4 条）

1. **输入 `adjList = []`（空图）** → 期望返回 `None`。容易错在没判空，直接对 `None` 取 `.val` 或 `.neighbors` 抛异常。题面示例 3 明确给了这个用例。
2. **输入 `adjList = [[]]`（单节点无邻居）** → 期望返回一个 `val=1`、`neighbors=[]` 的新节点。容易错在把「邻居列表为空」误判成「图不存在」，或者返回了原节点本身（没做深拷贝）。
3. **两个节点互相连接：`[[2],[1]]`** → 期望新图里 new1.neighbors=[new2]、new2.neighbors=[new1]。这是最容易暴露「先展开邻居后登记」bug 的用例：若顺序反了，会造出两个 new1 或两个 new2，或者直接无限递归。
4. **带自环的图（虽然题面说没有自环，但追问常考）**：若允许 `[[1]]` 这种自环，期望 new1.neighbors 里包含 new1 自己。容易错在「造节点前先查表」的逻辑写反，导致自环时造出第二个节点。
5. **长链图 `[[2],[3],[4],...,[n]]`** → 期望正常克隆。容易错在递归版栈深度达到 n，n=100 时 Python 默认递归上限 1000 还撑得住，但如果面试官把 n 放大到 10^5，递归版会 `RecursionError`，此时必须换 BFS。

## 8. 面试追问与变体（3 条）

1. **追问：如果图不连通怎么办？** 思路：外层再套一层循环，遍历所有节点，对每个未访问节点调用一次 clone 逻辑；`visited` 表全局共享，保证跨连通分量也不重复造节点。
2. **追问：不用哈希表，能不能用数组？** 思路：题面保证 `1 <= val <= 100` 且 val 唯一，可以开一个长度 101 的数组 `clone_of[val]` 代替字典，查询 O(1) 且常数更小；代价是依赖「val 范围小且唯一」这个题面条件，通用性差。
3. **追问：如何判断两个图是否同构（而不是克隆）？** 思路：克隆是「已知对应关系」的复制；同构判定需要额外做节点匹配，通常用「度数序列 + BFS 分层 + 规范化编码」或回溯匹配，复杂度远高于本题，属于另一个难度档。
