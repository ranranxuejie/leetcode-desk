## 1. 一句话本质

在数组里找一个最大的整数 h，使得「引用次数 ≥ h 的论文数量」也 ≥ h——即找满足 `count(≥h) ≥ h` 的最大 h。

## 2. 读完题的第一反应

**朴素解法**：对每个可能的 h（从 0 到 n）都扫一遍数组数一数有多少篇 ≥ h，取最大的合法 h。外层 n 种 h、内层 n 次扫描，O(n²)。n ≤ 5000 时其实也能过，但这不是我们想要的答案。

**卡在哪**：重复扫描。h 从 1 变到 2 时，`count(≥1)` 和 `count(≥2)` 之间有大量重复信息被浪费了。

**关键观察**：h 的定义只关心「有多少篇 ≥ h」，不关心具体是哪几篇、也不关心它们的原始顺序。一旦把数组**排好序**，`count(≥h)` 就变成了一次「从右往左数到哪停」的定位问题——有序性把「数个数」这个 O(n) 操作压缩成了 O(1) 的下标判断。

再进一步：h 最大不超过 n（最多 n 篇论文），而引用次数超过 n 的部分对 h 毫无影响（一篇被引 1000 次的论文，在 h ≤ n 的语境下和 n 次没区别）。这个「截断」观察直接引出计数排序的 O(n) 解法。

## 3. 从暴力到最优

**第一步：排序 + 线性扫描**

以 `citations = [3,0,6,1,5]` 为例，排序后 `[0,1,3,5,6]`，n = 5。

从右往左看：下标 i（0-based）处，从 i 到末尾共有 `n - i` 篇论文，它们的引用次数都 ≥ `citations[i]`（因为有序）。于是候选 h = `min(citations[i], n - i)`，取所有 i 上的最大值。

逐个算：

| i | citations[i] | n-i | min |
|---|---|---|---|
| 4 | 6 | 1 | 1 |
| 3 | 5 | 2 | 2 |
| 2 | 3 | 3 | 3 |
| 1 | 1 | 4 | 1 |
| 0 | 0 | 5 | 0 |

最大值 3，正确。瓶颈是排序 O(n log n)。

**第二步：计数排序消掉 log n**

观察到 `citations[i]` 可以大到 1000，但 h 最多是 n = 5。任何 ≥ n 的引用次数，在判断「是否 ≥ h」时（h ≤ n）效果完全等同于 n。所以把每个值**截断到 n**，值域就压到了 `[0, n]`，共 n+1 个桶，计数排序 O(n)。

仍用上例，n = 5，截断后还是 `[3,0,5,1,5]`（6 被截成 5）。计数桶 `cnt[0..5] = [1,1,0,1,0,2]`。

然后从 h = n 往下走，维护「引用次数 ≥ h 的论文数」`total`，每降一级就把 `cnt[h]` 累加进来：

- h=5：total = cnt[5] = 2，2 ≥ 5？否
- h=4：total += cnt[4] = 2，2 ≥ 4？否
- h=3：total += cnt[3] = 3，3 ≥ 3？是 → 返回 3

得到 3，正确。整个过程只扫了两遍数组，O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚计数排序版本。

**不变量**：在从 h = n 递减到 h 的任意时刻，变量 `total` 恰好等于「引用次数 ≥ h 的论文篇数」。

- 初始 h = n 时，`total = cnt[n]`，而 `cnt[n]` 统计的正是所有被截断后等于 n 的论文，也就是原始引用次数 ≥ n 的论文，不变量成立。
- 归纳步：从 h+1 降到 h 时，新增的恰好是引用次数**正好等于 h** 的那批论文，数量为 `cnt[h]`，其余论文的「≥ h+1」与「≥ h」判定相同。故 `total += cnt[h]` 后不变量仍成立。

**为什么第一个满足条件的 h 就是答案**：我们从 n 往下枚举，遇到的第一个满足 `total ≥ h` 的 h 就是最大的合法 h——比它大的所有 h' 都已经被检查过且不满足。所以既不会漏（枚举覆盖了所有候选），也不会重（返回即停）。

**截断为什么安全**：设原始值为 c，截断为 `min(c, n)`。对任意 h ≤ n，`c ≥ h` 与 `min(c,n) ≥ h` 等价（因为 h ≤ n，若 c ≥ h 则 min(c,n) ≥ h；反之 min(c,n) ≤ c，min(c,n) ≥ h 蕴含 c ≥ h）。所以截断不改变任何 h ≤ n 的判定结果，而 h 本来就不可能超过 n。

## 5. 完整代码（Python）

```python
class Solution:
    def hIndex(self, citations: list[int]) -> int:
        n = len(citations)

        # 桶：cnt[v] 表示「截断后引用次数恰好为 v」的论文数
        # 值域被压到 [0, n]，所以开 n+1 个桶
        cnt = [0] * (n + 1)
        for c in citations:
            # 超过 n 的引用次数对 h（h <= n）没有额外贡献，统一记到 n 号桶
            cnt[min(c, n)] += 1

        total = 0  # 引用次数 >= 当前 h 的论文篇数
        # 从大到小枚举 h，第一个满足 total >= h 的就是最大 h
        for h in range(n, -1, -1):
            total += cnt[h]      # 把「恰好等于 h」的论文并入「>= h」
            if total >= h:       # 不变量保证此时 total == count(>= h)
                return h

        return 0  # 逻辑上不会走到这里（h=0 时 total>=0 恒成立）
```

## 6. 复杂度

**时间 O(n)**：
- 建桶循环遍历 n 篇论文，每篇 O(1) 的 `min` 和自增 → O(n)。
- 倒序枚举 h 从 n 到 0，共 n+1 次，每次 O(1) → O(n)。
- 合计 O(n)，**没有 log n**，因为计数排序用「值域大小 = n+1」换掉了比较排序的 log n。

**空间 O(n)**：`cnt` 数组长度 n+1，其余是常数个变量。注意这里没有额外排序数组，原数组也没被修改。

对比：排序解法是 O(n log n) 时间、O(1) 或 O(n) 空间（取决于是否原地排序）；计数解法用 O(n) 空间换掉了 log n。

## 7. 边界与反例（至少 4 条）

1. **`citations = [0]`** → 期望 0。容易错在：`total = cnt[0] = 1`，但 1 ≥ 0 成立时返回的是 h=0，别写成返回 1；h 的上界是 n=1，但 1 篇 0 引用的论文 h 只能是 0。

2. **`citations = [100]`** → 期望 1。容易错在：不截断时若用「值域 = max(citations)」建桶，会开 101 个桶，虽然结果对但空间被 max 值绑架；更隐蔽的错是直接拿 `citations[i]` 当 h 候选，得出 100 这种非法答案。

3. **`citations = [1,1,1,1]`** → 期望 1。容易错在：4 篇论文都只被引 1 次，h 不能是 4；扫描时 `min(citations[i], n-i)` 在 i=0 处是 `min(1,4)=1`，别误以为「篇数够多 h 就大」。

4. **`citations = [5,5,5,5,5]`** → 期望 5。容易错在：所有值都 ≥ n，全部落进 `cnt[n]` 桶，`total = 5 ≥ 5` 在 h=5 时立即命中；若截断写错（比如截到 n-1）会漏掉这个桶。

5. **`citations = [3,0,6,1,5]`** → 期望 3（示例）。容易错在：h=4 时 total=2 不满足，h=3 时 total=3 满足，必须**从大到小**枚举才能保证第一个命中就是最大；从小到大枚举会返回 1。

## 8. 面试追问与变体（3 条）

1. **追问：不允许额外空间，怎么做？** 思路：排序后从右往左扫，`min(citations[i], n-i)` 取最大，O(n log n) 时间 O(1) 额外空间（原地排序）。

2. **追问：如果数组是流式输入、只能读一遍，怎么办？** 思路：仍然用计数桶，但需要知道 n 才能定桶大小；若 n 未知，可先按当前已读长度动态扩容，或退化为「维护一个大小为当前 n 的桶 + 每步重算」，讲清权衡即可。

3. **追问：如果要求返回所有可能的 h 值（不止最大）？** 思路：计数排序后从 n 往下扫，把所有满足 `total ≥ h` 的 h 收集起来，O(n) 时间；注意 h=0 恒合法，是否计入要跟面试官确认。
