## 1. 一句话本质

把「竖式乘法」这个人类手算过程，翻译成对两个数字字符数组的逐位相乘 + 进位累加，全程不把字符串转成整数。

## 2. 读完题的第一反应

**朴素解法**：把 num1、num2 转成 int 相乘再转回字符串。但题面明确禁止「直接将输入转换为整数」，而且提示里长度上限是 200 位——Python 的 int 能扛住，但出题人就是要你模拟，所以这条路直接封死。

那退一步，**用字符串模拟「加法」**：把 num2 的每一位拆出来，分别和 num1 相乘得到一个中间结果（字符串），再把这若干个中间结果错位相加。这个思路是对的，但瓶颈在「加法」：num2 有 m 位，就要做 m 次「大数加法」，每次加法 O(n+m)，总复杂度 O(m·(n+m))。当 n=m=200 时是 8 万次字符操作，能过，但代码里要维护「字符串加法」和「错位」两个辅助逻辑，容易写错。

**关键观察**：竖式乘法的本质是「第 i 位 × 第 j 位，结果落在第 i+j 位」。与其先算出 m 个中间字符串再相加，不如**开一个结果数组，把所有 i×j 的乘积直接累加到对应位置上，最后统一处理进位**。这样「加法」被摊平成了数组下标累加，一次遍历就完事，代码量骤降，也不容易错位。

这个观察能成立的依据是题面给的「num1、num2 只含数字、无前导零」——每一位都是 0~9，单次乘积最大 81，累加后进位逻辑简单可控。

## 3. 从暴力到最优

**第一步：字符串加法版（暴力模拟）**

以 `num1="123", num2="456"` 为例：

- 6 × 123 = "738"
- 5 × 123 = "615"，左移一位 → "6150"
- 4 × 123 = "492"，左移两位 → "49200"
- 三者相加：738 + 6150 + 49200 = 56088

每做一次乘法要 O(n)，做 m 次，再加 m 次 O(n+m) 的加法，瓶颈在「反复构造中间字符串 + 反复进位」。

**第二步：数组累加版（最优）**

还是 `123 × 456`。设 `a = [1,2,3]`（num1 从左到右），`b = [4,5,6]`。开结果数组 `res`，长度 `n+m = 6`，初始全 0。

核心规则：`a[i] * b[j]` 累加到 `res[i+j+1]`（因为最低位对齐在数组末尾）。

逐对累加（i 从 0 到 2，j 从 0 到 2）：

| 操作 | 乘积 | 累加到下标 | res 变化 |
|---|---|---|---|
| a[0]×b[0] | 1×4=4 | 1 | [0,4,0,0,0,0] |
| a[0]×b[1] | 1×5=5 | 2 | [0,4,5,0,0,0] |
| a[0]×b[2] | 1×6=6 | 3 | [0,4,5,6,0,0] |
| a[1]×b[0] | 2×4=8 | 2 | [0,4,13,6,0,0] |
| a[1]×b[1] | 2×5=10 | 3 | [0,4,13,16,0,0] |
| a[1]×b[2] | 2×6=12 | 4 | [0,4,13,16,12,0] |
| a[2]×b[0] | 3×4=12 | 3 | [0,4,13,28,12,0] |
| a[2]×b[1] | 3×5=15 | 4 | [0,4,13,28,27,0] |
| a[2]×b[2] | 3×6=18 | 5 | [0,4,13,28,27,18] |

此时 `res = [0,4,13,28,27,18]`，每一位都可能是两位数，需要**从右往左统一进位**：

- 下标 5：18 → 保留 8，进位 1 给下标 4 → res[4]=28
- 下标 4：28 → 保留 8，进位 2 给下标 3 → res[3]=30
- 下标 3：30 → 保留 0，进位 3 给下标 2 → res[2]=16
- 下标 2：16 → 保留 6，进位 1 给下标 1 → res[1]=5
- 下标 1：5 → 保留 5，进位 0
- 下标 0：0

最终 `res = [0,5,6,0,8,8]`，去掉前导 0 → `"56088"`。✅

对比两步：第一步的瓶颈是「m 次字符串拼接 + 加法」，第二步把「加法」变成「数组下标累加」，把「进位」推迟到最后一次性做，复杂度从 O(m·(n+m)) 降到 O(n·m)，而且没有字符串拼接的开销。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：在双重循环结束后、进位之前，`res[k]` 的值等于「所有满足 `i+j+1 = k` 的 `a[i]*b[j]` 之和」。

- **不漏**：双重循环枚举了所有 `(i,j)` 对，每一对恰好被访问一次，且都累加到了 `res[i+j+1]`。所以每个 `a[i]*b[j]` 都出现在某个 `res[k]` 里。
- **不重**：每个 `(i,j)` 对只被访问一次，只做一次累加，没有重复计入。

**为什么这个不变量等价于乘积**：把 num1 写成 `Σ a[i]·10^(n-1-i)`，num2 写成 `Σ b[j]·10^(m-1-j)`，乘积展开就是 `Σ a[i]·b[j]·10^(n+m-2-i-j)`。而 `res[i+j+1]` 在最终结果里对应的位权是 `10^(n+m-1-(i+j+1)) = 10^(n+m-2-i-j)`，正好吻合。所以「按 i+j+1 累加」和「按位权展开」是同一件事，只是把「乘 10 的幂」换成了「放在数组的对应下标」。

**进位为什么正确**：从右往左做 `res[k-1] += res[k] // 10; res[k] %= 10`，这是标准的十进制进位，每一步都保持「低位已定型、高位待处理」的状态，最终每位都在 0~9 之间，且数值不变。

**前导零**：最高位 `res[0]` 在 n、m 都 ≥1 时最多是进位产生的 0 或 1，去掉前导 0 后若为空串说明乘积为 0，返回 `"0"`。

## 5. 完整代码（Python）

```python
class Solution:
    def multiply(self, num1: str, num2: str) -> str:
        # 特判：任一为 "0"，乘积必为 "0"
        if num1 == "0" or num2 == "0":
            return "0"

        n, m = len(num1), len(num2)
        # 结果数组长度 n+m，下标 i+j+1 对应 a[i]*b[j] 的落点
        res = [0] * (n + m)

        # 双重循环：逐位相乘并累加到对应下标
        for i in range(n - 1, -1, -1):          # 从个位往高位遍历 num1
            for j in range(m - 1, -1, -1):      # 从个位往高位遍历 num2
                mul = (ord(num1[i]) - ord('0')) * (ord(num2[j]) - ord('0'))
                # 注意：这里用 i+j+1 作为落点，是从「末尾对齐」推出来的
                res[i + j + 1] += mul

        # 从右往左统一处理进位
        for k in range(n + m - 1, 0, -1):
            res[k - 1] += res[k] // 10
            res[k] %= 10

        # 去掉前导零（res[0] 可能是 0）
        start = 0
        while start < n + m and res[start] == 0:
            start += 1
        # 理论上 start 不会越界（因为已特判 "0"），但保险起见
        if start == n + m:
            return "0"

        return "".join(str(d) for d in res[start:])
```

**关键逻辑说明**：

- `res[i+j+1]` 的由来：`a[i]` 的位权是 `10^(n-1-i)`，`b[j]` 是 `10^(m-1-j)`，乘积位权是 `10^(n+m-2-i-j)`。结果数组长度 n+m，下标 k 的位权是 `10^(n+m-1-k)`。令两者相等：`n+m-1-k = n+m-2-i-j` → `k = i+j+1`。
- 双重循环从后往前遍历，只是习惯上「从个位开始」，其实从前往后也对，因为累加与顺序无关。
- 进位循环 `range(n+m-1, 0, -1)` 不处理下标 0，因为下标 0 只可能接收进位，不会自己产生进位（最大 n+m 位数的乘积最多 n+m 位）。

## 6. 复杂度

**时间**：O(n·m)。

- 双重循环：n × m 次乘法 + 累加，每次 O(1)。
- 进位循环：n+m 次，每次 O(1)。
- 拼接字符串：O(n+m)。
- 总计 O(n·m + n + m) = O(n·m)。这里没有 log 因子，因为全程是整数加减乘，不涉及除法或快速幂。

**空间**：O(n+m)。

- `res` 数组长度 n+m，每个元素是整数。
- 返回的字符串长度 ≤ n+m。
- 没有递归栈、没有额外的大数组。

对比暴力字符串加法版：时间 O(m·(n+m))，空间 O(n+m)（每次加法产生临时字符串）。数组版在时间上省掉了「m 次字符串构造」的常数，且代码更短。

## 7. 边界与反例（至少 4 条）

1. **`num1="0", num2="0"` → `"0"`**
   容易错：不特判的话，res 全 0，去前导零后 `start` 走到末尾，`res[start:]` 为空串，返回 `""` 而不是 `"0"`。所以开头必须特判。

2. **`num1="9", num2="9"` → `"81"`**
   容易错：n=m=1，res 长度 2，`res[1] = 81`，进位后 `res[0]=8, res[1]=1`。如果进位循环写成 `range(n+m-1, -1, -1)` 会访问 `res[-1]`，Python 里是最后一个元素，逻辑就乱了。必须 `range(n+m-1, 0, -1)`。

3. **`num1="123", num2="1"` → `"123"`**
   容易错：m=1 时，`res[i+0+1] = res[i+1]`，累加后 `res[1..3]` 是 1、2、3，`res[0]=0`。去前导零时 `start=1`，返回 `"123"`。如果去零逻辑写成 `lstrip('0')` 且没处理全零，会得到 `"123"` 没问题，但全零场景会出错（见第 1 条）。

4. **`num1="999", num2="999"` → `"998001"`**
   容易错：这是「进位链」最长的场景之一。`res` 初始 `[0,81,162,243,162,81]`（下标 1~5），进位时 `res[5]=81` 进 8 给 `res[4]`，`res[4]=162+8=170` 进 17 给 `res[3]`……如果进位循环方向写反（从左往右），高位先定型、低位后进位，结果会错。必须从右往左。

5. **`num1="1", num2="0"` → `"0"`**
   容易错：特判 `num1=="0" or num2=="0"` 必须用 `or`，用 `and` 会漏掉「一个为 0」的情况，导致进入正常流程后 res 全 0，去零逻辑若写得不严谨会返回空串。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求支持负数（带符号的字符串）怎么办？**
   思路：先剥离符号位，记录 `sign = -1 if 两符号异或 else 1`，对绝对值部分调用本题逻辑，最后根据 sign 决定是否加 `"-"`。注意 `"-0"` 要归一成 `"0"`。

2. **追问：如果要求支持小数（如 `"1.23" × "4.5"`）？**
   思路：先数小数点后位数 `d1+d2`，去掉小数点变成整数串，调用本题逻辑得到整数积，再从右往左插入小数点（不足位补前导零），最后去掉末尾多余的 0。

3. **追问：能不能用 FFT 把复杂度降到 O(n log n)？**
   思路：大整数乘法可以用快速傅里叶变换把「卷积」加速，本题的 `res[i+j+1] += a[i]*b[j]` 本质就是卷积。但 n,m ≤ 200 时 FFT 的常数和实现复杂度远超收益，面试中只需说出「卷积视角 + FFT 可优化到 O(n log n)」即可，不必真写。
