## 1. 一句话本质

在所有「每个出现过的字符都至少出现 k 次」的连续子串里，找最长的那一个的长度。

关键词是**每个出现过的字符**——不是「所有字符都出现 k 次」，而是「子串里出现的字符，各自计数都 ≥ k」。这个措辞差别决定了后面所有推理的方向。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子串（O(n²) 个），对每个子串统计字符频次再检查（O(n)），总复杂度 O(n³)。n = 10⁴ 时是 10¹² 量级，直接死。

退一步，用前缀和或增量统计把「检查一个子串」降到 O(1) 摊还，枚举仍是 O(n²) = 10⁸，Python 里也过不去。所以瓶颈在**枚举子串的个数**本身，必须想办法不枚举全部。

**关键观察**：假设整个串里某个字符 `c` 总共只出现了 `m < k` 次。那么任何合法子串都**不可能包含 `c`**——因为一旦包含，`c` 在这个子串里的次数 ≤ m < k，直接违规。所以 `c` 出现的每个位置都是「一刀切下去」的分割点：合法子串只能落在被 `c` 切开的某一段里，绝不可能跨越它。

这一步把「在一个长串里找」变成了「在若干短串里分别找」，而且这些短串互不重叠、拼起来不超过原串。这就是**分治**的入口：用「全局频次不足 k 的字符」当刀，把问题切小，递归求解。

## 3. 从暴力到最优

### 第一步：分治的骨架

对当前区间 `[l, r)`：

1. 统计区间内每个字符的频次。
2. 找出所有频次在 `(0, k)` 之间的字符（即「出现了但不够 k 次」的）。
3. 如果没有这样的字符，整个区间就是合法的，返回 `r - l`。
4. 否则，用这些字符把区间切成若干段，对每段递归，取最大值。

**小例子走一遍**：`s = "ababbc"`, `k = 2`。

- 第一层，区间 `[0, 6)`，频次：a=2, b=3, c=1。`c` 的频次 1 < 2，是刀。`c` 在下标 5，切成 `[0, 5)` = `"ababb"` 和 `[6, 6)` = 空。
- 第二层，区间 `[0, 5)`，频次：a=2, b=3，全部 ≥ 2，无刀，返回长度 5。
- 空区间返回 0。最终 `max(5, 0) = 5`。✓

**这一步的瓶颈**：每层递归都要重新扫一遍区间统计频次。最坏情况是什么？考虑 `s = "abababab..."`，`k` 很大，每层只切掉一个字符，递归深度 O(n)，每层扫描 O(n)，总 O(n²)。n = 10⁴ 时 10⁸，Python 悬。

### 第二步：用「字符种类数」把分治换成滑动窗口

换个角度想：合法子串里**最多有 26 种字符**（题面限定小写字母）。如果我们**固定子串里恰好包含 `t` 种字符**，问题就变成一个标准的「窗口内计数」滑动窗口：

- 右指针扩张，维护窗口内频次和「频次 ≥ k 的字符种数 `cntOk`」。
- 当窗口内字符种数 `> t` 时，左指针收缩，直到种数回到 `t`。
- 当种数 `== t` 且 `cntOk == t` 时，整个窗口合法，更新答案。

外层枚举 `t = 1..26`，内层一趟 O(n) 滑动窗口。总 O(26n)。

**同一个例子走一遍**：`s = "ababbc"`, `k = 2`，取 `t = 2`。

| 步骤 | 窗口 | 频次 | 种数 | cntOk | 动作 |
|---|---|---|---|---|---|
| 右扩到 0 | `a` | a=1 | 1 | 0 | 种数<2，继续 |
| 右扩到 1 | `ab` | a=1,b=1 | 2 | 0 | 种数=2，cntOk≠2 |
| 右扩到 2 | `aba` | a=2,b=1 | 2 | 1 | cntOk≠2 |
| 右扩到 3 | `abab` | a=2,b=2 | 2 | 2 | **合法，长度 4** |
| 右扩到 4 | `ababb` | a=2,b=3 | 2 | 2 | **合法，长度 5** |
| 右扩到 5 | `ababbc` | a=2,b=3,c=1 | 3 | 2 | 种数>2，左收缩 |
| 左缩到 1 | `babbc` | a=1,b=3,c=1 | 3 | 1 | 仍>2，继续缩 |
| 左缩到 2 | `abbc` | a=1,b=2,c=1 | 3 | 1 | 仍>2，继续缩 |
| 左缩到 3 | `bbc` | b=2,c=1 | 2 | 1 | 种数=2，cntOk≠2 |
| 右指针到头 | — | — | — | — | 结束 |

`t = 2` 这轮得到 5。其他 `t` 不会更大。✓

**为什么固定 `t` 就单调了**：滑动窗口要求「右指针只进不退、左指针只进不退」时答案可维护。固定种数上限 `t` 后，「窗口种数 ≤ t」这个性质对扩张是单调的（扩了可能超，缩回来又满足），所以双指针合法。如果不固定 `t`，窗口种数可以无限涨，左指针的收缩条件就没有明确边界，滑窗失效。

## 4. 正确性：为什么不会漏、不会重

**分治版的不变量**：对任意区间 `[l, r)`，递归函数返回的是「该区间内满足条件的最长子串长度」。归纳假设子区间正确，则：任一合法子串若不跨过任何「频次不足 k 的字符」，它必完整落在某个切分段内（因为切分点就是这些字符的位置，合法子串不能含它们）；若它跨过，则它含有该字符，频次 < k，矛盾。所以最优解必在某个子段内，取 max 不漏。各子段互不重叠，不重。

**滑窗版的不变量**：外层固定 `t`，内层维护「窗口内字符种数 ≤ t」。对每个右端点 `right`，左指针停在「使种数 ≤ t 的最小左边界」附近。任何以 `right` 结尾、种数恰为 `t` 的合法子串，其左端点不可能比当前 `left` 更靠左（否则种数 > t），而当前窗口是满足约束的最大窗口，所以若存在合法解必被覆盖。外层枚举所有 `t ∈ [1, 26]`，任一合法子串的种数必是其中之一，故不漏。不同 `t` 的窗口对应不同种数，同一子串不会被两个 `t` 重复计入答案（即使重复计入，取 max 也不影响正确性）。

## 5. 完整代码（Python）

```python
class Solution:
    def longestSubstring(self, s: str, k: int) -> int:
        # 分治版：用「全局频次不足 k 的字符」当分割点
        def solve(l: int, r: int) -> int:
            if r - l < k:          # 长度都不够 k，不可能合法
                return 0
            freq = {}
            for i in range(l, r):  # 统计当前区间频次
                freq[s[i]] = freq.get(s[i], 0) + 1
            # 找一个频次不足 k 的字符当刀
            split_char = None
            for ch, cnt in freq.items():
                if cnt < k:
                    split_char = ch
                    break
            if split_char is None:  # 没有刀，整个区间合法
                return r - l
            # 用 split_char 把区间切成若干段，逐段递归
            res = 0
            start = l
            for i in range(l, r):
                if s[i] == split_char:
                    res = max(res, solve(start, i))
                    start = i + 1
            res = max(res, solve(start, r))  # 最后一段
            return res
        return solve(0, len(s))
```

```python
class Solution:
    def longestSubstring(self, s: str, k: int) -> int:
        # 滑窗版：外层枚举窗口内字符种数 t，内层标准滑窗
        n = len(s)
        ans = 0
        for t in range(1, 27):          # 最多 26 种小写字母
            freq = [0] * 26
            left = 0
            kinds = 0                   # 窗口内出现的字符种数
            cnt_ok = 0                  # 频次 >= k 的字符种数
            for right in range(n):
                idx = ord(s[right]) - ord('a')
                if freq[idx] == 0:
                    kinds += 1
                freq[idx] += 1
                if freq[idx] == k:      # 刚好达到 k，计入达标
                    cnt_ok += 1
                # 种数超过 t，左指针收缩
                while kinds > t:
                    li = ord(s[left]) - ord('a')
                    if freq[li] == k:   # 收缩前刚好是 k，收缩后不达标
                        cnt_ok -= 1
                    freq[li] -= 1
                    if freq[li] == 0:
                        kinds -= 1
                    left += 1
                # 种数恰为 t 且全部达标，整个窗口合法
                if kinds == t and cnt_ok == t:
                    ans = max(ans, right - left + 1)
        return ans
```

两版都可提交。分治版代码短、思路直观，是面试首选；滑窗版是 O(26n) 的严格线性，适合追问「能不能不用递归」。

## 6. 复杂度

**分治版**：

- 时间：最坏 O(n²)。每层递归扫描当前区间 O(区间长)，最坏情况（如 `"ababab..."` 且 k 很大）每层只切掉一个字符，递归深度 O(n)，总扫描量 n + (n-1) + ... = O(n²)。平均/常见情况接近 O(n log n)，因为切分点通常把区间对半分。
- 空间：O(n)，递归栈深度最坏 O(n)。

**滑窗版**：

- 时间：O(26n) = O(n)。外层 26 是常数（字母表大小），内层 `right` 走 n 步、`left` 总共也走 n 步，每步 O(1)。26 这个因子来自「枚举种数」，不是 log。
- 空间：O(26) = O(1)，两个长度 26 的数组。

面试里如果被问「n 为什么不是 log」，答：这里没有二分，26 是字符集大小，是常数因子。

## 7. 边界与反例

1. `s = "a", k = 2` → 期望 0。容易错：忘记「长度 < k 直接返回 0」的剪枝，或滑窗里 `kinds == t && cnt_ok == t` 判断漏了 `cnt_ok`，把长度 1 的窗口误判合法。
2. `s = "aaaa", k = 1` → 期望 4。容易错：`k = 1` 时任何字符都达标，`cnt_ok` 应在 `freq[idx] == k` 即 `== 1` 时加一，逻辑要覆盖 k=1 的边界。
3. `s = "ababacb", k = 3` → 期望 0。容易错：分治版里 `c` 频次 1、`b` 频次 2 都不足 3，切完后每段都短于 3，要保证递归基 `r - l < k` 返回 0 生效，否则可能返回某段长度。
4. `s = "aaabb", k = 3` → 期望 3。容易错：滑窗版若外层只枚举到 `t = 2`，会漏掉 `t = 1` 时 `"aaa"` 的解；必须枚举全 1..26。
5. `s = "bbaaacbd", k = 3` → 期望 3（`"aaa"`）。容易错：分治时 `b` 频次 3 达标、`c`/`d` 不足，切分后要正确处理 `"aaa"` 这段被 `b` 和 `c` 夹住的情况。

## 8. 面试追问与变体

1. **追问：不用递归，能不能 O(n) 且不枚举 26 次？** 思路：可以，但需要更复杂的「按字符种类数分层的滑窗」或「后缀自动机 + 频次约束」，面试中通常接受 26 次枚举作为最优解，追问时说明 26 是常数即可。
2. **追问：如果字符集不是小写字母而是任意 Unicode？** 思路：枚举种数改为枚举「实际出现的不同字符数」，上界变成 `len(set(s))`，复杂度 O(D·n)，D 为不同字符数，最坏退化。
3. **变体：求「每个字符出现次数恰好为 k」的最长子串。** 思路：滑窗不再用「≥ k 达标」，而是维护「== k 的种数」和「> k 的种数」，后者 > 0 即窗口非法需收缩，逻辑对称但条件更严。
