## 1. 一句话本质

在一个**已经有序**的单链表上，把「相邻且相等」的节点合并成一个，返回去重后的链表头。

关键词是「已经有序」——它保证了重复元素一定挨在一起，所以不需要哈希表记录「见过谁」，只需要盯着相邻两个节点看。

## 2. 读完题的第一反应

**朴素解法**：遍历链表，把每个节点的值塞进一个 `set`，遇到见过的值就删掉这个节点。

它卡在哪？卡在**空间**上：`set` 要 O(n) 额外空间，而且完全没用上题面给的「已排序」这个条件。面试官给你「已排序」不是装饰，是在暗示你：重复元素是**连续**的，你只需要比较 `cur` 和 `cur.next` 两个相邻节点就够了，不需要记住整条链上出现过什么。

**关键观察**：因为升序排列，如果 `cur.val == cur.next.val`，那么 `cur.next` 一定是 `cur` 的重复，直接把它摘掉即可；如果不等，说明 `cur` 这个值已经彻底处理完了（后面不可能再出现 `cur.val`，因为有序），可以安全地往前走一步。

这个观察直接消掉了 `set`，把空间从 O(n) 降到 O(1)。剩下唯一要小心的是**指针操作**：删节点时 `cur` 不能动，因为删完之后新的 `cur.next` 可能还是重复值。

## 3. 从暴力到最优

**暴力版**（用 set，仅作对照）：

```python
seen = set()
dummy = ListNode(0, head)
prev, cur = dummy, head
while cur:
    if cur.val in seen:
        prev.next = cur.next      # 摘掉 cur
    else:
        seen.add(cur.val)
        prev = cur
    cur = cur.next
return dummy.next
```

时间 O(n)，空间 O(n)。瓶颈就是那个 `seen`。

**最优版**：把 `seen` 换成「只看前一个节点」。因为有序，`cur` 是否重复，等价于 `cur.val == 前一个保留下来的节点的值`。而前一个保留下来的节点，恰好就是 `cur` 的前驱——在链表里我们天然就有它。

用示例 2 `[1,1,2,3,3]` 走一遍，只维护一个 `cur` 指针：

| 步骤 | cur.val | cur.next.val | 判断 | 动作 | 链表状态 |
|---|---|---|---|---|---|
| 初始 | 1 | 1 | 相等 | `cur.next = cur.next.next`，cur 不动 | 1→2→3→3 |
| 2 | 1 | 2 | 不等 | cur 前进 | 1→2→3→3 |
| 3 | 2 | 3 | 不等 | cur 前进 | 1→2→3→3 |
| 4 | 3 | 3 | 相等 | `cur.next = cur.next.next`（即 None），cur 不动 | 1→2→3 |
| 5 | 3 | None | `cur.next` 为空 | 循环结束 | 1→2→3 |

注意第 1 步和第 4 步：**删完之后 `cur` 原地不动**，因为新的 `cur.next` 可能还是同一个值（比如 `[1,1,1]` 要连删两次）。这是这道题最容易写错的地方——很多人下意识写 `cur = cur.next`，结果 `[1,1,1]` 会输出 `[1,1]`。

循环的终止条件用 `while cur and cur.next`：`cur` 为空说明链表空；`cur.next` 为空说明 cur 是最后一个节点，没有「下一个」可比，自然结束。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。设指针 `cur` 指向的节点为「当前锚点」，定义不变量：

> 进入每轮循环时：(a) `cur` 之前的所有节点（从头到 cur）已经两两不同；(b) `cur` 是它这个值在链表中**最后一次**出现的那个节点（即 `cur.next` 要么为空，要么值不等于 `cur.val`，或者尚未检查）。

**初始化**：`cur = head`，它之前没有节点，(a) 空真成立；(b) 因为还没检查，视为待验证。

**保持**：
- 若 `cur.val == cur.next.val`：`cur.next` 是重复节点，摘掉它。摘掉后 `cur` 之前的部分没变，(a) 仍成立；新的 `cur.next` 值可能还等于 `cur.val`，所以 (b) 仍处于「待验证」状态，下一轮继续检查——这保证了**不会漏**（连续多个重复会被逐个摘掉）。
- 若 `cur.val != cur.next.val`：由有序性，`cur.val` 之后不可能再出现（后面所有值都 ≥ `cur.next.val > cur.val`），所以 `cur` 确实是该值最后一次出现，(b) 成立；同时 `cur` 与前面所有节点都不同，(a) 扩展到包含 cur 也成立。此时 `cur` 前移，不变量在新位置重新成立。

**终止**：`cur.next` 为空时，`cur` 是尾节点，由 (b) 它是自己值的最后一次出现，由 (a) 它和前面都不同，所以整条链两两不同。**不会重**。

「不会重」的另一个角度：我们从不复制节点、只改 `next` 指针，原链表中每个值只保留第一次出现的那个节点实例，后续同值节点被物理摘除，所以结果里不可能出现两个相同值。

## 5. 完整代码（Python）

```python
class Solution:
    def deleteDuplicates(self, head: ListNode) -> ListNode:
        # 空链表或单节点链表：没有「相邻重复」可言，直接返回
        if not head or not head.next:
            return head

        cur = head
        # cur.next 存在才有比较对象；cur 本身不会为空（见下方注释）
        while cur and cur.next:
            if cur.val == cur.next.val:
                # 发现重复：跳过 cur.next，把它从链上摘掉
                # 注意 cur 不前进，因为新的 cur.next 可能还是同一个值
                cur.next = cur.next.next
            else:
                # 值不同：由有序性，cur 这个值已经处理干净，安全前移
                cur = cur.next

        return head
```

几个细节说明：

- 开头的 `if not head or not head.next` 是可选的优化，不写也能跑（循环条件会兜住），但写上能省掉单节点链表的无谓判断，也让「空链表返回 None」这件事更显式。
- `while cur and cur.next` 里的 `cur` 判断其实在进入循环后永远为真（`cur` 从 `head` 出发，只在 `cur.next` 非空时才前移），但保留它防御性更强，读起来也不费劲。
- 返回 `head` 而不是 `cur`：`head` 是原链表头，本题**头节点永远不会被删**（第一个节点没有前驱，且它不可能是「重复的后一个」），所以直接返回 `head` 正确。这点和 82 题（删除所有重复元素，头可能被删）不同，别混淆。

## 6. 复杂度

**时间 O(n)**：`n` 是节点数。`cur` 只前进不后退，每轮循环要么摘掉一个节点（`cur.next` 被跳过，总摘除次数 ≤ n-1），要么 `cur` 前移一步（总前移次数 ≤ n-1）。两种操作加起来不超过 2n 次，所以是线性的。这里没有 log 项——没有分治、没有二分，就是一趟扫描。

**空间 O(1)**：只用了 `cur` 一个指针变量，没有递归栈、没有额外容器。注意如果写成递归版（`head.next = self.deleteDuplicates(head.next)`），空间会变成 O(n) 的调用栈，面试时如果被问「能不能 O(1) 空间」，就要改成迭代。

## 7. 边界与反例（至少 4 条）

1. **空链表** `head = []` → 期望 `[]` → 容易错在没判空，`head.next` 直接抛 `AttributeError`。
2. **单节点** `head = [1]` → 期望 `[1]` → 容易错在循环条件写成 `while cur.next` 而没考虑 `cur` 本身可能为 None，或者误以为要删掉「唯一的自己」。
3. **全相同** `head = [1,1,1,1]` → 期望 `[1]` → 最容易错：删完第一个重复后如果 `cur = cur.next`，会漏删后面的，输出 `[1,1,1]` 或 `[1,1]`。正确做法是删完 `cur` 原地不动。
4. **无重复** `head = [1,2,3]` → 期望 `[1,2,3]` → 容易错在把「不等」分支也写成改指针，或者忘了 `cur` 前移导致死循环。
5. **重复在尾部** `head = [1,2,2]` → 期望 `[1,2]` → 容易错在循环条件只写 `while cur.next.next`，漏掉最后两个节点的比较。
6. **负数与跨零** `head = [-3,-3,0,0,0,5]` → 期望 `[-3,0,5]` → 值域含负数不影响逻辑，但提醒你别用「值 > 0」之类的假设做剪枝。

## 8. 面试追问与变体（3 条）

1. **追问：如果链表没有排序呢？**
   思路：有序性没了，「相邻比较」失效，必须用哈希集合记录见过的值，时间 O(n)、空间 O(n)；或者先排序再套本题（但链表排序本身是 O(n log n)）。

2. **追问：改成「删除所有重复的元素，一个都不留」（即 82 题）？**
   思路：需要 `dummy` 哨兵节点 + `prev` 指针，因为头节点也可能被删；判断 `prev.next.val == prev.next.next.val` 时连续跳过所有同值节点，`prev` 不前移。

3. **追问：要求原地去重且不能改 `val`，只能改指针——本题已经满足，那如果要求「保留最后一个重复」而不是第一个呢？**
   思路：把比较方向反过来，从尾部往前不好做（单链表），可以改成先反转、去重、再反转，或者用递归从后往前处理，本质是「保留哪一侧」的指针方向选择问题。

## 9. 举一反三（2-3 道同类题）

- **26. 删除有序数组中的重复项**：完全同构的「有序 + 原地去重」，只是把 `next` 指针换成了数组的写指针 `slow`，双指针思想一致。
- **203. 移除链表元素**：链表删除节点的通用模板（哨兵 + 前驱指针），本题是它的特例——「要删的节点」由「与前驱同值」动态决定，而不是给定目标值。
