## 1. 一句话本质

在一个用数组表示的十进制数上，模拟「加 1」这个动作，并把进位一路传播到它该停下的位置。

## 2. 读完题的第一反应

**朴素解法**：把数组转成一个整数，加 1，再转回数组。比如 `[1,2,3]` → `123` → `124` → `[1,2,4]`。

它卡在哪？题面给了 `digits.length <= 100`。100 位的十进制数，Python 的 `int` 能扛住，但换到 Java/C++ 就溢出了。更重要的是，这个「转成整数」的步骤本身就是 O(n) 位数的乘加运算，而且它绕开了这道题真正想考的东西——**进位**。面试官出这道题，不是想看你调 `int()`，是想看你处理进位。

**关键观察**：加 1 只影响数组的**末尾**。从最低位开始，如果这一位是 9，加 1 后变 0 并向高位进 1；如果这一位不是 9，加 1 后直接结束，高位全部不动。

为什么这个观察能让你想到下一步？因为它把「整个数组都要重算」压缩成了「从右往左扫，遇到第一个非 9 就停」。最坏情况（全是 9）才扫满整个数组，平均情况往往一步就结束。

## 3. 从暴力到最优

**暴力**：`int(''.join(map(str, digits))) + 1`，再拆回数组。瓶颈是「构造大整数」这一步，它把数组的每一位都参与了一次运算，而且依赖语言的大数支持。

**优化**：直接在数组上模拟进位。用例子 `[1,9,9]` 走一遍：

- 初始 `digits = [1,9,9]`，从 `i = 2` 开始。
- `i = 2`：`digits[2] == 9`，置 0，`digits = [1,9,0]`，继续往左。
- `i = 1`：`digits[1] == 9`，置 0，`digits = [1,0,0]`，继续往左。
- `i = 0`：`digits[0] == 1 != 9`，加 1 变 2，`digits = [2,0,0]`，**停止**，返回。

再看 `[9,9,9]`：

- `i = 2`：9 → 0，`[9,9,0]`
- `i = 1`：9 → 0，`[9,0,0]`
- `i = 0`：9 → 0，`[0,0,0]`
- 循环结束，所有位都是 9，说明发生了「最高位进位」，需要在最前面插一个 1：`[1,0,0,0]`。

瓶颈怎么被消掉的：暴力法每一位都要参与「构造整数」和「拆回数组」两次运算；优化后每一位最多被访问一次，且一旦遇到非 9 就提前退出。**只有全 9 的情况才需要 O(n)，其余情况平均 O(1)**。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

设原始数组为 `d[0..n-1]`，我们从 `i = n-1` 往左扫。维护不变量：

> 在处理第 `i` 位之前，`d[i+1..n-1]` 已经全部变成 0，且「加 1 产生的进位」恰好是 1，需要加到 `d[i]` 上。

**初始**：`i = n-1`，右侧为空，进位为 1（因为要加的就是 1），不变量成立。

**保持**：若 `d[i] == 9`，9 + 1 = 10，本位写 0，进位仍为 1 传给 `i-1`，不变量对 `i-1` 成立。若 `d[i] != 9`，`d[i] + 1 <= 9`，不会产生新进位，本位加 1 后停止，此时右侧全是 0、本位已更新，结果正确。

**终止**：要么在某个 `i` 处停下（此时 `d[0..i]` 未被改动，`d[i]` 已加 1，`d[i+1..]` 全 0，正好是正确结果）；要么扫到 `i < 0`，说明每一位都是 9，原数是 `99...9`，加 1 得 `100...0`，长度多一位，在最前面插 1 即可。

**不会漏**：每一位要么被「置 0 并继续」，要么被「加 1 并停止」，没有第三种情况，所有位都被正确处理。
**不会重**：每个下标只被访问一次，循环单向递减，不存在重复处理。

## 5. 完整代码（Python）

```python
class Solution:
    def plusOne(self, digits):
        # 从最低位（数组末尾）开始向高位扫描
        for i in range(len(digits) - 1, -1, -1):
            if digits[i] < 9:
                # 这一位不是 9，加 1 后不会产生进位，直接结束
                digits[i] += 1
                return digits
            # 这一位是 9，加 1 变 0，进位继续往左传
            digits[i] = 0
        # 循环走完说明原数全是 9（如 999），加 1 后长度多一位
        # 此时 digits 已全为 0，在最前面插入 1
        return [1] + digits
```

关键逻辑说明：
- `range(len(digits) - 1, -1, -1)` 保证从右往左，符合「最低位先受加 1 影响」的物理顺序。
- `digits[i] < 9` 是提前退出的条件，也是平均 O(1) 的来源。
- 循环外 `return [1] + digits` 处理全 9 的进位溢出，这是唯一会让数组变长的情况。

## 6. 复杂度

**时间**：O(n)，n = `len(digits)`。来源是「最坏情况下每一位都被访问一次」，即全 9 的输入。平均情况是 O(1)，因为随机输入下末尾连续 9 的期望长度是常数（约 1/9 + 1/81 + … ≈ 1/8）。这里没有 log n 的项——没有二分、没有按位分解，纯粹是一次线性扫描。

**空间**：O(1) 额外空间（不计返回值）。原地修改 `digits`，只有全 9 时 `[1] + digits` 会新建一个长度 n+1 的列表，但那属于返回值本身，不算额外辅助空间。若严格按「返回值不计入空间」的惯例，空间是 O(1)。

## 7. 边界与反例（至少 4 条）

1. **输入 `[9]` → 期望 `[1,0]`** → 容易错在：循环里把 9 置 0 后直接返回 `[0]`，忘了最高位进位要补 1。
2. **输入 `[0]` → 期望 `[1]`** → 容易错在：误以为「不含前导 0」意味着 0 不合法，或者对 0 做了特殊判断。题面只说「不含前导 0」，单个 0 是合法的。
3. **输入 `[9,9,9]` → 期望 `[1,0,0,0]`** → 容易错在：只处理了「某一位不是 9」的分支，没处理「全部是 9」导致数组长度增加的情况。
4. **输入 `[1,9,9]` → 期望 `[2,0,0]`** → 容易错在：进位传播到中间某位就停了，但代码写成「遇到 9 就置 0 并 `break`」，导致高位没加 1。
5. **输入 `[8,9]` → 期望 `[9,0]`** → 容易错在：把「非 9 就加 1」写成「非 9 就置 1」，忽略了本位原本的值。

## 8. 面试追问与变体（3 条）

1. **追问：如果加的不是 1，而是任意整数 k（0 ≤ k ≤ 9），怎么改？**
   思路：把「进位」从固定的 1 改成变量 `carry = k`，循环条件改成 `while i >= 0 and carry > 0`，每位算 `s = digits[i] + carry`，`digits[i] = s % 10`，`carry = s // 10`，最后若 `carry` 还有剩就在前面补位。

2. **追问：如果两个这样的大整数数组相加（LeetCode 415 的数组版），怎么做？**
   思路：双指针从两个数组末尾对齐往左扫，逐位相加并维护进位，短的数组缺位补 0，最后处理最高位进位。

3. **追问：如果要求不能修改原数组，怎么办？**
   思路：先复制一份 `res = digits[:]`，在副本上做同样的进位逻辑；或者从右往左找到第一个非 9 的位置 `p`，构造结果：`digits[:p] + [digits[p]+1] + [0]*(n-1-p)`，全 9 时返回 `[1] + [0]*n`。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 67. 二进制求和**：同样是「从低位往高位逐位处理 + 进位传播」，只是进制从 10 变成 2，进位条件从「== 9」变成「== 1」。
2. **LeetCode 415. 字符串相加**：把数组换成字符串，核心仍是双指针 + 进位变量，和本题的进位逻辑同构。
3. **LeetCode 2. 两数相加（链表版）**：进位传播的载体从数组变成链表，但「逐位相加、维护 carry、最后补最高位」的骨架完全一致。
