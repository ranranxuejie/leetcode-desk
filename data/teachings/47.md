## 1. 一句话本质

在「元素可重复」的数组上枚举所有**按位置区分、按值去重**的排列，即把「相同值互换位置」产生的重复解压成一份。

## 2. 读完题的第一反应

**朴素解法**：直接套 46 题（无重复全排列）的交换回溯，`for i in range(start, n): swap; dfs; swap back`。它卡在：`[1,1,2]` 里两个 `1` 交换后数组长得一模一样，于是 `[1,1,2]` 会被输出两次、`[1,2,1]` 两次……答案规模被放大到「带重复计数的 n!」，而题目要的是去重后的规模。更糟的是，如果最后用 `set(tuple(...))` 去重，虽然能过，但**搜索树本身没剪**，重复分支照跑，复杂度仍是指数级的浪费。

**关键观察**：重复解只可能来自「值相同的两个元素被安排到了不同位置顺序」。所以只要在**同一层递归**里，对「相同值」只允许选一次，重复分支就整棵被砍掉。而「相同值」要能相邻比较，前提是数组**有序**——这就是为什么标签里有「排序」。排序不是为了输出好看，是为了让「重复」在数组里物理相邻，从而能用 `nums[i] == nums[i-1]` 一句话判定。

## 3. 从暴力到最优

**第 0 步：暴力交换法**。以 `nums = [1,1,2]` 为例，第一层 `start=0`，`i` 取 0、1、2：
- `i=0`：选第一个 `1`，往下得到 `[1,1,2]`、`[1,2,1]`
- `i=1`：选第二个 `1`，往下又得到 `[1,1,2]`、`[1,2,1]` ← 与上面完全重复
- `i=2`：选 `2`，得到 `[2,1,1]`

共 6 个结果，去重后 3 个。瓶颈：**同一层选了值相同的两个元素**。

**第 1 步：排序 + 同层去重**。先 `nums.sort()` 得 `[1,1,2]`。改用「used 数组 + 按顺序挑元素」的回溯，每层从左到右扫，跳过已用的。加一条剪枝：

```
if i > 0 and nums[i] == nums[i-1] and not used[i-1]:
    continue
```

走一遍 `[1,1,2]`（下标 0、1、2）：

- 第一层 `i=0`：`used=[T,F,F]`，path=`[1]`
  - 第二层 `i=1`：`nums[1]==nums[0]` 但 `used[0]=True`，**不跳过**，path=`[1,1]`
    - 第三层只能选 `2` → 得 `[1,1,2]` ✅
  - 第二层 `i=2`：path=`[1,2]` → 第三层选下标 1 → `[1,2,1]` ✅
- 第一层 `i=1`：`nums[1]==nums[0]` 且 `used[0]=False` → **跳过**（这正是砍掉的那棵重复子树）
- 第一层 `i=2`：path=`[2]` → 再选下标 0 → `[2,1]` → 再选下标 1 → `[2,1,1]` ✅

结果恰好 3 个，无重复。瓶颈从「n! 个叶子再去重」降到「去重后的叶子数 × 每层 O(n) 扫描」。

**第 2 步（可选优化）**：把「used 数组」换成「计数表 `Counter`」，每层遍历**不同的值**而非每个下标，天然不产生重复分支，且不用排序。面试写 used 版本更稳，因为剪枝条件能讲清楚；计数版作为加分项提一句即可。

## 4. 正确性：为什么不会漏、不会重

**不漏**：任意一个合法排列，都能按「从左到右依次选元素」的方式被构造出来——第 k 位选哪个下标是确定的，只要该下标未被用过。我们的递归正是枚举「所有未被使用的下标」，剪枝只跳过「值与前一个相同且前一个还没被用」的下标。对被跳过的下标 i，存在同值的 i-1 未被使用，说明「用 i 打头」和「用 i-1 打头」在剩余集合上完全等价，因此跳过 i 不会丢失任何**值序列**。故不漏。

**不重**：设两个不同分支产生了同一个值序列。它们第一次分叉的位置是某层选了不同下标 i < j，且 `nums[i] == nums[j]`（否则值序列不同）。由于同层扫描是从左到右，选 j 时 i 必然「未被使用」（i 没被选进 path），于是剪枝条件 `nums[j]==nums[i] and not used[i]` 成立，j 分支会被跳过。矛盾。故同一值序列只由唯一一条「尽量选最左同值下标」的路径产生，不重。

**不变量**：递归进入某层时，`path` 是某个前缀，`used` 标记已用下标；剪枝保证「同值下标中，只有最左边那个未使用的可以被选」。这个不变量在每层都成立，归纳即得正确性。

## 5. 完整代码（Python）

```python
from typing import List

class Solution:
    def permuteUnique(self, nums: List[int]) -> List[List[int]]:
        nums.sort()                 # 排序：让相同值物理相邻，剪枝才能用 nums[i]==nums[i-1] 判断
        n = len(nums)
        res = []
        path = []
        used = [False] * n          # used[i] 表示下标 i 是否已进入 path

        def dfs():
            if len(path) == n:      # 凑满 n 个，得到一个完整排列
                res.append(path[:]) # 必须拷贝，path 后续会被修改
                return
            for i in range(n):
                if used[i]:
                    continue    # 下标已被用，跳过
                # 核心剪枝：同层中，若前一个同值元素还没被用，说明「以它为头」的分支已经走过，
                # 当前这个同值元素再打头只会产生重复排列
                if i > 0 and nums[i] == nums[i - 1] and not used[i - 1]:
                    continue
                used[i] = True
                path.append(nums[i])
                dfs()
                path.pop()          # 回溯：撤销选择
                used[i] = False

        dfs()
        return res
```

## 6. 复杂度

设去重后的排列数为 `P`（最坏 `n!`，全相同值时 `P=1`），`n = len(nums)`。

- **时间**：`O(n · P + n log n)`。排序 `O(n log n)`；搜索树有 `P` 个叶子，每个叶子拷贝 `path` 花 `O(n)`，共 `O(n·P)`；每个内部节点扫描 `n` 个下标，但内部节点总数与叶子同阶（每个内部节点至少有一个孩子），故扫描开销 `O(n·P)` 被吸收。注意 `P` 本身可能远小于 `n!`，这正是剪枝的收益。
- **空间**：`O(n)` 递归栈 + `O(n)` 的 `path` 和 `used`，即 `O(n)`；若计入返回结果，则 `O(n·P)`。`log n` 只来自排序的比较次数，不进空间。

## 7. 边界与反例（至少 4 条）

1. `nums = [1]` → `[[1]]`。容易错：忘记 `n=1` 时 `i>0` 恒假，剪枝不触发，正常返回；但若把剪枝写成 `nums[i]==nums[i-1]` 而不判 `i>0`，会下标越界。
2. `nums = [1,1,1]` → `[[1,1,1]]`。容易错：以为会输出 6 个；实际第一层只有 `i=0` 能过剪枝，其余全跳过，只 1 个解。
3. `nums = [1,1,2,2]` → 6 个解（`4!/(2!2!)`）。容易错：只对第一层去重、忘了每层都要去重，会得到 24 个。
4. `nums = [-1,-1,2]` → `[[-1,-1,2],[-1,2,-1],[2,-1,-1]]`。容易错：负数排序后相邻判断仍成立，但若用「值做字典键去重」而忘了负数也合法，逻辑上没问题；真正的坑是**没排序**就判 `nums[i]==nums[i-1]`，`[-1,2,-1]` 里两个 `-1` 不相邻，剪枝失效。
5. `nums = [2,1,1]`（未排序输入）→ 期望同 `[1,1,2]` 的 3 个解。容易错：不排序直接跑，两个 `1` 不相邻，剪枝条件永远不成立，退化成暴力。

## 8. 面试追问与变体（3 条）

1. **追问：不用 used 数组，用计数表怎么做？** 思路：`Counter(nums)` 记录每个值的剩余次数，每层遍历「不同的值」，选一个就把计数减一、递归、再加回；天然无重复分支，也省掉排序。
2. **追问：如果要求按字典序输出，代码要改吗？** 思路：排序后按「从左到右选未用下标」的 DFS 本身就是字典序，无需改动；若用计数表，需保证遍历键时有序。
3. **追问：把「全排列」换成「全组合（子集）」且含重复，怎么改？** 思路：同一题的去重剪枝思想平移——排序后 `if i>start and nums[i]==nums[i-1]: continue`，且每个节点都收集结果而非只在叶子收集。

## 9. 举一反三（2-3 道同类题）

- **46. 全排列**：本题去掉重复元素后的版本，剪枝条件整个删掉即可，是理解 used 回溯的起点。
- **90. 子集 II**：同样「排序 + 同层同值跳过」，只是收集时机从叶子变成每个节点。
- **40. 组合总和 II**：同样靠排序让重复相邻，用 `i>start and nums[i]==nums[i-1]` 剪掉同层重复，区别是带目标和剪枝。
