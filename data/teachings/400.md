## 1. 一句话本质

在按位数分层的数字序列里，先定位第 n 位落在哪一层（几位数），再定位到具体哪个数、这个数的第几位。

## 2. 读完题的第一反应

**朴素解法**：从 1 开始，把每个整数转成字符串拼起来，数到第 n 个字符。或者更直接：维护一个计数器，逐个数字逐位消耗 n。

卡在哪？n 最大到 2^31 - 1 ≈ 2.1×10^9。序列里第 21 亿位数字，对应到的整数大约在 10^8 量级（因为 9 位数之前总位数已经到 8.9×10^8，9 位数区间每个数贡献 9 位，很快就能到 21 亿）。逐个数字走，循环次数是 O(n / 平均位数) ≈ 10^8 级别，Python 里绝对超时。瓶颈在于「一个一个数」这个动作本身。

**关键观察**：序列是按「位数」天然分层的。1 位数有 9 个（1~9），共 9 位；2 位数有 90 个（10~99），共 180 位；3 位数有 900 个，共 2700 位……第 d 层（d 位数）有 9×10^(d-1) 个数，贡献 9×10^(d-1)×d 位。每一层的总位数是确定的、可以 O(1) 算出来的。

这个观察为什么能让你想到下一步？因为「每层总量已知」意味着你可以**整层整层地跳过**：拿 n 去减每层的位数，减到不够减为止，就知道目标落在哪一层。层数最多到 10（因为 2^31 量级只到 10 位数），所以这个「减」的过程是 O(log n) 的。定位到层之后，层内每个数位数相同，用除法就能直接算出是第几个数、这个数的第几位——不需要再逐个走。

## 3. 从暴力到最优

**暴力**：`s = ''.join(str(i) for i in range(1, ...))`，然后取 `s[n-1]`。瓶颈：要生成约 10^8 个数的字符串，内存和时间都爆。

**第一步优化**：不拼字符串，改成逐层扣减。这是本题的核心跳跃。

**第二步优化**：层内用整除直接定位，不再遍历。

用一个具体例子走一遍，取 n = 11（示例 2）：

- 初始 `n = 11`，`digit = 1`（当前层是 1 位数）。
- 第 1 层：1 位数共 9 个，贡献 `9 * 1 = 9` 位。`n = 11 > 9`，说明不在这一层。`n -= 9` → `n = 2`，`digit = 2`。
- 第 2 层：2 位数共 90 个，贡献 `90 * 2 = 180` 位。`n = 2 <= 180`，停。目标在 2 位数层，且是这一层的第 2 位。
- 层内定位：2 位数从 10 开始。第 2 位落在第几个数？`(n - 1) // digit = (2 - 1) // 2 = 0`，即偏移 0 个数，目标数是 `10 + 0 = 10`。
- 是这个数的第几位？`(n - 1) % digit = (2 - 1) % 2 = 1`，即下标 1（0-based），也就是 `'10'[1] = '0'`。
- 返回 0。和示例一致。

再走一个 n = 3 的：`n = 3 <= 9`，直接在第 1 层。`(3-1)//1 = 2`，数 = `1 + 2 = 3`；`(3-1)%1 = 0`，取 `'3'[0] = '3'`。返回 3。对。

注意 `(n - 1)` 这个减一是关键：n 是 1-based 的「第几位」，而整除和取模要转成 0-based 才好算偏移。不减一的话，n = 2 会算成 `2//2 = 1`，偏移到 11，错位。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

设当前状态为 `(n, digit)`，含义是：**目标位是「所有 digit 位数按升序排列后拼接成的串」中的第 n 位**（1-based）。

- **初始不变量**：digit = 1 时，「所有 1 位数拼接」就是原序列的开头部分，n 就是题目给的 n，成立。
- **保持**：若 `n > 9 * 10^(digit-1) * digit`（即当前层总位数），说明目标不在当前层，必然在更后面的层。把当前层整层扣掉，`n -= 层总位数`，`digit += 1`。因为序列是「先所有 digit 位数、再所有 digit+1 位数」严格分段拼接的，扣掉前一段后，目标在新串中的位置恰好是 `n - 层总位数`，不变量保持。
- **终止**：`n <= 层总位数` 时，目标确定在当前层。层内第 k 个 digit 位数（k 从 0 计）是 `10^(digit-1) + k`，它占据层内位置 `[k*digit + 1, (k+1)*digit]`。由 `k = (n-1) // digit` 和 `r = (n-1) % digit`，有 `k*digit + r + 1 = n`，即第 n 位正好是第 k 个数的第 r 位（0-based）。唯一确定。

**不漏**：每层总位数是精确的 `9 * 10^(digit-1) * digit`，扣减是精确的，不会跳过任何一位。
**不重**：每层只被扣减一次，digit 单调递增，层与层之间不重叠（位数不同，数字集合不相交）。层内 `(n-1)//digit` 和 `(n-1)%digit` 是带余除法的唯一分解，一个 n 只对应一个 (k, r)。

## 5. 完整代码（Python）

```python
class Solution:
    def findNthDigit(self, n: int) -> int:
        # digit: 当前考察的位数（1 表示 1 位数层，2 表示 2 位数层...）
        digit = 1
        # 当前层的起始数字：1 位数从 1 开始，2 位数从 10 开始，3 位数从 100 开始
        start = 1
        # 当前层数字的个数：1 位数 9 个，2 位数 90 个，3 位数 900 个...
        count = 9

        # 整层整层地跳过，直到 n 落在当前层内
        while n > count * digit:
            n -= count * digit      # 扣掉当前层贡献的总位数
            digit += 1              # 进入下一层
            start *= 10             # 下一层起始数字 ×10
            count *= 10             # 下一层数字个数 ×10

        # 此时 n 是当前层内的第 n 位（1-based）
        # 转成 0-based 偏移，算出落在第几个数上
        index = (n - 1) // digit    # 层内第几个数（0-based）
        num = start + index         # 具体的那个整数
        # 是这个数的第几位（0-based，从左往右）
        pos = (n - 1) % digit
        # 转成字符串取该位，再转回整数
        return int(str(num)[pos])
```

## 6. 复杂度

**时间**：O(log n)。循环每轮 digit 加一，digit 的上界是 n 的十进制位数，即约 log10(n)。n ≤ 2^31-1 时 digit ≤ 10，循环最多 10 次。循环体内是常数运算。最后的 `str(num)` 长度是 digit，也是 O(log n)。所以总时间 O(log n)。

**空间**：O(log n)，来自 `str(num)` 生成的字符串，长度等于 digit = O(log n)。若不计字符串，额外空间 O(1)。

注意：这里**没有** O(n) 的项——因为没有任何一步是「按 n 的大小循环」的，循环次数只跟位数（log n）有关，这是本题从暴力到最优的核心收益。

## 7. 边界与反例（至少 4 条）

1. **n = 1** → 期望 1。容易错在 `(n-1)//digit` 写成 `n//digit`，会偏移到 2；或者循环条件写成 `n >= count*digit`，导致 n=9 时错误进入下一层。
2. **n = 9** → 期望 9。这是 1 位数层的最后一位。若循环条件用 `>=`，n=9 会被误判为「不在本层」，扣成 0 进入 2 位数层，越界或算错。必须是严格 `>`。
3. **n = 10** → 期望 1（是 10 的第一位）。这是跨层边界：n=10 时 1 位数层只有 9 位，扣完剩 n=1 进入 2 位数层，`(1-1)//2=0`，数=10，`pos=0`，取 '1'。容易错在忘记扣减后 n 变成 1 而不是 10。
4. **n = 11** → 期望 0（示例 2）。验证层内取模：`(2-1)%2=1`，取 '10'[1]='0'。容易错在 pos 用了 1-based，取到 '1'。
5. **n = 2^31 - 1 = 2147483647** → 期望某个 10 位数中的一位。容易错在 `count * digit` 用 int 溢出（Python 不会，但 C++/Java 要注意用 long），以及层数算到 10 时 start=10^9 是否还在 int 范围。

## 8. 面试追问与变体（3 条）

1. **追问：如果序列不是从 1 开始，而是从 0 开始（0,1,2,...），怎么改？** 思路：0 占 1 位，把 n 减 1 后按原逻辑处理，或单独处理 n=1 返回 0，其余 n-1 走原流程。
2. **追问：反过来，给定一个数字 x，求它在序列中的起始位置（第几位）？** 思路：累加所有位数小于 x 的层的总位数，再加上 x 在本层内的偏移 `(x - start) * digit + 1`，是本题的逆运算。
3. **追问：n 大到 10^18，还能用这方法吗？** 思路：可以，循环次数变成约 18 次，仍是 O(log n)；但要注意语言层面的整数溢出，Python 无此问题。

- **LeetCode 233. 数字 1 的个数**：同样按「位数分层、逐层统计」的思路，统计 1 出现的次数，共同点是利用十进制位数的结构性规律避免逐个枚举。
- **LeetCode 172. 阶乘后的零**：虽然场景不同，但共同点是「按因子/位数分层计数」而非暴力累乘，都是把 O(n) 的枚举压缩成 O(log n) 的数学计数。
