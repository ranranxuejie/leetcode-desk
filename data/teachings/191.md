## 1. 一句话本质

数一个整数在二进制下有多少个 `1`——但真正的考点是：**你能不能不去看那些本来就是 `0` 的位**。

## 2. 读完题的第一反应

最朴素的做法：把 n 转成二进制字符串，数 `'1'` 的个数；或者循环 32 次，每次看最低位是不是 1，然后右移一位。

这两种写法都能过，但它们的共同问题是：**它们把 32 个位全都检查了一遍，不管里面有几个 1**。n = 1 的时候你检查 32 次，n = 2^31 - 1 的时候你也检查 32 次。复杂度是 O(32)，也就是 O(位数)，跟 1 的个数无关。

关键观察来自一个很小的事实：**`n & (n - 1)` 会把 n 最低位的那个 1 变成 0，其余位不动**。

为什么？看 n 的最低位 1 的位置，设为第 k 位。n - 1 会把第 k 位借位变成 0，同时把第 k 位以下全变成 1；第 k 位以上不变。于是 n 和 n-1 在第 k 位以上完全相同，在第 k 位一个 1 一个 0，相与之后第 k 位归零，其余位保持 n 原样。**每做一次，1 的个数就少一个**。

这个观察的价值在于：它把「遍历所有位」变成了「遍历所有 1」。如果 n 只有 1 个 1，你只循环 1 次就结束。这就是从 O(位数) 到 O(1 的个数) 的跃迁。

## 3. 从暴力到最优

**第一步：暴力逐位检查。**

```python
count = 0
while n:
    count += n & 1   # 看最低位
    n >>= 1          # 右移
```

以 n = 11（二进制 `1011`）为例，走一遍：

| 轮次 | n（十进制） | n 的二进制 | n & 1 | count |
|---|---|---|---|---|
| 1 | 11 | 1011 | 1 | 1 |
| 2 | 5 | 101 | 1 | 2 |
| 3 | 2 | 10 | 0 | 2 |
| 4 | 1 | 1 | 1 | 3 |
| 5 | 0 | 0 | — | 循环结束 |

得到 3，正确。瓶颈：循环次数 = 最高位 1 的位置，n = 2^31 - 1 时要转 31 次，其中大量轮次 `n & 1` 都是 0，纯属白跑。

**第二步：用 `n & (n-1)` 消掉最低位的 1。**

还是 n = 11（`1011`）：

| 轮次 | n 的二进制 | n-1 的二进制 | n & (n-1) | count |
|---|---|---|---|---|
| 1 | 1011 | 1010 | 1010 | 1 |
| 2 | 1010 | 1001 | 1000 | 2 |
| 3 | 1000 | 0111 | 0000 | 3 |

三轮之后 n 变成 0，循环结束，count = 3。对比第一步：第一步跑了 4 轮（到 n=1 还要再跑一轮），第二步只跑 3 轮——**轮数恰好等于 1 的个数**。对 n = 128（`10000000`），第一步要右移 8 次，第二步只跑 1 次就结束。差距随「稀疏程度」放大。

这就是最终解法：`while n: n &= n - 1; count += 1`。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**说清楚。设 `count` 是已消除的 1 的个数，`n` 是当前剩余的数。不变量是：

> **`count + popcount(n) == popcount(原始输入)`**，其中 popcount 表示二进制中 1 的个数。

- **初始化**：进入循环前 count = 0，n = 原始输入，不变量成立。
- **保持**：每轮执行 `n = n & (n-1)`。由第 2 节的分析，这个操作**恰好把 n 中最低位的 1 变成 0，其他位不变**，所以 `popcount(n_new) == popcount(n_old) - 1`。同时 count 加 1，两边抵消，不变量继续成立。
- **终止**：循环条件是 `n != 0`，退出时 n = 0，`popcount(0) = 0`，于是 `count == popcount(原始输入)`。

**不会漏**：每轮只消掉一个 1，且消的是「当前最低位的 1」，只要还有 1 循环就不停，所以每个 1 都被数到。
**不会重**：被消掉的位变成 0 后，后续的 `n & (n-1)` 不可能再把它变回 1（与运算只会清位、不会置位），所以同一个 1 不会被数两次。

注意这里**没有用到位宽假设**——不变量对任意非负整数成立，所以即使 n 超出 32 位也照样正确。这是这个解法比「循环 32 次」更干净的地方。

## 5. 完整代码（Python）

```python
class Solution:
    def hammingWeight(self, n: int) -> int:
        count = 0
        # 循环不变量：count + popcount(n) == popcount(原始输入)
        while n:
            # n & (n - 1) 恰好清掉 n 最低位的那个 1，其余位不变
            n &= n - 1
            count += 1
        return count
```

如果面试官追问「多次调用怎么优化」，可以补一个查表版本（见第 8 节），但主解就是上面这 5 行。

## 6. 复杂度

**时间：O(k)，k 是 n 的二进制中 1 的个数。**
- 循环每轮消掉一个 1，所以循环次数 = k，这是「谁贡献了 k」。
- 每轮内部是常数次位运算（与、减、加），O(1)。
- 最坏情况 k = 31（n = 2^31 - 1），所以最坏 O(31) = O(log n)，因为 32 位整数最多 log₂n + 1 个位。**注意这里的 log n 是「位数」，不是「1 的个数」**——平均情况下 k 远小于位数，这正是本解法的优势。

**空间：O(1)。**
- 只用了 `count` 和循环中的临时值，与 n 的大小无关。

对比暴力逐位法：时间 O(log n)（固定 32 轮），空间 O(1)。两者最坏复杂度同阶，但本解法在稀疏输入上快一个数量级。

## 7. 边界与反例（至少 4 条）

1. **n = 1** → 期望 1 → 容易错在：如果写成 `while n > 1`，会漏掉最后一个 1；必须用 `while n`（即 `n != 0`）。
2. **n = 2^31 - 1 = 2147483647** → 期望 31 → 容易错在：如果循环写成固定 32 次并假设最高位是符号位，可能少数一位；本解法不受位宽影响，天然正确。
3. **n = 2147483645**（示例 3，二进制 `...1111101`）→ 期望 30 → 容易错在：这是「几乎全 1」的输入，本解法要跑 30 轮，和暴力法差不多——**说明本解法不是万能的，它优化的是稀疏输入**，面试时要能说清这个前提。
4. **n = 2 的幂（如 128）** → 期望 1 → 容易错在：如果误以为 `n & (n-1)` 会清掉多个 1，或者循环条件写成 `while n > 1`，会得到 0 或死循环。
5. **n = 0**（虽然题面限制 n ≥ 1，但作为函数健壮性）→ 期望 0 → 容易错在：`while n` 直接不进循环，返回 0，正确；但如果用 `n & (n-1)` 前没判空，某些语言会出问题，Python 无碍。

## 8. 面试追问与变体（3 条）

1. **「如果这个函数会被调用上百万次，怎么优化？」**
   思路：预处理一张 256 项的查表 `table[byte] = 该字节的 1 个数`，把 32 位拆成 4 个字节，每次查表相加，O(1) 且常数极小；或者用分治位运算（`x = x - ((x >> 1) & 0x55555555)` 那一套），无分支、无内存访问。

2. **「不用循环，能不能 O(1) 算出来？」**
   思路：分治法，把 32 位两两分组数 1、再四四分组、八八分组……用 5 次掩码与移位把结果累加到最低 6 位，本质是「并行前缀和」，对应题目标签里的「分治」。

3. **「如果 n 是负数（补码表示）怎么办？」**
   思路：Python 的整数是任意精度、负数没有固定位宽，直接 `while n` 会死循环（因为负数右移符号位补 1 永远不为 0）。要么先 `n &= 0xFFFFFFFF` 转成 32 位无符号，要么用 `n & (n-1)` 配合 `n != 0` 但注意 Python 负数 `n & (n-1)` 的行为——最稳妥是先掩码。

## 9. 举一反三（2-3 道同类题）

1. **231. 2 的幂**：共同点是都用 `n & (n-1)`——2 的幂恰好满足 `n & (n-1) == 0`，是本题「消 1」技巧的直接推论。
2. **338. 比特位计数**：共同点是都数 1 的个数，但那题要对 0..n 每个数都数，用 DP 递推 `dp[i] = dp[i >> 1] + (i & 1)` 或 `dp[i] = dp[i & (i-1)] + 1`，后者正是本题的递推化。
3. **136. 只出现一次的数字**：共同点是位运算的「抵消」思想——本题用 `& (n-1)` 消 1，那题用异或让成对的数互相抵消，都是「利用位运算的代数性质避免逐个比较」。
