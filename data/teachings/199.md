## 1. 一句话本质

对二叉树做一次「按层」的遍历，每层只保留**该层最靠右**的那个节点值，按层序拼成数组。

关键词是「每层」和「最右」。抓住这两点，题目就变成：**如何知道当前节点是不是它所在层的最右节点**。

## 2. 读完题的第一反应

**朴素解法**：把整棵树的所有节点按层收集起来，每层存成一个 list，最后取每层最后一个。这当然对，但你要额外维护「层 → 节点列表」的映射，空间上要为所有节点开桶，代码也啰嗦。更糟的是，如果你用 DFS 且不记录深度，你根本不知道一个节点属于哪一层，只能先全存下来再分组——这就是瓶颈：**信息（层号）没有被携带，只能事后补**。

**关键观察**：右视图的每个元素，恰好是「某一层里第一个被访问到的节点」——前提是你**从右往左**访问每一层。或者反过来：如果你**从左往右**按层访问，那每层**最后一个**被访问的节点就是答案。

这两个视角指向同一个事实：**右视图 = 层序遍历中每层的边界元素**。于是问题从「树的几何投影」降维成「层序遍历时打个标记」。这就是下一步的入口：BFS 天然按层推进，只要在每层结束时取最后一个出队的值即可。

另一个等价视角（DFS 版）：如果我用「根 → 右 → 左」的顺序做前序遍历，并且记录当前深度，那么**每个深度第一次被访问到的节点**就是该层最右节点。因为右子树先走，同层里最右的节点一定最先被碰到。这个视角在后面第 8 节会用到。

## 3. 从暴力到最优

**暴力版**：DFS 收集 `dict[depth] = [所有该层节点]`，最后 `[v[-1] for v in dict.values()]`。时间 O(n)，空间 O(n) 存全部节点。瓶颈不在时间，在于**多存了一份数据**，而且层号要靠递归参数手动传，容易写错。

**优化版（BFS）**：用队列做标准层序遍历。每一轮开始前先记下 `len(queue)`，这个数就是**当前层的节点个数**。循环这么多次，每次 `popleft` 一个节点、把它的孩子入队；循环到第 `len` 次时弹出的那个节点，就是本层最右节点，直接 append 到答案。

走一遍示例 1：`root = [1,2,3,null,5,null,4]`，树形是

```
        1
       / \
      2   3
       \   \
        5   4
```

- 初始 `queue = [1]`，`ans = []`
- 第 1 轮：`size = 1`。弹 1，入队 2、3 → `queue = [2,3]`。弹的是本轮唯一节点，`ans = [1]`
- 第 2 轮：`size = 2`。弹 2，入队 5 → `queue = [3,5]`；弹 3，入队 4 → `queue = [5,4]`。本轮最后弹出的是 3，`ans = [1,3]`
- 第 3 轮：`size = 2`。弹 5，无孩子 → `queue = [4]`；弹 4，无孩子 → `queue = []`。最后弹出 4，`ans = [1,3,4]`
- 队列空，结束。输出 `[1,3,4]` ✓

注意第 2 轮里，5 是第 3 层的节点，却在这一轮被**入队**了——它不影响本轮结果，因为 `size` 在轮开始时已经冻结。这正是「按层」的关键：**size 是这一层的快照，不是队列的实时长度**。很多人在这里写成 `while queue:` 里用 `len(queue)` 动态判断，就会把下一层的节点混进来。

**再优化（DFS）**：BFS 的空间是 O(最宽层)，最坏 O(n/2)。DFS 版用「根右左」前序 + 深度判断，空间降到 O(树高)，最坏 O(n)（链状树），平均 O(log n)。两者时间都是 O(n)。面试里 BFS 更好写、更不容易错，DFS 版是加分项。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚 BFS 版：

> 不变量：在第 k 轮循环开始时，队列中恰好存放第 k 层的全部节点，且顺序为从左到右。

归纳证明：第 1 轮开始时队列只有根，即第 1 层全部节点，成立。假设第 k 轮成立，则该轮按从左到右弹出第 k 层每个节点，并把它们的孩子按「左孩子先、右孩子先」的固定顺序入队；由于父节点从左到右、每个父节点先左后右，入队序列恰好是第 k+1 层从左到右的全部节点，不变量对 k+1 成立。

由此推出两条性质：

- **不漏**：每一层非空（否则不会有下一轮），第 k 轮必然执行 `size ≥ 1` 次弹出，最后一次弹出的节点存在，被记入答案。每个非空层贡献且仅贡献一个答案，层数 = 答案长度。
- **不重**：每轮只 append 一次，且 append 发生在该轮最后一次弹出时，不同轮对应不同层，互不干扰。

「最后一次弹出的是最右节点」由不变量的「从左到右」顺序直接得到：第 `size` 次弹出即该层最右。DFS 版的不变量是「按根右左前序访问时，深度 d 的第一个节点是该层最右节点」，理由是同层中更靠右的节点在「右优先」的遍历序里一定更早出现，交换论证一句话即可。

## 5. 完整代码（Python）

```python
from collections import deque
from typing import Optional, List


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def rightSideView(self, root: Optional[TreeNode]) -> List[int]:
        if root is None:          # 空树直接返回空列表，避免下面 dequeue 空队列
            return []

        ans = []
        queue = deque([root])     # BFS 队列，存放「当前层」的节点

        while queue:
            size = len(queue)     # 冻结本层节点数：这一轮只处理这 size 个
            for i in range(size):
                node = queue.popleft()
                # 孩子入队，供下一轮使用；顺序左→右，保证下一轮也是从左到右
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
                # 本轮最后一个弹出的节点 = 本层最右节点
                if i == size - 1:
                    ans.append(node.val)

        return ans
```

DFS 版（面试可作补充，空间更省）：

```python
class Solution:
    def rightSideView(self, root: Optional[TreeNode]) -> List[int]:
        ans = []

        def dfs(node, depth):
            if node is None:
                return
            # 该深度第一次被访问 → 就是这一层最右节点（因为先走右子树）
            if depth == len(ans):
                ans.append(node.val)
            dfs(node.right, depth + 1)   # 右子树优先
            dfs(node.left, depth + 1)

        dfs(root, 0)
        return ans
```

`depth == len(ans)` 这个判断的含义：`ans` 的长度恰好等于「已经记录过的最深层数」，若当前深度等于它，说明这一层还没记录过，而由于右优先，当前节点就是该层最右。

## 6. 复杂度

**BFS 版**

- 时间 O(n)：每个节点恰好入队一次、出队一次，入队出队都是 O(1)，共 2n 次操作；`size` 计算和 append 是 O(1) 摊还。n 是节点总数。
- 空间 O(w)，w 为树的最大宽度（最宽一层的节点数）。队列里最多同时存一层节点加下一层部分节点，量级是 O(w)。最坏是满二叉树最后一层，w ≈ n/2，即 O(n)；最好（链状树）w = 1，即 O(1)。答案数组本身 O(h)，h 为树高，被 O(w) 支配。

**DFS 版**

- 时间 O(n)：每个节点访问一次。
- 空间 O(h)：递归栈深度等于树高。链状树 h = n，O(n)；平衡树 h = log n，O(log n)。这里 log n 来自**树高**，不是来自节点数本身。

## 7. 边界与反例（至少 4 条）

1. `root = []` → `[]`。容易错在没判空就直接 `deque([root])` 然后 `popleft` 一个 `None`，或在 `node.left` 上抛 `AttributeError`。
2. `root = [1]` → `[1]`。单节点，`size = 1`，一轮结束。容易错在循环条件写成 `while len(queue) > 1` 之类，漏掉最后一层。
3. `root = [1,2]` → `[1,2]`。只有左孩子，右视图仍能看到 2（它虽是左孩子，但它是第 2 层唯一的节点，从右侧看得到）。容易错在误以为「只走右孩子」，把左子树整个忽略。
4. `root = [1,2,3,null,5,null,4]` → `[1,3,4]`。第 3 层最右是 4，但 5 是 2 的右孩子、位置更靠左。容易错在把「右孩子」当成「右视图」，5 会被误选。
5. `root = [1,2,3,4]` → `[1,3,4]`。第 3 层只有 4（2 的左孩子），它是最右。再次说明「最右」是层内位置，不是父子关系。
6. `root = [1,null,3]` → `[1,3]`。左子树为空，容易错在 DFS 版里先走 `node.left` 导致深度判断失效（必须右优先）。

## 8. 面试追问与变体（3 条）

1. **追问：改成左视图怎么做？** 思路：BFS 里取每层第一个弹出的节点（`i == 0`）；或 DFS 改成「根左 right 后」的前序，深度首次出现即记录。
2. **追问：不用队列，O(1) 额外空间能做吗？** 思路：Morris 遍历改造，用线索指针按层推进，代价是代码复杂、易错，面试中一般只要求说出思路。
3. **追问：如果树是 N 叉树呢？** 思路：BFS 完全不变，只是孩子入队改成遍历 `node.children`；DFS 版把两次递归改成循环孩子、仍保持「最右孩子优先」。
