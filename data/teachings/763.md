## 1. 一句话本质

对每个字符求出它「最后一次出现的位置」，然后从左到右扫描，用当前片段内所有字符的最远右端点不断扩张，直到扫描位置追上这个右端点——此时一个片段必须在这里闭合，否则某个字符就会被切开。

## 2. 读完题的第一反应

**朴素解法**：枚举所有可能的切分点组合，检查每种切分是否满足「同一字母只出现在一个片段」。切分点有 n-1 个，每个可选切或不切，组合数 2^(n-1)，再对每种组合做一次 O(n) 的合法性检查，复杂度指数级。即使剪枝，也卡在「怎么快速判断一个片段是否合法」上——你需要知道片段内每个字符在片段外还有没有出现，这本身就要反复扫描。

**关键观察**：一个片段能不能在位置 i 处结束，只取决于一件事——从片段起点到 i 之间出现过的所有字符，它们的**最后一次出现位置**是否都不超过 i。如果某个字符的最后一次出现位置在 i 之后，那这个片段就不能在 i 处闭合，必须继续往后吞。

这个观察之所以能让你想到下一步，是因为它把「全局的字母分布」压缩成了「每个字符的一个数字」——最远右端点。一旦你有了这张表，问题就从「搜索切分方案」变成了「一次线性扫描，维护一个不断变大的右边界」。贪心的结构就出来了：**能切就切，切得越早片段越多**，而「能切」的判据就是当前扫描位置等于当前维护的最远右端点。

## 3. 从暴力到最优

**第一步：暴力枚举切分点。** 瓶颈是组合爆炸，且每次判断合法性要 O(n)。消掉它的方式是：不要枚举切分方案，而是从左往右**增量地**决定切在哪里。

**第二步：预处理 last 表。** 扫一遍字符串，记录每个字符最后出现的下标。这一步 O(n)，把「某字符还会不会在后面出现」变成 O(1) 查表。

**第三步：贪心扫描。** 维护两个变量：`start` 是当前片段起点，`end` 是当前片段必须延伸到的最远位置。遍历 i 从 start 到 n-1，每遇到一个字符就更新 `end = max(end, last[s[i]])`。当 `i == end` 时，说明从 start 到 i 之间所有字符的最后出现位置都不超过 i，可以闭合，记录长度 `i - start + 1`，然后 `start = i + 1` 开始下一段。

**小例子走一遍**：s = "ababcbacadefegdehijhklij"

先算 last：a→8, b→5, c→7, d→14, e→15, f→11, g→13, h→19, i→22, j→23, k→20, l→21。

- start=0, end=0。i=0 字符 a，end=max(0,8)=8。i≠end，继续。
- i=1 字符 b，end=max(8,5)=8。i=2 字符 a，end=8。i=3 字符 b，end=8。i=4 字符 c，end=max(8,7)=8。i=5 字符 b，end=8。i=6 字符 a，end=8。i=7 字符 c，end=8。i=8 字符 a，end=8。
- i=8 == end=8，闭合，长度 8-0+1=9。start=9。
- start=9, end=9。i=9 字符 d，end=max(9,14)=14。i=10 字符 e，end=max(14,15)=15。i=11 字符 f，end=max(15,11)=15。i=12 字符 e，end=15。i=13 字符 g，end=max(15,13)=15。i=14 字符 d，end=15。i=15 字符 e，end=15。
- i=15 == end=15，闭合，长度 15-9+1=7。start=16。
- start=16, end=16。i=16 字符 h，end=max(16,19)=19。i=17 字符 i，end=max(19,22)=22。i=18 字符 j，end=max(22,23)=23。i=19 字符 h，end=23。i=20 字符 k，end=max(23,20)=23。i=21 字符 l，end=max(23,21)=23。i=22 字符 i，end=23。i=23 字符 j，end=23。
- i=23 == end=23，闭合，长度 23-16+1=8。start=24，结束。

结果 [9,7,8]，与示例一致。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在扫描过程中，`end` 始终等于「从 `start` 到当前 i 之间所有字符的最后出现位置的最大值」。归纳证明：初始时 start=i，end=last[s[start]]，成立；每步 i 前进，新字符的 last 与旧 end 取 max，不变量保持。

**为什么不会漏（片段数最大）**：当 `i == end` 时，区间 [start, i] 内每个字符的最后出现位置都 ≤ i，所以这个区间是**合法**的，可以闭合。而如果我们在更早的位置 j < end 处强行闭合，那么区间 [start, j] 内必然存在某个字符（正是把 end 撑到 end 的那个字符）的最后出现位置 > j，它会在后面的片段里再次出现，违反「同一字母最多出现在一个片段」。所以 `i == end` 是**最早**的合法闭合点，贪心地在此闭合不会损失任何片段数——任何合法划分的第一个片段都不可能比它更长，也不可能更短（更短就非法）。

**为什么不会重**：闭合后 `start = i + 1`，下一段从 i+1 开始，区间互不重叠，且拼接起来正好是原串，覆盖完整。

**交换论证的视角**：假设存在一个最优划分，它的第一个片段在位置 j < end 处结束。由于 [start, j] 内某字符的最后出现位置 > j，该字符在最优划分的第二个片段中再次出现，矛盾。所以最优划分的第一个片段必然在 end 处或之后结束；而我们的贪心在 end 处结束，片段数不会少于最优。归纳到后续片段，贪心解即最优解。

## 5. 完整代码（Python）

```python
class Solution:
    def partitionLabels(self, s: str) -> list[int]:
        # 第一步：预处理每个字符最后出现的下标
        last = {}
        for i, ch in enumerate(s):
            last[ch] = i  # 后面的覆盖前面的，最终存的就是最后一次出现

        res = []
        start = 0          # 当前片段的起始下标
        end = 0            # 当前片段必须延伸到的最远下标
        for i, ch in enumerate(s):
            # 当前字符的最后出现位置可能把右边界推得更远
            end = max(end, last[ch])
            # 扫描位置追上了右边界，说明 [start, i] 内所有字符都不会再出现
            if i == end:
                res.append(i - start + 1)  # 片段长度
                start = i + 1              # 下一段起点
        return res
```

关键逻辑只有三行：更新 `end`、判断 `i == end`、记录长度并移动 `start`。`last` 用字典存，因为提示说只有小写字母，也可以换成长度 26 的数组，把 `last[ch]` 换成 `last[ord(ch) - ord('a')]`。

## 6. 复杂度

**时间 O(n)**：第一遍遍历字符串建 `last` 表，每个字符 O(1) 哈希操作，共 n 次；第二遍遍历字符串做贪心扫描，每步 O(1) 的 max 和比较，共 n 次。总的是 2n 次常数操作，即 O(n)。这里没有 log n 的来源——没有排序、没有二分。

**空间 O(1)**（严格说是 O(Σ)，Σ 为字符集大小）：`last` 表最多存 26 个键值对（题目限定小写字母），与 n 无关，所以是常数空间。`res` 是输出本身，不计入辅助空间。如果字符集不固定，则空间为 O(Σ)，Σ ≤ n。

## 7. 边界与反例（至少 4 条）

1. **输入 `"a"` → 输出 `[1]`**。容易错在：循环里 `end` 初始为 0，i=0 时 `end = max(0, last['a']=0) = 0`，`i == end` 成立，正确闭合。如果 `end` 初始化成 -1 又忘了更新逻辑，可能漏掉单字符片段。

2. **输入 `"ab"` → 输出 `[1,1]`**。容易错在：误以为要尽量少切，把 "ab" 当成一段。但 a 和 b 各自只出现一次，切成两段片段更多，符合「尽可能多」。贪心在 i=0 时 end=0 就闭合，正确。

3. **输入 `"eccbbbbdec"` → 输出 `[10]`**。容易错在：看到 e 在位置 0 和 9 出现，c 在 1、2、8 出现，b 在 3-6 出现，d 在 7 出现，所有字符的最后出现位置都被 e 的 9 撑满，整串必须是一段。如果只按「相邻字符不同就切」会切错。

4. **输入 `"abab"` → 输出 `[4]`**。容易错在：以为可以切成 `["ab","ab"]`，但 a 和 b 都跨越了两段，非法。贪心在 i=0 时 end=last['a']=2，i=1 时 end=max(2,last['b']=3)=3，i=2 时 end=3，i=3 时 i==end 才闭合，得到 4。

5. **输入 `"aaaa"` → 输出 `[4]`**。容易错在：`end` 一直是 3，只有到最后一个位置才闭合，不能提前切，否则 a 出现在多个片段。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求每个片段内字符不重复（即每个片段是原串的一个「无重复字符子串」划分），怎么做？** 思路：这变成了「把字符串切成若干无重复字符的子串，求最少/最多段数」，可以用滑动窗口找每个起点的最长无重复区间，再贪心或 DP，和本题的「最后出现位置」思路不同，但同样依赖预处理字符位置。

2. **追问：如果字符集不是小写字母而是任意 Unicode，空间复杂度怎么变？** 思路：`last` 表大小变成 O(Σ)，Σ 是不同字符数，最坏 O(n)，空间从 O(1) 变成 O(n)，时间不变。可以用哈希表而非数组来适应。

3. **追问：如果要求返回具体的片段字符串而不是长度，代码怎么改？** 思路：在 `i == end` 时用 `s[start:i+1]` 切片追加到结果，其余逻辑不变，时间仍是 O(n)（切片总长度 n）。

## 9. 举一反三（2-3 道同类题）

1. **力扣 56. 合并区间**：共同点是都按「右端点」贪心扩张——本题维护字符的最远右端点，那题维护区间的右端点，扫描到无法延伸时闭合一段。

2. **力扣 435. 无重叠区间**：共同点是贪心选择「最早能结束的位置」，本题在 `i == end` 时最早闭合，那题按右端点排序后选最早结束的区间，都是「能早结束就早结束」的结构。

3. **力扣 45. 跳跃游戏 II**：共同点是维护一个「当前能到达的最远边界」，扫描到边界时步数加一、更新边界——本题的 `end` 就是跳跃游戏里的 `currentEnd`，`i == end` 就是「到达当前层边界」，结构几乎同构。
