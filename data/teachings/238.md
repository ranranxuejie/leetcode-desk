## 1. 一句话本质

对每个位置 i，求「它左边所有数的乘积」乘上「它右边所有数的乘积」——即把「除自己外的全体」拆成左右两段，分别求积再相乘。

## 2. 读完题的第一反应

**朴素解法**：对每个 i，再套一层循环把除 i 外的 n-1 个数乘起来。外层 n 次、内层 n 次，O(n²)。n 最大 10^5，10^10 次乘法必然超时。瓶颈在于：每个位置都重新扫一遍整个数组，大量重复计算。

**第二个念头（被题面堵死）**：先求总乘积 total，再对每个 i 算 total / nums[i]，O(n)。但题面明确写「请不要使用除法」，而且示例 2 里有 0——一旦有 0，除法直接崩（0 做除数），就算特判 0 的个数也会把代码写得很脏。所以这条路不能走，得找一条「只用乘法、且不重复计算」的路。

**关键观察**：`answer[i] = (nums[0]*...*nums[i-1]) * (nums[i+1]*...*nums[n-1])`。左边那段只跟 i 之前的元素有关，右边那段只跟 i 之后的元素有关。也就是说，**每个位置需要的两个因子，都可以从左到右、从右到左各扫一遍「累积」出来**。累积乘积天然满足「前一步的结果 + 当前元素 = 这一步的结果」，这正是前缀和/前缀积类题目的通用套路：把「区间查询」变成「两个端点前缀值的组合」。

## 3. 从暴力到最优

以 `nums = [1,2,3,4]` 为例，目标输出 `[24,12,8,6]`。

**第一步：暴力**。i=0 时算 2*3*4=24，i=1 时算 1*3*4=12……每个 i 都重乘一遍，共 4*3=12 次乘法。浪费在于：i=1 算的 3*4，i=0 时其实已经乘过 3 和 4 了。

**第二步：拆成左右两段，各扫一遍**。

- 左扫（前缀积，不含自己）：`left[i] = nums[0]*...*nums[i-1]`。
  - left[0] = 1（空积，这是关键约定）
  - left[1] = 1
  - left[2] = 1*2 = 2
  - left[3] = 1*2*3 = 6
  - 得 `left = [1,1,2,6]`
- 右扫（后缀积，不含自己）：`right[i] = nums[i+1]*...*nums[n-1]`。
  - right[3] = 1
  - right[2] = 4
  - right[1] = 3*4 = 12
  - right[0] = 2*3*4 = 24
  - 得 `right = [24,12,4,1]`
- 逐位相乘：`[1*24, 1*12, 2*4, 6*1] = [24,12,8,6]`。✓

这一步已经把 O(n²) 降到 O(n)，但用了两个额外数组，空间 O(n)。

**第三步：消掉 right 数组（进阶要求 O(1) 额外空间）**。注意 `answer` 数组本身不算额外空间。做法是：

1. 先把 `left` 直接写进 `answer`（第一遍从左往右）；
2. 再从右往左扫，维护一个滚动变量 `right`（初始 1），每步执行 `answer[i] *= right; right *= nums[i]`。

走一遍 `[1,2,3,4]`：

| i | 进入时 answer | 进入时 right | answer[i] *= right 后 | right *= nums[i] 后 |
|---|---|---|---|---|
| 3 | [1,1,2,6] | 1 | [1,1,2,6] | 4 |
| 2 | [1,1,2,6] | 4 | [1,1,2,8] | 12 |
| 1 | [1,1,2,8] | 12 | [1,1,12,8]→ 实际是 [1,12,8,6] 逐步成形 | 24 |
| 0 | [1,12,8,6] | 24 | [24,12,8,6] | 24 |

最终 `[24,12,8,6]`。✓ 瓶颈被彻底消掉：每个元素只被访问常数次，额外空间只剩一个滚动变量。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。设最终数组为 `ans`。

**第一遍（左→右）结束时的不变量**：对任意 i，`ans[i] = nums[0] * nums[1] * ... * nums[i-1]`（i=0 时为空积 1）。归纳：i=0 时 ans[0] 初始化为 1，成立；若 ans[i] 成立，则 ans[i+1] = ans[i] * nums[i] = nums[0..i]，成立。

**第二遍（右→左）过程中的不变量**：进入位置 i 时，滚动变量 `right = nums[i+1] * ... * nums[n-1]`（i=n-1 时为空积 1）。归纳：从 i=n-1 开始 right=1 成立；处理完 i 后执行 `right *= nums[i]`，进入 i-1 时 right 恰为 nums[i..n-1]，成立。

**合起来**：在位置 i 执行 `ans[i] *= right` 的那一刻，ans[i] 是「i 左侧全体之积」，right 是「i 右侧全体之积」，两者相乘恰好是「除 nums[i] 外全体之积」。**不重**：左侧因子只含下标 < i 的元素，右侧因子只含下标 > i 的元素，两个集合不相交，且都不含 i。**不漏**：除 i 外的每个下标要么 < i 要么 > i，必被其中一个因子覆盖。因此每个 ans[i] 都精确等于题目所求。

## 5. 完整代码（Python）

```python
class Solution:
    def productExceptSelf(self, nums: list[int]) -> list[int]:
        n = len(nums)
        ans = [1] * n

        # 第一遍：从左往右，ans[i] 先存「i 左侧所有元素的乘积」
        # 空积约定为 1，所以 ans[0] 保持 1
        left = 1
        for i in range(n):
            ans[i] = left          # 写入的是 nums[0..i-1] 的积
            left *= nums[i]        # 更新后 left 变成 nums[0..i] 的积，供 i+1 使用

        # 第二遍：从右往左，用滚动变量 right 补上「i 右侧所有元素的乘积」
        right = 1
        for i in range(n - 1, -1, -1):
            ans[i] *= right        # 左侧积 * 右侧积 = 除自身外全体之积
            right *= nums[i]       # 更新 right 为 nums[i..n-1] 的积，供 i-1 使用

        return ans
```

注意第一遍里 `ans[i] = left` 要在 `left *= nums[i]` **之前**执行——顺序反了就会把 nums[i] 自己乘进去，这是本题最容易写错的一行。

## 6. 复杂度

- **时间 O(n)**：第一遍 for 循环执行 n 次，每次常数次乘法和赋值；第二遍同样 n 次。总操作数 ≈ 4n，是 n 的线性函数。没有嵌套循环，也没有排序（排序才会引入 n log n）。
- **空间 O(1) 额外空间**：除返回数组 `ans`（n 个元素，题面明确不计入额外空间）外，只用了 `left`、`right`、`i`、`n` 四个标量，与 n 无关。若把返回数组也算进去则是 O(n)，但按题目对空间复杂度的定义，答案是 O(1)。

## 7. 边界与反例（至少 4 条）

1. **`nums = [1,2]` → `[2,1]`**。最短长度（题面下限 2）。容易错在循环边界写成 `range(n-1)` 漏掉最后一个，或空积没初始化为 1 导致结果全 0。
2. **`nums = [0,1,2]` → `[2,0,0]`**。含一个 0。容易错在：若用「总乘积除以自身」的思路，0 做除数直接异常；本题解法天然正确，因为 0 只是被当作普通因子参与乘法。
3. **`nums = [0,0,3]` → `[0,0,0]`**。含两个 0。容易错在特判「0 的个数」的写法：两个 0 时所有位置结果都是 0，特判逻辑容易写漏分支。本解法无需特判。
4. **`nums = [-1,1,0,-3,3]` → `[0,0,9,0,0]`**（示例 2）。含负数与 0 混合。容易错在符号：负负得正，若中间某步把符号搞丢（比如误用绝对值）就错。本解法纯乘法，符号自动正确。
5. **`nums = [-1,-1]` → `[-1,-1]`**。全负数且长度为 2。容易错在误以为结果应为正——实际「除自身外」只剩一个 -1，结果就是 -1。

## 8. 面试追问与变体（3 条）

1. **追问：如果允许用除法，怎么写？有什么坑？** 思路：统计 0 的个数。0 个 0 时用 total/nums[i]；1 个 0 时只有 0 所在位置非零（等于其余元素之积），其余全 0；≥2 个 0 时全 0。坑在于必须特判，且要单独处理 0 的位置。
2. **追问：如果要求返回「除自身外所有元素的和」而不是乘积？** 思路：完全同构，把乘法换成加法、空积 1 换成空和 0，两遍扫描即可，O(n)/O(1)。
3. **追问：如果数组是二维矩阵，要求每个位置「除自身外全矩阵元素之积」？** 思路：先求全矩阵总积（注意 0 的个数），再对每个位置用「总积 / 自身」并特判 0；或推广成「四个方向的前缀积」——上、下、左、右各扫一遍再合并，本质仍是把「全体减自身」拆成若干不相交的段。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 42. 接雨水**：共同点是「每个位置的值由它左边和右边的信息共同决定」，都用左右两遍扫描（前缀最大值 / 后缀最大值）来避免 O(n²)。
2. **LeetCode 135. 分发糖果**：共同点是「每个位置的答案依赖左右邻居」，标准解法是左→右一遍、右→左一遍取 max，和本题两遍扫描的骨架完全一致。
3. **LeetCode 724. 寻找数组的中心下标**：共同点是「用前缀和把『左边全体』与『右边全体』的比较变成 O(1)」，是本题前缀积思想在求和场景下的直接对应。
