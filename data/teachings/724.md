## 1. 一句话本质

在数组里找一个位置 `i`，使得「`i` 左边所有数之和」等于「`i` 右边所有数之和」，多个满足时取最左的，没有则返回 -1。

## 2. 读完题的第一反应

**朴素解法**：对每个下标 `i`，分别把 `nums[0..i-1]` 和 `nums[i+1..n-1]` 各加一遍，比较两个和。外层循环 n 次，内层每次最多加 n 个数，总复杂度 O(n²)。n 最大 10⁴，n² = 10⁸，在 Python 里这个量级大概率超时，而且它做了大量重复劳动——算 `i=1` 的左侧和时，其实已经把 `i=0` 的左侧和又算了一遍。

**关键观察**：题目里「左侧和」和「右侧和」是**同一个数组的两段**，而整个数组的总和 `total` 是固定的。于是对任意下标 `i`：

```
右侧和 = total - 左侧和 - nums[i]
```

也就是说，只要我知道 `i` 的左侧和，右侧和不用再扫一遍，一次减法就出来了。而左侧和随着 `i` 从左往右走，是**可以增量维护**的：走到 `i+1` 时，左侧和 = 原来的左侧和 + `nums[i]`。这一下就把「每个位置重新求和」变成了「边走边加」，瓶颈被消掉了。

这个观察之所以自然，是因为题面直接给了「左侧所有元素相加」和「右侧所有元素相加」这两个量——凡是题目里出现「某段区间的和」，就该条件反射地想：能不能用总和减去别的部分？能不能增量维护？

## 3. 从暴力到最优

拿示例 1 走一遍：`nums = [1, 7, 3, 6, 5, 6]`，`total = 28`。

**暴力**（以 `i=3` 为例）：左侧 `1+7+3=11`，右侧 `5+6=11`，相等，返回 3。但为了确认 3 是最左的，还得先检查 0、1、2，每个都重新求和。

**最优**：维护一个变量 `left_sum`，初值 0（下标 0 左侧没有元素，题面明确说视为 0）。从左往右扫：

| i | nums[i] | left_sum（进入时） | right_sum = total - left_sum - nums[i] | 判断 | 更新后 left_sum |
|---|---------|-------------------|----------------------------------------|------|-----------------|
| 0 | 1 | 0 | 28 - 0 - 1 = 27 | 0 ≠ 27 | 1 |
| 1 | 7 | 1 | 28 - 1 - 7 = 20 | 1 ≠ 20 | 8 |
| 2 | 3 | 8 | 28 - 8 - 3 = 17 | 8 ≠ 17 | 11 |
| 3 | 6 | 11 | 28 - 11 - 6 = 11 | **11 = 11，返回 3** | — |

每一步只做一次减法和一次比较，`left_sum` 的更新是 O(1)。整个流程：先花 O(n) 求 `total`，再花 O(n) 扫一遍，总 O(n)。对比暴力，省掉的是「每个 i 重新累加左右两段」这层内层循环。

再看示例 3 `[2, 1, -1]`，`total = 2`：

- `i=0`：`left_sum=0`，`right_sum = 2 - 0 - 2 = 0`，相等，返回 0。

这里要注意：`right_sum` 算出来是 0，而 `nums[1]+nums[2] = 1 + (-1) = 0`，确实相等。**负数不影响公式的正确性**，因为公式是纯代数恒等式，跟元素正负无关——这点很多人会下意识担心，其实不必。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**说清楚。扫描过程中，在检查下标 `i` 之前，始终有：

> 不变量：`left_sum == sum(nums[0..i-1])`。

- **初始化**：`i=0` 时 `left_sum=0`，而 `nums[0..-1]` 是空段，和为 0，成立。
- **保持**：若检查 `i` 时不变量成立，则 `right_sum = total - left_sum - nums[i] = total - sum(nums[0..i-1]) - nums[i] = sum(nums[i+1..n-1])`，正是 `i` 的右侧和。检查完若不返回，执行 `left_sum += nums[i]`，此时 `left_sum = sum(nums[0..i])`，对下一个下标 `i+1` 恰好是不变量要求的形式。
- **终止**：扫完所有下标仍未返回，说明每个 `i` 都满足 `left_sum ≠ right_sum`，即不存在中心下标，返回 -1 正确。

**不会漏**：每个下标都被检查了一次，且检查时 `left_sum`、`right_sum` 都等于题面定义的真实值（由不变量保证）。

**不会重**：从左往右扫，第一个满足条件的下标就立即返回，所以返回的必然是**最左**的那个，天然满足「多个时取最左」的要求，不需要额外处理。

## 5. 完整代码（Python）

```python
class Solution:
    def pivotIndex(self, nums: list[int]) -> int:
        total = sum(nums)          # 整个数组的总和，固定不变
        left_sum = 0               # 不变量：进入下标 i 时，left_sum == sum(nums[0..i-1])
        for i, x in enumerate(nums):
            # 右侧和 = 总和 - 左侧和 - 当前元素，O(1) 算出，不用再扫一遍
            right_sum = total - left_sum - x
            if left_sum == right_sum:
                return i           # 从左往右第一个满足的，就是最左的
            left_sum += x          # 为下一个下标维护不变量
        return -1                  # 扫完都没有，说明不存在中心下标
```

## 6. 复杂度

- **时间 O(n)**：`sum(nums)` 扫一遍贡献 n；`for` 循环扫一遍贡献 n；循环体内是常数次算术运算和比较，不随 n 变化。合计 2n，即 O(n)。这里没有 log n 的来源——没有排序、没有二分、没有树结构。
- **空间 O(1)**：只用了 `total`、`left_sum`、`right_sum`、`i`、`x` 这几个标量，与 n 无关。没有开前缀和数组（那会是 O(n) 空间，本题不需要）。

## 7. 边界与反例（至少 4 条）

1. **`nums = [1]`** → 期望 `0`。左侧和 0、右侧和 0，相等。容易错在：有人觉得「单元素没有左右」，直接返回 -1；题面明确说两端缺失部分视为 0，所以单元素数组的中心下标就是 0。
2. **`nums = [1, 2, 3]`** → 期望 `-1`。`total=6`：`i=0` 右和 5≠0；`i=1` 左 1 右 3；`i=2` 左 3 右 0。全不满足。容易错在：只检查了中间位置，忘了两端也要检查。
3. **`nums = [2, 1, -1]`** → 期望 `0`。容易错在：看到 `right_sum` 算出来是 0 就以为「右侧没元素」，其实右侧有 `1 + (-1) = 0`，和恰好为 0。**右侧和等于 0 不等于右侧为空**，这是本题最容易踩的坑。
4. **`nums = [-1, -1, -1, -1, -1, 0]`**（多个中心下标）→ 期望 `2`。`total=-5`：`i=2` 时左 `-2`、右 `-2 - 0 = -2`，相等；`i=3` 时左 `-3`、右 `-1`，不等。若从右往左扫会先撞到别的答案，必须从左往右、首个命中即返回。
5. **`nums = [0, 0, 0, 0]`** → 期望 `0`。全零数组每个下标都是中心下标，取最左的 0。容易错在：返回了最后一个或中间某个。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回所有中心下标（不止最左一个）？** 思路：去掉「命中即返回」，把满足的 `i` 全部 append 进结果列表，`left_sum` 照常更新，最后返回列表；时间仍是 O(n)。
2. **追问：如果数组是流式输入、不能先求 total 怎么办？** 思路：先完整读一遍求 total（流式也允许缓存），或者维护「已读总和」和「剩余总和」两个量同步推进；核心恒等式 `right = total - left - x` 不变，只是 total 的获取方式变了。
3. **追问：如果允许删除一个元素后再找中心下标（类似 1991 的加强版）？** 思路：先按原数组找；找不到时枚举删除位置，用前缀和数组 O(1) 查询删除后各位置的左右和，整体 O(n)，但要注意删除后下标平移的对应关系。

## 9. 举一反三（2-3 道同类题）

- **1991. 找到数组的中间位置**：与本题完全同构（题面已注明），共同点是「用总和减去左段和当前元素得到右段和」。
- **560. 和为 K 的子数组**：共同点是「区间和」问题，都用前缀和思想把「求一段和」转成「两个前缀和相减」，只是 560 需要哈希表统计出现次数。
- **303. 区域和检索 - 数组不可变**：共同点是预处理前缀和数组后，任意区间和 O(1) 查询；本题是它的「边扫边算、不存数组」的省空间版本。
