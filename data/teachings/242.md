## 1. 一句话本质

判断两个字符串是不是「同一堆字符的两种排列」——即它们各自包含的每种字符的**个数**完全一致。

## 2. 读完题的第一反应

**朴素解法**：把 s 和 t 都排序，然后比较两个结果是否相等。排序后，异位词必然变成同一个字符串。

它卡在哪？排序是 O(n log n)。n 最大到 5×10⁴，这个量级其实能过，但面试官问这道题，显然不是想看你调 `sorted()`——他想要的是 O(n) 的计数思路。而且排序法有个隐含代价：它把「字符顺序」这个信息彻底丢弃了，只为了比较内容，属于用大炮打蚊子。

**关键观察**：题目提示里有一句「s 和 t 仅包含小写字母」。这句话是整道题的钥匙。小写字母只有 26 种，意味着「每种字符出现几次」这个统计表的大小是**常数 26**，与字符串长度无关。于是我们不需要排序，只需要数数：扫一遍 s 把每个字母的计数加一，扫一遍 t 把计数减一，最后看计数表是不是全零。

为什么这个观察能直接导向下一步？因为「异位词」的定义本身就是「字符多重集相等」，而多重集相等最自然的表示就是**计数向量**。排序只是比较计数向量的一种间接手段，计数才是直接手段。

## 3. 从暴力到最优

**第一步：排序法。** 对 s = "anagram" 排序得 "aaagmnr"，对 t = "nagaram" 排序也得 "aaagmnr"，相等，返回 true。复杂度 O(n log n)，瓶颈在排序。

**第二步：计数法。** 开一个长度 26 的数组 `cnt`，初始全 0。

以 s = "anagram", t = "nagaram" 为例，先扫 s：

| 字符 | a | n | a | g | r | a | m |
|---|---|---|---|---|---|---|---|
| cnt['a'] | 1 | 1 | 2 | 2 | 2 | 3 | 3 |
| cnt['n'] | 0 | 1 | 1 | 1 | 1 | 1 | 1 |
| cnt['g'] | 0 | 0 | 0 | 1 | 1 | 1 | 1 |
| cnt['r'] | 0 | 0 | 0 | 0 | 1 | 1 | 1 |
| cnt['m'] | 0 | 0 | 0 | 0 | 0 | 0 | 1 |

扫完后 cnt 里 a=3, n=1, g=1, r=1, m=1，其余为 0。

再扫 t = "nagaram"，每遇到一个字符就减一：

n → cnt['n'] 从 1 变 0；a → cnt['a'] 从 3 变 2；g → cnt['g'] 从 1 变 0；a → cnt['a'] 变 1；r → cnt['r'] 变 0；a → cnt['a'] 变 0；m → cnt['m'] 变 0。

最终 cnt 全零，返回 true。

**瓶颈怎么被消掉的**：排序的 O(n log n) 来自「比较排序下界」，而计数法根本不比较字符之间的大小关系，只做「下标访问 + 加减一」，每次操作 O(1)，总共 O(n)。空间上从排序的 O(n)（或 O(log n) 栈空间）降到 O(26) = O(1)。

**一个必须先做的剪枝**：如果 `len(s) != len(t)`，直接返回 false。这不是优化，是正确性的一部分——长度不同时，计数表不可能同时被清零（想想为什么：s 扫完总和是 len(s)，t 扫完总和是 len(t)，两者不等则不可能全零）。而且它能在最坏情况前省掉一整轮扫描。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

定义不变量：在扫描 t 的过程中，任意时刻 `cnt[c]` 的值等于「c 在 s 中出现的次数」减去「c 在 t 已扫描部分中出现的次数」。

- 初始时 t 已扫描部分为空，`cnt[c]` 恰好是 s 中 c 的次数，不变量成立。
- 每扫描 t 的一个字符 c，`cnt[c]` 减一，正好对应「t 已扫描部分多了一个 c」，不变量保持。
- 扫描结束后，t 已扫描部分就是整个 t，所以 `cnt[c] = count_s(c) - count_t(c)`。

于是「cnt 全零」等价于「对所有 c，count_s(c) = count_t(c)」，这正是异位词的定义。**不会漏**：任何一对异位词，每个字符的差值都是 0，必然全零。**不会重**：任何非异位词，至少存在一个字符 c 使 count_s(c) ≠ count_t(c)，该位置非零，必然返回 false。两个方向都覆盖，判定是充要的。

注意这里不需要额外检查「有没有负数」——因为长度相等已保证总和为零，若某位为负必有另一位为正，全零检查会一并拦下。

## 5. 完整代码（Python）

```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        # 长度不同，字符多重集不可能相等，直接否掉
        if len(s) != len(t):
            return False

        # 26 个小写字母的计数表，下标 0 对应 'a'
        cnt = [0] * 26

        # 第一遍：s 中每个字符计数 +1
        for ch in s:
            cnt[ord(ch) - ord('a')] += 1

        # 第二遍：t 中每个字符计数 -1
        for ch in t:
            idx = ord(ch) - ord('a')
            cnt[idx] -= 1
            # 提前退出：某字符在 t 中出现次数已超过 s，不可能再拉平
            if cnt[idx] < 0:
                return False

        # 走到这里说明每个字符的净差都为 0
        return True
```

关于那个提前退出：它不是必需的（最后统一检查全零也对），但它把「t 里多出来的字符」在第一时间抓住，逻辑上更贴近不变量——一旦某位变负，说明 t 已扫描部分该字符就比 s 总数还多，后面只会更负，永远回不到零，可以立刻判定失败。

## 6. 复杂度

**时间 O(n)**，其中 n = len(s) = len(t)（长度不等时 O(1) 就返回了）。来源：第一遍扫 s 做 n 次 O(1) 的数组加减，第二遍扫 t 同样 n 次，合计 2n 次常数操作。没有 log 项，因为全程没有排序、没有二分、没有基于比较的操作。

**空间 O(1)**。来源：`cnt` 固定 26 个元素，与 n 无关；两个循环变量是常数。严格写是 O(Σ)，Σ 为字符集大小，本题 Σ=26，故视为常数。对比排序法：Python 的 `sorted` 会额外分配 O(n) 的列表，空间是 O(n)。

## 7. 边界与反例（至少 4 条）

1. **s = "a", t = "a"** → true。容易错在：有人写循环时用 `range(len(s))` 同时索引两个串，长度相等时没问题，但若先做了长度检查又忘了处理单字符，容易在初始化计数表时把边界写错（比如 `cnt = [0]*25`）。

2. **s = "ab", t = "a"** → false。容易错在：只比较「s 的字符是否都在 t 里」，漏掉长度检查，会误判为 true。长度不等必须最先拦。

3. **s = "aacc", t = "ccac"** → false。容易错在：两个串的字符集合相同（都是 {a,c}），只看「集合相等」会误判 true。必须比**计数**而非**种类**。这是本题最经典的坑。

4. **s = "rat", t = "car"** → false。容易错在：`cnt` 用减一法时忘了最后检查全零，或者只检查了「没有负数」——本例中 r 位为 +1、c 位为 -1，若只查负数会返回 false 恰好对，但换成 s="car", t="rat" 就漏了。统一检查全零最稳。

5. **s = "aab", t = "abb"** → false。容易错在：提前退出逻辑写反，或在减一后没及时判断负数，导致把「b 多出来」的情况拖到最后才发现（结果仍对，但暴露了对不变量的理解不牢）。

## 8. 面试追问与变体（3 条）

1. **追问：如果字符串含 Unicode 字符怎么办？** 思路：把固定长度 26 的数组换成哈希表（Python 的 `dict` 或 `collections.Counter`），键是字符本身，逻辑完全不变；空间从 O(1) 变为 O(k)，k 为不同字符数。

2. **追问：如果要求 O(1) 额外空间且不能改字符串呢？** 思路：在「仅小写字母」前提下，可以用一个 32 位整数做位图，但位图只能记录「出现过」不能记录「出现几次」，所以只适用于「判断字符集合是否相同」的弱化版；要计数则位图不够，需回到数组或哈希表。这个追问考的是你能否说清「位图 vs 计数」的适用边界。

3. **追问：如果 s 和 t 长度可达 10⁷，内存受限怎么办？** 思路：计数法本身已是 O(1) 空间、O(n) 时间，是这类问题的下界级解法；真正的瓶颈是读入，可考虑流式处理——边读边更新计数表，不把整个字符串载入内存。

## 9. 举一反三（2-3 道同类题）

1. **力扣 49. 字母异位词分组**：共同点是「异位词 = 计数向量相同」，把每个词的计数向量（或排序后的串）当哈希键分组即可。

2. **力扣 383. 赎金信**：共同点是「用一个串的字符去凑另一个串」，本质是单向的计数包含关系，把本题的「相等」放宽成「≥」即可。

3. **力扣 387. 字符串中的第一个唯一字符**：共同点是「先统计频次再按频次做判断」，是计数表思路的直接应用。
