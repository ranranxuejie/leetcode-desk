## 1. 一句话本质

把单链表在倒数第 `k mod n` 个节点处“剪断”，再把后半段接到前面——本质是**定位新的头节点**，而不是真的逐个移动节点。

## 2. 读完题的第一反应

**朴素解法**：模拟移动。每次把尾节点摘下来插到头部，重复 `k` 次。卡在哪？`k` 最大到 `2*10^9`，而节点数最多 500。`k` 次操作里绝大多数是“绕圈圈”的重复劳动，复杂度 `O(n·k)`，直接超时。瓶颈在于：**我们把“移动 k 次”当成了 k 次独立操作，但链表长度只有 n，移动 n 次就回到原样**。

**关键观察**：向右移动 `k` 位，等价于向右移动 `k mod n` 位。因为链表是个环状结构（首尾相接后），转 n 步回到起点。所以真正要做的只是：找到“新的尾节点”和“新的头节点”这两个位置，一次断开、一次连接即可。这一步把 `k` 从天文数字压到 `[0, n)`，问题瞬间变成“找倒数第几个节点”——这正是双指针（快慢指针）的经典场景。

再进一步想：既然要找“倒数第 `k mod n` 个”，那先遍历一遍拿到长度 n 和尾节点，把尾节点先接到头节点上形成环，再走 `n - (k mod n)` 步找到新尾，断开即可。**一次遍历求长度 + 一次走位**，`O(n)`。

## 3. 从暴力到最优

**暴力版**（思路，不写完整代码）：循环 k 次，每次遍历到倒数第二个节点，断开尾节点，插到 head 前。以 `[1,2,3,4,5], k=2` 为例：

- 第 1 次：`[5,1,2,3,4]`
- 第 2 次：`[4,5,1,2,3]`

两次都对，但 k=2*10^9 时就是 20 亿次遍历，每次 O(n)，不可行。

**优化第一步：取模**。n=5，k=2，`k mod n = 2`，还是要移 2 次。这一步单独看没省多少，但它把 k 的上界从 2e9 压到 n-1，是后面所有优化的前提。

**优化第二步：找“断点”而不是“移动”**。观察 `[1,2,3,4,5]` 移 2 位后是 `[4,5,1,2,3]`。新头是原第 4 个节点（值 4），新尾是原第 3 个节点（值 3）。也就是说，**新尾 = 原链表正数第 `n - k mod n` 个节点**（这里 n=5, k mod n=2，第 3 个，值 3，正确）。找到它，把它的 next 置空，把原尾的 next 指向原头，返回新头（原第 4 个）即可。

**优化第三步：用环 + 走位代替“找倒数第几个”**。先把尾节点 `5` 的 next 指向 head，形成环 `1→2→3→4→5→1→...`。此时从“原尾”出发走 `n - k mod n = 3` 步：5→1（1 步）→2（2 步）→3（3 步），停在 3，它就是新尾。新尾的 next（即 4）就是新头。断开 3→4，返回 4。整个过程只走了 3 步，加上前面求长度的 5 步，总共 8 步，与 k 无关。

中间变量走一遍（`[1,2,3,4,5], k=2`）：

| 步骤 | 变量 | 值 |
|---|---|---|
| 求长度 | n | 5 |
| 求尾 | tail | 节点 5 |
| 取模 | k | 2 |
| 成环 | tail.next | 节点 1 |
| 走位步数 | steps | 5 - 2 = 3 |
| 走位后 | newTail | 节点 3 |
| 新头 | newHead | 节点 4 |
| 断开 | newTail.next | None |

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。设原链表为 `v0 → v1 → ... → v(n-1)`，向右旋转 `r = k mod n` 位后，期望结果是 `v(n-r) → ... → v(n-1) → v0 → ... → v(n-r-1)`。

**不变量**：在成环后从 tail（即 `v(n-1)`）出发走 `n - r` 步，恰好停在 `v(n-r-1)`，也就是期望结果里的“新尾”。证明：从 `v(n-1)` 走 1 步到 `v0`，走 `n-r` 步后到达下标 `(n-1 + n - r) mod n = (n - r - 1) mod n`，正是 `v(n-r-1)`。它的 next 是 `v(n-r)`，正是期望的新头。

**为什么不会漏**：所有节点都在环上，走位只改变“从哪断开”，不改变节点集合，所以每个节点都保留且只出现一次。**为什么不会重**：断开操作只把一条边（newTail→newHead）置空，其余边不变，链表结构从环变回单链，不存在重复引用。

**边界 r=0 时**：steps = n，从 tail 走 n 步回到 tail 自己，newTail = tail，newHead = tail.next = 原 head，断开后与原链表完全一致——符合“移 0 位不变”的语义。这个不变量在 r=0 时依然成立，不需要特判（但代码里为清晰可特判）。

## 5. 完整代码（Python）

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def rotateRight(self, head, k):
        # 空链表或单节点，旋转无意义，直接返回
        if not head or not head.next:
            return head

        # 第一遍：求长度 n，同时记录尾节点
        n = 1
        tail = head
        while tail.next:
            tail = tail.next
            n += 1

        # k 可能远大于 n，取模得到真实位移量
        k %= n
        # 位移为 0，原样返回（也避免下面走 n 步的冗余）
        if k == 0:
            return head

        # 成环：尾节点指向头节点
        tail.next = head

        # 从 tail 出发走 n - k 步，停在“新尾”
        new_tail = tail
        for _ in range(n - k):
            new_tail = new_tail.next

        # 新头是新尾的下一个；断开环
        new_head = new_tail.next
        new_tail.next = None

        return new_head
```

关键逻辑注释已在代码中。注意 `n - k` 的走位是从 tail 出发，而不是从 head 出发——这是成环技巧的核心，避免再算一次“倒数第几”。

## 6. 复杂度

**时间 `O(n)`**：第一遍遍历求长度走 n 步；第二遍走位走 `n - k` 步，最坏 n 步。两遍都是线性，总 `O(n)`。这里 n 来自“节点数”，与 k 无关——取模把 k 的影响彻底消掉了。没有 log 项，因为没有任何分治或二分操作。

**空间 `O(1)`**：只用了 `n, tail, new_tail, new_head` 几个指针变量，没有开辟与 n 相关的数组或递归栈。成环是原地修改指针，不占额外空间。

## 7. 边界与反例（至少 4 条）

1. **空链表** `head = [], k = 0` → 输出 `[]` → 容易错在没判 `not head` 就去访问 `head.next`，直接 `AttributeError`。
2. **单节点** `head = [1], k = 5` → 输出 `[1]` → 容易错在成环后走位逻辑对单节点失效（tail.next 指向自己，走位后 new_tail 还是自己，new_head 也是自己，断开后 next=None，结果正确，但若没提前返回可能绕晕；更常见错误是没判 `head.next` 导致成环后死循环风险）。
3. **k 是 n 的整数倍** `head = [1,2,3], k = 6` → 输出 `[1,2,3]` → 容易错在没取模，走位步数算成 `n - 6 = -3`，`range` 负数不执行，new_tail 停在 tail，new_head = tail.next = head，看似对，但逻辑脆弱；显式 `k %= n` 后 `k=0` 直接返回最稳。
4. **k 大于 n 且非倍数** `head = [0,1,2], k = 4` → 输出 `[2,0,1]` → 容易错在直接用 k=4 走位，`n - k = -1`，逻辑崩掉；取模后 k=1，走 2 步，正确。
5. **k = 0** `head = [1,2], k = 0` → 输出 `[1,2]` → 容易错在成环后走 n 步回到 tail，虽然结果对，但多做一圈；显式返回更清晰，也避免“走 n 步”这种边界。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求向左旋转 k 位呢？** 思路：向左 k 位等价于向右 `n - k mod n` 位，把 `k` 换成 `(n - k % n) % n` 后套用同一套逻辑即可。
2. **追问：不允许修改原链表（要返回新链表）怎么办？** 思路：先遍历一遍把值存进数组，按旋转后的顺序重建链表，空间 `O(n)`；或者用“断点定位 + 分段复制”两遍扫描，空间仍是 `O(n)` 但只复制节点。
3. **追问：如果链表是双向链表，旋转怎么做？** 思路：同样成环再断开，但断开时要同时维护 `prev` 和 `next` 两个指针，新头的 `prev` 置空、新尾的 `next` 置空，其余不变，时间仍 `O(n)`。

1. **LeetCode 19. 删除链表的倒数第 N 个节点**：共同点是“定位倒数第几个节点”，快慢指针一次遍历即可，和本题的“走位找新尾”是同一类定位技巧。
2. **LeetCode 143. 重排链表**：共同点是“找链表中点/断点后重新拼接”，都需要先定位再改指针，考察对链表结构的整体把控。
3. **LeetCode 189. 轮转数组**：共同点是“旋转 k 位 + 取模”，数组版用三次反转实现 `O(1)` 空间，链表版用成环断开，思想都是“把线性结构看成环来处理位移”。
