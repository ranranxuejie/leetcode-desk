## 1. 一句话本质

对字符串里**每个字母位置**独立地做「保持/翻转」二选一，把所有位置的选择组合起来，得到全部结果——本质是求一个「每个字母贡献 2 种取值」的笛卡尔积。

## 2. 读完题的第一反应

**朴素解法**：把所有字母位置找出来，假设有 k 个字母，那么结果有 2^k 个。最直接的想法是枚举 0 到 2^k−1 的每个整数，用它的二进制位决定第 i 个字母翻不翻转。

这个思路本身没错，但新手容易卡在两点：

1. **不知道 k 是多少**：得先扫一遍字符串数出字母个数，再建立「第 j 个字母在原串的哪个下标」的映射，多一层间接。
2. **拼接字符串的开销**：每个结果都要从头拼一遍长度 n 的串，2^k × n 的字符操作，虽然本题 n ≤ 12 完全扛得住，但写起来别扭。

**关键观察**：数字位置永远不变，字母位置只有两种状态。这意味着**每个位置的处理是互相独立的**——处理完第 i 个字符，剩下的子问题跟前面怎么选完全无关。这种「每步独立二选一、结果要全枚举」的结构，天然对应**回溯（DFS）**：沿着字符串从左往右走，遇到字母就分叉两次，遇到数字就直走，走到末尾就收集一个答案。

为什么这个观察能直接导向下一步？因为「独立 + 全枚举」正是回溯的定义域。你不需要预先知道 k，也不需要维护下标映射，递归深度就是字符串长度，天然对齐。

## 3. 从暴力到最优

**暴力（位掩码枚举）**：先收集所有字母下标 `pos = [0, 2]`（对 `"a1b2"`），k=2，枚举 mask 从 0 到 3：

- mask=0（00）：a 不翻、b 不翻 → `"a1b2"`
- mask=1（01）：a 不翻、b 翻 → `"a1B2"`
- mask=2（10）：a 翻、b 不翻 → `"A1b2"`
- mask=3（11）：a 翻、b 翻 → `"A1B2"`

瓶颈在哪？每次都要「按 mask 重建整个串」，而且 mask 的位和字母位置的对应关系要手动维护，容易写错。复杂度是 O(2^k · n)，其中 n 的因子来自重建字符串。

**回溯**：把「重建」换成「边走边拼」。维护一个路径 `path`（当前已决定的字符列表），递归函数 `dfs(i)` 表示「前 i 个字符已定，现在处理第 i 个」：

以 `"a1b2"` 走一遍：

- `dfs(0)`，path=[]，s[0]='a' 是字母：
  - 分支 1 保持：path=['a'] → `dfs(1)`
  - 分支 2 翻转：path=['A'] → `dfs(1)`
- `dfs(1)`，s[1]='1' 是数字，唯一分支：path 追加 '1' → `dfs(2)`
- `dfs(2)`，s[2]='b' 是字母：
  - 保持：追加 'b' → `dfs(3)`
  - 翻转：追加 'B' → `dfs(3)`
- `dfs(3)`，s[3]='2' 是数字：追加 '2' → `dfs(4)`
- `dfs(4)`，i == n，收集 `''.join(path)`。

最终收集到 4 个串，和暴力一致。**瓶颈怎么被消掉的**：不再有「重建整串」这一步，每个字符在每条路径上只被 append 一次，收集时 join 一次。总字符操作从 O(2^k · n) 降到 O(2^k · n) 的同一量级但常数更小、代码更直白——更重要的是**不需要预先数 k、不需要下标映射**，逻辑和题面「每个字母二选一」一一对应。

> 说明：本题 n ≤ 12，两种写法都能过。选回溯是因为它可迁移——遇到「每个位置多选一、要全枚举」的题，回溯是通用模板；位掩码只适合「恰好两个选项且位置好数」的场景。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。

**不变量**：在 `dfs(i)` 入口处，`path` 恰好是「原串前 i 个字符的一个合法变换结果」——即数字原样保留、每个字母取原形或翻转形之一。

- **基础**：`dfs(0)` 时 path 为空，是前 0 个字符的唯一合法变换，成立。
- **保持**：`dfs(i)` 里，若 s[i] 是数字，只有一条分支追加 s[i]，前 i+1 个字符仍合法；若是字母，两条分支分别追加原形和翻转形，覆盖了该位置的全部两种合法取值，前 i+1 个字符仍合法。
- **终止**：`dfs(n)` 时 path 是前 n 个字符（即整串）的合法变换，收集它。

**不漏**：任取一个合法结果 T，它由每个字母位置的「翻/不翻」决定。沿 T 的决策序列在递归树上走，每一步都能对上一条分支（字母位置的两条分支覆盖了两种取值），最终必到达 `dfs(n)` 并收集 T。

**不重**：两个不同的决策序列，在**第一个不同的字母位置**上取值不同（一个原形一个翻转形），而大小写翻转是双射（翻转两次回到原形，原形 ≠ 翻转形），所以拼出的串在该位置字符不同，两个结果串必不相同。因此每条根到叶的路径对应唯一结果，收集不重复。

> 注意一个容易忽略的点：题面说「返回所有可能得到的字符串**集合**」，但输入里若同时出现大小写不同的同一字母（如 `"aA"`），翻转后可能撞车吗？`"aA"` 的四个结果是 `"aA" "aa" "AA" "Aa"`，互不相同——因为每个位置独立翻转，不同决策序列必在某个位置字符不同，不会撞。所以用 list 收集即可，无需去重。

## 5. 完整代码（Python）

```python
class Solution:
    def letterCasePermutation(self, s: str) -> list[str]:
        n = len(s)
        res = []          # 收集所有合法结果
        path = []         # 当前已决定的字符序列（回溯的"路径"）

        def dfs(i: int) -> None:
            # 终止条件：前 n 个字符都已决定，path 就是一个完整结果
            if i == n:
                res.append(''.join(path))
                return

            ch = s[i]
            if ch.isdigit():
                # 数字：唯一分支，原样追加后继续
                path.append(ch)
                dfs(i + 1)
                path.pop()          # 回溯：撤销本层选择
            else:
                # 字母：分支 1，保持原形
                path.append(ch)
                dfs(i + 1)
                path.pop()

                # 分支 2，翻转大小写（swapcase 对单字符安全）
                path.append(ch.swapcase())
                dfs(i + 1)
                path.pop()

        dfs(0)
        return res
```

关键逻辑注释已在代码中。补充两点：

- `path.pop()` 是回溯的灵魂——它保证「进入下一层前 path 是干净的」，兄弟分支不会看到对方追加的字符。漏写 pop 是新手最常见的 bug，结果会变成前缀不断累加。
- `ch.swapcase()` 对单个字母返回翻转形；用 `ch.upper() if ch.islower() else ch.lower()` 等价，但 swapcase 更短。

## 6. 复杂度

设 n = len(s)，k = 字母个数。

**时间**：O(2^k · n)。

- 2^k 来自：每个字母位置分叉两次，递归树叶子数 = 2^k，每个叶子对应一个结果。
- n 来自：每个叶子收集时 `''.join(path)` 要遍历长度 n 的 path；递归树内部节点总数也是 O(2^k · n) 量级（每条路径长度 n），但被叶子收集的 n 支配。
- 注意：**不是** O(2^n)，因为数字位置不分叉，只有字母贡献因子 2。k ≤ n，所以最坏 O(2^n · n)。

**空间**：O(2^k · n) 用于存结果（每个结果长 n，共 2^k 个）；递归栈深度 O(n)，path 长度 O(n)。若只算辅助空间（不含输出），是 O(n)。

- 谁贡献 n：字符串长度，体现在每个结果的长度、递归深度、path 长度。
- 本题没有 log n 项；若有人写 O(2^k · n log n) 是把字符串比较/哈希的开销算进去了，但这里没有比较操作，不成立。

## 7. 边界与反例（至少 4 条）

1. **输入 `"a"`** → 期望 `["a", "A"]` → 容易错：只返回原串，忘了字母本身也要分叉；或误以为长度 1 没有变换。
2. **输入 `"123"`** → 期望 `["123"]` → 容易错：全数字时 k=0，结果只有 1 个；若代码在「没有字母」时提前返回空列表就错了。
3. **输入 `"aA"`** → 期望 `["aA", "aa", "AA", "Aa"]`（4 个，互不相同）→ 容易错：以为大小写翻转会撞车而加 set 去重，或反过来漏掉某个组合；实际每个位置独立翻转不会产生重复。
4. **输入 `"C"`（大写开头）** → 期望 `["C", "c"]` → 容易错：只处理小写转大写，忘了大写也能转小写；`swapcase` 或 `islower` 判断能覆盖两个方向。
5. **输入 `"1a2b3"`（数字夹字母）** → 期望 4 个结果，数字位置固定 → 容易错：把数字也当字母分叉，或数字分支里忘了 `path.pop()` 导致后续路径污染。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求结果按字典序输出怎么办？**
   一句话思路：回溯时先走「原形」再走「翻转形」不一定得到字典序（大小写 ASCII 顺序：大写 < 小写），可在收集后 `res.sort()`，或调整分支顺序使生成即有序（需按字符实际大小比较决定先走哪支）。

2. **追问：如果每个字母可以变成「原形/大写/小写」三种（即不区分原形，统一三选一）呢？**
   一句话思路：把字母分支从 2 条改成 3 条（追加 lower、upper，若原形与二者不同再追加原形），本质仍是「每位置多选一」的回溯，只是分叉数变了，复杂度变 3^k。

3. **追问：如果输入很长（n 到 20），但只要求返回第 m 个结果（按某种枚举顺序）？**
   一句话思路：不生成全部，用「第 j 个字母对应结果的第几位」做进制分解，直接把 m 映射成每个字母的翻/不翻决策，O(n) 构造单个结果，避免 2^k 爆炸。

## 9. 举一反三（2-3 道同类题）

1. **46. 全排列**：同样是「每步从剩余选项里选一个、要全枚举」，回溯模板一致，区别是选项集合随已选元素变化（需要 used 数组），而本题每个位置选项固定为 2。
2. **77. 组合**：每步在「选/不选当前元素」上分叉，和本题「翻/不翻」结构同构，都是二叉决策树 + 路径收集。
3. **17. 电话号码的字母组合**：每个数字位置对应多个候选字母，分叉数不固定，是本题「数字位置只有 1 个候选、字母位置 2 个候选」的推广——本质都是「每个位置从候选集里选一个，求笛卡尔积」。
