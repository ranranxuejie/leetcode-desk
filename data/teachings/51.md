## 1. 一句话本质

在 n×n 棋盘上每行恰好放一个皇后，使任意两个皇后不同列、不同主对角线、不同副对角线，枚举所有这样的列号排列。

## 2. 读完题的第一反应

朴素解法：把 n² 个格子看成候选位置，从中选 n 个格子的所有组合，逐个检查是否互相攻击。组合数是 C(n², n)，n=8 时约 4.4×10⁹，再乘上每次 O(n²) 的检查，完全不可行。瓶颈有两层：一是「选哪些格子」这个搜索空间本身爆炸，二是大量候选在选到一半时就已经违规，却要等到最后才被检查出来。

关键观察来自题面第一句「同一行」：既然任意两个皇后不能同行，而棋盘只有 n 行、要放 n 个皇后，那么**每行必须恰好一个皇后**。这一句话把「从 n² 个格子里选 n 个」直接压缩成「给每一行选一个列号」，搜索空间从 C(n², n) 降到 n! 量级。更进一步，列也不能重复，所以解就是 0..n-1 的一个排列，n=8 时只有 8! = 40320 个候选。这个观察之所以能引出下一步，是因为它把问题变成了「逐行做决策」的形式——第 0 行选哪列、第 1 行选哪列……天然适合回溯：每行做一次选择，选完一行就检查冲突，冲突立刻剪枝，不必等到 n 行都放完。

## 3. 从暴力到最优

**第一步：全组合枚举 → 逐行枚举。** 利用「每行一个」的观察，搜索树从「选格子」变成「第 i 行选第 j 列」，深度 n，每层 n 个分支，共 nⁿ 个叶子（含重复列），比 C(n², n) 小得多，但仍允许同列。

**第二步：加列约束。** 用一个长度为 n 的布尔数组 `col_used`，某列被占后该层分支直接跳过。叶子数降到 n! 量级。

**第三步：加对角线约束，且用 O(1) 判断。** 这是本题真正的技巧。两条对角线各有自己的编号方式：

- 主对角线（左上到右下）：同一线上的格子满足 `row - col` 相等，取值范围 `-(n-1) .. n-1`，加偏移 n-1 后映射到 `0 .. 2n-2`。
- 副对角线（右上到左下）：同一线上的格子满足 `row + col` 相等，取值范围 `0 .. 2n-2`。

于是准备三个布尔数组 `col_used`、`diag1_used`、`diag2_used`，放皇后时把三个位置同时置 True，回溯时置回 False。冲突判断从「遍历已放的皇后逐个比较」的 O(n) 降到 O(1)。

**小例子走一遍 n=4。** 用 `path` 记录每行选的列号，三个数组初始全 False。

- 第 0 行试列 0：`col_used[0]=T`，`diag1_used[0-0+3]=diag1_used[3]=T`，`diag2_used[0+0]=diag2_used[0]=T`。`path=[0]`。
- 第 1 行试列 0：`col_used[0]` 已 True，跳过。试列 1：`diag1_used[1-1+3]=diag1_used[3]` 已 True，跳过。试列 2：三个位置 `col_used[2]`、`diag1_used[1-2+3]=diag1_used[2]`、`diag2_used[1+2]=diag2_used[3]` 全 False，放下。`path=[0,2]`。
- 第 2 行试列 0：`col_used[0]` 冲突。列 1：`diag2_used[2+1]=diag2_used[3]` 冲突。列 2：列冲突。列 3：`diag1_used[2-3+3]=diag1_used[2]` 冲突。四个分支全剪，回溯到第 1 行。
- 第 1 行试列 3：`col_used[3]`、`diag1_used[1-3+3]=diag1_used[1]`、`diag2_used[1+3]=diag2_used[4]` 全 False，放下。`path=[0,3]`。
- 第 2 行试列 0：列冲突。列 1：`diag1_used[2-1+3]=diag1_used[4]` 空闲、`diag2_used[2+1]=diag2_used[3]` 空闲、`col_used[1]` 空闲，放下。`path=[0,3,1]`。
- 第 3 行：列 0 列冲突，列 1 列冲突，列 2 的 `diag1_used[3-2+3]=diag1_used[4]` 冲突，列 3 列冲突。全剪，回溯。
- 第 2 行试列 2：`diag1_used[2-2+3]=diag1_used[3]` 冲突。列 3：列冲突。回溯到第 1 行，第 1 行无剩余列，回溯到第 0 行。
- 第 0 行试列 1：放下。第 1 行试列 3：`path=[1,3]`。第 2 行试列 0：`diag1_used[2-0+3]=diag1_used[5]` 空闲、`diag2_used[2+0]=diag2_used[2]` 空闲，放下。`path=[1,3,0]`。第 3 行试列 2：三个位置全空闲，`path=[1,3,0,2]`，得到一个解 `[".Q..","...Q","Q...","..Q."]`。
- 继续回溯，最终第 0 行试列 2 时得到第二个解 `[2,0,3,1]`，即 `["..Q.","Q...","...Q",".Q.."]`。第 0 行试列 3 时全部剪枝。

两个解与示例一致，且顺序也一致（按第 0 行列号递增枚举）。

## 4. 正确性：为什么不会漏、不会重

**不变量：** 在递归到第 `row` 行之前，`path[0..row-1]` 中任意两个皇后不同列、不同主对角线、不同副对角线，且 `col_used`、`diag1_used`、`diag2_used` 恰好标记了这些皇后占用的列与两条对角线。

**不会漏：** 任何一个合法解，按行看就是一组列号 `c₀, c₁, ..., c_{n-1}`。搜索树在第 0 行会依次尝试所有列，包括 `c₀`；由于合法解中 `c₀` 不与任何后续皇后冲突，第 1 行尝试到 `c₁` 时三个数组都不会拦截它；归纳下去，这条路径上的每一次选择都不会被剪枝，最终必然被枚举到并加入结果。剪枝只剪掉「当前已冲突」的分支，而合法解的任何前缀都不冲突，所以合法解不会被误剪。

**不会重：** 每个解对应唯一的列号序列（第 i 行的列号就是 `path[i]`），而搜索树中每个叶子对应唯一一条从根到叶的路径，不同路径的列号序列必然在某一行不同。因此同一个解只会被生成一次。

**剪枝的合法性：** 三个数组的判定与题面的攻击规则一一对应——同列由 `col_used` 拦截，同主对角线由 `row-col` 相等拦截，同副对角线由 `row+col` 相等拦截。题面只列了这三种攻击方式，没有第四种，所以三个数组覆盖了全部约束。

## 5. 完整代码（Python）

```python
class Solution:
    def solveNQueens(self, n: int) -> list[list[str]]:
        res = []
        path = []                      # path[i] = 第 i 行皇后所在的列号
        col_used = [False] * n         # 列是否被占
        diag1_used = [False] * (2 * n - 1)  # 主对角线 row-col 是否被占，已加偏移 n-1
        diag2_used = [False] * (2 * n - 1)  # 副对角线 row+col 是否被占

        def backtrack(row: int) -> None:
            if row == n:               # 每一行都放好了，path 是一个完整解
                board = []
                for c in path:
                    board.append("." * c + "Q" + "." * (n - 1 - c))
                res.append(board)
                return

            for col in range(n):
                d1 = row - col + n - 1  # 主对角线编号，映射到 0..2n-2
                d2 = row + col          # 副对角线编号，天然在 0..2n-2
                if col_used[col] or diag1_used[d1] or diag2_used[d2]:
                    continue            # 任一约束冲突，本分支剪掉

                # 做选择
                col_used[col] = diag1_used[d1] = diag2_used[d2] = True
                path.append(col)

                backtrack(row + 1)      # 进入下一行

                # 撤销选择，恢复现场
                path.pop()
                col_used[col] = diag1_used[d1] = diag2_used[d2] = False

        backtrack(0)
        return res
```

关键逻辑说明：`backtrack(row)` 的语义是「第 0..row-1 行已经放好且互不冲突，现在为第 row 行选列」。循环内先算两个对角线编号再判断，三个数组任一为 True 就 `continue`，这是剪枝；三个都空闲才修改数组、压入 `path`、递归；递归返回后必须把三处状态和 `path` 原样恢复，否则会影响同一层后续列的尝试。`row == n` 时把 `path` 翻译成字符串棋盘，翻译方式是用 `"." * c + "Q" + "." * (n-1-c)` 拼出长度为 n 的一行。

## 6. 复杂度

**时间：O(n! · n)。** 搜索树的叶子数上界是 n!（第 0 行 n 种、第 1 行至多 n-1 种……），实际因对角线剪枝更少；每个叶子要花 O(n) 把 `path` 翻译成 n 个长度为 n 的字符串，所以是 n! 乘 n。注意这里没有 log n 项——本题不涉及排序或二分，所有判断都是数组下标访问的 O(1)。若只问「找到第一个解」，最坏仍是这个量级，因为可能搜遍整棵树才找到。

**空间：O(n) 递归栈 + O(n²) 输出。** 递归深度为 n，每层常数个局部变量，栈空间 O(n)；三个布尔数组长度分别为 n、2n-1、2n-1，也是 O(n)；`path` 长度 n。输出本身占 O(n²) 每个解，若把结果集算进去则是 O(解的数量 × n²)，通常复杂度分析只算辅助空间，即 O(n)。

## 7. 边界与反例（至少 4 条）

1. **n = 1** → 期望 `[["Q"]]`。容易错在：`diag1_used` 长度为 `2*1-1 = 1`，若写成 `2*n` 虽不越界但偏移量 `n-1 = 0` 必须正确；另外 `row == n` 的终止条件在 n=1 时第一层递归就触发，若把终止条件写成 `row == n-1` 会漏掉最后一行的放置。
2. **n = 2** → 期望 `[]`。容易错在：以为「有 n 行就一定有解」，忘记返回空列表；代码里若在无解时没有正确回溯（比如忘记恢复 `col_used`），会在后续分支产生假解。
3. **n = 3** → 期望 `[]`。容易错在：对角线数组长度按 `2*n-1 = 5` 算，`row-col+n-1` 在 row=2、col=0 时为 4，恰好是最后一个下标，若长度写成 `2*n-2 = 4` 会越界。
4. **n = 4** → 期望两个解，且顺序为 `[1,3,0,2]` 在前、`[2,0,3,1]` 在后。容易错在：把结果顺序当成无关紧要，但力扣按枚举顺序比对；只要按列号从小到大枚举、先递归后回溯，顺序自然正确。
5. **n = 9** → 期望 352 个解。容易错在：以为 n 小就能暴力，实际上 9! 约 36 万，配合剪枝可跑，但若把冲突判断写成遍历已放皇后（O(n) 每次），常数会明显变大；另外结果列表很大，注意不要在每个分支里复制整个棋盘。

## 8. 面试追问与变体（3 条）

1. **追问：只要求返回解的个数，不要求列出棋盘，怎么改？** 思路：把 `res.append(board)` 换成计数器加一，省掉 O(n) 的棋盘翻译，时间降到 O(叶子数)，空间降到 O(n)。
2. **追问：n 很大时（比如 n=12）如何加速？** 思路：用位运算代替三个布尔数组，`col`、`d1`、`d2` 各用一个整数的位表示占用情况，判断和更新都是 O(1) 的位操作，常数更小；进一步可利用棋盘的对称性只搜一半再镜像，但要注意 n 为奇数时中心对称解不能重复计数。
3. **追问：如果棋盘不是正方形，或者皇后攻击规则改成「马步」呢？** 思路：回溯框架不变，变的只是「冲突判定函数」——把三个数组换成对应的攻击关系集合（如马步用 `(row±2, col±1)` 等偏移检查），说明白「搜索结构」与「约束表示」是解耦的。
