## 1. 一句话本质

在只含 `(` 和 `)` 的串里，找**最长的、连续的一段**，使得这段里每个 `)` 都能和它左边某个 `(` 一一配对、且配对不交叉——也就是求「合法括号串」作为子串出现时的最大长度。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子串 `s[i:j]`，对每个子串用栈判一遍是否合法，合法就更新答案。子串有 O(n²) 个，每个判一遍 O(n)，总 O(n³)。即便用「前缀和 + 判非负」把判定降到 O(1)，仍是 O(n²)。n 到 3×10⁴ 时 O(n²) 约 9×10⁸，Python 里必然超时。瓶颈在**枚举子串**这一步。

**关键观察**：合法括号串有一个等价刻画——把它看成 +1（`(`）和 −1（`)`）的序列，则「合法」⟺「所有前缀和 ≥ 0」且「总和 = 0」。这个刻画把「配对」这种结构信息压成了**一个数值序列上的条件**。一旦问题变成「在数值序列上找满足前缀条件的区间」，就自然想到：能不能用一次扫描 + 一个辅助结构，把「以每个位置结尾的最长合法段」直接算出来，而不是枚举起点？

顺着这个方向有两条路：**栈**（记录「上一个无法配对的右括号位置」作为分界）和**动态规划**（`dp[i]` = 以 i 结尾的最长合法长度）。两者都是 O(n)。下面主讲栈，因为它对「分界点」的直觉最直接，DP 作为对照放在第 8 节。

## 3. 从暴力到最优

**第一步：从 O(n³) 到 O(n²)。** 固定右端点 j，从 j 往左扫，维护一个计数器：遇 `)` 加 1，遇 `(` 减 1。若计数器变负，说明左边 `(` 不够了，再往左也没用，直接 break；若计数器归零，说明 `s[i:j+1]` 合法，更新答案。每个 j 最多扫 n 步，总 O(n²)。瓶颈变成「每个右端点都要重新往左扫」。

**第二步：观察「分界点」的复用。** 看例子 `s = ")()())"`，下标 0..5。

用栈存**下标**，栈底先放一个哨兵 `-1`，含义是「最近一个尚未被匹配掉的、可以作为合法段左边界的障碍位置」。

- i=0，`s[0]=')'`：栈顶 -1 是哨兵，弹不出东西，说明这个 `)` 无法配对。把栈清空后压入 0，表示「0 及其左边都不能再作为合法段的起点了」。栈 = [0]。
- i=1，`s[1]='('`：压入 1。栈 = [0, 1]。
- i=2，`s[2]=')'`：弹出 1，配对成功。此时栈顶是 0，当前合法段长度 = 2 − 0 = 2。答案 = 2。栈 = [0]。
- i=3，`s[3]='('`：压入 3。栈 = [0, 3]。
- i=4，`s[4]=')'`：弹出 3，配对成功。栈顶是 0，长度 = 4 − 0 = 4。答案 = 4。栈 = [0]。
- i=5，`s[5]=')'`：栈顶 0 是「障碍」，弹不出有效配对。清空后压入 5。栈 = [5]。

最终答案 4，对应子串 `s[1:5] = "()()"`。注意 i=2 和 i=4 两次算长度，用的都是**同一个栈顶 0**——这就是复用的来源：栈顶那个「最近的障碍」在一次扫描中只被读，不被反复重算。

**第三步：为什么这就消掉了 O(n²)。** 每个下标进栈一次、出栈至多一次，扫描一遍字符串，总操作 O(n)。「往左找起点」这件事被「读栈顶」替代了，而栈顶是 O(1) 拿到的。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。维护栈 `st`，约定：`st` 中存的是「当前尚未被匹配的 `(` 的下标」，外加**恰好一个**位于栈底的「障碍下标」`b`，含义是「`b` 及其左边的所有字符，已经不可能和 `b` 右边任何字符组成合法段」。

不变量在每一步之后成立，理由分两种情形：

- 遇到 `(`：它尚未匹配，压栈，不变量保持。
- 遇到 `)`：若栈中除障碍外还有 `(`，弹出最近的那个，二者配对。配对后，从「新的栈顶 + 1」到「当前下标」这一段，恰好是**以当前下标结尾的最长合法段**。为什么是最长：栈顶是这段左边最近的、还没被配掉的障碍，任何更靠左的起点都会跨过这个障碍，而跨过障碍的段必然含有一个无法配对的 `)`，不合法。若栈中只剩障碍，说明这个 `)` 无人可配，它自己成为新的障碍，清空后压入它的下标。

**不漏**：任何合法子串 `s[l:r+1]`，在处理到 r 时，l−1 一定是当时的栈顶（因为 l−1 要么是障碍，要么是一个未匹配的 `(`，而 l..r 内部全部配对完毕、不会残留在栈里）。于是长度 `r − (l−1)` 会被算到，不会漏。

**不重**：每个右端点 r 只在「成功配对」那一步算一次长度，且算的是以 r 结尾的最长合法段；最终取 max，重复计算不影响正确性，也不存在把非法段算进去的可能——长度公式只在配对成功时使用，而配对成功保证了该段前缀和恒 ≥ 0、总和为 0。

## 5. 完整代码（Python）

```python
class Solution:
    def longestValidParentheses(self, s: str) -> int:
        # 栈存下标；栈底哨兵 -1 表示「最近一个无法配对的障碍位置」
        st = [-1]
        ans = 0
        for i, ch in enumerate(s):
            if ch == '(':
                # 左括号尚未匹配，压入等待配对
                st.append(i)
            else:
                # 右括号：先弹出栈顶（可能是配对的左括号，也可能是障碍）
                st.pop()
                if not st:
                    # 栈空了，说明这个 ')' 无人可配，它成为新的障碍
                    st.append(i)
                else:
                    # 栈非空：栈顶是当前合法段的左边界（障碍）
                    ans = max(ans, i - st[-1])
        return ans
```

关键点：`st.pop()` 无条件执行，是因为栈里至少有一个元素（初始哨兵或之前压入的障碍），弹出后若为空，说明弹出的正是障碍，当前 `)` 无法配对，于是把它自己作为新障碍压回。这个「先弹再判空」的写法把「配对」和「换障碍」统一成一条路径，是这段代码最容易被写错的地方。

## 6. 复杂度

- **时间 O(n)**：`for` 循环执行 n 次（n = `len(s)`），每次循环内 `append`/`pop`/比较/取 max 都是 O(1)。每个下标至多进栈一次、出栈一次，所以栈操作总量 O(n)。没有嵌套循环，也没有排序，故无 log 项。
- **空间 O(n)**：栈最多存 n+1 个下标（全为 `(` 时，加上初始哨兵）。这是最坏情况；实际占用取决于未匹配 `(` 的个数。

## 7. 边界与反例（至少 4 条）

1. `s = ""` → 期望 `0` → 容易错在没处理空串：代码里 `st=[-1]`，循环不执行，返回 0，正确；但若手写时先取 `s[0]` 就会崩。
2. `s = "("` → 期望 `0` → 容易错在把「有左括号」当成「有合法段」；代码中该 `(` 进栈后无人弹出，`ans` 始终 0。
3. `s = ")"` → 期望 `0` → 容易错在 `st.pop()` 后栈空却忘了压回障碍，导致后续（若有）长度算错；本例返回 0 正确，但它是检验「先弹再判空」逻辑的最小用例。
4. `s = "()(()"` → 期望 `2` → 容易错在把 `"()(("` 里最后两个 `(` 误算进长度；代码在 i=1 配对得长度 2，之后两个 `(` 只进栈不出栈，答案保持 2。
5. `s = "()(())"` → 期望 `6` → 容易错在只算最内层 `"()"`；代码在最后一个 `)` 处栈顶为 -1，长度 = 5 − (−1) = 6，正确覆盖嵌套情形。

## 8. 面试追问与变体（3 条）

1. **追问：不用栈，用 DP 怎么做？** 思路：`dp[i]` 表示以 i 结尾的最长合法长度。若 `s[i]=')'` 且 `s[i-1]='('`，则 `dp[i]=dp[i-2]+2`；若 `s[i-1]=')'` 且 `s[i-dp[i-1]-1]='('`，则 `dp[i]=dp[i-1]+2+dp[i-dp[i-1]-2]`。答案取 `max(dp)`，O(n) 时间 O(n) 空间。
2. **追问：能否 O(1) 空间？** 思路：正反各扫一遍，用两个计数器 `left`、`right`。正向扫时 `left==right` 更新答案、`right>left` 清零；反向扫对称处理，解决 `"((())"` 这类正向漏掉的情况。
3. **追问：如果要求返回最长合法子串本身而非长度？** 思路：栈里存下标的同时，在每次成功配对时记录 `(栈顶+1, i)` 这个区间，最后取最长者对应的切片。
