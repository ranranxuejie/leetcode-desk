## 1. 一句话本质

对每个位置 i，求「右边第一个严格大于它的元素」与它的下标距离；找不到就记 0。

## 2. 读完题的第一反应

最直白的做法：对每个 i，从 i+1 开始往右扫，遇到第一个比 `temperatures[i]` 大的就停下，记下距离。这个做法在**最坏情况**下是 O(n²)——比如温度单调不增 `[90,89,88,...]`，每个位置都要扫到数组末尾才发现没有更高温度。n 最大 10^5，10^10 次操作必然超时。

关键观察来自一个反问：**暴力法里，哪些扫描是白做的？**

看 `[73,74,75,71,69,72,76,73]`。算第 3 天（75）的答案时，我们扫过 71、69、72、76，发现 76 更大，答案是 4。注意：**71 和 69 的答案，其实在这次扫描中已经顺带知道了**——它们右边第一个更大值也是 76。暴力法把它们的信息算完就扔了，下一次又要从头扫。

所以真正的问题是：**能不能让「还没找到答案的那些天」排好队，等一个更大的温度出现时，一次性把它们全部结算掉？** 这个「排队等结算」的结构，就是单调栈。而「排队」的顺序必须是温度从栈底到栈顶递减——因为如果栈里出现「下面的比上面的小」，说明下面那个早就该被上面那个结算了，它不该还留在栈里。

## 3. 从暴力到最优

**暴力**：外层 i 遍历 n 天，内层 j 从 i+1 往右找。瓶颈是内层重复扫描，O(n²)。

**消瓶颈的思路**：维护一个栈，存的是「**下标**」，并且保证这些下标对应的温度**从栈底到栈顶严格递减**。含义是：这些天都还没找到更高的温度，而且越靠栈顶的天越「矮」、越容易被后面的温度满足。

遍历到第 i 天，温度 t = temperatures[i]：

- 只要栈非空且栈顶那天的温度 < t，说明栈顶那天终于等到了它的答案，弹出它，`answer[栈顶] = i - 栈顶`。**注意这一步可能连续弹多次**，因为 t 可能一次满足好几个矮天。
- 弹完后把 i 压栈。

拿示例 1 走一遍，`temperatures = [73,74,75,71,69,72,76,73]`，answer 初始全 0：

| i | t | 弹栈过程 | 栈（存下标，对应温度） | answer 变化 |
|---|---|---|---|---|
| 0 | 73 | 无 | [0] (73) | — |
| 1 | 74 | 73<74，弹 0，ans[0]=1-0=1 | [1] (74) | ans[0]=1 |
| 2 | 75 | 74<75，弹 1，ans[1]=2-1=1 | [2] (75) | ans[1]=1 |
| 3 | 71 | 75>71，不弹 | [2,3] (75,71) | — |
| 4 | 69 | 71>69，不弹 | [2,3,4] (75,71,69) | — |
| 5 | 72 | 69<72 弹 4，ans[4]=5-4=1；71<72 弹 3，ans[3]=5-3=2；75>72 停 | [2,5] (75,72) | ans[4]=1, ans[3]=2 |
| 6 | 76 | 72<76 弹 5，ans[5]=6-5=1；75<76 弹 2，ans[2]=6-2=4 | [6] (76) | ans[5]=1, ans[2]=4 |
| 7 | 73 | 76>73，不弹 | [6,7] (76,73) | — |

最终 `answer = [1,1,4,2,1,1,0,0]`，和示例一致。剩下栈里的 6、7 没被弹过，answer 保持 0，正好对应「之后不会升高」。

对比暴力：第 3、4 天的答案是在 i=5 那一步被**一次性**结算的，没有各自再扫一遍。每个下标只进栈一次、出栈一次，总操作 O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。遍历到第 i 天之前，栈满足：

> **不变量**：栈中下标对应的温度从栈底到栈顶严格递减；且栈中每个下标 j 的 answer 尚未确定，即 j 右边到 i-1 为止没有比 temperatures[j] 更大的值。

**为什么成立（归纳）**：
- 初始空栈，平凡成立。
- 处理第 i 天时，若栈顶 j 满足 temperatures[j] < temperatures[i]，则 i 就是 j 右边第一个更大值：因为 j 入栈后一直没被弹出，说明 j 到 i-1 之间没有任何值大于 temperatures[j]（否则 j 早被弹了），而 i 是第一个。所以 `answer[j] = i - j` 是**正确且唯一**的答案，弹出它不会漏也不会重。
- 弹完后，栈顶温度 ≥ temperatures[i]（或栈空），把 i 压栈后递减性仍保持；且 i 的答案未定，因为刚检查过它前面没有更大值。不变量恢复。

**为什么「第一个」不会错**：弹出条件用的是 `<`（严格小于），所以温度相等时不弹。这正好对应题面「下一个**更高**温度」——相等不算更高。如果误写成 `<=`，`[73,73,74]` 就会把第 0 天的答案错算成 1（实际应是 2）。

**为什么不会漏**：每个下标入栈时答案未定，出栈时答案被正确赋值；遍历结束后仍在栈里的，说明右边确实没有更大值，answer 保持初值 0，符合题意。

## 5. 完整代码（Python）

```python
class Solution:
    def dailyTemperatures(self, temperatures: list[int]) -> list[int]:
        n = len(temperatures)
        answer = [0] * n          # 默认 0：右边没有更高温度时正好是答案
        stack = []                # 存下标，对应温度从栈底到栈顶严格递减

        for i, t in enumerate(temperatures):
            # 当前温度 t 可能一次性结算多个「矮天」，所以用 while 而不是 if
            while stack and temperatures[stack[-1]] < t:
                j = stack.pop()   # j 是还没找到答案、且比 t 矮的那天
                answer[j] = i - j # i 就是 j 右边第一个更高温度的下标
            stack.append(i)       # 当前这天还没找到答案，入栈等待

        return answer
```

关键点只有三处：栈里存**下标**（因为要算距离）、比较用**严格小于**、结算用 **while**（一次可能弹多个）。

## 6. 复杂度

- **时间 O(n)**：外层 for 循环执行 n 次；内层 while 的每次迭代都弹出一个下标，而每个下标最多入栈一次、出栈一次，所以 while 的总迭代次数 ≤ n。两者相加是 O(n)，不是 O(n²)——这是「均摊分析」的典型结论：单次 while 可能弹很多，但把整个循环摊开看，总弹出次数被入栈次数卡住。
- **空间 O(n)**：`answer` 数组占 n；`stack` 最坏情况（温度单调不增，如 `[90,89,...,30]`）会存下全部 n 个下标。所以是 O(n) + O(n) = O(n)。这里没有 log n 项，因为没有任何分治或二分。

## 7. 边界与反例（至少 4 条）

1. **输入 `[30]`** → 输出 `[0]`。容易错：忘了单元素时栈里会留一个下标，若代码在循环外错误地给残留下标赋非 0 值就错了。本题残留即 0，天然正确，但要意识到这一点。
2. **输入 `[30,30,30]`** → 输出 `[0,0,0]`。容易错：把弹出条件写成 `<=`，会得到 `[1,1,0]`。相等不是「更高」。
3. **输入 `[90,89,88,87]`（单调递减）** → 输出 `[0,0,0,0]`。容易错：这是暴力法的最坏情况，也是单调栈的**最坏空间**情况（栈里堆满 n 个元素）。若用递归或额外深拷贝，可能爆栈/超内存。
4. **输入 `[30,40,50,60]`（单调递增）** → 输出 `[1,1,1,0]`。容易错：每次 while 只弹一个，容易让人误以为「用 if 就够了」；但示例 1 的 i=5、i=6 证明必须用 while。
5. **输入 `[73,74,75,71,69,72,76,73]`** → 输出 `[1,1,4,2,1,1,0,0]`。容易错：第 2 天的答案是 4 而不是 1，因为 76 在很后面；手算时容易只看相邻。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求「下一个更高或相等的温度」怎么办？** 思路：把弹出条件从 `<` 改成 `<=`，其余不变——语义变了，栈的递减性变成「非严格递减」。
2. **追问：如果数组是循环的（首尾相接），怎么求？** 思路：把数组复制一遍接在后面（长度 2n），遍历 2n 次但只对前 n 个下标写答案；或者用取模 `i % n` 访问，栈里仍存原始下标。
3. **追问：不用栈，能不能 O(n) 做？** 思路：从右往左扫，维护一个「候选下标」的单调栈（栈顶是最近的更高候选），对每个 i 弹掉比它矮的，栈顶即答案；本质是同一单调栈的镜像写法，可用来检验你是否真理解不变量。
