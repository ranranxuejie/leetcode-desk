## 1. 一句话本质

在 n 个「把数组循环左移后、用下标 0..n-1 加权求和」的结果里找最大值，而相邻两个结果之间只差一个可以用 O(1) 算出来的量，所以不必真的旋转 n 次。

## 2. 读完题的第一反应

**朴素解法**：对每个 k 从 0 到 n-1，真的把数组旋转 k 位（或等价地用 `(i+k) % n` 取元素），再按定义累加 `i * arr_k[i]`。每个 k 要扫 n 个元素，总共 O(n²)。n 最大 10^5，10^10 次操作，必然超时。瓶颈很清楚：**每个 k 都从头重算了一遍**，而相邻两个 k 的结果其实高度相似。

**关键观察**：把 F(k) 和 F(k+1) 写出来对比。旋转一位，本质是「最后一个元素跑到最前面」，其余元素的下标全部 +1。于是：

- 原来下标 i 的元素（i ≥ 1）在新数组里下标变成 i+1，贡献从 `i * x` 变成 `(i+1) * x`，**每个元素多贡献了一份自己的值**；
- 原来下标 0 的元素被挤到最后，下标从 0 变成 n-1，贡献从 `0` 变成 `(n-1) * x`，**多贡献了 (n-1) 份**；
- 原来下标 n-1 的元素跑到下标 0，贡献从 `(n-1) * x` 变成 `0`，**少了 (n-1) 份**。

把这三条合起来，增量只和「所有元素之和」以及「被移动的那个元素」有关。这就是能想到下一步的钩子：**F(k+1) 可以由 F(k) 加一个 O(1) 的修正量得到**，于是整体从 O(n²) 降到 O(n)。

## 3. 从暴力到最优

先明确旋转方向。题面说「顺时针旋转 k 个位置」，而示例里 F(1) 用的数组是 `[6,4,3,2]`——原数组 `[4,3,2,6]` 的最后一个元素 6 移到了最前面。所以这里的「顺时针旋转」等价于**循环右移**：`arr_k[i] = nums[(i - k) mod n]`。下文都按这个方向推，代码也按这个方向写。

设 `S = sum(nums)`，`F(k) = Σ i * arr_k[i]`。

从 F(k) 到 F(k+1)：`arr_{k+1}` 是把 `arr_k` 的最后一个元素挪到最前面。记 `last = arr_k[n-1]`（它等于 `nums[(n-1-k) mod n]`）。

- 下标 0..n-2 的元素：下标各 +1，贡献增加 `Σ_{i=0}^{n-2} arr_k[i] = S - last`；
- 下标 n-1 的元素 last：下标变成 0，贡献减少 `(n-1) * last`。

所以

```
F(k+1) = F(k) + (S - last) - (n-1) * last
       = F(k) + S - n * last
```

用示例 `nums = [4,3,2,6]`，`S = 15`，`n = 4` 走一遍：

- `F(0) = 0*4 + 1*3 + 2*2 + 3*6 = 25`，此时 `last = nums[3] = 6`；
- `F(1) = 25 + 15 - 4*6 = 25 + 15 - 24 = 16` ✓（与题面一致），此时 `last = nums[2] = 2`；
- `F(2) = 16 + 15 - 4*2 = 16 + 15 - 8 = 23` ✓，此时 `last = nums[1] = 3`；
- `F(3) = 23 + 15 - 4*3 = 23 + 15 - 12 = 26` ✓，此时 `last = nums[0] = 4`。

注意 `last` 的取法：第 k 步要挪的是 `arr_k` 的末尾，也就是 `nums[(n-1-k) mod n]`。k 从 0 走到 n-2 即可，因为 F(n) 会回到 F(0)，不需要再算。

瓶颈怎么被消掉的：暴力里「每个 k 重扫 n 个元素」被替换成「每个 k 做一次加减乘」，O(n) 次 O(1) 操作。初始的 F(0) 和 S 各扫一遍数组，也是 O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。维护的不变量是：

> 在第 k 轮迭代开始时，变量 `cur` 恰好等于 F(k)，且 `last = nums[(n-1-k) mod n]` 恰好等于 `arr_k[n-1]`。

**初始**：k=0 时，`cur` 由定义式直接算出，等于 F(0)；`arr_0 = nums`，其末尾是 `nums[n-1]`，与 `(n-1-0) mod n = n-1` 一致。不变量成立。

**保持**：假设第 k 轮开始时不变成立。由第 3 节的推导，`F(k+1) = F(k) + S - n * arr_k[n-1]`，代码用 `cur + S - n * last` 更新 `cur`，得到的就是 F(k+1)。同时 `arr_{k+1}` 的末尾是 `arr_k` 的倒数第二个元素，即 `nums[(n-2-k) mod n] = nums[(n-1-(k+1)) mod n]`，代码把 `last` 更新为 `nums[n-1-k]`（k 从 0 起，索引不越界，因为循环只到 n-2），与不变量一致。

**终止**：循环跑完 k = 0..n-2，`cur` 依次取遍 F(0), F(1), ..., F(n-1)，每次更新后与当前最大值比较，所以最大值不会漏。又因为每个 F(k) 恰好被访问一次，也不存在重复计数导致的错误——重复计数本身不影响 max，但这里连「重」都没有。

**为什么不需要 F(n)**：`arr_n` 就是把数组转回原样，`F(n) = F(0)`，已在初始时计入，再算一遍是冗余。

## 5. 完整代码（Python）

```python
class Solution:
    def maxRotateFunction(self, nums: list[int]) -> int:
        n = len(nums)
        total = sum(nums)          # S，后续每步的修正量都要用

        # 先按定义算 F(0) = 0*nums[0] + 1*nums[1] + ... + (n-1)*nums[n-1]
        cur = 0
        for i, x in enumerate(nums):
            cur += i * x

        best = cur                 # 目前见过的最大值，先放 F(0)

        # 从 F(k) 推到 F(k+1)，k 取 0..n-2，共 n-1 次
        # 第 k 步要挪的是 arr_k 的末尾，即 nums[n-1-k]
        for k in range(n - 1):
            last = nums[n - 1 - k]         # arr_k[n-1]
            cur = cur + total - n * last   # F(k+1) = F(k) + S - n*last
            if cur > best:
                best = cur

        return best
```

几个容易写错的点，代码里已经规避：`last` 用 `nums[n-1-k]` 而不是 `nums[k]`（方向别搞反）；循环次数是 `n-1` 不是 `n`；`best` 的初值必须是 F(0) 而不是 0（数组全负时 F(0) 可能为负，答案也可能是负的，初值 0 会错）。

## 6. 复杂度

- **时间 O(n)**：`sum(nums)` 一次 O(n)；算 F(0) 的循环 O(n)；主循环 n-1 次，每次 O(1)。三项相加仍是 O(n)。没有 log 项——本题不涉及排序或二分。
- **空间 O(1)**：只用了 `total`、`cur`、`best`、`last` 几个标量，没有额外开数组。注意不要为了「方便」去真的构造旋转后的数组，那会变成 O(n) 空间且常数更大。

## 7. 边界与反例（至少 4 条）

1. **`nums = [100]`** → 期望 `0`。n=1 时 F(0) = 0*100 = 0，主循环 `range(0)` 一次都不跑，直接返回 0。容易错在：以为要进循环，或把 `best` 初值设成 `-inf` 之外的奇怪值。
2. **`nums = [-1,-2,-3]`** → 期望 `-2`。F(0) = 0*(-1)+1*(-2)+2*(-3) = -8；F(1) 对应 `[-3,-1,-2]`，= 0*(-3)+1*(-1)+2*(-2) = -5；F(2) 对应 `[-2,-3,-1]`，= 0*(-2)+1*(-3)+2*(-1) = -5。等等，重算：S = -6，F(1) = -8 + (-6) - 3*(-3) = -8 - 6 + 9 = -5；F(2) = -5 + (-6) - 3*(-2) = -5 - 6 + 6 = -5。最大值是 -5。**易错点**：`best` 初值若写 0，会返回 0，错。全负数时答案必为负。
3. **`nums = [0,0,0]`** → 期望 `0`。所有 F(k) 都是 0，`best` 初值 0 恰好对，但这是巧合，不能因此把初值写成 0。
4. **`nums = [1,1,1,1]`** → 期望 `6`。F(0) = 0+1+2+3 = 6，任何旋转后数组不变，所有 F(k) = 6。易错点：`last` 索引方向写反（写成 `nums[k]`）时，因为元素全相同看不出错，换个数组就崩。
5. **`nums = [4,3,2,6]`** → 期望 `26`。这是官方示例，用来验证 `last` 的取法：第 0 步 `last = nums[3] = 6`，第 1 步 `last = nums[2] = 2`，第 2 步 `last = nums[1] = 3`。若把 `last` 写成 `nums[k]`，会得到 `last = 4, 3, 2`，结果全错。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回取得最大值的那个 k（下标），怎么改？** 思路：在更新 `best` 时同步记录当前的 k+1（注意 F(0) 对应 k=0），其余不变，仍是 O(n)。
2. **追问：如果旋转方向反过来（循环左移），递推式怎么变？** 思路：左移一位是把首元素挪到末尾，`F(k+1) = F(k) - S + n * nums[k]`（符号和取的元素都反过来），推导方式完全对称，面试时现场推一遍即可。
3. **追问：如果 n 很大但只问 F(k) 单点值，不要求最大值呢？** 思路：单点可以直接用 `Σ i * nums[(i-k) mod n]` 算，O(n)；但若问多个 k，仍应预处理 S 和 F(0) 后用递推，把每个查询降到 O(1)（离线按 k 排序或直接全算一遍）。
