## 1. 一句话本质

对每个节点判断「从根到它的路径和 + 它子树里任意一条到叶子的路径和」是否**全都**小于 limit，全都小于就把它整棵子树砍掉——本质是一次**自底向上的后序判定**：一个节点该不该删，取决于它删完之后剩下的孩子。

## 2. 读完题的第一反应

**朴素解法**：对每个节点，枚举它下面所有根-叶路径，逐条求和，判断是否全部 < limit。树有 n 个节点，最坏情况（链状树）每个节点下面有 O(n) 条路径，总复杂度 O(n²)。n 到 5000 时 2500 万次操作，勉强能过，但这不是面试官想看的——而且它把「同一个子树被反复遍历」这件事暴露得很明显。

**关键观察**：题面说「通过 node 的每种可能的根-叶路径」——注意路径是**从根出发**的。但如果我们换个视角：设 `s` 为从根到 node 的路径和（不含 node 自己，或含，取决于约定），那么「经过 node 的某条根-叶路径和」= `s + (node 到某叶子的路径和)`。也就是说，**每条路径的和都可以拆成「根到 node 的前缀」+「node 到叶的后缀」**。

这个拆分带来两个直接后果：

1. 前缀 `s` 在从根往下走的过程中是**单调累积**的，一次 DFS 就能带着走，不需要每个节点重新算。
2. 后缀「node 到叶的最大路径和」只跟 node 的子树有关，跟上面长什么样无关——这正是**后序 DFS 能返回的东西**。

于是「枚举所有路径」退化成「每个节点只算一个数：它子树内的最大后缀和」。瓶颈从 O(n²) 消到 O(n)。

再补一个容易忽略的点：删除是**连锁**的。一个节点删掉后，它的父节点可能从「有孩子」变成「叶子」，判定条件随之改变。所以必须**先处理孩子、再判定自己**——这就是后序（自底向上）的由来，不是随便选的遍历顺序。

## 3. 从暴力到最优

**暴力**：对每个节点 u，收集 u 子树内所有叶子，对每个叶子算 `root→u 前缀和 + u→leaf 后缀和`，若全部 < limit 则删 u 子树。复杂度 O(n²)。

**瓶颈在哪**：u 的子树被它的每个祖先各扫一遍，同一批叶子被重复访问 O(深度) 次。

**消瓶颈**：让 DFS 函数**返回**「以当前节点为起点、往下走到某个叶子的最大路径和」。父节点拿到两个孩子的返回值，取 `max(左, 右) + 自己的值`，就得到了自己的最大后缀和，完全不用再往下扫。

**小例子走一遍**，用示例 3：`root = [1,2,-3,-5,null,4,null]`，`limit = -1`。

树结构：
```
        1
       / \
      2   -3
     /    /
   -5    4
```

后序 DFS，函数返回「以该节点为起点的最大下行路径和」，同时做删除：

- 节点 -5：叶子，最大下行和 = -5。它是叶子且 -5 < limit(-1)？**是**，删除，返回 -∞（表示「我这条路已经不存在了」）。
- 节点 2：左孩子被删（返回 -∞），右孩子为空。此时 2 变成叶子。它的最大下行和 = 2（只有自己）。2 < -1？否，保留，返回 2。
- 节点 4：叶子，4 < -1？否，保留，返回 4。
- 节点 -3：左孩子 4 返回 4，右空。最大下行和 = -3 + 4 = 1。1 < -1？否，保留，返回 1。
- 节点 1：左孩子 2 返回 2，右孩子 -3 返回 1。最大下行和 = 1 + max(2, 1) = 3。3 < -1？否，保留，返回 3。

结果：`[1, null, -3, 4]`，与示例 3 一致。注意 -5 被删后，2 从「有孩子」变成「叶子」，判定用的是**新的**叶子身份——这就是后序的必要性。

**为什么用「最大」而不是「全部」**：题面要求「每种路径全都小于 limit」才删。取反就是「只要存在一条路径 ≥ limit 就保留」。而「存在一条 ≥ limit」等价于「最大那条 ≥ limit」。所以每个节点只需要维护**一个**最大值，不需要维护所有路径——这是把 O(路径数) 压到 O(1) 的关键一步。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。定义 DFS(u) 的契约：

> 调用前：u 的子树尚未做任何删除判定。
> 调用后：u 的子树中所有「不足节点」已被删除；若 u 自身被删则返回 -∞，否则返回「以 u 为起点、到 u 子树内某叶子的最大路径和」。

**归纳证明**（对子树高度归纳）：

- **基**：u 是叶子。没有孩子，u 子树内只有它自己一条「路径」。若 `u.val < limit` 则删（返回 -∞），否则保留（返回 `u.val`）。契约成立。
- **归纳**：设左右孩子调用后契约成立。分两种情况：
  - 两个孩子都返回 -∞（或不存在）：u 在删除后成为叶子。此时「经过 u 的根-叶路径」只剩 u 自己这一条，判定 `u.val < limit` 即可，与基一致。
  - 至少一个孩子返回有限值 m：u 保留时，经过 u 的每条路径 = 前缀 + u.val + 某孩子的下行路径。这些路径全部 < limit ⟺ `u.val + max(左返回, 右返回) < limit`（因为 max 那条最大，它都 < limit 则全部 < limit）。若成立则删 u，否则保留并返回 `u.val + max(...)`。契约成立。

**不漏**：归纳保证每个节点都被判定一次，且判定时它的子树已处理完，用的是删除后的真实结构。
**不重**：每个节点只被父节点调用一次，DFS 树是原树，无环，不存在重复访问。

**一个容易踩的坑**：不能先判定 u 再处理孩子。因为 u 的孩子可能被删，删完后 u 可能变成叶子，判定条件从「u.val + max(孩子)」退化成「u.val」。顺序反了就会用旧结构做判定，示例 3 的节点 2 就是活证据。

## 5. 完整代码（Python）

```python
class Solution:
    def sufficientSubset(self, root, limit):
        # 返回：以 node 为起点的最大下行路径和；
        # 若 node 被删除，返回 None（用 None 表示「此路不通」）
        def dfs(node, acc):
            # acc = 从根到 node 的父节点为止的路径和（不含 node）
            if node is None:
                return None  # 空子树没有路径

            # 当前节点作为「根-叶路径」终点时的总和
            cur = acc + node.val

            # 叶子：直接判定
            if node.left is None and node.right is None:
                if cur < limit:
                    return None  # 删除该叶子
                return node.val  # 保留，返回以它为起点的下行和

            # 非叶子：先处理孩子（后序）
            left_max = dfs(node.left, cur) if node.left else None
            right_max = dfs(node.right, cur) if node.right else None

            # 孩子被删后，把指针置空，保证返回的树结构正确
            if left_max is None:
                node.left = None
            if right_max is None:
                node.right = None

            # 孩子都被删了 → node 变成叶子，用 cur 判定
            if left_max is None and right_max is None:
                if cur < limit:
                    return None
                return node.val

            # 至少一个孩子存活：取较大的下行和
            best_child = max(
                left_max if left_max is not None else float('-inf'),
                right_max if right_max is not None else float('-inf'),
            )
            # 经过 node 的最大根-叶路径和 = acc + node.val + best_child
            if cur + best_child < limit:
                return None  # node 是不足节点，整棵子树删掉
            return node.val + best_child  # 返回以 node 为起点的最大下行和

        # 根也可能被删，此时返回 None
        if dfs(root, 0) is None:
            return None
        return root
```

关键点：`dfs` 返回的是「以当前节点为起点的最大下行和」，而判定用的是 `acc + node.val + best_child`（完整路径和）。两者差一个 `acc`，别混。另外 `node.left = None` 的赋值必须在判定之前完成，否则返回的树里还挂着已删的子树。

## 6. 复杂度

- **时间 O(n)**：每个节点恰好被 `dfs` 访问一次，节点内做常数次比较和赋值。n 来自节点数，没有额外的 log 因子——因为这不是平衡树上的分治，而是对整棵树的一次线性遍历，树退化成链也是 O(n)。
- **空间 O(h)**：h 为树高，来自递归调用栈。最坏（链状树）h = n，即 O(n)；最好（平衡树）h = log n。题目 n ≤ 5000，递归深度 5000 在 Python 默认递归限制（约 1000）之外，**实际提交时需要 `sys.setrecursionlimit` 或改迭代**——这是这道题在 Python 里最容易被忽略的工程细节。

## 7. 边界与反例（至少 4 条）

1. **单节点树，值 ≥ limit**：`root=[5], limit=5` → 输出 `[5]`。容易错在把 `<` 写成 `<=`，把恰好等于的节点误删。题面是「全都小于」才删，等于要保留。
2. **单节点树，值 < limit**：`root=[5], limit=6` → 输出 `[]`（空树）。容易错在没处理「根被删」的情况，直接返回 root 导致返回了本该删掉的节点。
3. **删除连锁导致父变叶**：`root=[1,2,-3,-5,null,4,null], limit=-1` → 输出 `[1,null,-3,4]`。容易错在先判定父再处理孩子，节点 2 会被当成「有孩子的内部节点」用旧结构判定。
4. **全负值 + 负 limit**：`root=[-1,-2,-3], limit=-5` → 输出 `[-1,-2,-3]`（每条路径和 -3、-4 都 ≥ -5）。容易错在把「路径和」当成「节点值」比较，或者用 `max` 时把 `-inf` 和真实负值搞混。
5. **一侧孩子被删、另一侧存活**：`root=[1,2,3], limit=3` → 左路径 1+2=3 ≥ 3 保留，右路径 1+3=4 ≥ 3 保留，输出原树。若 limit=4，左路径 3 < 4 删 2，右路径 4 ≥ 4 保留，输出 `[1,null,3]`。容易错在删完一侧后忘了把 `node.left` 置 `None`，返回的树里还挂着幽灵节点。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求「路径和严格大于 limit 才保留」，代码怎么改？** 一句话思路：把所有 `< limit` 改成 `<= limit`，判定条件整体翻转，其余结构不变。
2. **追问：不用递归怎么写？** 一句话思路：显式栈做后序（或 Moris 遍历），栈里存 `(node, acc, 状态)`，第二次弹出时用孩子的返回值做判定，逻辑与递归一一对应。
3. **追问：如果 limit 是每个叶子各自不同的（给每个叶子一个阈值）？** 一句话思路：DFS 返回值从「最大下行和」改成「到各叶子的下行和集合」或「满足各自阈值所需的最小前缀」，判定从单值比较变成集合比较，复杂度可能升到 O(n·叶子数)。

## 9. 举一反三（2-3 道同类题）

- **LeetCode 112. 路径总和**：同样沿根到叶累积路径和，区别是只问「是否存在」一条等于 target 的路径，不需要后序删除。
- **LeetCode 814. 二叉树剪枝**：同样是后序删除，区别是判定条件是「子树里有没有 1」而不是路径和，返回布尔值而非最大和。
- **LeetCode 1325. 删除给定值的叶子节点**：同样是「删完孩子后父可能变叶」的连锁删除，区别是判定条件是节点值等于 target，且需要反复删到稳定。
