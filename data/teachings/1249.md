## 1. 一句话本质

在保证「每个右括号左边有足够的未匹配左括号」这一约束下，找出**必须被删掉的那些括号**（多余的右括号 + 最终没被配对的左括号），其余字符原样保留。

## 2. 读完题的第一反应

**朴素解法**：枚举所有删除方案，删最少的括号使结果合法。字符串长度到 10^5，子集枚举是 2^n，直接爆炸。即使退一步，先求「最少删几个」再构造，也没有天然的多项式枚举方式。

**关键观察**：括号是否合法，只取决于**每个前缀里左括号数量是否不少于右括号数量**，以及**全局左右数量相等**。也就是说，一个右括号如果出现在「它左边已经没有可配对的左括号」的位置，它就一定得删——这不是选择，是强制。同理，扫描结束后还剩下的左括号，也一定得删。

为什么这个观察能直接给出下一步？因为它把「删哪些」从**组合优化**变成了**一次线性扫描中的记账**：从左往右走，遇到 `(` 就记下来（它可能配对一个未来的 `)`），遇到 `)` 就尝试消耗一个记账的 `(`；消耗不到，说明这个 `)` 是多余的，标记删除。扫完以后，账上还没被消耗的 `(` 也是多余的，标记删除。剩下的字符拼起来就是答案。

这里有个容易忽略的点：题目说「返回任意一个合法字符串」，所以**不需要**去纠结删哪个左括号更优——所有「多余的」括号删掉后，剩下的必然合法，且删除数量最少（下面第 4 节证明）。

## 3. 从暴力到最优

**暴力**：枚举删除集合 → 检查合法性 → 取最小。瓶颈在枚举，O(2^n · n)。

**第一步优化：只删「必然多余」的括号。** 一个 `)` 如果左边没有未配对的 `(`，它无论怎么删别的字符都救不回来（删掉它左边的 `(` 只会让它更没救），所以必须删。这一步把「选哪些删」变成「扫描时判定」。

**第二步优化：用栈记录未配对的 `(` 的下标。** 为什么存下标而不是只存计数？因为最后要把这些位置标记为删除，需要知道「删哪里」。存计数只能算出删几个，构造不出字符串。

**小例子走一遍**：`s = "a)b(c)d"`，下标 0..6。

| 下标 | 字符 | 栈（存 `(` 下标） | 标记删除 |
|---|---|---|---|
| 0 | a | [] | — |
| 1 | ) | [] | 栈空，删下标 1 |
| 2 | b | [] | — |
| 3 | ( | [3] | — |
| 4 | c | [3] | — |
| 5 | ) | [] | 弹出 3，配对成功 |
| 6 | d | [] | — |

扫描结束栈为空，没有残留左括号。删除集合 = {1}，结果 `"ab(c)d"`，与示例一致。

再看 `s = "))(("`：

| 下标 | 字符 | 栈 | 删除 |
|---|---|---|---|
| 0 | ) | [] | 删 0 |
| 1 | ) | [] | 删 1 |
| 2 | ( | [2] | — |
| 3 | ( | [2,3] | — |

扫完栈里剩 [2,3]，这两个 `(` 也删。删除集合 = {0,1,2,3}，结果 `""`，与示例一致。

**瓶颈怎么被消掉的**：枚举的 2^n 被「必然多余」的判定消掉；判定本身用栈做到每个字符 O(1)，总 O(n)。构造答案时再扫一遍原串，跳过删除集合，O(n)。空间是栈 + 删除标记，O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。

**不变量**：扫描到位置 i 时，栈中保存的是「前缀 s[0..i] 中所有尚未被配对的 `(` 的下标」，且这些 `(` 按出现顺序排列。

- 初始 i = -1，栈空，成立。
- 遇到 `(`：它暂时没配对，压栈，不变量保持。
- 遇到 `)`：若栈非空，栈顶那个 `(` 是**离它最近的未配对左括号**，用它配对是合法的（中间没有未配对的 `(` 挡着，且这个 `)` 左边确实有可用的 `(`）；弹出后不变量保持。若栈空，说明这个 `)` 左边所有 `(` 都已被更早的 `)` 用掉了，它没有任何可配对的左括号，必须删——这是「漏不掉」的关键。
- 遇到字母：不影响括号配对，不变量保持。

**扫描结束后**，栈里剩下的 `(` 是「在整个串里找不到配对右括号」的左括号，必须删。**不会重**：每个 `)` 最多被判定一次（要么配对弹出，要么标记删除），每个 `(` 最多被压栈一次、弹出或残留一次，删除集合里没有重复下标。

**最少性（交换论证）**：设我们删了集合 D。对任意合法解 D'，考虑任意一个被我们标记删除的 `)`（位置 j，扫描到它时栈空）。在 D' 中，要么 j 被删，要么 j 保留——若保留，则 s[0..j] 中必须有一个 `(` 与它配对，但扫描到 j 时栈空意味着 s[0..j] 中所有 `(` 都已被更早的 `)` 消耗，矛盾。所以每个这样的 `)` 都必须出现在 D' 中。同理，扫描结束后残留的每个 `(`，在它右边没有未配对的 `)` 可用，也必须删。因此 D ⊆ D'，|D| ≤ |D'|，我们删的是最少的。剩下的串合法：所有保留的 `)` 都成功配对了某个 `(`，所有保留的 `(` 都被某个 `)` 配对（否则会残留在栈里被删），配对不交叉（栈是后进先出），满足题面递归定义。

## 5. 完整代码（Python）

```python
class Solution:
    def minRemoveToMakeValid(self, s: str) -> str:
        stack = []          # 存未配对 '(' 的下标
        remove = set()      # 需要删除的下标集合

        for i, ch in enumerate(s):
            if ch == '(':
                stack.append(i)          # 先记下，等未来的 ')' 来配对
            elif ch == ')':
                if stack:
                    stack.pop()          # 配对成功，这个 ')' 保留
                else:
                    remove.add(i)        # 左边没有可配对的 '('，必须删

        # 扫描结束后栈里剩下的 '(' 都找不到配对，全部删除
        remove.update(stack)

        # 按原顺序拼接未被删除的字符
        return ''.join(ch for i, ch in enumerate(s) if i not in remove)
```

关键逻辑说明：`stack` 只存 `(` 的下标，`remove` 用集合存删除位置（集合查找 O(1)，避免用列表导致 `in` 判断退化成 O(n)）；最后一遍用生成器拼接，保证字符相对顺序不变。

## 6. 复杂度

- **时间 O(n)**：第一遍扫描每个字符 O(1)（栈的 push/pop 均摊 O(1)，集合 add O(1)）；`remove.update(stack)` 最多 n 个元素；第二遍拼接每个字符做一次集合查找 O(1)。总 O(n)，n 是字符串长度。
- **空间 O(n)**：`stack` 最坏存 n 个下标（全是 `(` 时），`remove` 最坏存 n 个下标，拼接结果最坏 n 个字符。三项都是 O(n)，没有 log 项——因为这里没有排序或二分，所有操作都是线性的。

## 7. 边界与反例（至少 4 条）

1. **输入 `")("` → 期望 `""`** → 容易错：只处理了多余的 `)`，忘了扫描结束后栈里残留的 `(` 也要删，结果输出 `"("`。
2. **输入 `"((("` → 期望 `""`** → 容易错：以为「没有右括号就不用删」，实际上所有左括号都无配对，全删。
3. **输入 `"()()"` → 期望 `"()()"`** → 容易错：用「计数」而非「栈」时，若在遇到 `)` 时错误地无条件减计数，可能把合法串误删；这里每个 `)` 都能配对，不应删任何字符。
4. **输入 `"a)b(c)d"` → 期望 `"ab(c)d"`** → 容易错：删除下标 1 后，若用「边扫边删」的方式直接操作原串，下标会错位；必须先收集删除集合，最后统一拼接。
5. **输入 `"lee(t(c)o)de)"` → 期望 `"lee(t(c)o)de"`** → 容易错：末尾多出的 `)` 在扫描时栈已空，必须标记删除；若只统计数量不记下标，无法定位删哪个。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回字典序最小的合法串怎么办？** 思路：本题只要求任意解；字典序最小需要额外决策「删哪个左括号」，可转化为在合法前提下尽量保留靠前的字符，通常要结合贪心 + 栈的变体，复杂度仍可做到 O(n)，但判定条件更细。
2. **追问：只允许删除 `)`，不允许删 `(`，能否做到？** 思路：不能保证——`"((("` 这种没有 `)` 可删，只能删 `(`；若题目改成「只删右括号」，则需先判断是否存在合法解，本质是检查每个前缀的 `(` 数量是否足够。
3. **追问：如果字符串长度到 10^7，内存受限怎么办？** 思路：删除标记可以用布尔数组（1 字节/位）替代 set，栈可以用数组模拟；若连 O(n) 额外空间都不允许，需要两遍扫描 + 原地压缩（类似本题的「先算删除数，再原地写回」技巧），但 Python 字符串不可变，需转 list。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 20. 有效的括号**：共同点是都用栈做「最近未配对」的记账，区别是 20 只判定合法性、不构造删除方案。
2. **LeetCode 921. 使括号有效的最少添加**：共同点是扫描时维护「未配对左括号数」，区别是 921 求最少添加数（计数即可），本题求删除位置（需要下标）。
3. **LeetCode 32. 最长有效括号**：共同点是都基于「前缀左括号数不少于右括号数」的判定，区别是 32 求最长合法子串长度，需要记录每个位置的最早非法点，常用栈存下标或 DP。
