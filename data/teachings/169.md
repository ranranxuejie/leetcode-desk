## 1. 一句话本质

在一个保证存在「出现次数超过一半」的元素的数组里，把这个元素找出来——本质是**在“多数派一定压倒所有少数派之和”这个前提下，用最少的额外信息定位它**。

## 2. 读完题的第一反应

**朴素解法**：最直接的想法是数每个数出现多少次。用哈希表 `count[x] += 1`，边数边判断有没有超过 `n//2`。时间 O(n)，空间 O(n)。这个解法本身没错，能过题，但它卡在**空间**上——题目进阶明确要求 O(1) 空间，哈希表就出局了。

另一个朴素想法是排序后取中间元素 `nums[n//2]`。因为多数元素出现次数 > n/2，排序后它必然占据中间位置。时间 O(n log n)，空间取决于排序实现。这个解法很巧妙，但时间没到 O(n)。

**关键观察**：多数元素的定义是「出现次数 > 其余所有元素出现次数之和」。这句话不是修辞，是可以用代数表达的：设多数元素为 M，出现 k 次，则 k > n - k，即 **k - (n - k) > 0**。也就是说，如果把 M 记 +1、其他所有元素记 -1，整个数组的和是正数。

这个观察直接指向一个思路：**能不能一边遍历一边做“抵消”**？遇到两个不同的数就互相抵消掉，最后剩下的那个一定是多数元素——因为多数元素的数量比所有其他元素加起来还多，无论怎么配对抵消，它总会有剩余。这就是摩尔投票法（Boyer-Moore Voting）的直觉来源。

## 3. 从暴力到最优

我们用一个具体例子走三遍，看瓶颈怎么一步步被消掉。取 `nums = [2,2,1,1,1,2,2]`，n=7，多数元素是 2（出现 4 次 > 3）。

**第一版：哈希计数**

```
count = {}
遍历:
  2 -> {2:1}
  2 -> {2:2}
  1 -> {2:2, 1:1}
  1 -> {2:2, 1:2}
  1 -> {2:2, 1:3}
  2 -> {2:3, 1:3}
  2 -> {2:4, 1:3}   # 4 > 7//2=3，返回 2
```

时间 O(n) 没问题，瓶颈是 `count` 这个字典占了 O(不同元素个数) 的空间。要消掉它，就得**不记录每个元素的具体次数**，只维护“当前候选人 + 它的净优势”。

**第二版：排序取中**

排序后 `[1,1,1,2,2,2,2]`，取 `nums[3] = 2`。正确，但排序本身 O(n log n)，瓶颈在比较排序的下界。

**第三版：摩尔投票**

维护两个变量：`candidate`（当前候选人）和 `balance`（它的净票数）。

```
初始: candidate=None, balance=0

读 2: balance=0 -> candidate=2, balance=1
读 2: 同候选人 -> balance=2
读 1: 不同 -> balance=1
读 1: 不同 -> balance=0        # 此时 2 和 1 各抵消掉一部分，净优势归零
读 1: balance=0 -> candidate=1, balance=1   # 换候选人
读 2: 不同 -> balance=0
读 2: balance=0 -> candidate=2, balance=1   # 又换回 2
结束: candidate=2
```

注意中间 `candidate` 一度变成 1，但最后又回到 2。**为什么中途换人还能对？** 因为被抵消掉的那些元素里，多数元素和少数元素是成对消失的，多数元素的“盈余”始终存在，只是暂时被前面的抵消掩盖了。最后 `balance > 0` 时留下的候选人，一定是那个盈余者。

这一步把空间压到 O(1)（两个变量），时间 O(n)（一次遍历），两个瓶颈同时消掉。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证。摩尔投票的核心不变量是：

> 遍历到第 i 个元素后，把已经处理过的前缀中「被抵消掉的部分」全部删去，剩下的元素里，原数组的多数元素仍然是剩余部分的多数元素（若剩余非空）。

**证明思路（配对抵消论证）**：每次 `balance` 归零，意味着从上一个归零点到当前位置，候选人和其他元素**数量相等**，可以两两配对全部消掉。设原数组多数元素 M 出现 k 次，其他元素共 n-k 次，k > n-k。把整个数组划分成若干「抵消段」（每段内候选人票数归零）加最后一段「盈余段」。每个抵消段内 M 和非 M 的数量差为 0 或某个值，但**所有段加起来 M 的总盈余 = k - (n-k) > 0**。既然总盈余为正，最后一段的盈余必然为正，而最后一段的候选人就是 M。

换个角度用**反证**更直观：假设最后留下的候选人 c ≠ M。那么在整个过程中，c 的票数从 0 涨到正数，说明 c 没有被完全抵消。但 M 的总数超过一半，任何非 M 的元素想“存活”到最后，都必须先抵消掉所有 M——而 M 的数量比所有非 M 加起来还多，抵消不完。矛盾。所以候选人只能是 M。

**不会重**：题目保证多数元素唯一（出现次数 > n/2 的元素至多一个），所以返回值唯一，不存在选错的问题。

## 5. 完整代码（Python）

```python
class Solution:
    def majorityElement(self, nums: list[int]) -> int:
        candidate = None   # 当前候选人
        balance = 0        # 候选人的净票数（同票 +1，异票 -1）

        for x in nums:
            if balance == 0:
                # 净票数为 0，说明之前的候选人已被完全抵消，
                # 从当前元素重新开始计数
                candidate = x
                balance = 1
            elif x == candidate:
                # 和候选人相同，净票数增加
                balance += 1
            else:
                # 和候选人不同，互相抵消一票
                balance -= 1

        # 题目保证多数元素一定存在，所以 candidate 就是答案
        return candidate
```

> 说明：如果题目**不保证**多数元素存在，这里返回的 `candidate` 只是“可能的多数元素”，还需要再遍历一次统计它的真实出现次数，确认是否 > n//2。本题保证存在，所以省掉这一步。

## 6. 复杂度

- **时间 O(n)**：`for` 循环遍历数组一次，循环体里只有常数次比较和加减，每次 O(1)。n 来自 `nums` 的长度。没有嵌套循环，没有排序，所以没有 log n 项。
- **空间 O(1)**：只用了 `candidate` 和 `balance` 两个标量变量，与 n 无关。对比哈希表解法的 O(不同元素个数)，这里把空间彻底压平了。

## 7. 边界与反例（至少 4 条）

1. **输入 `[1]` → 期望 `1`** → 容易错在：`balance` 初始为 0，第一个元素触发 `candidate = 1, balance = 1`，循环结束直接返回。如果代码写成先判断 `x == candidate` 再判断 `balance == 0`，`candidate` 初始为 `None` 时可能出问题，顺序不能反。

2. **输入 `[1,1,1,1]` → 期望 `1`** → 容易错在：全是同一元素，`balance` 一路涨到 4，从不归零。如果误以为“归零才换人”是唯一逻辑，会担心没换人是不是漏了——其实这正是正确行为。

3. **输入 `[1,2,1,2,1]` → 期望 `1`** → 容易错在：`balance` 在中间多次归零（读 2 时归零、读 2 又归零），候选人反复切换。手算容易跟丢，误以为最后候选人不对。实际最后 `candidate=1, balance=1`，正确。

4. **输入 `[2,2,1,1,1,2,2]` → 期望 `2`** → 容易错在：这是官方示例 2，中途 `candidate` 一度变成 1（第 5 个元素处），如果只看中途状态会误判。必须理解“中途换人不影响最终结果”。

5. **输入 `[-1,-1,2]` → 期望 `-1`** → 容易错在：元素是负数，如果代码里用 `0` 或某个哨兵值初始化 `candidate` 并做特殊判断，可能和真实元素冲突。本题用 `None` 初始化，避免了这个坑。

## 8. 面试追问与变体（3 条）

1. **追问：如果不保证多数元素存在，怎么改？**
   思路：摩尔投票跑完后，再遍历一次统计 `candidate` 的真实出现次数，若 > n//2 返回它，否则返回 -1（或题目约定的值）。多一次 O(n) 遍历，总复杂度不变。

2. **追问：找出所有出现次数超过 n/3 的元素（力扣 229）？**
   思路：推广摩尔投票——超过 n/3 的元素最多 2 个，所以维护**两个**候选人 + 两个计数器，遍历时先匹配两个候选人，都不匹配再抵消。最后对两个候选人各验证一次。

3. **追问：如果要求返回多数元素的所有下标？**
   思路：先用摩尔投票 O(n) 找到值，再遍历一次收集所有等于该值的下标。时间仍 O(n)，空间 O(结果个数)。

## 9. 举一反三（2-3 道同类题）

- **力扣 229. 求众数 II**：和本题共同点是都用「抵消」思想，区别是阈值从 n/2 变成 n/3，候选人从 1 个变 2 个。
- **力扣 136. 只出现一次的数字**：共同点是都用「成对抵消」的直觉——异或运算里 `a ^ a = 0`，和摩尔投票的「同归于尽」是同一类思路。
- **力扣 1287. 有序数组中出现次数超过 25% 的元素**：共同点是利用「出现频率超过某比例」这一结构性质，可以用类似投票或二分定位的思路快速锁定候选。
