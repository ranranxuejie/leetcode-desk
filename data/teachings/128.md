## 1. 一句话本质

在数组里找「值域上连续」的最长整数段，而不是「下标上连续」的子数组——即求集合 `{nums[i]}` 中形如 `{x, x+1, ..., x+k}` 的最大 k+1。

## 2. 读完题的第一反应

**朴素解法**：先排序，再扫一遍数相邻差是否为 1。瓶颈在排序，`O(n log n)`，而题目明确要求 `O(n)`，所以排序这条路直接被题面否掉。另一种朴素是「对每个数 x，从 x 开始 while x+1 in nums 一路数下去」，单次查找是 `O(n)` 的线性扫描，最坏 `O(n²)`。

**关键观察**：题目只关心「某个值在不在数组里」，不关心它出现几次、出现在哪。这个信号非常强——**存在性查询**就该用哈希集合，`in` 操作降到 `O(1)`。于是第二个朴素解法的瓶颈从「查找慢」变成「起点选错」：如果对每个数都当起点往后数，`[1,2,3,4]` 里 2、3、4 都会被重复数一遍，总代价退化成 `O(n²)`。

**下一步的钥匙**：一条连续段只有一个「合法起点」——它的最小值。判断标准是 `x-1 not in set`。只从合法起点出发，每个元素最多被访问常数次，总代价压回 `O(n)`。

## 3. 从暴力到最优

用示例 1 `nums = [100,4,200,1,3,2]` 走一遍。

**第一步：排序法**。排序得 `[1,2,3,4,100,200]`，扫描时维护 `cur=1`，遇到 2 差 1 则 `cur=2`，3 则 `cur=3`，4 则 `cur=4`，到 100 差 96 则重置 `cur=1`。答案 4。代价 `O(n log n)`，卡在排序。

**第二步：哈希集合 + 无脑起点**。`S = {1,2,3,4,100,200}`。对每个 x 都往后数：x=1 数到 4 得 4；x=2 数到 4 得 3；x=3 得 2；x=4 得 1；x=100 得 1；x=200 得 1。答案对，但 1、2、3、4 这段被数了 4+3+2+1=10 次。最坏情况（整段连续）是 `O(n²)`。

**第三步：只从段头出发**。遍历时先判断 `x-1 in S`：
- x=100：99 不在 S → 是段头，往后数 101 不在 → 长度 1
- x=4：3 在 S → 跳过
- x=200：199 不在 → 段头，长度 1
- x=1：0 不在 → 段头，数 2、3、4 都在，5 不在 → 长度 4
- x=3：2 在 → 跳过
- x=2：1 在 → 跳过

每个元素要么被跳过（一次 `in` 判断），要么作为段头被数一次。总访问次数 `O(n)`。

**第四步：去重**。示例 3 `[1,0,1,2]` 里 1 出现两次。如果直接遍历原数组，1 会被当两次段头（虽然结果不错，但逻辑上重复计算）。所以先把 `nums` 转成 `set`，遍历集合而不是原数组。这一步同时解决了重复元素问题。

## 4. 正确性：为什么不会漏、不会重

**不变量**：对任意一个值 `x ∈ S`，设它所属的极大连续段为 `[L, R]`（即 `L-1 ∉ S` 且 `R+1 ∉ S`，且 `L..R` 全在 S 中）。算法恰好在这个段上执行一次「向后数」操作，且执行时从 `L` 开始，数出的长度正是 `R-L+1`。

**不漏**：每个 `x ∈ S` 都属于唯一一个极大连续段，而每个极大连续段的最小值 `L` 满足 `L-1 ∉ S`，必然通过段头判断，被数一次。所以每个段都被覆盖。

**不重**：非段头的元素 `x`（即 `x-1 ∈ S`）在遍历时被 `continue` 跳过，不会触发计数。所以每个段只被数一次。

**计数正确**：从 `L` 出发，`while cur+1 in S` 会一直数到 `R`（因为 `R+1 ∉ S` 时循环终止），长度 `R-L+1` 精确。

**为什么总复杂度是 O(n)**：虽然外层有 while 循环，但内层 while 只在段头触发，且内层每步访问的值 `cur+1` 在整个算法中只被这个段的内层循环访问一次（其他段的内层循环不会碰到它，因为段与段不相交）。所以内层总步数 ≤ |S| ≤ n，外层遍历也是 n 次，合计 `O(n)`。这是「均摊分析」的典型场景：不是每次操作都 O(1)，但总操作次数有上界。

## 5. 完整代码（Python）

```python
class Solution:
    def longestConsecutive(self, nums: list[int]) -> int:
        # 去重：重复元素不应被当作多个段头，也避免重复计算
        num_set = set(nums)
        best = 0

        for x in num_set:
            # 只从「段头」出发：x-1 不在集合中，说明 x 是某段的起点
            if x - 1 in num_set:
                continue

            # 从段头向后数，直到断掉
            cur = x
            length = 1
            while cur + 1 in num_set:
                cur += 1
                length += 1

            # 更新全局最长
            if length > best:
                best = length

        return best
```

注意 `for x in num_set` 遍历的是集合而非原数组，这是去重的关键；`x - 1 in num_set` 是 O(1) 哈希查询，不是线性扫描。

## 6. 复杂度

**时间 O(n)**：
- `set(nums)` 构造哈希集合：n 次插入，每次均摊 O(1)，共 O(n)。
- 外层 `for` 遍历集合：最多 n 次迭代，每次做一次 `x-1 in num_set` 查询，O(1)，共 O(n)。
- 内层 `while`：只在段头触发，且每个值最多被内层访问一次（段与段不相交），总步数 ≤ n，共 O(n)。
- 三项相加 O(n)。这里没有 log n 的来源——排序被哈希集合替代了。

**空间 O(n)**：`num_set` 最多存 n 个不同整数，每个整数占 O(1) 空间。没有递归栈、没有额外数组。

## 7. 边界与反例（至少 4 条）

1. **空数组** `[]` → 期望 `0` → 容易错在 `best` 初值没设 0 或循环前没处理空集。代码里 `best=0` 且 `for` 不执行，直接返回 0，安全。

2. **单元素** `[5]` → 期望 `1` → 容易错在 `length` 初值写成 0 导致返回 0。代码里 `length=1` 从段头本身算起。

3. **全重复** `[2,2,2]` → 期望 `1` → 容易错在遍历原数组时 2 被当三次段头，虽然结果碰巧对，但逻辑上重复；更隐蔽的错是 `set` 后忘了 `length` 初值。代码用集合遍历，只处理一次。

4. **整段连续** `[1,2,3,...,n]` → 期望 `n` → 容易错在没做段头判断，退化成 O(n²) 超时。代码里只有 1 是段头，其余全 `continue`。

5. **负数与跨零** `[-2,-1,0,1]` → 期望 `4` → 容易错在假设「连续」只针对正整数，或 `x-1` 判断时对负数处理不当。哈希集合对负数一视同仁，代码无需特殊处理。

6. **值域极大** `[10**9, -10**9]` → 期望 `1` → 容易错在用数组下标当哈希（值域 2×10^9 开不了数组）。代码用 `set`，与值域无关。

## 8. 面试追问与变体（3 条）

**追问 1：如果要求返回最长序列本身（不只是长度）？**
思路：内层 while 时把 `cur` 收集进列表，段结束时若长度刷新记录则保存该列表。时间空间不变，只是多存一份结果。

**追问 2：如果数组是流式输入（不能一次全读进内存）？**
思路：哈希集合方案失效（需要全局存在性）。改用并查集 + 外部存储，或分块处理；面试中通常答「需要额外存储，单遍流式无法保证 O(n)」，考察你是否理解哈希集合的全局性依赖。

**追问 3：如果要求「连续」指下标连续的子数组，且元素值也连续？**
思路：完全不同的题。用滑动窗口 + 集合判重，维护窗口内 `max-min == 窗口长度-1` 且无重复，双指针 O(n)。这题考的是「值域连续」和「下标连续」的区分。

- **力扣 217. 存在重复元素**：共同点是「去重 / 存在性」用哈希集合，O(n) 时间 O(n) 空间，是本题去重步骤的简化版。
- **力扣 674. 最长连续递增序列**：名字像但本质不同——那题要求下标连续且值递增，用一次线性扫描即可；对比本题可以帮你分清「值域连续」和「下标连续」两类问题。
