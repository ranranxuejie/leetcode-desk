## 1. 一句话本质

把一棵用字符串「前缀式」写出来的布尔表达式树，从叶子往根逐层求值，最终得到根节点的真假。

关键在于：`&(...)`、`|(...)`、`!(...)` 这三种写法，运算符永远在括号**前面**，所以括号里包着的就是它的操作数——这天然是一棵树的先序遍历序列，只是没有显式建树。

## 2. 读完题的第一反应

**朴素解法**：把字符串当成表达式，反复扫描——找到最内层的一个 `X(...)`（括号里不含括号），算出它的值，用 `t`/`f` 替换掉这一段，再重复，直到整个串只剩一个字符。示例 1 的官方解释走的就是这条路。

它卡在哪？每次替换都要重新扫描整个字符串找「最内层括号」，最坏情况表达式是一条长链 `!(!(!(...)))`，长度 n，每轮只消掉一层，就要扫 n 轮，每轮 O(n)，总复杂度 O(n²)。n 最大 2×10⁴，平方就是 4×10⁸ 量级，虽然 Python 里可能勉强过，但这是典型的「能过但不该这么写」。

**关键观察**：既然它是先序遍历，那「最内层括号」其实就是**最先闭合**的那个右括号。而「最先闭合」这件事，栈天生就会处理——遇到 `(` 压栈，遇到 `)` 弹栈，弹的那一刻，栈顶攒着的正是这个括号里的全部操作数。于是我们不需要反复扫描，**一次从左到右的遍历**就能按「后进先出」的顺序把每棵子树算完。

这个观察之所以能直接导向解法，是因为它把「找最内层」这个 O(n) 的搜索动作，变成了栈的 O(1) 弹出动作。

## 3. 从暴力到最优

**暴力版**（用示例 1 `"&(|(f))"` 走一遍）：

- 第 1 轮扫描，找到最内层 `|(f)`，算出 `f`，串变成 `"&(f)"`；
- 第 2 轮扫描，找到 `&(f)`，算出 `f`，串变成 `"f"`；
- 第 3 轮，返回 false。

每轮都从头扫，前两轮扫到的字符大部分是白扫的。

**栈版**：从左到右扫一遍，维护两个东西——一个存「还没算完的运算符」的栈 `ops`，一个存「当前这一层已经算出来的操作数」的栈 `vals`（每个元素是 `True`/`False` 的列表，或者更简单：一个栈，元素是「当前层的结果列表」）。

具体走 `"&(|(f))"`：

| 读到 | 动作 | ops | vals（每层的结果列表） |
|---|---|---|---|
| `&` | 记下运算符 | `[&]` | `[[]]` |
| `(` | 开新层 | `[&]` | `[[], []]` |
| `\|` | 记下运算符 | `[&, \|]` | `[[], []]` |
| `(` | 开新层 | `[&, \|]` | `[[], [], []]` |
| `f` | 往当前层塞 False | `[&, \|]` | `[[], [], [False]]` |
| `)` | 弹出 `\|`，对本层 `[False]` 求或 → False，塞进上一层 | `[&]` | `[[], [False]]` |
| `)` | 弹出 `&`，对本层 `[False]` 求与 → False，塞进上一层 | `[]` | `[[False]]` |
| 结束 | 取唯一结果 | | `False` |

对比一下：暴力版扫了 3 遍共约 3n 个字符，栈版只扫 1 遍 n 个字符。瓶颈从「反复找最内层」变成「一次遍历 + 每个字符 O(1) 的栈操作」，O(n²) → O(n)。

再补一个多操作数的例子 `"|(f,f,f,t)"`，验证逗号的处理：读到 `f` 塞 False，读到 `,` 什么都不做（它只是分隔符），继续塞 False、False、True，到 `)` 时本层列表是 `[F,F,F,T]`，求或得 True。逗号不需要特殊逻辑，这是栈版比暴力版省事的地方——暴力版替换时还得小心处理逗号。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义扫描到位置 i 时的状态：

> 不变量：`vals` 栈中每一层存的是「该层括号内、已经完整读到的那些子表达式」的布尔值列表；`ops` 栈中每一层存的是该层对应的运算符。两者深度始终相等，且与当前尚未闭合的括号层数一致。

三条性质保证正确：

1. **不漏**：每个 `t`/`f` 字符被读到时，立即作为当前层的一个操作数压入 `vals` 栈顶，之后只会被它所在层的 `)` 消费一次，不会丢失。
2. **不重**：每个 `)` 触发一次「弹出本层 + 求值 + 结果压入上一层」。求值后本层列表被丢弃，该层不会再被访问；结果作为上一层的**一个**操作数，恰好对应原表达式里「这个括号整体是一个子表达式」的语义。所以每个子表达式恰好被求值一次。
3. **顺序正确**：栈的后进先出保证了「先闭合的括号先求值」，这正是表达式树的后序遍历顺序——子节点全部算完才轮到父节点。由于题面保证输入合法，每个 `)` 出现时其对应层的操作数一定已经齐了，不会出现「求值时列表为空」的情况（`!(...)` 只有一个操作数，`&`/`|` 至少两个，题面已约定）。

因为不变量在初始（空栈）成立，每次读字符后仍成立，扫描结束时栈只剩一个结果，所以最终返回值就是整棵树的根值。

## 5. 完整代码（Python）

```python
class Solution:
    def parseBoolExpr(self, expression: str) -> bool:
        # ops: 每层未闭合括号对应的运算符，如 '&' '|' '!'
        # vals: 每层已读到的操作数列表，元素是 True/False
        ops = []
        vals = [[]]  # 最外层也占一个槽位，方便统一处理

        for ch in expression:
            if ch == 't':
                vals[-1].append(True)
            elif ch == 'f':
                vals[-1].append(False)
            elif ch in '&|!':
                # 运算符先记下，等它后面的 '(' 来开层
                ops.append(ch)
            elif ch == '(':
                # 开新的一层，给这个运算符准备操作数列表
                vals.append([])
            elif ch == ',':
                # 逗号只是分隔符，无需处理
                continue
            elif ch == ')':
                # 本层操作数已齐，弹出运算符求值
                operands = vals.pop()
                op = ops.pop()
                if op == '!':
                    # 题面保证 ! 只有一个操作数
                    res = not operands[0]
                elif op == '&':
                    res = all(operands)
                else:  # op == '|'
                    res = any(operands)
                # 结果作为上一层的一个操作数
                vals[-1].append(res)

        # 扫描结束，最外层槽位里应只剩一个最终结果
        return vals[0][0]
```

几个容易写错的地方，代码里已经规避：

- `vals` 初始化为 `[[]]` 而不是 `[]`，这样最外层的 `t`/`f`（比如输入就是 `"t"`）也有地方放，且 `vals[-1]` 永远安全。
- `!` 用 `not operands[0]`，不要用 `all`/`any`——虽然单元素时结果碰巧一样，但语义上 `!` 是取反不是聚合。
- `&` 用 `all`、`|` 用 `any`，天然处理「至少两个操作数」的任意长度。

## 6. 复杂度

**时间 O(n)**：n 是字符串长度。for 循环恰好遍历每个字符一次；每个字符的处理是 O(1)（`append`、`pop`、`all`/`any` 对单层列表的扫描——注意这里有个细节：`all(operands)` 会扫本层所有操作数，但每个操作数只属于一层、只被扫一次，所有层的操作数总数不超过 n，所以总代价仍是 O(n)，不是 O(n²)）。没有 log n 项，因为这里没有分治或二分。

**空间 O(n)**：`ops` 和 `vals` 的深度等于括号嵌套层数，最坏（如 `!(!(!(...)))`）是 O(n)；`vals` 里所有层的操作数总数也不超过 n。所以总空间 O(n)。

## 7. 边界与反例（至少 4 条）

1. **输入 `"t"`** → 期望 `True` → 容易错在 `vals` 初始化为空列表，导致 `vals[-1]` 越界。代码里初始化为 `[[]]` 规避。
2. **输入 `"f"`** → 期望 `False` → 同上，且要确认返回的是 `vals[0][0]` 而不是 `vals[-1]`（此时两者相同，但统一用 `vals[0]` 更稳）。
3. **输入 `"!(f)"`** → 期望 `True` → 容易错在用 `all([False])` 得到 False，忘了 `!` 是取反。必须单独分支处理 `!`。
4. **输入 `"|(&(t,f,t),!(t))"`** → 期望 `False` → 这是嵌套 + 多操作数 + 取反的组合，容易错在 `)` 求值后忘记把结果压回上一层，或者压错了层（`vals[-1]` 在 `pop` 之后指向的正是上一层，顺序不能反）。
5. **输入 `"&(t,t,t)"`** → 期望 `True` → 容易错在把逗号当成操作数或漏处理，导致本层列表长度不对。逗号直接 `continue` 即可。

## 8. 面试追问与变体（3 条）

1. **追问：如果表达式里出现 `^`（异或）或 `=>`（蕴含），怎么改？**
   思路：只需在 `)` 分支里加一个 `elif`，把本层操作数按对应规则折叠（异或用 `reduce(xor)`，蕴含用 `not a or b` 从左到右折叠），栈结构完全不变。

2. **追问：不用栈，用递归下降怎么写？**
   思路：写 `parse(i)` 返回 `(值, 下一个位置)`，读到运算符就递归解析括号内、用逗号循环收集操作数，读到 `t`/`f` 直接返回。本质是把栈的「后进先出」换成函数调用栈，复杂度相同。

3. **追问：如果要求返回表达式树的根节点（而不是布尔值），怎么改？**
   思路：`vals` 里不存布尔值而存节点对象，`t`/`f` 建叶子，`)` 时用弹出的运算符和本层子节点建内部节点，最后返回 `vals[0][0]`。这就是标准的「用栈从先序序列建树」。
