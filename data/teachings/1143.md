## 1. 一句话本质

在两个字符串的所有**保序配对**方案里，找能配上最多对字符的那一种，返回配对数。

## 2. 读完题的第一反应

**朴素解法**：枚举 `text1` 的所有子序列（共 $2^{n}$ 个），对每个子序列检查它是否也是 `text2` 的子序列。复杂度 $O(2^n \cdot m)$，`n` 只要到 20 就爆了。瓶颈在于「枚举所有子序列」这个动作本身——绝大多数子序列根本没希望成为公共的，我们却在逐个验证。

**关键观察**：不要从「枚举子序列」出发，而要从「两个字符串的末尾」出发。看 `text1` 的最后一个字符和 `text2` 的最后一个字符：

- 如果它们**相等**，那这个字符一定可以被放进某个最长公共子序列的末尾——把它配掉，问题缩小成两个前缀的子问题，答案 +1。
- 如果它们**不相等**，那这两个末尾字符至少有一个不会出现在最终答案里（不可能两个都进，因为它们不相等；也不可能都不进，因为那说明我们白白浪费了末尾）。于是答案等于「砍掉 `text1` 末尾」和「砍掉 `text2` 末尾」两个子问题的较大者。

这个观察之所以能让你想到下一步，是因为它把「一个 $n \times m$ 的大问题」拆成了「两个更小的同类问题」，而且**子问题的规模只由两个前缀长度决定**——这正是动态规划的状态定义信号：状态是 `(i, j)`，表示 `text1[:i]` 和 `text2[:j]` 的 LCS 长度。

## 3. 从暴力到最优

**第一步：暴力枚举。** 对 `text1` 每个子序列去 `text2` 里做子序列匹配。以 `text1 = "abcde"`、`text2 = "ace"` 为例，要检查 `"a"`、`"ab"`、`"ac"`、`"abc"`……共 32 个子序列，其中 `"ace"` 匹配成功，长度 3。问题：子序列数量指数级，且大量重复检查（`"ac"` 和 `"ace"` 的前缀关系被反复利用却没被缓存）。

**第二步：记忆化递归。** 按第 2 节的观察写递归 `f(i, j)`：

```
f(i, j) = f(i-1, j-1) + 1                     若 text1[i-1] == text2[j-1]
        = max(f(i-1, j), f(i, j-1))           否则
f(0, *) = f(*, 0) = 0
```

状态只有 $(n+1)(m+1)$ 个，每个状态 $O(1)$ 转移，瓶颈从 $O(2^n m)$ 降到 $O(nm)$。但递归有栈深度问题（`n, m` 到 1000 时递归深度 1000，Python 默认限制 1000，容易踩线），且自顶向下有函数调用开销。

**第三步：自底向上填表。** 把 `f(i, j)` 摊成二维表 `dp[i][j]`，按 `i` 从小到大、`j` 从小到大填。因为 `dp[i][j]` 只依赖 `dp[i-1][j-1]`、`dp[i-1][j]`、`dp[i][j-1]`，三者都在左上方，顺序填表天然满足依赖。

用 `text1 = "abcde"`、`text2 = "ace"` 走一遍（行是 `text1` 前缀，列是 `text2` 前缀，`dp[0][*] = dp[*][0] = 0`）：

| dp | "" | a | c | e |
|---|---|---|---|---|
| "" | 0 | 0 | 0 | 0 |
| a | 0 | 1 | 1 | 1 |
| b | 0 | 1 | 1 | 1 |
| c | 0 | 1 | 2 | 2 |
| d | 0 | 1 | 2 | 2 |
| e | 0 | 1 | 2 | 3 |

看几个关键格子：`dp[1][1]`：`'a' == 'a'`，取 `dp[0][0]+1 = 1`。`dp[3][2]`：`text1[2]='c'` 与 `text2[1]='c'` 相等，取 `dp[2][1]+1 = 1+1 = 2`。`dp[5][3]`：`'e' == 'e'`，取 `dp[4][2]+1 = 2+1 = 3`。最终 `dp[5][3] = 3`，与示例一致。

**第四步（可选优化）：滚动数组。** 观察转移只用到「上一行」和「当前行左边一格」，所以二维表可以压成两行（甚至一行加一个临时变量）。空间从 $O(nm)$ 降到 $O(\min(n,m))$。这一步在面试里是加分项，但先保证二维版本写对。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证。定义不变量：填完 `dp[i][j]` 时，它等于 `text1[:i]` 与 `text2[:j]` 的 LCS 长度。对 `i + j` 做归纳。

**基例**：`i = 0` 或 `j = 0` 时，有一侧是空串，LCS 必为 0，成立。

**归纳步**：设所有 `i' + j' < i + j` 的状态都满足不变量，考察 `dp[i][j]`。设 `A = text1[:i]`，`B = text2[:j]`，`x = text1[i-1]`，`y = text2[j-1]`。

**情形一：`x == y`。** 要证 `LCS(A, B) = LCS(A[:-1], B[:-1]) + 1`。
- 「≥」方向：取 `A[:-1]` 与 `B[:-1]` 的任一 LCS，末尾接上 `x`（等于 `y`），得到一个长度为 `LCS(A[:-1], B[:-1]) + 1` 的公共子序列，故 `LCS(A,B) ≥` 右边。
- 「≤」方向（交换论证）：设 `S` 是 `A`、`B` 的任一 LCS。若 `S` 末尾是 `x`，去掉它得 `A[:-1]`、`B[:-1]` 的公共子序列，长度 `|S|-1 ≤ LCS(A[:-1], B[:-1])`。若 `S` 末尾不是 `x`，把 `S` 末尾换成 `x`（`x` 在 `A` 末尾、`y=x` 在 `B` 末尾，替换后仍是公共子序列且长度不变），归入上一情况。故 `LCS(A,B) ≤` 右边。两边夹逼得等号。

**情形二：`x != y`。** 要证 `LCS(A, B) = max(LCS(A[:-1], B), LCS(A, B[:-1]))`。
- 「≥」方向：`A[:-1]` 是 `A` 的子序列，其与 `B` 的公共子序列也是 `A`、`B` 的公共子序列，故 `LCS(A,B) ≥ LCS(A[:-1], B)`；对称地 `≥ LCS(A, B[:-1])`。
- 「≤」方向：设 `S` 是 `A`、`B` 的任一 LCS。若 `S` 末尾不是 `x`，则 `S` 是 `A[:-1]` 与 `B` 的公共子序列，`|S| ≤ LCS(A[:-1], B)`。若 `S` 末尾不是 `y`，则 `|S| ≤ LCS(A, B[:-1])`。若 `S` 末尾既是 `x` 又是 `y`，则 `x = y`，与前提矛盾。所以 `S` 末尾至少缺一个，`|S| ≤ max(...)`。

两种情形都成立，归纳完成。**不会漏**：每种情形都穷尽了 `x`、`y` 的关系。**不会重**：`max` 取的是上界，且两个子问题各自独立计算、互不干扰，不存在重复计数。

## 5. 完整代码（Python）

```python
class Solution:
    def longestCommonSubsequence(self, text1: str, text2: str) -> int:
        n, m = len(text1), len(text2)
        # dp[i][j] = text1[:i] 与 text2[:j] 的 LCS 长度
        # 多开一行一列，dp[0][*] 和 dp[*][0] 天然为 0，省去边界判断
        dp = [[0] * (m + 1) for _ in range(n + 1)]

        for i in range(1, n + 1):
            for j in range(1, m + 1):
                if text1[i - 1] == text2[j - 1]:
                    # 末尾字符相等，配掉它，答案来自左上角 + 1
                    dp[i][j] = dp[i - 1][j - 1] + 1
                else:
                    # 末尾不等，至少砍掉一侧，取上方和左方的较大者
                    dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

        return dp[n][m]
```

**滚动数组版本**（空间 $O(\min(n,m))$，面试追问时用）：

```python
class Solution:
    def longestCommonSubsequence(self, text1: str, text2: str) -> int:
        # 让 text2 是较短的那个，滚动数组只开 min(n,m) 长度
        if len(text1) < len(text2):
            text1, text2 = text2, text1
        m = len(text2)
        prev = [0] * (m + 1)          # 上一行
        for i in range(1, len(text1) + 1):
            cur = [0] * (m + 1)       # 当前行
            for j in range(1, m + 1):
                if text1[i - 1] == text2[j - 1]:
                    cur[j] = prev[j - 1] + 1
                else:
                    cur[j] = max(prev[j], cur[j - 1])
            prev = cur
        return prev[m]
```

## 6. 复杂度

**时间 $O(nm)$**：两层循环，外层 `n = len(text1)` 次，内层 `m = len(text2)` 次，每次转移是常数次比较和加法。`n`、`m` 分别由两个字符串长度贡献，没有 `log` 项——因为不存在排序或二分，所有状态都被恰好访问一次。

**空间 $O(nm)$**：二维表有 `(n+1)(m+1)` 个格子，每个存一个整数。滚动数组版本降到 $O(\min(n,m))$：只保留两行，每行长度是较短串长度 +1。这里没有 `log` 项，因为空间是线性铺开的表格，不是递归树。

## 7. 边界与反例（至少 4 条）

1. **`text1 = "a"`, `text2 = "a"`** → 期望 `1`。容易错：如果循环从 `i=0` 开始且没处理好 `i-1` 下标，会越界或读到错误值；多开一行一列正是为了避开这个。
2. **`text1 = "abc"`, `text2 = "def"`** → 期望 `0`。容易错：有人会误以为「没有公共字符就返回 -1」或「返回空串长度」，题面明确要求返回 `0`。
3. **`text1 = "abc"`, `text2 = "abc"`** → 期望 `3`。容易错：把「子序列」误当成「子串」，子串要求连续，这里恰好连续所以答案一样，但换成 `text1 = "abcde"`, `text2 = "ace"` 时子串答案是 `1`（只有 `"a"` 或 `"c"` 或 `"e"`），子序列才是 `3`。这是本题最经典的混淆点。
4. **`text1 = "aaaa"`, `text2 = "aa"`** → 期望 `2`。容易错：以为重复字符会重复计数，实际上每个字符只能配一次，`dp` 表会正确限制在较短串长度内。
5. **`text1 = "bl", `text2 = "yby"`** → 期望 `1`。容易错：`'b'` 在 `text2` 中间，不在开头，贪心地「从前往后找第一个匹配」如果实现不当会漏掉；DP 表会通过 `dp[i][j-1]` 把「跳过 `text2` 前面的 `y`」这个决策覆盖到。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回具体的 LCS 字符串而不只是长度，怎么做？** 思路：填完 `dp` 表后从 `dp[n][m]` 回溯，相等就往左上走并记录字符，不等就往值大的方向走，最后反转结果。
2. **追问：空间能不能再压到一行？** 思路：可以，但需要额外变量暂存「左上角」的值（因为 `dp[i-1][j-1]` 会被当前行覆盖），用一个 `diag` 变量在每行开始时置 0、循环中滚动更新。
3. **追问：如果两个字符串很长（比如各 10 万），但其中一个很短，怎么办？** 思路：滚动数组已经让空间是 $O(\min(n,m))$，时间仍是 $O(nm)$；若 `min` 也很大会超时，此时要考虑 Hunt–Szymanski 算法（基于匹配位置 + LIS），复杂度 $O((n+m) \log n)$ 量级，但实现复杂，面试中说出思路即可。
