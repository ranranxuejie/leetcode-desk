## 1. 一句话本质

在一个「编号与二维坐标需要互相换算」的棋盘上，求从格子 1 到格子 n² 的**最少掷骰次数**——每次最多走 6 步，落点若有蛇/梯子则强制传送一次（且只传一次），本质是**无权图上的最短路**。

## 2. 读完题的第一反应

**朴素解法**：把每个格子看成一个状态，从 1 开始做 DFS，枚举所有掷骰序列，找到第一条到达 n² 的路径。它卡在**指数级分支**：每回合最多 6 个选择，深度可能到 n²，搜索树规模是 6^(n²)，n=20 时完全不可行。而且 DFS 找到的第一条路径不保证最短。

**关键观察**：题目要的是「最少掷骰次数」，而每一次掷骰的代价都是 1——这是一张**边权全为 1 的图**。边权为 1 的最短路，标准工具就是 BFS：BFS 按层扩展，第一次碰到目标时走过的层数就是最短距离。这个观察直接把「枚举所有路径」变成「每个格子只访问一次」。

第二个观察藏在题面里：「最多只能爬过蛇或梯子一次」。这句话决定了**建图方式**——从格子 curr 掷出点数 k 落到 next = curr + k 后，如果 next 上有传送，就直接把 next 改写成 board 上记录的目的地，然后把这个**改写后的终点**作为 BFS 的邻居。不能把传送当成额外的一步，也不能链式传送。

## 3. 从暴力到最优

**瓶颈一：状态爆炸。** DFS 会重复到达同一个格子很多次。消掉它的办法是 BFS + visited 数组：一个格子一旦被访问过，它的最短距离就确定了，之后再遇到直接跳过。这样状态数从「所有路径」压缩到「n² 个格子」。

**瓶颈二：编号与坐标的换算。** 棋盘是「蛇形」编号：第 0 行（最底行）从左到右，第 1 行从右到左，交替进行。如果每次访问格子都现场推导坐标，逻辑容易写错。做法是写一个 `get_pos(num)` 函数，把编号 num 映射到 (row, col)，BFS 里只操作编号，只在需要查 board 值时调用它。

推导：num 从 1 开始，先减 1 变成 0-based 的 `idx = num - 1`。`row_from_bottom = idx // n`，`col_in_row = idx % n`。实际行号 `r = n - 1 - row_from_bottom`。列号要看 `row_from_bottom` 的奇偶：偶数行（从底往上数第 0、2、4… 行）从左往右，`c = col_in_row`；奇数行从右往左，`c = n - 1 - col_in_row`。

**小例子走一遍**：用示例 2，board = [[-1,3],[-1,-1]]，n=2。

- 起点 1，`idx=0`，`row_from_bottom=0`，`r=1`，偶数行 `c=0`，board[1][0] = -1，无传送。
- BFS 队列初始 [(1, 0)]，visited={1}。
- 弹出 1，掷 1~2（因为 min(1+6, 4)=4，但 1+1=2、1+2=3 都在范围内，实际可到 2、3、4 中 ≤4 的）。等等，n²=4，所以 next ∈ [2, 4]。
  - next=2：`idx=1`，`row_from_bottom=0`，`r=1`，`c=1`，board[1][1]=-1，落到 2。入队 (2,1)。
  - next=3：`idx=2`，`row_from_bottom=1`，`r=0`，奇数行 `c = 2-1-0 = 1`，board[0][1]=3，传送后仍是 3。入队 (3,1)。
  - next=4：就是 n²，直接返回 1。
- 所以答案是 1。这里注意 next=3 时 board 值是 3，传送「到 3」等于原地，但题面保证 1 和 n² 不是起点，3 可以是终点，逻辑上照常处理即可。

**瓶颈三：传送只算一次。** 如果写成「while board 上有传送就继续跳」，示例 1 里 2→15、15 上若无传送则停；但若 15 上也有传送，就会多跳一次，答案偏小。正确写法是 `if board[r][c] != -1: nxt = board[r][c]`，只做一次赋值，不做循环。

## 4. 正确性：为什么不会漏、不会重

**不变量**：BFS 队列中，所有距离为 d 的格子一定排在所有距离为 d+1 的格子之前；且一个格子第一次被弹出时，记录的步数就是它到起点 1 的最少掷骰次数。

**为什么不会漏**：从任意格子 curr 出发，合法的一步就是掷出 1~6 中不越界的点数，落点经一次传送改写。BFS 对每个弹出的 curr 枚举了全部 6 个（或更少的）合法 next，所以图中每条边都被考虑过。任何一条从 1 到 n² 的合法路径，其每一步都对应 BFS 枚举过的一条边，因此路径上的每个格子都会被访问到。

**为什么不会重（且最短）**：用 visited 集合保证每个格子只入队一次。假设格子 v 第一次被访问时距离是 d，若存在更短路径距离 d' < d，那么 BFS 按层扩展，v 会在第 d' 层就被发现并入队，矛盾。所以第一次访问即最短。又因为边权全为 1，BFS 的层数就是掷骰次数，第一次弹出 n² 时返回的步数就是全局最少。

**传送只算一次的正确性**：题面明确「最多只能爬过蛇或梯子一次」，所以从 curr 到 next 的边定义为「掷骰落点 + 至多一次传送改写」。BFS 枚举的正是这个定义下的边，与题意一致。

## 5. 完整代码（Python）

```python
from collections import deque

class Solution:
    def snakesAndLadders(self, board: list[list[int]]) -> int:
        n = len(board)
        target = n * n

        def get_pos(num: int) -> tuple[int, int]:
            # 编号 num 是 1-based，转成 0-based 下标
            idx = num - 1
            row_from_bottom = idx // n          # 从底往上数第几行
            col_in_row = idx % n                # 该行内从左往右的第几个
            r = n - 1 - row_from_bottom         # 实际行号（0 在最上面）
            # 偶数行（从底数第 0、2、4… 行）从左往右；奇数行从右往左
            if row_from_bottom % 2 == 0:
                c = col_in_row
            else:
                c = n - 1 - col_in_row
            return r, c

        # BFS：队列存 (当前格子编号, 已掷骰次数)
        q = deque([(1, 0)])
        visited = {1}

        while q:
            curr, steps = q.popleft()
            # 枚举掷出 1~6 的所有落点
            for k in range(1, 7):
                nxt = curr + k
                if nxt > target:
                    break  # 超出棋盘，更大的 k 也一定超出
                r, c = get_pos(nxt)
                if board[r][c] != -1:
                    nxt = board[r][c]  # 传送一次，且只传一次
                if nxt == target:
                    return steps + 1
                if nxt not in visited:
                    visited.add(nxt)
                    q.append((nxt, steps + 1))
        return -1
```

几个容易写错的点，代码里已经处理：`nxt > target` 时 `break` 而不是 `continue`，因为 k 递增，后面只会更大；传送后要判断 `nxt == target`，因为传送可能直接送到终点；`visited` 在入队时标记，避免同一格子被多个前驱重复入队。

## 6. 复杂度

**时间**：O(n²)。每个格子最多入队一次，每次弹出枚举至多 6 个邻居，6 是常数。`get_pos` 是 O(1) 的算术运算。所以总操作数是 6·n²，即 O(n²)。这里没有 log n 项——没有排序、没有二分、没有堆。

**空间**：O(n²)。`visited` 集合最多存 n² 个编号，BFS 队列最多同时存 O(n²) 个格子（最坏一层很宽）。board 本身是输入，不计入额外空间。

## 7. 边界与反例（至少 4 条）

1. **输入**：board = [[-1,-1],[-1,-1]]，n=2 → **期望 1**。从 1 掷 3 点到 4。**易错点**：有人把「掷骰点数」和「格子编号差」搞混，以为只能走 1 步；或者 `get_pos` 的奇偶行判断写反，导致查错 board 值。

2. **输入**：board = [[-1,-1],[-1,3]] → **期望 1**。从 1 掷 2 点到 3，board 上 3 的值是 3（传送原地），再掷 1 点到 4？不对——注意从 1 掷 3 点直接到 4，一步到位。**易错点**：把「传送原地」当成死循环或额外消耗一步；实际上传送后 nxt 仍是 3，但 BFS 从 1 也能直接到 4，答案 1。

3. **输入**：board 中某格 board[r][c] 指向一个**更小的编号**（蛇），且该编号已被 visited → **期望**：正常跳过，不重复入队。**易错点**：传送后不检查 visited，导致同一格子反复入队，队列膨胀甚至死循环（若传送形成环）。

4. **输入**：n=2，board = [[-1,-1],[-1,-1]] 但起点 1 的 board 值非 -1（题面保证不会，但若测试数据违规）→ **期望**：按题面假设起点无传送，代码从 1 开始不查 board[起点]，所以不受影响。**易错点**：有人从 1 开始就先查一次 board[1 的坐标]，把起点也传送了，逻辑偏离题意。

5. **输入**：无法到达 n² 的棋盘（例如所有落点都被蛇传回起点附近且形成封闭集）→ **期望 -1**。**易错点**：BFS 队列空了忘记返回 -1，或者用 `while q` 但最后没有兜底 return。

## 8. 面试追问与变体（3 条）

1. **追问**：如果骰子不是 6 面，而是每次可以走 1~m 步（m 由输入给出），复杂度怎么变？**思路**：BFS 不变，内层循环改成 `range(1, m+1)`，时间 O(m·n²)，m 是常数时仍是 O(n²)。

2. **追问**：如果要求返回具体路径（经过哪些格子），而不只是步数？**思路**：BFS 时额外记录 `parent[nxt] = curr`，到达终点后从 target 沿 parent 回溯，反转得到路径。

3. **追问**：如果蛇和梯子可以**连续传送**（链式），题意怎么改、代码怎么改？**思路**：把传送改成 `while board[r][c] != -1: nxt = board[r][c]; r,c = get_pos(nxt)`，但要加环检测（visited 传送链上的格子），否则可能死循环；此时「一步」的语义变成「掷骰 + 任意次传送」。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 127. 单词接龙**：同样是无权图最短路，BFS 按层扩展，每个状态只访问一次；区别在于邻居的生成方式（逐字符替换）而非固定 6 个。

2. **LeetCode 752. 打开转盘锁**：状态是 4 位数字串，每步拨一位，BFS 求最少步数；和本题一样需要 visited 去重、按层计数，且要处理「死锁」这种不可达状态返回 -1。

3. **LeetCode 1091. 二进制矩阵中的最短路径**：8 方向 BFS，边权为 1，第一次到达终点即最短；共同点是「网格 + 固定邻居枚举 + visited 剪枝」的 BFS 骨架。
