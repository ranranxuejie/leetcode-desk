## 1. 一句话本质

在所有「连续子数组」里，找一个乘积最大的，而乘积这个运算的特殊性在于：**负负得正**，所以「当前最小的乘积」随时可能翻盘变成「最大的乘积」。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子数组，起点 `i` 从 0 到 n-1，终点 `j` 从 i 到 n-1，把 `nums[i..j]` 乘起来取最大。子数组个数是 O(n²)，每个再花 O(n) 连乘，总复杂度 O(n³)；即使边枚举边累乘，也是 O(n²)。n 最大 2×10⁴，O(n²) 是 4×10⁸ 次操作，Python 里必超时。瓶颈很清楚：**我们枚举了太多「没必要单独考虑」的子数组**。

**关键观察**：如果题目问的是「和最大子数组」，你会立刻想到：以 `i` 结尾的最大和，只依赖「以 `i-1` 结尾的最大和」，因为加法里正数永远帮正忙。但乘法不一样——一个很小的负数乘以当前负数，会变成很大的正数。也就是说，**以 `i-1` 结尾的最小乘积（最负的那个），乘以 `nums[i]` 后可能一跃成为以 `i` 结尾的最大乘积**。

这个观察直接给出下一步：状态不能只记「最大」，必须同时记「最大」和「最小」。这就是本题和「最大子序和」最本质的区别，也是 44.9% 通过率的主要来源——很多人套了加法那题的模板，只维护一个 max，遇到负数就崩。

## 3. 从暴力到最优

**第一步：从 O(n³) 到 O(n²)。** 固定起点 `i`，让 `j` 从 `i` 往后走，边走边乘，`prod *= nums[j]`，每步更新答案。这样每个子数组只花 O(1)，总 O(n²)。瓶颈变成「起点有 n 个，每个都要重新起跑」。

**第二步：从 O(n²) 到 O(n)。** 问自己：以 `i` 结尾的所有子数组，它们的乘积集合，能不能由「以 `i-1` 结尾的乘积集合」推出来？答案是能——以 `i` 结尾的子数组，要么是 `[nums[i]]` 单独一个，要么是「某个以 `i-1` 结尾的子数组」再接上 `nums[i]`。所以乘积集合 = {nums[i]} ∪ {p × nums[i] : p 属于以 i-1 结尾的乘积集合}。

问题在于这个集合可能很大。但我们只要**最大值**，而乘法对「取最大」有个好性质：如果 `nums[i] > 0`，集合里最大的 p 给出最大的结果；如果 `nums[i] < 0`，集合里**最小**的 p 给出最大的结果。所以只需要保留集合里的 max 和 min 两个数就够了——其余的数无论怎么乘，都不可能超过这两个之一产生的候选。

**走一遍示例 1：nums = [2, 3, -2, 4]**

初始化 `max_here = min_here = nums[0] = 2`，`ans = 2`。

- i=1，x=3：候选 = {3, max_here×3=6, min_here×3=6} → 新 `max_here=6`，`min_here=3`，`ans=6`。
- i=2，x=-2：候选 = {-2, 6×(-2)=-12, 3×(-2)=-6} → 新 `max_here=-2`，`min_here=-12`，`ans` 仍为 6。注意这里 max 掉到了 -2，但 min 记下了 -12，为后面翻盘埋了伏笔。
- i=3，x=4：候选 = {4, (-2)×4=-8, (-12)×4=-48} → 新 `max_here=4`，`min_here=-48`，`ans=6`。

最终 6，正确。注意 i=2 时如果只维护 max，会得到 -2 然后一路错下去；正是 `min_here=-12` 这个「最负值」保证了状态完整。

**走一遍示例 2：nums = [-2, 0, -1]**

- 初始 `max_here=min_here=-2`，`ans=-2`。
- i=1，x=0：候选 = {0, -2×0=0, -2×0=0} → `max_here=0`，`min_here=0`，`ans=0`。0 把之前所有积累「清零」，这是乘法特有的断点。
- i=2，x=-1：候选 = {-1, 0×(-1)=0, 0×(-1)=0} → `max_here=0`，`min_here=-1`，`ans=0`。

输出 0，正确。这个例子说明：`[-2, -1]` 虽然乘积是 2，但它不连续（中间隔着 0），所以不能选——这正是题面解释强调的点。

**一个易错细节**：更新 `max_here` 和 `min_here` 时，必须用**旧的**两个值同时算，不能先更新 max 再用新 max 算 min。代码里用临时变量或元组赋值解决。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义：

> 不变量：处理完 `nums[i]` 后，`max_here` 等于「所有以 i 结尾的非空连续子数组的乘积」中的最大值，`min_here` 等于其中的最小值。

**基础**：i=0 时，以 0 结尾的子数组只有 `[nums[0]]`，max 和 min 都是它，成立。

**归纳**：假设对 i-1 成立。以 i 结尾的任一子数组，要么是 `[nums[i]]`，要么形如 `nums[j..i]`（j ≤ i-1），后者等于 `nums[j..i-1]` 再乘 `nums[i]`。所以「以 i 结尾的乘积集合」= `{nums[i]} ∪ {p·nums[i] : p ∈ S_{i-1}}`，其中 `S_{i-1}` 是以 i-1 结尾的乘积集合。

现在要证这个集合的 max 和 min 只由 `S_{i-1}` 的 max、min 决定。分情况：

- 若 `nums[i] > 0`：对任意 p，`p·nums[i]` 随 p 单调递增，所以集合里的最大候选是 `max(S_{i-1})·nums[i]`，最小候选是 `min(S_{i-1})·nums[i]`。
- 若 `nums[i] < 0`：乘法翻转序，最大候选是 `min(S_{i-1})·nums[i]`，最小候选是 `max(S_{i-1})·nums[i]`。
- 若 `nums[i] = 0`：所有候选都是 0。

三种情况下，集合的极值都只依赖 `S_{i-1}` 的两个极值，加上单独元素 `nums[i]` 一起取 max/min 即可。归纳成立。

**不漏**：每个以 i 结尾的子数组都被 `{nums[i]} ∪ {p·nums[i]}` 覆盖，没有遗漏。**不重**：我们不是枚举子数组，而是对「乘积集合」取极值，取极值这个操作本身不关心重复，所以不存在重复计数问题。最终 `ans` 是遍历所有 i 时 `max_here` 的最大值，而每个子数组必以某个 i 结尾，故 `ans` 就是全局最大。

## 5. 完整代码（Python）

```python
class Solution:
    def maxProduct(self, nums: list[int]) -> int:
        # max_here / min_here：以当前下标结尾的子数组乘积的 最大 / 最小 值
        # 初始化成第一个元素，因为子数组至少含一个数
        max_here = min_here = nums[0]
        ans = nums[0]

        for x in nums[1:]:
            # 关键：必须用「旧的」max_here 和 min_here 同时算候选，
            # 所以先把两个候选都算出来再赋值，避免先更新 max 污染 min 的计算
            cand1 = max_here * x   # 旧最大值乘 x
            cand2 = min_here * x   # 旧最小值乘 x（x 为负时它可能最大）

            # 新的 max/min 在「单独成段 x」和两个候选之间取
            max_here = max(x, cand1, cand2)
            min_here = min(x, cand1, cand2)

            # 全局答案在每一步的 max_here 里取最大
            ans = max(ans, max_here)

        return ans
```

几个注释对应的坑：`cand1`、`cand2` 必须在更新前算好；`x` 本身要作为候选，因为「从 x 重新开始」可能比接前面更优（比如前面乘积是 0 或很小的负数）；`ans` 初始化为 `nums[0]` 而不是 0，防止全负数数组（如 `[-2]`）返回 0。

## 6. 复杂度

**时间 O(n)**：`for` 循环跑 `n-1` 次，每次做常数次乘法、比较、赋值，没有内层循环。n 来自数组长度，没有 log 项——因为没有排序、没有二分、没有按位分治。

**空间 O(1)**：只用了 `max_here`、`min_here`、`ans`、`cand1`、`cand2`、`x` 这几个标量，与 n 无关。没有开 DP 数组。如果写成 `dp_max[i]`、`dp_min[i]` 的数组形式，空间是 O(n)，但因为 `dp[i]` 只依赖 `dp[i-1]`，可以滚动掉，所以最优是 O(1)。

## 7. 边界与反例（至少 4 条）

1. **`nums = [-2]`** → 期望 `-2`。容易错在把 `ans` 初始化成 0 或 1，返回 0/1。单个负数也是合法子数组。
2. **`nums = [0, 2]`** → 期望 `2`。容易错在 0 把状态「污染」后没恢复：如果写成「遇到 0 就重置为 1 再乘」，会把 0 本身漏掉；正确做法是让 `x=0` 作为候选参与 max/min，自然处理。
3. **`nums = [-2, 3, -4]`** → 期望 `24`（整个数组）。容易错在只维护 max：i=1 时 max=3，i=2 时 3×(-4)=-12，得到 -12，漏掉 (-2)×3×(-4)=24。必须靠 `min_here` 在 i=1 时记下 -6，i=2 时 -6×(-4)=24 才能翻盘。
4. **`nums = [-1, -2, -3]`** → 期望 `6`（前两个）。容易错在认为「全负数一定取最大那个单元素」，实际上两个负数相乘更正。也容易错在更新顺序：若先 `max_here = max(...)` 再算 `min_here = min(min_here*x, max_here*x)`，此时 `max_here` 已是新值，`min_here` 算错。
5. **`nums = [2, -5, -2, -4, 3]`** → 期望 `24`（`[-5,-2,-4,3]` 中 -5×-2×-4×3 = -120？重算：-5×-2=10，10×-4=-40，-40×3=-120；实际最大是 `[-2,-4,3]`=24 或 `[2,-5,-2,-4]`= -80… 正确最大为 24，来自 `[-2,-4,3]`）。这条用来检验「负数个数奇偶」的直觉：不是简单看总负号数，而是看连续段内的分布，DP 能自动处理。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回子数组本身（下标），怎么改？** 思路：在更新 `max_here` 时额外记录「当前最优是从哪个下标开始的」，即维护 `start_max`、`start_min`，当选择「单独成段 x」时把起点设为当前 i，否则继承前驱的起点；`ans` 更新时同步记下 `(start, i)`。
2. **追问：如果数组里允许浮点数，或者乘积会溢出 32 位怎么办？** 思路：浮点直接照搬；溢出场景下要么用 Python 大整数（本题语言天然安全），要么在 C++ 里用 `long long` 并注意比较时可能溢出，可改存对数（`log|p|` 加符号位）来比较，但会损失精度，需和面试官确认。
3. **追问：如果改成「乘积最大子序列」（不要求连续）呢？** 思路：那就变成统计负数个数——负数为偶数则全乘，为奇数则去掉绝对值最小的那个负数（或 0 分段），是贪心而非 DP，和本题的「连续」约束是本质区别。

## 9. 举一反三（2-3 道同类题）

- **53. 最大子序和**：同样是「以 i 结尾」的线性 DP，但加法只需维护一个 max，对照本题能看清「乘法为什么要多维护一个 min」。
- **1567. 乘积为正数的最长子数组长度**：同样利用「负负得正」，维护以 i 结尾的「乘积为正 / 为负」的最长长度，是本题状态设计的直接变体。
- **1186. 删除一次得到子数组最大和**：也是「以 i 结尾 + 多一个状态维度（是否已删除）」的滚动 DP，和本题「多维护一个 min」是同一类「状态扩维」思路。
