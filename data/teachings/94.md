## 1. 一句话本质

按「左子树 → 根 → 右子树」的固定顺序，把树里每个节点的值各收集一次，拼成一个列表。

这里的关键词是「固定顺序」：中序遍历不是随便走，而是对**每一个**节点都强制遵守同一个局部规则——先处理完它的左子树，再记录它自己，最后处理右子树。整棵树的遍历顺序，就是这条规则递归展开的结果。

## 2. 读完题的第一反应

**朴素解法**：递归。写一个 `dfs(node)`，先 `dfs(node.left)`，再 `ans.append(node.val)`，再 `dfs(node.right)`。这几乎是照着定义翻译，三行就完事。

但它卡在哪？卡在两点：

1. **递归深度**。Python 默认递归深度约 1000，本题节点数 ≤ 100，所以实际不会爆栈。但如果面试官把约束改成 10^5（这是很常见的追问），一条链状的树就会直接 `RecursionError`。所以「递归能过」是题目约束给的运气，不是算法本身的性质。
2. **面试官明确在进阶里问了**：「你可以通过迭代算法完成吗？」这句话就是在告诉你：递归版本只是入场券，他真正想看的是你能不能**自己维护那个「递归调用栈」**。

**关键观察**：递归函数 `dfs(node)` 在「处理完左子树、还没处理右子树」这个中间状态时，它其实**挂起**了——它记住了「我现在在 node，左子树已经搞定，接下来该输出 node 了」。这个「挂起」的信息，就是迭代法要手动保存的东西。

一旦你意识到「递归 = 系统帮你维护一个栈」，下一步就自然了：我拿一个显式的栈，把「挂起」这件事自己写出来。这就是从递归到迭代的全部动机，不是技巧，是翻译。

## 3. 从暴力到最优

**第一步：递归版（暴力/朴素）**

```python
def dfs(node):
    if not node: return
    dfs(node.left)
    ans.append(node.val)
    dfs(node.right)
```

瓶颈：受调用栈深度限制，且「挂起状态」由解释器保管，你无法控制。

**第二步：迭代版——手动模拟栈**

核心难点在于：递归里「先一路向左走到底」这个动作，在迭代里要变成一个 while 循环，而且**沿途经过的每个节点都要压栈**，因为它们都是「左子树处理完了、自己还没输出」的挂起者。

用一个具体例子走一遍。树是 `root = [1, null, 2, 3]`，结构为：

```
    1
     \
      2
     /
    3
```

初始 `stack = []`，`cur = 1`，`ans = []`。

| 步骤 | 动作 | stack（底→顶） | cur | ans |
|---|---|---|---|---|
| 1 | cur=1 非空，压栈，向左走（左为空） | [1] | None | [] |
| 2 | cur 为空，弹栈得 1，输出 1，转向右子树 | [] | 2 | [1] |
| 3 | cur=2 非空，压栈，向左走 | [2] | 3 | [1] |
| 4 | cur=3 非空，压栈，向左走 | [2,3] | None | [1] |
| 5 | cur 为空，弹栈得 3，输出 3，转向右子树（空） | [2] | None | [1,3] |
| 6 | cur 为空，弹栈得 2，输出 2，转向右子树（空） | [] | None | [1,3,2] |
| 7 | cur 为空且栈空，结束 | [] | None | [1,3,2] |

输出 `[1,3,2]`，与示例一致。

**瓶颈怎么被消掉的**：原来「挂起」靠系统调用栈，现在靠一个普通 list 当栈，深度不再受解释器限制（只受内存限制）。时间上没有任何变化——每个节点仍然只被压栈一次、弹栈一次、输出一次，还是 O(n)。所以这一步**优化的是空间的可控性和鲁棒性，不是时间复杂度**。这一点面试时要讲清楚，别把「改成迭代」说成「变快了」。

**第三步：还有没有更优？**

没有。中序遍历必须访问每个节点至少一次才能输出它的值，下界就是 Ω(n)。所以迭代版已经是本题的最优解。真正值得讨论的「更优」是空间：Morris 遍历能把额外空间降到 O(1)（借用叶子节点的空右指针做临时线索），但会**临时修改树结构**，代码复杂、易错，面试里属于加分项而非必需项。本题不展开，第 8 节会提一句。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。设当前栈为 S，当前指针为 cur，已输出列表为 ans。

**不变量**：在每一轮循环开始时，S 中从底到顶的节点，恰好是「左子树已全部处理完、自身尚未输出」的那些祖先节点，且它们的顺序是从根往下的路径顺序；cur 指向「下一个待处理子树的根」（可能为空）。

分三种情况验证：

1. **cur 非空**：说明 cur 这棵子树还没开始处理。按中序定义，必须先处理它的左子树，所以把 cur 压栈（它成为新的挂起者），cur 左移。不变量保持：cur 的父节点仍在栈里且仍未输出，符合「挂起」定义。
2. **cur 为空且栈非空**：说明栈顶节点 t 的左子树已经处理完毕（否则 cur 不会为空着回来）。此时按定义该输出 t 了，弹出并 append。然后转向 t 的右子树。不变量保持：t 已从挂起集合中移除，右子树的根成为新的 cur。
3. **cur 为空且栈空**：所有挂起者都已输出，且没有待处理子树，遍历结束。

**不漏**：每个节点入栈时被记录为挂起者，出栈时被输出，入栈与出栈一一对应，所以每个节点恰好输出一次。
**不重**：节点只在出栈那一刻 append，而出栈是弹出操作，物理上移除了，不可能再弹第二次。
**顺序对**：由情况 2 可知，节点 t 被输出时，它的左子树已全部输出（因为 cur 是从左子树一路走空回来的），而它的右子树尚未开始（cur 刚被设为 t.right）。这正是「左—根—右」，与中序定义逐字吻合。

## 5. 完整代码（Python）

```python
from typing import Optional, List

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

class Solution:
    def inorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        ans = []
        stack = []          # 手动维护的「挂起栈」：左子树已处理、自身待输出的节点
        cur = root          # 当前正在处理的子树根，可能为 None

        # 只要还有待处理子树，或栈里还有挂起者，就继续
        while cur or stack:
            # 阶段一：一路向左，把沿途节点全部压栈（它们都是未来的挂起者）
            while cur:
                stack.append(cur)
                cur = cur.left

            # 阶段二：左边走不动了，栈顶就是「左已完、该输出自己」的节点
            cur = stack.pop()
            ans.append(cur.val)   # 中序的「根」在这里输出

            # 阶段三：转向右子树，下一轮循环会继续往它的左边钻
            cur = cur.right

        return ans
```

递归版对照（面试可先写这个再改迭代）：

```python
class Solution:
    def inorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        ans = []
        def dfs(node):
            if not node:
                return
            dfs(node.left)      # 左
            ans.append(node.val)  # 根
            dfs(node.right)     # 右
        dfs(root)
        return ans
```

## 6. 复杂度

**时间 O(n)**，n 为节点数。来源：外层 while 每轮要么消耗一个栈元素（pop 一次），要么推进 cur；内层 while 每个节点最多被压栈一次。总计每个节点「压栈 1 次 + 弹栈 1 次 + append 1 次」，常数次操作，故 O(n)。这里**没有 log n 项**——因为遍历是线性的，不涉及二分或树高相关的分支。

**空间 O(h)**，h 为树高。来源：栈的最大深度等于「从根一路向左的最长路径」，最坏情况是链状树 h = n，此时 O(n)；最好情况是平衡树 h = log n，此时 O(log n)。另外 `ans` 本身占 O(n)，但那是输出，通常不计入辅助空间。递归版的空间同样是 O(h)，只不过藏在系统调用栈里。

## 7. 边界与反例（至少 4 条）

1. **输入 `root = []`（空树）** → 期望 `[]`。易错点：没判空就访问 `root.left`，直接 `AttributeError`。迭代版里 `while cur or stack` 天然处理了空树（两个都空，循环不进），但递归版必须写 `if not node: return`。
2. **输入 `root = [1]`（单节点）** → 期望 `[1]`。易错点：以为「没有左子树就没东西可输出」，把输出逻辑写进了内层 while 里，导致单节点被漏掉。正确写法是输出发生在**弹栈之后**，与左子树是否存在无关。
3. **输入 `root = [1,2]`（只有左孩子）** → 期望 `[2,1]`。易错点：把中序当成「先根后左」，输出成 `[1,2]`。中序是左在前，根在中间，这个例子最能暴露顺序写反。
4. **输入 `root = [1,null,2]`（只有右孩子）** → 期望 `[1,2]`。易错点：内层 while 一路向左时 cur 立刻变 None，若此时误以为「遍历结束」而退出，就会漏掉右子树。必须靠外层 `while cur or stack` 继续。
5. **输入 `root = [3,1,4,null,2]`（左子树带右孩子）** → 期望 `[1,2,3,4]`。易错点：从节点 1 转向右孩子 2 后，忘了「对新子树重新一路向左压栈」，直接输出 2 之前漏了压栈步骤，导致 2 的子树处理顺序错乱。

## 8. 面试追问与变体（3 条）

1. **追问：不用递归也不用显式栈，能做到 O(1) 额外空间吗？**
   思路：Morris 中序遍历。对每个有左子树的节点，找到其左子树的最右节点，把它的 right 临时指向当前节点，形成线索；遍历完再拆掉。时间仍 O(n)（每条边最多走两次），空间 O(1)，代价是临时改树、代码易错。

2. **追问：如果要求返回的是「第 k 个被访问的节点」而不是整个列表呢？**
   思路：迭代版天然支持「访问到第 k 个就 return」，把 `ans.append` 换成计数器 `cnt += 1; if cnt == k: return cur.val`，可以提前终止，平均时间优于 O(n)。递归版做不到这么干净的提前退出。

3. **追问：改成前序/后序，代码怎么变？**
   思路：前序只需把「append」从弹栈后移到压栈时；后序可用「根右左」的前序变体再整体反转，或用一个 `last_visited` 指针判断右子树是否已处理。核心都是调整「输出时机」相对「压栈/弹栈」的位置。
