## 1. 一句话本质

在 `t` 中按从左到右的顺序，能否**依次**找到 `s` 的每一个字符——即判断 `s` 是否是 `t` 的一个「按序抽取」结果。

## 2. 读完题的第一反应

**朴素解法**：枚举 `s` 在 `t` 中的所有「下标组合」，检查是否存在一组递增下标 `i1 < i2 < ... < im` 使得 `t[i1]=s[0], t[i2]=s[1], ...`。这等价于枚举 `t` 的所有子序列（共 2^n 个）再比对，复杂度指数级，显然不可行。

**稍微聪明一点的暴力**：对 `s` 的每个字符，在 `t` 中从「上一次匹配位置之后」开始线性扫描找它。这其实就是双指针的雏形，但很多人第一次写会写成「对每个 s 字符都从头扫 t」，复杂度 O(m·n)，而且逻辑上还会错（会重复使用 t 的同一个字符）。

**关键观察**：题目要求「不改变相对位置」，这句话直接告诉我们——匹配是**单向推进**的。一旦 `s[i]` 匹配到 `t` 的位置 `j`，那么 `s[i+1]` 只可能在 `j` 之后。于是我们根本不需要回头，也不需要枚举组合：**两个指针各自只往前走，永不后退**。这就是双指针能成立的全部理由。

再往深一层想：为什么「贪心地取最早出现的匹配位置」是对的？因为越早匹配，留给后面字符的 `t` 的剩余部分就越长，可选空间只会更大不会更小。这个直觉在第 4 节会严格化。

## 3. 从暴力到最优

**暴力版本（错误示范，但能说明瓶颈）**：

```
for ch in s:
    for j in range(len(t)):      # 每次都从头扫
        if t[j] == ch:
            match...
```

瓶颈：每个 `s` 字符都要扫一遍 `t`，O(m·n)；而且「从头扫」会重复使用已用过的位置，逻辑错误。

**改进 1：记录上次位置**。用一个变量 `j` 记住「`t` 已经消费到哪」，下一个字符从 `j` 继续往后找。这样 `t` 的每个位置最多被访问一次，总扫描量降到 O(n)。但注意：如果对每个 `s` 字符都写一个内层 `while` 从 `j` 找起，最坏情况下 `j` 仍然只前进不后退，所以整体还是 O(n)——这就是双指针。

**改进 2（本题最终形态）**：把「找 `s[i]` 在 `t` 中的位置」和「推进 `t`」合并成一个循环：`i` 指向 `s`，`j` 指向 `t`，同步走。

**具体小例子**：`s = "abc"`, `t = "ahbgdc"`

| 步骤 | i | j | s[i] | t[j] | 动作 |
|---|---|---|---|---|---|
| 初始 | 0 | 0 | 'a' | 'a' | 相等，i=1, j=1 |
| 1 | 1 | 1 | 'b' | 'h' | 不等，j=2 |
| 2 | 1 | 2 | 'b' | 'b' | 相等，i=2, j=3 |
| 3 | 2 | 3 | 'c' | 'g' | 不等，j=4 |
| 4 | 2 | 4 | 'c' | 'd' | 不等，j=5 |
| 5 | 2 | 5 | 'c' | 'c' | 相等，i=3, j=6 |
| 结束 | 3 | 6 | — | — | i == len(s)，返回 True |

再看反例 `s = "axc"`, `t = "ahbgdc"`：`a` 匹配后 `j=1`；`x` 从 `j=1` 扫到末尾都没找到，`j` 走到 6，循环结束 `i=1 < 3`，返回 False。注意此时 `x` 根本没匹配上，`c` 也就无从谈起——这正是「按序」的含义。

## 4. 正确性：为什么不会漏、不会重

用**贪心选择 + 交换论证**说明。

**不变量**：在双指针循环的任意时刻，`s[0..i-1]` 已经作为子序列匹配进了 `t[0..j-1]`，并且 `j` 是「能匹配完 `s[0..i-1]` 的所有方案中，`t` 消耗位置最靠前的那一个」。

**为什么「最靠前」重要（交换论证）**：假设存在某个匹配方案把 `s[i]` 匹配到 `t` 的位置 `k`，而我们贪心选的是 `t` 中 `≥ j` 的第一个等于 `s[i]` 的位置 `j'`。由贪心定义 `j' ≤ k`。那么把原方案中 `s[i]` 的匹配位置从 `k` 换成 `j'`，后面的字符匹配位置全部不变——因为 `j' ≤ k`，后面字符用的位置本来就 `> k > j'`，相对顺序依然成立。所以「换用更靠前的匹配」不会破坏任何后续可行性。归纳下去，贪心方案可行当且仅当存在可行方案。

**不会漏**：如果贪心走到 `t` 末尾仍有 `s` 字符没匹配上，说明对当前字符 `s[i]`，`t` 从 `j` 到末尾根本没有这个字符。任何方案要匹配 `s[i]`，其位置必须 `≥ j`（因为前 `i` 个字符已经「最靠前」地占用了 `t[0..j-1]`），而这段里没有该字符，故无解。

**不会重**：`j` 单调递增，每个 `t` 位置最多被消费一次，天然满足「不重复使用字符」。

## 5. 完整代码（Python）

```python
class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        i = 0  # 指向 s 中待匹配的字符
        j = 0  # 指向 t 中当前扫描到的位置，只前进不后退
        m, n = len(s), len(t)

        # 只要 s 还没匹配完，且 t 还没扫完，就继续
        while i < m and j < n:
            if s[i] == t[j]:
                i += 1  # 匹配成功，s 前进一位
            j += 1      # 无论是否匹配，t 都要前进（关键：不回头）

        # s 全部匹配完才算成功；若 t 先扫完则 i < m，返回 False
        return i == m
```

> 说明：题面提示里 `0` 那两行被截断了，按力扣原题应为 `0 <= s.length <= 100`、`0 <= t.length <= 10^4`。本解法对空串同样正确（`m=0` 时循环不进入，直接返回 `True`）。

## 6. 复杂度

- **时间 O(n + m)**：`j` 从 0 走到 `n`，每轮 `while` 必让 `j` 加 1，所以 `t` 的每个字符最多被看一次，贡献 O(n)；`i` 从 0 走到 `m`，每次匹配成功才加 1，贡献 O(m)。两者相加 O(n+m)。注意这里**没有** log 项——因为没有二分、没有排序。
- **空间 O(1)**：只用了 `i, j, m, n` 四个整型变量，与输入规模无关。

对比：如果写成「对每个 `s` 字符都从头扫 `t`」，时间会退化成 O(m·n)；双指针把「回头」这个动作彻底消掉了，才降到线性。

## 7. 边界与反例（至少 4 条）

1. `s = ""`, `t = "abc"` → **True**。空串是任何串的子序列。易错点：有人写 `if not s: return False`，把空串当失败。
2. `s = "abc"`, `t = ""` → **False**。`t` 为空但 `s` 非空，`i` 停在 0，返回 `i == m` 为 False。易错点：循环条件写成 `while j < n` 而漏掉 `i < m`，导致空 `t` 时死循环或误判。
3. `s = "aaaa"`, `t = "aa"` → **False**。`t` 只有两个 `a`，`s` 需要四个。易错点：误以为「字符种类对就行」，忽略**数量**约束；双指针靠 `j` 单调前进自然挡住重复使用。
4. `s = "aec"`, `t = "abcde"` → **False**（题面明确点名的反例）。`a` 匹配 `t[0]`，`e` 匹配 `t[3]`，之后 `c` 在 `t[4..]` 中找不到（`c` 在 `t[2]`，已被越过）。易错点：误以为「每个字符都在 `t` 里出现」就够，忽略**相对顺序**——`c` 出现在 `e` 前面，不能回头取。
5. `s = "abc"`, `t = "abc"` → **True**。完全相同也是子序列（删除 0 个字符）。易错点：把「真子序列」和「子序列」混淆，多加 `i < m` 之外的严格性判断。

## 8. 面试追问与变体（3 条）

1. **追问：如果 k ≥ 10 亿个 `s` 依次判断是否为同一个 `t` 的子序列，怎么优化？**
   思路：预处理 `t`，对每个字符建「出现位置列表」，匹配时用 `bisect_right` 在列表里二分找「大于上一个位置的最小下标」。单次判断 O(m log n)，k 次总 O(k·m·log n)，避免每次重扫 `t`。这就是题面「进阶」的意图。

2. **追问：如果允许 `s` 的字符在 `t` 中「跳跃」但要求匹配位置严格递增且间隔不超过 d，怎么做？**
   思路：仍是双指针，但匹配时检查 `j - last_j <= d`，不满足则该 `s` 字符失败；本质是把「位置约束」加进贪心条件里。

3. **追问：如何判断 `s` 是 `t` 的**子串**（连续）而不是子序列？**
   思路：子串要求连续，双指针不再适用；改用滑动窗口或 KMP，在 `t` 中找 `s` 的连续出现，O(n+m)。

- **LeetCode 792. 匹配子序列的单词数**：正是本题「进阶」的落地版，对 `t` 预处理位置列表 + 二分，批量判断多个 `s`。
- **LeetCode 115. 不同的子序列**：把「是否存在」升级为「有多少种匹配方案」，双指针不够用，需要 DP，但「按序匹配」的核心思想一致。
