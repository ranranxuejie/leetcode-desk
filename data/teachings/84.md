## 1. 一句话本质

在所有可能的「以某根柱子为最低点、向左右延伸到第一个更矮柱子为止」的矩形里，取面积最大值。

## 2. 读完题的第一反应

**朴素解法**：枚举矩形的左右边界 `(i, j)`，这个矩形的最大高度是 `min(heights[i..j])`，面积 = 高度 × 宽度。枚举所有 `O(n²)` 个区间，每个区间求最小值再花 `O(n)`，总 `O(n³)`；用前缀/稀疏表优化最小值可以到 `O(n²)`。但 `n` 可达 `10^5`，`O(n²)` 是 `10^10` 级别，必然超时。瓶颈在于：**我们枚举的是「区间」，而区间有平方多个**。

**关键观察**：任何一个最优矩形，它的高度一定等于某根柱子的高度（否则把矩形往上抬一点还能更大，或者它已经顶到了某根柱子的顶端）。更进一步：如果固定「矩形的高度 = `heights[i]`」，那么这个矩形能往左延伸到第一个比 `heights[i]` 矮的柱子右边，往右延伸到第一个比 `heights[i]` 矮的柱子左边——再往外扩，高度就会被更矮的柱子卡住，`heights[i]` 就不再是有效高度了。

于是问题从「枚举平方个区间」变成「**对每根柱子，求它左右两边第一个更矮的柱子的位置**」。这就是「下一个更小元素」问题，而它有一个 `O(n)` 的单调栈解法。这一步转换是整道题的题眼：**把「求最大面积」翻译成「对每个位置求左右边界」**。

## 3. 从暴力到最优

**第一步：从 `O(n³)` 到 `O(n²)`。** 固定左边界 `i`，从左往右扫右边界 `j`，边扫边维护 `min_h = min(min_h, heights[j])`，面积 = `min_h * (j - i + 1)`。每个 `i` 扫一遍，`O(n²)`。瓶颈：仍然要枚举所有左边界。

**第二步：从 `O(n²)` 到 `O(n)`。** 利用上面的观察，只对「每根柱子作为最低点」算一次。对柱子 `i`，设 `left[i]` = 左边第一个 `heights` 严格小于 `heights[i]` 的下标，`right[i]` = 右边第一个严格小于 `heights[i]` 的下标，则以 `i` 为最低点的最大矩形宽度是 `right[i] - left[i] - 1`，面积 `heights[i] * (right[i] - left[i] - 1)`。

**怎么 `O(n)` 求 `left` 和 `right`？用单调递增栈。** 栈里存下标，保证栈内下标对应的 `heights` 单调递增。扫到 `i` 时，只要栈顶元素的高度 `>= heights[i]`，说明栈顶那个柱子的「右边第一个更矮的柱子」就是 `i`，可以弹栈并结算它的面积；弹完后栈顶就是 `i` 的「左边第一个更矮的柱子」。

**用示例 1 走一遍**：`heights = [2,1,5,6,2,3]`，为了统一处理「右边没有更矮的柱子」的情况，在末尾补一个高度 0 的哨兵，数组变成 `[2,1,5,6,2,3,0]`，下标 0..6。

| 步骤 | 当前 i / 高度 | 栈（存下标） | 动作与结算 |
|---|---|---|---|
| 1 | i=0, h=2 | [0] | 栈空，直接入栈 |
| 2 | i=1, h=1 | [] → [1] | 栈顶 0 高度 2 ≥ 1，弹出 0：左边界 = 栈空 → -1，右边界 = 1，宽 = 1-(-1)-1 = 1，面积 = 2×1 = 2。栈空，入栈 1 |
| 3 | i=2, h=5 | [1,2] | 5 > 1，入栈 |
| 4 | i=3, h=6 | [1,2,3] | 6 > 5，入栈 |
| 5 | i=4, h=2 | [1,2] → [1,4] | 弹出 3（h=6）：左边界 = 2，右边界 = 4，宽 = 4-2-1 = 1，面积 = 6。弹出 2（h=5）：左边界 = 1，右边界 = 4，宽 = 4-1-1 = 2，面积 = 5×2 = **10**。栈顶 1 高度 1 < 2，停止，入栈 4 |
| 6 | i=5, h=3 | [1,4,5] | 3 > 2，入栈 |
| 7 | i=6, h=0 | [] | 弹出 5（h=3）：左边界 = 4，右边界 = 6，宽 = 1，面积 = 3。弹出 4（h=2）：左边界 = 1，右边界 = 6，宽 = 4，面积 = 8。弹出 1（h=1）：左边界 = -1，右边界 = 6，宽 = 6，面积 = 6。栈空 |

最大值 10，与答案一致。注意第 5 步弹出的 `h=5` 那根柱子，宽度算出来是 2（覆盖下标 2 和 3），这正是示例中红色矩形的位置。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在扫描过程中，栈内下标对应的 `heights` 严格单调递增；且对于栈内任意下标 `k`，`k` 的「左边第一个更矮的柱子」就是它在栈中的前一个元素（栈底元素的前一个是虚拟下标 `-1`）。

**为什么不会漏**：设全局最优矩形的高度为 `H`，它一定等于某根柱子 `p` 的高度（否则矩形上边界可以继续上移直到碰到某根柱子，面积不减小）。当扫描到「`p` 右边第一个更矮的柱子」时，`p` 会被弹出，此时栈中 `p` 的前一个元素正是 `p` 左边第一个更矮的柱子（由不变量保证），结算出的宽度恰好是 `p` 能延伸的最大宽度。所以最优矩形一定在某个弹出时刻被结算到。

**为什么不会重**：每根柱子只在被弹出时结算一次（末尾哨兵保证所有柱子最终都被弹出），每次结算对应「以该柱子为最低点」的矩形，不同柱子对应的矩形最低点不同，互不重复。而「以 `p` 为最低点」的矩形中，宽度取到最大时面积最大，所以每根柱子只取一个候选值即可。

**为什么用「严格小于」而不是「小于等于」**：如果允许等于，那么高度相同的柱子会互相卡住，导致某些柱子永远等不到「右边更矮」而无法结算，或者宽度算错。用严格小于 + 弹栈条件 `>=`，保证高度相同的柱子中，靠右的那个先被弹出、靠左的继续留在栈里，宽度计算仍然正确（等于高度的柱子会被合并到同一个矩形里，不会漏）。

## 5. 完整代码（Python）

```python
class Solution:
    def largestRectangleArea(self, heights: list[int]) -> int:
        # 末尾补 0 作为哨兵：保证所有柱子最终都会被弹出结算
        # 用 list 模拟栈，存的是下标
        stack = []
        max_area = 0
        n = len(heights)

        for i in range(n + 1):
            # i == n 时高度视为 0，强制清空栈
            cur_h = heights[i] if i < n else 0

            # 当前柱子比栈顶矮（或相等），说明栈顶柱子的右边界确定了
            while stack and heights[stack[-1]] >= cur_h:
                h = heights[stack.pop()]          # 被结算柱子的高度
                # 弹出后栈顶就是它左边第一个更矮的柱子；栈空则左边界为 -1
                left = stack[-1] if stack else -1
                width = i - left - 1              # 右边界是 i，左边界是 left
                max_area = max(max_area, h * width)

            stack.append(i)                       # 当前柱子入栈，等待它的右边界

        return max_area
```

关键点：`while` 里用 `>=` 而不是 `>`，配合末尾哨兵，保证高度相同的柱子也能被正确结算；`left` 取弹出后的栈顶，是因为栈的单调性保证了「弹出后栈顶 = 左边第一个更矮」。

## 6. 复杂度

- **时间 `O(n)`**：外层循环 `n+1` 次；内层 `while` 每次弹出一个下标，而每个下标最多入栈一次、出栈一次，所以 `while` 总共执行不超过 `n+1` 次。总操作数 `O(n)`。这里没有 `log n` 的来源——单调栈是均摊线性，不是二分。
- **空间 `O(n)`**：栈最多同时存 `n+1` 个下标（最坏情况是高度严格递增的数组，全部入栈后才在哨兵处依次弹出）。没有额外数组。

## 7. 边界与反例（至少 4 条）

1. **输入 `[2,4]` → 期望 `4`**。容易错在：只算了「以 4 为最低点」的矩形（面积 4），忘了「以 2 为最低点、宽 2」的矩形面积也是 4，两者相等；如果代码里宽度算成 `i - left` 而不是 `i - left - 1`，会得到 6 或 2 的错误值。
2. **输入 `[1]` → 期望 `1`**。容易错在：没有哨兵时，最后一根柱子永远不会被弹出，`max_area` 保持 0。哨兵是必须的。
3. **输入 `[0,0,0]` → 期望 `0`**。容易错在：`>=` 弹栈时高度为 0，面积 0，没问题；但如果把哨兵写成 `-1` 或者用 `>` 弹栈，可能死循环或漏结算。高度为 0 的柱子也是合法柱子，宽度计算不能跳过。
4. **输入 `[5,5,5]` → 期望 `15`**。容易错在：用 `>` 弹栈时，前两个 5 永远不会被弹出（因为右边没有严格更矮的），只有最后一个 5 在哨兵处弹出，宽度算成 1，得到 5 而不是 15。必须用 `>=`。
5. **输入 `[2,1,2]` → 期望 `3`**。容易错在：中间的 1 把左右隔开，最优是「以 1 为最低点、宽 3」面积 3，而不是左右两个 2 各自宽 1 面积 2。如果只考虑「连续相同高度」会漏掉跨过矮柱子的宽矩形。

## 8. 面试追问与变体（3 条）

1. **追问：如果柱子宽度不都是 1，而是给定数组 `widths`，怎么改？** 思路：宽度不再是 `i - left - 1`，而是「区间 `(left, i)` 内 `widths` 的前缀和之差」，预处理前缀和数组即可，栈逻辑不变。
2. **追问：如果要求返回最大矩形的具体位置（左右下标）而不是面积？** 思路：结算时记录 `(left+1, i-1, h)`，最后取面积最大的那组；注意相同面积取任意一组即可。
3. **追问：如果柱子是环形排列（首尾相接），怎么求最大矩形？** 思路：把数组复制一份接在后面，长度变 `2n`，但限制矩形宽度不超过 `n`，用单调栈 + 滑动窗口约束，或者枚举「断点」做两次线性扫描。
