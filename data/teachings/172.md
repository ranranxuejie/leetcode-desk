## 1. 一句话本质

求 n! 的质因数分解里，因子 10 的个数——也就是 min(因子 2 的个数, 因子 5 的个数)，而它恰好等于因子 5 的个数。

## 2. 读完题的第一反应

**朴素解法**：直接把 n! 算出来，然后不断 `% 10 == 0` 地除下去数零。卡在哪？n 最大 10^4，10^4! 是个约 35660 位的数。Python 的大整数能算，但这是拿 O(n log n) 位运算换一个数学上根本不需要的中间结果；换到 C++/Java 直接溢出。即使语言支持大整数，这个思路也完全没利用题目的结构。

**关键观察**：尾随零来自 10，而 10 = 2 × 5。所以问题变成「n! 里能拆出多少对 (2, 5)」。再看一步：1 到 n 里偶数远多于 5 的倍数，所以因子 2 一定管够，瓶颈永远是 5。于是问题坍缩成：**1 到 n 中有多少个因子 5**。

这个观察为什么能带你走下一步？因为它把「算一个巨大的乘积」换成了「数一数 1..n 里 5 的倍数」，而后者不需要构造 n!，只需要对 n 做除法。这就是从 O(n! 的位数) 降到 O(log n) 的入口。

## 3. 从暴力到最优

**第一步：暴力**。算 n!，循环除 10 数零。瓶颈是 n! 本身的规模，n=10^4 时是几万位的大数，时间和空间都被这个中间量吃掉。

**第二步：只数因子 5**。不再算 n!，而是遍历 1..n，每个数反复除以 5 累计次数。复杂度 O(n log n)，n=10^4 完全能过，但进阶要求对数时间。

**第三步：按「5 的幂次」分层数**。这是核心跳跃。直接数「每个数贡献几个 5」要遍历每个数；换个角度，**按贡献的层数来数**：

- 是 5 的倍数的数，每个至少贡献 1 个 5 → 有 ⌊n/5⌋ 个
- 是 25 的倍数的数，每个**额外**再贡献 1 个 5 → 有 ⌊n/25⌋ 个
- 是 125 的倍数的数，再额外贡献 1 个 → ⌊n/125⌋ 个
- ……直到 5^k > n

把每层的个数加起来，就是因子 5 的总数。

**小例子走一遍，n = 25**：

| 层 | 计算 | 本层个数 | 累计 |
|---|---|---|---|
| 5 的倍数 | ⌊25/5⌋ | 5 | 5 |
| 25 的倍数 | ⌊25/25⌋ | 1 | 6 |
| 125 的倍数 | ⌊25/125⌋ | 0 | 停止 |

答案 6。验证一下：25! 里 5 的倍数有 5,10,15,20,25；其中 25 贡献两个 5（25 = 5×5），其余各一个，共 5 + 1 = 6。和分层计数一致。

再看 n = 100：⌊100/5⌋=20，⌊100/25⌋=4，⌊100/125⌋=0，答案 24。注意 25、50、75、100 这四个数在「5 的倍数」层已经被数过一次，在「25 的倍数」层再数一次，正好补上它们多出来的那个 5——**不是重复计数，是分层补差**。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。设 v_p(x) 表示 x 的质因数分解中 p 的指数。

**不变量**：对任意 k ≥ 1，⌊n/5^k⌋ 恰好等于 1..n 中「v_5 至少为 k」的数的个数。

证明：一个数 m 满足 v_5(m) ≥ k ⟺ m 是 5^k 的倍数 ⟺ m ∈ {5^k, 2·5^k, …}，在 1..n 中这样的数有 ⌊n/5^k⌋ 个。这是整除计数的标准结论，不依赖 n! 的结构。

**求和即得总数**：对每个 m ∈ 1..n，它在上述计数中被计入的次数 = 满足 5^k | m 的 k 的个数 = v_5(m)。所以

$$\sum_{k\ge1} \left\lfloor \frac{n}{5^k} \right\rfloor = \sum_{m=1}^{n} v_5(m) = v_5(n!)$$

**不漏**：每个因子 5 都对应某个 k 层，被计入一次。**不重**：同一个数的第 k 个 5 只出现在第 k 层，层与层之间是「补差」关系而非「重复」关系——第 k 层数的是「第 k 个 5」，不是「前 k 个 5」。

**为什么答案就是 v_5(n!) 而不是 min(v_2, v_5)**：需要说明 v_2(n!) ≥ v_5(n!)。对每个 k，⌊n/2^k⌋ ≥ ⌊n/5^k⌋，逐层比较后求和即得。所以 2 永远不缺，min 退化为 v_5。这一步不能省，否则「答案 = 因子 5 个数」是没根据的。

## 5. 完整代码（Python）

```python
class Solution:
    def trailingZeroes(self, n: int) -> int:
        count = 0
        # 逐层累加 floor(n / 5^k)，k = 1, 2, 3, ...
        # 每轮把 n 除以 5，等价于把分母从 5^k 推进到 5^(k+1)
        while n > 0:
            n //= 5          # 整数除法，得到 floor(原n / 5^k)
            count += n       # 本层贡献的 5 的个数
        return count
```

关键逻辑说明：

- `n //= 5` 复用同一个变量，第 i 轮循环后 `n` 的值就是 ⌊原始 n / 5^i⌋。这样避免了维护 `power = 5, 25, 125...` 的额外变量，也不会溢出。
- 循环条件 `n > 0`：当 ⌊n/5^k⌋ 变成 0 时，后面所有层都是 0，直接停。这同时天然处理了 n = 0（不进循环，返回 0）。
- `count += n` 在除法之后执行，顺序不能反——先推进分母，再加本层个数。

## 6. 复杂度

**时间 O(log₅ n)**：循环每轮把 n 除以 5，从 n 降到 0 需要 ⌊log₅ n⌋ + 1 轮。n = 10^4 时约 6 轮。这里的 log 来自「5 的幂次有多少层」，不是来自遍历。

**空间 O(1)**：只用了 `count` 和复用的 `n` 两个整型变量，没有数组、没有递归栈。

对比：暴力算 n! 是 O(n! 的位数) ≈ O(n log n) 位运算；逐个数因子是 O(n log n)。本题的 log 是「层数」，和 n 的规模无关，这是进阶要求「对数时间」的落点。

## 7. 边界与反例（至少 4 条）

1. **n = 0** → 期望 0。容易错在：直觉上 0! = 1，有人会想「1 有没有尾零」而犹豫；或者循环写成 `while n > 1` 之外的形式导致死循环/多算。代码里 `while n > 0` 直接不进循环，返回 0，正确。

2. **n = 4** → 期望 0。容易错在：⌊4/5⌋ = 0，但有人会误以为「只要 n ≥ 1 就有零」，或者把循环条件写成 `n >= 5` 之外的形式漏判。4! = 24，确实没有。

3. **n = 5** → 期望 1。容易错在：只数「5 的倍数」时容易把 5 本身漏掉（以为要严格大于 5），或者把 ⌊5/5⌋ 算成 0（整除写错）。5! = 120，一个零。

4. **n = 25** → 期望 6。这是最经典的坑：只算 ⌊25/5⌋ = 5 就返回，漏掉 25 贡献的第二个 5。必须继续 ⌊25/25⌋ = 1。同理 n = 125 期望 31（25 + 5 + 1），只算第一层会得 25。

5. **n = 10^4** → 期望 2499。容易错在：用 `math.factorial(10000)` 再数零，虽然 Python 能跑但极慢且暴露思路错误；或者用浮点除法 `n / 5` 导致精度问题和死循环。必须用 `//`。

## 8. 面试追问与变体（3 条）

1. **追问：如果问的是 n! 在 k 进制下的尾随零呢？** 思路：把 10 换成 k，对 k 做质因数分解 k = ∏ p_i^{e_i}，答案 = min_i ⌊v_{p_i}(n!) / e_i⌋。本题是 k = 10 = 2×5、e 全为 1 的特例。

2. **追问：不用循环，能不能 O(1) 公式？** 思路：理论上 v_5(n!) = (n - s_5(n)) / 4，其中 s_5(n) 是 n 的五进制各位数字之和（Legendre 公式）。但求 s_5 仍需 O(log n) 拆位，没有实质加速，面试里说出来是加分项而非必需。

3. **追问：如果 n 大到 10^18，你的代码还成立吗？** 思路：成立，循环轮数变成约 26 轮，仍是 O(log n)；但要注意语言层面的整型溢出（Python 无此问题，C++ 需用 long long），以及不能再用「算 n! 再数零」的暴力。
