## 1. 一句话本质

判断字符串 `s` 能否被**完整地**切分成若干段，使得每一段都恰好是字典里的某个词（词可重复用、可不全用）。

关键词是「完整地」：切分必须覆盖 `s` 的每一个字符，不能有剩余、不能有跳过。

## 2. 读完题的第一反应

**朴素解法**：从左往右尝试切。站在位置 `i`，枚举所有可能的「下一段」`s[i:j]`，如果它在字典里，就递归去处理 `j` 之后的部分。这本质是暴力搜索所有切分方案。

它卡在哪？**指数级**。考虑 `s = "aaaa...a"`（300 个 a），字典 `["a", "aa"]`。每个位置都有 2 种切法，方案数是 `2^299` 量级。但注意——这些方案里绝大多数是**重复的子问题**：从位置 `i` 出发能不能切完，答案只跟 `i` 有关，跟「前面是怎么切到 `i` 的」完全无关。暴力搜索把同一个 `i` 反复算了几亿次。

**关键观察**：把「从 `i` 出发能否切完」定义成一个状态 `f(i)`，那么

```
f(i) = 存在某个 j > i，使得 s[i:j] 在字典里 且 f(j) 为真
```

`f(i)` 只依赖比它大的下标，是一个**无后效性**的递推。这就是动态规划的信号：状态可定义、转移只依赖已求出的状态、子问题重叠。于是从右往左（或记忆化搜索）填表，把指数级压成多项式级。

## 3. 从暴力到最优

**第一步：暴力 DFS。** 以示例 3 为例，`s = "catsandog"`，字典 `{cats, dog, sand, and, cat}`。

从 0 出发，`s[0:3]="cat"` 在字典 → 跳到 3；`s[0:4]="cats"` 在字典 → 跳到 4。

走 `cat` 分支：位置 3，`s[3:6]="san"` 不在，`s[3:7]="sand"` 在 → 跳到 7；位置 7，`s[7:10]="dog"` 在 → 跳到 10 = 末尾，返回 true。

等等，示例 3 的答案是 false。问题出在：`cat` 之后接 `sand` 得到 `"catsand"`，剩 `"og"`，而 `s[7:10]` 是 `"dog"` 吗？`s = c a t s a n d o g`，下标 7 是 `o`，`s[7:10]="og"`，长度都不够 3。所以 `cat→sand` 这条路在位置 7 失败。走 `cats` 分支：位置 4，`s[4:7]="and"` 在 → 跳到 7，同样卡在 `"og"`。两条路都失败，返回 false。

暴力在这里还算快，但换成 `"aaaaaaaaab"` 这种就会爆炸。

**第二步：加记忆化。** 用一个数组 `memo`，`memo[i]` 记录「从 `i` 出发能否切完」，初始为未知（用 -1 或 None 表示）。第一次算 `f(i)` 时存下来，之后再遇到 `i` 直接查表。上面 `"aaaa...a"` 的例子，`f(i)` 只算一次，总计算量从 `2^299` 降到 `300 × 300`。

**第三步：改成自底向上的 DP。** 记忆化是「从大往小问、算到小」，自底向上是「从小往大填」。定义 `dp[i]` = `s` 的前 `i` 个字符 `s[0:i]` 能否被完整切分。`dp[0] = True`（空串视为可切分，这是递推的种子）。

转移：对每个 `i`，枚举切点 `j < i`，若 `dp[j]` 为真且 `s[j:i]` 在字典里，则 `dp[i] = True`。

用示例 1 走一遍，`s = "leetcode"`，字典 `{leet, code}`：

| i | 枚举 j | s[j:i] | dp[j] | 结果 |
|---|---|---|---|---|
| 0 | — | — | — | dp[0]=True（种子） |
| 1 | 0 | "l" | True | 不在字典，False |
| 2 | 0,1 | "le","e" | — | 都不在，False |
| 3 | 0..2 | "lee","ee","e" | — | 都不在，False |
| 4 | 0 | "leet" | True | **在字典 → dp[4]=True** |
| 5 | 0..4 | ... | dp[4]=True 但 "e" 不在 | False |
| 6 | ... | ... | ... | False |
| 7 | ... | ... | ... | False |
| 8 | 4 | "code" | dp[4]=True | **在字典 → dp[8]=True** |

返回 `dp[8] = True`。注意 `dp[4]` 这个「中间变量」正是关键：它把「leet 已经切好」这个信息存了下来，位置 8 直接复用，不用重新验证前 4 个字符。

**瓶颈消解总结**：暴力 DFS 的瓶颈是「同一位置反复算」，记忆化/DP 用一张 `O(n)` 的表消掉它；剩下的开销是「枚举切点 × 查字典」，查字典用 `set` 做到 `O(1)`（平均），于是总复杂度 `O(n²)`。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。

**不变量**：在填 `dp[i]` 之前，对所有 `j < i`，`dp[j]` 的值都已经是「`s[0:j]` 能否被完整切分」的正确布尔值。

**归纳证明**：

- 基础：`dp[0] = True`，空串不需要任何词就能「切分」，正确。
- 归纳步：假设不变量对 `i` 成立。任何 `s[0:i]` 的合法切分，其**最后一段**必然是某个 `s[j:i]`（`0 ≤ j < i`），且这段在字典里，且前 `s[0:j]` 能被完整切分（即 `dp[j]` 为真）。反过来，若存在这样的 `j`，把「`s[0:j]` 的切分」加上「`s[j:i]` 这一段」就拼成一个合法切分。所以 `dp[i]` 为真 **当且仅当** 存在这样的 `j`。我们的转移恰好枚举了所有 `j`，因此不漏。
- 不重：每个 `i` 只被赋值一次，枚举 `j` 只是「或」运算，重复命中不会改变结果，也不影响正确性。

**为什么不会漏**：因为「最后一段的起点 `j`」被完整枚举了，任何合法切分都对应某个 `j`，没有遗漏。

**为什么不会重**：`dp[i]` 是布尔值，多次命中同一 `i` 只是幂等赋值；且每个 `i` 的计算只读 `j < i` 的已定值，不存在循环依赖。

## 5. 完整代码（Python）

```python
class Solution:
    def wordBreak(self, s: str, wordDict: list[str]) -> bool:
        # 字典转 set，把「查一个词在不在」从 O(len) 降到平均 O(1)
        word_set = set(wordDict)
        n = len(s)

        # dp[i] 表示 s 的前 i 个字符 s[0:i] 能否被完整切分
        # 多开一位，dp[0] 是空串的种子
        dp = [False] * (n + 1)
        dp[0] = True

        # 外层：从小到大确定每个前缀的答案
        for i in range(1, n + 1):
            # 内层：枚举最后一段的起点 j
            for j in range(i):
                # 剪枝：只有前半段能切分，才值得检查后半段
                if not dp[j]:
                    continue
                # s[j:i] 是最后一段，必须在字典里
                if s[j:i] in word_set:
                    dp[i] = True
                    break  # 找到一个合法切法就够了，无需继续枚举 j

        return dp[n]
```

关键逻辑说明：

- `dp[0] = True` 是递推的种子，没有它，任何 `i` 都找不到 `j=0` 的合法起点。
- 内层 `if not dp[j]: continue` 是剪枝：`dp[j]` 为假时，`s[j:i]` 再合法也没用，因为前半段切不开。
- `break` 是「找到一个就收工」，因为 `dp[i]` 只关心「存在性」，不关心「有几种」。
- 返回 `dp[n]` 而不是 `dp[n-1]`：`dp` 的下标是「前 i 个字符」，`n` 个字符对应 `dp[n]`。

## 6. 复杂度

**时间 `O(n² · L)`，其中 `n = len(s)`，`L` 是字典中最长词长（≤ 20）。**

拆开看：
- 外层 `i` 走 `n` 次，内层 `j` 走 `i` 次，共 `O(n²)` 对 `(i, j)`。
- 每对里做一次 `s[j:i] in word_set`。切片本身要复制 `i-j` 个字符，是 `O(i-j)`；哈希查找平均 `O(1)`，但哈希计算要扫一遍字符串，也是 `O(i-j)`。所以单次检查是 `O(i-j)`。
- 严格写是 `O(n³)` 最坏；但实际中 `s[j:i]` 长度超过字典最长词 `L` 时必然不在字典里，可以提前 `break`（本题代码没加这个优化，但 `L ≤ 20` 是常数，所以常被写成 `O(n²)`）。**面试时建议说 `O(n² · L)`，并说明 `L` 是常数**。

**空间 `O(n)`。** `dp` 数组 `n+1` 个布尔值；`word_set` 存 `m` 个词，总字符数受输入限制，是 `O(总字典字符数)`，与 `n` 无关，通常不计入主项。

## 7. 边界与反例（至少 4 条）

1. **`s = "a"`, `wordDict = ["a"]`** → `True`。容易错在 `dp` 只开 `n` 位、忘记 `dp[0]` 种子，导致 `dp[1]` 找不到 `j=0` 的合法起点。

2. **`s = "a"`, `wordDict = ["b"]`** → `False`。容易错在把「字典非空」误当成「能拼出」，忘了逐段验证。

3. **`s = "catsandog"`, `wordDict = ["cats","dog","sand","and","cat"]`** → `False`（示例 3）。容易错在贪心：看到 `"cat"` 就切，切到 `"catsand"` 后剩 `"og"` 失败就放弃，没回头试 `"cats"`。DP 天然枚举所有 `j`，不会犯这个错。

4. **`s = "aaaaaaa"`, `wordDict = ["aaaa","aaa"]`** → `True`。容易错在只从 `j=0` 开始找、或找到第一个 `j` 就以为覆盖了所有情况；实际上 `"aaa"+"aaaa"` 和 `"aaaa"+"aaa"` 都要能试到，DP 的 `j` 全枚举保证了这点。

5. **`s = "applepenapple"`, `wordDict = ["apple","pen"]`** → `True`（示例 2）。容易错在以为「词只能用一次」，看到 `"apple"` 出现两次就判 false；题面明确说可重复使用，`dp` 每次查 `set` 不消耗词，天然支持重复。

6. **`s` 长度 300、字典含 1000 个词** → 必须 `O(n²)` 级别，暴力 DFS 会超时。容易错在没加记忆化直接提交。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回所有切分方案（不只 true/false）？**
   思路：把 `dp` 从布尔改成「以 `i` 结尾的所有切分列表」，或 DFS + 记忆化回溯，转移时把 `s[j:i]` 拼到 `dp[j]` 的每个方案后面。复杂度变成输出规模级别（方案数可能指数级）。

2. **追问：字典很大（比如 10⁵ 个词），怎么优化查词？**
   思路：用**字典树（Trie）** 存字典，从 `i` 出发沿 `s` 往下走 Trie，走到某个节点是词尾就得到一个合法 `j`，避免对每个 `(i,j)` 做切片哈希。这正是本题标签里「字典树」的来源。

3. **追问：如果允许「删除 `s` 中至多 `k` 个字符」后能切分，返回最少删除数？**
   思路：状态扩成 `dp[i][d]` = 前 `i` 个字符、已删 `d` 个时能否切分，转移时多一个「删掉当前字符」的分支，答案取最小的 `d` 使 `dp[n][d]` 为真。

## 9. 举一反三（2-3 道同类题）

1. **140. 单词拆分 II（困难）**：同一套 `dp` 骨架，但要把「存在性」升级成「枚举所有方案」，是本题的直接变体。

2. **322. 零钱兑换（中等）**：`dp[i]` = 凑出金额 `i` 的最少硬币数，转移枚举「最后一枚硬币」，和本题「枚举最后一段」结构同构，都是「完全背包 + 存在性/最优化」。

3. **300. 最长递增子序列（中等）**：`dp[i]` = 以 `i` 结尾的最长长度，转移枚举前驱 `j`，同样是「枚举前一个切点」的 `O(n²)` 骨架，可对照理解「状态定义决定转移方向」。
