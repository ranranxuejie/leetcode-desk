## 1. 一句话本质

在 n×n 棋盘上逐行放 n 个皇后，每行恰好一个、每列恰好一个、每条对角线至多一个，数一数满足这些约束的摆放方案有多少种。

## 2. 读完题的第一反应

**朴素解法**：把 n 个皇后放在 n×n 棋盘的任意 n 个格子上，枚举所有组合，再逐一检查是否互相攻击。组合数是 C(n², n)，n=8 时约 4.4×10⁹，n=9 时约 1.9×10¹²。这个量级完全不可行——瓶颈在于「枚举了大量注定冲突的方案」，比如两个皇后放在同一行，后面的检查纯属浪费。

**关键观察**：题目要求 n 个皇后互不攻击，而棋盘只有 n 行。如果某一行放了两个皇后，它们立刻互相攻击；如果某一行空着，那 n 个皇后只能挤在 n−1 行里，由鸽巢原理必然有两行各放两个——同样冲突。所以**每行恰好一个皇后**是硬约束，不是需要搜索的选项。

这一下把搜索空间从「n² 选 n」压成了「每行选一列」，即 nⁿ 量级。虽然还是大，但它给了我们一个天然的**逐行决策**结构：第 0 行选一列，第 1 行选一列……每选一个就检查是否和前面已放的冲突，冲突就剪枝。这就是回溯的骨架。

## 3. 从暴力到最优

**第一步：从「任意格子」到「每行一个」**。如上所述，搜索空间从 C(n²,n) 降到 nⁿ。n=4 时从 1820 降到 256。

**第二步：逐行放 + 即时剪枝**。放第 r 行的皇后时，只需检查它和前面 r−1 个皇后是否冲突（同列、同主对角线、同副对角线）。一旦冲突，这一支直接砍掉，不再往下走。

用 n=4 走一遍。列号 0–3，主对角线用 `r - c` 标记，副对角线用 `r + c` 标记。

- 第 0 行放列 0：`cols={0}, diag1={0}, diag2={0}`
- 第 1 行试列 0：列冲突，剪。试列 1：`r-c=0` 撞 diag1，剪。试列 2：`r-c=-1` 新，`r+c=3` 新，放。状态 `cols={0,2}, diag1={0,-1}, diag2={0,3}`
- 第 2 行试列 0：列冲突。列 1：`r-c=1` 新，`r+c=3` 撞 diag2，剪。列 2：列冲突。列 3：`r-c=-1` 撞 diag1，剪。第 2 行无路可走，**回溯**到第 1 行。
- 第 1 行试列 3：`r-c=-2` 新，`r+c=4` 新，放。状态 `cols={0,3}, diag1={0,-2}, diag2={0,4}`
- 第 2 行试列 1：`r-c=1` 新，`r+c=3` 新，放。状态加 `cols={0,3,1}, diag1={0,-2,1}, diag2={0,4,3}`
- 第 3 行试列 0：列冲突。列 1：列冲突。列 2：`r-c=1` 撞 diag1，剪。列 3：列冲突。回溯……
- 继续回溯到第 0 行换列 1，最终找到 `[1,3,0,2]` 和 `[2,0,3,1]` 两个解。

注意剪枝发生在**放下去的瞬间**，而不是等四行放完再检查——这正是回溯比暴力快的原因：冲突越早发现，砍掉的子树越大。

**第三步：用集合 O(1) 判冲突**。如果每次都用循环扫前面已放的皇后，判冲突是 O(r)，总复杂度多一个 n 的因子。用三个集合（列、主对角线、副对角线）记录已占用的编号，判冲突变成三次哈希查找，O(1)。这是本题从「能过」到「干净」的关键一步。

## 4. 正确性：为什么不会漏、不会重

**不变量**：进入第 r 层递归时，`cols`、`diag1`、`diag2` 三个集合恰好记录了前 r 行已放皇后的列号、`r-c` 值、`r+c` 值，且前 r 行内部互不攻击。

**不会漏**：任何合法解都满足「每行一个皇后」（第 2 节已证）。设合法解在第 r 行放在第 c 列，那么在第 r 层递归时，c 一定不在三个集合里（否则与前面某个皇后冲突，与合法性矛盾），所以 c 会被枚举到，这一支不会被剪掉。归纳下去，该解会被完整走到。

**不会重**：每个解对应一个长度为 n 的列序列 `(c₀, c₁, …, c_{n-1})`。递归树中每条从根到叶的路径唯一确定一个序列，不同路径在第 r 层选了不同的 c，序列就不同。所以每个解恰好被计数一次。

**计数时机**：只有当 `row == n`（n 行全部放完且每步都没冲突）时才 `count += 1`，此时前 n 行两两不冲突，就是一个合法解。

## 5. 完整代码（Python）

```python
class Solution:
    def totalNQueens(self, n: int) -> int:
        self.count = 0
        # 三个集合分别记录已占用的列、主对角线(r-c)、副对角线(r+c)
        cols = set()
        diag1 = set()   # r - c
        diag2 = set()   # r + c

        def backtrack(row: int) -> None:
            # 终止条件：n 行都放好了，说明找到一个合法解
            if row == n:
                self.count += 1
                return

            for col in range(n):
                d1 = row - col
                d2 = row + col
                # 冲突检查：同列 / 同主对角线 / 同副对角线
                if col in cols or d1 in diag1 or d2 in diag2:
                    continue

                # 做选择
                cols.add(col)
                diag1.add(d1)
                diag2.add(d2)

                backtrack(row + 1)   # 进入下一行

                # 撤销选择（回溯），保证兄弟分支看到的是干净状态
                cols.remove(col)
                diag1.remove(d1)
                diag2.remove(d2)

        backtrack(0)
        return self.count
```

关键点：`remove` 而不是 `discard`，因为能走到这里说明一定加过；三个集合的增删必须成对出现，否则回溯后状态被污染，后续分支会误判冲突。

## 6. 复杂度

**时间**：O(n!)。第 0 行有 n 种选法，第 1 行最多 n−1 种（列不能重复），第 2 行最多 n−2 种……上界是 n×(n−1)×…×1 = n!。实际因为对角线剪枝，搜索树比 n! 小得多（n=9 时实测约几万次递归），但渐进上界按 n! 算。每层判冲突是 O(1)（三次哈希查找），所以总时间就是搜索树的节点数。

**空间**：O(n)。递归深度最多 n 层，每层栈帧 O(1)；三个集合各存最多 n 个元素。没有额外的二维棋盘数组——这是用集合代替 `board` 的好处，空间从 O(n²) 降到 O(n)。

## 7. 边界与反例（至少 4 条）

1. **n = 1** → 期望 1。容易错在：终止条件写成 `row == n-1` 或循环范围写成 `range(1, n)`，导致漏掉唯一的解。第 0 行放列 0，`row` 变 1 等于 n，计数 1。
2. **n = 2** → 期望 0。容易错在：以为「有解」是默认情况，没考虑无解时 `count` 保持 0 直接返回。n=2 和 n=3 都无解，这是检验剪枝是否正确的天然用例。
3. **n = 3** → 期望 0。同上，且容易错在：回溯时忘记 `remove`，导致状态残留，把本该剪掉的分支误判为可走，返回非 0。
4. **n = 4** → 期望 2。容易错在：对角线编号用 `row + col` 和 `row - col` 时搞混主副，或者用 `abs` 比较导致 O(n) 判冲突，虽然结果对但慢；更隐蔽的是把 `r-c` 写成 `c-r`，对称性上没问题但和集合记录不一致就会误判。
5. **n = 9** → 期望 352。容易错在：用列表 `in` 判冲突（O(n)），n=9 时虽然也能过但慢一个量级；或者递归没设深度保护，Python 默认递归限制 1000 够用，但若改成迭代写法容易写错栈。

## 8. 面试追问与变体（3 条）

1. **追问：把「返回数量」改成「返回所有具体棋盘」怎么办？** 思路：把 `count += 1` 换成把当前 `cols` 序列（或一个 `board` 列表）深拷贝进结果集；需要在递归中维护每行选的列号，终止时按列号生成 `"....Q..."` 字符串。
2. **追问：n 很大时（比如 n=15）怎么优化？** 思路：用位运算代替集合——三个整数 `cols`、`diag1`、`diag2` 的二进制位表示占用情况，每层用 `available = ((1<<n)-1) & ~(cols|diag1|diag2)` 取出可放位置，`lowbit` 逐个枚举，判冲突和状态更新都是位运算，常数更小。
3. **追问：如果棋盘不是正方形，或者皇后攻击规则改成「马步」呢？** 思路：回溯骨架不变，只改「冲突判定」函数——把三个集合换成对应的攻击关系集合（马步是 8 个偏移），其余逐行枚举 + 剪枝 + 撤销的逻辑完全复用。
