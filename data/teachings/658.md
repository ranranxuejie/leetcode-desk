## 1. 一句话本质

在有序数组里找一个长度为 k 的连续窗口，使得这个窗口里的元素整体上离 x 最近（按题目定义的"更接近"比较规则）。

注意"连续窗口"这个说法是本题的核心——它不是随便挑 k 个最近的数，而是答案一定对应原数组中一段连续的子数组。这一点第 4 节会严格证明。

## 2. 读完题的第一反应

**朴素解法**：对每个元素算 `|arr[i] - x|`，按"距离升序、值升序"排序，取前 k 个，再排一次序输出。复杂度 O(n log n)，瓶颈在排序。

**卡在哪**：数组本来就是有序的，我们却把它打乱重排，白白浪费了"有序"这个信息。而且排序后取出的 k 个元素在原数组里未必连续，还得再排一次。

**关键观察**：既然 arr 有序，那么"离 x 最近的 k 个数"在数轴上必然聚集在 x 附近，反映到数组里就是**一段连续区间**。于是问题从"挑 k 个"变成"选一个起点 left，窗口是 `arr[left : left+k]`"，候选起点只有 `n - k + 1` 个。

这个转化把"组合选择"降成了"单变量决策"，是整道题的转折点。有了它，接下来只需回答：怎么快速判断哪个起点最好？

## 3. 从暴力到最优

**第一步：枚举起点（O(nk) 或 O(n log n)）**

对每个起点 `left ∈ [0, n-k]`，取出窗口，算窗口内所有元素到 x 的距离总和，取最小。每个窗口 O(k)，总 O(nk)。或者像第 2 节说的排序法 O(n log n)。

**第二步：发现相邻窗口只差两个元素**

设当前窗口是 `arr[left : left+k]`，右移一格变成 `arr[left+1 : left+k+1]`。两者只差：丢掉 `arr[left]`，加入 `arr[left+k]`。所以比较两个窗口谁更优，只需比较这两个"边缘元素"谁离 x 更近：

- 若 `x - arr[left] > arr[left+k] - x`，说明丢掉的左端比新进来的右端更远，右移更优；
- 否则左端不差于右端，不该右移。

这里 `x - arr[left]` 和 `arr[left+k] - x` 都是非负的（因为最优窗口一定跨在 x 两侧或贴着 x，见第 4 节），可以直接比大小，不用加绝对值。

**小例子走一遍**：`arr = [1,2,3,4,5], k = 4, x = 3`。

候选起点只有 `left ∈ {0, 1}`。

- `left = 0`：窗口 `[1,2,3,4]`，比较 `arr[0]=1` 与 `arr[4]=5`。`x - 1 = 2`，`5 - x = 2`，相等 → 按规则不右移（相等时保留左端，因为左端值更小，符合题目"距离相同取较小值"）。
- 结果 `[1,2,3,4]`，与示例一致。

再看 `arr = [1,1,2,3,4,5], k = 4, x = -1`，候选 `left ∈ {0,1,2}`：

- `left = 0`：窗口 `[1,1,2,3]`，比较 `arr[0]=1` 与 `arr[4]=4`。`x - 1 = -2`？这里 x=-1 比 arr[0] 还小，`x - arr[left]` 为负，说明整个窗口都在 x 右侧，右移只会更远，直接停。
- 结果 `[1,1,2,3]`，与示例一致。

**第三步：把线性扫描换成二分（O(log n)）**

上面从 `left=0` 一路右移，最坏 O(n) 次比较。但注意比较函数 `f(left) = (x - arr[left]) - (arr[left+k] - x)` 随 left 增大是**单调不增**的：left 越大，左端越靠近 x（`x - arr[left]` 变小），右端越远离 x（`arr[left+k] - x` 变大）。所以"该不该右移"这个判断在 left 轴上是单调的——存在一个分界点，左边全该右移，右边全不该。

单调性 ⇒ 二分。在 `[0, n-k]` 上二分找最后一个满足"右移更优"的 left，答案窗口从它右边开始。

## 4. 正确性：为什么不会漏、不会重

**不变量 1：答案窗口连续。** 用交换论证。假设最优解 S 含元素 `arr[i]` 和 `arr[j]`（i < j）却不含中间的 `arr[m]`（i < m < j）。由于 arr 有序，`arr[m]` 落在 `arr[i]` 与 `arr[j]` 之间。若 x 在 `arr[m]` 左侧，则 `arr[m]` 比 `arr[j]` 更接近 x；若 x 在右侧，则 `arr[m]` 比 `arr[i]` 更接近；若 x 恰在中间，`arr[m]` 至少不比两者都差。无论哪种，把 S 中较远的那个换成 `arr[m]` 都不会变差，且保持大小 k。反复交换，S 可化为连续窗口。所以只需在连续窗口中找。

**不变量 2：最优窗口跨在 x 两侧（或贴边）。** 若窗口整体在 x 左侧（`arr[left+k-1] < x`），右移一格丢掉最左（更远）、加入更右（更近），严格更优，矛盾。整体在右侧同理。所以最优窗口满足 `arr[left] <= x <= arr[left+k]` 或已贴到数组边界。这保证了第 3 节里两个距离差非负，比较合法。

**不变量 3：二分不漏解。** 比较函数单调不增，二分找到的分界点左侧所有 left 都满足"右移更优"，右侧都不满足。分界点右侧第一个 left 就是最优起点：它左边任何起点都能通过右移改进，它自己右移不再改进。单调性保证不会跳过最优解。

三条合起来：候选集被缩到连续窗口（不漏），窗口比较规则正确（不重、不比错），二分定位准确（不漏）。

## 5. 完整代码（Python）

```python
class Solution:
    def findClosestElements(self, arr: list[int], k: int, x: int) -> list[int]:
        n = len(arr)
        # 候选起点范围 [0, n-k]，二分找"最后一个仍应右移"的位置
        lo, hi = 0, n - k
        while lo < hi:
            mid = (lo + hi) // 2
            # 比较丢掉 arr[mid] 与加入 arr[mid+k] 谁更远
            # 若右端更近（严格小于），说明右移更优，起点应 > mid
            if x - arr[mid] > arr[mid + k] - x:
                lo = mid + 1
            else:
                # 左端不差于右端（含相等），保留左端，起点 <= mid
                hi = mid
        # lo 即最优窗口起点
        return arr[lo: lo + k]
```

关键点：`lo < hi` 的二分模板里，`hi = mid` 而非 `mid - 1`，因为 mid 本身可能是答案；`lo = mid + 1` 因为 mid 已确定不是答案。相等时走 `else` 分支保留左端，正好实现"距离相同取较小值"。

## 6. 复杂度

- **时间 O(log(n-k))**：二分区间长度 `n-k+1`，每次比较 O(1)，共 O(log(n-k)) 次。这里 n 来自数组长度，log 来自二分。切片 `arr[lo:lo+k]` 是 O(k)，所以严格说总时间 O(log(n-k) + k)，k 是输出本身的大小，不可避免。
- **空间 O(k)**：返回值切片占 k 个元素。若不计输出，额外空间 O(1)（只有 lo/hi/mid 几个变量）。

对比：排序法 O(n log n)，线性双指针 O(n)，二分法 O(log n + k)，是本题最优。

## 7. 边界与反例（至少 4 条）

1. `arr = [1], k = 1, x = 5` → `[1]`。只有一个元素，`n-k=0`，二分不进循环，直接返回。容易错在二分边界写成 `n-k-1` 导致空区间。
2. `arr = [1,2,3,4,5], k = 4, x = 3` → `[1,2,3,4]`。距离相等（1 和 5 都距 3 为 2），必须取较小值 1 而非 5。容易错在比较时用 `>=` 导致右移，输出 `[2,3,4,5]`。
3. `arr = [1,2,3,4,5], k = 5, x = 0` → `[1,2,3,4,5]`。k 等于 n，`n-k=0`，窗口唯一。容易错在没处理 k=n 时二分区间退化为单点。
4. `arr = [1,10,20,30], k = 2, x = 15` → `[10,20]`。x 落在两元素之间，窗口必须跨两侧。容易错在只往一侧找，返回 `[1,10]` 或 `[20,30]`。
5. `arr = [1,1,1,10,10,10], k = 3, x = 9` → `[10,10,10]`。重复元素多，比较时 `x - arr[mid]` 与 `arr[mid+k] - x` 可能多次相等，靠 `else` 分支稳定收敛。容易错在相等时乱跳导致死循环。

## 8. 面试追问与变体（3 条）

1. **追问：如果 arr 没排序怎么办？** 思路：先排序 O(n log n)，再套本题二分；或者用大小为 k 的最大堆维护"距离最远"的元素，O(n log k)。
2. **追问：要求返回元素下标而不是值？** 思路：二分逻辑不变，返回 `list(range(lo, lo+k))`，注意重复值时题目可能要求特定下标，需确认规则。
3. **追问：k 不固定，每次查询给不同的 (k, x)，多次查询？** 思路：预处理前缀和或对每个查询独立二分；若查询量大，考虑离线按 x 排序 + 双指针，或建线段树维护距离。
