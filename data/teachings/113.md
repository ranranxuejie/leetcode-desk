## 1. 一句话本质

在二叉树里枚举**所有根到叶的完整路径**，只保留路径和恰好等于 `targetSum` 的那些。

关键词是「所有」和「根到叶」——这决定了它不是「找一个就返回」的搜索，而是必须走遍每条候选路径的枚举。

## 2. 读完题的第一反应

**朴素解法**：先写一个函数收集所有根到叶路径（每条路径是一个 list），再逐条求和、筛选。这能过，但你要额外存下所有路径，最坏情况（满二叉树）叶子数约 n/2，每条路径长 log n，空间 O(n log n)，而且「收集完再筛」多了一遍无用功。

**卡点在哪**：不是时间复杂度（任何解法都得看每个节点至少一次，下界就是 O(n)），而是**空间和代码结构**。你不需要保留「和不对的路径」，那为什么要把它们存下来？

**关键观察**：题目要的是「路径和」，而路径和是**可以边走边累加**的。从根往下走一步，就把当前节点的值加进一个「正在走的路径」里；走到叶子时立刻判断和是否等于目标。这样只需要维护**一条**当前路径（一个栈），走不通就退回去——这正是回溯的形状。

第二个观察：既然要「退回去」，就必须在离开节点时把它的值从路径里弹掉。这个「加进去 / 弹出来」的配对，就是回溯的全部内容。

## 3. 从暴力到最优

用示例 1 走一遍：`root = [5,4,8,11,null,13,4,7,2,null,null,5,1]`，`targetSum = 22`。树结构：

```
        5
       / \
      4   8
     /   / \
    11  13  4
   / \      / \
  7   2    5   1
```

**暴力版**：先 DFS 收集所有根到叶路径，得到
`[[5,4,11,7], [5,4,11,2], [5,8,13], [5,8,4,5], [5,8,4,1]]`，
再逐条求和 `[27, 22, 26, 22, 18]`，筛出第 2、4 条。中间存了 5 条路径、共 17 个元素，其中 3 条是废的。

**回溯版**：维护 `path = []`、`remain = 22`（剩余目标和，比维护总和更省一次减法）。

| 动作 | path | remain |
|---|---|---|
| 进 5 | [5] | 17 |
| 进 4 | [5,4] | 13 |
| 进 11 | [5,4,11] | 2 |
| 进 7 | [5,4,11,7] | -5，是叶子，不匹配 |
| 退 7 | [5,4,11] | 2 |
| 进 2 | [5,4,11,2] | 0，是叶子，**命中**，拷贝 `[5,4,11,2]` 存入答案 |
| 退 2、退 11、退 4 | [5] | 17 |
| 进 8 | [5,8] | 9 |
| 进 13 | [5,8,13] | -4，叶子，不匹配 |
| 退 13，进 4 | [5,8,4] | 5 |
| 进 5 | [5,8,4,5] | 0，叶子，**命中** |
| 退 5，进 1 | [5,8,4,1] | 4，叶子，不匹配 |

全程 `path` 长度不超过树高 4，任何时刻只有一条路径在内存里。瓶颈从「存所有路径」降到「存一条路径 + 答案本身」。

注意一个细节：命中时存进答案的必须是 `path[:]`（拷贝），不能直接 `append(path)`。因为 `path` 是同一个可变对象，后续回溯会把它改掉，你最终会得到一堆空列表。这是本题最高频的实现 bug。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。

**不变量**：在 DFS 进入节点 `u` 的那一刻，`path` 恰好是从根到 `u` 的节点值序列（含 `u`），`remain` 恰好等于 `targetSum` 减去这条路径上所有值之和。

- **初始**：进入根时 `path = [root.val]`，`remain = targetSum - root.val`，成立。
- **保持**：进入子节点 `v` 时先 `path.append(v.val)`、`remain -= v.val`，此时 `path` 是根到 `v` 的序列，`remain` 同步更新，不变量保持。递归返回后 `path.pop()`、`remain += v.val`，恢复到进入 `u` 时的状态，不变量对兄弟子树同样成立。
- **终止**：当 `u` 是叶子时，`path` 就是一条完整的根到叶路径，`remain == 0` 当且仅当这条路径和等于目标。此时记录，判断精确。

**不漏**：任意一条根到叶路径，都对应 DFS 中「从根一路向下、每步选对应子节点」的一条递归链，这条链必然被执行到，且执行到叶子时 `path` 正是该路径（由不变量保证）。所以每条候选路径都被检查过。

**不重**：二叉树中每个节点只有一个父节点，因此「根到叶的路径」与「叶子节点」一一对应。DFS 对每个叶子只访问一次（每个节点只被其父节点递归一次），所以每条路径只被判定一次。答案里不会出现重复路径。

**为什么回溯的 pop 是必须的**：如果不 pop，`path` 会累积成「所有访问过的节点」，不变量立刻破裂，后续叶子的判断全部错误。pop 的作用就是把状态还原到「进入当前节点前」，这是回溯能正确枚举所有分支的前提。

## 5. 完整代码（Python）

```python
from typing import List, Optional


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> List[List[int]]:
        res: List[List[int]] = []
        path: List[int] = []

        def dfs(node: Optional[TreeNode], remain: int) -> None:
            if node is None:
                return

            # 进入节点：把当前值加入路径，剩余目标同步扣减
            path.append(node.val)
            remain -= node.val

            # 叶子判定：无左右子节点，且剩余目标恰好为 0
            if node.left is None and node.right is None and remain == 0:
                # 必须拷贝！path 是共享的可变对象，后续回溯会修改它
                res.append(path[:])

            # 继续向下探索左右子树
            dfs(node.left, remain)
            dfs(node.right, remain)

            # 离开节点：撤销选择，恢复进入前的状态
            path.pop()

        dfs(root, targetSum)
        return res
```

几个容易写错的地方，对照代码看：

- `remain` 用参数传递而不是全局变量，天然做到「进入时扣、返回时自动恢复」，比手动 `remain += node.val` 更不容易错。
- 叶子判定必须同时检查 `left is None and right is None`。只写 `remain == 0` 会把「中途就凑够和」的非叶子节点也记进去，那是错的——题目要求根到**叶**。
- `path[:]` 的拷贝不能省。

## 6. 复杂度

**时间 O(n)**，n 是节点总数。每个节点被访问恰好一次（父节点递归调用一次），每次访问做常数工作：append、减法、两次判空、pop。没有对路径求和的内层循环——因为 `remain` 是增量维护的。如果改成「每到叶子就对 `path` 求和」，最坏会变成 O(n log n)（满二叉树 n/2 个叶子 × 路径长 log n），这就是增量维护省下的部分。

**空间**：
- 递归栈深度 = 树高 h，最坏 O(n)（退化成链），最好 O(log n)（平衡树）。
- `path` 长度同样不超过 h，O(h)。
- 答案 `res` 本身占 O(答案总长度)，这部分是输出必需的，通常不计入辅助空间；但面试时值得主动说明「不计输出的话辅助空间是 O(h)」。

所以标准说法：**时间 O(n)，空间 O(h)，h 为树高，最坏 O(n)**。

## 7. 边界与反例（至少 4 条）

1. **空树** `root = [], targetSum = 0` → 期望 `[]`。容易错在：以为目标和为 0 就该返回 `[[]]`。空树没有叶子，不存在根到叶路径，必须返回空列表。代码里 `dfs(None, ...)` 第一行就 return，正确。

2. **单节点且值等于目标** `root = [5], targetSum = 5` → 期望 `[[5]]`。容易错在：把「叶子」理解成「必须有子节点才算」，漏判根节点本身是叶子的情况。代码里根节点 `left/right` 都是 None，直接命中。

3. **单节点但值不等于目标** `root = [5], targetSum = 0` → 期望 `[]`。对应示例 3 的变体，容易错在：`remain` 扣减后是 5 不是 0，不记录，正确。

4. **负数值导致「中途凑够」** 如 `root = [1,-2,1,-1], targetSum = -1`，路径 `1 → -2` 的和是 -1，但 -2 不是叶子（它有子节点 -1）。容易错在：只判 `remain == 0` 就记录，会把非叶子的中间路径也塞进答案。必须加上叶子判定。

5. **答案需要深拷贝** 任何有多个命中路径的用例（如示例 1）→ 期望两条独立列表。容易错在：`res.append(path)` 不拷贝，最终 `res` 里全是同一个空列表的引用。

6. **目标和为负、节点值有正有负** 题面提示节点值范围含负数，所以不能靠「和已经超过目标就剪枝」来优化——剪枝会漏解。这一点在追问里会展开。

## 8. 面试追问与变体（3 条）

1. **追问：能不能剪枝？** 思路：只有当所有节点值非负时，才能用「`remain < 0` 就提前返回」剪枝；本题值域含负数，剪枝不安全，必须老实走完。回答时点明「剪枝的正确性依赖值域假设」比直接写剪枝更加分。

2. **追问：改成「任意节点到任意后代节点」的路径，怎么改？** 思路：不再要求起点是根，需要在每个节点处把「以它为起点的路径」也纳入统计，典型做法是前缀和 + 哈希表（类似「路径总和 III」），把「根到当前节点的前缀和」存起来，查 `prefix - target` 是否出现过。

3. **追问：如果要求返回路径数量而不是路径本身？** 思路：去掉 `path` 和 `res`，只维护一个计数器，命中时 `count += 1`，空间从 O(h + 输出) 降到 O(h)，代码更短，也说明「路径内容」和「路径计数」是两件事。

## 9. 举一反三（2-3 道同类题）

- **112. 路径总和**：同样是从根到叶、边走边扣目标和，区别只是「找到一条就返回 true」，不需要回溯记录路径，是本题的简化版。
- **257. 二叉树的所有路径**：同样是根到叶枚举 + 回溯维护 `path`，区别是不做和判定，把所有路径都输出，练的是同一套「append / 递归 / pop」骨架。
- **437. 路径总和 III**：路径不再限定从根开始，需要前缀和 + 哈希，是本题从「固定起点」推广到「任意起点」的版本。
