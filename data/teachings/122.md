## 1. 一句话本质

把价格序列拆成若干段「低买高卖」，让所有上涨区间的涨幅之和最大——等价于**把所有相邻两天的正差价全部收进口袋**。

## 2. 读完题的第一反应

**朴素解法**：枚举所有买卖方案。每天有「买 / 卖 / 不动」三种选择，还要满足「最多持一股」的约束，方案数是指数级的。即使做记忆化搜索，状态也得是 `(第几天, 是否持股)`，转移时枚举「今天买还是卖」，复杂度 O(n) 状态 × O(1) 转移——其实这已经能过，但它是 DP 的思路，不是本题最直接的解法。

**关键观察**：题目允许「同一天多次买卖」，且**没有交易次数限制、没有手续费**。这两条限制一旦都不存在，「一笔跨多天的交易」和「拆成每天一笔的交易」在收益上完全等价。比如从第 1 天价格 1 持有到第 5 天价格 5，赚 4；拆成 1→2→3→4→5 每天买卖一次，赚 (2-1)+(3-2)+(4-3)+(5-4) = 4，一模一样。

这个观察一旦成立，问题就从「找最优的买卖配对」塌缩成「把每个正差价加起来」——因为任何一段上涨都可以被逐日拆解，而任何一段下跌都不该参与（参与了只会亏）。

## 3. 从暴力到最优

**第一步：DP 视角（保证不漏）**

定义两个状态：
- `hold`：第 i 天结束时**持有**股票的最大利润
- `free`：第 i 天结束时**不持有**股票的最大利润

转移：
- `hold = max(hold, free - prices[i])`（今天买，或继续持有）
- `free = max(free, hold + prices[i])`（今天卖，或继续空仓）

以 `prices = [7,1,5,3,6,4]` 走一遍：

| 天 | 价格 | hold | free |
|---|---|---|---|
| 初始 | - | -∞ | 0 |
| 0 | 7 | -7 | 0 |
| 1 | 1 | -1 | 0 |
| 2 | 5 | -1 | 4 |
| 3 | 3 | -1 | 4 |
| 4 | 6 | -1 | 7 |
| 5 | 4 | -1 | 7 |

答案 `free = 7`，和示例一致。这个 DP 是 O(n) 时间、O(1) 空间，已经是最优复杂度了。

**第二步：贪心视角（把 DP 化简）**

观察上表 `free` 的更新：`free = max(free, hold + prices[i])`。而 `hold` 在价格持续上涨时始终等于「上一次卖出后的 free 减去当前买入价」。把两个式子代入展开，会发现 `free` 的增量恰好是 `max(0, prices[i] - prices[i-1])`。

用同一组数据验证贪心：

```
i=1: 1-7 = -6 → 不加，累计 0
i=2: 5-1 = +4 → 加，累计 4
i=3: 3-5 = -2 → 不加，累计 4
i=4: 6-3 = +3 → 加，累计 7
i=5: 4-6 = -2 → 不加，累计 7
```

结果 7。**瓶颈被消掉的方式**：DP 需要维护「持股/空仓」两个状态并做 max，贪心直接看出「只要今天比昨天贵，就当作昨天买今天卖」，一步到位，代码从两个变量缩成一个累加器。

## 4. 正确性：为什么不会漏、不会重

用**交换论证 + 区间分解**说明。

**引理**：任意一个合法交易方案的总利润，等于它覆盖的每个「相邻日差价」之和，其中上涨日贡献正数、下跌日贡献负数（若该日处于持仓区间内）。

证明：设某笔交易在第 a 天买入、第 b 天卖出（a < b），利润 = `prices[b] - prices[a]` = `Σ_{i=a+1}^{b} (prices[i] - prices[i-1])`。这是恒等式，逐项展开即可。多笔交易互不重叠（因为最多持一股），所以总利润就是各笔交易对应区间内相邻差价之和。

**推论**：任何方案的总利润 ≤ `Σ max(0, prices[i] - prices[i-1])`，因为每个相邻差价最多贡献它的正值部分。

**可达性**：贪心方案「对每个 `prices[i] > prices[i-1]` 的日子，前一天买、当天卖」是合法的——每天最多持一股，当天买当天卖不违反约束，且相邻交易之间不重叠。它的总利润恰好等于 `Σ max(0, prices[i] - prices[i-1])`。

上界可达 ⇒ 贪心最优。**不会漏**：上界推导覆盖了所有方案；**不会重**：每个相邻差价只被计入一次，且贪心方案里每个上涨日独立成笔，不存在同一段被重复计算。

## 5. 完整代码（Python）

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        # 贪心：把所有相邻两天的正差价累加
        # 依据：一笔跨多天的交易可无损拆成逐日交易，故只需收集每个上涨日
        profit = 0
        for i in range(1, len(prices)):
            diff = prices[i] - prices[i - 1]
            if diff > 0:          # 只收上涨的部分，下跌日跳过（相当于空仓）
                profit += diff
        return profit
```

如果面试官要求写 DP 版本（更通用，能应对加手续费等变体），可以补一个：

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        # hold: 第 i 天结束时持股的最大利润；free: 空仓的最大利润
        hold = float('-inf')   # 初始不可能持股
        free = 0               # 初始空仓，利润 0
        for p in prices:
            # 先算新的 hold（用旧的 free），再算新的 free（用旧的 hold）
            new_hold = max(hold, free - p)   # 继续持有 or 今天买入
            new_free = max(free, hold + p)   # 继续空仓 or 今天卖出
            hold, free = new_hold, new_free
        return free
```

注意 DP 版本里 `new_free` 用的是**旧的** `hold`，不能先更新 `hold` 再算 `free`，否则会变成「同一天既买又卖」的非法状态（虽然本题允许同日多次买卖，但那样会重复计算，导致结果偏大）。这是写 DP 时最容易踩的坑。

## 6. 复杂度

- **时间 O(n)**：`n = len(prices)`，循环从 `i=1` 到 `n-1`，共 `n-1` 次迭代，每次 O(1) 的减法与比较。没有排序、没有二分，所以不出现 log n。
- **空间 O(1)**：只用了 `profit`（贪心版）或 `hold`、`free`（DP 版）几个标量，与 n 无关。输入数组本身不计入额外空间。

## 7. 边界与反例（至少 4 条）

1. **`prices = [5]`** → 期望 `0`。只有一天，`range(1, 1)` 为空，循环不执行，返回 0。容易错在忘记处理长度为 1 的情况，或误以为必须交易。
2. **`prices = [7,6,4,3,1]`** → 期望 `0`。全程下跌，每个 diff 都 ≤ 0，累加器保持 0。容易错在写成「必须买一次」，返回负数。
3. **`prices = [1,2,3,4,5]`** → 期望 `4`。连续上涨，贪心逐日累加 1+1+1+1=4。容易错在只算「首尾差」时漏掉中间，或误以为只能交易一次而返回 4 却解释不清为什么和「一次持有到底」等价。
4. **`prices = [2,1,2,0,1]`** → 期望 `2`。上涨段是 1→2（+1）和 0→1（+1），合计 2。容易错在把 2→1 的下跌也「持有」进去，或者把 2→0 的大跌当成机会反向操作（本题不允许做空）。
5. **`prices = [1,1,1]`** → 期望 `0`。diff 全为 0，`> 0` 判断为假，不累加。容易错在用 `>= 0` 时逻辑上没错但语义上多此一举，或误判为有利润。

## 8. 面试追问与变体（3 条）

1. **追问：如果每次卖出要收手续费 fee，怎么做？**
   思路：贪心不再成立（频繁交易会被手续费吃掉），回到 DP，转移改成 `free = max(free, hold + p - fee)`，其余不变，O(n) 时间。

2. **追问：如果最多只能交易 k 次，怎么做？**
   思路：状态扩成 `dp[i][j][0/1]`（第 i 天、已交易 j 次、是否持股），O(nk) 时间；k 很大时可用「贪心 + 优先队列」或「WQS 二分」优化。

3. **追问：如果允许做空（可以先卖后买），答案会变吗？**
   思路：会。此时下跌段也能赚钱，答案变成 `Σ |prices[i] - prices[i-1]|`，因为每个相邻差价的正负绝对值都能被收割。
