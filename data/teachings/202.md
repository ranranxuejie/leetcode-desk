## 1. 一句话本质

判断「把 n 反复替换成各位数字平方和」这个迭代过程，最终是落到 1，还是落进一个不含 1 的环里——本质是**在一条函数迭代轨道上做环检测**。

## 2. 读完题的第一反应

**朴素解法**：老老实实按定义模拟。写一个 `next(n)` 算平方和，然后 `while n != 1: n = next(n)`。

它卡在哪？题面自己说了：「也可能是无限循环但始终变不到 1」。也就是说这个 `while` 可能永远不退出。所以朴素解法的瓶颈不是单步太慢（单步是 O(log n)，很便宜），而是**终止性没有保证**——你必须额外判断「我是不是已经见过这个数了」。

**关键观察**：这个迭代是一个确定性函数 `f(n) = 各位平方和`。给定 n，下一步唯一确定。所以整条轨道只有两种命运：

- 要么撞到 1（然后 1→1，自环，停住）；
- 要么在有限个状态里无限游走，由鸽巢原理必然**重复**某个数，从而进入一个环。

这个观察直接给出下一步：只要能检测「重复」，就能判定。而「检测重复」有两个经典工具——哈希集合（记录走过的）和快慢指针（Floyd 判环）。题目标签里的「哈希表 / 双指针」正是这两条路。

还有一个隐藏的、让这题从「一般图判环」降级为「小常数问题」的观察：n ≤ 2^31−1 时，平方和会迅速掉到很小的范围（下一节算给你看）。这决定了复杂度分析怎么写。

## 3. 从暴力到最优

**第 0 步：暴力模拟，会死循环。**

以 n = 2 为例（示例 2）：

```
2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → ...
```

注意 `4` 出现了两次，之后就是 `4→16→37→...→20→4` 这个 8 元环在转。`while n != 1` 永远不退出。这就是瓶颈：**没有终止条件**。

**第 1 步：哈希集合，消掉「不知道是否重复」。**

用一个 `seen` 集合记录每个出现过的值。每步先查 `n in seen`，是则说明进环且没到过 1，返回 False；否则加入集合继续。一旦 `n == 1` 返回 True。

还是 n = 2，走一遍中间变量：

| 步 | n | seen（加入前） | 判断 |
|---|---|---|---|
| 1 | 2 | {} | 未见过，加入 |
| 2 | 4 | {2} | 未见过，加入 |
| 3 | 16 | {2,4} | 未见过，加入 |
| 4 | 37 | {2,4,16} | 未见过，加入 |
| 5 | 58 | {2,4,16,37} | 未见过，加入 |
| 6 | 89 | {2,4,16,37,58} | 未见过，加入 |
| 7 | 145 | {...} | 未见过，加入 |
| 8 | 42 | {...} | 未见过，加入 |
| 9 | 20 | {...} | 未见过，加入 |
| 10 | 4 | {...} | **4 已在集合中** → 返回 False |

瓶颈消掉了：终止性有了保证。代价是 O(环长) 的额外空间。

**第 2 步：快慢指针，把空间压到 O(1)。**

既然轨道是「一条链 + 一个环」（或链 + 自环 1），就可以用 Floyd 判环：慢指针每步走一次 `f`，快指针每步走两次 `f`。若存在环，快指针一定追上慢指针；若轨道终止于 1，快指针会先到 1。

对 n = 2 走一遍（只列关键帧）：

```
慢: 2   快: 2
慢: 4   快: 16
慢: 16  快: 58
慢: 37  快: 145
慢: 58  快: 20
慢: 89  快: 16
慢: 145 快: 58
慢: 42  快: 145
慢: 20  快: 20   ← 相遇，且不是 1 → False
```

对 n = 19（示例 1）：`19→82→68→100→1`，快指针会先踩到 1，直接返回 True。

**第 3 步：其实还有更省事的第三条路——数学硬编码。**

题面范围 n ≤ 2^31−1，任何数的平方和最多是 9 位数全 9 的情况吗？不是，2^31−1 = 2147483647 是 10 位，但平方和最大是 `9²×10 = 810`。也就是说**从第二步开始，所有值都 ≤ 810**。而 810 以内的轨道是固定的，可以预先算出「唯一的不含 1 的环」是

```
4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4
```

于是判据变成：迭代过程中只要撞到 4（或环里任一数），就是非快乐数。这是 O(1) 空间且常数极小，但**依赖题面范围**，属于「知道就好、面试别当主答案」的技巧。下面代码用快慢指针，通用且好讲。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

定义 `f(x) = x 的各位数字平方和`，轨道 `x_0 = n, x_{k+1} = f(x_k)`。

**引理（轨道结构）**：由于 f 是确定性函数，序列 `x_0, x_1, x_2, ...` 一旦出现 `x_i = x_j (i < j)`，则对所有 `t ≥ 0` 有 `x_{i+t} = x_{j+t}`，即从 i 开始进入周期为 `j−i` 的环。证明：对 t 归纳，每步都作用同一个 f。

**不变量 1（哈希法）**：循环每轮开始时，`seen` 恰好等于 `{x_0, ..., x_{k-1}}`（已走过的前缀集合），且其中不含 1。于是：
- 若某轮 `x_k == 1`，由定义 n 是快乐数，返回 True，不漏；
- 若某轮 `x_k ∈ seen`，由引理轨道从此周期性重复，且 `seen` 不含 1，故永远到不了 1，返回 False，不错判；
- 两者都不发生则继续，`seen` 严格增大，受状态空间有限约束必然终止。所以不会漏也不会重。

**不变量 2（快慢指针）**：设慢指针位置 `s_k = x_k`，快指针 `q_k = x_{2k}`（归纳可证：快指针每轮走两步，第 k 轮恰在 `x_{2k}`）。于是：
- 若轨道终止于 1，即存在 m 使 `x_m = 1` 且之后恒为 1。取 k ≥ m，则 `s_k = q_k = 1`，循环条件 `s != q` 失效，退出后判 `s == 1` 为真，返回 True，不漏。
- 若轨道进环且环不含 1，标准 Floyd 论证：设进入环的位置为 μ、环长为 λ。当 k ≥ μ 时两指针都在环上，位置差 `(2k − k) mod λ = k mod λ`，取 k 为 λ 的倍数即追上。追上时 `s = q ≠ 1`（环不含 1），返回 False，不错判。
- 两种情况之外无第三种命运（引理保证轨道只有「终止」或「进环」），故完备。

注意一个容易讲错的点：快慢指针在这里**不是**在找「环的入口」，只是判「有没有环、环是不是 1」。所以退出条件写 `while slow != fast` 之后判 `slow == 1` 就够了，不需要第二阶段找入口。

## 5. 完整代码（Python）

```python
class Solution:
    def isHappy(self, n: int) -> bool:
        def square_sum(x: int) -> int:
            """把 x 替换为各位数字的平方和。"""
            total = 0
            while x > 0:
                d = x % 10          # 取最低位
                total += d * d
                x //= 10            # 去掉最低位
            return total

        slow = n
        fast = n
        # 快指针每轮走两步，慢指针走一步；有环必相遇
        while True:
            slow = square_sum(slow)          # 走 1 步
            fast = square_sum(square_sum(fast))  # 走 2 步
            if slow == fast:
                break
        # 相遇点是否为 1：是则轨道终止于 1（快乐数），否则是进了非 1 的环
        return slow == 1
```

如果面试官更想要哈希版本（更好解释、也常被接受），等价写法：

```python
class Solution:
    def isHappy(self, n: int) -> bool:
        seen = set()
        while n != 1 and n not in seen:
            seen.add(n)
            total = 0
            while n > 0:
                d = n % 10
                total += d * d
                n //= 10
            n = total
        return n == 1   # 因 1 退出为 True；因重复退出时 n != 1 为 False
```

两版都对；快慢指针版空间 O(1)，是这题的最优形态。

## 6. 复杂度

先定一个量：**位数**。n 的十进制位数是 `O(log n)`（以 10 为底，常数因子不影响大 O）。单次 `square_sum` 要遍历每一位，所以是 **O(log n)**。

**哈希版**：
- 时间：轨道长度 × 单步代价。轨道长度是多少？由第 3 节，n ≤ 2^31−1 时第一步之后值 ≤ 810，而 810 以内的轨道长度有上界（实测最长也就十几步），是**常数**。所以总时间是 `O(log n)`——这个 log n 完全来自「第一次算平方和要扫 n 的所有位」，之后的迭代都是常数位。若把 n 看成任意大整数，则严格写 `O(log n · L)`，L 为轨道长度上界；在本题范围里 L 是常数，故 `O(log n)`。
- 空间：`seen` 存轨道上所有值，`O(L)`，本题范围下是 `O(1)`；若按一般化写是 `O(log n)` 级别（每个值本身是 O(log n) 位，但值有界所以实际常数）。

**快慢指针版**：
- 时间：同样 `O(log n)`，理由同上；快指针多走一步只是常数倍。
- 空间：`O(1)`，只有两个指针变量。这是它相对哈希版的唯一但关键的收益。

一句话记法：**log n 来自「拆数字」，不是来自「迭代次数」；迭代次数在本题范围里是常数。**

## 7. 边界与反例（至少 4 条）

1. **n = 1** → 期望 True → 易错点：有人写 `while n != 1` 再在循环里判断，1 直接不进循环，若返回语句写错（比如循环后才 `return False`）就会错。快慢指针版第一轮 `slow = fast = 1` 立即相遇，`return 1 == 1` 为 True，天然正确。
2. **n = 2** → 期望 False → 易错点：这是最短的非快乐数入口之一，会进入 `4→16→...→4` 的 8 元环。若只写 `while n != 1` 不加环检测，直接死循环（示例 2 就是专门考这个）。
3. **n = 7** → 期望 True → 易错点：轨道是 `7→49→97→130→10→1`，中间出现过 10、130 这种「看起来像要循环」的数，容易让人误以为要判 False；实际它最终到 1。说明**不能凭中间值大小猜**，必须真跑完。
4. **n = 2147483647（2^31−1）** → 期望 False → 易错点：这是范围上界，10 位数。若 `square_sum` 里用字符串转换或 `sum(int(c)**2 for c in str(x))` 也能过，但若有人误以为「平方和会很大、要开大数组」就会浪费空间；实际第一步后 ≤ 810。另外这题验证了「值域迅速收缩」这个观察。
5. **n = 4** → 期望 False → 易错点：4 本身就是那个 8 元环的成员。如果实现里把「遇到 4 就返回 False」当优化写死，要确保它和通用逻辑一致；若写死成「遇到 4 返回 True」就全错。

## 8. 面试追问与变体（3 条）

1. **追问：不用哈希也不用快慢指针，怎么 O(1) 空间做？**
   思路：利用值域收缩——第一步后 ≤ 810，而 810 以内非快乐数必落入 `4→16→37→58→89→145→42→20→4` 这个环。迭代中一旦 `n == 4` 就返回 False，`n == 1` 返回 True。本质是把「环检测」换成「硬编码环成员」。

2. **追问：如果定义改成「各位数字的立方和」呢？**
   思路：框架完全不变，只改 `square_sum` 里的指数。但要注意此时值域上界和环结构都变了（可能出现多个不同的环），所以「硬编码 4」那招失效，必须回到哈希或快慢指针这种通用判环。这题考的是「你的解法依赖了哪个具体常数」。

3. **追问：把「判断是否快乐」改成「返回轨道长度直到 1 或进环」？**
   思路：哈希版顺手就能记长度（`len(seen)`）；快慢指针版需要在相遇后补一段「从相遇点再走一圈数环长」，或直接退回哈希版。追问点在于你是否清楚快慢指针**只判有无环、不直接给环长**。
