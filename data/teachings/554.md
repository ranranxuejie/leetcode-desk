## 1. 一句话本质

在所有「砖缝的横坐标」里，找出被最多行共享的那一个位置，答案就是 `行数 - 该位置出现的行数`。

## 2. 读完题的第一反应

**朴素解法**：把垂线可能落在的每个横坐标都试一遍。对每个候选位置 `x`，逐行扫描该行的砖块，判断 `x` 是否落在某块砖内部（即不是砖缝），统计穿过的砖块数，取最小值。

卡在哪？候选位置的数量级是「墙的总宽度」，而砖块宽度可以到 `2^31-1`，总宽度是天文数字，根本枚举不了。即使只枚举「所有砖缝的坐标」，最坏情况下每行有 `10^4` 块砖、共 `10^4` 行，砖缝总数可达 `10^8`，再对每个砖缝扫一遍所有行，直接爆炸。

**关键观察**：题目问的是「穿过最少砖块」，而穿过砖块数 = `总行数 - 垂线恰好落在砖缝上的行数`。因为对任意一行，垂线要么穿过某块砖，要么正好落在两块砖之间（砖缝），二者必居其一。所以「穿过最少」等价于「落在砖缝上的行数最多」。

于是问题从「枚举位置、逐行判断」翻转成「枚举砖缝、统计它被多少行共享」。而每一行的砖缝位置，只需要对该行做一次前缀和就能全部得到——这就是下一步的入口。

## 3. 从暴力到最优

**第一步：暴力枚举位置**。候选 `x` 从 1 到总宽度-1，每个 `x` 扫所有行所有砖。复杂度 `O(总宽度 × 总砖数)`，总宽度可达 `10^13` 量级，不可行。

**第二步：只枚举真实存在的砖缝**。观察到垂线只有落在某行的砖缝上才「不穿砖」，所以最优位置一定在某个砖缝处（否则穿过所有行，答案就是 n，不可能更优）。把所有行的砖缝收集起来，对每个砖缝统计覆盖行数。收集阶段 `O(总砖数)`，但统计阶段如果对每个砖缝再扫所有行，还是 `O(砖缝数 × 行数)`。

**第三步：用哈希表一次遍历完成统计**。遍历每一行时，边做前缀和边把「当前前缀和」作为键、出现次数加一。前缀和就是该行砖缝的横坐标。所有行遍历完，哈希表里每个键的值就是「有多少行的砖缝落在这个坐标」。取最大值 `max_count`，答案 `n - max_count`。

**小例子走一遍**：`wall = [[1,2,2,1],[3,1,2],[1,3,2],[2,4],[3,1,2],[1,3,1,1]]`，n=6。

- 第 0 行 `[1,2,2,1]`：前缀和依次 1, 3, 5（最后一块不加，因为墙右边缘不算砖缝）。哈希表：`{1:1, 3:1, 5:1}`
- 第 1 行 `[3,1,2]`：前缀和 3, 4。表：`{1:1, 3:2, 5:1, 4:1}`
- 第 2 行 `[1,3,2]`：前缀和 1, 4。表：`{1:2, 3:2, 5:1, 4:2}`
- 第 3 行 `[2,4]`：前缀和 2。表：`{1:2, 3:2, 5:1, 4:2, 2:1}`
- 第 4 行 `[3,1,2]`：前缀和 3, 4。表：`{1:2, 3:3, 5:1, 4:3, 2:1}`
- 第 5 行 `[1,3,1,1]`：前缀和 1, 4, 5。表：`{1:3, 3:3, 5:2, 4:4, 2:1}`

最大覆盖数 `max_count = 4`（坐标 4），答案 `6 - 4 = 2`，与示例一致。

注意每行最后一块砖的右边界不加进哈希表：那是墙的右边缘，题目禁止沿墙边缘画线，且它本来也不构成「行内砖缝」。

## 4. 正确性：为什么不会漏、不会重

**不变量**：遍历完前 `k` 行后，哈希表中键 `x` 的值恰好等于「前 `k` 行中，砖缝横坐标为 `x` 的行数」。

- 初始 `k=0`，表为空，成立。
- 处理第 `k` 行时，对该行做前缀和，每得到一个前缀和 `s`（`s` 小于该行总宽），说明第 `k` 行在 `x=s` 处有一条砖缝，于是 `count[s] += 1`。其他键不受影响。不变量保持。

**不漏**：任何一条合法垂线（不沿墙边缘）若穿过少于 `n` 块砖，则至少有一行在垂线处是砖缝，故垂线横坐标必出现在哈希表中。反过来，哈希表中每个键都对应至少一行的真实砖缝，是合法候选位置。

**不重**：对固定行，前缀和严格递增（砖宽 ≥ 1），所以同一行不会对同一坐标重复计数；不同行的贡献是独立累加的，正是「共享该砖缝的行数」。

**最优性**：设哈希表最大值为 `M`，取对应坐标画线，有 `M` 行不穿砖，其余 `n-M` 行各穿一块，穿过数 `= n-M`。若存在更优位置穿过 `n-M' < n-M` 块，则它落在砖缝上的行数 `M' > M`，与 `M` 的最大性矛盾。故 `n-M` 是最小值。

## 5. 完整代码（Python）

```python
from collections import defaultdict

class Solution:
    def leastBricks(self, wall) -> int:
        # 记录每个砖缝横坐标被多少行共享
        gap_count = defaultdict(int)

        for row in wall:
            pos = 0
            # 只累加到倒数第二块砖：最后一块的右边界是墙的右边缘，不是砖缝
            for i in range(len(row) - 1):
                pos += row[i]
                gap_count[pos] += 1

        # 没有任何砖缝（每行只有一块砖）时，max 的默认值取 0
        max_shared = max(gap_count.values(), default=0)

        # 穿过砖块数 = 总行数 - 落在砖缝上的行数
        return len(wall) - max_shared
```

关键点说明：`range(len(row) - 1)` 是本题最容易写错的地方，它保证不把墙的右边缘当成砖缝；`default=0` 处理「每行只有一块砖、哈希表为空」的退化情况。

## 6. 复杂度

设总砖块数为 `S = sum(len(wall[i]))`，行数为 `n`。

- **时间 `O(S)`**：外层循环 `n` 行，内层对第 `i` 行循环 `len(wall[i]) - 1` 次，总次数 `S - n < S`。哈希表的插入和查询均摊 `O(1)`（Python dict 用哈希，无排序，所以**没有** `log` 项）。最后求 `max` 是 `O(不同砖缝数) ≤ O(S)`。
- **空间 `O(S)`**：哈希表最多存 `S - n` 个不同键，即所有行砖缝坐标的去重集合，上界 `O(S)`。题目保证 `S ≤ 2×10^4`，完全够用。

注意：空间与「墙的总宽度」无关，只与砖块个数有关——这正是用哈希表而非数组下标映射的原因（宽度可达 `2^31`，开不了数组）。

## 7. 边界与反例（至少 4 条）

1. **`wall = [[1],[1],[1]]` → 输出 3**。每行只有一块砖，内层循环 `range(0)` 不执行，哈希表为空，`max(..., default=0)=0`，返回 `3-0=3`。易错点：忘记 `default=0` 会抛 `ValueError`；或误把最后一块的右边界计入，得到错误答案。

2. **`wall = [[1,1],[2]]` → 输出 1**。第 0 行砖缝在 1，第 1 行无砖缝。`max_shared=1`，返回 `2-1=1`。易错点：以为「某行只有一块砖就没有贡献」是对的，但若因此跳过整行逻辑写错（比如提前 `continue` 前误加边界），会算错。

3. **`wall = [[2,2],[2,2]]` → 输出 2**。两行砖缝都在 2，`max_shared=2`，返回 `2-2=0`？不对——正确答案是 0 吗？检查：在 `x=2` 画线，两行都恰好落在砖缝，穿过 0 块砖。题目允许穿 0 块，返回 0 合法。易错点：有人以为答案至少为 1，或把「穿过 0 块」当成非法。

4. **`wall = [[1,2,1],[2,2]]` → 输出 1**。第 0 行砖缝 1、3；第 1 行砖缝 2。无共享砖缝，`max_shared=1`，返回 `2-1=1`。易错点：误以为「没有共享砖缝」时答案是 n=2，实际任选一个砖缝都能让一行不穿砖。

5. **单行 `wall = [[5]]` → 输出 1**。哈希表空，返回 `1-0=1`。易错点：把墙左边缘 `x=0` 或右边缘 `x=5` 当砖缝，会错误地返回 0。

## 8. 面试追问与变体（3 条）

1. **追问：如果允许沿墙的左右边缘画线，答案会变吗？** 思路：会。此时 `x=0` 对所有行都是「边缘」，穿过 0 块砖，答案恒为 0，题目失去意义——这正解释了题面为何要禁止沿边缘画线。

2. **追问：如果要求返回具体的垂线横坐标（而非穿过数），怎么改？** 思路：在哈希表里同时记录 `max_shared` 对应的键，遍历时维护当前最大值及其坐标即可，时间空间不变。

3. **追问：如果砖墙是「环形」的（首尾相接），怎么处理？** 思路：环形下每行的砖缝集合需加上「绕回点」，本质变成在模总宽意义下统计出现最多的余数，仍用哈希表，但要把每行的前缀和与 `总宽 - 前缀和` 一并考虑，注意去重。

## 9. 举一反三（2-3 道同类题）

1. **力扣 1. 两数之和**：共同点是「用哈希表把 O(n²) 的配对枚举降成 O(n) 的一次遍历」，都是「边遍历边记录、用记录反查」的套路。

2. **力扣 560. 和为 K 的子数组**：共同点是「前缀和 + 哈希表计数」，把「区间性质」转成「两个前缀和之差」，与本题把「砖缝位置」转成「前缀和坐标」是同一思想。

3. **力扣 525. 连续数组**：共同点是「把 0/1 转成 ±1 后求前缀和，用哈希表记录某前缀和首次出现位置」，核心都是「前缀和作为哈希键来消除重复枚举」。
