## 1. 一句话本质

给定一棵二叉树两种遍历的「访问顺序」，反推出这棵树唯一的形状——本质是**用前序定根、用中序切左右子树，然后递归地把同一个问题缩小到子数组上**。

## 2. 读完题的第一反应

先问自己：如果只给我 `preorder`，我能建树吗？不能。`[3,9,20,15,7]` 只告诉我「3 是根，后面依次访问」，但 9 到底是 3 的左孩子还是右孩子、20 挂在哪，完全无法确定。**单靠一种遍历信息量不够**，这是第一反应。

那两种遍历怎么配合？朴素想法是：前序第一个元素一定是整棵树的根（这是前序遍历的定义：根→左→右）。拿到根 `3` 后，去 `inorder` 里找 `3` 的位置——找到了，下标是 1。中序是「左→根→右」，所以 `3` 左边的 `[9]` 就是左子树的全部节点，右边的 `[15,20,7]` 就是右子树的全部节点。

到这里朴素解法的骨架就出来了：递归地做「找根 → 在中序里定位 → 切分 → 递归左右」。**瓶颈在哪？** 每次递归都要在 `inorder` 里线性扫描找根的位置，树有 n 个节点、每层扫描 O(n)，最坏（链状树）退化成 O(n²)。n 到 3000 时 O(n²) 是 9×10⁶，勉强能过，但面试官显然想看你把它优化掉。

关键观察：**元素无重复**（题面明确写了「均无重复元素」）。既然无重复，那「值 → 中序下标」就是一个固定的映射，可以**预处理成哈希表**，之后每次定位根都是 O(1)。这一条直接把瓶颈从「每次扫描」变成「查表」，整体从 O(n²) 降到 O(n)。这就是这道题从暴力到最优的全部跳跃。

## 3. 从暴力到最优

**暴力版**：递归函数 `build(pre_lo, pre_hi, in_lo, in_hi)`，每次取 `preorder[pre_lo]` 当根，在 `inorder[in_lo:in_hi+1]` 里 `index()` 找它，切成左右两段递归。定位是 O(区间长度)，总复杂度 O(n²)（链状树）到 O(n log n)（平衡树）。

**优化版**：建一个 `pos = {值: 中序下标}` 的字典，定位变 O(1)。剩下唯一要小心的是**切分时左右子树的区间边界怎么算**——这是这道题最容易写错的地方，必须用具体例子推一遍。

拿示例 1 走一遍：

```
preorder = [3, 9, 20, 15, 7]
inorder  = [9, 3, 15, 20, 7]
pos = {9:0, 3:1, 15:2, 20:3, 7:4}
```

**第一层**：`pre_lo=0`，根 = `preorder[0] = 3`。查表 `pos[3] = 1`。中序里 `3` 左边有 `1-0 = 1` 个元素（`[9]`），右边有 `4-1 = 3` 个元素（`[15,20,7]`）。

- 左子树：前序区间从 `pre_lo+1 = 1` 开始，长度 1，即 `preorder[1:2] = [9]`；中序区间 `inorder[0:1] = [9]`。
- 右子树：前序区间从 `pre_lo+1+左子树长度 = 1+1 = 2` 开始，到末尾，即 `preorder[2:5] = [20,15,7]`；中序区间 `inorder[2:5] = [15,20,7]`。

**第二层（左）**：根 = `preorder[1] = 9`，`pos[9]=0`，左边 0 个、右边 0 个，`9` 是叶子。

**第二层（右）**：根 = `preorder[2] = 20`，`pos[20]=3`。中序区间是 `[15,20,7]`（下标 2~4），`20` 左边 `3-2=1` 个（`[15]`），右边 `4-3=1` 个（`[7]`）。

- 左：前序 `preorder[3:4] = [15]`，中序 `inorder[2:3] = [15]`。
- 右：前序 `preorder[4:5] = [7]`，中序 `inorder[4:5] = [7]`。

拼起来：`3` 的左是 `9`，右是 `20`；`20` 的左是 `15`，右是 `7`。和输出 `[3,9,20,null,null,15,7]` 完全对上。

**这里必须记住的公式**（设根在中序的下标为 `k`，中序区间左端 `in_lo`）：

- 左子树节点数 `left_size = k - in_lo`
- 左子树前序区间：`[pre_lo+1, pre_lo+left_size]`，中序区间：`[in_lo, k-1]`
- 右子树前序区间：`[pre_lo+left_size+1, pre_hi]`，中序区间：`[k+1, in_hi]`

写代码时建议用「左闭右开」区间，能少一堆 `+1/-1` 的 off-by-one 错误。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。对任意一次递归调用 `build(pre_lo, pre_hi, in_lo, in_hi)`，维持这个不变量：

> `preorder[pre_lo:pre_hi]` 与 `inorder[in_lo:in_hi]` 恰好是同一棵子树的两种遍历，且两段长度相等。

**归纳基础**：初始调用两个数组是同一棵树，长度相等，成立。

**归纳步骤**：设当前区间非空。前序第一个 `preorder[pre_lo]` 是这棵子树的根（前序定义）。因为元素无重复，它在 `inorder` 中的位置 `k` 唯一确定。中序定义保证 `inorder[in_lo:k]` 是左子树全部节点、`inorder[k+1:in_hi]` 是右子树全部节点——**不漏**：中序里根两侧覆盖了所有节点；**不重**：`k` 只被用一次，左右两段互不相交。

再看前序切分：前序是「根→左子树全部→右子树全部」，所以紧跟根之后的 `left_size = k - in_lo` 个元素正是左子树的前序，剩下的是右子树的前序。这个 `left_size` 由中序算出，与「前序里左子树长度」必然相等（因为左右子树节点集合在两种遍历里是同一批），所以切分**不漏不重**。

于是两个子调用都满足不变量，递归下去每个节点恰好被创建一次、挂到唯一正确的位置。归纳成立。

## 5. 完整代码（Python）

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def buildTree(self, preorder, inorder):
        # 预处理：值 -> 中序下标，把「找根位置」从 O(n) 降到 O(1)
        # 题面保证元素无重复，所以这个映射是良定义的
        pos = {val: i for i, val in enumerate(inorder)}

        # 用左闭右开区间 [lo, hi) 表示当前子树在两数组中的范围
        def build(pre_lo, pre_hi, in_lo, in_hi):
            if pre_lo >= pre_hi:          # 空区间，没有节点
                return None

            root_val = preorder[pre_lo]   # 前序第一个就是根
            root = TreeNode(root_val)

            k = pos[root_val]             # 根在中序中的位置
            left_size = k - in_lo         # 左子树节点个数

            # 左子树：前序跳过根后取 left_size 个；中序取根左边一段
            root.left = build(pre_lo + 1, pre_lo + 1 + left_size,
                              in_lo, k)
            # 右子树：前序剩下的一段；中序取根右边一段
            root.right = build(pre_lo + 1 + left_size, pre_hi,
                               k + 1, in_hi)
            return root

        return build(0, len(preorder), 0, len(inorder))
```

## 6. 复杂度

**时间 O(n)**：建哈希表遍历 `inorder` 一次，O(n)。递归中每个节点恰好被访问一次（每次调用创建一个 `TreeNode`），每次调用内部只有查表、算术、两次递归调用，都是 O(1)，所以递归总开销 O(n)。合起来 O(n)。对比暴力版：定位根是 O(区间长度)，链状树时每层区间几乎不缩小，累加成 O(n²)——哈希表消掉的正是这一项。

**空间 O(n)**：哈希表存 n 个键值对，O(n)；递归栈深度最坏是链状树 O(n)、最好平衡树 O(log n)，取最坏 O(n)；返回的树本身占 n 个节点，O(n)。三项都是 O(n)，所以总空间 O(n)。注意递归栈那项是「深度」不是「节点数」，平衡时是 log n，但复杂度按最坏情况写。

## 7. 边界与反例（至少 4 条）

1. **单节点** `preorder=[-1], inorder=[-1]` → 返回 `[-1]`。容易错在：递归终止条件写成 `pre_lo > pre_hi`（闭区间写法）却配了开区间边界，导致空数组时多建一个节点或越界。用左闭右开 + `pre_lo >= pre_hi` 判断最稳。

2. **纯左链** `preorder=[3,2,1], inorder=[1,2,3]` → 返回 `[3,2,null,1]`（3 的左是 2，2 的左是 1）。容易错在：以为「前序第二个一定是左孩子」就无脑挂左边——本例确实如此，但换成纯右链 `preorder=[1,2,3], inorder=[1,2,3]` 时前序第二个 `2` 是右孩子。**必须靠中序定位判断左右**，不能靠前序相邻关系猜。

3. **纯右链** `preorder=[1,2,3], inorder=[1,2,3]` → 返回 `[1,null,2,null,3]`。容易错在：`left_size = k - in_lo` 算成 0 后，右子树前序起点写成 `pre_lo + 1` 而不是 `pre_lo + 1 + left_size`，本例恰好 left_size=0 看不出问题，但一旦左子树非空就切错。

4. **左右都有且左子树非空** `preorder=[1,2,4,3], inorder=[2,4,1,3]` → 根 1，左子树 `[2,4]`（中序 `[2,4]`，前序 `[2,4]`），右子树 `[3]`。容易错在：右子树前序起点漏加 `left_size`，写成 `pre_lo+1` 会把左子树节点重复塞进右子树。

5. **两数组长度不等**：题面保证相等，但若面试官故意给不等输入，应在入口断言 `len(preorder) == len(inorder)`，否则哈希表查不到值会 `KeyError`——这其实是个隐性保护，说明「无重复 + 长度相等」是算法成立的前提，不是装饰。

## 8. 面试追问与变体（3 条）

1. **追问：如果改成「中序 + 后序」建树呢？** 思路：后序最后一个元素是根，同样用中序定位切左右，只是前序区间要从「根在前」改成「根在后」，左子树后序区间是 `[post_lo, post_lo+left_size)`、右子树是 `[post_lo+left_size, post_hi-1)`。

2. **追问：如果元素有重复怎么办？** 思路：哈希表「值→下标」不再唯一，需要改成「值→下标列表」，并在切分时按出现顺序匹配；更稳妥的是题目会额外保证某种唯一性，否则答案不唯一，要先和面试官确认题意。

3. **追问：能不能不用递归（避免栈溢出）？** 思路：用显式栈模拟递归，把 `(pre_lo, pre_hi, in_lo, in_hi, parent, is_left)` 压栈，弹出时建节点并挂到 parent 上；逻辑和递归完全同构，只是把调用栈搬到堆上。
