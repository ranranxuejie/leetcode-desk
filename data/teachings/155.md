## 1. 一句话本质

在普通栈「后进先出」的基础上，额外维护一条**与主栈同步增长/收缩的最小值历史**，使得任意时刻的栈内最小值都能 O(1) 读出。

## 2. 读完题的第一反应

**朴素解法**：只用一个 list 存数据。`push/pop/top` 都是 O(1)，但 `getMin` 每次要遍历整个栈找最小，O(n)。题目明确要求「常数时间内检索到最小元素」，所以瓶颈就在 `getMin` 上——每次调用都重新扫一遍，浪费在「重复计算同一批元素的最小值」。

**关键观察**：栈的修改只发生在**栈顶**。也就是说，栈的状态是一条「只在一端变化」的序列。当 `push(x)` 时，新的最小值只可能是 `min(旧最小值, x)`；当 `pop()` 时，被删掉的元素如果是当前最小值，那新的最小值恰好就是「删掉它之前的历史最小值」。

这句话是整个解法的支点：**当前最小值只依赖「上一个状态的最小值」和「新进来的元素」**，是一个可以随栈一起滚动的量。既然栈顶进出是同步的，那最小值的变化也可以同步记录——用一个辅助栈，每 push 一个元素就 push 一次「此刻的最小值」，每 pop 就跟着 pop 一次。这样辅助栈的栈顶永远是当前主栈的最小值。

为什么这个观察能直接导向下一步？因为它把「求全局最小」这个看似需要扫描的操作，转化成了「查辅助栈栈顶」这个 O(1) 操作。代价是每个元素多存一份最小值，空间从 O(n) 变成 O(n)（常数因子 2），时间全部 O(1)。

## 3. 从暴力到最优

**暴力版**：`getMin` 里写 `min(self.data)`。每次调用 O(n)，n 次调用最坏 O(n²)。瓶颈是「每次都从头算」。

**中间想法**：能不能只用一个变量 `cur_min` 记录最小值？push 时更新 `cur_min = min(cur_min, x)`，getMin 直接返回 `cur_min`。问题出在 pop：如果 pop 掉的正好是当前最小值，`cur_min` 就失效了——你不知道「次小值」是多少，因为之前没存。比如栈是 `[-2, 0, -3]`，`cur_min = -3`；pop 掉 -3 后，真实最小值是 -2，但变量里还是 -3，错了。**这就是单变量方案卡住的地方：它只记住了「现在」，没记住「历史」。**

**最优版**：既然 pop 需要「回退到上一个状态的最小值」，那就把每个状态的最小值都存下来——用辅助栈 `min_stack`，与主栈 `stack` 同进同出。

用示例走一遍，写出每一步两个栈的内容：

| 操作 | stack | min_stack | 说明 |
|---|---|---|---|
| 初始 | [] | [] | |
| push(-2) | [-2] | [-2] | min_stack 空，直接压 -2 |
| push(0) | [-2, 0] | [-2, -2] | min(0, -2) = -2，压 -2 |
| push(-3) | [-2, 0, -3] | [-2, -2, -3] | min(-3, -2) = -3，压 -3 |
| getMin() | 不变 | 不变 | 返回 min_stack[-1] = **-3** ✓ |
| pop() | [-2, 0] | [-2, -2] | 两个栈同时弹栈顶 |
| top() | 不变 | 不变 | 返回 stack[-1] = **0** ✓ |
| getMin() | 不变 | 不变 | 返回 min_stack[-1] = **-2** ✓ |

输出 `-3, 0, -2`，与官方示例一致。注意 pop 之后 min_stack 的栈顶自动回退成 -2，这正是单变量方案做不到的「历史回退」。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义不变量：

> 对任意时刻，若主栈 `stack = [a₀, a₁, ..., a_{k-1}]`（a₀ 为栈底），则辅助栈 `min_stack` 长度相同，且 `min_stack[i] = min(a₀, ..., aᵢ)`，即 `min_stack[i]` 是「从栈底到第 i 个元素」这段前缀的最小值。

**初始**：两栈皆空，不变量平凡成立。

**push(x)**：设原长度为 k。新主栈为 `[a₀,...,a_{k-1}, x]`。对 i < k，`min_stack[i]` 不变，仍等于对应前缀最小值（前缀没变）；对 i = k，我们压入 `min(x, min_stack[k-1])`，而 `min_stack[k-1] = min(a₀,...,a_{k-1})`，所以压入值 = `min(a₀,...,a_{k-1}, x)`，正是新前缀的最小值。不变量保持。

**pop()**：两栈同时弹出栈顶，长度都减 1，剩下的前缀和对应的 min_stack 前缀完全没动，不变量保持。

**getMin()**：由不变量，`min_stack[k-1] = min(a₀,...,a_{k-1})`，即整个栈的最小值。返回它正确。

**不会漏**：每个元素 push 时都在 min_stack 里留下了「包含它为止的前缀最小值」，所以任何时刻的全局最小都被记录在栈顶。**不会重**：getMin 只读栈顶一个值，不涉及遍历，不存在重复计算或重复计数的问题。归纳法覆盖了所有操作序列，正确性成立。

## 5. 完整代码（Python）

```python
class MinStack:
    def __init__(self):
        # 主栈：存真实数据
        self.stack = []
        # 辅助栈：与主栈同步，栈顶始终是当前主栈的最小值
        self.min_stack = []

    def push(self, value: int) -> None:
        self.stack.append(value)
        # 辅助栈为空时，当前最小值就是 value 本身
        # 否则新最小值 = min(旧最小值, value)
        if not self.min_stack:
            self.min_stack.append(value)
        else:
            self.min_stack.append(min(value, self.min_stack[-1]))

    def pop(self) -> None:
        # 两个栈必须同步弹出，否则不变量被破坏
        self.stack.pop()
        self.min_stack.pop()

    def top(self) -> int:
        # 主栈栈顶就是栈顶元素
        return self.stack[-1]

    def getMin(self) -> int:
        # 辅助栈栈顶就是当前全局最小值，O(1)
        return self.min_stack[-1]


# 按题目给的调用序列做一次自测，方便直接运行验证
if __name__ == "__main__":
    ops = ["MinStack", "push", "push", "push", "getMin", "pop", "top", "getMin"]
    args = [[], [-2], [0], [-3], [], [], [], []]
    out = []
    obj = None
    for op, arg in zip(ops, args):
        if op == "MinStack":
            obj = MinStack()
            out.append(None)
        elif op == "push":
            obj.push(arg[0]); out.append(None)
        elif op == "pop":
            obj.pop(); out.append(None)
        elif op == "top":
            out.append(obj.top())
        elif op == "getMin":
            out.append(obj.getMin())
    print(out)  # 期望 [None, None, None, None, -3, None, 0, -2]
```

## 6. 复杂度

设总共调用 n 次（题面说最多 3×10⁴ 次）。

- **push**：主栈 append O(1) 均摊，辅助栈 append + 一次 `min` 比较 O(1)。合计 **O(1)**。
- **pop**：两次 list.pop() 都是尾部弹出，O(1)。合计 **O(1)**。
- **top**：读 `stack[-1]`，O(1)。
- **getMin**：读 `min_stack[-1]`，O(1)。

**空间**：主栈最多存 n 个元素 O(n)，辅助栈同样最多 n 个元素 O(n)，合计 **O(n)**。这里的 n 是「栈内元素个数峰值」，不是调用次数——因为 pop 会释放空间。没有 log n 项，因为没有任何二分/树结构。

对比暴力版：getMin 单次 O(n)，n 次调用最坏 O(n²)；本方案把每次操作都压到 O(1)，用一份额外空间换掉了重复扫描。

## 7. 边界与反例（至少 4 条）

1. **输入**：`push(5), push(5), getMin(), pop(), getMin()` → **期望**：`5, 5` → **易错点**：两个相等的最小值。若用「只在 value < 当前最小值时才压辅助栈」的变体，pop 掉一个 5 后辅助栈可能已经空了或对不上，导致 getMin 出错。本方案无条件同步压栈，天然处理重复值。

2. **输入**：`push(-2), push(0), push(-3), pop(), getMin()` → **期望**：`-2` → **易错点**：pop 掉当前最小值 -3 后，必须能「回退」到次小值 -2。单变量 `cur_min` 方案在这里返回 -3，是经典反例。

3. **输入**：`push(1), getMin(), pop(), push(2), getMin()` → **期望**：`1, 2` → **易错点**：栈被清空后再 push，辅助栈也必须从空状态重新开始。若辅助栈残留旧值，getMin 会返回 1 而不是 2。

4. **输入**：`push(-2^31), getMin()` → **期望**：`-2147483648` → **易错点**：用 `float('inf')` 或某个哨兵值初始化 `cur_min` 时，若哨兵选得比 -2^31 还小（比如某些语言用 INT_MIN 当哨兵），比较逻辑会出错。本方案辅助栈为空时直接压入 value，不依赖任何哨兵，规避了这个问题。

5. **输入**：`push(3), push(1), push(2), getMin(), pop(), getMin()` → **期望**：`1, 1` → **易错点**：pop 掉的 2 不是最小值，辅助栈栈顶应保持 1。若实现成「pop 时无条件重算最小值」，虽然结果对但退化成 O(n)，违背常数时间要求。

## 8. 面试追问与变体（3 条）

1. **追问**：能不能只用 O(1) 额外空间（不用辅助栈）实现？**思路**：存「差值」——主栈存 `value - cur_min`，配合一个 `cur_min` 变量，push 时若差值 < 0 说明出现了新最小值，更新 `cur_min`；pop 时若弹出的是负差值，用 `cur_min - 差值` 还原上一个最小值。代价是要处理整数溢出（Python 大整数无此问题，C++ 需用 long long）。

2. **追问**：如果还要支持 `getMax()` 呢？**思路**：再开一个辅助栈 `max_stack`，与 `min_stack` 完全对称地维护前缀最大值，两个辅助栈互不干扰，所有操作仍是 O(1)。

3. **追问**：如果要求 `getMin` 返回的是「最近 k 个元素的最小值」（滑动窗口最小值）呢？**思路**：这就不是栈而是单调队列问题了，用双端队列维护一个单调递增序列，队首即窗口最小值，均摊 O(1)。
