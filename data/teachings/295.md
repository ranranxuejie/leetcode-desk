## 1. 一句话本质

维护一个动态集合，使得「取中位数」这个查询能在 O(1) 时间回答，而每次插入只需要 O(log n)——本质是用**两个堆把数据按大小劈成两半，并让两半的规模差不超过 1**。

## 2. 读完题的第一反应

**朴素解法**：用一个 list 存所有数，`addNum` 直接 append（O(1)），`findMedian` 时排序再取中间（O(n log n)）。或者插入时保持有序（O(n) 挪动），查询 O(1)。

卡在哪？题面提示「最多 5×10⁴ 次调用」，如果每次 `findMedian` 都排序，最坏 5×10⁴ × 5×10⁴ log ≈ 天文数字，直接超时。瓶颈是：**每次查询都重新做了一遍「把数据分成大小两半」的工作**，而这个划分在两次插入之间几乎没变。

**关键观察**：中位数只关心「中间那个/那两个数」。也就是说，我们不需要全体有序，只需要知道**较小的一半里最大的那个**和**较大的一半里最小的那个**。而「一堆数里随时取最大/最小」正是堆的强项。于是把数据劈成两半：左半（较小的一半）用大顶堆，堆顶是左半最大值；右半（较大的一半）用小顶堆，堆顶是右半最小值。中位数只从这两个堆顶里出。

## 3. 从暴力到最优

**第一步（暴力）**：list 存全部，查询时 `sorted(arr)` 取中间。插入 O(1)，查询 O(n log n)。

**第二步（有序插入）**：用 `bisect.insort` 维持有序 list。插入 O(n)（挪元素），查询 O(1)。比第一步好，但 5×10⁴ 次插入 × 平均 2.5×10⁴ 次挪动 ≈ 10⁹，Python 里仍然危险。

**第三步（双堆）**：插入 O(log n)，查询 O(1)。这就是最优。

用示例走一遍，重点看**每次插入后两个堆的状态**。约定：`low` 是大顶堆（存较小一半，Python 用负数模拟），`high` 是小顶堆（存较大一半），并维持 `len(low) == len(high)` 或 `len(low) == len(high) + 1`。

```
初始: low = [], high = []

addNum(1):
  先压 low: low = [-1], high = []
  平衡: len(low)=1 > len(high)+1=1? 否（1 不大于 1），不动
  状态: low=[-1] (即 [1]), high=[]

addNum(2):
  2 与 low 堆顶 1 比较: 2 >= 1，压 high
  low = [-1], high = [2]
  平衡: len(low)=1, len(high)=1，差 0，不动
  状态: low=[1], high=[2]

findMedian():
  len 相等 → (low 堆顶 1 + high 堆顶 2) / 2 = 1.5   ✓

addNum(3):
  3 >= low 堆顶 1，压 high
  low = [-1], high = [2, 3]
  平衡: len(low)=1 < len(high)=2，把 high 堆顶 2 挪到 low
  low = [-1, -2] (即 [2,1]), high = [3]
  状态: low 堆顶 2, high 堆顶 3

findMedian():
  len(low)=2 > len(high)=1 → 返回 low 堆顶 2.0   ✓
```

注意第三步的「挪动」：插入后如果 `len(low) < len(high)`，就把 `high` 的最小值弹出来塞进 `low`。这一步保证了不变量，也保证了堆顶始终是「中间那两个候选」。

## 4. 正确性：为什么不会漏、不会重

用**不变量**论证。维护两条不变量：

- **不变量 A（大小关系）**：`low` 中每个元素 ≤ `high` 中每个元素。
- **不变量 B（规模关系）**：`len(low) == len(high)` 或 `len(low) == len(high) + 1`。

**插入时如何保持 A**：新元素 `num` 先和 `low` 堆顶（左半最大值）比较。若 `num <= low 堆顶`，说明它属于较小一半，压 `low`；否则压 `high`。这样压入后，被压入的堆内部仍有序，且跨堆的大小关系不被破坏（因为 `num` 落在正确的一侧）。随后若发生「挪动」，是从 `high` 弹出最小值塞进 `low`，或从 `low` 弹出最大值塞进 `high`——弹的是一侧极值、塞的是另一侧，A 依然成立。

**插入时如何保持 B**：每次插入后检查规模差，超过 1 就从元素多的堆弹一个给元素少的堆。由于每次只插入一个元素，规模差最多变成 2，挪一次就回到 0 或 1。所以 B 恒成立。

**查询为什么对**：由 A，`low` 的所有元素 ≤ `high` 的所有元素，所以全体排序后，前 `len(low)` 个就是 `low` 的元素、后 `len(high)` 个就是 `high` 的元素。由 B：
- 若 `len(low) == len(high)`，总数为偶数，中位数是第 `len(low)` 和第 `len(low)+1` 个的平均，即 `low` 最大值与 `high` 最小值之平均——正是两个堆顶。
- 若 `len(low) == len(high)+1`，总数为奇数，中位数是正中间那个，即 `low` 的最大值——正是 `low` 堆顶。

两条不变量覆盖了所有情况，不漏（每个数都进了某个堆）不重（每个数只进一个堆），查询公式与中位数定义逐一对应。

## 5. 完整代码（Python）

```python
import heapq


class MedianFinder:
    def __init__(self):
        # low: 大顶堆，存较小的一半。Python 无大顶堆，存负数模拟
        self.low = []
        # high: 小顶堆，存较大的一半
        self.high = []

    def addNum(self, num: int) -> None:
        # 1) 决定进哪个堆：与 low 堆顶（左半最大值）比较
        if not self.low or num <= -self.low[0]:
            heapq.heappush(self.low, -num)
        else:
            heapq.heappush(self.high, num)

        # 2) 平衡规模：保证 len(low) == len(high) 或 len(low) == len(high)+1
        if len(self.low) > len(self.high) + 1:
            # low 太多，把它的最大值挪给 high
            heapq.heappush(self.high, -heapq.heappop(self.low))
        elif len(self.high) > len(self.low):
            # high 太多，把它的最小值挪给 low
            heapq.heappush(self.low, -heapq.heappop(self.high))

    def findMedian(self) -> float:
        if len(self.low) == len(self.high):
            # 偶数个：两个堆顶取平均
            return (-self.low[0] + self.high[0]) / 2.0
        else:
            # 奇数个：low 多一个，堆顶就是中位数
            return float(-self.low[0])


# 按题目给的调用序列可直接运行验证
if __name__ == "__main__":
    mf = MedianFinder()
    mf.addNum(1)
    mf.addNum(2)
    print(mf.findMedian())  # 1.5
    mf.addNum(3)
    print(mf.findMedian())  # 2.0
```

> 说明：题面给的函数签名是 `Solution.solve(...) -> boolean`，但题面正文明确要求实现 `MedianFinder` 类（`addNum` / `findMedian`），示例也是按类调用。这里以题面正文和示例为准，实现 `MedianFinder`。若评测系统确实要求 `solve`，把上面类包一层即可，逻辑不变。

## 6. 复杂度

设当前元素总数为 n。

- **addNum**：一次堆比较 O(1)，一次 `heappush` 是 O(log n)（堆高 log n），最多一次「弹出+压入」也是 O(log n)。合计 **O(log n)**。这里的 log n 来自堆的层数，n 是当前堆内元素个数。
- **findMedian**：只读两个堆顶，**O(1)**。
- **空间**：两个堆合计存 n 个元素，**O(n)**。n 由 `addNum` 的调用次数贡献，最多 5×10⁴。

对比暴力：暴力每次查询 O(n log n)，双堆把「划分」这件事摊到每次插入的 O(log n) 里，查询变成 O(1)，总复杂度从 O(k·n log n) 降到 O(k log n)（k 为调用次数）。

## 7. 边界与反例（至少 4 条）

1. **只有一个元素**：`addNum(5)` → `findMedian()` 期望 `5.0`。容易错在 `findMedian` 里对 `high[0]` 取值——此时 `high` 为空，若先判 `len(low)==len(high)` 会走错分支或越界。代码里用 `if/else` 先判等长，奇数分支只碰 `low`，安全。

2. **两个相同元素**：`addNum(2), addNum(2)` → 期望 `2.0`。容易错在「相等时进哪个堆」的判断写成 `num < -low[0]` 而非 `<=`，导致两个 2 都进 `high`，触发平衡挪动，虽结果可能仍对，但若平衡逻辑写漏就会让 `low` 为空、`findMedian` 崩。用 `<=` 让相等元素稳定进 `low`，配合平衡逻辑最稳。

3. **负数**：`addNum(-1), addNum(-2), addNum(-3)` → 期望 `-2.0`。容易错在「大顶堆存负数」的取反方向搞混：`low` 里存的是 `-num`，堆顶 `-low[0]` 才是真正的最大值。若比较时忘了取负，会把大小关系整个颠倒。

4. **偶数个但两堆顶相等**：`addNum(1), addNum(1), addNum(1), addNum(1)` → 期望 `1.0`。容易错在浮点除法写成整除 `//`，得到 `1` 而非 `1.0`；题面要求 double，`/ 2.0` 保证浮点。

5. **插入顺序递减**：`addNum(5), addNum(4), addNum(3), addNum(2)` → 期望 `3.5`。容易错在只写了「`low` 太多就挪给 `high`」而漏了「`high` 太多就挪给 `low`」——递减序列会让元素持续进 `low`，若平衡只处理一个方向，`low` 会越堆越大，堆顶不再是中位数候选。

## 8. 面试追问与变体（3 条）

1. **追问：如果数据流里要支持删除任意元素，怎么改？** 思路：双堆 + 延迟删除（lazy deletion），用一个哈希表记录「待删元素」，`findMedian` 前先清理堆顶的待删元素；或改用平衡 BST / 有序容器。

2. **追问：要求返回滑动窗口内的中位数（窗口大小固定 k）？** 思路：双堆 + 延迟删除，窗口右移时加入新元素、标记移出元素，清理堆顶；复杂度 O(n log k)。这就是力扣 480。

3. **追问：数据范围很小（如 -10⁵ 到 10⁵），能不能 O(1) 查询？** 思路：用计数数组 + 维护「当前中位数指针」，插入时更新计数并微调指针，查询 O(1)，插入 O(1) 均摊（指针移动总量有界）。

## 9. 举一反三（2-3 道同类题）

- **力扣 480. 滑动窗口中位数**：和本题共同点是都用双堆维护「中间两个候选」，区别是要处理窗口移出元素的删除。
- **力扣 703. 数据流中的第 K 大元素**：共同点是「数据流 + 堆」，只是它只要第 K 大，用一个大小为 K 的小顶堆即可，比双堆更简单。
- **力扣 4. 寻找两个正序数组的中位数**：共同点是「求中位数」，但那题是静态两数组、要求 O(log(m+n))，用二分划分而非堆，可作为「中位数问题的另一种视角」对照学习。
