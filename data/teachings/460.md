## 1. 一句话本质

维护一个「按使用频率分层、每层内部按最近使用时间排序」的键值集合，使得每次淘汰都能 O(1) 地取出「频率最小层里最久没用的那个键」。

## 2. 读完题的第一反应

朴素解法很自然：用一个字典存 `key -> (value, freq, last_time)`，淘汰时扫一遍所有键，找 `freq` 最小的、再在其中找 `last_time` 最小的。`get`/`put` 本身 O(1)，但**淘汰是 O(n)**，而 `put` 在容量满时必然触发淘汰，所以 `put` 退化成 O(n)。题目明确要求 `get` 和 `put` 都 O(1) 平均，这条路直接堵死。

关键观察来自题面这句话：「使用计数最小的键是最久未使用的键」以及平局规则「去除最久未使用的键」。也就是说淘汰顺序是**先比频率、频率相同再比时间**，这是一个二维的偏序。二维比较想做到 O(1)，通常意味着要把其中一维「分桶」：把频率相同的键放进同一个桶，桶内再按时间排成一条链，那么「频率最小的桶」和「桶内最旧的键」都只要取桶头/链尾即可。

再往下想一步：频率只会 +1，不会跳变。所以一个键从频率 f 升到 f+1 时，只是从桶 f 挪到桶 f+1，不需要重新排序。这提示我们桶之间可以用一个「当前最小频率 `min_freq`」指针来定位，而不用维护有序结构——因为 min_freq 每次最多 +1（新插入的键频率为 1），或者淘汰后需要重置。这就是 O(1) 的来源。

## 3. 从暴力到最优

**暴力版**：字典 + 每次淘汰线性扫描。瓶颈在「找最小 (freq, time)」这一步是 O(n)。

**第一层优化——分桶**：建 `freq -> 双向链表` 的映射，链表里存频率恰为该值的所有键，**表头是最近使用的，表尾是最久未使用的**。淘汰时取 `min_freq` 对应链表的表尾。这一步把「找最小频率」变成读一个变量，把「同频率找最旧」变成取链表尾，都是 O(1)。

**第二层优化——min_freq 的维护**：插入新键时频率为 1，所以 `min_freq = 1`；键从 f 升到 f+1 时，如果 f 恰好等于 `min_freq` 且桶 f 空了，就让 `min_freq += 1`。因为频率只 +1，`min_freq` 也只会 +1 或重置为 1，不需要遍历。

**第三层优化——O(1) 删除链表节点**：双向链表节点要能被 O(1) 摘除，所以字典里存的不能只是 value，而要直接存**链表节点对象**（含 prev/next 指针）。这样 `key -> node` 一次哈希就能拿到节点，摘除不用遍历。

**小例子走一遍**（capacity=2，跟官方示例同一条路径，但只盯内部状态）：

初始：`freq_map = {}`，`min_freq = 0`，`key_map = {}`。

1. `put(1,1)`：key 不存在，新建节点 freq=1，插入桶 1 头部。`min_freq=1`。状态：桶1=[1]，`key_map={1:node1}`。
2. `put(2,2)`：新建 freq=1，插入桶 1 头部。桶1=[2,1]（头是 2）。`min_freq=1`。
3. `get(1)`：命中，值 1。把 node1 从桶 1 摘除，freq 变 2，插入桶 2 头部。桶1=[2]，桶2=[1]。因为桶 1 非空，`min_freq` 仍为 1。
4. `put(3,3)`：容量满，淘汰 `min_freq=1` 的桶尾 → 桶1 只有 [2]，淘汰 key=2。然后新建 key=3，freq=1 插入桶 1 头部。桶1=[3]，桶2=[1]，`min_freq=1`。
5. `get(2)`：不在 `key_map`，返回 -1。
6. `get(3)`：命中，node3 从桶 1 摘除（桶 1 空），freq 变 2 插入桶 2 头部。桶2=[3,1]。桶 1 空了且 `min_freq==1`，所以 `min_freq=2`。
7. `put(4,4)`：容量满，淘汰 `min_freq=2` 的桶尾 → 桶2 尾是 1，淘汰 key=1。新建 key=4 freq=1 插入桶 1。桶1=[4]，桶2=[3]，`min_freq=1`。
8. `get(1)`：-1。`get(3)`：命中，node3 从桶 2 摘除（桶 2 空），freq 变 3 插入桶 3。桶3=[3]，`min_freq` 原为 1（桶 1 非空），不变。`get(4)`：命中，node4 从桶 1 摘除（桶 1 空），freq 变 2 插入桶 2。桶 1 空且 `min_freq==1` → `min_freq=2`。

输出序列 `[null,null,null,1,null,-1,3,null,-1,3,4]`，与官方一致。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。维护三条不变量：

- **I1（分层完整）**：对任意在缓存中的键 k，`key_map[k].freq = f` 当且仅当 k 出现在 `freq_map[f]` 这条链表中，且只出现一次。
- **I2（桶内有序）**：每条链表从表头到表尾，是「最近使用 → 最久未使用」的顺序。
- **I3（min_freq 正确）**：`min_freq` 等于当前所有键频率的最小值（缓存非空时）。

**get/put 命中时**：把节点从桶 f 摘除、插入桶 f+1 头部。I1 由「摘除+插入」成对操作保证；I2 因为新位置是表头（最近使用），旧桶剩余节点相对顺序不变；I3 只需检查：若 f == min_freq 且桶 f 变空，则 min_freq 必须 +1——因为频率只 +1，f+1 一定存在（刚插进去），所以新的最小值就是 f+1，不会漏。

**put 未命中且满时**：淘汰 `freq_map[min_freq]` 的表尾。由 I3，min_freq 是最小频率，所以被淘汰者频率最小；由 I2，表尾是同频率中最久未使用的。两者合起来正是题面定义的「最不经常使用，平局取最久未使用」，所以**不会淘汰错**。又因为每次 put 未命中只淘汰一个、插入一个，缓存大小守恒，**不会漏淘汰也不会多淘汰**。

**put 未命中且未满时**：直接插入桶 1 头部并令 `min_freq=1`。新键频率 1 是最小的（频率至少为 1），I3 成立。

三条不变量在每次操作后都保持，归纳即得所有操作正确。

## 5. 完整代码（Python）

```python
class Node:
    __slots__ = ("key", "val", "freq", "prev", "next")
    def __init__(self, key=0, val=0, freq=1):
        self.key = key
        self.val = val
        self.freq = freq
        self.prev = None
        self.next = None


class DLinkedList:
    """带哨兵的双向链表：head 侧是最近使用，tail 侧是最久未使用。"""
    def __init__(self):
        self.head = Node()          # 哨兵，head.next 才是真正的表头
        self.tail = Node()          # 哨兵
        self.head.next = self.tail
        self.tail.prev = self.head
        self.size = 0

    def add_front(self, node):
        # 插到 head 之后 = 最近使用
        node.prev = self.head
        node.next = self.head.next
        self.head.next.prev = node
        self.head.next = node
        self.size += 1

    def remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev
        self.size -= 1

    def pop_back(self):
        # 取最久未使用的节点（tail 前一个）
        if self.size == 0:
            return None
        node = self.tail.prev
        self.remove(node)
        return node


class LFUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.key_map = {}      # key -> Node，O(1) 定位节点
        self.freq_map = {}     # freq -> DLinkedList
        self.min_freq = 0

    def _touch(self, node):
        """把 node 的频率 +1：从旧桶摘除，插入新桶头部。"""
        f = node.freq
        old_list = self.freq_map[f]
        old_list.remove(node)
        # 旧桶空了且它正是最小频率桶 → 最小频率上移
        if old_list.size == 0:
            del self.freq_map[f]
            if self.min_freq == f:
                self.min_freq = f + 1
        node.freq = f + 1
        new_list = self.freq_map.get(f + 1)
        if new_list is None:
            new_list = DLinkedList()
            self.freq_map[f + 1] = new_list
        new_list.add_front(node)

    def get(self, key: int) -> int:
        if key not in self.key_map:
            return -1
        node = self.key_map[key]
        self._touch(node)
        return node.val

    def put(self, key: int, value: int) -> None:
        if self.cap <= 0:
            return
        if key in self.key_map:
            node = self.key_map[key]
            node.val = value          # 改值
            self._touch(node)         # 频率 +1
            return
        # 未命中：先看是否要淘汰
        if len(self.key_map) >= self.cap:
            victim_list = self.freq_map[self.min_freq]
            victim = victim_list.pop_back()
            del self.key_map[victim.key]
            if victim_list.size == 0:
                del self.freq_map[self.min_freq]
        # 插入新键，频率 1
        node = Node(key, value, 1)
        self.key_map[key] = node
        lst = self.freq_map.get(1)
        if lst is None:
            lst = DLinkedList()
            self.freq_map[1] = lst
        lst.add_front(node)
        self.min_freq = 1             # 新键频率最小


class Solution:
    def solve(self, inputs, inputs2):
        # inputs: 操作名列表；inputs2: 参数列表
        out = []
        cache = None
        for op, args in zip(inputs, inputs2):
            if op == "LFUCache":
                cache = LFUCache(args[0])
                out.append(None)
            elif op == "get":
                out.append(cache.get(args[0]))
            elif op == "put":
                cache.put(args[0], args[1])
                out.append(None)
        return out
```

## 6. 复杂度

- **时间**：`get` 和 `put` 均摊 O(1)。拆开看：哈希表查找 O(1)；双向链表摘除/插入 O(1)（因为 `key_map` 直接存节点，不用遍历找前驱）；`min_freq` 的更新是常数次加减。没有 log n 项——因为频率只 +1，不需要有序结构来维护「最小频率」。
- **空间**：O(capacity)。`key_map` 存至多 capacity 个节点；`freq_map` 的桶数不超过 capacity（每个键一个频率，且频率值连续），链表节点总数也是 capacity。注意 `freq_map` 里空桶会被及时 `del`，否则桶数会随操作次数增长——这是容易忽略的空间泄漏点。

## 7. 边界与反例（至少 4 条）

1. **capacity = 0**：`put` 任何键都应无效。→ 期望：所有 `get` 返回 -1，`put` 不报错。→ 易错点：代码里 `len(key_map) >= cap` 恒成立，会去 `freq_map[min_freq]` 取桶，但 `min_freq=0` 且桶不存在，KeyError。所以开头必须 `if self.cap <= 0: return`。
2. **put 已存在的 key 只改值不新增**：`put(1,1)` 后 `put(1,99)`，容量 1。→ 期望 `get(1)` 返回 99，且不触发淘汰。→ 易错点：把「已存在」误判成「未命中」走了淘汰分支，或忘记此时也要 `_touch` 使频率 +1（题面明确 put 命中也要递增计数）。
3. **同频率平局取最久未使用**：capacity=2，`put(1,1)`、`put(2,2)`、`get(1)`、`put(3,3)`。→ 期望淘汰 key=2（频率 1，且比 1 更久没用）。→ 易错点：桶内顺序搞反（表头当最旧），会淘汰 key=1。
4. **min_freq 在桶空后必须上移**：capacity=1，`put(1,1)`、`get(1)`（freq 变 2，桶 1 空）、`put(2,2)`。→ 期望淘汰 key=1。→ 易错点：`_touch` 里忘了「旧桶空且等于 min_freq 时 min_freq += 1」，导致 `min_freq` 还停在 1，淘汰时去取空桶，崩溃或淘汰错。
5. **淘汰后 min_freq 重置**：capacity=2，`put(1,1)`、`put(2,2)`、`put(3,3)`（淘汰一个 freq=1 的），此时新键 freq=1，`min_freq` 必须重置为 1。→ 易错点：淘汰后没把 `min_freq` 设回 1，后续淘汰取错桶。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求 get/put 严格 O(1) 最坏而非均摊？** 思路：哈希表本身在极端哈希冲突下是 O(n)，可换成开放寻址或说明「平均」的前提；链表部分已是严格 O(1)，瓶颈只在哈希。
2. **追问：改成「按访问次数淘汰，但次数相同时淘汰最近最少使用（LRU 语义反过来）」？** 思路：只改桶内链表方向——表头放最久未使用，淘汰取表头即可，其余结构不变。
3. **追问：如何支持「批量提升某频率段所有键的频率」？** 思路：引入懒标记（lazy tag）挂在桶上，查询时再下推，类似并查集的路径压缩思想，避免逐个搬移。

## 9. 举一反三（2-3 道同类题）

- **146. LRU 缓存**：本题的退化版，只有「时间」一维，用一条双向链表 + 哈希即可，是理解本题桶内链表的前置。
- **432. 全 O(1) 的数据结构**：同样是「频率分桶 + 双向链表」，但要求取最大/最小频率的字符串，桶之间需要有序，是本题的加强版。
- **LFU 的变体（如按访问次数 + 过期时间淘汰）**：把「时间」换成「过期时间戳」，桶内链表改成按时间戳排序的小顶堆或有序链表，核心仍是「分桶 + 桶内有序」。
