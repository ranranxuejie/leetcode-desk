## 1. 一句话本质

在「完全二叉树」这个强约束下，用**结构信息**（左右子树高度）代替**逐个遍历**，把 O(n) 的计数压到 O(log²n)。

## 2. 读完题的第一反应

**朴素解法**：递归 `1 + countNodes(left) + countNodes(right)`，每个节点访问一次，时间 O(n)、空间 O(树高)。对 5×10⁴ 个节点完全能过——但题目「进阶」明确说：能不能更快？这句话就是在提示你：**完全二叉树的结构里藏着比 n 更少的信息量**。

**关键观察**：完全二叉树只有「最后一层」可能缺节点，且缺的都在右边。这意味着——对任意一个节点，它的**左子树和右子树中，至少有一棵是满二叉树**。为什么？设整棵树高度为 h（根到最深叶子的边数）。看根的左右子树：

- 若左子树高度 = h-1 且右子树高度 = h-1，两边都满（因为右子树也到了最底层）；
- 若左子树高度 = h-1 而右子树高度 = h-2，则左子树满、右子树不满；
- 左子树高度不可能小于右子树高度（完全二叉树最后一层靠左，左边只会更高或相等）。

所以每层递归里，**必有一棵子树是满的**。满二叉树节点数 = 2^height − 1，O(1) 算出来，不用进去数。这就是把 O(n) 砍成 O(log²n) 的入口。

## 3. 从暴力到最优

**暴力**：每个节点都进去数一遍。瓶颈在于「满子树」也被逐节点展开，浪费。

**优化**：每次递归只对**不满的那棵子树**继续递归，满的那棵直接套公式。

具体怎么判断哪棵满？分别求左右子树的**最左路径高度**（一路往左走到底）：

- `lh = height(root.left)`，`rh = height(root.right)`；
- 若 `lh == rh`：左子树是满的（它一直填到了最底层），节点数 `2^lh − 1`，加上根，再加上递归求右子树；
- 若 `lh > rh`：右子树是满的（高度 rh 且完全二叉树保证它填满），节点数 `2^rh − 1`，加上根，再加上递归求左子树。

**小例子走一遍**：`root = [1,2,3,4,5,6]`，结构是

```
        1
       / \
      2   3
     / \ /
    4  5 6
```

- 根 1：`lh = height(2) = 2`（2→4），`rh = height(3) = 1`（3→6）。`lh > rh`，右子树满，`2^1 − 1 = 1` 个（节点 3）。结果 = 1（根）+ 1（右满）+ 递归左子树。
- 节点 2：`lh = height(4) = 1`，`rh = height(5) = 1`，相等，左子树满，`2^1 − 1 = 1`（节点 4）。结果 = 1 + 1 + 递归右子树(5)。
- 节点 5：叶子，`lh = rh = 0`，左满 `2^0 − 1 = 0`，结果 = 1 + 0 + 递归右(null)=0 → 1。
- 回代：节点 2 得 1+1+1 = 3；根得 1+1+3 = **6**。✓

注意递归深度只有树高 O(log n)，每层求高度又花 O(log n)，所以总时间 O(log²n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说：对任意节点 u，`count(u)` 返回以 u 为根的子树节点数。

**归纳假设**：对 u 的所有后代成立。**归纳步骤**分两种情形，且两种情形**互斥且穷尽**（因为完全二叉树保证 `lh ≥ rh`，只可能是 `lh == rh` 或 `lh > rh`）：

- **情形 `lh == rh`**：左子树高度等于右子树高度，说明左子树的最深叶子到达了整棵子树的最底层，而完全二叉树在该层「靠左填满」，故左子树是满二叉树，节点数恰为 `2^lh − 1`。右子树是否满未知，交给递归。计数 = 1 + (2^lh−1) + count(right)，**无遗漏**（根、左、右三部分不交）**无重复**（三部分互不相交）。
- **情形 `lh > rh`**：右子树高度比左子树矮一层，说明右子树的最底层就是整棵子树的最底层且已填满（否则左子树不会更高），故右子树满，节点数 `2^rh − 1`。左子树交给递归。同理无漏无重。

两种情形都只把「满的那棵」用公式一次算清、把「可能不满的那棵」递归下去，归纳成立。**关键前提**是「完全二叉树 ⇒ lh ≥ rh 且必有一棵满」，这个前提由题面保证，不是我们额外假设的。

## 5. 完整代码（Python）

```python
class Solution:
    def countNodes(self, root) -> int:
        if root is None:
            return 0

        # 求以 node 为根的子树高度：一路往左走到底的边数
        # 完全二叉树里「最左路径」就是这棵子树的最大深度
        def height(node) -> int:
            h = 0
            while node is not None:
                h += 1
                node = node.left
            return h

        lh = height(root.left)
        rh = height(root.right)

        if lh == rh:
            # 左子树是满的：2^lh - 1 个节点，加上根，再递归右子树
            return (1 << lh) + self.countNodes(root.right)
        else:
            # lh > rh：右子树是满的：2^rh - 1 个节点，加上根，再递归左子树
            return (1 << rh) + self.countNodes(root.left)
```

说明：`1 << h` 就是 `2^h`，比 `2 ** h` 快且直观。`(1 << lh) + count(right)` 等价于 `1 + (2^lh - 1) + count(right)`，把「根」和「满子树」合并成一项，少一次加法。

## 6. 复杂度

- **时间 O(log²n)**：递归深度 = 树高 = O(log n)（完全二叉树高度不超过 ⌊log₂n⌋+1）。每一层递归里调用 `height` 两次，每次沿最左路径走 O(log n) 步。所以总时间 = O(log n) 层 × O(log n) 每层 = **O(log²n)**。这里的 n 来自节点总数，log n 来自树高。
- **空间 O(log n)**：递归栈深度等于树高 O(log n)；`height` 是迭代的，不额外占栈。没有开辟与 n 同阶的数组。

对比暴力 O(n)：n = 5×10⁴ 时 log²n ≈ 15² = 225 量级，差距明显。

## 7. 边界与反例（至少 4 条）

1. **`root = []`（空树）** → 期望 0 → 容易错在没写 `if root is None` 就访问 `root.left`，直接 `AttributeError`。
2. **`root = [1]`（单节点）** → 期望 1 → 容易错在 `height(None)` 返回 0 时把 `1 << 0 = 1` 当成「左子树有 1 个节点」，实际左子树为空。代码里 `lh = rh = 0`，走 `lh == rh` 分支得 `(1<<0) + count(None) = 1 + 0 = 1`，正确；但若把 `height` 写成返回边数而非节点数，就会差 1。
3. **完美满二叉树，如 `[1,2,3,4,5,6,7]`** → 期望 7 → 容易错在每层都 `lh == rh` 一直递归右子树，虽然结果对，但若误判成 `lh > rh` 分支会算错。验证：根 `lh=rh=2`，`(1<<2)+count(3)`；节点 3 `lh=rh=1`，`(1<<1)+count(7)=2+1=3`；根得 4+3=7。✓
4. **最后一层只填了最左一个，如 `[1,2,3,4]`** → 期望 4 → 根 `lh = height(2) = 2`（2→4），`rh = height(3) = 1`，`lh > rh`，右子树满 `(1<<1)=2`（节点 3 及其空？注意 `2^1−1=1`，加根共 2），递归左子树得 2，总 2+2=4。✓ 容易错在把 `lh > rh` 时误以为左子树满。
5. **`height` 用「往右走」求高度** → 完全二叉树右路径可能比左路径短，会低估高度，导致 `2^h − 1` 算少。必须走**最左**路径。

## 8. 面试追问与变体（3 条）

1. **追问：如果树不是完全二叉树，还能 O(log²n) 吗？** 思路：不能，结构信息没了，只能 O(n) 遍历；或退化为「求普通二叉树节点数」。
2. **追问：不用递归，改成迭代怎么写？** 思路：用 while 循环维护当前节点和累计答案，每轮判断 `lh == rh` 后把满子树节点数累加、把当前指针移到不满的那棵子树，直到 null。
3. **追问：如果要求返回「最后一层的节点数」而不是总数？** 思路：先求总高度 h，总数减去前 h 层满节点数 `2^h − 1`，即最后一层个数；或二分最后一层的位置（配合位运算判断第 k 个位置是否存在）。
