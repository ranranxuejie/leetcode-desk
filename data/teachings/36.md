## 1. 一句话本质

判断一个 9×9 的字符矩阵中，**已填入的数字在「行、列、3×3 宫」三类约束下是否各自无重复**——注意它只做「查重」，不做「求解」。

## 2. 读完题的第一反应

朴素解法：对每一行、每一列、每一个 3×3 宫，各自收集其中出现的数字，再检查有没有重复。比如第 r 行，用一个列表存下所有非 `.` 的字符，然后两两比较或排序后看相邻是否相等。

它卡在哪？**同一个格子会被检查三次**（一次作为行元素、一次作为列元素、一次作为宫元素），而且每次检查内部还要再做一次「查重」。如果查重靠两两比较，单条线是 O(9²)，总共 27 条线，虽然 9 是常数、实际也能过，但这是「用三重循环硬怼」的写法，面试官一眼看出你没抓住结构。

关键观察：**「有没有重复」这件事，天然适合用集合/哈希表来回答，而不是排序或两两比较。** 更进一步——我们不需要「先分组、再查重」，可以**一边遍历格子、一边把数字登记到它所属的行集合、列集合、宫集合里**；一旦某次登记发现「这个集合里已经有它了」，立刻返回 false。这样每个格子只被访问一次，重复检测是 O(1) 的。

那 3×3 宫的编号怎么算？这是本题唯一需要动点脑筋的地方。给定格子 `(r, c)`，它属于第 `r // 3` 行的大宫、第 `c // 3` 列的大宫，所以宫编号可以写成 `(r // 3) * 3 + (c // 3)`，取值 0~8。这个式子把二维的「第几行宫、第几列宫」压成了一维下标，后面就能和行、列一样用数组存集合。

## 3. 从暴力到最优

**第一步：分组 + 集合查重。** 建 9 个行集合、9 个列集合、9 个宫集合。遍历每个格子，若是数字 d：

- 行集合 `rows[r]` 里已有 d → 无效；
- 否则加入；
- 列、宫同理。

以示例 2 的左上角宫为例走一遍。该宫覆盖 `(0,0)~(2,2)`，按行优先遍历：

| 格子 | 字符 | rows 变化 | cols 变化 | boxes 变化 |
|---|---|---|---|---|
| (0,0) | '8' | rows[0]={8} | cols[0]={8} | boxes[0]={8} |
| (0,1) | '3' | rows[0]={8,3} | cols[1]={3} | boxes[0]={8,3} |
| (1,0) | '6' | rows[1]={6} | cols[0]={8,6} | boxes[0]={8,3,6} |
| (2,1) | '9' | rows[2]={9} | cols[1]={3,9} | boxes[0]={8,3,6,9} |
| (2,2) | '8' | rows[2]={9,8} | cols[2]={8} | **boxes[0] 已有 8 → 返回 false** |

注意 (2,2) 这个 8：它在第 2 行是第一次出现、在第 2 列也是第一次出现，**只有宫集合暴露了冲突**。这正好解释了示例 2 为什么错——单看行列都「合法」，错在宫内重复。这也说明三类集合缺一不可。

**第二步：把集合换成位掩码（可选优化）。** 数字只有 1~9，可以用一个整数的低 9 位表示「哪些数字出现过」：`mask |= 1 << d`，判断重复就是 `mask & (1 << d)` 非零。好处是省掉哈希开销、常数更小；坏处是可读性略降。面试里写集合版本完全够，位掩码版本可以作为「我知道还能更快」的加分项提一句。

**瓶颈是怎么被消掉的：** 暴力法每条线独立查重、格子被重复访问；一次遍历 + 增量登记，把「分组」和「查重」合并成同一个动作，每个格子 O(1)，总 O(81)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义遍历到第 k 个格子之后的不变量：

> 对任意行 r、列 c、宫 b，`rows[r]`、`cols[c]`、`boxes[b]` 恰好等于「前 k 个格子中、落在该行/列/宫里且非 `.` 的数字集合」，且此前未返回 false。

- **初始**：k=0，所有集合为空，不变量成立。
- **保持**：处理第 k+1 个格子 `(r,c)`，字符为 d。若 d 是 `.`，不变量显然保持。若 d 是数字，我们检查 `d ∈ rows[r]`：若在，说明前 k 个格子里已有一个 d 落在第 r 行，加上当前这个就构成行内重复，返回 false 是正确的；若不在，把 d 加入 `rows[r]`，此时 `rows[r]` 正好等于「前 k+1 个格子中落在第 r 行的数字集合」，列、宫同理。不变量保持。
- **终止**：遍历完 81 个格子仍未返回 false，由不变量知：任意行/列/宫内，所有已填数字构成的集合没有重复元素（因为每次加入前都检查过「不在集合中」）。这正是题目要求的三条规则，故返回 true 正确。

**不会漏**：三类约束各有一个集合在维护，每个格子都同时登记进三个集合，任何一处重复都会在「加入前检查」时被捕获。
**不会重**：每个格子只处理一次，且「检查 + 加入」是原子的，不会把同一个数字重复计入同一集合（重复的那次会直接返回）。

## 5. 完整代码（Python）

```python
class Solution:
    def isValidSudoku(self, board: list[list[str]]) -> bool:
        # 9 个行集合、9 个列集合、9 个宫集合
        rows = [set() for _ in range(9)]
        cols = [set() for _ in range(9)]
        boxes = [set() for _ in range(9)]

        for r in range(9):
            for c in range(9):
                ch = board[r][c]
                if ch == '.':
                    continue  # 空格不参与任何约束

                # 宫编号：把「第几行宫、第几列宫」压成一维 0~8
                b = (r // 3) * 3 + (c // 3)

                # 三类约束任一冲突，立即判无效
                if ch in rows[r] or ch in cols[c] or ch in boxes[b]:
                    return False

                # 登记到三个集合
                rows[r].add(ch)
                cols[c].add(ch)
                boxes[b].add(ch)

        return True  # 81 个格子全部登记完且无冲突
```

位掩码版本（可选，逻辑等价，常数更小）：

```python
class Solution:
    def isValidSudoku(self, board: list[list[str]]) -> bool:
        rows = [0] * 9
        cols = [0] * 9
        boxes = [0] * 9
        for r in range(9):
            for c in range(9):
                ch = board[r][c]
                if ch == '.':
                    continue
                bit = 1 << (ord(ch) - ord('1'))  # '1'->bit0 ... '9'->bit8
                b = (r // 3) * 3 + (c // 3)
                if (rows[r] & bit) or (cols[c] & bit) or (boxes[b] & bit):
                    return False
                rows[r] |= bit
                cols[c] |= bit
                boxes[b] |= bit
        return True
```

## 6. 复杂度

设棋盘边长为 N（本题 N=9，格子数 N²）。

- **时间 O(N²)**：外层双重循环恰好访问 N² 个格子，每个格子做常数次集合查询与插入（哈希集合均摊 O(1)）。本题 N=9，即 81 次操作。**没有 log 项**——因为查重靠哈希而非排序/二分。
- **空间 O(N²)**：27 个集合，每个集合最多装 9 个元素，总元素数不超过 81，即 O(N²)。位掩码版本是 27 个整数，O(N) 个机器字，但按「存了多少信息」算仍是 O(N²) 量级的上界；严格说位掩码是 O(N) 个整数。

注意：N 是题目给定的常数 9，所以实际是 O(1)；上面用 N 表达是为了说明「如果推广到 N×N 数独」时的增长趋势。

## 7. 边界与反例（至少 4 条）

1. **全空棋盘**（81 个 `.`）→ 期望 true → 容易错在：把 `.` 也当成一个「值」登记进集合，导致第二个 `.` 就判重复。代码里 `if ch == '.': continue` 必须写。
2. **示例 2 的棋盘**（左上角宫两个 8）→ 期望 false → 容易错在：只检查了行和列，漏掉宫检查，于是返回 true。这正是「三类集合缺一不可」的反例。
3. **某行有两个相同数字、但列和宫都干净**，例如把示例 1 的 `board[0][0]` 改成 `'3'`（与 `board[0][1]` 的 `'3'` 同行）→ 期望 false → 容易错在：只维护了宫集合，漏了行集合。
4. **棋盘本身不可解但局部合法**，例如示例 1 的棋盘（输出 true）→ 期望 true → 容易错在：把「数独是否有效」误解成「数独是否有解」，去写回溯求解器，既超时又答错。题面明确说「不一定是可解的」。
5. **某列重复**：把示例 1 的 `board[1][0]` 从 `'6'` 改成 `'5'`（与 `board[0][0]` 的 `'5'` 同列）→ 期望 false → 容易错在：行列下标写反，`cols[c]` 写成 `cols[r]`。

## 8. 面试追问与变体（3 条）

1. **追问：如果棋盘是 N×N、宫是 √N×√N，代码怎么改？** 思路：把硬编码的 9、3 换成参数 N 和 `int(N**0.5)`，宫编号公式 `(r // k) * k + (c // k)` 不变，集合数量改为 N 个。
2. **追问：能不能只用一个集合，把「行/列/宫」编码进字符串？** 思路：把每个数字登记为三个键，如 `f"row{r}-{d}"`、`f"col{c}-{d}"`、`f"box{b}-{d}"`，统一塞进一个 set，插入前判断是否已存在。空间常数更小，但字符串拼接有开销。
3. **追问：如果要求「返回第一个冲突的位置」而不只是布尔值？** 思路：把 `return False` 改成记录 `(r, c, 冲突类型)` 并返回；由于是首次冲突即返回，天然就是「按行优先顺序的第一个冲突」。
