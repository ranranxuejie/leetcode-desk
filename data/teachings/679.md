## 1. 一句话本质

在 4 个数字的所有「两两合并」顺序与所有运算符选择构成的空间里，搜索是否存在一棵求值结果为 24 的表达式树。

## 2. 读完题的第一反应

**朴素解法**：枚举 4 个数的全排列（4! = 24 种），枚举 3 个运算符位置（4³ = 64 种），再枚举 5 种括号结构（Catalan 数 C₃ = 5），总共 24 × 64 × 5 = 7680 种表达式，逐个求值看是否等于 24。

这个规模看起来很小，卡在哪？卡在**括号结构枚举本身不好写**：5 种括号结构要手写分支，而且一旦题目从 4 个数变成 n 个数，括号结构数量是第 n−1 个 Catalan 数，指数级爆炸，手写枚举根本不可维护。更关键的是，这种「先枚举结构再填数」的思路把「数字」和「运算顺序」割裂开了，写出来的代码又长又容易漏。

**关键观察**：任何合法的 24 点表达式，本质上都是「每次从当前数字集合里挑两个数，做一次运算，把结果放回集合」，重复 3 次后集合只剩一个数。比如 `(8-4)*(7-1)`：先挑 8 和 4 得 4，集合变 `{4,7,1}`；再挑 7 和 1 得 6，集合变 `{4,6}`；最后 4*6=24。这个视角下，**不需要预先知道括号结构**——括号结构被「挑哪两个数先算」这个动作自动决定了。于是问题变成：对当前数字列表，枚举所有「选两个数 + 选一个运算符」的分支，递归下去，直到只剩一个数时判断是否等于 24。

这个观察之所以能直接导向解法，是因为它把「结构枚举」转化成了「状态转移」：状态就是当前剩下的数字集合，转移就是一次二元运算。搜索空间从「排列 × 运算符 × 括号」变成了「每层选一对数 × 4 种运算符」，天然覆盖所有表达式树。

## 3. 从暴力到最优

**第一步：从「枚举括号」到「枚举合并」**。以上面 `[4,1,8,7]` 为例走一遍递归：

- 初始 `nums = [4,1,8,7]`
- 选 (8,4)，做减法得 4 → `nums = [4,7,1]`（注意 8-4 和 4-8 都要试，因为减法不交换）
- 选 (7,1)，做减法得 6 → `nums = [4,6]`
- 选 (4,6)，做乘法得 24 → `nums = [24]`，命中，返回 true

对比暴力法：暴力法要先决定「最外层是乘法，左子树是 8-4，右子树是 7-1」，再逐层验证；合并法只需要在每层做「选哪两个、做什么运算」的局部决策，括号结构是**涌现**出来的，不用显式枚举。

**第二步：处理重复状态**。`[1,2,1,2]` 这种有重复数字的输入，合并过程中会产生大量相同的中间状态（比如先合并第 1、2 个 1 和先合并第 1、4 个 1 结果一样）。如果不剪枝，同一状态会被反复搜索。用一个 `set` 记录「当前数字列表（排序后）+ 已访问」即可跳过。不过 4 个数时状态总数很小，剪枝是锦上添花，不是必需——这一点在复杂度一节会算清楚。

**第三步：浮点精度**。除法是实数除法，`(8-4)*(7-1)` 这种整数运算没问题，但像 `4/(1-2/3)` 会产生 `0.333...` 这样的浮点误差，最后判断 `== 24` 可能因为 `23.999999999` 而误判。解决办法是判断 `abs(x - 24) < 1e-6`，而不是精确相等。这是本题最容易踩的坑，示例 1 的官方解释里 `4/(1-2/3)=12` 就是在暗示除法会产生非整数。

**第四步：为什么这样就够了**。合并法每层把数字个数减 1，4 个数最多 3 层，每层枚举「选一对数」（最多 C(4,2)=6 种）× 4 种运算符，分支数最多 6×4=24，三层下来 24³ ≈ 13824 个叶子，和暴力法的 7680 同量级，但代码短得多、且天然支持任意 n。这就是「从暴力到最优」的全部：没有更优的算法，只有更清晰的搜索空间表达。

## 4. 正确性：为什么不会漏、不会重

**不漏（完备性）**：用归纳法。断言：对任意数字多重集 S，`dfs(S)` 返回 true 当且仅当存在一棵以 S 中元素为叶子、内部节点为四则运算的表达式树，其值为 24。

- 基础：|S|=1 时，表达式树就是单个数字，判断 `abs(S[0]-24)<eps` 正确。
- 归纳：|S|=k>1 时，任何合法表达式树的根节点必然把 S 划分成两个非空子集 S₁、S₂（左子树和右子树的叶子集合），根运算为 op，值为 `val(S₁) op val(S₂)`。我们的循环枚举了所有「选两个数 a,b」——注意这里选的是两个**元素**而非两个子集，但递归下去后，a 和 b 合并成的结果会和剩余元素继续合并，等价于枚举了所有划分。更严格地说：任何二叉树的最深一层必有两个兄弟叶子，它们对应 S 中某两个元素 a、b，先合并 a、b 不改变最终表达式的值（结合律意义下，这是「合并顺序可交换」的交换论证）。所以先合并任意一对再递归，不会漏掉任何表达式树。

**不重（无重复计数）**：严格说合并法**会**重复搜索同一表达式（比如 `(a+b)+c` 和 `a+(b+c)` 在合并顺序上不同但值相同），但重复不影响正确性，只影响效率。用 `set` 记录已访问的数字列表（排序后）可以消除大部分重复。注意：**不能**因为「a+b 和 b+a 一样」就只试一种顺序——加法和乘法可以，但减法和除法不行，`a-b ≠ b-a`，所以代码里对 `-` 和 `/` 要两种顺序都试。

## 5. 完整代码（Python）

```python
class Solution:
    def judgePoint24(self, cards: list[int]) -> bool:
        EPS = 1e-6

        def dfs(nums: list[float]) -> bool:
            # 只剩一个数：判断是否等于 24（浮点容差）
            if len(nums) == 1:
                return abs(nums[0] - 24) < EPS

            n = len(nums)
            # 枚举所有「选两个数」的组合（i < j，避免同一对选两次）
            for i in range(n):
                for j in range(i + 1, n):
                    a, b = nums[i], nums[j]
                    # 剩余数字：除了 i、j 之外的全部
                    rest = [nums[k] for k in range(n) if k != i and k != j]

                    # 枚举 4 种运算；减法和除法要试两个方向
                    candidates = [a + b, a * b, a - b, b - a]
                    if abs(b) > EPS:
                        candidates.append(a / b)
                    if abs(a) > EPS:
                        candidates.append(b / a)

                    for val in candidates:
                        # 把运算结果放回集合，递归下一层
                        if dfs(rest + [val]):
                            return True
            return False

        return dfs([float(x) for x in cards])
```

关键逻辑说明：

- `dfs` 的参数是「当前剩余数字列表」，每层减少一个元素，天然对应表达式树的一层。
- `i < j` 的双重循环保证每对数字只被选一次；`rest` 用列表推导排除 i、j 两个下标，注意不能用 `remove`（有重复值时会删错）。
- `candidates` 里加减乘各一个，但 `a-b` 和 `b-a` 都放进去；除法同理，且要防除零（`abs(b) > EPS` 而不是 `b != 0`，因为浮点下极小值也应视为零）。
- 递归返回 true 立即短路，不继续搜。

## 6. 复杂度

**时间**：设数字个数为 n（本题 n=4）。每层枚举 C(n,2) 对数字 × 最多 6 种运算结果（加、乘、减两向、除两向），下一层规模 n−1。递推 T(n) = C(n,2)·6·T(n−1)，展开得 T(n) = 6^(n−1) · ∏_{k=2}^{n} C(k,2)。n=4 时：C(4,2)=6，C(3,2)=3，C(2,2)=1，乘上 6³=216，得 216 × 18 = 3888 次递归调用量级（实际因短路更少）。一般形式是 O(6^(n−1) · (n!)²/...) 这种超指数，但 n 固定为 4，是常数。**注意**：这里没有 log n 项，因为不涉及排序或二分；如果加了 `set` 去重，状态数上界是「所有可能的中间数字多重集」，仍是常数级。

**空间**：递归深度最多 n−1 = 3 层，每层 `rest + [val]` 新建一个长度 ≤ n 的列表，栈空间 O(n²)（每层列表长度递减，总和 n+(n−1)+...+1）。若加 `set` 去重，额外 O(状态数) 空间，本题状态数很小。总体 O(n²)，n=4 时是常数。

## 7. 边界与反例（至少 4 条）

1. **输入 `[4,1,8,7]` → 期望 true**。容易错在：只试 `a-b` 不试 `b-a`，就会漏掉 `8-4=4` 这个方向（如果先选的是 4 和 8，`4-8=-4` 走不通）。必须两个方向都试。

2. **输入 `[1,2,1,2]` → 期望 false**。容易错在：用 `list.remove` 删除已选数字时，两个 1 会被删错位置，导致 `rest` 里剩下不该剩的数，可能误判为 true。必须用下标排除。

3. **输入 `[3,3,8,8]` → 期望 true**（`8/(3-8/3)=24`）。容易错在：浮点精度。`8/3=2.666...`，`3-2.666...=0.333...`，`8/0.333...=24.000...`，若用 `== 24` 可能因 `23.999999` 判 false。必须用 `abs(x-24) < 1e-6`。

4. **输入 `[1,1,1,1]` → 期望 false**。容易错在：误以为可以构造 `(1+1+1+1)!` 之类，但题目只允许二元四则运算，且禁止一元负号。另外注意 `1/1/1/1=1`，怎么组合都到不了 24，代码应正确返回 false。

5. **输入 `[0,0,0,0]`**（虽然题面说 1~9，但作为防御性测试）→ 期望 false。容易错在：除法防零只写了 `b != 0`，但 `a/b` 中 a 也可能为 0，`0/0` 在浮点下是 nan，`abs(nan-24)<eps` 为 false，不会误判，但会产生 nan 传播，建议用 `abs(b) > EPS` 显式跳过。

## 8. 面试追问与变体（3 条）

1. **追问：如果 cards 长度不是 4，而是任意 n，怎么做？** 思路：合并法代码完全不用改，只是复杂度变成超指数，n 稍大就跑不动；可以加记忆化（`set` 存排序后的元组）剪枝，或改用「枚举所有表达式树 + 动态规划」的思路（区间 DP，类似「合并石子」）。

2. **追问：如果要求返回具体的表达式字符串，而不只是 true/false？** 思路：`dfs` 的返回值从 bool 改成「表达式字符串或 None」，每次合并时把 `a`、`b` 替换成 `(a op b)` 的字符串形式，递归到底返回该字符串；注意加括号保证优先级正确。

3. **追问：如果运算符只有 `+` 和 `*`，有没有更快的判定？** 思路：只有加乘时，表达式值等于若干个数乘积的和，可以用「枚举划分 + 子集 DP」在 O(3^n) 内判定，比盲目搜索快；但本题运算符齐全，这个优化不适用。
