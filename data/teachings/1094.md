## 1. 一句话本质

把每个行程拆成「在 from 处 +num 人、在 to 处 −num 人」两个事件，问所有位置上人数的**前缀和**（即车上实时人数）是否始终不超过 capacity。

## 2. 读完题的第一反应

朴素解法：因为坐标最大到 1000，可以开一个长度 1001 的数组，对每个 trip 从 `from` 到 `to-1` 逐格累加人数，最后扫一遍看有没有超过 capacity。这个做法是对的，但每个 trip 要写 `to - from` 格，最坏 1000 个 trip × 1000 格 = 10⁶ 次写入，其实也能过（题面坐标上限 1000 就是给这个留的口子）。真正的瓶颈在于：如果坐标范围不是 1000 而是 10⁹，这个「逐格涂色」就废了。

关键观察：**我们并不关心每一公里具体是谁在车上，只关心「某个位置人数变化了多少」**。一个行程 `[num, from, to]` 对整条路线的贡献，只在 `from` 和 `to` 两个点上产生跳变——`from` 处人数 +num，`to` 处人数 −num，中间每一公里的人数完全一样。于是「区间加」被压缩成「两个端点加」，这就是差分数组的动机。再进一步，把所有端点事件按坐标排序后顺序扫描，就得到「扫描线」写法，它天然支持坐标是任意大整数。

## 3. 从暴力到最优

**第一步：逐格模拟（暴力）**

以示例 1 `trips = [[2,1,5],[3,3,7]], capacity = 4` 为例，开数组 `cnt[0..7]`：

- trip1：`cnt[1..4] += 2` → `[0,2,2,2,2,0,0,0]`
- trip2：`cnt[3..6] += 3` → `[0,2,2,5,5,3,3,0]`

扫描发现位置 3、4 处人数为 5 > 4，返回 false。正确，但每次区间加是 O(长度)。

**第二步：差分数组**

不直接维护人数，维护「人数的变化量」`diff`：`diff[from] += num`，`diff[to] -= num`。

- trip1：`diff[1] += 2, diff[5] -= 2`
- trip2：`diff[3] += 3, diff[7] -= 3`

得到 `diff = [0,2,0,3,-2,0,0,-3]`（下标 0..7）。然后从左往右做前缀和：

| 位置 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| diff | 0 | 2 | 0 | 3 | −2 | 0 | 0 | −3 |
| 前缀和（车上人数） | 0 | 2 | 2 | 5 | 3 | 3 | 3 | 0 |

位置 3 处人数 5 > 4，false。区间加从 O(长度) 降到 O(1)，总复杂度 O(坐标范围 + n)。

**第三步：扫描线（去掉坐标范围依赖）**

差分数组仍要开 1001 大小的数组并扫一遍，复杂度里带上了坐标上界。改成：把所有 `(位置, 变化量)` 事件收集起来，按位置排序，顺序累加当前人数，一旦超过 capacity 立即返回 false。

示例 1 的事件：`(1,+2), (5,−2), (3,+3), (7,−3)`，排序后 `(1,+2), (3,+3), (5,−2), (7,−3)`。扫描：

- 位置 1：cur = 0+2 = 2 ≤ 4
- 位置 3：cur = 2+3 = 5 > 4 → false

**这里有个必须讲清的细节**：同一位置可能同时有下车和上车事件。题面明确「乘客在接上新乘客之前会被放下」，所以同一位置应先处理下车（负变化）再处理上车（正变化），否则会误判超载。排序时把同一位置的负事件排在前面即可，或者更简单——先把同一位置的变化量全部累加成一个净变化，再判断。下面的代码采用「同位置合并净变化」的做法，天然规避了这个顺序问题。

## 4. 正确性：为什么不会漏、不会重

用**不变量**论证。

定义：扫描到位置 `p` 时，变量 `cur` 表示「车行驶在 `p` 这个点、且已经完成 `p` 处所有上下车之后，车上的乘客数」。

不变量：对任意位置 `p`，`cur(p) = Σ{ num_i : from_i ≤ p < to_i }`，即所有「已经上车且尚未下车」的行程人数之和。

- **初始**：`p` 小于所有 from 时，`cur = 0`，右侧求和为空，成立。
- **归纳步**：从 `p` 移到下一个事件位置 `q`，把 `q` 处所有事件净变化 `delta` 加到 `cur` 上。`delta = Σ{num_i : from_i = q} − Σ{num_i : to_i = q}`。前者正是「在 q 上车、满足 from_i ≤ q < to_i」的行程，后者正是「在 q 下车、不再满足 from_i ≤ q < to_i」的行程，其余行程的满足性不变。所以 `cur(q) = cur(p) + delta` 恰好等于新的求和，不变量保持。
- **不漏**：任意位置 `p` 的车上人数，等于「不大于 p 的最后一个事件位置」处的 `cur`（因为两个相邻事件之间人数不变），而该值在扫描中被检查过。
- **不重**：每个事件只被累加一次，`cur` 是精确求和而非上界估计。

由于 `cur` 精确等于每个位置的实时人数，检查 `cur > capacity` 就等价于「存在某位置超载」，返回 false 当且仅当无法完成所有行程。

## 5. 完整代码（Python）

```python
from typing import List

class Solution:
    def carPooling(self, trips: List[List[int]], capacity: int) -> bool:
        # 收集所有「变化事件」：位置 -> 净变化量
        # 用字典合并同一位置的多个事件，避免同位置上下车顺序问题
        delta = {}
        for num, start, end in trips:
            delta[start] = delta.get(start, 0) + num   # 上车，人数增加
            delta[end] = delta.get(end, 0) - num       # 下车，人数减少

        cur = 0  # 当前车上人数
        # 按位置从小到大扫描；同一位置已合并为净变化，无需关心先后
        for pos in sorted(delta):
            cur += delta[pos]
            # 该位置完成所有上下车后，若超载则失败
            if cur > capacity:
                return False
        return True
```

如果面试官要求不用字典、直接开数组（坐标 ≤ 1000 时更省常数）：

```python
class Solution:
    def carPooling(self, trips: List[List[int]], capacity: int) -> bool:
        diff = [0] * 1001          # 坐标上界 1000，多开一位防越界
        for num, start, end in trips:
            diff[start] += num     # 差分：起点加
            diff[end] -= num       # 差分：终点减
        cur = 0
        for d in diff:
            cur += d               # 前缀和还原实时人数
            if cur > capacity:
                return False
        return True
```

两版逻辑等价，第一版不依赖坐标上界，更通用。

## 6. 复杂度

设 `n = len(trips)`，`m` 为不同事件位置的数量（`m ≤ 2n`）。

- **时间**：收集事件 O(n)；排序 O(m log m)，`log m` 来自对事件位置排序，`m ≤ 2n` 所以是 O(n log n)；扫描 O(m)。总计 **O(n log n)**。数组版是 O(n + 坐标上界) = O(n + 1000)，因为省掉了排序。
- **空间**：字典/事件表存 O(m) = O(n) 个键值；排序时 `sorted()` 额外产生 O(m) 的列表。总计 **O(n)**。数组版是 O(坐标上界) = O(1000)，与 n 无关。

注意：`n` 来自行程条数，`log n` 只来自排序，与坐标数值大小无关——这正是扫描线相对差分数组的优势。

## 7. 边界与反例（至少 4 条）

1. **同一位置先下后上**：`trips = [[3,0,2],[2,2,4]], capacity = 3` → 期望 `true`。位置 2 处 3 人下车、2 人上车，净变化 −1，峰值是位置 0~1 的 3 人，不超载。若错误地先加上车再减下车，会算成 3+2=5 误判 false。
2. **单行程恰好满载**：`trips = [[4,0,1]], capacity = 4` → 期望 `true`。边界是「不超过」而非「小于」，`cur > capacity` 才失败，用 `>=` 会错。
3. **下车点不占座**：`trips = [[2,0,1],[2,1,2]], capacity = 2` → 期望 `true`。位置 1 处前一批下车、后一批上车，车上始终 2 人。若把区间当成闭区间 `[from, to]` 处理（`diff[to+1] -= num`），位置 1 会算成 4 人误判。
4. **多行程叠加超载**：`trips = [[2,0,3],[3,1,4],[1,2,5]], capacity = 5` → 期望 `false`。位置 2 处 2+3+1 = 6 > 5。容易错在只看单个行程是否超载，忽略叠加。
5. **空车收尾**：`trips = [[1,0,1000]], capacity = 1` → 期望 `true`。终点 1000 处人数归零，扫描结束时 `cur` 应为 0；若事件收集漏掉终点减操作，会残留人数但不影响本判断，却暴露逻辑缺陷。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回「超载发生的第一个位置」怎么办？** 思路：扫描时记录首次 `cur > capacity` 的 `pos` 直接返回，其余不变。
2. **追问：如果行程可以中途改变人数（比如某段路临时加人）？** 思路：仍用事件模型，只是每个行程拆成更多端点事件，扫描线框架不变。
3. **追问：坐标范围极大（10⁹）且 n 也很大（10⁵），还能做吗？** 思路：扫描线 O(n log n) 依然成立，因为复杂度只与事件数有关，与坐标数值无关——这正是选扫描线而非差分数组的理由。
