## 1. 一句话本质

在所有「用给定面额、每枚硬币可重复使用、总和恰好等于 amount」的硬币多重集里，找元素个数最少的那个；找不到就返回 -1。

## 2. 读完题的第一反应

**朴素解法**：枚举所有可能的硬币组合，看哪个和等于 amount 且枚数最少。这是指数级的——每层最多有 `len(coins)` 个分支，深度未知，直接爆炸。即使剪枝（和超过 amount 就停），最坏情况仍然是指数级，因为 `coins=[1]` 时深度就是 amount。

**关键观察**：题目要的是「最少枚数」，而枚数天然对应「步数」。把每个金额看成图上的一个节点，从金额 `s` 花一枚面额 `c` 的硬币走到 `s+c`，这就是一条边。于是问题变成：从节点 0 出发，到节点 amount 的**最短路径**（边权全为 1）。最短路径 → BFS。这是第一个能想到的多项式解法。

但 BFS 有个隐患：同一层里可能重复访问同一个金额，需要 visited 去重，空间是 O(amount)。再往下想一步——BFS 是按「层」推进的，第 k 层就是「用 k 枚硬币能凑出的所有金额」。如果我们只关心「凑出金额 s 最少要几枚」，那这个值只依赖比 s 小的金额（因为硬币面额 ≥ 1，凑 s 的最后一枚硬币拿掉后，剩下的金额一定 < s）。这就把问题从「图搜索」拉回到「按金额从小到大递推」——动态规划。

## 3. 从暴力到最优

**第一步：BFS 视角。** 以 `coins=[1,2,5], amount=11` 为例：

- 第 0 层：`{0}`
- 第 1 层：`{1,2,5}`
- 第 2 层：`{2,3,6,4,7,10}` → 去重后 `{2,3,4,6,7,10}`
- 第 3 层：从 `{2,3,4,6,7,10}` 各加 1/2/5，出现 11 → 答案 3。

BFS 能出答案，但每层要维护一个集合，且会重复生成大量中间金额。瓶颈在于：**同一个金额会被不同路径反复到达**，我们却只关心它第一次被到达的层数。

**第二步：把「第一次到达」记下来。** 定义 `dp[s]` = 凑出金额 s 的最少硬币数。BFS 第一次到达 s 的层数就是 dp[s]。而 BFS 的层序等价于「按 dp 值从小到大处理」，所以我们可以直接按 s 从 0 到 amount 递推：

```
dp[0] = 0
dp[s] = min over c in coins, c <= s of (dp[s-c] + 1)
```

**第三步：手算验证。** `coins=[1,2,5]`，amount=11：

| s | 候选 | dp[s] |
|---|------|-------|
| 0 | — | 0 |
| 1 | dp[0]+1 | 1 |
| 2 | dp[1]+1=2, dp[0]+1=1 | 1 |
| 3 | dp[2]+1=2, dp[1]+1=2 | 2 |
| 4 | dp[3]+1=3, dp[2]+1=2 | 2 |
| 5 | dp[4]+1=3, dp[3]+1=3, dp[0]+1=1 | 1 |
| 6 | dp[5]+1=2, dp[4]+1=3, dp[1]+1=2 | 2 |
| 7 | dp[6]+1=3, dp[5]+1=2, dp[2]+1=2 | 2 |
| 8 | dp[7]+1=3, dp[6]+1=3, dp[3]+1=3 | 3 |
| 9 | dp[8]+1=4, dp[7]+1=3, dp[4]+1=3 | 3 |
| 10 | dp[9]+1=4, dp[8]+1=4, dp[5]+1=2 | 2 |
| 11 | dp[10]+1=3, dp[9]+1=4, dp[6]+1=3 | 3 |

得到 3，和示例一致。注意 s=6 时 `dp[5]+1=2` 和 `dp[1]+1=2` 都给出 2，说明**多条路径到达同一金额是常态**，这正是 BFS 需要去重、DP 需要取 min 的原因。

**瓶颈消掉了什么**：BFS 的重复生成被「每个 s 只算一次」取代；指数枚举被「只枚举最后一枚硬币」取代。复杂度从指数降到 O(amount × len(coins))。

## 4. 正确性：为什么不会漏、不会重

**不变量**：处理完 s 之后，`dp[s]` 等于凑出金额 s 所需的最少硬币数（若凑不出则为 INF）。

**归纳证明**：

- 基础：`dp[0]=0`，凑 0 元确实需要 0 枚，成立。
- 归纳步：假设对所有 `t < s`，`dp[t]` 都正确。考虑凑出 s 的任意一个最优解，它至少有一枚硬币，取其中任意一枚面额 c（必有 `c <= s`，否则和超过 s）。拿掉这枚硬币后，剩下金额 `s-c < s`，由归纳假设 `dp[s-c]` 是凑出 `s-c` 的最少枚数。于是该最优解的枚数 = `dp[s-c] + 1`，而我们的递推枚举了所有可能的 c，取 min 后必然 ≤ 这个值。另一方面，递推产生的每个 `dp[s-c]+1` 都对应一个合法组合（`dp[s-c]` 的方案加上一枚 c），所以递推值不会小于真实最优。两边夹住，`dp[s]` 正确。

**为什么不会重**：每个 s 只被计算一次，且计算时只依赖严格更小的下标，不存在循环依赖。**为什么不会漏**：最优解的「最后一枚硬币」必在 coins 中，枚举覆盖了所有可能。

**凑不出的情况**：若所有候选都是 INF，`dp[s]` 保持 INF，最终 `dp[amount] == INF` 时返回 -1。这里 INF 不能取一个「可能被 +1 后仍小于真实答案」的值，取 `amount+1` 是安全的——因为任何合法方案最多用 amount 枚（面额最小为 1），`amount+1` 严格大于任何可行解。

## 5. 完整代码（Python）

```python
class Solution:
    def coinChange(self, coins: list[int], amount: int) -> int:
        # dp[s] = 凑出金额 s 的最少硬币数
        # 用 amount + 1 作为"无穷大"：任何可行解最多 amount 枚（面额 >= 1），
        # 所以 amount + 1 严格大于所有可行解，且 +1 后不会溢出成"看起来可行"的值
        INF = amount + 1
        dp = [INF] * (amount + 1)
        dp[0] = 0  # 凑 0 元需要 0 枚，这是递推的起点

        # 按金额从小到大递推：dp[s] 只依赖 dp[s-c]，而 s-c < s，已算好
        for s in range(1, amount + 1):
            for c in coins:
                if c <= s:  # 面额不能超过当前目标金额
                    # 候选：先用 dp[s-c] 枚凑出 s-c，再加这一枚 c
                    dp[s] = min(dp[s], dp[s - c] + 1)

        # 若仍是 INF，说明没有任何组合能凑出 amount
        return -1 if dp[amount] == INF else dp[amount]
```

外层循环是金额，内层是硬币——这个顺序保证 `dp[s-c]` 在用到时已经算完。反过来写（外层硬币、内层金额）也能过，但那是「完全背包」的写法，语义上不如「按金额递推」直观，初学建议用上面这版。

## 6. 复杂度

- **时间 O(amount × len(coins))**：外层 amount 次，内层 len(coins) 次，每次 O(1) 的 min 比较。这里 amount 贡献了线性因子，len(coins) 贡献了另一个线性因子，两者相乘。没有 log 项——因为没有排序、没有二分、没有堆。
- **空间 O(amount)**：dp 数组长度 amount+1。没有递归栈（迭代写法），没有额外集合。

对比 BFS：BFS 时间最坏也是 O(amount × len(coins))（每个金额入队一次、每次扩展 len(coins) 条边），空间 O(amount) 的队列 + visited。两者同阶，但 DP 常数更小、代码更短，且不需要处理「同一层重复入队」的细节。

## 7. 边界与反例（至少 4 条）

1. **`coins=[2], amount=3` → -1**。容易错在：dp 初始化为 0 而不是 INF，导致 `dp[3]` 被误判为 0 或某个小值。必须用 INF 初始化，且 INF 要大于任何可行解。
2. **`coins=[1], amount=0` → 0**。容易错在：循环从 1 开始，`dp[0]=0` 没显式设置，或返回时把 0 当成「没凑出」而返回 -1。`dp[0]=0` 是递推基石，必须写。
3. **`coins=[186,419,83,408], amount=6249` → 20**。容易错在：INF 取 `float('inf')` 时 `inf+1` 仍是 inf，比较没问题，但如果用 `10**9` 且 amount 很大，`dp[s-c]+1` 可能溢出或与真实解混淆。用 `amount+1` 最稳。
4. **`coins=[2], amount=1` → -1**。容易错在：内层 `if c <= s` 没写，`dp[s-c]` 下标为负，Python 会从尾部取值，得到错误结果而不报错——这是最隐蔽的坑。
5. **`coins=[1,2147483647], amount=2` → 2**。面额可以到 2^31-1，远超 amount。容易错在：没做 `c <= s` 过滤，或对 coins 做了不必要的排序/去重假设。本题不需要排序。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求输出具体的一种组合，而不只是枚数？** 思路：再开一个 `choice[s]` 记录 `dp[s]` 取到 min 时用的那枚硬币，最后从 amount 往回跳，边跳边收集。
2. **追问：如果每种硬币只能用一次（0/1 背包）？** 思路：内层金额必须**从大到小**遍历，防止同一枚硬币被重复使用；其余递推式不变。
3. **追问：如果 coins 很大（比如 10^5 种）而 amount 很小？** 思路：先过滤掉 `c > amount` 的硬币，再对剩余硬币去重；若剩余仍很多，可考虑 BFS + 双向搜索，或按面额建图跑最短路。

- **279. 完全平方数**：把 coins 换成 `1,4,9,16,...`（≤ amount 的平方数），求凑出 n 的最少个数，递推式完全一样。
- **518. 零钱兑换 II**：同样是无限制硬币，但求的是**组合数**而非最少枚数，递推从 min 改成求和，且循环顺序决定是否计重复。
- **139. 单词拆分**：把「硬币面额」换成「词典里的单词」，判断能否拼出目标串，本质是「可重复使用物品凑目标」的布尔版 DP。
