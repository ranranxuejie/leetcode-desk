## 1. 一句话本质

在数组里找一对「值相同、下标距离不超过 k」的元素——等价于问：**每个值最近两次出现的位置差，有没有一次 ≤ k**。

## 2. 读完题的第一反应

**朴素解法**：枚举所有下标对 (i, j)，i < j，检查 `nums[i] == nums[j] and j - i <= k`。这是 O(n²) 对检查，n 到 10⁵ 时是 10¹⁰ 量级，必然超时。瓶颈很清楚：**对每一对都重新比较值**，而「值是否相等」这件事被反复计算了。

**关键观察**：对某个固定的值 v，假设它出现在下标 p₁ < p₂ < p₃ < …。那么「存在一对距离 ≤ k」等价于「存在相邻两次出现 pₜ, pₜ₊₁ 满足 pₜ₊₁ − pₜ ≤ k」。为什么只需要看相邻的？因为如果 pₜ 和 pₛ（s > t+1）距离 ≤ k，那夹在中间的 pₜ₊₁ 与 pₜ 的距离只会更小，也一定 ≤ k。所以**每个值只需要记住它最近一次出现的位置**，新位置一来就和这个「最近位置」比一下即可。这就把「和所有历史位置比」压缩成「和最近一个位置比」，O(n²) 降到 O(n)。

## 3. 从暴力到最优

**第一步：暴力枚举**

```python
for j in range(n):
    for i in range(j):
        if nums[i] == nums[j] and j - i <= k:
            return True
```
内层循环对每个 j 扫了前面所有元素，O(n²)。

**第二步：只保留「最近一次位置」**

用一个字典 `last` 记录每个值上一次出现的下标。扫到 j 时，如果 `nums[j]` 在 `last` 里，就取 `last[nums[j]]` 和 j 比距离；比完把 `last[nums[j]]` 更新成 j。

用示例 1 走一遍：`nums = [1,2,3,1], k = 3`。

| j | nums[j] | last（更新前） | 距离 | 动作 |
|---|---|---|---|---|
| 0 | 1 | {} | — | last[1]=0 |
| 1 | 2 | {1:0} | — | last[2]=1 |
| 2 | 3 | {1:0,2:1} | — | last[3]=2 |
| 3 | 1 | {1:0,2:1,3:2} | 3−0=3 ≤ 3 | 返回 True |

再看示例 3：`nums = [1,2,3,1,2,3], k = 2`。

| j | nums[j] | last（更新前） | 距离 | 动作 |
|---|---|---|---|---|
| 0 | 1 | {} | — | last[1]=0 |
| 1 | 2 | {1:0} | — | last[2]=1 |
| 2 | 3 | {1:0,2:1} | — | last[3]=2 |
| 3 | 1 | {1:0,2:1,3:2} | 3−0=3 > 2 | last[1]=3 |
| 4 | 2 | {1:3,2:1,3:2} | 4−1=3 > 2 | last[2]=4 |
| 5 | 3 | {1:3,2:4,3:2} | 5−2=3 > 2 | last[3]=5 |

扫完没触发，返回 False。注意 j=3 时距离是 3 不是 2，因为 1 上一次出现在 0，中间没有别的 1——这正是「只记最近一次」的正确性依赖：如果更早的位置能成，最近的位置一定也能成。

**第三步：为什么字典就够了，不需要滑动窗口**

标签里写了「滑动窗口」，但本题其实不需要显式维护窗口。字典里存的是「每个值最近一次出现的下标」，这个下标天然就在 j 附近（如果它离 j 太远，距离检查会直接失败）。空间上字典最多存 n 个键，O(n)；时间上每个元素进出字典各一次，O(n)。如果强行用滑动窗口（维护一个大小为 k+1 的集合，进一个删一个），也能做，但需要额外处理「窗口内重复」的判断，代码更绕，收益为零。**这里要讲清楚：滑动窗口是「值域去重」的另一种视角，字典是「按下标追踪」的视角，两者等价，字典更直接。**

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。

**不变量**：在处理完下标 j 之后，对任意值 v，`last[v]` 等于 v 在 `nums[0..j]` 中**最后一次**出现的下标（若 v 未出现则不在字典里）。

**归纳证明**：
- j = 0 时，`last[nums[0]] = 0`，成立。
- 假设处理完 j−1 后不变量成立。处理 j 时，若 `nums[j]` 已在字典中，说明它之前出现过，`last[nums[j]]` 是它最后一次出现的下标（由归纳假设），我们检查 `j - last[nums[j]] <= k`；然后更新 `last[nums[j]] = j`，此时 j 是新的最后一次出现，不变量保持。若不在字典中，插入 `last[nums[j]] = j`，同样保持。

**不漏**：假设存在一对 (i, j)，i < j，`nums[i] == nums[j]` 且 `j - i <= k`。令 v = nums[i]。在扫描到 j 时，由不变量，`last[v]` 是 v 在 `nums[0..j-1]` 中最后一次出现的下标，记为 p。因为 i 是 v 的一次出现且 i ≤ j−1，所以 p ≥ i（p 是最后一次，不会早于 i）。于是 `j - p <= j - i <= k`，检查会通过，返回 True。**关键一步是 p ≥ i，这保证「最近位置」的距离不会比任何更早位置的距离更大。**

**不重**：我们只在发现满足条件时立即返回 True，不会重复计数；返回 False 意味着扫描全程没有任何一次检查通过，由上面的论证，不存在满足条件的对。

## 5. 完整代码（Python）

```python
class Solution:
    def containsNearbyDuplicate(self, nums: list[int], k: int) -> bool:
        # last[v] = v 在已扫描部分中最后一次出现的下标
        last = {}
        for j, v in enumerate(nums):
            # 若 v 之前出现过，检查与最近一次出现的距离
            if v in last and j - last[v] <= k:
                return True
            # 无论是否命中，都要把 v 的最近位置更新为 j
            # （即使刚才距离超了，更早的位置只会更远，没必要保留）
            last[v] = j
        return False
```

注意 `last[v] = j` 放在 if 外面：即使这次距离超了 k，也要更新，因为对后续的 j' 来说，j 比旧位置更近，更有可能满足条件。这是「只记最近一次」能成立的操作性保证。

## 6. 复杂度

- **时间 O(n)**：`for` 循环执行 n 次（n = len(nums)），每次做一次字典查找 `v in last`、一次字典赋值 `last[v] = j`，哈希表均摊 O(1)。所以总时间是 n × O(1) = O(n)。没有排序、没有二分，所以不出现 log n。
- **空间 O(min(n, 值域大小))**：字典最多存 n 个不同的键（每个下标最多引入一个新键），所以上界 O(n)；实际是不同值的个数。没有额外数组，没有递归栈。

对比暴力 O(n²)：n = 10⁵ 时，10¹⁰ 次比较不可接受，O(n) 是 10⁵ 次，差距是五个数量级。

## 7. 边界与反例（至少 4 条）

1. **`nums = [1], k = 0`** → 期望 False。容易错在：以为 k=0 时「自己和自己」算重复。题目要求 i ≠ j，单个元素没有对，必须返回 False。代码里 `v in last` 在 j=0 时为假，正确。
2. **`nums = [1,1], k = 0`** → 期望 False。两个 1 距离为 1 > 0，不满足。容易错在：把 `<= k` 写成 `< k` 或漏掉 k=0 的边界。代码用 `<=`，正确。
3. **`nums = [1,2,1], k = 1`** → 期望 False。两个 1 距离 2 > 1。容易错在：只检查「有没有重复」而忘了距离约束，或误以为「出现过就算」。代码检查 `j - last[v] <= k`，正确。
4. **`nums = [1,0,1,1], k = 1`**（示例 2）→ 期望 True。容易错在：j=2 时 1 与 0 距离 2 > 1 不触发，但 j=3 时 1 与 j=2 的 1 距离 1 ≤ 1 触发。如果代码在 j=2 失败后没有更新 `last[1] = 2`，j=3 时就会拿 j=3 和 j=0 比（距离 3），漏判。**这正是「失败也要更新」的考点。**
5. **`k` 大于数组长度**：如 `nums = [1,2,3,1], k = 100` → 期望 True。距离 3 ≤ 100，正常触发，代码不依赖 k 与 n 的大小关系，安全。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回所有满足条件的下标对，而不是只返回布尔值，怎么做？** 思路：字典里存「该值所有出现过的下标列表」，扫到 j 时把列表里所有满足 `j - p <= k` 的 p 都输出（因为列表有序，可以从后往前扫到不满足为止），总输出量可能 O(nk)，需要按输出规模计复杂度。
2. **追问：如果 k 很大（比如 k ≥ n），这题退化成什么？** 思路：退化成「数组是否有重复元素」（力扣 217），此时只需一个集合判断 `v in seen`，不需要存下标，空间仍是 O(n) 但常数更小。
3. **追问：如果数组是流式输入（不能存全部），只能存 O(k) 个元素，怎么做？** 思路：维护一个大小为 k+1 的滑动窗口集合（用队列 + 集合，或有序结构），每来一个新元素先查集合，再把窗口最左端元素移出。这就是标签里「滑动窗口」的真正用武之地——**当内存受限时，字典的 O(n) 空间不可接受，窗口的 O(k) 空间才是答案**。

## 9. 举一反三（2-3 道同类题）

1. **力扣 217. 存在重复元素**：本题令 k = ∞ 的退化版，共同点是「用哈希集合/字典做值到位置的映射，一次扫描判重」。
2. **力扣 220. 存在重复元素 III**：把「值相等」放宽成「值差 ≤ t」，共同点是「维护最近 k 个元素的结构」，但需要有序结构（如平衡树/桶排序）来查「是否存在值落在区间内」，是本题的严格加强版。
3. **力扣 3. 无重复字符的最长子串**：同样用「记录每个值最近出现位置」的字典，共同点是「最近位置」这个不变量驱动窗口边界移动，只是目标从「判存在」变成「求最长」。
