## 1. 一句话本质

从 0 号节点出发做一次图的可达性搜索，判断能否到达全部 n 个节点——`rooms` 就是邻接表，钥匙就是有向边。

## 2. 读完题的第一反应

**朴素想法**：模拟「拿钥匙 → 开门 → 进房间 → 再拿钥匙」的过程。但如果你没有组织好，很容易写成反复扫描：每拿到一把新钥匙就回头把整个 `rooms` 数组再扫一遍看有没有能开的门。最坏情况下每进一个房间扫一遍全表，复杂度 O(n²) 甚至更糟，n=1000 时虽然勉强能过，但这不是面试官想看的思路。

**关键观察**：题目里有两个词值得盯住——「进入一个房间，你可能会在里面找到一套**不同的**钥匙」和提示里的「所有 `rooms[i]` 的值**互不相同**」。这两条合起来说明：**每个房间最多被进入一次，每把钥匙最多被处理一次**。既然如此，进入房间这件事天然是「一次性」的，我们只需要一个集合记录「哪些房间已经进过」，然后从 0 号房间开始，把能到达的房间不断加入这个集合，直到没有新房间可加为止。

这个「不断扩张已访问集合」的结构，正是图遍历（DFS/BFS）的标准形态。想到这一步，题目就从「模拟开门」变成了「从起点做可达性搜索」。

## 3. 从暴力到最优

**暴力版**：维护 `visited` 集合，循环：遍历 `visited` 里每个房间的钥匙，若钥匙对应的房间未访问就加入 `visited`；如果某一轮 `visited` 大小没变就停止。每轮都要重新扫一遍所有已访问房间的钥匙列表，轮数最多 n 轮，总代价 O(n × 总钥匙数)，最坏 O(n × 3000)。

**瓶颈在哪**：已经处理过的房间，它的钥匙列表被反复扫描了很多次。但一个房间的钥匙只需要被展开一次——展开后它的所有钥匙就永久进入了「待处理」状态。

**消掉瓶颈**：把「待处理的钥匙」放进一个栈（或队列），每次弹出一把钥匙：如果它对应的房间没进过，就标记进过、并把该房间的钥匙全部压栈。这样每个房间的钥匙列表恰好被展开一次。

**小例子走一遍**，用示例 2：`rooms = [[1,3],[3,0,1],[2],[0]]`

用栈实现 DFS：

| 步骤 | 栈（待处理钥匙） | visited | 说明 |
|---|---|---|---|
| 初始 | `[]` | `{0}` | 0 号房间免费进入 |
| 展开 0 | `[1,3]` | `{0}` | 压入 0 的钥匙 |
| 弹出 3 | `[1]` | `{0,3}` | 3 未访问，进入；3 的钥匙 `[0]` 中 0 已访问，不入栈 |
| 弹出 1 | `[]` | `{0,3,1}` | 1 未访问，进入；1 的钥匙 `[3,0,1]` 全部已访问，不入栈 |
| 栈空 | `[]` | `{0,1,3}` | 结束 |

`len(visited) = 3 ≠ 4`，返回 `false`。2 号房间始终没被任何钥匙指向可达路径，正确。

对比示例 1 `[[1],[2],[3],[]]`：栈依次弹出 1、2、3，visited 涨到 `{0,1,2,3}`，大小等于 4，返回 `true`。

注意一个细节：**入栈时机**。上面表格里我是在「弹出时」才判断是否访问过，而不是「压入时」就标记。两种写法都对（因为钥匙互不相同，同一房间最多被压入一次），但更稳妥的写法是**压入时就标记 visited**，避免同一房间被多个房间的钥匙重复压栈。下面代码采用后者。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在算法执行的任意时刻，`visited` 恰好等于「从 0 号房间出发、经过已展开房间的钥匙所能到达的房间集合」，且 `stack` 中的每个元素都是某个已访问房间发出的、尚未展开的钥匙。

**不会重**：每个房间进入时立即加入 `visited`，之后任何钥匙指向它都会被 `if key not in visited` 挡掉，所以每个房间的钥匙列表最多展开一次。

**不会漏**（反证）：假设存在房间 r 实际可达但算法结束时不在 `visited` 中。因为 r 可达，存在路径 0 = v₀ → v₁ → … → vₖ = r，其中每条边 vᵢ → vᵢ₊₁ 表示 vᵢ 的钥匙列表含 vᵢ₊₁。取路径上第一个不在 `visited` 的节点 vⱼ（j ≥ 1）。它的前驱 vⱼ₋₁ 在 `visited` 中，意味着 vⱼ₋₁ 的钥匙列表一定被展开过（进入房间时就把钥匙全压栈了），那么 vⱼ 这把钥匙必然被压入过栈。栈只在为空时终止，所以 vⱼ 最终会被弹出并加入 `visited`，矛盾。因此算法结束时 `visited` 包含所有可达房间。

**结论**：`len(visited) == n` 当且仅当所有房间可达。

## 5. 完整代码（Python）

```python
class Solution:
    def canVisitAllRooms(self, rooms: list[list[int]]) -> bool:
        n = len(rooms)
        visited = {0}          # 0 号房间一开始就能进，直接标记
        stack = [0]            # 栈里放"已进入、但钥匙还没展开"的房间

        while stack:
            room = stack.pop()             # 取出一个待展开的房间
            for key in rooms[room]:        # 展开它的全部钥匙
                if key not in visited:     # 没进过的房间才处理
                    visited.add(key)       # 压栈前就标记，防止重复入栈
                    stack.append(key)

        return len(visited) == n           # 全部房间都进过才算成功
```

如果面试官要求 BFS，把 `stack.pop()` 换成 `collections.deque` 的 `popleft()` 即可，其余逻辑一字不改——这正是「遍历顺序不影响可达性结论」的体现。

## 6. 复杂度

设 n 为房间数，E 为钥匙总数（即 `sum(rooms[i].length)`，题面保证 E ≤ 3000）。

- **时间 O(n + E)**：每个房间最多入栈一次、出栈一次，贡献 O(n)；每个房间的钥匙列表在它出栈时被完整遍历一次，所有房间加起来恰好遍历 E 把钥匙，贡献 O(E)。集合的 `in` / `add` 平均 O(1)，不引入额外因子。
- **空间 O(n)**：`visited` 集合最多存 n 个房间号，`stack` 最多同时存 O(E) 把钥匙但去重后不超过 n 个不同房间，所以是 O(n)。递归版 DFS 还要额外 O(n) 的调用栈，迭代版没有这个开销。

注意这里**没有 log 因子**：没有排序、没有二分，集合哈希是均摊 O(1)。

## 7. 边界与反例（至少 4 条）

1. **`rooms = [[1],[0]]`** → 期望 `true`。两个房间互相给钥匙，容易错在只从 0 出发就以为 1 不可达——其实 0 的钥匙直接开 1。检查你的初始 `visited` 是否包含 0。
2. **`rooms = [[1],[2],[3],[]]`** → 期望 `true`。链式结构，容易错在只展开一层就返回（比如误用「只看 0 号房间的钥匙」）。必须持续展开到栈空。
3. **`rooms = [[1,3],[3,0,1],[2],[0]]`** → 期望 `false`。2 号房间是「孤岛」，只有它自己指向自己之外没人指向它。容易错在把「钥匙指向自己」误当成可达性证据，或者忘记最后比较 `len(visited) == n` 而直接返回 `True`。
4. **`rooms = [[],[1]]`** → 期望 `false`。0 号房间是空列表，一把钥匙都没有，1 号永远进不去。容易错在假设「至少有一把钥匙」或对空列表处理不当（`for key in []` 不执行，逻辑上没问题，但要确认不会因此死循环）。
5. **`rooms = [[1],[2],[0]]`** → 期望 `true`。环形结构，0→1→2→0。容易错在「压入时不标记 visited」，导致 0 被 2 的钥匙再次压栈，虽然结果仍对但多做了无用功；更糟的是若用递归且不标记，可能栈溢出。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回「最少需要多少把钥匙才能进所有房间」或「从 0 出发最少几步到每个房间」？** 思路：前者是另一个问题（最小钥匙集），后者把 BFS 的层数记录下来即可，`dist[key] = dist[room] + 1`。
2. **追问：如果钥匙有使用次数限制（每把钥匙只能用一次）？** 思路：把 `visited` 从集合改成计数或布尔数组，并在展开钥匙时消耗计数；本质变成带资源约束的搜索，需要更仔细的状态定义。
3. **追问：如果房间之间有双向门（无向图）？** 思路：把 `rooms[i]` 里的每条边同时加入反向边，再跑同样的 DFS；可达性结论不变，但邻接表要重建。
