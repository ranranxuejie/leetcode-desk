## 1. 一句话本质

在一个「按行优先顺序读出来恰好是一个整体有序序列」的二维矩阵里，判断某个值是否存在。

## 2. 读完题的第一反应

**朴素解法**：拿到 target，先扫一遍行，找到「可能包含它」的那一行，再在这一行里线性扫一遍。最坏情况是 m 行全扫、每行 n 个元素全扫，复杂度 O(m·n)。题面明确要求 O(log(m·n))，所以朴素解法直接出局。

**关键观察**：题面给了两条性质——

- 每行从左到右非严格递增；
- 每行第一个数 **大于** 前一行的最后一个数。

第二条是「大于」而不是「大于等于」，这意味着**行与行之间没有重叠、没有相等元素跨越行边界**。把矩阵按行首尾相接摊平成一维数组 `[1,3,5,7,10,11,16,20,23,30,34,60]`，它整体是严格递增的（行内非严格递增，但跨行处严格递增）。

一旦意识到「摊平后整体有序」，问题立刻退化成最熟悉的**一维二分查找**：在一个长度为 m·n 的有序数组里找 target。剩下的全部工作只是「一维下标 ↔ 二维坐标」的换算。

这一步观察为什么能让你想到下一步：因为二分查找的适用条件就是「有序 + 随机访问」，而矩阵恰好支持 O(1) 的随机访问（`matrix[i][j]`），所以不需要真的摊平出一个新数组，直接在原矩阵上用一维下标二分即可。

## 3. 从暴力到最优

**暴力**：双重循环，逐个比较。瓶颈是「每个元素都要看一次」，O(m·n) 次比较。

**第一次优化（行内二分）**：先对第一列二分，定位 target 可能落在哪一行，再对该行二分。复杂度 O(log m + log n) = O(log(m·n))。这已经达标，但实现上要写两段二分、处理「target 比所有行首还小」「target 比最后一行行首大」等边界，容易出错。

**最终方案（整体二分）**：把矩阵当成一维数组，只写一段标准二分。瓶颈被消掉的原因是：有序性保证了「二分一次就能排除一半候选」，而一维下标映射让「一半候选」在二维里依然可 O(1) 定位。

用示例 1 走一遍，`matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]]`，m=3，n=4，总长 12，`target = 3`：

| 轮次 | left | right | mid | 映射 (i,j) | matrix[i][j] | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 11 | 5 | (1,1) | 11 | 11 > 3，right = 4 |
| 2 | 0 | 4 | 2 | (0,2) | 5 | 5 > 3，right = 1 |
| 3 | 0 | 1 | 0 | (0,0) | 1 | 1 < 3，left = 1 |
| 4 | 1 | 1 | 1 | (0,1) | 3 | 相等，返回 True |

映射公式：`i = mid // n`，`j = mid % n`。第 1 轮 mid=5，5//4=1，5%4=1，落在第 1 行第 1 列，值 11，正确。

再走一个找不到的例子，`target = 13`：

| 轮次 | left | right | mid | (i,j) | 值 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 11 | 5 | (1,1) | 11 | 11 < 13，left = 6 |
| 2 | 6 | 11 | 8 | (2,0) | 23 | 23 > 13，right = 7 |
| 3 | 6 | 7 | 6 | (1,2) | 16 | 16 > 13，right = 6 |
| 4 | 6 | 6 | 6 | (1,2) | 16 | 16 > 13，right = 5 |

此时 left=6 > right=5，循环结束，返回 False。注意第 4 轮 mid 仍是 6，值 16 仍大于 13，right 被压到 5，区间为空——这正是二分「找不到」的标准收尾。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。设摊平后的一维数组为 `A`，长度 `N = m·n`，`A[k] = matrix[k // n][k % n]`。

**不变量**：在每一轮循环开始时，如果 target 存在于 `A` 中，那么它的下标一定落在闭区间 `[left, right]` 内。

**初始化**：`left = 0, right = N - 1`，覆盖整个数组，不变量成立。

**保持**：取 `mid = (left + right) // 2`，比较 `A[mid]` 与 target。

- 若 `A[mid] == target`，直接返回 True，无需保持。
- 若 `A[mid] < target`：由题面性质，摊平后的 `A` 整体有序，所以所有下标 `≤ mid` 的元素都 `≤ A[mid] < target`，target 不可能在 `[left, mid]` 里，只可能在 `[mid+1, right]`。令 `left = mid + 1`，不变量保持。
- 若 `A[mid] > target`：对称地，所有下标 `≥ mid` 的元素都 `≥ A[mid] > target`，target 只可能在 `[left, mid-1]`。令 `right = mid - 1`，不变量保持。

**终止**：循环在 `left > right` 时结束，此时区间为空。由不变量，若 target 存在则其下标必在空区间内——矛盾，故 target 不存在，返回 False。

**不会漏**：每次排除的半边都严格不可能是答案（依据是整体有序），排除是「安全」的。
**不会重**：二分每轮只保留一个连续区间，不存在两个候选区间并存的情况，所以不会重复检查同一元素。

这里唯一依赖的题面依据是「摊平后整体有序」，而它由两条性质共同保证：行内递增保证行内有序，行首大于前行行尾保证跨行处有序且无重叠。

## 5. 完整代码（Python）

```python
class Solution:
    def searchMatrix(self, matrix, target):
        if not matrix or not matrix[0]:
            return False

        m, n = len(matrix), len(matrix[0])
        left, right = 0, m * n - 1  # 一维下标区间，覆盖整个矩阵

        while left <= right:
            mid = (left + right) // 2
            # 一维下标 -> 二维坐标：整除得行，取余得列
            i, j = mid // n, mid % n
            val = matrix[i][j]

            if val == target:
                return True
            elif val < target:
                # 摊平后整体有序，mid 及其左侧全部小于 target，安全排除
                left = mid + 1
            else:
                # mid 及其右侧全部大于 target，安全排除
                right = mid - 1

        return False
```

关键逻辑只有三处：区间初始化覆盖 `[0, m*n-1]`；`mid // n` 与 `mid % n` 完成坐标换算；比较后按有序性收缩单侧边界。没有额外数组，没有两段二分。

## 6. 复杂度

**时间 O(log(m·n))**：二分每轮把候选区间长度减半，从 `m·n` 缩到 1 需要 `log₂(m·n)` 轮。每轮内部只做常数次操作（一次整除、一次取余、一次矩阵访问、一次比较），所以总比较次数是 `log₂(m·n)` 量级。这里的 `m·n` 来自「矩阵元素总数」，`log` 来自「每轮折半」。

**空间 O(1)**：只用了 `left, right, mid, i, j, val` 几个标量，没有开辟与输入规模相关的辅助空间。注意我们**没有**真的把矩阵摊平成新数组——如果摊平，空间会变成 O(m·n)，那就违背了「原地二分」的初衷。

## 7. 边界与反例（至少 4 条）

1. **单元素矩阵** `matrix = [[5]], target = 5` → 期望 True → 容易错在 `m*n-1 = 0`，若循环条件写成 `left < right` 会直接跳过循环返回 False。必须用 `left <= right`。
2. **target 小于所有元素** `matrix = [[1,3],[5,7]], target = 0` → 期望 False → 容易错在只判断「行首」就下结论；整体二分里它会一路把 `right` 压到 -1，自然收尾，不需要特判。
3. **target 大于所有元素** `matrix = [[1,3],[5,7]], target = 100` → 期望 False → 容易错在 `mid` 计算后 `left` 越过 `m*n-1` 时数组越界；由于循环条件是 `left <= right`，`left` 最多到 `m*n`，但那时循环已退出，不会访问 `matrix`，所以安全。
4. **target 恰好等于某行行首** `matrix = [[1,3,5],[10,11,16]], target = 10` → 期望 True → 容易错在「行内二分」方案里把行首归属搞混（是上一行末尾还是本行开头）；整体二分不区分行边界，天然正确。
5. **target 落在两行之间的空隙** `matrix = [[1,3],[5,7]], target = 4` → 期望 False → 容易错在误以为「4 在 3 和 5 之间所以属于某一行」；二分会在 `A[mid]` 比较中把它排除，最终区间为空。

## 8. 面试追问与变体（3 条）

1. **追问：如果去掉「行首大于前行行尾」，只保留「每行递增、每列递增」，还能 O(log(m·n)) 吗？**
   思路：不能整体二分，但可以从右上角（或左下角）出发，每步排除一行或一列，做到 O(m+n)；这是另一道经典题（搜索二维矩阵 II）的解法。

2. **追问：如果矩阵每行递增、每列递增，但行之间不保证「行首大于前行行尾」，如何做到 O(log(m·n))？**
   思路：一般不能，因为此时不存在一个全局有序的一维展开；只能 O(m+n) 的阶梯搜索，或对每行二分做到 O(m·log n)。

3. **追问：如果要求返回 target 的二维坐标而不是布尔值，代码怎么改？**
   思路：把 `return True` 改成 `return [i, j]`，找不到时返回 `[-1, -1]`；其余逻辑不变，因为 `i, j` 在比较时已经算好。

## 9. 举一反三（2-3 道同类题）

- **搜索二维矩阵 II（LeetCode 240）**：同样在矩阵里找 target，但只保证行、列各自递增，共同点是「利用有序性逐步缩小搜索范围」，区别是这里用阶梯搜索而非整体二分。
- **在排序数组中查找元素的第一个和最后一个位置（LeetCode 34）**：一维有序数组上的二分，共同点是「二分 + 边界收缩」，区别是要跑两次二分分别找左右端点。
- **寻找旋转排序数组中的最小值（LeetCode 153）**：有序性被「旋转」破坏了一部分，共同点是「先判断哪一半仍然有序，再决定往哪边收缩」，是二分不变量的进阶练习。
