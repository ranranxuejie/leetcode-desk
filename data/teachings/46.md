## 1. 一句话本质

枚举一个互异数组的**所有排列顺序**——也就是把「从 n 个元素里依次挑一个、挑完为止」的所有挑选路径都走一遍。

## 2. 读完题的第一反应

**朴素解法**：n 个元素的全排列有 n! 个，最直接的想法是「生成所有长度为 n 的序列，再筛掉有重复元素的」。长度为 n、每个位置有 n 种取值的序列共 n^n 个，筛完剩 n! 个。当 n=6 时 n^n = 46656，n! = 720，浪费了 98% 的计算量。瓶颈在于：**大量候选序列在「还没生成完」时就已经注定非法**（比如前两位都取了 1），但暴力法要等整个序列拼完才判断。

**关键观察**：题面明确说「所有整数互不相同」。这意味着「一个排列合法」等价于「每个元素恰好用一次」。于是我们不需要事后筛选，而是**在生成过程中就保证不重复用元素**：每选一个数，就把它从「可选池」里拿掉，选到池子空为止。这样每条搜索路径天然对应一个合法排列，路径数正好是 n!，一个不多一个不少。

这个观察直接指向**回溯**：把「当前已选的序列」当作状态，把「还没用的元素」当作下一步的候选集，选一个、递归、再撤销。

## 3. 从暴力到最优

**第一步：暴力枚举所有 n^n 序列。**
以 nums=[1,2,3] 为例，枚举 111,112,113,121,...,333 共 27 个，再筛掉有重复的，剩 6 个。中间变量：候选序列 `[1,1,2]` 在生成到第二位时其实已经废了，但暴力法仍会继续补完第三位。

**第二步：加「已用集合」剪枝。**
维护一个 `used` 集合。生成 `[1,1,...]` 时，第二位想选 1，发现 1 已在 used 里，直接不往下走。这样搜索树从 27 个叶子降到 6 个叶子。但注意：此时每个内部节点仍要遍历全部 n 个元素去判断「能不能选」，判断成本 O(n)。

**第三步：回溯 + 撤销（本题最终形态）。**
用一个 `path` 存当前排列，一个 `used` 布尔数组标记哪些下标已用。递归函数做三件事：

1. `len(path) == n` 时，把 `path` 的副本加入答案；
2. 否则遍历每个下标 i，若 `not used[i]`，则 `used[i]=True`、`path.append(nums[i])`、递归、然后 `path.pop()`、`used[i]=False`。

走一遍 nums=[1,2,3]：

- 根：path=[], used=[F,F,F]
- 选 1 → path=[1], used=[T,F,F]
  - 选 2 → path=[1,2], used=[T,T,F]
    - 选 3 → path=[1,2,3] 满，收集；回溯，path=[1,2]
    - 无其他可选，回溯，path=[1], used=[T,F,F]
  - 选 3 → path=[1,3], used=[T,F,T]
    - 选 2 → path=[1,3,2] 满，收集；回溯
  - 回溯到根，path=[], used=[F,F,F]
- 选 2 → 同理产出 [2,1,3]、[2,3,1]
- 选 3 → 产出 [3,1,2]、[3,2,1]

关键点：`path.pop()` 和 `used[i]=False` 是**成对**的，它们把状态精确还原到「选这个数之前」，所以兄弟分支互不污染。这就是「回溯」区别于「普通递归」的地方——递归只往下走，回溯还要负责干净地退回来。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说：

**不变量**：在递归树的任意节点，`path` 中的元素互不相同，且 `used[i]=True` 当且仅当 `nums[i]` 出现在 `path` 中。

- **不会重**：每个排列对应递归树中唯一一条从根到叶的路径——路径上第 k 步选的数就是排列的第 k 位。两条不同路径必然在某一步选了不同的数，产出的排列不同。所以 n! 条路径产出 n! 个互异排列。
- **不会漏**：任取一个合法排列 p，按 p 的顺序在树上走：第 1 步选 p[0]（此时 used 全 False，可选），第 2 步选 p[1]（p[1]≠p[0]，未被标记，可选）……由不变量，每一步都合法，最终必到达一个叶子并被收集。所以每个合法排列都被覆盖。

**数量对账**：叶子数 = n × (n-1) × … × 1 = n!，与全排列个数相等，配合「不重不漏」即证完备。

## 5. 完整代码（Python）

```python
class Solution:
    def permute(self, nums: list[int]) -> list[list[int]]:
        n = len(nums)
        res = []          # 收集所有排列
        path = []         # 当前正在构造的排列
        used = [False] * n  # used[i] 表示 nums[i] 是否已在 path 中

        def backtrack():
            # 终止条件：path 长度达到 n，说明凑满一个排列
            if len(path) == n:
                res.append(path[:])   # 必须拷贝，否则后续 pop 会改掉已存结果
                return

            # 枚举下一步可以选哪个下标
            for i in range(n):
                if used[i]:
                    continue          # 已用过，跳过（剪枝）
                used[i] = True        # 做选择
                path.append(nums[i])
                backtrack()           # 进入下一层
                path.pop()            # 撤销选择：恢复 path
                used[i] = False       # 撤销选择：恢复 used

        backtrack()
        return res
```

两个容易写错的细节：`res.append(path[:])` 的切片拷贝不能省；`path.pop()` 与 `used[i]=False` 必须都写，少一个就会污染兄弟分支。

## 6. 复杂度

**时间 O(n · n!)**。搜索树有 n! 个叶子，每个叶子对应一次 `res.append(path[:])`，拷贝长度 n，贡献 O(n·n!)。内部节点总数是 1 + n + n(n-1) + … ≈ e·n!，每个内部节点做 O(n) 的 for 循环扫描，贡献 O(n·n!)。两项同阶，总时间 O(n·n!)。这里的 n 来自「每个排列长度 n」和「每层扫描 n 个候选」，n! 来自「排列个数」。

**空间 O(n)**（不计输出）。递归深度最多 n，`path` 长度最多 n，`used` 长度 n，三者都是 O(n)。输出本身占 O(n·n!)，通常单独计。**没有 log n 项**——本题不涉及排序或二分，别硬套。

## 7. 边界与反例（至少 4 条）

1. **输入 [1]** → 期望 `[[1]]` → 容易错在：终止条件写成 `len(path) == n-1` 或循环里漏了「选第一个」的分支，导致返回空列表。n=1 时递归只走一层，必须能正常收集。
2. **输入 [0,1]** → 期望 `[[0,1],[1,0]]` → 容易错在：把 `used` 判断写成「值是否在 path 中」时用了 `in`，逻辑对但 O(n) 变慢；更常见的是忘了 `path.pop()`，导致第二个分支变成 `[0,1,1]` 之类。
3. **输入含负数如 [-1,0,1]** → 期望 6 个排列 → 容易错在：用「值本身」当下标去标记 used（如 `used[nums[i]]`），负数直接越界或索引错乱。必须用**下标** i 标记。
4. **输入 [1,2,3] 但收集时写 `res.append(path)`** → 期望 6 个互异排列 → 实际得到 6 个**同一个空列表的引用**（因为最后 path 被 pop 空了）。这是本题最高频的 bug，必须切片拷贝。
5. **输入长度 6 的数组** → 期望 720 个排列 → 容易错在：以为回溯会超时。实际 720 个叶子、约 2000 个节点，Python 毫秒级完成，题面 n≤6 正是为回溯量身定的。

## 8. 面试追问与变体（3 条）

1. **追问：如果 nums 含重复数字（如 [1,1,2]），怎么去重？** 思路：先排序，回溯时对同一层「相同值且前一个未被使用」的候选跳过（`if i>0 and nums[i]==nums[i-1] and not used[i-1]: continue`），保证相同值只按固定顺序被选一次。
2. **追问：不用 used 数组，用「交换」实现原地回溯行不行？** 思路：固定前 k 位，把第 k 位与后面每个位置交换后递归，返回时再换回来；空间省掉 used，但要注意交换法在含重复元素时去重更麻烦。
3. **追问：只要第 k 个排列（按字典序），不要全部？** 思路：用「康托展开」直接由 k 反算每一位该取剩余元素中的第几个，O(n²) 时间、O(n) 空间，不必枚举 n! 个。

## 9. 举一反三（2-3 道同类题）

- **47. 全排列 II**：与本题共同点是「按位置逐层做选择 + 回溯撤销」，区别只在候选集有重复，需要同层剪枝去重。
- **78. 子集**：同样是「每个元素选或不选」的决策树回溯，只是终止条件从「凑满 n 个」变成「每个元素都做过决策」，收集的是所有节点而非仅叶子。
- **77. 组合**：回溯框架相同，区别是候选集随层数收窄（只能选比上一个大的），体现「组合不看顺序、排列看顺序」的差异。
