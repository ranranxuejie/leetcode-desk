## 1. 一句话本质

判断一棵二叉树**左右两棵子树是否互为镜像**——注意不是"左右子树各自对称"，而是"左子树的左边"要和"右子树的右边"对上。

这个区别是整道题的分水岭。很多人第一反应是"递归检查每个节点的左右孩子是否相等"，那是判断"左右子树完全相同"，不是镜像。镜像要求的是**交叉相等**：左孩子的左 ↔ 右孩子的右，左孩子的右 ↔ 右孩子的左。

## 2. 读完题的第一反应

**朴素解法**：把整棵树按层序（BFS）展开成数组，每一层检查是不是回文。比如示例 1 展开是 `[1] / [2,2] / [3,4,4,3]`，每层都回文，返回 true。

它卡在哪？两个地方：

1. **空节点的位置信息会丢**。示例 2 的树是 `[1,2,2,null,3,null,3]`，第二层是 `[2,2]` 回文，第三层如果只收集非空节点是 `[3,3]` 也回文——但答案是 false。因为第三层真实结构是 `[null,3,null,3]`，`3` 一个在左子树的右边、一个在右子树的右边，位置根本对不上。所以必须把 null 也塞进数组占位，数组长度会膨胀到接近 2^h，最坏 O(n) 个 null 占位符，空间不划算，而且写起来容易漏。
2. **层序本身要 O(n) 空间**，虽然可接受，但代码里要处理"这一层有多少个节点"的边界，容易写错。

**关键观察**：镜像关系是**两个节点之间**的关系，不是单个节点的性质。与其问"这棵树对称吗"，不如问"节点 a 和节点 b 互为镜像吗"。一旦把问题降维成两节点关系，递归结构立刻清晰：

- `a` 和 `b` 互为镜像 ⟺ `a.val == b.val` 且 `a.left` 与 `b.right` 互为镜像 且 `a.right` 与 `b.left` 互为镜像。

这个观察之所以能直接导向解法，是因为它把"整棵树"的自指结构拆成了"两个子树"的互相指涉，递归的形参从 1 个变成 2 个，天然避免了"左右子树各自对称"这个错误理解。

## 3. 从暴力到最优

**暴力（层序 + 回文）**：每层收集节点值（含 null 占位），判断回文。瓶颈是 null 占位导致的空间膨胀，以及代码里要维护"当前层节点数"。

**优化到递归**：不再逐层展开，而是同时从根的两个孩子出发，一左一右地"对拍"。

用示例 2 走一遍：`root = [1,2,2,null,3,null,3]`。

```
check(2, 2)          # 根的左右孩子
  val 相等 ✓
  check(2.left=null, 2.right=3)   # 左的左 vs 右的右
    null vs 3 → 一空一非空 → 返回 False
```

立刻返回 false。注意这里**没有**去比较 `2.right` 和 `2.left`（那是 3 vs null，也会 false，但第一个分支已经短路了）。对比一下错误解法"检查左右子树是否相同"会怎么走：它会比较 `2.left vs 2.left`（null vs null ✓）和 `2.right vs 2.right`（3 vs 3 ✓），然后返回 true——这就是为什么必须交叉比较。

再看示例 1：`root = [1,2,2,3,4,4,3]`。

```
check(2, 2) ✓
  check(3, 3) ✓   # 左的左 3 vs 右的右 3
    check(null, null) ✓
    check(null, null) ✓
  check(4, 4) ✓   # 左的右 4 vs 右的左 4
    check(null, null) ✓
    check(null, null) ✓
→ True
```

中间变量就是递归栈上的每一对 `(a, b)`，每对都满足 `a.val == b.val` 且两个子调用都返回 true。

**迭代版**：把递归栈换成显式队列，每次弹出两个节点 `(a, b)`，按"a.left 配 b.right、a.right 配 b.left"的顺序压入。逻辑完全同构，只是把"函数调用栈"换成"你自己管理的队列"，好处是不会爆栈（Python 默认递归深度约 1000，本题节点数上限 1000，链状树可能刚好踩线）。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。定义谓词 `mirror(a, b)` 表示"以 a 为根的子树与以 b 为根的子树互为镜像"。我们维护的不变量是：

> 递归函数 `check(a, b)` 返回 true **当且仅当** `mirror(a, b)` 成立。

**基础情况**：`a` 和 `b` 都为空 → 空树与空树互为镜像，返回 true，符合定义。`a`、`b` 恰有一个为空 → 结构不同，不可能镜像，返回 false，符合定义。

**归纳步**：假设对更小的子树不变量成立。`mirror(a, b)` 按定义等价于三件事同时成立：`a.val == b.val`、`mirror(a.left, b.right)`、`mirror(a.right, b.left)`。代码恰好检查这三件事，且由归纳假设，两个子调用返回的值就是两个子 `mirror` 的真值。所以 `check(a, b)` 的返回值等于 `mirror(a, b)`，不变量保持。

**不漏**：每个节点对 `(a, b)` 只要在镜像关系里，就一定会被某次 `check` 调用覆盖——因为镜像关系是从根对 `(root.left, root.right)` 出发、按固定规则向下展开的，展开规则与 `mirror` 的定义一一对应，没有分支被跳过。

**不重**：每个节点对只被访问一次。`(a, b)` 的父对唯一确定（`a` 的父和 `b` 的父），展开树是一棵二叉树而非图，不存在两条路径到达同一对。所以总访问次数 = 节点对数 ≤ n/2，是线性的。

## 5. 完整代码（Python）

```python
class Solution:
    def isSymmetric(self, root) -> bool:
        # 空树按定义是对称的（题面节点数 >= 1，但防御性处理）
        if root is None:
            return True

        # 核心：判断 a、b 两棵子树是否互为镜像
        def check(a, b) -> bool:
            # 两个都空：结构一致，镜像成立
            if a is None and b is None:
                return True
            # 恰有一个空：结构不一致，镜像不成立
            if a is None or b is None:
                return False
            # 值不同：直接否掉
            if a.val != b.val:
                return False
            # 交叉比较：a 的左配 b 的右，a 的右配 b 的左
            return check(a.left, b.right) and check(a.right, b.left)

        # 从根的两个孩子出发，而不是根本身
        return check(root.left, root.right)


class SolutionIter:
    def isSymmetric(self, root) -> bool:
        if root is None:
            return True
        # 队列里存"待比较的节点对"
        queue = [(root.left, root.right)]
        while queue:
            a, b = queue.pop(0)          # 弹出当前要比较的一对
            if a is None and b is None:
                continue                 # 都空，这对没问题，继续下一对
            if a is None or b is None:
                return False             # 一空一非空，结构不对称
            if a.val != b.val:
                return False             # 值不同
            # 按交叉顺序压入下一层要比较的对
            queue.append((a.left, b.right))
            queue.append((a.right, b.left))
        return True
```

递归版是主推写法，迭代版用于应对"递归深度受限"的追问。两版逻辑完全同构，只是"调用栈"换成了"显式队列"。

## 6. 复杂度

**时间 O(n)**：`n` 是节点总数。每个节点最多作为某一对 `(a, b)` 的成员被访问一次（见第 4 节"不重"论证），每次访问做常数次比较，所以总操作数与 n 成正比。注意不是 O(n log n)——树不是平衡的，递归深度最坏是 n（链状），但**总节点访问次数**仍是 n，深度只影响空间。

**空间 O(h)**，`h` 是树高。递归版的空间来自调用栈，栈深度等于同时展开的路径长度，最坏（链状树）`h = n`，最好（完全平衡）`h = log n`。迭代版的空间来自队列，队列里最多存 O(h) 对（每层最多压入下一层的对，宽度受层数约束），同样是 O(h)。**没有额外的 O(n) 数组**，这是相比层序+回文解法的空间优势。

## 7. 边界与反例（至少 4 条）

1. **`root = [1]`** → 期望 `true` → 容易错在：只写 `check(root.left, root.right)` 而没处理 `root` 为空，或者误以为单节点要特殊判断。实际上 `check(None, None)` 直接返回 true，天然正确。
2. **`root = [1,2,2,null,3,null,3]`**（示例 2）→ 期望 `false` → 容易错在：写成"检查左右子树是否相同"（比较 `a.left vs b.left`），会得到 true。必须交叉比较 `a.left vs b.right`。
3. **`root = [1,2,2,2,null,2]`** → 期望 `false` → 容易错在：只看每一层的值集合是否对称，忽略了 null 的位置。这棵树第二层 `[2,2]` 对称，但第三层左边是 `[2,null]`、右边是 `[null,2]`，结构错位。
4. **`root = [1,2,2,null,3,3,null]`** → 期望 `true` → 容易错在：看到 null 就慌，以为不对称。实际左子树的右孩子 3 与右子树的左孩子 3 交叉对上，是镜像。
5. **链状树 `[1,2,null,3,null,...]`**（深度接近 1000）→ 期望 `false`（很快在第二层就返回）→ 容易错在：递归版若不加短路（先算两个子调用再 and），可能白跑很多层；Python 默认递归深度约 1000，极端链状树可能 `RecursionError`，此时应换迭代版。

## 8. 面试追问与变体（3 条）

1. **追问："如果要求判断两棵独立的树是否互为镜像，怎么改？"** → 思路：把入口从 `check(root.left, root.right)` 改成 `check(treeA, treeB)`，函数体一字不改，因为 `check` 本来就是两参数谓词。
2. **追问："不用递归、也不用队列，用栈行不行？"** → 思路：把 `queue.pop(0)` 换成 `stack.pop()`，压入顺序无所谓（因为比较的是无序对），DFS 和 BFS 只是遍历顺序不同，正确性不变。
3. **追问："如果树是 N 叉的，怎么判断对称？"** → 思路：`check(a, b)` 里要求 `a.children[i]` 与 `b.children[len-1-i]` 互为镜像，即孩子列表首尾配对，其余逻辑不变。
