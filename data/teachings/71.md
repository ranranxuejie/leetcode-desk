## 1. 一句话本质

把一条用 `/` 分隔的路径字符串，按「`.` 忽略、`..` 回退、其余保留」的规则逐段处理，最终拼回一条从根出发的规范路径。

## 2. 读完题的第一反应

**朴素解法**：把 `path` 按 `/` 切分成若干段，然后维护一个「当前路径字符串」，遇到普通名字就 `+= "/" + name`，遇到 `..` 就把末尾一段砍掉。问题在于「砍掉末尾一段」这个操作：如果当前路径存成字符串，找最后一个 `/` 的位置、截断、还要处理截断后变空的情况，每次都是 O(当前长度)。最坏情况下路径有 n 段，每段都触发一次回退，总代价 O(n²)。n 最大 3000，O(n²) 其实也能过，但这不是面试官想看的写法，而且字符串拼接在 Python 里反复创建新对象，逻辑也容易写错（比如 `"/a"` 回退后变成 `""` 还是 `"/"`？）。

**关键观察**：`..` 的作用是「撤销最近一次还没被撤销的目录名」。这正是**栈**的语义——后进先出。目录名依次入栈，`..` 就弹栈，`.` 和空段直接跳过。最后栈里剩下的就是答案的每一层。为什么这个观察能直接导向下一步？因为「撤销最近的」这个动作在字符串上很别扭，在栈上却是 O(1) 的 `pop()`，瓶颈被彻底消掉了。

## 3. 从暴力到最优

以示例 5 为例：`path = "/.../a/../b/c/../d/./"`。

**第一步：切分**。按 `/` 切，得到 `['', '...', 'a', '..', 'b', 'c', '..', 'd', '.', '']`。注意开头和结尾的 `/` 会产生空串，连续的 `//` 也会产生空串——这些空串正好对应题面「任意多个连续斜杠视为单个」的规则，直接跳过即可。

**第二步：逐段处理，维护栈 `stack`**：

| 段 | 动作 | stack |
|---|---|---|
| `''` | 跳过（空段） | `[]` |
| `'...'` | 不是 `.` 也不是 `..`，入栈 | `['...']` |
| `'a'` | 入栈 | `['...', 'a']` |
| `'..'` | 弹栈 | `['...']` |
| `'b'` | 入栈 | `['...', 'b']` |
| `'c'` | 入栈 | `['...', 'b', 'c']` |
| `'..'` | 弹栈 | `['...', 'b']` |
| `'d'` | 入栈 | `['...', 'b', 'd']` |
| `'.'` | 跳过（当前目录） | `['...', 'b', 'd']` |
| `''` | 跳过 | `['...', 'b', 'd']` |

**第三步：拼接**。`'/' + '/'.join(stack)` = `"/.../b/d"`，与期望一致。

对比暴力解法：暴力在 `'..'` 那一步要截断字符串，而这里只是 `stack.pop()`，一次 O(1)。整条路径只扫一遍，每个段最多入栈一次、出栈一次，总代价 O(n)。

有一个细节必须想清楚：**弹栈前要判空**。示例 4 `"/../"` 切分后是 `['', '..', '']`，遇到 `..` 时栈是空的，此时应该什么都不做（题面说「不可能从根目录上升一级」），而不是报错。这个判断就是 `if stack: stack.pop()`。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义处理到第 i 段时，栈 `stack` 的内容为「把前 i 段按规则化简后，从根到当前目录的目录名序列」。

- **初始**：i=0，栈为空，对应根目录，成立。
- **归纳**：假设处理完前 i 段后不变量成立，看第 i+1 段 s：
  - s 是空串或 `'.'`：不改变当前目录，栈不变，不变量保持。
  - s 是 `'..'`：当前目录上移一级。若栈非空，弹出栈顶正好是「上一级」；若栈空，已在根，上移无效，栈仍为空。两种情况都符合规则，不变量保持。
  - s 是其他名字：进入子目录，压入 s，不变量保持。
- **终止**：处理完全部段后，栈就是从根到目标的完整目录序列，按 `/` 连接并加前导 `/` 即得规范路径。

**不会漏**：每个非空、非 `.`、非 `..` 的段都被压入过栈，除非后来被某个 `..` 合法地撤销——而撤销正是规则要求的，所以最终栈里的每个名字都是「路径上真实存在且未被抵消」的目录。

**不会重**：每个段只被处理一次，入栈一次；一个名字要么还在栈里，要么被恰好一个 `..` 弹出，不会出现两次。拼接时用 `'/'.join`，天然保证「两个目录名之间只有一个斜杠」，且空栈时 `join` 返回空串，加前导 `/` 得到 `"/"`，符合「始终以 `/` 开头」。

## 5. 完整代码（Python）

```python
class Solution:
    def simplifyPath(self, path: str) -> str:
        # 按 '/' 切分，连续斜杠和首尾斜杠都会产生空串，后面统一跳过
        parts = path.split('/')
        stack = []

        for part in parts:
            if part == '' or part == '.':
                # 空段（连续斜杠/首尾斜杠）和 '.'（当前目录）都不改变路径
                continue
            elif part == '..':
                # 回退一级；已经在根目录时忽略（不能越过根）
                if stack:
                    stack.pop()
            else:
                # 普通目录名，包括 '...'、'....' 这类合法名字
                stack.append(part)

        # 栈中自底向上就是从根到目标的目录序列
        # 空栈时 join 返回 ''，加前导 '/' 得到 '/'
        return '/' + '/'.join(stack)
```

关键逻辑就三支：跳过、弹栈、入栈。`split('/')` 一次性解决了「连续斜杠」和「首尾斜杠」两个格式问题，这是让代码短下来的核心技巧——不要在循环里手动处理斜杠。

## 6. 复杂度

设路径长度为 n（字符数），段数为 m（m ≤ n）。

- **时间 O(n)**：`split('/')` 扫一遍字符串 O(n)；循环遍历 m 个段，每段做常数次比较，`pop`/`append` 均摊 O(1)，合计 O(m) ≤ O(n)；`'/'.join(stack)` 拼接的字符总数不超过 n，O(n)。三项相加仍是 O(n)。这里没有 log 项，因为没有任何排序或二分。
- **空间 O(n)**：`parts` 列表存所有段，总字符数不超过 n；`stack` 最多存 m 个段，字符总数也不超过 n；返回的字符串长度不超过 n。所以辅助空间和输出空间都是 O(n)。

注意：如果面试官追问「能否 O(1) 额外空间」，答案是不能——你至少要把结果构造出来，而结果本身可能长达 n。

## 7. 边界与反例（至少 4 条）

1. **输入 `"/../"` → 期望 `"/"`**。容易错在：遇到 `..` 时直接 `pop()`，空栈 `pop` 抛异常；或者错误地认为「根之上还有一层」。必须判空。
2. **输入 `"/home//foo/"` → 期望 `"/home/foo"`**。容易错在：手动逐字符扫描时把连续斜杠当成多个分隔符处理，拼出 `"/home//foo"` 或 `"/home/foo/"`。用 `split('/')` 加跳过空串可以自然规避。
3. **输入 `"/.../a/../b"` → 期望 `"/.../b"`**。容易错在：把 `'...'` 误判为「多个点 = 上级目录」。题面明确只有恰好两个点才是 `..`，`'...'` 是合法名字，必须走 `else` 分支入栈。
4. **输入 `"/a/./b/../../c/"` → 期望 `"/c"`**。容易错在：`.` 段没有跳过，导致栈里混入 `'.'`，输出 `"/a/./b/../../c"` 之类；或者回退次数算错。逐步走：`a` 入栈 → `.` 跳过 → `b` 入栈 → `..` 弹 `b` → `..` 弹 `a` → `c` 入栈，得 `['c']`。
5. **输入 `"/"` → 期望 `"/"`**。容易错在：`split` 得到 `['', '']`，全跳过，栈空，`'/' + ''` = `'/'`，正确；但如果代码写成 `'/'.join(stack)` 忘了加前导 `/`，就会返回空串。

## 8. 面试追问与变体（3 条）

1. **追问：如果路径不是绝对路径（不以 `/` 开头），怎么处理？** 思路：先判断首字符，相对路径需要保留「相对于当前目录」的语义，通常约定在开头补一个虚拟根或直接按同样规则化简但输出不带前导 `/`，要和面试官确认约定。
2. **追问：如果要求支持通配符 `*` 匹配多个目录，`..` 回退时怎么处理？** 思路：栈里存的是「模式段」，回退时弹一个模式段即可；匹配发生在最后比对阶段，用双指针或 DP 做通配符匹配，栈结构不变。
3. **追问：不用 `split`，只允许一次遍历、O(1) 额外空间（除输出外），能做到吗？** 思路：用两个指针在原字符串上原地扫描段边界，边扫边把结果写回字符串前部（类似原地去重），但 `..` 回退需要知道上一段的起点，得额外维护一个「段起点栈」——所以严格 O(1) 做不到，可以退一步用 O(m) 的整数栈存段起始下标，省掉字符串拷贝。
