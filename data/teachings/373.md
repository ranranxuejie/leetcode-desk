## 1. 一句话本质

在两个各自有序的数组里，按「两两之和」从小到大挑出前 k 个组合，本质是**在 k×k 个候选里做多路归并**——把二维的笛卡尔积压成一维的有序流，只取前 k 个。

## 2. 读完题的第一反应

**朴素解法**：把 nums1 × nums2 的所有组合算出来，按和排序，取前 k。组合数是 |nums1| × |nums2|，上限 10^5 × 10^5 = 10^10，光枚举就爆了，更别说排序。这条路直接死。

**关键观察**：两个数组都是**非递减**的。这意味着固定 nums1[i]，随着 j 增大，nums1[i] + nums2[j] 单调不减。也就是说，**每一行 nums1[i] 对应一条有序的「和序列」**：

```
行 0: (nums1[0], nums2[0]) ≤ (nums1[0], nums2[1]) ≤ (nums1[0], nums2[2]) ≤ ...
行 1: (nums1[1], nums2[0]) ≤ (nums1[1], nums2[1]) ≤ ...
...
```

题目要的「全局前 k 小」，就是**从这些有序行里做多路归并**。多路归并的标准工具是堆：每行只把当前最小的那个候选放进堆，弹出后再把该行的下一个推进去。这样堆里最多只有「行数」个元素，而不是全部组合。

这个观察是整道题的转折点：**二维的候选空间，被有序性切成了若干条一维有序链**。

## 3. 从暴力到最优

**暴力**：枚举全部组合 → O(m·n) 时间 + O(m·n) 空间，m、n 各 10^5 时不可行。

**第一步优化（多路归并）**：只维护每行的「队头」。初始把 (nums1[i], nums2[0]) 全部入堆，i 取 0..min(m,k)-1。每次弹出堆顶（当前全局最小），记录答案，然后把同一行的下一个 (nums1[i], nums2[j+1]) 入堆。

用示例 1 走一遍：nums1 = [1,7,11]，nums2 = [2,4,6]，k = 3。

初始堆（按和排序）：

```
(1,2) 和=3   ← 行0队头
(7,2) 和=9   ← 行1队头
(11,2) 和=13 ← 行2队头
```

第 1 次弹出 (1,2)，答案 [[1,2]]；行0 推进 (1,4) 和=5，堆变成 {(1,4)=5, (7,2)=9, (11,2)=13}。

第 2 次弹出 (1,4)，答案 [[1,2],[1,4]]；行0 推进 (1,6) 和=7，堆 {(1,6)=7, (7,2)=9, (11,2)=13}。

第 3 次弹出 (1,6)，答案 [[1,2],[1,4],[1,6]]；k 到，结束。与官方输出一致。

**第二步优化（截断行数）**：只需要 k 个答案，而行 0 的队头一定 ≤ 行 1 的队头 ≤ …（因为 nums1 有序，nums2[0] 固定）。所以第 k 行之后的队头不可能进入前 k——初始只放前 min(m, k) 行即可。同理每行最多被推进 k 次。这一步把堆的初始规模从 m 压到 min(m,k)，k ≤ 10^4，堆规模可控。

**为什么不能只放一行？** 因为行与行之间的大小关系会交错：示例 1 里 (7,2)=9 就排在 (1,6)=7 之后、但可能早于 (1,8)。多路归并必须同时盯着所有行的队头，才能保证每次弹出的都是全局最小。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在任意时刻，堆中保存的是「每一行尚未被输出的最小候选」。具体说，对每一行 i，若该行已输出到列 j，则堆中存的是 (i, j+1)，且该行所有列 > j+1 的候选都 ≥ 它（行内有序）。

**不会漏**：设真实前 k 小中某个对是 (i, j)。它所在行在它之前的所有候选 (i, 0..j-1) 都 ≤ 它，因此要么已被输出，要么仍在堆中。若 (i, j) 尚未入堆，说明 (i, j-1) 还没被弹出；而 (i, j-1) ≤ (i, j)，所以 (i, j) 不可能是「当前应输出的最小而未输出」的那个。归纳下去，每次弹出堆顶时，堆顶就是全局未输出候选中的最小值，不会跳过任何该输出的对。

**不会重**：每个 (i, j) 只在其前驱 (i, j-1) 被弹出时入堆一次，入堆即唯一，弹出即移出，不存在重复入堆的路径。

**交换论证补充**：假设算法第 t 次弹出的不是真实第 t 小。取真实第 t 小 (i*, j*)，它未入堆意味着 (i*, j*-1) 未弹出，而 (i*, j*-1) ≤ (i*, j*)，与「堆顶是未输出最小」矛盾。故算法输出序列与真实排序一致。

## 5. 完整代码（Python）

```python
import heapq

class Solution:
    def kSmallestPairs(self, nums1, nums2, k):
        # 边界：任一数组为空则无对可返回
        if not nums1 or not nums2 or k <= 0:
            return []

        m, n = len(nums1), len(nums2)
        # 堆元素：(两数之和, nums1下标, nums2下标)
        # 只初始化前 min(m, k) 行：第 k 行之后的队头不可能进前 k
        heap = []
        for i in range(min(m, k)):
            # 每行队头是 (nums1[i], nums2[0])
            heapq.heappush(heap, (nums1[i] + nums2[0], i, 0))

        res = []
        while heap and len(res) < k:
            s, i, j = heapq.heappop(heap)      # 弹出当前全局最小
            res.append([nums1[i], nums2[j]])   # 记录答案
            # 同一行的下一个候选入堆（行内有序，保证它是该行剩余最小）
            if j + 1 < n:
                heapq.heappush(heap, (nums1[i] + nums2[j + 1], i, j + 1))
        return res
```

关键点说明：堆里存的是**下标**而不是值，因为要据此推进同一行的下一个；和作为堆的第一关键字，Python 元组比较天然按和排序，和相等时按下标比较，不影响正确性（题目不要求相等时的顺序）。

## 6. 复杂度

- **时间**：O(k log(min(m, k)))。循环最多执行 k 次（每次弹一个答案），每次堆操作 O(log H)，H 是堆规模，初始 min(m,k) 且每弹一个最多补一个，故 H ≤ min(m,k)。初始化 O(min(m,k)) 可忽略。注意这里**没有** m·n 项——这正是多路归并省掉的部分。
- **空间**：O(min(m, k)) 的堆 + O(k) 的答案。堆规模由「行数」决定而非「组合数」，这是空间能压下来的原因。

对比暴力 O(m·n log(m·n))，这里把 m·n 换成了 k，因为题目只要前 k 个。

## 7. 边界与反例（至少 4 条）

1. **k 大于总组合数**：nums1=[1], nums2=[2], k=5 → 期望 [[1,2]]。题面保证 k ≤ m·n，但若调用方传超，代码靠 `len(res) < k` 和堆空自然退出，不会越界。容易错的是用 `for _ in range(k)` 硬循环，堆空后 pop 报错。
2. **含负数**：nums1=[-5,-1], nums2=[-3,2], k=2 → 期望 [[-5,-3],[-5,2]]（和 -8、-3，注意 -1+(-3)=-4 排在 -3 前？实际 -4 < -3，所以是 [[-5,-3],[-1,-3]]）。容易错：误以为「和最小」等价于「元素最小」，负数下必须老老实实比和。
3. **重复元素**：nums1=[1,1,2], nums2=[1,2,3], k=2 → 期望 [[1,1],[1,1]]。两个 (1,1) 来自不同行（行0和行1），必须都输出。容易错：用 set 去重，把合法重复对吞掉。
4. **k=1**：nums1=[1,2], nums2=[3,4], k=1 → 期望 [[1,3]]。容易错：初始化时把 min(m,k)=1 行入堆，只放行0，正确；但若误写成 `range(m)` 再在循环里截断，逻辑仍对，只是多做了无用功。
5. **单元素数组**：nums1=[1], nums2=[1,2,3], k=3 → 期望 [[1,1],[1,2],[1,3]]。只有一行，退化成单链表遍历，堆规模恒为 1。

## 8. 面试追问与变体（3 条）

1. **追问：如果 nums2 不是有序的怎么办？** 思路：先对 nums2 排序（O(n log n)），再套本题；或改用「值域二分 + 计数」找第 k 小和，再枚举。
2. **追问：要求返回第 k 小的「和」而不是所有对？** 思路：二分答案 s，统计有多少对和 ≤ s（双指针 O(m+n)），找到临界 s 后只输出和 < s 的对再补足。
3. **追问：两个数组都很大但 k 很小，能否 O(k log k) 且不初始化 m 行？** 思路：本题已做到 O(k log min(m,k))；若要彻底摆脱 m，可用「懒初始化」——堆里先只放 (0,0)，弹出 (i,j) 时把 (i+1,j) 和 (i,j+1) 入堆并用 visited 去重，堆规模 O(k)。
