## 1. 一句话本质

在数组里数出所有满足「两边之和大于第三边」的三元组，且三元组按**下标**区分、不按值去重。

## 2. 读完题的第一反应

**朴素解法**：三重循环枚举所有 `(i, j, k)`，对每组检查 `a+b>c and a+c>b and b+c>a`。复杂度 O(n³)，n=1000 时是 10⁹ 量级，Python 里必然超时。瓶颈在于「枚举」本身——组合数是 C(n,3)，没有任何剪枝。

**关键观察**：三角形判定有三条不等式，但如果我们**先把三条边排序**，设 `a ≤ b ≤ c`，那么 `a + c > b` 和 `b + c > a` 自动成立（因为 c 最大，a+c ≥ b+c > b 显然；b+c > a 因为 b ≥ a 且 c > 0）。**只剩一条需要检查：`a + b > c`**。

这一步把「三条件与」降成「单条件」，是整道题的转折点。它让你想到：既然只需比较「两个较小边之和」与「最大边」，那能不能固定最大边，然后**一次性数出**有多少对较小边满足条件，而不是逐对枚举？——这就指向了排序 + 双指针。

## 3. 从暴力到最优

**第一步：排序消掉两条不等式。**
排序 O(n log n)，之后每个三元组只需验证 `nums[i] + nums[j] > nums[k]`（i<j<k）。

**第二步：固定最大边 k，把「数对」变成「数区间」。**
对固定的 k，我们要数有多少对 (i, j)，i < j < k，满足 `nums[i] + nums[j] > nums[k]`。

注意数组已升序。固定 i 时，`nums[i] + nums[j]` 随 j 增大而增大，所以满足条件的 j 构成一个**后缀区间** `[j0, k-1]`。但这样对每个 i 二分找 j0 是 O(n log n)，总共 O(n² log n)——比 O(n³) 好，但还能再压。

**第三步：双指针把「每个 i 二分」变成「一次扫描」。**
反过来固定 i 和 j 的**两端**：让 i 从左端出发、j 从 k-1 出发。

- 若 `nums[i] + nums[j] > nums[k]`：那么对当前 i，j 以及 j 左边直到 i+1 的所有位置都满足（因为减小 j 只会让和更小？不对——减小 j 会让和变小，所以**不是**全满足）。等等，这里要小心方向。

重新理清：固定 k，i 从 0 开始、j 从 k-1 开始。若 `nums[i] + nums[j] > nums[k]` 成立，由于 i 固定时和随 j 增大而增大，那么**所有 j' ∈ [i+1, j] 都满足**（它们比 j 小，和更小？不，j' < j 时和更小，可能不满足）。

正确的双指针方向是：**i 从 0 往右，j 从 k-1 往左**，但判断逻辑是：

- 若 `nums[i] + nums[j] > nums[k]`：说明对**这个 j**，所有 i' ∈ [i, j-1] 都满足（因为 i' ≥ i 使和更大）。于是 `ans += j - i`，然后 `j -= 1`（j 已经数完，换更小的 j 继续）。
- 否则 `nums[i] + nums[j] <= nums[k]`：i 太小了，`i += 1`。

**小例子走一遍**：nums = [2,2,3,4]，排序后不变。k=3（值 4），i=0，j=2。

- `nums[0]+nums[2] = 2+3 = 5 > 4` ✓ → ans += 2-0 = 2（对应 (2,3,4) 两组，两个 2 分别配 3 和 4），j 变 1。
- `nums[0]+nums[1] = 2+2 = 4 > 4`？否（严格大于才成立）→ i 变 1。
- i=1, j=1，i >= j，内层结束。

k=2（值 3），i=0，j=1：`2+2=4 > 3` ✓ → ans += 1-0 = 1（对应 (2,2,3)），j 变 0，结束。

总 ans = 3，与示例一致。

## 4. 正确性：为什么不会漏、不会重

**不变量**：对每个固定的 k，内层双指针在任意时刻维护「尚未被计数的候选对 (i, j) 都满足 i ≤ j < k，且所有 i' < i 的配对已被处理完」。

- **不漏**：当 `nums[i]+nums[j] > nums[k]` 时，我们一次性计入 `j - i` 对，即 (i,j), (i+1,j), ..., (j-1,j)。这些对的较小边都 ≥ nums[i]，较大边都是 nums[j]，和 ≥ nums[i]+nums[j] > nums[k]，全部合法。j 左移后，j 右侧的所有配对都已计数完毕。
- **不重**：每对 (i,j) 只在「j 作为右指针被处理」的那一次被计入，且计入后 j 立即左移，不会再被访问。i 只在条件不满足时右移，也不会回头。
- **不误计**：当 `nums[i]+nums[j] <= nums[k]` 时，对当前 i 而言，所有 j' ≤ j 的和都 ≤ nums[i]+nums[j] ≤ nums[k]，均不合法，所以 i 必须右移——这一步是「排除」，不是「计数」。

外层 k 从 2 遍历到 n-1，每个 k 独立计数，三元组按最大边唯一归属，故不重不漏。

## 5. 完整代码（Python）

```python
class Solution:
    def triangleNumber(self, nums: list[int]) -> int:
        nums.sort()                      # 升序，之后只需检查 a+b>c
        n = len(nums)
        ans = 0
        # 固定最大边 k，在 [0, k-1] 中用双指针数满足 nums[i]+nums[j]>nums[k] 的对
        for k in range(2, n):
            i, j = 0, k - 1
            while i < j:
                if nums[i] + nums[j] > nums[k]:
                    # 对当前 j，i..j-1 都能和 j 组成合法对
                    ans += j - i
                    j -= 1               # j 已数完，换更小的 j
                else:
                    i += 1               # i 太小，右移增大和
        return ans
```

## 6. 复杂度

- **时间 O(n²)**：外层 k 循环 n-2 次；内层 i、j 只朝一个方向移动，合计最多 k 步，即 O(n)。乘起来 O(n²)。排序的 O(n log n) 被 O(n²) 支配。
- **空间 O(1)**（不计排序）：只用了 i、j、ans 三个变量。Python 的 `sort` 是 Timsort，最坏 O(n) 额外空间；若严格要求 O(1) 需换原地堆排序，但面试中通常按「不计排序空间」算。

## 7. 边界与反例（至少 4 条）

1. **输入 [0,0,0] → 期望 0**。容易错：`0+0>0` 为假，正确；但若写成 `>=` 就会错判为 1。三角形要求严格大于。
2. **输入 [2,2,3,4] → 期望 3**。容易错：把两个 2 当成同一个元素去重，只数出 2 组。题目按**下标**区分，两个 2 是不同元素。
3. **输入 [1,2,3] → 期望 0**。退化三角形（1+2=3）不合法，`>` 而非 `>=` 是关键。
4. **输入 [3,4,5,6,7] → 期望 5**（(3,4,5),(3,4,6)? 3+4=7>6 合法… 实际枚举：(3,4,5),(3,4,6),(3,5,6)? 3+5=8>6 合法，(4,5,6),(4,5,7)? 4+5=9>7 合法，(5,6,7)? 5+6=11>7 合法… 需仔细数，建议手算验证）。容易错：双指针方向写反，导致漏计。
5. **输入长度 < 3（如 [1,2]）→ 期望 0**。容易错：外层 `range(2, n)` 在 n<3 时不执行，返回 0，正确；但若手写循环边界 `range(2, n+1)` 会越界。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求三元组按值去重（相同值的组合只算一次）怎么办？** 思路：排序后跳过相邻重复值，或在计数时对相同值做组合数处理，双指针框架不变但计数逻辑要改。
2. **追问：改成「恰好能组成直角三角形」的个数？** 思路：条件变为 `a²+b²=c²`，固定 c 后双指针比较平方和，仍 O(n²)，但要注意整数溢出（Python 无此问题）。
3. **追问：数组很大（n=10⁵）且只需判断「是否存在」一个合法三元组？** 思路：排序后只需检查最大的三个数是否满足 `a+b>c`，O(n log n)；因为若最大三数都不满足，更小的更不满足。

## 9. 举一反三（2-3 道同类题）

- **15. 三数之和**：同样排序 + 固定一个数 + 双指针，共同点是「排序后利用单调性把 O(n³) 降到 O(n²)」。
- **16. 最接近的三数之和**：排序 + 双指针逼近目标值，共同点是双指针在有序数组上做区间收缩。
- **259. 较小的三数之和**：排序 + 固定最大边 + 双指针计数，和本题几乎同构，只是不等式方向相反。
