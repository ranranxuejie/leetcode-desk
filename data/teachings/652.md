## 1. 一句话本质

给每个子树算一个「结构+值的指纹」，找出指纹出现两次以上的那些子树。

## 2. 读完题的第一反应

**朴素解法**：对每个节点 u，再对每个节点 v，写一个 `isSameTree(u, v)` 逐节点比较。节点数 n ≤ 5000，两两配对是 O(n²)，每次比较最坏 O(n)，总复杂度 O(n³)。n=5000 时这是 1.25×10¹¹ 量级，必然超时。

**卡在哪**：瓶颈不在「比较」这个动作，而在「我们反复比较了很多其实一眼就能看出不同的子树」。比如一棵只有 3 个节点的子树和一棵有 100 个节点的子树，根本不可能相同，但我们却老老实实比了。问题的根源是：**我们没有为每棵子树准备一个可以 O(1) 比较的「身份证」**。

**关键观察**：一棵子树完全由「根的值 + 左子树 + 右子树」决定。这是递归结构，天然适合自底向上处理：如果左子树和右子树都已经有了身份证，那么当前子树的身份证就可以由「根值 + 左身份证 + 右身份证」拼出来。于是每个节点只需要算一次身份证，总共 n 次，每次拼接是常数级操作（用字符串或元组），整体 O(n)。

这个观察为什么能直接导向下一步？因为它把「两两比较树」这个 O(n²) 的问题，转化成了「给 n 个对象各算一个 key，再统计 key 的频次」这个 O(n) 的哈希表问题。**比较的对象从「树」变成了「字符串/元组」**，这是整道题的转折点。

## 3. 从暴力到最优

**第一步：暴力**。对每个节点 u，遍历所有节点 v，`isSameTree(u,v)`。复杂度 O(n³)。

**第二步：引入序列化**。对每个节点 u，把它的子树序列化成一个字符串（比如前序遍历，空节点用 `#` 占位）。然后对所有字符串排序或放进哈希表统计。序列化每棵子树是 O(size)，所有子树加起来最坏 O(n²)（链状树时，每个节点的子树大小分别是 n, n-1, ..., 1）。这一步把 O(n³) 降到 O(n²)，但还不够。

**第三步：自底向上 + 记忆化**。关键洞察：序列化子树 u 时，不需要重新遍历整棵子树，因为左子树和右子树的序列化结果已经算过了。直接拼 `str(u.val) + "," + left_ser + "," + right_ser` 即可，每次 O(1)。总共 n 次，O(n)。

**具体小例子走一遍**：用示例 1，`root = [1,2,3,4,null,2,4,null,null,4]`。

树结构：
```
        1
       / \
      2   3
     /   / \
    4   2   4
       /
      4
```

后序遍历（左→右→根），逐个节点算 key：

- 节点 4（最左下的叶子）：`"4,#,#"` → 哈希表 `{"4,#,#": 1}`
- 节点 2（左孩子是上面的 4）：`"2,4,#,#,#"` → `{"4,#,#":1, "2,4,#,#,#":1}`
- 节点 4（节点 3 的左孩子的左孩子，叶子）：`"4,#,#"` → 已存在，计数变 2，**记录这个节点**
- 节点 2（节点 3 的左孩子）：`"2,4,#,#,#"` → 已存在，计数变 2，**记录这个节点**
- 节点 4（节点 3 的右孩子，叶子）：`"4,#,#"` → 计数变 3，已经记录过，跳过
- 节点 3：`"3,2,4,#,#,#,4,#,#"` → 计数 1
- 节点 1：`"1,2,4,#,#,#,3,..."` → 计数 1

最终记录了两个节点：值为 2 的那个（子树 `[2,4]`）和值为 4 的那个叶子。输出 `[[2,4],[4]]`，与示例一致。

注意「计数变 2 时才记录」这个细节：第一次出现不记录，第二次出现记录一次，第三次出现不再记录。这样保证同一类重复子树只返回一个根节点。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在处理完以 u 为根的子树后，哈希表中 `key(u)` 的值等于「整棵树中，与 u 子树结构+值完全相同的子树个数」。

**归纳证明**：
- 基础：叶子节点，key 是 `"val,#,#"`，哈希表正确计数。
- 归纳：假设左右子树的 key 都已正确计算并计数。那么 `key(u) = val + left_key + right_key`。两棵子树相同 ⟺ 根值相同且左右子树分别相同 ⟺ key 相同。所以 key(u) 的计数就是与 u 相同的子树个数。

**不漏**：任何一对重复子树，它们的根节点都会被后序遍历访问到，且 key 相同，计数会 ≥ 2，第二次出现时被记录。

**不重**：只在计数恰好从 1 变 2 的那一刻记录一次。同一 key 的第三次、第四次出现不会重复记录。所以每个重复类恰好贡献一个根节点。

**为什么用后序**：因为 key(u) 依赖 key(left) 和 key(right)，必须孩子先算完。后序遍历天然满足这个顺序。

## 5. 完整代码（Python）

```python
class Solution:
    def findDuplicateSubtrees(self, root):
        from collections import defaultdict
        count = defaultdict(int)   # key -> 出现次数
        res = []                   # 存放重复子树的根节点

        def dfs(node):
            if not node:
                return "#"         # 空节点用 # 占位，保证结构信息不丢失
            # 后序：先算左右子树的 key，再拼当前 key
            left_key = dfs(node.left)
            right_key = dfs(node.right)
            key = f"{node.val},{left_key},{right_key}"
            count[key] += 1
            # 只在第二次出现时记录，避免同一类重复多次加入
            if count[key] == 2:
                res.append(node)
            return key

        dfs(root)
        return res
```

关键逻辑说明：
- `#` 占位不能省。如果省略空节点，`[1,2]` 和 `[1,null,2]` 会序列化成同一个字符串，导致误判。
- `count[key] == 2` 而不是 `>= 2`，是为了去重。
- 返回的是节点对象而不是值，因为题目要求返回根结点。

## 6. 复杂度

**时间 O(n)**：每个节点被访问一次，每次做常数级的字符串拼接和哈希表操作。n 是节点数。注意字符串拼接的代价：key 的长度与子树大小成正比，严格来说总代价是 O(n²)（链状树时最坏）。但在 n ≤ 5000 的约束下，实际运行很快；如果追求严格 O(n)，可以把 key 换成「整数 id」：用另一个哈希表把字符串映射成自增 id，key 用 `(val, left_id, right_id)` 元组。这是面试中值得提的优化点。

**空间 O(n)**：哈希表最多存 n 个不同的 key，递归栈深度最坏 O(n)（链状树），结果列表最多 O(n)。没有 log n 的项，因为这是树不是平衡结构，深度不由 log 控制。

## 7. 边界与反例（至少 4 条）

1. **输入 `[1,1]`** → 期望 `[[1]]`。容易错：根 1 和左孩子 1 的子树不同（根有孩子，孩子没有），不应判重。key 分别是 `"1,1,#,#,#"` 和 `"1,#,#"`，正确区分。
2. **输入 `[1,2,1]`** → 期望 `[]`。容易错：两个 1 的子树结构不同（一个只有右孩子，一个只有左孩子）。如果序列化时不分左右，会误判。key 分别是 `"1,#,2,#,#"` 和 `"1,2,#,#,#"`，不同。
3. **输入 `[2,2,2,3,null,3,null]`**（示例 3）→ 期望 `[[2,3],[3]]`。容易错：三个 2 中，根 2 的子树和左孩子 2 的子树不同（左孩子 2 有左孩子 3，根 2 的右孩子是 2）。需要仔细核对 key。
4. **输入 `[1,1,1]`**（完全相同的三个节点）→ 期望 `[[1]]`（只返回一个）。容易错：如果写成 `count[key] >= 2` 就 append，会把三个 1 都加进去。必须用 `== 2`。
5. **单节点 `[1]`** → 期望 `[]`。容易错：没有重复，哈希表计数都是 1，不应返回任何东西。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回所有重复子树（包括同一类的多个根节点）怎么办？** 思路：把 `count[key] == 2` 改成 `count[key] >= 2`，但用一个 `set` 记录已经加入过的 key，避免同一类重复加入。
2. **追问：如何把字符串 key 优化成严格 O(n)？** 思路：维护一个 `key_to_id` 哈希表，把 `(val, left_id, right_id)` 元组映射到自增整数 id，用整数代替字符串做 key，避免长字符串拼接的开销。
3. **追问：如果树非常大（n=10⁶），递归会栈溢出怎么办？** 思路：改成显式栈的迭代后序遍历，用 `(node, visited)` 标记状态，孩子处理完后再处理父节点。
