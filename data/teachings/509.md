## 1. 一句话本质

求一个由「前两项相加得到后一项」的递推关系定义的第 n 项，本质是**把重复计算的子问题合并成一次计算**。

## 2. 读完题的第一反应

题面已经把递推公式直接给你了：`F(n) = F(n-1) + F(n-2)`，边界 `F(0)=0, F(1)=1`。所以最朴素的想法就是**照着公式翻译成代码**：

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)
```

这个写法逻辑上完全正确，但它卡在哪？卡在**同一个子问题被反复求解**。算 `fib(5)` 要算 `fib(4)` 和 `fib(3)`；算 `fib(4)` 时又要算 `fib(3)` 和 `fib(2)`——注意 `fib(3)` 被算了两次。往下展开，重复次数呈指数膨胀，时间复杂度是 O(2^n)。n=30 时大约要跑上百万次调用，虽然题目限制 n≤30 勉强能过，但这不是能拿去面试的答案。

关键观察是：**`fib(k)` 的结果只由 k 决定，和「谁调用它」无关**。既然同样的 k 会算出同样的值，那第二次遇到 k 时就没必要重算，把第一次的结果存下来即可。这个「存下来」的动作，就是记忆化；而如果进一步发现「算 F(n) 只需要 F(n-1) 和 F(n-2) 两个值」，就能把存储压到常数——这就是从记忆化走向滚动变量的动机。

## 3. 从暴力到最优

分三步走，用 n=5 走一遍。

**第一步：朴素递归。** 调用树如下（只画部分）：

```
fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2) ...
│   │   └── fib(1)
│   └── fib(2)
└── fib(3)          ← 和上面那棵 fib(3) 完全重复
    ├── fib(2)
    └── fib(1)
```

瓶颈：`fib(3)` 算了两遍，`fib(2)` 算了三遍。重复量随 n 指数增长。

**第二步：记忆化（自顶向下）。** 开一个数组 `memo`，初始全为 -1。每次进函数先查 `memo[n]`，不是 -1 就直接返回；算完再写回。走 n=5：

- `fib(5)` → 查 memo[5]=-1 → 需要 fib(4)、fib(3)
- `fib(4)` → 查 memo[4]=-1 → 需要 fib(3)、fib(2)
- `fib(3)` → 查 memo[3]=-1 → 需要 fib(2)、fib(1)
- `fib(2)` → 查 memo[2]=-1 → 需要 fib(1)、fib(0) → 得 1，写 memo[2]=1
- 回到 `fib(3)`：fib(2)=1（命中 memo）、fib(1)=1 → 得 2，写 memo[3]=2
- 回到 `fib(4)`：fib(3)=2（命中 memo）、fib(2)=1（命中 memo）→ 得 3，写 memo[4]=3
- 回到 `fib(5)`：fib(4)=3、fib(3)=2（命中 memo）→ 得 5

每个 k 只真正计算一次，瓶颈消掉，时间降到 O(n)。但空间是 O(n) 的 memo 数组加 O(n) 的递归栈。

**第三步：滚动变量（自底向上）。** 观察递推式：算 `F(n)` 只需要前两个值。那我们从 `F(0)=0, F(1)=1` 出发，一路往后推，每次只保留「前两个」。走 n=5：

| 轮次 | a (F(i-2)) | b (F(i-1)) | 新值 a+b | 更新后 (a,b) |
|---|---|---|---|---|
| 初始 | 0 | 1 | — | (0,1) |
| i=2 | 0 | 1 | 1 | (1,1) |
| i=3 | 1 | 1 | 2 | (1,2) |
| i=4 | 1 | 2 | 3 | (2,3) |
| i=5 | 2 | 3 | 5 | (3,5) |

循环结束时 b 就是 F(5)=5。空间降到 O(1)，连递归栈都没了。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来证第三步的迭代写法。

设循环变量 i 从 2 走到 n，声明不变量：

> 在每轮循环开始时，`a = F(i-2)` 且 `b = F(i-1)`。

**初始化**：i=2 时，a=0=F(0)，b=1=F(1)，成立。

**保持**：假设第 i 轮开始时 a=F(i-2)、b=F(i-1)。本轮计算 `c = a + b = F(i-2) + F(i-1) = F(i)`（用了题面给的递推式，i>1 时成立）。然后令 `a = b = F(i-1)`、`b = c = F(i)`。进入下一轮 i+1 时，需要 a=F(i-1)、b=F(i)，恰好满足。不变量保持。

**终止**：循环在 i=n+1 时退出，此时不变量说 b=F(n)。返回 b 即得所求。

「不会漏」由初始化+保持保证：每个 F(i) 都被递推式覆盖到。「不会重」由滚动变量保证：每轮只算一个新值，旧值被覆盖而非重算。记忆化版本的正确性同理——memo[k] 一旦写入就等于 F(k)，之后命中直接返回，不改变结果。

## 5. 完整代码（Python）

```python
class Solution:
    def fib(self, n: int) -> int:
        # 边界：F(0)=0, F(1)=1，直接返回
        if n <= 1:
            return n

        # 滚动变量：a 代表 F(i-2)，b 代表 F(i-1)
        a, b = 0, 1

        # 从 i=2 推到 i=n，每轮算出一个新值
        for i in range(2, n + 1):
            a, b = b, a + b   # 同时更新：新的 a 是旧的 b，新的 b 是旧 a+旧 b

        # 循环结束时 b 就是 F(n)
        return b
```

注意 `a, b = b, a + b` 这一行：Python 的元组赋值会**先算右边再赋值**，所以 `a + b` 用的是更新前的 a、b，不会因为先改 a 而算错。这是本题最容易写错的一行。

## 6. 复杂度

**时间 O(n)**：循环从 2 到 n，共 n-1 次迭代，每次只做一次加法和两次赋值，常数时间。n 来自「要推多少项」。没有 log n 项——本题不涉及二分或位运算，别硬套。

**空间 O(1)**：只用了 a、b 两个变量，与 n 无关。对比：朴素递归空间 O(n)（递归栈深度 n），记忆化 O(n)（memo 数组 + 栈）。

## 7. 边界与反例（至少 4 条）

1. **n = 0** → 期望 0 → 容易错在循环从 2 开始、但没处理 n<2 的情况，导致返回 b=1。所以 `if n <= 1: return n` 必须写在最前面。
2. **n = 1** → 期望 1 → 同上，若漏掉边界会返回 1 碰巧对，但 n=0 就错了；两个边界要一起处理。
3. **n = 2** → 期望 1 → 循环只跑一轮：a,b=(0,1)→(1,1)，返回 b=1，正确。容易错在把循环写成 `range(2, n)`，少跑一轮返回 1 但 n=3 时会返回 1（错，应为 2）。
4. **n = 30** → 期望 832040 → 这是题目上限。若用朴素递归，调用次数约 2^30 量级，会超时；用迭代则瞬间完成。这条提醒你别因为「n 小」就交递归。
5. **误用 `a = b; b = a + b` 分开写** → 输入 n=3 时期望 2，但分开写会得到 a=1, b=2 后下一轮 a=2, b=3，n=3 返回 2 碰巧对，n=4 就返回 3 而正确是 3……真正出错在 n=5：分开写会返回 8 而非 5。必须用元组同时赋值。

## 8. 面试追问与变体（3 条）

1. **追问：如果 n 高达 10^18，怎么办？** 思路：用矩阵快速幂或快速倍增公式，把递推转成 2×2 矩阵的幂，时间 O(log n)。
2. **追问：要输出前 n 项整个数列，而不只是第 n 项？** 思路：滚动变量改成维护一个长度为 n+1 的数组，边推边存，时间 O(n)、空间 O(n)。
3. **追问：把「前两项相加」改成「前三项相加」（Tribonacci），代码怎么改？** 思路：滚动变量从两个扩成三个 `a,b,c`，每轮 `a,b,c = b,c,a+b+c`，结构不变。
