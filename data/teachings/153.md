## 1. 一句话本质

在一个「两段各自升序、整体断成两截」的数组里，用二分法定位那个「断点」——断点处的元素就是全局最小值。

## 2. 读完题的第一反应

**朴素解法**：从头扫到尾，维护一个 `min`，遇到更小的就更新。时间 O(n)，空间 O(1)。它卡在哪？题面明确要求 O(log n)，而线性扫描必须看每一个元素才能保证不漏——因为最小值可能藏在任何位置，扫到一半停下没有任何依据说「后面不会更小」。

**关键观察**：数组虽然被旋转，但它不是乱序的。它由**两段升序**拼成：前一段是原数组的后半部分（较大的那些数），后一段是原数组的前半部分（较小的那些数）。比如 `[4,5,6,7,0,1,2]`，前段 `4,5,6,7` 升序，后段 `0,1,2` 升序，中间 `7→0` 是一个「断崖」。最小值恰好是断崖右边的第一个元素。

这个观察为什么能引向二分？因为「断崖在哪」是一个**单调的判定**：取中点 `mid`，比较 `nums[mid]` 和 `nums[right]`，就能判断 `mid` 落在断崖左边还是右边。一旦能对「mid 在哪一侧」做二值判断，二分就有了依据——每次砍掉一半，正是 O(log n) 的来源。

## 3. 从暴力到最优

**第一步：暴力**。遍历全部 n 个元素取最小，O(n)。瓶颈：必须看每个元素。

**第二步：利用「两段升序」缩小范围**。既然数组是两段升序，最小值只可能出现在「断崖」处。问题从「找最小」变成「找断崖位置」。

**第三步：二分定位断崖**。维护 `left`、`right` 两个指针，`mid = (left+right)//2`。核心比较是 `nums[mid]` 与 `nums[right]`：

- 若 `nums[mid] > nums[right]`：说明 `mid` 在**前段**（大数段），断崖一定在 `mid` 的右边，最小值在 `mid+1 .. right` 里，于是 `left = mid + 1`。
- 若 `nums[mid] < nums[right]`：说明 `mid` 在**后段**（小数段），断崖在 `mid` 左边或就是 `mid` 本身，最小值在 `left .. mid` 里，于是 `right = mid`。

注意第二种情况是 `right = mid` 而不是 `mid - 1`——因为 `mid` 自己可能就是最小值，不能排除掉。

**走一遍例子** `nums = [4,5,6,7,0,1,2]`：

| 轮次 | left | right | mid | nums[mid] | nums[right] | 比较结果 | 动作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 7 | 2 | 7 > 2 | left = 4 |
| 2 | 4 | 6 | 5 | 1 | 2 | 1 < 2 | right = 5 |
| 3 | 4 | 5 | 4 | 0 | 1 | 0 < 1 | right = 4 |
| 4 | 4 | 4 | — | — | — | left == right | 结束，返回 nums[4]=0 |

四轮把 7 个元素砍到 1 个，正是 log₂7 ≈ 3 的量级。

**再走一个「没旋转」的例子** `nums = [11,13,15,17]`：

| 轮次 | left | right | mid | nums[mid] | nums[right] | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 3 | 1 | 13 | 17 | 13 < 17 → right = 1 |
| 2 | 0 | 1 | 0 | 11 | 13 | 11 < 13 → right = 0 |
| 3 | 0 | 0 | — | — | — | 返回 nums[0]=11 |

整个数组就是一段升序，`nums[mid] < nums[right]` 恒成立，`right` 一路收到 0，返回首元素——正确，因为没旋转时最小值就是 `nums[0]`。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。设当前搜索区间为 `[left, right]`，我们维持：

> **不变量**：全局最小值一定落在 `nums[left..right]` 这个闭区间内。

初始时 `left=0, right=n-1`，区间是整个数组，不变量显然成立。

**归纳步**：假设不变量成立，看 `mid` 的比较。

- 情况 A：`nums[mid] > nums[right]`。因为 `nums[mid]` 比 `nums[right]` 大，而 `mid < right`，说明从 `mid` 到 `right` 之间发生过「下降」（否则升序段里 `nums[mid]` 应小于 `nums[right]`）。这个下降点（断崖）必在 `mid` 右侧，即最小值在 `mid+1 .. right`。所以令 `left = mid+1`，新区间仍包含最小值，不变量保持。
- 情况 B：`nums[mid] < nums[right]`。说明 `mid` 到 `right` 是升序的，断崖不在 `mid` 右侧（或在 `mid` 及以左）。最小值在 `left .. mid`。令 `right = mid`，新区间仍包含最小值，不变量保持。

**终止**：每轮区间长度严格减小（`mid+1 > left` 或 `mid < right` 都成立，因为 `mid` 严格夹在 `left` 和 `right` 之间），最终 `left == right`，区间只剩一个元素。由不变量，它就是全局最小值，返回 `nums[left]` 正确。

**为什么不会漏**：每次砍掉的那一半，都被比较结果证明「不可能含最小值」。**为什么不会重**：区间是闭区间且每次收缩都保留 `mid` 或排除 `mid`，没有元素被重复计入，也没有元素被跳过。

## 5. 完整代码（Python）

```python
class Solution:
    def findMin(self, nums: list[int]) -> int:
        left, right = 0, len(nums) - 1

        # 不变量：最小值始终在 nums[left..right] 闭区间内
        while left < right:
            mid = (left + right) // 2

            if nums[mid] > nums[right]:
                # mid 在前段（大数段），断崖在 mid 右侧
                # mid 本身不可能是最小值，可以安全排除
                left = mid + 1
            else:
                # nums[mid] < nums[right]，mid 在后段（小数段）
                # mid 自己可能就是最小值，不能排除，右边界收到 mid
                right = mid

        # 区间收缩到只剩一个元素，它就是全局最小值
        return nums[left]
```

关键点只有两处：`nums[mid] > nums[right]` 时 `left = mid + 1`（排除 mid），否则 `right = mid`（保留 mid）。题面保证元素互不相同，所以不会出现 `nums[mid] == nums[right]` 的歧义分支。

## 6. 复杂度

- **时间 O(log n)**：每次循环区间长度从 `right-left+1` 变成大约一半，循环次数是 ⌈log₂n⌉。n 来自数组长度，log n 来自「每轮砍半」这个二分结构。循环体内只有常数次比较和赋值，所以总时间是 O(log n)。
- **空间 O(1)**：只用了 `left`、`right`、`mid` 三个整型变量，与 n 无关。没有递归、没有额外数组。

对比暴力 O(n)：n=5000 时暴力最多 5000 次比较，二分约 13 次，差距随 n 增大而拉大。

## 7. 边界与反例（至少 4 条）

1. **`nums = [1]`** → 期望 `1`。`left=0, right=0`，`while` 条件 `left < right` 不成立，直接返回 `nums[0]`。容易错在：如果写成 `while left <= right` 并在循环里访问 `mid`，单元素时逻辑会绕；或者忘了处理 n=1 的特判。
2. **`nums = [2,1]`** → 期望 `1`。`mid=0`，`nums[0]=2 > nums[1]=1`，`left=1`，循环结束返回 `nums[1]=1`。容易错在：把 `left = mid + 1` 写成 `left = mid`，导致死循环。
3. **`nums = [11,13,15,17]`（旋转 n 次，等于没转）** → 期望 `11`。全程走 `right = mid` 分支，`right` 收到 0。容易错在：误以为「一定有断崖」，写了个「找到第一个下降点」的逻辑，没下降点时返回了错误值或越界。
4. **`nums = [3,4,5,1,2]`** → 期望 `1`。`mid=2`，`nums[2]=5 > nums[4]=2`，`left=3`；`mid=3`，`nums[3]=1 < nums[4]=2`，`right=3`；返回 `nums[3]=1`。容易错在：比较对象写成 `nums[left]` 而不是 `nums[right]`——`nums[mid]` 与 `nums[left]` 比较无法区分「mid 在前段还是后段」，会给出错误方向。
5. **`nums = [4,5,6,7,0,1,2]`（断崖在中间偏右）** → 期望 `0`。见第 3 节走表。容易错在：`right = mid - 1` 把 `mid` 排除了，而 `mid` 恰好可能是最小值，导致漏解。

## 8. 面试追问与变体（3 条）

1. **追问：如果数组元素可以重复（力扣 154）怎么办？** 思路：当 `nums[mid] == nums[right]` 时无法判断方向，只能 `right -= 1` 缩小范围（因为 `nums[right]` 即使是最小值，`nums[mid]` 与它相等，丢掉一个不影响答案），最坏退化为 O(n)。
2. **追问：不返回最小值，而是返回最小值所在的下标？** 思路：二分逻辑完全一样，只是最后返回 `left` 而不是 `nums[left]`；注意重复元素时下标可能不唯一，需按题目要求取最左或最右。
3. **追问：如果数组是「旋转后仍升序」但允许旋转 0 次，且要求 O(log n) 找某个 target（力扣 33）？** 思路：先用本题方法判断 `mid` 在哪一段，再判断 target 落在哪一段的升序区间内，据此收缩边界——本题是那道题的「找断点」子问题。
