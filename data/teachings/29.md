## 1. 一句话本质

在**禁用乘法/除法/取余**的前提下，用「减法 + 倍增」模拟出 `dividend / divisor` 的商，并处理向零截断与 32 位溢出。

## 2. 读完题的第一反应

**朴素解法**：除法就是「被除数里能减掉多少个除数」。比如 `10 / 3`，就循环 `10-3=7, 7-3=4, 4-3=1`，减了 3 次，商是 3。这完全不用乘除取余，符合题意。

**它卡在哪**：如果 `dividend = 2^31-1`、`divisor = 1`，要减 20 多亿次，复杂度 O(商)，必然超时。瓶颈是「一次只减一个 divisor，太慢」。

**关键观察**：既然一次减一个太慢，那就一次减「很多个」。具体说，`divisor` 的 2 倍、4 倍、8 倍……都可以用**加法**（或左移）算出来，不用乘法。于是可以像「凑钱」一样：先看被除数里能装下几个 `divisor × 2^k`，装得下就一次性减掉，商里加上 `2^k`。这就是**倍增（binary lifting）**，把 O(商) 压到 O(log 商)。

另一个必须先处理的坑：题面范围含 `-2^31`，而 `-(-2^31)` 在 32 位里会溢出。所以统一转成**负数**来算（负数范围能容纳 `-2^31`），最后再定符号。

## 3. 从暴力到最优

以 `dividend = 10, divisor = 3` 走一遍。

**暴力**：`10 → 7 → 4 → 1`，减 3 次，商 3。次数 = 商，太大。

**倍增**：先把两数都转成负数：`a = -10, b = -3`（用负数避免溢出）。目标是在 `a` 里数出多少个 `b`。

- 先算 `b` 的倍增表：`-3, -6, -12, ...`，一旦 `< a`（即绝对值超过被除数）就停。这里 `-3, -6` 可用，`-12 < -10` 停。
- 从大到小试：`a = -10` 能装下 `-6` 吗？`-10 <= -6` 成立 → `a = -10 - (-6) = -4`，商 `+= 2`。
- 再试 `-3`：`-4 <= -3` 成立 → `a = -4 - (-3) = -1`，商 `+= 1`。
- `-1` 装不下 `-3`，结束。商 = `2 + 1 = 3`。✅

对比：暴力减了 3 次，倍增只做了 2 次「大减」，且倍增表长度是 log₂(商) 级别。当商是 20 亿时，暴力 20 亿次，倍增约 31 次。

**符号与截断**：商的正负由 `(dividend<0) ^ (divisor<0)` 决定。向零截断在「全转负数算绝对值商」的框架下天然成立——因为我们算的是 `|dividend| / |divisor|` 的整数部分，再补符号，正好是向零截断（`7/-3` 得 `-2`，不是 `-3`）。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说明。设 `a` 为当前剩余的被除数（负数），`ans` 为已累计的商，初始 `a = -|dividend|, ans = 0`。

**不变量**：每一步之后，恒有 `|dividend| = ans × |divisor| + |a|`，且 `0 <= |a| < |divisor| × 2^k`（`k` 为当前还能用的最大倍增层）。

- **不会重**：每次减掉的是 `|divisor| × 2^k`，同时 `ans` 加上 `2^k`，等式两边同步变化，不变量保持，不会多算。
- **不会漏**：倍增表覆盖了 `|divisor| × 2^0, 2^1, ..., 2^m`，任何整数都能用二进制表示，所以 `|dividend|` 的商一定能被这些「二进制块」恰好凑出。循环结束时 `|a| < |divisor|`，说明剩下的不够再减一个除数，`ans` 就是完整商。
- **终止性**：每轮 `a` 严格减小（至少减 `|divisor|`），且 `a` 有下界，必然终止。

符号处理是独立的：`ans` 始终是非负的绝对值商，最后按异或结果取负，不影响上述不变量。

## 5. 完整代码（Python）

```python
class Solution:
    def divide(self, dividend: int, divisor: int) -> int:
        INT_MAX = 2**31 - 1
        INT_MIN = -2**31

        # 唯一会溢出的情况：INT_MIN / -1 = 2^31，超出上界
        if dividend == INT_MIN and divisor == -1:
            return INT_MAX

        # 统一转成负数，避免 -(-2^31) 溢出
        negative = (dividend < 0) ^ (divisor < 0)
        a = -abs(dividend)   # 被除数，负数
        b = -abs(divisor)    # 除数，负数

        ans = 0
        # 当剩余被除数还能减掉至少一个除数时继续
        while a <= b:
            # 构造倍增：value = b, 2b, 4b...  count = 1, 2, 4...
            value = b
            count = 1
            # value + value >= a 保证减完不会「减过头」
            while value + value >= a:
                value += value      # 等价于 value *= 2，但用加法
                count += count      # 等价于 count *= 2
            a -= value              # 一次性减掉 count 个除数
            ans += count

        # 补符号
        return -ans if negative else ans
```

关键点注释已在代码中。注意内层 `value + value >= a` 用加法而非 `<<`，是为了在负数域里语义直观（`-6 + -6 = -12 >= -10` 为假，停）。

## 6. 复杂度

- **时间 O(log |商|)**：外层循环每轮至少消掉当前最高倍增层，商最多 `2^31`，倍增层数约 31；内层每轮把 `value` 翻倍，也是 O(log) 层。严格说外层循环次数 ≤ 31（因为每轮至少减去 `|divisor|` 的某个 2 的幂，商二进制位数有限），内层 ≤ 31，总计 O(log²|商|)，在 32 位下是常数级，可视为 O(log|商|) 的常数倍。**贡献 log 的是「倍增层数」，不是数据规模 n**。
- **空间 O(1)**：只用了 `a, b, ans, value, count` 几个变量，没有数组。倍增表是「边算边用」，不存储。

## 7. 边界与反例（至少 4 条）

1. `dividend = -2^31, divisor = -1` → 期望 `2^31-1` → 容易错：直接算得 `2^31` 溢出，必须先特判返回 `INT_MAX`。
2. `dividend = -2^31, divisor = 1` → 期望 `-2^31` → 容易错：若先 `abs(dividend)` 会溢出，必须用负数域。
3. `dividend = 0, divisor = 5` → 期望 `0` → 容易错：`while a <= b` 中 `a=0, b=-5`，`0 <= -5` 为假，直接返回 0，正确；但若符号处理写反会得 `-0`（Python 里是 0，但逻辑要清楚）。
4. `dividend = 7, divisor = -3` → 期望 `-2` → 容易错：向零截断不是向下取整，`-2.33` 截断是 `-2` 而非 `-3`；用「绝对值商 + 补符号」天然正确。
5. `dividend = 1, divisor = 2` → 期望 `0` → 容易错：`a=-1, b=-2`，`-1 <= -2` 为假，返回 0，正确；若循环条件写成 `<` 会漏掉相等情况。

## 8. 面试追问与变体（3 条）

1. **追问：不能用 `abs` 和 `-` 取负怎么办？** 思路：用位运算或条件判断手动取负，核心仍是「统一到同一符号域 + 倍增」。
2. **追问：如果要求支持 64 位、甚至任意精度大整数呢？** 思路：倍增框架不变，只是溢出特判去掉，`value + value` 用大整数加法，复杂度仍是 O(log 商)。
3. **追问：不用倍增，改用「每次减去除数的最大 2 的幂」的递归写法？** 思路：递归 `divide(a, b) = 2^k + divide(a - b*2^k, b)`，本质与迭代倍增等价，注意递归深度 O(log 商)。
