## 1. 一句话本质

在「每个数都出现 3 次、只有一个数出现 1 次」的数组里，用**按位统计每个二进制位出现 1 的次数并对 3 取模**，把「出现 3 次」这个倍数关系从数值层面搬到比特层面消掉，剩下的就是那个落单的数。

## 2. 读完题的第一反应

**朴素解法**：用哈希表（`dict` 或 `Counter`）统计每个数出现次数，再挑出次数为 1 的那个。时间 O(n)，但空间 O(n)——题目明确要求「常数级空间」，所以这条路被堵死。

**第二个朴素解法**：排序后扫描，相邻三个一组比较。时间 O(n log n)，空间 O(1)（原地排序），但违反「线性时间」。

两个朴素解各自卡在一条约束上：哈希卡空间，排序卡时间。要同时满足 O(n) 时间和 O(1) 空间，就必须找到一种**不依赖额外存储、又能把「三次」这个信息消掉**的运算。

**关键观察**：题目说「其余每个元素恰出现三次」。三次这个数字在**整数加法**里没有特殊性质（3 不是 0），但在**二进制按位**的视角下，它意味着：对任意一个二进制位，如果这个位不属于答案，那么它被「凑满」的次数一定是 3 的倍数（因为每个非答案数贡献 3 次，答案在该位是 0 时贡献 0 次）。于是「该位 1 的总个数 mod 3」就精确等于「答案在该位的值」。

这个观察之所以能直接落地，是因为**按位统计是线性的、且只需要常数个计数器**——每个二进制位一个计数器，而 int 只有 32 位，所以是 O(1) 空间。这就是从「数值层面」跳到「比特层面」带来的收益。

## 3. 从暴力到最优

**第一步：哈希表。** 遍历 nums，`cnt[x] += 1`，最后返回 `cnt[x] == 1` 的 x。时间 O(n)，空间 O(不同元素个数) = O(n)。瓶颈：空间。

**第二步：排序。** `nums.sort()` 后每三个一组比较。时间 O(n log n)，空间 O(1)。瓶颈：时间。

**第三步：按位取模。** 对 32 个二进制位分别统计 1 的个数，对 3 取模，拼回答案。时间 O(32n) = O(n)，空间 O(1)。

用示例 1 `nums = [2, 2, 3, 2]` 走一遍（只看低 2 位，高位全是 0）：

| 数 | 二进制（低 2 位） |
|---|---|
| 2 | 10 |
| 2 | 10 |
| 3 | 11 |
| 2 | 10 |

- 第 0 位（最低位）：2,2,3,2 分别是 0,0,1,0 → 1 的个数 = 1 → 1 mod 3 = **1**
- 第 1 位：分别是 1,1,1,1 → 1 的个数 = 4 → 4 mod 3 = **1**

拼起来：`11` = 3。✓

再看示例 2 `nums = [0,1,0,1,0,1,99]`，只看低 2 位：

| 数 | 低 2 位 |
|---|---|
| 0 | 00 |
| 1 | 01 |
| 0 | 00 |
| 1 | 01 |
| 0 | 00 |
| 1 | 01 |
| 99 | 11 |

- 第 0 位：0,1,0,1,0,1,1 → 1 的个数 = 4 → 4 mod 3 = **1**
- 第 1 位：0,0,0,0,0,0,1 → 1 的个数 = 1 → 1 mod 3 = **1**

低 2 位是 `11`，高位继续算下去得到 99。✓

**第四步（可选优化）：用两个状态变量代替 32 个计数器。** 上面的做法需要 32 个计数器（其实一个 `ans` 变量加循环内临时计数即可，空间仍是 O(1)）。更优雅的写法是用两个整数 `ones` 和 `twos` 表示「当前位出现 1 次 / 2 次」的状态，每读一个数就做状态转移：

```
ones = (ones ^ x) & ~twos
twos = (twos ^ x) & ~ones
```

含义：`ones` 记录「到目前为止该位 1 的个数 mod 3 == 1」的位，`twos` 记录「mod 3 == 2」的位。读到 x 时，x 为 1 的位在 ones 和 twos 之间轮转：0→1→2→0。最后 `ones` 就是答案。这个写法把「32 个计数器」压成「2 个整数」，是位运算题的标准套路，但**理解上先掌握第三步的「按位取模」更稳**，第四步是它的状态机压缩版。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证。

**不变量**：处理完前 k 个元素后，对任意二进制位 b，`count[b] mod 3` 等于「前 k 个元素中，位 b 上 1 的个数 mod 3」。

- 初始 k=0，所有 count 为 0，不变量成立。
- 归纳步：读入第 k+1 个数 x，对每个位 b，若 x 的位 b 为 1 则 count[b] 加 1，否则不变。mod 3 的语义在加法下保持，不变量继续成立。

**收尾**：处理完全部 n 个元素后，对位 b：
- 若答案 ans 的位 b 为 0：所有非答案数在该位贡献的 1 的个数是 3 的倍数（每个数出现 3 次），答案贡献 0，所以总数 mod 3 = 0。
- 若 ans 的位 b 为 1：非答案数贡献 3 的倍数，答案贡献 1，总数 mod 3 = 1。

因此 `count[b] mod 3` 恰好等于 ans 的位 b。逐位拼回即得 ans。**不会漏**：每一位都被独立计算；**不会重**：每一位只对应 ans 的一个确定位，拼回是唯一确定的整数。

**负数怎么办？** Python 的整数是任意精度、负数用补码语义但位运算按无限符号位处理。`x & 1` 对负数仍取最低位，`x >> 1` 对负数会保留符号位（算术右移），所以逐位取模时高位会一直得到 1（因为负数高位全是 1）。这会污染结果。**处理办法**：只统计低 32 位（题目保证 int32），最后若第 31 位为 1 则减去 2^32 还原成负数。代码里体现这一点。

## 5. 完整代码（Python）

```python
class Solution:
    def singleNumber(self, nums: list[int]) -> int:
        # 用 32 个比特位分别统计 1 的个数 mod 3
        # ans 的每一位由「该位 1 的总数 mod 3」决定
        ans = 0
        for b in range(32):                 # 题目保证 int32，只看低 32 位
            cnt = 0                         # 当前位 b 上 1 的个数
            for x in nums:
                # 取 x 的第 b 位（对负数也正确：& 1 只看最低位）
                cnt += (x >> b) & 1
            # cnt mod 3 就是答案在第 b 位的值
            if cnt % 3 == 1:
                ans |= (1 << b)
        # Python 整数无溢出，若第 31 位为 1 说明答案是负数，需还原
        if ans >= (1 << 31):
            ans -= (1 << 32)
        return ans
```

**更紧凑的 O(1) 状态机写法**（面试可加分，但先讲清上面的版本）：

```python
class Solution:
    def singleNumber(self, nums: list[int]) -> int:
        ones = twos = 0
        for x in nums:
            # 状态转移：ones 记 mod3==1 的位，twos 记 mod3==2 的位
            ones = (ones ^ x) & ~twos
            twos = (twos ^ x) & ~ones
        # 结束时 ones 就是只出现一次的数（负数也正确，因为按 32 位补码语义）
        return ones
```

第二版对负数的处理依赖 Python 的无限符号位补码语义，`~twos` 在 Python 里是无限位取反，但配合 `&` 后高位会被 `ones ^ x` 的有限位截断，实际结果正确；不过**面试时建议先写第一版讲清原理，再提第二版作为优化**，避免被追问时说不清负数细节。

## 6. 复杂度

**第一版（逐位统计）**：
- 时间：外层 32 次，内层 n 次，共 32n 次基本操作 → **O(32n) = O(n)**。这里的 32 是 int 的位数，是常数，不随 n 增长。
- 空间：`ans`、`cnt`、循环变量 b，常数个 → **O(1)**。

**第二版（状态机）**：
- 时间：遍历 n 个数，每个数做常数次位运算 → **O(n)**。
- 空间：`ones`、`twos` 两个整数 → **O(1)**。

注意：这里**没有 log n 的项**。log n 通常来自「按位分解一个数」或「二分」，本题的 32 是**数据类型的位宽**，与 n 无关，所以是常数。如果题目把 int 换成任意精度大整数，位宽会变成 O(log(max值))，那时才需要把 32 换成动态位宽。

## 7. 边界与反例（至少 4 条）

1. **`nums = [1]`** → 期望 `1` → 容易错：忘记处理「只有一个元素」的情况，或循环里 `cnt % 3` 逻辑写反（写成 `== 0` 就返回 0 了）。
2. **`nums = [-2, -2, -2, -3]`** → 期望 `-3` → 容易错：负数在 Python 里高位全是 1，逐位统计时若循环到 32 位以上会得到错误的高位；必须限定 32 位并在最后做 `ans -= 2^32` 的符号还原。
3. **`nums = [0, 0, 0, 5]`** → 期望 `5` → 容易错：0 的每一位都是 0，若把「cnt % 3 == 1」误写成「cnt % 3 != 0」，0 的位会被误判；另外答案 5 的位分布要正确拼回。
4. **`nums = [2^31 - 1, 2^31 - 1, 2^31 - 1, 1]`**（即 `[2147483647, 2147483647, 2147483647, 1]`）→ 期望 `1` → 容易错：最大值占满 31 位，若位宽只算到 30 位会漏掉最高位；必须循环到 32 位（含符号位）。
5. **`nums = [-1, -1, -1, 0]`** → 期望 `0` → 容易错：-1 的 32 位全是 1，三个 -1 让每一位的 1 的个数都是 3 的倍数，答案 0 的每一位都应是 0；若符号还原逻辑写错（比如无条件 `ans -= 2^32`），会把 0 变成负数。

## 8. 面试追问与变体（3 条）

1. **追问：如果其他数出现 k 次（k 任意），怎么改？** 思路：把「mod 3」换成「mod k」，逐位统计后取模即可；若 k 很大，用状态机需要 log k 个状态变量，或直接用逐位统计版。
2. **追问：如果有两个数各出现一次、其余出现两次（即题 260），怎么做？** 思路：全体异或得到 `a ^ b`，取最低的 1 位把数组分成两组，分别异或得到 a 和 b——从「按位取模」退化成「按位分组」。
3. **追问：不用位运算，能不能 O(1) 空间？** 思路：理论上需要「计数」信息，纯算术难以在 O(1) 空间内区分 3 次与 1 次；位运算是这道题在 O(1) 空间下的自然选择，可以反问面试官是否允许修改原数组（若允许，可用原地标记法，但会破坏数据）。

## 9. 举一反三（2-3 道同类题）

1. **136. 只出现一次的数字**：其他数出现 2 次，用全体异或即可——是本题「mod 2」的退化版，共同点是「用位运算消掉成对/成倍出现的数」。
2. **260. 只出现一次的数字 III**：两个数各出现一次、其余两次，用「异或 + 按最低 1 位分组」——共同点是「按位分析出现次数的奇偶性」。
3. **面试题 17.19. 消失的两个数字**：1~n 中缺两个数，用「异或 + 分组」或「求和差 + 按位分组」——共同点是把「缺失/落单」转化为「按位统计后取模或分组」。
