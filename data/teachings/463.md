## 1. 一句话本质

对每个陆地格子，数它**四条边里有多少条贴着水或贴着网格外部**，把所有陆地格子的这个数加起来。

## 2. 读完题的第一反应

**朴素解法**：把每个陆地格子的 4 条边都先算成周长（`4 * 陆地格子数`），然后看相邻关系。最直觉的写法是：对每个格子，检查它上下左右四个邻居，每有一个邻居是陆地，就说明这条边被两个陆地格子共享、不算外周长，减掉 1。

这个思路本身是对的，但它卡在一个地方：**你会对同一条共享边数两次**。格子 A 和格子 B 相邻，从 A 看过去 B 是陆地，减 1；从 B 看过去 A 也是陆地，又减 1。所以如果你对每个格子都做「4 减邻居陆地数」，得到的是正确答案；但如果你先算 `4*N` 再遍历所有相邻对去减，就得小心别重复减。这是第一个容易踩的坑，不是复杂度瓶颈。

真正的复杂度瓶颈在**怎么找到所有陆地格子**。如果岛屿形状复杂，你不能只扫一遍就完事——你需要知道哪些格子属于同一个连通块，或者至少需要一种方式保证每个陆地格子都被处理且只处理一次。朴素的「对每个格子做一次 BFS/DFS 找连通块」是 O((row·col)²)，因为每个格子都可能触发一次全图搜索。

**关键观察**：题目保证「恰好有一个岛屿」。这句话是整个解法的支点。它意味着你**不需要判断连通性**——所有值为 1 的格子天然属于同一个岛屿。于是你根本不用 BFS/DFS，直接双重循环扫一遍整个网格，对每个 1 做局部计算就行。连通性这个通常最麻烦的部分，被题面条件直接消掉了。

## 3. 从暴力到最优

**暴力版（会重复计数）**：

```
perimeter = 0
for 每个格子 (i,j):
    if grid[i][j] == 1:
        for 四个方向 (di,dj):
            if 邻居越界 或 grid[ni][nj] == 0:
                perimeter += 1
```

这其实已经是 O(row·col) 了，因为每个格子只看 4 个邻居，是常数时间。所以「暴力」和「最优」在复杂度上没差别——这题的优化空间不在渐进复杂度，而在**代码是否干净、是否容易写错**。

**更简洁的等价写法**：先假设每个陆地格子贡献 4 条边，然后每发现一对相邻的陆地，就减 2（因为这条共享边在两个格子的 4 条边里各被算了一次，实际它不贡献周长）。

用小例子走一遍，`grid = [[1,1],[1,0]]`：

- 陆地格子数 = 3，初始 `perimeter = 4*3 = 12`。
- 扫描相邻对（只看右和下，避免重复）：
  - (0,0) 的右边是 (0,1)，都是 1 → `perimeter -= 2` → 10
  - (0,0) 的下边是 (1,0)，都是 1 → `perimeter -= 2` → 8
  - (0,1) 的下边是 (1,1)，是 0 → 不减
  - (1,0) 的右边是 (1,1)，是 0 → 不减
- 结果 8。

验证：这个 L 形三格，外周长确实是 8（画一下：三个方块拼成 L，外轮廓 8 条单位边）。

**为什么「只看右和下」不会漏**：每一对相邻陆地，要么是左右相邻（左边格子的「右」方向能发现），要么是上下相邻（上面格子的「下」方向能发现）。只扫两个方向，恰好每对相邻陆地被数一次，不重不漏。这就是「交换论证」式的思路——把「所有相邻对」这个集合，按「由哪个格子负责发现」重新划分，每个相邻对恰好归属一个格子。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义：

> 对任意时刻，`perimeter` 的值 = 「已经被处理过的陆地格子所贡献的、尚未被相邻陆地抵消的边数」。

**初始**：处理 0 个格子，`perimeter = 0`，不变量成立。

**归纳步**：每遇到一个陆地格子，先 `+4`（它最多贡献 4 条边），然后检查它的**右**和**下**邻居。如果邻居是陆地，说明这条边被两个格子共享，从周长里扣掉 2（这个格子自己多算的 1 条 + 邻居将来会多算的 1 条，但邻居还没处理，所以这里先扣 2 是为了让最终账平）。

关键点：**每条共享边恰好被扣一次**。因为一对相邻陆地只有两种相对位置——左右或上下——而我们的扫描方向固定为「右」和「下」，所以这对相邻关系只会从位置更靠上/靠左的那个格子被发现一次。不会从两个方向各发现一次。

**终止**：所有格子处理完，每条陆地边要么是外边界（贡献 1），要么是共享边（贡献 0，因为 +4 后被 -2 两次覆盖……准确说，一条共享边涉及两个格子，每个格子 +4 时都把它算进去了，共算 2 次，扣 2 后净贡献 0）。所以最终 `perimeter` 恰好等于所有外边界边数，即周长。

**为什么「恰好一个岛屿」这个条件在这里用到了**：其实上面的计数法**不需要**这个条件——即使有多个岛屿，每个岛屿各自算周长再相加，结果也对。这个条件真正省掉的是「你不需要用 BFS/DFS 去分组」。如果题目改成「求最大岛屿的周长」，你就必须先找连通块了。所以这里要明确：条件让解法从「BFS + 计数」退化成「纯计数」，这是本题被标为「简单」的核心原因。

## 5. 完整代码（Python）

```python
class Solution:
    def islandPerimeter(self, grid) -> int:
        rows = len(grid)
        cols = len(grid[0])
        perimeter = 0

        for i in range(rows):
            for j in range(cols):
                if grid[i][j] != 1:
                    continue
                # 先假设这个陆地格子贡献 4 条边
                perimeter += 4
                # 只看「右」和「下」两个方向，保证每对相邻陆地只被数一次
                # 右边是陆地：这条共享边不该算周长，扣 2
                if j + 1 < cols and grid[i][j + 1] == 1:
                    perimeter -= 2
                # 下边是陆地：同理扣 2
                if i + 1 < rows and grid[i + 1][j] == 1:
                    perimeter -= 2

        return perimeter
```

这段代码没有用 DFS/BFS，因为题面保证只有一个岛屿，连通性不需要判断。如果面试官追问「如果有多个岛屿、要求总周长」，这段代码**依然正确**——它统计的是所有陆地的外边界总和，与岛屿个数无关。这一点值得在面试时主动说出来，显示你理解了自己解法的适用边界。

## 6. 复杂度

- **时间**：O(row · col)。双重循环遍历每个格子一次，每个格子内部做常数次判断（最多 2 次邻居检查）。`row · col` 就是网格总格子数，题面限制 ≤ 100×100，所以最多 10⁴ 次操作。
- **空间**：O(1)。只用了 `rows`、`cols`、`perimeter` 三个标量，没有额外数组、没有递归栈。对比 BFS 解法需要 O(row·col) 的 visited 集合或队列，这是本解法的一个实际优势。

注意：这里没有 log 项，因为没有任何排序或二分操作。

## 7. 边界与反例（至少 4 条）

1. **输入 `[[1]]` → 期望 4**。容易错在：忘记处理「邻居越界」的情况，直接访问 `grid[i][j+1]` 会 IndexError。代码里用 `j + 1 < cols` 短路保护，顺序不能反（先判断边界再访问）。
2. **输入 `[[1,0]]` → 期望 4**。容易错在：以为「右边是 0」要扣分。实际上右边是水，这条边就是外周长，不扣。只有右边是**陆地**才扣 2。
3. **输入 `[[1,1],[1,1]]`（2×2 全陆地）→ 期望 8**。容易错在：只扣一次共享边。2×2 有 4 对相邻陆地（两条横、两条竖），初始 16，扣 4×2 = 8，得 8。如果只扫「右」不扫「下」，会漏掉竖边，得 12，错。
4. **输入 `[[0,1,0],[1,1,1],[0,1,0]]`（十字形）→ 期望 12**。容易错在：中心格子的 4 条边全是共享边，它自己贡献 0；四个臂各贡献 3（4 减 1 条共享）。初始 5×4 = 20，共享边 4 对，扣 8，得 12。如果误以为中心格子也要算周长，会多算。
5. **输入 `[[0]]`（全是水，虽然题面说恰好一个岛屿，但防御性考虑）→ 期望 0**。代码里 `grid[i][j] != 1` 直接 continue，返回 0，不会崩。这条是「题面条件之外」的鲁棒性检查。

## 8. 面试追问与变体（3 条）

1. **追问：如果网格里有多个岛屿，要求返回每个岛屿的周长列表，怎么做？**
   思路：必须用 BFS/DFS 或并查集先分组，对每个连通块单独跑上面的计数逻辑，把结果收集起来。分组是 O(row·col)，每组计数也是 O(该组格子数)，总时间仍是 O(row·col)。

2. **追问：如果允许岛屿有「湖」（内部水域），周长怎么变？**
   思路：湖的边界也算周长的一部分——因为湖是水，陆地格子贴着湖的那条边仍然是外边界。上面的计数法**天然正确**，因为它只看「邻居是不是陆地」，邻居是水（不管是外部水还是湖）都算周长。所以这题的条件「没有湖」其实也是多余的，可以主动指出。

3. **追问：不用「+4 再减 2」，直接对每个陆地格子数「贴水或贴边界的边数」，两种写法等价吗？**
   思路：等价。直接数法对每个格子检查 4 个方向，越界或为 0 就 +1；+4 减 2 法把「4 个方向都算」和「共享边抵消」拆成两步。前者代码稍长但更直观，后者更短但需要想清楚「为什么减 2 而不是减 1」。面试时建议先讲直接数法，再提优化写法。

## 9. 举一反三（2-3 道同类题）

1. **力扣 200. 岛屿数量**：同样是在网格上找连通块，但这里需要**数连通块个数**，必须用 BFS/DFS 或并查集，不能像本题一样纯计数。对比着做，能看清「什么时候连通性信息是必需的」。
2. **力扣 695. 岛屿的最大面积**：在 200 的基础上，BFS/DFS 时累加格子数取最大值。和本题的共同点是都在网格上做局部邻居检查，区别是本题只关心边界、不关心分组。
3. **力扣 733. 图像渲染（Flood Fill）**：从起点出发把连通区域染成新颜色，是 BFS/DFS 在网格上的最基础模板。做完本题再做 733，会发现「网格 + 四方向」这套骨架是通用的，变的只是「在遍历时统计什么」。
