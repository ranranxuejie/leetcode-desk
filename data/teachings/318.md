## 1. 一句话本质

在 n 个单词里挑一对「字母集合不相交」的单词，让它们长度乘积最大——本质是**把"字母集合是否相交"这个判断从 O(L) 的字符串比较，压缩成 O(1) 的整数位与运算**。

## 2. 读完题的第一反应

朴素解法很直接：两两枚举 (i, j)，对每一对检查是否有公共字母，没有就更新答案。

卡在哪？检查公共字母这一步。最笨的写法是双重循环比对两个单词的每个字符，单次检查 O(L²)；好一点用集合求交集，单次 O(L)。总复杂度 O(n² · L)。代入数据范围：n ≤ 1000，L ≤ 1000，最坏 1000² × 1000 = 10⁹ 量级，Python 里必然超时。

关键观察来自提示里的那句话：**words[i] 仅包含小写字母**。小写字母只有 26 个。这意味着一个单词的"字母集合"可以被一个 26 位的二进制数完整表示——第 k 位为 1 表示字母表第 k 个字母出现过。于是"两个单词有没有公共字母"就等价于"两个掩码按位与是否为 0"。一次位与是 O(1) 的机器指令，把最贵的那一步直接消掉了。

这个观察之所以能立刻指向下一步，是因为它把**集合语义**映射到了**整数语义**：集合的交非空 ↔ 位与非零。一旦建立这个映射，后面所有操作都变成整数运算。

## 3. 从暴力到最优

**第一步：暴力枚举 + 集合检查。** 对每对 (i, j)，`set(words[i]) & set(words[j])` 判空。瓶颈在单次检查 O(L)，总计 O(n²L)。

**第二步：预计算掩码。** 每个单词只算一次掩码，之后每对比较只做一次 `mask[i] & mask[j] == 0`。预计算 O(nL)，两两比较 O(n²)。总复杂度降到 O(nL + n²)。这是本题的标准解法。

**第三步（可选优化）：同掩码去重。** 如果两个单词掩码相同，它们字母集合一样，长度短的永远不可能赢——保留最长的那个即可。用字典 `mask -> 最大长度` 去重，把参与两两比较的候选数从 n 降到「不同掩码的个数」，最多 2²⁶ 但实际远小于 n。这一步在 n 大、单词短时收益明显，但最坏情况（n=1000 且掩码全不同）退化为原复杂度，所以是常数级优化而非复杂度优化。

**小例子走一遍**，用示例 1：`["abcw","baz","foo","bar","xtfn","abcdef"]`。

先算掩码（a=第0位，b=第1位，…）：

| 单词 | 字母集合 | 掩码（二进制，只列低位） |
|---|---|---|
| abcw | {a,b,c,w} | 0b1000_0000_0000_0111 = 2055 |
| baz | {b,a,z} | 0b1000_0000_0000_0011 = 2051 |
| foo | {f,o} | 0b0010_0000_0010_0000 = 8224 |
| bar | {b,a,r} | 0b0001_0000_0000_0011 = 4099 |
| xtfn | {x,t,f,n} | 0b0100_1000_0010_0100 = 18500 |
| abcdef | {a..f} | 0b0000_0000_0011_1111 = 63 |

两两检查，看 `mask[i] & mask[j]`：

- abcw & baz = 2055 & 2051 = 2051 ≠ 0（共享 a、b），跳过
- abcw & xtfn = 2055 & 18500 = 0 ✓，长度 4×4 = 16，更新答案 = 16
- baz & foo = 2051 & 8224 = 0 ✓，3×3 = 9，不更新
- abcw & abcdef = 2055 & 63 = 7 ≠ 0，跳过
- ……

最终答案 16，对应 "abcw" 和 "xtfn"，与官方一致。

注意 `abcw & xtfn = 0` 这个判断：2055 的低位是 a、b、c、w，18500 的位是 x、t、f、n，两组位完全不重叠，位与自然为 0。整个过程没有任何字符串遍历，全是整数运算。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：在枚举到第 k 对 (i, j) 时，`ans` 等于「前 k 对中所有字母不相交的单词对的长度乘积最大值」。

- **初始**：k=0，`ans=0`，空集的最大值定义为 0，成立。
- **保持**：处理第 k+1 对时，若 `mask[i] & mask[j] != 0`，说明有公共字母，该对不合法，`ans` 不变，不变量保持；若为 0，该对合法，`ans = max(ans, len_i * len_j)`，恰好把新合法对纳入考虑，不变量保持。
- **终止**：枚举完所有 C(n,2) 对，`ans` 是所有合法对的最大值。

**不漏**：任意一对合法的 (i, j) 都恰好被枚举一次（i < j 的双重循环覆盖所有无序对），所以任何合法解都会被算到。

**不重**：每对只算一次乘积，`max` 操作对重复值不敏感，即使有多个相同最大值也只保留一个，不影响结果。

**掩码等价性**：需要单独说明 `mask[i] & mask[j] == 0` 与「两单词无公共字母」严格等价。掩码第 k 位为 1 当且仅当该字母在单词中出现过（由构造保证）。位与第 k 位为 1 当且仅当两个单词都含该字母。所以位与为 0 ↔ 不存在任何字母同时出现在两个单词中 ↔ 无公共字母。这个双向蕴含是整道题正确性的基石。

## 5. 完整代码（Python）

```python
class Solution:
    def maxProduct(self, words: list[str]) -> int:
        # 第一步：为每个单词计算 26 位掩码，同时用字典去重
        # key = 掩码，value = 该掩码下出现过的最长单词长度
        best_len = {}
        for w in words:
            mask = 0
            for ch in w:
                # ord(ch) - ord('a') 得到 0..25，左移后置位
                mask |= 1 << (ord(ch) - ord('a'))
            # 同一掩码只保留最长长度：短的那个永远不可能赢
            if len(w) > best_len.get(mask, 0):
                best_len[mask] = len(w)

        # 第二步：把去重后的 (掩码, 长度) 拉成列表，两两枚举
        items = list(best_len.items())  # [(mask, length), ...]
        ans = 0
        m = len(items)
        for i in range(m):
            mask_i, len_i = items[i]
            for j in range(i + 1, m):
                mask_j, len_j = items[j]
                # 位与为 0 表示字母集合不相交
                if mask_i & mask_j == 0:
                    ans = max(ans, len_i * len_j)
        return ans
```

关键逻辑说明：

- `mask |= 1 << (ord(ch) - ord('a'))`：把字符映射到 0~25 的位下标并置位，重复字母重复置位无副作用（幂等）。
- `best_len` 去重：掩码相同意味着字母集合相同，长度短的单词在任何配对里都不如长度长的，直接丢弃是安全的。
- 内层 `mask_i & mask_j == 0`：这是整个算法的核心判断，替代了字符串层面的公共字母检查。
- `ans` 初值 0：覆盖「不存在合法对」的情况，直接返回 0，与示例 3 一致。

## 6. 复杂度

设 n = words.length，L = 单词平均长度，U = 去重后不同掩码的个数（U ≤ n）。

**时间**：

- 计算掩码：每个单词遍历一次，O(nL)。这里的 L 是单词长度，来自题面 `words[i].length ≤ 1000`。
- 两两枚举：O(U²)，U ≤ n，最坏 O(n²)。
- 合计 O(nL + n²)。注意 n² 项与 L 无关——这正是位运算把字符串比较消掉的结果。原暴力是 O(n²L)，现在 L 只出现在一次性的预计算里。

**空间**：

- `best_len` 字典最多存 U 个键值对，O(U) ≤ O(n)。
- `items` 列表 O(U)。
- 每个掩码是 26 位整数，常数空间。
- 合计 O(n)。没有 O(nL) 的字符串存储，因为掩码是就地算完即弃的。

对比：如果不去重，空间仍是 O(n)，时间 O(nL + n²)，去重只是把 U 压小，不改变最坏复杂度。

## 7. 边界与反例（至少 4 条）

1. **输入 `["a","aa","aaa","aaaa"]` → 期望 0**。所有单词都只含字母 a，任意两两都有公共字母，没有合法对。容易错在：忘记 `ans` 初值为 0 直接返回，或误以为长度乘积最大的是 "aaa"×"aaaa"。实际必须返回 0。

2. **输入 `["abc","def"]` → 期望 3**。两个单词字母完全不相交，唯一一对合法，乘积 3×3=9？不对——"abc" 长度 3，"def" 长度 3，乘积 9。容易错在：把长度当成字母个数以外的量，或漏掉唯一一对导致返回 0。正确答案是 9。

3. **输入 `["ab","cd","ef"]` → 期望 4**。三对都合法，乘积都是 2×2=4。容易错在：只检查相邻对，或去重逻辑写错把不同掩码误合并。

4. **输入 `["a","b"]` → 期望 1**。两个单字母单词，字母不同，乘积 1×1=1。容易错在：把 `ans` 初值设成 1 或 -1，或对单字母单词的掩码计算越界（`ord('a')-ord('a')=0`，左移 0 位得 1，正确）。

5. **输入 `["aa","bb"]` → 期望 4**。重复字母不影响掩码（"aa" 掩码只有 a 位），两词不相交，2×2=4。容易错在：以为重复字母会让掩码出错，或去重时把 "aa" 和 "a" 当成不同掩码——它们掩码相同，若同时出现应只保留 "aa"。

## 8. 面试追问与变体（3 条）

1. **追问：如果字母表不是 26 个小写字母，而是全部 Unicode，怎么办？** 思路：位掩码失效（位数爆炸），退回用 `set` 求交集，或对每个单词排序后双指针判交，复杂度回到 O(n²L)，此时要考虑用倒排索引或分块优化。

2. **追问：如果要求三个单词两两不含公共字母，最大长度乘积？** 思路：三重枚举 O(n³) 配掩码判断，或用「按掩码分组 + 枚举子集」的技巧，把三数问题转成对每个掩码找其补集的子集最大值。

3. **追问：不要求两两不相交，而是要求所有单词的并集字母数不超过 k，最大长度和？** 思路：这是带约束的子集选择，掩码做状态，转化为 0/1 背包或状压 DP，状态是「已用字母掩码」，值是最长总长度。
