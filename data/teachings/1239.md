## 1. 一句话本质

从最多 16 个字符串里挑一个子集，按原顺序拼起来，要求拼出的结果里**每个字母最多出现一次**，求能拼出的最长长度。

注意这里有个容易被题面绕晕的点：题面说「子序列」，但实际约束是「从数组里挑若干个字符串、保持相对顺序拼接」。因为拼接顺序不影响最终字符集合是否冲突，所以「保持顺序」这个条件对答案没有任何影响——我们真正要决策的只是**选哪些字符串**。这个等价转换是后面所有推理的地基。

## 2. 读完题的第一反应

**朴素解法**：枚举 arr 的所有子集（2^16 = 65536 个），对每个子集把字符串拼起来，检查有没有重复字母，合法就更新最大长度。

它卡在哪？每个子集拼接 + 检查的代价是 O(总字符数)，总字符数最坏 16×26 = 416。于是 65536 × 416 ≈ 2700 万次字符操作。这个量级在 Python 里其实**勉强能过**，但很悬，而且每次都要重新拼字符串、重新扫重复，非常浪费。瓶颈在于：**大量子集在拼接早期就已经冲突了，我们却拼完才检查**。

**关键观察**：判断「有没有重复字母」根本不需要字符串本身，只需要知道**这个字符串里出现了哪些字母**。26 个小写字母，正好可以用一个 26 位整数的二进制位来表示——第 i 位为 1 表示字母 `chr(97+i)` 出现过。于是：

- 单个字符串是否内部有重复 → 看它自己的位掩码有没有「某位被置两次」，即 `len(s) != popcount(mask)`；
- 两个字符串能否拼接 → 看两个掩码按位与是否为 0；
- 拼接后的掩码 → 直接按位或。

这一步把「字符串比较」降维成了「整数位运算」，是整道题的转折点。为什么能想到？因为约束里明晃晃写着「只含小写英文字母」且长度 ≤ 26，这就是在暗示你：字母表很小，用位压缩。

## 3. 从暴力到最优

**第一步：预处理成掩码。** 对每个 `arr[i]` 算出掩码，同时如果它自身就有重复字母（比如 `"act"` 里没有，但 `"aab"` 有），这个字符串**永远不可能被选**，直接丢弃。示例 2 的 `arr = ["cha","r","act","ers"]`：

| 字符串 | 掩码（二进制示意） | 自身合法？ |
|---|---|---|
| "cha" | 位 c,h,a 置 1 | 是 |
| "r" | 位 r 置 1 | 是 |
| "act" | 位 a,c,t 置 1 | 是 |
| "ers" | 位 e,r,s 置 1 | 是 |

**第二步：在掩码上做回溯。** 维护当前已选集合的掩码 `cur` 和当前长度 `length`。对每个候选字符串，若 `cur & mask == 0` 就选它（`cur |= mask`，`length += len(s)`），递归；否则跳过。示例 2 走一遍：

- 选 "cha"：cur = {c,h,a}，len = 3
  - 试 "r"：cur & {r} = 0，选 → cur = {c,h,a,r}，len = 4
    - 试 "act"：{a,c,t} & cur ≠ 0（a、c 冲突），跳过
    - 试 "ers"：{e,r,s} & cur ≠ 0（r 冲突），跳过 → 此路得 4
  - 试 "act"：{a,c,t} & {c,h,a} ≠ 0，跳过
  - 试 "ers"：{e,r,s} & {c,h,a} = 0，选 → cur = {c,h,a,e,r,s}，len = 6
    - 试 "act"：冲突，跳过 → 得 6
- 选 "r" 起头：... 最终 "r"+"act"+"ers" 冲突（r 重复），得 4
- 选 "act" 起头：+"ers" 冲突（无冲突？{a,c,t} & {e,r,s}=0，选 → len=6）→ 得 6

最大 6，与答案一致。

**第三步：为什么这就够了？** 因为 2^16 个子集的问题被压成了「在掩码上做带剪枝的 DFS」，而位运算判断冲突是 O(1) 的整数操作，比字符串扫描快一个数量级。更关键的是，**冲突一旦发生就立刻剪枝**，不会像暴力那样拼完再发现。

**还能不能更快？** 可以。注意到「选哪些字符串」和顺序无关，可以用**迭代式状态压缩 DP**：`dp[mask] = 能拼出掩码 mask 的最长长度`，逐个字符串更新。但 arr 长度 16、每个字符串掩码是 26 位，状态空间是 2^26 而非 2^16，直接 DP 不划算。所以本题**回溯 + 位掩码**就是标准最优解，官方题解也是这个思路。面试时提一句「可以用 DP 但状态空间更大，回溯更合适」是加分项。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在回溯的任意时刻，`cur` 的每个二进制位至多被置 1 一次，且 `length` 恰好等于「已选字符串长度之和」，也等于 `cur` 中 1 的个数（因为每个被选字符串内部无重复，且与之前选的两两不冲突）。

**不会漏**：我们枚举的是「从 arr 中选子集」的所有可能。对任意一个合法子集 S，按 arr 的下标从小到大依次尝试，每次该字符串与当前 `cur` 都无冲突（因为 S 整体合法），所以 DFS 一定会沿着「选它」的分支走下去，最终到达 S 对应的状态并更新答案。归纳一下：DFS 在第 k 层枚举了「前 k 个字符串中所有合法子集」，第 k+1 层在此基础上加/不加第 k+1 个，覆盖全部。

**不会重**：每个子集只对应 DFS 树中唯一一条「选/不选」的路径（按下标顺序决策），不存在两种不同路径到达同一子集。因此不会重复计算，也不会因为顺序不同而重复统计。

**剪枝的正确性**：当 `cur & mask != 0` 时跳过，是因为任何包含该字符串的集合都会让某个字母出现两次，必然非法。这个剪枝只删掉非法解，不影响合法解，所以不破坏「不漏」。

## 5. 完整代码（Python）

```python
class Solution:
    def maxLength(self, arr) -> int:
        # 第一步：把每个字符串压成 26 位掩码，丢弃自身有重复字母的
        masks = []
        for s in arr:
            m = 0
            ok = True
            for ch in s:
                bit = 1 << (ord(ch) - ord('a'))
                if m & bit:      # 该字母在本字符串内已出现过 → 自身非法
                    ok = False
                    break
                m |= bit
            if ok:
                masks.append((m, len(s)))  # 存 (掩码, 长度)

        self.best = 0

        def dfs(idx, cur_mask, cur_len):
            # 每到一个状态就尝试更新答案（空集也合法，best 初值 0）
            if cur_len > self.best:
                self.best = cur_len
            if idx == len(masks):
                return
            # 分支一：不选第 idx 个字符串
            dfs(idx + 1, cur_mask, cur_len)
            # 分支二：选它（前提是与当前已选集合无字母冲突）
            m, l = masks[idx]
            if cur_mask & m == 0:
                dfs(idx + 1, cur_mask | m, cur_len + l)

        dfs(0, 0, 0)
        return self.best
```

关键逻辑说明：`m & bit` 检测单字符串内部重复；`cur_mask & m == 0` 检测跨字符串冲突；`cur_mask | m` 合并字母集合；`cur_len + l` 累加长度。DFS 先走「不选」再走「选」，两种分支都覆盖，保证不漏。

## 6. 复杂度

设 n = arr 长度（≤16），L = 单个字符串最大长度（≤26），总字符数 T = Σ|arr[i]| ≤ 416。

- **预处理**：O(T)，每个字符做一次移位和按位与。
- **回溯**：最坏枚举 2^n 个状态，每个状态做 O(1) 位运算，故 O(2^n)。n=16 时约 65536 个状态，非常快。
- **总时间**：O(T + 2^n)。注意这里**没有 log n**——位运算是常数时间，n 只出现在指数上。
- **空间**：递归栈深度 O(n)，`masks` 数组 O(n)，合计 O(n)。没有额外的 2^n 表，所以空间很省。

对比暴力：暴力是 O(2^n · T)，本题把每个状态的检查从 O(T) 降到 O(1)，这就是「位压缩」带来的收益。

## 7. 边界与反例（至少 4 条）

1. **输入 `["a","b","c"]` → 期望 3**。容易错在：误以为要「连续子序列」而只取一个；实际是任选子集，三个都能拼。
2. **输入 `["aa","bb"]` → 期望 0**。每个字符串自身就有重复字母，全部非法，只能选空集。容易错在：忘了检查**单字符串内部**重复，只检查了跨字符串冲突。
3. **输入 `["ab","cd","ef"]` → 期望 6**。容易错在：回溯时只走「选」分支、不走「不选」分支，导致漏掉某些组合；或者反过来只走「不选」。
4. **输入 `["abcdefghijklmnopqrstuvwxyz","a"]` → 期望 26**。第一个字符串占满 26 个字母，第二个 "a" 与它冲突，只能选第一个。容易错在：以为两个都能选、长度 27，但 27 > 26 本身就不可能（字母表只有 26 个），这是很好的自检信号。
5. **输入 `["un","iq","ue"]` → 期望 4**（示例 1）。"un"+"iq"=4，"iq"+"ue"=4，"un"+"ue" 冲突（u 重复）。容易错在：贪心地按长度排序选，可能先选 "un" 再选 "ue" 发现冲突就停，漏掉 "un"+"iq"。

## 8. 面试追问与变体（3 条）

1. **追问：如果 arr 长度变成 100 怎么办？** 思路：2^100 不可行，需要换思路——此时问题接近「最大权独立集」的变体，一般要用状压 DP 按字母集合（2^26 太大）或贪心/近似，面试中通常只需指出「回溯不再适用，需要重新建模」。
2. **追问：如果要求拼接结果保持 arr 中的相对顺序且必须连续？** 思路：那就退化成「最大无重复字母的连续子数组拼接」，用滑动窗口 + 掩码维护窗口内字母集合，O(n)。
3. **追问：能不能不回溯，用迭代 DP？** 思路：`dp` 用字典存「掩码 → 最大长度」，逐个字符串更新 `new_dp[mask|m] = max(..., dp[mask]+len)`，本质是把 DFS 的「选/不选」展开成层序更新，状态数受合法掩码数量限制，实际往往远小于 2^16。

2. **LeetCode 78. 子集**：本题回溯的骨架就是「选/不选」枚举子集，78 题是它的无约束版本，练熟 78 再回来看本题会顺很多。
3. **LeetCode 1371. 每个元音包含偶数次的最长子字符串**：同样用位掩码表示「奇偶状态」，前缀异或 + 哈希，是位压缩在「状态表示」上的另一种经典用法。
