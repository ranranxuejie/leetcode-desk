## 1. 一句话本质

把两个用字符串表示的二进制数，按位相加并处理进位，得到它们的和（同样用字符串表示）。

## 2. 读完题的第一反应

**朴素解法**：把 a、b 分别转成十进制整数，相加，再转回二进制字符串。Python 里一行就能写：

```python
return bin(int(a, 2) + int(b, 2))[2:]
```

它卡在哪？看提示：`a.length, b.length <= 10^4`。也就是说 a 可能有 10000 位。Python 的 `int` 是任意精度，`int(a, 2)` 本身能算，但这是一个 O(n²) 量级的操作（大整数乘法/转换的代价随位数增长），而且**这道题被归到「模拟」标签下，面试官要的就是你手写竖式加法**。更关键的是：如果换成 C++/Java，`int` 只有 32 位，`long` 只有 64 位，10000 位的二进制数根本装不下，必须自己模拟。所以「转整数」这条路在语言层面就不可移植，不能作为答案。

**关键观察**：二进制加法和小学竖式加法一模一样——从最低位（字符串末尾）开始，逐位相加，加上上一位的进位，当前位结果 = `(x + y + carry) % 2`，新进位 = `(x + y + carry) // 2`。因为两个数长度可能不同，短的那个高位补 0 即可。这个观察直接给出 O(max(m,n)) 的线性算法，且不依赖任何大数类型。

为什么这个观察「能让你想到下一步」？因为竖式加法是**从右往左、单向扫描**的：每一位只依赖「当前两个字符 + 一个进位」，不回头。这种「局部依赖 + 单向推进」的结构，天然对应一个 for 循环 + 一个 carry 变量，不需要额外数据结构。

## 3. 从暴力到最优

**第 0 步（暴力）**：`bin(int(a,2)+int(b,2))[2:]`。瓶颈：依赖大整数，位数上万时转换代价高，且换语言就废。

**第 1 步（模拟竖式）**：用两个指针 i、j 分别指向 a、b 的末尾，carry 初始 0，每轮：

- `x = int(a[i]) if i >= 0 else 0`
- `y = int(b[j]) if j >= 0 else 0`
- `s = x + y + carry`
- 当前位 = `s % 2`，carry = `s // 2`
- i、j 各减 1

循环结束后如果 carry 还是 1，再补一个 '1'。瓶颈消掉了：每轮 O(1)，总共 O(max(m,n))，不碰大整数。

**第 2 步（细节优化）**：结果是从低位往高位生成的，直接往列表尾部 append，最后 `reverse` 再 join，比每次 `res = str + res` 好——后者每次拼接是 O(len)，总复杂度退化成 O(n²)。这是很多人写模拟题时踩的坑。

**具体小例子**：a = "1010", b = "1011"（示例 2）。

| 轮次 | i | j | a[i] | b[j] | carry(进) | s | 当前位 | carry(出) |
|---|---|---|---|---|---|---|---|---|
| 1 | 3 | 3 | '0' | '1' | 0 | 1 | 1 | 0 |
| 2 | 2 | 2 | '1' | '1' | 0 | 2 | 0 | 1 |
| 3 | 1 | 1 | '0' | '0' | 1 | 1 | 1 | 0 |
| 4 | 0 | 0 | '1' | '1' | 0 | 2 | 0 | 1 |
| 结束 | -1 | -1 | — | — | 1 | — | 补 '1' | — |

res 列表依次 append：`['1','0','1','0','1']`，反转后 `"10101"`，与示例一致。注意第 4 轮结束后 carry 仍为 1，必须补位，否则会得到 "0101" 这种错误结果。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。

设 a 长度为 m，b 长度为 n，令 L = max(m, n)。把两个数都看成 L 位（短的高位补 0）。定义不变量：

> 在第 k 轮循环开始前（k 从 1 数起），`carry` 等于「a、b 的低 k-1 位之和」向第 k-1 位产生的进位；且 res 中已 append 的 k-1 个字符，恰好是「低 k-1 位之和」的二进制表示（低位在前）。

**初始化**：k=1 时，低 0 位之和为 0，carry=0，res 为空，成立。

**保持**：第 k 轮取 a、b 的第 k-1 位（越界取 0），加上 carry，得到该位的真实和 `s = x + y + carry`。`s % 2` 就是第 k-1 位的正确结果，`s // 2` 就是向第 k 位的进位。append 后不变量对 k+1 成立。

**终止**：循环跑完 L 轮后，低 L 位全部处理完，res 含 L 个字符。若 carry=1，说明最高位之上还有进位，补 '1'；若 carry=0，不补。此时 res 反转后就是完整结果。

**不漏**：每一位都被恰好访问一次（i、j 从末尾走到 -1），没有跳过。**不重**：每轮只 append 一个字符，且 i、j 单调递减，不会重复处理同一位。进位通过 carry 变量在轮次间传递，不会丢失也不会重复计入。

## 5. 完整代码（Python）

```python
class Solution:
    def addBinary(self, a: str, b: str) -> str:
        i, j = len(a) - 1, len(b) - 1   # 从两个字符串的末尾（最低位）开始
        carry = 0                        # 进位，初始为 0
        res = []                         # 结果按低位到高位 append，最后反转

        while i >= 0 or j >= 0 or carry:
            # 越界的那一位视为 0（短数高位补 0）
            x = int(a[i]) if i >= 0 else 0
            y = int(b[j]) if j >= 0 else 0

            s = x + y + carry            # 当前位的总和，取值 0~3
            res.append(str(s % 2))       # 当前位结果
            carry = s // 2               # 向高位的进位

            i -= 1
            j -= 1

        # res 是低位在前，反转得到正常顺序
        return ''.join(reversed(res))
```

注意 `while` 条件里的 `or carry`：它让「最高位进位」在循环内被处理，省掉了循环后单独补 '1' 的分支。两种写法都对，这种写法少一个 if，但需要理解 carry 为 1 时循环会多跑一轮、此时 i、j 都已为 -1、x=y=0、s=1、append '1'、carry 变 0，循环自然结束。

## 6. 复杂度

- **时间 O(max(m, n))**：循环轮数 = max(m, n)（若最高位有进位则 +1，仍是同阶）。每轮做常数次整数运算和一次 append，append 均摊 O(1)。最后 `reversed` + `join` 是 O(L)。总时间由「较长字符串的长度」贡献，记作 O(L)，L = max(m, n)。这里**没有 log n**——因为题目输入本身就是二进制字符串，不需要做进制转换；如果输入是十进制整数再转二进制，才会出现 log 因子。
- **空间 O(L)**：res 列表存 L（或 L+1）个单字符，join 出的结果字符串也是 O(L)。carry、i、j 是 O(1)。所以额外空间是 O(L)，主要来自输出本身；若不计输出，辅助空间是 O(L)（res 列表）。无法做到 O(1) 辅助空间，因为字符串不可变，必须借助列表累积。

## 7. 边界与反例（至少 4 条）

1. **a = "0", b = "0"** → 期望 `"0"`。容易错：若循环条件写成 `while i >= 0 and j >= 0`，会漏掉；若用「循环后无条件补 carry」的写法且没判断 carry，可能补出多余字符。本题代码输出 `"0"`，正确。
2. **a = "1", b = "1"** → 期望 `"10"`。容易错：忘记处理最高位进位，输出 `"0"`。这是最经典的翻车点。
3. **a = "1111", b = "1"** → 期望 `"10000"`。容易错：连续进位跨过整个字符串，若只在最后补一位而中间进位逻辑写错（比如用 `s > 1` 判断但没更新 carry），会得到 `"1000"` 之类。
4. **a = "0", b = "1010"** → 期望 `"1010"`。容易错：长度不等时没做越界补 0，直接 `a[i]` 会 IndexError；或者把短数当成前面补 0 但补错方向（补在末尾）。
5. **a = "1", b = "0"** → 期望 `"1"`。容易错：结果前导零问题——本题代码不会产生前导零，因为最高位只有在真有值时才会被 append；但如果用「固定长度 L+1 的数组再从前往后填」的写法，可能留下前导 '0'，需要额外 strip。

## 8. 面试追问与变体（3 条）

1. **追问：如果输入是十进制字符串，要求返回十进制字符串的和？** 思路：完全同构，把 `% 2` / `// 2` 换成 `% 10` / `// 10`，carry 上限变成 1（因为每位最大 9+9+1=19），其余不变。这就是「字符串大数加法」。
2. **追问：不用额外列表，能不能原地/常数额外空间？** 思路：Python 字符串不可变，做不到真正原地；但可以预分配一个长度为 L+1 的 `bytearray`，从后往前填，最后按需切片掉首位，辅助空间仍是 O(L) 但常数更小。若允许修改输入（比如输入是 list），可以原地写回。
3. **追问：如果是 36 进制（0-9, a-z）相加？** 思路：把 `int(ch)` 换成「字符→数值」的映射表，`% 2` 换成 `% 36`，结果数值再映射回字符。核心的「逐位 + carry」骨架完全不变。
