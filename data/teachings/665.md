## 1. 一句话本质

在「最多允许一次修改」的预算下，判断数组能否被修成单调不降——本质是**找出所有「下降点」，并验证这些下降点是否都能被同一个位置的修改同时消掉**。

## 2. 读完题的第一反应

**朴素解法**：枚举每一个位置 `i`，把它改成任意值（理论上值域是 -10^5 到 10^5，但实际只需考虑改成邻居附近的值），然后 O(n) 检查整个数组是否非递减。总复杂度 O(n² · 值域) 或至少 O(n²)，n = 10^4 时是 10^8 量级，勉强但很丑，而且「改成什么值」这个枚举本身就没有清晰边界。

**卡在哪**：枚举「改哪个位置」和「改成什么值」是两个耦合的维度，暴力把它们乘起来了。

**关键观察**：非递减数列的判定是**逐对相邻元素**的局部条件。一个数组不是非递减的，当且仅当存在某个 `i` 使 `nums[i] > nums[i+1]`。这种「坏对」如果出现 **2 次及以上**，一次修改最多只能影响两个相邻对（改 `nums[i]` 影响 `(i-1,i)` 和 `(i,i+1)`），但两个坏对如果相距很远，一次修改根本够不着——所以**坏对数量 ≥ 2 时直接判 false**（除了两个坏对共享同一个元素的情况，下面细说）。

这个观察把问题从「枚举改哪里改成什么」压缩成「扫描一遍找坏对，然后只在坏对附近做局部判断」。

## 3. 从暴力到最优

### 暴力版本

```python
def checkPossibility_bruteforce(nums):
    def is_ok(a):
        return all(a[i] <= a[i+1] for i in range(len(a)-1))
    if is_ok(nums):
        return True
    for i in range(len(nums)):
        old = nums[i]
        # 枚举改成哪些值？理论上要枚举值域，实际可只试 nums[i-1] 和 nums[i+1]
        for v in (nums[i-1] if i > 0 else nums[i], nums[i+1] if i < len(nums)-1 else nums[i]):
            nums[i] = v
            if is_ok(nums):
                nums[i] = old
                return True
        nums[i] = old
    return False
```

瓶颈：外层 O(n) 个位置 × 内层 O(n) 检查 = O(n²)。而且「只试两个候选值」这个剪枝需要额外证明（见第 4 节）。

### 一次扫描版本

从左到右扫，遇到第一个坏对 `nums[i] > nums[i+1]` 时，**只有两种修法**：

- **修 `nums[i]`**：把它降到 `nums[i+1]`（或更小）。为了不破坏左边，最好降到 `nums[i-1]` 附近，但 `nums[i-1] <= nums[i+1]` 时降到 `nums[i+1]` 就够。
- **修 `nums[i+1]`**：把它升到 `nums[i]`（或更大）。为了不破坏右边，最好升到 `nums[i+2]` 附近，但 `nums[i] <= nums[i+2]` 时升到 `nums[i]` 就够。

**具体例子走一遍**：`nums = [4, 2, 3]`

- i=0：`4 > 2`，坏对。此时 `i-1` 不存在，只能修 `nums[0]`（降 4）。降成多少？只要 `<= 2` 即可，比如 1。数组变 `[1,2,3]`，非递减 ✓ → 返回 true。
- 对应示例 1 的解释「把第一个 4 变成 1」。

**再看** `nums = [4, 2, 1]`

- i=0：`4 > 2`，坏对。修 `nums[0]` 降成 1 → `[1,2,1]`，此时 i=1 处 `2 > 1` 又是坏对，但预算已用完 → false。
- 或者修 `nums[1]` 升成 4 → `[4,4,1]`，i=1 处 `4 > 1` 坏对 → false。
- 返回 false ✓。

**再看一个需要「修右边」的例子**：`nums = [1, 4, 2, 3]`

- i=1：`4 > 2`，坏对。此时 `nums[i-1] = 1 <= nums[i+1] = 2`，说明**修左边（把 4 降下来）更安全**，因为左边 1 和右边 2 能接上。把 4 降成 2 → `[1,2,2,3]` ✓。
- 如果错误地修右边（把 2 升成 4）→ `[1,4,4,3]`，i=2 处 `4 > 3` 坏对 → 失败。

**再看需要「修左边」的例子**：`nums = [3, 4, 2, 3]`

- i=1：`4 > 2`，坏对。此时 `nums[i-1] = 3 > nums[i+1] = 2`，说明**修左边不行**（3 和 2 接不上），只能修右边：把 2 升成 4 → `[3,4,4,3]`，i=2 处 `4 > 3` 坏对 → 失败？等等，再检查：`[3,4,4,3]` 确实 i=2 处 4>3 坏。那这题答案是 false 吗？

  重新想：`[3,4,2,3]`，改 `nums[2]` 从 2 改成 4 → `[3,4,4,3]` 不行；改 `nums[1]` 从 4 改成 2 → `[3,2,2,3]`，i=0 处 3>2 坏。改 `nums[2]` 改成 3 → `[3,4,3,3]`，i=1 处 4>3 坏。确实 false。

  但注意：`nums[i-1] = 3 > nums[i+1] = 2` 时，我们判断「修左边不行」，于是尝试修右边（把 `nums[i+1]` 升到 `nums[i]`）。修完后**必须继续检查后面**，因为可能引入新坏对。这里修完 `[3,4,4,3]` 后面又坏了，所以 false。这个例子说明：**修完一次后不能直接返回 true，要验证整个数组**——但验证可以 O(n) 一次扫完，总复杂度仍是 O(n)。

**统一逻辑**：扫描时维护 `modified` 标志。遇到坏对时：

- 若已修改过 → false。
- 否则尝试修：若 `i == 0` 或 `nums[i-1] <= nums[i+1]`，修 `nums[i]`（降），令 `nums[i] = nums[i+1]`；否则修 `nums[i+1]`（升），令 `nums[i+1] = nums[i]`。标记 modified。
- 继续扫描。

**为什么「修 `nums[i]` 降成 `nums[i+1]`」和「修 `nums[i+1]` 升成 `nums[i]`」就够？** 因为非递减只要求相邻对满足 `<=`，把 `nums[i]` 降到恰好等于 `nums[i+1]` 是满足 `nums[i] <= nums[i+1]` 的**最大可能值**（降得越少越不容易破坏左边 `nums[i-1] <= nums[i]`）；同理把 `nums[i+1]` 升到恰好等于 `nums[i]` 是满足条件的**最小可能值**（升得越少越不容易破坏右边 `nums[i+1] <= nums[i+2]`）。这是贪心选择。

## 4. 正确性：为什么不会漏、不会重

**不变量**：扫描到位置 `i` 时，`nums[0..i]` 已经是非递减的，且 `modified` 准确反映「是否已经用掉修改预算」。

**归纳**：

- 初始 `i=0`，前缀 `[nums[0]]` 平凡非递减，`modified=False`。
- 假设扫描到 `i` 时前缀 `[0..i]` 非递减。检查 `nums[i] <= nums[i+1]`：
  - 若成立，前缀扩展到 `i+1` 仍非递减，不变量保持。
  - 若不成立，必须修改 `nums[i]` 或 `nums[i+1]` 之一（修改更远的位置无法修复这对相邻关系，因为非递减是局部条件）。若 `modified` 已为 true，预算耗尽，返回 false。否则：
    - 若 `i == 0` 或 `nums[i-1] <= nums[i+1]`：修 `nums[i]` 降为 `nums[i+1]`。此时 `nums[i-1] <= nums[i+1] = nums[i]`（新值），左边不破坏；`nums[i] = nums[i+1]`，右边不破坏。前缀 `[0..i+1]` 非递减。
    - 否则（`nums[i-1] > nums[i+1]`）：修 `nums[i+1]` 升为 `nums[i]`。此时 `nums[i] = nums[i+1]`（新值），这对满足；左边 `nums[i-1] <= nums[i]` 原本成立（因为前缀非递减），不受影响。前缀 `[0..i+1]` 非递减。
    - 两种修法都保持不变量，`modified` 置 true。

**为什么不会漏**：任何合法解若只改一个位置 `j`，则 `j` 必须覆盖所有坏对。扫描到第一个坏对 `(i, i+1)` 时，`j` 只能是 `i` 或 `i+1`（否则这对坏对没被修）。我们的贪心在两种可行修法中选一个，且选的是「对邻居破坏最小」的那个——若贪心选的修法导致后续失败，另一种修法是否可能成功？不会：若 `nums[i-1] <= nums[i+1]`，修 `nums[i]` 降成 `nums[i+1]` 是**对左边最友好**的（降得最少），修 `nums[i+1]` 升成 `nums[i]` 会破坏右边更多；反之若 `nums[i-1] > nums[i+1]`，修 `nums[i]` 无论降成多少都满足不了 `nums[i-1] <= nums[i]`（因为 `nums[i-1] > nums[i+1]` 且 `nums[i]` 要 `<= nums[i+1]`），所以只能修右边。贪心选择是**唯一可行或更优**的，不会漏解。

**为什么不会重**：每个坏对只处理一次，`modified` 保证预算只用一次，扫描线性推进，无重复。

## 5. 完整代码（Python）

```python
class Solution:
    def checkPossibility(self, nums: list[int]) -> bool:
        n = len(nums)
        modified = False  # 是否已经用掉唯一一次修改机会

        for i in range(n - 1):
            if nums[i] <= nums[i + 1]:
                continue  # 这对没问题，继续

            # 遇到坏对 nums[i] > nums[i+1]
            if modified:
                return False  # 预算已用完，还有坏对 → 不可能

            # 决定修左边还是修右边
            if i == 0 or nums[i - 1] <= nums[i + 1]:
                # 修 nums[i]：降成 nums[i+1]，对左边破坏最小
                nums[i] = nums[i + 1]
            else:
                # nums[i-1] > nums[i+1]，修左边接不上，只能修 nums[i+1]
                nums[i + 1] = nums[i]

            modified = True  # 标记预算已用

        return True  # 扫完没有第二个坏对
```

注意：代码原地修改 `nums`。若不允许修改输入，可复制一份 `a = nums[:]` 再操作，空间 O(n)；但本题通常允许原地改，空间 O(1)。

## 6. 复杂度

- **时间 O(n)**：`for` 循环恰好遍历 `n-1` 个相邻对，每个对做 O(1) 次比较和至多一次赋值。没有嵌套循环，没有排序，所以没有 log n 项。n 来自数组长度。
- **空间 O(1)**：只用了 `modified` 一个布尔变量和循环变量 `i`，原地修改 `nums` 不额外分配。若复制数组则 O(n)，但那是可选优化。

## 7. 边界与反例（至少 4 条）

1. **`nums = [1]`** → 期望 `true` → 容易错：循环 `range(0)` 不执行，直接返回 true，正确；但若写成 `range(n)` 访问 `nums[i+1]` 会越界。
2. **`nums = [3, 4, 2, 3]`** → 期望 `false` → 容易错：只看到第一个坏对 `4 > 2` 就以为修一下就行，没注意修完 `[3,4,4,3]` 后面还有 `4 > 3`。必须继续扫描验证。
3. **`nums = [1, 4, 2, 3]`** → 期望 `true` → 容易错：`nums[i-1]=1 <= nums[i+1]=2` 时应修左边（降 4），若错误地修右边（升 2 成 4）会得到 `[1,4,4,3]` 后面坏掉。条件判断方向写反就错。
4. **`nums = [2, 3, 3, 2, 4]`** → 期望 `true` → 容易错：坏对在 `i=2`（`3 > 2`），`nums[1]=3 > nums[3]=2`，所以修右边把 `nums[3]` 升成 3 → `[2,3,3,3,4]` ✓。若误判为修左边（降 `nums[2]` 成 2）→ `[2,3,2,2,4]`，i=1 处 `3>2` 坏。
5. **`nums = [5, 7, 1, 8]`** → 期望 `true` → 坏对 `7 > 1`，`nums[0]=5 > nums[2]=1`，修右边升 1 成 7 → `[5,7,7,8]` ✓。若修左边降 7 成 1 → `[5,1,1,8]`，i=0 处 `5>1` 坏。

## 8. 面试追问与变体（3 条）

1. **追问：如果允许最多改 k 个元素呢？** → 思路：贪心不再够用（局部选择可能影响全局预算分配），需要 DP：`dp[i][j]` 表示前 i 个元素用 j 次修改能否非递减，转移时枚举 `nums[i]` 改成 `<= nums[i+1]` 的最小值，O(nk) 时间。
2. **追问：改成「严格递增」呢？** → 思路：条件从 `<=` 变 `<`，修左边时 `nums[i] = nums[i+1] - 1`，修右边时 `nums[i+1] = nums[i] + 1`，判断条件 `nums[i-1] < nums[i+1]` 也要相应调整（注意整数边界）。
3. **追问：返回最少修改次数而不是布尔值？** → 思路：本题贪心其实已经在数修改次数（`modified` 计数），但「最少次数」在允许改任意值时，等价于「坏对连通块」的个数——每个连通块至少改一个元素，用并查集或扫描合并相邻坏对区间，O(n)。
