## 1. 一句话本质

在**不能改动原链表**的前提下，为原链表的每个节点建立一份「一对一」的新节点副本，并把副本之间的 `next` 和 `random` 关系按原样重建——难点全在 `random`：它可能指向前面、后面、甚至自己，复制时那个「目标副本」可能还没被创建出来。

## 2. 读完题的第一反应

最朴素的做法是分两趟：第一趟只复制 `val` 和 `next`，把新链表串起来；第二趟再补 `random`。卡点立刻出现：补 `random` 时，手里只有原节点 `cur.random`，你需要找到「它对应的新节点」。如果每次都从头遍历新链表去数位置，单次 O(n)，总共 O(n²)。

关键观察是：**原节点和新节点之间存在天然的一一对应**。既然是一一对应，就可以用一个字典把它记下来——`原节点 -> 新节点`。有了这张表，「原节点的 random 指向谁」就能 O(1) 翻译成「新节点的 random 该指向谁」。这一步把「按位置查找」换成了「按身份查找」，瓶颈就消掉了。

再往深想一层：既然映射关系这么规整，能不能不用字典、直接把新节点「挂」在原节点旁边？这就是 O(1) 空间的思路来源，第 3 节展开。

## 3. 从暴力到最优

**暴力（两趟 + 按位置查找）**：第一趟建新链，第二趟对每个原节点，先数出 `cur.random` 是第几个节点（O(n)），再走到新链第 k 个节点接上。总时间 O(n²)，空间 O(1)（不算输出）。

**哈希表法（两趟 + 字典）**：第一趟遍历原链，为每个节点 `cur` 建副本 `Node(cur.val)`，存进 `mapping[cur] = 副本`。第二趟再遍历一次，做两件事：`mapping[cur].next = mapping.get(cur.next)`、`mapping[cur].random = mapping.get(cur.random)`。`get` 返回 `None` 正好对应「指向空」，不用特判。时间 O(n)，空间 O(n)。

用示例 1 走一遍，`head = [[7,null],[13,0],[11,4],[10,2],[1,0]]`，节点记为 A(7) B(13) C(11) D(10) E(1)：

- 第一趟结束，`mapping = {A:a, B:b, C:c, D:d, E:e}`，五个新节点 val 分别是 7,13,11,10,1，`next/random` 都还是 None。
- 第二趟处理 A：`a.next = mapping[B] = b`；`a.random = mapping.get(None) = None`。
- 处理 B：`b.next = c`；`b.random = mapping[A] = a`（因为 B 的 random_index 是 0）。
- 处理 C：`c.next = d`；`c.random = mapping[E] = e`（index 4）。
- 处理 D：`d.next = e`；`d.random = mapping[C] = c`（index 2）。
- 处理 E：`e.next = None`；`e.random = mapping[A] = a`（index 0）。

结果 `a→b→c→d→e`，random 依次 None, a, e, c, a，与输入一致。

**O(1) 空间法（穿插 + 拆分）**：不用字典，把副本直接插在原节点后面：`A -> a -> B -> b -> ...`。这样 `cur.next` 就是 `cur` 的副本，`cur.random.next` 就是 `cur.random` 的副本——「翻译」变成了两次 `.next`，不需要任何表。然后一趟设 `random`：`cur.next.random = cur.random.next if cur.random else None`。最后一趟把两条链拆开，恢复原链、取出新链。

同一个例子走一遍穿插后的状态：`A -> a -> B -> b -> C -> c -> D -> d -> E -> e`。处理 B 时，`B.random = A`，于是 `b.random = B.random.next = A.next = a`，正确。处理 C 时 `C.random = E`，`c.random = E.next = e`，正确。拆分时 `A.next = a.next = B`，`a.next = B.next = b`，交替推进即可。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说。哈希表法的不变量是：第二趟遍历到节点 `cur` 时，`mapping` 已经包含原链全部 n 个节点到新节点的双射，且 `cur` 之前的所有节点，其副本的 `next` 和 `random` 都已正确设置。

- **不会漏**：第一趟遍历完整条链，每个原节点恰好插入一次，`mapping` 的键集合等于原节点集合，所以第二趟任何 `mapping[cur.next]`、`mapping[cur.random]` 都必然命中（或 `cur.next/random` 为 None 时 `get` 返回 None，也正确）。
- **不会重**：每个原节点只 `Node(cur.val)` 一次，字典键唯一，所以新节点恰好 n 个、互不相同，满足「正好由 n 个全新节点组成」。
- **指针不指回原链**：所有赋值右侧都是 `mapping[...]` 的结果，即新节点或 None，绝不可能是原节点。

O(1) 空间法的不变量是：穿插完成后，对任意原节点 `cur`，`cur.next` 恰为它的副本，且副本的 `val` 与原节点相同。设 `random` 时用 `cur.random.next` 取副本，依赖的正是这个不变量；拆分时 `cur.next = cur.next.next` 恢复原链、`copy.next = copy.next.next` 串新链，两条链长度都是 n，交替推进不会错位。

## 5. 完整代码（Python）

```python
class Node:
    def __init__(self, x: int, next: 'Node' = None, random: 'Node' = None):
        self.val = int(x)
        self.next = next
        self.random = random


class Solution:
    def copyRandomList(self, head: 'Node') -> 'Node':
        if head is None:
            return None

        # 第一趟：为每个原节点建副本，建立 原节点 -> 新节点 的映射
        mapping = {}
        cur = head
        while cur:
            mapping[cur] = Node(cur.val)
            cur = cur.next

        # 第二趟：用映射把 next / random 翻译到新节点上
        cur = head
        while cur:
            copy = mapping[cur]
            # get 在 cur.next 为 None 时返回 None，正好对应链尾
            copy.next = mapping.get(cur.next)
            copy.random = mapping.get(cur.random)
            cur = cur.next

        return mapping[head]
```

如果面试官要求 O(1) 额外空间，换成穿插法：

```python
class Solution:
    def copyRandomList(self, head: 'Node') -> 'Node':
        if head is None:
            return None

        # 第一步：把副本插到原节点后面，形成 A -> a -> B -> b -> ...
        cur = head
        while cur:
            copy = Node(cur.val)
            copy.next = cur.next
            cur.next = copy
            cur = copy.next

        # 第二步：cur.random.next 就是 cur.random 的副本
        cur = head
        while cur:
            if cur.random:
                cur.next.random = cur.random.next
            cur = cur.next.next

        # 第三步：拆成两条链，恢复原链并取出新链
        new_head = head.next
        cur = head
        while cur:
            copy = cur.next
            cur.next = copy.next          # 恢复原链
            copy.next = copy.next.next if copy.next else None  # 串新链
            cur = cur.next

        return new_head
```

## 6. 复杂度

哈希表法：时间 O(n)，两趟遍历各 O(n)，字典插入和查询均摊 O(1)；空间 O(n)，`mapping` 存 n 个键值对，外加 n 个新节点（新节点是输出，通常不计入额外空间，但字典是实打实的额外开销）。

穿插法：时间 O(n)，三趟遍历各 O(n)；额外空间 O(1)，只用了几个指针变量，新节点本身是输出。注意这里没有 log n 项——链表操作全是线性扫描，不存在分治或排序。

## 7. 边界与反例

- `head = None` → 返回 `None`。容易错：不判空直接 `mapping[head]` 会 KeyError。
- `head = [[1,1]]`（单节点，random 指向自己）→ 输出 `[[1,1]]`。容易错：设 `random` 时误写成 `copy.random = cur.random`，指回原节点；或穿插法里漏掉 `cur.random` 非空判断导致 `None.next` 报错。
- `head = [[3,null],[3,0],[3,null]]`（值全相同）→ 输出同输入。容易错：想用 `val` 做字典键来省事，三个 3 会互相覆盖，必须用节点对象（身份）做键。
- `head = [[1,null],[2,null]]`（random 全空）→ 输出 `[[1,null],[2,null]]`。容易错：`mapping.get(cur.random)` 返回 None 是对的，但如果写成 `mapping[cur.random]` 会 KeyError。
- `head = [[7,null],[13,0]]`（random 指向前面的节点）→ 输出同输入。容易错：只做「边遍历边建副本」的单趟写法，处理 B 时 A 的副本已存在没问题，但若 random 指向后面的节点（如示例 1 的 C 指向 E），单趟就会拿到还没创建的副本——这正是必须两趟或先建全表的原因。

## 8. 面试追问与变体

- **追问：能不能不用哈希表？** 思路：穿插法，把副本挂到原节点后面，用 `cur.random.next` 代替查表，最后拆分。
- **追问：如果要求复制后原链表被破坏也没关系呢？** 思路：仍然推荐穿插法，因为它本来就会临时改动原链，只要最后拆干净即可；若允许破坏，可省掉恢复原链那一步。
- **追问：如果是带 random 的图（不是链表）怎么复制？** 思路：同一套「映射 + BFS/DFS」框架，`mapping` 从节点映射到副本，遍历邻居时查表建边，本质是克隆图。

## 9. 举一反三

- **克隆图（LeetCode 133）**：同样是「节点带任意指针的深拷贝」，核心都是 `原节点 -> 副本` 的映射加一次遍历建边。
- **复制带随机指针的链表（本题的 O(1) 空间变体）**：穿插法把「查表」换成「结构上的相邻关系」，是空间优化的通用套路。
- **扁平化多级双向链表（LeetCode 430）**：同样要在不改动节点身份的前提下重建指针关系，考察对 `next/prev` 指针的精细操作。
