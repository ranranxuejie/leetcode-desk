## 1. 一句话本质

在 BST 里删掉一个指定值的节点，并让剩下的树**仍然满足 BST 的有序性**——难点不在「找到」，而在「删掉之后怎么把断掉的子树重新接好」。

## 2. 读完题的第一反应

**朴素解法**：遍历整棵树找到 key 节点，然后……然后就没有然后了。因为「删除」在链表里是改指针，在树里是**一个节点可能有两个孩子**，你没法简单地把父节点指向某个孩子就完事——另一个孩子会连同整棵子树一起丢掉。

如果硬来，一个朴素想法是：把整棵树中序遍历成有序数组，删掉 key，再重新建一棵平衡 BST。这能过，但复杂度是 O(n)，而且重建过程繁琐。题面进阶明确要求 O(h)，所以这条路直接堵死。

**关键观察**：BST 的中序遍历是**严格递增序列**。删除一个节点后，要让剩下的序列仍然递增，等价于「在有序序列里删掉一个元素」——而有序序列删元素，只需要让**被删位置的后继（或前驱）顶上来**即可。映射回树上就是：被删节点如果有两个孩子，用**右子树的最小节点**（中序后继）或**左子树的最大节点**（中序前驱）替换它的值，然后递归删除那个后继/前驱节点。后继节点最多只有一个右孩子，删除它退化成简单情况。

这个观察之所以能让你想到下一步，是因为它把「两个孩子的复杂删除」**归约**成了「零个或一个孩子的简单删除」，而后者只需要把唯一的孩子直接接上去。

## 3. 从暴力到最优

**瓶颈**：找到 key 节点后，若它有两个孩子，无法直接接。

**消解方式**：分三种情况处理被删节点 `node`：

- **无孩子**：直接返回 `None`，父节点指向空。
- **只有一个孩子**：返回那个孩子，父节点直接接上。
- **有两个孩子**：找右子树最小值 `succ`，把 `node.val = succ.val`，然后**在右子树里递归删除 `succ.val`**。因为 `succ` 是右子树最小值，它一定没有左孩子，所以这次递归只会走「零个或一个孩子」的分支，一步到位。

**小例子走一遍**：`root = [5,3,6,2,4,null,7]`，`key = 3`。

1. `3 < 5`，去左子树，`root.left = deleteNode(3, 3)`。
2. 当前节点 `3` 就是目标。它有左孩子 `2`、右孩子 `4`，两个孩子都有。
3. 找右子树 `4` 的最小值：`4` 没有左孩子，`succ = 4`。
4. 令 `node.val = 4`，此时节点变成 `4`（原 `3` 的位置），左孩子仍是 `2`。
5. 在右子树里删 `4`：`4` 无孩子，返回 `None`。
6. 回到节点 `4`，`right = None`，返回 `4`。
7. 回到根 `5`，`left = 4`，最终树为 `[5,4,6,2,null,null,7]`。

中间变量：`succ.val = 4`，`node.val` 从 `3` 改成 `4`，右子树递归返回 `None`。整个过程只沿一条路径下行，O(h)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说：在递归的每一步，我们维护「当前子树的中序序列 = 原序列删去 key 后的对应片段，且仍是递增的」。

- **查找阶段**：`key < node.val` 时，由 BST 性质，key 只可能在左子树，右子树整体大于 `node.val > key`，不可能含 key，所以只递归左边不漏；反之同理。这保证「找得到」且「不误删」。
- **删除阶段**：
  - 零/一个孩子：直接接上唯一孩子，中序序列只是少了 `node` 本身，其余顺序不变，不变量成立。
  - 两个孩子：`succ` 是右子树最小值，即中序序列中 `node` 的**直接后继**。把 `node.val` 改成 `succ.val`，相当于在序列里把 `node` 这个位置的值换成后继值；再删掉原 `succ` 节点（它无左孩子，删除不破坏结构）。序列中 `succ.val` 出现两次的问题被第二次递归删除消掉，最终序列恰好是「原序列删去 key」，不重不漏。

**不会重**：`succ` 一定在右子树且是唯一最小值（题面说节点值唯一），替换后原 `succ` 被删，值不会重复出现。

## 5. 完整代码（Python）

```python
class Solution:
    def deleteNode(self, root, key):
        # 空树或没找到：直接返回，父节点保持原指向
        if root is None:
            return None

        if key < root.val:
            # key 只可能在左子树，右子树整体更大，不用看
            root.left = self.deleteNode(root.left, key)
        elif key > root.val:
            # 对称地只走右子树
            root.right = self.deleteNode(root.right, key)
        else:
            # 找到目标节点，分三种情况
            if root.left is None:
                # 无左孩子（含叶子）：用右孩子顶替，可能为 None
                return root.right
            if root.right is None:
                # 无右孩子：用左孩子顶替
                return root.left
            # 两个孩子都有：找右子树最小值（中序后继）
            succ = root.right
            while succ.left is not None:
                succ = succ.left
            # 用后继值覆盖当前节点
            root.val = succ.val
            # 在右子树里删掉后继节点（它无左孩子，递归会走简单分支）
            root.right = self.deleteNode(root.right, succ.val)

        return root
```

关键点：`return root.right` / `return root.left` 是「把子树交给上一层接住」，这是递归删除的核心写法；两个孩子的分支里，先改值再递归删后继，顺序不能反。

## 6. 复杂度

- **时间 O(h)**：`h` 为树高。查找 key 沿一条路径下行，最多 `h` 步；找到后若有两个孩子，找后继再沿右子树左链下行，最多再 `h` 步；递归删除后继同样沿一条路径。总步数与 `h` 成正比。最坏 `h = n`（退化成链），平均/平衡时 `h = log n`。注意这里**没有**遍历整棵树，所以不是 O(n)。
- **空间 O(h)**：递归调用栈深度等于路径长度，最坏 `h = n`，平衡时 `log n`。没有额外数组或哈希表。

## 7. 边界与反例（至少 4 条）

1. **输入 `root = []`, `key = 0`** → 输出 `[]`。容易错：忘记处理 `root is None`，直接访问 `root.val` 报错。
2. **输入 `root = [5,3,6,2,4,null,7]`, `key = 0`** → 输出原树不变。容易错：以为「没找到」要返回 `None`，实际应原样返回根，父节点指针不能断。
3. **删除叶子，如 `root = [2,1,3]`, `key = 1`** → 输出 `[2,null,3]`。容易错：写成 `root.left = None` 后忘了 `return root`，或把「无孩子」和「有一个孩子」分支写混。
4. **删除只有左孩子的节点，如 `root = [3,1,null]`, `key = 3`** → 输出 `[1]`。容易错：只判断了 `root.left is None` 就返回 `root.right`（此时是 `None`），把左孩子 `1` 丢了；必须先判左空再判右空，或反过来但逻辑要对称。
5. **删除有两个孩子的根，如 `root = [5,3,8,1,4,7,9]`, `key = 5`** → 用后继 `7` 顶替，输出 `[7,3,8,1,4,null,9]`。容易错：找后继时写成找右子树最大值（那是前驱），或改完值忘记递归删除原后继，导致 `7` 出现两次。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求删除后树尽量平衡，怎么办？** 思路：本题只保证 BST 性质，不保证平衡；若要平衡需用 AVL/红黑树的旋转删除，属于另一套机制，面试中说明「本题不要求」即可。
2. **追问：不用递归，改成迭代怎么写？** 思路：先迭代找到目标节点并记录父节点，再按三种情况改指针；两个孩子时找后继并记录其后继父节点，做指针拼接。代码更长但空间 O(1)。
3. **追问：如果要删除的是一个区间 `[lo, hi]` 内所有节点呢？** 思路：递归时若 `node.val` 落在区间内，先递归修剪左右子树，再按本题逻辑删除当前节点；类似「修剪二叉搜索树」的扩展。
