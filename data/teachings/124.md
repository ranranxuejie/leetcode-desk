## 1. 一句话本质

在所有「树上的简单路径」里，找一条节点值之和最大的——而这条路径的形状必然是「一条从某点出发向上、在最高点拐弯、再向下」的折线，最高点可以是任意节点。

## 2. 读完题的第一反应

**朴素解法**：枚举所有起点和终点，对每对节点求路径和。树上有 n 个节点，路径条数是 O(n²) 量级，每条路径求和的代价又是 O(n)，总复杂度 O(n³)。即使预处理 LCA 把单条路径求和降到 O(log n)，也还是 O(n² log n)。n 最大 3×10⁴，平方级直接爆掉。

**卡在哪**：枚举路径这个动作本身太贵。路径数量是平方级的，任何「逐条枚举再比较」的思路都注定失败。

**关键观察**：路径在树上有一个强结构——它一定有一个「最高点」（离根最近的那个节点），路径从这个最高点向左右两个子树各伸出一条**向下的链**（其中一条可以为空）。也就是说，任何路径都能被唯一地描述为「某个节点 + 它左子树里一条向下的链 + 它右子树里一条向下的链」。

这个观察为什么能让你想到下一步？因为它把「枚举路径」换成了「枚举最高点」。最高点只有 n 个选择，问题从「平方级的路径」塌缩成「每个节点上做一次局部决策」。而「子树里向下的最大链」是天然的自底向上信息——这正是后序遍历（DFS）能递推的东西。

## 3. 从暴力到最优

**第一步：把路径拆成「过某节点的路径」**

对每个节点 u，定义「以 u 为最高点的最大路径和」= u.val + (左子树向下最大链，若为负则取 0) + (右子树向下最大链，若为负则取 0)。答案就是所有 u 的这个值的最大值。

**第二步：注意到「向下最大链」可以递推**

定义 `gain(u)` = 从 u 出发、只往下走（不拐弯）能得到的最大路径和。那么：

```
gain(u) = u.val + max(0, gain(u.left), gain(u.right))
```

因为从 u 往下走，要么停在 u，要么进入左子树或右子树——只能选一边，不能两边都要（要了两边就拐弯了，那就不是「向下链」了）。

**第三步：两个量在同一个 DFS 里同时算**

`gain(u)` 是给父节点用的（自底向上传），「以 u 为最高点的路径和」是拿来更新全局答案的。两者在同一个后序位置计算，一次遍历搞定。

**小例子走一遍**：`root = [-10, 9, 20, null, null, 15, 7]`

```
         -10
         /  \
        9    20
            /  \
           15   7
```

后序遍历，从叶子开始：

- 节点 9：`gain(9) = 9 + max(0, 0, 0) = 9`；过 9 的路径和 = 9 + 0 + 0 = 9；`ans = 9`
- 节点 15：`gain(15) = 15`；过 15 的路径和 = 15；`ans = max(9,15) = 15`
- 节点 7：`gain(7) = 7`；过 7 的路径和 = 7；`ans = 15`
- 节点 20：`gain(20) = 20 + max(0, 15, 7) = 35`；过 20 的路径和 = 20 + 15 + 7 = 42；`ans = max(15, 42) = 42`
- 节点 -10：`gain(-10) = -10 + max(0, 9, 35) = 25`；过 -10 的路径和 = -10 + 9 + 35 = 34；`ans = max(42, 34) = 42`

最终 `ans = 42`，和示例一致。注意 -10 那一步：`gain(-10) = 25` 是「从 -10 往下走的最大链」，但过 -10 的路径和 34 小于 42，所以答案没被它刷新——这说明「最高点」不一定是根，答案在 20 那里就定下来了。

**瓶颈怎么被消掉的**：原来枚举 O(n²) 条路径，现在每个节点只做 O(1) 次局部计算，靠 DFS 把子树的 `gain` 复用给父节点。总代价降到 O(n)。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在 DFS 处理完以 u 为根的子树后，`gain(u)` 恰好等于「从 u 出发、只向下走、至少包含 u 一个节点」的所有路径中的最大和。

**归纳证明**：
- 叶子：只有「停在 u」这一条路径，`gain = u.val`，成立。
- 内部节点：从 u 向下的路径，第一步要么停在 u，要么进入左孩子或右孩子（不能同时进两边，否则路径在 u 处就分叉了，不再是「向下链」）。进入某孩子后，最优续法就是该孩子的 `gain`。所以 `gain(u) = u.val + max(0, gain(left), gain(right))`，其中 `max(0, ...)` 对应「停在 u」这个选项。归纳成立。

**不漏**：任取一条最优路径 P，设其最高点为 u。P 在 u 处最多向左、右各伸一条向下链，两条链的和分别不超过 `max(0, gain(left))` 和 `max(0, gain(right))`。所以 P 的和 ≤ `u.val + max(0,gain(left)) + max(0,gain(right))`，而后者正是我们在 u 处计算并参与取 max 的值。因此答案不会小于真正的最优值。

**不重**：每条路径的最高点唯一（离根最近的那个节点唯一），所以每条路径只在它的最高点处被「认领」一次，不会重复计数，也不会因为重复而算错。

**边界**：`max(0, ...)` 保证当某侧子树贡献为负时直接舍弃——这对应「路径不往那一侧延伸」，是合法的（路径可以只有一条链甚至单节点）。

## 5. 完整代码（Python）

```python
class Solution:
    def maxPathSum(self, root) -> int:
        # 全局答案，初始化为负无穷：节点值可能全为负
        self.ans = float('-inf')

        def dfs(node) -> int:
            # 返回：从 node 出发、只向下走的最大路径和（gain）
            if node is None:
                return 0

            # 左右子树的向下最大链；负数直接舍弃（取 0 表示不延伸）
            left_gain = max(0, dfs(node.left))
            right_gain = max(0, dfs(node.right))

            # 以当前节点为「最高点」的路径和：左右两边都可以要
            cur_path = node.val + left_gain + right_gain
            # 用它更新全局答案
            self.ans = max(self.ans, cur_path)

            # 返回给父节点用：只能选一边（或都不选），不能拐弯
            return node.val + max(left_gain, right_gain)

        dfs(root)
        return self.ans
```

关键点：`cur_path` 用 `left_gain + right_gain`（两边都要），`return` 用 `max(left_gain, right_gain)`（只能要一边）。这两个式子的区别就是「拐弯」和「不拐弯」的区别，是本题最容易写错的地方。

## 6. 复杂度

**时间 O(n)**：DFS 每个节点访问一次，节点内是常数次加法、比较、取 max。n 来自节点总数（最多 3×10⁴）。

**空间 O(h)**，h 为树高：递归栈深度等于树高。最坏情况（链状树）h = n，空间 O(n)；最好情况（平衡树）h = log n，空间 O(log n)。这里没有额外的数组或哈希表，空间全部由递归栈贡献。注意题目没保证平衡，所以严格说最坏是 O(n)。

## 7. 边界与反例（至少 4 条）

1. **单节点 `[−3]`** → 期望 `−3`。容易错在把 `ans` 初始化为 0，结果返回 0——但路径至少含一个节点，不能是空路径。所以 `ans` 必须初始化为 `-inf`。

2. **全负数 `[−2, −1]`**（根 −2，左孩子 −1）→ 期望 `−1`。容易错在 `max(0, gain)` 把负数抹成 0 后，误以为可以「什么都不选」。实际上 `cur_path` 里 `node.val` 始终被加上，单节点路径 −1 会被正确捕捉；但如果 `ans` 初值写成 0 就会错。

3. **链状树 `[1, 2, null, 3]`**（1→2→3 一条左链）→ 期望 `6`。容易错在以为「必须经过根」或「必须左右都有」。这条路径是 1-2-3 一条直线，最高点是 1，只有一条向下链，`right_gain = 0`，靠 `max(0, ...)` 正确处理。

4. **根为负、子树为正 `[−10, 9, 20, null, null, 15, 7]`** → 期望 `42`。容易错在把根也算进最优路径（−10+9+35=34 < 42）。这提醒我们答案的最高点可以是任意节点，不一定是根。

5. **一边子树全负 `[1, −2, 3]`** → 期望 `4`（路径 1→3）。容易错在把 −2 也加进去。`max(0, gain(−2)) = 0` 正确处理了「不往负的一侧走」。

## 8. 面试追问与变体（3 条）

1. **追问：如果路径必须经过根节点，怎么做？** 思路：答案固定为 `root.val + max(0, gain(root.left)) + max(0, gain(root.right))`，仍然需要后序求 gain，但不再对每个节点取全局 max。

2. **追问：如果要求返回路径本身而不只是和？** 思路：在 DFS 里额外记录「取得最大 gain 的孩子方向」，更新 `ans` 时记下当时的节点，最后从该节点沿记录的方向回溯拼出路径。

3. **追问：如果树是 N 叉树呢？** 思路：`gain(u) = u.val + max(0, 所有孩子的 gain 中的最大值)`；过 u 的路径和 = `u.val + 最大的两个非负孩子 gain 之和`（取 top-2 而非固定左右）。

## 9. 举一反三（2-3 道同类题）

1. **543. 二叉树的直径**：同样是「最高点 + 左右两条向下链」，只是把「和」换成「边数」，`gain` 变成「向下最大深度」，过节点的值变成 `left_depth + right_depth`。

2. **687. 最长同值路径**：结构完全一致，但「向下链」只在子节点值与当前节点相同时才延伸，`gain` 的递推条件多一个相等判断。

3. **337. 打家劫舍 III**：也是树形 DP 自底向上，每个节点返回「选/不选」两个状态给父节点，和本题「返回 gain、同时更新全局答案」的双职责模式同源。
