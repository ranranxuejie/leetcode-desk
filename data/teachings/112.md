## 1. 一句话本质

判断「从根到某个叶子的所有完整路径」中，是否存在一条路径的节点值之和恰好等于给定目标。

关键词是**完整路径**和**叶子**——不是任意一段路径，也不是任意一个节点。

## 2. 读完题的第一反应

### 朴素解法：枚举所有根到叶路径，逐条求和

最直白的做法是：遍历整棵树，把每一条从根到叶的路径都收集出来，对每条路径求和，看有没有等于 `targetSum` 的。

它卡在哪？**空间**。如果树有 n 个节点，把所有路径都存下来，最坏情况（比如一条链）路径长度是 n，而你要存下所有路径的副本，空间是 O(n²) 级别。而且「先收集再比较」这个动作本身是多余的——你并不需要保留路径，只需要知道「有没有一条满足」。

### 关键观察：把「路径求和」变成「剩余目标」

这是这道题真正的转折点。与其从根往下累加、最后再和 `targetSum` 比，不如**每走一步就从目标里减掉当前节点的值**：

> 走到某个节点时，问自己：从「这里」到叶子，还需要凑出多少？

如果走到叶子时，剩余目标恰好被这个叶子的值减到 0，就说明找到了一条。这个视角把「求和」变成了「递减」，让递归的每一层只需要关心一个数——**还差多少**——而不需要携带一个累加器或一条路径。

为什么这个观察能让你想到下一步？因为「还差多少」这个量在递归时天然可以往下传：父节点算出的剩余值，直接就是子节点要面对的 `targetSum`。递归的结构就自然浮现了。

## 3. 从暴力到最优

### 第一步：暴力枚举路径

对每个叶子，回溯出它到根的路径，求和比较。瓶颈是路径存储和重复遍历。

### 第二步：递归传递「剩余目标」

不再存路径，而是把「还差多少」作为参数往下传。每到一个节点，先减掉自己的值，再看：

- 如果这个节点是叶子，判断剩余是否为 0；
- 如果不是叶子，把剩余值传给左右子树，任意一边返回 true 即可。

### 用示例 2 走一遍

`root = [1,2,3]`，`targetSum = 5`。

```
hasPathSum(节点1, 5)
  剩余 = 5 - 1 = 4
  节点1 不是叶子
  ├─ hasPathSum(节点2, 4)
  │    剩余 = 4 - 2 = 2
  │    节点2 是叶子 → 2 != 0 → 返回 False
  └─ hasPathSum(节点3, 4)
       剩余 = 4 - 3 = 1
       节点3 是叶子 → 1 != 0 → 返回 False
  两边都 False → 返回 False
```

结果 `False`，和题面一致。注意中间变量 `剩余` 在每一层都被重新计算，父层的 4 传给两个子节点，各自再减自己的值——这就是「剩余目标」在递归中的流动。

### 第三步：为什么这就是最优

每个节点最多被访问一次，没有重复计算，也没有额外存储路径。时间 O(n) 是下界（最坏情况必须看完所有节点才能确定不存在），空间 O(h) 是递归栈的深度，无法再省。所以这已经是最优解，不需要再优化。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：调用 `hasPathSum(node, remain)` 时，`remain` 恒等于「原始 targetSum 减去从根到 node 的父节点为止的所有节点值之和」。换句话说，`remain` 就是「从 node 出发到叶子还需要凑出的和」。

**基础**：根节点调用时，`remain = targetSum`，根到根的父节点路径为空，和为 0，不变量成立。

**归纳**：假设进入 `node` 时不变量成立。进入后先算 `remain - node.val`，这正好是「减掉 node 之后还差多少」，即从 node 的子节点出发需要凑的和。把它传给子节点，子节点收到时不变量的形式依然成立。

**终止**：当 node 是叶子时，没有子节点可传，此时「从 node 到叶子的路径」就是 node 自己，路径和是否等于原始目标，等价于 `remain - node.val == 0`。代码正是在这里做判断。

**不漏**：任何一条根到叶路径，都会在递归中被完整走一遍，且只在叶子处做判定，所以每条合法路径都会被检查到。

**不重**：每个节点只有唯一的父节点，递归从根出发、沿树结构下行，每个节点恰好被访问一次，不存在同一条路径被重复判定。

一个容易忽略的点：**判定必须放在叶子处**。如果在中途节点就判断 `remain == 0` 并返回 true，会误判——比如路径 `1 -> 2` 中途某节点剩余为 0，但后面还有节点没加，那不是完整路径。题面明确要求「根节点到叶子节点」，所以只有叶子才是合法终点。

## 5. 完整代码（Python）

```python
class Solution:
    def hasPathSum(self, root, targetSum):
        # 空树没有任何根到叶路径，直接 False
        # 注意：不能因为 targetSum == 0 就返回 True，示例 3 就是这个坑
        if root is None:
            return False

        # 先减掉当前节点的值，得到「从当前节点往下还需要凑多少」
        remain = targetSum - root.val

        # 叶子节点：没有子节点，当前节点就是路径终点
        # 此时剩余为 0 说明这条完整路径的和等于 targetSum
        if root.left is None and root.right is None:
            return remain == 0

        # 非叶子：只要左子树或右子树任意一边能找到，就返回 True
        # 把 remain 作为新的目标往下传，这就是「剩余目标」的递归
        return (self.hasPathSum(root.left, remain) or
                self.hasPathSum(root.right, remain))
```

这段代码可以直接运行（力扣的 `TreeNode` 由平台提供）。核心只有三块：空树判断、叶子判断、递归下传。没有累加器，没有路径列表，所有状态都压在 `remain` 这一个参数上。

## 6. 复杂度

**时间 O(n)**：n 是节点数。每个节点最多被递归访问一次，每次访问做常数次操作（减法、判空、比较）。为什么是 n 而不是 n log n？因为这不是平衡树的层序遍历，递归是沿树结构走的，每个节点只进一次函数，不存在按层重复访问。最坏情况（目标不存在）必须走完所有节点才能下结论，所以 O(n) 也是下界。

**空间 O(h)**：h 是树的高度，来自递归调用栈。每深入一层就压一个栈帧，栈的最大深度等于从根到最深叶子的路径长度。平衡树 h = log n，退化成链 h = n。这里没有额外的数组或哈希表，空间全部由递归栈贡献。如果面试官追问「能不能 O(1) 空间」，答案是可以用 Morris 遍历改造，但会牺牲代码可读性，通常不要求。

## 7. 边界与反例（至少 4 条）

1. **`root = []`, `targetSum = 0`** → 期望 `False`。容易错在把「空树」和「和为 0」混为一谈，误返回 True。题面示例 3 专门考这个：空树没有根到叶路径，和是多少都不算。

2. **`root = [1, 2]`, `targetSum = 1`** → 期望 `False`。根节点 1 不是叶子（它有左孩子 2），路径 `1 -> 2` 的和是 3。容易错在根节点处就判断 `remain == 0` 返回 True，忽略了「必须走到叶子」。

3. **`root = [-2, null, -3]`, `targetSum = -5`** → 期望 `True`。节点值可以是负数，路径和会「先减后加」地波动。容易错在以为和是单调递增的、提前剪枝。本题不能剪枝，必须走到底。

4. **`root = [1, -2, -3, 1, 3, -2, null, -1]`, `targetSum = -1`** → 期望 `True`（路径 `1 -> -2 -> 1 -> -1` 和为 -1）。容易错在只检查「剩余是否大于 0」之类的错误剪枝，负值场景下这类判断全失效。

5. **`root = [5]`, `targetSum = 5`** → 期望 `True`。单节点树，根就是叶子。容易错在把「根」和「叶子」当成互斥概念，漏掉单节点即叶子的情况。

## 8. 面试追问与变体（3 条）

1. **追问：如果要返回所有满足条件的路径，而不只是判断存在性，怎么改？** 思路：递归时携带当前路径列表，到叶子且剩余为 0 时把路径副本加入结果集，回溯时弹出当前节点。本质是把「布尔返回」换成「收集」，其余结构不变。

2. **追问：如果路径不要求从根开始、也不要求在叶子结束（任意向下路径），怎么做？** 思路：这是「路径总和 III」的形态。需要在每个节点作为起点时都做一次向下搜索，配合前缀和 + 哈希表把 O(n²) 降到 O(n)。

3. **追问：如果要求「路径和等于目标」且路径必须经过某个指定节点，怎么处理？** 思路：拆成两段——从指定节点向下到叶子的路径和，加上从根到指定节点的前缀和，分别计算后组合判断。

## 9. 举一反三（2-3 道同类题）

- **113. 路径总和 II**：和本题的共同点是同样沿根到叶路径做「剩余目标」递减，区别是要收集所有满足的路径而非只判断存在，考的是回溯与结果收集。

- **437. 路径总和 III**：共同点是「路径和等于目标」的判定，区别是路径不限定从根开始，需要前缀和 + 哈希表把暴力枚举优化到线性。

- **124. 二叉树中的最大路径和**：共同点是都在树上做「路径求和」的递归，区别是路径可以拐弯（经过某节点连接左右子树），递归返回的是「单边最大贡献」而非布尔值，考的是递归返回值的语义设计。
