## 1. 一句话本质

在只允许向右/向下走的 DAG 上，求从起点到终点的**最短加权路径**——每个格子的数字就是进入该格子的代价。

## 2. 读完题的第一反应

**朴素解法**：枚举所有从左上到右下的路径，每条路径求和取最小。从 (0,0) 到 (m-1,n-1) 一共要走 (m-1)+(n-1) 步，其中选 m-1 步向下，路径总数是组合数 C(m+n-2, m-1)。m=n=200 时这个数约等于 10^117，完全不可行。卡在**路径数量指数级爆炸**。

**关键观察**：走到格子 (i,j) 的路径，最后一步只可能来自上方 (i-1,j) 或左方 (i,j-1)。也就是说，"到达 (i,j) 的最小代价"这个子问题，只依赖"到达它上方格子的最小代价"和"到达它左方格子的最小代价"两个更小的子问题。这就是**最优子结构**——大问题的最优解由小问题的最优解拼出来，不需要枚举所有路径。

为什么这个观察能让你想到下一步？因为一旦确认"每个格子只需要存一个数（到达它的最小代价）"，你就从"枚举路径"切换到了"逐格填表"，状态数从指数级降到 m×n。

## 3. 从暴力到最优

**第一步：暴力 DFS。** 从 (0,0) 出发，每步尝试向右或向下，走到终点记录路径和，取全局最小。瓶颈：重复计算。比如从 (1,1) 到终点这段路，会被"从上方来的路径"和"从左方来的路径"各算一遍，而且随着格子变大，重复呈指数增长。

**第二步：记忆化。** 发现"从 (i,j) 到终点的最小代价"只和 (i,j) 有关，跟怎么到达 (i,j) 无关。于是开一个 memo 表，算过的直接查。复杂度降到 O(mn)。这一步已经能过，但递归有栈深问题（m+n 最多 400，其实还好），且常数偏大。

**第三步：自底向上 DP。** 把递归反过来：先算左上角，再一行一行（或一列一列）往右下推。定义 `dp[i][j]` = 从 (0,0) 走到 (i,j) 的最小路径和。转移：

```
dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])
```

第一行只能从左边来，第一列只能从上边来，单独处理。

**用示例 1 走一遍**：`grid = [[1,3,1],[1,5,1],[4,2,1]]`

初始化 dp 全 0，逐格填：

- dp[0][0] = 1
- 第一行：dp[0][1] = 3+1 = 4，dp[0][2] = 1+4 = 5
- 第一列：dp[1][0] = 1+1 = 2，dp[2][0] = 4+2 = 6
- dp[1][1] = 5 + min(dp[0][1]=4, dp[1][0]=2) = 5+2 = **7**
- dp[1][2] = 1 + min(dp[0][2]=5, dp[1][1]=7) = 1+5 = **6**
- dp[2][1] = 2 + min(dp[1][1]=7, dp[2][0]=6) = 2+6 = **8**
- dp[2][2] = 1 + min(dp[1][2]=6, dp[2][1]=8) = 1+6 = **7**

最终 dp 表：

```
1  4  5
2  7  6
6  8  7
```

答案 dp[2][2] = 7，和官方一致。注意 dp[1][1]=7 这个格子：从上方来代价 4+5=9，从左方来代价 2+5=7，取了小的 7——这正是"只保留最优、丢弃劣解"的体现。

**第四步：空间优化。** 观察转移只用到"上一行同列"和"本行左一格"，所以二维表可以压成一维：`dp[j]` 在更新前存的是上一行的值，更新后存的是本行的值。遍历到 (i,j) 时，`dp[j]`（旧值）= dp[i-1][j]，`dp[j-1]`（已更新）= dp[i][j-1]。转移变成 `dp[j] = grid[i][j] + min(dp[j], dp[j-1])`。空间从 O(mn) 降到 O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：在填完 dp[i][j] 的那一刻，`dp[i][j]` 的值等于"所有从 (0,0) 到 (i,j) 的合法路径中，路径和的最小值"。

**归纳证明**：

- **基础情形**：dp[0][0] = grid[0][0]。从起点到起点只有一条空路径，代价就是起点本身，成立。
- **归纳步**：假设所有"在 (i,j) 之前被填的格子"都满足不变量。考虑任意一条从 (0,0) 到 (i,j) 的路径，它的最后一步要么从 (i-1,j) 下来，要么从 (i,j-1) 过来（题面限定只能向下或向右，所以没有第三种可能——**这就是"不漏"的依据**）。这条路径的总代价 = 到达那个前驱格子的代价 + grid[i][j]。要让总代价最小，前驱那段的代价必须取最小，即 dp[i-1][j] 或 dp[i][j-1]（归纳假设保证这两个值已经是各自的最优）。两者取 min 再加 grid[i][j]，就覆盖了所有路径中的最小值。**这就是"不重"的依据**：每条路径按最后一步被唯一归类到"从上方来"或"从左方来"两类之一，两类内部各自取最优，不会把同一条路径算两次，也不会漏掉任何一条。

因为每个格子只被填一次，且填的时候依赖的格子都已填好（按行优先或列优先遍历即可保证），所以填完 dp[m-1][n-1] 时，不变量成立，答案正确。

## 5. 完整代码（Python）

```python
class Solution:
    def minPathSum(self, grid: list[list[int]]) -> int:
        m, n = len(grid), len(grid[0])

        # 一维滚动数组：dp[j] 在更新前代表上一行第 j 列的最优值，
        # 更新后代表当前行第 j 列的最优值。
        dp = [0] * n

        for i in range(m):
            for j in range(n):
                if i == 0 and j == 0:
                    # 起点：代价就是格子本身
                    dp[j] = grid[i][j]
                elif i == 0:
                    # 第一行：只能从左边来
                    dp[j] = dp[j - 1] + grid[i][j]
                elif j == 0:
                    # 第一列：只能从上边来（dp[j] 此时还是上一行的值）
                    dp[j] = dp[j] + grid[i][j]
                else:
                    # 一般情况：上方 dp[j]（旧值）与左方 dp[j-1]（新值）取小
                    dp[j] = min(dp[j], dp[j - 1]) + grid[i][j]

        return dp[n - 1]
```

关键点：`j == 0` 那一支里 `dp[j]` 还没被本行覆盖，读到的就是上一行的值，所以直接加即可，不需要额外判断"上方是否存在"。`i == 0` 那一支里 `dp[j-1]` 是本行刚算好的，正确。

## 6. 复杂度

**时间 O(m·n)**：两层循环各遍历 m 和 n 次，每次循环体内是常数次比较和加法。m、n 来自网格的行数和列数，没有 log 项——因为这里没有分治或排序，纯粹是线性填表。

**空间 O(n)**：滚动数组长度为列数 n。如果不用滚动数组，二维 dp 是 O(m·n)，其中 m 来自行数、n 来自列数。选 n 而不是 m 作为滚动维度，是因为内层循环沿列方向走，滚动数组自然对应列。若 n 远大于 m，可以转置思路改成按行滚动，空间取 min(m,n)，但本题 m,n ≤ 200，没必要。

## 7. 边界与反例（至少 4 条）

1. **输入 `[[5]]`** → 期望 `5` → 容易错在：忘记处理单格子，或把起点当成 0 初始化。代码里 `i==0 and j==0` 分支专门处理。
2. **输入 `[[1,2,3]]`（单行）** → 期望 `6` → 容易错在：误以为可以向下走绕路，或第一行转移写成 `min(dp[j], dp[j-1])` 时 `dp[j]` 初值 0 导致取到 0。代码里 `i==0` 分支强制只从左边累加。
3. **输入 `[[1],[2],[3]]`（单列）** → 期望 `6` → 容易错在：滚动数组里 `j==0` 分支若写成 `min(dp[j], dp[j-1])` 会访问 `dp[-1]`（Python 里是最后一个元素，静默出错）。代码里单独处理 `j==0`。
4. **输入 `[[0,0],[0,0]]`（全零）** → 期望 `0` → 容易错在：把"未初始化"和"代价 0"混淆，比如用 -1 当哨兵再判断，或初始化 dp 为无穷大后忘记起点赋值。本题非负，0 是合法代价，不能用 0 当"未访问"标记。
5. **输入 `[[1,3,1],[1,5,1],[4,2,1]]`** → 期望 `7` → 容易错在：贪心地每步选较小的邻居（在 (0,0) 处右边 3 比下边 1 大，贪心会先下，但后续在 (1,1) 处 5 很大）。这题**不能贪心**，必须全局 DP，因为局部小不代表全局小。

## 8. 面试追问与变体（3 条）

1. **追问：如果允许向上、向下、向左、向右四个方向走，怎么做？** 思路：此时图有环，DP 的拓扑序不存在，退化为带权图最短路，用 Dijkstra（边权非负）或 0-1 BFS（若权值只有 0/1）。
2. **追问：如果要输出具体路径而不只是最小和，怎么改？** 思路：额外开一个 `parent[i][j]` 记录每个格子是从上方还是左方转移来的，最后从终点回溯到起点即可，空间多 O(mn)。
3. **追问：如果网格里有障碍物（某些格子不可走），怎么改？** 思路：把障碍格子的 dp 设为无穷大（或跳过），转移时自然不会被选中；注意起点或终点是障碍时直接返回 -1 或特殊值。

## 9. 举一反三（2-3 道同类题）

1. **不同路径（LeetCode 62）**：同样是"只能向右/向下"的网格 DP，区别是求路径**条数**而非最小和，转移从 `min` 换成加法。
2. **三角形最小路径和（LeetCode 120）**：三角形网格上自顶向下的最小路径和，转移结构相同（每个位置只依赖上一层的相邻两个位置），是本题的"三角形版"。
3. **地下城游戏（LeetCode 174）**：网格上求"进入时至少需要多少初始血量"，同样是网格 DP，但需要**从终点倒推**，因为正向依赖的是"剩余血量"而非"累计代价"，是本题的逆向思维变体。
