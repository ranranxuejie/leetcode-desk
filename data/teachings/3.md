## 1. 一句话本质

在所有「连续、且字符互不相同」的区间里，找最长的那个区间的长度。

关键词是「连续」——这是子串和子序列的分水岭，示例 3 专门用 `"pwke"` 提醒你：`pwke` 虽然字符不重复，但它跳过了 `w` 和 `k` 之间的字符，不是连续的一段，所以不算。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子串（起点 `i` 和终点 `j`，共 O(n²) 个），对每个子串再检查有没有重复字符（O(n)），总复杂度 O(n³)。就算用集合边扩展边查重，也是 O(n²)。

O(n²) 卡在哪？卡在**大量重复劳动**：以 `"abcabcbb"` 为例，当你检查完 `s[0..2] = "abc"` 发现合法，接着检查 `s[0..3] = "abca"` 时，前三个字符 `abc` 的「无重复」这个事实被重新验证了一遍。而它明明上一轮已经验证过了。

**关键观察**：如果 `s[i..j]` 是无重复的，那么它的任意子区间 `s[i'..j']`（`i ≤ i' ≤ j' ≤ j`）也一定无重复。这个「合法性对收缩封闭」的性质，意味着**当区间变长导致重复时，你不需要从头重来，只需要把左端往右挪**。这就是滑动窗口的入口：维护一个「当前合法的窗口」，右端负责扩张，左端负责在冲突时收缩。

## 3. 从暴力到最优

用 `s = "abcabcbb"` 走一遍。维护窗口 `[left, right]` 和窗口内字符集合 `window`，以及答案 `ans`。

**第 0 步**：`left=0, right=0, window={}, ans=0`

| 步骤 | right 指向 | 字符 | 在 window 里？ | 动作 | window | ans |
|---|---|---|---|---|---|---|
| 1 | 0 | a | 否 | 加入，right→1 | {a} | 1 |
| 2 | 1 | b | 否 | 加入，right→2 | {a,b} | 2 |
| 3 | 2 | c | 否 | 加入，right→3 | {a,b,c} | 3 |
| 4 | 3 | a | **是** | 移出 s[left]=a，left→1 | {b,c} | 3 |
| 5 | 3 | a | 否 | 加入，right→4 | {b,c,a} | 3 |
| 6 | 4 | b | **是** | 移出 s[left]=b，left→2 | {c,a} | 3 |
| 7 | 4 | b | 否 | 加入，right→5 | {c,a,b} | 3 |
| 8 | 5 | c | **是** | 移出 s[left]=c，left→3 | {a,b} | 3 |
| 9 | 5 | c | 否 | 加入，right→6 | {a,b,c} | 3 |
| 10 | 6 | b | **是** | 移出 s[left]=a，left→4 | {b,c} | 3 |
| 11 | 6 | b | **是** | 移出 s[left]=b，left→5 | {c} | 3 |
| 12 | 6 | b | 否 | 加入，right→7 | {c,b} | 3 |
| 13 | 7 | b | **是** | 移出 s[left]=c，left→6 | {b} | 3 |
| 14 | 7 | b | **是** | 移出 s[left]=b，left→7 | {} | 3 |
| 15 | 7 | b | 否 | 加入，right→8 | {b} | 3 |

结束，`ans = 3`。

注意第 10-11 步：`right` 停在 6（字符 `b`），`left` 连续右移了两次才把冲突消掉。这说明**内层 while 可能执行多次，但 `left` 总共只从 0 走到 7，全程不超过 n 次**——这是复杂度分析的关键，第 6 节展开。

**瓶颈是怎么被消掉的**：暴力法每次扩张右端都要重新扫描整个窗口查重（O(n) 一次）；滑动窗口把「查重」降成集合的 O(1) 查询，把「收缩」摊还成每个字符最多被移出一次。于是 O(n²) → O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义循环不变量：

> 在每次外层循环开始时，`window` 恰好等于 `s[left..right-1]` 的字符集合，且该区间内无重复字符。

**初始化**：`left=right=0`，区间为空，`window` 为空，成立。

**保持**：外层循环取 `c = s[right]`。
- 若 `c ∉ window`，加入后 `window = s[left..right]` 的字符集，且无重复（原来无重复，新字符不在其中），`right` 自增，不变量恢复。
- 若 `c ∈ window`，内层 while 反复移出 `s[left]` 并 `left++`，直到 `c ∉ window`。由于 `c` 在窗口内只可能出现一次（不变量保证无重复），这个循环必然终止。终止时窗口无重复，再加入 `c`、`right++`，不变量恢复。

**不漏**：设最优解是 `s[i..j]`，长度 `L`。考虑 `right` 第一次到达 `j+1` 的那一刻（即刚处理完 `s[j]`）。此时窗口是 `s[left..j]`。由于 `s[i..j]` 无重复，而窗口是「以 `j` 结尾的最长无重复区间」——因为 `left` 只会因冲突而右移，且每次右移都是被迫的——所以 `left ≤ i`，窗口长度 `j-left+1 ≥ j-i+1 = L`。而 `ans` 每轮取 `max`，故 `ans ≥ L`。

**不重**：`ans` 只记录真实存在的合法窗口长度（每次更新时窗口确实无重复，由不变量保证），所以 `ans ≤ L`。两边夹住，`ans = L`。

## 5. 完整代码（Python）

```python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        window = set()      # 当前窗口 [left, right) 内的字符集合
        left = 0            # 窗口左边界（含）
        ans = 0             # 历史最长合法窗口长度

        for right in range(len(s)):          # 右端逐个扩张
            c = s[right]
            # 冲突时收缩左端，直到 c 不在窗口里
            while c in window:
                window.remove(s[left])
                left += 1
            # 此时窗口无重复，把 c 纳入
            window.add(c)
            # 窗口为 [left, right]，长度 right - left + 1
            ans = max(ans, right - left + 1)

        return ans
```

一个常见写法优化：用 `dict` 记录「字符 → 最后出现的下标」，冲突时 `left = max(left, last_pos[c] + 1)`，省掉 while 循环。但要注意 `max` 不能省——`last_pos[c]` 可能落在 `left` 左边（该字符已被移出窗口），直接赋值会让 `left` 倒退。初学阶段建议先用上面的 `set` 版本，逻辑更直白。

## 6. 复杂度

**时间 O(n)**，n 是字符串长度。拆开看：
- 外层 `for` 循环执行 n 次，每次 O(1) 的集合查询和插入。
- 内层 `while` 循环的总执行次数：`left` 从 0 单调递增到至多 n，每次 while 让 `left` 加 1，所以**整个算法生命周期内 while 体总共执行不超过 n 次**。这叫摊还分析——单次外层循环可能触发多次 while，但平均下来每个字符只被移出一次。
- 合计 O(n) + O(n) = O(n)。

**空间 O(min(n, Σ))**，Σ 是字符集大小。`window` 集合最多存 `min(n, Σ)` 个字符。本题提示说字符来自英文字母、数字、符号和空格，Σ 是个常数（ASCII 范围内约 128），所以实际是 O(1)；但按通用写法记 O(min(n, Σ)) 更严谨。

## 7. 边界与反例（至少 4 条）

1. **`s = ""`** → 期望 `0`。容易错在：`for` 循环不执行，若 `ans` 初值写成 `-1` 或忘了初始化就返回错值。初值必须是 `0`。

2. **`s = " "`（单个空格）** → 期望 `1`。容易错在：把空格当「空」处理，或用了 `s.strip()` 之类的预处理。题面明确说字符包含空格，空格是合法字符。

3. **`s = "bbbbb"`** → 期望 `1`。容易错在：内层 while 写成 `if`。这里 `right=1` 时窗口 `{b}` 冲突，移出后 `left=1`，窗口空，再加入 `b`——用 `if` 恰好也对。但换成 `s = "abba"`：处理第二个 `b` 时窗口 `{a,b}`，`if` 只移出 `a` 得到 `{b}`，再加入 `b` 就重复了。**必须用 while**。

4. **`s = "dvdf"`** → 期望 `3`（`"vdf"`）。容易错在：以为答案是 `"dv"` 长度 2。冲突发生在第二个 `d`，`left` 要从 0 移到 2 才能把第一个 `d` 移出去，窗口变成 `"vd"` 再加 `d` 得 `"vdf"`。这题专门检验「左端要连续收缩多次」。

5. **`s = "abba"`** → 期望 `2`。这是第 3 条提到的 `if` vs `while` 的经典反例，也是 `dict` 优化版里必须写 `max(left, ...)` 的原因。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求「至多包含 k 个不同字符的最长子串」怎么改？**
   思路：把「窗口内无重复」换成「窗口内不同字符数 ≤ k」，用 `dict` 记频次，超了就收缩左端直到频次降到 k，其余框架不变。

2. **追问：如果要求「至少包含 k 个不同字符的最短子串」怎么改？**
   思路：窗口合法性条件反过来——不足 k 时扩张右端，满足 k 后尝试收缩左端并更新答案，是同一套双指针的镜像用法。

3. **追问：如果字符串是流式输入、不能回看，还能做吗？**
   思路：可以。滑动窗口只依赖 `left` 和窗口内的字符集合，天然适合流式处理；但 `dict` 优化版需要存「最后出现位置」，流式下同样可行，只是要维护字符到位置的映射。
