## 1. 一句话本质

对每个节点问一句「以你为根的子树有多高」，答案就是「左右孩子报上来的高度取大，再加 1（算上自己）」，一路递归上报到根。

## 2. 读完题的第一反应

**朴素解法**：把树里所有从根到叶子的路径都枚举出来，数每条路径的节点数，取最大。这需要显式地维护「当前路径」，走到叶子时记录长度。问题在于：你要写一个带状态的回溯过程，而且每条路径都要单独走一遍——虽然总代价其实还是 O(n)（每个节点只属于若干条路径中的一条前缀，但枚举所有路径的总长度是 O(n·h) 级别，最坏链状树是 O(n²)）。卡点不在「想不出来」，而在「写起来啰嗦、容易在回溯时忘记恢复状态」。

**关键观察**：题目问的是「最长路径上的节点数」，而路径必然从根出发。那么对任意节点 u，以 u 为根的子树的最大深度，只依赖 u 的左右子树的最大深度，跟 u 的祖先、兄弟完全无关。这就是**最优子结构**：大问题（整棵树的高度）可以拆成两个同构的小问题（左右子树的高度），拆到空树时答案是 0。

这个观察直接指向递归：`maxDepth(u) = 1 + max(maxDepth(u.left), maxDepth(u.right))`，空节点返回 0。你不需要「记住路径」，因为高度是自底向上汇总出来的，不是自顶向下数出来的。

## 3. 从暴力到最优

**暴力（枚举所有根到叶路径）**：以示例 1 的树 `[3,9,20,null,null,15,7]` 为例，结构是：

```
        3
       / \
      9   20
         /  \
        15   7
```

枚举路径得到 `[3,9]`（长度 2）、`[3,20,15]`（长度 3）、`[3,20,7]`（长度 3），取最大 3。中间变量就是「当前路径列表」和「当前最大长度」，每到一个叶子比较一次。瓶颈：需要显式栈保存路径，回溯时要 pop，代码分支多；且对链状树，路径枚举的累计代价退化。

**递归汇总（最优）**：换个方向想——不问「根到叶有多长」，而问「叶子往根报多高」。

- 节点 9：左空返回 0，右空返回 0 → `1 + max(0,0) = 1`
- 节点 15：同理返回 1
- 节点 7：返回 1
- 节点 20：左 1、右 1 → `1 + max(1,1) = 2`
- 节点 3：左 1、右 2 → `1 + max(1,2) = 3`

每个节点只被访问一次，返回值就是「以它为根的子树高度」。瓶颈被消掉的方式是：**不再维护路径，而是让子问题的返回值携带信息**。路径信息（长度）被压缩成了一个整数，沿调用栈向上传递。

对比一下：暴力是「自顶向下数，到叶子结算」；递归是「自底向上报，到根结算」。后者每个节点只算一次常数工作，天然 O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义函数 `f(u)` 的语义为：**返回以 u 为根的子树中，从 u 到该子树最远叶子的节点数**（空树定义为 0）。

**不变量**：每次 `f(u)` 返回时，返回值恰好等于上述定义的值。

**归纳证明**（对子树高度归纳）：

- 基例：u 为空，返回 0，与定义一致（空树无路径，深度 0）。
- 归纳步：设 u 非空，且对 u 的左右孩子 `f` 均满足不变量（孩子子树更小，归纳假设成立）。u 到最远叶子的路径，第一步必然走向左孩子或右孩子（叶子情形下两边都是空，路径只有 u 自己）。若走左，路径长度 = 1 +（左子树内从孩子到最远叶子的节点数）= `1 + f(u.left)`；走右同理。取两者较大者即覆盖了所有可能，故 `1 + max(f(left), f(right))` 正是 u 子树的最大深度。

**不漏**：任意一条从 u 出发到叶子的路径，第一步只能落在左或右，两种情形都被 max 覆盖。
**不重**：max 只取一个值，不存在重复计数；且每个节点只被其父节点调用一次，整棵树每个节点恰好贡献一次「+1」。

因为根节点没有父节点，`f(root)` 就是题目所求，归纳保证它正确。

## 5. 完整代码（Python）

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def maxDepth(self, root) -> int:
        # 空树深度为 0，这是递归的基例，也是整棵树为空时的答案
        if root is None:
            return 0

        # 分别求左右子树的最大深度（子问题，语义与本题完全一致）
        left_depth = self.maxDepth(root.left)
        right_depth = self.maxDepth(root.right)

        # 当前节点自身贡献 1 层，加上左右中较深的一侧
        return 1 + max(left_depth, right_depth)
```

如果担心递归深度（题目节点数上限 10^4，链状树会触发 Python 默认递归上限约 1000），可以改成显式栈的迭代版，思路完全一样，只是把「返回值」换成「栈里的 (节点, 是否已处理)」：

```python
class Solution:
    def maxDepth(self, root) -> int:
        if root is None:
            return 0
        # 栈元素: (节点, 该节点子树是否已计算完毕)
        stack = [(root, False)]
        depth = {None: 0}  # 用字典模拟「子问题返回值」，None 代表空树
        while stack:
            node, visited = stack.pop()
            if node is None:
                continue
            if visited:
                # 两个孩子都已算完，此时可以汇总当前节点
                depth[node] = 1 + max(depth[node.left], depth[node.right])
            else:
                # 先标记「待汇总」，再把孩子压栈（后进先出，孩子先处理）
                stack.append((node, True))
                stack.append((node.left, False))
                stack.append((node.right, False))
        return depth[root]
```

## 6. 复杂度

**时间 O(n)**，n 为节点数。每个节点在递归中恰好被访问一次，每次做常数次操作（两次递归调用 + 一次 max + 一次加法）。没有节点被重复进入，所以总工作量与 n 成正比。

**空间 O(h)**，h 为树高。空间全部来自递归调用栈：最深同时存活的栈帧数等于从根到最深叶子的路径长度，即 h。注意这里**不是 O(log n)**——O(log n) 只适用于平衡树；最坏情况是链状树，h = n，空间退化为 O(n)。迭代版同理，栈最多压入 O(h) 量级的待处理节点（每个节点压两次，仍是 O(h) 常数倍）。

## 7. 边界与反例（至少 4 条）

1. **`root = []`（空树）** → 期望 `0` → 容易错在没写 `if root is None: return 0`，直接访问 `root.left` 抛 `AttributeError`。题面节点数区间是 `[0, 10^4]`，明确允许空树。
2. **`root = [1]`（单节点）** → 期望 `1` → 容易错在把「叶子」当成深度 0，或误以为要减 1。定义是「节点数」，单节点路径含 1 个节点。
3. **`root = [1,null,2]`（示例 2，只有右链）** → 期望 `2` → 容易错在只递归左子树，或误判「左空则深度为 0」。必须对左右都递归再取 max，不能因为一边空就跳过。
4. **`root = [1,2,null,3,null,4]`（长左链，深度 4）** → 期望 `4` → 容易错在递归深度超限（Python 默认约 1000，链长 10^4 时必崩），需要迭代版或 `sys.setrecursionlimit`。
5. **完全平衡树 `[1,2,3,4,5,6,7]`** → 期望 `3` → 容易错在把「层数」和「边数」混淆，或误用 `log2(n)+1` 的公式（只对满二叉树成立）。

## 8. 面试追问与变体（3 条）

1. **追问：不用递归，用 BFS 怎么做？** 思路：按层遍历，每弹完一层 `depth += 1`，队列空时返回 depth；天然避免递归深度问题，空间 O(最宽层)。
2. **追问：求最小深度怎么改？** 思路：`1 + min(left, right)`，但**必须特判单孩子节点**——若一边为空，最小深度只能走非空那侧，不能取 min（否则空侧返回 0 会得到错误答案）。
3. **追问：判断是否平衡二叉树（每个节点左右子树高度差 ≤ 1）？** 思路：在求高度的递归里顺带返回「是否平衡」，一旦某子树不平衡就向上短路返回 -1，避免对每个节点重复求高度导致 O(n²)。

## 9. 举一反三（2-3 道同类题）

- **111. 二叉树的最小深度**：与本题同构，都是「子树高度汇总」，区别在 min 与单孩子特判。
- **110. 平衡二叉树**：复用本题的「求高度」子过程，把返回值扩展成「高度 + 平衡标记」。
- **543. 二叉树的直径**：同样自底向上汇总，但答案不是根的高度，而是「左右高度之和」在任意节点处的最大值，需要在递归中维护全局最优。
