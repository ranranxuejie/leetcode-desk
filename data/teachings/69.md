## 1. 一句话本质

求最大的整数 `k`，使得 `k² ≤ x`。

把这句话和题面对一下：题目要「整数部分」，也就是 `⌊√x⌋`。而 `k = ⌊√x⌋` 恰好等价于「`k² ≤ x` 且 `(k+1)² > x`」，即满足 `k² ≤ x` 的**最大**整数。这一步转换是整道题的枢纽——它把「开方」这个我们不会算的运算，换成了「平方比较」这个我们一定会算的运算。

## 2. 读完题的第一反应

**朴素解法**：从 `k = 0` 开始，逐个试 `k = 1, 2, 3, ...`，找到第一个 `k² > x` 就返回 `k-1`。

它卡在哪？看数据范围：`x` 最大到 `2^31 - 1 ≈ 2.1×10⁹`，对应的答案约 `46340`。也就是说最坏要循环四万六千多次。单次测试能过，但这是 O(√x) 的复杂度——面试官问「能不能更快」时你就没牌了。瓶颈在于：我们**线性地**扫描候选答案，而候选答案的集合其实有很强的结构。

**关键观察**：定义函数 `f(k) = k²`。在 `k ≥ 0` 上它是**单调递增**的。于是「`k² ≤ x`」这个条件在候选区间 `[0, x]` 上呈现出「前面全真、后面全假」的形状——一条分界线，左边全满足，右边全不满足。凡是这种「单调谓词 + 找分界点」的结构，二分查找就是标准答案：每次砍掉一半候选，`46340` 次比较变成 `log₂(46340) ≈ 16` 次。

注意这里二分的是**答案**，不是数组下标。这是很多人第一次见会愣住的地方：二分查找不要求有数组，只要求「候选集合有序 + 判定条件单调」。

## 3. 从暴力到最优

以 `x = 8` 为例（答案应为 2）。

**暴力**：`k=0, 0²=0≤8` 继续；`k=1, 1≤8` 继续；`k=2, 4≤8` 继续；`k=3, 9>8` 停，返回 `3-1=2`。做了 4 次乘法。

**二分**：候选区间 `lo=0, hi=8`（先粗放地取 `hi=x`，后面再优化）。

- `mid=(0+8)//2=4`，`4²=16 > 8` → 答案在左半边，`hi=3`
- `mid=(0+3)//2=1`，`1²=1 ≤ 8` → 1 可行，但可能还有更大的，`lo=2`
- `mid=(2+3)//2=2`，`2²=4 ≤ 8` → `lo=3`
- 此时 `lo=3 > hi=3`？不，`lo=3, hi=3`，循环条件 `lo <= hi` 仍成立：`mid=3`，`3²=9 > 8` → `hi=2`
- `lo=3 > hi=2`，退出。返回 `hi=2`。✓

4 次比较，和暴力一样多——因为 `x=8` 太小了。但把 `x` 换成 `2^31-1`，暴力要 46340 次，二分只要 16 次。**二分的收益随规模指数级放大**，小例子看不出优势是正常的，别因此怀疑它。

**两个必须想清楚的细节**：

1. **返回 `lo` 还是 `hi`？** 循环退出时必然 `lo = hi + 1`。`hi` 是「最后一个满足 `k² ≤ x` 的位置」，`lo` 是「第一个不满足的位置」。我们要的是最大可行解，所以返回 `hi`。
2. **`hi` 的初值取 `x` 还是更小？** 取 `x` 是对的但浪费：`x ≥ 4` 时 `√x ≤ x/2`，可以令 `hi = x // 2`；`x < 4` 时答案就是 `x` 本身（0→0, 1→1, 2→1, 3→1）。这个优化不是必需的，但能体现你想过边界。下面的代码用 `hi = x` 保持逻辑最简，把优化留作注释。

**溢出问题**：Python 的大整数不会溢出，`mid * mid` 随便算。但如果面试官让你用 C++/Java 写，`mid` 最大约 46340，`mid²` 约 2.1×10⁹，刚好卡在 `int` 上限附近，必须用 `long` 或写成 `mid <= x // mid` 来规避。**主动提这一点是加分项**，因为它说明你知道二分的坑不只在逻辑上。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。维护两个断言：

- **不变量 A**：`hi` 始终是一个「可行解」，即 `hi² ≤ x`（初始 `hi = 0`，`0² = 0 ≤ x` 恒成立，因为 `x ≥ 0`）。
- **不变量 B**：`lo - 1` 始终是「可行解的上界之外」，即 `(lo-1)² ≤ x` 且 `lo² > x` 在退出时成立；循环中我们保证 `lo` 只会移动到「已验证可行」的位置之后。

每轮迭代：

- 若 `mid² ≤ x`：`mid` 可行，真正的答案 ≥ `mid`，把 `lo` 推到 `mid+1`，**不会漏掉 `mid` 本身**，因为 `hi` 的更新只在 `mid² > x` 时发生，而那时 `mid` 确实不可行。
- 若 `mid² > x`：`mid` 不可行，答案 < `mid`，把 `hi` 推到 `mid-1`，**不会误纳 `mid`**。

两个分支都把候选区间缩小了至少一半（`mid` 被排除），所以循环必然终止。终止时 `lo = hi + 1`，由不变量 A 知 `hi` 可行，由不变量 B 知 `hi+1 = lo` 不可行。于是 `hi` 是「可行的最大值」，正是 `⌊√x⌋`。

**为什么不会重**：每个 `mid` 只被检查一次，检查后立刻被排除出区间，不存在重复判定。**为什么不会漏**：每次排除的都是已被证明不可行的值，可行值永远留在 `[lo, hi]` 内（`hi` 只在不可行时才降，`lo` 只在可行时才升）。

## 5. 完整代码（Python）

```python
class Solution:
    def mySqrt(self, x: int) -> int:
        # 边界：0 和 1 直接返回，避免后续 hi 计算出现负数区间
        if x < 2:
            return x

        lo, hi = 1, x          # 候选答案区间 [lo, hi]，答案一定落在其中
        ans = 0                # 记录最后一个验证可行的值

        while lo <= hi:
            mid = (lo + hi) // 2
            sq = mid * mid     # Python 大整数，无溢出风险

            if sq == x:
                return mid     # 精确命中，直接返回，省掉后续收敛
            elif sq < x:
                ans = mid      # mid 可行，先记下来，再往右找更大的
                lo = mid + 1
            else:
                hi = mid - 1   # mid 不可行，往左找

        return ans             # 循环结束时 ans 就是最大的可行解
```

几个写法上的说明：

- `if x < 2: return x` 覆盖了 `x=0` 和 `x=1`。不写这行也能跑（`lo=1, hi=0` 时循环不进入，返回 `ans=0`，对 `x=1` 就错了），所以这行是**必要的**，不是装饰。
- 用 `ans` 变量而不是靠 `hi` 收尾，是为了让「记录可行解」这件事显式化，读代码的人一眼看出我们在找最大值。你也可以去掉 `ans`、最后 `return hi`，逻辑等价（因为退出时 `hi` 就是最后一个可行位置），但显式记录更不容易在变体题里写错。
- `sq == x` 提前返回是纯优化，去掉不影响正确性。

## 6. 复杂度

**时间 O(log x)**。二分的候选区间长度初始为 `x`，每轮至少减半，所以迭代次数是 `⌈log₂ x⌉`。`x` 最大 `2^31`，即最多约 31 次迭代。这里的 `log` 来自**候选答案的个数**，不是输入的长度——这是本题容易被问倒的点：输入是一个整数，它的「规模」既可以用数值 `x` 衡量（那二分是 O(log x)），也可以用位数 `log x` 衡量（那二分是 O(位数)，即输入规模的多项式）。面试时说「O(log x)」并补一句「x 是数值大小」最稳妥。

**空间 O(1)**。只用了 `lo, hi, mid, ans, sq` 五个变量，与 `x` 无关。没有递归，没有栈。

对比暴力：暴力是 O(√x) 时间，`x = 2^31` 时约 4.6 万次乘法；二分 31 次。差距三个数量级。

## 7. 边界与反例（至少 4 条）

1. **`x = 0`** → 期望 `0`。容易错在：若 `lo` 初始化为 1 且不特判，`lo=1 > hi=0` 循环不进，返回 `ans=0` 恰好对；但如果你的写法是 `return lo`，就会返回 1。**返回值的选取在空区间时最危险**。
2. **`x = 1`** → 期望 `1`。容易错在：同上，若靠 `return lo` 且不特判，`lo=1, hi=1` 进入循环，`mid=1, 1²=1` 命中返回 1，碰巧对；但若 `hi` 初值取 `x//2 = 0`，区间变空，返回 0 就错了。**`hi` 的优化写法必须配合 `x < 4` 的特判**。
3. **`x = 2`** → 期望 `1`。容易错在：`√2 ≈ 1.414`，向下取整是 1 不是 2。有人会误以为「四舍五入」或「至少返回 1」，其实 `x=2` 时 `1²=1≤2`、`2²=4>2`，答案就是 1。
4. **`x = 2147483647`（`2^31-1`）** → 期望 `46340`。容易错在：`46340² = 2147395600 ≤ x`，`46341² = 2147488281 > x`，边界极窄。若在 C++ 里用 `int` 算 `mid*mid`，`46341²` 会溢出成负数，导致判定反转、死循环或错答。Python 无此问题，但**要能说出这个坑**。
5. **`x = 4`** → 期望 `2`。容易错在：这是「精确平方数」，`mid² == x` 的分支必须能命中；若你把条件写成 `sq < x` 才更新 `lo`、`sq > x` 才更新 `hi`，漏掉 `==`，会多绕几轮（虽然最终仍可能对，但逻辑不干净，且在某些变体里会错）。

## 8. 面试追问与变体（3 条）

1. **「如果要求返回精确到小数点后 k 位的平方根呢？」** 思路：二分不再在整数上做，而是在浮点数区间 `[0, x]` 上做，循环条件改成 `hi - lo > 1e-6`（或迭代固定次数 `k*log` 量级），最后返回 `lo` 或 `(lo+hi)/2`。核心不变：单调谓词 + 二分，只是「分界点」从整数变成实数。
2. **「不用二分，用牛顿迭代怎么写？复杂度如何？」** 思路：迭代 `y = (y + x/y) / 2`，从 `y = x` 出发，收敛到 `√x` 是**二次收敛**（每轮有效位数翻倍），迭代次数 O(log log x)，比二分更快。终止条件用 `y*y <= x` 判断并返回 `int(y)`。面试官问这个通常是想看你知不知道「二分不是唯一解，数值方法更快但更难写对边界」。
3. **「如果 x 是浮点数，且要求返回 `⌊√x⌋`，你的代码要改哪里？」** 思路：`lo, hi` 的初值改为 `0` 和 `int(x)`（或 `x` 本身），`mid` 用浮点，比较 `mid*mid <= x` 时注意浮点误差，通常加一个 `eps` 容差，最后 `return int(hi)`。考点是「整数二分的边界处理在浮点下会退化，需要容差」。

## 9. 举一反三（2-3 道同类题）

- **LeetCode 367. 有效的完全平方数**：和本题共用「`k²` 与 `x` 比较」的单调谓词，只是把「找最大可行 k」换成「判断是否存在 k 使 `k² == x`」，二分骨架完全一致。
- **LeetCode 35. 搜索插入位置**：同样是「在有序候选上找分界点」，返回 `lo` 还是 `hi` 的取舍逻辑与本题同源，是练习「循环不变量 + 返回值选择」的最佳配对题。
- **LeetCode 875. 爱吃香蕉的珂珂**：二分答案的典型——不在数组上二分，而是在「速度」这个答案空间上二分，判定函数是「以速度 k 能否在 h 小时内吃完」。和本题一样，难点不在二分模板，而在**把问题翻译成「单调谓词 + 找最小/最大可行值」**。
