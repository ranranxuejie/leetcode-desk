## 1. 一句话本质

在 value 上切两刀（a 的长度、b 的长度），使得按 pattern 展开后拼出来的字符串恰好等于 value——本质是**枚举两个未知长度的二元一次方程求解**。

## 2. 读完题的第一反应

朴素想法：pattern 里每个 `a` 和 `b` 都是未知字符串，那就回溯——给第一个 `a` 尝试 value 的每个前缀，给第一个 `b` 尝试剩下的每个前缀，然后顺着 pattern 往下匹配，遇到冲突就回退。这确实能写，但分支因子是 O(n)，pattern 长度最多 1000，最坏退化成指数级，肯定过不了。

关键观察：**一旦 a 的长度 `la` 和 b 的长度 `lb` 定下来，整个匹配过程就没有任何选择余地了**。因为 pattern 里 a 出现 `cntA` 次、b 出现 `cntB` 次，展开后的总长度必须满足

```
la * cntA + lb * cntB == len(value)
```

这是一个二元一次方程。`cntA`、`cntB`、`len(value)` 都是已知常数，所以只要枚举 `la`（0 到 len(value)），`lb` 就被唯一确定了——不需要枚举 `lb`。分支从「指数」直接降到「线性枚举一个变量」。

更进一步：如果 `cntA > 0`，`la` 的上界是 `len(value) // cntA`，因为 a 至少要占这么多位置。这又砍掉一大截。

## 3. 从暴力到最优

**暴力回溯**：给 a 选一个前缀、b 选一个前缀，沿 pattern 走，冲突回退。最坏 O(n^pattern长度)，不可行。

**第一步优化——枚举长度代替枚举字符串**：不再猜「a 是什么」，而是猜「a 有多长」。因为长度定了，a 的内容就被 pattern 中第一个 a 出现的位置唯一确定（就是 value 开头那 `la` 个字符），b 同理。枚举量从「所有子串组合」变成「O(n) 个长度」。

**第二步优化——用方程消掉一个变量**：`lb = (len(value) - la * cntA) / cntB`，要求整除且非负。于是只需枚举 `la`，O(n) 个候选，每个候选做一次 O(len(value)) 的验证，总 O(n²)，n ≤ 1000 完全够。

**小例子走一遍**：`pattern = "abba"`，`value = "dogcatcatdog"`，len=12，cntA=2，cntB=2。

- 枚举 `la = 3`：`lb = (12 - 3*2) / 2 = 3`。a 取 value[0:3]="dog"，b 取 pattern 中第一个 b 的位置——pattern[1] 对应 value 偏移 `la*1 = 3`，即 value[3:6]="cat"。展开验证：a b b a → "dog"+"cat"+"cat"+"dog" = "dogcatcatdog"，相等，返回 true。
- 若先枚举到 `la = 1`：`lb = (12-2)/2 = 5`，a="d"，b 从偏移 1 取 5 个 = "ogcat"，展开 "d"+"ogcat"+"ogcat"+"d" = "dogcatogcatd" ≠ value，继续。
- 枚举到 `la = 5`：`lb = (12-10)/2 = 1`，a="dogca"，b 从偏移 5 取 1 个 = "t"，展开 "dogca"+"t"+"t"+"dogca" ≠ value，继续。

只有 `la=3` 通过。

**示例 4 的坑**：`pattern="abba"`，`value="dogdogdogdog"`，len=12。枚举 `la=6`：`lb=(12-12)/2=0`，a="dogdog"，b 为空串。展开 "dogdog"+""+""+"dogdog" = "dogdogdogdog"，通过。所以**必须允许长度为 0**，这是很多人漏掉的分支。

## 4. 正确性：为什么不会漏、不会重

**不漏**：假设存在某个合法解 (a₀, b₀)，令 `la = len(a₀)`、`lb = len(b₀)`。由于展开后总长等于 len(value)，必有 `la*cntA + lb*cntB = len(value)`。我们的枚举覆盖了 `la` 从 0 到 `len(value)//cntA` 的所有值（若 cntA=0 则单独处理），所以这个 `la` 一定被枚举到；此时算出的 `lb` 由方程唯一确定，必等于 `len(b₀)`。长度对上后，a 的内容被「pattern 中第一个 a 对应的 value 片段」唯一确定，b 同理，验证函数会接受它。故不漏。

**不重**：不同的 `la` 对应不同的 a 长度，不可能产生同一个解；同一 `la` 下 `lb` 唯一。所以每个候选解只被检查一次，不存在重复计数影响正确性（本题只问存在性，重不重其实无所谓，但枚举结构本身是无重的）。

**不变量**：在验证阶段，维护「已匹配的 value 前缀长度 `pos`」和「a、b 已绑定的字符串」。每处理一个 pattern 字符，就要求 value 从 `pos` 开始的那一段等于已绑定的字符串（若未绑定则绑定之）。`pos` 单调递增，处理完 pattern 时 `pos` 必须恰好等于 len(value)——这个不变量保证了「展开长度 = value 长度」和「逐段内容相等」同时成立，即完全匹配。

## 5. 完整代码（Python）

```python
class Solution:
    def patternMatching(self, pattern: str, value: str) -> bool:
        n, m = len(pattern), len(value)
        # 空 pattern：只有 value 也为空才匹配
        if n == 0:
            return m == 0
        cntA = pattern.count('a')
        cntB = n - cntA

        # 统一处理：让 cntA 是较多的那个（或至少非零），减少枚举上界
        # 若 a 不出现，交换角色，保证下面枚举的是"出现次数>0"的那个
        if cntA == 0:
            pattern = pattern.replace('b', 'a')
            cntA, cntB = cntB, cntA

        # 现在 cntA > 0。枚举 a 的长度 la
        # la 上界：a 总共占 la*cntA 个字符，不能超过 m
        for la in range(m // cntA + 1):
            rest = m - la * cntA
            # b 的总长度必须能被 cntB 整除
            if cntB == 0:
                if rest != 0:
                    continue
                lb = 0  # 无 b，lb 随便，验证时不会用到
            else:
                if rest < 0 or rest % cntB != 0:
                    continue
                lb = rest // cntB

            # 用长度 la、lb 去验证
            if self._check(pattern, value, la, lb):
                return True
        return False

    def _check(self, pattern: str, value: str, la: int, lb: int) -> bool:
        a_str = None  # a 绑定的字符串
        b_str = None
        pos = 0       # value 已消费到的位置
        for ch in pattern:
            length = la if ch == 'a' else lb
            seg = value[pos:pos + length]
            # 长度不够（越界）直接失败
            if len(seg) != length:
                return False
            if ch == 'a':
                if a_str is None:
                    a_str = seg
                elif a_str != seg:
                    return False
            else:
                if b_str is None:
                    b_str = seg
                elif b_str != seg:
                    return False
            pos += length
        # 必须恰好用完 value
        if pos != len(value):
            return False
        # a、b 不能同时表示相同字符串（题面要求）
        if a_str is not None and b_str is not None and a_str == b_str:
            return False
        return True
```

## 6. 复杂度

设 `n = len(pattern)`，`m = len(value)`。

- **时间**：外层枚举 `la`，上界 `m // cntA + 1 ≤ m + 1`；每个候选做一次 `_check`，`_check` 遍历 pattern 共 n 次，每次切片 `value[pos:pos+length]` 最坏 O(m)。所以单次验证 O(n·m)，总 O(m · n · m) = **O(n·m²)**。n, m ≤ 1000 时约 10⁹ 量级偏紧，但实际 `la` 的上界是 `m//cntA`，cntA 通常不小，且切片在 Python 里是 C 层 memcpy，常数很小，实测可通过。若想更稳，可把切片换成逐字符比较，复杂度不变但常数更可控；或预先算哈希把单次验证降到 O(n)，总 O(n·m)。
- **空间**：`_check` 里 `seg` 是切片产生的临时字符串，最坏 O(m)；`a_str`、`b_str` 各 O(m)。递归深度无（迭代）。总计 **O(m)**，不含输入本身。

## 7. 边界与反例（至少 4 条）

1. `pattern="", value=""` → **true**。容易错：忘记空 pattern 特判，或误以为空 pattern 匹配任何串。
2. `pattern="", value="abc"` → **false**。容易错：同上，空 pattern 只能匹配空串。
3. `pattern="a", value=""` → **true**（a 为空串）。容易错：枚举 `la` 时从 1 开始，漏掉长度 0。
4. `pattern="abba", value="dogdogdogdog"` → **true**（a="dogdog", b=""）。容易错：不允许 b 为空，或验证时 `pos != len(value)` 判断写反。
5. `pattern="aaaa", value="dogcatcatdog"` → **false**。容易错：只检查长度方程 `4*la == 12` 得 la=3，但没验证四段内容是否相同（"dog"≠"cat"）。
6. `pattern="ab", value="aa"` → **false**。因为 a="a"、b="a" 相同，违反「a、b 不能同时表示相同字符串」。容易错：漏掉最后的 `a_str == b_str` 检查。

## 8. 面试追问与变体（3 条）

1. **追问：如果 pattern 里不止 a、b，而是 26 个小写字母呢？** 思路：枚举变成 26 元方程，无法简单消元；改用回溯 + 剪枝（每个字母的长度上界由剩余长度和剩余出现次数决定），或对出现次数少的字母做枚举。
2. **追问：要求返回所有匹配方案（a、b 的具体取值），而不只是布尔？** 思路：把 `_check` 改成收集 `a_str`、`b_str`，枚举所有 `la` 不提前 return，去重后输出。
3. **追问：value 很长（10⁶），pattern 很短，怎么优化？** 思路：先算长度方程筛掉大部分 `la`，再用字符串哈希（Rabin-Karp）把每段比较降到 O(1)，总 O(m + n·候选数)。
