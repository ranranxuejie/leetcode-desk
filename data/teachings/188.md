## 1. 一句话本质

在「同一时刻最多持一股、买卖交替」的约束下，从价格序列里挑出**至多 k 组「低买高卖」的配对**，使各组价差之和最大。

## 2. 读完题的第一反应

**朴素解法**：枚举所有可能的交易划分。第 i 天要么不操作、要么买、要么卖，还要记录已经用掉几笔交易——搜索树的分支是指数级的，n=1000 时完全不可行。即使退一步想「枚举所有买入日/卖出日组合」，组合数也是 C(n, 2k) 量级。

**卡在哪**：真正让暴力爆炸的是「**天数 × 已用交易数 × 当前是否持股**」这三个维度同时存在。但注意——这三个维度恰好都是**有限且小**的：天数 ≤ 1000，交易数 ≤ 100，持股状态只有 2 种。也就是说，状态空间本身只有 1000 × 100 × 2 = 20 万，完全可枚举。

**关键观察**：题目问的是「前 i 天、最多 j 笔交易、结束时持不持股」的最优利润。这个量只依赖更小规模子问题的答案，不依赖具体做了哪几笔交易——**最优子结构**成立。一旦意识到「我只需要记住每个状态的最优值，不需要记住路径」，DP 就是自然选择。

另一个必须提前想到的点：k 可能远大于 n/2。一天最多完成一笔交易（买和卖不能同日，因为同日买卖利润为 0 且浪费额度），所以有效交易数上限是 ⌊n/2⌋。当 k ≥ n/2 时，约束「最多 k 笔」形同虚设，退化成「不限次数」的贪心问题——把所有相邻上涨段全部吃掉即可。这个剪枝不是可选项，是必须写进代码的，否则 k=100、n=2 时 DP 会白算一堆无用状态（虽然不会错，但这是面试官爱问的点）。

## 3. 从暴力到最优

**第一步：把「决策」翻译成状态转移。**

定义 `dp[i][j][0]` = 考虑前 i 天、至多完成 j 笔交易、第 i 天结束时**不持股**的最大利润；`dp[i][j][1]` = 同样条件下**持股**的最大利润。

第 i 天（价格 p = prices[i-1]，用 1-based 天数方便对齐）只有三种动作：

- 不持股 → 不持股：什么都不做，`dp[i-1][j][0]`
- 持股 → 不持股：今天卖出，`dp[i-1][j][1] + p`（卖出当天结算利润，交易数在买入时已经计过，见下）
- 不持股 → 持股：今天买入，`dp[i-1][j-1][0] - p`（**买入时把交易数 +1**，这样一笔交易只在买入瞬间计数一次，避免买卖各算一次）
- 持股 → 持股：什么都不做，`dp[i-1][j][1]`

于是：

```
dp[i][j][0] = max(dp[i-1][j][0], dp[i-1][j][1] + p)
dp[i][j][1] = max(dp[i-1][j][1], dp[i-1][j-1][0] - p)
```

**第二步：用小例子走一遍。** 取 `k=2, prices=[3,2,6,5,0,3]`，只跟踪 j=1 和 j=2 的关键值（j=0 时持股状态为 -∞，不持股为 0）。

初始：`dp[0][*][0]=0`，`dp[0][*][1]=-∞`。

- i=1, p=3：`dp[1][1][0]=max(0,-∞)=0`；`dp[1][1][1]=max(-∞, 0-3)=-3`。j=2 同理 `dp[1][2][1]=-3`。
- i=2, p=2：`dp[2][1][0]=max(0,-3+2)=0`；`dp[2][1][1]=max(-3, 0-2)=-2`。注意持股成本从 -3 改善到 -2，说明「第 2 天买比第 1 天买更划算」。
- i=3, p=6：`dp[3][1][0]=max(0,-2+6)=4`（第 2 天买、第 3 天卖，赚 4）；`dp[3][1][1]=max(-2, 0-6)=-2`；`dp[3][2][0]=max(0, dp[2][2][1]+6)=max(0,-3+6)=3`（第 1 天买、第 3 天卖，赚 3）。
- i=4, p=5：`dp[4][1][0]=max(4,-2+5)=4`；`dp[4][2][0]=max(3, dp[3][2][1]+5)=max(3,-2+5)=3`。
- i=5, p=0：`dp[5][1][0]=4`；`dp[5][1][1]=max(-2, 0-0)=0`（第 5 天买入成本 0，这是关键转折）；`dp[5][2][0]=max(3, dp[4][2][1]+0)=3`；`dp[5][2][1]=max(dp[4][2][1], dp[4][1][0]-0)=max(-2, 4)=4`。
- i=6, p=3：`dp[6][2][0]=max(3, dp[5][2][1]+3)=max(3, 4+3)=7`。

答案 `dp[6][2][0]=7`，与示例一致。注意 j=2 的持股状态在 i=5 时从 `dp[4][1][0]=4` 转移而来——意思是「先做完 1 笔赚 4，再在第 5 天以 0 元买入」，这正是示例里两笔交易的组合方式。

**第三步：消掉第一维。** 观察转移式，`dp[i][*][*]` 只依赖 `dp[i-1][*][*]`，所以可以把 i 这一维压掉，用两个长度为 k+1 的数组滚动更新。但**更新顺序有坑**：`dp[j][1]` 依赖 `dp[j-1][0]` 的旧值，而 `dp[j][0]` 又依赖 `dp[j][1]` 的旧值。安全做法是每轮先算新的 `dp0`、`dp1` 两个临时数组，或者按 j 从大到小更新（因为 `dp[j][1]` 用的是 `dp[j-1][0]`，j 递减时 `dp[j-1][0]` 还没被本轮覆盖）。下面代码用临时数组，最不容易写错。

**第四步：k 的剪枝。** 若 `k >= n // 2`，直接贪心：`sum(max(0, prices[i]-prices[i-1]))`。

## 4. 正确性：为什么不会漏、不会重

**不变量**：对任意 i、j，`dp[i][j][0]` 等于「前 i 天、至多 j 笔交易、第 i 天结束不持股」的所有合法方案中的最大利润；`dp[i][j][1]` 同理但要求持股。

**归纳证明**：i=0 时无交易可做，不持股利润 0、持股不可能（-∞），成立。假设 i-1 成立，考虑第 i 天。任何合法方案在第 i 天结束时要么不持股、要么持股。若不持股，则第 i 天要么没动作（对应 `dp[i-1][j][0]`），要么当天卖出（对应 `dp[i-1][j][1] + p`，卖出前必须持股，且交易数在买入时已计，卖出不再增加）。若持股，则要么没动作（`dp[i-1][j][1]`），要么当天买入（`dp[i-1][j-1][0] - p`，买入消耗一笔额度）。四种情况穷尽了所有可能，取 max 即得最优，**不漏**。

**不重**：交易数只在买入时 +1，卖出不计数，所以一笔完整交易恰好被计一次；「不能同时参与多笔交易」由状态 `[1]` 只能从 `[0]` 转移来保证——持股状态下不可能再买。因此不会把同一笔交易重复计入，也不会出现「同时持两股」的非法方案。

**为什么「至多 j 笔」可以用「恰好用 j 笔的额度」来算**：因为允许「什么都不做」的转移（`dp[i-1][j][0]` 直接继承），额度用不满时自动退化为更少笔数的最优解，所以「至多」和「恰好」在取 max 后等价。

## 5. 完整代码（Python）

```python
class Solution:
    def maxProfit(self, k: int, prices: list[int]) -> int:
        n = len(prices)
        if n < 2 or k == 0:
            return 0

        # 剪枝：一天最多一笔交易，有效交易数上限是 n//2
        # k 超过它时约束失效，退化为「不限次数」的贪心
        if k >= n // 2:
            return sum(max(0, prices[i] - prices[i - 1]) for i in range(1, n))

        NEG = float('-inf')
        # dp0[j]: 至多 j 笔交易、当前不持股的最大利润
        # dp1[j]: 至多 j 笔交易、当前持股的最大利润
        dp0 = [0] * (k + 1)
        dp1 = [NEG] * (k + 1)

        for p in prices:
            # 用临时数组承接本轮结果，避免原地更新时读到已被覆盖的值
            new0 = dp0[:]          # 默认「今天不操作」继承昨天
            new1 = dp1[:]
            for j in range(1, k + 1):
                # 今天卖出：昨天持股 + 今天价格
                new0[j] = max(new0[j], dp1[j] + p)
                # 今天买入：昨天不持股（j-1 笔额度）+ 付出今天价格
                new1[j] = max(new1[j], dp0[j - 1] - p)
            dp0, dp1 = new0, new1

        return dp0[k]
```

## 6. 复杂度

- **时间**：O(n·k)。外层遍历 n 天，内层遍历 k 个交易额度，每次常数操作。剪枝分支是 O(n)。谁贡献 n？天数；谁贡献 k？交易额度上限。
- **空间**：O(k)。两个长度 k+1 的数组，外加每轮两个临时数组（也是 O(k)）。没有 O(n) 的维度，因为天数维被滚动掉了。注意这里**没有 log 项**——如果面试官问「能不能更快」，答案是不能，因为至少要读一遍价格数组，Ω(n) 是下界，而 k 维无法消除（不同 k 的答案本质不同）。

## 7. 边界与反例（至少 4 条）

1. `k=0, prices=[1,2,3]` → 期望 `0`。容易错：忘记特判 k=0，进入循环后 `range(1,1)` 为空，返回 `dp0[0]=0` 其实也对，但如果剪枝写成 `k >= n//2` 而 n=3、k=0 不触发，逻辑仍正确；真正的坑是有人把 k=0 当成「不限次数」处理。
2. `k=100, prices=[1,2]` → 期望 `1`。容易错：不剪枝时 DP 要跑 100 层，虽然结果对但白费；更隐蔽的错是剪枝条件写成 `k > n//2` 而非 `>=`，k=1、n=2 时 `1 >= 1` 应走贪心，若写成 `>` 会走 DP，结果仍对但暴露理解不牢。
3. `prices=[5,4,3,2,1]`（单调下跌），任意 k → 期望 `0`。容易错：`dp1` 初始化为 0 而不是 -∞，会导致「买入」转移算出正利润的假象；必须用 -∞ 表示「不可能持股」。
4. `k=1, prices=[1]` → 期望 `0`。容易错：n<2 时若直接进 DP，`dp1[1] = max(-∞, 0-1) = -1`，最后返回 `dp0[1]=0` 碰巧对，但若代码里对 `prices[0]` 做了越界访问（比如贪心分支里 `prices[i-1]` 在 i=0 时）就会崩，所以 n<2 必须提前返回。
5. `k=2, prices=[1,2,4]` → 期望 `3`（一次买 1 卖 4，或买 1 卖 2 再买 2 卖 4 也是 3）。容易错：有人以为必须用满 2 笔，强行拆成两笔反而可能算错；「至多」语义靠 `new0 = dp0[:]` 的继承保证。

## 8. 面试追问与变体（3 条）

1. **追问：如果允许同一天既卖又买（即卖出后立刻用同一价格买入），答案会变吗？** 思路：不会。同日卖买等价于把两笔交易合并成一笔跨日的交易，利润不变，DP 的转移已经隐含允许（`dp0[j-1]` 可以是当天卖出后的值吗？注意代码里用的是**昨天**的 `dp0`，所以严格来说不允许同日卖买；但由于同日卖买无利可图，最优解总可以改写成不允许的形式，答案不变——这是需要讲清楚的细节）。
2. **追问：如果每笔交易有手续费 fee，怎么改？** 思路：卖出转移改成 `dp1[j] + p - fee`，其余不变；剪枝分支也要相应改成 `sum(max(0, prices[i]-prices[i-1]-fee))` 不再成立，需去掉剪枝或改用带 fee 的贪心。
3. **追问：如果要求恰好 k 笔交易（不能少做），怎么办？** 思路：把 `dp0` 初始化为 -∞（除 `dp0[0]=0`），禁止「不操作继承」把未用满额度的状态混进来，最后返回 `dp0[k]`；若为 -∞ 说明不可行。
