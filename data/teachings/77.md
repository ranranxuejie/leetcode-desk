## 1. 一句话本质

从 1..n 这 n 个有序候选里，按**下标递增**的方式挑出恰好 k 个，枚举所有这样的递增下标序列——也就是求大小为 k 的**子集**（组合无序，但我们可以用「升序」把它规范化成唯一一种写法）。

## 2. 读完题的第一反应

**朴素解法**：枚举所有长度为 k 的序列（n^k 种），再对每个序列排序去重。瓶颈有两处：一是 n^k 里绝大多数序列是「同一组合的不同排列」，重复计算；二是去重本身要额外开销。当 n=20、k=10 时，n^k 是天文数字，而真正的答案只有 C(20,10)≈18 万。

**关键观察**：组合和排列的唯一区别是「顺序无关」。那就在生成时**强制一种顺序**——只允许下标严格递增地往下选。这样每个组合只对应唯一一条「递增选择路径」，天然不重；同时因为每次都从「上一个选中元素的下一个位置」继续，也不会漏。这个「强制递增」的约束，正是回溯里 `start` 参数的来源。

顺着这个观察，问题变成：在一棵「候选树」上做深度优先搜索，每层选一个比上层大的数，选够 k 个就收集。这就是回溯。

## 3. 从暴力到最优

**第一步：暴力枚举所有 k 元序列。** 以 n=4,k=2 为例，会生成 (1,1),(1,2),...,(4,4) 共 16 条，其中 (1,2) 和 (2,1) 是同一组合，重复了。瓶颈：排列冗余。

**第二步：加「递增」约束消冗余。** 规定第二个数必须大于第一个数。此时 (2,1) 这类路径直接被剪掉，16 条降到 6 条，正好等于 C(4,2)=6。这一步把「排列」压成了「组合」。

**第三步：用回溯 + start 实现这个约束。** 维护 `path`（当前已选）和 `start`（下一个可选的最小值）。走一遍 n=4,k=2：

- 初始 `path=[], start=1`
- 选 1 → `path=[1], start=2`
  - 选 2 → `path=[1,2]`，长度=2，收集 `[1,2]`，回退
  - 选 3 → 收集 `[1,3]`，回退
  - 选 4 → 收集 `[1,4]`，回退
  - 回退到 `path=[1]`，本层枚举完，回退到 `path=[]`
- 选 2 → `path=[2], start=3`
  - 选 3 → 收集 `[2,3]`
  - 选 4 → 收集 `[2,4]`
- 选 3 → `path=[3], start=4`
  - 选 4 → 收集 `[3,4]`
- 选 4 → `path=[4], start=5`，后面没数可选，长度不够 2，直接返回

得到 6 个组合，和示例一致（顺序不同但题目允许任意顺序）。

**第四步：剪枝。** 注意上面「选 4」那一支是白跑的：`path=[4]` 时还剩 `n-4=0` 个数，凑不够 k-len(path)=1 个。一般地，若 `len(path) + (n - start + 1) < k`，即「已选 + 剩余可选」都不够 k，就没必要再往下。加上这个判断，能砍掉大量无效分支。这是本题从「能过」到「跑得快」的关键一步。

## 4. 正确性：为什么不会漏、不会重

**不变量**：搜索过程中，`path` 始终是一个严格递增的序列，且所有元素都在 `[1,n]` 内；`start` 等于 `path` 最后一个元素 +1（空时为 1）。

- **不漏**：任取一个合法组合，把它按升序写成 `a1<a2<...<ak`。因为 `a1≥1=初始 start`，且每步 `a_{i+1}>a_i`，所以这条路径在搜索树里一定存在——第 i 层选 `a_i` 时，`start=a_{i-1}+1≤a_i`，可选。故每个组合都会被走到。
- **不重**：每个组合的升序写法唯一，而搜索树里「从根到叶的路径」与「升序序列」一一对应（每层选一个数，路径即序列）。不同组合升序写法不同，路径不同，故不会重复收集。

**剪枝不破坏正确性**：剪枝条件是「剩余可选数不足以凑满 k」，被剪掉的分支确实无法产生长度 k 的组合，所以剪掉的都是无效解，不影响不漏。

## 5. 完整代码（Python）

```python
from typing import List

class Solution:
    def combine(self, n: int, k: int) -> List[List[int]]:
        res = []          # 收集所有长度为 k 的组合
        path = []         # 当前正在构造的组合（始终递增）

        def backtrack(start: int) -> None:
            # 终止条件：已选够 k 个，收集当前路径的副本
            if len(path) == k:
                res.append(path[:])   # 必须拷贝，path 后续会被修改
                return

            # 剪枝：从 start 到 n 一共 n-start+1 个数，
            # 若「已选 + 剩余」仍不足 k，则本层及以后都凑不满，直接返回
            if len(path) + (n - start + 1) < k:
                return

            # 枚举本层可选的数：从 start 到 n
            for i in range(start, n + 1):
                path.append(i)          # 做选择
                backtrack(i + 1)        # 下一层只能选比 i 大的数（保证递增、不重）
                path.pop()              # 撤销选择，回溯

        backtrack(1)
        return res
```

关键点说明：`path[:]` 拷贝是必须的，否则 `res` 里存的都是同一个列表的引用，最后全变成空列表；`backtrack(i+1)` 里的 `i+1` 就是「强制递增」约束的落地，也是 `start` 参数的意义所在。

## 6. 复杂度

- **时间**：O(k · C(n,k))。搜索树有 C(n,k) 个叶子（每个叶子对应一个组合），每个叶子在收集时要拷贝长度为 k 的 `path`，故乘 k。剪枝只减少常数级无效分支，不改变量级。注意不是 O(n^k)，因为递增约束把排列砍掉了。
- **空间**：O(k) 递归栈 + O(k) 的 `path`，即 O(k)（不计结果集）。结果集本身占 O(k·C(n,k))，这是输出规模决定的，通常不计入「算法额外空间」。这里没有 log n 项——本题不涉及排序或二分，别把别的题的复杂度套过来。

## 7. 边界与反例（至少 4 条）

1. **k=1**：输入 n=3,k=1 → 期望 `[[1],[2],[3]]`。易错点：有人把终止条件写成 `len(path)==k` 后忘了 `start` 从 1 开始，导致漏掉 1 或重复。
2. **k=n**：输入 n=3,k=3 → 期望 `[[1,2,3]]`。易错点：剪枝条件写反（写成 `>` 或漏掉 `+1`），会把唯一解剪掉；`n-start+1` 的 `+1` 极易漏。
3. **n=1,k=1**：输入 1,1 → 期望 `[[1]]`。易错点：`range(start, n+1)` 当 start=2 时为空，若终止判断放在循环后而非循环前，会返回空。
4. **忘记拷贝 path**：任何输入下 `res.append(path)` 不拷贝 → 最终全是空列表。这是最高频的 bug。
5. **start 传错**：写成 `backtrack(start+1)` 而非 `backtrack(i+1)`，会导致每层只前进一格、漏掉大量组合（如 n=4,k=2 只出 `[1,2]` 一类）。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求组合内元素可重复（如 [1,1,2] 合法）？** 思路：把 `backtrack(i+1)` 改成 `backtrack(i)`，允许同一元素被再次选取，其余不变。
2. **追问：如果候选数组含重复元素，要求结果去重（组合总和 II 型）？** 思路：先排序，同层枚举时跳过 `i>start and nums[i]==nums[i-1]` 的分支，保证同一层不选相同值。
3. **追问：不返回所有组合，只返回第 m 个（按字典序）？** 思路：利用组合的字典序与「递增路径」一致，用组合数学算每棵子树大小（C(剩余, 还需)），按大小跳转定位，O(nk) 而非枚举全部。

## 9. 举一反三（2-3 道同类题）

- **46. 全排列**：同样是回溯枚举，区别是不用 `start` 而用 `used` 数组标记已选，因为排列允许任意顺序、只需不重复选同一元素。
- **78. 子集**：同一棵「递增选择树」，只是不限制长度 k，每个节点（而非仅叶子）都收集，是本题的「无长度约束版」。
- **39. 组合总和**：本题加「元素可重复 + 目标和约束」，回溯骨架不变，改的是 `start` 传递方式和终止条件（和等于 target 时收集）。
