## 1. 一句话本质

把一棵树按「离根的距离」分层，同一层的节点从左到右收集成一组，最后返回一个「列表的列表」。

注意这个本质里有两个约束同时存在：**分层**（不同深度的节点不能混在一起）和**层内有序**（同一层必须从左到右）。后面所有的设计选择，都是围绕怎么同时满足这两点展开的。

## 2. 读完题的第一反应

最朴素的想法是：我遍历整棵树，把每个节点连同它的深度一起记下来，最后按深度分组。

这个思路本身没错，但它卡在一个地方：**你怎么知道当前节点在第几层？** 如果只做普通的递归遍历（前序/中序），递归函数里确实可以额外传一个 `depth` 参数，把 `(depth, val)` 塞进一个字典里。这能跑通，但有两个隐患：

- 递归深度受树高限制，虽然本题节点数 ≤ 2000，退化链状树时递归深度也是 2000，Python 默认递归上限 1000，会直接 `RecursionError`；
- 更关键的是，题目要的是「逐层」这个**顺序**。递归是深度优先的，天然先钻到底再回头，你是在「事后」按 depth 重新分组，而不是「按层推进」。这跟题目的语义是拧着的。

关键的观察在这里：**「逐层访问」这个词本身就在提示遍历顺序**。如果我用一个队列，先把根放进去，然后每次把「当前队列里的所有节点」一次性取完、取的同时把它们的左右孩子塞到队尾——那么这一批取出来的，恰好就是同一层，而且是从左到右（因为入队时先左后右）。下一批自然就是下一层。

这个观察之所以能让你想到下一步，是因为它把「分层」这个抽象要求，转化成了一个具体的**批次边界**问题：队列里哪些元素属于当前层？答案就是「这一轮开始前队列的长度」。

## 3. 从暴力到最优

**暴力版**：DFS 递归 + 字典按 depth 分组。

拿示例 1 走一遍：`root = [3,9,20,null,null,15,7]`，树形是

```
        3
       / \
      9   20
         /  \
        15   7
```

DFS 前序访问顺序是 `3(d0) → 9(d1) → 20(d1) → 15(d2) → 7(d2)`。字典累积成 `{0:[3], 1:[9,20], 2:[15,7]}`，最后按 key 排序输出。结果对，但注意：**访问顺序是 3,9,20,15,7，跟层序 3,9,20,15,7 碰巧一样**——这是巧合，换成 `[1,2,3,4]` 这种左偏树，DFS 顺序是 1,2,4,3，而层序是 1,2,3,4，就对不上了。所以暴力版本质是「先乱序收集、再排序重组」，多了一层不必要的间接。

**瓶颈在哪**：不是时间复杂度（DFS 也是 O(n)），而是**它没有利用「层」这个结构**，导致你要额外维护 depth、额外做分组、还要处理递归深度。换句话说，暴力版的复杂度没超，但它的「思维模型」和题目要求错位了。

**最优版**：BFS + 队列 + 按层切批。

还是示例 1，我逐步写出队列状态（`Q` 表示队列内容，`res` 是结果）：

| 轮次 | 进入本轮时 Q | 本轮长度 k | 取出的本层 | 新入队的孩子 | 本轮结束 Q | res |
|---|---|---|---|---|---|---|
| 1 | [3] | 1 | [3] | 9, 20 | [9,20] | [[3]] |
| 2 | [9,20] | 2 | [9,20] | 15, 7（9 无孩子，20 有俩） | [15,7] | [[3],[9,20]] |
| 3 | [15,7] | 2 | [15,7] | 无 | [] | [[3],[9,20],[15,7]] |

关键动作是第 2 轮：进入时队列长度是 2，我就**只循环 2 次**，不管循环体里又往队列塞了多少新节点。这 2 次取完，队列里剩下的正好是下一层。这个「先记长度、再按长度循环」就是消掉瓶颈的那一刀——它让「分层」变成了一个纯机械的计数问题，不需要 depth 参数、不需要字典、不需要排序。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来证。设队列为 `Q`，外层循环每执行一轮之前，我断言：

> **不变量**：此刻 `Q` 中恰好包含「当前尚未处理的那一层」的全部节点，且按从左到右排列；`res` 中已经存好了所有更浅层的完整结果。

**初始**：第一轮前，`Q = [root]`，恰好是第 0 层（唯一节点），从左到右成立；`res` 为空，没有更浅层，成立。

**保持**：假设某轮开始时不变量成立，`Q` 有 k 个节点，是第 d 层从左到右。本轮我循环 k 次，每次弹出队首——由于队列 FIFO 且入队顺序是「先左后右」，弹出的顺序就是第 d 层从左到右，**不漏不重**（k 次正好弹完这一层的 k 个节点，一个不多一个不少）。每次弹出时把左右孩子入队，这些孩子恰好是第 d+1 层的全部节点，且入队顺序保持了从左到右。k 次结束后，`Q` 里只剩第 d+1 层、从左到右，`res` 追加了第 d 层的完整结果。不变量对下一轮成立。

**终止**：当 `Q` 为空时，说明没有未处理的层了，所有层都已进 `res`，且每层内部有序。故输出正确。

「不会漏」由 k 次循环恰好覆盖本层全部节点保证；「不会重」由每个节点只在其父节点被弹出时入队一次、且只被弹出一次保证（根节点初始入队一次）。这两条合起来就是 BFS 在树上「每个节点访问恰好一次」的标准论证。

## 5. 完整代码（Python）

```python
from collections import deque
from typing import List, Optional

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

class Solution:
    def levelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        # 空树直接返回空列表，避免后面 deque 处理 None 的麻烦
        if root is None:
            return []

        res = []                 # 存放每一层的结果
        q = deque([root])        # BFS 队列，初始只有根

        while q:
            level_size = len(q)  # 关键：先锁定"本层"的节点个数
            level = []           # 本层的结果

            # 只循环 level_size 次，循环体里新入队的节点属于下一层，本轮不碰
            for _ in range(level_size):
                node = q.popleft()      # 队首出队，保证从左到右
                level.append(node.val)  # 收集本层值

                # 先左后右入队，保证下一层的顺序也是从左到右
                if node.left:
                    q.append(node.left)
                if node.right:
                    q.append(node.right)

            res.append(level)    # 本层收工，整层追加

        return res
```

两个细节值得单独说：`level_size = len(q)` 必须在 `for` 循环**之前**取，如果写成 `for _ in range(len(q))` 虽然 Python 会在进入循环时求值一次、结果一样，但语义上容易让人误以为每轮重算，教学时建议显式提出变量；`if node.left` 而不是 `if node.left is not None`，因为节点对象恒为真，但空节点是 `None`，两种写法等价，前者更简洁。

## 6. 复杂度

**时间 O(n)**，n 是节点数。每个节点入队一次、出队一次，入队出队都是 O(1)，所以总操作数是 2n 量级。`level.append` 和 `res.append` 也都是 O(1) 摊还。这里没有 log n 的项，因为 BFS 不涉及「对半分」或「树高」相关的操作——树高只影响队列的最大长度（空间），不影响时间。

**空间 O(w)**，w 是树的最大宽度（某一层最多的节点数）。队列里最多同时存一层多的节点，最坏情况是满二叉树最后一层，w ≈ n/2，所以最坏 O(n)。另外 `res` 本身要存 n 个值，也是 O(n)。如果只算「辅助空间」不算输出，就是 O(w)；算上输出就是 O(n)。面试时把这两个口径都说清楚，比笼统说 O(n) 更显功底。

对比一下：DFS 递归版空间是 O(h)（h 为树高），链状树 h=n 时反而更差，而且有递归深度风险——这也是本题选 BFS 而非 DFS 的一个实际理由。

## 7. 边界与反例（至少 4 条）

1. **输入 `root = []`（空树）** → 期望 `[]` → 容易错在没判空，直接 `deque([None])` 然后 `popleft().val` 抛 `AttributeError`。代码里第一行 `if root is None: return []` 就是防这个。

2. **输入 `root = [1]`（单节点）** → 期望 `[[1]]` → 容易错在把结果写成 `[1]` 而不是 `[[1]]`，忘了「每层是一个列表」这层嵌套。这是最常见的格式错误。

3. **输入 `root = [1,2,null,3]`（左偏链）** → 期望 `[[1],[2],[3]]` → 容易错在用 DFS 前序收集后直接输出，得到 `[1,2,3]` 一维结果，或者按 depth 分组时把 depth 算错。这条专门用来暴露「DFS 顺序 ≠ 层序」的陷阱。

4. **输入 `root = [1,2,3,4,5,null,6]`（层内节点数不均）** → 期望 `[[1],[2,3],[4,5,6]]` → 容易错在 `for` 循环里用 `while q` 而不是固定次数，导致把下一层节点也混进本层，输出变成 `[[1],[2,3,4,5,6]]`。这是「忘记锁 level_size」的典型症状。

5. **输入含负值 `root = [-1,-2,-3]`** → 期望 `[[-1],[-2,-3]]` → 容易错在判空时写 `if not root` 之外还写了 `if not node.val` 之类的值判断，把 `val=0` 的节点误当空节点跳过。节点是否存在只看对象是否为 `None`，跟 `val` 无关。

## 8. 面试追问与变体（3 条）

1. **追问：改成「从下往上」层序（第 102 题变体，LeetCode 107）怎么办？**
   思路：正常 BFS 得到 `res` 后 `return res[::-1]`，或者每层 `res.insert(0, level)`（后者 O(n²)，不推荐，面试时主动说清取舍）。

2. **追问：改成「之字形」层序（LeetCode 103），奇数层从左到右、偶数层从右到左？**
   思路：BFS 框架不变，加一个层号 `depth`，偶数层收集完后 `level.reverse()` 再 append，或者用双端队列按方向 `appendleft`/`append`。

3. **追问：不用队列，用 DFS 递归怎么写出层序？**
   思路：递归函数带 `depth` 参数，若 `depth == len(res)` 就 `res.append([])`，然后 `res[depth].append(node.val)`，先递归左再递归右即可保证层内从左到右。这正好呼应第 2 节的暴力版，面试官常用来考察你是否理解两种遍历的等价性。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 107 二叉树的层序遍历 II**：共同点是 BFS 按层切批的骨架完全一样，只差最后结果要不要反转。

2. **LeetCode 199 二叉树的右视图**：共同点是同样按层 BFS，只是每层只取最后一个节点（`level[-1]`），考察你是否能复用「锁 level_size」这个技巧。

3. **LeetCode 111 二叉树的最小深度**：共同点是 BFS 逐层推进，第一次遇到叶子节点时当前层号就是最小深度，考察「BFS 天然适合求最短距离」这个直觉。
