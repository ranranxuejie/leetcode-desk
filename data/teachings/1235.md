## 1. 一句话本质

在「区间互不重叠」的约束下，从 n 个带权区间里挑一个子集，使权值和最大。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子集，对每个子集检查区间是否两两不重叠，取合法子集里权值最大的。子集数 2^n，n 最大 5×10^4，直接爆炸。就算退一步想「按某种顺序贪心」，也会立刻发现贪心不成立——示例 1 里单看 profit 最大的是第 4 份（70），但选它就不能选第 1 份（50），而 50+70=120 才是答案；如果贪心按「结束早优先」选，会先选第 1 份，然后第 2 份（2-4）和第 1 份重叠被跳过……这条路走不通。

**关键观察**：一旦把所有工作**按结束时间排好序**，问题就有了「线性扫描 + 决策」的结构。考虑排序后的第 i 份工作，它只有两种命运：不选它，答案等于「前 i-1 份的最优解」；选它，答案等于「它的报酬 + 在它开始之前就结束的那些工作的最优解」。后者是一个**只依赖 i 之前**的子问题——这就是 DP 的状态转移雏形。

为什么「按结束时间排序」是关键？因为「能不能接上」这个判断，只取决于前一份工作的**结束时间**是否 ≤ 当前工作的**开始时间**。把结束时间排成单调的，前面那些「能接上」的工作就构成一个**前缀**，于是「找最后一个能接上的工作」变成一个二分查找，而不是每次线性扫描。

## 3. 从暴力到最优

**第一步：把三维信息压成一维顺序。** 原始输入是三个平行数组，工作之间没有顺序。先打包成 `(start, end, profit)` 三元组，按 `end` 升序排序。排序后，任何「合法的选择序列」在时间上一定是这个顺序的子序列——因为后选的工作开始时间必须 ≥ 前一个的结束时间，而结束时间又单调递增。

**第二步：定义 DP。** 令 `dp[i]` = 只考虑排序后的前 i 份工作（下标 0..i-1）能拿到的最大报酬。`dp[0] = 0`。

**第三步：转移。** 对第 i 份工作（0-indexed，对应 `dp[i+1]`）：

- 不选：`dp[i+1] = dp[i]`
- 选：需要找到最大的 j，使得第 j 份工作的 `end ≤ 第 i 份的 start`。那么 `dp[i+1] = dp[j+1] + profit[i]`（`dp[j+1]` 表示前 j+1 份工作的最优解，即下标 0..j）。

两者取 max。

**第四步：消掉「找 j」的线性扫描。** 因为 `end` 已排序，`end` 数组单调不减，用 `bisect_right(ends, start_i)` 得到第一个 `end > start_i` 的位置 `k`，则 `j+1 = k`，即 `dp[k]` 就是「所有在 start_i 之前结束的工作的最优解」。O(log n)。

**小例子走一遍**（示例 1）：

```
原始: start=[1,2,3,3], end=[3,4,5,6], profit=[50,10,40,70]
排序后（按 end）: (1,3,50), (2,4,10), (3,5,40), (3,6,70)
ends = [3,4,5,6]
```

- i=0: start=1, `bisect_right([3,4,5,6], 1)=0` → 选它得 `dp[0]+50=50`；不选 `dp[0]=0`。`dp[1]=50`
- i=1: start=2, `bisect_right(...,2)=0` → 选它得 `0+10=10`；不选 `dp[1]=50`。`dp[2]=50`
- i=2: start=3, `bisect_right(...,3)=1` → 选它得 `dp[1]+40=90`；不选 `dp[2]=50`。`dp[3]=90`
- i=3: start=3, `bisect_right(...,3)=1` → 选它得 `dp[1]+70=120`；不选 `dp[3]=90`。`dp[4]=120`

答案 120，和题面一致。注意 i=3 时 `bisect_right` 返回 1 而不是 0，因为 `ends[0]=3 ≤ start=3`——题面明确说「在时间 X 结束可以立刻进行时间 X 开始的工作」，所以用 `bisect_right`（找第一个 **严格大于** start 的位置）而不是 `bisect_left`。这是本题最容易写错的一个字符。

## 4. 正确性：为什么不会漏、不会重

**不变量**：处理完前 i 份工作后，`dp[i]` 等于「从排序后前 i 份工作中选出一个两两不重叠子集」的最大报酬。

**归纳**：考虑前 i+1 份工作（第 i 份是最后一份）。任何合法子集要么不含第 i 份，要么含。不含时，它也是前 i 份的合法子集，上界是 `dp[i]`，且 `dp[i]` 可达。含第 i 份时，子集里其余工作必须全部在第 i 份开始前结束；由于按 end 排序，这些工作恰好是下标 0..k-1（k 由二分确定）的一个子集，其最大报酬是 `dp[k]`，加上 `profit[i]` 可达。两种情形取 max 覆盖了所有合法子集，且没有重复计数（因为「含/不含第 i 份」是互斥划分）。

**为什么不会漏**：任何合法子集按 end 排序后，最后一个元素若是第 i 份，则前面所有元素都在 0..k-1 内，被 `dp[k]` 覆盖；若不是第 i 份，被 `dp[i]` 覆盖。

**为什么不会重**：DP 是按「最后一个被选工作的下标」做划分的，每个子集有唯一的最后元素，只被算一次。

## 5. 完整代码（Python）

```python
from bisect import bisect_right

class Solution:
    def jobScheduling(self, startTime, endTime, profit):
        n = len(startTime)
        # 打包并按结束时间升序排序，让「能接上」的工作构成前缀
        jobs = sorted(zip(startTime, endTime, profit), key=lambda x: x[1])
        ends = [e for _, e, _ in jobs]

        # dp[i] = 前 i 份工作（下标 0..i-1）能拿到的最大报酬
        dp = [0] * (n + 1)

        for i in range(n):
            s, e, p = jobs[i]
            # 找第一个 end > s 的位置 k，则下标 0..k-1 的工作都能接在第 i 份之前
            # 用 bisect_right 而非 bisect_left：end == s 也算能接上
            k = bisect_right(ends, s)
            # 选第 i 份：dp[k] + p；不选：dp[i]
            dp[i + 1] = max(dp[i], dp[k] + p)

        return dp[n]
```

关键点注释已在代码中。注意 `dp` 长度是 `n+1`，`dp[i+1]` 对应「前 i+1 份」，`dp[k]` 对应「前 k 份」，下标对齐不要错位。

## 6. 复杂度

- **排序**：O(n log n)，n 来自工作数量，log n 来自比较排序。
- **二分**：每份工作一次 `bisect_right`，O(log n)，共 O(n log n)。
- **DP 循环**：O(n)。
- **总时间**：O(n log n)。瓶颈在排序和 n 次二分。
- **空间**：`jobs`、`ends`、`dp` 各 O(n)，总 O(n)。没有递归栈。

## 7. 边界与反例（至少 4 条）

1. **`startTime=[1,1,1], endTime=[2,3,4], profit=[5,6,4]`** → 期望 6。三份工作开始时间相同，两两重叠，只能选一份。容易错在：以为「开始时间相同可以都选」，或者二分时把 `end==start` 判成重叠。
2. **`startTime=[1,2,3,4,6], endTime=[3,5,10,6,9], profit=[20,20,100,70,60]`** → 期望 150。这是示例 2，容易错在：只看 profit 最大（100）而忽略它和 70、60 的组合。DP 必须比较「选/不选」两条路。
3. **`startTime=[1,2], endTime=[2,3], profit=[10,20]`** → 期望 30。`end[0]=2 == start[1]=2`，题面允许接上。若用 `bisect_left` 会得到 k=0，算出 20 而不是 30。这是 `bisect_right` 与 `bisect_left` 的分水岭。
4. **`startTime=[1], endTime=[2], profit=[5]`** → 期望 5。n=1 的退化情形，`dp[1] = max(dp[0], dp[0]+5) = 5`，验证下标对齐。
5. **所有工作两两重叠**（如 `start=[1,1,1], end=[2,2,2], profit=[3,4,5]`）→ 期望 5。DP 会正确退化为「取最大单份」，不会把重叠的加在一起。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求输出具体选了哪些工作，而不只是最大报酬？** 思路：在 DP 里额外记录「选/不选」的决策来源（`dp[i+1]` 是从 `dp[i]` 还是 `dp[k]+p` 转移来的），最后从 `dp[n]` 回溯。
2. **追问：如果工作可以「部分重叠」——即允许同时做 k 份重叠的工作（k 台机器调度）？** 思路：这是加权区间调度的多机版本，DP 状态要扩展成「前 i 份工作、用了 j 台机器」的二维，或者用最小费用流/贪心+堆，复杂度上升。
3. **追问：如果 profit 可以为负，还选不选？** 思路：转移里「不选」分支天然处理了负值——`max(dp[i], dp[k]+p)` 会自动跳过负收益工作，答案至少是 0（空集）。但若题目要求「必须选至少一份」，需要额外处理。

## 9. 举一反三（2-3 道同类题）

- **LeetCode 435. 无重叠区间**：同样按结束时间排序 + 贪心/DP，区别是本题求最大权值和，435 求最少删除数（等价于最大不重叠个数，权值全为 1）。
- **LeetCode 646. 最长数对链**：区间不重叠的最长链，是本题 profit 全为 1 的退化版，排序 + DP 或贪心。
- **LeetCode 1751. 最多可以参加的会议数目 II**：本题的二维推广（最多参加 k 场），DP 状态多一维「已选场数」，二分逻辑完全复用。
