## 1. 一句话本质

在所有区间中挑出**尽可能多的互不重叠区间**，答案 = 总数 − 这个最大值。

注意题目问的是「移除的最小数量」，但直接求「移除最少」很难下手；把它翻成「保留最多」才是可解的形态。这个翻转是整道题的起点。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子集，检查每个子集是否两两不重叠，取最大的合法子集。子集数 $2^n$，$n=10^5$ 时完全不可行。即使退一步想 DP：按起点排序后，令 `dp[i]` 表示「以第 i 个区间结尾的最大不重叠区间数」，转移要往前找所有 `end <= start_i` 的 j，是 $O(n^2)$，$10^5$ 也过不了。

**关键观察**：区间选择问题里，「结束得越早，给后面留的空间越大」。这句话不是空话——它直接指向一个贪心策略：**按结束时间升序排序，然后从头扫，能选就选**。为什么是结束时间而不是开始时间？因为一个区间对后续的「伤害」只取决于它的右端点：右端点越靠左，后面能塞进去的区间就越多。开始时间早但拖得长的区间（比如 `[1,100]`）反而是最坏的。

这个观察之所以能让你想到下一步，是因为它把「全局最优选择」压缩成了「局部一个比较」：每次只需要问「当前区间的 start 是否 ≥ 上一个选中区间的 end」。一旦问题变成这种形式，排序 + 一次线性扫描的结构就浮出来了。

## 3. 从暴力到最优

**第一步：从子集枚举到 DP。** 按 start 排序，`dp[i]` = 以 i 结尾的最大数量，转移 `dp[i] = 1 + max(dp[j])`，其中 `end_j <= start_i`。瓶颈：找 j 是 $O(n)$，总共 $O(n^2)$。

**第二步：消掉「找 j」的瓶颈。** 如果按 end 排序，那么所有 `end_j <= start_i` 的 j 一定排在前面连续的一段里（因为 end 单调），可以用二分或双指针维护「目前为止最大的 dp 值」。这一步把 $O(n^2)$ 降到 $O(n \log n)$。但还能更简单。

**第三步：贪心直接跳过 DP。** 关键洞察：我们其实不需要「以谁结尾」这个维度。因为按 end 排序后，第一个区间一定可以选（它的 end 最小，选它不会比选任何别的区间差），选完之后问题就递归地变成「在 start ≥ 它的 end 的区间里再选」。于是只需要一个变量 `last_end` 记录上一个选中区间的右端点。

**小例子走一遍**：`intervals = [[1,2],[2,3],[3,4],[1,3]]`

- 按 end 排序：`[[1,2],[2,3],[1,3],[3,4]]`（end 分别为 2,3,3,4；end 相同时顺序不影响结果）
- 初始化 `last_end = -inf`，`kept = 0`
- 区间 `[1,2]`：`start=1 >= last_end=-inf` → 选，`kept=1`，`last_end=2`
- 区间 `[2,3]`：`start=2 >= last_end=2` → 选（注意题面说「只在一点接触不算重叠」，所以用 `>=` 不是 `>`），`kept=2`，`last_end=3`
- 区间 `[1,3]`：`start=1 < last_end=3` → 跳过
- 区间 `[3,4]`：`start=3 >= last_end=3` → 选，`kept=3`，`last_end=4`
- 答案 = `4 - 3 = 1` ✓

对比一下如果按 start 排序会怎样：`[[1,2],[1,3],[2,3],[3,4]]`，先选 `[1,2]` 还好，但如果数据是 `[[1,100],[2,3],[3,4]]`，按 start 排序先选 `[1,100]` 就只保留 1 个，而最优是保留 `[2,3],[3,4]` 两个。这就是「按 end 排序」的必要性。

## 4. 正确性：为什么不会漏、不会重

用**交换论证**（exchange argument）。

设按 end 升序排序后的区间为 $I_1, I_2, \dots, I_n$。贪心选出的集合为 $G$，最优解为 $O$，且设 $O$ 是「与 $G$ 前缀重合最长」的那个最优解。

**不变量**：处理完前 $k$ 个区间后，贪心选出的集合 $G_k$ 与某个最优解 $O$ 的前 $|G_k|$ 个区间完全相同，且 $G_k$ 的最后一个区间的 end 不大于 $O$ 对应位置的 end。

**归纳步**：假设前 $k$ 步成立，现在贪心考虑 $I_{k+1}$。

- 若 $I_{k+1}$ 与 $G_k$ 冲突（`start < last_end`），贪心跳过它。此时 $O$ 也不可能选 $I_{k+1}$ 而不破坏与 $G_k$ 的一致性——因为 $G_k$ 的最后一个区间 end 已经 ≤ $O$ 对应位置的 end，$I_{k+1}$ 连更靠左的 end 都过不去，更过不去 $O$ 的。跳过不损失。
- 若 $I_{k+1}$ 不冲突，贪心选它。如果 $O$ 也选了它，无事。如果 $O$ 没选它，那么 $O$ 在这一步之后要么空着、要么选了某个 $I_m$（$m > k+1$）。由于排序保证 $end_{k+1} \le end_m$，把 $O$ 里的 $I_m$ 换成 $I_{k+1}$ 不会让后面的区间更难选（右端点只会更靠左或相等），所以替换后仍是最优解，且与 $G$ 的前缀重合更长，矛盾于 $O$ 的选择。故贪心选它不劣。

**结论**：贪心保留的区间数 = 最优保留数，答案 = $n - |G|$。这个论证同时说明了「不会漏」（每一步都有最优解与贪心一致）和「不会重」（每个区间只被判断一次）。

## 5. 完整代码（Python）

```python
from typing import List

class Solution:
    def eraseOverlapIntervals(self, intervals: List[List[int]]) -> int:
        if not intervals:
            return 0

        # 按右端点升序排序：右端点越小，给后面留的空间越大
        # 这是整个贪心的核心，排序键必须是 end 而不是 start
        intervals.sort(key=lambda x: x[1])

        kept = 0                 # 已保留的互不重叠区间数
        last_end = float('-inf') # 上一个被保留区间的右端点

        for start, end in intervals:
            # 题面明确：只在一点接触不算重叠，所以用 >=
            if start >= last_end:
                kept += 1
                last_end = end   # 只有真正选中时才更新右端点

        # 移除数 = 总数 - 最多能保留的数
        return len(intervals) - kept
```

## 6. 复杂度

- **时间 $O(n \log n)$**：排序贡献 $O(n \log n)$，这是唯一的非线性项；后面的 for 循环每个区间只做一次常数比较，贡献 $O(n)$。总的是 $O(n \log n + n) = O(n \log n)$。
- **空间 $O(\log n)$**：Python 的 `sort` 是 Timsort，最坏额外空间 $O(n)$，平均/常见情况 $O(\log n)$；除此之外只用了 `kept`、`last_end` 两个变量，$O(1)$。如果面试官追问，可以说「不计排序的栈空间则是 $O(1)$」。

$n$ 来自 `intervals.length`，$\log n$ 来自排序的比较次数下界。

## 7. 边界与反例（至少 4 条）

1. **输入 `[[1,2],[2,3]]` → 期望 `0`**。容易错在把 `start == last_end` 判成重叠（写成 `>`）。题面专门强调「只在一点上接触的区间是不重叠的」，所以必须是 `>=`。
2. **输入 `[[1,2],[1,2],[1,2]]` → 期望 `2`**。容易错在排序后没意识到三个区间两两冲突，贪心只保留第一个，`kept=1`，答案 `3-1=2`。如果误以为「相同区间可以共存」就会答 0。
3. **输入 `[[1,100],[2,3],[3,4]]` → 期望 `1`**。这是「按 start 排序会翻车」的经典反例：按 start 排先选 `[1,100]`，只能保留 1 个，答案 2；按 end 排先选 `[2,3]` 再选 `[3,4]`，保留 2 个，答案 1。容易错在排序键选错。
4. **输入 `[[1,2]]` → 期望 `0`**。单区间无冲突，`kept=1`，答案 0。容易错在初始化 `last_end` 时用了 0 或某个具体数，导致第一个区间被误判为冲突（尤其当区间起点为负数时，题面允许 `start_i` 到 `-5*10^4`）。用 `-inf` 才安全。
5. **输入 `[[-5,-3],[-4,-2],[-3,-1]]` → 期望 `1`**。负坐标下如果 `last_end` 初始化成 0，第一个区间 `start=-5 < 0` 会被跳过，`kept` 少算，答案偏大。这是第 4 条的具体化，值得单独提。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求「移除的区间总长度最小」而不是「数量最小」，还能贪心吗？** 思路：不能直接套本题贪心，因为「保留最多数量」和「保留最大总长度」目标不同；需要转成加权区间调度，用 DP + 二分（按 end 排序后 `dp[i] = max(dp[i-1], dp[p(i)] + weight_i)`），$O(n \log n)$。
2. **追问：如果区间是开区间 `(start, end)`，接触点算重叠吗？** 思路：只需把判断从 `start >= last_end` 改成 `start > last_end`，其余不变；这考察你是否理解 `>=` 的来源是题面的「接触不算重叠」约定。
3. **追问：如果要输出具体移除了哪些区间，而不只是数量？** 思路：贪心扫描时把被跳过的区间收集起来即可；注意「被跳过」的定义是 `start < last_end`，这些正是需要移除的，且数量恰好等于 `n - kept`。
