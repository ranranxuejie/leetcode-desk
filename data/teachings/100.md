## 1. 一句话本质

判断两棵二叉树在**每一个对应位置上**是否同时满足「都存在且值相等」——也就是对两棵树做一次同步的结构+值比对。

## 2. 读完题的第一反应

最朴素的思路：把两棵树各自遍历一遍，序列化成两个列表，再比较两个列表是否相等。

这个思路卡在两处：

- **序列化方式必须携带结构信息**。示例 2 就是陷阱：`p = [1,2]` 和 `q = [1,null,2]`，如果只收集「存在的节点值」，两棵树的节点值序列都是 `[1,2]`，会被误判为相同。所以序列化时必须把 `null` 也写进去，比如前序遍历写成 `[1,2,null]` 和 `[1,null,2]`，这才区分得开。
- **额外空间和额外一趟遍历**。序列化要存两个长度最多 2n 的列表，再逐项比较，本质上是「先摊平再比」，多花了 O(n) 空间却没有任何信息增益。

关键观察是：**「相同」这个判断是逐位置独立的**。根和根比、左子树和左子树比、右子树和右子树比，三个子判断之间互不影响，而且子判断和原问题形式完全一样。这正是递归的定义形态——原问题可以拆成同构的更小问题，且拆分点唯一（就是根）。所以不需要先摊平，直接在遍历过程中同步比较即可，一旦发现不一致立刻返回。

## 3. 从暴力到最优

**暴力版（序列化比较）**，用示例 2 走一遍：

- 对 p 做带 null 的前序遍历：根 1 → 左 2 → 左的左 null → 左的右 null → 右 null，得 `[1,2,null,null,null]`
- 对 q 做同样遍历：根 1 → 左 null → 右 2 → 右的左 null → 右的右 null，得 `[1,null,2,null,null]`
- 逐项比较，第 2 项 `2 != null`，返回 false。

正确，但代价是：两趟完整遍历 + 两个列表 + 一趟比较，时间 3 倍常数，空间 O(n)。

**瓶颈在哪**：序列化把「结构」编码进了列表，但比较列表时我们其实只关心「第一个不相等的位置」。也就是说，序列化产生的绝大部分元素是浪费的——一旦发现差异，后面的都不用看了。

**消掉瓶颈**：把「生成列表」和「比较列表」合并成一步。递归函数 `isSameTree(p, q)` 直接回答「以 p、q 为根的两棵子树是否相同」，内部只做三件事：

1. 两个都为空 → 相同（这是递归的终止条件之一）
2. 只有一个为空 → 不同（结构不一致，立刻返回）
3. 都不为空 → 值必须相等，且左右子树分别相同

用示例 3 走一遍：`p = [1,2,1]`，`q = [1,1,2]`。

- 调用 `isSameTree(1, 1)`：都非空，值 1 == 1 ✓，继续比左右
- 比左：`isSameTree(2, 1)`：都非空，值 2 != 1 → 返回 false
- 上层拿到 false，直接返回 false，**右子树根本没访问**。

这就是「提前剪枝」：暴力版要遍历完两棵树才比较，递归版在第一个差异处就停。最坏情况（两棵树完全相同）仍然访问全部 n 个节点，但最好情况只需 O(1)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义递归函数的不变量：

> `isSameTree(p, q)` 返回 true，当且仅当以 p 为根和以 q 为根的这两棵子树，在结构和每个对应节点的值上都完全相同。

**基础情况**（归纳起点）：

- `p == q == None`：两棵空树，结构相同、无节点可比，返回 true，符合不变量。
- 恰有一个为 None：一棵有节点一棵没有，结构必然不同，返回 false，符合不变量。

**归纳步**：假设对任意高度小于 h 的子树，不变量成立。现在 p、q 高度为 h 且都非空。两棵树相同 ⟺ 根值相同 ∧ 左子树相同 ∧ 右子树相同。代码先检查 `p.val == q.val`，再递归检查左右子树——左右子树高度都小于 h，由归纳假设，两次递归调用的返回值精确对应「左子树相同」「右子树相同」。三个条件用 `and` 连接，恰好等价于原命题。故不变量对高度 h 成立。

**不会漏**：`and` 的短路只发生在已经确定整体为 false 时，此时结论已定，跳过后续检查不影响正确性。

**不会重**：每个节点对 (p 中某节点, q 中对应位置节点) 只在「父节点递归下来」时被访问一次，树结构无环，不存在重复访问。

由数学归纳法，不变量对所有高度的树成立，算法正确。

## 5. 完整代码（Python）

```python
class Solution:
    def isSameTree(self, p, q) -> bool:
        # 基础情况 1：两棵都为空，结构相同，视为相同
        if p is None and q is None:
            return True
        # 基础情况 2：只有一个为空，结构不同，直接判否
        # 注意：这里必须用 is None 判断，不能用 not p，
        # 因为节点值可能是 0，not 0 为 True 会误判
        if p is None or q is None:
            return False
        # 两个都非空：先比值，不等立刻返回
        if p.val != q.val:
            return False
        # 值相等，再递归同步比较左子树和右子树
        # 用 and 连接：左子树一旦不同，右子树无需再比（短路）
        return self.isSameTree(p.left, q.left) and \
               self.isSameTree(p.right, q.right)
```

关键逻辑说明：

- 两个 `if` 的顺序不能反。先判「都为空」，再判「恰有一个为空」，才能覆盖全部空/非空组合。
- `p is None` 而非 `not p`：节点值为 0 时 `not p` 会得到 True（因为节点对象本身不是 None，但这里其实 `not p` 对非 None 对象恒为 False，真正的问题是如果写成 `if not p and not q` 再配 `if not p or not q`，逻辑上没问题；但用 `is None` 语义更明确，避免读者误以为在判断值）。更稳妥的写法就是显式 `is None`。
- 返回值用 `and` 串联，天然实现「发现不同立即停止」。

## 6. 复杂度

设两棵树节点数分别为 m、n，取 N = min(m, n) 为同步比较时能对齐的节点数上界。

**时间**：O(min(m, n))，最坏 O(n)（当两棵树节点数相同且完全相同时，每个节点对访问一次）。每一项的来源：

- 每个节点对做 O(1) 的判空和比值操作，共访问至多 min(m,n) 个节点对，故 O(min(m,n))。
- 不存在 log n 项：这不是二分或平衡树高度相关的算法，递归深度虽与树高有关，但那是空间，不是时间。

**空间**：O(h)，h 为树高，来自递归调用栈。

- 最坏情况：树退化成链，h = n，空间 O(n)。
- 最好/平均情况：平衡树 h = log n，空间 O(log n)。
- 这里没有额外的列表或队列，空间全部由调用栈贡献。

## 7. 边界与反例（至少 4 条）

1. **`p = [], q = []`** → 期望 `true` → 容易错在：把空树当成非法输入直接报错，或忘记写「都为空返回 True」的基础情况导致 `None.val` 崩溃。
2. **`p = [], q = [1]`** → 期望 `false` → 容易错在：只判了「都为空」没判「一个为空」，继续访问 `None.val` 抛异常。
3. **`p = [0], q = [0]`** → 期望 `true` → 容易错在：用 `if not p or not q` 判空时，若把节点值 0 和 None 混淆（某些语言/写法里），会误判。Python 中节点对象非 None 时 `not node` 为 False，其实安全，但写成 `if p.val != q.val` 前必须先确认两者非空，顺序不能乱。
4. **`p = [1,2], q = [1,null,2]`**（示例 2）→ 期望 `false` → 容易错在：只比较节点值集合或中序遍历序列，两者都是 `[1,2]`，会误判为相同。必须同步比较结构。
5. **`p = [1,2,1], q = [1,1,2]`**（示例 3）→ 期望 `false` → 容易错在：只比根和节点总数，忽略左右位置。值相同但位置不同，必须逐位置比。

## 8. 面试追问与变体（3 条）

1. **追问：不用递归，用迭代怎么写？** 思路：用队列做 BFS，每次同时弹出 p、q 的一个节点对，按「都空跳过 / 一个空返回 false / 值不等返回 false / 否则把左右孩子成对入队」处理。时间空间同阶，空间从 O(h) 变成 O(宽度)，最坏 O(n)。
2. **追问：如果允许「忽略某些节点」或「子树可以旋转」，怎么改？** 思路：忽略节点等价于在递归时对特定值直接返回 true；允许旋转则退化为「判断两棵树是否同构」，需要比较左右子树时尝试「左左配右右」和「左右配右左」两种组合，复杂度上升到 O(n log n) 或更高。
3. **追问：如果树非常大、深度可能爆栈怎么办？** 思路：改迭代 BFS/DFS 用显式栈，把递归深度从 O(h) 转移到堆上的显式容器，避免 Python 默认递归上限（约 1000）触发 `RecursionError`。

## 9. 举一反三（2-3 道同类题）

- **101. 对称二叉树**：和本题共同点是「同步比较两棵子树」，只是比较对象变成同一棵树的左右子树，且方向要镜像（左比右、右比左）。
- **572. 另一棵树的子树**：共同点是复用 `isSameTree` 作为子过程，外层再遍历主树每个节点调用它，是「本题 + 一次遍历」的组合。
- **226. 翻转二叉树**：共同点是递归处理左右子树的结构，区别在于本题是「比较」、那题是「交换」，但递归骨架完全一致，可用来巩固「树递归三要素：终止条件、单层逻辑、返回值」。
