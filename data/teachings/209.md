## 1. 一句话本质

在所有「和 ≥ target」的连续区间里，找最短的那个长度。

## 2. 读完题的第一反应

最直接的思路：枚举所有子数组 `[l, r]`，对每个子数组求和，判断是否 ≥ target，记录最短长度。子数组有 O(n²) 个，每个求和 O(n)，总复杂度 O(n³)。即使预处理前缀和把求和降到 O(1)，枚举本身仍是 O(n²)，n = 10⁵ 时是 10¹⁰ 次操作，必然超时。

瓶颈在哪？在于「枚举了太多不可能成为答案的区间」。注意到题面强调 **nums 全是正整数**——这个条件不是装饰。它意味着：固定左端点 l，随着右端点 r 往右扩，区间和**单调不减**。单调性一旦成立，就有两件事可以做：

1. 对每个 l，右端点不需要从 l 开始一个个试，可以二分找「第一个使和 ≥ target 的 r」——这是进阶要求的 O(n log n) 解法。
2. 更关键的是：当 l 右移时，之前找到的 r **不需要回退**。因为 l 右移会让区间和变小，原本满足条件的 r 可能不再满足，需要继续往右扩；但绝不会出现「r 需要往左缩」的情况。这直接引出滑动窗口，O(n)。

所以关键观察就一句：**正数保证了区间和关于右端点单调递增、关于左端点单调递减**。没有这个条件（比如允许负数），滑动窗口的正确性立刻崩塌。

## 3. 从暴力到最优

**暴力 O(n²)**：固定 l，r 从 l 开始累加，一旦和 ≥ target 就更新答案并 break（因为再往右只会更长）。这个 break 已经用上了单调性，但每个 l 都要重新从 l 开始累加，最坏仍是 O(n²)。

**滑动窗口 O(n)**：维护一个窗口 `[left, right]` 和窗口和 `total`。策略是：

- 右指针每次右移一格，把 `nums[right]` 加进 `total`；
- 只要 `total >= target`，就说明当前窗口是一个可行解，用 `right - left + 1` 更新答案；然后**尝试收缩**：把 `nums[left]` 从 `total` 里减掉，`left` 右移一格，再看是否仍满足，循环收缩直到不满足为止。

用示例 1 走一遍：`target = 7, nums = [2,3,1,2,4,3]`，下标 0~5。

| 操作 | left | right | total | ans |
|---|---|---|---|---|
| 加入 nums[0]=2 | 0 | 0 | 2 | ∞ |
| 加入 nums[1]=3 | 0 | 1 | 5 | ∞ |
| 加入 nums[2]=1 | 0 | 2 | 6 | ∞ |
| 加入 nums[3]=2 | 0 | 3 | 8 | 4 |
| 收缩：减 nums[0]=2 | 1 | 3 | 6 | 4 |
| 加入 nums[4]=4 | 1 | 4 | 10 | 4 |
| 收缩：减 nums[1]=3 | 2 | 4 | 7 | 3 |
| 收缩：减 nums[2]=1 | 3 | 4 | 6 | 3 |
| 加入 nums[5]=3 | 3 | 5 | 9 | 3 |
| 收缩：减 nums[3]=2 | 4 | 5 | 7 | 2 |
| 收缩：减 nums[4]=4 | 5 | 5 | 3 | 2 |

最终 ans = 2，对应窗口 `[4,3]`。注意 right 从 0 走到 5 只走了 5 步，left 也只走了 5 步——两个指针各自单调右移，总移动次数 O(n)，这就是瓶颈被消掉的地方：**不再对每个 l 重新扫描，而是复用上一个 l 已经扩到的位置**。

## 4. 正确性：为什么不会漏、不会重

用不变量来论证。定义：在算法执行的任意时刻，`[left, right]` 是当前窗口，`total` 是它的和。

**不变量 1（left 的语义）**：当 `total >= target` 时，我们持续收缩 left，直到 `total < target` 或 `left > right` 为止。因此收缩结束后，`[left, right]` 是「以 right 为右端点、满足和 ≥ target 的最短窗口」——因为再往右移一格 left，和就掉到 target 以下了，不可能更短。

**不变量 2（不漏解）**：考虑任意一个最优解 `[l*, r*]`。当 right 扫描到 r* 时，此时 left 一定 ≤ l*。为什么？反证：若 left > l*，说明 left 曾经从 l* 或更小的位置被右移过，而 left 只在「当前窗口和 ≥ target」时才右移。若 left 越过 l* 时窗口右端 ≤ r*，则窗口 `[l*, 当前right]` 的和 ≥ target 且长度 ≤ r* - l* + 1，这与 `[l*, r*]` 是最优解矛盾（除非等长，那也不影响答案正确）。所以 left 不会越过 l*，`[l*, r*]` 会被完整考察到。

**不变量 3（不重）**：每个 right 只被加入一次，每个 left 只被移除一次，没有区间被重复计算。

三条合起来：所有可行区间中，至少有一个最短的会被窗口在某时刻精确覆盖，且答案只会在满足条件时被更新，不会记录非法区间。所以结果正确。

## 5. 完整代码（Python）

```python
class Solution:
    def minSubArrayLen(self, target: int, nums: list[int]) -> int:
        n = len(nums)
        ans = float('inf')   # 用无穷大表示"还没找到解"
        total = 0            # 当前窗口 [left, right] 的元素和
        left = 0             # 窗口左边界

        for right in range(n):
            total += nums[right]          # 右指针扩张，纳入新元素

            # 只要窗口和达标，就尝试收缩左边界，找以 right 结尾的最短窗口
            while total >= target:
                ans = min(ans, right - left + 1)   # 记录当前可行长度
                total -= nums[left]                # 左边界右移，移出元素
                left += 1

        # 若 ans 从未被更新，说明不存在满足条件的子数组
        return 0 if ans == float('inf') else ans
```

关键点：`while` 而不是 `if`——因为收缩一次后可能仍然达标，要继续收缩直到不达标，这样才能保证拿到「以 right 结尾的最短窗口」。`ans` 用 `float('inf')` 初始化，最后统一判断，避免用 `n+1` 之类的哨兵值时和真实长度混淆。

## 6. 复杂度

**时间 O(n)**：外层 `for` 循环执行 n 次，贡献 n。内层 `while` 循环看起来嵌套，但 `left` 指针在整个过程中**只增不减**，最多从 0 走到 n，所以 `while` 体总共执行不超过 n 次。两个指针各自单调移动，总操作数 2n，即 O(n)。这里没有 log n——log n 只出现在进阶的二分做法里：对每个左端点 l，在前缀和数组上二分找第一个 ≥ `prefix[l] + target` 的位置，n 次二分，每次 O(log n)，合计 O(n log n)。

**空间 O(1)**：只用了 `ans`、`total`、`left`、`right` 几个变量，与 n 无关。二分做法需要 O(n) 的前缀和数组。

## 7. 边界与反例（至少 4 条）

1. **输入** `target = 11, nums = [1,1,1,1,1,1,1,1]` → **期望 0** → 容易错在：总和 8 < 11，循环里 `while` 一次都不会进，`ans` 保持 `inf`，必须显式返回 0，不能直接返回 `ans`。
2. **输入** `target = 4, nums = [1,4,4]` → **期望 1** → 容易错在：`right=1` 时 `total=5 ≥ 4`，`while` 第一次收缩记录长度 2，减掉 `nums[0]=1` 后 `total=4` 仍 ≥ 4，必须继续收缩记录长度 1。若写成 `if` 就漏掉答案 1。
3. **输入** `target = 1, nums = [1]` → **期望 1** → 容易错在：单元素数组，`right=0` 时 `total=1 ≥ 1`，收缩后 `left=1 > right`，循环条件要能正确处理 `left` 越过 `right` 的情况（`while total >= target` 在 `total` 变 0 后自然退出，不会越界，因为减的是 `nums[left]` 且 `left ≤ right` 时才可能达标）。
4. **输入** `target = 100, nums = [1,2,3]` → **期望 0** → 容易错在：所有元素和都远小于 target，返回 0 的分支必须存在。
5. **输入** `target = 7, nums = [1,1,1,1,1,1,1]` → **期望 7** → 容易错在：整个数组恰好达标，窗口会一路扩到末尾才第一次满足，答案等于 n，验证 `right - left + 1` 在 `left=0` 时算得对。

## 8. 面试追问与变体（3 条）

1. **追问：如果 nums 里允许负数，滑动窗口还成立吗？** 思路：不成立。负数和会破坏「右扩单调增、左缩单调减」，窗口收缩后和可能反而变大，需要换思路（如前缀和 + 单调队列 / 哈希，视具体变体而定）。
2. **追问：改成「和恰好等于 target」的最短子数组？** 思路：正数前提下前缀和严格递增，可用哈希表存「前缀和 → 最早下标」，对每个位置查 `prefix - target` 是否存在，O(n)；这其实是「和为 K 的子数组」的变体。
3. **追问：要求 O(n log n) 且不许用滑动窗口，怎么做？** 思路：构造前缀和数组 `prefix`（严格递增），对每个左端点 l，二分查找最小的 r 使 `prefix[r+1] - prefix[l] >= target`，取所有候选长度的最小值。

## 9. 举一反三（2-3 道同类题）

- **3. 无重复字符的最长子串**：同样是滑动窗口，区别是「窗口合法性」由字符是否重复决定，用哈希集合维护窗口内字符，右扩左缩的骨架完全一致。
- **76. 最小覆盖子串**：滑动窗口求「最短」，但合法性判断变成「窗口内字符频次覆盖目标串」，需要计数器 + 一个 `valid` 变量记录已满足的字符种类数。
- **713. 乘积小于 K 的子数组**：把「和」换成「乘积」，正数保证乘积关于右端点单调，窗口收缩逻辑同构，但求的是「计数」而非「最短长度」。
