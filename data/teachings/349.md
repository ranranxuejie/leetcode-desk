## 1. 一句话本质

求两个集合的公共元素，**去重**后返回——注意是"集合交"，不是"多重集交"（不是取 min 出现次数）。

## 2. 读完题的第一反应

**朴素解法**：对 nums1 里每个元素 x，去 nums2 里从头扫一遍看有没有 x。复杂度 O(m·n)，m、n 各 1000 时是 10^6，能过，但这是"能过"不是"对"。

瓶颈在哪？**"nums2 里有没有 x"这个查询是 O(n) 的**。我们反复问同一个问题（nums1 里每个元素都问一次），却每次都重新扫一遍 nums2，这是纯粹的浪费。

**关键观察**：题目要求输出**唯一**元素。这句话是题眼——它意味着"元素在 nums1 里出现 2 次还是 5 次"根本不重要，我们只关心"在不在"。一旦把数组看成**集合**，"有没有"这个问题就可以用哈希表 O(1) 回答，或者用排序 + 双指针 O(m log m + n log n) 回答。

另一个观察来自提示：`0 <= nums1[i], nums2[i] <= 1000`。值域只有 1001 个，这暗示还可以用**布尔数组**当哈希表，连哈希函数都省了。

## 3. 从暴力到最优

### 第 0 步：暴力

```python
res = []
for x in nums1:
    for y in nums2:
        if x == y and x not in res:   # 还要去重
            res.append(x)
```

复杂度 O(m·n)，且 `x not in res` 又是一层线性扫描。**瓶颈：内层查找 O(n)，去重查找 O(k)。**

### 第 1 步：哈希集合消掉内层扫描

把 nums2 塞进 set，查询变 O(1)：

```python
set2 = set(nums2)
res = []
for x in nums1:
    if x in set2 and x not in res:   # 第二个条件还在
        res.append(x)
```

现在瓶颈转移到 `x not in res`。而且注意：nums1 里若有重复的 2，我们会重复判断、重复跳过，白做功。

### 第 2 步：把 nums1 也去重

既然结果要求唯一，nums1 的重复元素对答案毫无贡献。直接 `set(nums1)` 迭代：

```python
set2 = set(nums2)
res = []
for x in set(nums1):
    if x in set2:
        res.append(x)
```

到这里已经是 O(m + n)。**这就是最优解**，因为读入两个数组本身就要 O(m + n)，不可能更快。

### 具体走一遍

`nums1 = [4,9,5]`, `nums2 = [9,4,9,8,4]`

| 步骤 | 中间变量 |
|---|---|
| `set2 = set(nums2)` | `{9, 4, 8}` |
| 迭代 `set(nums1) = {4, 9, 5}` | — |
| x = 4 | 4 ∈ set2 → res = [4] |
| x = 9 | 9 ∈ set2 → res = [4, 9] |
| x = 5 | 5 ∉ set2 → 跳过 |
| 返回 | `[4, 9]` |

对照示例 2 输出 `[9,4]`，题目明说顺序无所谓，通过。

### 另一条路：排序 + 双指针

如果面试官说"不许用额外空间"，就排序后双指针：

```python
nums1.sort(); nums2.sort()
i = j = 0; res = []
while i < len(nums1) and j < len(nums2):
    if nums1[i] < nums2[j]: i += 1
    elif nums1[i] > nums2[j]: j += 1
    else:
        if not res or res[-1] != nums1[i]:   # 靠排序天然去重
            res.append(nums1[i])
        i += 1; j += 1
```

`[4,9,5]` 排序成 `[4,5,9]`，`[9,4,9,8,4]` 排序成 `[4,4,8,9,9]`。i 指 4、j 指 4，相等，收 4；i 指 5、j 指 4，5>4 所以 j 前进到 8；5<8 所以 i 前进到 9；9>8 所以 j 前进到 9；相等，收 9。结果 `[4,9]`。**去重靠"排序后相同元素相邻"这个性质**，用 `res[-1]` 比较即可，不需要额外 set。

## 4. 正确性：为什么不会漏、不会重

**不漏**（哈希法）：设 x 同时出现在 nums1 和 nums2 中。因为 `set(nums1)` 包含 nums1 的所有不同值，迭代必然访问到 x；此时 `set2` 包含 nums2 的所有不同值，故 `x in set2` 为真，x 被加入 res。所以任何公共元素都不会被漏掉。

**不重**：迭代对象是 `set(nums1)`，一个集合的迭代序列中每个值只出现一次，因此 res 中不可能出现重复值。这是"输出唯一"要求的直接保证。

**双指针法的不变量**：循环每轮开始时，`nums1[0..i-1]` 和 `nums2[0..j-1]` 中所有公共元素都已被正确收集，且 `res` 无重复。三种分支分别对应：`nums1[i] < nums2[j]` 时，nums1[i] 不可能等于 nums2 中任何 ≥ nums2[j] 的元素（因为都更大），也不可能等于已跳过的更小元素（那些已确认不匹配），故 i 可安全前进；对称地 j 前进；相等时收下并同时前进，且因为两数组有序，相同值必然连续出现，用 `res[-1]` 比较即可跳过后续重复。归纳可得循环结束时无遗漏。

## 5. 完整代码（Python）

```python
class Solution:
    def intersection(self, nums1: list[int], nums2: list[int]) -> list[int]:
        # 把较短的数组建集合，迭代较长的数组：
        # 这样迭代次数取 min(m, n)，常数更小（虽然渐进复杂度不变）
        if len(nums1) > len(nums2):
            nums1, nums2 = nums2, nums1

        set2 = set(nums2)          # O(n) 建表，之后查询 O(1)
        res = []
        for x in set(nums1):       # set(nums1) 自动去重，保证结果唯一
            if x in set2:          # O(1) 成员查询
                res.append(x)
        return res
```

如果面试要求 O(1) 额外空间（不计返回值和排序开销），换成双指针版本：

```python
class Solution:
    def intersection(self, nums1: list[int], nums2: list[int]) -> list[int]:
        nums1.sort()
        nums2.sort()
        i = j = 0
        res = []
        while i < len(nums1) and j < len(nums2):
            if nums1[i] < nums2[j]:
                i += 1
            elif nums1[i] > nums2[j]:
                j += 1
            else:
                # 排序后相同值相邻，用 res[-1] 判重即可，无需额外 set
                if not res or res[-1] != nums1[i]:
                    res.append(nums1[i])
                i += 1
                j += 1
        return res
```

## 6. 复杂度

**哈希法**：时间 O(m + n)。`set(nums2)` 遍历 nums2 一次，贡献 O(n)；`set(nums1)` 遍历 nums1 一次，贡献 O(m)；循环迭代 min(m, n) 次，每次 O(1)。空间 O(m + n)，两个集合各存一份去重后的元素，最坏（全不重复）各占 m、n。

**双指针法**：时间 O(m log m + n log n)。两个 `sort` 分别贡献 m log m 和 n log n（Python 的 Timsort 最坏如此）；双指针扫描是 O(m + n)，被排序项支配。空间 O(1)（不计排序内部栈和返回值；Python 的 sort 实际是 O(n) 辅助空间，严格说不是原地，面试时若被追问要承认这点）。

**为什么哈希法更快却不一定更优**：哈希法时间更短，但用了额外空间；双指针省空间但慢一个 log。这是典型的时空权衡，面试时主动说出这一点是加分项。

## 7. 边界与反例（至少 4 条）

1. **`nums1 = [1,2,2,1], nums2 = [2,2]` → `[2]`**
   容易错：忘记去重，返回 `[2, 2]`。哈希法靠 `set(nums1)` 天然避免；双指针法靠 `res[-1]` 判重避免。

2. **`nums1 = [1,2], nums2 = [3,4]` → `[]`**
   容易错：返回 `None` 或忘记处理空结果。代码里 `res` 初始化为空列表，直接返回即可，不要写 `return res or None`。

3. **`nums1 = [1], nums2 = [1]` → `[1]`**
   容易错：双指针版本里 `res[-1]` 在 res 为空时越界。必须写 `if not res or res[-1] != ...`，短路求值保证安全。

4. **`nums1 = [0,0,0], nums2 = [0]` → `[0]`**
   容易错：值域含 0，若用"布尔数组 + 判断非零"的写法会漏掉 0。用 set 或正确初始化的布尔数组（`[False]*1001`）都没问题，但别用 `if flag[x]` 之外的花招。

5. **`nums1 = [4,9,5], nums2 = [9,4,9,8,4]` → `[4,9]` 或 `[9,4]`**
   容易错：以为必须按某种顺序输出。题目明说"不考虑顺序"，别自作主张排序，也别因为顺序不同就以为答案错。

## 8. 面试追问与变体（3 条）

**追问 1：如果要求返回多重集交集（每个元素出现 min(次数) 次），怎么改？**
思路：用 `collections.Counter` 统计两数组频次，对每个公共 key 取 `min(c1[k], c2[k])` 次加入结果。哈希法从"在不在"升级为"出现几次"。

**追问 2：如果 nums2 是超大的、存在磁盘上只能顺序读一次，nums1 很小能放内存，怎么办？**
思路：把 nums1 建成 set 放内存，顺序流式扫描 nums2，命中就收集并（可选）从 set 中删除以去重。这就是"小表建哈希、大表流式扫"的经典模式，也是数据库 hash join 的思路。

**追问 3：如果两个数组都有序，能不能做到 O(m + n) 且 O(1) 空间？**
思路：能，就是双指针，但此时不需要排序开销，总时间就是 O(m + n)。这解释了为什么"已排序"是个强前提——它把 log 项直接消掉了。
