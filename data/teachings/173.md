## 1. 一句话本质

把一棵 BST 的**中序遍历序列**，做成一个「按需吐值」的流式接口：每次 `next()` 只推进一格，而不是一次性把整棵树拍平成数组。

## 2. 读完题的第一反应

**朴素解法**：构造函数里做一次完整中序遍历，把结果存进数组 `self.arr`，再维护一个下标 `self.i`。`next()` 返回 `arr[i++]`，`hasNext()` 返回 `i < len(arr)`。

它卡在哪？时间上其实没问题（构造 O(n)，每次调用 O(1)），但**空间是 O(n)**——题目进阶明确要求 O(h)。对于一条 10^5 个节点的链状 BST，你要额外开一个 10^5 的数组，而树高 h 可能也是 10^5，但如果是平衡树，h 只有 log n，O(h) 就非常省。所以瓶颈是**空间**，不是时间。

**关键观察**：中序遍历的递归写法是「一路向左压到底，弹出栈顶，再转向右子树」。这个「栈」本身就是中序遍历的**暂停状态**——它恰好记录了「我现在走到哪了」。也就是说，我不需要把整条序列算完，我只需要把**递归的调用栈保存下来**，每次 `next()` 相当于「恢复执行一步」。

为什么这个观察能直接落地？因为递归转迭代的标准手法就是显式栈，而这道题要的正是「可暂停的迭代」。栈里存的是「还没访问、但左子树已经处理完」的节点，天然就是「下一个该输出的候选」。

## 3. 从暴力到最优

**第一步：暴力（数组）**

以示例树为例：

```
        7
       / \
      3   15
         /  \
        9    20
```

中序遍历得 `[3, 7, 9, 15, 20]`，存进数组。`next()` 依次返回。空间 O(n)=5。

**第二步：观察瓶颈在哪**

数组里存了 5 个数，但任意时刻「我接下来要输出谁」其实只依赖一条路径。比如输出完 3 之后，下一个是 7——这个信息藏在「7 的左子树已处理完」这个状态里，而不是藏在数组的某个下标里。

**第三步：用栈模拟递归**

初始化：从 root 出发一路向左压栈。

- 压 7 → 压 3 → 3 无左孩子，停。栈 = `[7, 3]`（栈底在左）。
- `next()`：弹出栈顶 3，返回 3。然后转向 3 的右子树（空），什么都不压。
- `next()`：弹出栈顶 7，返回 7。转向 7 的右子树 15，一路向左：压 15 → 压 9，停。栈 = `[15, 9]`。
- `next()`：弹出 9，返回 9。9 无右子树。
- `next()`：弹出 15，返回 15。转向 15 的右子树 20，压 20。栈 = `[20]`。
- `next()`：弹出 20，返回 20。栈空。
- `hasNext()`：栈空 → false。

对比一下中间变量：暴力法在构造时就把 `[3,7,9,15,20]` 全算出来了；栈法在任意时刻栈里最多只有 h 个元素（这棵树 h=3，栈最多 2 个）。**瓶颈被消掉的方式**：把「预先算完整条序列」换成「只保存当前这条向左路径」，因为中序遍历的下一个元素永远可以从这条路径上「弹」出来。

**第四步：均摊 O(1) 怎么来的**

每个节点在整个生命周期里**恰好被压栈一次、弹栈一次**。总共 n 个节点，n 次 `next()` 调用（每次弹一个），总压栈次数也是 n。所以 n 次 `next()` 的总代价是 O(n)，均摊到每次就是 O(1)。注意单次 `next()` 可能压很多个（比如从根一路向左压 h 个），但那是「预支」了后面 h 次调用的工作量。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证。

**不变量**：在任意时刻（构造函数结束后、以及每次 `next()` 返回后），栈中从栈顶到栈底，恰好是「中序遍历中尚未输出的节点里，按输出顺序排列的那些**左子树已处理完**的节点」；并且栈顶就是下一个该输出的元素。

分三段验证：

1. **初始化**：从 root 一路向左压栈。这条路径上的节点，其左子树要么为空、要么已被这条路径覆盖，所以它们都满足「左子树已处理完」，且按中序顺序（最左的在栈顶）排列。不变量成立。

2. **`next()` 弹出栈顶 x 并返回**：由不变量，x 是下一个该输出的。弹出后，x 的右子树还没处理。于是对 x 的右孩子做「一路向左压栈」——这恰好把「x 的右子树的中序前缀」补进栈，且这些新节点的左子树都已处理完。不变量恢复。

3. **`hasNext()`**：栈非空 ⟺ 还有未输出节点。因为中序遍历会输出所有节点，而每个节点在被输出前必然先进入栈（要么在初始化路径上，要么作为某个已弹出节点的右子树路径）。栈空时，所有节点都已输出，没有遗漏。

**不会重**：每个节点只在「一路向左压栈」时入栈一次（入栈后到弹出前不会再次入栈，因为入栈只发生在它的某个祖先被弹出后转向右子树时，而一个节点只有一个父节点）。弹出即输出，输出后不再入栈。

**不会漏**：由不变量，栈顶永远是「下一个」，且只要还有节点没输出，栈就非空（归纳：若还有未输出节点，取其中中序最靠前的那个，它的左子树已全部输出，故它必在栈中）。

## 5. 完整代码（Python）

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class BSTIterator:
    def __init__(self, root: TreeNode):
        # 显式栈，模拟中序遍历的递归调用栈
        self.stack = []
        self._push_left(root)   # 初始化：一路向左压到底

    def _push_left(self, node):
        # 把 node 及其所有左后代压栈，栈顶是最左（最小）的节点
        while node:
            self.stack.append(node)
            node = node.left

    def next(self) -> int:
        # 栈顶就是下一个该输出的节点
        node = self.stack.pop()
        # 转向右子树，并把右子树的左链压栈
        self._push_left(node.right)
        return node.val

    def hasNext(self) -> bool:
        return len(self.stack) > 0


def solve(inputs, inputs2):
    """
    按力扣的「操作序列 + 参数序列」格式驱动 BSTIterator。
    inputs:  操作名列表，如 ["BSTIterator","next",...]
    inputs2: 对应参数列表，如 [[[7,3,15,null,null,9,20]], [], ...]
    返回:    与操作一一对应的输出列表（构造返回 None）
    """
    def build(arr):
        # 层序数组建树，null 用 None 表示
        if not arr or arr[0] is None:
            return None
        root = TreeNode(arr[0])
        q = [root]
        i = 1
        while q and i < len(arr):
            cur = q.pop(0)
            if i < len(arr) and arr[i] is not None:
                cur.left = TreeNode(arr[i])
                q.append(cur.left)
            i += 1
            if i < len(arr) and arr[i] is not None:
                cur.right = TreeNode(arr[i])
                q.append(cur.right)
            i += 1
        return root

    out = []
    it = None
    for op, args in zip(inputs, inputs2):
        if op == "BSTIterator":
            it = BSTIterator(build(args[0]))
            out.append(None)
        elif op == "next":
            out.append(it.next())
        elif op == "hasNext":
            out.append(it.hasNext())
    return out
```

## 6. 复杂度

**时间**：
- 构造函数：O(h)。`_push_left` 沿左链走 h 步，h 是树高。
- `next()`：单次最坏 O(h)（弹出后可能压入一条长左链），但**均摊 O(1)**。理由：每个节点一生只入栈一次、出栈一次，n 次 `next()` 总共 O(n) 次入栈+出栈操作，均摊到每次是 O(1)。这里的 n 是节点总数，h 是树高。
- `hasNext()`：O(1)，只看栈长度。

**空间**：O(h)。栈里最多同时存 h 个节点——恰好是「从根到当前最左节点」这条路径，长度不超过树高。没有额外数组，所以不是 O(n)。平衡树 h=log n，链状树 h=n（此时 O(h)=O(n)，但这是树本身的高度决定的，无法更省）。

## 7. 边界与反例（至少 4 条）

1. **单节点树 `[5]`** → `next()` 返回 5，`hasNext()` 返回 false。易错点：构造函数里 `_push_left(root)` 压入 5，`next()` 弹出后转向 `node.right`（None），`_push_left(None)` 不做事，栈空，`hasNext` 正确返回 false。若忘记在 `next()` 里处理右子树，会漏掉后续节点。

2. **只有左链的树 `[3,2,null,1]`** → 中序 `[1,2,3]`。易错点：初始化时一路向左压 `[3,2,1]`，栈顶是 1，正确。若误以为「栈顶是根」会输出 3，顺序全错。

3. **只有右链的树 `[1,null,2,null,3]`** → 中序 `[1,2,3]`。易错点：初始化只压 1（1 无左孩子），`next()` 返回 1 后转向右子树 2，压 2；再 `next()` 返回 2 转向 3，压 3。若在 `next()` 里忘了 `_push_left(node.right)`，第二次 `next()` 时栈空，直接崩。

4. **`hasNext()` 在 `next()` 之前调用** → 应返回 true（只要树非空）。易错点：把 `hasNext` 实现成「栈长度 > 1」或「有右孩子」，会误判。正确实现就是「栈非空」。

5. **连续调用 `next()` 直到栈空后再调 `hasNext()`** → 返回 false。易错点：题目保证 `next()` 调用有效，但 `hasNext()` 可以在任意时刻调，必须能正确返回 false 而不抛异常。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求支持「反向迭代」（从大到小）怎么办？**
   思路：镜像操作——初始化一路向右压栈，`next()` 弹出后转向左子树并一路向右压。本质是把「左-根-右」换成「右-根-左」。

2. **追问：如果树在迭代过程中会被修改（插入/删除节点），还能用吗？**
   思路：栈里存的是节点引用，若被删的节点还在栈里会出问题。需要额外维护「版本号」或改用「按值惰性查找」的方案；简单场景下可要求迭代期间树不变（多数面试只考不变版本）。

3. **追问：不用栈，用 Morris 遍历能做到 O(1) 空间吗？**
   思路：Morris 中序用「线索化」临时改右指针，可以做到 O(1) 额外空间，但会**修改树结构**，且迭代器需要保存「当前节点 + 是否已线索化」的状态，实现复杂。面试里通常作为加分项提一句即可。
