## 1. 一句话本质

从左到右扫描小行星，用一个栈维护「目前还没爆炸、且仍有可能参与后续碰撞」的小行星序列，每来一颗新星就与栈顶反复对撞，直到它爆炸或不再与栈顶相撞为止。

## 2. 读完题的第一反应

**朴素解法**：把数组当成物理模拟，每一轮扫描所有相邻对，凡是「左正右负」的就让它们对撞、删掉较小的（或两个都删），然后重新扫描，直到某一轮没有任何碰撞发生。这个思路直接对应题面规则，但卡在两点：一是每轮都要重新扫全数组，最坏情况下碰撞次数是 O(n)，于是总复杂度 O(n²)；二是「删掉元素后数组下标会移动」，用 Python list 做删除本身又是 O(n)，很容易写出一堆下标 bug。

**关键观察**：碰撞只可能发生在「左边一颗向右（正）、右边一颗向左（负）」的相邻对之间。也就是说，**只有栈顶是正数、新来的是负数时，才可能发生碰撞**。其余情况（栈顶是负、新来是正、两者同号）都不会撞，直接入栈即可。这个观察把「全局反复扫描」压成了「每颗星只和栈顶局部交互」，因为一旦某颗星被确定留在栈里，它左侧的所有星都已经处理完毕、不会再被右侧影响——这正是栈结构适用的信号。

## 3. 从暴力到最优

**暴力**：反复扫描数组，遇到 `a[i] > 0 and a[i+1] < 0` 就处理这一对，处理完重新从头扫。以 `[10, 2, -5]` 为例：

- 第 1 轮：扫到 `2` 和 `-5`，`2 < 5`，删掉 `2`，数组变 `[10, -5]`；
- 第 2 轮：扫到 `10` 和 `-5`，`10 > 5`，删掉 `-5`，数组变 `[10]`；
- 第 3 轮：无碰撞，结束。

正确但慢：每轮 O(n) 扫描 × 最多 O(n) 轮 = O(n²)。

**瓶颈在哪**：一颗新来的负星可能连续撞掉栈里好几颗正星（示例 4 的 `-6` 就连撞 `5`、`3`），而暴力法每撞一次都要「回到数组开头重新扫」，把已经确认无关的左半部分又看了一遍。

**栈的消解**：把「已处理且未爆炸」的星压栈，新星只跟栈顶比。还是 `[10, 2, -5]`：

- 读 `10`：栈空，入栈 → `[10]`
- 读 `2`：栈顶 `10 > 0`、新星 `2 > 0`，同号不撞，入栈 → `[10, 2]`
- 读 `-5`：栈顶 `2 > 0`、新星 `-5 < 0`，撞！`|2| < |-5|`，`2` 爆炸，弹出 → `[10]`；继续看栈顶 `10 > 0` 与新星 `-5`，撞！`10 > 5`，新星 `-5` 爆炸，新星消失，结束 → `[10]`

每颗星最多入栈一次、出栈一次，总操作 O(n)。注意「新星消失」和「栈顶消失」是两种不同结局，代码里要分开处理——这是本题最容易写错的地方。

## 4. 正确性：为什么不会漏、不会重

用**不变量**论证。定义处理完前 i 颗星后，栈中内容为 S_i，声称满足：

> **不变量**：S_i 恰好是「只考虑前 i 颗星、按规则碰撞后」的幸存者序列，且 S_i 中不存在「左正右负」的相邻对（即 S_i 内部已稳定，不会再自发碰撞）。

**基础**：i = 0 时栈空，成立。

**归纳步**：设 S_{i-1} 满足不变量，加入第 i 颗星 x。

- 若 x 与栈顶不构成「左正右负」，则 x 不会与栈内任何星碰撞（栈内更靠左的星与 x 之间隔着栈顶，而栈顶要么同号、要么是负号在左，物理上碰撞只能发生在相邻的「正-负」之间），直接入栈，S_i 仍稳定。
- 若构成碰撞，则栈顶 t 与 x 必有一方或双方爆炸。**关键点**：t 右侧原本没有任何星（它是栈顶），所以 t 只可能与 x 撞，绝不会「跳过 x」去撞别人；x 左侧第一个可能撞的也必然是 t。因此这一对的对撞是**唯一且必须发生**的，处理它不会漏掉任何碰撞，也不会重复处理别的对。处理完弹出或丢弃后，问题规模缩小一颗星，继续用归纳假设即可。

**为什么不会重**：每颗星入栈一次、出栈至多一次，每次对撞都让「存活星总数」严格减少 1，总对撞次数 ≤ n，不存在同一对被反复处理。

**为什么不会漏**：任何一次真实碰撞，在扫描到「右侧那颗负星」时，其左侧的正星必然还在栈中（若它已爆炸，说明它先被更靠右的负星撞掉了，那次碰撞已被处理）。所以所有碰撞都会在「新星入栈前的 while 循环」里被触发。

## 5. 完整代码（Python）

```python
class Solution:
    def asteroidCollision(self, asteroids: list[int]) -> list[int]:
        stack = []  # 存放「已处理且尚未爆炸」的小行星

        for x in asteroids:
            # alive 表示当前这颗新星 x 是否还活着
            alive = True

            # 只有「栈顶向右(>0) 且 新星向左(<0)」才可能碰撞
            while alive and stack and stack[-1] > 0 and x < 0:
                top = stack[-1]
                if top < -x:
                    # 栈顶较小，栈顶爆炸，弹出后继续用 x 撞新的栈顶
                    stack.pop()
                elif top == -x:
                    # 大小相等，同归于尽：栈顶弹出，新星也死
                    stack.pop()
                    alive = False
                else:
                    # 栈顶较大，新星爆炸，什么都不用做
                    alive = False

            # 新星若还活着就入栈（同号、栈空、栈顶为负等情况也会走到这里）
            if alive:
                stack.append(x)

        return stack
```

几个容易忽略的细节：`while` 条件里 `alive` 必须放前面，否则新星已死还会继续撞；`top == -x` 分支里 `alive = False` 不能漏，否则会把已爆炸的星又压回去；`stack[-1] > 0 and x < 0` 两个条件缺一不可，只写 `x < 0` 会让 `[-2, -1]` 这种同向负星错误地进入碰撞逻辑。

## 6. 复杂度

- **时间 O(n)**：外层 for 循环执行 n 次（n = `len(asteroids)`）；内层 while 每次执行都伴随一次 `stack.pop()`，而每颗星最多入栈一次、出栈一次，所以所有 while 迭代加起来不超过 n 次。总操作数 ≤ 2n，即 O(n)。这里没有 log 项，因为没有任何排序或二分。
- **空间 O(n)**：栈最多存放 n 颗星（例如全为正数 `[1,2,3,...]` 时全部入栈）。返回值本身也占 O(n)，但通常不计入额外空间；若计入，仍是 O(n)。

## 7. 边界与反例（至少 4 条）

1. **输入 `[8, -8]` → 期望 `[]`**。容易错在相等分支只弹栈顶、忘了把新星标记为死亡，结果输出 `[-8]`。
2. **输入 `[-2, -1, 2]` → 期望 `[-2, -1, 2]`**。全是同向或「负在左、正在右」，永远不撞。容易错在碰撞条件只判断了 `x < 0`，导致 `-1` 去撞 `-2`。
3. **输入 `[1, 2, 3, -10]` → 期望 `[-10]`**。一颗大负星连撞三颗正星，考验 while 循环是否持续到栈空。容易错在只撞一次就 `break`，输出 `[1, 2, -10]`。
4. **输入 `[-5, 10, -3]` → 期望 `[-5, 10]`**。栈顶 `10` 撞掉 `-3` 后，新星已死，不能再回头去撞栈里的 `-5`（方向不对，`-5` 在左、`10` 在右，`-5` 向左跑、`10` 向右跑，越离越远）。容易错在 `alive` 逻辑写反，把 `-3` 压栈。
5. **输入 `[10, 2, -5]` → 期望 `[10]`**（示例 3）。`-5` 先撞掉 `2` 再撞 `10`，验证「新星存活时继续撞下一个栈顶」的循环结构。

## 8. 面试追问与变体（3 条）

1. **追问：如果小行星速度不同（绝对值同时表示大小和速度），碰撞规则怎么变？** 思路：碰撞判定不再只看方向，还要比较到达同一位置的时间，通常需要按位置排序后用优先队列模拟「最早发生的碰撞」，复杂度升到 O(n log n)。
2. **追问：如果要求返回每颗幸存星最终的位置或碰撞次数？** 思路：栈里除了存大小，再存一个「原始下标」或「累计碰撞次数」的附加字段，出栈时把次数累加到幸存者上。
3. **追问：能不能不用栈、用双指针原地做？** 思路：可以用一个写指针 `k` 模拟栈顶，把 `stack` 换成 `asteroids[0..k]` 原地覆盖，空间降到 O(1)（返回值除外），逻辑与栈版本完全一致。

- **LeetCode 1047. 删除字符串中的所有相邻重复项**：新字符与栈顶相同就弹出，是「相邻对撞」思想的最简版本。
