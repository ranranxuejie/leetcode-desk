## 1. 一句话本质

把两条已经各自排好序的链表，按大小关系**交错地拆开再串起来**，使结果整体有序——本质上是归并排序里「归并」那一步的链表版。

## 2. 读完题的第一反应

**朴素解法**：把两个链表的所有节点值倒进一个数组，`sort()` 一下，再重新建一条链表。复杂度 O((m+n) log(m+n))，瓶颈在排序——但题目已经告诉你两条链表各自有序了，这个排序是**白排的**，信息被浪费了。

**关键观察**：既然两条链表各自升序，那么「全局最小值」只可能出现在两个**当前头节点**中的一个。谁小谁就先出列。这个观察之所以能直接推出下一步，是因为它把「在 m+n 个元素里找最小」降级成了「在 2 个元素里找最小」——每次比较只要 O(1)，一共比 m+n 次，排序那层 log 就被彻底消掉了。

这也解释了为什么这题标签是「递归」：递归的思维就是「我只要处理好当前这一步（选谁当头），剩下的交给子问题」。

## 3. 从暴力到最优

**第一步（暴力）**：收集 → 排序 → 重建。瓶颈是排序的 O((m+n) log(m+n))。

**第二步（双指针归并）**：用两个指针分别指向两条链表的当前节点，每次比较，把小的那个接到结果链尾部，然后该指针后移。瓶颈消失，降到 O(m+n)。

**第三步（实现细节）**：链表没有「尾部追加」的天然操作，需要维护一个 `tail` 指针；同时结果链表的头不好确定（第一个节点可能是 l1 的也可能是 l2 的），标准做法是加一个**哑节点 dummy**，让 `tail` 从 dummy 出发，最后返回 `dummy.next`。这一步不改变复杂度，但把「头节点特判」这个坑填掉了。

**走一遍示例 1**：`l1 = [1,2,4]`，`l2 = [1,3,4]`。

| 轮次 | l1 当前 | l2 当前 | 比较 | 接到 tail 后 | tail 变成 | 结果链 |
|---|---|---|---|---|---|---|
| 初始 | 1 | 1 | — | — | dummy | [] |
| 1 | 1 | 1 | 1 ≤ 1，取 l1 | 1 | 原 l1 的 1 | [1] |
| 2 | 2 | 1 | 2 > 1，取 l2 | 1 | 原 l2 的 1 | [1,1] |
| 3 | 2 | 3 | 2 ≤ 3，取 l1 | 2 | 原 l1 的 2 | [1,1,2] |
| 4 | 4 | 3 | 4 > 3，取 l2 | 3 | 原 l2 的 3 | [1,1,2,3] |
| 5 | 4 | 4 | 4 ≤ 4，取 l1 | 4 | 原 l1 的 4 | [1,1,2,3,4] |
| 6 | None | 4 | l1 空，取 l2 | 4 | 原 l2 的 4 | [1,1,2,3,4,4] |
| 7 | None | None | 循环结束 | — | — | 同上 |

注意第 6 轮：l1 先耗尽，剩下的 l2 整段直接挂上去即可，不用再逐个比较——因为 l2 自己是有序的，且它的每个元素都 ≥ 已放入的最大值。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**说清楚。设结果链已接好的部分为 `R`，当前 `l1`、`l2` 指向尚未处理的节点。

不变量（每轮循环开始时成立）：

1. `R` 严格升序；
2. `R` 中所有元素 ≤ `l1` 和 `l2` 当前指向的值（若存在）；
3. `R` 恰好由「原 l1 前 i 个 + 原 l2 前 j 个」组成，不重不漏。

**初始化**：`R` 为空，三条都平凡成立。

**保持**：假设不变量成立，比较 `l1.val` 与 `l2.val`，取较小者 x 接到 `R` 尾部。由不变量 2，x ≥ `R` 末尾，故 `R` 仍升序（不变量 1 保持）；x 是两链当前头中的较小者，而两链各自有序，所以 x 是**所有未处理元素中的最小值**，接上后不变量 2 仍成立；`R` 只多了一个来自某条链的节点，不变量 3 保持。

**终止**：某条链耗尽时，另一条链剩余部分整体有序且每个元素都 ≥ `R` 末尾（由不变量 2 和该链自身有序性），整段接上后三条不变量依然成立，且此时所有节点都已进入 `R`——不重不漏，故结果正确。

「不会漏」由不变量 3 保证（每个节点恰好被处理一次），「不会重」同理；「有序」由不变量 1 保证。

## 5. 完整代码（Python）

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def mergeTwoLists(self, list1: ListNode, list2: ListNode) -> ListNode:
        # 哑节点：让 tail 一开始就有落脚点，省掉「结果头是谁」的特判
        dummy = ListNode(0)
        tail = dummy

        # 两个指针都非空时才需要比较；任一为空就退出循环
        while list1 and list2:
            if list1.val <= list2.val:
                # 取 l1 当前节点：注意是「摘下来接上」，不是新建节点
                tail.next = list1
                list1 = list1.next
            else:
                tail.next = list2
                list2 = list2.next
            tail = tail.next  # tail 永远指向结果链最后一个节点

        # 循环结束时至少一条链为空，把另一条剩余部分整段挂上
        # 用 or 而不是 if/else：两条都空时结果是 None，正好正确
        tail.next = list1 or list2

        return dummy.next  # dummy 本身是哨兵，真正的头是它的下一个
```

递归写法（面试常被要求写，思路是「当前选谁当头，剩下的递归合并」）：

```python
class Solution:
    def mergeTwoLists(self, list1: ListNode, list2: ListNode) -> ListNode:
        if not list1:
            return list2          # 一条空，答案就是另一条
        if not list2:
            return list1
        if list1.val <= list2.val:
            list1.next = self.mergeTwoLists(list1.next, list2)
            return list1          # l1 当头，它的 next 交给子问题
        else:
            list2.next = self.mergeTwoLists(list1, list2.next)
            return list2
```

## 6. 复杂度

设两条链表长度分别为 m、n。

- **时间 O(m+n)**：循环每轮恰好消耗一个节点（`list1` 或 `list2` 前移一步），总共消耗 m+n 个节点，每轮内部只有一次比较和常数次指针赋值，所以是 O(m+n)。这里没有 log 项，因为没有任何「分治/排序」结构。
- **空间 O(1)**（迭代版）：只用了 `dummy`、`tail` 两个额外指针，与输入规模无关。注意我们**没有新建节点**，只是改 `next` 指针把原节点重新串起来。
- **递归版空间 O(m+n)**：递归深度最坏为 m+n（每次只消耗一个节点），每层一个栈帧。这是面试里常被追问的点——「能不能不用额外空间」就是在问迭代版。

## 7. 边界与反例（至少 4 条）

1. **`[]` 与 `[]`** → 输出 `[]`。容易错在：`tail.next = list1 or list2` 中两者都是 `None`，`None or None` 得 `None`，正确；但如果写成 `if list1: ... elif list2: ...` 而漏了「都空」分支，`tail.next` 可能没被赋值（虽然默认是 None，但逻辑上不严谨）。
2. **`[]` 与 `[0]`** → 输出 `[0]`。容易错在：循环一次都不进，直接走尾部拼接；如果忘了这一步，会返回空链表。
3. **`[5]` 与 `[1,2,3]`** → 输出 `[1,2,3,5]`。容易错在：l1 的第一个元素比 l2 全部大，结果链的头来自 l2——这正是需要 dummy 的原因，若手动维护 head 会写出一堆特判。
4. **`[1,1,1]` 与 `[1,1]`** → 输出 `[1,1,1,1,1]`。容易错在：比较用 `<` 而非 `<=` 时虽然结果值一样，但会改变「相等时取谁」的稳定性；更危险的是有人误以为相等要跳过，导致丢节点。
5. **`[1,2,4]` 与 `[1,3,4]`（示例 1）** → 输出 `[1,1,2,3,4,4]`。容易错在：把节点「复制」而不是「移动」，虽然值对，但破坏了「拼接原节点」的题意，且空间变成 O(m+n)。

## 8. 面试追问与变体（3 条）

1. **追问：不用递归、不用 dummy 能不能写？** 思路：手动处理「结果头是谁」的特判（比较两链头，小的当 head），之后逻辑与 dummy 版一致；dummy 只是把这个特判藏起来了。
2. **追问：如果要求合并后去重（相同值只保留一个）？** 思路：比较时若 `list1.val == list2.val`，接一个、两个指针同时后移，其余不变。
3. **追问：合并 k 条有序链表（LeetCode 23）？** 思路：两两归并（分治）或用大小为 k 的小顶堆，每次取堆顶；本题是 k=2 的特例。
