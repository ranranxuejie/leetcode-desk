## 1. 一句话本质

在字符串末尾跳过所有空格后，数出连续字母的个数。

## 2. 读完题的第一反应

**朴素解法**：用 `s.split()` 按空格切分，取最后一个元素求长度。这在 Python 里一行就能写：

```python
return len(s.split()[-1])
```

它卡在哪？`split()` 会扫描**整个字符串**、为每个单词创建新的字符串对象、再放进列表。虽然时间复杂度是 O(n)，但常数很大：分配了 O(n) 的额外内存，还做了大量无用功——我们只关心末尾那一小段，前面几万个字符被白白处理了。

**关键观察**：题目只问「最后一个单词」，而最后一个单词只和字符串的**尾部**有关。从右往左看，字符串尾部只有三种字符状态：空格、字母、以及「字母之后又遇到空格」的边界。一旦我们从右往左扫到第一个字母，再继续往左数到空格（或越界）为止，就得到了答案——**根本不需要碰字符串的前半部分**。

这个观察直接指向下一步：用两个指针（或者一个下标）从末尾走，先跳过尾部空格，再数字母。

## 3. 从暴力到最优

**暴力（split）**：对 `s = " fly me to the moon "`，`split()` 得到 `["fly","me","to","the","moon"]`，取 `"moon"` 长度 4。它处理了全部 21 个字符，创建了 5 个新字符串。

**优化思路的演进**：

第一步，想到「从右往左扫」。设下标 `i = len(s) - 1`。

第二步，明确要跳过什么。尾部可能有空格（示例 2 末尾就有一个），所以先做**阶段一：跳过尾部空格**。对 `" fly me to the moon "`：

```
i 从 20 开始（最后一个字符是空格）
s[20]=' ' → i=19
s[19]='n' → 停止，进入阶段二
```

第三步，**阶段二：数连续字母**。从 `i=19` 往左数，直到遇到空格或越界：

```
i=19 'n' → count=1, i=18
i=18 'o' → count=2, i=17
i=17 'o' → count=3, i=16
i=16 'm' → count=4, i=15
i=15 ' ' → 停止
```

返回 4。整个过程只访问了下标 20 到 15 共 6 个字符，前面 15 个字符一次都没看。

**瓶颈怎么被消掉的**：暴力法的瓶颈是「处理了整个字符串 + 额外分配内存」。从右往左扫把「处理范围」从整个字符串收缩到「尾部空格 + 最后一个单词」，同时只用两个整型变量（`i` 和 `count`），额外空间从 O(n) 降到 O(1)。

注意一个细节：最坏情况仍然是 O(n)——比如 `s = "a"` 或 `s = "aaaa...a"`（整个串就是一个单词），此时确实要扫完。但这是**信息论下界**：你至少得看一眼才能知道它有多长。所以 O(n) 是最优的，我们优化的是常数和空间，不是渐进复杂度。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

定义两个阶段，各自维护一个不变量：

**阶段一的不变量**：循环开始时，`s[i+1:]` 全部是空格。每次迭代 `i -= 1` 时，因为当前 `s[i]` 是空格，所以新的 `s[i+1:]` 仍然全是空格。循环终止条件是 `i < 0` 或 `s[i] != ' '`。若因 `i < 0` 终止，说明整个串全是空格——但题面保证「至少存在一个单词」，此情况不会发生；若因 `s[i] != ' '` 终止，则 `i` 恰好指向**最后一个单词的最后一个字母**（因为 `s[i+1:]` 全是空格，`s[i]` 是字母，它右边再没有字母了）。

**阶段二的不变量**：循环开始时 `count = 0`，且 `s[i]` 是字母。每次迭代，若 `s[i]` 是字母则 `count += 1` 并左移；若 `s[i]` 是空格或 `i < 0` 则终止。终止时，`count` 等于从 `i+1` 到阶段一结束位置之间连续字母的个数。由阶段一的结论，这段连续字母**就是**最后一个单词的全部，且**只**包含它——因为往左第一个非字母字符（空格）就停了，不会把倒数第二个单词的字母算进来（不会重），也不会在单词中间停下（不会漏）。

两个不变量合起来：阶段一精确定位了最后一个单词的右端点，阶段二从右端点向左精确数完了这个单词。因此返回值正确。

## 5. 完整代码（Python）

```python
class Solution:
    def lengthOfLastWord(self, s: str) -> int:
        i = len(s) - 1

        # 阶段一：跳过尾部空格，定位最后一个单词的最后一个字母
        while i >= 0 and s[i] == ' ':
            i -= 1

        # 阶段二：从右往左数连续字母
        count = 0
        while i >= 0 and s[i] != ' ':
            count += 1
            i -= 1

        return count
```

关键逻辑说明：
- `i = len(s) - 1`：从最后一个字符开始，这是「只看尾部」的起点。
- 第一个 `while`：`i >= 0` 防止越界（虽然题面保证有单词，但防御性写法更稳），`s[i] == ' '` 是跳过条件。退出时 `i` 指向最后一个单词的末字母。
- 第二个 `while`：`s[i] != ' '` 是继续数字母的条件，`i >= 0` 处理「单词顶到字符串开头」的情况（如 `"a"`）。
- 两个循环串行，不嵌套，总访问次数不超过 `len(s)`。

## 6. 复杂度

**时间 O(n)**，其中 n = `len(s)`。来源：阶段一最多走完整个字符串（全空格时，但题面排除），阶段二最多走完整个字符串（整个串是一个单词时）。两个阶段是**串行**的，总步数 ≤ n + n，仍是 O(n)。没有 log n 项——本题没有任何分治或二分结构，所有操作都是线性扫描。

**空间 O(1)**。来源：只用了 `i` 和 `count` 两个整型变量，与 n 无关。对比 `split()` 解法的 O(n)（列表 + 每个单词的新字符串），这是本题空间优化的核心收益。

## 7. 边界与反例（至少 4 条）

1. **输入 `s = "a"`** → 期望 `1` → 容易错在：阶段一 `i=0` 时 `s[0]='a'` 不是空格，直接进阶段二；阶段二数到 `i=-1` 才停。如果第二个循环漏写 `i >= 0`，会越界报错或死循环。

2. **输入 `s = "   "`** → 题面保证「至少存在一个单词」，此输入非法。但若面试官追问，代码会：阶段一走到 `i=-1` 退出，阶段二因 `i >= 0` 为假直接返回 `0`。**假设**：本题按题面约束，不出现全空格串；代码对非法输入返回 0 而非崩溃，属于防御性行为。

3. **输入 `s = "Hello World"`** → 期望 `5` → 容易错在：有人从右往左数到第一个空格就返回，但没先跳过尾部空格——本例尾部无空格所以碰巧对；换成 `"Hello World "` 就会返回 0。**必须先跳空格再数字母**，顺序不能反。

4. **输入 `s = "a "`** → 期望 `1` → 容易错在：阶段一跳过末尾空格后 `i=0`，阶段二数 1 个字母后 `i=-1` 退出。若阶段二的终止条件写成 `s[i] != ' '` 而没加 `i >= 0`，在 `i=-1` 时会访问 `s[-1]`（Python 里是最后一个字符 `' '`），恰好也能停，但这是**依赖 Python 负索引的巧合**，换语言就错。显式写 `i >= 0` 才是正确做法。

5. **输入 `s = "day"`** → 期望 `3` → 容易错在：整个串就是一个单词，阶段二必须能一路数到 `i=-1`。这验证了「单词顶到开头」的边界。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回最后一个单词本身（字符串），而不是长度？** 思路：阶段二记录终止下标 `end = i`（阶段一结束位置）和起始下标 `start = i + 1`（阶段二结束位置），返回 `s[start:end+1]`。空间变成 O(单词长度)，因为要返回子串。

2. **追问：如果字符串有 10^8 长度，且保证最后一个单词很短，怎么进一步优化？** 思路：本题已是 O(尾部长度)，无法渐进优化；但可以讨论「从右往左按块读取」以减少缓存未命中，或说明在 Python 中 `s[i]` 是 O(1) 随机访问，无需额外优化。核心是让面试官看到你理解「下界由必须检查的字符数决定」。

3. **追问：改成求「第一个单词的长度」？** 思路：对称地把两个循环改成从左往右：先跳过头部空格，再数连续字母。代码结构完全镜像，考察你是否真正理解「跳空格 + 数字母」这个模式而非死记从右往左。
