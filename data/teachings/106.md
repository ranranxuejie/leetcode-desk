## 1. 一句话本质

后序遍历的**最后一个元素**就是当前子树的根，拿它去中序数组里一劈两半，左边是左子树、右边是右子树，然后对两半递归重复这个动作。

## 2. 读完题的第一反应

**朴素解法**：后序最后一个元素是根，这谁都知道。于是每次递归时，拿着这个根值去 `inorder` 里**线性扫描**找位置，找到后切出左右两段，再对 `postorder` 切出对应长度，继续递归。这个思路本身是对的，卡在「线性扫描」上：树退化成链时，每层都要扫 O(n)，总复杂度 O(n²)。n = 3000 时 9×10⁶ 次操作其实还能过，但面试官问你这题，八成是想听你把它压到 O(n)。

**关键观察**：瓶颈只在「根值 → 中序下标」这一步的查找。而题面明确说「inorder 和 postorder 都由**不同**的值组成」——值唯一，意味着可以预先建一张 `值 → 中序下标` 的哈希表，把每次查找从 O(n) 降到 O(1)。这一步是整道题从「能过」到「漂亮」的分水岭。

第二个观察更隐蔽：**切 postorder 不需要真的切**。后序数组里，左子树的所有元素紧挨在右子树前面，而右子树的长度 = 中序里根右侧的元素个数。所以只要知道「当前子树在 postorder 里的右边界」和「左子树的节点数」，就能用下标算出来，不必复制数组。这一点决定了空间复杂度能不能从 O(n log n) 降到 O(n)。

## 3. 从暴力到最优

拿示例 1 走一遍：`inorder = [9,3,15,20,7]`，`postorder = [9,15,7,20,3]`。

**第 0 层**：postorder 末尾是 `3`，根 = 3。去 inorder 找 3，下标 1。于是左子树中序 = `[9]`（长度 1），右子树中序 = `[15,20,7]`（长度 3）。postorder 里，左子树占前 1 个 = `[9]`，右子树占接下来 3 个 = `[15,7,20]`，根 3 在最后。

**第 1 层（左）**：postorder 段 `[9]`，末尾 9，根 = 9。inorder 段 `[9]` 里 9 的下标就是段首，左长度 0、右长度 0，叶子。

**第 1 层（右）**：postorder 段 `[15,7,20]`，末尾 20，根 = 20。inorder 段 `[15,20,7]` 里 20 在中间，左 = `[15]`，右 = `[7]`。postorder 里左占 1 个 `[15]`，右占 1 个 `[7]`。

**第 2 层**：15 和 7 都是叶子。

树长成 `3(9, 20(15, 7))`，和输出对得上。

**暴力版**在这一步的代价：每层都要 `inorder.index(root)`，第 0 层扫 5 次、第 1 层扫 1+3 次……链状树时是 1+2+…+n。**优化版**：建表一次 O(n)，之后每次查表 O(1)，总查找 O(n)。同时用四个下标 `(in_l, in_r, post_l, post_r)` 圈定当前子数组范围，不复制数组，递归只传整数。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说。定义递归函数 `build(in_l, in_r, post_l, post_r)` 的契约：*它返回的树，其中序遍历恰好是 `inorder[in_l:in_r+1]`，后序遍历恰好是 `postorder[post_l:post_r+1]`，且两段长度相等*。

**基础**：区间为空（`in_l > in_r`）时返回 None，空树的中序、后序都是空序列，契约成立。

**归纳**：设区间非空。后序的最后一个元素 `postorder[post_r]` 是整棵子树的根——这是后序遍历的定义（根最后访问），题面保证输入是合法后序，所以这个元素一定存在且就是根。设它在 inorder 中的下标为 `k`（哈希表保证能查到，因为题面保证两数组元素集合相同）。中序遍历中根左侧 `inorder[in_l:k]` 全部属于左子树、右侧 `inorder[k+1:in_r+1]` 全部属于右子树——这是中序遍历的定义，且**每个节点只属于一边**，所以不会重；两段拼上根恰好覆盖整个区间，所以不会漏。

左子树节点数 `L = k - in_l`。后序中左子树占 `postorder[post_l : post_l+L]`，右子树占 `postorder[post_l+L : post_r]`（根在 `post_r` 被排除）。这两个切分与中序的切分长度一致，因为同一棵子树在两序中的节点数必然相同。对左右两段分别递归，由归纳假设各自满足契约，拼上根后整棵树满足契约。

**唯一性**：题面说值互不相同，所以 `k` 唯一确定，切分唯一，构造出的树唯一。这保证了「不会构造出另一棵合法但不同的树」。

## 5. 完整代码（Python）

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def buildTree(self, inorder, postorder):
        # 值 -> 中序下标，O(n) 建表，之后每次定位根 O(1)
        pos = {v: i for i, v in enumerate(inorder)}

        def build(in_l, in_r, post_l, post_r):
            # 空区间：没有节点可建
            if in_l > in_r:
                return None

            root_val = postorder[post_r]      # 后序末尾即根
            root = TreeNode(root_val)
            k = pos[root_val]                 # 根在中序中的位置

            left_size = k - in_l              # 左子树节点数
            # 左子树：中序 [in_l, k-1]，后序 [post_l, post_l+left_size-1]
            root.left = build(in_l, k - 1,
                              post_l, post_l + left_size - 1)
            # 右子树：中序 [k+1, in_r]，后序 [post_l+left_size, post_r-1]
            root.right = build(k + 1, in_r,
                               post_l + left_size, post_r - 1)
            return root

        return build(0, len(inorder) - 1, 0, len(postorder) - 1)
```

注意右子树后序的右边界是 `post_r - 1` 而不是 `post_r`——根已经用掉了。这是最容易写错的一处。

## 6. 复杂度

**时间 O(n)**：建哈希表 O(n)；递归共访问 n 个节点，每个节点做常数次操作（查表、算下标、建节点），合计 O(n)。没有排序、没有二分，所以没有 log 因子。

**空间 O(n)**：哈希表存 n 个键值对，O(n)；递归栈深度等于树高，最好 O(log n)、最坏 O(n)（链状树）；返回的树本身占 n 个节点，但那是输出，通常不计入辅助空间。所以辅助空间是 O(n)，由哈希表主导。

对比暴力版：时间 O(n²)（每层线性查找），空间 O(n)（递归栈最坏）加上切片复制的话可能到 O(n log n)。哈希表把时间那一维彻底消掉了。

## 7. 边界与反例（至少 4 条）

1. **单节点** `inorder=[-1], postorder=[-1]` → 返回 `[-1]`。容易错在：递归里 `left_size = 0`，左右子树的区间都变成 `[0, -1]` 这种「左边界大于右边界」的形式，如果判空条件写成 `in_l == in_r` 就会漏判、死递归。必须用 `in_l > in_r`。

2. **只有左孩子的链** `inorder=[1,2,3], postorder=[3,2,1]` → 根 1，右子树为空，左子树是 `2(3)`。容易错在：以为后序末尾是 1 就当中序里 1 在中间；实际 `k=0`，`left_size=0`，右子树拿到 `[1,2]` 中序和 `[3,2]` 后序，继续递归。若把左右子树的 postorder 边界写反，会构造出镜像树。

3. **只有右孩子的链** `inorder=[1,2,3], postorder=[1,2,3]` → 根 3，左子树是 `1(2)`。容易错在：`k=2`，`left_size=2`，左子树后序取 `[post_l, post_l+1]` = `[1,2]`，右子树区间 `[post_l+2, post_r-1]` = `[3,2]` 是空的（左边界 > 右边界），必须正确返回 None。

4. **完全平衡树** `inorder=[4,2,5,1,6,3,7], postorder=[4,5,2,6,7,3,1]` → 根 1，左右各 3 个节点。容易错在：`left_size=3` 时右子树后序起点是 `post_l+3`，若误写成 `post_l+left_size+1` 会跳过元素，导致右子树少一个节点、区间长度对不上。

5. **负数值** `inorder=[-3,-1], postorder=[-3,-1]` → 根 -1，左孩子 -3。哈希表用值做键，负数没问题；但如果有人用「值当数组下标」就会崩。题面值域 -3000~3000，提醒别用值直接索引。

## 8. 面试追问与变体（3 条）

1. **追问：如果改成「前序 + 中序」构造呢？** 思路：前序**第一个**元素是根，其余切分逻辑完全一样，只是左右子树的 preorder 区间变成 `[pre_l+1, pre_l+left_size]` 和 `[pre_l+left_size+1, pre_r]`。核心不变：用根在中序的位置算左子树大小。

2. **追问：如果数组里有重复值怎么办？** 思路：哈希表失效，因为一个值可能对应多个中序下标，无法唯一确定切分。此时题目本身可能无解或多解，需要额外约束（比如规定取最左匹配）或改用「按值+出现次数」的计数匹配，复杂度上升。这题能 O(n) 的前提正是「值互不相同」。

3. **追问：不用递归、用迭代能写吗？** 思路：可以。从后序末尾往前扫，配合一个栈模拟中序回溯：当前节点若不等于中序栈顶就压栈当右孩子，相等则弹栈直到不相等，再挂成左孩子。本质是把递归的「根→右→左」顺序显式化，代码更绕但空间省掉递归栈。

## 9. 举一反三（2-3 道同类题）

- **105. 从前序与中序遍历序列构造二叉树**：同一套「根定位 + 中序劈半 + 下标传参」的骨架，只是根在前序开头。
- **889. 根据前序和后序遍历构造二叉树**：没有中序，根能定但左右子树边界不唯一，答案不唯一，需要额外约定（如前序第二个元素归左子树），是本题的「退化版」。
- **108. 将有序数组转换为二叉搜索树**：同样是「取中点当根、递归两半」，只是根由中序位置直接给出（中点），不需要后序辅助，可看作本题分治思想的简化特例。
