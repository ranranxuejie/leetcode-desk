## 1. 一句话本质

在 `s` 里枚举所有长度等于 `len(p)` 的窗口，判断每个窗口的字符多重集是否与 `p` 完全相同，输出满足条件的窗口左端点。

## 2. 读完题的第一反应

**朴素解法**：枚举 `s` 中每个长度为 `m = len(p)` 的起点 `i`，把 `s[i:i+m]` 拿出来排序，和排序后的 `p` 比较。窗口个数约 `n`，每个窗口排序 `O(m log m)`，总复杂度 `O(n·m log m)`。`n, m` 都到 `3×10^4`，最坏 `9×10^8` 量级，超时。

**关键观察**：异位词的本质是「字符计数向量相同」，跟顺序无关。所以比较两个字符串不需要排序，只需要比较 26 个字母的计数。更进一步：相邻两个窗口 `s[i:i+m]` 和 `s[i+1:i+1+m]` 只差两个字符——**移出一个 `s[i]`、移入一个 `s[i+m]`**。这意味着窗口的计数向量可以 `O(1)` 增量更新，而不是每个窗口重新数一遍。这一步把「每个窗口 `O(m)` 的重算」压成了「整体 `O(n)` 的滑动」。

## 3. 从暴力到最优

**第一步：排序比较 → 计数比较。** 每个窗口数 26 个字母，`O(26)` 比较，总 `O(26n)`。已经能过，但常数偏大，且每次窗口都要重新数 `m` 个字符，本质还是 `O(nm)`。

**第二步：计数比较 → 增量滑动窗口。** 维护一个长度固定为 `m` 的窗口，窗口右移时只做两次计数修改。

用示例 1 走一遍：`s = "cbaebabacd"`，`p = "abc"`，`m = 3`。

`need = {a:1, b:1, c:1}`。

- 初始窗口 `s[0:3] = "cba"`，`window = {c:1, b:1, a:1}`，与 `need` 相等 → 记录 `0`。
- 右移：移出 `s[0]='c'`，移入 `s[3]='e'`。`window = {b:1, a:1, e:1}`，不等。
- 右移：移出 `s[1]='b'`，移入 `s[4]='b'`。`window = {a:1, e:1, b:1}`，不等。
- 右移：移出 `s[2]='a'`，移入 `s[5]='a'`。`window = {e:1, b:1, a:1}`，不等。
- 右移：移出 `s[3]='e'`，移入 `s[6]='b'`。`window = {b:2, a:1}`，不等。
- 右移：移出 `s[4]='b'`，移入 `s[7]='a'`。`window = {b:1, a:2}`，不等。
- 右移：移出 `s[5]='a'`，移入 `s[8]='c'`。`window = {b:1, a:1, c:1}`，相等 → 记录 `6`。
- 右移：移出 `s[6]='b'`，移入 `s[9]='d'`。`window = {a:1, c:1, d:1}`，不等。

结果 `[0, 6]`，与示例一致。

**第三步：比较本身也能 `O(1)`。** 每次窗口移动后如果都拿两个字典逐键比，最坏 `O(26)`。引入一个计数器 `matched`：表示「当前有多少个字母的计数已经恰好等于 `need` 中的计数」。窗口移动时只更新被移出/移入的两个字母的匹配状态，比较变成 `matched == len(need)` 的 `O(1)` 判断。这是本题从「能过」到「面试官满意」的关键细节。

## 4. 正确性：为什么不会漏、不会重

**不漏**：任何长度等于 `m` 的子串，其左端点 `i` 必满足 `0 ≤ i ≤ n-m`。我们的循环恰好枚举了所有这些左端点（初始窗口在 `0`，之后每次右移一格直到右端点触底）。所以候选集合被完整覆盖。

**不重**：每个左端点只被访问一次，且只在访问时判断一次是否记录，天然无重复。

**判断正确**：维护不变量——「循环体每次判断前，`window` 恰好等于 `s[i:i+m]` 的字符计数，`matched` 恰好等于 `need` 中计数与 `window` 相等的字母个数」。初始时窗口就是 `s[0:m]`，成立。归纳步：右移时移出 `s[i]`、移入 `s[i+m]`，对这两个字母分别做「减一/加一后重新判定是否匹配」，其余字母计数不变、匹配状态不变，不变量保持。于是 `matched == len(need)` 当且仅当所有字母计数都相等，当且仅当 `s[i:i+m]` 是 `p` 的异位词。判定与事实等价，故不漏判也不错判。

## 5. 完整代码（Python）

```python
from collections import Counter

class Solution:
    def findAnagrams(self, s: str, p: str) -> list[int]:
        n, m = len(s), len(p)
        # 窗口比模式还长，不可能存在异位词子串
        if n < m:
            return []

        need = Counter(p)          # 目标计数
        window = Counter()         # 当前窗口计数
        matched = 0                # 已与 need 计数完全相等的字母种数
        res = []

        for right in range(n):
            # 1. 右端字符入窗
            ch = s[right]
            window[ch] += 1
            # 入窗后该字母的匹配状态可能从「不等」变「相等」
            if window[ch] == need[ch]:
                matched += 1
            elif window[ch] == need[ch] + 1:
                # 原本相等，加一后变不等，匹配数减一
                matched -= 1

            # 2. 窗口超过 m，左端字符出窗
            if right >= m:
                left_ch = s[right - m]
                # 出窗前若该字母原本匹配，减一后就不匹配了
                if window[left_ch] == need[left_ch]:
                    matched -= 1
                elif window[left_ch] == need[left_ch] + 1:
                    # 原本不匹配（多一个），减一后变匹配
                    matched += 1
                window[left_ch] -= 1

            # 3. 窗口长度恰为 m 时判断
            if right >= m - 1 and matched == len(need):
                res.append(right - m + 1)

        return res
```

注意 `need[ch]` 对不在 `p` 中的字母返回 `0`（`Counter` 的默认值），所以 `window[ch] == need[ch]` 在 `ch` 不在 `p` 中时等价于「窗口里这个字母计数为 0」，逻辑自洽，无需特判。

## 6. 复杂度

- **时间 `O(n + m)`**：`Counter(p)` 建表 `O(m)`；主循环 `right` 从 `0` 到 `n-1` 共 `n` 次，每次只做常数次字典读写和整数比较，`O(1)`，合计 `O(n)`。没有排序，没有 `log` 项。
- **空间 `O(1)`（严格说是 `O(Σ)`，`Σ` 为字符集大小）**：`need` 和 `window` 最多各存 26 个小写字母的计数，与 `n`、`m` 无关。结果列表 `res` 最坏 `O(n)`，但那是输出本身，通常不计入辅助空间。

## 7. 边界与反例（至少 4 条）

1. `s = "a", p = "ab"` → `[]`。**易错点**：不判 `n < m` 直接进循环，`right >= m` 永远不成立，窗口长度永远到不了 `m`，虽然结果碰巧对，但逻辑上窗口从未成型；显式提前返回更清晰。
2. `s = "ab", p = "ab"` → `[0]`。**易错点**：判断条件写成 `right >= m` 而不是 `right >= m - 1`，会漏掉第一个窗口（`right = m-1` 时窗口刚好成型）。
3. `s = "aa", p = "aa"` → `[0]`。**易错点**：用 `set` 代替计数，`"aa"` 和 `"a"` 会被判成相同；必须用计数而非去重集合。
4. `s = "baa", p = "aa"` → `[1]`。**易错点**：出窗时先减计数再判匹配状态，顺序反了会导致 `matched` 多减一次；必须先根据「减之前」的状态判断，再减。
5. `s = "abc", p = "d"` → `[]`。**易错点**：`need` 里没有的字母，`need[ch]` 取 `0`，若代码里写 `need[ch] -= 1` 会污染 `need`；本题只读 `need`，不写，安全，但要意识到这个坑。

## 8. 面试追问与变体（3 条）

1. **追问：如果字符集不是小写字母而是任意 Unicode，怎么做？** 思路不变，把 `Counter` 换成通用哈希表即可，复杂度按字符集大小 `Σ` 计为 `O(n + m)` 时间、`O(Σ)` 空间。
2. **追问：不要求长度相等，求 `s` 中包含 `p` 所有字符（可多不可少）的最短子串。** 这是「最小覆盖子串」，滑动窗口变成可变长：右端扩张直到覆盖，左端收缩求最短，`matched` 的语义改为「已满足的字母种数」。
3. **追问：求 `s` 中所有是 `p` 的「排列」的子串，但允许一个字符不同（近似匹配）。** 在 `matched` 基础上再加一个 `diff` 计数，记录当前有多少字母计数偏差为 1，判断条件改为 `matched + diff == len(need) and diff <= 1`。

## 9. 举一反三（2-3 道同类题）

- **567. 字符串的排列**：几乎同一题，只是返回布尔值而非所有下标，滑动窗口 + 计数比较的框架完全复用。
- **76. 最小覆盖子串**：同样是「窗口计数 vs 目标计数 + matched 计数器」，区别在窗口长度可变、求最短而非枚举定长。
- **3. 无重复字符的最长子串**：滑动窗口的入门版，窗口内用集合/计数维护「无重复」这一不变量，体会「右扩左缩」的通用骨架。
