## 1. 一句话本质

在所有字符串的「同一列」上，从左往右找**最长的、所有串都相同的列序列**——一旦某一列出现分歧，或者某个串提前用完，就立刻停。

## 2. 读完题的第一反应

**朴素解法**：拿第一个串当候选前缀 `prefix = strs[0]`，然后依次和每个串比较，每次把 `prefix` 截短到「它和当前串的公共前缀」为止。这是最自然的写法，复杂度是 O(S)，其中 S 是所有字符串的字符总数——因为最坏情况下每个字符都要被看一次。这个复杂度其实**已经是最优量级**了，因为答案本身可能就有 O(S) 长，你不可能比读一遍输入更快。

那瓶颈在哪？在于**「每次比较都要从头扫 prefix」**。如果第一个串特别长（比如 200 个字符），而后面每个串都在第 1 个字符就分歧，你会对每个串都扫一遍那个长 prefix 的前缀部分，虽然摊还下来仍是 O(S)，但常数上做了很多无用功。

**关键观察**：公共前缀这个性质是**逐列独立**的。第 0 列所有串都相同，才可能讨论第 1 列；第 1 列都相同，才可能讨论第 2 列。也就是说，**列与列之间是「与」的关系，一旦某列失败，后面全部作废**。这直接指向一个「按列扫描、遇错即停」的写法：不需要维护一个会变长的 prefix 再反复截断，而是**直接定位到「第一个出错的列」**，答案就是 `strs[0][:那个列号]`。

这个观察的价值在于：它把「反复截断字符串」变成了「一次定位边界」，代码更短，且天然早停。

## 3. 从暴力到最优

**暴力（纵向逐列比较，但写法笨）**：

```python
prefix = strs[0]
for s in strs[1:]:
    while not s.startswith(prefix):
        prefix = prefix[:-1]
        if not prefix:
            return ""
return prefix
```

问题：`startswith` 每次从头比，`prefix[:-1]` 每次造新串。逻辑对，但做了重复工作。

**优化（纵向扫描，遇错即停）**：

以 `strs = ["flower","flow","flight"]` 为例，走一遍：

- 第 0 列：`f, f, f` → 全相同，继续
- 第 1 列：`l, l, l` → 全相同，继续
- 第 2 列：`o, o, i` → `i != o`，**分歧**，停。答案 = `strs[0][:2]` = `"fl"`

再看 `["dog","racecar","car"]`：

- 第 0 列：`d, r, c` → 立刻分歧，停。答案 = `strs[0][:0]` = `""`

注意这里有个**必须处理的细节**：扫描到第 j 列时，要保证**每个串都还有第 j 个字符**。如果某个串长度只有 j，它就已经「用完」了，说明公共前缀不可能超过 j，也要停。比如 `["ab", "a"]`：第 0 列 `a,a` 相同；第 1 列时 `"a"` 没有第 1 个字符，停，答案 `"a"`。

所以循环条件是：`对每个 s，j < len(s) 且 s[j] == strs[0][j]`。任一不满足就返回 `strs[0][:j]`。

**为什么这是最优的**：每个字符最多被访问一次（第 j 列比较完就不再回看），且一旦分歧立刻返回，不会多扫。时间下界就是「答案长度 × 串数」这个量级，已经达到。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。

**不变量**：在进入第 j 列的比较之前，`strs[0][:j]` 已经是所有串的公共前缀（即对每个 s，`s[:j] == strs[0][:j]`）。

- **初始**：j = 0，空前缀是所有串的公共前缀，成立。
- **保持**：若第 j 列所有串都满足 `j < len(s)` 且 `s[j] == strs[0][j]`，则 `s[:j+1] == strs[0][:j+1]`，不变量对 j+1 成立。
- **终止**：循环在第一个不满足条件的 j 处停下。此时 `strs[0][:j]` 是公共前缀（由不变量保证），而 `strs[0][:j+1]` **不是**公共前缀（因为第 j 列有串缺失或字符不同）。所以 `strs[0][:j]` 是**最长**公共前缀——再长一位就失败，不可能有更长的。

**不会漏**：任何长度 > j 的候选前缀都包含第 j 列，而第 j 列已被证明失败，故不存在。
**不会重**：每列只比较一次，返回的是精确边界，没有重复计算。

## 5. 完整代码（Python）

```python
class Solution:
    def longestCommonPrefix(self, strs) -> str:
        # 题面保证 strs 非空（1 <= strs.length），但防御性处理空列表
        if not strs:
            return ""

        first = strs[0]
        n = len(first)

        # 逐列扫描：j 是当前正在检查的列号
        for j in range(n):
            ch = first[j]  # 以第一个串的第 j 个字符为基准
            for s in strs:
                # 两种情况必须停：
                # 1) 当前串长度不够，没有第 j 个字符
                # 2) 当前串第 j 个字符与基准不同
                if j >= len(s) or s[j] != ch:
                    return first[:j]  # 前 j 列全部相同，答案就是前 j 个字符
        # 所有列都通过，说明第一个串本身就是公共前缀
        return first
```

关键逻辑说明：
- 外层 `for j in range(n)` 只以**第一个串**的长度为上界——公共前缀不可能比最短串还长，而第一个串已经是一个上界，够了。
- 内层 `for s in strs` 包含 `strs[0]` 自己，第一次比较 `s[0][j] != ch` 恒为 False，无害；也可以从 `strs[1:]` 开始，省一次比较。
- `return first[:j]` 是**唯一**的提前返回点，保证「第一次失败即答案」。

## 6. 复杂度

设 `m` = 字符串个数（≤ 200），`L` = 最短串长度（≤ 200），`S` = 所有串字符总数。

- **时间**：O(m · L)。外层最多 L 列，内层最多 m 个串，每列每串 O(1) 比较。注意这是**最坏**情况；实际是 O(答案长度 × m)，一旦分歧立刻停。用 S 表示时，因为只扫到最短串长度，所以 ≤ O(S)，但更精确的上界是 O(m · L)。
- **空间**：O(1) 额外空间（不算返回的字符串切片）。`first[:j]` 会创建一个长度 j 的新串，那是输出本身的开销，不计入辅助空间。没有递归、没有额外数组。

对比一下：如果写「两两求公共前缀」的横向扫描，时间同样是 O(S)，但常数更大（每个串都要和当前 prefix 从头比）。纵向扫描的早停性质在「第一个串很长、后面串很短」的输入上优势明显。

## 7. 边界与反例（至少 4 条）

1. **`[""]`** → `""`。容易错：以为空串是「没有字符」，其实它是长度为 0 的合法串，公共前缀就是空。代码里 `n = 0`，循环不进入，直接返回 `first = ""`，正确。
2. **`["a"]`** → `"a"`。单元素数组，公共前缀就是它自己。容易错：误以为要「至少两个串才有公共前缀」。
3. **`["ab", "a"]`** → `"a"`。容易错：内层只判断 `s[j] != ch` 而忘了 `j >= len(s)`，会越界或误判。这是本题最经典的坑——**短串提前用完**。
4. **`["", "abc"]`** → `""`。第一个串为空，`n = 0`，直接返回 `""`。容易错：如果以「最短串」为基准但没处理空串，可能进循环后越界。
5. **`["dog","racecar","car"]`** → `""`。第 0 列就分歧，验证早停逻辑。容易错：用 `startswith` 写法时，`prefix` 被截到空串后要正确返回 `""` 而不是继续循环。

## 8. 面试追问与变体（3 条）

1. **追问：如果字符串是流式输入（不能全部存下来），怎么办？**
   思路：维护当前已知的公共前缀 `prefix`，每来一个新串就把它截短到与 `prefix` 的公共前缀；空间 O(答案长度)，时间仍是 O(S)。

2. **追问：改成求「最长公共后缀」？**
   思路：把所有串反转，跑同一套纵向扫描，再把结果反转回来；或者从每个串末尾往前逐列比较。

3. **追问：如果要求「任意两个串之间的最长公共前缀」的最大值（不要求所有串共享）？**
   思路：这是另一道题（最长公共前缀的「两两版」），可用字典树：把所有串插入 Trie，答案就是「某个节点被至少两个串经过」的最大深度；或排序后只比较相邻串（排序后最长公共前缀必出现在相邻对之间）。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 58. 最后一个单词的长度**：共同点是「从边界逐字符扫描、遇分隔即停」，都是线性扫描 + 早停的套路。
2. **LeetCode 28. 找出字符串中第一个匹配项的下标**：共同点是「逐位比较、失配即回退/停止」，是字符串匹配的入门版，理解「比较—失配—移动」的节奏对本题的逐列扫描有直接帮助。
3. **LeetCode 208. 实现 Trie（前缀树）**：共同点是「前缀」这个概念的结构化表达——本题是「所有串共享的最长前缀」，Trie 是「任意前缀的集合」，把本题的纵向扫描理解成「在隐式 Trie 上走一条链」，能自然过渡到 Trie 题。
