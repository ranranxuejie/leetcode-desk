## 1. 一句话本质

把所有在数轴上「有交集」的区间粘成一块，输出这些「连通块」的左右端点。

## 2. 读完题的第一反应

**朴素解法**：拿每个区间去和其余所有区间两两比较，只要 `a.start <= b.end and b.start <= a.end` 就判定重叠、合并，然后重复扫描直到没有变化。问题在于：合并一次后区间集合变了，可能又产生新的重叠，最坏要反复扫很多轮；而且两两比较是 O(n²) 的，n = 10⁴ 时就是 10⁸ 量级的判断，虽然勉强能过，但思路本身没有抓住结构。

**卡在哪**：两两比较之所以低效，是因为「谁和谁可能重叠」这件事完全没有被组织起来。一个区间可能和左边远处的区间重叠，也可能和右边远处的重叠，我们却只能盲目配对。

**关键观察**：如果所有区间**按左端点排好序**，那么「可能重叠」的区间在序列里一定是**相邻的一段**。理由很直接：设排序后第 i 个区间是 `[s_i, e_i]`，第 j 个是 `[s_j, e_j]` 且 i < j，则 `s_i <= s_j`。若 `[s_i, e_i]` 与 `[s_j, e_j]` 重叠，意味着 `s_j <= e_i`；那么夹在中间的任何区间 `[s_k, e_k]`（i < k < j）都满足 `s_k <= s_j <= e_i`，也就是它一定和 `[s_i, e_i]` 重叠。**重叠关系在排序后是「连续」的**，不会跳过中间某个区间去和更远的重叠。这就是从「两两配对」跳到「线性扫描」的转折点。

## 3. 从暴力到最优

**第一步：排序。** 排序本身不解决问题，但它把「任意两个区间是否重叠」的二维关系压成了一维顺序。排序后，我们只需要关心「当前正在合并的区间」和「下一个区间」。

**第二步：一次扫描。** 维护一个结果列表 `merged`，里面存已经合并好的区间。对排序后的每个区间 `[s, e]`：

- 如果 `merged` 为空，或 `s > merged[-1][1]`（当前区间完全在最后一个已合并区间的右边，不重叠），就把它作为新区间追加进去；
- 否则 `s <= merged[-1][1]`，说明有重叠，把 `merged[-1][1]` 更新为 `max(merged[-1][1], e)`。

注意这里为什么用 `max` 而不是直接赋 `e`：因为新区间可能被完全包含在旧区间里，比如 `[1,10]` 后面跟 `[2,3]`，合并后右端点仍是 10。

**走一遍示例 1**：`intervals = [[1,3],[2,6],[8,10],[15,18]]`，已按左端点有序。

| 处理区间 | merged 状态 | 判断 | 动作 |
|---|---|---|---|
| [1,3] | [] | 空 | 追加 → [[1,3]] |
| [2,6] | [[1,3]] | 2 <= 3 重叠 | 右端 max(3,6)=6 → [[1,6]] |
| [8,10] | [[1,6]] | 8 > 6 不重叠 | 追加 → [[1,6],[8,10]] |
| [15,18] | [[1,6],[8,10]] | 15 > 10 不重叠 | 追加 → [[1,6],[8,10],[15,18]] |

**再看示例 3**：`[[4,7],[1,4]]`，排序后变成 `[[1,4],[4,7]]`。处理 `[1,4]` 追加；处理 `[4,7]` 时 `4 <= 4` 判定重叠（题面明确「可被视为重叠」），右端 `max(4,7)=7`，结果 `[[1,7]]`。**排序这一步直接消掉了「输入无序」带来的麻烦**——如果不排序，`[4,7]` 先入结果，再遇到 `[1,4]` 就得回头改，逻辑立刻复杂。

**瓶颈怎么被消掉的**：暴力法的 O(n²) 来自「每个区间都要和所有区间比」。排序后，每个区间只和「当前合并块的右端点」比一次，比较次数从 n² 降到 n。剩下的成本就是排序的 O(n log n)，它成了新的主导项，但比 n² 好得多。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。设排序后的区间为 `I_1, ..., I_n`（按左端点升序）。扫描到第 k 个区间时，维护的不变量是：

> `merged` 恰好是 `I_1..I_k` 这些区间合并后的结果，且 `merged` 内部两两不重叠、按左端点升序。

**基础**：k=0 时 `merged` 为空，成立。

**归纳步**：处理 `I_{k+1} = [s, e]`。由于 `merged` 的最后一个区间 `[L, R]` 的右端点 R 是 `I_1..I_k` 中所有区间右端点的最大值（这是合并规则 `max` 保证的），且 `merged` 中其余区间右端点都小于 L ≤ R。

- 若 `s > R`：`I_{k+1}` 与 `I_1..I_k` 中任何区间都不重叠（因为它们全在 R 左边结束，而 `I_{k+1}` 从 s > R 开始），所以它自成一个新块，追加正确。
- 若 `s <= R`：`I_{k+1}` 与最后一个块 `[L, R]` 重叠，合并成 `[L, max(R,e)]`。它会不会和更前面的块重叠？不会——更前面的块右端点都 < L ≤ s，而 `I_{k+1}` 从 s 开始，碰不到它们。所以只需更新最后一个块，正确。

**为什么不会漏**：上面归纳步已经证明，任何与已有块重叠的区间都会被归入「最后一个块」，因为排序保证了重叠只可能发生在相邻块之间（第 2 节的关键观察）。**为什么不会重**：每次要么追加一个新块（与之前所有块都不重叠），要么只扩展最后一个块而不新增块，所以 `merged` 里永远没有两个块重叠。

## 5. 完整代码（Python）

```python
class Solution:
    def merge(self, intervals):
        # 按左端点升序排序；左端点相同则右端点顺序无所谓，不影响结果
        intervals.sort(key=lambda x: x[0])

        merged = []  # 存放已合并、互不重叠的区间
        for s, e in intervals:
            # 情况一：结果为空，或当前区间与最后一个块不重叠（严格在它右边）
            if not merged or s > merged[-1][1]:
                merged.append([s, e])
            else:
                # 情况二：有重叠，扩展最后一个块的右端点
                # 用 max 是因为当前区间可能被完全包含在最后一个块里
                merged[-1][1] = max(merged[-1][1], e)

        return merged
```

## 6. 复杂度

- **时间 O(n log n)**：`n` 来自区间个数，排序贡献 O(n log n)（Python 的 Timsort，比较的是左端点）；扫描是 O(n)，因为每个区间只被访问一次、每次只做常数次比较和一次可能的 `max`。总时间由排序主导。
- **空间 O(log n) 到 O(n)**：排序本身在 Python 中可能用 O(n) 的临时空间（Timsort 最坏情况）；结果列表 `merged` 最坏存 n 个区间，是 O(n)。若不计输出，额外空间主要是排序开销。注意这里**没有**用递归，所以没有调用栈的额外开销。

## 7. 边界与反例（至少 4 条）

1. **输入 `[[1,4],[4,5]]` → 输出 `[[1,5]]`**。容易错在把「端点相等」判成不重叠（写成 `s >= merged[-1][1]` 就漏合并）。题面示例 2 明确说 `[1,4]` 和 `[4,5]` 可视为重叠，所以判断条件必须是 `s > R` 才不重叠，等号要归入重叠。
2. **输入 `[[1,10],[2,3]]` → 输出 `[[1,10]]`**。容易错在合并时直接写 `merged[-1][1] = e`，把右端点从 10 改成 3，区间被「缩水」。必须用 `max`。
3. **输入 `[[1,2]]`（单区间）→ 输出 `[[1,2]]`**。容易错在循环里对 `merged[-1]` 取值前没判空，`merged` 为空时 `merged[-1]` 直接抛 IndexError。代码里 `not merged or ...` 的短路求值就是为了防这个。
4. **输入 `[[1,2],[3,4],[5,6]]`（全不重叠）→ 输出原样**。容易错在把「相邻但不重叠」误判为重叠，比如把 `[1,2]` 和 `[3,4]` 合并。判断依据是 `3 > 2`，严格大于才不重叠，这里 3 > 2 成立，正确追加。
5. **输入 `[[2,3],[1,2],[4,5]]`（乱序）→ 排序后 `[[1,2],[2,3],[4,5]]` → 输出 `[[1,3],[4,5]]`**。容易错在忘记排序，直接按原顺序扫描，`[2,3]` 先入结果，`[1,2]` 来时发现 `1 <= 3` 却无法正确扩展左端点（左端点应取更小的 1，但代码只更新右端点）。这暴露了「必须先排序」这个前提。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回的区间按右端点排序，或者要求合并后区间个数最少，怎么办？** 思路：本题结果天然按左端点升序，若需按右端点排序，对结果再排一次即可（O(k log k)，k 为结果个数）；「个数最少」在本题语义下就是标准合并，没有额外优化空间，但可以反问面试官是否指「删除最少的区间使剩余不重叠」——那是另一道题（类似 435 题）。
2. **追问：如果区间是动态插入的（流式），每次插入一个区间后要返回当前合并结果？** 思路：用有序结构（如平衡树 / `bisect` 维护有序列表）定位插入位置，向左右两侧扩展合并，单次插入 O(log n + 合并掉的区间数)，均摊仍高效。
3. **追问：如果区间是开区间 `(start, end)`，端点相等不算重叠，代码怎么改？** 思路：只需把判断条件从 `s > merged[-1][1]` 改成 `s >= merged[-1][1]`，其余不变——这正好和第 7 节第 1 条形成对照，说明「端点是否算重叠」完全由这一个比较符决定。

## 9. 举一反三（2-3 道同类题）

1. **57. 插入区间**：和本题共同点是都维护「已合并、互不重叠的区间序列」，只是插入一个新区间后需要局部重合并，扫描逻辑几乎一样。
2. **435. 无重叠区间**：同样先按端点排序再贪心扫描，区别是本题求「合并后的块」，那题求「最多保留多少个不重叠区间」，排序键和贪心选择略有不同。
3. **252. 会议室 / 253. 会议室 II**：都是区间重叠判定问题，252 判断是否存在重叠（排序后看相邻），253 求最大重叠层数（排序 + 扫描线 / 小根堆），和本题共享「排序让重叠关系局部化」这一核心思想。
