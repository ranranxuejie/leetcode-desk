## 1. 一句话本质

在一个「整体有序、但被一刀切成两段后交换了位置」的数组里，用二分查找定位 target 的下标。

## 2. 读完题的第一反应

**朴素解法**：从头到尾扫一遍，`if nums[i] == target: return i`。时间 O(n)，空间 O(1)。它卡在哪？题目明确要求 O(log n)，线性扫描直接不达标。而且数组本身是「升序旋转」的，明明带着很强的有序结构，线性扫描等于把这个结构白白浪费了。

**关键观察**：旋转后的数组有一个非常硬的性质——**从任意位置 mid 把数组劈成两半，至少有一半是严格升序的**。为什么？因为旋转只是把一条上升的直线在一个点折断，折点只有一个。用 mid 去切，折点要么落在左半，要么落在右半，不可能两边都落。所以 `nums[left..mid]` 和 `nums[mid..right]` 里必有一半是「正常升序」的。

这个观察为什么能让你想到下一步？因为二分查找的核心动作是「判断 target 在不在某一半里，然后丢掉另一半」。普通二分靠 `nums[mid] < target` 判断；现在数组整体不有序了，不能直接比。但**只要那一半是升序的，我就能用两个端点判断 target 是否落在它的值域区间内**。于是「判断 target 在哪一半」这件事重新变得可做——二分就能继续走下去。

## 3. 从暴力到最优

**暴力**：O(n) 扫描。瓶颈是「每个元素都要看一次」。

**第一步优化思路**：能不能每次丢掉一半？普通二分能丢，是因为 `nums` 全局有序，`nums[mid]` 和 target 一比就知道方向。现在全局无序，直接比会出错。比如 `nums = [4,5,6,7,0,1,2]`，`target = 0`，`mid = 3` 时 `nums[3] = 7 > 0`，按普通二分该往左走，但答案 0 在右边——直接比就翻车了。

**第二步：利用「必有一半有序」**。还是 `nums = [4,5,6,7,0,1,2]`，`target = 0`，`left = 0, right = 6`。

- 第 1 轮：`mid = 3`，`nums[mid] = 7`。看左半 `nums[0..3] = [4,5,6,7]`，满足 `nums[0] <= nums[3]`（4 ≤ 7），**左半升序**。target = 0 是否落在 `[nums[0], nums[3]] = [4,7]`？不在。所以 target 只可能在右半，`left = mid + 1 = 4`。
- 第 2 轮：`left = 4, right = 6`，`mid = 5`，`nums[5] = 1`。看左半 `nums[4..5] = [0,1]`，`nums[4] <= nums[5]`（0 ≤ 1），**左半升序**。target = 0 是否落在 `[0,1]`？在。`right = mid - 1 = 4`。
- 第 3 轮：`left = 4, right = 4`，`mid = 4`，`nums[4] = 0 == target`，返回 4。

每轮都把区间砍半，瓶颈从「看 n 个」变成「看 log n 个」。

**第三步：把「哪半有序」写成对称的两支**。上面只处理了「左半有序」的情况。如果左半无序，那右半必有序（由第 2 节的性质保证），逻辑完全对称：判断 target 是否落在右半的值域里，在就 `left = mid + 1`，不在就 `right = mid - 1`。两支合起来，就是完整的二分。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来证。维护不变量：

> 若 target 存在于 `nums` 中，则它的下标一定落在闭区间 `[left, right]` 内。

初始时 `left = 0, right = n - 1`，覆盖整个数组，不变量成立。

归纳步：设当前 `mid = (left + right) // 2`。

- 若 `nums[mid] == target`，直接返回，正确。
- 否则分两种情况：
  - **左半升序**（`nums[left] <= nums[mid]`）：因为左半是升序的，target 落在左半当且仅当 `nums[left] <= target < nums[mid]`。若成立，target 只可能在 `[left, mid-1]`，令 `right = mid - 1`；若不成立，target 不可能在左半（左半的值域是 `[nums[left], nums[mid]]`，target 不在其中），只能在 `[mid+1, right]`，令 `left = mid + 1`。两种情况下，被丢弃的那一半都不含 target，不变量保持。
  - **右半升序**（左半不升序，则右半必升序）：对称地，target 落在右半当且仅当 `nums[mid] < target <= nums[right]`。成立则 `left = mid + 1`，否则 `right = mid - 1`。同样只丢弃不含 target 的一半。

**不会漏**：每次丢弃的半边都被值域论证排除了 target，剩下的半边仍含 target（若存在）。
**不会重**：每次 `mid` 被排除在新区间之外（`mid-1` 或 `mid+1`），区间严格缩小，不会重复检查同一元素。
**终止**：区间长度每轮至少减 1（实际减半），`left > right` 时退出，此时不变量说「若存在则在空区间内」，即不存在，返回 -1 正确。

## 5. 完整代码（Python）

```python
class Solution:
    def search(self, nums, target):
        left, right = 0, len(nums) - 1

        while left <= right:
            mid = (left + right) // 2

            if nums[mid] == target:
                return mid

            # 判断哪一半是升序的：比较左端点和中点
            if nums[left] <= nums[mid]:
                # 左半 [left, mid] 升序
                # target 落在左半的值域内，则收缩到左半
                if nums[left] <= target < nums[mid]:
                    right = mid - 1
                else:
                    # 否则 target 只能在右半
                    left = mid + 1
            else:
                # 右半 [mid, right] 升序
                # target 落在右半的值域内，则收缩到右半
                if nums[mid] < target <= nums[right]:
                    left = mid + 1
                else:
                    right = mid - 1

        return -1
```

关键逻辑说明：`nums[left] <= nums[mid]` 用 `<=` 而不是 `<`，是因为 `left == mid` 时左半只有一个元素，也算「升序」，用 `<=` 能正确归入左半分支（此时 `target < nums[mid]` 不成立，会走 `else` 去右半，逻辑仍自洽）。两个内层判断都用**开区间**写法（`target < nums[mid]`、`nums[mid] < target`），因为 `nums[mid] == target` 已经在前面返回了，这里排除等号能少一次边界纠结。

## 6. 复杂度

- **时间 O(log n)**：`while` 循环每轮把 `[left, right]` 的长度砍半，从 n 缩到 1 需要 log₂n 轮，每轮内部只做常数次比较和赋值。log n 来自「区间长度每次减半」。
- **空间 O(1)**：只用了 `left, right, mid` 三个整型变量，没有递归、没有额外数组。n 不贡献任何空间。

## 7. 边界与反例（至少 4 条）

1. **`nums = [1], target = 0`** → 期望 `-1`。容易错在：`left = right = 0`，`mid = 0`，`nums[0] != 0`，然后进 `nums[left] <= nums[mid]`（1 ≤ 1 成立）走左半分支，`target < nums[mid]` 即 `0 < 1` 成立但 `nums[left] <= target` 即 `1 <= 0` 不成立，整体条件为假，走 `left = mid + 1 = 1`，循环退出返回 -1。若把内层条件写成 `nums[left] <= target <= nums[mid]` 而漏了开区间，这里仍对，但下面第 2 条会暴露问题。

2. **`nums = [3,1], target = 1`** → 期望 `1`。容易错在：`mid = 0`，`nums[0] = 3 != 1`，`nums[left] <= nums[mid]`（3 ≤ 3）成立，走左半分支，`nums[left] <= target < nums[mid]` 即 `3 <= 1 < 3` 为假，走 `left = mid + 1 = 1`；下一轮 `mid = 1`，`nums[1] == 1` 返回 1。如果误把「左半升序」判断写成 `nums[left] < nums[mid]`，这里 3 < 3 为假，会误判右半升序，进而用 `nums[mid] < target <= nums[right]` 即 `3 < 1 <= 1` 为假，走 `right = mid - 1 = -1`，直接漏掉答案。

3. **`nums = [4,5,6,7,0,1,2], target = 3`** → 期望 `-1`。容易错在：target 比所有元素都「夹在中间」，既不在左半值域也不在右半值域，每轮都走 `else` 收缩，最后 `left > right` 退出。如果内层判断用了闭区间 `nums[left] <= target <= nums[mid]`，当 target 恰好等于某个端点时可能多走一步，但本题 target=3 不在任何端点，主要考「不在任何值域内时能否正确退出」。

4. **`nums = [5,1,3], target = 5`** → 期望 `0`。容易错在：`mid = 1`，`nums[1] = 1 != 5`，`nums[0] <= nums[1]`（5 ≤ 1）为假，判定右半升序，`nums[1] < target <= nums[2]` 即 `1 < 5 <= 3` 为假，走 `right = mid - 1 = 0`；下一轮 `mid = 0`，`nums[0] == 5` 返回 0。若把「右半升序」的值域判断写成 `nums[mid] <= target <= nums[right]`（带等号），`1 <= 5 <= 3` 仍为假，结果不变，但若 target 恰好等于 `nums[mid]` 已被前面拦截，等号是冗余的，写错成 `nums[mid] < target < nums[right]` 则会在 target 等于 `nums[right]` 时漏判。

5. **`nums = [1,3], target = 3`** → 期望 `1`。容易错在：`mid = 0`，`nums[0] = 1 != 3`，左半升序（1 ≤ 1），`1 <= 3 < 1` 为假，`left = 1`；`mid = 1`，命中返回 1。若把外层 `while left <= right` 写成 `while left < right`，长度为 2 时可能提前退出漏掉。

## 8. 面试追问与变体（3 条）

1. **追问：如果数组里有重复元素怎么办？**（对应力扣 81 题）思路：当 `nums[left] == nums[mid] == nums[right]` 时无法判断哪半有序，只能 `left += 1, right -= 1` 缩小范围，最坏退化到 O(n)，但平均仍是 O(log n)。

2. **追问：不返回下标，返回 target 在旋转数组中的「插入位置」怎么做？** 思路：先二分找到旋转点（最小值下标），把下标映射回「未旋转」的虚拟有序数组，再在虚拟数组上做标准二分，最后映射回原下标。

3. **追问：如果旋转了多次（即数组被切成多段各自升序）呢？** 思路：本题性质依赖「只有一个折点」，多折点后「必有一半有序」不再成立，二分失效，需要先找所有折点或改用其他结构（如分块 + 二分），复杂度不再是 O(log n)。

## 9. 举一反三（2-3 道同类题）

- **力扣 81. 搜索旋转排序数组 II**：和本题共同点是「旋转数组 + 二分」，区别是允许重复元素，需要处理 `nums[left] == nums[mid] == nums[right]` 的退化情况。
- **力扣 153. 寻找旋转排序数组中的最小值**：和本题共同点是「利用必有一半有序的性质做二分」，区别是目标从「找 target」变成「找折点」，判断条件改为比较 `nums[mid]` 与 `nums[right]`。
- **力扣 34. 在排序数组中查找元素的第一个和最后一个位置**：和本题共同点是「二分 + 边界处理」，区别是数组全局有序，但需要写两次二分分别找左右边界，训练的是「二分收缩方向」的精细控制。
