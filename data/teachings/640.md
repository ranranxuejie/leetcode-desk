## 1. 一句话本质

把方程两边各自化简成 `a*x + b` 的形式，再解一个一元一次方程 `(a左-a右)*x = (b右-b左)`，最后按系数是否为 0 分类讨论解的三种情况。

## 2. 读完题的第一反应

**朴素解法**：把方程当成字符串，想办法"移项"——把含 x 的项挪到左边、常数挪到右边，再合并。但字符串层面做移项极其别扭：你得判断每一项原来在哪边、移过去要变号，还要处理 `x` 前面没写系数（其实是 1）、`-x`（系数是 -1）、`+x`、`-x` 这些省略写法。卡点不在算法复杂度（长度才 1000），而在于**字符串解析的边界太多，容易写乱**。

**关键观察**：一元一次方程的本质是"两边都是 `a*x + b`"。既然两边结构一样，就没必要真的去"移项"——只要**分别扫描左右两半，各自统计出 x 的系数和常数**，最后做一次减法就等价于移项了。这个观察把"字符串操作问题"降维成"两个独立的累加问题"，每个累加只需要一个带符号的扫描指针。

为什么这个观察能直接指向下一步？因为一旦你决定"分别统计 (系数, 常数)"，剩下的问题就只剩一个：**怎么把 `"x+5-3+x"` 这种串切成一堆带符号的项**。而切分规则非常统一——遇到 `+`/`-` 就是新项的开始，项要么以 `x` 结尾（系数项），要么是纯数字（常数项）。规则统一，代码就短。

## 3. 从暴力到最优

**暴力思路**：用正则或 `split` 把整个方程按 `+`/`-` 切开，再逐项判断。问题在于 `split` 会丢掉符号信息，你得回头再找每个分隔符是什么，反而更绕；而且 `-x` 这种项切出来是空串加 `x`，要特判。

**改进**：不用 `split`，用**一次线性扫描 + 当前符号变量 `sign`**。核心是维护三个东西：`coef`（x 的累计系数）、`const`（常数累计）、`num`（正在读的数字缓冲区）。扫描到字符时：

- 数字 → 累进 `num`
- `x` → 说明刚读的是一个系数项，系数是 `num`（若 `num` 为空则视为 1），累加 `sign * coef_of_x`，清空 `num`
- `+` / `-` → 说明前面攒的是一个常数项（如果 `num` 非空），累加 `sign * num`，然后更新 `sign`，清空 `num`
- `=` → 把左边结果存起来，重置 `coef/const/sign/num` 开始算右边

**小例子走一遍**：`"x+5-3+x=6+x-2"`，先算左边 `"x+5-3+x"`：

| 字符 | sign | num | coef | const | 动作 |
|---|---|---|---|---|---|
| `x` | +1 | 空 | 1 | 0 | num 空→系数 1，coef += 1 |
| `+` | +1 | 空 | 1 | 0 | num 空，跳过；sign=+1 |
| `5` | +1 | 5 | 1 | 0 | 读数字 |
| `-` | +1 | 5 | 1 | 5 | const += 5；sign=-1；num 清空 |
| `3` | -1 | 3 | 1 | 5 | 读数字 |
| `+` | -1 | 3 | 1 | 2 | const += -3；sign=+1；num 清空 |
| `x` | +1 | 空 | 2 | 2 | 系数 1，coef += 1 |

左边得 `coef=2, const=2`，即 `2x+2`。右边 `"6+x-2"` 同理得 `coef=1, const=4`，即 `x+4`。

方程 `2x+2 = x+4` → 移项 `(2-1)x = 4-2` → `x = 2`。和示例一致。

**瓶颈怎么被消掉的**：原本"移项"需要知道每项在哪边、要不要变号，现在因为两边独立统计，变号被压缩成最后一步的 `a = coefL - coefR`、`b = constR - constL`，中间过程完全对称，不需要任何方向判断。复杂度从"字符串操作的不确定性"变成"一次 O(n) 扫描"。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义扫描过程中的不变量：

> 扫描到位置 `i` 时，`coef` 恰好等于已处理前缀中所有 x 项系数之和，`const` 恰好等于已处理前缀中所有常数项之和，`num` 是当前尚未结算的数字。

逐字符验证这个不变量在每一步都保持：

- 读数字：`num` 更新，`coef/const` 不变，前缀的"已结算部分"没变，不变量成立。
- 读 `x`：此时 `num` 是这一项的系数（空则 1），把它乘 `sign` 加进 `coef`，这一项被"结算"，前缀扩大且和正确，不变量成立。
- 读 `+`/`-`：若 `num` 非空，说明刚结束一个常数项，乘 `sign` 加进 `const` 后结算；`sign` 切换为下一项的符号。前缀和正确，不变量成立。
- 读 `=`：左边已全部结算（`num` 必为空，因为 `=` 前不会悬空数字），保存 `coef/const` 后重置，开始右边，不变量对右边重新成立。

**不漏**：每个字符恰好被处理一次，每个项在遇到它的终止符（`x` 或 `+`/`-`/`=`）时被结算，没有项被跳过。**不重**：结算后 `num` 清空，同一项不会被二次累加。扫描结束时若 `num` 非空（方程以数字结尾），补一次结算，保证最后一项不漏。

最后解方程 `a*x = b` 时按 `a` 是否为 0 分类：`a≠0` 唯一解 `b/a`；`a=0 且 b=0` 无限解；`a=0 且 b≠0` 无解。这三类互斥且穷尽，所以结论不会错。

## 5. 完整代码（Python）

```python
class Solution:
    def solveEquation(self, equation: str) -> str:
        # 解析一段表达式（不含 '='），返回 (x的系数, 常数)
        def parse(expr: str):
            coef = 0      # x 的累计系数
            const = 0     # 常数累计
            num = 0       # 正在读的数字
            has_num = False  # num 是否有效（区分"没读到数字"和"读到 0"）
            sign = 1      # 当前项的符号
            for ch in expr:
                if ch.isdigit():
                    num = num * 10 + int(ch)
                    has_num = True
                elif ch == 'x':
                    # 系数项：num 为空说明系数是 1（如 "x"、"-x"）
                    c = num if has_num else 1
                    coef += sign * c
                    num = 0
                    has_num = False
                else:  # ch 是 '+' 或 '-'
                    # 先结算前面可能攒着的常数项
                    if has_num:
                        const += sign * num
                        num = 0
                        has_num = False
                    sign = 1 if ch == '+' else -1
            # 表达式以数字结尾时，补结算最后一项
            if has_num:
                const += sign * num
            return coef, const

        left, right = equation.split('=')   # 题面保证只有一个 '='
        cl, bl = parse(left)
        cr, br = parse(right)

        # 移项：cl*x + bl = cr*x + br  =>  (cl-cr)*x = br-bl
        a = cl - cr
        b = br - bl

        if a == 0:
            return "Infinite solutions" if b == 0 else "No solution"
        # 题面保证唯一解时 x 为整数，直接整除
        return "x=" + str(b // a)
```

## 6. 复杂度

- **时间 O(n)**：`n` 是方程字符串长度。`parse` 对左右两段各扫一遍，每个字符 O(1) 处理，总字符数就是 `n`，所以是 O(n)。`split('=')` 也是 O(n)。没有排序、没有嵌套循环，所以没有 log 项。
- **空间 O(n)**：`equation.split('=')` 会生成两个子串，最坏情况长度和原串同阶，占 O(n)。除此之外只有常数个变量。若把 `split` 改成手动定位 `=` 下标、用切片传参，切片本身仍是 O(n) 拷贝；想做到 O(1) 额外空间可以传下标区间，但对本题长度 1000 完全没必要。

## 7. 边界与反例（至少 4 条）

1. **`"x=x"` → `"Infinite solutions"`**。容易错在：`a = 1-1 = 0`、`b = 0-0 = 0`，若只判断 `a==0` 就返回无解，会漏掉无限解这一支。必须先判 `b` 再判 `a`。
2. **`"2x=x"` → `"x=0"`**。容易错在：`a = 1`、`b = 0`，结果 `0//1 = 0` 正确；但如果代码写成 `if b == 0: return "Infinite"` 就错了——`b=0` 不代表无限解，要看 `a`。另外 `b // a` 对负数整除在 Python 里是向下取整，本题保证唯一解为整数所以安全，但若题目放宽需改用 `int(b/a)` 或先判整除。
3. **`"x+1=2x+2"` → `"No solution"`**（`a=-1, b=1`，`x=-1`？注意：`-1*x = 1` 得 `x=-1`，其实有解）。真正无解的例子是 `"x+1=x+2"` → `a=0, b=1` → `"No solution"`。容易错在：把 `a=0` 一律当无限解，忘了 `b≠0` 时是无解。
4. **`"-x=-1"` → `"x=1"`**。容易错在：`-x` 的系数是 -1，若代码把"`x` 前无数字"一律当 +1，会算成 `x=-1`。必须让 `sign` 参与系数计算。
5. **`"0x=0"` → `"Infinite solutions"`**。容易错在：`0x` 的系数是 0，若把 `0x` 误判成系数 1（因为"有 x"），会得到 `a=1` 而错判唯一解。`has_num` 标志要能区分"读到 0"和"没读到数字"。

## 8. 面试追问与变体（3 条）

1. **追问：如果方程里出现乘除或括号怎么办？** 思路：那就不是一元一次了，需要先做表达式解析（递归下降或栈），本题的"两边独立统计"思路只在纯加减、无括号时成立；有括号要先展开或建表达式树。
2. **追问：如果解不是整数，要求返回分数形式 `"x=3/2"` 怎么办？** 思路：用 `math.gcd` 约分 `b/a`，处理负号和 `a<0` 时把符号挪到分子，输出 `f"x={b//g}/{a//g}"`。
3. **追问：如何把空间做到 O(1)（不 split）？** 思路：先 `find('=')` 拿到下标，`parse` 改成接收 `(s, l, r)` 区间参数，扫描时只读不切片，额外空间就是常数。
