## 1. 一句话本质

把每个节点的 `next` 指针从「指向后一个」改成「指向前一个」，最后把新的头节点（原链表的尾节点）返回出去。

## 2. 读完题的第一反应

**朴素解法**：把链表所有值读进一个 Python 列表，`reverse()` 之后再新建一条链表返回。这能过，但它卡在两个地方：一是空间 O(n)，题目虽然没禁止，但面试官问「能不能原地做」你就哑了；二是它根本没在操作指针，而这道题的全部考点就是指针操作。

**关键观察**：链表反转之所以看起来难，是因为你顺着 `next` 往前走的时候，一旦把当前节点的 `next` 改掉，就找不到「后面还没处理的部分」了。所以真正的问题不是「怎么改指针」，而是「改指针之前，怎么把后路留好」。这个观察直接推出迭代法的骨架：**用三个变量分别记住「前一个」「当前」「后一个」**，改完当前节点的指针后，整体往后挪一格。

递归的观察角度不同：如果 `head.next` 之后的那段已经反转好了，那么我要做的只是把 `head.next` 这个节点重新指回 `head`，再把 `head` 的 `next` 置空。也就是「先相信子问题已解决，再补上最后一步」。

## 3. 从暴力到最优

**暴力**：读值 → 反转列表 → 重建链表。时间 O(n)，空间 O(n)。瓶颈是空间，而且完全没练到指针。

**迭代（原地）**：空间降到 O(1)。核心是三个指针 `prev / cur / nxt`。

拿 `1 → 2 → 3 → None` 走一遍，初始 `prev = None, cur = 1`：

| 轮次 | 进入时 cur | nxt = cur.next | cur.next = prev | prev, cur 更新后 |
|---|---|---|---|---|
| 1 | 1 | 2 | 1.next = None | prev=1, cur=2 |
| 2 | 2 | 3 | 2.next = 1 | prev=2, cur=3 |
| 3 | 3 | None | 3.next = 2 | prev=3, cur=None |

循环结束时 `cur` 为 `None`，`prev = 3`，正好是新头，返回 `prev`。注意 `nxt` 必须在改 `cur.next` **之前**取，否则后路就断了——这就是第 2 节那个观察的落地。

**递归**：时间同样 O(n)，空间 O(n)（递归栈）。写法上先递归到尾部拿到新头 `new_head`，回溯时做两件事：`head.next.next = head`（让后一个节点指回来），`head.next = None`（断开原来的正向指针）。以 `1 → 2 → 3` 为例，递归到 `3` 返回 `3`；回到 `2` 这一层，执行 `2.next.next = 2` 即 `3.next = 2`，再 `2.next = None`；回到 `1` 这一层，执行 `2.next = 1`、`1.next = None`。最终 `3 → 2 → 1 → None`。

两种写法复杂度只差在空间，面试时先写迭代（更稳、不爆栈），再补递归展示思路。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**说清楚。迭代法在每轮循环开始时，维持这个不变量：

> `prev` 是以原链表第 1 到第 k-1 个节点为素材、已经反转好的那段的头；`cur` 是原链表第 k 个节点，也就是尚未处理部分的头；并且 `prev` 这段的尾节点（原第 1 个节点）的 `next` 为 `None`，与 `cur` 这段完全断开。

三条性质逐一验证：

- **初始化**：k=1 时 `prev = None`，空段反转后仍是空，成立。
- **保持**：一轮里先存 `nxt = cur.next`（保住未处理部分），再令 `cur.next = prev`（把 `cur` 接到已反转段前面），然后 `prev = cur, cur = nxt`。此时 `prev` 覆盖了前 k 个节点且顺序正确，`cur` 指向第 k+1 个，不变量继续成立。
- **终止**：`cur == None` 时未处理部分为空，`prev` 覆盖全部 n 个节点且顺序反转，正是所求。

**不会漏**：每个节点在它作为 `cur` 的那一轮恰好被处理一次，`nxt` 保证了后续节点在改指针后仍可达。
**不会重**：`cur.next` 被改写后，该节点就脱离了未处理段，不会再被当作 `cur` 访问第二次。

递归的正确性用**数学归纳法**：设 `reverseList` 对长度 ≤ n-1 的链表正确。对长度 n 的链表，`reverseList(head.next)` 返回长度 n-1 的反转链表且其尾是 `head.next`；执行 `head.next.next = head` 把 `head` 接到尾部，`head.next = None` 保证不成环，得到长度 n 的正确反转。基例 `head is None or head.next is None` 直接返回 `head`，成立。

## 5. 完整代码（Python）

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def reverseList(self, head: ListNode) -> ListNode:
        # 迭代法：三指针原地反转，空间 O(1)
        prev = None          # 已反转段的头，初始为空段
        cur = head           # 未处理段的头
        while cur is not None:
            nxt = cur.next   # 先存后路，否则改完指针就找不到后面了
            cur.next = prev  # 当前节点指回前一个，完成"反转"这一步
            prev = cur       # 已反转段扩张一格
            cur = nxt        # 未处理段前移一格
        return prev          # cur 为空时，prev 就是新头

    def reverseListRecursive(self, head: ListNode) -> ListNode:
        # 递归法：先反转 head.next 之后的部分，回溯时补最后一根指针
        if head is None or head.next is None:
            return head                      # 空表或单节点，本身就是反转结果
        new_head = self.reverseListRecursive(head.next)
        head.next.next = head                # 让后一个节点指回来
        head.next = None                     # 断开正向指针，防止成环
        return new_head                      # 新头始终是原尾节点
```

## 6. 复杂度

**时间 O(n)**：迭代法循环体执行 n 次，每次常数次指针赋值，n 来自链表节点数。递归法每个节点进入一次函数、回溯时做两次赋值，也是 n 次，n 同样来自节点数。这里没有 log n 的项——链表是线性结构，不存在折半。

**空间**：迭代法 O(1)，只用了 `prev / cur / nxt` 三个指针，与 n 无关。递归法 O(n)，n 来自递归调用栈的深度（最坏情况链表不带头、一路递归到底），这是递归相对迭代唯一多出来的开销。题目节点数上限 5000，Python 默认递归深度约 1000，**递归写法在极端用例上会 RecursionError**，这也是我建议面试先写迭代的实际原因。

## 7. 边界与反例（至少 4 条）

1. `head = []` → 返回 `None` → 容易错在没判空就访问 `head.next`，直接 AttributeError。迭代法天然安全（`while cur` 不进入），递归法靠基例 `head is None` 兜住。
2. `head = [1]` → 返回 `[1]` → 容易错在递归基例只写了 `head is None`，漏了 `head.next is None`，导致对单节点继续递归并在 `head.next.next` 处崩。
3. `head = [1,2]` → 返回 `[2,1]` → 容易错在迭代时先改 `cur.next` 再取 `nxt`，后路断掉，`nxt` 拿到的是已改过的值，结果只剩一个节点。
4. `head = [1,2,3]` 用递归 → 返回 `[3,2,1]` → 容易错在忘了 `head.next = None`，原头节点仍指向第二个节点，形成 `1 ↔ 2` 的环，判题器输出超时或死循环。
5. 节点值有负数（题面提示范围含负）→ 输出顺序正确即可 → 容易错在把「反转链表」误解成「按值排序」或「只反转正数部分」，值本身不参与任何逻辑。

## 8. 面试追问与变体（3 条）

1. **「只反转区间 [m, n] 的部分」**（对应题 92）→ 思路：用 dummy 节点定位到第 m-1 个节点，对区间内做 m 到 n 次「头插」，把区间内节点逐个挪到区间头部。
2. **「每 k 个一组反转，不足 k 个保持原序」**（对应题 25）→ 思路：先数够 k 个再反转这一段，反转后把上一段的尾接到新头、新尾接到下一段头，递归或迭代推进。
3. **「不用额外变量、只用一个指针反转」** → 思路：把 `cur.next` 指向 `prev` 之前，用 `cur.next` 暂存后路再回填，本质是把三指针压成两指针的技巧，考察对指针时序的理解。
