## 1. 一句话本质

在「每步能跳多远由当前下标决定」的约束下，求从下标 0 走到下标 n-1 的**最少步数**——注意求的是步数，不是路径，也不是最大距离。

## 2. 读完题的第一反应

**朴素解法**：把每个下标看成一个节点，`i` 能连到 `i+1 ... i+nums[i]`，这就是一张有向图，求 0 到 n-1 的最短路。BFS 一遍即可，每个节点出队时枚举它能到的所有下标。复杂度 O(n²)（最坏每个点都往后看 n 个），n ≤ 10⁴ 时 10⁸ 量级，勉强能过但很悬，而且完全没利用「区间连续」这个结构。

**关键观察**：`i` 能到达的不是任意集合，而是**一段连续区间** `[i+1, i+nums[i]]`。既然每步的落点是一段区间，那么「跳 k 步能覆盖到的所有下标」也必然是一段连续区间——因为从区间里每个点出发的落点区间会首尾相接。于是问题变成：**从区间 [0,0] 出发，每轮把区间右端点尽量往右推，推几次能盖住 n-1**。这个「区间右端点」就是唯一需要维护的状态，一下子把 O(n²) 的枚举压成了 O(n) 的扫描。

## 3. 从暴力到最优

**暴力（BFS 分层）**：第 0 层是 {0}，第 1 层是 0 能到的所有下标，第 2 层是第 1 层所有下标能到的并集……每层扫一遍全数组，层数最多 n，总 O(n²)。

**瓶颈在哪**：每一层都要重新枚举「这一层所有点」的出边，而相邻两层的点大量重叠、区间也大量重叠，做了重复功。

**消掉瓶颈的办法**：不记录「这一层有哪些点」，只记录**这一层能到达的最右下标 `cur_end`**，以及**下一层能到达的最右下标 `next_end`**。扫描时每遇到一个下标 `i`，就用 `i + nums[i]` 去更新 `next_end`；当 `i` 走到 `cur_end` 时，说明当前这一层的「弹药」用完了，必须再跳一步，于是 `steps += 1`、`cur_end = next_end`。

**小例子走一遍** `nums = [2,3,1,1,4]`：

| i | nums[i] | i+nums[i] | next_end | cur_end | steps | 说明 |
|---|---|---|---|---|---|---|
| 0 | 2 | 2 | 2 | 0 | 0 | 初始化 next_end=0, cur_end=0 |
| 0 | 2 | 2 | 2 | 0 | 1 | i==cur_end，跳一步，cur_end=2 |
| 1 | 3 | 4 | 4 | 2 | 1 | 更新 next_end=4 |
| 2 | 1 | 3 | 4 | 2 | 2 | i==cur_end，跳一步，cur_end=4，已覆盖 n-1=4，返回 2 |

关键点：**在 `i` 从 `cur_end` 之前的所有位置里，我们都在为「下一步」攒最远距离**，而不是真的决定跳去哪。这正是贪心的精髓——不选具体落点，只选「下一步能到的最远处」。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。设第 k 轮结束时 `cur_end = R_k`，含义是：**用 k 步能到达的所有下标恰好构成区间 [0, R_k]**（因为每步落点是连续区间，区间并仍是区间，且从 0 出发必然覆盖前缀）。

- **不会漏**：归纳假设第 k 步能到 [0, R_k]。第 k+1 步能到的集合 = ∪_{i∈[0,R_k]} [i+1, i+nums[i]]，其右端点 = max_{i≤R_k}(i+nums[i])，正是我们扫描 [0, R_k] 时维护的 `next_end`。所以 R_{k+1} = next_end，一个不漏。
- **不会重（即步数最少）**：若存在更少步数 t < k 到达 n-1，则 n-1 ≤ R_t < R_k，与「k 是首次覆盖 n-1 的轮数」矛盾。因为我们每轮都把右端点推到**理论最大值**，任何方案在第 k 步能到的最远处都不会超过 R_k，所以 R_k 是 k 步可达的**上界且可达**，首次覆盖 n-1 的 k 就是最小步数。

一句话：**每轮取「当前可达区间内所有点能跳到的最远点」，是 k 步可达范围的精确刻画，不是近似**。

## 5. 完整代码（Python）

```python
class Solution:
    def jump(self, nums: list[int]) -> int:
        n = len(nums)
        if n == 1:
            return 0  # 已在终点，0 步

        steps = 0        # 已经跳的步数
        cur_end = 0      # 当前 steps 步能到达的最右下标
        next_end = 0     # steps+1 步能到达的最右下标（扫描中不断更新）

        for i in range(n - 1):          # 注意只扫到 n-2，扫到 n-1 会多算一步
            # 站在 i 上，为「下一步」攒最远距离
            next_end = max(next_end, i + nums[i])

            if i == cur_end:            # 当前步数的覆盖区间用完了
                steps += 1              # 必须再跳一步
                cur_end = next_end      # 进入下一层覆盖区间
                if cur_end >= n - 1:    # 已能覆盖终点，提前结束
                    break

        return steps
```

两个容易写错的细节：`range(n-1)` 而不是 `range(n)`——因为当 `i` 走到 `n-1` 时已经到终点了，再触发一次 `steps += 1` 会多算；`if cur_end >= n-1: break` 是提前退出，不写也对（循环自然结束），但写了更清晰。

## 6. 复杂度

- **时间 O(n)**：`for` 循环最多执行 n-1 次，循环体内是常数次比较和赋值。没有嵌套循环——这正是相对 BFS 的 O(n²) 省下来的地方：每个下标只被「看一眼」，不重复枚举出边。
- **空间 O(1)**：只用了 `steps`、`cur_end`、`next_end` 三个整型变量，与 n 无关。没有队列、没有 visited 数组。

对比一下：BFS 解法时间 O(n²)、空间 O(n)（队列 + visited）；本题贪心把两者都降了一档。

## 7. 边界与反例（至少 4 条）

1. **`nums = [0]`** → 期望 `0`。容易错：不特判 `n == 1` 时，循环 `range(0)` 不执行，返回 0 其实也对；但如果写成 `range(n)` 且没提前 break，会在 i=0 时 `i==cur_end` 触发 `steps=1`，错答 1。所以 `n==1` 的早返回或 `range(n-1)` 必须有一个。
2. **`nums = [1,1,1,1]`** → 期望 `3`。容易错：每步只能前进 1，必须老老实实跳 3 次；若误以为「能跳就跳最远」而跳过中间更新，可能算成 1 步。
3. **`nums = [2,3,0,1,4]`** → 期望 `2`。容易错：下标 2 是 0，站上去就动不了，但它仍在第 1 步的覆盖区间内，不影响 `next_end`（由下标 1 的 3 贡献到 4）。若实现里「遇到 0 就跳过整段」会漏掉正确路径。
4. **`nums = [1,2,3]`** → 期望 `2`。容易错：从 0 只能到 1，从 1 能到 3（下标 2），共 2 步；若贪心地「从 0 直接看最远」会以为 1 步能到，实际 0 的 nums[0]=1 只够到下标 1。
5. **`nums = [5,0,0,0,0,0]`**（n=6）→ 期望 `1`。容易错：一步从 0 跳到 5，`next_end` 一次就 ≥ n-1，必须能正确返回 1 而不是 2。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求输出具体跳跃路径（每一步落在哪）？** 思路：在贪心扫描时额外记录「每个 `cur_end` 是被哪个下标 `i` 推到的」，即记录 `next_end` 的来源下标，最后从终点回溯。
2. **追问：如果 nums[i] 表示「必须恰好跳 nums[i] 步」而不是「最多」？** 思路：问题性质变了，可能无解；用 BFS/DP 判断可达性，`dp[i]` 表示到 i 的最小步数，转移 `dp[i+nums[i]] = min(dp[i+nums[i]], dp[i]+1)`，注意可能成环需判重。
3. **追问：如果允许「往回跳」呢？** 思路：区间单调性被破坏，贪心失效，退化为图上的最短路（BFS），复杂度回到 O(n²) 或需更精细的建模。
