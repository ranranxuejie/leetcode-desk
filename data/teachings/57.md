## 1. 一句话本质

在**已排好序且互不重叠**的区间序列里，把新区间"塞"进去，凡是和它沾边的旧区间全部吸收合并成一个更大的区间，其余原样保留。

## 2. 读完题的第一反应

**朴素解法**：把 `newInterval` 直接 append 到 `intervals` 末尾，然后对整个列表按起点排序，再跑一遍"合并区间"（LeetCode 56 的套路：遍历、若当前区间起点 ≤ 上一个区间终点就合并）。

这个解法**是对的**，但卡在两点：

- 排序要 O(n log n)。而题面明确说 `intervals` 已经按 `start_i` 升序排好了——这个"已排序"是白送的信息，排序等于把送来的礼物又扔了。
- 合并要扫全表 O(n)，但真正会被 `newInterval` 影响的只是**中间一小段连续区间**，两头的区间根本不可能变。

**关键观察**：因为原列表有序且不重叠，`newInterval` 和旧区间的关系只可能有三种，而且这三种在列表上是**按位置连续分布**的：

1. 完全在 `newInterval` 左边（`end < newStart`）——原样保留；
2. 和 `newInterval` 有交集（`start <= newEnd` 且 `end >= newStart`）——要合并；
3. 完全在 `newInterval` 右边（`start > newEnd`）——原样保留。

也就是说，整个列表被切成"左段 / 中段 / 右段"三块，中段是连续的一段。这个"三段式"结构就是 O(n) 一次扫描的全部依据。

## 3. 从暴力到最优

**暴力**：append + 排序 + 合并，O(n log n) 时间、O(n) 空间。

**瓶颈在哪**：排序那一步。但排序之所以需要，是因为我们破坏了"有序"这个前提（append 到末尾）。如果**不破坏**它，排序就完全不需要。

**怎么不破坏**：不要 append，而是边扫描边决定每个旧区间归到哪一段。用一个具体例子走一遍：

```
intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]]
newInterval = [4,8]
```

初始化：`res = []`，`newStart = 4`，`newEnd = 8`，指针 `i = 0`。

**第一段（左段）**：只要 `intervals[i][1] < newStart`，就是完全在左边。

- `i=0`：`[1,2]`，`2 < 4` ✓ → 放入 `res`，`res = [[1,2]]`，`i=1`
- `i=1`：`[3,5]`，`5 < 4`？否 → 左段结束

**第二段（合并段）**：只要 `intervals[i][0] <= newEnd`，就说明有交集，把它的范围吸收进 `newInterval`。

- `i=1`：`[3,5]`，`3 <= 8` ✓ → `newStart = min(4,3) = 3`，`newEnd = max(8,5) = 8`，`i=2`
- `i=2`：`[6,7]`，`6 <= 8` ✓ → `newStart = min(3,6) = 3`，`newEnd = max(8,7) = 8`，`i=3`
- `i=3`：`[8,10]`，`8 <= 8` ✓ → `newStart = min(3,8) = 3`，`newEnd = max(8,10) = 10`，`i=4`
- `i=4`：`[12,16]`，`12 <= 10`？否 → 合并段结束

此时把膨胀后的 `newInterval = [3,10]` 放入 `res`，`res = [[1,2],[3,10]]`。

**第三段（右段）**：剩下的全部原样放入。

- `i=4`：`[12,16]` → `res = [[1,2],[3,10],[12,16]]`

结果 `[[1,2],[3,10],[12,16]]`，和示例 2 一致。

注意 `[8,10]` 这个细节：`8 <= 8` 成立，说明"共享端点也算重叠"（题面原话"至少共享一个点"），所以它必须被吸收。这是最容易写错的地方之一。

**瓶颈怎么被消掉的**：每个区间只被访问一次，且只做 O(1) 的 min/max 比较，排序这一步彻底消失，O(n log n) → O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。维护三个不变量：

**不变量 A（左段已定）**：进入合并段之前，`res` 里的每个区间都满足 `end < newStart`，且它们和 `newInterval` 无交集。因为左段的判定条件就是 `intervals[i][1] < newStart`，而原列表有序不重叠，所以这些区间既不会被 `newInterval` 影响，也不会和后面的合并结果重叠（合并结果的起点 ≥ `newStart` > 它们的终点）。

**不变量 B（合并段完整）**：合并段循环的退出条件是 `intervals[i][0] > newEnd`。由于原列表按起点升序，一旦某个区间起点超过当前 `newEnd`，它后面的所有区间起点只会更大，都不可能再和 `[newStart, newEnd]` 有交集。所以退出时，**所有**与 `newInterval` 有交集的区间都已被吸收，一个不漏。同时，每次吸收都取 `min`/`max`，保证合并后的区间恰好覆盖所有被吸收区间的并集，不多不少。

**不变量 C（右段无交集）**：右段区间起点 > 合并后的 `newEnd`，且原列表有序，所以它们和合并结果、和彼此都不重叠，原样保留即可。

三个不变量合起来：左段、合并结果、右段三者按起点严格递增且两两不重叠，覆盖了原列表的全部区间加上 `newInterval`，且没有重复放入任何区间（每个 `i` 只被一个段消费一次）。因此输出恰好是"插入并合并"的唯一正确结果。

## 5. 完整代码（Python）

```python
class Solution:
    def insert(self, intervals, newInterval):
        res = []
        i = 0
        n = len(intervals)
        newStart, newEnd = newInterval[0], newInterval[1]

        # 第一段：所有完全在 newInterval 左边的区间，原样保留
        # 判定：旧区间终点 < 新区间起点，说明它整个在左边
        while i < n and intervals[i][1] < newStart:
            res.append(intervals[i])
            i += 1

        # 第二段：所有与 newInterval 有交集的区间，吸收进 newInterval
        # 判定：旧区间起点 <= 当前 newEnd（注意是 <=，共享端点也算重叠）
        # 每吸收一个，newStart/newEnd 会向外扩张，可能连锁吸收更多
        while i < n and intervals[i][0] <= newEnd:
            newStart = min(newStart, intervals[i][0])
            newEnd = max(newEnd, intervals[i][1])
            i += 1
        # 合并完成，把膨胀后的新区间放入结果
        res.append([newStart, newEnd])

        # 第三段：剩下的区间起点都 > newEnd，原样保留
        while i < n:
            res.append(intervals[i])
            i += 1

        return res
```

注意第二段的 `while` 条件用的是**动态的** `newEnd`：每吸收一个区间 `newEnd` 可能变大，从而让循环继续。这正是"连锁合并"能自动完成的原因，不需要额外处理。

## 6. 复杂度

**时间 O(n)**：三个 `while` 循环共享同一个指针 `i`，`i` 从 0 单调递增到 n，每个区间恰好被一个循环处理一次，每次处理是 O(1) 的 min/max/append。总操作数 ≤ 3n，所以是 O(n)。这里 n = `len(intervals)`，**没有 log n 项**，因为排序被"利用已有有序性"消掉了。

**空间 O(n)**：`res` 最坏情况下装下全部 n 个区间再加 1 个合并结果，即 O(n)。这是输出本身占的空间；除输出外只用了 `i`、`newStart`、`newEnd` 三个变量，额外空间 O(1)。题面明确允许新建数组，所以这个空间是合规的。

## 7. 边界与反例（至少 4 条）

**① 空列表**
`intervals = [], newInterval = [5,7]` → 期望 `[[5,7]]`。
易错：如果代码在左段循环后忘了无条件 `append` 合并结果，或者对空列表做了 `intervals[0]` 访问，就会崩或返回空。本题代码第一段、第二段循环都不进入，直接 append `[5,7]`，正确。

**② 新区间完全在所有区间右边**
`intervals = [[1,2],[3,4]], newInterval = [10,12]` → 期望 `[[1,2],[3,4],[10,12]]`。
易错：左段循环会把两个区间都吃掉（`2<10`、`4<10`），此时 `i=2`，第二段不进入，append `[10,12]`，第三段空。若把左段判定写成 `<=` 而非 `<`，或忘了第二段后必须 append，就会漏掉新区间。

**③ 新区间完全在所有区间左边**
`intervals = [[5,6],[7,8]], newInterval = [1,2]` → 期望 `[[1,2],[5,6],[7,8]]`。
易错：左段不进入，第二段判定 `5 <= 2` 为假，直接 append `[1,2]`，第三段原样放入。若第二段判定误写成 `intervals[i][0] < newStart` 之类的变体，可能错误吸收 `[5,6]`。

**④ 端点恰好相接（共享一个点）**
`intervals = [[1,2],[3,4]], newInterval = [2,3]` → 期望 `[[1,4]]`。
易错：这是"至少共享一个点即重叠"的直接体现。第二段判定必须是 `intervals[i][0] <= newEnd`（`3 <= 3` 成立），吸收 `[3,4]` 后 `newEnd=4`，再回头吸收 `[1,2]` 吗？不——`[1,2]` 已在左段被放入 `res` 了吗？左段判定 `2 < 2` 为假，所以 `[1,2]` 没进左段，而是被第二段吸收（`1 <= 3` 成立），`newStart=1`，最终 `[1,4]`。若把第二段判定写成 `<`，就会得到 `[[1,2],[2,4]]` 这种错误的重叠结果。

**⑤ 新区间被一个区间完全包含**
`intervals = [[1,10]], newInterval = [3,5]` → 期望 `[[1,10]]`。
易错：第二段吸收 `[1,10]` 后 `newStart=min(3,1)=1`、`newEnd=max(5,10)=10`，输出 `[[1,10]]`。若 min/max 只更新一边，会得到 `[1,5]` 或 `[3,10]` 这种截断错误。

## 8. 面试追问与变体（3 条）

**追问 1：如果 `intervals` 没有排序，怎么办？**
思路：先按起点排序 O(n log n)，再跑本题逻辑；或者直接对 `intervals + [newInterval]` 排序后跑 LeetCode 56 的合并。此时 O(n log n) 无法避免。

**追问 2：如果要支持"删除一个区间"（LeetCode 1272），怎么改？**
思路：同样三段式，但中段不是合并而是"挖洞"——被删区间可能把一个旧区间劈成两半，需要判断删除区间是否严格落在某个旧区间内部，若是则输出左右两个残段。

**追问 3：如果 `newInterval` 是一批区间（批量插入），怎么处理？**
思路：把新批次和原列表一起按起点排序，然后跑一遍标准合并（LeetCode 56），复杂度 O((n+m) log(n+m))；若新批次本身有序，可归并后线性合并。

## 9. 举一反三（2-3 道同类题）

**LeetCode 56. 合并区间**：本题的"母题"，把无序区间排序后做一遍扫描合并，本题的中段逻辑就是它的核心循环。

**LeetCode 1272. 删除区间**：与本题对称——不是吸收而是挖去，同样用"左段/处理段/右段"的三段式扫描框架。

**LeetCode 435. 无重叠区间**：同样基于"区间按端点排序 + 贪心扫描"，但目标是删最少区间使剩余不重叠，考的是按终点排序的贪心选择。
