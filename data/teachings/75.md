## 1. 一句话本质

把只含 0/1/2 的数组原地重排成「0 段、1 段、2 段」三段，且要求一趟扫描、常数空间。

## 2. 读完题的第一反应

**朴素解法**：统计 0、1、2 各多少个，再回填。这需要两趟扫描，但空间 O(1)、时间 O(n)，其实已经能过。它「卡」的地方不在复杂度，而在**进阶要求：一趟扫描**。两趟的本质是「先数清楚再写」，而一趟扫描要求「边看边把元素放到最终位置」。

另一个朴素解法是调用 `sort`，但题面明确禁止，且比较排序是 O(n log n)，对只有 3 种取值的数据是浪费——这正是「计数排序」思想能派上用场的地方。

**关键观察**：数组只有三种值，且最终形态是「前面全是 0，中间全是 1，后面全是 2」。也就是说，**每个元素的目标区域是确定的**：看到 0 就该扔到最左边，看到 2 就该扔到最右边，看到 1 就留在中间。既然如此，我们不需要先数完再放，可以边扫描边把元素「甩」到它该去的边界上。

这个观察直接引出下一步：维护两个边界指针，一个指向「0 区右边界」，一个指向「2 区左边界」，中间未处理区随着扫描不断收缩。这就是荷兰国旗问题（Dutch National Flag）的三指针划分。

## 3. 从暴力到最优

**第一步：计数排序（两趟）**

先扫一遍数出 c0、c1、c2，再扫一遍按数量回填。时间 O(n)，空间 O(1)，但不满足「一趟」。

**第二步：三指针一趟划分**

设三个指针：

- `low`：0 区右边界（`[0, low)` 全是 0）
- `i`：当前扫描位置（`[low, i)` 全是 1）
- `high`：2 区左边界（`(high, n-1]` 全是 2）

未处理区是 `[i, high]`。规则：

- `nums[i] == 0`：和 `nums[low]` 交换，`low++`、`i++`
- `nums[i] == 1`：`i++`（1 天然在中间，不动）
- `nums[i] == 2`：和 `nums[high]` 交换，`high--`，**`i` 不动**

**为什么 `i` 不动？** 因为从 `high` 换过来的元素还没被检查过，可能是 0/1/2，必须重新判断。而 `low` 换过来的元素一定是 1（因为 `[low, i)` 全是 1），所以 `i` 可以安全前进。

**小例子走一遍**：`nums = [2,0,2,1,1,0]`，n=6，初始 `low=0, i=0, high=5`。

| 步骤 | i | low | high | nums | 动作 |
|---|---|---|---|---|---|
| 1 | 0 | 0 | 5 | [2,0,2,1,1,0] | nums[0]=2，与 nums[5] 换 → [0,0,2,1,1,2]，high=4 |
| 2 | 0 | 0 | 4 | [0,0,2,1,1,2] | nums[0]=0，与 nums[0] 换（自身），low=1，i=1 |
| 3 | 1 | 1 | 4 | [0,0,2,1,1,2] | nums[1]=0，与 nums[1] 换，low=2，i=2 |
| 4 | 2 | 2 | 4 | [0,0,2,1,1,2] | nums[2]=2，与 nums[4] 换 → [0,0,1,1,2,2]，high=3 |
| 5 | 2 | 2 | 3 | [0,0,1,1,2,2] | nums[2]=1，i=3 |
| 6 | 3 | 2 | 3 | [0,0,1,1,2,2] | i > high，结束 |

结果 `[0,0,1,1,2,2]`，正确。注意第 4 步换过来的 1 被第 5 步重新检查了，这正是 `i` 不前进的意义。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**论证。在每一轮循环开始时，以下三条同时成立：

1. `[0, low)` 内全是 0；
2. `[low, i)` 内全是 1；
3. `(high, n-1]` 内全是 2。

**初始**：`low=i=0`，`high=n-1`，三个区间都是空的，不变量平凡成立。

**保持**：考察 `nums[i]`：

- 若为 0：`nums[low]` 属于 `[low, i)`，按不变量 2 必为 1。交换后 `nums[low]=0` 并入 0 区，`nums[i]=1` 并入 1 区，`low++`、`i++`，三条不变量仍成立。
- 若为 1：`i++`，1 区扩大一格，成立。
- 若为 2：`nums[high]` 属于未处理区，值未知，交换后 `nums[high]=2` 并入 2 区，`high--`；换到 `i` 位置的元素未检查，留在未处理区，`i` 不动，成立。

**终止**：循环条件 `i > high` 时未处理区为空，三条不变量合起来说明整个数组已按 0、1、2 分段。

**不漏不重的关键**：每个元素要么被 `i` 检查后归位（0 和 1），要么被从 `high` 换到 `i` 后**重新检查**（2 的情况），所以没有任何元素跳过检查；而每次交换都是把元素放进它所属的区间，不会重复处理同一位置。`i` 只增不减、`high` 只减不增，两者相向而行，循环必然终止。

## 5. 完整代码（Python）

```python
class Solution:
    def sortColors(self, nums: list[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        荷兰国旗三指针划分：一趟扫描，常数空间。
        """
        low = 0                 # [0, low) 是 0 区
        i = 0                   # [low, i) 是 1 区，i 是当前扫描位置
        high = len(nums) - 1    # (high, n-1] 是 2 区

        while i <= high:        # 未处理区 [i, high] 非空时继续
            if nums[i] == 0:
                # 0 应去最左边；nums[low] 必为 1，换过来后 i 可安全前进
                nums[low], nums[i] = nums[i], nums[low]
                low += 1
                i += 1
            elif nums[i] == 1:
                # 1 天然属于中间区，直接跳过
                i += 1
            else:
                # 2 应去最右边；换过来的元素未检查，i 不能动
                nums[high], nums[i] = nums[i], nums[high]
                high -= 1
```

## 6. 复杂度

**时间 O(n)**：`i` 从 0 单调增到 `high+1`，`high` 从 n-1 单调减到 `low-1`，两者合计推进不超过 n 步；每步只做常数次比较和交换。没有嵌套循环，所以是线性的，n 来自数组长度。

**空间 O(1)**：只用了 `low`、`i`、`high` 三个整型变量，交换是原地进行，没有开辟与 n 相关的辅助数组。注意这里没有 log n 项——因为不是分治或比较排序，不存在递归栈或树高。

对比：内置 `sort` 是 O(n log n) 时间（Timsort 最坏情况），计数排序是 O(n) 但两趟。本题最优解把两者优点合并：O(n) 时间 + 一趟 + O(1) 空间。

## 7. 边界与反例（至少 4 条）

1. **输入 `[0]`** → 期望 `[0]`。容易错在循环条件写成 `i < high`，n=1 时 `i=0, high=0`，`i<high` 为假直接跳过，虽然结果碰巧对，但换成 `[2]` 就会漏处理。正确写法是 `i <= high`。

2. **输入 `[2,2,2]`** → 期望 `[2,2,2]`。容易错在 `nums[i]==2` 分支里误写 `i += 1`，导致换过来的 2 被跳过、`high` 与 `i` 交错，数组前半段残留未处理元素。

3. **输入 `[1,1,1]`** → 期望 `[1,1,1]`。容易错在把 1 分支也写成交换，虽然结果对，但多做了无谓交换；更隐蔽的错是循环条件写成 `i < len(nums)` 而非 `i <= high`，当 `high` 已缩到 `i` 左边时仍继续访问，可能越界或破坏已排好的 2 区。

4. **输入 `[2,0,1]`** → 期望 `[0,1,2]`。这是示例 2。走一遍：`i=0` 遇 2，与 `nums[2]=1` 换 → `[1,0,2]`，`high=1`；`i=0` 遇 1，`i=1`；`i=1` 遇 0，与 `nums[0]=1` 换 → `[0,1,2]`，`low=1, i=2`；`i=2 > high=1` 结束。容易错在 2 分支后错误地 `i++`，会得到 `[1,0,2]` 之类的错误结果。

5. **输入 `[0,0,1,1,2,2]`（已有序）** → 期望不变。容易错在 0 分支交换时误以为 `nums[low]` 可能是 2，实际上不变量保证它是 1 或就是自身，交换是安全的；若实现里把 `low` 和 `i` 的更新顺序写反，会破坏 1 区。

## 8. 面试追问与变体（3 条）

1. **追问：如果颜色有 k 种（k 远小于 n），怎么推广？** 思路：计数排序 O(n+k) 最直接；若要一趟且原地，可用 k-1 个边界指针做多路划分，但实现复杂、常数大，通常计数排序更实用。

2. **追问：为什么 2 的分支 `i` 不前进，而 0 的分支要前进？** 思路：0 分支换过来的是 1（已确定），2 分支换过来的是未检查元素；本质是「交换源是否已知」。

3. **追问：能否只扫一遍且不交换、只赋值？** 思路：先数出各颜色数量再回填是两趟；若坚持一趟，必须靠交换把元素送到边界，无法避免写操作，但可以论证交换次数上界为 n。
