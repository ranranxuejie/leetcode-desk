## 1. 一句话本质

把两个「低位在前」的十进制数按位做带进位的加法，边加边造出新链表。

## 2. 读完题的第一反应

**朴素解法**：把两个链表各自遍历一遍，还原成 Python 整数，相加，再把结果拆成数字逆序建链表。

它卡在两处：

- 题面提示节点数最多 100。100 位的十进制数远超 Python 的 `int` 转换限制（`int` 转字符串默认上限 4300 位，但更关键的是：**面试官要考的是链表操作，不是大数库**）。即便 Python 能算，这个解法也把「链表」这个数据结构完全绕开了，等于没做这道题。
- 就算用 `int` 硬算，复杂度是 O(n) 还原 + O(n) 重建，看似不差，但一旦换成 C++/Java 就得手写大整数，题目本意就是让你手写。

**关键观察**：题面说「每位数字按照**逆序**存储」。逆序意味着链表的**头节点就是个位**，而竖式加法恰好是**从个位开始往高位算**的。也就是说，链表天然的遍历顺序 = 竖式加法的计算顺序。这一条直接把「对齐」这个麻烦事消掉了：两个链表同时从头走，走一步算一位，进位 `carry` 带着走。

如果题目是正序存储（高位在前），你就得先反转链表或者用栈，难度立刻上一个台阶。所以「逆序」不是随便写的，它是这道题能一遍扫描做完的根本原因。

## 3. 从暴力到最优

**暴力**：链表 → 整数 → 相加 → 拆数字 → 建链表。瓶颈是「整数」这个中间表示，它要求你把整个数先物化出来，空间 O(n)，且依赖语言的大数能力。

**过渡想法**：能不能不物化整个数，只物化「当前这一位 + 进位」？可以。竖式加法本来就是这么做的：`(a_i + b_i + carry) % 10` 是这一位，`// 10` 是新的 carry。

**最优**：双指针同步遍历，一个 `carry` 变量，一个哑节点（dummy）挂结果链表。走完两个链表后如果 `carry` 还是 1，再补一个节点。

用小例子走一遍 `l1 = [2,4,3]`（即 342），`l2 = [5,6,4]`（即 465）：

| 步 | p 的值 | q 的值 | carry 入 | total | 本位 | carry 出 | 结果链表 |
|---|---|---|---|---|---|---|---|
| 1 | 2 | 5 | 0 | 7 | 7 | 0 | 7 |
| 2 | 4 | 6 | 0 | 10 | 0 | 1 | 7→0 |
| 3 | 3 | 4 | 1 | 8 | 8 | 0 | 7→0→8 |
| 结束 | None | None | 0 | — | — | — | 7→0→8 |

输出 `[7,0,8]`，即 807，和示例一致。

再看示例 3 的进位链：`[9,9,9,9,9,9,9]` + `[9,9,9,9]`。前 4 位每位都是 `9+9+carry=19`，本位 9、carry 1；第 5 位是 `9+0+1=10`，本位 0、carry 1；第 6、7 位是 `9+0+1=10`，本位 0、carry 1；循环结束后 carry 仍为 1，补一个节点 1。结果 `[8,9,9,9,0,0,0,1]`。**这个例子专门用来暴露「循环结束后忘了补 carry」的 bug**。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**说清楚。

设两个链表长度分别为 m、n，令 L = max(m, n)。定义不变量：

> 在第 k 次循环开始前（k 从 0 计），`carry` 等于「两个数前 k 位之和」除以 10^k 的整数部分，且结果链表的前 k 个节点恰好是「前 k 位之和」的十进制低 k 位（逆序存放）。

**初始化**：k = 0，carry = 0，结果链表为空。前 0 位之和为 0，成立。

**保持**：第 k 步取 `a = p.val if p else 0`，`b = q.val if q else 0`，`total = a + b + carry`。由不变量，carry 是前 k 位之和的高位部分，加上第 k 位的 a、b，正好是「前 k+1 位之和」；`total % 10` 是它的个位，`total // 10` 是它的高位部分，赋回 carry。结果链表追加 `total % 10`，前 k+1 位正确。不变量保持。

**终止**：循环在 p、q 都为 None 时结束，此时前 L 位全部处理完。若 carry = 1，说明和比 L 位多一位，补节点；若 carry = 0，不补。两种情况下结果链表的每一位都由「该位两数之和 + 该位进位」唯一确定，**没有漏位**（每一位都被访问一次），**没有重位**（每个节点只被读一次、只被写一次）。

「不会重」还依赖一个细节：`p = p.next if p else None` 这种写法保证指针只前进不回头，且长度不等时短链表补 0 而不是补节点，所以不会出现重复读取。

## 5. 完整代码（Python）

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def addTwoNumbers(self, l1: ListNode, l2: ListNode) -> ListNode:
        # 哑节点：避免对「结果链表的第一个节点」写特判
        dummy = ListNode(0)
        tail = dummy          # tail 始终指向结果链表最后一个节点
        carry = 0             # 进位，取值只可能是 0 或 1
        p, q = l1, l2

        # 循环条件用 or：长度不等时，长的那条还要继续走
        while p or q:
            # 短链表走完后按 0 处理，这是「对齐」的关键
            a = p.val if p else 0
            b = q.val if q else 0

            total = a + b + carry
            carry = total // 10          # 新的进位
            tail.next = ListNode(total % 10)  # 本位挂到结果链表尾部
            tail = tail.next

            # 指针前进，注意 None 判断，不能直接 p = p.next
            p = p.next if p else None
            q = q.next if q else None

        # 循环结束后若还有进位，必须补一个节点（示例 3 就靠这一步）
        if carry:
            tail.next = ListNode(carry)

        return dummy.next     # 跳过哑节点
```

## 6. 复杂度

- **时间 O(max(m, n))**：循环体执行 L = max(m, n) 次，每次做常数次加法、取模、赋值。m、n 分别是两个链表的节点数。没有嵌套循环，所以不是 O(m·n)。
- **空间 O(max(m, n))**：结果链表最多 L + 1 个节点（多出的 1 是最后的进位）。这是**输出本身占的空间**，不算额外空间；额外空间只有 `dummy`、`tail`、`carry`、`p`、`q` 五个变量，是 O(1)。面试时如果被问「额外空间」，答 O(1)。

注意这里**没有 log n**：题目是十进制按位加，位数就是节点数，不存在「位数 = log 数值」这种换算，因为输入给的就是位，不是数值。

## 7. 边界与反例（至少 4 条）

1. **`l1=[0], l2=[0]` → `[0]`**。容易错在：有人写 `if carry: ...` 之外还加 `if not dummy.next: return ListNode(0)`，其实循环至少跑一次，`dummy.next` 一定非空，多此一举；反过来，若把循环条件写成 `while p and q`，两个单节点会正常跑，但长度不等时就会漏。
2. **`l1=[9,9,9,9,9,9,9], l2=[9,9,9,9]` → `[8,9,9,9,0,0,0,1]`**。容易错在：循环结束后 `carry=1` 忘了补节点，输出少一位，变成 `[8,9,9,9,0,0,0]`。
3. **`l1=[5], l2=[5]` → `[0,1]`**。容易错在：只处理了 `total % 10` 忘了 `carry = total // 10`，或者把 carry 写死成 0，输出 `[0]`。
4. **`l1=[1], l2=[9,9,9]` → `[0,0,0,1]`**。长度差 2，容易错在：短链表走完后直接 `p.next` 抛 `AttributeError`，或者用 `while p and q` 导致后两位没算。
5. **`l1=[2,4,3], l2=[5,6,4]` → `[7,0,8]`**。容易错在：把逆序当正序，从尾节点开始加，结果变成 `[8,0,7]`。

## 8. 面试追问与变体（3 条）

1. **追问：如果链表是正序存储（高位在前）怎么办？** 思路：先各自反转链表，套本题，再把结果反转；或者用两个栈把节点压进去，从栈顶弹出低位相加。前者 O(n) 时间 O(1) 额外空间（原地反转），后者 O(n) 额外空间。
2. **追问：不允许修改输入链表，且要求 O(1) 额外空间，正序怎么做？** 思路：递归。递归到两个链表末尾，回溯时从低位往高位加，用返回值把进位带上来；递归栈深度 O(n)，严格说不是 O(1)，需要和面试官确认「额外空间」是否含递归栈。
3. **追问：如果是三数相加、或者链表表示的是其他进制（比如二进制）？** 思路：把 `% 10`、`// 10` 换成 `% base`、`// base`，carry 上限变成 base-1；三数相加时 `total = a + b + c + carry`，carry 可能大于 1，逻辑不变。
