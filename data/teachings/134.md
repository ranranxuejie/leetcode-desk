## 1. 一句话本质

在环上找一个起点，使得从它出发、沿环累加 `gas[i]-cost[i]` 的**前缀和全程不为负**，且总和不为负。

## 2. 读完题的第一反应

最直白的做法：枚举每个起点 `s`，从 `s` 出发模拟走一圈，油箱一旦变负就换下一个起点。这是 $O(n^2)$，$n=10^5$ 时约 $10^{10}$ 次操作，必然超时。瓶颈在于「每个起点都从头模拟一遍」，大量重复计算。

关键观察有两条，都来自把 `gas[i]-cost[i]` 记作 `diff[i]`（第 i 站净收益）：

- **总和判生死**：绕一圈的总净收益是 $\sum diff$。如果它小于 0，无论从哪出发，走完一圈油箱必然比出发时少，不可能回到起点。所以总和 < 0 直接返回 -1。这一条把「无解」的情况 $O(n)$ 判掉。
- **失败区间可以整段跳过**：从 `s` 出发，若走到 `j` 时油箱首次变负，说明 `s` 到 `j` 这段路走不通。那么 `s+1, s+2, ..., j` 这些起点**全都不用试**——因为从 `s` 出发到它们时油箱已经 ≥ 0（是首次变负之前），从它们出发相当于「油箱更空」地走同一段路，只会更早失败。于是可以直接把起点挪到 `j+1`。

第二条是贪心的核心，它把「每个起点重走一遍」压成了「整条数组只扫一遍」。

## 3. 从暴力到最优

**暴力版**：对每个 `s`，`tank=0`，走 `n` 步，每步 `tank += diff[(s+k)%n]`，中途 `<0` 就 break。最坏 $O(n^2)$。

**贪心版**：维护两个量——`total`（全局总和，判有没有解）和 `tank`（当前这段起点的累计油量）。一次遍历：

- `total += diff[i]`，`tank += diff[i]`
- 若 `tank < 0`：说明从当前 `start` 到 `i` 走不通，令 `start = i+1`，`tank = 0`（重新开始累计）
- 遍历完，若 `total >= 0` 返回 `start`，否则 -1。

拿示例 1 走一遍，`gas=[1,2,3,4,5]`，`cost=[3,4,5,1,2]`，`diff=[-2,-2,-2,3,3]`：

| i | diff | tank | total | start | 动作 |
|---|------|------|-------|-------|------|
| 0 | -2 | -2 | -2 | 0 | tank<0 → start=1, tank=0 |
| 1 | -2 | -2 | -4 | 1 | tank<0 → start=2, tank=0 |
| 2 | -2 | -2 | -6 | 2 | tank<0 → start=3, tank=0 |
| 3 | 3 | 3 | -3 | 3 | 继续 |
| 4 | 3 | 6 | 0 | 3 | 继续 |

`total=0 ≥ 0`，返回 `start=3`，与答案一致。注意 `total` 一路是负的，但最后归零——这正是「前面欠的账被后面补上」，所以起点必须落在补账的那一段（索引 3）。

再看示例 2，`diff=[-1,-1,1]`：i=0 tank=-1 → start=1；i=1 tank=-1 → start=2；i=2 tank=1。`total=-1 < 0`，返回 -1。正确。

对比暴力的收益：暴力在示例 1 里会从 0、1、2 各试一次都失败，贪心只扫一遍就定位到 3。

## 4. 正确性：为什么不会漏、不会重

用**不变量**论证，分两部分。

**不变量 1（跳过不丢解）**：设从 `s` 出发首次在 `j` 处 tank 变负。对任意 $k \in (s, j]$，从 `k` 出发走到 `j` 的净收益，等于「从 `s` 走到 `j` 的净收益」减去「从 `s` 走到 `k` 的净收益」。而后者在首次变负前 ≥ 0，前者 < 0，所以从 `k` 出发到 `j` 的净收益更负，必然也在 `j` 之前（或 `j` 处）失败。故 `s..j` 全部排除，`start` 跳到 `j+1` 不丢任何可行解。

**不变量 2（唯一候选必可行）**：遍历结束时 `start` 是最后一个「失败段」之后的位置。若 `total ≥ 0`，从 `start` 出发绕一圈的累计和就是 `total`（因为 `start` 之后到数组末尾的累计已 ≥ 0，加上开头被跳过的那段，整体等于 `total`），全程不会跌破 0——否则会在某处触发 `tank<0` 把 `start` 再往后推，与「遍历已结束」矛盾。题面保证解唯一，所以这个 `start` 就是答案。

两条合起来：既不漏（跳过的段确实无解），也不重（每个下标只被扫一次，`start` 单调右移）。

## 5. 完整代码（Python）

```python
class Solution:
    def canCompleteCircuit(self, gas: list[int], cost: list[int]) -> int:
        n = len(gas)
        total = 0   # 全局净收益，判断是否存在解
        tank = 0    # 当前候选起点出发的累计油量
        start = 0   # 当前候选起点

        for i in range(n):
            diff = gas[i] - cost[i]   # 第 i 站的净收益
            total += diff
            tank += diff

            # 从 start 走到 i 后油箱为负：start..i 都不能作为起点
            if tank < 0:
                start = i + 1   # 下一个候选起点
                tank = 0        # 重新累计

        # 总净收益为负则无解；否则 start 就是唯一可行起点
        return start if total >= 0 else -1
```

注意 `start` 可能等于 `n`（最后一段失败），但此时 `total` 必为负（否则不会在末尾失败），会走 `-1` 分支，不会越界返回。

## 6. 复杂度

- **时间 $O(n)$**：单层 `for` 循环遍历 `n` 个下标，循环体内全是 $O(1)$ 的加减和比较。没有嵌套、没有排序，所以没有 $O(\log n)$ 项。$n$ 来自数组长度。
- **空间 $O(1)$**：只用了 `total`、`tank`、`start`、`diff` 四个标量，与 `n` 无关。没有额外数组。

## 7. 边界与反例（至少 4 条）

1. `gas=[1], cost=[1]` → 期望 `0`。容易错：忘记单元素时 `diff=0`，`tank` 不为负，应返回 0 而非 -1。
2. `gas=[1], cost=[2]` → 期望 `-1`。容易错：`tank=-1` 触发 `start=1`，若直接返回 `start` 会越界；必须靠 `total<0` 兜底。
3. `gas=[2,3,4], cost=[3,4,3]` → 期望 `-1`（示例 2）。容易错：只看局部 `tank` 会以为 2 号站能走，但 `total=-1` 说明整体不够，必须判 `total`。
4. `gas=[5,1,2,3,4], cost=[4,4,1,5,1]` → `diff=[1,-3,1,-2,3]`，`total=0`，期望 `4`。容易错：`start` 会被推到 4，若误以为「`total=0` 就无解」会返回 -1；实际 `total≥0` 即有解。
5. `gas=[0,0,0], cost=[0,0,0]` → 期望 `0`。容易错：全零时 `tank` 始终为 0，不触发重置，`start` 保持 0，正确；但若把条件写成 `tank <= 0` 就会误重置。

## 8. 面试追问与变体（3 条）

1. **追问：如果答案不唯一，要返回所有可行起点怎么办？** 思路：先按本题求出总和与一个候选，再用滑动窗口/前缀和最小值在 $O(n)$ 内枚举所有满足「环上最小前缀 ≥ 0」的起点。
2. **追问：油箱有容量上限 C，还能贪心吗？** 思路：不能简单跳段，因为「油多」可能溢出浪费，需要把状态改成「到达每站时的油量」做 DP 或单调队列，复杂度上升。
3. **追问：把「绕一圈」改成「走 k 步」呢？** 思路：用前缀和 + 滑动窗口最小值，判断每个起点后 k 步内前缀是否跌破起点值，$O(n)$。
