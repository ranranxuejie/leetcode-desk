## 1. 一句话本质

在所有任务都必须被排进时间轴、且同类任务间隔至少 n 的约束下，求时间轴的最短长度——而这个长度几乎完全由「出现次数最多的那个任务」决定。

## 2. 读完题的第一反应

**朴素解法**：把任务当成一个待排序列，用回溯/搜索枚举所有合法排列，取最短的那个。卡在哪？任务数最多 10^4，排列空间是阶乘级，直接爆炸。即使退一步用「贪心 + 优先队列」模拟每个时间片（每次挑当前冷却完毕、剩余次数最多的任务），复杂度是 O(总时间 × 26)，总时间最坏约 10^4 × 100，虽然能过，但它是「模拟」而非「计算」，面试官往往想看你能否直接推出公式。

**关键观察**：冷却约束只对「同一任务」生效，不同任务之间随便插。于是最紧的约束来自出现次数最多的任务——它必须被 n 个空位隔开，这些空位是硬性的、绕不过去的。其他任务能做的只有一件事：**往这些空位里填**。填满了，总时间就是「框架长度」；填不满，框架里就留 idle，总时间还是框架长度；只有当任务多到把框架撑爆（即所有空位都填满还有剩余），总时间才退化成「任务总数」。

这个观察把问题从「排列搜索」降维成「数一数框架有多大、空位够不够填」，一步到位。

## 3. 从暴力到最优

**第一步：看清框架。**

设出现次数最多的任务出现了 `maxFreq` 次（可能有多个任务并列最多，记并列个数为 `cntMax`）。以 `tasks = [A,A,A,B,B,B], n = 2` 为例，`maxFreq = 3`，`cntMax = 2`（A、B 都是 3 次）。

把最多的任务排开，中间强制塞 n 个间隔：

```
A _ _ A _ _ A
```

这是 A 的骨架，长度 = `(maxFreq - 1) * (n + 1) + 1 = 2*3 + 1 = 7`。注意最后一段后面不需要再留 n 个空位（没有下一个 A 了），所以是 `+1` 而不是 `+(n+1)`。

**第二步：往空位里填其他任务。**

上例中空位有 6 个（两段各 3 个）。B 有 3 个，填进去：

```
A B _ A B _ A B
```

填完后 B 也用完了，还剩 2 个空位（第 3、6 位）没东西填，只能 idle。总长度 = 7 + 2 = 9？等等，这里要小心：B 填进去后，B 自己也占了位置，但框架长度 7 是「A 的骨架 + 空位」的总长，B 是填进空位里的，不额外增加长度。所以总长度就是框架长度 7……但示例 1 的答案是 8，不是 7。

问题出在哪？`cntMax = 2`，A 和 B 都是 3 次。骨架不能只按 A 算——最后一个 A 后面，B 还需要一个位置（B 的第 3 次不能和 A 的第 3 次挤在同一格）。所以当有多个任务并列最多时，最后一段要容纳 `cntMax` 个任务，框架长度修正为：

```
(maxFreq - 1) * (n + 1) + cntMax = 2*3 + 2 = 8
```

验证：`A B _ A B _ A B` 长度 8，第 3、6 位 idle，符合示例 1。

**第三步：空位够不够？**

框架长度公式给出的是「至少这么长」。但如果其他任务特别多，多到把框架里的空位全填满还有剩，那总长度就由任务总数决定（因为每个时间片都能排一个任务，不需要 idle）。

`tasks = [A,A,A,B,B,B,C,C,C], n = 1`：`maxFreq = 3`，`cntMax = 3`，框架 = `2*2 + 3 = 7`。但任务总数 = 9 > 7，说明框架装不下，实际最短就是 9（可以排成 `A B C A B C A B C`，间隔 1 满足）。所以答案取 `max(框架长度, 任务总数)`。

**第四步：合并成公式。**

```
ans = max( (maxFreq - 1) * (n + 1) + cntMax , len(tasks) )
```

再走一遍示例 3：`[A,A,A,B,B,B], n = 3`。`maxFreq = 3`，`cntMax = 2`，框架 = `2*4 + 2 = 10`，任务总数 6，取 max = 10。与示例 3 输出一致。

## 4. 正确性：为什么不会漏、不会重

**下界（不会更短）**：取出现次数最多的任务（设出现 `maxFreq` 次）。这 `maxFreq` 次执行之间至少有 `maxFreq - 1` 段间隔，每段至少 n 个时间片，加上这 `maxFreq` 次本身，至少需要 `(maxFreq - 1) * (n + 1) + 1` 个时间片。若并列最多的任务有 `cntMax` 个，最后一段间隔之后必须同时容纳这 `cntMax` 个任务的最后一次（它们互相之间也要隔 n，不能挤在同一格），所以下界收紧为 `(maxFreq - 1) * (n + 1) + cntMax`。同时总时间不可能少于任务总数（每个时间片最多一个任务）。两个下界取 max，得到答案的下界。

**上界（能构造出来）**：按「列」填充——把时间轴切成 `maxFreq - 1` 个长度为 `n + 1` 的块，每块放一个最多任务，剩余位置按任意顺序填入其他任务（同一块内不会出现两个相同任务，因为每种任务的总数不超过 `maxFreq`，且每块每种任务至多放一个）。最后一块放 `cntMax` 个最多任务。若任务总数超过框架，说明空位被填满，直接顺序排即可（此时任意相邻同类任务间隔自然 ≥ n，因为同类任务总数 ≤ maxFreq 且被其他任务隔开）。构造存在，上界可达。

下界 = 上界，公式正确。这里用的是「下界 + 构造」的论证，不是「显然」。

## 5. 完整代码（Python）

```python
from collections import Counter

class Solution:
    def leastInterval(self, tasks: list[str], n: int) -> int:
        # 统计每种任务的出现次数
        freq = Counter(tasks)
        # 出现次数的最大值
        max_freq = max(freq.values())
        # 有多少种任务达到了这个最大值（并列最多）
        cnt_max = sum(1 for v in freq.values() if v == max_freq)

        # 框架长度：前 max_freq-1 段各占 n+1，最后一段放 cnt_max 个最多任务
        frame = (max_freq - 1) * (n + 1) + cnt_max

        # 若任务总数超过框架，说明空位不够填，总时间就是任务总数
        return max(frame, len(tasks))
```

关键逻辑注释已在代码中。注意 `cnt_max` 统计的是「次数等于 max_freq 的任务种类数」，不是「max_freq 本身」，这是最容易写错的地方。

## 6. 复杂度

- **时间 O(m)**，m = `len(tasks)`。`Counter` 遍历一遍任务列表 O(m)；`max(freq.values())` 遍历至多 26 个键 O(26) = O(1)；`sum(...)` 同理 O(1)。所以主导项是 O(m)。
- **空间 O(1)**（严格说 O(Σ)，Σ = 26 为字母表大小）。`Counter` 最多存 26 个键值对，与 m 无关。若把输入本身算进去则是 O(m)，但那是输入占用，不是算法额外空间。
- 没有 log n 项：本题不排序、不用堆，纯计数。标签里的「堆」对应的是模拟解法，公式解法不需要。

## 7. 边界与反例（至少 4 条）

1. **`tasks = ["A"], n = 0`** → 期望 1。容易错：公式 `(1-1)*(0+1)+1 = 1`，正确；但若把 `cnt_max` 写成 `max_freq` 会得 1 也碰巧对，掩盖 bug。用下一条暴露。
2. **`tasks = ["A","A","A"], n = 0`** → 期望 3。`max_freq=3, cnt_max=1`，框架 `2*1+1=3`，正确。若 n=0 时误以为「冷却为 0 就随便排」而返回 `len(tasks)=3`，也碰巧对——但换成 `["A","A","A","B"]`，n=0，期望 4，框架 `2*1+1=3`，取 max(3,4)=4，正确；若漏掉 `max(..., len(tasks))` 会返回 3，错。
3. **`tasks = ["A","A","A","B","B","B","C","C","C","D","D","D"], n = 2`** → 期望 12。`max_freq=3, cnt_max=4`，框架 `2*3+4=10`，任务总数 12，取 max=12。容易错：只算框架得 10，忘了任务多到撑爆框架。
4. **`tasks = ["A","B","C","D","E","F"], n = 2`** → 期望 6。`max_freq=1, cnt_max=6`，框架 `0*3+6=6`，正确。容易错：`max_freq=1` 时若公式写成 `(max_freq-1)*(n+1)+1` 会得 1，严重偏小——必须用 `cnt_max` 而非 1。
5. **`tasks = ["A","A","A","B","B","B"], n = 100`** → 期望 `2*101+2 = 204`。n 很大时框架主导，idle 极多。容易错：误以为 n 大就该用模拟，其实公式照样成立。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求输出具体的调度序列，而不只是长度？** 思路：按「列」构造——建 `max_freq` 个桶，第 i 个桶放第 i 次出现的各任务，桶之间插 n 个空位，空位用剩余任务按顺序填，填不满补 idle。O(m) 构造。
2. **追问：如果冷却时间对每种任务不同（任务 A 冷却 2、B 冷却 5）？** 思路：公式失效，退回「贪心 + 优先队列」模拟：每个时间片选冷却完毕且剩余次数最多的任务，用堆维护，O(总时间 × log 26)。
3. **追问：如果允许在冷却未满时「打断」并重新计时（即冷却可被覆盖）？** 思路：约束变松，问题退化为「同类任务尽量分散」，可用贪心按频率降序轮转填充，本质是本题框架的推广。

2. **358. K 距离间隔重排字符串**：把冷却从「同类间隔 n」推广到「任意相同元素间隔 ≥ k」，共同点是「频率最高的元素决定框架，其余元素填空位」。
3. **1054. 距离相等的条形码**：要求相邻元素不同，共同点是「按频率贪心 + 优先队列」的模拟思路，与本题的堆解法同源。
