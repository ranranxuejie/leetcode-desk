## 1. 一句话本质

按「根 → 左子树 → 右子树」的固定顺序，把每个节点的值各收集一次，得到一个长度等于节点数的序列。

## 2. 读完题的第一反应

**朴素解法**：递归。写一个 `dfs(node)`，先 `append(node.val)`，再 `dfs(node.left)`，再 `dfs(node.right)`。这几乎是照着「前序」的定义直译，正确性没有悬念。

**它卡在哪**：递归本身不是复杂度瓶颈（时间 O(n)、空间 O(h) 都已经是理论下界），瓶颈在**工程约束**——递归深度受调用栈限制。题面提示节点数最多 100，递归完全安全；但进阶要求明确问「你能用迭代完成吗」，面试官问这句话时，真正想听的是：**你能不能自己维护一个栈，来模拟递归的执行过程**。所以这道题的教学价值不在「怎么遍历」，而在「递归被展开成循环后，那些隐式状态长什么样」。

**关键观察**：递归函数 `dfs(node)` 在任意时刻只有两件事要做——「访问当前节点」和「记住还没处理的两个孩子」。前者是立即动作，后者是**待办事项**。既然待办事项需要后进先出（先记下的右孩子要最后处理），那它天然就是一个栈。把「递归调用」换成「往栈里压节点」，递归就变成了迭代。

再补一个细节观察：前序是「根、左、右」，而栈是后进先出。所以压栈时必须**先压右孩子、再压左孩子**，这样弹出时左孩子先出——顺序才对。这个「反着压」是本题迭代写法唯一容易写错的地方。

## 3. 从暴力到最优

**第一步：递归（暴力但正确）**

以示例 2 的树为例（`[1,2,3,4,5,null,8,null,null,6,7,9]`），递归执行顺序是：

```
dfs(1) → 记录 1 → dfs(2) → 记录 2 → dfs(4) → 记录 4 → 左空、右空返回
       → dfs(5) → 记录 5 → dfs(6) → 记录 6 返回 → dfs(7) → 记录 7 返回
       → 返回 → 返回
       → dfs(3) → 记录 3 → 左空 → dfs(8) → 记录 8 → dfs(9) → 记录 9
```

结果 `[1,2,4,5,6,7,3,8,9]`，与题面一致。瓶颈：调用栈深度 = 树高 h，最坏 O(n) 层，Python 默认递归上限约 1000，深树会 `RecursionError`。

**第二步：显式栈（消掉调用栈）**

把「函数调用」翻译成「栈 + 循环」。维护 `stack` 存**待访问的节点**，`res` 存结果：

```
初始：stack = [1], res = []
弹出 1 → res=[1]，压右 3、压左 2 → stack=[3,2]
弹出 2 → res=[1,2]，压右 5、压左 4 → stack=[3,5,4]
弹出 4 → res=[1,2,4]，无孩子 → stack=[3,5]
弹出 5 → res=[1,2,4,5]，压右 7、压左 6 → stack=[3,7,6]
弹出 6 → res=[1,2,4,5,6] → stack=[3,7]
弹出 7 → res=[1,2,4,5,6,7] → stack=[3]
弹出 3 → res=[1,2,4,5,6,7,3]，压右 8 → stack=[8]
弹出 8 → res=[...,8]，压右 9 → stack=[9]
弹出 9 → res=[...,9] → stack=[]
```

每一步的中间变量都写出来了，可以看到：**栈里存的永远是「已经知道、但还没轮到」的节点**，且栈顶总是下一个该访问的节点。瓶颈被消掉了——不再有函数调用栈，深度只受显式列表长度影响，而列表长度最多 O(n)，且不受解释器递归限制。

**第三步：还能不能更好？**

时间上每个节点必须被读一次，O(n) 是下界，无法再降。空间上，结果数组本身就要 O(n)，所以额外空间 O(h)（栈的最大深度）已经是最优量级。**这道题没有「更优的渐近复杂度」可追**，迭代版的意义是消除递归深度风险、以及在面试中展示对递归展开的理解。这一点要跟学员讲清楚，避免他们误以为迭代版在复杂度上赢了。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来证。

定义不变量：*在迭代版的每一轮循环开始时，`res` 恰好是按前序顺序排列的、所有「已弹出过」节点的值；`stack` 中的节点恰好是所有「已弹出节点的孩子中尚未被访问的」节点，且栈中从顶到底的顺序，正是它们应被前序访问的顺序。*

- **初始**：`res` 为空，`stack=[root]`，不变量成立（root 是唯一待访问节点）。
- **保持**：弹出栈顶 `node`，它按不变量正是下一个该访问的节点，追加到 `res` 后，`res` 的前序性质保持。接着把 `node.right`、`node.left` 依次压栈——由于栈后进先出，`node.left` 会先于 `node.right` 被弹出，正好符合「左子树整体先于右子树」的前序要求。其余已在栈中的节点位于这两个孩子之下，仍保持原有相对顺序。
- **终止**：栈空时，不变量说「没有待访问节点」，而 `res` 已包含所有被弹出节点；又因为每个节点入栈恰好一次（只在其父节点被弹出时压入，root 单独压一次），所以 `res` 恰好包含全部 n 个节点，无漏无重。

**不会漏**：每个节点要么是 root，要么在父节点弹出时被压栈，因此必被弹出一次。
**不会重**：压栈动作只发生在父节点弹出的那一刻，一个节点只有一个父节点，故只压一次。

## 5. 完整代码（Python）

```python
from typing import Optional, List

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

class Solution:
    def preorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        res = []
        if root is None:          # 空树直接返回空列表，避免下面 stack 里塞 None
            return res

        stack = [root]            # 显式栈：存放"已发现、待访问"的节点
        while stack:
            node = stack.pop()    # 栈顶就是下一个该访问的节点
            res.append(node.val)  # 前序：先访问根

            # 关键：先压右、再压左。栈是后进先出，
            # 这样左孩子会先被弹出，符合"根→左→右"的顺序
            if node.right:
                stack.append(node.right)
            if node.left:
                stack.append(node.left)

        return res
```

递归版作为对照（面试时可以先写这个，再被追问时改迭代）：

```python
class Solution:
    def preorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        res = []
        def dfs(node):
            if node is None:
                return
            res.append(node.val)   # 根
            dfs(node.left)         # 左
            dfs(node.right)        # 右
        dfs(root)
        return res
```

## 6. 复杂度

**时间 O(n)**：n 是节点数。每个节点入栈一次、出栈一次，`append` 到 `res` 一次，每次都是 O(1) 操作，合计 3n 次常数操作。没有嵌套循环，所以是严格的 O(n)，不是 O(n log n)——树结构里不存在「每层扫一遍」的动作，log n 不会出现。

**空间 O(n)**：
- `res` 存 n 个值，贡献 O(n)，这部分无法避免（输出本身就要 n 个元素）。
- `stack` 的最大长度：最坏情况是「每个节点都只有右孩子」的链状树，此时栈里同时最多只有 1 个元素；最坏是「完全二叉树」的某一层，栈长度可达 O(n/2) 量级；更准确地说，栈的最大深度受树高 h 约束，最坏 h = n（链状树时其实栈很浅，真正的峰值出现在「左孩子密集」的形态）。保守写 O(n)，紧一点写 O(h)，h 为树高，平均 O(log n)、最坏 O(n)。

**递归版空间**：调用栈深度 = h，同样 O(h)，但受 Python 默认递归上限（约 1000）约束；本题 n ≤ 100 所以安全，但这是工程上的隐患，不是复杂度问题。

## 7. 边界与反例（至少 4 条）

1. **`root = []`（空树）** → 期望 `[]` → 容易错在：没判空就把 `None` 压进栈，循环里 `node.val` 直接 `AttributeError`。代码里 `if root is None: return res` 就是防这个。
2. **`root = [1]`（单节点）** → 期望 `[1]` → 容易错在：压栈时没判 `node.left`/`node.right` 是否为 `None`，把 `None` 压进去，下一轮 `pop` 出 `None` 再取 `.val` 崩掉。必须用 `if node.right:` 而不是无条件 `append`。
3. **`root = [1,2,null]`（只有左孩子）** → 期望 `[1,2]` → 容易错在：压栈顺序写反成「先左后右」，虽然这棵树看不出差别，但换成 `[1,2,3]` 就会输出 `[1,3,2]`。这是本题最高频的 bug，必须用「先右后左」。
4. **`root = [1,null,2,3]`（示例 1，右链带左孩子）** → 期望 `[1,2,3]` → 容易错在：误以为「右孩子先压」会导致右子树先被访问。实际压栈后栈是 `[2]`（右孩子 2 在底），弹出 2 后压 3，再弹 3，顺序正确。要理解「压的顺序」和「访问的顺序」是反的。
5. **`root = [1,2,3,4,5,null,8,null,null,6,7,9]`（示例 2）** → 期望 `[1,2,4,5,6,7,3,8,9]` → 容易错在：把「前序」和「层序（BFS）」搞混，层序会得到 `[1,2,3,4,5,8,6,7,9]`。前序是深度优先，必须一路扎到最左叶子再回头。

## 8. 面试追问与变体（3 条）

1. **追问：不用递归、也不用显式栈，能做到 O(1) 额外空间吗？**
   思路：Morris 遍历。利用叶子节点的空右指针临时指回中序后继，遍历完再还原，空间 O(1)，时间仍 O(n)。前序的 Morris 稍特殊：在「左子树最右节点」处建线索，访问时机要调整。

2. **追问：改成中序 / 后序，迭代怎么写？**
   思路：中序是「一路压左到底，弹出时访问，再转向右孩子」；后序最省事的写法是「按根→右→左遍历再整体反转」，或者用「上一个访问节点」判断是从左子树回来还是从右子树回来。

3. **追问：如果要求按层输出（每层一个子列表）呢？**
   思路：BFS + 队列，每轮先记下 `len(queue)`，把这一层的节点一次性弹完再进下一层。和本题的共同点是「用容器模拟遍历顺序」，区别是容器从栈换成队列。

## 9. 举一反三（2-3 道同类题）

- **94. 二叉树的中序遍历**：同一套「显式栈模拟递归」的框架，只是「访问根」的时机从「入栈时」挪到「弹出时」。
- **145. 二叉树的后序遍历**：同样用栈，但需要额外记录「右子树是否已处理」，是前序迭代的加强版。
- **102. 二叉树的层序遍历**：把栈换成队列，是「容器决定遍历顺序」这一思想的直接对照，适合和本题一起讲，帮学员建立「DFS 用栈、BFS 用队列」的直觉。
