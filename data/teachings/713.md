## 1. 一句话本质

对每个右端点，找出「以它为结尾、乘积仍小于 k」的最长连续区间，这个区间的长度就是该右端点贡献的子数组个数，把所有右端点的贡献加起来。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子数组（左端点 i、右端点 j 两层循环），对每个子数组再乘一遍求积。子数组有 O(n²) 个，每个求积 O(n)，总复杂度 O(n³)。即便用「固定 i、j 向右扩展时累乘」的技巧把内层求积省掉，仍然是 O(n²)。n 最大 3×10⁴，n² 是 9×10⁸，Python 里必然超时。

**关键观察**：题目里所有 `nums[i] >= 1`（提示明确写了 `1 <= nums[i]`）。这一点极其重要——它意味着**乘积关于区间长度是单调的**：区间往右扩，乘积只会变大（乘一个 ≥1 的数不会变小）；区间往左缩，乘积只会变小。单调性一旦成立，「满足条件的最长区间」就可以用两个指针同向移动来维护，而不需要回头重算。

如果 nums 里允许 0 或负数，这个单调性就崩了，滑动窗口也就不成立。所以「元素全为正」不是无关紧要的细节，而是整个解法的地基。

## 3. 从暴力到最优

**暴力**：对每个左端点 i，让 j 从 i 开始往右走，边乘边判断，一旦乘积 ≥ k 就停。这样每个 i 最多走 n 步，总 O(n²)。

**瓶颈在哪**：当 i 右移一格时，j 得从头（i+1）重新开始走。但上一轮 j 已经走到某个位置了，这些信息被浪费了。

**滑动窗口怎么消掉它**：维护一个窗口 `[left, right]`，保证窗口内乘积 < k。每轮把 `right` 往右扩一格、乘进 `prod`；如果 `prod >= k`，就把 `left` 往右挪、把 `nums[left]` 除出去，直到 `prod < k` 为止。此时窗口 `[left, right]` 内所有以 `right` 结尾的子数组都合法，个数恰好是 `right - left + 1`。

**小例子走一遍**：`nums = [10,5,2,6], k = 100`。

| 步骤 | right | 乘入后 prod | 收缩后 left | 窗口 | 新增个数 | 累计 |
|---|---|---|---|---|---|---|
| 1 | 0 | 10 | 0 | [10] | 1 | 1 |
| 2 | 1 | 50 | 0 | [10,5] | 2 | 3 |
| 3 | 2 | 100 ≥ 100，除 10 → 10 | 1 | [5,2] | 2 | 5 |
| 4 | 3 | 60 | 1 | [5,2,6] | 3 | 8 |

第 3 步值得盯一眼：乘入 2 后 prod = 10×5×2 = 100，不满足「严格小于」，于是把 left 从 0 挪到 1，prod 变成 100/10 = 10，窗口变成 [5,2]，长度 2，贡献 2 个子数组（[2]、[5,2]）。第 4 步乘入 6 得 60，窗口 [5,2,6] 长度 3，贡献 3 个（[6]、[2,6]、[5,2,6]）。合计 1+2+2+3 = 8，与示例一致。

注意 left 全程只往右走、从不回退，这就是 O(n) 的来源。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。循环体每轮结束时，维持两个不变量：

**不变量 A（窗口合法且极大）**：`prod = nums[left] × ... × nums[right] < k`，且 `left` 是满足此条件的最小下标（即若 left 再往左一格，乘积就 ≥ k，或者 left 已经到 0）。

**不变量 B（计数完备）**：累计答案恰好等于所有右端点 ≤ right 的合法子数组总数。

**为什么不会漏**：对固定的 right，以 right 结尾的子数组是 `[right,right]`、`[right-1,right]`、…、`[left,right]`、`[left-1,right]`…。由单调性（元素 ≥1），从 right 往左扩展时乘积单调不减。不变量 A 说 `[left,right]` 合法而 `[left-1,right]` 不合法，所以合法的恰好是起点在 `[left, right]` 之间的那些，共 `right-left+1` 个。一个不多一个不少。

**为什么不会重**：每个子数组由它的右端点唯一确定归属——它只在处理那个 right 时被计入一次。不同 right 贡献的子数组右端点不同，天然不重叠。

**收缩为什么不会误删**：收缩时我们只丢掉了「以当前 right 结尾但乘积 ≥ k」的起点，这些本来就不该计。而由于单调性，丢掉它们不会让更靠右的起点变得不合法——prod 只会越除越小。

## 5. 完整代码（Python）

```python
class Solution:
    def numSubarrayProductLessThanK(self, nums, k):
        # k <= 1 时不可能有乘积严格小于 k 的正整数子数组
        # （nums[i] >= 1，最小乘积就是 1，1 < k 要求 k > 1）
        if k <= 1:
            return 0

        prod = 1          # 当前窗口 [left, right] 的乘积
        left = 0          # 窗口左边界
        ans = 0           # 累计合法子数组个数

        for right in range(len(nums)):
            prod *= nums[right]          # 右端点扩张，乘入新元素

            # 乘积不满足严格小于 k 时，左端点右移收缩
            while prod >= k:
                prod //= nums[left]      # 整除安全：prod 一定是 nums[left] 的倍数
                left += 1

            # 此时 [left, right] 内所有以 right 结尾的子数组都合法
            # 起点可以是 left, left+1, ..., right，共 right-left+1 个
            ans += right - left + 1

        return ans
```

两个细节值得强调：`k <= 1` 的提前返回不是优化，是正确性需要——若 k = 1，while 循环会把窗口收缩到空，`prod` 变成 1 后仍 ≥ 1，会死循环或越界。用 `//` 而不是 `/` 是因为乘积始终是整数且能整除。

## 6. 复杂度

**时间 O(n)**：`right` 从 0 走到 n-1，贡献 n 次迭代；`left` 全程单调右移，最多也走 n 步。while 循环的总执行次数被 left 的总移动次数上界住，是 O(n) 而不是每轮 O(n)——这是「均摊分析」的典型场景。两层循环但总步数 2n，所以是 O(n)。

**空间 O(1)**：只用了 `prod`、`left`、`ans` 三个标量，没有随 n 增长的辅助结构。

对比一下：暴力 O(n²) 的 n 来自「每个左端点都要重新扫一遍右端点」；滑动窗口把这份重复扫描消掉，n 只出现一次。题目标签里的「二分查找 / 前缀和」是另一条思路（对前缀积取对数后二分），复杂度 O(n log n)，log n 来自每次二分，本题滑动窗口更优，不必走那条路。

## 7. 边界与反例（至少 4 条）

1. **`nums = [1,2,3], k = 0` → 0**。容易错在没处理 k ≤ 1：k=0 时任何乘积（≥1）都不小于 0，答案必为 0。若直接进循环，while 里 `prod >= 0` 恒真，left 会一路冲出数组边界。

2. **`nums = [1,1,1], k = 2` → 6**。全是 1，乘积永远是 1 < 2，窗口从不收缩，每轮贡献 `right-left+1`，累计 1+2+3 = 6。容易错在误以为「乘积不变就不用管」而漏加计数。

3. **`nums = [1,1,1], k = 1` → 0**。乘积恒为 1，`1 < 1` 不成立，一个都没有。这是 k ≤ 1 分支的另一个触发点，和第 1 条一起说明「严格小于」的等号方向不能写反（写成 `prod > k` 就错了）。

4. **`nums = [100], k = 100` → 0**。单元素乘积 100 不严格小于 100。容易错在把条件写成 `<=`，或忘记单元素也要过一遍 while 收缩。

5. **`nums = [10,5,2,6], k = 1000000` → 10**。k 远大于所有乘积，窗口从不收缩，答案就是全部子数组数 n(n+1)/2 = 10。容易错在把答案初始化成 0 后忘了每个 right 都要加，或误以为要特判。

## 8. 面试追问与变体（3 条）

1. **追问：如果 nums 里允许 0 怎么办？** 思路：0 会让乘积瞬间归零，单调性被破坏。可以把数组按 0 切段，每段内部仍全正、用滑动窗口；含 0 的子数组乘积为 0，只要 k > 0 就全部合法，单独计数。

2. **追问：如果要求「乘积恰好等于 k」的子数组个数？** 思路：滑动窗口只能处理「小于」这种单调阈值。恰好等于需要前缀积 + 哈希表（类似「和为 k 的子数组」），但乘积会溢出，得用对数或质因数分解，且 0 和 1 要特殊处理。

3. **追问：改成「和小于 k」呢？** 思路：元素若含负数，前缀和不再单调，滑动窗口失效，得用前缀和 + 二分或树状数组；若全为正，滑动窗口一字不改，把 `prod *=` 换成 `sum +=` 即可。

## 9. 举一反三（2-3 道同类题）

1. **209. 长度最小的子数组**：同样是「和 ≥ target 的最短窗口」，滑动窗口维护单调性，只是求的是最小长度而非计数。

2. **3. 无重复字符的最长子串**：窗口内维护「无重复」这一单调可维护的性质，left 收缩逻辑与本题同构，区别是判据用哈希集合而非乘积。

3. **992. K 个不同整数的子数组**：把「恰好 K 个」转成「至多 K 个 − 至多 K−1 个」，两次滑动窗口相减，是本题「计数型窗口」思路的进阶用法。
