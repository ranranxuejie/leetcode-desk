## 1. 一句话本质

在数组里找一对下标 `i < j`，使 `prices[j] - prices[i]` 最大，且结果不小于 0。

## 2. 读完题的第一反应

**朴素解法**：枚举所有买入日 `i` 和卖出日 `j`（`j > i`），算差值取最大。两层循环，时间复杂度 O(n²)。n 到 10⁵ 时就是 10¹⁰ 次运算，必然超时。瓶颈在于：对每个买入日，我们都在**重新扫描它后面所有价格**去找最大值，而这些扫描之间大量重复。

**关键观察**：固定某一天作为「卖出日」`j` 时，最优买入价一定是 `prices[0..j-1]` 里的**最小值**。也就是说，我根本不需要枚举买入日——只要一边往后走，一边记住「到目前为止见过的最低价格」，就能在 O(1) 时间内算出「今天卖能赚多少」。

这个观察之所以能让你想到下一步，是因为它把「二维的配对搜索」压成了「一维的单向扫描」：每个位置只需要两个信息——**历史最低价**和**当前最优利润**，两者都能随扫描增量更新。

## 3. 从暴力到最优

**暴力版**：

```python
best = 0
for i in range(n):
    for j in range(i + 1, n):
        best = max(best, prices[j] - prices[i])
```

瓶颈：内层循环对每个 `i` 都重扫一遍后缀，重复劳动。

**第一次优化（仍然 O(n²)，但思路变了）**：对每个卖出日 `j`，用 `min(prices[:j])` 算利润。这等价于暴力，但把「买入」从枚举变成了「求前缀最小值」——这一步是转折点。

**第二次优化（O(n)）**：前缀最小值可以增量维护。扫描到第 `j` 天时，`min_price` 已经记录了 `prices[0..j-1]` 的最小值，直接 `prices[j] - min_price` 就是「今天卖的最优利润」，然后更新 `min_price = min(min_price, prices[j])` 供后面用。

用示例 1 `[7,1,5,3,6,4]` 走一遍，初始 `min_price = 7`（第 0 天），`best = 0`：

| 天 j | prices[j] | 当天利润 = prices[j] - min_price | best | 更新后 min_price |
|---|---|---|---|---|
| 0 | 7 | —（第 0 天只能当买入日） | 0 | 7 |
| 1 | 1 | 1 - 7 = -6 | 0 | 1 |
| 2 | 5 | 5 - 1 = 4 | 4 | 1 |
| 3 | 3 | 3 - 1 = 2 | 4 | 1 |
| 4 | 6 | 6 - 1 = 5 | 5 | 1 |
| 5 | 4 | 4 - 1 = 3 | 5 | 1 |

最终 `best = 5`，对应第 1 天买、第 4 天卖。注意第 1 天利润是负数，`best` 保持 0——这正好处理了「不能盈利就返回 0」的要求，不需要额外判断。

再看示例 2 `[7,6,4,3,1]`：`min_price` 一路被刷新成 7→6→4→3→1，每天利润都是负的，`best` 始终为 0，输出 0。正确。

**为什么这个顺序不会出错**：先算利润、再更新 `min_price`，保证 `min_price` 永远来自「今天之前」的价格，绝不会出现「今天买今天卖」这种非法配对。这个顺序细节是很多人写错的地方。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义扫描到第 `j` 天（循环体执行前）时的不变量：

> `min_price` = `min(prices[0..j-1])`，`best` = 所有满足 `0 ≤ i < k ≤ j-1` 的配对中 `prices[k] - prices[i]` 的最大值（与 0 取大）。

**初始化**：`j = 1` 时，`min_price = prices[0]`，`best = 0`，不变量成立（此时没有合法配对，最大值按定义为 0）。

**归纳步**：假设第 `j` 天前不变量成立。第 `j` 天新增的合法配对，恰好是「以 `j` 为卖出日、以 `0..j-1` 中某天为买入日」的那些。这些配对的利润最大值是 `prices[j] - min(prices[0..j-1]) = prices[j] - min_price`。所以新的全局最优是 `max(旧 best, prices[j] - min_price)`，代码正是这么更新的。随后 `min_price` 更新为 `min(min_price, prices[j]) = min(prices[0..j])`，为下一天准备。不变量保持。

**终止**：扫描完所有天，`best` 覆盖了所有 `i < j` 的配对，且被 0 截断，正是题目所求。

**不会漏**：任意一对合法 `(i, j)`，在扫描到第 `j` 天时，`min_price ≤ prices[i]`，所以 `prices[j] - min_price ≥ prices[j] - prices[i]`，即该配对的利润被 `best` 的候选值「压住」了，不会漏掉更优解。**不会重**：每个 `j` 只贡献一次候选值，且候选值取的是该 `j` 下的最优买入，不重复计算同一对。

## 5. 完整代码（Python）

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        # 边界：空数组或单日无法交易，利润为 0
        if not prices:
            return 0

        min_price = prices[0]   # 历史最低买入价，初始为第 0 天
        best = 0                # 当前最大利润，天然处理"不能盈利返回 0"

        for j in range(1, len(prices)):
            # 先算：以今天为卖出日、历史最低价为买入日的利润
            profit = prices[j] - min_price
            if profit > best:
                best = profit
            # 后更新：把今天也纳入"历史最低价"的候选，供明天使用
            # 顺序不能反，否则会出现"今天买今天卖"的非法配对
            if prices[j] < min_price:
                min_price = prices[j]

        return best
```

## 6. 复杂度

- **时间 O(n)**：`for` 循环从 `j = 1` 走到 `n-1`，共 `n-1` 次迭代，每次迭代只做常数次比较和减法。n 来自 `prices` 的长度，没有嵌套循环，也没有排序带来的 log n。
- **空间 O(1)**：只用了 `min_price`、`best`、`profit` 三个标量变量，与 n 无关。没有开辟额外数组。

对比暴力 O(n²)：内层循环贡献了第二个 n，被「前缀最小值增量维护」消掉了。

## 7. 边界与反例（至少 4 条）

1. **输入 `[5]` → 输出 `0`**。只有一天，无法完成「买入后未来卖出」，循环一次都不进，`best` 保持 0。容易错在：有人写 `min_price = prices[0]` 后忘了处理单元素，或误以为要返回 `-1`。
2. **输入 `[7,6,4,3,1]` → 输出 `0`**。单调递减，每天利润都为负，`best` 从未被更新。容易错在：忘记用 `max(0, ...)` 截断，返回了负数（比如 `-1`）。
3. **输入 `[2,4,1]` → 输出 `2`**。最优是第 0 天买 2、第 1 天卖 4。容易错在：看到最后一天价格 1 最低，误以为「最低价买入」一定最优，但最低价出现在最后，后面没有卖出机会——这正是「先算利润后更新 min_price」要防的坑。
4. **输入 `[1,2]` → 输出 `1`**。最小规模的可盈利情形。容易错在：循环从 `j = 0` 开始，导致第 0 天自己减自己得 0，虽然结果碰巧对，但逻辑上把「当天买当天卖」算进去了，遇到其他用例会埋雷。
5. **输入 `[3,3,5,0,0,3,1,4]` → 输出 `4`**（第 3 天买 0、第 7 天卖 4）。容易错在：只盯着全局最低价 0，但 0 出现两次，要选「后面还有更高价」的那次——增量维护天然处理，手写「先找全局最低再找其后最高」则容易选错位置。

## 8. 面试追问与变体（3 条）

1. **追问：如果允许多次买卖（同一天不能同时持有两笔），最大利润是多少？** 思路：把问题拆成相邻两天的差分，所有正差分求和即可（题号 122）。因为「低买高卖」的区间可以无缝拼接，等价于吃掉每一段上涨。
2. **追问：如果最多只能交易 k 次，怎么做？** 思路：二维 DP，`dp[t][0/1]` 表示前若干天、已交易 t 次、当前是否持股的最大收益，按「买/卖/不动」转移（题号 188）。k = 1 时退化成本题。
3. **追问：如果允许买卖但有冷冻期（卖出后隔一天才能再买）？** 思路：状态机 DP，多一个「冷冻」状态，转移时从「冷冻」只能到「可买」（题号 309）。

## 9. 举一反三（2-3 道同类题）

- **53. 最大子数组和**：同样是「扫描时维护一个局部最优 + 全局最优」，把「历史最低价」换成「以当前元素结尾的最大和」，增量思想一致。
- **122. 买卖股票的最佳时机 II**：本题的「多次交易」版本，核心仍是单次扫描 + 增量累加，只是累加对象从「单笔最大差」变成「所有正差分」。
- **152. 乘积最大子数组**：扫描时同时维护「最大」和「最小」两个量（因为负数会翻转大小关系），和本题维护「最低价 + 最大利润」的双变量结构同源。
