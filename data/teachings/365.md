## 1. 一句话本质

在状态空间 `(a, b)`（a、b 分别为两壶当前水量）上做可达性判定：从 `(0,0)` 出发，只允许六种操作，问能否到达任意满足 `a + b == target` 的状态。

## 2. 读完题的第一反应

**朴素解法**：把每个 `(a, b)` 当成图上的一个节点，六种操作当成六条边，从 `(0,0)` 做 BFS/DFS，看能否碰到 `a + b == target`。状态总数是 `(x+1)(y+1)`，x、y ≤ 10³ 时最多约 10⁶ 个状态，每个状态 6 条边——能过，但很笨，而且面试官显然不满足于此。

**卡在哪**：状态空间是二维的，规模随 x、y 乘积增长。如果 x、y 放大到 10⁹，BFS 直接爆掉。所以瓶颈不在「搜索写得好不好」，而在「我们根本不需要搜索」。

**关键观察**：题目允许的操作里，只有「装满」和「倒空」会改变两壶的总水量，而每次改变的量恰好是 x 或 y 的整数倍；「互相倒水」只是把水在两壶之间搬运，总水量不变。于是任何时刻的总水量必然是 `ax + by` 的形式（a、b 为整数，可正可负——正代表净装满，负代表净倒空）。这就把问题从「图上的可达性」压缩成了「一个二元一次方程有没有整数解」，也就是数论里的裴蜀定理。

## 3. 从暴力到最优

**第一步：BFS 暴力。** 状态 `(a, b)`，六种转移：

1. 装满 A：`(x, b)`
2. 装满 B：`(a, y)`
3. 倒空 A：`(0, b)`
4. 倒空 B：`(a, 0)`
5. A 倒向 B：倒入量 `d = min(a, y - b)`，得 `(a - d, b + d)`
6. B 倒向 A：对称

用 `visited` 集合去重，碰到 `a + b == target` 就返回 True。复杂度 `O(xy)`。

**第二步：看出总水量的规律。** 拿示例 1（x=3, y=5, target=4）走一遍，只盯总水量 `s = a + b`：

| 操作 | 状态 (a,b) | s |
|---|---|---|
| 装满 B | (0,5) | 5 = 0·3 + 1·5 |
| B→A | (3,2) | 5（搬运，不变） |
| 倒空 A | (0,2) | 2 = −1·3 + 1·5 |
| B→A | (2,0) | 2（不变） |
| 装满 B | (2,5) | 7 = −1·3 + 2·5 |
| B→A | (3,4) | 7（不变） |
| 倒空 A | (0,4) | 4 = −2·3 + 2·5 |

每一步的总水量都是 `3` 和 `5` 的整系数线性组合。这不是巧合：装满 A 让 s 加 x，倒空 A 让 s 减 x，装满/倒空 B 让 s 加减 y，互相倒水让 s 不变。归纳可得：**任何可达状态的总水量都形如 `ax + by`（a, b ∈ ℤ）**。

**第三步：裴蜀定理收口。** 裴蜀定理说：`ax + by` 能取到的所有值，恰好是 `gcd(x, y)` 的所有整数倍。所以可达的总水量集合 ⊆ `{k·g : k ∈ ℤ}`，其中 `g = gcd(x, y)`。于是必要条件：`target % g == 0`。

**第四步：验证充分性。** 光有必要条件不够，还得说明「只要 target 是 g 的倍数，就真能倒出来」。这一步靠两个额外约束：

- `target ≤ x + y`：两壶总容量就这么多，超过不可能。
- `target ≥ 0`：题面 target ≥ 1，天然满足。

在这两个约束下，`target` 是 g 的倍数就充分。直观理由：反复执行「装满 B → 倒入 A → A 满了就倒空」这个循环，B 壶里剩下的水量会依次取遍 `y mod x, 2y mod x, ...`，即 `{0, g, 2g, ..., x−g}` 这些值（因为 y 与 x 的最大公约数是 g，y 在模 x 下的生成子群就是 g 的倍数）。所以只要 target 不超过单壶能凑出的范围、且是 g 的倍数，就能凑到；超过单壶时用两壶叠加（示例 3 就是 `1 + 2 = 3`）。

**结论**：`target <= x + y and target % gcd(x, y) == 0`。O(log min(x,y)) 一行搞定。

## 4. 正确性：为什么不会漏、不会重

**不漏（必要性）**：定义不变量 `I(s) = (s mod g == 0)`，其中 s 是两壶总水量。初始 s = 0，满足 I。六种操作对 s 的改动分别是 `+x, +y, −x, −y, 0, 0`，而 x、y 都是 g 的倍数，所以改动量是 g 的倍数，I 保持不变。因此任何可达状态的 s 都是 g 的倍数——target 不是 g 的倍数就绝无可能。同时 s 永远落在 `[0, x+y]`，target 超界也不可能。必要性得证。

**不重（充分性）**：要证「target ≤ x+y 且 target % g == 0」时一定可达。分两种情况：

- `target ≤ max(x, y)`：不妨设 `y ≥ x`。考虑循环「装满 y → 往 x 里倒 → x 满了就倒空 → 继续倒」。y 壶剩余水量序列为 `y mod x, 2y mod x, 3y mod x, ...`。由于 `gcd(x, y) = g`，序列 `{k·y mod x}` 恰好遍历 `{0, g, 2g, ..., x−g}`，所以任何不超过 x 的 g 的倍数都会在某个时刻出现在 y 壶里（此时 x 壶要么空要么满，总水量就是那个余数或余数加 x，两者都是 g 的倍数且覆盖了 `[0, x+y]` 内所有 g 的倍数）。target 是 g 的倍数且 ≤ x+y，故可达。
- `target > max(x, y)`：此时 target 必然 ≤ x+y，直接两壶都装满，总水量就是 x+y；若 target < x+y，先按上一种情况凑出 `target − x`（它是 g 的倍数且 ≤ y），再装满 x 壶叠加即可。

两种情况覆盖了所有合法输入，充分性得证。

## 5. 完整代码（Python）

```python
from math import gcd


class Solution:
    def canMeasureWater(self, x: int, y: int, target: int) -> bool:
        # 边界：两壶总容量都不够，直接不可能
        # （题面 target >= 1，但保留这个判断让函数对任意输入都正确）
        if target > x + y:
            return False

        # target 为 0 时不需要任何操作，视为可达
        if target == 0:
            return True

        # 裴蜀定理：ax + by 能表示的所有正整数恰为 gcd(x, y) 的倍数
        # 因此 target 必须是 gcd(x, y) 的倍数
        return target % gcd(x, y) == 0
```

> 注：`gcd(0, y) = y`，Python 的 `math.gcd` 已处理 0 的情况，所以即使 x 或 y 为 0 也不会崩。题面保证 x, y ≥ 1，这里只是防御性写法。

## 6. 复杂度

- **时间**：`O(log min(x, y))`。全部开销在 `gcd` 上，欧几里得算法每两步至少把较大数减半，迭代次数是 `O(log min(x, y))`。取模、比较都是 O(1)。注意这里**没有** n 的线性项——我们根本没遍历状态空间。
- **空间**：`O(1)`。只用了几个整型变量；`gcd` 的递归版是 `O(log min(x,y))` 栈深，迭代版（Python 标准库实现）是 O(1)。

对比 BFS 解法的 `O(xy)` 时间和 `O(xy)` 空间，差距的来源就是第 3 节那一步「把图搜索换成数论判定」。

## 7. 边界与反例（至少 4 条）

1. **`x=2, y=6, target=5` → False**。易错点：看到 5 在 `[0, 8]` 范围内就以为能凑，忘了 `gcd(2,6)=2`，奇数永远凑不出。这是示例 2，也是最典型的反例。
2. **`x=1, y=2, target=3` → True**。易错点：只检查「target 能否由单壶凑出」，漏掉两壶叠加的情况。`target == x + y` 时直接两壶装满即可，此时 `3 % gcd(1,2) = 3 % 1 = 0` 也通过。
3. **`x=3, y=5, target=8` → True**。易错点：`target > max(x,y)` 时误以为不可能。实际两壶都装满就是 8。代码里 `target > x + y` 的判断保证了 8 ≤ 8 不被误杀。
4. **`x=3, y=5, target=9` → False**。易错点：`9 % gcd(3,5) = 9 % 1 = 0`，取模判断通过，但总容量只有 8，物理上装不下。**必须先判 `target > x + y`**，顺序不能反。
5. **`x=1, y=1, target=2` → True**。易错点：`gcd(1,1)=1`，任何 target 都过取模，但 target=2 恰好等于 x+y，边界上容易把 `>` 写成 `>=` 而误判为 False。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求输出具体操作步骤，而不只是 True/False，怎么做？**
   思路：回到 BFS，在队列里存 `(a, b, 路径)` 或记录 `parent` 指针，找到目标状态后回溯。状态数 `O(xy)`，适合 x、y 不大的场景；数论解法只能判可行性，给不出路径。

2. **追问：如果允许第三个水壶，结论还成立吗？**
   思路：三个壶时总水量仍是 `ax + by + cz` 的整系数组合，裴蜀定理推广为 `gcd(x, y, z)` 的倍数，但「充分性」的构造更复杂（需要证明模运算能遍历所有余数），一般面试只要求说出「必要条件变成 gcd 三元组」即可。

3. **追问：如果每次倒水必须倒到某一壶空或满，但允许「只倒一半」这种部分操作呢？**
   思路：操作集合变了，状态空间不再是离散的有限图，裴蜀定理失效。此时问题退化为连续可达性，通常答案变成「target 在 `[0, x+y]` 内即可」（因为可以任意微调），需要重新建模。
