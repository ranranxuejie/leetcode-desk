## 1. 一句话本质

在数组里挑出一个子集，问它的元素和能不能恰好等于**总和的一半**——也就是一个「子集和恰好等于 target」的判定问题。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子集，看有没有哪个子集的和等于 `sum/2`。n 个元素有 2^n 个子集，n=200 时是天文数字，直接死。

**第一个关键观察**：两个子集和相等，意味着每个子集的和都等于 `sum/2`。所以问题从「分成两堆」塌缩成「能不能凑出 sum/2」——我们只需要关心**一个**子集，另一个自动成立。

**第二个关键观察**（决定能不能做）：如果 `sum` 是奇数，直接返回 false，因为整数和不可能等于小数。这一刀砍掉了近一半输入。

**第三个观察**（决定用什么算法）：每个元素只有「选」或「不选」两种状态，且选了的和不能超过 target。这是典型的**0-1 背包**形状：物品是数组元素，重量和价值都是 `nums[i]`，背包容量是 `target`，问能不能恰好装满。看到「每个元素用一次 + 目标和」就该条件反射想到 0-1 背包，而不是搜索。

## 3. 从暴力到最优

**第 0 步：暴力枚举子集**。对 `[1,5,11,5]`，sum=22，target=11。枚举 16 个子集，发现 `{11}` 和 `{1,5,5}` 都等于 11。复杂度 O(2^n)，n=200 不可行。

**第 1 步：DFS + 剪枝**。从前往后决定每个数选不选，维护当前和 `cur`，`cur > target` 就剪枝。这能过不少数据，但最坏情况（大量小数字、target 很大）仍然是指数级，比如 `[1,1,1,...,1]`（200 个 1）target=100，搜索树巨大。瓶颈在于：**不同的选择路径会到达同一个 `(下标, cur)` 状态，却被重复计算**。

**第 2 步：记忆化，把状态压成二维**。定义 `dp[i][j]` = 用前 i 个元素能否凑出和 j。转移：

```
dp[i][j] = dp[i-1][j]            # 不选 nums[i-1]
         or dp[i-1][j-nums[i-1]] # 选，前提 j >= nums[i-1]
```

拿 `nums=[1,5,11,5]`, target=11 走一遍（只列关键格子）：

- 初始化 `dp[0][0]=True`，其余 False。
- 处理 1：`dp[1][0]=T, dp[1][1]=T`。
- 处理 5：`dp[2][0]=T, dp[2][1]=T, dp[2][5]=T, dp[2][6]=T`。
- 处理 11：`dp[3][11] = dp[2][11] or dp[2][0] = F or T = T`。**此时已经能判定 true**。
- 处理第二个 5：`dp[4][11] = dp[3][11] or dp[3][6] = T`。

状态数 `n × target`，每个 O(1) 转移，复杂度 O(n·target)。n=200、target≤10000 时约 2×10^6，可过。

**第 3 步：滚动数组压成一维**。观察转移只依赖上一行 `i-1`，所以二维可以压成一维。但**必须倒序遍历 j**：因为 `dp[j]` 要用到「上一轮的 `dp[j-num]`」，如果正序，`dp[j-num]` 可能已经被本轮更新过，等于同一个元素被用了两次（变成完全背包）。倒序保证读到的是旧值。

一维转移：`dp[j] = dp[j] or dp[j-num]`，j 从 target 倒着走到 num。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在第 i 轮循环结束后，`dp[j] == True` 当且仅当「存在一个子集，只由前 i 个元素组成，其和恰好为 j」。

**归纳证明**：
- 基础：i=0 时只有空集，和为 0，`dp[0]=True`，其余 False，成立。
- 归纳：考虑第 i 个元素 x。任何由前 i 个元素组成的、和为 j 的子集，要么不含 x（对应 `dp[j]` 旧值），要么含 x（去掉 x 后是前 i-1 个元素中和为 j-x 的子集，对应 `dp[j-x]` 旧值）。两种情况恰好覆盖全部，且互斥，所以 `dp[j] = 旧dp[j] or 旧dp[j-x]` 不漏不重。
- **倒序为什么正确**：倒序遍历时，计算 `dp[j]` 用到的 `dp[j-x]` 中 `j-x < j`，还没被本轮碰过，仍是「前 i-1 个元素」的旧值，正好对应「含 x 时去掉 x」的语义。若正序，`dp[j-x]` 已是「前 i 个元素」的值，语义变成 x 可重复使用，错误。

最终 `dp[target]` 为 True 即答案。

## 5. 完整代码（Python）

```python
class Solution:
    def canPartition(self, nums: list[int]) -> bool:
        total = sum(nums)
        # 总和为奇数，两个整数子集和不可能相等
        if total % 2 == 1:
            return False
        target = total // 2

        # dp[j] 表示：用已处理的元素能否凑出和 j
        dp = [False] * (target + 1)
        dp[0] = True  # 空集凑出 0

        for num in nums:
            # 倒序遍历：保证 dp[j-num] 是上一轮（不含当前 num）的值，
            # 从而每个元素最多用一次（0-1 背包）
            for j in range(target, num - 1, -1):
                dp[j] = dp[j] or dp[j - num]
            # 提前返回：已经能凑出 target，无需继续
            if dp[target]:
                return True

        return dp[target]
```

## 6. 复杂度

- **时间 O(n · target)**：外层遍历 n 个元素，内层对每个元素最多扫 target 个 j，每次 O(1) 的布尔或运算。`target = sum/2`，所以也可写成 O(n · sum)。注意 target 不是 n 的函数，是**数值大小**，这是伪多项式复杂度——sum 很大时（比如元素值到 10^9）这个 DP 会爆，但本题 sum ≤ 200×100 = 20000，安全。
- **空间 O(target)**：一维 dp 数组长度 target+1。二维版本是 O(n·target)，滚动数组把「行」这一维消掉了，因为转移只依赖上一行。
- 没有 log 项：本题不涉及排序或二分，所有操作都是线性扫描。

## 7. 边界与反例（至少 4 条）

1. `nums = [1]` → 期望 false。总和 1 是奇数，直接返回。容易错在忘了奇偶判断，进入 DP 后 target=0，`dp[0]=True` 会误返回 true。
2. `nums = [2,2,2]` → 期望 false。总和 6，target=3，但所有元素是偶数，凑不出奇数 3。容易错在只判断奇偶总和，没意识到 target 可能无法由元素组合达成。
3. `nums = [1,2,5]` → 期望 false。总和 8，target=4，子集和只有 0,1,2,3,5,6,7,8，没有 4。容易错在以为「总和偶数就能分」。
4. `nums = [1,1]` → 期望 true。target=1，一个 1 即可。容易错在倒序循环写成 `range(target, num)` 漏掉 `num` 本身，导致 `dp[1]` 永远不更新。
5. `nums = [100,100,100,100]` → 期望 true（两个 200）。target=200，需要选两个 100。容易错在正序遍历 j，导致一个 100 被重复用，`dp[200]` 在只处理一个 100 时就变 true，逻辑上错但答案碰巧对——这类 bug 在别的用例上会暴露。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回具体的两个子集，而不只是 true/false？** 思路：额外维护 `parent[i][j]` 记录 `dp[i][j]` 是从「不选」还是「选」转移来的，最后从 `dp[n][target]` 回溯出选中的元素，剩下的就是另一堆。
2. **追问：如果元素可以是负数呢？** 思路：target 可能为负，dp 下标不能直接用，需要偏移量或改用哈希表存可达和；同时「总和一半」的剪枝失效，问题变成一般子集和，NP-hard，只能搜索+剪枝。
3. **追问：如果每个元素可以用无限次（完全背包）？** 思路：内层 j 改成正序遍历，`dp[j] = dp[j] or dp[j-num]`，因为允许重复使用当前元素。

## 9. 举一反三（2-3 道同类题）

- **494. 目标和**：给每个数加正负号使和为 target，本质是「选一个子集和为 (sum+target)/2」的 0-1 背包计数，和本题只差「求方案数」而非「可行性」。
- **1049. 最后一块石头的重量 II**：把石头分成两堆使差最小，等价于「子集和尽量接近 sum/2」，是本题的优化版（不求恰好等于，求最接近）。
- **322. 零钱兑换**：凑出金额的最少硬币数，同样是「容量 + 选/不选」的背包骨架，区别是完全背包 + 求最小值。
