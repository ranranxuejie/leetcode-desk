## 1. 一句话本质

在一堆「成对出现」的数里，把那个落单的数揪出来——本质是**用异或运算的「成对抵消」性质，把配对关系当作可消去的噪声**。

## 2. 读完题的第一反应

**朴素解法**：最直接的是用哈希表（字典）统计每个数出现次数，最后挑出计数为 1 的那个。时间 O(n)，但空间 O(n)——题目明确要求「常量额外空间」，这条路直接被堵死。

另一个朴素想法是排序后两两比较：排序后相同的数一定相邻，扫描一遍找那个「和左右都不相等」的元素。时间 O(n log n)，空间 O(1)（原地排序），但违反「线性时间」要求。

**关键观察**：题目给了两个强约束——「其余每个元素出现两次」+「线性时间 + 常量空间」。这两个条件合起来，几乎是在明示你去找一种**满足结合律、且 x 与自身运算结果为「单位元」**的运算。因为只有这种运算，才能让「成对的数」在累积过程中自动消失，而落单的数留下来。

满足这个性质的运算里，最经典的就是**按位异或（XOR）**：`a ^ a = 0`，`a ^ 0 = a`，且异或满足交换律和结合律。这意味着无论数组顺序如何，把所有数异或起来，成对的会两两抵消成 0，最后剩下的就是那个只出现一次的数。

这一步的推理链条是：**「成对」→ 需要「自消」的运算 → 异或**。不是背结论，而是从约束反推出工具。

## 3. 从暴力到最优

**第一步：哈希计数**
遍历数组，`count[x] += 1`，最后找 `count[x] == 1` 的键。
瓶颈：额外空间 O(n)，不满足题目要求。

**第二步：排序后扫描**
`nums.sort()`，然后从下标 0 开始每次跳 2 格比较 `nums[i] != nums[i+1]`，不等则 `nums[i]` 是答案（注意处理最后一个元素单独的情况）。
瓶颈：排序 O(n log n)，不满足线性时间。

**第三步：异或累积**
维护一个变量 `ans = 0`，遍历每个数执行 `ans ^= x`。

用示例 2 `[4,1,2,1,2]` 走一遍，写出中间值：

| 步骤 | 当前 x | ans 运算 | ans 值 |
|------|--------|----------|--------|
| 初始 | —      | —        | 0      |
| 1    | 4      | 0 ^ 4    | 4      |
| 2    | 1      | 4 ^ 1    | 5      |
| 3    | 2      | 5 ^ 2    | 7      |
| 4    | 1      | 7 ^ 1    | 6      |
| 5    | 2      | 6 ^ 2    | 4      |

最终 `ans = 4`，正是答案。注意中间值 5、7、6 看起来「乱七八糟」，但这不是问题——异或的交换律保证：`4^1^2^1^2 = 4^(1^1)^(2^2) = 4^0^0 = 4`。中间过程不需要有语义，只要最终配对能抵消即可。

**瓶颈是怎么被消掉的**：哈希表需要「记住」每个数出现几次，所以必须开 O(n) 空间；而异或把「计数」压缩成了一个整数——`a^a=0` 相当于「出现两次就归零」，不需要记录具体是谁出现了几次。空间从 O(n) 降到 O(1)，时间从 O(n log n) 降到 O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证。

设数组为 `nums[0..n-1]`，其中恰有一个元素 `s` 出现一次，其余元素各出现两次。定义不变量：

> **在处理完前 k 个元素后，`ans` 等于「前 k 个元素中所有出现奇数次的元素的异或和」。**

**初始**：k=0，`ans=0`，空集的异或和为 0，成立。

**归纳**：假设处理完前 k 个元素后不变量成立。处理第 k+1 个元素 `x` 时，执行 `ans ^= x`。分两种情况：
- 若 `x` 在前 k 个元素中出现过偶数次（含 0 次），则加入 `x` 后它变为出现奇数次，异或和应「加上」x，而 `ans ^ x` 正好做到这一点；
- 若 `x` 在前 k 个元素中出现过奇数次，则加入后变为偶数次，应从异或和中「去掉」x，而 `ans ^ x` 同样做到（因为 `x ^ x = 0`）。

两种情况都保持不变量，归纳成立。

**终止**：处理完全部 n 个元素后，`ans` 等于「所有出现奇数次的元素的异或和」。由题设，只有 `s` 出现奇数次（一次），其余都出现偶数次（两次），所以 `ans = s`。

这个证明同时说明了「不会漏」（s 一定被计入）和「不会重」（成对的元素异或后归零，不会残留）。

## 5. 完整代码（Python）

```python
class Solution:
    def singleNumber(self, nums: list[int]) -> int:
        # ans 初始为 0：0 是异或运算的单位元，任何数 ^ 0 = 自身
        ans = 0
        for x in nums:
            # 核心：成对的数会两两抵消为 0，落单的数最终留下
            # 利用异或的交换律和结合律，遍历顺序不影响结果
            ans ^= x
        return ans
```

如果面试官允许用库函数，也可以写成一行 `return reduce(lambda a, b: a ^ b, nums, 0)`，但手写循环更能体现你理解「累积」的过程，建议默认写循环版本。

## 6. 复杂度

**时间 O(n)**：循环体执行 n 次（n = `len(nums)`），每次做一次整数异或，是 O(1) 的基本操作。没有嵌套循环，没有排序，所以总时间是 n × O(1) = O(n)。这里没有 log n 的来源——因为没排序、没二分。

**空间 O(1)**：只用了 `ans` 一个整型变量。注意 Python 的整数是任意精度的，`ans` 的位宽取决于输入数值范围（题面给的是 ±3×10⁴，约 16 位），是常数级别，不随 n 增长。循环变量 `x` 也是常数空间。没有开辟任何与 n 相关的容器。

对比：哈希法时间 O(n) 但空间 O(n)；排序法空间 O(1)（原地）但时间 O(n log n)。异或法同时拿到两个最优。

## 7. 边界与反例（至少 4 条）

1. **输入 `[1]` → 期望 `1`** → 容易错在：如果代码写成「先取前两个比较」或假设数组长度至少为 3，会越界或逻辑错乱。异或法天然处理：`0 ^ 1 = 1`。

2. **输入 `[0]` → 期望 `0`** → 容易错在：把「答案非零」当默认假设，或者用 `if ans:` 判断是否找到答案，会把 0 误判为「没找到」。异或法返回 0 是正确的，不要加多余的非零判断。

3. **输入 `[-1, -1, -2]` → 期望 `-2`** → 容易错在：以为异或只对非负数有效。实际上 Python 的负数以补码形式参与位运算，`-1 ^ -1 = 0` 依然成立，结果正确。但如果你手写 C 风格代码并假设无符号，可能出问题。

4. **输入 `[2, 2, 1, 1, 3]` → 期望 `3`** → 容易错在：误以为「落单的数一定在末尾」或「一定在奇数下标」，写出依赖位置的错误逻辑。异或法与位置无关，这是它的优势。

5. **输入 `[1, 2, 1, 2, 3]`（落单数在末尾）→ 期望 `3`** → 容易错在：排序法如果只比较相邻对，末尾单元素需要单独处理，容易漏掉 `nums[-1]` 的情况。异或法无此问题。

## 8. 面试追问与变体（3 条）

1. **追问：如果「其余元素出现三次」，只有一个出现一次，怎么办？** → 思路：异或不再适用（三次不会抵消）。改用「按位统计」：对 32 个二进制位分别统计 1 的个数，对 3 取模，余数拼起来就是答案。时间 O(32n) = O(n)，空间 O(1)。

2. **追问：如果有「两个」元素各出现一次，其余出现两次，怎么找出这两个？** → 思路：先全部异或得到 `a^b`（非零），取 `a^b` 最低位的 1 作为分组依据，把数组分成两组分别异或，得到 a 和 b。这是本题的直接升级版（力扣 260）。

3. **追问：不用异或，还能怎么做到 O(1) 空间？** → 思路：数学法——用 `set` 求和 `2*sum(set) - sum(nums)` 得到答案，但 `set` 是 O(n) 空间，不满足；真正 O(1) 的替代很少，异或是这道题「量身定做」的解法，可以借此说明「为什么异或是唯一自然的 O(1) 方案」。

## 9. 举一反三（2-3 道同类题）

1. **力扣 137. 只出现一次的数字 II** → 共同点：同样是「找落单元素」，但重复次数变成 3 次，异或失效，需要按位取模统计。

2. **力扣 260. 只出现一次的数字 III** → 共同点：两个落单元素，核心仍是异或，但要多一步「按某一位分组」的技巧。

3. **力扣 268. 丢失的数字** → 共同点：用异或把「下标 0..n」和「数组元素」全部异或，配对抵消后剩下的就是缺失的数，是异或「自消」性质的另一经典应用。
