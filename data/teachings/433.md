## 1. 一句话本质

在一个「只含合法基因序列」的图里，求从起点到终点的**最短路径边数**——每个基因是节点，两个基因只差一个字符就连一条边。

## 2. 读完题的第一反应

**朴素解法**：把 bank 里所有基因两两比较，差一个字符就连边，建出整张图，然后从 start 做 BFS 找 end。卡在哪？bank 长度最多 10，两两比较是 O(|bank|² × 8)，其实完全跑得动。但真正的问题不是建图，而是**你不知道从 start 出发该往哪走**——如果只盯着 bank 里的现成基因去连边，你会漏掉「start 本身不在 bank 里」这个事实（题面明确说了 start 默认有效但可能不在 bank 中），而且「差一个字符」这个关系需要你主动去枚举，而不是被动等 bank 给你。

**关键观察**：每个基因长度固定为 8，字符集只有 4 个（A/C/G/T）。所以对任意一个基因，**它所有可能的邻居最多只有 8 × 3 = 24 个**（每一位换成另外 3 种字符）。这个数字是常数，跟 bank 多大无关。于是「找邻居」这件事从「扫描整个 bank」变成了「枚举 24 个候选，查一下在不在 bank 里」。用哈希集合存 bank，单次查询 O(1)，一次扩展就是 O(24)。

这一步观察直接把我们引向 BFS：既然每次扩展的代价是常数，且要求「最少变化次数」，那就是无权图最短路，BFS 天然按层扩展，第一次碰到 end 就是最短。

## 3. 从暴力到最优

**暴力版**：对当前基因，遍历 bank 中每个基因，逐字符比较是否只差一位。每次扩展 O(|bank| × 8)。BFS 总共扩展 |bank| 个节点，总代价 O(|bank|² × 8)。bank ≤ 10 时无所谓，但这是「靠数据小」而不是「靠算法对」。

**优化版**：把 bank 转成 `set`。对当前基因的每一位，枚举另外 3 个字符，拼成新串，`if 新串 in bank_set` 就入队。每次扩展固定 8 × 3 = 24 次哈希查询。

**小例子走一遍**（示例 2）：

- start = `AACCGGTT`，end = `AAACGGTA`，bank = {`AACCGGTA`, `AACCGCTA`, `AAACGGTA`}
- 队列初始 `[AACCGGTT]`，`visited = {AACCGGTT}`，`steps = 0`
- 第 0 层弹出 `AACCGGTT`，枚举 24 个邻居，命中 bank 的有：
  - 第 7 位 T→A 得 `AACCGGTA`（在 bank 里）→ 入队
  - 第 5 位 G→C 得 `AACCGCTA`（在 bank 里）→ 入队
  - 其余 22 个不在 bank，丢弃
- `steps = 1`，队列 `[AACCGGTA, AACCGCTA]`
- 第 1 层弹出 `AACCGGTA`，枚举邻居，命中 `AAACGGTA`（第 3 位 C→A）→ 入队，此时 `steps` 将变 2
- 弹出 `AAACGGTA`，等于 end，返回 2 ✓

注意 `AACCGGTA` 和 `AACCGCTA` 之间也差一位，但它们同层，BFS 不会重复走——`visited` 挡住了。

**为什么 BFS 而不是 DFS**：DFS 也能找到一条路径，但找到的不一定最短，你得把所有路径都试一遍取最小，退化成指数级。BFS 按「变化次数」分层，第 k 层就是「恰好 k 次变化能到达的所有基因」，第一次遇到 end 必然是最小 k。

## 4. 正确性：为什么不会漏、不会重

**不漏**：设从 start 到 end 的最短变化次数为 d。归纳证明 BFS 第 k 层恰好包含所有「从 start 出发、恰好 k 次合法变化可达、且未被更早层访问过」的基因。k=0 时只有 start 本身。假设第 k 层正确，第 k+1 层由第 k 层每个节点枚举全部 24 个单字符变化、筛出在 bank 中的得到——这恰好是「k+1 次变化可达」的全部候选，因为任何 k+1 步路径的第 k 步终点必在第 k 层，第 k+1 步必是它的某个单字符邻居。所以 end 若可达，必在某个第 d 层被访问到，不会漏。

**不重**：`visited` 集合保证每个基因最多入队一次。关键论点是：**BFS 中一个节点第一次被访问时，所走的步数就是它到 start 的最短距离**。因为 BFS 按层推进，若存在更短路径，那个节点会在更早的层被枚举到并入队，`visited` 会先记下它，后来的更长路径会被 `if 新串 not in visited` 挡掉。所以每个节点只处理一次，且处理时的步数是最优的。

**边界前提**：start 本身可能不在 bank，但题面说它默认有效，所以 start 可以作为 BFS 起点，不需要在 bank 里。end 若不在 bank 且不等于 start，则永远无法到达（因为变化后的基因必须在 bank 中），直接返回 -1。

## 5. 完整代码（Python）

```python
from collections import deque

class Solution:
    def minMutation(self, startGene: str, endGene: str, bank: list[str]) -> int:
        # end 不在 bank 且不等于 start，永远到不了
        # （start 默认有效，但 end 必须出现在 bank 里才能作为"变化后"的基因）
        bank_set = set(bank)
        if endGene not in bank_set and endGene != startGene:
            return -1

        chars = "ACGT"
        visited = {startGene}
        q = deque([(startGene, 0)])  # (当前基因, 已用变化次数)

        while q:
            gene, steps = q.popleft()
            if gene == endGene:
                return steps

            # 枚举每一位换成另外 3 个字符，共 8 * 3 = 24 个候选
            for i in range(len(gene)):
                for c in chars:
                    if c == gene[i]:
                        continue
                    nxt = gene[:i] + c + gene[i+1:]
                    # 必须在 bank 中，且没访问过
                    if nxt in bank_set and nxt not in visited:
                        visited.add(nxt)
                        q.append((nxt, steps + 1))

        return -1  # 队列空了还没碰到 end，不可达
```

几个容易写错的点，代码里已经处理：`endGene == startGene` 时直接返回 0（虽然题面示例没给，但逻辑上成立，且 `endGene not in bank_set` 的提前返回不能误杀这种情况）；`visited` 在入队时就加，不是出队时加，否则同一层会有重复入队。

## 6. 复杂度

设基因长度为 L = 8（题面固定），bank 大小为 B ≤ 10，字符集大小 C = 4。

- **时间**：每个基因最多入队一次，共 O(B) 个节点（加上 start）。每个节点枚举 L × (C-1) 个候选，每个候选做一次哈希查询 O(L)（字符串哈希要扫一遍，但 L 是常数）。所以总时间 O(B × L × C × L) = O(B × L² × C)。代入常数就是 O(B)。如果按一般化写：O(B × L × C × L)，其中 B 来自节点数，L×C 来自每节点枚举量，最后一个 L 来自字符串拼接和哈希。
- **空间**：`visited` 和队列各存 O(B) 个长度为 L 的字符串，bank_set 存 O(B) 个字符串。总空间 O(B × L)。

注意这里**没有 log n**——没有排序、没有二分，全是哈希和常数枚举。面试时如果被问「为什么不是 O(B log B)」，答案是：我们没排序，哈希集合的均摊查询是 O(1)。

## 7. 边界与反例（至少 4 条）

1. **start == end** → 期望 0。容易错在：先判断 `endGene not in bank_set` 就返回 -1，把这种情况误杀。代码里用 `and endGene != startGene` 兜住。
2. **end 不在 bank 里**（且不等于 start）→ 期望 -1。容易错在：忘记这个前置判断，BFS 跑完整个可达集才发现到不了，虽然结果对但多跑；更隐蔽的错是以为 start 在 bank 里就能到 end，忽略了「变化后必须在 bank」。
3. **bank 为空** → 期望 -1（除非 start == end）。容易错在：`bank_set` 为空时 BFS 第一层枚举 24 个候选全部 `not in bank_set`，队列空，返回 -1，逻辑对；但如果提前判断写反了会崩。
4. **start 不在 bank 但 end 在 bank，且路径需要经过 start 的邻居** → 期望正常返回步数。容易错在：把 start 也塞进 bank_set 去判断，或者反过来要求 start 必须在 bank 里才启动 BFS。题面明确 start 默认有效、不一定在 bank。
5. **bank 里有 end 但和 start 差不止一位、且中间没有桥接基因** → 期望 -1。容易错在：只判断「end 在 bank」就返回 1，没真正跑 BFS 验证连通性。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回具体的变化路径而不只是次数，怎么改？** 思路：BFS 时记录每个节点的前驱（`parent[nxt] = gene`），到达 end 后从 end 沿 parent 回溯到 start，反转即得路径。
2. **追问：如果 bank 很大（比如 10⁵），还能这么做吗？** 思路：仍然可以，因为每节点枚举量是常数 24，总时间 O(B × L²)，瓶颈变成哈希集合的内存；若内存吃紧可改用双向 BFS，从 start 和 end 同时扩展，层数减半，实际访问节点数大幅下降。
3. **追问：如果允许一次变化改两个字符，怎么做？** 思路：邻居定义变了，枚举量变成 C(8,2) × 3² 量级，仍是常数，BFS 框架不变；但要重新论证「邻居数常数」这个前提是否还成立（成立，因为 L 固定）。

## 9. 举一反三（2-3 道同类题）

- **127. 单词接龙**：同样是「每次改一个字符、只能在字典内变、求最短变化次数」，只是字符集从 4 变成 26、长度不固定，BFS + 枚举替换的骨架完全一致。
- **752. 打开转盘锁**：状态是 4 位数字，每次拨一位 ±1，求从 `0000` 到 target 的最少步数，且要避开 deadends——本质是同一张「隐式图」上的 BFS，邻居枚举方式不同而已。
- **1091. 二进制矩阵中的最短路径**：网格上 8 方向移动求最短路，和本题共享「无权图 BFS 按层扩展、第一次到达即最短」的核心不变量，只是邻居从「改字符」变成「走格子」。
