## 1. 一句话本质

在**有重复元素的数组**里，枚举所有「和为 target 且元素下标互不相同」的子集，同时把「值相同但下标不同」产生的重复解去重。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子集（每个元素选或不选），筛出和为 target 的。复杂度 O(2^n)，n=100 时完全不可行。而且即使跑得动，`[1,1,6]` 会因为两个 1 来自不同下标被枚举两次，还得额外去重。

**关键观察**：题目要的是「组合」而不是「排列」，这意味着我们可以规定一个**顺序**——只允许按下标递增的顺序选元素。这样每个组合只被生成一次，天然消除排列层面的重复。这是所有组合类回溯的公共骨架。

但本题多了一层麻烦：`candidates` 里有重复值。示例 1 中 `[10,1,2,7,6,1,5]` 有两个 1，示例 2 中 `[2,5,2,1,2]` 有三个 2。排序后重复值相邻，于是「同一层递归里，值相同的分支只走第一个」就能砍掉值层面的重复。**排序是让这个剪枝可实现的必要前提**——不排序，重复值不相邻，你没法用「和前一个比」来判断。

所以整道题的思路链是：组合 → 按下标递增选 → 排序让重复值相邻 → 同层跳过重复值。

## 3. 从暴力到最优

**第一步：子集枚举 → 按下标递增的回溯**

维护 `start` 指针，每层从 `start` 往后选，选完把 `i+1` 传给下一层。这样 `[1,2]` 和 `[2,1]` 只会出现前者。节点数从 2^n 降到「所有组合数」，但重复值问题没解决。

**第二步：排序 + 同层去重**

以示例 2 走一遍：`candidates = [2,5,2,1,2]`，`target = 5`。

排序后 `candidates = [1,2,2,2,5]`。

从 `start=0` 开始，`path=[]`，`remain=5`：

- 选 `i=0`，值 1，`path=[1]`，`remain=4`，下一层 `start=1`。
  - 选 `i=1`，值 2，`path=[1,2]`，`remain=2`，下一层 `start=2`。
    - 选 `i=2`，值 2，`path=[1,2,2]`，`remain=0` → **记录 `[1,2,2]`**。
    - `i=3` 值也是 2，但 `i>start` 且 `candidates[3]==candidates[2]`，**跳过**。若不跳，会再生成一次 `[1,2,2]`。
    - `i=4` 值 5，`remain` 变负，剪枝。
  - 回到 `start=1` 层，`i=2` 值 2，`i>1` 且 `candidates[2]==candidates[1]`，**跳过**。这就是「同层去重」：在 `start=1` 这一层，值 2 的分支已经由 `i=1` 走过了，`i=2`、`i=3` 是同一个值的重复分支。
- 回到 `start=0` 层，`i=1` 值 2，`path=[2]`，`remain=3`，下一层 `start=2`。
  - `i=2` 值 2，`path=[2,2]`，`remain=1`，下一层 `start=3`。
    - `i=3` 值 2，`remain` 变负，剪枝。
    - `i=4` 值 5，剪枝。
  - `i=3` 值 2，`i>2` 且与前一个相同，跳过。
  - `i=4` 值 5，`remain` 变负，剪枝。
- `i=2`、`i=3` 在 `start=0` 层都是值 2，与前一个相同，跳过。
- `i=4` 值 5，`path=[5]`，`remain=0` → **记录 `[5]`**。

结果 `[[1,2,2],[5]]`，和期望一致。注意 `[1,2,2]` 里两个 2 分别来自下标 1 和 2（或 1 和 3、2 和 3），但只保留了下标最小的那条路径——这正是「同层去重」的效果：**同一层只允许同一个值出现一次，但不同层可以重复使用同一个值**（因为不同层对应不同的下标位置）。

**第三步：排序带来的额外剪枝**

排序后如果 `candidates[i] > remain`，后面的元素只会更大，直接 `break`。这是排序的第二个红利。

## 4. 正确性：为什么不会漏、不会重

**不漏**：任何合法组合 `[a_1 ≤ a_2 ≤ ... ≤ a_k]`（排序后）都对应 `candidates` 中一组递增下标 `i_1 < i_2 < ... < i_k`。回溯时每层从 `start` 往后扫，只要该下标的值没被「同层去重」跳过，就会被选中。被跳过的唯一情况是「同层前面已有一个同值的下标被选过」——此时用前面的下标替换当前下标，得到的组合值完全相同，所以该组合仍然被生成。归纳下去，每个合法组合至少被生成一次。

**不重**：假设两个不同的下标序列生成同一个值序列。由于每层按下标递增选，两个序列的第一个不同位置 `j` 满足 `i_j ≠ i'_j` 但 `candidates[i_j] == candidates[i'_j]`。不妨 `i_j < i'_j`。在生成第二个序列的那次递归中，`i'_j` 与 `i_j` 同层（`start` 相同），且 `i'_j > start`、`candidates[i'_j] == candidates[i_j]`，触发同层去重条件被跳过。矛盾。所以每个值组合只生成一次。

**不变量**：递归进入 `dfs(start, remain)` 时，`path` 中所有元素来自下标 `< start`，且 `sum(path) + remain == target`。每层选 `i ≥ start` 后传 `i+1`，不变量保持。`remain == 0` 时记录，`remain < 0` 时剪枝，保证记录的都是精确解。

## 5. 完整代码（Python）

```python
class Solution:
    def combinationSum2(self, candidates: list[int], target: int) -> list[list[int]]:
        candidates.sort()          # 排序：让重复值相邻，同时支持 remain 剪枝
        res = []
        path = []

        def dfs(start: int, remain: int) -> None:
            if remain == 0:        # 精确凑到 target，记录当前路径
                res.append(path.copy())
                return
            for i in range(start, len(candidates)):
                # 同层去重：i > start 保证不是本层第一个，
                # 与前一个值相同说明该值的分支已经走过，跳过
                if i > start and candidates[i] == candidates[i - 1]:
                    continue
                # 排序后当前值已超过剩余目标，后面只会更大，直接结束本层
                if candidates[i] > remain:
                    break
                path.append(candidates[i])
                dfs(i + 1, remain - candidates[i])   # i+1：每个下标只能用一次
                path.pop()         # 回溯，恢复现场

        dfs(0, target)
        return res
```

关键点说明：`i > start` 而不是 `i > 0`——这是「同层」去重，不是「全局」去重。如果写成 `i > 0`，会把不同层使用相同值的情况也误杀（比如 `[1,1,6]` 里第二个 1 在下一层，`i > 0` 会错误跳过它）。`break` 而不是 `continue`——因为已排序，后面的元素只会更大，没必要再试。

## 6. 复杂度

设 n = `len(candidates)`，答案个数为 R，每个答案平均长度 L。

**时间**：O(n log n + R · L + 搜索树节点数)。排序 O(n log n)。搜索树最坏情况下每个节点对应一次 `path.copy()` 或一次循环迭代，节点数上界是 O(2^n)（最坏无剪枝时），但实际受 `remain` 剪枝和同层去重约束，通常远小于此。面试中标准回答是「最坏 O(2^n · n)」——2^n 是子集枚举上界，乘 n 是每个解拷贝路径的代价。注意 `n log n` 来自排序，`2^n` 来自回溯，两者独立。

**空间**：O(n) 递归栈深度（最坏选满 n 个元素）+ O(L) 路径 + O(R · L) 结果存储。递归栈和路径是辅助空间，结果存储不计入通常意义的空间复杂度。

## 7. 边界与反例

1. **`candidates = [1,1], target = 2`** → 期望 `[[1,1]]`。容易错：同层去重写成 `i > 0` 会跳过第二个 1，漏掉唯一解。必须 `i > start`。
2. **`candidates = [1,1,1], target = 2`** → 期望 `[[1,1]]`。三个 1 两两组合值相同，只保留一组。容易错：只做一次去重不够，`i > start` 条件在每层都生效才能保证。
3. **`candidates = [2], target = 1`** → 期望 `[]`。容易错：`candidates[i] > remain` 的 `break` 在第一个元素就触发，循环直接结束，返回空列表——正确。若写成 `continue` 也能过，但效率差。
4. **`candidates = [1,2], target = 4`** → 期望 `[]`。容易错：`remain` 永远到不了 0，递归自然返回空。检查 `remain < 0` 的剪枝是否覆盖所有路径。
5. **`candidates = [5,5,5], target = 10`** → 期望 `[[5,5]]`。容易错：三个 5 选两个，值组合只有一种。同层去重保证 `start=0` 层只走第一个 5，`start=1` 层只走第二个 5，生成一次 `[5,5]`。

## 8. 面试追问与变体

1. **追问：如果 candidates 无重复，代码怎么简化？** 思路：去掉排序后的同层去重条件 `if i > start and ...`，其余不变；排序仍保留用于 `break` 剪枝。
2. **追问：如果每个数字可以用无限次（组合总和 I）？** 思路：递归传 `i` 而不是 `i+1`，允许同一元素重复选；无重复值时不需要同层去重。
3. **追问：如果要求返回组合的个数而不是所有组合？** 思路：把 `res.append` 换成计数器，或者用 DP（完全背包计数）做到 O(n · target)，避免枚举所有解。

## 9. 举一反三

- **组合总和（LeetCode 39）**：元素可重复使用，递归传 `i` 而非 `i+1`，其余骨架相同。
- **子集 II（LeetCode 90）**：同样的「排序 + 同层去重」套路，只是终止条件从 `remain == 0` 变成「每个节点都记录」。
- **全排列 II（LeetCode 47）**：去重逻辑相同，但排列需要 `used` 数组而非 `start` 指针，因为顺序有意义。
