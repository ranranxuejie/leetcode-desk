## 1. 一句话本质

把每张机票看成有向图的一条边，求一条从 JFK 出发、**恰好走完所有边各一次**的路径，并在所有合法路径中取字典序最小的那条——即"字典序最小的欧拉路径"。

## 2. 读完题的第一反应

**朴素解法**：从 JFK 开始 DFS，每次尝试一条还没用过的机票，走到死路就回溯，把所有能走完的完整路径收集起来，最后取字典序最小的。这本质上是枚举所有排列。

它卡在哪？假设有 n 张机票，最坏情况下从 JFK 出发的分支很多，DFS 会反复进入"走到一半发现某条边再也用不上"的死胡同。复杂度是指数级的——因为**回溯会重复探索同一批边的不同使用顺序**，而这些顺序对"能不能走完"的判断是等价的。

**关键观察**：题目保证"至少存在一种合理行程"，且每张票必须用一次。这正好是**欧拉路径**的定义（每条边恰好经过一次）。欧拉路径有一个经典性质：如果从起点出发、每次优先走字典序最小的边，走到无路可走时，**把节点逆序记录下来**，得到的反向序列就是答案。这个性质来自 Hierholzer 算法——它不需要回溯，因为"走不下去时当前节点一定是路径的终点（或某个环的收尾点）"。

为什么这个观察能指向下一步？因为它把"枚举所有顺序"变成了"贪心选最小边 + 事后逆序"，把指数级降到了线性级。

## 3. 从暴力到最优

**暴力瓶颈**：回溯时，同一条边可能在不同分支里被反复尝试。比如示例 2，从 JFK 出发有 SFO 和 ATL 两条边，暴力会分别尝试，每条分支内部又继续分叉。

**Hierholzer 的核心操作**：维护一个 `graph[from] = [to1, to2, ...]` 的邻接表，**每个列表按字典序升序排好**（用最小堆或排序后当栈用）。DFS 时每次从当前节点的列表里**弹出字典序最小的那个 to**（弹出即"用掉这张票"），递归进去；等递归返回、当前节点再没有出边时，把当前节点**追加到结果列表**。

**小例子走一遍**（示例 2）：

```
tickets = [["JFK","SFO"],["JFK","ATL"],["SFO","ATL"],["ATL","JFK"],["ATL","SFO"]]
```

建图（升序）：

```
JFK: [ATL, SFO]
SFO: [ATL]
ATL: [JFK, SFO]
```

DFS 从 JFK 开始：

| 步骤 | 当前节点 | 弹出边 | 递归后 | 结果列表（追加时机） |
|---|---|---|---|---|
| 1 | JFK | ATL | → ATL | |
| 2 | ATL | JFK | → JFK | |
| 3 | JFK | SFO | → SFO | |
| 4 | SFO | ATL | → ATL | |
| 5 | ATL | SFO | → SFO | |
| 6 | SFO | 无出边 | 返回 | append SFO → `[SFO]` |
| 7 | ATL | 无出边 | 返回 | append ATL → `[SFO, ATL]` |
| 8 | SFO | 无出边 | 返回 | append SFO → `[SFO, ATL, SFO]` |
| 9 | JFK | 无出边 | 返回 | append JFK → `[SFO, ATL, SFO, JFK]` |
| 10 | ATL | 无出边 | 返回 | append ATL → `[SFO, ATL, SFO, JFK, ATL]` |
| 11 | JFK | 无出边 | 返回 | append JFK → `[SFO, ATL, SFO, JFK, ATL, JFK]` |

最后**整体反转**：`["JFK","ATL","JFK","SFO","ATL","SFO"]`，正是答案。

注意第 6~11 步：节点是在"出边耗尽"时才被追加的，所以追加顺序是路径的**逆序**。这就是为什么最后要 reverse。

**瓶颈怎么被消掉的**：每条边只被弹出一次，没有回溯重试。排序的代价是 O(E log E)，DFS 本身 O(E)。指数级 → O(E log E)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**论证。

**不变量 1（不重）**：每条边在被 DFS 访问时立即从邻接表中 `pop` 掉，之后不可能再被选中。所以结果路径中每条边恰好出现一次，不会重复。

**不变量 2（不漏）**：DFS 只在当前节点出边为空时才返回并记录节点。由于题目保证存在欧拉路径，从 JFK 出发的 DFS 一定会把所有可达边走完（Hierholzer 定理：若图存在欧拉路径且起点正确，贪心走任意未用边都能走完所有边）。因此每条边都会被弹出，不会遗漏。

**为什么"逆序"就是字典序最小**：这是最容易被跳过的一步。直觉上，我们在每一步都优先弹出了字典序最小的边，所以"先走的路"字典序最小。但直接按访问顺序输出会出错——因为可能先走进一个环，环走完后回到原节点，此时原节点还有更大的边没走，导致输出顺序错乱。Hierholzer 的逆序记录恰好修正了这一点：**环上的节点会被后记录、先反转**，从而被"插入"到正确位置。形式化地说，逆序后的序列满足：对任意前缀，它都是所有合法欧拉路径前缀中字典序最小的（可用交换论证：若某合法路径在某位置选了比贪心更大的边，把贪心选的那条边换进来，路径仍合法且字典序更小，矛盾）。

## 5. 完整代码（Python）

```python
from collections import defaultdict
import heapq

class Solution:
    def findItinerary(self, tickets: list[list[str]]) -> list[str]:
        # 建图：每个出发地对应一个最小堆，保证每次弹出字典序最小的目的地
        graph = defaultdict(list)
        for src, dst in tickets:
            heapq.heappush(graph[src], dst)

        result = []

        def dfs(airport: str) -> None:
            # 只要当前机场还有未使用的机票，就贪心走字典序最小的那张
            while graph[airport]:
                nxt = heapq.heappop(graph[airport])  # 弹出即"用掉"，不会重复
                dfs(nxt)
            # 出边耗尽时才记录：此时该机场是当前子路径的终点
            result.append(airport)

        dfs("JFK")
        # 记录顺序是路径逆序，反转得到答案
        return result[::-1]
```

关键点注释已在代码中。注意 `heapq` 保证每次 `heappop` 取到的是当前出发地剩余机票中字典序最小的目的地，等价于"排序后当栈用"，但插入时自动维护顺序，比每次排序更省。

## 6. 复杂度

设 n 为机票数（边数），V 为机场数（节点数）。

- **建图**：遍历 n 张票，每次 `heappush` 是 O(log d)，d 是该出发地的出度。总计 O(n log n) 最坏（所有票从同一地出发）。
- **DFS**：每条边恰好被 `heappop` 一次，每次 O(log d)，总计 O(n log n)。递归调用次数为 n+1（每条边一次 + 起点一次）。
- **反转**：O(n)。
- **总时间**：O(n log n)。其中 log n 来自堆操作，n 来自边数。
- **空间**：图存储 O(n)（n 条边），递归栈最坏 O(n)（链状图），结果 O(n+1)。总计 O(n)。

## 7. 边界与反例（至少 4 条）

1. **输入** `[["JFK","KUL"],["JFK","NRT"],["NRT","JFK"]]` → **期望** `["JFK","NRT","JFK","KUL"]` → **易错点**：若先走 KUL 就死路，必须靠逆序修正。直接按访问顺序输出会得到 `["JFK","NRT","JFK","KUL"]` 恰好对，但若图更复杂（如先走小边进环）就会错，必须 reverse。

2. **输入** `[["JFK","ATL"],["ATL","JFK"]]` → **期望** `["JFK","ATL","JFK"]` → **易错点**：这是纯环，DFS 会先走 ATL 再回 JFK，记录顺序是 `[JFK, ATL, JFK]` 反转后 `[JFK, ATL, JFK]`，看似没变，但若误以为"访问顺序即答案"而不 reverse，在更长的环上会出错。

3. **输入** `[["JFK","SFO"],["JFK","ATL"],["SFO","ATL"],["ATL","JFK"],["ATL","SFO"]]`（示例 2）→ **期望** `["JFK","ATL","JFK","SFO","ATL","SFO"]` → **易错点**：若邻接表没排序（比如用普通 list 当栈），可能先弹出 SFO，得到字典序更大的 `["JFK","SFO",...]`，违反"字典序最小"要求。

4. **输入** `[["MUC","LHR"],["JFK","MUC"],["SFO","SJC"],["LHR","SFO"]]`（示例 1）→ **期望** `["JFK","MUC","LHR","SFO","SJC"]` → **易错点**：这是链状图，没有环，DFS 一路走到底，记录顺序 `[SJC, SFO, LHR, MUC, JFK]` 反转即答案。若忘记 reverse 会输出完全颠倒的路径。

## 8. 面试追问与变体（3 条）

1. **追问**：如果题目不保证存在合法行程，怎么改？**思路**：DFS 结束后检查 `len(result) == n+1`，不等则返回空列表（说明有边走不到）。

2. **追问**：如果要求字典序**最大**的行程？**思路**：把最小堆换成最大堆（存负数或用 `heapq` 取反），其余逻辑不变。

3. **追问**：如果图是无向图（每张票可双向飞）？**思路**：建图时每条边加两次，DFS 时弹出后要同时删掉反向边（用边的唯一 id 标记已用），仍是 Hierholzer，但要注意自环和重边的处理。
