## 1. 一句话本质

给定一棵以 `id` 为根的「员工树」，求这棵子树所有节点权值（importance）之和。

---

## 2. 读完题的第一反应

**朴素解法**：拿到 `id`，先在 `employees` 数组里线性扫一遍找到这个员工，把它的 importance 加上，然后对它的每个下属 id 再线性扫一遍数组找对应员工，递归下去。

卡在哪？每次「按 id 找员工」都要 O(n) 扫描整个数组。假设树是一条链、深度 n，那么总复杂度就是 O(n²)。n 最大 2000，n² = 4×10⁶，其实也能过，但这不是面试官想看的写法——而且一旦 n 放大到 10⁵ 就废了。

**关键观察**：题面明确说「所有的 `employees[i].id` 互不相同」。这句话就是在提示你：**id 是天然的主键，可以建索引**。把「id → 员工对象」的映射预先存进哈希表，之后每次查下属就是 O(1)，整个遍历的瓶颈就从「反复扫描数组」变成了「只访问树上的节点」。

另一个观察：题面说「一名员工最多有一名直接领导」，这意味着 `subordinates` 关系构成的是**森林/树**，不会有环，也不会有节点被两个父节点共享。所以从根出发做一次 DFS，每个节点恰好被访问一次，不需要 visited 集合。

---

## 3. 从暴力到最优

**第一步：暴力递归（不建索引）**

以示例 1 为例：`employees = [[1,5,[2,3]],[2,3,[]],[3,3,[]]], id = 1`。

- 找 id=1：扫数组，第 0 个命中，`total = 5`，下属 `[2,3]`。
- 处理下属 2：扫数组，第 1 个命中，`total = 5+3 = 8`，下属 `[]`。
- 处理下属 3：扫数组，第 2 个命中，`total = 8+3 = 11`，下属 `[]`。

结果 11，正确。但每次「找 id」都扫了 3 个元素，一共扫了 3 次，代价 9 次比较。树越深、数组越大，这个乘积越难看。

**第二步：建哈希表消掉重复扫描**

先花 O(n) 建 `id → Employee` 的字典：

```
mp = {1: 员工1, 2: 员工2, 3: 员工3}
```

再走一遍上面的过程：

- id=1：`mp[1]` 直接命中，`total = 5`，下属 `[2,3]`。
- id=2：`mp[2]` 命中，`total = 8`。
- id=3：`mp[3]` 命中，`total = 11`。

每次查下属从 O(n) 降到 O(1)。总代价 = 建表 O(n) + 遍历每个节点一次 O(节点数)。示例里就是 3 + 3 = 6 次操作，比 9 次少，而且树越大差距越明显。

**第三步：确认遍历方式**

DFS 和 BFS 都行，因为只是求和、与顺序无关。DFS 写起来短（递归或显式栈），BFS 用队列。下面代码用 DFS 递归，因为树深最多 2000，Python 默认递归上限 1000 会爆——所以代码里用**显式栈**迭代，避免 `sys.setrecursionlimit` 这种不优雅的补丁。

---

## 4. 正确性：为什么不会漏、不会重

**不变量**：在 DFS 的任意时刻，设已弹出栈的节点集合为 S，栈中待处理节点集合为 T，则「根到 S 中每个节点的路径上的所有节点」都已被计入 `total`，且 `total` 恰好等于「以根为起点、已经完整展开的子树」的权值和；同时 T 中的每个节点都是某个已展开节点的直接下属，且尚未被计入。

**归纳**：

- 初始：栈只有根，`total = 0`，不变量平凡成立（S 为空）。
- 每步：弹出节点 u，把 `u.importance` 加入 `total`，把 u 的所有下属压栈。u 的父节点此前已展开（否则 u 不会在栈里），所以 u 被计入时其路径完整；u 的下属入栈后成为「待处理」，符合 T 的定义。
- 终止：栈空，T 为空，所有从根可达的节点都进过 S 并被计入一次。

**不会漏**：树中每个节点都从根经 `subordinates` 边可达（题面保证 id 有效、最多一个领导，故是连通子树），DFS 沿边展开必然覆盖。

**不会重**：每个节点只有一个父节点（题面「最多有一名直接领导」），且只在被父节点展开时入栈一次；入栈后只弹出一次。所以每个节点恰好贡献一次 importance。

---

## 5. 完整代码（Python）

```python
from typing import List

class Employee:
    def __init__(self, id: int, importance: int, subordinates: List[int]):
        self.id = id
        self.importance = importance
        self.subordinates = subordinates

class Solution:
    def getImportance(self, employees: List['Employee'], id: int) -> int:
        # 1. 建索引：id -> Employee，O(n)
        #    题面保证 id 互不相同，所以字典不会覆盖
        mp = {e.id: e for e in employees}

        # 2. 显式栈 DFS，避免递归深度超过 1000
        #    栈里存的是「待展开的员工 id」
        stack = [id]
        total = 0

        while stack:
            cur_id = stack.pop()
            emp = mp[cur_id]          # O(1) 查表
            total += emp.importance   # 当前节点计入一次
            # 把直接下属压栈，稍后展开
            for sub_id in emp.subordinates:
                stack.append(sub_id)

        return total
```

> 假设说明：题面给的 `employees` 是 `Employee` 对象数组（力扣原题如此），上面代码按此签名写。若你的判题环境传的是 `[[id, imp, [sub...]], ...]` 的列表形式，只需在 `mp` 构建处改成 `mp = {e[0]: e for e in employees}`，并在循环里用 `emp[1]`、`emp[2]` 取值即可，逻辑不变。

## 6. 复杂度

**时间 O(n)**，n = `employees.length`。

- 建字典：遍历数组一次，每个元素做一次哈希插入，O(n)。
- DFS：每个员工节点入栈一次、出栈一次，共 2n 次栈操作；每次出栈做一次字典查询 O(1)、一次加法、把 `subordinates` 里每个 id 压栈一次。所有 `subordinates` 列表长度之和 = 边数 = n−1（树的性质），所以压栈总次数 O(n)。
- 合计 O(n)。没有 log 项，因为哈希表平均 O(1)，不涉及排序或二分。

**空间 O(n)**。

- 字典 `mp` 存 n 个键值对：O(n)。
- 栈最坏情况：星形树（根有 n−1 个下属）时栈里同时有 n−1 个 id，O(n)。
- 合计 O(n)。

## 7. 边界与反例（至少 4 条）

1. **输入**：`employees = [[5,-3,[]]], id = 5` → **输出** `-3` → **易错点**：importance 可以是负数（题面范围 −100~100），如果初始化 `total = 0` 后误以为「没下属就返回 0」会错；必须把根自己的 importance 加进去。

2. **输入**：`employees = [[1,2,[5]],[5,-3,[]]], id = 5`（示例 2）→ **输出** `-3` → **易错点**：根不是数组第一个元素，且根在数组末尾。如果代码假设「`employees[0]` 就是根」会直接错；必须靠 `id` 查表定位。

3. **输入**：`employees = [[1,5,[2,3]],[2,3,[]],[3,3,[]]], id = 2` → **输出** `3` → **易错点**：从中间节点出发，只能算它自己的子树，不能把它的领导 1 算进来。DFS 从 `id` 出发天然正确，但如果先「找整棵树的根再遍历」就会多算。

4. **输入**：`employees = [[1,1,[2,3,4]],[2,1,[]],[3,1,[]],[4,1,[]]], id = 1` → **输出** `4` → **易错点**：星形结构，栈会一次性压入 3 个下属。如果用递归且树退化成链（深度 2000），会触发 `RecursionError`；本题用显式栈规避。

5. **输入**：`employees = [[1,0,[2]],[2,0,[3]],[3,0,[]]], id = 1` → **输出** `0` → **易错点**：所有 importance 为 0，结果 0 是合法值，不能把「返回 0」误判成「没找到」。

## 8. 面试追问与变体（3 条）

1. **追问**：如果 `subordinates` 里可能出现无效 id（题面现在保证有效），怎么改？
   **思路**：压栈前加 `if sub_id in mp` 判断，或出栈时 `emp = mp.get(cur_id)` 为 `None` 就跳过。

2. **追问**：如果要求返回「重要度最大的那条从根到叶的路径和」，怎么改？
   **思路**：DFS 时多传一个「当前路径和」参数，到叶子时更新全局最大值；本质是把「求和」换成「沿路径累积 + 打擂台」。

3. **追问**：如果员工关系可能成环（比如数据脏了），怎么防止死循环？
   **思路**：加 `visited` 集合，出栈时若已访问则跳过；空间多 O(n)，时间不变。
