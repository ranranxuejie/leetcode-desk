## 1. 一句话本质

在 O(log n) 次乘法内算出 x 的 n 次幂——把「乘 n 次」这个线性过程，压缩成「按 n 的二进制位跳着乘」的对数过程。

## 2. 读完题的第一反应

**朴素解法**：`result = 1`，循环 n 次，每次 `result *= x`。复杂度 O(n)。

它卡在哪？看数据范围：`n` 可以到 `2^31 - 1`，也就是约 21 亿。循环 21 亿次，Python 里光循环开销就要几十秒，必然超时。瓶颈非常明确：**n 太大，而我们把 n 当成了「要做 n 次操作」的计数**。

**关键观察**：幂运算有结合律，`x^a * x^b = x^(a+b)`。这意味着我们不必一次一次地乘 x，而可以「成倍地」累加指数。具体说：

- `x^8 = (x^4)^2 = ((x^2)^2)^2`，只需 3 次平方就得到 8 次幂，而不是 8 次乘法。
- 更一般地，任何 n 都能拆成若干个 2 的幂之和（就是 n 的二进制表示）。比如 `n = 13 = 8 + 4 + 1`，于是 `x^13 = x^8 * x^4 * x^1`。

这个观察直接给出下一步：**把 n 看成二进制，从低位往高位扫，维护一个「当前位的 x 的 2^k 次幂」，遇到 n 的该位是 1 就把它乘进答案**。这就是快速幂（二进制幂）。

为什么这个观察「自然」？因为题目给的 n 范围是 32 位整数，而任何 32 位整数最多 32 个二进制位——这暗示了「按位处理」能把 21 亿次降到 32 次量级。

## 3. 从暴力到最优

**第一步：暴力**。`x^13` 就是乘 13 次 x。复杂度 O(n)。

**第二步：平方拆分（递归视角）**。利用 `x^n = (x^(n/2))^2`（n 偶数）或 `x * (x^(n//2))^2`（n 奇数）。这样每次 n 减半，递归深度 O(log n)。

**第三步：迭代版（二进制视角）**，也是最终写法。以 `x = 2, n = 13` 走一遍：

n = 13 的二进制是 `1101`。我们从低位往高位处理，维护两个变量：
- `base`：当前位的底数，初始 `base = x = 2`，每轮平方一次；
- `ans`：累积结果，初始 `ans = 1`。

| 轮次 | n（当前） | n & 1 | 动作 | ans | base |
|---|---|---|---|---|---|
| 起始 | 13 | — | — | 1 | 2 |
| 1 | 13 | 1 | ans *= base | 2 | 2 |
| | | | base *= base, n >>= 1 | 2 | 4 |
| 2 | 6 | 0 | 跳过 | 2 | 4 |
| | | | base *= base, n >>= 1 | 2 | 16 |
| 3 | 3 | 1 | ans *= base | 32 | 16 |
| | | | base *= base, n >>= 1 | 32 | 256 |
| 4 | 1 | 1 | ans *= base | 8192 | 256 |
| | | | base *= base, n >>= 1 | 8192 | 65536 |
| 结束 | 0 | — | — | 8192 | — |

验证：`2^13 = 8192` ✓。总共只做了约 4 轮，每轮常数次乘法，而不是 13 次。

**瓶颈怎么被消掉的**：暴力是「n 次乘法」，快速幂是「log₂n 轮，每轮最多 2 次乘法」。n 从 21 亿降到 31 轮，这就是全部收益。

**负数指数**：题面示例 3 给了 `n = -2`。利用 `x^(-n) = 1 / x^n`，先把 n 取反、x 取倒数，再走上面的流程。这里有个坑：`n = -2^31` 时 `-n` 在 32 位整数里会溢出（`2^31` 超出 int 上限）。Python 整数无溢出问题，但如果你写 C++/Java 就要用 long 存 n。Python 里直接 `n = -n` 是安全的，这点在边界一节再说。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。设原始指数为 N（已处理成正数），把 N 写成二进制 `N = Σ b_k · 2^k`，其中 `b_k ∈ {0,1}`。

在迭代过程中，我们维护这样一个不变量：

> **循环不变量**：`ans * base^n == x^N`（这里的 n 是当前还没处理的指数部分，base 是 `x^(2^当前位)`）。

初始时 `ans = 1, base = x, n = N`，有 `1 * x^N == x^N`，成立。

每轮做两件事：
1. 若 `n & 1 == 1`，说明当前二进制位是 1，需要把 `base` 乘进答案：`ans *= base`。此时 `ans` 变成 `ans * base`，而 `n` 即将右移，`base` 即将平方，可以验证不变量仍成立（因为 `(ans·base) · (base^2)^((n-1)/2) = ans · base^(1 + n - 1) = ans · base^n`）。
2. 无论该位是否为 1，都执行 `base *= base`（即 `base` 从 `x^(2^k)` 变成 `x^(2^(k+1))`），并 `n >>= 1`。这一步对应「把当前位处理掉，看下一位」。

**为什么不会漏**：每一位 `b_k = 1` 时，恰好有一次 `ans *= base` 把 `x^(2^k)` 乘进去；`b_k = 0` 时跳过，不贡献。所有为 1 的位都被且仅被处理一次。

**为什么不会重**：每轮 `n >>= 1` 让 n 严格减小，循环必然终止；且每个二进制位只被访问一次，不存在重复乘。

循环结束时 `n == 0`，由不变量得 `ans * base^0 == x^N`，即 `ans == x^N`。证毕。

## 5. 完整代码（Python）

```python
class Solution:
    def myPow(self, x: float, n: int) -> float:
        # 处理负指数：x^(-n) = (1/x)^n
        # Python 整数无溢出，n = -2^31 时 -n 也安全
        if n < 0:
            x = 1.0 / x
            n = -n

        ans = 1.0          # 累积结果，用 1.0 保证浮点
        base = x           # 当前位的底数，代表 x^(2^k)

        while n > 0:
            if n & 1:      # 当前最低位是 1，把这一份乘进答案
                ans *= base
            base *= base   # 底数平方，准备处理下一位
            n >>= 1        # 右移，丢掉已处理的最低位

        return ans
```

几个细节说明：

- `ans = 1.0` 而不是 `1`：虽然 Python 会自动提升，但显式写浮点更清晰，也避免 `x` 为整数时返回 int 的歧义。
- `if n < 0` 里先改 `x` 再改 `n`，顺序不能反——如果先 `n = -n` 再 `x = 1/x`，逻辑上等价，但保持「先改底数」更符合 `x^(-n) = (1/x)^n` 的推导。
- 循环条件 `n > 0`：因为前面已把 n 转正，这里不用考虑负数。
- 没有单独处理 `n == 0`：循环不进入，直接返回 `ans = 1.0`，正确（`x^0 = 1`，题面保证 x 不为零或 n > 0，所以不会出现 `0^0` 的争议）。

## 6. 复杂度

**时间 O(log n)**。循环次数等于 n 的二进制位数，即 `⌊log₂n⌋ + 1`。每轮内部是常数次浮点乘法和一次移位，所以总乘法次数约 `2·log₂n`。这里的 log 来自「每次 `n >>= 1` 让问题规模减半」，n 贡献的是它的位数而不是数值本身。

**空间 O(1)**。只用了 `ans`、`base`、`n` 三个变量，与 n 大小无关。注意：如果写成递归版，空间是 O(log n)（递归栈深度），迭代版把它压到了 O(1)——这是迭代写法的一个实际优势。

对比暴力：时间 O(n)、空间 O(1)。快速幂用「多存一个 base」换来了指数级的加速。

## 7. 边界与反例（至少 4 条）

1. **`x = 2.0, n = -2`** → 期望 `0.25`。容易错在忘记处理负指数，直接对负数 n 跑循环（`n > 0` 不成立，返回 1.0，错）。必须先取倒数再取反。

2. **`x = 2.0, n = 0`** → 期望 `1.0`。容易错在把 `n == 0` 当成特殊情况漏处理，或者误以为要返回 0。任何非零数的 0 次幂是 1，循环不进入直接返回 `ans` 即可。

3. **`x = 1.0, n = 2147483647`（2^31-1）** → 期望 `1.0`。容易错在暴力循环超时；快速幂 31 轮就结束。同时这条也检验「大 n 不溢出」——Python 没问题，但如果你把 n 存成 32 位有符号整数并做 `-n`，`n = -2^31` 时会溢出，这是 C++/Java 的经典坑。

4. **`x = 0.00001, n = 2147483647`** → 期望接近 0（题面保证 `x^n` 在 `[-10^4, 10^4]` 内，所以实际测试不会给这种极端组合，但理解上要知道：快速幂的中间 `base` 会平方很多次，浮点下溢/上溢是真实存在的）。容易错在以为「快速幂一定数值稳定」——它只是减少了乘法次数，不改变浮点误差的累积方式，极端值下仍可能有精度问题。

5. **`x = -2.0, n = 3`** → 期望 `-8.0`。容易错在符号处理：负底数的奇数次幂为负。快速幂里 `base` 会带着符号平方，`(-2)^2 = 4`、`4^2 = 16`，符号在 `ans *= base` 时正确带入，不需要特判——但如果你手动「先取绝对值再补符号」就可能写错。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回结果对 1337 取模（即 `x^n mod 1337`），怎么改？**
   思路：每步乘法后对 1337 取模，`ans = (ans * base) % 1337`、`base = (base * base) % 1337`，避免大数；注意负指数时要用模逆元（扩展欧几里得），这是 LeetCode 372 的套路。

2. **追问：不用乘法，只用加法实现 `x * n`（n 为正整数），怎么做？**
   思路：同一套二进制拆分思想——`x * n = x * (n 的二进制各位之和)`，维护 `base` 每次翻倍（`base += base`），遇 `n & 1` 就 `ans += base`，把「乘法」换成「加法」即可。

3. **追问：矩阵快速幂求斐波那契第 n 项，和本题什么关系？**
   思路：把「数」换成「矩阵」，矩阵乘法满足结合律，`[[1,1],[1,0]]^n` 的第一行第一列就是 F(n+1)；快速幂的框架完全不变，只是 `base *= base` 变成矩阵乘。
