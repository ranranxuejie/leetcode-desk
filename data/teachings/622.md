## 1. 一句话本质

在一个**固定长度 k 的数组**上，用两个会「绕圈」的下标（队头、队尾）模拟先进先出队列，使得出队腾出的空间能被后续入队复用。

## 2. 读完题的第一反应

**朴素解法**：用一个普通 Python list 当队列，`enQueue` 就 `append`，`deQueue` 就 `pop(0)`。

它卡在哪？`pop(0)` 是 O(n)——删掉队首后，后面所有元素都要往前挪一格。题面明确说「操作数 1 到 1000」，单看数据量 O(n) 也能过，但题目的**考点根本不在这里**：它要你实现「环形缓冲器」，即**队尾绕回队首**这件事本身。用 list 的 `pop(0)` 你压根没实现「循环」，只是碰巧能跑。

**关键观察**：队列满时不能插入，是因为「队尾指针追上了队头」。如果让下标走到 k 就回到 0（取模），那么出队后队头前移，队尾就有空间绕回来继续写——**数组的物理空间被当成一个环来用**。这一步想通，剩下的全是「怎么用两个下标判断空和满」的细节。

而「空 vs 满」是这道题唯一的真难点：如果只用 `head` 和 `tail` 两个下标，`head == tail` 既可能是空也可能是满，无法区分。题面给的 `isEmpty` / `isFull` 两个接口，就是在逼你解决这个歧义。

## 3. 从暴力到最优

**第一步：普通数组队列。**
`head` 指向队首元素，`tail` 指向「下一个要写入的位置」。入队写 `arr[tail]`，`tail += 1`；出队 `head += 1`。问题：`tail` 一直涨，涨到 k 就数组越界，而前面 `head` 让出来的格子全浪费了。这正是题面说的「普通队列一旦满了就不能插入，即使前面还有空间」。

**第二步：让下标绕圈。**
把 `tail += 1` 改成 `tail = (tail + 1) % k`，`head` 同理。这样下标永远落在 `[0, k)`，物理空间被循环使用。

**第三步：解决空/满歧义。**
两种主流方案，我选**方案 A：多开一个格子**（容量开 k+1，实际只存 k 个）。

约定：`head` 指向队首元素，`tail` 指向「下一个写入位置」，且**队列满时 tail 的下一个位置就是 head**，即 `(tail + 1) % cap == head` 表示满，`head == tail` 表示空。因为永远留一个空位，`head == tail` 就只可能是空。

走一遍示例，k=3，`cap = 4`，初始 `head = tail = 0`，`arr = [_, _, _, _]`：

| 操作 | 动作 | head | tail | arr |
|---|---|---|---|---|
| enQueue(1) | 写 arr[0]=1，tail=(0+1)%4=1 | 0 | 1 | [1,_,_,_] |
| enQueue(2) | 写 arr[1]=2，tail=2 | 0 | 2 | [1,2,_,_] |
| enQueue(3) | 写 arr[2]=3，tail=3 | 0 | 3 | [1,2,3,_] |
| enQueue(4) | 判满：(3+1)%4==0==head → 满，返回 False | 0 | 3 | 不变 |
| Rear() | 队尾是 tail 的前一格：(3-1+4)%4=2，arr[2]=3 | 0 | 3 | 返回 3 |
| deQueue() | head=(0+1)%4=1 | 1 | 3 | [_,2,3,_] |
| enQueue(4) | 写 arr[3]=4，tail=(3+1)%4=0 | 1 | 0 | [_,2,3,4] |
| Rear() | (0-1+4)%4=3，arr[3]=4 | 1 | 0 | 返回 4 |

注意最后一行：`tail` 已经绕回 0，而 `head=1`，队列里实际是 `[2,3,4]`，队尾在物理下标 3——**逻辑顺序和物理下标已经错开了**，这正是「环」在起作用。

**为什么这是最优**：每个操作只做常数次下标运算和一次数组读写，O(1)。没有比 O(1) 更好的了，所以到此为止。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证。设 `cap = k + 1`，维护以下不变量：

> **不变量 I**：队列中的元素恰好是 `arr[head], arr[(head+1)%cap], ..., arr[(tail-1+cap)%cap]`，共 `(tail - head + cap) % cap` 个，且这个数量恒在 `[0, k]` 内。

- **空**：`head == tail`，按公式元素个数为 0，与 `isEmpty` 返回 True 一致。
- **满**：`(tail+1)%cap == head`，按公式个数为 `cap-1 = k`，与 `isFull` 返回 True 一致。由于个数上限是 k，`head == tail` 时个数必为 0，**空和满被彻底区分开**，不会误判。
- **enQueue**：先判满，不满则写 `arr[tail]` 再 `tail` 前移一格。写入位置正是「当前队尾的下一个空位」，元素个数 +1，不变量保持。
- **deQueue**：先判空，不空则 `head` 前移一格。被丢弃的正是队首元素，个数 -1，不变量保持。
- **Front / Rear**：分别读 `arr[head]` 和 `arr[(tail-1+cap)%cap]`，正是不变量的首、尾元素。

因为每个操作都在不变量成立的前提下执行、执行后不变量仍成立，且初始状态（`head=tail=0`，个数 0）满足不变量，由归纳法，**任何操作序列后队列内容都正确，既不漏元素也不重复计数**。

## 5. 完整代码（Python）

```python
class MyCircularQueue:
    def __init__(self, k: int):
        # 多开一个格子：容量 cap = k + 1，实际最多存 k 个
        # 这样 head == tail 只表示空，(tail+1)%cap == head 表示满
        self.cap = k + 1
        self.arr = [0] * self.cap
        self.head = 0   # 指向队首元素
        self.tail = 0   # 指向下一个写入位置

    def enQueue(self, value: int) -> bool:
        if self.isFull():
            return False
        self.arr[self.tail] = value
        self.tail = (self.tail + 1) % self.cap   # 绕圈
        return True

    def deQueue(self) -> bool:
        if self.isEmpty():
            return False
        self.head = (self.head + 1) % self.cap   # 队首前移，旧格子自动可复用
        return True

    def Front(self) -> int:
        if self.isEmpty():
            return -1
        return self.arr[self.head]

    def Rear(self) -> int:
        if self.isEmpty():
            return -1
        # 队尾是 tail 的前一格，注意 +cap 防止负数取模
        return self.arr[(self.tail - 1 + self.cap) % self.cap]

    def isEmpty(self) -> bool:
        return self.head == self.tail

    def isFull(self) -> bool:
        return (self.tail + 1) % self.cap == self.head
```

> 说明：题面给的签名是 `Solution.solve(...) -> boolean`，但这是一道**设计题**，力扣原题要求实现 `MyCircularQueue` 类。我按设计题的标准写法给出类实现；若评测系统确实只认 `Solution.solve`，把上述方法包进 `Solution` 并自行维护状态即可，逻辑完全一致。这是我对题面签名的一处假设。

## 6. 复杂度

- **时间**：`enQueue` / `deQueue` / `Front` / `Rear` / `isEmpty` / `isFull` 全部 **O(1)**。每一项只做常数次取模、比较、一次数组下标读写，与 k 无关，也没有循环。
- **空间**：**O(k)**。数组开 `k+1` 个格子，`k` 来自构造器参数；两个下标是 O(1)。这里没有 log 项——没有任何分治或树结构。

## 7. 边界与反例（至少 4 条）

1. **k=1，连续入队两次** → 第一次 True，第二次 False。容易错：忘了 `cap = k+1 = 2`，满判据是 `(tail+1)%2 == head`，而不是 `tail == head`。
2. **空队列调 Front / Rear** → 都返回 -1。容易错：`Rear` 里 `(tail-1+cap)%cap` 在 `tail=0` 时若不 `+cap` 会得到负数下标，Python 会静默取到 `arr[-1]`，返回垃圾值而不报错。
3. **k=3，入 1,2,3 后 deQueue 再 enQueue(4)** → 返回 True，Rear 为 4。容易错：以为「满了就不能再进」，没意识到出队后 tail 能绕回 0 号格。
4. **反复 deQueue 到空，再 enQueue** → 应正常入队。容易错：只更新 head 不检查 tail 与 head 的关系，导致空队列被误判为满。
5. **k=3，入满后 deQueue 三次再 isEmpty** → True。容易错：`head` 绕圈后与 `tail` 数值相等但语义是空，若用「元素计数」方案而忘记同步减计数就会误判。

## 8. 面试追问与变体（3 条）

1. **追问：不用「多开一格」，还能怎么区分空和满？** 思路：维护一个 `size` 计数，`size==0` 空、`size==k` 满，`head/tail` 照常绕圈；或用一个 `flag` 记录最后一次操作是入队还是出队。
2. **追问：改成线程安全 / 支持并发读写？** 思路：用锁保护 `head/tail/size` 的读改写，或改用无锁的原子计数 + CAS（面试里说清「临界区是下标更新」即可）。
3. **追问：实现一个支持动态扩容的循环队列？** 思路：满时把 `cap` 翻倍，按逻辑顺序（从 head 起）把旧元素搬到新数组，重置 `head=0, tail=size`，均摊 O(1)。
