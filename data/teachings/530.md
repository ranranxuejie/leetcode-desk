## 1. 一句话本质

在 BST 的中序遍历序列（一个递增数组）里，找相邻两个元素的差的最小值。

## 2. 读完题的第一反应

**朴素解法**：把树里所有节点值收集成一个列表，然后两两求差的绝对值，取最小。节点数 n 最多 10^4，两两组合是 O(n²)，10^8 次操作，Python 里大概率超时。就算不超时，这个做法也完全没用上「二叉搜索树」这个条件——题目特意说是 BST，一定有用。

**关键观察**：BST 有一个性质——**中序遍历得到严格递增序列**。这句话是整道题的钥匙。为什么它有用？因为在一个递增数组里，任意两数之差的绝对值，最小值一定出现在**相邻**的两个数之间。证明很直接：设 a ≤ b ≤ c，则 c - a = (c - b) + (b - a) ≥ max(c-b, b-a)，跨着取差只会更大。所以「任意两节点」这个看似 O(n²) 的搜索空间，被压缩成了「中序序列里相邻两项」这 n-1 个候选。

于是问题从「两两比较」变成「边遍历边比较相邻值」，一趟中序遍历就能解决。

## 3. 从暴力到最优

**暴力版本**：收集所有值 → 排序（其实中序已经有序，但暴力版可能先随便收集再排序）→ 相邻求差。复杂度 O(n log n) 排序 + O(n) 扫描。这已经能过了，但还可以更好。

**瓶颈在哪**：排序是多余的。BST 的中序遍历天然有序，不需要额外排序。把「收集 + 排序」换成「中序遍历时直接比较」，就省掉了排序这一步，也不需要存整个数组。

**用示例 1 走一遍**：`root = [4,2,6,1,3]`，树结构是 4 为根，左子树 2（左 1 右 3），右子树 6。

中序遍历顺序：左 → 根 → 右，递归下去得到 `1, 2, 3, 4, 6`。

用一个变量 `prev` 记录上一个访问的值，`ans` 记录当前最小差：

| 访问节点 | prev | 差值 | ans |
|---|---|---|---|
| 1 | None | — | ∞ |
| 2 | 1 | 1 | 1 |
| 3 | 2 | 1 | 1 |
| 4 | 3 | 1 | 1 |
| 6 | 4 | 2 | 1 |

返回 1。注意 `prev` 初始为 None 时跳过比较，这是第一个节点没有「前一个」导致的，不是特殊情况，是逻辑必然。

**再看示例 2**：`[1,0,48,null,null,12,49]`，中序是 `0, 1, 12, 48, 49`，相邻差 `1, 11, 36, 1`，最小是 1。这里如果只比较「根和直接孩子」就会漏掉 12 和 48 这一对——它们不是父子关系，但在中序里相邻。这正是「必须用中序相邻」而不是「父子相邻」的原因。

**还能不能更快**：不能。最坏情况下你得看每个节点一眼才知道最小值，Ω(n) 是下界。所以 O(n) 时间就是最优。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：在中序遍历进行到任意时刻，`ans` 等于「已访问节点序列中所有相邻对的差」的最小值，`prev` 等于「已访问的最后一个节点值」。

**初始**：还没访问任何节点，`ans = ∞`，`prev = None`，空序列的相邻对集合为空，最小值约定为 ∞，成立。

**归纳步**：访问新节点 `cur`。由中序遍历的定义，`cur` 紧接在 `prev` 之后，所以 `(prev, cur)` 是已访问序列新增的唯一一个相邻对。更新 `ans = min(ans, cur - prev)` 后，不变量保持。若 `prev` 为 None（第一个节点），没有新增相邻对，`ans` 不变，不变量也保持。

**终止**：遍历完所有 n 个节点，`ans` 是全部 n-1 个相邻对差的最小值。

**为什么不会漏**：任意两个不同节点 a < b，在中序序列里它们之间至少隔着一个相邻对，而由第 2 节的论证，b - a ≥ 其中某个相邻对的差 ≥ ans。所以 ans 不会大于真实最小值。

**为什么不会重/不会错**：每个相邻对恰好在中序走到后一个节点时被计算一次，没有重复也没有遗漏；BST 中序严格递增（题目节点值互不相同，由「任意两不同节点值」的措辞可推知），所以 `cur - prev > 0`，不需要取绝对值。

两个方向合起来：ans 既 ≤ 真实最小值（每个候选都是合法差值），又 ≥ 真实最小值（不会漏掉更小的），故相等。

## 5. 完整代码（Python）

```python
class Solution:
    def getMinimumDifference(self, root) -> int:
        # prev 记录中序遍历中上一个访问到的节点值
        # 用列表包一层是为了在嵌套函数里能修改它（Python 闭包对外层变量赋值需要 nonlocal）
        self.prev = None
        self.ans = float('inf')

        def inorder(node):
            if node is None:
                return
            # 1. 先递归左子树：保证按递增顺序访问
            inorder(node.left)

            # 2. 处理当前节点：与中序前驱比较
            if self.prev is not None:
                # BST 中序严格递增，node.val > self.prev，直接相减即可
                diff = node.val - self.prev
                if diff < self.ans:
                    self.ans = diff
            # 更新前驱为当前节点，供下一个节点使用
            self.prev = node.val

            # 3. 再递归右子树
            inorder(node.right)

        inorder(root)
        return self.ans
```

几个容易写错的点，代码里已经体现：

- `self.prev` 必须在**处理完当前节点之后**才更新，不能提前，否则当前节点会和自己比较，差为 0。
- 第一个节点 `prev is None` 时跳过比较，不能把 `prev` 初始化成 0 或 -1——节点值可以是 0（示例 2 就有），初始化成 0 会算出错误的差。
- 用 `self.` 而不是闭包变量，是为了避免 `nonlocal` 的写法差异；两种都行，选一种写熟即可。

如果不想用递归（树深可能到 10^4，Python 默认递归深度约 1000，理论上会爆栈，虽然力扣通常放宽了），可以改成显式栈：

```python
class Solution:
    def getMinimumDifference(self, root) -> int:
        stack = []
        prev = None
        ans = float('inf')
        cur = root
        while cur or stack:
            # 一路向左压栈，模拟递归进入左子树
            while cur:
                stack.append(cur)
                cur = cur.left
            cur = stack.pop()
            # 出栈顺序即中序顺序，此时 cur 是当前应访问的节点
            if prev is not None:
                ans = min(ans, cur.val - prev)
            prev = cur.val
            cur = cur.right
        return ans
```

面试时建议先写递归版讲清思路，再提一句「深树可以换迭代」作为加分。

## 6. 复杂度

**时间 O(n)**：中序遍历每个节点恰好进入一次、处理一次，每次处理是常数时间（一次减法、一次比较、一次赋值）。n 来自节点总数，没有 log n 的项——因为这里不需要在有序结构里做查找，只是线性扫描。

**空间 O(h)**，h 是树高：

- 递归版：递归调用栈深度等于树高。最坏情况树退化成链，h = n，空间 O(n)；最好情况平衡树，h = log n，空间 O(log n)。
- 迭代版：显式栈的最大深度同样是树高，结论一致。

注意这里**没有** O(n) 的数组开销，这正是相比「收集后排序」版本的改进点之一。如果面试官追问「能不能 O(1) 空间」，答案是 Morris 遍历（利用叶子节点的空右指针做线索），时间仍是 O(n)，空间 O(1)，但代码复杂、容易写错，一般作为追问的谈资而非首选。

## 7. 边界与反例（至少 4 条）

1. **输入 `[1, 2]`（只有两个节点，根 1 右孩子 2）** → 期望 1 → 容易错在：`prev` 初始化为 0，第一个节点 1 与 0 比较得 1，碰巧对；但换成 `[0, 100000]` 就会在第一个节点算出 0 与 0 的差 0，错误地返回 0。必须用 None 做哨兵。

2. **输入 `[5, 4, null, 3, null, 2]`（退化成左链）** → 中序 `2,3,4,5`，期望 1 → 容易错在：递归深度等于 4，节点数到 10^4 时递归深度 10^4，Python 默认限制下会 `RecursionError`。要么用迭代版，要么在面试中主动说明。

3. **输入 `[0, null, 100000]`（根 0，右孩子 100000）** → 期望 100000 → 容易错在：把 `ans` 初始化成某个小常数（比如 10^5 或 `float('inf')` 写成 `10**5`），而 100000 恰好等于 10^5，若用 `<=` 判断或初始化不当会出错。用 `float('inf')` 最稳。

4. **输入 `[236, 104, 701, null, 227, null, 911]`** → 中序 `104, 227, 236, 701, 911`，相邻差 `123, 9, 465, 210`，期望 9 → 容易错在：只比较父子节点。236 和 227 是祖孙关系，差 9 才是答案；只看父子会得到 236-104=132 或 701-236=465，全错。这直接验证了「必须用中序相邻」。

5. **输入 `[1, 0, 48, null, null, 12, 49]`（示例 2）** → 期望 1 → 容易错在：以为最小差一定出现在「根与某节点」之间。实际 0 和 1 差 1，48 和 49 差 1，都跟根 1 无关。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求 O(1) 额外空间怎么做？**
   思路：Morris 中序遍历，用叶子节点的空右指针临时指向中序后继，遍历时维护 `prev` 和 `ans`，遍历完恢复指针。时间 O(n)，空间 O(1)。

2. **追问：如果不是 BST，是普通二叉树，怎么求任意两节点的最小差？**
   思路：中序相邻的结论失效了。做法是收集所有值 → 排序 → 扫相邻，O(n log n)；或者用有序集合（如平衡 BST / 跳表）边遍历边找前驱后继，也是 O(n log n)。BST 条件省掉的正是这个 log n。

3. **追问：求 BST 中任意两节点的最大差？**
   思路：最大差一定是最小值（最左节点）和最大值（最右节点）之差，一路向左、一路向右即可，O(h)。对比本题：最小差要扫全部相邻对，最大差只要两个端点——这个不对称性值得在面试里点出来。

## 9. 举一反三（2-3 道同类题）

- **783. 二叉搜索树节点最小距离**：与本题完全相同（题面已注明），可当作复习。
- **98. 验证二叉搜索树**：同样依赖「中序递增」这个不变量，只是把「比较相邻差」换成「检查是否严格递增」。
- **501. 二叉搜索树中的众数**：中序遍历得到有序序列后统计相邻相同值的连续长度，同样是「中序 + 一个 prev 变量」的套路。

这三道题的共同骨架是：**BST 的中序遍历 = 有序数组，把树上的问题降维成数组上的扫描问题，用一个 prev 指针在 O(1) 额外状态下完成**。把这个骨架记住，这一类题都能自己推出来。
