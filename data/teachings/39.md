## 1. 一句话本质

在所有「由 candidates 中元素构成、元素顺序无关、元素可重复使用」的多重集合里，筛出元素和恰好等于 target 的那些。

## 2. 读完题的第一反应

最朴素的想法：既然每个数可以无限用，那就枚举「每个数用几次」。对 candidates 里每个数，尝试用 0 次、1 次、2 次……直到和超过 target。这本质是一棵**决策树**，每个节点决定「当前这个数用几次」，然后递归到下一个数。

这个朴素解法卡在哪？卡在**重复**。如果你把 candidates 当成一个「可以随便挑」的池子，每一步都从下标 0 开始重新挑，那么 `[2,3]` 和 `[3,2]` 会被当成两条不同路径分别走到，最后产出两份一模一样的组合。组合数本身不到 150，但搜索树会因为排列而爆炸——比如 target=40、candidates 全是 2 附近的小数时，路径数远超实际组合数。

关键观察：**组合与顺序无关，所以我们可以人为规定一个顺序**。具体说，递归时记录一个「当前可以从哪个下标开始选」，并且因为同一个数可以重复用，选完 `candidates[i]` 之后下一次仍然允许从 `i` 开始（而不是 `i+1`）。这一条规定同时干掉了两件事：不重复（不会回头选更小的下标），也不遗漏（每个组合都能按非降下标顺序被唯一构造出来）。

## 3. 从暴力到最优

**暴力版**：每一步从整个 candidates 里任选一个数加入当前路径，和等于 target 就收集，超过就停。问题：`[2,2,3]` 会以 `[2,2,3]`、`[2,3,2]`、`[3,2,2]` 等多种顺序被重复生成。搜索树的分支因子是 n，深度最多 target/min(candidates)，节点数约 n^(target/min)，而实际答案不到 150 个——浪费巨大。

**改进版（本题正解）**：给递归加一个参数 `start`，表示「本次及以后只允许从下标 ≥ start 的数里选」。选了下标 i 的数之后，递归传 `start = i`（不是 i+1，因为可重复）。

拿示例 1 走一遍：candidates = [2,3,6,7]，target = 7。

- 根节点：path=[], remain=7, start=0。
- 选 i=0（值 2）：path=[2], remain=5, start=0。
  - 再选 i=0（值 2）：path=[2,2], remain=3, start=0。
    - 再选 i=0（值 2）：remain=1，下一个最小也是 2 > 1，此路不通（剪枝）。
    - 选 i=1（值 3）：path=[2,2,3], remain=0 → **收集**。
    - i=2 值 6 > remain=3，break（因为数组已排序，后面更大）。
  - 选 i=1（值 3）：path=[2,3], remain=2, start=1。此时可选的最小值是 3 > 2，此路不通。
  - 选 i=2 值 6 > remain=5，break。
- 选 i=1（值 3）：path=[3], remain=4, start=1。后续最小 3，3+3=6>4 不通；6、7 更大，break。
- 选 i=2（值 6）：remain=1，不通。
- 选 i=3（值 7）：path=[7], remain=0 → **收集**。

结果 `[[2,2,3],[7]]`，和官方一致。注意 `[2,3,2]` 这条路径根本不存在——因为选了 3 之后 start=1，不可能再回头选下标 0 的 2。这就是 `start` 参数的作用。

**再加一层剪枝**：先把 candidates 排序。递归里一旦 `candidates[i] > remain`，直接 `break`——因为后面的数只会更大，全都不行。这在小 target、大元素时能砍掉大量无效分支。

## 4. 正确性：为什么不会漏、不会重

**不重（无重复）**：我们给每个组合规定了一个「规范形式」——按所选元素在 candidates 中的下标**非降序**排列。递归中 `start = i` 保证了路径上的下标序列单调不减，所以任何一条搜索路径产出的组合，其下标序列都是唯一的规范形式。反过来，同一个多重集合不可能对应两条不同的非降下标序列（下标序列由元素值和出现次数唯一确定，因为 candidates 无重复元素）。因此每个组合最多被收集一次。

**不漏（完备）**：任取一个合法组合，把它的元素按下标排成非降序 i₁ ≤ i₂ ≤ … ≤ iₖ。从根出发，第 1 步选 i₁（start=0 允许），第 2 步选 i₂（start=i₁ ≤ i₂ 允许），依此类推，这条路径在搜索树中真实存在，且每一步 remain 都 ≥ 0（因为总和恰好为 target，前缀和不会超）。走到第 k 步时 remain=0，被收集。所以每个合法组合都至少被收集一次。

两者合起来：恰好一次。

## 5. 完整代码（Python）

```python
from typing import List

class Solution:
    def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]:
        # 排序是为了后面能「一旦超过就 break」的剪枝
        candidates.sort()
        res = []
        path = []

        def dfs(start: int, remain: int) -> None:
            # remain == 0：当前路径的和正好凑齐，收集一份拷贝
            if remain == 0:
                res.append(path[:])   # 必须拷贝，path 后面还会被修改
                return

            # 从 start 开始尝试，保证下标非降 → 不重复
            for i in range(start, len(candidates)):
                # 剪枝：当前数已经比剩余目标大，后面的数更大，直接结束本层循环
                if candidates[i] > remain:
                    break
                path.append(candidates[i])
                # 传 i 而不是 i+1：同一个数允许重复使用
                dfs(i, remain - candidates[i])
                path.pop()            # 回溯：撤销选择，恢复现场

        dfs(0, target)
        return res
```

关键点说明：`path[:]` 是浅拷贝，因为 `path` 是共享的可变列表，不拷贝的话最后 res 里全是空列表；`dfs(i, ...)` 里的 `i` 是「可重复」的体现，改成 `i+1` 就变成「每个数只能用一次」（那是第 40 题）；`break` 依赖排序，没排序只能用 `continue`。

## 6. 复杂度

设 n = len(candidates)，T = target，m = min(candidates)。

**时间**：搜索树的深度最多 T/m（每层至少加 m），每层最多 n 个分支，粗略上界 O(n^(T/m))。但这是很松的上界——`start` 约束和 `break` 剪枝让实际节点数远小于它。更贴切的说法是：时间与「搜索树中被访问的节点数 × 每个节点 O(1) 的工作量」成正比，而节点数受答案数量（<150）和剪枝共同约束。收集答案时 `path[:]` 拷贝长度最多 T/m，所以总时间还要乘上这个拷贝开销。面试里答「指数级，受剪枝和答案规模约束，最坏 O(n^(T/m))」即可。

**空间**：递归栈深度 O(T/m)，`path` 长度也是 O(T/m)，这是辅助空间；答案本身占 O(答案数 × 平均组合长度)。注意**没有**额外的 log 项——本题不涉及排序后的二分或分治，排序只花 O(n log n)，被指数级搜索淹没。

## 7. 边界与反例（至少 4 条）

1. **candidates=[2], target=1** → 期望 `[]`。容易错：没做 `candidates[i] > remain` 的剪枝时，会进入 dfs 但永远凑不齐，虽然结果也对，但若写成 `if remain < 0: return` 而忘了初始就小于 0 的情况，可能死循环或漏判。本题靠 break 直接返回空。

2. **candidates=[1], target=40** → 期望 `[[1]*40]`。容易错：这是最深的一条路径（深度 40），递归栈和 path 都到 40 层；如果误把 `dfs(i,...)` 写成 `dfs(i+1,...)`，会得到 `[]`，因为 1 只能用一次。

3. **candidates=[7,3,2], target=7（未排序输入）** → 期望 `[[2,2,3],[7]]`。容易错：如果忘了 `candidates.sort()` 却写了 `break`，遇到 7 之后 break 会漏掉后面的 3 和 2，答案错误。排序和 break 必须配对出现。

4. **candidates=[2,3,5], target=8** → 期望 `[[2,2,2,2],[2,3,3],[3,5]]`。容易错：`[3,2,3]` 这类排列不应出现；若 start 传错（比如每层都从 0 开始），会产出重复的排列版本。

5. **candidates=[2,4,6], target=3** → 期望 `[]`。容易错：最小元素 2 就大于 remain=3 吗？不，2<3，会进入；但 2+2=4>3 剪掉，4、6 直接 break。考验剪枝逻辑是否在「加入前」判断而非「加入后」。

## 8. 面试追问与变体（3 条）

1. **追问：如果每个数只能用一次呢？** 思路：递归传 `start = i + 1`，并且 candidates 有重复元素时要先排序、同层跳过相同值（这就是第 40 题「组合总和 II」）。

2. **追问：如果要求返回组合数而不是所有组合呢？** 思路：把 `res.append` 换成计数器加一，或者用 DP（完全背包计数），后者能把指数级降到 O(n·T)。

3. **追问：如果 candidates 里有负数怎么办？** 思路：本题的 `break` 剪枝和「remain 单调递减」前提全部失效，搜索可能无限深，需要额外约束（如每个数使用次数上限）或改用带记忆化的搜索；面试里通常说明「本题保证正数」即可。

## 9. 举一反三（2-3 道同类题）

- **40. 组合总和 II**：同样是无序组合搜索，区别是元素不可重复用 + 输入有重复值，需要 `i+1` 和同层去重。
- **77. 组合**：从 1..n 里选 k 个，同样是「下标非降 + start 参数」的模板，只是终止条件是路径长度而非和。
- **46. 全排列**：对照题——排列关心顺序，所以不能用 start 约束，而要用 used 数组标记，正好帮你分清「组合」和「排列」的搜索树差异。
