## 1. 一句话本质

对每个区间 `i`，在所有「起点 ≥ 区间 i 的终点」的区间里，挑起点最小的那个，返回它的下标。

注意这句话里藏着两个约束：**候选集由 `end_i` 决定**，**选择标准是 `start_j` 最小**。整道题的所有设计都围绕这两个词展开。

## 2. 读完题的第一反应

### 朴素解法：每个区间扫一遍全场

对每个 `i`，遍历所有 `j`，筛出 `start_j >= end_i` 的，再取 `start_j` 最小的。两层循环，`O(n²)`。

n 上限是 `2 * 10^4`，`n² = 4 * 10^8`。Python 里这个量级基本是 10 秒起步，必然超时。**瓶颈在于：对每个 i 都重新扫一遍全场，而全场的信息其实没变。**

### 关键观察：候选集只跟 `end_i` 有关，跟 `i` 是谁无关

题目要求「`start_j >= end_i` 且 `start_j` 最小」。这句话里**完全没有出现 `start_i`**。也就是说，区间 `i` 的起点是多少根本不参与判断，只有它的终点 `end_i` 有用。

这意味着：如果我把所有区间的**起点**单独拎出来排好序，那么对任意一个 `end_i`，我只需要在这个有序的起点数组里找「第一个 ≥ `end_i` 的位置」。这正是二分查找的标准形态。

第二个观察：题目保证**每个 start 都不同**。这条保证不是装饰——它保证了「起点最小的那个区间」是唯一的，不会出现两个区间起点相同、答案有歧义的情况。同时它也让我们可以放心地建立 `起点 → 下标` 的映射，不会覆盖。

这两条合起来，思路就出来了：**排序 + 二分**。

## 3. 从暴力到最优

### 第一步：把「找最小起点」变成「在有序数组里找下界」

拿示例 2 走一遍：`intervals = [[3,4],[2,3],[1,2]]`。

先抽出所有起点和对应下标：

| 起点 | 下标 |
|---|---|
| 3 | 0 |
| 2 | 1 |
| 1 | 2 |

按起点排序后：`starts = [1, 2, 3]`，`idx = [2, 1, 0]`。

现在逐个区间处理：

- `i = 0`，`end = 4`。在 `starts` 里找第一个 ≥ 4 的位置。`starts` 最大是 3，找不到 → `-1`。
- `i = 1`，`end = 3`。找第一个 ≥ 3 的位置，是下标 2（值 3）→ 映射回原下标 `idx[2] = 0`。
- `i = 2`，`end = 2`。找第一个 ≥ 2 的位置，是下标 1（值 2）→ `idx[1] = 1`。

结果 `[-1, 0, 1]`，和示例一致。

这里「找第一个 ≥ x 的位置」就是 `bisect_left`。为什么是 `left` 不是 `right`？因为条件是 `start_j >= end_i`，**等号要包含**。`bisect_left` 返回第一个 `>= x` 的位置，`bisect_right` 返回第一个 `> x` 的位置。差一个等号，答案就错。这是本题最容易踩的坑之一。

### 第二步：瓶颈消掉了吗

原来每个区间要扫 `n` 个候选，现在每个区间只做一次二分，`O(log n)`。总时间从 `O(n²)` 降到 `O(n log n)`，瓶颈变成了排序本身。

排序能不能省？不能——二分的前提就是有序。所以 `O(n log n)` 就是这题的复杂度下界（比较模型下），已经是最优了。

### 第三步：为什么不需要对 `end` 也排序

有人会想：是不是要把区间按 `end` 排序再双指针？不需要。因为每个 `i` 的查询是**独立的**，`end_i` 之间没有单调关系，双指针要求两个序列都单调才能移动指针。而二分对任意查询顺序都成立，所以直接对每个 `i` 单独二分即可，代码也更短。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证。

**不变量**：处理完任意区间 `i` 后，`starts` 数组始终是「所有区间起点按升序排列」，`idx[k]` 始终是「起点 `starts[k]` 对应的原区间下标」。这个不变量在排序后建立，之后不再修改，显然成立。

**不漏**：设 `p = bisect_left(starts, end_i)`。若 `p == len(starts)`，说明所有起点都 `< end_i`，不存在满足 `start_j >= end_i` 的区间，返回 `-1` 正确。若 `p < len(starts)`，则 `starts[p] >= end_i`，且对任意 `k < p` 有 `starts[k] < end_i`（二分下界的定义）。所以 `starts[p]` 是所有满足条件的起点中最小的，`idx[p]` 就是答案。

**不重**：题目保证起点互不相同，所以 `starts` 中不存在重复值，`bisect_left` 返回的位置唯一，答案唯一。如果起点允许重复，这里就要额外处理「多个区间起点相同取哪个」——但题面排除了这种情况，我们不需要考虑。

**边界自洽**：`i == j` 是允许的（题面明说）。当 `end_i <= start_i` 时（区间退化或正常），`bisect_left` 可能返回 `i` 自己，这是合法的，代码不需要特判。

## 5. 完整代码（Python）

```python
from bisect import bisect_left


class Solution:
    def findRightInterval(self, intervals):
        n = len(intervals)

        # 抽出 (起点, 原下标)，按起点升序排序
        # 题目保证起点互不相同，所以排序后起点严格递增
        order = sorted(range(n), key=lambda i: intervals[i][0])
        starts = [intervals[i][0] for i in order]

        res = [-1] * n
        for i in range(n):
            end_i = intervals[i][1]
            # 找第一个 >= end_i 的起点位置（等号必须包含，故用 left）
            p = bisect_left(starts, end_i)
            if p < n:
                # p 是排序后的位置，映射回原下标
                res[i] = order[p]
            # p == n 表示没有起点 >= end_i，保持 -1

        return res
```

几个实现细节值得说：

- `order` 存的是原下标，`starts` 是按 `order` 排好的起点。两者用同一个 `order` 对齐，这样 `order[p]` 就是 `starts[p]` 对应的原下标，不需要额外建字典。
- 没有用 `dict` 做「起点 → 下标」映射，因为排序后的数组已经天然承担了这个角色，少一次哈希表构建。
- `res` 初始化为全 `-1`，只在找到时覆盖，省掉一个 `else` 分支。

## 6. 复杂度

**时间 `O(n log n)`**：

- 排序 `order`：`O(n log n)`，这是主导项。
- 构建 `starts`：`O(n)`。
- 对每个 `i` 做一次 `bisect_left`：每次 `O(log n)`，共 `n` 次，合计 `O(n log n)`。
- 三项相加仍是 `O(n log n)`。

**空间 `O(n)`**：

- `order` 长度 `n`，`starts` 长度 `n`，`res` 长度 `n`，都是线性。
- 排序本身在 Python 里是 Timsort，额外空间最坏 `O(n)`。
- 没有递归，没有栈开销。

注意 `log n` 来自两处：排序和二分。不要笼统说「二分所以 log n」——排序也贡献了同样的量级，而且常数更大。

## 7. 边界与反例（至少 4 条）

**① 单区间**：`[[1,2]]` → `[-1]`。
容易错在：忘记处理 `p == n` 的情况，直接 `order[p]` 越界。或者误以为 `i == j` 时应该返回自己，其实 `start_i = 1 < end_i = 2`，不满足条件。

**② 区间自己就是答案**：`[[1,1]]` → `[0]`。
`end = 1`，`starts = [1]`，`bisect_left` 返回 0，`order[0] = 0`。这里 `i == j` 成立，是合法的。容易错在：加了一个 `if j != i` 的过滤，把正确答案滤掉了。题面明确说 `i` 可能等于 `j`。

**③ 等号边界**：`[[1,2],[2,3]]` → `[1,-1]`。
`end_0 = 2`，`starts = [1,2]`，`bisect_left([1,2], 2)` 返回 1，对应原下标 1。如果误用 `bisect_right`，会返回 2，越界变成 `-1`，答案错。这是 `>=` 和 `>` 的区别，必须用 `left`。

**④ 全部无解**：`[[5,6],[7,8]]` → `[-1,-1]`。
`end_0 = 6`，`starts = [5,7]`，`bisect_left` 返回 1，`order[1] = 1`——等等，这里其实有解。换个真正全无解的：`[[5,6],[1,2]]`，`end_0 = 6` 无解，`end_1 = 2` 找 `>= 2` 的起点是 5，对应下标 0，所以是 `[?]`。要构造全无解，需要每个 `end_i` 都大于所有起点，比如 `[[1,10],[2,20]]`：`end_0 = 10`，起点最大 2，无解；`end_1 = 20`，无解 → `[-1,-1]`。容易错在：以为「至少有一个区间能当别人的右区间」，没考虑全 `-1` 的输出。

**⑤ 负数和零**：`[[-5,-3],[-1,0]]` → `[1,-1]`。
`end_0 = -3`，找 `>= -3` 的起点，`-1` 满足，返回下标 1。负数不改变二分逻辑，但容易在手动验算时符号搞错。

## 8. 面试追问与变体（3 条）

**追问 1：如果起点允许重复，答案怎么定义？**
思路：题面要求「起点最小的区间」，起点相同时需要额外规则（比如取下标最小的）。此时 `bisect_left` 找到的是第一个相等位置，需要往后扫到相等段的末尾再取最小下标，或者排序时用 `(start, index)` 元组让顺序确定。

**追问 2：如果要返回「右侧区间」本身而不是下标，怎么改？**
思路：`order` 里存原下标，返回时改成 `intervals[order[p]]` 即可，其余逻辑不变。这题返回下标反而更省事，因为下标是稳定的，区间对象可能被复制。

**追问 3：如果要求「右侧区间」的终点也最小（即起点相同再比终点），怎么改？**
思路：排序键从 `start` 改成 `(start, end)`，二分时仍然只按 `start` 找下界，但找到后要在相等起点段内取 `end` 最小的。由于起点互不相同这条保证被打破，需要额外处理相等段。
