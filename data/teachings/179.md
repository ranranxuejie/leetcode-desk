## 1. 一句话本质

把一堆数字串按某种「拼接优先级」排成一个序列，使得从左到右拼起来的字符串字典序最大。

## 2. 读完题的第一反应

**朴素解法**：枚举所有排列，把每个排列拼成字符串，取最大的那个。`nums.length` 最大 100，排列数是 100!，完全不可行。即使剪枝也救不回来——瓶颈在于「排列空间是指数级的」，你根本枚举不完。

**关键观察**：题目要求的是「顺序」，而顺序问题往往可以退化成「两两比较」。具体来说，如果对于任意两个数 a、b，我们都能判断「a 排在 b 前面更好」还是「b 排在 a 前面更好」，那么整个问题就变成了一个**排序问题**。

那怎么判断两个数谁在前？直接比大小不行：示例 2 里 9 最大，排最前没问题；但 3 和 30 谁在前？3 > 30，可正确答案里是 "330" 而不是 "303"，说明 3 在前。再看 34 和 3：34 > 3，但正确答案是 "343" 而不是 "334"，说明 34 在前。所以「数值大小」这个直觉是错的。

正确的比较方式是：**把两个数拼起来看**。比较 `a+b` 和 `b+a` 这两个字符串，哪个字典序大，就说明哪种拼接方式更优。比如 a=3, b=30：`"330" > "303"`，所以 3 排在 30 前面。a=34, b=3：`"343" > "334"`，所以 34 排在 3 前面。这个比较规则同时解决了「谁在前」的问题，而且它只依赖两个元素，可以塞进排序的比较函数里。

## 3. 从暴力到最优

**暴力**：枚举排列，O(n!) 种，每种拼接 O(n·L)（L 是数字平均位数），总复杂度爆炸。瓶颈是「排列空间」。

**第一步优化**：注意到「最终顺序」只由元素之间的相对次序决定，而相对次序可以用一个比较器定义。于是把问题转成：定义一个比较器 `cmp(a, b)`，然后用任意 O(n log n) 排序算法排一遍。这一步把 n! 降到了 n log n。

**第二步：确定比较器**。比较器就是 `a+b > b+a`（字符串比较）。为什么不是 `a > b`？用示例 2 走一遍：

nums = [3, 30, 34, 5, 9]

- 比较 3 和 30：`"330"` vs `"303"` → 3 在前
- 比较 3 和 34：`"334"` vs `"343"` → 34 在前
- 比较 30 和 34：`"3034"` vs `"3430"` → 34 在前
- 比较 5 和 9：`"59"` vs `"95"` → 9 在前
- 比较 5 和 34：`"534"` vs `"345"` → 5 在前

按这个比较器排序，得到顺序 9, 5, 34, 3, 30，拼起来 `"9534330"`，和示例一致。

**第三步：处理全零**。如果排序后第一个元素是 `"0"`，说明所有数都是 0（因为 0 是最小的，能排第一说明没有正数），此时直接返回 `"0"`，否则会返回 `"000...0"`。

每一步的瓶颈消除：n! → n log n（转成排序），比较器从「数值比较」换成「拼接比较」（保证正确性），最后加一个全零特判（保证边界正确）。

## 4. 正确性：为什么不会漏、不会重

用**交换论证**来证。

**定义**：对任意两个字符串 x、y，定义 x ≻ y 当且仅当 `x+y > y+x`（字典序）。我们要证：按 ≻ 排序得到的序列，拼接后字典序最大。

**引理 1（传递性）**：≻ 是传递的。即若 a ≻ b 且 b ≻ c，则 a ≻ c。这个引理不平凡——它依赖字符串拼接的一个性质：`a+b > b+a` 等价于 `a` 的无限重复串大于 `b` 的无限重复串（可以想象成比较 `aaaa...` 和 `bbbb...`）。在这个视角下，≻ 就是无限重复串的字典序，字典序当然传递。严格证明略（面试时说出「可以看成无限重复串比较」即可）。

**引理 2（交换论证）**：设有一个排列，其中相邻两个元素 a、b 满足 b ≻ a（即 b 应该在前但实际在后）。交换它们，拼接结果不会变小。证明：设前缀为 P，后缀为 S，交换前是 `P + a + b + S`，交换后是 `P + b + a + S`。由于 `b+a > a+b`（b ≻ a 的定义），且前缀 P 相同，所以交换后字典序更大。

**主定理**：对任意排列，只要存在相邻逆序对（按 ≻ 定义），就能通过交换让它变大。反复交换直到没有逆序对，得到的就是 ≻ 下的有序序列，且每一步都不变小。所以有序序列的拼接结果不小于任何其他排列，即最大。

**不会漏**：排序算法会遍历所有元素，每个元素恰好出现一次，拼接时不会漏掉任何一个。
**不会重**：每个元素在排序结果中恰好出现一次，拼接时不会重复。

## 5. 完整代码（Python）

```python
from functools import cmp_to_key

class Solution:
    def largestNumber(self, nums: list[int]) -> str:
        # 把整数转成字符串，后续所有比较都在字符串层面做
        strs = [str(x) for x in nums]

        # 比较器：a 排在 b 前面 当且仅当 a+b > b+a
        # 返回负数表示 a 应排在 b 前（Python sort 的约定）
        def cmp(a: str, b: str) -> int:
            if a + b > b + a:
                return -1   # a 更大，排前面
            elif a + b < b + a:
                return 1    # b 更大，a 排后面
            else:
                return 0    # 相等，顺序无所谓

        # 用自定义比较器排序，O(n log n) 次比较，每次比较 O(L)
        strs.sort(key=cmp_to_key(cmp))

        # 全零特判：排序后第一个是 "0" 说明全是 0
        # 否则会拼出 "000...0" 这种非法结果
        if strs[0] == "0":
            return "0"

        return "".join(strs)
```

关键逻辑说明：
- `cmp_to_key` 把「比较函数」转成「key 函数」，让 Python 的 `sort` 能用自定义比较器。Python 3 的 `sort` 只接受 key，所以必须转换。
- 比较器返回 `-1` 表示 a 应在前，这是 Python 的约定（和 C++ 的 `bool cmp(a,b)` 返回 true 表示 a 在前不同，注意区分）。
- 全零特判放在排序之后、拼接之前，因为只有排序后才能确定「第一个是不是 0」。

## 6. 复杂度

**时间**：O(n log n · L)，其中 n 是数组长度，L 是数字的最大位数（本题 nums[i] ≤ 10^9，所以 L ≤ 10，可视为常数）。

- `n log n` 来自排序的比较次数（标准比较排序的下界）。
- 每次比较要做两次字符串拼接和一次字符串比较，拼接长度是 O(L)，比较也是 O(L)，所以每次比较 O(L)。
- 总时间 = 比较次数 × 每次比较代价 = O(n log n) × O(L) = O(n log n · L)。
- 如果把 L 当常数，就是 O(n log n)。

**空间**：O(n · L)。

- `strs` 列表存了 n 个字符串，每个长度 O(L)，共 O(n · L)。
- 排序本身（Python 的 Timsort）需要 O(n) 的辅助空间存指针，但字符串本身不复制，所以总额外空间是 O(n)（指针）+ O(n·L)（字符串内容）。
- 结果字符串 `"".join(strs)` 也是 O(n · L)。
- 所以空间 O(n · L)，L 为常数时 O(n)。

## 7. 边界与反例（至少 4 条）

1. **输入 `[0, 0]`** → 期望 `"0"` → 容易错：不特判会返回 `"00"`，力扣会判错。这是最常见的坑。
2. **输入 `[0]`** → 期望 `"0"` → 容易错：同上，单元素也要走特判逻辑（虽然 `strs[0] == "0"` 恰好能覆盖）。
3. **输入 `[10, 2]`** → 期望 `"210"` → 容易错：如果按数值排序（10 < 2 是错的，应该 2 在前），会得到 `"102"`。必须用拼接比较：`"210" > "102"`，所以 2 在前。
4. **输入 `[3, 30, 34, 5, 9]`** → 期望 `"9534330"` → 容易错：如果按数值降序排，得到 `[34, 30, 9, 5, 3]`，拼出 `"3430953"`，完全不对。必须用拼接比较器。
5. **输入 `[1, 1, 1]`** → 期望 `"111"` → 容易错：比较器返回 0 时顺序无所谓，但要注意 `cmp_to_key` 对相等元素的处理是稳定的，不会出错，但如果不小心写成 `>=` 返回 -1 可能导致排序不稳定（虽然结果一样，但逻辑上不严谨）。
6. **输入 `[999999999, 999999998]`** → 期望 `"999999999999999998"` → 容易错：位数接近 10^9，拼接后字符串很长，但 Python 字符串比较没问题，注意不要用整数比较（会溢出，虽然 Python 不会，但其他语言会）。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求组成最小的数呢？** → 思路：把比较器反过来，`a+b < b+a` 时 a 在前；同样要处理前导零（但最小数允许前导零吗？需要和面试官确认，通常返回 `"0"` 或去掉前导零）。
2. **追问：为什么这个比较器满足传递性？能证明吗？** → 思路：把每个字符串看成无限重复串（如 `"3"` 看成 `"333..."`），比较 `a+b` 和 `b+a` 等价于比较这两个无限串的字典序，字典序天然传递。这是本题最容易被追问的点，要能说清楚。
3. **追问：如果 nums 里有负数怎么办？** → 思路：本题限定非负，有负数时拼接比较器不再适用（负号会干扰字典序），需要重新设计规则，通常这类题不会这么变，但可以提一句「需要重新定义比较语义」。
