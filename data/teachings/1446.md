## 1. 一句话本质

在字符串里找**最长的、由同一个字符连续重复构成的片段**，返回它的长度。

注意「子字符串」在这里必须是**连续**的（题面示例 1 的 "ee" 就是从 "leetcode" 里连续取出来的），所以这题不是「统计某字符出现次数」——"leetcode" 里 'e' 出现 3 次，但答案是 2，因为那 3 个 'e' 不连续。这个区别是本题唯一的坑。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子串 `s[i:j]`，对每个子串检查「是否只含一种字符」，是就更新答案。子串有 O(n²) 个，每次检查 O(n)，总复杂度 O(n³)。n ≤ 500 时这也能过（500³ 太大，实际是 O(n²) 个子串 × O(n) 检查，约 1.25 亿次字符比较，勉强），但这不是我们想要的答案——面试官问这题，考的是你能不能看出**根本不需要枚举所有子串**。

**关键观察**：一个「只含一种字符」的子串，如果它长度是 L，那么它内部任意长度为 L-1 的连续片段也满足条件。也就是说，**最优解一定可以「贴着」某个极大连续段取**。更直接地说：把字符串切成若干个「极大连续相同字符段」（run），答案就是这些 run 里最长的那个长度。

为什么这个观察能让你想到下一步？因为它把「枚举子串的起点和终点」这个二维问题，压成了「从左到右扫一遍、维护当前 run 长度」的一维问题。你不需要知道最优子串在哪，只需要在扫描时**记住到目前为止见过的最长 run**。

## 3. 从暴力到最优

**暴力版**（O(n²) 枚举起点 + 向后延伸）：

```python
best = 0
for i in range(len(s)):
    j = i
    while j < len(s) and s[j] == s[i]:
        j += 1
    best = max(best, j - i)
```

这个版本其实已经是 O(n²) 最坏（比如 "aaaa..." 每个起点都扫到底），但思路已经接近了。瓶颈在于：从 i 出发扫到 j 之后，从 i+1 出发又要重扫一遍。

**消掉重复扫描**：注意到如果 `s[i..j-1]` 全是同一字符，那么从 `i+1` 出发的 run 一定在 `j` 处结束（或更早，但不会更晚）。所以**一次扫描就能同时得到所有 run 的长度**——只要在扫描时维护「当前 run 长度」和「历史最大 run 长度」两个变量。

**小例子走一遍**：`s = "abbcccddddeeeeedcba"`，答案是 5（"eeeee"）。

| 下标 | 字符 | 与前一个是否相同 | cur | best |
|---|---|---|---|---|
| 0 | a | —（初始化） | 1 | 1 |
| 1 | b | 不同 | 1 | 1 |
| 2 | b | 相同 | 2 | 2 |
| 3 | c | 不同 | 1 | 2 |
| 4 | c | 相同 | 2 | 2 |
| 5 | c | 相同 | 3 | 3 |
| 6 | d | 不同 | 1 | 3 |
| 7 | d | 相同 | 2 | 3 |
| 8 | d | 相同 | 3 | 3 |
| 9 | d | 相同 | 4 | 4 |
| 10 | e | 不同 | 1 | 4 |
| 11 | e | 相同 | 2 | 4 |
| 12 | e | 相同 | 3 | 4 |
| 13 | e | 相同 | 4 | 4 |
| 14 | e | 相同 | 5 | **5** |
| 15 | d | 不同 | 1 | 5 |
| 16 | c | 不同 | 1 | 5 |
| 17 | b | 不同 | 1 | 5 |
| 18 | a | 不同 | 1 | 5 |

扫描结束，best = 5。注意 `cur` 在字符变化时**重置为 1**（不是 0），因为新字符自己就构成一个长度 1 的 run。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义扫描到下标 `i`（含）时的不变量：

> `cur` 等于「以 `i` 结尾的、只含一种字符的最长连续片段」的长度；`best` 等于「`s[0..i]` 中所有只含一种字符的连续片段」的最大长度。

**初始化**：`i = 0` 时，`cur = 1`（单个字符自成一段），`best = 1`，不变量成立。

**归纳步**：假设处理完 `i-1` 时不变量成立，处理 `i` 时：
- 若 `s[i] == s[i-1]`，则以 `i` 结尾的最长同字符段 = 以 `i-1` 结尾的最长同字符段 + 1，即 `cur` 加 1，正确。
- 若 `s[i] != s[i-1]`，则以 `i` 结尾的同字符段不可能延伸到 `i-1` 之前，只能是 `s[i]` 本身，长度 1，正确。
- `best = max(best, cur)` 保证 `best` 始终是「已扫描部分所有 run 的最大值」，正确。

**为什么不会漏**：任何「只含一种字符的连续片段」都必然以某个下标 `i` 结尾，而归纳保证 `cur` 在那一刻恰好等于「以 `i` 结尾的最长同字符段」，所以 `best` 至少覆盖了它。又因为 `best` 只从真实的 run 长度中取 max，**不会重**（不会算出比真实 run 更长的值）。两者合起来，最终 `best` 就是全局最大 run 长度，也就是题目定义的「能量」。

## 5. 完整代码（Python）

```python
class Solution:
    def maxPower(self, s: str) -> int:
        # 空串按题意不会出现（1 <= len(s)），但防御性处理
        if not s:
            return 0

        best = 1          # 历史最长 run 长度，至少为 1
        cur = 1           # 以当前字符结尾的 run 长度

        for i in range(1, len(s)):
            if s[i] == s[i - 1]:
                cur += 1          # 延续当前 run
            else:
                cur = 1           # 字符变了，新 run 从长度 1 开始
            if cur > best:
                best = cur        # 更新历史最大值

        return best
```

关键点：`cur` 重置为 **1** 而不是 0；`best` 初值取 1 而不是 0（因为长度至少 1，且循环从下标 1 开始，若 s 只有一个字符，循环不执行，直接返回 1）。

## 6. 复杂度

- **时间 O(n)**：`for` 循环执行 `n-1` 次，每次只做常数次比较和赋值。n 来自字符串长度，没有嵌套循环，所以是线性。这里**没有 log n 项**——没有任何分治或二分。
- **空间 O(1)**：只用了 `best`、`cur`、`i` 三个整型变量，与 n 无关。注意我们**没有**把字符串切片存下来（切片会引入 O(n) 空间），只比较相邻字符。

## 7. 边界与反例（至少 4 条）

1. **`s = "a"`** → 期望 `1` → 容易错在：循环从下标 1 开始、一次都不执行，如果 `best` 初值写成 0 就会返回 0。所以 `best` 必须初始化为 1。
2. **`s = "abcde"`** → 期望 `1` → 容易错在：每个字符都不同，`cur` 每次重置为 1，若误写成重置为 0，答案会变成 0 或负数逻辑。
3. **`s = "aaaa"`** → 期望 `4` → 容易错在：全程 `cur` 递增，若忘记在循环内更新 `best`（只在循环外取 `cur`），会漏掉「最长 run 在末尾」的情况。
4. **`s = "aabbbbbcc"`** → 期望 `5` → 容易错在：最长 run 在中间，前后都有更短的 run，若只在字符变化时更新 `best` 而漏掉「run 结束时才比较」，可能错过中间段。本代码每步都更新，安全。
5. **`s = "leetcode"`** → 期望 `2` → 容易错在：误以为答案是 'e' 的总出现次数 3。这提醒你「连续」这个约束不能丢。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回那个最长子串本身（而不只是长度）？** 思路：额外记录当前 run 的起始下标 `start`，在 `cur > best` 时同步记录 `best_start = i - cur + 1`，最后返回 `s[best_start:best_start+best]`，仍是 O(n) 时间、O(1) 额外空间（返回值本身除外）。
2. **追问：如果字符串是流式输入（不能存整个串）？** 思路：本题解法天然适合流式——只需保留「上一个字符」和两个计数器，来一个字符处理一个，空间 O(1)，这正是滑动窗口/在线扫描的优势。
3. **追问：如果「能量」定义为「最多包含 k 种不同字符的最长子串」？** 思路：变成滑动窗口（双指针）问题，用哈希表维护窗口内字符种类数，右指针扩张、种类超 k 时左指针收缩，O(n) 时间、O(字符集) 空间。本题是 k=1 的特例。

## 9. 举一反三（2-3 道同类题）

1. **力扣 485. 最大连续 1 的个数**：和本题几乎同构，只是字符集限定为 0/1，同样是「扫描 + 维护当前 run 长度」。
2. **力扣 1004. 最大连续 1 的个数 III**：允许翻转 k 个 0，是本题的滑动窗口升级版，共同点是「连续段 + 维护窗口内某种计数」。
3. **力扣 424. 替换后的最长重复字符**：允许替换 k 个字符使某段全同，本质是「找最长窗口使窗口内 (长度 - 最多字符频次) ≤ k」，和本题共享「连续段 + 频次维护」的思想。
