## 1. 一句话本质

从所有初始腐烂橘子同时出发，求「最远的那个新鲜橘子」到最近腐烂源的最短距离（按四邻接步数计），若存在新鲜橘子到不了任何腐烂源则返回 -1。

## 2. 读完题的第一反应

**朴素解法**：模拟每一分钟。每一分钟扫描整个 m×n 网格，把所有「与腐烂橘子四邻接」的新鲜橘子标记为腐烂，分钟数 +1；直到某一分钟没有任何橘子变腐烂为止，再检查是否还剩新鲜橘子。

它卡在哪：假设答案是 T 分钟，就要扫 T 遍全图，复杂度 O(T·m·n)。题面给的 m,n ≤ 10 时这当然能过，但这不是这道题被归为 BFS 的原因——真正的瓶颈是**这个模拟没有利用「同一分钟内所有腐烂是并行发生的」这个结构**，T 最大可以到 m·n 量级，于是退化成 O((mn)²)。面试官问这题，考的就是你能不能把它识别成「多源最短路」。

**关键观察**：题面说「每分钟，腐烂的橘子周围 4 个方向上相邻的新鲜橘子都会腐烂」。这句话等价于：一个新鲜橘子在第 t 分钟腐烂，当且仅当它到某个初始腐烂橘子的**最短四邻接路径长度**恰好是 t。也就是说，每个格子的腐烂时刻 = 它到「腐烂源集合」的最短距离，而答案 = 所有新鲜橘子这个距离的最大值。

一旦把「逐分钟模拟」翻译成「求到源集合的最短距离」，就落到了 BFS 的射程内：BFS 按层扩展，第 k 层恰好是距离为 k 的所有格子，天然对应「第 k 分钟腐烂的那一批」。多个源怎么办？把所有初始腐烂橘子**同时**放进队列作为第 0 层——这就是多源 BFS。

## 3. 从暴力到最优

**暴力（逐分钟全图扫描）**：每轮 O(mn) 找新腐烂，共 T 轮 → O(T·mn)。

**瓶颈在哪**：每一轮里，绝大多数格子上一轮已经被检查过、这一轮结果不会变，重复扫描是纯浪费。真正「有新信息」的只有上一轮刚变腐烂的那些格子的邻居。

**消掉瓶颈**：把「上一轮刚变腐烂的格子」放进一个队列，只从它们出发检查邻居。每个格子最多入队一次、出队一次，总工作量 O(mn)。这就是 BFS。

**小例子走一遍**，用示例 1：

```
grid = [[2,1,1],
        [1,1,0],
        [0,1,1]]
```

初始：腐烂源只有 (0,0)。新鲜橘子共 6 个（(0,1),(0,2),(1,0),(1,1),(2,1),(2,2)）。

- 队列初始化：`q = [(0,0)]`，`fresh = 6`，`minutes = 0`。
- **第 1 层**：弹出 (0,0)，邻居 (0,1)=1、(1,0)=1 变腐烂，入队，`fresh = 4`。本层结束，`minutes = 1`。`q = [(0,1),(1,0)]`。
- **第 2 层**：弹出 (0,1) → 邻居 (0,2) 腐烂；弹出 (1,0) → 邻居 (1,1) 腐烂。`fresh = 2`，`minutes = 2`。`q = [(0,2),(1,1)]`。
- **第 3 层**：弹出 (0,2) → 邻居 (1,2) 是 0，跳过；弹出 (1,1) → 邻居 (2,1) 腐烂。`fresh = 1`，`minutes = 3`。`q = [(2,1)]`。
- **第 4 层**：弹出 (2,1) → 邻居 (2,2) 腐烂。`fresh = 0`，`minutes = 4`。`q = [(2,2)]`。
- **第 5 层**：弹出 (2,2) → 邻居 (2,1) 已腐烂、(1,2) 是 0，无新增。`fresh` 仍为 0，但这一层没有产生任何新腐烂，所以 `minutes` 不应再 +1。

这里有个实现细节必须讲清楚：**分钟数只在「本层确实有新橘子变腐烂」时才递增**。常见写法是用 `for _ in range(len(q))` 把一层处理完再 `minutes += 1`，但这样最后一层空转也会 +1，得到 5 而不是 4。正确做法是：处理完一层后，如果队列非空（说明下一层还有东西要处理）才 +1；或者更稳的写法是记录每个格子的距离 `dist`，最后取 `max(dist)`。我在第 5 节代码里用「层处理完、队列非空才 +1」的方式，并在注释里点明。

对照示例 2：

```
grid = [[2,1,1],
        [0,1,1],
        [1,0,1]]
```

左下角 (2,0)=1，它的四邻是 (1,0)=0、(2,1)=0，被 0 完全隔断，BFS 永远到不了它。BFS 结束后 `fresh > 0`，返回 -1。这正是「多源最短路 + 可达性检查」的第二个职责。

## 4. 正确性：为什么不会漏、不会重

**不变量**：BFS 处理完第 k 层后，队列中剩下的所有格子到源集合的最短距离都 ≥ k+1，且所有距离 ≤ k 的格子都已被处理过；同时，所有「距离为 k 的新鲜橘子」在这一层结束时都已变成腐烂。

**为什么不会漏**：设某新鲜橘子 x 到源集合的最短距离为 d。沿这条最短路，x 的前一个格子 y 距离为 d-1。由归纳，y 在第 d-1 层被处理（或本身就是源，d=1 时 y 是源，在第 0 层入队），处理 y 时会把 x 入队，所以 x 一定在第 d 层被访问到。归纳基：所有源距离为 0，初始就在队列里。

**为什么不会重**：一个格子一旦变腐烂（值从 1 改成 2）或被标记访问，就不会再次入队。BFS 的层序保证第一次访问它时用的就是最短距离——若存在更短路径，那条路径上的前驱会更早被处理，从而更早把它入队，矛盾。所以每个格子入队恰好一次。

**答案为什么是最大距离**：腐烂是并行传播的，第 t 分钟腐烂的格子集合 = 距离恰为 t 的格子集合。全部腐烂所需分钟数 = 所有新鲜橘子距离的最大值。若某新鲜橘子距离为 ∞（不可达），则永远烂不掉，返回 -1。

## 5. 完整代码（Python）

```python
from collections import deque

class Solution:
    def orangesRotting(self, grid):
        m, n = len(grid), len(grid[0])
        q = deque()
        fresh = 0

        # 1) 初始化：所有腐烂橘子作为多源 BFS 的第 0 层；统计新鲜橘子数
        for i in range(m):
            for j in range(n):
                if grid[i][j] == 2:
                    q.append((i, j))
                elif grid[i][j] == 1:
                    fresh += 1

        # 边界：一开始就没有新鲜橘子，0 分钟即可（对应示例 3）
        if fresh == 0:
            return 0

        minutes = 0
        dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        # 2) 逐层 BFS：每一层 = 同一分钟内新腐烂的一批
        while q:
            size = len(q)          # 固定本层节点数，避免把下一层混进来
            rotted_this_layer = 0  # 本层实际感染了几个新鲜橘子
            for _ in range(size):
                x, y = q.popleft()
                for dx, dy in dirs:
                    nx, ny = x + dx, y + dy
                    # 越界、空格、已腐烂的格子都跳过
                    if 0 <= nx < m and 0 <= ny < n and grid[nx][ny] == 1:
                        grid[nx][ny] = 2   # 立刻标记为腐烂，防止同层/后续重复入队
                        q.append((nx, ny))
                        fresh -= 1
                        rotted_this_layer += 1
            # 只有本层真的感染了新橘子，时间才前进一分钟
            if rotted_this_layer > 0:
                minutes += 1

        # 3) 还有新鲜橘子没烂 → 被 0 隔断，不可达
        return minutes if fresh == 0 else -1
```

两个容易写错的地方，代码里已经用注释标出：一是 `size = len(q)` 必须在 `for` 之前取，否则队列在循环中变长会导致层边界错乱；二是 `minutes` 的递增条件，用 `rotted_this_layer > 0` 而不是无条件 +1，才能让示例 1 输出 4 而不是 5。

## 6. 复杂度

**时间 O(m·n)**。初始化扫描全图一次，O(mn)。BFS 中每个格子最多入队一次、出队一次，每次出队检查 4 个邻居，是常数工作，总计 O(mn)。没有排序、没有二分，所以**不存在 log 项**——这里的 n 指的是网格总格数 mn，不是某个数组长度。

**空间 O(m·n)**。队列最坏情况下同时容纳一整层，一层最多 O(mn) 个格子（例如源在中心、网格是棋盘状时）。另外没有额外开 visited 数组，直接原地把 1 改成 2 复用 grid 做标记，所以额外空间就是队列本身。递归栈不存在（BFS 是迭代的），这点比 DFS 写法安全。

## 7. 边界与反例（至少 4 条）

1. **`[[0,2]]` → 0**。一开始就没有新鲜橘子。容易错在：直接返回 BFS 层数，而 BFS 从 (0,1) 出发没有邻居可感染，若按「每层 +1」会得到 1。所以必须先判 `fresh == 0` 提前返回 0（示例 3 就是考这个）。

2. **`[[1]]` → -1**。只有一个新鲜橘子、没有任何腐烂源。容易错在：队列初始为空，`while q` 直接不进，若忘了最后检查 `fresh`，会返回 0，误以为「0 分钟就烂完了」。

3. **`[[2,1,1],[1,1,0],[0,1,1]]` → 4**。容易错在分钟数多算 1（最后一层空转），见第 3 节的分析。这是本题最高频的 off-by-one。

4. **`[[2,1,1],[0,1,1],[1,0,1]]` → -1**。左下角被 0 围死。容易错在：BFS 跑完只看队列空没空就返回 `minutes`，忘了检查 `fresh` 是否归零。注意这个反例里 BFS 是能正常结束的，不会死循环，所以错误很隐蔽。

5. **`[[2,2],[1,1]]` → 1**。多个源同时出发。容易错在：把多源写成对每个源单独跑一次 BFS 再取 min，虽然结果对但复杂度退化；或者只把第一个源入队，导致 (1,1) 要绕路、答案偏大。

6. **`[[1,1,1],[1,2,1],[1,1,1]]` → 2**。源在正中心，最远角距离为 2。容易错在：把「四邻接」写成八邻接（含对角），会得到 1。

## 8. 面试追问与变体（3 条）

**追问 1：如果每分钟腐烂可以沿八个方向（含对角）传播，怎么改？**
把 `dirs` 换成 8 个方向即可，BFS 框架、正确性论证、复杂度全不变——因为 BFS 只依赖「图是单位权重的」，与邻居个数无关。这题考的是你能否说清「变的只是邻接关系，不变的是分层最短路的骨架」。

**追问 2：不返回分钟数，而是返回每个新鲜橘子各自的腐烂时刻矩阵，怎么做？**
把 `minutes` 换成 `dist` 二维数组，入队时 `dist[nx][ny] = dist[x][y] + 1`，源初始化为 0，不可达的保持 -1。本质是把 BFS 的「层号」显式存下来，而不是靠外层计数器推。

**追问 3：网格很大（比如 10^6 格）且稀疏，怎么优化空间？**
队列里只存坐标，不存距离（距离靠层计数推），已经是最省的；若要进一步省，可考虑按行压缩或用位图标记访问状态。但要注意：本题必须原地改 grid 才能省掉 visited，若不允许修改输入，就得额外开 O(mn) 的 visited，空间翻倍——面试时主动点出这个 trade-off 是加分项。
