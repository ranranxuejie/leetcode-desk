## 1. 一句话本质

判断一个整数的十进制数字序列是否**左右对称**——注意是「数字序列」对称，不是「数值」对称，符号和小数点都不参与。

## 2. 读完题的第一反应

**朴素解法**：把整数转成字符串 `s = str(x)`，然后判断 `s == s[::-1]`。这在 Python 里一行就写完了，时间复杂度 O(log₁₀|x|)（数字的位数），空间也是 O(log₁₀|x|)（字符串长度）。

它卡在哪？其实**没卡在复杂度上**——位数最多 10 位（因为 x 在 int32 范围内），字符串方案完全够快。它卡在**题目进阶要求**：不许转字符串。面试官问这道题，八成就是想看你不用字符串怎么把数字「从两头往中间」拆开。所以真正的瓶颈是：**整数没有下标，你没法像数组那样 `s[i]` 和 `s[n-1-i]` 直接比**。

**关键观察**：整数的「末尾数字」很容易拿——`x % 10`；整数的「开头数字」也能拿——`x // 10^(位数-1)`。但每次取开头都要重新算位数，很别扭。换个方向想：**回文数的后半段反转过来，应该等于前半段**。比如 1221，后半段 `21` 反转成 `12`，正好等于前半段 `12`。而「从末尾取数字并反转」恰好是整数最擅长的操作：`rev = rev * 10 + x % 10`。这就是下一步的入口。

## 3. 从暴力到最优

**第 0 步（暴力）**：`str(x) == str(x)[::-1]`。能过，但不满足进阶。

**第 1 步（整体反转整数）**：把 x 整个反转成 `rev`，再判断 `rev == x`。以 x = 1221 为例：

| 轮次 | x 当前值 | 取出的末位 d = x%10 | rev 更新后 | x 更新后 |
|---|---|---|---|---|
| 初始 | 1221 | — | 0 | 1221 |
| 1 | 1221 | 1 | 1 | 122 |
| 2 | 122 | 2 | 12 | 12 |
| 3 | 12 | 2 | 122 | 1 |
| 4 | 1 | 1 | 1221 | 0 |

`rev = 1221 == x 原值`，返回 true。这已经不用字符串了，复杂度 O(log₁₀|x|)。**瓶颈**：反转整个数有溢出风险（在 C++/Java 里 `rev` 可能超出 int 范围；Python 不会溢出，但面试官会追问「如果语言会溢出怎么办」），而且反转到一半其实信息就够了。

**第 2 步（只反转一半）**：观察到回文数只需要比较前后两半。以 x = 1221 为例，循环条件是 `x > rev`（还没反转到中间）：

| 轮次 | x | rev | 判断 x > rev |
|---|---|---|---|
| 初始 | 1221 | 0 | 是 |
| 1 | 122 | 1 | 是 |
| 2 | 12 | 12 | 否，停 |

停下时 `x = 12`，`rev = 12`，相等 → true。

再看奇数位 x = 12321：

| 轮次 | x | rev | 判断 |
|---|---|---|---|
| 初始 | 12321 | 0 | 是 |
| 1 | 1232 | 1 | 是 |
| 2 | 123 | 12 | 是 |
| 3 | 12 | 123 | 否，停 |

停下时 `x = 12`，`rev = 123`。中间那位 `3` 被多反转到 rev 里了，所以比较时要把 rev 去掉末位：`rev // 10 == x` → `12 == 12` → true。

**第 3 步（提前剪枝）**：负数一定不是回文（负号没法对称），末位是 0 且 x 本身不是 0 的数也一定不是（比如 10 反转成 01，开头不可能是 0）。这两条在进入循环前就返回，省掉无谓计算。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。设原始输入为 `n`（已通过剪枝，n ≥ 0 且 n 非「末位 0 的非零数」）。循环过程中维护：

> **不变量**：`rev` 恰好是「n 的末 k 位数字」反转后的值，`x` 恰好是「n 去掉末 k 位」后的值，其中 k 是已执行的循环轮数。

- **初始化**：k = 0，`rev = 0`（空串反转），`x = n`（去掉 0 位），成立。
- **保持**：每轮取 `d = x % 10`（即 n 的第 k+1 位末位），`rev = rev*10 + d` 相当于在已反转串前面拼上 d，正好是「末 k+1 位反转」；`x //= 10` 正好是「去掉末 k+1 位」。成立。
- **终止**：循环在 `x <= rev` 时停。此时 k 大约是一半位数（严格说，是 rev 的位数追上或超过 x 的位数时）。

终止时有两种情况：

1. **偶数位**：`x == rev`，说明前半段等于后半段反转，整个数对称 → 回文。
2. **奇数位**：`rev` 比 `x` 多一位（中间那位被反转到 rev 的末位），`rev // 10 == x` 说明去掉中间位后前后对称 → 回文。

反过来，如果终止时两个条件都不满足，说明存在一对不对称的数字，必然不是回文。**不会漏**：任何回文数在循环终止时必然落入上述两种情况之一（因为对称性保证前后半段相等）。**不会重**：循环每轮恰好消耗一位，终止条件唯一，不存在重复判断。

## 5. 完整代码（Python）

```python
class Solution:
    def isPalindrome(self, x: int) -> bool:
        # 剪枝 1：负数一定不是回文（负号无法对称）
        # 剪枝 2：末位为 0 且本身不是 0 的数一定不是回文
        #         （否则反转后首位是 0，而整数没有前导 0）
        if x < 0 or (x % 10 == 0 and x != 0):
            return False

        rev = 0
        # 只反转后半段：当 rev 追上或超过 x 时，说明已到中间
        while x > rev:
            rev = rev * 10 + x % 10   # 把 x 的末位拼到 rev 末尾
            x //= 10                  # 砍掉 x 的末位

        # 偶数位：x == rev；奇数位：中间那位在 rev 末位，去掉再比
        return x == rev or x == rev // 10
```

## 6. 复杂度

- **时间**：O(log₁₀|x|)。循环每轮把 `x` 除以 10，循环次数是 x 的十进制位数，即 ⌊log₁₀|x|⌋ + 1。注意这里的 n 是「数值大小」，位数是 log 级别，所以是 O(log n) 而不是 O(n)。x 最大约 2×10⁹，位数最多 10，实际循环不超过 5 轮（只反一半）。
- **空间**：O(1)。只用了 `rev` 一个整型变量，没有字符串、没有数组。这正是相对字符串解法（O(log n) 空间）的优势所在。

## 7. 边界与反例（至少 4 条）

1. **x = 0** → true。容易错：`x % 10 == 0` 的剪枝如果写成 `x % 10 == 0` 而不加 `and x != 0`，会把 0 误判为 false。0 是回文。
2. **x = 10** → false。容易错：不剪枝直接进循环，`rev` 会变成 1，`x` 变成 1，`x == rev` 成立，误判为 true。必须靠「末位 0 且非 0」剪枝挡掉。
3. **x = -121** → false。容易错：只想着数字部分 121 对称，忘了负号。剪枝 `x < 0` 直接返回。
4. **x = 12321**（奇数位）→ true。容易错：只写 `x == rev` 不写 `x == rev // 10`，奇数位回文全被判 false。
5. **x = 1000021** → false。容易错：中间有多个 0，反转一半后 `x = 100`、`rev = 1200`，`rev // 10 = 120 ≠ 100`，正确判 false；但如果剪枝或循环条件写错（比如用 `x >= rev`），可能提前停导致误判。

## 8. 面试追问与变体（3 条）

1. **追问：如果语言会整数溢出（C++/Java），你的写法安全吗？** 思路：只反转一半，`rev` 的位数不超过原数一半，最大约 10⁵ 量级，远小于 int 上限；即便反转整个数，也可在 `rev > INT_MAX/10` 时提前判 false。
2. **追问：不用除法、只用位运算能做吗？** 思路：十进制回文和二进制无关，位运算帮不上；但可以改成判断「二进制回文」（见下一节），那时 `x & 1` 取末位、`x >>= 1` 去末位，结构完全同构。
3. **追问：如果输入是字符串但允许前后有空格、正负号，怎么判？** 思路：先做规范化（strip、去符号、去前导 0），再双指针从两头向中间比，本质和本题「前后半段对称」是同一件事。
