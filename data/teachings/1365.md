## 1. 一句话本质

对每个 `nums[i]`，数一数整个数组里严格小于它的元素有多少个——注意是「值」的比较，不是「位置」的比较，所以同一个值出现几次，答案就重复几次。

## 2. 读完题的第一反应

**朴素解法**：对每个 `i`，再扫一遍整个数组数 `nums[j] < nums[i]` 的个数。两层循环，`O(n²)`。n ≤ 500 时其实能过，但面试官不会满意——这题被标了「计数排序 / 排序」标签，说明出题人想考的是「怎么把重复比较消掉」。

**卡在哪**：瓶颈在于「每个元素都重新数一遍」。但仔细想，`nums[2]=2` 和 `nums[3]=2` 的答案必然相同（示例 1 里都是 1），我们却各扫了一遍数组。**相同值的答案是一样的**，这是第一个关键观察。

**第二个观察**：答案只取决于「有多少个不同的值比它小」，跟这些值在原数组的哪个位置无关。也就是说，如果我们把所有值排好序，某个值 `v` 的答案就是「排序后 `v` 第一次出现的位置下标」。示例 1 排序后是 `[1,2,2,3,8]`，`8` 在下标 4，答案就是 4；`2` 第一次出现在下标 1，答案就是 1。对上了。

这两个观察合起来指向同一个方向：**先把「值 → 答案」这张表建好，再回头查表**。剩下的问题只是「建表用什么方式」。

## 3. 从暴力到最优

### 第一步：暴力，O(n²)

```python
res = []
for x in nums:
    cnt = 0
    for y in nums:
        if y < x:
            cnt += 1
    res.append(cnt)
```

以 `nums = [8,1,2,2,3]` 为例，处理 `8` 时要扫 5 次，处理两个 `2` 时各扫 5 次且结果完全一样。**浪费在重复值上**。

### 第二步：排序 + 哈希表，O(n log n)

把数组排序，然后从左往右扫一遍，记录「每个值第一次出现的下标」：

```
排序后: [1, 2, 2, 3, 8]
下标:    0  1  2  3  4
```

扫的时候维护一个字典 `first`：

| 扫到 | 值 | first 里有没有 | 动作 | first |
|---|---|---|---|---|
| 下标0 | 1 | 没有 | 记 `first[1]=0` | `{1:0}` |
| 下标1 | 2 | 没有 | 记 `first[2]=1` | `{1:0, 2:1}` |
| 下标2 | 2 | 有 | 跳过 | 不变 |
| 下标3 | 3 | 没有 | 记 `first[3]=3` | `{1:0, 2:1, 3:3}` |
| 下标4 | 8 | 没有 | 记 `first[8]=4` | `{1:0, 2:1, 3:3, 8:4}` |

最后对原数组逐个查表：`[first[8], first[1], first[2], first[2], first[3]] = [4,0,1,1,3]`。

瓶颈从「每个元素扫全数组」变成了「排序一次 + 查表 O(1)」，`O(n²)` 降到 `O(n log n)`。

### 第三步：计数排序，O(n + k)

题面给了一个非常强的提示：`0 <= nums[i] <= 100`。值域只有 101 个可能值，比 n 大不了多少。这时候排序是杀鸡用牛刀——**值域小的时候，直接开一个大小为 101 的桶数频次**，比比较排序更快。

以 `[8,1,2,2,3]` 为例，先数频次 `freq`（只列非零项）：

```
freq[1]=1, freq[2]=2, freq[3]=1, freq[8]=1
```

再做前缀和，`less[v]` 表示「严格小于 v 的个数」：

```
less[0]=0
less[1]=0            # 比 1 小的没有
less[2]=0+freq[1]=1  # 比 2 小的只有 1
less[3]=1+freq[2]=3  # 比 3 小的有 1,2,2
less[4]=3+freq[3]=4
...
less[8]=4            # 比 8 小的有 1,2,2,3
```

注意递推式是 `less[v] = less[v-1] + freq[v-1]`——**加的是 `v-1` 的频次，不是 `v` 的**，因为要「严格小于」。这一步是本题最容易写错的地方，示例 3 `[7,7,7,7]` 就是专门来抓这个错的：如果写成 `less[v] = less[v-1] + freq[v]`，`less[7]` 会变成 4，输出 `[4,4,4,4]`，全错。

最后查表：`[less[8], less[1], less[2], less[2], less[3]] = [4,0,1,1,3]`。

三步的复杂度对比：`O(n²)` → `O(n log n)` → `O(n + k)`，其中 `k = 101` 是值域大小。在本题约束下第三步最快，而且代码并不比第二步长。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证计数排序版本。

**定义**：`freq[v]` = 数组中值等于 `v` 的元素个数；`less[v]` = 数组中值严格小于 `v` 的元素个数。

**不变量**：在从左到右计算 `less` 的过程中，对任意 `v`，`less[v] = Σ_{u < v} freq[u]` 恒成立。

**归纳证明**：

- 基础：`v = 0` 时，没有比 0 更小的非负整数，`less[0] = 0 = 空和`，成立。
- 归纳：假设 `less[v-1] = Σ_{u < v-1} freq[u]`。按代码 `less[v] = less[v-1] + freq[v-1] = Σ_{u < v-1} freq[u] + freq[v-1] = Σ_{u < v} freq[u]`，成立。

**不漏**：对任意 `nums[i] = x`，答案定义为 `|{j : nums[j] < x}|`。按 `freq` 的定义，这个集合的大小恰好是 `Σ_{u < x} freq[u]`，而不变量保证它等于 `less[x]`。所以查表得到的数就是正确答案，一个都没漏。

**不重**：`freq` 是对每个值**恰好累加一次**（遍历原数组时每个下标只贡献一次），前缀和是对每个 `u` **恰好加一次**。所以 `less[x]` 里每个小于 `x` 的元素被计入且仅被计入一次，不会因为重复值被多算。

**为什么「严格小于」这个细节必须靠 `freq[v-1]` 而不是 `freq[v]`**：如果加 `freq[v]`，等于把「等于 v 的元素」也算进「小于 v」，直接违反答案定义。示例 3 全相等时，错误版本会把 4 个 7 全算进去，输出全 4。

## 5. 完整代码（Python）

```python
class Solution:
    def smallerNumbersThanCurrent(self, nums: list[int]) -> list[int]:
        # 值域上界，题面保证 nums[i] <= 100
        MAX_V = 100

        # 1) 数频次：freq[v] = 值恰好等于 v 的元素个数
        freq = [0] * (MAX_V + 1)
        for x in nums:
            freq[x] += 1

        # 2) 前缀和：less[v] = 值严格小于 v 的元素个数
        #    递推式 less[v] = less[v-1] + freq[v-1]
        #    注意加的是 v-1 的频次，不是 v 的，否则会把「等于 v」算进去
        less = [0] * (MAX_V + 1)
        for v in range(1, MAX_V + 1):
            less[v] = less[v - 1] + freq[v - 1]

        # 3) 查表：每个 nums[i] 的答案就是 less[nums[i]]
        return [less[x] for x in nums]
```

如果不想依赖 `MAX_V = 100` 这个硬编码（比如面试官追问「值域变了怎么办」），可以改成动态取最大值：

```python
class Solution:
    def smallerNumbersThanCurrent(self, nums: list[int]) -> list[int]:
        m = max(nums)                      # 动态值域上界
        freq = [0] * (m + 1)
        for x in nums:
            freq[x] += 1
        less = [0] * (m + 1)
        for v in range(1, m + 1):
            less[v] = less[v - 1] + freq[v - 1]
        return [less[x] for x in nums]
```

两版逻辑完全一致，区别只是值域上界是「题面给的常量」还是「运行时算出来的」。面试时写第二版更稳，因为它对值域变化免疫。

## 6. 复杂度

**时间 `O(n + k)`**，其中 `n = len(nums)`，`k = max(nums) + 1`（本题 `k = 101`）：

- 数频次：遍历 `nums` 一次，`O(n)`。
- 前缀和：遍历值域一次，`O(k)`。
- 查表：遍历 `nums` 一次，`O(n)`。
- 合计 `O(n + k)`。本题 `k` 是常数 101，所以实际是 `O(n)`。

**空间 `O(k)`**：`freq` 和 `less` 各占 `k` 个槽位，输出数组 `O(n)` 是题目要求返回的，不计入额外空间。没有 `O(n log n)` 里的 `log n`——因为计数排序不做比较，排序的 `log n` 因子被「值域直接寻址」消掉了。

对比一下：排序 + 哈希是 `O(n log n)` 时间、`O(n)` 空间；计数排序是 `O(n + k)` 时间、`O(k)` 空间。**当 `k` 远小于 `n log n` 时计数排序赢**，本题 `k = 101`、`n ≤ 500`，稳赢。但如果值域是 `10^9`，计数排序就退化成开一个十亿大小的数组，反而不可行——这就是为什么这题必须靠题面给的 `nums[i] <= 100` 才能用计数排序。

## 7. 边界与反例（至少 4 条）

1. **输入 `[7,7,7,7]` → 期望 `[0,0,0,0]`**。容易错在把前缀和写成 `less[v] = less[v-1] + freq[v]`，这样 `less[7]` 会算成 4，输出 `[4,4,4,4]`。这是「严格小于」和「小于等于」的分界线，示例 3 就是专门抓这个的。

2. **输入 `[0,0,1]` → 期望 `[0,0,2]`**。容易错在 `less[0]` 的初始化：`0` 是最小可能值，`less[0]` 必须是 0。如果循环从 `v = 0` 开始写 `less[v] = less[v-1] + ...`，会访问 `less[-1]`（Python 里是最后一个元素，静默出错，不报错），结果莫名其妙。循环必须从 `v = 1` 开始。

3. **输入 `[1,2]` → 期望 `[0,1]`**。最小规模，容易错在 `max(nums)` 动态版里 `freq` 长度取 `m+1` 后，前缀和循环 `range(1, m+1)` 的边界——`m=2` 时循环到 `v=2`，`less[2] = less[1] + freq[1] = 0 + 1 = 1`，正确。如果写成 `range(1, m)` 就漏了 `less[m]`，查表时 `less[2]` 是初始值 0，输出 `[0,0]`。

4. **输入 `[8,1,2,2,3]` → 期望 `[4,0,1,1,3]`**。重复值 `2` 出现两次，答案必须相同。容易错在「对每个元素单独数」的暴力写法里，如果内层循环写成 `for j in range(i)`（只数前面的），第二个 `2` 会得到不同答案——这提醒我们答案跟位置无关，只跟值有关。

5. **输入 `[100, 0]` → 期望 `[1, 0]`**。值域上界 `100` 必须被覆盖。如果 `freq` 开成 `[0] * 100`（少一位），`freq[100]` 会越界报 `IndexError`。开数组时长度是 `MAX_V + 1` 还是 `MAX_V` 是经典 off-by-one。

## 8. 面试追问与变体（3 条）

1. **追问：如果值域变成 `0 <= nums[i] <= 10^9`，你怎么办？**
   思路：计数排序失效（开不了十亿的数组），退回「排序 + 哈希表」的 `O(n log n)` 方案——排序后扫一遍记录每个值第一次出现的下标，再查表。核心思想「先建值→答案的表再查」不变，变的只是建表手段。

2. **追问：如果要求「小于等于」而不是「严格小于」呢？**
   思路：前缀和递推式改成 `less_eq[v] = less_eq[v-1] + freq[v]`，即把「等于 v」也算进去；或者等价地，答案变成 `less[v] + freq[v]`。改动只有一行，但要能说清楚为什么。

3. **追问：如果数组是动态的（支持插入/删除，每次都要查询）呢？**
   思路：静态前缀和不够用了，换成树状数组（Fenwick Tree）或线段树维护频次，单次插入/删除/查询都是 `O(log k)`。本题的「前缀和」就是树状数组在「只查询不修改」场景下的退化版本。

2. **力扣 1636. 按照频率将数组升序排序**：先数频次再按频次排序，和本题「先建频次表再查表」是同一个套路的两个方向（本题查的是前缀和，那题查的是频次本身）。

3. **力扣 274. H 指数**：也可以用计数排序把 `O(n log n)` 降到 `O(n)`——论文引用数有上界 `n`，开大小为 `n+1` 的桶数频次，再从高往低累加找答案，和本题「值域小就用桶」的判断逻辑完全一致。
