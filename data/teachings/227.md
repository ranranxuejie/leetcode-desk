## 1. 一句话本质

在只含 `+ - * /` 和空格、没有括号的表达式里，按「乘除优先于加减」的优先级求值——而实现优先级的核心手段是**把加减法推迟到乘除算完之后再做**。

## 2. 读完题的第一反应

**朴素解法**：从左到右扫，遇到运算符就立刻算。卡在哪？`"3+2*2"` 会先算 `3+2=5`，再 `5*2=10`，错。因为「先算」这个动作把 `+` 的右操作数 `2` 提前吞掉了，而 `2` 其实属于后面的 `*`。瓶颈在于：**扫描到 `+` 时，你无法知道它右边那一整块乘除链的值**。

**关键观察**：没有括号，意味着乘除链是「自成一体的连续段」。`3+2*2` 可以看成 `3 + (2*2)`，`3+5/2` 看成 `3 + (5/2)`。也就是说，**每个 `+`/`-` 号把表达式切成若干段，每段内部只有乘除**。于是问题变成：先算出每一段的值，再把这些段用加减拼起来。

这个观察直接指向下一步：我需要一个地方**暂存每一段的值**，等全部段算完再求和。栈就是那个地方。而 `+`/`-` 决定这一段是「加进总和」还是「减掉」，`*`/`/` 决定这一段内部怎么和上一段合并。

## 3. 从暴力到最优

**第一步：只处理加减（无优先级问题）**。维护一个 `ans`，遇 `+` 就加、遇 `-` 就减。这能过 `"1+2-3"`，但过不了乘除。

**第二步：引入栈，把「段」的边界定在加减号上**。规则是：

- 读到数字 `num`，看它**前面那个运算符** `op`（初始为 `+`）：
  - `op == '+'`：`num` 作为独立一段，`push(num)`
  - `op == '-'`：`push(-num)`
  - `op == '*'`：它和上一段合并，`push(pop() * num)`
  - `op == '/'`：`push(int(pop() / num))`
- 最后 `sum(stack)`。

走一遍 `s = "3+2*2"`：

| 读到 | num | op（读数字前） | 栈操作 | 栈内容 |
|---|---|---|---|---|
| `3` | 3 | `+`（初始） | push(3) | [3] |
| `+` | — | 更新 op=`+` | — | [3] |
| `2` | 2 | `+` | push(2) | [3,2] |
| `*` | — | 更新 op=`*` | — | [3,2] |
| `2` | 2 | `*` | pop 2, push(2*2=4) | [3,4] |

结束，`sum([3,4]) = 7`。✓

再走 `s = " 3+5 / 2 "`：

| 读到 | num | op | 栈操作 | 栈内容 |
|---|---|---|---|---|
| `3` | 3 | `+` | push(3) | [3] |
| `+` | — | op=`+` | — | [3] |
| `5` | 5 | `+` | push(5) | [3,5] |
| `/` | — | op=`/` | — | [3,5] |
| `2` | 2 | `/` | pop 5, push(5//2=2) | [3,2] |

`sum = 5`。✓ 注意 `5//2` 在 Python 里对正数是 2，但**负数会向下取整**（`-5//2 = -3`），而题目要求「仅保留整数部分」即向零截断，所以代码里必须用 `int(a / b)` 而不是 `a // b`。这是本题最容易翻车的点，见第 7 节。

**瓶颈怎么被消掉的**：暴力法的瓶颈是「遇到 `+` 就得立刻定值，但右边乘除链还没算」。栈把「定值」推迟了——`+`/`-` 只负责把一段**压进去**，真正的合并发生在遇到 `*`/`/` 时对栈顶做原地更新。一次扫描，O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。定义扫描到位置 `i` 时的不变量：

> 栈中所有元素之和，等于「表达式前缀 `s[0..i]` 中，所有已经闭合的加减段的值之和」；栈顶元素是「当前尚未闭合的那一段」的当前值。

分三种情况验证不变量在每一步后仍成立：

1. **读到数字**：只是把当前段的数值累积进 `num`，栈不变，不变量显然保持（当前段还没闭合）。
2. **读到 `+`/`-`**：此刻上一段闭合。按 `op` 把 `num`（或 `-num`）压栈，等价于「把闭合段的值记入总和」，不变量保持；同时新段开始，`num` 清零、`op` 更新。
3. **读到 `*`/`/`**：上一段并未真正闭合，而是与当前数字合并。`pop()` 取出栈顶（上一段的当前值），乘/除 `num` 后压回。因为栈顶代表的就是「这一段」，原地更新不改变「栈元素之和 = 已闭合段之和」这一性质，只是让当前段的值变大了。

扫描结束时，最后一段也闭合（循环外补一次 `push`），此时「栈元素之和 = 所有段之和 = 表达式值」。**不会漏**：每个数字恰好被压栈一次或被合并一次；**不会重**：`pop` 后立即 `push` 回合并结果，栈顶始终只代表一段，不存在同一段被计两次。

## 5. 完整代码（Python）

```python
class Solution:
    def calculate(self, s: str) -> int:
        stack = []
        num = 0          # 当前正在累积的数字
        op = '+'         # 当前数字前面那个运算符，初始视为 '+'
        n = len(s)

        for i in range(n):
            ch = s[i]

            if ch.isdigit():
                # 多位数：逐位累积，如 "12" -> 1 -> 12
                num = num * 10 + int(ch)

            # 遇到运算符，或已到字符串末尾，就要"结算"num
            if ch in '+-*/' or i == n - 1:
                if op == '+':
                    stack.append(num)
                elif op == '-':
                    stack.append(-num)
                elif op == '*':
                    # 与上一段合并：弹出栈顶，乘完压回
                    stack.append(stack.pop() * num)
                else:  # op == '/'
                    # 关键：向零截断，不能用 //（负数会向下取整）
                    stack.append(int(stack.pop() / num))
                op = ch      # 更新运算符，供下一个数字使用
                num = 0      # 数字清零，开始累积下一个

        return sum(stack)
```

几个细节值得单独说：

- `i == n - 1` 这个条件：字符串末尾可能不是运算符（如 `"3+2"` 以 `2` 结尾），必须强制结算最后一个数字，否则它永远进不了栈。
- `op = ch` 放在结算之后：因为 `ch` 是**下一个**数字的运算符，而结算用的是**上一个** `op`，顺序不能反。
- `int(stack.pop() / num)`：先转 float 再 `int()` 截断。`3*10^5` 长度下数值不会溢出 float 精度（中间结果在 32 位内），安全。

## 6. 复杂度

- **时间 O(n)**：`n = len(s)`。循环体每个字符访问一次；`isdigit`、`append`、`pop`、`sum` 都是 O(1) 摊还（`sum(stack)` 是 O(k)，k 为栈大小，k ≤ n，总计仍 O(n)）。没有嵌套循环，没有排序，所以**没有 log 项**。
- **空间 O(n)**：栈最多存 n/2 个元素（最坏情况 `"1+1+1+..."` 全是加减，每个数字都独立入栈），即 O(n)。除此之外只有常数个变量。

## 7. 边界与反例（至少 4 条）

1. **`s = "14-3/2"` → 期望 `13`**。`3/2 = 1`，`14-1 = 13`。易错点：若用 `//`，`3//2=1` 碰巧对；但换成 `s = "-3/2"` 类场景（本题无非负整数开头，但减法会产生负栈顶）如 `"1-3/2"`，`-3//2 = -2` 而正确是 `-1`。**必须 `int(a/b)`**。
2. **`s = " 3/2 "` → 期望 `1`**。易错点：忘记跳过空格，或把空格当数字处理。代码里 `isdigit()` 对空格返回 False，`ch in '+-*/'` 也 False，自然跳过，但**末尾空格**会让 `i == n-1` 落在空格上，此时 `num` 已结算过、`op` 被更新成空格——所以更稳妥的写法是在结算条件里排除空格，或先 `s = s.replace(' ','')`。上面代码依赖「末尾结算时 num 可能为 0，push(0) 不影响 sum」这一巧合，教学时应指出这是**隐患**，推荐显式 `strip` 或加 `ch != ' '` 判断。
3. **`s = "0-0"` → 期望 `0`**。易错点：`num=0` 时若用 `if num:` 判断是否结算，会漏掉数字 0。必须用「遇到运算符/末尾」判断，而不是「num 非零」。
4. **`s = "1000000000*2"` → 期望 `2000000000`**（在 32 位内）。易错点：多位数累积 `num = num*10 + digit` 若中途用字符串拼接再转 int 也行，但若用 `int(ch)` 单字符处理会拆成 `1,0,0,...`。必须逐位累积。
5. **`s = "1*2-3/4"` → 期望 `2`**。`1*2=2`，`3/4=0`，`2-0=2`。易错点：`-` 后面跟的是 `3/4` 这一段，`-` 只作用于段的结果，不能写成 `-(3)/4`。

## 8. 面试追问与变体（3 条）

1. **追问：如果加入括号 `(` `)` 怎么办？** 思路：遇到 `(` 递归调用 `calculate` 求子表达式，或用一个「栈的栈」保存外层上下文；本质是把「段」的边界从加减号扩展到括号。
2. **追问：如果运算符有 `^`（幂，右结合）？** 思路：优先级表 + 两个栈（操作数栈、运算符栈），按优先级弹栈；右结合意味着同级时 `^` 不弹栈。这就是通用的「双栈表达式求值」。
3. **追问：不允许用栈，空间 O(1) 怎么做？** 思路：维护 `ans`（已闭合段之和）和 `last`（当前段值），遇 `*`/`/` 时 `ans -= last; last = last * num; ans += last`，用两个变量模拟栈顶。
