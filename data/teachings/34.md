## 1. 一句话本质

在有序数组里，用两次二分分别求出「target 第一次出现的下标」和「target 最后一次出现的下标」，本质是**把「找某个值」改造成「找满足某个边界条件的第一个位置」**。

## 2. 读完题的第一反应

**朴素解法**：从头到尾扫一遍，遇到第一个 target 记下起点，继续扫到不等于 target 为止记下终点。时间 O(n)。

它卡在哪？题面明确要求 O(log n)，而数组长度上限是 10^5。O(n) 虽然能过（10^5 不大），但**不满足题目对复杂度的硬性要求**，面试官会直接判不合格。瓶颈在于：线性扫描没有利用「数组有序」这个信息——有序意味着我们可以通过一次比较排除掉一半的候选区间。

**关键观察**：题目要的不是「target 在不在」，而是「target 占据的那段连续区间的两个端点」。因为数组非递减，所有等于 target 的元素必然**连续排在一起**。于是问题变成两个独立的边界问题：

- 左边界 = 第一个 `nums[i] >= target` 的位置（如果这个位置的值不等于 target，说明 target 不存在）；
- 右边界 = 最后一个 `nums[i] <= target` 的位置，等价于「第一个 `nums[i] > target` 的位置再减 1」。

这两个都是「在有序数组里找第一个满足某条件的位置」，正是二分查找最擅长的形态。想到这一步，解法就出来了：写一个 `lower_bound` 模板，调用两次。

## 3. 从暴力到最优

**第一步：线性扫描。** 用示例 1 `nums = [5,7,7,8,8,10], target = 8` 走一遍：i=0 值 5 跳过，i=1 值 7 跳过，i=2 值 7 跳过，i=3 值 8 → 起点 3，i=4 值 8 继续，i=5 值 10 ≠ 8 → 终点 4。结果 `[3,4]`。正确，但最坏要访问 n 个元素。

**第二步：把「找起点」换成二分。** 我们不再逐个看，而是维护一个候选区间 `[lo, hi]`，每次看中点 `mid`：

- 若 `nums[mid] < target`，那么 mid 及其左边全部小于 target，起点一定在 mid 右侧 → `lo = mid + 1`；
- 若 `nums[mid] >= target`，mid 本身可能就是起点，答案在 mid 或它左边 → `hi = mid`。

注意这里 `hi = mid` 而不是 `mid - 1`，因为 mid 还没被排除。循环在 `lo == hi` 时结束，此时 lo 就是第一个 `>= target` 的位置。

用示例 1 找左边界，target = 8：

| 轮次 | lo | hi | mid | nums[mid] | 判断 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 2 | 7 | 7 < 8 | lo = 3 |
| 2 | 3 | 5 | 4 | 8 | 8 >= 8 | hi = 4 |
| 3 | 3 | 4 | 3 | 8 | 8 >= 8 | hi = 3 |

lo == hi == 3，左边界 = 3。✓

**第三步：右边界复用同一个函数。** 右边界 = 「第一个 `> target` 的位置」减 1。把上面的 `nums[mid] >= target` 改成 `nums[mid] > target` 即可，得到第一个严格大于 8 的位置。继续用示例 1：

| 轮次 | lo | hi | mid | nums[mid] | 判断 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 2 | 7 | 7 > 8 假 | lo = 3 |
| 2 | 3 | 5 | 4 | 8 | 8 > 8 假 | lo = 5 |
| 3 | 5 | 5 | — | — | 循环结束 | lo = 5 |

第一个 `> 8` 的位置是 5，所以右边界 = 5 - 1 = 4。结果 `[3,4]`。✓

**瓶颈怎么被消掉的**：每轮把候选区间长度从 `hi - lo + 1` 砍到约一半，n 个元素只需约 log₂n 轮，两次二分就是 2·log₂n，量级仍是 O(log n)。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**说清楚。对 `lower_bound(nums, target)`（找第一个 `>= target` 的位置），维护不变量：

> 循环开始时，答案（若存在）一定落在闭区间 `[lo, hi]` 内。

- **初始**：`lo = 0, hi = n`，答案若存在必在 `[0, n]` 内（n 表示「不存在，返回 n」的哨兵位置），成立。
- **保持**：取 `mid = (lo + hi) // 2`。
  - 若 `nums[mid] < target`：由于数组非递减，下标 ≤ mid 的元素都 < target，都不可能是答案，答案必在 `[mid+1, hi]`，令 `lo = mid + 1` 后不变量保持。
  - 若 `nums[mid] >= target`：mid 可能是答案，答案不可能在 mid 右侧（右侧元素 ≥ nums[mid] ≥ target，而我们要的是**第一个**），所以答案在 `[lo, mid]`，令 `hi = mid` 后不变量保持。
- **终止**：`lo == hi` 时区间只剩一个位置，由不变量它必是答案。

**为什么不会漏**：每次收缩都只排除「确定不是答案」的那一半，被排除的元素都有严格的大小关系作依据。

**为什么不会重**：左边界取的是「第一个 ≥ target」，右边界取的是「第一个 > target 减 1」，两个定义互不重叠地刻画了区间的两端；中间的元素不需要单独枚举。

**存在性判断**：左边界 `l` 算出来后，若 `l == n` 或 `nums[l] != target`，说明 target 不存在，直接返回 `[-1, -1]`。这一步不能省——否则示例 2（target = 6）会错误地返回一个越界或错误的下标。

## 5. 完整代码（Python）

```python
class Solution:
    def searchRange(self, nums, target):
        n = len(nums)

        def lower_bound(t):
            # 返回第一个满足 nums[i] >= t 的下标；若都不满足返回 n
            lo, hi = 0, n          # hi 取 n 作为哨兵，处理「全部小于 t」的情况
            while lo < hi:
                mid = (lo + hi) // 2
                if nums[mid] < t:
                    lo = mid + 1   # mid 及左侧都 < t，全部排除
                else:
                    hi = mid       # mid 可能是答案，保留在区间内
            return lo

        left = lower_bound(target)          # 第一个 >= target 的位置
        # 左边界越界，或该位置的值不是 target，说明 target 不存在
        if left == n or nums[left] != target:
            return [-1, -1]

        right = lower_bound(target + 1) - 1  # 第一个 > target 的位置减 1
        return [left, right]
```

关键点说明：

- `hi` 初始化为 `n` 而不是 `n - 1`，是为了让「target 比所有元素都大」时返回 `n`，配合 `left == n` 的判断统一处理不存在的情况。
- `target + 1` 依赖提示中 `target` 是整数（范围 -10^9 到 10^9），加 1 不会溢出，且能正确表达「严格大于 target」。这是本题能用一次函数复用两次的核心技巧。
- 循环条件 `lo < hi` 配合 `hi = mid`，保证不会死循环：因为 `mid < hi` 恒成立（当 `lo < hi` 时 `(lo+hi)//2 < hi`），所以 `hi` 每轮严格减小。

## 6. 复杂度

**时间 O(log n)**：`lower_bound` 每轮把区间长度 `hi - lo` 至少减半，从 n 收缩到 0 需要 ⌈log₂(n+1)⌉ 轮，每轮 O(1) 次比较。调用两次，总轮数 2·log₂n，常数因子被大 O 吸收，仍是 O(log n)。n 来自数组长度，log n 来自二分的折半次数。

**空间 O(1)**：只用了 `lo, hi, mid, left, right` 几个整型变量，没有递归、没有额外数组。注意 `lower_bound` 是闭包，但它捕获的 `nums` 和 `n` 是引用，不产生新空间。

## 7. 边界与反例（至少 4 条）

1. **空数组**：`nums = [], target = 0` → 期望 `[-1, -1]`。容易错在 `lower_bound` 里 `hi = n = 0`，循环不进入直接返回 `lo = 0`，此时 `left == n` 成立，返回 `[-1,-1]`。若漏掉 `left == n` 的判断，会去访问 `nums[0]` 抛 IndexError。

2. **target 比所有元素都小**：`nums = [2,3,4], target = 1` → 期望 `[-1, -1]`。`lower_bound(1)` 返回 0，`nums[0] = 2 != 1`，正确返回 `[-1,-1]`。容易错在只判断 `left == n` 而忘了判断值是否相等。

3. **target 比所有元素都大**：`nums = [2,3,4], target = 5` → 期望 `[-1, -1]`。`lower_bound(5)` 返回 3（= n），触发 `left == n` 分支。容易错在把 `hi` 初始化为 `n-1`，导致返回 `n-1` 并误判 `nums[n-1]`。

4. **全部元素都等于 target**：`nums = [7,7,7], target = 7` → 期望 `[0,2]`。左边界 `lower_bound(7)` 返回 0；右边界 `lower_bound(8)` 返回 3，减 1 得 2。容易错在右边界写成 `lower_bound(target)` 而不是 `target + 1`，会得到 `[0,-1]` 这种非法区间。

5. **只有一个元素且等于 target**：`nums = [5], target = 5` → 期望 `[0,0]`。左边界 0，右边界 `lower_bound(6) - 1 = 1 - 1 = 0`。容易错在循环条件写成 `lo <= hi` 配合 `hi = mid`，导致死循环。

## 8. 面试追问与变体（3 条）

1. **追问：如果数组是循环有序的（如 `[4,5,6,7,0,1,2]`），还能 O(log n) 找 target 的区间吗？**
   思路：先用二分找到旋转点（最小值位置），把数组切成两段各自有序，再在两段上分别做本题的两次二分；或者直接在旋转数组上做带「哪半边有序」判断的二分。

2. **追问：不用 `target + 1`，怎么求右边界？**
   思路：单独写一个 `upper_bound`，把判断条件改成 `nums[mid] <= target` 时 `lo = mid + 1`，否则 `hi = mid`，返回的就是第一个 `> target` 的位置。这样不依赖 target 是整数、也不依赖加 1 不溢出。

3. **追问：如果要求返回 target 出现的次数呢？**
   思路：直接复用本题结果，`right - left + 1`；若 target 不存在则为 0。本质是同一个边界问题的副产品。
