## 1. 一句话本质

在一条价格序列上，挑出**至多两个互不重叠的「低买高卖」区间**，使两段价差之和最大。

## 2. 读完题的第一反应

**朴素解法**：枚举第一笔交易的买入日 `i`、卖出日 `j`，再枚举第二笔的买入日 `k`、卖出日 `l`，要求 `i < j <= k < l`（或只做一笔），取最大利润。这是四重循环，O(n⁴)，n 上千就废了。

**关键观察**：题目说「最多两笔」，而两笔交易在时间轴上是**前后拼接**的——第一笔在某个位置结束，第二笔从它之后开始。这意味着存在一个「分界点」`p`：第一笔完全落在 `[0, p]` 内，第二笔完全落在 `[p, n-1]` 内。于是问题被拆成两个独立的子问题：

> 对每个分界点 `p`，求「前 p 天做一笔的最大利润」+「后 n-p 天做一笔的最大利润」，取最大。

而「一段区间内做一笔交易的最大利润」是 121 题，有 O(n) 的经典解法（维护历史最低价）。所以整体 O(n) 就能解决。这个「枚举分界点 + 左右各算一次」的思路，是本题最直观的入口。

## 3. 从暴力到最优

**第一步：把四重循环降到「枚举分界点」**

原暴力是 O(n⁴)。观察到两笔交易不重叠，一定存在分界点 `p` 把两笔分开。固定 `p` 后，左右两段互不影响，各自独立求「一笔交易最大利润」。枚举 `p` 是 O(n)，每次左右各 O(n)，总 O(n²)。已经能过大部分数据，但还不是最优。

**第二步：预处理左右数组，降到 O(n)**

`left[p]` = 在 `prices[0..p]` 内做一笔交易的最大利润。
`right[p]` = 在 `prices[p..n-1]` 内做一笔交易的最大利润。

这两个数组都能用「维护历史最低/最高价」一次扫描填出来：

- 从左往右扫，维护 `min_price`，`left[i] = max(left[i-1], prices[i] - min_price)`。
- 从右往左扫，维护 `max_price`，`right[i] = max(right[i+1], max_price - prices[i])`。

然后答案 = `max over p of (left[p] + right[p+1])`，再和「只做一笔」的 `left[n-1]` 取 max（其实 `left[n-1]` 已覆盖，因为可以令第二笔利润为 0）。

**小例子走一遍**：`prices = [3,3,5,0,0,3,1,4]`

从左扫（`min_price` 初值 +∞）：

| i | price | min_price | 当日利润 | left[i] |
|---|-------|-----------|----------|---------|
| 0 | 3 | 3 | - | 0 |
| 1 | 3 | 3 | 0 | 0 |
| 2 | 5 | 3 | 2 | 2 |
| 3 | 0 | 0 | 0 | 2 |
| 4 | 0 | 0 | 0 | 2 |
| 5 | 3 | 0 | 3 | 3 |
| 6 | 1 | 0 | 1 | 3 |
| 7 | 4 | 0 | 4 | 4 |

从右扫（`max_price` 初值 -∞）：

| i | price | max_price | 当日利润 | right[i] |
|---|-------|-----------|----------|----------|
| 7 | 4 | 4 | - | 0 |
| 6 | 1 | 4 | 3 | 3 |
| 5 | 3 | 4 | 1 | 3 |
| 4 | 0 | 4 | 4 | 4 |
| 3 | 0 | 4 | 4 | 4 |
| 2 | 5 | 5 | 0 | 4 |
| 1 | 3 | 5 | 2 | 4 |
| 0 | 3 | 5 | 2 | 4 |

枚举分界点 `p`（第一笔在 `[0,p]`，第二笔在 `[p+1, n-1]`）：

- p=0: left[0]+right[1] = 0+4 = 4
- p=1: 0+4 = 4
- p=2: 2+4 = 6
- p=3: 2+4 = 6
- p=4: 2+3 = 5
- p=5: 3+3 = 6
- p=6: 3+0 = 3

最大值 6，与示例一致。对应 p=2 时：第一笔在 `[0,2]` 内赚 2（3 买 5 卖），第二笔在 `[3,7]` 内赚 4（0 买 4 卖）——但示例给的是 0 买 3 卖 + 1 买 4 卖，也是 6。**注意：最大利润值唯一，但具体交易方案可能不唯一**，这是本题容易让人困惑的点，后面第 4 节会讲清楚为什么「值」一定对。

**第三步：还能不能更省空间？**

可以。用「状态机 DP」把左右两个数组压成 4 个变量，空间 O(1)。但那是另一种建模方式，第 5 节给的是左右数组版本（更好讲、更好 debug），状态机版本放在第 8 节追问里。

## 4. 正确性：为什么不会漏、不会重

**不变量 1（left 数组）**：`left[i]` 等于「只允许在 `prices[0..i]` 内交易一次」时的最大利润。

归纳证明：`i=0` 时利润为 0，成立。假设 `left[i-1]` 正确，考虑 `prices[0..i]`。任何一笔交易要么卖出日 `< i`（利润已被 `left[i-1]` 覆盖），要么卖出日 `= i`（利润为 `prices[i] - min(prices[0..i])`）。两者取 max 即 `left[i]`。所以递推式 `left[i] = max(left[i-1], prices[i] - min_price)` 不漏任何情况。

**不变量 2（right 数组）**：对称地，`right[i]` 是「只允许在 `prices[i..n-1]` 内交易一次」的最大利润，归纳同理。

**关键引理（分界点覆盖）**：设最优方案为两笔交易 `T1 = (b1, s1)`、`T2 = (b2, s2)`，满足 `b1 < s1 <= b2 < s2`（允许某一笔为空）。取 `p = s1 - 1`（即第一笔卖出日的前一天），则 `T1` 完全落在 `[0, p]`，`T2` 完全落在 `[p+1, n-1]`。于是 `left[p] >= T1 利润`，`right[p+1] >= T2 利润`，所以 `left[p] + right[p+1] >= 最优利润`。另一方面，`left[p] + right[p+1]` 本身对应一个合法方案（两段不重叠），所以 `<= 最优利润`。两边夹逼，等号成立。

**为什么不会重**：`left[p]` 和 `right[p+1]` 的区间 `[0,p]` 与 `[p+1,n-1]` 严格不相交，两笔交易不可能共用同一天，满足「必须先卖后买」的约束。**为什么不会漏**：上面的引理说明任意合法两笔方案都能被某个 `p` 覆盖。

**一个容易踩的坑**：`p` 从 0 枚举到 n-2，`left[0]` 可能为 0（第一天没法交易），这对应「第一笔为空、只做第二笔」的情况，是合法的（题目说「最多两笔」，允许一笔都不做或只做一笔）。所以不需要额外处理「只做一笔」，`p=0` 已经覆盖。

## 5. 完整代码（Python）

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        n = len(prices)
        if n < 2:
            return 0

        # left[i]: 在 prices[0..i] 内做至多一笔交易的最大利润
        left = [0] * n
        min_price = prices[0]
        for i in range(1, n):
            min_price = min(min_price, prices[i])          # 维护历史最低买价
            left[i] = max(left[i - 1], prices[i] - min_price)  # 不卖 or 今天卖

        # right[i]: 在 prices[i..n-1] 内做至多一笔交易的最大利润
        right = [0] * n
        max_price = prices[-1]
        for i in range(n - 2, -1, -1):
            max_price = max(max_price, prices[i])          # 维护历史最高卖价
            right[i] = max(right[i + 1], max_price - prices[i])  # 不买 or 今天买

        # 枚举分界点：第一笔在 [0, p]，第二笔在 [p+1, n-1]
        ans = 0
        for p in range(n - 1):
            ans = max(ans, left[p] + right[p + 1])
        # 只做一笔的情况已被 p=0（left[0]=0）覆盖，无需单独处理
        return ans
```

## 6. 复杂度

- **时间 O(n)**：三次独立线性扫描。第一次从左到右填 `left`（n-1 次迭代），第二次从右到左填 `right`（n-1 次），第三次枚举分界点（n-1 次）。每次迭代 O(1) 操作，总 3(n-1) = O(n)。没有排序、没有二分，所以**没有 log n 项**。
- **空间 O(n)**：`left` 和 `right` 各占 n 个整数，共 2n。若改用状态机 DP（见第 8 节），可压到 O(1)，但可读性下降。

## 7. 边界与反例（至少 4 条）

1. **`prices = [1]`** → 期望 `0`。容易错：代码里 `range(1, 1)` 不执行，`left=[0]`；`range(-1, -1, -1)` 也不执行，`right=[0]`；`range(0)` 不执行，`ans=0`。若忘记 `n<2` 提前返回，`min_price = prices[0]` 仍安全，但 `prices[-1]` 在 n=0 时会崩——所以 `n<2` 的守卫要保留。

2. **`prices = [7,6,4,3,1]`（单调递减）** → 期望 `0`。容易错：`left` 全 0，`right` 全 0，`ans=0`，正确。但若把 `left[i] = max(left[i-1], prices[i]-min_price)` 写成 `left[i] = prices[i]-min_price`（漏掉「不交易」选项），会得到负数，答案错。

3. **`prices = [1,2,3,4,5]`（单调递增）** → 期望 `4`。容易错：直觉上「拆成两笔」可能以为能赚更多（比如 1 买 2 卖 + 3 买 4 卖 = 2），但实际一笔 1 买 5 卖赚 4 更大。代码里 `left[4]=4`，`right` 全 0，`p=0` 时 `left[0]+right[1]=0+4=4`，正确。**这个例子专门打脸「两笔一定比一笔好」的错觉**。

4. **`prices = [3,3,5,0,0,3,1,4]`** → 期望 `6`。容易错：如果分界点只枚举到 `n-2` 且忘记 `p=0` 的情况，或者把 `right[p]` 和 `left[p]` 的区间写成重叠（都用 `p`），会重复计算同一天，得到偏大或偏小的错误值。

5. **`prices = [2,1,2,0,1]`** → 期望 `2`。容易错：最优是 1 买 2 卖（赚 1）+ 0 买 1 卖（赚 1）= 2，分界点 `p=1`（第一笔在 `[0,1]` 内 1 买 2 卖？不对，`[0,1]` 只有 2,1，利润 0）。实际最优分界点是 `p=2`：`left[2]=1`（1 买 2 卖），`right[3]=1`（0 买 1 卖），合计 2。若 `right` 数组从右扫时把 `max_price` 初值设成 `prices[0]` 而非 `prices[-1]`，会算错。

## 8. 面试追问与变体（3 条）

1. **追问：如果允许 k 笔交易呢？** 思路：状态机 DP，`buy[j]` / `sell[j]` 表示第 j 笔的持有/卖出状态，时间 O(nk)，空间 O(k)。k=2 时就是本题的 O(1) 空间版本。

2. **追问：如果允许「同一天既卖又买」（即两笔交易可以首尾相接在同一天）呢？** 思路：本题约束是 `s1 <= b2`，允许 `s1 == b2`（同一天卖完再买），代码里 `left[p] + right[p+1]` 已经满足；若题目改成 `s1 < b2` 严格不等，则分界点要改成 `left[p] + right[p]` 且 `p` 处不能同时买卖，需额外处理。

3. **追问：如果要求「恰好两笔」而不是「最多两笔」呢？** 思路：把 `left[0]` 初始化为 `-inf`（第一天无法完成一笔完整交易），并强制 `p >= 1`，最后答案不取「只做一笔」的退化情况。注意此时全递减数组的答案会变成负数或需要特判。

## 9. 举一反三（2-3 道同类题）

1. **121. 买卖股票的最佳时机**：本题的「单笔」子问题，`left` 数组的构造逻辑就是它的全部内容。

2. **122. 买卖股票的最佳时机 II**：不限交易次数，贪心「所有上涨段都吃」即可，和本题的「分界点枚举」是同一族问题的不同约束。

3. **188. 买卖股票的最佳时机 IV**：把「2 笔」推广到「k 笔」，状态机 DP 的直接扩展，本题是它的 k=2 特例。
