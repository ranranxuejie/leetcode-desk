## 1. 一句话本质

对每个位置 i，在「nums 后面再接一份 nums」这个长度 2n 的序列里，找 i 之后第一个严格大于 nums[i] 的值。

关键就在「再接一份」这四个字：循环搜索这件事，被翻译成了「在更长的线性数组上做一次单向扫描」。剩下的全是单调栈的活。

## 2. 读完题的第一反应

**朴素解法**：对每个 i，从 i+1 开始往后走，最多走 n-1 步（绕一圈），遇到第一个比 nums[i] 大的就停。最坏情况是数组单调不增，比如 `[5,4,3,2,1]`，每个位置都要走满一圈才发现没有更大的，总代价 O(n²)。n = 10⁴ 时是 10⁸ 量级，Python 里基本必超时。

**卡在哪**：对每个元素都重新「往后找一遍」，而相邻两个元素要找的东西高度重叠。比如 `[1,2,1]`，第一个 1 往后扫到 2 就停了；第二个 1 又要从头扫一遍。这些重复扫描没有被复用。

**关键观察**：如果我从左往右扫，手里维护一个「还没找到答案的元素下标」的集合，那么当我扫到某个值 x 时，这个集合里所有比 x 小的元素，答案就是 x——它们可以一次性全部结算掉。而且这个集合有个天然性质：**它里面的值是单调不增的**（后面进来的元素如果比前面的大，前面那个早就被结算走了）。于是它就是一个栈，栈底到栈顶单调不增。

这一步是整个解法的支点：**「谁还没被结算」这个信息，可以用一个单调栈压缩成 O(n) 的状态**，而不是每个位置各存一份。

至于循环，不需要真的去处理「绕回去」的边界判断，直接把数组遍历两遍（下标取模）就行——第二遍相当于把第一遍的元素再「喂」一次，让第一遍没结算完的元素有机会被后面的值结算。

## 3. 从暴力到最优

**第一步：先解决非循环版本。** 对 `[1,2,1]`（不循环），从左往右扫，栈存下标：

- i=0，val=1，栈空，压入 0。栈：[0]
- i=1，val=2，栈顶 nums[0]=1 < 2，结算 ans[0]=2，弹出 0；栈空，压入 1。栈：[1]
- i=2，val=1，栈顶 nums[1]=2 > 1，不结算，压入 2。栈：[1,2]
- 扫完，栈里剩 [1,2]，答案都是 -1。

得到 `[2,-1,-1]`。非循环版本到这里就对了，复杂度 O(n)——每个下标进栈一次、出栈一次。

**第二步：循环怎么补。** 正确答案是 `[2,-1,2]`，差在最后一个 1 上：它需要绕回去看到开头的 2。做法是把遍历长度从 n 拉长到 2n，下标用 `i % n` 取值：

- i=3（对应下标 0），val=1，栈顶 nums[2]=1，不满足严格大于，压入 3。栈：[1,2,3]
- i=4（对应下标 1），val=2，栈顶 nums[3]=1 < 2，结算 ans[3 % 3] = ans[0] = 2，弹出 3；栈顶 nums[2]=1 < 2，结算 ans[2]=2，弹出 2；栈顶 nums[1]=2，不满足，停。压入 4。栈：[1,4]
- i=5（对应下标 2），val=1，栈顶 nums[4 % 3]=nums[1]=2 > 1，压入 5。栈：[1,4,5]

扫完，栈里剩 [1,4,5]，对应下标 1、1、2，ans[1] 和 ans[2] 保持 -1 和 2。最终 `[2,-1,2]`，对上了。

注意第二遍里 ans[0] 被写了两次（i=3 时没写，i=4 时写了 2），但写的是同一个值——因为下标 0 在第一遍就已经出栈了，第二遍它只是作为「值」被读，不会再作为「待结算的下标」进栈两次。这一点在正确性一节会讲清楚。

**瓶颈怎么被消掉的**：暴力是「每个 i 各自往后扫」，代价 O(n²)；单调栈把「往后扫」变成「扫一遍，边扫边结算」，每个下标最多进栈一次、出栈一次，总代价 O(n)。循环的部分只是把扫描长度乘 2，不改变量级。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在扫描到位置 i（0 ≤ i < 2n）之后，栈中存放的是下标 j₁ < j₂ < … < jₖ，满足：

1. 这些下标对应的值 `nums[j % n]` 从栈底到栈顶**单调不增**；
2. 对栈中任意 j，在区间 (j, i] 内**不存在**值严格大于 `nums[j % n]` 的元素——也就是说，j 的答案还没出现；
3. 所有不在栈中、且下标 < n 的位置，其答案已经被正确写入。

**为什么不会漏**：假设某个下标 p（p < n）的正确答案是位置 q（q 在 p 之后、循环意义下第一个更大）。那么 q 一定落在 (p, p+n) 内。扫描到 q 时，p 要么还在栈里（因为 (p, q) 内没有比 nums[p] 大的值，由不变量 2，p 不会被提前弹出），要么已经出栈——但出栈的唯一途径就是被某个更大的值结算，那答案早就写对了。所以 p 一定会在 q 处被结算，不会漏。

**为什么不会重**：每个下标出栈时结算一次，出栈后不再进栈（第二遍扫描时，下标 i ≥ n 对应的是 `i % n`，而 `i % n` 在第一遍已经处理过；第二遍压入的是 i 本身，不是 `i % n`，所以不会把同一个「待结算下标」压两次）。ans 数组每个位置最多被写一次有效值，其余保持初始的 -1。

**为什么第二遍扫描不会污染答案**：第二遍压入的是下标 i ≥ n，它们只作为「栈里的值」参与比较，结算时写的是 `ans[i % n]`。而 `i % n` 这个位置在第一遍就已经出过栈了，第二遍再写它，写的是同一个正确答案（因为循环意义下第一个更大值唯一）。所以重复写不产生错误。

## 5. 完整代码（Python）

```python
class Solution:
    def nextGreaterElements(self, nums: list[int]) -> list[int]:
        n = len(nums)
        ans = [-1] * n          # 默认 -1，表示循环一圈也找不到更大值
        stack = []              # 存下标，栈底到栈顶对应的值单调不增

        # 遍历 2n 个位置：第二遍是「再接一份 nums」，用来处理循环
        for i in range(2 * n):
            cur = nums[i % n]   # 取模拿到真实值
            # 当前值能结算栈顶所有比它小的元素
            while stack and nums[stack[-1] % n] < cur:
                idx = stack.pop()
                ans[idx % n] = cur   # 写回原数组下标
            stack.append(i)     # 当前下标入栈，等待后面更大的值

        return ans
```

几个容易写错的地方，注释里已经点明：比较时用 `nums[stack[-1] % n]` 而不是 `nums[stack[-1]]`（栈里可能存着 ≥ n 的下标）；写答案时用 `ans[idx % n]`；判断条件是严格小于 `<`，不是 `<=`（题目要「更大」，相等不算）。

## 6. 复杂度

**时间 O(n)**：外层循环跑 2n 次，贡献 2n。内层 while 每次弹出一个下标，而整个过程中每个下标最多入栈一次，所以总入栈次数 ≤ 2n，总弹出次数 ≤ 2n。while 的总代价是 O(n)，不是 O(n²)——这是单调栈类题目的标准摊还分析。合起来 O(n)。

**空间 O(n)**：ans 数组 n 个元素；stack 最多存 2n 个下标（最坏情况数组单调不增，一个都不弹），所以是 O(n)。没有 log 项，因为没有任何排序或二分。

## 7. 边界与反例（至少 4 条）

1. **输入 `[1]`** → 期望 `[-1]`。容易错在：只遍历 n 次时，单个元素永远没有「后面」，直接返回 -1 是对的；但如果代码里写了 `stack[-1]` 却没判空，或者循环写成 `range(2*n - 1)` 漏掉最后一个位置，就会出错。

2. **输入 `[5,4,3,2,1]`** → 期望 `[-1,-1,-1,-1,-1]`。容易错在：这是单调不增的极端情况，栈会一直增长到 2n 个元素，一个都不弹。如果 while 条件写成 `<=` 而不是 `<`，或者误以为「第二遍一定能结算」，就会给出错误答案。同时这也是空间最坏情况，验证 stack 不会越界。

3. **输入 `[1,1,1]`** → 期望 `[-1,-1,-1]`。容易错在：把「更大」理解成「大于等于」。相等不结算，三个 1 互相都等不到严格更大的值，全部 -1。

4. **输入 `[2,1,2]`** → 期望 `[2? 不对，是 [-1,2,-1]`。具体算：下标 0 的值 2，循环一圈后遇到的最大是 2（下标 2），不严格大于，所以 -1；下标 1 的值 1，下一个是 2，答案 2；下标 2 的值 2，绕回去遇到下标 0 的 2，不严格大于，-1。容易错在：以为「循环」意味着每个元素都能找到答案，或者把下标 2 的答案错写成 2（因为它后面「看起来」有 2，但相等不算）。

5. **输入 `[1,2,3,4,3]`**（官方示例 2）→ 期望 `[2,3,4,-1,4]`。容易错在：最后一个 3 需要绕回开头找 4，如果只扫一遍 n 次，它会留在栈里得到 -1，而正确答案是 4。这条专门检验「2n 次遍历」是否写对。

## 8. 面试追问与变体（3 条）

**追问 1：如果要求「下一个更大或等于」的元素呢？**
把 while 条件里的 `<` 改成 `<=` 即可，其余不变。思路一句话：单调栈的结算条件直接对应题目对「更大」的严格性定义。

**追问 2：如果数组不是循环的，但要求返回「下一个更大元素的距离」而不是值呢？**
栈里存下标，结算时写 `ans[idx] = i - idx` 而不是 `ans[idx] = cur`。思路一句话：下标差就是距离，栈存下标天然支持这个信息。

**追问 3：如果要求「上一个更大元素」呢？**
把扫描方向反过来，从右往左扫，栈的单调性方向相应翻转。思路一句话：单调栈的方向和扫描方向要匹配，「往后找」对应从左往右，「往前找」对应从右往左。
