## 1. 一句话本质

判断一张有向图里**有没有环**——把课程当点、先修关系当有向边，能修完全部课 ⟺ 这张图是 DAG（有向无环图）。

## 2. 读完题的第一反应

朴素想法：从某门课出发，反复问「它的先修课修完了吗」，修完就标记，再回头修它。这本质是**模拟选课过程**，但卡在一个地方：如果存在环，你会永远在「等对方先修完」里打转，程序无法判断「等不到」和「还没轮到」的区别。

关键观察来自题面那句 `prerequisites[i] = [a, b]` 表示「学 a 必须先学 b」。这句话把问题翻译成了**依赖关系**，而依赖关系最自然的模型就是有向边 `b → a`。一旦建好图，「能否修完」就等价于「能不能把点排成一个线性顺序，使每条边都从前指向后」——这正是**拓扑排序**的定义。于是问题变成：这张图能不能拓扑排序？而拓扑排序做不出来的唯一原因就是有环。

这一步转换的价值在于：它把「模拟一个动态过程」变成了「对静态结构做一次遍历」，环的检测从「靠超时猜」变成「靠遍历状态精确判定」。

## 3. 从暴力到最优

**暴力版**：对每门课做一次 DFS，看从它出发能不能回到自己。复杂度 O(V·(V+E))，V=2000、E=5000 时约 1.4×10⁷，其实能过，但重复遍历大量子图，是明显的浪费。

**瓶颈在哪**：同一门课会被不同起点的 DFS 反复访问。比如 0→1→2，从 0 出发走一遍，从 1 出发又走一遍 1→2。

**消掉瓶颈的观察**：DFS 过程中，一个点只有三种状态——**未访问 / 正在当前递归栈上 / 已完成**。如果 DFS 走到一个「正在栈上」的点，说明绕回来了，有环；走到「已完成」的点，说明它的子树早就验证过无环，直接跳过即可。这样每个点最多被完整处理一次，总复杂度降到 O(V+E)。

**小例子走一遍**：`numCourses=3, prerequisites=[[1,0],[2,1],[0,2]]`，即边 0→1、1→2、2→0。

建图 `graph = {0:[1], 1:[2], 2:[0]}`，状态数组 `state = [0,0,0]`（0 未访问，1 在栈上，2 已完成）。

- `dfs(0)`：state[0]=1，看邻居 1 → `dfs(1)`
  - state[1]=1，看邻居 2 → `dfs(2)`
    - state[2]=1，看邻居 0 → state[0]==1，**在栈上，返回 False**
  - 一路 False 冒泡回来
- 结果 False，正确（0、1、2 互相等待，成环）。

对比无环例子 `[[1,0],[2,1]]`（0→1→2）：`dfs(0)` 走到 2 时邻居为空，state[2]=2 返回 True；回到 1 置 2；回到 0 置 2。全程没有碰到 state==1 的点，返回 True。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。DFS 过程中维护不变量：

> 对任意点 u，若 `state[u]==2`（已完成），则 u 及其所有可达点构成的子图无环；若 `state[u]==1`，则 u 在当前递归路径上。

**不会漏（有环必被抓）**：设图中有环 C。取 C 上第一个被 DFS 访问的点 v（DFS 从某点出发，必然先碰到环上某点）。从 v 沿环走，环上每个点都会被递归访问，最终回到 v。此时 v 的 state 仍是 1（还没返回、没置 2），于是触发 `state==1` 判定，返回 False。所以任何环都逃不掉。

**不会重（无环不会误报）**：若图无环，DFS 走到 state==1 的点意味着存在一条从当前点到该点的路径，加上递归栈上的路径，构成环，与无环矛盾。所以无环时永远不会触发 `state==1` 分支，只会正常置 2。

**为什么可以跳过 state==2**：由不变量，state==2 的点其子图已验证无环，从它出发不可能再产生环，跳过不损失信息——这就是把 O(V·(V+E)) 压到 O(V+E) 的依据。

## 5. 完整代码（Python）

```python
class Solution:
    def canFinish(self, numCourses: int, prerequisites: list[list[int]]) -> bool:
        # 建图：边 b -> a，表示学 a 前要先学 b
        graph = [[] for _ in range(numCourses)]
        for a, b in prerequisites:
            graph[b].append(a)

        # 0=未访问, 1=在当前递归栈上, 2=已完成
        state = [0] * numCourses

        def dfs(u: int) -> bool:
            if state[u] == 1:      # 回到栈上的点 => 有环
                return False
            if state[u] == 2:      # 已验证无环，直接复用
                return True
            state[u] = 1           # 标记入栈
            for v in graph[u]:
                if not dfs(v):
                    return False   # 子树有环，整条路径失败
            state[u] = 2           # 子树全部验证完，标记完成
            return True

        # 图可能不连通，每个点都要作为起点试一次
        for i in range(numCourses):
            if state[i] == 0 and not dfs(i):
                return False
        return True
```

关键点：外层循环不能省。图可能分成多个连通块，只从 0 出发会漏掉别的块里的环。

## 6. 复杂度

- **时间 O(V+E)**：V=numCourses，E=prerequisites.length。每个点因 state 机制只被完整 DFS 一次（state==2 直接返回），每条边在它起点被展开时看一次，故 V 个点 + E 条边。建图也是 O(E)。
- **空间 O(V+E)**：`graph` 存 E 条边占 O(E)，`state` 数组 O(V)，递归栈最深 O(V)（链状图）。没有 log 项，因为这里没有排序或二分。

## 7. 边界与反例（至少 4 条）

1. `numCourses=1, prerequisites=[]` → `True`。容易错：忘记处理「没有先修课」的空图，或外层循环写成只从 0 开始却漏了孤立点。
2. `numCourses=2, prerequisites=[[1,0],[0,1]]` → `False`。容易错：把 `[a,b]` 的边方向建反（建成 a→b），两个方向都成环时结果碰巧对，但单边例子会错。
3. `numCourses=3, prerequisites=[[1,0],[2,1]]` → `True`。容易错：链状图递归深度到 3，若用 BFS 版忘记统计入队数量，会误判。
4. `numCourses=3, prerequisites=[]` → `True`。容易错：图完全不连通，只从 0 出发会漏掉 1、2，但本题返回 True 不受影响——真正暴露问题的是「某个连通块有环、0 所在块无环」，如 `numCourses=4, prerequisites=[[1,0],[3,2],[2,3]]` → `False`，只从 0 出发会错判 True。
5. `numCourses=2, prerequisites=[[0,1]]` → `True`。容易错：把「学 0 前先学 1」误读成「学 1 前先学 0」，方向反了。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回一个合法的修课顺序？** 思路：DFS 在置 state=2 时把点压入结果栈，最后反转；或 BFS 拓扑排序直接按出队顺序输出。
2. **追问：不用递归，怎么改？** 思路：BFS 拓扑排序——统计每个点入度，入度为 0 的入队，出队时把邻居入度减 1，减到 0 再入队；最终出队数 == V 则无环。
3. **追问：如果先修关系带「或」条件（学 a 只需 b 或 c 之一）？** 思路：这不再是简单图可达性问题，需转成 2-SAT 或依赖图上的搜索，超出拓扑排序范畴，面试中说明建模变化即可。
