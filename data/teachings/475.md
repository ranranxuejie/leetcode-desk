## 1. 一句话本质

对每个房屋，找离它最近的供暖器，取这个距离；所有房屋里最大的那个距离，就是答案。

---

## 2. 读完题的第一反应

**朴素解法**：枚举半径 r，从 0 开始往上试，每次检查「所有房屋是否都被某个供暖器覆盖」。检查一次是 O(n·m)（每个房屋扫一遍所有供暖器），半径最大可能到 1e9，整体不可行。

换个朴素角度：对每个房屋，扫一遍所有供暖器找最近的，取最大。复杂度 O(n·m)，n、m 都是 3e4，最坏 9e8，超时。

**关键观察**：题目问的是「每个房屋各自找最近供暖器」这件事的最大值——房屋之间互不影响。所以问题拆成了 n 个独立的「最近邻查询」。而「在一堆有序数里找离 x 最近的」是二分的经典场景。于是想到：把 heaters 排序，每个房屋二分找插入位置，比较左右两个候选。

这个观察之所以关键，是因为它把「全局覆盖」这个听起来很整体的条件，化成了「逐房屋取最近距离再取 max」——**max 和 min 的顺序可以交换**：我们要的最小半径 R，恰好等于 max over houses ( min over heaters |h - t| )。这一步是整道题的题眼。

---

## 3. 从暴力到最优

**第一步：暴力 O(n·m)**

对每个房屋扫所有供暖器。以示例 2 为例：houses = [1,2,3,4]，heaters = [1,4]。

- 房屋 1：到 1 距离 0，到 4 距离 3 → 最近 0
- 房屋 2：到 1 距离 1，到 4 距离 2 → 最近 1
- 房屋 3：到 1 距离 2，到 4 距离 1 → 最近 1
- 房屋 4：到 1 距离 3，到 4 距离 0 → 最近 0

取 max = 1。答案对，但每个房屋都扫了全部供暖器。

**第二步：排序 + 二分 O((n+m) log m)**

瓶颈在「找最近」这一步。把 heaters 排序后，对房屋 x，最近的供暖器一定是「排序后插入位置左边那个」或「右边那个」——因为距离函数关于位置是 V 形的，最小值只可能出现在 x 两侧紧邻的两个点上。

还是示例 2，heaters 排序后 = [1,4]：

- 房屋 2：bisect_left([1,4], 2) = 1，左候选 heaters[0]=1（距离 1），右候选 heaters[1]=4（距离 2）→ 取 1
- 房屋 3：bisect_left([1,4], 3) = 1，左候选 1（距离 2），右候选 4（距离 1）→ 取 1

每个房屋 O(log m)，总 O(n log m + m log m)。

**第三步：双指针 O(n log n + m log m)，扫描部分 O(n+m)**

二分已经够用，但可以更顺：把 houses 也排序，然后两个指针一起从左往右走。对当前房屋，不断把「右指针」往前推，直到右供暖器比左供暖器更远为止，此时左指针就是最近的那个。

示例 2 走一遍（houses 排序 = [1,2,3,4]，heaters = [1,4]）：

- 房屋 1：i=0 指向 1。看 i+1=1 指向 4，|1-4|=3 > |1-1|=0，不前进。最近距离 0。
- 房屋 2：i=0 指向 1，|2-1|=1；i+1 指向 4，|2-4|=2 > 1，不前进。最近 1。
- 房屋 3：i=0 指向 1，|3-1|=2；i+1 指向 4，|3-4|=1 < 2，前进 i=1。现在 i=1 是最后一个，最近 1。
- 房屋 4：i=1 指向 4，最近 0。

取 max = 1。注意指针 i 只前进不后退，所以扫描是 O(n+m)。

**为什么指针不用回退**：房屋是从小到大处理的，如果对房屋 x 来说供暖器 t_{i+1} 比 t_i 更近，那么对更大的房屋 x' > x，t_{i+1} 只会更近或持平，t_i 不可能重新变近。这就是单调性，也是双指针成立的根本原因。

---

## 4. 正确性：为什么不会漏、不会重

**不变量**：处理到房屋 x 时，指针 i 满足「heaters[i] 是 heaters[0..i] 中离 x 最近的」，且「heaters[i+1..] 中离 x 最近的只可能是 heaters[i+1]」。

**为什么最近的一定在相邻两个里**：设排序后供暖器为 t_0 ≤ t_1 ≤ …。对任意房屋 x，若 t_j < x < t_k 且 k > j+1，则 t_{j+1} 夹在中间，|x - t_{j+1}| ≤ max(|x - t_j|, |x - t_k|) 中至少有一个不更差——更直接地，距离 |x - t| 在 t ≤ x 时随 t 增大而减小，在 t ≥ x 时随 t 增大而增大，所以最小值只可能在 x 左侧最近点和右侧最近点取到。二分和双指针都基于这个 V 形性质。

**为什么双指针不会漏**：指针前进的条件是「右邻居比当前更近」。一旦右邻居更远，由于房屋单调递增，右邻居之后只会更远，当前就是最近。若右邻居更近，则当前被淘汰，指针前进——被淘汰的供暖器对当前及之后所有房屋都不可能更近（因为房屋在增大，左侧点只会更远）。所以每个供暖器最多被跳过一次，不会漏掉真正的最近者。

**为什么取 max 就是答案**：设答案为 R*。对每个房屋，最近距离 d_h ≤ R*（否则该房屋在半径 R* 下没被覆盖，矛盾），所以 max d_h ≤ R*。反过来，取 R = max d_h，每个房屋到最近供暖器距离 ≤ R，全部被覆盖，所以 R* ≤ max d_h。两边夹住，相等。

## 5. 完整代码（Python）

```python
from bisect import bisect_left
from typing import List

class Solution:
    def findRadius(self, houses: List[int], heaters: List[int]) -> int:
        houses.sort()
        heaters.sort()
        ans = 0
        i = 0  # 指向当前考虑的供暖器下标
        m = len(heaters)

        for h in houses:
            # 只要右边还有供暖器，且右邻居比当前更近，就前进
            # 注意用 <= 还是 < 不影响结果，这里用严格小于保证稳定
            while i + 1 < m and abs(heaters[i + 1] - h) <= abs(heaters[i] - h):
                i += 1
            # 此时 heaters[i] 就是离 h 最近的供暖器
            ans = max(ans, abs(heaters[i] - h))

        return ans
```

如果更习惯二分写法，等价实现：

```python
from bisect import bisect_left
from typing import List

class Solution:
    def findRadius(self, houses: List[int], heaters: List[int]) -> int:
        heaters.sort()
        ans = 0
        m = len(heaters)
        for h in houses:
            pos = bisect_left(heaters, h)  # 第一个 >= h 的位置
            # 右候选：pos 处；左候选：pos-1 处。越界就取无穷大
            right = heaters[pos] - h if pos < m else float('inf')
            left = h - heaters[pos - 1] if pos > 0 else float('inf')
            ans = max(ans, min(left, right))
        return ans
```

两版都对。双指针版少一个 log，且不需要处理越界的 inf，面试里更推荐写双指针，讲起来也更能体现「单调性」这个洞察。

## 6. 复杂度

**双指针版**：

- 时间：排序 houses 是 O(n log n)，排序 heaters 是 O(m log m)；外层 for 走 n 次，内层 while 中指针 i 总共只前进 m 次（不回退），所以扫描部分是 O(n + m)。合计 **O(n log n + m log m)**。这里的 log 全部来自排序，n、m 分别是房屋数和供暖器数。
- 空间：排序本身 O(log n + log m) 的递归栈（Python 的 Timsort 是 O(n) 最坏辅助空间，但通常认为是 O(n)）；除此之外只用了几个变量，**O(1) 额外空间**（不计排序）。

**二分版**：时间 O(m log m + n log m)，空间同上。双指针在 n 和 m 同量级时略优，但两者都能过。

## 7. 边界与反例（至少 4 条）

1. **houses = [1], heaters = [1]** → 输出 0。容易错在初始化 ans 时写成 1 或忘记距离可以为 0。
2. **houses = [1,5], heaters = [2]** → 输出 3（示例 3）。容易错在只算了房屋 1 到 2 的距离 1，忘了房屋 5 到 2 的距离是 3，取 max 才是答案。
3. **houses = [1,2,3,4], heaters = [1,4]** → 输出 1（示例 2）。容易错在双指针里 while 条件写成 `abs(heaters[i+1]-h) < abs(heaters[i]-h)` 时对相等情况处理不当——本例中房屋 2 到 1 和到 4 距离分别是 1 和 2，不相等，但如果数据是 [1,3] 和 heaters=[2]，房屋 1 到 2 距离 1，指针不动，结果仍对；真正要小心的是指针越界判断 `i+1 < m` 漏写。
4. **houses = [1,2,3], heaters = [1,2,3]** → 输出 0。容易错在二分版里 `pos < m` 和 `pos > 0` 两个越界判断只写了一个，导致 `heaters[pos]` 越界或 `heaters[-1]` 被误用。
5. **houses 和 heaters 有重复位置**，如 houses = [1,1,1], heaters = [1]** → 输出 0。双指针版没问题，但若用 set 去重再排序，逻辑上也没错，只是没必要；容易错在误以为重复会干扰指针。

## 8. 面试追问与变体（3 条）

1. **追问：如果供暖器有不同功率（半径不同），怎么改？** 思路：每个房屋的「最近距离」不再是几何距离，而是「到某供暖器的距离 / 该供暖器功率」的最小值，仍是逐房屋取 min 再取 max，二分/双指针的框架不变，只是比较函数换掉。
2. **追问：如果要求返回具体是哪个半径、并给出每个房屋被哪个供暖器覆盖？** 思路：在求 max 的同时记录 argmin，最后再扫一遍分配，O(n + m)。
3. **追问：如果房屋和供暖器都在二维平面上？** 思路：最近邻查询变成二维，排序+双指针失效，需要 KD-tree 或对每个房屋做最近点查询；若数据规模小可暴力，规模大要上空间索引——这题的一维单调性是二维没有的。
