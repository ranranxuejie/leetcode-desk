## 1. 一句话本质

在一张「树 + 一条多余边」的图里，找出那条**加入时会让两个已连通节点再次连通**的边——也就是唯一构成环的那条边，且当有多条候选时取输入顺序中最后出现的那条。

## 2. 读完题的第一反应

**朴素解法**：枚举每条边，删掉它，然后用 DFS/BFS 检查剩下的图是否连通且无环（即是否是一棵 n 个节点的树）。检查一次是 O(n)，枚举 n 条边就是 O(n²)。n ≤ 1000 时 O(n²) = 10⁶ 其实能过，但这不是面试官想听的答案，而且它完全没利用「图 = 树 + 恰好一条边」这个强结构。

**关键观察**：题目保证图是「一棵树加一条边」得到的。树有 n−1 条边、无环、连通；加一条边后变成 n 条边、恰好含**一个环**。所以「删掉哪条边能变回树」等价于「删掉环上的任意一条边」——删环外的边图会不连通，删环上的边环就断了。而题目要求「多个答案取最后出现的」，意味着我们要找的是**按输入顺序依次加边时，第一次让某两个节点从「不连通」变成「已连通」的那条边**。因为在这条边之前，所有边都还没形成环（各自连接两个不同连通块），它一加进来就闭合了环；而它之后如果还有别的边也在环上，题目要的是最后出现的——但注意，一旦环形成，后续再加边只会让图更「冗余」，真正让图从树变成非树的**那条临界边**是唯一的：它就是「加入时两端已经连通」的第一条边。等等，这里要小心：题目说「最后出现的那个」，而环上可能有多条边。我们需要确认「第一条使两端已连通的边」是否就是答案。

**验证**：示例 2 中 edges = [[1,2],[2,3],[3,4],[1,4],[1,5]]。依次加边：1-2 连通{1,2}；2-3 连通{1,2,3}；3-4 连通{1,2,3,4}；加 1-4 时 1 和 4 已连通 → 形成环 1-2-3-4-1，这条边是 [1,4]。加 1-5 时 1 和 5 不连通，不形成环。所以「第一条使两端已连通的边」= [1,4]，正是答案。再看示例 1：[[1,2],[1,3],[2,3]]，加 1-2、1-3 后 {1,2,3} 连通，加 2-3 时 2、3 已连通 → 答案 [2,3]。✓

所以核心就一句话：**按顺序加边，用并查集维护连通性，第一条「两端已属同一集合」的边就是答案。** 这条边一定是环上最后被加入的那条（因为环上其他边在它之前加入时两端都还不连通），因此也满足「最后出现」的要求。

## 3. 从暴力到最优

**暴力**：对每条边做一次「删除 + 连通性检查」，O(n²)。瓶颈在于每次检查都从头扫全图。

**优化思路**：我们不删边，而是**正向加边**，动态维护连通性。加边时只需回答一个问题：「这两个端点现在连通吗？」如果连通，这条边就是多余的。维护连通性最合适的结构是并查集（Union-Find）：查询和合并近似 O(1)（严格说是 O(α(n))，α 是反阿克曼函数，实际可视为常数）。

**小例子走一遍**：edges = [[1,2],[2,3],[3,4],[1,4],[1,5]]，n=5，初始化 parent = [0,1,2,3,4,5]（下标即节点，0 占位）。

| 步骤 | 边 | find(a) | find(b) | 是否同集合 | 动作 | parent 变化 |
|---|---|---|---|---|---|---|
| 1 | [1,2] | 1 | 2 | 否 | union | parent[2]=1 |
| 2 | [2,3] | 1 | 3 | 否 | union | parent[3]=1 |
| 3 | [3,4] | 1 | 4 | 否 | union | parent[4]=1 |
| 4 | [1,4] | 1 | 1 | **是** | 返回 [1,4] | 不变 |
| 5 | — | — | — | — | 不执行 | — |

第 4 步 find(1)=1，find(4) 沿 parent[4]=1 找到 1，两端同根 → 这条边闭合了环 → 返回。瓶颈从「每次 O(n) 重扫」变成「每次近似 O(1) 的路径压缩查询」，总复杂度降到 O(n·α(n))。

## 4. 正确性：为什么不会漏、不会重

用**不变量**论证。设处理到第 i 条边之前，并查集正确维护了前 i−1 条边构成的图的连通分量（归纳假设：初始时每个点自成一个分量，正确；每次 union 把两个分量合并，正确）。

**不会漏**：题目保证图含恰好一个环。设环上的边按输入顺序为 e_{k1}, e_{k2}, …, e_{km}（k1<k2<…<km）。在加入 e_{k1} 到 e_{k(m−1)} 时，环还没闭合，每条边的两端在「此前已加入的边」构成的森林中必属不同分量（否则提前成环，与「恰好一个环」矛盾）。只有加入 e_{km} 时，它的两端已经通过环上其余边连通，find 返回同根。所以算法一定会在 e_{km} 处返回，不会漏。

**不会重（且满足「最后出现」）**：e_{km} 是环上最后加入的边，也是整个输入中**第一条**触发「同集合」的边——因为在此之前图始终是森林。算法返回第一条触发边，恰好就是 e_{km}。环上其他边都在它之前，不可能被返回；环外的边（如 [1,5]）两端不连通，也不会被返回。因此返回值唯一且正确。

**为什么「第一条触发边」= 「最后出现的可删边」**：可删的边必须属于那个唯一的环。环上最后被加入的边就是 e_{km}，它也是第一条触发边。两者是同一个对象，所以不矛盾。

## 5. 完整代码（Python）

```python
class Solution:
    def findRedundantConnection(self, edges):
        n = len(edges)
        # parent[i] 表示节点 i 的父节点，初始每个节点自成一个集合
        parent = list(range(n + 1))  # 节点编号 1..n，下标 0 不用

        def find(x):
            # 路径压缩：把沿途节点直接挂到根上，后续查询近似 O(1)
            while parent[x] != x:
                parent[x] = parent[parent[x]]  # 路径减半，迭代写法避免递归深度
                x = parent[x]
            return x

        for a, b in edges:
            ra, rb = find(a), find(b)
            if ra == rb:
                # 两端已连通，加入这条边会成环 → 它就是冗余边
                return [a, b]
            # 否则合并两个连通分量
            parent[ra] = rb

        return []  # 题目保证有解，理论上不会走到这里
```

关键逻辑说明：`find` 用迭代 + 路径减半，避免 n=1000 时递归虽不深但风格更稳；`parent[ra] = rb` 是最简合并（不做按秩合并，因为路径压缩已足够，且 n 很小）。返回 `[a, b]` 保持输入中的原始顺序，符合题目要求。

## 6. 复杂度

- **时间**：O(n·α(n))。n 来自遍历 edges 的 n 条边；每条边做两次 find 加至多一次 union，单次操作均摊 O(α(n))，α 是反阿克曼函数，n ≤ 1000 时 α(n) ≤ 4，实际就是常数。所以总时间近似 O(n)。这里没有 log n——如果用「按秩合并但不路径压缩」才会出现 O(log n)，本题路径压缩后是 α(n)。
- **空间**：O(n)。`parent` 数组长度 n+1，贡献 O(n)；find 是迭代写法，无递归栈开销。没有额外的图结构存储，这是并查集相对 DFS 建邻接表的优势（DFS 方案需要 O(n) 的邻接表 + O(n) 递归栈，空间常数更大）。

## 7. 边界与反例（至少 4 条）

1. **输入 `[[1,2],[2,3],[1,3]]`** → 期望 `[1,3]`。容易错：有人以为环上任意边都行就返回第一条，但题目要「最后出现」，必须返回触发同集合的那条，即 [1,3]。
2. **输入 `[[1,2],[1,3],[1,4],[1,5],[2,3]]`（星形 + 一条闭合边）** → 期望 `[2,3]`。容易错：环是 1-2-3-1，[2,3] 是最后加入的，若用 DFS 从节点 1 出发找环，可能先遇到 [1,2] 就误判。
3. **输入 `[[1,2],[2,3],[3,4],[4,1],[1,5]]`** → 期望 `[4,1]`（注意输出保持输入顺序，是 `[4,1]` 不是 `[1,4]`）。容易错：返回时把端点排序了，导致与期望数组不匹配。
4. **输入 `[[1,2],[2,3],[3,1],[3,4]]`（环在前，尾巴在后）** → 期望 `[3,1]`。容易错：以为要处理完所有边再判断，其实第一条触发边就是答案，提前返回即可；若继续处理 [3,4] 会误以为它也可删（但它不在环上，删了图不连通）。
5. **n=3 最小规模 `[[1,2],[1,3],[2,3]]`** → 期望 `[2,3]`。容易错：并查集数组开成 `range(n)` 而非 `range(n+1)`，节点 3 越界。

## 8. 面试追问与变体（3 条）

1. **追问：如果图里可能有多个环（不是「树+一条边」），怎么找所有冗余边？** 思路：仍用并查集，把所有「两端已连通」的边收集起来返回列表，而不是第一条就返回。
2. **追问：如果要求返回「字典序最小」的可删边而不是「最后出现」的？** 思路：先找出环上所有边（DFS 找环或并查集定位环），再在环边集合里取字典序最小的一条。
3. **追问：不用并查集，用 DFS 怎么做，复杂度多少？** 思路：建邻接表，从任意点 DFS，记录访问状态，遇到「已访问且不是父节点」的边即为环边；但 DFS 找到的环边不一定是「最后加入」的，需要额外按输入顺序过滤，复杂度 O(n)，空间 O(n) 邻接表。
