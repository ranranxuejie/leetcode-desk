## 1. 一句话本质

在一堆互不相同的绝对路径里，筛掉所有「祖先路径也在列表里」的路径，只留下最顶层的那些。

## 2. 读完题的第一反应

**朴素解法**：对每个 `folder[i]`，遍历所有 `folder[j]`，检查 `folder[i]` 是否以 `folder[j] + "/"` 开头。这是 O(n²) 次字符串比较，n 最大 4×10⁴，每次比较最长 100 字符，最坏约 1.6×10¹¹ 字符操作，必然超时。

**关键观察**：判断「谁是子文件夹」这件事，本质上是在比较**前缀**。而前缀关系有一个天然的性质——如果把所有路径按字典序排序，那么一个路径的所有后代一定紧跟在它后面（中间可能夹着别的后代），而不会散落到别处。

为什么？因为字典序比较是从左往右逐字符比的。`"/a"` 和 `"/a/b"` 共享前缀 `"/a"`，`"/a/b"` 在 `"/a"` 之后；而任何不以 `"/a"` 开头的字符串，比如 `"/b"`，在第一个不同字符处就比 `"/a"` 大，排在 `"/a"` 后面但排在 `"/a/..."` 这一整块之后。所以**同一棵子树的所有路径在排序后是连续的一段**。

这就把「两两比较」变成了「只看前一个留下的路径」——排序后线性扫一遍即可。

## 3. 从暴力到最优

**暴力**：双重循环，对每对 (i, j) 做 `startswith` 判断。瓶颈在于 n² 次比较。

**第一步优化——排序**：先对 `folder` 排序。排序后，任何路径的祖先一定出现在它**之前**（因为祖先更短且是它的前缀，字典序更小）。

**第二步优化——只和「上一个保留的路径」比**：这是最容易卡住的地方。为什么不用和所有已保留的路径比？

考虑排序后的序列。假设当前保留的最后一个路径是 `last`。对于新来的 `cur`：

- 如果 `cur` 以 `last + "/"` 开头，那 `cur` 是 `last` 的后代，删掉。
- 如果 `cur` 不以 `last + "/"` 开头，那 `cur` 也不可能是**更早**那些保留路径的后代。因为更早的保留路径要么是 `last` 的祖先（那 `cur` 若是它的后代，也必然是 `last` 的后代，矛盾），要么和 `last` 不在同一棵子树（那 `cur` 排在 `last` 之后，更不可能回到前面那棵子树里去）。

用示例 1 走一遍：`["/a","/a/b","/c/d","/c/d/e","/c/f"]` 排序后不变。

| 步骤 | cur | last（保留的最后一个） | 判断 | 动作 |
|---|---|---|---|---|
| 1 | `/a` | 无 | — | 保留，last=`/a` |
| 2 | `/a/b` | `/a` | 以 `/a/` 开头 | 删除 |
| 3 | `/c/d` | `/a` | 不以 `/a/` 开头 | 保留，last=`/c/d` |
| 4 | `/c/d/e` | `/c/d` | 以 `/c/d/` 开头 | 删除 |
| 5 | `/c/f` | `/c/d` | 不以 `/c/d/` 开头 | 保留，last=`/c/f` |

结果 `["/a","/c/d","/c/f"]`，正确。

再看示例 3 这个「陷阱」：`["/a/b/c","/a/b/ca","/a/b/d"]` 排序后是 `["/a/b/c","/a/b/ca","/a/b/d"]`。

- `/a/b/c` 保留，last=`/a/b/c`
- `/a/b/ca`：是否以 `/a/b/c/` 开头？`"/a/b/ca"` 的第 7 个字符是 `a`，不是 `/`，所以**不是**子文件夹，保留。
- `/a/b/d`：不以 `/a/b/ca/` 开头，保留。

结果三个都留下，正确。这里的关键就是**必须比较 `last + "/"` 而不是 `last`**——否则 `"/a/b/ca"` 会被误判为 `"/a/b/c"` 的子文件夹。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：扫描到第 k 个元素时，`ans` 中保存的恰好是前 k 个元素里所有「不是任何其他元素子文件夹」的路径，且 `ans` 按字典序递增。

**归纳基础**：第一个元素直接保留，显然它是前 1 个里唯一非子文件夹的。

**归纳步骤**：设前 k 个已满足不变量，`last = ans[-1]`。考虑第 k+1 个元素 `cur`。

- **若 `cur` 以 `last + "/"` 开头**：`cur` 是 `last` 的后代，应删。它不可能是其他保留路径的后代（否则那个路径也是 `last` 的祖先或同层，与 `last` 是最后一个保留路径矛盾）。删除后不变量保持。
- **若 `cur` 不以 `last + "/"` 开头**：需要证明 `cur` 不是 `ans` 中任何路径的后代。反证：若 `cur` 是某个 `p ∈ ans` 的后代，则 `p` 是 `cur` 的前缀，字典序 `p < cur`，所以 `p` 在 `cur` 之前出现。由于 `ans` 按字典序递增且 `last` 是 `ans` 中最后一个，`p ≤ last`。若 `p = last`，则 `cur` 以 `last + "/"` 开头，与假设矛盾；若 `p < last`，则 `p` 是 `last` 的祖先（因为 `last` 排在 `p` 之后且同属一棵子树），于是 `cur` 以 `p + "/"` 开头意味着 `cur` 也以 `last + "/"` 开头（`last` 在 `p` 和 `cur` 之间），同样矛盾。所以 `cur` 应保留，加入 `ans` 后不变量保持。

**不会漏**：任何非子文件夹的路径，在扫描到它时，要么是第一个，要么它前面的保留路径都不是它的祖先，按归纳步骤会被保留。

**不会重**：每个元素只被处理一次，`ans` 中元素互不相同（输入已保证唯一）。

## 5. 完整代码（Python）

```python
from typing import List

class Solution:
    def removeSubfolders(self, folder: List[str]) -> List[str]:
        # 按字典序排序，保证祖先一定出现在后代之前
        folder.sort()
        ans = []
        for path in folder:
            # 第一个元素直接保留
            if not ans:
                ans.append(path)
                continue
            last = ans[-1]
            # 关键：比较 last + "/"，而不是 last
            # 这样 "/a/b/ca" 不会被 "/a/b/c" 误判为子文件夹
            if not path.startswith(last + "/"):
                ans.append(path)
        return ans
```

## 6. 复杂度

设 n = `folder.length`，L = 单个路径最大长度（≤ 100）。

- **排序**：O(n log n · L)。比较两个字符串最坏 O(L)，排序做 O(n log n) 次比较。这里的 log n 来自排序，L 来自字符串比较。
- **扫描**：O(n · L)。每个元素做一次 `startswith`，最坏 O(L)。
- **总时间**：O(n log n · L)。n = 4×10⁴、L = 100 时约 4×10⁴ × 16 × 100 ≈ 6.4×10⁷，可接受。
- **空间**：O(n · L) 用于存储结果（最坏所有路径都保留）；排序本身若不计入则额外空间 O(1)（Python 的 `sort` 是 Timsort，最坏 O(n) 辅助空间，但通常视为原地）。

注意：如果面试官追问「能不能不排序」，可以用字典树，把每条路径按 `/` 切分插入，插入时若遇到已标记为「终止」的节点就说明是子文件夹。时间 O(n · L)，空间 O(n · L)，但常数更大、代码更长。排序法在本题数据规模下更优。

## 7. 边界与反例（至少 4 条）

1. **输入** `["/a"]` → **输出** `["/a"]` → **为什么容易错**：只有一个元素，`ans` 为空时直接 append，别写成 `ans[-1]` 越界。

2. **输入** `["/a/b/c","/a/b/ca","/a/b/d"]` → **输出** 三个都保留 → **为什么容易错**：用 `startswith(last)` 而非 `startswith(last + "/")`，会把 `"/a/b/ca"` 误删。

3. **输入** `["/a/b","/a"]` → **输出** `["/a"]` → **为什么容易错**：输入未排序时 `"/a/b"` 在前，若不排序直接扫，会先保留 `"/a/b"` 再保留 `"/a"`，两个都留下。排序后 `"/a"` 在前，`"/a/b"` 被正确删除。

4. **输入** `["/a/b/c","/a/b/c/d","/a/b/c/d/e"]` → **输出** `["/a/b/c"]` → **为什么容易错**：链式嵌套，`last` 一直是 `"/a/b/c"`，后两个都以 `"/a/b/c/"` 开头被删。若中途错误更新 `last` 为被删元素，会漏删。

5. **输入** `["/a/b","/a/c","/a"]` → **输出** `["/a"]` → **为什么容易错**：`"/a"` 排序后在最后，前两个先被保留，等 `"/a"` 到来时它不以 `"/a/c/"` 开头，会被错误保留。**这暴露了排序法的前提：排序后祖先一定在前**。`"/a"` 字典序小于 `"/a/b"` 和 `"/a/c"`，所以排序后 `"/a"` 在最前，问题不存在。但如果有人手动构造「不排序」的版本，这条就是反例。

## 8. 面试追问与变体（3 条）

1. **追问**：如果要求返回的路径保持输入顺序怎么办？
   **思路**：先用排序法求出「保留集合」（用 set 存），再按原 `folder` 顺序过滤输出，时间不变。

2. **追问**：如果路径里允许出现 `..` 或 `.` 需要规范化怎么办？
   **思路**：先对每条路径做栈式规范化（遇 `..` 弹栈），再套本题逻辑；注意规范化后可能产生重复，需去重。

3. **追问**：不用排序，用字典树怎么做？
   **思路**：按 `/` 切分路径插入 Trie，节点标记 `is_end`；插入时若路径上遇到 `is_end` 节点，说明是子文件夹，跳过；若插入完成后该节点已有后代，需清理。时间 O(n·L)。

## 9. 举一反三（2-3 道同类题）

- **LeetCode 648 单词替换**：同样是「前缀匹配 + 只保留最短前缀」，排序后扫描或 Trie 都能做。
- **LeetCode 820 单词的压缩编码**：判断一个单词是否是另一个的后缀，排序后只比较相邻元素，和本题「排序后只比 last」的思路同源。
- **LeetCode 14 最长公共前缀**：排序后只需比较首尾两个字符串，利用的正是「字典序相邻元素共享前缀最长」这一性质。
