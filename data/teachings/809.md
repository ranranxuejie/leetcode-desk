## 1. 一句话本质

判断每个候选单词能否通过「把长度不足 3 的字母组补到 3、把长度 ≥3 的字母组任意加长」变成目标串 `s`——本质是**按字母组做逐段匹配，每段比较字符是否相同、长度是否落在允许区间内**。

## 2. 读完题的第一反应

朴素想法：对每个 word，枚举所有可能的扩张方式，看能否得到 `s`。但扩张方式是指数级的（每个字母组可以加任意多个字符），根本枚举不完。这是第一个卡点。

第二个卡点：即使不枚举，直接逐字符比对 `word` 和 `s` 也不行。因为 `"hello"` 和 `"heeellooo"` 长度不同，逐位对齐会错位——`word` 的第 2 个 `l` 对应 `s` 的第 5 个 `e`，毫无意义。

关键观察：**扩张操作只改变字母组的长度，从不改变字母组的顺序，也从不改变每个字母组的字符本身**。也就是说，`"hello"` 的字母组序列是 `h|e|ll|o`，`"heeellooo"` 是 `h|eee|ll|ooo`，两者的「骨架」（字符序列 `h,e,l,o`）必须完全一致，只有每段的长度可以不同。这就把「枚举扩张」转化成了「对齐骨架 + 检查长度约束」——一个线性的双指针问题。

## 3. 从暴力到最优

**暴力**：对每个 word 做 BFS/DFS 枚举所有扩张结果，与 `s` 比较。每个字母组可加 0 到任意多个字符，状态空间爆炸，复杂度不可接受。

**第一步优化——按组切分**：把 `s` 和 `word` 各自压缩成「(字符, 长度)」的列表。比如：

```
s    = "heeellooo"  →  [('h',1), ('e',3), ('l',2), ('o',3)]
word = "hello"      →  [('h',1), ('e',1), ('l',2), ('o',1)]
```

这一步把「字符串对齐」变成了「组列表对齐」，问题规模从字符数降到组数。

**第二步——逐组检查**。设 `s` 的组为 `(c1, n1)`，`word` 的组为 `(c2, n2)`。能匹配的条件是什么？

- 字符必须相同：`c1 == c2`，否则骨架不同，直接失败。
- 长度约束：扩张只能「加长」，不能「缩短」，所以 `n1 >= n2`。
- 如果 `n2 < 3`，则这个组**不能被扩张**（题面：扩张后长度须达到 3 或以上，而扩张只能加不能减），所以必须 `n1 == n2`。
- 如果 `n2 >= 3`，可以扩张到任意 `>= n2` 的长度，所以只要 `n1 >= n2` 即可。

用上面的例子走一遍：

| 组 | s 的长度 | word 的长度 | 判断 |
|---|---|---|---|
| h | 1 | 1 | 字符同，word 长度 1 < 3，要求相等 → 1==1 ✓ |
| e | 3 | 1 | 字符同，word 长度 1 < 3，要求相等 → 3==1 ✗ |

等等，这里 `e` 组失败了？但示例说 `"hello"` 是可扩张的。重新读题面：「选择一个字母组，往其中添加相同的字母 c 使其长度达到 3 或以上」。注意——扩张操作是**对 word 做的**，把 word 的组加长去凑 s。`"hello"` 的 `e` 组长 1，扩张到 3 得到 `"heeello..."`，这是合法的，因为扩张后达到了 3。所以约束应该反过来理解：

- word 的组长度 `n2`，扩张后长度 `n1` 必须满足：要么 `n1 == n2`（不扩张），要么 `n1 >= 3` 且 `n1 > n2`（扩张了，且扩张后 ≥3）。
- 合并成一条：**`n1 == n2`，或者 `n1 >= max(3, n2+1)`**。更简洁地：`n1 >= n2` 且（`n1 == n2` 或 `n1 >= 3`）。

再走一遍：

| 组 | s 长度 n1 | word 长度 n2 | 判断 |
|---|---|---|---|
| h | 1 | 1 | n1==n2 ✓ |
| e | 3 | 1 | n1≠n2，但 n1=3≥3 ✓ |
| l | 2 | 2 | n1==n2 ✓ |
| o | 3 | 1 | n1≠n2，n1=3≥3 ✓ |

全部通过，`"hello"` 可扩张。而 `"helo"` 的组是 `h|e|l|o`，`l` 组 n2=1，对应 s 的 `l` 组 n1=2，n1≠n2 且 n1=2<3，失败——正是题面说的「ll 长度小于 3」。

**第三步——组数必须相同**。如果 word 的组数和 s 不同（比如 `"hi"` 只有 2 组，s 有 4 组），骨架就对不上，直接失败。

这样每个 word 只需 O(len(word) + len(s)) 的扫描，总复杂度 O(len(s) + Σlen(words[i]))。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在双指针扫描过程中，指针 `i` 始终指向 `s` 中某个字母组的起点，指针 `j` 始终指向 `word` 中某个字母组的起点，且此前所有组都已成功匹配。

**必要性（不会漏判为可扩张）**：如果 word 能扩张成 s，那么扩张不改变字符顺序和每组字符，所以两串的组序列字符必须一一对应相同；且每组扩张后长度 n1 要么等于原长 n2，要么 ≥3（题面扩张定义），所以长度条件必须满足。我们的检查恰好覆盖这两条，任何可扩张的 word 都会通过。

**充分性（不会误判）**：如果所有组都通过检查，我们可以对每个 `n1 ≠ n2` 的组执行扩张（把 n2 加到 n1，此时 n1≥3 保证合法），对 `n1 == n2` 的组不操作，最终得到的就是 s。所以检查通过 ⟹ 可扩张。

**不重**：每个 word 独立判断一次，计数加一，不存在重复计数。

## 5. 完整代码（Python）

```python
class Solution:
    def expressiveWords(self, s: str, words: list[str]) -> int:
        # 把字符串压缩成 [(字符, 连续长度), ...]
        def compress(t: str):
            groups = []
            i = 0
            n = len(t)
            while i < n:
                j = i
                while j < n and t[j] == t[i]:
                    j += 1
                groups.append((t[i], j - i))
                i = j
            return groups

        s_groups = compress(s)
        ans = 0

        for w in words:
            w_groups = compress(w)
            # 组数不同，骨架对不上，直接跳过
            if len(w_groups) != len(s_groups):
                continue

            ok = True
            for (cs, ns), (cw, nw) in zip(s_groups, w_groups):
                # 字符必须相同
                if cs != cw:
                    ok = False
                    break
                # 长度条件：相等，或扩张后达到 3 以上
                if ns != nw and ns < 3:
                    ok = False
                    break
                # 扩张只能加长，不能缩短
                if ns < nw:
                    ok = False
                    break

            if ok:
                ans += 1

        return ans
```

注意 `ns != nw and ns < 3` 这一条：当 `ns != nw` 时，说明发生了扩张，扩张后长度 `ns` 必须 ≥3。而 `ns < nw` 单独检查是因为扩张不能缩短——虽然 `ns < 3` 且 `ns < nw` 时前一条已拦截，但 `ns >= 3` 且 `ns < nw` 的情况需要这条兜底（比如 s 组长度 3，word 组长度 5，不能把 5 缩短成 3）。

## 6. 复杂度

设 `L = len(s)`，`W = Σ len(words[i])`，`k = len(words)`。

- **时间**：压缩 s 是 O(L)；每个 word 压缩 O(len(word))，比较组列表 O(组数) ≤ O(len(word))。总计 O(L + W)。没有排序、没有二分，所以没有 log 项。
- **空间**：`s_groups` 最多 O(L) 个组（最坏情况每个字符一组），每个 word 临时压缩 O(len(word))，但可复用/即用即弃。峰值 O(L + max_len(word))，即 O(L + max word 长度)。若不计输入，额外空间 O(L)。

## 7. 边界与反例

1. **`s = "aaa", words = ["a"]`** → 期望 1。`"a"` 的组 `a` 长 1，s 的组 `a` 长 3，n1≠n2 且 n1=3≥3，合法。容易错：误以为 word 组必须 ≥3 才能扩张，其实 word 组可以 <3，只要扩张后 ≥3。

2. **`s = "aa", words = ["a"]`** → 期望 0。s 的 `a` 组长 2，word 的 `a` 组长 1，n1≠n2 但 n1=2<3，不能扩张到 2（扩张后必须 ≥3）。容易错：只检查 `n1 >= n2` 就放行。

3. **`s = "aaa", words = ["aaaa"]`** → 期望 0。word 的 `a` 组长 4 > s 的 3，扩张只能加长不能缩短。容易错：忘了 `ns < nw` 的检查。

4. **`s = "heeellooo", words = ["hi"]`** → 期望 0。组数 4 vs 2，骨架不同。容易错：只比较第一个字符就下结论，或没检查组数。

5. **`s = "abcd", words = ["abcd"]`** → 期望 1。所有组长度都是 1，`n1==n2`，无需扩张。容易错：误以为必须至少有一个组被扩张。

## 8. 面试追问与变体

1. **追问：如果扩张操作允许把长度 ≥3 的组缩短到 3，答案怎么变？** 思路：长度条件改为 `n1 == n2` 或 `n1 >= 3`（不再要求 n1≥n2），因为可以双向调整。

2. **追问：如果要求输出所有可扩张的单词而非计数？** 思路：把 `ans += 1` 改成收集 `w` 到结果列表，逻辑不变。

3. **追问：如果 words 很大（比如 10^5 个），如何优化？** 思路：预处理 s 的组列表一次，每个 word 仍 O(len) 比较；若 word 间有大量重复，可按压缩后的组元组做哈希缓存结果。
