## 1. 一句话本质

在数组里找两个下标 `i < j`，满足 `j - i >= 2` 且 `(prefix[j] - prefix[i]) % k == 0`——也就是找两个**前缀和模 k 同余**、且**下标至少隔 2** 的位置。

## 2. 读完题的第一反应

**朴素解法**：枚举所有长度 ≥ 2 的连续子数组，对每个子数组求和判断能否被 k 整除。子数组有 O(n²) 个，每个求和 O(n)，总 O(n³)；用前缀和优化求和到 O(1)，仍有 O(n²) 个区间。n 最大 10⁵，O(n²) 是 10¹⁰ 量级，必然超时。

**卡在哪**：瓶颈是「枚举区间」这件事本身。要消掉它，必须换一个视角——不去枚举区间，而是去枚举**端点**，并让端点之间「配对」的过程变成 O(1) 的查表。

**关键观察**：设 `prefix[t] = nums[0] + ... + nums[t-1]`（前缀和，`prefix[0] = 0`）。子数组 `nums[i..j-1]` 的和是 `prefix[j] - prefix[i]`。它被 k 整除，等价于

```
prefix[j] ≡ prefix[i]  (mod k)
```

这一步是整个题的转折点：**「区间和是 k 的倍数」被翻译成了「两个前缀和模 k 相等」**。于是问题从「找区间」变成「找一对同余的前缀和」，而「找一对」天然适合用哈希表边扫边存——扫到 `j` 时，只要查表里有没有同余的 `i` 即可。

## 3. 从暴力到最优

**第一步：前缀和把求和降到 O(1)。** 预处理 `prefix` 数组后，任意区间和 O(1) 得到。但区间个数还是 O(n²)，瓶颈没动。

**第二步：把「区间和」换成「同余配对」。** 由上面的观察，我们不再关心区间和的具体值，只关心 `prefix[t] % k`。对每个 `j`，我们要问：之前有没有某个 `i`，使得 `prefix[i] % k == prefix[j] % k`？如果有，`nums[i..j-1]` 就是一个候选答案。

**第三步：哈希表把「找 i」降到 O(1)。** 维护一个字典 `first_seen`，键是余数 `r`，值是**这个余数第一次出现的下标**。扫到 `j` 时：

- 若 `prefix[j] % k` 已在表里，且 `j - first_seen[r] >= 2`，返回 True；
- 否则把当前余数（若未出现过）记入表中。

**为什么存「第一次出现」而不是「最近一次」？** 因为我们要的是长度 ≥ 2，下标差越大越容易满足条件。存最早的下标，能给后续所有 j 提供最大的长度余量，是最优选择。

**小例子走一遍**：`nums = [23, 2, 4, 6, 7], k = 6`。

| j | nums[j-1] | prefix[j] | prefix[j] % 6 | 表内已有同余? | 动作 |
|---|---|---|---|---|---|
| 0 | — | 0 | 0 | 否 | 存 {0: 0} |
| 1 | 23 | 23 | 5 | 否 | 存 {0:0, 5:1} |
| 2 | 2 | 25 | 1 | 否 | 存 {0:0, 5:1, 1:2} |
| 3 | 4 | 29 | 5 | 是，i=1 | j-i=2 ≥ 2 → **True** |

对应子数组 `nums[1..2] = [2, 4]`，和 6，正是示例 1 的答案。

再看一个「同余但长度不够」的陷阱：`nums = [1, 2], k = 3`。j=1 时 prefix=1，余数 1，表 {0:0}；j=2 时 prefix=3，余数 0，表里有 i=0，但 j-i=2 ≥ 2，返回 True（子数组 [1,2] 和 3）。而 `nums = [3], k = 3`：j=1 时余数 0 命中 i=0，但 j-i=1 < 2，不能返回 True，继续扫完返回 False——这正是「长度至少 2」这条约束在代码里必须显式检查的原因。

## 4. 正确性：为什么不会漏、不会重

**不变量**：扫描到下标 `j` 时，哈希表中恰好存着 `{prefix[t] % k : t}`，其中 `t` 取遍 `0..j-1` 中**每个余数第一次出现的位置**。

**不会漏**：假设存在合法子数组 `nums[i..j-1]`（`j - i >= 2`，和是 k 的倍数）。那么 `prefix[i] % k == prefix[j] % k`。当扫描到 `j` 时，`i` 已经在表里（因为 `i < j`），且表里存的是该余数**最早**出现的位置 `i' <= i`。于是 `j - i' >= j - i >= 2`，检查会通过，返回 True。所以任何合法解都会被捕获。

**不会重（不误报）**：代码只在「余数相同」且「下标差 ≥ 2」时返回 True。余数相同保证区间和是 k 的倍数（由第 2 节的等价性），下标差 ≥ 2 保证长度至少 2。两个条件都满足，返回的必然是合法解，不会把非法区间当成答案。

**为什么「存最早位置」不影响正确性**：对固定的 `j`，若存在某个合法 `i`，则最早位置 `i' <= i` 也合法（长度更大）。所以用最早位置替代任意合法位置，判定结果不变——这是「交换论证」的实质：把「用 i 判定」换成「用 i' 判定」，结论一致。

## 5. 完整代码（Python）

```python
class Solution:
    def checkSubarraySum(self, nums, k):
        # first_seen: 余数 -> 该余数第一次出现的下标（前缀和下标）
        # 初始化放入 (0, 0)：空前缀 prefix[0] = 0，余数 0，下标 0
        first_seen = {0: 0}
        prefix = 0  # 滚动维护前缀和，省掉整个 prefix 数组

        for j in range(1, len(nums) + 1):
            prefix += nums[j - 1]          # prefix 现在是 nums[0..j-1] 的和
            r = prefix % k                 # 当前前缀和模 k 的余数

            if r in first_seen:
                # 找到同余的更早前缀，检查长度是否 >= 2
                if j - first_seen[r] >= 2:
                    return True
                # 长度不够（只可能是 j - first_seen[r] == 1），
                # 不能更新 first_seen[r]，否则会丢掉更早的位置
            else:
                # 该余数首次出现，记录下标
                first_seen[r] = j

        return False
```

两个容易写错的点，代码里已经体现：

1. **初始化 `{0: 0}` 不能省**。它代表「空前缀」，让「从下标 0 开始的子数组」也能被正确判定。例如 `nums = [2, 4], k = 6`，j=2 时 prefix=6、余数 0，命中 i=0，j-i=2，返回 True。
2. **命中但长度不够时，不能覆盖 `first_seen[r]`**。因为更早的位置对后续 j 更有利，覆盖会丢掉潜在的最优解。

## 6. 复杂度

- **时间 O(n)**：`for` 循环跑 n 次，每次做一次加法、一次取模、一次字典查找/插入，都是 O(1)。n 来自数组长度，没有 log 项——因为哈希表操作平均 O(1)，不涉及排序或二分。
- **空间 O(min(n, k))**：字典最多存 `min(n+1, k)` 个不同余数（余数取值只有 0..k-1 共 k 种，前缀和下标只有 n+1 个）。最坏 O(n)。没有额外开 prefix 数组，滚动变量把空间压到只剩哈希表。

## 7. 边界与反例（至少 4 条）

1. **`nums = [5, 0, 0, 0], k = 3` → True**。易错点：`[0, 0]` 和为 0，0 视为 k 的倍数，应返回 True。若代码把「和 > 0」当必要条件就错了。
2. **`nums = [1], k = 1` → False**。易错点：单个元素构不成长度 ≥ 2 的子数组。若忘记检查 `j - i >= 2`，j=1 时余数 0 命中 i=0，会误返回 True。
3. **`nums = [0, 1, 0], k = 2` → False**。易错点：`[0,1]` 和 1、`[1,0]` 和 1、`[0,1,0]` 和 1，都不是 2 的倍数。前缀和余数序列 0,0,1,1：j=1 命中 i=0 但长度 1 不够；j=3 命中 i=2 但长度 1 不够。必须靠「不覆盖 first_seen」才能正确判定。
4. **`nums = [23, 2, 4, 6, 6], k = 7` → True**。易错点：`[2,4,6,6]` 和 18 不是 7 的倍数，但 `[4,6,6]` 和 16 也不是……实际 `[23,2,4,6,6]` 和 41 不是。真正答案是 `[2,4,6,6]`？18 不是。检查：`[23,2,4,6,6]` 前缀和 0,23,25,29,35,41，模 7 为 0,2,4,1,0,6。j=4 时余数 0 命中 i=0，长度 4 ≥ 2，子数组 `[23,2,4,6]` 和 35 = 5×7，True。易错点：答案区间可能很长，不能只盯着短区间。
5. **`k = 1` → 恒为 True（当 n ≥ 2）**。易错点：任何整数都是 1 的倍数，只要数组长度 ≥ 2 就返回 True。代码里余数恒为 0，j=2 时命中 i=0、长度 2，正确返回。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回具体的子数组下标，而不是布尔值？** 思路：`first_seen` 存下标不变，命中且长度够时直接返回 `(first_seen[r], j-1)`，其余逻辑完全一样。
2. **追问：如果 k 可能为 0 或负数？** 思路：题面保证 `k >= 1`，若放开，需先处理 k=0（此时要求区间和为 0，退化为「找两个相等前缀和」），负数取模在 Python 里结果非负，逻辑仍成立但要说明。
3. **追问：如果要求子数组长度恰好为 2？** 思路：不再需要哈希表，直接扫相邻两数判断 `(nums[i] + nums[i+1]) % k == 0`，O(n) 时间 O(1) 空间——这反过来说明哈希表是为「任意长度」服务的。

## 9. 举一反三（2-3 道同类题）

- **560. 和为 K 的子数组**：同样用「前缀和 + 哈希表」把区间和转成前缀和之差，区别是这里求「差等于定值」而非「差模 k 同余」，哈希表存的是「前缀和的值 → 出现次数」。
- **974. 和可被 K 整除的子数组**：几乎是本题的计数版，把「是否存在」换成「有多少个」，哈希表存「余数 → 出现次数」，命中时累加次数而不是返回 True。
- **525. 连续数组**：把 0 看成 -1 后求「和为 0 的最长子数组」，同样是前缀和 + 哈希表存「首次出现位置」，和本题的「存最早下标」技巧完全同源。
