## 1. 一句话本质

用一棵「每个节点代表一个字符、从根到某节点的路径拼出一个前缀」的多叉树，把字符串集合的存储和前缀查询都压到 O(字符串长度)。

## 2. 读完题的第一反应

最朴素的做法：用一个 `list` 或 `set` 存所有插入过的字符串。

- `insert`：`set.add(word)`，O(L)。
- `search`：`word in set`，O(L) 哈希。
- `startsWith`：**卡住了**。`set` 里没有「前缀」这个概念，你只能遍历所有已插入的字符串，逐个判断 `s.startswith(prefix)`。设已插入 m 个串、总长 N，单次 `startsWith` 就是 O(N)。调用 3×10⁴ 次，直接爆。

瓶颈的根源是：**哈希表把整个字符串当成一个不可分割的键，丢掉了字符之间的顺序结构**。而 `startsWith` 恰恰只关心「顺序结构的前一段」。

关键观察：`search("app")` 和 `startsWith("app")` 的差别，仅仅是「走完 `a→p→p` 这条路径后，当前节点是不是某个单词的结尾」。也就是说，**前缀查询 = 沿字符边走；完整匹配 = 沿字符边走 + 终点带结束标记**。这两件事共用同一条路径，天然适合用树来存。

## 3. 从暴力到最优

**第一步：把字符串「拆开」存。** 不存 `"apple"` 这个整体，而是存路径 `a→p→p→l→e`。多个字符串共享前缀时，路径自然合并——插入 `"apple"` 后再插入 `"app"`，前三个节点复用，只在第三个节点上打一个「单词结束」标记。

**第二步：节点需要什么。** 每个节点两样东西：
1. `children`：一个从字符到子节点的映射（题面限定小写字母，可以用长度 26 的数组，也可以用 dict）；
2. `is_end`：布尔值，标记「从根走到这里恰好是一个完整单词」。

**第三步：三个操作统一成「沿路径走」。**

用一个具体例子走一遍。依次执行 `insert("apple")`、`search("app")`、`startsWith("app")`、`insert("app")`、`search("app")`。

初始：根节点 `root`，`children={}`，`is_end=False`。

`insert("apple")`：从 root 出发，依次处理 `a,p,p,l,e`。每步若 `children[c]` 不存在就新建节点挂上去，最后把 `e` 节点的 `is_end` 置 `True`。此时路径上 5 个节点，只有 `e` 节点 `is_end=True`。

`search("app")`：从 root 走 `a→p→p`，三个节点都存在，能走通。但停在第三个 `p` 节点时，它的 `is_end` 是 `False`（因为只插过 `apple`）。**走通 ≠ 是单词**，返回 `False`。这正是示例里第二个 `search` 输出 `false` 的原因。

`startsWith("app")`：同样走 `a→p→p`，走通即可，**不看 `is_end`**，返回 `True`。

`insert("app")`：走 `a→p→p`，节点已存在，不新建，只把第三个 `p` 节点的 `is_end` 改成 `True`。

`search("app")`：走通且终点 `is_end=True`，返回 `True`。

对比暴力法：`startsWith` 从「扫全部字符串」变成「走 L 步」，瓶颈被彻底消掉，因为**共享前缀只存了一份，查询只走这一份**。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义不变量 I：

> 对任意字符串 s，从根沿 s 的字符逐边走，若路径存在，则终点节点唯一；且 `s` 被插入过 ⟺ 该路径存在且终点 `is_end=True`。

- **insert 维持 I**：插入时逐字符确保路径存在（缺则建），最后置终点 `is_end=True`。路径唯一性由「每个节点对每个字符最多一个子节点」保证（数组/dict 的键唯一）。所以插入后 I 成立。
- **search 维持 I 且返回正确**：search 就是沿路径走一遍。若中途某字符无对应子节点，说明没有任何插入过的字符串以该前缀开头，故 s 不可能被插入过，返回 `False` 正确；若走通，由 I 的「⟺」右半部分，`is_end` 的真假恰好等于 s 是否被插入过，返回 `is_end` 正确。
- **startsWith 正确**：走通即存在某个插入过的字符串以 prefix 为前缀（因为路径上的节点只可能由插入操作创建，而创建它的那次插入必然经过这条前缀）。走不通则不存在。与 I 一致。

「不会重」体现在：多个字符串共享前缀时，路径只有一条，`is_end` 是节点级标记，不同单词的结束位置不同，互不覆盖；同一个单词重复插入只是把已为 `True` 的标记再置一次，幂等。

## 5. 完整代码（Python）

```python
class TrieNode:
    def __init__(self):
        # 26 个小写字母，初始为 None 表示该分支不存在
        self.children = [None] * 26
        # 标记「从根走到本节点」是否构成一个完整单词
        self.is_end = False


class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        node = self.root
        for ch in word:
            idx = ord(ch) - ord('a')          # 字符映射到 0..25
            if node.children[idx] is None:    # 分支不存在才新建，存在则复用（共享前缀）
                node.children[idx] = TrieNode()
            node = node.children[idx]         # 沿路径下移
        node.is_end = True                    # 终点打标记，幂等

    def _walk(self, s: str):
        """沿 s 走，走通返回终点节点，走不通返回 None。search 和 startsWith 共用。"""
        node = self.root
        for ch in s:
            idx = ord(ch) - ord('a')
            if node.children[idx] is None:
                return None                   # 前缀断裂，后续无需再看
            node = node.children[idx]
        return node

    def search(self, word: str) -> bool:
        node = self._walk(word)
        # 走通还不够，必须是某个单词的结尾
        return node is not None and node.is_end

    def startsWith(self, prefix: str) -> bool:
        # 只要走通即可，不关心是否单词结尾
        return self._walk(prefix) is not None
```

> 说明：题面给的签名是 `Solution.solve(...) -> boolean`，但本题是「设计类」题，力扣实际要求实现 `Trie` 类并由评测器按操作序列调用。上面的 `Trie` 类即符合该调用协议；若你的平台强制要求 `Solution.solve`，把 `Trie` 实例化后按操作分发即可，核心逻辑不变。

## 6. 复杂度

设单次操作的字符串长度为 L，总操作次数为 Q，字符集大小 Σ=26。

- **insert**：时间 O(L)——每个字符做一次数组下标访问和一次判空，常数时间。空间 O(L)——最坏情况新建 L 个节点，每个节点一个 26 长数组。
- **search / startsWith**：时间 O(L)——`_walk` 逐字符下移，每步 O(1)；走不通时提前返回，实际 ≤ L。
- **总空间**：O(总插入字符数 × Σ)。这里 Σ=26 是「每个节点固定开 26 个槽」的代价；若改用 dict 存 children，空间降到 O(总节点数)，但单步期望仍 O(1)。题面 L≤2000、Q≤3×10⁴，26 数组完全够用且常数更小。

注意：**没有 log 项**。树的高度就是字符串长度 L，查询代价与「已存多少字符串」无关——这正是 Trie 相对哈希+遍历的优势所在。

## 7. 边界与反例（至少 4 条）

1. **插入 `"apple"` 后 `search("app")`** → 期望 `False`。易错点：以为「路径走得通就是单词」，忘了检查 `is_end`。这是本题最经典的坑，示例里专门考了。
2. **插入 `"apple"` 后 `startsWith("apple")`** → 期望 `True`。易错点：误以为 `startsWith` 也要求 `is_end`，把两个方法写成一样。
3. **先 `search("app")` 再 `insert("app")` 再 `search("app")`** → 期望 `False, True`。易错点：`search` 在路径不存在时若直接抛异常或误建节点（把查询写成插入），会污染树结构，导致后续结果错乱。查询必须只读。
4. **插入 `"app"` 后 `search("apple")`** → 期望 `False`。易错点：走到 `a→p→p` 后继续找 `l`，`children` 为 `None`，必须返回 `False` 而不是「前缀匹配就算」。
5. **重复插入同一单词 `"a"` 两次** → 期望两次后 `search("a")` 仍 `True`。易错点：若用计数器而非布尔标记，需保证幂等；本题用布尔 `is_end` 天然幂等。
6. **单字符 `"a"` 与空前缀边界**：题面保证 `prefix.length ≥ 1`，但若平台传入空串，`_walk("")` 返回 root，`startsWith("")` 返回 `True`——语义上「空前缀是任何串的前缀」，可接受，需在注释里说明假设。

## 8. 面试追问与变体（3 条）

1. **追问：如何支持通配符查询，如 `search(".app")` 中 `.` 匹配任意字母？**
   思路：`_walk` 改成 DFS，遇到 `.` 时枚举当前节点所有非空子节点递归，其余字符照常单路下移；终点仍检查 `is_end`。

2. **追问：如何统计以某前缀开头的单词个数？**
   思路：每个节点额外维护 `cnt`（经过该节点的单词数），`insert` 时沿途 `+1`；`startsWith` 走通后返回终点 `cnt` 即可，O(L)。

3. **追问：内存吃紧，如何压缩？**
   思路：把 26 数组换成 dict（稀疏时省空间），或进一步用「双数组 Trie / 压缩前缀树（Radix Tree）」，把单链节点合并成一条边存整个子串。
