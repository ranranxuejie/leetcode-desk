## 1. 一句话本质

把每条「根→叶」路径上的节点数字按顺序拼成一个十进制整数，再把所有这样的整数加起来。

## 2. 读完题的第一反应

**朴素解法**：先枚举出所有根到叶的路径（每条路径存成一个列表），再把每条路径的列表转成整数，最后求和。枚举路径本身就要遍历整棵树，每条路径还要额外花 O(路径长度) 去拼接数字。整体是 O(n·h)，n 是节点数、h 是树高。这个复杂度其实不算爆炸（h ≤ 10），但它卡在**「先把路径完整存下来，再回头算」**这个思路上——你需要额外的列表存储，而且代码里会出现「收集路径」和「转换数字」两段割裂的逻辑，容易写错。

**关键观察**：拼接数字这个动作是**可以边往下走边累积的**。走到节点 v 时，从根到 v 拼成的数 = 从根到 v 的父节点拼成的数 × 10 + v.val。也就是说，父节点那一步算出来的中间结果，正好是子节点需要的输入。这让你意识到：不需要把路径存下来，只需要在递归往下传的时候带一个「到目前为止拼成的数」参数即可。一旦想到「参数往下传」，DFS 的骨架就自然浮现了。

## 3. 从暴力到最优

**暴力版**：递归收集所有路径到 `paths` 列表里，再对每条路径做 `int(''.join(...))` 求和。瓶颈在于「存路径」这一步：每条路径都要单独占一份内存，且拼接是事后做的。

**优化版**：把「拼数字」提前到遍历过程中。用一个参数 `cur` 表示「从根走到当前节点为止拼成的数」。进入节点时执行 `cur = cur * 10 + node.val`，然后：

- 如果当前是叶子（左右都空），说明一条完整路径到头了，把 `cur` 累加进答案；
- 否则把 `cur` 分别传给左右子节点继续。

**小例子走一遍**：以 `root = [4,9,0,5,1]` 为例（结构是 4 的左孩子 9、右孩子 0；9 的左孩子 5、右孩子 1）。

| 步骤 | 节点 | 传入 cur | 更新后 cur | 动作 |
|---|---|---|---|---|
| 1 | 4 | 0 | 0×10+4 = 4 | 非叶，传给 9 和 0 |
| 2 | 9 | 4 | 4×10+9 = 49 | 非叶，传给 5 和 1 |
| 3 | 5 | 49 | 49×10+5 = 495 | 叶子，ans += 495 → 495 |
| 4 | 1 | 49 | 49×10+1 = 491 | 叶子，ans += 491 → 986 |
| 5 | 0 | 4 | 4×10+0 = 40 | 叶子，ans += 40 → 1026 |

对比暴力版：暴力版会先存下 `[4,9,5]`、`[4,9,1]`、`[4,0]` 三条列表，再分别转成 495、491、40。优化版把「存列表」和「转数字」合并成了一次 `cur*10+val`，中间变量 `cur` 在回溯时自动「恢复」——因为它是按值传参的，回到父节点时父节点的 `cur` 没被改动。这就是瓶颈被消掉的地方：**路径信息不再需要显式存储，它被编码进了一个整数参数里**。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

定义不变量：*当 DFS 调用 `dfs(node, cur)` 时，`cur` 恰好等于「从根节点到 node 的父节点」这条路径拼成的十进制数（根节点调用时 cur=0，视为空前缀）。*

- **初始**：调用 `dfs(root, 0)`，空前缀拼成的数定义为 0，不变量成立。
- **保持**：进入 node 后计算 `cur*10 + node.val`。由不变量，`cur` 是根到父节点的数，那么「根到 node 的数」= 父节点的数 × 10 + node 的数字，这正是十进制左移一位再补末位的定义。所以传给子节点的参数满足不变量。
- **终止与收集**：当 node 是叶子时，根到 node 的路径就是一条完整的根→叶路径，此时 `cur*10+node.val` 正是该路径对应的整数，累加进答案。

**不漏**：树中每个叶子都会被 DFS 访问到（DFS 遍历所有节点），每个叶子恰好对应一条根→叶路径，所以每条路径都被计入。

**不重**：每个叶子只被访问一次（树无环、DFS 每个节点进一次），且只在叶子处累加，非叶子不累加，所以每个整数只加一次。

两者合起来：答案 = 所有根→叶路径对应整数之和，且每个恰好一次。

## 5. 完整代码（Python）

```python
class Solution:
    def sumNumbers(self, root) -> int:
        # 全局累加器：所有根->叶路径对应整数之和
        self.ans = 0

        def dfs(node, cur):
            # cur 表示「从根到 node 的父节点」拼成的数
            # 进入 node 后，把 node 的数字接到末尾
            cur = cur * 10 + node.val

            # 叶子判定：左右孩子都为空
            if node.left is None and node.right is None:
                # 一条完整路径到头，累加
                self.ans += cur
                return

            # 非叶子：把当前 cur 分别传给存在的孩子
            if node.left is not None:
                dfs(node.left, cur)
            if node.right is not None:
                dfs(node.right, cur)

        dfs(root, 0)
        return self.ans
```

关键逻辑说明：

- `cur = cur * 10 + node.val`：十进制左移补末位，是「拼接」的数学表达，替代了字符串拼接。
- `self.ans` 用实例属性而非返回值累加：因为 DFS 是「往下走、到叶子才产出结果」，用外部累加器最直观；也可以用返回值版本（见第 8 节追问）。
- 叶子判定放在「更新 cur 之后」：保证叶子自己的数字也被拼进去，这是最容易写反的地方。

## 6. 复杂度

**时间 O(n)**：n 是节点数。DFS 对每个节点恰好访问一次，每次做常数次操作（一次乘加、一次判空、一次累加）。没有对路径做额外遍历，所以没有 h 因子。

**空间 O(h)**：h 是树高，来自递归调用栈的深度。每层递归占一个栈帧，最深走到叶子，栈深 = 树高。题面给 h ≤ 10，所以实际很小；最坏情况（链状树）h = n，空间退化为 O(n)。注意这里**没有** O(n) 的路径存储开销，这正是优化版相对暴力版省下的地方——暴力版要存所有路径，最坏 O(n·h)。

## 7. 边界与反例（至少 4 条）

1. **单节点树** `root = [5]` → 期望 `5` → 容易错：有人把「叶子」判定写成「至少有一个孩子为空」，导致根节点被误判为非叶、不累加，返回 0。正确判定是「左右都为空」。
2. **含 0 的路径** `root = [0,1,2]` → 期望 `1+2=3`（路径 0→1 得 01=1，0→2 得 02=2）→ 容易错：用字符串拼接后 `int("01")` 得 1 没问题，但若有人手动去掉前导零或误以为 0 节点应跳过，就会算错。`cur*10+val` 天然处理前导零，不需要特判。
3. **只有左孩子的链** `root = [1,2,null,3]` → 路径 1→2→3 得 123，期望 `123` → 容易错：把「非叶」当成「有两个孩子」，导致中间节点 2 被当成叶子提前累加（累加 12），答案偏大。
4. **只有右孩子的链** `root = [1,null,2,null,3]` → 期望 `123` → 容易错：递归时只写了 `dfs(node.left)` 忘了右孩子，或先判 `left` 再 `else` 导致右分支被吞。两个 `if` 要独立判断。
5. **深度接近上限** `root` 为深度 10 的链 → 期望是 10 位数拼接 → 容易错：Python 整数无溢出问题，但若用其他语言（如 C++ int）需注意 10 位数可能超 32 位，本题 Python 无此坑，可作为对照记忆点。

## 8. 面试追问与变体（3 条）

1. **追问：不用全局变量，改成返回值版本怎么写？** 思路：`dfs(node, cur)` 返回「以 node 为根的子树中所有根→叶路径（前缀为 cur）对应整数之和」；叶子返回 `cur*10+val`，非叶返回左右子树返回值之和。这样无副作用，便于并行/复用。
2. **追问：如果节点值不限于 0–9，而是任意非负整数，怎么改？** 思路：拼接规则不再是 ×10，而是 ×10^(位数)。需要额外传「当前已拼数字的位数」或改用字符串/列表拼接，复杂度不变但常数变大。
3. **追问：改成求「所有根→叶路径数字的乘积之和」或「最大值」呢？** 思路：骨架完全一样，只把叶子处的 `ans += cur` 换成 `ans *= cur` 或 `ans = max(ans, cur)`；注意乘积版初值应为 1、且空树需特判。

## 9. 举一反三（2-3 道同类题）

- **112. 路径总和**：同样「根→叶路径 + 边遍历边累积」，只是把「拼数字求和」换成「累加节点值判断是否等于 target」，叶子处做等值判断。
- **257. 二叉树的所有路径**：同样枚举根→叶路径，但要求输出路径字符串列表，是本题「暴力版」的直接形态，可用来对照理解「存路径」与「边算边传」的差别。
- **113. 路径总和 II**：在 112 基础上要求返回所有满足条件的路径，需要显式维护路径栈并在回溯时弹出，是「路径信息必须显式存储」的场景，正好反衬本题「路径可编码进一个整数」的巧妙之处。
