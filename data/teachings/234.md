## 1. 一句话本质

判断单链表这条「单向的线」从两端往中间读是否对称——难点不在比较，而在于单链表**只能从头往后走**，没法从尾巴倒着走。

## 2. 读完题的第一反应

**朴素解法**：把链表所有值倒进一个 Python 列表，然后用双指针从列表两头往中间夹，一发现不等就返回 False。这个解法是对的，但空间是 O(n)——你为了「能倒着读」额外造了一份数据。

**卡在哪**：题目进阶明确要求 O(1) 空间。列表方案直接出局。而单链表本身没有 prev 指针，你无法从尾节点往回走，这就是全部矛盾的来源。

**关键观察**：回文比较的本质是「第 i 个元素 == 第 n-1-i 个元素」。既然不能从尾巴倒着走，那就**把后半段原地翻转，让它变成能从中间往后走**。翻转之后，前半段从头往后、后半段（原尾部）也从头往后，两条链同步前进逐个比即可。翻转链表是 O(1) 空间的经典操作，这就是突破口。

注意一个细节：翻转后半段会**破坏原链表结构**。面试里要主动提这一点，严谨的写法在比较完后把后半段翻回去。

## 3. 从暴力到最优

以 `head = [1,2,2,1]` 为例，节点记为 A(1)→B(2)→C(2)→D(1)。

**第一步：找中点（快慢指针）**

slow 每次走 1 步，fast 每次走 2 步。fast 走到头时，slow 正好在中间。

| 轮次 | slow 位置 | fast 位置 |
|---|---|---|
| 初始 | A | A |
| 1 | B | C |
| 2 | C | 越界(None) |

fast 为 None，停。slow 在 C。对 4 个节点，后半段应从 C 开始（长度 2），前半段是 A→B（长度 2）。这里有个易错点：**节点数是奇数还是偶数，后半段的起点不一样**。用「fast 走完时 slow 停在哪」来统一处理：循环条件写 `while fast and fast.next`，结束时 slow 就是后半段起点。对 `[1,2,2,1]`，slow=C，后半段 C→D；对 `[1,2,1]`，走法是 slow:A→B，fast:A→C→None，结束时 slow=B，后半段 B→(只有一个节点)，前半段 A，长度对齐。

**第二步：翻转后半段**

从 slow 开始翻转。C(2)→D(1) 翻成 D(1)→C(2)。中间变量：

- prev=None, cur=C
- 第 1 轮：nxt=D，C.next=prev(None)，prev=C，cur=D
- 第 2 轮：nxt=None，D.next=prev(C)，prev=D，cur=None
- 结束，新头是 prev=D。后半段变成 D→C。

**第三步：双链同步比较**

p1 从原头 A 出发，p2 从新头 D 出发：

- 比 A.val=1 与 D.val=1，相等，各进一步
- 比 B.val=2 与 C.val=2，相等，各进一步
- p2 走到 None（后半段只有 2 个节点），循环结束，返回 True。

**瓶颈怎么被消掉的**：列表方案花 O(n) 空间是为了「能倒着访问」；翻转把「倒着访问」变成「正着访问一条被改造过的链」，空间降到 O(1)。时间仍是 O(n)：找中点 O(n/2)、翻转 O(n/2)、比较 O(n/2)，常数相加还是 O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

设链表长度为 n，后半段起点为 slow（由快慢指针确定），后半段长度 `m = n - (slow 的下标)`，前半段长度 `k = slow 的下标`。快慢指针的性质保证 `m == k`（n 偶数）或 `m == k + 1`（n 奇数，中间那个节点归入后半段，但它自己和自己对称，不影响判断）。

**不变量**：在第 t 轮比较时（t 从 0 开始），p1 指向原链表第 t 个节点，p2 指向原链表第 n-1-t 个节点。

- 初始 t=0：p1 是头节点（第 0 个），p2 是翻转后后半段的头，即原链表最后一个节点（第 n-1 个）。成立。
- 归纳：每轮 p1、p2 各前进一步，t 加 1，p1 到第 t+1 个；p2 在翻转后的链上前进一步，对应原链表倒数第 t+2 个，即第 n-1-(t+1) 个。成立。

循环在 p2 走完（或 p1 走完前半段）时结束，此时已比较了 `min(k, m)` 对，恰好覆盖所有对称位置对，**不漏**（每个 i 与 n-1-i 都比过）也**不重**（每对只比一次）。中途任何一对不等立即返回 False，正确。

## 5. 完整代码（Python）

```python
class Solution:
    def isPalindrome(self, head) -> bool:
        if head is None or head.next is None:
            return True  # 0 或 1 个节点，天然回文

        # 1. 快慢指针找后半段起点
        slow, fast = head, head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
        # 循环结束时 slow 指向后半段第一个节点

        # 2. 翻转后半段
        prev, cur = None, slow
        while cur:
            nxt = cur.next
            cur.next = prev
            prev = cur
            cur = nxt
        # prev 是翻转后后半段的头

        # 3. 双链同步比较
        p1, p2 = head, prev
        ok = True
        while p2:  # 后半段较短或等长，以它为准
            if p1.val != p2.val:
                ok = False
                break
            p1 = p1.next
            p2 = p2.next

        # 4. 还原后半段（面试加分项，保持输入不被破坏）
        prev, cur = None, prev
        while cur:
            nxt = cur.next
            cur.next = prev
            prev = cur
            cur = nxt

        return ok
```

关键逻辑注释已在代码中。第 3 步循环条件用 `while p2` 而不是 `while p1 and p2`：因为后半段长度 ≥ 前半段，p2 先或同时走完，用 p2 做条件即可，奇数长度时中间节点会被 p2 自己覆盖到，不参与比较也无妨。

## 6. 复杂度

- **时间 O(n)**：找中点循环走 n/2 步；翻转后半段走 m ≈ n/2 步；比较走 min(k,m) ≈ n/2 步；还原再走 n/2 步。四段相加是 2n 量级，常数忽略，O(n)。没有任何 log 项——本题不涉及分治或树结构。
- **空间 O(1)**：只用了 slow、fast、prev、cur、nxt、p1、p2 这几个指针变量，数量固定，与 n 无关。递归写法（用调用栈模拟倒序）会是 O(n) 空间，本题最优解刻意避开递归。

## 7. 边界与反例（至少 4 条）

1. **输入 `[1]`** → 期望 True → 易错点：快慢指针循环 `while fast and fast.next` 对单节点直接不进循环，slow 停在头节点，翻转后 p2 指向该节点，比较 1==1 通过。若忘了开头的 `head.next is None` 提前返回，逻辑也能跑通，但多做了翻转，容易在还原时写错。
2. **输入 `[1,2]`** → 期望 False → 易错点：slow 走到第 2 个节点，后半段只有 `[2]`，翻转后 p2 指向 2；p1 指向 1，1≠2 返回 False。若把后半段起点错写成 `slow.next`，后半段为空，循环不执行，会误判 True。
3. **输入 `[1,2,1]`** → 期望 True → 易错点：奇数长度，slow 停在中间节点 2，后半段是 `[2,1]`（含中间节点），翻转成 `[1,2]`；p1 从 1 出发比 1、比 2，p2 走完结束，返回 True。若错误地让后半段从 `slow.next` 开始，会漏掉中间节点，长度不匹配但恰好也能过——这是「碰巧对」的陷阱，换 `[1,2,3]` 就暴露。
4. **输入 `[1,1,1,1]`** → 期望 True → 易错点：全相等时任何比较都通过，测不出逻辑错误；要配合 `[1,1,2,1]`（期望 False）一起测，后者能在第 2 轮比较时暴露 p1/p2 对齐错误。
5. **输入 `[1,2,2,1,3]`** → 期望 False → 易错点：n=5 奇数，slow 停在第 3 个节点 2，后半段 `[2,1,3]` 翻转成 `[3,1,2]`；p1 从 1 比 3，立刻不等返回 False。这条用来验证「中间节点归后半段」的处理是否一致。

## 8. 面试追问与变体（3 条）

1. **追问：不还原后半段行不行？** 思路：算法正确性不受影响，但会破坏调用方持有的链表，工程上算副作用。回答时说明「能过题，但生产代码应还原」，并现场补上还原代码，体现严谨性。
2. **追问：如果链表带环怎么办？** 思路：回文的前提是线性结构，带环链表无「尾」可言，需先判环（快慢指针相遇即环），有环直接返回 False 或按题意报错，再进入本流程。
3. **追问：改成判断「两个链表是否互为回文」/ 双向链表怎么做？** 思路：双向链表有 prev 指针，直接双指针从两头夹，O(1) 空间且不破坏结构，比单链表更简单——这反过来说明本题的难点纯粹来自「单向」这一约束。

- **链表的中间结点（LeetCode 876）**：本题第一步的快慢指针就是它，共同点是「fast 走两步、slow 走一步」定位中点，是链表分段的通用手法。
- **重排链表（LeetCode 143）**：把「找中点 + 翻转后半段 + 交替合并」三步串起来，和本题共享前两步，是同一套工具的组合应用题。
