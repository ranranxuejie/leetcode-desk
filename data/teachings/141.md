## 1. 一句话本质

判断一个单向链表在沿着 `next` 走的过程中，会不会**回到已经走过的节点**——也就是「走的路是不是无限循环」。

## 2. 读完题的第一反应

**朴素解法**：从 `head` 出发，用一个集合 `visited` 记录走过的每个节点对象，每走一步先查集合：如果当前节点已在集合里，说明回到了走过的点，有环；否则加入集合继续走；走到 `None` 说明没环。

它卡在哪？**空间**。集合最坏要存下全部 n 个节点，空间 O(n)。题目进阶明确要求 O(1) 内存，所以这个解法虽然正确，但拿不到「最优」。

**关键观察**：我们不需要记住「哪些节点走过」，只需要知道「有没有走回头路」。而链表只有一个 `next` 出口，一旦有环，所有进入环的路径最终都会在环里打转。于是问题变成：**两个速度不同的指针，在同一个环里跑，会不会相遇？**

这个观察为什么能引出下一步：如果让一个指针每次走 1 步、另一个每次走 2 步，那么在有环的情况下，快指针会先进入环，然后在环里不断逼近慢指针。由于每轮快指针相对慢指针**净追近 1 步**，而环的长度是有限的，追近的距离迟早会变成 0——也就是相遇。没有环时，快指针会先撞到 `None`，直接返回 false。

这就是 Floyd 判圈算法（龟兔赛跑）。

## 3. 从暴力到最优

**第 0 步（暴力）**：哈希集合记录访问过的节点。时间 O(n)，空间 O(n)。瓶颈在空间。

**第 1 步（消掉空间）**：不再记录「访问过谁」，改成用两个指针的相对运动来检测「是否在绕圈」。空间降到 O(1)。

用示例 1 走一遍：`head = [3,2,0,-4]`，`pos = 1`，即 `-4` 的 `next` 指回索引 1 的节点 `2`。链表结构是 `3 → 2 → 0 → -4 → 2 → 0 → -4 → ...`。

设 `slow = head`（节点 3），`fast = head`（节点 3）。

| 轮次 | slow 走 1 步后 | fast 走 2 步后 | 是否相遇 |
|---|---|---|---|
| 初始 | 3 | 3 | 是（但这是起点，不能算，所以循环体先动再判） |
| 1 | 2 | 0 | 否 |
| 2 | 0 | 2 | 否 |
| 3 | -4 | -4 | **是** → 返回 true |

注意第 3 轮：slow 从 0 走到 -4；fast 从 2 走两步：2 → 0 → -4。两者都落在 -4，相遇。

再看示例 3：`head = [1]`，`pos = -1`，即 `1 → None`。

- 初始 `slow = fast = 节点1`。
- 第 1 轮：`fast.next` 是 `None`，`fast.next.next` 会报错，所以循环条件里要先检查 `fast` 和 `fast.next` 非空。检查发现 `fast.next is None`，退出循环，返回 false。

**为什么快指针走 2 步而不是 3 步？** 走 2 步时，快慢指针在环内的相对速度是 1 步/轮，追近过程是「每次缩短 1」，一定能追到 0。如果走 3 步，相对速度是 2 步/轮，当环长为偶数时可能永远跳过慢指针（相对位置在奇偶之间跳变），虽然理论上换一种分析也能证明最终会相遇，但「走 2 步」是最简单、最容易讲清楚的选择。这是本题的标准做法。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：在每一轮循环开始时，`slow` 和 `fast` 都指向链表中真实存在的节点（非 `None`），且 `fast` 在链表中走过的步数是 `slow` 的两倍。

**无环情况（不会漏判为 true）**：链表长度有限，`fast` 每轮前进 2 步，必然在有限轮内到达末尾。循环条件 `while fast and fast.next` 保证一旦 `fast` 或 `fast.next` 为 `None` 就退出，返回 false。因为无环链表的 `next` 链最终一定终止于 `None`，所以不会误判。

**有环情况（不会漏判为 false）**：设环长为 L。`fast` 先进入环，`slow` 后进入。当 `slow` 刚进入环时，设 `fast` 在环内领先 `slow` 的距离为 d（0 ≤ d < L，d 是沿 `next` 方向从 slow 到 fast 的步数）。之后每轮，`fast` 相对 `slow` 多走 1 步，所以 d 每轮减 1（模 L）。由于 d 是整数且每轮严格递减 1，经过 d 轮后 d 变为 0，即两指针重合。因此有环时一定会在有限轮内相遇，返回 true。

**不会「重」**：我们只判断「是否相遇」，相遇即证明有环，不存在把无环误判成有环的情况——因为无环时 `fast` 根本到不了「绕回来」的状态，它只会撞 `None`。

两个方向合起来：有环 ⇔ 两指针相遇。算法返回 true 当且仅当有环。

## 5. 完整代码（Python）

```python
class ListNode:
    def __init__(self, x):
        self.val = x
        self.next = None


class Solution:
    def hasCycle(self, head: ListNode, pos: int = -1) -> bool:
        # pos 只是评测系统用来构造环的标记，不参与判断；
        # 真实输入中环已经通过 next 指针建好了，这里直接忽略 pos。
        if head is None or head.next is None:
            # 0 个或 1 个节点不可能成环（单节点自环在本题构造下也不会出现，
            # 但即便出现，下面的循环也能处理；这里提前返回只是省事）
            return False

        slow = head          # 慢指针，每轮走 1 步
        fast = head          # 快指针，每轮走 2 步

        # 循环条件：fast 和 fast.next 都必须存在，
        # 否则 fast 走两步会越界（访问 None.next）
        while fast is not None and fast.next is not None:
            slow = slow.next          # 慢指针前进一步
            fast = fast.next.next     # 快指针前进两步

            if slow is fast:
                # 两指针在环内相遇，说明存在环
                return True

        # fast 走到了链表末尾，说明没有环
        return False
```

说明：题面给的签名是 `hasCycle(head, pos)`，但力扣实际调用时 `pos` 不传，环是通过 `next` 指针在内部构造好的。上面的代码保留 `pos` 参数并默认 `-1`，兼容两种调用方式，逻辑上完全忽略它。

## 6. 复杂度

**时间 O(n)**，n 是链表节点数。推导：无环时，`fast` 每轮走 2 步，最多走 n 步到达末尾，所以循环最多约 n/2 轮，每轮 O(1)。有环时，`slow` 进入环之前最多走 n 步；进入环后，`fast` 追 `slow` 最多再走 L 轮（L 为环长，L ≤ n）。总轮数 O(n)，每轮 O(1)，合计 O(n)。这里没有 log 项，因为没有任何「折半」操作。

**空间 O(1)**。只用了 `slow`、`fast` 两个指针变量，与 n 无关。对比哈希集合法是 O(n)，这正是进阶要求消掉的部分。

## 7. 边界与反例（至少 4 条）

1. **空链表** `head = None` → 期望 `false` → 容易错：直接写 `slow = head; fast = head` 后进循环，`fast.next` 会抛 `AttributeError`。代码里用 `head is None` 提前拦截，或循环条件 `fast and fast.next` 也能兜住（`fast` 为 `None` 时短路）。

2. **单节点无环** `head = [1], pos = -1` → 期望 `false` → 容易错：`fast.next` 是 `None`，若循环条件只写 `while fast:`，进入循环后 `fast.next.next` 会崩。必须同时检查 `fast.next`。

3. **单节点自环** `head = [1]`，`1.next = 1`（pos = 0）→ 期望 `true` → 容易错：如果像上面那样用 `head.next is None` 提前返回 false，就会误判。注意：力扣本题的构造中单节点自环是合法的（pos 可以是 0），所以提前返回 `head.next is None` 其实有风险。更稳妥的写法是去掉这个提前返回，只保留 `head is None` 的判断，让主循环处理。这是本题一个真实的坑。

4. **环在尾部** `head = [1,2], pos = 1`，即 `2.next = 2` → 期望 `true` → 容易错：`slow` 走到 2 后，`fast` 也在 2 附近打转，若循环条件或指针更新顺序写反（先判后动 vs 先动后判），可能漏掉相遇。标准写法是「先动再判」，且初始时两指针同点不算相遇。

5. **两节点成环** `head = [1,2], pos = 0`，即 `2.next = 1` → 期望 `true` → 容易错：环长 2，`fast` 相对速度 1，第 1 轮 slow 到 2、fast 到 2（1→2→1 走两步回到 2？实际是 1→2→1，落在 1；需仔细算）。这类小环最容易在手动模拟时算错，建议用代码跑。

## 8. 面试追问与变体（3 条）

1. **追问：如果有环，怎么找到环的入口节点？** 思路：相遇后，把一个指针放回 `head`，两个指针都改成每次走 1 步，再次相遇的位置就是环入口。原理是「头到入口的距离」等于「相遇点到入口的距离」（绕环若干圈意义下）。

2. **追问：怎么求环的长度？** 思路：在相遇点固定一个指针，另一个指针继续每次走 1 步，再次回到相遇点所走的步数就是环长。

3. **追问：不用快慢指针，还能 O(1) 空间判环吗？** 思路：可以「标记法」——遍历时把节点的 `val` 改成一个特殊标记（如超出值域的数），遇到已标记的节点即有环；但这会破坏数据，且依赖值域，不如 Floyd 干净。面试中一般答 Floyd 即可。

## 9. 举一反三（2-3 道同类题）

1. **142. 环形链表 II**：同样用快慢指针，但要求返回环的入口节点，是本题的直接升级——共同点是都用「快慢指针在环内相遇」这一核心机制。

2. **287. 寻找重复数**：把数组下标和值看成 `next` 指针，数组就变成一条带环的链表，用 Floyd 判圈找重复数——共同点是把「判环」抽象成「指针沿 next 走是否回头」。

3. **202. 快乐数**：不断对各位数字平方求和，若最终回到 1 则快乐，若陷入循环则不快乐——共同点是用快慢指针检测「迭代过程是否进入环」，避免用集合存历史。
