## 1. 一句话本质

把数字串切成若干段，每段长度只能是 1 或 2，且切出的每段必须落在 1~26 的合法编码区间内，求合法切法的总数。

## 2. 读完题的第一反应

**朴素解法**：枚举所有切分方式。每个位置可以选择「切一刀」或「不切」，最多 2^(n-1) 种切法，对每种切法再检查每段是否合法。n=100 时这是天文数字，直接爆炸。

**关键观察**：切分是**从左往右逐位推进**的，而且第 i 位的切法只取决于「前面已经切到哪」。更具体地说，当我们处理到位置 i 时，能影响当前决策的信息只有两样：`s[i]` 本身（能不能单独成段），以及 `s[i-1:i+1]` 这个两位数（能不能合并成段）。**再往前的字符怎么切的，对「从 i 往后有几种切法」毫无影响**——这就是无后效性，是动态规划的入场券。

一旦确认「后缀的答案只依赖起点」，问题就变成：定义 `dp[i]` = 从第 i 位开始到末尾的解码方法数，然后找 `dp[i]` 和 `dp[i+1]`、`dp[i+2]` 的递推关系。

## 3. 从暴力到最优

**第一步：暴力枚举 + 剪枝**

从位置 0 出发做 DFS：每步尝试「取 1 位」和「取 2 位」，取到末尾就计数 +1。剪枝条件是取出的段必须合法（1~9 或 10~26）。以 `s = "226"` 为例：

```
dfs(0):
  取"2" 合法 → dfs(1)
    取"2" 合法 → dfs(2)
      取"6" 合法 → dfs(3) 到达末尾，count=1   → "BBF"
    取"26" 合法 → dfs(3) 到达末尾，count=2     → "BZ"
  取"22" 合法 → dfs(2)
    取"6" 合法 → dfs(3) 到达末尾，count=3      → "VF"
```

结果是 3，正确。但注意 `dfs(2)` 被调用了两次（一次从 `dfs(1)` 取"2"来，一次从 `dfs(0)` 取"22"来），每次都把「从 2 到末尾有几种切法」重算一遍。n 大时这种重复子问题会指数级膨胀——这就是瓶颈。

**第二步：记忆化，消掉重复**

给 `dfs(i)` 加个缓存：`memo[i]` 记录「从 i 到末尾的切法数」。还是 `"226"`：

- `dfs(3) = 1`（空串算一种切法，作为递归基）
- `dfs(2)`：取"6" → `dfs(3)=1`，合计 1
- `dfs(1)`：取"2" → `dfs(2)=1`；取"26" → `dfs(3)=1`，合计 2
- `dfs(0)`：取"2" → `dfs(1)=2`；取"22" → `dfs(2)=1`，合计 3

每个 `dfs(i)` 只算一次，复杂度降到 O(n)。

**第三步：改成自底向上的 DP**

记忆化是从右往左递归，改成从右往左迭代就是标准 DP。定义 `dp[i]` = 从 i 到末尾的切法数，`dp[n] = 1`（空后缀视为一种切法，这是递推的种子）。递推：

```
dp[i] = (s[i] != '0' ? dp[i+1] : 0)              # 单独取 1 位
      + (10 <= int(s[i:i+2]) <= 26 ? dp[i+2] : 0) # 合并取 2 位
```

`"226"` 的 dp 数组从右往左填：

| i | s[i] | 单取贡献 | 双取贡献 | dp[i] |
|---|------|---------|---------|-------|
| 3 | — | — | — | 1（种子） |
| 2 | '6' | dp[3]=1 | 越界，0 | 1 |
| 1 | '2' | dp[2]=1 | "26"合法，dp[3]=1 | 2 |
| 0 | '2' | dp[1]=2 | "22"合法，dp[2]=1 | 3 |

答案 `dp[0] = 3`，和暴力一致。

**第四步：滚动变量**

`dp[i]` 只依赖 `dp[i+1]` 和 `dp[i+2]`，所以两个变量就够，空间从 O(n) 降到 O(1)。这是可选的优化，面试时先写数组版讲清楚，再提滚动版加分。

## 4. 正确性：为什么不会漏、不会重

**不变量**：对任意 i ∈ [0, n]，`dp[i]` 恰好等于「后缀 `s[i:]` 的合法切法总数」。

**归纳证明**（从右往左）：

- **基础**：`dp[n] = 1`。空后缀只有「什么都不切」这一种切法，定义上成立。
- **归纳步**：假设对 i+1、i+2 成立，考察 `s[i:]` 的任意一种合法切法。它的**第一段**只有两种可能：长度 1（就是 `s[i]`）或长度 2（就是 `s[i:i+2]`），不可能更长，因为编码最大是 26，两位封顶。
  - 若第一段长 1：合法当且仅当 `s[i] != '0'`，剩余部分 `s[i+1:]` 的切法数由归纳假设是 `dp[i+1]`。
  - 若第一段长 2：合法当且仅当 `10 <= int(s[i:i+2]) <= 26`（这个区间同时排除了前导零，因为 `"06"` 转成 6 小于 10），剩余部分切法数是 `dp[i+2]`。
  - 这两类按「第一段长度」划分，**互斥且穷尽**，所以相加既不漏也不重。

**为什么前导零被自然处理**：`s[i] == '0'` 时单取贡献为 0；而 `"0x"` 形式的两位数一定小于 10，双取贡献也为 0。两个分支同时归零，`dp[i] = 0`，正好对应「以 0 开头的段无法解码」。不需要额外写特判。

## 5. 完整代码（Python）

```python
class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)
        # dp[i] 表示后缀 s[i:] 的解码方法数
        # dp[n] = 1：空后缀视为一种切法，作为递推种子
        dp = [0] * (n + 1)
        dp[n] = 1

        # 从右往左填表，因为 dp[i] 依赖 dp[i+1] 和 dp[i+2]
        for i in range(n - 1, -1, -1):
            # 分支一：s[i] 单独成段，'0' 不能单独解码
            if s[i] != '0':
                dp[i] += dp[i + 1]

            # 分支二：s[i:i+2] 合并成段，必须落在 10~26
            # 注意这里用字符串比较前先判 i+1 < n，防止越界
            if i + 1 < n and 10 <= int(s[i:i + 2]) <= 26:
                dp[i] += dp[i + 2]

        return dp[0]
```

滚动变量版（空间 O(1)），逻辑完全等价，只是把数组换成两个变量：

```python
class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)
        # prev2 对应 dp[i+2]，prev1 对应 dp[i+1]
        # 初始时 i = n-1，dp[n] = 1（prev1），dp[n+1] 不存在但不会被用到
        prev2, prev1 = 0, 1
        for i in range(n - 1, -1, -1):
            cur = 0
            if s[i] != '0':
                cur += prev1
            if i + 1 < n and 10 <= int(s[i:i + 2]) <= 26:
                cur += prev2
            prev2, prev1 = prev1, cur
        return prev1
```

## 6. 复杂度

**时间 O(n)**：循环体执行 n 次，每次做常数次操作——一次字符比较、一次两位子串的 `int()` 转换（长度固定为 2，是 O(1)）、两次加法。n 来自字符串长度，没有 log 项，因为不存在二分或按位分解。

**空间 O(n)**：`dp` 数组长度 n+1。若用滚动变量版则降为 **O(1)**，只存两个整数。递归记忆化版的空间是 O(n) 的栈 + O(n) 的缓存，不如迭代版。

## 7. 边界与反例（至少 4 条）

1. **`s = "0"` → 0**。容易错在把 `'0'` 当成合法单字符，或忘记 `dp[n]=1` 的种子导致返回 1。实际 `s[0]=='0'` 单取贡献 0，双取越界，`dp[0]=0`。
2. **`s = "06"` → 0**。容易错在把 `"06"` 当成 6 来解码。`int("06")=6 < 10`，双取不合法；`s[0]=='0'` 单取也不合法，两个分支同时归零。
3. **`s = "10"` → 1**。容易错在只看到 `'1'` 合法就返回 2。实际 `s[1]=='0'` 使 `dp[1]=0`，只有 `"10"` 合并这一条路，答案是 1。
4. **`s = "100"` → 0**。`"10"` 合法但剩下 `"0"` 无法单独解码，`dp[2]=0` 传染到 `dp[1]=0`，最终 `dp[0]=0`。容易错在只看局部合法就累加。
5. **`s = "27"` → 1**。`"27" > 26`，双取不合法，只能 `"2"+"7"`。容易错在把上界写成 `< 27` 之外的宽松条件，或漏掉 26 这个边界。
6. **`s = "1"` → 1**。最小长度，验证 `dp[n]=1` 种子是否让单字符正确返回 1，而不是 0。

## 8. 面试追问与变体（3 条）

1. **追问：如果编码表不是 1~26，而是任意给定的字符串数组（比如 `["a","ab","abc"]`），怎么改？**
   思路：把「长度只能是 1 或 2」放宽为「长度是编码表里出现过的所有长度」，`dp[i]` 对每个合法长度 L 累加 `dp[i+L]`，复杂度变成 O(n·maxLen)。

2. **追问：要求返回任意一种具体的解码方案，而不只是数量。**
   思路：在 DP 表上从 `dp[0]` 出发做一次回溯，每步选一个「使 `dp[i] == dp[i+L]` 成立」的合法段，沿路收集字符即可，O(n) 构造。

3. **追问：如果允许 `'*'` 通配 1~9 任意数字（对应力扣 639），怎么处理？**
   思路：递推结构不变，只是单取和双取的合法性判断要按 `'*'` 展开成多种情况分别计数，注意 `'*'` 与 `'0'`、`'1'`、`'2'` 组合时的分支要分类讨论，且答案要取模。
