## 1. 一句话本质

给定若干条「区间加」操作（对 `[first, last]` 这一段整体加上 `seats`），求所有操作叠加后每个位置上的最终值。

## 2. 读完题的第一反应

**朴素解法**：对每条预订记录，用一层 for 循环把 `answer[first-1 .. last-1]` 逐个加上 `seats`。

它卡在哪？看数据范围：`bookings.length` 最多 2×10⁴，每条区间最长可覆盖 n = 2×10⁴ 个航班。最坏情况是每条记录都覆盖整个区间，总操作量 2×10⁴ × 2×10⁴ = 4×10⁸，Python 里这个量级基本会超时。瓶颈在于：**每条记录都要「真的」去碰区间里的每一个位置**，而区间可能很长。

**关键观察**：我们真正在意的不是「中间过程每个位置被加了几次」，而是**最终值**。而一个区间加操作，对最终数组的影响可以拆成两个「边界事件」：

- 在 `first` 处，从这里开始，后面的值都多了 `seats`；
- 在 `last+1` 处，从这里开始，这个 `seats` 的增量消失了。

也就是说，**区间的「内部」是均匀的，信息只集中在两个端点上**。只要记录下每个位置「相对于前一个位置变化了多少」，最后从头累加一遍，就能还原出每个位置的绝对值。这就是差分数组的思想，也是前缀和的逆运算。

## 3. 从暴力到最优

### 暴力版

```python
ans = [0] * n
for first, last, seats in bookings:
    for i in range(first - 1, last):   # 注意转 0-index
        ans[i] += seats
```

用示例 1 走一遍：`bookings = [[1,2,10],[2,3,20],[2,5,25]], n = 5`。

- 第 1 条：`ans = [10, 10, 0, 0, 0]`
- 第 2 条：`ans = [10, 30, 20, 0, 0]`
- 第 3 条：`ans = [10, 55, 45, 25, 25]`

结果对，但每条记录内层循环长度是 `last - first + 1`，最坏 O(n)。

### 差分版

维护一个差分数组 `diff`，长度 `n+1`（多留一位当「哨兵」，方便处理 `last == n` 时 `last+1` 越界）。对每条记录：

- `diff[first-1] += seats`
- `diff[last] -= seats`（因为 `last` 是 1-index，`last+1` 对应 0-index 的 `last`）

然后对 `diff` 做前缀和，`answer[i] = diff[0] + ... + diff[i]`。

同样用示例 1，`n = 5`，`diff` 初始 `[0,0,0,0,0,0]`：

- 记录 `[1,2,10]`：`diff[0] += 10`，`diff[2] -= 10` → `[10, 0, -10, 0, 0, 0]`
- 记录 `[2,3,20]`：`diff[1] += 20`，`diff[3] -= 20` → `[10, 20, -10, -20, 0, 0]`
- 记录 `[2,5,25]`：`diff[1] += 25`，`diff[5] -= 25` → `[10, 45, -10, -20, 0, -25]`

前缀和：

- `i=0`：10
- `i=1`：10+45 = 55
- `i=2`：55-10 = 45
- `i=3`：45-20 = 25
- `i=4`：25+0 = 25

得到 `[10, 55, 45, 25, 25]`，与暴力一致。

**瓶颈怎么被消掉的**：原来每条记录要碰 O(区间长度) 个位置，现在每条记录只碰 **2 个位置**（两个端点），把「区间更新」降成了「点更新」。代价是最后要花 O(n) 做一次前缀和还原——但这一次是全局的、只做一遍，而不是每条记录做一遍。总复杂度从 O(记录数 × n) 降到 O(记录数 + n)。

## 4. 正确性：为什么不会漏、不会重

用**差分数组的定义 + 前缀和还原**来论证，核心是一个不变量。

**定义**：设最终答案数组为 `A`（0-index），定义差分数组 `D` 满足：

- `D[0] = A[0]`
- `D[i] = A[i] - A[i-1]`（i ≥ 1）

那么反过来，`A[i] = D[0] + D[1] + ... + D[i]`，即 `A` 是 `D` 的前缀和。这是恒等式，与怎么构造 `D` 无关。

**不变量**：在处理完任意前 k 条预订记录后，我们维护的 `diff` 数组，恰好等于「前 k 条记录叠加后的答案数组」的差分数组。

**归纳证明**：

- k = 0 时，没有任何预订，答案全 0，差分也全 0，成立。
- 假设处理完前 k-1 条后不变量成立。现在加入第 k 条 `[first, last, seats]`，它让 `A[first-1 .. last-1]` 每个元素都加 `seats`，其余不变。看差分数组会怎么变：
  - `D[first-1] = A[first-1] - A[first-2]`：`A[first-1]` 加了 `seats`，`A[first-2]` 没变，所以 `D[first-1]` 增加 `seats`。
  - 对 `first ≤ i ≤ last-1`：`A[i]` 和 `A[i-1]` 都加了 `seats`，差值不变，`D[i]` 不变。
  - `D[last] = A[last] - A[last-1]`：`A[last]` 没变，`A[last-1]` 加了 `seats`，所以 `D[last]` 减少 `seats`。
  - 其余位置不变。

  这正好对应代码里的 `diff[first-1] += seats; diff[last] -= seats`。所以处理完第 k 条后不变量仍成立。

归纳完毕，处理完所有记录后 `diff` 就是最终答案的差分数组，前缀和还原即得 `A`。

**为什么不会漏**：区间内每个位置都受到 `seats` 的影响，而差分只在两个端点记录变化，中间位置靠前缀和「继承」左端点的增量，一个都不会漏。
**为什么不会重**：每条记录只改两个端点，不同记录改的是各自端点，加法满足交换律和结合律，叠加顺序不影响结果；前缀和只累加一次，不会把同一条记录的贡献算两遍。

## 5. 完整代码（Python）

```python
from typing import List

class Solution:
    def corpFlightBookings(self, bookings: List[List[int]], n: int) -> List[int]:
        # 差分数组，多开一位 n+1，作为 last == n 时 last+1 的哨兵位
        diff = [0] * (n + 1)

        for first, last, seats in bookings:
            # 题目是 1-index，转成 0-index：
            # 区间 [first, last] 对应下标 [first-1, last-1]
            diff[first - 1] += seats      # 从 first-1 开始，增量出现
            diff[last] -= seats           # 从 last 开始（即 last-1 的下一位），增量消失

        # 对差分数组做前缀和，还原每个航班的最终座位数
        ans = [0] * n
        running = 0
        for i in range(n):
            running += diff[i]
            ans[i] = running

        return ans
```

关键点说明：

- `diff` 长度取 `n+1` 而不是 `n`，是因为 `last` 可能等于 `n`，此时 `diff[last]` 就是 `diff[n]`，需要这一位存在。它不参与最终答案（循环只到 `n-1`），只用来「关掉」增量。
- `running` 是滚动前缀和，避免再开一个数组或反复切片求和。

## 6. 复杂度

设 `m = len(bookings)`，`n` 为航班数。

- **时间**：O(m + n)。
  - 遍历 `bookings` 一次，每条记录做两次加法，贡献 O(m)。
  - 前缀和循环一次，贡献 O(n)。
  - 没有 log 项：本题不涉及排序、二分或树结构，所以复杂度里不出现 log n。
- **空间**：O(n)。
  - `diff` 长度 `n+1`，`ans` 长度 `n`，都是 O(n)。
  - 若把前缀和直接写回 `diff` 并返回 `diff[:n]`，可省掉 `ans`，但仍是 O(n) 量级（返回值本身就要 O(n)）。
  - 除输入输出外，额外辅助空间是 O(n)（差分数组），这是必要的，因为要存每个位置的累计增量。

对比暴力：暴力时间 O(m × 平均区间长度)，最坏 O(m·n) = 4×10⁸；差分是 O(m + n) ≈ 4×10⁴，差了四个数量级。

## 7. 边界与反例（至少 4 条）

1. **单点区间**：`bookings = [[2,2,15]], n = 2` → 期望 `[0, 15]`。
   容易错：把 `diff[last] -= seats` 写成 `diff[last-1] -= seats`，会把增量在起点就抵消掉，结果全 0。`last` 是 1-index，减 seats 的位置是 0-index 的 `last`，不是 `last-1`。

2. **区间覆盖到末尾**：`bookings = [[1,5,10]], n = 5` → 期望 `[10,10,10,10,10]`。
   容易错：`diff` 只开 `n` 长度，`diff[5]` 越界报 IndexError。必须开 `n+1`。

3. **区间从 1 开始**：`bookings = [[1,1,7]], n = 3` → 期望 `[7,0,0]`。
   容易错：忘记 1-index 转 0-index，写成 `diff[first] += seats`，增量从第 2 个航班才开始，答案整体右移一位。

4. **多条记录完全重叠**：`bookings = [[1,3,5],[1,3,5],[1,3,5]], n = 3` → 期望 `[15,15,15]`。
   容易错：以为要「去重」或「取最大」，实际是累加。差分天然支持重复叠加，不需要特殊处理。

5. **n = 1**：`bookings = [[1,1,10000]], n = 1` → 期望 `[10000]`。
   容易错：`diff` 开成 `n+1 = 2`，循环 `range(n)` 只走 `i=0`，`diff[1]` 的 `-10000` 不参与结果，正确；但若循环写成 `range(n+1)` 再截取，可能把哨兵位算进答案。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求支持「区间赋值」而不是「区间加」，还能用差分吗？**
   思路：普通差分只能处理可减的运算（加法）。区间赋值需要「区间染色」类结构（如线段树带 lazy 标记，或倒序处理 + 并查集跳过已赋值位置），不能直接套本题差分。

2. **追问：如果 bookings 是流式到来的，随时可能查询某个航班的当前座位数，怎么做？**
   思路：用树状数组（Fenwick）维护差分数组，区间加变成两次单点更新，单点查询变成前缀和查询，每次操作 O(log n)。这是本题差分的「在线化」版本。

3. **追问：如果 n 很大（比如 10⁹）但 bookings 很少，怎么省空间？**
   思路：只对出现过的端点做坐标压缩（离散化），把端点排序后建差分，最后按压缩后的区间长度展开或直接回答查询。空间从 O(n) 降到 O(m)。
