## 1. 一句话本质

统计每个元素的出现次数，然后从「次数」这个维度上挑出最大的 k 个，返回它们对应的元素。

注意这句话的重心：**排序的对象不是元素本身，而是元素的频率**。这是整道题所有解法的分水岭。

## 2. 读完题的第一反应

**朴素解法**：先遍历一遍用哈希表数出每个元素的频率，然后把 `(元素, 频率)` 这些对按频率降序排序，取前 k 个。

这个解法是对的，卡点也很明确：排序是 O(m log m)，m 是不同元素的个数，最坏 m = n，于是整体 O(n log n)。而题面「进阶」明确要求**优于 O(n log n)**，所以排序这一步必须被干掉。

**关键观察**：我们不需要「完整有序」，只需要「前 k 大」。这两件事的代价差一个量级——完整排序必须确定所有元素之间的相对次序，而「前 k 大」只需要保证：**选出来的 k 个，每一个都不比没选上的任何一个小**。剩下 k 个内部谁大谁小、没选上的内部怎么排，都无所谓。

这个「只要偏序不要全序」的观察，直接指向两条路：

- 用**大小为 k 的小顶堆**维护「当前见过的最大的 k 个」，堆顶是这 k 个里最小的，新元素只要比堆顶大就替换掉它。代价 O(m log k)。
- 用**桶排序**：频率的取值范围被题面锁死了——`1 <= nums.length <= 10^5`，所以任何元素的频率必然落在 `[1, n]`。既然值域是线性的，就可以开 n+1 个桶，把「按频率排序」变成「按频率下标直接落桶」，代价 O(n)。

两条路都能突破 O(n log n)。下面主推桶排序，因为它更简单、更快，而且「值域有限所以能开桶」这个思维在面试里非常值钱。

## 3. 从暴力到最优

用示例 3 走一遍：`nums = [1,2,1,2,1,2,3,1,3,2], k = 2`。

**第一步：数频率（所有解法共用）**

遍历一遍，得到 `freq = {1: 4, 2: 4, 3: 2}`。这一步 O(n)，谁也省不掉——不数频率就无从谈「高频」。

**第二步（暴力）：排序**

把 `freq.items()` 变成 `[(1,4), (2,4), (3,2)]`，按频率降序排，得 `[(1,4), (2,4), (3,2)]`，取前 2 个元素 `[1,2]`。

瓶颈：m 个不同元素要 O(m log m)。这里 m=3 看不出痛，但 m 可以到 10^5。

**第二步（堆）：大小为 k 的小顶堆**

k=2，维护一个最多装 2 个 `(频率, 元素)` 的小顶堆：

- 放入 `(4,1)` → 堆：`[(4,1)]`
- 放入 `(4,2)` → 堆：`[(4,1),(4,2)]`，堆顶是 `(4,1)`
- 处理 `(2,3)`：堆已满，比较 `2 > 堆顶频率 4`？否，丢弃。

最终堆里是 `(4,1),(4,2)`，取出元素得 `[1,2]`。代价 O(m log k)，当 k 远小于 m 时明显优于排序。

**第二步（桶）：值域落桶**

频率最大是 4（= n 的下界附近），开 `n+1 = 11` 个桶，但实际只用下标 0..4：

- `freq=4` 的元素有 1、2 → `buckets[4] = [1,2]`
- `freq=2` 的元素有 3 → `buckets[2] = [3]`
- 其余桶为空

然后**从大到小**扫桶下标：`i=4` 拿到 `[1,2]`，已凑够 2 个，停。答案 `[1,2]`。

这里的关键动作是「从大到小扫」——因为桶下标就是频率，倒着扫天然就是频率降序，**根本不需要比较**。这就是桶排序干掉 log 因子的地方：它用「下标即键」把排序变成了寻址。

## 4. 正确性：为什么不会漏、不会重

**不漏**：设真实答案集合为 S（频率前 k 大的元素集合）。对 S 中任一元素 x，它的频率 f(x) 满足 f(x) >= 第 k 大的频率 f_k。倒序扫桶时，我们一定会在扫到下标 f_k 之前（含）就遇到 x 所在的桶，因为 f(x) >= f_k。所以在凑满 k 个之前，S 中每个元素都还没被跳过——不会漏。

**不重**：每个元素在 `freq` 字典里只出现一次，因此只会被 append 进**唯一一个**桶（下标等于它的频率）。扫描时每个桶只被访问一次，所以同一个元素不可能被取两次。

**为什么可以提前停**：题面保证「前 k 个高频元素的集合唯一」。这意味着不存在「第 k 名和第 k+1 名频率相同」的歧义情况——如果存在，答案就不唯一了。所以当我们从高到低累计到恰好 k 个时，这 k 个必然就是唯一的答案集合，后面频率更低的元素不可能挤进来。这条保证是提前 `break` 的合法性来源，不是随手写的优化。

**桶大小的合法性**：频率最大值为 n（所有元素相同），所以开 `n+1` 个桶，下标 0..n 一定装得下，不会越界。这是题面 `1 <= nums.length <= 10^5` 给的底气。

## 5. 完整代码（Python）

```python
from collections import Counter
from typing import List


class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        # 第一步：数频率。Counter 等价于手写字典累加，O(n)
        freq = Counter(nums)

        # 第二步：开桶。频率最大不超过 len(nums)，所以桶数取 n+1 足够
        # buckets[i] 存放「出现 i 次」的所有元素
        n = len(nums)
        buckets = [[] for _ in range(n + 1)]
        for num, cnt in freq.items():
            buckets[cnt].append(num)

        # 第三步：从高频往低频扫桶，凑够 k 个就停
        res = []
        for i in range(n, 0, -1):          # 频率 0 的桶没意义，扫到 1 即可
            for num in buckets[i]:
                res.append(num)
                if len(res) == k:          # 题面保证答案唯一，可安全提前返回
                    return res
        return res                          # 理论上到不了这里，兜底
```

如果面试官要求不用 `Counter`，把第一段换成手写循环即可，逻辑完全一样：

```python
        freq = {}
        for x in nums:
            freq[x] = freq.get(x, 0) + 1
```

## 6. 复杂度

设 n = `len(nums)`，m = 不同元素个数（m <= n）。

**时间 O(n)**，拆开看每一项的来源：

- 数频率：遍历 nums 一次，O(n)。这里的 n 就是数组长度。
- 建桶：`[[] for _ in range(n+1)]` 是 O(n)，因为桶的数量由数组长度决定；往桶里放 m 个元素是 O(m) <= O(n)。
- 扫桶：外层循环最多走 n 次下标，内层总共只 append 了 m 个元素（每个元素只在一个桶里），合计 O(n + m) = O(n)。
- **没有 log 因子**：因为「按频率排序」被「按下标寻址」替代了，比较操作整个消失了。

**空间 O(n)**：

- `freq` 字典存 m 个键值对，O(m) <= O(n)。
- `buckets` 有 n+1 个列表对象，O(n)——这是空间的主要贡献者，也是桶排序的代价：用空间换掉了 log。
- `res` 最多 k 个，O(k) <= O(n)。

对比一下：堆解法是时间 O(n log k)、空间 O(m + k)；桶排序是时间 O(n)、空间 O(n)。桶排序更快但更费空间，面试时把这两句对比说出来，比只报一个复杂度更有说服力。

## 7. 边界与反例（至少 4 条）

1. **`nums = [1], k = 1`** → 期望 `[1]`。容易错在：桶数组开成 `range(n)` 而不是 `range(n+1)`，此时 `buckets[1]` 越界（频率 1 = n = 1，需要下标 1 存在）。这是最常见的 off-by-one。

2. **`nums = [1,1,1,2,2,3], k = 2`** → 期望 `[1,2]`。容易错在：扫桶时写成 `range(n)` 正序扫，会先拿到低频的 3，输出 `[3,2]` 之类的错误结果。必须**倒序**。

3. **`nums = [4,4,4,4], k = 1`** → 期望 `[4]`。容易错在：桶下标只开到最大频率，但最大频率等于 n，若桶数组长度写成 n 则 `buckets[n]` 越界。另外这里 m=1，若代码里假设「至少有两个不同元素」会崩。

4. **`nums = [1,2,3,4], k = 4`**（全不重复，k = m）**→ 期望 `[1,2,3,4]` 的任意顺序**。容易错在：所有频率都是 1，全挤在 `buckets[1]` 里，若内层循环里漏了 `len(res) == k` 的判断或提前 return 位置写错，可能只返回部分元素。这题也提醒：k 可以等于不同元素个数，不能假设 k < m。

5. **`nums` 含负数如 `[-1,-1,2,2,2]`，k = 1** → 期望 `[2]`。容易错在：把元素值当桶下标（负数直接越界）。桶下标必须是**频率**，不是元素值——这是本题最容易混淆的一点。

## 8. 面试追问与变体（3 条）

1. **追问：如果数据是流式的，内存放不下所有元素，怎么办？**
   思路：桶排序要求先知道全部频率，流式场景不适用；改用大小为 k 的小顶堆在线维护，来一个元素更新频率后尝试入堆，空间 O(k + 不同元素数)。

2. **追问：如果要求返回结果按频率降序、同频率按元素值升序排列呢？**
   思路：桶排序天然给出频率降序，只需在往每个桶 append 前对元素排序，或最后对同桶元素排序；也可改用堆并在比较键里加入元素值做 tie-break。

3. **追问：不用额外 O(n) 空间，能不能做到 O(n) 时间？**
   思路：可以用快速选择（quickselect）在 `(元素, 频率)` 数组上按频率做部分划分，平均 O(n) 时间、O(1) 额外空间，代价是最坏 O(n²) 且实现复杂——这正是题目标签里「快速选择」的由来。
