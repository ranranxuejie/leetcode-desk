## 1. 一句话本质

把数组元素分成「加号组」和「减号组」，问有多少种分组方式使两组元素之和之差恰好等于 target。

## 2. 读完题的第一反应

**朴素解法**：每个元素有 2 种符号选择，n 个元素共 2^n 种表达式，全部枚举再验证和是否等于 target。n ≤ 20 时 2^20 ≈ 100 万，勉强能过，但这是指数级，面试官不会满意。

**关键观察**：设加号组元素之和为 P，减号组元素之和为 N，则 P - N = target，且 P + N = sum(nums)（记为 S）。两式相加得 **P = (S + target) / 2**。于是问题变成：从 nums 中选若干元素，使它们的和恰好为 (S+target)/2，问有多少种选法——这是一个**子集和计数**问题，可以用动态规划在多项式时间内解决。

这个转化的价值在于：把「2^n 种符号组合」压成了「一个目标和为 P 的子集选取问题」，状态空间从指数级降到 S 量级（S ≤ 1000）。

## 3. 从暴力到最优

**第一步：暴力回溯。** 对每个元素尝试 + 和 - 两个分支，递归到底部检查累加和是否等于 target。复杂度 O(2^n)，n=20 时约 100 万次递归，能过但不够优雅。

**第二步：数学转化。** 令 P 为取正号的元素和，N 为取负号的元素和。有：
- P - N = target
- P + N = S

解得 P = (S + target) / 2。若 S + target 为奇数或为负数，直接返回 0（因为 P 必须是非负整数）。

**第三步：DP 计数子集和。** 定义 `dp[j]` = 用当前已处理的元素能凑出和为 j 的选法数。初始 `dp[0] = 1`（空集凑出 0 有 1 种方式）。对每个 num，**倒序**更新 `dp[j] += dp[j - num]`（倒序保证每个元素只用一次）。

**小例子走一遍**：nums = [1,1,1,1,1]，target = 3。S = 5，P = (5+3)/2 = 4。求子集和为 4 的选法数。

初始 dp = [1,0,0,0,0]（下标 0~4）。

处理第 1 个 1：倒序 j=4..1，dp[1]+=dp[0] → dp=[1,1,0,0,0]
处理第 2 个 1：dp[2]+=dp[1]=1, dp[1]+=dp[0]=1 → dp=[1,2,1,0,0]
处理第 3 个 1：dp[3]+=dp[2]=1, dp[2]+=dp[1]=2, dp[1]+=dp[0]=1 → dp=[1,3,3,1,0]
处理第 4 个 1：dp[4]+=dp[3]=1, dp[3]+=dp[2]=3, dp[2]+=dp[1]=3, dp[1]+=dp[0]=1 → dp=[1,4,6,4,1]
处理第 5 个 1：dp[4]+=dp[3]=4, dp[3]+=dp[2]=6, dp[2]+=dp[1]=4, dp[1]+=dp[0]=1 → dp=[1,5,10,10,5]

dp[4] = 5，与示例输出一致。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在处理完前 i 个元素后，`dp[j]` 恰好等于「从前 i 个元素中选取子集，使其和等于 j 的选法数」。

**归纳证明**：
- 基础：i=0 时只有空集，dp[0]=1，其余为 0，成立。
- 归纳步：考虑第 i 个元素 num。凑出和 j 的选法分两类——不含 num 的（数量为旧 dp[j]）和含 num 的（数量为旧 dp[j-num]）。两者不交（一个含 num 一个不含），并集覆盖全部。所以新 dp[j] = 旧 dp[j] + 旧 dp[j-num]。倒序遍历保证 dp[j-num] 还是「前 i-1 个元素」的值，没有被本轮污染。

**不漏**：每个子集要么含当前元素要么不含，两类都计入。
**不重**：两类互斥，且每类内部由归纳假设不重。

**与原始问题的对应**：每个子集（加号组）唯一确定一个符号分配（其余为减号），且 P - N = target 当且仅当 P = (S+target)/2。所以子集计数 = 表达式计数，一一对应。

## 5. 完整代码（Python）

```python
class Solution:
    def findTargetSumWays(self, nums, target):
        total = sum(nums)
        # P = (total + target) / 2 必须是合法非负整数
        if (total + target) % 2 != 0 or total + target < 0:
            return 0
        P = (total + target) // 2
        # dp[j] = 凑出和为 j 的选法数
        dp = [0] * (P + 1)
        dp[0] = 1  # 空集凑出 0，1 种方式
        for num in nums:
            # 倒序遍历，保证每个元素只被用一次
            for j in range(P, num - 1, -1):
                dp[j] += dp[j - num]
        return dp[P]
```

关键逻辑说明：
- 奇偶/负数检查：P 必须是整数且非负，否则无解。
- `dp[0]=1`：空集是一种合法选法，这是计数的基准。
- 倒序循环：若正序，`dp[j-num]` 可能已经包含当前 num，导致同一元素被重复使用（变成完全背包）。

## 6. 复杂度

- **时间 O(n · P)**：外层 n 个元素，内层最多 P+1 次更新。P = (S+target)/2 ≤ S ≤ 1000（由题面 sum ≤ 1000 保证），所以最坏约 20 × 1000 = 2 万次操作。
- **空间 O(P)**：一维 dp 数组长度 P+1。没有 log n 项——本题不涉及排序或二分。

对比暴力 O(2^n)：n=20 时约 100 万，DP 快了约 50 倍，且 n 增大时差距指数级拉大。

## 7. 边界与反例

1. **nums=[0], target=0** → 期望 2（"+0" 和 "-0" 都等于 0）。容易错在：认为 0 只有一种符号，或 dp 初始化时忽略空集导致漏算。代码中 dp[0]=1 且 0 会被处理两次贡献，结果正确为 2。
2. **nums=[1], target=2** → 期望 0。S=1，P=(1+2)/2=1.5 非整数，直接返回 0。容易错在：不检查奇偶性，整数除法截断后误算出 1。
3. **nums=[100], target=-200** → 期望 0。S+target = -100 < 0，P 为负无意义。容易错在：只检查奇偶不检查负数，导致数组下标越界或逻辑错误。
4. **nums=[0,0,0,0,0], target=0** → 期望 32（2^5，每个 0 可正可负）。容易错在：dp 更新时正序遍历导致 0 被重复计数，或误以为 0 不贡献方案数。
5. **nums=[1,2,3], target=0** → 期望 2（+1-2+3 和 -1+2-3）。S=6，P=3，子集和为 3 的有 {3} 和 {1,2}，共 2 种。容易错在：忘记验证转化后 P 对应的子集确实能映射回合法表达式。

## 8. 面试追问与变体

1. **追问：如果 nums 长度到 40，sum 到 10^5 怎么办？** 思路：DP 仍可行但 O(n·S) 可能偏大；可考虑 meet-in-the-middle，把数组分两半各枚举 2^20 种子集和，排序后双指针/哈希匹配，O(2^(n/2) log)。
2. **追问：要求输出具体表达式而非数量？** 思路：DP 记录前驱（每个 dp[j] 存来源），回溯重建所有方案；或用 DFS + 记忆化同时收集路径。
3. **追问：每个元素可以用多次（完全背包版）？** 思路：内层改正序遍历即可，dp[j] += dp[j-num] 允许重复使用当前元素。
