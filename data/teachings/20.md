## 1. 一句话本质

判断一个括号序列是否满足「后开先闭」的嵌套结构——也就是每个右括号必须匹配**最近一个尚未闭合**的同类型左括号。

## 2. 读完题的第一反应

**朴素解法**：从左往右扫，遇到右括号就去前面找一个还没配对的同类型左括号。问题在于「找」这个动作——如果每次都要回头扫描，最坏情况是 `"((((...))))"` 这种，每遇到一个 `)` 都要往前找很久，整体退化成 O(n²)。n 到 10⁴ 时 10⁸ 量级，Python 里基本会超时。

**关键观察**：题面第二条「左括号必须以正确的顺序闭合」，加上示例 5 `"([)]"` 判 false，说明匹配关系是**嵌套**而不是**交叉**的。嵌套结构有一个天然性质：**最后出现的未闭合左括号，一定是最先被闭合的那个**。这正是「后进先出」。

一旦意识到「最近未闭合」=「栈顶」，整个问题就变成：扫一遍字符串，左括号入栈，右括号和栈顶比对。回头找的动作被 O(1) 的栈顶访问替代，瓶颈消失。

## 3. 从暴力到最优

**暴力版**：维护一个「已配对」布尔数组，遇到右括号时从当前位置往前线性扫描，找第一个未配对且类型匹配的左括号，标记配对；找不到就返回 false。扫完还要检查是否所有左括号都配对了。

以 `s = "([])"` 为例走一遍：

- i=0 `(`：左括号，先记下位置 0。
- i=1 `[`：左括号，记下位置 1。
- i=2 `]`：右括号，从 i=1 往前找，位置 1 是 `[` 且未配对 → 配对，标记 used[1]=True。
- i=3 `)`：右括号，从 i=2 往前找，位置 1 已用，位置 0 是 `(` 未配对 → 配对。
- 结束，全部配对 → true。

这个例子看着还行，但换成 `"((((((...))))))"`（n/2 个左括号后接 n/2 个右括号），第 k 个右括号要往前扫 k 个位置，总扫描次数 ≈ (n/2)²/2 = O(n²)。瓶颈就在「往前找第一个未配对」这一步。

**优化**：注意暴力版里「往前找第一个未配对」的结果，恰好总是**最靠右的那个未配对左括号**——因为嵌套结构不允许跳过中间未配对的去配更早的（示例 5 就是反例）。既然永远取最靠右的，那就没必要「找」，直接维护一个「最靠右未配对」的指针即可。而这个指针的行为就是栈顶：新左括号压上来成为新的最靠右，右括号消费掉栈顶后，次靠右的自然浮现。

用栈重走 `"([])"`：

| 字符 | 操作 | 栈内容（底→顶） |
|---|---|---|
| `(` | 入栈 | `(` |
| `[` | 入栈 | `( [` |
| `]` | 栈顶 `[` 匹配，弹出 | `(` |
| `)` | 栈顶 `(` 匹配，弹出 | 空 |

结束栈空 → true。每一步都是 O(1)，总 O(n)。

再看反例 `"([)]"`：

| 字符 | 操作 | 栈内容 |
|---|---|---|
| `(` | 入栈 | `(` |
| `[` | 入栈 | `( [` |
| `)` | 栈顶是 `[`，类型不符 → false | — |

在第 3 步就返回 false，正好对应示例 5。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义扫描到第 i 个字符后，栈中存放的是「前 i 个字符里所有尚未闭合的左括号，按出现顺序从底到顶」。

**不变量成立的理由**（对 i 归纳）：
- 遇到左括号：它尚未闭合，且是最新出现的，压到栈顶，不变量保持。
- 遇到右括号 c：若栈空，说明 c 没有可配对的左括号，直接判 false，正确。若栈非空，设栈顶为 t。由不变量，t 是「最近一个未闭合左括号」。若 t 与 c 类型相同，则 c 闭合 t，弹出后栈恰好是「前 i 个字符里尚未闭合的左括号」；若类型不同，则 c 无法闭合 t——而 c 也不能去闭合栈中更靠下的括号，因为那会形成交叉（更靠下的括号比 t 出现更早，c 比 t 闭合更早，违反嵌套），所以判 false 正确。

**不漏**：每个右括号都被检查，栈空或类型不符都会返回 false，不存在「悄悄放过」的路径。
**不重**：每个左括号入栈一次、出栈至多一次，每个右括号只与栈顶比较一次，没有重复配对。

**收尾**：扫描结束后，若栈非空，说明有左括号从未被闭合，返回 false；栈空则所有括号都配对且顺序合法，返回 true。这一步对应题面第三条「每个右括号都有对应左括号」的反向要求——左括号也不能剩。

## 5. 完整代码（Python）

```python
class Solution:
    def isValid(self, s: str) -> bool:
        # 右括号 -> 对应左括号 的映射，方便 O(1) 查表
        pairs = {')': '(', ']': '[', '}': '{'}
        stack = []

        for ch in s:
            if ch in pairs:
                # 右括号：栈空说明没有可配对的左括号
                # 栈顶不是同类型左括号说明顺序/类型错误
                if not stack or stack[-1] != pairs[ch]:
                    return False
                stack.pop()          # 配对成功，弹出栈顶
            else:
                # 左括号：直接入栈，等待后续闭合
                stack.append(ch)

        # 扫描结束，栈必须为空，否则有左括号没被闭合
        return len(stack) == 0
```

关键点说明：`ch in pairs` 用字典做「是不是右括号」的判断，比写 `if ch in ')]}'` 再查表更紧凑；`not stack or stack[-1] != pairs[ch]` 把「栈空」和「类型不符」两种失败合并成一次判断，注意 `or` 的短路顺序——先判空再访问 `stack[-1]`，避免越界。

## 6. 复杂度

- **时间 O(n)**：n = len(s)。循环体执行 n 次，每次最多做一次字典查找、一次栈顶比较、一次 push 或 pop，全是 O(1)。没有嵌套循环，也没有排序，所以不出现 log n 项。
- **空间 O(n)**：栈最坏情况装下所有字符，比如 `"((((((..."` 全左括号时栈大小为 n。字典 `pairs` 固定 3 个键，是 O(1)，不随 n 增长。

## 7. 边界与反例（至少 4 条）

1. **`s = "("` → false**：只有一个左括号。容易错在「只检查右括号」——如果代码只处理右括号、结尾不检查栈空，就会误判 true。收尾的 `len(stack) == 0` 就是为这种情况准备的。
2. **`s = ")"` → false**：一上来就是右括号。容易错在没判栈空就访问 `stack[-1]`，Python 会抛 IndexError。`not stack or ...` 的短路顺序必须写对。
3. **`s = "([)]"` → false**：交叉嵌套。容易错在只比较「类型是否出现过」而不比较「栈顶」——比如误写成「栈里存在 `(` 就认为 `)` 能配」，会漏掉顺序约束。必须严格和栈顶比。
4. **`s = "(){}}{"` → false**：前四个字符 `(){}` 配完后栈空，接着 `}` 遇到空栈返回 false。容易错在把「配对成功」当成「整个字符串合法」，忘了后续还可能出错。
5. **`s = "((("` → false**：全左括号，栈最后非空。和第 1 条同类但更极端，用来验证收尾检查不是摆设。

## 8. 面试追问与变体（3 条）

1. **追问：如果括号种类不止三种，而是任意多种，怎么改？** 思路：把 `pairs` 字典换成从输入或配置构建的映射即可，算法结构不变，仍是 O(n)。
2. **追问：如果要求返回最长有效括号子串的长度（不是判断整体）？** 思路：这是力扣 32 题，栈里存下标而不是字符，配合一个「最后一个未匹配位置」的哨兵来算长度；或者用 DP。核心仍是「最近未闭合」的栈思想。
3. **追问：如果字符串里混有其他字符，只判断括号部分是否合法？** 思路：遇到非括号字符直接跳过（或按题意视为分隔），其余逻辑完全不变——栈只关心括号的相对顺序。

## 9. 举一反三（2-3 道同类题）

- **力扣 32. 最长有效括号（困难）**：同样用栈维护「未闭合左括号」，只是栈里存下标并额外记录长度，共同点是「后开先闭」的嵌套判定。
- **力扣 150. 逆波兰表达式求值（中等）**：用栈处理「最近的操作数先参与运算」，共同点是后进先出的消费顺序。
- **力扣 1047. 删除字符串中的所有相邻重复项（简单）**：栈顶与新字符相同就弹出，共同点是「栈顶即最近待处理元素」的消消乐模式。
