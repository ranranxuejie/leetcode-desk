## 1. 一句话本质

在一个 9×9 的格盘上，把每个空格填上 1–9 的数字，使得「每行、每列、每个 3×3 宫」这三类集合里 1–9 各恰好出现一次——本质是一个**带三类约束的精确覆盖搜索问题**。

## 2. 读完题的第一反应

**朴素解法**：把 81 个格子按顺序扫，遇到 `.` 就尝试填 1–9，填完继续往后走，走不通就退回来换下一个数。这就是最裸的 DFS 回溯。

它卡在哪？两个地方：

1. **合法性判断太贵**。每填一个数，都要扫一遍所在行（9 格）、列（9 格）、宫（9 格）来检查冲突，单次判断 O(27)。搜索树一大，这个常数就压不住。
2. **搜索顺序是死的**。按行优先从左到右填，可能前 20 个空格都很好填，到第 21 个才发现矛盾，于是要把前面 20 层的选择全部推倒重来。搜索树的分支因子接近 9，深度接近空格数，最坏是指数级的。

**关键观察**：数独的约束是「局部」的——一个格子能不能填 `d`，只取决于它所在的行、列、宫。这意味着两件事：

- 合法性可以**增量维护**：用三个布尔表 `row[r][d]`、`col[c][d]`、`box[b][d]` 记录「数字 d 是否已出现在第 r 行 / 第 c 列 / 第 b 宫」，填数时 O(1) 更新，回溯时 O(1) 撤销。判断从 O(27) 降到 O(1)。
- 搜索顺序可以**动态选**：与其按固定顺序填，不如每次挑「当前可选数字最少」的那个空格先填（MRV，Minimum Remaining Values）。可选数少的格子先定，能尽早暴露矛盾、尽早剪枝。

这两点合起来，就是这道题从「能过」到「稳过」的全部内容。

## 3. 从暴力到最优

**第一步：裸回溯。** 对每个 `.` 枚举 1–9，每次用三重循环检查行/列/宫是否冲突。能出答案，但常数大、剪枝弱。

**第二步：增量约束表。** 开三个 9×10 的布尔数组（第二维用 1–9，0 号位空着方便下标对齐）。填 `board[r][c] = d` 时：

```
row[r][d] = col[c][d] = box[b][d] = True
```

其中宫编号 `b = (r // 3) * 3 + c // 3`。回溯时全部置回 `False`。合法性判断变成 `not (row[r][d] or col[c][d] or box[b][d])`。

**第三步：MRV 选格。** 每层递归先扫一遍所有空格，对每个空格数一下「在它所在行/列/宫里还没被用掉的数字有几个」，挑最少的那个来填。

**小例子走一遍。** 取示例棋盘左上角：

```
5 3 .
6 . .
. 9 8
```

- 空格 `(0,2)`：第 0 行已有 {5,3}，第 2 列已有 {8}，第 0 宫已有 {5,3,6,9,8}。并集 {3,5,6,8,9}，可选 {1,2,4,7}，共 4 个。
- 空格 `(1,1)`：第 1 行已有 {6}，第 1 列已有 {3,9}，第 0 宫已有 {5,3,6,9,8}。并集 {3,5,6,8,9}，可选 {1,2,4,7}，共 4 个。
- 空格 `(2,0)`：第 2 行已有 {9,8}，第 0 列已有 {5,6}，第 0 宫已有 {5,3,6,9,8}。并集 {3,5,6,8,9}，可选 {1,2,4,7}，共 4 个。

假设某一步出现一个空格只剩 `{4}` 可选，MRV 就会先填它——填完立刻更新三张表，可能让别的空格可选数从 2 掉到 1，连锁触发。这就是「先定死局」的威力：矛盾越早暴露，回溯越少。

**为什么 MRV 不改变正确性？** 因为它只是改变了「先填哪个空格」的顺序，而数独的解与填写顺序无关——所有空格最终都要被填，且每个空格的可选集合由已填数字唯一决定。顺序只影响搜索效率，不影响解集。

## 4. 正确性：为什么不会漏、不会重

**不变量（Invariant）**：在递归的任意时刻，三张约束表 `row/col/box` 精确记录了「当前棋盘上已填数字」在三类约束下的分布，且棋盘上所有已填数字互不冲突。

- **初始**：扫描一遍输入棋盘，把已给数字写入三张表。题面保证输入合法，不变量成立。
- **填数**：只在 `row[r][d] or col[c][d] or box[b][d]` 全为假时才填 `d`，填完同步置位三张表。不变量保持。
- **撤销**：回溯时把三张表对应位置清零，棋盘恢复为 `.`。不变量回到填之前的状态。

**不会重**：每个空格在某一层递归里只被填一个数字，且填完立即进入下一层，不会在同一层对同一空格填两个值。不同分支对应不同的填数序列，序列不同则最终棋盘不同（因为空格位置固定、填的值不同），所以不会产生重复解。

**不会漏**：这是回溯的完备性。对当前选中的空格，我们枚举了它**所有**合法候选（1–9 中不冲突的那些）。任何合法解在这个空格上必然取某个合法候选值，因此必然落在某个分支里。归纳下去，若存在解，DFS 一定能走到。题面保证「仅有一个解」，所以搜到的第一个完整解就是答案。

**终止性**：每层递归填一个空格，空格数严格递减，深度不超过 81，搜索树有限，必然终止。

## 5. 完整代码（Python）

```python
class Solution:
    def solveSudoku(self, board: list[list[str]]) -> None:
        # 三张约束表：row[r][d] 表示第 r 行是否已用数字 d
        # 下标 1..9 有效，0 号位不用
        row = [[False] * 10 for _ in range(9)]
        col = [[False] * 10 for _ in range(9)]
        box = [[False] * 10 for _ in range(9)]

        # 初始化：把题面已给的数字写入约束表
        for r in range(9):
            for c in range(9):
                if board[r][c] != '.':
                    d = int(board[r][c])
                    b = (r // 3) * 3 + c // 3
                    row[r][d] = col[c][d] = box[b][d] = True

        def dfs() -> bool:
            # MRV：找可选数字最少的空格
            best_r = best_c = -1
            best_cands = None
            for r in range(9):
                for c in range(9):
                    if board[r][c] != '.':
                        continue
                    b = (r // 3) * 3 + c // 3
                    cands = [
                        d for d in range(1, 10)
                        if not row[r][d] and not col[c][d] and not box[b][d]
                    ]
                    # 剪枝：某空格无候选，当前分支必失败
                    if not cands:
                        return False
                    if best_cands is None or len(cands) < len(best_cands):
                        best_r, best_c, best_cands = r, c, cands
                        if len(best_cands) == 1:
                            break  # 已经最少，不必再扫
                else:
                    continue
                break

            # 没有空格了，说明填满，找到解
            if best_r == -1:
                return True

            r, c, b = best_r, best_c, (best_r // 3) * 3 + best_c // 3
            for d in best_cands:
                # 填数 + 更新约束表
                board[r][c] = str(d)
                row[r][d] = col[c][d] = box[b][d] = True

                if dfs():
                    return True

                # 回溯：撤销
                board[r][c] = '.'
                row[r][d] = col[c][d] = box[b][d] = False

            return False  # 所有候选都失败

        dfs()
```

## 6. 复杂度

设空格数为 `k`（本题 `k ≤ 81`），每个空格候选数上界为 9。

- **时间**：最坏 O(9^k)，因为每层最多 9 个分支、深度 k。但这是**上界**，实际远小于此：MRV 让分支因子大幅下降，且约束表让每层判断 O(1)。初始化扫描 81 格，每格 O(1)，贡献 O(81)。每层 MRV 扫描最多 81 格、每格算候选最多 9 次，贡献 O(81×9)=O(729) 每层。所以总时间 ≈ O(9^k × 729)，但 k 和实际分支都远小于最坏值。**注意**：这里没有 log n，因为数独尺寸固定为 9，所有「n」都是常数 9 或 81；如果推广到 N×N 数独，才是 O(N^2) 初始化 + 指数搜索。
- **空间**：三张表各 9×10 布尔，O(9×10×3)=O(270)，常数。递归栈深度 ≤ k ≤ 81，O(k)。总空间 O(k + 270)，即 O(k)。同样没有 log 项。

## 7. 边界与反例（至少 4 条）

1. **输入全是 `.`** → 期望输出任意一个合法完整数独（题面保证唯一解，但全空其实多解，属于题面外情形）→ 容易错在：以为「唯一解」保证对任意输入成立，实际全空有多解，代码会返回搜到的第一个，不保证是某个特定解。**假设**：本题输入保证唯一解，全空不在测试范围内。
2. **某行已填满 9 个数字** → 期望该行不再被修改 → 容易错在：MRV 扫描时把已填格也当空格处理，或初始化时重复置位导致约束表状态错乱。
3. **空格候选数为 0（输入本身矛盾）** → 期望返回失败/不修改 → 容易错在：没写 `if not cands: return False` 的剪枝，导致该层 `best_cands` 为空列表，`for d in []` 直接跳过、返回 False，逻辑上碰巧对，但若 MRV 选格逻辑写错（比如 `best_cands is None` 判断漏了空列表），会选到无候选格却继续递归，浪费搜索。
4. **只有一个空格** → 期望直接填上唯一候选 → 容易错在：MRV 的 `break` 优化写错（比如 `break` 只跳出内层 `for c`，外层 `for r` 继续跑），导致选格结果被后续格子覆盖。
5. **数字是字符串 `'1'` 不是整数 `1`** → 期望 `int(board[r][c])` 转换 → 容易错在：直接拿 `board[r][c]` 当下标去索引 `row[r][d]`，字符串下标会抛 `TypeError`。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回所有解而不是一个解，怎么改？** 思路：把 `dfs` 的返回值从 `bool` 改成「收集解」，找到完整解时把 `board` 深拷贝进结果列表，然后**不 return True**，继续回溯枚举其他分支。
2. **追问：如何判断输入数独是否「有解」而不必求出解？** 思路：同样的 DFS，但找到第一个完整解就返回 True；若搜完所有分支没找到返回 False。可以加更强的剪枝（如唯一候选、隐性唯一）加速。
3. **追问：如果棋盘是 16×16（数字 1–16，4×4 宫），代码怎么改？** 思路：把常量 9 换成 16、3 换成 4、`range(1,10)` 换成 `range(1,17)`，宫编号公式 `(r//4)*4 + c//4` 不变，约束表维度改成 16×17。
