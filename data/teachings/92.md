## 1. 一句话本质

在一条单链表上，把**位置区间 [left, right] 内的那一段子链就地逆序**，再把这段逆序后的子链原样接回它前后的两个"断口"上。

关键词是"接回断口"——反转本身是链表入门题（206 题），本题真正的新东西是**定位断口 + 缝合**。

## 2. 读完题的第一反应

**朴素解法**：把 [left, right] 的节点值全部取出来放进数组，数组反转，再按顺序写回这些节点的 `val`。时间复杂度 O(n)、空间 O(k)（k = right-left+1）。它卡在哪？卡在**它改的是值不是指针**。面试官问"如果节点里存的是不允许修改的对象呢"，这解法立刻失效；而且题目要的是"反转节点"，改值属于偷换语义。所以这条路只能当兜底，不能当答案。

**关键观察**：链表反转有一个极其干净的局部操作——"把当前节点摘下来，头插到已反转部分的头部"。206 题整条链反转就是重复这个动作。本题只是把这个动作**限定执行 right-left 次**，并且执行前先走到 left 的前一个节点。

为什么这个观察能直接导向最优解？因为"头插"这个动作**只依赖三个指针**：已反转段的头、当前节点、当前节点的后继。它不需要知道整条链有多长，也不需要回头。于是"只反转一段"和"反转整条"在代码上是同一套骨架，差别只在**起点在哪、循环几次、最后缝哪两根线**。

## 3. 从暴力到最优

**第一步：暴力（改值）**
遍历到第 left 个节点，收集 k 个值，反转，写回。瓶颈：语义不对，且没练到指针操作。

**第二步：拆成"反转整段"+"缝合"**
把问题切成三块：
1. 找到第 left 个节点，记为 `segHead`；找到它前一个节点，记为 `prev`（left=1 时 `prev` 是哑节点）。
2. 从 `segHead` 开始，反转 k = right-left+1 个节点，得到新的段头 `newHead`。
3. 缝合：`prev.next = newHead`，原来的 `segHead` 现在成了段尾，让它指向第 right+1 个节点。

**第三步：一趟扫描（进阶要求）**
上面第 1、2 步可以合并：一边往后走一边头插，走满 k 次就停。这就是"头插法"，也是下面代码采用的写法。

**具体走一遍**：`head = [1,2,3,4,5], left = 2, right = 4`，k = 3。

先建哑节点 `dummy(0) -> 1 -> 2 -> 3 -> 4 -> 5`。`prev` 从 dummy 出发走 left-1 = 1 步，停在节点 1。此时：

- `prev = 1`，`cur = prev.next = 2`（这是段头，反转后它会变成段尾）

进入循环，执行 k-1 = 2 次"摘 cur 的后继、头插到 prev 后面"：

**第 1 次**：`nxt = cur.next = 3`；`cur.next = nxt.next = 4`；`nxt.next = prev.next = 2`；`prev.next = nxt = 3`。
链变成 `0 -> 1 -> 3 -> 2 -> 4 -> 5`。此时 `prev.next = 3`，`cur` 仍是 2。

**第 2 次**：`nxt = cur.next = 4`；`cur.next = nxt.next = 5`；`nxt.next = prev.next = 3`；`prev.next = nxt = 4`。
链变成 `0 -> 1 -> 4 -> 3 -> 2 -> 5`。

循环结束，返回 `dummy.next`，即 `[1,4,3,2,5]`。✓

注意 `cur` 从头到尾没动过，它一直是节点 2——因为每轮被摘走的是它的**后继**，它自己始终是"已反转段的尾巴"。这个细节是本题最容易写错的地方，第 4 节会讲清为什么。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来证。

设 k = right-left+1，`prev` 是第 left-1 个节点（哑节点兜底），`cur = prev.next` 是第 left 个节点。循环体执行第 i 次（i 从 1 到 k-1）之前，维持如下不变量：

> **不变量 I(i)**：从 `prev.next` 到 `cur` 的这一段，恰好是原链表第 left 到第 left+i-1 个节点，且顺序已被逆序；`cur.next` 指向原链表第 left+i 个节点；`prev` 之前的链与原链表完全一致。

**初始**：i=1 时，`prev.next == cur`，这一段只有 1 个节点，"逆序"平凡成立，`cur.next` 指向第 left+1 个节点。成立。

**保持**：第 i 次循环中，`nxt = cur.next` 正是原链表第 left+i 个节点（由不变量）。三步操作：
- `cur.next = nxt.next`：把 `nxt` 从原位摘出，`cur` 直接连到第 left+i+1 个节点，保证"未处理部分"不丢。
- `nxt.next = prev.next`：把 `nxt` 插到已逆序段的头部。
- `prev.next = nxt`：让 `prev` 指向新的段头。

三步之后，`prev.next` 到 `cur` 这一段变成"原第 left+i 个节点 + 原第 left..left+i-1 的逆序"，正好是第 left..left+i 的逆序，且 `cur.next` 指向第 left+i+1 个。I(i+1) 成立。

**终止**：循环执行 k-1 次后，i=k，`prev.next` 到 `cur` 覆盖了原第 left..right 全部 k 个节点且已逆序，`cur.next` 指向原第 right+1 个节点——缝合天然完成，无需额外操作。而 `prev` 之前的链从未被改动，所以区间外节点一个没漏、一个没重。

**为什么 `cur` 不动**：`cur` 的语义是"已反转段的尾"，而头插法每次都在头部插入，尾部自然不变。若误写成 `cur = cur.next`，就会跳过节点，这是本题最高频的 bug。

## 5. 完整代码（Python）

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def reverseBetween(self, head: ListNode, left: int, right: int) -> ListNode:
        # 哑节点统一处理 left == 1 的情况：此时 prev 就是 dummy
        dummy = ListNode(0, head)
        prev = dummy

        # 1. 走到第 left 个节点的前一个，停住
        for _ in range(left - 1):
            prev = prev.next

        # 2. 头插法反转 k 个节点
        cur = prev.next          # 段头，反转后成为段尾
        for _ in range(right - left):
            nxt = cur.next       # 待摘出的节点
            cur.next = nxt.next  # 从原位摘除，保住后半段
            nxt.next = prev.next # 插到已反转段头部
            prev.next = nxt      # prev 指向新段头

        # 3. 缝合已在循环中完成：cur 天然指向第 right+1 个节点
        return dummy.next
```

三段逻辑对应第 3 节的三步，`cur` 全程不动，缝合是"免费"的。

## 6. 复杂度

- **时间 O(n)**：第一段循环走 left-1 步，第二段走 right-left 步，合计 right-1 ≤ n-1 步，每步常数次指针赋值。n 来自"最坏情况下 left=1、right=n，需要遍历整条链"。没有 log 项，因为不存在分治或二分。
- **空间 O(1)**：只用了 `dummy, prev, cur, nxt` 四个指针，与 n 无关。递归写法会是 O(n) 栈空间，本题不需要递归。

## 7. 边界与反例（至少 4 条）

1. **`head=[5], left=1, right=1`** → `[5]`。k=1，第二段循环 `range(0)` 不执行，直接返回。易错点：有人把循环写成 `range(right-left+1)`，会多走一步把 `nxt` 取成 `None` 然后 `nxt.next` 崩掉。
2. **`head=[3,5], left=1, right=2`** → `[5,3]`。left=1 时 `prev` 是 dummy，若没有哑节点，`prev.next` 会直接改到 `head` 上，返回时拿不到新头。易错点：忘记返回 `dummy.next` 而返回 `head`。
3. **`head=[1,2,3], left=2, right=3`** → `[1,3,2]`。right=n，`cur.next` 最终为 `None`，`nxt.next = prev.next` 时 `nxt` 是最后一个节点，`nxt.next` 被设为段头，正确。易错点：以为 right 到末尾要特判。
4. **`head=[1,2,3,4,5], left=1, right=5`** → `[5,4,3,2,1]`。退化为整链反转，验证哑节点路径。易错点：`prev` 停在 dummy，`cur` 是原 head，循环 4 次后 `cur` 是原 head 即新尾，`cur.next` 应为 `None`——检查一下：第 4 次循环 `cur.next = nxt.next`，`nxt` 是原第 5 个节点，`nxt.next` 是 `None`，所以 `cur.next = None`，正确。
5. **`left == right`（任意位置）** → 原链表不变。k=1，循环不执行，`prev.next` 未被改动，返回原链。易错点：把 `range(right-left)` 写成 `range(right-left+1)` 会破坏链表。

## 8. 面试追问与变体（3 条）

1. **"如果要求每 k 个一组反转，不足 k 个保持原样呢？"**（25 题）→ 外层循环每次先探路数够不够 k 个，够就复用本题的头插骨架反转 k 个，再把上一组的尾接到本组新头。
2. **"能不能不用哑节点？"** → 可以，但要把 left=1 单独分支：先反转前 right 个，再让原 head 指向剩余部分。代价是代码分叉，哑节点是用一个哨兵换掉分支，面试时说明这个取舍即可。
3. **"如果链表是双向链表 / 要返回被反转段的头尾呢？"** → 双向链表头插时多维护一个 `prev` 指针域；返回头尾只需在循环结束后返回 `(prev.next, cur)`，因为 `prev.next` 是新段头、`cur` 是段尾。

## 9. 举一反三（2-3 道同类题）

- **206. 反转链表**：本题的 k = n、left = 1 的特例，骨架完全相同，是必须先练熟的前置。
- **25. K 个一组翻转链表**：把"反转一段"当成子过程反复调用，考的是组间缝合与不足 k 个的处理。
- **24. 两两交换链表中的节点**：k=2 的定长分组反转，可用同一套头插骨架，也可用三指针直接换。
