## 1. 一句话本质

把数组里的**每个不同数值当成一个"块"**，先按块的长度从小到大排，长度相同的块再按数值从大到小排，最后把排好序的块依次摊平。

## 2. 读完题的第一反应

**朴素解法**：对每个位置 i，数一遍 nums 里和 nums[i] 相等的元素有多少个，得到频率；然后写一个自定义比较函数，比较两个元素时先比频率、频率相同比数值，直接对原数组排序。

它卡在哪？每次比较都要重新数频率，一次计数是 O(n)，排序要做 O(n log n) 次比较，总复杂度 O(n² log n)。而且同一个数的频率被反复计算，纯属浪费——**频率是"每个值"的属性，不是"每个位置"的属性**。

**关键观察**：数组里不同的值最多只有 n 个，而频率只跟"值"有关。所以先把"值 → 频率"这张表一次性建好（哈希表，O(n)），之后任何一次比较都变成 O(1) 查表。这一步把"反复数数"这个瓶颈直接消掉了。

第二个观察来自题面那句"频率相同按数值降序"：这说明排序的**主键是频率、次键是数值**，两个键方向相反（频率升、数值降）。Python 的 `sort` 只能给一个 key 且默认升序，所以要么用 `key=(频率, -数值)` 这种"取负翻转"的技巧，要么用 `functools.cmp_to_key` 写比较器。前者更短，后者更直白，两种都值得会。

## 3. 从暴力到最优

**第一步：消掉重复计数。** 用 `Counter(nums)` 或手写字典，一次遍历得到 `freq = {值: 出现次数}`。以示例 2 `[2,3,1,3,2]` 为例：

```
遍历过程：
  读到 2 → freq={2:1}
  读到 3 → freq={2:1, 3:1}
  读到 1 → freq={2:1, 3:1, 1:1}
  读到 3 → freq={2:1, 3:2, 1:1}
  读到 2 → freq={2:2, 3:2, 1:1}
```

现在每个值的频率都是 O(1) 可查。

**第二步：确定排序对象。** 注意一个容易踩的坑：我们**不是**对原数组的 n 个元素排序，而是对"不同的值"排序。`freq` 的键只有 3 个：`{2, 3, 1}`。对它们排序：

```
排序键 (freq[v], -v)：
  v=2 → (2, -2)
  v=3 → (2, -3)
  v=1 → (1, -1)
按元组升序排：(1,-1) < (2,-3) < (2,-2)
对应值顺序：1, 3, 2
```

为什么 `-v` 能实现"数值降序"？因为对 v 取负后，v 越大 `-v` 越小，升序排就变成了 v 的降序。这是本题最值得记住的一招。

**第三步：摊平。** 排好的值序列是 `[1, 3, 2]`，每个值重复它自己的频率次：

```
1 出现 1 次 → [1]
3 出现 2 次 → [3, 3]
2 出现 2 次 → [2, 2]
拼接 → [1, 3, 3, 2, 2]
```

和示例 2 的期望输出一致。

**瓶颈对比**：暴力是 O(n² log n)（比较里藏计数）；建表后排序只对 k 个不同值做，k ≤ n，排序 O(k log k)，摊平 O(n)，总计 O(n + k log k) ≤ O(n log n)。计数那层从"每次比较都做"降到了"只做一次"。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：在构造最终答案的任意时刻，已输出的前缀恰好是"按 (频率升, 数值降) 排序后、前若干个完整块"的拼接。

分三点说明它成立：

1. **不漏**：`freq` 的键集合就是 nums 中出现过的所有不同值（Counter 对每个出现过的值恰好记一次键）。排序只重排这些键，不增不减；摊平时对每个键输出 `freq[v]` 次，总输出长度 = Σ freq[v] = n，正好等于原数组长度。所以每个元素都被输出且只被输出一次。

2. **不重**：摊平阶段是"对每个键 v，连续输出 freq[v] 个 v"，不同键之间不交叉，同一个键内部是连续的一段，因此不会出现某个值被拆成两段的情况，也不会多输出。

3. **顺序对**：设排序后相邻两个值 a、b（a 在前）。由排序键 `(freq[v], -v)` 升序可知，要么 `freq[a] < freq[b]`（频率升序成立），要么 `freq[a] == freq[b]` 且 `-a < -b` 即 `a > b`（同频时数值降序成立）。这正是题面要求的两个条件，且覆盖了所有相邻对，传递下去就是全局有序。

**交换论证的补充视角**：假设存在一个更优排列，其中某两个块 a、b 的相对顺序违反了上述规则。若 `freq[a] > freq[b]` 却把 a 放在 b 前面，交换它们后频率序列更符合升序，不会变差；若同频且 `a < b` 却把 a 放前面，交换后数值降序更符合要求。反复交换直到无逆序，就得到我们的排列，说明它是最优（唯一满足约束）的。

## 5. 完整代码（Python）

```python
from collections import Counter

class Solution:
    def frequencySort(self, nums: list[int]) -> list[int]:
        # 第一步：一次遍历统计每个值的出现次数，O(n)
        freq = Counter(nums)

        # 第二步：只对"不同的值"排序
        # 主键 freq[v] 升序；次键 -v 升序等价于 v 降序
        ordered_values = sorted(freq.keys(), key=lambda v: (freq[v], -v))

        # 第三步：按排好的值顺序，每个值重复它自己的频率次，摊平
        res = []
        for v in ordered_values:
            res.extend([v] * freq[v])   # 连续输出 freq[v] 个 v
        return res
```

如果面试官要求不用 `Counter`、手写计数（考察基本功），把第一步换成：

```python
freq = {}
for x in nums:
    freq[x] = freq.get(x, 0) + 1
```

如果面试官追问"不用取负技巧怎么写"，用比较器版本，逻辑更贴近题面文字：

```python
from functools import cmp_to_key

def cmp(a, b):
    if freq[a] != freq[b]:
        return freq[a] - freq[b]      # 频率升序
    return b - a                       # 数值降序

ordered_values = sorted(freq.keys(), key=cmp_to_key(cmp))
```

## 6. 复杂度

设 n = len(nums)，k = 不同值的个数（k ≤ n）。

- **时间 O(n + k log k)**：
  - 建频率表：遍历 n 个元素，每个 O(1) 字典操作 → 贡献 O(n)。
  - 排序：对 k 个键排序，比较是 O(1)（查表 + 取负），排序本身 O(k log k) → 贡献 O(k log k)，log 来自排序的分治层数。
  - 摊平：Σ freq[v] = n 次 append → 贡献 O(n)。
  - 最坏 k = n 时是 O(n log n)，但实际常远小于 n（本题值域 [-100,100]，k ≤ 201）。
- **空间 O(n + k)**：
  - 频率表存 k 个键值对 → O(k)。
  - 结果数组长度 n → O(n)。
  - 排序的键列表 O(k)，Python 的 Timsort 额外 O(k) 辅助空间。
  - 合计 O(n + k)，即 O(n)。

## 7. 边界与反例（至少 4 条）

1. **输入 `[5]`** → 期望 `[5]`。容易错在：以为要处理"没有同频值"的特殊分支，其实单元素直接走通用逻辑即可，别加多余判断。

2. **输入 `[1,1,1]`** → 期望 `[1,1,1]`。容易错在：只对"不同值"排序后忘了按频率摊平，输出成 `[1]`；或者摊平时误用"排序后键的个数"而不是 `freq[v]`。

3. **输入 `[2,2,1,1,3,3]`** → 期望 `[3,3,2,2,1,1]`。三个值频率都是 2，全靠次键降序决定。容易错在：把次键也写成升序，输出 `[1,1,2,2,3,3]`；或者忘了取负，`key=lambda v: (freq[v], v)` 就是错的。

4. **输入 `[-1,-1,2,2,3]`** → 期望 `[3,-1,-1,2,2]`。频率：3→1，-1→2，2→2。同频的 -1 和 2 按数值降序，2 在 -1 前面。容易错在：负数取负后大小关系搞反，或者误以为"负数排前面"。验证：`(1,-3) < (2,1) < (2,-(-1))=(2,1)`？注意 -1 的键是 `(2, 1)`，2 的键是 `(2, -2)`，`(2,-2) < (2,1)`，所以 2 在 -1 前，正确。

5. **输入 `[1,2,3,4]`** → 期望 `[4,3,2,1]`。全部频率为 1，退化成纯数值降序。容易错在：以为"频率升序"会让它保持原序。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求"频率降序、同频数值升序"呢？** 思路：把排序键改成 `(-freq[v], v)`，取负的位置换一下即可，其余逻辑不变。

2. **追问：值域很大（比如 10^9）或 n 很大时，你的方案还成立吗？** 思路：成立，哈希表不依赖值域大小；但若值域小（如本题 [-100,100]），可以用计数数组替代字典，把 O(k log k) 的排序换成按频率桶排序做到 O(n + 值域)，这是"值域换时间"的经典权衡。

3. **追问：能不能不排序、用桶做到线性？** 思路：频率最大为 n，建 n+1 个桶，桶下标是频率，桶内放该频率的值（桶内按数值降序维护），最后从低频桶到高频桶依次摊平。时间 O(n + 值域)，空间 O(n)。
