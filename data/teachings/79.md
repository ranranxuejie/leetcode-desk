## 1. 一句话本质

在一个字符矩阵里找一条**不重复经过同一格**的路径，使路径上依次读出的字符恰好拼成目标单词——本质是「带访问标记的路径存在性搜索」。

## 2. 读完题的第一反应

**朴素解法**：从每个格子出发，枚举所有长度等于 `len(word)` 的路径，看有没有一条拼出 `word`。路径数是指数级的：每个格子最多 4 个邻居，长度 L 的路径最多约 `4^L` 条，再乘上 `m*n` 个起点。`word.length` 最大 15，`4^15 ≈ 10^9`，乘上 36 个起点直接爆炸。

**卡在哪**：枚举了大量「前缀就已经不对」的路径。比如 `word = "ABCCED"`，从某格出发第一步是 `'X'`，这条路径根本不可能成功，但我们还是把它走完了。

**关键观察**：单词是**按顺序**匹配的。走到第 `k` 步时，前 `k` 个字符必须已经和 `word[0..k-1]` 完全一致。一旦某个格子字符不等于 `word[k]`，这条路立刻死掉，不需要再往下走。这就把「枚举所有路径」变成了「沿着匹配前缀的路径走」——也就是 DFS + 回溯，走不通就退回来换方向。

第二个观察来自题面的「同一个单元格不允许重复使用」：这要求我们在搜索过程中**标记已访问**，退出时**取消标记**，否则会污染其他分支。

## 3. 从暴力到最优

**第 0 步：纯暴力枚举所有路径**。对每个起点做长度 L 的 DFS，不检查字符。复杂度 `O(m*n*4^L)`，L=15 时不可行。

**第 1 步：加字符匹配剪枝**。DFS 进入格子 `(i,j)` 时，先判断 `board[i][j] == word[k]`，不等就返回 False。这一步把「前缀不对」的分支全部砍掉。以上面示例 1 的 `word = "ABCCED"` 为例，从 `(0,0)='A'` 出发：

- k=0：`board[0][0]='A' == word[0]='A'` ✓，标记 `(0,0)` 已访问
- k=1：邻居里 `(0,1)='B' == word[1]='B'` ✓，标记 `(0,1)`
- k=2：邻居 `(0,2)='C' == word[2]='C'` ✓，标记 `(0,2)`
- k=3：邻居 `(0,3)='E' != 'C'`，`(1,2)='C' == word[3]='C'` ✓，标记 `(1,2)`
- k=4：邻居 `(1,1)='F' != 'E'`，`(2,2)='E' == word[4]='E'` ✓，标记 `(2,2)`
- k=5：邻居 `(2,1)='D' == word[5]='D'` ✓，k 走到 6 == len(word)，返回 True

中间那些 `'E'`、`'F'` 的分支在字符比较那一步就被砍掉了，根本没往下走。

**第 2 步：加访问标记 + 回溯**。没有标记的话，`"ABCB"` 这种会沿着 `A→B→C→B` 走回 `(0,1)`，而 `(0,1)` 已经被用过。标记后 `(0,1)` 在 k=1 时被占用，k=3 想回去时发现已访问，直接跳过——这正是示例 3 返回 False 的原因。DFS 返回前必须把标记清掉，否则这个格子对「从别的起点出发」或「同一层的其他分支」就永久不可用了。

**第 3 步（进阶剪枝）**：统计 `board` 里每个字符的出现次数，如果 `word` 里某字符出现次数超过 board 中的总数，直接返回 False。另外可以比较 `word[0]` 和 `word[-1]` 在 board 中的出现次数，从更稀少的那个字符开始搜（把 word 反转），减少起点数量。这两条不改变最坏复杂度，但实测能显著加速。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在 DFS 的任意时刻，调用栈上的格子序列 `(i0,j0), (i1,j1), ..., (ik,jk)` 满足三个条件：(a) 相邻两格在矩阵中上下左右相邻；(b) `board[i_t][j_t] == word[t]` 对所有 `t <= k` 成立；(c) 序列中格子互不相同（由访问标记保证）。

**不会漏**：假设存在一条合法路径 `P = p0, p1, ..., p_{L-1}` 拼出 `word`。我们从 `p0` 出发做 DFS。由于 DFS 会尝试当前格子的**所有**未访问邻居，而 `p1` 是 `p0` 的邻居且字符匹配，DFS 一定会进入 `p1`；归纳地，DFS 一定会沿 `P` 走到 `p_{L-1}`，此时 `k == L`，返回 True。所以只要解存在，DFS 必然找到。

**不会重**：访问标记保证同一路径内不重复走格子，满足题面「同一个单元格不允许重复使用」。回溯时清除标记，保证不同分支之间互不干扰——一个格子在某条路径中被占用，不影响它在另一条路径中被使用。

**终止性**：每层 DFS 的 `k` 严格递增，且 `k <= len(word)`，深度有界；每层最多 4 个分支，搜索树有限，必然终止。

## 5. 完整代码（Python）

```python
class Solution:
    def exist(self, board, word):
        if not board or not board[0] or not word:
            return False

        m, n = len(board), len(board[0])

        # 进阶剪枝 1：字符频次检查，word 中某字符比 board 里还多，直接不可能
        from collections import Counter
        board_cnt = Counter(ch for row in board for ch in row)
        word_cnt = Counter(word)
        for ch, c in word_cnt.items():
            if board_cnt[ch] < c:
                return False

        # 进阶剪枝 2：从首尾字符中在 board 里更稀少的那个开始搜
        # 若 word[-1] 更稀少，反转 word，等价于从尾部开始匹配
        if board_cnt[word[0]] > board_cnt[word[-1]]:
            word = word[::-1]

        L = len(word)
        # visited 标记当前路径上已使用的格子
        visited = [[False] * n for _ in range(m)]

        def dfs(i, j, k):
            # 字符不匹配，这条分支死掉
            if board[i][j] != word[k]:
                return False
            # 已经匹配完最后一个字符
            if k == L - 1:
                return True

            visited[i][j] = True  # 占用当前格
            # 四个方向：上、下、左、右
            for di, dj in ((-1, 0), (1, 0), (0, -1), (0, 1)):
                ni, nj = i + di, j + dj
                # 越界或已访问，跳过
                if 0 <= ni < m and 0 <= nj < n and not visited[ni][nj]:
                    if dfs(ni, nj, k + 1):
                        visited[i][j] = False  # 找到解也要先还原再返回
                        return True
            visited[i][j] = False  # 回溯：释放当前格，供其他分支使用
            return False

        # 枚举每个格子作为起点
        for i in range(m):
            for j in range(n):
                if dfs(i, j, 0):
                    return True
        return False
```

注意 `visited[i][j] = False` 在「找到解返回」和「没找到返回」两条路径上都要执行，代码里分别在 `return True` 前和循环后各写了一次，保证状态干净。

## 6. 复杂度

**时间**：`O(m * n * 3^L)`，其中 `L = len(word)`。推导：起点有 `m*n` 个；从起点出发，第一步最多 4 个方向，之后每一步因为不能走回上一格（已访问），最多 3 个方向，所以每条搜索路径的分支数约 `4 * 3^(L-1)`，即 `O(3^L)`。字符比较是 `O(1)`。频次剪枝是 `O(m*n + L)`，被主项吸收。最坏情况（board 全是同一字符、word 也全是该字符）会接近这个上界。

**空间**：`O(m*n)` 来自 `visited` 二维数组；递归栈深度最多 `L`，即 `O(L)`。总空间 `O(m*n + L)`，其中 `m*n` 是主导项（`m,n <= 6` 时很小，但按一般规模写）。

## 7. 边界与反例（至少 4 条）

1. **`board = [["A"]], word = "A"`** → 期望 `True`。容易错在：`k == L-1` 的判断放在字符比较之前，或者忘了单格也是合法路径。代码里先比较字符再判断 `k == L-1`，顺序正确。

2. **`board = [["A"]], word = "AA"`** → 期望 `False`。容易错在：没有访问标记，DFS 从 `(0,0)` 出发又走回 `(0,0)` 自己，误判为 True。访问标记在进入时置 True，保证不会原地复用。

3. **`board = [["A","B"],["C","D"]], word = "ABD"`** → 期望 `False`（`A→B` 后 `B` 的邻居是 `A` 和 `D`，`A` 已访问，`D` 字符是 `'D'` 但 word[2]='D' 其实匹配……这里要小心：`A(0,0)→B(0,1)→D(1,1)` 是合法的，返回 True）。换个真正的反例：**`board = [["A","B"],["C","D"]], word = "ABC"`** → 期望 `False`，因为 `A→B` 后 `B` 的邻居只有 `A`（已访问）和 `D`，没有 `C`。容易错在：回溯时忘了清除 `visited`，导致后续起点搜索时格子被永久占用。

4. **`board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]], word = "ABCB"`** → 期望 `False`（示例 3）。容易错在：不标记访问，路径 `A→B→C→B` 会走回 `(0,1)` 的 `B`，误判 True。

5. **`word` 长度超过 `m*n`** → 期望 `False`。容易错在：没做这个前置检查，DFS 会一直搜到越界才停，虽然结果对但浪费；更隐蔽的是如果 `word` 里有 board 没有的字符，频次剪枝会提前拦住。

## 8. 面试追问与变体（3 条）

1. **追问：如果 board 很大（比如 1000×1000），word 很长，怎么优化？**
   思路：先做字符频次剪枝和首尾字符选择；再用「按 word 顺序预处理每个字符在 board 中的位置集合」，从候选位置里搜而不是全图枚举起点；极端情况下可以考虑双向 BFS 从 word 两端同时搜，减少搜索深度。

2. **追问：如果允许同一个格子重复使用呢？**
   思路：去掉 `visited` 标记即可，但要注意这会让搜索树不再有「路径长度 ≤ m*n」的天然上界，可能无限循环（比如 board 里 `A` 的邻居还是 `A`，word 是 `"AAAA..."`）。需要额外加「连续相同字符段长度不超过 board 中该字符总数」之类的剪枝，或者用 BFS 按层扩展并限制步数。

3. **追问：如果要返回所有不同的路径（而不只是 true/false）呢？**
   思路：DFS 找到一条完整路径时，把当前栈上的坐标序列拷贝进结果集；由于不同路径可能坐标序列相同但顺序不同（实际上本题路径由坐标序列唯一确定），用 `tuple` 存路径去重。注意回溯时要 `pop` 栈顶，保持栈与当前路径一致。

3. **力扣 130. 被围绕的区域**：和本题的共同点是「矩阵 DFS + 边界处理」，区别是本题从任意格出发找路径，130 从边界出发标记「与外界连通」的格子，剩下的就是要翻转的，DFS 的作用是「传播标记」而非「匹配序列」。
