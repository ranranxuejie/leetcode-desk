## 1. 一句话本质

对每个「恰好凑齐 a、b、c 三种字符」的连续区间，数它有多少个右端点可以继续往右延伸——把「枚举所有子串」换成「枚举左端点、一次算出它贡献多少个子串」。

## 2. 读完题的第一反应

朴素解法：枚举所有子串（O(n²) 个），每个子串再花 O(n) 检查是否三种字符齐全，总复杂度 O(n³)。n 最大 5×10⁴，n³ 是 1.25×10¹⁴ 量级，必然超时。即使把「检查」优化成 O(1) 的前缀计数，枚举子串本身也是 O(n²) ≈ 2.5×10⁹，仍然过不去。

瓶颈在哪？在于「枚举子串」这个动作本身。子串有 O(n²) 个，只要你还想逐个判断，就注定慢。

关键观察：**子串是否合法，对右端点具有单调性**。固定左端点 L，随着右端点 R 从左往右移动，窗口里字符种类只增不减。所以一旦某个 R₀ 让窗口凑齐了 a、b、c，那么所有 R ≥ R₀ 都合法。这意味着：对每个 L，我不需要逐个试 R，只需要找到**最小的合法右端点** R₀，然后直接知道这个 L 贡献了 `n - R₀` 个子串。问题从「判断每个子串」变成「对每个 L 求一个临界点」，而临界点随 L 增大也单调右移——这正是滑动窗口的用武之地。

## 3. 从暴力到最优

**第一步：暴力枚举。** 对每个 L，对每个 R ≥ L，检查 s[L..R] 是否含 a、b、c。以 `s = "abcabc"`（n=6）为例，L=0 时要检查 R=0,1,2,3,4,5 共 6 个子串，L=1 时 5 个……总共 21 个子串，每个再扫一遍，代价很高。

**第二步：利用单调性，对每个 L 只找临界 R₀。** 还是 `"abcabc"`：

- L=0：R 从 0 开始扩，R=0 窗口 "a"（缺 b,c），R=1 "ab"（缺 c），R=2 "abc" 齐了 → R₀=2，贡献 6-2=4 个（"abc","abca","abcab","abcabc"）。
- L=1：从 R=2 的窗口 "bc" 出发（去掉 s[0]='a' 后剩 "bc"，缺 a），R 扩到 3 得 "bca" 齐了 → R₀=3，贡献 6-3=3 个。
- L=2：窗口去掉 s[1]='b' 剩 "ca"，R 扩到 4 得 "cab" → R₀=4，贡献 2 个。
- L=3：去掉 s[2]='c' 剩 "ab"，R 扩到 5 得 "abc" → R₀=5，贡献 1 个。
- L=4：去掉 s[3]='a' 剩 "bc"，R 已经到 5 且无法再扩，窗口仍缺 a → 贡献 0。
- L=5：同理贡献 0。

合计 4+3+2+1 = 10，与示例一致。

**第三步：注意到 R₀ 单调不减，用双指针一次扫完。** 上面 L 从 0 走到 5，R₀ 是 2,3,4,5,∞,∞，从不回退。所以 R 指针总共只前进 n 次，L 指针也前进 n 次，总操作 O(n)。中间变量就是窗口内三个字符的计数 `cnt = {'a':x,'b':y,'c':z}`，每次 L 右移时把移出的字符计数减一，若某计数归零说明窗口不再齐全，就继续推 R 直到重新齐全。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。维护的不变量是：**在当前 L 下，R 是使 s[L..R] 包含 a、b、c 的最小右端点（若不存在则 R = n）。**

- **不漏**：对固定 L，由第 2 节的单调性，所有 R ≥ R₀ 的子串都合法，所有 R < R₀ 的都不合法。所以「以 L 开头的合法子串」恰好是 `n - R₀` 个，我们一个不多一个不少地加上了。
- **不重**：每个子串由唯一的左端点 L 标识，我们在处理 L 时只统计「以 L 开头」的子串，不同 L 统计的集合互不相交，因此不会重复计数。
- **不变量如何维持**：L 右移时，窗口收缩可能丢掉某种字符，此时 R 只增不减地向右扩，直到重新齐全——因为 R 之前的位置对旧 L 是临界点，对新 L 只会更不够（窗口更短），所以新临界点必然 ≥ 旧 R，R 不回退是安全的，不会错过答案。

## 5. 完整代码（Python）

```python
class Solution:
    def numberOfSubstrings(self, s: str) -> int:
        n = len(s)
        cnt = {'a': 0, 'b': 0, 'c': 0}  # 当前窗口 [left, right] 内各字符出现次数
        ans = 0
        right = 0  # 右指针，全程只向右移动

        for left in range(n):
            # 扩张 right，直到窗口凑齐 a、b、c 或 right 越界
            while right < n and not (cnt['a'] > 0 and cnt['b'] > 0 and cnt['c'] > 0):
                cnt[s[right]] += 1
                right += 1

            # 此时若窗口齐全，则 right-1 是最小合法右端点，
            # 以 left 开头的合法子串有 n - (right - 1) 个
            if cnt['a'] > 0 and cnt['b'] > 0 and cnt['c'] > 0:
                ans += n - (right - 1)

            # 左指针即将右移，把 s[left] 移出窗口
            cnt[s[left]] -= 1

        return ans
```

注意 `right` 在 while 里先自增再判断，所以循环结束时 `right` 指向「最小合法右端点的下一个位置」，合法子串数是 `n - (right - 1)`。当窗口始终凑不齐时，`right == n`，`cnt` 中必有字符为 0，走不进加法分支，贡献 0，正确。

## 6. 复杂度

- **时间 O(n)**：`left` 从 0 到 n-1 走 n 步；`right` 从 0 单调增到 n，总共也只增 n 次。两个指针合计 O(n) 次移动，每次移动做 O(1) 的计数更新和判断。没有排序、没有二分，所以**没有 log n 项**。
- **空间 O(1)**：`cnt` 固定三个键，与 n 无关。若用数组 `[0,0,0]` 也是常数空间。

## 7. 边界与反例（至少 4 条）

1. `s = "abc"` → 期望 1。容易错在把 `right` 的偏移算错，写成 `n - right` 会得 0；正确是 `n - (right-1)`。
2. `s = "aaaa"` → 期望 0。窗口永远凑不齐，`right` 一路推到 n，加法分支不触发。容易错在没处理「凑不齐」的情况，导致 `n - (right-1)` 算出负数或越界。
3. `s = "aaacb"` → 期望 3。L=0 时 R₀=4，贡献 5-4=1；L=1 时窗口去掉一个 a 仍齐全（"aacb"），R 不动，贡献 1；L=2 同理贡献 1；L=3 去掉后剩 "cb" 缺 a，贡献 0。合计 3。容易错在 L 右移后忘记「窗口可能仍然齐全、R 不该动」，误把 R 重置回 L。
4. `s = "abcabcabc"`（n=9）→ 期望 9+8+7+6+5+4+3+2+1 中前若干项之和，具体为 L=0..6 各贡献 9-R₀，R₀=2,3,4,5,6,7,8，贡献 7+6+5+4+3+2+1=28，L=7,8 贡献 0，合计 28。容易错在把「相同字符串算多次」理解成去重，题目明确要求按位置计数。

## 8. 面试追问与变体（3 条）

1. **追问：如果字符集不是固定的 a、b、c，而是任意 k 种字符，怎么做？** 思路不变，把 `cnt` 换成哈希表，维护「计数 > 0 的字符种类数」这个变量，与 k 比较即可，仍是 O(n)。
2. **追问：改成「恰好包含 a、b、c 各一次」的子串数目？** 思路：用「至多包含各一次」的窗口数减去「至多包含各零次」的窗口数（容斥），或对每个右端点维护最近一次出现位置，取三者最小值。
3. **追问：如果要求子串中 a、b、c 出现次数都相等？** 思路：把 a 记 +1、b 记 -1、c 记 0 之类做前缀和映射，转成「前缀和相等」的计数问题，用哈希表统计。
