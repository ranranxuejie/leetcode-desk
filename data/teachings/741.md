## 1. 一句话本质

把「一去一回」等价成「两个人同时从 (0,0) 走到 (n-1,n-1)」，求两条路径并集上樱桃数的最大值，且两条路径在同一时刻必须处于同一条反对角线上。

## 2. 读完题的第一反应

**朴素解法**：先 DP 求一遍从 (0,0) 到 (n-1,n-1) 的最大樱桃路径，把走过的格子清零，再 DP 求一遍从 (n-1,n-1) 回到 (0,0) 的最大路径，两次相加。

它卡在哪？**贪心失效**。第一趟选「局部最优」的路径，可能把第二趟唯一能走的樱桃全吃光，或者第一趟为了多吃一个樱桃绕了路，导致第二趟无路可走。复杂度本身是 O(n²) 的两次 DP，不慢——**错在策略，不在复杂度**。这是这道题最容易踩的坑：看起来像两道独立 DP，实际上两趟路径互相耦合。

**关键观察**：把「去程 + 回程」整体翻转。回程从 (n-1,n-1) 走回 (0,0) 只能上/左，等价于把回程路径**时间反演**成一条从 (0,0) 到 (n-1,n-1) 的只下/右路径。于是问题变成：**同时选两条从 (0,0) 到 (n-1,n-1) 的单调路径，最大化它们覆盖的樱桃并集**。

为什么这个转化有用？因为两条路径「同时走」时，第 k 步两人都在反对角线 `i+j=k` 上。于是状态可以用「步数 k + 两人各自的行号」来刻画，而不需要记录两条完整路径——这就把指数级的路径枚举压成了多项式 DP。

## 3. 从暴力到最优

**暴力**：枚举所有从 (0,0) 到 (n-1,n-1) 的单调路径（数量是组合数 C(2n-2, n-1)，n=50 时天文数字），对每对路径算并集樱桃数。不可行。

**第一步优化——同时走**：两个人 A、B 同时从 (0,0) 出发，每步都下/右。走 2n-2 步后同时到达终点。第 k 步时，A 在 `(r1, k-r1)`，B 在 `(r2, k-r2)`——**列坐标由行坐标和步数唯一确定**。所以状态是 `(k, r1, r2)`，共 O(n³) 个。

**第二步——合并采摘**：当 A、B 在同一格（r1==r2 且同一步，列也必相同）时，樱桃只算一次；否则各算各的。这就是「不会重复计数」的机制。

**小例子走一遍**：`grid = [[0,1,-1],[1,0,-1],[1,1,1]]`，n=3，终点步数 k=4。

- k=0：A、B 都在 (0,0)，`dp[0][0][0] = grid[0][0] = 0`。
- k=1：可能位置行号 ∈ {0,1}。A、B 各选。比如 `dp[1][1][0]`：A 在 (1,0) 值 1，B 在 (0,1) 值 1，不同格，和 = 0+1+1 = 2。
- k=2：A 可在行 0,1,2。注意 (0,2) 和 (1,2)、(2,1) 里有荆棘 -1，这些状态直接置 -∞。`dp[2][2][1]`：A 在 (2,0) 值 1，B 在 (1,1) 值 0，和 = 2+1+0 = 3。
- k=3：`dp[3][2][2]`：两人都在 (2,1)，值 1，只算一次，从 `dp[2][2][1]=3` 转移来 → 3+1 = 4。
- k=4：两人都在 (2,2)，值 1，只算一次，从 `dp[3][2][2]=4` → 4+1 = **5**。

最终答案 5，和示例一致。注意 k=3 时两人重合在 (2,1)，樱桃只加了一次——这正是「并集」语义。

**第三步——滚动数组**：`dp[k]` 只依赖 `dp[k-1]`，所以 k 这一维可以压掉，空间从 O(n³) 降到 O(n²)。转移时 A、B 各有「上一步在下 / 上一步在右」两种来源，共 4 种组合取 max。

## 4. 正确性：为什么不会漏、不会重

**不变量 1（状态完备）**：任何一对合法的单调路径，在第 k 步时 A 的行号 r1、B 的行号 r2 唯一确定两人的位置（列 = k - 行）。所以 `(k, r1, r2)` 完整刻画了「两人同时走到第 k 步」的所有可能局面，DP 不会漏掉任何路径对。

**不变量 2（采摘不重不漏）**：定义 `gain(r1, r2, k)` = 若 r1==r2 则取该格值一次，否则取两格值之和。因为两条路径的并集樱桃数 = 路径上所有格子值的并集计数，而同一时刻同一格只可能被两人同时踩到（不同时刻踩同一格在单调路径下不可能，因为行号严格随步数不减、列号也不减，回到同一格需要步数相同）。所以按步累加 `gain` 恰好等于并集大小，**不重**；每个被任一路径经过的格子都会在它对应的那一步被计入，**不漏**。

**不变量 3（最优子结构）**：`dp[k][r1][r2]` 定义为「两人走到第 k 步、分别在第 r1、r2 行时，前 k 步能采到的最大樱桃数」。第 k 步的最优值只依赖第 k-1 步的最优值（四种前驱取 max），符合最优子结构，归纳可证。

**关于「回程等价」**：回程路径从 (n-1,n-1) 到 (0,0) 只上/左，把它反向读就是从 (0,0) 到 (n-1,n-1) 只下/右的路径，且经过的格子集合完全相同。所以「去程 + 回程」的樱桃并集 = 「两条正向路径」的樱桃并集，转化是等价的，不是近似。

## 5. 完整代码（Python）

```python
class Solution:
    def cherryPickup(self, grid) -> int:
        n = len(grid)
        NEG = -10**9  # 表示不可达

        # dp[r1][r2]：当前步数 k 下，A 在第 r1 行、B 在第 r2 行的最大樱桃数
        # 初始 k=0，两人都在 (0,0)
        dp = [[NEG] * n for _ in range(n)]
        dp[0][0] = grid[0][0]

        # k 从 1 走到 2n-2（终点步数）
        for k in range(1, 2 * n - 1):
            ndp = [[NEG] * n for _ in range(n)]
            # 第 k 步时，行号范围是 [max(0, k-(n-1)), min(n-1, k)]
            lo = max(0, k - (n - 1))
            hi = min(n - 1, k)
            for r1 in range(lo, hi + 1):
                c1 = k - r1
                if grid[r1][c1] == -1:      # A 踩到荆棘，该行状态全废
                    continue
                for r2 in range(lo, hi + 1):
                    c2 = k - r2
                    if grid[r2][c2] == -1:  # B 踩到荆棘
                        continue
                    # 当前步两人贡献的樱桃（重合只算一次）
                    gain = grid[r1][c1] if r1 == r2 else grid[r1][c1] + grid[r2][c2]
                    # 四种前驱：A 上一步来自上/左，B 上一步来自上/左
                    best = NEG
                    for pr1 in (r1 - 1, r1):      # r1-1 表示从上方来，r1 表示从左边来
                        if pr1 < 0 or pr1 >= n:
                            continue
                        for pr2 in (r2 - 1, r2):
                            if pr2 < 0 or pr2 >= n:
                                continue
                            if dp[pr1][pr2] > best:
                                best = dp[pr1][pr2]
                    if best > NEG // 2:           # 存在可达前驱
                        ndp[r1][r2] = best + gain
            dp = ndp

        # 终点 (n-1, n-1)，两人行号都是 n-1
        ans = dp[n - 1][n - 1]
        return max(ans, 0)  # 不可达时返回 0（题面：无路径则摘不到樱桃）
```

## 6. 复杂度

**时间**：外层 k 有 O(n) 个（2n-1 步），内层 r1、r2 各 O(n)，最内层 4 种前驱是常数。总计 **O(n³)**。n=50 时约 50³ = 125000 次状态转移，轻松通过。

**空间**：`dp` 和 `ndp` 各是 n×n 的二维表，滚动后只保留两层，**O(n²)**。没有 log 项——所有操作都是常数时间的数组下标访问，不涉及排序或二分。

## 7. 边界与反例（至少 4 条）

1. **`grid = [[0]]`** → 期望 0。n=1 时循环 `range(1, 1)` 不执行，直接返回 `dp[0][0] = 0`。容易错在把起点当樱桃硬加 1，或循环边界写成 `range(1, 2*n-1)` 之外的错误范围。

2. **`grid = [[1]]`** → 期望 1。起点即终点，只采一次。容易错在「去程 + 回程」各算一次得 2——这正说明必须用「并集」语义而非「两趟相加」。

3. **`grid = [[1,1,-1],[1,-1,1],[-1,1,1]]`** → 期望 0。起点到终点被荆棘完全隔断。容易错在 DP 里用 0 初始化而非 -∞，导致「不可达」被当成「采到 0 个」而错误地继续转移，最终返回非 0。代码里用 `NEG` 和 `best > NEG//2` 判断可达性就是防这个。

4. **`grid = [[1,1],[1,1]]`** → 期望 4。两条路径可以覆盖全部 4 格（比如 A 走下右、B 走右下，在 (1,1) 汇合）。容易错在认为「两人重合的格子只算一次」导致少算——注意重合只发生在同一时刻同一格，本例中 (0,0) 和 (1,1) 各重合一次，但 (0,1)、(1,0) 各被一人踩，总和仍是 4。

5. **`grid = [[0,0],[0,0]]`** → 期望 0。全空，无樱桃。容易错在把 0 值格子和不可达混淆，或返回 -1。

## 8. 面试追问与变体（3 条）

1. **追问：如果允许走 k 趟（k>2）而不是 2 趟，怎么做？** 思路：状态升到 k 维行号 `(r1,...,rk)`，时间 O(n^{k+1})，k 固定时仍是多项式；k 是输入时问题变难，需要另想。

2. **追问：如果格子里的樱桃可以重复采摘（不清零），答案会变吗？** 思路：会。此时两趟独立，直接两次 DP 相加即可，退化成简单题——说明「清零」是本题难度的来源。

3. **追问：如果要输出具体路径而不只是数量，怎么改？** 思路：DP 表里额外记录每个状态的最优前驱（4 选 1 的编号），最后从终点回溯，得到两条路径。
