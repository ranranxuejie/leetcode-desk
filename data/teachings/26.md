## 1. 一句话本质

在一个**已经排好序**的数组里，把「相邻重复」压掉，让每个值只留一份，并把去重结果原地挤到数组最前面，返回去重后的个数 k。

## 2. 读完题的第一反应

最朴素的做法：新建一个空列表，遍历 nums，遇到和「上一个放进结果的值」不同的就 append，最后把结果写回 nums 前几位，返回长度。

这个做法**逻辑上完全正确**，但它卡在两点上：

- 空间上开了 O(n) 的额外列表，而题面明确要求「原地」；
- 就算不管原地，写回那一步也要再遍历一次，代码啰嗦。

关键的观察来自题面那句「**非严格递增排列**」——这是整道题的地基。它意味着：**相等的元素一定挨在一起**。所以「某个值是否重复」根本不需要哈希表去记，只要看它和「上一个保留下来的值」是否相等就够了。重复项是连续的，不是散落的。

第二个观察来自判题标准：它只检查 `nums[0..k-1]` 是否等于期望答案，`k` 之后的内容「可以忽略」。这句话等于官方授权你：**把去重结果往前覆盖，后面被覆盖掉的旧值不用管**。于是「新建列表再写回」可以合并成「一边读一边往前面写」，额外空间降到 O(1)。

## 3. 从暴力到最优

**暴力版**：`res = []`，遍历 nums，`if not res or nums[i] != res[-1]: res.append(nums[i])`，然后 `nums[:len(res)] = res`，返回 `len(res)`。时间 O(n)，空间 O(n)。

**瓶颈在哪**：`res` 这个列表是多余的。我们真正需要的只是「结果写到哪了」这个位置信息，而它恰好可以复用 nums 自己的前缀——因为读指针永远走在写指针前面或同位置，写进去的值不会破坏还没读到的数据。

**双指针版**：用 `slow` 表示「下一个唯一值该放的位置」，也等于「目前已确认的唯一值个数」；用 `fast` 做遍历读指针。

拿 `nums = [0,0,1,1,1,2,2,3,3,4]` 走一遍：

| fast | nums[fast] | 比较对象 nums[slow-1] | 动作 | slow | 数组前段 |
|---|---|---|---|---|---|
| 初始 | — | — | slow=1（nums[0] 天然是第一个唯一值） | 1 | `[0,...]` |
| 1 | 0 | nums[0]=0 | 相等，跳过 | 1 | `[0,...]` |
| 2 | 1 | nums[0]=0 | 不等，`nums[1]=1` | 2 | `[0,1,...]` |
| 3 | 1 | nums[1]=1 | 相等，跳过 | 2 | `[0,1,...]` |
| 4 | 1 | nums[1]=1 | 相等，跳过 | 2 | `[0,1,...]` |
| 5 | 2 | nums[1]=1 | 不等，`nums[2]=2` | 3 | `[0,1,2,...]` |
| 6 | 2 | nums[2]=2 | 相等，跳过 | 3 | `[0,1,2,...]` |
| 7 | 3 | nums[2]=2 | 不等，`nums[3]=3` | 4 | `[0,1,2,3,...]` |
| 8 | 3 | nums[3]=3 | 相等，跳过 | 4 | `[0,1,2,3,...]` |
| 9 | 4 | nums[3]=3 | 不等，`nums[4]=4` | 5 | `[0,1,2,3,4]` |

结束，返回 5。注意 `nums[1]=1` 那次写入时，`nums[1]` 原来的值是 0，被覆盖了——但那个 0 已经处理过（fast=1 时读过），不会再被需要，所以安全。

**为什么比较对象是 `nums[slow-1]` 而不是 `nums[fast-1]`？** 这是最容易写错的地方。`nums[fast-1]` 是「原数组里的前一个」，而 `nums[slow-1]` 是「已确认的唯一值里的最后一个」。因为数组有序，两者在「是否等于当前值」上判断结果一致，但用 `slow-1` 语义更直接：我在跟「上一个保留的值」比。用 `fast-1` 也能过，但解释起来绕。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**说清楚。定义不变量：

> 在每轮循环开始时，`nums[0..slow-1]` 恰好是 `nums[0..fast-1]` 中所有出现过的不同值，且按原相对顺序排列；`slow >= 1`。

**初始化**：fast=1、slow=1 时，`nums[0..0]` 就是 `nums[0..0]` 的唯一值集合，成立。

**保持**：设当前 fast 指向 x = nums[fast]。
- 若 x == nums[slow-1]：因为数组非递减，`nums[slow-1]` 是已保留值中最大的，x 等于它说明 x 这个值此前已出现过，不该再留。slow 不动，不变量对 fast+1 仍成立（x 不是新值）。
- 若 x != nums[slow-1]：由非递减性，x > nums[slow-1]，即 x 严格大于所有已保留值，说明 x 是**新值**。写入 `nums[slow]=x`、slow 加一，前缀恰好扩展了 x 这一个新值，不变量保持。

**终止**：fast 走到 n，`nums[0..slow-1]` 就是全体不同值，slow 即 k。

**不会重**：每次写入前都确认 x 严格大于已保留的最大值，所以写入的值两两不同。
**不会漏**：任何在原数组中出现过的值，在它第一次出现的那一轮，`nums[slow-1]` 必然严格小于它（因为它是首次出现，之前没保留过它），于是被写入。

另外要保证「写入不破坏未读数据」：始终有 `slow <= fast`（slow 从 1 开始，fast 从 1 开始，slow 只在 fast 前进的同一轮或更早前进，且 slow 增量不超过 fast 增量），所以 `nums[slow]` 这个位置要么是已读过的旧值，要么就是 fast 自己，覆盖它不会丢失未读信息。

## 5. 完整代码（Python）

```python
class Solution:
    def removeDuplicates(self, nums: list[int]) -> int:
        # 题面保证长度 >= 1，所以 nums[0] 天然是第一个唯一值
        # slow：下一个唯一值要写入的下标，也等于当前已确认的唯一值个数
        slow = 1

        # fast：遍历读指针，从第二个元素开始扫描
        for fast in range(1, len(nums)):
            # 和「上一个保留下来的值」比较：
            # 相等说明这个值此前已出现过（有序保证重复项相邻），跳过
            # 不等说明是新值，写到 slow 位置，并把 slow 前移
            if nums[fast] != nums[slow - 1]:
                nums[slow] = nums[fast]
                slow += 1

        # slow 就是唯一值个数 k，nums[0..slow-1] 已是去重结果
        return slow
```

如果担心空数组（本题约束不会出现，但作为通用写法），在开头加 `if not nums: return 0` 即可。

## 6. 复杂度

**时间 O(n)**：`for fast in range(1, len(nums))` 恰好执行 n-1 次，每次循环体内是比较 + 至多一次赋值 + 一次自增，都是 O(1)。n 来自数组长度，没有嵌套循环，也没有排序或二分带来的 log 因子——因为「有序」这个前提是题目白送的，我们不需要为它付代价。

**空间 O(1)**：只用了 `slow`、`fast` 两个整型变量。没有新建列表、没有切片拷贝（`nums[:] = ...` 那种写法会额外开空间，这里刻意避开了）。原地修改，符合题面「原地删除」的要求。

## 7. 边界与反例（至少 4 条）

1. **输入 `[1]` → 期望 `1, nums=[1]`**。容易错在把 `slow` 初始化为 0，然后循环从 0 开始，导致把 `nums[0]` 又写一遍或越界比较 `nums[-1]`。正确做法是 slow 从 1 起、fast 从 1 起，天然处理单元素。

2. **输入 `[1,1,1,1]` → 期望 `1, nums=[1,_,_,_]`**。容易错在只判断「和 fast-1 不同」就写入，逻辑上没错但若写成「和 fast+1 不同」就会越界；另一个坑是误以为要返回去重后数组长度以外的信息。全程 slow 停在 1，返回 1。

3. **输入 `[1,2,3]`（全不重复）→ 期望 `3, nums=[1,2,3]`**。容易错在以为「没有重复就不用动」，其实每轮都在执行 `nums[slow]=nums[fast]`，只是 slow==fast 时是自我赋值，无害。若代码里加了「slow != fast 才写」的优化，结果一样，但别因此漏掉 slow 自增。

4. **输入 `[-3,-1,-1,0,0,2]`（含负数）→ 期望 `4, nums=[-3,-1,0,2,...]`**。容易错在拿「值是否大于 0」之类做判断，或误用 `nums[fast] > nums[slow-1]` 之外的条件。负数不影响逻辑，比较只看相等与否。

5. **输入 `[0,0,1,1,1,2,2,3,3,4]`（官方示例）→ 期望 `5`**。容易错在返回 `len(set(nums))`——值对但没原地修改，判题的第二段断言 `nums[i] == expectedNums[i]` 会挂。

## 8. 面试追问与变体（3 条）

1. **追问：如果每个元素最多保留两次（力扣 80 题）怎么办？**
   思路：把比较对象从 `nums[slow-1]` 换成 `nums[slow-2]`，即「只有当当前值和已保留的倒数第二个不同时才写入」，slow 初始化为 2（并处理长度 < 2 的边界）。本质是「允许重复次数」参数化。

2. **追问：如果数组没排序，还能 O(1) 空间去重吗？**
   思路：不能保持相对顺序地 O(1) 空间去重（需要哈希或排序）。要么先排序 O(n log n) 再套本题，要么用哈希集合 O(n) 空间。这题「有序」是省掉哈希的关键前提，要能说清这一点。

3. **追问：不用双指针，用 Python 的 `nums[:] = sorted(set(nums))` 行不行？**
   思路：结果对，但空间 O(n)、时间 O(n log n)（set 建完还要 sorted），且违背「原地、O(1) 额外空间」的考察意图。面试里这么写会被追问复杂度，属于「能过但没答到点上」。

## 9. 举一反三（2-3 道同类题）

1. **力扣 27. 移除元素**：同样是「原地 + 双指针 + 返回新长度」，区别是删除条件从「与前一个重复」变成「等于给定 val」，写指针逻辑几乎一模一样。

2. **力扣 80. 删除有序数组中的重复项 II**：本题的直接升级，把「保留 1 次」放宽到「保留 2 次」，比较对象从 slow-1 挪到 slow-2，是检验你是否真懂不变量的好题。

3. **力扣 283. 移动零**：同为「读写双指针原地压缩」，把「非零元素往前挤」和本题「唯一值往前挤」是同一套骨架，只是判据不同。
