## 1. 一句话本质

数出所有「奇数个数恰好等于 k」的连续区间个数——把奇偶性压成 0/1 序列后，就是数「区间和恰好为 k」的子数组个数。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子数组 `[i, j]`，对每个子数组数一遍奇数个数，等于 k 就计数。子数组有 O(n²) 个，每个再花 O(n) 数奇数，总复杂度 O(n³)。即便用前缀和优化到 O(n²)，n = 50000 时也是 2.5×10⁹ 次操作，必然超时。瓶颈在于「枚举所有区间」这个动作本身——区间太多，必须想办法不逐个枚举。

**关键观察**：题目只关心奇数的**个数**，不关心奇数的具体值。所以可以把 `nums` 变成一个 0/1 数组：奇数记 1，偶数记 0。这样「子数组里恰好有 k 个奇数」就等价于「子数组的和恰好为 k」。

这一步转换为什么能带来下一步？因为「区间和」有一个天然的工具：**前缀和**。设 `P[i] = 前 i 个元素的和`，那么区间 `[l, r)` 的和 = `P[r] - P[l]`。要求它等于 k，就是要求 `P[r] - P[l] = k`，即 `P[l] = P[r] - k`。于是问题从「枚举区间」变成了「枚举右端点 r，数一数它左边有多少个前缀和恰好等于 `P[r] - k`」——这正是「两数之和」的哈希表套路。

## 3. 从暴力到最优

**第一步：暴力枚举区间。** 以 `nums = [1,1,2,1,1], k = 3` 为例，枚举 `[0,3]`（即 `[1,1,2,1]`）数出 3 个奇数，计数；枚举 `[1,4]`（即 `[1,2,1,1]`）数出 3 个奇数，计数；其余区间奇数个数都不是 3。答案 2。复杂度 O(n³)，卡在「每个区间都要重新数」。

**第二步：前缀和 + 双重循环。** 转成 0/1 数组 `[1,1,0,1,1]`，前缀和 `P = [0,1,2,2,3,4]`（P[0]=0 表示空前缀）。对每个右端点 r，遍历所有 l < r，检查 `P[r] - P[l] == k`。r=4 时 P[4]=3，需要 P[l]=0，l=0 满足，得到一个区间 `[0,4)`；r=5 时 P[5]=4，需要 P[l]=1，l=1 满足，得到 `[1,5)`。共 2 个。复杂度降到 O(n²)，但 n=50000 时仍是 2.5×10⁹，不够。

**第三步：哈希表消掉内层循环。** 瓶颈是「对每个 r 都要扫一遍所有 l」。但我们要找的只是「P[l] 等于某个特定值 `P[r]-k` 的 l 有多少个」——这是一个计数查询，用哈希表存「每个前缀和值出现过几次」即可 O(1) 回答。

继续上面的例子，维护 `count = {0: 1}`（空前缀和 0 出现 1 次），`ans = 0`：

- r=1，P=1，需要 P[l]=1-3=-2，count 中没有，ans=0；把 P=1 记入，count={0:1, 1:1}
- r=2，P=2，需要 -1，没有，ans=0；count={0:1,1:1,2:1}
- r=3，P=2，需要 -1，没有，ans=0；count={0:1,1:1,2:2}
- r=4，P=3，需要 0，count[0]=1，ans=1；count 加入 3
- r=5，P=4，需要 1，count[1]=1，ans=2；count 加入 4

最终 ans=2，与暴力一致。复杂度 O(n)，每个元素只被处理常数次。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。在循环处理到下标 r（即准备计算以 r 结尾的所有区间）之前，哈希表 `count` 满足不变量：

> 对任意整数 v，`count[v]` 等于「满足 `P[l] = v` 且 `l < r` 的 l 的个数」。

**不会漏**：任何一个优美子数组 `[l, r)` 都对应唯一的右端点 r 和左端点 l，且 `P[r] - P[l] = k`。当循环走到 r 时，由不变量，`count[P[r]-k]` 恰好统计了所有满足条件的 l（包括这个 l），所以它一定被计入 ans。

**不会重**：每个子数组由 (l, r) 唯一确定，只在处理右端点 r 的那一轮被统计一次；不同 r 对应不同右端点，区间必然不同。同一轮内，count 里每个 l 只贡献 1 次计数，不会重复。

**不变量维持**：每轮结束把当前 `P[r]` 加入 count，恰好把「l < r」扩展为「l < r+1」，不变量继续成立。初始时 r=0，没有 l < 0，count 中只有 `{0:1}` 表示空前缀——这对应「从下标 0 开始的区间」，是必须的初始化，漏了它所有以 0 开头的区间都会丢。

## 5. 完整代码（Python）

```python
class Solution:
    def numberOfSubarrays(self, nums, k):
        # count[v] = 前缀和恰好为 v 的左端点个数
        # 初始放入 0:1，代表「空前缀」，用于统计从下标 0 开始的区间
        count = {0: 1}
        prefix = 0   # 当前前缀和（即奇数个数）
        ans = 0

        for x in nums:
            # 奇数贡献 1，偶数贡献 0，直接累加即可
            prefix += x & 1

            # 以当前位置为右端点，找左端点使区间和恰为 k
            # 即需要 P[l] = prefix - k
            ans += count.get(prefix - k, 0)

            # 把当前前缀和记入哈希表，供后面的右端点使用
            count[prefix] = count.get(prefix, 0) + 1

        return ans
```

注意 `x & 1` 这个写法：奇数二进制末位为 1，偶数末位为 0，比 `x % 2` 更直接地表达「取奇偶性」。`count.get(prefix - k, 0)` 处理了「该前缀和从未出现过」的情况，避免 KeyError。

## 6. 复杂度

**时间 O(n)**：外层 for 循环遍历 n 个元素，每次循环内做常数次哈希表操作（一次查询、一次插入），哈希表均摊 O(1)。n 来自数组长度，没有 log n 项——因为这里没有排序或二分，哈希表把「查找」降到了常数时间。

**空间 O(n)**：哈希表最多存 n+1 个不同的前缀和（前缀和取值在 0 到「奇数总数」之间，最坏情况每个位置都不同）。n 同样来自数组长度。没有额外的数组开销。

对比：如果不用哈希表而用「前缀和数组 + 双重循环」，时间 O(n²)、空间 O(n)；哈希表把时间换成了线性，空间不变。

## 7. 边界与反例（至少 4 条）

1. **`nums = [2,4,6], k = 1`** → 期望 0。全是偶数，前缀和恒为 0，`prefix - k = -1` 永远查不到。容易错在：忘记初始化 `count = {0:1}` 时反而「碰巧」对，但若 k=0 就会出错——本题 k≥1 所以安全，但思维上要清楚初始化是为「从 0 开始的区间」服务的。

2. **`nums = [1], k = 1`** → 期望 1。单元素奇数。容易错在：循环里先 `ans += count.get(prefix-k)` 再插入当前 prefix，顺序反了就会把「当前元素自己」当成左端点，导致区间长度为 0 被误计。

3. **`nums = [1,1,1], k = 2`** → 期望 2（区间 `[0,2)` 和 `[1,3)`）。前缀和 `P = [0,1,2,3]`。r=2 时 P=2 需要 P[l]=0，count[0]=1；r=3 时 P=3 需要 P[l]=1，count[1]=1。容易错在：把「恰好 k 个」误读成「至少 k 个」，那样会多算 `[0,3)`。

4. **`nums = [2,2,2,1,2,2,1,2,2,2], k = 2`** → 期望 16（示例 3）。两个奇数之间夹着大量偶数，每个偶数位置都产生新的合法左/右端点组合。容易错在：用滑动窗口时「窗口内奇数恰好 k 个」的左右边界扩展计数写错，导致漏乘偶数段长度。哈希表法天然规避这个问题。

5. **`k` 大于奇数总数**，如 `nums = [1,2,1], k = 3` → 期望 0。前缀和最大为 2，`prefix - k` 恒为负，查不到。容易错在：没有意识到 k 可以大于实际奇数个数，代码里不需要特判，哈希表自然返回 0。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求「奇数个数不超过 k」的子数组数目呢？** 思路：把「恰好」改成「至多」，可以用双指针滑动窗口维护「窗口内奇数 ≤ k」，对每个右端点累加合法左端点个数；或者仍用前缀和，但需要统计 `P[l] ≥ P[r] - k` 的个数，得用树状数组/有序结构。

2. **追问：如果数组元素可以修改（单点更新），多次查询优美子数组数目？** 思路：前缀和 + 哈希表是「一次性」的，动态更新下需要线段树维护「区间内奇数个数」并配合分治统计跨中点的合法区间数，复杂度 O(log n) 每次更新。

3. **追问：为什么不能用普通滑动窗口（左右指针都只右移）直接数「恰好 k 个」？** 思路：因为「恰好 k 个」不满足单调性——窗口右移奇数个数增加，左移减少，但「恰好」的窗口在右端点固定时可能有多个左端点，普通滑窗只能找到一个边界，需要「至多 k」减「至多 k-1」两次滑窗，或者像本题用哈希表直接计数。

## 9. 举一反三（2-3 道同类题）

1. **560. 和为 K 的子数组**：和本题几乎同构，把「奇数个数」换成「元素和」，同样用前缀和 + 哈希表数 `P[r]-P[l]=k`，是本题的「母题」。

2. **930. 和相同的二元子数组**：数组只含 0/1，求和恰好为 goal 的子数组数，与本题把奇偶压成 0/1 后的形式完全一致。

3. **974. 和可被 K 整除的子数组**：前缀和取模后用哈希表统计「同余」的前缀和个数，核心思想仍是「把区间条件转成两个前缀之间的关系，用哈希表计数」。
