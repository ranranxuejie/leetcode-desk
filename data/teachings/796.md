## 1. 一句话本质

判断 `goal` 是不是 `s` 的某个**循环移位**——也就是把 `s` 看成一个首尾相接的环，从环上某个位置剪开、按原方向读一圈，能不能读出 `goal`。

## 2. 读完题的第一反应

**朴素解法**：枚举所有旋转次数 `k = 0..n-1`，每次真的把 `s` 左移一位，和 `goal` 比较。写起来最直白：

```python
cur = s
for _ in range(len(s)):
    if cur == goal:
        return True
    cur = cur[1:] + cur[0]
return False
```

它卡在哪？每次旋转 `cur[1:] + cur[0]` 要复制整个字符串，是 O(n)；比较 `cur == goal` 也是 O(n)；一共 n 次。**总复杂度 O(n²)**。n 只有 100 时当然能过，但这不是这道题想让你答的东西——面试官问「能不能 O(n)」时，你得有话说。

**关键观察**：所有旋转结果，其实都藏在 `s + s` 里面。因为 `s + s` 把 `s` 复制了一份接在后面，于是「从任意位置开始、连续读 n 个字符」读出来的，恰好就是某一次旋转的结果。比如 `s = "abcde"`，`s + s = "abcdeabcde"`，从下标 2 开始读 5 个字符得到 `"cdeab"`，正是左旋 2 位的结果。

这一步观察为什么能让你想到下一步？因为它把「**枚举 n 种旋转 + 每种比较 n 个字符**」这个二维问题，压成了「**在一个长度 2n 的串里找一个长度 n 的子串**」这个一维问题。而「找子串」是有现成 O(n) 工具的（KMP、或 Python 内置的 `in`），瓶颈就被消掉了。

## 3. 从暴力到最优

分三步走，每步只消掉一个瓶颈。

**第一步：暴力枚举旋转。** 瓶颈是「每次旋转都要 O(n) 复制」。但其实我们不需要真的构造出每个旋转串，只需要知道「从下标 k 开始读 n 个字符」是什么——这提示我们去看 `s + s`。

**第二步：用 `s + s` 把枚举变成查找。** 现在问题变成：`goal` 是不是 `s + s` 的某个子串？用具体例子走一遍，`s = "abcde"`, `goal = "cdeab"`：

- `doubled = "abcdeabcde"`（长度 10）
- 在 `doubled` 中找 `"cdeab"`：从下标 2 开始匹配，`doubled[2:7] = "cdeab"`，命中 → `True`

再看反例 `goal = "abced"`：

- 在 `"abcdeabcde"` 中找 `"abced"`：从下标 0 开始比，`a b c` 对上，第 4 位 `doubled[3] = 'd'` 而 `goal[3] = 'e'`，失败；换起点继续找，全串扫完没有匹配 → `False`

这一步把「n 次 O(n) 比较」变成了「一次子串查找」，但**子串查找本身**如果用 Python 的 `in`，底层是优化过的（近似线性），如果手写朴素匹配还是 O(n²)。所以还差最后一步。

**第三步：子串查找用 KMP（或直接信任 `in`）。** KMP 的核心是「匹配失败时，利用已匹配部分的信息，不回退主串指针」，把查找降到 O(n)。在面试里，你可以直接写 `goal in s + s` 并说明「Python 的 `in` 对字符串是优化实现，最坏 O(n·m) 但实际接近线性；要严格 O(n) 就手写 KMP」。这就是从暴力到最优的完整链条：**枚举旋转 → 拼接成 2n 串 → 线性子串匹配**。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来讲。

**不变量**：对任意 `k ∈ [0, n-1]`，`s` 左旋 k 位得到的串，恰好等于 `(s + s)[k : k + n]`。

证明：`s + s` 的第 k 位到第 k+n-1 位，前 `n-k` 个字符是 `s[k..n-1]`，后 `k` 个字符是 `s[0..k-1]`（因为 `s+s` 的后半段就是 `s` 本身）。拼起来正是「把前 k 个字符挪到末尾」的结果，即左旋 k 位。∎

由这个不变量：

- **不会漏**：如果 `goal` 是 `s` 的某个旋转，设旋转次数为 k，则 `goal = (s+s)[k:k+n]`，所以 `goal` 一定是 `s+s` 的子串，查找必然命中。
- **不会重（不会误判）**：如果 `goal` 是 `s+s` 的子串，设起始位置为 k。注意 `s+s` 长度是 2n，子串长度是 n，所以 k 只能落在 `[0, n]` 范围内（否则越界）。当 `k = n` 时，`(s+s)[n:2n] = s`，对应旋转 0 次；当 `k < n` 时，由不变量对应左旋 k 次。两种情况都是合法旋转，所以命中就意味着 `goal` 确实是某个旋转结果。

还有一个**前置条件**必须单独检查：如果 `len(s) != len(goal)`，直接返回 `False`。因为旋转不改变长度，长度不同必然不可能。这个检查不能省——否则 `goal = "abc"`, `s = "ab"` 时 `"abc" in "abab"` 是 `False` 碰巧对了，但 `goal = "ab"`, `s = "abab"` 时 `"ab" in "abababab"` 是 `True`，而长度不同显然不该返回 `True`。所以长度检查是正确性的一部分，不是优化。

## 5. 完整代码（Python）

```python
class Solution:
    def rotateString(self, s: str, goal: str) -> bool:
        # 旋转不改变长度，长度不同直接排除
        if len(s) != len(goal):
            return False

        # 空串是任意串的旋转（题面约束长度 >= 1，这里防御性处理）
        if len(s) == 0:
            return True

        # 所有旋转结果都是 s+s 中长度为 n 的子串
        doubled = s + s

        # 在 doubled 中查找 goal；Python 的 in 对字符串是优化实现
        return goal in doubled
```

如果面试官要求「不许用内置 `in`，手写线性匹配」，就换成 KMP：

```python
class Solution:
    def rotateString(self, s: str, goal: str) -> bool:
        if len(s) != len(goal):
            return False
        if len(s) == 0:
            return True

        text = s + s
        pattern = goal

        # 构造 pattern 的 next 数组：next[i] 表示 pattern[0..i] 的最长相等前后缀长度
        n = len(pattern)
        nxt = [0] * n
        j = 0
        for i in range(1, n):
            while j > 0 and pattern[i] != pattern[j]:
                j = nxt[j - 1]          # 失配时回退到上一个可能的前缀位置
            if pattern[i] == pattern[j]:
                j += 1
            nxt[i] = j

        # 在 text 中匹配 pattern
        j = 0
        for ch in text:
            while j > 0 and ch != pattern[j]:
                j = nxt[j - 1]          # 主串指针不回退，只回退模式串指针
            if ch == pattern[j]:
                j += 1
            if j == n:
                return True             # 完整匹配到 pattern
        return False
```

## 6. 复杂度

**时间**：

- 拼接 `s + s`：O(n)，n 是 `s` 的长度。
- 子串查找：用 `in` 时，Python 内部实现最坏 O(n·m)（m 为模式串长度，这里 m = n，即 O(n²)），但实际是高度优化的，通常接近 O(n)；用 KMP 则严格 O(n + m) = O(n)。
- 总时间：**KMP 版 O(n)**；`in` 版最坏 O(n²)、实际接近 O(n)。

**空间**：

- `doubled = s + s` 占 O(n)。
- KMP 的 `nxt` 数组占 O(m) = O(n)。
- 总空间：**O(n)**，主要来自拼接串和 next 数组。

注意：这里没有 log n 项——题目不涉及排序或二分，所有操作都是线性的。

## 7. 边界与反例（至少 4 条）

1. **`s = "a", goal = "a"` → `True`**。容易错在：有人写循环 `for k in range(len(s))` 时，`len(s) = 1` 只试一次，没问题；但如果写成 `range(1, len(s))` 就漏掉了旋转 0 次的情况。旋转 0 次也是合法旋转。

2. **`s = "ab", goal = "ba"` → `True`**。容易错在：只检查「goal 是否是 s 的子串」而忘了拼接。`"ba"` 不是 `"ab"` 的子串，但它是 `"abab"` 的子串（下标 1 开始）。必须用 `s + s`。

3. **`s = "abc", goal = "abcabc"` → `False`**。容易错在：忘了长度检查。`"abcabc" in "abcabc"` 是 `True`，但长度不同，旋转不可能改变长度。所以长度检查必须放在最前面。

4. **`s = "abcde", goal = "abced"` → `False`**（题面示例 2）。容易错在：以为「字符集合相同」就够了。两个串字符完全一样，但相对顺序不同，不是旋转关系。`s + s` 中找不到 `"abced"`，正确返回 `False`。

5. **`s = "aa", goal = "aa"` → `True`**。容易错在：有重复字符时，`s + s = "aaaa"`，`"aa"` 在其中出现多次，但只要有任意一次命中就返回 `True`，不能因为「有多个匹配位置」就判错。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回具体的旋转次数 k，怎么做？** 思路：在 `s + s` 中用 KMP 找到 `goal` 的起始下标 k，若 `k < n` 则旋转次数为 k，若 `k == n` 则旋转 0 次；找不到返回 -1。

2. **追问：如果允许「旋转」的定义变成「把最右边字符移到最左边」（右旋），答案会变吗？** 思路：不变。右旋 k 位等价于左旋 n-k 位，所有旋转结果的集合完全相同，`s + s` 的判定依然成立。

3. **追问：如果 s 和 goal 长度可达 10^5，且要求严格 O(n) 且不许用内置函数，怎么写？** 思路：手写 KMP（见第 5 节第二段代码），时间 O(n)、空间 O(n)；也可以提一句「Rabin-Karp 用滚动哈希，期望 O(n)，但有碰撞风险，需要双哈希或验证」。
