## 1. 一句话本质

对每一排，判断它最多能塞下几个「合法的四人块」（0/1/2 个），把所有排的贡献加起来；而绝大多数排一个预订都没有，直接贡献 2。

## 2. 读完题的第一反应

**朴素解法**：开一个 `n × 10` 的布尔矩阵，把 `reservedSeats` 标进去，然后逐排检查三个候选块 `[2,5]`、`[4,7]`、`[6,9]` 是否全空，能放两块就放两块，否则放一块。

它卡在哪？`n` 最大 `10^9`。开 `10^9 × 10` 的矩阵直接爆内存，逐排遍历也爆时间。而 `reservedSeats` 长度只有 `10^4`，也就是说**被预订的座位最多一万个，涉及的行最多一万行**，剩下 `n - 10000` 行是干干净净的。

**关键观察**：一行如果没有任何预订，它必然能放 2 组（座位 2-5 和 6-9 互不重叠）。所以答案的「底」是 `2 * (n - 有预订的行数)`，我们只需要对**有预订的那几千行**单独精算，把它们的贡献从 2 修正成 0/1/2。这样复杂度就和 `n` 脱钩了。

第二个观察：一行里只有座位 2~9 有意义。座位 1 和 10 无论被谁占了，都不影响任何候选块（三个块分别是 2-5、4-7、6-9，都不含 1 和 10）。所以处理一行时，只需关心 2~9 这 8 个位置，天然就是一个 8 位掩码。

## 3. 从暴力到最优

**第一步：从「按排遍历」变成「按预订遍历」。**

用一个哈希表 `row_mask: dict[int, int]`，键是行号，值是该行 2~9 号座位的占用位掩码。遍历 `reservedSeats`，若 `2 <= seat <= 9`，就把 `1 << (seat - 2)` 或进对应行。座位 1、10 直接丢弃。

**第二步：对每个出现过的行，用位运算判块。**

把三个候选块也写成掩码（位 0 对应座位 2，位 7 对应座位 9）：

- 块 A = 座位 2,3,4,5 → `0b00001111` = `0x0F`
- 块 B = 座位 4,5,6,7 → `0b00111100` = `0x3C`
- 块 C = 座位 6,7,8,9 → `0b11110000` = `0xF0`

判空就是 `mask & BLOCK == 0`。

**第三步：一行最多两块，怎么判？**

注意块 A 和块 C 完全不重叠（A 占 2-5，C 占 6-9），所以「A 空且 C 空」→ 2 块。否则只要 A、B、C 中任意一个空 → 1 块。否则 0 块。这里不需要搜索，因为三块里任意两块要么不重叠（A、C），要么重叠（A、B 共享 4,5；B、C 共享 6,7），重叠的两块不可能同时用，所以「最多 2」只可能由 A+C 达成。

**走一遍示例 1**：`n = 3`，预订 `[[1,2],[1,3],[1,8],[2,6],[3,1],[3,10]]`。

建哈希表（只收座位 2~9）：

- 行 1：座位 2 → 位 0，座位 3 → 位 1，座位 8 → 位 6。mask = `0b01000011` = `0x43`。
- 行 2：座位 6 → 位 4。mask = `0b00010000` = `0x10`。
- 行 3：座位 1 和 10 都被丢弃，行 3 不进表。

精算：

- 行 1：`0x43 & 0x0F = 0x03 ≠ 0`（A 被占）；`0x43 & 0xF0 = 0x40 ≠ 0`（C 被占）；`0x43 & 0x3C = 0x00`（B 空）→ 贡献 1。
- 行 2：`0x10 & 0x0F = 0`（A 空），`0x10 & 0xF0 = 0x10 ≠ 0`（C 被占）→ 不是 A+C 全空，但 A 空 → 贡献 1。

无预订的行数 = `3 - 2 = 1`（行 3 虽然出现在输入里，但它的预订全在 1、10 号位，掩码表里没有它，所以它被算作「无预订行」），贡献 `2 × 1 = 2`。

总计 `1 + 1 + 2 = 4`，与期望一致。

**走一遍示例 3**：`n = 4`，预订 `[[4,3],[1,4],[4,6],[1,7]]`。

- 行 1：座位 4 → 位 2，座位 7 → 位 5。mask = `0b00100100` = `0x24`。
- 行 4：座位 3 → 位 1，座位 6 → 位 4。mask = `0b00010010` = `0x12`。

精算：

- 行 1：`0x24 & 0x0F = 0x04 ≠ 0`；`0x24 & 0xF0 = 0x20 ≠ 0`；`0x24 & 0x3C = 0x24 ≠ 0` → 贡献 0。
- 行 4：`0x12 & 0x0F = 0x02 ≠ 0`；`0x12 & 0xF0 = 0x10 ≠ 0`；`0x12 & 0x3C = 0x10 ≠ 0` → 贡献 0。

无预订行数 = `4 - 2 = 2`，贡献 4。总计 4，与期望一致。

## 4. 正确性：为什么不会漏、不会重

**不变量**：设 `S` 为「掩码表中出现过的行」集合，则答案 = `2 × (n - |S|) + Σ_{r∈S} f(mask[r])`，其中 `f` 是上面那套 0/1/2 的判定。

**为什么不会漏**：

1. 对 `r ∉ S`，该行没有任何 2~9 号座位被预订，块 A（2-5）和块 C（6-9）都全空且不重叠，所以至少能放 2 组；而一行 10 个座位、每块 4 座，最多放 2 组（3 组需要 12 个座位）。故 `f = 2`，公式给的值是紧的。
2. 对 `r ∈ S`，`f` 的三种情况穷尽了所有可能：A、C 都空则放 2；否则若 A/B/C 有一个空则放 1；否则 0。这里要论证「A、C 不都空时不可能放 2」：能放 2 组必须选两个不重叠的块，而三块中只有 (A, C) 不重叠，(A, B) 共享 4、5，(B, C) 共享 6、7，所以 2 组的唯一可能是 A+C。因此判定是完备的。

**为什么不会重**：每行独立计算，行与行之间座位不共享，贡献直接相加；行内 `f` 返回的是该行的最大组数，不是某种具体摆法，不存在「同一组被两行算两次」的问题。另外，座位 1 和 10 被丢弃不影响任何块，因为三个候选块都不含这两列，丢弃是安全的。

## 5. 完整代码（Python）

```python
class Solution:
    def maxNumberOfFamilies(self, n: int, reservedSeats: list[list[int]]) -> int:
        # 三个候选块的位掩码，位 i 对应座位 i+2（即座位 2..9）
        BLOCK_A = 0b00001111  # 座位 2,3,4,5
        BLOCK_B = 0b00111100  # 座位 4,5,6,7
        BLOCK_C = 0b11110000  # 座位 6,7,8,9

        # 只记录 2..9 号座位的占用情况；座位 1、10 与任何块无关，直接忽略
        row_mask = {}
        for row, seat in reservedSeats:
            if 2 <= seat <= 9:
                row_mask[row] = row_mask.get(row, 0) | (1 << (seat - 2))

        # 没有任何有效预订的行，每行固定贡献 2 组
        ans = 2 * (n - len(row_mask))

        # 对每个有预订的行单独精算
        for mask in row_mask.values():
            a_free = (mask & BLOCK_A) == 0
            c_free = (mask & BLOCK_C) == 0
            if a_free and c_free:
                ans += 2          # A 与 C 不重叠，可同时使用
            elif a_free or c_free or (mask & BLOCK_B) == 0:
                ans += 1          # 至少有一个块可用
            # 否则该行贡献 0
        return ans
```

## 6. 复杂度

- **时间**：`O(m)`，`m = len(reservedSeats) ≤ 10^4`。建表遍历 `m` 次，精算遍历「不同行数」次，不同行数 `≤ m`。位运算都是常数时间。**注意这里没有 `n`**：`n` 只参与一次乘法 `2 * (n - len(row_mask))`，是 `O(1)`。
- **空间**：`O(k)`，`k` 是「有 2~9 号预订的不同行数」，`k ≤ m ≤ 10^4`。哈希表每个条目存一个 int。
- 对比朴素解法的 `O(n)` 时间和 `O(n)` 空间，这里把 `n` 从复杂度里彻底消掉了——这正是 `n ≤ 10^9` 而 `m ≤ 10^4` 这组提示数字在暗示的事。

## 7. 边界与反例（至少 4 条）

1. **`n = 1, reservedSeats = [[1,1]]`** → 期望 `2`。易错点：把座位 1 当成占用块 A 的位置，误判成只能放 1 组。座位 1 不在任何块内，必须丢弃。
2. **`n = 1, reservedSeats = [[1,5]]`** → 期望 `1`。座位 5 同时属于块 A 和块 B，A、B 都废了，但 C（6-9）仍空，答案是 1。易错点：只检查块 A 就下结论，或误以为「中间被占就全废」。
3. **`n = 1, reservedSeats = [[1,4],[1,6]]`** → 期望 `0`。座位 4 废 A、B，座位 6 废 B、C，三块全废。易错点：用「A 空或 C 空」的短路逻辑时漏掉 B 的检查，或者反过来把 `elif` 写成只看 A。
4. **`n = 10^9, reservedSeats = [[1,2]]`** → 期望 `2 × (10^9 - 1) + 1 = 1999999999`。易错点：开数组按 `n` 分配内存直接 MemoryError；或者用 `range(1, n+1)` 循环超时。
5. **`n = 2, reservedSeats = [[1,1],[1,10],[2,1],[2,10]]`** → 期望 `4`。两行的预订全在 1、10 号位，掩码表为空，`ans = 2 × 2 = 4`。易错点：把「出现在 reservedSeats 里的行」当成「有冲突的行」，导致少算。

## 8. 面试追问与变体（3 条）

1. **追问：如果四人块的位置集合变了（比如允许 1-4、3-6、5-8、7-10 四个块），代码怎么改？** 思路：只需重算块掩码常量，判定逻辑从「A+C 不重叠」推广为「在块集合上做一次小规模的最大匹配/枚举」，因为块数固定为常数，枚举所有不重叠组合即可，复杂度不变。
2. **追问：如果要求返回具体安排方案而不只是数量？** 思路：对每个有预订的行记录「选了哪几个块」，无预订行统一选 A、C；空间从 `O(k)` 变成 `O(k)` 存块编号，输出时按行号展开，注意 `n` 很大时不能真的展开所有行，要按区间压缩输出。
3. **追问：如果每组不一定是 4 人，而是给定 `k` 人，块的定义随之变化？** 思路：本质仍是「每行独立的一维区间装填」，行内座位数固定为 10，可以预处理所有长度 `k` 的窗口掩码，再对每行做小规模枚举；`n` 大、预订稀疏的结构不变，仍然只精算有预订的行。
