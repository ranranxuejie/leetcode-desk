## 1. 一句话本质

对每个长度为 k 的连续子数组，求其最大值，并按窗口从左到右的顺序输出这些最大值。

## 2. 读完题的第一反应

**朴素解法**：对每个窗口位置，遍历窗口内 k 个元素求最大值。窗口有 n-k+1 个，每个窗口扫 k 个，总复杂度 O(n·k)。当 n=10^5、k 也接近 10^5 时，最坏约 10^10 次操作，必然超时。瓶颈在于：**相邻两个窗口有 k-1 个元素是重叠的，但朴素解法把这 k-1 个元素重新扫了一遍，没有复用上一次的结果。**

**关键观察**：窗口滑动时，左边出去一个元素、右边进来一个元素。如果上一次的最大值还在窗口里，那新窗口的最大值只可能是「旧最大值」和「新进来的元素」二者之一——不需要重新扫。但问题在于：**当旧最大值恰好被移出窗口时，我们得知道「剩下的元素里谁是最大的」**。这就要求我们不仅记住最大值，还要记住一个「按大小排好序的候选队列」，且能快速剔除过期元素。

这个「既要能快速拿到最大值、又要能快速剔除过期元素」的需求，直接指向**单调队列**：队列里元素的值单调递减，队首永远是当前窗口最大值，队尾负责在入队时淘汰掉不可能成为最大值的元素。

## 3. 从暴力到最优

**第一步：暴力 O(n·k)**

以 `nums = [1,3,-1,-3,5,3,6,7], k = 3` 为例，逐个窗口扫：

- 窗口 `[1,3,-1]` → 扫 3 次 → max=3
- 窗口 `[3,-1,-3]` → 扫 3 次 → max=3
- 窗口 `[-1,-3,5]` → 扫 3 次 → max=5
- ……

每个窗口都从头扫，重叠部分白扫了。

**第二步：想用「记住旧最大值」偷懒，但会翻车**

假设我们只维护一个变量 `cur_max`。窗口 `[1,3,-1]` 时 `cur_max=3`。窗口右移到 `[3,-1,-3]`，3 还在，`cur_max` 仍是 3，正确。再右移到 `[-1,-3,5]`，3 被移出了，此时 `cur_max` 失效，我们不知道剩下 `-1,-3` 里谁大——只能重扫。所以「只记一个最大值」不够，**必须记住一个有序的候选集合**。

**第三步：单调队列 O(n)**

维护一个**下标队列** `dq`，队列中下标对应的值**从队首到队尾严格递减**。规则两条：

1. **入队**：新元素 `nums[i]` 入队前，从队尾弹出所有「值 ≤ nums[i]」的下标。理由：这些元素比新元素小（或相等）且更早过期，永远不可能再成为最大值，留着没用。
2. **出队**：如果队首下标 `≤ i-k`，说明它已滑出窗口，弹出。

走一遍 `nums = [1,3,-1,-3,5,3,6,7], k = 3`：

| i | nums[i] | 入队前弹尾 | 队列（存下标） | 队列对应值 | 队首过期？ | 输出 |
|---|---------|-----------|---------------|-----------|-----------|------|
| 0 | 1 | 无 | [0] | [1] | 否 | — |
| 1 | 3 | 弹 0（1≤3） | [1] | [3] | 否 | — |
| 2 | -1 | 无 | [1,2] | [3,-1] | 否 | 3 |
| 3 | -3 | 无 | [1,2,3] | [3,-1,-3] | 否 | 3 |
| 4 | 5 | 弹 3,2,1 | [4] | [5] | 否 | 5 |
| 5 | 3 | 无 | [4,5] | [5,3] | 否 | 5 |
| 6 | 6 | 弹 5,4 | [6] | [6] | 否 | 6 |
| 7 | 7 | 弹 6 | [7] | [7] | 否 | 7 |

输出 `[3,3,5,5,6,7]`，与示例一致。注意 i=4 时，队首下标 1 对应的 3 虽然值大，但被 5 从队尾弹掉了——因为 5 更晚过期且更大，3 再无出头之日。这就是「弹尾」消掉冗余的关键。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在处理完下标 i 之后，队列 `dq` 中存储的下标满足：
- (a) 所有下标都在当前窗口 `[i-k+1, i]` 内（过期元素已被弹出）；
- (b) 下标对应的值从队首到队尾严格递减；
- (c) 当前窗口内的最大值就是队首下标对应的值。

**证明 (c)**：由 (a) 队首在窗口内，由 (b) 队首是队列中最大的。还需说明「窗口内任何不在队列中的元素都不可能是最大值」。一个元素 x 不在队列中只有两种原因：
- 它被从**队尾弹出**：说明它入队时，队尾有一个更晚入队（更晚过期）且值 ≥ x 的元素。x 在窗口内的整个生命周期里，那个更大的元素都还在，所以 x 永远不是最大值——**不会漏**。
- 它被从**队首弹出**：说明它已滑出窗口，不在当前窗口内——**不会误算**。

因此队首就是当前窗口最大值，每个窗口恰好输出一次，**不重不漏**。

## 5. 完整代码（Python）

```python
from collections import deque

class Solution:
    def maxSlidingWindow(self, nums, k):
        dq = deque()          # 存下标，对应值从队首到队尾严格递减
        res = []

        for i, x in enumerate(nums):
            # 1) 入队前：从队尾弹出所有值 <= x 的下标
            #    它们比 x 小且更早过期，永远不可能再当最大值
            while dq and nums[dq[-1]] <= x:
                dq.pop()

            dq.append(i)      # 新元素下标入队

            # 2) 出队：队首下标若已滑出窗口（<= i-k），弹出
            if dq[0] <= i - k:
                dq.popleft()

            # 3) 窗口形成后（i >= k-1），队首即当前窗口最大值
            if i >= k - 1:
                res.append(nums[dq[0]])

        return res
```

注意顺序：**先弹尾、再入队、再弹头、最后取最大值**。弹头放在入队之后是安全的，因为新入队的下标 i 一定 > i-k，不会被误弹。

## 6. 复杂度

- **时间 O(n)**：外层循环 n 次。内层 `while` 每次弹出一个下标，而每个下标**最多入队一次、出队一次**，所以整个循环中 `pop` 总次数 ≤ n。均摊到每次迭代是 O(1)，总计 O(n)。这里没有 log n——不是堆，是双端队列。
- **空间 O(k)**：队列中最多同时存 k 个下标（窗口大小），结果数组 O(n-k+1) 是输出本身，通常不计入辅助空间；若计入则总空间 O(n)。

## 7. 边界与反例（至少 4 条）

1. **`nums=[1], k=1` → `[1]`**：窗口和数组等长，循环只跑一次，`i>=k-1` 即 `0>=0` 成立，正常输出。容易错在把「窗口形成条件」写成 `i > k-1`，导致空结果。
2. **`nums=[1,-1], k=1` → `[1,-1]`**：k=1 时每个元素自成一个窗口。容易错在弹尾用 `<` 而非 `<=`——若用 `<`，相等元素会堆积，虽然本题结果仍对，但在「值相等」的变体里会出问题；用 `<=` 更稳。
3. **`nums=[7,2,4], k=2` → `[7,4]`**：i=1 时队尾 7>2 不弹，队列 `[0,1]`；i=2 时 4 弹掉 2（2≤4），队列 `[0,2]`，但队首 0 已满足 `0 <= 2-2=0`，被弹出，剩 `[2]`，输出 4。容易错在**弹头判断用 `<` 而非 `<=`**：`0 <= 0` 必须弹，否则会输出过期的 7。
4. **`nums=[1,3,1,2,0,5], k=3` → `[3,3,2,5]`**：i=3 时窗口 `[3,1,2]`，队首 3（下标1）仍在窗口内（`1 > 3-3=0`），不弹，输出 3；i=4 时窗口 `[1,2,0]`，下标1 满足 `1 <= 4-3=1`，弹出，队首变 2，输出 2。容易错在弹头时机——必须在**每轮入队后**检查，而不是只在窗口形成后检查。
5. **全递减 `nums=[5,4,3,2,1], k=3` → `[5,4,3]`**：弹尾从不触发，队列长度一直增长到 k，靠弹头维持窗口。容易错在以为「单调队列长度恒为 1」，实际它可以是 k。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回每个窗口的最小值？** 思路：把「弹尾条件」从 `nums[dq[-1]] <= x` 改成 `>= x`，队列变成单调递增，队首即最小值，其余逻辑不变。
2. **追问：滑动窗口的中位数（数据流中位数变体）？** 思路：单调队列只能维护极值，中位数需要两个堆（大顶堆 + 小顶堆）配合延迟删除，复杂度 O(n log k)。
3. **追问：窗口大小不固定，而是「和 ≤ target 的最长窗口」？** 思路：这是滑动窗口 + 双指针的另一类题，用左右指针维护窗口和，不涉及单调队列，考察的是「窗口收缩条件」的推导。
