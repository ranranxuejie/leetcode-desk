## 1. 一句话本质

求「用 1 和 2 凑出 n 的有序拆分方案数」——注意是**有序**（1+2 和 2+1 算两种），这正是它和整数拆分题的分水岭。

## 2. 读完题的第一反应

**朴素解法**：枚举所有由 1、2 组成的序列，看哪些和等于 n。这等价于对每个位置做「走 1 还是走 2」的二叉决策，叶子数约 2^n，n=45 时是 3.5×10¹³ 量级，必然超时。瓶颈在于：**大量不同的决策路径会落到同一个台阶上，却被重复展开**。

**关键观察**：站在第 i 阶时，你只可能来自两个地方——第 i-1 阶（再走 1 步）或第 i-2 阶（再走 2 步）。而且「怎么到达第 i-1 阶」和「怎么到达第 i-2 阶」这两批方案**互不重叠**（最后一步长度不同），合起来又**覆盖全部**（最后一步只能是 1 或 2）。于是：

> f(i) = f(i-1) + f(i-2)

这一步把「指数级的路径枚举」压成了「线性递推」。为什么能想到？因为题目给了「每次只能 1 或 2」这个**有限步长**，有限步长意味着「按最后一步分类」只有常数种情况——这是所有「走法计数」类 DP 的通用起手式。

## 3. 从暴力到最优

以 n = 5 为例，走三步。

**第一步：暴力递归**。`f(5) = f(4) + f(3)`，`f(4) = f(3) + f(2)`……画出来是一棵二叉树，`f(3)` 被算了 2 次，`f(2)` 被算了 3 次，`f(1)` 被算了 5 次。n 越大，重复越夸张，重复次数本身就是斐波那契增长。

**第二步：记忆化**。开一个数组 `memo`，算过的直接取。还是 n=5，但每个 `f(i)` 只真正计算一次，树被「剪」成一条链。复杂度从 O(2^n) 降到 O(n)。瓶颈消掉了，但代价是 O(n) 的递归栈 + 哈希/数组开销。

**第三步：自底向上 + 滚动变量**。既然 `f(i)` 只依赖前两项，就没必要存整张表。用两个变量滚动：

```
n=5 的迭代过程（a=f(i-2), b=f(i-1)）：
初始 a=1 (f0), b=1 (f1)
i=2: a,b = 1, 2      → f2=2
i=3: a,b = 2, 3      → f3=3
i=4: a,b = 3, 5      → f4=5
i=5: a,b = 5, 8      → f5=8
```

答案 8。空间从 O(n) 降到 O(1)。注意 `f(0)=1` 这个初值不是「0 阶有 1 种爬法」的物理直觉，而是为了让 `f(2)=f(1)+f(0)=1+1=2` 成立——它是递推的**边界补丁**，后面第 7 节会专门说。

## 4. 正确性：为什么不会漏、不会重

用**划分不变量**来证。定义 S(i) 为到达第 i 阶的所有方案集合，要证 |S(i)| = f(i)。

**不重**：对任意方案 p ∈ S(i)，看它的最后一步。最后一步长度只能是 1 或 2（题面约束），所以 p 必属于「最后一步为 1」或「最后一步为 2」二者之一，且不可能同时属于两者（一步的长度是唯一确定的）。因此 S(i) = A ∪ B 且 A ∩ B = ∅，其中 A 是最后一步为 1 的方案、B 是最后一步为 2 的方案。

**不漏**：A 中的方案去掉最后那一步 1，剩下的恰好是到达第 i-1 阶的某个方案，且这个映射是双射（可逆：任何到达 i-1 的方案补一个 1 就回到 A）。所以 |A| = |S(i-1)| = f(i-1)。同理 |B| = f(i-2)。

合起来 |S(i)| = f(i-1) + f(i-2)，归纳成立。**关键就在「按最后一步分类」这个划分同时满足不重和不漏**——这是这类计数 DP 正确性的标准论证模板，面试时把这两句说出来就够了。

## 5. 完整代码（Python）

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        # 边界：n=1 时只有「1」一种走法，直接返回，避免下面循环不执行时返回错值
        if n <= 2:
            return n

        # a 代表 f(i-2)，b 代表 f(i-1)
        # 初值取 f(0)=1, f(1)=1：f(0)=1 是为了让 f(2)=f(1)+f(0)=2 成立
        a, b = 1, 1

        # 从第 2 阶推到第 n 阶，每轮把 (a,b) 右移一格
        for i in range(2, n + 1):
            a, b = b, a + b   # 新的 f(i) = f(i-1) + f(i-2)，同时旧的 b 降级为新的 a

        return b  # 循环结束时 b 就是 f(n)
```

如果面试官要你先讲思路再优化，可以按这个顺序给三版：递归 → 加 `memo` 字典 → 上面这版滚动变量。三版代码骨架完全一样，只是「存不存、存多少」在变，这正好体现优化的主线。

## 6. 复杂度

**时间 O(n)**：循环从 i=2 跑到 i=n，共 n-1 次迭代，每次迭代只做一次加法和两次赋值，是常数操作。n 来自题面的台阶数上限 45，所以实际运算量极小。这里**没有 log n 的项**——因为没有任何「折半」操作（没有二分、没有快速幂）。如果面试官追问「能不能 O(log n)」，那要靠矩阵快速幂或斐波那契通项公式，属于变体，见第 8 节。

**空间 O(1)**：只用了 `a`、`b` 两个整型变量，与 n 无关。对比记忆化版本的 O(n) 数组和 O(n) 递归栈，这是滚动数组带来的收益。注意 Python 的大整数不占额外渐进空间（n≤45 时结果远小于 2^63）。

## 7. 边界与反例（至少 4 条）

1. **n = 1** → 期望 1 → 容易错在：如果只写 `if n == 2: return 2` 然后进循环，n=1 时循环不执行、返回未初始化的值或 0。必须用 `n <= 2` 兜住。
2. **n = 2** → 期望 2 → 容易错在：把 `f(0)` 设成 0 而不是 1，导致 `f(2)=f(1)+f(0)=1+0=1`，少算一种。这是本题最经典的初值坑。
3. **n = 3** → 期望 3 → 容易错在：误以为「1+2 和 2+1 是同一种」，按组合数去重，得到 2。题面示例 2 明确把两者列为不同方法，说明是**有序**计数。
4. **n = 45** → 期望 1836311903 → 容易错在：用递归不记忆化，直接超时或爆栈；另外若用某些语言 32 位 int 会溢出（本题结果在 int32 范围内，但变体如「每次 1/2/3 步」在 n=45 时会溢出，需留意）。
5. **n = 0（题面不出现，但面试常追问）** → 按递推约定返回 1（空方案）→ 容易错在：返回 0 会破坏 `f(2)=f(1)+f(0)` 的链条。要能说清「这是递推边界约定，不是物理意义」。

## 8. 面试追问与变体（3 条）

1. **追问：n 扩大到 10^9，还能 O(n) 吗？** → 思路：递推是线性的，用矩阵快速幂 `[[1,1],[1,0]]^n`，O(log n) 时间；或直接用斐波那契通项公式（浮点精度在超大 n 下不可靠，慎用）。
2. **追问：每次可以爬 1、2、3 阶呢？** → 思路：`f(i)=f(i-1)+f(i-2)+f(i-3)`，滚动三个变量即可，空间仍 O(1)；本质是「按最后一步长度分类」的推广。
3. **追问：如果某些台阶是「坏台阶」不能踩呢？** → 思路：遇到坏台阶令 `f(i)=0`，递推照常跑，相当于在状态转移时把该状态清零，是 DP 加约束的标准做法。

## 9. 举一反三（2-3 道同类题）

- **LeetCode 746 使用最小花费爬楼梯**：同样是「最后一步 1 或 2」，但求的是最小代价而非方案数，把 `+` 换成 `min` 即可。
- **LeetCode 509 斐波那契数**：递推式完全同构，本题就是它的一个应用题外壳，滚动变量写法可原样复用。
- **LeetCode 91 解码方法**：也是「按最后一段长度（1 位或 2 位）分类」的计数 DP，区别在于要额外判断合法性，是本题「分类不重不漏」思路的直接迁移。
