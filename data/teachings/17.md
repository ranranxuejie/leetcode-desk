## 1. 一句话本质

把输入数字串的每一位“翻译”成它对应的若干候选字母，然后从每一位的候选集合里各挑一个字母，枚举出所有可能的“逐位选择组合”。

---

## 2. 读完题的第一反应

**朴素解法是什么？** 最直接的想法：如果 `digits` 长度固定是 2，那就写两层循环；长度是 3 就写三层循环。也就是“有几层就写几层 for”。

**它卡在哪？** 题面给的约束是 `1 <= digits.length <= 4`，看起来层数不多，但注意——**层数是输入决定的，不是代码里写死的**。你没法在写代码时知道要嵌套几层。这就是瓶颈：**循环层数依赖运行时数据**，静态的 for 嵌套表达不了。而且就算硬编码到 4 层，一旦题目把长度放宽到 10，代码直接作废。

**关键观察是什么？** 把问题拆成“逐位决策”：第 0 位选哪个字母、第 1 位选哪个字母……每一位的选择只依赖当前数字，且**每一位的选择互不干扰**，只是最后要拼成一个完整串。这种“每一步从候选集里选一个、选完进入下一步、走到底收集结果”的结构，正是**回溯（DFS）** 的典型形态——用递归代替“动态层数的循环”，递归深度天然等于 `digits` 长度。

这个观察直接把你从“写不出循环”带到“写一个递归函数，参数是当前处理到第几位 + 已经拼好的前缀”。

---

## 3. 从暴力到最优

**暴力版本（思想实验）**：假设长度最多 4，写 4 层嵌套 for，每层遍历当前数字的字母，最内层把 4 个字母拼起来。复杂度是各位置字母数的乘积，也就是答案个数本身。这个复杂度**已经是最优下界**了——因为你要输出所有组合，输出本身就有这么多。所以这题不存在“从 O(指数) 优化到 O(多项式)”的空间，**瓶颈不在复杂度，而在“如何用代码表达不定层数的枚举”**。

**回溯版本**：用一个递归函数 `dfs(index, path)`，`index` 表示正在处理第几位，`path` 是已经拼好的前缀。

拿 `digits = "23"` 走一遍，映射 `2 -> "abc"`，`3 -> "def"`：

```
dfs(0, "")            # 处理第0位，数字'2'
  ├─ 选'a' → dfs(1, "a")   # 处理第1位，数字'3'
  │    ├─ 选'd' → dfs(2, "ad") → index==2 到底，收集 "ad"
  │    ├─ 选'e' → dfs(2, "ae") → 收集 "ae"
  │    └─ 选'f' → dfs(2, "af") → 收集 "af"
  ├─ 选'b' → dfs(1, "b")
  │    ├─ 'd' → 收集 "bd"
  │    ├─ 'e' → 收集 "be"
  │    └─ 'f' → 收集 "bf"
  └─ 选'c' → dfs(1, "c")
       ├─ 'd' → 收集 "cd"
       ├─ 'e' → 收集 "ce"
       └─ 'f' → 收集 "cf"
```

中间变量 `path` 的变化轨迹：`"" → "a" → "ad"`（收集）`→ "a" → "ae"`（收集）……每次从 `dfs(index+1)` 返回后，`path` 要**回退**到进入前的状态，才能试下一个字母。这就是“回溯”二字的来源：**前进时加一个字符，返回时删掉它**。

对比一下：暴力嵌套 for 的“层数”被递归深度替代了，`index` 走到 `len(digits)` 就到底。瓶颈（动态层数）被消掉了，而枚举总量不变——这已经是最优。

---

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：在调用 `dfs(index, path)` 的那一刻，`path` 恰好是“前 `index` 位数字各选了一个字母”拼成的串，且 `path` 的长度等于 `index`。

- **初始**：`dfs(0, "")`，前 0 位没选，`path` 为空，长度 0 = index，成立。
- **保持**：在 `dfs(index, path)` 中，对第 `index` 位数字的每个候选字母 `c`，调用 `dfs(index+1, path+c)`。进入时 `path+c` 是前 `index+1` 位各选一个的结果，长度 `index+1`，不变量保持。
- **终止**：当 `index == len(digits)`，`path` 是全部位各选一个字母的完整串，收集它。

**不漏**：任意一个合法答案，都是“第 0 位选某字母、第 1 位选某字母……”。按这个选择序列，递归会唯一地沿着对应分支走下去，最终在叶子处被收集。所以每个答案都有一条路径到达。

**不重**：每个答案对应一个**唯一的选择序列**（第 i 位选的是哪个字母是确定的）。递归树中，从根到叶的路径与选择序列一一对应，不同选择序列走不同分支，因此同一答案不会被收集两次。

这两条合起来：**解集 = 递归树所有叶子所代表的串，且是一一对应**。所以既不漏也不重。

## 5. 完整代码（Python）

```python
class Solution:
    def letterCombinations(self, digits: str) -> list[str]:
        # 空输入直接返回空列表（题面约束 length>=1，但防御性处理更稳）
        if not digits:
            return []

        # 数字到字母的映射，用列表下标对齐字符 '2'~'9'
        phone = {
            '2': 'abc', '3': 'def', '4': 'ghi', '5': 'jkl',
            '6': 'mno', '7': 'pqrs', '8': 'tuv', '9': 'wxyz'
        }

        res = []          # 收集所有完整组合
        path = []         # 当前前缀，用 list 便于 append/pop 回溯

        def dfs(index: int) -> None:
            # 终止条件：所有位都选完了，path 就是一个完整答案
            if index == len(digits):
                res.append(''.join(path))   # 拼成字符串存入结果
                return

            # 取出当前位数字对应的候选字母串
            letters = phone[digits[index]]
            for ch in letters:
                path.append(ch)      # 做选择：加入当前字母
                dfs(index + 1)       # 进入下一位
                path.pop()           # 撤销选择：回退，试下一个字母

        dfs(0)            # 从第 0 位、空前缀开始
        return res
```

关键点说明：`path` 用 `list` 而不是字符串拼接，是因为 `append/pop` 是 O(1)，而 `path + ch` 每次都会新建字符串（O(长度)）。虽然本题长度 ≤ 4 影响不大，但这是回溯的**标准写法**，值得养成习惯。

## 6. 复杂度

设 `digits` 长度为 `n`，第 `i` 位数字对应的字母个数为 `k_i`（取值 3 或 4，`7` 和 `9` 是 4 个，其余是 3 个）。

**答案个数** = `k_0 × k_1 × ... × k_{n-1}`，记作 `M`。

- **时间复杂度：O(M · n)**。递归树有 `M` 个叶子，每个叶子收集答案时要 `''.join(path)`，耗时 O(n)；树的总节点数是 O(M) 量级（每层节点数不超过叶子数乘以常数），每个非叶节点做 O(1) 的 append/pop。所以总量是 `M` 个答案 × 每个答案 O(n) 的拼接 = **O(M·n)**。这里的 `n` 来自“每个答案长度是 n，拼接要遍历 n 个字符”。
- **空间复杂度：O(n)**（不计输出）。递归深度最大为 `n`，`path` 长度最大为 `n`，两者都是 O(n)。**注意**：如果把返回的 `res` 算进去，是 O(M·n)——`M` 个答案、每个长度 `n`。面试时通常说“额外空间 O(n)，输出空间 O(M·n)”。

这里没有 log 项，因为不涉及排序或二分。

## 7. 边界与反例（至少 4 条）

1. **`digits = "2"`** → `["a","b","c"]`。容易错在：把单字符输入当成“没有组合”返回空，或者递归终止条件写成 `index == len(digits) - 1` 导致少走一层。
2. **`digits = "7"`** → `["p","q","r","s"]`。容易错在：映射表把 `7` 写成 3 个字母（`pqrs` 是 4 个），漏掉 `s`。`9` 同理是 `wxyz`。
3. **`digits = "79"`** → 16 个组合（4×4）。容易错在：以为所有数字都是 3 个字母，按 3×3=9 去估算或写死循环上界。
4. **`digits = ""`（空串）** → 期望 `[]`。容易错在：不加空串判断，`dfs(0)` 会因 `index == len(digits) == 0` 直接收集一个空串 `""`，返回 `[""]` 而不是 `[]`。这是本题最经典的坑——**空输入应返回空列表，而不是含一个空串的列表**。
5. **`digits = "2222"`** → 3^4 = 81 个组合。容易错在：以为长度 4 就“很小”，实际输出 81 个串，若用字符串拼接而非 list 回溯，常数会偏大（虽不影响正确性）。

## 8. 面试追问与变体（3 条）

1. **追问：如果数字 1 也要映射（比如映射到空或某个符号），怎么改？** 思路：在 `phone` 字典里补上 `'1'` 的映射；若映射为空串，则 `for ch in ""` 不执行，该分支自然消失——但要确认题意是“跳过”还是“无解”，据此决定是否提前返回。
2. **追问：不用递归，用迭代（BFS 式）怎么写？** 思路：维护一个结果列表，初始为 `[""]`；对 `digits` 每一位，把当前列表里每个串与当前位每个字母做笛卡尔积，生成新列表替换旧列表。本质是“按层扩展”，和回溯的递归树是同一棵树的两种遍历顺序。
3. **追问：如果要求按字典序输出，怎么保证？** 思路：映射表里每个数字的字母本身按字母序排列（`abc`、`def`…），回溯时按顺序遍历候选字母，DFS 的叶子收集顺序天然就是字典序，无需额外排序。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 46. 全排列**：共同点是“逐位从候选集选一个、选完进入下一位、到底收集”，区别是候选集随已选元素动态变化（需要 used 标记），回溯骨架完全一致。
2. **LeetCode 78. 子集**：共同点是回溯枚举所有选择组合；区别是“每个元素选或不选”而非“每位从多个字母里选一个”，是二叉决策树而非多叉。
3. **LeetCode 22. 括号生成**：共同点是递归 + 前缀 + 回溯撤销；区别是候选字母受“左右括号数量约束”动态限制，考察的是“在回溯中加剪枝条件”。
