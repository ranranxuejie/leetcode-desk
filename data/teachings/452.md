## 1. 一句话本质

给定一堆闭区间，求用最少的点去「扎穿」所有区间——一个点能扎穿所有包含它的区间。

## 2. 读完题的第一反应

**朴素解法**：把 x 轴离散化，枚举所有可能的射击位置组合，找最小的能覆盖全部区间的点集。这是集合覆盖问题的一个特例，而集合覆盖是 NP-hard 的，暴力枚举是指数级。即使不这么悲观，一个自然的贪心雏形是「每支箭尽量多扎气球」，但「尽量多」怎么定义？如果随便选一个位置，可能扎到 3 个气球，但剩下的气球分布很散，总数反而多。所以朴素思路卡在：**没有一个明确的「选点标准」**。

**关键观察**：所有区间都是闭区间，且「一个点扎穿多个区间」等价于「这些区间有公共交点」。于是问题变成：把区间分成最少的组，每组区间有公共交点。再进一步——如果按区间的**右端点**从小到大排序，那么第一个区间的右端点 `end` 就是一个「最紧迫」的位置：任何要扎穿第一个区间的箭，位置必须 ≤ `end`；而把箭放在 `end` 处，能扎穿所有左端点 ≤ `end` 的区间（因为它们的右端点 ≥ 第一个区间的右端点 ≥ `end`，所以只要左端点 ≤ `end`，`end` 就落在它们内部）。这就是贪心的抓手：**每次把箭放在当前未覆盖区间中右端点最小的那个位置**。

## 3. 从暴力到最优

**暴力**：枚举所有射击位置组合。对 n 个区间，候选位置最多 2n 个端点，组合数爆炸，不可行。

**第一步优化——排序**：把区间按右端点升序排列。为什么是右端点而不是左端点？因为「箭的位置」受右端点约束更紧：一个区间 `[l, r]` 要求箭 ≤ r，而 r 越小，约束越强。先处理约束最强的区间，箭放在它的 r 处，能覆盖的区间最多。

**第二步——线性扫描**：维护一个变量 `arrow_pos`，表示上一支箭的位置。遍历排序后的区间：
- 如果当前区间的左端点 `l > arrow_pos`，说明上一支箭扎不到它，必须新射一支，位置放在当前区间的右端点 `r`，箭数 +1。
- 否则，当前区间被上一支箭覆盖，跳过。

**小例子走一遍**：`points = [[10,16],[2,8],[1,6],[7,12]]`

按右端点排序后：`[[1,6],[2,8],[7,12],[10,16]]`

| 步骤 | 区间 | arrow_pos | 判断 | 箭数 |
|------|------|-----------|------|------|
| 初始 | — | -∞ | — | 0 |
| 1 | [1,6] | -∞ | 1 > -∞，新箭，arrow_pos=6 | 1 |
| 2 | [2,8] | 6 | 2 ≤ 6，被覆盖 | 1 |
| 3 | [7,12] | 6 | 7 > 6，新箭，arrow_pos=12 | 2 |
| 4 | [10,16] | 12 | 10 ≤ 12，被覆盖 | 2 |

结果 2，与示例一致。

再看示例 3：`[[1,2],[2,3],[3,4],[4,5]]`，已按右端点排序。

| 步骤 | 区间 | arrow_pos | 判断 | 箭数 |
|------|------|-----------|------|------|
| 1 | [1,2] | -∞ | 新箭，arrow_pos=2 | 1 |
| 2 | [2,3] | 2 | 2 ≤ 2，被覆盖（闭区间，端点重合算覆盖） | 1 |
| 3 | [3,4] | 2 | 3 > 2，新箭，arrow_pos=4 | 2 |
| 4 | [4,5] | 4 | 4 ≤ 4，被覆盖 | 2 |

结果 2。注意第 2 步的 `2 ≤ 2` 是闭区间的关键——如果写成 `l < arrow_pos` 就会错。

## 4. 正确性：为什么不会漏、不会重

用**交换论证**说明贪心最优。

设排序后第一个区间为 `I₁ = [l₁, r₁]`，贪心把第一支箭放在 `r₁`。考虑任意一个最优解，它一定有一支箭 `p` 扎穿了 `I₁`，即 `l₁ ≤ p ≤ r₁`。把 `p` 移到 `r₁`：原来被 `p` 扎穿的区间 `[l, r]` 满足 `l ≤ p ≤ r`，由于 `p ≤ r₁` 且 `l ≤ p ≤ r₁`，所以 `r₁` 也落在 `[l, r]` 内（需要 `r ≥ r₁`，而排序保证 `r ≥ r₁`）。因此把 `p` 移到 `r₁` 不会减少覆盖的区间数，箭数不变。于是存在一个最优解，第一支箭就在 `r₁`。删掉被 `r₁` 覆盖的区间，对剩余区间递归，贪心每一步都等价于某个最优解的前缀，故总箭数最少。

**不变量**：扫描到第 i 个区间时，`arrow_pos` 是当前已射出的最后一支箭的位置，且所有前 i-1 个区间都已被覆盖。每次 `l > arrow_pos` 时新射的箭放在 `r`，保证覆盖当前区间且不浪费（放在 `r` 是能覆盖当前区间的最大位置，对后续区间最有利）。

## 5. 完整代码（Python）

```python
class Solution:
    def findMinArrowShots(self, points: list[list[int]]) -> int:
        if not points:
            return 0

        # 按右端点升序排序：右端点越小，约束越紧，优先处理
        points.sort(key=lambda p: p[1])

        arrows = 1                      # 至少需要一支箭
        arrow_pos = points[0][1]        # 第一支箭放在第一个区间的右端点

        for l, r in points[1:]:
            if l > arrow_pos:
                # 当前区间左端点超过上一支箭的位置，必须新射一支
                arrows += 1
                arrow_pos = r           # 新箭放在当前区间右端点
            # 否则当前区间被上一支箭覆盖，什么都不做

        return arrows
```

## 6. 复杂度

- **时间 O(n log n)**：排序贡献 O(n log n)，其中 n 是区间个数；线性扫描贡献 O(n)。总复杂度由排序主导。
- **空间 O(1)**（不计排序本身）：只用了 `arrows` 和 `arrow_pos` 两个变量。Python 的 `sort` 是 Timsort，最坏额外空间 O(n)，但算法逻辑本身是常数空间。

## 7. 边界与反例（至少 4 条）

1. **输入 `[[1,2]]`** → 期望 `1`。容易错：初始化 `arrows = 0` 然后循环里判断，导致单区间返回 0。代码里初始化为 1 并单独处理第一个区间，避免此问题。

2. **输入 `[[1,2],[2,3]]`** → 期望 `1`。容易错：把覆盖条件写成 `l < arrow_pos`（严格小于），则 `2 < 2` 为假，误判需要第二支箭。闭区间端点重合必须算覆盖，用 `l > arrow_pos` 判断「不覆盖」才正确。

3. **输入 `[[1,10],[2,3],[4,5]]`** → 期望 `1`。容易错：按左端点排序后贪心，可能先处理 `[1,10]` 把箭放在 10，再处理 `[2,3]` 发现 `2 ≤ 10` 覆盖，看似没问题；但如果数据是 `[[1,10],[2,3],[4,5],[6,7]]` 且按左端点排序，箭放 10 仍覆盖全部，结果对。真正的反例是按左端点排序后把箭放在第一个区间的**左端点**：`[[1,10],[2,3]]` 箭放 1，`[2,3]` 的左端点 2 > 1，误判需要两支箭。必须按右端点排序且箭放右端点。

4. **输入 `[[1,2],[3,4],[5,6],[7,8]]`** → 期望 `4`。容易错：相邻区间端点不重合（2 < 3），每支箭只能扎一个，若误以为「相邻就合并」会返回 2 或 3。

5. **输入 `[[-2^31, 2^31-1]]`** → 期望 `1`。容易错：用 `float('inf')` 做初始 `arrow_pos` 比较时，大整数与 inf 比较在 Python 中没问题，但若用固定大常数如 `10^9` 会误判。代码用第一个区间的右端点初始化，天然规避。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求输出具体的射击位置而不是数量？** 思路：贪心过程中记录每次新射箭的 `arrow_pos`，最后返回列表即可，逻辑不变。

2. **追问：如果区间是开区间 `(l, r)` 呢？** 思路：覆盖条件从 `l ≤ arrow_pos` 变为 `l < arrow_pos`（因为开区间端点不能取），且箭放在 `r` 时不再覆盖右端点为 `r` 的区间，需要调整为放在 `r - ε` 或重新推导。核心变化是端点处理。

3. **追问：如果每个气球有一个「引爆收益」，求最大收益而非最少箭数？** 思路：变成加权区间覆盖/最大权独立集问题，贪心不再适用，需要动态规划（按右端点排序后 DP，`dp[i] = max(dp[i-1], weight[i] + dp[prev(i)])`，其中 `prev(i)` 是最后一个与 i 不重叠的区间）。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 435. 无重叠区间**：同样按右端点排序贪心，求最多保留多少个互不重叠的区间，本质是「用最少的删除让区间不重叠」，与本题的「用最少的点覆盖所有区间」是同一套排序+扫描框架。

2. **LeetCode 56. 合并区间**：按左端点排序后合并重叠区间，虽然排序键不同，但核心都是「排序后线性扫描，维护当前区间的边界」，与本题共享「排序消掉乱序、扫描维护不变量」的思维模式。

3. **LeetCode 253. 会议室 II**：求最少会议室数使所有会议不冲突，等价于求最大重叠区间数，用扫描线或最小堆，与本题的「区间覆盖」是互补视角——本题求最少点覆盖所有区间，那题求最大同时重叠数。
