## 1. 一句话本质

把 k 条已经各自有序的链，**归并**成一条全局有序的链——本质是「多路归并」，核心矛盾是**每次从 k 个候选头结点里挑最小的那个**。

## 2. 读完题的第一反应

最朴素的想法：既然每条链都有序，那就每次从 k 条链的**当前头结点**里挑最小的接上去，挑完把那条链的头往后挪一格。这个思路本身没错，问题在「挑最小」这一步：如果每轮都线性扫一遍 k 个头结点，一轮 O(k)，总共要挑 n 次（n 是全部结点总数），复杂度 O(nk)。看提示：k 最大 10⁴，n 最大 10⁴，最坏 10⁸，Python 里基本会超时。

关键观察有两个，分别通向两条不同的路：

- **观察一（堆）**：每轮只需要「k 个候选里的最小值」，这是一个典型的**动态取最值**场景，用最小堆把「挑最小」从 O(k) 降到 O(log k)。为什么能想到？因为候选集合大小固定为 k、且每次只换掉一个元素，正是堆的适用形态。
- **观察二（分治）**：先把两条链合并成一条（这是第 21 题「合并两个有序链表」，O(m+n)），再把结果两两合并。为什么能想到？因为「合并两个」是已知的、线性的、简单的操作，而 k 条链的合并可以拆成若干次两两合并——**把不会做的问题化归成会做的问题**。

两条路都能到 O(n log k)，下面主推分治（代码短、无额外数据结构），堆作为对照讲。

## 3. 从暴力到最优

**暴力（逐个头结点线性扫描）**：以示例 1 为例，三条链头分别是 1、1、2，扫一遍取 1（第一条），接上，第一条头变 4；再扫 1、4、2 取 1（第二条），接上，第二条头变 3；再扫 4、3、2 取 2……每接一个结点扫 k 次，n 个结点共 nk 次比较。

**瓶颈在哪**：k 个头结点里，除了刚被取走的那条链换了个新头，其余 k−1 个候选**完全没变**。线性扫描把这 k−1 个「已知不是最小」的信息全扔了，每轮重新比一遍。堆的价值就是**把这 k−1 份信息缓存下来**：堆里始终存着 k 个当前头，取走最小后只 push 进一个新头，其余不动，调整代价 O(log k)。

**分治怎么消掉瓶颈**：换个角度，不做「n 次挑最小」，而做「log k 层两两合并」。

具体走一遍示例 1，lists = [L0:1→4→5, L1:1→3→4, L2:2→6]：

- 第 1 层：合并 L0 和 L1 → `1→1→3→4→4→5`（记作 A）；L2 单独，本轮结果 [A, L2]。
- 第 2 层：合并 A 和 L2 → `1→1→2→3→4→4→5→6`。

对比一下代价：合并两个长度 m、n 的链是 O(m+n)，每个结点在**每一层**恰好被访问一次，层数是 ⌈log₂k⌉，所以总代价 O(n log k)。k=3 时层数 2，n=8 时约 16 次操作，而暴力是 8×3=24 次——k 越大差距越悬殊（k=10⁴ 时 log k≈14，暴力是 10⁴）。

**为什么分治比「依次合并」好**：如果写成 `merge(merge(merge(L0,L1),L2),L3)...`，第 i 次合并时左边已经累积了前 i 条链的全部结点，长链反复被扫，总代价退化成 O(nk)，和暴力一个量级。分治保证**每条链在每一层只参与一次合并**，长链不会反复被搬。这是本题最容易写错的地方，务必用「两两配对」而不是「逐个累加」。

## 4. 正确性：为什么不会漏、不会重

**不变量（针对分治）**：设当前待合并的链集合为 S，我们断言「把 S 中所有链合并后的结果，等于把 S 按任意方式两两配对、各自合并、再递归合并所得的结果」。证明用**结合律**：合并运算 merge 满足 `merge(merge(A,B),C) = merge(A,merge(B,C))`，因为两边都是「把 A、B、C 的全部元素按升序排成一条链」，而多重集合的升序排列唯一。所以配对方式不影响最终结果，分治的任意配对都正确。

**不变量（针对单次两两合并）**：合并 A、B 时，用双指针 pa、pb，每次取较小者接到结果尾部。不变量是「结果链已接部分 = A、B 已消耗部分的升序归并，且剩余未接部分仍各自有序」。取 min(pa, pb) 接上，是因为 pa、pb 分别是各自剩余部分的**最小元**，全局剩余最小元必在二者之中，故接它不会漏掉更小的；每个结点只被接一次，故不重。指针走完一条链后把另一条整段接上，剩余部分有序性由前提保证。

两条不变量合起来：分治保证「拆法不影响答案」，双指针保证「每次合并正确」，归纳即得整体正确。

## 5. 完整代码（Python）

```python
class Solution:
    def mergeKLists(self, lists):
        # 边界：空数组直接返回 None
        if not lists:
            return None

        # 分治：每轮把相邻两条链合并，规模减半，直到只剩一条
        while len(lists) > 1:
            merged = []
            # 步长 2 两两配对；i 每次 +2
            for i in range(0, len(lists), 2):
                l1 = lists[i]
                # 若本轮落单（奇数个），l2 取 None，merge 会原样返回 l1
                l2 = lists[i + 1] if i + 1 < len(lists) else None
                merged.append(self._merge_two(l1, l2))
            lists = merged  # 用本轮结果替换，进入下一层

        return lists[0]

    def _merge_two(self, a, b):
        # 标准「合并两个有序链表」，dummy 简化头结点处理
        dummy = ListNode(0)
        tail = dummy
        while a and b:
            if a.val <= b.val:   # <= 保证稳定性，相等时先取 a
                tail.next = a
                a = a.next
            else:
                tail.next = b
                b = b.next
            tail = tail.next
        # 一条走完后，另一条剩余部分整体接上（已有序）
        tail.next = a if a else b
        return dummy.next
```

（`ListNode` 由判题环境提供；本地跑需自行定义 `__init__(self, val=0, next=None)`。）

## 6. 复杂度

- **时间 O(n log k)**：n 是全部结点总数（提示里「lists[i].length 总和 ≤ 10⁴」就是 n 的上界），k 是链表条数。每一层合并，所有结点恰好被访问一次，贡献 O(n)；层数是 ⌈log₂k⌉（每轮规模减半），贡献 log k 因子。相乘即得。注意 n 来自「结点总数」，log k 来自「分治层数」，两者来源不同，别混。
- **空间 O(1) 额外（不计输出）**：分治是迭代写法，只用了 `merged` 列表，其大小从 k 逐层减半，峰值 O(k)；递归版 `_merge_two` 是迭代的，没有递归栈。若把 `merged` 算进去，额外空间 O(k)。输出链表本身占 O(n)，但那是必须返回的结果，通常不计入额外空间。

对照：堆解法时间同为 O(n log k)（每次 push/pop O(log k)，共 n 次），额外空间 O(k) 存堆。

## 7. 边界与反例（至少 4 条）

1. **lists = []** → 期望 `[]`（返回 None）。易错：直接 `lists[0]` 或进 while 前不判空，IndexError。
2. **lists = [[]]** → 期望 `[]`。易错：以为「有一条空链」就非空，实际合并后仍是 None；分治里 `_merge_two(None, None)` 要能返回 None（代码里 dummy.next 即 None，正确）。
3. **lists = [[], [1], []]** → 期望 `[1]`。易错：把空链当特殊值处理，或在堆解法里 push 了 None 导致比较报错。
4. **lists = [[1], [1], [1]]** → 期望 `[1,1,1]`。易错：`_merge_two` 里用 `<` 而非 `<=` 本身不影响结果，但若误写成「相等时丢弃」就会漏结点；另外要确认三个相同值都被接上。
5. **k 为奇数（如 3 条链）** → 分治第二轮会落单。易错：`i+1` 越界；代码用 `if i + 1 < len(lists) else None` 兜住，`_merge_two(l1, None)` 原样返回 l1。

## 8. 面试追问与变体（3 条）

1. **追问：如果 k 远大于 n（比如 10⁴ 条链但总共才 10 个结点），分治还合适吗？** 思路：分治仍正确，但大量空链参与配对浪费；可先过滤掉空链再分治，或改用堆（堆大小实际受非空链数限制）。
2. **追问：改成「合并 K 个降序链表」怎么办？** 思路：`_merge_two` 里比较方向反过来（取较大者），或先把每条链反转再套本题。
3. **追问：要求返回合并后链表的第 m 个结点（不建整条链）？** 思路：堆解法天然支持「流式」取前 m 个，取到第 m 个即停，时间 O(m log k)，不必处理全部 n。
