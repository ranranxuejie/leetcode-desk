## 1. 一句话本质

对 dictionary 里每个单词做一次「子序列判定」，然后在所有判定通过的单词里，按「长度最大、同长字典序最小」这个双关键字挑出冠军。

## 2. 读完题的第一反应

**朴素解法**：对 dictionary 里每个单词 w，检查 w 是不是 s 的子序列。检查方法是双指针：i 扫 s，j 扫 w，字符相同就 j 前进，最后看 j 是否走到 w 末尾。全部检查完后，再按规则挑最优。

这个解法本身**就是正解**，复杂度是 O(|s| × Σ|w|)，最坏 1000 × 1000 × 1000 = 10^9……等等，这里要算清楚：dictionary 有 1000 个词，每个词长 1000，每次判定要扫 s 的 1000 个字符，所以是 1000 × 1000 × 1000 = 10^9 量级。这个数字看着吓人，但实际跑起来远没这么糟——因为双指针判定里，j 一旦走到 w 末尾就提前退出，而且 s 的扫描是「每个 w 独立扫一遍」。真正的最坏情况是每个 w 都很长且都接近 s 的长度，此时才逼近 10^9。力扣上这个规模用 Python 双指针通常能过（实测 200ms 量级），因为常数很小、且大部分词会提前失败。

**关键观察**：题目要的是「最长且字典序最小」，而不是「所有可行解」。这意味着我们不需要对每个词都完整判定——可以先按「长度降序、字典序升序」排序，然后**第一个判定通过的词就是答案**，直接返回。这样最坏情况不变，但平均情况大幅提前退出。更重要的是，这个排序让「双关键字比较」这个容易写错的逻辑，变成了「排序规则 + 第一个命中」两件独立的小事，代码更不容易出错。

另一个观察：判定子序列时，**不需要真的删除字符**。删除某些字符后能得到 w，等价于 w 的字符按顺序出现在 s 中——这就是子序列的定义。所以问题从「删除操作」转化为「顺序匹配」，双指针天然适配。

## 3. 从暴力到最优

**第一步：暴力判定 + 手动比较**

对每个 w 判定，维护 best。比较逻辑：`len(w) > len(best)` 或 `len(w) == len(best) and w < best` 时更新。这是 O(Σ|w| × |s|) 的判定加 O(1) 比较。

**第二步：排序 + 提前返回**

把 dictionary 按 `(-len(w), w)` 排序。Python 里 `sorted(dictionary, key=lambda w: (-len(w), w))` 一行搞定。然后从头遍历，第一个 `is_subsequence(w, s)` 为真的就是答案。

为什么排序能消掉「手动比较」的复杂度？因为排序后，**第一个满足子序列条件的词，一定同时满足「最长」和「同长字典序最小」**——长度降序保证先遇到最长的，字典序升序保证同长度里先遇到最小的。这就是把「双关键字比较」外包给了排序。

**小例子走一遍**：s = "abpcplea", dictionary = ["ale","apple","monkey","plea"]

排序后：["monkey"(6), "apple"(5), "plea"(4), "ale"(3)]

- 判 "monkey"：i 扫 s，j 扫 "monkey"。s[0]='a'≠'m'，i=1；'b'≠'m'，i=2；'p'≠'m'，i=3；'c'≠'m'，i=4；'p'≠'m'，i=5；'l'≠'m'，i=6；'e'≠'m'，i=7；'a'≠'m'，i=8 越界。j=0 没动，失败。
- 判 "apple"：i=0 'a'='a'，j=1；i=1 'b'≠'p'；i=2 'p'='p'，j=2；i=3 'c'≠'p'；i=4 'p'='p'，j=3；i=5 'l'='l'，j=4；i=6 'e'='e'，j=5 到末尾。成功，返回 "apple"。

注意 "plea" 其实也是子序列（p-l-e-a 在 s 中顺序出现），但因为 "apple" 更长且排在前面，我们根本没检查它——这就是提前返回省下的工作。

**第三步：还能不能更快？**

可以预处理 s 的「下一个字符位置表」：`next_pos[i][c]` 表示从 s 的第 i 个位置往后，字符 c 第一次出现的位置。这样判定一个 w 只需 O(|w|) 而不是 O(|s|)。但预处理本身是 O(26|s|)，且本题规模下双指针已经够快，这个优化属于「面试追问」级别，不是必须。我在第 8 节会提。

## 4. 正确性：为什么不会漏、不会重

**不变量**：排序后的序列中，对任意下标 k，若前 k 个词都不是 s 的子序列，则答案（若存在）一定在下标 ≥ k 的位置。

**证明**：排序规则是 `(-len, w)`，即长度降序、同长字典序升序。假设答案存在且为 w*。w* 在排序序列中的位置为 m。对任意 k < m，位置 k 的词要么比 w* 长（但比 w* 长且是子序列的词会违反 w* 是最长的假设），要么与 w* 同长但字典序更小（同样违反 w* 是同长最小假设），要么比 w* 短（不可能是答案）。所以前 m 个词都不可能是答案，且它们若通过判定会与 w* 的最优性矛盾——因此它们必然判定失败。于是循环会跳过它们，在 m 处命中 w*。

**不会重**：第一个命中的词直接返回，不存在「多个候选需要比较」的情况。排序已经把所有比较做完了。

**不会漏**：如果答案存在，它一定在排序序列中某个位置，且该位置之前的所有词都判定失败（否则那个词才是答案），所以循环一定能走到它。

这个论证的关键是：**排序把「全局最优」转化成了「局部第一个命中」**，从而把正确性从「比较逻辑写对」降级为「排序规则写对 + 子序列判定写对」两个更简单、更不容易出错的子问题。

## 5. 完整代码（Python）

```python
class Solution:
    def findLongestWord(self, s: str, dictionary: list[str]) -> str:
        # 排序：长度降序，同长度字典序升序
        # 这样第一个满足子序列条件的词就是答案
        dictionary.sort(key=lambda w: (-len(w), w))

        def is_subsequence(w: str, s: str) -> bool:
            # 双指针：i 扫 s，j 扫 w
            i = j = 0
            while i < len(s) and j < len(w):
                if s[i] == w[j]:
                    j += 1  # 匹配成功，w 前进
                i += 1      # s 无论是否匹配都前进
            # j 走到 w 末尾说明 w 是 s 的子序列
            return j == len(w)

        for w in dictionary:
            if is_subsequence(w, s):
                return w  # 第一个命中即最优
        return ""  # 没有任何词是子序列
```

注意 `dictionary.sort` 是原地排序，会修改传入的列表。如果面试官在意「不修改输入」，改成 `for w in sorted(dictionary, key=...)` 即可，复杂度不变。

## 6. 复杂度

设 n = len(s)，m = len(dictionary)，L = max(len(w))。

**时间**：
- 排序：O(m log m × L)。比较两个字符串是 O(L) 的（最坏情况要逐字符比），排序有 O(m log m) 次比较，所以是 O(m log m × L)。这里 log m 来自排序，L 来自字符串比较。
- 判定：最坏 O(m × n)。每个词判定 O(n)（i 扫完 s），共 m 个词。注意判定里 j 最多走 L 步，但 i 走 n 步是主导，所以是 O(n) 而非 O(L)。
- 合计：O(m log m × L + m × n)。

**空间**：O(1) 额外空间（不算排序可能用的栈空间和输入本身）。双指针只用两个整数。Python 的 `sort` 是 Timsort，最坏 O(m) 辅助空间，但通常认为是 O(m) 或 O(1) 视实现而定——严格说排序需要 O(m) 辅助空间。

## 7. 边界与反例（至少 4 条）

1. **s = "a", dictionary = ["b"]** → 期望 `""`。容易错：忘记处理「没有任何词是子序列」的情况，直接返回了排序后的第一个词。代码里 `return ""` 兜底。

2. **s = "ab", dictionary = ["ba"]** → 期望 `""`。容易错：把「子序列」误写成「子串」或「字符集合包含」。'b' 和 'a' 都在 s 里，但顺序反了，不是子序列。双指针判定天然处理顺序，但如果你用 `set(w) <= set(s)` 就会错。

3. **s = "aaa", dictionary = ["aa", "aaa"]** → 期望 `"aaa"`。容易错：排序后 "aaa" 在前，判定通过直接返回，正确。但如果排序写成 `(len(w), w)` 升序，会先判 "aa" 通过并返回，漏掉更长的 "aaa"。

4. **s = "abce", dictionary = ["abe", "abc"]** → 期望 `"abc"`。两者都是子序列且同长 3，字典序 "abc" < "abe"。容易错：排序 key 写成 `(-len(w), w)` 是对的；若写成 `(-len(w), -ord(w[0]))` 之类的手动比较，容易在第二位字符上翻车。用元组 key 让 Python 做字典序比较最稳。

5. **dictionary 里有重复词**，如 s = "ab", dictionary = ["a", "a"] → 期望 `"a"`。排序后两个 "a" 相邻，第一个命中就返回，不影响正确性。容易错：如果先做去重再排序，逻辑上没问题但多此一举；如果手动维护 best 且用 `>` 而非 `>=`，也不会错，但代码更长。

## 8. 面试追问与变体（3 条）

1. **追问：如果 dictionary 很大（比如 10^5 个词），怎么优化？**
   思路：预处理 s 的 `next_pos[i][c]` 表（26 × n），判定每个词从 O(n) 降到 O(|w|)，总判定 O(Σ|w|)。预处理 O(26n)。这样总复杂度变成 O(26n + m log m × L + Σ|w|)，在 m 大时显著更优。

2. **追问：如果要求返回所有满足条件的词，而不是最优一个？**
   思路：去掉排序和提前返回，对每个词判定，收集所有通过的，最后按规则排序或手动维护列表。复杂度回到 O(m × n)，但省掉了排序的 O(m log m × L)。

3. **追问：如果 s 和 dictionary 的字符集不是小写字母，而是任意 Unicode？**
   思路：`next_pos` 表从 26 维变成字符集大小维，可能爆炸。此时双指针反而是更稳的选择，或者用哈希表存「每个字符出现的位置列表」+ 二分查找下一个位置，判定 O(|w| log n)。

## 9. 举一反三（2-3 道同类题）

1. **392. 判断子序列**：本题的判定子程序单独成题，双指针 O(n) 解法完全一致，是本题的「零件」。

2. **792. 匹配子序列的单词数**：给定 s 和一堆词，数有多少个是 s 的子序列。和本题共用判定逻辑，但要求计数而非求最优，且规模更大时需要用 `next_pos` 预处理或按首字符分组。

3. **1850. 邻位交换的最小次数**：虽然操作不同（交换而非删除），但核心都是「把字符串 A 变成 B 的最少操作」，且都用「按字符出现位置匹配 + 贪心」的思路，和本题的「顺序匹配」思想同源。
