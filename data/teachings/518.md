## 1. 一句话本质

在「硬币面额集合固定、每种面额可用无限次」的约束下，数出**和为 amount 的多重集（无序组合）个数**——注意是组合数，不是排列数。

## 2. 读完题的第一反应

朴素想法：枚举所有可能的硬币选取方案，递归地「每次挑一枚硬币，把剩余金额交给子问题」。写出来大概长这样：

```
dfs(rest) = sum over c in coins of dfs(rest - c)
dfs(0) = 1
```

这个递归**能算出答案，但会把同一种组合数很多遍**。以 amount=5, coins=[1,2,5] 为例，`2+1+1+1` 和 `1+2+1+1` 和 `1+1+2+1` 在递归里是三条不同路径，但它们对应同一种组合。更糟的是递归树的分支因子是 `len(coins)`，深度是 `amount/min(coins)`，最坏情况指数级。

关键观察来自示例 1 的解释：题目列出的四种方案里，`5=2+2+1` 只出现一次，没有把 `2+1+2` 另算一种。这说明**顺序不重要，重要的是每种面额用了几个**。一旦意识到「顺序无关」，就应该想到：与其让递归自由地挑硬币，不如**给硬币定一个顺序，强制按顺序使用**——比如「先决定用几个 1，再决定用几个 2，最后决定用几个 5」。这样每条组合路径唯一，不会重复计数。

这个「强制有序」的想法，正是从暴力搜索过渡到动态规划（完全背包）的桥梁。

## 3. 从暴力到最优

**第一步：消除重复计数。** 把递归改成「只允许使用 coins[i..] 这些面额」：

```
dfs(i, rest) = 用 coins[i:] 凑出 rest 的方案数
dfs(i, 0) = 1
dfs(len(coins), rest>0) = 0
dfs(i, rest) = dfs(i+1, rest)              # 不用第 i 种
             + dfs(i, rest - coins[i])     # 用一枚第 i 种（注意 i 不变，因为可无限用）
```

这就是「完全背包」的递归形式。状态是 `(i, rest)`，共 `len(coins) × (amount+1)` 个，每个状态 O(1) 转移，复杂度降到 O(n·amount)。但递归有重复子问题吗？有——`dfs(i, rest)` 会被不同路径多次调用，所以加记忆化或改写成递推。

**第二步：改写成递推（二维 DP）。** 令 `dp[i][j]` = 只用前 i 种面额凑出金额 j 的方案数。转移：

```
dp[i][j] = dp[i-1][j]                    # 第 i 种用 0 枚
         + dp[i][j - coins[i-1]]         # 第 i 种至少用 1 枚（注意是 dp[i] 不是 dp[i-1]）
```

`dp[0][0] = 1`，`dp[0][j>0] = 0`。

**具体走一遍** amount=5, coins=[1,2,5]：

初始化 `dp[0] = [1,0,0,0,0,0]`（i=0 表示不用任何硬币）。

i=1，coin=1：`dp[1][j] = dp[0][j] + dp[1][j-1]`
- j=0: 1
- j=1: 0+1=1
- j=2: 0+1=1
- j=3: 0+1=1
- j=4: 0+1=1
- j=5: 0+1=1
→ `dp[1] = [1,1,1,1,1,1]`

i=2，coin=2：`dp[2][j] = dp[1][j] + dp[2][j-2]`
- j=0: 1
- j=1: 1+0=1
- j=2: 1+1=2
- j=3: 1+1=2
- j=4: 1+2=3
- j=5: 1+2=3
→ `dp[2] = [1,1,2,2,3,3]`

i=3，coin=5：`dp[3][j] = dp[2][j] + dp[3][j-5]`
- j=0..4: 同 dp[2]
- j=5: 3 + dp[3][0] = 3+1 = 4
→ `dp[3][5] = 4`，与示例一致。

**第三步：压成一维。** 观察转移 `dp[i][j] = dp[i-1][j] + dp[i][j-c]`：计算第 i 行时只依赖上一行同列（`dp[i-1][j]`）和本行更小列（`dp[i][j-c]`）。如果用一个一维数组 `dp[j]` 原地更新，**从左往右**遍历 j，那么 `dp[j]` 在更新前是上一行的值（对应 `dp[i-1][j]`），`dp[j-c]` 已经被本行更新过（对应 `dp[i][j-c]`）。所以：

```
for c in coins:
    for j in range(c, amount+1):
        dp[j] += dp[j-c]
```

**这里最容易错的地方**：内层循环必须**正序**。如果倒序，`dp[j-c]` 还是上一行的值，等价于每种硬币最多用一次（0-1 背包），算出来的是「用不同面额各至多一枚」的方案数，不是本题答案。正序保证同一面额可以被反复使用——这正是「完全背包」和「0-1 背包」在代码上唯一但致命的区别。

## 4. 正确性：为什么不会漏、不会重

**不变量**：处理完前 i 种面额、内层循环走到 j 之后，`dp[j]` 等于「只用 coins[0..i] 这些面额凑出金额 j 的组合数」。

**归纳证明**：
- 基础：i=0（未处理任何面额）时 `dp[0]=1, dp[j>0]=0`，正确。
- 归纳步：处理第 i 种面额（面值 c）时，对任意 j，按「第 i 种用了几枚」分类：用 0 枚的方案数 = 更新前的 `dp[j]`（即只用前 i-1 种）；用至少 1 枚的方案数 = 先放一枚 c，剩下 j-c 用前 i 种凑，即 `dp[j-c]`（此时已被本行更新）。两类互斥且穷尽，相加即得。正序遍历保证 `dp[j-c]` 确实是「本行」的值。

**为什么不会重**：每条组合被唯一地按「面额从小到大、每种面额用几枚」编码。DP 按面额外层循环，等价于强制这个编码顺序，所以同一条组合只会在「最后一种用到的面额」那一步被计入一次。

**为什么不会漏**：任何合法组合都对应某个「各面额使用枚数」向量，归纳步对每种面额枚数做了完全分类，覆盖所有向量。

## 5. 完整代码（Python）

```python
class Solution:
    def change(self, amount: int, coins: list[int]) -> int:
        # dp[j] 表示凑出金额 j 的组合数（只用当前及之前处理过的面额）
        dp = [0] * (amount + 1)
        dp[0] = 1  # 凑出 0 元：什么都不选，算 1 种方案（空组合）

        for c in coins:                      # 外层：逐个面额，强制组合有序
            for j in range(c, amount + 1):   # 内层：正序，保证同一面额可重复使用
                dp[j] += dp[j - c]           # 不用 c 的方案 + 至少用一枚 c 的方案

        return dp[amount]
```

关键点：`dp[0]=1` 是「空组合」这一种方案，不是 0；内层 `range(c, amount+1)` 从 c 开始，因为 j<c 时 `dp[j-c]` 无意义（负数下标）。

## 6. 复杂度

- **时间 O(n · amount)**：外层 n = len(coins) 次，内层最多 amount 次，每次 O(1) 加法。n 来自硬币种数，amount 来自金额上界，没有 log 项。
- **空间 O(amount)**：一维数组长度 amount+1。二维版本是 O(n·amount)，滚动掉一维后省掉 n 因子。

## 7. 边界与反例（至少 4 条）

1. **amount = 0, coins = [1,2]** → 期望 1 → 容易错写成 0。空组合算一种方案，`dp[0]=1` 必须初始化对。
2. **amount = 3, coins = [2]** → 期望 0 → 容易错：`dp[3]` 始终为 0，因为 j 从 2 开始且 `dp[1]=0`。若误把内层写成 `range(0, amount+1)` 会下标越界或逻辑混乱。
3. **amount = 5, coins = [5]** → 期望 1 → 容易错：只有 j=5 时 `dp[5] += dp[0]` 生效，若 `dp[0]` 初始化为 0 则答案变 0。
4. **amount = 5, coins = [1,2,5]，但内层写成倒序** → 会得到 3（对应 5、2+1+1+1、1×5 中只算各面额至多一枚的组合），而正确答案是 4。这是本题最经典的错误，倒序 = 0-1 背包。
5. **coins 含大于 amount 的面额**，如 amount=3, coins=[5,2] → 期望 1（只有 2+1 不行，实际是 0？注意：2 凑不出 3，5 也凑不出，期望 0）。容易错：内层 `range(c, amount+1)` 当 c>amount 时为空，自动跳过，正确；但若手写循环忘了这个边界会越界。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回具体方案而不是方案数？** 思路：在 DP 基础上回溯，从 `dp[amount]` 出发，对每个面额判断「用了几枚」并递归收集，或用 DFS + 剪枝枚举。
2. **追问：如果每种硬币只能用一次（0-1 背包）？** 思路：内层循环改倒序 `for j in range(amount, c-1, -1)`，其余不变。
3. **追问：如果要求「最少硬币数」而不是方案数？** 思路：把 `dp[j] += dp[j-c]` 改成 `dp[j] = min(dp[j], dp[j-c]+1)`，初始化 `dp[0]=0`、其余为 INF，这是零钱兑换 I。
