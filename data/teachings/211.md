## 1. 一句话本质

在一个「前缀树」上做**带通配符的单点路径搜索**：`.` 意味着在当前层要枚举所有可能的子分支，其余字符意味着只能走唯一一条边。

## 2. 读完题的第一反应

**朴素解法**：用一个 `list` 存所有 `addWord` 进来的词。`search` 时遍历整个列表，对每个词逐字符比对，遇到 `.` 就跳过该位。复杂度：`addWord` 是 O(1)，`search` 是 O(总词数 × 词长)。

**卡在哪**：题面提示「最多调用 10^4 次 addWord 和 search」，词长 ≤ 25。最坏情况 10^4 个词、每次 search 扫全部 → 10^8 次字符比较，Python 里必然超时。瓶颈是**每次 search 都从头扫所有词，复用了零信息**。

**关键观察**：`search("bad")` 和 `search("b..")` 共享前缀 `b`；`search(".ad")` 和 `search("bad")` 共享后缀 `ad`。也就是说，**大量词共享前缀**——这正是「前缀树（字典树 / Trie）」的适用信号。把词按字符逐层挂到树上，`search` 就变成「从根往下走一条路径」，而不是「扫一遍列表」。

第二个观察来自 `.`：它让路径不再唯一。在树上，唯一路径的搜索是循环；**分叉路径的搜索天然是 DFS**——这就是标签里「深度优先搜索」的来源。两个观察合起来，数据结构就定了：**Trie + DFS**。

## 3. 从暴力到最优

### 第一步：用 Trie 消掉「扫全部词」

Trie 的节点长这样：每个节点有一个 `children` 字典（字符 → 子节点），加一个 `is_end` 标记「是否有词在此结束」。

插入 `bad`、`dad`、`mad` 后，树是：

```
root
 ├─ b → a → d (is_end=True)
 ├─ d → a → d (is_end=True)
 └─ m → a → d (is_end=True)
```

`search("bad")`：root 走 `b`、`a`、`d`，到叶子且 `is_end=True` → True。**只走了 3 步，与词库大小无关**。瓶颈从「词数 × 词长」降到「词长」。

注意 `is_end` 不能省：如果只插了 `bad`，`search("ba")` 也能沿树走到 `a` 节点，但那里没有词结束，必须返回 False。

### 第二步：用 DFS 处理 `.`

`search(".ad")`：root 这一层不知道走哪个孩子，**枚举 root 的所有孩子**（`b`、`d`、`m`），对每个孩子递归匹配剩下的 `ad`。

具体走一遍：

- 尝试 `b` 分支：`b` 匹配 `.`，剩下 `ad` → `a` 匹配 `a` → `d` 匹配 `d`，到 `is_end=True` 的节点 → **True，立即返回**。
- （若 `b` 分支失败才会试 `d`、`m`。）

`search("b..")`：root 走 `b`（唯一），剩下 `..`。第一层 `.` 枚举 `b` 的孩子（只有 `a`），第二层 `.` 枚举 `a` 的孩子（只有 `d`），`d` 是 `is_end` → True。

**关键点**：`.` 分支一旦某个子树返回 True 就立刻短路返回，不再试其他分支——这是 DFS 的标准剪枝，也是复杂度分析里「最坏情况」和「平均情况」差距的来源。

### 第三步：为什么这就是最优形态

对比一下：如果 search 里含 `k` 个 `.`，最坏要枚举 `26^k` 条路径。但题面约束词长 ≤ 25、总调用 ≤ 10^4，且实际词库远小于 26^25，**Trie 的节点数被「插入过的总字符数」封顶**，DFS 最多访问这些节点，不会爆炸。这就是「用数据结构把指数级枚举压回线性」的典型手法。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义 DFS 函数 `dfs(node, i)` 的语义为：

> 从 `node` 出发，能匹配 `word[i:]` 当且仅当 `dfs(node, i)` 返回 True。

**归纳证明**（对剩余长度 `len(word) - i` 归纳）：

- **基础情形** `i == len(word)`：此时要匹配空串。按定义，空串匹配成功当且仅当 `node.is_end` 为 True（当前节点恰好是某个已插入词的结尾）。代码直接返回 `node.is_end`，与语义一致。
- **归纳步**：设对长度 `L-1` 成立，证长度 `L`。
  - 若 `word[i]` 是普通字母 `c`：`word[i:]` 匹配成功当且仅当 `c in node.children` 且 `dfs(node.children[c], i+1)` 为 True。代码正是这么写的，**唯一分支，不漏不重**。
  - 若 `word[i]` 是 `.`：`.` 可代表任意字母，所以 `word[i:]` 匹配成功当且仅当**存在**某个孩子 `ch` 使 `dfs(node.children[ch], i+1)` 为 True。代码枚举所有孩子、任一成功即返回 True，**穷举了所有可能，不漏；每个孩子只试一次，不重**。

由归纳，`dfs(root, 0)` 返回 True 当且仅当存在某个已插入词与 `word` 匹配。**不变量成立，算法正确**。

「不会重」的额外保证：Trie 中每个节点对应唯一的前缀字符串，DFS 沿树向下走不会回到同一节点两次（树无环），所以枚举分支不会重复计算同一条路径。

## 5. 完整代码（Python）

```python
class TrieNode:
    def __init__(self):
        self.children = {}      # 字符 -> TrieNode
        self.is_end = False     # 是否有词在此节点结束


class WordDictionary:

    def __init__(self):
        self.root = TrieNode()

    def addWord(self, word: str) -> None:
        node = self.root
        for ch in word:
            # 没有这条边就新建，有就复用（共享前缀）
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True      # 标记词尾，search 时靠它判断"完整词"

    def search(self, word: str) -> bool:
        # 从根、第 0 个字符开始 DFS
        return self._dfs(self.root, word, 0)

    def _dfs(self, node: TrieNode, word: str, i: int) -> bool:
        # 递归出口：word 已全部匹配完，看当前节点是否是某个词的结尾
        if i == len(word):
            return node.is_end

        ch = word[i]
        if ch != '.':
            # 普通字符：唯一分支，走不通直接 False
            nxt = node.children.get(ch)
            if nxt is None:
                return False
            return self._dfs(nxt, word, i + 1)
        else:
            # 通配符：枚举当前节点的所有孩子，任一成功即 True（短路）
            for nxt in node.children.values():
                if self._dfs(nxt, word, i + 1):
                    return True
            return False


# 题面给的签名是 Solution.solve(...) -> boolean，
# 这里提供一个适配入口，方便按题面签名调用：
class Solution:
    def solve(self, operations, arguments):
        """
        operations: ["WordDictionary","addWord",...]
        arguments:  [[],["bad"],...]
        返回与 operations 等长的结果列表（addWord/构造返回 None）
        """
        results = []
        wd = None
        for op, args in zip(operations, arguments):
            if op == "WordDictionary":
                wd = WordDictionary()
                results.append(None)
            elif op == "addWord":
                wd.addWord(args[0])
                results.append(None)
            elif op == "search":
                results.append(wd.search(args[0]))
        return results
```

## 6. 复杂度

设 `L` 为词长（≤ 25），`N` 为已插入词的总字符数（Trie 节点数上界），`k` 为 search 中 `.` 的个数。

**addWord**：时间 O(L)——逐字符走一遍，每步字典操作 O(1)。空间 O(L)——最坏新建 L 个节点；但共享前缀时实际增量更少，总空间由 N 封顶。

**search**：
- 无 `.` 时：时间 O(L)，空间 O(L)（递归栈深度）。
- 有 `.` 时：最坏 O(26^k · L)？不对——**DFS 访问的节点数被 Trie 节点总数 N 封顶**，因为树无环、每个节点最多进一次。所以时间 O(min(26^k, N) · 1)，更准确地说是 **O(访问到的节点数)**，上界 O(N)。空间 O(L) 递归栈（深度不超过词长）。
- 这里没有 log n：字典查找是哈希 O(1)，不是二分。

**总空间**：O(N)，N = 所有 addWord 词的字符总数（去重共享前缀后）。

## 7. 边界与反例（至少 4 条）

1. **只插前缀词**：`addWord("bad")` 后 `search("ba")` → 期望 False → 容易错在忘了 `is_end`，走到 `a` 节点就返回 True。
2. **`.` 匹配到非词尾**：`addWord("bad")` 后 `search("b.")` → 期望 False → `.` 枚举到 `a` 节点，但 `a` 不是词尾，必须继续判断 `is_end` 而非「走到就成功」。
3. **`.` 在末尾且多分支**：`addWord("bad")`、`addWord("bae")` 后 `search("ba.")` → 期望 True → 容易错在只试第一个孩子就返回，必须「任一成功即 True」。
4. **search 的词比所有已插词都长**：`addWord("a")` 后 `search("ab")` → 期望 False → 走到 `a` 节点后 `children` 为空，普通字符分支要返回 False 而不是抛异常（用 `.get` 而非 `[]`）。
5. **空词典 search**：未 addWord 直接 `search(".")` → 期望 False → root 的 `children` 为空，DFS 枚举零个孩子返回 False，不能崩。

## 8. 面试追问与变体（3 条）

1. **追问：如果 `.` 可以匹配「零个或多个字符」（类似正则 `.*`）怎么办？**
   思路：DFS 增加一个分支——`.` 处既可以「消费一个字符往下走」，也可以「不消费、留在当前节点继续匹配剩余串」，需要记忆化 `(node, i)` 防重复。

2. **追问：如何支持删除单词？**
   思路：`is_end` 改为计数（同一词可重复插入），删除时计数减一；若计数归零且该节点无孩子，可回溯剪枝删节点。

3. **追问：search 调用远多于 addWord，如何进一步加速？**
   思路：对无 `.` 的查询走纯循环（已是 O(L)）；对含 `.` 的查询可缓存 `(word, 结果)`，或用 AC 自动机处理多模式匹配场景。
