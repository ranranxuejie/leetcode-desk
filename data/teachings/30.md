## 1. 一句话本质

在 `s` 中找出所有长度为 `len(words) * len(words[0])` 的窗口，使得窗口按固定长度 `L` 切分后得到的词频表，与 `words` 的词频表**完全相等**。

## 2. 读完题的第一反应

**朴素解法**：枚举 `s` 中每个起点 `i`（共 `n` 个），对每个起点取出长度 `m*L` 的子串，按 `L` 切成 `m` 段，排序后和 `words` 排序比较。复杂度 `O(n * m * L log m)`，`n=10^4, m=5000` 直接爆炸。

**卡在哪**：两处浪费。第一，每个起点都重新切分、重新计数，相邻窗口之间大量重叠信息被丢弃；第二，用排序比较词频，其实哈希表 `O(m)` 就能比。

**关键观察**：窗口长度固定为 `m*L`，且切分点只依赖起点模 `L` 的余数。也就是说，起点 `i` 和 `i+L` 的切分方式完全一致——它们切出来的词边界是对齐的。于是所有起点可以按 `i mod L` 分成 `L` 组，每组内部是一个「以 `L` 为步长的滑动窗口」，窗口每右移一格，恰好**移出一个词、移入一个词**。这就是滑动窗口能生效的结构性依据。

## 3. 从暴力到最优

**第一步：固定起点，改成词频比较。** 用 `Counter(words)` 做目标表，对每个起点切 `m` 个词、建计数表、比较。复杂度降到 `O(n * m * L)`（切词本身要 `L`），仍不够。

**第二步：按余数分组 + 滑动窗口。** 对每个 `r in range(L)`，从 `s[r:]` 出发，以步长 `L` 取词，维护一个长度恰为 `m` 的窗口。

用具体例子走一遍：`s = "barfoothefoobarman"`, `words = ["foo","bar"]`，`L=3, m=2`，目标表 `{foo:1, bar:1}`。

- `r=0`：词序列为 `bar(0) foo(3) the(6) foo(9) bar(12) man(15)`。
  - 窗口 `[bar, foo]`：计数 `{bar:1, foo:1}`，与目标相等 → 记录起点 `0`。
  - 右移：移出 `bar`，移入 `the` → `{foo:1, the:1}`，不等。
  - 右移：移出 `foo`，移入 `foo` → `{the:1, foo:1}`，不等。
  - 右移：移出 `the`，移入 `bar` → `{foo:1, bar:1}`，相等 → 记录起点 `9`。
  - 右移：移出 `foo`，移入 `man` → 不等。
- `r=1`、`r=2`：词序列分别是 `arf oot hef oob arm an` 之类，全部不匹配。

结果 `[0, 9]`，与示例一致。注意每次右移只做两次哈希更新，而不是重建整张表——这就是瓶颈被消掉的地方：`O(m)` 的建表被摊还成 `O(1)` 的增量更新。

**第三步：用「匹配词数」代替整表比较。** 维护 `matched` 表示当前窗口中有多少种词的出现次数已经和目标一致。移入/移出时只更新受影响的那个词的计数，并同步调整 `matched`。当 `matched == len(target)` 时窗口合法。这样每次移动是严格 `O(1)`，比较也不再是 `O(m)`。

## 4. 正确性：为什么不会漏、不会重

**不漏**：任意合法起点 `i`，设 `r = i mod L`。由于 `i` 与 `r` 同余，`i` 一定落在第 `r` 组的词序列上，且该组窗口会从 `r` 开始逐步右移，必然经过以 `i` 为左端、长度 `m` 的那个窗口。该窗口的词频等于目标表，`matched` 会等于 `len(target)`，于是被记录。

**不重**：每个起点 `i` 唯一确定 `r = i mod L`，只会在第 `r` 组被检查一次；组内窗口左端随步长单调右移，每个左端只出现一次。所以同一索引不会被记录两次。

**不变量**：在任意时刻，`window` 记录的是「当前窗口内各词出现次数」，`matched` 记录的是「`window[w] == target[w]` 成立的词 `w` 的个数」。每次移出/移入只改动一个词的计数，因此在改动前后对 `matched` 做增量修正，不变量始终成立。当 `matched == len(target)` 时，对所有 `w in target` 都有 `window[w] == target[w]`；又因为窗口总词数恰为 `m = sum(target.values())`，窗口内不可能出现目标表之外的词（否则总数会超出），故词频表完全相等。

## 5. 完整代码（Python）

```python
from collections import Counter

class Solution:
    def findSubstring(self, s: str, words: list[str]) -> list[int]:
        if not s or not words:
            return []
        L = len(words[0])          # 每个词的长度
        m = len(words)             # 词的个数
        n = len(s)
        total = m * L              # 串联子串的总长度
        if n < total:
            return []

        target = Counter(words)    # 目标词频表
        need = len(target)         # 需要匹配的词种数
        res = []

        # 起点按 mod L 分成 L 组，组内以 L 为步长滑动
        for r in range(L):
            left = r           # 窗口左端（词边界）
            right = r          # 窗口右端（词边界）
            window = Counter()
            matched = 0        # 当前 window 中计数已与 target 一致的词种数

            while right + L <= n:
                # 移入一个词
                w = s[right:right + L]
                right += L
                if w in target:
                    window[w] += 1
                    if window[w] == target[w]:
                        matched += 1
                    elif window[w] == target[w] + 1:
                        # 从「刚好相等」变成「超出」，匹配数减一
                        matched -= 1

                # 窗口词数超过 m，从左侧移出一个词
                if right - left > total:
                    lw = s[left:left + L]
                    left += L
                    if lw in target:
                        if window[lw] == target[lw]:
                            matched -= 1
                        elif window[lw] == target[lw] + 1:
                            matched += 1
                        window[lw] -= 1

                # 窗口恰好 m 个词且全部匹配
                if right - left == total and matched == need:
                    res.append(left)

        return res
```

关键点说明：`matched` 的增减逻辑必须写成「先判断旧状态、再改计数」或「改完计数后判断是否跨越等号」，代码里用 `== target[w]` 和 `== target[w]+1` 两个分支精确捕捉「刚好进入匹配」和「刚好破坏匹配」的瞬间，避免重复计数。

## 6. 复杂度

- **时间**：外层 `L` 组，每组内 `right` 从 `r` 走到 `n`，共约 `n/L` 次迭代，每次 `O(1)`（切片 `s[right:right+L]` 是 `O(L)`，但哈希计算摊还后按 `O(L)` 计）。总计 `O(L * (n/L) * L) = O(n * L)`。注意 `L <= 30` 是常数上界，实际接近 `O(n)`。若把切片成本计入，严格是 `O(n*L)`，其中 `n` 来自字符串长度，`L` 来自每次切词。
- **空间**：`target` 和 `window` 各至多 `m` 个键，`O(m)`；结果数组最坏 `O(n)`。合计 `O(m + n)`。没有 `log` 项，因为全程用哈希而非排序。

## 7. 边界与反例（至少 4 条）

1. `s = "a", words = ["a"]` → `[0]`。容易错在 `n < total` 的判断写成 `<=`，把唯一解过滤掉。
2. `s = "aaaaaa", words = ["aa","aa"]` → `[0,1,2]`。容易错在 `matched` 用「计数相等」而非「种数相等」：`window["aa"]=2` 与 `target["aa"]=2` 相等，但若误用 `window[w] >= target[w]` 判断，会在窗口未满时就误报。
3. `s = "wordgoodgoodgoodbestword", words = ["word","good","best","word"]` → `[]`。容易错在 `target` 用 `set(words)` 而非 `Counter`，丢掉重复词 `word` 需要出现两次的约束。
4. `s = "barfoofoobarthefoobarman", words = ["bar","foo","the"]` → `[6,9,12]`。容易错在只跑 `r=0` 一组，漏掉 `r=1,2` 组里起点模 `L` 不为 0 的解。
5. `s = "abababab", words = ["ab","ab","ab"]` → `[0,2]`。容易错在移出词时忘记同步修正 `matched`，导致窗口右移后 `matched` 虚高。

## 8. 面试追问与变体（3 条）

1. **追问：如果 `words` 中词长度不全相同怎么办？** 思路：题目结构被破坏，滑动窗口的「对齐切分」不再成立，退化为对每个起点做多模式匹配（如 AC 自动机 + 回溯），复杂度显著上升，需重新设计。
2. **追问：要求返回最短的串联子串而不是所有起点？** 思路：仍是滑动窗口，但把「窗口长度固定为 `m*L`」改成「窗口内词频覆盖 `target` 即可」，用 `matched == need` 收缩左边界，取最小长度。
3. **追问：`s` 是流式输入，内存放不下？** 思路：维护长度为 `m*L` 的环形缓冲，配合增量哈希，每读入 `L` 个字符更新一次窗口，空间 `O(m*L)`。

## 9. 举一反三（2-3 道同类题）

- **力扣 438. 找到字符串中所有字母异位词**：同样是固定长度窗口 + 词频表比较，只是切分单位从「词」变成「字符」，`matched` 技巧完全复用。
- **力扣 76. 最小覆盖子串**：窗口长度不固定，用 `matched` 判断覆盖并收缩左界，是本题「增量维护匹配数」思路的推广。
- **力扣 567. 字符串的排列**：本题的字符版简化，窗口长度固定为 `len(s1)`，判断词频相等即可。
