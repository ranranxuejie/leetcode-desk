## 1. 一句话本质

把「公交线路」当作图的节点、「两条线路有公共车站」当作边，求从「包含 source 的线路集合」到「包含 target 的线路集合」的最少边数（再加 1）。

## 2. 读完题的第一反应

**朴素解法**：把车站当节点建图。对每条线路 `routes[i]`，把线路上任意两个车站连一条边（因为同一辆车可以在这两个站之间直达）。然后从 source 做 BFS 到 target，BFS 的层数就是换乘次数……但这里立刻卡住：**BFS 的边权不是「坐车次数」，而是「是否换了车」**。同一辆车坐 5 站和坐 1 站都只算 1 次乘车，可如果按车站建图，BFS 会把「坐 5 站」当成 5 步，答案就错了。

更糟的是复杂度：一条线路有 k 个站，两两连边是 O(k²)。题面提示 `sum(routes[i].length)` 规模不小，k 一大就爆。

**关键观察**：题目问的是「最少乘坐几辆车」，而不是「经过几个站」。所以真正该被 BFS 遍历的对象是**线路**，不是车站。两条线路只要有一个公共车站，就能在这个站换乘——这是一步。于是：

- 节点 = 线路编号 `0..n-1`
- 边 = 两条线路共享至少一个车站
- 起点 = 所有包含 `source` 的线路（坐第一辆车）
- 终点 = 所有包含 `target` 的线路

这样 BFS 每走一层就是「多坐一辆车」，层数天然等于答案。而且不需要显式建 O(n²) 的边：从一条线路出发，只要枚举它经过的每个车站，再通过「车站 → 线路列表」的反向索引找到所有能换乘的线路即可。

## 3. 从暴力到最优

**第一步：车站建图（暴力）**

以示例 1 为例，`routes = [[1,2,7],[3,6,7]]`，source=1，target=6。

车站图：线路 0 内部连 1-2、1-7、2-7；线路 1 内部连 3-6、3-7、6-7。从 1 出发 BFS：1→2（1 步）、1→7（1 步）、7→6（2 步）。看起来能到，但「步数」是车站跳数，不是乘车次数。如果线路是 `[1,2,3,4,5,6]`，从 1 到 6 只需坐 1 辆车，车站 BFS 却要 5 步。**瓶颈：边权语义错了，且 O(k²) 建边。**

**第二步：线路建图（正确方向）**

节点变成线路。示例 1 中线路 0 和线路 1 共享车站 7，所以它们之间有一条边。source=1 在哪些线路里？只有线路 0。target=6 在哪些线路里？只有线路 1。从线路 0 出发，一步到线路 1，答案 = 1 步 + 1 = 2。对上了。

**第三步：不显式建边，用反向索引**

线路建图如果两两比较，还是 O(n²)。但我们不需要预先知道「线路 A 和线路 B 相邻」，只需要在 BFS 到线路 A 时，能快速找到「和 A 共享车站的所有线路」。做法：

1. 建 `station_to_routes`：车站 → 经过它的线路编号列表。
2. BFS 队列里放线路编号。弹出线路 `r`，遍历 `routes[r]` 的每个车站 `s`，查 `station_to_routes[s]` 得到所有线路 `nr`，若 `nr` 未访问就入队。
3. 为避免同一车站被反复展开，可以额外维护 `visited_station`，车站展开过一次就跳过。

示例 1 走一遍：

- `station_to_routes`：1→[0]，2→[0]，7→[0,1]，3→[1]，6→[1]
- 起点线路：source=1 在 [0]，队列 `[0]`，`dist[0]=1`（坐第 1 辆车）
- 弹出 0：车站 1→线路 [0] 已访问；车站 2→[0]；车站 7→[0,1]，线路 1 未访问，`dist[1]=2`，入队
- 弹出 1：车站 3→[1]；车站 6→[1]；车站 7 已展开跳过
- 检查 target=6 所在线路 [1]，`dist[1]=2`，返回 2

**瓶颈消掉了**：每条线路只出队一次，每个车站最多被展开一次，总代价 O(总车站数 + 总线路数)。

## 4. 正确性：为什么不会漏、不会重

**不变量**：BFS 队列中线路 `r` 的 `dist[r]` 等于「从 source 出发、以线路 r 作为最后一辆车所需的最少乘车数」。

**归纳证明**：

- 初始：所有包含 source 的线路 `dist=1`，这是下界（至少坐 1 辆车），且可达，成立。
- 转移：若 `dist[r]=d`，线路 `r` 经过车站 `s`，线路 `nr` 也经过 `s`，则可以在 `s` 下车换乘 `nr`，`dist[nr] ≤ d+1`。BFS 按层扩展保证第一次给 `nr` 赋值时就是最小值（标准 BFS 性质：无权图首次访问即最短路）。
- 不会漏：任何可行方案都是一串线路 `r0, r1, ..., rk`，相邻两条共享换乘站。归纳可知 `dist[ri] ≤ i+1`，所以 target 所在线路一定被访问到。
- 不会重：`visited` 保证每条线路只入队一次，`visited_station` 保证每个车站只展开一次，避免重复计算但不影响正确性（因为同一车站展开出的邻居集合相同）。

**答案**：`min(dist[r] for r in station_to_routes[target])`，若 target 所在线路都不可达则 -1。

## 5. 完整代码（Python）

```python
from collections import deque, defaultdict

class Solution:
    def numBusesToDestination(self, routes, source, target):
        # source == target 时不用坐车
        if source == target:
            return 0

        n = len(routes)
        # 车站 -> 经过该车站的线路编号列表
        station_to_routes = defaultdict(list)
        for i, route in enumerate(routes):
            for s in route:
                station_to_routes[s].append(i)

        # target 不在任何线路上，直接不可能
        if target not in station_to_routes:
            return -1

        # BFS：节点是线路编号，dist[i] = 坐 i 号线所需的最少乘车数
        dist = [-1] * n
        q = deque()

        # 起点：所有包含 source 的线路，坐第 1 辆车
        for r in station_to_routes[source]:
            if dist[r] == -1:
                dist[r] = 1
                q.append(r)

        visited_station = set()  # 已展开过的车站，避免重复枚举

        while q:
            r = q.popleft()
            d = dist[r]
            for s in routes[r]:
                if s in visited_station:
                    continue
                visited_station.add(s)
                # 通过车站 s 换乘到其他线路
                for nr in station_to_routes[s]:
                    if dist[nr] == -1:
                        dist[nr] = d + 1
                        q.append(nr)

        # 答案：所有包含 target 的线路中 dist 的最小值
        ans = -1
        for r in station_to_routes[target]:
            if dist[r] != -1:
                if ans == -1 or dist[r] < ans:
                    ans = dist[r]
        return ans
```

## 6. 复杂度

设 `S = sum(len(routes[i]))` 为所有线路的车站总数，`n = len(routes)`。

- **建索引**：遍历所有线路的所有车站，O(S)。
- **BFS**：每条线路最多出队一次，出队时遍历它的车站，总车站遍历量 O(S)；每个车站最多被 `visited_station` 展开一次，展开时遍历 `station_to_routes[s]`，所有车站的该列表长度之和恰好是 S（每个「车站-线路」出现一次），所以展开总代价 O(S)。
- **总时间**：O(S + n)，即 O(S)。
- **空间**：`station_to_routes` 存 S 个条目，O(S)；`dist` O(n)；队列和 `visited_station` O(S)。总计 O(S + n) = O(S)。

没有 log 项，因为 BFS 是无权图，不需要堆。

## 7. 边界与反例（至少 4 条）

1. **`source == target`** → 期望 0。容易错：直接走 BFS 会返回 1 或 -1，因为「初始不在车上」意味着不用坐车。必须在开头特判。
2. **`routes = [[1,2],[3,4]]`, source=1, target=4** → 期望 -1。容易错：两条线路无公共站，BFS 从线路 0 出发找不到线路 1，`dist[1]` 保持 -1，最终返回 -1。若忘记检查 `dist[r] != -1` 就取 min，会误取 -1 或报错。
3. **`routes = [[1,2,3]], source=1, target=3`** → 期望 1。容易错：车站建图会算成 2 步（1→2→3），但同一辆车只算 1 次。这验证了「按线路 BFS」的必要性。
4. **`target` 不在任何线路中** → 期望 -1。容易错：`station_to_routes[target]` 为空，若直接遍历空列表取 min 会出错或返回 -1 但逻辑不清晰。代码里显式判断 `target not in station_to_routes` 提前返回。
5. **`source` 不在任何线路中但 `source != target`** → 期望 -1。容易错：起点线路集合为空，队列为空，BFS 不执行，最终 target 线路 `dist` 全 -1，返回 -1。逻辑自洽，但需要确认不会误把 `source` 当已访问。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求输出具体换乘方案（坐哪几辆车、在哪站换）？**
   思路：BFS 时记录 `parent_line[nr] = r` 和 `transfer_station[nr] = s`，最后从 target 所在线路回溯到起点线路，反转输出。

2. **追问：如果每条线路有不同票价，求最小总票价？**
   思路：变成带权图最短路，节点仍是线路，边权是换乘后的票价（或两段票价之和），用 Dijkstra 替代 BFS；注意起点票价单独计。

3. **追问：如果允许步行在相邻车站之间移动（给定步行边），怎么改？**
   思路：把车站也作为节点加入图，线路内部边权 0（同一辆车不额外计费），换乘边权 1，步行边权 0 或按题意，用 0-1 BFS 或 Dijkstra；核心仍是「乘车次数」作为层。
