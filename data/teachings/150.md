## 1. 一句话本质

把一串「操作数在前、运算符在后」的 token 按顺序扫一遍，用栈暂存还没被消费的操作数，遇到运算符就弹出最近的两个算掉、把结果塞回去——本质是**用栈模拟表达式树的「后序遍历求值」**。

## 2. 读完题的第一反应

朴素解法：先把后缀表达式转成中缀（或直接建表达式树），再按常规方式递归求值。卡在哪？建树要额外 O(n) 节点，转中缀还要处理括号优先级，代码量大且容易错；更关键的是——**你根本不需要知道表达式长什么样，只需要知道「每个运算符该吃哪两个数」**。

关键观察藏在题面最后一段：「遇到数字则入栈；遇到算符则取出栈顶两个数字进行计算，并将结果压入栈中」。这句话不是提示，是**算法本身**。为什么它成立？因为后缀表达式的定义保证了：任何一个运算符出现时，它要的两个操作数**一定已经完整地算出来了**，并且就躺在栈顶。换句话说，运算符出现的位置，恰好是它两个子表达式「刚刚求值完毕」的时刻。

这个观察直接把你从「解析结构」拉到「线性扫描 + 一个栈」，问题从「怎么理解表达式」变成「怎么维护一个待消费操作数的栈」。

## 3. 从暴力到最优

**暴力路线**：递归下降建树 → 后序遍历求值。瓶颈是建树 O(n) 空间 + 递归栈，且要处理负数和多位数字的解析，代码长。

**最优路线**：一个栈，一次线性扫描。瓶颈被消掉的原因是——后缀表达式**已经替你做好了后序遍历**，你只需要按 token 顺序执行「入栈 / 弹两个算一个再入栈」即可，不需要任何结构信息。

用示例 2 走一遍：`tokens = ["4","13","5","/","+"]`

| 步骤 | token | 动作 | 栈（底→顶） |
|---|---|---|---|
| 1 | "4" | 入栈 | [4] |
| 2 | "13" | 入栈 | [4, 13] |
| 3 | "5" | 入栈 | [4, 13, 5] |
| 4 | "/" | 弹 5、弹 13，算 13/5=2，入栈 | [4, 2] |
| 5 | "+" | 弹 2、弹 4，算 4+2=6，入栈 | [6] |

扫描结束，栈里只剩一个数 6，就是答案。

注意第 4 步的顺序：**先弹出的是右操作数，后弹出的是左操作数**。`13/5` 不是 `5/13`，减法和除法必须按这个顺序，这是本题最容易翻车的地方（见第 7 节）。

再看示例 3 里一个负数的片段：`["9","3","+","-11","*"]`。9、3 入栈 → `+` 得 12 入栈 → `-11` 入栈 → `*` 弹 -11、弹 12，算 `12 * (-11) = -132`。负数 token 用 `int()` 直接转即可，Python 的 `int("-11")` 没问题。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。定义扫描到第 i 个 token 之后栈的状态满足：

> 栈中从底到顶，恰好是「已扫描前缀中，尚未被某个运算符消费掉的子表达式」的求值结果，且顺序与它们在原表达式中出现的顺序一致。

归纳证明：

- **基础**：扫描 0 个 token，栈空，不变量成立。
- **数字 token**：它本身是一个完整的子表达式，还没被消费，压栈后不变量保持。
- **运算符 token**：由后缀表达式的合法性（题面保证输入是合法的逆波兰表达式），该运算符的两个操作数必然已经作为两个完整子表达式出现在已扫描前缀中，且是**最近两个未被消费的**——也就是栈顶两个。弹出它们、算出结果、压回，相当于把「两个子表达式 + 一个运算符」合并成一个新的完整子表达式，未消费集合的大小减一，顺序不变，不变量保持。
- **终止**：扫描完所有 token，合法表达式保证栈中恰剩一个元素，即整个表达式的值。

「不会漏」：每个数字都被压栈，每个运算符都消费恰好两个栈顶元素，没有 token 被跳过。「不会重」：每个元素被弹出后就不再存在于栈中，结果作为新元素压回，一个子表达式只被消费一次。这就是为什么线性扫描一遍就够。

## 5. 完整代码（Python）

```python
class Solution:
    def evalRPN(self, tokens) -> int:
        stack = []
        # 运算符到「二元函数」的映射，避免一长串 if-elif
        ops = {
            "+": lambda a, b: a + b,
            "-": lambda a, b: a - b,
            "*": lambda a, b: a * b,
            # 关键：Python 的 // 是向下取整，负数会错；用 int(a / b) 实现向零截断
            "/": lambda a, b: int(a / b),
        }

        for tok in tokens:
            if tok in ops:
                # 先弹出的是右操作数，后弹出的是左操作数
                right = stack.pop()
                left = stack.pop()
                stack.append(ops[tok](left, right))
            else:
                # 不是运算符就是整数（含负数），直接转 int 入栈
                stack.append(int(tok))

        # 合法表达式扫描完后栈中恰剩一个元素
        return stack[-1]
```

两个必须讲透的点：

1. **除法向零截断**。题面明确「两个整数之间的除法总是向零截断」。Python 的 `//` 对负数是向下取整：`-7 // 2 == -4`，而向零截断要的是 `-3`。所以用 `int(a / b)`（`int()` 对 float 是截断小数部分，方向就是向零）。注意 `a / b` 会产生 float，在 32 位范围内精度足够，本题数据范围安全；若追求纯整数，可写 `abs(a)//abs(b)` 再补符号，但没必要。
2. **弹出顺序**。`right = pop()` 再 `left = pop()`，然后 `left op right`。写反了减法和除法全错，加乘碰巧对——这种「一半用例能过」的 bug 最难查。

## 6. 复杂度

- **时间 O(n)**，n = `len(tokens)`。每个 token 被处理一次：数字做一次 `int()` 转换和一次 `append`，运算符做两次 `pop`、一次运算、一次 `append`，都是 O(1)。没有嵌套循环，没有排序，所以没有 log 项。
- **空间 O(n)**，最坏情况所有 token 都是数字（如 `["1","2","3",...]` 这种前缀全是操作数的合法表达式），栈会存下约 n/2 到 n 个元素；一般情况栈的深度等于表达式树在「后序扫描」时的最大待消费子表达式数，上界仍是 O(n)。运算符映射表是常数 4 项，O(1)。

## 7. 边界与反例（至少 4 条）

1. `tokens = ["18"]` → 输出 `18`。只有一个数字，没有运算符。容易错在：代码假设「一定会遇到运算符」，或返回时写了 `stack.pop()` 之外的多余逻辑。本题代码直接返回 `stack[-1]`，安全。
2. `tokens = ["4","13","5","/","+"]` → 输出 `6`。`13/5` 向零截断得 2，不是 2.6 也不是 3。容易错在：用了 `//`（正数碰巧对）或用了 `round`。
3. `tokens = ["10","6","9","3","+","-11","*","/","*","17","+","5","+"]` → 输出 `22`。中间 `6 / -132` 向零截断得 `0`（不是 `-1`，也不是 `-0.045`）。容易错在：除法用了 `//`，`6 // -132 == -1`，最终结果会变成 12 而不是 22。
4. `tokens = ["3","-4","-"]` → 输出 `7`。`3 - (-4)`。容易错在：把 `-4` 误判成运算符（本题运算符集合只有四个单字符，`"-4"` 不等于 `"-"`，用 `tok in ops` 判断是安全的；但如果用 `tok[0] in "+-*/"` 判断就会把负数当运算符）。
5. `tokens = ["-7","2","/"]` → 输出 `-3`。向零截断，`-7/2` 得 `-3` 而非 `-4`。这是 `//` 与 `int(a/b)` 差异的最短反例。

## 8. 面试追问与变体（3 条）

1. **追问：如果 token 是多位数、带正号 `+5`，你的解析还成立吗？** 思路：`int("+5")` 在 Python 里合法，返回 5；判断运算符必须用「完整字符串等于四个符号之一」，不能用首字符判断，否则 `+5` 会被误认成加号。
2. **追问：不用栈，能不能 O(1) 额外空间？** 思路：可以原地复用 `tokens` 数组当栈——用一个指针 `top` 指向当前栈顶位置，数字写入 `tokens[top]`，运算符读 `tokens[top-1]`、`tokens[top]` 算完写回 `tokens[top-1]` 并 `top -= 1`。时间不变，额外空间降到 O(1)（不计输入本身）。
3. **追问：如果要求支持一元负号、幂运算 `^`（右结合），后缀表达式怎么变？** 思路：一元负号在后缀里是「一个操作数 + 一个运算符」，弹一个即可；`^` 右结合在中缀转后缀时要注意，但在后缀求值阶段无影响——后缀已经消除了结合性歧义，求值逻辑不变，变的只是生成后缀的那一步。
