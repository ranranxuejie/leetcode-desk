## 1. 一句话本质

在所有长度任意的子串中，找一个子串，使得「子串长度 − 子串内出现次数最多的字符的频次 ≤ k」，求满足这个条件的最大子串长度。

换句话说：一个子串能被改成「全同字符」，当且仅当**非主角字符的数量不超过 k**，因为那些非主角字符正是要被替换掉的。主角选谁？选子串里出现最多的那个字符，这样要替换的字符最少。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子串（O(n²) 个），对每个子串统计字符频次、找出最大频次、判断 `长度 - 最大频次 ≤ k`。统计频次本身 O(n)，总复杂度 O(n³)。即使预处理前缀频次降到 O(n²)，n = 10⁵ 也过不了。

**卡在哪**：枚举子串这个动作本身是 O(n²)，必须消掉。

**关键观察**：题目问的是「最长」，而且有一个单调性质——如果某个长度 L 的子串可行，那么它的所有子串也可行吗？不完全对，但反过来：**如果窗口 [left, right] 不可行（即 `窗口长度 - 最大频次 > k`），那么任何包含它的更长窗口也不可行**。因为扩大窗口只会让「长度 − 最大频次」不减（长度增加 1，最大频次最多增加 1，差值不会变小）。

这个单调性就是滑动窗口的入场券：窗口一旦不合法，左边界只能右移，不能回退。于是两个指针各自单调右移，总移动次数 O(n)。

## 3. 从暴力到最优

**暴力**：固定左端点 left，枚举右端点 right，对每个 [left, right] 统计频次。瓶颈在「每个窗口重新统计」。

**第一步优化**：右端点右移时，只把新字符加入频次表，不重新统计。这样固定 left 时是 O(n)，总 O(n²)。还是不够。

**第二步优化（滑动窗口）**：注意到当窗口不合法时，我们不需要把 left 一个个试回去——直接把 left 右移一格，同时把离开窗口的字符频次减 1。关键是：**窗口大小只增不减**。

用一个具体例子走一遍 `s = "AABABBA", k = 1`：

| 步骤 | 操作 | 窗口 | 频次表 | maxFreq | 窗口长 - maxFreq | 是否合法 |
|---|---|---|---|---|---|---|
| 1 | right=0 加入 A | [0,0]="A" | A:1 | 1 | 0 | 是 |
| 2 | right=1 加入 A | [0,1]="AA" | A:2 | 2 | 0 | 是 |
| 3 | right=2 加入 B | [0,2]="AAB" | A:2,B:1 | 2 | 1 | 是 |
| 4 | right=3 加入 A | [0,3]="AABA" | A:3,B:1 | 3 | 1 | 是 |
| 5 | right=4 加入 B | [0,4]="AABAB" | A:3,B:2 | 3 | 2 | 否 |
| 6 | left 右移到 1，移除 A | [1,4]="ABAB" | A:2,B:2 | 2 | 2 | 否 |
| 7 | left 右移到 2，移除 A | [2,4]="BAB" | A:1,B:2 | 2 | 1 | 是 |
| 8 | right=5 加入 B | [2,5]="BABB" | A:1,B:3 | 3 | 1 | 是 |
| 9 | right=6 加入 A | [2,6]="BABBA" | A:2,B:3 | 3 | 2 | 否 |
| 10 | left 右移到 3，移除 B | [3,6]="ABBA" | A:2,B:2 | 2 | 2 | 否 |

最终答案 = 窗口最大长度 = 4。

注意第 6、7 步：窗口不合法时，我们**只移 left 一格**，然后继续移 right。窗口长度保持 4 不变（第 5 步长度 5 不合法，第 6 步移 left 后长度 4，第 7 步又移 left 长度变 3——等等，这里要小心）。

实际上标准写法是：**当窗口不合法时，left 右移一格，right 也右移一格**，窗口长度保持不变。这样窗口长度只增不减，最终窗口长度就是答案。让我重新梳理这个「只增不减」的写法：

维护 `left`，`right` 从 0 到 n-1 遍历。每次 `right` 加入字符，更新频次和 maxFreq。如果 `right - left + 1 - maxFreq > k`，说明当前窗口不合法，`left` 右移一格（移除 `s[left]` 的频次），然后 `left += 1`。注意此时窗口长度 `right - left + 1` 保持不变（因为 right 也刚加了 1）。这样窗口长度单调不减，最后 `n - left` 或 `right - left + 1` 就是答案。

**为什么 maxFreq 不需要在 left 移动时减小？** 这是本题最精妙的地方。maxFreq 记录的是「历史最大频次」。当 left 右移导致某个字符频次减小时，maxFreq 可能虚高，导致窗口「看起来合法」但实际不合法。但没关系——因为我们要的是**最大长度**，虚高的 maxFreq 只会让窗口更容易保持长度，不会让我们错过更大的答案。严格证明见第 4 节。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在整个过程中，`right - left + 1`（窗口长度）单调不减，且始终 ≤ 真实答案。

**为什么 ≤ 真实答案**：窗口长度只在两种情况下增加——right 右移且窗口合法时。窗口合法意味着 `长度 - maxFreq ≤ k`，而 maxFreq 是窗口内真实最大频次（或历史虚高值，虚高只会让条件更容易满足，但此时窗口内真实最大频次 ≤ maxFreq，所以 `长度 - 真实maxFreq ≥ 长度 - maxFreq`，可能不合法）。等等，这里需要仔细论证。

标准证明用**反证 + 单调性**：假设真实最优解长度为 L*，出现在某个窗口 [i, j]。考虑算法运行到 right = j 的时刻。此时 left 的位置记为 left'。由于窗口长度单调不减，且每次不合法时 left 只右移一格（窗口长度不变），可以归纳证明：算法过程中窗口长度从未超过 L*，且当 right 到达 j 时，left' ≤ i（因为如果 left' > i，说明之前某个时刻窗口长度已经超过 L*，矛盾）。于是 [left', j] 包含 [i, j]，长度 ≥ L*，但长度 ≤ L*（由归纳），所以长度 = L*，算法找到了答案。

**maxFreq 虚高为什么不影响**：maxFreq 只增不减，所以 `长度 - maxFreq` 只会偏小，窗口更容易被判为合法。这导致窗口可能「过早」停止收缩，但窗口长度仍然 ≤ L*（因为如果长度 > L*，则 `长度 - 真实maxFreq > k`，而 `长度 - maxFreq ≤ 长度 - 真实maxFreq`，所以 `长度 - maxFreq` 可能 ≤ k，窗口被判合法，长度继续增长——这会违反 ≤ L* 的归纳吗？不会，因为真实最优解 L* 的定义就是最大可行长度，如果窗口长度超过 L* 且被判合法，说明存在一个长度 > L* 的可行窗口，矛盾于 L* 的最优性。所以虚高 maxFreq 不会导致窗口长度超过 L*）。

**不会漏**：每个 right 位置都被考虑，left 只右移不回退，所有可能的「最优窗口右端点」都被覆盖。

## 5. 完整代码（Python）

```python
class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        from collections import defaultdict
        
        freq = defaultdict(int)  # 窗口内各字符频次
        left = 0
        max_freq = 0  # 历史最大频次（只增不减）
        ans = 0
        
        for right in range(len(s)):
            # 右端点字符加入窗口
            freq[s[right]] += 1
            # 更新历史最大频次
            max_freq = max(max_freq, freq[s[right]])
            
            # 窗口不合法：长度 - 最大频次 > k
            # 注意：这里用 if 而不是 while，因为窗口长度只增不减
            if (right - left + 1) - max_freq > k:
                # 左端点字符移出窗口
                freq[s[left]] -= 1
                left += 1
                # 窗口长度保持不变（right 刚加了 1，left 也加了 1）
            
            # 更新答案（窗口长度单调不减，最后就是答案）
            ans = max(ans, right - left + 1)
        
        return ans
```

**关键点注释**：
- `max_freq` 只增不减，这是「窗口长度只增不减」写法的核心。
- 用 `if` 而非 `while`：因为每次 right 右移最多让窗口长度 +1，不合法时 left 右移一格即可让长度回到上一轮的值，不需要连续收缩。
- `ans` 其实可以最后直接返回 `len(s) - left`，但显式维护更清晰。

## 6. 复杂度

**时间 O(n)**：`right` 从 0 到 n-1 遍历一次，`left` 最多从 0 走到 n-1，两个指针各自单调右移，总移动次数 ≤ 2n。每次移动做常数次哈希表操作（字符集大小 26，哈希操作 O(1)）。所以 O(n)。

**空间 O(1)**：频次表最多存 26 个大写字母的计数，与 n 无关。严格说是 O(Σ)，Σ = 26 为字符集大小，视为常数。

**没有 log n**：本题没有排序、没有二分、没有堆，所以不出现 log 项。

## 7. 边界与反例（至少 4 条）

1. **输入 `s = "A", k = 0` → 期望 1**。容易错：忘记单字符窗口也是合法子串，返回 0。代码中 `right=0` 时 `freq["A"]=1`，`max_freq=1`，`1-1=0 ≤ 0`，`ans=1`，正确。

2. **输入 `s = "ABAB", k = 0` → 期望 1**。容易错：以为可以替换，返回 2 或 4。k=0 时不能替换，最长全同子串就是单个字符。代码中窗口一旦长度 2 就 `2-1=1 > 0`，left 右移，窗口长度保持 1，正确。

3. **输入 `s = "AAAA", k = 2` → 期望 4**。容易错：窗口一直合法，但忘记更新 ans 或提前返回。代码中 `max_freq` 一路涨到 4，`4-4=0 ≤ 2`，ans=4，正确。

4. **输入 `s = "ABCDE", k = 1` → 期望 2**。容易错：以为可以替换成 5 个相同字符，但 k=1 只能替换 1 个，最长是 2（如 "AB" 替换一个变 "AA"）。代码中窗口长度 2 时 `2-1=1 ≤ 1` 合法，长度 3 时 `3-1=2 > 1` 不合法，ans=2，正确。

5. **输入 `s = "AABABBA", k = 0` → 期望 2**（"AA" 或 "BB"）。容易错：max_freq 虚高导致窗口不收缩。验证：right=1 时窗口 "AA" 长度 2，max_freq=2，`2-2=0 ≤ 0` 合法；right=2 加入 B，长度 3，max_freq=2，`3-2=1 > 0` 不合法，left 右移，窗口 "AB" 长度 2；后续类似，ans 保持 2，正确。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回具体的子串（不只是长度），怎么做？** 思路：在窗口长度创新高时记录 `left` 和 `right`，最后切片返回。注意 max_freq 虚高可能导致记录的窗口不是真实最优，需要额外验证或改用 `while` 收缩的写法。

2. **追问：如果 k 是动态变化的（每次查询给不同的 k），怎么预处理？** 思路：对每个可能的「主角字符」c，把 s 转成 0/1 数组（等于 c 为 0，否则为 1），问题变成「最长子数组使得和 ≤ k」，可以用前缀和 + 二分，或双指针预处理所有 k 的答案。

3. **追问：如果允许替换成任意字符（不只是大写字母），且 k 次替换可以分散在多个子串？** 思路：题目变成「选一个子串，替换其中 ≤ k 个字符使其全同」，本质不变，因为替换操作只对选中的子串有意义，分散替换不会增加任何子串的长度。
