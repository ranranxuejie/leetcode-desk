## 1. 一句话本质

把数组里所有非零元素按原顺序「挤」到前面，剩下的位置全部填 0，且全程只用一个数组。

## 2. 读完题的第一反应

**朴素解法**：新建一个数组，先遍历一遍把非零元素按顺序放进去，再补 0，最后拷贝回 `nums`。时间复杂度 O(n) 没问题，但题面明确写了「必须在不复制数组的情况下原地操作」，所以这个思路直接被判死——它额外开了 O(n) 空间。

那退一步，能不能不新建数组、只做原地删除+插入？比如遇到 0 就把它删掉、在末尾补一个 0。Python 的 `list.pop(i)` 是 O(n) 的，外层再套一层遍历就是 O(n²)，n 到 10⁴ 时是 10⁸ 级别，虽然勉强能过但显然不是出题人想要的。**瓶颈在于「删除中间元素」这个动作本身要搬移后面的所有元素。**

**关键观察**：我们其实不需要「删除」0，只需要决定每个位置最终放什么。换个角度想——如果我把所有非零元素按顺序写到数组的前部，那么写完之后，前 `k` 个位置就是答案的前半段（k 是非零个数），后 `n-k` 个位置直接填 0 即可。这个「写」的过程是顺序的、只前进不回退的，天然适合用一个指针记录「下一个非零元素该放哪」。这就是双指针的入口：**一个指针负责扫描原数组，一个指针负责维护「已处理好的非零区」的右边界。**

## 3. 从暴力到最优

**第一步：暴力（额外数组）**

```python
res = [x for x in nums if x != 0]
res += [0] * (len(nums) - len(res))
nums[:] = res
```
时间 O(n)，空间 O(n)。瓶颈是空间，违反原地要求。

**第二步：原地删除+补零（O(n²)）**

```python
i = 0
while i < len(nums):
    if nums[i] == 0:
        nums.pop(i)      # O(n) 搬移
        nums.append(0)
    else:
        i += 1
```
瓶颈是每次 `pop` 都要把后面所有元素左移一位。

**第三步：双指针（O(n)）**

核心思路：用 `slow` 指向「下一个非零元素应该写入的位置」，用 `fast` 扫描整个数组。遇到非零就写到 `slow` 处、`slow` 前进；遇到 0 就跳过。扫描结束后，`[0, slow)` 全是非零元素且保持原序，再把 `[slow, n)` 全部置 0。

拿示例 1 走一遍，`nums = [0,1,0,3,12]`，初始 `slow = 0`：

| fast | nums[fast] | 动作 | 数组状态 | slow |
|---|---|---|---|---|
| 0 | 0 | 跳过 | [0,1,0,3,12] | 0 |
| 1 | 1 | 写入 nums[0]=1 | [1,1,0,3,12] | 1 |
| 2 | 0 | 跳过 | [1,1,0,3,12] | 1 |
| 3 | 3 | 写入 nums[1]=3 | [1,3,0,3,12] | 2 |
| 4 | 12 | 写入 nums[2]=12 | [1,3,12,3,12] | 3 |

扫描结束，`slow = 3`，把 `nums[3:]` 置 0 → `[1,3,12,0,0]`。✓

注意中间状态里出现了「重复值」（比如 `1` 出现了两次），这是正常的——`fast` 还没扫到的位置是「脏数据」，我们只保证 `[0, slow)` 是干净的。这正是原地算法的典型特征：**用「已处理区」和「未处理区」的划分来避免额外空间**。

**第四步（进阶要求）：减少操作次数**

上面的写法每个非零元素都要写一次，最后还要再写一遍 0 区。如果数组里 0 很少，其实可以更省：**用交换代替覆盖**。当 `fast` 遇到非零且 `fast != slow` 时，交换 `nums[slow]` 和 `nums[fast]`，然后 `slow += 1`。这样 0 会被「换」到后面去，扫描结束时天然就位，不需要最后再补一遍 0。交换次数等于「非零元素被移动的次数」，比「写非零 + 写零」的总写入次数少。题面进阶问的「减少操作次数」指的就是这个优化。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。设在 `fast` 从 0 走到 n 的任意时刻，维护如下不变量：

> **不变量 I**：`nums[0..slow)` 恰好是原数组 `nums[0..fast)` 中所有非零元素，且保持它们在原数组中的相对顺序；`slow` 等于这个区间内非零元素的个数。

**初始化**：`fast = 0, slow = 0`，区间 `[0,0)` 为空，原数组前缀也为空，不变量成立。

**保持**：假设处理 `fast` 位置前不变量成立。
- 若 `nums[fast] == 0`：前缀 `[0, fast]` 的非零元素集合没变，`slow` 不动，不变量仍成立。
- 若 `nums[fast] != 0`：它是前缀 `[0, fast]` 中「最新出现的非零元素」，按顺序应排在已有非零元素之后，即位置 `slow`。写入后 `slow += 1`，区间扩展为 `[0, slow)`，恰好包含新元素且顺序正确。不变量成立。

**终止**：`fast == n` 时，`[0, slow)` 是全部非零元素且保序，`[slow, n)` 长度恰为 0 的个数，全部置 0 后即为所求。

**为什么不会漏**：每个位置都被 `fast` 访问且仅访问一次，非零元素必被写入。
**为什么不会重**：`slow` 单调递增，每个非零元素只写一次；写入位置 `slow` 之前从未被写过（因为 `slow` 只在写入后前进）。
**为什么保序**：`fast` 从左到右扫描，先遇到的非零元素先写入，写入位置 `slow` 也单调递增，所以相对顺序与原数组一致。

交换版本的正确性同理，只是把「写入」换成「交换」：交换后 `nums[slow]` 拿到非零值，`nums[fast]` 拿到原来的 0（或 `slow == fast` 时无操作），不变量 I 依然成立，且扫描结束时 0 已全部位于 `[slow, n)`。

## 5. 完整代码（Python）

```python
from typing import List

class Solution:
    def moveZeroes(self, nums: List[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        slow = 0  # 下一个非零元素应该写入的位置，也是已处理非零区的右边界
        for fast in range(len(nums)):
            if nums[fast] != 0:
                # 交换：把非零元素换到 slow 处，0 被换到 fast 处（可能 fast == slow，此时无操作）
                nums[slow], nums[fast] = nums[fast], nums[slow]
                slow += 1
        # 循环结束后，[0, slow) 全是非零且保序，[slow, n) 天然全是 0，无需额外补零
```

说明：这里用的是交换版，满足进阶要求。如果面试官更想要「覆盖 + 补零」的写法，把交换那行换成 `nums[slow] = nums[fast]`，循环后加 `for i in range(slow, len(nums)): nums[i] = 0` 即可，逻辑等价，只是多写了 0 区。

## 6. 复杂度

- **时间 O(n)**：`for fast in range(len(nums))` 恰好执行 n 次，循环体内是常数次比较和赋值/交换，所以总操作数是 `c·n`，n 来自数组长度。
- **空间 O(1)**：只用了 `slow`、`fast` 两个整型变量和一次交换的临时变量，与 n 无关。没有新建任何与输入规模相关的容器。
- 没有 log n 项——本题不涉及分治或二分，所有操作都是线性的。

## 7. 边界与反例（至少 4 条）

1. **输入 `[0]` → 输出 `[0]`**：`fast=0` 时 `nums[0]==0`，跳过，`slow` 保持 0，结束。容易错在循环条件写成 `while slow < fast` 之类导致空转或越界。
2. **输入 `[1]` → 输出 `[1]`**：全非零、无 0。`fast=0` 时 `slow==fast`，交换是「自己和自己换」，无副作用。容易错在交换前忘了判断 `slow != fast` 就做多余操作（虽然结果对，但违背「减少操作次数」的进阶要求）。
3. **输入 `[0,0,0]` → 输出 `[0,0,0]`**：全 0。`slow` 始终为 0，一次交换都不发生。容易错在「覆盖+补零」版本里把 `slow` 初始化成 1 或把补零区间算错。
4. **输入 `[1,2,3]` → 输出 `[1,2,3]`**：全非零且已就位。每次 `slow == fast`，交换无操作。容易错在误以为「必须发生交换」而写出 `nums[slow], nums[fast] = nums[fast], nums[slow]` 之外的逻辑（比如先 `slow += 1` 再写），导致错位。
5. **输入 `[0,1]` → 输出 `[1,0]`**：`fast=0` 跳过；`fast=1` 时 `nums[1]=1`，交换 `nums[0]` 和 `nums[1]` → `[1,0]`，`slow=1`。容易错在只做「覆盖」不做「补零」就返回，得到 `[1,1]`。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求把所有 0 移到前面、非零移到后面并保序，怎么做？** 思路：把判断条件反过来（`nums[fast] == 0` 时写入/交换），或者从右往左扫描，本质不变。
2. **追问：如果数组里除了 0 还有「目标值 target」要移到末尾，怎么改？** 思路：把 `nums[fast] != 0` 改成 `nums[fast] != target`，其余逻辑完全一致，这就是「移除元素」类问题的通用模板。
3. **追问：能否用一次遍历同时统计 0 的个数并完成移动，且保证最少的写操作？** 思路：交换版已经接近最少写操作；进一步可以只在 `fast != slow` 时交换，避免「自己换自己」的无效写，写次数等于「被移动的非零元素个数」。

## 9. 举一反三（2-3 道同类题）

1. **力扣 27. 移除元素**：同样是「原地 + 双指针 + 保序」，只是把「移到末尾」换成「删掉并返回新长度」，`slow` 的语义完全一致。
2. **力扣 26. 删除有序数组中的重复项**：双指针的 `slow` 维护「去重后区间」的右边界，`fast` 扫描，判断条件从「是否非零」变成「是否与前一个不同」。
3. **力扣 80. 删除有序数组中的重复项 II**：在 26 的基础上把「允许重复一次」编码进 `slow` 的判断，仍是同一套「读指针 + 写指针」骨架。
