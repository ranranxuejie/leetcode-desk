## 1. 一句话本质

判断能否把 s3 的每一个字符，按顺序「认领」给 s1 或 s2，使得 s1、s2 各自被完整、按原顺序地消耗掉。

## 2. 读完题的第一反应

**朴素解法**：把 s1 和 s2 的所有交错方式枚举出来，看有没有等于 s3 的。s1 长度 n、s2 长度 m，交错方式有 C(n+m, n) 种，是指数级的。n、m 到 100 时完全不可行。

**卡在哪**：枚举的爆炸来自「同一个前缀被反复重新构造」。比如 s1="aa"、s2="aa"，前两个字符是 "aa" 这件事，可能来自「s1 取两个」「s1 取一个 s2 取一个」「s2 取两个」等多种路径，但后续能不能走通只取决于「当前消耗了 s1 的前 i 个、s2 的前 j 个」这个状态，跟怎么走到这里的无关。

**关键观察**：如果 s3 是交错串，那么它长度必须等于 n+m（这是必要条件，先判掉）。在此前提下，s3 的前 i+j 个字符一定由 s1 的前 i 个和 s2 的前 j 个组成。于是「走到哪了」可以用一个二元组 (i, j) 完全刻画，而 i+j 又由 s3 的下标决定——状态空间从指数级塌缩成 (n+1)×(m+1) 的网格。这就是能上 DP 的信号：**状态可压缩、且当前状态只依赖更小的状态**。

## 3. 从暴力到最优

**第一步：暴力 DFS。** 从 (0,0) 出发，每步看 s3[i+j] 能否匹配 s1[i] 或 s2[j]，能就递归。问题：同一 (i,j) 会被不同路径重复访问，最坏指数级。

**第二步：加记忆化。** 用一个 visited 表记录「(i,j) 已经算过且失败」，避免重复。状态数 (n+1)(m+1)，每状态 O(1) 转移，复杂度降到 O(nm)。这已经能过，但递归有栈深问题（n+m 可达 200，还好，但面试官会追问迭代写法）。

**第三步：改成自底向上的 DP。** 定义 `dp[i][j]` = s1 的前 i 个和 s2 的前 j 个能否交错成 s3 的前 i+j 个。转移：

- 若 `s1[i-1] == s3[i+j-1]`，则 `dp[i][j] |= dp[i-1][j]`
- 若 `s2[j-1] == s3[i+j-1]`，则 `dp[i][j] |= dp[i][j-1]`

**走一遍示例 1**：s1="aabcc"(n=5)，s2="dbbca"(m=5)，s3="aadbbcbcac"（长度 10 = 5+5，通过长度检查）。

初始化 `dp[0][0]=True`。第一行（i=0，只用 s2 拼 s3 前缀）：s2="dbbca" 对 s3="aadbb..."，s3[0]='a' ≠ s2[0]='d'，所以 dp[0][1]=False，后面全 False。第一列（j=0，只用 s1）：s1="aabcc" 对 s3="aadbb..."，dp[1][0]=True（'a'='a'），dp[2][0]=True（'a'='a'），dp[3][0]=False（s1[2]='b' vs s3[2]='d'），后面全 False。

填到 `dp[2][1]`：s3[2]='d'，s1[1]='a' 不匹配；s2[0]='d' 匹配，看 dp[2][0]=True → dp[2][1]=True。继续填，最终 `dp[5][5]=True`，与答案一致。

**第四步：滚动数组。** 观察转移只用到 `dp[i-1][j]`（上一行同列）和 `dp[i][j-1]`（本行左一格）。把二维压成一维 `dp[j]`：外层循环 i，内层循环 j 递增。此时 `dp[j]` 在更新前存的是「上一行的 dp[i-1][j]」，`dp[j-1]` 已经是「本行的 dp[i][j-1]」，正好够用。空间从 O(nm) 降到 O(m)。这就是进阶要求。

## 4. 正确性：为什么不会漏、不会重

**不变量**：处理完 `dp[i][j]` 时，它恰好为 True 当且仅当存在一种把 s1[0..i) 和 s2[0..j) 交错成 s3[0..i+j) 的方案。

**归纳证明**（对 i+j 归纳）：

- 基础：i=j=0，空串交错成空串，dp[0][0]=True，成立。
- 归纳步：假设所有 i'+j' < i+j 的状态正确。若存在合法交错方案，看 s3[i+j-1] 这个「最后一个字符」来自谁——要么来自 s1[i-1]（此时 s1[i-1]==s3[i+j-1]，且去掉它后 s1[0..i-1) 与 s2[0..j) 交错成 s3[0..i+j-1)，由归纳假设 dp[i-1][j]=True），要么来自 s2[j-1]（对称）。转移恰好覆盖这两种情况，所以不漏。反过来，转移为 True 时，把对应字符接在归纳假设给出的方案末尾，就构造出合法方案，所以不重（不会误判为 True）。

**为什么不会重复计数**：我们只关心「存在性」，不关心方案数，所以两种来源都成立时取或即可，重复不影响正确性。

## 5. 完整代码（Python）

```python
class Solution:
    def isInterleave(self, s1: str, s2: str, s3: str) -> bool:
        n, m = len(s1), len(s2)
        # 必要条件：长度必须恰好等于两者之和，否则不可能交错
        if n + m != len(s3):
            return False

        # dp[j] 表示：当前处理到 s1 的前 i 个、s2 的前 j 个时，能否交错成 s3 的前 i+j 个
        # 一维滚动：外层 i 递增，内层 j 递增
        dp = [False] * (m + 1)
        dp[0] = True  # 空串 + 空串 -> 空串

        for i in range(n + 1):
            for j in range(m + 1):
                if i == 0 and j == 0:
                    continue  # dp[0] 已初始化
                # 情况一：s3 的当前字符来自 s1
                # 注意 dp[j] 此刻还是「上一行」的值，即 dp[i-1][j]
                from_s1 = (i > 0 and s1[i - 1] == s3[i + j - 1] and dp[j])
                # 情况二：s3 的当前字符来自 s2
                # dp[j-1] 已在本次内层循环中被更新为「本行」的值，即 dp[i][j-1]
                from_s2 = (j > 0 and s2[j - 1] == s3[i + j - 1] and dp[j - 1])
                dp[j] = from_s1 or from_s2

        return dp[m]
```

关键点：`from_s1` 读的 `dp[j]` 是旧值（上一行），`from_s2` 读的 `dp[j-1]` 是新值（本行），这个「新旧混用」正是滚动数组能成立的原因，写注释时务必点明。

## 6. 复杂度

- **时间 O(n·m)**：两层循环，i 从 0 到 n 共 n+1 次，j 从 0 到 m 共 m+1 次，每次 O(1) 的字符比较和布尔运算。n、m 各贡献一个因子，乘起来。
- **空间 O(m)**：滚动数组只开长度 m+1 的一维表。若用二维则是 O(n·m)。这里没有 log 项，因为没有任何分治或排序操作。

## 7. 边界与反例（至少 4 条）

1. `s1="", s2="", s3=""` → True。空串交错成空串，dp[0][0] 直接返回。容易错在没处理 i=j=0 的 continue，导致越界访问 s3[-1]。
2. `s1="a", s2="", s3="a"` → True。单字符来自 s1。容易错在循环里 `i>0` 判断漏写，访问 s1[-1]。
3. `s1="a", s2="b", s3="ab"` → True；但 `s1="a", s2="b", s3="ba"` → True 也对（顺序可换）。真正反例是 `s1="a", s2="b", s3="aa"` → False，长度对但字符对不上，容易错在只判长度就返回 True。
4. `s1="aabcc", s2="dbbca", s3="aadbbbaccc"` → False（示例 2）。长度 10 对，但中间 "bbb" 无法由 s1 的 "b" 和 s2 的 "bb" 按序拼出，容易错在贪心：看到 s3 当前字符同时匹配 s1 和 s2 时随便选一个，选错就死。DP 用「或」把两种选择都保留，才不漏。
5. `s1="ab", s2="bc", s3="babc"` → True（b 来自 s2，a 来自 s1，b 来自 s1，c 来自 s2）。容易错在贪心先匹配 s1 的 'a' 失败后不回溯。

## 8. 面试追问与变体（3 条）

1. **追问：如果 s1、s2 长度到 10^4，还能做吗？** 思路：O(nm) 会爆，需要换思路——通常这类题在超大输入下会退化成「字符计数 + 特殊结构」或者题目本身有额外约束（如字符集很小），否则是 NP 难，要跟面试官确认是否允许近似或改条件。
2. **追问：输出一种具体的交错方案，而不只是 True/False。** 思路：DP 表里额外记录每个状态是从上还是从左转移来的，最后从 (n,m) 回溯到 (0,0) 重建路径。
3. **追问：s3 由 s1、s2、s4 三个串交错，怎么做？** 思路：状态升到三维 dp[i][j][k]，转移三选一，复杂度 O(nmk)；空间可用两层滚动压到 O(mk)。
