## 1. 一句话本质

在 nums1 的所有排列中，选一个让「逐位比 nums2 大的位置数」最多的排列——本质是**田忌赛马**：用下等马去消耗对方的上等马，用刚好能赢的马去拿分。

## 2. 读完题的第一反应

**朴素解法**：枚举 nums1 的所有排列，对每个排列数一遍 `nums1[i] > nums2[i]` 的个数，取最大。排列数是 n!，n 到 10^5 时完全不可行。即使退一步想「对每个位置贪心地挑一个能赢的最小值」，也要 O(n²) 的匹配，10^5 下会超时。

**关键观察**：nums2 的顺序是固定的，但**我们只关心每个位置「需要多大的数才能赢」**。也就是说，nums2 里每个元素真正重要的是它的大小，而不是它现在站在哪个下标。于是可以先把 nums2 按值排序（同时记住原下标），问题就变成：把 nums1 排序后，从左到右依次去「喂」排序后的 nums2，能赢就赢，赢不了就把最小的马扔出去送死。

这个观察之所以能推进，是因为它把「排列」这个组合问题，转化成了「两个有序数组的匹配」这个线性问题——而有序数组的匹配天然可以用双指针。

## 3. 从暴力到最优

**第一步：从「枚举排列」到「排序后匹配」**

既然只关心大小关系，就把 nums1 升序排、nums2 升序排（带原下标）。排序后，一个自然的贪心是：对 nums2 从小到大处理，每次从 nums1 里拿「能赢它的最小数」。这已经能保证不漏，但「找能赢的最小值」如果线性扫描，还是 O(n²)。

**第二步：双指针消掉「找」的开销**

把 nums1 排序后，用两个指针：`left` 指向 nums1 当前最小的、`right` 指向当前最大的。对 nums2 从**大到小**处理（注意方向）：

- 如果 nums1[right] > nums2[j]（当前最大的马能赢当前最大的对手），就让 right 去赢，right--；
- 否则，nums1[right] 赢不了这个对手，那 nums1[left]（最小的马）更赢不了，干脆让 left 去送死，left++。

**小例子走一遍**：nums1 = [2,7,11,15]，nums2 = [1,10,4,11]。

排序后 nums1 = [2,7,11,15]；nums2 带下标排序 = [(1,0),(4,2),(10,1),(11,3)]。

从 nums2 最大端开始（j 从 3 到 0），left=0, right=3：

| j | nums2[j] | nums1[right] | 判断 | 动作 | 结果数组 ans |
|---|---|---|---|---|---|
| 3 | 11 | 15 | 15>11 赢 | ans[3]=15, right=2 | [_,_,_,15] |
| 2 | 10 | 11 | 11>10 赢 | ans[1]=11, right=1 | [_,11,_,15] |
| 1 | 4 | 7 | 7>4 赢 | ans[2]=7, right=0 | [_,11,7,15] |
| 0 | 1 | 2 | 2>1 赢 | ans[0]=2, left=1 | [2,11,7,15] |

得到 [2,11,7,15]，和示例一致。

再看一个「需要送死」的例子：nums1 = [12,24,8,32]，nums2 = [13,25,32,11]。

nums1 排序 = [8,12,24,32]；nums2 带下标排序 = [(11,3),(13,0),(25,1),(32,2)]。

| j | nums2[j] | nums1[right] | 判断 | 动作 | ans |
|---|---|---|---|---|---|
| 3 | 32 | 32 | 32>32 假 | ans[2]=8, left=1 | [_,_,8,_] |
| 2 | 25 | 32 | 32>25 赢 | ans[1]=32, right=2 | [_,32,8,_] |
| 1 | 13 | 24 | 24>13 赢 | ans[0]=24, right=1 | [24,32,8,_] |
| 0 | 11 | 12 | 12>11 赢 | ans[3]=12, right=0 | [24,32,8,12] |

结果 [24,32,8,12]，和示例一致。注意 j=3 时 32 赢不了 32（严格大于才算赢），于是把最小的 8 扔给 32 送死——这正是田忌赛马的核心动作。

## 4. 正确性：为什么不会漏、不会重

用**交换论证**说明「贪心选择不劣于任何最优解」。

**不变量**：处理到 nums2 排序后的第 j 个（从大到小）时，nums1 中尚未分配的数恰好是排序后的一段连续区间 [left, right]，且这个区间内的数就是「剩下的马」。

**贪心选择 1（能赢就赢）**：若 nums1[right] > nums2[j]，任何最优解都会让某个数去赢 nums2[j]（因为最大的马能赢，说明至少有一个数能赢）。假设最优解让 nums1[k]（k<right）去赢，而把 nums1[right] 留给后面某个更小的对手 nums2[j']。交换两者：nums1[right] 去赢 nums2[j] 仍然成立（它更大），nums1[k] 去对 nums2[j'] 也仍然成立（因为 nums2[j'] ≤ nums2[j] < nums1[k] 不一定成立……这里要小心）。

更干净的论证：**若 nums1[right] 能赢 nums2[j]，那么让 nums1[right] 去赢 nums2[j] 不会减少总胜场**。因为 nums1[right] 是当前最大的马，它能赢的对手集合是「所有 ≤ nums2[j] 的对手」的超集；把它用在最大的对手上，剩下的马去对付更小的对手只会更容易赢。形式化地说，若某个最优解用 nums1[k] 赢 nums2[j] 而把 nums1[right] 用于别处，交换后 nums1[right] 赢 nums2[j] 成立，nums1[k] 去顶替 nums1[right] 原来的位置——由于 nums1[k] ≤ nums1[right]，原来能赢的现在不一定能赢，但**总胜场不会减少**，因为原来 nums1[k] 赢的那一场现在由 nums1[right] 赢，而 nums1[right] 原来那一场即使输了，也只是把「赢」换成「输」，净变化为 0 或正。严格写：交换前两场胜场数 = [nums1[k]>nums2[j]] + [nums1[right]>nums2[j']]；交换后 = [nums1[right]>nums2[j]] + [nums1[k]>nums2[j']]。由 nums1[k] ≤ nums1[right] 且 nums2[j'] ≤ nums2[j]，可逐项验证交换后不小于交换前。

**贪心选择 2（赢不了就送死）**：若 nums1[right] ≤ nums2[j]，说明当前所有马都赢不了 nums2[j]（right 是最大的）。这一场必输，那让谁去输都一样，让最小的 nums1[left] 去输，把大的马留给后面更小的对手，是最优的——这同样是交换论证：任何最优解在这一场派出的马，换成 nums1[left] 后，被换下的马回到剩余集合，剩余集合只会「更强」，后续不会更差。

**不漏不重**：每轮恰好消耗 nums1 的一个元素、处理 nums2 的一个元素，n 轮后全部处理完，每个位置恰好填一次，所以是合法排列且覆盖所有位置。

## 5. 完整代码（Python）

```python
from typing import List

class Solution:
    def advantageCount(self, nums1: List[int], nums2: List[int]) -> List[int]:
        n = len(nums1)
        # nums1 升序，双指针从两端取
        nums1.sort()
        # nums2 带原下标排序，按值从小到大
        order = sorted(range(n), key=lambda i: nums2[i])

        ans = [0] * n
        left, right = 0, n - 1  # nums1 的可用区间 [left, right]

        # 从 nums2 的最大值开始处理（order 从后往前）
        for k in range(n - 1, -1, -1):
            idx = order[k]          # 当前对手在原数组中的下标
            if nums1[right] > nums2[idx]:
                # 最大的马能赢，就让它去赢（拿分）
                ans[idx] = nums1[right]
                right -= 1
            else:
                # 最大的马都赢不了，派最小的马去送死
                ans[idx] = nums1[left]
                left += 1
        return ans
```

关键逻辑说明：`order` 保存的是 nums2 的下标按值升序排列；倒序遍历 `order` 等价于「从最大的对手开始处理」。`left/right` 维护 nums1 剩余可用区间，赢就动右端，输就动左端，保证每个数只用一次。

## 6. 复杂度

- **时间 O(n log n)**：`nums1.sort()` 是 O(n log n)；`sorted(range(n), key=...)` 对 n 个下标排序，比较 key 是 O(1)，排序本身 O(n log n)；主循环 n 次，每次 O(1)。总的是 O(n log n)，瓶颈在两次排序。
- **空间 O(n)**：`order` 列表 n 个整数，`ans` 列表 n 个整数，排序的临时空间视实现而定（Python 的 Timsort 最坏 O(n)）。不计输出的话额外空间是 O(n)。

## 7. 边界与反例（至少 4 条）

1. **nums1 = [2], nums2 = [3]** → 期望 [2] → 容易错在「赢不了就返回空」或忘记送死逻辑，必须仍然填一个数。
2. **nums1 = [3], nums2 = [3]** → 期望 [3] → 容易错在把 `>` 写成 `>=`，相等不算优势，必须走送死分支（虽然结果一样，但逻辑分支不同，若有多元素会暴露）。
3. **nums1 = [1,2,3], nums2 = [3,2,1]** → 期望 [1,2,3]（或任意使胜场最大的排列，最大胜场是 2：2>1、3>2，1 输给 3）→ 容易错在从 nums2 小端开始贪心，导致把大马浪费在小对手上。
4. **nums1 全部相同，如 [5,5,5], nums2 = [5,5,5]** → 期望任意排列，胜场 0 → 容易错在死循环或指针越界，因为每轮都走送死分支，left 会一路加到 n。
5. **nums1 全部大于 nums2，如 [10,20,30], nums2 = [1,2,3]** → 期望任意排列都全胜 → 容易错在「能赢就赢」时用了最小的马而不是最大的马，虽然本题全胜时结果都对，但换成部分能赢就会错。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回字典序最小的最优排列怎么办？** 思路：在贪心框架下，当「能赢」时选「能赢的最小马」而不是最大马，需要额外的有序结构（如平衡树 / 二分查找）来取 lower_bound，复杂度升到 O(n log n) 但常数变大。
2. **追问：如果 nums2 也会变（动态查询）？** 思路：把 nums1 放进 multiset，每次对查询值做 upper_bound，找不到就取最小元素，用有序容器维护。
3. **追问：证明最大胜场数等于多少？** 思路：排序后双指针统计「能赢就配对」的个数，本质是求两个数组的最大匹配数，等价于「田忌赛马」的胜场计数，可用贪心或二分图匹配（但贪心已最优）。
