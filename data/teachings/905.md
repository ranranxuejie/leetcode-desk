## 1. 一句话本质

把数组按「元素是否为偶数」这个二元属性做一次**稳定分组**——偶数全在左、奇数全在右，组内顺序无所谓。

注意「组内顺序无所谓」是这道题最关键的一句话：题面明确说「返回满足此条件的**任一**数组」，示例 1 也列了四种答案都算对。这句话直接决定了我们不需要排序，也不需要保持原相对顺序，从而把问题从 O(n log n) 压到 O(n)。

## 2. 读完题的第一反应

**朴素解法**：新建一个结果数组，先遍历一遍把所有偶数 append 进去，再遍历一遍把所有奇数 append 进去。这个做法是对的，复杂度 O(n)，但需要额外 O(n) 空间。

如果不想开新数组，很多人的第一反应是「原地排序」：写一个比较函数，让偶数排在奇数前面。Python 里就是 `nums.sort(key=lambda x: x % 2)`。这也能过，但排序是 O(n log n)——而我们其实只关心一个二值属性，根本不需要「比较大小」这种强度的操作。**瓶颈就在这里：排序做了远超题目要求的工作量。**

**关键观察**：题目只要求「偶数在前、奇数在后」，这是一个**分区（partition）**问题，不是排序问题。分区只需要把元素分成两类，不需要类内有序。而「分成两类」这件事，用两个指针从两端往中间夹逼就能一次扫描完成——每个元素最多被看一次，O(n) 时间、O(1) 额外空间。

这个观察之所以能让你想到下一步，是因为它把「排序」降级成了「分类」，而分类天然适合双指针：左指针负责找「站错位置的奇数」，右指针负责找「站错位置的偶数」，找到一对就交换。

## 3. 从暴力到最优

**第一步：暴力（额外数组）**

```python
even = [x for x in nums if x % 2 == 0]
odd  = [x for x in nums if x % 2 == 1]
return even + odd
```

时间 O(n)，空间 O(n)。瓶颈是空间——虽然题目没限制空间，但面试官通常会追问「能不能原地做」。

**第二步：原地排序**

```python
nums.sort(key=lambda x: x % 2)
return nums
```

空间降到 O(1)（Python 的 sort 是 Timsort，最坏 O(n) 辅助空间，但概念上算原地），时间却升到 O(n log n)。瓶颈是时间——为了一个二值分类付出了排序的代价。

**第三步：双指针原地分区（最优）**

用 `i` 从左往右扫，用 `j` 从右往左扫。核心循环是：

- `i` 向右走，跳过所有偶数（它们已经在正确的一侧）；
- `j` 向左走，跳过所有奇数；
- 当 `i < j` 时，说明 `nums[i]` 是奇数、`nums[j]` 是偶数，两者都站错了位置，交换它们。

拿示例 1 走一遍，`nums = [3, 1, 2, 4]`，初始 `i = 0, j = 3`：

| 步骤 | i | j | nums | 动作 |
|---|---|---|---|---|
| 初始 | 0 | 3 | [3,1,2,4] | — |
| 1 | 0 | 3 | [3,1,2,4] | `nums[0]=3` 是奇数，i 停住；`nums[3]=4` 是偶数，j 停住；i<j，交换 |
| 2 | 0 | 3 | [4,1,2,3] | 交换后 i 右移→1，j 左移→2 |
| 3 | 1 | 2 | [4,1,2,3] | `nums[1]=1` 奇数，i 停；`nums[2]=2` 偶数，j 停；i<j，交换 |
| 4 | 1 | 2 | [4,2,1,3] | 交换后 i 右移→2，j 左移→1 |
| 5 | 2 | 1 | [4,2,1,3] | i > j，循环结束 |

结果 `[4, 2, 1, 3]`，偶数 4、2 在前，奇数 1、3 在后，符合要求（题面示例里 `[4,2,1,3]` 正是被认可的答案之一）。

对比一下：暴力法要开一个长度 4 的新数组，排序法要做约 4·log4 ≈ 8 次比较，双指针法只做了 2 次交换、扫了 4 个元素。**瓶颈被消掉的方式是：把「排序」这个强需求换成「分区」这个弱需求，弱需求允许用双指针一次扫描解决。**

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。在每一轮循环开始时（即每次判断 `i < j` 之前），下面三条同时成立：

1. `nums[0..i-1]` 全部是偶数；
2. `nums[j+1..n-1]` 全部是奇数；
3. `nums[i..j]` 是尚未确定归属的区间。

**初始化**：`i = 0, j = n-1`，前两个区间为空，第三条覆盖整个数组，成立。

**保持**：进入循环后，`i` 一直右移直到遇到奇数或 `i >= j`，`j` 一直左移直到遇到偶数或 `i >= j`。若此时 `i < j`，则 `nums[i]` 是奇数、`nums[j]` 是偶数，交换后 `nums[i]` 变成偶数、`nums[j]` 变成奇数，正好补进两侧已确定的区间，不变量继续成立。若 `i >= j`，循环退出。

**终止**：退出时 `i >= j`，此时 `nums[0..i-1]` 全是偶数、`nums[j+1..n-1]` 全是奇数，而 `i >= j` 意味着这两个区间已经覆盖（或重叠覆盖）整个数组，中间没有「归属不明」的元素。所以整个数组满足「偶数在前、奇数在后」。

**为什么不会漏**：每个元素要么被 `i` 扫过并确认是偶数，要么被 `j` 扫过并确认是奇数，要么作为一次交换的参与者被放到正确一侧。三种情况穷尽了所有元素。

**为什么不会重**：交换只发生在 `i < j` 时，且交换后 `i` 右移、`j` 左移，两个指针永不回头，所以每个位置最多被处理一次。交换本身是「对调」而非「复制」，元素个数守恒，不会凭空多出或丢掉元素。

## 5. 完整代码（Python）

```python
class Solution:
    def sortArrayByParity(self, nums: list[int]) -> list[int]:
        i, j = 0, len(nums) - 1

        while i < j:
            # 左指针右移，跳过已经在正确一侧的偶数
            while i < j and nums[i] % 2 == 0:
                i += 1
            # 右指针左移，跳过已经在正确一侧的奇数
            while i < j and nums[j] % 2 == 1:
                j -= 1
            # 此时 nums[i] 是奇数、nums[j] 是偶数，两者都站错位置，交换
            if i < j:
                nums[i], nums[j] = nums[j], nums[i]
                i += 1
                j -= 1

        return nums
```

几个容易写错的地方，注释里已经隐含，这里点明：

- 内层两个 `while` 的条件里**必须**带 `i < j`，否则当整个数组都是偶数时，`i` 会一路冲出右边界。
- 交换后的 `i += 1, j -= 1` 不能省，否则交换完两个指针不动，下一轮又会在同一对位置交换回去，死循环。
- 外层 `if i < j` 的判断不能省：内层循环可能因为 `i >= j` 而退出，此时不该再交换。

## 6. 复杂度

**时间 O(n)**：`i` 只增不减、`j` 只减不增，两者相向而行，总移动步数不超过 n。每次交换是 O(1)。所以总操作次数是 O(n)，这里的 n 就是 `len(nums)`，由「每个元素最多被一个指针访问一次」贡献。

**空间 O(1)**：只用了 `i, j` 两个整数变量和一次交换用的临时空间（Python 的元组交换底层也是常数空间）。没有开新数组，没有递归栈。注意这里**没有 log n 项**——因为我们没排序，排序才会引入 log n。

对比一下三种解法的复杂度，能更清楚「瓶颈被消掉」的含义：

| 解法 | 时间 | 空间 |
|---|---|---|
| 额外数组 | O(n) | O(n) |
| 原地排序 | O(n log n) | O(1)~O(n) |
| 双指针分区 | O(n) | O(1) |

双指针同时拿到了时间下界和空间下界，这就是它是最优解的原因。

## 7. 边界与反例（至少 4 条）

**① 输入 `[0]` → 输出 `[0]`**。`0` 是偶数，`i = j = 0`，外层循环不进，直接返回。容易错在：把 `0` 当成「假值」用 `if nums[i]` 判断奇偶，导致 `0` 被误判为奇数。必须用 `% 2 == 0` 判断。

**② 输入 `[1, 3, 5]`（全奇数）→ 输出 `[1, 3, 5]`（任意顺序）**。`i` 停在 0（`nums[0]=1` 是奇数），`j` 一路左移到 0，`i < j` 不成立，循环退出。容易错在：内层 `while` 漏写 `i < j`，`j` 减到 -1 越界。

**③ 输入 `[2, 4, 6]`（全偶数）→ 输出 `[2, 4, 6]`**。`i` 一路右移到 3，`j` 停在 2，`i < j` 不成立退出。容易错在：内层第一个 `while` 漏写 `i < j`，`i` 越界访问 `nums[3]` 抛 IndexError。

**④ 输入 `[2, 1]`（已满足条件）→ 输出 `[2, 1]`**。`i=0` 是偶数，右移到 1；`j=1` 是奇数，左移到 0；`i < j` 不成立，不交换。容易错在：交换后忘了 `i += 1, j -= 1`，或者外层没判 `i < j` 就交换，把已经正确的 `[2,1]` 换成 `[1,2]`。

**⑤ 输入 `[1, 2]`（完全反序）→ 输出 `[2, 1]`**。`i=0` 奇数停住，`j=1` 偶数停住，交换得 `[2,1]`，然后 `i=1, j=0` 退出。这是最基础的一对交换，用来验证交换逻辑本身。

## 8. 面试追问与变体（3 条）

**追问 1：如果要求偶数之间、奇数之间都保持原来的相对顺序（稳定分区），怎么做？**

双指针交换会打乱组内顺序，不再适用。思路：用额外数组做两遍扫描（先偶后奇）可以稳定，但 O(n) 空间；若要 O(1) 空间，需要类似「插入排序」的原地稳定分区，时间退化到 O(n²)。面试里通常接受 O(n) 空间的稳定解法，但要能说清「稳定」和「原地」在这题上不可兼得。

**追问 2：如果要求把数组分成三段——能被 3 整除的、余 1 的、余 2 的，怎么做？**

这是「荷兰国旗问题」的三路分区。思路：用三个指针 `low, mid, high`，`mid` 扫描，根据 `nums[mid] % 3` 的值决定和 `low` 还是 `high` 交换，一次扫描 O(n) 完成。

**追问 3：这题和「移动零」有什么区别？**

「移动零」要求把所有 0 移到末尾且**非零元素保持相对顺序**，所以不能用两端交换，要用「快慢指针 + 覆盖」：慢指针指向下一个非零元素该放的位置，快指针扫描，遇到非零就写到慢指针处。共同点是都用双指针做原地分区，区别在于是否要求稳定。

## 9. 举一反三（2-3 道同类题）

**① 力扣 283. 移动零**。共同点：都是原地分区，用双指针把满足某属性的元素挤到一侧；区别是 283 要求稳定，所以用快慢指针而非两端交换。

**② 力扣 75. 颜色分类（荷兰国旗）**。共同点：都是「按属性分组」的分区问题，本题是二路分区，75 是三路分区，双指针思路直接扩展成三指针。

**③ 力扣 26. 删除有序数组中的重复项**。共同点：都是快慢指针原地改写数组，慢指针维护「已确定区域」的边界，快指针负责探测——和本题的循环不变量是同一套思维框架。
