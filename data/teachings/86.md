## 1. 一句话本质

把一条链表按「节点值是否 < x」拆成两段，再按原顺序首尾接起来——本质是**稳定划分（stable partition）**，稳定性由「保持相对位置」这句话强制要求。

## 2. 读完题的第一反应

**朴素解法**：新建一条结果链表，第一轮扫原链表把所有 `< x` 的节点挑出来接上，第二轮再扫一遍把所有 `>= x` 的接上。这个思路是对的，但两轮扫描意味着你要么把原链表遍历两遍（每轮都要从头走，O(n) 时间但常数翻倍、代码里要处理「第二轮从哪开始」），要么先存进数组再重建（O(n) 额外空间）。

更常见的朴素写法是**数组法**：把节点值全读进列表，用 Python 的 `sorted(..., key=lambda v: v >= x)` 做稳定排序，再重建链表。它卡在两点：一是 O(n) 额外空间；二是「重建链表」这一步在面试里会被追问「能不能原地做」，而排序的稳定性虽然 Python 保证，但面试官想听的是链表指针操作，不是调库。

**关键观察**：题目只要求「小于的在前、大于等于的在后」，**没有要求组内有序**，只要求组内保持原相对顺序。这句话直接排除了排序，指向一个更轻的动作：**一次遍历，把节点分别挂到两条临时链表的尾部**。因为遍历是从头到尾的，挂到尾部天然就保持了原顺序——稳定性是「尾插」这个动作免费送的，不需要额外比较。

这个观察一旦成立，问题就从「怎么排序」塌缩成「怎么维护两条链表的尾指针」，而尾指针正是链表题里最标准的 O(1) 工具。

## 3. 从暴力到最优

**第一步：数组法（能过，但不是考点）**

```python
vals = []
cur = head
while cur:
    vals.append(cur.val)
    cur = cur.next
vals.sort(key=lambda v: v >= x)   # 稳定排序，False 在前
# 再重建链表
```

瓶颈：O(n) 空间 + 依赖库排序。面试里这么写基本等于放弃。

**第二步：两轮扫描法**

第一轮收集 `< x` 的节点串成链表 A，第二轮收集 `>= x` 的串成链表 B，最后 `A尾.next = B头`。时间 O(n)，但你要遍历两遍，且第二轮得重新从 head 走——代码里多一层循环，容易在「第二轮从哪开始」上写错。

**第三步：一次遍历 + 双哑节点（最优）**

维护两条带哑头（dummy）的链表：`small` 存 `< x`，`large` 存 `>= x`，各自维护一个尾指针。遍历原链表一次，每个节点根据值挂到对应链表的尾部，最后把 `small` 的尾接到 `large` 的头。

用示例 1 走一遍：`head = [1,4,3,2,5,2], x = 3`。

| 当前节点 | 判定 | small 链 | large 链 |
|---|---|---|---|
| 1 | <3 | 1 | 空 |
| 4 | >=3 | 1 | 4 |
| 3 | >=3 | 1 | 4→3 |
| 2 | <3 | 1→2 | 4→3 |
| 5 | >=3 | 1→2 | 4→3→5 |
| 2 | <3 | 1→2→2 | 4→3→5 |

拼接：`small` 尾（第二个 2）`.next = large` 的头（4），得到 `1→2→2→4→3→5`。和官方输出一致。

注意最后一步必须把 `large` 尾的 `next` 置为 `None`，否则可能指回原链表里的某个节点，形成环——这是本题最容易踩的坑，第 7 节会展开。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来证。

设遍历到原链表的第 k 个节点时，已处理的前 k 个节点被分到 `small` 和 `large` 两条链中。维护两个不变量：

- **不变量 A（不漏不重）**：每个已处理节点恰好出现在 `small` 或 `large` 其中一条链上，且只出现一次。归纳基础：k=0 时两链皆空。归纳步：处理第 k+1 个节点时，它只被挂到一条链的尾部，且原链表中它只被访问一次，故仍恰好一次。
- **不变量 B（组内相对顺序）**：`small` 链中节点的相对顺序 = 它们在原链表中出现的相对顺序；`large` 同理。归纳步：新节点总是追加到某条链的**尾部**，而遍历顺序就是原链表顺序，所以追加不会打乱已有顺序。

遍历结束后，不变量 A 保证所有 n 个节点都被分完（没有遗漏、没有重复），不变量 B 保证两个分区内部各自稳定。最后 `small尾.next = large头` 把两段拼起来，由于 `small` 中全是 `< x`、`large` 中全是 `>= x`，拼接后满足「小于的都在大于等于的之前」，且拼接不改变各自内部顺序。三件事合起来就是题目要求的全部。

## 5. 完整代码（Python）

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def partition(self, head: ListNode, x: int) -> ListNode:
        # 两条哑节点链表：small 存 < x，large 存 >= x
        small_dummy = ListNode(0)
        large_dummy = ListNode(0)
        # 各自的尾指针，用于 O(1) 尾插
        small_tail = small_dummy
        large_tail = large_dummy

        cur = head
        while cur:
            nxt = cur.next          # 先存下一个，防止改指针后丢失
            if cur.val < x:
                small_tail.next = cur
                small_tail = cur    # 尾指针后移
            else:
                large_tail.next = cur
                large_tail = cur
            cur = nxt               # 用预先存好的 next 前进

        # 关键：large 链尾必须断开，否则可能指回原链表形成环
        large_tail.next = None
        # 把 small 链尾接到 large 链头（跳过哑节点）
        small_tail.next = large_dummy.next

        # 返回 small 的真实头；若 small 为空，则返回 large 的头
        return small_dummy.next if small_dummy.next else large_dummy.next
```

两个细节值得单独说：

- `nxt = cur.next` 必须在改 `cur.next` 之前存。虽然本题里我们改的是 `small_tail.next` / `large_tail.next` 而不是 `cur.next`，但 `cur` 被挂到某条链后，它的 `next` 会在后续被覆盖，提前存 `nxt` 是防御性写法，也方便你以后改写成「原地摘链」版本。
- `large_tail.next = None` 不能省。考虑 `head = [1,2], x = 3`：所有节点都进 `small`，`large` 是空链，`large_tail` 就是 `large_dummy`，它的 `next` 本来就是 `None`，没事。但考虑 `head = [3,1,2], x = 3`：`large` 链是 `3`，`small` 链是 `1→2`，`large_tail` 是节点 3，它的 `next` 原本指向 1（原链表里 3 的下一个），如果不置 `None`，拼接后 `1→2→3→1→...` 成环。这是本题最高频的 WA。

## 6. 复杂度

- **时间 O(n)**：`while cur` 循环对每个节点执行一次，循环体内全是常数操作（一次比较、一次指针赋值、一次尾指针更新）。n 是链表节点数，来自「每个节点必须被判定一次」这个下界，所以 O(n) 是最优的。
- **空间 O(1)**：只用了 `small_dummy`、`large_dummy`、两个尾指针、`cur`、`nxt` 共 6 个额外变量，与 n 无关。注意我们**没有新建节点**，只是重排原有节点的 `next` 指针，所以不算 O(n) 空间。递归写法会是 O(n) 栈空间，这里刻意用迭代。

## 7. 边界与反例（至少 4 条）

1. **空链表** `head = [], x = 0` → 期望 `[]`。容易错在没判空就直接 `small_tail.next = ...`，其实哑节点写法天然处理了空链表（循环不进，返回 `small_dummy.next` 即 `None`），但如果你写成先取 `head.val` 就会崩。
2. **全部小于 x** `head = [1,2], x = 5` → 期望 `[1,2]`。容易错在拼接时 `small_tail.next = large_dummy.next`（即 `None`），这步是对的；但若你忘了 `large_tail.next = None` 且 `large` 非空，就会出问题——本例 `large` 为空所以侥幸对，换成 `[3,1,2], x = 3` 就暴露了。
3. **全部大于等于 x** `head = [3,4], x = 1` → 期望 `[3,4]`。此时 `small_dummy.next` 是 `None`，返回语句必须走 `large_dummy.next` 分支，否则返回 `None` 丢链。
4. **成环陷阱** `head = [3,1,2], x = 3` → 期望 `[1,2,3]`。`large` 链只有节点 3，它的 `next` 还指着原链表里的 1；不置 `None` 就成环，判题器会超时或报错。这是最值得单独强调的反例。
5. **单节点** `head = [1], x = 1` → 期望 `[1]`。节点进 `large`，`small` 空，走 `large_dummy.next` 分支，且 `large_tail.next = None` 把原本就为 `None` 的指针再置一次，无害。

## 8. 面试追问与变体（3 条）

1. **追问：能不能不用哑节点？** 思路：可以，但要额外处理「某条链为空时头指针的初始化」，代码里会多出 `if small_head is None: small_head = cur` 这类分支，哑节点正是为了消掉这些分支，面试时建议保留哑节点并说明理由。
2. **追问：如果要分成三段（< x、== x、> x）呢？** 思路：同一套模板扩成三条哑链表 + 三个尾指针，最后两两拼接，复杂度不变，考的是你能不能把「双链」抽象成「多链」。
3. **追问：要求原地（in-place）且不借助哑节点，只许改指针，怎么做？** 思路：本质仍是双链，但需要先找到第一个 `>= x` 的节点作为分界，再用「摘链—插到尾」的方式搬运后续的小节点；难点在于维护「分界点前驱」和「尾指针」两个游标，容易在头节点就是 `>= x` 时写错。
