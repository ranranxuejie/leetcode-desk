## 1. 一句话本质

把单词序列按"每行尽量塞满"切成若干段，然后对**非最后一行**做"空格数按 maxWidth 补齐、且左多右少地均摊"的字符串拼接，最后一行退化为普通左对齐。

## 2. 读完题的第一反应

朴素解法很自然：外层循环扫单词，内层循环往当前行里塞单词，塞到再塞一个就超宽为止，然后拼这一行。**这个框架本身没错，题目的"贪心"就是明示你这么干**。真正卡人的不是找行，而是**拼行**：

- 一行里 k 个单词，单词总字符数是 `sum_len`，要补的空格总数是 `maxWidth - sum_len`。
- 这些空格要分到 `k-1` 个间隙里，且"左边不少于右边"。
- 如果 `k == 1`，没有间隙可分，只能把空格全堆在单词右边。
- 如果这是最后一行，空格全堆在行尾，单词之间只留 1 个空格。

所以关键观察是：**"切行"和"排版"是两个独立子问题**。切行用贪心（能塞就塞，这是题面钦定的），排版用整除 + 取余（`base = total // gaps`，`extra = total % gaps`，前 `extra` 个间隙多放一个空格）。把这两件事拆开，代码结构立刻清晰：一个 while 找行边界，一个函数负责把 `words[l:r]` 渲染成字符串。

## 3. 从暴力到最优

这题没有"暴力 vs 最优"的复杂度鸿沟——任何正确解法都必须至少读一遍所有单词、写一遍所有输出字符，下界就是 `O(总字符数)`。所谓"优化"是把**拼接方式**从低效改成高效，以及把**边界判断**从混乱改成清晰。

**低效写法**：每行用 `" " * n` 反复字符串加法拼接。Python 里字符串不可变，`s += t` 在循环里是 `O(len(s))` 的拷贝，一行拼 k 次就是 `O(k * maxWidth)`，虽然本题规模小（300 词、宽 100）不会超时，但这是坏习惯。

**正确写法**：先把一行的所有片段收进 list，最后 `"".join(parts)` 一次成型，单行 `O(maxWidth)`。

走一遍示例 1 的前两行，`maxWidth = 16`：

```
words = ["This","is","an","example","of","text","justification."]
```

**找第一行**：从 `l=0` 开始，`cur_len` 表示"这些单词 + 最少 1 个间隔"的长度。

- 放 "This"：`cur_len = 4`
- 放 "is"：需要 `4 + 1 + 2 = 7 ≤ 16`，接受，`cur_len = 7`
- 放 "an"：`7 + 1 + 2 = 10 ≤ 16`，接受，`cur_len = 10`
- 放 "example"：`10 + 1 + 7 = 18 > 16`，拒绝。行边界 `r = 3`。

**渲染第一行**：`words[0:3] = ["This","is","an"]`，`sum_len = 8`，`gaps = 2`，`total_space = 16 - 8 = 8`。`base = 8 // 2 = 4`，`extra = 8 % 2 = 0`。两个间隙各 4 个空格 → `"This    is    an"`（长度 16 ✓）。

**找第二行**：`l = 3`。

- 放 "example"：`cur_len = 7`
- 放 "of"：`7 + 1 + 2 = 10 ≤ 16`，接受
- 放 "text"：`10 + 1 + 4 = 15 ≤ 16`，接受
- 放 "justification."：`15 + 1 + 14 = 30 > 16`，拒绝。`r = 6`。

**渲染第二行**：`["example","of","text"]`，`sum_len = 13`，`gaps = 2`，`total_space = 3`。`base = 1`，`extra = 1`。第一个间隙 `1+1=2` 个空格，第二个间隙 `1` 个空格 → `"example  of text"`（长度 16 ✓）。

**第三行**：只剩 `["justification."]`，是最后一行，左对齐 + 尾部补空格 → `"justification.  "`（14 + 2 = 16 ✓）。

注意第二行 `extra = 1` 时，多出来的那个空格给了**最左边**的间隙——这正是"左侧空格数多于右侧"的落地方式：前 `extra` 个间隙各多 1 个。

## 4. 正确性：为什么不会漏、不会重

用**不变量**论证。维护循环不变量：**进入每轮外层循环时，`words[0:l]` 已经被完整、正确地排版成若干行，且 `l` 是下一个尚未处理的单词下标。**

- **初始化**：`l = 0`，前缀为空，成立。
- **保持**：内层贪心从 `l` 出发，在"再加一个单词（含 1 个间隔）不超过 maxWidth"的前提下尽量右扩，得到 `r`。由于每个单词长度 `≤ maxWidth`（题面保证），至少能放下 `words[l]` 一个，所以 `r > l`，行非空，不会死循环。渲染后 `l = r`，前缀扩大且仍正确。
- **终止**：`l` 严格递增且上界为 `n`，循环必停，此时所有单词都已排版。

**不会漏**：每个单词恰好被某一次 `words[l:r]` 覆盖一次，因为区间 `[l, r)` 首尾相接、无缝无叠。

**不会重**：`l` 单调递增，区间互不重叠。

**贪心为什么是"对"的**：题面直接规定"尽可能多地往每行放单词"，所以这不是需要证明最优性的贪心，而是**题目定义的规则**。我们要证明的只是"渲染函数忠实执行了规则"：非末行且 `gaps > 0` 时，`base * gaps + extra = total_space`（整除恒等式），且前 `extra` 个间隙比后面的多 1，满足"左多右少"；`gaps == 0` 或末行时，空格全补在行尾，满足"左对齐、不插额外空格"。

## 5. 完整代码（Python）

```python
class Solution:
    def fullJustify(self, words: list[str], maxWidth: int) -> list[str]:
        res = []
        n = len(words)
        l = 0

        while l < n:
            # ---- 第一步：贪心确定这一行能放哪些单词 ----
            r = l
            cur_len = 0          # 当前行"单词字符数 + 最少间隔数"的总长
            while r < n:
                # 若 r 不是本行第一个词，需要额外 1 个空格做间隔
                need = len(words[r]) + (1 if r > l else 0)
                if cur_len + need > maxWidth:
                    break
                cur_len += need
                r += 1
            # 现在 words[l:r] 是本行的单词，r 是开区间右端

            # ---- 第二步：渲染这一行 ----
            sum_len = sum(len(w) for w in words[l:r])  # 单词字符总数
            gaps = r - l - 1                            # 间隙个数
            is_last = (r == n)                          # 是否是最后一行

            if is_last or gaps == 0:
                # 最后一行，或本行只有一个单词：左对齐，单词间 1 个空格，尾部补满
                line = " ".join(words[l:r])
                line += " " * (maxWidth - len(line))
            else:
                # 普通行：空格尽量均摊，前 extra 个间隙各多 1 个
                total_space = maxWidth - sum_len
                base = total_space // gaps
                extra = total_space % gaps
                parts = []
                for i in range(gaps):
                    parts.append(words[l + i])
                    # 前 extra 个间隙多放一个空格
                    parts.append(" " * (base + (1 if i < extra else 0)))
                parts.append(words[r - 1])   # 最后一个单词后面不加间隙
                line = "".join(parts)

            res.append(line)
            l = r   # 推进到下一行起点

        return res
```

## 6. 复杂度

设单词总数 `n`，`maxWidth = W`，所有单词字符总长 `S`。

- **时间 `O(S + n + 输出总长)`**：外层 while 每轮至少消费 1 个单词，总共 `n` 轮；内层 while 的 `r` 全局单调递增，所有轮次加起来最多扫 `n` 次，所以"找行"部分总计 `O(n)`。每行渲染时 `sum(len(w))` 和 `join` 都只碰本行字符，所有行加起来是 `O(S + 输出总长)`。输出总长 = 行数 × W，行数 ≤ n，所以整体 `O(S + n·W)`，在本题约束下就是 `O(n·W)` 量级。**没有 log 项**——这题不涉及排序或二分。
- **空间 `O(n·W)`**：结果列表存所有行，每行长度 W，行数最多 n。除此之外只有常数个临时变量；`parts` 是单行的临时缓冲，`O(W)`。

## 7. 边界与反例（至少 4 条）

1. **`words = ["a"], maxWidth = 1`** → `["a"]`。容易错在：把唯一一行当普通行处理，`gaps = 0` 时除零。代码里 `gaps == 0` 分支兜住了。
2. **`words = ["a","b","c"], maxWidth = 1`** → `["a","b","c"]`。每行一个词，全是"单单词行"。容易错在：单单词行误走均摊分支，`gaps = 0` 触发 `ZeroDivisionError`。
3. **`words = ["Listen","to","many","speak","to","few"], maxWidth = 6`** → `["Listen","to    ","many  ","speak ","to    ","few   "]`。全是单单词行 + 最后一行，容易错在：单单词行忘了在**尾部**补空格到 W，输出长度不足。
4. **`words = ["What","must","be","acknowledgment","shall","be"], maxWidth = 16`**（示例 2）→ 第二行 `"acknowledgment "` 是单单词行，第三行 `"shall be "` 是最后一行。容易错在：把第二行当普通行，试图在单词内部或尾部之外的地方补空格；以及最后一行 `"shall be"` 忘了补尾空格变成 16 长。
5. **`words = ["My","name","is"], maxWidth = 5`** → `["My   ","name ","is   "]`。第一行 `"My"` 后补 3 空格；第二行 `"name"` 补 1 空格；第三行最后一行 `"is"` 补 3 空格。容易错在：把 `"My"` 和 `"name"` 塞进同一行（`2+1+4=7 > 5`，塞不下），判断间隔时漏算那 1 个空格。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求"右侧空格不少于左侧"怎么办？** 思路：把 `extra` 个多出的空格从**右边**开始分配，即第 `i` 个间隙（从 0 数）在 `i >= gaps - extra` 时多放 1 个。
2. **追问：如果单词之间允许"两端对齐但单词内部也可以断行"（类似 CSS 的 word-break）？** 思路：这就变成完全不同的题，需要按字符切分，贪心单位从"单词"变成"字符"，且要处理连字符规则，通常用 DP 最小化"行尾空格平方和"（LeetCode 1592 的加权版本）。
3. **追问：如果要求所有行的"行尾空格平方和"最小（而不是贪心塞满）？** 思路：这是经典的"文本排版 DP"，`dp[i]` 表示前 `i` 个单词的最优代价，转移枚举最后一行放 `words[j:i]`，代价是 `(剩余空格)^2`（最后一行代价为 0），`O(n^2)`。
