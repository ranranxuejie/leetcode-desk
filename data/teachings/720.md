## 1. 一句话本质

在所有「自身以及它的每一个前缀都出现在词典里」的单词中，挑出最长的那一个；长度相同时取字典序最小的。

关键词是**每一个前缀**。一个单词合格，不是因为它能由某个单词加一个字母得到，而是因为从长度 1 到它自身长度，每一层前缀都得在词典里存在。这条链一旦断在任何一层，这个单词就不合格。

## 2. 读完题的第一反应

朴素解法很直接：对每个单词 `w`，枚举它的所有前缀 `w[:1], w[:2], ..., w[:len(w)-1]`，逐个去 `words` 里查是否存在。全部存在就说明 `w` 合格，然后在所有合格单词里按「长度降序、字典序升序」取第一个。

它卡在哪？查一次是 O(n) 的线性扫描（n 是单词个数），一个单词最多 30 个前缀，总共 n 个单词，于是 O(n² · L)，L 是最大长度。n=1000 时是 3×10⁷ 量级的字符串比较，能过但很丑。真正的瓶颈是**「查存在」这件事被做成了线性扫描**。

关键观察有两层：

第一层，**「前缀链」这个结构天然是树形的**。`w` 合格 ⟺ `w` 的父节点（去掉最后一个字母）合格，且父节点本身在词典里。这是一个可以自底向上递推的定义，意味着我们不需要对每个单词独立地枚举前缀，而是可以按长度从小到大处理，让每个单词只依赖一个更短的单词。

第二层，**「查存在」应该用集合**。把 `words` 丢进 `set`，查一次变成 O(1)（均摊），瓶颈立刻从「查找」转移到「排序」上。

这两层合起来，就指向了排序 + 哈希集合的解法。字典树是另一条路，本质相同，只是把「前缀是否存在」显式地存成了树边。

## 3. 从暴力到最优

**第一步：暴力枚举前缀。**

以示例 2 的 `"apple"` 为例，枚举前缀得 `"a"`, `"ap"`, `"app"`, `"appl"`，四个都在词典里，合格。再看 `"apply"`，前缀是 `"a"`, `"ap"`, `"app"`, `"appl"`，也全在，也合格。两者长度都是 5，比较字典序，`"apple" < "apply"`，取 `"apple"`。这一步逻辑没问题，问题只在每次 `in words` 都是 O(n)。

**第二步：换成集合。**

`word_set = set(words)`。现在 `"appl" in word_set` 是 O(1)。对每个单词仍然要枚举最多 30 个前缀，总代价 O(n · L)。这一步消掉的是「查找」这个瓶颈。

**第三步：消掉「对每个单词重复枚举前缀」的浪费。**

注意 `"apple"` 合格蕴含 `"appl"` 合格、`"app"` 合格……也就是说，如果我们按长度从小到大处理，处理到 `"appl"` 时已经知道它合不合格，那么 `"apple"` 只需要检查一件事：`"appl"` 合格吗？加上 `"apple"` 自己在集合里（它当然在，它就是输入之一），就够了。

于是维护一个 `valid` 集合，只装合格单词。按长度升序处理：

- 处理 `"a"`：长度 1，前缀为空，直接合格 → `valid = {"a"}`
- 处理 `"ap"`：去掉末字母得 `"a"`，`"a" ∈ valid` → 合格 → `valid = {"a", "ap"}`
- 处理 `"app"`：父是 `"ap"`，在 → 合格 → `valid` 加 `"app"`
- 处理 `"appl"`：父是 `"app"`，在 → 合格
- 处理 `"apple"`：父是 `"appl"`，在 → 合格
- 处理 `"apply"`：父是 `"appl"`，在 → 合格
- 处理 `"banana"`：父是 `"banan"`，不在 `valid`（也不在词典）→ 不合格，跳过

最后在合格集合里按「长度降序、字典序升序」取第一个，得 `"apple"`。

这一步把每个单词的检查从「最多 30 次查找」压到「1 次查找」，总代价 O(n · L) 变成 O(n)，剩下的开销全在排序上。为什么能这么压？因为长度升序保证了父节点一定先于子节点被处理，父节点的合格性已经算好了——这就是**拓扑序**的思想，树上的父子依赖被排序一次性满足了。

**第四步（可选）：字典树。**

把 `words` 建成 Trie，然后 DFS：只有当一个节点的 `is_end` 为真、且它所有祖先的 `is_end` 也都为真时，这条路径才构成合格单词。DFS 时优先走 `'a'` 到 `'z'`，第一个到达的最深节点就是答案（天然满足字典序最小）。复杂度 O(n · L)，和排序法同阶，但常数和代码量都更大。面试时排序法足够，Trie 作为追问再展开。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。

**不变量**：在处理完所有长度 ≤ k 的单词后，`valid` 集合恰好等于「长度 ≤ k 且合格」的单词集合。

- **基础**：长度 1 的单词，前缀为空，按定义合格（题面允许从单字母开始构建，示例 1 的 `"w"` 就是起点）。代码里对 `len(w) == 1` 直接放行，与定义一致。
- **归纳**：设不变量对 k-1 成立，考虑长度恰为 k 的单词 `w`。`w` 合格 ⟺ `w` 的所有真前缀都在词典中 ⟺ `w[:-1]` 在词典中且 `w[:-1]` 合格（因为 `w[:-1]` 的所有前缀就是 `w` 的所有真前缀去掉最后一个）。而 `w[:-1]` 长度为 k-1，由归纳假设，它的合格性已正确记录在 `valid` 中。所以代码里 `w[:-1] in valid` 这个判断，恰好等价于 `w` 合格。归纳成立。

**不会漏**：任何合格单词 `w`，其长度对应的那一轮一定会被处理（我们遍历了所有单词），且判断条件由上面的等价性保证为真，所以它一定进 `valid`。

**不会重**：`valid` 是集合，重复插入无副作用；最终选答案时遍历的是 `valid`，每个单词只出现一次。

**选答案的正确性**：合格集合确定后，题目要求「最长优先、同长字典序最小」。代码用 `min(valid, key=lambda w: (-len(w), w))`，`-len(w)` 让长单词排前面，`w` 让同长时字典序小的排前面，`min` 取到的就是目标。这是对题目排序规则的字面翻译，不存在歧义。

一个容易忽略的点：**`w[:-1] in valid` 隐含了 `w[:-1]` 在词典里**，因为 `valid` 只从 `words` 里挑。所以不需要额外再查一次 `word_set`。但长度 1 的分支要单独处理，因为 `""` 不在任何集合里。

## 5. 完整代码（Python）

```python
class Solution:
    def longestWord(self, words: list[str]) -> str:
        # 按长度升序排序；同长度时字典序升序也无妨，
        # 因为 valid 是集合，插入顺序不影响最终结果。
        words.sort(key=len)

        valid = set()  # 只装「合格」单词：自身及所有前缀都在词典中

        for w in words:
            if len(w) == 1:
                # 单字母单词没有真前缀，按定义直接合格
                valid.add(w)
            elif w[:-1] in valid:
                # 父节点（去掉末字母）已确认合格，
                # 且父节点本身在词典里（因为它来自 words），
                # 所以 w 的所有前缀都在词典中，w 合格
                valid.add(w)
            # 否则 w 不合格，跳过；它的子节点也不会合格，
            # 因为子节点检查父节点时会失败

        if not valid:
            return ""

        # 最长优先，同长取字典序最小
        return min(valid, key=lambda w: (-len(w), w))
```

注意 `words.sort(key=len)` 是稳定排序，同长度单词保持输入顺序，但这不影响正确性——同长度的单词之间没有依赖关系（一个不可能是另一个的前缀，因为长度相同且不相等）。

## 6. 复杂度

设 n 为单词个数，L 为最大单词长度（题面给 L ≤ 30）。

**时间**：O(n log n · 比较代价 + n · L)。

- 排序：`sort(key=len)` 对 n 个元素排序，比较的是整数长度，O(n log n)。这里的 log n 来自排序的比较次数。
- 遍历：每个单词做一次切片 `w[:-1]`，代价 O(L)（字符串切片要复制），加一次集合查找 O(L)（哈希要算整个字符串）。所以是 O(n · L)。L 是常数 30，实际就是 O(n)。
- 选答案：`min` 遍历 `valid`，每个元素算 key 要 O(L)，O(n · L)。

合计 O(n log n + n · L)。因为 L ≤ 30 是常数，口语上可以说 O(n log n)。

**空间**：O(n · L)。`valid` 最多存 n 个单词，每个单词占 L 个字符；`words.sort` 原地排序，额外空间 O(log n)（排序栈）。切片 `w[:-1]` 每次临时产生一个长度 L-1 的字符串，是 O(L) 的瞬时开销，不计入峰值。

对比暴力法：O(n² · L) 时间，瓶颈在「每个单词的每个前缀都线性扫描整个数组」。排序法把「查找」降到 O(1) 均摊，把「重复枚举前缀」降到「只查一次父节点」，两处瓶颈都消掉了。

## 7. 边界与反例（至少 4 条）

1. **输入 `["a"]`** → 期望 `"a"`。容易错在：把「长度 1 的单词」也拿去查 `w[:-1] in valid`，`""` 不在集合里，于是判为不合格，返回 `""`。必须单独放行长度 1。

2. **输入 `["banana"]`** → 期望 `""`。`"banana"` 的父 `"banan"` 不在词典，不合格；词典里也没有别的单词，`valid` 为空。容易错在：忘了处理 `valid` 为空时返回空串，直接 `min` 会抛 `ValueError`。

3. **输入 `["a", "ab", "abc", "abcd"]`** → 期望 `"abcd"`。这是标准链，容易错在：排序时用了 `key=lambda w: (len(w), w)` 之类的复合键，导致同长度单词的处理顺序被打乱——本题不受影响，但如果误以为「必须字典序升序处理才能保证父先于子」，会写出多余逻辑。真正保证父先于子的是**长度**，不是字典序。

4. **输入 `["abc", "ab", "a"]`**（乱序）**→ 期望 `"abc"`**。容易错在：不排序直接遍历，处理 `"abc"` 时 `"ab"` 还没进 `valid`，误判为不合格。排序是正确性的前提，不是优化。

5. **输入 `["a", "aa", "aaa", "aaaa"]` 与 `["a", "aa", "aaa", "aaab"]` 混合**，比如 `["a", "aa", "aaa", "aaaa", "aaab"]` → 期望 `"aaaa"`。`"aaab"` 也合格（父 `"aaa"` 在），长度同为 4，字典序 `"aaaa" < "aaab"`，取 `"aaaa"`。容易错在：只按长度取最大，忘了同长比字典序。

6. **输入 `["w", "wo", "wor", "worl", "world", "worlds"]`** → 期望 `"worlds"`。容易错在：以为答案一定是输入里最长的那个，但若 `"worlds"` 的父 `"world"` 不在词典，它就不合格，答案应回退到 `"world"`。本题父在，所以 `"worlds"` 胜出——这个例子用来检验「合格性优先于长度」。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回所有合格单词，按长度降序、字典序升序输出，怎么做？**
   思路：`valid` 集合已经算好，直接 `sorted(valid, key=lambda w: (-len(w), w))` 返回列表即可，主逻辑不变。

2. **追问：如果词典很大（n = 10⁵），但单词总字符数有上限，排序法还合适吗？**
   思路：排序 O(n log n) 仍是主导。可以换成 Trie：建树 O(总字符数)，DFS 一次 O(总字符数)，且 DFS 按 `'a'→'z'` 走，第一个到达的最深合格节点就是答案，省掉排序和最后的 `min`。代价是空间从 O(n) 变成 O(总字符数)，代码量增加。

3. **追问：如果允许「从任意单词开始，每次在任意位置插入一个字母」而不是只在末尾追加，题意怎么变？**
   思路：这就退化成「判断 `w` 的每个子序列（保持相对顺序）是否都在词典中」，不再是前缀链，排序递推失效，需要按长度分层做 BFS/DP，复杂度显著上升。这个追问的目的是检验你是否真的理解「只在末尾追加」这个约束在本题里的作用——它把依赖关系变成了一棵树。

## 9. 举一反三（2-3 道同类题）

1. **力扣 648. 单词替换**：同样用「前缀是否在词典中」做判断，只是把「合格」换成「找到最短的词根就替换」，Trie 或按长度排序 + 集合都能做。

2. **力扣 139. 单词拆分**：把「前缀链」推广成「任意切分」，用 DP 判断 `s[:i]` 能否由词典拼出，和本题的递推思想同源——都是「当前状态依赖一个更短的状态是否成立」。

3. **力扣 208. 实现 Trie（前缀树）**：本题 Trie 解法的地基，把「前缀存在性」显式建模成树，是理解「为什么前缀链是树形依赖」的最佳练习。
