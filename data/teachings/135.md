## 1. 一句话本质

在一条评分序列上，给每个位置赋一个正整数，使得任意相邻两位置中评分较高者的数值严格更大，求所有位置数值之和的最小值。

## 2. 读完题的第一反应

**朴素解法**：把「每个孩子至少 1 颗」作为初始分配，然后反复扫描数组，只要发现某个相邻对不满足「评分高者糖果多」，就给评分高的那个 +1，直到整轮扫描没有任何修改为止。这本质上是「松弛到不动点」。

它卡在哪：最坏情况下，一个长度为 n 的单调递增序列，最右边的孩子最终要拿 n 颗糖，而每一轮扫描只能把不满足的地方推进一格，于是需要 O(n) 轮、每轮 O(n)，总复杂度 O(n²)。n 到 5×10⁴ 时就是 2.5×10⁹ 次操作，直接超时。

**关键观察**：约束只存在于「相邻」之间，而且方向是单向的——`ratings[i] > ratings[i-1]` 只约束 i 相对 i-1，`ratings[i] > ratings[i+1]` 只约束 i 相对 i+1。这两类约束互不干扰，可以拆开处理。更具体地说：一个孩子最终的糖果数，只取决于「以他为终点的连续上升段有多长」和「以他为起点的连续下降段有多长」，取两者较大值再加 1。这个观察把「反复松弛」变成了「两次单向扫描」。

为什么能想到下一步：既然约束是单向的、局部的，那就先只满足「从左往右看，评分递增处糖果也递增」这一半，再只满足「从右往左看」那一半，最后对每个位置取两次结果的较大值——因为取 max 不会破坏任何一侧已经满足的约束（后面第 4 节会严格说明）。

## 3. 从暴力到最优

**第一步：暴力松弛。** 初始 `c = [1,1,1,...]`。每轮从左到右扫，若 `ratings[i] > ratings[i-1]` 且 `c[i] <= c[i-1]`，则 `c[i] = c[i-1] + 1`；若 `ratings[i] > ratings[i+1]` 且 `c[i] <= c[i+1]`，则 `c[i] = c[i+1] + 1`。重复到无修改。瓶颈是轮数 O(n)。

**第二步：拆成两个方向。** 注意到「左邻约束」和「右邻约束」可以分别用一次扫描解决：

- 左扫：`left[0] = 1`；对 i 从 1 到 n-1，若 `ratings[i] > ratings[i-1]` 则 `left[i] = left[i-1] + 1`，否则 `left[i] = 1`。这一次扫描就彻底满足了所有「左边邻居评分更低」的约束，因为 `left[i]` 只依赖 `left[i-1]`，是纯递推。
- 右扫：对称地，`right[n-1] = 1`；对 i 从 n-2 到 0，若 `ratings[i] > ratings[i+1]` 则 `right[i] = right[i+1] + 1`，否则 `right[i] = 1`。

**第三步：合并。** 最终 `c[i] = max(left[i], right[i])`，答案求和。

**小例子走一遍**：`ratings = [1,0,2]`。

- 左扫：`left[0]=1`；`ratings[1]=0` 不大于 `ratings[0]=1`，故 `left[1]=1`；`ratings[2]=2 > ratings[1]=0`，故 `left[2]=left[1]+1=2`。得 `left = [1,1,2]`。
- 右扫：`right[2]=1`；`ratings[1]=0` 不大于 `ratings[2]=2`，故 `right[1]=1`；`ratings[0]=1 > ratings[1]=0`，故 `right[0]=right[1]+1=2`。得 `right = [2,1,1]`。
- 合并：`max` 逐位得 `[2,1,2]`，和 = 5。与示例一致。

再看 `ratings = [1,2,2]`：左扫 `[1,2,1]`（第三个 2 不大于第二个 2，重置为 1），右扫 `[1,1,1]`（第二个 2 不大于第三个 2，重置为 1），合并 `[1,2,1]`，和 = 4。注意这里「相等」的处理是重置为 1 而不是继承，这正是示例 2 想强调的点。

**瓶颈怎么被消掉的**：暴力法的 O(n) 轮，本质是在「传播」一个上升段的信息。而递推式 `left[i] = left[i-1] + 1` 让信息在一次扫描内就传到底，轮数从 O(n) 降到 1。总复杂度 O(n)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**定义**：设最终分配为 `c[i] = max(left[i], right[i])`。

**不变量 1（下界）**：对任意合法分配 `x`，必有 `x[i] >= left[i]` 且 `x[i] >= right[i]`。证明用归纳：`left[0] = 1 <= x[0]`（因为每个孩子至少 1 颗）。若 `ratings[i] > ratings[i-1]`，则约束要求 `x[i] > x[i-1] >= left[i-1]`，即 `x[i] >= left[i-1] + 1 = left[i]`；若 `ratings[i] <= ratings[i-1]`，则 `left[i] = 1 <= x[i]`。右扫同理。因此 `x[i] >= max(left[i], right[i]) = c[i]`，即 `c` 是逐点下界，**不会漏**（任何合法解都不比它小）。

**不变量 2（可行性）**：`c` 本身合法。检查相邻对 (i-1, i)。若 `ratings[i] > ratings[i-1]`，由左扫定义 `left[i] = left[i-1] + 1 > left[i-1]`，且 `right[i] >= 1`，于是 `c[i] = max(left[i], right[i]) >= left[i] > left[i-1]`，而 `c[i-1] = max(left[i-1], right[i-1])`，需要比较 `left[i]` 与 `right[i-1]`。这里的关键是：`ratings[i] > ratings[i-1]` 意味着右扫在位置 i-1 处不会因「右邻更高」而增长，即 `right[i-1] = 1`（除非 i-1 的右邻 i 评分更低，但这里 i 更高，所以确实重置为 1）。于是 `c[i] >= left[i] = left[i-1] + 1 >= c[i-1]` 中的 `c[i-1]` 至多为 `max(left[i-1], 1)`，而 `left[i] > left[i-1]` 且 `left[i] >= 2 > 1`，故 `c[i] > c[i-1]` 成立。对称地处理 `ratings[i] < ratings[i-1]`。相等时两边都重置为 1，`c[i] = c[i-1] = 1`，不违反「更高才更多」的约束（题面只要求严格更高者更多，相等无约束）。**不会重**（`c` 自身合法）。

由不变量 1 得 `sum(c) <= sum(x)` 对一切合法 `x` 成立，由不变量 2 得 `c` 合法，故 `c` 是唯一的最优解（逐点最小），`sum(c)` 即最少糖果数。

## 5. 完整代码（Python）

```python
class Solution:
    def candy(self, ratings):
        n = len(ratings)
        if n == 0:
            return 0

        # 左扫：只保证「评分比左邻高的人糖果比左邻多」
        left = [1] * n
        for i in range(1, n):
            if ratings[i] > ratings[i - 1]:
                left[i] = left[i - 1] + 1
            # 否则保持 1，因为左邻不比自己低，没有来自左边的下界

        # 右扫：只保证「评分比右邻高的人糖果比右邻多」
        right = [1] * n
        for i in range(n - 2, -1, -1):
            if ratings[i] > ratings[i + 1]:
                right[i] = right[i + 1] + 1
            # 否则保持 1

        # 合并：每个位置取两侧下界的较大值，既满足左约束也满足右约束
        total = 0
        for i in range(n):
            total += max(left[i], right[i])
        return total
```

空间可以优化到 O(1) 额外（除输出外）：先左扫把 `left` 存进结果数组，再右扫时用一个滚动变量 `right` 边算边合并，但为了教学清晰这里保留两个数组。

## 6. 复杂度

- 时间 O(n)：左扫一次遍历 n-1 个位置，右扫一次遍历 n-1 个位置，合并一次遍历 n 个位置，三次都是线性，常数因子为 3，故 O(n)。没有排序、没有二分，所以**没有 log n 项**。
- 空间 O(n)：`left` 和 `right` 各占 n 个整数，合并时不再额外分配。若做滚动优化可降到 O(1) 额外空间（不计返回值），但 Python 里整数对象本身的开销仍在。

## 7. 边界与反例（至少 4 条）

1. `ratings = [5]` → 期望 1 → 容易错在忘记 n=1 时循环不执行、直接返回 0（若初始化写错）。
2. `ratings = [1,2,2]` → 期望 4 → 容易错在把「相等」当成「递增」处理，导致第三个孩子拿 2 颗，答案变 5。题面只约束「更高者更多」，相等无约束，必须重置为 1。
3. `ratings = [3,2,1]` → 期望 6（分配 3,2,1）→ 容易错在只做左扫不做右扫，得到 `[1,1,1]` 和 3，漏掉了整条下降段。
4. `ratings = [1,3,2,2,1]` → 期望 7（分配 1,2,1,2,1？不对，检查：位置 3 的 2 与位置 2 的 2 相等无约束，位置 3 的 2 > 位置 4 的 1 需更多，位置 1 的 3 > 位置 2 的 2 需更多。合法最小为 `[1,2,1,2,1]`，和 7）→ 容易错在下降段与上升段在「谷底」交汇时没有取 max，导致谷底被两侧同时要求而冲突。
5. `ratings = [1,2,3,4,5]` → 期望 15 → 容易错在暴力法超时（n=5×10⁴ 时 O(n²) 不可行），或误以为答案是 n。

## 8. 面试追问与变体（3 条）

1. **追问：能否只用 O(1) 额外空间？** 思路：左扫结果直接写入结果数组，右扫时用滚动变量 `right` 从右往左算，每步 `total += max(res[i], right)`，同时更新 `right`，无需第二个数组。
2. **追问：如果要求「评分相同者糖果也必须相同」呢？** 思路：把相等视为强连通，先对相等段做并查集缩点，再在缩点后的 DAG 上做同样的双向扫描（或拓扑排序求最长路）。
3. **追问：如果约束改成「评分更高者糖果至少多 2 颗」？** 思路：把递推式里的 `+1` 改成 `+2`，其余结构不变，因为约束仍是单向局部的，双向扫描依然成立。

## 9. 举一反三（2-3 道同类题）

1. **接雨水（LeetCode 42）**：同样是「每个位置受左右两侧约束、取两侧较小值」，用左右两次扫描预处理前缀/后缀最值，和本题的双向扫描 + 取 max 是同一套骨架。
2. **最长递增子序列的 O(n log n) 解法（LeetCode 300）**：虽然用了二分，但核心也是「单向递推 + 维护每个位置的最优下界」，与本题 `left[i]` 的递推思想同源。
3. **摆动序列（LeetCode 376）**：统计相邻差值的符号变化，同样是「只看相邻关系、单向扫描即可确定全局最优」的贪心结构。
