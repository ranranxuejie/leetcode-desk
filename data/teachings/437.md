## 1. 一句话本质

在二叉树里数「所有向下连续路径」中，节点值之和恰好等于 `targetSum` 的条数——注意路径的起点和终点都任意，只要方向朝下。

## 2. 读完题的第一反应

**朴素解法**：枚举每一条路径。具体做法是，对每个节点作为起点，向下 DFS 收集所有以它为起点的路径和，看有多少等于 `targetSum`。这等价于「双重递归」：外层遍历每个节点当起点，内层从该起点往下走。

它卡在哪？内层 DFS 从每个节点出发都要往下走一遍，最坏情况（链状树）是 `n + (n-1) + ... + 1 = O(n²)`。节点数上限 1000，`n² = 10⁶`，其实能过，但面试官显然想看你把它降到 `O(n)`。

**关键观察**：路径和是「前缀和之差」。从根到某个节点 `cur` 的路径上，累计和记为 `prefix[cur]`。那么「以 `cur` 结尾、起点在它某个祖先 `a` 下方」的路径和 = `prefix[cur] - prefix[a]`。要让这个差等于 `targetSum`，等价于 `prefix[a] = prefix[cur] - targetSum`。

也就是说：**走到 `cur` 时，只要数一数「从根到 `cur` 的路径上，有多少个祖先的前缀和等于 `prefix[cur] - targetSum`」，就得到了以 `cur` 结尾的合法路径条数。** 这个「数一数」用哈希表存前缀和出现次数，`O(1)` 完成。

这个观察之所以自然，是因为「连续子段和」问题（比如数组里的「和为 K 的子数组」）用的就是同一招前缀和 + 哈希表。树只是把「数组」换成了「根到当前节点的路径」。

## 3. 从暴力到最优

**暴力**：对每个节点当起点，向下 DFS 累加，遇到和等于 `targetSum` 就计数。复杂度 `O(n²)`。

**瓶颈**：每个节点都被当作起点重复向下扫了很多遍，大量重复计算。

**优化思路**：换视角——不再「枚举起点」，而是「枚举终点」。走到节点 `cur` 时，一次性算出「所有以 `cur` 结尾的合法路径数」，靠前缀和哈希表 `O(1)` 得到。每个节点只访问一次，总 `O(n)`。

**小例子走一遍**：用示例 1，`root = [10,5,-3,3,2,null,11,3,-2,null,1]`，`targetSum = 8`。

维护 `prefix_count`（前缀和 → 出现次数），初始 `{0: 1}`（空前缀，代表「从根开始」这种情况），`cur_sum = 0`，`ans = 0`。

- 访问 10：`cur_sum = 10`。查 `cur_sum - targetSum = 2`，`prefix_count` 里没有 2 → 贡献 0。记录 `{0:1, 10:1}`。
- 访问 5：`cur_sum = 15`。查 `15 - 8 = 7`，没有 → 贡献 0。记录 `{0:1,10:1,15:1}`。
- 访问 3（5 的左孩子）：`cur_sum = 18`。查 `18 - 8 = 10`，有 1 个 → `ans = 1`（路径 5→3，和 8）。记录 `18:1`。
- 访问 3（3 的左孩子）：`cur_sum = 21`。查 `21 - 8 = 13`，没有。记录 `21:1`。
- 访问 -2（3 的右孩子）：`cur_sum = 19`。查 `19 - 8 = 11`，没有。记录 `19:1`。回溯，删掉 `21`、`19`。
- 回溯到 3，删掉 `18`。访问 2（5 的右孩子）：`cur_sum = 17`。查 `17 - 8 = 9`，没有。记录 `17:1`。回溯删掉。
- 回溯到 5，删掉 `15`。回溯到 10，删掉 `10`。访问 -3（10 的右孩子）：`cur_sum = 7`。查 `7 - 8 = -1`，没有。记录 `7:1`。
- 访问 11（-3 的右孩子）：`cur_sum = 18`。查 `18 - 8 = 10`，有 1 个 → `ans = 2`（路径 10→-3→11，和 8）。记录 `18:1`。回溯删掉。
- 回溯到 -3，删掉 `7`。回溯到 10，删掉 `-3` 对应的记录……

继续走完剩余节点，最终 `ans = 3`。三条路径分别是：`5→3`、`10→-3→11`、`5→3→...`（示例图中第三条，这里不逐一展开，机制已清楚）。

关键点：**回溯时必须把当前节点的前缀和从哈希表里删掉**，否则兄弟子树会误用不属于自己路径上的前缀和。

## 4. 正确性：为什么不会漏、不会重

**不变量**：进入节点 `cur` 的 DFS 时，`prefix_count` 恰好记录了「从根到 `cur` 的父节点这条路径上，每个前缀和出现的次数」（外加初始的 `{0:1}`）。

**为什么不会漏**：任何一条合法路径都有唯一的终点 `cur`（路径方向向下，终点是路径上最深的节点）。在访问 `cur` 时，它的起点 `a` 一定是 `cur` 的祖先（或就是根，对应前缀和 0）。由不变量，`prefix[a]` 已在表中，且 `prefix[cur] - prefix[a] = targetSum` 等价于 `prefix[a] = prefix[cur] - targetSum`，所以这条路径会被计入。

**为什么不会重**：每条路径由「起点 + 终点」唯一确定，而它只在访问终点 `cur` 时被计数一次（起点由前缀和的值唯一对应，哈希表里数的是「有多少个祖先前缀和等于目标值」，每个祖先对应一条不同的路径，互不重复）。不同终点的路径天然不同。

**回溯的正确性**：离开 `cur` 时删掉 `prefix[cur]`，保证进入兄弟子树时，表里只剩「根到兄弟的父节点」这条路径上的前缀和，不变量得以维持。

## 5. 完整代码（Python）

```python
class Solution:
    def pathSum(self, root, targetSum: int) -> int:
        # prefix_count: 从根到当前节点路径上，各前缀和出现的次数
        # 初始 {0: 1} 代表「空前缀」，用于统计从根节点开始的路径
        prefix_count = {0: 1}
        self.ans = 0

        def dfs(node, cur_sum):
            if node is None:
                return
            cur_sum += node.val  # 根到当前节点的前缀和

            # 以当前节点为终点，起点在祖先中的合法路径数
            # 需要 prefix[a] == cur_sum - targetSum
            self.ans += prefix_count.get(cur_sum - targetSum, 0)

            # 把当前前缀和加入表，供子孙使用
            prefix_count[cur_sum] = prefix_count.get(cur_sum, 0) + 1

            dfs(node.left, cur_sum)
            dfs(node.right, cur_sum)

            # 回溯：离开当前节点，撤销它的前缀和，避免污染兄弟子树
            prefix_count[cur_sum] -= 1
            if prefix_count[cur_sum] == 0:
                del prefix_count[cur_sum]

        dfs(root, 0)
        return self.ans
```

注意 `cur_sum` 是值传递（Python 整数不可变），回溯时不需要手动恢复 `cur_sum`，只需恢复哈希表。

## 6. 复杂度

**时间 `O(n)`**：每个节点被 DFS 访问一次，每次做常数次哈希表操作（`get`、赋值、删除均摊 `O(1)`）。`n` 是节点数，来自「每个节点恰好进一次、出一次」。

**空间 `O(n)`**：
- 哈希表最多存「根到当前节点路径」上的不同前缀和，最坏（链状树且前缀和互不相同）是 `O(n)`，这是 `n` 的来源。
- 递归栈深度等于树高 `h`，最坏链状树 `h = n`，最好平衡树 `h = log n`。所以空间严格写是 `O(n)`（取最坏），平衡树情形下是 `O(log n)`。

## 7. 边界与反例（至少 4 条）

1. **空树** `root = []`，`targetSum = 0` → 期望 `0`。容易错：初始 `{0:1}` 让人以为会返回 1，但 `dfs(None)` 直接返回，不会触发计数。要确认空树不进循环。

2. **单节点且值等于目标** `root = [5]`，`targetSum = 5` → 期望 `1`。容易错：忘记初始 `{0:1}`，导致「从根开始」的路径统计不到。

3. **节点值为 0** `root = [0,0,0]`，`targetSum = 0` → 期望 `3`（三条单节点路径都是 0；注意路径必须至少含一个节点）。容易错：回溯时用 `prefix_count[cur_sum] -= 1` 但没删键，残留的 0 计数会让后续误判；另外要理解「空路径不算路径」。

4. **负数值导致前缀和重复** `root = [1,-1,1]`，`targetSum = 0` → 期望 `2`（路径 `1→-1` 和 `-1→1`）。容易错：哈希表存的是「次数」不是「是否存在」，同一前缀和出现多次要累加，删的时候也要减到 0 才删键。

5. **目标为负** `root = [-3]`，`targetSum = -3` → 期望 `1`。容易错：以为目标必须为正，逻辑上 `cur_sum - targetSum` 照样成立，不需要特判。

## 8. 面试追问与变体（3 条）

1. **追问：如果路径要求「必须从根开始」呢？** 思路：退化成一维前缀和，只需在 DFS 时判断 `cur_sum == targetSum` 即可，不需要哈希表，`O(n)`。

2. **追问：如果路径要求「必须在叶子结束」呢？** 思路：仍用前缀和哈希表，但只在 `node.left is None and node.right is None` 时才累加 `prefix_count.get(cur_sum - targetSum, 0)`，其余逻辑不变。

3. **追问：如果树是普通图（有环）怎么办？** 思路：前缀和思路失效（路径不再唯一），需要换用「以每个节点为起点做带访问标记的 DFS」或转化为「树上路径计数」的经典问题，复杂度上升。

## 9. 举一反三（2-3 道同类题）

- **112. 路径总和**：只问「是否存在」一条从根到叶子的路径，是本题去掉「任意起点终点」和「计数」后的简化版。
- **124. 二叉树中的最大路径和**：同样在树上做「路径」相关的 DFS，但求的是最大值而非计数，且路径可以「拐弯」，需要后序返回单边最大贡献。
