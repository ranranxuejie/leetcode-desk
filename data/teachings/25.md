## 1. 一句话本质

把链表按 k 个节点切段，**每段内部指针反向**，段与段之间的连接关系保持原方向，最后不足 k 个的尾巴原样保留。

## 2. 读完题的第一反应

**朴素解法**：把链表转成数组，按 k 分组，每组用切片反转，再拼回链表。时间复杂度 O(n)，但空间 O(n)——题目进阶要求 O(1) 额外空间，数组方案直接出局。而且题面明确说"不能只改变节点内部的值"，所以连"存值再写回"这条路也堵死了，必须动指针。

**关键观察**：链表翻转的本质是"让每个节点的 next 指向它的前驱"。单看一个长度为 k 的段，翻转它和经典的「反转链表」完全一样——只是翻转完之后，原来的段头变成了段尾，要接上**下一段翻转后的新头**，原来的段尾变成了段头，要接上**上一段翻转后的新尾**。也就是说，每一段翻转时，需要同时记住三个外部接口：上一段的尾、本段的头（翻转后变尾）、下一段的头。

这个观察直接给出迭代框架：**维护一个"上一段翻转后的尾节点"作为锚点，每次取 k 个节点翻转，把锚点接到新段头，新段尾成为下一个锚点**。难点只剩一个：翻转前必须先确认"后面还有没有 k 个节点"，否则会把不足 k 个的尾巴也翻了，违反题意。

## 3. 从暴力到最优

**暴力（数组法）**：遍历存值 → 分组反转 → 写回。时间 O(n)，空间 O(n)。瓶颈在空间：n 最大 5000，虽然能过，但进阶要求 O(1)。

**迭代法（最优）**：核心是把"翻转一段"抽象成一个子过程，然后循环调用。用示例 1 走一遍：`head = [1,2,3,4,5], k = 2`。

先引入哑节点 `dummy -> 1`，令 `prev = dummy`（prev 始终是"上一段翻转后的尾"）。

**第 1 轮**：从 `prev.next = 1` 出发数 k=2 个节点，得到段 `[1,2]`，段后是 `3`。
- 记 `start = 1`（段头，翻转后变段尾），`nxt = 3`（段后第一个节点）。
- 翻转 `[1,2]`：`2 -> 1`，翻转后新头是 `2`，新尾是 `1`。
- 接线：`prev.next = 2`（dummy 指向新头），`start.next = nxt`（即 `1 -> 3`）。
- 此时链表：`dummy -> 2 -> 1 -> 3 -> 4 -> 5`。
- 更新 `prev = start = 1`（本段翻转后的尾，作为下一轮的锚点）。

**第 2 轮**：从 `prev.next = 3` 数 2 个，得 `[3,4]`，段后是 `5`。
- `start = 3`，`nxt = 5`，翻转得 `4 -> 3`。
- 接线：`prev.next = 4`（即 `1 -> 4`），`start.next = 5`（即 `3 -> 5`）。
- 链表：`dummy -> 2 -> 1 -> 4 -> 3 -> 5`。`prev = 3`。

**第 3 轮**：从 `prev.next = 5` 数，只能数到 1 个，不足 k=2，**直接退出循环**，尾巴 `5` 保持原样。

返回 `dummy.next = 2`，结果 `[2,1,4,3,5]`，与示例一致。

瓶颈消解过程：数组法的 O(n) 空间被"原地改指针"消掉；而"先数 k 个再翻"这个前置检查，保证了不足 k 的尾巴不会被误翻——这是本题最容易漏的一步。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**论证。设循环开始时满足：

> **不变量**：`prev` 指向的节点及其之前的所有节点，已经完成了分组翻转且连接正确；`prev.next` 是尚未处理部分的第一个节点。

三条性质：

1. **不会漏**：每轮从 `prev.next` 开始数 k 个节点，这 k 个恰好是"尚未处理部分"的前 k 个（由不变量保证起点正确），翻转后全部处理完毕，`prev` 前移到本段新尾，不变量对下一轮继续成立。
2. **不会重**：翻转只改段内 k 个节点的 next 指针，段内每个节点恰好被访问一次；`prev` 单调向后移动，已处理的段不会再被数到。
3. **终止正确**：循环退出条件是"剩余节点不足 k 个"。此时 `prev.next` 指向剩余尾巴的第一个节点，而尾巴从未被改动过指针（因为每轮都是先数够 k 个才翻），所以保持原顺序，符合题意。

**边界接线正确性**：翻转段时，`start.next = nxt` 把段尾接到段后，`prev.next = 新头` 把上一段尾接到段头。这两个赋值覆盖了段与外界的所有连接，段内指针由翻转过程负责，三者合起来保证整条链表连通且无环。

## 5. 完整代码（Python）

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def reverseKGroup(self, head: ListNode, k: int) -> ListNode:
        # 哑节点：让"第一段"和"后续段"的接线逻辑统一，省掉对 head 的特判
        dummy = ListNode(0, head)
        prev = dummy  # prev 始终是上一段翻转后的尾节点

        while True:
            # 第一步：从 prev.next 出发，检查后面是否还有 k 个节点
            # 这一步是"不足 k 个不翻"的唯一保障，不能省
            node = prev
            for _ in range(k):
                node = node.next
                if node is None:
                    return dummy.next  # 不足 k 个，剩余部分原样保留，直接返回
            # 循环结束时 node 是第 k 个节点，即本段最后一个

            start = prev.next   # 本段原头，翻转后变段尾
            nxt = node.next     # 段后第一个节点，翻转后要接到段尾上

            # 第二步：翻转 [start, node] 这 k 个节点（标准反转链表，限定 k 步）
            cur, pre = start, None
            for _ in range(k):
                tmp = cur.next
                cur.next = pre
                pre = cur
                cur = tmp
            # 翻转后 pre 是新头，start 是新尾

            # 第三步：接线。顺序不能反：
            # 先让 prev 指向新头，再让新尾指向段后
            prev.next = pre
            start.next = nxt

            # 第四步：prev 前移到本段新尾，进入下一轮
            prev = start

        return dummy.next
```

关键点：`prev.next = pre` 必须在 `start.next = nxt` 之前或之后都行（两者不冲突），但**不能**在翻转前就改 `start.next`，否则会切断翻转所需的链。代码里翻转完再接线，安全。

## 6. 复杂度

- **时间 O(n)**：外层 while 每轮处理 k 个节点，共约 n/k 轮；每轮内"数 k 个"和"翻 k 个"各 O(k)，合计每轮 O(k)，总 O(n)。注意"数"和"翻"是两遍扫描，常数因子为 2，但仍是 O(n)。n 来自节点总数，k 被 n/k 轮摊掉。
- **空间 O(1)**：只用了 `dummy, prev, node, start, nxt, cur, pre, tmp` 常数个指针变量，没有递归栈、没有数组。这正是进阶要求。若用递归写法，空间会变成 O(n/k) 的栈深度——这是本题"递归标签"的陷阱，迭代版才满足 O(1)。

## 7. 边界与反例（至少 4 条）

1. **k = 1** → 输入 `[1,2,3], k=1` → 期望 `[1,2,3]`。容易错：翻转单节点段时若逻辑写错（比如把 `start.next` 置空），会断链。本代码每段翻 1 个节点，`pre=start, start.next=nxt`，等价于不动，正确。
2. **n 恰好是 k 的整数倍** → 输入 `[1,2,3,4], k=2` → 期望 `[2,1,4,3]`。容易错：最后一轮数 k 个时 `node` 恰好走到最后一个节点而非 None，循环正常结束，不会误判为"不足"。若把检查写成 `node.next is None` 就错了。
3. **n < k 不成立但尾巴不足** → 输入 `[1,2,3,4,5], k=3` → 期望 `[3,2,1,4,5]`。容易错：第二轮从 `4` 数 3 个只能数到 2 个，必须原样保留 `4,5`。若先翻后查，会把 `4,5` 翻成 `5,4`。
4. **单节点** → 输入 `[1], k=1` → 期望 `[1]`。容易错：`dummy.next` 返回逻辑、`prev` 更新逻辑都要能处理"只有一段"的情况。
5. **k 等于 n** → 输入 `[1,2,3], k=3` → 期望 `[3,2,1]`。容易错：整条链翻完后 `start.next = nxt` 中 `nxt` 是 None，必须允许赋 None，不能对 `nxt` 做解引用。

## 8. 面试追问与变体（3 条）

1. **追问：改成"从尾部开始每 k 个一组翻转"？** 思路：先求长度，定位到第一个需要翻转的段起点（长度对 k 取模后的位置），再套同样的迭代框架，只是起点不是 head。
2. **追问：不足 k 个的尾巴也要翻转？** 思路：把"数 k 个"的检查改成"数到 None 为止"，记录实际个数 m，翻转这 m 个即可，其余逻辑不变。
3. **追问：用递归怎么写，空间多少？** 思路：先数 k 个确认够，递归处理 `nxt` 之后的链表得到新头，再翻转当前 k 个并接到递归结果上；空间 O(n/k) 栈深度，不满足 O(1)。
