## 1. 一句话本质

在字符网格上做「带剪枝的路径枚举」，用一棵所有待查单词共享的前缀树，把「对每个单词单独搜一遍」变成「一次搜索同时匹配所有单词」。

## 2. 读完题的第一反应

**朴素解法**：对 `words` 里每个单词，从网格每个格子出发做 DFS，逐字符匹配。单词数最多 3×10⁴，每个单词长最多 10，网格最多 12×12=144 格，每格 DFS 分支最多 4，深度 10，单次搜索上界约 144×4⁹ ≈ 3.8×10⁷，乘上 3×10⁴ 个单词——直接爆炸。瓶颈在于：**大量单词共享前缀，却被反复从网格根节点重新搜**。比如 `words` 里有 `oath`、`oat`、`oak`，前两个字符 `oa` 的路径被走了三遍。

**关键观察**：题面给的上限很能说明问题——`words[i].length <= 10`，而 `words.length` 高达 3×10⁴。单词**短而多**，这正是前缀树（Trie）的典型适用场景：把所有单词插进一棵树，树的总节点数不超过 3×10⁴×10 = 3×10⁵，而搜索时**从网格出发只走一遍**，每走一步就沿着 Trie 往下走一层，走到某个节点发现「没有单词以当前路径为前缀」就立刻回头。这样网格上的每条路径只被枚举一次，而不是每个单词枚举一次。

换句话说：把「以单词为外层循环」翻转成「以网格路径为外层循环」，Trie 负责在路径增长时同步判断「这条路还有没有前途」。

## 3. 从暴力到最优

**第一步：暴力 DFS 单单词。** 对 `oath`，从 (0,0) 的 `o` 出发，找相邻的 `a`……能搜到，但每个单词都要重来。复杂度 O(W · m·n · 4^L)，W=3×10⁴ 时不可接受。

**第二步：引入 Trie。** 把 `["oath","pea","eat","rain"]` 插入后结构大致是：

```
root
├─ o → a → t → h(词尾)
├─ p → e → a(词尾)
├─ e → a → t(词尾)
└─ r → a → i → n(词尾)
```

现在从网格每个格子出发 DFS，维护一个「当前在 Trie 的哪个节点」的指针。走到 (0,0) 字符 `o`，查 root 的孩子里有 `o`，指针下移；下一步走到 (0,1) 的 `a`，查当前节点孩子里有 `a`，继续；再走到 (1,1) 的 `t`，有；再走到 (2,1) 的 `h`，有且是词尾，收集 `oath`。**如果某一步字符不在当前节点的孩子里，立刻 return**——这就是剪枝，暴力解法里做不到这么早停，因为它不知道「前缀已经不可能了」。

**第三步：处理重复收集。** 网格里可能有多条路径拼出同一个单词（比如 `a` 出现多次）。用一个 `set` 收集结果，最后转 list 即可。另外，收集到某单词后可以把它从 Trie 里「删掉」（把词尾标记清空），避免后续重复匹配同一单词——这是常见优化，但用 set 已经能保证正确性。

**小例子走一遍**：`board = [["a","b"],["c","d"]]`，`words = ["abcb"]`。Trie 是 `a→b→c→b`。从 (0,0) `a` 出发 → (0,1) `b` → 相邻只有 (0,0) 已访问、(1,1) `d`，`d` 不在 `c` 的孩子里，剪枝；换方向也不行。最终无路径，返回 `[]`。注意这里「同一格子不能重复使用」靠 `visited` 集合保证，否则 `a→b→a→b` 会误判。

## 4. 正确性：为什么不会漏、不会重

**不漏**：设单词 `w` 在网格上存在一条合法路径。DFS 从该路径起点格子出发，每一步的字符都必然在 Trie 对应节点的孩子中（因为 `w` 被插入过，路径上每个前缀都是 Trie 中的一条链），所以剪枝条件不会误杀这条路径；DFS 会枚举所有四邻方向，必然走到路径终点，此时 Trie 节点带词尾标记，`w` 被收集。归纳到「任意合法单词都会被某条 DFS 路径命中」。

**不重**：结果用 `set` 存储，同一字符串多次命中只保留一份。若进一步在命中后清除 Trie 词尾标记，则同一单词在 Trie 中只可能被报告一次，双重保险。

**不误报**：只有 Trie 节点带词尾标记才收集，而词尾标记只在插入完整单词时设置，所以收集到的字符串一定在 `words` 中。

**不变量**：DFS 进入某格子时，`node` 指针始终表示「从起点到当前格子这条路径构成的字符串在 Trie 中的节点」，且 `visited` 恰好是当前路径上的格子集合。这个不变量在递归进入/回溯时分别维护，保证路径合法且不重复用格。

## 5. 完整代码（Python）

```python
class Solution:
    def findWords(self, board: list[list[str]], words: list[str]) -> list[str]:
        # 1. 建 Trie：用 dict 嵌套表示，'#' 作为词尾标记
        trie = {}
        for w in words:
            node = trie
            for ch in w:
                node = node.setdefault(ch, {})
            node['#'] = w          # 词尾存完整单词，便于直接收集

        m, n = len(board), len(board[0])
        res = set()
        visited = set()            # 当前 DFS 路径上已用的格子

        def dfs(i: int, j: int, node: dict):
            ch = board[i][j]
            if ch not in node:     # 剪枝：当前前缀在 Trie 中不存在
                return
            nxt = node[ch]
            if '#' in nxt:         # 命中一个完整单词
                res.add(nxt['#'])
                # 可选优化：del nxt['#']，避免同一单词被反复报告
            visited.add((i, j))
            for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                ni, nj = i + di, j + dj
                if 0 <= ni < m and 0 <= nj < n and (ni, nj) not in visited:
                    dfs(ni, nj, nxt)
            visited.remove((i, j))  # 回溯：恢复现场

        for i in range(m):
            for j in range(n):
                dfs(i, j, trie)
        return list(res)
```

关键逻辑说明：`node.setdefault(ch, {})` 让插入和查找共用同一套 dict 结构；`'#'` 键与字母键不冲突，因为题面保证只有小写字母；`visited` 用集合而非布尔矩阵，回溯时 `remove` 即可，语义清晰。

## 6. 复杂度

设网格 m×n，单词总字符数 S = Σ|words[i]| ≤ 3×10⁵，最长单词长 L ≤ 10。

- **建 Trie**：O(S)，每个字符一次插入。
- **搜索**：从每个格子出发 DFS，深度不超过 L（超过 L 的路径在 Trie 中必然断掉，因为 Trie 最深 L 层）。每个格子作为起点，分支因子 ≤ 4，深度 ≤ L，单起点上界 O(4^L)，总上界 O(m·n·4^L)。注意这里的 L 是**最长单词长度**而非网格尺寸，这是 Trie 剪枝带来的核心收益——暴力是 O(W·m·n·4^L)，这里去掉了 W 因子。
- **空间**：Trie 占 O(S)；递归栈深 ≤ L；`visited` ≤ L；结果集 ≤ W。合计 O(S + L + W)，主导项是 O(S)。

## 7. 边界与反例（至少 4 条）

1. **单词比网格路径还长**：`board=[["a"]], words=["aa"]` → 期望 `[]`。容易错在忘记「同一格子不能重复用」，误以为能原地踏步拼出 `aa`。
2. **单词是单字符且网格中不存在**：`board=[["a"]], words=["b"]` → 期望 `[]`。容易错在 Trie 根节点直接查 `b` 不存在时没 return，或误把根当命中。
3. **同一单词有多条路径**：`board=[["a","a"],["a","a"]], words=["aa"]` → 期望 `["aa"]`（只出现一次）。容易错在不用 set，输出重复。
4. **单词是另一个单词的前缀**：`board=[["o","a"],["t","h"]], words=["oa","oath"]` → 期望 `["oa","oath"]`（若路径存在）。容易错在命中 `oa` 后直接 return，漏掉继续往下匹配 `oath`——所以命中后**不能停**，要继续 DFS。
5. **网格 1×1 且单词就是该字符**：`board=[["a"]], words=["a"]` → 期望 `["a"]`。容易错在循环边界或 visited 初始化。

## 8. 面试追问与变体（3 条）

1. **追问：如果 words 里有 10⁵ 个单词、每个长 100，怎么优化？** 思路：Trie 依然适用，但要注意递归深度和 Python 递归上限；可改迭代 DFS，或在命中后 `del` 词尾并剪掉空子树，减少无效遍历。
2. **追问：如果要求返回每个单词在网格中的所有出现位置？** 思路：命中后不清词尾标记，把 `(i,j)` 起点或路径记下来，结果结构从 set 改为 dict[str, list]。
3. **追问：如果允许斜对角相邻？** 思路：把方向数组从 4 个扩到 8 个，其余逻辑不变——这题的核心（Trie 剪枝 + 回溯）与邻接定义解耦。
