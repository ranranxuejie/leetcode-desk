## 1. 一句话本质

把已经排好序的数组切成若干段「连续整数块」，每块用 `a->b` 或 `a` 的形式输出。

## 2. 读完题的第一反应

**朴素解法**：对每个数字，往后看它能不能和后面的数连上，能连就继续扩，断了就收一段。这其实就是正确解法，复杂度 O(n)。很多人第一反应会想复杂——比如先建一个 set 判断 `x+1` 在不在，再逐个数字扫。但题面已经给了「有序」和「无重复」两个条件，这两个条件合起来意味着：**连续的数字在数组里一定挨着**。所以根本不需要 set，也不需要排序，从左到右扫一遍即可。

**关键观察**：数组有序且无重复，那么「一段连续区间」在数组中就是一段**下标连续的子数组**。判断两个相邻元素是否属于同一段，只需要看 `nums[i] - nums[i-1] == 1` 是否成立。这个观察直接消掉了「查找 x+1 在哪」这一步，把问题变成一次线性扫描。

如果没注意到「有序」这个条件，可能会去排序（O(n log n)）或者用哈希表（O(n) 空间），都是多余的。

## 3. 从暴力到最优

**暴力思路**：对每个位置 i，从 i 开始往后找最长的连续段。最坏情况（整个数组连续）下，每个 i 都要扫到末尾，O(n²)。

**瓶颈在哪**：重复扫描。当 i=0 扫到 i=5 发现断了，i=1 又从头扫一遍——但 i=1 到 i=5 这段信息在第一次扫描时已经知道了。

**消除瓶颈**：维护一个「当前段的起点 start」。从左到右扫，一旦发现 `nums[i] != nums[i-1] + 1`，说明上一段在 i-1 处结束，把 `[start, i-1]` 收掉，然后令 `start = i`。每个元素只被看一次。

**小例子走一遍**：`nums = [0,2,3,4,6,8,9]`

| i | nums[i] | 与前一元素差 | 动作 | start | 结果列表 |
|---|---------|------------|------|-------|---------|
| 0 | 0 | — | 初始化 start=0 | 0 | [] |
| 1 | 2 | 2 | 收 [0,0]→"0"，start=1 | 1 | ["0"] |
| 2 | 3 | 1 | 继续 | 1 | ["0"] |
| 3 | 4 | 1 | 继续 | 1 | ["0"] |
| 4 | 6 | 2 | 收 [1,3]→"2->4"，start=4 | 4 | ["0","2->4"] |
| 5 | 8 | 2 | 收 [4,4]→"6"，start=5 | 5 | ["0","2->4","6"] |
| 6 | 9 | 1 | 继续 | 5 | ["0","2->4","6"] |
| 结束 | — | — | 收 [5,6]→"8->9" | — | ["0","2->4","6","8->9"] |

注意最后一段是在循环结束后补收的——这是最容易漏的一步。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义循环不变量：

> 在第 i 次迭代开始时，`start` 是当前尚未收尾的那一段的起始下标，且 `nums[start..i-1]` 恰好构成一段连续整数，`result` 中已收录的区间恰好覆盖 `nums[0..start-1]` 且互不重叠。

**初始化**：i=0 时，`start=0`，`nums[0..-1]` 为空段，`result` 为空，覆盖 `nums[0..-1]`，成立。

**保持**：第 i 次迭代检查 `nums[i] - nums[i-1]`。若等于 1，`nums[start..i]` 仍连续，不变量保持；若大于 1（不可能小于 1，因为数组升序无重复），则 `nums[start..i-1]` 已是极大连续段——因为 `nums[i]` 接不上，而 `nums[start-1]` 在上一轮已被判定接不上 `nums[start]`——所以收掉它不会漏掉任何元素，也不会和已收的段重叠，然后 `start=i`，不变量恢复。

**终止**：循环结束时 `nums[start..n-1]` 是最后一段极大连续段，补收后 `result` 覆盖整个数组。

**不会漏**：每段都是「极大」的，段与段之间必有断点，断点两侧的数字都被分到了相邻两段中。**不会重**：每段收尾时 `start` 立即跳到断点后一位，下一段从新 `start` 开始，下标区间 `[start, i-1]` 互不相交。

## 5. 完整代码（Python）

```python
class Solution:
    def summaryRanges(self, nums: list[int]) -> list[str]:
        result = []
        n = len(nums)
        if n == 0:
            return result

        start = 0  # 当前连续段的起始下标
        for i in range(1, n):
            # 相邻元素差为 1 说明还在同一段，继续
            if nums[i] - nums[i - 1] == 1:
                continue
            # 差不为 1，说明上一段在 i-1 处结束，收掉 [start, i-1]
            result.append(self._format(nums[start], nums[i - 1]))
            start = i  # 新段从 i 开始

        # 循环结束后，最后一段 [start, n-1] 还没收
        result.append(self._format(nums[start], nums[n - 1]))
        return result

    def _format(self, a: int, b: int) -> str:
        # 单元素输出 "a"，多元素输出 "a->b"
        if a == b:
            return str(a)
        return f"{a}->{b}"
```

关键点：`_format` 把「单点还是区间」的判断抽出来，主循环只负责切段，职责清晰。空数组要单独返回，否则 `nums[n-1]` 会越界。

## 6. 复杂度

- **时间 O(n)**：主循环 `for i in range(1, n)` 执行 n-1 次，每次 O(1) 比较；`_format` 每次 O(1)（数字转字符串的位数是常数级，因为值域在 32 位整数内）。总共 O(n)。没有排序、没有查找，n 来自数组长度。
- **空间 O(1) 额外空间**（不计输出）：只用了 `start`、`i` 两个变量。输出列表本身最多 n 个字符串，属于必须返回的结果，通常不计入额外空间；若计入则 O(n)。这里没有 log n 项，因为没有任何分治或排序。

## 7. 边界与反例（至少 4 条）

1. **输入 `[]`** → 期望 `[]` → 容易错在没判空，直接访问 `nums[0]` 或 `nums[n-1]` 越界。
2. **输入 `[5]`** → 期望 `["5"]` → 容易错在循环 `range(1,1)` 不执行，忘了循环后补收最后一段，返回空列表。
3. **输入 `[1,2,3,4,5]`** → 期望 `["1->5"]` → 容易错在循环内每次都收段（把 `if` 写成无条件收），导致输出五段。
4. **输入 `[-2147483648, -2147483647, 2147483647]`** → 期望 `["-2147483648->-2147483647","2147483647"]` → 容易错在负数格式化或边界值处理；本题用差值判断，不涉及加减溢出，但若改成 `nums[i] == nums[i-1]+1` 在极端值上仍安全（Python 无溢出），换 C++ 需注意。
5. **输入 `[0,2]`** → 期望 `["0","2"]` → 容易错在把「差为 2」误判为连续（写成 `<= 1` 或 `!= 0`）。

## 8. 面试追问与变体（3 条）

1. **追问：如果数组没排序怎么办？** 思路：先排序 O(n log n) 再套本题逻辑；若要求保持原顺序输出，则需先记录原下标或用哈希表找连续段，复杂度上升。
2. **追问：如果允许重复元素呢？** 思路：排序后跳过相邻相等元素（`nums[i] == nums[i-1]` 时 `continue`），断点判断改为 `nums[i] - nums[i-1] > 1`。
3. **追问：要求返回区间个数最少的覆盖，但区间可以跨过数组里不存在的数？** 思路：那就退化成「整个数组一个区间 `[min, max]`」，因为题面「不存在属于区间但不属于 nums 的数」这个约束被去掉了，答案恒为一段。

## 9. 举一反三（2-3 道同类题）

- **LeetCode 163 缺失的区间**：同样是在有序数组上找「连续段」，只是求的是补集（数组没覆盖到的区间），切段逻辑完全对称。
- **LeetCode 128 最长连续序列**：无序数组找最长连续段，共同点是「判断 x 和 x+1 是否同段」，但那题需要哈希集去重并做 O(n) 扩展。
- **LeetCode 56 合并区间**：都是把「有重叠/相邻关系」的区间合并成极大段，核心都是「排序后一次扫描，维护当前段边界」。
