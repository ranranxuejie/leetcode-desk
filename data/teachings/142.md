## 1. 一句话本质

在一条可能带环的单链表中，找到**环的入口节点**——即从链表头顺着 next 走，第一次"走进环里"的那个节点。

注意题目要的不是"有没有环"，而是"环从哪个节点开始"。这是它比 141 题（环形链表 I）难的地方。

---

## 2. 读完题的第一反应

**朴素解法**：用一个哈希集合 `visited`，从头遍历，每到一个节点就检查它是否在集合里。第一次遇到"已经在集合里"的节点，就是环的入口。

这个解法完全正确，但卡在**空间**上：最坏情况要把 n 个节点全存进去，空间 O(n)。题目进阶明确要求 O(1) 空间，所以哈希法只能算"能过但不是最优"。

**关键观察**：如果只用一个慢指针（每次走 1 步）和一个快指针（每次走 2 步），它们在有环时一定会相遇——这是 141 题已经证明的。但相遇点**不一定是入口**。真正让这道题有解的是一个几何事实：

> 设头到入口的距离为 `a`，入口到相遇点的距离为 `b`，相遇点绕回入口的距离为 `c`（环长 = b + c）。快慢指针相遇时，有 **a = c**（模环长意义下）。

这个等式一出来，下一步就自然了：相遇后，让一个指针回到 head，两个指针都改成每次走 1 步，它们再次相遇的地方就是入口。因为从 head 走 `a` 步到入口，从相遇点走 `c` 步也到入口，而 `a = c`。

---

## 3. 从暴力到最优

**第一步：哈希法（能过，但 O(n) 空间）**

遍历时把节点对象存进 `set`。第一个重复出现的节点就是入口。

小例子：`head = [3,2,0,-4]`，`pos = 1`（尾节点 -4 指回索引 1 的节点 2）。

```
访问 3  → set={3}
访问 2  → set={3,2}
访问 0  → set={3,2,0}
访问 -4 → set={3,2,0,-4}
next 回到 2 → 2 已在 set 中 → 返回节点 2 ✓
```

瓶颈：set 里最多存 n 个节点，空间 O(n)。

**第二步：快慢指针判环（消掉空间，但只得到"相遇点"）**

slow 走 1 步，fast 走 2 步。有环必相遇，无环 fast 会先撞到 null。

同一个例子：

```
初始: slow=3, fast=3
第1轮: slow=2, fast=0
第2轮: slow=0, fast=2   (fast: 0→-4→2)
第3轮: slow=-4, fast=-4  → 相遇于 -4
```

相遇点是 -4，但入口是 2。**相遇点 ≠ 入口**，这就是 141 题的方法不够用的原因。

**第三步：利用 a = c 找入口（消掉"相遇点不是入口"的瓶颈）**

相遇后，把 slow 拨回 head，fast 留在相遇点，两者都每次走 1 步：

```
slow 从 head=3 出发，fast 从 -4 出发
第1轮: slow=2, fast=2  → 相遇于 2 ✓ 正是入口
```

为什么？头到入口是 `a` 步（3→2 是 1 步），相遇点到入口是 `c` 步（-4→2 是 1 步），`a = c`，所以同步走会在入口撞上。

**这个 a = c 是怎么来的**（这是全题的核心推导，必须能自己讲出来）：

设头到入口距离 `a`，入口到相遇点距离 `b`，环长 `L = b + c`（c 是相遇点回到入口的距离）。

- 相遇时 slow 走了 `a + b` 步。
- fast 走了 `a + b + kL` 步（k 是 fast 多绕的整圈数，k ≥ 1）。
- fast 速度是 slow 的 2 倍：`2(a + b) = a + b + kL`，化简得 `a + b = kL`，即 `a = kL - b = (k-1)L + c`。

所以 `a ≡ c (mod L)`。从 head 走 `a` 步、从相遇点走 `c` 步，都会落在入口（相差整数圈）。这就是第三步成立的依据。

---

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证，分两段。

**第一段（判环阶段）的不变量**：若存在环，slow 和 fast 必在环内相遇。

理由：一旦两者都进入环，fast 相对 slow 每轮净追 1 步（速度差 2−1=1），而环是有限的，所以 fast 一定会在有限轮内"追上"slow。无环时 fast 会先到达 null，循环自然终止。这保证了"有环必相遇、无环必退出"，不会漏判。

**第二段（找入口阶段）的不变量**：设相遇点为 M，入口为 E。由第 3 节推导 `a ≡ c (mod L)`。把 slow 放回 head、fast 留在 M，两者同速前进：

- slow 走 `a` 步到达 E；
- fast 从 M 走 `c` 步也到达 E（可能多绕了整数圈，但落点仍是 E）。

两者步数相同、速度相同，所以**同时**到达 E，第一次相遇点就是 E。这保证找到的是入口，不会停在环内其他节点。

**不会重**：入口是唯一的（一个节点只有一个 next，环的"第一个"节点由结构唯一确定），所以返回值唯一，不存在歧义。

## 5. 完整代码（Python）

```python
class ListNode:
    def __init__(self, x):
        self.val = x
        self.next = None


class Solution:
    def detectCycle(self, head, pos=None):
        # pos 仅用于评测系统构造链表，算法本身不依赖它
        if head is None or head.next is None:
            return None

        slow = fast = head

        # 第一阶段：快慢指针判环，找到相遇点
        while fast is not None and fast.next is not None:
            slow = slow.next          # 慢指针每次 1 步
            fast = fast.next.next     # 快指针每次 2 步
            if slow is fast:          # 相遇，说明有环
                break
        else:
            # while 正常结束（fast 撞到 null），说明无环
            return None

        # 防御：如果循环因 fast 为 None 退出但没 break，也返回 None
        if fast is None or fast.next is None:
            return None

        # 第二阶段：一个指针回 head，两者同速前进，相遇点即入口
        slow = head
        while slow is not fast:
            slow = slow.next
            fast = fast.next
        return slow
```

> 说明：题面给的签名是 `detectCycle(head, pos)`，但 `pos` 在真实评测中**不作为参数传入**（题面原文："pos 不作为参数进行传递"）。这里保留 `pos=None` 只为对齐签名，算法逻辑完全不使用它。若你的评测环境确实不传 `pos`，把签名改成 `detectCycle(self, head)` 即可，其余不变。

## 6. 复杂度

**时间 O(n)**：n 是节点数。第一阶段 slow 最多走 n 步（进入环后最多再绕一圈就相遇），fast 走的步数是 slow 的 2 倍，仍是 O(n)。第二阶段两个指针各走不超过 n 步。两段相加仍是 O(n)。这里没有 log 项，因为没有任何"折半"操作。

**空间 O(1)**：只用了 `slow`、`fast` 两个指针变量，与 n 无关。这正是相对哈希法（O(n) 空间）的改进点。

## 7. 边界与反例（至少 4 条）

1. **空链表** `head = None` → 返回 `None` → 容易错在没判空就直接 `head.next`，抛 `AttributeError`。

2. **单节点无环** `head = [1], pos = -1` → 返回 `None` → 容易错在 `head.next is None` 时仍进循环，`fast.next.next` 越界。

3. **单节点自环** `head = [1], pos = 0`（1 指向自己）→ 返回节点 1 → 容易错在提前用 `head.next is None` 直接返回 None，把自环误判成无环。正确做法是让循环去处理：slow 走 1 步、fast 走 2 步（fast 绕回自己），会相遇。

4. **入口就是头节点** `head = [1,2], pos = 0` → 返回节点 1 → 容易错在第二阶段把 slow 放回 head 后，若 fast 恰好也在 head（a=0 的情形），循环 `while slow is not fast` 一次都不执行，直接返回 head，这是对的；但如果写成 `do-while` 或先移动再判断，就会多走一步返回错误节点。

5. **环在链表尾部、入口较深** `head = [1,2,3,4,5], pos = 2` → 返回节点 3 → 容易错在只验证了"相遇点"就返回，忘了第二阶段；相遇点可能是 4 或 5，不是入口。

## 8. 面试追问与变体（3 条）

1. **追问：如何求环的长度？**
   思路：在第一阶段相遇后，让一个指针从相遇点出发绕一圈回到相遇点，走过的步数就是环长 L。

2. **追问：不用快慢指针，怎么在 O(1) 空间判环？**
   思路：Floyd 判圈本质是"龟兔赛跑"；另一种是 Brent 算法（记录 2 的幂次步长的"哨兵"），同样 O(1) 空间、常数更小，但实现更绕，面试一般答 Floyd 即可。

3. **追问：如果链表可能有多个环（实际不可能，但被问"如何检测结构异常"）？**
   思路：单链表每个节点只有一个 next，结构上不可能有多个环；可指出这一点，并说明"多环"只可能出现在图结构里，那时要用拓扑排序或 DFS 染色。

## 9. 举一反三（2-3 道同类题）

1. **141. 环形链表**：只判有没有环，是本题的第一阶段，共同点是快慢指针相遇判定。

2. **287. 寻找重复数**：把数组下标当 next 指针，本质是"带环链表找入口"，同一套 Floyd 算法，共同点是 `a = c` 的几何推导。

3. **202. 快乐数**：把"平方和变换"当 next，判是否会进入循环，共同点是用快慢指针检测隐式链表中的环。
