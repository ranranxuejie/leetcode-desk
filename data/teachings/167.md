## 1. 一句话本质

在一个**已经排好序**的数组里，找到唯一一对下标 `i < j` 使 `numbers[i] + numbers[j] == target`，并且只能用 O(1) 额外空间。

关键词是「已排序」和「O(1) 空间」——前者是解题的钥匙，后者是堵死哈希表那条路的墙。

## 2. 读完题的第一反应

**朴素解法**：两层循环枚举所有 `(i, j)` 组合，检查和是否等于 target。时间复杂度 O(n²)，n 最大 3×10⁴，最坏约 9×10⁸ 次比较，Python 里必然超时。瓶颈在于：对每个 `i`，我们都在**盲目地**试所有 `j`。

**第一层优化**：对每个 `i`，我要找的是 `target - numbers[i]`。数组有序，那能不能二分查找？可以，O(n log n)。但题目要求 O(1) 额外空间——二分本身是 O(1) 空间，所以这个方案**合法**，只是不是最优。

**关键观察**：题目同时给了两个条件——「有序」和「O(1) 空间」。有序意味着**大小关系是有信息的**；O(1) 空间意味着**不能开哈希表记录「见过谁」**。那怎么在不额外存储的前提下利用大小关系？

答案是：**用两个指针从两端往中间夹**。因为数组有序，左端是最小值、右端是最大值，它们的和给了我们一个「调节旋钮」：

- 和太小 → 说明左边这个数配不上右边最大的数，左指针右移（换更大的数）；
- 和太大 → 说明右边这个数太大了，右指针左移（换更小的数）。

这个「根据当前和的大小决定移动哪一端」的机制，正是有序性带来的红利，而且只需要两个下标变量，天然满足 O(1) 空间。

## 3. 从暴力到最优

用示例 1 走一遍：`numbers = [2, 7, 11, 15]`，`target = 9`。

**暴力**：枚举 (2,7)=9 ✓，但最坏要枚举 n(n-1)/2 对。

**双指针**：`left = 0`，`right = 3`（0-based，最后返回时 +1）。

| 步骤 | left | right | numbers[left] | numbers[right] | 和 | 与 target=9 比较 | 动作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 3 | 2 | 15 | 17 | 17 > 9，太大 | right -= 1 |
| 2 | 0 | 2 | 2 | 11 | 13 | 13 > 9，太大 | right -= 1 |
| 3 | 0 | 1 | 2 | 7 | 9 | 相等 | 返回 [1, 2] |

只走了 3 步。对比暴力要试 (2,7)、(2,11)、(2,15)……双指针每一步都**排除了整整一行或一列的可能性**，这就是它快的原因（第 4 节会严格说明）。

再看示例 2：`numbers = [2, 3, 4]`，`target = 6`。

| 步骤 | left | right | 和 | 比较 | 动作 |
|---|---|---|---|---|---|
| 1 | 0 | 2 | 2+4=6 | 相等 | 返回 [1, 3] |

一步命中。

再看一个「和太小」的情况，假设 `numbers = [1, 3, 5, 8]`，`target = 9`：

| 步骤 | left | right | 和 | 比较 | 动作 |
|---|---|---|---|---|---|
| 1 | 0 | 3 | 1+8=9 | 相等 | 返回 [1, 4] |

换个 `target = 8`：

| 步骤 | left | right | 和 | 比较 | 动作 |
|---|---|---|---|---|---|
| 1 | 0 | 3 | 1+8=9 | 9 > 8，太大 | right -= 1 |
| 2 | 0 | 2 | 1+5=6 | 6 < 8，太小 | left += 1 |
| 3 | 1 | 2 | 3+5=8 | 相等 | 返回 [2, 3] |

可以看到指针交替移动，每次都在缩小搜索区间。

**为什么二分不是最优**：二分是 O(n log n)，双指针是 O(n)。双指针的每一步移动都能**永久排除**一个元素（左指针右移说明当前 left 不可能和任何 right 及更左的元素配对；右指针左移同理），总共最多移动 2n 次，所以是线性的。二分没有利用「两个指针同时收缩」这个结构。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：在任意时刻，如果答案存在，那么答案的两个下标 `(i*, j*)` 一定满足 `left <= i* < j* <= right`。也就是说，答案永远落在当前 `[left, right]` 区间内。

**初始时**：`left = 0, right = n-1`，显然任何合法下标对都在这个区间内，不变量成立。

**归纳步**：假设不变量成立，考察当前 `sum = numbers[left] + numbers[right]`：

- **若 `sum == target`**：直接返回，正确。
- **若 `sum > target`**：因为数组非递减，`numbers[right]` 是区间内最大的元素。对任意 `k` 满足 `left <= k < right`，都有 `numbers[k] <= numbers[right]`，所以 `numbers[left] + numbers[k] <= numbers[left] + numbers[right] = sum > target`。这意味着 **`right` 这个位置不可能和区间内任何左边的元素凑成 target**，可以安全地 `right -= 1`，不变量保持。
- **若 `sum < target`**：对称地，`numbers[left]` 是区间内最小的元素。对任意 `k` 满足 `left < k <= right`，都有 `numbers[k] >= numbers[left]`，所以 `numbers[left] + numbers[k] <= sum < target`。这意味着 **`left` 这个位置不可能和区间内任何右边的元素凑成 target**，可以安全地 `left += 1`，不变量保持。

**终止**：每次移动都让区间严格缩小，最多 2n 步后 `left >= right`。但题目保证「仅存在一个有效答案」，所以一定在 `left < right` 时命中，不会走到空区间。

**不会重**：我们返回的是第一次命中的 `(left, right)`，且题目保证答案唯一，所以不存在「先返回一个错误答案」的问题。

这个论证的本质是**交换论证**：当 `sum > target` 时，我们证明了「`right` 与任何更小元素的组合都不可能是答案」，所以排除 `right` 是安全的——被排除的组合里不可能藏着正确答案。

## 5. 完整代码（Python）

```python
from typing import List


class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        # 双指针：left 指向最小端，right 指向最大端
        left, right = 0, len(numbers) - 1

        while left < right:
            current_sum = numbers[left] + numbers[right]

            if current_sum == target:
                # 题目要求下标从 1 开始，所以整体 +1
                return [left + 1, right + 1]
            elif current_sum < target:
                # 和太小：left 位置配不上当前 right，
                # 且配不上任何更小的 right，故 left 可以安全右移
                left += 1
            else:
                # 和太大：right 位置配不上当前 left，
                # 且配不上任何更大的 left，故 right 可以安全左移
                right -= 1

        # 题目保证有唯一解，理论上不会走到这里
        return []
```

几个容易踩的点：

- `left < right` 而不是 `left <= right`：题目要求两个**不同**元素，`left == right` 时是同一个元素，不允许。
- 返回 `[left + 1, right + 1]`：题面明确「下标从 1 开始」，这是最容易丢分的地方。
- 不需要处理「答案顺序」：因为 `left < right` 恒成立，返回的下标天然是升序。

## 6. 复杂度

**时间复杂度 O(n)**：`left` 从 0 出发只增不减，最多走 n 步；`right` 从 n-1 出发只减不增，最多走 n 步。两者合计最多移动 2n 次，每次循环做常数次比较和加法。所以是 O(n)。这里的 n 就是 `numbers.length`，来自指针的总移动距离。

**空间复杂度 O(1)**：只用了 `left`、`right`、`current_sum` 三个整型变量，与输入规模无关。没有开数组、没有开字典。这正是题目「必须只使用常数级的额外空间」所要求的。

对比一下：哈希表解法是 O(n) 时间 + O(n) 空间，被空间限制卡掉；二分是 O(n log n) 时间 + O(1) 空间，合法但慢。双指针同时拿到 O(n) 时间和 O(1) 空间，是这题的最优解。log n 的来源是二分每次把区间折半，而双指针每次只排除一个元素但保证总移动次数线性——两者思路不同。

## 7. 边界与反例（至少 4 条）

1. **输入** `numbers = [2, 3, 4], target = 6` → **期望** `[1, 3]` → **易错点**：答案的两个下标不相邻，且 `2+4=6` 跳过了中间的 3。如果误以为「答案一定相邻」会写错。

2. **输入** `numbers = [-1, 0], target = -1` → **期望** `[1, 2]` → **易错点**：负数参与运算。如果代码里写了「和小于 target 就左移」但没考虑负数，逻辑本身没问题，但若有人用「正数才成立」的直觉去优化就会翻车。另外 n=2 是最小规模，循环只跑一次。

3. **输入** `numbers = [1, 2, 3, 4, 5], target = 9` → **期望** `[4, 5]` → **易错点**：答案是最大的两个数，双指针一开始 `1+5=6 < 9` 会连续右移 left，直到 `4+5=9`。如果循环条件写成 `left <= right`，可能在 `left == right` 时误判同一个元素。

4. **输入** `numbers = [0, 0, 3, 4], target = 0` → **期望** `[1, 2]` → **易错点**：数组含重复的 0，且 target 为 0。答案是两个不同的 0。如果代码用「值去重」的思路会漏掉；双指针天然处理重复值，因为比较的是下标不是值。

5. **输入** `numbers = [5, 25, 75], target = 100` → **期望** `[2, 3]` → **易错点**：`5+75=80 < 100` 左移，`25+75=100` 命中。如果返回时忘了 +1，会输出 `[1, 2]` 而不是 `[2, 3]`。

## 8. 面试追问与变体（3 条）

1. **追问**：如果数组**没有排序**，还能 O(1) 空间做吗？
   **思路**：不能。无序时无法用「大小关系」排除元素，O(1) 空间下只能 O(n²) 暴力。要么排序（O(n log n) 时间，但会打乱原下标，需要额外记录），要么用哈希表（O(n) 空间）。这题的有序性是核心前提。

2. **追问**：如果要求返回**所有**满足条件的数对（不止一对），怎么改？
   **思路**：命中后不能立即返回，而是记录答案，然后 `left += 1` 和 `right -= 1` 同时移动（跳过重复值），继续找。注意处理重复元素时要去重，避免同一对值被多次记录。

3. **追问**：如果数组是**非递减**但允许重复，且要求返回**字典序最小**的那对下标，双指针还成立吗？
   **思路**：成立。双指针从左端开始找，第一次命中时 `left` 已经是最小的可行左下标（因为更小的 left 都被排除了），所以天然是字典序最小的。但要注意：如果存在多对答案，第一次命中的不一定是 left 最小的——需要分析。实际上双指针第一次命中时 left 是「能配成 target 的最小左下标」，因为所有更小的 left 都因「和太小」被右移排除了，而右移的前提是「该 left 配不上任何 right」，所以确实是最小左下标。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 15. 三数之和**：共同点是「排序 + 双指针」。外层固定一个数，内层用双指针在剩余部分找两数之和等于 `-nums[i]`，本质是本题的嵌套版。

2. **LeetCode 11. 盛最多水的容器**：共同点是「双指针从两端向中间收缩」。区别在于移动规则：本题按「和与 target 的大小」移动，那题按「哪边高度更矮就移动哪边」移动，但都用「排除法」保证不漏解。

3. **LeetCode 125. 验证回文串**：共同点是「左右双指针向中间夹」。那题按「字符是否相等」决定移动，本题按「和的大小」决定移动，结构完全同构，适合作为双指针的入门练习。
