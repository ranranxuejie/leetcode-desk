## 1. 一句话本质

在只允许「向右/向下」的有向网格图上，统计从起点到终点、且**绕开所有障碍点**的路径条数。

## 2. 读完题的第一反应

**朴素解法**：枚举所有长度为 `(m-1)+(n-1)` 的移动序列（其中恰好 `m-1` 个「下」、`n-1` 个「右」），对每个序列模拟走一遍，检查是否踩到障碍物，没踩到就计数。

它卡在哪：序列总数是组合数 `C(m+n-2, m-1)`。m = n = 100 时这个数约 10^58，远超题目保证的答案上界 2×10^9——注意，**答案小不代表搜索空间小**，绝大多数序列都是废的，暴力枚举把时间全花在了「走进去才发现撞墙」上。复杂度是指数级，直接爆掉。

**关键观察**：题目只允许向右和向下，这意味着**移动方向构成一个偏序**——你永远不可能回到左上方。于是「到达格子 (i, j) 的路径」只能来自它的上方 (i-1, j) 或左方 (i, j-1)，没有第三条入口。这句话把「全局枚举」压成了「局部递推」：一个格子的答案只依赖它两个邻居的答案。这正是动态规划成立的信号——**无后效性**（怎么走到 (i,j) 不影响从 (i,j) 往后怎么走）加上**最优子结构**（路径数可加）。

## 3. 从暴力到最优

**第一步：把「路径」换成「计数」**。不再关心具体路径长什么样，只关心「到某个格子有几条路」。设 `dp[i][j]` = 从起点到 (i,j) 的合法路径数。

**第二步：写出转移**。若 (i,j) 是障碍，`dp[i][j] = 0`（根本到不了，也走不出去）；否则 `dp[i][j] = dp[i-1][j] + dp[i][j-1]`。瓶颈从「指数级枚举」降到「每个格子 O(1) 加法」，总时间 O(mn)。

**第三步：用一维数组消掉一维空间**。算 `dp[i][j]` 时只需要「上一行同列」和「本行左一格」。如果我们按行从左到右扫，`dp[j]` 在更新前存的是上一行的值（即 `dp[i-1][j]`），更新后存的是本行的值（即 `dp[i][j]`），而 `dp[j-1]` 已经是本行刚算好的。所以一个长度为 n 的数组就够。

**走一遍示例 1**：`grid = [[0,0,0],[0,1,0],[0,0,0]]`，用一维 `dp`（长度 3，初始全 0）。

- 起点特殊处理：`dp[0] = 1`。
- 第 0 行：j=0 是起点跳过；j=1 非障碍 → `dp[1] = dp[1] + dp[0] = 0+1 = 1`；j=2 → `dp[2] = 0+1 = 1`。此时 `dp = [1,1,1]`。
- 第 1 行：j=0 非障碍 → `dp[0] = dp[0] + 0 = 1`（左边没有格子，只有上方）；j=1 是障碍 → `dp[1] = 0`；j=2 非障碍 → `dp[2] = dp[2] + dp[1] = 1 + 0 = 1`。此时 `dp = [1,0,1]`。
- 第 2 行：j=0 → `dp[0] = 1 + 0 = 1`；j=1 → `dp[1] = 0 + 1 = 1`；j=2 → `dp[2] = 1 + 1 = 2`。此时 `dp = [1,1,2]`。

答案 `dp[2] = 2`，与示例一致。注意第 1 行 j=1 被置 0 后，第 2 行 j=1 的 `dp[1]` 只从左边 `dp[0]=1` 拿到 1 条，说明「障碍把路径掐断」这件事是自动通过 0 传播的，不需要额外判断。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说：处理完第 i 行第 j 列后，`dp[k]`（k ≤ j）等于「从起点到 (i,k) 的合法路径数」，`dp[k]`（k > j）等于「从起点到 (i-1,k) 的合法路径数」。

- **不漏**：任何一条到 (i,j) 的合法路径，最后一步要么从 (i-1,j) 下来，要么从 (i,j-1) 过来（题面限定只能向下/向右，没有别的入口）。这两类路径分别被 `dp[j]`（更新前，即上一行）和 `dp[j-1]`（已更新，即本行）完整统计，相加即全部。
- **不重**：一条路径的最后一步是唯一的——它不可能既从上方来又从左边来。所以两类路径集合不相交，直接相加不会重复计数。
- **障碍处理**：障碍格 `dp[j]=0`，等价于「没有任何路径能到达它」，也等价于「任何经过它的路径都不合法」，与题面「路径中不能包含障碍格」一致。

归纳基础是起点 `dp[0]=1`（空路径算一条），归纳步骤由上面的转移保证。所以最终 `dp[n-1]` 就是答案。

## 5. 完整代码（Python）

```python
class Solution:
    def uniquePathsWithObstacles(self, obstacleGrid) -> int:
        m, n = len(obstacleGrid), len(obstacleGrid[0])

        # 起点就是障碍：一步都走不了，直接 0
        if obstacleGrid[0][0] == 1:
            return 0

        # dp[j] 滚动表示「当前行第 j 列」的路径数
        dp = [0] * n
        dp[0] = 1  # 起点：空路径算 1 条

        for i in range(m):
            for j in range(n):
                if obstacleGrid[i][j] == 1:
                    dp[j] = 0          # 障碍格：到达数清零，切断后续传播
                    continue
                if j > 0:
                    # dp[j] 此刻还是上一行的值（从上方来）
                    # dp[j-1] 已是本行刚算好的值（从左方来）
                    dp[j] = dp[j] + dp[j - 1]
                # j == 0 且非障碍：dp[0] 保持原值（只能从上方来，或就是起点）

        return dp[n - 1]
```

关键点：`j == 0` 那一列不执行加法，因为左边没有格子；它的值要么是起点初始化的 1，要么是上一行传下来的 `dp[0]`，要么被障碍清成 0——三种情况都正确。

## 6. 复杂度

- **时间 O(m·n)**：两层循环各遍历 m 行、n 列，每个格子做常数次加法/赋值。m、n 来自网格的行数和列数，没有 log 项——因为没有任何排序或二分。
- **空间 O(n)**：只开一个长度为 n 的一维数组。n 来自列数；如果转置思路（按列扫）可以做到 O(min(m,n))，但本题 m,n ≤ 100，没必要。原始二维 DP 是 O(mn)，滚动数组把它压掉了一维。

## 7. 边界与反例（至少 4 条）

1. **`[[1]]`** → 期望 `0` → 容易错：只写 `dp[0]=1` 就返回，忘了起点本身可能是障碍。代码里开头单独判了。
2. **`[[0]]`** → 期望 `1` → 容易错：把「空路径」当成 0 条。起点到起点算一条路径，这是 DP 的归纳基础。
3. **`[[0,0],[1,1],[0,0]]`**（中间整行是墙）→ 期望 `0` → 容易错：以为只要终点非障碍就有路。实际上障碍把上下完全隔断，`dp` 会自然传播成 0，但要理解「0 会沿着行/列一路传下去」。
4. **`[[0,0,0],[0,0,0],[0,0,0]]`**（无障碍）→ 期望 `6`（即 `C(4,2)`）→ 容易错：一维滚动时把 `dp[j] = dp[j] + dp[j-1]` 写成先更新 `dp[j-1]` 再用，或者把 `dp[j]` 当成「本行」而不是「上一行」，导致重复加。顺序必须是「先读旧 `dp[j]`，再加新 `dp[j-1]`」，代码里一行 `dp[j] = dp[j] + dp[j-1]` 恰好满足。
5. **第一行有障碍**，如 `[[0,1,0],[0,0,0]]` → 期望 `1` → 容易错：初始化时把第一行全设成 1，没考虑障碍后面的格子应该为 0。滚动写法里第一行靠 `dp[j] = dp[j] + dp[j-1]` 自然处理，障碍处清 0 后，后面的 `dp[j-1]` 就是 0，自动断掉。

## 8. 面试追问与变体（3 条）

1. **追问：如果允许上下左右四个方向移动呢？** 思路：那就不是 DAG 了，路径可能成环、条数可能无穷，DP 失效；若要求「不重复经过格子」则是 #980 的变体，得用 DFS + 记忆化（状态含已访问集合），复杂度指数级。
2. **追问：如果障碍物可以「清除」k 个，问路径数？** 思路：状态加一维 `dp[i][j][t]` 表示到 (i,j) 已清 t 个障碍的路径数，转移时按当前格是否障碍决定 t 是否 +1，时间 O(mnk)。
3. **追问：如果要求返回一条具体路径而不是条数？** 思路：先 DP 出计数（或只做可达性 BFS），再从终点倒推，每次选一个「能到达且计数匹配」的邻居回退，O(m+n) 构造。
