## 1. 一句话本质

把「在所有矩形覆盖的整数点里等概率抽一个」拆成两步：先按**面积（整数点个数）加权**抽一个矩形，再在这个矩形内部等概率抽一个点。

## 2. 读完题的第一反应

**朴素解法**：把所有矩形覆盖的整数点全部枚举出来，塞进一个大列表，`pick()` 时 `random.choice` 一下。

它卡在哪？看数据范围：每个矩形宽高各不超过 2000，所以单个矩形最多约 2001×2001 ≈ 4×10⁶ 个点，100 个矩形就是 4×10⁸ 个点。存不下，更别说每次 `pick` 还要在 4 亿里随机——内存和时间都爆了。而且 `pick` 最多调用 10⁴ 次，如果每次 `pick` 都重新扫一遍所有点，更是灾难。

**关键观察**：题目说「所有满足要求的点必须等概率被返回」。这句话等价于——每个点被选中的概率是 1/(总点数)。而「等概率」这件事可以**分层实现**：如果我先以「矩形 i 的点数 / 总点数」的概率选中矩形 i，再在矩形 i 内部均匀抽点，那么矩形 i 里任意一个点被选中的概率就是 (点数_i / 总点数) × (1 / 点数_i) = 1 / 总点数。**恰好就是全局均匀**。

这一步把「4 亿个点」压缩成了「100 个矩形 + 每个矩形内部的小范围随机」，问题瞬间从「存所有点」变成「按权重选矩形」。

## 3. 从暴力到最优

**第一步：暴力枚举所有点**

以示例 `rects = [[-2,-2,1,1], [2,2,4,6]]` 为例。

矩形 0：x 从 -2 到 1 共 4 个整数，y 从 -2 到 1 共 4 个整数，点数 = 4×4 = 16。
矩形 1：x 从 2 到 4 共 3 个，y 从 2 到 6 共 5 个，点数 = 3×5 = 15。

总点数 31。暴力就是把 31 个点列出来。这里还好，但换成 100 个 2000×2000 的矩形就崩了。

**第二步：按点数加权选矩形**

把每个矩形的点数算出来，做**前缀和**：

```
cnt  = [16, 15]
pre  = [16, 31]     # pre[i] = 前 i+1 个矩形的点数之和
```

`pick()` 时，在 `[0, 31)` 里随机取一个整数 `r`。然后找第一个满足 `pre[i] > r` 的 i——这个 i 就是被选中的矩形。

为什么这样是「按点数加权」？因为 `r` 落在 `[0,16)` 的概率是 16/31，落在 `[16,31)` 的概率是 15/31，正好对应两个矩形的点数占比。

举例：`r = 20`。`pre[0]=16 ≤ 20`，`pre[1]=31 > 20`，所以选矩形 1。`r = 5` 则选矩形 0。

**第三步：在矩形内部均匀抽点**

选中矩形 i 后，`r` 相对于这个矩形起点的偏移是 `r - (pre[i-1] 或 0)`。设偏移为 `k`，矩形宽 `w = x - a + 1`（注意 +1，因为两端都算），高 `h = y - b + 1`。

则 `dx = k % w`，`dy = k // w`，返回 `[a + dx, b + dy]`。

继续上面的例子：`r = 20`，选矩形 1，偏移 `k = 20 - 16 = 4`。矩形 1 宽 `w = 4-2+1 = 3`，高 `h = 6-2+1 = 5`。`dx = 4 % 3 = 1`，`dy = 4 // 3 = 1`，返回 `[2+1, 2+1] = [3, 3]`。

**瓶颈怎么被消掉的**：原来要存 4×10⁸ 个点，现在只存 100 个前缀和；原来每次 `pick` 要在大列表里随机，现在只需一次 `random.randrange(总点数)` 加一次二分查找（或线性扫描，因为只有 100 个矩形）。空间从 O(总点数) 降到 O(矩形数)，时间从 O(总点数) 降到 O(log 矩形数)。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。

**不变量**：对任意一次 `pick()`，设随机数 `r ∈ [0, total)` 均匀分布。则对任意矩形 i 内的任意整数点 p，p 被返回的概率恒为 `1/total`。

证明分两层：

1. **矩形层**：`r` 落在区间 `[pre[i-1], pre[i])` 的概率 = `(pre[i] - pre[i-1]) / total` = `cnt[i] / total`。由于前缀和严格递增（每个矩形至少 1 个点，因为 `a < x` 且 `b < y`），这些区间**互不重叠且恰好覆盖 `[0, total)`**，所以不会漏掉任何矩形，也不会重复计入。

2. **点层**：在矩形 i 内部，偏移 `k = r - pre[i-1]` 在 `[0, cnt[i])` 上均匀分布。映射 `k → (k % w, k // w)` 是 `[0, w×h)` 到 `[0,w)×[0,h)` 的**双射**（因为 `w×h = cnt[i]`），所以矩形内每个点被选中的概率都是 `1/cnt[i]`。

两层相乘：`(cnt[i]/total) × (1/cnt[i]) = 1/total`。与 i 无关，故全局均匀。

**不会重**的依据是矩形互不重叠（题面保证），所以不同矩形里的点集合不相交；**不会漏**的依据是前缀和区间恰好铺满 `[0, total)`。

## 5. 完整代码（Python）

```python
import random
import bisect

class Solution:
    def __init__(self, rects):
        self.rects = rects
        self.pre = []          # 前缀和：pre[i] = 前 i+1 个矩形的整数点总数
        total = 0
        for a, b, x, y in rects:
            w = x - a + 1      # 宽度上的整数点个数（两端都算，故 +1）
            h = y - b + 1      # 高度上的整数点个数
            total += w * h
            self.pre.append(total)
        self.total = total

    def pick(self):
        # 在 [0, total) 上均匀取一个整数
        r = random.randrange(self.total)
        # 二分找第一个 pre[i] > r 的矩形下标
        i = bisect.bisect_right(self.pre, r)
        # 该矩形之前的点数之和
        base = self.pre[i - 1] if i > 0 else 0
        k = r - base           # 矩形内部的偏移量
        a, b, x, y = self.rects[i]
        w = x - a + 1
        # 把一维偏移 k 还原成二维坐标
        dx = k % w
        dy = k // w
        return [a + dx, b + dy]


# 题目给的签名是 Solution.solve(inputs, inputs) -> list<String>，
# 这里做一个适配层，方便按力扣的「操作序列」形式调用。
def solve(ops, args):
    res = []
    obj = None
    for op, arg in zip(ops, args):
        if op == "Solution":
            obj = Solution(arg[0])
            res.append(None)
        elif op == "pick":
            res.append(obj.pick())
    return res
```

注意 `bisect_right(self.pre, r)` 返回的是第一个 `> r` 的位置，正好对应「第一个 `pre[i] > r`」的 i，和前面推导一致。

## 6. 复杂度

设矩形个数为 `n`（≤100），总点数为 `total`。

- **初始化**：遍历 `n` 个矩形，每个算一次 `w*h` 并累加，时间 **O(n)**；存 `pre` 数组，空间 **O(n)**。这里 `n` 就是矩形个数，不是点数。
- **每次 `pick`**：`random.randrange` 是 O(1)；`bisect_right` 在长度 `n` 的有序数组上二分，时间 **O(log n)**；坐标还原是常数次算术，O(1)。合计 **O(log n)**。
- **总空间**：O(n)，因为只存了 `rects` 引用和 `pre` 数组，**没有存任何点**。这是相对暴力解 O(total) 的核心改进。

`total` 最大约 100 × 4×10⁶ = 4×10⁸，但 `total` 只作为一个整数参与运算，不占额外空间，也不影响时间复杂度。

## 7. 边界与反例（至少 4 条）

1. **单点矩形**：`rects = [[0,0,0,0]]` → 期望恒返回 `[0,0]`。容易错在 `w = x - a + 1` 写成 `x - a`，得到 `w=0`，`k % 0` 直接除零崩溃。题面 `a < x` 保证宽至少 1，但 `+1` 不能漏。

2. **负坐标**：`rects = [[-2,-2,1,1]]` → 期望返回 x∈[-2,1]、y∈[-2,1] 的点。容易错在把 `a + dx` 写成 `dx`，忘了加左下角偏移；负坐标下这个错误不会报错，只会静默返回错误范围。

3. **多个矩形点数差异极大**：`rects = [[0,0,0,0], [10,10,2010,2010]]` → 第一个矩形 1 个点，第二个约 4×10⁶ 个点。期望第一个矩形被选中的概率约 1/4×10⁶。容易错在「先均匀选矩形再均匀选点」——那样第一个矩形概率变成 1/2，严重偏离。必须**按点数加权**选矩形。

4. **`pick` 被调用 10⁴ 次**：如果每次 `pick` 都重新遍历 `n` 个矩形算前缀和，就是 O(n) 每次，10⁴×100 = 10⁶ 次运算，虽然能过但没必要。容易错在把前缀和计算放进 `pick` 里而不是 `__init__` 里。前缀和是**静态**的，初始化算一次即可。

5. **矩形边界相邻但不重叠**：`rects = [[0,0,1,1], [2,0,3,1]]` → 两个矩形在 x 方向相邻（1 和 2 之间没有整数点重叠）。容易错在担心「边界点被算两次」，实际上整数点集合 `{0,1}` 和 `{2,3}` 不相交，前缀和方案天然正确。

## 8. 面试追问与变体（3 条）

1. **追问：如果矩形会动态增删，怎么办？** 思路：前缀和是静态结构，动态场景要换成**有序集合 + 树状数组/线段树**维护权重，按权重随机选变成「在树状数组上二分找第 r 个权重」，O(log n) 完成。

2. **追问：如果要求抽的是实数点而不是整数点，怎么改？** 思路：把 `w = x - a + 1` 改成 `w = x - a`（实数区间长度），`k` 改成 `random.uniform(0, total)` 的浮点数，`dx = k % w` 用浮点取模，其余逻辑不变——本质是「按面积加权 + 区间内均匀」。

3. **追问：如果矩形允许重叠，还能这样做吗？** 思路：不能直接按面积加权，因为重叠区域的点会被重复计数，概率不再均匀。需要先做**矩形并的面积**（扫描线），或者用拒绝采样（随机选一个矩形和点，若落在重叠区则重抽），但拒绝采样在最坏情况下效率退化。

2. **力扣 382. 链表随机节点**：用**水塘抽样**在未知长度的流里等概率取一个元素，和本题「等概率」的核心诉求一致，只是数据结构不同（流 vs 静态数组）。

3. **力扣 398. 随机数索引**：在含重复元素的数组里等概率返回目标值的某个下标，同样是水塘抽样思想，可以对照本题理解「分层等概率」的另一种实现方式。
