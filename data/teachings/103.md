## 1. 一句话本质

在普通层序遍历（BFS）的基础上，给每一层加一个「方向开关」：偶数层正序输出、奇数层逆序输出，层与层之间翻转这个开关。

## 2. 读完题的第一反应

**朴素解法**：先老老实实做一次标准层序遍历，得到 `[[3],[9,20],[15,7]]`，然后对结果数组里下标为奇数的子列表做一次 `reverse()`。

它卡在哪？其实**不卡**——这个朴素解法本身就是 O(n) 的，因为每个节点只被访问一次，每层最多被翻转一次，翻转总代价也不超过 O(n)。所以这道题不存在「暴力超时」的瓶颈，真正的考点是**你能不能在遍历过程中就把方向处理好**，而不是事后补救。

**关键观察**：题面说「先从左往右，再从右往左进行下一层遍历」——注意这里的「遍历」指的是**输出顺序**，不是**访问顺序**。也就是说，我们仍然可以永远按「左孩子、右孩子」的顺序把节点塞进队列（这样下一层的节点在队列里天然是左→右排列的），只是**收集本层结果时**，根据层号决定是 `append` 到尾部还是 `append` 到头部（或者收集完再翻转）。

这个区分很重要：它让你意识到「访问顺序」和「输出顺序」可以解耦，于是 BFS 的骨架一行都不用改，只在「收集」这一步动手脚。

## 3. 从暴力到最优

其实「暴力」和「最优」在这里是同一个复杂度，差别只在代码整洁度和是否多一次遍历。我们走一遍示例 1：`root = [3,9,20,null,null,15,7]`。

**方案 A：先 BFS 再翻转**

```
第 0 层：队列 [3]        → 收集 [3]        → level=0 偶数，不翻转 → [3]
第 1 层：队列 [9,20]     → 收集 [9,20]     → level=1 奇数，翻转   → [20,9]
第 2 层：队列 [15,7]     → 收集 [15,7]     → level=2 偶数，不翻转 → [15,7]
结果：[[3],[20,9],[15,7]]
```

**方案 B：收集时就按方向插入**

用双端队列 `deque` 当本层的容器：

```
第 0 层：访问 3，level=0 偶数 → append 到右端 → deque=[3]
第 1 层：访问 9 → appendleft → [9]
        访问 20 → appendleft → [20,9]
第 2 层：访问 15 → append 到右端 → [15]
        访问 7  → append 到右端 → [15,7]
```

两个方案结果一致。方案 B 省掉了「收集完再翻转」这一步，代码里方向逻辑集中在插入那一行，读起来更清楚；方案 A 更直白，不容易写错。面试时两种都能过，我下面代码用方案 A 的变体（收集完按层号翻转），因为它的**不变量**最容易讲清楚。

**为什么这就够了？** 因为 BFS 的队列天然保证了「同一层的节点连续出队、下一层的节点连续入队」，这个性质与方向无关。方向只影响我们怎么摆放已经拿到的值，不影响我们怎么找下一批节点。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来证。设当前正在处理第 `k` 层。

**不变量**：进入每一轮外层 `while` 时，队列中恰好包含第 `k` 层的全部节点，且按「从左到右」的顺序排列；此前 0..k-1 层的结果已按锯齿规则正确写入答案。

**初始化**：`k=0` 时队列只有根节点，第 0 层只有它一个，从左到右成立。

**保持**：内层循环执行 `len(queue)` 次，每次弹出一个第 `k` 层节点，把它的左、右孩子依次入队。由于弹出顺序是左→右，入队顺序也是左→右，所以内层循环结束后，队列里正好是第 `k+1` 层全部节点且左→右排列。同时，本层收集到的值集合恰好是第 `k` 层全部节点值（每个节点弹出一次，不漏），且每个节点只弹出一次（不重）。按 `k` 的奇偶决定是否翻转，得到的就是锯齿规则要求的顺序。

**终止**：队列为空时，所有层都已处理完毕，且每层都满足锯齿规则。

**不漏**：每个节点入队恰好一次（根节点入队一次，之后每个节点只被它的父节点入队一次），出队恰好一次，所以每个值恰好被收集一次。
**不重**：同上，出队即收集，没有重复路径。

## 5. 完整代码（Python）

```python
from collections import deque
from typing import List, Optional


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def zigzagLevelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        # 空树直接返回空列表，避免后面 deque 里塞 None
        if root is None:
            return []

        result = []
        queue = deque([root])   # BFS 队列，始终按「左→右」存放当前层节点
        level = 0               # 当前层号，从 0 开始，用来决定方向

        while queue:
            size = len(queue)   # 关键：先固定本层节点数，内层循环只处理这一层
            current = []        # 收集本层的值

            for _ in range(size):
                node = queue.popleft()
                current.append(node.val)

                # 入队顺序永远是左→右，保证下一层在队列里天然有序
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)

            # 奇数层翻转；偶数层保持原样
            if level % 2 == 1:
                current.reverse()

            result.append(current)
            level += 1          # 层号递增，方向随之交替

        return result
```

几个容易写错的点，代码里已经体现：

- `size = len(queue)` 必须在 `for` 之前取，否则循环中队列长度变化会导致层边界错乱。
- 入队顺序固定为左→右，**不要**因为当前层要逆序就把孩子也反着入队——那会把下一层的顺序搞乱。
- `root is None` 要单独判断，因为 `deque([None])` 会让 `popleft()` 拿到 `None` 再访问 `.val` 报错。

## 6. 复杂度

**时间 O(n)**，n 是节点总数。每个节点入队一次、出队一次，各 O(1)，共 2n 次操作。每层的 `reverse()` 代价是该层节点数，所有层加起来不超过 n。所以总时间是 O(n)，与树的形状无关。

**空间 O(w)**，w 是树的最大宽度（某一层最多的节点数）。队列里最多同时存放一层节点加上下一层正在入队的节点，量级是 O(w)。结果数组本身要存 n 个值，这部分是 O(n)，但通常算作输出空间、不计入辅助空间。最坏情况（完全二叉树最后一层）w ≈ n/2，所以最坏 O(n)；最好情况（链状树）w = 1，O(1)。

注意这里**没有 log n**：BFS 不递归，不占调用栈，树高不进入复杂度。如果换成 DFS 递归写法，栈深度才是 O(h) = O(log n)（平衡树）到 O(n)（链状树）。

## 7. 边界与反例（至少 4 条）

1. **输入 `root = []`** → 期望 `[]` → 容易错在没判空，`deque([None])` 后访问 `.val` 直接崩。
2. **输入 `root = [1]`** → 期望 `[[1]]` → 容易错在把单节点当成「没有下一层」而漏掉外层循环，或误以为要返回 `[1]` 而不是 `[[1]]`。
3. **输入 `root = [1,2,3]`** → 期望 `[[1],[3,2]]` → 容易错在只翻转了值没翻转顺序，或者把第 1 层也当成偶数层不翻转。
4. **输入 `root = [1,2,null,3,null,4]`（左斜链）** → 期望 `[[1],[2],[3],[4]]` → 每层只有一个节点，翻转与否结果相同，容易错在误以为「锯齿」在单节点层会出问题，实际不会；但若代码里用 `level % 2` 判断时把 `level` 初值写成 1，就会整体错位。
5. **输入 `root = [1,2,3,4,null,null,5]`** → 期望 `[[1],[3,2],[4,5]]` → 第 2 层只有 `4` 和 `5`，注意 `4` 是 `2` 的左孩子、`5` 是 `3` 的右孩子，BFS 队列顺序是 `[4,5]`，偶数层不翻转，容易错在把 `null` 也当成节点入队导致顺序错乱。

## 8. 面试追问与变体（3 条）

1. **追问：不用 `reverse()`，能不能在插入时就保证顺序？** 思路：本层用 `deque`，偶数层 `append` 到右端、奇数层 `appendleft` 到左端，最后 `list(dq)` 即可，省掉一次翻转。
2. **追问：如果要求「从下往上」的锯齿遍历（先底层再顶层）？** 思路：正常锯齿 BFS 得到结果后整体 `result.reverse()`，或者用 DFS 按层号把值插到 `result` 对应位置（层号从 0 开始，DFS 时 `result[level]` 不存在就新建）。
3. **追问：如果树是 N 叉树，锯齿规则怎么改？** 思路：把「左孩子、右孩子」换成「按 children 列表顺序入队」，其余逻辑不变；方向仍然只影响收集顺序，不影响入队顺序。
