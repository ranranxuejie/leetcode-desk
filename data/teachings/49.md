## 1. 一句话本质

把「互为字母异位词」这个关系当成等价关系，为每个等价类算出一个**唯一且可比较的指纹**，再按指纹把字符串分桶。

## 2. 读完题的第一反应

最朴素的做法是两两比较：对每对字符串判断是否互为异位词（排序后比较或数 26 个字母的计数），是就放进同一组。判断一对是 O(L log L)（L 为串长），而配对要 O(n²) 次，总复杂度 O(n² · L log L)。n 最大 10⁴，n² 就是 10⁸ 次配对，直接超时。瓶颈在「两两比较」这个结构本身——它没有利用「异位词关系是传递的」这一点。

关键观察来自题面示例：`"eat"`、`"tea"`、`"ate"` 被分到一组，而 `"tan"`、`"nat"` 在另一组。它们的共同点是**排序后完全相同**：`"eat"/"tea"/"ate"` 排序都是 `"aet"`，`"tan"/"nat"` 排序都是 `"ant"`。也就是说，「排序后的字符串」是异位词类的一个天然标签。一旦有了标签，问题就从「两两配对」变成「按标签分组」——这正是哈希表的用武之地，一次遍历即可，O(n) 次哈希操作。

## 3. 从暴力到最优

**暴力版**：双重循环，对每对字符串排序后比较，相同则合并。瓶颈是 O(n²) 次比较。

**第一步优化——用标签代替比较**：不再比较字符串之间，而是给每个字符串算一个标签 `key = ''.join(sorted(s))`，用字典 `groups[key].append(s)`。这样每个字符串只处理一次，O(n) 次字典操作。以示例 1 走一遍：

```
s="eat" → sorted → ['a','e','t'] → key="aet" → groups={"aet": ["eat"]}
s="tea" → key="aet" → groups={"aet": ["eat","tea"]}
s="tan" → key="ant" → groups={"aet": [...], "ant": ["tan"]}
s="ate" → key="aet" → groups={"aet": ["eat","tea","ate"], "ant": ["tan"]}
s="nat" → key="ant" → groups={"ant": ["tan","nat"]}
s="bat" → key="abt" → groups={"abt": ["bat"], ...}
```

最后取 `groups.values()` 即可。瓶颈从 O(n²) 降到 O(n · L log L)，其中 L log L 是每个串排序的代价。

**第二步优化——把排序换成计数**：题面提示「仅包含小写字母」，字母表只有 26 个。排序是为了得到「字母的多重集合」，而计数数组同样能唯一表示多重集合，且只需 O(L + 26) 而非 O(L log L)。把计数数组转成元组作 key（元组可哈希，列表不行）：

```
s="eat" → count[0..25]，a:1, e:1, t:1，其余 0 → key=(1,0,0,0,1,...,1,...)
s="tea" → 同样的计数 → 同一个 key
```

这一步把每个串的处理从 O(L log L) 降到 O(L + 26)。注意 26 是常数，所以整体是 O(n · L)。当 L 很大时这个优化才明显；L ≤ 100 时两者差距不大，但面试里讲出这一步能体现你对「为什么排序可行、计数也可行」的理解。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。设 `key(s)` 为 s 排序后的字符串（或计数元组）。核心不变量：

> 对任意两个字符串 a、b，`key(a) == key(b)` 当且仅当 a 与 b 互为字母异位词。

证明两个方向：

- **若 a、b 互为异位词**：它们由完全相同的字母多重集合构成，排序后字符序列必然逐位相同，计数也必然逐位相同，故 `key(a) == key(b)`。
- **若 `key(a) == key(b)`**：排序后的序列相同意味着两者的字母多重集合相同，即 a 可由 b 重排得到，故互为异位词。

有了这个充要条件，算法「按 key 分桶」就恰好是「按异位词等价类分桶」：

- **不会漏**：每个字符串都被遍历一次并放入自己 key 对应的桶，任何异位词对因 key 相同必进同一桶。
- **不会重**：一个字符串只有一个 key，只进一个桶；不同 key 的桶对应不同等价类，不会混入。

等价关系的传递性（a~b、b~c 则 a~c）由 key 相等直接保证，这也是为什么「标签法」能替代「两两比较」——标签把传递闭包一次性算完了。

## 5. 完整代码（Python）

```python
from collections import defaultdict
from typing import List


class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        # key 是「排序后的字符串」，value 是同一异位词类的所有原串
        groups = defaultdict(list)

        for s in strs:
            # 排序得到该串的字母多重集合的规范表示
            # 异位词排序后必然相同，非异位词排序后必然不同
            key = ''.join(sorted(s))
            # 同 key 的串归入同一桶；defaultdict 自动建空列表
            groups[key].append(s)

        # 桶的集合就是答案，顺序任意
        return list(groups.values())
```

如果要用计数法（面试追问时可能要求），把 key 换成计数元组：

```python
class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        groups = defaultdict(list)
        for s in strs:
            count = [0] * 26
            for ch in s:
                count[ord(ch) - ord('a')] += 1
            # 列表不可哈希，转元组才能当字典 key
            groups[tuple(count)].append(s)
        return list(groups.values())
```

两版逻辑完全一致，只是「指纹」的算法不同。第一版更短、更不易写错；第二版在 L 很大时更优。

## 6. 复杂度

设 n = 字符串个数，L = 单个字符串的最大长度，Σ = 26（字母表大小）。

**排序版**：

- 时间：O(n · L log L)。外层遍历 n 个串；每个串排序 O(L log L)，拼接 O(L)，字典插入均摊 O(1)（key 长度 L，哈希计算 O(L)，但被排序的 O(L log L) 支配）。所以总的是 n 乘以 L log L。
- 空间：O(n · L)。所有字符串本身要存（输入已占 O(n·L)），字典里每个 key 长度 L、共最多 n 个 key，value 里存的是原串引用不复制字符，额外空间主要是 key 的 O(n·L)。

**计数版**：

- 时间：O(n · (L + Σ)) = O(n · L)（Σ=26 是常数）。每个串数一遍字母 O(L)，建元组 O(Σ)，哈希元组 O(Σ)。
- 空间：O(n · Σ) 存 key（每个 key 是长度 26 的元组），加上输入本身 O(n·L)。

注意：如果面试官问「为什么不是 O(n)」，答案是每个串必须至少被读一遍，L 是躲不掉的；n 是串的个数，L 是串的长度，两者独立。

## 7. 边界与反例（至少 4 条）

1. **输入 `[""]`** → 期望 `[[""]]`。空串排序后仍是 `""`，key 为 `""`，能正常分桶。易错点：有人写 `if not s: continue` 把空串跳过，导致漏掉。
2. **输入 `["a"]`** → 期望 `[["a"]]`。单字符，排序不变，正常。易错点：无，但要注意返回值是「列表的列表」，别返回 `["a"]`。
3. **输入 `["", ""]`** → 期望 `[["",""]]`（两个空串同组）。易错点：用 `if key not in groups` 手动判断时写反条件，或误以为空串应各自成组。
4. **输入 `["ab", "ba", "abc"]`** → 期望 `[["ab","ba"],["abc"]]`。易错点：key 用 `set(s)` 而非排序/计数——`"ab"` 和 `"ba"` 的 set 都是 `{'a','b'}` 没问题，但 `"aab"` 和 `"ab"` 的 set 也相同却**不是**异位词，set 丢失了重数信息，是经典错误。
5. **输入 `["ddddddddddg", "dgggggggggg"]`** → 期望两组分开。易错点：同上，若用 set 或对字符求和当 key，会误判为同组（两者字符和可能相同但多重集合不同）。

## 8. 面试追问与变体（3 条）

1. **追问：如果字符集不是小写字母，而是任意 Unicode，怎么办？** 思路：排序法仍然成立（O(L log L)），计数法需要把「26 个桶」换成哈希表统计字符频次，再把频次表转成可哈希的元组（如 `tuple(sorted(freq.items()))`），复杂度变为 O(L log L) 级别。
2. **追问：不要求分组，只问「有多少对异位词」怎么算？** 思路：同样按 key 分桶，桶大小为 k 时贡献 C(k,2) 对，累加即可，时间仍是 O(n·L log L)。
3. **追问：内存受限，不能存所有 key，能否流式处理？** 思路：对每个串算 key 后只保留「key → 计数」的映射（不存原串），若只需分组数量或最大组大小，空间可降到 O(不同 key 数)；若要输出分组内容则必须存原串，无法进一步压缩。
