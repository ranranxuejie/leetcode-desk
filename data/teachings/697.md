## 1. 一句话本质

在所有「出现次数等于数组度」的元素里，找「首次出现到末次出现」跨度最小的那个，返回它的跨度长度。

## 2. 读完题的第一反应

**朴素解法**：先扫一遍统计每个元素的频数，求出度 d；然后枚举所有元素 x，对每个频数为 d 的 x，再扫一遍数组找出它的首次位置和末次位置，算跨度。统计频数 O(n)，枚举元素最多 n 个、每个再扫一遍 O(n)，最坏 O(n²)。n 到 50000 时 2.5×10⁹ 次操作，超时。

**卡在哪**：对每个候选元素都要重新扫数组找首末位置，这是重复劳动。而「首次位置」「末次位置」「频数」这三样东西，其实**一遍扫描就能同时拿到**——扫到下标 i 的元素 x 时：如果 x 第一次见，记 first[x]=i；无论如何 last[x]=i、count[x]+=1。三个哈希表同步更新，O(n) 搞定。

**关键观察**：一个元素 x 的所有出现位置中，最左是 first[x]、最右是 last[x]。任何包含 x 全部出现次数的连续子数组，左端点不可能晚于 first[x]，右端点不可能早于 last[x]，所以最短的那个恰好就是 `nums[first[x] : last[x]+1]`，长度 `last[x] - first[x] + 1`。这个「恰好」是整道题的支点：它把「在所有子数组里搜」变成了「对每个元素算一个固定公式」。

## 3. 从暴力到最优

**第一步（暴力）**：两遍扫描，第一遍求度，第二遍对每个频数等于度的元素找首末。瓶颈是第二遍的「每个元素一次全扫」。

**第二步（观察）**：首末位置和频数是同一批信息，一遍扫描就能同时记录。于是把「求度」和「求首末」合并成一次遍历，最后再遍历一次哈希表挑答案。

用示例 1 `[1,2,2,3,1]` 走一遍，维护 `first`、`last`、`count` 三个字典：

| i | x | first | last | count |
|---|---|-------|------|-------|
| 0 | 1 | {1:0} | {1:0} | {1:1} |
| 1 | 2 | {1:0,2:1} | {1:0,2:1} | {1:1,2:1} |
| 2 | 2 | 不变 | {1:0,2:2} | {1:1,2:2} |
| 3 | 3 | {1:0,2:1,3:3} | {1:0,2:2,3:3} | {1:1,2:2,3:1} |
| 4 | 1 | 不变 | {1:4,2:2,3:3} | {1:2,2:2,3:1} |

扫描结束，度 d = max(count.values()) = 2。候选元素是 1 和 2：
- 1 的跨度 = last[1]-first[1]+1 = 4-0+1 = 5
- 2 的跨度 = 2-1+1 = 2

取最小，答案 2。和题面给的 `[2,2]` 一致。

**第三步（合并成一次遍历）**：其实连「先求度再挑」都可以省——在扫描过程中维护 `degree` 和 `ans`：遇到 x 时更新 count[x]，若 count[x] > degree 则 degree 刷新、ans 直接设为当前跨度；若 count[x] == degree 则 ans = min(ans, 当前跨度)。这样一次遍历结束答案就出来了。不过为了代码可读性，下面代码采用「先建表、再挑答案」的两段式，逻辑更直白，复杂度同为 O(n)。

## 4. 正确性：为什么不会漏、不会重

**不变量**：扫描到下标 i 结束时，对任意已出现的元素 x，`first[x]` 是 x 在 `nums[0..i]` 中首次出现的下标，`last[x]` 是末次出现的下标，`count[x]` 是出现次数。

归纳证明：i=0 时显然成立。假设 i-1 时成立，处理 i 时若 x 首次出现则 first[x]=i（此前没有 x，所以这是全局首次），last[x]=i、count[x]=1；若 x 已出现，first[x] 不动（保持全局首次），last[x] 更新为 i（i 是当前最右），count[x] 加一。不变量保持。

**不漏**：设数组的度为 d，任一频数为 d 的元素 x 的跨度 `last[x]-first[x]+1` 一定被枚举到（我们遍历了所有出现过的元素）。而任何「度等于 d」的连续子数组必须包含某个频数为 d 的元素 x 的全部 d 次出现——否则这个子数组里 x 出现不到 d 次，它的度就小于 d 了。包含 x 全部出现的最短区间正是 `[first[x], last[x]]`，所以最短合法子数组的长度 ≥ min over x 的跨度，且这个下界能被取到。故答案正确。

**不重**：每个元素只贡献一个候选跨度，取 min 不会把不同元素的跨度错误叠加；同一元素内部也不存在「更短的合法区间」——任何比 `[first[x], last[x]]` 更短的区间都会漏掉 x 的某次出现，度就不够了。

## 5. 完整代码（Python）

```python
class Solution:
    def findShortestSubArray(self, nums: list[int]) -> int:
        first = {}   # 元素 -> 首次出现的下标
        last = {}    # 元素 -> 末次出现的下标
        count = {}   # 元素 -> 出现次数

        # 一遍扫描，同时维护三张表
        for i, x in enumerate(nums):
            if x not in first:
                first[x] = i          # 只在第一次见到时记录
            last[x] = i               # 每次见到都刷新为最右位置
            count[x] = count.get(x, 0) + 1

        degree = max(count.values())  # 数组的度

        ans = len(nums)               # 上界：整个数组
        for x, c in count.items():
            if c == degree:           # 只有频数等于度的元素才是候选
                span = last[x] - first[x] + 1
                if span < ans:
                    ans = span
        return ans
```

关键逻辑说明：
- `if x not in first` 保证 first 只写一次，即全局首次位置；`last[x] = i` 无条件写，天然保留最右位置。
- `count.get(x, 0) + 1` 是 Python 里计数哈希表的惯用写法，避免先判断再赋值。
- 第二段只对 `c == degree` 的元素算跨度，因为频数小于度的元素即使跨度再小也不满足「度相同」的要求。

## 6. 复杂度

**时间 O(n)**：第一段 for 循环遍历 n 个元素，每次字典查找/插入均摊 O(1)，共 O(n)。`max(count.values())` 遍历至多 n 个不同元素，O(n)。第二段 for 遍历至多 n 个不同元素，O(n)。三段相加仍是 O(n)。这里没有 log 项——哈希表操作是均摊常数，不是 O(log n)（那是平衡树/堆的代价）。

**空间 O(k)**，k 为不同元素个数，最坏 k=n 即 O(n)：三张字典各存至多 k 个键值对，常数因子 3 不影响量级。没有递归栈、没有额外数组。

## 7. 边界与反例（至少 4 条）

1. **输入 `[1]`** → 期望 1。容易错在：度=1，候选元素只有 1，跨度 1-0+1=1。若代码把 `ans` 初始化为 0 或忘记 `+1`，会返回 0。
2. **输入 `[1,2,3,4]`** → 期望 1。所有元素频数都是 1，度=1，每个元素跨度都是 1。容易错在：误以为「度=1 时答案就是 n」，其实每个单元素子数组度都是 1，最短是 1。
3. **输入 `[1,2,2,3,1,4,2]`** → 期望 6。度=3（元素 2），跨度 last[2]-first[2]+1 = 6-1+1 = 6。容易错在：看到元素 1 跨度 5-0+1=5 更短就想选它，但 1 的频数是 2 ≠ 度 3，必须被排除——这正是「只对 c==degree 的元素算跨度」的意义。
4. **输入 `[2,1,1,2,1,3,3,3,3]`** → 期望 6。度=4（元素 3），跨度 8-5+1=4？等等，元素 3 出现在下标 5,6,7,8，跨度 4。元素 1 频数 3、元素 2 频数 2，都不是度。答案应为 4。容易错在：只盯着数组开头的高频元素，忘了后面才出现的元素也可能是度最大者。
5. **输入 `[1,1,2,2]`** → 期望 2。度=2，元素 1 跨度 2、元素 2 跨度 2，取 min 仍是 2。容易错在：以为要返回「所有候选跨度之和」或「第一个候选的跨度」，其实取最小即可，两个候选相等时结果不变。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回最短子数组本身（下标区间）而不是长度？** 思路：在第二段循环里同时记录 `best_x`，最后返回 `(first[best_x], last[best_x])`；若多个候选跨度相同，按题目约定取任意一个即可，需和面试官确认 tie-break 规则。
2. **追问：如果数组元素范围很大（比如到 10⁹）或含负数，字典方案还成立吗？** 思路：完全成立，哈希表不依赖值域；若值域小（如本题 0~49999）可改用数组代替字典，常数更小但空间固定为 50000，需权衡。
3. **追问：如果「度」定义为出现次数严格大于 1 的最大频数，没有重复元素时返回什么？** 思路：此时度不存在，需明确返回 0 或 -1（取决于约定）；代码上在 `max` 前加判断 `if max(count.values()) == 1: return 0`。
