## 1. 一句话本质

枚举表达式所有可能的**加括号方式**，每种方式对应一棵不同的运算树，求所有树根节点的值。

---

## 2. 读完题的第一反应

**朴素解法**：枚举所有加括号方式。但"加括号方式"的数量是卡特兰数级别——n 个运算符有 Catalan(n) 种括号化方案，n=10 时已经是 16796 种，虽然本题 n≤10 勉强能过，但枚举括号本身写起来极其别扭，而且大量子表达式被重复计算。

**关键观察**：任何一个加括号方案，最后一步一定是"选某个运算符作为整棵树的根，左边子串算出一个值，右边子串算出一个值，两者做这个运算符"。比如 `2*3-4*5`，最后一步可能是：

- 以第一个 `*` 为根：左 `2`，右 `3-4*5` 的所有值
- 以 `-` 为根：左 `2*3` 的所有值，右 `4*5` 的所有值
- 以第二个 `*` 为根：左 `2*3-4` 的所有值，右 `5`

这就把"枚举括号"转化成了"枚举根运算符 + 递归求左右子串的所有值"，是标准的**分治**结构。而子串会被反复用到（比如 `3-4` 在多个方案里出现），所以加**记忆化**。

---

## 3. 从暴力到最优

**第一步：纯递归分治**

对字符串 `expression`，扫描每个运算符，以它为根切开：

```
solve(s):
    if s 是纯数字: return [int(s)]
    res = []
    for i, ch in enumerate(s):
        if ch in '+-*':
            left_vals  = solve(s[:i])
            right_vals = solve(s[i+1:])
            for a in left_vals:
                for b in right_vals:
                    res.append(apply(a, ch, b))
    return res
```

以 `"2-1-1"` 走一遍：

- 根取第一个 `-`（下标 1）：左 `"2"` → `[2]`，右 `"1-1"` → 递归得 `[0]`，结果 `2-0 = 2`
- 根取第二个 `-`（下标 3）：左 `"2-1"` → `[1]`，右 `"1"` → `[1]`，结果 `1-1 = 0`

返回 `[2, 0]`，和示例一致。

**瓶颈**：`"1-1"` 这个子串在两次递归里被算了两次。更长的表达式里，同一个子串会被指数级重复计算。比如 `"1-1-1-1-1"`，中间的 `"1-1"` 会被不同上层反复调用。

**第二步：记忆化**

用一个字典 `memo`，key 是子串（或子串的起止下标），value 是该子串所有可能的值。递归前先查表，算完写表。这样每个子串只算一次。

以 `"2*3-4*5"` 为例，记忆化后：

| 子串 | 值列表 |
|---|---|
| `"2"` | `[2]` |
| `"3"` | `[3]` |
| `"4"` | `[4]` |
| `"5"` | `[5]` |
| `"3-4"` | `[-1]` |
| `"4*5"` | `[20]` |
| `"3-4*5"` | `[-17]`（`3-20`）和 `[-5]`（`(3-4)*5`）→ `[-17, -5]` |
| `"2*3-4"` | `[2]`（`6-4`）和 `[-2]`（`2*(3-4)`）→ `[2, -2]` |
| 整体 | 见下 |

整体以 `-` 为根：左 `"2*3"`=`[6]`，右 `"4*5"`=`[20]`，得 `-14`；以第一个 `*` 为根：左 `[2]`，右 `[-17,-5]`，得 `-34, -10`；以第二个 `*` 为根：左 `[2,-2]`，右 `[5]`，得 `10, -10`。合并 `[-14, -34, -10, 10, -10]`，与示例一致。

**为什么记忆化能消掉瓶颈**：子问题由"子串"唯一确定，不同括号方案共享同一子串时直接复用结果，把指数级的重复计算压成每个子串算一次。

---

## 4. 正确性：为什么不会漏、不会重

**不变量**：`solve(s)` 返回的列表，恰好是子串 `s` 所有合法加括号方式对应的值（允许重复值，因为不同括号方式可能算出同一个数，题目也允许重复输出，示例 2 里 `-10` 出现两次）。

**不漏**：任取 `s` 的一种合法加括号方案，它对应一棵运算树，树根必是 `s` 中某个运算符 `op`（下标 `i`）。该方案把 `s` 分成左子串 `s[:i]` 和右子串 `s[i+1:]`，左右各自是一种合法加括号方案。由归纳假设，`solve(s[:i])` 和 `solve(s[i+1:])` 分别包含左右的值，外层双重循环枚举所有组合，必然产出这个方案的值。所以不漏。

**不重**：每个方案唯一确定"根运算符下标 `i`"和"左右子方案"。外层循环按 `i` 分组，组内按左右值组合枚举，不同 `(i, 左方案, 右方案)` 三元组对应不同方案，不会把同一方案算两次。注意：**不同方案算出相同数值是允许的**，这不是"重"，是题目要求保留的（示例 2 的 `-10` 两次）。

**记忆化的正确性**：`solve(s)` 的返回值只依赖 `s` 本身，与调用它的上下文无关，所以缓存安全。

## 5. 完整代码（Python）

```python
class Solution:
    def diffWaysToCompute(self, expression: str) -> list[int]:
        memo = {}  # key: 子串, value: 该子串所有可能的计算结果

        def solve(s: str) -> list[int]:
            if s in memo:
                return memo[s]

            res = []
            is_number = True  # 假设整串是数字，扫描中若遇运算符则否定

            for i, ch in enumerate(s):
                if ch in '+-*':
                    is_number = False
                    # 以 s[i] 为根，分治左右
                    left_vals = solve(s[:i])
                    right_vals = solve(s[i + 1:])
                    for a in left_vals:
                        for b in right_vals:
                            if ch == '+':
                                res.append(a + b)
                            elif ch == '-':
                                res.append(a - b)
                            else:
                                res.append(a * b)

            if is_number:
                # 没有运算符，整串是一个数（题面保证无前导符号，直接转 int）
                res.append(int(s))

            memo[s] = res
            return res

        return solve(expression)
```

关键逻辑说明：

- `is_number` 标志：扫描完没有任何运算符，说明是纯数字叶子，直接返回 `[int(s)]`。这是递归的**基例**，不能漏。
- 外层 `for i, ch` 枚举根运算符，内层双重循环做笛卡尔积，把左右所有值两两组合。
- `memo` 在函数入口查、出口写，保证每个子串只算一次。

## 6. 复杂度

设表达式长度为 `n`（本题 `n ≤ 20`），运算符个数为 `m`（`m ≤ 10`），每个子串的结果数最多为 `C`（题面保证不同结果数 ≤ 10^4，但实际远小于此）。

**时间**：子串由起止下标确定，共 `O(n^2)` 个不同子串。对每个子串，枚举根运算符 `O(n)`，每个根做左右笛卡尔积 `O(C^2)`。所以总时间 `O(n^3 · C^2)`。其中 `n^3` 来自"子串数 `n^2` × 每个子串扫运算符 `n`"，`C^2` 来自左右值列表的两两组合。本题规模下 `n^3` 很小，`C` 也受约束，实际很快。

**空间**：`memo` 存 `O(n^2)` 个子串，每个子串存最多 `C` 个值，共 `O(n^2 · C)`。递归栈深度最多 `O(m)`（每次至少切掉一个运算符），即 `O(n)`。合计 `O(n^2 · C)`。

注意：这里没有 `log n` 项，因为不涉及排序或二分；`n` 的幂次全部来自"子串枚举"和"运算符扫描"。

## 7. 边界与反例（至少 4 条）

1. **输入 `"2"`** → 期望 `[2]` → 容易错：忘记处理"整串无运算符"的基例，返回空列表。代码里 `is_number` 就是防这个。

2. **输入 `"0"`** → 期望 `[0]` → 容易错：把 `0` 当成"没有结果"或误判为空串。`int("0")` 正常返回 0，但若用 `if not s` 判空会误伤。

3. **输入 `"2-1-1"`** → 期望 `[0, 2]`（顺序任意）→ 容易错：只按从左到右算得 `[0]`，漏掉右结合方案 `2-(1-1)=2`。必须枚举每个运算符当根。

4. **输入 `"2*3-4*5"`** → 期望含两个 `-10` → 容易错：用 `set` 去重，把重复的 `-10` 删成一个。题目要求保留所有方案的值，**不能去重**。

5. **输入 `"1+1+1+1"`** → 期望 `[4,4,4,4,4]`（5 种括号方式都等于 4）→ 容易错：以为"结果相同就只输出一次"。实际要输出 5 个 4，因为 5 种括号方案各产出一个值。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求输出去重后的结果集，怎么改？** 思路：把 `res` 换成 `set`，或最后 `list(set(res))`；注意这会改变复杂度里 `C` 的含义（去重后 `C` 变小）。

2. **追问：表达式里出现括号或除法怎么办？** 思路：括号需要先做词法/语法解析（或递归下降），除法要处理整除与除零；分治骨架不变，只是"根运算符"的切分要跳过括号内的运算符。

3. **追问：只求"有多少种不同的计算结果"而不是列出所有值？** 思路：仍用记忆化分治，但每个子串存 `set` 而非 `list`，最后返回 `len`；这等价于把 `C` 压到去重后的大小。
