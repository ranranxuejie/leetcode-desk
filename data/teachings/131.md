## 1. 一句话本质

把字符串切成若干段，要求每段都是回文，枚举出**所有**切法——本质是在「切点序列」这棵决策树上做穷举，而回文判断是剪枝条件。

## 2. 读完题的第一反应

**朴素解法**：枚举所有 $2^{n-1}$ 种切法（每个相邻字符间隙「切/不切」），对每种切法逐段检查是否回文。检查一段回文最坏 $O(n)$，总复杂度 $O(2^{n-1} \cdot n)$。$n=16$ 时 $2^{15}=32768$，乘上 $n$ 也就五十万级别——其实**能过**。所以这道题真正的难点不是「超时」，而是「怎么把穷举写对、写清楚」。

**关键观察**：切法不是任意枚举的，它天然是**从左往右逐段确定**的：先定第一段的右端点，再在剩余后缀上递归。这正好对应回溯的「做选择 → 递归 → 撤销选择」。而「这一段是不是回文」这个判断会被反复用到（同一个子串 `s[i:j]` 在搜索树的不同分支里可能被查多次），于是引出两个可优化点：

1. 回文判断能不能 $O(1)$ 拿到？→ 预处理 `dp[i][j]` 表示 `s[i:j]` 是否回文，$O(n^2)$ 打表。
2. 搜索本身能不能少走？→ 不能，因为题目要**所有**方案，输出规模本身就是答案的一部分，搜索树必须走完所有合法叶子。

所以本题的「最优」= 回溯枚举 + $O(1)$ 回文查询，而不是某种多项式算法。

## 3. 从暴力到最优

以 `s = "aab"` 走一遍。

**第一步：朴素枚举切法。** 间隙有两个（`a|a|b` 位置），共 4 种：

| 切法 | 分段 | 是否全回文 |
|---|---|---|
| 不切 | `["aab"]` | `aab` 不是回文 ✗ |
| 切第 1 个 | `["a","ab"]` | `ab` 不是 ✗ |
| 切第 2 个 | `["aa","b"]` | ✓ |
| 都切 | `["a","a","b"]` | ✓ |

得到答案。但注意：这种枚举方式**先产生完整切法再验证**，验证失败时前面已经做的判断全浪费了。比如「切第 1 个」这条分支，一旦发现 `ab` 不是回文，后面根本不用看——可枚举法已经把它算完了。

**第二步：改成逐段生长（回溯）。** 从位置 `start=0` 出发，枚举第一段右端点 `end`：

- `end=0`：段 `"a"` 是回文 → 递归 `start=1`，路径 `["a"]`
  - `start=1`，`end=1`：段 `"a"` 回文 → 递归 `start=2`，路径 `["a","a"]`
    - `start=2`，`end=2`：段 `"b"` 回文 → `start=3` 到达末尾，**记录** `["a","a","b"]`
  - `start=1`，`end=2`：段 `"ab"` 非回文 → **剪掉**，不再深入
- `end=1`：段 `"aa"` 是回文 → 递归 `start=2`，路径 `["aa"]`
  - `start=2`，`end=2`：段 `"b"` 回文 → 到达末尾，**记录** `["aa","b"]`
- `end=2`：段 `"aab"` 非回文 → 剪掉

对比一下：朴素法在「`a` + `ab`」这条路上要等整条切法生成完才发现 `ab` 非法；回溯法在 `end=2` 处**当场**判定 `"ab"` 非回文就回头，省掉了它后面所有展开。这就是「剪枝发生在决策点」带来的收益——虽然最坏复杂度没变（答案多的时候本来就要走这么多），但无效分支被提前掐死。

**第三步：把回文判断降到 $O(1)$。** 上面每次判断 `s[start:end+1]` 是否回文，切片 + 反转是 $O(\text{长度})$。用区间 DP 预处理：

`dp[i][j] = (s[i] == s[j]) and (j - i <= 2 or dp[i+1][j-1])`

对 `"aab"` 打表（只列 $i \le j$）：

- `dp[0][0]=T`，`dp[1][1]=T`，`dp[2][2]=T`（单字符）
- `dp[0][1]`：`s[0]==s[1]`（`a==a`）且长度 2 → `T`，即 `"aa"` 回文
- `dp[1][2]`：`s[1]!=s[2]`（`a!=b`）→ `F`
- `dp[0][2]`：`s[0]!=s[2]`（`a!=b`）→ `F`

之后回溯里每次查表 $O(1)$。$n=16$ 时这点优化感知不强，但它是这类题的标准配套，且面试官常追问。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在递归进入 `dfs(start)` 时，`path` 中已存的每一段都是回文，且这些段按顺序**恰好拼成** `s[0:start]`。

- 初始 `start=0`，`path` 为空，拼成空串 = `s[0:0]`，成立。
- 归纳步：在 `dfs(start)` 中枚举 `end ∈ [start, n-1]`，只对 `dp[start][end]` 为真的段递归。此时新段 `s[start:end+1]` 是回文，且 `path + [该段]` 拼成 `s[0:end+1]`，进入 `dfs(end+1)` 时不变量保持。
- 终止：`start == n` 时 `path` 拼成 `s[0:n] = s`，且每段回文，是一个合法方案，记录。

**不漏**：任取一个合法方案，它的第一段必是 `s[0:k]` 且回文，对应 `end=k-1` 这个分支，该分支一定被枚举到（`end` 遍历了所有可能）。对剩余后缀归纳，方案必被走到。

**不重**：一个方案由「切点序列」唯一确定，而切点序列与「每层选的 `end`」一一对应。搜索树中每个节点对应唯一的前缀切法，不同叶子对应不同切点序列，故不会重复记录。

**剪枝不丢解**：只跳过 `dp[start][end]` 为假的分支，而任何合法方案的第一段都必须回文，所以被跳过的分支里不可能有合法方案。

## 5. 完整代码（Python）

```python
from typing import List


class Solution:
    def partition(self, s: str) -> List[List[str]]:
        n = len(s)

        # 预处理：dp[i][j] 表示 s[i:j+1] 是否为回文（闭区间）
        # 按区间长度从小到大填，保证 dp[i+1][j-1] 已算好
        dp = [[False] * n for _ in range(n)]
        for i in range(n):
            dp[i][i] = True                      # 单字符必回文
        for length in range(2, n + 1):           # 区间长度 2..n
            for i in range(n - length + 1):
                j = i + length - 1
                if s[i] == s[j]:
                    # 长度 <= 2 时无需看内部；否则看内层
                    dp[i][j] = (length <= 2) or dp[i + 1][j - 1]

        res = []
        path = []

        def dfs(start: int) -> None:
            if start == n:                       # 切到末尾，path 是一个完整方案
                res.append(path[:])              # 必须拷贝，path 后续会被修改
                return
            for end in range(start, n):          # 枚举当前段的右端点
                if not dp[start][end]:           # 非回文，剪枝
                    continue
                path.append(s[start:end + 1])    # 做选择
                dfs(end + 1)                     # 在剩余后缀上递归
                path.pop()                       # 撤销选择

        dfs(0)
        return res
```

## 6. 复杂度

设 $n = |s|$。

**时间**：$O(n \cdot 2^n)$。

- 预处理 DP：两层循环，区间长度 $n$ 种 × 起点约 $n$ 种，$O(n^2)$。
- 回溯：搜索树的叶子数等于合法方案数，最坏情况（如 `"aaaa..."` 全同字符）方案数为 $2^{n-1}$ 量级；每个叶子记录时拷贝 `path` 长度最多 $n$，故 $O(n \cdot 2^n)$。这是**输出规模决定的下界**，无法更优。

**空间**：$O(n^2)$。

- `dp` 表 $n \times n$，$O(n^2)$。
- 递归栈深度最多 $n$（每层至少切一个字符），$O(n)$。
- `path` 最多 $n$ 段，$O(n)$。
- 结果集不计入（属于输出）。

## 7. 边界与反例（至少 4 条）

1. **输入 `"a"`** → 期望 `[["a"]]`。易错点：`dfs` 的终止条件写成 `start >= n - 1` 会漏掉最后一段；或 `dp` 只初始化对角线却忘了长度 1 的循环边界。
2. **输入 `"ab"`** → 期望 `[["a","b"]]`。易错点：`"ab"` 整体非回文，若 `dp` 填表时把 `length <= 2` 且 `s[i]==s[j]` 的条件写反（比如漏了 `s[i]==s[j]` 判断），会误判 `"ab"` 为回文，多出 `[["ab"]]`。
3. **输入 `"aaaa"`** → 期望 8 种方案（每个间隙独立切/不切）。易错点：`res.append(path)` 不拷贝，最后所有结果都指向同一个被清空的列表，输出全是空列表或重复同一份。
4. **输入 `"abcba"`** → 期望 `[["a","b","c","b","a"],["a","bcb","a"],["abcba"]]`。易错点：`dp` 填表顺序若按 `i` 从大到小、`j` 从小到大但没保证 `dp[i+1][j-1]` 先算，会读到未初始化的 `False`，漏掉 `"bcb"` 这类长度 3 的回文。
5. **输入 `"aab"`（官方示例）** → 期望 `[["a","a","b"],["aa","b"]]`。易错点：`end` 循环写成 `range(start+1, n+1)` 配合切片 `s[start:end]` 时，`dp` 索引与切片边界错位一位，导致 `"aa"` 查成 `dp[0][1]` 还是 `dp[0][2]` 搞混。

## 8. 面试追问与变体（3 条）

1. **追问：只要求返回最少切割次数，怎么做？** 思路：把「枚举所有」换成 DP，`f[i] = min(f[j] + 1)` 对所有 `dp[j][i-1]` 为真的 `j`，$O(n^2)$。
2. **追问：不预处理 DP，用中心扩展在回溯里现场判回文，行不行？** 思路：行，单次判断 $O(n)$，总复杂度多一个 $n$ 因子；面试里可以先写这个版本再优化，体现迭代过程。
3. **追问：如果要求每段长度至少为 2，怎么改？** 思路：`end` 从 `start+1` 开始枚举，同时终止条件要保证剩余后缀也能切出长度 ≥2 的段（或允许最后一段例外，需和面试官确认语义）。
