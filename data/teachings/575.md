## 1. 一句话本质

在「最多只能吃 n/2 枚」和「总共只有 k 种糖」这两个上限里，取较小的那个。

## 2. 读完题的第一反应

**朴素解法**：枚举所有大小为 n/2 的子集，对每个子集数一数有多少种不同的糖，取最大值。这卡在组合爆炸上——从 n 枚里选 n/2 枚的方案数是 C(n, n/2)，n=10^4 时是天文数字，完全不可行。即使退一步想「枚举所有可能的种类组合」，种类数最多也是 n，同样爆炸。

**关键观察**：题目问的是「最多能吃到几种」，而不是「具体吃哪几枚」。这两个上限是天然存在的：

- 上限一：她只能吃 n/2 枚糖，所以种类数不可能超过 n/2（一枚糖最多贡献一种）。
- 上限二：数组里总共只有 k 种不同的糖，所以种类数不可能超过 k。

于是答案就是 `min(n/2, k)`。这个观察之所以能直接给出答案，是因为**这两个上限可以同时达到**——只要 k ≥ n/2，我们就能从每种糖里挑一枚凑够 n/2 枚；只要 k < n/2，我们就能把每种糖都吃一遍（每种至少一枚），总数不超过 n/2。所以不是「上界」，而是「可达的上界」。

## 3. 从暴力到最优

**第一步：暴力枚举子集。** 瓶颈是 C(n, n/2) 种选法，每种选法还要 O(n/2) 去重，总复杂度指数级。消不掉。

**第二步：换个问法。** 不问「选哪些」，而问「答案的上界是什么」。这一步把「搜索问题」变成了「计数问题」——我们只需要知道数组里有多少种不同的糖，不需要知道怎么选。

**第三步：数种类。** 用集合去重，`len(set(candyType))` 就是 k。答案 `min(n//2, k)`。

**小例子走一遍**：`candyType = [1,1,2,3]`，n=4。

- 第一步：n//2 = 2，她只能吃 2 枚。
- 第二步：`set([1,1,2,3]) = {1,2,3}`，k = 3 种。
- 第三步：min(2, 3) = 2。答案 2。

对照示例 2 的解释：不管选 [1,2]、[1,3] 还是 [2,3]，都只能吃到 2 种——因为枚数上限 2 先卡住了，种类上限 3 没起作用。

再看 `[6,6,6,6]`：n//2 = 2，k = 1，min(2,1) = 1。这次是种类上限卡住了，枚数上限 2 没起作用。

两个例子分别展示了两个上限各自成为瓶颈的情况，这正是 min 的含义。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。设答案为 A，我们要证明 A = min(n/2, k)。

**上界（A ≤ min(n/2, k)）**：Alice 吃的糖不超过 n/2 枚，每枚糖至多贡献一种，所以不同种类数 ≤ n/2；同时所有糖总共只有 k 种，吃到的种类数不可能超过 k。两条都成立，故 A ≤ min(n/2, k)。

**可达性（A ≥ min(n/2, k)）**：分两种情况构造。

- 若 k ≥ n/2：从每种糖里各取一枚，取 n/2 种不同的糖（因为 k ≥ n/2，种类够用），得到 n/2 枚、n/2 种，达到上界。
- 若 k < n/2：把每种糖各取一枚，共 k 枚，k ≤ n/2 满足「不超过 n/2 枚」的约束，得到 k 种，达到上界。

两种情况都构造出了达到上界的吃法，所以 A = min(n/2, k)。这里没有「漏」的问题，因为我们证明的是上界可达；也没有「重」的问题，因为集合去重天然保证 k 是精确的不同种类数。

## 5. 完整代码（Python）

```python
class Solution:
    def distributeCandies(self, candyType: list[int]) -> int:
        n = len(candyType)          # 糖的总数，题面保证是偶数
        max_eat = n // 2            # 医生允许吃的枚数上限
        kinds = len(set(candyType)) # 数组里实际有多少种不同的糖
        return min(max_eat, kinds)  # 两个上限取小，即为可达的最大种类数
```

关键逻辑只有三行：算枚数上限、算种类数、取 min。`set` 负责去重，`len` 负责计数，`min` 负责在两个约束里取紧的那个。

## 6. 复杂度

- **时间 O(n)**：`set(candyType)` 要遍历数组一次，每个元素做一次哈希插入，平均 O(1)，共 O(n)；`len` 和 `min` 都是 O(1)。n 来自数组长度。
- **空间 O(k)**：集合里最多存 k 个不同元素，k ≤ n，最坏 O(n)。这里没有 log n 的项——没有排序、没有二分，所以不出现对数因子。

对比一下：如果先 `sorted` 再去重，时间会变成 O(n log n)，log n 就来自排序的比较次数。本题不需要有序，所以用哈希集合而不是排序。

## 7. 边界与反例（至少 4 条）

1. **全部相同**：`[6,6,6,6]` → 期望 1。容易错在只算 n/2=2 就返回 2，忘了种类上限 k=1 更紧。
2. **全部不同**：`[1,2,3,4]` → 期望 2。容易错在返回 k=4，忘了她只能吃 2 枚，枚数上限更紧。
3. **种类数恰好等于 n/2**：`[1,1,2,2,3,3]` → 期望 3。两个上限相等，min 取谁都对，但容易在「k ≥ n/2 还是 k > n/2」的边界判断上写错分支。
4. **n=2 的最小规模**：`[1,2]` → 期望 1。n//2=1，k=2，min=1。容易错在把 n/2 当成浮点算出 1.0 再比较，或忘记 n 最小是 2 这个约束。
5. **负数类型值**：`[-1,-1,2,2]` → 期望 2。类型值是负数不影响集合去重，但若有人用「值当数组下标」的计数法会越界，这是选错数据结构导致的错。

## 8. 面试追问与变体（3 条）

1. **追问：如果医生要求吃「至少」n/2 枚而不是恰好 n/2 枚，答案变吗？** 不变。吃更多枚不会减少种类数，最优仍是 min(n/2, k)，因为多吃只能让枚数上限放松，但种类上限 k 依然卡着。
2. **追问：如果要求「每种糖最多吃一枚」，答案变吗？** 不变，因为我们的构造本来就是每种取一枚，恰好满足这个额外约束。
3. **追问：如果要返回具体吃哪 n/2 枚，怎么构造？** 先按种类分组，若 k ≥ n/2 就取前 n/2 种各一枚；若 k < n/2 就每种取一枚再随便补重复的凑够 n/2 枚。思路是把「取 min」的证明过程直接翻译成构造。

2. **力扣 1207. 独一无二的出现次数**：先统计频次再对频次去重，共同点是「用集合判断不同值的个数」这一核心动作。
