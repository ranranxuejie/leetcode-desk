## 1. 一句话本质

在一个有序的候选区间 `[1, n]` 里，用 `guess()` 返回的「大了/小了」作为比较信号，把目标数定位到唯一一个值——这就是把「猜数」翻译成「在有序数组里找 target」的二分查找。

## 2. 读完题的第一反应

**朴素解法**：从 1 开始逐个猜，猜 `1, 2, 3, ...` 直到 `guess` 返回 0。最坏情况 pick = n，要猜 n 次，每次调用 `guess` 是一次交互，复杂度 O(n)。n 最大到 2^31 - 1，逐个猜显然过不了。

**关键观察**：`guess(num)` 的返回值不是「对/错」这种二元信息，而是三元的——它告诉你 `num` 和 pick 的相对大小。这意味着每次猜完，你都能**排除掉一整段区间**：如果 `guess(mid) == -1`，说明 `mid > pick`，那么 `[mid, n]` 全部不可能是答案；如果返回 `1`，说明 `mid < pick`，那么 `[1, mid]` 全部排除。

这个「一次比较能砍掉一半候选」的性质，正是二分查找的触发条件。题目里「1 到 n 随机选一个」其实是个幌子——pick 是固定的，候选集合始终是一个连续整数区间，且区间内每个数都「有序」地对应着大小关系，二分的前提完全满足。

## 3. 从暴力到最优

**第一步：线性扫描。** 维护 `x = 1`，每次 `guess(x)`，返回 0 就结束，返回 1 就 `x += 1`。瓶颈：最坏 O(n) 次交互。

**第二步：二分。** 维护一个闭区间 `[lo, hi]`，表示「答案一定在这个区间内」。每次取中点 `mid = (lo + hi) // 2`，调用 `guess(mid)`：

- 返回 0：`mid` 就是答案，直接返回。
- 返回 -1（`mid > pick`）：答案在 `[lo, mid - 1]`，令 `hi = mid - 1`。
- 返回 1（`mid < pick`）：答案在 `[mid + 1, hi]`，令 `lo = mid + 1`。

每次区间长度大约减半，最多 log₂n 次交互。

**小例子走一遍**：n = 10, pick = 6。

| 轮次 | lo | hi | mid | guess(mid) | 动作 |
|---|---|---|---|---|---|
| 1 | 1 | 10 | 5 | 1（5 < 6） | lo = 6 |
| 2 | 6 | 10 | 8 | -1（8 > 6） | hi = 7 |
| 3 | 6 | 7 | 6 | 0 | 返回 6 |

三轮结束，区间从长度 10 缩到命中。对比线性扫描要猜 6 次，二分 3 次。

**第三步：为什么不用 `while lo < hi` 那种写法？** 两种写法都对，但闭区间 `while lo <= hi` 的循环不变量更直观（见第 4 节），且天然处理 n = 1 的情况：lo = hi = 1，mid = 1，一次 guess 就返回。这里选闭区间写法，因为它对「区间内一定含答案」的表述最干净。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**论证。定义不变量：

> 每次循环开始时，pick ∈ [lo, hi]。

**初始化**：lo = 1, hi = n，题面保证 1 ≤ pick ≤ n，不变量成立。

**保持**：设某轮 mid = (lo + hi) // 2，由不变量 pick ∈ [lo, hi]，故 lo ≤ mid ≤ hi。

- 若 `guess(mid) == -1`，题面定义 num > pick，即 mid > pick，所以 pick ≤ mid - 1，新区间 `[lo, mid-1]` 仍含 pick。
- 若 `guess(mid) == 1`，即 mid < pick，所以 pick ≥ mid + 1，新区间 `[mid+1, hi]` 仍含 pick。
- 若返回 0，直接返回 mid，正确。

三种情况覆盖了 `guess` 的全部返回值，且每种情况下新区间都保持不变量。

**终止**：每轮区间长度严格减小（mid 被排除或直接命中），且 lo ≤ hi 时 mid 一定落在区间内，所以循环必然终止。终止时若没提前返回，说明 lo > hi，但由不变量 pick ∈ [lo, hi] 要求 lo ≤ pick ≤ hi，与 lo > hi 矛盾——因此循环内一定会命中并返回，不会「漏掉」答案。

**不会重**：每次排除的都是 `mid` 及其一侧，新区间与旧区间的关系是「旧区间 = 新区间 ∪ 被排除部分」，被排除部分不含 pick，所以 pick 只可能落在新区间里，不会出现「答案被排除后又找回来」的情况。

## 5. 完整代码（Python）

```python
class Solution:
    def guessNumber(self, n: int, pick: int) -> int:
        # 本地模拟题目提供的 guess 接口：pick 作为闭包变量传入
        def guess(num: int) -> int:
            if num > pick:
                return -1   # 猜大了
            if num < pick:
                return 1    # 猜小了
            return 0        # 猜中

        lo, hi = 1, n       # 闭区间 [lo, hi]，不变量：pick 始终在此区间内
        while lo <= hi:
            mid = (lo + hi) // 2   # 取中点；Python 整数无溢出问题
            res = guess(mid)
            if res == 0:
                return mid          # 命中，直接返回
            elif res == -1:
                hi = mid - 1        # mid 太大，答案在左半区
            else:                   # res == 1
                lo = mid + 1        # mid 太小，答案在右半区
        # 理论上不可达：不变量保证循环内必命中
        return -1
```

> 说明：力扣原题里 `guess` 是平台预置的全局接口，函数签名写作 `guessNumber(self, n)`。本题给定的签名是 `guessNumber(n, pick)`，所以代码里用闭包把 `pick` 包成 `guess`，逻辑与线上完全一致，可直接运行。

## 6. 复杂度

**时间**：O(log n)。来源是循环次数——每轮区间长度从 L 变为约 L/2（最坏情况 mid 落在端点附近时减 1，但均摊仍是减半），从 n 缩到 1 需要 ⌈log₂n⌉ 轮，每轮做一次 `guess` 调用和 O(1) 的算术比较。n 贡献的是「区间初始长度」，log n 贡献的是「减半次数」。

**空间**：O(1)。只用了 `lo, hi, mid, res` 四个整型变量，没有递归、没有额外数组。注意 `guess` 闭包捕获 `pick` 是 O(1) 的。

## 7. 边界与反例（至少 4 条）

1. **n = 1, pick = 1** → 期望 1。容易错在写成 `while lo < hi` 且初始化 `hi = n` 后不处理单元素，或 mid 计算后直接 `lo = mid` 造成死循环。闭区间 `lo <= hi` 写法下一轮即命中。

2. **n = 2, pick = 1** → 期望 1。mid = (1+2)//2 = 1，`guess(1) == 0` 直接返回。容易错在 mid 取 `(lo+hi+1)//2` 时 mid = 2，`guess(2) == -1`，`hi = 1`，下一轮 mid = 1 命中——两种取整都对，但混用 `lo = mid` / `hi = mid` 的写法容易死循环。

3. **pick = n（最大值）** → 期望 n。例如 n = 10, pick = 10。二分过程中 `guess` 一直返回 1，lo 不断右移，最后 lo = hi = 10 命中。容易错在把 `res == 1` 的分支写成 `hi = mid`（方向反了），导致区间不收缩。

4. **pick = 1（最小值）** → 期望 1。`guess` 一直返回 -1，hi 不断左移。容易错在 `hi = mid` 而非 `hi = mid - 1`，当 lo = hi 时 mid = lo，若 `guess(mid) == -1` 则 hi 不变，死循环。

5. **n = 2^31 - 1** → 期望任意合法 pick。容易错在 C/Java 里 `(lo + hi) / 2` 溢出；Python 无此问题，但若移植到其他语言需写 `lo + (hi - lo) // 2`。

## 8. 面试追问与变体（3 条）

1. **追问：如果 `guess` 的返回值语义反过来（-1 表示猜小了）怎么办？** 思路：只需交换两个分支的赋值，或统一在入口处对返回值取反，核心不变量不变。

2. **追问：如果允许「猜错但接近」有额外反馈（比如返回距离）呢？** 思路：这就超出了二分的比较模型，需要看反馈是否单调；若反馈只是三元比较，二分仍是最优；若反馈是距离，可考虑插值查找，但最坏复杂度仍退化到 O(n)。

3. **追问：如何证明二分是交互次数最少的？** 思路：每次 `guess` 最多三种结果，信息论下界是 ⌈log₃n⌉ 次；但本题实际只有「大/小/中」且「中」即终止，有效比较是二元的，下界为 ⌈log₂n⌉，二分达到该下界，故最优。
