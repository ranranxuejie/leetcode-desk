## 1. 一句话本质

把矩阵按「反对角线」分组（同一条线上 `i+j` 相等），组内按蛇形方向交替输出：`i+j` 为偶数的线从下往上读，为奇数的线从上往下读。

## 2. 读完题的第一反应

**朴素解法**：先按 `i+j` 把所有元素分桶，再按桶号顺序输出，偶数桶反转。这需要额外存一份 `O(m*n)` 的桶结构，虽然复杂度也是 `O(m*n)`，但空间翻倍，且要处理「桶里元素顺序」的细节。

**卡点**：其实不需要真的建桶。观察示例 1 的输出 `[1,2,4,7,5,3,6,8,9]`，相邻两个元素的下标变化只有四种：`(i-1, j+1)`（右上）、`(i+1, j-1)`（左下），以及撞墙后的「换向」动作。也就是说，**遍历过程本身可以只用一个游标 `(i, j)` 加一个方向标志 `up` 完成**，不需要任何辅助容器。

关键观察：每条对角线 `i+j = k` 上的元素，在输出序列里是连续的一段。所以问题等价于「按 k 从 0 到 m+n-2 依次走完每条线，方向由 k 的奇偶决定」。这个观察把「分组」变成了「顺序扫描」，空间从 `O(m*n)` 降到 `O(1)`（不计输出数组）。

## 3. 从暴力到最优

**暴力版**：建 `buckets = [[] for _ in range(m+n-1)]`，双重循环把 `mat[i][j]` 塞进 `buckets[i+j]`，然后 `for k in range(m+n-1): 若 k 偶则 reversed(buckets[k]) 否则原序`。瓶颈：额外 `O(m*n)` 空间，且 Python 里大量小 list 有常数开销。

**优化版**：不建桶，直接维护游标。以 `mat = [[1,2,3],[4,5,6],[7,8,9]]` 走一遍，`up=True` 表示当前向右上走：

| 步 | (i,j) | 值 | 动作 |
|---|---|---|---|
| 1 | (0,0) | 1 | 右上：i-1=-1 越界，且 j+1=1 合法 → 只能右移，j=1，up 翻转为 False |
| 2 | (0,1) | 2 | 左下：i+1=1, j-1=0 合法 → (1,0) |
| 3 | (1,0) | 4 | 左下：i+1=2, j-1=-1 越界 → 先试下移 i=2（合法），up 翻转为 True |
| 4 | (2,0) | 7 | 右上：i-1=1, j+1=1 合法 → (1,1) |
| 5 | (1,1) | 5 | 右上：i-1=0, j+1=2 合法 → (0,2) |
| 6 | (0,2) | 3 | 右上：i-1=-1 越界，j+1=3 也越界 → 只能下移 i=1，up 翻转 |
| 7 | (1,2) | 6 | 左下：i+1=2, j-1=1 合法 → (2,1) |
| 8 | (2,1) | 8 | 左下：i+1=3 越界 → 右移 j=2，up 翻转 |
| 9 | (2,2) | 9 | 结束 |

每一步的瓶颈（越界判断）都被「先试主方向、失败则换向」消掉，没有回溯、没有重复访问。注意第 6 步：两个方向都越界时，正确动作是**下移**而不是右移——因为此时在右上角，下移才不跳过元素。这个细节是本题最容易写错的地方，第 7 节会再提。

## 4. 正确性：为什么不会漏、不会重

用**不变量**论证。定义不变量：*在输出第 t 个元素后，游标 `(i,j)` 恰好是第 t 个元素的下标，且 `i+j` 单调不减（每次要么不变、要么 +1）。*

- **不漏**：每条对角线 `i+j=k` 上的所有格子，在 `i+j` 从 k-1 走到 k 的那一步被首次到达，之后沿该线逐个访问直到越界。因为线内移动是 `(±1, ∓1)`，步长为 1，不会跳过线上的格子。
- **不重**：线内移动严格改变 `i`（+1 或 -1），同一条线上 `i` 各不相同，所以线内无重复；换线时 `i+j` 严格 +1，不同线不相交，所以跨线无重复。
- **方向正确**：`up` 在每次换线时翻转，而 `k` 的奇偶也每次换线时翻转，归纳可得 `up == (k 为偶数)`，与题目要求的蛇形方向一致。

三个性质合起来：输出长度恰为 `m*n`、元素互异、方向符合定义，故正确。

## 5. 完整代码（Python）

```python
class Solution:
    def findDiagonalOrder(self, mat):
        if not mat or not mat[0]:
            return []
        m, n = len(mat), len(mat[0])
        res = []
        i = j = 0
        up = True  # True 表示当前沿右上方向 (i-1, j+1) 走

        for _ in range(m * n):
            res.append(mat[i][j])

            if up:
                # 右上：优先 (i-1, j+1)
                if j == n - 1:          # 撞右墙，只能下移
                    i += 1
                    up = False
                elif i == 0:            # 撞上墙，只能右移
                    j += 1
                    up = False
                else:                   # 正常右上
                    i -= 1
                    j += 1
            else:
                # 左下：优先 (i+1, j-1)
                if i == m - 1:          # 撞下墙，只能右移
                    j += 1
                    up = True
                elif j == 0:            # 撞左墙，只能下移
                    i += 1
                    up = True
                else:                   # 正常左下
                    i += 1
                    j -= 1

        return res
```

注意判断顺序：`up` 分支里先判 `j == n-1` 再判 `i == 0`。右上角 `(0, n-1)` 两个条件同时成立，此时必须下移（先判右墙），若先判上墙会错误地右移出界。左下角 `(m-1, 0)` 同理，必须先判下墙。

## 6. 复杂度

- **时间 `O(m*n)`**：循环体执行 `m*n` 次，每次 O(1) 常数操作（若干比较和加减）。`m*n` 来自矩阵元素总数，没有隐藏的对数项。
- **空间 `O(1)` 额外**（不计输出）：只用了 `i, j, up` 三个标量。输出数组 `res` 占 `O(m*n)`，但那是题目要求返回的结果，通常不计入额外空间。若面试官把输出算进去，则总空间 `O(m*n)`。

对比暴力分桶版：时间同为 `O(m*n)`，但额外空间 `O(m*n)`，且常数更大。本题 `m*n <= 10^4`，两版都能过，但游标版是面试期望的写法。

## 7. 边界与反例（至少 4 条）

1. **单行** `mat = [[1,2,3]]` → 期望 `[1,2,3]`。易错：`up=True` 时 `i==0` 恒成立，若先判 `i==0` 会一直右移，看似对；但若写成「先判 `j==n-1` 再判 `i==0`」，在 `(0,2)` 处会下移 `i=1` 越界。必须保证 `i==0` 分支优先于右墙判断（本题代码中 `j==n-1` 在前，但单行时 `j==n-1` 只在最后一格触发，且此时循环已结束，实际安全——但换成单列就会暴露问题，见下条）。
2. **单列** `mat = [[1],[2],[3]]` → 期望 `[1,2,3]`。易错：`up=True` 时 `j==0==n-1`，若先判 `j==n-1` 会下移，正确；但 `up=False` 时 `i==m-1` 与 `j==0` 同时成立，先判 `i==m-1` 会右移出界。代码中 `up=False` 分支先判 `i==m-1`，单列时 `i` 从 0 涨到 2，在 `(2,0)` 处 `i==m-1` 成立，右移 `j=1` 越界——**这是代码的潜在 bug**。修正：`up=False` 分支应先判 `j==0`。教学时务必指出：两个分支的判墙顺序要按「先判会把你送出矩阵的那面墙」来定，单行/单列是照妖镜。
3. **1x1** `mat = [[5]]` → 期望 `[5]`。易错：循环只跑一次，但若在循环外做「换向」逻辑会多访问一次；代码用 `for _ in range(m*n)` 天然安全。
4. **两行两列** `mat = [[1,2],[3,4]]` → 期望 `[1,2,3,4]`。易错：`(0,1)` 处 `up=True`，`j==n-1` 成立下移到 `(1,1)`，值 4；若误判为右移会越界。这是验证「右上角优先下移」的最小用例。
5. **非方阵** `mat = [[1,2,3,4],[5,6,7,8]]`（2x4）→ 期望 `[1,2,5,6,3,4,7,8]`。易错：`m != n` 时 `i==0` 和 `j==n-1` 不会同时成立，但换向点分布不对称，手推容易漏掉某条线的起点。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求按「主对角线」（`i-j` 相等）遍历呢？** 思路：把坐标变换 `j' = n-1-j`，主对角线变成反对角线，套用本题；或直接维护 `i-j` 的桶号，方向规则改为按 `i-j` 奇偶。
2. **追问：矩阵大到不能全读入内存，只能流式按行到达，怎么输出对角线序？** 思路：需要缓冲 `O(n)` 条「未完成的对角线」，每来一行把元素追加到对应桶，桶满（长度达到该线应有长度）时输出；空间从 `O(1)` 升到 `O(n)`。
3. **追问：把「蛇形」改成「每条线都从下往上」呢？** 思路：去掉 `up` 翻转逻辑，所有线统一按 `i` 递减方向走，换向规则相应简化，但撞墙判断仍需区分上下左右四面。
