## 1. 一句话本质

在数组里挑出一个**下标递增、值也严格递增**的最长子序列，求这个子序列的长度（不要求连续，也不要求唯一）。

## 2. 读完题的第一反应

**朴素解法**：枚举所有子序列，判断是否递增，取最长。子序列有 $2^n$ 个，$n=2500$ 时完全不可行——瓶颈在「枚举」这一步，是指数级的。

退一步，用「以每个位置结尾」来组织状态：设 `dp[i]` 表示**以 `nums[i]` 结尾**的最长递增子序列长度。转移时回头看所有 `j < i`，若 `nums[j] < nums[i]`，就能把 `nums[i]` 接在 `dp[j]` 后面：

$$dp[i] = 1 + \max_{j<i,\ nums[j]<nums[i]} dp[j]$$

这是 $O(n^2)$，$n=2500$ 时约 625 万次操作，能过。但题目「进阶」明确要求 $O(n\log n)$，说明出题人希望你看到第二层。

**关键观察**：上面转移里，我们真正关心的不是「哪个 `j`」，而是「在所有长度为 $L$ 的递增子序列里，结尾最小能是多少」。结尾越小，后面越容易接上新元素。于是可以只维护一个数组 `tails`，`tails[L]` = 长度为 `L+1` 的递增子序列的**最小可能结尾值**。这个数组天然是**严格递增**的（长度更长的子序列，结尾不可能更小），所以可以用二分查找定位新元素该放在哪。

## 3. 从暴力到最优

**第一步：$O(n^2)$ DP。** 以示例 1 `[10,9,2,5,3,7,101,18]` 走一遍：

| i | nums[i] | 可接的 j（nums[j]<nums[i]） | dp[i] |
|---|---|---|---|
| 0 | 10 | 无 | 1 |
| 1 | 9 | 无 | 1 |
| 2 | 2 | 无 | 1 |
| 3 | 5 | j=2 (2) | 2 |
| 4 | 3 | j=2 (2) | 2 |
| 5 | 7 | j=2,3,4 → max dp=2 | 3 |
| 6 | 101 | j=0..5 → max dp=3 | 4 |
| 7 | 18 | j=0..5 → max dp=3 | 4 |

答案 4。瓶颈：每个 `i` 都要扫一遍前面所有 `j`，$O(n^2)$。

**第二步：换成 `tails` 视角。** 同样走示例 1，`tails` 初始为空：

- `10`：`tails` 空，直接追加 → `[10]`
- `9`：9 比 10 小，**替换** 10（长度为 1 的子序列，结尾最小可以是 9）→ `[9]`
- `2`：替换 9 → `[2]`
- `5`：5 > 2，**追加** → `[2, 5]`
- `3`：3 在 `[2,5]` 中，替换 5（长度 2 的子序列结尾最小可以是 3）→ `[2, 3]`
- `7`：追加 → `[2, 3, 7]`
- `101`：追加 → `[2, 3, 7, 101]`
- `18`：18 落在 7 和 101 之间，替换 101 → `[2, 3, 7, 18]`

最终 `tails` 长度 = 4，就是答案。

注意两个细节，它们是这道题最容易错的地方：

1. **替换不是「改答案」，是「改潜力」**。`[2,3,7,101]` 变成 `[2,3,7,18]` 时，长度没变，但结尾从 101 降到 18，后面若来个 50 就能接上，来个 200 也照样能接。替换只会让未来更宽松，不会让答案变差。
2. **`tails` 本身不一定是一个真实存在的子序列**。比如 `[1, 5, 2, 3]` 走完是 `[1, 2, 3]`，恰好真实；但 `[2, 3, 1]` 走完是 `[1, 3]`，而 `[1,3]` 在原数组里下标是 2、1，顺序反了。所以 `tails` 只能用来读**长度**，不能直接当答案序列输出。这是面试官最爱追问的点。

**第三步：二分。** 每来一个 `x`，在 `tails` 里找**第一个 $\ge x$ 的位置**（`bisect_left`），替换它；找不到就追加。因为 `tails` 严格递增，二分 $O(\log n)$，总复杂度 $O(n\log n)$。

为什么是「第一个 $\ge x$」而不是「第一个 $> x$」？因为要求**严格**递增，相等的值不能接在后面，必须替换掉。示例 3 `[7,7,7,7,7,7,7]`：每个 7 都替换位置 0，`tails` 始终是 `[7]`，长度 1，正确。若用 `bisect_right`，会变成 `[7,7,7,...]`，长度 7，错。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。处理完前 `i` 个元素后，维护的不变量是：

> 对每个 $L \ge 1$，`tails[L-1]` 等于「用前 `i` 个元素能构成的、长度为 $L$ 的严格递增子序列」的**最小结尾值**；若不存在这样的子序列，则 `tails` 长度小于 $L$。

**归纳证明**：

- 初始 `i=0`，`tails` 为空，不变量空真。
- 加入 `x = nums[i]`。设 `pos = bisect_left(tails, x)`。
  - 若 `pos == len(tails)`：说明所有已知长度的最小结尾都 $< x$，于是可以接在最长的那条后面，得到长度 `len+1` 的新子序列，且 `x` 是它唯一的结尾，最小性成立。其余长度不受影响。
  - 若 `pos < len(tails)`：`tails[pos]` 是第一个 $\ge x$ 的。对长度 `pos+1`，原来最小结尾是 `tails[pos]`，现在 `x < tails[pos]`（严格，因为 `bisect_left` 找的是第一个 $\ge$，若相等则 `x == tails[pos]`，替换后不变，仍最小），所以用 `x` 结尾更优，替换合法。对长度 `pos`（即下标 `pos-1`），`tails[pos-1] < x`，`x` 接不上，无法产生更短的更优结尾；对更长长度，`x` 更接不上。所以只有 `pos` 这一格需要更新。

**不会漏**：任何长度 $L$ 的递增子序列，其结尾值一定 $\ge$ `tails[L-1]`（由最小性），所以 `tails` 长度 $\ge$ 真实答案；反过来 `tails` 的每一格都对应一个真实存在的子序列（归纳中构造出来的），所以 `tails` 长度 $\le$ 真实答案。两边夹住，相等。

**不会重**：`tails` 每个位置只存一个值，替换是覆盖而非累加，长度只在「追加」时 +1，而追加的前提是 `x` 严格大于当前所有结尾，对应一条真实的新子序列，不会重复计数。

## 5. 完整代码（Python）

```python
from bisect import bisect_left

class Solution:
    def lengthOfLIS(self, nums: list[int]) -> int:
        tails = []  # tails[L-1] = 长度 L 的递增子序列的最小结尾值
        for x in nums:
            # 找第一个 >= x 的位置：严格递增要求相等的值不能接在后面
            pos = bisect_left(tails, x)
            if pos == len(tails):
                # x 比所有结尾都大，可以延长最长子序列
                tails.append(x)
            else:
                # 用更小的结尾替换，为后续元素留出更大空间
                tails[pos] = x
        return len(tails)  # tails 的长度就是 LIS 长度
```

## 6. 复杂度

- **时间 $O(n\log n)$**：外层遍历 `n` 个元素，每个元素做一次 `bisect_left`，二分在长度最多为 `n` 的 `tails` 上进行，代价 $O(\log n)$。乘起来 $O(n\log n)$。对比 $O(n^2)$ DP，省掉的是「扫前面所有 `j`」那一层，被二分替代。
- **空间 $O(n)$**：`tails` 最坏情况（数组本身严格递增）长度等于 `n`。没有额外的 DP 表。

## 7. 边界与反例（至少 4 条）

1. **`[7,7,7,7,7,7,7]` → 1**。容易错在用了 `bisect_right` 或 `<=` 判断，把相等元素当成可接，得到 7。严格递增必须用 `bisect_left`。
2. **`[1]` → 1**。单元素，`tails` 追加一次，返回 1。容易错在循环里对空 `tails` 做 `tails[-1]` 比较而越界。
3. **`[5,4,3,2,1]` → 1**。全程替换位置 0，`tails` 长度始终 1。容易错在以为「递减就返回 0」或「替换会缩短长度」。
4. **`[2,3,1]` → 2**。走完 `tails = [1,3]`，但 `[1,3]` 在原数组里下标是 2、1，顺序反了。若题目要求**输出序列本身**，直接返回 `tails` 是错的，必须额外记录前驱下标重建。这是本题最隐蔽的坑。
5. **`[0,1,0,3,2,3]` → 4**（示例 2）。走一遍：`[0]→[0,1]→[0,1]`（0 替换位置 0，不变）`→[0,1,3]→[0,1,2]→[0,1,2,3]`，长度 4。容易错在替换时把 `tails` 搞乱顺序。

## 8. 面试追问与变体（3 条）

1. **追问：如果要输出具体的 LIS 序列，怎么改？** 思路：额外维护 `prev[i]` 记录 `nums[i]` 接在哪个下标后面，以及 `tails` 每格对应的原数组下标；最后从 `tails` 最后一格的下标沿 `prev` 回溯。
2. **追问：改成「最长非递减子序列」（允许相等）怎么做？** 思路：把 `bisect_left` 换成 `bisect_right`，相等元素就能接在后面，长度会变长。
3. **追问：改成「最长递增子数组」（必须连续）怎么做？** 思路：子数组要求连续，DP 退化成 `dp[i] = dp[i-1]+1 if nums[i]>nums[i-1] else 1`，$O(n)$，和本题的「子序列」是两回事，别混。
