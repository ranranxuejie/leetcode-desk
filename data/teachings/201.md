## 1. 一句话本质

求区间 `[left, right]` 内所有整数的**二进制公共前缀**——从最高位往下看，第一个出现分歧的位及其之后的所有位，在按位与后必然全变成 0。

## 2. 读完题的第一反应

**朴素解法**：把 `left` 到 `right` 每个数依次做 `&`，累加结果。复杂度 O(right − left)，当区间跨度达到 2×10⁹ 时直接超时。示例 3 就是专门用来卡这个解法的：`left=1, right=2147483647`，暴力要循环 21 亿次。

**关键观察**：按位与有一个性质——某一位只要在区间内**出现过一次 0**，最终结果这一位就是 0。那么问题变成：区间内所有数，哪些二进制位是「从头到尾都是 1」的？

把 `left` 和 `right` 写成二进制对齐看：

```
left  = 5 → 101
right = 7 → 111
```

从最高位开始比：第 2 位（4 的位）两者都是 1；第 1 位（2 的位）`left` 是 0、`right` 是 1，出现分歧。一旦某一位上 `left` 是 0 而 `right` 是 1，说明区间里必然跨过了「这一位从 0 翻到 1」的边界，那么这一位以及它右边所有低位，在区间内一定都出现过 0（因为数字是连续递增的，低位会经历完整的 0/1 循环）。所以**答案就是 `left` 和 `right` 的公共前缀，后面全部补 0**。

这个观察直接指向两个方向：一是「不断右移直到相等，再左移回来」，二是「用 `right & (right-1)` 不断抹掉最低位的 1，直到 ≤ left」。两者本质相同，下面走第一种。

## 3. 从暴力到最优

**暴力**：`res = left; for x in range(left+1, right+1): res &= x`。瓶颈是区间长度，最坏 2×10⁹ 次操作。

**优化思路**：我们不关心区间里每个数具体是什么，只关心公共前缀。用 `left = 5, right = 7` 走一遍「右移对齐」：

| 步骤 | left | right | 说明 |
|---|---|---|---|
| 初始 | 101 (5) | 111 (7) | 第 0 位不同 |
| 右移 1 次 | 10 (2) | 11 (3) | 第 0 位仍不同 |
| 右移 2 次 | 1 (1) | 1 (1) | 相等了！公共前缀 = `1` |
| 左移 2 次还原 | 100 (4) | 100 (4) | 答案 4 |

每右移一次，就「扔掉」一个已经确定会变成 0 的低位。当 `left == right` 时，剩下的就是公共前缀。最后把扔掉的位数左移补 0 回来。

再看示例 3：`left=1, right=2147483647`。`right` 是 31 个 1，`left` 是 `1`。右移过程中 `left` 很快变成 0，而 `right` 要右移 31 次才变 0，最终两者都归 0，答案 0。循环次数是位数（≤31），不是区间长度——这就是瓶颈被消掉的地方：**从「遍历数值」变成「遍历二进制位」**。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。设原始输入为 `L, R`，循环执行 `k` 次右移后得到 `L_k = L >> k`、`R_k = R >> k`。

**不变量**：对任意 `k ≥ 0`，`[L, R]` 内所有数的按位与，等于 `(L_k & R_k & ... )` 左移 `k` 位——更精确地说，`L_k` 到 `R_k` 之间所有整数的按位与，左移 `k` 位，恰好等于原区间的按位与。

**为什么成立**：右移 `k` 位等价于「丢弃低 `k` 位」。而低 `k` 位在区间 `[L, R]` 中，只要区间长度 ≥ 2^k，低位必然遍历过 0，最终与结果为 0；若区间长度 < 2^k，则 `L_k` 和 `R_k` 已经相等（因为高位相同、低位差异被丢弃后无差别），此时区间内所有数共享同一前缀，低位与结果也由前缀决定。两种情况下，「丢弃低位 + 左移补 0」都不改变最终答案。

**终止性**：每次右移，`R_k` 严格减小（除非已为 0），最多 31 次后 `L_k = R_k = 0`，循环必停。

**不漏**：循环停止时 `L_k == R_k`，这个值就是公共前缀，左移 `k` 位补 0 得到完整答案，没有遗漏任何应保留的 1 位。

**不重**：每一位只被判断一次（右移时丢弃或保留），不存在重复计算。

## 5. 完整代码（Python）

```python
class Solution:
    def rangeBitwiseAnd(self, left: int, right: int) -> int:
        shift = 0
        # 不断右移，直到 left 和 right 相等，相等的部分就是公共前缀
        while left < right:
            left >>= 1
            right >>= 1
            shift += 1
        # 把丢弃的低位补 0 还原
        return left << shift
```

另一种等价写法（更短，但思路要讲清楚）：

```python
class Solution:
    def rangeBitwiseAnd(self, left: int, right: int) -> int:
        # 每次抹掉 right 最低位的 1，直到 right <= left
        # 此时 right 剩下的高位就是公共前缀（低位已被清零）
        while left < right:
            right &= right - 1
        return right
```

第二种写法依赖一个事实：`right & (right - 1)` 把 `right` 最低位的 1 变成 0。当 `right` 被削到 ≤ `left` 时，说明所有「会变化的位」都被清掉了，剩下的就是公共前缀。两种写法复杂度相同，面试时讲第一种更直观，写第二种更简洁。

## 6. 复杂度

**时间**：O(log R)，即 O(位数)。循环每轮把 `right` 右移一位（或抹掉一个 1），最多执行 31 次（32 位整数）。这里的 `log` 来自**二进制位数**，不是区间长度——这正是相对暴力的 O(R − L) 的改进点。暴力解法的 `n` 是区间跨度，本解法的 `n` 是数值的位宽。

**空间**：O(1)。只用了 `shift` 一个计数器，没有额外数组或递归栈。

## 7. 边界与反例（至少 4 条）

1. **输入 `left = 0, right = 0`** → 期望 `0`。容易错在：以为 `left == right` 时直接返回 `left` 就行，但若代码写成 `while left <= right` 会死循环或逻辑错乱。正确做法是 `while left < right`，相等时直接返回。

2. **输入 `left = 1, right = 1`** → 期望 `1`。容易错在：循环条件写成 `while left != right` 时，初始就相等，`shift=0`，返回 `1 << 0 = 1`，正确；但若误写成先右移再判断，会多移一位得到 0。

3. **输入 `left = 2147483646, right = 2147483647`** → 期望 `2147483646`。这两个数只差 1，二进制是 `...11111110` 和 `...11111111`，按位与抹掉最低位得 `...11111110`。容易错在：以为「区间很短所以答案接近 right」，实际最低位被清 0。

4. **输入 `left = 5, right = 7`** → 期望 `4`。容易错在：直接返回 `left & right = 5 & 7 = 5`，漏掉了中间数 6（`110`）会把第 0 位清 0。必须考虑区间内**所有**数，不能只看端点。

5. **输入 `left = 0, right = 2147483647`** → 期望 `0`。容易错在：暴力解法超时；优化解法中若 `shift` 计数超过 31 位（比如用 64 位思维）也不会错，但若用 `while left < right` 且 `left` 一开始就是 0，`0 < right` 成立会继续右移，最终 `0 == 0` 停止，返回 `0 << 31 = 0`，正确——但要注意 Python 整数无溢出，C++ 里 `1 << 31` 可能溢出，需用 `unsigned` 或提前返回。

## 8. 面试追问与变体（3 条）

1. **追问：如果区间是 `[left, right]` 但要求「按位或」的结果呢？**
   思路：按位或只需看区间内是否出现过 1。若 `left == right` 返回 `left`；否则从最高分歧位开始，该位及以下全置 1（因为区间跨过了 0→1 边界，低位必然出现过 1）。可用 `left | right` 再补低位。

2. **追问：如果要求「区间内所有数的按位异或」呢？**
   思路：异或有前缀性质，`f(n) = 1^2^...^n` 有 O(1) 公式（按 `n % 4` 分四种情况），答案 = `f(right) ^ f(left-1)`。和本题的「与」不同，异或不能只看公共前缀，必须用前缀和思想。

3. **追问：如果 `left` 和 `right` 是 64 位整数，且区间可能跨 2^63？**
   思路：算法不变，循环次数变成 63 次，仍是 O(位数)。注意语言层面的移位溢出问题（C++ 用 `1ULL`，Java 用 `long`），Python 无此问题。

3. **LeetCode 231. 2 的幂**：共同点是用 `n & (n-1) == 0` 判断是否只有一位 1，正是本题第二种写法里抹 1 操作的直接应用。
