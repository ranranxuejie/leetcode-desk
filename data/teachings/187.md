## 1. 一句话本质

在长度为 n 的字符串里，找出所有**长度为 10 且出现次数 ≥ 2 的子串**，每个不同的子串只输出一次。

注意两个关键词：「长度固定为 10」和「去重输出」。前者决定了滑动窗口的窗口大小是常数，后者决定了我们需要一个能记录「出现过几次」的结构，而不是简单的集合。

## 2. 读完题的第一反应

**朴素解法**：枚举所有起点 i（从 0 到 n-10），取出 `s[i:i+10]`，用一个字典统计每个子串出现次数，最后把次数 ≥ 2 的挑出来。

这个思路本身是对的，问题出在**切片和哈希的代价**上。Python 里 `s[i:i+10]` 会创建一个新字符串，长度是 10；把它作为字典的 key 时，哈希函数要遍历这 10 个字符。所以每个窗口的操作是 O(10)，总共 n 个窗口，复杂度 O(10n) = O(n)。看起来是线性的？

问题在于：**10 是常数，但常数不小**。当 n = 10^5 时，你要创建 10^5 个长度为 10 的字符串对象，每个都要分配内存、拷贝字符、计算哈希。这在 Python 里是实打实的开销。更关键的是，面试官问这道题，往往是想看你**能不能把「长度为 10 的字符串」压缩成一个整数**——这才是这道题被归到「位运算 / 滚动哈希」标签下的原因。

**关键观察**：DNA 只有 4 种字符 A/C/G/T，正好可以用 2 个二进制位表示（00/01/10/11）。长度 10 的序列，就是 20 个二进制位，能塞进一个 32 位整数里。于是「比较两个子串是否相同」变成了「比较两个整数是否相同」——O(1) 的整数比较，而不是 O(10) 的字符串比较。

更进一步：相邻两个窗口有 9 个字符是重叠的。如果窗口 i 的编码是 `code`，窗口 i+1 的编码可以**在 O(1) 内从 code 推出来**，不需要重新扫描 10 个字符。这就是「滚动哈希」的思想。

## 3. 从暴力到最优

**第一步：暴力 + 字典计数**

```python
count = {}
for i in range(len(s) - 9):
    sub = s[i:i+10]
    count[sub] = count.get(sub, 0) + 1
return [k for k, v in count.items() if v >= 2]
```

复杂度 O(10n)，能过，但不是最优形态。

**第二步：把子串编码成整数**

给四个字符分配编码：A=0, C=1, G=2, T=3。一个长度为 10 的序列 `c0 c1 ... c9` 编码为：

```
code = c0 * 4^9 + c1 * 4^8 + ... + c9 * 4^0
```

这就是一个 20 位的二进制数（因为 4^10 = 2^20）。

**第三步：滚动更新**

设窗口 i 的编码为 `code_i`。窗口 i+1 相比窗口 i，**去掉最左边一位，右边补一位新字符**。用公式表达：

```
code_{i+1} = ((code_i - c_i * 4^9) * 4 + c_{i+10}) 
           = (code_i & 0xFFFFF) * 4 + c_{i+10}   # 用位掩码更简洁
```

`0xFFFFF` 是低 20 位全 1 的掩码（20 个 1）。`code_i & 0xFFFFF` 等价于「去掉最高 2 位」，再左移 2 位（乘 4）腾出最低 2 位，加上新字符的编码。

**走一遍小例子**：s = "AAAAACCCCCAAAAACCCCCCAAAAAGGGTTT"，取前 12 个字符 "AAAAACCCCCAA"。

- 初始窗口 i=0："AAAAACCCCC"，编码 = 0（全是 A，编码 0）
- i=1：去掉第一个 A（编码 0），`(0 & 0xFFFFF) * 4 + 0 = 0`，还是 0
- ...前 5 个窗口全是 0（因为前 5 个字符都是 A）
- i=5：窗口 "ACCCCCAAAA"？不对，重新看：s[5:15] = "CCCCCAAAAA"。此时窗口从 i=4 的 "AACCCCCAAA" 滚动而来。i=4 的编码：前两个 A 是 0，后面 CCCCC 是 1，AAAA 是 0，所以编码 = 1*4^7 + 1*4^6 + 1*4^5 + 1*4^4 + 1*4^3 = 16384+4096+1024+256+64 = 21824。i=5 时：`(21824 & 0xFFFFF) * 4 + 0`。21824 的二进制低 20 位就是它本身（小于 2^20），乘 4 得 87296，加上新字符 A=0，得 87296。这个数对应 "CCCCCAAAAA" 的编码。

这样每个窗口的编码更新是 O(1) 的位运算，字典的 key 是整数，哈希也是 O(1)。总复杂度 O(n)，且常数极小。

**第四步：去重的细节**

字典记录每个编码出现的次数。但注意：**同一个编码可能对应多个不同的子串吗？** 不会——因为编码是单射的（4 进制表示唯一）。所以编码和子串一一对应，用编码计数等价于用子串计数。

输出时，遍历字典，把次数 ≥ 2 的编码**解码回字符串**。解码方法：从低位到高位，每次取 `code % 4` 得到一个字符，然后 `code //= 4`，重复 10 次，最后反转。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在循环的第 i 次迭代结束时，`code` 恰好等于 `s[i:i+10]` 的 4 进制编码，且字典 `count` 中已经记录了 `s[0:10], s[1:11], ..., s[i:i+10]` 这 i+1 个窗口各自的出现次数。

**初始**：i=0 时，`code` 由前 10 个字符累加得到，等于 `s[0:10]` 的编码；字典记录了一次，不变量成立。

**归纳**：假设第 i 次迭代后不变量成立。第 i+1 次迭代，`code` 更新为 `(code & 0xFFFFF) * 4 + encode(s[i+10])`。由于 `code` 的低 20 位恰好是 `s[i:i+10]` 的后 9 个字符的编码（去掉最高 2 位即去掉 `s[i]`），乘 4 左移 2 位后，低 2 位补 0，加上 `s[i+10]` 的编码，得到的正是 `s[i+1:i+11]` 的编码。字典计数加一。不变量保持。

**不漏**：循环覆盖了所有起点 i ∈ [0, n-10]，每个长度为 10 的子串都被恰好处理一次，所以任何出现 ≥ 2 次的子串都会被计数到 ≥ 2。

**不重**：输出时遍历字典的 key（编码），每个编码只输出一次。由于编码与子串一一对应，同一个子串不会输出两次。

**边界**：当 n < 10 时，循环不执行，返回空列表，正确。

## 5. 完整代码（Python）

```python
class Solution:
    def findRepeatedDnaSequences(self, s: str) -> list[str]:
        n = len(s)
        if n < 10:
            return []

        # 字符到 2 位编码的映射
        mp = {'A': 0, 'C': 1, 'G': 2, 'T': 3}
        # 解码用的反向表
        rev = 'ACGT'

        # 计算第一个窗口的编码（10 个字符，每个 2 位，共 20 位）
        code = 0
        for ch in s[:10]:
            code = (code << 2) | mp[ch]

        count = {code: 1}          # 编码 -> 出现次数
        mask = (1 << 20) - 1       # 低 20 位全 1，用于去掉最高 2 位

        for i in range(1, n - 9):
            # 滚动：去掉 s[i-1] 的编码（最高 2 位），左移 2 位，加上 s[i+9]
            code = ((code & mask) << 2) | mp[s[i + 9]]
            count[code] = count.get(code, 0) + 1

        # 把出现次数 >= 2 的编码解码回字符串
        res = []
        for code, cnt in count.items():
            if cnt >= 2:
                chars = []
                c = code
                for _ in range(10):
                    chars.append(rev[c & 3])   # 取最低 2 位
                    c >>= 2
                res.append(''.join(reversed(chars)))
        return res
```

几个容易写错的点，注释里已经标了，再强调一下：

- `mask = (1 << 20) - 1` 是 20 个 1。`code & mask` 保留低 20 位，等价于「去掉最高 2 位」。如果你写成 `code & 0xFFFFF` 也一样。
- 循环从 `i = 1` 开始，因为 `i = 0` 的窗口已经在初始化时计入。循环条件是 `i < n - 9`，即 `i + 9 <= n - 1`，保证 `s[i+9]` 不越界。
- 解码时从低位往高位取，所以最后要 `reversed`。

## 6. 复杂度

**时间**：O(n)。

- 初始化第一个窗口：10 次操作，O(1)。
- 主循环：n - 10 次迭代，每次做常数次位运算和字典操作，O(n)。
- 解码：字典最多有 n - 9 个 key，每个 key 解码 10 次，O(10n) = O(n)。

没有 log n 项，因为所有操作都是整数位运算和哈希表操作，不涉及排序或二分。

**空间**：O(n)。

- 字典最多存 n - 9 个 key，每个 key 是整数，O(n)。
- 输出列表最多 O(n) 个字符串，每个长度 10，O(10n) = O(n)。

注意：如果不用编码而直接用字符串做 key，空间也是 O(10n)，但常数更大（每个字符串对象有额外开销）。编码方案把每个 key 压成一个整数，实际内存占用更小。

## 7. 边界与反例（至少 4 条）

1. **输入 `s = ""` 或 `s = "ACGT"`（长度 < 10）** → 期望 `[]` → 容易错在：循环范围写成 `range(n - 9)` 时，n < 10 会得到负数或 0，`range` 为空没问题，但初始化 `s[:10]` 会取到短字符串，编码不完整。所以开头必须显式判断 `n < 10` 直接返回。

2. **输入 `s = "AAAAAAAAAAAAA"`（13 个 A）** → 期望 `["AAAAAAAAAA"]` → 容易错在：所有窗口编码都是 0，字典里只有一个 key，计数为 4。如果输出时不去重（比如每次计数到 2 就 append），会输出多次。必须等循环结束后统一遍历字典。

3. **输入 `s = "ACGTACGTAC"`（恰好 10 个字符）** → 期望 `[]` → 容易错在：循环 `range(1, n - 9)` 中 `n - 9 = 1`，`range(1, 1)` 为空，正确。但如果把循环写成 `range(n - 9)` 从 0 开始，会重复处理第一个窗口，导致计数错误。

4. **输入 `s = "AAAAAAAAAA"`（恰好 10 个 A）** → 期望 `[]`（只出现一次）→ 容易错在：把「出现次数 ≥ 2」写成「出现次数 ≥ 1」，会把只出现一次的也输出。

5. **输入 `s = "AAAAACCCCCAAAAACCCCCCAAAAAGGGTTT"`** → 期望 `["AAAAACCCCC", "CCCCCAAAAA"]` → 容易错在：解码时位序搞反，得到 "CCCCCAAAAA" 的反转 "AAAAACCCCC" 之类。务必用 `reversed` 或从高位往低位拼。

## 8. 面试追问与变体（3 条）

1. **追问：如果长度不是 10，而是 k（k 可能很大，比如 1000），怎么办？** → 思路：2 位编码方案需要 2k 位，k 大时整数放不下。此时改用**双哈希**（两个大质数取模）或 Python 的字符串切片 + 字典（k 大时切片开销 O(k)，总 O(nk)）。如果 k 接近 n，直接暴力比较所有子串对，O(n^2 k) 但实际可能更优。

2. **追问：如果要求返回出现次数最多的长度为 10 的子串（可能有多个），怎么改？** → 思路：字典计数后，找最大值，再遍历字典收集所有计数等于最大值的 key，解码输出。时间不变，O(n)。

3. **追问：如果 DNA 字符集扩展到 8 种（比如加上 U、N 等），编码方案怎么调整？** → 思路：每个字符需要 3 位（2^3 = 8），长度 10 需要 30 位，仍在 32 位整数范围内。掩码改为 `(1 << 30) - 1`，滚动公式不变。如果字符集超过 16 种，需要 5 位，长度 10 需要 50 位，Python 整数无上限，但其他语言要用 64 位整数。

## 9. 举一反三（2-3 道同类题）

1. **LeetCode 3. 无重复字符的最长子串** → 共同点：都是滑动窗口 + 哈希表记录窗口内元素，区别在于本题窗口大小固定、求重复，那题窗口大小可变、求最长。

2. **LeetCode 438. 找到字符串中所有字母异位词** → 共同点：固定长度窗口滑动 + 用计数/编码判断窗口内容是否匹配目标，本题是判断窗口是否重复出现。

3. **LeetCode 1044. 最长重复子串** → 共同点：都是找重复子串，但那题长度不固定、要求最长，需要二分答案 + 滚动哈希（Rabin-Karp），是本题的「升级版」：本题固定长度 10 所以 O(n) 直接扫，那题要二分长度 k，对每个 k 做 O(n) 的滚动哈希检查，总 O(n log n)。
