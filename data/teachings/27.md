## 1. 一句话本质

在**不允许额外数组**的前提下，把「不等于 val 的元素」全部挤到数组前部，并返回它们的个数 k；后 k 位之后的内容随便是什么都行。

## 2. 读完题的第一反应

**朴素解法**：新建一个数组 `res`，遍历 `nums`，遇到不等于 `val` 的就 `append` 进去，最后把 `res` 拷回 `nums` 前部，返回 `len(res)`。

它卡在哪？卡在**空间**上。题面明确写了「原地 移除」，评测代码直接拿你传进去的 `nums` 去断言，所以你不能返回一个新数组，必须改原数组。就算评测不卡，开一个长度 n 的辅助数组也是 O(n) 额外空间，面试官一定会追问「能不能 O(1)」。

**关键观察**：题面里有一句话是解题的钥匙——「nums 的其余元素和 nums 的大小并不重要」，以及示例解释里的「这五个元素可以任意顺序返回」。

这句话的意思是：**输出不要求保序**。一旦不要求保序，你就不需要「把后面的元素整体往前挪」这种昂贵操作，你只需要保证「前 k 个位置装的是合法元素」——至于某个合法元素原来在数组的哪个位置，无所谓。

于是问题从「删除并保持相对顺序」降级成「把合法元素收集到前缀区」。这就自然引出双指针：一个指针负责「扫描源」，一个指针负责「写目标」。

## 3. 从暴力到最优

### 第一步：暴力（额外数组）

以 `nums = [0,1,2,2,3,0,4,2], val = 2` 为例：

```
i=0: nums[0]=0 ≠ 2 → res=[0]
i=1: nums[1]=1 ≠ 2 → res=[0,1]
i=2: nums[2]=2 = 2 → 跳过
i=3: nums[3]=2 = 2 → 跳过
i=4: nums[4]=3 ≠ 2 → res=[0,1,3]
i=5: nums[5]=0 ≠ 2 → res=[0,1,3,0]
i=6: nums[6]=4 ≠ 2 → res=[0,1,3,0,4]
i=7: nums[7]=2 = 2 → 跳过
返回 5
```

瓶颈：`res` 是 O(n) 额外空间。

### 第二步：把 res 塞回 nums 自己（快慢指针）

注意上面 `res` 每次 `append` 之后长度是 1,2,3,4,5——它永远不超过「已经扫描过的位置数」。也就是说，**写入位置永远落后于或等于读取位置**，所以可以直接写回 `nums` 本身，不会覆盖掉还没读的数据。

这就是快慢指针：

- `slow`：下一个合法元素该写到的位置，同时它最终的值就是 k。
- `fast`：当前正在检查的位置。

走一遍 `nums = [0,1,2,2,3,0,4,2], val = 2`：

```
初始 slow=0, fast=0
fast=0: nums[0]=0≠2 → nums[0]=nums[0]=0, slow=1
fast=1: nums[1]=1≠2 → nums[1]=nums[1]=1, slow=2
fast=2: nums[2]=2=2 → 跳过, slow=2
fast=3: nums[3]=2=2 → 跳过, slow=2
fast=4: nums[4]=3≠2 → nums[2]=3, slow=3   ← 注意这里把 3 写到了下标 2
fast=5: nums[5]=0≠2 → nums[3]=0, slow=4
fast=6: nums[6]=4≠2 → nums[4]=4, slow=5
fast=7: nums[7]=2=2 → 跳过, slow=5
返回 5
```

最终 `nums = [0,1,3,0,4,2,2,2]`，前 5 个是 `[0,1,3,0,4]`，正好是全部非 2 元素。注意 `fast=4` 那一步：`nums[2]` 原本是 2（已经被判定为要删的），所以覆盖它没有任何损失——这就是「写入位置落后于读取位置」带来的安全性。

### 第三步：为什么这就是最优

每个元素必须至少被看一次，否则你无法判断它等不等于 `val`，所以时间下界是 Ω(n)，快慢指针正好 O(n)。空间上你只用了两个下标变量，O(1)。时间和空间都触到了下界，没有进一步优化的空间。

（题面允许乱序，所以还有「对撞双指针」的写法：左指针找等于 val 的，右指针找不等于 val 的，交换。它也是 O(n)/O(1)，但会打乱顺序、且要处理更多边界，本题用快慢指针更稳。面试时提一句「因为允许乱序，也可以用对撞指针」是加分项。）

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来证。

定义不变量：**在每一轮循环开始时，`nums[0:slow]` 恰好是「`nums` 原始前 `fast` 个元素中所有不等于 `val` 的元素」，且顺序与原数组一致；`slow <= fast`。**

三条性质逐一验证：

1. **初始化**：`slow = fast = 0`，`nums[0:0]` 是空区间，原始前 0 个元素中非 val 元素也是空集，成立。

2. **保持**：
   - 若 `nums[fast] == val`：不写入，`slow` 不变。新区间 `nums[0:slow]` 仍是「前 fast 个中的非 val 元素」，而第 `fast` 个是 val 不该进，不变量保持。
   - 若 `nums[fast] != val`：执行 `nums[slow] = nums[fast]; slow += 1`。因为 `slow <= fast`，写入位置 `slow` 要么等于 `fast`（自赋值，无影响），要么小于 `fast`——而小于 `fast` 的位置上放的都是「已经被判定为 val 或已被搬走的旧值」，覆盖它不会破坏 `nums[0:slow]` 里已有的合法元素。写入后 `nums[0:slow]` 恰好多了这一个非 val 元素，不变量保持。

3. **终止**：`fast == n` 时，不变量说 `nums[0:slow]` 是「原始全部 n 个元素中所有非 val 元素」，即**不漏**（每个非 val 都被收集了）；又因为每个位置最多被写一次、且只在遇到非 val 时才写，所以**不重**（不会把同一个元素算两次）。此时 `slow` 就是非 val 元素总数 k，返回它即正确。

关键点在于 `slow <= fast` 这个不等式：它保证了「写」永远发生在「读」的后面或原地，绝不会覆盖尚未检查的数据。这是快慢指针能原地工作的根本原因，也是面试时要讲出来的那句话。

## 5. 完整代码（Python）

```python
class Solution:
    def removeElement(self, nums: list[int], val: int) -> int:
        # slow: 下一个合法元素要写入的位置，最终等于 k
        # fast: 当前扫描到的位置
        slow = 0
        for fast in range(len(nums)):
            if nums[fast] != val:
                # 把合法元素搬到前缀区；slow <= fast 保证不覆盖未读数据
                nums[slow] = nums[fast]
                slow += 1
            # nums[fast] == val 时什么都不做，相当于「跳过」
        # nums[0:slow] 就是全部非 val 元素，slow 即 k
        return slow
```

如果面试官要求「尽量少写数组」（写操作比读贵），可以加一个判断避免自赋值：

```python
class Solution:
    def removeElement(self, nums: list[int], val: int) -> int:
        slow = 0
        for fast in range(len(nums)):
            if nums[fast] != val:
                if slow != fast:          # 避免 nums[i] = nums[i] 的无谓写
                    nums[slow] = nums[fast]
                slow += 1
        return slow
```

两版逻辑等价，第一版更短，第二版在「写代价高」的场景更优，面试时说出这个取舍即可。

## 6. 复杂度

- **时间 O(n)**：`for fast in range(len(nums))` 恰好迭代 n 次，n 来自数组长度；循环体内是常数次比较和赋值，没有嵌套循环、没有排序，所以是 n × O(1) = O(n)。这里**没有 log n 项**——因为没有二分、没有分治、没有堆操作。
- **空间 O(1)**：只用了 `slow`、`fast` 两个整型变量，与 n 无关。没有新建列表、没有切片（`nums[:]` 会复制，别用）、没有递归栈。

对比暴力解：时间同为 O(n)，但空间从 O(n) 降到 O(1)，这就是本题的全部收益。

## 7. 边界与反例（至少 4 条）

1. **`nums = [], val = 0`** → 期望返回 `0`。容易错在：手写 `while` 循环时忘了空数组直接返回，或访问 `nums[0]` 越界。用 `for ... in range(len(nums))` 天然安全。

2. **`nums = [3,3,3], val = 3`** → 期望返回 `0`，`nums` 前 0 个元素为空。容易错在：以为「至少要留一个」，或返回 `slow` 之前多做了一次 `slow += 1`。注意 `slow` 初值必须是 0，且只在「遇到非 val」时自增。

3. **`nums = [1,2,3], val = 4`（val 不存在）** → 期望返回 `3`，`nums` 保持 `[1,2,3]`。容易错在：把「没找到 val」当成特殊情况处理，或误以为要返回 `len(nums) - 1`。快慢指针此时每步都自赋值，`slow` 一路涨到 3，自然正确。

4. **`nums = [2], val = 2`（唯一元素就是要删的）** → 期望返回 `0`。容易错在：`slow` 初始化成 1，或循环结束后返回 `slow + 1`。这类「单元素 + 全删」是最容易暴露 off-by-one 的用例。

5. **`nums = [4,5], val = 4`（要删的在最前）** → 期望返回 `1`，`nums[0]` 应为 5。容易错在：用「从后往前删」的思路写，或对撞指针时右指针初始化为 `len-1` 后忘记处理 `left == right` 的情况。快慢指针：`fast=0` 跳过，`fast=1` 时 `nums[0]=5, slow=1`，正确。

6. **`nums = [0,0,0], val = 0`（全删且值等于 0）** → 期望返回 `0`。容易错在：把 `val` 和「假值」混淆，写成 `if nums[fast]:` 而不是 `if nums[fast] != val:`。Python 里 `0` 是假值，这个坑很真实。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求保留非 val 元素的相对顺序，你的解法还成立吗？**
   思路：快慢指针本身就保序（因为按 `fast` 递增顺序写入），所以直接成立——这一点要主动说出来，它是快慢指针相对对撞指针的优势。

2. **追问：如果允许 O(1) 空间但要求「删除后数组尾部元素保持原样」，怎么做？**
   思路：改用对撞双指针，`left` 从左找 val，`right` 从右找非 val，交换后 `right -= 1`；交换会打乱顺序，所以「尾部保持原样」这个条件其实与「原地删除」冲突，需要和面试官确认到底要哪个约束——这题考的是你敢不敢指出需求矛盾。

3. **追问：如果 val 是一个区间 `[lo, hi]`，要删掉所有落在区间内的元素呢？**
   思路：把 `nums[fast] != val` 换成 `not (lo <= nums[fast] <= hi)`，其余逻辑一字不改，仍是 O(n)/O(1)。这题考的是你能否识别「判定条件」和「搬运框架」是解耦的。

## 9. 举一反三（2-3 道同类题）

- **26. 删除有序数组中的重复项**：同样是快慢指针原地压缩，区别是判定条件从「≠ val」变成「≠ 前一个已保留元素」，且因为有序所以天然保序。
- **283. 移动零**：把 0 全部挪到末尾、非 0 保持相对顺序。本质是本题的「保序 + 补零」版本——先用快慢指针收集非 0，再把 `slow` 之后的格子填 0。
- **80. 删除有序数组中的重复项 II**：每个元素最多保留两次，快慢指针的判定条件变成「与 `nums[slow-2]` 比较」，是本题框架的直接推广。

这三道题共用同一个骨架：**一个读指针扫描、一个写指针收集，写指针永远不越过读指针**。把这个骨架记牢，这一类「原地删除/压缩」的题都能套。
