## 1. 一句话本质

把 32 位整数的第 `i` 位搬到第 `31-i` 位，其余位置不动——也就是对 32 个比特做一次"下标镜像"。

## 2. 读完题的第一反应

**朴素解法**：把 `n` 转成 32 位二进制字符串，`[::-1]` 反转，再转回整数。这在 Python 里一行就能写，但它卡在两点：一是字符串转换的常数很大，二是题目进阶明确问"多次调用如何优化"——字符串方案每次都要分配 O(32) 的额外内存，且完全没利用位运算的硬件特性。

**关键观察**：反转的本质是"第 i 位去第 31-i 位"。如果我能每次从 `n` 的**最低位**取出一个比特，把它放到结果的**最高位**，然后两边同时向中间推进，那么 32 次之后自然完成镜像。这个观察之所以能让你想到下一步，是因为它把"整体反转"拆成了 32 个互不干扰的"单比特搬运"——而单比特搬运恰好是位运算最擅长的事。

## 3. 从暴力到最优

**第一步：字符串反转（能过，但不优雅）**

```python
s = bin(n)[2:].zfill(32)
return int(s[::-1], 2)
```

瓶颈：`bin` + `zfill` + `[::-1]` + `int(..., 2)` 四趟 O(32) 的字符串操作，常数大，且不是"位运算"题该有的解法。

**第二步：逐位搬运（标准解）**

维护两个变量：`res` 存结果，`n` 存剩余待处理的位。每轮做三件事：

1. `res = (res << 1) | (n & 1)`：把 `res` 左移腾出最低位，再把 `n` 的最低位填进去；
2. `n >>= 1`：`n` 右移，丢掉已处理的最低位；
3. 循环固定 32 次。

注意一个细节：`res << 1` 之后最低位是 0，`| (n & 1)` 就是"把这一位写进去"，不需要先清位。

**小例子走一遍**：取 `n = 6`（二进制 `...000110`），为看清过程只写低 6 位，循环 6 次（真实代码固定 32 次，高位全是 0 不影响结果）。

| 轮次 | n（低6位） | n & 1 | res 左移前 | res 左移后 | res 或上 bit |
|---|---|---|---|---|---|
| 初始 | 000110 | - | - | - | 0 |
| 1 | 000110 | 0 | 0 | 0 | 0 |
| 2 | 000011 | 1 | 0 | 0 | 1 |
| 3 | 000001 | 1 | 1 | 2 | 3 |
| 4 | 000000 | 0 | 3 | 6 | 6 |
| 5 | 000000 | 0 | 6 | 12 | 12 |
| 6 | 000000 | 0 | 12 | 24 | 24 |

结果 `24 = 11000₂`，而 `6 = 110₂` 在 6 位下反转应为 `011000₂ = 24`。✅

**第三步：分治（进阶答案）**

逐位搬运是 O(32) 次迭代。分治的思路是：先交换相邻的 1 位一组，再交换相邻的 2 位一组，再 4 位、8 位、16 位——5 步完成，与位宽的对数成正比。这就是"多次调用"场景下的优化方向，第 8 节展开。

## 4. 正确性：为什么不会漏、不会重

用**不变量**说清楚。设循环执行了 `k` 轮（`0 ≤ k ≤ 32`），断言：

> `res` 的低 `k` 位，恰好是 `n` 原始值的最低 `k` 位的逆序；且 `n` 的当前值等于原始值右移 `k` 位。

**初始**：`k=0`，`res=0` 低 0 位为空，`n` 未动，成立。

**归纳**：假设第 `k` 轮前成立。第 `k` 轮取 `n & 1`，即原始值的第 `k` 位（因为 `n` 已右移 `k` 位，最低位正是原第 `k` 位）。`res << 1` 把已有 `k` 位整体上移一位，新位落在最低位，于是 `res` 的低 `k+1` 位 = 原低 `k` 位的逆序再接上原第 `k` 位——正好是原低 `k+1` 位的逆序。`n >>= 1` 后等于原始值右移 `k+1` 位。归纳成立。

**终止**：`k=32` 时，`res` 的低 32 位是原 `n` 全部 32 位的逆序，高位因 `res` 始终在 32 位内左移（Python 整数无溢出，但每轮只左移一位、共 32 轮，`res` 最多 32 位）不会多出东西。**不漏**：每一位都被 `n & 1` 取到恰好一次；**不重**：每轮 `n` 右移丢弃该位，不会二次取用。

## 5. 完整代码（Python）

```python
class Solution:
    def reverseBits(self, n: int) -> int:
        res = 0
        for _ in range(32):          # 固定 32 轮，不能写成 while n，否则前导 0 会漏
            res = (res << 1) | (n & 1)  # 结果左移腾位，填入 n 的最低位
            n >>= 1                  # n 右移，丢弃已搬运的位
        return res
```

关键逻辑说明：

- `range(32)` 而非 `while n`：这是本题最容易踩的坑。若用 `while n`，当 `n` 高位是 0 时循环提前结束，`res` 左移次数不足，前导零对应的"反转后应出现在低位"的 0 就丢了。例如 `n=1` 用 `while n` 只跑 1 轮得 `res=1`，正确答案是 `2^31`。
- `(res << 1) | (n & 1)`：左移保证新位落在最低位，`|` 保证不破坏已积累的高位。
- 返回 `res` 时 Python 不会自动截断到 32 位，但由于只左移 32 次且每次只或入 1 位，`res < 2^32`，符合题意。

## 6. 复杂度

- **时间 O(32) = O(1)**：循环体执行 32 次，每次是常数次位运算。这里的"32"来自**位宽**（题面固定 32 位有符号整数），不是输入规模 `n` 的大小——所以严格说是 O(log n) 的位宽意义下 O(1)。若把位宽记作 `w`，则是 O(w)。
- **空间 O(1)**：只用了 `res` 和循环变量两个标量，与 `n` 无关。

对比字符串解法：时间同样是 O(w)，但常数大得多（字符串分配、解析），空间 O(w)。逐位搬运在空间上严格更优，这也是它成为标准解的原因。

## 7. 边界与反例（至少 4 条）

1. **`n = 0`** → 期望 `0`。容易错：若用 `while n` 循环体一次都不执行，`res=0` 碰巧对；但若有人写成"先取位再判断"，可能多跑一轮导致 `res` 仍为 0 但逻辑混乱。用固定 32 轮最稳。
2. **`n = 1`** → 期望 `2147483648`（`2^31`）。容易错：`while n` 只跑 1 轮得 `1`，完全错误；这是检验"是否固定 32 轮"的试金石。
3. **`n = 2147483644`（示例 2）** → 期望 `1073741822`。容易错：这个数接近 `2^31`，最高位是 0，反转后最低位应为 0；若误把 Python 的 `~` 或符号位处理进来，会得到负数或差 1。
4. **`n` 为偶数（题面保证）** → 最低位恒为 0，反转后最高位恒为 0，结果必 `< 2^31`。容易错：有人看到"有符号整数"就担心符号位，实际上输入范围 `0 ≤ n ≤ 2^31-2` 保证非负，输出也非负，无需处理补码符号。
5. **`n = 4294967295`（若越界测试）** → 题面范围不含，但若传入，32 轮后 `res` 仍是 32 位全 1，结果 `4294967295`，不会溢出——说明固定 32 轮对边界是安全的。

## 8. 面试追问与变体（3 条）

1. **追问：多次调用如何优化？** 思路：分治法，5 步完成——`((n & 0x55555555) << 1) | ((n >> 1) & 0x55555555)` 交换相邻位，再用 `0x33333333`、`0x0F0F0F0F`、`0x00FF00FF`、`0x0000FFFF` 依次交换 2/4/8/16 位组，最后整体移位对齐。每步 O(1)，共 5 步，比 32 轮快一个常数因子，且无分支、适合流水线。
2. **追问：如果位宽不是 32 而是动态的 `w`？** 思路：把 `range(32)` 换成 `range(w)`，或先求 `w = n.bit_length()` 再循环；分治版则按 `w` 的对数选掩码层数。
3. **追问：不用循环，用查表怎么做？** 思路：预计算 8 位（256 项）的反转表，把 32 位拆成 4 个字节，查表后按字节逆序拼接：`table[n & 0xFF] << 24 | table[(n >> 8) & 0xFF] << 16 | ...`，时间 O(1) 但常数是 4 次查表 + 移位，空间 O(256)。

## 9. 举一反三（2-3 道同类题）

- **191. 位 1 的个数**：同样逐位取 `n & 1` 并右移，共同点是"用最低位 + 右移"遍历所有比特。
- **338. 比特位计数**：对 `0..n` 每个数求 1 的个数，共同点是位运算的逐位分解思想，可用 `dp[i] = dp[i >> 1] + (i & 1)` 复用子问题。
- **461. 汉明距离**：先 `x ^ y` 再数 1 的个数，共同点是"异或暴露差异位、再逐位统计"的组合套路。
