## 1. 一句话本质

把一串按「从大到小、左减右加」规则编码的符号，逐字符翻译回它对应的十进制数值并累加。

## 2. 读完题的第一反应

**朴素解法**：把七个字符和数值做成字典，从左到右扫一遍，每个字符查表拿到值，全部加起来。

这个思路对 `III`、`XII`、`LVIII` 都对，但一碰到 `IV` 就崩：查表得 `1 + 5 = 6`，而正确答案是 4。也就是说，朴素解法卡在「减法组合」上——它把每个字符当成独立贡献，忽略了「小字符在大字符左边时要被减掉」这条规则。

**关键观察**：题面明确说「小的数字在大的数字的右边」是常态，特例只有六种（`IV/IX/XL/XC/CD/CM`）。再仔细看这六种特例的共同结构：**它们都是「前一个字符的值 < 后一个字符的值」**。`IV` 里 1 < 5，`CM` 里 100 < 1000。而正常情况（如 `VI`、`MC`）永远是前 ≥ 后。

于是问题被转化成一个纯比较问题：**扫描时看当前字符和下一个字符，如果当前 < 下一个，当前这个值就取负号；否则取正号。** 这样 `IV` 变成 `-1 + 5 = 4`，`VI` 变成 `5 + 1 = 6`，两种情形用同一套逻辑覆盖，不需要单独枚举六种组合。

这个观察之所以能直接导向解法，是因为它把「识别特例」这种容易漏分支的工作，压缩成了一个统一的、逐位置的局部判断——你不需要记住哪六种是特例，只需要比较相邻两个数的大小。

## 3. 从暴力到最优

**第一步：朴素累加（错误示范）**

以 `MCMXCIV` 为例，逐字符查表累加：

```
M=1000 → 1000
C=100  → 1100
M=1000 → 2100
X=10   → 2110
C=100  → 2210
I=1    → 2211
V=5    → 2216
```

得到 2216，正确答案是 1994。差了 222，正好是 `CM`(应 900 却算成 1100，多 200)、`XC`(应 90 却算成 110，多 20)、`IV`(应 4 却算成 6，多 2) 三处减法组合被当成加法多算的部分。瓶颈就在这里：**每个减法组合被多算了两倍的小数值**（本该减 1 却加了 1，误差 2）。

**第二步：相邻比较，符号修正**

不再无脑加，而是对每个位置 `i` 判断：`s[i]` 的值是否小于 `s[i+1]` 的值。

走一遍 `MCMXCIV`，用 `vals` 存每个字符的值 `[1000,100,1000,10,100,1,5]`：

| i | 当前值 | 下一个值 | 比较 | 贡献 | 累计 |
|---|--------|----------|------|------|------|
| 0 | 1000 | 100 | 1000 ≥ 100 | +1000 | 1000 |
| 1 | 100 | 1000 | 100 < 1000 | −100 | 900 |
| 2 | 1000 | 10 | 1000 ≥ 10 | +1000 | 1900 |
| 3 | 10 | 100 | 10 < 100 | −10 | 1890 |
| 4 | 100 | 1 | 100 ≥ 1 | +100 | 1990 |
| 5 | 1 | 5 | 1 < 5 | −1 | 1989 |
| 6 | 5 | 无 | 末位默认加 | +5 | 1994 |

结果 1994，与示例一致。注意 `i=1` 的 `C` 被减掉、`i=2` 的 `M` 照常加，合起来 `-100+1000=900`，正好是 `CM` 的值——**减法组合被拆成「减小的、加大的」两步，天然拼出正确结果**。

**第三步：这就是最优**

第二步已经是 O(n) 单次扫描，每个字符只查一次表、做一次比较。没有更低的复杂度空间了，因为至少要把每个字符读一遍。所以「从暴力到最优」的终点就是这一步，不需要再优化。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。定义扫描到位置 `i` 时，累计变量 `total` 满足：

> **不变量**：`total` 等于 `s[0..i-1]` 这段前缀所表示的整数值。

**初始**：`i=0` 时前缀为空，`total=0`，成立。

**归纳步**：假设处理完 `s[0..i-1]` 后不变量成立，现在处理 `s[i]`。分两种情形：

- 若 `val(s[i]) ≥ val(s[i+1])`（或 `i` 是末位）：说明 `s[i]` 不是任何减法组合的左半部分，它独立贡献正值。题面规则「小的在大的右边」保证此时 `s[i]` 应整体加上，`total += val(s[i])` 后前缀含义正确扩展。
- 若 `val(s[i]) < val(s[i+1])`：题面限定这种「小在左」只出现在六种合法组合中，且组合的语义是「大减小」。把 `s[i]` 记为 `−val(s[i])`，下一步 `s[i+1]` 会被记为 `+val(s[i+1])`（因为 `s[i+1]` 比它右边大或到末尾），两者相加恰好等于 `val(s[i+1]) − val(s[i])`，即该组合的值。前缀含义仍正确。

两种情形都保持不变量。扫描结束时 `i=n`，前缀就是整个串，`total` 即答案。

**不漏**：每个位置恰好被访问一次，每个字符恰好贡献一次带符号的值。
**不重**：减法组合虽然涉及两个字符，但只在左字符处取负、右字符处取正，各贡献一次，没有字符被加两次。

这里依赖题面给的保证「数据保证是有效罗马数字」，所以不会出现 `IM` 这种非法组合——若出现，上述归纳步的第二种情形会失效，但题目排除了这种情况。

## 5. 完整代码（Python）

```python
class Solution:
    def romanToInt(self, s: str) -> int:
        # 七个基本符号到数值的映射，查表 O(1)
        value = {
            'I': 1, 'V': 5, 'X': 10, 'L': 50,
            'C': 100, 'D': 500, 'M': 1000,
        }

        total = 0
        n = len(s)

        for i in range(n):
            cur = value[s[i]]
            # 若不是末位，且当前值小于下一位的值，说明处在减法组合的左半边
            if i + 1 < n and cur < value[s[i + 1]]:
                total -= cur          # 左半边取负
            else:
                total += cur          # 其余情况（含末位）取正

        return total
```

关键逻辑说明：
- `i + 1 < n` 这个条件保证末位不会越界访问 `s[i+1]`，末位永远走 `else` 分支取正——这符合「最后一个字符不可能是减法组合左半边」的事实。
- `cur < value[s[i+1]]` 是整道题唯一的分支判断，它同时覆盖了「正常加法」和「六种减法组合」，不需要额外枚举。

## 6. 复杂度

**时间 O(n)**：`n = len(s)`，循环执行 `n` 次，每次做一次字典查询（O(1)）和一次整数比较（O(1)），所以总时间是 `n × O(1) = O(n)`。这里没有 log 项，因为不存在分治或排序。

**空间 O(1)**：字典固定 7 个键值对，与 `n` 无关；`total`、`cur`、`i` 都是常数个变量。没有开辟与输入规模相关的额外结构（比如没有把整个串转成数组），所以是常数空间。

## 7. 边界与反例（至少 4 条）

1. **`s = "I"` → 1**：单字符，`i+1 < n` 为假，走 `else` 加 1。容易错在循环里忘了判越界，直接访问 `s[1]` 抛 `IndexError`。
2. **`s = "IV"` → 4**：`I` 的值 1 < `V` 的值 5，`I` 取负，`-1+5=4`。容易错在只写无脑累加，得 6。
3. **`s = "VI"` → 6**：`V` 的值 5 ≥ `I` 的值 1，`V` 取正，`5+1=6`。这是「大在左」的正常情形，容易和 `IV` 混淆——两者字符相同、顺序相反，结果差 2，必须靠比较大小区分，不能靠字符本身。
4. **`s = "MMMCMXCIX"` → 3999**：上界用例，包含 `CM`、`XC`、`IX` 三个减法组合，检验连续多个减法组合能否正确累加。容易错在只处理了第一个减法组合就停止判断。
5. **`s = "LVIII"` → 58**：`L=50`、`V=5`、`III=3`，全是加法，检验纯加法路径不被减法逻辑误伤（`V` 后面是 `I`，5 ≥ 1，取正，正确）。

## 8. 面试追问与变体（3 条）

1. **追问：如果输入不保证合法（可能出现 `IIII` 或 `IM`），怎么改？**
   思路：在相邻比较之外，额外校验「小在左」时是否属于六种合法组合，否则返回错误或按题面规则拒绝；同时可加一条「同一字符连续出现不超过 3 次」的检查。

2. **追问：反过来，给你整数，转成罗马数字（第 12 题），思路有何不同？**
   思路：那是「贪心 + 查表」，从大到小枚举 13 个「值-符号」对（含 `CM/XC/IX` 等组合对），能减就减并拼接；本题是「扫描 + 相邻比较」，方向相反，但都依赖同一张符号-数值表。

3. **追问：能不能不用字典，用 ASCII 码或数组下标做映射？**
   思路：七个字符的 ASCII 不连续，直接做数组下标会浪费空间；可以建一个长度 128 的数组按 ASCII 索引存值，查询仍是 O(1)，但可读性不如字典，属于微优化，面试中说明取舍即可。

2. **Excel 表列名称（第 168 题）**：同样是「符号序列 ↔ 数值」的进制式转换，核心都是建立字符到数值的映射后逐位累加/取模。
3. **字符串解码（第 394 题）**：同样需要「扫描字符串 + 根据局部相邻关系决定累加还是特殊处理」，是本题「相邻比较」思想在嵌套结构上的推广。
