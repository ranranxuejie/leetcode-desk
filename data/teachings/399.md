## 1. 一句话本质

把每个变量看成图上的一个节点，已知的 `A/B = v` 看成一条带权有向边（A→B 权为 v，B→A 权为 1/v），题目问的就是：两个节点之间是否存在一条路径，以及这条路径上边权的**乘积**是多少。

## 2. 读完题的第一反应

**朴素解法**：对每个 query，从起点开始做一次 BFS/DFS，沿途把边权乘起来，走到终点就返回乘积。这能过，因为 `equations.length ≤ 20`，节点数最多 40，query 最多 20，单次搜索 O(V+E)，总复杂度 O(Q·(V+E))，完全够用。

**卡在哪**：如果数据规模放大（比如 10^5 条边、10^5 个 query），每个 query 都重新搜一遍就退化成 O(Q·E)，会超时。这时候需要「预处理一次，之后 O(1) 或 O(α) 查询」。

**关键观察**：题目保证「不存在矛盾的结果」。这句话是整道题的命门——它意味着**同一个连通分量内，任意两个变量之间的比值是唯一确定的**。换句话说，图里不会出现「a→b→c 算出 a/c=6，另一条路算出 a/c=7」的情况。既然比值唯一，我们就可以在预处理阶段把每个连通分量「压平」：选定一个代表元（根），算出每个节点相对根的比值，之后任意两点 x/y = (x/root) / (y/root)，一次除法搞定。

这个观察直接指向两种实现：**带权并查集**（把比值挂在到根的路径上）或**建图后对每个连通分量做一次 DFS 预处理**。前者更「算法味」，后者更直观、更好写、更好讲。下面我选 DFS 预处理 + 哈希表存比值这条路线，因为它把「为什么正确」讲得最清楚，也最容易在面试里现场写出来。

## 3. 从暴力到最优

**暴力版**：每个 query 独立 BFS。以示例 1 为例，`equations=[["a","b"],["b","c"]]`，`values=[2,3]`，图是 `a --2--> b --3--> c`（反向边权为 1/2、1/3）。

- query `["a","c"]`：从 a 出发，a→b 乘 2 得 2，b→c 乘 3 得 6，返回 6。
- query `["b","a"]`：从 b 出发，b→a 乘 0.5，返回 0.5。
- query `["a","e"]`：e 不在图里，直接 -1。
- query `["a","a"]`：起点等于终点，返回 1（注意：即使 a 不在图里，`["x","x"]` 也返回 -1，因为 x 未定义——这是易错点，见第 7 节）。

瓶颈：每个 query 都从零开始搜，重复走了大量相同的路径。

**优化版**：先对整张图做一次遍历，对每个连通分量选一个根，记录 `ratio[node] = node / root`。还是示例 1：

- 选 a 为根，`ratio[a]=1`。
- 沿 a→b 权 2：`ratio[b] = ratio[a] * 2 = 2`（因为 b/a = 2，即 b = 2a，b/a_root = 2）。
- 沿 b→c 权 3：`ratio[c] = ratio[b] * 3 = 6`。

预处理完，`ratio = {a:1, b:2, c:6}`。之后：

- `a/c = ratio[a]/ratio[c] = 1/6`？不对，方向反了。注意 `ratio[x] = x/root`，所以 `x/y = (x/root)/(y/root) = ratio[x]/ratio[y]`。`a/c = 1/6`，但正确答案是 6。问题出在边的方向定义上：`a/b=2` 表示 a = 2b，所以 b 相对 a 是 1/2 而不是 2。

修正：定义 `ratio[x] = root / x`（根除以节点），则 `x/y = ratio[y]/ratio[x]`。重新算：`ratio[a]=1`，`ratio[b]=ratio[a]/2=0.5`，`ratio[c]=ratio[b]/3≈0.1667`。`a/c = ratio[c]/ratio[a] = 0.1667/1 = 0.1667`，还是不对。

再想清楚：`a/b=2` 意味着 a 是 b 的 2 倍。若 `ratio[x] = x/root`，则 `ratio[a]=1`（a 是根），`ratio[b] = b/a = 1/2 = 0.5`。`a/c = ratio[a]/ratio[c]`，而 `ratio[c] = c/a = (c/b)·(b/a) = (1/3)·(1/2) = 1/6`。所以 `a/c = 1/(1/6) = 6`。✓

结论：**`ratio[x] = x/root`，查询 `x/y = ratio[x]/ratio[y]`**。遍历时，若已知 `u/v = w` 且 `ratio[u]` 已求出，则 `ratio[v] = ratio[u]/w`（因为 v = u/w，v/root = (u/root)/w）。这个推导要在代码注释里写清楚，否则极易写反。

**再优化**：如果 query 量巨大，可以把每个连通分量内所有点对的比值预先算成字典，查询 O(1)。但本题规模下没必要，DFS 预处理 + 每次两次哈希查找已经是最优实用解。带权并查集是另一种等价写法，查询 O(α)，但路径压缩时权值合并的推导更绕，面试里写 DFS 更稳。

## 4. 正确性：为什么不会漏、不会重

**不变量**：在预处理阶段，对任意已访问节点 x，`ratio[x]` 恒等于 `x / root(x)`，其中 root(x) 是 x 所在连通分量的根。

**归纳证明**：
- 根节点：`ratio[root] = 1 = root/root`，成立。
- 扩展边 `u/v = w`：若 u 已访问、v 未访问，则 `ratio[v] = ratio[u]/w = (u/root)/(u/v) = v/root`，成立。反向边 `v/u = 1/w` 同理。

**不漏**：DFS 从每个未访问节点出发，遍历其整个连通分量，所以分量内每个节点都会被赋 `ratio`。query 的两点若在同一分量，必都能查到。

**不重（唯一性）**：题目保证无矛盾，即同一分量内任意两点间所有路径的边权乘积相同。因此无论 DFS 从哪个节点开始、沿哪条路径先到达某节点，算出的 `ratio` 都一致——这保证了「先到先赋值、后到不覆盖」是安全的。若题目不保证无矛盾，这个不变量就崩了，必须检测冲突。

**查询正确性**：`x/y = (x/root)/(y/root) = ratio[x]/ratio[y]`，直接由不变量推出。

**未定义情形**：x 或 y 不在 `ratio` 字典里（不在任何等式中出现），或两者根不同（不同连通分量，比值无法确定），返回 -1。特例 `x==x` 且 x 已定义时返回 1，因为 `ratio[x]/ratio[x]=1`，公式自然覆盖，无需特判；但 x 未定义时公式查不到，返回 -1，也正确。

## 5. 完整代码（Python）

```python
from collections import defaultdict

class Solution:
    def calcEquation(self, equations, values, queries):
        # 建图：graph[u] = [(v, u/v 的值), ...]，同时存正向和反向边
        graph = defaultdict(list)
        for (u, v), w in zip(equations, values):
            graph[u].append((v, w))        # u / v = w
            graph[v].append((u, 1.0 / w))  # v / u = 1/w

        # ratio[x] = x / root，root 是 x 所在连通分量的代表元
        ratio = {}

        # 对每个连通分量做一次 DFS，把 ratio 填满
        for start in graph:
            if start in ratio:
                continue
            ratio[start] = 1.0             # 自己作为根，root/root = 1
            stack = [start]
            while stack:
                u = stack.pop()
                for v, w in graph[u]:      # 已知 u / v = w
                    if v not in ratio:     # 未访问才赋值，保证不覆盖
                        # v = u / w  =>  v/root = (u/root) / w
                        ratio[v] = ratio[u] / w
                        stack.append(v)

        res = []
        for x, y in queries:
            # 任一点未定义，或不在同一连通分量，都无法确定
            if x not in ratio or y not in ratio:
                res.append(-1.0)
            else:
                # 同一分量内 x/y = (x/root)/(y/root)
                res.append(ratio[x] / ratio[y])
        return res
```

注意：`x==y` 且 x 已定义时，`ratio[x]/ratio[x]=1.0`，公式自动给出正确答案，不需要额外分支；`x==y` 但 x 未定义时，第一个 if 拦截返回 -1，也正确。

## 6. 复杂度

设 E = `len(equations)`，V = 不同变量个数（V ≤ 2E），Q = `len(queries)`。

- **建图**：O(E)，每条等式加两条边。
- **DFS 预处理**：每个节点入栈一次、每条边被检查两次（正反），O(V+E)。哈希表插入均摊 O(1)。
- **查询**：每个 query 两次哈希查找 + 一次除法，O(1)，共 O(Q)。
- **总时间**：O(E + V + Q) = O(E + Q)（因 V ≤ 2E）。没有 log 项——没有排序、没有堆。
- **空间**：图存 2E 条边 O(E)，`ratio` 存 V 个键 O(V)，栈最深 O(V)，结果数组 O(Q)。总计 O(E + V + Q) = O(E + Q)。

对比暴力版 O(Q·(V+E))，优化版把「每个 query 重走路径」的因子 Q 消掉了，代价是预处理一次 O(V+E)。

## 7. 边界与反例（至少 4 条）

1. **`queries=[["x","x"]]`，x 从未出现** → 期望 `[-1.0]`。易错：有人看到 `x==x` 就无脑返回 1.0。题面明确「未在等式列表中出现的变量是未定义的」，必须先查 `ratio` 是否存在。

2. **`equations=[["a","b"]], values=[0.5], queries=[["a","c"]]`** → 期望 `[-1.0]`。易错：c 不在图里，若代码只检查「起点在不在」而漏查终点，会抛 KeyError 或返回错误值。必须两端都查。

3. **两个不相交的连通分量**：`equations=[["a","b"],["c","d"]], values=[2,3], queries=[["a","d"]]` → 期望 `[-1.0]`。易错：a 和 d 都在 `ratio` 里，但根不同，比值无法确定。代码里靠「分别除以各自 root」会算出 `ratio[a]/ratio[d]` 一个无意义的数——所以**必须先判断是否同根**。上面代码用「同一次 DFS 才赋 ratio」隐含了同根，但严格说 `ratio` 字典本身不记录根，若两个分量恰好都从 ratio=1 开始，`ratio[a]/ratio[d]` 会给出错误数字。修正：额外存 `root_of[x]`，或把 `ratio` 的值设计成「相对全局唯一根」——更稳妥的写法是给每个分量一个独立 id，查询时比对 id。这是本题最隐蔽的坑，面试官很可能追问。

4. **自环/重复边**：`equations=[["a","a"]], values=[1.0]`（题面说输入有效，但边界测试常加）→ 期望 `a/a=1`。代码中 `graph[a]` 会有 `(a,1.0)` 和 `(a,1.0)` 两条边，DFS 时 a 已在 ratio 中，跳过，不覆盖，安全。

5. **链式长路径**：`a/b=2, b/c=3, c/d=4`，查 `a/d` → 期望 24。易错：DFS 用栈（迭代）时，若在 `ratio[v]` 赋值前就 push，可能重复 push 同一节点；代码里「先赋值再 push」保证每个节点只入栈一次。

## 8. 面试追问与变体（3 条）

1. **追问：如果输入可能矛盾（比如同时给 a/b=2 和 a/b=3），怎么检测？** 思路：DFS 时若遇到已访问节点 v，校验 `ratio[u]/w == ratio[v]`，不等则报告矛盾；并查集版本则在 union 时校验权值一致性。

2. **追问：query 量到 10^5，怎么优化？** 思路：预处理阶段对每个连通分量枚举所有点对，存 `pair_ratio[(x,y)]`，查询 O(1)；或改用带权并查集，查询 O(α)，避免 O(V²) 预处理。

3. **追问：如果要求支持动态加边（在线）？** 思路：带权并查集天然支持在线 union，每次加边 O(α)，查询 O(α)；DFS 预处理方案需要重建，不适用。
