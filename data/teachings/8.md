## 1. 一句话本质

在字符串上做一次**从左到右的单向扫描**，按「跳空格 → 读符号 → 读数字 → 截断」四段固定顺序抽取一个整数，遇到第一个不合法的字符就立刻停手。

注意这句话里两个关键词：**单向**（不回头、不回溯）和**立刻停手**（不是"跳过非法字符继续找数字"）。示例 5 `"words and 987"` 输出 0 而不是 987，示例 4 `"0-1"` 输出 0 而不是 -1，都是在告诉你：一旦进入"读数字"阶段，遇到非数字就结束，后面即使还有数字也不要。

## 2. 读完题的第一反应

**朴素解法**：用正则一把梭，`re.match(r'^\s*([+-]?\d+)', s)`，拿到匹配串再 `int()`，最后 clamp。这写法能过，但它把题目拆成了"正则引擎的黑盒 + 一个 int 转换"，面试官问"如果不能用正则呢"你就卡住了。而且正则的 `\d+` 会把 `"00000000000000000000042"` 整段吞进去再交给 `int()`，虽然 Python 大整数不怕溢出，但你就失去了"在扫描过程中就做截断"这个考点——而截断恰恰是本题最容易写错的地方。

**关键观察**：题面把算法拆成了四步，且这四步是**严格有序、互不重叠**的。空格只可能在最前面；符号只可能在空格之后、数字之前，且最多一个；数字只可能在符号之后连续出现。这意味着整个流程可以写成一个"指针一路向右走"的状态机，每个字符只被看一次。

这个观察直接决定了下一步：既然每个字符只看一次，那就不需要任何额外数据结构，一个下标 `i` 加一个累加变量 `num` 就够了。空间复杂度天然是 O(1)。

## 3. 从暴力到最优

**暴力版**：先 `s = s.lstrip()` 去掉前导空格，再判断 `s[0]` 是不是符号，然后 `while s[i].isdigit()` 把数字子串切出来，最后 `int(子串)` 再 clamp。

瓶颈在哪？`int(子串)` 这一步。如果子串有 200 位（题面 `s.length <= 200`），Python 会老老实实构造一个 200 位的大整数，然后再和 `2^31-1` 比较。虽然 200 位对 Python 不算事，但**这个思路在 C++/Java 里会溢出**，而且它违背了题面"舍入"那一步的精神——题面要的是"边读边判断是否越界"，而不是"读完再判断"。

**消掉瓶颈的办法**：不要先拼字符串再转换，而是**边读边累加**：`num = num * 10 + digit`。每加一位，就立刻检查 `num` 是否已经超过 `INT_MAX // 10` 或者等于 `INT_MAX // 10` 且当前位 `> 7`。一旦超了，直接返回边界值，后面的字符连看都不用看。

**小例子走一遍**：`s = "  -042"`，`INT_MAX = 2147483647`。

| 步骤 | i | 字符 | 动作 | sign | num |
|---|---|---|---|---|---|
| 跳空格 | 0→2 | `' '`,`' '` | i 右移 | 1 | 0 |
| 读符号 | 2 | `'-'` | sign = -1, i=3 | -1 | 0 |
| 读数字 | 3 | `'0'` | num = 0*10+0 = 0 | -1 | 0 |
| 读数字 | 4 | `'4'` | num = 0*10+4 = 4 | -1 | 4 |
| 读数字 | 5 | `'2'` | num = 4*10+2 = 42 | -1 | 42 |
| 结束 | 6 | 越界 | 停 | -1 | 42 |

返回 `-1 * 42 = -42`。注意前导零 `'0'` 那一步 `num` 还是 0，天然被"跳过"了，不需要专门写跳零逻辑——这是 `num*10+digit` 这个累加式的一个免费好处。

再看一个触发截断的：`s = "2147483648"`（比 INT_MAX 大 1）。

读到第 10 位 `'8'` 时，`num = 214748364`，此时 `num == INT_MAX // 10`（214748364）且 `digit = 8 > 7`，判定溢出，正数返回 `2147483647`。如果 `s = "-2147483648"`，同样在第 10 位触发，但负数下界是 `-2147483648`，所以负数溢出时返回 `-2147483648`。**正负溢出的返回值不同**，这是本题最阴的坑，第 7 节会再提。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来论证。设扫描指针为 `i`，定义不变量：

> 在处理完第 `i` 个字符后，`num` 恰好等于 `s[0..i]` 中"有效数字部分"所表示的数值（不含符号），且 `i` 左侧的所有字符都已被正确分类为"空格 / 符号 / 数字 / 终止符"四类之一。

**初始化**：`i = 0, num = 0`，空串的有效数字部分数值为 0，成立。

**保持**：分四种情况。若 `s[i]` 是空格且尚未遇到非空格，则它属于"前导空格"，不改变 `num`，`i` 右移，不变量保持；若 `s[i]` 是符号且尚未遇到数字，则它只改变 `sign`，不改变 `num`；若 `s[i]` 是数字，则 `num_new = num_old * 10 + digit`，这正是"在旧数值末尾追加一位"的数学定义，不变量保持；若 `s[i]` 是其他字符，则循环终止，不变量在终止点仍成立。

**终止**：循环在 `i == len(s)` 或遇到非法字符时结束。此时 `num` 就是全部有效数字的数值，乘以 `sign` 并 clamp 后即为答案。

**为什么不会漏**：四类字符的判定是互斥且完备的（题面保证 `s` 只含字母、数字、空格、`+`、`-`、`.`），每个字符必然落入某一类，循环不会提前跳过任何字符。

**为什么不会重**：`i` 单调递增，每个字符恰好被访问一次，`num` 的更新是"追加"而非"重算"，不存在重复累加。

**截断的正确性**：在追加第 `k` 位之前判断 `num > INT_MAX // 10` 或 `num == INT_MAX // 10 and digit > 7`，等价于判断"追加后是否超过 INT_MAX"。因为 `num * 10 + digit > INT_MAX` ⟺ `num > (INT_MAX - digit) / 10`，而整数除法下这等价于上述条件。一旦判定溢出，真实值只会更大（后续位只会让数变大），所以直接返回边界值不会错。

## 5. 完整代码（Python）

```python
class Solution:
    def myAtoi(self, s: str) -> int:
        INT_MAX = 2**31 - 1      # 2147483647
        INT_MIN = -2**31         # -2147483648
        n = len(s)
        i = 0

        # 第 1 步：跳过前导空格
        while i < n and s[i] == ' ':
            i += 1

        # 第 2 步：读符号，默认正号
        sign = 1
        if i < n and s[i] in '+-':
            if s[i] == '-':
                sign = -1
            i += 1

        # 第 3 步：读数字并边读边截断
        num = 0
        while i < n and s[i].isdigit():
            digit = ord(s[i]) - ord('0')
            # 溢出预判：先看会不会超，再决定是否累加
            # 正数上限末位是 7，负数下界末位是 8
            limit = 7 if sign == 1 else 8
            if num > INT_MAX // 10 or (num == INT_MAX // 10 and digit > limit):
                return INT_MAX if sign == 1 else INT_MIN
            num = num * 10 + digit
            i += 1

        # 第 4 步：带符号返回（未溢出时 num 一定在范围内）
        return sign * num
```

几个值得讲的细节：

- `s[i].isdigit()` 在 Python 里对 Unicode 数字也返回 True（比如 `'²'`），但题面保证输入只含 ASCII 数字，所以安全。严谨写法是 `'0' <= s[i] <= '9'`，面试时提一句能加分。
- `limit` 的取值 `7 / 8` 来自 `INT_MAX` 末位是 7、`INT_MIN` 绝对值末位是 8。这是本题唯一需要"背"的常量，但你可以现场推：`2^31-1 = 2147483647`，末位 7；`2^31 = 2147483648`，末位 8。
- 溢出判断放在 `num = num*10 + digit` **之前**，这样 `num` 永远不会超过 `INT_MAX // 10`，Python 里虽然不会溢出，但这个顺序让逻辑和 C++ 版本一一对应，面试官一看就知道你懂底层。

## 6. 复杂度

**时间 O(n)**：`n = len(s)`。三个 while 循环的指针 `i` 都只增不减，且三个循环的区间互不重叠（空格段、符号段、数字段），所以每个字符最多被访问一次，总访问次数 ≤ n。没有嵌套循环，没有排序，没有 log 项。

**空间 O(1)**：只用了 `i, sign, num, digit, limit` 五个标量变量，与 `n` 无关。没有切片、没有 `int(子串)` 产生的大整数对象、没有额外列表。

对比一下暴力版：`int(子串)` 在子串长度为 `m` 时是 O(m) 时间 + O(m) 空间（构造大整数），虽然总时间仍是 O(n)，但空间从 O(1) 退化到 O(n)。这就是"边读边截断"相对"读完再截断"的实际收益。

## 7. 边界与反例（至少 4 条）

1. **`s = ""`** → 期望 `0` → 容易错在没处理空串，`s[0]` 直接 IndexError。代码里 `i < n` 的守卫就是防这个。
2. **`s = "   "`**（全空格）→ 期望 `0` → 跳空格后 `i == n`，符号判断和数字判断的 `i < n` 守卫必须都在，漏一个就崩。
3. **`s = "+-12"`** → 期望 `0` → 容易错在把 `+` 和 `-` 都读了。正确行为是只读第一个符号 `+`，然后 `s[1] = '-'` 不是数字，立即停，返回 0。
4. **`s = "-2147483648"`** → 期望 `-2147483648` → 容易错在溢出判断用了 `digit > 7` 一刀切，导致这个合法下界被误判为溢出返回 `INT_MIN`（碰巧结果一样，但逻辑错了）；更隐蔽的是 `s = "-2147483649"` 才该返回 `INT_MIN`，两者要区分开。
5. **`s = "2147483648"`** → 期望 `2147483647` → 正数溢出返回 `INT_MAX`，不是 `INT_MIN`，符号别搞反。
6. **`s = "00000000000000000000000000000000000000000000000042"`** → 期望 `42` → 前导零很多时，`num` 一直是 0，不会误触发溢出判断（因为 `0 > INT_MAX//10` 为假），这是累加式天然处理的，不需要专门跳零。

## 8. 面试追问与变体（3 条）

1. **追问：如果输入是 64 位整数范围，怎么改？** 思路：把 `INT_MAX` 换成 `2^63-1`，`limit` 换成 `7/8` 的对应值（`2^63-1` 末位仍是 7），逻辑完全不变——截断判断是参数化的，改常量即可。
2. **追问：如果要求支持小数点（变成 atof）？** 思路：在数字段后加一个"是否遇到 `.`"的分支，遇到后继续读数字但用 `frac = frac * 10 + digit, scale *= 10` 累加小数部分，最后 `num + frac/scale`。截断逻辑要挪到整数部分结束时。
3. **追问：如果要求支持科学计数法 `1e10`？** 思路：读完尾数后检查 `s[i] in 'eE'`，再递归调用一次 `myAtoi` 读指数，最后 `num * 10**exp`，注意指数也要截断防止 `10**exp` 爆炸。
