## 1. 一句话本质

在有序数组里找**第一个大于等于 target 的位置**——target 存在时它就是 target 的下标，不存在时它就是插入点。

## 2. 读完题的第一反应

最直白的做法是从头扫到尾：遇到第一个 `nums[i] >= target` 就返回 `i`，扫完都没遇到就返回 `len(nums)`。这个解法在示例上全对，但它卡在**复杂度**上——题面明确要求 O(log n)，而线性扫描是 O(n)。这个约束不是装饰，它在提示你：数组有序，别浪费这个信息。

关键观察是：把数组按「是否小于 target」切成两半，左半部分全部 `< target`，右半部分全部 `>= target`。因为数组升序，这个切分点**唯一存在**，而且一旦确定了某个位置是 `< target`，它左边所有位置必然也 `< target`；一旦确定某位置 `>= target`，它右边所有位置必然也 `>= target`。这种「一个判断能排除一整片」的结构，正是二分查找的适用条件。我们要找的就是这条分界线的位置。

## 3. 从暴力到最优

**暴力**：`for i in range(len(nums))`，逐个比较，第一个 `>= target` 就返回。瓶颈在于最坏要看 n 个元素，n 到 10^4 时虽然也能过，但违反题面的 O(log n) 要求。

**二分**：维护一个「答案一定在 `[left, right]` 里」的区间，每次看中点，用中点值把区间砍掉一半。

用示例 2 走一遍：`nums = [1,3,5,6], target = 2`，我们要找第一个 `>= 2` 的位置。

初始 `left = 0, right = 4`（注意 right 取 `len(nums)`，是「开区间」的右端，含义见第 4 节）。

- 第 1 轮：`mid = (0+4)//2 = 2`，`nums[2] = 5 >= 2`，说明答案在 mid 或 mid 左边，令 `right = 2`。区间变成 `[0,2)`。
- 第 2 轮：`mid = (0+2)//2 = 1`，`nums[1] = 3 >= 2`，令 `right = 1`。区间变成 `[0,1)`。
- 第 3 轮：`mid = (0+1)//2 = 0`，`nums[0] = 1 < 2`，说明答案在 mid 右边，令 `left = 1`。区间变成 `[1,1)`，为空，循环结束。
- 返回 `left = 1`，与期望输出一致。

再看示例 3：`target = 7`，所有元素都 `< 7`，每一轮都走 `left = mid + 1` 分支，最终 `left` 一路推到 4，返回 4，正好是「插到末尾」。

对比一下：暴力每轮只排除 1 个元素，二分每轮排除一半。n = 10^4 时，暴力最坏 10^4 次比较，二分约 14 次（log₂10^4 ≈ 13.3）。这就是「瓶颈被消掉」的具体含义——不是代码变短了，是每轮的信息利用率从 1/n 变成了 1/2。

## 4. 正确性：为什么不会漏、不会重

用**循环不变量**来讲。我们维护的区间是 `[left, right)`，不变量有两条：

1. `[0, left)` 中所有元素都 `< target`；
2. `[right, len(nums))` 中所有元素都 `>= target`。

初始时 `left = 0, right = len(nums)`，两个区间都是空的，不变量平凡成立。

每轮取 `mid = (left + right) // 2`，此时必有 `left <= mid < right`（因为区间非空时 `right > left`，整数除法保证 mid 落在区间内），所以 `nums[mid]` 是「尚未判定」的元素：

- 若 `nums[mid] >= target`：由升序，`mid` 及其右边全部 `>= target`，于是把 `right` 收缩到 `mid`，不变量 2 依然成立（新纳入的 `[mid, 旧right)` 都满足条件），不变量 1 不受影响。
- 若 `nums[mid] < target`：由升序，`mid` 及其左边全部 `< target`，于是 `left = mid + 1`，不变量 1 依然成立，不变量 2 不受影响。

每轮区间严格缩小（`right` 变小或 `left` 变大，且 `mid` 被排除），所以循环必然终止于 `left == right`。此时区间为空，由不变量 1，`[0, left)` 全 `< target`；由不变量 2，`[left, n)` 全 `>= target`。也就是说 `left` 恰好是第一个 `>= target` 的下标——这正是题目要的答案。**不会漏**：所有被排除的元素都被不变量「记账」了；**不会重**：每轮 mid 只被判定一次就永久移出待定区间。

## 5. 完整代码（Python）

```python
class Solution:
    def searchInsert(self, nums, target):
        # 在 [left, right) 中找第一个 >= target 的下标
        # right 取 len(nums) 而非 len(nums)-1，是为了让「插到末尾」这种情况
        # 也能被区间自然覆盖，不需要额外特判
        left, right = 0, len(nums)

        while left < right:          # 区间非空才继续
            mid = (left + right) // 2  # mid 一定落在 [left, right) 内
            if nums[mid] >= target:
                # mid 可能是答案，不能排除，所以 right = mid（不是 mid-1）
                right = mid
            else:
                # nums[mid] < target，mid 及其左边都不可能是答案
                left = mid + 1

        # 循环结束时 left == right，即第一个 >= target 的位置
        return left
```

关键点只有两处：`right` 初始化为 `len(nums)`（开区间写法），以及 `nums[mid] >= target` 时 `right = mid` 而不是 `mid - 1`——因为 `mid` 本身可能就是答案，排除它就错了。这两处是二分最容易写错的地方，第 7 节会专门展开。

## 6. 复杂度

**时间 O(log n)**：每轮循环把区间长度从 `right - left` 缩到至多一半（`mid` 要么成为新右端，要么被排除），所以最多执行 ⌈log₂ n⌉ 轮。每轮只做一次比较和常数次赋值，故总比较次数是 O(log n)。这里的 log 来自「每次砍一半」，n 是数组长度。

**空间 O(1)**：只用了 `left, right, mid` 三个整型变量，与 n 无关。没有递归、没有额外数组。

## 7. 边界与反例（至少 4 条）

1. `nums = [1], target = 0` → 期望 `0`。容易错在把 `right` 初始化为 `len(nums)-1 = 0`，此时 `left == right` 直接不进循环，返回 0 碰巧对；但换成 `target = 2` 就返回 0 而期望 1——闭区间写法必须额外处理「插到末尾」，开区间写法天然覆盖。

2. `nums = [1,3,5,6], target = 7` → 期望 `4`。容易错在循环条件写成 `left <= right` 且 `right = len(nums)-1`，最后 `left` 可能越界到 4 但代码里又访问了 `nums[mid]` 导致 IndexError；或者返回 `right` 得到 3。

3. `nums = [1,3,5,6], target = 0` → 期望 `0`。容易错在 `nums[mid] >= target` 分支写成 `right = mid - 1`，把可能的答案排除了，最终返回 -1 或 0 之外的错误值。

4. `nums = [1,3], target = 3` → 期望 `1`（target 存在，返回其下标）。容易错在把「找到 target」和「找插入点」当成两件事写两段逻辑，第二段边界没处理好；本题的妙处就是二者是同一个位置，一段二分即可。

5. `nums = [1,3], target = 2` → 期望 `1`。这是「夹在中间」的情况，mid 判定两次后 `left` 停在 1，验证 `right = mid` 而非 `mid-1` 的必要性。

## 8. 面试追问与变体（3 条）

1. **追问：如果数组有重复元素，要返回 target 第一次出现的位置，怎么办？** 思路：本题代码原样就能用——「第一个 `>= target`」在有重复时恰好就是第一次出现的位置，这正是 `bisect_left` 的语义。

2. **追问：如果要返回 target 最后一次出现的位置呢？** 思路：改成找「第一个 `> target`」的位置再减 1，即把判定条件从 `nums[mid] >= target` 改为 `nums[mid] > target`，对应 `bisect_right - 1`。

3. **追问：不用二分，用 Python 标准库怎么写？** 思路：`import bisect; return bisect.bisect_left(nums, target)`，一行搞定，但面试官要的是你能手写并解释不变量，库函数只是对照验证。

## 9. 举一反三（2-3 道同类题）

- **34. 在排序数组中查找元素的第一个和最后一个位置**：同一套「找第一个 `>= x`」的二分骨架，调用两次（一次找左界、一次找右界）即可。
- **69. x 的平方根**：在 `[0, x]` 这个「有序答案空间」上二分，判定条件是 `mid*mid <= x`，本质仍是找分界点。
- **875. 爱吃香蕉的珂珂**：二分答案的典型——答案空间（速度）有序，判定函数单调，用二分找最小可行值，和本题「找第一个满足条件的位置」是同一个思维模型。
