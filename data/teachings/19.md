## 1. 一句话本质

在**不知道链表总长度**的前提下，定位并摘掉「从尾部数第 n 个」结点——难点不在删除，而在**定位**。

## 2. 读完题的第一反应

**朴素解法**：先遍历一遍数出总长 `sz`，倒数第 n 个就是正数第 `sz - n + 1` 个，再从头走 `sz - n` 步，删掉它的后继。这解法完全正确，卡在**两趟扫描**：第一趟纯粹为了「量长度」，第二趟才干活。题面末尾那句「你能尝试使用一趟扫描实现吗」就是在点这个瓶颈。

**关键观察**：倒数第 n 个结点，等价于「从它往后数，恰好还有 n 个结点（含它自己）」。也就是说，如果我能让两个指针保持**固定间距 n**，那么当后面的指针走到链表末尾时，前面的指针就正好停在待删结点的前一个位置。这个观察之所以能立刻导向下一步，是因为它把「需要知道总长」这个全局信息，换成了「两个指针之间的相对距离」这个局部信息——而相对距离是可以在一次前进中维持的。

## 3. 从暴力到最优

**暴力**：两趟。第一趟 `sz` 步，第二趟 `sz - n` 步，合计约 `2sz - n` 步。

**优化**：引入哑结点 `dummy`（指向 head），让 `fast` 和 `slow` 都从 `dummy` 出发。先让 `fast` 单独走 `n + 1` 步，此时 `fast` 与 `slow` 相距 `n + 1` 个结点。然后两者同步前进，直到 `fast` 变成 `None`。此时 `slow` 恰好停在待删结点的**前驱**上，执行 `slow.next = slow.next.next` 即可。

为什么是 `n + 1` 而不是 `n`？因为我们要让 `slow` 停在**前驱**，删除才不用额外记录父结点。这个 +1 是本题最容易写错的地方，第 7 节会专门给反例。

**小例子走一遍**：`head = [1,2,3,4,5]`，`n = 2`。链表加哑结点后是 `dummy(0) -> 1 -> 2 -> 3 -> 4 -> 5`。

| 阶段 | fast 指向 | slow 指向 |
|---|---|---|
| 初始 | dummy | dummy |
| fast 走 3 步（n+1=3）后 | 3 | dummy |
| 同步走 1 步 | 4 | 1 |
| 同步走 2 步 | 5 | 2 |
| 同步走 3 步 | None | 3 |

`fast` 到 `None` 时 `slow` 在结点 `3` 上，`slow.next` 是 `4`（正是倒数第 2 个），执行 `slow.next = slow.next.next` 后链表变成 `1 -> 2 -> 3 -> 5`，返回 `dummy.next` 即 `[1,2,3,5]`。全程只走了一趟。

再验证一下 `n = 1`、`head = [1,2]`：`fast` 先走 2 步到结点 `2`，`slow` 在 `dummy`；同步走 1 步，`fast` 到 `None`，`slow` 到结点 `1`；删 `slow.next`（结点 `2`），得 `[1]`，与示例 3 一致。

## 4. 正确性：为什么不会漏、不会重

用**不变量**来论证。设链表（含哑结点）共 `L = sz + 1` 个结点，编号 0 到 `sz`，其中 0 是 `dummy`，`sz` 是尾结点。

**不变量**：在同步前进阶段，任意时刻 `fast` 的下标减去 `slow` 的下标恒等于 `n + 1`。

- **建立**：`fast` 单独走 `n + 1` 步后，`fast` 下标为 `n + 1`，`slow` 下标为 0，差为 `n + 1`，成立。
- **保持**：同步阶段两者每步都加 1，差值不变。
- **终止**：`fast` 走到 `None` 时，它「越过尾结点一步」，即下标为 `sz + 1`。由不变量，`slow` 下标为 `sz + 1 - (n + 1) = sz - n`。

而待删结点是倒数第 n 个，其下标为 `sz - n + 1`。所以 `slow` 停在 `sz - n`，正好是待删结点的前驱。删除 `slow.next` 删的就是下标 `sz - n + 1` 的结点，**不多不少恰好一个**，因此不会漏也不会重。

这个论证同时解释了为什么 `n + 1` 是必须的：如果只走 `n` 步，不变量变成差为 `n`，终止时 `slow` 下标为 `sz - n + 1`，即停在待删结点本身——此时你拿不到它的前驱，单链表无法回头删除。

## 5. 完整代码（Python）

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def removeNthFromEnd(self, head: ListNode, n: int) -> ListNode:
        # 哑结点：统一处理「删除头结点」的情况，避免特判
        dummy = ListNode(0, head)
        fast = slow = dummy

        # 第一步：fast 单独前进 n+1 步，拉开固定间距
        # 走 n+1 而非 n，是为了让 slow 最终停在待删结点的前驱
        for _ in range(n + 1):
            fast = fast.next

        # 第二步：同步前进，直到 fast 越过尾结点
        # 循环结束时 slow 恰好位于待删结点的前一个结点
        while fast is not None:
            fast = fast.next
            slow = slow.next

        # 第三步：摘链。slow.next 就是倒数第 n 个结点
        slow.next = slow.next.next

        # 返回哑结点的后继，兼容「删掉原头结点」的情形
        return dummy.next
```

注意 `for _ in range(n + 1)` 里没有做 `fast is None` 检查，这依赖题面保证 `1 <= n <= sz`：`fast` 最多走到下标 `n + 1 <= sz + 1`，即最多到 `None`，不会越界访问 `None.next`。如果题目不保证 `n <= sz`，这里需要加防御。

## 6. 复杂度

- **时间 O(sz)**：`fast` 先走 `n + 1` 步，同步阶段再走 `sz - n` 步（因为 `fast` 从下标 `n + 1` 走到 `sz + 1`），合计 `(n + 1) + (sz - n) = sz + 1` 步。这里的 `n` 被两段行程**互相抵消**了，所以总步数与 `n` 无关，只与链表长度 `sz` 成正比。这就是「一趟扫描」的含义：每个结点最多被访问常数次。
- **空间 O(1)**：只用了 `dummy`、`fast`、`slow` 三个指针变量，与 `sz` 和 `n` 都无关。没有递归、没有额外容器，所以没有 `log` 项——本题不存在分治结构，任何 `log` 都不会出现。

## 7. 边界与反例（至少 4 条）

1. **`head = [1], n = 1` → `[]`**。容易错在：待删结点就是头结点，若不用 `dummy` 而直接返回 `head`，会返回已被摘掉的结点。用 `dummy.next` 返回才正确。
2. **`head = [1,2], n = 2` → `[2]`**。容易错在：`fast` 走 `n + 1 = 3` 步后正好是 `None`，同步循环一次都不执行，`slow` 停在 `dummy`，删 `dummy.next` 即删结点 1。若把 `n + 1` 写成 `n`，`fast` 停在结点 2，同步后 `slow` 停在结点 1，删的是结点 2，答案错成 `[1]`。
3. **`head = [1,2,3], n = 3` → `[2,3]`**。与上一条同理，是「删头结点」的另一种形态，检验 `dummy` 是否真正起作用。
4. **`head = [1,2,3,4,5], n = 1` → `[1,2,3,4]`**。容易错在：`n = 1` 时 `slow` 应停在尾结点的前驱（结点 4），若循环条件写成 `while fast.next` 而非 `while fast`，`slow` 会多走一步或提前停，导致删错位置。
5. **`head = [1,2,3,4,5], n = 5` → `[2,3,4,5]`**。`fast` 走 6 步恰好到 `None`，同步阶段零次迭代，`slow` 在 `dummy`，删头。这是 `n` 取到上界的极端情形。

## 8. 面试追问与变体（3 条）

1. **追问：如果要求返回被删除结点的值，怎么改？** 思路：删除前先存 `slow.next.val`，再摘链，最后把值和头结点一起返回（或用一个包装类）。
2. **追问：如果链表是双向链表呢？** 思路：可以只用一个指针先走到尾再回退 n 步，但那样仍是两趟；双指针一趟的写法依然最优，且删除时可以直接改 `prev`/`next` 两侧，不需要前驱指针。
3. **追问：如果 n 可能大于链表长度，要求不删除任何结点并返回原链表？** 思路：在 `fast` 前进阶段加 `if fast is None: return head` 的提前退出，把「越界」当作「无需删除」处理。

## 9. 举一反三（2-3 道同类题）

- **876. 链表的中间结点**：同样用快慢指针维持固定比例间距（这里 fast 走 2 步、slow 走 1 步），本质都是「用相对位移代替绝对长度」。
- **141. 环形链表**：快慢指针在环内必然相遇，共同点是「两个指针速度/起点不同，靠相对运动推出结构信息」。
- **160. 相交链表**：双指针各自走完自己的链再走对方的链，靠「总路程相等」在交点相遇，同样是「用相对量绕开长度差」的思路。
