# 开发指南 · 代码地图

> 给「下个循环接手的人」看的：这个项目由哪些部分组成、改哪里要跑什么、哪些是雷区。
> 面向改代码的人；只想用的话看 [使用指南](使用指南.md)。

## 一、整体形状

```
浏览器（React 19 + Vite）
  ├─ 数据：app/public/data/*.json  ← 构建期由 tools/build_web_data.py 生成
  ├─ 运行：Pyodide（浏览器内 Python）  ← app/src/lib/runner.ts
  └─ 存储：localStorage（lc.progress.v1 = 学习进度；lc.ui.* = 界面偏好）
桌面版（launcher/）：C# 启动器 + Node 静态服务（gzip + 协商缓存）
数据管线（tools/ + data/）：抓题面 → 生成精讲/参考解/边界用例 → 汇编
```

## 四、雷区（都踩过）

1. **`ErrorBoundary` 的 `resetKeys`**：崩溃后换页必须能清错误态，否则用户被困在错误卡片里。
2. **`Problems.tsx` 的筛选签名**：`useEffect` 在 StrictMode 下跑两遍，用 `ref` 布尔标记会被第二次跑冲掉 —— 必须比较「筛选签名」。
3. **URL 同步的双写**：popstate 回灌 state 后不能再反手写 URL，否则来回 push（实测一次后退 push 56 次）。只有用户真的动了筛选才写。
4. **判题的软/硬失败**：边界用例不一致是软的（AI 参考解不可全信），官方示例不一致才是硬的。改 `judgeCase` 前先看 `docs/已知限制.md` 第 1 节。
5. **顺序白名单**：只能放「外层顺序自由」的题；89 格雷编码、37 解数独、48/59 必须排除。
6. **`nodes.ts` 的类型覆盖按题号**：题库里 559 的 `root` 写的是 `integer`，按类型名推不出来。
7. **重建数据会覆盖 `app/public/data`**：`data/ref_solutions/` 和 `data/edge_cases.json` 是输入，重建不会重新生成它们。
8. **BOM**：用 PowerShell 的 `Set-Content -Encoding UTF8` 写文件会带 BOM，`node --check` 会在 shebang 上报错 —— 写完用 Python 剥一下，或者用编辑器保存。

## 五、测试脚本

| 脚本 | 覆盖 | 依赖 |
| --- | --- | --- |
| `scripts/unit.mjs` | 34 条纯函数断言（判题/白名单/筛选/用例构建/复习节奏） | `npm run dev` |
| `scripts/regression.mjs` | 18 项页面回归（URL/判题/崩溃/滚动/焦点/键盘/参考解/1366/迁移/性能/错题闭环/离线兜底） | `npm run dev` + 本机 Chrome |
| `scripts/firstrun.mjs` | 干净 profile 走完新用户五步 | `npm run dev` + 本机 Chrome |

三个脚本都会**自己拉一个无头 Chrome**（临时 profile），跑完关掉；端口冲突时设 `CDP_PORT`。
