# 已知限制与取舍

> 记录「为什么现在是这样」以及「哪些地方还不完美」。改代码前先看这一页，能省掉重新踩坑的时间。

## 一、数据

### 1. AI 参考解与边界期望同源
`data/ref_solutions/*.json` 是 DeepSeek 生成的参考解，**只保证通过官方示例**；`edgeCases` 的期望值就是拿它跑出来的。
所以「参考解」和「边界期望」共享同一个可信度上限 —— 用它验证它是循环论证，UI 文案里**不能**出现「已验证 / 保证正确」。

实测抽样（120 道题 / 232 个独立变体 / 572 条期望）：**不一致率 3.61%**，其中 74% 来自越界输入、14% 是参考解本身错（如 2546）、9% 是变体写错、合法输入上只有 1 条（49 的多解顺序）。
据此定判题口径：**边界用例不一致 → 琥珀「与参考解不一致」，不判红、不拦通过**；官方示例不符 / 边界用例真的抛异常才算失败。

### 2. 越界输入的期望不可信
`gen_edge_cases.py` 按类型造边界，会塞 `±2^31`、`n=0`、空集合这类值，很多超出题目约束。
- 含 ±2^31 哨兵值的用例（3307 条）：构建期**清空期望**，并标 `extreme: true` → 报错也只算软提示（递归题会直接爆栈）。
- 非极端但越界（`n=0`、`k=-1`）：**保留期望**。理由：经典递归写法在 `n=0` 时本来也返回 `['']`/`[[]]`，和参考解一致；带防御 guard 的写法会被判「软不一致」，已不判红。

### 3. 期望覆盖率 53%
2934 道题 / 12126 条边界用例有期望，其余「只运行不判定」。
剩下的缺口：答案不唯一的题（如 95 生成所有 BST，字符串比对必然失败）、特殊类型无 prelude（N 叉树 `Node`、`NestedInteger`、四叉树）、会员锁题无题面、SQL 题（116 道已排除）。

### 4. 790 道会员题没有题面
只有目录元数据，题目页给「去力扣看题」入口。没有题面就不自动生成 AI 解析（凭空猜题意不如不生成）。

### 5. 题面示例解析的已知坑
- 2024 年起力扣换版，新题用 `<div class="example-block">`，老解析只认 `<pre>` —— 已加兜底（925 道题新增示例，`exampleCount` 6371 → 8731）。
- `<pre>` 里行内加粗（`le<strong>e</strong>etcode`）用 `get_text("\n")` 会被拆成带空格的假文本 —— 已改 `get_text("")`（40 道题受影响，全量 diff 验证 0 回归）。
- 仍有 577 道题有题面但无示例：12 道 LCP 用 `<blockquote>`、68 道只有「输入」标签无 `<pre>`、456 道连「输入」标签都没有（多为设计/数据库题）。

## 二、判题

### 1. 原地修改题只运行不判定
力扣 `metaData.output.paramindex` 标记的题（移动零、旋转图像等），方法返回 `None`，答案在被改写的实参里。按返回值比对会把写对的代码判错 —— 所以这类题只运行、不判定（`Problem.inPlace`）。

### 2. 「通过」的判定口径
- **有期望的用例全过 + 无硬失败** → 这次运行算通过（`passes + 1`）。
- **全是「只运行不判定」** → 记为 `null`（未判定），不加 passes，也不计失败。
- 统计页的「全过率（有期望用例）」按这个口径算；历史数据（口径变更前）没有重算。

### 3. 模板代码是第三态
`isUntouchedStarter()` 判定「还没开始写」（等于模板 / 方法体只剩 pass），命中后不跑引擎、不出红、不计入「今日运行」，只给中性提示。

## 三、界面

### 1. 窄屏
- `< 980px` 单栏布局，能用但没专门适配；**题库表格在 390px 下标题列会被挤成竖排**（已知问题，未修 —— 目标用户是桌面本地训练台）。
- 1366×768 这类短屏：用例区默认 28%、`max-height: calc(100% - 390px)`、隐藏底部键盘提示条 → 编辑器保 18 行。

### 2. 分栏
侧边栏宽度、题面/代码区左右比例、编辑器/用例区上下比例都可拖，双击复位。
**只 clamp 显示值、不写回偏好**：拖到 41% → 缩到 1024 宽（左栏夹到 360）→ 放大回 1600 → 仍是 41%。

### 3. 自定义光标
`data-cursor-fx` 层在代码区 / 终端 / 输入框**整块让位给系统光标**（否则编辑器里会出现「没有光标」的区域）。分栏手柄保留 `col-resize` / `row-resize`。

### 4. 动效
三档（完整 / 克制 / 关闭），`prefers-reduced-motion` 自动降级。庆祝动效要等 View Transition 快照结束（+320ms 延迟）才可见 —— 这是浏览器行为，不是 bug。

## 四、工程

### 1. 没有自动化测试
回归靠 `.tmp/regression_round6.mjs`（CDP 脚本，11 项）和 `.tmp/agents/` 下各子智能体的验证脚本。**改完 `Problems.tsx` / `CodeLab.tsx` 务必跑一遍**。

### 2. 数据重建会覆盖 `app/public/data`
`build_web_data.py` 是唯一入口。重建后要断言：`exampleCount` 8731、`edgeExpectedTotal` 12126、`statementCount` 4152 不被意外改变。
`data/ref_solutions/` 与 `data/edge_cases.json` 是**输入**，重建不会重新生成它们（生成要跑 `gen_ref_solutions.py` / `gen_edge_cases.py`）。

### 3. 存档版本
`lc.progress.v1` 当前 `version: 3`。v1/v2 导入时走 `migrate()` 补 `runs: []` 等字段，**不重算历史** `attempts/passes`。

### 4. 缓存
- 桌面版 `launcher/server.mjs`：只有 `dist/assets/*`（带内容哈希）是 `immutable`；`data/*.json` 走 `no-cache` + ETag。
- 前端所有数据请求带 `cache: 'no-store'`（防止历史遗留的 immutable 缓存）。

## 五、其他已知边界

### 1. 窄屏（< 430px）表格溢出
390px 视口下题库页横向溢出约 20px、题目列被挤到 33px（标题竖排）。**定位是桌面本地训练台，未做移动端适配** —— 用文档承认边界，而不是用代码假装支持。

### 2. 答案顺序不唯一的处理范围（白名单明细）
`lib/answer-order.ts` 的白名单按题号精确匹配，分两档：
- **只放开外层**（内层是有意义的序列）：17 电话号码 / 22 括号生成 / 46·47 全排列 / 51 N 皇后 / 93 复原 IP / 131 分割回文串 / 1079 活字印刷
- **内外都放开**（外层是答案集合、内层是组合）：15 三数之和 / 18 四数之和 / 39·40·216 组合总和 / 49 字母异位词分组 / 77 组合 / 78·90 子集 / 254 因式分解组合
- **故意不放**：89 格雷编码（`[0,1,2,3]` 与期望同集合但不是格雷码，放进去会放行最典型的错误答案）、37 解数独（棋盘唯一）、48 旋转图像 / 59 螺旋矩阵（顺序敏感）。
`npm run verify` 里有一条纯函数断言专门守这个白名单。
- 白名单内：字面比对失败后，再做一次「外层列表无序」深比较（49 连内层也无序），命中则判「顺序不同，视为另一种合法答案」并计入通过。
- 白名单外：行为完全不变（48 旋转图像、59 螺旋矩阵这类顺序敏感题**故意不在名单里**）。
- 约 100 道「列表的列表」输出但未进白名单的题，仍按字面比较。

### 3. AI 内容是构建期快照
`data/ref_solutions/`、`data/edge_cases.json`、`data/teachings/*.md` 都是**生成物**。重建题库（`build_web_data.py`）不会重跑校验 —— 重建后如果要保证可信度，需要重跑 `gen_ref_solutions.py` + `gen_edge_cases.py` + 抽样校验脚本。

### 4. 性能没有度量
`problems.json` 3.4MB、题面分片总计 17MB（按题懒加载）。本地无感（`DOMContentLoaded` 约 167ms），但没有性能预算和监控；真要优化，拆 `problems.json` 会牵动所有页面的数据契约，留到下个循环。

### 5. 回归脚本依赖本机 Chrome
`npm run verify` 会自己拉一个无头 Chrome（临时 profile），需要本机装了 Chrome / Chromium；找不到会直接报错退出（exit 2）。

### 6. 极端输入的运行超时
边界用例会塞 `±2^31` 这类值。对「循环到 n」的题（如 89 格雷编码 `n=31` → `range(2**31)`），点运行会触发 15 秒超时并重置 Python 会话。
数据侧对含 ±2^31 哨兵值的用例已经清空期望（`extreme: true`，报错只算软提示），但**超时不是报错**，仍会发生。遇到时删掉那条用例即可；彻底修需要按题解析约束区间，留到下个循环。

### 7. 首屏传输（两组数字）

| 口径 | 每页传输 | 说明 |
| --- | --- | --- |
| dev server（Vite，不压缩） | **≈ 6.4MB** | 87 个请求，`problems.json` 3.4MB + `tutorials.json` 2.9MB（各一次） |
| launcher（gzip 后，dist 产物） | **≈ 1.3MB** | 8 个请求，`tutorials.json` 943KB + `problems.json` 381KB + JS 397KB |

- FCP：dev 124–288ms、launcher 69–120ms（本机口径，换机器会变）。
- **`/stats` 也会加载 `problems.json` + `tutorials.json`**（`DataProvider` 全局加载），这是已知浪费，未修；要修得把 tutorials 改成按需加载，会牵动命令面板的教程搜索，留到下个循环。
- `npm run verify` 里有一条「首屏传输（launcher · gzip）」检查，预算 **< 1.6MB**（实测 1.3MB，留 ~20% 余量）；dev 口径只打印不判定 —— 因为 Vite 不压缩，拿它当 FAIL 条件会一上线就红，然后一定被人关掉。

### 8. 特殊节点题的运行器支持（部分已修）

**N 叉树（559/589/590/429）已支持**：`nodes.ts` 补了 `Node` / `_build_nary_tree` / `_dump_nary_tree`，实测 4 道题的官方示例与边界用例全部通过。

**四叉树（427/558）与 NestedInteger（385）仍不支持**：
559/589/590/429（N 叉树）、558/427（四叉树）、385（NestedInteger）的**边界输入和期望都已经是对的**（`gen_edge_cases.py` 与 `gen_ref_solutions.py` 都有按题号覆盖的参数类型表），但**前端 `app/src/lib/nodes.ts` 还没有这些节点类型的前导**：
- 本地运行器会把裸列表直接塞给 `root`，用户代码访问 `root.children` 会 `AttributeError`；
- 因此参考答案面板的「载入到编辑器」对这 7 道题是置灰的（文案「本地跑不了」）。
- 这些用例是 `kind: 'edge'`，崩溃会走**软失败**（琥珀「与参考解不一致」，不判红、不拦通过），不会误伤学习进度。
- 要修：把 `tools/gen_ref_solutions.py` 的 N 叉树/四叉树/NestedInteger 前导镜像到 `nodes.ts`，并按题号加参数类型覆盖（`paramTypes` 里这几题写的是 `integer`/`integer[][]`，按类型名推不出来）。

- 四叉树：官方示例对「非叶子节点的 val」允许 `True` / `False` 两种写法，前端只做字符串比对，没法两边同时规范化（会把写对的解判红）。前导和 `_build_quad` / `_dump_quad` 已经写好，等比对支持「结构规范化」再打开。
- `NestedInteger`（385）：边界输入全是违反语法约束的字符串，参考解返回 `None`，本来就没有期望。
- 这三道题的「载入到编辑器」按钮保持置灰（文案「本地跑不了」）。

### 9. 桌面版依赖 WebView2

桌面版窗口用 WebView2（Edge 内核）渲染，需要「Microsoft Edge WebView2 Runtime」—— Windows 10/11 通常自带。
没有的话启动会弹提示；装一个即可。WebView2 的 profile 和 Chrome 分开，所以两边的进度互不同步
（首次启动会自动从 Chrome 迁移一次，之后以 WebView2 为准）。
